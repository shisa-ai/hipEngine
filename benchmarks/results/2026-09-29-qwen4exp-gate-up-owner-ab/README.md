# Q4_K routed gate/up: the production default beats its registered fallback at every measured shape

The two registered owners of `moe_linear` /
`prefill_rows_ge64_exact_grouped_q4_gate_up` are measured against each other on the main
kernel. **The production default is faster in all 12 cases**, by 19.6% at the most
realistic small shape up to 1172% at a degenerate one.

This answers the question `EG-1` was parked on. It is a main-kernel timing comparison, not
an engine or model measurement, and it carries **no correctness gate**.

## Why this comparison was missing

The manifest has two designs for this route:

| list | variant | design |
| --- | --- | --- |
| production default | `selected_dual_wmma_iu8_risk_prefill_bf16_bf16_out` | one output column per lane; each lane reads its own weight row |
| strict default and production fallback | `selected_dual_grouped_rowbatch8_out4_expertgrid64_bf16_bf16_out` | cooperative LDS metadata staging; a weight row is reused across the rows of one expert |

The archived promotion evidence for the production default
(`../2026-09-07-framework-qwen4exp-q4-iu8-exact-production.json`, 72 exact trajectories,
every prefill case improving, PP512/1024/4096 +7.602%/+8.842%/+8.361%) compares it against
`selected_gemv_bf16_bf16_out`. **No archived artifact puts these two owners in an `arms`
pair**, so "is the production default better than its own fallback?" was open.

## Result

Physical host `gfx1151`, machine ID `55ea6c509d0b49eea8de7094a1023668`, kernel
`7.1.6-1-cachyos`, AMD Radeon 8060S, TheRock `therock10-staging-20260828`. Geometry
`HIDDEN=2560`, `FFN=640`, 512 experts, Q4_K (1,440-byte weight rows). Fifteen HIP-event
samples after two primed launches per arm; the production-default arm is measured again
last to expose drift.

**On the two realistic distributions the grouped fallback is 19.61% to 389.24% slower.**

## What this does and does not establish

**Establishes:** the production promotion of `selected_dual_wmma_iu8_risk_prefill` over
`selected_dual_grouped_rowbatch8_out4_expertgrid64` for this route is consistent with a
direct measurement of the two designs, not only with the gemv comparison that justified it
originally.

**Does not establish** that the wmma design is better in general. It wins here, and the
mechanism is visible in the padded-rows column: the wmma owner pads every non-empty expert
to a 16-row tile, so at `balanced-1024` it processes 8,192 padded rows against the grouped
owner's 1,024 compact rows - **8x the row-tile work** - and still wins by 22.91%. The
grouped owner's weakness is parallelism per expert, which is why it degrades hardest as
rows concentrate: at `single-10240` one expert owns all 10,240 rows and the grouped
launch leaves only its 80 output-blocks with work.

## Limits

- **No correctness gate was run.** No output was compared between the two owners, so
  nothing here says they agree numerically. This is a timing comparison only.
- **Weights are synthesized** at the real shapes and byte layout. The access pattern and
  byte counts are representative; the values are not. There is no real-router population
  in this packet - the populations are generated by the harness's own count synthesizers.
- **Main kernel only.** `max_risks=0`, so the risk queue is never written; no repair pass,
  no packing, no engine work, no complete-owner or engine rate. The production default's
  iu8-risk machinery is therefore not fully charged here, which if anything understates it.
- One host, one geometry, one quantization (Q4_K), one process.
- `single-512` repeats with 14.73% drift, the largest in the sweep, on the shortest
  measurement (0.734 ms) where event overhead is proportionally largest. Its conclusion is
  +528.81%, so the drift does not change it. Every other case repeats within 3.45%.
