# gfx1100 RDNA3 Audit Application Plan — 2026-09-05

## Purpose

This document is the handoff for applying the 2026-09-05 RDNA3 tuning audit on
an AMD Radeon Pro W7900 (`gfx1100`) machine. It separates candidates that need
independent W7900 qualification from work already measured and rejected on
W7900.

The starting revision is `58b7e77ff4dea88fb5d0eac6dd455aaaeb0d652a` or a
later revision containing it. The primary workload is Qwen3.8-27B Q4_K_M with
BF16 KV. Do not copy a `gfx1151` capability value into `hip_gfx1100` and call
that a transfer. Every retained value needs same-host W7900 correctness,
route-ownership, profiler, and performance evidence.

The candidate order is intentional:

1. singleton-indexed GDN;
2. Q5 selected-down tile8;
3. Q8 c4/c8 rowtiles;
4. C8 Q4/Q5/Q6 duplicate-expert reuse;
5. the Q6 LM-head C8 partition;
6. shared runtime changes retained by the gfx1151 campaign;
7. independent W7900 qualification of the shared MTP width/depth policy.

Commit each accepted or rejected unit before starting the next. A rejected
candidate remains disabled and gets a compact artifact plus worklog entry.

revision limited the primitive metadata to four rows; the shared primitive now
advertises rows through 8, while the gfx1100 package still caps the owner at 6.
Changing only the package value can therefore reach rows 8 now, but that does
not establish a W7900 win. Treat primitive metadata, registry resolution, and
the package chunk policy as one gate.

## Non-negotiable evidence rules

- Use the physical W7900 host for both control and candidate. A result from a
  different `gfx1100` card or host is an independent lane, not an old-to-new
  comparison.
- Record model path, sampled fingerprint, quant, BF16 KV, host identity, GPU,
  ROCm, compiler, exact command, source revision, dirty state, warmups,
  repetitions, samples, correctness result, and profiler result.
- Keep wave32. Do not add wave64, global non-temporal loads, or a new compiler
  flag while evaluating these candidates.
- These candidates claim exact arithmetic. Require primitive byte equality and
  exact request/slot/token/position/mask/KV/state ownership. Do not relabel an
  ownership mismatch as acceptable numerical drift.
- Keep every established segmented, per-row, 16-column, and chunked fallback.
- Profile a final child or the dedicated profiler harness after JIT warmup.
  Never run `hipcc` inside `rocprofv3`.
- A leaf win is not enough. Retain it only when the complete affected owner is
  non-regressive. Small exact cycle-wall or verified sub-window savings count,
  but must be measured and attributed.
- Run the full multi-prompt suite for MTP. Never select a width or route from a
  single prompt.

## Work packet F — shared runtime transfers

Transfer each item only after its gfx1151 campaign decision. The packed-prefill
final-row mask is retained and ready for independent W7900 qualification.
Persistent streamed workers are rejected and excluded from this transfer packet.
Do not recreate that candidate on W7900 without new profiling that identifies a
live product owner and changes the reachability premise.

### F1. Packed-prefill final-row mask

The shared runtime now carries a package-owned final-output mask. It is enabled
only for gfx1151; gfx1100 remains on the original unmasked route. On gfx1151,
the retained C8/512 gate uses six bounded rounds, preserves final tokens,
positions, and all FP32 hidden-seed hashes, and skips 40 intermediate samples.
The matched trace removes five Q6 LM-head launches and 28.843 ms from that
head sub-window. Pooled A/B/B/A complete prefill wall improves
0.149%/0.219%/0.217%/0.033% at C5-C8, so treat this as an exact launch
reduction, not a transferable throughput percentage.

Re-run W7900 packed-prefill exact state and timing for mixed prompt lengths and
multiple bounded rounds. Verify that intermediate chunk tails skip output norm,
full LM-head, and sampling, while final rows, target-hidden sinks, MTP catch-up,
and all request ownership remain correct.

Required W7900 coverage:

- one-round and multi-round packed prefill;
- mixed final/intermediate slots in the same round;
- cancellation and a newly admitted request after an intermediate tail;
- direct AR and MTP-enabled consumers;
- trace evidence showing fewer output-head/sampler launches;
- same-host prefill and TTFT performance with decode non-regression.

### F2. Persistent streamed workers — do not transfer

The gfx1151 decision retains no shared implementation. Source inspection found
three per-cycle `ThreadPoolExecutor` sites, but a traced Qwen3.8 C8/K3 server
cell created zero generation-side pools; all four observed pools belonged to the
benchmark's HTTP request fan-out. The dense direct Qwen3.8 control also created
none. The churn is confined to direct compatibility/control loops tracked under
GGUF duplicate loop ownership in `docs/REFACTOR.md`.

A Qwen3.6 MoE direct-control trace reached the old sites: each of eight C8
cycles built an eight-worker draft pool and a two-worker verifier pool, while a
short C9 packed-AR control built seven two-worker pools. A five-by-200-cycle host
microbenchmark estimated only 0.091 ms of reusable-pool savings per C8
draft-plus-verify cycle. An out-of-tree persistent-pool A/B confirmed a real
draft sub-window reduction, but complete call and cycle walls each won only two
of four counterbalanced pairs. All rows remained token-exact and the temporary
threads drained.

That result fails the required live complete-server/load gate and does not
justify adding thread/context/environment lifecycle to the product model loop.
Do not transfer the candidate to W7900. Reopen it only if a W7900 profile first
shows executor construction on a live product owner and a complete same-host A/B
is consistently positive. See
`benchmarks/results/2026-09-05-gfx1151-persistent-stream-workers-rejected.json`.
