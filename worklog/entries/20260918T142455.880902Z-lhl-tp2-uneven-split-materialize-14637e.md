# TP2 uneven split: materialize per-rank MLP shard widths end to end

## Summary

The balance solve from `078f169c6` planned an uneven MLP split but nothing could
run it: the shard manifest could describe per-rank block counts, while every
session, prefill path and weight binding still assumed one width for both
ranks. This unit wires the plan through to a materialized session. An uneven
session now builds, reports its own per-rank FFN widths, resolves the fused
gate/up+SiLU route per rank, and generates **the same tokens** as the even
split, with top-1 agreement 1.0 on every teacher-forced row.

The split is still **default-off** (`uneven_split=None` is the even split): the
change moves `ffn_down`'s summation grouping, so it is a production-profile
arithmetic change and needs the teacher-coverage gate before it becomes the
default. The pair+SiLU allowlist gap that the first smoke exposed is closed in
the companion unit; this entry records the plumbing.

## Changes

- `hipengine/loading/qwen35_gguf_shards.py`: `UnevenSplitPolicy` and the
  manifest's per-rank block counts are now consumed by the weight binding path,
  so a rank's `ffn_gate`/`ffn_up`/`ffn_down` slices are built from the planned
  boundary rather than from `feed_forward_length // world_size`. The policy
  refuses any leaf outside `SAFE_UNEVEN_LEAVES` and refuses a partially named
  coupled set, because the three MLP roles must move together.
- `hipengine/distributed/shard_group.py`: `MlpTP2ShardGroup` takes
  `per_rank_ffn` as either one width or a per-rank mapping, validates that every
  device has a width, and exposes `mlp_decode_variant` as a scalar when both
  ranks resolve the same variant or as a per-rank mapping when they diverge -
  which is exactly what an uneven split does, since the policy lookup is
  shape-qualified.
- `hipengine/distributed/shard_weights.py`, `tp2_generate.py`,
  `tp2_prefill.py`: thread the per-rank width through weight binding, the
  decode session and the prefill path, so no site recomputes the even split.
- `scripts/tp2_teacher_coverage_broad.py`: `--shard-fractions` gives the tp2
  arm an explicit split while the tp1 controls keep the even one (they are the
  comparison basis and must not move), and the artifact's resolved route now
  records the per-rank widths and the per-rank resolved variants, so a gate
  artifact states the route it measured instead of leaving it to be inferred.
- `docs/REFACTOR.md`: records the flag, why it is default-off, and what
  retires it.

## Validation

- `python3 -m pytest tests/test_unit_loading_uneven_split.py
  tests/test_unit_distributed_shard_group.py tests/test_unit_distributed_tp2_generate.py
  tests/test_unit_scripts_tp2_teacher_harness.py` - all pass. New coverage:
  per-rank width validation, the scalar/mapping variant contract, refusal of a
  head-structured leaf, refusal of a partial coupled set, and the gate's
  route recording.
- End-to-end smoke on the two-card host (W7900 + RX 7900 XTX),
  `scripts/tp2_uneven_split_smoke.py --fractions 0.417145/0.582855`: the uneven
  session materialized widths `{0: 7168, 1: 10240}`, generated the same 16
  tokens as the even split, and agreed with it on the top-1 token of all four
  teacher-forced rows. Max absolute logit difference 0.134, mean 0.019 - the
  expected `ffn_down` regrouping, not a control difference.
- The first smoke run also found the one real gap: both ranks reported
  `variant=None`, i.e. the uneven widths fell out of the dense pair+SiLU
  allowlist and both ranks silently took the unfused three-launch chain. Fixed
  in the companion unit with a bit-identity measurement at both new widths.
