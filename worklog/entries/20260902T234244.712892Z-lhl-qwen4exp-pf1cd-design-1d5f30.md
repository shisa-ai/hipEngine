# PF-1c/d design checkpoint: grid decode and MMQ levers

## Summary

Decoded the production launch grids (rocprof CSV Grid_Size_* is work-items =
blocks x workgroup dims) and read the MMQ kernel body. This fixes the PF-1c/d
design targets and corrects the PF-1a interpretation: the MMQ family is not a
naive column-per-block kernel.

## Changes

- No code change; design checkpoint only (this entry + grid decode).

## Findings

1. **MMQ (`q8_0_raw_mmq128_q8_1_d4_kernel`, 6,926 ms/req at p4096)** is a
   WMMA iu8 tensor-core port of llama.cpp MMQ (lineage comment: llama.cpp HIP
   `1ebf790c`, `mmq.cuh`/`mma.cuh`), 128 output x 128 token x K256 tiles,
   256 threads, 57,856 B shared. Its observed grids map exactly to the seven
   `QWEN4EXP_Q8_MMQ_PREFILL_POLICY` shapes (out 320/512/640/2560x2/10240/
   12288 at in 2560/6144/10240). Two levers vs llama's 1,592 ms dense-Q8
   device time:
   - **Three activation passes**: the d4x3 residual scheme runs the full WMMA
     pass three times (activation_passes=3), ~3x compute. d4 (1-plane) and
     d4x2 wrappers already exist in-tree. Plane reduction changes arithmetic
     (production-profile gate + calibrated numerics required), occupancy/
     tile retuning does not if per-element accumulation is preserved.
   - **Occupancy**: 57.9 KB shared caps residency near 1 block/CU on gfx1151
     (64 KB LDS); `__launch_bounds__(256, 2)` cannot be honored. halo-box
     a7ad7b7f `mmq-config-rdna3-5.cuh` retunes exactly this class (128-thread
     I=64 / 256-thread I=128 tiles with J<=128).
2. **coltile F32 (`gguf_k_prefill_out_coltile_rowbatch<float,float,8,8,4>`,
   2,759 ms/req)** serves the non-policy attention-gate projections at
   out in {2560, 6144}, in=2560, rows=512 (84 launches per 512-token chunk:
   the GDN/QSA gate roles). Scalar-FMA kernel; per-element K ownership
   (128-thread stride + shuffle tree + 4-wave serial publication) makes
   bit-exact retiling impossible; tensor-core admission is a
   production-profile arithmetic change with the strict coltile fallback.
3. **selected Q8_0 down (`gguf_k_selected_prefill_out_kernel<quant8>`,
   3,065 ms/req)** runs grid (out=2560, rows=512x10 selected): one 128-thread
   block per (output column, selected row) — a scalar per-element GEMV at
   GEMM shapes (~87 GFLOP/s effective). The production Q4_K/Q5_K selected
   WMMA prefill kernels are the in-tree precedent for a Q8_0 selected WMMA
   variant.

## Decision

PF-1d (MMQ) proceeds first within PF-1: screen plane count (d4/d4x2/d4x3,
existing wrappers, no code change) and occupancy/tile retune (code, bit-exact
contract) at the seven policy shapes before any whole-model run. PF-1c
(coltile + selected) targets tensor-core admission as production-profile
variants with strict fallbacks, mirroring the retained Q4_K/Q5_K WMMA
precedent.
