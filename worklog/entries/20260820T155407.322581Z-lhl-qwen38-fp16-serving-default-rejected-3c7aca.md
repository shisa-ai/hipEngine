# Reject FP16-state public default on serving screen

## Summary

The clean, predeclared static c1/c8 production serving screen rejects changing
the public default to FP16 recurrent state. Both FP32 and FP16 fail the
0.5-second c8 ITL-p99 SLO, and FP16 improves exact c8 server throughput only
1.33%, below the 3% public-default materiality target. FP16 remains a retained
opt-in; spending the complete canonical tuning/ragged/continuous/cancel/
overload/recovery/soak packet cannot reverse either binding screen result.
