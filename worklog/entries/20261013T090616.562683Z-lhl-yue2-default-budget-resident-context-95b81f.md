# Fit YuE2 shipped song budget to the resident AR context

## Summary

Exercising the shipped YuE2 song path with a real request, rather than the capped
phase budgets the generator was validated with, found that the two shipped defaults
disagreed: `DEFAULT_SEMANTIC_SAMPLING.max_tokens` was 9000 while the AR runtime the
song pipeline builds allocated only 4096 positions. Any default-budget request drove
the decode loop to a position the runtime cannot address and died inside
`Yue2ArRuntime._validate_position` (`position must be an integer in [0, 4096)`)
instead of producing a song or naming a request error. Fixed by making the loop's
budget check aware of the resident context and by sizing the shipped context from the
span-attention kernel ceiling, so a default request now generates a full song.

## Changes

- `hipengine/runtime/yue2_session.py`: `generate_tokens` now also validates
  `prefix + budget` (and the CFG negative prefix) against `runtime.max_context`, not
  only the checkpoint's declared 24576. An over-budget request is refused by name
  before prefill instead of failing inside the runtime's position check.
- `hipengine/generation/yue2_song.py`: `DEFAULT_AR_CONTEXT` 4096 -> 16000, the
  span-attention kernel's shared-memory ceiling (`SPAN_ATTENTION_MAX_CONTEXT`). The
  shipped semantic budget (9000) plus a planning prefix now fits, so the default path
  is not self-refusing. K/V allocation for the AR route grows from ~0.47 GiB to
  ~1.83 GiB; short songs pay no latency for it because the span attention walks live
  spans, not the allocation.
- `tests/test_unit_yue2_session.py`: two tests. One pins the resident-context refusal
  (and that it does not touch the runtime); the other asserts the shipped semantic
  budget fits the shipped AR context, so the two constants cannot drift apart again.

## Validation

- New tests are RED before the fix (the first reproduces the production failure as an
  internal position assertion; the second fails on `9000 < 4096`) and GREEN after.
- `uv run pytest tests/ -k yue2`: **296 passed, 10718 deselected**.
- Live on gfx1151 from the local HF-cache snapshots, `LLM.generate_song()` at product
  defaults (`cot="full"`, 32 ODE steps, no budget override) with a full lyric sheet:
  **173.24 s (2:53) of 48 kHz stereo, natural EOS, both truncation flags false, no
  torch import**, in **575.4 s end-to-end (RTF 3.32)**. Stage split: ABC planning
  66.4 s / 1864 tokens, semantic 287.7 s / 4331 tokens (prefix 2101), NAR 155.0 s
  (35.8 ms/frame), VAE 66.3 s (15.3 ms/frame).
- Audio checked as music, not just non-empty: spectral flatness 5.3e-4, tonal peak
  ratio 130, L/R correlation 0.53, 21 dB envelope range, 173 BPM onset periodicity,
  and an outro over the last ~13 s. Peak 1.068 clips 9 samples in the 16-bit WAV
  export; the pipeline's own output is unclipped by contract.
- Independent ASR (VibeVoice-ASR) recovered lyric fragments from the prompt in the
  first ~72 s (for example "Echo softly in my head", "Barefoot on the summer heat")
  but not in prompt order, and labelled the remaining ~101 s `[Music]`. Re-running ASR
  on just the 85-145 s slice returned `[Music]` for the whole window, so that label is
  not a long-context give-up: roughly 58% of the generated song is instrumental, and
  the model's own ABC plan carries extended instrumental intro and outro sections.
  Vocal presence is therefore partial, and this song is not a full lyric reading.
- `python3 audit/audit.py check` fails on this tree, but it also fails on a clean
  `main` checkout (stashed the change and reproduced: 2 `ungoverned-flag-branch` + 1
  `unguarded-hip-test` untriaged rows over a zero budget), so it is pre-existing and
  not introduced here. The `audit/` artifacts that `check` rewrote were restored.

## Next

- The 4096 default was the pipeline's own bound, not a checkpoint one; 16000 is now
  the ceiling the kernel supports. Raising it further needs a span-attention kernel
  change, not a constant.
- The full-song RTF is 3.32, higher than the ~2.2 estimated from short clips, because
  semantic AR slows from 23.1 to 15.1 tok/s and NAR from 19.6 to 35.8 ms/frame as the
  prefix and key set grow. The AR decode remains the dominant cost (50% of elapsed
  time) and is the item to profile next.
- A per-stage progress surface would make a ~10-minute song observable while it runs;
  `generate_song` currently reports only at completion.
- Lyric adherence was partial on this request: the shipped defaults produced a 173 s
  song whose vocals occupy roughly the first 72 s. Whether that is the `cot="full"`
  plan (long instrumental intro/outro) or a semantic-stage behaviour is not yet
  separated, and a task-quality suite would settle it.
