# The dense-wide 0-47 extension is refuted by the production gate at 1.47x mean KL; 8-47 fails one category

## Summary

`20261004T032242.378046Z-lhl-qwen4exp-dense-wide-0-47-42cf4b` measured
**+18.88% prefill and +5.79% decode** from extending
`PRODUCTION_Q8_DENSE_WIDE_PREFILL_LAYERS` from 16-47 to 0-47, with identical
generated-token digests in all three arms, and blocked promotion on the
production gate. **The gate refutes it.** At the canonical protocol (12 cases,
128 decode steps, 3 repeats, chunk 1024):

| scope | engaged rate | kl_mean | kl_p95 | kl_max | top-1 | worst category | hard gates |
| --- | ---: | ---: | ---: | ---: | ---: | --- | --- |
| 16-47 (control) | 0.337 | 4.527e-4 | 2.320e-3 | 2.341e-2 | 0.99354 | - | **PASS** |
| 8-47 | 0.421 | 8.839e-4 | 4.647e-3 | 4.146e-2 | 0.99096 | general_en 1.181e-3 | FAIL, 1 scope |
| 0-47 | 0.508 | **1.468e-3** | **7.517e-3** | **5.140e-2** | **0.98837** | general_en 1.753e-3 | FAIL, 6 scopes |

At 0-47 the mean is **1.47x over** the 1e-3 limit, p95 **1.50x over** the 5e-3
limit, max **1.03x over** the 5e-2 limit, and top-1 is **below the 0.99
minimum**. All four categories fail, plus shape `c1` and transition `steady`.

So the largest single lever found this session - and it is large, and it is real
as a *speed* measurement - is **not admissible**. The 18.9% is not recovered by
any scope the gate admits so far; the boundary is between 8-47 and 16-47 and the
ladder is running.

## Changes

### Attribution is clean, which is what makes this a refutation

The gate's baseline had drifted before in this project (the 2026-09-30
`dense_wide` 16-47 re-gate), so a 0-47 failure would be uninterpretable without
a control at the same HEAD. The control was run first:

| metric | recorded 16-47 (`cac0f1da5`) | control 16-47 at HEAD (`04d0f4161`) |
| --- | ---: | ---: |
| `kl_mean` | 4.38817e-4 | 4.527038e-4 |
| `kl_p95` | 2.360965e-3 | 2.320395e-3 |
| `kl_max` | 2.3411946e-2 | **2.341195e-2** |
| top-1 | 0.994186 | 0.993540 |
| rows over review | 1 | 1 |

`kl_max` is identical to the printed precision, the single over-review row is
the same row (`general_en-p512`, teacher step 82, KL 2.3411946e-2), and the
control passes every hard gate with **2.2x headroom on the tightest**. The
instrument is good and the baseline has not moved, so the 0-47 and 8-47
failures are attributable to the scope extension.

**The strict teacher hash is identical in all three runs**
(`4377006f4f0827dd419e9d92da9b61b0dbf65074195ffec5852fb98cc7e65ed7`), so the
three runs are directly comparable and the candidate hashes are the only
difference. Engagement scales monotonically with the scope (0.337 / 0.421 /
0.508), confirming each run dispatched the layer set it claimed.

### The drift enters through decode, not through the prefill

Every scope leaves the prefill's own logits essentially untouched:

| scope | `prefill_last` kl_mean | `prefill_last` top-1 |
| --- | ---: | ---: |
| 16-47 | 4.32e-9 | 1.0 |
| 8-47 | 3.15e-8 | 1.0 |
| 0-47 | 4.66e-8 | 1.0 |

while `steady` (decode) carries the whole drift. That is the expected shape for
a route that changes the *rounding* of the projections feeding the KV cache: the
last prompt position's logits are dominated by the final layer's own
computation and barely move, but all 4096 cached positions carry slightly
different values, and decode attention over them accumulates the difference.

Per-category mean KL grows monotonically with scope for **every** category, so
this is not one anomalous category:

| scope | code | general_en | general_ja | mixed_ja_en |
| --- | ---: | ---: | ---: | ---: |
| 16-47 | 4.66e-4 | 5.41e-4 | 4.09e-4 | 3.96e-4 |
| 8-47 | 6.85e-4 | **1.18e-3** | 8.99e-4 | 7.70e-4 |
| 0-47 | **1.01e-3** | **1.75e-3** | **1.96e-3** | **1.15e-3** |

At 8-47 only `general_en` is over; at 0-47 all four are.

### The failures are near-ties, and that is not a defence

All 18 top-1 mismatches at 0-47 are `strict_top1_candidate_rank: 2` with
`topk_overlap` 0.8-1.0 and strict margins of 0.003-0.11, i.e. the top-5 sets are
largely identical and only the top-two order moved. That is the same character
the 2026-09-30 baseline-drift finding had, and it is recorded here for the same
reason: it explains the failure and does not excuse it. The mean and p95 gates
are aggregate statistics, not tail statistics, and they are over by 1.47x and
1.50x - this is a broad-based failure, not a tail one, so a per-layer or
per-row guard would not rescue it.

## Limits

- The gate's `status` is `invalid_or_screen_only` and `measurement_valid` is
  `false` for the **control** as well, because `qualification_blockers` carries
  the standard uncollected-certificate list plus the single over-review row.
  `hard_gates_passed` is the field that separates the runs, and it is `true`
  only for 16-47. `measurement_valid` should not be read as "the run is
  untrustworthy" here.
- One host (gfx1151, not the gfx1100 default hardware), one model, one quant,
  one execution profile, one chunk size (1024), one route.
- The boundary between 8-47 and 16-47 is not yet located. This project has
  already measured a **non-monotonic** scope boundary on a sibling route (the
  staged-f32 ladder found 15-47 failing while 14-47 and 16-47 pass), so the
  boundary may not be a simple threshold and no scope may be inferred from a
  neighbour's result.
- No kernel-level trace of any candidate scope, so the per-layer cost model
  behind the 18.9% is inferred from the 16-47 trace rather than measured on the
  extended one.
- The `general_en` per-category failure at 8-47 is 1.18x over; the gate's
  per-scope rule applies the 1e-3 mean limit per category, so a scope that
  passes in aggregate can still fail here.
