# Capability admission in the serving and KV path

## Summary

Implements the policy committed in `eb20c9c80` in the runtime. Capability now
admits in every request mode; retained evidence selects among admitted paths,
records what may be claimed, and withholds a path only when it recorded an
actual rejection. No identity — model name, path, SHA-256, revision — gates
execution anywhere on this path.

This entry also accepts and commits the parallel worker's in-flight work on the
same chain, which was reviewed rather than discarded. That session was stopped
and its ownership transferred here.

## Changes

Capability admission:

- `hipengine/models/kv_capabilities.py`: added `KVCapabilityDeclaration`, the
  admission axis, holding what the kernels execute for one KV contract plus its
  operative bounds. `resolve_kv_capability` now refuses only a contract no
  declaration covers (`unsupported`); a covered contract with no retained row
  admits as `unmeasured`, and a retained `rejected` row withholds the path as a
  known-bad configuration scoped to the identity that recorded it.
  `weight_quant` is a nullable declaration axis because the KV decode kernel key
  is `(backend, layer, kv_storage, variant)` — naming a quant the kernel does
  not key on would rebuild the allowlist.
- `hipengine/models/qwen35.py`: registered the int8 per-token-head declarations
  for both `hip_gfx1100` and `hip_gfx1151`, both of which register
  `per_token_head_gqa_splitk_gate_bf16_batch_strided_spans`.
- `hipengine/runtime/qwen35_gguf_runner.py`: renamed
  `_qualified_no_mirror_int8_capability` to `_admitted_no_mirror_int8_capability`
  and removed its `promotion_eligible is True` and `status == "qualified"`
  conditions. Admission reads `runtime_action`; `promotion_eligible` is reserved
  for claims. Operative bounds now come from the resolution, which sources them
  from the measurement when one exists and the declaration otherwise.
- `hipengine/speculative/serving.py`: deleted the `artifact_identity_unverified`
  check from the implementation declaration and the early reject from
  `resolve_speculative_mtp_serving_plan`. Renamed the `*_not_qualified` axes to
  `*_unmeasured`, which is what they describe. `_artifact_identity_matches` now
  additionally requires `content_verified`, so an unverified file cannot be
  credited with a measurement it did not earn — it still runs, on capability.
  Added `unsupported_contract`, which relabels a terminal miss as the capability
  fact it is instead of reporting a missing measurement.
- `hipengine/models/qwen35.py` plugin combine: the implementation declaration
  now admits in every request mode, not only `explicit` or
  `automatic_eligible`.

Accepted from the stopped parallel session, reviewed:

- `hipengine/loading/gguf.py`: `gguf_execution_fingerprint` — layout-based
  execution identity (tensor table plus routing-relevant metadata, excluding
  tokenizer, provenance, and bytes). Under this change it is provenance only.
- `hipengine/llm.py`: `_mtp_sampling_params` makes direct `LLM.generate()`
  callers resolve the same serving plan the HTTP layer does, closing a
  works-in-the-harness gap. `request_mode` threaded through.
- `hipengine/server/api.py`: marks a request `explicit` when it actually asked
  for speculation.
- `scripts/gguf_execution_identity.py`, `tests/test_unit_llm_mtp_eligibility.py`,
  `tests/test_unit_gguf_prefix_int8_attention_source.py`, and the int8 prefix
  attention ownership repair in the runner and generation modules.
