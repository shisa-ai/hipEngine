# UD-U1 repair 5: unknown manifests no longer inherit plain policy identity

## Summary

U1 finding 5: preset resolution only recognizes the exact-UD fingerprints; every
other manifest resolved `preset=None` and inherited the plain stamp-based
policy identity (`_gguf_policy_identity` returning `(geometry, stamp)`, runner
line ~10957) and the packaged hot-vocabulary identity (metadata-only 5-tuple,
`gguf_mtp_hot_vocab.py` ~69).  A mutated plain K_M — same stamp, different role
manifest — therefore silently received plain-certified arithmetic rows and the
packaged hot-vocabulary selection.

## Changes

- `hipengine/loading/qwen35_gguf_admission.py`:
  - `GGUF_UNQUALIFIED_MANIFEST_PRESET = "gguf-unqualified-manifest"` sentinel.
  - `_PINNED_PLAIN_CONTROL_FINGERPRINTS`: the seven qualified plain-control
    role-manifest fingerprints computed on this host from the local artifacts
    (Qwen3.8-27B Q4_K_M / Q4_K_S, Qwen3.5-0.8B Q8_0 / Q4_K_M,
    Qwen3.6-27B-Q4_K_M — which shares the Qwen3.8 dense h5120 geometry+stamp
    and must stay pinned — Qwen3.6-35B-A3B-UD-Q4_K_M (plain MoE control,
    not a UD preset), Ornith-1.5-35B-A3B-Q4_K_M).
  - `qwen35_gguf_artifact_preset_key_for_report(report)` and
    `qwen35_gguf_artifact_preset_key(model_map, ..., preset=None)`: pinned UD
    fingerprint → UD preset key; pinned plain-control fingerprint → `None`
    (historical plain identity preserved); anything else → the sentinel.
- `hipengine/loading/qwen35_gguf_materialize.py`: the loader binds
  `Qwen35GGUFResidentWeights.artifact_preset_key` from the admission report
  via the new helper (was: `preset.preset_key if preset else None`).
- `hipengine/loading/qwen35_gguf_nextn_materialize.py`: the MTP draft
  materializer derives the same qualification (reusing the pre-resolved
  preset) for the hot-vocabulary identity, so an unknown manifest can no
  longer resolve the packaged hot-vocabulary selection that was certified for
  the plain control sharing its stamp/tokenizer.
- Downstream behavior (no code change needed):
  - `_gguf_policy_identity` returns a 3-tuple for the sentinel, which misses
    every plain 2-part `(geometry, stamp)` policy row (repair 6 threading).
  - `default_gguf_hot_vocab_path(..., artifact_preset_key=sentinel)` appends
    the sentinel to the identity tuple and resolves no packaged map.
  - Runner `as_full_stack_weights` copies `artifact_preset_key` verbatim.
  - NextN draft residents keep `artifact_preset_key=None`, but the draft
    geometry (block_count=1) cannot match the 64-block plain policy rows.
