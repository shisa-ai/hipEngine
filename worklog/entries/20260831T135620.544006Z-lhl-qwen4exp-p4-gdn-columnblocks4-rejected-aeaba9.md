# Reject Qwen4Exp early GDN column blocks

## Summary

Rejected and removed an early-GDN four-column-block candidate. It improves the
real device window and preserves recurrent state, but fails production-width
output parity. A reduced one-block fixture passed and therefore did not cover
the cross-block failure mode.

## Changes

- Prototyped four 32-column blocks per v-head, each duplicating the incumbent
  128-thread Q/K norm tree and updating disjoint state columns.
- Added reduced strict/serial parity during screening, then ran a production-
  width output/state microbenchmark before model dispatch.
- Reversed all candidate code/tests after the parity failure.
- Added compact rejection evidence and updated P4 campaign/changelog.

## Validation

- Reduced rows5/head_dim8 (one column block) output/state are exact.
- Production rows508/16 heads/H128:
  - recurrent state F32-bit exact;
  - output not exact, with debug mismatch counts
    `[66090,66159,66103,65625]` across the four 32-column quarters;
  - device wall `12.628→12.227 ms` (`1.0328x`).
- Candidate patch/debug script/raw timing are hash-pinned. No model dispatch or
  whole-model timing was run.

## Next

Any future GDN layout candidate must start RED with production H128 multi-block
output and state, not only a reduced one-block fixture. Continue QSA flash
geometry meanwhile or localize the cross-block output discrepancy before
retrying direct column ownership.
