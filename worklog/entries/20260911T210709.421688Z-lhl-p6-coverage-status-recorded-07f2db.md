# P6 coverage status recorded; the layer budget is derived, not a settable knob

## Summary

Two of the four remaining P6 coverage items turned out to be claim-clarity problems
rather than missing measurements. Both are now recorded where the claim lives, in
the P6 section of `docs/SERVER-DIRECT-PARITY-ROADMAP.md`, rather than left as
ambiguity for the next reader.

**The layer budget is not a knob.** A reviewer asked for "layer budgets other than
4", which presumes a control that does not exist. The budget is computed
(`qwen35_gguf.py:8244-8248`):

```python
remaining_polls = max(1, -(-remaining_tokens // chunk_len))
budget = max(1, -(-remaining_layers // remaining_polls))
```

So it is derived from prompt length and prefill chunk size, and a budget sweep means
varying those inputs, not setting a flag. The observed budget of 4 is an emergent
consequence of the harness's 3072-row prompt and chunk sizing, not a configured
value.

**BF16 coverage has no referent.** The resumable executor is only attempted when the
session's `kv_attention_source` is `int8_direct` (`qwen35_gguf.py:8094`), so there
is no BF16 resumable path to cover. The BF16 route's bounded yield comes from the
default route and is measured by the seven non-engagement gates, which pass under
BF16. The roadmap now says this explicitly instead of listing "BF16 resumable
coverage" as open.
