# the full-layer attention kernel lands and attention leaves the critical path

## Summary

The five head_dim-512 full layers had no matrix-core path. The strict kernel
served them at 434.9 GFLOP/s -- about one percent of this part's BF16 rate -- and
they are 36 percent of Gemma 4's prefill attention FLOPs. A BF16 WMMA
online-softmax prefill for that geometry now runs at **4383 GFLOP/s, 10.04x the
strict kernel**, on the same device buffers, shapes, mask and arguments.

Both attention kernels are now selected by the production profile, each matched
against its own layer's head geometry:

| geometry | layers | variant | kernel row at 4096 tokens | in situ |
| --- | ---: | --- | ---: | ---: |
| sliding, head_dim 256, 16q/8kv | 25 | `gemma4_wmma_flash` | 13.67x | 348.40 ms |
| full, head_dim 512, 16q/2kv | 5 | `gemma4_wmma_flash_full` | 10.04x | 231.08 ms |

**Attention goes from 61.0 percent of the 4096-token prefill step to 13.5
percent**, and the step from 8.980 s (456.1 tok/s) to 4.189 s (977.8 tok/s):

| prompt | strict only | sliding candidate | both candidates | llama.cpp |
| ---: | ---: | ---: | ---: | ---: |
| 512 | 870.0 | 1012.8 | 1078 | 1012.98 |
| 1024 | 707.2 | 925.1 | 1042 | 1057.48 |
| 2048 | 570.0 | 804.6 | 1007 | 1067.14 |
| 4096 | 456.1 | 628.2 | 977.8 | 1039.85 |

**The 4096 step is 0.94x the same-host llama.cpp reference and 1.06x at 512, and
what is left is not attention.** The census puts the routed experts at 54.8
percent of the step and the dense projections at 22.8 percent; every
non-attention term is already linear in token count. Reaching parity at 4096
means a faster expert or dense projection, not a faster attention kernel -- the
whole of attention is now 579 ms of a 4277 ms step, so even deleting it entirely
would not close the remaining 6 percent on its own.

## Changes

- **`gemma4_attention_prefill_wmma_full.hip` / `.py`** -- new kernel and raw-pointer
  wrapper. The ABI is the strict kernel's argument for argument, so the two can
  be driven on the same buffers without an adapter. Tiling: 16 query rows x 2 GQA
  heads = 32 WMMA columns, 128 threads in 4 waves (2 column groups x 2 output
  dimension groups of 256), K_BATCH 16, 49,920 bytes of LDS. The dimension split
  is what keeps the accumulator at 128 floats per lane; it costs 1.5x the ideal
  score-dot count, which is affordable because the tensor unit is at 10 percent
  utilisation. BF16 operands, so staging is a 16-byte copy with no conversion.
- **Two measured optimizations**, both from ablations rather than hunches:
  staging issues all eight 16-byte K/V loads before the first LDS store consumes
  one (97.93 -> 68.37 ms), and the keep-mask batch is one 16-byte vector read per
  lane instead of eight scattered byte loads (-> 62.16 ms). The second one is the
  kind of thing that only shows up in an ablation: eight byte loads are the same
  eight cache sectors eight times over, and the dependent compare put the load
  latency on the batch's critical path.
- **Profile wiring.** A profile selection now names one variant *and* the
  geometry scope it was measured on, and the production plan carries one
  selection per scope. The request the generator binds is the set of variants,
  and `select_prefill_attention` takes the first one whose declared geometry
  matches the layer's own -- so the sliding and full layers of one model get
  different kernels from one profile, and a geometry neither implements still
  falls back to the strict kernel with a reason.
- **`tests/test_gpu_gemma4_attention_prefill_wmma_full.py`** -- 19 correctness
  cases against the strict kernel.
- **`tests/test_unit_gemma4_prefill_attention_selection.py`** -- 29 cases, now
  covering both geometries, both variants, and the per-geometry routing.
- **`scripts/gemma4_prefill_kernel_census.py`** -- the census patched attention
  on the layer module, which the variant selection had made dead: it would have
  reported attention as unaccounted rather than as free. It now spies on every
  launcher a profile can select and warns when it intercepts none of them.
- **`scripts/gemma4_attention_prefill_bench.py`** -- `--compare-wmma-full`, the
  full-layer row this evidence rests on.
- **`docs/REFACTOR.md`** -- the ledger said the full layers keep the strict
  kernel because the variant declares that geometry unimplemented. Both
  candidates are now on the default path with the same numerical gate
  outstanding, so the entry says that and carries the three-arm ladder.
- **`docs/KERNELS.md`** -- Gemma 4 was missing from the catalog entirely; added
  the source tree line and the exact/production row for both attention kernels.
- **`audit/hipaudit/core.py`** -- `_ref_identity` stripped a line number only
  when it ended the ref, but a doc-path-drift ref is `path:line:subject`. Editing
  a scanned document therefore orphaned every decision beneath the edit: adding
  one line to `docs/KERNELS.md` un-triaged 129 rows, which is exactly the failure
  the function exists to prevent. The line segment is now dropped wherever it
  sits, with a regression test.
- Removed the now-unused `gemma4_attention_prefill_bf16` import from
  `gemma4_layer.py`; the layer reaches attention through the selection.

## What is not claimed

- **The production numerical gate is not run.** `docs/EXECUTION-PROFILES.md` §6
  wants a KL envelope over full-vocabulary teacher-forced rows. Twelve identical
  greedy rows at four prompt lengths are a screen, not that gate, and the entry
  in `docs/REFACTOR.md` records it as outstanding for both candidates.
- **No float64 reference and no quality metric.** Correctness is measured against
  the strict kernel at a declared four-BF16-ulp bound (worst observed 3.4e-3
  relative to each case's output peak, 2.3x margin), not against the model.
- **One host, one session, one clock state.** Run-to-run spread between separate
  invocations reaches 10 percent, which is why the ratio is the headline and the
  ablation shares are quoted only from runs made in one batch.
- **The reference ladder is the recorded baseline, not re-run.** It is
  llama.cpp's `-p 512,1024,2048,4096 -n 128 -r 3 -ngl 99` on this host.
- **Decode is untouched.** This is a prefill kernel; decode still runs the strict
  attention path.

## Next

The next unit is not attention. At 4096 tokens the step is 4.189 s against a
4.000 s parity target, and 3.6 s of it is the expert block and the dense
projections. Within this kernel the remaining rate is the LDS fragment read
pattern (47 percent of the kernel between Q, K and V) and the staging global load
(25 percent), at 1 wave per SIMD and 60 bytes of spill -- a latency problem that
more waves made worse, not better.
