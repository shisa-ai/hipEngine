# the dense rate is a property of the shape, and it splits on the input-to-output ratio

## Summary

The dense probe attributes each projection shape at 512 prompt tokens. Running it again
at 1024 answers the question the 512 run could not: whether a slow shape is slow because of
its geometry or because of where it is called from.

| shape | 512 prompt | 1024 prompt | in/out |
| --- | ---: | ---: | ---: |
| `4096 -> 2816` | 6.59 | 6.81 | 1.45 |
| `8192 -> 2816` | 6.53 | 7.14 | 2.91 |
| `2816 -> 1024` | 7.24 | 7.31 | 2.75 |
| `2816 -> 2048` | 9.88 | 10.24 | 1.38 |
| `2816 -> 2112` | 10.38 | 10.92 | 1.33 |
| `2816 -> 4096` | 9.61 | 9.76 | 0.69 |
| `2816 -> 8192` | 11.56 | 11.57 | 0.34 |
| `2112 -> 2816` | 11.90 | 12.15 | 0.75 |
| lm head, 1 row | 0.42 | 0.42 | -- |

**Every rate is stable to within about 5 percent across a doubling of the prompt**, and
the ordering is identical. The 512-row tile is a tile, not the prompt: the `rows` column
reads 512 at both lengths and `n` doubles from 25 to 50 and 5 to 10. **So the rate is a
property of the shape, and the call site does not depress it.**

## The split

**The slow shapes and the fast ones separate cleanly on the input-to-output ratio:**

```
in/out >= 1.45   ->  6.5 to 7.3 TFLOP/s     4096->2816, 8192->2816, 2816->1024
in/out <= 1.38   ->  9.6 to 12.2 TFLOP/s    2816->2048, 2816->2112, 2816->4096,
                                            2816->8192, 2112->2816
```

The threshold sits between 1.38 and 1.45. Note that **K alone does not explain it**:
`2112 -> 2816` reaches 11.90 at K = 2112 while `2816 -> 1024` reaches 7.24 at K = 2816,
and **the two orientations of the same weight matrix separate too** -- `4096 -> 2816` and
`2816 -> 4096` are both 11.5M weights and run at 6.59 and 9.61, and `8192 -> 2816` and
`2816 -> 8192` are both 23.1M and run at 6.53 and 11.56.

**The mechanism is not established.** The ratio correlation is empirical, measured on nine
shapes at two prompt lengths, and a plausible mechanism -- a tile count that changes at
some width -- has not been checked against the kernel's tiling.

## The addressable size

At 512 prompt tokens the slow shapes are 44.79 + 18.10 + 2.04 = **64.9 ms of the dense
term's 189.8**, and 9.4 percent of the whole prefill. Bringing them to the family's fast
rate would save roughly **22 ms, 3.2 percent of the prefill**. That assumes a rate the
shapes may not be able to reach and is an estimate, not a measurement.

## Next

- **Read the Q8_0 dense prefill kernel's tiling and count its tiles for `4096 -> 2816`
  against `2816 -> 4096`.** Those two are the same weight count and differ 1.5x in rate,
  which is the sharpest available contrast and it isolates orientation from size. If the
  tile counts differ, the mechanism is tiling and the lever is a tile choice; if they do
  not, the ratio correlation is a coincidence and this line should be dropped.
- **Do not read the ratio as a law.** It is a fit to nine shapes at two prompt lengths.
  The two-orientation contrast above is the experiment that would make it a mechanism.
- **The dense term's fast shapes are not the target.** 9.6 to 12.2 TFLOP/s across five
  shapes of four different geometries is a narrow band, and there is no evidence that a
  higher rate is available for them.
