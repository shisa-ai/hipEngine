# Keep sampled verifier logits across graph fallback

## Summary

A staged device sampling plan did not guarantee that graph verification ran. On an eager fallback, the adapter requested neither host nor device logits, then uploaded an empty `(rows, 0)` array and invoked the full-vocabulary sampler on the resulting four-byte allocation. This explains the previously observed `sampler_sort_tiles_kernel` memory fault without requiring a sampler-workspace lifetime defect. The allocation/consumer mismatch is reproduced by CPU tests; the original GPU fault is not intentionally repeated.

The depth repair in `24aa0d0f9` removes one trigger, but the accept step must remain valid when graph selection changes for another reason.

## Changes

- Native sampled verification always requests a resident logits view, including when a device sampling plan has been staged. The graph path keeps its device accept operation; the eager path now has the logits its existing accept walk needs.
- The accept walk checks host matrix shape and device pointer/span before upload or native sampling. It does not change sampling arithmetic, RNG state, or kernel selection.
- `tests/test_unit_mtp_sampler_lifetime.py` covers matching/mismatched candidate depths, complete host-logits upload, and empty, short, malformed, or null logits sources.
