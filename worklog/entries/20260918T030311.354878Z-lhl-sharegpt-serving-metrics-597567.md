# Report serving metrics and output identity in the real-workload harness

## Summary

The routing recorder reported route and attribution telemetry but not the
quantities that decide whether a routing change is a serving win. A run could
show 96% speculative coverage while completing requests more slowly, and nothing
in the artifact would say so. This unit makes the harness report completed
requests per second, time to first token, inter-token latency, and end-to-end
latency with p95 tails, plus a per-row output digest so two arms of the same
load can be checked for greedy exactness instead of assuming it.

This is the measurement half of the reviewer's P0: the next implementation
result must be judged on matched completed-request throughput and latency, not
on MTP coverage.

## Changes

- `scripts/sharegpt_mtp_routing_pass.py`
  - `_inter_token_latencies_ms()` derives per-token latency from consecutive
    decode-state timeline reports; repeated counters are skipped rather than
    divided by zero. `_percentile()` gives the tail without pulling in numpy.
  - Rows gain `itl_median_ms`, `itl_p95_ms`, `itl_samples`, and
    `output_sha256` (a digest over the thinking and answer text, which keeps
    the artifact small enough to retain).
  - `summarize()` gains `median_e2e_ms`, `p95_e2e_ms`, `total_e2e_ms`,
    `median_itl_ms`, `p95_itl_ms`, `p95_ttft_ms`, `output_hashes`, and
    `duplicate_output_hashes`.
  - The run report gains `completed_requests_per_second` and
    `request_error_rate`, and the printed summary leads with completed
    throughput and the latency medians/tails.
  - Module docstring updated to say what the new numbers are for.
- `tests/test_unit_sharegpt_mtp_routing_recorder.py`: 4 new cases (17 total)
  pinning the ITL derivation including a repeated counter, the per-row
  digest/ITL fields, the serving-metric summary, and the earlier totals fix.

## Validation

- `uv run pytest tests/test_unit_sharegpt_mtp_routing_recorder.py`: 17 passed.
- `uv run python scripts/sharegpt_mtp_routing_pass.py --help` parses.
- The one live run made with the previous revision of this file is a harness
  smoke test, not evidence: it used the fixed 48-token override and the first
  arm paid a cold provider warmup. Its rows are still readable because the
  digest and ITL fields are additive.
