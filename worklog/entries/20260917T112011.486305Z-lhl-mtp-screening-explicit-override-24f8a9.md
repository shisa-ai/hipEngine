# Explicit screening override reaches the serving plan layer

## Summary

An explicit `speculative_mtp: true` request can now select the dense MTP route
for a physical cell that no retained evidence row qualifies, when the operator
sets `HIPENGINE_MTP2_SCREEN_UNQUALIFIED_CELLS=1`. Before this change the serving
plan layer rejected the cell first, so the resident owner's existing screening
admission was unreachable for every rejection except a physical width miss and
an explicit request fell to pre-mutation K0 — the reason a default Qwen3.8
server (`--speculative-candidate-budget 4`, which matches no retained row) could
not serve MTP at all.

Automatic intent is unchanged and still fail-closed: `auto`, `enabled` without an
explicit request, and every automatic-eligible plan behave exactly as before.
Sampling-mode, artifact-identity, and memory-fit rejections also stay
fail-closed for explicit requests, because those are correctness boundaries
rather than unmeasured cells. Every screening admission is non-automatic by
construction and is marked in response metadata as
`qualification: explicit_screening_unqualified_cell` with `unqualified: true` and
the original rejection reason, so a tuning rate cannot be read as a qualified
route.

## Changes

- `hipengine/generation/qwen35_gguf_mtp2.py`: the screening switch is now the
  public `MTP2_SCREEN_UNQUALIFIED_CELLS_ENV` with the public
  `unqualified_mtp_screening_enabled()` helper (single source of truth for the
  adapter and the server); both are exported.
- `hipengine/server/api.py`:
  - `_MTP_SCREENING_REASONS` (qualification axes only) and
    `_MTP_SCREENING_QUALIFICATION`;
  - `_mtp_screening_static_eligibility()` builds a non-automatic
    `speculative_capable` eligibility carrying the requested depth, the server's
    physical width bound, and a screening fingerprint;
  - `_generation_route_for_request()` applies it for explicit unqualified
    requests, records `screening`/`qualification`/`unqualified_reason` on the
    plan, and no longer demotes those requests to K0;
  - `_realized_model_serving_plan()` carries the screening intent through the
    queue's realized re-resolution, which re-runs the same resolver and would
    otherwise drop it (this gap was found by the real-server run, not by the
    unit tests);
  - `_resolve_realized_generation_route()` keeps typed intent for screening
    decisions and reports `unqualified_cell_deferred_to_resident_owner`;
  - `_mtp_response_summary()` surfaces `qualification`, `unqualified`, and
    `unqualified_reason`.
- `tests/test_integration_server_api.py`: `UnqualifiedBudgetSpeculativeMTPFakeLLM`
  plus six tests covering the closed default, the override, automatic intent,
  the sampling-mode boundary, the realized carry-forward, and the response
  metadata.
- `docs/ENVS.md` (variable entry), `docs/REFACTOR.md` (extended removal scope),
  `docs/EXECUTION-PROFILES.md` §2.9 (the override does not weaken physical
  admission).
