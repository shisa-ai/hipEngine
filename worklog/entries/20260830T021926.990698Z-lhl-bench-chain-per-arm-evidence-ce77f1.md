# W7900: A/B chains must report per-arm exit status; add scripts/bench_chain.sh

## Summary

Three measurement chains on 2026-08-30 printed an unconditional completion marker while
an arm had failed or produced nothing: one floor-16 server arm died with `RuntimeError:
benchmark requires tracked-clean source` under an `SRV_DONE floor=16` echo, and two
chains (`CAND_RUN_DONE`, `ROUTECOUNT_DONE`) left 14-16 byte logs with no artifact
anywhere on disk. Two of those were only caught because I went looking for the missing
packet. Nothing in the tree enforced the convention, so I added the runner and wrote the
rule into the Benchmark Output Contract.

`scripts/bench_chain.sh TAG OUTDIR "NAME|COMMAND" ...` runs arms sequentially, tees each
arm's stdout+stderr to `OUTDIR/TAG-NAME.log`, exports `$CHAIN_JSON=OUTDIR/TAG-NAME.json`
for the arm's artifact, requires that artifact to parse with `status == "complete"`,
reports every arm's exit code in a summary, and exits non-zero unless all arms measured.
Arms that legitimately emit no artifact take a trailing `!` in their name and are
reported as `ok(no-artifact)`.

## Changes

- `scripts/bench_chain.sh` (new).
- `docs/BENCHMARK.md`: "Benchmark Output Contract" gains a paragraph stating that an A/B
  chain is one measurement per arm and that a bare `*_DONE` marker is not evidence.

## Validation

- `bash -n` clean.
- Self-test pass path: two arms (`good` writing a complete artifact, `smoke!` writing
  none) -> summary `ok` / `ok(no-artifact)`, `CHAIN_DONE`, exit 0.
- Self-test failure path: a writer that dies on a syntax error, an arm that `exit 3`s
  after printing, and an arm whose artifact says `status: aborted` -> summary reports
  `exit=1`, `exit=3`, `bad-artifact-status=aborted`, `CHAIN_FAILED`, exit 1. The dying
  arm's log retains its own output instead of a marker.
- No GPU was used, so the concurrent C1-C8 packet refresh was not perturbed.
