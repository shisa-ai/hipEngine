# Make TP2 bulk workspace contract fail closed

## Summary

`scripts/tp2_bulk_workspace_contract.py` summarized its own ladder with checks
that could pass on a broken run. It checked finiteness only on the first prefill
of each length, accepted any exception as a valid over-capacity refusal, called
a sufficiently large final workspace proof of reuse, accepted an empty variant
list vacuously, and recorded a raw `argmax` with no oracle. The verdict logic is
now pure and fail-closed, with focused CPU tests that reproduce each former gap.

## Changes

- `scripts/tp2_bulk_workspace_contract.py`
  - Extracted `evaluate_variant_checks()` and `summarize_checks()` as pure
    verdict functions over a ladder record; `main()` now calls them instead of
    inlining `all(...)` expressions.
  - Capacity refusal now goes through `_probe_capacity_refusal()`, which only
    catches `ValueError`. Any other exception propagates as a harness failure.
    A `ValueError` is only accepted when `_is_capacity_refusal()` matches the
    exact expected type, row count, and capacity in the message.
  - Each measured prefill repeat records `_logits_facts`; every repeat must be
    finite and the same shape as the first call. The first output must be a
    2-D `(1, vocab)` block with positive elements.
  - `generate` completion is meaningful: decode steps and generated token count
    must each equal `--decode-tokens`.
  - Revisit is verified two ways: `workspace_rows_before ==
    workspace_rows_after_first` and the device-buffer pointer signature
    (`_workspace_allocation_signature`) is unchanged. Row count alone is no
    longer treated as allocation identity.
  - `--variants` must name at least one variant; `--decode-tokens` and
    `--repeats` must be positive.
  - Refusals must exactly cover the lengths above the pinned capacity
    (`refused_lengths_match_expected`); a missing refusal is now a failure.
  - `argmax` is renamed `last_row_argmax_diagnostic` and never feeds a check.
    Records now carry `oracle_scope` (finiteness and completion counts only, no
    numerical/KL/top-1/argmax oracle), `exact_command`, and git source
    revision/dirty state via `_git_source_state()`.
- `tests/test_unit_scripts_tp2_bulk_workspace_contract.py` (new): 33 CPU tests
  over the pure helpers and synthetic ladder records.

Diagnostic ladder preserved: same lengths/order/revisit, same three workspace
variants, same timing fields and warmup.

## Limitations

- `oracle_scope` is finiteness/shape/completion only. A finite all-zero
  generation still passes the completion-count check because this harness has no
  teacher to call a token correct. Do not cite its `argmax` field as a quality
  verdict.
- `generate` runs without `capture_logits`, so decode-step logit finiteness is
  not inspected; only its step and token counts are checked.
- The committed pre-change artifact
  `benchmarks/results/2026-09-25-w7900-tp2-bulk-workspace-contract.json` is not
  rewritten. This change does not claim the historical non-finite result is
  explained.
