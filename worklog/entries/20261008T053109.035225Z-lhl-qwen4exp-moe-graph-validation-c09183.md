# Per-layer MoE decode graph validated: +3.2% decode over eager

## Summary

The first complete-engine A/B of the existing per-layer MoE decode graph (the
gfx1151 production default, capability QWEN4_EXP_MOE_GRAPH=True) measures it
against the eager fallback: **decode 16.328 -> 16.846 tok/s (1.0317x)**,
aggregate client wall 480.532 -> 471.854 s (0.9819x), prefill exactly unchanged
(the graph engages only at rows=1). One residency, 12 canonical cases,
balanced arms, engagement from the cache's own stats (48 captures, 18,432
replays per case-arm, zero rejects), all trajectories cross-mode exact and
within-mode deterministic, clean teardown. Because the graph is already the
default, this is the missing qualification evidence for it - not a promotion.

The A/B also recalibrates the decode-depth model: the rocprof stall
decomposition describes the eager fallback path (HIP graph capture under the
profiler runs eager), so production decode is ~3.2% better than the traced
model, and the remaining p4096 stall mass sits outside the MoE graph envelope -
in the dense projection chain (not yet captured), the attention/GR sections,
and the host preparation before each per-layer graph launch.

- Same-residency A/B: 72 balanced arm samples, cross-mode outputs exact on
  12/12 cases, within-mode deterministic, zero capture rejects, zero
  allocations after close.
- The cache's self-validating parity guarantees bit-identical replay (a
  failing capture is rejected to eager); the A/B independently confirms via
  output digests.
