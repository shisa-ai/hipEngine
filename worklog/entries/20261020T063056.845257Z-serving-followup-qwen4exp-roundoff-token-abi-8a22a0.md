# Use the embedding token ABI in long-context controls

## Summary

The round-off-control helper uploads an `int32` token into the runner's
8-byte token buffer, but the registered embedding lookup reads `int64_t` IDs.
The pointer-only copy defaults to the destination's size and reads four bytes
past the host source. Consequently the control can read a different embedding
or leave its output untouched. Its one-element perturbation is not established.
Use the kernel's 64-bit input format and the source's explicit byte count.

## Changes

- Correct `_embedding_bits()` only; runtime and kernels are unchanged.
- Add a fake-copy regression that reads the actual 64-bit source value and
  checks the explicit copy length. It fails on the old helper.
- Preserve old controls as invalid evidence. Replacing their floor requires
  recapturing every control through the repaired helper with unchanged seeds,
  prompt hashes, profiles, evaluator thresholds and unperturbed trajectories.
