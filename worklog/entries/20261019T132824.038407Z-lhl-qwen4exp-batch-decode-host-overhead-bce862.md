# Flash-Next batch decode host overhead

## Summary

The N-row `Qwen4ExpGGUFBatchRunner` was slower than the c1 runner at one row
and barely faster at four because the host, not the GPU, set the step time.
A rocprofv3 kernel trace of one decode step (gfx1151, production profile,
4,096-token context) showed the GPU busy for 42.4 ms of a 70.3 ms width-1 step,
against 39.9 ms of a 45.6 ms c1 step; at width 4 it was busy 64.8 ms of
103.6 ms. The c1 runner graph-captures its stateless layer segments; the batch
runner launched about 1,450 kernels eagerly per step and added:

- a `load_backend_kernel_package` call in the PLE stage on every step, which
  re-walks the whole backend registration (one 4.5 ms gap per step);
- about 86 synchronous host-to-device copies per step from `prepare` calls that
  re-uploaded unchanged slot indices and block tables;
- two full-buffer selection uploads per QSA layer per step, issued mid-step,
  for dense rows whose selection is always `arange(context)`.

The same trace exposed a defect: the row-wise argmax scratch was sized for one
row (`stage1_blocks`, not `rows * stage1_blocks`). Allocation rounding hid the
overflow up to four rows; at width 5 and above the step returned token ids
outside the vocabulary. The documented "qualified maximum of four slots"
coincided with that boundary.

## Changes

- `hipengine/runtime/qwen4_exp_batch_runner.py`: every GDN and QSA layer runs
  as two captured segments keyed by `(layer, rows)` around the eager stateful
  mixer core (GR read plus input projections; output projection, GR write, FFN
  read, MoE, GR write). The cache is the existing self-validating
  `MoeGraphCache`; the residual is passed as a mutable input because
  consecutive layers write their output over it. A `graph_segments=False`
  constructor argument keeps the eager path for tests. Argmax scratch is sized
  `state_slots * stage1_blocks`. `graph_stats` reports capture/replay counts.
- `hipengine/runtime/qwen4_exp_batch_gdn.py`, `qwen4_exp_batch_qsa.py`: the
  batch mixers are split into validate / input projections / stateful core /
  output projection functions; the composed mixer functions keep their
  behaviour. Selection staging keeps every row's device positions as
  `arange(stride)` (the kernel reads only `positions[r, :counts[r]]`), rewrites
  a row only after a sparse selection overwrote it, and uploads counts only
  when they differ from the device copy.
- `hipengine/runtime/qwen4_exp_batch_gdn.py`, `qwen4_exp_batch_state.py`: skip
  the slot-index and block-table uploads when the host mirror shows the device
  already holds them.
- `hipengine/runtime/qwen4_exp_batch_ple.py`: refresh the backend package only
  when the indexed PLE conv key is missing.
- `hipengine/runtime/qwen4_exp_runner.py`: the grouped MoE route's memsets are
  stream-ordered (`memset_async`) so a capture records them; eager callers on
  stream 0 keep the same ordering.
- `hipengine/runtime/moe_graph.py`: clear HIP's last error after a capture
  attempt. A unit that cannot be captured (the Q8_0 expert-down layers read a
  tile count back to the host at two or more rows) left the error set, and the
  next eager kernel's launch check failed with error 901.

## Validation

Host zbook (gfx1151), unsloth Flash-Next `UD-Q4_K_XL`, production profile,
4,096-token context, 74-token prompt, 16 timed steps after warmup, in-process
(`Qwen4ExpGGUFBatchRunner.step(capture_logits=False)` against
`Qwen4ExpGGUFResidentModelRunner.step`):

| width | before ms | after ms | after aggregate tok/s |
| --- | --- | --- | --- |
| c1 runner | 45.1 | 45.6 | 21.9 |
| batch 1 | 71.8 | 48.9 | 20.4 |
| batch 2 | 97.0 | 62.6 | 31.9 |
| batch 4 | 97.5 | 71.4 | 56.0 |
| batch 8 | failed (vocab) | 88.5 | 90.4 |

- Graphed vs eager (`graph_segments=False`) batch runners on the real model,
  same imported states: logits bit-identical on all 48 steps of a schedule that
  crosses widths 1-5 with permuted slot order, and on 32 steps with two rows
  past the dense bound (2,242 and 2,381-token prompts, sparse selection). One
  segment per width is rejected (the host-readback MoE layer) and runs eagerly.
- New GPU tests: graphed-vs-eager bit-exact across a width/permutation schedule
  and KV bytes; argmax scratch covers every slot (RED against the old sizing:
  `assert 4 >= 6 * 1 * 4`).
- Qwen4Exp unit and GPU bundle (308 files plus graph-capture tests):
  3,037 passed, 3 skipped.
