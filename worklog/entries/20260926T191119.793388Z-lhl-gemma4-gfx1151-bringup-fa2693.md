# Bring the Gemma 4 26B-A4B path up on gfx1151

## Summary

Two units landed together because the second was blocked on the first: the
`gemma4` branch was synced with current `main`, then the Gemma 4 public path was
brought up on the Strix Halo host (`gfx1151`, Radeon 8060S). The generator was
registered only for `hip_gfx1100`, so on this box `LLM(model=<gemma4 gguf>)`
resolved the auto backend to `hip_gfx1151` and failed with a named missing
generator. Registering the same factory under `hip_gfx1151` fixes the public
path; no kernel or arithmetic change was needed because the gfx1151 package
already aliases the gfx11 bodies and the JIT compiles them for the native arch.

## Changes

- `merge 71eaaf019`: sync `gemma4` with `main` `f26bccbe8` (published
  `9c31ba9fe` plus the local DMS/serving and audit-triage commits). This is a
  merge rather than a history rewrite because `origin/gemma4` is shared and the
  project syncs long-lived branches with merge commits (`gfx1151`'s
  "merge: bring main into gfx1151"). Resolutions: keep both `docs/REFACTOR.md`
  ledger sections, both synthetic-weight fixture families (Q5_1 and Q3_K), and
  both benchmark `CHANGELOG.md` entry sets; take main's Halo-box README
  paragraph; regenerate the audit inventory/findings and the docs indexes.
  Re-recorded the 17 `doc-path-drift` and 7 `ungoverned-flag-branch` decisions
  the merge shifted, and triaged the two Gemma Q5_1 compact-GEMV kernel rows as
  `EXACTNESS-REJECT`/keep with the recorded gate failure.
- `hipengine/generation/gemma4_gguf.py`: one backend-parameterized
  `make_gemma4_generator` factory with `make_gemma4_generator_gfx1100` and
  `make_gemma4_generator_gfx1151` wrappers, and registration under both
  backends. The gfx1100 wrapper keeps its name and signature so existing
  callers and tests are unchanged.
- `tests/test_unit_build.py`: clear `HIPENGINE_HIP_ARCH` /
  `HIPENGINE_HIP_OFFLOAD_ARCH` before the fake cached artifacts are planned in
  `test_build_hip_fast_path_honours_environment_changes`. The arch flag is part
  of the cache key, so an ambient `HIPENGINE_HIP_ARCH` (this host exports
  `gfx1151`) keyed the fixture differently from the build call under test and
  the test failed with a misleading `require_cached` error.
