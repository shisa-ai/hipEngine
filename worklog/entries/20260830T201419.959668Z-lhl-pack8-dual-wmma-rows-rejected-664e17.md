# pack8 dual-WMMA prefill owner rejected at exact suite rows

## Summary

Task #12's only remaining hypothesis was the operation-complete
`pack8_dual_wmma_prefill_bf16_bf16_out` owner that gfx1100 registers but never dispatches, because
`_pack8_dual_wmma_silu_dispatch` additionally requires a backend capability plus exact shape qualification and
gfx1100 declares neither. The single declared instance is gfx1151 at `(512, 1024, 3584)`, whose +13.8% the
handoff correctly labelled a hypothesis rather than W7900 evidence. I measured the pair directly at the exact
rows this suite produces and the hypothesis is **dead for this workload**: the fused owner is
**14.6%-40.5% slower at every row** (geomean 0.78x) and only wins from ~110 rows up, which explains gfx1151's
row-512 declaration as a crossover artefact. No declaration was made and no production arithmetic changed.

The measurement also exposed a gap that matters more than the rejected candidate: nobody has ever named the
kernel that owns the FFN gate/up pair at rows 35-67 on this backend. See *Next*.

## Changes

- `scripts/gguf_pack8_dual_wmma_row_microbench.py` (new). Kernel-level, one process, one weight pair
  uploaded once. Per row it times three arms twice each (forward and reversed order) at
  `(rows, 5120, 17408)`: `production_dual` (pack8 dual prefill + standalone SiLU, 2 launches), `wmma_pair`
  (per-side pack8 WMMA prefill + standalone SiLU, 3 launches), and `wmma_dual_silu` (the candidate owner, 1
  launch). It records host identity, git commit/dirty state, both pass medians, best-of-two, spread,
  ULP/max-abs divergence versus the reference arm, and finiteness. Ratios are uniformly reference/candidate so
  `> 1.0` always means the candidate is faster, and an arm that wins in only one order is not a win.
- `benchmarks/results/2026-08-30-w7900-q4km-pack8-dual-wmma-rows-rejected.json` (new) and one
  `benchmarks/CHANGELOG.md` one-liner. No `benchmarks/README.md` row: this is a rejected microbenchmark, not
  a retained scoreboard row, matching how the all-GEMV rejection was recorded.
- No changes to `hipengine/kernels/hip_gfx1100/__init__.py`. gfx1100 still declares no
  `GGUF_Q4_PACK8_DUAL_WMMA_SILU_PREFILL`, `_SHAPES`, or `_POLICIES`; the strict per-side chain stays the
  owner and the fallback, and `HIPENGINE_GGUF_Q4_PACK8_DUAL_WMMA_SILU_PREFILL=0` stays the kill switch.

Two instrumentation faults were caught and corrected before any number was kept, both recorded in the
artifact:

1. The first version fed randomly generated pack8-shaped byte arrays to every arm. The gemv-family consumer
   does not read that layout; the misread path timed at ~18 GB/s and the arms disagreed by 34264 BF16 ULPs.
   The harness now builds payloads with the shipping repacker and asserts finite outputs. Every number from
   that run is void, including an earlier "fused loses by 25%" reading that was directionally right but
   computed from invalid bytes.
2. The first win flag compared `candidate/reference` while the ratio field carried `reference/candidate`, so
   losers printed as winners. The direction is now uniform and stated in the docstring.

## Next

- Name the real small-row FFN pair owner before any further prefill work. The pair fallback owner
  (`gguf_q4_k_pack8_dual_prefill_bf16_bf16_out`, from the gemv family) costs 6.2 ms at 35 rows and 12.0 ms at
  67 and scales linearly with rows, but 64 layers x 6.2 ms is ~0.40 s against the published ~0.235 s C1
  admission wave, so it cannot be what the shipping AR path runs. gfx1100 declares no
  `GGUF_Q4_PACK8_WMMA_BULK_PREFILL`, which is what would route the pair to the 1.20-1.48 ms per-side WMMA
  leaves, and the `GGUF_Q4_T16_DUAL_WMMA_SILU` family qualifies from row 33. One `rocprofv3 --kernel-trace`
  over a single real 35-row AR prefill (prebuilt `.so`, precomputed compiler-version file, `require_cached`,
  per `docs/KERNELS.md`) decides between "needs new kernels" and "one missing measured capability declaration
  worth 4-8x on the FFN pair". Do not guess from source again; this task's premise was a source reading and it
  survived exactly one measurement.
