# Live startup check: the probe preflight needed the LLM wrapper

## Summary

The width preflight committed in `660f9b414` was a no-op on a real server. It looked
for `resident_capacity_estimate` on the `LLM` the server holds, and `LLM` delegates
generator hooks through explicit methods rather than attribute passthrough, so the
lookup found nothing and every probe ran at its configured width. The unit tests
passed because their fake engines carried the method directly.

Found by restarting the server at the width that failed, with the preflight in the
binary. The retry path from the same commit did run and did save that startup.

## Changes

- `hipengine/llm.py`: `LLM.resident_capacity_estimate` delegates to the generator,
  mirroring `prepare_request_scratch`. `None` when the backend has no resident
  capacity model, which leaves the caller's width unchanged.
- `tests/test_unit_llm_generate.py`: asserts the delegation reaches the generator and
  that a generator without the hook returns `None`.
- `docs/REFACTOR.md`: records that a failed wide probe can leave the process unable to
  allocate the next startup stage, with the rollback check that would clear it.

## Validation

- `pytest tests/test_unit_llm_generate.py tests/test_integration_server_api.py`:
  692 passed.
- Live, `--max-active-requests 4` on the 120 GiB box (Qwen3.8-27B-Q4_K_M, resident
  context auto-sized to 100864 tokens), with the fix:

  ```
  WARNING:  STARTUP_SCRATCH_PROBE: width 4 reduced to 1; 4 concurrent sessions need
            107.18 GiB against 26.85 GiB usable
  INFO:     STARTUP_SCRATCH_PROBE: ... max_batch_size=1 release_after_probe=True
  INFO:     hipEngine is ready.
  ```

  `/ready` reports `startup.checks.scratch_probe.status = "reduced"`,
  `requested_max_batch_size = 4`, `max_batch_size = 1`, `scratch_probe_s = 0.446`, and
  the diagnostic line above. `mtp_smoke` passed with
  `realized_route = speculative_mtp`.
- Live, same box and width, without the fix (previous commit): the probe ran at width
  4, took the ladder down 100864 -> 50432 -> 25088 -> 12544 with four HIP out-of-memory
  errors, then the retry at width 1 logged
  `STARTUP_SCRATCH_PROBE: width 4 failed to allocate (...); retrying at width 1`, the
  probe passed, and the chat smoke then failed with
  `HipError: HIP error 2: out of memory` during prefill. Startup ended with
  `Application startup failed. Exiting.` -- the new exit path, working.
- Live, user's config (no `--max-active-requests`), final state left running:
  `/ready` 200, no diagnostics, probe `passed` at width 1, `mtp_smoke` on the
  speculative route, `startup_total_s = 58.45`. First explicit-MTP `/bench` request on
  the fresh process: TTFT 1.33 s cold, 0.57 s cached.

## Next
