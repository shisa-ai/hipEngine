# Review the activation-workspace handoff and qualify unsupported claims

## Summary

Source inspection confirms that Qwen4Exp does not bind the wide-F16 activation
workspace. This entry corrects overstatements in
[the previous synthesis](20260926T130638.338457Z-lhl-qwen4exp-campaign-re-review-09eb84.md)
without changing its immutable text. The missing binder remains the next
implementation task; no performance gain has been measured for it.

## Changes

- Qualify the MoE spill explanation as a hypothesis rather than a proven
  compiler-allocation cause. LDS placement of flags does not identify every
  source of register pressure.
- Treat the QSA comparator difference as an investigation budget, not proven
  recoverable time. Arithmetic-preserving changes still need integrated
  correctness checks.
- Preserve shared workspace helpers used by Qwen3.5/3.6 even if a Qwen4Exp
  experiment fails. Flag removal also requires non-regressive performance.
- Distinguish the existing Qwen3.5/3.6 1024-row owner from the as-yet absent
  Qwen4Exp owner. Measure chunk/hoist interaction rather than asserting its
  magnitude. Correct the percentage direction: today's throughput is about
  32% higher, not the earlier throughput 32% lower.
- Align the numbered priorities with the previous decision's experiment order.

## Validation

- Rechecked `gguf_linear.py` workspace binding, size check and dispatch hook;
  `qwen35_gguf_runner.py` owner and context; and Qwen4Exp workspace selection,
  chunk execution and close paths. The tree-wide search still finds only the
  Qwen3.5/3.6 production binder.
- `python3 scripts/worklog.py check` and `git diff --check` pass before commit.
- ROCm is available through `/tmp/run-gpu.sh`: `ctypes.CDLL` succeeds and
  `rocminfo` identifies Radeon 8060S / gfx1151. The unconfigured default shell
  cannot find the library; this is not evidence of ROCm corruption.
- No new numerical or performance result. External upstream claims have not
  been independently re-fetched in this review.
