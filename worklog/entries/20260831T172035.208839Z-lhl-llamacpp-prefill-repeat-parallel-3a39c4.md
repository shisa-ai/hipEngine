# Decouple peer widths from server capacity

## Summary

The first task-#33 current-HIP C5/C6 attempt was invalid before comparison:
selecting `--widths 5,6` changed the server command from the published `-np 8`
to `-np 6`. That capacity change can alter memory/scheduling and measured only
about 230-250 prompt tok/s, so the packet is void rather than evidence of peer
regression.

## Changes

- Added independent `--parallel` capacity, default 8, and recorded it in packet
  protocol metadata. Narrow measured widths now preserve the published `-np 8`.
- Fail closed when capacity is below the largest requested width.
- Extended the CPU contract for C5/C6 and C8 subset plans.
