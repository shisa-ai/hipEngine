# Add default-off P9 automatic qualification policy

## Summary

Add the exact P9 C1/K2 automatic product policy as a default-off qualification
route while keeping normal `auto` on K0. This is not promotion. The temporary
`HIPENGINE_SPECDEC2_P9_AUTO_QUALIFY=1` adapter lets clean product gates exercise
the real automatic server route and will be removed on either final promotion
or rejection.

## Changes

- Extend immutable offline cells with optional artifact/backend/profile-manifest/
  KV/context/horizon constraints included in their canonical fingerprint.
- Define a product-candidate policy for the exact Qwen3.8 Q4_K_S artifact on
  hip_gfx1151, production manifest, BF16 KV, C1, prompt 1-128 tokens, horizon
  25-64, K2. Every mismatch selects stable pre-mutation K0.
- Keep `DEFAULT_AUTO_DEPTH_POLICY` K0; server chooses the candidate only under
  the qualification env adapter.
- Resolve streaming auto route through the same policy before selecting a
  backend streamer, and expose plugin/profile-derived scope through `LLM`.
- Add the removal trigger to `docs/REFACTOR.md`.

## Validation

- RED policy tests fail because old cells accept only C/horizon and server auto
  never selects the candidate.
- GREEN policy **23/23** and focused server auto/default tests pass; default auto
  remains K0 without the override.
- Real cached production server with the override: D25 and p128/D25 blocking
  select automatic K2 and match AR; h24, h65, and p512 report default/K0; D25
  SSE returns the same 25 generated IDs; final active ownership is zero.
- Boundary evidence: D8 exact but 1.058x AR; D25 1.409x; D64 1.582x; D128 has a
  deterministic 3/3 divergence at token 81. p128 D25/D64 is exact at
  1.291x/1.506x; p512 D25 is only 1.008x with one category regression. Long
  p4K/p16K remains exact `target_context_k0` with no provider mutation.
