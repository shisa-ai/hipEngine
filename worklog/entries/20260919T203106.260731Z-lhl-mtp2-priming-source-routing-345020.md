# Route speculation by priming source: refuse the sink, keep the intent, and reject stale or partial prompt buffers

## Summary

Task #22. A sink refusal used to mean two different things at once -- "this row
cannot stream its prompt" and "this row may never speculate" -- and the refusal
paths answered both by zeroing `mtp2_candidate_budget`. That conflated a
transient scheduling outcome with a property of the row, and it left the row's
actual priming source unchecked.

The rule is now explicit in one place, `_priming_source(request_id)`, which
returns where a row's draft-provider state would come from and whether that
source is usable:

| class | source | decision |
| --- | --- | --- |
| live | provider state already attached to the row | speculate |
| valid buffered priming | complete prompt buffer, at the row's first draft step | speculate |
| stale buffered priming | prompt buffer behind the row's position | refuse, serve AR |
| partial buffered priming | prompt buffer missing rows | refuse, serve AR |
| absent | neither state nor buffer | refuse, serve AR |
| unsupported priming | reused prefix, unsupported target profile, prompt past the context window, operator-disabled streaming | refuse permanently (budget 0) |
| temporary contention | another prompt activation holds the claim | refuse the *sink* only; intent survives |

Two ways a buffered prompt could be present but unusable were invisible before:

- **Stale.** The catch-up walk leaves the provider at the row's first draft
  step: it hands the target the last prompt hidden row, which the draft step
  consumes together with the next root token. That is the row's current
  position only while it has generated at most that one token. A row admitted
  later -- after a refusal that has since cleared -- would draft from the
  prompt's end while the target is several tokens ahead. Because the target
  verifies every candidate, the cost is silent acceptance loss rather than a
  wrong answer, which is why it needed a refusal rather than a fix-up.
- **Partial.** A prompt that started without a sink leaves a partial buffer, and
  `_catch_up_provider` raises `ValueError` when the shape disagrees with the
  prompt. A scheduling outcome therefore surfaced as an engine execution
  failure instead of an autoregressive fallback.

## Changes

- `hipengine/speculative/accounting.py`: `PRIMING_SOURCE_LIVE` /
  `PRIMING_SOURCE_BUFFERED` / `PRIMING_SOURCE_ABSENT` and `PRIMING_SOURCES`,
  next to the readiness vocabulary they answer to.
- `hipengine/generation/qwen35_gguf_mtp2.py`:
  - `_priming_source` -- the routing rule above, including why a source that
    cannot be inspected (no `shape`, no `prompt_ids`) is reported valid rather
    than refused.
  - the capability gate refuses on `_priming_source(...)[1]` instead of on
    "neither state nor buffer", and reports that reason as the row's
    readiness (so a partial or stale buffer reads as absent-with-reason rather
    than as `prompt_buffered`).
  - `begin_prompt_streaming`: the in-flight branch no longer zeroes the budget.
    It records the row in `_streaming_refused_requests`, because the caller
    prefills a refused row's chunk without a sink, so a later chunk could only
    add a partial buffer. A mixed call still carries its streaming rows.
  - `_drop_request` clears that set.
- `hipengine/generation/qwen35_gguf.py`: the admission-intent comment now states
  which refusals do zero the budget (the unsupported class) and which do not.
