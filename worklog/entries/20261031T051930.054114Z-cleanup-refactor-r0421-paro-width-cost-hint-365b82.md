# Make PARO native width artifacts cost hints, not admission

## Summary

The native c>N benchmark artifact no longer decides whether an implemented
native path runs. Executable widths are derived from the session's
`max_batch_size` and the backend's existing full-attention row-chunk
declaration; exact widths are the complement of that declaration. The artifact
annotates those widths with measured costs and concrete failures.

Model snapshot, backend/architecture/quant/KV mismatch, measured decode
position range, a missing accepted performance claim, and a different
correctness oracle are cost notes. They cannot disable native. A missing or
`None` correctness field is missing evidence, not a failure. A present `False`
end-to-end check is a concrete failure and blocks native only when the
artifact declares geometry and its capability fields and geometry match the
session. A present `False` row finding excludes only that width under the same
match. Model directory identity is cost-only: renaming the same model cannot
change executable widths or blockers. A legacy artifact without `geometry`
keeps its findings as provenance and cost notes rather than widening them to
every model. A missing default artifact uses nominal costs. An explicitly
selected missing or malformed artifact raises its configuration error.

Both backends keep their existing contracts: gfx1151 exact widths are
`(2, 4, 8)` with `3, 5, 6, 7` row-chunked; gfx1100 exact is `(2,)` with
`3..8` row-chunked. Width 1 remains the scalar serial path. No kernel body,
arithmetic, launch dimension, schedule, scheduler, prefill-batching, or product
default changed.

## Changes

- `hipengine/dispatch/batch_width.py`: `NativeBatchWidthProfile` now carries
  `native_widths`, `exact_widths`, and `cost_notes`. The planner selects from
  those executable widths, prefers exact widths on equal cost, uses measured
  costs only when they apply to the capability/geometry and position envelope,
  falls back to `serial_row_step_ms * width` for unmeasured widths, never
  disables native on position, and reports `cost_source` as `measured` or
  `nominal`. Cost ties use a `1e-12` relative/absolute tolerance before the
  exact-width/group-count tie-break, so repeated nominal serial accumulation
  cannot beat a nominal c4/c8 cover through host float non-associativity.
- `hipengine/runtime/qwen35_paro_batch_width.py`:
  `native_batch_width_domain(max_batch_size, row_chunk_widths=...)` derives the
  executable/exact split. Negative findings match backend/arch/quant/KV plus
  an optional artifact `geometry` object compared against a caller-supplied
  `config_signature`; model snapshot is never part of that decision. The
  loader keeps present-false widths for non-matching or undeclared geometry as
  provenance notes, excludes them only for matching geometry, keeps widths
  with missing row evidence on nominal cost, raises for explicit
  missing/malformed artifacts, and labels nominal selection.
- `hipengine/runtime/qwen35_paro_runner.py`: width-loader method only. It
  derives the domain from `max_batch_size` and
  `_automatic_full_attention_row_chunk_size`, passes the explicit-artifact
  flag and a real model/session geometry signature, and keeps the three
  parent-owned `backend=self.backend` constructor additions untouched.
- `hipengine/generation/qwen35_paro.py`: width-loader and cost-gate consumers.
  Removed the prompt-position blocker. The isolated width path checks only
  `profile.blockers`. The helper passes the runner's model geometry signature
  when a config is available. Telemetry now records `cost_source` and
  `cost_notes` instead of `position_blockers`.
- Tests: `tests/test_unit_batch_width_dispatch.py`,
  `tests/test_unit_qwen35_paro_batch_width_profile.py`,
  `tests/test_unit_generation_qwen35_paro.py`, and
  `tests/test_unit_qwen35_paro_special_tokens.py`.

## Validation

- RED (contract mismatch): the pre-existing profile tests encoded the old
  admission contract and failed under the new loader
  (`blocks_identity_mismatch`, `blocks_diagnostic_only_artifact`,
  `requires_end_to_end_correctness_contract` for removed fields, and
  `falls_back_to_serial_outside_profile_context`). They were rewritten to
  assert the new contract rather than patched to keep the old one.
- RED (identity-keyed failures): the previous `geometry_applicable` expression
  combined capability with `model_matches`, so a geometry-matching artifact
  with a rejected c4 row excluded c4 under the artifact's model name but kept
  c4 under a renamed copy. The rename regression now requires identical widths
  and blockers for both names. Additional regressions prove a geometry mismatch
  and a legacy no-geometry artifact keep the width as provenance, while
  matching geometry still excludes c4.
- RED (nominal roundoff): with nominal weights only and
  `serial_row_step_ms=49.203623078682384`, the planner chose `(4, 2, 2)` for
  eight rows because the repeated host sums were one ulp below `c1 * 8`. The
  c8 regression now requires `(8,)`; the c4 tie regression requires `(4,)`.
