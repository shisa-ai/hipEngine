# Gemma 4 decoder layer forward assembled on gfx1100, matched to the reference

## Summary

`hipengine/kernels/hip_gfx1100/gemma4/gemma4_layer.py` runs a whole Gemma 4
decoder layer on gfx1100 and matches `gemma4_decoder_layer_forward` to **1.2%
(k_eq_v=False) and 1.4% (k_eq_v=True)** max relative, **~0.2% mean**.

This was the last missing capability in the kernel family. A new kernel was
needed for it: **Gemma 4 attention is ungated**, and every Qwen3.5 prefill variant
reads an attention gate and multiplies by `sigmoid(gate)`, while Laguna's ungated
kernel hard-codes Laguna's head geometry. Neither could be reused, so
`gemma4_attention.hip` adds `gemma4_attention_prefill_{bf16,f32}`.

## The layer structure the reference pins

```
residual = hidden
attended = attention(rmsnorm(hidden, input_layernorm))
hidden   = residual + rmsnorm(attended, post_attention_layernorm)

# Both feed-forward branches read the SAME pre-MLP residual and run in
# PARALLEL; they are not stacked.
residual = hidden
dense    = rmsnorm(down(gelu(gate(x)) * up(x)), post_feedforward_layernorm_1)
             where x = rmsnorm(residual, pre_feedforward_layernorm)
experts  = rmsnorm(moe(rmsnorm(residual, pre_feedforward_layernorm_2)),
                   post_feedforward_layernorm_2)

out = (residual + rmsnorm(dense + experts, post_feedforward_layernorm)) * layer_scalar
```

## Three composition bugs caught before the match

1. **The dense MLP needs a split GeGLU.** `gemma4_gelu_tanh_mul_bf16` operates on
   a *fused* `(rows, 2 * intermediate)` buffer with the gate in the first half.
   The GGUF stores `ffn_gate` and `ffn_up` as **separate tensors**, so that kernel
   cannot serve the dense branch. Added
   `gemma4_gelu_tanh_mul_split_bf16(gate, up, out, total)` to `gemma4_moe.hip`.
   The expert path keeps the fused form because `ffn_gate_up_exps` really is
   stacked — the two paths genuinely differ in the artifact.

2. **The k_norm must not run in place.** On `attention_k_eq_v` layers the
   reference binds V to the *raw* K projection and then normalises a separate
   `key` array. My first draft normed K in place and only then copied it to V,
   which would have given V the k_norm weight applied twice over. The k_norm now
   writes to its own `k_normed` buffer, and on `k_eq_v` layers V is the
   **weightless** norm of the raw K projection. This also removed the only
   device-to-device copy in the layer.

3. **The rope tables are doubled.** The kernels index a `(tokens, head_dim)`
   table built by `gemma4_rope_cos_sin_tables`; the reference builds its own
   half-width `(tokens, head_dim // 2)` tables internally. Passing the
   reference's half tables produced a 75% relative error — this was the failure
   that surfaced first.

## Two contract details the attention kernel deliberately does not assume

- **`scale` is 1.0, never `head_dim**-0.5`.** Gemma 4 folds the softmax scaling
  into the query norm weight. The kernel multiplies by whatever scale it is
  handed, and there is a test using `scale=0.37` — deliberately not
  `head_dim**-0.5` (0.17677669) — so a kernel hard-coding the reciprocal square
  root fails rather than passing by coincidence of geometry.
- **The mask is a caller-supplied *keep* mask**, not an implied causal test.
  Sliding-window layers need `key > query - window` in addition to
  `key <= query`, and which layers those are is a config decision. A test uses a
  sliding-window mask and asserts token 0's context is exactly `V[0]`, so a
  kernel that re-derived causality instead would attend over the whole prefix.

## Validation

- `pytest tests/test_unit_gemma4_gpu_kernels.py` — **48 passed** (41 prior + 7 new):
  - `test_attention_prefill_f32_matches_the_reference` — masked GQA against a
    hand-written f32 oracle.
  - `test_attention_prefill_applies_the_mask_it_is_given` — sliding-window mask;
    also asserts token 0's context equals `V[0]`.
  - `test_attention_prefill_scale_is_not_assumed` — `scale=0.37`.
  - `test_attention_prefill_bf16_tracks_the_f32_path`.
  - `test_layer_forward_matches_the_reference[False/True]` — the whole layer
    against `gemma4_decoder_layer_forward`, both `k_eq_v` variants.
  - `test_layer_forward_applies_the_layer_scalar` — runs the layer at 0.0703125
    and at 1.0 and asserts the ratio, so a dropped scalar (a ~14× error a loose
    tolerance would absorb) fails.
- Gemma 4 unit tier (GPU kernels, CPU reference, GGUF loader, materializer,
  tokenizer, streaming): **129 passed**, exit 0.
- `ruff check` clean; `python3 audit/audit.py check` exit 0.

The layer tolerance is 3%, about 2× the measured 1.4%, chosen so the guard still
catches structural errors (which land 10–100× larger) instead of absorbing them.
