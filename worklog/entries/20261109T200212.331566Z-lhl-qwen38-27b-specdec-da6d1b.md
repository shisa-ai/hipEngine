# EAGLE-4 parallel top-K: draft head 13->1.44ms, cycle +17.8% AR-exact (acc identical)

## Summary

Profiled the EAGLE-4 draft chain (task #32) and found the dominant cost was a hidden top-K inefficiency, not the assumed weight-bandwidth read. Replaced the naive single-block `eagle4_topk` with a two-stage parallel top-K: draft head **13.04 -> 1.44 ms** (9x), draft chain (2 steps) **36.3 -> 13.35 ms**, full-cycle decode **13.90 -> 16.37 tok/s (+17.8%)**, AR-exact with **identical acceptance (0.650)** — confirming the optimization is semantically exact.

## Changes

- `hipengine/kernels/hip_gfx1100/speculative/eagle4.hip`: replaced `eagle4_topk_kernel` (one workgroup, K serial full-vocab argmax passes) with `eagle4_topk_stage1_kernel` (one workgroup per disjoint 2048-element vocab chunk, each finds its local top-K; disjoint chunks make the -inf marking race-free) + `eagle4_topk_stage2_kernel` (one workgroup selects the global top-K from the compact G*K candidates). The launcher uses a persistent single-stream scratch grown on demand. The selected SET equals repeated global argmax; only boundary tie order can differ, which the downstream full-lm_head re-score + argmax makes irrelevant.
- `tests/test_gpu_eagle4_kernels.py`: added `test_gpu_topk_two_stage_large_vocab` (rows/vocab/K incl the real V=248320 and chunk-boundary/small geometries), comparing the top-K set to numpy argsort.
- Artifact: `benchmarks/results/2026-11-09-gfx1151-qwen38-27b-eagle4-topk-parallel.json`.

## Validation

- rocprofv3 `--kernel-trace` of the draft head: `eagle4_topk_kernel` 14.04 ms/head dominated; the full-V low-rank GEMM (`dflash_dense_bf16_to_f32_wmma`) was only 0.58 ms — disproving the "63 MB head read is the bottleneck" hypothesis. After the fix the head kernel-sum is ~1.5 ms.
- Microbench (drafter-only, synthetic context): efficient head 13.04 -> 1.44 ms; draft chain(2) 36.3 -> 13.35 ms; layer qkv+attend+ffn unchanged ~10.5 ms/step (now the dominant draft cost).
- `tests/test_gpu_eagle4_kernels.py` (7) + `test_gpu_eagle4_device_projection.py` (2) + `test_gpu_eagle4_kv_cache.py` (2): 11 passed. `test_unit_eagle4_cpu_oracle.py`: passed. `audit/audit.py check`: ok.
- Full mtpbench gate (10 prompts, 25 greedy outputs, 3 reps, n_draft=2, gfx1151/Qwen3.8-27B-Q4_K_M): **16.37 tok/s, 1.45x own concurrent AR, AR-exact, acceptance 0.650** (identical to pre-opt 0.650). +17.8% absolute vs the pre-opt 13.90 tok/s.
- RED note: this is a perf optimization; the RED anchor is the measured 14 ms top-k baseline (rocprof), and correctness is guarded by the argsort-set tests (the naive kernel was already correct, just slow).
- Caveat: throttled ZBook; AR reference drifted across runs, so the +17.8% absolute tok/s and identical acceptance are the clean signals, not cross-run ratios.
