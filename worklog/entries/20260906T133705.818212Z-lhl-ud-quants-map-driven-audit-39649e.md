# UD-U0b map-driven quant-route audit

## Summary

Completed the interrupted UD-U0b unit: `scripts/gguf_quant_route_audit.py` now
derives every route table from the actual production tensor maps — the AR map
from `build_qwen35_gguf_tensor_map` and the separate runtime NextN map from
`build_qwen35_gguf_nextn_tensor_map` — instead of regex-guessing slot names
over all disk tensors. Marks the two UD-U0 mapping checkboxes in
`docs/UD-QUANTS.md`; all other U0 items (artifact pin, allocation bytes,
policy/capability RED, schema versioning) remain open and are not claimed.
CPU-only throughout: no GPU/backend package import, no weights read, and no
model support or consumer qualification is claimed by any output.

Verified against the three pinned local files (metadata-only CLI smoke):
plain K_M 866 disk / 851 AR slots / 15 ignored / 0 refusals; UD K_M 271 AR
BF16-expansions + 18 refusals; UD K_S 264 + 41 — matching the corrected
numbers in docs/UD-QUANTS.md section 2 exactly. K_M refusals are Q3_K 7 +
IQ4_NL 7 + IQ3_S 4; K_S are Q3_K 13 + IQ3_S 15 + IQ3_XXS 5 + IQ4_NL 7 +
IQ2_S 1. Both UD files report the NextN draft dtype divergence (`eh_proj`
Q6_K versus the dense manifest's Q8_0, plus draft-block dtype swaps)
diagnostically while the AR report stays valid.

## Changes

- `scripts/gguf_quant_route_audit.py`:
  - `plan(backend, metadata, maps)` now plans AR consumer slots in production
    order (`root.<slot>`, `layers.<id>.<slot>`) through
    `plan_qwen35_gguf_materialization`; when the whole-AR plan refuses a slot
    it falls back to per-slot `plan_qwen35_gguf_weight_spec` calls that
    collect every refusal (no all-or-nothing failure). NextN routes are a
    separate `nextn_routes` report with `own` (`draft.layer.*`/`draft.nextn.*`)
    and `fallback` (`root.*`) scopes; NextN failures never discard the AR
    report. Repack for NextN mirrors the runtime default
    (`materialize_qwen35_gguf_nextn_weights` hardcodes `decode_repack=True`).
  - Replaced the old `mapping_result`/`plugin_tensor_map` section with a
    `tensor_map` section: the full map/source/alias summary when the map
    builds (`available: true`), otherwise `{available: false,
    diagnostic_only: true, error}`; backends then report no route table at
    all (parser-only audit, no guessed routes, nothing called loadable or
    consumer-qualified). `mapping_result` is removed.
  - `section["ignored"]` reduced to `{tensor_count, block_ids,
    nextn_tensor_count}` (names stay in `validation.ignored`).
  - Added `_ar_iq_contract`, a reporting-only mirror of the AR planner's
    raw-IQ repack veto; the veto itself is applied by the production planner.
- `tests/test_scripts_gguf_quant_route_audit.py`: corrected the interrupted
  draft's expectations to production behavior and added the per-slot refusal
  test. Corrections were probe-verified against the production planners, not
  assumed: (1) AR layers have 14 slots (linear) / 11 (full attention), so the
  64-layer fixture has 875 AR consumer slots / 874 unique sources and 889
  disk tensors, not 707/706/721; (2) a tied Q4_K head plans pack8 at
  `root.lm_head` — production's alias dedup keys on `(source, layout)`, which
  differ from the embedding's raw layout — so AR Q4_K routes are
  `{raw-gguf-kernel: 1, kernel:gguf_q4_k: 1}`, surfacing the
  duplicate-resident hazard instead of the draft's assumed `raw-gguf-kernel:
  2`; (3) NextN alias consumer slots carry the `nextn:` scope prefix; with
  optional block-local tensors present the combined alias count is 4, not 3.
- `docs/UD-QUANTS.md`: checked only the two fulfilled U0 mapping checkboxes.

## Limitations

- In `per_slot_fallback` mode the model-wide F32 contraction is not applied
  (`f32_contraction_applied: false` in the report): F32 alpha/beta/router
  slots report f32-resident there. The production-planner path applies it.
  This is the existing F32-contraction repair item, deliberately outside this
  unit (docs/UD-QUANTS.md U0 policy checkbox, docs/REFACTOR.md).
- Env-gated planner flags (`HIPENGINE_GGUF_C8_Q5_RAW_MMQ`,
  `HIPENGINE_C8_Q5_PLANAR_DP4A`) and the gfx1151 Q6 excluded-slot list are not
  wired (later U0 capability-policy checkbox).
- Route tables are per consumer slot through production planner semantics;
  they are diagnostics, not consumer qualification, and say nothing about
  whether a backend kernel accepts the file. Allocation bytes, sidecar
  listing, and refusal-scenario accounting remain open U0 items.
