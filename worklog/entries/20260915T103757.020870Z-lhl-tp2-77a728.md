# tp2 full-model mlp-only generation checkpoint: all production gates pass on w7900+rx7900xtx

## Summary

Packet 3 handoff step 2 is done: the full Qwen3.8-27B `Q4_K_M` model generates
tokens through the MLP-only TP2 runtime module (`hipengine/distributed/tp2_generate.py`)
on the real W7900 + RX 7900 XTX host, with the matched TP1 control run fresh on
each physical device and the calibrated production envelope deciding the
arithmetic gate. Result: the sharded model stays inside the envelope against
both controls, the controls agree bit-identically with each other, a repeated
TP2 run is bit-exact, and the integrated exchange trace prices the native- vs
host-driven exchange question. No TP2 speedup is claimed: TP2 decodes at
56.5 ms/token against 26.3 (XTX TP1) / 31.8 ms (W7900 TP1) on the diagnostic
eager schedule.

Hardware: device 0 AMD Radeon Pro W7900 (gfx1100), device 1 AMD Radeon RX 7900
XTX (gfx1100), one host, ROCm HIP. Model fingerprint a0b9749e2d7b.

The review packet's completion evidence now includes: per-GPU matched TP1
controls (bit-identical cross-device), full-logit teacher-forced production
gates vs both controls (PASS), TP2 deterministic repeatability (bit-exact), an
integrated per-layer exchange trace, and a does-it-fit answer at depth (XTX
rank holds full replica + shards with 0.75 GiB free after load).

## Changes

- `hipengine/distributed/tp2_generate.py`: `generate()` and
  `teacher_forced_logits()` now zero every rank's scratch state (KV spans, GDN
  conv/recurrent state) under its own device scope before running, so each call
  is a fresh sequence. Before this, a teacher-forced pass after a generation on
  the same session silently inherited stale recurrent state and produced badly
  wrong logits - that harness flaw (not a TP2 bug) caused the first E2E run's
  catastrophic KL 1.178. `_build_shard_group` pins a uniform `staging_dtype="bf16"`
  schedule (the artifact's Q4_K down projections register only a bf16 partial
  consumer); the Q6_K layers' registered f32-partial variant is recorded as a
  per-layer numerical candidate, not this run's schedule.
- `hipengine/distributed/staged.py`: `StagedExchangeTransport` gained a
  `staging_dtype` ("f32" | "bf16"); the pinned arena rows are staged in the
  partial dtype and the host sum widens bf16 bits to f32 (shift into the high
  half) before the single f32 reduction. The published payload stays f32.
- `hipengine/distributed/shard_exec.py`: `MlpShardRank` gained `partial_dtype`;
  the down GEMV launches bf16-out by default and f32-out only where the rank's
  partial dtype is f32; `read_partial` returns the right dtype either way.
- `hipengine/distributed/shard_group.py`: `MlpShardGroup` threads
  `staging_dtype` into both ranks and the transport.
- `scripts/tp2_mlp_generate_e2e.py` (new): three fresh sessions (TP1 on device
  0, TP1 on device 1, TP2 on both), four short prompts per arm across code /
  general-EN / general-JA / mixed categories, a fixed 16-token teacher-forced
  gate, TP2 determinism repeat, exchange-wall summary, memory readings, and the
  KL metrics gate vs `docs/EXECUTION-PROFILES.md` 6.1. Explicit
  `no_speedup_claim` field in the artifact.
- `benchmarks/results/2026-09-15-w7900-tp2-mlp-generate-e2e.json` (new): the
  committed artifact with all gates and walls.
- `tests/test_unit_scripts_tp2_mlp_generate_e2e.py` (new): 10 host-checkable
  tests for the gate math (softmax shift invariance on exactly-representable
  integers, hand-computed KL value, exact top-1 flip counting, envelope
  boundary semantics, shape-mismatch refusal) plus a HIP-guarded
  vocabulary-range test.
- `benchmarks/README.md`: full-model generation checkpoint paragraph (walls,
  gate metrics, bf16-staging note, memory headroom) and the artifact link.

  (`uv run python3 scripts/tp2_mlp_generate_e2e.py --json
  benchmarks/results/2026-09-15-w7900-tp2-mlp-generate-e2e.json`, exit 0):
  - `tp2_vs_tp1_teacher_device0`: mean KL 6.425e-04 (limit 1e-3), max KL
    5.246e-03 (limit 5e-2), top-1 100% (limit 99%) - PASS.
  - `tp2_vs_tp1_teacher_device1`: identical metrics - PASS.
  - `tp1_device0_vs_device1_control`: mean KL 0.000e+00, top-1 100% - the two
    physical cards execute the TP1 route bit-identically.
  - TP2 determinism: repeated generation tokens identical, teacher-forced
    logits bit-identical (max abs diff 0.0).
  - Decode p50 (matched composition): TP1@W7900 31.82 ms, TP1@XTX 26.30 ms,
    TP2 56.45 ms. Exchange: 9216 reductions over three generations + repeats,
    in-step wall p50 201.18 us, p95 237.76 us.
  - Generated text identical across arms and coherent (e.g. "The weather today
    is" -> " very nice.\nThe weather today is very nice...").
- Localization probes run while chasing the first gate failure (all in /tmp,
  not committed): per-position teacher-forced KL from a clean state was already

  sub-quantum partial deviations vs a NUMPY oracle - i.e. kernel-vs-numpy
  accumulation order plus the bf16 partial rounding, within the calibrated
  envelope in the full model. The real defect was the harness state leak fixed
  above.
- Unit tests: 10/10 new script tests; 17/17 in the transport/rank bundle
  (including two new CPU-pinned tests for the bf16 staging sum and the staging
  dtype validation); 121 passed across the full TP2 test bundle

  `test_gpu_distributed_shard_components.py`).
