# Use register lookup in tiled Inkling NVFP4 prefill

## Summary

Reuse the exact FP4 magnitude lookup already used by selected decode in the tiled NVFP4 prefill projector. This changes neither the packed layout nor the accumulation order.

## Changes

- Use register lookup for both shared-input and per-route-input tiles. No new runtime option or fallback is required.

## Validation

- The change is arithmetic-identical, so a behavior RED is not expected. The isolated control/candidate test (`python -u /tmp/hipengine_inkling_register_tile4_probe.py "$backend" "$control_so" "$candidate_so"`) matched all outputs bitwise on W7900 and Strix Halo. Both HIP libraries were compiled with `hipcc -O3 -shared -fPIC --offload-arch="$arch"`. Synthetic inputs used model-sized projection dimensions, 128 experts, uneven and skewed routes, and signed outer scales.
- At 64 uniform input rows on Strix Halo, HIP-event medians were 7.820/6.275 ms for shared gate/up and 3.869/3.173 ms for down (control/register, six samples per arm, eight launches per sample). The candidate also had lower event medians in the other tested cells on both GPUs. Logs: `/tmp/kendex-pi-bg/bg-118-1795365606569.log`, `/tmp/kendex-pi-bg/bg-119-1795365606588.log`. These are isolated kernel timings, not end-to-end or matched Loom evidence.
- The CPU deterministic bundle and focused W7900 GPU fixtures passed. Cached `rocprofv3 --kernel-trace` captured both tile input layouts with positive durations. `python -u ./hipengine_inkling_register_tile4_public_probe.py "$model" "$backend" "$control_so"` matched first-token logits bitwise at 151 input and all eight generated IDs at 151, 575, and 1,027 on W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL. Both tile layouts ran. Request medians were mixed across workloads, so the isolated kernel improvement is not an end-to-end claim. Logs: `/tmp/kendex-pi-bg/bg-120-1795365717608.log`, `/tmp/kendex-pi-bg/bg-121-1795365717627.log`, `/tmp/kendex-pi-bg/bg-122-1795365717646.log`.
