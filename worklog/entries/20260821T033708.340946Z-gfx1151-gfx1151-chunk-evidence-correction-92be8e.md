# Correct gfx1151 chunk-boundary evidence

## Summary

Review found that the retained 35B 512-row chunk artifact cited KL 0.00013 as
direct evidence for 512-vs-1024 even though the recorded oracle compared
256-vs-1024. Added a reproducible direct 512-vs-1024 oracle and corrected the
retained and null artifacts plus the tuning landscape/changelog.

## Changes

- Added `scripts/pn3_chunk_correctness.py`, which bypasses the geometry
  override and evaluates 1024 and 512 with independent fresh resident sessions
  at the same 2048-token input before computing KL, top-1, and max logit delta.
- Corrected `benchmarks/results/2026-08-20-gfx1151-qwen36-35b-prefill-chunk-512-retained.json`
  and `benchmarks/results/2026-08-21-gfx1151-27b-35b-prefill-chunk-512-vs-1024-null.json`.
- Updated `docs/GFX1151-TUNING-LANDSCAPE.md` and added a correction entry to
  `benchmarks/CHANGELOG.md`. The result is described as numerical, not exact.
- The first exploratory helper reused one session and produced run-dependent
  KL values; those measurements were discarded. Independent sessions match
  the original oracle structure and are the retained evidence.

## Validation

- Physical host: `gfx1151`, AMD RYZEN AI MAX+ 395 / Radeon 8060S, gfx1151,
  ROCm/HIP 7.15.0.
- Exact command, run twice: `uv run python scripts/pn3_chunk_correctness.py
  --length 2048`.
- Run 1: KL(l1024||l512)=0.00012652, top-1 9707==9707, max absolute logit
  delta 7.89071131.
- Run 2: KL(l1024||l512)=0.00013192, top-1 9707==9707, max absolute logit
  delta 9.61576939.
- Both runs pass the broad KL <= 0.05 and top-1 agreement floor.
- JSON parse, Python compile, documentation reread, and worklog validation are
  run before commit.
