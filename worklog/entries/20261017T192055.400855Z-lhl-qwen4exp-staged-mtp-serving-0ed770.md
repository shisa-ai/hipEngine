# Run Flash-Next MTP as bounded scheduler work

## Summary

Flash-Next explicit MTP now submits without running generation. Target prompt
chunks, shifted draft priming, root emission, planned verification cycles and
provider-synchronized K0 steps execute under the existing resident scheduler.
Request commands no longer lose ownership at an administrative timeout.

## Changes

- Add `qwen4_exp_serving_mtp.py`: cold-prepared draft pool and reusable target
  snapshots, exclusive target/draft request owners, bounded cooperative iterator
  steps, real target device transaction and draft append-cursor rollback.
- Advertise physical speculative C1 and use the existing serial partition hook
  for logical concurrent requests. This is not physical C2/C4 qualification.
  No sidecar means no staged speculative capability. Keep explicit EOS support;
  fail closed on unimplemented processors rather than silently ignoring them.
- Target prompt chunks export hidden seeds for matching draft chunks. Preserve
  the preceding chunk's final hidden seed; never prefill or prime twice. Root
  emission does not step the target; later K0 synchronizes both cursors.
- Add optional generic engine hooks binding the original request and probing
  its cancellation reason before admission and after work. Filter cancelled AR
  tokens before publication, preserve opaque cancellation result ownership and
  reasons, and keep the existing committed-speculative cancellation guard.
  Parent reviewed the child's hook implementation and tests.
- Admission, cancellation and shutdown commands wait for ownership transfer or
  retirement, not the short administrative timeout. Queued cancelled/expired
  children retire before model work. Driver failure resolves queued command
  responses as well as active collectors. Nonblocking `service_health` reports
  closing/closed/failure; HTTP readiness wiring is the next unit.
- Cancellation output uses only scheduler-committed IDs. Unwind bounded prompt
  work locally, rollback speculative device work before publication, release
  target/draft owners and reset them at next admission.
