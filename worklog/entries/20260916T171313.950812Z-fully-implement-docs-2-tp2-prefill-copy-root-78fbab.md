# Restore resident prefill H2D copies; both GPUs pass bounded numerical checks

## Summary

The optimized resident TP1 failure is localized and repaired at the **host-to-
device copy primitive**, before embedding or any transformer layer. In the
pre-fix XTX run, `session.prefill()` reset attempted an 8-byte upload of position
`0` to an unattributed scratch view. The helper returned without issuing a
copy; exact readback was `-7878674376980526012`. The observer stopped there.

`7c2a7fb66751abf4fa10f008a47811a39ed2953a` introduced the defect when adding
256 MiB upload chunking: it deleted the `device is None` copy branch. The
resident optimized scratch arena constructs unattributed `DeviceBuffer` views;
resident embedding also constructs unattributed token/hidden upload views.
By contrast, the diagnostic TP1 `_FullStackScratch.allocate()` uses dedicated
allocations by default, and its token upload passes the attributed allocation.
This explains why the prior raw/diagnostic TP1 controls could work while the
optimized resident path did not. It is not an output-head kernel defect or an
inference of a corrupted GPU context.

The minimal repair scopes device selection only when attribution exists and
executes the same bounded copy loop in both cases. On both XTX and W7900, one
same-prompt validation per device now passes **746 observed stages**, including
64 layer outputs and the checked norm/attention/MLP/Conv/GDN boundaries, then
passes a token-eager numerical comparison, exact bulk repeat, eager next step,
and explicit teardown. No isolation switch, threshold relaxation, kernel edit,
GPU reset, environment restoration, or performance sweep.

This closes the diagnosed nonfinite source, **not** the full optimized TP1
baseline or TP2 campaign. Parent review remains required before full-baseline
measurement. Evidence:
`benchmarks/results/2026-09-16-tp2-resident-prefill-h2d-repair.json`.
Raw logs/fixtures: `/tmp/tp2-prefill-boundary/`.

### Route and contract audit

The comparison remains on `/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`, SHA-256
`7b2aec3b9ababdfd75aa17552ee95607d866e44decf547f6f12fcef85cc89f1b`.

in the compact artifact. Physical host `epyc`, Ryzen 9 5950X; W7900/gfx1100 UUID
`e282895b62c2b295` at `0000:0d:00.0`; XTX/gfx1100 UUID `cc4d02090dc9c3ff` at
`0000:10:00.0`. Fresh child visibility remaps each selected card to logical 0.

- Working diagnostic `_forward_token_eager` uses `_enqueue_embedding` with an
  attributed token buffer, dedicated decode scratch, token attention, add/norm,
  and local GEMV MLP. Resident defaults select an optimized scratch arena;
  `_FullStackScratch.allocate(use_single_arena=True)` creates `device=None`
  subviews. The prefill reset H2D and embedding derived-token H2D were skipped
  by the broken helper, irrespective of intended arithmetic or stream.
- Resident automatic prefill runs bulk attention/WMMA at 21 rows, default-stream
  uploads, `use_wmma_prefill=True`, `use_gemv_decode=True`, decode repack `1`,
  `PrefillConfig(attn_aotriton_min_tokens=512)`, capacity 23, BF16 KV with FP16
  scale default (no BF16 scales), and FP32 recurrent state. Both measured builds
  reported mapped host embeddings enabled and FP32 recurrent state. No flags
  were toggled to disable the optimized route. The 21-row bulk route and
  token-eager route are different arithmetic schedules, not exact peers.
- The reference calls the real resident token-eager path (`use_bulk=False`) on
  the **same prompt, weights, model, and session** after a reset; it uses the
  full-stack runner's token attention/FFN primitives underlying the diagnostic
  TP1 teacher. It is a nearest working scheduler reference, not a separately
  certified framework teacher. The upload's independent correctness oracle is
  the exact host payload and the CPU memmove fixture, not either GPU scheduler.
- No explicit generator profile binder or new variant selection was introduced.
  These direct sessions retain their defaults and existing registered kernels.
  The repair's binding gate is exact bytes/control/ownership in every profile;
  it does not introduce changed arithmetic requiring a new numerical envelope.
  The one-prompt full-logit comparison is an outer smoke only, never a complete
  production qualification. No claims transfer to another model or workload.
