# Dense Llama second-pass safety and public profile repair

## Summary

Second-pass review of `3931dc869` found unsafe strict null-mask dispatch,
stale prompt bounds after serving context changes, strict bounds computed as
though flash were selected, and a quadratic prompt mask still allocated by the
tiled route. All four have RED regression evidence and focused GREEN results.
This host is `zbook`, AMD Radeon 8060S `gfx1151`, not the W7900 stated in the
previous session's final report. The earlier claim that dense attention became
linear in prompt length is withdrawn: tiling reduces traffic, not the quadratic
number of causal query/key pairs. The earlier single-logit comparison does not
establish a production numerical envelope or an equal-length speedup.

## Changes

- Register public strict plans for both gfx11 backends without changing omitted-profile
  selection. Remove the satisfied missing-profile ledger entry. GPU validation
  exercises gfx1151; gfx1100 profile construction is CPU-tested only.
- Expanded public geometry coverage exposed a KV projection width that WMMA
  cannot execute. Select the existing GEMV implementation for dimensions outside
  WMMA's contract. Both strict and default hd32 cases failed before this repair
  and pass afterward against the CPU token oracle.
- Reject a null mask before the strict launch, refresh declared prompt capacity,
  account for strict arithmetic in prompt bounds, and preflight exact attention
  shared-memory needs before publishing KV state.
- Allocate a prompt mask only for the exact route. The previous implementation
  skipped the upload but still allocated `rows * rows` bytes.
- Stage selected normalized rows device-to-device for the output projection,
  instead of downloading the entire prompt and uploading a row subset.
  The pre-change cProfile probe showed `_copy_bf16_rows` on the generation path;
  this mechanical copy-only optimization preserves projection inputs exactly.
  RED-first was not used for this copy rewrite; profiling preceded it, and the
  regression test now rejects the old full-prompt readback.
- Expand kernel tests across the row-8 dispatch boundary, multiple query blocks,
  decode, partial tiles, mask holes, empty rows, and repeated output bytes.
  The exact Gemma fallback explicitly returns NaN for empty softmax rows;
  tiled empty rows return zero. Tests assert each declared behavior rather than
  changing the shared Gemma kernel's empty-row contract.
