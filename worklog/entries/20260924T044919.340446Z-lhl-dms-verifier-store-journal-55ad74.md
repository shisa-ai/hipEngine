# Verifier journals a compact-DMS row through the store transaction

## Summary

Task #11's verifier half, first unit: `Qwen35GGUFTransactionalVerifier` now
selects `_DMSStoreJournal` when its target carries a `_dms_backend`, and the
`compact_dms_mtp_transaction_not_implemented` decline is gone from the source
tree. The adapter composes the resident `_StateJournal` (which keeps owning
every non-KV tap: conv/recurrent rows, hidden rows, hidden taps) with
`DMSCompactBackend.begin_transaction`/`commit`/`rollback` for KV.

The load-bearing ordering is that a row is captured *after* that row's append,
matching how the resident journal is already used. Restoring the selected row's
snapshot is therefore exactly "state as of the accepted prefix", which is what
makes a commit keep the accepted candidates and discard the rejected ones;
restoring the initial snapshot undoes the whole cycle.

## Changes

- `hipengine/runtime/qwen35_gguf_mtp.py`: added `_DMSStoreJournal`. It binds one
  request id (`bind_request`), snapshots the store at `capture_initial` and after
  every `capture_row`, restores the whole cycle at `restore_initial`, restores
  the accepted prefix at `restore_row`/`restore_native_row`, retires the
  transaction with `DMSCompactBackend.commit` on that accepted path, and fails
  loudly when a row has no snapshot. `initial_state_only` is always `False`
  because a DMS row cannot use the native target graph and always verifies
  through the serial route. `row_hidden`, `_copy_d2d`, `hidden_nbytes`,
  `state_row_capacity`, `hidden_rows_tensor`, `capture_hidden_rows`,
  `mark_initial_state_captured` and `close` delegate to the resident journal.
- `hipengine/runtime/qwen35_gguf_mtp.py`: the verifier wraps its freshly
  allocated `_StateJournal` in `_DMSStoreJournal` when the target carries a
  `_dms_backend`, and `prepare` calls the optional `bind_request` hook with the
  batch's request id before any capture.
- `hipengine/generation/qwen35_gguf_mtp2.py`: the `_dms_backend` decline is
  replaced by a comment naming the route that now serves the row. The string
  `compact_dms_mtp_transaction_not_implemented` no longer appears anywhere under
  `hipengine/`.
- `tests/test_unit_dms_verifier_journal.py`: new CPU-only unit file (default
  tier, no HIP). Seven cases: full rejection restores the pre-cycle store; partial
  acceptance keeps exactly the accepted prefix; a rejected cycle leaves the row
  usable for the next cycle; a commit with no row snapshot fails loudly; the
  journal binds to one request; a session without a DMS backend is refused; and
  the journal is always serial-capable while delegating hidden state.
- `tests/test_unit_qwen35_gguf_mtp2_seam.py`: the case that pinned the removed
  decline now pins its absence, both behaviorally and against the capability
  function's own source.
