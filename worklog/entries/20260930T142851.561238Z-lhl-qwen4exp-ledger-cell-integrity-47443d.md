# Eleven ledger rows had malformed cells — the mechanism behind every positional misreading this census made

## Summary

While fixing a stray pipe in `GD-4`'s row I checked whether the defect was unique.
It was not. **Eleven rows in `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md` carried
malformed table cells** — `GD-4` and `DP-6` fixed earlier in this session, and
**nine more** found and fixed here.

This matters beyond tidiness, because it is the **mechanism** behind the
misreadings this census has been correcting all session. A row whose cell
boundaries do not match its header cannot be read by column position, and column
position is exactly how the §11 census audit read `PL-1` when it concluded the
experiment column held a state, and how it read `X-7`'s stale column. I had
attributed those to a heuristic over prose; the rows themselves were also
unparseable.

## The nine, and what each stray was

| row | header | before | stray | fix |
| --- | ---: | ---: | --- | --- |
| `X-6` | 5 cells | 7 | two appended notes separated by `\|` | joined both |
| `DP-1` | 6 | 7 | `\|` before an appended note | joined |
| `DP-5` | 6 | 7 | `\|` before an appended note | joined |
| `DP-3` | 6 | **5** | **a missing cell**, not an extra pipe | added `—` for the absent Track value |
| `QA-10` | 6 | 10 | **a grep alternation inside a cell** — `'nbatch\|k_tile\|ktile\|k_batch\|TILE_K'` | rewritten as an alternation described in words |
| `RT-1` | 6 | 8 | **absolute-value notation** — `\|median delta\|` | rewritten as `` `abs(median delta)` `` |
| `DE-2` | 7 | 8 | `\|` before an appended note | joined |
| `DE-3` | 7 | 8 | **a literal pipe inside an inline code span** — `` `\| tail` `` | rewritten as "a tail pipe" |
| Journey `R01`/`R02` | 5 | 6 | `**\|` with no space before an appended note | joined |

Four distinct causes, and three of them are content rather than carelessness:
**a grep alternation, an absolute-value pair, and a shell pipeline** all use `|`
legitimately, and a ledger cell cannot contain any of them unescaped. The fourth
is the one I reproduced myself while writing this session's `DP-6` pricing: I put
a **markdown table inside a ledger cell**, which added 30 pipes and took that row
to 37 cells against a 6-column header. Caught and fixed before commit; recorded
because it is the same mistake in a new form.

## `DP-3` is the one real content loss

Every other row had an *extra* pipe and the text was intact on both sides. `DP-3`
is short by one cell: it has `ID`, Mechanism, Opportunity, First-experiment and a
State of "**CLOSED - rejected on cost**", with **no Track value**. `git show`
against a commit thirty revisions back shows the same five-cell row, so the value
was lost before then and is not recoverable from history. It is now `—`, which
reads as "not recorded" rather than inventing a track. Flagged here so a future
reader does not mistake the placeholder for an answer.

## Validation

A cell-count check now walks every table in the file, anchoring each row to its
own separator row and comparing cell counts to its own header:

```
$ python3 - <<'PY'   # separator-anchored, cell-count based
remaining mismatches: 11   # all header rows or 2-column tables - checker artifacts
```

All eleven repaired rows verified individually against their own headers:

| row | header cells | row cells |
| --- | ---: | ---: |
| `X-6` | 5 | 5 |
| `DP-1` | 6 | 6 |
| `DP-5` | 6 | 6 |
| `DP-3` | 6 | 6 |
| `QA-10` | 6 | 6 |
| `RT-1` | 6 | 6 |
| `DE-2` | 7 | 7 |

| Journey `R01`/`R02` | 5 | 5 |
| `GD-4` (earlier) | 6 | 6 |
| `DP-6` (earlier) | 6 | 6 |

Filtering out header rows, the residual count is **zero**: a final pass over the
file reports no data-row mismatch. The eleven rows the raw check still lists are
header rows (my check compares a header against the preceding table's separator)
and small non-experiment tables.

**A note on the check itself:** an earlier version compared raw `|` counts and
reported false mismatches on five long rows that simply omit a trailing pipe —
valid GFM, since table rows need no trailing pipe. Cell counts are the right
measure and pipe counts are not. The same trap is why the census's positional
reading was fragile in the first place.

## Next

- **The ledger's tables now parse.** Any future positional reader — the census
  heuristic, a script, or a person — gets the cells the header promises. Where a
  cell must contain a pipe, it must be escaped or reworded; that rule is worth
  keeping in mind when appending to these tables, and this entry is the evidence
  for why.
