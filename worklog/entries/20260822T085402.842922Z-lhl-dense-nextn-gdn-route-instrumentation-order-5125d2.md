# Repair dense NextN GDN route instrumentation order

## Summary

Localized task #32 to runtime registry replacement, not a missing production
GDN route. The dense NextN gate installed counted wrappers for Conv and GDN
keys, but `_resolve_gguf_gdn_prefill_plan()` then called the whole GDN registrar
with its default `replace=True` during model prefill. That replaced only the GDN
wrappers after fixture setup. This exactly explains the observed census:
`conv_snapshot` populated while `gdn_snapshot`, `gdn_fused_snapshot`, every
other chain-GDN wrapper, and scalar GDN output fusion were all empty, even though
transaction/state gates passed.

Registration is owned by module/backend initialization. A hot-path plan resolver
must resolve existing plugin keys, not re-register and overwrite them. Removing
the refresh preserves test instrumentation and real plugin overrides without
changing production kernel selection or weakening route assertions.
