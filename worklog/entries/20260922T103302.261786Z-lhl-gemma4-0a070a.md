# Gemma 4 text CPU reference gated against the HF transformers oracle

## Summary

Locks the Gemma 4 text-tower arithmetic before any HIP work. A new NumPy CPU
reference reproduces a tiny `Gemma4ForCausalLM` forward from HF transformers
5.13 to 1.4e-6 max logit deviation, and every intermediate stage boundary
(embedding, each decoder layer, final norm) matches within 1.8e-5.

Gemma 4 is not a configuration variant of any ported architecture. The
reference and its tests pin the six features that would otherwise be silently
wrong:

1. Dual attention geometry in one model. Sliding layers are `head_dim`/8 KV
   heads; global layers are `global_head_dim`/2 KV heads. `key_length`,
   `value_length`, and the KV cache must take per-layer geometry.
2. Proportional partial RoPE on global layers. `partial_rotary_factor=0.25`
   over a 512-wide head rotates 64 of 256 pairs, and those pairs keep the
   exponent scale of the *full* head dimension (`2i/512`), not of the rotated
   span. The remaining 192 pairs carry inverse frequency zero.
3. `attention_k_eq_v` on global layers: no `v_proj`, V is the raw K projection,
   passed through a **weightless** RMS norm, and never rotated. K gets `k_norm`
   and the rotation.
4. Parallel dense MLP and routed experts. Both branches run, each with its own
   post-norm (`post_feedforward_layernorm_1` / `_2`), and are summed before the
   block post-norm. The routed branch reads the **pre-MLP residual**, not the
   dense MLP output. This is not hipEngine's `ffn_*_shexp` shared-expert
   topology.
5. `gelu_pytorch_tanh` in both branches, not SiLU.
6. Weightless router norm plus two scales: weightless RMS norm, then
   `scale * hidden_size**-0.5`, then projection, full softmax, top-8,
   renormalize to one, then `per_expert_scale` of the selected experts.

Also pinned: attention scaling is exactly `1.0` (never `head_dim**-0.5`),
`layer_scalar` per layer, `sqrt(hidden_size)` embedding scale, sliding window
`1024` with an inclusive query position, and `final_logit_softcapping` 30.

### Real-artifact facts confirmed against the downloaded GGUF

`unsloth/gemma-4-26B-A4B-it-GGUF` → `gemma-4-26B-A4B-it-UD-Q4_K_XL.gguf`
(17,010,980,576 bytes, 658 tensors, GGUF v3, `general.architecture=gemma4`):

- `gemma4.attention.head_count_kv` is a per-layer array
  `[8,...,2,...]`; `head_count` is a scalar 16.
- `gemma4.attention.key_length` 512 / `_swa` 256; same split for
  `value_length`.
- `rope.dimension_count` 512 / `_swa` 256. **These are not the rotated span.**
  The GGUF carries no `partial_rotary_factor`; the rotated span is recovered
  from the `rope_freqs.weight` tensor, which holds 64 entries of `1.0` followed
  by 192 entries of `1e30`. Counting the finite factors gives the 64 rotated
  pairs.
- Global layers have no `blk.N.attn_v.weight` (25 of 30 layers carry one).
- `ffn_gate_up_exps.weight` is the fused expert gate+up,
  `(128, 1408, 2816)`, first 704 rows gate.
- `ffn_down_exps.scale` (128,) is the router's `per_expert_scale`;
  `ffn_gate_inp.scale` (2816,) is the router's `scale`.
- `layer_output_scale.weight` (1,) is `layer_scalar`.
- No `output.weight`; embeddings are tied.
- Quant mix is dynamic: Q4_K/Q5_K fused experts, Q5_1/Q8_0 expert down,
  Q8_0 attention and dense MLP, F32 norms and router. Every type is already
  supported by `hipengine.quant.gguf`.
- `tokenizer.ggml.model` is `gemma4` with 514,906 merges and raw UTF-8 tokens
  (SPM-style, not GPT-2 byte-encoded) — a new tokenizer family for hipEngine.

## Changes

  HF config/state-dict adapters, and the full fp32 reference forward.

  `config.json` with a pinned weight digest.
- `tests/test_unit_gemma4_cpu_reference.py` (new): 16 unit tests.

## Validation

```bash
uv run pytest tests/test_unit_gemma4_cpu_reference.py -q
# 16 passed

~/mambaforge/envs/therock/bin/python scripts/gemma4_hf_tiny_oracle.py \
    --out tests/fixtures/gemma4
# 90 weight tensors, 8 activations
```

Measured deviations against the framework oracle (float32 eager HF forward):

| Boundary | max abs deviation |
| --- | --- |
| embedding | 0.0 |
| layer 0 / 1 / 2 / 3 | 2.98e-6 / 9.30e-6 / 1.07e-5 / 1.81e-5 |
| final norm | 7.63e-6 |
| logits | 1.44e-6 |

The reference is gated at `atol=1e-5` on logits and `5e-5` per stage, and the
fixture carries a sha256 over all 90 weight tensors so a silent regeneration
fails the suite.
