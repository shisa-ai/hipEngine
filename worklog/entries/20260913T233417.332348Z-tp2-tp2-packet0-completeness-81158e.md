# TP2 Packet 0 completeness: model hash binding, display load, and transport state tests

## Summary

Three small gaps in the Packet 0/1 punchlist are closed.

1. **The shard manifest is now bound to the model file hash.** Packet 0 asks for
   the model path/hash to be recorded and the shard manifest to be bound to it;
   the manifest carried a `model_hash` field that nothing filled. The report
   script now streams the file's SHA-256 and passes it into
   `build_shard_manifest`, so the manifest hash changes if the file changes.
   The hashes therefore moved:

   | Degree | Previous (unbound) | Bound to the model SHA-256 |
   | --- | --- | --- |
   | N=1 | `c6dc8b6953a6` | `e73622ab8cb6` |
   | N=2 | `6ee685942825` | `7fc6cbf4251e` |
   | N=4 | `a450ff358957` | `9feb21f5419f` |

   Model SHA-256: `7b2aec3b9ababdfd75aa17552ee95607d866e44decf547f6f12fcef85cc89f1b`
   for `/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`. This supersedes the hash values in
   `worklog/entries/20260913T224345.473403Z-tp2-tp2-shard-planner-and-transport-4eedcc.md`;
   the byte-exactness results and per-rank byte totals there are unchanged.

2. **Display load is recorded, not assumed.** Packet 0 asks for display load as
   part of the host record. `collect_display_load` scans `/proc/*/fd` for openers
   of the DRM nodes and records the session type. On this host nothing holds
   `card0`/`card1`/`renderD128`/`renderD129` open (`busy: false`, Wayland
   session), so no compositor shares either device during the screening numbers.

3. **Transport state-machine coverage.** Packet 1 asks for repeated buffer reuse
   and cleanup tests. Five mock-level tests now cover 50 consecutive groups over
   one buffer pair with no accumulation, idempotent close plus rejection of later
   work, an aborted group that does not leave a group open, per-rank pointer
   isolation (send buffers untouched, every rank receiving the group sum), and
   per-group recorder state.

  serving evidence so a shard layout can be identified from an artifact alone.
