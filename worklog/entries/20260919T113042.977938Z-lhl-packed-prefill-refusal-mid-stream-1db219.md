# Stop failing a live stream when the packed prefill route refuses the context

## Summary

The packed AR prefill guard
(`packed paged AR prefill currently requires context < 1024`) raised
`NotImplementedError`, and the server maps that exception to HTTP 400
`unsupported_parameter`. Two of the sites that can raise it run **after the
request has already published output**: the single-row native prefill that a
declined incremental prefill replays at the prompt's final chunk, and the
post-commit target rebuild that `recover_cycle_failure` calls after an uncertain
selected commit. The second one is the 2026-09-18 field observation - a request
that streamed 139 s of output and then ended with a 400, which the client cannot
distinguish from a truncation.

A route refusal is a route decision, not a runtime fault. Both sites now finish
the affected rows on the registered strict per-session prefill route with the
same tokens and cursors, record the route change as a fallback reason, and keep
sessions whose KV layout only the block-table-aware route can represent
fail-closed.

The guard itself is narrow: `_validate_packed_ar_prefill_context` refuses only
when the slab's live count is >= 1024 **and** no slot needs slot-local full
attention. With `attn_aotriton_min_tokens = 512`, that means a shared or
otherwise non-contiguous COW allocation
(`device_kv_nonidentity_scatter`), which is exactly the speculative/reused
prefix shape - not an ordinary long prompt. An ordinary long prompt keeps
slot-local full attention and never reaches the guard.

## Changes

- `hipengine/generation/qwen35_gguf.py`
  - `_mark_execution_stepped`: materialize `_execution_stepped_request_ids` on
    first use so runners built with `__new__` (the scheduling-test convention in
    this file) keep working; this repairs three tests that commit `de6d31685`
    broke for lightweight fixtures.
  - `_prefill_native_row`: a packed-route `NotImplementedError` now closes the
    MTP2 prompt streaming, zeroes the row's candidate budget
    (`mtp2_prompt_fallback_reason = "packed_prefill_unsupported_k0"`), records
    `fallback_reasons["packed_prefill_unsupported_k0"]`, and replays the prompt
    through `lease.session.prefill` (the same call the route already uses when
    the packed owner is absent). Sessions that require block-table-aware prefill
    still re-raise.
  - `restore_speculative_target_request_ids`: the same refusal rebuilds each row
    with `session.prefill(tokens)` after the resets the function already
    performed, and returns `False` for block-table-required sessions so the
    containment path keeps its fail-closed outcome. The caller's existing
    canonical-token and cursor assertions validate the fallback.
- `docs/EXECUTION-PROFILES.md` section 4.3: an unsupported-shape refusal from an
  optional packed route is a route decision; a recovery path that runs after a
  canonical commit re-routes instead of raising into a live response.
