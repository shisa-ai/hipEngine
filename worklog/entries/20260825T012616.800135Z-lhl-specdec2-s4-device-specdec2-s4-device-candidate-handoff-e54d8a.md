# Keep gfx1151 SPECDEC2 candidates device-resident

## Summary

Remove the binding S4 pre-target candidate readback for physical C2/C4. Dense
NextN now writes one request-major INT32 candidate vector on device. Shared
proposal depths feed their prior top-1 through device i32→i64 conversion, ragged
single-row tails use the same device top-1 contract, and packed target staging
overlays each request's candidate slice without host materialization.

The bounded candidate readback now happens only after packed target execution,
when the current host accept oracle and provider repair still need candidate
IDs. This closes the device-resident-through-target checklist item; it does not
claim the separate one-device accept/selected-state commit item.

## Changes

- Add `Qwen35GGUFNextNBatchDeviceProposal`, with request/count/root ownership,
  a request-major INT32 token tensor, and BF16 hidden rows retained for provider
  repair.
- Add physical device proposal execution for C2/C4 and K1-K3: full-logit target
  arithmetic and row argmax stay on device, prior-depth tokens feed the next
  depth without D2H, and ragged singleton tails use the same ownership.
- Add deferred provider materialization after target execution; only then bind
  `last_results` for exact checkpoint repair.
- Extend `CandidateGraph` use in the real adapter to device `token_ids`, allow a
  device-only `TargetFrontier`, and stage target roots plus D2D-converted
  candidates in the packed verifier.
- Add request telemetry for device handoffs and candidate D2H-after-target, and
  make the strict C2/C4 gate bind those counters.
- Add RED/contract tests for provider deferral, real adapter graph ownership, and
  packed target device staging.
