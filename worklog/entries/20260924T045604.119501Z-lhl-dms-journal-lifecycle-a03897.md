# Compact-DMS journal lifecycle: cancel, deadline, disconnect

## Summary

Task #11's lifecycle half at the journal level. `_DMSStoreJournal.close()` no
longer drops an open cycle: it rolls the transaction back, so a shutdown or
disconnect path that reaches close() with a cycle in flight cannot strand the
writes the journal exists to undo. The verifier normally rolls back before
closing, in which case this is a no-op.

The new tests cover the five acceptance shapes at the mechanism level: partial
acceptance, full rejection, cancellation mid-cycle, deadline mid-cycle, and
disconnect/shutdown. Each asserts the exact restored store state, and the
cancellation and rejection cases also assert that the next cycle on the same row
commits exactly.

## Changes

- `hipengine/runtime/qwen35_gguf_mtp.py`: `_DMSStoreJournal.close()` rolls
  back an open transaction before releasing the resident journal.
- `tests/test_unit_dms_verifier_journal.py`: five new cases. Cancellation
  mid-cycle restores the pre-cycle store and clears the snapshot; a deadline
  mid-cycle is exact and the unwind is idempotent; a cancelled cycle leaves the
  next one exact; shutdown rolls back an open cycle and is itself idempotent; and
  a full lifecycle completes with `malloc`/`free` monkeypatched to raise,
  which is what makes "zero outstanding HIP allocations after teardown" hold for
  the adapter by construction — it owns no device buffers, and everything it
  holds is host-side store state released by rollback or commit.
