# W7900 Qwen3.8: batch-route profile gate gains packed prompt admission; c3 smoke passes hard gates

## Summary

Follows up on the same-day finding that the c>N packed prompt prefill route is
default-on but has no profile evidence because
`scripts/execution_profile_gguf_batch_route_gate.py` only ever admitted prompts
one session at a time (and asserted byte-exact prefill logits, which the packed
route can never satisfy - see
`20260830T005330.724870Z-lhl-w7900-qwen38-packed-prefill-state-gate-3df834.md`).
This unit adds the missing admission mode and takes the first measurement
through it. The gate now supports `--packed-prefill-candidate`, which admits the
candidate group through `prefill_batch_native` while leaving the strict teacher
on independent serial admission. At c3 over four prompts, 24 decode steps and
three exact repeats, the packed candidate passes every numeric hard gate:
category `code` KL_mean `3.07e-5` (limit `1e-3`), KL_p95 `2.06e-4` (limit
`5e-3`), KL_max `7.70e-4` (limit `5e-2`), top-1 agreement `1.0` (limit `0.99`),
teacher-NLL delta `+4.95e-5`, `repeat_deterministic: true`, zero scope failures
and zero top-1 mismatch rows. This is not yet a qualification claim - see
Caveats.

## Changes

- `scripts/execution_profile_gguf_batch_route_gate.py`:
  `--packed-prefill-candidate` threads a `packed_candidate` flag from `run()`
  into `_prefill_group` via `_run_static_group` / `_run_dynamic` /
  `_run_sparse_c8`. When set, the group enters through
  `sessions[0].prefill_batch_native(prompts, sessions=tuple(sessions))` after a
  per-session `reset()`, and the prefill calibration weakens from byte-exact
  logits to **token equality only** (`CalibrationError` on token drift, or on a
  `None` probe). Guardrails kept deliberate: the candidate stays on the
  package-default GDN route (production serving arithmetic, not the strict mode
  the teacher has), every decode-step KL/top-1 threshold still applies, and the
  artifact records `protocol.packed_prefill_candidate` so the run can never be
  read as the canonical serial-admission protocol. Module docstring updated.
- Retained the smoke as
  `benchmarks/results/2026-08-30-w7900-qwen38-q4km-packed-prefill-c3-profile-smoke.json`
  (verbatim, `performance_claim: false`).

### Caveats (why this is smoke, not qualification)

- `status: invalid_or_screen_only` with `measurement_valid: false`. The three
  recorded blockers are structural and pre-existing, not caused by this flag:
  the route manifest is evidentiary rather than runtime-profile resolved, the
  adapter does not emit the complete exact control-plane record schema, and
  fresh task plus BF16-relative verdicts are not available. `profile_qualification_claim: false`.
- Only four prompts (the first of the mtpbench suite, category `code` only), so
  no per-category spread and no heldouts. A full-suite canonical run (18 prompts
  across `code` / `general_en` / `general_ja` / `mixed_ja_en` plus the GDN
  category heldouts, widths 3/5/6/7) was launched as a background task when this
  entry was written; its result belongs in a later entry, not here.
- Captured at `hipengine_commit c543b9e80` with `provenance.dirty: true`, i.e.
  with this evaluator patch still uncommitted. Unavoidable for a first run of new
  tooling; after this commit the code is byte-identical to what was measured.
