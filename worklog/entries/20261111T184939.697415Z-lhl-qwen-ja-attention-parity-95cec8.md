# Align native graph short attention with scalar selection

## Summary

Fix the Japanese AR/native-MTP divergence investigated in
`worklog/entries/20261111T171034.987223Z-lhl-qwen-ja-native-parity-7322e1.md`.
The captured verifier used plain span attention while scalar decoding selected
short batch attention with 1024 threads on this host. Matching the scalar
selector restores generated-token parity in the public reproducer.

## Changes

- Graph row views use the immutable context bucket as the batch leaf's upper
  bound when the bucket fits the backend's short-context range. Actual live
  counts come from device memory, not capture-time host positions.
- Reuse the existing scalar variant selector, without hard-coded backend or
  thread-count branches. Eager caps and out-of-range span selection stay unchanged.
  No kernel body or scalar baseline changed.
- Add RED/GREEN dispatch coverage for graph bounds 127, 777, and 1023 alongside
  the existing 8192-bound fallback and eager-cap checks.
