# The fused expert tensor is pack8-compatible because 1408 is a multiple of 8

## Summary

The last thing that could have invalidated the pack8 plan is checked, in pure
Python with no GPU and no model load, and **the fused expert tensor is
compatible**.

**The apparent obstacle.** `Q4_K_PACK8_SHAPE` is
`GGUFRepackShape(source_type=Q4_K, rank=2, columns=8)`, so it rejects the rank-3
expert tensor outright:

```
ValueError: raw_qweight must have GGUF Q4_K dense byte shape
            [out_features, bytes_per_row] (rank-2)
```

**The resolution.** Reshaping `(128, 1408, 1584)` to `(180224, 1584)` is accepted,
and `repack_gguf_q4_k_pack8` returns `qweight=(22528, 2816)` with
`out_packed=22528` and `out_features=180224 = 128 * 1408`, so per-expert row
ranges are preserved exactly.

**The decisive detail:** pack8 groups **eight consecutive output columns**, and
`1408 % 8 == 0`, so **no group straddles an expert boundary**. The fused gate/up
layout is compatible rather than an obstacle - and it would not have been if the
intermediate had been, say, 704-with-a-remainder against the packing width. This
is worth stating because the same 704 that made the iu8 route a capability miss
earlier in this campaign is *fine* here, for a different reason: 704 % 8 == 0 even
though 704 % 128 != 0.

`qwen35_gguf_materialize.py:85` also defines a dedicated
`LAYOUT_GGUF_EXPERT_PACK8_SIDECAR` (`"gguf_expert_pack8_v1"`) if the flat view is
not the right shape for the kernel's expert indexing.

Either way, **the port is viable**, and this was the last open risk in the plan.

## Validation

- Executed in pure Python: `Q4_K_PACK8_SHAPE.validate` on both shapes and a real
  `repack_gguf_q4_k_pack8` call over a 285.5 MB synthetic tensor, with the
  non-trivial `0x21` payload so the repack did real work rather than short-cutting
  on zeros.
- The straddle argument is arithmetic on the packing width and the tensor's own
  intermediate, not an assumption: `1408 % 8 == 0`.
- **Not yet verified:** that the pack8 expert kernel reads the flat layout with
  the expert indexing it expects, and that its numerics match the current route on
  Gemma 4's geometry. Those belong to the implementation unit's correctness gate.
