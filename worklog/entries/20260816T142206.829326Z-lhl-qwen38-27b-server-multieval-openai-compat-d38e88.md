# OpenAI-compat server API fixes for multieval (max_completion_tokens, EOS strip, usage reasoning tokens)

## Summary

Made the hipEngine OpenAI-compatible `/v1/chat/completions` endpoint pass the
multieval harness preflight and return OpenAI-standard fields. Three behaviors
were changed, all in `hipengine/server/api.py`.

## Changes

- **Accept `max_completion_tokens`.** Added `max_completion_tokens: int |
  None = Field(default=None, ge=0)` to `ChatCompletionRequest` and
  `CompletionRequest` so it no longer lands in `model_extra` and is no longer
  rejected as `unsupported request parameter`. Added `_request_completion_cap`
  which prefers legacy `max_tokens`, else `max_completion_tokens`, and wired it
  into `_request_max_tokens` and `_thinking_generation_budget` so it acts as
  the total reasoning+answer completion cap (per the multieval requirement).
- **Strip the terminating special token from visible content.** Added
  `_strip_chat_terminal_markers` and applied it in `_chat_message_from_parsed`
  (non-streaming `message.content`) and in `_ReasoningSplitter.finish_parts`
  (streaming final content delta). Previously the decoded Qwen generation
  included the literal `<|im_end|>` EOS marker in `content`.
- **Expose reasoning tokens in standard usage.** `_usage` now adds
  `usage.reasoning_tokens` and `usage.completion_tokens_details.reasoning_tokens`
  (summed from each `GenerationOutput.finish_details.reasoning_tokens` via the
  new `_finish_reasoning_token_total`). This flows into `batch.usage`, so both
  chat and completions responses expose it.
