# Host blocker: the model volume is unmounted, so all GPU measurement work stops

## Summary

`/data/models/gguf/` stopped existing partway through the session, so no further hipEngine measurement
work can run. Nothing was deleted: the 1.8 TB volume that provides it is present and healthy but is
**no longer mounted**, leaving an empty `/data` mountpoint behind. This is a host storage event, not
engine or harness behavior, and I did not attempt to fix it - remounting is outside this task's scope
and would interfere if the volume was taken offline deliberately.

## Changes

- No code or config change. Inspection was read-only: `ls`, `/proc/mounts`, `findmnt`, `lsblk`, and
  `sudo blkid` / `sudo fdisk -l` purely to identify the device. Nothing was mounted, written, or
  repaired.

## Evidence

- Failure signature (bg-79, `scripts/gguf_mtp_verifier_rocprof.py --child`):
  `FileNotFoundError: [Errno 2] No such file or directory: '/data/models/gguf/Qwen3.8-27B-Q4_K_M.gguf'`.
- `ls /data` returns nothing; `ls -ld /data` shows `drwxr-xr-x lhl lhl` dated Oct 26 2024 - an empty
  mountpoint, not a removed tree.
- `/proc/mounts` has no `/data` and no `nvme1` line. `findmnt -T /data` resolves to `/`
  (btrfs `/@`), confirming nothing is layered under the mountpoint.
- `lsblk`: `nvme1n1 1.8T` → `nvme1n1p1 1.8T` with an empty MOUNTPOINT. `sudo blkid`:
  `LABEL="models" UUID="f4b66101-530a-4d43-868b-90db91280718" TYPE="ext4"`.
- `/etc/fstab` has entries only for `/boot` (vfat) and `/`+`/home` (btrfs subvols). There is **no**
  fstab entry for this volume, so whatever mounted it did so ad hoc and it will not survive a reboot -
  which is probably why it is gone now.
- The mount was alive minutes earlier: bg-78 loaded
  `/data/models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` and reached `prefill`, and the parity probe wrote
  its report at 14:17 from `/data/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`.
- Side finding worth correcting someday: project memory describes this host as a dual-NVMe **ZFS**
  layout with host-specific mount points. `zfs` is not installed here (`timeout zfs` → command not
  found) and the models volume is plain ext4. That memory is wrong or belongs to another host, and it
  would mislead anyone debugging this.
