# Staged linear-attention rows above the split threshold under production numerics

## Summary

Long-context MTP economics are gated by the 48 dense linear-attention layers,
which `strict_long_rows` keeps on the row-wise c1 route whenever
`_use_gguf_full_attention_split_decode(start_position + rows)` is true: a
same-server AR/MTP pair measures 0.90x AR at a 945-token prompt and 0.68x at
3,530 tokens, against 1.38x when the split threshold is raised so both chains
batch. The 2026-09-12 rejection of the batched linear chain was bit-exactness
only (one BF16 ULP in the layer-46 output, max abs 0.015625, on the retained B3
fixture), which is not the promotion bar under
`docs/EXECUTION-PROFILES.md`.

This unit makes the route reachable for that evaluation without changing any
default: `HIPENGINE_GGUF_STAGED_LINEAR_ROWS_LONG` (or the eventual backend
package capability `GGUF_STAGED_LINEAR_ROWS_LONG`) admits dense linear rows to
the staged chain above the split threshold, and unset keeps the row-wise strict
route byte-for-byte.

Re-reviewing it on the current tree already overturns the recorded reason for
the rejection: on the eager route the staged chain is **byte-exact** against the
serial-exact teacher at the 1024/1025/1026 straddle, with route counters proving
the staged owner ran (48 `staged_chain_calls`, 0 `row_wise_attn_calls` per case)
while the matched row-wise control is exact as well. The BF16 boundary that
motivated the blanket row-wise rule does not reproduce on the current dense
Q4_K_M path.

The same sweep also isolated a *different*, pre-existing divergence that has
nothing to do with this candidate: the cached native **target graph** route
differs from the serial-exact teacher at cycle ends 1016-1022 and 1026-1032
(`target_logits_exact` false, KL up to 6.16 on one row, Conv/GDN state and K/V
rows diverging), identically with the admission flag on and off. The gate now
has `--disable-target-graph` so eager-chain arithmetic is measurable on its own
instead of silently measuring a graph when one is eligible.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`
  - `_gguf_staged_linear_rows_long_enabled(backend)`: default-off admission with
    an env override that wins in either direction, and a fail-closed answer for
    an unresolved backend (a partially built runner declares no capability).
  - `_run_native_attention_bulk_ffn_layer_rows`: `strict_long_rows` gains the
    `and not _gguf_staged_linear_rows_long_enabled(self.backend)` term, so the
    admission also moves the FFN of those rows to the batched owner. Nothing
    else changes; `rows == 1` decode and MoE rows never reach the term.
- `scripts/gguf_mtp_long_context_gate.py`
  - `_logit_diagnostics`: per-row KL, mean/max row KL, top-1 matches/agreement
    and max abs logit delta beside the gate's bit-exact verdict, so a
    non-exact candidate is measurable against the calibrated envelope instead
    of binary. The bit-exact `gate_passed` contract is unchanged.
  - `_count_linear_route_owners`: staged-versus-row-wise call counters per arm,
    the evidence that a candidate arm changed the route and not only its
    configuration.
  - `--disable-target-graph` (mutually exclusive with `--require-target-graph`)
    forces the eager verifier so graph eligibility cannot silently substitute a
    different arithmetic route.
  - `HIPENGINE_GGUF_STAGED_LINEAR_ROWS_LONG` and
    `HIPENGINE_MTP2_MAX_CONTEXT_TOKENS` join the tracked provenance environment.
- `tests/test_live_gguf_native_spec_cycle.py`: the admission is env-gated, reads
  the backend capability, fails closed without a backend, and never changes
  short-context or single-row dispatch.
- `tests/test_unit_gguf_mtp_long_context_gate.py`: the KL/top-1 diagnostics
  measure a reassociated candidate (and report an unavailable capture), and the
  graph switches are mutually exclusive.
- `scripts/gguf_mtp_server_pair_bench.py`: the same-server AR/MTP pair harness,
  committed so the long-context ratio rows have an executable recorded command
  instead of a `/tmp` probe. Adds a JSONL suite mode with deterministic context
  padding and a recorded request-extras block.
- `docs/REFACTOR.md`: the row-wise strict dispatch entry records the admission
  and its removal trigger; the coupled-threshold entry no longer claims the
  split-threshold workaround is the only way to batch linear rows.
- `docs/ENVS.md`: the new variable and its classification.
