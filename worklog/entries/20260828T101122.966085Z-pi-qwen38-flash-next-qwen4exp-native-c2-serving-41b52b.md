# Qualify native Qwen4Exp c2 serving

## Summary

Qualified native request-owned Qwen4Exp c2 serving at <=1K over one shared
weight/PLE layout. c1/c2 IDs, blocking HTTP, SSE ownership, admission,
cancellation, and teardown pass. Model transitions remain request-serial, so
this is a functionality/isolation result without a throughput claim.

## Changes

- Added `Qwen4ExpResidentServingRunner` implementing the resident-loop
  prefill/decode/compact/reclaim/admission contract at capacity 2.
- Reused the primary generator runner as one row and added one request-owned
  state/KV/scratch runner over shared weights.
- Added native stream-many/control capability and bounded server admission.
- Added RED/GREEN unit coverage for distinct runner ownership, c2 admission,
  rollback, cancellation before mutation, and capacity advertising.
- Artifact: `benchmarks/results/2026-08-28-gfx1151-qwen38-flash-next-native-c2-serving.json`.

## Validation

- Physical c1-vs-c2: 2/2 varied 8-token generated-ID rows exact.
- Native stream-many: two rows / six chunks with correct row ownership.
- Two simultaneous blocking chats: HTTP 200; two simultaneous SSE chats: HTTP
  200 and `[DONE]`.
- Third admission rejects at c2; rollback releases a runner; pre-mutation
  cancellation returns empty IDs and `cancelled`.
- c1 peak 83,073,775,800 bytes; c2 peak 83,624,059,760 bytes (+550,283,960);
  both close to zero.
- Complete affected Qwen4Exp/LLM/engine-loop bundle: 162 passed.
