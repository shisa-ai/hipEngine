# W7900 Qwen3.8: pin the fused SiLU FFN owner's rows33 scope in the dispatch suite

## Summary

While checking whether today's two promoted row floors were actually covered, I
found an asymmetry. The unequal QKV floor (16) is pinned behaviourally in
`tests/test_gguf_linear_dispatch.py` (rows 1, 4, **15** must not route, with a
comment citing the 2026-08-30 re-qualification). The dense Q4T16 FFN fused SiLU
floor had **no** scope assertion anywhere: the `linear_pair_silu` tests exercise
variant choice on `hip_gfx1151`/qmicro and a generic 1024x3584 pack8 owner at its
512-row floor, never the W7900 (5120, 17408) shape at the 33-row boundary. A dispatch
change could therefore have sent 45-row prefill back to the unfused chain with every
test green, which is the same failure shape as the packed-wiring regression that only
surfaced as a 3.5x wall slowdown.

Writing the pin also settled what the owner's opt-outs actually are, which I had
assumed wrongly twice: the t16 dense+SiLU owner has **no per-request admission
session and no env kill-switch** - `q4_pack8_dual_wmma_silu_prefill_session` and
`HIPENGINE_GGUF_Q4_PACK8_DUAL_WMMA_SILU_PREFILL` gate the *pack8* owner - and
`wmma_prefill_session(False)` does not stop it at rows 512. Rows and shape are the
only scope controls, which is precisely why both are now asserted.

## Changes

- `tests/test_gguf_linear_dispatch.py`: add
  `test_w7900_q4_k_t16_ffn_pair_silu_scope_pins_the_rows33_floor`, CPU-only, using the
  file's existing fixture-stub idiom (register under the candidate
  `linear_pair_silu` key, restore in `finally`). Asserts routing at rows 33/45/192/512,
  no routing at 32, no routing at the near-miss shape (5120, 17_344), and records the
  measured absence of a per-request opt-out.

## Validation

  listed only the test file.
- Whole file: 132 passed, no regressions from the added registration churn.

  nothing in the appended block.
- No GPU was used, so the concurrent C1-C8 packet refresh was not perturbed.
