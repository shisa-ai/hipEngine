# packet5 K4 localization: two-layer root cause (admission literal + draft chain budget)

## Summary

The Packet-5 K4 hang (1200 s / 3000 s, no completed prompt) has two
independent layers. Layer 1 (server) is FIXED: the MTP2 adapter's
candidate-budget admission hardcoded `{1, 2, 3}` and the batcher worker
orphaned queued items when it raised. Layer 2 (draft runtime) is now
localized and NOT yet fixed: the NextN exact-chain graph budget
`(1, 2, 3)` sizes the proposal token buffer for K3 only, so a K4 proposal
writes out of bounds and wedges the device in a blocking 4-byte D2D
`hipMemcpy`.

- `scripts/qwen38_packet5_k4_watchdog_probe.py` (commits 64f4db787,
  b69b5d2b5, 88bb3bf80, 6617c7bf1): watchdog probe with finished-task
  exception dump, direct engine-runner mode, batcher

- Commit 7a535cf23 — layer-1 fix:
  - `qwen35_gguf_mtp2.py`: admission bound derives from
    `_MTP2_MAX_CANDIDATE_DEPTH` (was the literal `{1, 2, 3}`).
  - `qwen35_gguf.py`: depth constant read live from the mtp2 module

    adapter clamping and desired-candidate logic.
  - `server/api.py`: `_run()` tracks popped-but-unfinished items

    with unchanged behavior.
  - Tests: admission-derives-from-depth; batcher finishes queued items
    when the route-cap raises.
