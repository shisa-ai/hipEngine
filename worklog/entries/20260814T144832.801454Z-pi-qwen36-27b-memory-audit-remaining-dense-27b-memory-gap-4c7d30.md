# Audit remaining dense 27B memory gap

## Summary

Reconciled the current selector-unset 512/1K/4K/8K memory matrix after the retained private-c1 arena. The objective is still open: whole-device peaks are **16.028/16.195/16.905/17.160 GiB**, or **0.339/0.495/0.993/0.994 GiB above llama.cpp Vulkan**. The 4K-to-8K slope itself is now correct (hipEngine **+0.2548 GiB**, Vulkan **+0.2539 GiB**, expected BF16 KV **+0.2500 GiB**); the unresolved growth is the **0.6541-GiB excess from 512 to 4K**, where full-row prefill scratch and hidden ownership scale while Vulkan does not.

A synchronized per-layer prefill trace reaches its resident plateau at the first full-attention layer; with tracked ownership unchanged, this is consistent with lazy page/runtime commitment and does not prove a separate allocation leak.
