# Compose ngram-mod ahead of dense GGUF MTP2

## Summary

Composed the request-local exact n-gram cache ahead of dense GGUF MTP2 without
creating a second request loop or target owner. Every eligible physical group
consults committed request history before NextN proposal. An all-row hit stages
only the already-qualified K<=3 prefix and uses the existing target frontier,
device accept, selected target commit, output, and cancellation transaction. A
miss or mixed hit/miss group runs ordinary physical MTP unchanged.

After target verification, the composer restores the pre-proposal NextN
checkpoint and catches target-attached MTP state up from target-owned BF16
pre-output hidden rows for the committed root plus exactly the accepted n-gram
prefix. Rejected candidates never enter MTP state or the request-local index.

Correction to the preceding core-entry wording: the final hardened cache does
not allow iterative exact-key cycles. It records the latest exact occurrence
and requires the configured contiguous continuation to end before the current
trailing n-gram. This preserves the useful llama.cpp mechanism while excluding
collision aliases, cyclic count/repetition artifacts, cross-request leakage,
and benchmark-order effects.
