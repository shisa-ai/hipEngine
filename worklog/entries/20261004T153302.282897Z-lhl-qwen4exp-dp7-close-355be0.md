## The capacity guard is the mechanism, and it is live

`Qwen4ExpGGUFTextGenerator`'s public chunk argument defaults to `None`, and `None` is what runs the
guard:

```

# plan is built there for the rung that wins.
plan = (None if prefill_chunk_size is None else plan_...(model_map, staging_token_capacity=prefill_chunk_size))
...
if prefill_chunk_size is None:
    # Capacity guard (ledger RT-1/RT-3): take the largest chunk whose
    # admission still yields the requested context, and fall back a step at a time when it does not.
```

**So the 1024→4096 step RT-1 asked for is not pending: it is the default path, reached through a
guard rather than a blanket flip, which is exactly the form RT-1's own cell argued for** ("a real
change with its own test/gate burden, not a constant edit"). This campaign implemented it
(`ee19f3321`, worklog `20261004T145428`).
