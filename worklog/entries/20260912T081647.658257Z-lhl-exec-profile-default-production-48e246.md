# Production execution profile becomes the shipped default

## Summary

An omitted `execution_profile` now resolves to `production` for every
model/backend/quant combination with a certified production plan, so a no-flag
run gets the measured fast composition instead of exact arithmetic. A
combination with no registered plan keeps the pre-profile migration path.

## Changes

- `hipengine/execution_profiles.py`: new
  `resolve_default_execution_profile(model, backend, quant)` returns
  `ExecutionProfile.PRODUCTION` when both a strict and a production plan are
  registered for that key, and `None` otherwise. Exported in `__all__`.
- `hipengine/llm.py`: `_resolve_execution_profile` consults the resolver when
  `execution_profile` is unset, so generator construction, the manifest
  properties, and server metadata all report the resolved `production` profile
  rather than `None`.
- `hipengine/server/__main__.py`: `--execution-profile` help text now names the
  new default.
- Tests: `tests/test_execution_profile_defaults.py` (new) pins the seven
  certified combinations as `production` and five uncertified ones as `None`.
  `tests/test_execution_profile_runtime.py` gains the omitted-profile case and a
  resolver unit test; the strict-only test is renamed to say what it now covers.
- Docs: `docs/EXECUTION-PROFILES.md` §2.1 default decision plus a superseding
  note in §2.2, `docs/REFACTOR.md` migration-seam entry, `docs/ENVS.md`,
  `docs/PLAN.md`, `CHANGELOG.md`, `README.md`.

## Validation

- RED/GREEN: with only `hipengine/llm.py` reverted, the omitted-profile test
  fails with `assert ['hello:legacy'] == ['hello:production']`; with the change
  it passes.
- Selector audit against the real registrations plus the runtime kernel modules:
  all seven certified combinations resolve `strict`→strict,
  `production`→production, `batch_invariant`→batch_invariant (per-scope strict
  fallback, `fell_back_to_strict` set), and omitted→production. Five uncertified
  combinations return `None`.
- `uv run pytest tests/test_execution_profile_defaults.py
  tests/test_execution_profile_runtime.py tests/test_execution_profile_evaluator.py
  tests/test_execution_profiles.py tests/test_qwen36_gguf_profiles.py
  tests/test_qwen36_gguf_gfx1100_profiles.py tests/test_qwen38_gguf_profiles.py
  tests/test_qwen4_exp_profiles.py tests/test_paro_mtp_profiles.py
  tests/test_server_speculative_provider.py` passes.
- Not run: the per-combination GPU numerical and serving gates. Those ran at
  certification and are retained as the §2.4–§2.8 decision artifacts; this
  change reuses them rather than re-measuring, so the evidence chain is the
  retained packets plus the resolver audit above, not a fresh gate run.
