# Defer bounded streaming handoff contract

## Summary

R0503 is still present. Move the stream-handoff interface decision to the ledger
bottom rather than changing collector limits and falsely calling it fixed.

## Changes

- Record both single-request server paths and the multi-request path, plus both
  one-event collector drains, in the deferred section.
- Name the choice between a ready-only batch contract and a bounded producer
  bridge. Generic iterators cannot distinguish buffered output from a blocking
  next step; permanent threadpool ownership introduces a capacity question.
- Preserve first-chunk latency, fairness, bounded buffering, terminal ordering
  and cancellation requirements. Current queue cleanup already waits for the
  producer to avoid closing a generator during an active worker call.
- No production behavior or collector limit changed; no speedup is claimed.

## Validation

- Inspected `hipengine/server/api.py` stream adapters and batcher cancellation,
  `hipengine/generation/engine_service.py` drain sites, and
  `hipengine/generation/concurrency2.py` nonblocking drain implementation.
- Read the revised ledger section; documentation and audit gates passed.
