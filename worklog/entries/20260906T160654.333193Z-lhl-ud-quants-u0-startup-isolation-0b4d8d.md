# ud-quants U0 startup isolation: lazy root-package LLM exports

## Summary

Fixed the one binding gap from the U0 review: a fresh process importing
`scripts/gguf_quant_route_audit.py` loaded `hipengine.kernels.hip_gfx1100`
through the eager chain `hipengine/__init__ -> hipengine.llm ->
hipengine.speculative.__init__ -> mtp_native -> kernels`, violating the
absolute no-backend-import requirement for the CPU metadata audit. The root
package now resolves `LLM`/`SamplingParams` lazily (PEP 562 module
`__getattr__`); `ExecutionProfile` stays eager. Public API, runtime behavior,
and kernel registration are unchanged. Supersedes the "residual cold-path
import chain (not fixed here)" note in docs/REFACTOR.md, which itself
acknowledged the gap left open by the U0 policy/accounting entries
(20260906T155656..., 20260906T155736...).

## Changes

- `hipengine/__init__.py`: `LLM` and `SamplingParams` became lazy exports
  resolved on first attribute access from `hipengine.llm` and cached in package
  globals; `ExecutionProfile` still imports eagerly (pure metadata module).
  `__all__` and `__dir__` unchanged in content. Chosen over alternatives
  because it is the narrowest boundary: registrations happen inside
  `LLM.__init__` (not at module import), and no other in-package module imports
  `hipengine.llm`, so a bare `import hipengine` is now CPU-safe while any real
  use of `LLM` imports exactly the same modules as before. No
  sys.modules stubbing, no scanner copying, no swallowing of import errors.
- `tests/test_scripts_gguf_quant_route_audit.py`: NEW
  `test_fresh_process_audit_never_imports_gpu_backend_packages` -- fresh
  subprocess installs a meta-path import guard rejecting
  `hipengine.kernels.hip_*` / `hipengine.kernels.cuda_*` / torch BEFORE any
  import, then spec-loads the audit script, exercises the real CLI
  (`--help` plus `main()` with `--json` over the deterministic complete-fixture
  GGUF), and asserts zero backend modules loaded, zero guard trips, no
  `hipengine.llm`/`hipengine.speculative` loaded, and a schema-v2 format-valid
  report. The existing in-process delta guard
  (`test_capability_path_adds_no_backend_package_imports`) is kept: it covers
  the audit's own added imports, while the new test covers startup.
- `tests/test_hipengine_public_api.py` (NEW): fresh-subprocess contracts for
  the lazy boundary -- bare `import hipengine` loads no llm/speculative/backend
  module and no torch; `from hipengine import LLM, SamplingParams,
  ExecutionProfile` binds the real classes with identity across repeat access
  and against `hipengine.llm`/`hipengine.execution_profiles`; direct
  `import hipengine.llm` keeps package attributes in sync; unknown attributes
  still raise AttributeError.
- `docs/REFACTOR.md`: residual cold-path import chain marked fixed (2026-09-07)
  with the mechanism, guards, and the honest remaining limitation (touching
  `LLM` still loads kernels by design).
- `docs/UD-QUANTS.md`: U0 files list and exit text updated with the
  startup-isolation follow-up; status line notes `import hipengine` loads no
  GPU backend package. No runtime numerical/dispatch claim added.

## Limitations

- Actually touching `hipengine.LLM` (or importing `hipengine.llm`) still loads
  the speculative package and the kernel modules -- that is the required
  runtime registration path and is intentionally preserved.
- The fresh-subprocess guard blocks backend subpackage names by prefix
  (`hipengine.kernels.hip_`, `hipengine.kernels.cuda_`, `torch`); a future
  backend directory outside those prefixes would need its prefix added to the
  guard's `BLOCKED_PREFIXES` in the test driver.
- pytest collection imports test modules in-process, so startup isolation
  remains provable only via the subprocess tests; that is by design and
  documented in the test file.
