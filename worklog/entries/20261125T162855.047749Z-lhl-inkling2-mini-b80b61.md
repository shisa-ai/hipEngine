Artifacts: [`production`](../../benchmarks/results/2026-11-25-w7900-inkling2-mini-gguf-serve-production.json), [strict](../../benchmarks/results/2026-11-25-w7900-inkling2-mini-gguf-serve-strict.json). `/v1/models` reports the resolved profile and manifest, and every
request on both profiles returned the same text. The server needs `--kv-storage auto` for this
model; started without it, startup stops at the warm-up with `kv_storage='bf16'` refused by name.

**Four requests together do not use the resident visit.** A four-row decode batch steps the
sessions in lockstep through the eager path with the strict F32 expert tiles. In a probe with four
threads, a round of four 48-token requests took 8.45 s, 22.7 tok/s in aggregate, which is about
176 ms for each step of four tokens against 26 ms for one resident step; the model counted 2
captures and 0 replays. A stream in that batch decodes at 5.5 tok/s where it would decode at 37.8 alone. Four
resident single-row steps would take about 106 ms, so stepping each row of a multi-row batch
through its own resident visit would raise the aggregate to about 37 tok/s before any batching.
That is the next serving work; the campaign plan's step 6 owns it. No capture pin is allocated for
this model, so captures do not grow the pin pool.
