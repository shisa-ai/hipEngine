# the attention reduce placement is throughput neutral so phases wins on shape

## Summary

Head sharding makes `attn_output`/`ssm_out` row-parallel, so each rank holds a
hidden-size partial that `_bulk_norm_residual_layer`'s residual add plus
`post_attention_norm` consumes. That is a second reduction per layer, and the
open question was where it should live: a second `CompiledDeviceExchange`
instance (`split`) or extra slots on the existing one (`phases`).

Both were built and measured. **They are throughput-equivalent**, which the
layer structure makes necessary rather than surprising: the norm sits between the
attention output and the MLP chain, so no placement can fuse the two rounds, and
each pays one staging write, one publish, one peer read and one spin-add per
round. Warmed, `phases` measures **0.964 ms/reduction** and `split` **1.003** at
the production shape, with **identical pinned staging at 20.97 MB/rank** —
`split` buys 2+2 slots across two arenas, `phases` buys 4 slots in one.

The decision is therefore `phases`: equal throughput, equal memory, one exchange
handle, one step counter and one arena instead of two, with the phase separation
explicit in the slot index rather than implicit in a second object.

## Changes

- `hipengine/distributed/shard_group.py`:
  - `MlpShardGroup(reductions_per_layer=P)` sizes the device exchange at
    `2 * P` slots. `P = 1` is the shipped configuration and is unchanged.
  - New `reduce_device_payload(layer_id, partial_ptrs, out_ptrs, *, phase=0,
    rows=None)` sums one payload across ranks into a named output, using
    `slot = P * (layer_id % 2) + phase`. `_forward_device_reduce` is now a thin
    wrapper passing `phase=0` and `self._out_ptrs`, so the MLP route's slot
    sequence is untouched.
  - The phase count is validated at construction (`>= 1`) and the phase index at
    each call (`[0, P)`), so a mis-sized or mis-indexed call fails instead of
    aliasing a slot.
- `scripts/tp2_attention_exchange_ab_probe.py` (new): drives all three placements
  over one synthetic `layers x (attention, mlp)` reduction sequence, reporting
  wall time, staging per rank, and a bit-exact check of every reduced output
  against the host RNE-narrowed bf16 sum.
- `tests/test_unit_distributed_shard_group.py`: three tests pinning the phase
  slot arithmetic (`[0,0,1,1, 2,2,3,3, 0,0,1,1]` over three layers), that
  `P = 1` still yields `[0,0,1,1,0,0]`, and the output targeting plus phase and
  phase-count validation.

## Validation

- `python3 -m pytest tests/test_unit_distributed_shard_group.py -q` — 25 passed.
- `python3 -m pytest tests/test_unit_distributed_shard_weights.py
  tests/test_unit_distributed_tp2_generate.py
  tests/test_unit_distributed_staged_and_shard.py
  tests/test_unit_distributed_staged_compiled.py -q` — 125 passed.
- `python3 -m pytest tests/test_gpu_distributed_staged_compiled.py -q` — 7
  passed, 1 skipped (two-device guard). The real device exchange is unchanged
  for `P = 1`.
- A/B on the two-device host at 512 rows x 5120 hidden x 64 layers, 9 repeats,
  2 warmup: warmed `phases` 0.964 vs `split` 1.003 ms/reduction, identical
  20.97 MB/rank staging, and **0 mismatches** in every checked reduction of both
  ranks for both placements. Artifact:
  `benchmarks/results/2026-09-23-w7900-tp2-attention-reduce-placement-ab.json`.

Two findings worth carrying forward:

- **The first measurement was wrong, and the reversal caught it.** The initial
  run reported `split` at 2.62 ms/reduction and `phases` at 0.96, a 2.7x gap that
  would have justified `phases` on performance. Re-running with the order
  reversed reversed the result: whichever variant runs first in a process is
  1.7-2.7x slower. `split` alone measures 1.03 and `phases` alone 1.69, so the
  only consistent figures are the order-corrected warmed ones. The apparent win
  was a warmup artifact.
- **`shared` is rejected on the protocol, not on a reproduced failure.** Reusing
  the two existing slots would need half the staging (10.49 MB/rank) and measured
  no slower (0.94 ms/reduction). But `tp2_dev_spin_add_bf16` spins on
  `while (*remote_flag < expected)`, so it exits as soon as the flag *reaches*
  the step — the peer is then free to overwrite its staging while this rank's
  spin-add is still reading it, and nothing in the protocol acknowledges the
  read. One 25-minute hang was observed in a single `shared` timing run at the
  production shape; it did not reproduce in two later bounded attempts, and
  160 checked reductions across three shapes showed 0 mismatches, so the hazard
  is argued from the protocol rather than demonstrated.

## Next

  the per-rank attention-output partial, and the reduce writes into the buffer
  `_bulk_norm_residual_layer` already reads, so no extra destination buffer is
  needed. Construct the group with `reductions_per_layer=2` and call
  `reduce_device_payload(..., phase=1)` for the attention partial.
