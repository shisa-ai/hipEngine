# Full-grid prefetch cost stays in the value pass

## Summary

The depth16 value pass takes longer than depth4 at every profiled shape. At
1152 keys / dimension 256, medians are 255.162 versus 200.161 microseconds;
the incumbent slice and combine take 101.361 + 3.360 microseconds. Value-pass
VGPR allocation rises from 40 to 48; neither candidate spills to scratch.
These traces do not establish occupancy or register moves as the causal limit.

The unchanged incumbent measures 45.86173681210079 decode tok/s on host `epyc`,
physical GPU1 RX 7900 XTX, Gemma 4 26B-A4B-it UD-Q4_K_XL, context 8192,
greedy, BF16 KV, 1024 prompt / 128 output, three samples. This is a baseline
refresh, not an optimization win or a claim that the numerical defect is fixed.

records the cached-binary trace protocol, source script, binary hashes, shape

BF16, 16 query heads, respectively 2/8 KV heads. Eight repetitions per shape;
discard the first and report medians of seven. Sort CSV dispatches by start
timestamp before grouping: CSV row order is not reliably dispatch order.
Expected class, slice/combine and dimension kernels appear with plausible
nonzero durations. Phase1 times are similar between candidates; the value-pass
increase is the principal difference in these traces.
