# Release renumbered to v0.6.1 by lead decision

## Summary

The lead set this release to **v0.6.1**, a point release, not v0.7.0. The decision
is executed: the version is renumbered and the release content is unchanged. The
release scope is still everything between the v0.6.0 tag and `main`.

This supersedes the version choice in
`worklog/entries/20260922T065307.435598Z-lhl-release-v070-publish-028b54.md`, which
picked a minor bump by applying the `docs/reference/PUBLISH.md` rule that new
public/server features and meaningful runtime behavior additions take a minor
bump. That rule is a documented default for choosing a number; it does not
override the lead's call, and the lead owns the number. The rule text is left as
written.

## Changes

- `pyproject.toml`: `version = "0.6.1"`.
- `CHANGELOG.md`: the release heading is `## v0.6.1 - 2026-09-22`. Section content
  is unchanged.
- `README.md`: the current-release line and the changelog anchor point at v0.6.1,
  and the status section reads `v0.6.1 is alpha`.
- No other tracked file referenced the old number. The two remaining `0.7.0`
  strings in `benchmarks/results/` are the `safetensors` library version and are
  unrelated.
