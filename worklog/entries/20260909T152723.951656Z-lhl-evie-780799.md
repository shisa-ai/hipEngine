# EVIE k2 recurrence + GDN precision wall

## Summary

Swapped the GDN recurrence to the exact k2 variant (5.96e-08 parity vs
naive, 3.2x faster: 3.24 -> 1.02 ms/layer). Bench (8p+8q, fp16): 4.52 s
-> 4.08 s: doc 3.19 s, query 0.89 s, maxsim 0.4 ms — beats the torch fp32
baseline (4.148 s). torch bf16 (1.356 s) still ~3x ahead.

## Changes

- `hipengine/runtime/evie.py`: `qwen35_gdn_prefill_recurrent_k2_f32`
  replaces the naive kernel.

## Validation

- k2 vs naive recurrence on the layer-0 capture: max 5.96e-08.
- Full fixture parity (fp16 mode, GDN projections fp32): query cos
  0.9999995, doc cos 0.99987, maxsim 5.9240 vs 5.9114 (+0.2%).
- `tests/test_evie_gpu_runtime.py` 3/3 (strict fp32 path).

## Decision: GDN projections stay FP32

Empirically re-verified (post-conv1d-fix, no confounders): with
in_proj/out_proj in fp16, text-stack hidden states drift systematically
(query cos 0.015) — the gated-delta-net recurrence amplifies fp16 input
rounding through the persistent state. An earlier "GDN fp16 is fine"
conclusion was a silent no-op edit (outputs identical to the digit); the
real fp16-GDN config runs 2.76 s but produces wrong embeddings. GDN
projections remain fp32 SGEMM (~6.8 ms/layer, the current dominant cost,
~160 ms/page). The normalized/cluster8 recurrent variants (0.25 ms) are
not numerically equivalent (max err 0.39 on scale 0.43) and would need
the full production-profile gate before use.
