# Bind the GR-up wide tile to runner ownership

## Summary

`HIPENGINE_QWEN4_EXP_GR_WIDE` no longer exists as a runtime input. The resolved
plan's own manifest selection is published on the owning runner (`gr_wide`), the
GR read dispatch reads that field, and every diagnostic harness that used to
write the key binds the field with the new `gr_wide(owner, enabled)` scope. This
is the host-side half of `docs/REFACTOR.md` R0028, following the R0029
`router_producer_variant` pattern. The parent's public correct-path check now
shows the route engaging on the F16-direct leaf above 256 rows and not at 73;
the canonical depth gate is still running and this entry claims no result from
it. See Next.

## Changes

- `hipengine/runtime/qwen4_exp_runner.py`: `_qwen4_exp_gr_wide_enabled(rows,
  low_rank, published=False)` keeps the `rows > 256` and `low_rank % 64 == 0`
  guards and drops the process-key read. `run_qwen4_exp_gr_read` and the three
  layer entry points (`dense_qsa`, `qsa_prefill`, `gdn`) take and forward
  `gr_wide` exactly where they forward `gr_wave_scale`; the resident runner
  declares `gr_wide: bool = False` and forwards `self.gr_wide` at all eight
  layer/head call sites. New `gr_wide(owner, enabled)` scope: binds a generator
  and the runner it currently holds, yields the prior values, restores on
  unwind including after an exception, and also restores a runner the owner
  builds or swaps in during the scope to the owner's prior route.
- `hipengine/generation/qwen4_exp_profiles.py`: `_publish_gr_wide` publishes the
  manifest decision (`_gr_wide_projection_selected`) to the generator and its
  current runner on every bind, so a later bind in the same process publishes
  its own route. The retired key name is kept only for
  `_record_owner_transport`, so a pre-binder caller value is still reported as
  discarded. `GR_WIDE` joins `Q4_DP4A64`, `PRODUCTION_MOE_PREFILL` and
  `Q8_MMQ_PREFILL` in the recovery sweep's exclusion set, so no production path
  writes the key.
- `hipengine/generation/qwen4_exp_gguf.py`: unbound generator default and
  `_inherit_lane_decisions` clone transport for the new field.
- Diagnostics migrated together, matching R0029: `qwen4exp_profile_gap.py`
  gains `--gr-wide on|off` and rejects `--override
  HIPENGINE_QWEN4_EXP_GR_WIDE=...`; `qwen4exp_disabled_selector_ranking.py`
  moves the `gr_wide` arm into `OWNER_ARMS`; `qwen4exp_layer2_profile_gate.py`
  gains `CandidateSpec.gr_wide` and moves the four arms that named the key
  (`production_conservative`, `fast_composition`, `production_gr_up_wide`, the
  F16 isolation set) onto the field; `qwen4exp_gr_iu8_logits_probe.py` binds the
  `wide` route on the generator; `qwen4exp_halo_box_campaign_ab.py`'s
  `gr_wave_scope` closes the wide tile on the runner instead of in
  `GR_WAVE_ENV`.
- Every harness that applies a candidate environment binds the shared
  declaration now, so no arm can silently inherit the plan's route:
  `qwen4exp_layer2_profile_gate.py` owns `gr_wide_arm_scope` and
  `bind_candidate_gr_wide` (both read `CandidateSpec.gr_wide`); the depth gate,
  `qwen4exp_prefill_restore_ab.py`, `qwen4exp_active_task_checks.py`,
  `qwen4exp_q8_repair_tasks.py` and `qwen4exp_long_context_gate.py` call them and
  record the route in force, and `qwen4exp_conservative_cost.py` binds its
  before/after pair (`before` = the production publication, `after` = the
  conservative package's former `0`).
- `qwen4exp_journey_localize.py` is the one harness whose arms are not
  candidates. The retired key was a captured `GR_*` key, so both bindings' former
  environments carried it: `gr_wide_snapshot` reconstructs each snapshot from the
  route its binding publishes, `snapshot_arms` rebuilds the snapshot-derived arms
  from them exactly as before, and `migrate_gr_wide_arms` records each arm's
  former value (declaration first, then the snapshot's key, then the production
  route the arm loop's `bound` snapshot supplied) and drops the key. The arm loop
  binds `gr_wide_arm_enabled`, `gr_wide_split_scope` binds the split arms'
  strict phase, and `owner_overrides.gr_wide` reports what ran.
- Dispatch counting follows the leaf that runs: `CandidateSpec` gains
  `extra_direct_dispatch_targets`, `count_candidate_dispatch` patches and names
  them in the same counter (`leaves`), and `production_gr_up_wide` declares the
  two F16-operand fused epilogues beside its F32 tile. Counting only the F32 tile
  reported zero calls while the F16-direct composition ran the route.
- Counter shape is uniform: `empty_dispatch_counter()` owns `calls`/`shapes`/
  `leaves`, `count_candidate_dispatch` returns it on every path (and accepts
  extra targets without a primary, rejecting only `shape_positions` with no
  primary to describe), and `candidate_dispatch_counter` is the single
  create-or-count helper both gates now call. The two gates used to initialize
  `{"calls": 0, "shapes": {}}` for noncounted arms and then read
  `counter["leaves"]` unconditionally, so `production_baseline` and every other
  uncounted candidate raised `KeyError: 'leaves'` while the report was written.
- `docs/ENVS.md`: the `HIPENGINE_QWEN4_EXP_GR_WIDE` row is now `retired` with the
  owner-bound replacement named. `docs/REFACTOR.md` is untouched (parent owns
  R0028's closure text).
- Tests: new `tests/test_unit_qwen4exp_gr_wide_owner.py` pins shape guards
  (rows 64/256/257/1024, ranks 64/300/320/384), the published choice, stale-key
  inertness, absence of a runner-module reader, manifest-driven publication,
  profile precedence across two owners, discarded pre-binder reporting, nested
  and raising scopes, a runner built inside the scope, clone inheritance, and
  layer forwarding. Existing tests moved from the key to the field
  (`test_unit_qwen4_exp_profiles`, `test_unit_qwen4exp_arithmetic_recovery`,
  `test_unit_qwen4exp_gr_staged_removal`, `test_unit_qwen4exp_gr_wave_scope`,
  `test_unit_qwen4exp_disabled_selector_ranking`,
  `test_unit_qwen4exp_layer2_profile_gate`); the `gr_scale_only` expression
  evaluator and the `prefill_chunks` harness now supply the field. New
  `tests/test_unit_qwen4exp_gr_wide_arms.py` covers the shared scope and binder,
  every harness's per-arm helper, the journey reconstruction (the full arm table
  the former environments produced) and the split-phase scope, plus the
  multi-leaf counter.
