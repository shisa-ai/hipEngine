# R0195 retire exact-rows and Q6-mixed rollback flags

## Summary

Retired the two R0195 rollback flags, `HIPENGINE_GGUF_SPECDEC2_EXACT_TARGET_ROWS` and
`HIPENGINE_GGUF_SPECDEC2_Q6_MIXED_TARGET_ROWTILES`, now that their replacement policies have
explicit device coverage. Both defaulted to the production behavior (True); retirement removes
the ability to withdraw the capability, so exact rowtile rows and mixed Q6 rowtiles are always
admitted per backend capability. The C7/C8 policy `enabled_env` diagnostic controls are separate
and preserved. This closes the last R0195 cleanup step; the publicly reachable device coverage was
already complete (see the device / committed-state / exact_row_count checkpoints).

## Changes

- `hipengine/generation/physical_target_rows.py` `resolve_physical_target_rows()`: dropped the
  `enabled("…EXACT_TARGET_ROWS", True)` wrapper (exact rows + C7/C8 policies now unconditional) and
  the `and enabled("…Q6_MIXED_TARGET_ROWTILES", True)` clause in `mixed_q6`. Kept the `enabled`
  helper and the C7/C8 `enabled_env` checks. Updated the docstring.
- `tests/test_unit_physical_target_rows.py`: renamed `test_rows_plan_snapshots_rollbacks` →
  `test_rows_plan_snapshots_capabilities_ignoring_retired_rollbacks`; it now sets both retired flags
  to `0` and asserts the capability stays admitted, while the C7 `TEST_EXACT_ROWS` control still
  gates only its own rows. Removed the retired flag from the attribution-matrix env cleanup.
- `tests/test_unit_qwen35_gguf_mtp2_seam.py`: renamed the two rollback tests and replaced their
  rollback sections with retired-flag-ignored assertions (`mixed_q6` stays True; exact rows stay
  `(8, 28, 32)` with pad 0). C7/C8 and profile-bound-owner sections preserved.
- `docs/ENVS.md`: both flags marked `retired` / "No runtime reader" per the file's convention.
- `docs/REFACTOR.md` R0195: Scope marks both flags retired; corrected `accept_capacity_fallback`
  from "still outstanding" to definitively unreachable (accept buffer sized to
  `max(24, ceil(frontier/6)*6)`, a rows6 multiple ≥ the largest possible group, so the capacity guard
  in `physical_group_pad_rows` never fires); recorded the retirement + replacement coverage.
