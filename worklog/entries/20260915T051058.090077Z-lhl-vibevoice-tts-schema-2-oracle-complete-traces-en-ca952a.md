# VibeVoice-TTS schema-2 oracle: complete traces, enforced pins; fixtures regenerated

## Summary

A second review rejected the milestone-1 closure on five capture/provenance
gaps. All five were verified against the code and the fork, and all five are
real. The oracle was reworked to fixture schema 2 and the fixtures were
regenerated; two consecutive full runs now reproduce all 12 artifact files
byte-identically. Milestone 1 is re-established on complete traces.

The five findings, each confirmed before fixing:

1. **Checkpoint pin not enforced.** `_snapshot_dir()` resolved the
   lexicographically last cached snapshot for the manifest while
   `from_pretrained` loaded the model ID through the hub cache's own
   resolution -- two independent resolutions of one pin. Fix: both the
   processor and the model load from the explicit snapshot directory named by
   `--model-revision` (default: the doc pin
   `c00898d257e6b46004e3e2866a47534085fb685a`), and a dirty fork tree is
   refused unless `--allow-dirty-fork`. `vibevoice_tts_weight_inventory.py`
   had the same defect and gets the same treatment.
2. **Decoder input capture broken.** The recorder cleared `_cur` when
   `sample_speech_tokens` returned; the decoder runs afterward, so its hook
   never fired with state attached -- both committed diffusion fixtures
   contained zero `scaled_latent` arrays, and the 8-call cap left the
   latent-to-PCM chain unreplayable (25/48 audio chunks). Fix: `_cur` stays
   set until the decode hook consumes it; every diffusion call is retained
   (cap removed); each decode records its `scaled_latent` input, batch
   `sample_indices` (the fork passes them to `decode`), and a
   `decoder_called` flag; `check_complete()` refuses an incoherent capture.
3. **Unconnected captures.** The oracle performed three separate speech-encode
   passes -- a reseeding one in `_reference_fixture`, the explicit prefill,
   and generate's first step -- each consuming different draws, and only the
   first was exported. Fix: one connected execution trace. The standalone
   reseed is gone; `_process_speech_inputs` is wrapped so the prefill and
   generation passes each record their own draws, latents, features and
   connected embeddings, and every fixture states which pass it holds
   (`reference.npz` = the generation pass; `prefill_*` keys in
   `lm.npz` = the prefill pass). A capture that cannot be attributed is an
   error.
4. **Incomplete feedback and scheduler records.** Feedback fixtures held
   semantic features only (the docstring advertised more), and the scheduler
   record had class + timesteps but no solver configuration. Fix: feedback
   fixtures now carry semantic features, the acoustic and semantic connector
   embeddings, their recorded sum, and sample indices per diffusion call; the
   scheduler record adds the full config as canonical JSON (`dpmsolver++`,
   order 2, midpoint, cosine, v_prediction, timestep spacing) plus
   streaming-cache `set_to_zero` events labeled acoustic/semantic with their
   sample indices.
5. **Destructive setup script.** `setup_vibevoice_tts_oracle_env.sh` ran
   `rm -rf "$VENV"` unconditionally on a caller-supplied path. Fix: an
   existing destination is refused; `--recreate` is the explicit, guarded
   deletion path. Both behaviors tested.

## Changes

- `scripts/vibevoice_tts_oracle_torch.py`: rewritten to schema 2 (enforced
  snapshot + fork pins, complete per-call capture, connected per-pass trace
  attribution, feedback embeddings and sum, scheduler config, cache-reset
  events, NaN check on the scaling factors, `check_complete` invariant).
- `scripts/vibevoice_tts_weight_inventory.py`: pinned snapshot resolution and
  load-from-snapshot for `--verify-model`.
- `scripts/setup_vibevoice_tts_oracle_env.sh`: refuse existing destination
  without `--recreate`.
- `docs/MODEL-VIBEVOICE-TTS.md`: status, oracle section and milestone-1
  closure rewritten for schema 2.
- `tests/fixtures/vibevoice_tts/`: regenerated (10 `.npz`, 1,690 arrays,
  12 MB; `weight_inventory.json` re-verified with the model cross-check).

## Validation

- Full oracle run (gfx1151, Radeon 8060S, pinned venv transformers 4.51.3,
  torch 2.13.0+rocm10.0.0, snapshot and fork pins enforced, fork clean):
  single 148 generated ids -> 80,000 samples (3.333 s, rms 0.055272), 25/25
  diffusion calls with decoder inputs; two 411 ids -> 176,000 samples
  (7.333 s, rms 0.091783), 55/55 calls with decoder inputs; 6 cache-reset
  events across both requests; `check_complete` invariants held.
- Reproducibility: two consecutive full runs byte-identical across all 10
  `.npz` + `manifest.json` + `weight_inventory.json` (md5). The first
  reproducibility attempt caught a real bug the schema-2 change introduced:
  the scheduler's `_use_default_values` list is built upstream from a set
  difference, so its order varies per Python process and the recorded config
  JSON broke byte identity. Canonicalizing (sorting) that list fixed it; the
  numeric arrays were identical throughout.
- Weight inventory re-run with `--verify-model`: 1204 tensors,
  2,704,021,987 parameters, 5.037 GiB, zero orphans, `lm_head` tie verified
  by `data_ptr` equality, buffer delta 2 -- unchanged numbers, now loaded
  from the enforced snapshot.

## Notes

- The regenerated PCM differs from the first closure's fixtures (rms
  0.055272/0.091783 vs 0.059446/0.053668; the two-speaker script now
  generates 411 vs 402 ids). Expected: removing the reseeding standalone
  encode changed the RNG consumption order, so generation follows a different
  but equally pinned draw sequence. The old numbers remain only in the
  immutable first-closure entry, which this entry supersedes on capture
  completeness.
- The manifest records `oracle_schema: 2`, `model_revision_matches`, and
  `fork_dirty: false`.
