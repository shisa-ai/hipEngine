# Promote WMMA prefill attention for gfx1100

## Summary

Lead directive (2026-10-10): make WMMA prefill attention work on gfx1100 and
keep going on prefill. The gfx1100 production plan now requests
`gemma4_wmma_flash` and `gemma4_wmma_flash_full` for multi-row prefill blocks.
Decode is untouched: the plan's decode scope still owns decode steps, and the
flash route serves them.

Measured on AMD Radeon Pro W7900, Gemma 4 26B-A4B `UD-Q4_K_XL`, production,
BF16 KV, 128 outputs, one warmup and three samples,
`scripts/gemma4_campaign_bench.py`, same tree before and after the change:

| prompt | prefill tok/s before | after | ratio | decode tok/s before | after |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 512 | 1249.6 | 1253.2 | 1.003x | 70.22 | 70.38 |
| 8192 | 1014.9 | 1194.3 | 1.177x | 69.12 | 69.22 |
| 32768 | 892.0 | 1086.4 | 1.218x | 54.07 | 53.86 |
| 65536 | 772.8 | 970.8 | 1.256x | 41.75 | 41.67 |

Public generated ids are equal before and after at every length and
`public_path_parity` is true on all rows.

## Changes

- `hipengine/generation/gemma4_profiles.py`: the gfx1100 production plan
  declares the two `prefill_attention` scopes with the WMMA variants and its
  binder sets the generator's prefill request in scope order. Strict declares
  `gemma4_plain` as each scope's rollback key and binds no request, so strict
  prefill stays on the layer's route chain (blocker B5 in the module docstring).
  Variant registration reuses `gemma4_gguf_profiles`.
- `hipengine/runtime/gemma4.py`: a decode step forwards no prefill request when
  the plan declares a decode scope. Without this the request would take every
  one-token block and displace the flash decode route. A plan with no decode
  scope (gfx1151) is unchanged.
- `hipengine/runtime/gemma4_decode_graph.py`: the explicit capture surface
  mirrors the same rule in its workspace reservation.
- Tests: `tests/test_unit_gemma4_profiles.py` pins the production request, its
  order, and the strict no-request behavior;
  `tests/test_unit_gemma4_staged_prefill_integration.py` pins the four
  phase-by-scope forwarding cases.
- `docs/REFACTOR.md`, `benchmarks/CHANGELOG.md`, `benchmarks/README.md`, and
  `benchmarks/results/2026-10-09-gemma4-gfx1100-wmma-promotion-packet.json`.

  against 3%, top-1 98.94% against 96%; every case passed with repeats and
  isolation clean. `mixed_ja_en_review` fails its task check on both arms.

  (flash) with identical launch counts, 30,655 / 122,695 / 15,790 at keys
  1,025-2,047 / 4,097-8,191 / 15,857-16,383.

  5e-8 over 1,023, 4,095 and 527 rows, with 0, 1 and 0 top-1 flips. Maxima are
  3.87, 15.3 and 4.5e-3: isolated routing-flip rows, which the envelope budgets

  4.4e-6 and max 1.3e-3 against that tree's exact arm.
- `pytest` default unit tier: exit 0 before the new tests; the two edited test
  files pass 78/78 after.
