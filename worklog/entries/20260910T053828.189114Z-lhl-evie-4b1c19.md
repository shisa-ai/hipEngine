# EVIE review round 3: encode-path fixed costs + bench accuracy leg

## Summary

Review round 3 optimization candidates verified and fixed: (a) the GDN
conv-state zero was a host alloc + H2D upload per layer (24x per page) —
replaced with the GPU-side scale-by-0.0 kernel on the persistent buffer;
(b) the prefix head did a GPU->CPU->GPU bias roundtrip per encode — now a
persistent device copy (kept across _release_call_buffers) — and computed
all 2048 projection channels before slicing to 128 — now GEMMs the
contiguous first 128 rows directly (16x less head GEMM work, no slice
pass). Batching (the reference's 8-pages-per-forward) remains the known
lever, not attempted here.

Also: the bench gains an accuracy leg (`--accuracy`): after timing, the
same inputs are re-encoded in strict fp32 and the full NxN MaxSim matrix
is compared (max/mean delta, maxrel, argmax agreement).

## Changes

- hipengine/runtime/evie.py (conv-state zero, head projection, bias
  cache, keep-set), scripts/evie_hip_bench.py (--accuracy).

## Validation

- tests: gpu strict 3/3, gpu fp16 4/4 (first attempt failed maxsim by
  0.054 — the head-bias buffer was freed by _release_call_buffers and
  reused; fixed by adding it to the keep set).
- bench fp16 8p+8q: 2163 -> ~2114-2153 ms (~-2.5%); accuracy leg:
  max|d| 0.0065, maxrel 0.001, argmax agreement 8/8 vs strict fp32.
