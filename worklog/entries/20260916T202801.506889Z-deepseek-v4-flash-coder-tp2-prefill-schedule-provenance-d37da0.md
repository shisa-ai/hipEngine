# Bulk-vs-serial prefill divergence is T2 arithmetic; sustained gate fails closed on mixed schedules

## Summary

The saved TP2 sustained failure is **not** an ownership/control defect. A bounded
per-layer bisect on the same loaded resident TP1 model, prompt, and positions
(`mixed_ja_en_translate`, 64 prompt tokens) shows that changing only the prefill
schedule (bulk vs token-serial) produces smooth, monotone T2 association drift:

| Boundary, prefill end | bulk vs token-serial |
| --- | ---: |
| Full-vocabulary logits KL | **6.08e-05** (top-1 match) |
| Hidden RMS, layer 0 → 63 | 5.5e-05 → 0.122 |
| Conv-state RMS, layer 0 → 62 | 1.8e-03 → 5.5e-02 |
| GDN recurrent-state RMS (all layers) | ≤ 4.5e-04 |

There is no step change, no single-layer jump, and the long GDN accumulator
barely moves. The 0.299 bulk-vs-serial KL previously measured at decode position
146 is that small prefill-end state difference amplified over 83 GDN-recurrent
decode steps.

The actual defect is a **protocol/provenance gap**: the TP2 native path
(`MlpTP2GenerationSession`) only implements token-by-token prefill, while the
optimized TP1 teacher uses bulk prefill. `NativeARAdapter` did not record which
prefill schedule it used, and `report_sustained` scored the arms regardless, so
the harness reported a "TP2 numerical failure" for what is also a prefill
schedule mismatch. `TP2` (serial) sits at KL 0.028379 from a matched-schedule
serial TP1 reference and 0.108406 from the bulk teacher — consistent with the
schedule being the dominant difference.

Minimal repair: record `prefill_schedule` in the adapter route/scope manifest
and make `report_sustained` fail closed on any teacher/candidate mismatch. The
production numerical envelope is unchanged; token-serial is **not** substituted
as a denominator; no arithmetic or GPU path changed.
