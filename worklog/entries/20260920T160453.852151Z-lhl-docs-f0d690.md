# Complete ENVS.md env-var reference and coverage checker

## Summary

Made `docs/ENVS.md` a complete reference for every environment variable read
by the runtime, tests, and bundled harnesses, and added
`scripts/check_envs_docs.py` so the coverage stays complete. A code scan
resolved 837 distinct env names (literal and `CONST = "NAME"`-indirected
`os.environ`/`getenv` reads, every `HIPENGINE_*` literal to cover tuple-of-
names harness loops, and `${VAR}` shell reads); before this unit roughly 130
names were documented and the rest were absent.

## Changes

- `docs/ENVS.md` rewritten as a subsystem-organized reference (core runtime,
  server, vision, build/JIT cache, engine loop, GGUF, shared paged attention,
  fusion seams, PARO, Qwen4Exp, build ablation, diagnostics, test gates,
  harness, third-party, and a "Names that are not environment variables"
  appendix for `-D` macros, name-prefix fragments, `_ENV` constant
  identifiers, capability keys, placeholders, and removed flags).
- Kept the existing recommended-profiles guidance and all prior row text;
  descriptions for new rows are grounded in the reading sites (defaults,
  accepted values, rollback semantics).
- Added `scripts/check_envs_docs.py`: scans the tree for env reads and fails
  while any name is missing from the doc or its not-env-vars appendix.
  `--list` prints only the uncovered names. The doc intro references it.

## Validation

- `python3 scripts/check_envs_docs.py` reports 837/837 names covered and
  exits 0.
- `python3 -m py_compile scripts/check_envs_docs.py` passes.
- Read the changed `docs/ENVS.md` end-to-end; fixed two table-formatting
  defects found during the read (a merged build-table row and a missing
  trailing cell pipe).
- No GPU run needed (docs/process tier).

## Next

- Run `scripts/check_envs_docs.py` whenever adding or renaming an env knob
  (the doc intro now says so).
