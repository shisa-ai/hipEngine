# Isolate retryable admission rejection per service child

## Summary

Fixed a C2-6 overload defect where one pending request's retryable global-page rejection escaped `driver.poll()`, causing `EngineService` to fail the unrelated active 32K survivor and close the model service.

## Changes

- Added optional request identity to `GenerationAdmissionRejected` without changing its public routing JSON.
- Qwen device-KV admission identifies the rejected backend request.
- `SubmitPollTextGenerator.poll()` converts a retryable admission exception into one rejected-child event, atomically aborting only that pending submission.
- `EngineService` publishes that event as the named child's terminal error and continues driving every survivor.
- Preserved `EngineLoopEvent` positional field order by appending the error payload.

## Validation

- EngineService, focused scheduler admission, and Qwen high-water tests — 15 passed.
- Ruff and diff checks — passed.
- The broader server API run passed all affected service/scheduler paths and found only two unrelated stale exact-dictionary expectations for previously added KV capability metadata; per focused-repair policy those unrelated nodes were not modified.
- The preceding hardware pressure attempts both produced the intended retryable 4K `engine_busy` error with five pages free, but closed the service and therefore remain rejected.
