# Open the Q5_1 MMQ leaf to K=704 and fix its 1-plane pack mismatch

## Summary

P10's precondition is the K=704 divisibility problem recorded in `f589bdf8f`.
This unit clears it: the `gguf_q5_1_mmq_selected_prefill` leaf now serves a K
that is not a multiple of 128, pinned RED-then-GREEN by a new test.

**Seven enforcement points had to move together.** Rejecting 704 was not one
gate but a consistent floor division spread across both languages:

| # | Location | Was |
| --- | --- | --- |
| 1 | `ds4_workspace_nbytes` | raised `ValueError` on `% 128`, sized with `// 128` |
| 2 | consumer `.py` wrapper | `in_features must be a positive multiple of 128` |
| 3 | consumer `.hip` `ds4_blocks` | `in_features / Q8_1_MMQ_BLOCK` (floors to 5) |
| 4 | consumer `.hip` host validator | `(in_features % Q8_1_MMQ_BLOCK) != 0` |
| 5 | pack `.py` wrapper | `hidden must be divisible by ... 128` |
| 6 | pack `.hip` validator | `(hidden % Q8_1_MMQ_BLOCK) == 0` |
| 7 | pack `.hip` kernel **and** its launcher grid | `hidden / Q8_1_MMQ_BLOCK` |

All seven now ceil, and the consumer additionally clamps its `for sub` loop:
at `kb = 5` only 2 Q5_1 blocks remain, so an unclamped loop would read 576
bytes against a 528-byte weight row. Trailing activation lanes are zero-filled,
which is exact — a zero lane contributes 0 to `dot4`, to the block sum, and
therefore to the `m` offset. For K divisible by 128 every one of these
expressions is unchanged, so existing shapes take an identical code path.

**A latent bug the gate was hiding.** The down route imported
`gguf_q8_1_mmq_ds4_pack_bf16`, which is exported as
`launch_q8_1_mmq_ds4_pack_bf16<1>` — **one** residual pass, writing only plane
0 — while the consumer it feeds runs with `planes=3` and reads all three. Planes
1 and 2 were read uninitialized. Measured directly: with identical inputs at
K=640 (a shape the old gate accepted), the plain pack produces **2560 NaN**
outputs and a max scaled error of 3.3M, while `..._d4x3`
(`launch_q8_1_mmq_ds4_pack_bf16<3>`) produces **0 NaN** and max error 0.0036.
The mismatch was never noticed because the K gate meant the route never ran.
The route and the test now both use `d4x3`, matching the sibling test that
already paired it with this consumer.

**Dispatch is unchanged, deliberately.** `gemma4_experts` tries
`gemma4_project_experts_wmma` before `gemma4_project_experts_mmq`, and WMMA
succeeds, so a traced 1024-token prefill still reports
`wmma=60, mmq_dual=60, mmq=0`. The leaf is now *reachable*; making it primary
would promote a changed-arithmetic path to the default, which requires the
execution-profile gate in `docs/EXECUTION-PROFILES.md` rather than a dispatch
edit. That promotion, plus P10's actual I=64/J=64 tile, remains ahead.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_q5_1_mmq_selected_prefill.py` —
  added the `Q8_1_MMQ_BLOCK` constant; `ds4_workspace_nbytes` ceils and drops
  its `% 128` rejection; consumer wrapper now requires a multiple of **32**
  (what the Q5_1 weight row actually needs) instead of 128.
- `hipengine/kernels/hip_gfx1100/quant/gguf_q5_1_mmq_selected_prefill.hip` —
  `ds4_blocks` ceils, `q51_blocks` added, `for sub` clamped to the blocks left
  in the weight row, host validator no longer rejects `% 128`.
- `hipengine/kernels/hip_gfx1100/quant/gguf_q4_k_q8_1_selected_prefill.hip` —
  pack kernel ceils `blocks_per_row` and zero-fills lanes past the row end;
  launcher grid ceils; `valid_q8_1_mmq_ds4_pack` drops the modulo.
- `hipengine/kernels/hip_gfx1100/quant/gguf_q4_k_q8_1_selected_prefill.py` —
  both pack wrappers (`bf16` and `bf16_d4x3`) drop the divisibility `ValueError`.
- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py` — down route no
  longer gates on `in_features % _DS4_BLOCK_VALUES`, and imports the `d4x3`
  pack so all three planes are written.
- `tests/test_gpu_gguf_q5_1_mmq_selected_prefill.py` — new
  `test_q5_1_mmq_ds4_serves_in_features_not_divisible_by_128` at K=704.
