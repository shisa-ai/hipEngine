# EVIE review round 2: six fixes

## Summary

Responded to the second external review (worklog 7c156d). All six
high-priority findings plus both additional ones verified against the
code and fixed:

1. **Loader oversizing (confirmed, fixed).** np.empty/np.zeros received
   byte counts as element counts: fp32 weights allocated 4x (70.55 GiB
   vs 17.64), fp16 2x (26.23 vs 10.36). Data placement was element-indexed
   so outputs were always correct — this was silent waste, and it
   explains the earlier dual-model host panic (2x26 GiB) better than the
   GTT-pressure framing. Fixed to element counts + pad/itemsize.
2. **Teardown leaks (confirmed, fixed).** close() now frees the
   attention score/plane caches (_scores_bufs, _plane16_bufs) and calls
   loaded.free() so sequential runners are truly single-model-resident.
3. **Padding masks (confirmed latent bug, fixed).** lm_rope_positions
   returns valid-token-ordered positions but execution ran over the full
   padded ids (misaligned rope, OOB position reads). encode_query/
   encode_document now compress ids by the mask first; returned
   embeddings are valid-token-only. Invisible before because the fixture
   has no padding.
4. **Patch order (confirmed, fixed, verified).** The real
   ColQwen3_5Processor emits patches in 2x2 merge-block order
   (empirically [0,1,16,17, 2,3,18,19,...]); the bench's fold was
   raster. Fixed fold verified bit-exact (5.9e-08) against the processor
   on a block-constant 256x256 image. Bench-only issue: fixtures/tests
   use real processor outputs; timing is shape-based.
5. **Workload protocol (documented).** Cross-engine ratios labeled
   approximate in MODEL-EVIE.md (different queries/pairs/preprocessing
   boundaries); no matched-protocol rerun in this pass.
6. **Certification language (fixed).** fp16 path described as
   fixture-gated T1 evidence, not a registered production-profile
   certification; EVIE manifest + ranking qualification recorded open.

Additional: runner/loader precision mismatch now raises at construction
(EvieLoadedModel carries its precision); scratch cache buckets to
64-token multiples and evicts beyond 4 entries.
