# audit: batched suffix prefill is gated by policy, not missing machinery

## Summary

Audit of the claim in `docs/REFACTOR.md` that "the batched
`prefill_batch_native` route cannot start at a non-zero sequence position."
**The claim is wrong about the mechanism.** Every piece a batched suffix
("extend") prefill needs already exists in the packed AR prefill path:

- Non-zero start positions are plumbed: `_GGUFPackedVerifySlotBlock` carries
  `start_position=int(session.position)`
  (`hipengine/runtime/qwen35_gguf_runner.py:24212`), and
  `_prefill_batch_native_impl` explicitly validates
  `session.position + len(prompt) <= full_prompt_length` — a contract written
  for outer schedulers supplying one logical prompt over multiple calls.
- GDN per-slot state seeding exists: `_sync_packed_decode_initial_state`
  copies each session's Conv/recurrent state into the packed per-slot segments
  (fused pair copy), keyed off the slot's start position.
- Prefix KV import exists: the same helper copies the session's prior-history
  KV into the packed planes through page-aligned segment D2D
  (`_copy_session_packed_kv_segments`, `copy_kv=True` when the slab is not
  slot-local).
- Commit-back exists: `_scatter_packed_decode_state` copies packed GDN state
  back to session scratch, scatters the new suffix KV rows into the session's
  own pages through its block table (handles non-contiguous shared-prefix
  allocations by design — the COW-fork case), and advances position cursors.
- The paged prefill attention kernel consumes row-local spans with
  `paged_max_context_len=layout.max_live_count` and uses owned global score
  scratch past 64 KiB (docs/KERNELS.md), i.e. it is built for long context.

The actual blocker is a single policy gate:
`_validate_packed_ar_prefill_context`
(`hipengine/runtime/qwen35_gguf_runner.py:1967`) raises NotImplementedError
when `max_live_count >= 1024 and not slot_local_full_prefill`. It was
introduced in 84fd737a3 (2026-07-20) when the slot-local AOTriton rebase became
the qualified >=1024 route; the paged route was never *qualified* past 1024 —
the message says "currently requires", not "cannot". Every realistic prefix hit
(total context > 1024, shared prefix => non-contiguous => not slot-local)
trips exactly this gate, which is why the generation layer falls back to the
serial `session.step()` loop (~34 ms/token, ~1,679 dispatches/token) measured
in the cost-attribution entry.

This also unifies the two recorded blockers: the admission-side
`shared_admission_noncontiguous` gate exists only because the >=1024 prefill
route requires a contiguous slot-local KV slab. If the paged packed prefill is
qualified past 1024, hit admissions need no contiguity and the serial suffix
loop has no reason to exist.

## Changes

- Docs only: this audit entry. No code changed.

## Decision

Fix order for the batched suffix unit:

1. RED: live fixture test (Qwen3.5-0.8B-Q4_K_M, 18 GDN + 6 full-attention
   layers) — restore/prefill a session to a 256-aligned boundary and run a
   batched suffix prefill through `prefill_batch_native`; oracle is the serial
   `session.step()` loop over the same suffix from the same state, plus a full
   private prefill control. Today this raises NotImplementedError at total
   context >= 1024.
2. Lift the <1024 paged gate (route policy only; slot-local remains the
   private-miss route) and qualify numerically against the strict oracle.
3. Wire the generation-side reused-suffix branches
   (`_prefill_native_chunk`, `_prefill_processed_argmax_chunk`) to the batched
   route behind an env flag with the serial loop as the registered fallback.
4. Drop `require_contiguous` for shared-prefix admissions once the hit route
   no longer needs the slot-local slab.
