# Muse Glimmer decode-attention restructure investigated: LDS redundant-read fix neutral; kernel is L2/compute-bound not DRAM-bound

## Summary

Investigated the long-context decode-attention lever (campaign §10: "~2.5x its
bandwidth floor at 32K"). Tried the obvious fix — cooperative LDS K/V tiling so
a block's 4 waves (4 Q heads sharing one KV head) load each K/V row once
instead of 4x — and measured it NEUTRAL/slightly worse, then reverted it.
Counter-free kernel-trace diagnosis shows why: the redundant reads hit L2, not
DRAM, so the kernel is L2/compute/latency-bound, not DRAM-bandwidth-bound.

## Changes

- No production change landed. The LDS-tiling variant of
  muse_glimmer_decode_attn_split_kernel was implemented, unit-tested
  (CPU-reference floor passed), measured, and reverted (working tree clean).

## Validation

- rocprofv3 --kernel-trace at 32K ctx (Radeon 8060S/gfx1151, 16 decode steps):
  decode step ~90 ms; GEMVs ~87% (weight-bandwidth-bound, ~17 GB weights/token
  at ~220 GB/s ≈ 78 ms); decode_attn_split ~7.7 ms/step (≈8.6%), combine
  ~1.3 ms. Geometry: 52 layers (13 NoPE full + 39 SWA window-2048), 32 Q / 2 KV
  heads, dim 128. K/V read 518 MB/step at 32K → DRAM floor 2.35 ms; measured
  split 7.7 ms = 3.3x floor. At 128K: 1827 MB/step → floor 8.30 ms.
- LDS variant: split 127.5 ms vs 123.1 ms baseline over the same window
  (slightly worse); 32K decode 90.0 vs 89.8 ms/step (neutral). Removing the 4x
  redundant global reads did not cut DRAM traffic because L2 already serves
  them; the __syncthreads + LDS bank-conflict overhead offset the L2 savings.
- The --pmc counter pass invalidated the JIT cache and spawned clang under the
  profiler (OPTIMIZATION.md §7 forbids this), so it was abandoned; the
  kernel-trace + bandwidth-floor arithmetic already classify the bottleneck.

## Next

- The attention is compute/latency-bound (serial per-key wave reductions +
  online softmax), not DRAM-bound. The remaining lever is a lane-per-key
  restructure (parallelize keys across lanes to drop the per-key wave_sum), a
  larger rewrite with bounded payoff: attention is ~9% of the 32K step (~28%
  at 128K), so the ceiling is ~10% at 32K / ~26% at 128K. Related split-count
  and Q-heads-per-block sweeps already showed no gain (campaign §10). Recommend
  lead decide whether to fund that campaign; the larger decode lever is
  weight-byte compaction (T16 scale/min +2.78%), since decode is weight-bound.
