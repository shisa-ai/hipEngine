# Topline MTP cell is single-request; use the C1 value

## Summary

The previous unit
(`worklog/entries/20260912T112735.384625Z-lhl-w7900-qwen36-27b-mtp-topline-provenance-14179c.md`,
commit `92ad83308`) replaced a stale W7900 Qwen3.6-27B `With MTP` cell with
34.341 tok/s. That value is the current automatic default, but it is measured at
**resident capacity 2** with K2/D24, while the topline `With MTP` column is
**single-request**. The cell now carries **60.929 tok/s**, the C1
exact/default natural25 B3 figure.

## Decision

The topline `With MTP` column is C1. Every other populated cell in it is a
single-request measurement, so a two-request row does not belong there:

| Populated cell | Scoreboard contract | Requests |
| --- | --- | --- |
| W7900 PARO W4 = 115.8 | Production/default `B1` fast, raw D24 | 1 |
| W7900 Qwen3.6-35B-A3B = 122.7 | `llama-compat` MTP-2 natural suite | 1 |
| gfx1151 Qwen3.8 `Q4_K_S` = 23.9 | Exact native B3 spec-decode | 1 |
| gfx1151 Qwen3.8 `Q4_K_M` = 15.6 | normal-cap4 realized-C1 B3, automatic | 1 |

The C1 row for this model is the exact/default natural25 B3 entry: true AR
29.457 -> MTP 60.929 tok/s (2.0684x). The resident-C2 K2 D24 row (30.736 ->
34.341, 1.1173x) stays in the speculative scoreboard unchanged as the
two-request number.
