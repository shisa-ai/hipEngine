# Reuse SPECDEC2 provider groups across refill

## Summary

Repair a current strict and production refill regression exposed by P8 lifecycle
validation. A K0 newcomer was opened in a singleton provider group before its
joint cycle with an existing survivor, so proposal saw two group identities and
fell back to AR. Reuse any live provider group with capacity before opening a
new group.

## Changes

- `_ensure_request_states()` now attaches missing requests to a live compatible
  group even when none of the input IDs already owns state.
- New group creation remains the fallback when no group has capacity.
- Added a fake provider-group RED/GREEN contract.

## Validation

- RED strict and production compaction packets both failed after the same move
  `request 1: slot1→slot0`; request 2 recovered through
  `RuntimeError: physical NextN proposal requires one provider group`.
- Diagnostic identity was `(1→group(0,1), 2→group(2))`.
- GREEN strict and production packets both pass: the same compaction move occurs,
  request 2 executes staged SPECDEC2 with no failure reason, substitution output
  is exact, survivor cancellation drains, and final active ownership is zero.
- Focused K0/refill seam tests pass; compile/diff checks pass.
