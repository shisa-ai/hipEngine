# Schedule independent Inkling GGUF request sessions

## Summary

Ordinary Inkling GGUF serving now advances independent requests through the existing resident driver. A long prefill no longer blocks the whole driver until its first token. Each request still owns separate KV and convolution state. Decode rows use the existing packed HIP path, one row at a time; this is not a packed multi-row kernel change.

## Changes

- Bind an Inkling request owner to the existing scheduler. Give it model-width prefill blocks and a bounded default round budget. If an operator changes the scheduler chunk size, accumulate scheduled tokens before running the original model block width so the change cannot alter prefill arithmetic. Keep deadlines, cancellation, refill, and streamed stop filtering in the scheduler's existing lifecycle.
- Preserve the direct row path as the reference for request semantics. Reclaim by request ID, not by physical slot index. Keep the shared sampler, configured EOS, stop sequences, seeded sampling, and zero-output finish metadata.
