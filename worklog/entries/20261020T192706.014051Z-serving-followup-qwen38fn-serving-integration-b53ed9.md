# Ship Flash-Next prefill time sharing; keep shared MTP target opt-in

## Summary

This commits the serving integration that had stayed uncommitted since
2026-10-19. Completed-layer prefill time sharing is on by default and
measurably cuts decode tail latency under concurrent prefill. The shared
MTP/AR target pass works through `hipengine serve`, but it is slower than
separate execution at every measured width. Explicit MTP therefore keeps
separate execution by default, and `HIPENGINE_QWEN4_EXP_SHARED_MTP_TARGET=1`
selects the shared pass. The production profile's numerical drift is
pre-existing and is recorded here as outside this campaign.

## Changes

- Scheduler and engine loop: a decode-active prefill token bound
  (`decode_prefill_token_budget`; Flash-Next selects 1024) and resumable prefill
  that returns at a completed-layer boundary while decode is due. A deferred
  segment rewinds the prompt cursor and does not publish completion. Prefill
  slices appear in `/v1/hipengine/decode`.
- Peer capability split: when a due group mixes a capable speculative row with
  an incapable peer, each partition plans separately instead of dropping the
  capable row to K0.
- `hipengine/generation/qwen4_exp_serving_mixed.py`: scheduler-owned proposal,
  shared target pass, accepted-prefix commit, and containment for explicit MTP
  rows that live in the batch. It is reached only when
  `_shared_mtp_target_enabled()` is true.
- `HIPENGINE_QWEN4_EXP_SHARED_MTP_TARGET` (default `0`), with an ENVS row and a
  `docs/REFACTOR.md` entry naming the cause and the clearing command.
- New test: by default, explicit MTP keeps its c1 runner on a mixed-capable
  owner. Existing shared-pass tests set the variable.
