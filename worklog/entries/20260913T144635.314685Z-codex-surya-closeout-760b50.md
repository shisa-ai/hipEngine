# Close Surya review gaps and qualify final runtime

## Summary

Close the four findings in 22efe05d4: remove Surya request-time device drains,
make the poison helper reject incomplete coverage and snapshot outputs, make
allocator reuse diagnostic, and package Pillow with a fail-on-skip acceptance
gate. Full acceptance exposed an additional CPU-reference dtype defect; fix
that without changing any oracle tolerance or fixture.

## Changes

- SuryaGpuRunner._upload retains a contiguous local through synchronous H2D and
  no longer calls device_synchronize. The helper is used during token decode,
  mRoPE/span uploads, prefill, vision, and loading. No kernel body or arithmetic
  on the GPU was changed. Added a strided-source and no-drain regression.
- Poison probes snapshot reference arrays (including localization), collect
  after warmup, and reject empty groups or exhausted visit/depth limits. Real
  TimesFM probes then exposed traversal into _loaded.index metadata; skip the
  loaded model explicitly, as intended for non-scratch state. Tests cover the
  failure modes and verify offender localization with reused output arrays.
- The allocator reuse experiment skips if the allocator does not reuse the
  address. The deterministic weakref lifetime assertion stays mandatory.
- The surya optional extra declares pillow>=10. scripts/surya_acceptance.py
  discovers all test_surya*.py files and fails on test/module skips; plugin tests
  prove pass, failure, test skip, and collection skip behavior. The extra installs
  Pillow 12.3.0 in the source-checkout environment; package metadata confirms the
  requirement is attached to the surya extra.
- The original full gate failed in CPU rectangular-page vision (3/236544 tower
  values beyond the original bound). Position interpolation returned float64,
  and np.sqrt scalar constants promoted GELU; this happened on both NumPy 2.4.4
  and 2.5.2, although only 2.5.2 crossed the measured tolerance on this host.
  Return fp32 position embeddings and use Python math constants in GELU to keep
  fp32 activations. Three new dtype regressions fail before the fix. Existing
  tensor, logit, greedy-ID, and numerical thresholds remain unchanged.
- Update MODEL-SURYA installation/acceptance instructions and KERNELS ownership
  documentation, including the distinction between mutable TimesFM 2.5 state
  and the initialized TimesFM 3 zero-offset constant.
