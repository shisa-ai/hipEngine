# Cross-process Gemma 4 KV save and restore

## Summary

Deep-decode iteration no longer pays the prefill. `Gemma4Runner` gains
`save_kv_state` / `restore_kv_state`: the live BF16 key/value planes of every
layer are serialized up to the current position -- exactly the bytes a
continuation's attention reads -- under a JSON header that carries the
position, the per-layer plane sizes and the caller's identity mapping, with
the prefill's last-row logits stored alongside so a restored caller can sample
its first token without recomputing it. Restore validates the schema, the
capacity, the plane sizes and the identity and refuses a mismatch before any
byte lands; the INT8 KV route is refused with a named capability miss.

The exactness contract is asserted, not assumed: a restored runner holds the
same cache bytes and position, so restored decode must reproduce fresh decode
bit for bit. `tests/test_gpu_gemma4_kv_restore.py` proves it on two runners
sharing weights (2 passed): identical greedy IDs including the first token,
byte-identical saved logits, and identity/capacity mismatches refused with the
runner's state untouched. The harness `scripts/gemma4_kv_restore_bench.py`
proves the same at scale in verify mode: at 2048 (save/restore 0.04s each) and
at 65536 -- prefill 292.53s, save 4.57s for a 13.8 GiB state, restore 0.89s,
decode 8.13s in both arms, `exact_ids_equal=True` over 128 greedy tokens.

Iteration economics: a 65536 decode run now costs model-load plus restore
(~30s total) instead of a 293s prefill; at 262015 the state will replace the
76-minute prefill with a few seconds of load, which is what makes the 0.76x
deep-decode gap attackable at minutes per iteration.

## Changes

- `hipengine/runtime/gemma4.py`: `Gemma4Runner.save_kv_state` and
  `restore_kv_state` (new `KV_STATE_SCHEMA` / chunk constants; `ctypes`, `json`,
  `Path` imports). Restore resets the exposed state first, lands the bytes,
  then sets the position and per-layer write offsets exactly as `rewind` does.
- `tests/test_gpu_gemma4_kv_restore.py`: new; cross-runner bitwise parity,
  identity refusal, anonymous-file refusal, capacity refusal.
- `scripts/gemma4_kv_restore_bench.py`: new; save / restore / verify modes,
  campaign-corpus prompt ids and campaign identity hashes so a state pairs
  with the ladder's rows.
