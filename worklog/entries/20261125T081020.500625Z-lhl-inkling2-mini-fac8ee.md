# Read shared route inputs without per-route copies in the Inkling decode chain

## Summary

First unit of the decode fusion work (task 10). The device-routed expert chain copied the normalized
row once per route before the gate/up projection, eight device copies per visit. The selected NVFP4
projection now takes `routes_per_input`, so every route reads the token's resident row; banks
without that variant (the Q5_K gate/up and Q8_0 down experts of layers 20 to 23) write the row once
per route in one launch.

## Why this first

A rocprofv3 kernel trace of the decode graph arm on the tree of `ec2fa6d32` (47 prompt tokens, 29
steady steps) puts a token at 32.81 ms: 22.57 ms of kernels and 10.24 ms of gaps between them.
Every gap is under 5 us, 2,657 of them at 3.8 us each, so each node of the token costs 3.8 us
besides its own execution. Device copies were the third largest family:

| Family | Launches per token | Execution | Gaps | Sum |
| --- | ---: | ---: | ---: | ---: |
| NVFP4 experts, selected F32 GEMV | 88 | 5.61 ms | 0.33 ms | 5.94 ms |
| rocBLAS GEMV (router, loop controllers, BF16 projections) | 400 | 4.65 ms | 1.52 ms | 6.17 ms |
| device copies | 635 | 1.02 ms | 2.53 ms | 3.55 ms |
| Q8_0 dense projections | 288 | 3.38 ms | 1.08 ms | 4.46 ms |
| Q5_K and Q8_0 experts of layers 20 to 23 | 8 | 1.29 ms | 0.03 ms | 1.32 ms |
| residual read, row RMS, row add | 327 | 1.89 ms | 1.22 ms | 3.11 ms |
| attention preparation (clip, RMS) | 192 | 0.99 ms | 0.71 ms | 1.70 ms |
| Q8_0 head | 1 | 0.73 ms | 0.00 ms | 0.73 ms |
| decode attention (scores, values) | 96 | 0.89 ms | 0.36 ms | 1.25 ms |
| short convolutions | 192 | 0.56 ms | 0.71 ms | 1.27 ms |
| loop controller input and blend | 96 | 0.54 ms | 0.37 ms | 0.91 ms |

One steady step of the graph arm, read from the trace. The listed families are 2,323 of its
2,669 launches and 30.4 of its 32.9 ms; the rest is the router top-k and route records, the input
norms, the expert split and mix, the cache writes and the tick.

Of the 635 copies, 384 were the per-route replication (48 visits times 8). At 1,717 prompt tokens
the same step is 43.85 ms with `decode_values` at 6.48 ms and `decode_table_scores` at 1.34 ms; the
rest is unchanged.

## Changes

- `gguf_nvfp4_gemv.hip`: `gguf_nvfp4_selected_shared_f32_kernel`, the selected kernel's loop with
  `input = x + (batch / routes_per_input) * in_features`. Entry points
  `hipengine_gguf_nvfp4_selected_shared_f32_f32_out` and `..._shared_register_fp4_f32_f32_out`,
  registered as `moe_linear/gguf_nvfp4/selected_shared{,_register_fp4}_f32_f32_out` on both HIP
  backends (the gfx1151 alias refresh skips them like the other NVFP4 launchers).
- `inkling2_experts.hip`: `inkling2_replicate_row`, registered as
  `inkling2_expert_pointwise/inkling2_mixed/replicate_row`.
- `Inkling2GGUFDeviceProjections.project_experts_device_routes`: the shared projection for a bank
  that has one, otherwise one replication launch; the per-route copies remain only when neither is
  registered.

Arithmetic is unchanged: a wave still handles one (route, output) with the same loads, the same
`fmaf` chain and the same wave reduction.

## Validation

- `tests/test_gpu_inkling2_shared_selected.py` (5 passed on the W7900): the shared projection over
  two rows with eight routes equals the selected projection over replicated rows bit for bit for
  both FP4 decoders and for the gate/up and down shapes; both match a NumPy decode of the packed
  rows; null scales and a `routes_per_input` that does not divide the routes behave as specified;
  the replicated rows equal the source row.
- `tests/test_unit_inkling2_device_routes.py` (7 passed): the route chain calls the shared
  projection with the resident row, replicates in one launch without it, and copies per route only
  when nothing is registered.
- `test_unit_gfx1151_registry_baseline.py`, `test_unit_gfx1151_backend.py`,
  `test_integration_check_lineage.py`: 71 passed with the device-route tests.
- The public route ran the new path in the bench above (resolved profile `fast`, no fallback, the
  same 128 output tokens at every depth).
