# Approve gfx1151 SPECDEC2 performance campaign

## Summary

The user approved a separate `SPECDEC2-PERF` campaign and assigned all
performance retention to the stable physical `gfx1151` agent. This is not a
rewrite and does not reopen S1-S6 correctness. It preserves Generation-2 target
frontier/provider/transaction/output ownership, automatic K0, and strict
fallbacks while optimizing prompt activation and the bounded hot cycle.

The frozen diagnosis is that physical batching is real but absolute speculative
cost loses to AR. Short K2 scales 6.876→9.500→16.053 tok/s from C1→C2→C4 while
AR scales 7.025→11.574→21.585. R16 target is 1.702x faster than two R8 sweeps,
but C2/K2 still attributes 392.8 ms target, 32.3 ms proposal, 7.2 ms provider
repair, about 1 ms accept/commit/readback, and 1053.5 ms complete warm request.
Automatic promotion requires approximately 25.5%/32.8% short C2/C4 and
57.1%/60.7% full-suite C2/C4 total-wall reduction.

The first implementation candidate is the already-retained exact OI-3 streaming
NextN prompt sink. SPECDEC2 currently bypasses it and performs prompt-sized host
hidden capture plus post-prefill per-token replay. Stable slabs/zero hot
allocation follow, then device-resident proposal→target→accept→selected commit.
Only after those phases does a complete R6/R8/R12/R16 profile admit one target
kernel/graph candidate. Provider repair is conditional, FP16-state qualification
uses the faster production AR denominator, and policy/wider concurrency follow
only after a fixed cell wins.
