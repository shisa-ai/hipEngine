# Add pair-only source-F16 admission

## Summary

Added a generic ordered pair-only source-F16 policy. It admits an otherwise
exact second projection only when an already-qualified first projection owns the
same activation. Qwen3.6-27B uses it for the 24 mixed Q6-QKV/Q4-gate layers at
rows 512-2047; standalone Q4 gates and the 24 Q4/Q4 unequal pairs remain exact.

## Changes

- Added normalized ordered keys `(first_quant, K, first_N, second_quant,
  second_N)` with non-overlapping inclusive row intervals mapping to the second
  operand's tile, registered variant, and in-place behavior.
- Extended the existing pair resolver/launcher to synthesize only the second
  source-F16 dispatch, reuse the first operand's activation cast, and fail closed
  on interval, order, quant, shape, registry, or in-place mismatch.
- Added the model package entry for Q6T16 K5,120/N10,240 followed by Q4T16
  N6,144: tile2048 at M512-M1023 and tile512 at M1024-M2047.
- Excluded pair-only metadata from scratch-plane sizing. The first operand's
  existing admitted planes already bound all three current scratch dimensions;
  no allocation, kernel, role branch, sidecar, or environment selector was
  added.

## Validation

- RED first failed at package capability, session constructor, and policy bridge.
- GREEN proves Q6-first plus pair-produced-Q4-second ownership with exactly one
  activation cast; standalone Q4 has no tile policy, M2048 returns `False`, and
  missing pair registry returns `False`.
- Package normalization is Qwen3.6/model/backend scoped; gfx1151 has no entry.
  Scratch liveness and capacity remain unchanged.
- Affected kernel/registry/dispatch/scratch/runner bundle passes **119 passed,
  9 skipped**. Ruff, diff hygiene, lineage census, and worklog schema pass.
