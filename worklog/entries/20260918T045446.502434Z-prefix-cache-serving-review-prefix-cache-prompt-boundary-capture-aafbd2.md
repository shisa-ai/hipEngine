# Capture only the prompt-aligned prefix boundary during chunked prefill

## Summary

Chunked greedy prefill refreshed the radix prefix cache after every prefill
chunk, and `_refresh_prefix_cache` captures a state snapshot whenever the
session position is 256-aligned. With 256-token prefill chunks every chunk
boundary is aligned, so one request captured one snapshot per chunk. Each
capture allocates 2 device buffers per linear-attention layer, issues one
device-to-device copy per buffer, and calls `device_synchronize()`, so a
32-chunk prompt paid 32 device synchronizations and roughly 2.1 GB of redundant
state copy traffic.

Only the deepest 256-token boundary at or before the prompt end can be reached
by a following turn: a client that resends the whole transcript and a client
that rebuilds the transcript from its own normalized assistant text both start
with the previous prompt verbatim. Shallow boundaries are superseded by that
boundary, and snapshots captured during prefill for a request are already
evicted by the next capture of the same request, so the extra captures bought
no additional reuse.

This change captures exactly one boundary per request. The reuse point is
unchanged: the retained snapshot is still the deepest prompt-aligned boundary.
The per-chunk refresh is replaced by `_refresh_prefix_cache_at_prompt_boundary`,
which captures only when the session position equals
`floor(len(prompt_ids) / 256) * 256`. Live-source matching is unaffected because
`_prefix_source_for` already requires an active source to sit exactly at the
matched token count, and rows refresh their own cache entry at admission.

## Changes

- `hipengine/generation/qwen35_gguf.py`: add `_prefix_prompt_boundary` and
  `_refresh_prefix_cache_at_prompt_boundary`; use them in the incremental greedy
  prefill chunk path and in the reused-suffix prefill path instead of the
  unconditional `_refresh_prefix_cache` call. Add `snapshot_captures` and
  `snapshot_capture_bytes` to the prefix-cache observability payload so capture
  cost is visible in serving diagnostics.
- `tests/test_unit_gguf_prefix_cache_runner.py`: add
  `test_incremental_prefill_captures_only_the_prompt_aligned_boundary`, which
  asserts `session.snapshot_capture_calls == [512]` for a two-chunk 512-token
  prompt (RED before the change: `[256, 512]`), that the retained snapshot is
  keyed by the whole prompt, and that a following request still reuses 512
  tokens from it. Generalize the fake session's `clone_prefix_state_from`
  block-id expectation from a hardcoded single page to
  `block_ids[: position // 256]` so multi-page reuse is representable.
