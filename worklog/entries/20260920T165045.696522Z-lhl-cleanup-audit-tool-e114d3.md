# Add the cleanup audit: mechanical debt inventory, durable triage, budget gate

## Summary

hipEngine started as a kernel-optimization project and kept that project's
working style after outgrowing it. The result is that cleanup debt was recorded
rather than worked: `docs/REFACTOR.md` holds 396 `##` entries with no ids and
exactly one marked resolved, `worklog/entries/` holds 3,333 entries including 68
blocked and 19 handoff, 747 distinct `HIPENGINE_*` flags are read across the
tree, and `scripts/` already contains 151 one-off `*audit*`/`*inventory*`
scripts written per campaign and never consolidated.

The debt was never undiscovered. It was unqueryable, so nothing could be worked
through and new debt landed faster than old debt retired.

Modelled on `~/code-audit/` (read-only reference), which the lead uses for shisa
production code. Its spine transfers: dated immutable runs, a generated report
separate from hand-written judgement, computed tables that cannot drift from
their rows, and a gate. What does not transfer is its findings-first premise —
that a human reads unfamiliar code and writes down what is wrong. hipEngine's
debt is already written down, so this tool is **inventory-first**: extractors
enumerate candidates, and triage is a decision on a row.

Lead decisions: in-repo `audit/`; written fresh borrowing the structure rather
than forking `caudit`; all four extractors in the first pass. Lead constraints:
everything must stay inventoried automatically even when agents are lazy, and
extractor conclusions are often wrong, so agents must be able to read, triage,
and eventually resolve every row within a structure that survives re-runs.

## Changes

- `audit/hipaudit/core.py` — `Row` (evidence, never a verdict), `Triage`, the
  durable JSONL store, and `reconcile`. 13 tags (`DEAD-FLAG`, `LOST-OPT`,
  `ORPHAN-KERNEL`, `STALE-LEDGER`, `GATE-CATCH22`, … plus `NOT-DEBT` for when
  the extractor was wrong) and 6 dispositions (`promote`, `remove`, `qualify`,
  `keep`, `document`, `defer`) — cleanup verbs, not bug-tracker verbs, because
  most debt here resolves by turning something on or deleting it.
- Four extractors under `audit/hipaudit/inventory/`, producing 1,623 rows in
  ~22 s: `ledger` 396, `flags` 747, `kernels` 255, `candidates` 225.
- `audit/audit.py` — `inventory`, `status`, `open`, `show`, `triage`, `check`,
  `report`, `budget`.
- `audit/budget.json` — untriaged ceiling per kind, enforced by `check`. This is
  the anti-laziness mechanism: new debt cannot land without being triaged, and
  cleanup shows up as the number going down.
- `.claude/agents/cleanup-triage.md` — a dedicated triage agent whose rules are
  "never record a decision you did not verify", "`NOT-DEBT` is a first-class
  outcome", "the note carries the evidence", and "do not raise the budget".
- `audit/README.md`, `audit/tests/`, first dated run under `audit/runs/`, and
  `AGENTS.md` ground rule + Key Files row + verification-tier row.

## Durability contract

The property that makes this usable rather than a one-off report: every row has
a content-stable id, triage lives in files re-extraction never touches, and each
decision stores a hash of the evidence it was made against. Re-running never
destroys triage; but when evidence moves, the row returns as `stale` rather than
letting a conclusion stand on facts that no longer hold. That is what lets a
wrong early call be corrected instead of calcifying — the lead's stated concern.

## First findings

The extractors produced real signal before any triage:

- **4 flags carry conflicting defaults across runtime modules** — the same name
  read default-on in one module and default-off in another:
  `HIPENGINE_QWEN35_NATIVE_SAMPLER`, `HIPENGINE_W4_MULTI_ROW_PACK8`,
  `HIPENGINE_W4_OUTPUT_TILED_PREFILL`,
  `HIPENGINE_W4_DUAL_OUTPUT_TILED_SPLIT_PREFILL`. Only the first was known. This
  signal was added specifically because the extractor initially missed the known
  case, which is the right way to grow an extractor.
- **41 ledger entries name paths that no longer exist.**
- **30 campaign candidates were not promoted while citing an exactness bar** —
  the rejection reason `docs/OPTIMIZATION.md` §4.1 explicitly says cannot stand
  alone.
- **22 kernel sources have no caller outside `hipengine/kernels/`.**

Two demonstration triages recorded: `HIPENGINE_QWEN35_NATIVE_SAMPLER` as
`GATE-CATCH22`/`qualify`/high, and `HIPENGINE_LITERAL` as `NOT-DEBT`/`keep` — a
genuine extractor false positive, it is a placeholder inside
`scripts/check_envs_docs.py:53`'s own scanning regex.
