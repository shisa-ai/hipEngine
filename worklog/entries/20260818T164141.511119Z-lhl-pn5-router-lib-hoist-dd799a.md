# PN5: hoist router library cache — exact +957 us/tok host-dispatch win

## Summary

Measured the MoE router slice of Qwen3.6-35B-A3B GGUF eager decode on the ZBook
(gfx1151) and found it **host-dispatch-bound, not GPU-bound**: 40 cooperative
router launches/step, each ~45-49 us of host time. Root cause: every router
launch called `build_qwen35_router(load=True)`; with the session's pinned
compiler version that key misses the loaded-library cache (the launch path
passes `compiler_version=None`), re-running the full build/load machinery
(~34 us/call). GPU kernel durations are negligible (per rocprof and raw-launch
timing).

Fix: hoist the router `.so` handle into a module-level `_router_library()`
cache in `hipengine/kernels/hip_gfx1100/moe/router.py` and use it in all 19
router launch wrappers (`library = library or _router_library()`). The launch
path becomes a plain ctypes call (~14.6 us).

Counter-rotated exact A/B (`scripts/pn5_router_lib_ab_probe.py`), sync'd eager,
30 steps, warmup 6, token 9707, prefill 512:

- old (per-call build) #1: 30.86 ms/tok
- new (cached library):     29.83 ms/tok
- old (per-call build) #2: 30.70 ms/tok
- **tokens byte-identical** across all three runs (exactness preserved)
- mean old 30.78 -> new 29.83 = **+957 us/tok (+3.2%)**

The whole router slice measured ~1.73 ms/step by no-op A/B; the host-time
reduction (~0.96 ms) is most of it — the remainder is overlapped with GPU work.

## Evidence trail

- `scripts/pn5_router_slice_probe.py`: coop active (40/step), zero fallback
  chain calls; no-op router slice saves 1732 us/tok (31.03 -> 29.29 ms/tok).
- `scripts/pn5_router_host_dispatch_probe.py`: 40 coop calls = 1.88 ms/step
  host time, per-call median 45.1 us.
- `scripts/pn5_router_raw_launch_probe.py`: raw coop launch 49.0 us default vs
  14.6 us with preloaded library -> build_hip per call costs ~34 us.
- `scripts/pn5_router_rocprof_child.py`: rocprofv3 kernel trace confirmed the
  coop kernel `qwen35_router_topk_split_shared_coop_out_f32w_kernel<...,true>`
  (persistent counter) as the decode router; per-step granularity too coarse for
  its duration (host-side cost dominates).

## Changes

- `hipengine/kernels/hip_gfx1100/moe/router.py`: add `_router_library()`
  module cache; replace 19 per-call `build_qwen35_router(load=True)` sites.
  Pure host-side change; kernel code and math untouched.
- `docs/KERNELS.md`: router catalog note for the hoisted library.

## Validation

- Router tests: `test_gfx1151_backend.py` + `test_laguna_router_gpu.py` +
  `test_execution_profile_gguf_c1_route_gate.py` all pass.
- Exactness through the runner: `test_qwen35_gguf_hidden_seed_contract.py` +
  `test_llm_generate.py` pass.
- Exact A/B tokens identical old/new/old; counter-rotated wall +957 us/tok.

## Next

sites across the hot GEMV/prefill kernels. PN4 established launch_gguf_linear is
mostly GPU-bound (host A/B ~857 us headroom), so those likely do NOT pay the
same 34 us/call cache-miss cost, but a targeted audit (session-pinned compiler
version vs per-call None on the largest families) is a cheap follow-up. Do not
expand this unit beyond the router slice.
