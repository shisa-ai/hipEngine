# 24 GB context recovery: INT8 prefill lifetimes, width-scoped sidecar, host token table

## Summary

Follow-up to `20261020T141307.986932Z-lhl-xtx-24gb-serving-memory-ff5b02.md` and the
v0.8.1 DMS units. Live-owner tracing of `hipengine serve` (Qwen3.8-27B `Q4_K_M`,
malloc/free owners snapshotted at each new device-free low) found four non-KV
owners that dominated the 24 GB budget:

1. INT8 + MTP + prefix cache prefilled every prompt chunk-outer through
   `_prefill_int8_boundary_split`, because the one-shot layer-outer route refused
   streamed MTP sinks. Chunk-outer keeps one full-length BF16 oracle pair per INT8
   attention layer: 1.08 GiB at 17,664 positions, the bytes per token of BF16 KV.
   This is why INT8+MTP sized below BF16+MTP.
2. Resumable layer-outer checkpoints copied both hidden planes although only the
   boundary-phase plane is live (and the INT8 route aliases both names to one
   buffer), and single-slot servers copied them although nothing can interleave.
   Default chat traffic (prefix cache on) never suspends, but sizing charged two
   full-length planes for it.
3. The raw recurrent-output Q5 sidecar (48 tensors, 989 MiB) is read only by the
   eight-request MTP verify owner; an unpinned server never exceeds four requests.
4. The shared runner kept the Q4_K token table (682 MiB) on the device although
   gfx1100 declares mapped-host support for it.

Commits: `52d8461cf` (1, 2 and their pricing), `0c2d3f4f5` (3), `d091610ec` (4),
plus `eb7804ae9` (INT8 servers were told to use INT8) and `62961b951` (DMS banner
printed "Context unknown tokens").

## Changes

- Layer-outer executor accepts streamed MTP sinks on the one-shot route and can
  leave them open for a boundary-split tail. MTP INT8 sizing now prices the
  layer-outer transient and checkpoints instead of per-layer oracles.
- Checkpoints save the live plane only; capacity-1 servers suspend in place and
  refuse a resume whose planes were replaced.
- `LLM` declares its pinned `max_active_requests` before weights load; the
  generator drops the C8 Q5 sidecar below eight. Dispatch already keeps the exact
  T16 route without the raw allocation.
- Shared runner token-table placement `auto`: mapped from host when the backend
  declares the table type; `HIPENGINE_GGUF_HOST_TOKEN_EMBEDDING=0` keeps it on
  device. `docs/ENVS.md` updated for both behaviors.

## Rejected or deferred

- Direct INT8 prefill: the recorded numerics rejection stands (`docs/REFACTOR.md`
  2026-09-09: row-KL 0.215, top-1 0.71, 72% of oracle-route speed).
- Aliasing the packed verify scratch onto the bulk prefill scratch (about
  0.8 GiB): single-slab prefill uses both within one layer; the shared arena
  produced token 2147483647 on BF16+MTP 27,163 and INT8+MTP 16,983-token prompts.
  Reuse would need a per-field liveness audit across both owners.
- NextN hot-vocab head (0.513 GiB): `HIPENGINE_GGUF_MTP_HOT_VOCAB=0` measured
  52.37/52.03 vs 53.66/52.94 tok/s c=1 decode on W7900 (about -2%). Left on;
  a product call.
- MTP verify per-row linear state (0.562 GiB, four rows of FP32 recurrent state):
  at most one row (0.14 GiB) looks removable; not pursued.
- DMS sizing prices full retention (`per_head = n`): a tiny prompt may ask for
  nearly the whole context as output, and the per-request store is
  `retained(prompt) + max_tokens`. The 156,672 automatic context left 2.87 GiB
  free at 151,823 inputs. Tighter sizing needs an admission rule that bounds
  `max_tokens` against the store budget, which is an API decision.
