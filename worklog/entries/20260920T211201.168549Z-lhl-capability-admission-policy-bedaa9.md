# Capability is the only admission gate

## Summary

Lead decision: a capability gate may only express "the kernels cannot execute
this" or "this configuration is recorded bad". Everything else runs. The
prohibition is now stated positively in `AGENTS.md` instead of being implied by
three separate prohibitions about flags, defaults, and benchmark rows.

The review that prompted this found the licence was not in `AGENTS.md` at all —
it was in the documents `AGENTS.md` points at. `docs/EXECUTION-PROFILES.md`
§2.9 specified the speculative-MTP resolver as matching a retained evidence row
whose first admission axis was artifact SHA-256 and size, which is a per-file
allowlist by construction: a GGUF nobody had benchmarked could never match,
whatever the kernels supported. `docs/MODELS.md` read as an admission matrix
("Support is specific to the combinations listed here"). An agent implementing
those documents faithfully produces exactly the refuse-by-default behavior the
lead had to correct four times in one session.

## Changes

- `AGENTS.md`: three new Product Defaults — **Capability is the only gate**
  (closed list of legal refusal reasons), **Never key admission on identity**
  (no model name, path, SHA-256, revision, or known-good combination list), and
  **An explicit request runs or fails loudly** (no silent downgrade, no
  `unqualified` label, no diagnostic-env-var route). Added "which models,
  artifacts, or configurations may load" to what evidence does not govern, and
  three rows to Handling Blockers.
- `docs/EXECUTION-PROFILES.md`: narrowed `owns:` from "registry resolution
  policy" to "kernel-variant selection policy" and added an explicit scope
  paragraph stating the document does not govern product admission. §1.1 now
  bans expressing a restriction as an identity. §2.1's registered-combination
  list is marked explicitly not an admission list. §2.7's "runtime admission
  requires model metadata containing `Qwen3.8`" was stale doc drift — the
  kernel tables key on geometry plus file type, so it now reads as variant
  selection with a named fallback rather than a refusal.
- `docs/EXECUTION-PROFILES.md` §2.9 rewritten as "Capability admits; evidence
  selects and promotes", superseding the in-flight two-stage text that kept
  evidence rows as the automatic-intent admission mechanism. Capability now
  admits in every mode; evidence selects among admitted paths and governs
  claims. Exactly one further restriction is legal, a recorded observed failure
  or measured regression, and it names its artifact and its clearing
  measurement. Artifact execution identity is retained as provenance only, and
  the unrecorded-identity-withholds-the-path rule is gone. The screening env var
  is documented as retired, with removal already tracked in `docs/REFACTOR.md`.
- `docs/MODELS.md`: reframed as a coverage record, not an admission list, with
  an explicit statement that a model absent from the page still loads if its
  architecture, geometry, and quantization fit a registered kernel.
- Anchor retarget for the §2.9 retitle across `docs/API.md` and two closed
  campaign documents; `docs/README.md` index regenerated.
