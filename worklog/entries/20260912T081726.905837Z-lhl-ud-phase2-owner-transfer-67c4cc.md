# Classify every dense prefill owner for verifier transfer

## Summary

Phase 2 of `docs/UD-GFX1151-OPTIMIZE.md`. Every important dense prefill owner is
now classified, and the rows 2-4 IQ sibling headroom is bounded by measurement
rather than extrapolation.

| Family | Verifier owner at rows 2-4 | Classification |
| --- | --- | --- |
| Q4_K / Q5_K / Q6_K / Q8_0 | `q4_k_t16_dense_rowtile_gemv`, `q5_k_t16_dense_rowtile_gemv`, `q6_k_t16_qmicro_planar_gemv_rowtile_col8`, `q8_0_t16_dual_split_gemv` | **Direct transfer** |
| IQ4_XS / IQ4_NL / IQ3_S / IQ3_XXS / IQ2_S / IQ2_XS | `gguf_iq_dense_strict` (strict per-row GEMV) | **Prefill-only** prefill owner + **verifier sibling required** |
| Q3_K | `gguf_iq_dense_strict` | **Verifier sibling required**, no rows==1 owner exists |
| Norm / residual | `gguf_add_rmsnorm_bf16_f32_weight`, `gguf_rounded_add_rmsnorm_bf16_f32_weight` | **Direct transfer** |
| Gate/up SiLU | UD `gguf_q5_k_t16_dense_dual_wmma_prefill_silu_bf16`, plain `q4_k_t16_dense_dual_rowtile_silu_gemv` | **Direct transfer** |
| Attention / GDN | `qwen35_paged_full_attn_decode_context_tensor`, `qwen35_gdn_recurrent_rmsnorm_gate_lowp_c1_exact` | **Direct transfer** |

Two measurements carry the classification.

**The W4A16 prefill owner is prefill-only.** Interleaved against the strict
GEMV on the four largest real tensors per quant, worst case over shapes:

| Quant | rows 1 | rows 2 | rows 4 | rows 8 | rows 16 | rows 32 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| IQ4_XS | 0.36 | 0.29 | 0.31 | 0.79 | 1.20 | 2.32 |
| IQ4_NL | 0.70 | 0.73 | 0.74 | 1.26 | 2.08 | 3.88 |
| IQ3_S | 0.27 | 0.23 | 0.47 | 0.75 | 1.54 | 2.65 |
| Q3_K | 0.20 | 0.21 | 0.27 | 0.64 | 1.00 | 1.86 |
| IQ3_XXS | 0.25 | 0.22 | 0.29 | 0.73 | 1.09 | 2.15 |
| IQ2_S | 0.56 | 0.45 | 0.53 | 0.86 | 1.54 | 3.23 |
| IQ2_XS | 0.50 | 0.38 | 0.43 | 0.64 | 1.20 | 2.29 |

It loses at rows 2-4 on every quant and wins from 8-16 rows, so routing MTP
through the prefill owner is not the fix.

**The rows==1 local32 decode owner already beats the strict GEMV at rows 2-4.**
Same tensors, interleaved:

| Quant | rows 2 | rows 4 | max relative error vs strict |
| --- | ---: | ---: | ---: |
| IQ4_XS | 2.40x | 3.04x | <= 2.3e-4 |
| IQ4_NL | 4.45x | 5.19x | <= 2.9e-3 |
| IQ3_S | 1.99x | 3.19x | <= 1.1e-3 |
| IQ3_XXS | 2.21x | 3.05x | <= 1.7e-3 |
| IQ2_S | 2.63x | 3.04x | <= 1.5e-3 |
| IQ2_XS | 2.43x | 2.85x | <= 6.0e-4 |

The strict GEMV's own time is flat from rows 1 to 4 (IQ4_NL `ffn_down`
0.554 / 0.530 / 0.534 ms), so it is weight-decode-bound and does not rescan
weights per row tile. The deficit is the decode cost per output block, and the
local32 owner already decodes 2.0-7.4x cheaper. A rows 2-4 sibling therefore
covers 94.1% (K_M) / 85.9% (K_S) of the dead-zone MACs; Q3_K (2.28% / 8.57%)
has no rows==1 owner and needs separate work.

## Validation

- **Device identity.** Every run set `HIP_VISIBLE_DEVICES=1` with
  `ROCR_VISIBLE_DEVICES` unset on physical GPU1 (RX 7900 XTX, gfx1100).
- **Representativeness.** The strict-GEMV leaf time reproduces the Phase 1
  census: IQ4_XS `blk.0.ffn_gate` (N=17408, K=5120) measures 241 us at rows 4
  against 237 us/call in the census.
- **Cross-check.** The W4A16 rows-2/rows-4 ratios here (0.29-0.74x) agree with
  the recorded 2026-09-08 integer-MMQ crossover (0.59x at 2 rows, 0.68x at 4
  rows) in sign and magnitude.
- **Agreement screen.** Every (quant, rows) cell reports max relative error
  <= 5.4e-3 and correlation 1.000000 between the strict GEMV and the local32
  owner; the owner is approximate, so Phase 4 still owes the production
  numerical gate.
- `python3 scripts/worklog.py check`: valid.
