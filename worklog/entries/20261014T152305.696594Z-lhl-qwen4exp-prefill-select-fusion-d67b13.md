# Qwen4Exp prefill selection and write fusion, decode PLE overlap

## Summary

Second pass over the prefill families against gufo after the long-prompt
gate, plus the first decode pass. All kept changes are bit-identical; the
regression check with identical output passes on both fixtures. Prefill at
p4096 1615.5 -> 1646.3 (0.95x gufo), p8192 +3.3%, p16384 +3.9%; decode +0.5%.

## Changes

- `e72b0ea50` QSA prefill: causal-only block scoring from a once-staged
  query tile (the old tiled scorer re-read the query tile for every key tile
  and had a 16-way LDS bank conflict on key rows); direct top-k to WMMA
  mask with a parallel bin scan.
- `94aba2453` attention gate read in place + F16 image for the output
  projection.
- `68dc89ad9`, `5ca8e5957` residual write fused into the next
  hyper-connection norm (FFN read, and across the layer boundary), chunks
  of >= 1024 rows.
- `2dd109247` decode PLE host staging overlapped with layer 0.

Findings that set the next steps:

- Prefill kernel time 2493 ms vs gufo 2373 (HEAD 492186123). Biggest
  remaining: GDN conv 54.8 ms (gufo fuses the conv into the input-projection
  GEMM epilogue, boundary kernel 11.4 ms) and GDN norm/gate 57.7 vs 44.4.
- Decode: 37.9 ms kernel per step, 1354 launches. Wall-minus-kernel was
  about 5 ms with a warm PLE cache: ~3.5 ms of 2-5 us launch gaps and ~1.5 ms
  of host at step boundaries. Without a warm page cache the PLE row gather
  takes 2.5 ms per step from major faults (28.8 GB IQ4_NL table via mmap).
  A device-side PLE hash+gather would remove the host round trip per step
  and is the prerequisite for pipelined or graph-captured steps.
- A bug I introduced and fixed before commit: skipping the separate mask
  kernel also skipped the WMMA attention launch in the same block (output
  changed with history); a stale-state probe (logits hash across mode
  orders) caught it. The first A/B (+4.6%) was invalid for that reason.
