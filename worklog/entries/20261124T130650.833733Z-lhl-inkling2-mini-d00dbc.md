# Fix the shared pinned staging buffer race

## Summary

The async H2D upload path copied each payload into one shared pinned buffer and returned without waiting, so a later payload overwrote bytes the device had not read yet. This was the self-inflicted corruption behind the divergent resident-block results at the loop re-entry. The fix pools pinned buffers per in-flight copy and recycles a buffer only after the event recorded after its copy reports completion.

## Changes

- `hipengine/loading/inkling2_activation_transfer.py`: `enqueue_upload` now checks out a pinned slot, copies into it, records a stream-0 event after the async copy, and recycles slots only once their event completes. New `upload_slots` pool with `_checkout_upload`/`close` handling; pin-unavailable fallback keeps the synchronous path.
- `tests/test_unit_inkling2_activation_transfer.py`: fake-runtime tests for distinct buffers per in-flight upload, buffer recycling after event completion, no reuse while pending, the pin-unavailable synchronous fallback, and close-time cleanup.
