# GD-4's state-drift screen passes — the chunked fp16 GDN arithmetic is admissible in principle

## Summary

With `MX-1` refuted, `GD-4` is the largest remaining performance lever in the ledger:
its cost gate is measured at a **~5.5% of prefill** ceiling, and its risk is that it
**changes arithmetic in the recurrence, which carries state across the whole prompt**.
The row therefore requires a **state-drift screen over 4K prompts and chunk/tail
boundaries before any build**.

No chunked/scan GDN kernel exists in this tree — every registered route is a sequential
chain variant — so the screen was run on the arithmetic itself: the same gated
recurrence computed in chunks with fp16 operands, fp16 intra-chunk accumulation and an
f32 chunk carry, against the sequential f32 chain, at the model's real geometry
(Hk16/Hv48/Dk=Dv=128, 3x kv-repeat, 4096 tokens).

**The screen passes.** State NMSE **1.106e-07**, out NMSE 1.56e-07, max |dS| 6.32e-05:

| variant | state NMSE |
| --- | ---: |
| chunk 64, fp16 + fp16 intra | 1.10599e-07 |
| chunk 128 | 1.10582e-07 |
| chunk 256 | 1.10516e-07 |
| chunk 512 | 1.10602e-07 |
| chunk 384 (**tail 256**) | 1.105e-07 |
| f32 operands (reassociation only) — control | 1.9e-13 … 1.5e-11 |

Drift growth over the prompt (chunk 64): 1.138e-07 / 1.147e-07 / 1.099e-07 / 1.106e-07
at 512 / 1024 / 2048 / 4096 — **flat**.

## What this establishes

1. **The reference's claim reproduces in this model's regime.** halo-box PR #91 reports
   NMSE ~2e-7; measured here it is **1.1e-07**.
2. **Chunk-size-independent** — a larger chunk, the efficiency-relevant direction, costs
   no accuracy.
3. **No tail penalty and no compounding**, the two hazards the row named.
4. **The dominant error is operand rounding, not reassociation order.** Pure f32
   reassociation sits at fp32 round-off; fp16 operands move it six orders; and fp16
   intra-chunk accumulation on top costs only a further **1.3x** (1.106e-07 vs
   8.462e-08). So the fused fp16 accumulation the kernel needs is nearly free relative
   to the rounding it already implies.
5. **The row proceeds to the build** rather than closing.

## A bug the screen's own control caught

The first version omitted the chunk's **first** gate factor on the cross-chunk and carry
terms. The symptom was that `out NMSE` was **identical across all three variants at each
chunk size** (3.265e-03 for all three at chunk 64) while the f32-reassociation control
showed state NMSE 8.7e-13 — an exact state with a 0.16% output error. That combination
is only possible if the discrepancy is structural, not numerical, and it was. Fixed by
carrying the unshifted cumulative log-gate and forming the pairwise decay ratio in log
space so it stays ≤ 1 and cannot hit 0/0 when `exp(cum)` underflows.

**The control variant is what makes the result trustworthy.** Without it the screen
would have reported a plausible-looking 3.3e-03 that was entirely its own bug — and this
is the second time this session that a measurement's own instrument was the defect (the
`candidate_dispatch_calls: 0` counter, and the `DP-8` launch counter before it).

## Validation

- Deterministic: two runs at the same seed reproduce every figure exactly.
- The **control variant** (f32 operands, reassociation only) returns fp32 round-off
  (1.9e-13 … 1.5e-11), which is what establishes the formulation is correct and that the
  fp16 figures are signal.
- The screen's own bug was found by that control and fixed before any number was
  recorded.

## Scope and limits

- **Synthetic unit-scale inputs and a NumPy model of the fp16 arithmetic, not the real
  kernel.** Real activations would confirm the regime.
- **State/output NMSE is not a KL measurement and does not establish production
  admissibility.** The binding bar is the per-scope production envelope, and this
  session's own `MX-1` result is the cautionary case: a route whose output error sits
  8.0-9.5x below the BF16 floor already in the path still failed the 18-row
  `prefill_last` scope. The screen says the arithmetic is admissible *in principle*; the
  production gate decides production.
- The ~5.5% ceiling is unchanged, and the row notes it is the same lever as `GD-3`.
