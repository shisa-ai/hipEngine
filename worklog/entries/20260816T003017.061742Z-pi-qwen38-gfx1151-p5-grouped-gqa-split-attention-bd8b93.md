# Screen Qwen3.8 grouped GQA split attention

## Summary

The clean post-G2 4K profile creates one new P5 premise: long-context BF16
attention is now **1,093.871 ms / 9.79%** of selected 128-token kernel wall,
but Qwen3.8's 24Q/4KV/D256 geometry falls through to the generic query-head
split producer. The existing in-tree grouped-GQA producer already shares each
K/V read across 8Q/2KV and the INT8 sibling supports both 8Q/2KV and 24Q/4KV.
Screen the corresponding BF16 `q_per_kv=6` specialization only at the >=4096
context crossover; 512/1K, natural short prompts, peer backends, and generic
fallbacks must remain unchanged.

## Changes

- Extend the existing BF16 grouped-GQA producer/wrapper with the same 24Q/4KV
  shape already supported by its INT8 sibling. The new template keeps the
  established `q_per_kv=6` arithmetic and uses the existing generic reducer.
- Add a gfx1151 package policy for dense H5120/L64/24Q/4KV/D256/block256 from
  active context 4096. Runtime selection reads that capability; 512/1K, natural
  short prompts, peer backends, explicit opt-out, and misses keep the generic
  query-head split producer.
- RED first required the public BF16 grouped wrapper to accept 24Q/4KV. GREEN
  matches the generic producer plus gated reducer and CPU attention on a paged
  4,097-token fixture. The route adds no resident payload or workspace.

## Decision

- **Retain and default** the grouped BF16 producer only for the gfx1151 package
  policy at dense H5120/L64/24Q/4KV/D256/block256 and context >=4096. Keep the
  generic producer/reducer as the explicit rollback and required fallback.
- Durable evidence is
  `benchmarks/results/2026-08-16-gfx1151-qwen38-27b-grouped-gqa-split-attention.json`.
  P5 remains open because Vulkan is still faster at 4K and both clean llama
  backends remain faster at 512/1K; natural AR is unchanged by this threshold.
