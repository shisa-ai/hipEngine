# Harden DMS task evaluator identity and exact scoring

## Summary

Hardened the G3 task/free-running evaluator after end-to-end review. Runtime
inputs now remain bound to the frozen model, manifest, evaluator, and generation
schedule, and exact-answer scoring no longer accepts prose that merely contains
the answer nonce.

## Changes

- Make task/free-running outputs atomic and immutable, and remove a build-path
  reference to a nonexistent parser argument.
- Stop greedy generation after the requested output count instead of taking an
  extra unreported decode step.
- Validate task-manifest model identity, frozen length, case count, unique IDs,
  and every recorded token-position invariant before execution.
- Bind dense free-running references to model, data manifest, and schedule, with
  exactly one matching prompt.
- Require dense/sidecar/sidecar G3 arm identities, both evaluator hashes, unique
  case IDs, and identical paired case sets.
- Score only a stripped exact answer, while retaining substring location as a
  diagnostic; clarify that no separate answer signal reaches the selector.
