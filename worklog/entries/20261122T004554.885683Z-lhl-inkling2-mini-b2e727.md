# Keep Inkling GGUF expert and Q8 projections packed on HIP

## Summary

Add the HIP owner for packed Inkling GGUF projections. The owner reuses the dense activation exchange, addresses expert slices by physical bank, and restores the original route order after grouping by expert. No GGUF generator is registered by this unit.

## Changes

- Keep dense Q8_0 matrices and NVFP4, Q8_0, and Q5_K expert banks packed. Upload each bank once, even when separate state slots visit it. Resolve the packed projection through the backend registry. Pass NVFP4's external scale into its projection; use a post-projection multiply for optional scales on the other formats.
- Allow the existing Q8_0/Q5_K build helper to bind the resolved HIP target explicitly. Its existing callers retain their default target selection.

## Validation

- `OPENBLAS_NUM_THREADS=1 python -m pytest -q tests/test_gpu_inkling2_gguf_device.py` failed before the owner existed and passed on `epyc` (W7900, `gfx1100`) and `strixhalo` (Radeon 8060S, `gfx1151`). Both format fixtures check the truncated Q8_0 vocabulary head, selected projection outputs in original route order, physical expert scale reuse, and exact packed bank bytes. The Strix run used the clean compiler environment from the [NVFP4 validation](20261122T004057.747259Z-lhl-inkling2-mini-8d4d1e.md) with `LD_LIBRARY_PATH=/opt/rocm/lib:/opt/rocm/core/lib` for rocBLAS.
- On `strixhalo`, projected both expert matrices from the pinned Loom checkpoint using visits 6, 18, 30, and 44 and ordered expert IDs `[61, 31, 61]`. FP32 input rows from NumPy seed 1983 matched the slice-decoded CPU oracle at `atol=1e-5, rtol=1e-5`, including NVFP4 repeated visits and a final Q8_0 bank. The original device-dense, GGUF linear registry, GGUF quant layout, and Inkling GGUF metadata tests also passed on `epyc`.
