# Attribution mappers: the promoted wide dense route was unclassified

## Summary

The wide-row dense prefill route was promoted to the production default at
layers 16-47 (`15b056111`), and every instrument around it was updated except
the one that produces the published family table. `map_hipengine` in
`scripts/qwen4exp_comparator_role_map.py` keys on **device kernel symbols** --
the registry's dispatch labels never reach a `rocprofv3` trace -- and its dense
rules were `dense_gemv`, `gguf_k_prefill_out_coltile_rowbatch` and
`gguf_k_pack8_prefill_out`. The promoted route's symbol is
`q8_0_dense_wide_kernel<...>`, which matches none of them.

Measured RED, on the exact route set the shipped default runs:

```
map_hipengine("q8_0_dense_wide_kernel<128, 256, 64, 64>") -> "other"
load_hipengine(post_promotion_role_set) ->
  by_family_ms        : {'other': 5400.0, 'dense_projection': 4200.0}
  unmapped_over_floor : [{'kernel': 'q8_0_dense_wide_kernel<128, 256, 64, 64>', 'ms': 5400.0}]
```

So the owed HEAD attribution would have billed the route the promotion is
*about* to `other`. `qwen4exp_shared_family_comparison.py` is run with
`--strict --unmapped-floor-ms 1` (the recorded protocol in
`benchmarks/results/2026-09-17-qwen4exp-per-role-cost/README.md`), so it fails
loudly instead of publishing that table -- but it cannot complete either way,
and that run is step 1 of the review's own ordering.

The hole was wider than the promoted symbol. Every kernel in
`gguf_q8_0_dense_wide.hip` (1), the dense WMMA scope the promotion replaced and
the plan retains for re-gating (5: `gguf_q8_0_prefill_wmma_kernel`,
`gguf_q8_0_prefill_dual_wmma_kernel`, `gguf_q8_0_t16_prefill_wmma_kernel`,
`gguf_q8_0_t16_prefill_wmma_nwave_kernel`,
`gguf_q8_0_t16_dual_prefill_wmma_kernel`), and two dense Q8_0 pack8 GEMV kernels
that the prefill census records on 9 launches were all `other`. The WMMA scope's
hole predates this promotion and was never exercised: the 2026-09-16 WMMA
promotion was evidenced by wall time and a launch census, not by this mapper.

## Changes

- `scripts/qwen4exp_comparator_role_map.py`: the inline dense token loop becomes
  `DENSE_PROJECTION_STEMS`, a named table with per-stem provenance, extended to
  the ten stems that cover the dense Q8_0 prefill route family (the promoted

  single and dual gate+up GEMV, and the raw-row vector leaf). `map_hipengine`'s
  docstring records that this list is coverage rather than best effort and why

  classifies hipEngine symbols, the cross-engine work-category bucketer, gains

  unmatched name is printed as `unattributed`), but the promoted route was
  unmatched there too.

  equal the example table and each example classifies; the promoted route
  classifies from the symbol recorded in the committed candidate artifact

  anonymous-namespace + tail-instantiation spelling a trace carries; every

  `dense_projection` and every `selected` one does not; a negative guard keeps
