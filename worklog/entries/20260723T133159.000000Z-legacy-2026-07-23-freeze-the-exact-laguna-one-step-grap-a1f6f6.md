# 2026-07-23 — Freeze the exact Laguna one-step graph design

## Summary

- First appended to the journal in commit `293aa80b` (subject: docs: freeze Laguna one-step graph design).

## Changes


- Audited `LagunaGGUFResidentSession.forward_token()`, `LagunaKVCache`, the global/SWA device `KVLiveSpans` consumers, the raw-greedy public loops, exact retained-prefix ownership, Qwen/PARO one-step graphs, and the graph-friendly runtime-state kernels. Current eager ownership performs two host position writes, one host token write, 869 Python/ctypes kernel submissions, argmax synchronization, and two scalar reads per D7 token. KV append already updates `live_counts`, `token_positions`, and `evict_mask` on device, so the graph does not need a second KV ABI.
- Froze a session-local, pointer-bound, position-independent one-step graph. It embeds directly from device `argmax_id`, runs the unchanged 48-layer/final-head/top-1 chain, and ends with one registered paired-position advance for RoPE and KV row state. A static identity key covers model/config/quant/layout/variant and every weight/RoPE/scratch/MoE/KV/span/control pointer; a dynamic replay ticket covers lifecycle epoch, committed cursor, pending transactions, capacity, dense-span policy, and re-priming after reset/prefill/exact continuation. The eager path and `scratch.token_id` remain the mandatory fallback.
- Eligibility is fail-closed to certified gfx1100, c=1, <=4K, BF16 KV, exact raw greedy, no processors/captures/verifier/eviction/user stream/multi-step replay. Host stop/EOS/deadline checks remain between one-token launches. Any replay/sync/readback ambiguity retires the session; reset and exact prefix reuse preserve the graph only while all pointers/variants remain stable and re-prime both positions to `session.position + 1`.
- Frozen RED gates compare eager and graph IDs, argmax value bits, full logits, final/post-layer hidden, both cursors, all 48 K/V payloads, and every live-span field at short, 255/256, 510-513, 1023/1024, reset/third replay, and retained-prefix continuation checkpoints. Capture must be non-executing, replay allocation-free, and tracing must show one `hipGraphLaunch` plus the D7 family and paired state tail. Full train+heldout category exactness, lifecycle, cold-inclusive E2E, and eager rollback remain mandatory.
- The bound is `T_h32 = 21.548 - 3.385*r + g + C/31` ms/token. With zero graph/capture overhead, 25/50/75/100% residual removal models 48.31/50.36/52.61/55.06 tok/s. Reaching 50 requires at least **45.73%** residual removal; at 50% only **0.145 ms/token** remains for graph/read/state-tail plus amortized capture. Capture is reported separately only for steady-state replay and remains included in fresh-request E2E promotion accounting. Updated `docs/LAGUNA.md`; this is a design result, not graph support or a performance claim. Task #277 implements/gates it and task #278 measures/promotes or rejects it.
