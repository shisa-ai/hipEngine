# add exact row64 shared-B down-projection candidate

## Summary

Task #11 now has a source-clean benchmark candidate. The retained shared-B kernel pads every `(17408,5120)` suite row to 256 and launches only 107 four-wave blocks. Its code object is VGPR254/SGPR24/LDS24576/scratch0; rocprof reports VGPR256/SGPR128/LDS24576/scratch0, grid 107×128 threads, exactly `SQ_WAVES=428`, and about 1.17 ms/launch under trace at row 35. With 96 CUs and 64 KiB LDS/CU, the grid supplies only ~1.1 blocks/CU and LDS admits at most two blocks/CU; this is measured low-wave supply plus row-padding waste, not the old false “107 blocks against 512 CUs” premise.

The new exact row64 sibling preserves the same four-wave, 48-column, shared-weight block and each output's K16 WMMA/F32-accumulator/BF16-store sequence. It changes only `ROW_TILES_PER_WAVE` from four to one, reducing block ownership from 256 to 64 rows. The existing 256-row parent remains a separately registered strict fallback.

- Refactored the incumbent device implementation into one forced-inline `ROW_TILES_PER_WAVE` body. The incumbent global still instantiates `<4>` under its existing name; the new `shared_b_row64` global instantiates `<1>`.

- RED/GREEN tests pin policy/registration/fallback and require parent byte equality plus the existing Q4_K CPU-reference gate at rows 35/48/67.
