# Qwen3.8 K3 selected hot-vocabulary draft head

## Summary

Porting the selected MTP proposal-head concept from exllamav3 PR #303
(`turboderp-org/exllamav3@5705f07b`) to the current W7900 Qwen3.8 GGUF route
as a default-off, model-bound screen. This is
not the older contiguous `vocab_cap`: arbitrary individual Q6 rows are repacked
into a compact planar-T16 head, and the existing stage-2 top-1 reduction maps
the compact winner back to its full token ID before the next draft step. The
full target head remains authoritative, so generated target IDs remain exact;
selection can only change draft acceptance and economics.

The current one-group profile makes this newly relevant: proposal Q6 is
14.864/17.777/21.454 ms per C6/C7/C8 cycle, or 6.60-7.12% of total cycle wall.
A 64K head has a bandwidth-only 5.15-5.58% complete-cycle ceiling, unlike the
older gfx1151 C1 deferral where the whole proposal stage was only 2.08% of wall.

## Changes

- Added a model-bound selected-vocabulary JSON contract keyed by the ordered
  tokenizer-token SHA-256, with strict size/sort/uniqueness/range validation.
- Added an independent-corpus map builder; it has no proposal-ID or fixed-prompt
  input mode. The first 65,536-token screen uses 2,201 source/docs files and
  separate Japanese technical documents, 12,143,395 corpus tokens, and includes
  every tokenizer special token.
- Added a compact individually selected Q6 materializer and a separately
  registered `proposal_top1_mapped_bf16` composite. Its stage-2 reduction maps
  the compact winner on device; the incumbent full-head exact variant remains
  the registered fallback.
- Wired `HIPENGINE_GGUF_MTP_HOT_VOCAB=<artifact.json>` through the dense NextN
  provider and provider-pool key. Unset keeps the existing full-vocabulary path.
