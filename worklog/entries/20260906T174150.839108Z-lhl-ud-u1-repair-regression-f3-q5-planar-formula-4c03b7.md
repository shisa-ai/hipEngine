# UD-U1 repair regression F3: exact Q5 planar sidecar allocation formula

## Summary

Second review round of the UD-U1 repairs: the F3 repair (commit `d665c01eb`)
made `preflight_qwen35_gguf_artifact` call
`planned_qwen35_gguf_weight_allocation_nbytes(spec)` per slot as a mandatory
materializability check, but that accounting function had no formula for the
`qmicro_planar` allocation name — so the existing env-gated
(`HIPENGINE_C8_Q5_PLANAR_DP4A=1`, plus the `GGUF_C8_Q5_RAW_MMQ_SSM_OUT`
capability) planar Q5 T16 `ssm_out` resident that the C8-P2 route materializes
today became a hard `planner_refused`
("unsupported resident allocation 'qmicro_planar'"). The prior U0 audit had
explicitly labeled this formula unknown and reported the resident
formula-unavailable rather than guessing; the new admission check turned that
known gap into a refusal of a previously supported path. This unit derives
the exact formula from the actual current host-side converter/allocation ABI
(no kernel, math, or default change) and preserves the env-gated planar path.

## Changes

- `hipengine/loading/qwen35_gguf_materialize.py`
  (`planned_qwen35_gguf_weight_allocation_nbytes`): new `qmicro_planar`
  allocation branch. The materializer uploads the INT8 `planar.tiles` array
  of `convert_gguf_q5_k_qmicro_tile16_to_planar(
  repack_gguf_q5_k_qmicro_tile16(raw[None, ...]))`, whose shape is
  `[experts, out/16, bytes_per_row/176, GGUF_Q5_K_QMICRO_PLANAR_T16_BLOCK_BYTES]`
  (3328 B/block) — exactly the `_planned_t16_nbytes` tile expansion with the
  planar block size. The branch is gated to `LAYOUT_GGUF_Q5_K_T16` residents,
  mirroring the materializer's own "qmicro_planar sidecar is only supported
  for Q5_K T16 residents" gate; tile-alignment and unsupported-layout
  refusals are unchanged. The never-produced standalone
  `gguf_q5_k_qmicro_planar_v1` resident layout stays refused.
- `tests/test_gguf_ud_admission.py` (RED first):
  - `test_q5_planar_sidecar_resident_plans_exact_converter_bytes`: realistic
    dense-H5120 `ssm_out` (5120, 6144) Q5_K; asserts the planned
    `("tiles", "raw", "qmicro_planar")` bytes equal the independent converter
    oracle computed from the real CPU converter chain: tiles 22,118,400 +
    raw 21,626,880 + planar 25,559,040.
  - `test_q5_planar_sidecar_resident_is_admitted_with_planar_flags`:
    preflight with all three flags is supported again; default-off (raw
    sidecar only) control unchanged.
  - `test_q5_planar_env_gate_resolves_off_by_default_and_on_with_env`:
    end-to-end through `resolve_gguf_dense_flags` with the real backend
    capability reader — env off → `("tiles", "raw")`, `HIPENGINE_C8_Q5_PLANAR_DP4A=1`
    → `("tiles", "raw", "qmicro_planar")`, both sized exactly.
  - `test_unaffected_sidecar_and_t16_controls_keep_exact_accounting`: Q8_0
    T16 tiles control and the Q6 qmicro-planar resident-layout control are
    byte-exact and admitted.
  - `test_invalid_planar_layouts_and_shapes_still_fail_closed`: the unused
    Q5 planar resident layout, a planar allocation on a non-Q5-T16 layout,
    and a non-tile-aligned planar shape are all still refused (mandatory
    shape checks are not waived).
- `tests/test_scripts_gguf_quant_route_audit.py`: the planar resident is now
  formula-sized instead of formula-unavailable — the sidecar is counted with
  exact bytes (25,559,040 for the fixture shape) and the pre-existing tied
  pack8 head fixture gap is the only remaining formula-unavailable entry.
- `docs/UD-QUANTS.md`: the U0 "no production formula yet" note is updated to
  the exact formula; a dated "U1 review repair regressions" subsection records
  both round-2 regressions and keeps U1 pending re-review (F6 accepted; F1,
  F3 concrete consumer, F4, F5 pending).
- `docs/REFACTOR.md`: precise C8-P2 formula-gap-closed note with the exact
  block formula and the tests that pin it.
