# Same-GGUF Qwen3.8-27B comparison: hipEngine vs llama.cpp and strix-llama.cpp

## Summary

Five engines ran against the same `Qwen3.8-27B-Q4_K_M.gguf` file on the
physical `gfx1151` host in one sequential session: hipEngine production AR
(`a2f62c881`), upstream llama.cpp HIP (`002a12ad2`) and Vulkan (`37b3a9e0c`),
and halo-box `strix-llama.cpp` HIP and Vulkan (`654803517`). BF16 K/V, no
speculation, shapes 512/128, 1K/128, 4K/128.

`strix-llama.cpp` HIP leads prompt processing at every shape
(**442.3/442.3/431.9** versus hipEngine **405.0/394.4/372.1** tok/s, i.e.
**+9.21%/+12.15%/+16.07%**). Both Vulkan builds lead text generation
(**12.86/12.82/12.68** versus **12.226/11.994/12.150**, **+4.4% to +6.9%**).
Upstream llama.cpp HIP is **-3.65%/-1.15%/+3.03%** against hipEngine prefill
and **+0.98%/+2.20%/-3.69%** decode; upstream Vulkan is behind on prefill at
every shape and ahead on decode at every shape. The hipEngine row reproduces
the published 404.5/12.2 headline to **+0.13%**, so the published cells stand
and no scoreboard number moved.

This is a diagnostic external comparison, not a retained performance claim, and
it carries no output-correctness gate for the llama.cpp-family rows.
