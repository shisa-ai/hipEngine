# Match Flash-Next Q4 decode execution to its strict manifest

## Summary

The UD-Q4_K_XL production manifest names strict Q4 gate/up decode, but the
binder restored the one-plane DP4A route. Remove that restoration so execution
matches the manifest. Other production optimizations stay enabled. The larger
prefill, scheduler, and task-quality requirements remain open.

A two-plane activation correction was implemented and tested first, but did
not resolve the long-context discrepancy. Its patch and captures are archived
outside the tree; no new kernel, selector value, or runtime branch is kept.

- Work in an isolated tree based on `53293a2ac`; preserve main's unrelated
  inventory metadata and scratch/prepared-comparator files.
- Reuse the October 20 first-divergence and DP4A-off captures. They show equal
  prefill outputs, the first live difference at layer-0 expert intermediate,
  and exact strict trajectories after disabling only decode DP4A on two
  witnesses. The full diagnostic pass disabled 34 settings; it is not the

  existing strict selection, strict fallback, one-plane registered variants,
  and diagnostic layer scope. Production and the opt-in fast profile now bind
  the same Q4 decode operation that their manifests declare.
- Add a profile/manifest regression test. Both production and fast failed
  before the change; strict already passed. Update the historical DP-9 test
  and selector-count test to reflect the numerical repair rather than require
  restoration of an observed-failing operation.
- Pin the existing `decode_dp4a_linear` diagnostic to its declared logical128
  consumer by disabling the warp override. A regression test reproduced the
  missing pin before the fix; the candidate remains executable for future
  numerical repair.
