# Provision and shrink compact DMS prompt extents

## Summary

Fix a real sidecar admission failure found during exact-Q4 masked-logit
prototyping. Compact admission reserved the target projected live count before
running the learned decision source; a validation prompt whose heads
under-compressed exceeded that extent and failed before quality could be scored.

## Changes

- Admission now reserves the complete prompt plus decode growth credit
  provisionally. Metadata separately reports the projected compressed extent.
- After streaming pack succeeds, each request-owned layer/head extent shrinks to
  actual live rows plus decode credit. Freed tails coalesce in the compact pool
  and matching K/V/position/eviction ledger claims are released atomically.
- Added `CompactExtentPool.shrink`, committed-capacity telemetry, and provisional
  release counters. Device storage remains one global fixed pool; shrinking
  changes allocator ownership, not backing pointers.
- Pressure-gate capacity now uses correctness-first provisional demand.

## Validation

- Focused admission fixture records provisional 8 vs projected 5 prompt rows.
- A 12-token pack with six survivors and two decode credits shrinks all extents
  to eight and releases 24 coupled-plane slots while preserving conservation.
- Existing compact lifecycle/device journal gates remain applicable.
