# Budget 5 is refused with a log warning, not clamped, and the c=8 no_provider case is a different mechanism

## Summary

The task #32 clamp probe is answered, and the answer is split.

**Budget 5 at c=1 is not clamped, and the engine does say so.** The capability
surface resolves it as requested (`candidate_budget={"requested": 5, "resolved":
5, "source": "explicit"}`) and the server logs an explicit refusal:

    WARNING:  EFFECTIVE_MTP: speculative_mtp_serving=enabled but the retained
    evidence rejects this cell (candidate_budget_not_qualified); requests fall
    back to autoregressive

The load arm then behaves exactly as that warning says: `mtp_requests=0`,
`speculation coverage: never_entered=2` of 2 requests, `routes: effective=
{"default": 2}`, decode 21.92 tok/s aggregate and 12.31 tok/s per-request median
at 83 ms ITL. Against the #32 sweep's budget 3 at the same c=1 (28.01
tok/s/request, 35.71 ms ITL), budget 5 lands at the AR rate, which is the
refusal working as intended rather than a performance regression.

So the safety half is correct: an unqualified cell refuses and falls back to AR
instead of running unqualified arithmetic.

**The discoverability half is not.** The same capability surface that refuses the
cell also prints `serving_route: true`, `configured_policy: "enabled"`,
`engine_supported: true`, `model_has_mtp_tensors: true`, `resolved: 5`, and
`certified_explicit_scope.key.candidate_budget = 5`. A client reading
capabilities would conclude this cell runs MTP. The refusal exists only as a
server-log WARNING, and the only machine-readable signal that nothing was
speculated is the harness's own `mtp_requests=0` / `never_entered` counters. For
a default-on MTP this is the difference between "safe" and "silently advertises a
speedup it declines to deliver".

**The c=8 `no_provider` result is a different mechanism, and this run does not
explain it.** Correction to the hypothesis that the two share a cause: the c=8
server log shows `serving=enabled engine_supported=True default_enabled=True
policy=enabled candidate_budget=requested:3 resolved:3 source:explicit` with **no**
rejects-this-cell warning. MTP was admitted at the serving level there and the
provider still never engaged, which is a distinct and more concerning failure:
nothing declined the row.
