# qwen4_exp MTP publishes shared per-request output accounting

## Summary

`Qwen4ExpMTPTextProvider` now records each request's committed output through
the shared speculative accounting helper and publishes the resulting block as
`telemetry.diagnostics.specdec2_mtp2`. The server already reads that block for
`output_accounting`, `mtp_output_tokens`, and the depth/acceptance counts, so a
Qwen4Exp MTP response reports the same MTP-versus-AR split as the resident
routes instead of falling back to the provider's legacy scalar counts.

The provider keeps every legacy diagnostic (`cycles`, `proposed_draft_tokens`,
`accepted_draft_tokens`, `draft_acceptance`, `timing.mtp_*`) unchanged. The new
block is additive, so `_mtp_draft_counts`' provider fallback and `chat_cli`'s
compatibility reader still work.

## Changes

- `hipengine/generation/qwen4_exp_mtp.py`
  - One duck-typed accounting record per `iter_generate` iterator. The record is
    local to the iterator, and that iterator's terminal `GenerationOutput` is
    the only publication point, so concurrent requests on one provider never
    share counters and a cancelled iterator publishes nothing.
  - Committed cycles call `record_speculative_outputs` with the selected depth
    (`len(candidates)`), the accepted draft count, and
    `visible_count = len(generated) - step_start`. `step_start` is the
    generated-token index the cycle started at, which is the helper's
    `output_position` contract, so spans tile the output and the prompt-prefill
    root token stays unattributed.
  - Scheduler-selected K0 steps (`send(0)`) call `record_autoregressive_step`
    with `plan_reason="scheduler_k0"` (`_K0_STEP_REASON`). This provider has no
    planner: the caller's per-step budget is the plan, and zero is a
    target-only step. K0 is not counted as a cycle, which keeps the block's
    `cycles` equal to the legacy `diagnostics["cycles"]` length.
  - `mtp2_requested_budget` and `mtp2_candidate_budget` are both the provider's
    configured budget. The generic provider route already rejects a request
    whose `speculative` budget differs from the configured owner, so requested
    and effective depth are the same number here.
  - Diagnostics are now built in a local dict and the block is added only when
    `speculative_output_accounting` returns one, matching
    `qwen35_gguf._request_diagnostics`.
- `tests/test_unit_qwen4exp_mtp_output_accounting.py` (new, 7 tests, RED first):
  serial accepted-plus-correction, batched bonus row, mid-cycle EOS truncation,
  AR-only K0 steps, K0 after a committed cycle (fallback position), cancellation,
  and a `_mtp_response_summary` reconciliation check.

Semantics preserved deliberately:

- Speculative tokens are only visible committed output. Rejected proposals, the
  prompt root token, and the duplicate prefill seed are never counted; a cycle
  cut short by EOS or the output horizon counts what it appended, not what it
  proposed or verified.
- Nothing is recorded for a step that raises before its commit, so cancellation
  rollback cannot leave attribution behind.
