# Compare speculative methods through public streaming

## Summary

Measure AR, native MTP budget 3, EAGLE-4 depth 3 and DSpine budget 5 through
public streaming with a common external clock. This is a same-host ZBook
comparison, not a stable-desktop result. No runtime arithmetic or defaults
change in this unit.

## Changes

- Add a common harness with three resident public LLM owners; AR/MTP share an
  owner. Requests are sequential and method order rotates per prompt group.
- Use every mtpbench prompt plus the separate category-heldout file, 256 outputs
  per request, two repetitions, greedy fixed count and no prefix cache. Preserve
  complete token IDs and compare both methods and repeats against public AR.
- Pool output counts and external request times. Separately pool generated
  transitions and first-to-last token-arrival intervals; keep internal timers
  diagnostic. Record prepare and first-use latency separately from warm calls;
  these are not cold OS/JIT measurements.
- Record profile manifests, actual route engagement, draft projections, hardware
  snapshots and hashes of the evaluator and prompt inputs.

## Validation

- CPU measurement, order, aggregation and exactness tests fail before the new
  driver exists and pass after implementation. The first live smoke exercised
  AR/MTP but rejected MTP because the harness read the stale batch snapshot
  rather than the completed request's `specdec2_mtp2` cycles. A RED/GREEN
  regression now checks request-local terminal telemetry. The invalid attempt
  stays local at `/tmp/qwen38-public-smoke.json`; no timing conclusion uses it.
  The second smoke passed all first-use ID checks; its short-output MTP tail
  selected depth 2 before an AR catchup. The route assertion now allows legal
  depths up to the requested budget, with a RED/GREEN regression. The next
  smoke uses the full planned output length before the suite run.
- Full-length smoke completed every route but found a genuine mismatch on the
  final output of `code_merge_intervals`: zero-based index 255 is token 10562
  for public AR and 1220 for MTP/EAGLE/DSpine; all preceding IDs agree. Preserve
  `/tmp/qwen38-public-smoke-v3.json` and investigate output-length dependence,
  profile selection and graph/eager behavior before accepting timing claims.
  No runtime or arithmetic change has been made in response.
- The follow-up diagnosis localized the difference to the production c1
  attention geometry, which strict incorrectly inherited. The separate repair
  `da2101ef5` binds strict to fixed256 and keeps production arithmetic unchanged;
  its public long-output regression passes. See
  `20261112T102755.458770Z-primary-qwen38-strict-attention-owner-3db2d1.md`.
- The harness now separates same-method repeat exactness from cross-route ID
  equality. Production records every first difference rather than rejecting a
  declared numerical difference. Strict comparison still requires cross-method
  equality. RED/GREEN tests cover both profiles and ensure a production repeat
  mismatch remains fatal. This is not a replacement numerical qualification;
  the timing artifact explicitly does not establish task-quality equivalence.

## Results

- The full production run completed all 144 measured requests: 18 prompts,
  two repetitions, four methods, 256 outputs each. All intended routes run;
  all same-method repetitions preserve complete IDs. MTP/EAGLE-4/DSpine IDs
  agree on every request, but differ from AR on 13 of 18 prompts. Earlier
  short-output exactness evidence must not be generalized to these lengths.
- Pooled whole-request AR/MTP/EAGLE-4/DSpine rates are
  9.0143/15.0478/14.4547/11.2398 tok/s; first-to-last-arrival transition rates
  are 9.1288/15.4703/14.9769/11.5885 transitions/s. MTP exceeds EAGLE-4 by
  4.1032% in this session. This is not a causal before/after comparison.
- Per-repetition whole-request rates decline from 9.3236 to 8.7249 for AR,
  15.5391 to 14.5866 for MTP, 14.9403 to 13.9996 for EAGLE-4, and 11.5632 to
  10.9340 for DSpine. Keep the thermally drifting ZBook lane separate from
  desktop results; do not infer a stable small-margin ranking from two repeats.
- Median warm first-token latencies are 0.4602/0.5391/0.6903/0.7742 seconds.
  Post-prepare first-use first-token latencies are
  0.4125/0.6654/9.7569/74.2243 seconds; the shared AR/MTP target and uncleared
  OS/JIT caches preclude calling these process-cold comparisons.
- Inspected text around every differing prompt. Changes include wording,
  code identifiers and explanation structure; the quantization response
  changes substantially after its first difference. Fixed output limits
  truncate answers. This inspection is not a scored task-quality or numerical
  envelope gate, and does not establish quality equivalence.
- Preserve complete IDs, texts, timings, hardware snapshots, exact invocation,
  model/drafter fingerprints and manifests in
  `benchmarks/results/2026-11-12-qwen38-public-production-comparison.json`.
  The evaluator source hash matches the measured source. Production uses the
  same manifest across owners, including the 1024-thread attention leaf,
  production Q4 verifier rowtile and FP32 recurrent state.
- Update only the benchmark rollup and changelog; root README is unchanged.

Reproduce with the downloaded drafter snapshot directories:

```bash
uv run python scripts/qwen38_public_comparison.py \
  --eagle4 "$EAGLE4_SNAPSHOT" --dspine "$DSPINE_SNAPSHOT" \
  --tokens 256 --repetitions 2 --execution-profile production \
  --output /tmp/qwen38-public-production-full.json
```

The exact absolute snapshot paths and command are in the artifact provenance.
CPU harness tests and documentation gates pass. The live full run verifies
public route engagement, output lengths, incremental streaming and repeats.
