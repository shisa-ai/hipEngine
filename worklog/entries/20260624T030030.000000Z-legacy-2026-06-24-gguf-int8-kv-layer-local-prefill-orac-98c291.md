# 2026-06-24 — GGUF INT8 KV layer-local prefill oracle and prefix-8 guard

## Summary

- Historical pre-Worklog2 journal entry, ported verbatim from `WORKLOG-LEGACY.md` (source lines 95983-95991).
- First appended to the journal in commit `6b5ac188` (subject: fix: use layer-local GGUF INT8 prefill oracles).

## Changes


- Root-caused the surprising W7900 GGUF INT8-KV long-context prefill mismatch: the temporary BF16 prefill oracle was shared across all INT8-retained full-attention layers, but chunk-outer bulk prefill revisits layers once per prompt chunk. With more than one INT8 layer, later layers overwrote earlier layers' previous chunks before those earlier layers processed the next chunk. This made the 2026-06-23 prefix `3..8` prefill failures a shared-oracle bug, not pure decode-quality evidence.
- Fixed GGUF retained-INT8 prefill to allocate layer-local temporary BF16 oracle caches for INT8 full-attention layers and release them before decode. Also stopped allocating the old shared BF16 oracle in `_GGUFFullAttentionPrefillScratch`. Short mirrored sessions still prefer the existing BF16 mirror; long decode still uses retained INT8 KV with no persistent BF16 mirror.
- Diagnostic confirmation on W7900/GPU0 with cached 7.13 compiler-version env guards: old shared-oracle prefix-3 `128K` prefill-only was rejected (`KL=3.09063`, top-1 `0.0`, first row mismatch `[7018] -> [82]`); with layer-local oracle the same prefix-3 prefill-only gate is exact (`KL=0`, top-1 `1.0`, no BF16 mirror). Pure INT8 still fails real decode quality (`4K/1` KL mean `0.275781`, top-1 `0.5`). Prefix `6` and `7` fail `128K/16` top-1 (`0.88235` for prefix 7); prefix `8` passes `128K/16` and full `128K/128`.
- Promoted GGUF long explicit-INT8 default from prefix `9` to prefix `8`. No-env W7900/GPU0 quality command: `HIP_VISIBLE_DEVICES=0 HIPENGINE_COMPILER_VERSION_FILE=/tmp/hipengine-hipcc-version-713.txt HIPENGINE_HIPCC_VERSION_FILE=/tmp/hipengine-hipcc-version-713.txt HIPENGINE_GGUF_DECODE_REPACK=1 HIPENGINE_HIP_ARCH=gfx1100 python3 scripts/qwen35_gguf_int8_kv_correctness.py --model /models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf --quant gguf_q4_k_m --prompt-lengths 128K --decode-steps 128 --max-sequence-length 131202 --compiler-version-file /tmp/hipengine-hipcc-version-713.txt --require-cached-build --require-no-bf16-mirror --json /tmp/gguf-int8-default-prefix8-128k-d128-perlayer.json` -> accepted, `KL mean=0.014484`, `KL max=0.660677`, top-1 `0.961240`, first mismatch row `4`, no persistent BF16 mirror, layout `8` BF16 primary / `2` INT8, effective scales `fp32`, candidate tracked peak/current `25.239/24.738 GiB`. This is a correctness gate, not a throughput claim; runtime environment was a direct shell with cached compiler-version guards, not the hermetic benchmark wrapper.
- Added artifact `benchmarks/results/2026-06-24-w7900-gguf-q4km-int8kv-prefill-oracle-prefix8.json` and updated `docs/TUNING-gguf.md`, `benchmarks/README.md`, and `benchmarks/CHANGELOG.md`. The next memory-saving options are now real HIP alternate KV formats (block16 / q8_0 / key-only variants) or non-KV residency reductions; current per-token/head pure INT8 is still not quality-admitted.
- Validation: `python3 -m pytest tests/test_qwen35_gguf_int8_kv_policy.py -q` -> `12 passed`; `python3 -m py_compile hipengine/runtime/qwen35_gguf_runner.py tests/test_qwen35_gguf_int8_kv_policy.py`; `python3 -m ruff check hipengine/runtime/qwen35_gguf_runner.py tests/test_qwen35_gguf_int8_kv_policy.py` -> passed; full W7900 `128K/128` quality gate above -> accepted.
