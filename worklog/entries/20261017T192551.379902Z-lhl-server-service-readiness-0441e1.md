# Report current service lifetime in HTTP readiness

## Summary

`/ready` now combines startup readiness with the loaded service's nonblocking
lifetime status. A failed, closing or closed service returns HTTP 503 with
`status: unavailable`, rather than reporting ready because warmup once passed.

## Changes

- Read `service_health` only from the loaded text generator or a direct engine
  hook. Never trigger lazy model construction. A raising health probe fails
  closed; engines without the hook keep their existing behavior.
- Preserve startup evidence, add sanitized service diagnostics, and skip live
  scheduler queries for an unavailable service (including metric helper fallback
  queries). Parent reviewed the implementation and CPU real-service tests.
- Document the service payload in `docs/API.md`. Also correct that page's
  Laguna generic-provider serving claim: the earlier sole-driver repair now
