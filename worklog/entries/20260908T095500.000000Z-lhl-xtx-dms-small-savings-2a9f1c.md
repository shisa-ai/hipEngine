# Review target 6: host-pack staging laziness, collector logits sizing, recovery proof

## Summary

Three small savings/recovery items from review target 6.

## 6a — lazy host-pack staging

The device payload store allocated the max_pack_rows-sized host-composition
staging trio (pack_k/pack_v/pack_evict) eagerly at construction, but only the
host-composition pack path ever uploads through it. The device-pointer path
(pack_layer_device / device_streaming_pack_layer — the layer_outer DMS route)
never stages through host memory. The trio is now allocated on first host
pack, sized at the constructor's max_pack_rows so the copy-size guard is
preserved. At the layer_outer route's max_pack_rows=min(tokens,4096) this
skips 16,793,600 bytes (16.01 MiB) of device memory on the device-pointer
route.

## 6b — collector logits sized by selection mode

The external-DMS prefill collector allocated the full
[layers, tokens, heads] FP32 logits plane whenever the sidecar decision mode
was active (64 MiB at 256K). Audit finding: the exact-budget selection
genuinely requires the full plane — finalize runs the cross-layer global
eviction budget over every layer's logits — but all other sidecar selections
never read logits back (write-only kernel scratch), and captures are
stream-ordered per layer, so one layer's worth is shared across layers.
Exact-budget (this campaign's route) is unchanged at 64 MiB; threshold routes
drop to 4 MiB (60 MiB saved at 256K). The capture offset math is
mode-conditional.

## 6c — mid-pack recovery proof

No new runtime code was needed: the teardown landed with the layerwise
campaign (per-buffer rollback in _ensure_layer; the layer_outer pack pass
closes the partially built backend on BaseException). This unit adds the
missing proof: a simulated mid-pack MemoryError on the second per-layer
allocation rolls the partial layer back to zero, the tracked registry
returns to its pre-attempt level, the store remains usable (the retry
succeeds), and close drains every tracked byte.
