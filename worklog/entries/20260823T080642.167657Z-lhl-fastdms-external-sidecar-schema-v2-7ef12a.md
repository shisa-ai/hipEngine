# Add external DMS sidecar schema v2

## Summary

Added a strict schema-v2 metadata contract for an external linear DMS decision
sidecar while preserving schema-v1 corrected borrowed-query behavior and its
existing compatibility fingerprint. This is the first product-facing unit for
the hybrid Qwen3.8 path; no synthetic sidecar is admitted as model evidence.

The current local Qwen3.8 Q4_K_M artifact has the expected 64-layer hybrid
geometry but hashes to
`7e78da5d7e3ae28d178121f58646953305f3e5bd3cb46f4a75584e8b6c6fe169`,
not the older handoff hash. Future captures and sidecars in this branch must
bind the measured current hash.

## Changes

- Added `DMSLinearSidecarSpec` and `DMSTrainingProvenance` with strict format,
  BF16 shape, SHA-256, data-manifest, trainer, FastDMS-source, and seed checks.
- Extended `DMSRetrofitConfig` with a discriminated
  `external_linear_sidecar_v1` schema-v2 path, explicit physical layer IDs,
  hidden size/input stage, and preserved-Q semantics.
- The loader verifies the actual model file hash, sidecar hash, safetensors
  header/tensor names/dtypes/shapes/byte ranges, and an optional model-plugin
  physical-layer capability map before activation.
- Kept schema-v1 borrowed-channel validation and fingerprint byte-compatible;
  external configs fail closed if routed through borrowed-Q extraction.
- Added RED/GREEN CPU tests for valid loading, model/layer mismatches, duplicate
  layers, missing files, hash mismatches, malformed declared/file shapes, and
  dtype mismatches.
- Updated `PLAN.md`, `KVCACHE.md`, and `CONCURRENCY2.md` to distinguish schema-v1
  borrowed-channel semantics from schema-v2 external sidecars.

## Validation

- GREEN: 30 focused metadata, compact-backend, and decision-extraction tests
  passed.
- Targeted Ruff passed with only the file's pre-existing repository-wide lint
  exclusions (`I001,RUF022,BLE001,B009,RUF046,C408`) ignored.
- `py_compile` and `git diff --check` passed.
