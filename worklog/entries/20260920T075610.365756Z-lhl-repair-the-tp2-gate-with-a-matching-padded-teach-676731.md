# repair the tp2 gate with a matching padded teacher

## Summary

The gate now compares like with like, and the picture is **much better than the
retracted numbers suggested**. With a teacher captured for the identical padded
512-token prompt and forced trajectory:

- the **heldout prompt PASSES** with the exact T16 owner (`mean_kl 0.000995`,
  `max_kl 0.0370`, top-1 1.0). The retracted run reported `mean_kl 0.06998`,
  `max_kl 3.7705` for the same arm; all of that was the mismatched teacher.
- the route is **top-1 perfect in all four runs** (`top1_agreement 1.0`,
  `flipped_rows 0`). The remaining blocker is a narrow KL tail, not a broken
  route.
- the owner is a **large improvement on translate and a small regression on
  heldout**, so it still does not qualify - but both arms are close to the bar
  rather than far outside it.

## Changes

- `scripts/tp2_teacher_coverage_broad.py`
  - `_pad_prompt_tokens` - one padding rule, used by the teacher. The padded
    prompts land in the artifact's `suite.tokens`, which is where the diagnostic
    reads its prompts, so the teacher is the single source of the padded context
    and the two sides cannot diverge.
  - `--pad-prompt-tokens`; the sustained capacity check now requires
    `pad + 128 + 2` rather than a literal 200, which is what made a padded
    capture impossible before.
  - the adapter capacity follows `--max-sequence-length` instead of a hardcoded
    200 (the padded run failed with `bulk prefill rows 512 exceed cache
    capacity 256`).
- `scripts/tp2_bulk_prefill_diagnostic.py`
  - `assert_prompt_matches_reference` and `assert_trajectory_matches_reference`,
    called before scoring every prompt. They refuse a student whose context
    differs from the teacher's in length, in tokens, or in forced trajectory.
- `tests/test_unit_scripts_tp2_bulk_prefill_diagnostic.py` (new).

## What this changes

The owner's status is **unqualified, pending a heldout-tail fix** - not rejected.
It buys a 5.5x mean, 7.3x p99 and 6.1x max improvement on the translate prompt,
where only `max_kl 0.0752` now exceeds the bar, at the cost of moving the heldout
from passing to `mean_kl 0.001148 / max_kl 0.056886`. Both failing margins are
small.

A note on the earlier attempt: padding is legitimate for **dispatch coverage**
but is only *scoreable* when the reference was captured with the same padding.
The assertion now enforces that, so this class of error cannot recur silently.
