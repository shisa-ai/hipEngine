# MTP E1a: scope physical C3 prompt streaming

## Summary

The existing physical prompt-streaming path is a material Qwen3.8
standard-Q4 C3/K3 win, but the first speed screen exposed a hidden-representation
defect. Streaming originally consumed pre-output-norm BF16 target rows while
host replay consumes post-output-norm MTP seeds. Generated outputs remained
exact, but one prompt's acceptance trajectory changed (468/597 versus the
471/597 control).

The corrected path normalizes every streamed target row on device before NextN
consumes it and reuses normalized slot tails for target sampling. A full dirty
screen then restores the control's exact 471/597 acceptance and reaches
**27.169 vs 24.054 tok/s (1.1295x AR)**, up 27.1% from the E0 K3 control. All ten
cells are exact/engaged/budget-conformant and every category is positive.

## Changes

- Add a gfx1151 backend-package policy for only dense-H5120
  `MOSTLY_Q4_K_M`/production/physical-C3 prompt streaming.
- Resolve model/quant/profile widths in the generic dense MTP adapter; unlisted
  widths and keys retain host replay.
- Normalize complete packed target prompt rows into existing packed norm scratch
  before streaming; reuse normalized tails for LM-head sampling instead of
  running a duplicate tail norm.
- Correct the target-hidden sink contract to post-output-norm rows.
- Add RED-first package/scope/normalization tests; preserve the internal manual
  streaming override used by existing tests.

## Validation

- RED: package policy and adapter width admission were absent; the packed
  prefill seam had no post-output-norm source helper.
- GREEN: focused package/policy/streaming tests pass, followed by the complete
  MTP2 seam + gfx1151 backend + serving-capability bundle.
- Initial pre-output-norm speed screen: 27.068/24.120 tok/s, but acceptance
  changed to 468/597 and was rejected.
- Corrected dirty full-suite screen: 27.169/24.054 tok/s (1.1295x), 471/597
  acceptance exactly matching E0, 10/10 exact/engaged/budget-conformant cells.
- No new kernel body, changed arithmetic, persistent allocation, env flag, or
  prompt/category selector.
- Clean-source full-suite gate is required after this code commit because the
  canonical harness rejects tracked-dirty source.
