# Indexed Qwen4Exp PLE dilated-conv decode: one token per request over history slots

## Summary

Adds the independent-request form of the PLE dilated depthwise convolution, the
third prerequisite for batched (C2/C4) serving after the GDN recurrent primitive
(`e7476fe65`) and the linear-attention Conv (`3c56655ce`). One launch advances
`rows` independent requests: row `r` is one token of its own request, reads its
own packed token row, writes its own output row, and reads and writes exactly PLE
history slot `state_indices[r]` of a `[state_slots][(kernel_size - 1) *
dilation][channels]` FP32 slab. Slots no row selects keep their exact bytes.

This is a primitive plus its tests. No runner, serving path, or dispatch default
was changed. Parent integrated the catalog and cleanup-ledger entries and ran
`uv run pytest -q tests/test_unit_qwen4exp_ple_indexed_decode.py tests/test_gpu_qwen4exp_ple_indexed_decode.py tests/test_gpu_qwen4_exp_ple_hip.py tests/test_unit_qwen4_exp_ple_cpu_reference.py`
on the final source: 91 passed on zbook/gfx1151.

## Semantics: what one row is

The single-request owner walks `rows` consecutive tokens of one request and reads
`input[logical]` when `logical >= 0`, else `history[history_rows + logical]`, with
`logical = row - (kernel_size - 1 - tap) * dilation`. For the indexed ABI every
row is **one token**, so `row == 0` in that expression:

- tap `t < kernel_size - 1` reads history row `t * dilation`;
- tap `kernel_size - 1` reads the row's own token;
- the state update (`logical = 1 - history_rows + state_row`) is shift-by-one-row
  with the token appended to the last row.

The kernel keeps the owner's statements and its ascending `state_row` order, so
the read-before-write relation inside one slot is the owner's. The history update
is a copy with no arithmetic, so the emitted history is bit-exact, not merely
close. This was verified, not assumed: see the numerical section.

## Changes

- `hipengine/kernels/hip_gfx1100/fused/qwen4_exp_ple.hip`
  - `ple_dilated_depthwise_conv_decode_indexed_f32_kernel`: the owner's
    convolution statements with `blockIdx.y` selecting the row and
    `state_indices[row]` selecting the history slot.
  - **Whole-batch admission before every write.** Two rows naming one slot would
    interleave two requests' shifts, and the output row is a write too, so both
    are gated. The read phase runs first (it only reads), then warp 0 clears a
    4096-bit shared bitmap, sets one bit per row, and sets `s_batch_rejected` on
    an out-of-range or duplicate slot. The clear-to-scan dependency stays inside
    the warp via one `__syncwarp()`, so publication costs one block barrier. A
    slot outside the slab is redirected to slot 0 for the read phase so no load
    leaves the slab; the scan then rejects the batch anyway. The `channel >=
    channels` tail is guarded by a predicate rather than an early return, so the
    barrier stays convergent. Shared names, the `warp`/`lane` locals and the
    `atomicExch(&s_batch_rejected, 0)` init follow the existing
    `qwen4_exp_linear_attn_conv_decode_indexed_f32_kernel` convention.
  - **One un-restricted slot alias for both loads and stores.** The first version
    derived `const float* __restrict__ slot_history` for the read phase and a
    second `float* __restrict__ slot_out` for the write phase from the same
    `history` allocation. Both are aliases of one object, so the pair contradicted
    `__restrict__`; they are now a single `float* slot_history` that carries no
    `__restrict__` of its own, with the restricted `history` argument supplying
    the no-alias promise against `input`, `weights`, `output` and `state_indices`.
    The load and store expressions and the ascending `state_row` order are
    unchanged, and the arithmetic is re-measured below.
  - Launcher mirrors every host bound and the 8-byte `state_indices` alignment,
    and bounds the derived `(kernel_size - 1) * dilation` directly.
- `hipengine/kernels/hip_gfx1100/fused/qwen4_exp_ple.py`
  - `qwen4_exp_ple_dilated_depthwise_conv_indexed_f32` wrapper and the
    `qwen4_exp_ple_indexed_state_indices` host admission helper (distinct slots,
    slab bounds, `state_slots >= rows`).
  - Six `QWEN4_EXP_PLE_INDEXED_MAX_*` constants paired one-for-one with the C
    `constexpr` guards; a source-scanning test asserts the pairing.
  - Registry variant `qwen4exp_ple_indexed_decode` on `(hip_gfx1100,
    ple_dilated_depthwise_conv, f32)`. The existing `f32` / `strict` single-row
    owner stays registered and is the fallback.
- `tests/test_unit_qwen4exp_ple_indexed_decode.py` (40 tests): slot admission
  (permuted/numpy-int32/duplicates/out-of-range/bounds), launcher admission
  including the misaligned index vector and the inclusive history-rows bound,
  C/Python bound pairing, and the CPU oracle over the layout claim, repeated
  steps, row-order independence and the stateless `kernel_size == 1` case.
- `tests/test_gpu_qwen4exp_ple_indexed_decode.py` (44 tests): bit-exactness vs
  the single-row owner, untouched-slot canaries, output-tail canary, whole-batch
  rejection for out-of-range and duplicate slots (bytes unchanged, deterministic,
  including rows in the second warp-scan pass at 64 rows), repeated steps with
  permuted slots, determinism across reruns, history edge cases (`history_rows` 1,
  3, 9 and 0), the 64-row maximum, the independent CPU oracle, registry/fallback,
  and the raw C entry point for ten invalid geometries plus one valid call.

## Numerical result

Measured on the device above. `channels=320`, twelve (kernel_size, dilation,
row-count) combinations; "bits" is the count of differing `uint32` payloads
against the same-host single-row owner run per row.

| comparison | output | history |
| --- | --- | --- |
| vs single-row owner, K=4 D=3/1, K=3 D=2, K=2 D=1, N=1/2/4 | 0 differing bits | 0 differing bits |
| vs single-row owner, production width `channels=10240`, K=4 D=3, N=1/4 | 0 differing bits | 0 differing bits |
| vs CPU oracle (`dilated_depthwise_conv`, one-token positions) | relL2 3.7e-8..6.0e-8, max abs 3.0e-8..6.0e-8 | 0 differing bits |

Declared class is **T0 (layout-only)**: the block body repeats the owner's
statements in the same order, so bit-exact equality with the single-row owner is
the declared expectation and it is asserted in the test, not assumed. The oracle
row is the independent check; the history is exact there too because the update
is a copy. No production numerical gate is required for this variant, and none
was run. The test's oracle tolerance is `atol=2e-6` (~30x the measured 6e-8),
matching the sibling GDN primitive rather than being tuned to this fixture.

## Parent review repair

Two source defects were raised after the first report and are fixed in the
uncommitted source above. No test file, catalog, runner or other doc changed.

1. **Redundant restricted aliases to one allocation.** `const float*
   __restrict__ slot_history` (read phase) and `float* __restrict__ slot_out`
   (write phase) both named the same history slot, which contradicts
   `__restrict__`. Replaced with one `float* slot_history` that carries no
   `__restrict__`; the restricted `history` argument still supplies the

## Limitations (unqualified)

- **One token per row, one step per row.** The ABI does not accept multiple
  consecutive tokens per request; a multi-token request still uses the
  single-request owner. Nothing here composes the two.
- **Nothing dispatches the variant.** No runner, scheduler, or serving path calls
  it, so there is no end-to-end, batching, or speed result and none is implied.
- **Admission is a guard, not an allocation policy.** `channels` up to 1048576,
  `state_slots` up to 4096 and `history_rows` up to 65536 are admitted; only
  `channels` 64..10240, `kernel_size` 1/2/3/4, `dilation` 1/2/3 and up to 64 rows
  were exercised. Wide values are unmeasured.
- **Outer KL / top-1 gate: missing, not satisfied.** This primitive emits a Conv
  vector and a history update, not logits; nothing on the logit path consumes it
  yet. Bit-exactness with the dispatched owner bounds risk but is a per-call
  identity, not the gate.
- **The whole-batch guard costs one barrier and a 512 B shared bitmap.** It was
  not compared against a guard-free variant, so the cost is unquantified.
- **Test-helper pitfall found, not fixed in the shared suite.** A H2D copy of a
  non-contiguous host array made inline (`np.ascontiguousarray(x)` as an argument)
  is freed before the copy is read, and `np.empty_like` on a strided view keeps
  the strided layout so a packed D2H copy scrambles it. Both were hit and fixed
  inside the new GPU test file. Existing tests that upload only contiguous arrays
  are unaffected; tests that upload a strided view may be silently comparing
  garbage. Worth an audit outside this unit's scope.
- **Slot admission is duplicated.** The host validator restates
  `qwen4_exp_conv_indexed_state_indices` semantics rather than sharing a helper,
  because edit scope was `qwen4_exp_ple.{hip,py}`. A shared admission helper is a
  reasonable follow-up.
- Parent verification and catalog integration are recorded in the summary.
