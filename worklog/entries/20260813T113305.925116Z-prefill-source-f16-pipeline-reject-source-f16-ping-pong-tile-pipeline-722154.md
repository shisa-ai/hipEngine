# Reject source-F16 ping-pong tile pipeline

## Summary

Rejected two-stream ping-pong overlap of exact T16-to-F16 production with the
retained rocBLAS-plus-BF16-cast consumer. Both same-geometry candidates are BF16
byte-exact and fit two tiles inside the existing liveness-aliased planes, but Q5
loses on XTX and the heavier Q4 threshold case decisively regresses W7900.

## Changes

- Added
  `benchmarks/results/2026-08-13-qwen36-27b-source-f16-ping-pong-pipeline-rejected.json`
  with capacity arithmetic, three counterbalanced screens, exactness, hashes,
  and the cross-board stop decision.
- Added no production streams/events, workspace partitioning, runtime selector,
  rollback flag, allocation, kernel, or dispatch change.

## Validation

- M512 Q5 K6144/N5120 tile1280 uses two 15.0-MiB weight tiles and two 1.25-MiB
  output tiles inside the existing 34.0/3.0-MiB planes, but XTX changes
  **0.544684 -> 0.552524 ms (+1.44%)**, only **6/31** pairs win.
- M512 Q4 attention-output K6144/N5120 tile1024 is the heavier same-geometry
  threshold case. XTX improves **0.637443 -> 0.628404 ms (-1.42%)**, but W7900
  regresses **0.634924 -> 0.680402 ms (+7.16%)** with **0/31** wins.
- Sequential and pipelined outputs are BF16 byte-identical in all three screens.
  No additional allocation is used.
- Wider Q4/Q6 roles would require shrinking independently qualified GEMM tiles
  to fit two weight planes, so they are closed after the same-geometry
  cross-board failure rather than benchmarked under a different arithmetic/
  library geometry.
- JSON syntax, worklog schema, raw hashes, and diff hygiene pass.
