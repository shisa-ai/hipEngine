# every expert stage is cleared in isolation while the whole call still diverges

## Summary

The elimination in `20260928T055827` left the group-scatter as the only stage
never exercised. It is now read and cleared, and so are all the rows of both
projections -- and the contradiction is now explicit.

**The group-scatter is correct.** `hipengine_qwen35_moe_group_compact_active`
launches `qwen35_moe_group_compact_active_kernel` (the serial one, `dim3(1)` by
`dim3(256)`, not the parallel ballot variant), which recomputes `expert_start`
itself from a shared-memory count pass and then writes, for each active expert,

```cpp
int64_t out_idx = expert_start[expert];
for (int64_t lane = 0; lane < total_lanes; ++lane) {
  if (selected_experts[lane] == expert) {
    sorted_lanes[out_idx] = lane;
    sorted_experts[out_idx] = expert;
    sorted_weights[out_idx] = routing_weights[lane];
    ++out_idx;
  }
}
```

That is stable ascending-lane order inside each expert with `expert_start` as
the base -- the correct compaction. It also writes `expert_start[num_experts]`,
so the prefix is complete. It overwrites `expert_start`, `active_experts` and
`active_count` after `prefix_active`, which makes that earlier call redundant
rather than wrong.

**Both projections are cleared on every row**, not just row 0:

| weight | compact=4 route | row 0 | row 1 |
| --- | --- | --- | --- |
| `experts_gate_up_proj` | `grouped_prefill` | rel 0.0, bit-equal | rel 0.0, bit-equal |
| `experts_down_proj` | `grouped_prefill` | rel 0.0, bit-equal | rel 0.0, bit-equal |

The earlier probes compared only `out[0]`, which was a real gap: the combine sums
*all* of a token's lanes, so a divergence in row 1 would have been invisible.

## The contradiction

| stage | status |
| --- | --- |
| group-scatter (`sorted_lanes`, `expert_start`, `sorted_weights`) | correct, read |
| gather | correct, read |
| gate_up projection, all rows | bit-identical across routes |
| GeGLU | elementwise over `lanes * intermediate` |
| down projection, all rows | bit-identical across routes |
| lane-to-row map | correct, read |
| weighted combine | correct, read |

Every stage agrees, and the full call still differs by 0.9 to 1.9 percent
between `rows=1` and `rows=2` under a single-expert routing. Something in the
full call is therefore **not one of the stages enumerated here**, or the stages
interact in a way the isolated probes cannot see.

## What the isolated probes cannot see

They supply inputs by hand: a routing, and a packed hidden buffer with *distinct*
rows. The full call supplies a routing from the group-scatter and a packed
buffer from the gather, where **both lanes of a token carry the same hidden
row** (`packed_hidden[2i] == packed_hidden[2i+1]` for `top_k=2`, since
`token = lane / top_k`). No probe has run with that aliasing present.

The other candidate is a stage the enumeration misses. The list above is
constructed by reading `gemma4_experts_forward_bf16`, so a buffer written
outside it -- by the layer wrapper, or by the `_zero` helper, or a scratch
buffer reused across calls -- would not appear.

## Changes

None. This unit is a read and a measurement.

## Validation

- `group_scatter.hip` read at `qwen35_moe_group_compact_active_kernel` and at
  its `hipengine_qwen35_moe_group_compact_active` wrapper, which is what
  establishes that the serial kernel is the one launched.
- Probe on the 8060S (gfx1151) comparing **every shared row** of both
  projections across `compact_rows=2` and `=4`, on the F32 output with bit
  equality as well as relative L2. Exit 0.
- The contradiction is stated as a contradiction rather than resolved by
  preference: no stage is claimed wrong on the strength of the whole-call
  divergence alone.

## Next

Instrument the full call rather than the stages. Compare the intermediate
buffers -- `packed_hidden`, `gate_up_out`, `activated`, `expert_out` and the
final output -- between a `rows=1` and a `rows=2` call with the same first row,
under the single-expert routing. That locates the divergence by buffer instead
of by kernel, and it is the only remaining way to see a stage the enumeration
does not contain.
