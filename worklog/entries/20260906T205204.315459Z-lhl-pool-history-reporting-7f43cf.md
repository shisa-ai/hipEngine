# Pool history wide-C1 clean; retired-bytes reporting landed

## Summary

The Packet 2 "Bound cached graph/workspace buckets and safe retirement; test
wide-to-C1 and C1-to-wide histories; report reusable pool capacity separately
from memory returned to the device allocator" item is complete on both its
reporting and history halves.

Reporting (RED-first): `DeviceKVPoolStats` gains cumulative
`retired_pages`/`retired_bytes`, accumulated by `DeviceChunkedKVPool` in
`shrink_idle` and `close` — pages returned to the device allocator, distinct
from `free_pages` (reusable capacity parked inside allocated chunks). The
server metrics surface exposes them as
`hipengine_kv_pool_retired_pages_total`/`hipengine_kv_pool_retired_bytes_total`
(the `_stats_to_mapping` allowlist was the reason a naive stats field would
have silently read as 0 — it now carries the retired keys).

History: a new `scripts/gguf_pool_history_probe.py` serves one cold session
and drives wide(1,535 tok) -> C1(63) -> C1(63) -> wide -> C1 with held/drained
sampling per phase. Measured on the XTX (BF16, N=2, ctx 2048, post-scratch-cap,
commit 5c36ac653):

- All five phases validate against exact server accounting.
- Whole-card usage is flat at 22,224 MiB through every phase — zero creep
  between wide and C1 shapes; post-load usage stable; sampler peak 21.703 GiB.
- The default pool is born at full serving capacity (32 pages = 512 MiB for
  2x2,048): grow_events 0, shrink_events 0, retired 0 across the whole
  history. 16 pages (256 MiB) park as reusable capacity (`free_pages`), 16
  pages stay pinned by the resident sessions. Retirement is grow-scenario
  machinery (CPU-verified); the default path never grows, so there is nothing
  to return — the parking is the finding, recorded via
  `pool_parks_full_capacity`.
- graph_bucket_entries 0 at these shapes (eager routes; no packed captures).
