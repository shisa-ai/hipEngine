# DE-1 dual vs strict: the warp256 gate/up max-KL tail is the candidate's, the flip is not a near-tie, and the 18-case suite fails BOTH arms

## Summary

DE-1's `warp256` gate/up candidate is 2.06x faster and recomputes to **2.792 ms/step =
~5.9%** of the decode kernel total, but stayed default-off because an earlier run measured
it 4.34x worse on max KL than the incumbent on `heldout_mixed_review`. The open question was
**which arm owned that tail**. Every prior measurement compared the candidate *against the
incumbent*; this run compares **both arms against the strict teacher** in one process, which
is the only basis that can answer it.

Three results, and the third is the one that changes how the row should be read.

**1. The tail belongs to the candidate.** `heldout_mixed_review`: candidate 0.26119 vs the
incumbent's own 0.06017 against strict (**4.34x**). `mixed_ja_en_review`: 0.19023 vs 0.05364
(**3.55x**). The regression is real and is not the incumbent's.

**2. The flip is not a near-tie.** The single top-1 flip on `heldout_mixed_review` is at
**step 63 of 83** with **margin 0.954472**, where the candidate's step KL is 0.261188 against
the incumbent's 0.039213 (**6.7x worse**). The minimum step margin anywhere in that case is
**0.1076**. This **corrects an earlier reading** that described the flips as near-ties with
min top-5 overlap 3-4 of 5 and min margin 0.0335-0.1686; that came from a different run and
does not describe this one.

**3. The suite fails BOTH arms, so its bars cannot discriminate.** Against strict:

| metric | bar | candidate | incumbent |
| --- | --- | --- | --- |
| `kl_mean` | 0.001 | **0.001164 FAIL** | **0.001054 FAIL** |
| `kl_p95` | 0.005 | 0.003536 pass | 0.003732 pass |
| `kl_p99` | 0.02 | 0.019565 pass | **0.024299 FAIL** |
| `kl_max` | 0.05 | **0.261188 FAIL** | **0.078490 FAIL** |
| `top1_overall` | 0.99 | 0.993307 pass | 0.994645 pass |
| `top1_by_category` | 0.97 | 0.99197-0.99398 pass | pass |

The **incumbent** exceeds the 0.05 max-KL ceiling on **3 of 18** cases and fails `p99` as
well. This reproduces on the larger 18-case suite the conclusion an earlier run reached on
the canonical 12-case fixture (incumbent failed mean 0.0012761 and max 0.0525692; candidate
equal on mean 0.0012891 and better on max 0.0477176).

**4. The candidate's regression is confined to `max`.** Relative to the incumbent against
the same teacher the candidate is worse on `max` (3.33x) and `mean` (1.10x), but **better**
on `p99` (0.81x) and `p95` (0.95x). It is not uniformly worse: the entire envelope failure is
the single step-63 outlier on one case - exactly the shape the row's remaining action
targets.

## Next

- **DE-1's remaining action is a layer localization**, which this run sets up: the flip is a
  single wide-margin step, so bisecting the effective layer scope
  (`HIPENGINE_QWEN4_EXP_Q4_DP4A64_LAYERS`, which the warp path inherits because it is only
  reachable where `use_dp4a` is true) should identify it. A `--dp4a-layers` override was
  added to the probe for this.
- **A trap found while setting that up, recorded because it is easy to hit again:** the
  runner tests `(not dp4a_layers or gate_layer in dp4a_layers)`, so an **empty** value means
  *no filter* (every layer), not *none*. Setting the scope to `""` to mean "no dp4a"
  therefore enables dp4a on **all 48 layers** including the 5 normally excluded ones, and
  measured **incumbent max KL 0.19363 vs strict** - 3.2x the 43-layer scope's 0.06017. The
  exclusion set is load-bearing, and `none` must be expressed as a list matching no layer id.
- Limits: one model, one quant, one host, one execution profile, one fixture family; the
  candidate's 2.06x is a microbenchmark projection onto DE-1's traffic model, not an
  end-to-end measurement, and this run makes no speed claim.
