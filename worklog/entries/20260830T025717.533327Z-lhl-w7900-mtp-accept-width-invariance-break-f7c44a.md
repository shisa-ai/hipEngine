# W7900 Qwen3.8: MTP loses 40% of accepted drafts the moment width>=2, and cycles never pack across the wave

## Summary

Two independent MTP defects, both measured from the retained K3 C1-C8 packet
(``/tmp/he-c1c8-k3/c1c8-k3-packet.json``, status complete, 80 cells) with no new GPU
run. **(1) MTP cycles never pack across the wave**: cost per lane-cycle is flat
(107 ms at C1, then 98/83/85/89/90/84/85 ms), so a wave cycle costs 107 ms at C1 and
680 ms at C8 - linear in lanes, zero amortisation. **(2) The native GPU-accept path
is not batch-composition invariant**: per-prompt acceptance is 0.65-1.00 at C1 and
0.30-0.69 at C4, and C4 and C8 are *exactly* equal for all ten prompts. Together
these explain the objective's MTP row: hipEngine sits at ~31 tok/s at every width
(slower than its own AR at 45.66 from C2 up) while llama.cpp current scales
32.6 -> 94.7 tok/s.

## Changes

Analysis only - no code or benchmark-rollup change. Adds this entry, the per-prompt
acceptance table, and the queue of one attribution experiment
(``HIPENGINE_GGUF_MTP_VERIFY_MODE=serial_exact`` at K3 C1-C8, `bg-54`).

Drafts per cycle are unchanged by width (2.75/cycle at C1 and at C8), so the loss is
in acceptance, not in proposal volume. ``mtp_engaged``/``mtp_budget_conformed``/
``exact`` are true for all 80 cells: a rejected draft only falls back to the verified
token, so **content-exactness cannot see this defect at all** - batch-composition
invariance is the gate that covers it (`docs/EXECUTION-PROFILES.md`).

Attribution so far: at width 1 every MTP decode step runs the ``native_c1_*`` route;
from width 2 on the packed route appears and acceptance drops. C4 == C8 exactly for
every prompt, so this is a binary route switch at width >= 2, not a capacity or
row-count gradient. `bg-54` separates the two candidate causes - if ``serial_exact``
restores C2+ acceptance to C1 levels the packed *accept predicate* is at fault;
if it does not, the *packed draft* differs from the c1 draft.

Refuted along the way: I suspected the width-1 AR decode route was slow. A linear fit
of packed AR steps (28.0 ms fixed + 18.4 ms/row) predicts 46.4 ms for one row against
the measured c1 route's 45.3 ms, so the c1 route is consistent and not a defect.
