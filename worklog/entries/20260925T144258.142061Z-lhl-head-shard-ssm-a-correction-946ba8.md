# correct the ssm_a example and narrow the residual-error claim

## Summary

Two corrections to
`worklog/entries/20260925T112122.661729Z-lhl-head-shard-ssm-a-abi-717817.md`,
which is immutable and stays as written:

1. **The example had the source and converted values swapped.** The entry says
   "For `blk.0.ssm_a[0] = -3.203125` the kernel used `-0.040635`". The tensor's
   own value is `-0.0406350195`, and `-3.203125` is the `A_log` the kernel needs:
   `log(-(-0.0406350195)) = log(0.0406350195) = -3.203125`. The defect was that
   the kernel read the raw coefficient `-0.0406350195` in a slot that holds
   `A_log`, so its decay term used `exp(-0.0406350195) = 0.9602` where it needs
   `exp(A_log) = 0.040635`. Both numbers were right; their roles were reversed,
   which makes the mechanism read backwards.
2. **"The residual is the reduction's own floor" is stronger than the evidence.**
   The two quantities behind it - the sharded route's output against the
   unsharded reference, and `partials_sum_vs_full` against the same reference -
   are largely the same comparison once the exchange is known to equal the host
   sum. They cannot separate bf16 narrowing of the partials from a remaining
   error inside them, and each layer after the first is also compared through
   inputs earlier layers already changed.

The narrow claim that the evidence does support: the residual is **consistent
with split-projection arithmetic**, the reduction is **independently exact**
(host-sum check at every layer, ranks agree with each other exactly), so the
difference lives in the partials rather than in the exchange - and a same-input
projection control would be needed to say more.

## Changes

- `scripts/tp2_head_shard_agreement_probe.py`: the split-check comment no longer
  infers "any remaining error belongs to the reduction". It now states what the
  number is (the magnitude the split's own arithmetic accounts for), why it is
  not independent of the route comparison, and that a same-input control running
  the full and the rank-local projections over one captured input is what would
  establish the rest.

## Validation

- Documentation and comment correction; no arithmetic or dispatch changed, so no
  GPU run is needed. The probe's reported numbers are unchanged - only the
  inference drawn from them.
- The value pair is checked against the code's own definition
  (`_gguf_ssm_a_to_kernel_a_log` is `log(-coefficient)`) and pinned by
  `tests/test_unit_distributed_shard_weights.py::test_the_ssm_a_abi_is_the_kernel_a_log_of_the_source_coefficient`,
  which asserts `-0.0406350195 -> -3.203125` and `exp(A_log) = 0.0406350195`.

## Next

- A same-input projection control (one captured pre-projection input through the
  full projection and through the reconstructed rank-local projections, with the
  bf16 narrowing and the final summation accounted for separately) is the
  measurement that would replace "consistent with" with a bound.
