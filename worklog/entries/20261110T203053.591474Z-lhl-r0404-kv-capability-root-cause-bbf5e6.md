# R0404 root cause: gate never engages INT8 (two defects), safety guard added

## Summary

Supersedes the analysis in
`worklog/entries/20261110T201355.411545Z-lhl-r0404-int8-direct-false-positive-5bc43a.md`
with the confirmed root cause. The calibrated INT8 direct-prefill gate's
`passed / kl_mean=0.0` result is a false positive: the session runs BF16 KV, so
both arms are BF16 and the bit-identity is trivial. Two independent defects cause
it; R0404 stays OPEN and no arithmetic default changes.

## Changes

- `scripts/execution_profile_gguf_int8_direct_prefill_gate.py`:
  - Construct the resident session inside `route_environment(PURE_INT8_ENV)` so
    `ALLOW_UNVERIFIED_LONG=1` / `BF16_FULL_LAYERS=none` are live at construction
    (defect 1 fix).
  - Added a post-construction guard that raises `GateError` unless the session
    will actually engage mirror-free INT8: non-empty
    `int8_bf16_full_attention_layer_indices`, nonzero
    `int8_bf16_prefix_full_attention_layers`, or
    `int8_kv_no_mirror_qualified=False` all abort the gate. This converts the
    silent BF16-vs-BF16 false pass into a loud failure (defect 2 is NOT yet
    fixed, so the gate currently aborts here by design).
- No production runtime code changed. Diagnostic harness
  `/tmp/refactor-gfx1100/r0404_engage.py` (untracked) captures session KV config.

## Analysis (confirmed root cause)

Defect 1 — env timing: the session fixes `kv_storage_dtype` and the BF16 mirror
layer set at construction (`qwen35_gguf_runner.py:13853`, ~13905). The gate
applied `PURE_INT8_ENV` only inside the per-arm `route_environment` blocks
(gate:426/450) AFTER construction (gate:397), and `_rearm_bulk_workspace` only
releases the bulk workspace (does not recompute the layer set). With
`ALLOW_UNVERIFIED_LONG` unset at construction the default
`_GGUF_INT8_LONG_BF16_PREFIX_FULL_ATTENTION_LAYERS=8` made the first 8
full-attention layers BF16; this model's full-attention layers all fall in that
prefix, so every dispatch was BF16. Fixed by constructing inside
`route_environment(PURE_INT8_ENV)`.

Defect 2 — missing kv_capability (OPEN): the gate constructs
`Qwen35GGUFResidentSession(...)` WITHOUT `kv_capability=`, so it defaults to
`None` (runner:13173). `_admitted_no_mirror_int8_capability(None)` returns False
(runner:12325 requires `runtime_action=="admit"`), so
`int8_kv_no_mirror_qualified=False` and allocation falls closed to BF16 even
with the INT8 policy and empty mirror set. Production resolves it in
`hipengine/generation/qwen35_gguf.py::_resolve_int8_kv_capability` (line 1600):
builds `KVCapabilityKey` from artifact identity + backend/target/weight_quant +
kv contract, then `resolve_kv_capability(evidence=(), key, artifact,
declarations=model_plugin.kv_capability_declarations)`
(`hipengine/models/kv_capabilities.py:507`), which admits on kernel declaration
(unmeasured -> `runtime_action="admit"`). The gate must do the same and pass the
resolution to the session.
