# R0523 c4 race: corruption during conv-kernel execution, slot 1; conv/launch/streams cleared

## Summary

A 4-point per-slot state hash (ENTRY before norm / PRECONV after projections before conv /
MID after conv / EXIT after recurrent) pins the corruption to the **conv kernel execution
window**: slot 1's conv_state is clean at PRECONV and corrupt at MID, with **zero** cases
corrupt before conv and zero cases where the recurrent is the first corruptor. The onset
step varies across runs (73, 200, ...), confirming a timing-dependent race. The indexed
conv kernel body, its launch grid, the state-slab layout, and the static state_indices
were all inspected and are correct; no concurrent HIP stream is active during eager c4
decode. The exact race (in-kernel memory ordering vs an unidentified concurrent writer)
remains open. BEFORE perf baseline recorded for the requested before/after fix comparison.
No production behavior changed; hooks env-gated and uncommitted.

## Validation

Measured W7900 gfx1100, Qwen3.8-27B-Q4_K_M, c4 eager, 30 reps:
- bg-191 (ENTRY/MID/EXIT): clean_entry_corrupt_MID=10, clean_MID_corrupt_EXIT=0 => conv
  window is the source; recurrent divergence is downstream of corrupt conv_out.
- bg-192 (ENTRY/PRECONV/MID/EXIT): clean_PRECONV_corrupt_MID=4, corrupt_PRECONV=0 =>
  conv_state clean before the conv kernel, corrupt after. Conv kernel execution is the
  corruption point.
- BEFORE perf (bg-190, clean, no diagnostics): c1 24.298 tok/s aggregate (sigma 0.60%,
  0 mismatches); c4 58.850 tok/s aggregate (sigma 0.29%, 10 mismatches). Saved to
  /tmp/refactor-gfx1100/r0523-perf-BEFORE-baseline.json.
- Cleared: conv kernel per-(row,channel) window shift; launch grid dim3(ceil(ch/256),rows)
  bounds-checked; static distinct state_indices (_native_state_indices_buf); packed-slab
  per-slot stride; no active concurrent stream in eager decode (stream_create sites are
  graph-capture / MTP / Aotriton-prefill, all inactive here).
