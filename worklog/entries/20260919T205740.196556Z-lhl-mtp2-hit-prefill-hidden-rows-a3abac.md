# Unit 2's prerequisite: a hit row's suffix prefill is asked for no hidden rows at all

## Summary

Task #21 unit 2 was planned as "restore the checkpoint, then walk the suffix
from the restored boundary". Reading the code before writing it found a
prerequisite that unit 1's blob does not cover and that the design entry did not
name: **a prefix-cache hit row's prefill is never asked for hidden rows**, so
there is no suffix data for a provider to be primed from even once the prefix
half is restored.

The chain, read from the code in this session:

1. `_observe_mtp2_prefill` (`hipengine/generation/qwen35_gguf.py:10174`) passes
   the row's **full** `prompt_ids` to
   `adapter.observe_prefill_result(row.request_id, row.prompt_ids, result)`.
2. `observe_prefill_result` (`qwen35_gguf_mtp2.py:1983`) requires the result's
   hidden rows to be shaped `(len(prompt_ids), hidden_size)` and raises
   otherwise. For a hit row the prefill covers only the suffix, so a
   suffix-shaped result would raise inside the engine loop rather than fall back.
3. The resident serial prefill path used for these rows passes
   `return_hidden_seeds=False` unconditionally
   (`hipengine/generation/qwen35_gguf.py:9573`, and the segment path at 9702),
   so `hidden` is `None` and the row takes the "no hidden rows" branch, which
   records `prefix_reuse_k0`.
4. On the packed path `return_hidden_seeds=True` additionally requires
   `sample_output=True` (`qwen35_gguf_runner.py:23988`), and the returned rows
   are the rows for the **prefilled** tokens, concatenated per round.

Live evidence agrees with (3): in the c=4 artifact
(`benchmarks/results/2026-09-20-gfx1151-q4km-mtp2-provider-state-lifecycle-c4.json`)
the three prefix-hit rows report `activation_reason=prefix_reuse_k0`,
`provider_state_present=false`, and 0 cycles, with 0 failed requests -- no
exception, i.e. `hidden is None` rather than a shape failure.

## Why this matters for the plan

The checkpoint blob makes the *prefix* half unnecessary to re-prefill. The
*suffix* half still has to come from the row's own prefill, because the draft
provider consumes target hidden rows and nothing else produces them. So unit 2
splits:

- **2a (runner, new):** make a hit row's suffix prefill return hidden rows for
  the suffix, and let `observe_prefill_result` accept a suffix-shaped buffer
  keyed by the row's `prefix_reused_tokens` (the existing buffer map assumes one
  buffer per full prompt). Open question for 2a: whether the gapped slot-local
  prefill route that serves these rows can return per-round FP32 hidden rows at
  all, since the packed route's hidden-seed return is coupled to
  `sample_output=True`. If it cannot, 2a is a route capability change, not a
  flag flip.
- **2b (adapter):** the `restored_checkpoint` priming source, the restore, and
  the suffix walk from the restored boundary -- the plan already written.

## Changes

None: this unit is the dependency finding, and no code changed. Recording it
before implementing 2b is what stops a restore path being built against a suffix
buffer that the runner never fills.

## Validation
