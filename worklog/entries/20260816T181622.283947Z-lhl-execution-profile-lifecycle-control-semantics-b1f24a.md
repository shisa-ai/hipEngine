# Separate lifecycle controls from c1 arithmetic

## Summary

Separated lifecycle correctness controls from universal c1 arithmetic identity.
The first c8 run passed token trajectories, packed routes, cancellation,
re-admission, session reuse, compaction, graph invalidation, and final cleanup,
but correctly reported cN-vs-c1 BF16 KV byte differences. Those arithmetic
bytes are not request ownership or state-routing correctness.

## Changes

- Derive expected c1/c2/c4/c8 active masks from logical width, cancellation
  slots, and compaction instead of hardcoding the legacy 13-row shape.
- Add explicit `--allow-c1-arithmetic-drift`; it keeps all c1 byte mismatches in
  the artifact but makes them non-binding only with a matching clean, passed
  distributional `--quality-artifact` (KL <= 0.05, top-1 >= 90%).
- Same-run state/KV preservation across compaction, resource identity,
  request-token trajectories, routes, masks, session reuse, and drain remain
  hard pass criteria.

## Validation

  identity (and the old hardcoded masks) blocked the legacy verdict.
- `tests/test_gguf_arbitrary_c_lifecycle.py` passes `6/6`, including shape masks,
  opt-in arithmetic semantics, and matching quality-artifact validation.
- The actual 1,050-row ZBook quality artifact validates through the loader;
  script compilation and `git diff --check` pass.
