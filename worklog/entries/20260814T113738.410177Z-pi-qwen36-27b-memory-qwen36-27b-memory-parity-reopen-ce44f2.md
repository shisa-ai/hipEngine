# Reopen dense 27B memory parity work

## Summary

Reopened the dense Qwen3.6-27B memory lane after incorrectly treating explicit blocker publication as completion. The actual acceptance criterion remains whole-device peak delta at or below the lower llama.cpp HIP/Vulkan row at 512/1K/4K/8K with no meaningful prefill or decode regression. Current peaks are 16.094/16.305/17.022/17.277 GiB versus Vulkan's 15.690/15.700/15.912/16.166 GiB, leaving 0.405/0.605/1.110/1.111 GiB.

The retained ownership census localizes the growth. Physical weights are fixed at 15.280 GiB. BF16 full-attention KV is 48/80/272/528 MiB and expected. FP32 linear-attention recurrent state is a fixed 151.5 MiB. The package-default 4096-row full-attention query chunk drives bulk-prefill scratch to 495.315/501.612 MiB at 4K/8K, plus 80 MiB of full-sequence hidden ping-pong. Whole-device peak exceeds tracked ownership by 510/620/778/774 MiB; phase snapshots show only 282-403 MiB of that at steady boundaries, so the balance is a real load/execution transient rather than an allocator leak.

## Changes

- Restored the strict lower-backend memory floor as the binding goal instead of a best-effort stop rule.
- Audited current raw benchmark snapshots and the scratch planner rather than reviving rejected raw-Q4 or INT8-KV paths.
- Selected the already-supported exact full-attention query chunk as the first reopened screen. A 1024-row cap leaves linear/post/rope chunks unchanged at 1024, reduces modeled 4K bulk scratch 495.315 -> 142.913 MiB and hidden ping-pong 80 -> 20 MiB (about 412.4 MiB tracked), and does not alter decode ownership or arithmetic.

## Validation

- Recomputed all four current ownership families directly from `/tmp/qwen36-27b-memory-goal/compact-qk-final-{512,1024,4096,8192}.json` and cross-engine gaps from their 5-ms VRAM artifacts.
- Reconstructed dense scratch ownership with the production allocator and model fixture at 768/1024/1280/2048/4096 rows: 108.869/142.913/171.895/250.964/495.315 MiB.
- Confirmed Q5 and Q6 resident replacement layouts are byte-neutral; converting all Q4 to the previously rejected raw representation saves only 0.2716 GiB and cannot close any long-context gap alone.
- Working tree began clean and synchronized at `d209ded45`; HIP and both gfx1100 devices are available.
