# TimesFM 3.0 var-attention norm fusion — 0.397s -> 0.319s

## Summary

Fused the variate-attention QK RMSNorm + per-dim query scaling into the
var_attention kernel (the 2.5 qkv_norm_scatter pattern): the three
generic per-layer kernels (head_rmsnorm x2 + head_perdim, 100 ms =
29% of decode) are gone; metric decode 0.397 s -> 0.319 s (-20%),
now 4.17x the torch fp32 reference on the same GPU.

## Changes

- timesfm3.hip: var_attention_kernel now takes raw GEMM outputs plus
  the folded qscale (q_ln * log2e/sqrt(D) * softplus(per_dim)), k_ln,
  and eps; q/k rows are RMS-normalized in-kernel (LDS, deterministic
  warp-per-row sumsq) before the scores. A first implementation used
  atomicAdd row sums — run-to-run nondeterministic (fp32 parity flapped
  7.5e-5..1.9e-4 across runs) — replaced with warp-per-row
  lane-strided reductions before any validation was retained.
- timesfm3.py launcher + runtime: fused signature; per-layer folded
  __var_qscale uploaded at init; the three separate norm kernel calls
  removed from the var path.

## Validation

- fp32 vs torch oracle: base 1.3e-5, edge 1.1e-5, covmask 8.1e-6 —
  deterministic across repeat runs.
- fp16: base 7.2e-3 (~0.34% signal scale), edge 3.1e-3, covmask 6.3e-3
  — all under the 2%/0.5% production gate.
- Metric: 0.319 s (was 0.397 s); guard green on 3 fixtures; 7 GPU
  tests green. rocprofv3: head_rmsnorm/head_perdim eliminated; var
  attention family 121 ms -> 34 ms; total device time 345 -> 252 ms.
- MODEL-TIMESFM3.md updated (perf table + optimization history row).

## Decisions

- Determinism is non-negotiable in this kernel family (atomicAdd
  ordering was caught by fixture parity flapping before any commit).
- Fusion math: normalize from the f16-rounded raw values (single
  rounding order) — fp32 strict parity moved 8.3e-6 -> 1.3e-5,
  well inside the 1e-4 gate.

## Next

fused var 34 ms. Candidate follow-ups: fp16 rmsnorm/norm_add vector
widths, attention-kernel shape tuning, host preprocessing overlap.
Merge to main after review.
