## Changes

- Added `_set_batch_token_embeddings_from_ptr(token_src_ptr, *, rows)` to `Qwen35ParoResidentSession`: gathers batch token embeddings straight from a device int64 token buffer (e.g. `batch_lm_out_index`) via `embedding_lookup_batch_mapped_fp16_i64` (token_slots=rows, row_map=None), with no host token list, host→device copy, or host bounds check — so the gather is capture-safe inside a c>1 decode graph. The device argmax that fills the source buffer guarantees ids in `[0, vocab_size)` (the kernel skips any out-of-range id). Device-resident analog of the host-fed `_set_batch_token_embeddings`.
- RED/GREEN: `tests/test_qwen35_batch_embedding_from_device_ptr.py` (HIP-guarded, tiny fp16 table on device, no 35B model) asserts the gather is bit-identical to both the host-fed path and the numpy reference `embedding[token_ids]`, plus rows-bounds rejection. 2/2 PASS on `HIP_VISIBLE_DEVICES=1`. Building block for the C3.0b device-resident step (piece E); not yet wired.
