# Compare compact no-evict and dense attention on identical inputs

## Summary

Added a matched-input primitive diagnostic for the compact no-evict investigation.
On synthetic Q/K/V inputs, both compact and generic dense split attention agree
with a float64 softmax oracle at the historical 1,025/1,026-row boundary. This
narrows the investigation but does not explain the historical full-model logit
mismatch or prove absence of a synchronization race.

## Changes

- New GPU test uses the same BF16 K/V bytes in compact head-major extents and
  dense paged position-major storage, with NaN padding past the live extent.
- Check 257, 1023, 1025, 1026 and 1537 rows at 24 query heads, four KV heads,
  head dimension 256, seed 20260926, unit-normal synthetic Q/K/V.
- Compare both implementations against the same float64 oracle with
  atol=2e-5, rtol=2e-4; assert exact repeated compact outputs.
- No kernel, dispatch, arithmetic or threshold changed. This is an investigative
  diagnostic, so there is no deliberately failing RED implementation test.

## Validation

- ZBook Radeon 8060S gfx1151, torch-free HIP, no model/weight quantization:
  `HIPENGINE_HIP_ARCH=gfx1151 uv run pytest -xsq
  tests/test_gpu_dms_no_evict_matched_attention.py` passes all five cases.
- At 1025 and 1026 rows the observed compact/dense maximum absolute context
  differences are 1.9744038581848145e-7 and 1.6205012798309326e-7.
  Log: `/tmp/dms-matched-attention.log`.
- Dense uses the generic split-context producer and FP32 reducer; compact uses
  the existing split wrapper. This is output evidence, not a profiler trace or
  full-model quality claim. Synthetic inputs are not captured failing activations.
- ROCm liveness passed. Broad lineage inspection cannot run because the external
  atlas reference checkout is absent. No source was ported or kernel edited.
