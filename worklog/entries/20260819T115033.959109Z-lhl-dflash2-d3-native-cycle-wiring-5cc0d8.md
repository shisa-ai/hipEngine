# D3 wiring: native DFlash2 drafter in GGUF cycle + recall diagnostics

## Summary

Wired the native `DFlash2NativeDrafter` (forward + selector) into
`scripts/dflash2_gguf_cycle.py` via a `--native` mode, replacing the numpy
drafter's per-cycle forward+propose with the GPU kernels. End-to-end numbers
on the real Qwen3.8-27B GGUF (gfx1151) are now available, with a key selector
diagnostic: the drafter's candidate set is good (recall@16 0.872) but the
bilinear selector's top-1 (0.462) underperforms the raw draft-logit argmax
(0.513).

## Changes

- `hipengine/speculative/dflash2_native.py`: chunked host-staging H2D upload
  (for the 2.5 GB output head, which exceeds the staging buffer);
  `last_candidates()` and `last_logits_argmax()` diagnostics.
- `scripts/dflash2_gguf_cycle.py`: `--native` mode (`_run_dflash2_cycle_native`)
  that seeds the projected-context cache from prefill taps, runs native
  forward+select per cycle, sequentially verifies with commit-only-accepted
  greedy (identical semantics to the numpy cycle), appends accepted rows'
  projected taps, and reports per-position recall@1/@16/unary-argmax.

## Validation

Smoke prompt "The quick brown fox jumps over the lazy dog. Continue:",
Qwen3.8-27B-Q4_K_M on gfx1151, block_size 8, 40 new tokens:

- Correctness: DFlash2 native greedy == pure-AR greedy **40/40** tokens.
- Native vs numpy cycle (40 tokens): identical acceptance (mean 1.82,
  accepted/draft 0.117); native 5.08 tok/s vs numpy 1.99 tok/s (numpy drafter
  is the D1 bottleneck) vs AR ~10 tok/s.
- Recall per draft position: bilinear-selector recall@1 0.462, unary-argmax
  0.513, recall@16 0.872 (n=39).
- Existing D2b GPU tests still pass (10/10).

## Key decisions / findings

1. **Selector ranking diagnostic**: the bilinear selector's top-1 matches the
   target argmax less often (0.462) than simply taking the argmax of the raw
   draft logits (0.513), while the candidate set contains the target 87% of
   the time. The bilinear scoring is not adding ranking value on this prompt
   and likely degrades it — a candidate for the D4 selector-ablations
   (top-1 lane, unary-primary scoring).
2. **Throughput is verify-bound, but acceptance is the real blocker**: even
   with free verification, recall@1 ~0.5 caps the expected speedup near
   ~1x AR, far below exact MTP B3 (23.85 tok/s, 1.7845x). DFlash2 on this
   model is likely a diagnostic lane unless the selector/acceptance improves.
3. The native cycle matches the D1 numpy acceptance (0.095-0.117/draft on the
   smoke), confirming the low acceptance is the model's drafter behavior, not
   a native-path bug.
