# Profile and reduce Qwen4Exp MTP transaction costs

## Summary

MTP rollback and partial acceptance now share the runner's existing compact
cursor upload. On the public diagnostic, 56 partial restores use one 192-byte
copy rather than 24 eight-byte copies; their median synchronized window falls
from 1.503 to 1.211 ms (19.4%). Device snapshot allocation, size and state-copy
layout are unchanged. Baseline is `9c57c9d88`:
Qwen3.8-Flash-Next UD-Q4_K_XL, Q8_0 MTP sidecar, Framework Desktop / Radeon
8060S, production/BF16 KV, budget 3, fresh prompts and prefix cache off.
All 208 canonical/category/heldout outputs and acceptance rates match the
baseline. This unit claims a restore-window improvement, not an isolated
end-to-end speedup or a new numerical-quality verdict.

## Changes

- Added external diagnostic drivers under
  `/tmp/qwen38fn-mtp-state-20261022/`. The server wraps transaction creation,
  state snapshots, verification and accepted-row commit with synchronized
  nested windows, and groups copy calls/bytes by their enclosing phase.
- Reuse the runner's shared position/context staging in `adopt_prefix_cursor`,
  preserving bounds checks, closed-state checks, host mirrors, index counts,
  PLE history ownership, and the per-state fallback.
- Route `commit_target_block_rows` partial acceptance through that helper
  after computing the accepted PLE history. No state layout, arithmetic,
  snapshot allocation, GDN restoration, or full-acceptance behavior changes.

## Outcome

The compact upload is on the existing default shared-staging route, with no
new flag or arithmetic change. Reusable snapshots already avoid steady-state
allocation; their 119,533,568 bytes remain a cost. The pitched-copy screen did
not justify a new runtime API. Inherited strict-teacher numerical findings
are outside this exact state-movement change and remain open.
