# Repair checked full-row admission byte-range and provenance findings

## Summary

Corrects four parent-review findings in `b91209bc8` before any natural/model
qualification. No default, runtime or profile change. The repair tightens the
checked-int32 admission to float activation/output byte ranges, validates scalar
dimensions before forming the packed row byte count so a block-aligned
near-INT64_MAX K cannot overflow signed int64, corrects the exactness wording,
and adds reconstructable source/build/raw-sample provenance to the screen
harness. The original `b91209bc8` screen (`screen.json`) recorded only a dirty
head with no diff or source-file hashes, so its source provenance is incomplete;
corrected evidence is regenerated on a tracked-clean implementation after this
commit.

## Changes

- **Float byte ranges.** `q8_0_coltile_checked_int32_admissible` and
  `gguf_k_coltile_checked_int32_admissible` now require
  `rows * in_features * 4 <= INT32_MAX` and `rows * out_features * 4 <=
  INT32_MAX` (division-first), in addition to the raw-weight byte range and the
  `rows + row_batch - 1` grid product. This is strictly tighter than the prior
  element-only bounds, which the byte bound subsumes.
- **No pre-validation overflow.** The C++ helper now takes
  `block_size`/`block_bytes` and forms `row_bytes = (in_features / block_size) *
  block_bytes` only after rejecting any dimension above `INT32_MAX`, so a
  block-aligned near-INT64_MAX K cannot overflow signed int64 before the range
  check. The launcher passes the Q8_0/QK_K block parameters instead of a
  precomputed row byte count.
- **RED tests.** Unit cases assert the activation and output float byte ranges
  independently at the boundary where elements fit but bytes exceed
  INT32_MAX, plus refusal-before-build for those shapes. The raw-ABI GPU case
  now passes block-aligned near-INT64_MAX K, extreme int64 rows/N and the byte
  boundaries with pointer arguments `1,2,3`, proving the launcher refuses them
  before dereferencing.
- **Wording.** The artifact README now states that the full output tensor is
  bit-identical before and after the timing loop (one comparison at each end),
  not a per-pair check. This worklog is the correcting immutable entry; the
  prior `20261007T035429Z` entry is left unedited.
- **Provenance.** `scripts/qwen4exp_dense_dpp_checked_full_rows_screen.py` now
  records `source_files` (kernel `.hip`, wrapper `.py`, harness `.py` SHA256),
  `build_identity` (loaded shared-library path + SHA256, build-cache key, and
  device-object SHA256 when present) and `raw_samples_sha256` with the raw
  per-sample arrays written beside the output outside Git.
