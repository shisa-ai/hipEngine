# Check provider live KV through precommit recovery

## Summary

Add provider committed-prefix KV preservation to the precommit recovery test.
The prior unit checked target state and provider cursors, not provider KV bytes.
GPU0 N8/N2 pass all ten category-suite prompts each; no runtime implementation change.

## Changes

- `snapshot_provider_kv` uses the actual NextN `_batch_sessions` slot and the
  checkpoint's pre-proposal position. Hash both BF16 K/V planes over logical
  rows [0, position), mapping independent page/slot rows with `resident_rows`.
  Preserve request/slot, pointers, allocation sizes, row addresses and hashes;
  exclude rejected suffix bytes. Missing planes/ownership or unsupported dtype fail.
- Wrap the real `capture_request_checkpoint` to capture KV before proposal.
  Compare with that exact saved prefix after packed verification before injection,
  and again after real provider restoration. Require a nonempty verified prefix
  before a recovery cell passes. The target and provider cursor checks still apply.

## Validation

- Four addressing/ownership RED cases fail before helper creation, then pass.
  Two probe tests compare against pre-proposal capture and reject changed KV.
  All 56 provider-KV/recovery/lifecycle CPU tests and `git diff --check` pass.
- `bg-99` runs N8 then N2 on epyc W7900 GPU0:
  `HIP_VISIBLE_DEVICES=0 ROCR_VISIBLE_DEVICES=0 GPU_MAX_HW_QUEUES=1
  HIPENGINE_HIP_ARCH=gfx1100 .venv/bin/python scripts/qwen38_packed_c1_lifecycle.py
  --engine-boundary --precommit-failure --capacity N
  --output /tmp/packed-c1-provider-kv-recovery-nN.json`.
  Logs use the same stem with `.log`; both runs pass with clean teardown.
  Both K/V planes preserve 42–75 committed rows per prompt before injection
  and after restoration. All 20 cells preserve 131 target buffers, restore
  provider cursors once, continue with exact AR IDs, and drain all requests.
  Compact evidence: `benchmarks/results/2026-09-07-w7900-packed-c1-provider-kv-recovery-diagnostic.json`.
- Addressing audit: `resident_slot_view` supplies the owner and slot index;
  `_FullStackScratch.for_slot` keeps whole K/V cache allocations rather than
  slicing them. Thus `resident_rows` applies the private slot offset once.
  `capture_request_checkpoint` uses the logical next-consume position.
  Automated review could not launch because the configured reviewer model
  matched multiple providers; this addressing audit was performed directly.

- Broader regression while GPU runs: all 231
  `tests/test_qwen38_packed_c1_*.py` CPU tests and `git diff --check` pass.
  No running script changes were made for this verification.
