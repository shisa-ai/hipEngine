# Corrected - the dense_wide and wmma 16-47 certificates are one documented measurement, and the live default is dense_wide

## Summary

Supersedes `20260930T110914` (`5f220eb4c`), which opened the bit-identical
`dense_wide`/`wmma` 16-47 certificate hashes as a possible third false pass.
**It is not one.** The identity is documented, intended, and is the stated
reason the WMMA route was retired at that scope.

## What the earlier entry got wrong

It framed the identical hashes as an unexplained anomaly and asked whether one
gate failed to run its route. The answer was already in the tree:

```
hipengine/generation/qwen4_exp_profiles.py
PRODUCTION_Q8_WMMA_PREFILL_LAYERS = tuple(range(16, 48))
# Retired as the production default at this scope on 2026-09-17: the wide-row
# route below holds the identical envelope (byte-identical strict and candidate
# logits digests) and is 5.4% faster at 1K/4K.

PRODUCTION_Q8_DENSE_WIDE_PREFILL_LAYERS = tuple(range(16, 48))
# ... with `strict_logits_sha256` and `candidate_logits_sha256` equal to that
# route's gate artifact byte for byte.
```

The wide route replaced the WMMA route at 16-47 **because** it holds the
identical envelope while being 5.4% faster. `_q8_dense_wide_claims_parent`
documents the mechanism: the WMMA rewrite runs earlier in the launch chain, both
families are f16-operand WMMA, and the wide route takes precedence over the
family it replaces at that tile.

All three artifacts agree, including the 2026-09-16 WMMA certificate at
`f1d676684` - which the earlier entry did not check, having compared the
`dense_wide` certificate against a *later* 2026-09-29 control artifact.

## What the sweep did establish

1. **The two certificates are not independent evidence** - one measurement cited
   twice. Accounting that counts "wmma 16-47 certified" and "dense_wide 16-47
   certified" as two supporting artifacts double-counts. The project knew this
   (the docstring cites the identity); the artifact set does not make it visible.

2. **The earlier entry's "the production default is `wmma`" is imprecise.** The
   route that runs at 16-47 today is `dense_wide`
   (`PRODUCTION_Q8_DENSE_WIDE_PREFILL_LAYERS`); the WMMA selector is retired at
   this scope and retained for opt-in and re-gating.

   **This sharpens the stale-certificate finding rather than weakening it.** The
   certificate that admits the **live** default carries teacher hash `550bb9b8`,
   which `20260930T110625` showed no longer reproduces at HEAD. Its teacher
   movement also follows **by identity** rather than by a separate run: both
   gates clear every selector for the teacher arm, so both teachers are the same
   exact chain and both now return the value the `wmma` gate returns at HEAD.

   **The action item is therefore a re-gate of `dense_wide` at 16-47**, not of
   `wmma`.

## What remains open

## Method note

This is the **third** plausibility-first hypothesis in this campaign refuted by
a cheap check run late: the cache-key fix (`20260930T102145`), DE-3 as the first
baseline mover (`20260930T102357`), and now this. In each case the decisive check
was a grep or a diff that took under a minute. The pattern is the finding, not
the individual instances: **name a cause only after the cheap decisive check, or
record it explicitly as a hypothesis.** An earlier draft of the superseded entry
also said the check "should have preceded writing the open-lead file" - it did
not, and the file went into the ledger before the resolution.
