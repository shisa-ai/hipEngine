# Bind c1-c8 harness to expected MTP and K0 widths

## Summary

Made the canonical c1-c8 server harness distinguish expected engaged MTP cells
from expected typed-K0 cells. Staged MTP2 currently supports at most four
physical requests; c5-c8 are safety/fallback observations, not failed MTP
engagement. The harness can now pass full correctness when MTP engages every
expected cell and zero unexpected cell.

The T0.4 production c1 rung also established the resident-capacity constraint:
a capacity-8 owner correctly rejects a lone c1 MTP child, while a capacity-1
owner engages. T0.4 therefore runs one fresh capacity-matched process per
width instead of one max-capacity process for all widths.

## Changes

- Added `--expected-mtp-widths`; `none`/`k0` declare typed K0-only cells.
- Summary records `mtp_expected` and `route_expectation_passed` per width.
- Overall pass requires every correctness cell plus exact expected engagement,
  not MTP engagement at unsupported widths.
- Added unit coverage for parsing, expected engagement, and expected K0.
