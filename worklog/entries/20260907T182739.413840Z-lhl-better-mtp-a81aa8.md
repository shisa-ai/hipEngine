# Packed-route C1 overhead localized to host accept sync; structural parity conclusion

## Summary

A stage-timing comparison through the product HTTP route
(`campaign-artifacts/c1-k-sweep/stage_timing_compare.py`: one model load, two
identical explicit-MTP K3 requests, legacy leg on the default evidence, packed
leg after the injected `packed_c1_target` row with the legacy verifier
replaced by a guard; 8 cycles each, both legs engaged, acceptance 0.652,
identical 2.95 tokens/cycle) shows the packed-vs-legacy C1 gap is entirely
per-cycle wall cost, not cycle count or acceptance:

| Stage (8 cycles) | Legacy | Packed | Delta |
| --- | --- | --- | --- |
| target (verify) | 385.6 ms | 252.6 ms | −133.0 |
| accept | 0.0 | 459.3 | +459.3 |
| ↳ target_readback (D2H) | 0.0 | 453.2 | +453.2 |
| proposal | 10.9 | 32.3 | +21.3 |
| execution route | graph ×8 | eager ×8 | — |

The packed route's accept stage round-trips through the host (~57 ms/cycle
readback that also acts as the cycle sync point) and the packed target runs
eager (`verify_target_blocks_batch` has no graph plumbing; the legacy
`verify_target_block` does). The eager target itself is faster per cycle
(31.6 vs 48.2 ms launch) — the graph gap is not the target cost.

**Structural conclusion:** at C1 the packed route verifies the same 4-row
frontier through the batch-oriented path; with graph capture and device-side
acceptance its best case is parity with the legacy singleton graph replay
(~48 ms/cycle), not a win — there is no batching advantage with one active
request. The legacy singleton route (measured 1.6329x median) is the correct
C1 default and stays. The packed route's value is C2-C8 batching, where it is
already the product default with the retained wins. The dual C1 target-route
dispatch is ledgered in `docs/REFACTOR.md` (2026-09-07 entry) with its
removal condition: graph-captured packed parity re-measured on the C1
balanced-pair protocol.
