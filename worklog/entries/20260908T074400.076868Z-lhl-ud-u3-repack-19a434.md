# UD-U3 per-tensor repack eligibility becomes the default

## Summary

Executed item 1 of docs/UD-OPTIMIZED-ROUTE-PLAN.md. The model-wide raw-IQ
decode-repack veto (which put 0.0% of UD weight bytes on optimized layouts)
is replaced by a per-tensor veto: only a tensor whose own GGML type is
raw-IQ keeps its compressed raw layout; every other type repacks under the
same request. Measured on the published sweep protocol (zbook): K_M prefill
22.1 -> 29.9 tok/s (+35%), decode 6.21 -> 7.24 (+17%), resident weights
16.55 -> 15.57 GB. Gap to the plain file on the same host and protocol
narrowed from 13.3x to 9.9x (prefill) and 2.0x to 1.73x (decode).

## Changes

- `qwen35_gguf_policy.py`: `resolve_ud_repack_eligibility` (env
  `HIPENGINE_UD_REPACK_ELIGIBILITY`, default `per-tensor`, rollback
  `model-wide`) and `gguf_tensor_repack_eligible` (per-tensor form).
- `qwen35_gguf_materialize.py`: the model-wide veto applies only when
  explicitly forced (`repack_veto=True`) or under the `model-wide`
  eligibility mode; `per_tensor_repack_veto` is threaded into
  `_spec_for_tensor`, which vetoes repack for raw-IQ tensors only.
- `tests/test_gguf_ud_repack_eligibility.py` (new, RED-first): default
  grants non-IQ repack, raw-IQ stays raw, model-wide rollback strips repack,
  optimized share >= 40%.
- Updated planning-truth tests that pinned the model-wide default
  (`test_qwen35_gguf_materialize_helpers.py`: default now expects T16 with a
  new explicit rollback test; the contraction-independence test pins
  `repack_veto=True`). `test_gguf_ud_admission.py`'s synthetic
  F32-contraction fixture pins the model-wide rollback (it tests owner
  admission, not layout selection).

## Validation

- RED-first: two of the four new tests failed before the implementation,
  all four pass after; the 154-test planning/admission/parity sweep and the
  E2E acceptance suite are green. Real-model K_M admission reports zero
  refusals under the new default.
- Perf (published sweep protocol, zbook, item-0 baseline same command):
  prefill 22.10 -> 29.93 tok/s, decode 6.21 -> 7.24 tok/s, tracked resident
  peak 15.28 GiB, allocated weight buffers 15,568,398,336 bytes.
- Numerics (context512, consumed tokens verified equal to the teacher input
  binary in both captures):
  - serial-prefill capture: **bit-identical logits** to the pre-UD-U3 raw
    default - the T16 decode owners are exact versus the raw/pack8 decode
    path, so the residency change alone does not move decode numerics.
  - production-config capture (bulk+WMMA prefill, the sweep path): mean
    0.0012376, p95 0.0053786, p99 0.0211052, max 0.0332762, top-1 162/162.
    Mean is better than the old expanded-BF16 default (0.0013153) and
    slightly worse than the serial-prefill raw default (0.0011282); the
    delta is the WMMA prefill approximation - the same kernel family the
    plain published path uses in production. Top-1 and max are the best
    measured of any default.
  - Gate status unchanged: max and top-1 pass; mean/p95/p99 remain above
    the strict thresholds (pre-existing campaign state; the common-KV
    diagnostic attributes a substantial part of the mean excess to the
    hipEngine-BF16-KV vs teacher-F16-KV precision mismatch).
- Artifact: `benchmarks/results/2026-09-08-zbook-ud-u3-per-tensor-repack.json`.
