# Prefix reuse after a cancelled request, both cache modes and both MTP modes

## Summary

The last open readiness row is closed. `tests/test_live_int8_mtp_prefix_reuse_cancel.py`
runs both cache configurations and both MTP configurations inside each of them on
the INT8 KV cell, seeds a prefix boundary with one full request, reuses it with a
second request, and cancels that request mid-generation twice per arm. **2
passed**, 61 s and 64 s.

What the arms assert, all of it measured:

- the response's own `FinishDetails(reason="cancelled")`, so the cancellation is
  the engine's and not just a short generation;
- `reused_tokens: 512` for the reuse against a 256-token floor, and no reuse at
  all in the cache-off control;
- the pool's `current_pages`, `refcounted_pages` and `pinned_pages` plus
  `active_allocations` back on the seeded baseline after each cancellation;
- the same prompt reproducing the seed's exact ids afterwards, so the prefix the
  cancellation interrupted is intact.

## Scope, and why the arms are where they are

Prefix reuse is an engine mechanism: `HIPENGINE_PREFIX_CACHE` is read by
`engine_loop.py` and `server/__main__.py`, while `dms_metadata_path` is read by
the resident session. The two never meet in one harness, so this row is covered
at the engine surface -- where a request can be cancelled after its prefix was
reused -- and the DMS store trace stays with the lifecycle arms, which abort a
cycle on a resident DMS row and compare the store.

Three surface details cost a diagnosis each and are recorded in the test and the
row:

- A cancelled speculative **stream** on this path ends without publishing its
  terminal chunk, so the engine's cancellation is not observable there. The arms
  use a timer-driven cancel against a **blocking** request, whose finish details
  carry it. The streamed run does show the request stopping at two tokens against
  a 48-token limit, so the cancellation itself always landed; only the report was
  missing.
- The DMS parity gate's cases are bare content tokens repeated to a fixed length.
  Through the engine surface those stop on the first token, which would seed
  nothing to reuse, so the prompt here is text the engine renders and tokenizes.
- The shared conftest restores the kernel table to its collection-time baseline
  after every test, and this backend's package is imported lazily after that, so
  from the second case on the execution-profile plan cannot resolve its own keys.
  The file imports once and restores the resulting table before every case, the
  same guard the DMS parity file uses.
