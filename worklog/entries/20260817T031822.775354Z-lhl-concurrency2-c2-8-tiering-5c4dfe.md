# Add C2-8 optional cold tier composition

## Summary

Implemented optional host/NVMe cold tiering as a `KVCacheBackend` composition. Cold objects always restore into the compatible hot backend before attention; no cold codec becomes an attention dtype and no request scheduler is forked.

## Changes

- Added complete `ColdObjectKey` identity over hot backend/artifact/generation/codec, cold codec, token digest, request scope, and state fingerprint.
- Added deterministic checksummed `kvtc_zlib_v1` encode/restore with corruption and key mismatch rejection.
- Added bounded `ColdTierStore` with host/NVMe placement, atomic NVMe replace, tenant quotas, explicit pin-aware LRU, deterministic access ordering, deletion, and conservation.
- Added `TieredKVCacheBackend` delegation for all hot execution plus backend-declared offload/restore/evict maintenance work and separate host/NVMe cache + transfer-workspace ledger pools.
- Offload persists cold bytes before hot reclaim; restore reserves/imports hot state before deleting cold ownership; callback failure reclaims hot and leaves cold intact.
- Added final drain and restore-vs-recompute economics helper/gate. Tiering remains default-off.

## Validation

- Tier codec/key/store/NVMe/quota/LRU/offload/restore/failure/drain/economics plus DMS/global/ledger/token-budget bundle — 94 passed.
- Synthetic 1 MiB host gate: encoded 2,839 bytes (non-representative repeated payload); median restore 1.203 ms versus 8.967 ms recompute proxy; offload/restore/final drain pass.
- Ruff, compileall, JSON, diff, and common lifecycle checks pass.
- Evidence: `benchmarks/results/2026-08-17-concurrency2-c2-8-tier-host-accepted.json`.
