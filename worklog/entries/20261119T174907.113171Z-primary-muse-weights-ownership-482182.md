# Preserve Muse device allocations through teardown

## Summary

Found two Muse Glimmer lifetime defects while investigating GPU memory exhaustion in GitHub #14. The target and drafter lost allocation records, and the resident session left verify-graph buffers allocated after close. The bounded replay verifies both repairs, not the cause of every failure in the original run.

## Changes

- Keep every uploaded allocation in its owner's cleanup map under its tensor allocation name. Initialize the drafter map before loading so partial uploads are freed on failure.
- Retire decode and verify graph executables and streams before releasing their backing buffers. Reuse the verify stream across captures and release the temporary graph even if instantiation fails. No kernel arithmetic changes.

## Validation

- Four allocation-ownership regressions failed before the loader repair; the graph teardown regression failed before the session repair. `uv run pytest tests/test_unit_muse_glimmer_loading.py tests/test_unit_muse_glimmer_prefix_reuse.py -q -o addopts='' --tb=short`: 20 passed after both fixes.
- On gfx1151, ran `uv run pytest tests/test_live_muse_glimmer_dflash_exactness.py tests/test_live_muse_glimmer_dflash_gpu.py tests/test_live_muse_glimmer_exact_rows.py -p muse_ownership -v -s -o addopts='' --tb=short` with a temporary module teardown fixture on `PYTHONPATH=/tmp/main-suite-tools`. All 34 passed, including the public LLM speculative request and the exact-row fixture that first hit OOM in the full run. Each module finished with zero active allocations and zero bytes in hipEngine's allocation tracker. HIP-reported free memory did not return to its exact starting value; those counters include different scopes. Log: `/tmp/issue14-muse-live-final.txt`.
- Compileall, fixture checks, and registry, CPU-fixture, and smoke-add-plan checks passed.
