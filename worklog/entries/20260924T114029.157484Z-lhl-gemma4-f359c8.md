# Gemma 4 compact Q5_1 down GEMV kernel + registry-driven FFN alignment (iteration 16)

## Summary

Landed steps (b) and (c) of the follow-on order recorded in
`20260924T111851.082630Z-lhl-gemma4-f98888.md`: the compact selected
down-GEMV decode kernel for raw Q5_1 (the quant of Gemma 4's
`ffn_down_exps` tensors) and a registry-driven rewire of the c1 compact
route's FFN-alignment guard, so gemma4's MoE decode can compact-route at
ffn=704 while wide-block down quants keep their per-layer legacy fallback.
The four stacked gates from that entry now read: (1) C1-vs-retained default
decision — still the lead's, with a runnable candidate now in tree;
(2) Q5_1 down kernel — done this iteration; (3) ffn=704 alignment guard —
done, with the guard reading declared per-quant alignment instead of a
blanket `% 256`, validated at the gemma4 geometry on GPU; (4) unreachable
retained route — unchanged fact, gemma4 runs raw legacy kernels by
capability until (1) is decided.

The default path is untouched this iteration: compact remains behind
`HIPENGINE_GGUF_GEMV_DECODE` + `HIPENGINE_GGUF_COMPACT_MOE_C1`, and the
single Q5_K straggler layer (blk.29) falls back per layer by capability.
