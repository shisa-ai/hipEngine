# Layers 16-47 is the deepest certified Q8 WMMA dense prefill scope

## Summary

The f16 WMMA dense Q8_0 prefill route passes the full calibrated envelope at
layers **16-47**, moving the certified boundary four layers deeper than 20-47.
The arm is `measurement_valid: true` with no qualification blockers, no scope
failures, `hard_gates_passed` and `eligible_for_automatic_admission` both true,
and three identical trajectory hashes.

| Metric | Value | Limit | Headroom |
| --- | ---: | ---: | ---: |
| Mean KL | 3.796e-4 | 1e-3 | 2.6x |
| p95 KL | 1.762e-3 | 5e-3 | 2.8x |
| p99 KL | 5.424e-3 | 2e-2 | 3.7x |
| Max KL | 1.530e-2 | 5e-2 | 3.3x |
| Top-1 | 1538/1548 = 0.99354 | 0.99 | pass |

All ten top-1 misses are inside the 154-row flip-eligible set and none outside
it, the same pattern as the 20-47 arm. The deepest certified scope is now 16-47;
20-47, 28-47 and 32-47 remain certified and 0-47 still fails the mean and p95
limits on `code` alone.

**The screen overestimated the full arm by 1.8x** (`6.728e-4` against
`3.796e-4`), the second deep-scope control point to do so after 20-47's `0.507`.
`docs/EXECUTION-PROFILES.md` 6.4 now carries four control points and the
`0.50`-`1.20` interval's low end rests on two independent scopes.

**The saving is not measured.** This gate records no timing
(`timing_protocol: none_full_logits_only_v1`), so the byte-share interpolation of
~+4.42 s at 16-47 remains a prediction. Only 32-47 (+2.436 s) and 0-47
(+7.041 s) have measured time in this campaign; every deeper figure is
`7.0409 s x owned byte share`. Two arms remain below 16-47 (12-47, 8-47), both
screen-inconclusive, worth about +0.5 s of *predicted* gain between them.

### Two killed attempts, and what actually caused them

The arm was attempted three times. The first two died before writing an
artifact. Neither was the route or the harness memory guard:

1. `OSError: libamdhip64.so: cannot open shared object file` at generator
   construction. The gate loads the runtime by bare soname and needs the TheRock
   `LD_LIBRARY_PATH`. The recorded provenance carries `HIPENGINE_HIP_ARCH` but
   not `LD_LIBRARY_PATH`, so this is not recoverable from an artifact. The
   protocol section of the gate README now carries the host setup.
2. `--require-cached-build` (added by me, **not** part of this gate's protocol)
   failed closed on `gguf_q6_k_embedding-975923c3c2d602b2`. The flag is not in
   the recorded command of any committed arm, and it fails on any kernel not
   built under the current environment's cache key. Dropped; compiling on demand
   with the same `hipcc` produces the same kernels.

The third attempt ran to completion in about 14 minutes of evaluation on a
quiet host with swap and `/tmp` cleared.

### Provenance

The run's own provenance is the cleanest test of the documentation-only
exemption so far: `execution_affecting_dirty` is **false** while `dirty` is
**true**, because the only modified paths were `docs/*` and a
`benchmarks/results/*/README.md`. Those edits were made deliberately while the
arm was in flight, which is exactly the case the rule is meant to permit.
