# ud-quants U0 shared policy API and v2 audit accounting

## Summary

Completed the remaining code-side UD-U0 requirements of docs/UD-QUANTS.md:
backend capability resolution for the quant-route audit now goes through one
pure shared policy API (`hipengine/loading/qwen35_gguf_policy.py`) used by both
the runtime loader and the audit, replacing the audit's regex/quoted-substring
mirror and its local raw-IQ predicate copy; the per-slot fallback planner now
applies the model-wide F32 contraction exactly like the production AR planner;
the audit reports allocation-formula requested weight bytes with sidecar
reasons and both hypothetical refusal treatments per scope; and the report
carries `schema_version` 2 with per-file header identity. No GPU work, no
kernel changes, no runtime semantic changes (production refactors are exact
extractions; defaults unchanged).

## Changes

- NEW `hipengine/loading/qwen35_gguf_policy.py`: pure, cold-path, backend-import-free
  policy module. `resolve_gguf_dense_flags(backend, file_type_name,
  capability_reader, environ)` is the single home of the dense-capability +
  environment-override semantics (`HIPENGINE_GGUF_C8_Q5_RAW_MMQ` default-on,
  `HIPENGINE_C8_Q5_PLANAR_DP4A` default-off, qmicro file-type stamp gating,
  planar-Q6 excluded slots); `gguf_ar_raw_iq_contract` is the production
  raw-IQ predicate (IQ2_XS/IQ3_XXS/IQ4_XS over AR layer types);
  `gguf_fp16_recurrent_state_default` mirrors the runner's normalized
  file-type membership for backend defaults. `GGUF_DENSE_CAPABILITY_NAMES`
  enumerates every constant the policy consumes (12 names, including
  `GGUF_C8_Q5_RAW_MMQ_SSM_OUT` and
  `GGUF_DENSE_Q6_T16_QMICRO_PLANAR_EXCLUDED_SLOTS` the old audit missed).
- `hipengine/loading/qwen35_gguf_materialize.py`: exact extraction refactors —
  `plan_qwen35_gguf_materialization` now derives `contract_q3_f32_linear` from
  the shared predicate; `materialize_qwen35_gguf_weights` resolves its dense
  flags via `resolve_gguf_dense_flags(..., capability_reader=backend_package_capability,
  environ=os.environ)` (identical semantics: case-sensitive file-type
  membership, env defaults, excluded-slot tuple); `plan_qwen35_gguf_weight_spec`
  gained a default-off `contract_f32_linear` passthrough so per-slot planning
  can carry the model-wide contraction (NextN callers unchanged).
- `scripts/gguf_quant_route_audit.py`:
  - Bounded AST literal reader (`backend_source_assignments`,
    `source_capability_reader`, `capability_status`) replaces the regex
    mirror; handles the `frozenset({...})`/`set`/`tuple`/`list` wrapper-call
    forms the backends actually use; missing/nonliteral constants are reported
    per capability and resolve to the runtime default (never guessed, never
    evaluated, no backend import).
  - `plan()` resolves flags through the shared API; per-slot fallback passes
    `contract_f32_linear` from the shared raw-IQ predicate; NextN scopes keep
    exactly the four production NextN flags (AR policies not applied to the
    draft); `f32_contraction_applied` replaced by counted
    `f32_contracted_slots`; `capability_status` reported per backend.
  - New `_allocation_account` per planner scope (AR, nextn own, nextn
    fallback): unique `(source, layout)` residents sized by
    `planned_qwen35_gguf_weight_allocation_nbytes` (production formula, incl.
    pack8/qweight/scales/mins/T16/planar), sidecar records beyond each
    layout's base allocations aggregated with reasons, refused tensors deduped
    by physical source into both hypothetical treatments
    (native-refusal lower bound = accepted + compressed source bytes;
    BF16-refusal scenario = accepted + 2*elements), and an explicit
    `formula_unavailable_residents` list for layouts the production formula
    cannot size (the optional planar-Q5 sidecar today) — bytes are never
    invented and refusals never silently omitted.
  - `_header_identity`: SHA256 over raw file bytes `[0, data_start)` as
    established by production `scan_gguf` (magic+version+metadata+descriptor
    table+alignment padding; excludes payload bytes); withheld with an
    explicit note when the payload boundary is unknown.
  - Report `schema_version: 2` + `schema_notes` (v1 was the implicit schema of
    docs/UD-QUANTS-REVIEW.json); `--check-constants` gate rewritten over the
    AST reader (fails when a capability name is missing from every backend).
- Tests: NEW `tests/test_loading_qwen35_gguf_policy.py` (pure resolution,
  env-override truth tables, case-sensitive stamp gating, contraction
  predicate); NEW `tests/test_qwen35_gguf_policy_capability_parity.py`
  (HIP-guarded cross-caller parity: source reader vs backend_package_capability
  for both backends x three file types — skipped on no-ROCm hosts);
  `tests/test_scripts_gguf_quant_route_audit.py` rewrote the three legacy
  capability guards against the AST reader + shared API and added the UD-U0c
  RED suite: gfx1100 Q5 raw-MMQ sidecar (and gfx1151 absence), gfx1151
  planar-Q6 attn_qkv exclusion (and gfx1100 contrast), F32 contraction in both
  production-planner and per-slot-fallback modes (112 contracted slots on the
  synthetic raw-IQ fixture), env overrides (repack/raw-mmq/planar), allocation
  accounting with hand-computed pack8/refusal bytes (49,152 / 28,160 /
  131,072), schema_version + header identity (incl. withheld case),
  capability-path import purity, and the check-constants gate.

## Limitations

- Cross-caller parity tests are HIP-guarded and were SKIPPED on this session
  host (no `libamdhip64.so`); they must run on a ROCm host. Source-reader
  values were validated against pins read from the real backend sources.
- Importing any `hipengine.loading.*` module transitively loads
  `hipengine.kernels.hip_gfx1100` via the engine root `__init__` (pre-existing
  on committed HEAD, verified by stash probe). The audit's own
  capability/policy path adds no backend-package imports (guarded); recorded
  as residual cold-path import debt in docs/REFACTOR.md rather than fixed
  here (engine root packaging is out of U0 scope).
- The audit no longer carries any policy mirror; the source reader is a
  bounded literal reader, so a future backend constant written as a computed
  expression degrades to the runtime default with a visible "nonliteral"
  status instead of being guessed.
