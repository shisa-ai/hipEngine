# Compare Y3 direct and pair ISA

## Summary

Compared generated direct and retained-pair shared4r6 code to determine whether
pair decode removed qmicro operations or only changed work scheduling.

## Changes

- Published code size, resource metadata, and static decode-region instruction
  classes for both specializations.

## Validation

Both bodies use VGPR198, LDS16 KiB, and scratch0. Pair adds two SGPR and expands
code 50,376->51,440 bytes. Its static decode body doubles record loads, stores,
converts, and mix-FMAs because the inner `pair_col` loop repeats complete
per-column work. Pair therefore wins by halving scheduling units, not by sharing
record-byte operations.

## Next

- Specialize pair decode to load each qmicro low byte once, extract both
  nibbles, and share record/base address calculation while preserving separate
  scales, exact LDS values, and unchanged WMMA accumulation.
