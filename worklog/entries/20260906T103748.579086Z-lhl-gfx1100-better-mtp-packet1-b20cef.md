# Packet 1: staged-cycle attribution for C8/K3, C2/K2, C5/K3, C3/K3

## Summary

Profiled the four better-MTP cells through the specdec2 bridge (final-leaf
mode, rocprofv3 kernel+marker+hip-runtime+copy+allocation traces) and
attributed the staged-cycle walls to named stages and kernel families.
Headline: the C5/K3 screening deficit vs AR is concentrated in the
verify-GEMV family — the width-5 verify batch pays ~58 ms/cycle in
`rowtile16_w2_grouped_gemv` vs ~33 ms/cycle at width 3 and ~30 ms/cycle at
width 8 — while the MoE q6-k planar-prefill family is width-flat
(~50–58 ms/cycle everywhere). This is a kernel-dispatch tile-shape gap for
mid-width verify batches, not an MTP-logic cost.

- `scripts/specdec2_perf_bridge.py`: added `--diagnostic-plan`, which attaches

## Measured (single train prompt, D24 greedy outputs capped at 12 tokens,
one measured arm per cell after warmup, W7900 gfx1100, Q4_K_M)

Arm-complete windows, profiled runs (unprofiled baselines in parentheses):

| cell | MTP arm | AR arm | MTP/AR |
| --- | --- | --- | --- |
| C8/K3 | 1.258 s (1.240) | 1.273 s (1.242) | ~parity |
| C2/K2 | 0.692 s (0.669) | 0.662 s (0.639) | +4.7% slower |
| C5/K3 | 1.031 s (0.998) | 0.935 s (0.902) | +10.3% slower |
| C3/K3 | 0.771 s (0.748) | 0.763 s (0.731) | +2.3% slower |

These are 12-token attribution runs, not the retained suite ratios; the
one-time prompt prefill + NextN prime is inside every arm window.

Stage attribution inside the MTP arm (marker-range sums, measured window):

- Cycle (verify/commit) marker span: C2/K2 0.349 s / 3 cycles (0.116 s per
  cycle); C3/K3 0.422 s / 3 (0.141); C5/K3 0.560 s / 3 (0.187); C8/K3 0.383 s /
  2 (0.192) plus a 0.217 s residual AR-decode tail (straggler rows finish via
  AR ticks at C8; ~0 at the other cells).
- Width-5 cycles cost the same as width-8 cycles (0.187 vs 0.192 s) while
  producing fewer tokens per cycle: consistent with capacity-padded frontier
  execution (5 live rows run the 8-row-shaped verify graph at capacity 8).
- Cycle-scoped kernel families (busy ms over the measured cycles):
  `q6_k_t16_qmicro_planar_wmma_prefill_bf16` is width-flat (C2 151, C3 155,
  C5 175, C8 116 over 3/3/3/2 cycles). The verify-GEMV family
  (`q4_k_t16_dense_rowtile16_w2_grouped_gemv`, ~288 calls/cycle everywhere)
  is the width-sensitive term: C2/K2 58 ms (plain `_gemv` variant), C3/K3
  98 ms, C5/K3 174 ms, C8/K3 60 ms over 3 cycles (plus fused dual variants).
  Width 5 (5×4 = 20 verify rows) lands in a bad tile configuration.
- NextN prompt prime: C8 0.264 s vs C5 0.087 s / C3 0.068 s / C2 0.064 s
  (superlinear in group width at the one 8-row observation).
