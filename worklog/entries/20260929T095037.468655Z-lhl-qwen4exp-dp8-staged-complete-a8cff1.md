# All six dense Q8_0 tensors: staged-f32 best in 30/30, rel L2 4.6e-07

## Summary

The dense-family measurement is complete: **all six Q8_0 dense projections of a
layer step**, five layers each, at rows=1024. The staged-f32 tile is the fastest
variant in the sweep at **30/30 (layer, tensor) cases**, and the relative-error
figure the earlier packets flagged as missing is now measured.

| tensor | shape (out x in) | leaf ms | staged ms | speedup | time | rel L2 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| attn_qkv | 10240x2560 | 16.1753 | 13.1121 | 1.2336x | -18.94% | - |
| attn_gate | 6144x2560 | 9.8217 | 7.3819 | 1.3305x | -24.84% | - |
| ssm_out | 2560x6144 | 9.2511 | 7.2360 | 1.2785x | -21.78% | - |
| ffn_gate_shexp | 640x2560 | 1.0028 | 0.7251 | 1.3830x | -27.70% | 9.116e-07 |
| ffn_up_shexp | 640x2560 | 1.0060 | 0.7217 | 1.3939x | -28.26% | 9.134e-07 |
| ffn_down_shexp | 2560x640 | 1.6486 | 0.7440 | **2.2158x** | **-54.87%** | 4.622e-07 |
| **total** | | **38.9055** | **29.9208** | **1.3003x** | **-23.09%** | |

Two things stand out.

**ffn_down_shexp at 2.22x.** The leaf costs 1.65 ms there for the same 3.36 GFLOP
it does in 1.00 ms on the K=2560/N=640 shapes. The K=640/N=2560 geometry is the
leaf's worst case and the staged tile is insensitive to it.

**The relative error is 4.622e-07 to 9.134e-07**, i.e. 4-8 f32 ulp
(eps = 1.19e-07). That is f32 accumulation-order magnitude. The f16 WMMA sibling
route measures relative L2 4.709e-05 on the GR shape - roughly **50-100x worse**.
This converts the earlier "consistent with summation-order drift, but no relative
bound was computed" caveat into a measured one.

## Changes

- `scripts/qwen4exp_dense_projection_ab.py`: added
  `relative_l2_vs_production` and `max_relative_to_peak_vs_production` to each
  result entry, computed in float64. The harness previously recorded only an
  absolute difference, which cannot by itself separate f32 summation-order drift
  from f16 operand rounding.
- `benchmarks/results/2026-09-29-dp8-staged-f32-dense-family/`: three new run
  artifacts (`ffn_gate_shexp`, `ffn_up_shexp`, `ffn_down_shexp`),
  `family.json` extended to all six tensors, and the README rewritten.
- `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md` and `benchmarks/CHANGELOG.md`: updated.

No engine change, no registration, no default change.

## Validation

Three runs of the same command shape as before:

```
scripts/qwen4exp_dense_projection_ab.py --model-root <UD-Q4_K_XL dir> \
  --tensor-suffix ffn_gate_shexp.weight --in-features 2560 --out-features 640 \
  --rows 1024 --repetitions 5 --output /tmp/dp8-ffn_gate_shexp.weight.json
```

and likewise for `ffn_up_shexp.weight 2560 640` and
`ffn_down_shexp.weight 640 2560`. All figures are means over layers
0/9/22/34/46 and are computed against
`coltile8_rowbatch4_wave_scale_pipelined_f32_f32_out`, the leaf the engine
actually selects.

Host: Radeon 8060S (gfx1151), machine-id `55ea6c509d0b49eea8de7094a1023668`,
ROCm 10.0.0, TheRock staging `therock10-staging-20260828`.

Two self-caught errors, both fixed before commit:

1. The first assembly of the summary table rounded the relative error to three
   decimals, which turned 9.1e-07 into 0.0. `family.json` now stores the raw
   float.
2. An early version of the "best variant" tally selected the **slowest** variant
   per case (`max` over `-1/ms`) and reported 0/5 everywhere. Corrected to
   `min` over `ms`; the 30/30 claim is from the corrected tally.

## Next

**The prefill share remains underivable, and the full six-tensor data makes that
concrete rather than provisional.** The six tensors total 38.9055 ms per layer
step; the attribution puts the whole `dense_projection` family at 4553.007 ms
and the anchor splits it into 3262.5 ms at layers 0-15 and 1404.2 ms at 16-47.
`4553.007 / 38.906 = 117` and `3262.5 / 38.906 = 84`; neither matches 16, 48 or
192 layer-steps. Until the per-step multiplicity or row count of the profiled
forward pass is established, **no prefill-wide number should be quoted**, and the
earlier ~6.8% figure stays withdrawn.

Remaining before promotion:

1. **Re-run the first three suffixes** to fill their `relative_l2` field. Cheap,
   and it would make the packet uniform. The three measured values span only a
   factor of two, so this is unlikely to change any conclusion.
2. **Natural activations.** The synthetic standard-normal control is correct for
   comparing variants on identical operands; it is not a real activation range.
3. **The production gate** (`docs/EXECUTION-PROFILES.md`) plus a registered
   strict fallback. The output is not bit-identical, so this is not a strict
   promotion. Not run.
