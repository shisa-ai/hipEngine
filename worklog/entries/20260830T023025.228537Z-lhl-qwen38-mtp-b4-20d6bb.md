# Close adaptive-K and B4 reopen on exact raw oracle

## Summary

The verifier-rowtile prerequisite for parity P4.3 is satisfied, so B4 received
its predeclared fixed-policy oracle. The first attempt exposed the exact B4
clamp: proposal-history/graph capacity stops at B3 and rows5 target verification
falls to `serial_exact` (**7.936→29.116 s target verify**, B4 7.381 tok/s).

With temporary oracle-only B4 capacity, native R5, neighboring production Q4 R5
rowtiles, and the **exact canonical raw prompt rendering**, fixed B4 becomes
competitive but fails binding scopes:

- full **27.575→28.826 tok/s (+4.53%)**;
- train **+9.63%**;
- heldout **-2.81%**;
- code **+11.03%**, general English **-9.82%**, Japanese **+6.31%**, mixed
  **+4.98%**.

B4 improves visible transitions/cycle **3.239→3.651 (+12.70%)** and cuts cycles
71→63, but acceptance falls 77.94%→71.98% and proposal cost rises 9.95%.
Under E3, fixed K4 must win full/train/heldout/every category before adaptive K
is considered. It does not, so adaptive is not opened and fixed K3 remains.
All temporary capacity/clamp/R5 policy changes are removed.

## Changes

- Temporarily extend NextN proposal-history/graph capacity from B3 to B4.
- Temporarily allow native target rows5 and production Q4 R5 rowtiles.
- Add an oracle wrapper that encodes the exact frozen raw rendered strings
  directly; the stock reasoning-off rendering is 40 vs 36 tokens on the first
  prompt and is not used for the decision.
- Remove all temporary code after measurement; add only durable artifact/docs.

## Validation

- All ten raw canonical/heldout prompts complete at B3 and B4 with exact
  generated IDs.
- Stage ledgers reconcile exactly for both budgets.
- Full/train/heldout/category results are reported separately; no favorable
  category subset is used for policy.
- No adaptive/category/content selector is implemented. Category-dependent K
  would violate anti-gaming and the request-owned content-agnostic policy rule.
