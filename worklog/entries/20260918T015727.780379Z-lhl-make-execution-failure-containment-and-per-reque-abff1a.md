# Make execution-failure containment and per-request eligibility normative

## Summary

The 2026-09-17 architecture review (worklog/entries/20260917T172827.054150Z-lhl-mtp-failure-isolation-review-27cbb4.md)
found two control-plane gaps that `docs/EXECUTION-PROFILES.md` did not name:
an exception escaping shared model execution closed the whole service, and a
row-local refusal could downgrade its peers. The containment repair landed as
`ad77b625b`, but the normative document still described only successful
execution, so a profile claim had no stated obligation to contain a fault or to
keep per-request eligibility independent of group decisions.

This entry makes both contracts normative in section 4 ("What is exact in every
profile"), where control-plane exactness already lives. It is a policy
clarification of an implemented contract plus one declared gap; no runtime code
changed.

## Changes

- `docs/EXECUTION-PROFILES.md`
  - Section 1 now states that failure belongs to the first property
    (semantic/control correctness), not to a separate concern.
  - Section 4's exactness table gains "Failure containment" and "Per-request
    eligibility" rows.
  - New section 4.3 defines containment: the quiescence and reclaimability
    proof a runner must return before it may end one request and keep serving;
    the `none`/`partial`/`committed`/`unknown` mutation classes; that naming a
    narrower scope asserts the unnamed rows of the failed work item still hold
    canonical state; that a scope naming rows outside the failed work item is
    refused; the classes that must stay fatal; the observability and diagnostic
    requirements; the survivor requirement; and the coverage a containment claim
    needs. It names the implemented scope (resident GGUF runner, `none` only,
    prefill/decode, after per-row device synchronization) and states that no
    runner claims `partial`/`committed`/`unknown` yet.
  - New section 4.4 defines per-request eligibility under group execution and
    records the current gap: a group-level resource-claim miss still downgrades
    every row and replaces each row's own reason
    (`hipengine/generation/engine_loop.py:2811`).
  - Section 10 gains rejection items 10 and 11 for the two contracts.
  - The status line now distinguishes implemented pre-device containment from
    the pending wider classes and partitioning.
- `docs/CONCURRENCY.md` Gate 3 gains the containment scenarios (a failing row
  with surviving neighbors, a request admitted after a contained failure, the
  refusal path) and points at sections 4.3/4.4 for the normative text.
- `AGENTS.md` key-files row for `docs/EXECUTION-PROFILES.md` now names
  failure-containment semantics.

## Validation

Docs-only change; verification is a full re-read of the changed sections, not a
GPU run. Every factual claim was checked against the implementation:

- `hipengine/generation/engine_loop.py` `ExecutionFailure` (mutation vocabulary,
  the narrower-scope assertion) and the scope check that refuses rows outside
  the failed work item; `GenerationExecutionFailed` reporting
  phase/request_ids/work_kind/state_mutation/cause.
- `hipengine/generation/qwen35_gguf.py` `contain_execution_failure` and
  `_quiesce_after_execution_failure`: `none` only, prefill/decode only,
  `HipError` and unreachable/ failing runtimes stay fatal.
- `hipengine/generation/engine_service.py` `health()` ok/unhealthy/closed with
  phase and deepest frame, and `_closed_service_error()` explaining a refusal.
- `hipengine/server/api.py` readiness reporting `status: unhealthy`,
  `ready: false`, diagnostics naming the exception and location, and
  `_execution_failed_error` returning the request-scoped 500 with
  `hipengine.execution` fields.
- `hipengine/generation/engine_loop.py:2811` replanning with `claims_fit=False`
  after a group claim miss, which is the recorded gap in 4.4.

`tests/test_unit_generation_execution_failure_containment.py` (13 tests) already
covers the contained prefill/decode, packed-group, fatal, refused-scope and
unproven-recovery paths; no test parses these documents, so no test changed.

## Next

  improvement.
