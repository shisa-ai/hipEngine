# C8 iter33: grouped dp4a kernel — 9/9 leaf wins at R8-R32, default-off pending L4

## Summary

Implemented the grouped q8_1 DP4A planar-Q6 kernel named by iterations 31-32
and screened it at production row counts on actual Qwen3.8 weights. The new
kernel merges the registered rows 1-4 dp4a decode body (integer dp4a, u32
record loads, per-group d/scale) with the grouped-R8 row-group grid
(grid.y = rows/8, ROW_TILE 8) and its wave-reduce + cross-warp xchg
epilogue. Leaf A/B against the dispatched BF16 owners (grouped-R8 at
rows ≥ 16, rowtile col8 at rows = 8), q8_1 quantize launch included:
**dp4a wins 9/9** — FFN-down 0.7529–0.7837× (1.28–1.33× faster),
recurrent-QKV 0.7662–0.7977×, attention-V 0.9368–0.9982× (launch-bound).
At R32 the 30.353 ms/cycle grouped-R8 pool projects to ~25.2 ms/cycle
(~17%); projection from leaf medians, not a measured e2e claim.

## Implementation notes

- The first build had a real bug the RED test caught: the epilogue copied
  the owner's xchg cross-warp sum but omitted the `GGUF_T16_WAVE_REDUCE`
  pass, so only the 4 wave-lane-0 partials survived (99.5% element
  mismatch vs the q8 oracle). Localized by A/B-ing against the registered
  rows 1-4 dp4a kernel on identical inputs, fixed by adding the wave
  reduce, and locked by the new test file.
- Kernel contracts
  (`tests/test_gguf_q6_k_t16_planar_q8_1_grouped_gemv.py`): q8-quantized
  CPU oracle rtol 2e-2, exact-oracle KL ≤ 0.05 + top-1 ≥ 0.90 outer floor,
  run-to-run determinism, registry resolution, wrapper row validation —
  all green at rows 8/16/32.
- Arithmetic class: **changed** (x → q8_1 activation quantization;
  15,954–234,724 element mismatches vs the BF16 owner at the leaf shapes,
  informational KL recorded). The BF16 grouped-R8 owner remains the
  dispatch default and the registered strict fallback; the dp4a variant is
  registered opt-in and default-off by construction (nothing dispatches
  it). A `docs/REFACTOR.md` entry records the removal condition.
