# Freeze AGENTIC-QUALITY2 v1 evaluation suite

## Summary

Froze `agentic-quality2-v2` before any model or candidate implementation. V1
was superseded during fake-endpoint validation because its schema-invalid detail
reason and reasoning-leak raw text were mis-specified; v2 corrects only those two
controls. It contains 34 independent
one-turn task blocks split evenly into 17 development and 17 heldout rows. Four
families each have both splits: tool selection (5/5), repository (4/4), Python
code (4/4), and instruction following (4/4). Twelve heldout rows are Japanese or
mixed Japanese/English, and five heldout rows are patch or generated-code
executable tasks. Ten separate fail-safe controls cover malformed, truncated,
duplicate, undeclared, schema-invalid, content/reasoning leakage, required-tool
missing, ambiguous required selection, and `tool_choice=none` violation.

The suite is project-original under the repository's AGPL license. Exact public
revisions and licenses were audited for BFCL (Apache-2.0), HumanEval (MIT), MBPP
(CC-BY-4.0), and IFEval (Apache-2.0). HumanEval and MBPP have read-only ZBook
copies under `/home/lhl/omlx`; BFCL and IFEval are absent. No upstream prompt,
solution, assertion, expected value, test, or evaluator byte was copied or
adapted, and no official upstream score is claimed. The public datasets supply
only conceptual labels for function calling, pure-function execution, and
behavioral instruction checks.

Expected result hashes, patch replacement text, reference results, and hidden
code inputs/outputs are isolated in the oracle file and never rendered into
prompts. Machine-readable instruction checks mirror public request constraints
but contain no reference response. Expected code source and exact response prose
are not stored. AQ4 did not execute generated code, run a model, inspect heldout
output, or admit a mechanism.

## Validation

- All six files parse as JSON; all three fixtures pass their Draft 2020-12
  schemas.
- Exact hash references form `suite -> oracle/source` and `oracle -> source`.
- Mechanical audit confirms 34 unique workload/case IDs; exactly 17/17 split;
  no overlap; all split manifests equal workload membership; 5/5, 4/4, 4/4,
  and 4/4 family distribution; 12 non-English heldout rows; five heldout
  patch/code rows; eight code cases with >=4 hidden cases; eight instruction
  cases; and ten unique fail-safe controls spanning every declared class.
- Every task points to exactly one same-split oracle case and every oracle case
  points back to one task. Tool and argument shapes satisfy the frozen tool
  declarations at schema scope.
- Prompt audit rejects oracle hashes, hidden code outputs, patch replacement
  text, reference result objects, expected source/prose, and exact serialized
  checker objects; public instruction constraints remain visible by design.
- The source record pins selection, authorship, serialization, hash method,
  license URLs, revisions, and local availability.
- Suite card is re-read end-to-end; local links, JSON Schema, Worklog2,
  benchmark sync, and diff checks pass before commit.
