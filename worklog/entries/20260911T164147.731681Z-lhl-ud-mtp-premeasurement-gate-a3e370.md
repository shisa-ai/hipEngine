# U6 pre-measurement gate closed: item 3 state disjointness measured, item 5 contract corrected to the production profile, paired run unblocked

## Summary

Two defects in the U6 unit from the previous turn are fixed, and the paired
measurement's gate now opens without weakening the pin.

**Defect 1 - the item-5 contract was the strict contract on a production
record.** The record declares `execution_profile="production"`, but item 5
required "greedy token IDs exactly equal to the true no-MTP AR denominator".
`docs/EXECUTION-PROFILES.md` section 6 states that free-running generated-ID
equality "is recorded but is not the denominator", and section 4.1 lists "logits
and generated IDs at near ties" as permitted production drift. The strict
contract was simply wrong for this profile, which is why the K_S near-tie read
as a failure. Item 5's contract is now the production control-plane contract
(exact acceptance and transaction accounting, GPU/CPU acceptance agreement,
deterministic repeats) with ID equality recorded but not binding.

**Defect 2 - gating the measurement on the whole unit was circular.** Items 5
and 6 can only be established *by* the paired run (its control/determinism
evidence and the envelope it measures), so requiring them before the run can
never be satisfied. Items now carry a `phase`:

- `pre_measurement` - structural and control items, verifiable without the run
  and required before it may start: residency/ownership, the blk.64 draft
  operation set, state ownership, and the UD journal requirement.
- `paired_run` - established by the run itself: control/determinism evidence
  and the backend/profile/context/width envelope.

`is_complete()` (the pin) still requires every item in both phases;
`measurement_ready()` requires only the pre-measurement items. Both UD records
are now `measurement_ready() == True` while `is_complete() == False`, so the
pin stays empty and the measurement can proceed.

**Item 3 is now measured, not asserted.** On the real objects the draft
executor's 62 device buffers are disjoint from the target session's 188 and from
the verifier journal's 381 (pointer-set intersection empty for both). The
verifier deliberately references the target session, so the check walks the
journal object separately rather than the verifier object.
