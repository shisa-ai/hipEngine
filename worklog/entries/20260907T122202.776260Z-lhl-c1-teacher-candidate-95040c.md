# Build teacher-driven packed target execution core

## Summary

Implement a CPU-tested packed target execution core driven by fixed teacher
windows. GPU integration and numerical measurements are pending.

## Changes

- Prefill the teacher prompt, execute only teacher input tokens in packed target
  windows, and preserve exact prompt/decode cursor boundaries for K1–K7.
- Require deferred scatter and unchanged canonical state before commit. Check
  returned request, physical slot, transaction and row ownership.
- Observe the actual head call and require a fresh full-logit path before
  copying logits. Restore instance hooks on both success and failure.
- Commit each full teacher window with the existing host-selected state helper.
  This measures target arithmetic in isolation; it does not exercise speculative
  provider decisions or the native device-accept transaction. Results explicitly
  record this distinction and never claim full profile qualification.

## Validation

- RED: test collection fails with the execution module absent. GREEN:
  `.venv/bin/python -m pytest -q -o addopts=''
  tests/test_qwen38_packed_c1_teacher_candidate.py
  tests/test_qwen38_packed_c1_teacher_fixture.py
  tests/test_qwen38_packed_c1_teacher.py` passes 78 CPU tests (0.89s).
- Sixteen execution tests cover all budgets, candidate predictions that differ
  from teacher inputs, stale/direct heads, canonical-state changes, commit cursor
  drift, wrong ownership/count/shape, nonfinite logits and hook restoration.
- No GPU execution yet. No runtime or dispatch edits; no performance claim.
