# the immediate eos was my probe not applying the chat template and the benches never exercise the text path

## Summary

`20260928T073254` reported an immediate-EOS defect and listed two candidate causes. It was
neither. **It was my probe's error**, and resolving it turned up something worth knowing
about the benchmark suite.

## The resolution

```
raw text         ->   6 chars  '\n<eos>'
chat-templated   -> 154 chars  "<thought\n</thought>The sky is blue because of a phenomenon
                               called Rayleigh scattering. When sunlight enters the Earth's "
```

Same artifact, same sampling parameters, same call. The only difference is the chat
template.

**An instruction-tuned model requires its chat template. Returning EOS for a raw prompt is
correct behaviour, not a defect.** I raised a false alarm by measuring through a path I had
not validated, and the engine was fine.

## Why it looked like a defect

The benchmark scripts do not take a text prompt at all. `gemma4_campaign_bench.py:484`:

```python
output = llm.generate_detailed(list(prompt_ids), params)[0]
```

**They pass raw token ids**, and the ids are synthetic (`range(1000, 1000 + n)`). So:

- tokenization is never exercised;
- the chat template is never applied;
- the text-generation path that a user actually reaches is not covered by them.

That is fine for what those benches measure -- kernel throughput does not care what the
token ids mean -- but it means **a green benchmark run says nothing about the text path**,
and it is why the failure was invisible to them.

**Corollary worth recording:** the route ablation's 28.29 tok/s decode figure is measured
on a synthetic token sequence, not a real prompt. Valid as a throughput measurement;
not a statement about generating anything meaningful.

## What this does and does not change

**Changes:** `20260928T073254`'s "immediate-EOS defect" is withdrawn. There is no engine
defect here.

**Does not change:** the MTP conclusion from that entry stands. `supports_speculative_mtp`
is still `False` for the Gemma 4 generator, and the drafter's measured acceptance (0.796,
mean 4.10 tokens/round) is unaffected.

**Also does not change:** the probe's missing token-count assertion. It printed 541.76
tok/s for a six-character generation, and it would still do so on a raw prompt. That flaw
is real and unfixed.
