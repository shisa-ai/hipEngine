# Gemma 4 long-row flash decode slicing

## Summary

Long-context decode trailed llama.cpp `45451c3` (0.93x at 64K, 0.94x at
128K). A W7900 kernel trace of a 65536-key step put 11.0 of 22.5 ms in the five
global layers' flash decode: 256 blocks (2 KV heads x 128 slices) each walking
~512 keys serially, about 61-122 GB/s. A slice sweep (patched policy, step
time) found one slice per 128 keys capped at 1024 best from 32K up and harmful
at 8K (more slices at 8192 keys: 13.9 -> 16+ ms), so the new variant
`gemma4_flash_long` uses max(default, min(1024, ceil(keys/128))), which equals
the default through 8192 keys. The gfx1100 production plan selects it; gfx1151
and strict are untouched. Public-path decode 54.12 -> 58.80 (32K), 41.67 ->
48.69 (64K), 32.79 -> 36.02 (128K), ids equal; decode now leads llama.cpp at
every ladder length.

## Changes

- `gemma4_attention.py`: `FLASH_LONG_ROW_KEYS_PER_SLICE = 128`,
  `FLASH_LONG_ROW_MAX_SLICES = 1024`, `flash_long_row_slices`,
  `flash_request_slices(long_rows=)`, `_launch_prefill(long_rows=)`, shared
  `_decode_flash_bf16` body with `gemma4_attention_decode_flash_bf16` and
  `gemma4_attention_decode_flash_long_bf16`, `DECODE_ATTENTION_FLASH_LONG`.
- `gemma4_layer.py`: the decode selector treats the long variant like
  `gemma4_flash` and resolves the plan's own launcher.
- `gemma4_decode_graph.py`: reservation passes `long_rows`; a capture refuses a
  bucket where the long count departs from the device-side partition rule
  (above 8192 keys), since a replay would walk longer slices than its LDS was
  sized for. gfx1100's capture window is empty.
- `gemma4_profiles.py`: registration and the gfx1100 production selection.
- `scripts/gemma4_public_route_probe.py`: names the long variant.
- Tests: selection, policy values, request, launcher resolution, capture guard,
  profile pins.
- Docs: `docs/KERNELS.md`, `docs/REFACTOR.md`, `benchmarks/README.md`.

## Validation

  before the change, the 128K baseline captured with the policy mapped back):
  511 rows each at 32K/64K/128K, mean KL 1.2e-6/2.3e-6/1.1e-5, max
  2.9e-4/9.4e-4/5.2e-3, top-1 100%. The script requires full-layer WMMA
  launches unconditionally; `--wmma-full-slices 1` exempts that check (the
  gfx1100 plan never takes the route) and changed no number.

  passed; `tests/test_gpu_gemma4_flash_decode.py` 112 passed.
- Public path `scripts/gemma4_campaign_bench.py` at 8K/32K/64K/128K, parity
  true.
