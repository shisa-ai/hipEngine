# Normalize llama context AR transitions

## Summary

Closed the token-repeat timing mismatch before context-matched XTX runs. Shape
`P/N` now means `N` timed decode transitions: the harness requests `N+1`
visible outputs because llama.cpp samples the first output before
`t_start_generation`. It retains both native `predicted_n/predicted_ms` and the
cross-engine transition-normalized rate.

## Changes

- Added observed first-output, transition count/rate, denominator, and timing
  boundary fields to token-repeat rows/summaries.
- Enabled llama-server `return_tokens`, retained every output token ID/count and
  a stable little-endian int64 SHA-256, and fail the run if returned IDs do not
  cover `predicted_n`.
- Updated the campaign protocol text to state the now-mechanical 129-output /
  128-transition boundary.
