# Resolve MTP depth from executable capability before adapter construction

## Summary

Fixed two separate default-depth defects. Explicit-only MoE requests no longer lose the capability's K2 default, and the resident adapter no longer starts as K3 while the public request uses K2. The latter mismatch disabled graph verification in the actual capacity-four path.

## Changes

- `Qwen35GGUFBringupGenerator.speculative_candidate_budget_default` considers executable declarations regardless of automatic eligibility.
- `Qwen35GGUFResidentModelRunner._resolved_mtp2_adapter` uses that default before LLM publishes its resident-cell budget; an explicitly pinned budget still wins.
- Regression tests cover both backends, unpublished and pinned budgets, and automatic-AR versus explicit-MTP selection.
