# An unmatched KV contract now names the axis and verdict it overrides

## Summary

The automatic-INT8-MTP c2 readiness row took three readings to get right, and
the refusal message is why. A run whose key misses every declaration reports:

```
no registered kernel implements this backend/target/quant/KV/scale contract
```

That sentence is true and useless. Here the artifact, backend, quant, KV
storage, layout and granularity were all declared, and exactly one axis kept the
request off the declaration -- the scale dtype, fp16 requested against fp32
declared. The reader is told no kernel implements any of it, so the recorded
quality rejection behind the declared contract stays invisible.

The same investigation changed the row's clearing route. The cell's first cycle
raises `NotImplementedError: packed target verifier requires a shared direct
INT8 decode leaf at this group width`, and `rollback_cycle` then disables those
requests, which is what the run's `no_provider` fallbacks actually report. The
leaf is absent because `/ready` resolves `max_direct_rows: 0`, and that is not a
quality verdict in this run: the request key is fp16
(`_prepared_kv_scale_dtype` defaults to fp16; `_gguf_int8_effective_scale_dtype`
raises it to fp32 only when a BF16 full-attention mirror is present at long
context), while every INT8 declaration is keyed fp32. No declaration matches, so
no evidence row is ever consulted.

## Changes

`hipengine/models/kv_capabilities.py`:

- `_axis_mismatch` names the first declared axis a request does not match, with
  the declared and requested values.
- `_unmatched_contract_note` picks the closest declaration by matched-axis count
  and reports that axis plus the retained verdict for the contract it keeps the
  request off -- `qualified` or `rejected`, with its recorded reason.
- The unsupported branch appends the note when one exists. With no declaration
  at all the message is unchanged, and the note is additive, so callers
  asserting the existing prefix still hold.

`docs/reference/INT8-MTP-SERVER-READINESS.md`:

- Row 67 records the two distinct refusals behind the cell, the scale-dtype key
  mismatch that makes the declared contract unreachable under the override, and
  three clearing routes in order, with resolving the capability for the
  effective scale dtype first.

## Validation

- `test_unmatched_scale_axis_names_the_declared_verdict_it_overrides` pins the
  refused cell: the gfx1151 fp16 request reports
  `scale_dtype (declared 'fp32', requested 'fp16')` and the retained rejection
  including its `0.7778` measurement; the gfx1100 pass artifact reports the same

leaf exists at four rows. The fp16 key binds nothing.
