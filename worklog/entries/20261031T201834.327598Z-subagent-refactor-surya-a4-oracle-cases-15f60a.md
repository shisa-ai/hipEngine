# Add the Surya A4 protocol oracle case without capturing it

## Summary

R0493's case-table half is implemented: `a4` is in `PROTOCOL_MAX_TOKENS` with a
4000-token budget derived from the committed protocol rows, the documented
clearing command parses and selects only that page, and a single-page capture
merges into an existing oracle instead of replacing it. No capture ran. The
`datalab-to/surya-ocr-2` checkpoint and the optional `torch`/`transformers`
extra are absent from this host, so the committed fixture still holds its seven
rows and R0493 stays open.

## Changes

- `scripts/surya_oracle_greedy.py`
  - `PROTOCOL_MAX_TOKENS["a4"] = 4000`, with the derivation in the table
    comment. The A4 page draws 1586 characters in 12 text units plus the same
    ruled 7x4 table the `table` page draws. The worst ids-per-drawn-character
    rate among the captured text pages is 1.435 (ja, 287 ids / 200 chars); times
    1586 is 2276, and the captured `table` row spends 448 ids on that grid, so
    the derived floor is ~2724. 4000 clears it by 1.47x. It is also the budget
    `tests/test_live_surya_transcription.py` already declares for its
    quality-only A4 case, so the capture and the gate run the same number.
  - `--only` on `--case protocol` now merges into the oracle already in
    `--out-dir`: uncaptured rows keep their values and their order, a captured
    name replaces only its own row, and a new name is appended. A full
    `--case protocol` run still writes exactly the case table.
  - `build_parser()` and `parse_args()` are split out of `main()`. Page
    selection is validated before any checkpoint load, and `--only` is rejected
    for the cases that capture every page instead of being silently ignored.
  - `torch` and the `surya_oracle_torch` page drawers are imported inside the
    functions that use them, so the module imports, prints `--help` and parses
    arguments on a host without the optional torch extra.
- `tests/test_unit_surya_oracle_protocol_cases.py` (new, host-only, faked model
  and greedy decode): pins the case table, the derived budget floor, the exact
  clearing command, a torch-free parse in a subprocess, the selection errors,
  merge preservation (including byte-identical serialization of preserved
  rows), the scratch-directory capture, and full-capture replacement.
