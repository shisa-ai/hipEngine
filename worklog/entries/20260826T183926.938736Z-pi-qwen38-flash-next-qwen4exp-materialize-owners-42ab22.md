# Materialize Qwen4Exp physical weight owners

## Summary

Implemented physical Qwen4Exp residency ownership: one byte-preserving device
allocation for every hot tensor plus the existing one mmap/dequant/staging owner
for PLE. Loading failure and normal close release owners in reverse creation
order and close is idempotent.

## Changes

- Added `Qwen4ExpResidentWeights`, slot lookup, and materialization from ordered
  split readers using each tensor ref's explicit part index.
- Dense F32/F16/BF16 retain their runtime dtype; every GGUF block-quant tensor is
  copied byte-preserving as an INT8-addressed raw buffer for quant kernels.
- Device loading is injectable for lifecycle tests; the production loader uses
  the common device allocation/copy owner.
- PLE mmap/ring are created only after all hot owners succeed; any subsequent
  error closes them and frees every prior device owner.

## Validation

- RED: tests failed collection because `materialize_qwen4_exp_weights` did not
  exist.
- GREEN: `uv run pytest -q tests/test_qwen4_exp_materialize.py` -> `4 passed`,
  including a real HIP Q8_0 byte-preservation allocation/copy/free test.
- Materialize/residency/mapping plus Qwen35 compatibility bundle ->
  `26 passed, 3 skipped`.
- Injected fourth-load failure frees the first three owners in reverse and never
  maps PLE; successful synthetic ownership creates 1,223 unique device owners,
  maps PLE exactly once, then closes every owner in reverse.
