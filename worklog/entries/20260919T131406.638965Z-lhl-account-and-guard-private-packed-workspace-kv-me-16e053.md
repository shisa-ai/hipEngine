# Account and guard private packed workspace KV memory

## Summary

Review of merge 6a5860817 confirmed that capacity-sized leases and private
fallback are intentional, but private packed KV bypassed the pool budget.
Arena and private workspace KV now share one enforced payload ceiling. This
supersedes the accounting limitation in
[the lease-sizing entry](20260918T160119.350325Z-lhl-packed-workspace-lease-sizing-5c2b68.md).

## Changes

- GlobalDeviceKVPool reserves private KV bytes before allocation, counts the
  entire allocated arena (including free and pinned pages), and checks their
  sum on both automatic and direct growth. Private reservations prevent pool
  close until their buffers have been freed. Releasing a reservation restores
  growth headroom without pretending the arena's pinned pages were freed.
- Packed state owns its reservation; failure rolls it back and synchronized
  workspace teardown releases it. Fault injection found pre-existing leaks
  when the second allocation of a Conv/recurrent, K/V, mirror, or scale pair
  failed; each successful allocation is now registered for cleanup immediately.
- Explicit KV budgets apply even without HIP memory telemetry and no longer
  silently expand to fit the initial arena. Automatic sizing rejects an initial
  allocation that exceeds the available bytes after the existing 3 GiB reserve.
- Memory snapshots and ready pool telemetry expose private and combined KV
  bytes. Workspace lease reporting uses the named lease, excluding unrelated
  request graph pins. Arena stats remain arena-only; private payload is also
  part of owner workspace/allocator totals and must not be added to those twice.
- Corrected comments: serving capacity and 1024 tokens are floors, not physical
  verifier/context ceilings. Private fallback remains available within budget.
  ENVS documents the payload ceiling: recurrent state, execution scratch and
  pointer-table metadata remain outside it. No flag, arithmetic, kernel,
  registry, or architectural plan change.
