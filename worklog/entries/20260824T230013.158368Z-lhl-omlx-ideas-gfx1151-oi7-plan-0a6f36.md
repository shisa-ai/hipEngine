# Define Qwen3.8 native mixed-quant artifact plan

## Summary

Authorized one concrete `OI-7` candidate after a source/template/loader
preflight. This is a model-artifact campaign, not a runtime optimization and not
an oMLX-format port.

The current local Qwen3.8 `Q4_K_M` is already mixed
(`294 Q4_K / 48 Q5_K / 67 Q6_K / 1 Q8_0`) and protects NextN `eh_proj` at Q8.
Requantizing it cannot recover precision and is explicitly forbidden.

The public `unsloth/Qwen3.8-27B-GGUF@4ca72078...` revision supplies:

- two BF16 shards totaling 54,657,735,616 bytes with all 866 tensors;
- `imatrix_unsloth.gguf` (13,642,656 bytes, SHA256 `0ee5b10b...`);
- an 866-tensor `UD-Q4_K_XL` sensitivity template (SHA256 `3f227079...`).

The template cannot run unchanged because it includes unsupported dense
`IQ4_NL/IQ3_S` codecs. The selected projection promotes unsupported
`IQ4_XS/IQ4_NL/Q3_K/IQ3_S` tensors to native Q4_K, retains every measured
Q5/Q6/Q8 assignment, and enforces Q8 NextN K/V plus Q6 NextN Q/output/FFN/
`eh_proj` and LM-head floors.

## Changes

- Added `scripts/qwen38_mixed_quant_plan.py`, which binds exact source/template/
  imatrix hashes, validates complete matching inventories and NextN floors,
  emits an anchored per-tensor llama.cpp type file, and enforces a byte cap.
- Added `scripts/qwen38_gguf_teacher.py` for a same-runtime merged-BF16 80-row
  full-vocabulary teacher fixture compatible with existing quant-quality
  compare/bootstrap tooling.
- Added deterministic unit tests for codec projection, exact regex output,
  inventory/budget identity, NextN-floor rejection, and teacher protocol.
- Recorded the 79,877-byte compact exact plan artifact and campaign docs.

## Validation

- Planning tests: `tests/test_qwen38_mixed_quant_plan.py` and
  `tests/test_qwen38_gguf_teacher.py` pass.
- Ranged sparse-header inspection proves source/template names and shapes match
  exactly at 866/866 tensors; no model payload was inferred from a recipe name.
- Native projection is exactly `360 F32 / 149 Q4_K / 191 Q5_K / 56 Q6_K /
  110 Q8_0`, with 27,320,697,856 manifest parameters, 17,779,359,744 projected
  tensor bytes, and 5.2061217 effective bpw. It is +683,581,440 bytes (+4.00%)
  versus the deployed Q4_K_M payload.
- llama.cpp `749f688f...` dry run with the exact imatrix and 866-entry anchored
  type file passes: source 52,115.19 MiB / 16.00 bpw -> candidate 16,955.72 MiB /
  5.21 bpw. `--allow-requantize` was not used.
