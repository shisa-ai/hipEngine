# UD-U1 review repair 1: native-row alpha/beta BF16-pointer owner binding

## Summary

The consolidated UD-U1 review rejected the U1 closure: the loader requested
only `DEFAULT_AR_OPERATIONS` (which excludes `ar_decode_native_rows`) while
`Qwen35GGUFResidentSession.step_rows_native` never checked that operation at
all. A Q8_0 sole-T16 alpha/beta (or an uncontracted dense-F32 one, or a raw-Q8
sidecar) could therefore be loaded with a passing preflight and later either
crash on a missing `allocation('raw')` mid-layer or silently feed non-BF16
bytes into `dense_gemv_out_bf16` (a `uint16_t*` weight ABI).

This unit binds requested modes to pre-allocation admission and enforces the
actual binding at native execution entry, before any state mutation or device
call. No new kernels.

## Changes

- `hipengine/loading/qwen35_gguf_admission.py`: new CPU-safe
  `qwen35_gguf_native_row_binding_errors(resident_weights)` — for every
  linear-attention layer it requires `ssm_alpha`/`ssm_beta` to be a dense-BF16
  resident with a real BF16 `raw` allocation (the only valid
  `dense_gemv_out_bf16` owner); it names each violating slot and why (raw-GGUF
  bytes, missing raw allocation on sole-T16, dense-F32, non-BF16 dtype).
- `hipengine/loading/qwen35_gguf_materialize.py`:
  `materialize_qwen35_gguf_weights` gains `requested_operations`
  (default `DEFAULT_AR_OPERATIONS`), so a caller that knows it will run the
  native route binds `ar_decode_native_rows` to the aggregated preflight
  BEFORE any device allocation.
- `hipengine/runtime/qwen35_gguf_runner.py`: `step_rows_native` and
  `capture_native_rows_graph` enforce the actual resident binding at entry via
  the new helper and raise before `set_full_attention_positions`, embedding
  staging, or any kernel launch, with the load-time knob named in the error.
  Existing valid paths are preserved: the runner does not add the operation to
  the load-time default (a sole-T16 artifact such as Qwen3.5-0.8B-Q8_0 must
  keep loading for its c1/layout-aware rows route); the entry check refuses
  exactly the residents that cannot run the native route.

## Tests (tests/test_gguf_ud_admission.py, RED first)

- `test_native_row_binding_errors_name_every_invalid_alpha_beta_owner` —
  dense-BF16 valid; raw-GGUF INT8 / sole-T16-no-raw / dense-F32 all refused
  with per-slot reasons (RED: helper did not exist).
- `test_materializer_requested_operations_bind_native_rows_before_allocation`
  — real `Qwen3.5-0.8B-Q8_0` + allocation sentinel: requesting the native
  operation refuses through the aggregated admission error naming both slots,
  zero allocator invocations.
- `test_step_rows_native_refuses_unbound_native_owner_before_state_or_device`
  — a real synthetic qwen35 GGUF file (new shared writer
  `tests/_qwen35_gguf_fixture.py`) materialized by the REAL loader with
  CPU-faked allocations, then the REAL `step_rows_native` entry: refused with
  `ar_decode_native_rows` named, position owner untouched.
- `test_capture_native_rows_graph_refuses_unbound_native_owner_before_device`
  — same for the graph-capture twin entry.
- `test_step_rows_native_admits_contracted_bf16_owner_and_reaches_device_entry`
  — a raw-IQ manifest (IQ4_XS attn_qkv triggers the F32 linear contraction)
  yields dense-BF16 alpha/beta; the entry check passes and execution reaches
  the (mocked) device scratch step with the position owner staged.
