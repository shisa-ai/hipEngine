# Share the packed Inkling decode gate input across routes

## Summary

Inkling GGUF `fast` now uploads and packs one gate/up activation row for all eight selected NVFP4 experts instead of uploading eight copies. The expert order, per-expert scales, and projection arithmetic are unchanged.

## Changes

- Register the shared-input variant for gfx1100 and gfx1151. Use it only when one token supplies all eight routes and the gate/up bank matches the supported NVFP4 dimensions. Keep the existing path for independent inputs, prefill, and strict. Reserve sufficient Q8 scratch before dispatch so both projections can use it without reallocating while kernels are queued.

## Validation

- The new cases failed on the missing variant, then passed on both GPUs against the quantized CPU reference. They cover both supported input widths and scaled and unscaled banks. The focused GPU and profile tests, deterministic CPU suite, fixture/smoke checks, and documentation gates passed. W7900 `rocprofv3 --kernel-trace` confirmed two `nvfp4_q8_selected<true>` launches with positive durations in the test fixture.
- `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. python -u /tmp/hipengine_inkling_shared_gate_public.py "$model" "$backend"` compared shared and repeated gate inputs via `LLM.generate_detailed()` on W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL with `fast`, FP32 KV, greedy decoding, no reuse or drafting. At 47, 151 and 1,027 input tokens, all eight scored decode logits and all nine generated IDs matched bit-for-bit on each GPU. Each fused request ran 352 shared gate projections at width 2,304. The seven omitted FP32 rows per call account for 22,708,224 fewer uploaded bytes per request, not a wall-time claim.
