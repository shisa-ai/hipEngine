# Indexed Qwen4Exp GDN decode: independent rows over per-row state slots

## Summary

Adds the independent-request form of the Qwen4Exp GDN decode step, which is the
first prerequisite for batched (C2/C4) serving: one launch advances `rows`
independent requests, each reading its own packed Conv/scalar/gate/output row and
reading and writing exactly the recurrent-state slot `state_indices[r]` of a
shared `[state_slots][v_heads][128][128]` FP32 slab. Slots no row selects are
untouched, so a ragged active subset leaves the other requests' state
byte-identical.

This is a primitive plus its tests only. No runner, serving, or dispatch default
was touched, and the existing single-row row-split owner stays registered as the
strict fallback and as the per-row arithmetic oracle.

## Changes

- `hipengine/kernels/hip_gfx1100/linear_attn/qwen4_exp_gdn.hip`
  - `qwen4_exp_gdn_decode_rowsplit_indexed_f32_kernel`: the single-row row-split
    decode kernel with (a) row `blockIdx.y` selecting the row offset of every
    packed operand and (b) `state_indices[row]` selecting the state slot. The
    per-row address math folds into the existing expressions, so the block body
    is the single-row instruction sequence.
  - Uniform batch ownership check: warp 0 clears a 4096-bit shared bitmap and
    sets one bit per row, then sets `s_batch_rejected` on an out-of-range or
    duplicate slot. The decision is published by the barrier that already
    separates the loads from the compute, and every block returns before any
    write when it fires.
  - `kQwen4ExpGdnIndexedMaxRows = 64`, `kQwen4ExpGdnIndexedMaxStateSlots = 4096`,
    and the `hipengine_qwen4_exp_gdn_decode_rowsplit_indexed_f32` launcher.
  - The launcher mirrors every host bound: pointer nullity, head geometry, row
    and slab bounds, all four row-width lower bounds, `conv_row_stride % 4 == 0`,
    16-byte Conv base alignment, 8-byte `state_indices` alignment.
- `hipengine/kernels/hip_gfx1100/linear_attn/qwen4_exp_gdn.py`
  - `qwen4_exp_gdn_decode_rowsplit_indexed_f32` raw-pointer wrapper, with
    `_INDEXED_ARGS`, packed-stride defaults, and the same
    `HIP_SUCCESS`/`runtime.check` error path as the neighbours.
  - `qwen4_exp_gdn_indexed_state_indices`: host admission for the per-row slot

  - `QWEN4_EXP_GDN_INDEXED_MAX_ROWS = 64`,

- `tests/test_unit_qwen4exp_gdn_indexed_decode.py` (new, 42 tests): slot-index
  admission including duplicate rejection and the slab bound, stride/alignment

## Design notes

- **Duplicate slots are an ownership violation, not drift.** Each row is one
  independent request, so two rows naming one slot would both read the same
  initial state and both write it: the survivor would depend on block completion
  order. Rejected on the host with a message naming the slot and both rows, and
  rejected again on the device as a whole batch. The device path is uniform
  (all-or-nothing) rather than first-writer-wins, because committing the rows
  that happen not to collide would be a silent partial update. The device guard
  exists for callers that build the index vector themselves; the host validator
  is the one that can say *which* row was wrong.
- **`state_slots >= rows` is a capacity bound, not a uniqueness check.** It
  rejects a slab that cannot hold one slot per row. Uniqueness is enforced
  separately and is not implied by it.
- **The batch check was placed to cost no barrier.** A first version put two
  `__syncthreads()` before the strided state loads and measured 227198..231988 ns
  for the N=4 kernel — 4.1x the 51953..56002 ns of the pre-check version, because
  the barrier exposed the state-load latency. The check now runs inside warp 0
  with `__syncwarp()` and is published by the barrier that already existed,
  measuring 52137..57266 ns. The 4.1x variant was rejected, not retained.
- **Arithmetic profile is T0, not T2.** Each block executes the single-row
  kernel's instruction sequence on its own row, so the declared contract is
  bit-exact equality with the single-row owner, and that is asserted rather than
  assumed. Because the arithmetic is unchanged, this variant does not need a new
  production numerical envelope or task gate for its own correctness. See
  "Missing evidence" below for what is nevertheless not established.
- **Conv stride and base alignment are admission terms.** The Q/K loads are
  `float4`, so every row base must be 16-byte aligned. A stride below the packed
  row width would make adjacent rows overlap (row r reading row r+1's Conv
  values), and a stride that is not a whole `float4` would misalign every row
  after the first. Both are rejected in C as well as Python, because the C symbol
  is reachable directly.
- **Two bounds must agree.** `QWEN4_EXP_GDN_INDEXED_MAX_ROWS` /
  `_MAX_STATE_SLOTS` (Python) and `kQwen4ExpGdnIndexedMaxRows` /
  `kQwen4ExpGdnIndexedMaxStateSlots` (C) are checked by
  `test_row_bound_matches_the_c_launcher`. The host check runs first, so a drift
  widening only the Python side would make the C guards dead code.

## Missing evidence

The CPU-reference outer safety gate in `docs/TESTING.md` section 4 is
KL <= 0.05 with top-1 agreement >= 90%, and the doc scopes it to logit-producing
paths. That gate has **not** been run for this variant, and the evidence is
missing rather than satisfied:

- The primitive emits a gated per-head output vector and an updated recurrent
  state. Neither is a logit distribution, so KL and top-1 cannot be computed from
  its own outputs.
- The committed CPU reference exposes `gdn_prefill_recurrent_segments` (which
  this unit's oracle uses) but no logit-producing Qwen4Exp GDN layer;
  `qwen4_exp_reduced_qsa_layer` composes GR -> QSA -> GR -> MoE with no GDN stage.
- Nothing dispatches `qwen4exp_gdn_indexed_decode` yet, so no model-level fixture
  exercises it. Closing the gap needs a layer-level CPU-reference fixture plus a
  path that reaches logits, which is outside this unit's scope.

What does exist in its place: per-call bit-exact equality with the
currently-dispatched single-row owner, and FP32 round-off agreement with the
committed CPU recurrence. The first is a stronger statement about this kernel's
arithmetic than a KL threshold, but it is a per-call identity, not a
distributional comparison through the rest of the model. It bounds the risk; it
does not satisfy the gate.

## Limitations

- Single decode step per row. Nothing here handles a row that must run several
  steps (MTP verification), and mixed AR+MTP rows in one work item are
  undesigned.
- The primitive advances the recurrent state only. It does not touch conv state,
  PLE state, KV cache, or index state; a batched request still needs the same
  per-row treatment for those before C2/C4 serving exists.
- No graph capture, no multi-stream, and no overlap with neighbouring layers was
  tested.
- `v_heads` was exercised at 16, 32 and 48. The ABI accepts up to 4096; wider
  head counts are unmeasured.
- Downstream numerical quality (logits, KL, top-1, task quality) is not measured;
  see "Missing evidence".
- The device duplicate scan is a 4096-bit shared bitmap, which is what bounds
  `state_slots` to 4096. A larger pool would need a different check.
- The `state_slots >= rows` admission rule and the 64-row bound are this
  primitive's own choices; a future serving path with a different pooling scheme
  may need them revisited.
- The kernel-duration comparison against four sequential single-row launches
  (4 x 17673..22522 ns vs one 52137..57266 ns) is arithmetic over one trace, not
  an end-to-end latency measurement.
