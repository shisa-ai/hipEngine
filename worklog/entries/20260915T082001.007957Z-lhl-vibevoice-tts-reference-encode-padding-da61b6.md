# VibeVoice-TTS reference encode padding semantics

## Summary

The reference voice-prompt encode now reproduces the fork's padding instead of
working around it. The port had been zero-padding the reference waveform to a
3200 multiple, which produced the right frame count (70) with the wrong content
for the final frame, and that difference had been recorded as numerical drift.
It is a semantic difference: the fork feeds the unpadded waveform and appends
per-stage right zero padding so every stage emits `ceil(rows/stride)` frames,
while the runtime's `conv_rows_out` floors.

## Root cause

`get_extra_padding_for_conv1d` in the fork pads each stage's input to the next
stride multiple, so the cascade `ceil(222480/8)=27810`, `ceil(27810/5)=5562`,
`ceil(5562/5)=1113`, `ceil(1113/4)=279`, `ceil(279/2)=140`, `ceil(140/2)=70`
yields 70 frames. Feeding the same 222480 samples to the port's floor-based
cascade yields 69. Pre-padding the waveform to 224000 gave 70 frames again, but
the extra rows sat at the input instead of at each stage, so frame 69 was built
from a different input extent: measured relative error 0.39 against a 0.045
interior-frame gate.

## Changes

- `hipengine/kernels/hip_gfx1100/vibevoice/encoder.hip`: `vv_conv_gemm_kernel`
  and `vv_im2col_kernel` take a `rows_in` bound and contribute zero for taps at
  or past it, which is the fork's right zero padding. This changes both kernels'
  C ABI and the matching `_ARGTYPES_*` tuples.
- `hipengine/kernels/hip_gfx1100/vibevoice/encoder.py`: `rows_in` is exposed as
  a trailing argument defaulting to `-1` (unbounded), so the decoder call sites
  and the encoder kernel test keep their previous behaviour unchanged.
- `hipengine/runtime/vibevoice_encoder.py`: `_encoder_forward` takes
  `align_stages`, which pads each stage's effective row count to the next stride
  multiple and passes the true row count as `rows_in`. New `encode_reference()`
  is the non-streaming entry point for a whole waveform; `encode()` and
  `encode_chunk_streaming()` are untouched.
- `hipengine/runtime/vibevoice_tts_session.py`: `voice_prompt_rows()` calls
  `encode_reference()` with the unpadded waveform and drops its own padding.
- `tests/test_live_vibevoice_tts_session_gpu.py`: the strict-xfail tail-frame
  test is replaced by a single 0.045 gate covering every frame.

## Validation

- The reference tail frame moves from relative error 0.39 to 0.0035, which is
  below the interior frames' 0.0347. The tail no longer needs a separate
  tolerance, and the strict xfail was removed rather than widened.
- `uv run pytest tests/test_gpu_vibevoice_encoder_kernels.py
  tests/test_live_vibevoice_tts_session_gpu.py` — 14 passed.
- `uv run pytest tests/test_live_vibevoice_tts_decoder_gpu.py` — passed.
- `uv run pytest tests/test_live_vibevoice_asr_cpu_reference.py` — 5 passed, so
  the shared front-end runtime still serves the ASR lane.
- The streaming feedback path is unaffected by construction: 3200-sample chunks
  divide every encoder ratio, so `pad` is 0 at every stage and `align_stages`
  is a no-op there.
- Hardware: AMD RYZEN AI MAX+ PRO 395 w/ Radeon 8060S (gfx1151).
