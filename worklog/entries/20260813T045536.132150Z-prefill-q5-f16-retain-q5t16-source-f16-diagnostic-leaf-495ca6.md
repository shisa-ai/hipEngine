# Retain Q5T16 source-F16 diagnostic leaf

## Summary

Retained a runtime-unwired Q5T16-to-F16 bounded producer and rocBLAS composite
after the final profile exposed Q5 as an untested source-F16 lane. On the
actual Qwen3.6-27B K6,144/N5,120 `ssm_out` tensor, the complete changed-
arithmetic leaf is uniformly 1.56-1.95x faster across 512/1K/4K and both gfx1100
boards. No model policy, resident weight, decode, MTP, or default path changes
in this unit.

## Changes

- Added a local64 sole-Q5T16 tile producer that expands exact source-F16 weight
  bytes from the resident T16 payload.
- Registered the producer and its existing bounded activation-cast/rocBLAS/
  strided-output-cast composite under the Q5T16 quant key.
- Added RED/GREEN source-F16 byte, registry/backend-scope, bounded workspace,
  CPU correctness-gate, lifecycle, and build coverage.
- Updated the kernel catalog, benchmark status/changelog, and compact
  cross-board leaf/trace evidence. The exact Q5T16 WMMA path remains the
  required fallback.

## Validation

- `tests/test_gguf_q6_k_f16_rocblas_prefill.py`: **13 passed** on RX 7900 XTX;
  ruff, JSON validation, worklog schema, and `git diff --check` pass.
- Actual-weight 15-pair screen, all **90/90** pairs win. Selected XTX speedups
  are **1.925x/1.742x/1.555x** and W7900 **1.948x/1.906x/1.604x** at
  512/1K/4K. Selected row top-1 is 98.05-98.24%, but this is not a full-model
  quality claim.
- Cached rocprof names `gguf_q5_k_t16_dequantize_f16_tile_kernel` with VGPR16,
  LDS0, scratch0, local64, and plausible duration.

## Next

- Add Q5 to the existing model-scoped bounded policy without adding allocation,
  then run counterbalanced full-prefill and the complete ten-prompt/four-
  category changed-arithmetic quality gate. Promote only if quality, decode,
  memory, and MTP safeguards pass; otherwise remove runtime policy and keep this
  isolated diagnostic primitive/evidence.
