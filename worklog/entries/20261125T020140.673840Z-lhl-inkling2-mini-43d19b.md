# Fix two to four request rows decoding together on the Inkling GGUF route

## Summary

On the public route a request with two to four prompts, or two to four requests decoding at the same
time in `hipengine serve`, failed in `fast` as soon as their rows decoded together: the engine raised
`TypeError: this function takes at least 13 arguments (12 given)` and the server closed its engine
service, so every later request got a 503.

- **Cause.** `8c04c09c4` gave the NVFP4 Q8 dot kernels a stream argument and updated four of the five
  launchers in `gguf_nvfp4_q8_dot.py`. `launch_counted_shared_input_q8_dot`, the gate/up projection
  of two to four decode rows, kept its twelve arguments. The kernel-level GPU test
  `tests/test_gpu_gguf_nvfp4_q8_dot.py` has been red since that commit; it is not part of the default
  discovery, and nothing drove several rows through the public surface.
- **Found by** the mixed-load measurement for the prompt block width: one stream decoding while a
  2K prompt is prefilled beside it. The failure came when both requests decoded together.
- **Fix.** The launcher takes `stream=None` and passes the captured stream like its siblings. One
  line of behavior; no kernel changed.
- **Measured after the fix**, W7900, mainline `UD-Q4_K_M`: two, three and four prompts in one
  request give the same 24 greedy output tokens as each prompt alone, in `strict` and in `fast`.
  The same holds for rows that start at different prompt lengths.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_nvfp4_q8_dot.py`: `launch_counted_shared_input_q8_dot`
  passes the stream.
- `tests/test_gpu_inkling2_decode_rows.py`: two, three and four prompts through `LLM.generate_detailed`
  against each prompt alone, in both profiles, checking that every decode step carried all rows. It
  runs when `HIPENGINE_INKLING2_MINI_GGUF` points at the model and a HIP runtime loads.
