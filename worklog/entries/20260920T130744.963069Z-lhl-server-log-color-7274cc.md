# Server log colorization via --log-color

## Summary

`hipengine serve` now styles its own log output through `--log-color`
(`HIPENGINE_LOG_COLOR`), defaulting to `auto`. The motivating case is a
long-lived `tmux`/byobu pane that pipes the server through `tee`: that stream is
not a TTY, so a TTY-only heuristic leaves the pane uncolored, and `always` is the
mode that colors it. Uvicorn's stock formatter colors the level prefix only and
does not touch hipEngine's structured lines, so the useful parts of a
`REQUEST_INFO:` or `MODEL_LOAD:` line stayed plain.

## Changes

- `hipengine/server/log_style.py` (new): `COLOR_MODES`, `resolve_color_mode`,
  `colors_enabled` (honors `NO_COLOR` / `FORCE_COLOR`, unrecognized values fall
  back to `auto`), `style_log_message`, `HipEngineLogFormatter`, and
  `build_log_config`. It styles the level prefix, the leading `LABEL:` of a
  structured line, every `key=` of a field, and model-load progress bars.
- Text is never rewritten: `strip_styles(styled) == plain` byte for byte, so
  `grep`, `cut`, and log shippers keep working, and an unlisted label (including a
  new failure label such as `UNHANDLED_ERROR`) is already legible through its
  level color.
- `hipengine/server/__main__.py`: `--log-color {auto,always,never}` (env
  `HIPENGINE_LOG_COLOR`, default `auto`) passed to `uvicorn.run(log_config=...)`.
- `docs/API.md` and `docs/ENVS.md`: document the flag, the mode semantics, and the
  `NO_COLOR` / `FORCE_COLOR` interaction.

## Validation

- `tests/test_unit_server_log_style.py` (57 tests): mode resolution including
  `NO_COLOR` / `FORCE_COLOR` precedence and unknown values, byte-identical
  `strip_styles` round-trips, label and level coloring, progress-bar styling, and
  the built log config's formatter wiring. Exit 0.
- Integration check: `uvicorn.Config(..., log_config=build_log_config(mode="always"))`
  builds both `default` and `access` formatters without error.
