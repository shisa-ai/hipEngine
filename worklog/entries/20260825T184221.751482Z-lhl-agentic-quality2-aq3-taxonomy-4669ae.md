# Classify AQ2 quality failures by earliest boundary

## Summary

Classified all 48 AQ2 observations and 24 independent task blocks at their
earliest observable boundary. Five task blocks fail: four at model-generated
arguments and one at model tool selection. Nineteen pass. There are zero runtime
implementation failures and zero unresolved rows in the retained denominator.

Every raw response joins one-to-one with a normalized record; all generated IDs
match both exact arrays and hashes. The exact Qwen GGUF tokenizer reconstructs
the pre-parser text and all 48 prompt token sequences decode→encode losslessly.
A standalone parser that does not call the server parser accepts all 48 raw
texts as one canonical tool envelope and reproduces the public tool/arguments
exactly. All 48 calls are schema-valid, finish as `tool_calls`, contain empty
public content, use zero repairs, and execute an external oracle. Thus none of
the five answer failures begins at template/tokenizer, envelope, JSON, schema,
parser/publication, finish, repair, HTTP/generation, session, or ownership.

The four wrong-argument blocks substitute plausible but task-incorrect values:
query prose for the fixture's `ValueError`, one file for the requested docs
directory, `release_validation` for Japanese key `release_check_ja`, and the
English release path for `docs/release_ja.md`. The wrong-tool block selects valid
declared `read` instead of `grep`. AQ3 nominates aggregate classes
`model_argument_grounding` (4/24) and `model_tool_selection` (1/24), but admits
no implementation before development/heldout suite freeze.
