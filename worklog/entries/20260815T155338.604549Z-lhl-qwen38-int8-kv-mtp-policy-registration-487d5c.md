# Carry INT8 scale metadata into GGUF MTP policy

## Summary

Unblocked the mandatory natural-MTP gate for explicit INT8 GGUF targets. Target
prefill and AR already passed, but MTP request-policy registration recreated the
target storage dtype without carrying its scale metadata, so
`KVReservation` correctly failed closed before verification.

## Changes

- For INT8 target ownership, select the first non-null per-layer scale metadata
  object from the resident full-attention layout and attach it to the MTP
  request reservation.
- Preserve the BF16 path with `scale_metadata=None` and fail explicitly if an
  INT8 target somehow owns no scale metadata.
- No verifier kernel, transaction, commit/rollback, or decode arithmetic changed.

## Validation

- RED: the focused registration test reproduced
  `ValueError: int8_per_token_head reservations require scale metadata`.
- GREEN: `tests/test_qwen35_gguf_mtp_session.py` and
  `tests/test_qwen35_gguf_mtp_e2e.py` pass 10 tests.
- The failed pre-fix natural run completed its first true-AR row at
  `35.535580 tok/s` before failing exactly at MTP policy registration; no MTP
  result from that run is retained.

FP32-scale INT8 target. Require exact AR/MTP output and category non-regression
