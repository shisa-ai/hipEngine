# vibevoice-tts milestone 3: diffusion head + DPMSolver on HIP

## Summary

Milestone 3 boundary done: the MLP-DiT diffusion head and the two-branch CFG
DPMSolver++ sampling loop run torch-free on CPU (numpy) and HIP GPU, gated on
the frozen milestone-1 fixture chain. The GPU head matches the numpy CPU
reference within the eager-bf16 envelope, and the full 20-step replay of both
fixture requests lands inside the calibrated fixture envelope.

## Changes

- `hipengine/kernels/cpu_reference/vibevoice_tts_diffusion.py`: numpy port of
  the fork's `VibevoiceDiffusionHead` (bf16 grid ops, eager double-rounded
  RMSNorm, bf16-cast timesteps before the sinusoid) and the vendored
  `DPMSolverMultistepScheduler` (dpmsolver++ order-2 midpoint, v_prediction,
  cosine betas, linspace, zero final sigma) with the fork's exact torch
  promotion structure (0-dim FP32 tensors cast to bf16 before bf16 products;
  python-float scalars participate via fp32 opmath without pre-rounding).
- `hipengine/loading/vibevoice_tts.py`: `load_vibevoice_tts_diffusion_head`
  (26 tensors, 123,279,360 params) + the two checkpoint scaling factors.
- `hipengine/kernels/hip_gfx1100/vibevoice/diffusion.{hip,py}`: six
  eager-rounded elementwise kernels (two-rounding RMSNorm with a nullable
  weight, silu, add, strided adaLN modulate, strided gated residual,
  cfg-combine) + build/wrappers, registered in the shared `vibevoice` family.
- `hipengine/runtime/vibevoice_tts_diffusion.py`: head on device (linears via
  `dense_gemv_out_bf16`, RMSNorm/silu/modulate/residual via the new kernels),
  DPMSolver on host through the CPU reference (per-step tensors are 2x64);
  shape validation on the sampling entry point.
- `tests/test_unit_vibevoice_tts_diffusion.py` (7 tests, CPU tier) and
  `tests/test_live_vibevoice_tts_diffusion_gpu.py` (5 tests, HIP-guarded).
- `scripts/vibevoice_tts_decoder_rocprof_smoke.py`: extended to prebuild and
  trace the diffusion head (paro_silu added to the cached prebuild so the
  profiled process never spawns hipcc).

## Validation

- `python3 -m pytest tests/test_unit_vibevoice_tts_diffusion.py` — 7 passed
  (2.1 s): both fixture requests replayed per-step (eps/speech trajectories,
  final latent, scaled latent) inside the measured envelope; exact schedule
  (linspace timesteps `[999, 949, ...]`, zero final sigma, first/second-order
  switching); bf16 timestep cast pinned (999 -> 1000, 949 -> 948); byte
  determinism.
- `python3 -m pytest tests/test_live_vibevoice_tts_diffusion_gpu.py` — 5
  passed (2.5 s) on gfx1151: GPU-vs-CPU per-step eps worst ratio 3.3%/6.2% of
  peak, speech 1.3%/1.9%, final latent 0.004/0.021 abs; fixture-chain gates
  (final latent 0.0088/0.026 abs, scaled 0.047/0.13); determinism; registry
  resolution.
- Drift attribution (measured): replaying the recorded bf16 eps through the
  FORK'S OWN scheduler on CPU drifts the trajectory to 0.031 by step 20 —
  the same magnitude as the numpy port — so the fixture drift is inherent to
  bf16-rounded inputs compounding through the solver, not a port bug
  (my-solver vs fork-solver on identical eps: 62% bit-identical, diffs are
  occasional single bf16 ulps from torch-vs-numpy exp/log rounding).
- `rocprofv3 --kernel-trace` (cached-only, no hipcc in the profiled process):
  1585 dispatches — vv_diff_rmsnorm 100x mean 25.9 us, vv_diff_silu 120x
  1.9 us, vv_diff_modulate 100x 1.9 us, vv_diff_gated_residual 80x 2.3 us,
  silu_mul 80x 2.1 us, vv_diff_add 20x 1.7 us, dense_gemv_out_kernel 492x
  461.3 us. Every kernel ran under its expected registered name.
- Kernel-debugging note worth keeping: device rbf()/float_to_bf16_bits
  returns bf16 BITS as uint16 — assigning that to a float variable converts
  NUMERICALLY (bits(1.125)=0x3F90 -> 16272.0), it does not bit-reinterpret.
  Any in-kernel round-trip must go back through bf16_bits_to_float.
