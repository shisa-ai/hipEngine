# Separate Qwen scratch and capacity planning from execution

## Summary

Separate geometry/storage-policy scratch sizing and capacity estimation from execution while keeping a single plan consumed by allocation and admission.

## Changes

- `hipengine/runtime/qwen35_gguf_planning.py` owns `_FullStackScratchPlan`, scratch sizing, resolved KV layout construction, resident breakdown and capacity search. Execution retains real allocation, route selection and route-specific sizing callbacks. Serving consumers import the planning owner directly; existing runner imports remain aliases.
- Removed unconditional host metadata/RoPE construction repeated after the `materialize` branch. - Shared constants, alignment and the unchanged RoPE table helper moved with planning; five live diagnostic fixtures now patch the private mirror threshold in both execution and planning so diagnostic layout/price agree. No new flag, runtime guard or fallback.
- Updated the runtime structure reference and PLAN boundary. Prefill scratch's execution-backed sizing adapter remains explicitly documented as a separate boundary; this unit does not claim to extract all workspace planning.
