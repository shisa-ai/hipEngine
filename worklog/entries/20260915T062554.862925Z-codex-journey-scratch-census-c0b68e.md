# Add CPU census of Qwen4Exp allocation recipes

## Summary

Add a CPU-only diagnostic that exercises the actual base runner allocation
routines with virtual pointers, then attributes every root allocation.
Use this to derive the chunk4096 accounting repair rather than guessing slack.

## Changes

- Invoke the existing _allocate/close routines and worst-case repair-queue
  preparation. Optional MMQ setup is explicitly excluded; no graph/verify
  resources or model weights are allocated.
- Use a temporary memory-stat tracker and reject simulated device reads.
  Walk dataclass fields, including slotted structures and dynamic lazy
  attributes, and count owning buffers once rather than counting views.
- This script is standalone diagnostic code, not a hot-path planner.

## Validation

- Three focused CPU tests pass. Initial tests exposed the metadata-parser
  object contract and slotted dataclass traversal; both were repaired.
- Tests verify ownership-root deduplication, complete attribution, closed
  virtual allocations, preserved outer counters and rejected invalid copies.
- No new production allocation estimate or device-memory limit is asserted.
