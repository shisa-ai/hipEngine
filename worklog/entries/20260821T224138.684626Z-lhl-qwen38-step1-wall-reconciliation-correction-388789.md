# Correct #37 step-1 wall reconciliation: graph replay is host-bound, not GPU-bound

## Summary

Review correctly rejected the committed step-1 reconciliation
(`20260821T104444.857482Z-lhl-qwen38-c8-wall-reconciliation-dense-first-758601`).
That entry treated summed kernel durations as serialized wall time under
multi-stream overlap and wrongly concluded ">=89% of wall is GPU kernels" and
"dispatch/sync is deprioritized". This checkpoint supersedes it.

Corrected method (profiler now enables `--hip-runtime-trace` and
`--memory-copy-trace`, routes c1 through the graph path for matched controls,
and records kernel interval-union + uncovered + HIP-API + memory-copy
accounting):

| lane | wall (ms) | kernel sum (ms) | kernel interval union (ms) | GPU busy % | uncovered % |
| --- | ---: | ---: | ---: | ---: | ---: |
| graph c1 | 35.53 | 31.16 | 2.55 | 7.2% | 92.8% |
| graph c4 | 43.87 | 39.00 | 5.61 | 12.8% | 87.2% |
| graph c8 | 62.03 | 56.73 | 17.87 | 28.8% | 71.2% |
| eager c1 | 36.10 | 29.17 | 21.19 | 58.7% | 41.3% |
| eager c4 | 43.36 | 38.19 | 27.02 | 62.3% | 37.7% |

**Corrected finding.** The GPU kernel interval union is only ~7-29% of wall in
the graph-replay decode (c1->c8) and ~59-62% in eager decode. The graph-replay
decode is substantially host/dispatch/phase-gap bound, NOT GPU-bound. My earlier
">=89% GPU-bound, deprioritize dispatch" claim conflated summed duration with
wall coverage under ~3-12x overlap (sum/union = 12.2/7.0/3.2 at graph c1/c4/c8).

Kernels in the graph replay cluster in tight bursts with multi-ms gaps (c1
shows ~4 bursts with ~10 ms idle-GPU gaps), consistent with host-side phase
gaps between graph nodes. The eager path keeps the GPU far busier (58-62%).
