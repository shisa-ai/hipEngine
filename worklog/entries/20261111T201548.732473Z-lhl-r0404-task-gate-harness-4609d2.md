# R0404 INT8 direct-prefill task-quality gate harness

## Summary

Adds `scripts/execution_profile_gguf_int8_direct_prefill_task_gate.py`, the R0404
execution-profile TASK gate (docs/EXECUTION-PROFILES.md §6.5) left open after the per-token-head
and tail-four Hadamard numerical-envelope verdicts. It runs the committed RF1 long-context task
packet (`benchmarks/prompts/mtp-realworld-long-context.jsonl`, 6 categories) free-running under two
arms on the SAME mirror-free INT8 KV resident session: strict oracle-bridge prefill
(`HIPENGINE_GGUF_INT8_PREFILL_DIRECT=0`) vs direct INT8 prefill (`=1`), scores `choice_exact`, and
binds a predeclared per-category paired non-inferiority criterion (a category regresses iff the
candidate misses a task the strict arm answered correctly). Session construction mirrors the
numerical gate's `_capture` and fails closed if the direct route would not engage.

## Changes

- New harness `scripts/execution_profile_gguf_int8_direct_prefill_task_gate.py`:
  - reuses the numerical gate's `route_environment`, `PURE_INT8_ENV`, `_candidate`,
    `_rearm_bulk_workspace`, `_DIRECT_ROUTE_MIN_MAX_POSITIONS`;
  - reuses the RF1 MTP gate's `load_tasks` / `score_task_output` / `_build_prompt_tokens`;
  - free-running greedy generation with EOS/EOT stopping; `--kv-layout`, `--kernel`, `--limit`,
    `--max-new-tokens` (default 1024) selectors; provenance via `collect_artifact_provenance`.

## Validation

- DEFECT FOUND AND FIXED: the first run at `--max-new-tokens 24` was a VACUOUS pass — both arms
  scored 0/6 because Qwen3.8-27B is a reasoning model and 24 tokens cut off `` before the
  answer. The RF1 packet's own MTP gate uses 8 tokens (binding-only, `production_quality_claim=False`),
  so short generation cannot measure task quality. A 1-task 512-token smoke confirmed the model
  finishes reasoning (~100 tokens) and emits the correct choice.
- FIX: generation stops at EOS/EOT; default cap raised to 1024; `--limit` added for smokes.
- Full per_token_head (flash) run, W7900 gfx1100, Qwen3.8-27B-Q4_K_M: strict 6/6, candidate 6/6,
  0 regressions, `non_inferior=True`. 4/6 outputs byte-identical; retrieval + long_doc diverge but
  both correct — evidence the direct route genuinely ran (not a BF16 bit-identity) and preserved
  task quality. `measurement_valid=False` only because the harness was uncommitted at run time.
