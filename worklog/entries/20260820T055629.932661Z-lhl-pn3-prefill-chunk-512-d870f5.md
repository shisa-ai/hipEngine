# gfx1151 GGUF prefill: 512-row chunk override (H2048-MoE geometry)

## Summary

From the gfx1100-hardcoded-numbers review: the gfx1151 `_ARCH_CHUNK_PROFILES`
(linear/moe 256) exists for the PARO path but the **GGUF runner never passes
`target_arch` to `resolve_prefill_config_for_sequence`, so GGUF prefill used the
generic 1024/4096 chunks**. A chunk-size sweep on the 8060S found **512-row
linear/MoE chunks are the GGUF optimum** for the 35B-A3B (H2048-MoE): ~1.2%
faster @2048, ~2.3% faster @4096, chunk-boundary exact (KL 0.00013). Retained a
geometry-keyed override.

## Measurement (2026-08-20, 8060S, whole-prefill median of 2 iters)

Chunk sweep @2048 tok (35B-A3B): 128=20058, 256=19952, 512=19742, 1024=19984 ms.

Robustness 512 vs 1024:
- 35B @2048: 19891 vs 20279 (+388ms), 19922 vs 20127 (+205ms) -> 512 wins.
- 35B @4096: 47696 vs 48784 (+1089ms), 47736 vs 48891 (+1156ms) -> 512 wins ~2.3%.
- 27B @2048: 67432 vs 68007 (+575ms) then 74645 vs 71279 (-3366ms) ->
  **inconclusive** (60W-lane variance ~10%); left on default.

Correctness: KL(logits 1024-chunk || 256-chunk) = 0.00013 at 2048, top-1 both
9707 -> chunk-boundary change is effectively exact (GDN prefill chunking is
deterministic across boundaries; far below the 0.034 run-noise floor).

## Review context (gfx1100-hardcoded-numbers sweep)

- gfx1151 already overrides 47/56 GGUF-path capability knobs; 5 tables inherit
  gfx1100 defaults (`GGUF_DENSE_PREFILL_SCRATCH_LIVENESS_POLICIES`,
  `GGUF_Q4_T16_UNEQUAL_PAIR_PREFILL_POLICIES`, `GGUF_T16_F16_ROCBLAS_PAIR_ONLY_*`,
  `SOLUTION_INDICES`, `SOLUTION_VERSION_PREFIX`) -- mostly 27B H5120
  memory/prefill-variant policies, low value for our workloads, not changed.
- Hard-coded `threads=256` launch geometry in the shared .hip (paged_attn_decode,
  cast, gather, conv, group_scatter) is shared with gfx1100 (gfx1151 has no .hip
  files) -> needs .hip changes; deferred to P3-FULLATTN.
- Aotriton prefill threshold -> routed native (previous unit).

## Implementation

- `hipengine/kernels/hip_gfx1151/__init__.py`:
  `GGUF_PREFILL_CHUNK_SIZES_BY_GEOMETRY = {(QWEN35_MOE_H2048_E256_GEOMETRY,
  "MOSTLY_Q4_K_M"): (512, 512)}` (+ `__all__`).
- `hipengine/runtime/qwen35_gguf_runner.py`: `_gguf_prefill_chunk_sizes_for(backend,
  weights)` (geometry-keyed via `_gguf_policy_identity`) applied after
  `resolve_prefill_config_for_sequence` in the GGUF session init.
