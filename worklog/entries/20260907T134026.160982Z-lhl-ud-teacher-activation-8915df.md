# Localize teacher projection arithmetic to Q8_1 activations

## Summary

The independent llama.cpp HIP teacher uses Q8_1-quantized activations in its
one-token quantized matrix-vector path. At two sampled layer-0 Q5_K
projections, reconstructing those activations reproduces teacher outputs
within 1e-6. hipEngine's existing raw kernel instead matches its BF16-input
CPU oracle within 1.5e-6. This establishes an arithmetic-contract difference
at those projections, not the cause of every long-context KL failure.

## Changes

No runtime or external-repository changes. The prebuilt common-BF16-KV
teacher runs one token from the existing K_M input archive under rocprofv3.
A temporary evaluation callback then captures `attn_norm-0`,
`linear_attn_qkv_mixed-0` and `z-0`. Its full logits must remain bitwise equal
to the uninstrumented teacher. The CPU check uses 128 uniformly spaced output
rows from each projection, the same captured normalized input and decoded
published Q5_K weights. A separate GPU check uses the BF16-rounded input and
the existing raw Q5_K F32-output leaf.

Host: zbook, Radeon 8060S, gfx1151. Model: published Qwen3.8-27B UD Q4_K_M.
llama.cpp pin: `17252c769a63c1cb650ce98ae309cf4de0da7778`.

## Validation

Both teacher runs completed. Instrumented/uninstrumented logits are bitwise
equal across the 248320 vocabulary entries. The boundary parser found exactly
three unique finite records at prompt/position 0: widths 5120, 10240 and 6144.
The trace contains 461 `quantize_q8_1` launches and quantized matrix-vector
kernels. All recorded selected-kernel durations are positive; duration ranges
are evidence of execution, not a performance comparison.

The GPU checks pass existing elementwise tolerances, exact repeated-output
checks and output canaries. No new kernel or full-model numerical pass is
claimed. The reconstructed Q8_1 oracle does not reproduce affine sum-correction
terms or GPU reduction order; its close match is measured for these samples,
not a general exact emulation contract.
