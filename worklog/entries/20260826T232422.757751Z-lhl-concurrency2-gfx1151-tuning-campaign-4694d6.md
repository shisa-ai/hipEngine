# Admit FP16 eager-target device proposal under oracle

## Summary

Added a default-off qualification seam for T1.3: when
`HIPENGINE_SPECDEC2_DEVICE_CHAIN_ORACLE=1`, an FP16 production target may
receive a device-resident C1 proposal while retaining the qualified eager target
verifier. Target graph eligibility remains false. The flag-off production path
is byte-for-byte unchanged.

This tests the narrow unqualified seam that current telemetry exposed (70 eager
cycles, zero device handoffs): provider device graph -> production eager target.
It does not promote a speed path. Production numerical/task/lifecycle and
operation gates plus same-suite speed are required before retention.
