# Retain both production-load oracles and enforce worker coverage

## Summary

Retain both `--oracle-mode same_owner` (the default) and `isolated` in
`scripts/gguf_production_load_gate.py`. They compare different ownership
boundaries: the first runs serial trajectories on the measured owner and
checks drain; the second starts bounded subprocess owners, partitions at
four prompt keys per child, and compares tokenizer identities before load.
Neither mode duplicates the other's isolation contract. R0208's choice is
complete; no oracle was retired and no arithmetic or default changed.

Inspection found a concrete contract defect: isolated workers were checked
only for merged prompt-key coverage, not reference-key coverage or trajectory
length. A child could omit a reference, add an unexpected reference or return
a truncated/overlong trajectory without the parent rejecting it at the worker
boundary. This unit repairs that defect instead of only recording a decision.

## Changes

- Validate each child's prompt and reference key sets against its assigned
  keys before merging. Require every reference to have exactly the maximum
  requested output count for that prompt key, matching same-owner behavior.
- Preserve explicit subprocess failures, duplicate detection, tokenizer
  comparison, serial drain and final measured ownership checks.
- Add fault-injection coverage for missing/extra reference keys, short/long
  reference trajectories and extra prompt keys. Existing round-trip and
  four-key partition tests cover valid packets.
- Remove the completed R0208 disposition entry. Both modes remain documented
  by CLI help; no CLI migration or removal is needed.
