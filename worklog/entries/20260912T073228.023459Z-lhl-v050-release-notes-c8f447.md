# v0.5.0 release-notes pass-through and promoted-default audit

## Summary

Pass-through of the v0.5.0 changelog ahead of the release, a README model-support
update, and an audit of whether promoted (measured, exact, non-regressive)
performance routes are the no-flag default.

## Changes

- `CHANGELOG.md` v0.5.0: release date 2026-09-06 → 2026-09-12; intro broadened
  from dense-Qwen-only to the full family set; new Added bullet "Initial support
  for more model families" (EVIE-4.5B/8B, TimesFM 2.5/3.0, Qwen3.8 Flash-Next);
  two Changed bullets for the promoted INT8 KV route wins (C2 1.25x / C4 1.42x
  aggregate throughput; layer-outer packed prefill default at −0.438 GiB tracked
  peak, which also makes the resumable bounded-yield prefill the default for
  leased requests); re-measurement line extended to 2026-09-11; and the "INT8
  cache still saves no memory" bullet scoped to Strix Halo so it no longer reads
  as a contradiction of the qualified explicit W7900 INT8 route.
- `README.md`: added EVIE 4.5B/8B and TimesFM 2.5/3.0 rows to the Supported
  models grid (`gfx1151` Yes, `gfx1100` —), and a Qwen3.8-27B highlight sentence
  linking `docs/QWEN38-STRIX-HALO-EXTERNAL-SURVEY.md`.

## Validation

- `scripts/sync_benchmark_readme.py --check` → "README benchmark blocks are
  synchronized".
- Read the changed `CHANGELOG.md` and `README.md` sections end to end.
- Promoted-default audit method: extracted every `HIPENGINE_*` environment read
  in `hipengine/`, cross-referenced the flags that appear on
  `benchmarks/CHANGELOG.md` "promoted/default-on" lines, and read the effective
  default at each call site.
- Default-on verified: `GGUF_AR_PACKED_PREFILL`/`_DECODE` ("1"),
  `GGUF_PACKED_LAYER_OUTER` ("1"), `GGUF_MTP_SERVER_PACKED_PREFILL` ("1"),
  `GGUF_MTP_SERVER_STREAM_VERIFY`/`_DRAFT` ("1"), `GGUF_C8_Q5_SOURCE_MMQ`
  (True), `GGUF_MTP_VERIFY_MODE` ("native"), `GGUF_FP16_RECURRENT_STATE` (scoped
  True), `GGUF_DECODE_REPACK` (true), `MOE_C1_C_DISPATCH` (enabled),
  `RESIDENT_MTP_DRAFT_DEVICE_MOE` (True), `DFLASH_DRAFTER_DENSE` ("wmma"),
  `PARO_MARLIN_K_REPLACE` (true), `QWEN35_NATIVE_SAMPLER` (true).
- Correctly off: Maple fusion/graph (unfused is the measured fast path),
  `GGUF_INT8_KV_DECODE_GRAPH` (24–127-step regression, REFACTOR entry),
  `GGUF_INT8_PREFILL_DIRECT` (prefill speed), PARO fused/rejected knobs.
- Finding: the only promoted-path gap is the execution-profile migration seam.
  Seven model/backend/quant combinations register strict+production plans
  (`qwen3_5_gguf` gfx1100+gfx1151 `gguf_q4_k_m`, `qwen3_5_moe_gguf`
  gfx1100+gfx1151 `gguf_q4_k_m`, `qwen3_5_moe_paro` gfx1100 `w4_paro`,
  `qwen4_exp_gguf` gfx1151 `gguf_q4_k_m` + `gguf_ud_q4_k_xl`). An omitted
  profile bypasses plan resolution and keeps exact/strict arithmetic, so
  production-only wins are not in the no-flag path: gfx1100 Qwen3.8 C7/K3
  76.510→81.641 tok/s (+6.71%), C8/K3 95.708→97.674 (+2.05%), gfx1151 planar-Q6
  C5–C8 +1.75–2.08%, and the Flash-Next Framework headline row was measured with
  `engines.profile.requested = production`. The W7900 Qwen3.8 `Q4_K_M` c1
  680.4/29.7, W7900 PARO 2852.1/115.8, and gfx1151 Qwen3.8 `Q4_K_S` 396.1/13.1
  headline artifacts carry no profile field and are the no-flag path.
- Not flipped: `docs/EXECUTION-PROFILES.md` §2.1 and `docs/REFACTOR.md`
  "Execution-profile migration seam" govern this as a gated P4/P7 migration
  (re-certify non-exact defaults, public-default SLO/c1 guard, docs name the
  default, one release window). Changing it is an owner decision, not an audit
  fix.
