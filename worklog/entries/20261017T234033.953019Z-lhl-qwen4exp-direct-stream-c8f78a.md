# Stream committed steps from the direct Flash-Next MTP provider

## Summary

The direct Flash-Next MTP provider now yields committed root/cycle steps instead of completing generation before its first yield. This closes the direct adapter's buffering gap; it is not a hardware or end-to-end production qualification.

## Changes

- `stream_detailed` consumes `iter_generate` lazily, emits cumulative committed IDs with each text delta and step-owned logprobs, then emits final telemetry and finish metadata without duplicating logprobs.
- Incomplete UTF-8 replacement suffixes are withheld until later tokens or final output. Rewriting already published text raises an error rather than corrupting the stream.
- Iterator closure runs in `finally`, including client closure and exceptions. The next request still owns its ordinary prefill/reset path; this adapter does not introduce shared-runner concurrency.
- Direct capability `streaming_mode` now reports `committed_tokens`. No additional HTTP logprob capability is advertised by this change.
- Structured grammar/tool stream tests reconstruct the response and require multiple chunks, exact text/logprobs and terminal metadata rather than requiring one buffered chunk.
