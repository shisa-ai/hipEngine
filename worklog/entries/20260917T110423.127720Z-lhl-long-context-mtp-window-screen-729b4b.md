# Long-context MTP window screen on gfx1151

## Summary

The dense Qwen3.8 MTP adapter can serve prompts and generations past the
1,024-token attention transition today, and with the batched long-row verifier
that is faster than normal decoding rather than slower. The two literal 1,023
limits in `qwen35_gguf_mtp2.py` are now one experimental environment override
(`HIPENGINE_MTP2_MAX_CONTEXT_TOKENS`, default unchanged). Screening on zbook
`gfx1151` at the Atlas comparison protocol (greedy 128 outputs, one active
request, `Q4_K_M`, BF16 KV, 16,384-token session) measured:

| Arm | ~1024 (945-token prompt) | ~4096 (3,530-token prompt) |
| --- | ---: | ---: |
| Normal decoding, default policy | 11.72 | 10.96 |
| Normal decoding, matched control (split decode off) | 11.60 | 10.01 |
| MTP, shipping window 1,023 | 17.20 | 10.94 (MTP refused) |
| MTP, window 16,384, per-row strict above the transition | 11.92 | 6.29 |
| MTP, window 16,384, batched rows above the transition | **21.30** | **13.82** |

The override alone loses throughput (per-row strict is 0.57x normal decoding at
3,530 tokens); the batched staged rows are the enabler. Both batched-row runs
emitted text byte-identical to the AR arm (690 and 666 characters). Reaching
them requires disabling split decode globally, which costs normal decoding about
9% at 3,530 tokens — recorded in `docs/REFACTOR.md` as the promotion-quality
shape of the change.

This is a diagnostic screen, not a retained benchmark row: the full category
suite, heldouts, production numerical gates, and reconciliation of the earlier
boundary BF16 difference were not run. No benchmark rollup changed.

## Changes

- `hipengine/generation/qwen35_gguf_mtp2.py`: replaced the prompt gate's and the
  capability's literal 1,023 with `_mtp2_context_window()`, which reads
  `HIPENGINE_MTP2_MAX_CONTEXT_TOKENS` and defaults to the qualified 1,023.
  Invalid or non-positive values raise at resolve time. Both call sites read the
  same value so admission and per-cycle policy cannot disagree.
- `tests/test_unit_qwen35_gguf_mtp2_seam.py`: pins the default window, the
  override, five rejected values, and the behavioral difference — a 1,022-token
  prompt still stops at `target_context_k0` by default and reaches provider
  acquisition with the override.
- `docs/ENVS.md`, `docs/REFACTOR.md`: variable entry plus two ledger entries
  (the override's removal trigger, and the verifier-scoped row policy the screen
  argues for).
- `docs/QWEN38-GFX1151-MTP-SERVING-IMPROVEMENTS.md`: the AR-tail inference is
  now a measured confirmation, and P1 carries the screen table and its limits.
- `benchmarks/results/2026-09-17-gfx1151-qwen38-long-context-mtp-screen.json`:
  every arm, ratio, coverage accounting, identity check, and protocol limit.

## Validation

- `uv run --extra dev pytest tests/test_unit_qwen35_gguf_mtp2_seam.py -q` — 17
  passed, including the new window tests.
- Real server runs on zbook `gfx1151` (HIP 7.15.26333 / ROCm 10.0.0), each arm
  in its own process, one host, one session: streaming bench with three measured
  runs after a warmup plus a non-streaming probe per shape. Decode-throughput CV
  was 0.05-0.09% on the measured arms; the server pinned
  `--speculative-candidate-budget 3` because the default 4 is unqualified.
- Coverage accounting confirms the mechanism rather than inferring it: 945
  tokens went from 21 cycles + 56 accepted = 77 of 127 outputs to 44 + 83 = 127
  of 127, and 3,530 tokens went from refused to 54 cycles + 74 accepted = 128.
- Output identity is byte equality of the full greedy continuation against the
  AR arm's text at the same shape, not a prefix or a fixed window.

## Next

- Promote the verifier-scoped long-row policy so normal decoding keeps split-K
  attention while the verifier batches rows; the global split-decode switch is
  the only reason the win costs AR ~9% at 3,530 tokens.
- Run the promotion protocol before claiming a speedup: the full multi-prompt
  mtp-bench category suite plus category heldouts at 1024/4096/8K shapes against
  true no-MTP AR, the production numerical/task gates, and a targeted repro of
  the staged long-row BF16 difference recorded at a row ending at position 1024.
- Add the execution accounting (MTP versus AR output counts, first fallback
  position) so a future mixed run cannot present itself as full coverage; this
  screen had to reconstruct coverage from cycle and acceptance counters.
