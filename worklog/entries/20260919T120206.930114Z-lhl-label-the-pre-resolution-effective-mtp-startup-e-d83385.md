# Label the pre-resolution EFFECTIVE_MTP startup echo as pending

## Summary

The server no longer reports MTP as off before the engine has resolved its
generator. `_log_effective_mtp_config` now logs the pending form whenever the
engine exists but its speculative route is not resolved yet, so exactly one
operator-facing `EFFECTIVE_MTP` line states a resolved state and that line
matches what the engine actually serves.

## Observed contradiction (quoted verbatim)

The same server command line, production profile, `Qwen3.8-27B-Q4_K_M.gguf`,
`hip_gfx1151` backend, `--max-context-tokens 8192 --kv-storage bf16
--speculative-mtp-serving auto --speculative-candidate-budget 3`
(`/tmp/task17/server-repro.log`):

```
INFO:     MODEL_LOAD: loading model=/home/lhl/models/gguf/Qwen3.8-27B-Q4_K_M.gguf size=15.93 GiB backend=hip_gfx1151 quant=auto
INFO:     EFFECTIVE_MTP: serving=off engine_supported=False default_enabled=False policy=auto thinking=hint candidate_budget=requested:3 resolved:3 source:explicit
INFO:     MODEL_LOAD: engine created elapsed=0.0s; preparing weights, KV pool, and runtime workspace
...
INFO:     EFFECTIVE_MTP: serving=enabled engine_supported=True default_enabled=True policy=auto thinking=hint candidate_budget=requested:3 resolved:3 source:explicit
INFO:     hipEngine is ready.
```

The first line is emitted from `get_llm` right after `LLM(...)` is constructed
and before `prepare` resolves the text generator, so `engine_supported=False`
there means "not known yet", not "unsupported". It reads as the effective
setting and contradicts the second line, which is emitted after the model is
resident.

## Changes

- `hipengine/server/api.py::_engine_speculative_mtp_unresolved` — new helper: an
  engine is resolved when it has a callable speculative MTP route or a resolved
  text generator (`_text_generator`, `text_generator`). `engine=None` counts as
  unresolved.
- `hipengine/server/api.py::_log_effective_mtp_config` — the pending branch now
  also covers an engine that is present but unresolved, and its message names
  the condition: `... source:pending (pre-resolution: the engine has not
  prepared its generator yet)`. A resolved engine with no MTP route still logs
  `serving=off engine_supported=False`, so a genuine "off" is unchanged.
- `tests/test_integration_server_api.py` — `test_unprepared_engine_logs_pending_not_off`
  (RED: pre-fix it logs the exact contradicting line) and
  `test_resolved_engine_without_mtp_route_still_logs_off`.
