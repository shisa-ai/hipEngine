# Repair MoE packed verifier convolution state addressing

## Summary

The MoE physical C2 target read convolution state using packed segment ordinal
and verifier workspace capacity. With direct resident state, those are not the
resident slot index or slab capacity. A two-request group in a four-slot server
could therefore read another request's state and use the wrong row stride.

The corrected-label replay reproduced the symptom: identical greedy prompts
could emit only `<think>\n` and EOS. After repairing the address mapping, the
same prompt completes the requested 32 tokens at C1-C4; all greedy rows match
the same-session AR control. This is a state-ownership regression, not a finding
inferred solely from differing generated IDs.

## Changes

- Pass `linear_state_owner.slot_count` and `layout.state_indices` into
  `_run_moe_physical_c2_linear_rows_exact`. Derive each state stride from that
  owner and address each initial convolution state through its resident slot.
  Captured output rows remain indexed by packed token row. GDN already uses
  the device slot map.
- Add executable CPU pointer-capture tests covering contiguous, reordered and
  sparse resident slots at capacities two and four, plus malformed mappings.
  There are no arithmetic, kernel-body, flag or admission-policy changes.
- Archive the before/after HTTP requests, token IDs, text, stop reasons, physical
  counters and source hashes in
  `benchmarks/results/2026-10-17-moe-mtp-state-slot-repair.json`.
- Re-anchor 52 audit decisions to identical source lines after this edit,
  including one line whose new key collided with an old decision. Copy each
  decision from HEAD through the unchanged-line map rather than from a
  progressively modified decision store. Dispositions and budgets are unchanged.
