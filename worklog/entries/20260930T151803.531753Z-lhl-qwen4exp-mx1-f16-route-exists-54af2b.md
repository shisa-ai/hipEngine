# MX-1's F16 route is already implemented — one flag reaches it, and it runs with no repair

## Summary

`MX-1` is the ledger's largest remaining lever: the routed-expert repair is
**1,219.978 ms = 7.75%** of the 15,741.963 ms prefill union, and the row's action column
prescribes **building** a "real-input routed packet with F16 operands" and scoping "a
full candidate" — i.e. a from-scratch kernel port, priced with a documented structural
risk (16-bit operands double the LDS weight footprint against the iu8 route's 8-bit
staging, forcing a smaller tile or a halved K-slice).

**That build is not needed. The route already exists, is registered, is reachable by
clearing one flag, and runs with no repair pass.**

`hipengine/kernels/hip_gfx1100/quant/gguf_q4_k_selected_prefill.hip` contains
`gguf_q4_k_selected_dual_wmma_prefill_compact_kernel`, whose inner loop is exactly
`MX-1`'s description:

```c
b_reg[kk] = static_cast<half_t>(scale_f * static_cast<float>(q) - min_f);
acc[tm][tn] = __builtin_amdgcn_wmma_f32_16x16x16_f16_w32(a_reg[tn], b_reg, acc[tm][tn]);
```

- **Q4_K decoded to F16** (`b_reg` is `half16_t`, built from the raw `block_q4_K` bytes)
- **F16 WMMA with F32 accumulate** (`wmma_f32_16x16x16_f16_w32`)
- **Dual gate+up** (`use_b` switches to `qweight_b` / `out_features_b`)
- **Selected-MoE** (`expert_id`, `compact_base`, `tile_row_in_expert` over the compact ABI)
- **Activations already half** (`load_compact_row_half16<scalar_t>`)

It is registered as `selected_dual_wmma_prefill_compact_bf16_bf16_out` (plus
`_hot_fulltile_` and `_sidemeta_` siblings) for `(hip_gfx1151, moe_linear, gguf_q4_k)`.
**The `iu8` owners are the optimization layered on top of it**, not the other way
round — which is why the file contains both `wmma_f32_16x16x16_f16_w32` (×8, in the
compact family) and `wmma_i32_16x16x16_iu8_w32` (×2, in the iu8 pair).

## How it is reached

The grouped-MoE dispatch is a chain, and the F16 owner is the fall-through:

```
4160  if q4_k_mmq_prefill:
4197  elif exact_grouped_q4_gate:      → iu8-risk + repair   (production)
4360  elif exact_grouped_down:
4387  elif expert_gate.quant == gguf_q4_k:
          if q4_iu8:  → iu8 (plain)
          else:       → F16 compact          ← MX-1's route
```

So **`HIPENGINE_QWEN4_EXP_EXACT_GROUPED_Q4=0` alone** reaches it: `Q4_IU8_PREFILL`
already defaults to 0, and the down leg selects its own route at a separate dispatch
site, so leaving `EXACT_GROUPED_DOWN` at production isolates the gate/up half.

## Engagement — verified before any gate run

An owner probe applied the env post-construction exactly as the gate does and counted
every candidate owner on one short request:

| config | F16 compact | plain iu8 | iu8-risk | repair |
| --- | ---: | ---: | ---: | ---: |
| production | 0 | 0 | (via `resolve`) | (via `resolve`) |
| `EXACT_GROUPED_Q4=0` | **4** | 0 | 0 | **0** |
| `EXACT_GROUPED_Q4=0, Q4_IU8_PREFILL=1` | 0 | 4 | 0 | 0 |

Shapes are the gate/up projection: `[50, 2560, 640, 640, 512, 464]` — same for both
owners. **The F16 route engages on all layers with zero repair calls.**

The probe also settles a detail that would otherwise waste a run: `EXACT_GROUPED_Q4=0`
**alone** is sufficient. Adding `EXACT_GROUPED_DOWN=0` is unnecessary and would touch
the down leg for no reason.

## Why this matters

- The row's **build risk is removed**, not mitigated. The LDS-footprint question the
  pricing raised (16-bit staging versus 8-bit) is already answered by a shipping
  kernel that uses this exact operand class.
- The admissibility work the row already completed — F16 decode error at the F16 limit
  (max rel 4.88e-4 = 2^-11), output error **8.0x-9.5x below the BF16 floor already in
  the path** on real natural-input capture, zero overflow, and the gate/up Q5_K
  coverage gap closed at ratio 0.159 — now has an implementation to test rather than
  one to write.
- The prize is unchanged and still requires **performance**: the F16 owner must beat
  the iu8-risk owner plus the repair it removes (gate/up 2,779.713 ms + 573.211 ms of
  repair; the row's combined target is 4,280.901 ms for gate/up+down). A numerics pass
  is necessary and not sufficient.
