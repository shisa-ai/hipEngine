# Run post-reject cooldown discriminator

## Summary

Settle policy-vs-corruption for the C2/K2 post-reject code acceptance collapse
with an env-gated one-shot K0-transitional catchup
(`HIPENGINE_SPECDEC2_POST_REJECT_COOLDOWN`, commits `d01365bc8`, `6a835dd72`).
Verdict: post-reject difficulty is real and the catchup repairs code, but the
catchup path itself degrades non-code requests, so the policy is not
retainable as implemented; default stays off and the retained default
economics remain the no-cooldown rows6-padded 1.1902x.

## Changes

- `plan_speculative_requests(suppress_speculation=...)` pins suppressed
  requests to K0 TRANSITIONAL so `prepare_k0` runs the target-hidden catchup;
  engine-loop probe, runner hook `speculative_post_reject_cooldown`, adapter
  one-shot pending set (set at reject commit, cleared by the catchup advance,
  discarded on request drop).
- `tests/test_specdec2_policy.py` pins the TRANSITIONAL semantics and alignment
  validation (17 pass). REFACTOR.md entry records the removal condition.

## Validation

- Latched first cut: code acceptance 72.92% -> 87.04% but 200 catchups for 96
  spec cycles (flag never cleared) -> 1.0997x; proved acceptance recovery and
  exposed the latch.
- One-shot: 49 catchups, 166 spec cycles, 10/10 exact/engaged/budget, zero
  failures, full drain. Aggregate 1.1480x (< 1.1902x no-cooldown).
- Conditional position-1 acceptance, one-shot vs no-cooldown: code post-reject
  0.471 -> **1.000** (n=6), code post-accept 0.840 -> 0.885; but en post-reject
  1.000 (n=2) -> **0.167** (n=12), other post-reject 1.000 (n=2) -> 0.500
  (n=8); post-accept stays healthy everywhere (0.885-0.920).
- Interpretation: post-reject re-speculation difficulty is category-general
  and strongest for code; the target-hidden catchup fully repairs code's
  post-reject proposals but degrades en/other, pointing at the catchup's
  positional semantics (`root_position = target.position` at prepare time)
  needing audit before any policy use.
