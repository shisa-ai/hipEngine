# Keep Inkling block attention inputs on the device

## Summary

The attention half of each `fast` prefill visit now runs from device-resident rows: loop controllers, the seven attention-input projections, K/V and output short convolutions, clip/normalization and block attention read and write one arena, and only the branch rows come back. The 575-token public prefill on W7900 fell from 4.176 s to 2.974 s (medians of four interleaved runs). Strict, unnamed profiles and scalar decode keep the host expression.

## Changes

- Add `norm/inkling2_attention_prepare.hip`: per-head L2 clip with an optional coefficient and log position factor (`clip`), and per-head RMS normalization (`rms`). Register `host_clip` as the strict counterpart.
- Add `block_table_sigmoid` to `attention/inkling2_target_attention.hip`: the relative bias is evaluated from one score row per (query, head) and a lag table on the device instead of a materialized query-by-history tensor. The template keeps the dense-bias path unchanged for `block` and `block_sigmoid`.
- `Inkling2GGUFDeviceProjections`: factor the controller plan, staging and launches so one resident arena can reuse them; add `resident`, `resident_vector`, `project_attention_resident`. The arena covers controller input and output, every projection, the clip/normalization outputs, the attention output and the output projection, and only the last buffer is downloaded.
- `Inkling2DeviceAttention.step_block_resident` launches block attention over device pointers without fencing, so the caller's later launches stay on stream zero.
- `Inkling2TextSession._prepare_layer` takes the resident path only for multi-row, committed, non-staged blocks with the lag-table kernel and a device convolution; everything else keeps the existing expression. `Inkling2GGUFText._resident_attention` builds the per-visit plan.
- Profile plan: `resident_block_relative_bias` (`block_table_sigmoid` over `block_sigmoid`) and `resident_block_inputs` (`clip` over `host_clip`).

## Validation

- New `tests/test_gpu_inkling2_resident_attention.py`: the lag-table kernel matches the dense-bias block kernel across ring wrap at capacities 3, 17 and 49, and both prepare kernels match the host clip and RMS at `(dim, heads)` of `(67, 4)`, `(128, 3)` and `(16, 7)`, with and without a scale, and with the log position factor. Six cases pass on W7900 and six on Strix Halo. The existing target-attention, controller, device and unit suites pass on both GPUs.
- Per-visit hidden states against the host expression, 64 and 151 input tokens: worst relative deviation `7.6e-6` at 64 tokens (largest state 296) and `1.8e-6` at 151. The deviation appears at the first looped visit and grows through the core passes, which is the expected accumulation of clip and attention round-off, not a routing or ownership difference.
- W7900, mainline `UD-Q4_K_M`, `fast`, greedy, no prefix reuse or drafting, through `LLM.generate_detailed()`: generated IDs identical to the host path at 64, 65, 151, 257 and 575 input tokens. Worst KL from `strict` `1.26e-4` against `1.67e-4` for the host control; worst KL from the host control `6.7e-5`; top-token agreement 20 of 20, the same as the host control. Repeats are bit-identical. Both paths logged manifests `615e6270e615ba223b8d19834b2e81f7fd5e293fb7e85c79fafb845e5ff621ce` (strict) and `a3476ebf9cdd009c9e7ade40cbb1f047d996112633d6d31a34af5d0e50c08a3c` (fast, before the final evidence path, which the digest includes).
- Strix Halo, pinned Loom `UD-Q4_K_XL`, `hip_gfx1151`, same protocol at 64, 65, 257, 575 and 1031 input tokens: identical IDs, worst KL from `strict` `5.5e-4` against `6.6e-4` for the host control, worst KL from the host control `7.2e-5`, 20 of 20 top agreement, bit-identical repeats. ## Next

- Two wave-reduction bugs were caught by the staged comparison, not by the parity checks: `inkling2_prepare_*` returned the reduction to lane 0 only, and the lag-table dot sat inside a `lane == 0` guard. Both made every row differ from the host path while the model still produced finite, plausible text, so keep the per-visit state comparison as the first check for any further resident step.
- Next step in the campaign: move expert-route selection and the residual reads and adds onto the device, then extend the resident path to scalar decode.
