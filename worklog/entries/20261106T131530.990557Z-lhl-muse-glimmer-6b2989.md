# Muse Glimmer DFlash drafter WMMA prefill + cycle-economics findings

Enabled the fast WMMA prefill family in the DFlash drafter (the draft only
proposes; correctness is target-verify-governed, so changed draft arithmetic
is acceptable). Draft block 146 -> 62 ms; full-suite DFlash decode up to
~8.7 tok/s (n_draft=5) from 4.52. Draft oracle parity and target exactness

## Findings (the path to Gate B)

- **llama.cpp default n_max = 3** (common.h:331), not 15. It proposes 3
  drafts/cycle: higher mean acceptance (no deep positions) and a cheap 3-row
  verify. hipEngine's registered candidate_budget=15 wastes verify cost on
  deep positions that rarely accept. Tuning budget toward 3-5 helps.
- **Cycle overhead is the binding barrier.** At n_draft=3 hipEngine commits
  ~2.4 tokens/cycle but the cycle costs ~291 ms -> ~8.2 tok/s, below AR (11).
  llama.cpp's cycle is ~112 ms (21.3 tok/s): int8 MMQ draft/verify (2x bf16
  peak on RDNA3) and the bonus token folded into the verify batch (no extra
  forward). hipEngine pays a separate ~50 ms bonus/correction decode each
  cycle and a bf16 verify.
