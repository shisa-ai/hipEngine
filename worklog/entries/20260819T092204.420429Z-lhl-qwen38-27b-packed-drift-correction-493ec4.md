# Correction: Qwen3.8-27B packed c2/c4 token flip is T2 production drift, not a correctness bug

## Summary

Supersedes the F2 characterization in
[`20260819T053637.974792Z-lhl-qwen38-27b-old-vs-new-ab-267a45.md`](20260819T053637.974792Z-lhl-qwen38-27b-old-vs-new-ab-267a45.md)
and the matching `docs/REFACTOR.md` entry. The earlier entry labeled the
packed c2/c4 divergence a "C2 regression" and a "first-class gate
violation." That was overstated. Per the protocol, byte-exactness is not a
correctness requirement, and the output here is not incorrect.

## What the exactness check actually measures

`scripts/server_f1_concurrency_bench.py` (`correctness_summary` +
`_first_mismatch`): a cN record is "exact" iff its 128 generated token IDs
are **byte-identical** to an independent c1 oracle trajectory for the same
prompt (matched by prompt sha256). A "mismatch" therefore means
**not bit-invariant across batch composition** — it is a composition
invariance detector, **not** a correctness oracle. It does not (and cannot)
judge whether the produced tokens are valid.

## The divergence is a single narrow-margin flip, not corruption

Same host/protocol/model (W7900 dev0, p512/d128, prompt = 512x token 9707
with last token 9708). c1 oracle vs C2 packed (c2 and c4 are byte-identical
to each other):

- Identical prefix through **token 73** (indices 0-72).
- **One flip at index 73**: oracle 3154, packed 6866.
- **After the flip, packed = oracle shifted by exactly 2 tokens**: 44/44
  positions match at offset k=2 (indices 76-120). So the "39 differing
  positions" is one root flip amplified by autoregression, not 39 errors.
- Both trajectories end in the same long 9707-repeat loop.
- Decoded text: oracle "…commitment to **making a positive impact on
  society**…", packed "…commitment to **giving back to society**…". Both are
  fluent, valid, re-converging boilerplate — a legitimate alternative
  continuation, not garbage.

Deterministic across all c2 and c4 runs; only the one prompt row that
generates varied tokens (before converging to the repeat) flips; the
all-9707 rows stay exact.

## Protocol grounding (docs/EXECUTION-PROFILES.md)

- `production` profile: *"Width- and shape-specific arithmetic is allowed"*
  and *"Cross-width generated-ID equality is diagnostic, not a promotion
  requirement."*
- T2 drift (line 163): *"reduction reorder, split-K/online merge, …
  width-specific arithmetic"* is `production` after the full gate — exactly
  what a packed (batched) decode does relative to c1.
- Bit-exact generated IDs are required only under `strict` (fixtures/oracle
  parity) or `batch_invariant` (RL/eval/reproducible serving).

Therefore the packed c2/c4 path for this model is a **T2 production
drift**, not a correctness failure and not a production gate failure. The
pre-C2 tree happened to be bit-invariant on this shape; the C2 tree is not.
Both produce correct output.

## Consequences / corrected posture

- **Not a blocker** for production serving of this model. Remove the
  "blocker" framing from REFACTOR.md.
- It **would** matter only if this route is ever declared `strict` (must be
  bit-stable on retained fixtures) or `batch_invariant` (must preserve the
  request result across widths/slots/admission order). If that is required,
  restore cross-width parity (bisection targets af5d00098 / 29a786afc) or
  keep the route `production`.
- Optional confirmation (nice-to-have, folds into the profiling work):
  measure the step-73 logit margin between 3154 and 6866 in a high-precision
  reference to confirm the flip is a narrow-margin (rounding) event rather
  than a >1-logit error.

## Unchanged

The F1 finding (neither design scales this model; packed c2/c4 step ~5x the
c1 step in BOTH trees, model-specific) stands and is the item to profile
next.
