# Retire MTP compatibility stream-draft rollback

## Summary

Remove the unused compatibility MTP stream-draft rollback reader while
preserving the supported stream path and concrete pre-launch fallback. Move
remaining per-phase worker-pool lifetime work to the bottom of the ledger.

## Changes

- Delete constant/resolver and the single stream-draft call-site env check.
  No script writes the switch. The resident MTP2 adapter has a separate staged
  proposal implementation and does not consume this compatibility reader.
- Replace its ENVS description with a retired/no-reader note; it incorrectly
  described buffered client emission. This reader selected device-stream
  scheduling, not token delivery behavior. The literal remains in regression
  tests, so env-coverage tooling still requires its retirement note.
- Extend existing stream-draft/stream-destruction adapter coverage for unset,
  stale `0` and stale `false`. New policy nodes cover widths 0/1/2/3/4/8,
  one-token tail, missing pending seed and missing runtime sync before launch.
- Move per-phase `ThreadPoolExecutor` work to bottom
  `R0281-MTP-DRAFT-EXECUTOR`, separating compatibility extraction from bounded
  pool lifetime, future draining, deadlines/cancellation and device teardown.
  Do not infer current overhead from historical server timing.
- No kernels, arithmetic, provider semantics or performance claim changes.
