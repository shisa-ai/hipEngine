# Explain PARO versus GGUF MTP draft-acceptance gap

## Summary

The canonical acceptance gap is real but the headline routes are not equivalent.
Strict current-packed PARO B1 accepts `16/214 = 7.48%` drafts and only `16/240 =
6.67%` accepted/output. The retained GGUF headline accepts `80.45%` of drafts and
`60.00%` accepted/output, but it is the explicitly labeled accuracy-traded
`llama-compat` B2 route, not exact/default generation. Automatic GGUF requests
remain on AR because that route is not generated-ID exact against true AR.

## Changes

- **Route contract dominates the comparison.** PARO N4 is gated under serial-c1-
  equivalent target arithmetic and must emit the exact target-AR correction.
  GGUF N1R preserves the existing `llama-compat` trajectory and is exact against
  that route's own target/state/KV lifecycle, not against exact/default AR.
  Therefore the `80.45% vs 7.48%` ratio overstates the production-exact drafter
  quality difference.
- **The remaining model-alignment advantage is still substantial.** The MTP-
  bearing GGUF packages target and trailing `blk.40.nextn.*` tensors together.
  The NextN forward uses the intended post-norm hidden seed, its own attention/KV
  state, and target embedding/output weights when optional draft copies are
  absent. The implementation was developed against a CPU reference and captured
  llama.cpp draft/token contract.
- PARO instead attaches a BF16 sidecar dequantized from the official
  `Qwen/Qwen3.6-35B-A3B-FP8` MTP shard to an independently packed/calibrated
  `shisa-ai/...PARO-packed` target. Shape/dtype/lineage validation passes `19/19`
  and all sidecar payloads match the older assembly, so there is no evidence of
  corruption. But validation does not prove proposal-logit calibration against
  the separately quantized target. The PARO target itself has `92.856%` top-1
  agreement versus BF16, so target quantization/hidden-seed differences can
  compound an already imperfect one-layer drafter.
- **This is not a metric-only illusion.** On the same canonical ten prompts,
  PARO strict accepted/output is `6.67%`, while GGUF llama-compat is `60.00%`.
  Category draft acceptance is PARO/GGUF: code `9.52/93.94%`, general English
  `2.22/75.68%`, general Japanese `2.22/69.23%`, mixed `15.00/72.97%`.
  B1 versus B2 and denominator definitions cannot explain that order-of-
  magnitude accepted/output difference.
- **Runtime optimization did not create GGUF acceptance.** N1R moved the old
  GGUF route from `54.88` to `122.67 tok/s` while acceptance stayed exactly
  `80.45%`; reusable target graphs removed submission wall but did not change
  proposal quality.
- The legacy PARO eight-prompt fast route pools `91/159 = 57.23%` B1 acceptance,
  proving the sidecar can look much stronger on a different prompt/trajectory
  and non-strict verifier path. That diagnostic excludes the failing translation
  row and is not evidence that the strict canonical result is wrong.

## Next

1. Follow the strict target's canonical true-AR trajectory and invoke the MTP
   sidecar from the exact target hidden/state at every token without committing
   speculative state.
2. Record target-token rank/probability in full sidecar logits, top-1/top-k
   overlap, vocab-cap misses, and results by category/train/heldout.
3. Compare native sidecar logits/top-k to the existing torch/reference forward on
   the same captured hidden rows. Also compare the sidecar's documented hidden
   observation/precision against the target tap actually supplied.
4. If native and reference match but target-token rank is poor, the blocker is
   model/sidecar alignment: use an integrated/matched target+NextN artifact or
   regenerate/train the sidecar for the packed target. If they differ, fix the
   proposer implementation/seed/KV contract. If target tokens are usually in a
   small top-k, only then test a generic tree/top-k policy on the full suite.
