# Screening override must read every failed qualification axis, not the summary reason

## Summary

The screening override granted speculative eligibility to cells that failed a
correctness boundary, because both the resolver and the helper reasoned about a
single string: the resolver reported only the first failed qualification axis,
and the helper decided from that one reason. Reproduced before the fix: a plan
failing `candidate_budget_not_qualified` (screenable) and `insufficient_memory`
(structural) returned

```
{'state': 'speculative_capable', 'eligible': True,
 'reason': 'candidate_budget_not_qualified', 'max_candidate_count': 3, ...}
```

from `_mtp_screening_static_eligibility`, so an explicit request could enter the
speculative route on a cell that does not fit in memory.

The masking is not a corner case, because the axis order in `_evidence_checks`
puts both structural axes *after* screenable ones:

```
artifact, backend, arch, weight_quant, kv_storage, kv_layout,
physical_group, resident_capacity, candidate_budget, sampling_mode, memory_fit
```

The reachable instance on the server is the sampling boundary: an explicit
`speculative_mtp` request with `temperature > 0` and `candidate_budget` above the
qualified depth fails both the sampling and the budget axes, reports the
screenable budget reason, and would have been admitted by the override. The
memory-fit instance is reachable through `LLM.resolve_speculative_mtp_serving_plan`
(which takes `memory_fit` from its caller) and through the realized re-resolution
path; the request-time server funnel hardcodes `memory_fit=True`, so that path
was not the live one.

## Changes

- `speculative/serving.py`
  - `SpeculativeMTPServingDecision.failed_axes` carries every failed axis of the
    selected evidence row. `reason` keeps its meaning (the first failed axis in
    declaration order) for diagnostics and response metadata.
  - `structural_rejection` returns the first failed structural axis, so a caller
    does not have to re-derive the set.
  - `STRUCTURAL_REJECTION_AXES = {artifact_identity_unverified,
    sampling_mode_not_qualified, insufficient_memory}` is the single definition
    of the correctness boundaries. It is deliberately not folded into
    `as_dict()["plan_fingerprint"]`: the axes are a pure function of the key and
    the selected row, and both are already covered there, so rejection
    fingerprints stay stable.
  - `_reject` takes `failed_axes`; the rejection loop keeps the full tuple
    instead of collapsing to `failed_reasons[0]` at the point of selection.
- `server/api.py`
  - `_mtp_plan_structural_rejection` reads a plan's failed set (falling back to
    the summary reason for a payload without `failed_axes`, which is the
    pre-existing behaviour).
  - `_mtp_screening_static_eligibility` refuses when any failed axis is
    structural, independently of the summary reason.
  - `_realized_model_serving_plan` applies the same check before carrying a
    request-time screening intent forward. The realized group can fail a
    structural axis the request-time plan did not (memory fit at a wider group),
    and the request-time eligibility must not authorize that. This is a second
    instance of the same class, found while tracing the first.

## Notes

- No GPU run: the change is a pre-mutation admission rule, and the tests above
  cover the resolver, the request-time helper, the realized carry-forward, and
  the live server funnel. Nothing here changes arithmetic, so no profile gate
  applies.
- `docs/REFACTOR.md` records that the invariant is now enforced against the
  failed set and names the single definition of the structural axes, so the
  removal scope for the screening override stays accurate.
- The remaining fail-open shape to watch is any future consumer that branches on
  `plan["reason"]`. `_resolve_realized_generation_route`'s
  `physical_group_not_qualified` deferral is the one other such branch: it is a
  deferral to the resident owner (which re-resolves with the real capacity and
  memory fit), not an override, and it does not grant `static_intent_allowed`.
