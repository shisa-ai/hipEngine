# VibeVoice-TTS session benchmark harness - executable protocol baseline

## Summary

Added `scripts/vibevoice_tts_session_bench.py`, the first harness that reports
the TTS document's four protocol numbers (cold start, warm synthesis, time to
first audible chunk, pooled RTF) with sync-bracketed stage timers, and recorded
its baseline artifact. This entry is written after the fact to close the
bookkeeping gap for commit `9c2194edc`, which landed without an entry.

**Scope caveat (reviewer-identified, see "Next"):** this harness is
fixture-assisted replay, not complete synthesis. It consumes the recorded
prompt embeddings and negative conditions, so it does not exercise the
reference-audio preparation or the negative-LM branch, and it enables trace
downloads during the timed region. Its numbers are diagnostic.

## Changes

- `scripts/vibevoice_tts_session_bench.py` (new): reads
  `tests/fixtures/vibevoice_tts/manifest.json` for the pinned single-speaker
  request, injects the fixture-recorded random operands (`callN_initial_noise`)
  and recorded negative conditions (`callN_neg_condition`) so both lanes consume
  one frozen request, and wraps `sample_speech_tokens`, `decode` and
  `encode_chunk_streaming` in explicit `device_synchronize` brackets to report
  diffusion / decode / semantic as execution wall time. The LM remainder is
  derived as total wall minus those three stages.
- `benchmarks/results/vibevoice_tts_session_baseline.json` (new): the baseline
  artifact. It carries model, quant, workload shape, physical host identity, GPU
  name, exact command, the four protocol numbers, the stage split and a
  `chain_exact` correctness gate.

## Validation

- Measured on the pinned single-speaker request (121 prompt tokens, 27 generated
  ids, 25 diffusion frames, 20 DDPM steps, cfg 1.3), host `zbook`, GPU
  `AMD RYZEN AI MAX+ PRO 395 w/ Radeon 8060S` (gfx1151), command
  `uv run python scripts/vibevoice_tts_session_bench.py`:
  cold start 7.942 s, warm synthesis 7.743 s, pooled RTF 2.323, `chain_exact`
  true. Stage split: LM 3.306 s, diffusion 2.165 s, decode 1.279 s,
  semantic 0.993 s.
- The generated chain equals the frozen oracle's 27-token constrained chain, so
  the timed path is the correct chain even though its operands are injected.
- `chain_exact` is the only correctness gate this artifact carries; it is a
  control/ownership gate, not an audio-quality gate.

## Next

- The GPU identity in this artifact was corrected by the follow-up commit
