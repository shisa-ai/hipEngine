# Add private residual launch planning to GGUF linear runtime

## Summary

RF-10 residual slice. `launch_gguf_linear_residual` previously resolved the
bulk WMMA gate, the explicit rows-1 admission, sidecar priority, the registered
small-row fallback and the composite owner inline while binding pointers. The
public launcher now resolves a private, immutable `_GGUFResidualLaunchPlan` at
the shape/resource boundary and executes it immediately.

The plan carries the backend, shape, weight layout/quant, owner slot, exact
resident weight object, selected operation, primitive and fused `KernelKey`s,
ABI, allocation name, sidecar variant, declared fallback reason and registry
generation. The exact weight owner is retained, but no device pointer value,
allocation choice, callable or scratch is copied into the plan. The public
launcher resolves and executes immediately without caching across launches.
Execution rejects a different weight object even when its
layout/quant/backend/slot metadata matches, then rechecks the registry
generation, owner slot, primitive/composite registration and fetches the current
sidecar or `tiles` allocation before binding pointers.

The plan is intentionally private and has no execution-profile identity. It is
launch-local: callers must re-resolve after a profile or registry change. A
future owner-bound reusable plan needs a token derived from
`ResolvedRuntimeProfile` under RF-1/RF-10, not an `ExecutionProfile` enum.

Public behavior is preserved: `launch_gguf_linear_residual` keeps its signature,
boolean return contract, ambient WMMA/native-session policy, sidecar ordering,
library lookup and launch arguments. The old inline `_launch_registered_linear_residual`
helper became unused after the resolve-then-execute split and was removed.
