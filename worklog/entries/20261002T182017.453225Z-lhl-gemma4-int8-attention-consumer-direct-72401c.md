# Gemma4 direct INT8 per-token/head decode attention consumer

## Summary

Second bounded Gemma D12 prerequisite: the strict direct consumer for the
BF16-source per-token/head INT8 KV writer. The writer stores an INT8 payload
plus a per-token/per-KV-head FP16 or FP32 scale; this unit adds a decode
attention kernel that reads exactly that representation and reconstructs K/V as
`float32(int8) * float32(scale)` in FP32, plus an independent CPU representation
oracle. It is a single-row decode consumer over `KVLiveSpans`.

The BF16 Gemma 4 attention family is untouched. This is a new sibling file, not
a change to the BF16 kernels, and there is no runtime/config/owner wiring and no
whole-D12 integration in this unit.

## Numerical contract (strict)

Defined on the quantized representation, not on the original BF16 rows:

* Reconstruction is `float32(int8_payload) * float32(scale)`, where the stored
  scale is widened from FP16 or FP32 to FP32. This matches the writer codec and
  the existing `dequantize_kv_int8_per_token_head` CPU reference.
* One masked decode row per query head, GQA map `kv_head = q_head / (Hq/Hkv)`.
* `logit = (sum_d q[d] * K[j,d]) * scale_param` (Gemma 4 passes `scale=1.0`).
* Keep semantics are span-native: a logical slot is visible when it is not
  evicted, its absolute `token_positions` entry is non-negative and no later
  than `row_positions`, and -- on a sliding layer -- strictly inside
  `sliding_window`. When the span carries no position/eviction tensors the dense
  fill is uniform: slot `j` sits at position `j`, the query at `context_len - 1`.
* A masked key is `-inf` in the max, `0` in the denominator, and `0` in the
  weighted value sum. An all-masked row returns zeros, never NaN.
* The oracle is compared on that same representation. The agreement is FP32
  `expf`/reduction-order level (`rtol=1e-3`, `atol=3e-4`), not bit-exact,
  because the oracle uses NumPy `exp` and a BLAS dot while the kernel uses
  `expf` and a warp tree. The original unquantized FP32 fixture rows are compared
  only diagnostically (correlation > 0.95 on the same mask). This fixture does
  not establish writer-to-consumer integration or BF16-source quality.

## Repair: empty-span, metadata-bounds, and non-finite hardening

Parent and fresh-source review found five in-scope defects in the consumer and
its oracle. All five are repaired here, still without wiring or commits.

### Findings and repaired behavior

1. **Physical page id out of range.** The wrapper validated only the logical
   block-table *length*, and the kernel indexed `base_offsets[logical_block]`
   with no physical bound, so a negative or `>= cache_blocks` id read out of
   bounds. Repaired with a checked host-side readback of the page-table prefix
   (`_read_device_metadata` + `_check_device_metadata`) that raises a named
   `ValueError` before launch, plus a kernel guard that writes a NaN row on a
   visible out-of-range id. The checked path is synchronous by design; the
   module docstring states it is not the async hot path.
2. **Live count above capacity silently truncated.** The kernel clamped to
   `capacity` and returned a success-shaped prefix. Repaired: a count above
   `max_context_len` is reported (`ValueError` on the checked path; NaN row in
   the kernel), never a truncated success. Empty (`0`) stays supported and is
   distinct from a negative count, which is also reported/NaN.
3. **Single-row contract not enforced.** The wrapper accepted multi-entry
   `live_counts`/`row_positions` and a rank-2 page table. Repaired: exactly one
   live count, exactly one row position, and a 1-D `base_offsets` are required
   before build. `KVLiveSpans` already aligns `row_positions` to `live_counts`;
   the wrapper check is the defensive second line, tested by bypassing that
   upstream guard.
4. **Inconsistent non-finite handling.** The GPU included a visible `+inf` in
   the maximum then discarded it (treated as masked); the oracle discarded it
   before the maximum. Repaired with one policy on both sides: a *visible*
   non-finite logit is a failure and yields a NaN row (never a masked key and
   never a success zero); a masked slot never participates.
5. **Masked NaN/Inf scale leaked into the oracle.** `weights[:, None] * values`
   produced `0 * NaN = NaN` for a masked slot. Repaired with
   `np.where(keep[:, None], weights[:, None] * values, 0.0)` so masked slots
   contribute exactly zero; a visible non-finite V still propagates as NaN.

Coverage repairs: repeated launches are now compared to each other
bit-exactly; a mixed visible/future/negative `token_positions` case is added; a
non-positive `sliding_window` is normalized to global on both sides (the oracle
previously raised); and non-contiguous `k_scale`/`v_scale`/`base_offsets`/
`live_counts`/`token_positions`/`evict_mask`/`row_positions` are refused.

### API / ABI deltas

- Kernel and both `extern "C"` wrappers take a new `int64_t cache_blocks`
  argument after `capacity`.
- Kernel shared memory grows by `_NUM_WARPS * 4` bytes for the per-warp
  non-finite flags (host check updated to match).
- The wrapper performs a synchronous device-to-host read of the live count, row
  position, and page-table prefix before launch. This is the checked path; a
  future async caller would validate once at admission and rely on the kernel's
  defensive guards.
- `sliding_window <= 0` is now global on both sides.

## Repair 2: stream ordering, visible non-finite V, canary proofs

A second focused review confirmed the prior five repairs and found three more
in-scope gaps plus coverage/doc fixes. All are repaired here; no commits.

### Findings and repaired behavior

1. **Stream ordering of the checked readback.** The wrapper accepts ``stream``,
   but the synchronous ``hipMemcpy`` used for the metadata readback is not
   ordered against a non-blocking producer stream that wrote the metadata.
   Repaired: ``_read_device_metadata`` now calls
   ``runtime.stream_synchronize(stream)`` before the D2H read when a non-zero
   stream is supplied. The module docstring states the checked path makes no
   graph-capture or async promise.
2. **Visible non-finite V was weight-dependent.** The kernel skipped
   underflow-zero-weight slots (``if (!(weight > 0)) continue``), so a poisoned
   visible V was silently dropped; the oracle only propagated it through
   ``weight * value``, so a positive-weight ``inf`` V returned ``inf`` instead of
   the promised NaN. Repaired on both sides: a visible slot whose reconstructed V
   is non-finite is a failure independent of its softmax weight. The kernel scans
   visible reconstructed V in pass 1 (any lane, warp/block OR); the oracle checks
   ``np.isfinite(values[keep])``. The failure is head-local: only the query heads
   mapped to the poisoned KV head fail.
3. **Non-finite tests could not prove a write.** The old tests poisoned the
   output with NaN and asserted NaN. Repaired: the direct-symbol tests start the
   output at a finite sentinel (7.0) with finite canaries on both sides, and
   assert every affected dim is NaN and the canaries are intact. Head-local
   isolation is asserted separately (one KV head poisoned -> only its GQA heads
   NaN).

Coverage and docs:

- Direct-symbol guard tests reach the kernel's own guards with allocated
  metadata and a bounded cache: empty -> zeros, negative/over-capacity count ->
  NaN, visible out-of-range (and negative) page -> NaN, all with canaries intact
  and no out-of-bounds access. A masked out-of-range page is *not* a failure
  (never dereferenced) -> zeros.
- A live non-blocking stream test seeds the live-count buffer with an invalid
  count and enqueues a valid one on a non-blocking stream; the ordered readback
  must see the valid count and launch cleanly.
- Repeat-exactness comparisons use a ``uint8`` byte view (signed zeros / NaN
  payloads cannot hide behind a float compare).
- The module docstring now states the host/device split explicitly: the host
  raises ``ValueError`` for structural invalidity (a malformed count or an
  out-of-range page id anywhere in the live prefix, **even a masked slot**); the
  device fails only a *visible* invalid page and reports a numerical failure
  (non-finite visible logit or reconstructed V) as a NaN row.
