# Wire DMS INT8 native MTP through library and serving

## Summary

The user requested that the implemented DMS INT8 transaction path become
reachable through the library and HTTP server. The follow-up also requests an
inventory and matched comparison of available sidecars, distinguishing the local
W256/2x external linear sidecar from published W8192 policies. No subagents.

## Changes

- Add `dms_metadata_path` to LLM and server configuration, with CLI forwarding.
- Carry the selected compact codec into resident sessions without applying dense
  INT8 evidence to a different retention topology. An optional codec quality
  record remains evidence, not a prerequisite for instantiating the codec.
- Use existing singleton engine ownership, complete-prompt DMS capture, native
  NextN prompt streaming and serial-exact transactional target verification.
- Require one resident request and disable prefix caching by default for DMS;
  explicitly requested packed residency or prefix snapshots fail by name because
  those session ownership contracts are not implemented.
- Reclaim completed DMS sessions rather than resetting freed dense prefill planes.
  The next request constructs its own session with shared model weights.
- Report compact-store diagnostics, including window and selection policy.
