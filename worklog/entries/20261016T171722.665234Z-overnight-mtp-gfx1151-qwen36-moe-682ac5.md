# gfx1151 Qwen3.6 MoE MTP lane

## Summary

The first live Qwen3.6-35B-A3B gfx1151 run found the generic server depth default of 3 exceeded the MoE adapter's executable depth of 2. The default-depth resolver now clamps the automatic budget to the model plugin's declared backend capability. A rerun resolved MTP automatically at depth 2 and served greedy MTP.

## Changes

- `Qwen35MoeGGUFModel` keeps the existing gfx1100 declaration and adds a separate gfx1151 declaration.
- `Qwen35GGUFGenerator.speculative_candidate_budget_default()` now bounds the generic default by automatic implementation declarations for the active backend and BF16 storage.
- The gfx1151 MoE declaration is C1-only for automatic physical prompt streaming; concurrent rows can serialize/AR rather than falsely entering the rejected multi-row streaming category.

## Validation

- Before fix: startup reported `MTP unavailable (mtp_candidate_depth_unsupported)` and both greedy and sampled requests used AR.
- After depth fix: startup reported `MTP enabled`, `default_enabled=true`, candidate budget 2, context `2,048 / 262,144`.
- Live greedy request: HTTP 200, route `speculative_mtp`, used true, accepted/rejected prediction tokens 6/3, acceptance rate 0.6667.
- Live sampled request before the C1-only declaration adjustment: route selected MTP but the provider declined with `physical_streaming_category_rejected`, so it fell back to AR. The C1-only declaration adjustment is intended to make singleton sampled requests eligible while allowing concurrency to serialize/AR.
