# C2-7 U4: DMS compact decode attention HIP kernel, KL/top-1 gate

## Summary

Continues the campaign (U1 = 9791576ad, U2 = 3cd91e060, U2b = 11e6c78a7,
U3 = 3c82f447a). U4 lands the attention half of the C2-7 BF16 no-shadow
port: GQA decode attention over the dense-in-extent DMS storage written
by the pack/append kernels. The `cpu_reference` sibling
(`compact_attention_reference`, pre-registered as the strict fallback
under the same four-axis key) is the oracle.

## Changes

- `dms_compact_attn_decode_kernel` (+ launcher
  `hipengine_dms_compact_attn_decode_bf16`) in `dms_compact.hip`: one
  workgroup per (row, q_head); K/V rows read from the slot-major extent
  at `base_offsets` for `live_counts` rows (no block table — the compact
  extent is dense per head). Numerics mirror the paged decode kernel
  (lineage: nano-vllm-amd@59195ed via `qwen35_full_attn_decode_impl`):
  fp32 score accumulation, tree max, `expf` softmax with a
  floored denominator, fp32 P@V. `live == 0` writes zeros (the host
  oracle rejects live=0, so zero is the defined safe neutral);
  `live == 1` is bit-exact (single-element softmax is exactly 1).
  Shared memory is dynamic, sized `2 * score_capacity * sizeof(float)`
  by the launcher.
- `dms_compact_attn_decode_bf16` ctypes wrapper (FP32 Q/out, BF16 K/V
  slot buffers, `[rows, kv_heads]` extent arrays, `scale`,
  `score_capacity`) + registration
  `("hip_gfx1100", "dms_compact_attn_decode", "bf16", "grouped_gqa")`
  + `attention/__init__.py` export. Updated the family docstrings (the
  append wrapper docstring still described the pre-U3 single-drop
  steady-state behavior; it now describes the strict parent walk).
- RED test `tests/test_dms_compact_attn_decode_hip.py` (5 tests, 3 GPU):
  registration/build-plan, wrapper validation, bit-exact
  live-0/live-1 structural cases, and KL/top-1 gates at small
  (4x2xgroup2xD16, variable live) and production-adjacent geometry
  (2x4xgroup2xD128, live up to 40) plus a determinism re-run inside
  each gate case. Slot buffers carry NaN canary bits past each head's
  live count so any out-of-extent read corrupts the output.

## Validation

- RED-first: 5/5 ImportError before the kernel landed.
- 5/5 green after, on this W7900 host (2026-08-18). Measured gate
  quality: max softmax KL 4.2e-16 and zero non-tie top-1 flips on the
  gate fixtures (device vs oracle max abs diff 2.98e-8 — the kernel is
  within fp32 rounding of the reference; the headline gate is 0.05/90%).
- Neighbor gates green alongside: the full DMS suite
  (`test_dms_compact_attn_decode_hip` + `test_dms_append_decode_hip` +
  `test_dms_streaming_pack_hip` + `test_dms_extract_decision_hip`) and
  `test_kvcache_dms.py` (17/17). Lint clean on touched files.
- Test-design notes: the live-1 exact expectation must be the
  bf16-quantized V row (the kernel reads bf16 bits, not the original
  FP32); and top-1 must be tie-tolerant (candidate top value within a
  fp32 epsilon of the reference top value) because bf16-quantized data
  produces exact ties in the oracle output that a 1-ulp rounding
  difference flips (observed: two exactly equal 0.388671875 entries in
  one gate row).
