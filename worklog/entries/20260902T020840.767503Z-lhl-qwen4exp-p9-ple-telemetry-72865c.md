# Add opt-in PLE pipeline telemetry

## Summary

Added opt-in per-request PLE mmap/staging/H2D telemetry and proved it on the
real warm canonical p512 path. Instrumented wall is diagnostic only.

## Changes

- `Qwen4ExpPLEMMapTable` now reports requested/unique rows, source bytes,
  unique/adjacent pages and compact runs, cache advice/range, process fault
  proxies, and gather/dequant wall only after explicit enablement.
- The staging ring records copy wall and accepts H2D wall/bytes from the runner.
- Canonical AR adds `--ple-telemetry` and embeds a reset per-request snapshot.
- Added CPU tests and compact evidence; closed the P9 instrumentation item,
  reducing open-or-partial count 37→36.

## Validation

- `uv run pytest -q tests/test_qwen4_exp_residency.py tests/test_qwen4exp_canonical_ar_bench.py`: 16 passed.
- Real production code-p512 under `auto` clocks: 129 calls, 10,240 requested /
  4,216 unique rows, 4,297 unique pages, 86 adjacent pairs, 921,600 source bytes,
  1,310,720 H2D bytes, 2,959/2,611 minor/major process-fault proxies, 5.670-s
  gather/dequant, 0.825-ms copy, and 19.207-ms H2D.
- Output SHA-256 `b2b0d957...` remains canonical; teardown is zero.
- W=19.066-s instrumented complete wall, C/s not applicable, observed nested PLE
  owner=5.690 s. T0 observability only; telemetry defaults off. Nested timing is
  excluded from performance and kernel buckets.
