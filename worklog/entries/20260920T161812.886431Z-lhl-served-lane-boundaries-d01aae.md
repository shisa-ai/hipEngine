# Serve radix prefix caching by default; the gfx1100 numerical gate stays open

## Summary

`hipengine serve` now defaults `--prefix-cache radix`, matching the in-process
engine loop. The owner set this default on 2026-09-20 as a production call, with
the outstanding gfx1100 numerical qualification assigned to another worker.

This supersedes the "keep HTTP `--prefix-cache off`" instruction in
`docs/REFACTOR.md`, and the default-off state recorded in
`worklog/entries/20260920T155434.502352Z-lhl-served-lane-boundaries-bc9b95.md`.
Both entries remain accurate as history: the measurements below are unchanged,
and none of them is withdrawn. What changed is who holds the default.

## Why the flip is contained

The path fails closed per request rather than at admission or startup, which is
what makes the default safe to set before the numerical gate closes. An
unqualified row falls back to a private prefill and records
`row.prefix_fallback_reason`, so a bad row costs the reuse, not the response. The
reason vocabulary is `cache_off`, `sampling_unsupported`, `prompt_too_short`,
`miss`, `full_prompt_boundary_requires_suffix`, and `state_source_unavailable`
(`hipengine/generation/qwen35_gguf.py`).

Rollback is one flag or one variable: `--prefix-cache off`,
`HIPENGINE_PREFIX_CACHE=off`.

## What the default does and does not reach

`_prefix_reuse_supported` requires either `native_greedy` or a sampled plan whose
mode is `PROCESSED_ARGMAX`. The served GGUF path samples on the host by default
(`HIPENGINE_QWEN35_NATIVE_SAMPLER` is unset, so `_native_gpu_sampler_requested()`
returns False), and any non-greedy plan is `native_sampled`, not
`native_greedy`. So:

- greedy traffic reuses prefixes;
- temperature/top-p traffic records `sampling_unsupported` and prefills
  privately, costing nothing but the reuse;
- the multi-turn economics measured below therefore only materialize on the
  greedy route until the native sampler is wired. That is the same
  capacity-wiring defect recorded in the superseded entry
  (`packed native sampler row 0 exceeds capacity 0`), and it now gates the
  benefit of this default as well as the sampler's own cost.

## What is still open

The gate that previously held the default off, unchanged and unmeasured on
current HEAD:

- `benchmarks/results/2026-09-20-w7900-gfx1100-prefix-gate-bf16.json`: six
  active-lifecycle scopes fail the scheduler state-byte comparison (120
  final-state component mismatches); `heldout-code` exceeds the
  `docs/EXECUTION-PROFILES.md` section 6.1 mean/max KL ceilings (`2.264e-3` vs
  `1e-3`, `0.2753` vs `0.05`). Only the two completed-lifecycle `general_ja`
  scopes pass all eight binding terms.
- `benchmarks/results/2026-09-20-w7900-prefix-completed-code-control.json`: the
  completed-source parent control has exact scheduler state and 100% top-1, but
  mean/p99/max KL of `0.00678/0.12955/0.67657` still exceed the calibrated
  limits. Root cause is unlocalized.
- The A2 packet rejects the agentic economics on W7900: radix hits 0/12, 3/24
  and 3/18 C1 turns and regresses active-SSE goodput 64.19%/65.63%/26.64%.
- HTTP-default INT8 scale-plane/suffix/reclaim/pressure checks have not been run.
- Two prefix-path commits (`c56a0c9dc`, `ae199dc68`) postdate the W7900 packet.

`docs/REFACTOR.md` now states the default and carries this list as the close-out
condition rather than as a reason to keep the default off.

## Changes

- `hipengine/server/__main__.py`: `--prefix-cache` default resolves through
  `resolve_prefix_cache_mode(os.environ.get("HIPENGINE_PREFIX_CACHE"))`, which
  yields `PREFIX_CACHE_DEFAULT` when unset, so the env var stays an override of
  the flag instead of a second default.
- `hipengine/server/api.py`: `ServerConfig.prefix_cache` takes
  `PREFIX_CACHE_DEFAULT`.
- `hipengine/kvcache/radix.py`: the default's comment now covers both entry
  points and names the open gate.
- `tests/test_integration_server_api.py`: the pin returns to
  `PREFIX_CACHE_DEFAULT`, with the reason and the rollback recorded.
- `docs/ENVS.md`, `benchmarks/README.md`, `docs/REFACTOR.md`: the default is
  stated as `radix` for both surfaces, with the open gfx1100 gate and the
  `--prefix-cache off` rollback.

## Validation

- `build_parser().parse_args(["--model", ...]).prefix_cache` returns `'radix'`
  with `HIPENGINE_PREFIX_CACHE` unset, `'off'` with it set to `off`, and `'off'`
  for an explicit `--prefix-cache off`; `ServerConfig(model=...).prefix_cache` is
  `'radix'`.
- `uv run pytest tests/test_integration_server_api.py tests/test_unit_server_log_style.py
  tests/test_unit_kvcache_policy.py tests/test_unit_bench_env_preflight.py -q`:
  exit 0.
- Live `gfx1151` server, no serving flags, startup summary and `/ready`:
  `Prefix cache radix (256-token blocks)`, `prefix_cache.mode == "radix"`,
  `KV cache bf16 (fp32 scales)`, `Speculation MTP enabled, candidate budget 3`.

Not measured here: no multi-turn served workload was re-run against the new
default, so the `-18.6% wall` figure is cited from the gfx1151 packet rather than
re-measured, and no W7900 gate was re-run. The `sampling_unsupported` reach above
is read from `_prefix_reuse_supported` and the sampler-plan construction rather
than observed in a served trace.
