# Reuse stateless scratch across Flash-Next mixed passes

## Summary

Mixed-target stateless scratch is now batch-owned and reused up to its largest
allocated row capacity. Device and public-serving checks pass. No arithmetic,
execution profile, or flag changed.

## Changes

- The batch runner owns token, embedding, residual, logit, GDN/QSA layer and
  output-head scratch. Growth allocates the replacement before releasing the
  previous capacity; failed allocation leaves the previous set usable.
- An exclusive lease prevents two live passes from overwriting shared scratch.
  Parent review found and fixed the initial implementation's multiple-borrow
  hole. Closing a pass releases its lease and provisional state; closing the
  batch releases retained scratch.
- Request-dependent GDN, QSA and PLE state remains per-pass. Uploads and readbacks
  specify the active row extent rather than the retained buffer capacity.
- Added CPU ownership/failure tests and a GPU growth/shrink/repeat test that also
  checks prior host results remain unchanged.

## Validation

- The implementer reported RED-first CPU coverage. Parent independently ran 98
  focused cases covering scratch, mixed target, batch runner, mixed serving,
  lifecycle and public telemetry; all passed.
- `uv run pytest` could not find a pytest executable in this environment.
  `.venv/bin/python -m pytest` runs successfully and was used instead.
- The CPU deterministic bundle (`bg-66`) passed: compileall, default unit suite,
  fixture validation, registry and CPU-fixture smoke, and the build-plan smoke.
  The 33 focused GPU tests passed as `bg-67`, including growth/shrink/repeat,
  mixed target and batch runner checks. Real HTTP requests exercised the shared
  MTP target and AR-peer routes at physical width two. Public counts agree with
  diagnostics (MTP: 76 proposed, 43 accepted, 20 cycles; AR: zero speculation).
  Both 64-token responses match the pre-reuse witness token IDs. The capture
  verified unchanged runtime source. Exact commands, environment, source hashes
  and responses are under `/tmp/qwen38fn-serving-followup/scratch-reuse-*`.
  The first parent route assertion used an incorrect substring; checking the
  two exact documented route names passes.
- No performance improvement is claimed. Existing numerical and task-quality
  failures remain separate, unresolved campaign requirements.
