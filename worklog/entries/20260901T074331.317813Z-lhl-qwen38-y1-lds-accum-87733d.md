# Qwen3.8 Y1 LDS accumulator one-sweep rejected

## Summary

Implemented and screened an exact Q4T16 single-sweep prototype for rows<=384.
One workgroup owned one 16-column output tile, held all rows' FP32
accumulators in LDS across K256 slabs, and used `Grid_Size_Y=1`. The design is
bit-exact but loses badly on an actual rows288 K5120/N6144 matrix:
**1.103 -> 1.712 ms (+55.1%)** versus retained shared-B2W2 and **+36.6%**
versus the strict shared-B parent. FP32 LDS accumulator traffic and reduced
output-column parallelism cost more than the eliminated weight sweeps.

## Changes

- Added the candidate HIP body, wrapper, explicit gfx1151 registry variant,
  microbench route, and RED registration/capacity tests during the screen.
- Scope-reverted all uncommitted candidate source and tests after rejection.
  The exact candidate patch and measurement are hash-preserved in
  `benchmarks/results/2026-09-01-gfx1151-qwen38-y1-lds-accum384-rejected.json`.

## Validation

- Small K256/N16 fixture compiled and passed bit-exact output against all seven
  strict siblings.
- Actual K5120/N6144 rows288 fixture passed bit-exact output (`max_abs=0`) for
  the candidate and every sibling; 1 warmup + 3 measured iterations.
- Physical AMD Ryzen AI MAX+ 395 / Radeon 8060S (`gfx1151`), cache-only after
  the initial candidate build. Exact commands/raw hashes are in the artifact.

## Next

- Reject FP32 partial accumulation in LDS/global memory for Y1. The remaining
  plausible path is operation-complete persistent/cache reuse without partial
  spills; size the dual gate/up owner separately because it dominates rows536+
  and already exposes one workgroup-owned row loop.
