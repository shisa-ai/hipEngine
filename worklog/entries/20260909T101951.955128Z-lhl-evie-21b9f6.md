# EVIE HIP fp32 runtime: full-pipeline GPU parity

## Summary

`hipengine/runtime/evie.py` (`EvieRunner`) runs the complete EVIE-4.5B
pipeline on the HIP device (gfx1151 / Strix Halo) in fp32 and matches the
torch fp32 oracle fixture end to end: query embeddings max 1.9e-06, doc
embeddings max 3.0e-05, MaxSim 5.9113851 vs reference 5.9113932 (8e-06),
bit-repeatable across invocations.

## Changes

- `hipengine/kernels/hip_gfx1100/evie/evie_ops.hip|py`: 20 fp32 kernels —
  delta-form RMSNorm, LayerNorm(+bias), residual add, SwiGLU, tanh/erf GELU,
  sigmoid gate, per-row L2 norm, row softmax, GDN gates (sigmoid beta,
  exp(-exp(A_log) softplus(a + dt_bias)) decay), GDN q/k l2norm+scale+head-
  repeat (stride-aware), GDN RMSNormGated with silu(z), row-strided mRoPE
  rotate_half, fused q/gate split, head expand/gather (with transposed-v
  variant for GEMM W layout), head scatter, broadcast bias add, scale,
  embedding lookup with visual-feature injection, scaled add. Classic
  shared-memory tree reductions (wave-size agnostic).
- `hipengine/runtime/evie.py`: EvieRunner — rocBLAS SGEMM for all
  projections, qwen35 conv prefill kernel, qwen35 GDN recurrent prefill
  kernel, per-head gather/scatter attention (vision bidirectional + text
  full-attention with GQA repeat and sigmoid gate), vision tower (patch
  embed GEMM + bias, host bilinear pos-embed resample, 2D rope in packed
  qkv, merger), Prefix-MRL head, encode_query / encode_document.
- `hipengine/loading/evie.py`: weight tails padded + fully committed for
  rocBLAS tile overreads.
- Allocation discipline: every GEMM-touched buffer is padded (1 MiB) and
  zero-committed at malloc; on APU/GTT systems demand-mapped pages that are
  read before first write abort the process with "page not present".

## Bugs found on the way (all fixed, all unit-tested after)

1. GDN l2norm-repeat kernel assumed dense (tokens, kv_heads, dim) source;
   the conv output is (tokens, 8192) with q/k/v planes per row — needed
   src_stride + k_offset.
2. GDN v plane needed dense expansion for the recurrent kernel.
3. Attention value GEMM needs W=(out, in) = transposed v (gather-TP kernel).
4. The conv prefill kernel CHAINS conv_state (mutates it); it must be
   re-zeroed before every GDN layer. State layout is (channels, kernel_size)
   with slot 0 unused — undersizing it reads OOB.
5. Missing vision biases everywhere except patch embed (qkv, proj, fc1, fc2,
   merger fc1/fc2) — PyTorch Conv3d/Linear biases.
6. Debug-methodology trap: passing a temporary numpy array into
   host_array_ptr() frees the buffer before the H2D copy reads it —
   intermittent "sin data in the cos buffer" corruption. All runner uploads
   hold named references.

## Validation

- Kernel unit tests vs numpy formulas: all within 1e-6 (rope 2.4e-07,
  gates 1.2e-07, l2norm-scale-repeat 7.5e-09, softmax 1.5e-08, recurrence
  via the existing qwen35 prefill kernel verified against the closed-form
  1-token case and torch captures).
- Full-pipeline vs `tests/fixtures/evie/evie_4p5b_doc_query.npz`:
  query emb max 1.9e-06, visual features max 6.4e-05, doc emb max 3.0e-05,
  MaxSim 8e-06, deterministic repeat.
