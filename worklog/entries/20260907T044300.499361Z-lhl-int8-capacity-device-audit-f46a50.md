# Audit dense INT8 capacity failure and missing DMS device codec

## Summary

The user assigns both dense INT8 repair and DMS INT8 implementation to this
worktree. There is no separate INT8 owner. The prior campaign's completion
claim did not establish a functional long-context INT8 path or device-backed
DMS INT8. The current cold-server reproduction fails at 16,128 declared
context (16,111 actual prompt tokens) with HIP error 1 at 20.3566 GiB.
The isolated native-prefill test reproduces the same launch error above its
64 KiB shared-memory limit. The audit is complete; the repair and DMS
implementation remain open tasks. No repaired capacity result is claimed.

## Changes

- Audited the local Q4_K_M capability row in `hipengine/models/qwen35.py`:
  exact artifact `7b2aec3b...`, FP32 per-token/head scales, physical C1,
  logical serial residency through C4, no persistent BF16 mirror. This does
  not qualify native multi-row prefill or graphs, Q4_K_S, or DMS composition.
- Audited `_plan_gguf_int8_prefill_lifetime` in
  `hipengine/runtime/qwen35_gguf_runner.py`: chooses between per-layer BF16
  oracle caches and one shared oracle with full-length hidden buffers.
  Compact steady-state KV therefore does not imply a 2x total capacity gain.
- Native BF16 oracle prefill launch in `paged_attn_decode.hip` allocates
  `(max_context_len + threads + head_dim) * 4` dynamic shared bytes. With
  64 threads and D256, contexts above 16,064 exceed 64 KiB. This is a
  confirmed isolated launch defect and a candidate explanation for the
  measured server boundary; connection to the failing server call still
  needs a traceback or launch trace.
- DMS device INT8 is not just missing a qualification artifact:
  `DMSCompactBackend.__init__` explicitly rejects non-BF16 device payloads;
  `DMSDevicePayloadStore` resolves BF16-only pack/append/attention keys and
  allocates two-byte K/V slots; resident finalize explicitly constructs
  `create_dms_bf16_backend`. CPU codec qualification cannot enable this path.
- `scripts/dms_backend_gate.py` constructs the CPU-backed implementation
  unless device payloads are separately enabled. Its lifecycle verdict is
  not proof that INT8 device kernels ran.
- Added an uncommitted isolated native-prefill RED candidate at contexts
  15,872/16,128/81,920. Q=0 gives analytic uniform attention over BF16 V;
  this separates launch capacity from model quantization. The 15,872 case
  passes its oracle, 16,128 fails at the HIP launch, and 81,920 was not run
  because pytest stopped at the first failure. This test is reserved for
  the subsequent validated repair commit, not this audit-only commit.
