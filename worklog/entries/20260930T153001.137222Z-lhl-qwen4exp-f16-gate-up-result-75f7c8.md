# The F16 gate/up route is the tightest non-exact route measured, and it still fails the binding prefill scope

## Summary

`MX-1` is the ledger's largest remaining lever — the routed-expert repair is
**1,219.978 ms = 7.75%** of the 15,741.963 ms prefill union — and its route is "F16
routed experts with **no repair**". Reconnaissance found that route already ships
(`gguf_q4_k_selected_dual_wmma_prefill_compact_kernel`, `wmma_f32_16x16x16_f16_w32`
with F32 accumulate, dual gate+up), so this was a measurement rather than the
from-scratch port the row was priced as.

**Result: it fails the layer2 envelope.** `hard_gates_passed: false`, `decision.next:
"reject candidate and keep strict fallback"`. But it fails **better than any
alternative route** and against a bar production meets exactly, which is what makes the
result decisive rather than merely negative.

| metric | **F16 compact** | plain iu8 | limit |
| --- | ---: | ---: | ---: |
| mean KL | **4.5837e-4** | 5.2778e-4 | 1e-3 |
| p95 | **2.5307e-3** | 2.8062e-3 | 5e-3 |
| p99 | **5.1165e-3** | 5.2674e-3 | 2e-2 |
| max | **6.3267e-3** | 2.4688e-2 | 5e-2 |
| top-1 | **0.99778** | 0.99556 | 0.99 |
| over review boundary | **0** | 1 | — |

The failure is per-scope, on the same 18 `prefill_last` rows: **mean 1.127e-3 (1.13x
over) and p95 5.067e-3 (1.013x over)**, with p99 5.665e-3, max 5.815e-3 and top-1 1.0
all passing. The plain-iu8 route was 2.16x and 1.56x over on the same two metrics and
also failed p99.

## What this establishes

1. **MX-1's admissibility prediction is confirmed.** F16 is the tightest non-exact
   operand class measured: better than plain iu8 on every metric, 3.9x better on max.
   The "8.0-9.5x below the BF16 floor already in the path" prediction shows up as real
   headroom.
2. **It still fails, against a bar production meets exactly.** Production's iu8-risk
   route carries the repair so its gate/up arithmetic is **bit-identical to the strict
   parent** — zero deviation from the strict teacher by construction — while this route
   sits at 1.127e-3 on the binding scope.
3. **The repair is load-bearing on the prefill path in every configuration tested.**
   Two routes fail it and F16 is the best non-exact one available, so removing the
   repair is not reachable by operand class.
4. **The binding constraint is a scope, not a kernel.** The failure is an 18-row scope
   at a 1e-3 mean limit — the scope the ledger's own `prefill_last`-row work already
   flagged as "a scope-and-threshold question for the qualification packet, not a kernel
   question". **This entry does not resolve that question and the result is not a pass.**

## The full route

`MX-1` as specified also replaces the **down** leg with F16. Reconnaissance found that
owner too — `qwen4_exp_q5_1_selected_grouped_wmma_prefill_compact_bf16_bf16_out` calls
`__builtin_amdgcn_wmma_f32_16x16x16_f16_w32` — and the down dispatch tests
`exact_grouped_down` **before** `q5_wmma`, so the full route needs **three** flags:
`EXACT_GROUPED_Q4=0` + `EXACT_GROUPED_DOWN=0` + `Q5_1_WMMA=1`.

**Engagement verified for the full route: 47 F16 gate/up calls + 43 F16 down calls,
zero repair calls on either half.** The counts are not 48 each because layer 2's
gate/up is Q5_K and 5 down layers are Q8_0 — matching the ledger's tensor census
(94 Q4_K / 43 Q5_1 / 2 Q5_K / 5 Q8_0).

Gate candidate `mx1_full_route` is registered and the gate is **running**. Its
expectation is that it cannot be better than the gate/up-only result measured here,
since the F16 down adds its own error — but that is a prediction, and the run is what
decides it.
