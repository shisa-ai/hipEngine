# rf-m5-zero-bound-routed-to-whole-batch-ar

## Summary

- docs/REFACTOR.md's wide-MTP-groups entry (found 2026-09-19) and RF-M5 were the
  open ledger items for the MTP serving path; this unit closes both recorded
  defects instead of leaving the engine half masked by admission caps.
- Root-cause chain of the 2026-09-19 width-8 fail-open: (a) config drift — the
  production width-depths table listed `(8, 3)` while the gfx1151
  prompt-streaming policy admitted only `(1, 2, 3, 4)`; (b) capability used to
  route by sink refusal rather than priming source, so cycles ran against a
  provider with no prompt state; (c) `_maybe_run_partitioned_speculative_decode`
  read the partition owner's zero bound (RF-M5's over-width AR instruction) as
  "do not partition" and fell through to whole-item speculative cycles.
- The incident half was already repaired by 9c8ff5444 (cell withdrawal) and
  3edac59c9 (priming-source routing). What remained was the engine's zero-bound
  semantics, reachable whenever capability could grant the wide cycle — this
  unit proves that with a regression test rather than arguing it from the
  current admission caps.

## Changes

- `hipengine/generation/engine_loop.py`: a zero partition bound now returns one
  whole-batch AR step (`_run_ar_decode(work)`) instead of `None`; the comment
  cites RF-M5 and the width-8 fail-open.
- `tests/test_unit_specdec2_engine_loop.py`: new `_WideWholeBatchARRunner`
  (wide-capable capability + zero bound) with
  `test_zero_partition_bound_stops_a_wide_capable_runner_from_cycling`. RED:
  pre-fix code planned a full 5-wide speculative cycle under a zero bound
  (`specdec2-cycle:1`, candidate counts `(1, 1, 1, 1, 1)`). GREEN post-fix:
  no cycle plans, two whole-batch AR ticks. The old zero-bound test lost its
  two `last_speculative_plan` asserts because the zero-bound path no longer
  enters the speculative resolver (mechanism change — recorded here as the
  rationale).
- `tests/test_unit_qwen35_gguf_mtp2_seam.py`:
  `test_capability_refuses_a_row_whose_prompt_sink_was_refused` pins the
  3edac59c9 fail-closed contract (streaming-refused row → capability `None`
  with `provider_state_absent`, `_states` untouched). Preservation guard for
  existing behavior, so no RED phase applies.
- `docs/REFACTOR.md`: the wide-MTP-groups and RF-M5 entries are marked
  RESOLVED with their three-step resolution. RF-M5 records the decision to
  KEEP the partitioner-level threshold (it is the zero-bound signal the engine
  maps, not a redundant defense) and that no C5-C8 remeasure row is claimed
  (those widths never enter MTP on gfx1151; the census artifact's true-AR
  column stays their baseline).
