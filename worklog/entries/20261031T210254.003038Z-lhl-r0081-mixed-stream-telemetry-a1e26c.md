# Preserve mixed-row telemetry on terminal K0 stream chunks

## Summary

Terminal single-token publications now choose mixed telemetry for a row that
used mixed MTP or shared target widths, matching reclaim's selection. Previously
`_published_token` always chose AR telemetry, so a mixed request finishing on a
K0 step lost its speculative accounting on the stream's only terminal packet.

## Changes

- Select `_mixed_telemetry` for `row.mixed_mtp or row.mixed_widths` in
  `Qwen4ExpResidentServingRunner._published_token`, retaining prefix metadata.
- Add three branch tests: MTP ownership, shared-width ownership and ordinary AR.
  No change to generated tokens, finish details or nonterminal publications.

## Validation

- RED: the two mixed-owner cases chose AR; the ordinary AR control passed.
- GREEN: all three branch cases pass. The lifecycle/mixed/provider-stream/server
  bundle passes 70 tests (`/tmp/r0081-mixed-stream-narrow.xml`).
- The initial 75-test run had an isolated pre-existing-style fake incompatibility
  while the separate mixed-accounting implementation was being edited: the
  legacy-only summary fixture no longer supplies the new counters. That worker
  was notified; its disposition is separate from this routing branch.
- No real HTTP stream executed in this unit; public validation remains in R0081.
