# Fix the Q5_1 staged prefill tile overrun and re-gate the flash routes

## Summary

`ff7569f41` ("perf: widen Gemma Q5 staged prefill tile") instantiated
`q5_1_selected_grouped_prefill_staged_bf16_bf16_kernel` with `OUT_TILE = 8`
while `launch_q5_1_staged_grouped` still sized the grid and the staged shared
bytes from `out_tile = 4`. The kernel staged and read twice the shared memory
the launch reserved, so the Q5_1 expert down projection returned wrong values in
prefill. This is the cause of the teacher-forced instrument's "1000x" shift
recorded in
`worklog/entries/20261008T175944.497327Z-lhl-gemma4-gemma4-teacher-forced-sensitivity-545402.md`
and
`worklog/entries/20261008T174856.609217Z-lhl-gemma4-gemma4-short-route-vs-exact-f6ba87.md`:
it is a prefill defect, not increased model sensitivity to a bf16 rounding flip.
Those entries' mechanism and their conclusion that the envelope is unattainable
on the current model state are superseded by this one.

The defect lived only in unpushed commits `ff7569f41..42f9a9d94`. Every
teacher-forced reading taken on that range is invalid, including the rejection
of the flash global decode route (`efbf6978c`), whose baseline worktree at
`308c4c38c` carried the defect.

With the tile restored, measured on W7900 (GPU0, `max_block` 1024), frozen
chain, `kl(baseline || candidate)`:
