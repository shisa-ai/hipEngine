# gfx1100 MTP width depth K1-K4 C1-C7 qualification campaign

Opening checkpoint for qualifying the gfx1100 MTP width/depth matrix across
C1-C7 and K1-K4. No code or capability changed yet. This entry records the
provenance of the current narrow table and the measurements that rule out the
obvious causes of non-engagement, so the next session does not repeat them.

## Validation

### Established facts

### Provenance of the current 4-cell table

- `5794ff228` (2026-09-05, "perf: qualify explicit gfx1151 C8 MTP") introduced
  `GGUF_SPECDEC2_MTP2_PHYSICAL_WIDTH_DEPTHS` into the **gfx1100** package as an
  empty dict `{}`. With an empty dict `_physical_width_depths()` returns
  `_MTP2_CERTIFIED_WIDTH_DEPTHS`, which is every (width, depth) for width 1-4
  and depth 1-3 — twelve cells.
- The campaign-side merge parent `10f49ec95` did not contain the symbol at all.
- The merge `cca981f08` authored **both** the narrow value
  `{"production": ((1,2),(1,3),(2,2),(8,3)), "strict": ((2,2),)}` **and** the
  comment above it. `git blame` attributes lines 610-615 and 620-623 to the
  merge commit.

So the narrowing was a deliberate authored policy during the merge, not a
botched conflict resolution. It is still a reduction from twelve effective
cells to four, and it closed C3-C7 entirely.

### The table is not what blocks C1

The merge comment claims production owns "the qualified Qwen3.6/Qwen3.8
C1-K2/**C1-K3**/C2-K2 and Qwen3.8 C8-K3 frontiers". Qwen3.8-27B `Q4_K_M`
C1/K3 does **not** engage on the W7900:

| Run | Capacity | Mode | Budget | Engaged | MTP cycles |
| --- | --- | --- | --- | --- | --- |
| c1 | 1 | explicit | K3 | 0/10 | 0 |
| c1 | 1 | automatic | K3 | 0/10 | 0 |
| c1 | 8 | explicit | K3 | 0/10 | 0 |

All three are 10/10 token-exact; MTP simply never runs. Ruled out as causes:

- **The width/depth table.** `(1,3)` is listed. At capacity 1
  `_physical_width_depth_policy()` resolves to `[(1,2),(1,3)]` and
  `_max_physical_requests()` is 1, so `len(semantics)=1` passes the first gate.
- **Resident capacity.** Measured at capacity 1 and capacity 8 with the same
  result. An earlier packet G run used capacity 8 for c1/c2 and reported
  `engaged 0`; that invocation was wrong for measuring the c1 path, but the
  corrected capacity-1 run reproduces the same outcome.
- **Request mode.** Explicit and automatic both give zero cycles.
- **Candidate budget.** K3 tested; a K2 run aborted on a dirty tree
  (my concurrent edit) and still needs a clean repeat.

The remaining gate is downstream of `_physical_width_depth_admitted()` in
`Qwen35GGUFMTP2Adapter` — the per-request conditions in the same block
(`native_greedy`, `first_token_emitted`, `row.lease`, `row.slot`,
`static_eligibility.max_candidate_count`) or the model-evidence resolver the
merge comment refers to. `--generation2-diagnostic` does not surface an
admission reason; it captures stage timings only, so localizing this needs
either engine instrumentation or a targeted unit-level reproduction.

### K4 is not reachable without a code change

`_MTP2_MAX_CANDIDATE_DEPTH = 3` in hipengine/generation/qwen35_gguf_mtp2.py,
and `_physical_width_depths()` raises for any depth outside [1, 3]. Qualifying
K4 requires raising that bound, which is an architectural change plus its own
correctness and acceptance evidence, not a table edit.
