## Changes


- Start H4 from clean H3 rejection revision `cb666600a`. HIP is live and `rocminfo` exposes the Radeon Pro W7900 as gfx1100. The required kernel-lineage audit reports only the same four already catalogued external drifts. Freeze llama.cpp HIP `c0bc8591e8815c63cb01dd3f051a8b0df02501c9`; the extracted `ggml-cuda.cu`, `convert.cu`, `dequantize.cuh`, `convert.cuh`, and `ggml-common.h` bytes match that commit at SHA-256 `33e6fe76...049`, `ddc86402...9f9`, `2cdf4dcd...8b2`, `fc323724...6ce`, and `af255601...4a0`. No external tree is modified.
- The source path is not the rejected Q6 Q8_1/MMQ32 design. At M512, gfx1100 exceeds llama.cpp's Q6 MMQ cutoff and `ggml_cuda_mul_mat_cublas_impl<F16>` (1) dequantizes every raw 210-byte K256 block to F16 with one local64 block, (2) casts the F32 graph activation to F16, (3) runs column-major rocBLAS with F16 inputs, F16 accumulation, and F16 output, then (4) casts the result to F32. Q6 dequant computes `F16(d) * int8(scale) * signed_q6` in F32 before one F16 rounding. hipEngine's unavoidable boundary difference is BF16 input rather than llama.cpp F32 input; H4 therefore preserves the resident BF16 value, rounds it once to F16, and returns the F16 result through one BF16 or F32 cast.
- Freeze the raw-pointer primitive ABI as BF16 row-major input `[M,K]`, raw output-major Q6_K bytes `[N,K/256*210]`, caller-owned row-major F16 input/weight/output planes, and row-major BF16 or F32 output `[M,N]`. No dequantized weight survives one projection. At M512 the independent maxima are **75,497,472 bytes** for F16 weights (`K12288/N3072`), **12,582,912 bytes** for F16 input (`M512/K12288`), and **9,437,184 bytes** for F16 output (`M512/N9216`): one reusable three-plane session owner is therefore bounded at **97,517,568 bytes** and must recover fully at teardown. The registered exact coltile remains fallback for small rows, unsupported shapes/backends, missing keys, and any admission failure.
- Freeze all **144** traced M512 source stacks across six `(K,N)` configurations: BF16-out `1024x3072` (46), `9216x3072` (1), and `12288x3072` (1); F32-out `3072x72` (1), `3072x1024` (94), and `3072x9216` (1). The two remaining Q6 tensors use source MMVQ after graph pruning and are outside H4. Exact dispatch adjacency proves every included stack is `dequant, input cast, rocBLAS, output cast`. Recounting the canonical trace gives **1.983050 + 1.948221 + 9.603580 + 1.385014 = 14.919865 ms** inclusive; the published ledger's **14.916 ms** is the same rounded/reclassified row, so H4 uses the slightly stricter exact recount. hipEngine's corresponding exact bodies are **156.111 ms**, a **10.46x** gap.
- RED/GREEN is fixed before implementation: (1) an independent CPU oracle must match source F16 dequant bytes for signed Q6 extrema, positive/negative/zero group scales, F16 super-scales, N tails, and K256 blocks; (2) BF16-to-F16, F16-result-to-BF16/F32, and complete rocBLAS outputs must be finite and pass KL <=0.05/top-1 >=90% against the raw exact CPU path; (3) separately named four-axis gfx1100 keys and build planning must fail closed on gfx1151 and reject invalid dimensions before loading HIP/rocBLAS; (4) cached-only `rocprofv3` must name the local64 dequant, both casts, and expected rocBLAS body with plausible resources/durations; and (5) an all-six-shape M512 leaf must measure the inclusive 144-stack cost, exact scratch bound, deterministic repeat, and allocation recovery before runtime integration.
- Production promotion remains conditional on an explicit default-off owner, complete natural-M512 state/lifecycle, the binding 18-prompt/576-step train+heldout/category-heldout quality lane, counter-ordered 512/1K timing, and an all-family reprofile. Do not stack H1-H3 rejected arithmetic, tune layer IDs/prompts, or run 4K/long context before complete H4 quality passes.
