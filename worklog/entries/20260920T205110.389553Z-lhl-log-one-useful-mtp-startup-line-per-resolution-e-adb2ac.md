# Log one useful MTP startup line per resolution event

## Summary

The server no longer prints an MTP line it is about to supersede. `get_llm`
echoed `EFFECTIVE_MTP: serving=pending ...` the moment the lazy `LLM` object
existed, which on eager startup landed between `MODEL_LOAD: loading` and
`MODEL_LOAD: engine created` while the weights were still loading. That line
carried only the requested values, and the resolved line followed minutes later.
Now exactly one line states a resolved state per resolution event, emitted when
the engine resolves its generator: after eager `prepare`, and after the first
lazy request prepares the model. The pending form is kept only where it is the
whole truth - lazy startup, where no engine exists yet.

## Observed noise (quoted verbatim)

`hipengine serve --model /models/gguf/Qwen3.8-27B-UD-Q4_K_M.gguf
--served-model-name qwen3.8-27b --info`:

```
INFO:     MODEL_LOAD: loading model=/models/gguf/Qwen3.8-27B-UD-Q4_K_M.gguf size=15.33 GiB backend=auto quant=auto
INFO:     EFFECTIVE_MTP: serving=pending engine_supported=unknown default_enabled=unknown policy=auto thinking=hint candidate_budget=requested:None resolved:pending source:pending mtp2_context_window=env:none resolved:target_capacity (pre-resolution: the engine has not prepared its generator yet)
INFO:     MODEL_LOAD: engine created elapsed=0.0s; preparing weights, KV pool, and runtime workspace
MODEL_LOAD: [####################--------]  72.4% approx 11.10 GiB/15.33 GiB VRAM 13.49 GiB/124.00 GiB
```

The pending form replaced an earlier, worse contradiction (`serving=off
engine_supported=False` at the same position, worklog 20260919T120206.930114Z).
It removed the wrong answer without removing the line, so eager startup still
printed two field lines where only the second one said anything.

## Changes

- `hipengine/server/api.py::_log_pending_mtp_config` - new: the pending form,
  reachable only from lazy startup, where the model is not created until the
  first request and the requested policy is everything that is knowable. Its
  parenthetical now says so instead of claiming a generator is being prepared.
- `hipengine/server/api.py::_log_effective_mtp_config` - returns `bool`, logs
  nothing while the engine is unresolved, and otherwise keeps the resolved line
  and the unservable-budget warning unchanged.
- `hipengine/server/api.py::create_app` - `log_effective_mtp_once` emits the
  resolved line the first time an engine resolves and stays silent afterwards.
  Called from `get_llm` (an engine resolved at construction reports at once),
  from both return paths of `ensure_resident_context` (where eager startup and
  the first lazy request prepare the model), and from the eager readiness tail
  as a backstop. `_log_pending_mtp_config` replaces the eager-path echo.
- `tests/test_integration_server_api.py` - `LateResolvingMTPFakeLLM` (route
  exists only after `prepare`, as the real `LLM` behaves),
  `test_unprepared_engine_logs_no_mtp_state_yet` (replaces the superseded
  `test_unprepared_engine_logs_pending_not_off`),
  `test_missing_engine_logs_no_mtp_state`,
  `test_lazy_startup_pending_line_defers_to_the_first_request`,
  `test_eager_startup_logs_one_resolved_mtp_line`.
- `docs/API.md` - the startup-line contract now states one resolved line per
  resolution event and no pre-load echo.
