# X-7's first blocker is dropped, and the promoted route fails at prefill->c1

## Summary

The long-form heldout protocol from the previous unit was run against the
promoted 16-47 default, `dense_wide`. **The evidence is complete and X-7's first
blocker is dropped. The route does not pass the quality gate**, and it fails on
exactly the scope the WMMA route failed on.

## Engagement, checked before any KL

An identical strict/candidate hash pair is this packet family's recorded failure
mode twice over, so it is checked first:

```
strict    = 4877307044f53ff8a93e2a9abb0783924a7a0eeb9386c69d40a45a71241a34a5
candidate = 0553c7f988acf28817a4a2ecefe7dcb7a40a8943d4b9f01e6446badf03d8be29
```

They differ, and the dispatch counts confirm it independently: the candidate ran
the `dense_wide` selector **1056** times (`dense_wide256_f32_f32_out`) against the
teacher's **0** (`exact coltile8_rowbatch4_f32_f32_out`). `rows_seen` is
`[1, 424, 438, 508, 512]`, so the long prompts reached the guard as their real
token counts.

All seven heldout checks pass, `blocked_reason: null`, `longest_prompt_rows` 512
against `route_min_engaging_rows` 257.

## The blocker is dropped; the claim is not made

`category_heldout_evidence_complete: true` and **`category-heldout numerical
evidence` is absent from the seven remaining `qualification_blockers`** — dropped
by producing evidence, not by asserting it.

`category_heldout_qualification_claim: False`, because the claim requires the
evidence *and* a passing quality gate. That distinction is exactly what the tests
in `test_unit_qwen4exp_heldout_coverage.py` pin, and this run is the case it was
written for.

## The result

Aggregate passes every metric: mean KL 4.33572e-4, p95 1.68697e-3, p99
5.19085e-3, max 6.40050e-3, top-1 **1.0** on 100/100 rows, 3-run deterministic,
no rows over the review boundary, no top-1 mismatches.

`hard_gates_passed: False` on two per-scope gates, both over the same 4 rows:

| failing scope | rows | mean KL | top-1 | limit |
| --- | --- | --- | --- | --- |
| `shape=prefill_last` | 4 | **1.438974e-3** | 1.0 | 1e-3 |
| `transition=prefill_to_c1` | 4 | **1.438974e-3** | 1.0 | 1e-3 |

**1.44x over, on KL only, with perfect top-1 at that scope.** `shape=c1` (96
rows) passes at 3.91681e-4 and all four categories pass.

## The finding: the locus is the transition, not the route

WMMA at the same window, same host, over the short admission suite fails the
**same two scopes** at 2.06179e-3 with top-1 1.0 there as well.

Two different routes, one window, the same scope, KL-only, perfect top-1 in both.
That points at 16-47's prefill->c1 handling rather than the `dense_wide` rewrite,
and `dense_wide` is the milder of the two at that scope.

**The routes are not equivalent in aggregate**, and I am not claiming they are:
WMMA's max KL is 4.2x worse (2.70641e-2 vs 6.40050e-3) and its top-1 is 0.99556
against 1.0. They agree only on *where* the per-scope failure is.

**The aggregate would have passed both times.** Every aggregate metric is inside
its limit in both runs, including a perfect top-1 here. The per-scope gate is the
only thing that localizes the defect, which is why a passing aggregate is not
admissible as clearance.

## What this is not

- **Not a regression.** This is the first heldout gate this route has been
  through, so there is no prior certificate it fails to match. It is a
  newly-localized defect, not a change.
- **Not host-independent.** Measured on **`gfx1151`** (Ryzen AI MAX+ 395 / Radeon
  8060S), not the default W7900. The WMMA comparison run is same-host, so that
  comparison is like for like.
- **`measurement_valid: false` is expected and is not a defect.** It is bound to
  the canonical protocol's `complete` flag and this run used the heldout fixture.
- **`execution-affecting worktree provenance` is a blocker for a reason outside
  this packet**: 28 untracked files, which are other workers' raw logs and
  profiler dumps in a shared worktree. `staged_dirty` and `unstaged_dirty` are
  both false and `dirty_paths` is empty, so no execution-affecting tracked file
  was modified. Recorded as it stands rather than worked around.

## Two harness traps worth recording

**The exit code is not the verdict.** The gate exits 1 whenever
`measurement_valid` is false, which is every heldout run. Two earlier launches of
this same command also reported "exit 0" from the task wrapper while having
failed outright — the first at `libamdhip64.so`, the second at a missing `hipcc` —
because the command was piped through `tail`, so the pipeline's status was
`tail`'s. I read the artifact rather than the status, which is how the real result
was found.

**The environment needs pinning.** `scripts/run_qwen4exp_x7_longform_heldout.sh`
sets the ROCm SDK library path and puts `hipcc` on `PATH`. Without the first the
runtime fails to load; without the second the first JIT build fails with
`FileNotFoundError: 'hipcc'`.
