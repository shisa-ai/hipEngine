# Qwen4Exp F16 route composition promoted to production

## Summary

Owner decision (2026-10-13 UTC): "if it passes global production scope then
we should enable these for production profile as well. i don't think we care
about the per-scope means if our global is fine." The production envelope's
KL limits now bind on the complete row set; a declared scope binds on its
top-1 floor only and its KL statistics are reported as advisories. Under that
rule the complete F16 route composition that had lived in the opt-in `fast`
profile passes the numerical gate, so it is now the `production` plan for
`qwen4_exp_gguf` / `hip_gfx1151` / `gguf_ud_q4_k_xl`.

Measured before the commit on the working tree (canonical 12-case protocol,
Radeon 8060S / gfx1151, machine `55ea6c509d0b49eea8de7094a1023668`,
`UD-Q4_K_XL`, chunk 4096, compact capture, warm PLE cache, one warmup and
three repetitions): `production` prefill 305.6 / 331.6 / 335.5 to
768.4 / 930.6 / 1101.8 tok/s at p512/p1024/p4096 (2.51x / 2.81x / 3.28x),
decode 20.92 / 20.16 / 20.54 to 20.93 / 20.17 / 20.58. All 12 cases are
deterministic and produce the same output token sequences as the last `fast`
run. A clean-tree rerun and the gates follow in the next entry.

## Decisions

- **Per-scope KL is advisory.** My reading of the owner's sentence covers
  per-scope p95/p99 as well as the mean: `mixed_ja_en` also misses the p95
  limit (5.636e-3 against 5e-3 over 100 rows). The per-scope top-1 floor of
  97% still binds. This is a change to the shared evaluator, so it applies to
  every model's production gate, not only this lane.
- **Task axis.** The composition's gate status is `requires_task_review` at
  15 of 18 strict-exact tasks, the same count and status under which the
  arithmetic-recovery plan was already the production plan.
- **`fast` stays registered** as the profile the next uncertified route lands
  in. It currently selects the same routes as `production`.
- **`gguf_q4_k_m` is unchanged.** The composition is gated for
  `gguf_ud_q4_k_xl` only.
- **An explicitly named router producer is kept.**
  `HIPENGINE_QWEN4_EXP_ROUTER_VARIANT` set before import remains a rollback;
  only the unset default moves to the F16 GEMM producer.
- **The attention K/V gather takes `KVLiveSpans`**, validated as uniform BF16
  like the scalar sparse-attention wrappers. I had recorded that as a
  condition for leaving `fast`.
- **Diagnostic, not binding:** against the plan it replaces, 9 of the 12
  canonical cases generate a different 128-token continuation (three of the
  four p512 cases match; none of the p1024/p4096 cases do).
