# gfx1151 declares four admitted MoE prefill modes that the gemma4 expert block never consults

## Summary

The 11.6x compactor fix (`20260929T110000`) came from one pattern: **a registered backend
capability declared "on" that the consumer never read**. That pattern generalises, so this entry
swept for it. The sweep found the same shape four more times, on the block that is 44.7 percent
of the prefill.

## The sweep

For each capability-shaped constant declared in `hipengine/kernels/hip_gfx1151/__init__.py`,
count its readers outside the declaring package:

| class | count | example |
| --- | ---: | --- |
| read by non-Laguna consumers | 54 | `GGUF_RAW_K_PREFILL_*` |
| **read ONLY by Laguna paths** | **24** | **`LAGUNA_SELECTED_DOWN_MODE`** |
| read by nobody outside the backends | 27 | `GGUF_Q6_*_PREFILL_*`, `GGUF_Q8_T16_PREFILL_FOUR_WAVE` |

**A capability that only the Laguna runner reads is a capability every other model silently
ignores**, which is exactly what `LAGUNA_MOE_GROUP_COMPACT_MODE` was.

## The four that matter

`hipengine/kernels/hip_gfx1151/__init__.py` declares, with the measured admission written
above each:

```python
# "For chunks of at least 512 rows, prefetch the next K32's eight raw nibble
#  words while current packed dots execute... Packed-dot arithmetic and K order
#  remain bit-for-bit unchanged."
LAGUNA_SELECTED_GATE_UP_MODE = (
    "mmq128x32_d8_f32_wavecols_direct_doublebuf_rawprefetch_ge512"
)
# "Exact eight-token router tiling preserves every token/expert's K traversal
#  and reduction tree while reusing each F32 weight row twice as long."
LAGUNA_ROUTER_LOGITS_MODE = "token_tile_8"
# "At producer rows >=512, Q4 down also carries the next K32 raw nibble payload
#  in registers."
LAGUNA_SELECTED_DOWN_MODE = (
    "mmq64x64_d4_f32_q6_wavecols_direct_rawprefetch_q4_ge512"
)
# "Exact scratch reuse writes packed gate/up into the larger selected-down
#  output allocation, then folds the standalone BF16 SiLU boundary into the
#  range-safe down pack. Seven paired pp512 runs are exact and win 7/7; the
#  standalone SiLU plus ordinary pack remain the explicit rollback chain."
LAGUNA_FUSED_SELECTED_SILU_PACK = True
```

against the census (`20260929T083000`):

| mode | targets | measured cost of the target |
| --- | --- | ---: |
| `LAGUNA_SELECTED_GATE_UP_MODE` | expert gate/up | **153.82 ms** |
| `LAGUNA_SELECTED_DOWN_MODE` | expert down | **114.85 ms** |
| `LAGUNA_FUSED_SELECTED_SILU_PACK` | standalone SiLU + down pack | 2.762 + 2.619 ms |
| `LAGUNA_ROUTER_LOGITS_MODE` | router | 17.5 ms |

**Every one is `>=512`-gated and the prefill is 512 rows**, so all four apply to this workload by
their own stated conditions.

## Why gemma4 cannot see them

`hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py` selects its consumer by quant key:

```python
quant_key = getattr(weight.spec, "quant_key", None)
if quant_key == "gguf_q5_1":
    from ...gguf_q5_1_mmq_selected_prefill import (
        gguf_q5_1_mmq_ds4_selected_prefill_bf16_bf16_out as mmq_down,
    )
elif quant_key == "gguf_q8_0":
    ...
```

There is no mode lookup. The Laguna runner reaches the same kernels through
`resolve_laguna_selected_gate_up_mode` / `resolve_laguna_selected_down_mode` /
`resolve_laguna_router_logits_mode` (`hipengine/runtime/laguna_moe.py`), which read those
capabilities and validate the result. **The variants the modes name are in the same
`*_selected_prefill` family gemma4 already calls -- gemma4 picks a different variant, it does not
use a different kernel family.**

This is not a claim that the modes will help. It is that the block is 44.7 percent of the
prefill, four admitted and documented optimisations for it are declared on this backend, and
nothing on the gemma4 path reads any of them.

## Next

- **Resolve each mode in the gemma4 expert dispatch the way the compactor now is** -- through
  `resolve_laguna_*_mode(weight.backend)`, so the registered capability decides and the existing
  rollback stays the lever. No backend branch and no new flag, as `20260929T110000` did.
- **Start with `LAGUNA_FUSED_SELECTED_SILU_PACK`.** It is a boolean, its own note records seven
  paired pp512 runs exact and winning 7/7, and its rollback chain is named. It is the cheapest of
  the four and worth about 5.4 ms by the census.
- **Then `LAGUNA_SELECTED_DOWN_MODE`**, which targets the largest single kernel after gate/up and
  whose note claims unchanged arithmetic. It may also make `20260929T093000`'s tile layout
  unnecessary -- check it before building that unit.
- **Verify each against the mode's own claim rather than assuming it.** These were admitted on
  Laguna shapes; the notes say "bit-for-bit unchanged" for the arithmetic, but the `>=512` gating
  and the shape coverage are Laguna conditions and gemma4's expert geometry (704-wide down,
  128 experts) is not the same.
- **27 declared constants are read by nothing at all** (`GGUF_Q6_*_PREFILL_*`,
  `GGUF_Q8_T16_PREFILL_FOUR_WAVE`, `QWEN4_EXP_PRODUCTION_Q8_PREFILL_*`). Either dead
  declarations or missing consumers; the cleanup ledger should decide which, and
  `GGUF_Q8_T16_PREFILL_FOUR_WAVE` is worth a look because the dense term is Q8_0 T16.
