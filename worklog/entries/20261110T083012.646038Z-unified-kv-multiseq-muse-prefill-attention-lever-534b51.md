Hypothesis under test (arithmetic-neutral): the mt kernel stages K/V tiles
at row stride HEAD_DIM=128 halves (256 B). The QK k_frag read
`k_tile[lane16*128 + dt*16 + k]` puts all 16 lanes on the same LDS bank
group (256 B stride % 128 B bank window = 0): a 16-way bank conflict on
every K-fragment load, 128 loads per wave-tile. Padded row stride (128+2
halves) makes the lane pattern conflict-free. Pure layout change: identical
arithmetic, bit-identical output expected.
