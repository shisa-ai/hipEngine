# Muse Glimmer DFlash bench harness + sequential-verify baseline

## Summary

Task #9 tooling. Added a same-protocol mtpbench decode bench for hipEngine
DFlash vs the true no-spec AR control, with the exact greedy ID equality gate
(DFlash == AR) and acceptance economics. Measured the current bring-up
(sequential single-row verify) as the starting point for the batched-invariant
block verify work.

## Changes

- `hipengine/generation/muse_glimmer_gguf.py` and
  `hipengine/generation/muse_glimmer_dflash.py`: record `last_prefill_seconds`
  and `last_decode_seconds` (decode wall starts after prefill/inject; each
  cycle ends in a device-to-host logits readback, so the wall is synchronized).
  No change to generation logic.
- `scripts/muse_glimmer_dflash_bench.py`: runs the mtpbench suite, reports AR
  and DFlash decode tok/s (post-prefill decode wall; a transition-normalized
  variant mirrors llama.cpp (predicted_n-1)/predicted_ms), exact ID equality
  per prompt, and acceptance economics. Writes a diagnostic artifact with
  canonical provenance.

## Validation

Smoke (3 code prompts, max_tokens=128, 1 repeat), production llama.cpp server
idle on :8000 (memory resident, no compute contention):

- AR decode 11.19 tok/s; DFlash (sequential verify) 2.59 tok/s
  (transition-norm 2.57) → 0.23x AR. Exactness True on all 3.
- Draft acceptance 314/1395 = 22.5% (block-15 mean over positions);
  committed 384, ~4.4 tokens/cycle.

The sequential verify runs 15 single-row target forwards per cycle (no
weight-read amortization), so it is ~4.3x slower than AR — confirming the
campaign design note that block verify must become batched-invariant to win.
Gate B target is llama.cpp draft-dflash 21.30 tok/s.

Note: hipEngine block-15 mean acceptance (22.5%) is lower than llama.cpp's
reported draft_acceptance (55.4%); the metrics count differently (hipEngine
averages over all 15 proposed positions; deep positions accept rarely). The
binding gate is decode tok/s + exact ID equality, not acceptance parity. With
a batched verify committing ~4.4 tokens/cycle at ~1 forward cost, the projected
rate clears 21.3 even at this acceptance.
