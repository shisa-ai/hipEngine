# Packet 3 opening: width-flat q6-planar cycle cost is the dominant hypothesis

## Summary

Re-analyzing the Packet 1 cycle-scoped traces for Packet 3 ("amortize target
verification across real frontier rows"): the dominant cycle kernel at every
cell is `q6_k_t16_qmicro_planar_wmma_prefill_bf16_kernel` — 64 launches per
staged cycle at BOTH C2/K2 and C8/K3 (one per layer), width-flat in count and
nearly flat in duration (C2 0.787 ms/call, C8 0.910 ms/call; grid.y = 1 at
both, C8 does 32 frontier rows in the time C2 does 6). Rows ride nearly free
inside the 64-row block; the fixed ~0.8 ms per call is the cost.

Roofline frame (Qwen3.8-27B planar-Q6 geometry, KERNELS.md: down K17408/N5120,
narrow-V K5120/N1024; W7900 864 GB/s):

- One down-tensor stream = 73.1 MB = **84.6 µs**.
- Measured per call: C2 787 µs (9.3× one stream), C8 910 µs (10.7×).
- A per-row weight-stream model does NOT explain the data (C8 would be
  2708 µs); the traffic is per-call, not per-row.
- Open question: the cycle-call grid is (3424,1,1) with Workgroup 32; the
  prefill-phase calls for the same kernel family use (6848,2,1) and (704,*).
  3424 × 48 (Q6_DENSE_TILE_COLS = 3×T16_COLS) = 164,352 — which does not match
  the down (N5120) or V (N1024) output dims, so the exact tensor/shape these
  cycle calls process is UNRESOLVED. The L1 probe must identify it before any
  kernel change.
