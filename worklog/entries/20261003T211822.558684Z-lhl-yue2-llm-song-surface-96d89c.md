# YuE2 song generation through LLM.generate_song

## Summary

The YuE2 pipeline was reachable only by constructing `Yue2Session` by hand. It now
has a library surface (`LLM.generate_song()`, `LLM.song_generator()`) and a model
plugin declaration that says what a model produces, so callers and the server can
route on capability instead of on a model name.

## Changes

- `hipengine/models/base.py` — `DEFAULT_GENERATION_SURFACES` and
  `generation_surfaces(plugin)`: a plugin may declare the surfaces it implements
  (`text`, `song`); a plugin that declares nothing is a text model. The reader
  keeps the declaration optional, so `ModelPlugin` gains no required member.
- `hipengine/models/yue2.py` — declares `generation_surfaces = ("song",)`. YuE2
  produces audio, so a text endpoint on this model is a capability miss, not a
  request that fails mid-generation.
- `hipengine/generation/yue2_song.py` (new) — `YuE2SongGenerator` registered as the
  `yue2` text-generator factory for `hip_gfx1100` and `hip_gfx1151`. The generator
  owns request shape, the companion decoder path (`vae_model_path`, then
  `HIPENGINE_YUE2_VAE_DIR`, then the local HF cache snapshot of `m-a-p/YuE2-Vae`),
  and the resident session built on first use. Nothing loads at import or
  construction.
- `hipengine/llm.py` — `generate_song()` and `song_generator()`, `vae_model=`
  constructor input forwarded as the factory's `vae_model_path`, and the
  `generation_surfaces` / `supports_song_generation` properties. Model metadata
  resolution moved into `_resolve_model_metadata()`, which
  `resolve_generation_surfaces(model)` reuses to answer "what does this model
  declare?" without loading weights.
- `hipengine/util/wav.py` (new) — `encode_wav_bytes()`: clip, scale, interleave,
  wrap as 16-bit PCM (or 32-bit float). The pipeline's output is unclipped FP32,
  and a wrap would be audible distortion rather than the loud sample the model
  produced.

## Validation

- `tests/test_unit_yue2_song_generator.py` (new, 30 tests) covers the generator's
  request shape, the decoder resolution order, and the registered factory for both
  backends. `tests/test_unit_util_wav.py` (new, 12 tests) covers header fields,
  frame interleaving, clipping rather than wrapping, the float form, and the
  refused inputs.
- `uv run pytest tests/test_unit_yue2_*.py -q` → exit 0, 264 tests.
- Live, on this host (gfx1151, local HF-cache snapshots of `m-a-p/YuE2-3B` and
  `m-a-p/YuE2-Vae`): `LLM(model_dir, vae_model=vae_dir)` then
  `generate_song(cot="off", seed=20260916)` with the phase budgets capped at 64
  tokens → 14.9 s, 64 frames, 2.56 s of 48 kHz stereo, finite, `torch imported`
  false. This is a wiring and plumbing result on the cached snapshot
  (`14fc6c6f…`), not a parity measurement against the pinned oracle revision
  (`29b3558d…`).
