# Repair full-suite CLI import and HIP architecture isolation

## Summary

The post-review `uv run pytest -v` reached 39% with one assertion failure, then
aborted in a HIP test. Focused reruns reproduced both independently:

- `scripts/execution_profile_gate.py` failed when invoked by path because
  Python put `scripts/`, not the repository root, first on `sys.path`; the
  subprocess could not import `hipengine.benchmark.execution_profiles`.
- `test_laguna_argmax_control_publish` defaulted its compiled target to gfx1151
  when `HIPENGINE_HIP_ARCH` was unset, then launched that binary on gfx1100,
  aborting the process. The suite already provides a device-detected
  `hip_test_target_arch` fixture for exactly this contract.

Neither failure was in a Concurrency2 code path, but both prevented a valid
whole-branch validation result.

## Changes

- Bootstrap the repository root in `scripts/execution_profile_gate.py` before
  package imports, matching other directly executable repository scripts.
- Make the Laguna argmax module-scoped library fixture compile for the detected
  `hip_test_target_arch` instead of defaulting to gfx1151.
