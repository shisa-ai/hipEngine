# Confine the resident block row corruption to the restart

## Summary

The layer-12 residual row is written exactly and is wrong by the time the message pass reads it. Gating the dump to the first pass removes the pass-conflation that made the previous measurement inconclusive: the fresh row matches the host's block to 7.153e-06, so the row write is correct and something between the write and the read changes the region the read addresses.

## Changes

- Gated the row dump on `previous is None`, which selects the first pass, and captured only the first host occurrence per layer.

## Validation

64 rows, fast profile, `hip_gfx1100`. Fresh first-pass layer-12 row against the host's three blocks at that layer: `3.010e+01 3.381e+01 7.153e-06`. The third value is the exact match to the host's own layer-12 block.

- The earlier 1.441e+01 reading came from the loop's second pass, whose state is wrong because it follows the broken message read.
- The row read at the message pass is 1.441e+01 off against the same host block, so the region the message pass reads is not the region that holds the first pass's rows.
- The restart computes `previous = (working, ...)` before flipping `working`, so the message branch addresses the pre-flip name. If the flip and the snapshot restore move the live rows, that name no longer holds them.
