# Prepare and validate the v0.7.0 release

## Summary

v0.7.0 is a minor release: 7 `feat:` and 5 user-facing `fix:` commits landed on
`main` after the v0.6.0 tag. Package metadata, `CHANGELOG.md`, and `README.md`
are updated, the full suite and every documentation gate pass, both
distributions build clean, and the shipped BF16 route is exact on real gfx1151
hardware. The tag has not been pushed.

## Version: 0.7.0

`docs/reference/PUBLISH.md` reserves a minor bump for "new public API/server
features, new supported model paths, new backend/quant surfaces, or meaningful
runtime behavior additions". This release has all four: the chat client's
`/bench` command and prefix-cache token reporting, startup warmup of the admitted
width and the speculative route, packed INT8 MTP verification at group widths up
to four, the sampled MTP route declared on INT8 KV, and the autoregressive finish
rule applied to a verified chain.

  `hipengine serve --help` exits 0 and `hipengine version` reports 0.7.0.
- **ROCm gate, gfx1151.** The documented INT8 MTP gate needs a live server; the
  co-resident worker's server held port 8098, so the gate ran on a second server
  at port 8099 with the recorded readiness config
  (`worklog/entries/20260920T175640.564502Z-lhl-int8-mtp-public-serving-df9489.md`)
  and the `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED=1` override wrapper.
  - The direct-INT8 override acceptance that `c3c246372` recorded as not-run now
    passes. `/ready` reports `runtime_action: diagnostic_override`,
    `diagnostic_override: true`, `effective_kv_storage: int8_per_token_head`.
    The gate's per-request assertions saw `kv_attention_source: int8_direct` with
    `persistent_bf16_mirror_bytes: 0`.
  - **The first attempt used `--max-context-tokens 8192` and failed the mirror
    assertion.** That was a config error, not a defect: at or below 8192
    positions the INT8 route deliberately keeps the exact BF16 decode mirror
    (`_GGUF_INT8_SHORT_BF16_MIRROR_MAX_POSITIONS`, `qwen35_gguf_runner.py:11421`,
    documented in `docs/ENVS.md`). The recorded run used 9216 for this reason.
  - **At 9216 the gate fails on a token divergence, and the divergence is
    pre-existing.** On `code_lru_cache` the INT8 autoregressive route emits
    `LRU Cache` while INT8 MTP emits `LRUCache` — a one-space difference, and the
    only difference in 24 tokens. It is deterministic across repeated runs. The
    same prompt, config, and prompt files were run against a detached worktree of
    the released **v0.6.0** tag, which reproduces the identical divergence, so
    this release does not introduce it. The artifact's INT8 KV quality record is
    rejected on this host and the route is reachable only through the explicit
    diagnostic override.
  - **The shipped default is exact.** On BF16 KV, all 18 gate prompts (10
    category plus 8 heldout) match between autoregressive and speculative
    decoding, 0 mismatches, including `code_lru_cache`.
  - This contradicts the recorded 09-20 claim that the gate passed 36 rows / 108
    requests with agreeing ids. The gate's id comparison and the prompt files are
    unchanged since then, so the earlier claim is not reproducible on this
    artifact. Recorded as a contradiction rather than resolved.
