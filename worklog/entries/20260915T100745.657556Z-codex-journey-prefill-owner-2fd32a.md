# Separate owning prefill workspaces from decoder state

## Summary

Separate prefill storage ownership from decoder/KV state as preparation for
shape-dependent workspace selection. The default still uses one workspace;
no automatic dispatch or performance claim is introduced.

## Changes

- Add Qwen4ExpPrefillWorkspace with phased scratch/input allocation, keeping
  the original default allocation order and sizes.
- Runner cleanup follows its owned workspace list rather than active borrowed
  aliases. Extra inactive workspaces carry no decoder/KV allocations and
  remain owned until runner close; callers must budget them separately.
- Add a GPU owned-workspace check against frozen isolated references.
  The benchmark's existing full-donor path is not changed yet.

## Validation

- 45 focused CPU tests pass, including frozen allocation-sequence equality
  at1024/2048/4096, mandatory sizing, existing borrowing and c2 semantics.
- Extra workspace bytes equal only the prefill components of the planner.
  Tests cover foreign borrowed-owner survival, scratch allocation failure,
  input allocation failure and complete cleanup.
- Refactor/tests were developed together; no arithmetic changed. Frozen
  pre-refactor allocation records supply the independent regression oracle.
- Real-GPU validation follows at this committed source.

## Next

- Verify prefill-only borrowing and frozen output/state parity on GPU.
- Then implement/admit shape-dependent selection and measure it; do not
  call the remaining automatic-selection goal complete from this refactor.
