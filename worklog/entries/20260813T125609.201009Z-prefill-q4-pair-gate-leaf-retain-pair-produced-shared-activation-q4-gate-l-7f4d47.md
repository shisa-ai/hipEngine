# Retain pair-produced shared-activation Q4 gate leaf

## Summary

Retained a runtime-unwired actual-weight Q6-QKV/Q4-gate pair leaf. Unlike the
prior rejected scalar-produced singleton gate route, this candidate uses the
later exact adjacent-pair Q4 producer and reuses the FP16 activation already
produced for the admitted Q6 QKV peer.

## Changes

- Added
  `benchmarks/results/2026-08-13-qwen36-27b-q4-pair-gate-shared-activation-leaf-retained.json`
  with all 60 raw pairs, byte/top-1 checks, hashes, prior-result reconciliation,
  and the fail-closed runtime admission contract.
- Added a compact benchmark changelog entry. Production dispatch, package
  policy, memory ownership, decode, MTP, and public toplines remain unchanged.

## Validation

- Actual `blk.0.attn_qkv.weight` Q6T16 K5,120/N10,240 plus
  `blk.0.attn_gate.weight` Q4T16 K5,120/N6,144, 15 alternating pairs per cell:
  XTX improves **1.127x/1.131x** at M512/M1024 with **28/30** wins; W7900
  improves **1.169x/1.106x** with **30/30** wins.
- Q6 final BF16 output is byte-identical under both labels. Pair-produced Q4
  source-F16 output is byte-identical to the scalar source-F16 oracle in every
  cell. Q4 projection top-1 versus exact T16 is **95.12-95.21%**, maximum abs
  error **0.0234375**, mean abs **0.00115335**, and all values are finite.
- The leaf uses only current activation, weight-tile, and output-tile scratch;
  it adds no persistent or workspace bytes. The proposed runtime interval is
  M512-M2047 only; M2048/4K, decode, MTP, peer/model misses remain exact.
- JSON syntax, raw hashes, worklog schema, and diff hygiene pass.
