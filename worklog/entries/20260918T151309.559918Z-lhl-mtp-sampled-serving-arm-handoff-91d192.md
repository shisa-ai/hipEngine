# Sampled MTP serving arm: exact prerequisites, two override points

## Summary

The sampled accept rule is implemented and its distribution gate passes
(`9b588fec2`). What is left for the sampled route to reach a real request is the
**serving arm**: a matched `temperature > 0` measurement with a true-AR control in
the same load, which is what an evidence row has to cite. This entry pins the two
places that currently refuse the route, so the measurement does not have to
rediscover them.

A request at `temperature > 0` is refused twice, by different owners:

1. `hipengine/speculative/serving.py` (`_evidence_checks`, the
   `key.sampling_mode in row.sampling_modes` check, reason
   `sampling_mode_not_qualified`): the model plugin's serving rows for
   Qwen3.8 `Q4_K_M` on gfx1151 all declare `sampling_modes=("greedy_fast",)`, so a
   `sampled` request resolves to the autoregressive route before the adapter is
   asked.
2. `hipengine/generation/qwen35_gguf_mtp2.py::_sampled_route_qualified()`: the
   adapter advertises `("greedy",)` unless a row for
   `(backend, target_arch, weight_quant, artifact_size_bytes)` lists `sampled`.

Both read the same tuple, so a **temporary uncommitted edit** that appends
`"sampled"` to one gfx1151 `Q4_K_M` row's `sampling_modes` opens the whole route
for a measurement without adding a flag. Either the measurement then produces the
serving artifacts that justify a new row, or the edit is reverted and the route
stays closed - there is no third state, and no `HIPENGINE_*` override is needed.
