# Factor attention/GDN bulk prefill subgraphs out of the resident layer methods

## Summary

Split the attention/GDN prefix out of the two monolithic bulk-prefill layer
methods in `hipengine/runtime/qwen35_gguf_runner.py` so the TP2 bulk route can
run a layer's attention subgraph and then a *sharded* MLP instead of the
full-width one. The extraction is a pure mechanical move: the new attention
helpers contain the exact original attention/GDN statements, and the original
public wrappers keep their names and signatures and now call the helper
followed by the unchanged `_run_post_attention_ffn_rows`. No kernel, no
dispatch branch, no arithmetic change.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`
  - New `_run_linear_attention_prefill_attn_rows` (GDN/linear-attention prefix
    of the old `_run_linear_attention_prefill_layer_rows`, both the
    capture/prefill-score path and the segmented-conv path). Returns the
    optional f32 attention output pointer: the capture path returns
    `attn_out_f32_ptr`, the segment path returns `None`.
  - New `_run_full_attention_prefill_attn_rows` (full-attention prefix of the
    old `_run_full_attention_prefill_layer_aotriton`). Returns `used_aotriton`.
  - `_run_linear_attention_prefill_layer_rows` and
    `_run_full_attention_prefill_layer_aotriton` are now thin wrappers: call the
    matching attention helper once, then `_run_post_attention_ffn_rows` once,
    forwarding the helper's f32 attention output (or `None`) and the original
    pointers / rows / `linear_state_rows` / `commit_final_linear_state` /
    `stage_timings` / `sync_stage_timings` / `stage_prefix` / stream. The linear
    wrapper keeps the `..._ffn_total` stage mark after the FFN call. Public
    signatures are byte-identical, so every existing caller, monkeypatch and
    instrumented script keeps working.
  - The attention helpers no longer take `out_ptr` / `expert_sidecar` (the FFN
    owns them); the only remaining `out_ptr`/`expert_sidecar` references inside
    the wrappers are the original forwarding sites.
- `tests/test_unit_qwen35_gguf_attn_prefill_split.py` (new)
  - Structural guards: each split method is defined exactly once; neither
    attention helper references `_run_post_attention_ffn_rows`; each wrapper
    calls its helper exactly once then the FFN exactly once, in that order.
  - Mocked launch-sequence contract: the wrapper forwards the same
    `layer_id`/`hidden_ptr`/`out_ptr`/`scratch`/`rows`/`decode_scratch`/`stream`/
    `expert_sidecar`/`linear_state_rows`/`commit_final_linear_state`/
    `hidden_f32_ptr`/`out_f32_ptr`/`stage_timings`/`sync_stage_timings`/
    `stage_prefix`, passes the helper's returned f32 attention pointer to the
    FFN (`None` for the full-attention path), records the events in
    `["attn", "ffn"]` order, and launches the FFN exactly once (no double MLP).
  - Full-attention wrapper returns `used_aotriton` from the helper; linear
    wrapper returns `None`; both public signatures are pinned.

Native-ABI audit (P1 create change, recorded here so it is not re-litigated):
`tp2_staged_create` gained a `capacity_rows` argument in
`hipengine/distributed/staged_exchange_host.cpp`; the only Python binding site
is `hipengine/distributed/staged_compiled.py`, the tests bind matching fakes,
and `build_hip(sources=...)` keys the cache on source bytes so the changed C++
recompiles. The single-row reduce symbols `tp2_staged_reduce` and
`tp2_staged_reduce_at` keep their original signatures; only the new
`tp2_staged_reduce_rows` / `tp2_staged_reduce_at_rows` are additive. So the
create ABI changed and the old reduce signatures did not.
