## Changes


- Added a guarded GGUF key-only retained-KV diagnostic path via `HIPENGINE_GGUF_INT8_KV_KEY_ONLY=1`: INT8 per-token/head K, BF16 V, K scales only, and no default-path behavior change. The path adds HIP writer wrappers (`qwen35_write_paged_kv_int8_key_bf16_value_{spans,prompt_spans,batch_spans}`), split-K decode wrappers (`qwen35_paged_attn_decode_int8_key_bf16_value_gqa_splitk_{spans,gate_bf16_spans}`), CPU-reference helpers, and `scripts/qwen35_kv_int8_accuracy.py` primitive coverage. Long contexts still use the existing BF16-prefix guard; lower prefixes require `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1`.
- Primitive gate on W7900/GPU0 with cached ROCm 7.13 compiler env: `python3 scripts/qwen35_kv_int8_accuracy.py --device hip --contexts 64,520 --block-size 256 --num-q-heads 16 --num-kv-heads 2 --head-dim 256 --scale-dtype fp32 --compiler-version-file /tmp/hipengine-hipcc-version-713.txt --require-cached-build --require-int8-hip --json /tmp/hipengine-keyonly-int8-primitive-64-520.json` -> accepted. Key-only HIP vs CPU oracle max abs was `2.98e-08` at ctx64 and `2.42e-08` at ctx520, pseudo-logit top-1 `1.0`. `rocprofv3 --kernel-trace` over ctx64 showed `qwen35_write_paged_kv_int8_key_bf16_value_kernel<float>` (64 calls, `174801 ns` total) and `qwen35_paged_full_attn_decode_split_k_ctx_tensor_gqa_int8_key_bf16_value_kernel<float,8,16,2>` (1 call, `20520 ns`).
- Model quality result: key-only improves over pure K/V INT8 but does not beat the admitted prefix-8 per-token/head path. With `HIPENGINE_GGUF_INT8_KV_KEY_ONLY=1` and no BF16 mirror: prefix `0` failed `4K/1` (`KL mean=0.873115`, top-1 `0.0`, candidate current/peak `24.368/26.873 GiB` in the landed-env rerun; an earlier prototype-env rerun also failed at `KL mean=0.136334`, top-1 `0.5`); prefix `6` passed `4K/1` (`KL mean=0.00553`, top-1 `1.0`) but failed `128K/16` top-1 (`KL mean=0.01595`, top-1 `0.88235`, peak/current `25.744/24.742 GiB`); prefix `7` passed `128K/16` (`KL mean=0.00741`, top-1 `0.94118`) but saved less current memory than the admitted prefix-8 per-token/head path and had higher prefill peak (`25.554/24.803 GiB`). Do not promote key-only KV; keep it as diagnostic evidence only.
- Added compact artifact `benchmarks/results/2026-06-24-w7900-gguf-q4km-int8kv-keyonly-diagnostic.json` and updated `docs/TUNING-gguf.md`, `docs/ENVS.md`, `docs/REFACTOR.md`, `docs/KERNELS.md`, `benchmarks/README.md`, and `benchmarks/CHANGELOG.md`. Next practical options are a genuinely different calibrated KV format with a long BF16-vs-candidate guard, or non-KV residency reductions.
