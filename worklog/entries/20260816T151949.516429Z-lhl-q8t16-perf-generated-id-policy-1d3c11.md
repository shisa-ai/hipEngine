# Keep production generated IDs diagnostic in batch A/B

## Summary

Corrected the Q8T16 performance harness after the first complete c4/c8 packet
exposed a policy mismatch: free-running generated-ID equality was incorrectly
binding even though the approved production profile makes it diagnostic and
uses strict-teacher full logits as the binding numerical comparison.

## Changes

- Removed free-running trajectory equality from timing validity while retaining
  explicit diagnostic hashes and, for future captures, full first/last token
  fingerprints.
- Added a fail-closed policy revalidator for already-complete raw packets. It
  accepts only clean provenance, exact teardown, p512/d128, at least seven
  declared counterbalanced pairs, and balanced shape/run records; it records the
  original invalid verdict, source SHA256, correction commit, and command.
- Added RED/GREEN coverage proving mismatched free-running IDs remain visible
  without invalidating a production-profile timing packet.

## Validation

- The original clean `7901c822a` c4/c8 packet completed 28 measured runs with
  clean provenance and exact teardown. Its only failed predicate is the now-
  corrected generated-ID binding. Raw result:
  c4 `78.623998 -> 78.974141 tok/s` (`1.004453x`, 7/7 wins) and native c8
  `96.482397 -> 97.125349 tok/s` (`1.006664x`, 6/7 wins).
- Focused tests pass `2/2`; Python compilation and `git diff --check` pass.
- No performance artifact or package default changes in this correction unit.
