## Summary

Task #33 is resolved as **(a) a harness defect**: a `token_id_resident` contract
violation in the R7 A/B harness scripts. It is not configuration mixing and not a
runtime defect, so the batched-position promotion does not need re-examination and
no production runner fix is required.

`_finish_lm_head(capture_logits=False)` publishes the greedy token to
`token_id_buffer` via the device `argmax_f32` kernel, and steps with
`token_id_resident=True` read that buffer instead of uploading a host token. Every
R7 A/B harness script called `runner.prefill(...)` with the default
`capture_logits=True` — token computed host-side via `np.argmax`, buffer never
written — then drove decode steps with `token_id_resident=True`, so each case's
first decode step embedded whatever was last left in `token_id_buffer`.

## The contract

`Qwen4ExpGGUFResidentModelRunner._finish_lm_head(capture_logits=False)` publishes the
greedy token to `token_id_buffer` via the device `argmax_f32` kernel. Steps with
`token_id_resident=True` skip the host upload and read `token_id_buffer` directly.
Production honors this pairing:

- generator compact path: `prefill(capture_logits=False)` + steps
  `token_id_resident=True` (consistent — prefill publishes);
- generator controlled path: `prefill(capture_logits=True)` + steps
  `capture_logits=True, token_id_resident=False` (consistent — host round-trip).

## The violation

Every R7 A/B harness script (flawed v8 mid-process toggle experiment AND the
per-process attribution arms) called `runner.prefill(...)` with the default
`capture_logits=True` — token computed host-side via `np.argmax`, `token_id_buffer`
never written — then drove decode steps with `token_id_resident=True`. Each case's
first decode step therefore embedded whatever was last in `token_id_buffer`:

- fresh-process case 1: the fresh (in-practice deterministic) allocation contents;
- later cases / later repetitions: the previous sequence's final argmax token.

## Validation

All evidence below is on code-p512, 48 steps, UD-Q4_K_XL production profile.

- **Toggle reproducer** (one process, one generator, OFF/ON/OFF/ON toggles of
  `HIPENGINE_QWEN4_EXP_BATCHED_POSITION` plus the runner attribute): all four
  toggled runs bit-identical, exonerating the flag. The no-toggle control's first
  run differed from runs 2+ (`3fbadf290fceee64` versus `0017e313cfbd504a` x2) —
  first-run versus repeat divergence, not flag divergence.
- **Fresh-process ground truth**: a single run gives `3fbadf290fceee64`, so the
  fresh-state run is the canonical-family one and repeats deviate.
- **`capture_logits=True` localization**: three consecutive runs are bit-identical
  with max |Δlogits| = 0, so the mismatch lives in the `capture_logits=False` path.
- **Parameter bisect** (fresh process, 3 runs each): `(logits=0, resident=0)`,
  `(logits=1, resident=1)` and `(logits=1, resident=0)` are all stable;
  `(logits=0, resident=1)` diverges as `3fbad… → 0017…` for both `hidden`
  settings. The trigger pair is therefore exactly `capture_logits=False` +
  `token_id_resident=True`, and `capture_target_hidden` is irrelevant.
- **Flow comparison** (12 canonical cases x 48 steps,
  `sha256(json.dumps(toks))[:16]`): Flow B (the A/B harness pattern) in a fresh
  process reproduces the attribution arms' digest `ea0412231532bc7b` exactly;
  Flow A (the canonical-bench contract) gives `19045b7c9fd442e5`.

## Consequences

- **v8 mid-process mismatch explained**: the flawed experiment repeated the 12-case
  set six times in one process; repetition 1's case-1 read fresh allocation contents,
  repetitions 2+ read the prior repetition's final token — exactly two digests
  (`ea0412…`/`5d02…`). The OFF/ON toggle correlation was coincidental with run
  order.
- **Attribution artifact (0bf43f1d) stands**: all 12 arm-reps were fresh processes
  with the identical deterministic buffer history, so the digest was identical across
  arms and the arm-equality conclusion is valid. The digest is, however, the
  A/B-harness digest, not the canonical-contract digest (`19045b7c9fd442e5`);
  `digest_erratum` added to the artifact JSON. Per-step kernel work is
  token-independent in volume (fixed top-k expert routing, same shapes), so the TG
  latency deltas are unaffected.
- **Production is safe**: only the harness mixed the contracts; both generator paths
  are internally consistent. No runner fix required.
