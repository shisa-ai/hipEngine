# Gate the sliding flash route at keys 4097-8191

## Summary

The flash decode route had numeric gates at keys 1,025-2,047 (the d2/d4 pair)
and, since the promotion, at 15,857-16,383. Between them sat the whole band
where the route serves ordinary decode with the request count pinned at the
64-slice occupancy target. This closes it with a teacher-forced gate at
**keys 4,097-8,191**, above the point where the policy reaches its cap and with
the per-slice span an order of magnitude larger than the d2 baseline scored.

| check | limit | measured |
| --- | --- | --- |
| mean KL | <= 1e-3 | **6.87e-6** |
| p95 KL | <= 5e-3 | **3.69e-6** |
| p99 KL | <= 2e-2 | **5.56e-5** |
| max KL | <= 5e-2 | **5.59e-3** |
| top-1 | >= 99% | **100%**, 0 flips |

4,095 scored rows, baseline captured as the strict single-kernel chain on this
commit (`capture --prompt 8192 --prefill 4096 --slices 1`). Route observation:
**122,695 of 122,695 decode launches were flash** (`selections: [3]`), across
both head dims -- 256 for the sliding layers and 512 for the global ones -- with
keys spanning 1,024-8,191.

The task's motivating suspicion is resolved and was not a packing mechanism: the
mean KL 1.11e-2 it contrasted against the sliding route's 7.75e-6 was the Q5_1
staged prefill overrun (`ff7569f41`, fixed in `ebe2cc48b`). With that fixed, the
same global packing that read 1.11e-2 reads 2.90e-6 at 15,857-16,383 keys. The
coverage gap was real independently of that, which is why this run still exists.
