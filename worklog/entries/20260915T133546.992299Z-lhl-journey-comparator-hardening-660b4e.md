# Harden the comparator: warmups, KV dtype, stall detection

## Summary

The first pass of the engine comparison produced numbers that could not be
trusted, and three separate causes turned up. All three are now handled and
visible in the output rather than absorbed by it.

1. **No warmup.** The first request on a shape pays graph capture and
   weight-touch costs. On one engine the first 4K request measured 14498 ms
   against 5600 ms for the next two. Every case now gets unmeasured warmups and
the measured rate is the median.
2. **Stalls from memory pressure.** This host holds a 104 GB model in 125 GB of
   RAM with 125 GB of zram swap. A stalled request is an environment event, not
   an engine property, so a request below 0.7x the case median is flagged as a
   stall instead of being averaged in.
3. **KV dtype is not a free choice.** pwilkin `40a9f4d01` asserts at model load
   with BF16 KV: `qwen4exp.cpp:1360` requires `q->ne[0] == 256 && k->type ==
   GGML_TYPE_F16` on the sparse-QSA direct-indices path. The same binary loads
   and serves with F16 KV. `--kv-dtype` is now explicit and recorded.

## Changes

- `scripts/qwen4exp_llamacpp_prefill_comparator.py`: `--warmups` (default 1),
  `--kv-dtype`, per-case `median_prompt_tok_s`, `stalled_reps`,
  `median_prompt_tok_s_by_shape` and `total_stalled_reps`. The mean is still
  reported for continuity but the median is the headline.
- `tests/test_unit_qwen4exp_llamacpp_comparator.py`: adds a stall-threshold
  check and a parser check that the validity arguments are all still exposed.

- **Upstream llama.cpp supports this model.** `LLM_ARCH_QWEN4EXP` is in
  `origin/master` (added around 2026-09-03 with Unsloth's GDN `max`->`rsqrt`
  fix), so the upstream row is a real same-file comparator.
- **pwilkin's default branch is two months stale.** `master` is `e8e6c7af2`
  (2026-07-22) with no `qwen4exp` at all. The current Flash-Next work is on
  `strix-halo`, whose head is `40a9f4d01` (2026-09-15) - `hip: extend MMB quants
  and fuse Flash-Next F32 PLE`. Quoting pwilkin `master` as "latest pwilkin"
  would compare against a tree that cannot load the model.
- **halogen cannot run this file.** Its README refuses the K-quant family
  ("`Q4_K`, `Q5_K`, `Q5_1`, `Q4_1`; unsloth's `UD-Q4_K_XL`") by name at
  startup. Its 1246-1424 tok/s GGUF figures are on unsloth `UD-IQ4_XS`, a
  different file. It is out of scope for a same-UD comparison by its own
  design.
- **The fastest engine has a prompt-category pathology.** halo-box `69946438a`
  runs `code`/`general_en`/`general_ja` at 730-757 tok/s at 4K but
  `mixed_ja_en` at 328-429. The server's own log shows a step change: the first
  twelve requests report 686-769 tok/s, the last four 324-486. It is stable
  within the category, not a transient, and it reproduced in two runs. This is
  why a single-prompt or single-category comparator number is not a rate.
