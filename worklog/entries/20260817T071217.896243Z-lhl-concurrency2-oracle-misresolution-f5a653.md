# State-oracle gates ran the wrong checkout; c4/c8 promotion reverted

## Summary

`scripts/gguf_packed_ar_state_oracle.py` had no `sys.path` bootstrap, so every
plain `python3 scripts/...` oracle invocation resolved `hipengine` through the
shared therock env's editable install — pointing at `/home/lhl/hipEngine`, a
separate checkout on branch `redline-integration-spike` since 2026-07-31 17:52,
i.e. the entire concurrency2 campaign. All gfx1100 state-oracle byte-exact
evidence (the c2/(1,2) qualification, the Aug-16 C2-6 packet's state-level
claims, and the c4/c8 gates behind `4baed0f33`) measured the wrong tree's
kernels. Agent-caused tooling defect, not a hardware or kernel regression: the
GPU is healthy and the in-session "GPU degradation" alarms were misdiagnosis of
this same misresolution.

## Changes

- `0855899d5` — revert of `4baed0f33` (c4/c8 width promotion, host gates, docs,
  artifact): its byte-exact gate evidence was measured on the wrong tree.
  `GGUF_SHARED_SLOT_AR_PHYSICAL_WIDTHS` returns to `(1, 2)`.
- `46466a86e` — root-cause fix: REPO_ROOT bootstrap in the oracle script (same
  pattern as `server_f1_concurrency_bench.py`), plus `hipengine_module`
  provenance and an out-of-checkout warning in the JSON payload; pytest
  `pythonpath = ["."]` so collection resolves this checkout regardless of the
  editable install (the same shadowing caused 204 collection errors in plain
  `uv run pytest`).
- Audited the other concurrency2 gate scripts
  (`gguf_reference_oracle_worker.py`, `dms_backend_gate.py`, `smoke.py`,
  `server_f1_concurrency_bench.py`): all already had the bootstrap.

## Validation

- Provenance: 27 recorded campaign oracle invocations used plain
  `python3 scripts/...` (no PYTHONPATH); only 3 gfx1151 runs used
  `PYTHONPATH=$PWD`. JIT cache is keyed by source path, so the two trees had
  distinct builds — the oracle genuinely executed redline kernels.
- Re-measured on the redline checkout (exact original flags): c2 and c8 packed
  AR bit-identical to independent c1 — that is what all prior byte-exact
  evidence actually measured.
- Re-measured on THIS checkout (PYTHONPATH-forced): c2 **and** c8 both fail
  state byte-exactness — tokens exact everywhere (`token_mismatches: 0`,
  consistent with all server-side exact gates) but layer hidden states diverge
  from decode step 1, layer 1 (max_abs ≈ 0.014–0.016, ~2000 elements);
  deterministic across repeats. Identical signature for c2 (the retained
  default) and c8, so it is branch-wide packed-vs-c1 arithmetic divergence, not
  a c4/c8-specific defect.
- Server-side evidence is unaffected: the server bench bootstraps REPO_ROOT, so
  all HTTP-level exactness and performance numbers (F1 sweep, matched packets,
  p512 runs) genuinely ran this tree.
- `python3 scripts/gguf_packed_ar_state_oracle.py --help` passes post-fix;
  plain pytest collection (previously 204 errors) now succeeds.
