# Qwen4Exp PS14: complete HTTP grid, recovery soak, and milestone-gate finding

## Summary

PS14 is complete for the served surface and the checklist is now fully closed
except for one pre-existing defect outside the served path. The full HTTP grid
runs 50 probes against one live server at 32,768 context and two slots with no
non-200 response; the mixed-request soak passes 35 checks over three rounds at
width 4; the requirement-to-evidence audit resolves 27 artifact links with zero
findings; and the stale PS2 row was closed against the artifact-fingerprint
resolver that already existed. `pytest --suite all` cannot go green on this
tree: it aborts with SIGABRT after 23 percent, and three further runs abort at
three different files, always at a `hipMemcpy` or `hipFree`. That path is
Qwen3.5 linear-attention and Q4_IU8 MoE tile code, which the served Qwen4Exp
model never reaches.

`unsloth-Qwen3.8-Flash-Next-UD-Q4_K_XL/UD-Q4_K_XL`, execution profile
`production`, BF16 KV, `ar_batch=1`, `speculative_mtp=opt_in`,
`candidate_budget=3`.

- HTTP grid, 50 probes, `max_context_tokens=32768`,
  `max_active_requests=2`:
  `.venv/bin/python scripts/qwen4exp_http_grid.py --url http://127.0.0.1:18400 --model qwen38fn-capon --long-tokens 30000 --output /tmp/grid_ps14.json`
  — 50/50 HTTP 200; 24 probes executed the AR route and 24 executed MTP with
  `used=true`, so each row is checked against its recorded payload rather than
  its status; both streaming probes emitted SSE events with usage and terminal

  91.01 s; `/ready` returned `ready` after the grid.

  `.venv/bin/python scripts/qwen4exp_http_soak.py --url http://127.0.0.1:18400 --rounds 3 --output /tmp/soak_ps14c.json`

  after every round; a fixed greedy prompt returned identical answers across
  rounds; the documented `429 engine_busy` refusal is retryable.
- Evidence audit: `.venv/bin/python scripts/qwen4exp_serving_evidence_audit.py`
  — 16 rows, 27 links, 0 findings. The audit found four unsourced figures while
