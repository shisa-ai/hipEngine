# Gemma 4 reaches LLM.generate() end to end; fix the generator's model_path

## Summary

`LLM.generate()` now runs Gemma 4 end to end and returns detokenized text. Two
real defects stood between the registered generator and that result:

- `Gemma4GGUFGenerator.__post_init__` read `self.weight_index.model_path`, an
  attribute `GGUFModelInfo` does not have, so construction raised
  `AttributeError` on the first request. The dataclass already carried a correct
  `model_path` field; the line was overwriting it.
- The fixture could not build a loadable end-to-end artifact. `FIXTURE_VOCAB` is
  64 while `tokenizer_fixture_metadata` declares 294 tokens, and the loader
  checks the two against each other, so the load failed with a shape error.

## Changes

- `hipengine/generation/gemma4_gguf.py`: normalize `self.model_path` instead of
  reading a nonexistent attribute off the weight index.
- `tests/_gemma4_gguf_fixture.py`: `default_fixture_tensors` takes a `vocab`
  parameter so an end-to-end artifact can match the tokenizer section's width.
- `tests/test_unit_gemma4_generate.py`: new module covering the public surface —
  `LLM.generate` resolves the Gemma 4 generator, decodes, and returns text, plus
  a token-budget check that separates a real decode loop from one that stops
  after a single step.

## Validation

- `LLM.generate("Hello", SamplingParams(max_tokens=16))` on the fixture returns
  `['<eos>b<pad><turn|>']` through `SubmitPollTextGenerator` -> `Gemma4GGUFGenerator`
  -> `Gemma4Runner` -> device kernels. The text carries no meaning because the
  fixture weights are synthetic; the path completing is the result.
- `pytest tests/test_unit_gemma4_generate.py` — 2 passed.
- `pytest tests/ -k gemma4` — 164 passed, exit 0, zero failures.
- No new `sq_intr` faults in `dmesg` during the end-to-end run.

## Next

## Why this unit matters more than its size

The Gemma 4 generator was registered and constructing a generator object worked,
so every existing test passed while the first real request raised. Nothing in the
suite called `LLM.generate` for Gemma 4 — the coverage stopped exactly where the
user starts. The two-line `model_path` fix was the whole gap between "the adapter
is wired" and "the adapter runs".
