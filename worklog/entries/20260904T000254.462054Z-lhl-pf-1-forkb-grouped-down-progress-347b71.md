# PF-1 fork-b grouped selected down: kernel win, wired default, whole-model A/B pending

## Summary

The PF-1 fork (b) T0 candidate (`gguf_k_selected_grouped_prefill_out_kernel`,
one block per (expert, out_col) pair serving every lane of the pair, weight
row read once) is bit-exact vs the strict per-expert selected gemv owner and
measured **−31.6%** at the production p4096 compact down shape in a paired
kernel-level A/B (32.42 vs 47.42 ms median, two independent runs). It is
wired as the Qwen4-exp Q8_0 down default inside the grouped-prefill block
with opt-out `HIPENGINE_QWEN4_EXP_FORKB_GROUPED_DOWN=0`. Whole-model
same-session counterbalanced A/B is in flight.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_k_gemv.{hip,py}`: grouped
  selected down kernel, launcher, extern export, python wrapper. Per-output
  arithmetic identical to the owner (same k sequence, ordered
  `acc += xv * wv`, same `reduce_block_sum` reduce + serial wave
  publication); inter-lane `__syncthreads()` guards the shared wave_sums
  scratch across the lane loop.
- `hipengine/runtime/qwen4_exp_runner.py`: Q8_0 down dispatch inside the
  grouped-prefill block routes through the fork-b kernel by default,
  consuming the already-built `group_expert_start` + `group_sorted_lanes`
  map; flag off restores the strict per-expert selected gemv. Legacy P1
  WMMA/grouped owners unchanged below the new branch.
- `tests/test_qwen4exp_pf1_forkb_selected_down.py`: kernel bit-parity +
  determinism + uneven-expert boundary case, plus a runner-level gate
  asserting whole-MoE output bits identical between default and flag-off.
- `docs/REFACTOR.md`: fork-b flag entry with removal trigger.
- Distinct from the perf-negative P1 grouped owner (worklog
  20260830T202256, 3-12x slower than strict): different dataflow, no serial
  expert loop, no OUT_BATCH=1.
