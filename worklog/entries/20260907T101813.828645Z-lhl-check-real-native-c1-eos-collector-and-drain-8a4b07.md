# Check real native C1 EOS collector and drain

## Summary

Prepare a real-engine configured-EOS diagnostic for a native C1 survivor.
GPU EOS qualification is blocked by shared MTP admission. The diagnostic
correctly rejects the exact AR fallback because no native target runs.

## Changes

- Add a request helper that sets EOS to a first-occurrence independent AR
  token at index >=12, before the final output token. Keep min_tokens=0:
  suppressing earlier occurrences could change sampling and the AR comparison.
  Leave max_tokens and the explicit speculative ownership unchanged.
  This is a correctness fixture, never a performance or acceptance input tweak.
- Validate returned IDs against the exact AR prefix including EOS, EOS finish
  reason, and actual terminal collector request identity, IDs, and error state.

## Validation

- Seven new tests fail before helper creation, then all pass (0.39s).
  Negative cases reject output/collector ID drift, wrong finish reason,
  wrong collector identity, and terminal errors.

- Real `submit_engine_pair` integration has a RED/GREEN test checking only
  the survivor request changes and actual collector evidence is returned.
  A fake eligibility object initially failed schema validation; replaced it
  with the real `SpeculativeMTPStaticEligibility` type. All 62 focused
  EOS/lifecycle/cancel/refill tests and `git diff --check` pass.
- `--engine-boundary --eos-survivor` requires native C2-to-C1 trace, exact peer,
  exact EOS prefix/collector bound to the traced survivor and serialized drain.
  Other scenarios cannot be combined. No public usage qualification.
- `bg-101` runs GPU0 N8 then N2 with
  `HIP_VISIBLE_DEVICES=0 ROCR_VISIBLE_DEVICES=0 GPU_MAX_HW_QUEUES=1
  HIPENGINE_HIP_ARCH=gfx1100 .venv/bin/python scripts/qwen38_packed_c1_lifecycle.py
  --engine-boundary --eos-survivor --capacity N --output /tmp/packed-c1-eos-nN.json`.
  Logs have the same stem with `.log`; results pending.

- Three additional helper guards cover repeated EOS markers, minimum-token
  suppression, and out-of-range indices. The minimum-token fixture initially
  violated GenerationRequest validation (missing EOS); repaired it with EOS=99.
  All 11 EOS tests now pass (0.38s); no running script/runtime changes.

- `bg-101` failed N8 first prompt: no real C2-to-C1 transition, zero target
  traces/cells, clean teardown; N2 never ran. Therefore no native EOS proof.
- Persist last EOS/returned response evidence even if transition validation
  fails; keep the hard native transition gate. All 37 focused EOS/lifecycle
  tests pass. `bg-102` retries N8 only with `HIPENGINE_MTP2_TRACE_DECLINE=1`,
  same command otherwise, output `/tmp/packed-c1-eos-v2-n8.json` and `.log`.
  This traces admission rather than assuming a target-state bug.

- CPU source localization: `generation/sampling.py:800–813` explicitly adds
  `eos_token_id` to speculative MTP blockers even when the sampler itself is
  GREEDY_FAST. A direct request comparison prints no blockers for EOS=None and
  `('eos_token_id',)` for EOS=12, both GREEDY_FAST. `engine_loop.py:2464`
  translates that into processed semantics. This explains why a configured
  EOS request cannot qualify the existing native route; no kernel bug claim.

- `bg-102` confirms the block: zero native target traces, passed=false,
  clean teardown. The D24 child returns exactly the independent AR prefix
  through EOS=7308 at index 12; its terminal collector matches all 13 IDs and
  both service/backend request ID 3. This output correctness does not certify
  MTP. N2 was not run. Compact blocked evidence:
  `benchmarks/results/2026-09-07-w7900-packed-c1-eos-blocked.json`.
- Commit this diagnostic as a bounded blocker reproduction, not a runtime fix
  or passing GPU gate. All 11 EOS helper and 37 combined EOS/lifecycle CPU
  checks passed; the failure evidence and shared blocker remain intact.
