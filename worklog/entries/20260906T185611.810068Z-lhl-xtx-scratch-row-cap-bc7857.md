# XTX dense prefill scratch row cap moves boundaries

## Summary

Closed the "prefill scratch rows" remainder of the Packet 2 right-size item.
Root cause of the ~1 MiB-per-declared-token memory slope: the retained >1K
auto policy resolves a 4096-row full-attn query chunk, so
`_prefill_scratch_rows(capacity)` returned the full declared context for every
declared context at or below 4096, and the dense bulk-prefill scratch (plus the
bf16 hidden plane pair and token buffer) scaled with `max_positions` instead of
the 64 KiB/token KV payload. gfx1100 registered no
`GGUF_DENSE_PREFILL_SCRATCH_ROW_CAP_POLICIES` entry (gfx1151's is dense-Q4_K_S
keyed), so nothing bounded it.

Fix: geometry-keyed registry policy on gfx1100 for
(`QWEN35_DENSE_H5120_GEOMETRY`, `MOSTLY_Q4_K_M`) with `min_capacity 1024 ->
max_rows 1024` — the same retained outer chunk the 24GB low-memory (52K+) and
gfx1151 8K+ policies already use. Measured on the XTX (same repaired-probe
protocol, one cold server per point):

- BF16 declared-context boundary 3,840 -> 40,960 tokens (10.7x). Direct A/B at
  3,840: request peak 21.820 -> 19.375 GiB (-2.445, -11.2%). 4,096 (pre-fix
  first OOM at 23.951) now passes at 19.379; 8,192/16,384/32,768 pass at
  19.955/21.098/23.162; 40,960 passes razor-thin at 23.973; 45,056 fails
  startup OOM at 23.943.
- INT8 fp32/per_token_head: 5,120 (pre-fix first OOM) now passes at 19.290 and
  the route reaches 15,872 (20.349). The next blocker is FUNCTIONAL, not
  memory: request-time HIP error 1 (invalid argument) in (15872, 16128],
  reproduced uncapped on the base tree at 16,384 (22.771 GiB peak). Recorded
  as a pre-existing INT8 long-context kernel blocker for a separate unit.
- d512 concurrency (declared 1,280, 512-in/512-out): solid last pass N=3 ->
  N=4 (23.821 clean; pre-fix N=4 was marginal/not_idle), N=5 marginal
  (serves the horizon; idle residue 159 MiB vs the 128 MiB gate, reproduced),
  N=6 startup OOM (23.976). N=3 peak 22.692 -> 22.129 (-0.19 GiB/session).

## Changes

- `hipengine/kernels/hip_gfx1100/__init__.py`: register
  `GGUF_DENSE_PREFILL_SCRATCH_ROW_CAP_POLICIES` for the dense H5120 Q4_K_M
  geometry (min_capacity 1024, max_rows 1024) and export it. No dispatch/engine
  branch added; the existing `_gguf_dense_prefill_scratch_row_cap` registry
  lookup consumes it unchanged.
- `scripts/gguf_context_ceiling_probe.py`: fix the default prompt-fit target
  (`context - max_tokens` -> `context - max_tokens - 1` via
  `default_prompt_token_target`); the server charges prompt + max_tokens + 1
  against the preallocated context, so exact fits at declared 8,192/32,768
  failed with 400 context_length_exceeded (observed prompt 8,177/32,752).
  This harness defect, not memory, produced the first two 8K/32K
  request_failed rows.
- `tests/test_qwen35_gguf_geometry_policy.py`: RED-first test for the row-cap
  registration, cap values (768 uncapped; 1,024/1,280/2,048/3,840/4,864/8,192
  -> 1,024), and session-level `_prefill_scratch_rows` behavior.
- `tests/test_gguf_context_ceiling_probe.py`: RED-first test for the +1 prompt
  target reservation.
- Artifact: `benchmarks/results/2026-09-06-rx7900xtx-capacity-scratch-row-cap.json`
  (all points, prior values, parity evidence, commands).
