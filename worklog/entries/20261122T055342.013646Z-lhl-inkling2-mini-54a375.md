# Check grouped Inkling integer-dot prefill on real prompts

## Summary

Grouped Q8 prefill shortened the warm diagnostic requests, but one short-prefix teacher-forced Strix Halo row exceeded the numerical safety floor despite matching the top token. Do not integrate the grouped Q8 chain as tested.

## Changes

- Scratch only. Compared the existing public `fast` profile with the [grouped Q8 leaf](20261122T054919.424003Z-lhl-inkling2-mini-af60dd.md) substituted only for tiled NVFP4 prefill. The single-token integer-dot projection, activation, cache storage, and sampling were unchanged.

## Validation

- `python -u ./hipengine_inkling_q8_tile4_public_probe.py "$model" "$backend" "$so"` on W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL, hipEngine `33e0e9719` runtime, FP32 KV, no prompt reuse or drafting. All 16 teacher-forced rows per GPU retained the top token at 47, 151, 575, and 1,027 input tokens. On Strix the fourth 47-input row had KL divergence `0.085515` from the existing `fast` path, above the `0.05` outer floor; W7900's worst was `0.025181`. The small screen is not production qualification.
- The trial reproduced the same eight greedy IDs as the control on both GPUs at 151 and 575 input tokens. Median seconds over two warm samples per arm, in both orders: W7900 control/trial 2.418/2.319 at 151 and 7.929/7.454 at 575; Strix 3.084/2.890 at 151 and 10.824/9.798 at 575. These compare against the existing `fast` path, not Loom. Logs: `/tmp/kendex-pi-bg/bg-91-1795326655291.log`, `/tmp/kendex-pi-bg/bg-92-1795326655308.log`.
