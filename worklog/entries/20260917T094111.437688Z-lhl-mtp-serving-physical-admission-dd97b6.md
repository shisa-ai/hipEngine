# Make speculative-MTP serving admission physical, not shape-scoped

## Summary

Speculative-MTP serving admission no longer depends on prompt context, output
horizon, session length, or the resolved execution-profile manifest. Those four
axes described the envelope a benchmark measured, not the physics of the
verified path, and every one of them changes with ordinary serving traffic or
with any kernel/variant selection. Gating on them silently disabled an
already-qualified path, which is why the 2026-09-17 Atlas comparison could not
measure hipEngine MTP at all: a 128-token horizon at a 16,384-token session
under the current production manifest failed four axes at once and failed closed
to AR.

Admission is now decided only by artifact content, backend, target arch, weight
quant, KV storage/layout, realized group rows, resident capacity, candidate
depth, sampling mode, and memory fit. Two rules replace the removed axes:

- When several retained rows describe one physical cell, the cell takes the
  strongest authorization: an automatic-eligible row wins over an explicit-only
  row, and remaining ties keep declaration order. Without this, the strict
  explicit-only row for gfx1100 dense C2/K2 would have shadowed the production
  automatic row purely because of declaration order.
- Profile safety stays with the provider. FP16 recurrent-state spec-dec2 still
  requires a complete non-fallback production manifest
  (`_fp16_specdec2_profile_authorized`), independent of serving admission.

## Changes

- `hipengine/speculative/serving.py`: removed the five checks
  (`execution_profile_not_qualified`, `execution_profile_manifest_not_qualified`,
  `max_sequence_length_not_qualified`, `context_bucket_not_qualified`,
  `output_horizon_not_qualified`) and the seven evidence-row / five key fields
  that carried them. Added the strongest-authorization rule for exact physical
  matches and for the deferred static-eligibility override.
- `hipengine/models/qwen35.py`: 16 evidence rows lost their shape/profile
  fields. Evidence keys, reasons, artifacts, depth bounds, sampling modes, and
  `automatic_eligible` are unchanged, so the measured envelopes remain readable
  provenance.
- `hipengine/generation/qwen35_gguf.py`, `hipengine/llm.py`,
  `hipengine/server/api.py`: dropped the removed axes from the resolver
  signature, key construction, capability resolution, and the two route
  resolution call sites. `LLM.resolve_speculative_mtp_serving_plan` no longer
  accepts `context_tokens`/`output_horizon_tokens`.
- Diagnostic harnesses updated to the same physical contract:
  `scripts/gguf_mtp_c1c8_server_bench.py` (its local `_diagnostic_plan`),
  `scripts/qwen38_packet5_k4_watchdog_probe.py` (base-row selection),
  `scripts/qwen38_packed_c1_lifecycle.py` (the D8 clone is gone: one row now
  covers both retirement children), `scripts/qwen38_packed_c1_wide_refill.py`.
- Docs: `docs/EXECUTION-PROFILES.md` §2.9 states the contract and the three
  campaign sentences that read as current policy were corrected;
  `docs/API.md` documents the route-decision reasons and the physical axes;
  `docs/REFACTOR.md` records the three now-shadowed rows and the historical
  campaign documents that were deliberately left intact.
- Tests: `tests/test_unit_speculative_mtp_serving_capability.py` (43 pass),
  `tests/test_integration_server_api.py`,
  `tests/test_unit_qwen38_packed_c1_lifecycle.py`,
  `tests/test_unit_qwen38_packed_c1_wide_refill.py`,
  `tests/test_unit_gguf_mtp_c1c8_server_bench.py`. The axis guard test now
  fails if any removed axis is reintroduced as a key or row field.
