# VibeVoice ASR native implementation for gfx1151/gfx1100

## Summary

Native (torch-free HIP) implementation of VibeVoice-ASR per
`docs/MODEL-VIBEVOICE-ASR.md`, targeting gfx1151 (Radeon 8060S) with
gfx1100 compatibility. Correctness first vs torch CPU and torch GPU (ROCm),
then speed vs torch GPU.

## Changes

- Environment frozen for oracle work: transformers 5.15.0 (has
  `vibevoice_asr` + `vibevoice_acoustic_tokenizer`), torch 2.13.0+rocm,
  huggingface_hub 1.27.0, python 3.13 (miniforge). Host: Strix Halo
  Ryzen AI MAX+ 395 + gfx1151.
- Original artifact `microsoft/VibeVoice-ASR` (rev d0c9efdb) fully cached
  (17 GB, 8 shards, 1177 tensors, all **BF16** - the config `"dtype":
  "float32"` is misleading metadata; weights are BF16 ~8.5B params).
  HF artifact `microsoft/VibeVoice-ASR-HF` download started (background).
- Weight inventory complete: `model.{acoustic,semantic}_tokenizer.encoder.*`
  (stem conv K7, 6 downsample stages with strided convs kernel 2*stride,
  ConvNext blocks norm->depthwise conv K7->gamma, ffn_norm->linear1(4x)->
  gelu->linear2->ffn_gamma, head conv), `model.{acoustic,semantic}_connector
  .{fc1,norm,fc2}`, `model.language_model.*` (Qwen2-7B: separate q/k/v
  proj weights+biases, untied lm_head).
- Encoder topology verified against installed transformers source:
  stem left_pad 6; downsample stage s: in 32*2^s -> out 32*2^(s+1),
  kernel 2*ratio, stride ratio, left_pad ratio; head 2048->64/128 K7.
  Ratios [2,2,4,5,5,8], total stride 3200. Output frames =
  nested floor(L/stage_strides) = floor(L/3200) for full passes.
  Acoustic sampling noise drawn AFTER chunk concat: scale
  vae_std*randn(batch) per example times randn_like(latents).
