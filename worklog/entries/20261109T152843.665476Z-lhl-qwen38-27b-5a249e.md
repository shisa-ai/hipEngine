# EAGLE-4 device-resident fc projection: cycle wall -19.1% (task #25c)

## Summary

Task #25 part (c): move the EAGLE-4 committed-aux fc projection off the host and
onto the device, reading the target verify's graph-owned FP32 aux buffers directly.
The host numpy projection (`project_target_features`, fc 15360->5120 + 3 RMS-norms)
measured 21.2 ms/call — the dominant cost in the ~35 ms append phase — and stalled
the host pipeline. On device it is a memory-bound bf16 GEMM (~0.2-0.5 ms).

Profiling first (`/tmp/eagle4_append_profile.py`, 8 steady cycles, m=3 committed
rows) attributed the append phase: host_proj 21.24 ms, d2h_concat 1.87 ms,
h2d_feat_embed_pos 0.68 ms, device _qkv/_store_kv/_finish_last_feature 11.07 ms;
append_total 34.85 ms. The host projection + aux D2H + feature H2D (~23.8 ms) is
what device projection eliminates.

Same-process A/B (`/tmp/eagle4_projection_ab.py`, real Qwen3.8-27B-Q4_K_M,
gfx1151, n_draft=2, 64 tokens, 27 graph cycles, 3 alternating runs/path; host path
monkeypatched to the old D2H+concat+append_committed):

| path | cycle wall (64 tok) | tok/s | graph cycles | accept/draft |
| --- | --- | --- | --- | --- |
| host projection | 5466.18 ms | 11.71 | 27 | 1.37 |
| device projection | 4423.61 ms | 14.47 | 27 | 1.37 |

Cycle wall -1042.57 ms (-19.1%); device==host output token-identical. The realized
per-cycle win (~38.6 ms) exceeds the raw 21 ms host projection because the host
matmul also stalled host enqueue/pipelining; on device the host runs ahead.
