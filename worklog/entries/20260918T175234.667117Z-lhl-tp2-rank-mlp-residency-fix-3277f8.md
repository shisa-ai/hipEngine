# TP2 ranks stop materializing the MLP the shard group already owns

## Summary

The cross-engine comparison
(`20260918T172237.892687Z-lhl-tp2-external-llamacpp-comparison-467836.md`) found
that TP2 used 22.37 GiB per rank against the shard manifest's planned 7.83 GiB of
resident weights per rank, and left the 24 GiB RX 7900 XTX rank with 1.58 GiB
free. The cause is now identified and fixed, and the fix is larger than the
manifest arithmetic predicted.

**Cause.** `MlpTP2GenerationSession._build_rank` built a full
`Qwen35GGUFFullStackRunner` per rank with no slot restriction, then
`_build_shard_group` materialized and uploaded that rank's MLP shard *in
addition*. Every rank therefore held the complete `ffn_gate`/`ffn_up`/`ffn_down`
set for all 64 layers - 9.650 GiB of GGUF source weights, and more than that
resident after the t16 decode repack - while `_shard_group.forward` served every
MLP call from the shard. The only reader of a runner's resident MLP is
`_local_mlp`, which runs in the `else` branch of `if self.mode == "tp2"`, i.e.
only in the matched single-GPU control mode. In a `tp2` session those weights
were unreachable.

**Fix.** A `tp2` rank's runner is now built from an explicit slot allowlist that
omits the MLP leaves the shard group owns, so the weights are never materialized
instead of being materialized and held for the session's lifetime.
`rank_slot_allowlist_from_records` derives the allowlist from the file's own role
manifest and takes the leaf names from the shard module's `MLP_TENSORS`, so a
different model or layer count stays correct and the allowlist cannot disagree
with the shard materializer about what the shard replaces. `tp1` mode keeps the
full slot set because `_local_mlp` needs it.

**Measured effect** (same host, same GGUF, per-device `hipMemGetInfo` delta after
load, validated device-scoped earlier this session):

| TP2 configuration | rank 0 (W7900) | rank 1 (RX 7900 XTX) | free on XTX |
| --- | ---: | ---: | ---: |
| even split, before | 22.402 GiB | 22.402 GiB | 1.58 GiB |
| even split, after | 12.402 GiB | 12.402 GiB | 11.58 GiB |
| 0.44/0.56, after | 11.650 GiB | 12.840 GiB | 11.14 GiB |

**10.00 GiB per rank returned**, 44.7% of the previous footprint, which is more
than the 4.825 GiB of source bytes because the resident copy also carried its t16
decode repack. Throughput is unaffected or better: the even split measured 41.03
tok/s prefill / 40.48 tok/s decode at 128/16 against 39.49 / 38.79 at 512/128
before the change, and the 0.44/0.56 split measured 42.77 / 42.11 tok/s, i.e. the
retained uneven split is also the fastest TP2 configuration measured so far.
Against llama.cpp's tensor split (7.75 GiB per rank) the gap closes from 2.89x to
1.60x.

**Arithmetic is unchanged by construction.** The restricted preflight produces
the *same* manifest fingerprint (`a0b9749e2d7bde4b`) and the same
`artifact_preset_key` (`None`, a pinned qualified plain control) as the
unrestricted one, so the recurrent-state dtype policy and every
artifact-qualified route resolve identically. The removal is of unreachable
weights, not of a participating operand.

## Changes

- `hipengine/distributed/tp2_generate.py` — `rank_slot_allowlist_from_records`
  (pure, manifest-driven), `_rank_slot_allowlist`, and the `selected_slots`
  passed to each rank's runner when `mode == "tp2"`.
- `hipengine/runtime/qwen35_gguf_runner.py` — `Qwen35GGUFFullStackRunner` gains
  an optional `selected_slots` forwarded to the materializer; `None` keeps the
  full-model default for every existing caller.
- `tests/test_unit_distributed_tp2_generate.py` — four tests: the allowlist drops
  exactly the shard-owned leaves across layer types; it refuses a manifest with
  no MLP leaves; a `tp2` session passes the allowlist to every rank's runner; a
  `tp1` session passes `None` so `_local_mlp` keeps its weights.
- `.gitignore` — ignore rocprofv3's `*_results.db`. The harness's
  `_git_dirty()` uses `git status --porcelain`, so a stray profiler directory
  from another session marked a clean revision as dirty; that provenance signal
  now reflects tracked changes.
- Artifacts: `2026-09-18-w7900-tp2-residency-fix-even.json`,
  `2026-09-18-w7900-tp2-residency-fix-044.json`, and the clean-revision
  certification `2026-09-18-w7900-tp2-uneven-split-044-gate-clean.json`.
