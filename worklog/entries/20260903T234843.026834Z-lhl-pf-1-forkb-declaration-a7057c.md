# PF-1 fork (b) declaration: T0 bit-exact dense kernel for coltile-served shapes

## Summary

Opening the PF-1 remainder unit along campaign section 6.3 fork (b): build a
**bit-exact faster dense kernel** for the shapes served by the exact F32
coltile owner, matching coltile's reduction order rather than replacing it.
Arithmetic class: **T0** (bit-exact; same per-output accumulation order —
k strided by threadIdx.x over 128 threads, ordered `fmaf`, wave32
`__shfl_down` reduce, serial wave-0..3 publication — same output bytes).
Per section 6.3 this needs the exact-parity RED gate, a
`rocprofv3 --kernel-trace` smoke, and a whole-model counterbalanced A/B; **no
production-numerics packet** (PF-0 dependency not binding for T0).

## Registered strict fallback

The strict fallback is the existing exact owner chain already registered:
`KernelKey("hip_gfx1100", "linear", "gguf_q8_0", "coltile8_rowbatch4_f32_f32_out")`
→ `gguf_k_prefill_out_coltile_rowbatch_kernel<float,float,8,8,4>`
(`hipengine/kernels/hip_gfx1100/quant/gguf_k_gemv.hip:638`), with sibling
registered geometries `coltile4_rowbatch8` and `coltile16_rowbatch4`. Any new
candidate registers under its own four-axis variant key and dispatches only
via registry/policy selection; the coltile8_rowbatch4 owner remains
production until a candidate passes the full section 6.5 gate.

`dense_projection_compute` family = 8,767 ms/req vs llama.cpp 337.7:

| Kernel | ms/req | In scope? |
| --- | ---: | --- |

| `gguf_k_selected_prefill_out_kernel<ushort,ushort,8>` (dense-FFN layers 2/4/30/46/47 down, 40 launches) | 3,065.2 | Secondary (block-per-output GEMV at prefill shapes; candidate schedule: share the expert's weight row across rows mapping to the same expert, preserving per-output k-order) |
| `gguf_k_selected_prefill_out_kernel<…,5>` (layer-2 Q5_K) | 2,325.4 | No — OUT of PF-1 per campaign (WMMA variant rejected on numerics; strict path stays) |

Geometry retiles inside the existing coltile family are **closed, not just
explored**: `benchmarks/results/2026-08-31-gfx1151-qwen38-flash-next-p3-attn-gate-exact-geometry-exhausted.json`
measured every registered variant at the rows508/K2560/N6144 attention-gate
shape — incumbent coltile8_rowbatch4 8.042 ms fastest; c4r8 10.59, c8r8
12.46, c16r2 9.69, c16r4 18.06, c32r1 37.92 ms, all bit-exact. No retile
point remains admissible on the coltile family.

Fork (b) primary target is therefore the **selected Q8_0 down**
(`gguf_k_selected_prefill_out_kernel<ushort,ushort,8>`, 3,065.2 ms/req, 40
launches/req ≈ 76.6 ms/launch). Production call site
(`qwen4_exp_runner.py` `selected_projection("expert_down", …, x_rows=compact,
selected_rows=compact, in_features=ffn, out_features=hidden)`): launch grid =
(out_features, compact) with one 128-thread block **per output element** —
13.1M blocks at compact=5120, out=2560 — and each block re-reads its expert's
weight row. Rows sharing an expert (~compact·top_k/experts ≈ 100/launch) re-
read the same 680-byte row ~100×. Measured 76.6 ms for 2·13.1M·640 MACs ≈
219 GFLOP/s — far below device capability; the schedule, not the arithmetic,
is the deficit.

Candidate (T0, bit-exact by construction): a **grouped selected down** —
per-expert row lists (the M2 group-map infrastructure already produces
`expert_start`/sorted-lane maps), grid = (out_features, experts), each block
serves all lanes of one (expert, out_col) pair, reading the weight row once
while every output keeps the exact per-thread k sequence (`k = tid; k +=
blockDim.x`, ordered `fmaf`), the wave32 `__shfl_down` reduce, and the serial
wave-0..waves-1 publication of `reduce_block_sum` (gguf_k_gemv.hip:238).
Identical arithmetic per output ⇒ identical bits; 13.1M → 1.3M blocks and a
~10× weight-traffic cut are the mechanisms.

Secondary (deferred): coltile F32 attention-gate roles have no admissible
retile left and no unexplored T0 mechanism identified; revisit only if the
selected-down lever closes with a win and time remains.
