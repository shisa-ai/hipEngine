# Fix the Gemma accumulation oracle scalar conversion

## Summary

The accumulation grid-independence test failed inside its NumPy oracle before
comparing device results. Packing a scalar with `ascontiguousarray` produced a
one-element array, whose conversion to a scalar is rejected by this NumPy
version. This is an oracle compatibility failure, not a kernel arithmetic failure.

## Changes

- `tests/test_unit_gemma4_gpu_kernels.py`: pack and widen the whole expert-output
  array once, then index scalar values inside the existing ordered FP32 sum.
- Preserve all bitwise device/oracle comparisons, grid variants and sentinel
  checks. No runtime or kernel changes.
