# Replay Gufo ordered depth history with native count contracts

## Summary

Add an ordered-depth adapter around Gufo's reviewed Python benchmark code.
The reference checkout and executable are read-only inputs. This preserves
calibration requests, warmup, eight-token prefix replies, adaptive retries and
cross-depth calibration rather than approximating them with independent long
prompts. No runtime arithmetic is changed.

## Changes

- Add `scripts/qwen4exp_gufo_http_replay.py` with AR, MTP prose and MTP
  repetition arms. The default keeps the publication's ordered eight-depth
  history, capacity 133760, pp2048/tg128 and single sample. Explicit depth
  subsets and repeat extensions have a distinct protocol label.
- Capture every request, prefix reply and failed attempt in a JSONL journal
  outside the reference checkout. Bind source, executable and benchmark-script
  hashes, exact server commands, per-arm host state and temperatures.
- Check short-request allocation at the requested capacity, then reopen a
  fresh server before calibration so the capacity probe cannot alter measured
  prefix history. `--probe-only` supports allocation-only diagnostics.
- Validate native cached/new/output counts, positive phase durations and
  speculative work. Keep output-count and transition-count rates distinct;
  text hashes are not labelled native token identity. G0–G4 are explicit and
  incomplete until the same-pin characterization is attached.
- Document the command in the campaign without closing BASE.
