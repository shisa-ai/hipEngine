# Reject selective unsafe math for Qwen3.6 PARO SiLU

## Summary

Tested ROCmFPX transferable opportunity 4 on the repaired Qwen3.6
35B-A3B packed-PARO path: compile only the profiled PARO SiLU/rotate family as
a separately hashed gfx1151 object with `-funsafe-math-optimizations`. Explicit
NaN/Inf branches preceded the finite arithmetic path; blanket `-ffast-math` and
`-ffinite-math-only` were prohibited. The candidate passed the numeric gate but
regressed its target operation by **7.67%**, so it is rejected and no complete-
model run is justified.

## Changes

- Temporarily added an `unsafe_math=True` PARO SiLU build variant and explicit
  non-finite SiLU sentinels, built strict and candidate code objects under
  different cache keys, then removed the entire candidate after measurement.
- Added compact rejection artifact
  `benchmarks/results/2026-08-16-qwen36-35b-gfx1151-rocmfpx-opp4-unsafe-math-rejected.json`.
- Kept the strict registered PARO SiLU object as the only production route. No
  runtime flag, fallback chain, or refactor debt was retained.

## Validation

- Actual shared-prefill leaf: rows=512, features=512, group=128, krot=8,
  7 alternating blocks x 500 launches after 50 warmups/object.
  - strict median: **20.032 us**
  - candidate median: **21.569 us**
  - strict/candidate: **0.929x**; candidate is **7.67% slower**
- Finite 262,144-element output comparison:
  - top-1 agreement **100%**
  - mean KL **4.74e-13**, max KL **8.30e-11**
  - 25 BF16 mismatches; max abs **9.77e-4**, mean abs **2.75e-8**
- Explicit NaN/Inf sentinel classes matched strict for all eight cases. NaN
  payload sign differed in one case and is not a classification/value gate.
- After removing the candidate, `git diff` showed no production/test changes;
  only this durable evidence and its benchmark rollup remain.

## Next

Do not apply selective unsafe-math to this family. Proceed to adaptive MTP
whole-cycle economics using the admitted MTP-bearing 35B-A3B artifact.
