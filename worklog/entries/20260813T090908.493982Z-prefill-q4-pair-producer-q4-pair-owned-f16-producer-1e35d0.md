# Retain pair-owned Q4 source-F16 producer leaf

## Summary

Added an exact pair-owned Q4T16 source-F16 producer. One local64 workgroup owns
an adjacent column pair for one K256 block, loads each shared packed-Q4 payload
byte once, and emits both scalar-source-equivalent F16 columns. The leaf is
retained as a registered primitive but remains runtime-unwired in this unit:
complete-chain timing is role dependent, so a global producer replacement would
regress full-attention output at M1024 and on W7900 at M4096.

## Changes

- Added the pair-owned HIP leaf, Python wrapper, four-axis dequant registration,
  and byte-exact RED-first HIP test.
- Kept the scalar column-owned producer and existing Q4 composite unchanged as
  the required unfused/reference fallback.
- Added compact evidence in
  `benchmarks/results/2026-08-13-qwen36-27b-q4-pair-owned-f16-producer-retained.json`.
- Added no persistent or scratch bytes and changed no resident layout, model
  policy, arithmetic, decode/MTP route, peer backend, or runtime default.

## Validation

- Actual FFN-down, attention-V, and attention-output weights on XTX and W7900:
  **66/66 leaf pairs win**, source-F16 byte exact, at **1.358-1.878x** producer
  speedup.
- Producer + production rocBLAS + BF16 output is BF16-byte exact on all tested
  role/row cells. FFN-down wins M512/M768/M1024/M1280/M4096 on both boards;
  attention-V wins confirmed M512/M768/M1024/M4096 anchors; attention-output
  wins M512/M768 but loses M1024 and is not cross-board positive above it.
- Focused byte-exact test passes on both gfx1100 boards. The changed kernel test
  file passes **16/16** on W7900.
- Cache-only W7900 `rocprofv3 --kernel-trace` names
  `gguf_q4_k_t16_dequantize_f16_tile_pair_kernel` at **4,480 ns**.
