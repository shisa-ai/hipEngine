# Restore gfx1151 Q6 LM-head rows-8 reachability

## Summary

The `gfx1151-qwen38-q4km-b5` package declared a Q6 LM-head chunk limit of 8,
but the live planar-qmicro primitive advertised only 4 rows. The existing exact
rows-8 HIP body was therefore unreachable. A second control defect let a
primitive-supported full-row call bypass smaller package and environment
limits, so simply raising the primitive bound would also have enabled rows 8 on
gfx1100 and made the rollback ineffective.

This unit raises only the planar-qmicro FP32 wrapper bound to 8 and makes runtime
direct-route selection intersect the primitive and package/environment limits.
The Qwen3.8/gfx1151 package now uses one physical rows-8 LM-head launch;
gfx1100 remains capped at 6, and
`HIPENGINE_GGUF_Q6_LM_HEAD_MAX_CHUNK=4` restores 4+4. The HIP arithmetic and
weight layout are unchanged. This is a T0 production-profile dispatch repair:
it has no stateful surface and cannot change downstream decisions because the
rows-8 result is bit-exact to 4+4.

On the physical-C8 512/128 raw graph-decode protocol, a clean A-B-B-A packet
measured **68.731 -> 71.043 tok/s (+3.36%)**. Both pair deltas were positive
(+3.29%, +3.40%), all six candidate samples exceeded all six controls, and all
generated trajectories matched. Evidence is compacted in
`benchmarks/results/2026-09-05-gfx1151-qwen38-q6-lm-head-row8-retained.json`.

## Changes

- Raised
  `gguf_q6_k_t16_qmicro_planar_gemv_rowtile_bf16_f32_out._hipengine_max_rows`
  from 4 to 8. The standard Q6 FP32 wrapper remains capped at 6.
