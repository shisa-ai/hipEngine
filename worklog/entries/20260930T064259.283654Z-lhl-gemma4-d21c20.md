# x7 device softcap: host tanh moved to device, +3.34% decode

## Summary

X7's largest remaining host item moved to the device:
`final_logit_softcapping` (`np.tanh(logits / cap) * cap` over the full
vocab, 0.528 ms of host time per decode step — a third of the measured
1.7 ms host wall gap) is now a kernel launched against the logits device
buffer before the D2H copy. Campaign A/B at 1024/128 on the XTX lane:
**64.43 → 66.58 decode tok/s (+3.34%)**, public-chain parity=True,
samples 66.65/66.58/66.36 — the recovery exceeds the raw 0.528 ms
because the host `astype` copy and its fresh allocation went with it.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_norm.hip`: new
  `gemma4_logit_softcap_f32_kernel` + extern "C" launcher — in-place
  `x = tanhf(x / cap) * cap` grid-stride over the vocab.
- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_norm.py`:
  `gemma4_logit_softcap_f32(...)` wrapper (symbol, argtypes, build via
  `build_gemma4_norm(load=True)`), documented with the rounding contract.
- `hipengine/runtime/gemma4.py`: `_collect_logits` enqueues the softcap on
  the block's stream before the stream sync and D2H; the host expression
  is removed. `apply_softcap=False` callers are untouched (no launch).
- `tests/test_gpu_gemma4_softcap_kernel.py` (new, RED-first): device-vs-
  numpy batteries on vocab-scale arrays — gaussian / heavy-tail /
  boundary-band / saturation / signed-ties / extremes — asserting ≤2 f32
  ulps of the capped range elementwise, greedy argmax exact on a unique
  top, tie sets preserved for exact ties and for the saturating tail
  (bitwise `+cap` in both paths), and in-place single-element behavior.
