# Stream committed Flash-Next resident MTP events

## Summary

Flash-Next resident MTP now publishes decoded committed events through EngineService instead of waiting for the terminal output. This is a CPU-qualified implementation checkpoint for task 20, not HTTP/GPU streaming qualification.

## Changes

- Decorate root/K0 and verified-cycle events with cumulative text deltas and target logprobs. Hold trailing replacement characters until another token completes the UTF-8 codepoint or generation ends.
- Capture row references before scheduler completion callbacks reclaim them; retain the existing decorator hook for other runners. No target/draft arithmetic or acceptance changes.
- Declare `resident_streaming_mode=committed_tokens` separately from `streaming_mode=buffered_public`: the direct provider iterator still buffers, while the resident service has canonical incremental events.
- Apply token-stop filtering before stripping finish metadata from speculative live chunks. The terminal service chunk alone owns final IDs, finish and telemetry.
- Keep HTTP stop-string safety buffering unchanged. Token matching is not a substitute for incremental decoded-text matching across BPE boundaries.
