# VibeVoice ASR HIP encoder kernels and GPU runtime

## Summary

First working hipEngine-native VibeVoice-ASR audio front-end on HIP: new
vibevoice kernel family (gfx1100 tree, built per-arch for gfx1151), a GPU
runtime driving both causal tokenizer encoders + connectors, and a fix to the
CPU reference's strided conv im2col. Follow-up to
`20260913T210227.953338Z-lhl-vibevoice-asr-cpu-reference-e7cb55.md`.

## Changes

- `hipengine/kernels/hip_gfx1100/vibevoice/encoder.hip`: bf16-storage /
  fp32-accum kernels - plain-weight RMSNorm, erf-GELU, scale-residual,
  depthwise causal conv K7 with fused residual+gamma epilogue, strided
  causal pointwise conv-as-gemm (per-thread dot, coalesced [K][C_in][C_out]
  transposed weights, explicit zero/chunk prefix), bias add, recorded-noise
  sampling.
- `encoder.py`: C-ABI wrappers + fp32->bf16 host conversion + conv-weight
  transpose; `tests/...test_gpu_vibevoice_encoder_kernels.py` gates.
- `hipengine/runtime/vibevoice_encoder.py`: `VibevoiceFrontendRuntime` -
  device weights, full-pass encoder sequence, FFN/connector via existing
  `dense_prefill_gemm_out_bf16` (+bias-add kernel), connector sum, optional
  recorded-noise acoustic sampling.
- CPU reference fix: im2col tap rows must be channel-major (ci*K + k) to
  match nn.Conv1d weight reshape; the earlier taps-major layout was wrong
  for any groups==1 conv with stride>1 or C_in>1 - exposed by the GPU
  conv_gemm parity test, verified by brute-force loop. The committed
  encoder smoke in the previous entry ran with the buggy conv; latent
  values from that smoke are invalid (shapes/finite checks remain valid).

## Validation

- GPU kernel parity vs corrected CPU reference (gfx1151): rmsnorm, gelu,
  scale-residual, depthwise, strided conv (incl. 1024->2048 K16 stride 8),
  bias, noise - all rel <= ~4e-3.
- Full front-end e2e on real original-checkpoint weights, 12000-sample
  synthetic PCM: acoustic/semantic latent rel 2.1e-3, connector-sum embeds
  rel 2.9e-3 vs fp32 CPU reference. `pytest --suite gpu
  tests/test_gpu_vibevoice_encoder_kernels.py`: 6 passed.
- Bugs found and fixed en route: FFN/connector biases missing (dense
  prefill GEMM has no bias arg), zero-prefix buffers allocated with raw
  malloc (uninitialized device memory poisoned left-edge windows at deep
  stages), stage widths doubled from 1 instead of num_filters, double-free
  in runtime close().
- NOT yet validated vs torch (HF artifact download still incomplete at
  commit time; retried in background).
