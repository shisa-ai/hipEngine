# the fix is to size logits_s by tile not by keys because the logit is cooperative and the output is per d

## Summary

`20260928T073550` called the prefill fix "a fusion of three existing passes" and said
`logits_s` should be eliminated. Reading pass 3 shows the fusion is **not mechanical**, and
that "eliminate `logits_s`" is the wrong target. The right target is smaller and more
concrete.

## Pass 3's loop nest, and why the array exists

```cpp
for (int64_t d = threadIdx.x; d < head_dim; d += blockDim.x) {
  float acc = 0.0f;
  for (int64_t j = first_kept; j < keys; ++j) {
    const float weight = logits_s[j];
    if (weight == 0.0f) { continue; }
    const scalar_t* v_row = value + (j * num_kv_heads + kv_head) * head_dim;
    acc += weight * gemma4_attn_to_float(v_row[d]);
  }
  out[...] = gemma4_attn_to_scalar<scalar_t>(acc / denominator);
}
```

**`d` is the outer loop and `j` is the inner one.** Each thread owns a slice of `d` and
walks every key for each element it owns. With `threads = head_dim = 256` (the launcher
rounds up to `head_dim`), **each thread owns exactly one `d`**, so the accumulator is a
single `float` per thread -- which is the good case for a fused rewrite.

**But the logit is computed cooperatively, not per thread.** Pass 1:

```cpp
const int lane = static_cast<int>(threadIdx.x) & 31;
int64_t j = static_cast<int64_t>(threadIdx.x) >> 5;
...
logit = gemma4_warp_key_logit<scalar_t, 8>(q_s, k_row, lane);
if (lane == 0) { logits_s[j] = logit; }
```

Warp `w` handles keys `w, w+8, w+16, ...` and reduces the dot product across its 32 lanes.
So **warp 0 computes keys 0, 8, 16, ...; warp 1 computes 1, 9, 17, ...**

**The output accumulation needs *every* key's weight in *every* thread, but each weight is
computed by one warp.** `logits_s` exists to bridge exactly that gap.

## Why "fuse the passes" is not the instruction

A fused loop would have each thread walk all keys, but the weight for key `j` is not
available to a thread that is not in the warp that computed it. So fusing requires one of:

1. **recompute the logit per output element** -- `head_dim` redundant evaluations per key,
   which is precisely the cost pass 2's write-back was introduced to remove (the kernel's
   own comment records it as "256 per key at this artifact's sliding-window geometry, and
   the whole of the kernel's inner loop"); or
2. **a different decomposition**, where a warp owns a contiguous run of keys and shares its
   weights with the block through shared memory.

Option 2 is the workable one, and it does not eliminate `logits_s` -- it **resizes** it.

## The concrete fix

**Size `logits_s` by tile instead of by `keys`.** Process keys in tiles of `T`:

- warp `w` computes the weights for the keys in the tile that belong to it, writing `T`
  floats to shared memory;
- a barrier;
- every thread accumulates its own `d` over the tile's `T` weights, rescaling its
  accumulator by `expf(old_max - new_max)` when the tile raises the running max;
- the buffer is reused for the next tile.

**That is online softmax, and it changes the LDS footprint from `keys` floats to `T`.**

The launcher makes the payoff exact:

```cpp
const size_t shared_bytes = static_cast<size_t>(head_dim + keys + threads) * sizeof(float);
if (shared_bytes > 64 * 1024) { return static_cast<int>(hipErrorInvalidValue); }
```

With `head_dim = 256` and `threads = 256`, the cap `256 + keys + 256 <= 16384` gives
**`keys <= 15872`** -- which is exactly the 15872 context ceiling found independently in
`20260928T071119`. **Replacing `keys` with a tile size makes `shared_bytes` independent of
the context length, and the ceiling disappears.**

## What this changes about the plan

- **Target is not "eliminate `logits_s`"** but "make its size independent of `keys`".
- **The cooperative logit computation is preserved**, so the bit-identical warp reduction
  and its careful ordering stay.
- **The gate is still a tolerance, not exact equality** -- the cross-tile rescaling
  reassociates (`20260928T073550`).
- The change is confined to the key loop and the shared-memory sizing, which is smaller
  than the whole-body rewrite `20260928T073550` implied.
