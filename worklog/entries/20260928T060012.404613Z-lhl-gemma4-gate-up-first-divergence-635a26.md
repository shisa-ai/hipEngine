# the divergence first appears at gate_up_out and only when the lanes of a token alias

## Summary

`20260928T055923` left a contradiction -- every stage cleared in isolation, the
whole call still diverging -- and proposed locating it by buffer instead of by
kernel. Doing that resolves it: the divergence first appears at **`gate_up_out`**,
one buffer after the gather, and the gather's own output is bit-identical.

Read after a `rows=1` and a `rows=2` call with the same first row, under a
single-expert routing (both lanes of a token select expert 0), comparing the
shared prefix:

| buffer | shared | relative L2 | max absolute |
| --- | --- | --- | --- |
| `sorted_lanes` | `[0, 1]` | **identical** | -- |
| `sorted_weights` | `[0.5, 0.5]` | **identical** | -- |
| `packed_hidden` | 256 | **0.00000000** | **0.0** |
| **`gate_up_out`** | 256 | **0.00646647** | **4.0** |
| `activated` | 128 | 0.00953000 | 3072.0 |
| `expert_out` | 512 | 0.00919143 | 12288.0 |
| `out` | 256 | 0.00919143 | 12288.0 |

`expert_start` differs at index 4 (`2` against `4`), which is correct: that
entry is the total lane count, so it must differ.

## What this establishes

**The gather is correct on the real path.** `packed_hidden` is bit-identical
over the shared rows, so the earlier read of the gather is now backed by a
measurement on the actual call rather than by the isolated probe.

**Everything from `gate_up_out` onward is inherited.** `activated`,
`expert_out` and `out` carry the same relative error as `gate_up_out` (0.0091 to
0.0095 against 0.0065) because each is a function of it. There is one divergence,
not several.

**The divergence is in the gate/up projection after all** -- the stage
`20260928T055743` and `20260928T055827` cleared by direct probe.

## The difference between the cleared probe and the real call

The direct probe passed **distinct** packed rows and the two routes were
bit-identical on every row. The real call passes rows where **both lanes of a
token carry the same hidden row**: with `top_k = 2`, the gather computes
`token_idx = lane / top_k`, so `packed_hidden[2i] == packed_hidden[2i+1]`.

Everything else matches: the same `expert_start` shape, the same
`sorted_experts` (all zeros), the same `compact_rows` values, and the same route
pair (`selected_gemv` at `compact_rows=2`, `grouped_prefill` at `compact_rows=4`
-- the same switch the real call makes at `rows=1` against `rows=2`).

So the two routes agree on distinct rows and disagree on aliased ones. That is
not a reduction-order difference: a different summation order would show on any
input, and it did not show on the distinct-row probe. It is a route that
behaves differently when its input rows are equal.

## Leading candidates

- **`grouped_prefill` deduplicating or caching by row content.** It is
  documented as reading the expert's weight row once and reusing it across the
  expert's rows, which is a structure where "same row" could be mistaken for
  "same row to compute".
- **`selected_gemv` skipping a lane whose input equals a neighbour's.** The
  per-lane geometry has no reason to look at other lanes, so this is the less
  likely of the two.
- **A bf16 rounding path taken only when the two addends are equal**, in either
  route. `max_abs = 4.0` is small and round, which is consistent with a
  rounding or a single-term difference rather than a layout error.

## Changes

None. This unit is a measurement.

## Validation

- Probe on the 8060S (gfx1151) calling `gemma4_experts_forward_bf16` directly
  with a single-expert routing (`[[0, 0]]` per row), reading `packed_hidden`,
  `gate_up_out`, `activated`, `expert_out` and the output back out of the
  layer's own expert scratch after each call, and comparing the shared prefix
  across `rows=1` and `rows=2`. Exit 0.
- The buffers are read from the scratch the call itself used, so the values are
  the real intermediates rather than a reconstruction.
- `sorted_lanes`, `sorted_weights` and `packed_hidden` being identical is what
  makes `gate_up_out` the first divergence rather than an inherited one.
- The `expert_start` difference is identified as expected rather than counted as
  a divergence, because index 4 is the total lane count.

## Next

Reproduce it in the isolated projection probe by making the two rows equal:
call `gemma4_project_experts_rows` with `packed_hidden` rows 0 and 1
byte-identical at `compact_rows=2` and `=4`, and confirm `gate_up_out` row 0
differs. That is a two-line change to a probe that already exists, and it
converts this localization into a minimal reproduction.
