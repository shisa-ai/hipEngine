# Guard packed C1 committed state before acceptance

## Summary

Add an exact state-publication guard to the actual packed-C1 logit diagnostic.
GPU validation passes: 70 calls, 131 buffers per call, 11,374,290,016 bytes
hashed per side in total, unchanged before acceptance. No public qualification
or performance claim.
The user prioritizes native C1 correctness ahead of further performance tuning.

## Changes

- New `scripts/qwen38_packed_c1_state.py` captures destination pointers,
  allocation sizes and BLAKE2b digests for resident Conv/GDN, committed live
  BF16 KV, hidden seed and device cursors, plus host cursors. Reject short KV
  buffers rather than silently truncating checks. Ignore uncommitted KV tails.
- `scripts/qwen38_packed_c1_logits.py capture --check-state` requires the actual
  packed job's deferred-state flags and checks resident state before and after
  the real verifier call. It does not replace target execution or commit.
- Exact no-publication is binding independently of arithmetic tolerances:
  `_scatter_packed_verify_outputs` creates deferred state and skips resident
  scatter/cursor updates; adapter `_execute_target_frontier_batch` separately
  selects and commits state only after acceptance.
- Reuse in-tree `scripts/gguf_packed_ar_state_oracle.py::_device_hash`; no kernel,
  runtime, dependency, environment-flag or public policy change.
