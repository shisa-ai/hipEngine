# Own resident MTP uploads by serving assets

## Summary

Resident MTP uploads now belong to serving assets instead of the kernel wrapper's process-global name cache. Closing one model releases its own uploaded weights without affecting another model or runtime.

## Changes

- Add `WeightUploadCache`, keyed by runtime identity and immutable tensor name within one owner. Cache instances isolate models; a changed byte size is an error rather than an undersized cache hit.
- Route both resident NextN weight uploads and the FP32 embedding table through that owner. Remove the resident runner's use of `_cached_upload`; the older NumPy diagnostic wrapper's global cache is unchanged.
- Share the serving asset cache across pooled draft runners. Generator shutdown closes drafts before uploads. A standalone resident draft owns and closes its own cache.
- Keep failed uploads unpublished and release them on copy failure. Failed frees remain reachable for retry; cleanup does not mask the original copy error. Draft construction uses the same temporary-owner helper to unwind allocation/prewarm failure.
- No kernels, arithmetic, variants, precision or production defaults changed.
