# LDS-stride audit: dense Llama prefill 2.10x fixed; inventory of 13 kernels

## Summary

Task #29. Audited the WMMA/attention kernel tree for the LDS bank-conflict
bug class fixed earlier in the Muse prefill mt and shared decode/verify
kernels: 2D LDS tiles whose row stride is a multiple of the 128 B bank
window, with lane-strided fragment reads (all lanes on one bank group).

Fixed this unit: **dense_flash_prefill** (Llama head_dim-128 tiled prefill).
Its k_s/v_s tiles used an unpadded 128-half (256 B) row stride; the per-key
dot walks put all 32 lanes on one bank group. Padded to HD+2 (130 halves),
arithmetic unchanged. Isolated 512x8192 32Q/8KV: **185.4 -> 88.4 ms
(2.10x)**, bit-exact; 28/28 dense-prefill tests pass.

Confirmed but deferred: the Muse single-token flash-prefill fallback has the
same 16-way pattern, but padding regresses it ~19% (both +2 and +8 strides;
a b128-alignment/vectorization tradeoff). Left unpadded; needs a swizzle
rather than padding. It is the multi_token=False fallback only — production
uses the mt variant (already fixed).

Already clean by design: gemma4 prefill WMMA (both, kPad=8), laguna flash
prefill (K_PAD=8), q4/q6 dense WMMA prefill (SLAB_STRIDE=272), iq WMMA
prefill (+16), qwen4_exp QSA flash (+16). Not applicable: grouped GEMV (no
2D tiles), gemma4 decode WMMA full (no LDS tiles). Needs deep review:
gguf_k_mmq_prefill struct tiles, gemma4 int8 / dms_compact staging.
