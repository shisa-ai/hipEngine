# Stop MTP at EOS and commit only the terminal prefix

## Summary

Fix MTP continuing beyond EOS on the user's Qwen3.8-27B-Q4_K_M server.
Before the fix, `hello` matched AR's ten IDs through EOS 248046 but continued
to the 96-token limit with extra assistant turns. The patched server stops
after "Hello! How can I help you today?" with finish_reason=stop.

## Changes

- Resolve EOS from sampling metadata, request metadata, or the tokenizer.
  Singleton and packed acceptance now select the terminal prefix and publish
  an EOS finish reason instead of relying only on the output limit.
- Keep EOS as the final prediction, not a consumed draft input. When a graph
  already selected a later state, stage retained hidden rows and acceptance
  buffers and use the saved-row commit path to restore the terminal prefix.
  Provider repair sees the shortened accepted count before publication.
- Publish the target cursor through request-local scratch, preserving neighbor
  slots. Host sampled acceptance stops consuming RNG after accepted EOS.
  The summary limiter respects ignore_eos and minimum output length.
- Add CPU boundary/state-selection tests and actual-model INT8 KV/scales,
  Conv/GDN, cursor, and next-logit comparisons against the AR prefix at all
  four EOS positions in eager and captured graph modes.
- No kernel arithmetic or architecture change; no performance claim.
