# Contain MTP short-graph context crossings

## Summary

Closed RF0 containment for the cached below-1024 dense GGUF MTP target graph.
The device proposal path now proves the exact live cycle fits a compatible
cached target graph before launching proposal work and rechecks admission before
target submission. Long/context-tail misses use host proposal plus eager target
verification instead of launching a proposal that the target graph cannot
retire.

## Changes

- Added side-effect-free `launch_ineligibility_reason()` / `can_launch()` checks
  over graph state, session/configuration identity, allocation binding, row
  shape, live cycle end, and remaining output room.
- Made `Qwen35GGUFTransactionalVerifier.device_proposal_ready()` accept
  `remaining_decode`, preserve a stable rejection reason, and reject B1/B2/B3 at
  the exact first cycle that exceeds the captured `context_limit=1023`.
- Centralized the proposal launch guard so an ineligible target graph cannot
  call `launch_device_proposal()`.
- Rechecked graph eligibility in the cached-only device-proposal target adapter;
  clean context misses do not destroy the reusable short graph, while cursor
  drift remains a hard pre-target-submission error with no replay/fallback.
- Standardized context/tail telemetry as
  `target_graph_context_bucket_miss` / `target_graph_output_room_miss`, including
  capture-admission misses, direct cycle records, and dense server batch-cycle
  metadata.
- Changed server and CLI MTP defaults from `enabled` to fail-closed `auto`;
  explicit controlled MTP and operator-selected `enabled` remain available.
- Updated `README.md`, `docs/API.md`, and `docs/MTP-FIX.md`; RF1/RF2
  long-context correctness and fast graph work remain open.
