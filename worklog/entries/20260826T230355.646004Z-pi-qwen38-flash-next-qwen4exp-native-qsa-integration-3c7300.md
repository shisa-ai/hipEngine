# Integrate native Qwen4Exp QSA into target runner

## Summary

Integrated Qwen4Exp index projection/cache/selection and sparse original-K/V
attention into every QSA layer of the complete resident target runner. The
runner now owns contexts through the frozen 262,144-token native limit rather
than rejecting above the 2,051-token dense-equivalence bound.

## Changes

- Added one raw FP32 index-key owner per QSA layer, physically mapped through
  the same paged block table as its BF16 K/V owner. Contiguous append fails
  closed; reset/close are explicit and no alternate index-key payload exists.
- Added strict index-query RMSNorm + split-half partial-RoPE primitive. Above
  2,051 production tokens, the runner executes real index Q/K projections,
  FP32 complete-block pooling, index norm/RoPE, ReLU-per-head scoring,
  deterministic block selection, block/tail expansion, and sparse paged GQA
  against original K/V. At and below the exact boundary, it retains dense
  attention while still building raw index state.
- Bound `index_q/index_k` and index norm tensors in resident QSA layer roles,
  sized complete-runner scratch for 4x128 index geometry, and lifted admission
  to the artifact's 262,144-token context limit. The public factory default
  remains a conservative 2,051 tokens until real-artifact memory admission.
