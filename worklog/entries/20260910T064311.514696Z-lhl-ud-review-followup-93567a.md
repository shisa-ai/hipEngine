# Review follow-up: owner gate, weight clamping, gate completeness, occupancy regression, census dedup, publication

## Summary

Both P1 correctness defects and all four validation/reporting gaps from the
2026-09-10 external review are fixed. The fresh plain-model control the
review demanded also caught a real performance regression the frozen-target
comparison had hidden: the dual kernels' bank-conflict padding had halved
their occupancy and regressed plain Q4_K_M prefill 982.8 -> 808.2.

## Changes

1. IQ4_XS dual owner gate (P1): the pair dispatcher now applies the same
   prefill-owner rewrite the singles get and requires both operands to
   resolve to the admitted cooperative prefill owner - an explicit variant
   contract, not a live-policy lookup (a pinned policy must move one side
   only). Without a dense-IQ session the pair falls through to the strict
   singles. Regression tests:
   tests/test_gguf_iq_dual_owner_gate.py (no session -> no fusion; session +
   shipped policy -> fusion; session + pinned incumbent -> no fusion).
2. Per-column weight clamping (P1): the dual's decode clamped only the
   pair's first column, reading one row past the weight tensor for
   incomplete 32-column blocks (N=16/48). Each column clamps
   independently; verified bit-exact at N=16/48/5120/17408, rows=129/512.
3. Combined-stack gate (P1): the shipped arm is derived from the live
   module defaults and asserted against the expected seven-quant shape
   (the stale pin still named the one-wave owner); the predicate binds the
   complete section-6.1 screen (mean/p95/p99/max KL
   <= 1e-3/5e-3/2e-2/5e-2, top-1 >= 0.99) plus a new 18-prompt
   category/heldout mode binding per-scope top-1 >= 0.97 over
   code/general_en/general_ja/mixed_ja_en. All three seeds pass both
   screens.
4. Dual occupancy regression (P2, found by the fresh control): the
   272-half slab padding grew the duals' LDS from exactly 32 KB (two
   blocks/CU) to 34.8 KB (one block) - the Q4 dual measured 0.60x the
   two-singles path, and plain Q4_K_M prefill regressed to 808.2 median.
   The duals now use the unpadded 256-half stride (column rows stay
   32 B aligned, vector loads remain legal); the dual measures 0.96x two
   singles and plain recovers to 985.2. The single owners keep the padding
   (measured faster despite the occupancy cost).
5. Fresh four-arm control (P2): all arms on the final build, one
   consistent statistic (median of 3), XTX 512/128 graph-replay decode:
   plain K_M 985.2 / UD K_M 936.4 (0.950x prefill, 0.765x decode);
   plain K_S 949.8 / UD K_S 896.0 (0.943x / 0.728x).
6. Census dedup (P2): the stage recorder accumulates each interval under
   every alias, so summing the result dict double counted 85.273ms. The
   census drops aliases at mark time; its total (552.5ms) matches the
   557ms wall. Corrected attention numbers: full-attn core_gate 10.942ms
   (the closure's 22.4ms had summed an aliased entry), qkv_head_norm_rope
   28.598ms, GDN recurrence 35.330ms. The verification doc states
   deprioritization on vendor-tuning/bandwidth evidence, not proof.
7. Publication (P2): benchmarks/CHANGELOG.md entry for the campaign with
   the four-arm medians and both gate screens; the route-plan ledger gains
   the XTX lane row (item 9).
