# EAGLE-4 device-resident efficient head + draft step: 8 syncs/20 H2D/11 D2H -> 0/0/1 per chain

## Summary

Task #25 parts (d)+(e) (campaign §6.2-5/6, §6.4 P1 rows 4-5). The EAGLE-4
efficient head did 2 device syncs + a D2H of the top-K ids + a host numpy gather
of 128 fp32 lm_head rows + an H2D of the bf16 shortlist + a D2H of the logits +
host softmax/argsort per draft step; the cached draft loop also round-tripped the
feature, embedding, and positions through the host every step. Moved the whole
head and draft step on device: top-K -> BF16 gather of the shortlist rows from
the resident lm_head -> re-score -> device row argmax -> I32 pick back to the
token id; the draft loop carries the feature in out_feature, gathers the
embedding by device token id, and reads positions from a pre-filled identity
arange via 4-byte D2D. One D2H returns the whole chain's draft ids.

Measured effect (counted by wrapping runtime sync/memcpy during a 4-token chain
on the real model): syncs 8 -> 0, H2D 20 -> 0, D2H 11 -> 1 per chain; draft ids
identical. Draft-phase wall is flat (old 115.2 ms vs new 121.7 ms median,
run-to-run variance; the cycle suite is flat too), because the head's DEVICE
compute (~28 ms/step: the 128x248320 low-rank estimate + full-vocab top-K)
dominates, not the removed host work. This is a §4.3 launch-count/H2D-D2H
sub-window win and the prerequisite for graph-capturing the draft step; the
newly exposed bottleneck is the head estimate/top-K device cost (and the eager
target verify, part (a)).
