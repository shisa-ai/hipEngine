# EG-1 closed by measurement: the gate/up production default beats its own fallback at every shape

## Summary

EG-1 proposed building LDS-staged gate/up weights. Its row was parked "OPEN, after ED-1",
and the previous unit showed the staging it wanted already exists as the registered
fallback. This unit measures the two owners against each other for the first time.

**The production default is faster in all 12 cases**, by +19.61% at the most realistic
small shape and up to +1171.80% at a degenerate one; on the two realistic distributions the
range is **+19.61% to +389.24%**. So EG-1's premise - that gate/up would gain from the
staging - is not supported, and the row is closed.

This is a main-kernel timing comparison with **no correctness gate**. It changes no
default; it confirms the existing one.

## Why this comparison was missing

The archived promotion evidence for the production default
(`2026-09-07-framework-qwen4exp-q4-iu8-exact-production.json`, 72 exact trajectories,
+7.602/+8.842/+8.361% at PP512/1024/4096) compares it against `selected_gemv_bf16_bf16_out`.
Scanning every artifact's `arms` field, **no artifact puts the production default and the
grouped owner in an arms pair**. So "is the production default better than its own
registered fallback?" was unmeasured.

## Mechanism, and why this is not a general claim about the wmma design

The production default pads every non-empty expert to a 16-row tile, so at `balanced-1024`
it processes **8,192 padded rows against the grouped owner's 1,024 compact rows - 8x the
row-tile work - and still wins by 22.91%**. The grouped owner's weakness is parallelism per
expert, which is why it degrades hardest as rows concentrate: at `single-10240` one expert
owns all 10,240 rows and only its 80 output-blocks have work.

## Limits

- **No correctness gate was run.** No output was compared between the owners. This is a
  timing comparison and says nothing about numerical agreement.
- **Weights are synthesized** at the real shapes and byte layout - representative access
  pattern and byte counts, not real values - and the populations come from the harness's own
  count synthesizers. **There is no real-router population in this packet.**
- `max_risks=0`: the risk queue is never written and no repair, packing or engine work is
  timed. If anything this **understates** the production default, whose iu8-risk machinery is
  not fully charged.
- One host, one geometry, one quant, one process.
- `single-512` repeats with 14.73% drift, the largest in the sweep, on the shortest
  measurement (0.734 ms) where event overhead is proportionally largest. Its conclusion is
  +528.81%, so the drift does not change it; every other case repeats within 3.45%.
- The `single` distribution is degenerate and included only to bracket the parallelism
  behaviour. It is not a routing pattern the model exhibits.

## Validation

- 12 of 12 cases measured with the two arms in one process on identical buffers; the
  production-default arm repeated last as a drift control.
- Repeat drift ≤3.45% in 11 of 12 cases.
- The host identity matches the ED-1 artifacts' recorded host, so the two packets are
  comparable.
- Table integrity checked after the ledger edit: the five rows stay contiguous, `--numstat`
  is `1 1`.
- No default, dispatch or kernel changed. No pytest run applies; the change is a new
  diagnostic harness plus an artifact plus a ledger state update.
