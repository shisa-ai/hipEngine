# Correct verifier speed lane closure: diagnostic evidence leaves live work

## Summary

Review of the prior checkpoint
`20260823T170152.912326Z-lhl-verifier-speed-lanes-157687.md` finds that its raw
reduced-DAG opt-out numbers are internally consistent, but its broad conclusion
that all four lanes were tested/closed and that no wins remain is not supported.
This entry supersedes only those lane-closure conclusions; it does not invalidate
the recorded diagnostic measurements.

## Changes

- **Evidence scope:** all three new `/tmp` artifacts are explicitly
  `performance_claim=false`, use one run per prompt, the legacy eight-prompt
  non-translation subset, and the available `PARO-packed-MTP-BF16` model. They
  do not run the canonical ten-prompt category+heldout suite required by current
  `docs/BENCHMARK.md`. The intended full4096 target blob is absent. Current docs
  identify the available packed target/sidecar as `a5c9100b...cc60` /
  `556c607c...26f`, not the old full4096-e5 benchmark artifact. The summary JSON
  captures child commands but not the outer opt-out environment, so the worklog
  is the only durable record of those flag values.
- **#12 reduced-DAG:** the 8-prompt opt-out is a valid corroboration of already
  retained micro-fusions. Accepted-length and active-budget traces match on all
  prompts, and disabling the group regresses every prompt by `0.375-0.748`
  ms/cycle, aggregate `+0.515 ms` wall / `+0.513 ms` verify. It does **not** test
  the TaskList's new full-layer reduced-DAG composite. `docs/MTP.md` explicitly
  leaves that work open against `833` launches/pass and a `~3.47 ms/pass`
  host/kernel gap. “Fused optimum” was therefore an overclaim.
- **#13 adaptive budget:** the measured `0.9318x` row tests the oracle map chosen
  on the old full4096 model, not an oracle for the current packed model. Relative
  to the separate current-model B1 run, mapped B3 improves `code_python` by
  `+0.074x` observed and mapped B2 improves `qa_factual` by `+0.050x`, while the
  stale choices regress `code_cpp` by `-0.067x` and `creative_short` by
  `-0.206x`. This proves the map does not transfer; it does not prove adaptive B
  is a no-hold. A fresh B1/B2/B3 sweep plus a non-oracle train/heldout selector is
  still required. The historical same-model full4096 oracle remains valid design
  evidence at `1.041x` prompt-mean / `1.027x` total-time.
- **#14 overlap:** only the naive side-stream implementation is closed. Its real
  prior gate hid `0.138 ms` verify/commit but added `0.196 ms` proposal/update,
  for `+0.066 ms` aggregate wall. `docs/MTP.md` explicitly says broader update/
  submission redesign remains possible after final sync/readback removal.
  Later NativeSpecCycle work also demonstrates retained submission/control
  reductions, so “effectively closed” was too broad; this remains lower priority.
- **#15 D64:** the checkpoint is factually stale. D64 correctness was already
  repaired by the opt-in exact GDN, linear-out, and decode-batched exact-suffix
  fallbacks (`9/9` exact), and the later current-packed strict N4 gate passes
  `10/10` prompts / `240/240` IDs. The open lane is making the exact fallback
  faster, not recovering correctness from scratch.
- **Process:** no new optimization was implemented in the prior unit. It
  re-measured one already-known opt-out, applied a stale budget map, and reviewed
  removed code. Marking all four implementation/research tasks complete and the
  goal achieved was not justified. The work was also committed on `main`; the
  `mtp-iu4` branch is not checked out in a worktree.
