# Bind provider host checkpoint storage to an explicit byte allowance

## Summary

Bound provider host KV storage during owner trim, independently from device
residency. Preserve target cache entries when provider host payloads are evicted.

## Changes

- The existing configured retained-byte limit now supplies two distinct
  allowances: target/provider device checkpoint owners plus idle pool storage,
  and provider host checkpoint storage. They are not added or conflated.
- Host pressure evicts provider LRU only; a later target prefix hit can run AR
  if no provider checkpoint survives. Existing entry-count safety bound remains.
- Capture/replacement already invokes owner trim, so the host bound is enforced
  after publication as well as ordinary target cache transitions.
