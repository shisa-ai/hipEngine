# Retire Qwen4Exp fused grouped-prefill combine after same-residency A/B (R0410)

## Summary

R0410 asked for a same-residency comparison of the opt-in fused grouped-prefill
combine (`weighted_lanes_sum_shared_gate_combine_batch_out_bf16_f32w`, PF-4 lever 2)
against today's default: unfused weighted-lanes sum, then the cast-folded
`shared_gate_combine_f32_shared_out_bf16`. The fused route is bit-exact but slower,
so it is retired under the lead's 2026-11-07 decision to retire failed candidates.

Measured on gfx1151 (Radeon 8060S), Qwen3.8-Flash-Next UD-Q4_K_XL, production
profile, one `LLM` residency, `prefix_cache="off"`, greedy, 8 output tokens with
EOS ignored. Each length had one warmup per arm, then 6 timed repetitions per arm
in alternating order (`fused_combine_enabled(owner/runner, ...)` toggled between
calls). Wall time is `generate_detailed` bracketed by device syncs.

  | prompt tokens | unfused median s | fused median s | unfused/fused | fused launches | tokens identical |
  | ---: | ---: | ---: | ---: | ---: | --- |
  | 512 | 0.8076 | 0.8100 | 0.9971 | 48 | True |
  | 2048 | 1.7929 | 1.8008 | 0.9956 | 48 | True |
  | 8192 | 5.5404 | 5.5683 | 0.9950 | 96 | True |

Fused was slower at every length (0.3-0.5%); it does not beat the default.
