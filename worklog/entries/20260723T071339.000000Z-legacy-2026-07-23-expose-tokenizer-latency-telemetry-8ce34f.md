## Changes


- RED required Laguna blocking, streaming, and zero-generation outputs to carry `timing.tokenize_ms`, Qwen direct raw-token prompts to report exactly zero, and resident Qwen GGUF text/zero-token outputs to retain the tokenizer timing through scheduler ownership. All five focused nodes failed on a missing key or the old raw-input wrapper timing; the diagnostics endpoint separately failed on a missing timing payload.
- Laguna now measures only string encoding in `_prepare_request()` and passes the value through every token/terminal/empty telemetry record; exact token-ID prompts bypass the tokenizer and report `0.0`. Qwen's shared prompt helper likewise returns exact-zero for raw IDs and measured string encoding for serial, native-batch, packed AR, MTP, and direct streaming paths. The persistent submit/poll loop measures text tokenization around the resident runner boundary and publishes it through an optional owner hook; both GGUF and native PARO owners preserve the per-row value across prefill/decode/empty completion. Existing model-only timing boundaries are unchanged rather than silently folding tokenization into prefill.
- `/v1/hipengine/tokenize` and `/v1/hipengine/count_tokens` now return `timing.tokenize_ms`, including threadpool dispatch as observed by the HTTP request. Generation responses already expose the same key through choice/stream `GenerationTelemetry`. Focused GREEN reports 24 passes across complete Laguna public generation, Qwen GGUF raw/resident/greedy+sampled stream paths, native PARO resident ownership, compatibility submit/poll, and token diagnostics; Ruff, py_compile, and diff checks pass. No throughput claim is made by this telemetry unit.
