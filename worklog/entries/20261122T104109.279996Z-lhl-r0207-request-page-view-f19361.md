# Own device page tables at the resident request boundary

## Summary

Keep graph-facing page-table addresses independent of the global pool's table
publication, which can be replaced and freed during growth or shrink. This is
an ownership change, not the retirement of chunk confinement.

## Changes

- Resolve payload and scale addresses from an active request allocation, in
  logical lease order. Pack the per-plane pointer tables and identity block
  table into one resident-owned, budget-accounted device allocation.
- Keep that allocation alive until unbind, and refuse to free it while graph
  pins remain. Do not allocate it for existing contiguous consumers.

## Validation

- The new unit cases failed before implementation and then passed in the
  143-test allocation, growth, binding, and prefix-cache bundle. They verify
  table contents, budget accounting, replacement of the pool's publication,
  graph-pin refusal, and rollback on upload failure.
- The paged KV test file passed on W7900/gfx1100. Its BF16 reader used the
  resident-owned tables over independently allocated and permuted pages and
  matched the contiguous reference bit-for-bit for both tested head widths.
  This was a direct device test, not a public cross-chunk request.
- The complete CPU unit tier passed: 29,010 passed, 117 skipped, and 15
  subtests passed. Compilation, CPU fixtures, and registry smoke checks passed.
- The cleanup audit fails on the same gated row IDs on the untouched parent
  (`9ba169c81`) and this change. No debt budget or disposition changed.
