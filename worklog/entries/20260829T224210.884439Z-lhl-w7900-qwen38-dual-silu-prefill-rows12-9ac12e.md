# W7900 Qwen3.8: fused dual+SiLU prefill owner promoted to rows12 (+4.2% prefill at 45 rows, bit-identical)

## Summary

The submodule-parity entry traced a 45-row prefill and found hipEngine running
two singleton WMMA projections plus a separate SiLU kernel, while a 512-row
prefill ran `dense_dual_wmma_prefill_silu_bf16_bf16_out` and the rocBLAS F16
chain. The cause is one tuning constant:
`_Q4_T16_DUAL_WMMA_SILU_MIN_ROWS = 512` in `hipengine/runtime/gguf_linear.py`,
whose dispatch predicate (`_q4_t16_dual_wmma_silu_dispatch`) is otherwise purely
shape/abi based (`in=5120`, `out=17408`, t16, dense Q4 quants).

The floor was a perf-qualification floor, not a correctness boundary. Proved by
asserting bit equality between the fused owner and the unfused
two-singleton + `silu_mul_separate_out_bf16` chain **at the shape the predicate
actually admits**, then measured:

| rows | control (fused <512 off) | candidate (fused from 12) | prefill gain | id / final logit |
| --- | --- | --- | --- | --- |
| 16 | 0.2360 s | 0.2289 s | +3.1% | identical / identical |
| 32 | 0.2601 s | 0.2498 s | +4.1% | identical / identical |
| 45 | 0.2811 s | 0.2697 s | **+4.2%** | identical / identical |
| 96 | 0.3171 s | 0.3044 s | +4.2% | identical / identical |
| 192 | 0.3998 s | 0.3811 s | **+4.9%** | identical / identical |
| 512 | 0.5791 s | 0.5798 s | -0.1% (same route) | identical / identical |

Two rejected alternatives measured on the way, both recorded so they are not
re-attempted: (1) the `rows % 6` verifier-pad decomposition is not the lever -
42/45/48-row prefill is flat at 0.2807/0.2811/0.2836 s, so there is no
divisibility cliff; (2) the gain is not the *unequal* (QKV) dual: attributing
with only the SiLU gate lowered reproduces 4.2-4.9%, whereas lowering both gates
gave 6.3%, so the remaining 2 points belong to the unproven unequal dual, whose
parity test still covers rows>=512 only.

## Changes

- `hipengine/runtime/gguf_linear.py`: `_Q4_T16_DUAL_WMMA_SILU_MIN_ROWS` 512 ->
  12 with provenance in a comment. The floor stays above the dedicated small-B
  rowtile/GEMV domain (rows<=8), and the unfused singleton+SiLU chain remains
  the registered fallback.
- `tests/test_gguf_q4_k_t16_dense.py`: new
  `test_q4_t16_dense_dual_wmma_silu_matches_unfused_chain_at_production_shape`
  (`assert_array_equal` on BF16 output bits, K5120/N17408, rows 45/96/192/511/512);
  widened the fixture parity test to rows 2/12/45/48/128/256/511/512/513/1024;
  flipped the declared contract - `..._uses_canonical_tiles` is now parametrized
  rows 12/45/48/128/256/511/512 and
  `..._keeps_unfused_fallback_below_512` became
  `..._keeps_unfused_fallback_below_12` (rows 2/5/8/11).
- `scripts/gguf_kernel_family_rocprof_summary.py`: summarizes one
  `rocprofv3 --kernel-trace` output directory per kernel family (launches,
  median/total duration, grid/workgroup count, ms per 1k tokens) so "same kernel
  slower" versus "different kernel selected" becomes a mechanical check.
- `scripts/gguf_prefill_rowgate_probe.py`: diagnostic runner that lowers these
  module-level row gates at runtime (both constants are read at dispatch time)
  so a route floor can be measured before it is changed.
- `docs/KERNELS.md`: Q4/Q5/Q6 T16 selected row now records the gfx1100 fused
  gate/up floor at rows12 with its parity rows and measured deltas.
- `benchmarks/results/2026-08-30-w7900-q4km-t16-dual-silu-prefill-rows12-promotion.json`
  plus a `benchmarks/CHANGELOG.md` line.

## Validation

- `pytest tests/test_gguf_q4_k_t16_dense.py -q -x` on W7900 -> **74 passed**,
  including both parity tests at the production shape and the flipped dispatch
  contract.
- A/B protocol, exclusive device, production profile, shipping AR route
  (`--public-ar-profile`), 3 measured runs per cell, `--persistent-session`;
  the control restores the old route at runtime with
  `HE_DUAL_WMMA_SILU_MIN_ROWS=512`, so both sides share one binary and one
  session:

  ```bash
  HE_DUAL_WMMA_SILU_MIN_ROWS={12,512} .venv/bin/python scripts/gguf_prefill_rowgate_probe.py \
    --model /models/gguf/Qwen3.8-27B-Q4_K_M.gguf --prompt-length {16,32,45,96,192,512} \
    --decode-tokens 1 --warmup-runs 1 --measured-runs 3 --persistent-session --public-ar-profile
  ```

- Arithmetic identity is claimed from bit-level equality of the kernel outputs
  and from every measured pair reproducing the same generated token id **and**
  the same final logit (e.g. 45 rows: id 9707, logit 21.9644 both routes; 512
  rows: 25.1641 both). No KL/top-1 campaign is needed because the fused owner
  is not an approximation of the unfused chain.
- Kernel-family evidence (`scripts/gguf_kernel_family_rocprof_summary.py`):
  45-row prefill trace is dominated by `gguf_q4_t16_dense_wmma_prefill_shared_b`
  (351.3 ms, 576 launches, 363 workgroups, median 0.672 ms) with no dual and no
  Tensile kernel; the 512-row trace shows
  `gguf_q4_t16_dense_dual_wmma_prefill_silu` (454.8 ms) plus
  `Cijk_Alik_Bljk_HB_MT64x64x32_*` rocBLAS kernels and
  `gguf_q4_k_t16_dequantize_f16_tile_pair`.
