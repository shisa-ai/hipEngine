# IKV-C2 XTX model gate passes; INT8 integration map recorded

## Summary

The Packet 3 gate-inspection item is complete: what INT8 KV actually does
today on the XTX is now separated into qualified, proven, and not-integrated
lanes, and the one missing piece of model-level evidence (the IKV-C2
batch-decode gate run) is produced.

Qualified/proven:

- Serial compact residency: IKV-C1 no-mirror audits report zero persistent
  BF16 payload bytes; the 2026-09-06 XTX probe points are serial c=1
  per-token/head INT8 with FP32 scales — 2,048/3,072/4,096 contexts ok
  (request peaks 21.35/22.60/23.75 GiB), 5,120 OOM at startup.
- Batched decode (IKV-C2): `scripts/qwen38_int8_batch_decode_gate.py` now
  has its first recorded XTX run and it passes exactly — token-exact,
  max KL 0.0, top-1 1.0, zero hidden and zero state/KV-scale mismatches over
  4 rows x 4 steps vs independent c1 oracles. Every step reports
  `kv_live_spans_int8_batch`, physical_rows 4, host_model_row_iterations 0 —
  genuinely native row-batched decode, no serial fallback, no host row loop
  — under `per_token_head_gqa_splitk_gate_bf16_batch_strided_spans`.
  The artifact capability still admits c1 (capability
  `3a105595...`), so this is a pre-promotion gate executed under
  `--diagnostic-direct-rows 4`; capability promotion belongs to the INT8
  campaign's own protocol.
- Artifact: `benchmarks/results/2026-09-07-rx7900xtx-ikv-c2-batch-decode-gate.json`.

Not integrated (code-inspection facts, each with its raise site):

- Packed decode graphs hard-require BF16 KV —
  `gguf_packed_decode_graph.capture_qwen35_gguf_packed_decode_graph` raises
  `NotImplementedError("packed decode graphs currently support BF16 KV
  only")` for any other `kv_storage_dtype`. All INT8 decode is eager.
- c=1 decode graphs admit INT8 only in the tail4-Hadamard-group32 layout
  with hadamard_group32 scale granularity
  (`gguf_decode_graph._decode_graph_kv_layout_admitted`); the per-token/head
  FP32-scale layout used by every probe point runs eager.
- Batched prefill remains IKV-C3-blocked: the gate harness deliberately
  prefetches prompts through independent scalar sessions, so no shared
  prefill ownership claim is made (and batched prefill scratch is the
  known residency risk).
- The MTP native spec target graph N1 requires BF16 KV
  (`gguf_native_spec_cycle` raises `NativeSpecTargetGraphUnsupportedError`),
  so INT8+MTP is unproven on both axes (independent of the BF16 MTP warmup
  bug already recorded for the MTP campaign).
