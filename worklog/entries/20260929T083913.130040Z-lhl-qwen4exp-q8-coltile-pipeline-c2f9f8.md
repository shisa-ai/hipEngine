# Q8 coltile software pipeline: bit-exact +6.84% on the exact prefill leaf

## Summary

The exact Q8_0 prefill leaf for the `prefill_exact_q8_f32_coltile` scope now
runs a software-pipelined sibling of the wave-scale coltile kernel. The new
kernel issues the next K iteration's Q8_0 weight-block and activation loads
before the current iteration's FMAs retire, leaving the arithmetic, the
per-output FMA order, the wave shuffle tree and the four-wave publication
unchanged. It is bit-identical to its parent on every measured shape and
6.71-7.09% faster on the production `attn_qkv` shape (2560 -> 10240, 1024
rows), so it replaces `coltile8_rowbatch4_wave_scale_f32_f32_out` as the
promoted leaf. The wave-scale parent and the unscaled
`coltile8_rowbatch4_f32_f32_out` exact parent both stay registered as the
rollback chain.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_k_gemv.hip`: add the pipelined
  kernel body, sharing the existing dequantization and wave-shuffle helpers so
  the pipeline is the only difference from the parent.
- `hipengine/kernels/hip_gfx1100/quant/gguf_k_gemv.py`: add the host launcher
  and register three variants:
  `coltile8_rowbatch4_wave_scale_pipelined_f32_f32_out`,
  `coltile8_rowbatch4_pipelined_f32_f32_out` (unscaled),
  `coltile4_rowbatch8_pipelined_f32_f32_out` (alternate geometry).
- `hipengine/runtime/gguf_linear.py`: add `_raw_k_coltile_pipelined_dispatch`
  and call it last in the launch chain, so every route keeps the parent it
  already matches on and only the leaf kernel of the exact Q8/F32 coltile scope
  is replaced. The step is `is_registered`-guarded: if the pipelined key is
  absent the wave-scale parent is retained and the registered strict fallback
  chain is untouched.
- `hipengine/generation/qwen4_exp_profiles.py`: the production
  `prefill_exact_q8_f32_coltile` selection now names the pipelined leaf, with
  `coltile8_rowbatch4_f32_f32_out` still the strict fallback, so the variant
  manifest records the kernel that actually runs.
- `scripts/qwen4exp_row4_state_gate.py`: the `q8-wave-scale` route package now
  counts the promoted leaf, which is what the route engages.
- `scripts/qwen4exp_dense_projection_ab.py`: the A/B harness gains the three
  pipelined variants.

including the production `1023 x 2560 x 10240` case, covering a partial row

End-to-end default-state gate, `scripts/qwen4exp_row4_state_gate.py
--route-package q8-wave-scale --case-id code-p4096 --full-kv`: **passed**. The
three arms (`enabled=0`, `enabled=1`, `enabled=0`) produce identical
`state_sha256`, `layout_sha256`, `prefill_logits_sha256`, `step_logits_sha256`
and `full_kv_sha256`. The enabled arm invokes the promoted kernel 1072 times,
all in prefill and none in decode, which shows the promotion reaches the engine
rather than only the registry; zero live allocations remain after close. The
gate confirms exactness and routing, not a rate. The first run of this gate
failed with `route not engaged correctly` because it still counted the
wave-scale parent: the kernel it watched was invoked 0 times precisely because
the dispatch now selects the pipelined leaf. The counted key was updated to the
promoted variant and the rerun passes.
