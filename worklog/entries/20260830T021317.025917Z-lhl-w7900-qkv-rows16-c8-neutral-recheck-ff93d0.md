# W7900 Qwen3.8: surviving server packets read the QKV floor axis as C8-neutral; the +0.7% pair is not reproducible

## Summary

A completed background chain surfaced two things: one of its own arms had failed
silently, and the surviving measurements contradict a top-line number in a
promotion artifact I committed earlier today. The chain echoed `SRV_DONE
floor=33` and `SRV_DONE floor=16` and looked complete, but the floor-16 server run
died at startup with `RuntimeError: benchmark requires tracked-clean source`, so the
chain produced one packet, not a pair. Looking for the pair behind the retained
"+0.7% shipping C8 AR" claim instead, the two surviving same-manifest server packets
on the *floor* axis read **46.062 tok/s (floor 33) -> 45.999 tok/s (shipped floor
16) = -0.14%**, and since the shipped arm ran second, the <=0.9% second-arm
advantage makes the true value more negative, not less. So C8 AR is neutral for this
promotion, and the 45.62 -> 45.94 pair cannot be re-derived from anything retained.

The promotion itself is untouched: it rests on byte-identical arithmetic (20/20
packed trajectory hashes across both measurement orders) and the order-controlled
+1.81% packed prefill crossover, neither of which involves the C8 wall number.

## Validation

- Packets: `/tmp/he-uneq-srv-33.json` (created 2026-08-29T23:44:51Z) and
  `/tmp/he-uneq16-shipped.json` (2026-08-29T23:58:15Z), both `status: complete`,
  same prompt suite (`benchmarks/prompts/mtpbench-code-general-ja.jsonl`) and the
  same resolved production profile manifest sha256 prefix `38a90b99`.
- `summary.8.ar.tok_s`: 46.062 vs 45.999 -> **-0.14%**; `summary.8.mtp.tok_s`:
  31.751 vs 31.746 -> -0.02% (also neutral).
- Ordering: the floor-16 packet is the later of the two. Today's order-swap bounds
  the second-arm advantage at <=0.9% on a dispatch-identical control, so the whole
  plausible range for the shipped arm is about -1.0% to -0.14%. No ordering
  assumption recovers +0.7%.
- Provenance gaps found, both worth closing:
  1. The row-gate probe monkeypatches `hipengine.runtime.gguf_linear` gates but the
     resulting bench/server packet does not record the patched values, so an arm is
     identifiable only by its filename and the chain log.
  2. The chain printed `SRV_DONE floor=16` after a non-zero exit, because the loop
     echoed unconditionally - a finished background chain is not evidence of a
     successful measurement.
