# XTX capacity: D=512 concurrency boundary drops to N=3

## Summary

Raising the output horizon from 128 to 512 tokens (512-token prompts,
page-aligned 1,280-token context, BF16 KV, one cold server per point) drops
the XTX concurrency boundary from last pass N=6 to a **solid last pass of
N=3** (22.692 GiB request peak). N=4 is marginal and non-deterministic at the
card edge: one run served the full 512-token horizon across four rows but
post-request reclaim left 159 MiB above baseline against the 128 MiB idle
gate, and a repeat run failed eager warmup OOM at 23.947 GiB. N=5/6/7 fail
warmup OOM cleanly (23.939-23.972 GiB sampled peaks). The mechanism is the
per-session prefill scratch scaling with `max_positions`: each resident
session's bulk-prefill footprint grows with the context budget, so the
per-request slope that was ~0.99 GiB at the 768-token context grows past the
card before N=4 stabilizes. A first attempt at context 1,024 was rejected by
the server's own admission (prompt+max_tokens+1 = 1,025 > 1,024) and is
recorded as a policy rejection, not a memory point.
