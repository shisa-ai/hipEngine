# Harden D2 artifact contract and correct promotion status

## Summary

Review and repair the committed #28/#29 D2 implementation. The DP arithmetic
was correct and the gfx1100 physical-width promotion was backed by the clean
#36 lifecycle artifact, but D2 accepted arbitrary summary-shaped JSON, depended
on an untracked `/tmp` packet, mislabeled a different greedy partition as the
ceiling fallback, and was documented beyond its evidence. The only post-width-
promotion run was dirty c5 lifecycle without D2 configured; no actual-server
c1-c32 performance/SLO gate exists.

## Changes

- Replace the three-field group record with a complete D2 cost-map contract:
  exact host/device/backend/arch/model fingerprint/quant/KV/profile/graph
  identity; active/physical rows and mask class; model-step cost; workspace
  scope/bytes; route/correctness hashes; sample count; and source SHA.
- Add a complete D1 primitive record schema for plugin/registry evidence axes;
  the current cost map honestly declares it but leaves records empty because D2
  consumes complete physical-group measurements.
- Retain the compact strict cost map at
  `benchmarks/results/2026-08-20-concurrency2-qwen38-d2-cost-map.json`, derived
  mechanically from clean `/tmp/q6_rowtile8_bench.json` SHA
  `147acc...bd6` and bound to the clean 1,950-row quality and four-width
  lifecycle artifacts.
- Make the loader reject wrong kind/schema/status, failed/incomplete source
  correctness, dirty or mismatched provenance, incomplete width sets,
  non-finite/non-positive costs, undeclared widths, and malformed hashes.
- Correct `ceiling_partition` to the existing masked ceiling semantics and make
  `batch.py` require every explicit D2 width be a registered physical bucket.
- Add optional per-group workspace and model-step SLO constraints and
  deterministic equal-cost/equal-count canonical tie-breaking.
- Bind runtime cost resolution to current host/device/model/backend/quant/KV/
  width identity, cache by file stat plus runtime identity, and expose D2 source,
  identity, width sequence, and estimated serial wall in owner telemetry.
- Correct docs/rollups: physical c1-c8 are package-promoted, but D2 remains
  explicit-config only. Reclassify the dirty c5 no-override artifact as a
  diagnostic, not product qualification.

## Validation

- Review RED probes proved the old loader accepted dirty/failed/wrong-backend
  artifacts, NaN/Inf costs, and c9 above `default_max_width=8`; old ceiling
  returned c3=2+1 and c13=8+4+1 instead of masked c4 / c8+masked-c8.
- RED tests added for clean exact identity, negative provenance, non-finite and
  incomplete maps, workspace/SLO filtering, canonical ties, undeclared explicit
  widths, retained artifact loading, and runtime quant mismatch.
- GREEN: 154 affected host tests pass across D2, dispatch, GGUF owner/lifecycle,
  and benchmark provenance. Focused Ruff, Python compilation, both JSON parses,
  Worklog2 validation, README synchronization, and `git diff --check` pass.
- The real retained map mechanically recovers c9=5+4, c10=6+4, c11=6+5,
  c12=6+6, c13=7+6, c14=7+7, c16=8+8. This is a policy-input result, not a
  server throughput claim.
