# EVIE review round 3 fixes: fold layout, cache bounds, close safety

## Summary

Fixed the four failures from review 821af6:

1. **Patch channel/temporal layout (P1).** The 2x2 merge-block spatial fix
   emitted (t, ch, ...) per patch; the model requires (ch, t, 16, 16)
   per the Conv3d weight layout (cpu_reference reshapes patches to
   (-1, 3, 2, 16, 16)). The prior 5.9e-08 "verification" used a
   channel-constant image and could not catch a channel permutation.
   Fixed transpose to (2,5,3,6,1,0,4,7); verified bit-exact
   (max|d| 0.0) against the reviewer's independent construction with
   RGB-differentiated tiles, and pinned by new CPU-only regression
   tests (tests/test_evie_bench_preprocess.py, including a
   guard-the-guard test that a channel swap must be detectable).
2. **Unbounded attention caches (P1).** _scores_scratch, _scores16_scratch,
   _plane16_scratch now evict beyond 4 entries via _evict_caches
   (the main scratch bound only covered _scratch; attention keys are
   exact-dimension so token bucketing did not apply).
3. **_ptr_array_bufs leak + double-close (P2).** close() now frees the
   pointer-array cache and is idempotent (a _closed guard guards the
   unconditional loaded.free()).
4. **Doc language (P2).** "Same shapes" contradiction replaced with an
   explicit differences sentence; benchmarks/README "beats torch fp32"
   now labeled cross-precision with the matched-protocol pointer;
   "strict fallback registered"/"recorded manifest" softened.

Also: the loader's fp32 padded tail is now np.zeros (explicitly
initialized) instead of np.empty.
