# Device-side route selection wired into Inkling 2 GGUF decode

## Summary

Device-resident route selection for the Inkling 2 GGUF MoE decode path: router
logits stay on the GPU, a HIP kernel selects top-k, a second kernel widens the
i64 ids to i32 and gathers per-route scales, and the expert chain launches
directly from those device pointers — no logits D2H, no host top-k, no ids/mix
H2D per layer per token. Opt-in behind `HIPENGINE_INKLING2_DEVICE_ROUTES=1`
(default off), per-layer NVFP4 capability gate, host path retained as fallback.

## Validation

On W7900 with the real UD-Q4_K_M artifact, `execution_profile="fast"`:
greedy 128-token A/B is 18.08 vs
18.05 tok/s (within noise); the first 67 tokens match the host-route chain
exactly, then diverge from ulp-level mix differences. Instrumented comparison
over 240 consecutive expert calls: 0 selection mismatches, mix max abs diff
3.8e-6, FFN output max rel diff 1.8e-6.

- `pytest tests/test_gpu_inkling2_route_tiles.py tests/test_gpu_inkling2_router_gpu.py
  tests/test_unit_inkling2_gguf_runtime.py tests/test_unit_inkling2_gguf.py` — pass.
- `tests/test_gpu_inkling2_gguf_device.py` fails identically with and without
  these changes (pre-existing on 4307e775; not introduced here, not fixed here).

## Notes

- Performance parity is expected: the removed transfers are ~600 B per layer per
  token, negligible against ~55 ms/token. The value is structural — the expert
  chain no longer round-trips the host — which is what a fully device-resident
  block path needs next. No speedup is claimed.
- The flag engages only under the `fast` execution profile (q8_dot kernels).
  Mixed-quant layers (Q4_K/Q8_0 banks) fall back to the host path per layer.
- `_resident_block` remains uncalled in-tree; its branch is wired but exercises
  no new user-facing path yet.
- Tracked in docs/REFACTOR.md R0526 for promotion or removal.
