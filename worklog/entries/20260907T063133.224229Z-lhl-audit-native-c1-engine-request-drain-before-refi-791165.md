# Audit native C1 engine request drain before refill

## Summary

Real C2-to-C1-to-C2 refill and request-drain checks pass all 10 category-suite
prompts at N8 and N2 on epyc W7900 GPU0. All three outputs match independent AR;
the D24 survivor retains its physical storage through refill. This proves the
bounded engine request/lease scenario, not full numerical or public qualification.

## Changes

- Add `validate_request_drain` over real snapshot schema from EngineService
  `live_loop_snapshot`, BatchScheduler `observability_snapshot`, and GGUF runner
  `observability_snapshot`. Require no service children/queued commands, no
  pending/active/admitted scheduler requests, no occupied slots, all inactive
  mask bits, and return of every resident session lease.
- This is request ownership, not a claim that graph caches or persistent GPU
  allocations are released. Pool-page references need their own inspection.

## Validation

- All 13 CPU cases fail before the helper exists, then pass using
  `.venv/bin/python -m pytest -q -o addopts='' tests/test_qwen38_packed_c1_drain.py`.
  Faults cover residual children/commands, scheduler requests/slots/mask, runner
  IDs/requests/leases, and missing snapshot data.

## Refill integration

- Eight trace-validator RED cases fail before the refill helper exists, then
  pass. Two controller tests verify that a refill is submitted only after the
  singleton event, and a missing event fails without submission.
- `--engine-boundary --refill-peer` starts D8/D24 children, signals only after
  successful native C1 execution following a real pair, and submits a new D8
  child from the controller. Require the actual D24 backend ID to join a new
  packed pair with the refill ID while retaining its resident slot. All three
  outputs must match independent AR (the refill reuses the first D8 oracle).
- Capture serialized `live_loop_snapshot` after all results and validate request
  drain before marking a cell successful. Persist service, scheduler, and runner
  request-ownership fields; this is not a pool-page or cached-memory release gate.
- All 63 focused lifecycle/cancel/drain/refill CPU tests and `git diff --check`
  pass. CLI integration follows the RED helper contracts; it has no fake GPU
  implementation test and must pass the real GPU trace.
- `bg-94` runs N8 then N2 on epyc W7900 GPU0:
  `HIP_VISIBLE_DEVICES=0 ROCR_VISIBLE_DEVICES=0 GPU_MAX_HW_QUEUES=1
  HIPENGINE_HIP_ARCH=gfx1100 .venv/bin/python scripts/qwen38_packed_c1_lifecycle.py
  --engine-boundary --refill-peer --capacity N
  --output /tmp/packed-c1-refill-lifecycle-nN.json`.
  Logs use the same stem with `.log`; both results are pending.
- A CPU integration test calls the real `submit_engine_pair` refill branch with
  a fake service. It verifies the D8/D24 initial submission, delayed D8 refill,
  exact static-intent object preservation, and three output/backend identities.
  All 11 refill CPU tests pass. No running GPU script was changed for this test.

## Partial GPU result and trace-validator repair

- N8 passes all 10 prompts. Independent raw-JSON inspection verifies all three
  outputs versus AR, ordered real-ID transitions, unique request IDs and resident
  slots, unchanged survivor storage, and empty service/scheduler/runner ownership.
  Counts: 21 initial-pair, 21 survivor-only, 25 refilled-pair cycles. Slot tables
  are all null, buffered completions zero, and admitted totals equal reclaimed.
- Two extra RED cases expose a trace-validator gap: duplicated request IDs or
  two requests sharing a slot could pass set comparisons. Require uniqueness
  of both. All 26 refill/drain CPU tests pass; replay the strengthened validator
  over all 10 saved N8 traces, which also pass. This changes only offline trace
  checking, not execution or event signalling. N2 was already running and its
  saved capture must also be replayed through the final validator.

## Final GPU and CPU validation

- `bg-94` passes N8 and N2, 10 prompts each. Replay the final uniqueness-aware
  validator over both saved captures and independently inspect exact three-child
  output IDs, ordered transitions, same survivor storage and all drain fields.
  N8 counts are 21 initial-pair / 21 survivor / 25 refilled-pair cycles;
  N2 counts are 21 / 20 / 25. Both close without error.
- Every snapshot has no service children/commands, no active/pending/buffered
  scheduler requests, null slot tables, all resident leases returned, and equal

- Final `.venv/bin/python -m pytest -q -o addopts='' tests/test_qwen38_packed_c1_*.py`
  passes all 181 tests. No runtime or public policy changes.
- Artifact: `benchmarks/results/2026-09-07-w7900-packed-c1-refill-drain-diagnostic.json`.

  full traces and snapshots are in the named captures.
