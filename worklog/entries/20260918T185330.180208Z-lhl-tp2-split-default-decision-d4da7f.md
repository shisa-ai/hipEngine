# The 0.44/0.56 TP2 split stays opt-in: its optimum is host-specific

## Summary

The 0.44/0.56 split is production-certified and is the fastest TP2 configuration
measured (42.77 tok/s prefill / 42.11 tok/s decode at 128/16 against the even
split's 41.03 / 40.48, i.e. +4.2% / +4.0%). The repository rule is that a
measured, exact, non-regressive win is promoted to the default path unless there
is a concrete blocker. **This entry records the blocker, and the split stays
opt-in.**

The blocker is that this split is a property of *this host's pair*, not of the
engine:

1. **The split's value comes from a measured asymmetry between two specific
   cards.** `scripts/tp2_split_balance_plan.py` solved 0.417145/0.582855 from
   measured streaming rates (W7900 432.0 GiB/s with 2.347 ms/step fixed work
   against RX 7900 XTX 526.6 GiB/s with 2.092 ms/step) and a rank-1 spin cost of
   4.182 ms/step. Give the engine a different pair - two W7900s, two XTXs, a
   different PCIe topology - and the equalizing fraction moves, while a
   hardcoded default would keep handing the larger shard to whichever card is
   second in the device list.
2. **The solve's own optimum fails the production gate.** 0.417145 breaches at
   max KL 0.0699 and 0.43 breaches worse at 0.1006, while 0.44 passes at 0.0141
   with 100% top-1. The max-KL tail is not monotone in the move, so the retained
   value cannot be *computed* from the plan - it was selected from measured
   passing candidates. An automatic default would therefore have to either ship a
   number that fails the gate or embed a host-specific allowlist of passing
   candidates.
3. **The gain is small next to the portability cost.** ~4% on both phases does
   not justify making the engine's out-of-the-box behaviour depend on which two
   GPUs happen to be installed.

What would change this decision: a split policy that derives its candidate from
measured per-rank rates *and* validates each candidate against the production
gate automatically, so the engine can pick a passing fraction per host instead of
shipping one. That is a real unit of work (the gate is minutes per candidate) and
it is not attempted here.

The even split therefore remains the default, and the 0.44/0.56 boundary remains
reachable through the shard-fraction option with its widths admitted to the
pair+SiLU allowlist so it keeps the fused route. The certification, the sweep
that selected it, and the ladder that measured its capacity are all retained as
evidence for whoever builds the per-host policy.
