# Record Qwen3.8 INT8 KV quality frontier

## Summary

Qwen3.8-27B is a real model-version exception to the Qwen3.6 dense-27B INT8
quality rejection. Pure FP32-scale per-token/head INT8 and the existing
tail-four Hadamard layout both pass complete 512/8 and 4K/16 suites plus a
bounded `mixed_v1` 32K/16 row without BF16 mirrors. Neither becomes supported
or default: chunk-outer exact-prefill oracles more than reverse the retained
memory savings at request high water, both prefill sample bands regress about
0.33%, and the existing no-oracle direct prefill path is non-finite.

## Changes

- Added a compact benchmark artifact with exact model/hardware identity,
  commands, raw-source hashes, complete quality summaries, byte-exact 32K
  retained/oracle memory math, matched RX 7900 XTX runtime rows, and the support
  decision.
- Updated `docs/KVCACHE.md`, `docs/TESTING.md`, and `docs/REFACTOR.md` to record
  the Qwen3.8-specific quality frontier without transferring it to Qwen3.6 or
  changing the BF16 product default.
- Updated the internal benchmark scoreboard and changelog. The public root
  README is unchanged because no supported/topline route changed.
- Made no runtime or kernel source change. The direct-prefill experiment was a
  disposable `/tmp` monkeypatch and was not retained.

## Validation

- Pure FP32-scale INT8 complete 512/8: 11/11 prompts pass, mean/max KL
  `0.00011315/0.00229281`, aggregate/minimum-prompt top-1 `100%/100%`.
- Pure FP32-scale INT8 complete 4K/16: 11/11 prompts pass, mean/max KL
  `0.00014637/0.01430840`, aggregate/minimum-prompt top-1 `99.47%/94.12%`.
- Pure FP32-scale INT8 bounded 32K/16: mean/max KL
  `0.00317700/0.03684868`, 100% top-1.
- Tail-four Hadamard complete 512/8 and 4K/16: 11/11 prompts pass at each shape;
  mean/max KL `0.00001899/0.00038714` and `0.00002436/0.00108406`, with 100%
  minimum-prompt top-1. Bounded 32K/16 is `0.00002142/0.00036116`, 100% top-1.
- RX 7900 XTX 4K/128 at 32K capacity: BF16 graph
  `981.806/31.741 tok/s` prefill/decode and `17.920 GiB` tracked peak/current;
  pure INT8 eager `978.573/34.108`, `18.943 GiB` peak, `16.928 GiB` current;
  tail-four graph `978.447/32.559`, `18.188 GiB` peak, `17.684 GiB` current.
  Every row has finite logits and stable final token ID 9707.
- Byte accounting matches measurement exactly: pure saves `0.992065 GiB` live
  but adds `1.023560 GiB` peak; tail-four saves `0.236206 GiB` live but adds
  `0.267700 GiB` peak.
- Disposable direct tail-four prefill fails on the first candidate prompt with
  `FloatingPointError: GGUF resident lm-head logits contain NaN or Inf`.
- Validation commands and final doc/worklog/JSON checks are recorded in the
  committed artifact and commit message.

## Next

Preserve exact BF16 prefill while replacing the chunk-outer per-INT8-layer
full-length oracle lifetime with a bounded/shared owner. A layer-outer owner is
the leading design, but it needs an independently measured hidden-plane memory
trade. Only then rerun complete quality, actual server whole-device high water,
prefill/decode, and full natural MTP. Do not expose direct INT8 prefill.
