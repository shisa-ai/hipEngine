# QSA prefill's 9.01x is recoverable cost: identical selection, scalar-FMA kernel against tensor cores

## Summary

The `qsa_attention` family's 9.01x ratio (1402.5 ms against the comparator's
155.7 ms at `code-p4096`, worth 1246.8 ms of the 12.97 s total gap) is
**recoverable cost, not a bucket artifact**. Both engines select the same
positions by the same formula with the same budget: hipEngine's
`qsa_dense_equivalent_max_tokens` is `indexer_top_k + compress_ratio - 1` = 2051
(`hipengine/loading/qwen4exp_gguf.py:107-109`) and llama.cpp's `build_qsa_top_k`
computes `min(n_kv, indexer_top_k + r - 1)` with the comment "the reference
returns indexer_top_k + compress_ratio - 1: whole blocks plus the tail"
(`llama.cpp-hip/src/models/qwen4exp.cpp:664-665`) - also 2051. Re-bucketing the
engine's `qsa_score` (212.0 ms) into the comparator's `indexer` family, the most
generous reading available, moves the ratio from 9.01x to **6.58x**, not to
parity; the two engines' indexer work is already comparable (17.6 ms against
15.0 ms, 1.17x). The residual gap is kernel technology: the comparator's QSA
attention runs at an effective **11.93 TFLOP/s**, above this host's ~9.5 TFLOP/s
fp32 peak, so it is using BF16 tensor cores, while the engine's
`qsa_sparse_attention_h256_wave_rows_f32<true,4>` is a 32-lane scalar-FMA wave
kernel at **2.04 TFLOP/s** with `LDS_Block_Size` 0.

## Next

- Ranked levers, from the artifact: (1) K/V reuse and LDS staging - raise the
  amortization from the current 4 query heads toward the 24 that share each KV
  head by staging the selected K/V tile in shared memory and tiling rows, which
  is bit-exact per row and needs no numerical gate; raising `HEADS` alone is the
  trap, since VGPR 112 at `HEADS=4` becomes roughly 184 at `HEADS=8` and the
  routed-MoE 32-row tile precedent shows a spilled variant going 4.8-8.1x
  slower. (2) Tensor cores for QK^T and P*V, which changes arithmetic and needs
  the production numerical gate plus a strict fallback. (3) An occupancy and
  tiling sweep measured as a kernel microbenchmark.
- Open observation to resolve before any grid change: the traced launch has grid
  (192, 1021, 1) with block 32 for `<true,4>`, but the kernel's
  `head = blockIdx.x * HEADS` and `out_base = (row * query_heads + head) * 256`
  imply a launch-time `query_heads` of 768 while the model metadata carries
  `attention.head_count = 24` (and the QSA layer's `attn_q` emits
  12288 = 6144 query + 6144 gate).
- The engine-level A/B that would retain a prefill-level number is blocked: an
  idle `hipengine serve` (pid 4175913) holds 98.6 GB of GTT in
