# v0.5.0 release prep: README export contract, changelog, docs prose

## Summary

Started v0.5.0 release preparation. The manual README edits (heading rename, the
24 GB capacity bullet removal, the shorter concurrency lead-in) sat inside the
`TOPLINE:README_HIGHLIGHTS` block, whose source of truth is
`benchmarks/README.md`, so `scripts/sync_benchmark_readme.py --check` was failing
and the next `--write` would have reverted them. Mirrored the intent into the
export source instead of special-casing the script, then wrote the v0.5.0
changelog section, rewrote the README release summary, and de-slopped the new
user-facing docs. No benchmark was run for this unit; the gfx1151 refresh is
queued and waiting on exclusive GPU access.

## Changes

- `benchmarks/README.md` (export source): heading is now `### Performance`; the
  blank-cell/Max-context explanation moved to `Reading the tables`; the 24 GB
  Qwen3.8 note left the public block and became a scoped, honest statement in the
  direct `c1-c8` section, because the 2026-09-06 capacity audit says the
  3,072/4,096 startup points are not a published ceiling
  (`docs/QWEN38-27B-GFX1100-24GB-CAPACITY.md`). Replaced the unevidenced "a 24 GB
  card runs the same model comfortably at one or two" with "not qualified yet",
  which is what the audit supports. Restored the comparison basis sentence the
  shortened lead-in had deleted (aggregate tok/s, Qwen3.8-27B `Q4_K_M`, W7900, one
  server protocol, peers on F16 KV). The user kept the `vs llama.cpp (or even
  vLLM)` phrasing deliberately; no vLLM number is published and none is scheduled,
  and no current vLLM artifact exists for `gfx1151` (the 2026-06-15 attempt is
  recorded blocked).
- `README.md`: version line, `## Status and limits` summary rewritten for v0.5.0.
- `CHANGELOG.md`: new dated v0.5.0 section (Added / Changed / Fixed / Known
  limitations), sourced from the surface diff since tag `v0.4.0`, not from commit
  subjects: new server flags `--execution-profile` and `--speculative-mtp-thinking`,
  `POST /v1/hipengine/speculative_mtp/rollback`, `HIPENGINE_SPECULATIVE_MTP_*`,
  `HIPENGINE_GGUF_MTP_VERIFY_MODE`/`_CANDIDATE_BUDGET`,
  `HSA_SCRATCH_SINGLE_LIMIT`, `HIPENGINE_GGUF_FP16_RECURRENT_STATE`, the
  `fair` package defaults, the Python 3.11 floor, the withdrawn Qwen3.8 gfx1100
  MTP speedups, and the dense-27B INT8 KV rejection.
- `docs/ENVS.md`: `HIPENGINE_SPECULATIVE_MTP_SERVING` documented a default of
  `enabled` and called it "the default"; `hipengine/server/__main__.py` resolves
  `auto`, and `docs/API.md` plus the README both say fail-closed `auto`. Corrected
  the row to `auto` and rewrote the eight rows added since `v0.4.0` in plain
  language, keeping every default, value, and rollback.
- `pyproject.toml`: version `0.4.0` -> `0.5.0`, matching the README claim. Bump
  can be dropped if the version is wanted only at tag time.
- `tests/test_benchmark_readme_sync.py`: the pinned release string followed the
  README (`**Current release: v0.5.0.**`).
- Plain-language pass over the new prose (AGENTS.md "Public-facing prose is
  self-contained" + clear-writing): removed `fail closed`, `non-regressive`,
  `retained`, `incumbent package behavior`, `gate admits`, `validated leaf`,
  campaign packet labels, and slash-stacked qualifier chains.
