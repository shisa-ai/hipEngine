# Concurrency2 C2-2 resource ledger and fit-aware admission

## Summary

Implemented C2-2's production, format-neutral named-resource ledger and fit-aware admission boundary. Backend-produced claim vectors now support atomic provisional reserve/commit/rollback, signed owner deltas, reclaim, per-lifetime conservation, bounded lookahead, starvation drain mode, impossible-request rejection, and per-plane telemetry without scheduler codec formulas.

## Changes

- Added `ResourceLedger`, structured fit/blocking results, retryable `ResourceUnavailable`, reservation state, exact release deltas, high-water/lifetime counters, and mechanical conservation checks over `KVPoolPlan`.
- Added `FitAwareAdmissionController` with O(1) pending cancellation/tombstones, bounded lookahead, explicit bypass counts, starvation drain mode, and impossible-envelope rejection.
- Added `LedgerAdmissionCoordinator` to compose registered backend estimators with scheduler plan/reserve/rollback/reclaim callbacks.
- Extended `ResidentBatchScheduler.admit_pending()` to accept a stable request-ID plan while preserving FCFS compatibility; `ResidentEngineLoop` consumes optional runner admission plans and translates impossible claims into named `GenerationAdmissionRejected` overload.
- Added resource telemetry to resident-loop observability and common-ledger conformance against all four C2 fake backend compositions.
- Removed physical-route cap leakage for service-backed plain AR: native LLM resident capacity now follows the explicit operator cap while physical-width registration remains separate; non-resident compatibility grouping retains its legacy cap.
- Marked the C2-2 roadmap checklist complete.
