# The pack8 expert layout is never ahead, and the deletion condition is met
## Summary
`docs/REFACTOR.md`'s "Gemma 4's pack8 expert layout is off by default" entry names
its own clearing condition:
> Clear it by measuring the packed layout against the raw one at a row count where
> `rows` exceeds the expert count, which is the one regime the ladder does not
> already give to `grouped_prefill`.

Gemma 4 has 128 experts and the prefill chunk is 512 rows, so `--prompt 512` is
exactly that regime. This entry performs the named measurement. **The packed
layout is not ahead**, so the entry's stated deletion condition is met.
| layout | prefill tok/s | prefill s | decode tok/s |
| --- | --- | --- | --- |
| off (raw) | **343.2** | 1.492 | **21.24** |
| on (pack8) | 340.0 | 1.506 | **7.78** |
## What the numbers say
**Prefill: 343.2 against 340.0, a 0.9 percent difference** in favour of the raw
layout. That is inside run-to-run variation and is not a win for either side.
**Decode: 21.24 against 7.78, so the packed layout is 2.73x slower.** This
reproduces the 2.75x regression the entry already documents, on a fresh run with
the same flag, which is a useful independent confirmation that the documented
cause is real and stable.
## Verdict
The packed layout is never ahead. It is not ahead in the regime the ladder
already assigns to `grouped_prefill`, and it is not ahead in the one regime the
ladder does not cover — which is the condition the entry set for deletion.
## Consequence
The entry's own text says the flag and the unreached code "go away together when
the question is settled". The question is now settled by the entry's own named
method, so the deletion is unblocked: `LAYOUT_Q4_K_PACK8`, `pack8_arrays`,
`_materialize_pack8`, `_pack8_shapes`, `_pack8_nbytes`, `pack8_layout_enabled`,
and `gemma4_project_experts_pack8`.
## Caveats, stated rather than smoothed
- The prefill comparison is a 0.9 percent difference, so this run does **not**
  establish a prefill win for the raw layout. It establishes that the packed
  layout is not ahead, which is what the deletion condition asks.
- The decode regression is measured at `rows == 1`, which is not the regime the
  clearing condition names. It is reported because it is the larger and more
  decisive of the two effects, and because it reproduces a previously documented
  number rather than introducing a new claim.
- The flag costs 19.2 GB of duplicated weights. Both runs fit; the raw run does
  not carry that cost, which is a further reason not to keep the layout.
