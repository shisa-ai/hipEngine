# TimesFM transpose + GEMM autotune (flash-attn follow-up)

## Summary

Two retained optimizations driven by a fresh rocprofv3 kernel-trace of the
flash-attention build (0.0959s): the head-transpose kernel was rewritten
(37us -> 6.8us per call, 96 calls per decode) and the FP16 projection GEMMs
gained shape-keyed rocBLAS solution autotuning (enumerate
`rocblas_gemm_ex_get_solutions`, benchmark the top candidates, pin the
fastest). Wall metric 0.0959s -> 0.0915s median (-4.6%, MAD 0.6ms,
multiloop HIGH confidence). A split-K variant of the AR flash attention was
implemented, measured slower (146us vs 113us per call), and reverted.

## Changes

- `hipengine/kernels/hip_gfx1100/timesfm/timesfm.hip`:
  `transpose_heads_kernel` rewritten as one block per output row,
  half4-vectorized, coalesced (was: one thread per element with int64
  div/mod, 90 GB/s).
- `hipengine/core/rocblas.py`: `gemm_ex_rowmajor_nt_fp16_solutions_f32`
  (solution enumeration; beta API guarded by symbol presence) and
  `solution_index` passthrough on the f32-compute wrapper.
- `hipengine/runtime/timesfm_decode.py`: `_gemm_solution` shape-keyed
  autotuning (one-time per (rows, fin, fout); candidates benchmarked with
  the live operands — idempotent overwrite — ties fall back to the rocBLAS
  heuristic; `autotune_gemm=True` constructor default).

## Measured

- transpose: 37us -> 6.8us per call (rocprofv3), ~2.9ms per decode.
- GEMM solutions (standalone, best-of-50): AR qkv 61.6 -> 49.0us;
  8x1280 quantile 59.6 -> 37.4us; prefill qkv 534 -> 481us.
- Wall: 0.0959 -> 0.0915s median (11 runs 0.0906-0.0951).
- Split-K AR flash (2-tile chunks): 146us vs 113us single-block — the fixed
  per-chunk cost (q-fragment loads, init, unnormalized epilogue, merge
  kernel) exceeded the parallelism win at Q=4. Reverted; kernels removed.

## Validation

- `python3 scripts/timesfm_gpu_bench.py --check`: fp32 strict parity +
  fp16 production gate pass.
- `python3 -m pytest tests/test_timesfm_gpu_decode.py -q`: 3/3.
- Autotune determinism: candidates enumerated by shape only (no input-data
  dependence); benchmark reruns are idempotent overwrites of the same GEMM.

## Next
