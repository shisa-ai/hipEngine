# Batch MoE C2 NextN prompt KV priming

## Summary

Batch MoE C2 NextN prompt priming across the complete prompt sequence instead
of replaying every token through a one-row K/V path. Streamed target hidden rows
remain device-owned until the completion boundary; one embedding/norm/fusion
and one K/V-only attention pass build exact provider cache state per request.

## Changes

- Stage request-local prompt token/hidden rows in bounded max-position buffers.
- Materialize embedding/enorm/hnorm/eh_proj with prompt-length weight sweeps.
- Add a packed single-segment K/V-only NextN session primitive and scatter only
  full-attention K/V back to the stable request slot.
- Preserve cursor publication, stream synchronization, reset/release/close.

## Validation

- Existing prompt/checkpoint/reset test bundle passes; Ruff/compile checks pass.
- One-run full economics: **100.736 vs 87.043 tok/s = 1.1573x AR**.
  `nextn_prompt_prime` falls from ~21.8 ms to ~0.2 ms/call; stage total is
  `1.306 s/60 calls` in the prior three-run packet versus `0.0041 s/20 calls`.
- Full ten-prompt gate:
  `/tmp/gfx1100-moe-c2-bulk-prompt-full-quality.json` — 281 rows,
  mean/p95/p99/max KL `0.0000266/0/0.000229/0.003588`, 100% top-1,
  all category/shape/transition, repeatability, isolation, task and lifecycle
  checks pass. Generated-ID equality is not used as the binding gate.
