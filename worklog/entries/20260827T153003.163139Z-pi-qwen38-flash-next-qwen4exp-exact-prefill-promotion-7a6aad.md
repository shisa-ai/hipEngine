# Promote exact Qwen4Exp chunk64 prefill

## Summary

Promoted exact chunk64 prefill as the public Qwen4Exp default. The complete
687-row category+heldout packet is bit-exact to token-serial strict execution,
while natural-suite prefill improves 2.30x.

## Changes

- Fixed PLE ring-view ownership (`daa0766ec`).
- Kept all expensive projections batched, but advances the tiny causal Conv
  row-by-row through the exact decode owner.
- Groups post-SiLU Q5_1 down lanes by expert using an exact direct-lane gather,
  scalar rowbatch8 grouped down, and original-lane weighted reduction.
- Changed default prompt chunk from 2 to 64 and public `prefill()` from serial
  to exact chunked execution. `prefill_serial()` remains fallback.
- Exact Conv/grouped-down flags default on and can be set to 0 for bisection.
- Artifact:
  `benchmarks/results/2026-08-27-gfx1151-qwen38-flash-next-exact-prefill-promotion.json`.

## Validation

- Focused model/generation/PLE/GDN/QSA/MoE bundle: 20 passed.
- Binding gate: 18 prompts / 687 teacher-forced full-vocabulary rows; every row
  bit-exact, mean/p95/p99/max KL 0, overall and every category top-1 100%.
- Same one-residency wall: strict 130.485 s / 5.265 tok/s; exact chunk64
  56.697 s / 12.117 tok/s (2.301x).
- Warm repeated-token p512: size2 8.674 tok/s; exact chunk64 16.555 tok/s
  (1.909x), structural token 264 unchanged.
- Public API returns `" 4.\n\n"`; load plus four-token generation 29.707 s
  diagnostic, tracked peak 82,807,048,480 bytes, zero teardown bytes/owners.
- Full 512-row performance candidate remains internal/default-off at 211.76
  tok/s because its 687-row production packet fails.
