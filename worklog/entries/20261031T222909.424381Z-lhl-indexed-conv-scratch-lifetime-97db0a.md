# Keep indexed Conv BF16 input live through FP32 output

## Summary

The public two-request AR request reaches the first indexed linear-attention
layer with finite embeddings and Conv/recurrent state, but later emits all-NaN
logits and the invalid argmax token sentinel. The cause is the shared
prefill/decode scratch lifetime for `linear_qkv`: it ends at stage 2, where
`conv_out` begins. The public parent probe confirms that BF16 input and FP32
output use exactly the same address. Extending QKV's lifetime through stage 3
separates the planes and repairs the public two-request generation.

## Changes

- Added `tests/test_unit_gguf_indexed_conv_scratch.py`, exercising rows
  2/8/128/768 and both single-arena and owner-slot grouping. It requires
  disjoint QKV/Conv storage and preserves the existing FP32-input protection.
The minimal repair extends the BF16 QKV lifetime through the Conv stage,
rather than changing the general lifetime conflict predicate. This prevents a
width-changing read/write overlap in both arena layouts; the FP32 prefill input
already has that protection. It modestly increases some planned scratch sizes,
so allocation-size fixtures are updated from the executed planner values.
