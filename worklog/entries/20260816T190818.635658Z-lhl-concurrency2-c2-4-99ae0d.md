# Concurrency2 C2-4 backend radix snapshots and eviction

## Summary

Implemented C2-4's generation-checked backend radix snapshots and cache-owned global-pool lifecycle. Dense complete-page prefixes now survive source-request reclaim, attach as shared pages without format casts, advance only the generic prefill cursor, and remain bounded by LRU/TTL/global and tenant quotas plus cache-first pressure eviction.

## Changes

- Added `PrefixCompatibilityKey` covering model artifact/revision, adapter, hardware/model/weight quant, resolved backend and artifact, RoPE, multimodal input, and prompt-token radix scope.
- Added immutable `KVSnapshotHandle` plus `BackendRadixCache` over the existing token radix: exact backend/generation checks, complete-page publication, nested snapshot refs, lookup/touch, stale/TTL rejection, explicit/LRU/quota/pressure eviction, and telemetry.
- Added atomic cross-lifetime `ResourceLedger.transfer()` so each unique physical cache page moves from one lease owner to one cache owner and back to an active lease (or free capacity) without double counting.
- Extended `GlobalKVPoolSet` with cache refs and corrected active-shared state; overlapping snapshots retain pages independently while the ledger counts each physical page once.
- Extended dense admission to consume opaque snapshot page IDs, allocate only uncached prompt pages plus one growth credit, materialize shared/private handles, and return a generic `RequestState` prefill cursor update to the scheduler.
- Integrated optional prefix lookup/publication and cache-first pressure eviction into `DenseKVAdmissionManager`. Sampled/unqualified reuse remains fail-closed unless a caller registers an explicit eligibility policy.
- Kept the prefix default unchanged and documented the remaining two-gfx11 hardware/default-promotion gate under C2-6.
