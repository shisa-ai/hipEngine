# Cache-only guard was a no-op: HIPENGINE_HIP_REQUIRE_CACHED_BUILD

## Summary

While de-risking the remaining P5 C1 decode attribution work I checked how the
cache-only profiling recipe is actually wired, and found that the IKV-C2
ownership trace's recorded command set `HIPENGINE_HIP_REQUIRE_CACHED_BUILD=1`.
`hipengine/core/build.py` reads `HIPENGINE_REQUIRE_CACHED_BUILD`
(`_ENV_REQUIRE_CACHED_BUILD`, line 24). The name in the command was a lookalike,
so the guard was never active during that trace, and the artifact's note
claiming `HIPENGINE_REQUIRE_CACHED_BUILD=1 prevented hipcc in the profiled
process` was unsupported for the run it described.

This is the failure mode that matters for profiling: a no-op guard does not
merely weaken a claim, it leaves the profiled process free to spawn `hipcc` and
corrupt the trace while the artifact still certifies the run as cache-only. The
kernel evidence in that artifact was consistent and reproducible, so nothing
about the IKV-C2 promotion depended on the corrupt-trace outcome having
occurred — but the provenance claim was not true, and a reader had no way to
tell.

Two other occurrences of the same literal exist in the tree and are recorded
below rather than edited. Neither makes a false claim.

## Changes

- `scripts/qwen38_int8_batch_decode_ownership_trace.py`:
  - `REQUIRE_CACHED_BUILD_ENV` is now taken from
    `hipengine.core.build._ENV_REQUIRE_CACHED_BUILD` instead of being spelled
    out, so the generator cannot drift from the module that reads it.
  - New `trace_environment` block records the cache-relevant environment the run
    set (`HIP_VISIBLE_DEVICES`, `HIPENGINE_HIP_ARCH`,
    `HIPENGINE_COMPILER_VERSION_FILE`, `HIPENGINE_REQUIRE_CACHED_BUILD`), which
    makes the cache-only claim checkable rather than asserted.
  - The cache-only note is now emitted only when the generator ran the trace.
    The parse-only path states instead that it cannot observe that property.
- `benchmarks/results/2026-09-11-w7900-ikv-c2-batch-decode-ownership-trace.json`
  re-taken with the guard genuinely active (profiled `rocprofv3` run, not a
  parse-only regeneration).
- `tests/test_qwen38_int8_batch_decode_ownership_trace.py`:
  - the trace environment must use the names the build module reads, and the
    real predicate `_environment_requires_cached_build()` is driven for each
    accepted truthy spelling;
  - the version-file name is proven by finding the path in
    `_environment_version_identity` and the resolved value in
    `_compiler_version_from_environment`;
  - the committed artifact must record the guard, use the correct name, and
    carry a note that does not name the lookalike;
  - a repo-level lint over `scripts/*.py` rejects quoted use of the lookalike.

## Validation

- `uv run pytest tests/test_qwen38_int8_batch_decode_ownership_trace.py -q` ->
  30 passed.
- Guard genuinely active: the profiled gate run completed with
  `HIPENGINE_REQUIRE_CACHED_BUILD=1` set, so every kernel was already cached. A
  missing cache entry would have failed the run instead of silently compiling.
- Mutation RED (lookalike reintroduced as the constant): three tests fail, the
  environment-name test, the artifact-claim test, and the lint. Generator
  restored to the module-derived constant and re-green.
- Re-taken trace is consistent with the previous one where it must be: launch
  counts and geometry identical (one batch producer grid `[1024, 5, 4]` plus one
  strided reducer grid `[6144, 4, 1]` for all four rows; 2 packed launches vs 8
  c1 leaf launches). Single-shot durations move within run-to-run noise
  (batch path 75,562 -> 75,694 ns, c1 leaf 245,921 -> 240,574 ns, ratio
  3.255 -> 3.178); this artifact is launch-count and sub-window evidence with
  `performance_claim` false, so no rate is published from it.
