# Execute review punchlist R1-R3: provenance, refresh, drift diagnosis

## Summary

Executed the first three items of the campaign review punchlist at committed
source. R1: re-ran the six-case off/on/off ordered-v2 state gate at clean
`91de3e295` (full logits, four decode steps, recurrent state, full KV — all
bit-identical, exact engagement accounting: 48 sparse decode calls per enabled
p4096 arm, zero prefill/short-context), retained named v2 kernel durations
under cache-only rocprof profiling as a durable artifact (scores 33.5us,
coefficients 14.3us, values 100.7us versus parent 399.7/176.1/533.0us; VGPR
32/40/96, scratch 0), and updated the kernel catalog (`docs/KERNELS.md`) and
rollback-selector ledger (`docs/REFACTOR.md`).

R2: complete shared-taxonomy family capture at clean `20a63e689` (six cases,
twelve phases, chunk1024, pinned Vulkan profiles reused and declared as
such), joined with table regeneration. Code-p4096 prefill: FFN 8.643s (was
10.214s — the iu8 promotion's effect), linear 4.442s, GR 3.383s, QSA 1.330s,
GDN 0.801s; device total 18.714s = 1.892x Vulkan (was 2.09x). Fixed-live4097
decode: QSA 2.617ms versus Vulkan 3.161ms (0.849x — hipEngine is now faster
on the QSA decode owner); MoE 17.28ms at 1.388x is the top remaining decode
owner; device decode total 46.533ms = 1.101x (was 1.43x). Logger-off
combined-default 12-case baselines: HE PP 204.24/221.26/210.74 (unchanged),
TG 19.15/18.58/16.39 — p4096 TG +18.2% versus the pre-ordered-v2 packet
(13.87), Vulkan TG lead 1.500x at p4096 (was 1.764x). Both engines run the
identical 1-warmup + 3-repetition protocol, so the 1:1 comparison is
protocol-matched; hipEngine's repetition-order drift makes its 3-rep average
conservative versus its own first-rep rate (p4096 first-rep ~18.0 versus
average 16.4) while Vulkan is flat (0.12% CV). Final comparisons must use
matched multi-run averages on both sides — recorded as a standing caveat.

R3: counterbalanced off/on drift probe (fresh prefill per arm, eight warmup
steps, 128-step windows, GPU sclk/temperature/power and per-step CPU
frequency sampled). Findings: GPU sclk pinned at 2900MHz, temperatures
68-77C, CPU at 5.1GHz (p10 >= 4.84GHz) in every arm — the drift is not
clock, thermal, or CPU-frequency; per-step logits capture does not reproduce
it. The ordered-v2 route is repetition-stable to 0.3-0.4% spread in both
cases; the parent route shows a uniform first-window-after-first-prefill
penalty (general_en 12.03s versus 8.45s steady, decaying after one window;
mechanism unidentified — cache warmth, not clocks). The canonical protocol's
third-rep sag (18.0 -> 12.8 TG) did not reproduce under this controlled
structure in either arm; in the retained A/B it is arm-independent (both
before/after drift), so it is carried by the canonical harness sequencing
(one warmup per mode, slot interleave) with hardware state ruled out. A
future narrowing probe must mirror the canonical slot/warmup sequence
exactly.

An earlier family-capture attempt failed mid-run because the review session
committed documentation while the capture was in flight (tracked-clean gate
correctly rejected the dirty tree); the capture was redone fully at the
clean commit rather than resuming across revisions.
