# Prefer fold128 grouped prefill owner in Gemma expert route

## Summary

The normal preferred grouped-prefill dispatch now leads with the exact
pair2_fold128 owner where it registers and the input width fits its fold limit.
`gemma4_project_experts_grouped_prefill` used to walk
`_GROUPED_PREFILL_VARIANTS` starting at the staged_out4 owner, so the folded
owner was reachable only through the pinned/`grouped` probe
(`gemma4_project_experts_grouped`, which already inserts it first inside
`_GROUPED_FOLD128_MAX_IN_FEATURES = 4096`). The auto ladder in
`gemma4_project_experts_rows` therefore reached the fold owner only for the
down-projection probe, not for the default dispatch.

This is a cost/dispatch change only. The folded owner is the same reduction as
the rest of the grouped family and bit-identical to it, so no arithmetic
changes. No feature flag, no kernel body, no model/quant-name admission.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py`
  - Added `_grouped_prefill_variant_order(in_features)`, which prepends
    `_GROUPED_FOLD128_PREFILL_VARIANT` when `in_features <=
    _GROUPED_FOLD128_MAX_IN_FEATURES` and otherwise returns the unchanged
    `_GROUPED_PREFILL_VARIANTS` order. The width gate exists because the fold
    wrapper rejects a wider input outright rather than declining.
  - `gemma4_project_experts_grouped_prefill` now walks that width-aware order.
    Fallback is unchanged: a quant that does not register the fold owner, or a
    width past the fold limit, still falls through the staged/row-batch/compact
    variants and then to the selected GEMV.
  - Updated the `_GROUPED_PREFILL_VARIANTS` comment and the route docstring to
    record the width-aware order.
- `tests/test_unit_gemma4_expert_route.py`
  - `_GROUPED_KEY` is now the fold128 variant (the route's first preference at
    the 704-wide Q5_1 geometry these tests use).
  - New CPU route tests: fold128 preferred inside its limit; a registered
    fold128 stub dropped past the limit; base order kept when fold128 is
    unregistered; the pure order helper at the limit boundary and at an
    unrelated width; an unrelated quant (Q8_0) still resolving its own compact
    owner.
  - Existing route-order tests now iterate `_grouped_prefill_variant_order`
    instead of the fixed base list, so they track the route's actual order.
  - The HIP bit-exact test now compares the route's unused variants as the tail
    of the width-aware order.
