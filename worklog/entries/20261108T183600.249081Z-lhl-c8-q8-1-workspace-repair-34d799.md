# Repair dense C8 target Q8_1 workspace disable

## Summary

Found and repaired a real gfx1100 product defect exposed by the first public
C1-C8 MTP run on the W7900: **explicit C8 MTP never engaged**. Correctness was
preserved (every request fell back to exact AR), but the speculative feature was
silently dead at width 8. Root cause is a resource conflict between two
default-on features, not a numerical or admission problem.

Reproduction (bg-1 full suite, bg-2 C8-only with `HIPENGINE_DEBUG_SAMPLED_ROUTE=1`):
all 10 C8 cohorts failed their first speculative cycle with
`ValueError: Q5 raw MMQ target session requires a device workspace`, then
`precommit_failure_ar_fallback` retired the cohort to permanent AR
(`no_provider`, `provider_decline_reason: request N unregistered or disabled`).
C1-C7 engaged 10/10 with exact AR/MTP IDs.

## Root cause

- The C8 physical target selects the source-Q5 raw-MMQ owner
  (`GGUF_C8_Q5_RAW_MMQ_SSM_OUT=True`, enabled at `request_count==8`) and the Q6
  grouped-dp4a owner. Both borrow `scratch.moe_q8_1` as their bounded Q8_1
  activation workspace (`_q5_raw_mmq_target_context` /
  `_q6_dp4a_grouped_target_context` in `qwen35_gguf_runner.py`).
- The dense prefill-scratch liveness optimization
  (`_gguf_prefill_scratch_liveness_disabled_fields`) disables every `moe_*` field
  for non-MoE models via `_GGUF_PREFILL_SCRATCH_DENSE_DISABLED_FIELDS`, because a
  dense checkpoint has no MoE experts. That set includes `moe_q8_1`.
- Net effect: on a dense model `scratch.moe_q8_1` is the shared empty buffer
  (`ptr=0, nbytes=0`). Opening the enabled C8 target session raises the workspace
  ValueError, failing the whole cycle pre-commit. The Q5 owner raises first; the
  Q6 grouped owner has the identical dependency and would raise next.

This is exactly the "works in the harness is not works" failure the refactor
ledger's public-engagement entries (R0170/R0171/R0393-Q6) exist to catch: leaf
numerical gates passed because they provision a workspace explicitly, while the
public dense serving path allocated none.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: add
  `_gguf_c8_target_q8_1_workspace_declared(backend)`, true when the backend
  declares `GGUF_C8_Q5_RAW_MMQ_SSM_OUT` or nonempty
  `GGUF_Q6_DP4A_GROUPED_TARGET_REQUEST_COUNTS`. In the dense branch of
  `_gguf_prefill_scratch_liveness_disabled_fields`, remove `moe_q8_1` from the
  disabled set when that capability is declared. Capability-driven, not
  model/file/identity-driven; backends without the consumers (gfx1151) keep the
  memory optimization. No arithmetic, dispatch, or admission change.
- `tests/test_unit_qwen35_gguf_prefill_scratch_liveness.py`: RED/GREEN regression
  `test_gfx1100_dense_scratch_retains_c8_target_q8_1_workspace` (plane live, sized
  for the widest declared target shape, and both C8 target contexts bind exactly
  that plane) plus `test_dense_scratch_q8_1_workspace_is_capability_scoped`
  (no-consumer backend keeps the empty plane). Updated the two dense arena budget
  pins to include the retained plane.

The retained plane is sized by the existing plan (`rows * ceil(ffn/32) * 36`),
which already covers the Q6 grouped requirement at the widest target shape
(17408 input columns) and exceeds the Q5 D4S4 requirement. Memory cost: +14.34 MiB
at 768 rows, +76.5 MiB at 4096 rows per dense scratch on a consumer backend.
