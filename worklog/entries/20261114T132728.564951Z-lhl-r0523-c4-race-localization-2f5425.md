# R0523 c4 race pinned: layer-0 GDN, slot 1, conv/recurrent state

## Summary

The c4 packed-decode nondeterminism is now localized to a specific layer, row, and
stage. Per-slot hashing of the residual stream across GDN layers shows the corruption
is created in **layer 0** (the first linear-attention layer) and **always in slot 1
(row 1)**. Within layer 0, the first divergent stage is the **conv output (19 source
steps) or the recurrent output (71 source steps)**; the attention norm and the QKV/gate
projections never diverge first. The recurrent (gdn_indexed_singleton) kernel is the
dominant source. No production behavior changed; all hooks are env-gated (off by
default) and uncommitted.

## Changes

- Env-gated diagnostics in `hipengine/runtime/qwen35_gguf_runner.py`:
  `_r0523_gdn_stage_hash` (hidden-IN/norm-OUT/QKV-OUT per slot, multi-layer via
  `HIPENGINE_R0523_GDN_STAGE_HASH_LAYER=0,4,8,...`, global call counter) and
  `_r0523_gdn_post_hash` (conv-OUT/recurrent-OUT/ssm_out-OUT per slot after the
  recurrence). Diagnostic only; revert before any production commit.

## Validation

Measured on W7900 (gfx1100), Qwen3.8-27B-Q4_K_M, c4 eager
(`HIPENGINE_GGUF_DECODE_GRAPH=0`), 30 measured reps each, strict correctness profile:

- bg-185 (layers 0,4,8,12,16,20): separated SOURCE steps (layer-0/embedding identical,
  a later layer diverges) from CONSEQUENCE steps (embedding already differs because the
  prior token flipped). Source earliest-layer histogram: layer4=165, layer8=120,
  layer16=16, layer20=23. Diverging-slot histogram: slot1-only=309, slots1+2+3=15.
- bg-186 (layers 0,1,2,4): all 75 source steps have layer-0 input identical and layer-1
  input divergent => corruption created in layer 0. Slot1-only=60, slots1+2+3=15.
- bg-188 (layer 0, H/N/Q + conv/rec/out, corrected strides): first-corrupting stage
  conv-out=19, recurrent-out=71; norm/QKV never first. Slot1-only=75, slots1+2+3=15.
- Measurement-bug fix: bg-187's conv/rec hash used `nbytes//rows`, but those slabs are
  sized by `slot_count=max_batch_size` (> live rows), overstating the stride and giving
  a false systematic divergence at step 0. Corrected to true per-row strides
  (`linear_qkv_width*4`, `ssm_inner_size*4`); hidden/norm/QKV strides were already correct.

Cleared as the owner (all verified correct/deterministic): attention norm and QKV/gate
projection (never diverge first); static distinct `state_indices=[0,1,2,3]`; the
indexed recurrent kernel's per-(slot,v_head) state indexing and per-workgroup shared
memory (no overlap); the packed state-import destination offset (per-slot stride matches
the session state size). The race is therefore a concurrent write to slot 1's GDN state,
not an indexing or arithmetic defect in the inspected kernels.
