# Exact iu8-WMMA MoE gate/up repair study

## Summary

Structural FFN study after committing the F32-cache rejection (1633801b0).
The p4096 kernel-level trace (/tmp/qwen4exp-post-qsa-quad-family.raw,
code-p4096-prefill, gfx1151, chunk1024) shows the early-layer MoE gate/up
owner is the raw scalar `gguf_q4_k_selected_dual_grouped_pair2_bf16_kernel`
(3.39s/run, 32.6ms per layer-chunk) on exact route layers, while the
production iu8-WMMA kernel (layers 35-47) runs the same shapes in ~13ms
and the f16-WMMA legacy in ~30ms. Q5_1 down pair2 is 1.61s vs the
qualified WMMA down ~4.6ms/call. Certified fast-scope extension to early
layers is numerics-blocked (layer-2 f16-WMMA KL 0.001179 > 0.001;
"full-layer and adjacent boundary candidates measured and rejected"),
so the remaining structural route is a BIT-EXACT fast path.

Key finding: the production iu8-WMMA gate/up kernel is already
weight-exact (raw Q4_K nibbles as the int operand; min-offset
reconstructed per subblock from staged activation int8 sums) and uses
3 residual activation planes, so its only differences vs the exact pair2
parent are epsilon-class: 3-plane activation residual and f32 accumulation
order. bf16 outputs can only differ for values essentially at a bf16
rounding boundary. Adding the linear family's established
risk-collected sparse exact repair (collect_risks + sparse_exact_correct,
lineage gguf_q8_0_mmq_prefill) to the MoE iu8 kernel should make it
bit-identical to pair2, allowing early-layer promotion through the
exact-trajectory route instead of the blocked T2 KL gates.

## Changes

- Committed prior F32-cache rejection evidence as 1633801b0 (docs,
  result JSON, worklog entry; no code change).
- New kernel `gguf_q4_k_selected_dual_wmma_iu8_risk_prefill_kernel`
  (gguf_q4_k_selected_prefill.hip): the production iu8-WMMA gate/up
  arithmetic with an added Kahan-compensation error probe and per-output
  risk collection. Published values are bit-identical to the plain iu8
  kernel; at-risk outputs queue a linear output index via atomicAdd.
- New kernel `gguf_q4_k_selected_dual_sparse_exact_repair_bf16_kernel`:
  recomputes each queued index with the grouped pair2 parent's exact
  arithmetic (per-thread K ownership k=tid/tid+128 per 256-block, shuffle
  16..1 wave tree, serial wave-0..3 publication sum), overwriting the
  published BF16 value.
- Launchers, extern-C exports, Python wrappers, registry variants
  `selected_dual_wmma_iu8_risk_prefill_bf16_bf16_out` and
  `selected_dual_sparse_exact_repair_bf16` (default: no runtime route
  change; production dispatch untouched).
- `tests/test_qwen4exp_q4_iu8_exact.py`: 9 focused tests (registry RED/GREEN,
  bit-exact chain vs pair2 on three fixture shapes including the
  huge-multiplier full-repair case, determinism, argument validation).
- `scripts/qwen4exp_q4_iu8_flip_probe.py`: actual-weight iu8-vs-pair2
  flip/speed probe with output dumps.
- `scripts/qwen4exp_q4_iu8_flip_analyze.py`: offline float64-truth
  characterization of flips (boundary distance, cancellation ratio).
- `scripts/qwen4exp_q4_iu8_exact_screen.py`: actual-weight operation-
  complete A/B screen (GPU tile map with static upper bound, risk prefill,
  sparse repair, identical SiLU in both arms) with per-pair bit-exact
  verification and multiplier sweep.

## Validation

- Feasibility probe (actual layer0 gate/up weights, uniform routing):
  iu8 is 2.24x/2.43x faster than the exact pair2 parent at 512/1024-row
  chunks; BF16 flip fraction 0.030%/0.029%. 94% of flips are +-1 ulp;
  float64-truth analysis shows the larger outliers are extreme
  cancellation outputs (|truth| <= 7e-6 with sum|x*w| ~ 4.5). The error
  is absolute-scale (~eps * sum|terms|), so flips concentrate on small-
  magnitude outputs near BF16 rounding boundaries.
- All 9 focused tests pass; existing suites
  (test_gguf_q4_k_selected_wmma_prefill, test_qwen4exp_q4_bundle,
  test_qwen4_exp_pf3_moe_schedules) stay green after the kernel-file edits.
- Exact screen, layer0, rows 512/1024, multipliers 1/2/4/8: every pair
  bit-identical to pair2 (gate, up, and downstream SiLU). Speedups:
  1024-row chunk 2.00x/1.91x/1.76x/1.53x at m=1/2/4/8; 512-row chunk
  1.86x/1.77x/1.67x/1.47x. Risk fraction is stable at 0.25%*m/1.
- Safety sweep, layers 3/10/26 x uniform/skewed x rows 512/1024 at
  m=2 and m=4: all 24 cases bit-exact; 1024-row speedups 1.81-1.97x (m=4),
  512-row 1.50-1.67x (m=4).
- Failure floor located: at layer3 uniform m=0.5 the chain MISSES flips
  (assertion failure), m=1 passes. Recommended default multiplier is 4
  (>=4x above the observed floor), speedup 1.50-1.82x across shapes.
- Kernel-only screens; no model A/B, no runtime default changed.
