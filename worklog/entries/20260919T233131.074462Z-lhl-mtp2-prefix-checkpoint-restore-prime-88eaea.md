# Prefix-cache hits prime their draft provider from a restored checkpoint

## Summary

A prefix-cache hit now primes its draft provider from the checkpoint a previous
turn captured at that boundary, so the hit row speculates instead of decoding
autoregressively. Measured on the same host, protocol, and workload: a hit row
goes from 0 draft cycles and ~83 ms median inter-token latency to 20-24 cycles
and 35-41 ms, matching the miss rows' 30-40 ms, with the miss rows' acceptance
(24 cycles / 39 accepted on the first hit row, exactly the first miss row's
24/39) and no accounting drift (`unexplained_mtp_output_tokens=0`,
`reconciled=true`).

## Changes

- `hipengine/generation/qwen35_gguf_mtp2.py`: `begin_prompt_streaming` admits a
  reused-prefix row when a validated checkpoint exists, and builds its sink from
  that checkpoint -- `prompt_tokens=prompt_ids[prefix_len:]`,
  `start_position=prefix_len`, `initial_hidden` wrapped from the checkpoint's
  boundary row -- after `restore_prefix_state` puts the provider back into the
  row's slot. `restorable_prefix_rows` is the pure query the runner gates on.
  `_restored_priming_source` no longer publishes
  `restored_checkpoint_suffix_unavailable_k0`: the suffix feed it named now
  exists, and a checkpoint without a boundary row is refused as
  `restored_checkpoint_hidden_absent_k0` instead.
- `hipengine/generation/qwen35_gguf.py`: `prefill_claim_available` and
  `prefill_needs_activation` treat a restorable hit row as a claiming row, the
  streaming selection includes it, and `_prefill_native_chunk`'s batched
  reused-suffix route opens the sink before the first suffix chunk, feeds every
  segment at its suffix-relative offset with `finish_target_hidden_sinks=False`
  (a segment does not own the sink's timeline), and commits it once the prompt
  is complete. A row with no usable checkpoint keeps the `prefix_reuse_k0`
  refusal and the autoregressive fallback.
- `hipengine/runtime/qwen35_gguf_mtp.py`: the finish-failure trace was added and
  removed again while localizing the packed-route finish (see Validation).
- Tests: the restored-priming-source cases in
  `tests/test_unit_qwen35_gguf_mtp2_seam.py` now cover a priming checkpoint and
  one without a boundary row; two runner doubles gained the
  `supports_speculative_mtp` / `model_plugin` attributes the adapter probe
  reads.

## Validation

- Live, dense 27B Q4_K_M on gfx1151 (Radeon Pro W7900 is the default target;
  this lane is gfx1151), c=1, `--prefix-cache radix`, 2 ShareGPT conversations
  x 2 turns, `--min-prompt-len 300 --max-prompt-len 600 --output-len 64
  --seed 4242 --route-mix on`, `scripts/sharegpt_mtp_routing_pass.py` against a
  `hipengine.server` with `--speculative-mtp-serving enabled
  --speculative-candidate-budget 3`:
  - miss row 1: `prefix_reused_tokens=0`, `effective_route=speculative_mtp`,
    `draft_cycles=24`, `accepted_draft_tokens=39`, `ttft_ms=5236`,
    `itl_median_ms=39.9`, `e2e_ms=7708`.
  - hit row 2: `prefix_reused_tokens=256`, `effective_route=speculative_mtp`,
    `draft_cycles=24`, `accepted_draft_tokens=39`, `ttft_ms=1217`,
    `itl_median_ms=41.1`, `e2e_ms=3767`, `provider_state_present=true`,
    `provider_readiness=ready`, `unexplained_mtp_output_tokens=0`,
    `reconciled=true`.
  - hit row 4: `prefix_reused_tokens=256`, `draft_cycles=20`,
    `accepted_draft_tokens=42`, `ttft_ms=1208`, `itl_median_ms=34.9`,
    `e2e_ms=3371`.
  - Before this change, on the same protocol, both hit rows reported
    `mtp_used=false`, `draft_cycles=0`, `fallback_reason=prefix_reuse_k0`,
    `e2e_ms=6168` and `6156`.
- Same-protocol autoregressive control on the same server and seed
  (`--route-mix off --speculative-mtp off`, MTP still enabled server-side so the
  requests are accepted): hit rows measure `itl_median_ms` 82.62 / 82.57 and
  `e2e_ms` 6134 / 6137 against the drafted 41.13 / 34.88 and 3767 / 3371, and
  their `output_sha256` values are **identical** to the drafted run's on both
  conversations, so the hit rows' output is unchanged by drafting. The miss
  rows differ in one token between the arms; this change alters no miss-row
  route (the sink priming that distinguishes the arms predates it), so that is
  the pre-existing MTP-vs-AR prefill-route variance and is recorded as such in
  the artifact rather than claimed away.
- Rollup: `benchmarks/results/2026-09-20-gfx1151-qwen38-prefix-hit-mtp-restore.json`,
  a `benchmarks/CHANGELOG.md` entry, and the `benchmarks/README.md`
  current-state paragraph corrected (it claimed warm prefix hits use no MTP).
- The first two attempts at this wiring failed the same way and are worth
  recording because the fix was not where it looked: the sink's own
  `finish` raised `streaming NextN prompt sink finished before every row was
  consumed`, and the caller was not the segment loop but
  `_consume_packed_target_hidden_sinks` inside `_prefill_batch_native_impl`,
  which finishes a sink through its `finish_target_hidden_sinks` flag
  (default true) with `total_rows=sink.total_rows`. Instrumenting the raise
  named it in one run. Suffix segments now pass
  `finish_target_hidden_sinks=False` and the adapter closes the sink.
- `uv run --no-sync python -m pytest -q` (reviewed unit tier): exit 0.
- `pytest -k "mtp or prefix"`: exit 0.
