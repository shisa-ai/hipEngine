# Apples-to-apples old-protocol p512/d128 c1/c8 comparison

## Summary

Ran the current Generation-2 engine under the exact retained old-design protocol (p512/d128, SSE streaming-primary, 20 ms generation batch window, 256 prefill chunk, ctx 1024, 1 warmup + 3 measured, independent c1 oracles, W7900 pinned to device 0) to produce a clean old-vs-new performance comparison. This directly answers "how does concurrency2 compare to the old implementation?"

## Validation

Same protocol, same model, same GPU (W7900 device 0):

| c | Current G2 (SSE median) | Old G1 (SSE) | Ratio |
| ---: | ---: | ---: | ---: |
| 1 | 76.371 tok/s | 72.169 tok/s | **1.058x** |
| 8 | 47.239 tok/s | 158.542 tok/s | **0.298x** |

- c1: Generation-2 is ~5.8% faster — the cleanest apples-to-apples point; blocking wall 76.707, streaming 76.371; 3/3 exact; TTFT p95 0.252 s, ITL p99 17.6 ms.
- c8: Generation-2 is ~70% slower **entirely because of the physical-c2 shared-slot cap**: logical c8 lowers to c2 groups, whereas the old design ran one physical c8 (158.5 tok/s). Warmup 8/8, measured 24/24 exact; streaming passed.
- The c8 delta is a physical-width-composition effect, not a kernel regression (different source commits: current ad030591 vs old 2a1fafb8).

Open issue found: the c8 live-admission sub-gate (new-harness join-after-N-decode protocol, which differs from the old live test) failed — all 8 join requests hit a **server-side request-cancellation (HTTP 499)** after ~86-93 of 128 tokens (`finish_reason=error`), `observed_active_rows=[0,1]`. This is not part of the old/new apples-to-apples scope but is a real G2 open issue to investigate separately.
