# Fix Qwen3.5-family XML tool-call serving drop

## Summary

The OpenAI-compatible server dropped the entire generated output for
Qwen3.5-family models (Qwen3.5/Qwen3.6/PARO; same template lineage as
Qwen3.8-Flash-Next "qwen4exp") whenever the model answered a tools request
with its trained tool-call envelope: the response surfaced
`content: ""`, no `tool_calls`, no `reasoning_content`, `finish_reason: stop`.
Root cause was a format mismatch between the server's generic Qwen adapter
and the checkpoint family: hipEngine prompted for and parsed only the legacy
`<tool_call>{"name":...,"arguments":{...}}</tool_call>` JSON body, while the
Qwen3.5-and-later chat template trains the XML function envelope
`<tool_call>\n<function=name>\n<parameter=k>\nvalue\n</parameter>\n</function>\n</tool_call>`.
When the model emitted the trained envelope, `_parse_chat_tool_calls` lifted
nothing, `_validate_chat_tool_result` flagged the block unparseable, and
`_tool_validation_failure` replaced the parsed output with empty text — the
fail-closed zeroing produced exactly the observed empty message with
`finish=stop` (the tool-eval-bench "did not route" failures; 14-token
thinking-off and 63-token thinking-on repro shapes).

## Changes

- `hipengine/server/api.py` `_parsed_tool_call_from_block_body` now lifts the
  XML function envelope after the JSON body and duplicate-start-repair
  attempts; `tools` is threaded through `_valid_tool_call_blocks`,
  `_find_valid_tool_call_block`, `_parse_chat_tool_calls`,
  `_parse_chat_tool_calls_for_engine`, and the validation scanners so
  schema-typed argument decoding reaches the envelope parser.
- New helpers `_parsed_tool_call_from_function_xml`, `_xml_parameter_value`,
  `_xml_parameter_is_string_typed`, `_tool_parameter_property_schema`, and
  `_json_schema_resolves_to_string` follow llama.cpp's Qwen3-Coder-family
  parser semantics (`common/chat.cpp` qwen3-coder handler): string-typed
  parameters stay verbatim including multi-line values; other parameters
  decode as JSON and fall back to the raw string; parameters may appear in
  any order; non-parameter residue inside the envelope fails closed.
- `_render_tools_prompt` now mirrors the checkpoint template's tools block
  (the `# Tools` / `<tools>` / `<function=example_function_name>` instruction)
  instead of instructing the legacy JSON envelope, keeping the tool_choice
  directive line.
- `_render_tool_call_for_prompt` renders assistant-history tool calls in the
  family XML format (string arguments verbatim, non-string compact JSON), and
  `render_chat_prompt` joins content and calls with the template's
  `\n\n`/`\n` separators.
- Capability descriptor: `format` is now
  `qwen_tool_call_xml_with_json_fallback` and the compatibility repairs list
  gained `qwen35_family_xml_function_envelope` and `legacy_json_tool_call_body`.
- `docs/REFACTOR.md` records the three deliberately deferred follow-ups
  (required/function forced JSON prefix, XML truncated-call close repair,
  consecutive tool-response merging).
