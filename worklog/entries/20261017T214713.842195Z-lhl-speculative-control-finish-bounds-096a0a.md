# Preserve semantic speculative finishes at the output bound

## Summary

EngineService's generic speculative length normalization overwrote a provider's
grammar-complete `stop` and `thinking_budget_exhausted` when the terminal token
landed exactly on `max_tokens`. Preserve these semantic finishes when the
corresponding request control is active, IDs are unchanged, and length is the
only boundary detected by generic trimming.

## Changes

- Scope preservation to active grammar with a no-stop-sequence `stop`, or an
  active hard-thinking cap with `thinking_budget_exhausted`. Ordinary stop,
  EOS policy conflicts and over-budget providers still use generic normalization.
- Preserve all provider finish metadata, visible text/logprobs and committed IDs
  on the semantic-boundary path. No scheduler, kernel or API admission change.
