# SessionResult reports why generation ended

## Summary

`SessionResult` carried `ids`, `chunks` and `trace`, so a caller could not tell a
complete utterance from one the token budget cut off. That is the difference
between "the model finished the sentence" and "the model was still talking when
we stopped it", and the quality suite needs it to score missing speech. It now
carries `finish_reason`, using the engine-wide vocabulary already defined in
`hipengine/generation/finish.py`: `"stop"` for a stop token, `"length"` for an
exhausted budget. `FINISH_STOP` and `FINISH_LENGTH` are module constants so
callers do not spell the strings.

The EOS token stays in `ids`, so `len(ids) - 1` is the spoken token count when
the reason is `"stop"`; the docstring says so.

## RED/GREEN

`test_finish_reason_separates_eos_from_truncation` drives the pinned chain with
recorded noise and conditions, where the oracle chain is 27 tokens and ends on
EOS:

| budget | ids | expected reason |
| --- | --- | --- |
| 27 | the oracle chain | `"stop"` |
| 26 | the oracle chain minus its EOS | `"length"` |
| 0 | `[]` | `"length"` |

Both directions are asserted so the field cannot be a constant. RED: hardcoding
`finish_reason = FINISH_STOP` fails the budget-26 case with "a budget that stops
one token before EOS must not report a stop".

## Note on the derivation

The reason is derived from the last token rather than from a break flag. Those
are equivalent here, because the loop appends a token and then breaks on EOS in
the same iteration, so a chain whose EOS lands on its last allowed token still
breaks. Deriving it from the token is the version that stays correct if the loop
is ever restructured to check EOS at the top.

## Changes

- `hipengine/runtime/vibevoice_tts_session.py`: `FINISH_STOP` / `FINISH_LENGTH`,
  a required `finish_reason` field on `SessionResult`, and the derivation at the
  end of `generate`.
- `tests/test_live_vibevoice_tts_session_gpu.py`: the new test.
