# Measure DMS INT8 near-limit fit with whole-card accounting

## Summary

Measure closer to the XTX card limit, as requested. DMS INT8 C1 passes 72,960
prompt tokens plus eight decode appends at 23.893085 GiB sampled whole-card
peak and 23.125341 GiB tracked peak. Sampled headroom is 93.480469 MiB.
This is approximately the requested 23.9 GiB, but misses that literal target
by 7.080469 MiB; do not claim 23.9+. Stop rather than add more multi-minute
prefills for that small difference. No maximum or serving promotion is claimed.

## Validation

- Hardware: epyc / Ryzen 5950X, GPU1 RX 7900 XTX gfx1100, PCI
  0000:10:00.0, unique ID cc4d02090dc9c3ff, 25,753,026,560 bytes total.
  GPU0 was used independently by another worker and was not touched.
  HIP availability and rocm-smi identity/memory/use were checked; every
  failed child returned GPU1 to baseline before the next attempt.
- Commands: `.venv/bin/python /tmp/xtx-capacity/run_dms_edge.py T` for
  T=83968,82944,81920,77824,65536,72704,72960 in that order.
  Each wrapper launches the existing qwen38_dms_concurrency_probe.py with
  HIP_VISIBLE_DEVICES=1 GPU_MAX_HW_QUEUES=1 OPENBLAS_NUM_THREADS=1
  PYTHONUNBUFFERED=1, --sessions 1 --decode-steps 8 --refill-cycles 1
  --codec int8_evaluation --backend hip_gfx1100 and the same exact model,
  metadata and manifest as the bounded merge gate. Full executable commands
  and wrapper source are in the artifact. No --verify-c1 in these probes.
- First four points OOM after prefill, while constructing compact V payloads
  in DMSDevicePayloadStore.__init__. HIP error 2, not a timeout or invalid
  argument. Failed sampled peaks are 23.940395 / 23.967308 / 23.945831 /
  23.951675 GiB respectively. They are not successful capacity results.
- The initial estimate used tracked-byte scaling and was too optimistic.
  The required 64K whole-card control passes at 23.377312 GiB versus the
  identical prior tracked peak of 24,200,876,888 bytes. Its eight logit
  SHA256 values and prompt fingerprint match the earlier independent-replay
  run exactly. Future edge work should start with whole-card controls;
  OOM after a full prefill costs about five minutes per attempt.
- 72,704 passes at 23.892929 GiB sampled / 23.105115 GiB tracked.
  A final 256-token increment to 72,960 also passes, but sampled peak stays
  effectively flat: 25,655,005,184 bytes (23.893085 GiB), versus tracked
  24,830,645,644 bytes (23.125341 GiB). Both complete all eight finite
  decode transitions, have no cycle errors and drain tracked allocations
  to zero. No exact replay/teacher gate is newly asserted at these sizes.
- Sampling interval 20 ms; maximum observed gaps are about 21 ms. Failed
  peaks describe usage before allocation failure, not required peak memory.
  Physical end-state returns within the wrapper's baseline+16 MiB bound.
  Same-process OOM recovery and long-output stability are unqualified.
- `python3 /tmp/xtx-capacity/publish_dms_edge.py` validates raw hashes,
  source identity, all eight finite decode rows, clean drain and the
  64K comparison before emitting the artifact. Requested-peak attainment
  is explicitly false; the actual near-limit result is not rounded upward
  into a passing literal threshold.
- Publication validation: benchmark README tests, sync --check, worklog
  check and git diff --check. No broad test suite or numerical rerun for
  this measurement/documentation-only unit.
