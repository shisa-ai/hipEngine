# Muse Glimmer vision stack: oracle, CPU reference, GPU runner, multimodal surface

## Summary

P2 vision stack implemented and oracle-validated: mmproj graph decoded from
llama.cpp mtmd, exact-arithmetic oracle captured (F32-dequantized mmproj,
flash attention disabled, f32 cuBLAS), NumPy reference + GPU runner (FP32
primitives + rocBLAS) gated against it, and the public multimodal surface
wired through the generator with pre-norm embedding-row overrides.

## Changes

- `scripts/muse_glimmer_vision_oracle.cpp`: capture tool linking the peer
  llama.cpp build; dumps projected rows + named graph nodes; GLIMMER_CPU and
  GLIMMER_DUMP_TENSORS modes; flash attention disabled for the semantic oracle.
- `fixtures/muse_glimmer/images/`: 3 deterministic fixtures (896², 448²,
  672×448 non-square), all grid-aligned (no resize confound).

- Tests: 11 hermetic units; live CPU-reference and GPU tiers (3 images each).

## Validation

- **Precision investigation**: default llama.cpp RDNA3 computes Q4_K via MMQ
  (int8 activations, all batch sizes), CPU via Q8_K, plus flash attention —
  none is a semantics oracle (diverges ~50% by layer 49). hipEngine dequant
  verified bit-exact vs ggml's F32 conversion; `llama-quantize ... F32`
  produced the exact-arithmetic oracle source.
- **Semantics confirmed by bisection**: injecting the oracle's pre_ln into
  the GPU runner makes the full downstream tower agree to 0.004 max err;
  every graph stage matches to f32 rounding in direct comparison.
- **Amplification pinned**: the residual upstream difference is zero-mean
  f32 noise (std 6e-4); random noise of the same std injected into the
  oracle's own pre_ln reproduces the output spread (2.9–14.9 vs our 14.4 on
  the smooth 896² gradient). Gates are distributional: cosine ≥ 0.998,
  mean/std drift ≤ 0.01, catastrophic max-err bound 25.
- GPU tier: 3/3 images pass (shapes max err 0.023, blocks 0.125/cosine≈1.0,
  gradient 14.4/cosine 0.9985 with mean drift 4e-6). 11 unit tests green.
  CPU-reference tier: 3/3 pass under the same distributional gates.
- Token placement verified vs oracle chunks: [BOS, text…, 200080] + n_out +
  [200081]; tokenizer encodes the special span exactly.
- **Image-conditioned generation sanity vs llama.cpp (product gate): 3/3
  consistent.** Both engines describe the fixtures accurately: shapes — red
  square upper-left, blue oval right-lower, green diagonal (near-identical
  wording); blocks — purple/green/blue/pink/brown mosaic grid; gradient —
  dark-green top-left to pink top-right, bright green bottom-left. Reached
  through `hipengine.LLM(vision_model=mmproj).generate_multimodal_detailed()`
  (greedy, prompt_tokens 264/392/1032 = text + n_out + markers). llama.cpp
  side: llama-mtmd-cli --jinja (the legacy template handler crashes on ATEM;
  --jinja renders it), production quantized config. Bring-up latency is
  dominated by the unoptimized text prefill (decode-shaped raw-Q4_K kernels
  at rows>1) — campaign P4 / task #7 owns speed.
