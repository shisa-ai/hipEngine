# c8 iter45: q6 head chunk-shape leaf screen closed (col8 is the roofline shape)

## Summary

Follow-up to the iter44 retained Q6 head-rowtile route (+5.71% e2e): screened
the remaining shapes that could eliminate the col8 kernel's 2× tile-split
traffic (each 8-row chunk reads 2×1,042.9 MB because 16 output columns do not
fit per-CTA accumulators at full occupancy). All alternatives measured slower;
the col8 shape is the DRAM-roofline-optimal form for the planar-Q6 lm-head
path. C8-P4 exit criterion (measured bandwidth/reuse floor) is now met.

## Changes

- No tree changes; all scratch kernels built and screened under /tmp/q6rt8/
  (hipcc gfx1100, leaf-screen protocol, bit-identity vs the registered leaf
  verified per variant before timing).
- 16-col single-read ROW_TILE=8 clone of the plain T16 kernel:
  `__launch_bounds__(128,2)` → 349 GB/s (0.82× vs col8 2.496-2.607 ms);
  `(128,3)` → 335 GB/s (0.81×). Both bit-identical. The 128-VGPR accumulator
  floor persists at 3 CTAs/CU (spills); latency-hiding stays below the DRAM
  demand curve.
- col8 occupancy bump `(128,4)→(128,8)`: 1.02× (2.646 vs 2.690 ms) — noise;
  4 CTAs/CU already saturates DRAM (col8 uses 64 VGPRs).
- Chunk-interleaved single launch (chunk = fast grid dimension so the 5
  verify-chunk CTAs of one out_group are co-resident and share tile fetches
  through L2/IC): 0.36-0.73× (rows=40: 18.8 vs 13.8 ms). Same total DRAM
  bytes, L2 thrash from the 5 temporally-offset readers of each 3,360 B tile.
  Bit-identical at full-chunk shapes (rows 40/16); the rows 33/9 "mismatch"
  was an unwritten reference tail in the A/B harness, not a kernel defect.
- Verify-head DRAM-roofline confirmation: 5 sequential chunks × 2×1,042.9 MB
  at ~790 GB/s effective = ~96% of the 819 GB/s W7900 peak. The 2× split is
  structural; no co-residency scheme recovers it.
