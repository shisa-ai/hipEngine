# Resolve GPU telemetry from the active ROCm environment only

## Summary

ROCm 10.1.0 removed ROCm SMI from the standard build, so 18 hipEngine scripts
that called `rocm-smi` for GPU identity and memory provenance would either fail
or, worse, silently run a `rocm-smi` from a system ROCm 7.2.3 install that
happens to sit on `PATH`. That second case is the dangerous one: it succeeds and
records tool identity belonging to a different software stack.

All call sites now go through `scripts/gpu_smi.py`, which resolves the tool from
the active ROCm root only. It prefers `amd-smi`, falls back to `rocm-smi` for
stacks that predate the removal, and refuses a tool found on `PATH` rather than
borrowing another environment's binary.

## Changes

- `scripts/gpu_smi.py` (new): `active_rocm_root` (declared `ROCM_PATH`/`ROCM_HOME`,
  else `python -m rocm_sdk path --root` from the running interpreter),
  `resolve_gpu_tool`, `try_resolve_gpu_tool`, `command_argv`, `command_line`,
  `capture_text`, and normalized `device_identity` / `product_name` /
  `memory_usage` / `metrics` accessors that return one shape for either tool.
- Migrated 18 scripts: `qwen35_batch_serial_bench`, `qwen35_paro_bench`,
  `qwen35_batch_retained_bench`, `maple_batch_decode_bench`, `maple_c1_bench`,
  `maple_prefill_bench`, `maple_public_batch_bench`, `server_f1_concurrency_bench`,
  `qwen38_int8_server_context_soak`, `qwen38_int8_batch_decode_gate`,
  `qwen38_int8_batch_decode_ownership_trace`, `gemma4_campaign_bench`,
  `gemma4_scoreboard_snapshot`, `gguf_pack8_dual_wmma_row_microbench`,
  `gguf_c1_decode_attribution`, `gguf_server_cwidth_probe`,
  `laguna_poolside_prefill_control`, `benchmarks/micro/collect_env.py`.
- `scripts/qwen35_batch_artifact_schema.py`: accepts either telemetry invocation
  in `commands.environment` and validates command fragments against the tool the
  capture record names. A record with no `tool` field is read as `rocm-smi`,
  which is what produced it.
- `docs/reference/THEROCK.md`: the per-call-site table is replaced by the
  resolution contract, including the refusal rule and how to clear it.
- Tests: new `tests/test_unit_gpu_smi.py` (17 cases) and
  `tests/test_unit_batch_artifact_schema_telemetry.py` (5 cases); updated the
  C-width probe, scoreboard snapshot, and schema tests whose seams moved.

## Validation

- `tests/test_unit_gpu_smi.py` — 17 passed. Covers amd-smi preference, rocm-smi
  fallback, refusal of a `PATH`-only binary while it is present and executable,
  and cross-tool normalization of identity, VRAM, clocks, power, and temperature.
- Targeted suite over every file that touches a migrated script — 288 passed
  (plus 2 rewritten C-width cases) after the seam updates.
- Live on the ROCm 10.1.0 prefix, `benchmarks/micro/collect_env.py` recorded all
  four telemetry probes resolving to
  `<prefix>/_rocm_sdk_devel/bin/amd-smi`, not `/opt/rocm`.
- Live refusal check: with `ROCM_PATH` pointed at an empty root and
  `/opt/rocm/bin` on `PATH`, resolution raised `GpuToolUnavailable` naming
  `<root>/bin/amd-smi` and `<root>/bin/rocm-smi` instead of using the system
  binary that was present and working.
- Cross-tool agreement: `memory_usage()` returned `vram_total_bytes = 536870912`
  from amd-smi, byte-identical to the `rocm-smi --showmeminfo vram --json` value
  captured from the 10.0.0 backup prefix.
- `python3 scripts/docs/check_all.py` — all 4 gates passed.
- Full default suite: **13,572 tests, 13,465 passed, 92 skipped, 15 failed**. The
  15 failures are identical, by name, to a clean `HEAD` checkout run in the same
  environment (`test_unit_grammar_masks` 7, `test_unit_yue2_protocol` 5,
  `test_unit_build` 1, `test_unit_smoke_add_plan` 1,
  `test_unit_yue2_ar_runtime` 1); none are attributable to this change.
- Schema backward compatibility: the pre-change and post-change validators were
  run side by side over every artifact in `benchmarks/results/` — 7,156 payloads,
  **0 outcome differences** (167 validate as c>N artifacts both before and after).

Fixtures in the new tests are real captured output from `amd-smi` 27.1.0 (ROCm
10.1.0) and `rocm-smi` 4.0.0 (the preserved 10.0.0 prefix), not invented shapes.

A note on running this suite: stripping `HIP_PATH`/`HIP_CLANG_PATH` to get a
"clean" environment makes hipEngine fall back to `/opt/rocm/lib/llvm/bin/clang++`
(the system ROCm 7.2.3) and breaks 25 YuE2 kernel tests. That fallback is the
same cross-environment leak this change fixes for telemetry, and it is why the
`THEROCK.md` clean-process wrapper sets `HIP_PATH` and `ROCM_PATH` explicitly.
The suite must run with those variables present.

## Next

- Artifact fields keep their historical `rocm_smi` key while the record's `tool`
  field names the CLI. Renaming the key to `gpu_telemetry` would be cleaner but
  makes old and new artifacts structurally incompatible; it was left alone
  deliberately.
- `qwen38_int8_server_context_soak` maps `--showpids --showuse --showmemuse` to
  `amd-smi process`, which covers process and per-process memory but not GPU
  utilization. Utilization is available from `gpu_smi.metrics()` if that field
  needs to be equivalent rather than indicative.
