# W7900: the ROCTX blocker on eight wrappers was a search-path artifact, not a missing SDK

## Summary

`docs/KERNELS.md` trap 1 says the self-contained rocprof wrappers cannot run on this host because
"no such library is installed anywhere here", citing a `find` over the project venv, `/opt/rocm*` and
`/usr/lib`. That claim is retracted. **Twelve copies of `librocprofiler-sdk-roctx.so.1` exist**, all
under `~/mambaforge/envs/*/lib/python3.12/site-packages/` in `_rocm_sdk_core/lib` and
`_rocm_sdk_devel/lib`, in the `therock` and `vllm` envs. The original search never looked in
`~/mambaforge`, which is exactly where the ROCm SDK pip packages live on this host and where the
`rocprofv3` binary itself comes from.

This is not pedantry: eight wrappers (`gguf_mtp_verifier_rocprof.py`, `gguf_decode_rocprof.py`,
`gguf_packed_ar_rocprof.py`, `gguf_mtp_draft_rocprof.py`, `gguf_continuous_owner_rocprof.py`,
`gguf_sh_c0_profile.py`, `qwen35_rocprof_audit.py`, `mtp_verifier_rocprof.py`) were written off as
unusable on this host, and task #10's block-row sweep is blocked behind them.

## Changes

Corrected trap 1 in place (it is a claim about the host, not an immutable record) and recorded the
mechanism. No code change: the one-line default fix is stated below for whoever takes it.

## Validation

`_default_roctx_sdk()` builds every candidate from `sys.prefix`. The wrappers are run as
`.venv/bin/python`, so the prefix is `/home/lhl/hipEngine-main/.venv`, whose
`lib/python3.12/site-packages/_rocm_sdk_core/lib` **does not exist** (directory missing, not just the
file). Meanwhile `shutil.which('rocprofv3')` resolves to
`/home/lhl/mambaforge/envs/therock/bin/rocprofv3`, and the same install ships:

```
/home/lhl/mambaforge/envs/therock/lib/python3.12/site-packages/_rocm_sdk_core/lib/librocprofiler-sdk-roctx.so.1  (879137 bytes)
/home/lhl/mambaforge/envs/therock/lib/python3.12/site-packages/_rocm_sdk_devel/lib/librocprofiler-sdk-roctx.so.1.3.2
```

plus the same pair under `envs/vllm`. Passing the therock core path to the helper no longer raises:
`_prepare_roctx_override(<that path>)` returns `/tmp/hipengine-roctx-sdk-override-gguf-mtp`. Proven in
plain Python with no GPU touched. **Not** yet proven: that marker tracing then produces valid
`roctx` markers through a real `rocprofv3` session - that needs one short arm, warmed first so the
profiled process does not spawn `hipcc`/`clang` and hit trap 5.

## Next

- Task #10's blocker list shrinks from four to three: the ROCTX leg is a flag, not an install. Still
  standing: trap 4 (`block-verify` rejects its own `INT32_MAX` padding), trap 6 (`--backend` is not an
  accepted argument so a whole ladder dies on argparse), trap 2 (rocprofv3 flag forms).
- The permanent fix is a search path, not an install step: have `_default_roctx_sdk` also probe the
  prefix of `shutil.which('rocprofv3')` next to `sys.prefix`, since a host with the profiler on PATH
  almost always has the matching ROCTX library beside it.
- General lesson for "X is not installed here" claims: the negative was established by a `find` with
  a hand-written list of roots. When the claim is about a tool, search from the tool - start at the
  directory containing the binary that needs the library.
