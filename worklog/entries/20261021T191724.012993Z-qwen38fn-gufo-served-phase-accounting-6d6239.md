# Expose request-owned Flash-Next serving phase intervals

## Summary

Flash-Next serving now records request-owned backend phase intervals for
prepared-session and cached-prefix benchmark accounting. These are wall
intervals that include scheduler waits, not sums of GPU kernel time. The change
adds diagnostics without changing model arithmetic or route selection.

## Changes

- Track first suffix-prefill entry and completion after target/draft catch-up,
  prefix capture and batch-state import. Resumable work keeps its original
  start time across scheduler visits.
- End decode at terminal publication and freeze that endpoint, so later
  reclamation does not extend the measurement. Preserve the existing route,
  speculative and prefix-cache metadata in blocking and streaming responses.
- Report native prompt, cached/new prompt, generated-token and decode-transition
  counts alongside the intervals. The first generated token belongs to
  prefill; the transition count is one less than generated outputs.
- Keep cache-restore time separate. Registration-to-first-prefill and total
  backend request wall are also explicit; no tokenization or HTTP-delivery
  timing is claimed. Unstarted requests report absent phase intervals rather
  than fabricated zero-duration work.
