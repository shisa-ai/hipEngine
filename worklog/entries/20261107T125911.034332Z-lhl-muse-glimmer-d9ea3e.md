# Muse Glimmer: wide-N NaN was a loader bug; 8-wave wide tiles win

## Summary

External reviews correctly identified that the rejected wide-N experiment was
invalid: gguf_k_t16_selected_prefill.hip shared_b assigned
decode_pair = threadIdx.x >> 2 with NO stride, so 128 threads initialized only
64 weight columns; OUT_TILES >= 5 read uninitialized LDS (NaN). Fixed the
cooperative loader to stride over every column pair (decode_pair +=
WAVES_PER_BLOCK * 8). The default <3,4,4> is byte-identical (maxerr 0.0000 vs
production). With the fix, 8-wave wide tiles are a real, shape-banded win.

## Changes

- shared_b cooperative loader: if-guard -> strided for-loop covering all column
  pairs independent of compute geometry. (Experimental cfg-dispatch wrapper
  present in-tree for the sweep; integration into the production selector is
  pending rollup.)

blocks: more threads decode the slab faster + wider N cuts activation re-reads.
