# Repair Qwen streamed multibyte decoding

## Summary

Qwen AR and MTP now assemble split UTF-8 bytes before emitting text. The native
MoE route check had found streamed box-drawing characters replaced by U+FFFD
despite blocking/SSE generated-ID equality. The repair also isolates
special-token suppression by request and fixes sampled blocking responses that
concatenated individually decoded token strings.

## Changes

- Add tokenizer-owned incremental byte-BPE decoding, preserving the existing
  special-token, literal-token, vocabulary-bound, and invalid-byte policies.
- Share one decoder per request across resident AR and speculative events.
  Decoder state outlives row reclaim until final publication, then clears on
  completion, output consumption, cancellation/discard, or runner close.
- Use incremental decoding for direct generator streams too. Decode complete
  committed ID sequences for sampled blocking text; keep per-token logprob
  records and exact generated IDs unchanged.
- Preserve `ignore_eos`: a hidden EOS does not suppress later streamed text
  when the request explicitly ignores EOS.
- Add 32 regressions in `tests/test_unit_qwen35_stream_utf8.py`; update the
  existing logprob decorator double for the shared streaming helper.
- Refresh generated audit rows and re-triage the shifted bounded-cycle adapter
  guard as `NOT-DEBT`; its implementation and capability semantics did not
  change. No new flag, kernel, execution default, or README change.
