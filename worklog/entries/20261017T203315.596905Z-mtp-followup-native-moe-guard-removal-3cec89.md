# Restore native MoE verification and repair sampled graph capture

## Summary

Remove the gfx1151 MoE native-verifier containment. It was introduced after a
generated-token difference from AR and incorrectly described that difference
as a cumulative state failure. Cross-path numerical differences do not prove
wrong state ownership. This corrects the conclusions in
`20261017T161559.094347Z-mtp-repair-moe-native-state-fallback-fa8047.md` and
`20261017T162931.315903Z-mtp-validation-mtp-throughput-revalidation-d590b8.md`;
their historical measurements remain unchanged.

The corrected probes in
`benchmarks/results/2026-10-17-qwen-native-commit-attribution.json` find exact
selected source/destination copies, accepted-row and cursor ownership, and
same-schedule repeatability at the two examined prefixes. AR and serial
controls match. Native-versus-AR arithmetic differs. These local probes do not
establish whole-trajectory numerical quality; they also do not supply a reason
to prohibit the existing native implementation.

Automatic gfx1151 MoE selection still uses AR because the paired workload
recorded in the throughput entry was slower with MTP. Explicit MTP requests
remain executable and now use native verification within its context/storage
contract. This change neither adds a kernel nor promotes changed arithmetic.

## Changes

- Delete `GGUF_SPECDEC2_MOE_NATIVE_STATE_SAFE` from the gfx1151 backend package
  and its mode-selection branch in `hipengine/generation/qwen35_gguf_mtp2.py`.
- Preserve compact-DMS and context-limit handling and an explicit `serial_exact`
  request. Remove no unrelated backend limits.
- Run the prefill graph-capture hook under the staged-cycle environment. The
  live trace found `HIPENGINE_GGUF_VERIFY_CAPTURE_PREFILL_GDN=1` at replay but
  absent at capture; it was the only differing cache-key field. Graph admission
  correctly refused the mismatch. Six tests cover environment/architecture
  parity and restoration after successful or failed capture.
- Also bind target execution-profile metadata before prefill-time graph
  capture. A separate four-case CPU regression found that deferred provider
  creation can replace a captured legacy identity with the resolved manifest.
  This was not the differing field in the live failure. Tests cover strict and
  production manifest identities at resident capacities one and four.
- Correct the automatic-selection comment in `hipengine/models/qwen35.py`:
  the observed slowdown, not an asserted production-envelope failure, is the
  reason for choosing AR automatically.
- Replace containment expectations with native-route tests at several context
  positions within each backend's existing limits. The first draft incorrectly
  expected native above gfx1100's generic limit; that test assumption was
  corrected rather than changing the unrelated limit.
