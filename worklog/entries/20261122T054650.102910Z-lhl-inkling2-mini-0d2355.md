# Screen matrix-instruction tiles for packed Inkling experts

## Summary

The first grouped FP16 matrix-instruction NVFP4 leaf passed its projection checks but was slower than the four-route FP32 control in every tested Strix Halo case. Do not select it on the primary target.

## Changes

- Scratch experiment only. Read the same raw packed banks for both arms. The candidate converts the input tile to FP16, decodes a packed weight fragment in registers, accumulates with FP32 matrix instructions, and applies the existing per-route output scale. It packs up to 16 same-expert routes per tile and masks padded routes.

## Validation

- Ran `hipcc -O3 -shared -fPIC --offload-arch="$arch" /tmp/hipengine_inkling_nvfp4_wmma_trial.hip -o "$so"` and `python -u ./hipengine_inkling_nvfp4_wmma_trial.py "$backend" "$model" "$so"`. Uploaded one real 128-expert bank each for gate/up and down from W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL. Seeded routing covered 13 uniform and 64 uniform/skewed rows, eight distinct experts per input row, and uneven group tails. These are not model-captured activations or route histograms.
- The first run failed its projection comparison because the matrix instruction operands were reversed. After correcting the order, three independently decoded CPU elements per shape matched both arms under their own activation arithmetic; every compared output was finite. Relative RMS error versus the FP32 parent was about `2.08e-4` across the full outputs.
- HIP events measured four warm samples per arm, eight launches per sample, including the FP16 input conversion. At 64 uniform rows on Strix the FP32/candidate medians were 7.092/10.732 ms for gate/up and 3.648/5.072 ms for down. The candidate also lost on the 13-row and skewed Strix cases. On W7900 some 64-row cases improved, but gate/up at 13 rows regressed; no public request or promotion test was run. Raw data: `/tmp/hipengine_inkling_nvfp4_wmma_trial-w7900.jsonl`, `/tmp/hipengine_inkling_nvfp4_wmma_trial-strix.jsonl`.
