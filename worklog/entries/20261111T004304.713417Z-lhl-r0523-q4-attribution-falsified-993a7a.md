# R0523: Q4_K residual attribution falsified; race is row-1 state corruption at context 585

## Summary

R0523's c4 packed-decode race is **not** the Q4_K fused down-residual. A
forced-dispatch test initially looked clean (0/30) after capping Q4_K residual
fusion at rows 3, but the 60-repeat clearing burst **still diverged (2/60)**, so
that attribution is falsified and the cap was reverted. The divergence is a large
token flip (6866 vs 3154), i.e. state corruption rather than rounding drift, and
concentrates on **row 1 at decode position 73 (context 512+73=585)**. This points
at graph-replay state/KV ownership, not the down-residual arithmetic.

## Changes

- None landed. The temporary `GGUF_LINEAR_RESIDUAL_MAX_ROWS_BY_QUANT["gguf_q4_k_t16_v1"]`
  4→3 diagnostic and its test edit were **reverted** (`git restore`); tree is back

## Validation

W7900 GPU0 (gfx1100), hermetic TheRock env, dense Qwen3.8-27B-Q4_K_M, BF16 KV,
greedy, strict, native packed route; prompt_length 512, decode 128.

- c4 + Q4_K-residual-cap-3 (all-split, rocprof-verified no `rowtile_residual`):
  first 30 repeats byte-clean, then the 60-repeat clearing burst hit **2
  divergences, both row 1 / pos 73 / 6866 vs 3154**
  (`r0523-c4-fix-clear60.json`). The earlier 0/30 was a false-clean at the ~4%
  race rate ((0.96)^30 ≈ 29%).
- Therefore the Q4_K row-4 fused residual is **not** the (sole) cause; do not
  re-try that cap as the fix. c5 all-split 0/30 is likewise not a clearance.
- Kernel inspection (col8 ROW_TILE4, q4_k rowtile_residual ROW_TILE4, bf16_add,
  attention/GDN reductions) found no arithmetic race; all are barriered /
  fixed-order / single-wave.
