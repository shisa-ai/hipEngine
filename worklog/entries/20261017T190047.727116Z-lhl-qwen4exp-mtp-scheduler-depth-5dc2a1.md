# Honor scheduler MTP depth and provider-synchronized K0

## Summary

The cooperative provider iterator now accepts a scheduler-selected candidate
budget through `send(k)`. Zero performs one target-only step and synchronizes
the draft cursor without proposing tokens. Ordinary direct consumers still use
`next()` and the original configured budget.

## Changes

- Validate the selected budget before draft/target work; reject negative depth
  or depth above the configured provider limit.
- For K0, consume the current root in the draft without running its head, then
  perform one target step and carry forward its hidden seed. Check cursor
  alignment, EOS and output room. This keeps later positive-depth cycles valid.
- Report K0 target/catchup phases separately; do not count K0 as an MTP proposal,
  acceptance or verifier cycle. The scheduler must own rollback around a step.
