# Retain SPECDEC2 P7 provider root snapshots

## Summary

Implemented the P7 conditional physical-provider repair candidate for strict
gfx1151 C2/C4. Persistent request-slot storage now captures Conv/GDN state and
the logical cursor immediately after each proposal root. Reject restores that
snapshot, accepted `K-1` publishes the already-current proposal state without
replay, full acceptance advances only the last candidate, and all other depths
retain checkpoint restore/replay. The change is T0: provider arithmetic and the
strict fallback are unchanged.

## Changes

- Added persistent max-capacity root-state buffers to the NextN executor,
  included them in executor ownership/teardown, and invalidated request metadata
  on reset/release.
- Captured slot-major state plus position/context metadata after proposal depth
  zero, and added exact device-to-device restore with cursor restoration.
- Specialized physical device repair for reject and accepted `K-1`; retained
  checkpoint replay for unsupported partial depths and the existing last-row
  advance for full acceptance.
- Added fake-runtime state/cursor copy coverage and a repair state-machine RED
  contract spanning full, `K-1`, and reject rows.
