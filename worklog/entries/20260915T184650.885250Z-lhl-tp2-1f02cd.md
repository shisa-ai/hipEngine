# tp2 device-side exchange: graph-internal lockstep reduction, -9.4% decode p50

## Summary

The graphed schedule's remaining host bubble was the per-layer exchange: each
layer synced both rank streams so the host could sum the down partials. This
unit moves the whole exchange inside the captured graphs
(`reduce_mode="device"`, now the graphed default; `"host"` is the explicit
opt-out and the eager schedule's reducer).

Mechanism (`hipengine/distributed/device_exchange_host.cpp` +
`device_exchange_compiled.py`): each rank owns one host-mapped staging slot
per layer and one host-mapped flag per slot. Per (layer, rank) the captured
graph records three stream-ordered operations on that rank's own stream - a
D2H memcpy node staging its bf16 partial, a publish kernel writing its
system-scope flag to the rank's device step counter, and a bounded spin-sum
kernel that waits for the OTHER rank's flag to reach this rank's counter,
then adds the other rank's staged row (read zero-copy over the bus) to its
own device partial in f32 and narrows once to bf16. Every rank publishes
before it spins, so the two ranks lockstep at every slot with no host
synchronization and no deadlock; slot reuse across steps is safe by the same
lockstep. The widen/add/narrow bit arithmetic is the boundary-cast kernel's,
so the device sum is bit-identical to the host driver's sum.

Two review findings on the first draft were fixed before any gate ran: the
draft widened bf16 bit patterns with `static_cast<float>(unsigned short)`
(integer interpretation - which the first hardware run then localized
exactly), and the spin was unbounded with a blocking sync (a missing peer
could hang the group). The landed contract: every spin is bounded
(`max_spins`, default 2,000,000 lead-thread sleeps); a stalled peer exits,
sets a device timeout flag, and the host's `wait` raises
(`spin timeout on rank N`) instead of hanging. Host-mapped device pointers
are taken per viewing device (a pointer mapped on one device is not
necessarily valid from another device's kernel).

## Changes

- `reduce_mode` knob on the session: `device` (graphed default) | `host`
  (opt-out + eager). Device requires graphed. The e2e script gained
  `--reduce-mode` and its artifact summary reports device-mode step counters
  (no host walls exist to percentile in device mode).
- New HIP-guarded tests: bit-parity of the device sum against the host
  oracle (fixture rows, both slot-reuse steps) and the spin-timeout failure
  path (one rank never publishes; wait raises, nothing hangs).
- The peer-access probe (`scripts/tp2_peer_spin_probe.py`) is kept for
  provenance; the landed design does not need device peer access at all
  (host-mapped staging works over the bus).

  schedule wiring (capture-time enqueues for prior slots, eager tail,

- HIP-guarded hardware: device-sum output bit-identical to the host sum on
  random bf16 rows (both steps); stalled-peer wait raises within the spin
  budget instead of hanging.
