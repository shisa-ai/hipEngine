# Gemma 4 model plugin and GGUF config/tensor-map loader

## Summary

Adds the Gemma 4 model plugin and the loader that turns a `gemma4` GGUF header
into a validated, per-layer tensor contract. No HIP code is involved yet; the
whole unit runs on a CPU-only host.

Two of Gemma 4's structural features cannot be read off the metadata as written,
and the loader derives both instead of trusting a scalar:

1. **The rotated span is not in the metadata.** `gemma4.rope.dimension_count` is
   `512` on global layers and `256` on sliding layers, which is the *head* width,
   not the rotated width. The GGUF carries no `partial_rotary_factor`. The
   rotated pair count is recovered by counting the finite factors in the
   `rope_freqs.weight` tensor, whose rotated prefix is `1.0` and whose unrotated
   tail is the `1e30` sentinel. `gemma4_rotated_pair_count` rejects a tensor that
   is not a finite prefix followed by the sentinel, and rejects a length that
   does not match the head half-width.
2. **The sliding pattern has two encodings.** `sliding_window_pattern` is written
   as a per-layer boolean array by current converters and as a bare stride by
   older ones. Both are accepted. The reference implementation also forces the
   last layer to full attention regardless of the pattern, which the loader
   applies after decoding either encoding.

Per-layer attention geometry is taken as a real array. Sliding layers use
`key_length_swa`/`value_length_swa` (256) with `head_count_kv` 8; global layers
use `key_length`/`value_length` (512) with `head_count_kv` 2. Global layers carry
no `attn_v.weight` at all, because `attention_k_eq_v` makes V the raw K
projection. The tensor map therefore makes `attn_v.weight` a *forbidden* name on
global layers and a *required* name on sliding layers, and both directions are
tested.

## Changes

- `hipengine/models/gemma4.py` (new): `Gemma4GGUFModel` plugin. The unfused
  layer plan puts `dense_mlp` and `selected_expert_mlp` in sequence, because
  Gemma 4 runs both branches in parallel and sums them after two separate
  post-norms rather than choosing between them.
- `hipengine/models/__init__.py`: import the plugin so registration happens.
- `hipengine/loading/gemma4_gguf.py` (new): `Gemma4GGUFConfig`,
  `Gemma4GGUFRoPEConfig`, per-layer map, `gemma4_gguf_config_from_metadata`,
  `read_gemma4_rope_freqs`, `gemma4_rotated_pair_count`,
  `required_gemma4_gguf_tensor_names`, `build_gemma4_gguf_tensor_map`, and the
  shape/type/quantized-scale validator.
- `tests/_gemma4_gguf_fixture.py` (new): a two-layer structurally real GGUF
  writer — one sliding layer, one global layer — including the `rope_freqs`
  sentinel layout and the missing `attn_v.weight`. Tests run the real
  `scan_gguf` and `build_gemma4_gguf_tensor_map` entry points against it.
- `tests/test_unit_gemma4_gguf_loader.py` (new): 21 unit tests.
