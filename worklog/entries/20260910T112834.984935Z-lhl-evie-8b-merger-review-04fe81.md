# EVIE 8B review: merger geometry RED blocks numerical diagnosis

## Summary

P1: the in-progress 8B port uses vision block MLP width 4304 for merger
fc1 output, bias, and GELU, but merger fc2 consumes rows of width 4608.
The actual cached tencent/EVIE-8B checkpoint at revision
b3cbfc6cf6bf18fe7da480eacb0f70017d666fe9 has merger fc1 weight
(4608,4608), bias (4608,), and fc2 weight (4096,4608).
4304 belongs to vision_config.intermediate_size, not the merger.
The runtime's packed output and subsequent input row boundaries disagree.
This invalidates attributing the GPU/Torch discrepancy solely to inherent
conditioning. It does not establish how much discrepancy this bug explains.

The reported fp64/fp32 divergence can indicate sensitivity, but fp64 is not
automatically mathematical truth, nor does absolute error alone establish
that useful parity is impossible. Shared FP16/FP32 implementation bugs can
pass deterministic self-consistency tests. Re-evaluate after fixing geometry.
