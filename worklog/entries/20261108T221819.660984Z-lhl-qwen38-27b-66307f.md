# DSpine clean-room implementation design + RED test plan (Qwen3.8-27B)

## Summary

Task #16. Reviewed the DSpine paper (arXiv:2609.36173v2) and the Tencent reference
source for mechanics + weight layout only (clean-room; no code vendored). Wrote
docs/reference/DSPINE-IMPLEMENTATION-DESIGN.md: an independent hipEngine design for
the DSpine parallel drafter plus a RED test plan.

Key mechanics captured: DFlash-style block-parallel backbone (fc + hidden_norm +
L block-CAUSAL full-attention layers + norm, no sliding window, no DFlash2
conv/selector); a unified transfer space (codebook C from PCA-whitened target LM
head); per-layer adjacent causal injection (RMS-read → R_l project → normalize →
packed [G_q;G_p;A] matmul → sigmoid gate → predecessor message → W_l residual
write → next norm; anchor uses sqrt(C)·C_x, position-0 message zero); and
predecessor-conditioned decoding via vocabulary-wide TG/TSV transition tables +
a parallel [n,K,K] score table walked greedily (last-write refinement). Bridge
kept BF16 (rounding-sensitive); backbone optionally INT8.

Design maps onto the DFlash2 foundation: new loading/dspine.py,
runtime/dspine.py, kernels/.../speculative/dspine.{hip,py}, generation/dspine.py,
cpu_reference/dspine.py; reuses DFlash2 dense-WMMA + the task-#7 WMMA draft
attention (adapted non-causal→block-causal) + the existing qwen35_gguf target
verify. Four-axis registry keys (dspine_injection/dspine_refine), capability-gated.
The "ReplaySSM-equivalent" is a target-verify concern (advance/rollback the
Qwen3.8-27B linear-attention state for the draft block) already handled by the
qwen35_gguf recurrent-state path — no new drafter SSM kernel.
