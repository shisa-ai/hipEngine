# Extend lifecycle oracle to one physical group

## Summary

Extended the existing independent-c1 lifecycle/state oracle to support a
single physical group. This is required on gfx1151, whose resident production
runner caps active requests at eight; the old `rows > 8` diagnostic could
never run there.

## Changes

- Accept logical widths of at least four while preserving the existing
  two-slot cancel/re-admit, compaction, token, Conv/GDN state, live-KV byte,
  ownership, and active-mask checks.
- Preserve the default 13-row cross-group protocol for backends that support
  it; callers must provide in-range cancellation slots for smaller widths.

## Validation

- RED: both the c8 support test and lower-bound test failed on the old
  greater-than-eight guard.
- GREEN: `tests/test_gguf_arbitrary_c_lifecycle.py` passes `4/4`; script
  compilation and `git diff --check` pass.
