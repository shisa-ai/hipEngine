# Measure DE-2 shared-expert decode cost by dispatch signature

## Summary

DE-2's shared-expert decode cost is now **measured at 2.0621 ms/step = 3.80% of the
54.2181 ms/step decode kernel sum**, not merely bracketed. The ledger's claim that the
name-to-kernel join is "structurally impossible" held only for the renamed X-4 export; a
**real-kernel-name twin of the same decode protocol is committed**
(`benchmarks/results/2026-09-29-qwen4exp-de1-dp4a-e2e/rocprof/e2ebase_kernel_trace.csv`,
`renamed = 0`, same 3 windows / 5,313 selected kernels). The shared expert still cannot be
split by a Python role marker, because the whole per-layer MoE is **one replayed HIP graph**
(`graph_before.capture = 48, replay = 0`; `graph_after.replay = 144`) and the nested
`launch_gguf_linear` markers never execute. The split is therefore done by **dispatch
signature** cross-checked against exact GGUF payload shapes.

## Changes

- Added `scripts/qwen4exp_de2_shared_expert_attribution.py`: reads the renamed and real-name
  decode captures, isolates the 1,749 replayed MoE-graph rows, groups by
  `(Grid_Size_X, Workgroup_Size_X, VGPR, LDS)`, resolves each signature to a real kernel name
  from the twin (restricted to graph-replayed rows with no HIP launch API row), and classifies
  against the shipped GGUF shapes. Read-only, no GPU.
- Added `tests/test_unit_qwen4exp_de2_shared_expert_attribution.py` (7 cases): signature
  classification for every MoE owner, GGUF shape cross-check rejection, window selection,
  aggregation/sum contract, marker scope/cleanup, GGUF role shapes, and an end-to-end run on
  the committed captures.
- Added `benchmarks/results/2026-10-07-qwen4exp-de2-shared-expert-attribution/` (`README.md`,
  `attribution.json`).
- Updated the DE-2 cell of `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md`.

## Validation

- `uv run pytest tests/test_unit_qwen4exp_de2_shared_expert_attribution.py -q` -> **7 passed**.
- The 24.5504 ms/step MoE family decomposes exactly; the three published self-checks
  reproduce: routed gate+up 14.0126 (vs 14.013), routed down 5.4436 (vs 5.444), shared combine
  0.0671 (vs 0.067).
- Shared expert 2.0621 ms/step sits inside DE-2's own `[1.36, 2.544]` bracket.
- No GPU run: ROCm is unavailable in this environment (`libamdhip64.so` absent, no `rocminfo`),
  so no new capture was produced; the result is derived from committed traces and the shipped
  GGUF.
