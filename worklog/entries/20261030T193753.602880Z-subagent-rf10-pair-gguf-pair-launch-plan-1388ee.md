# Separate GGUF pair launch planning from execution

## Summary

`launch_gguf_linear_pair` now resolves a private `_GGUFLinearPairPlan` and executes it immediately. The plan carries the selected operation, two exact resident weight owners, logical geometry, resolved registry key or per-side T16 keys, Q4 pack8 prefill mode, Q8T16 split mode, library-key precedence, fallback reason, and registry generation. Pointers, allocations, and registry callables are still resolved at execution.

The public signature, boolean return, dispatch/sidecar/shape priority, early declines, and kwargs shapes are unchanged. The physical-verifier Q4T16 row chunking remains the pre-plan early path; it launches singletons or recurses through the public pair launcher. There is no exported plan API, reuse cache, profile token, flag, or copy.

## Changes

- `hipengine/runtime/gguf_linear.py`
  - Added private `_GGUFPairedOperand`, `_GGUFT16PairOperand`, and `_GGUFLinearPairPlan`.
  - Added `_resolve_gguf_linear_pair_plan` and `_execute_gguf_linear_pair_plan`.
  - Execution binds the exact weight objects and rejects a foreign owner or registry-generation change before launching. No generic layout/shape/allocation revalidation framework was added.
  - Reused the existing `_PAIR_DISPATCH_RESOLVE_CACHE`; no new cache was added.
  - Preserved no-kwargs branches (`q4_raw_dual_wmma`, `q8_raw_dual`, base Q4 pack8 dual prefill), `stream`/`runtime`-only branches, and `library`-present branches including the rowtile/WMMA always-present `library=None` shape.
  - Preserved library precedence: variant key before quant key for WMMA bulk; quant key for registered pairs; no library for Q8T16 split and T16 F16/rocBLAS.
- `tests/test_unit_gguf_linear_pair_plan.py`
  - Covers a registered decode pair, exact owner rejection, Q4 pack8 prefill rowtile versus base thresholds, Q8T16 split exact versus rowtile thresholds, fallback reasons, kwargs absence, WMMA variant-library precedence, and execution-time callable/pointer resolution.
