# contain the device exchange's timeout and teardown lifecycle

## Summary

Two lifecycle holes in the device exchange, both predating the head-sharded
route, both closed here, plus the two test gaps that let them hide.

1. **A clear could erase an unobserved timeout.** `step_begin()` and
   `reset_timeouts()` both clear the per-rank spin-timeout flags, and the Python
   wrapper only poisoned the handle after a host call had observed a failure. So
   `enqueue -> reset before wait -> wait` could erase a real failure: the spin
   kernel writes nothing on timeout, which is exactly why the flags are sticky,
   and a cleared flag lets a stale output row pass as the result. The wrapper now
   refuses a clear while a submitted step is unobserved, and `wait` is what
   observes it. Enqueueing the clear is what does the damage, so the refusal
   happens before the driver call, not after.
2. **Teardown leaked the timeout flags.** Creation takes four allocations per
   rank - mapped staging arena, mapped flag array, step counter, spin-timeout
   flag - and `tp2_dev_exchange_destroy` freed the first three. Every
   create/close cycle leaked one device allocation per rank. Teardown now lives
   in the handle's destructor, which is also what makes the create function's
   nine failure paths safe: they `delete ex` exactly as `destroy` does, so a
   create that failed halfway through releases what it had already taken. Each
   pointer is appended to its vector the moment it exists (previously all four
   were appended at the end of the iteration, so a mid-iteration failure leaked
   the allocations that had just succeeded) and the destructor is idempotent.

Ownership is now observable: the driver counts the allocations it owns and
exposes the count, so "a cycle gives everything back" and "a failed create gives
everything back" are assertions rather than arguments.

## Changes

- `hipengine/distributed/device_exchange_host.cpp`: the handle owns its teardown
  through `~Tp2DeviceExchange()`, `tp2_dev_exchange_destroy` is `delete ex`, each
  allocation is tracked immediately after it succeeds, and
  `tp2_dev_exchange_live_allocations()` reports the process-wide count.
- `hipengine/distributed/device_exchange_compiled.py`: `_unobserved_steps`
  tracks submitted-and-unwaited work; `step_begin` and `reset_timeouts` refuse
  while it is non-zero; `wait` clears it. `enqueue_rank` deliberately does not
  count: a graph capture records enqueues that have not executed, so counting
  them would make the first token after a capture unable to begin.
- `tests/test_unit_distributed_device_exchange_compiled.py` (new): the wrapper's
  lifecycle against a faked driver, so it runs without a GPU. Covers the two
  refusals, that `wait` is what legalizes the next clear, both real submission
  shapes (graphed per-step, batched per-group), that capture-time enqueues do not
  block a later clear, and that a failed wait poisons without observing the step.
- `tests/test_gpu_distributed_staged_compiled.py`: the cross-layer test now bumps
  with **no further exchange**, so a clearing bump leaves nothing to set the flag
  again and the test fails; a second test completes a later layer successfully
  and requires the earlier timeout to still surface; two new tests assert the
  driver's allocation count returns to its resting value after 50 create/close
  cycles and after a create that fails on its second rank.

## Validation

- `tests/test_unit_distributed_device_exchange_compiled.py`: 9 passed.
- `tests/test_gpu_distributed_staged_compiled.py`: 11 passed, 1 skipped
  (`HIPENGINE_TP2_TEST_MODEL` not set).
- RED, unit tier: with `_refuse_unobserved_clear` neutralized, both refusal tests
  fail with `DID NOT RAISE TransportStateError`.
- RED, GPU tier: with a bump that clears (the reset enqueued right after the real
  bump), both timeout tests fail with `DID NOT RAISE`; the pre-fix teardown makes
  the two leak tests fail at `102 == 2` (50 cycles x 2 ranks) and `105 == 104`
  (one rank's flag from a failed create), i.e. exactly the leaks.
- The wider bundle (`-k "distributed or shard or gguf or exchange"`, 4000+ nodes)
  has failures only in `tests/test_unit_gguf_ud_ffn_callers.py` and
  `tests/test_unit_qwen35_gguf_prefill_scratch_liveness.py`, which fail
  identically with these changes stashed: their fixtures are `SimpleNamespace`
  objects missing runner attributes (`compiler_version`,
  `_run_post_attention_norm_residual_rows`). Not this unit's files, left alone.
