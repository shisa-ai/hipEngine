# launch_gguf_linear is bit-exact across row counts so the linear family is cleared

## Summary

`20260928T054754` localized the block-width divergence to inside layer 0 and
listed four remaining candidates, with a direct `launch_gguf_linear` probe as
the cheapest decisive one. The probe is run and the answer is negative, which is
the useful direction: the dense linear funnel is not the cause.

| comparison | relative L2 | bit-equal |
| --- | --- | --- |
| row 0, `rows=2` against a `rows=1` launch of the same input | 0.00000000 | **True** |
| row 1, `rows=2` against a `rows=1` launch of the same input | 0.00000000 | **True** |

## Method

The fixture's `token_embd.weight` is a resident Q8_0 `GGUFDeviceWeight`, the
same object type and the same quant family the layer path projects through, and
`launch_gguf_linear` is the single funnel every dense projection in the model
goes through. The probe calls it three ways on one random BF16 input tensor:
once with `rows=1` on row 0, once with `rows=2` on both rows, and once with
`rows=1` from the second row's pointer. Row 0 of the two-row launch is compared
against the one-row launch of row 0, and row 1 against the one-row launch of row
1. Both are bit-equal, so a wider launch does not change a row's result.

Q8_0 is one of the two quants `launch_gguf_linear`'s docstring names for the
`rows > 1` WMMA rewrite, so this also shows the rewrite is not firing here --
consistent with `20260928T054754`'s finding that its opt-in resolves to False
for a partial block with the env var unset.

## What is left

The candidate list from `20260928T054754`, with the linear funnel now removed:

1. **`_keep_mask`'s extra column.** A two-row block's mask has
   `start + rows - key_begin` columns against a one-row block's
   `start + 1 - key_begin`, so row 0 carries one more column than it does in the
   one-row path. Row 0's entry there must be zero; if the kernel's causal test
   is built from the block rather than the row, row 0 reads row 1's key.
2. **The attention kernel's own `rows` handling**, which is the same question
   from the kernel's side.
3. **The experts.** The fixture's expert tensors are Q4_K, a different quant
   family from the projection probe above, and the MoE entry points take
   `compact_rows` and `total_rows` that are derived from the routing. This is
   now the least-tested remaining candidate and deserves the same direct probe
   shape: one expert call at a one-row routing against a two-row routing.
4. **The layer wrapper's per-row path** for the norm and the MLP.

The single-key argument from `20260928T054754` still constrains this: row 0
reads exactly one key, so a 0.63 percent error there cannot come from a
reduction over many keys. It is consistent with one extra masked column leaking
in, and it is consistent with a wrong expert selection.
