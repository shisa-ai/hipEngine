# layer 29 is on the fast expert routes for both projections

## Summary

The Q8_0 expert down projection now has a DS4 DP4A MMQ route. Layer 29's down goes
**43.85 ms to 4.60 ms per launch, 9.5x**, and the fp32 grouped fallback disappears from the
prefill entirely — a route/quant probe over a real 512-token step shows four expert routes
and no `rows`/`grouped_*` call at all.

With the gate/up route from the previous unit, layer 29 goes from **151.6 ms to 17.97 ms per
layer-block, 8.4x**, and from 606.6 ms of the 2048-token prefill to 21.6 ms.

The loop's 512/128 prefill metric moves **0.92 s to 0.88 s (-4.3%)**, 557 to 582 tok/s. Over
this session's two units it is **1.01 s to 0.88 s, -12.9%**.

## The one subtlety, settled by probe rather than by reading

Q8_0's bytes are genuine int8 rather than Q5_1's 0..15 nibble, so the dot has to be signed
on both operands. `__builtin_amdgcn_sdot4` is not usable — the toolchain wants a
`dot1-insts` target feature that this tree's build does not pass. `sudot4` compiles, but its
two negate flags must be *constant integers*, so the choice has to be made in source. A
one-block probe settled what the flags mean: `sudot4(true, 0xFF, true, 0xFF, 0, false)`
returns **1**, which is `(-1) * (-1)`, where an unsigned first operand would return 65025.
So `sudot4(true, a, true, b, c, false)` is signed-by-signed and needs no correction term.

The same probe incidentally confirms the Q5_1 route's operand choice is safe: it passes the
same flags, and its nibbles and expanded fifth bits are non-negative, so signed and unsigned
agree there.

## Validation

- **Both quants at the real geometry**: 704 contraction by 2816 output by 8 experts, against
  an independent dequantized reference, both within the envelope the Q4_K gate/up MMQ route
  runs at (normalized max under 2e-2, mean under 2e-3 of scale).
- **Trailing-block power check**: 704 = 5 x 128 + 64, so flooring the DS4 block count drops
  the last 64 contraction columns. The test builds a second reference with those columns
  removed and asserts the route is *closer to the full one*, so it can see the failure the
  Q5_1 route already hit once. It is not vacuous.
- **Route engages in production**: a route/quant probe over a real 512-token prefill shows
  `gemma4_project_experts_down_mmq` with `quant=gguf_q8_0` returning `True` in **4.599 ms**,
  against 43.85 ms for the `rows -> grouped_prefill` fallback it replaced. No `rows` or
  `grouped_*` expert call remains in the step.
- **Loop metric**: `scripts/gemma4_campaign_bench.py --prompt 512 --output 128 --samples 3`
  gives prefill 0.88 / 0.88 / 0.88 s, median **0.88 s**, against the 0.92 s recorded best.
  Same run: decode 24.896 tok/s, path parity True.
- **Model surface**: `scripts/gemma4_real_generate.py` produces coherent text and its first
  tokens still match llama.cpp's.

## Open

Layer 29 is now 1.65x its siblings per layer-block (17.97 ms against 10.90 ms) rather than
14.1x. The residual is the route's own arithmetic, not a fallback: the Q5_K iu8 route is a
risk-and-repair route that quantizes activations to three residual planes and then re-runs
the queued outputs exactly, because its contract is bit-identity with the strict owner. The
Q4_K and Q5_1 routes use one plane and are approximate. If the Q5_K route's exactness is not
worth 7.7 ms per layer-block at 2048 tokens (0.9% of the step), a one-plane variant would
close it — but that is a contract decision, not a defect.
