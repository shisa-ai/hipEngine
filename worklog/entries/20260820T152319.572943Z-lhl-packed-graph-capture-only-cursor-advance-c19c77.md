# Fix packed graph capture-only cursor advance

## Summary

Correct the capture-only packed-graph ownership bug surfaced by the direct-c5
lifecycle. The prior blocker entry
`20260820T150624.351199Z-lhl-direct-width-c5-compaction-blocker-packed-ar-pos-bd8c95.md`
correctly blocked promotion, but its attribution to non-power-of-two widths was
too narrow. The actual trigger was graph capture followed by invalidation before
the first replay: capture imported current session state, incorrectly marked the
packed copy dirty, and compaction then scattered a singleton transition layout.
That scatter advanced each session cursor by one without a decoded token, giving
`positions (18,20,22)` versus session cursors `(19,21,23)`.

## Changes

- Preserve the packed state's pre-capture ownership in
  `capture_qwen35_gguf_packed_decode_graph`. Import-only capture no longer claims
  that a token transition ran; `Qwen35GGUFPackedDecodeGraph.replay()` remains the
  operation that marks packed state dirty.
- Add a focused RED/GREEN ownership regression in
  `tests/test_gguf_packed_decode_graph.py`. The sanity check in
  `step_batch_native` remains strict; there is no c5 special case or cursor
  resynchronization workaround.
