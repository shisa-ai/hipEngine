# the experts 1.5 percent figure is inconsistent with the memory floor and I should not have committed it unqualified

## Summary

`20260928T072450` reported `no_experts` at **1.5%** of the decode step and drew the
conclusion that the expert path is "nearly free". Checking the arms turned up two
things: one that explains an apparent anomaly, and one that undermines that figure.

## The anomaly, and its resolution

`no_all_gemv` saves **42.5%** while `no_dense_q8_both` -- which skips strictly fewer
symbols -- saves **42.9%**. Skipping more cannot save less, so one of the two arms is
not skipping what its name says.

Reading the spies:

```python
def spy_q4_k_selected(symbol, *a, **kw):
    if mode == "k_launch" and ("*" in skip or str(symbol) in skip):
        return None
    ...

def spy_selected(weight, x_ptr, selected_ptr, out_ptr, *a, **kw):
    if mode == "experts":
        return True
    ...
```

`spy_selected` intercepts **only when `mode == "experts"`**. The `no_all_gemv` arm runs
in mode `k_launch`, so it passes through and **the expert selected path is not skipped
by it**. So `no_all_gemv` means "every GEMV except the expert selected path", and 42.5%
is consistent after all. The `k_launch` hooks do cover both `gguf_k_gemv._launch` and
`gguf_q4_k_gemv._launch_selected` as its comment claims; the expert route simply lives
behind a third entry point that only the `experts` mode reaches.

That resolves the anomaly in favour of the numbers, and it also means `no_experts`
**is** measuring the expert route through its own hook.

## The figure that does not survive

**1.5% for the expert path is inconsistent with a memory floor.**

A4B activates roughly 4B parameters, most of them expert weights. At Q4_K's ~4.5 bits
per parameter that is on the order of **1.7 GB read per token**, and this part's DRAM
peak is ~256 GB/s, so the expert weights alone should cost roughly **6.6 ms** -- about
**19%** of the 35.53 ms step. Measured: **0.54 ms, 1.5%**.

Those cannot both be right. At least one of these is true and I did not determine which:

1. the `experts` hook under-intercepts, so the arm skips only part of the route;
2. the expert weights are substantially L2-resident across the two timed output
   lengths, so the marginal cost of the arm is not the full read;
3. my parameter accounting is wrong -- the artifact's expert tensors may be a smaller
   share of the active set than "A4B" suggests.

**None of these is tested.** The contradiction is recorded rather than resolved.

## What stands and what does not

**Stands:** the **dense Q8 path is ~43% of the decode step**. That comes from
`no_dense_q8_both`, which skips two **named symbols** -- the most direct measurement in
the table, with no choke-point subtleties. The redirect of decode work toward the dense
GEMV path and the `lm_head` is unaffected.

**Does not stand:** "the expert path is nearly free", and by extension any conclusion
that the expert route can be ignored. The 1.5% is a number I committed as a finding
without checking it against an independent bound. I should have done that before writing
it down, and the check is arithmetic I already had.

**Also stands:** the `no_attention` **5.8%** figure, which is the one that corrects my
earlier 19.1% claim. That arm hooks the attention entry points directly and nothing
about this affects it.
