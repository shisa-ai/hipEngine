# Repair resumed INT8 prefix attention ownership

## Summary

Following the BF16 repair in `ae8977de0`, reproduced a separate no-mirror
INT8 prefix defect: the suffix selected a newly allocated BF16 oracle whose
prefix rows were never initialized. The retained INT8 payload/scales remain
valid; the reader selected the wrong storage.

## Changes

- Resumed packed prefill without a live oracle uses retained INT8 spans and
  scales. Cold full-prompt prefill and mirror-backed sessions keep their
  existing source. Gapped resumed requests use slot-local physical page tables
  without rebasing. No kernel bodies or new environment flags.
- The multi-chunk layer-outer optimization is limited to cold starts; resumed
  chunks use the reader with initialized retained state.

## Validation

- Numerical RED: `uv run --extra dev pytest
  tests/test_unit_gguf_prefix_int8_attention_source.py -q` fails four
  contiguous/gapped and slot-local/packed cases. The selected prefix reads
  NaNs from poisoned oracle pages instead of hand-derived K/V values
  `[[2,-2],[10,6]]` from retained INT8 and FP32 scales. Eight cold/mirror
  controls pass unchanged.
- GREEN: the same test plus packed-verify layout, device-KV binding and gapped
  slot-local prefill modules pass 111 tests. A binding fixture was completed
  with its real BF16 prefill-spans field rather than weakening the runtime
  contract for incomplete fake scratch objects.
- Public pre-fix probe with an unaligned 513-token source produced no snapshot
  and correctly missed; it is not evidence of a hit or of repair. Rerunning
  with an aligned 512-token source to reach the actual suffix reader.
