# Bind strict short-context attention to its registered reference

## Summary

Fix the dense gfx1151 strict profile inheriting the production short-context
attention geometry. Strict now owns the registered fixed256 leaf; production
keeps its existing 1024-thread arithmetic. Both selections appear in their
owner's variant manifest and cannot be retargeted by an ambient environment
change.

The longer public comparison exposed the missing ownership: the first
`code_merge_intervals` difference was generated index 255, under both named
profiles. A longer output limit reproduced it, and repeated public AR agreed
with eager scalar decoding. Forcing the pre-existing 256-thread control made
public AR and MTP identical on the complete request. This is not a production
quality verdict or a throughput result.

## Changes

- Register the existing 1024-thread wrapper as a named gfx1151 variant, with
  the existing registered fixed256 leaf as strict fallback. No kernel body or
  production arithmetic changes.
- Carry the profile selection through shared and private target runners and
  sessions; reject a shared runner with a conflicting explicit owner.
- Add CPU RED/GREEN coverage for manifests, ambient isolation, construction
  order, resolver caching and shared/private transport, plus a guarded public
  long-output regression. Direct unbound controls are unchanged.
- Record the probe source, full output IDs, profile/length experiment and
  fixed-prefix logit comparisons in
  `benchmarks/results/2026-11-12-qwen38-short-attention-owner-diagnosis.json`.
  Its pre-edit process identity is explicit; source code was imported before
  the runtime edits. The source comparison's provenance identifies the model,
  quantization and physical host.
- Update the environment, profile and kernel references. The earlier
  production attention evidence is historical provenance, not a newly claimed
  Qwen3.8 qualification.
