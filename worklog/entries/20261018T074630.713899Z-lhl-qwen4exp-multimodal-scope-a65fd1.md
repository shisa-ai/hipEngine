# qualify multimodal serving and publish its scope

## Summary

The image route worked, but it was a second-class response path: it returned
the raw generated text, so a think block reached `content`, `reasoning_content`
was absent, a request `stop` string was silently ignored, `finish_details` was
missing, and `prompt_tokens` counted the unrendered user text instead of what
the model read. Nothing in `/v1/hipengine/capabilities` described the scope.

A 64x64 solid red PNG, before the fix:

```
content: " think\n\n</think>\n\nRed"   finish_details: null
```

After the fix, on the same request:

```
content hex: 0a0a526564 ("\n\nRed")
reasoning hex: 0a0a
finish_details: {"reason": "eos", "eos_token_id": 248046,
                 "sampler_mode": "greedy_multimodal_mrope",
                 "cache_action": "append_none"}
generated_token_ids: [248068, 271, 248069, 271, 5844, 248046]
```

The multimodal branch now applies `_apply_stop`, builds the message through
`_chat_message_from_parsed` with `reasoning_initially_open=False` (the
multimodal renderer ends its prompt with a bare assistant turn, so the model
emits `<think>` itself), reports `finish_details` through the shared payload
builder, and takes `prompt_tokens` from the engine's rendered prefill length.
`hipengine.generated_token_ids` travels with the answer so a vision response can
be inspected the way a text response can.

Two decoding notes that cost time and are worth keeping:

- `skip_special=True` at the emission sites is correct. `<think>` and
  `</think>` are ordinary tokens for this tokenizer, so stripping specials
  removes only template controls such as `<|im_end|>`. A blanket text-level
  strip of template markers was tried first and broke six existing residue
  tests, because the server deliberately preserves residue when reporting a
  structured-output failure; that approach was reverted.
- A tool-output display can swallow `<...>` sequences, so marker comparisons in
  this work were checked with hex dumps rather than rendered text.

## Changes

  split, `finish_details`, rendered `prompt_tokens`, `generated_token_ids`);
  `_multimodal_capability` published as `features.multimodal`.
- `hipengine/generation/qwen4_exp_gguf.py`: the multimodal generator reports
  `usage.prompt_tokens` from the rendered prompt it actually prefilled.
- `tests/test_integration_qwen4_exp_server_multimodal.py`: reasoning/finish/
  stop contract, backend length finish, and the published capability scope.
- `scripts/qwen4exp_http_multimodal_gate.py`: live gate over the vision server
  and the text-only refusal.
- `benchmarks/results/2026-10-18-zbook-qwen4exp-http-multimodal.json`:
  17 checks (10 with the sidecar, 7 without), 0 failures.
