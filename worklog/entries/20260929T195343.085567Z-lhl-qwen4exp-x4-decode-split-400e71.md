# X-4's decode device split analyzed: the MoE expert gate is 45.28%, and decode is not kernel-bound

## Summary

X-4's harness captured the decode transition and its own `decision.next` read
**"analyze marker-scoped kernel/API/role owners"**. **That analysis had never been run**, and
six `DE-*` rows are parked "after X-4" waiting for a device split to rank against.

This entry produces it: **54.218 ms/step of decode kernel time**, 1,771 kernels/step, 740
distinct roles, **100% attributed**.

## Result

| family | ms/step | share |
|---|---:|---:|
| **`moe:expert_gate`** | **24.550** | **45.28%** |
| `linear:attn_qkv` | 4.658 | 8.59% |
| `linear:root.lm_head` | 2.980 | 5.50% |
| `linear:attn_gate` | 2.890 | 5.33% |
| `linear:ssm_out` | 2.842 | 5.24% |
| `qsa_decode:attn_q` | 2.621 | 4.83% |
| `gdn:attn_qkv` | 2.401 | 4.43% |

**The MoE expert gate is 45.28%** - more than every other family combined below it, spread
over 48 layers rather than one large kernel (largest single role 0.724 ms/step, 1.33%, and
the rest cluster at 0.5-0.6, so no layer dominates). **`linear:root.lm_head` is 5.50% in a
single kernel per step** - the second largest single role is one output projection.

## Decode is not kernel-bound

Unprofiled wall for the same transition: **median 153.0 ms** (spread 1.30x, `token_exact` and
`state_exact` both true). Against 54.2 ms of kernel time that is **~35% kernel and ~65%
host/launch overhead**, with 48 graph launches carrying 1,771 kernels.

That is the number the `DE-5`/`DE-6` runtime rows were missing, and it says the runtime side
is larger than the device side for a decode step.

## Reusable method finding

The correlation-id join reached **3,516** of 5,313 kernels and missed **1,797**. **0 of the
1,797 unattributed correlation ids appear in the HIP launch trace at all** - they are replayed
from captured HIP graphs (192 `hipGraphLaunch`), so there is no launch API row to join.

The fix is **not a heuristic**: `rocprofv3 --kernel-rename` names each kernel with its
enclosing roctx region, so those kernels arrive already named
`qwen4exp_role:moe:layers.N.expert_gate`. Reading the role back out recovers an identity **the
profiler assigned**, taking attribution to 5,313 of 5,313.

**In a graph-replaying engine, role attribution must not rely on the correlation-id join
alone.**

## Validation

- `token_exact` and `state_exact` both true on the profiled run, so the transition is the
  same one the unprofiled arm measures.
- The JIT cache was warmed **outside** the profiler and the profiled run used
  `--require-cached-build` with a precomputed compiler-version file, per `AGENTS.md`.
- **100% attribution is asserted, not assumed**: the report records the split by source
  (`correlation` 3,516, `kernel_rename` 1,797, `none` 0), so a future capture that loses
  roctx coverage will show up as `none` rather than being silently absorbed.
- **The kernel/wall ratio uses the unprofiled wall**, because the profiled arm's own wall has
  a **4.12x** spread (58.9-242.7 ms) and is not usable. The unprofiled spread is 1.30x, so
  ~35% is labelled approximate.
- Limits recorded: one case, one live count, one model, one host, one profile, three
  repetitions; per-kernel times from a profiled capture are diagnostic; attribution is only
  as good as the roctx coverage.
- **No performance claim, no promotion, no default changed.** Raw rocprof dumps (37 MB) are
  not committed.
