# Qwen4Exp AR batch variant manifest binds live dispatch identities

## Summary

Added a structured batch variant manifest for the Qwen4Exp AR batch path and
made the layer-2 gate validate it instead of accepting a c1 execution-profile
manifest by name. The manifest binds the live direct callables, registry keys,
row-dependent projection dispatch keys, runner class/config, and the profile
manifest plus source revision. The validator recomputes every identity from the
current process, so a c1 manifest cannot be relabelled into a batch manifest.

No admission campaign was run. The CPU tests and one GPU dispatch smoke cover
the new wiring; the full 18-prompt admission loop remains the next step.

## Changes

- `hipengine/runtime/qwen4_exp_batch_manifest.py` (new): manifest schema,
  builder, canonical SHA-256, and live validator. Direct roles record the exact
  function identity, source hash, function hash, build identity, and optional
  registered key. Registry roles record the key and strict fallback. The
  `projection_dispatch` role records every key observed during the measured
  steps, including rows, geometry, ABI, and resolved function identity. The
  manifest reports `unbound` and `not_used` roles instead of implying them.
- `hipengine/runtime/gguf_linear.py`: added the context-local
  `record_gguf_linear_dispatch` recorder and made the dispatch cache carry the
  resolved key's backend so a record names the key that was actually resolved,
  not the runtime alias.
- `hipengine/runtime/qwen4_exp_batch_gdn.py`,
  `qwen4_exp_batch_qsa.py`, `qwen4_exp_batch_qsa_index.py`,
  `qwen4_exp_batch_ple.py`, and `qwen4_exp_batch_runner.py`: added explicit
  call tables for the callables each module imports and calls directly. The
  GDN table marks the two indexed owners as direct calls even though matching
  registry keys exist; the PLE module exposes the indexed-Conv key and its
  `strict` fallback.
- `scripts/qwen4exp_ar_batch_candidate.py`: records projection dispatch around
  every measured teacher/free step, builds the manifest from the live owner
  runner and the generator's execution-profile manifest, and exposes the
  manifest in its evidence. The old substring `batch_manifest_binding` remains
  only as a legacy test helper.
- `scripts/qwen4exp_layer2_profile_gate.py`: `_run_batch_candidate` builds the
  manifest before closing the adapter; the gate validates it with the candidate
  profile hash, source HEAD, backend, model, and quant, and passes the
  structured result to admission. Admission now uses the validator's `valid`
  field, so an invalid identity blocks admission even if a legacy `bound` flag
  is true. The artifact records `batch_variant_manifest_sha256`.
- Tests: `tests/test_unit_qwen4exp_batch_variant_manifest.py` covers real
  direct/registry bindings, a real `dense_gemv` projection key, forged direct
  and oracle identities, changed projection variants, missing step widths,
  canonical serialization, profile/source binding, and the recorder. The
  admission and adapter tests cover structured-invalid admission and the
  adapter's manifest build. `tests/test_gpu_qwen4exp_batch_runner.py` adds a
  one-step recorder smoke.
- `docs/REFACTOR.md`: tracks removal of the legacy substring binding.
