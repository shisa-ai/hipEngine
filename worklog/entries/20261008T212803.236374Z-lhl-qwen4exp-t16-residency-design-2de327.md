# T16 tile residency design: net-zero full-window materialization

## Summary

The production tile-residency design (the committed follow-on from
T16-GU/T16-DOWN): docs/QWEN4EXP-T16-RESIDENCY.md.

**The measured core fact:** the T16 tile sets are bit-lossless
rearrangements, so the tiles equal the raws exactly - gate/up 42.38
GiB (96 tensors, 48 layers), down ~26.3 GiB (43 Q5_1 layers),
combined routed experts 71.73 GiB. Materialize-and-free is therefore
NET-ZERO memory: today's sidecar keeps both resident (84.76 GiB for
gate/up alone), which is the only reason the gate/up window was
bounded at 30-of-46 layers. Freeing the raw the tiles replace gives
the full windows at exactly the model's existing footprint.

**Design decisions committed:** (1) the tiles become a binding-owned
allocation stage ("t16") instead of the module-level sidecar caches -
removing the raw-pointer keys that freed raws would invalidate and
the cross-session lifetime hazards in one move; (2) the load path
materializes tiles then frees the raw for window-selected layers
(production profile only); (3) the strict fallback contract becomes
profile-level (strict materializes raw, production materializes
tiles) plus the PLE-style lazy re-materialization escape hatch from
the on-disk GGUF; (4) full windows: 48/48 gate/up, 43/43 Q5_1 down;
(5) admission sequencing: residency alone changes no default and no
numerics - if X-7 admits the candidates, the full-window engine A/B
and layer2 gate re-run (the +6.53% gate/up figure was a 30/46-layer
window measurement; the full window's figure gets measured, not
extrapolated).

## Validation

- The byte accounting is measured from the model's GGUF index (96
  gate/up tensors = 42.38 GiB; 48 down tensors = 29.35 GiB; the Q5_1
  subset ~26.3 GiB), and the tile-set equality to raw follows from
  the bit-lossless staging the round-trip gates proved (5e90c9b9e for
  Q5_1, the committed Q4_K precedent for gate/up).
- The integration points are named from the actual load path
  (materialize_qwen4_exp_weights / materialize_qwen4_exp_raw_weight,
  DeviceTensorAllocation.free, the binding allocation stages) and the
  runner branches (the tile-cache keying at allocation("raw").ptr).
