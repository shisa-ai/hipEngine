# gemma4-moe-prefill-wmma-routing

## Summary

The Gemma 4 26B-A4B prefill bottleneck was the MoE expert projections, not
attention. Routing them through the repository's existing compact WMMA prefill
owners took a 1024-token prefill on the W7900 lane from 8.523 s (120.1 tok/s) to
2.544 s (402.5 tok/s), +235%.

Two arms landed, with different standing:

- **Exact arm, now the default, +22%.** The Q5_1 down projection is 17.8% of the
  incumbent prefill (1238 ms over 58 calls). The grouped rowbatch8 owner serves
  it bit-for-bit in the same class as the selected GEMV, and the teacher-forced
  gate reports `kl_max` of exactly 0.000000, not merely below the bar. Prefill
  8.523 -> 6.982 s (146.7 tok/s). This is a correctness-neutral win and is what
  `auto` runs.
- **Fast arm, off the default path, pending a lead ruling.** Both WMMA owners
  breach the campaign's absolute `kl_max` bar. The compensated forms are the
  recommended fast arm; see the decision below.

The fused `gate_up` tensor needed a new `expert_stride_rows` argument on the
dual owner: a fused tensor stores both halves in one allocation, so the expert
stride is `out_features_a + out_features_b` while each half still indexes from
its own origin. Passing each half's own width (the two-tensor convention) reads
the wrong expert's rows.

## Validation

Measured on the W7900 lane (GPU0), same GGUF artifact, greedy, bf16 KV, 1024
prompt tokens, 60 layer calls, via `scripts/gemma4_prefill_census.py`:

| expert route | prefill s | tok/s | teacher-forced gate |
| --- | ---: | ---: | --- |
| selected GEMV (incumbent) | 8.523 | 120.1 | `kl_max` 0.000000, pass |
| grouped rowbatch8 (default) | 6.982 | 146.7 | `kl_max` 0.000000, pass |
| compensated WMMA | 2.544 | 402.5 | `kl_max` 0.060867, fail |
| plain WMMA | 2.236 | 458.0 | `kl_max` 0.182137, fail |

Route attribution, teacher-forced gate against
`/mnt/nvme1/gemma4-eval/teacher-forced-prefilled-strict-001c4fec3.npz`, prompt
2048 with prefill 1024, 1023 scored rows, bars `kl_max` 0.05 / `kl_mean` 1e-3 /
`kl_p95` 5e-3 / `kl_p99` 2e-2 / top-1 0.99:

- selected 0.000000, grouped 0.000000, plain WMMA 0.182137, compensated WMMA
  0.060867, gate+up-only WMMA 0.174212, down-only WMMA 0.162814.
- Compensated WMMA passes every other bar: `kl_mean` 8.58e-05 (12x margin),
  `kl_p99` 9.89e-05 (200x), top-1 rate 1.0 with zero flips on all 1023 rows.
- Compensating the fp16 weight rounding is what moves 0.182137 to 0.060867, for
  14% more time. A two-way accumulator split moved it to 0.081599, so the
  residual is irreducible reduction association rather than a defect.

The `+22%` default arm is gated at `kl_max` exactly 0.000000 on the same
baseline, which is the strictest available statement: the grouped owner
reproduces the strict reduction order rather than approximating it.

## Next

The campaign's absolute `kl_max` bar now gates a 3.4x prefill win instead of the
1.1x it gated for the key-slice attention split, and it is the same decision: an
absolute order statistic on a peaked reference versus a reordering-class change
that never moves a decision. That ruling is the lead's; the iteration-59
diagnostic records the mechanism and the numbers, and `docs/REFACTOR.md` names
the command that clears it. If the bar does not apply, `wmma` becomes the
default and the plain variants and diagnostic modes are deleted with the
selector.

At the compensated-WMMA rate the remaining prefill is attention 959 ms (37.9%),
dense Q8_0 625 ms (24.7%), fused gate+up 577 ms (22.8%), layer-29 MoE 204 ms
(8.1%) and down 82 ms (3.2%). llama.cpp's HIP prefill on the same file is 3910
tok/s, so attention and the dense Q8_0 linears are the larger remaining share
and neither is routed through a WMMA owner yet. The layer-29 MoE (Q5_K gate+up
and Q8_0 down, 204 ms) has a registered single-output WMMA owner for Q5_K that
would take the fused width, and no WMMA owner at all for Q8_0.
