# DE-5 re-derivation: the wrapper is ~3 ms/token and the loop-start cost is a per-prefill reset transient

## Summary

DE-5's premise of a large per-token wrapper host cost does not hold. Measured at the
production decode boundary on `code-p1024`, wrapper host time is **2.7-3.3 ms/token**
(512 transitions, three loops: wall 52.76 / 54.01 / 53.78 ms/token, host 2.69 / 3.34 /
3.05) - the row's own ~3.6 ms/token, about 5-6% of a step, not a lever.

Steady-state decode is flat at **49.8-50.5 ms/token (~19.8-20.1 tok/s)** from step 32
onward, drifting +1.2 ms over 480 steps (context growth).

The reproducible anomaly is a **per-prefill transient of ~1.5-1.8 s confined to the
first ~32 decode steps**. It is absent in the warmup (the first loop after model load)
and present in every repeat: first-eighth bands 145.48 / 144.42 / 145.99 ms decaying
through ~65 ms to a flat ~49.9. The row's prior correction had closed with an untested
hypothesis that this belongs to the x4 harness's `snapshot_restore_between_repeats`
interacting with the QSA indexed-sparse rewindable index state. This probe does not use
the snapshot mechanism at all - its only state rewind is `runner.prefill()`, which calls
`reset()` - so **the hypothesis is reproduced and relocated onto the `reset()` path**.

Four mechanisms were tested and excluded, and the settle "fix" was rejected.

## Validation

Exact command (one representative run; all runs use the same form):

```bash
D=/home/lhl/miniforge3/envs/vllm/lib/python3.12/site-packages/_rocm_sdk_devel
PATH=$D/bin:$PATH LD_LIBRARY_PATH=$D/lib python3 scripts/qwen4exp_de5_wall_split.py \
  --case code-p1024 --steps 512 --repeats 2 \
  --json-out benchmarks/results/2026-09-30-qwen4exp-de5-wrapper-wall/wall-split-production.json
```

Mechanism exclusions, each from a separate run in the same artifact directory:

| candidate | test | result |
| --- | --- | --- |
| unsynchronized prefill tail | time prefill across `device_synchronize()`, then re-sync immediately | prefill 4.2-4.8 s; **`resync` 0.00-0.01 ms** - nothing queued |
| queued device work | same | excluded by `resync` = 0 |
| clock throttling | sample `pp_dpm_sclk` / `pp_dpm_mclk` per 5 ms as sixteenth-bands | **flat 2900 / 1000 MHz in every band** |
| pure host blocking | busy counter during the transient | busy mean **82.0%** vs 95.4% with an idle; pure host blocking over 32 steps would need ~37% idle, so it is a **mix** |
| 5 s settle as a fix | idle between prefill and decode | removes the transient but is net **+3.3 s** (31.8 s no-settle vs 35.1 s settle) - **relocated, not removed** |

Path-independence: the probe was first written with the runner default
`capture_logits=True`, which synchronizes, copies full-vocab logits D2H and argmaxes on
the host. Every canonical bench and probe uses the device-argmax boundary instead, so the
probe was corrected and re-run. The two agree within noise at this shape (production
54.01 / 53.78 versus diagnostic 53.94 / 53.79) and **the transient is present on both**,
so it is a decode-path property rather than a logits-capture artifact. The earlier
"bench wall is transient-inflated" reading was wrong and is not recorded.

Limits: one case, one prompt, one model, one quant, one host, one profile. The driver
does not document the busy counter's averaging window, so busy-derived shares are
approximate and the per-step wall series is the primary evidence. No mechanism inside
`reset()` is isolated.
