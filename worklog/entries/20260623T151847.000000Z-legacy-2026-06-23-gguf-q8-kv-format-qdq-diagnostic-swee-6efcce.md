# 2026-06-23 — GGUF Q8 KV format QDQ diagnostic sweep

## Changes


- Added `scripts/qwen35_gguf_q8_format_sweep.py`, a host-side numerical QDQ harness for GGUF full-attention KV formats. It runs a BF16 resident session, backs up per-layer BF16 KV caches after prefill, quantize/dequantizes candidate layouts into the BF16 cache, and replays one decode step through the existing BF16 path. Caveat: this is not a real HIP Q8 KV implementation; the full-model replay quantizes retained prefill rows but the appended decode-token row remains BF16. The script also reports an exact layer-local CPU attention probe for the first full-attention layer including the appended decode row.
- W7900/GPU0 hermetic env run: `HIP_VISIBLE_DEVICES=0 HIPENGINE_GGUF_DECODE_REPACK=1 HIPENGINE_HIP_ARCH=gfx1100 HIPENGINE_COMPILER_VERSION_FILE=/tmp/hipengine-hipcc-version-713.txt HIPENGINE_HIPCC_VERSION_FILE=/tmp/hipengine-hipcc-version-713.txt python3 scripts/qwen35_gguf_q8_format_sweep.py --model /models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf --prompt-length 4K --max-sequence-length 8192 --formats per_token_head_fp16,q8_0_block32_fp32,block16_fp32,key_q8_0_block32_value_bf16_fp16 --bf16-prefix-full-layers 0,3,6,8,9 --compiler-version-file /tmp/hipengine-hipcc-version-713.txt --require-cached-build --json /tmp/hipengine-gguf-q8-format-prefix-sweep-4k.json`.
- Result: no all-Q8 format passed the approximate 4K/1 KL/top-1 gate. Zero-prefix best was `block16_fp32` (`KL=0.1084`, top-1 mismatch). At prefix 3, `block16_fp32` and key-only `q8_0` were below KL 0.05 but still top-1 mismatched. First approximate passes: prefix 6 for current `per_token_head_fp16` (`KL=0.00468`, top-1 `1.0`, ~19.8% full-KV saving), prefix 6 for `block16_fp32` (`KL=0.0110`, top-1 `1.0`, ~15.0% saving), prefix 6 for key-only `q8_0` (`KL=0.00887`, top-1 `1.0`, ~9.4% saving), and prefix 8 for `q8_0_block32_fp32` (`KL=0.00644`, top-1 `1.0`, ~8.75% saving). The layer-local probe says key-only `q8_0` is least disruptive at layer 3, but it saves little memory and is not an implemented runtime path.
- Interpretation: a llama-style block-32 Q8 format is not an obvious all-layer fix for GGUF long-context quality. The only approximate passes still need a large BF16 full-attention prefix, so no Q8 KV path is promoted. Next real implementation candidate, if we continue, is a minimal HIP `q8_0_block32`/`block16` decode+prefill path gated behind diagnostics, followed by the existing long BF16-vs-candidate guard; otherwise switch to non-KV memory reductions.
- Added artifact `benchmarks/results/2026-06-23-w7900-gguf-q4km-q8kv-format-sweep-diagnostic.json` and updated `docs/TUNING-gguf.md` / `benchmarks/CHANGELOG.md` with the non-promotion note.
- Validation: `python3 -m py_compile scripts/qwen35_gguf_q8_format_sweep.py`; `python3 -m ruff check scripts/qwen35_gguf_q8_format_sweep.py`; `python3 -m json.tool benchmarks/results/2026-06-23-w7900-gguf-q4km-q8kv-format-sweep-diagnostic.json` -> passed.
