# The prefix-reuse gate now binds the production-shaped state contract, isolating the Japanese KL as the one open failure

## Summary

`scripts/gguf_prefix_reuse_gate.py` no longer fails on comparisons that cannot
be bit-equal by construction. Its pass expression now binds the comparison that
reproduces the production prefill shape (the native chunked oracle's boundary
and final state) plus the lifecycle, ownership, sampler-route, and numerical
terms, and keeps the one-shot-prefix, one-shot-bulk, and serial comparisons in
the payload as diagnostics. On the four natural categories this turns `code`,
`general_en`, and `mixed_ja_en` green and leaves `general_ja` failing on exactly
one term -- the KL/top-1 envelope against the teacher-forced reference -- which
is the real, still-open accuracy question rather than a shape artifact.

## Changes

- `scripts/gguf_prefix_reuse_gate.py`: added `_PRODUCTION_GATE_TERMS`,
  `_DIAGNOSTIC_COMPARISONS`, and `gate_passed()`, replaced the inline `passed`
  conjunction with them, and recorded `gating_route`, `gating_terms`,
  `diagnostic_comparisons`, and the scheduler boundary/final/output booleans in
  the payload.
- `tests/test_unit_gguf_prefix_reuse_gate.py`: new
  `test_only_the_production_shaped_comparison_gates_the_contract` (RED first:
  `ImportError` before the change), asserting that the diagnostic comparisons do
  not gate, that every binding term does, and that a missing term raises.
- `docs/REFACTOR.md`: the "Strict prefix gate cannot bind a batched candidate"
  entry moves from open limitation to resolved, with the remaining accuracy
  question recorded as its removal scope.

## Validation

Unit tier: `tests/test_unit_gguf_prefix_reuse_gate.py` and
`tests/test_unit_agentic_a2_prefix_lifecycle_artifact.py`, 6 passed. The a2 test
reads frozen artifacts by sha256, so it is unaffected by the pass expression.

Gate re-run on all four categories with the artifact's own recorded per-category
commands (`--prompt-file benchmarks/prompts/mtpbench-code-general-ja.jsonl`,
`--prompt-category <category>`, `--prefix-tokens 1024 --suffix-tokens 200
--teacher-forced-steps 4`, `greedy_fast`, per-category lifecycle preserved:
`active` for `code`/`general_en`/`mixed_ja_en`, `completed` for `general_ja`):

| category | passed | scheduler boundary/final | kl_mean | metrics_passed |
| --- | --- | --- | --- | --- |
| `code` | True | True / True | 3.9e-05 | True |
| `general_en` | True | True / True | 0.007199 | True |
| `general_ja` | False | True / True | 0.681121 | False |
| `mixed_ja_en` | True | True / True | 0.003394 | True |

Before the change all four reported `failed`, in every case because
`semantic_boundary_exact` and `initial_state_exact` compared the candidate's
state bytes against routes that prefill through a different shape (126 and 128
mismatches on `general_ja`, spread across every layer of both state families).
Those comparisons are now diagnostics, and the state contract that remains
binding is the one measured against an independent implementation of the
production shape: 0/0 mismatches in all four categories.

`scheduler_output_exact` is deliberately **not** binding. The candidate's
continuation token can be a processor-forced token while the native oracle
samples freely, so the two are only comparable when no forcing is active. On
`mixed_ja_en` the continuation row carries
`processor_forced_token_ids: [9709, 9710]`: the candidate emits 9709 while the
oracle samples 248046, with the boundary and final states still bit-identical
(0/0). That is a diagnostic-route artifact, not a state or ownership defect, and
token quality stays covered numerically by `metrics_passed`. The four token
fields on that category are recorded in
`/tmp/t30-gate-fixed/mixed_ja_en.json` (candidate 9709, serial reference 9709,
one-shot prefix 271, one-shot bulk 248046, native chunked 248046).

The four post-change artifacts are under `/tmp/t30-gate-final` and are
summarized in `benchmarks/results/2026-09-20-gfx1151-prefix-gate-production-binding.json`
(one row per category with `gating_terms`, the diagnostic mismatch counts, and
the KL/top-1 envelope), with a dated line at the top of
`benchmarks/CHANGELOG.md`.

## Next

- `general_ja` remains the single failing category and it now fails on one term.
  The open question is accuracy, not state: the production route predicts 271
  where the serial reference predicts 96026 and the one-shot prefix route
  predicts 174267, so the three routes disagree and only a higher-precision
  reference (`kernels/cpu_reference/` fp32, or the `serial_exact` verify
  teacher) can say which is closer to the truth. Until then the envelope stays
  binding and keeps flagging it.
- Re-run the calibrated mean/tail/top-1 and task gates once that reference
  exists; any performance claim still needs the full mtp-bench category suite
  plus heldouts.
