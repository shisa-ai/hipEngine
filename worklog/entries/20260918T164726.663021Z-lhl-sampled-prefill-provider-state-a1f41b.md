# open provider draft state on the sampled prefill path

## Summary

A sampled request that the server had already routed to the speculative route
still never reached a provider: the trace showed `capability=none` with planner
reason `no_provider` on every cycle, so the row decoded autoregressively while
reporting route `speculative_mtp`. The cause was in the prefill path, not in the
sampled accept rule. A due sampled row now reaches the provider for its first
admitted cycle; that cycle then fails for a separate reason, recorded below.

## Changes

- `hipengine/generation/qwen35_gguf.py`:
  - `_finish_sampled_prefill` now calls the same `_observe_mtp2_prefill` hook
    `_finish_native_prefill` already called, through a new shared helper. That
    hook is what hands the provider the prompt's hidden rows, and the provider's
    capability refuses a row that has neither hidden rows nor a request state,
    so skipping it on the sampled path left a sampled row without a provider for
    its whole lifetime.
  - `_prefill_sampled_row` opens the streamed target-hidden sink
    (`_begin_mtp2_prompt_streaming` plus the `target_hidden_chunk_sinks` kwargs)
    for a row with a candidate budget, and finalizes it with
    `_finish_mtp2_prompt_streaming` on both the success and failure paths. A
    packed prefill refuses to return logits and host hidden rows together
    (`qwen35_gguf_runner.py:24403`), and a host-sampled row needs its first-token
    logits, so the streamed sink is the only route that serves both. Without an
    admitted sink the row keeps the shipped scalar prefill and decodes without a
    provider.
- `tests/test_unit_qwen35_gguf_mtp2_seam.py`: two seam tests, both RED before
  their fix. `test_sampled_prefill_hands_the_row_to_its_mtp_provider` calls the
  real `_finish_sampled_prefill` and asserts the provider observes the result;
  `test_sampled_prefill_streams_prompt_hidden_rows_for_a_due_row` asserts the
  sink is opened with `return_logits=True` and `return_hidden_seeds=False` for a
  due row, that a refused sink falls back to the shipped scalar prefill, and
  that a row with no candidate budget never opens a sink.

## Validation

- `timeout 600 uv run pytest tests/test_unit_qwen35_gguf_mtp2_seam.py -q -k
  sampled_prefill`: 2 passed. Both were confirmed RED by reverting each half of
  the fix in place and re-running.
- Serving probe, gfx1151, Qwen3.8-27B Q4_K_M, c=1, 24 tokens, temperature 0.7,
  explicit `speculative_mtp`, `HIPENGINE_DEBUG_SAMPLED_ROUTE=1` +
  `HIPENGINE_MTP2_TRACE_DECLINE=1`, `/tmp/mtp-sampled/gate4.log`:
  - before this change: `capability=none`, reason `no_provider` on all 24
    cycles, no decline trace, `prefill-debug ... hidden_seeds=False`.
  - after: cycle 1 `capability=none` (row not yet attached), cycle 2
    `capability=set ... k=3 reason=speculative_qualified`, then cycles 3+ return
    to `no_provider` with one decline trace
    `request 2 unregistered or disabled`.
  - the response reports `fallback_event_counts = {"no_provider": 22,
    "precommit_failure_ar_fallback": 1}`, so the admitted cycle failed before its
    commit and the adapter disabled the row (`_drop_request(disable=True)` from
    `rollback_cycle`), which is why the remaining cycles refuse. All 24 tokens
    were autoregressive, so this is still not a sampled-MTP measurement.
- The evidence-row edit that opens the route
  (`hipengine/models/qwen35.py`, `sampling_modes` gains `"sampled"`) is
  deliberately **not** committed: shipped behavior for a temperature request is
  unchanged until that row is retained with a serving result behind it.
