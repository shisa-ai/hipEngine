# gfx1151 dispatch tests stub retained high-row Q6 owners

## Summary

Two dispatch-pinning tests in tests/test_gfx1151_backend.py were stale after
the retained Y2 routing bands landed: they called the planar Q6 dispatcher
with fake device pointers (1, 2, 3) on shapes/rows that now route to kernel
bodies the tests did not monkeypatch. The real kernels then launched with
garbage pointers and aborted the whole pytest process with an async GPU
memory fault (HSA_STATUS_ERROR_MEMORY_FAULT, page-not-present, e.g.
q6_k_t16_qmicro_planar_wmma_prefill_shared_bf16_kernel<3,1,2> and <4,4,2>),
which also destroyed the failure report being formatted.

This is the same failure class 4a9077c08 repaired for the sibling test; that
repair's guard ran only the four structural-campaign files, so this file's
remaining leaks were never executed at commit time.

## Root cause

The router is correct (retained Y2 bands: shared3r1 rows33-48 on
(5_120,1_024)/(17_408,5_120); shared4r4 at rows256, shared4r6 from row288,
shared4r9 at rows536 on (17_408,5_120)). The tests' expected routing
predates those bands and omitted stubs for the new bodies.

## Changes

- test_gfx1151_q6_planar_prefill_lowvgpr_bands_route_by_rows_and_shape:
  stub shared4r3/r4/r6/r9 + shared3r1; rows33-48 (17_408,5_120) expects
  shared3r1; rows45 (5_120,1_024) expects shared3r1; rows512 (17_408,5_120)
  expects shared4r6. Expectations built by mapping the shapes list in call
  order.
- test_gfx1151_highrow_prefill_bands_route_by_family_and_shape: add the same
  five Q6 stubs; split the former rows(256,536) blanket shared4 expectation
  into rows256 -> shared4r4, rows288 -> shared4r6, rows536 -> shared4r9 on
  (17_408,5_120), shared4 otherwise.

No production code changed; routing is untouched.
