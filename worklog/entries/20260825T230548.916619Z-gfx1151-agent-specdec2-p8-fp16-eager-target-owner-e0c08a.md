# Keep SPECDEC2 P8 FP16 target verify eager

## Summary

P8 production FP16 target logits and eager transaction ownership are correct,
but native target graph replay is not. Keep every FP16 target verify/selected
commit on the exact eager owner before graph lookup/capture. This is a scoped
correctness repair, not a graph-performance retention: strict FP32 graph
selection is unchanged and production automatic policy remains K0.

## Changes

- Native target dispatch now rejects every FP16-state graph bucket before
  capture and calls the existing eager verifier when fallback is allowed.
- Device-proposal handoff already fails closed under FP16 state and remains so.
- Added RED/GREEN dispatch coverage and updated the P8/refactor handoff.

  mean/p95/p99/max KL **4.00e-5/1.95e-4/4.28e-4/6.88e-4**, top-1
  **448/450 = 99.56%**, no scope/review failures, exact three-repeat
  determinism and state fingerprints.
- SPECDEC2 target-logit gate before selected commit: strict target equals scalar
  exactly; production FP16 chain equals scalar exactly; **36/36 top-1**, max KL
  **7.16e-4**, exact three-repeat logits/state.
- Localized failure before repair:
  - eager reject/partial/full selected commit: state and following full logits

  - graph source-row tracing shows divergence beginning after layer 51 under
    FP16 state despite correct byte strides (`conv 163,840`, recurrent
    `1,572,864`) and pointer-table counts;
  - post-device-commit rollback still restored the initial owner exactly.
- After repair, caller `allow_graph=True` and explicit eager both use eager
  target ownership; reject/partial/full state, token, and full logits are exact
  **3/3**, with `native_graph_submitted=false`.
- Focused native graph-key/eligibility dispatch tests pass; previously qualified
