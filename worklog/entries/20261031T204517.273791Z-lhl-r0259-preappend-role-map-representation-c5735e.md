# R0259 bounded backend preappend role maps keep decision

## Summary

R0259 resolves to **keep** the bounded backend role maps. The runtime already
normalizes at the cache boundary: `allocate_laguna_kv_cache` stores
`(prefill_preappend_role_scoped: bool, prefill_preappend_role_variants:
Mapping[str, str])`, and every preappend consumer reads only that pair. The
package maps
are therefore a declaration format for that pair, not a second runtime
representation to unify. Absence, an empty map, independent global/SWA package
defaults and explicit variants select four different consumer outcomes, and the
map value also selects launch operand shape — the score-replay variants take a
borrowed scratch pointer and `score_scratch_nbytes`. A unified selector would
have to re-encode all of that, and the normalization R0259 contemplates has
already happened one layer down.

No runtime, kernel, arithmetic, README, PLAN, ARCHITECTURE, KERNELS or REFACTOR
change. No device parity claim.

## Changes

- Inspected the live owners: `hipengine/kernels/hip_gfx1100/__init__.py`
  (base map, dense-initial source map, H6A/H6W rollback declarations),
  `hipengine/runtime/laguna_kv.py` (two scope parsers, one resolver, the
  `can_preappend_attention_prefill` gate, `attend_prefill_cached` operand
  selection, `prefill_score_scratch_*`), and
  `hipengine/runtime/laguna_gguf_runner.py` (`_global/_swa_prefill_package_default`
  derivation, `allocate_laguna_kv_cache` call, `prefill_kv_preappend` and
  `stage_verifier_kv` gates, append-before-attention branch).
- Representation inventory: two scopes (base = SWA role only; dense-initial =
  global + SWA roles), two role names, per-scope candidate sets, one resolved
  dict, one scoped flag. The base scope legitimately rejects the global role, and
  the dense scope legitimately rejects a base-only SWA variant; those two
  rejections happen before allocation.
- The preappend maps are independent of `LAGUNA_SWA_PREFILL_ROLE_VARIANTS`, which
  is a separate SWA *prefill* role substitution (`qrow4_m128_c256_exact` →
  source-qualified variant) applied at `start_position >= 256` in the
  attend-then-append fallback. The two policies share role vocabulary and both
  appear in the same layer call, so a normalization that merged them would
  change fallback launch identity, not only the preappend route.
- The two role-map mechanisms already key selection differently, and a
  reachable request separates them. The preappend gate drops a role when the
  caller *requests* a variant (`global_prefill_variant is None`,
  `swa_prefill_variant is None`), while the prefill role map compares the
  resolved variant with the package default. Passing the package default
  explicitly therefore drops the preappend role and still applies the prefill
  role substitution in the same allocation. This is executed in the new test
  file; nothing documented it before, and a unified selector has to choose a
  side rather than preserve both.
- Added `tests/test_unit_laguna_r0259_preappend_role_maps.py` (7 unit tests,
  host doubles, no device). It covers the states the R0259 bundle did not
  assert: base map absent versus `{}`; dense-only, base-only and merge-by-role;
  the package-default override kwargs (the runner's rollback lever, previously
  pinned only by source string) next to explicit variants; per-scope rejection
  before allocation; a 512-row chunk at start 0 versus start 512
  (append-then-attend versus attend-then-append); complete 256/512-row global
  widths that `can_preappend_prefill` admits but the policy gate denies; the SWA
  ring tail at 384 admitted and 448/512 denied; 64/192 fallbacks; score-replay
  fallback without leaving the preappend route, including the scratch operand
  difference; and the base-scope H5R role surviving dense-initial metadata
  invalidation.
- Source finding outside R0259's decision, reported not fixed:
  `LagunaKVCache.prefill_score_scratch_required`
  (`hipengine/runtime/laguna_kv.py:665`) is a plain method while its sibling
  accessors are properties, and
  `hipengine/runtime/laguna_gguf_runner.py:4077` reads it as a truthiness test on
  the bound method. The scratch is therefore bound whenever the F32 ordered
  prefill scratch exists, and the "not required" branch is unreachable. Benign
  under the current H6Z/H6W source maps, which do require it. Runtime edits are
  out of this unit's scope.

## Next

- Shared-doc edits were not made in this unit. Proposed current-contract
  location: `docs/reference/KVCACHE.md` (its `owns:` line already covers "KV
  cache ABI, policy notes"), as a new subsection in the Laguna policy material.
  Proposed text:

  > ### Laguna prefill append-before-attention policy
  >
  > The gfx1100 package declares two bounded role maps. They are declaration
  > data, not a runtime selector: `allocate_laguna_kv_cache` resolves them once
  > into `(prefill_preappend_role_scoped, prefill_preappend_role_variants)` and
  > every consumer reads that pair.
  >
  > | Scope | Capability | Roles |
  > | --- | --- | --- |
  > | base | `LAGUNA_PREFILL_PREAPPEND_ROLE_VARIANTS` | `swa_qrow4_m128_c512_no_wrap_exact` |
  > | dense-initial | `LAGUNA_PREFILL_DENSE_INITIAL_PREAPPEND_ROLE_VARIANTS` | `global_m128_c4096_first_fill_exact`, `swa_qrow4_m128_c512_no_wrap_exact` |
  >
  > - Absent map (either name unbound): `scoped` is false and
  >   append-before-attention follows the primitive bound only. gfx1151 is in
  >   this state.
  > - Empty map: `scoped` is true with no roles, so the bounded route admits
  >   nothing. Empty and absent are different policies, not two spellings of "no
  >   override".
  > - The dense map overrides the base map on their shared SWA role.
  > - Each scope has its own candidate set. The base scope rejects the global
  >   role and the dense scope rejects base-only SWA variants, both before
  >   allocation.
  > - `global_prefill_variant`, `swa_prefill_variant`, or the explicit
  >   `prefill_*_preappend_package_default=False` lever drops only its own role.
  >   Dropping both leaves `scoped` true with no roles.
  > - A role is dropped when the caller *requests* a variant, including a
  >   request that names the package default. The separate
  >   `LAGUNA_SWA_PREFILL_ROLE_VARIANTS` substitution keys on the resolved
  >   variant instead and stays active for that same request.
  > - A role admits only complete 128-row tiles at start 0/128/256/384, with
  >   dense-initial metadata intact and the shape the role names. Complete wider
  >   global chunks are safe for `can_preappend_prefill` and still outside the
  >   bounded policy. Wrapped and partial SWA ring tails fall back to
  >   attend-then-append.
  > - The selected variant owns the launch operands. Score-replay roles pass a
  >   borrowed scratch pointer and `score_scratch_nbytes`; when that scratch is
  >   unbound they fall back to the fixed512/cached variant on the same route.
