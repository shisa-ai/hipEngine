# Freeze the public DMS sidecar comparison protocol

## Summary

Freeze a same-host diagnostic comparison of dense INT8 KV, local W256/CR2
DMS INT8, and published W8192/CR2 DMS INT8 through `LLM.generate_detailed`.
This compares already-shipped paths; it neither changes arithmetic defaults nor
certifies either sidecar's task quality.

## Changes

- Add `scripts/dms_public_sidecar_compare.py` with the first manifest prompt
  from each of code, English, Japanese and mixed Japanese/English, selected
  before observing results. Exact input lengths: 128, 2048 and 12288 tokens.
  A common tokenized background precedes each category request; an explicit
  closed thinking prefix keeps the short output budget in answer text.
- All arms: Qwen3.8-27B Q4_K_M on this host's Radeon 8060S/gfx1151,
  production profile, INT8 per-token/head KV, FP32 scales, singleton request,
  prefix cache off, no MTP, 32 greedy output tokens with EOS ignored.
  One untimed warmup per prompt/shape, then two measured repeats. Each arm
  runs in a separate process to release ownership and allocation state.
- Report backend prefill separately from request-total minus prefill. The
  latter includes sampling/scheduling and uses N-1 post-prefill tokens;
  it is not GPU kernel-only decode time. Also preserve public call wall time.
- Preserve request diagnostics, sampler selection, sidecar metadata,
  achieved versus configured compression, payload/scale/resident bytes,
  per-request tracked allocator peaks, generated IDs/text, exact prompt hashes,
  execution-profile manifests and canonical host/toolchain/source provenance.
  Tracked allocation excludes internal HIP/library allocations and is not
  a whole-device reserved-memory measurement.
- Export exact token manifests for supplementary dense-BF16-teacher checks
  using the existing integrated quality suite, at 2048 and 12288 with both
  no-eviction and learned-eviction controls, eight teacher-forced decode steps,
  mean/max KL and top-1 by category. These are diagnostic numerical checks,
  not full task-quality or production-promotion certification. Public-path
  generated-ID equality across different policies is diagnostic, not binding.
- Comparisons remain `status: diagnostic`: four category prompts and a
  repeated neutral background do not certify realistic long-context task
  quality. Warmups may build kernels; measured repeats do not intentionally
  compile or profile. No MTP speedup is claimed from this AR protocol.

## Validation

- ROCm library loads and `rocminfo` identifies Radeon 8060S, gfx1151.
- CPU harness tests: 8 passed. They cover the N-1 timing denominator,
  non-finite/invalid timing rejection, deterministic category selection and
  exact-length request suffix preservation.
- No RED-first production regression: this adds a diagnostic script, not a
  runtime or arithmetic change. Formula/error/selection unit tests accompany it.
- The first public smoke exposed a harness assumption: `GenerationOutput`
  may omit its optional `prompt_tokens`; the authoritative count is in
  `telemetry.decode_state.prompt_tokens`. The assertion now uses that field.

- Focused CPU harness/serving/policy bundle: 39 passed; documentation gates passed.
- Corrected public W8192 smoke: all 12 requests completed, exact repeated IDs,
  reported W8192 compact INT8 route. Preparatory artifact:
  `/tmp/dms-published-public-smoke-initialized.json`.
- Profile manifests are queried after public tokenizer initialization, which
  registers the generator's plans. Querying them before initialization raised
  a missing-plan exception in the preparatory harness.
