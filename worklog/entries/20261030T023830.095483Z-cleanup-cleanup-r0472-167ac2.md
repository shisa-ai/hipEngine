# Close obsolete eager verifier-journal allocation debt

## Summary

R0472's proposed lazy serial-journal allocation is already implemented. Remove
its stale eager-allocation description without changing runtime policy.

## Changes

- The verifier constructs a compact native primary journal. `_select_journal`
  lazily allocates a separate consumer-owned row journal for serial fallback.
- `prepare()` selects that journal before `capture_initial` or state mutation.
  Native graph pointers retain their original owner. Subsequent serial calls
  reuse their journal; `close()` releases both owners. A failed allocation
  leaves the native owner intact. Serial-only sessions reuse their primary.
- The previous ledger measurement describes the former eager allocation,
  not current memory consumption. No new memory or speed claim is made.
- Remove both obsolete R0472 bullets. No RED cycle or GPU run is needed for
  this documentation-only reconciliation of existing implementation and tests.
