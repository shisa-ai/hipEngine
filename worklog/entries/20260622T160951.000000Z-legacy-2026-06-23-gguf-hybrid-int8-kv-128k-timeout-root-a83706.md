# 2026-06-23 — GGUF hybrid INT8 KV 128K timeout root cause and diagnostic run

## Summary

- Historical pre-Worklog2 journal entry, ported verbatim from `WORKLOG-LEGACY.md` (source lines 95954-95960).
- First appended to the journal in commit `1ce10f58` (subject: docs: record GGUF hybrid 128K diagnostic).

## Changes


- Re-ran the GPU1 Q4_K_M hybrid INT8 KV `128K/128` benchmark in a detached wrapper to avoid interactive tool timeouts. The first detached attempt still appeared hung: after `42m` it had `99%` VRAM resident, near-zero GPU use, no JSON artifact, and little CPU time. A faulthandler reproduction on `128K/1` localized the stall to a lazy `build_hip()` compiler-version probe from `hipengine/kernels/hip_gfx1100/fused/paro_silu.py` during bulk prefill (`subprocess.run(hipcc --version)`), not to the 128K kernels themselves.
- Fix for manual long runs: set the compiler-version cache key in the environment, not only via `--compiler-version-file`: `HIPENGINE_COMPILER_VERSION_FILE=/tmp/hipengine-hipcc-version-713.txt` and `HIPENGINE_HIPCC_VERSION_FILE=/tmp/hipengine-hipcc-version-713.txt`. With those env guards, the same GPU1 TheRock ROCm 7.13 `128K/128` command completed in `252s`.
- Result: `scripts/qwen35_readme_sweep.py --engine gguf --model /models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf --quant gguf_q4_k_m --workloads 128K/128 --warmup-runs 0 --measured-runs 1 --warmup-decode-tokens 1 --force-bulk-prefill --bulk-prefill-attention-mode bulk --use-wmma-prefill --use-gemv-decode --compiler-version-file /tmp/hipengine-hipcc-version-713.txt --require-cached-build --kv-storage int8_per_token_head` under `HIP_VISIBLE_DEVICES=1`, `HIPENGINE_GGUF_DECODE_REPACK=1`, `HIPENGINE_HIP_ARCH=gfx1100` -> `756.715` prefill tok/s, `66.053` decode tok/s, final token ID `13`, finite logits, tracked peak `23.291 GiB`, prefill chunks `768`, persistent session load `75.37s`.
- Added diagnostic artifact `benchmarks/results/2026-06-23-gpu1-gguf-q4km-int8kv-hybrid-128k-diagnostic.json` and updated benchmark/docs notes. Treat this as capacity/throughput diagnostic only: 4K BF16-vs-hybrid correctness is accepted, but a long-context BF16-vs-hybrid quality gate is still needed before promoting a 24GB `128K/128` row.
