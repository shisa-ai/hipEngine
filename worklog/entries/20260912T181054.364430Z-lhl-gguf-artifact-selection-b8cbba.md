# GGUF artifact selection: UD is the 35B-A3B target, not the 27B

## Summary

Unsloth Dynamic (`UD`) is the supported quant variant for **Qwen3.6-35B-A3B** and
is **not** the supported variant for the **27B** dense model, where UD fixes are
still incoming. The two must not be swapped when extending the GGUF capacity work
or re-running its retained rows.

Checked the retained auto-context measurements against that rule; **both rows are
already on the correct artifact**, so no benchmark number changes. Evidence is in
`## Validation`.

## Changes

- None to code or benchmarks. The retained rows were already on the correct
  artifact, so this entry records the artifact-selection rule and its evidence
  rather than changing a measured number.
- `worklog/entries/20260912T181054.364430Z-lhl-gguf-artifact-selection-b8cbba.md`
  (this entry) is the durable record.

## Validation

The retained auto-context rows were re-read against the rule and are already on
the correct artifact, so **no measured number changes**:

| --- | --- | --- | --- |
| Qwen3.8-27B `Q4_K_M` | `/models/gguf/Qwen3.8-27B-Q4_K_M.gguf` | standard, non-UD | yes |
| Qwen3.6-35B-A3B `UD-Q4_K_M` | `/models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` | UD | yes |

## Evidence

GGUF metadata cannot distinguish the variants — `general.name` and
`general.basename` both report `Qwen3.8-27B` for the UD and the non-UD file — so
the filename alone is not a safe signal. The quant recipe is:

| File | Bytes | Tensor types | Recipe |
| --- | ---: | ---: | --- |
| `Qwen3.8-27B-Q4_K_M.gguf` | 17,106,773,984 | 5 | `{0: 456, 8: 1, 12: 294, 13: 48, 14: 67}` |
| `Qwen3.8-27B-UD-Q4_K_M.gguf` | 16,464,440,224 | 9 | `{0: 360, 8: 106, 11: 7, 12: 104, 13: 131, 14: 30, 20: 7, 21: 4, 23: 117}` |

`Qwen3.8-27B-Q4_K_M.gguf` carries the vanilla five-type Q4_K_M recipe. The UD
file carries Unsloth's mixed recipe, with `Q4_1`/`Q5_1` and the extra types in
place of `Q5_0`/`Q6_K` coverage. That is a different quant scheme, not a rename of
the same weights.

The repository's own target paths agree: `docs/BENCHMARK.md` references
`Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` four times and never a non-UD 35B, while the 27B
target it names is a plain `Q4_K_M`.

The distinction reaches the auto-context work only through the weight footprint.
The capacity model is quant-agnostic by construction: it prices `bytes_per_token`
from attention geometry and reads free memory from `mem_get_info()`. No code
depends on the UD/non-UD distinction, and none should be added.
