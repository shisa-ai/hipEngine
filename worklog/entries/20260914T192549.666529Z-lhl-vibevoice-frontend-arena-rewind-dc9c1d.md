# Front-end scratch arena: rewind instead of free+realloc per encoder pass (3.4-15% faster encode)

## Summary

`_ScratchPool.reset()` closed the `DeviceMemoryArena` and created a new one on
every call. `reset()` runs once per encoder pass, so every forward paid two
`hipMalloc`/`hipFree` pairs for the whole arena — 287 MB for an 11 s clip,
754 MB for 30 s and 2.23 GB for 90 s (the requested capacity is
`24 * chunk_samples * num_filters * 2 + 16 MiB`).

The pool now rewinds the arena's bump pointer when it is already large enough
and replaces it only when a request does not fit. `DeviceMemoryArena` gains a
`rewind()` method; that change is purely additive and no other arena user is
affected.

Measured with an in-process rotating A/B (same frontend, lanes alternating, 6
timed passes each) on zbook / gfx1151:

| clip | before | after | delta |
| --- | ---: | ---: | ---: |
| 11 s | 290.2 ms | 280.6 ms | **+3.42%** |
| 30 s | 594.9 ms | 529.7 ms | **+12.31%** |
| 90 s | 1657.7 ms | 1441.9 ms | **+14.96%** |

The saving scales with the arena, because the bytes freed and reallocated per
forward are twice its size.

## Changes

- `hipengine/core/memory.py`: add `DeviceMemoryArena.rewind()` (resets the bump
  offset, stats and live-view map; keeps the HIP owner).
- `hipengine/runtime/vibevoice_encoder.py`: `_ScratchPool.reset()` rewinds a
  large-enough arena and grows only when needed, so a capacity that varies
  between passes never shrinks back into churn. Docstrings updated.
- `tests/test_unit_vibevoice_frontend_contract.py`: three new reuse tests.
- `benchmarks/results/2026-09-14-gfx1151-vibevoice-frontend-arena-rewind.json`
  and a `benchmarks/CHANGELOG.md` line.

## Validation

- New unit tests are RED on the parent revision and GREEN after: a fitting reset
  must `rewind()` and must not `close()`; a larger request must replace the
  arena while a later smaller one reuses it; repeated resets must rewind each
  time. They use a mock arena, so they need no GPU.
- 34 passed across `tests/test_unit_vibevoice_frontend_contract.py`,
  `tests/test_gpu_memory_stats.py`, `tests/test_unit_loading_materialize.py` and
  `tests/test_gpu_vibevoice_encoder_kernels.py` — every test that touches
  `DeviceMemoryArena`.
- Front-end embeddings are bit-identical before and after for 11 s
  single-chunk, 30 s multi-chunk (`chunk_samples=160000`, three chunks) and 30 s
  single-chunk, and stable across four repeated calls in each configuration.
  The multi-chunk case is the one that exercises six resets inside one forward,
  so it is where a stale arena would surface.
- Both revisions were run in the same session on zbook / gfx1151; the separate
  before/after runs agree with the rotating A/B at 30 s (+12.5% vs +12.31%) and
  disagree at 11 s (+6.9% vs +3.42%), which is why the rotating in-process number
  is the one quoted.

## Next
