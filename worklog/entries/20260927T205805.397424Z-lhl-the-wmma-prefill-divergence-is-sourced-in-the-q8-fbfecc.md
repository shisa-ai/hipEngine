# The WMMA prefill divergence is sourced in the q8_0 kernel alone

## Summary

Checkpoint on `worklog/entries/20260927T205252.984133Z-lhl-the-wmma-dense-prefill-is-19-percent-faster-and-066917.md`.
That entry reverted a 19 percent prefill win because the route diverges by up to
10.9 KL at short prompt lengths, and listed two candidate causes. Both are now
closed.

**Cause 1, a small-row dispatch difference, is dead.** `rocprofv3 --kernel-trace`
on the 64-row case, both arms, shows both dispatch **1560** kernels and exactly
three names differ:

| off | on | kernel |
| --- | --- | --- |
| 205 | 0 | `gguf_q8_0_exact_prefill_tiled_out_kernel<u16, u16, 4, 16>` |
| 0 | 175 | `gguf_q8_0_prefill_wmma_kernel<u16, u16, 32, 32>` |
| 0 | 30 | `gguf_q8_0_prefill_wmma_kernel<u16, u16, 64, 32>` |

Every other kernel is identical, including the MoE router and the tile map. The
`HIPENGINE_GGUF_WMMA_PREFILL` env var flips four dispatch decisions, which was the
leading ambiguity; the divergence comes from the q8_0 dense prefill and nothing
else.

**Cause 2, a row-tile tail, is dead.** The WMMA row tile is `AWQ_TILE_N = TN =
32`, so 64 rows is exactly two tiles and no clamping is involved. The kernel is
wrong where a tail cannot exist. It is also memory-safe: stores are guarded
(`out_row >= rows` continues, `col < out_features` guards) and reads are clamped
through `safe_token` / `safe_out`.

## Precision is not the explanation, which makes this a defect

The exact tiled route keeps the activation in **f32**:

```cpp
x_tile[r] = scalar_to_float<scalar_t>(x[safe_row * in_features + k_base + j]);
```

The WMMA route narrows it to **f16**:

```cpp
out[i] = static_cast<half_t>(scalar_to_float<scalar_t>(p[i]));
```

f16 carries 10 mantissa bits against bf16's 7, so the WMMA route hands the matrix
core a *strictly more precise* activation for any value in f16 range, and gemma4
activations are O(1) after RMSNorm so nothing overflows. **A more precise input
format cannot produce a 10.9 KL gap.** That is what rules out "different
arithmetic contract, bounded by the gate" and leaves a kernel defect.
