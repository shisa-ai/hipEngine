# RF-8.1 declared-owner resolver fallback and source merge

## Summary

RF-8.1 makes capability ownership explicit on both read paths before any
compatibility alias is removed. `hip_gfx1151` now declares its ordered policy
owners once (`POLICY_MODULE_NAMES`), derives its module references from that
declaration, and `backend_package_capability` falls through to those owners for
a name the package does not bind. The cold source reader performs the same
bounded merge for the same declaration. The alias block and `__all__` are
unchanged in this unit; alias deletion and consumer migration stay separate,
dependent units.

## Changes

- `hipengine/kernels/hip_gfx1151/__init__.py`: one literal ordered owner
  declaration `POLICY_MODULE_NAMES = ("policy_capability", "policy_gguf",
  "policy_laguna")` and `_POLICY_MODULES` derived from it with `import_module`,
  so the runtime references cannot drift from the declaration. No alias, no
  `__all__`, and no registration change.
- `hipengine/kernels/backends.py`: `backend_package_capability` reads the
  package binding first (an explicit `None`/`False` is a real value), then the
  backend's `_POLICY_MODULES` in declaration order, then the caller default.
  Nothing is cached; no backend or quant branch was added.
- `hipengine/loading/backend_source_literals.py`: root reads merge the declared
  owners' uppercase module constants. The merge is cold, root-only, bounded by
  the existing depth and cycle guards, and fail-closed: absent, nonliteral,
  non-tuple, non-string, or non-identifier declarations contribute no owners,
  and a package binding always wins, including a nonliteral one. New public
  constant `POLICY_MODULE_NAMES_DECLARATION`.
- Tests: owner-declaration identity/order, collision freedom, per-name owner
  fallback with the package binding removed, falsy/`None` package precedence
  without owner mutation, owner-value mutation visible with the package binding
  absent (no cache), unknown-name and peer-backend defaults (capability
  boundary); declared-owner merge, package precedence including explicit
  `None`/`False` bindings, malformed/missing/nonliteral/path-escape
  declarations, duplicate ordered owner names, an unparseable or absent
  declared owner, and two-module plus owner-to-root cycles (source-literal
  fixtures); the capability ledger now follows the package's own owner
  declaration instead of assuming initializer aliases, and the boundary
  comment that still described the ledger as initializer-only is corrected.
- Worklog: this entry.

Measured on the live tree: 376 uppercase owner declarations across the three
policy modules, no divergent collisions (the three geometry names are the same
object re-imported by `policy_gguf`), and every one of the 376 resolves to the
identical owner object through `backend_package_capability` with its package
binding deleted. A scratch copy of the package with exactly its 396-line
compatibility region removed (373 alias assignments, first alias line through
last, verified by AST; scratch only) reads all 376 names from source with none
absent; `GGUF_CONSUMER_LAYERS` stays literal with its 10 layers and
`backend_gguf_consumer_layers("hip_gfx1151")` agrees.
