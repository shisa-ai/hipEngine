## Changes

### Shared physical owner and operand inventory

`hipengine/loading/qwen35_gguf_native_operands.py` adds:

- `NativeRowsOperands`: the actual session-owned launch/readback plan, consumed
  by native enqueue, eager readback and graph replay. It includes token input,
  BF16 hidden A/B, F32 logits, i32 cu_seqlens and i64 state indices, sampler
  block values/indices, sampler output index/value, and the persistent i32 host
  token destination. Every device view must be an allocator-owned member,
  aligned, correctly typed when typed metadata exists, large enough for the
  requested rows, and non-overlapping with incompatible roles. The i32 sampler
  views use the existing larger i64-sized allocations without reallocating or
  changing arithmetic. The runner uses its existing sampler shape helper to
  validate block geometry; threads/blocks remain in the captured identity.
- `physical_operand_inventory`: recursively traverses all named dataclass
  scratch fields, nested KV spans/scale metadata, cache tuples, Tensor views,
  owning buffers and host array metadata. Pointer, extent, dtype, device,
  shape/stride and static geometry are bound with their complete alias paths.
  It does not reduce the inventory to `scratch.buffers`. New typed-owner fields
  are automatically traversed, including scalar pointer tuples. Host ndarrays
  bind address/shape/dtype/strides, not changing token/position/state contents.
  Span max-live values are excluded from the physical inventory; the issued
  invocation independently pins its actual decode bound. This permits dynamic
  positions while refusing changed kernel geometry or graph context bounds.
- `NativeIndexBinding`: records the canonical compact independent-row host
  metadata, buffer identity/extent and dtype. The actual session allocator
  records it **after** the existing successful H2D copies of i32 `arange(C+1)`
  and i64 `arange(C)`. Native calls consume only the requested row-prefix and
  refuse missing/changed/permuted/short publications. The native consumers are
  read-only users of these arrays. This is producer/ownership evidence, **not
  a claim to have read or verified device contents**; arbitrary external writes
  cannot be inferred correct from a pointer. CPU tests explicitly mock that
  producer boundary.

### Context, callers and ordering

- `NativeInvocationContext.issue` is a session-owner operation. It requires
  current F4 authorization and the shared operand plan, and compares the
  supplied scratch against the real owner's `_native_compact_scratch` result.
  The compact-prefix Tensor views are constructed by the existing production
  owner, not an admission-side reimplementation of KV layout.
- Both `_run_linear_attention_decode_rows_native` and
  `_run_full_attention_decode_rows_native` require this context before library,
  runtime or kernel access. Validation binds the actual runner/runtime, layer
  type and geometry, scratch views and current operand plan. Supplied hidden
  and output pointers must equal the full-stack plan's BF16 ping-pong row-prefix
  views; supplied cu/state pointers must equal the published compact index
  views. Null, unowned, undersized, dtype-mismatched or unrequested offset views
  refuse even with qualified resident weights and an otherwise valid context.
  A context cannot substitute a different cached operand plan or foreign
  scratch, or change its rows/decode bound. Legacy `None` contexts grant no
  authority. Existing two direct production call sites both forward context.
- `step_rows_native` and `capture_native_rows_graph` retain their pre-mutation
  authorization checks, now using the complete operand inventory. They issue
  the context and forward it to actual enqueue; enqueue validates it before
  embedding or any layer. Enqueue uses the plan for embedding, ping-pong,
  indices, logits and all sampler writes. Eager and graph host readbacks use
  that same plan rather than independently reading mutable session fields.
- Capture stores the issued context. Replay compares current authorization,
  all named physical views, sampler/readback owners and freshly derived compact
  views against it before token H2D, position publication, graph launch or
  readback. Replacing sampler, KV, position or rotary views while leaving the
  allocator's buffer list unchanged now refuses. Stable owners with changed
  array contents remain legal. Graph rows/span-role/context bounds stay bound.
- No general runner rewrite or new dispatch mirror: two layer signatures and
  the native enqueue gain only the scoped context argument. Availability,
  registry keys, kernels, loader plans, arithmetic, state layout and public c1/
  prefill scopes are unchanged. Direct arbitrary-offset diagnostic calls must
  obtain an appropriate owner context; this is not permission for bare pointer
  calls. The production compact row-prefix and KV subviews remain supported.

### Tests and documentation

- New `tests/test_gguf_native_physical_operands.py` has 65 CPU cases. Qualified
  real tiny loader residents cover both linear and full-attention layers.
  Tests include actual successful capture then replacement of all four sampler
  fields, the host readback array, named KV caches and position/rotary views;
  null/nonzero/offset/undersized/dtype direct arguments with an issued context;
  malformed or missing index publication; both legal direct layer entries;
  real compact-prefix construction; foreign nested views; actual enqueue
  context forwarding and sampler argument order; same-owner changing-content
  replay; and an AST check that native launch/readback callers use the shared
  operand plan rather than stray session pointer fields.
- Existing native mocks now model the actual sampler buffers, aligned owning
  allocations, host readback array and canonical index publication. The F4
  mixed-GDN caller test retains its dtype/cast assertions and now supplies the
  actual context and owned pointers. No certificate or ownership check is
  monkeypatched away in the positive direct-entry tests.
- PLAN and UD-QUANTS explicitly correct the prior HIGH gaps and retain F1
  pending review/F5 OPEN. REFACTOR updates the existing repeated-scan debt:
  contexts now exist, but live revalidation is intentional, not an unkeyed
  authorization cache or a claimed performance improvement.
