# Classify a prefix-cache hit row's restored-checkpoint priming source

## Summary

Task #21 unit 2b, routing half. A prefix-cache hit row now has a named priming
source of its own -- `restored_checkpoint` -- with the same
`(source, invalid_reason)` contract the other sources answer to, so a hit row's
readiness says what it actually is instead of the generic `provider_state_absent`
it used to report. The engine half that feeds a hit row's suffix to the sink is
not wired yet, and that fact is published as a reason rather than hidden: a row
whose checkpoint is complete and current reports
`restored_checkpoint_suffix_unavailable_k0` until 2a lands.

## Changes

- `hipengine/speculative/accounting.py`: `PRIMING_SOURCE_RESTORED =
  "restored_checkpoint"`, added to `PRIMING_SOURCES`.
- `hipengine/generation/qwen35_gguf_mtp2.py`:
  `_priming_source` routes a row with `prefix_reused_tokens > 0` to
  `_restored_priming_source`, because such a row is prefilled only after the
  reused prefix and can never take its provider state from prompt rows.
  `_lookup_prefix_checkpoint` resolves the row's current block ids through the
  same `prefix_checkpoint_key` the capture uses and asks the store for the token
  prefix, so a hit whose ids have moved is a miss rather than a restore into the
  wrong blocks. Three reasons, in the order they can occur:
  `restored_checkpoint_absent_k0` (no store, no ids, or a failed validation),
  `restored_checkpoint_stale_k0` (`generated > 1`, the same currency rule the
  buffered source carries -- a restore lands the provider at the boundary, which
  is the row's current position only while it has generated at most that first
  token), and `restored_checkpoint_suffix_unavailable_k0` (checkpoint valid,
  engine half missing).
- `docs/REFACTOR.md`: the `prefix_reuse_k0` entry now records what is in place
  and names both remaining gates -- the reason above and the runner-side
  `prefix_reuse_k0` label with the `prefill_activation_ready` /
  `prefill_needs_activation` shortcut that treats a reused row as never priming
  a provider.

## Validation

- `tests/test_unit_qwen35_gguf_mtp2_seam.py`: a hit row with no capture in the
  process reports absent; a valid checkpoint reports the suffix-unavailable
  reason; a row past its first draft step reports stale; moved block ids and a
  prefix below one block both report absent rather than restoring; a row with no
  reused prefix still reports absent then buffered, so the new branch does not
  capture ordinary rows.
- Focused bundle (seam, session, checkpoint, store, accounting, shadow
  lifecycle, prefix-reuse gate) -> 245 passed; `-k "mtp or prefix or accounting"`
