# TP2 layer-0 MLP boundary is the bf16 rounding floor

## Summary

Finished the same-input layer-0 MLP comparison that the previous checkpoint
(`ec797a0f6`) left open, and it clears the sharded MLP chain as a defect source.
On the W7900 + RX 7900 XTX pair with the production profile bound in-process and
a 64-token `mixed_ja_en_translate` prompt, the layer-0 MLP input
(`post_norm`, `residual`) is **bit-identical** to the resident TP1 bulk teacher,
the concatenated rank activation reproduces the teacher's full-width activation
**bit-identically** (1,114,112 cells, both rank slices), and every
schedule-internal step of the TP2 route is exact on both ranks: the staged f32
reduce equals the sum of the staged bf16 partials to rel `5.11e-11`, `cast` is
exactly the bf16 rounding of `reduced`, and `out` is exactly
`bf16(residual + cast)`.

The entire remaining difference is confined to the down projection and sits at
the bf16 rounding floor: `cast` vs the teacher's `ffn_down` is max_abs `0.125` /
rel `6.90e-03` (110,629 of 327,680 cells, 17,021 beyond one bf16 ULP), and the
same difference survives the residual add at the layer output. An independent
numpy f32 reference built from the dequantized layer-0 weights separates the
terms: f32 partials vs the full-width f32 projection differ by rel `1.05e-07`
(reassociation only), the bf16 partial boundary costs max_abs `0.0309` / rel
`1.70e-03`, and **each route's own output deviates from that same f32 reference
by 1-2 bf16 ULPs** (teacher `0.125`, candidate `0.0625`). So roughly half the
observed gap is the shipped bf16 partial boundary and the rest is the two down
kernels' own f32 accumulation order — not weight slicing, layout, kernel
selection, or state ownership. No production code changed, no threshold moved,
and the bulk route stays opt-in and default-off.

## Changes

- `scripts/tp2_layer0_mlp_capture.py` (new, from the preserved handoff): the
  layer-0 dense-MLP capture descriptors plus an independent numpy/float32
  reference for both schedules (`reference_full_width_mlp`,
  `reference_sharded_mlp`), with no `hipengine` imports so the schedule
  arithmetic and descriptor logic are CPU-testable.
- `scripts/tp2_layer0_mlp_reference_check.py` (new, from the preserved handoff):
  offline consumer of the capture `.npz`. Compares the captured arms against the
  reference and separates `activation_kernel_error`, `shard_kernel_error`,
  `partial_rounding`, and `reassociation`.
- `scripts/tp2_bulk_vs_resident_layer0.py`: MLP capture wiring — per-route
  recorders armed for layer 0 only, producer-derived descriptors, and a
  `mlp_comparison` / `earliest_mlp_divergence` block in the report; the capture
  `.npz` gains the `{tag}.mlp.{name}` payload.
- **Defect fixed in the preserved tooling** (it crashed before producing any
  output, so the handoff had no reference result):
  `scripts/tp2_layer0_mlp_capture.py::reference_exact_partials` is the single
  source of the per-rank down partials, and it slices the **activation and the
  weight on the same `ffn` range**. The inline version in the reference check
  contracted the *full-width* activation against a shard-width down slice
  (`intermediate @ down[:, start:stop].T`), which has the wrong inner dimension
  (`ffn` against `ffn / ranks`) and raised `ValueError` — it never reached the
  down-boundary block. `reference_sharded_mlp` now calls the same helper instead
  of duplicating the slicing.
- `tests/test_unit_scripts_tp2_layer0_mlp_capture.py`: the preserved 29 CPU tests
  plus the `reference_exact_partials` regression (shapes, bit-equality with the
  both-sliced expression, agreement with `reference_sharded_mlp`'s own partials,
  a zero-the-other-rank's-columns invariant that a full-width contraction
  cannot satisfy, and fail-closed width/rank checks).
- `tests/test_unit_scripts_tp2_layer0_mlp_reference_check.py` (new): drives
  `main()` end to end on a synthetic capture built from the reference itself
  (same key naming and raw-byte encoding), asserting the down-boundary block is
  computed from the shard activation (no cell beyond the local bf16 half-ULP of
  its own exact slice) and that the reference separates partial rounding from
  reassociation.
- Docs/artifacts: `benchmarks/results/2026-09-17-w7900-tp2-layer0-mlp-boundary.json`,
  `benchmarks/CHANGELOG.md`, `docs/QWEN38-27B-GFX1100-TP2.md` (measured layer-0
  MLP boundary, remaining-work note), `docs/REFACTOR.md` (the open
  envelope item now records that the layer-0 MLP chain is cleared as a defect
