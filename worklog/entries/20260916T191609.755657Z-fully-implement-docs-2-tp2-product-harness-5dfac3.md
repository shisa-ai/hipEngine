# Implement native-product timing and sustained shared-trajectory gates RED first

## Summary

Implemented the authorized next measurement protocol in the **existing**
matched-AR harness and coverage machinery. This commit is harness preparation,
not a measured result. The interrupted predecessor left only the product RED
tests/log; no hardware work was running on resume, and none was restarted.

## Changes

- `scripts/tp2_matched_ar_baseline.py`: explicit `--protocol product`, fresh
  product workers and fail-first Latin-rotated parent; per-arm idle gate; exact
  prompt/token/repetition identity; required model/source/staged-diff/profile/
  capacity and actual route/scope evidence. Refuse missing, failed or stale
  sustained D128 correctness before launching measurements or emitting ratios.
  The original matched-transfer diagnostic remains a distinct mode.
- One common outer host clock encloses each decode loop on both arms. TP1 uses
  its state-bound graph with token-only readback except the last full logits;
  TP2 uses its normal graphed `_forward_token`, full-logit readback, CPU argmax,
  and native StepTrace construction. Trace sums are attribution only, never a
  denominator. Final finiteness is checked after the timers; all-position
  numerical diagnostics run in the separate companion.
- Count **128 transitions at P..P+127**, plus the prefill sample: **129 samples**.
  Explicitly not API `max_new_tokens=128` completion latency. Steady throughput
  divides actual transitions by the outer decode wall; generation throughput
  divides 129 samples by the generation wall. Prefill, request capture/close,
  one-time TP2 capture/destroy, model teardown/load, and global warmup are
  separate fields. Session end-to-end adds actual one-time capture/destroy and
  natural teardown; model load and global warmup are reported separately.
- `scripts/tp2_resident_control.py`: a native adapter over existing primitives,
  no kernel/engine change. Product TP1 does not allocate the diagnostic hidden
  capture slab. Extra teacher forcing and actual device-control readback are
  correctness-only methods, never called in product timers.
- `scripts/tp2_teacher_coverage_broad.py`: sustained companion over the same 18
  product prompts and 128 decode positions each (2,304 scored rows). TP1-d0
  chooses a shared trajectory; every arm/repeat forces those inputs. The chooser
  also performs the same exact input-copy/control schedule, so repeated runs
  have the same schedule. Every row must be finite with exact controls; an
  absolute KL ceiling failure saves the first row pair and stops immediately.
  First-sweep global/category/canonical/heldout envelope failures stop before
  further repeats. Three repeats and reset/neighbor/generation-reset controls
  are required. Task/BF16-relative/public distributed qualification stays false.
- `tests/test_unit_tp2_product_baseline.py`: main/adapter tests for native
  transfers, clocks/counts, weighted rates, actual prompt hashes, repetitions,
  physical denominator choice, missing provenance, nonfinite data, and stop on
  first fault. `tests/test_unit_tp2_sustained_quality.py`: shared inputs instead
  of candidate rollouts, repeat schedule, numerical ceiling and control-stop
  tests. No user bisect/`epyc/` changes.
