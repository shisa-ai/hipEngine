# gfx1151 fp16-state decode_order state-rows prefill writers

## Summary

Follow-up to the R2 fp16 recurrent-state device change
(`worklog/entries/20260818T212108.040509Z-lhl-qwen38-gfx1151-r2-fp16-recurrent-state-device-74f6a4.md`,
commit 5895c8879). That change fail-closed when the flag was combined with the
packed-prefill verify-capture decode_order state-rows writers because those
kernels had no fp16-state variant. This unit templates the two decode-order
state-rows prefill kernels on `state_t` (fp32 strict identity vs fp16
production storage, fp32 accumulate, RNE half round-trip) and adds the fp16
launchers, Python wrappers, and registry entry so the packed-prefill
decode_order capture path can be fp16-capable under the flag.

## Changes

- `gdn.hip`: `qwen35_gdn_state_read` and the two decode-order state-rows
  kernels (`qwen35_gdn_prefill_recurrent_rmsnorm_gate_decode_order_kernel`
  and `..._decode_order_segments_state_rows_kernel`) are now templated on
  `state_t`; all state reads/writes use the existing typed
  `gdn_state_read_qwen35`/`gdn_state_write_qwen35` helpers. Existing strict
  launchers explicitly instantiate `float` (the HIP launch macro does not
  apply the default `state_t` deduction through `nullptr`).
- Added `extern "C"` fp16 launchers
  `...decode_order_state_rows_no_copy_fp16state` and
  `...decode_order_segments_state_rows_no_copy_fp16state` (half_t state
  buffers).
- `gdn.py`: fp16 symbol constants, the two fp16 wrapper functions, and a
  `decode_order_bf16_segments_state_rows_no_copy_fp16state` registry entry.
  (The non-segmented no-copy writer has no strict registry entry either, so it
  is exercised directly through the wrapper only.)
- `linear_attn/__init__.py`: exported the two fp16 wrappers.

## Validation

- Two new RED tests in `tests/test_qwen35_gguf_gdn_fp16_state.py` vs a host
  fp16-state decode-order replay with per-token row capture:
  - `...state_rows_no_copy_matches_host_replay` (single segment): output
    rtol 5e-2/atol 5e-3 (BF16-quantized out), rows rtol/atol 2e-3 (~2 fp16
    ULPs).
  - `...segments_state_rows_no_copy_matches_host_replay` (two segments, packed
    rows, distinct initial slots): output + rows close, and the fp16 initial
    slots are byte-untouched (no-copy).
- Full `tests/test_qwen35_gguf_gdn_fp16_state.py` bundle (5 tests) passes on
  gfx1151 (HIP build with new symbols).
- Strict path unchanged: the two strict decode-order state-rows oracle tests
  in `test_qwen35_gguf_gdn_prefill_correctness.py` pass (fp32 identity
  templates), and the gdn plan/routing/session-mode registry bundles pass.
