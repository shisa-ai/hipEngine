# Correct selected-device resolution for the backend capability check

## Summary

Commit `869000432` added the HIP-backend capability refusal but resolved the
selected device incorrectly. Review found three P1 defects, all reproduced
before the fix:

1. **Dedupe loses the device index.** `selected_device_arches` collapsed the host
   architecture list before indexing it, so
   `("gfx1100", "gfx1100", "gfx1151")` with `ROCR_VISIBLE_DEVICES=1` resolved to
   `gfx1151` (device 1 is a gfx1100) and wrongly admitted `hip_gfx1151`. The
   same dedupe turned `("gfx1100", "gfx1100")` index 1 into an out-of-range
   index and returned an empty (permissive) set.
2. **Host membership is not current-device validation.** With no visibility
   filter the old code returned every host architecture, so a gfx1151 on device 1
   excused gfx1151 kernels launched on the default device 0.
3. **The visibility variables compose; they are not precedence.**
   `("gfx1100", "gfx1151")` with `ROCR_VISIBLE_DEVICES=1` and
   `HIP_VISIBLE_DEVICES=0` has logical device 0 = gfx1151, but the old code let
   `HIP_VISIBLE_DEVICES` win and reported gfx1100.

## Producer semantics (verified, not assumed)

On ROCm 7.2 with two gfx1100 cards, `amdgpu-arch` and `rocm_agent_enumerator`
each print **one architecture per physical device, in device order, duplicates
preserved**, and both **ignore** `ROCR_VISIBLE_DEVICES`/`HIP_VISIBLE_DEVICES`
(2 lines for `=unset`, `=0`, `=1`, and `=0,1`; same for `HIP_VISIBLE_DEVICES`).
`_parse_arches` then deduplicated that list, which is where defect 1 entered.

So the probe is the physical device list, and the visibility remap must be
applied by the caller exactly once.

## Design

- `detect_hip_physical_device_arches()`: per-device architecture list, device
  order, duplicates preserved. Runs the arch command with the visibility
  variables removed so the result is the physical list on every ROCm release,
  whether or not a given release makes the tool visibility-aware. This is what
  prevents double-filtering an already-visible list. `detect_hip_target_arches`
  (deduped, ambient) is unchanged for auto selection and the provenance/benchmark
  consumers.
- `_visible_logical_device_arches()`: applies `ROCR_VISIBLE_DEVICES` to the
  physical list, then `HIP_VISIBLE_DEVICES` to the result. `None` when a variable
  cannot be resolved to device indices or names an out-of-range index.
- `selected_device_arches(..., current_device=None)`: returns the architecture of
  the **current logical device**. When `current_device` is omitted and the
  visible devices disagree on architecture, the ordinal comes from
  `hipGetDevice`; a homogeneous visible set never loads the HIP runtime, and a
  host without ROCm falls back to logical device 0.
- `_current_hip_device_ordinal()`: `hipGetDevice` through `ctypes` using only
  scalar APIs, so there is no `hipDeviceProp_t` ABI hazard. Returns `None` when
  `libamdhip64.so` is unavailable.

Why logical device 0 is the fallback rather than a runtime query on every call:
hipEngine has no `hipSetDevice` path, so the engine executes on the default
logical device. Querying `hipGetDevice` initializes the HIP runtime, and the
refusal is required to land before device work; the query is therefore limited
to the ambiguous (heterogeneous) case where it changes the decision.

## Changes

- `hipengine/kernels/backends.py`: `detect_hip_physical_device_arches`,
  `_parse_arches_ordered`, `_parse_visible_device_indices`,
  `_visible_logical_device_arches`, `_current_hip_device_ordinal`; rewrote
  `selected_device_arches` and `require_backend_device_compatibility`
  (`current_device` parameter); removed `_visible_device_indices`.
- `tests/test_unit_backend_device_capability.py`: replaced the wrong-precedence
  assertion with the composition contract; added duplicate-index, same-arch
  two-card, mixed-host current-device, visibility-composition, permissive-only-
  when-unavailable, homogeneous-no-runtime, and public-seam sentinel cases.

## Validation

- RED against `869000432` (backends.py stashed), old `selected_device_arches`:
  - `("gfx1100","gfx1100","gfx1151")` + `ROCR=1` -> `('gfx1151',)`, and
    `hip_gfx1151` was **admitted** (defect 1).
  - `("gfx1100","gfx1100")` + `ROCR=1` -> `()` (dedupe artifact, defect 1b).
  - `("gfx1100","gfx1151")` no filter -> `('gfx1100','gfx1151')`, `hip_gfx1151`
    **admitted** (defect 2).
  - `("gfx1100","gfx1151")` + `ROCR=1 HIP=0` -> `('gfx1100',)` (defect 3).
- GREEN: `tests/test_unit_backend_device_capability.py` -> `17 passed`.
- Affected CPU bundle (`test_unit_backend_device_capability`,
  `test_unit_gfx1151_backend`, `test_unit_cuda_sm120a_backend`,
  `test_unit_ud_hip_guard`, `test_unit_gemma4_expert_route`,
  `test_unit_vibevoice_registry`, `test_unit_llm_generate`) -> `189 passed` in
  134 s. Registry-only resolution (`resolve_vibevoice_kernels`) is unaffected.
- Public fail-fast, CPU, real model path, no GPU window: 
  `LLM("/models/gguf/Qwen3.8-27B-Q4_K_M.gguf", backend="hip_gfx1151").generate(...)`

  `resolve_text_generator`, `load_backend_kernel_package`, and
  `_current_hip_device_ordinal` to prove no generator, weight load, or device
  work runs; the GGUF index metadata read is the only prior step and is stubbed
  in the test.
- Runtime query path on GPU1 (`ROCR_VISIBLE_DEVICES=1`, GPU1 free):
  `detect_hip_physical_device_arches()` -> `('gfx1100','gfx1100')`;
  `_current_hip_device_ordinal()` -> `0`; a synthetic mixed host with no filter
  is refused through the real `hipGetDevice` path.
