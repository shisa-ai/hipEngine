# Fail long SPECDEC2 activation before provider mutation

## Summary

Complete the long-context rejection by moving it before provider streaming.
Restoring `max_context_tokens=1023` alone was insufficient because the target
prefill owner opens before the scheduler's post-prefill capability plan. A p4K
request could therefore mutate/allocate complete NextN state and only then
select K0.

## Changes

- `begin_prompt_streaming()` checks prompt room against min(1023, live target
  capacity) before acquiring/resetting a provider or allocating a sink.
- Unsupported long rows clear speculative intent and report `target_context_k0`.
- Add a focused test proving no provider acquisition, sink, or staged state.
