# Extract JSON Schema subset/value validators from the server API

## Summary

`hipengine/server/api.py` no longer defines the JSON Schema subset and value
validators. They now live in `hipengine/server/json_schema.py`, which depends
only on the standard library: it imports neither FastAPI nor the HTTP
application, and no engine, model, runtime, dispatch, or loading module.

The moved definitions are the fourteen cohesive functions from
`_json_schema_pointer_token` through `_primary_json_schema_type` plus
`_JSON_SCHEMA_SUPPORTED_TYPES`, `_JSON_SCHEMA_SUPPORTED_KEYS`, and the
`_JSON_SCHEMA_ANNOTATION_KEYWORDS` tuple that `_JSON_SCHEMA_SUPPORTED_KEYS`
expands. `api.py` imports all seventeen names and keeps them as private
aliases, so `hipengine.server.api._validate_json_schema_value` and every other
existing name still resolve to the identical objects.

This is a move-only boundary unit under RF-7. No error tuple, message, path,
numeric or boolean rule, local JSON Pointer resolution, cycle detection,
JSON-value equality, regex semantics, route, flag, or scheduling behavior
changed.

## Changes

- `hipengine/server/json_schema.py` (new)
  - Owns `_JSON_SCHEMA_ANNOTATION_KEYWORDS`, `_JSON_SCHEMA_SUPPORTED_TYPES`,
    `_JSON_SCHEMA_SUPPORTED_KEYS`, `_json_schema_pointer_token`,
    `_json_schema_resolve_local_ref`, `_validate_json_schema_subset`,
    `_validate_json_schema_value`, `_schema_nonnegative_int`,
    `_schema_finite_number`, `_schema_positive_finite_number`,
    `_schema_decimal_number`, `_schema_number_is_multiple_of`,
    `_schema_array_items_unique`, `_schema_json_values_equal`,
    `_schema_json_value_kind`, `_json_schema_type_matches`, and
    `_primary_json_schema_type`.
  - Function bodies and constants were extracted byte-for-byte (33,242
    characters of function text and the constant block compare equal to
    `HEAD:hipengine/server/api.py`).
- `hipengine/server/api.py`
  - Removed the moved definitions and the now-unused `decimal` and
    `urllib.parse.unquote` imports; `math` and `re` remain because other
    functions in the module use them.
  - Imports the seventeen names from `hipengine.server.json_schema`, preserving
    identity and the existing `hipengine.server.api` import surface.
- `tests/test_unit_server_json_schema_boundary.py` (new)
  - Pins the module's stdlib-only AST imports, standalone file import without
    `hipengine`/FastAPI/Starlette/torch, and package import without the HTTP
    app, generation, runtime, models, KV cache, speculative, LLM, kernels,
    dispatch, loading, or quant modules.
  - Asserts `api.py` imports every moved name from the owner module, defines
    none of them locally, and exposes identical objects.
  - Embeds the pre-move results for 85 schema cases and 95 value cases plus the
    pointer, ref-resolution, numeric-helper, uniqueness, equality, kind,
    type-match, and primary-type tables, so behavior is checked against the old
    implementation rather than against the module itself.
  - Adds focused checks for regex error messages and search semantics, cycles at
    both layers, boolean-is-never-number, and `:g` numeric message formatting.
