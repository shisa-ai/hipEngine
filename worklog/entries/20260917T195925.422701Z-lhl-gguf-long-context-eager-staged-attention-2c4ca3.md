# Long-context eager MTP verification keeps full-attention rows staged

## Summary

The staged full-attention chain used to refuse any verifier batch whose
span-wide attention limit crossed the split-K threshold, so an eager
verification that straddled the 1024-token split boundary dropped every
full-attention layer back to the scalar row-wise owner. The chain now resolves
each row's own c1 leaf instead of the span-wide one, so rows on both sides of
the boundary stay inside one batched projection / head-norm / rotary / KV-write /
output-projection chain. On the retained 10-case eager packet (cycle ends
1024/1025 x B1/B2/B3 plus the four controlled B3 acceptance cases) the packet's
own cycle wall moves **8.129 s -> 7.893 s median (-2.9%, 7 of 10 cases faster)**
with every exactness flag unchanged against the serial-exact teacher, and the
long-context target graph at cycle end 1032 keeps its exactness and its
32/48/64 split-K calls.

Two defects had to be fixed on the way, and both were invisible to the gate
until the route actually ran:

1. A row below the threshold must attend on the leaf the scalar owner picks from
   its own `position + 1` cap. On `hip_gfx1151`
   (`GGUF_SHORT_C1_BATCH_ATTN_MAX_CONTEXT = 1023`) that is the short-context
   batch leaf, not the plain non-split leaf, and the first version of the chain
   launched the plain leaf for row 0 of a 1024 cycle end. The gate caught it as a
   Conv/GDN-state divergence from layer 12 and a K/V divergence from layer 15.
   Verified by reading the leaf: both non-split leaves loop over the row's live
   count, so `max_context_len` is inert and the *leaf choice*, not the bound, was
   the difference.
2. The per-row leaf must also resolve when the scalar owner reaches the split
   leaf through a backend short-context split policy
   (`GGUF_SHORT_C1_SPLIT_ATTN_POLICIES`, `(1024, 24, 8, 2, 256, 256, 256) ->
   (514, 641)` on gfx1151) rather than the long-context threshold, or such a row
   would silently attend on the non-split leaf.

The eager per-row attention limit is deliberately left at the span-wide value:
the kernel bound is the row's live count, the staged chain's existing contract
passes the span limit, and changing it moved no arithmetic when measured.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`
  - New `_staged_full_attention_row_leaf(config, *, backend, scratch,
    row_scratch, position)`: resolves one row's split-K gate leaf, chunk size and
    split tiling from its own `active_context = position + 1`, on either the
    long-context threshold or a backend short-context split policy, and declines
    when the split workspace or the registered leaf is missing.
  - New `_staged_full_attention_rows_ready(...)`: the caller's gate. Every row
    must carry a scalar position and resolve a leaf; otherwise the layer keeps
    the row-wise strict route.
  - `_run_full_attention_attn_chain_rows_exact`: replaced the
    `_use_gguf_full_attention_split_decode(attention_context_limit)` refusal with
    per-row leaves. Split rows run the split gate leaf with the scalar owner's
    own chunk size and split count; non-split rows run the short-context batch
    leaf or the plain leaf, whichever the scalar owner would pick, followed by
    the same standalone gate multiply. The shared-cache batch branch is used only
    when no row needs split-K. A row that needs a split leaf and cannot resolve
    one now raises instead of silently attending with the slower leaf.
  - `_eager_native_row_views(...)`: builds the per-row attention views the graph
    owner already gets from device metadata, so eager verification stages the
    same rows (bulk-scratch position/context entries plus the resident page
    table) instead of handing the chain no views at all.
  - `verify_target_block`: builds those views for a native multi-row block whose
    span end crosses the split threshold, passes them with the span end as the
    coverage bound, and keeps the scalar owner's own `position + 1` cap on the
    row-wise loop (`row_views_keep_scalar_caps`) so a view never changes which
    leaf a row resolves to.
- `tests/test_live_gguf_native_spec_cycle.py`: four new cases - split-K rows
  across the split boundary (batched projections plus one leaf per row, row 0 on
  the non-split leaf), the same without a shared cache owner, a refusal when a
  long-context row has no split leaf, and the caller keeping dense
  full-attention rows staged at long context.
- `benchmarks/results/2026-09-18-gfx1151-qwen38-long-context-eager-verifier-staged-chain.json`,
  `benchmarks/CHANGELOG.md`, `benchmarks/README.md`.

  `kv_rows_exact` and `target_logits_exact` all true. The graph captures

- Correctness (graph route, real host-proposal generation at context 1024 with
