# W7900: correct the C2 mechanism claim - projection dispatch is PARO-only, the flag means a different decode path

## Summary

Supersedes the mechanism section of
`worklog/entries/20260830T050921.498416Z-lhl-w7900-ar-c2-decode-amortization-87cc7e.md`. That entry
claimed `throughput_claim_eligible` false in 80/80 AR cells showed the projection dispatch falling
back to `row_gemv_until_caware_benchmark` for lack of a benchmark-accepted c-aware projection
candidate on this path. **That attribution is false.** The measurement in the entry - decode
amortizing at 1.00x/1.52x/1.62x/2.69x of the weight-read ideal at C1/C2/C3/C8 - stands, because it is
arithmetic over published rate rows minus an independently measured prefill wall, but the cause is
open again.

## Validation

`grep -rln projection_dispatch hipengine/` returns `dispatch/projection.py`, `dispatch/__init__.py`
and `runtime/qwen35_paro_runner.py` only - the c-aware projection decision is not reachable from the
GGUF path at all. For GGUF the field is computed at `qwen35_gguf.py:9005` as
`bool(native_batch and native_decode_steps > 0)`, and `native_batch=True` appears at exactly one site
(:1877), inside a `generate_detailed` branch gated by `plan.mode is GREEDY_FAST and
len(request.prompts) > 1 and self.native_batch_decode`. An earlier branch routes GREEDY_FAST
multi-prompt requests to `_generate_ar_serving_slots` whenever `_gguf_ar_packed_decode_enabled() or
_gguf_ar_stream_decode_enabled()`, which is why all 80 cells report
`path=gguf_packed_ar_server_decode`. So the flag distinguishes two c-aware decode implementations -
serving slots versus the native continuous batch path - and says nothing about projection admission.
`native_caware_decode` was true in all 70 width>1 cells under the flag being false, which is itself
the direct disproof of the old reading.

The error came from reading one producer (`dispatch/projection.py`) and assuming it was the producer
of a telemetry field that three modules also write as a literal (`laguna_gguf.py:779/1237`,
`qwen35_paro.py` x4). For a telemetry field, the check is which module builds *this* path's payload,
not which module contains the key.
