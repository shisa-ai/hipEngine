# Add request-local ngram-mod MTP composition

## Summary

Added the backend-neutral, request-local n-gram continuation owner needed for a
safe MTP composition spike. The implementation follows llama.cpp `ngram-mod`'s
long-suffix iterative continuation shape, but deliberately uses exact keys and
request-local state instead of a process-shared modulo table. This prevents
hash-collision candidates, cross-tenant history leakage, benchmark-order
contamination, and batch-composition-dependent proposal contents.

The cache returns only a verifier-bounded prefix after the configured long
continuation horizon is available. It synchronizes from scheduler-authoritative
committed history before every proposal; any shrink or non-append replacement
rebuilds the index, so rejected/cancelled candidates never become future input.

Source reviewed read-only: llama.cpp `common/ngram-mod.{h,cpp}` and
`common/speculative.cpp` at `9d57ce456c94d241dde672b2db9cf18879766568`.
