# x7 default-on attempt: decode-graph routing measured negative, reverted

## Summary

Attempted the X7 default-on: route single-token decode in
`Gemma4Runner.forward` through `Gemma4DecodeGraphSession` and A/B it on
the campaign bench. All three design variants lose — **64.43 tok/s
launched vs 60.30 / 60.66 / 61.21 with the route at 1024/128 (−6.4% /
−5.9% / −5.0%)**, public-chain parity=True every run. The routing was
reverted; the bitwise-proven session, the capture improvements, and the
full evidence chain stay. Launched decode is already device-bound: its
~10.5 ms/step of host submission is hidden under device work, so the
screen's submission saving cannot be collected, and the graph adds new
serial host instead.

## Changes

- `hipengine/runtime/gemma4_decode_graph.py` (kept):
  - **Global capture mode** (`hipStreamBeginCapture(mode=0)`) with
    `stream_moe=-1`, so the layer's parallel MoE stream and its event
    dependencies are recorded into the graph — replaces the single-stream
    fold, which alone cost ~0.45–0.7 ms/step of device overlap.
  - **Split-workspace pre-touch** before `streamBeginCapture`: the decode
    route's only lazy allocation is the attention split workspace, which
    is keyed per stream and *non-monotonic in key count* (measured:
    keys=1088 needs 69760 B where keys=8192 needs 65728 B), so a
    max-bucket warm cannot cover it; `hipMalloc` inside an active Global
    capture is rejected (HIP 900).
  - **Weak runner ref** (property `_runner`): the runner owns the session,
    so a strong back-ref made a cycle whose bulk is a 17 GB weight map —
    unreachable at refcount-zero until a cyclic gc the process never
    triggered; this showed up as cross-file OOM in combined live runs
    (identical OOM reproduced at clean HEAD for the unrelated
    fixture-leak half; the cycle half was mine and is fixed).
  - `launch(b, tables, masks)` closure so the warm/capture paths share one
    definition; docstring records the negative verdict and the v2 route.
- `hipengine/runtime/gemma4.py` + `tests/test_gpu_gemma4_decode_graph_capture.py`:
  routing edits **reverted** (files identical to 8df7acb86). During the
  attempt they also carried: the `forward` decode gate (`rows == 1 and
  position > 0 and not return_hidden`), a launched-first warm step (module
  loads may not run inside a capture), session close ordering in
  `runner.close` (buffers release drains the session stream, so it must
  precede `session.close()`), and route/close assertions in the test.
- `scratch/x7_graph_phase_probe.py`: the host/device split probe (wraps
  stage/launch/key/retarget/graph_launch/collect for both routes).
- `benchmarks/results/2026-09-30-gemma4-x7-graph-{pre,post,post2,post3}.json`:
  the four A/B artifacts (pre = launched baseline, post = fold+relaxed,
  post2 = Global+per-crossing warm, post3 = Global+pre-touch).
- `docs/campaigns/GEMMA4-26B-A4B-PUNCHLIST.md`: X7 row carries the
  attempt, numbers, and the clearing route.

## Validation

- Bitwise RED stayed green through every variant: replay == launched
  across consecutive positions, the 127 singleton, and the 128 boundary
  (`tests/test_gpu_gemma4_decode_graph_capture.py`), plus the bucket unit
  — final run after the revert: suite incl. contracts/generate/chat
  `exit=0`.
- Phase probe (prompt 1024, N=128): launched 15.60 ms/step (host enqueue
  10.48 hidden under device, collect 5.52); graph 15.78 (stage 0.14 +
  key 0.006 + retarget 0.17 + `hipGraphLaunch` 0.27 serial, collect
  15.29). Graph device is ~0.4 ms *faster*, but 0.59 ms of serial host is
  not hidden, and each capture re-records the ~780-launch chain (~10.5 ms
  host) once per 64-step bucket — which is why the summed bench (−5.0%)
  is worse than the median-based probe (+0.18 ms/step).
- Failure-path evidence during the attempt (all fixed or reverted):
  relaxed-mode fold lost MoE overlap; Global mode without pre-touch hit
  HIP 900 at the workspace malloc; the max-bucket dry run faulted the
  device (uncorrectable, surfaced at the next `stream_synchronize`); dry
  staging before key computation caused per-step recapture (key churn);
  session/stream close order segfaulted `attention.close`.
- `python3 scripts/docs/check_docs.py` rc=0;
  `python3 docs/campaigns/check_gemma4_punchlist.py` rc=0;
  combined live OOM combination reproduced identically at clean HEAD
  (pre-existing fixture-leak behavior; each file passes alone).
