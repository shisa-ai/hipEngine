# Qwen4Exp per-slot batch attention state ownership

## Summary

Adds the ownership prerequisite for sharing one paged dense-attention cache
across independent Qwen4Exp requests. `Qwen4ExpDenseAttentionState` in
`runtime/qwen4_exp_runner.py` owns one request (one cache, one page table, one
int64 position/context scalar), which is why N resident requests cost N full
copies of the per-layer state today.

New module `hipengine/runtime/qwen4_exp_batch_state.py` gives each physical
state slot its own disjoint block range with a full `max_positions` capacity, so
capacity stays additive in requests instead of being silently shared and
smaller. Slot `s` owns blocks
`[s * ceil(max_positions/block_size), (s+1) * ceil(...))`; total capacity is
`state_slots * ceil(max_positions/block_size) * block_size` tokens.

`prepare` packs the active rows into the leading metadata rows while the
physical slots they name stay arbitrary (sparse and permuted sets), so the
active width (`1 .. state_slots`) is independent of physical capacity and
shrinking/regrowing the active set never reallocates or remaps a slot. `prepare(slot_ids, positions)`
validates the whole row set on the host, then uploads only the active prefix of
the page table, position vector, and context vector, and returns the
`KVLiveSpans` append/decode views plus `max_context_len`.

This is an ownership/ABI unit. Nothing dispatches the new views yet; the runner
still calls the c1 wrappers, and no kernel changed.

## Changes

- `hipengine/runtime/qwen4_exp_batch_state.py` (new, 489 lines):
  - `Qwen4ExpBatchAttentionState.allocate(state_slots, max_positions,
    block_size, kv_heads, head_dim)` builds `arange` block partition, allocates
    K/V (`state_slots * blocks_per_request * block_size * kv_heads * head_dim *
    2` bytes each), a `(state_slots, blocks_per_request)` int32 page table, and
    `(state_slots,)` int64 position/context vectors. Metadata is published as
    zeros and K/V is zeroed so "never written" is a checkable value.
  - Shape products are bounded before a runtime is resolved or a host array is
    built (`_check_shape_products`), using the kernels' own integer types rather
    than invented limits: page-table entries are int32 physical block ids
    (`block_table[row * block_table_len + logical_block]` in both the write and
    batch dense-attention kernels), `live_counts`/position/context are int64,
    and K/V element offsets are the int64 product
    `(physical_block * block_size + block_offset) * kv_heads * head_dim` with a
    `size_t` byte count handed to the allocator. So `total_blocks - 1 <=
    INT32_MAX`, `max_positions <= INT64_MAX`, `kv_elements <= INT64_MAX`, and
    `kv_elements * 2 <= INT64_MAX`. The generic (non-precompute) decode route
    used here indexes in int64, so the narrower int32-offset bound of the
    fixed256 precompute variant does not apply.
  - Lifecycle cleanup is retry-safe and cannot be used after it starts:
    `_pending_free` holds the buffers in allocation order and a buffer leaves it
    only after its `free` returns, so a `hipFree` failure leaves the remainder
    owned instead of setting up a double free. `closing` is set *before the
    first free*, and `_require_open` rejects uploads on either `closed` or
    `closing`, because a partial close has already released the newest buffers
    (the context and position vectors `prepare` writes) while older ones remain
    owned. `close()` itself only guards on `closed`, so it may retry the
    remainder. `__enter__` checks open, so `with state:` cannot resurrect a
    closing state. A failed allocation frees the same way and attaches any
    cleanup failure as a note on the original error rather than masking it.
    `close()` also reclaims from the five buffer fields if the ownership list was
    never handed over, so a construction path cannot leak silently.
  - `prepare(slot_ids, positions)` requires 1..state_slots rows, in-range unique
    slots (permuted and sparse sets are supported and preserved as row order),
    in-range positions, equal lengths, and integer (non-bool) metadata. All
    validation happens before any device write, so a rejected call mutates
    nothing. A device-copy failure clears the active set (fail closed) rather
    than publishing a half-uploaded table.
  - `append_spans` (`live_counts` = positions, `max_live_count` =
    `max_positions - 1`) and `decode_spans` (`live_counts` = positions + 1,
    `max_live_count` = `max_positions`), both BF16 uniform spans over a
    row-major per-row page table. Access before `prepare` raises.
  - `active_rows` / `state_slots`, `blocks_per_request`, `slot_capacity_tokens`,
    `total_capacity_tokens`, `cache_bytes_per_slot`, `blocks_for_slot`;
    idempotent `close()`; context-manager support.
- `tests/test_unit_qwen4exp_batch_attention_state.py` (new, 43 tests): fake
  runtime records allocations, memsets, and copy payloads, so layout, uploaded
  bytes, sparse/permuted slot mapping, duplicate/out-of-range rejection,
  width shrink/regrow, invalid-metadata no-op, allocation cleanup, and
  idempotent close are all asserted without a device. Huge-geometry cases
  ((2^31)+1 slots, 2^63+1 positions, a 2^66-element K/V product, and a
  2^63-byte allocation) prove rejection with `get_hip_runtime` and
  `np.arange`/`np.zeros` replaced by spies that fail the test if reached, plus
  a fake runtime showing zero malloc/copy/memset calls. Bool geometry is
  rejected like any other non-integer. A close path with an injected `free`
  failure is retried and asserted to free each pointer exactly once, and the
  partial-close case asserts that `prepare`, `append_spans`, `decode_spans`, and
  `with state:` all refuse with zero further copies, memsets, or allocations
  before the retry releases the remainder.
- `tests/test_gpu_qwen4exp_batch_attention_state.py` (new, 8 tests):
  `4 slots x 1280 positions x block_size 256 x kv_heads 2 x head_dim 64`
  (1.31 MB per cache). Uses the existing
  `qwen35_write_paged_kv_f32_batch_spans` and
  `qwen35_paged_full_attn_decode_context_bf16_batch_spans` wrappers against the
  production `Qwen4ExpDenseAttentionState` c1 path at the same
  `max_positions`, plus the `qsa_sparse_gqa_attention` CPU oracle.

The batch dense-attention kernel selects a 1024-thread geometry when
`rows <= 2 and max_context_len < 1024` while the c1 kernel is fixed at 256
threads, so only that regime can differ; the measured deltas there are
`<= 7.45e-8` (asserted `< 1e-5`). Every geometry-matched case is asserted
bit-exact and measured 0.0, including the 1024-token context and the
`rows <= 2` long-context route.

max abs error `5.96e-8` (n4 boundary), `5.59e-8` (n4 long), `4.10e-8` (n1).

Also asserted: slots never admitted stay bit-zero across the whole cache;
within a written slot everything above `position + 1` stays zero; identical
`prepare` + decode reproduces bytes exactly; a permuted re-prepare moves each
output with its slot; a fresh state instance reproduces the reused instance's
bytes; writing slot 1 after slots 0/2 leaves both untouched.

## Next

- Runner integration: `runtime/qwen4_exp_runner.py` still builds
  `gdn_state_index` from the layer ordinal (`:2420`, `:8817-8832`) and passes
  `attention_state=self.attention_states[binding.qsa_state_index]` with
  `rows=1`, `position=self.position` (`:8849-8861`). Replacing the per-layer
  `Qwen4ExpDenseAttentionState` list with one
  `Qwen4ExpBatchAttentionState` per layer needs a request-to-slot assignment
  and an explicit state move on slot compaction, since state ownership is exact in
  every profile (`docs/EXECUTION-PROFILES.md` "Stateful ownership").
- Admission beyond this unit: prefill chunks and verify/MTP rows are sequence
  and candidate rows, not requests, so they must not be passed as independent
  active rows. A batch-width guard belongs with the mixer, not here.
- Capacity contract change: today c2 costs 2x the full per-request state; a
  shared cache makes the per-layer budget `state_slots * max_positions` and the
  user-visible limit "sum of resident contexts", which must be stated when the
  default moves.
- Cache reuse across requests in the same slot is caller policy: `prepare` does
  not zero the slot's K/V, matching
  `Qwen4ExpDenseAttentionState.clear_written_cache`.
- Known limits: a state that fails mid-close stays permanently unusable
  (`closing`, retryable only through `close()`), which is the intended trade-off
  since the alternative is writing through a released pointer. The shape guards
  bound what the kernels can *address*, not what
  the device can *hold*; an in-range-but-too-large geometry (for example 4 slots
  x 2^32 positions with a small head) still fails at `hipMalloc` with the
  runtime's error. Slot admission is per call: nothing here tracks which request
  currently owns a slot, so a caller that prepares the same slot for two live
  requests gets silent aliasing. Both belong to the runner integration.
