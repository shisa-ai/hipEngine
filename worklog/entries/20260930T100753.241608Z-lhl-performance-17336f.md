# D10 first half: device greedy argmax replaces the full-vocab D2H

## Summary

D10's first half: greedy decode stops transferring the vocabulary. The
production loop was `forward()` -> sync D2H of all 262144 logits ->
`np.argmax` on the host; the single `hipMemcpy` measured 1.51 ms per
decode step in the d8 attribution (1.17-1.79 across runs), of which
0.118 ms is the 1 MB transfer measured idle on this box and 0.016 ms is
the host argmax. A device argmax kernel behind the device softcap now
emits `(index, value)` and the greedy generator brings home 16 bytes.
The drain the copy waits for is the token dependency itself and stays;
what shrinks is the transfer and the host argmax. `forward()` and the
host-logits path are untouched for diagnostics, gates, and any future
non-greedy sampler.

## Changes

- - `gemma4_norm.hip`: two-stage `gemma4_logit_argmax_f32` -- grid-stride
  stage 1 to per-block partials, single-block stage 2, with a
  piecewise-total winner order (first NaN above value-desc/index-asc)
  so any reduction tree equals a left-to-right `np.argmax`, ties and
  `+0/-0` included.
- `gemma4_norm.py`: wrapper plus `gemma4_logit_argmax_scratch_bytes`;
  scratch is caller-owned so no malloc happens per step.
- `runtime/gemma4.py`: admission extracted to `_validated_tokens`,
  new `forward_argmax()` (identical chunking/validation; collect phase
  swaps to `_collect_block_argmax`, which softcaps, argmaxes on the
  stream, and sync-copies 16 bytes), `_argmax_out`/`_argmax_scratch`
  pre-allocated beside `_logits` at construction (no malloc under
  capture or in a step), `collect_argmax` threaded through
  `_forward_block`/`_forward_block_inner`. `_collect_block` unchanged
  for the decode-graph module.
- `generation/gemma4_gguf.py`: the greedy loop calls
  `runner.forward_argmax` instead of `forward` + `next_token`;
  token flow and stop handling identical.
- Tests: new `tests/test_gpu_gemma4_argmax_kernel.py` (RED first --
  ImportError on the symbol -- then GREEN 3/3); contracts fake gains
  `forward_argmax`; the lifecycle constructor-failure fixture's
  positional `fail_at` moves 5 -> 7 for the two new pre-layer allocs
  (allocation order documented, cleanup contract unchanged).

## Validation

- - Battery 3/3: device index equals `np.argmax` exactly on eight
  adversarial batteries (spread three-way ties, saturation, NaN with
  finite 1e30 present, `+0/-0`, extremes, single element); value
  bitwise `x[index]`; chained after the production softcap the
  comparator is numpy over the device-capped bytes (the production
  host path) and matches.
- Changed-surface bundle 45/45: contracts, `test_unit_gemma4_generate`
  (LLM.generate surface), campaign-bench accounting, lifecycle,
  both batteries, decode-graph capture, bucket math.
- Default tier: no new failures. 9 documented pre-existing (runner x6,
  weighted-accumulate bitwise, specdec2 bridge, the order-dependent
  `test_layer_incremental_decode_matches_a_dense_prefill` which passes
  4/4 isolated) plus one fixture break caused by this change and fixed
  as above; its file is green.
- Token differential through `generate_detailed` (campaign bench,
  GPU1, recorded command): `path parity=True` -- instrumented
  `forward`+`next_token` and the public `forward_argmax` route are two
  different code paths and produced identical tokens -- and all 128
  greedy ids equal the recorded `x7-149-head` run (0 divergences).
  decode_tps 80.49 vs 80.64 recorded (flat, -0.19%).
- Loop metric `per_decode_step.hip_host_ms`: 4.7147 ->
  **4.5991-4.6372 across four runs** (all below the pre value);
  the big `hipMemcpy` itself 1.5143 -> 1.3371 ms/step. Final artifact
  written at HEAD `764570ab5` plus these changes (the artifact's
  `git_commit` field reads HEAD; the worktree carries this unit).
- Wall, told carefully: absolute probe wall drifted up during the day
  -- an in-session A/B emulating the pre-D10 host route on the same
  binary reads 13.51/13.68 ms/step against the new route's
  12.78/13.12/13.20/13.175, so the route is ~0.4 ms/step better in
  window while the environment moved ~+1.0 under both. The morning's
  12.6126 (old route) and the afternoon's old-route reads bracket the
  drift; cross-timepoint wall comparisons need the in-window arm.
  Device cost of the new kernel: softcap 0.0082 ms, argmax 0.0261 ms,
  both 0.0280 ms (event-timed), i.e. +0.020 ms on the critical path.
