# Qwen3.8 B2 moves F16 workspace into resident lifecycle

## Summary

Resolved B2's workspace ownership blocker. The F16 cast path no longer owns a
module-global allocation. Each enabled `Qwen35GGUFResidentSession` lazily owns
one bounded 34 MiB buffer, supplies it only through the active prefill context,
reuses it for that session, and frees it through the existing session teardown.
Missing or undersized ownership fails closed to the registered BF16 launch.
No registry key, kernel body, arithmetic, or strict fallback changed.

## Changes

- `hipengine/runtime/gguf_linear.py`: replace `_PREFILL_F16_WORKSPACE` and its
  process lock with immutable `PrefillF16StagingWorkspace` context ownership.
  The launch consumes no allocation API and returns to BF16 when ownership is
  absent or too small.
- `hipengine/runtime/qwen35_gguf_runner.py`: lazily allocate one
  `1024 * max(hidden, feed_forward, ssm_inner) * sizeof(FP16)` buffer per
  enabled session (34 MiB for Qwen3.8), bind it around scalar and packed
  prefill, and include it in `_buffers` teardown.
- `tests/test_gguf_k_t16_dense_f16_activation_prefill.py`: pin bounded restore,
  exact-capacity admission, undersized fallback, removal of module-global
  state, same-session reuse, and distinct-session pointers.
- Added the compact lifecycle artifact and closed only the B2 implementation/
  ownership item; the production retention item remains open.
