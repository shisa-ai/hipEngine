# Packed workspace lease sizing: one geometry for lease and demand

## Summary

The packed KV-plane workspace lease and the allocation that consumes it were
two independently written expressions of one geometry, so they disagreed. The
lease is taken once at pool creation (`configure_engine_loop`); the demand is
computed per request by `_packed_verify_union_geometry` +
`_GGUFPackedTargetState.allocate`. When they disagreed, `allocate` raised
`packed workspace lease holds N pages but the workspace needs M` and wedged
prefill. Both sides now derive from one helper,
`packed_verify_workspace_lease_pages`, and a lease that still cannot cover a
request degrades to a private KV chunk instead of failing closed.

This was found while validating the batched reused-suffix prefill unit
(`20260918T152121.577918Z-pi-prefix-cache-batched-suffix-extend-1ee788.md`),
whose `scripts/gguf_prefix_reuse_gate.py` arms died on this error. The defect
itself is older than that unit and independent of it: the removal of the <1024
paged-prefill gate merely routed long contexts onto the paged path, which is
the path that consumes the lease, so a pre-existing mismatch started firing.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: new
  `packed_verify_workspace_lease_pages(max_batch_size, max_positions)`, the
  lease-side twin of `_packed_verify_union_geometry`
  (`ceil(max(max_positions, _PACKED_VERIFY_MIN_MAX_SEQUENCE)/256)` pages per
  slot x `packed_verify_lease_slot_ceiling(max_batch_size)` slots).
- `hipengine/runtime/qwen35_gguf_runner.py`: `_GGUFPackedTargetState.allocate`
  no longer raises when the lease is shorter than the request. It records the
  shortfall on `runner._packed_workspace_lease_shortfalls` and falls through to
  the private KV chunk branch, which allocates the identical geometry. The
  lease is a fast path, not a correctness dependency. A layout-incompatible
  arena is a different kind of fault and still fails closed.
- `hipengine/generation/qwen35_gguf.py`: the lease call site uses the shared
  helper with `int(self.capacity)`. Two defects fixed:
  * the capacity argument read `self._resident_model_runner`, a field of
    `Qwen35GGUFBringupGenerator` that never exists on
    `Qwen35GGUFResidentModelRunner`. The `getattr` always yielded `None`, so
    `packed_verify_lease_slot_ceiling` fell back to the historical 8-slot floor
    and every server over-pinned pages it could not touch.
  * the per-slot term `max(max_pages_per_request, 4)` equalled the demand
    side's `ceil(max(max_positions, 1024)/256)` only by coincidence of
    rounding.
  Orphaned imports (`_PACKED_VERIFY_MIN_MAX_SEQUENCE`,
  `packed_verify_lease_slot_ceiling`) removed.

## Validation

- RED evidence, pre-existing: `test_configure_engine_loop_leases_packed_workspace_pages`
  and `test_configure_engine_loop_leases_single_slot_workspace_at_c1` were RED
  on clean HEAD (d01ec1b51), confirmed in a throwaway worktree, failing
  `assert 40 == 12` — exactly the 8-slot-floor over-lease
  (8 request pages + 8 slots x 4 = 40 vs the intended 8 + 1x4 = 12). Both are
  GREEN now. The capacity=2 test's assertions (4 pinned pages, a ONE-slot
  lease) contradicted its own comment (`capacity slots * max(3, 1024/256) = 8`);
  the assertions predate the capacity term and were never updated. They now
  read 8 pinned / 16 total, matching the comment and the shared helper.
- New contracts in `tests/test_unit_gguf_packed_workspace_stability.py`:
  * `test_lease_pages_helper_covers_every_capacity_bounded_geometry` sweeps
    capacity {1,2,4,8} x positions {256,512,1024,2048,8192} x every
    within-capacity slot count and asserts the helper never under-sizes what
    `_packed_verify_union_geometry` demands. This is the anti-drift contract.
  * `test_lease_pages_helper_applies_the_context_floor_and_capacity_term`
    pins both terms individually.
  * `test_short_lease_degrades_to_private_instead_of_failing_closed` and
    `test_sufficient_lease_still_prefers_the_arena` pin the new degradation
    behaviour and that it costs nothing in the normal case.
  * the superseded `test_lease_sized_from_ceiling_covers_the_realized_workspace`
    (which asserted the lease must be sized from `ceiling(None)`, i.e. the
    broken-lookup value) is replaced by the above.
- `tests/test_unit_gguf_packed_verify_layout.py::test_gguf_packed_target_state_allocate_rejects_bad_lease`
  updated: the short-lease half now pins degradation to the private branch

## Next

- `initial_state_exact: false` (GDN conv/recurrent bytes at the reuse boundary)
  is the only remaining failing check in the gate, with `output_exact: true`,
  both boundary checks exact, `final_state_mismatches: []`, `lifecycle.exact:
  true`, and `teacher_forced.gate_passed: true`. A prior artifact
  (`benchmarks/results/2026-07-21-gfx1100-gguf-processed-argmax-p2048-active-prefix-correctness.json`)
  recorded `initial_state_exact: true`, so the check is meant to hold. The
  batched-suffix unit owns isolating it with the
  `HIPENGINE_GGUF_PREFIX_BATCHED_SUFFIX=0` control and re-reviewing it under
  the production-profile gates in `docs/EXECUTION-PROFILES.md` rather than the
  strict byte oracle, per the "there is no exactness contract" rule in
  `AGENTS.md`.
- `_packed_workspace_lease_shortfalls` is diagnostic only; it is not yet
  surfaced in `kv_pool_memory_snapshot()` telemetry. If a real workload ever
  records entries, the lease sizing rule (not the fallback) is what should
  change.
