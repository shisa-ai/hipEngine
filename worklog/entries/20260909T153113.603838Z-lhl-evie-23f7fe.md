# EVIE GDN f32-out fp16 projections

## Summary

Isolated the GDN fp16 drift to the f16 OUTPUT rounding (not input/weight
rounding): routing the GDN in_proj/out_proj through the f32-output gemm_ex
epilogue (fp16 inputs, ~4 TF/s, 2x the fp32 SGEMM) restores full accuracy
while keeping the matrix-core path. Benchmark: 4.08 s -> 3.47 s
(doc 2.71 s, query 0.76 s, 8p+8q fp16).

## Changes

- `hipengine/runtime/evie.py`: `_gemm32` (GDN projections) now casts x to
  fp16 and runs `gemm_ex_rowmajor_nt_fp16_f32_out` in fp16 mode; plain
  SGEMM in strict fp32 mode.
- `hipengine/loading/evie.py`: GDN in_proj/out_proj converted to fp16
  again (predicated in `evie_gemm_weight`), docstring updated with the
  f32-out requirement.

## Validation

- Fixture parity (fp16): query cos 0.9999995 / max 6.5e-4, doc cos
  0.99987 / max 2.8e-2, maxsim 5.9242 vs 5.9114 (+0.22%).
- Strict fp32 path: tests/test_evie_gpu_runtime.py 3/3.
- Best of 3 bench: 3471.5 ms total (doc 2709.5, query 761.6, maxsim 0.4).
