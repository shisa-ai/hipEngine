# RF1 extended long-context matrix and tails

## Summary

RF1 boundary qualification passed earlier (1024/1025/1032 + B3 full accept +
real crossing, committed in `7f1734158`). This entry extends the eager
long-context oracle across 2K/4K/8K/16K/32K/64K (largest practical), adds
near-cap output tails, and records the task/state/KV/wall/memory evidence
required to close RF1. RF1 remains open until this packet is complete.

## Changes

- `scripts/gguf_mtp_long_context_gate.py`: the real-generation path never
  released the NextN request slot between generation contexts, so a second
  context failed with "GGUF NextN executor has no free request slot". The
  harness now calls `provider.release_request(...)` after each owned cycle,
  matching the server path (`_generate_dense_speculative_mtp_detailed`).
- Added independently selectable direct/generation modes, flushed structured
  case and prefill progress on stderr, atomic running checkpoints after every
  event/result, and atomic final artifacts. A stopped process now preserves
  completed rows and identifies its active stage instead of leaving no output.
- Added CPU/fake-runner RED/GREEN coverage for generation-only execution,
  checkpoint transitions/finalization, progress emission, and empty-scenario
  rejection.
- Discovered a latent strict-fallback prefill bug:
  `launch_qwen35_paged_full_attn_prefill_gqa_gate_bf16` sizes dynamic LDS as
  `(max_context_len + threads + head_dim) * 4`, which exceeds the 64 KiB
  workgroup limit at `max_context_len ~= 16K` and fails the launch with
  `HIP error 1 (invalid argument)`. Production gfx1151 uses AOTriton prefill by
  default (native is only sub-512), so this is reachable only when
  `HIPENGINE_GGUF_AOTRITON_PREFILL_ENABLE=0` at large context; the RF1 matrix
  uses the committed AOTriton default. Referenced in `docs/REFACTOR.md`.
