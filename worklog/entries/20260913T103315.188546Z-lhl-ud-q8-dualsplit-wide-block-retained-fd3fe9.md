# The Q8_0 ssm dual_split wide block is promoted: bit-identical tokens and a better section-6.1 gate

## Summary

Follows `ud-q8-dualsplit-block-width`, which landed the infrastructure for a
wider block on `q8_0_t16_dual_split_gemv` and measured a 1.35x per-call win
but deliberately left the default at 128, because the wider block changes the
k-split summation order for `ssm_alpha`/`ssm_beta` and this repository had
recorded that changing this path's arithmetic diverges generated tokens.

This unit ran the evidence bar that the earlier Q8T16 rowtile change used for
the same class of edit. **The change passes it and the default is now 256.**

## Changes

`hipengine/kernels/hip_gfx1100/quant/gguf_q8_0_t16_gemv.py`:
`_DUAL_SPLIT_DEFAULT_THREADS` goes from `_DEFAULT_THREADS` (128) to 256.

`docs/UD-GFX1151-OPTIMIZE.md`: the block-width item is closed as retained
with the gate numbers and the token sequence.

No other source changes. The kernel, validator, launch bounds, reduction
buffer and thread-override test all landed in the previous unit
(`3784a27b3`) and are unchanged here.

## Validation

Three independent checks, all passing, on physical GPU1 (RX 7900 XTX, gfx1100).

**1. Generated tokens are bit-identical.** `scripts/qwen35_gguf_mtp_e2e.py
--model /models/gguf/Qwen3.8-27B-UD-Q4_K_M.gguf --quant gguf_ud_q4_k_m
--max-new-tokens 12 --candidate-budgets 1`, one run per arm, default prompt.
Both the AR and the MTP sequence are identical:

```
271, 248068, 198, 760, 1156, 6587, 264, 12654, 709, 421, 25, 198
```

**2. The section-6.1 teacher-forced gate passes and improves on every KL
metric.** `scripts/ud_mtp_ar_verify_numerics_gate.py --prompt-tokens 64
--budgets 1,2,3 --repeat-runs 2 --require-native-graph`, 18 prompts, 162
rows, two deterministic repeats per arm, run in the same session in both
directions:

| threads | mean KL | p95 | p99 | max | top-1 | passed | deterministic |
| ---: | ---: | ---: | ---: | ---: | ---: | --- | --- |
| 128 (before) | 3.471e-05 | 1.927e-04 | 2.459e-04 | 2.517e-04 | 1.0000 | yes | yes |
| **256 (after)** | **3.287e-05** | **1.759e-04** | **2.351e-04** | **2.432e-04** | 1.0000 | yes | yes |

Limits are mean <= 1e-3, p95 <= 5e-3, p99 <= 2e-2, max <= 5e-2, top-1 >= 0.99
overall and >= 0.97 per scope. The mean margin is about 30x and the maximum
about 20x. Every metric moves the same direction the earlier Q8T16 rowtile
substitution moved, which is consistent with the replaced four-wave reduction
being the less accurate of the two orderings on this shape.

**3. Unit tests pass across every allowed block size.**
`tests/test_gguf_q8_0_t16_gemv_decode.py` (41 passed, threads parametrized
over 0/64/128/256/512), plus `test_gguf_linear_dispatch_cache.py` and
`test_qwen35_gguf_dense_q8_dp4a_routing.py`: 62 passed.

**Performance.** Verifier census, same protocol and host as the baseline
(`scripts/gguf_mtp_verifier_rocprof.py --quant gguf_ud_q4_k_m --mode
block-verify --block-rows 3 --block-verify-mode native --native-spec-target-cycle
--steps 12 --warmup 3`):

| kernel | before us/call | after us/call | before ms/step | after ms/step |
| --- | ---: | ---: | ---: | ---: |
| `q8_0_t16_dual_split_gemv` | 18.28 | **13.54** | 0.8773 | **0.6500** |
| `q8_0_t16_rowtile_gemv` | 51.21 | 51.15 | 0.3585 | 0.3580 |
| `q8_0_t16_gemv` | 13.58 | 13.73 | 0.0407 | 0.0412 |

`avg_kernel_ms` 36.3115 -> **36.0772** (-0.65%), `avg_host_ms` 41.4378 ->
40.9720 (-1.1%), calls/step unchanged at 985.0, every other kernel flat
within run-to-run noise.

## Scope of the claim

The paired AR/MTP economics protocol was **not** re-run, so no decode topline
row in `benchmarks/README.md` moves and the changelog entry is scoped to the
verifier window. The retained claim is the verifier-window kernel win plus the
correctness evidence above. Rollback is the single constant
`_DUAL_SPLIT_DEFAULT_THREADS = _DEFAULT_THREADS`, or an explicit
`threads=128` at the call site.
