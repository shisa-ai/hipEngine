# Correct R0029/R0030 router ownership descriptions

## Summary

The two router ledger entries still described ordered DPP as the
`gguf_ud_q4_k_xl` production router producer. That was true before
`e73e6bed1` ("F16 route composition is the Qwen4Exp UD-Q4_K_XL production
plan") and is false at HEAD: the production plan selects
`f32_hidden_f16_wmma_gemm`, ordered DPP is the arithmetic-recovery plan's
default producer and the named rollback, and strict and `gguf_q4_k_m`
production keep `f32_hidden_token_tile4_dense_exact`.

The entries' evidence records are unchanged and remain valid for the DPP
producer. Only the ownership statements, the precedence description and the
reader's removal condition were corrected. Parent integration also fixes the
missing evidence mapping for an explicitly named F16 producer, with a fresh-process
regression test. Default selection, env reader, arithmetic, and kernel bodies
are unchanged; the previously failing explicit request can now import.

Precedence verified at HEAD:

1. The plan is built at profile registration. `_f16_route_selections` starts
   from `_production_selections(recovery=True)`, whose router row is
   `_ROUTER_UD_LOGITS_SELECTED_VARIANT` (DPP when nothing is named), and
   replaces DPP with the F16 GEMM unless a producer was named before import.
   A named producer changes the production plan only; strict stays on tile4.
2. The production binder publishes the resolved manifest row into
   `HIPENGINE_QWEN4_EXP_ROUTER_VARIANT`.
3. `_qwen4_exp_router_producer_variant` returns the linear GGUF path below two
   rows, the published producer from two rows, and DPP instead of the F16 GEMM
   below 64 rows (the GEMM stages 128-row tiles). An empty variable falls back
   to tile4, which a bound run reaches only by clearing the variable after the
   bind.
