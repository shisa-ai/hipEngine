# Fix MTP observability ownership and lazy reporting

## Summary

Follow-up review of `a9419949d` found that the new MTP response helpers did
not honor `GenerationTelemetry.timing_owner`, zero-draft MTP requests were not
counted by the request counter, and lazy startup reported an unloaded engine as
MTP-off without later logging the effective loaded state. Corrected those
contracts and removed the unreachable MTP SSE promise from `docs/API.md`.

## Changes

- MTP usage and compact response summaries now ignore batch-scoped timing
  copies with `timing_owner=false`; mapping and dataclass telemetry forms are
  both supported.
- A realized `speculative_mtp` route reports `used=true` even when no drafts
  were proposed.
- `hipengine_mtp_requests_total` now counts an MTP usage payload by field
  presence, including accepted=0/rejected=0 requests.
- Lazy startup logs `serving=pending engine_supported=unknown`; `get_llm()`
  logs the effective state immediately after first-request model creation.
- API documentation now accurately states that MTP serving is non-streaming
  and describes timing ownership, zero-draft behavior, and lazy logging.
