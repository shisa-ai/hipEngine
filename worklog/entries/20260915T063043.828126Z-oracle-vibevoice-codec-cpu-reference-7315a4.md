# Implement and validate the VibeVoice codec decoder CPU reference

## Summary

M2a of docs/VIBEVOICE-TTS-CONTRACT.md is done: the acoustic decoder
(latent -> PCM, x3200 to 24 kHz) now exists as a torch-free CPU reference and
matches the pinned torch oracle at the FP32 rounding floor.

- hipengine/kernels/cpu_reference/vibevoice_codec.py: the full
  TokenizerDecoder forward (fork @ 952326dd) in numpy with FP32 accumulation -
  causal streaming SConv1d (dense and depthwise) with per-layer context caches,
  causal SConvTranspose1d with the right (k-s) trim, channel-axis RMSNorm,
  exact erf GELU, FFNs with layer-scale residuals, and the stem/head. A
  DecoderGeometry dataclass pins the shape contract (276 tensors) and
  load_decoder_weights validates it while widening BF16 storage.
- scripts/vibevoice_codec_cpu_reference_check.py compares, on a fixed latent:
  full-sequence decode vs the fork's decode, frame-by-frame streaming decode
  vs the fork's streaming decode, and streaming vs full inside the reference.

Measured (benchmarks/results/2026-09-15-vibevoice-codec-cpu-reference.json,
6 frames, seed 20260915, f32):

| comparison | max abs |
| --- | ---: |
| reference full vs oracle full | 3.07e-10 |
| reference streaming vs oracle streaming | 3.63e-10 |
| reference streaming vs reference full | 3.09e-10 |
| oracle streaming vs oracle full | 2.78e-10 |

Waveform peak 8.67e-05 for a random latent, so max relative error is
~3.5e-06 - the BLAS accumulation-order floor, the same class the oracle shows
against itself.

## Decisions

- The oracle loads through VibeVoiceForConditionalGenerationInference
  from_pretrained: constructing the tokenizer standalone leaves randomly
  initialized weights (caught because the stem weights diverged from the
  checkpoint by 0.35 - the fixture must come from the real load path).
- erf GELU via vectorized math.erf (house pattern from cpu_reference/evie.py);
  scipy is not an engine dependency.
- Streaming SConv1d zero-initializes its context on the first chunk (the
  fork's final-flush semantics); SConvTranspose1d starts with an empty cache
  and crops to the last T*stride trimmed samples. Both mirror the fork and
  are covered by the streaming-vs-full gates.
