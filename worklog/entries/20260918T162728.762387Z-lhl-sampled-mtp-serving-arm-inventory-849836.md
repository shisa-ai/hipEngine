# sampled MTP serving arm: temporary-edit inventory and gate map

## Summary

The sampled-serving arm has accumulated enough open instrumentation that
keep-or-revert is no longer a single decision. This entry freezes the inventory
of every working-tree edit, the four admission gates found so far, and the
per-edit decision rule, so a crash cannot leave an ambiguous worktree and the
eventual artifact can cite one clean map. It records no new measurement: the
current on-arm numbers are autoregressive fallback through a refused
speculative route, not sampled MTP.

## Changes

### Temporary edits in the working tree (uncommitted, base 805e46582)

1. `hipengine/models/qwen35.py` - one line. `_QWEN38_Q4KM_MTP_SERVING_EVIDENCE[0]`
   gains `"sampled"` in `sampling_modes`. This is the qualification switch:
   `_sampled_route_qualified()` matches an evidence row on
   (backend, target arch, weight quant, artifact size) and requires the mode.
   **Decision rule:** keep only if the serving arm engages the provider and the
   sampled arm is non-regressive against its own in-load AR control on the
   matched workload. Otherwise revert this line and record the sampled route as
   measured-and-closed, exactly as the wider-realized-group rejection was.
2. `hipengine/generation/qwen35_gguf_mtp2.py` - debug prints only, no
   semantics. `[route-debug]` in `_sampled_route_request`, `[cap-debug]` at the
   top of `capability()`, and `[cap-silent-none]` on the row-readiness
   `return None` path. All gated on `HIPENGINE_DEBUG_SAMPLED_ROUTE`.
3. `hipengine/generation/engine_loop.py` - debug print only.
   `[plan-debug]` after the first `plan_speculative_requests()` call prints the
   cycle id, whether a capability was supplied at all, and per request the
   sampling mode, planned candidate count, and plan reason. Gated on
   `HIPENGINE_DEBUG_SAMPLED_ROUTE`.

### Committed diagnostics from this arm

- `HIPENGINE_DEBUG_SAMPLED_QUALIFY` echo inside `_sampled_route_qualified()`
  (committed with 805e46582). Remove with the same unit that resolves the row
  edit, or name it as a retained diagnostic in `docs/REFACTOR.md`.
- `HIPENGINE_MTP2_TRACE_DECLINE=1` in `_decline()` is pre-existing and prints
  each unique refusal reason once. It is the instrument that closes the
  remaining admission gate, so it needs no edit.
- The `server/api.py` change from 80f895e58 is **not** a temporary edit. It
  reroutes a request from the default route to the batch route when the engine
  advertises a row for the request's sampling mode, and it is already gated on
  that advertisement, so the default (no evidence row) behavior is unchanged.
  If it stays, it is production semantics and needs its own test rather than a
  revert.

### Admission gates found so far

1. Server route choice: any non-greedy request was forced to K0 before the
   resolver. Opened in 80f895e58, gated on the engine's advertised row.
2. Static speculative intent: the request must still carry typed speculative
   intent when semantics are built. Fixed in 990f6af41 (the sampled-mode helper
   the intent check used).
3. Adapter qualification: `_sampled_route_qualified()` requires the evidence row
   to list `"sampled"`. Opened by edit 1 above.
4. Adapter admission, still closed. With 1-3 open, the resolver reports
   `qualified=True` with `semantics=[(2, 'sampled')]` and route
   `speculative_mtp`, while the request still decodes autoregressively
   (`decision_reason=backend_k0_fallback`, `mtp_output_tokens=0`). So the
   remaining refusal is downstream of the resolver, inside `capability()`
   (a `_decline` reason, or the row-readiness path that returns `None` without
   a reason) or in the planner's reason assignment. The three prints above
   cover all three sites in a single instrumented pass.
