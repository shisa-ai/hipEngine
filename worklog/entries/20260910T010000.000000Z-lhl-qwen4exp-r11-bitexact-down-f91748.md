## Summary

Wired the R11 warp256 MoE decode kernels into the runner, then qualified them
against the campaign's exact-trajectory requirement. Both kernels went into the
`qwen4_exp_runner.py` decode branch behind default-off envs and joined the
gdn/qsa `moe_graph_key`s; in-situ wrapper counting showed 84 dual + 86 wsum calls

The prior "bit-exact" vectorized down kernel was **not** bit-exact: an in-situ
43-call capture oracle showed 11/43 calls differing by 1-3 bf16 ulps from the
incumbent, because a warp shuffle-tree reduction adds fp32 partials in a
different order than the incumbent's shared-memory tree. The kernel was rewritten

118.0us.

1.72x) and the gate/up warp256 (56.6us, 2.0x) both break trajectory exactness,
which this campaign's A/B harness requires.

## Why T1 is blocked for decode routes

The campaign A/B harness requires exact generated trajectories
(`correctness_scope`: "Exact generated trajectories are required by this
screening harness"), and every decode promotion this campaign (QSA
ordered-v2, and all iu8 routes) has been bit-exact. A T1 decode route
breaks trajectory exactness at 4 steps and compounds through the KV/GDN
feedback - so bit-exact is the only qualification path. (The envelope
route exists in principle per EXECUTION-PROFILES 6.1, but the harness's
trajectory-exactness requirement makes it moot for decode.)

## The fast-bit-exact design (option a)

Replicate the exact logical tree but feed the fma chain from
vectorized loads + lane-shuffle redistribution:

- Each lane j loads THREE uint4s of x: elements [8j..8j+7],
  [8j+256..+263], [8j+512..+519] (the third only for j<16). Each load is
  warp-coalesced (512B per layer).
- Element e = j+32m+256delta (what lane j must process) lives in lane
  (j>>3)+4m at u32 sub-index (j&7)>>1 - because 32m is 8-aligned, this is
  a fixed butterfly: per (m, delta) one __shfl_sync of the holding u32.
  ~20 shuffles per lane total (8+8+4 valid deltas).
- Weight side: at fixed (m, delta) the warp's 32 elements are one Q5_1
  block (32 consecutive columns); load d/m/qh once per (m,delta) via
  broadcast-friendly scalars, nibble byte = qs[8+(within&15)] per element
  - can also be staged per-block as uint4 and shuffled similarly
  (element e's byte is at lane (e&31)>>2 of the block's qs uint4 holder).
- The per-element fma ORDER is unchanged (per logical, ascending
  columns), so bit-exactness is preserved by construction.
- Target: ~60-70us (removes ~4 of 5 scalar loads per element).
- Then the standard chain: state gate (--route-package moe-decode-warp
  or a down-only variant), campaign A/B (serving-path TG focus), promote.

Gate/up exact variant (option c) is the same technique on the
logical128_t64 structure (logical = tid + slot*64, stride 128 over
4-element groups; per-group dp4a expression must be preserved exactly -
the screen already validated the per-group arithmetic matches).

## Addendum (follow-up window): exact-kernel tuning ladder closed

Measured variants of the bit-exact down (all preserved the incumbent
digest on screen inputs; the simple committed form is the reference):

| variant | time |
| --- | ---: |
| exact tree (committed bc3a3d440) | 134.5us |
| + m-loop unroll hint | 133.6us |
| launch_bounds 320,2 | 134.9us |
| launch_bounds 320,3 | 140.5us (spill) |
| ILP form (per-m prefetch of all delta constants + x pairs) | 134.7us |
| shared-staged weights (cooperative uint2 pass, 2 barriers) | 142.7us |

Incumbent 117-118us; T1 vectorized 68.6us. Diagnosis: the gap is
structural - the exact logical order requires 20 narrow (m,delta)
transactions per lane (24B weight + 64B x each) versus the vectorized
form's 2 wide contiguous loads per lane; neither ILP nor staging changes
the transaction count on the x side, and the shared pass adds a barrier.
The definitive fix remains the full shuffle butterfly: stage x per warp
as 3 coalesced uint4 layers (elements [8j..], [8j+256..], [8j+512..])
and redistribute via ~80 __shfl_sync u32 moves (element j+32m lives in
lane (j>>3)+4m, u32 sub (j&7)>>1 - 32m is 8-aligned so the pattern is a
fixed butterfly), feeding the unchanged per-logical fma order. The weight
side stays per-(m,delta) uniform (block index m+8*delta). Estimated
~60-80us; validate with the 43-call oracle before any timing claims.
