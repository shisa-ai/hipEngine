# Route TimesFM kernel families through the registry

## Summary

Resolve R0420 in loop iteration 381. TimesFM 3.0 already consumes shared 2.5
primitives; both decoders now bind four-axis kernel callables rather than
importing backend wrappers directly. No arithmetic, precision default, kernel
body, buffer ownership or fused/unfused branch changes.

## Changes

- `hipengine/dispatch/timesfm.py` owns the primitive names and exact-key binding.
  Both constructors accept `backend="auto"` and bind before device allocation.
  Registry fallback must not reinterpret resident FP32 buffers as FP16 or host
  pointers; missing exact keys fail with `MissingKernelError`.
- Shared registrations in `kernels/hip_gfx1100/timesfm/registered.py` publish
  the 2.5 and 3.0 families for both HIP backend packages. Layer names remove
  wrapper dtype suffixes; quant is fp16/fp32, variant empty. Wrappers validate
  dtype and scope JIT architecture to their backend. Imports do not build HIP.
- Register fused FP16 paths and the strict FP32 primitive chains, including
  separate RoPE/head normalization/scatter/attention and 3.0 variate Q/K
  normalization plus FP64-accumulation SGEMM. Runtime branch order is unchanged.
- Architecture RED exposed the generic gfx1151 alias pass copying gfx1100
  closures. Register native TimesFM closures before that pass and exclude their
  exact keys from aliases, including replacement registration.
- Remove the obsolete ledger item, document registry mapping in KERNELS, close
  R0420 in the sweep, and record a scoped triage decision without rewriting
  unrelated dirty decision files. No new flag or dependency.
