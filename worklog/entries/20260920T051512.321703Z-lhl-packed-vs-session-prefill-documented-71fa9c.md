# The residual difference is packed versus single-session prefill, a documented and previously qualified property

## Summary

The residual difference the native-reference run left is **packed versus
single-session prefill**, and the project already treats it as a known property
rather than a defect. The candidate's prefix path is
`prefill_batch` -> `_try_prefill_native_work_batch` ->
`session.prefill_batch_native`, the packed multi-request route the shipping AR
engine binds. The gate's reference is `session.prefill`, which runs one session
at a time. `scripts/execution_profile_gguf_batch_route_gate.py` records the
distinction in its own help text -- admitting a candidate through packed
multi-request prefill "relaxes the prefill calibration from byte-exact logits to
token equality (**the routes persist different final-state arithmetic**) and
leaves the decode-step profile comparison unchanged" -- and that route was
qualified on gfx1100 on 2026-08-30, where "the packed prompt route's different
final-state arithmetic stays inside the production thresholds" with
`quality.hard_gates_passed: true`, `eligible_for_automatic_admission: true`, zero
scope failures and `repeat_determinism` true.

So the gate has been comparing two route families whose final-state arithmetic is
documented to differ, and the 126/127 mismatched state components are that
documented difference rather than a defect. The gate already computes the
matching reference -- `scheduler_chunk_diagnostic`, which prefills through
`prefill_batch_native` and matches the candidate bit-exactly (0/0 in every
category) -- but the numerical comparison is not bound to it.

## Validation

Route identification, from the source:

- `hipengine/generation/qwen35_gguf.py:8702` -- `prefill_batch` calls
  `_try_prefill_native_work_batch`.
- `hipengine/generation/qwen35_gguf.py:8338` -- that method resolves
  `prefill_batch = getattr(owner, "prefill_batch_native", None)` and calls it,
  i.e. the candidate's prefix goes through the packed route.
- `hipengine/runtime/qwen35_gguf_runner.py:23705` -- `prefill_batch_native` is
  the packed multi-request prefill: it packs rows from several sessions into one
  wave, invalidates live packed decode graphs, and flushes deferred packed decode
  state before reuse.
- `hipengine/runtime/qwen35_gguf_runner.py:20488` -- `prefill` documents that it
  selects the plugin's certified **bulk** scheduler by default and takes
  `bulk_attention_mode='native'` only as a diagnostic; it runs the session's own
  path, not the packed wave.

Recorded prior treatment:

- `scripts/execution_profile_gguf_batch_route_gate.py:1149` -- the
  `--packed-prefill-candidate` help text names the different final-state
  arithmetic and relaxes the prefill calibration to token equality.
- `worklog/entries/20260830T011300.377155Z-lhl-w7900-qwen38-packed-prefill-profile-gate-full-74863b.md`
  -- the gfx1100 qualification of that route against the production thresholds
  (`benchmarks/results/2026-08-30-w7900-qwen38-q4km-packed-prefill-profile-gate-c3567.json`).

This is consistent with every measurement in this investigation: the packed
oracle matches the candidate bit-exactly, both single-session variants (bulk and
native) differ from it in ~127 of 128 components regardless of their attention
mode, the serial control flips as much as the batched arm because it still
builds its prefix on the single-session side, and the served route -- which uses
the packed path -- is byte-stable across prefill chunk widths 128-1,024.
