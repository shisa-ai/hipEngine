# Automatic MTP engages at c1, c2 and c4 on the INT8 cell

## Summary

The automatic-MTP INT8 cell engages at every resident width for the first time.
The fix was one contract binding, not a kernel: `declared_int8_scale_dtype`
(`07e33bbb7`) keys the KV capability on the scale dtype the declarations name
instead of the fp16 request default, so the fp32 declaration resolves, its
four-row `max_direct_rows` supplies the shared direct decode leaf, and a packed
group wider than one row can verify.

```
scripts/gguf_mtp_c1c8_server_bench.py --kv-storage int8_per_token_head
  --mtp-request-mode automatic, HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED=1
```

| physical width | engaged | exact | AR tok/s | MTP tok/s | ratio |
| --- | --- | --- | --- | --- | --- |
| c1 | 10/10 | 10/10 | 10.77 | 18.14 | 1.684x |
| c2 | 10/10 | 10/10 | 17.24 | 25.24 | 1.464x |
| c4 | 10/10 | 10/10 | 26.00 | 31.70 | 1.220x |

Artifact:
`benchmarks/results/2026-09-24-gfx1151-qwen38-int8kv-declared-fp32-mtp-vs-ar-c1c4-automatic.json`
(status complete, 224 s, no failure reasons, zero cycle-failure events where the
previous run had eleven).

Batched AR decoding gains more from resident width than MTP does, so the ratio
falls as width rises while MTP throughput rises at every width.
