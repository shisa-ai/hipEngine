# Design bounded Qwen3.8 INT8 prefill lifetime

## Summary

Selected a bounded exact-prefill design for Qwen3.8 pure FP32-scale INT8 KV.
The runtime already contains a layer-outer bulk-prefill branch and the dense
long-row policy already proves one-plane in-place hidden execution at 4K. The
smallest safe route is therefore not a new attention kernel: allocate that one
hidden plane for the full prompt, run the existing layer-outer chunk loop, and
reuse one full-length BF16 K/V oracle pair across INT8-retained attention
layers. Keep the current chunk-outer/per-layer-oracle route whenever byte math
says the full hidden plane would cost more, and preserve the short BF16 mirror.

## Changes

- Added a pure, geometry-driven lifetime planner with no model-name/backend
  branch. It compares current chunk-hidden + per-INT8-layer oracle ownership
  against full-prompt hidden + one shared oracle, and records all byte terms,
  selected mode, required hidden capacity, and oracle-pair count.
- Added RED/GREEN policy tests for Qwen3.8 pure INT8, Qwen3.8 tail-four,
  Qwen3.6-35B prefix-8/2-INT8, and the short BF16-mirror route.
- The planner chooses layer-outer/shared for Qwen3.8 pure and tail-four, but
  correctly retains chunk-outer/layer-local for the 35B two-INT8-layer layout.
  No runtime route is wired in this decision unit.

## Validation

- RED: `uv run pytest -q tests/test_qwen35_gguf_int8_kv_policy.py` failed at
  collection because `_plan_gguf_int8_prefill_lifetime` did not exist.
- GREEN: `uv run pytest -q tests/test_qwen35_gguf_int8_kv_policy.py tests/test_qwen35_gguf_prefill_scratch_liveness.py` passes 55 tests.
- At 33,024 positions with 4,096 scratch rows, pure Qwen3.8 replaces
  `2,164,260,864` bytes of 16 layer-local oracle pairs with a `135,266,304`-byte
  shared pair and grows one hidden plane `41,943,040 -> 338,165,760` bytes. The
  modeled peak falls exactly `1,732,771,840` bytes / `1.613770 GiB`.
- Tail-four falls `109,576,192` bytes / `0.102051 GiB`. The 35B prefix-8 route
  would rise `1,555,038,208` bytes, so it stays on the existing lifetime.
- At a 65,536-position/1,024-scratch-row Qwen3.8 request, the same model predicts
  `3,365,928,960` bytes / `3.134766 GiB` lower prefill ownership than the current
  16-oracle route.
