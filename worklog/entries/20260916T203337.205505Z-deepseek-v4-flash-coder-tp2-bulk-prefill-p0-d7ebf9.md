# Bulk TP2 prefill P0: geometry plan, batched shard math, and RED CPU contract

## Summary

The second approved unit is rank-local batched/bulk TP2 prefill. This checkpoint
delivers **P0 only**: the design, the CPU planning/reference module, the first
batched rank-local MLP shard extension, and the RED-then-GREEN CPU contract. The
bulk TP2 prefill path is **partial**: no GPU execution of the batched path has
run, the batched transport and batched attention/GDN prefill (P1 transport and
P2) are not implemented, and no performance or quality claim is made.

## Design (recorded in `docs/QWEN38-27B-GFX1100-TP2.md`)

New section "Rank-local bulk TP2 prefill design (2026-09-17)" maps the supplied
GGUF geometry (64 layers: 48 linear-attention/GDN, 16 full-attention; hidden
5120, ffn 17408, per-rank ffn 8704, vocab head 124160 rows/rank; full attention
24 q / 4 kv heads, key/value 256; GDN `ssm_inner_size` 6144, `ssm_group_count`
16, `ssm_time_step_rank` 48, `ssm_state_size` 128, conv kernel 4, `linear_qkv_width`
10240), the replicated-vs-sharded ownership, the KV/Conv/GDN final-state shapes,
the exchange payload, and four bounded packets (P0 planning/reference, P1
batched rank-local MLP, P2 batched attention/GDN + prefill->decode transition,
P3 bounded GPU probes then the full D128 gate). It explicitly keeps the MLP
sharded and reduced and forbids bypassing TP2 by running full TP1 and copying
hidden state.

## Changes

- `hipengine/distributed/tp2_prefill.py` (new, CPU-only): `plan_batched_prefill`
  derives per-layer batched shapes, MLP shard dims, Conv/GDN final-state shapes,
  full-attention KV geometry, chunk boundaries, and the exchange payload from a
  config; `chunk_ranges`; `silu`; `batched_sharded_mlp_reference` is an
  independent numpy oracle for the batched column/row-sharded MLP (per-rank
  gate/up column shards, down row shards, summed full-hidden partial).
- `hipengine/distributed/shard_exec.py`: `MlpShardRank` gains an opt-in
  `rows` parameter (default 1). Buffers are row-sized; `write_input_from_device`
  takes `rows`; `forward_partial(rows=...)` uses the unfused gate/up/SiLU/down
  chain with `use_gemv_decode=False` for `rows > 1`, while the single-row fused
  decode route is byte-for-byte unchanged. No new kernel: `launch_gguf_linear`
  already supports `rows > 1` WMMA prefill. No backend/quant dispatch branch, no
  Torch, no new allocation beyond the rank's persistent buffers.
- `tests/test_unit_tp2_prefill_plan.py` (new): ownership/shape/state, chunk
  boundaries, impossible-degree rejection, and reference-math equality/row
  independence.
- `tests/test_unit_tp2_prefill_shard.py` (new): fake-runtime CPU contract for
  row-sized buffers, `rows*hidden` input copies, batched unfused GEMM, unchanged
  single-row fused decode, row bounds, and idempotent teardown.

## Validation

- New tests were RED first (`ModuleNotFoundError` for the plan module; the shard
  tests were written against the new `rows` API), then GREEN: **13 passed** for
  the two new files, **185 passed in 3.17s** for the full focused TP2 bundle
  (the eight unit files). No GPU run.
- The plan was also checked against the real GGUF config (not only the fixture):
  64 layers / 48 linear / 16 full, per-rank ffn 8704, payload 81920 floats for
  16 rows, Conv `(4, 10240)`, GDN `(48, 128, 128)`, KV 4/256/256.
- `scripts/sync_benchmark_readme.py --check` and `scripts/worklog.py check`
  pass. No default/broad CPU suite rerun; the three previously scoped unrelated
  failures are untouched.

## Next

1. **P1 transport**: the staged/compiled exchange is single-row (`hidden`-sized
   payload per layer). Batched prefill needs a `rows * hidden` reduction payload
   and slot sizing; the rank chain already emits the row-sized partial. Until
   then, `ShardGroup` still constructs `MlpShardRank(rows=1)`.
2. **P2**: batched replicated attention/GDN per rank reusing
   `_run_linear_attention_prefill_layer_rows` and the full-attention prefill
   primitives, with KV span writes and final Conv/GDN state, plus the
   prefill -> graph-decode transition (state reset, positions, liveness,
   multi-GPU streams).
3. **P3**: bounded GPU probe at the saved 64-token prompt / position 146 plus a
   category-heldout control, then the full D128 sustained gate only after the
   failure is repaired. Numerics that are not bit-exact are judged against the
   production contract, not rejected.
4. The batched `MlpShardRank.forward_partial(rows>1)` path is CPU-shape-verified
   only; it has no GPU execution evidence yet.

No performance claim until a valid product baseline exists. No threshold change,
no serial substitution, no firmware/reset. User files
(`scripts/tp2_d1_boundary_bisect.py`, `epyc/`) untouched.
