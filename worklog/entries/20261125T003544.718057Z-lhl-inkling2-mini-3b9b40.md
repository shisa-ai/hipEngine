# Start the Inkling 2 server again: count tokens and probe request scratch

## Summary

`hipengine serve` did not start for Inkling 2 on this branch. Startup counts the tokens of its
warm-up prompt and probes request scratch, and both generators lacked the two hooks: the first
attempt failed with `'Inkling2GGUFGenerator' object has no attribute 'count_tokens'` and the next
with `'prepare_request_scratch'`. The scratch probe is written as optional, but the engine wrapper
defines the forwarding method on itself, so the generator's missing method is only reached when
the probe calls it.

`Inkling2ReferenceGenerator`, and with it the GGUF generator, now has both:

- `count_tokens` is the tokenizer's count, as the other generators do it.
- `prepare_request_scratch` checks the admitted size against the sequence capacity, opens one
  session per slot at that capacity and releases them when it is only a probe. Each request owns
  its session state, so that is the allocation a live request makes.

The server also needs `--kv-storage auto` for this model. Its default, `bf16`, is refused by name
(`Inkling 2 CPU reference does not implement: kv_storage='bf16' (CPU reference stores FP32)`),
which is the contract working as written. The serve command in the plan now carries the flag.

Measured on `epyc` (Radeon Pro W7900, mainline `UD-Q4_K_M`), `fast` profile, prefix cache and
drafting off, `--max-context-tokens 4096 --max-active-requests 4`:

- **Startup:** 5.8 s, of which the scratch probe takes 1 ms and the chat smoke 0.17 s.
- **Requests:** "The capital of France is" streams " Paris."; a 223-token prompt with 12 outputs
  answers in 1.58 s; a 3,451-token prompt with 6 outputs in 17.3 s.

## Changes

- `hipengine/generation/inkling2_mini.py`: `count_tokens` and `prepare_request_scratch` on
  `Inkling2ReferenceGenerator`.
- `docs/campaigns/INKLING2-MINI-GGUF-EXECUTION.md`: `--kv-storage auto` on the serve command.
- Tests: `tests/test_unit_inkling2_generation.py`.

## Validation

- RED then GREEN on both hooks; `pytest tests/test_unit_inkling2_generation.py`: 9 passed.
- The server started and served the three requests above; the responses report route `default`,
  one request, no speculative decoding.

## Next

- The server-side check `getattr(engine, "prepare_request_scratch", None)` cannot fail for any
  generator behind the engine wrapper, so the "optional" branch is unreachable. That is a server
  concern and is left as it is.
- The startup warm-up and chat smoke run on a 27-token prompt and a 4,095-token probe; neither
  exercises a multi-block prompt beyond the scratch allocation.
