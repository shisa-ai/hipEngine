# Verify the graph AR denominator against the eager path

## Summary

The true-AR performance denominator runs the production decode-graph replay
path (`--ar-decode-mode graph`, commit `2d12f1283`). That path is fast because
the host submits one graph instead of roughly 860 individual kernels per
transition, but it is only a valid denominator if it decodes the same tokens:
a graph that produced a different sequence would be measuring different work.

Nothing in the suite could see that fault. Its `exact_greedy_match` compares AR
tokens against the MTP verifier's tokens, and both of those run through graphs,
so a defect shared by the graph paths is invisible to it. This unit adds the
independent check and pins it.

## Changes

- Added `scripts/gguf_ar_eager_graph_equivalence.py`. It runs the same model,
  prompt, and settings twice -- once eager, once graph -- and compares the
  recorded token ids transition by transition, reporting each divergence by
  prompt, run, and transition index. It requires an explicit `--device-index`
  and can assert `--expect-device`, so the device is declared rather than
  inferred.
- The suite runs in-process under `mtp_scope_granted` rather than as a
  subprocess. The suite always materializes the NextN draft provider, so even
  an AR-only comparison needs MTP admission, and the U6 pin is empty. The
  scope grant patches the admission module in this interpreter, so a
  subprocess would not inherit it; this mirrors `ud_mtp_paired._run_pair`.
- Added `tests/test_gguf_ar_eager_graph_equivalence.py` for the pure comparison
  half: a length mismatch that agrees on its prefix, rows present in only one
  payload, and empty payloads must all fail rather than vacuously match.
- Added a `docs/REFACTOR.md` entry recording that `--ar-decode-mode eager` is
  retained as a synchronous diagnostic control, with its removal trigger and
  the rule that it must never become a published denominator.

## Validation

- `tests/test_gguf_ar_eager_graph_equivalence.py` and
  `tests/test_qwen36_dense_gguf_suite.py`: 24 passed.
- RED check, both mutations restored clean afterwards: suppressing the
  length-mismatch problem fails
  `test_a_length_mismatch_is_a_problem_even_when_the_prefix_agrees`; suppressing
  the missing-rows problem fails `test_empty_payloads_do_not_vacuously_match`
  and both `test_absent_structure_is_missing_rows_not_a_crash` cases.
- Device check on physical GPU1:

  ```
  scripts/gguf_ar_eager_graph_equivalence.py \
    --model /models/gguf/Qwen3.8-27B-UD-Q4_K_M.gguf --quant gguf_ud_q4_k_m \
    --device-index 1 --expect-device "7900 XTX" --limit 1 --max-new-tokens 24
  ```

  Result: `device='AMD Radeon RX 7900 XTX' rows=1 transitions=24 matched=True`,
  zero divergences. Both payloads report `resolved_backend=hip_gfx1100` and
  their own `ar_decode_mode`, so the two modes really did run separately on the
  declared device rather than one mode being reported twice.
