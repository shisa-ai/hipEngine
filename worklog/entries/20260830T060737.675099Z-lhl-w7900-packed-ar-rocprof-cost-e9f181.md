# W7900: the packed-AR profiler works but costs ~30-40 min per traced configuration

## Summary

Follow-up to the instrument-gap entry, with measured costs so the next attempt is budgeted correctly
instead of guessed. `scripts/gguf_packed_ar_rocprof.py` **does** profile this model on this host: the
traced phase reached "HIP (runtime) version 7.2.0 initialized" and "HSA version 1.18.0 initialized"
and was still running when my 1500 s `timeout` killed it, 12 minutes after it started. What is missing
is wall-clock budget, not capability. No trace was produced, so the rows-scaling question for #14 is
still open.

No code changed by this entry. The tool fix it depends on already landed separately

## Validation

Measured on this host, model `/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`, `HIPENGINE_EXECUTION_PROFILE=production`:

| attempt | settings | outcome |
|---|---|---|
| 1500 s | `--concurrency 1 --decode-mode graph`, default `--prompt-length 512` | timeout inside warmbuild; child `child.json` shows it had reached the 512-row prefill plan, so it was working, not deadlocked |
| 900 s | same but `--prompt-length 48` | timeout; **both** `warmbuild-c1` and `warmbuild-c4` children ran, i.e. two warmups are built regardless of `--concurrency 1` |
| 1200 s | `--decode-mode eager --prompt-length 48 --steps 8 --warmup-steps 1` | argparse rejects `--steps`/`--warmup-steps`; those belong to `gguf_decode_rocprof.py` |
| 1200 s | `--decode-mode eager --prompt-length 48 --skip-warmbuild` | fails fast inside `rocprofv3` (`_run_checked` raises, command failed (1)) - skipping warmbuild leaves the traced child without what it needs |

Also ruled out: a profiler/engine version mismatch. `rocprofv3 --version` is 1.3.2 from
`/home/lhl/mambaforge/envs/therock/bin`, the venv ships no `librocprofiler-sdk`, and the traced phase
initialised HIP and HSA cleanly before the kill.

## Next

  one background job with a 2 h ceiling and check back. Do not use `--skip-warmbuild`.
- Cheaper alternative worth trying first: `scripts/gguf_decode_rocprof.py` accepts `--steps`,
  `--warmup-steps`, `--prompt-length`, `--compiler-version-file` and `--require-cached-build`, which is
