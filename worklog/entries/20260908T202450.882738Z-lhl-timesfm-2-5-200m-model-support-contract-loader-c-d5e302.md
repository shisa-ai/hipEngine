# TimesFM 2.5 200M model support: contract, loader, CPU reference

## Summary

First hipEngine support unit for `google/timesfm-2.5-200m-pytorch` (TimesFM 2.5
200M patched-decoder time-series forecaster). Adds the pinned model contract
and plugin, a torch-free safetensors loader (F32, no conversion), and a NumPy
CPU reference that reproduces the official torch decode to ~2e-5 absolute on a
seeded multi-regime fixture. GPU kernels and a fast decode path are follow-up
work; this unit establishes the correctness oracle they will be gated against.

Reference lineage: google-research/timesfm master
`src/timesfm/timesfm_2p5/timesfm_2p5_torch.py` plus
`src/timesfm/torch/{transformer,dense,normalization,util}.py`
(`TimesFM_2p5_200M_torch_module.forward` / `.decode`,
`TimesFM_2p5_200M_Definition`). The oracle generator script vendors those
classes verbatim (Apache-2.0, trimmed to the 200M config).

## Changes

- `hipengine/models/timesfm.py`: `TimesFMModelSpec` / `parse_timesfm_model_spec`
  pinning the checkpoint contract (20 layers, hidden 1280, 16 heads x head_dim
  80, patch 32, horizon 128, quantile horizon 1024, 9+1 quantile heads,
  decode_index 5), `expected_timesfm_weight_shapes` (232 tensors exactly
  matching the checkpoint manifest), `validate_timesfm_weight_index`, and the
  `TimesFM25Model` plugin registered as `TIMESFM` for architecture
  `TimesFmModelForPrediction`.
- `hipengine/models/__init__.py`: TIMESFM exports.
- `hipengine/loading/timesfm.py`: `load_timesfm_model` /
  `materialize_timesfm_weights` — torch-free validation + FP32 upload with
  finite checks (stored dtype preserved; no FP16 conversion since no runtime
  kernel contract exists yet).
- `hipengine/kernels/cpu_reference/timesfm.py`: NumPy forward + decode +
  `forecast_naive` mirroring the reference ops: multiplicative-scale RMSNorm
  (eps inside rsqrt), biased tokenizer / unbiased head ResidualBlocks with
  Swish, fused QKV, non-interleaved-halves RoPE, QK RMSNorm, per-dim query
  scaling (softplus), unscaled masked dot-product attention, Swish ff0/ff1,
  patch-level running stats + revin, and the AR patch decode loop.
- `scripts/timesfm_oracle_torch.py`: fixture generator (torch, GPU) vendoring
  the official module.
- `tests/fixtures/cpu_reference/timesfm_2p5_200m_decode.npz`: seeded oracle
  (batch 2, context 512 incl. a front-padded masked series, horizon 256 =
  1 prefill backcast + 1 AR step).
- Tests: `tests/test_timesfm_model_contract.py`,
  `tests/test_timesfm_cpu_reference.py`.

## Validation

- `python3 -m pytest tests/test_timesfm_model_contract.py -q` — 5 passed
  (config parse pin, drift rejection, 232-tensor manifest +
  231,289,280-param count, shape/dtype/missing/extra rejection, plugin
  resolution + layer sequence).
- `python3 -m pytest tests/test_timesfm_cpu_reference.py -q` — 3 passed on
  W7900/gfx1100 + local HF cache (oracle parity, forecast_naive smoke, GPU
  load/free with 925,157,120 resident FP32 bytes).
- Oracle parity (numpy vs torch, float32): renormed_outputs max_abs 1.86e-5,
  quantile_spread 1.90e-5, ar_outputs 1.43e-5; test tolerance atol 5e-4 /
  rtol 1e-2. Commands:
  `python3 scripts/timesfm_oracle_torch.py --output tests/fixtures/cpu_reference/timesfm_2p5_200m_decode.npz`
  then an inline `timesfm_decode` comparison on the saved fixture.
- Real-checkpoint load smoke on device:
  `load_timesfm_model("google/timesfm-2.5-200m-pytorch")` → spec ok, 925 MB
  resident, clean free.
