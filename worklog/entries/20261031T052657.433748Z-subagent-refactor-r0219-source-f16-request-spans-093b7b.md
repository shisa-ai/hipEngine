# Bind request-local source-F16 owners to packed prefill row spans

## Summary

A packed prefill slab now carries one source-F16 owner per request instead of
one owner for the slab. The owner is still filtered by the request's **complete
logical length**; the projection still launches at **its own physical rows**.
Ordinary prefill is the degenerate case where the two numbers are equal, so its
launch, plan, and schedule are unchanged.

Two earlier designs were rejected before implementation:

- A physical `row_domains` owner plus unfiltered pair intervals let one
  aggregate slab choose one interval for every request. `[600, 600]` resolves to
  1200 aggregate rows, which selects the `(1024, 2047)` pair-only interval,
  while each 600-row request alone selects `(512, 1023)`; `[1024, 1024]` would
  select *no* interval while each request alone is admitted. That substitutes
  aggregate rows for the complete-request filter at
  `qwen35_gguf_runner.py:_source_f16_prefill_owner`, which is the one thing the
  R0219 seam may not do.
- A whole-call fallback that disabled the owner whenever any request exceeded
  the scratch disabled eligible neighbours instead of integrating request-local
  ownership.

The `id()` → serial session cache-key change stays out of scope: no reproducer,
separate latent work.

## Real scheduling precondition: no default engagement

On the public gfx1100 Q4_K_M route the engine loop's prefill chunk defaults to
256 tokens: `generation/qwen35_gguf.py:14270` seeds
`engine_loop_config_defaults["max_prefill_chunk_tokens"]` from the
`GGUF_Q4_K_M_MAX_PREFILL_CHUNK_TOKENS` capability with a `256` fallback. Every
public packed slab therefore reaches `_prefill_batch_native_single_slab` (or one
layer-outer round) with at most 256 physical rows, while `full_prompt_lengths`
still carries the complete 517/1024/4096 length.

Those are exactly the two numbers this unit separates. The complete length
still filters the owner, so a 517-token request builds the owner its own length
selects; the launch still runs at its real 256 rows, which is below that owner's
`min_rows` (the smallest source-F16 policy row, 512 on gfx1100, since
`_source_f16_prefill_owner` derives `min_rows` from `min(all_shape_tiles)`).
No span is admitted, `_source_f16_slab_spans` returns `None`, and every launch
takes today's path.

So at factory defaults this unit changes **nothing on the public surface** — it
is a no-engagement parity arm, not a source-F16 engagement claim. Engagement
needs a slab at or above the policy's smallest row, which requires a supported
larger `max_prefill_chunk_tokens` (1024/4096). The parent is collecting those
public controls separately and comparing them after this unit; whether the
default chunk should change is the parent's decision, not this unit's.

Nothing here changes a threshold, a default, or the chunking. No neighbour is
disabled to force engagement, and no span ever substitutes its logical length
for its physical rows: doing either would be the aggregate-row substitution this
design exists to prevent.

Arithmetic status, stated separately because the two are not the same claim:

- **Already validated per request**: a single request's own length selecting its
  own owner, and that owner's rows producing the source-F16 GEMM. Unchanged by
  this unit.
- **New, cross-composition**: several requests, each with its own length and
  owner, in one slab, with one slab-level launch replaced by per-request spans.
  This unit establishes the ownership mechanism and row/pointer bookkeeping
  only. No arithmetic equivalence claim is made here, and no performance claim
  is made anywhere in this unit.

## Changes

- `hipengine/runtime/gguf_linear.py`
  - `SourceF16RowSpan` (`row_start`, `rows`, `request_rows`, `owner`) and
    `SourceF16SlabSpans`, which requires the spans to tile the slab in row order
    and cover every row exactly once. The two row numbers are separate fields
    precisely so a span cannot inherit another request's rows or interval.
  - `source_f16_slab_spans_session` / `current_source_f16_slab_spans` and the
    `_source_f16_launch_probe` leaf probe.
  - `launch_gguf_linear` split into a span-aware wrapper plus
    `_launch_gguf_linear_impl`. The wrapper clears the span map for its whole
    body, so spans cannot leak into the strict slab plan or a nested row-chunk
    projection, and restores it afterwards.
  - `_launch_gguf_linear_source_f16_spans`: all-eligible slabs run one span per
    request at its own `row_start`/`rows` and pointer offsets; a mixed slab runs
    the unchanged whole-slab strict launch first and then overwrites only the
    admitted requests' rows, so an out-of-band neighbour keeps exactly today's
    launch; an all-ineligible slab returns `False` and the caller keeps its
    ordinary launch. Every span launch must reach the source-F16 leaf, else it
    raises instead of silently leaving an exact projection in place.
  - `launch_gguf_linear_pair` / `_launch_gguf_linear_pair_impl` get the same
    split. `_launch_gguf_linear_pair_source_f16_spans` resolves each span's own
    ordered pair plan under that span's owner at that span's rows, executes it
    at the span's pointer offsets, and leaves `pair_silu`/`pair_concat`, the
    shared-activation cast ownership, the Q4 `(5120, 12288) → 2047` ceiling,
    strides, and the decline/fallback contract untouched. A declining strict
    slab plan returns `False` rather than pretending the slab was handled. Span
    plans are re-resolved after the strict pass because a registration sweep
    advances the registry generation a plan is resolved against.
- `hipengine/runtime/qwen35_gguf_runner.py`
  - `_source_f16_prefill_owner` extracted from
    `_t16_f16_rocblas_prefill_context`, returning the owner or `None` so it can
    be reused per request length; the context manager still wraps it for the
    single-request path. The opt-out (`use_t16_f16_rocblas_prefill is False`),
    the missing-policy, empty-tile, and complete-length-exceeds-scratch
    branches all return `None`, so they stay exactly as effective as before.
  - `_source_f16_request_owners` builds one owner per distinct length;
    `_source_f16_slab_spans` builds the span map from the slot layout's
    `cu_seqlens` plus each slot's complete length.
  - Single-slab packed AR prefill: owners and spans are built once per slab
    after the layout rebind; the aggregate linear-attention and non-slot-local
    full-attention layers run under the span map. Slot-local full attention
    binds that slot's own owner directly, because its rows already are that
    request's rows.
  - Layer-outer resumable prefill: `_GGUFResumablePrefillState.request_lengths`
    carries the complete lengths across segments, each chunk plan records the
    lengths of its own slots, and each segment re-derives owners from those
    lengths rather than from a round's rows. The chunk plan, budget, phase, and
    ping-pong schedule are unchanged.
  - `_request_lengths` is a private kwarg on `_prefill_batch_native_single_slab`
    and `request_lengths` a public one on
    `prefill_batch_native_layer_outer_resumable`; both default to `len(prompt)`,
    which is the ordinary-prefill value.
