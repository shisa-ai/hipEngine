# Unify SPECDEC2 production and simulator transactions

## Summary

Replaced SPEC-C0's simulator-private transaction and result types with production
SPECDEC2 records. One transaction now owns complete reserved claims, target and
optional provider modes/owners/checkpoints, cursor/RNG checkpoints, and an atomic
commit-or-rollback verdict. Terminal results carry committed IDs/lengths,
selected rows, cursor deltas, finish reasons, cancellation, and bounded logical/
physical complete-wall telemetry.

The existing simulator now constructs and returns those production records.
Compatibility aliases preserve `SpecTransaction` and `SpeculativeCycleResult`
for current callers while S1/S2 migrate.

## Changes

- Added `hipengine/speculative/transaction.py` with `SpecCycleStage`,
  `SpecCycleTransaction`, `SpecCycleTelemetry`, and `SpecCycleResult`.
- Allowed target-only K0 transactions without a stale provider owner while
  requiring atomic target/provider commit whenever a provider is present.
- Added exact claim/owner/checkpoint/request alignment and terminal-result
  validation.
- Rebased `SpeculativeCycleSimulator` on the production records and added honest
  logical C/K/R plus physical proposal/target telemetry.
- Exported the production names and retained identity aliases for old callers.
- Added RED/GREEN coverage in `tests/test_specdec2_transactions.py` and updated
  the normative S1 punchlist.
