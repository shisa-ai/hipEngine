# Release every graph and executable handle on a partial capture failure

## Summary

Repairs review finding R9 (P2). `_capture_graph_probe()` destroyed captured
graphs on the failure path but never the executables it had already instantiated,
and it ended every stream's capture whether or not that stream was still
capturing. Injecting a failure while instantiating rank 1 left rank 0's
executable allocated with no handle retained.

## Changes

- `scripts/tp_collective_bench.py`:
  - Track which ranks are still capturing, and close only those streams during
    cleanup. A stream whose capture already ended is no longer ended a second
    time.
  - Destroy instantiated executables before their graphs, each under its owning
    device, in reverse creation order. An executable references its graph, so the
    previous ordering could not be extended by simply appending a destroy loop.
  - A capture closed during cleanup contributes its graph to the same release
    list.
- `tests/test_unit_scripts_tp_collective_bench.py`: a recording runtime stand-in
  with failure injection, plus two tests: created-versus-destroyed handle sets
  must match on the failure path, and no stream may be ended twice. The probe's
  device read-backs are stubbed so the test needs no device memory.

## Validation

- RED with the previous cleanup restored: `test_partial_capture_failure_destroys_graphs_and_executables`
  failed (1 failed, 13 passed). GREEN with the fix: 14 passed.
- Real two-GPU capture smoke after the restructure, deliberately at chain depth 1
  rather than the depth-32 fault case:
  `uv run python scripts/tp_collective_bench.py --mode collective --devices 0,1
  --rows 1,2 --prefill-rows 64 --dtypes bf16 --ops all_reduce --iterations 20
  --warmup 5 --chain-depth 1 --enqueue single --graph-chain-depth 1
  --graph-iterations 5 --json /tmp/r9_capture_smoke.json`
  -> `captured: true`, `replay_matches_eager: true`, `graph_nodes: [3, 3]`,
  graph replay p50 0.3414 ms with cv 0.0061, launch p50 0.0302 ms.

## Note on the graph-node observation

The measured node count at chain depth 1 is 3 per rank: one producer memset, one
collective, one consumer memset. This is the same composition the reviewer
identified in R3 - the ladder aggregates its reductions inside one group, so the
node count does not demonstrate a per-layer dependent reduction chain. The R3
repair addresses that protocol; this entry only fixes the leak.
