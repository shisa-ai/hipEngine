# Qwen3.8 B3 wires shadow adapter ownership boundary

## Summary

Wired the GREEN B3 lifecycle state machine to explicit adapter-level
resource-pool boundaries without selecting the route. The adapter can now
acquire/drop one request's concrete shadow bundle through a declared resident
owner ABI and the existing provider checkpoint/request ABI. Production behavior
and current C1 fallback are unchanged.

## Ownership boundary

`acquire_c1_shadow_lifecycle(request_id, real_slot, shadow_slot)` requires an
active real target row/provider state, obtains a shadow target/hidden/KV/
recurrent bundle from the owner, resets a shadow provider request, captures
distinct real/shadow checkpoints, and constructs the validated lifecycle.

`drop_c1_shadow_lifecycle` closes or cancels the lifecycle before releasing the
shadow provider request. `_drop_request` invokes it before tearing down the real
provider state. If checkpoint capture fails, the adapter releases any captured
checkpoint, shadow provider request, and owner bundle atomically.

The owner-pool methods are explicit and not yet implemented:
`acquire_c1_shadow_resources`, `reclaim_c1_shadow_resource`, and
`abort_c1_shadow_resources`. Because no caller selects acquisition and the real
owner ABI is absent, the path fails closed and serving behavior cannot change.
