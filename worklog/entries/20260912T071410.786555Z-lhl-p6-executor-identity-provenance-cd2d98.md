# Resumable prefill records its own executor identity

## Summary

A reviewer flagged that the P6 service artifact proved the resumable INT8 route
indirectly and then reported the wrong executor. This unit fixes the
provenance defect at its source and makes the gate fail if it recurs.

The reviewer's finding was correct and the artifact confirms it:

- `kv_attention_sources {"int8_direct": 2.0}` — the resumable route was reached
- `oracle_observed_peak_owners 1.0`, `prefill_work_total_delta 24` — real work ran
- `executor_modes {"None": 2.0}` — no executor identity recorded
- `layer_outer_executor_mode: "layer_outer_packed"` — the harness's **constant
  expectation**, published beside the measured histogram and easy to misread as
  a measurement

## Root cause

The serving path invokes the resumable executor on
`_packed_execution_owner(lease.session)` (`qwen35_gguf.py:8213`) — the batch
owner. `last_packed_prefill_plan["executor_mode"]` was written only on `self`,
i.e. that owner, at `qwen35_gguf_runner.py:23158`. Telemetry reads the *leased*
session (`prefill_transient_owner_inventory`, `qwen35_gguf.py:221`), and for a
slot view that is a different object whose plan `resident_slot_view`
(`qwen35_gguf_runner.py:16571`) initializes to `{}`. An empty dict stringifies
to `None`, which is what the metric reported.

This also explains why the cwidth probe measured `layer_outer_packed` while the
P6 service proof measured `None`: `_packed_execution_owner` returns the session
itself when `_resident_batch_owner` is unset, so the two probes lease different
shapes.

## Changes

- `_record_packed_prefill_executor_identity` (new): writes the identity on the
  sessions the executor actually ran for. Called from
  `_prefill_batch_native_layer_outer` and re-asserted at the top of every
  segment in `_prefill_batch_native_layer_outer_segment`, so a slot view rebuilt
  between scheduler polls cannot silently lose it.
- `_GGUFResumablePrefillState.executor_mode` (new field): carries the label
  across segments.
- `prefill_batch_native_layer_outer_resumable` labels itself
  `layer_outer_resumable`, distinct from the one-shot `layer_outer_packed`, so a
  proof can positively report which of the two ran.
- `resumable_path_engaged` gate: `passed` now additionally requires a recorded
  executor identity, and the gate reports `executor_identity_recorded` and
  `executor_identity_labels`. The oracle peak is only a proxy for *which*
  executor ran, so a resumable run with no identity fails instead of passing on
  it.
- `layer_outer_executor_mode` renamed to `layer_outer_executor_mode_expected` so
  the harness's expectation cannot be read as evidence.
- `LAYER_OUTER_EXECUTOR_MODE` is now `layer_outer_resumable`, because this proof
  drives the serving path, which enters through the resumable entry.
- Artifact `notes` gained the per-session semantics: `None` means no packed
  layer-outer prefill ran on that session.

## Supersedes

The earlier entry
`worklog/entries/20260911T192828.961843Z-lhl-p6e-service-kv-never-int8-a742c1.md`
series and the CHANGELOG entry "correction: `executor_mode` does not identify
the resumable route" concluded that `None` is the expected value for the
resumable route and that the oracle peak must remain the engagement indicator.
The **diagnosis there was correct**; the conclusion accepted the defect instead
of fixing it. Both are marked superseded rather than rewritten, since committed
entries are immutable.

## Validation

- Re-ran the proof with the same gates unchanged (`--packed-layer-outer`,
  3,072-row long prompt, 512-row short, 96 decode tokens, cancellation sweep
  600/2000/3500 ms, W7900 GPU0, `HIP_VISIBLE_DEVICES=0`, compiler version file
  plus `--require-cached-build`):
  `executor_modes {"None": 1, "layer_outer_resumable": 1}`,
  `executor_identity_labels ["layer_outer_resumable"]`,
  `executor_identity_recorded: true`, `kv_attention_sources {"int8_direct": 2.0}`,
  all **eleven** gates pass, `passed: true`, `performance_claim: false`.
- Tests: `tests/test_gguf_resumable_layer_outer_prefill.py` gains four tests
  (identity written on the executed sessions; the resumable label; survival
  across a simulated mid-prompt view rebuild; the helper tolerating a missing
  plan attribute), and `tests/test_gguf_p6e_cancel_refill_proof.py` gains three
  (gate fails on missing identity, gate names the recorded identity, the proof
  expects the resumable label). The healthy fixture now carries the positive
  identity it asserts, which is the point: it previously passed on the proxy.
- 703 tests across the five affected suites, exit 0. Ruff: no new errors (three
  pre-existing in `qwen35_gguf_runner.py`).

## The remaining `None`

One of the two sessions still reports `None`. That is the honest answer rather
than an incomplete fix: the proof's short 512-row prompts are single-chunk, so
no packed layer-outer prefill ran on that session. The gate therefore requires
at least one explicit identity, not one per session. Recorded in the artifact
notes so a reader does not read it as a partial repair.
