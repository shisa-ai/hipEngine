# Close public GGUF generator ownership

## Summary

Lifecycle audit found that public `LLM.close()` closed the scheduler-facing GGUF resident runner but the underlying `Qwen35GGUFBringupGenerator` exposed no `close()` method. Sessions released back to its pools, pooled resident NextN draft runners, host-side MTP assets, and the shared full-stack weight runner therefore remained process-resident. Added idempotent generator-owned teardown and made the resident owner hand off closure after releasing all request/session/KV state.

## Changes

- `Qwen35GGUFBringupGenerator.close()` drains pooled target sessions and pooled MTP draft runners before closing the shared full-stack runner, then drops host-side MTP assets. It is idempotent and preserves the first defensive cleanup error while attempting all owners.
- `Qwen35GGUFResidentModelRunner.close()` is idempotent, clears outputs/completion metadata in addition to request/KV/session state, then closes the generator so public `LLM.close()` and server shutdown release model weights.
- Added an ownership-order test proving target sessions -> draft runners -> shared weights and a second close is a no-op.
