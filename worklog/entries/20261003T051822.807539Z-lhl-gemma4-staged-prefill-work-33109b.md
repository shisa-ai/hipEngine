# Measure and optimize exact staged Gemma prefill work

## Summary

Task #33 tests a T0 work-decomposition change to the strict-order staged
attention default introduced in 2c4dec995. On physical host `zbook`, Radeon
8060S/gfx1151, the candidate reduces synthetic staged-attention event latency
10.8–25.8% across eight BF16 causal block shapes. All paired outputs are
bit-identical, and each gain reproduces in all three measurement blocks.
The paired runner diagnostic reduces prefill latency 3.3/7.4/8.1% at
513/2053/8191 tokens, with matching IDs. Public generation and cached profiler
confirm the specialized production path. No new model topline, decode,
llama.cpp comparison or 256K performance result is claimed.

## Changes

- Specialize PV's resident query rows to 1/2/4/8 for GQA ratios that fit exactly
  in one group. Other ratios retain the generic eight-row kernel, including
  partial groups. No score/denominator arithmetic, accumulator order, workspace,
  grid, launcher ABI, profile, or default-selection changes. No new flags.
- Add a host export reporting PV resident rows from the same helper used by
  dispatch. GPU coverage pins the selection and compares exact/generic row
  groups using raw F32 bits. All four exact ratios already have strict-parity
  cases in the primitive matrix.
- Add `scripts/gemma4_staged_prefill_bench.py` and three CPU workload tests.
  The synthetic causal blocks use query/key sizes 512/513, 512/2053, 512/8191
  and 127/17000, each at 16q/8kv/d256/window1024 and 16q/2kv/d512/window0.
  These are kernel ABI shapes, not claims about the runner's effective trimmed
  KV span. Timing uses default-stream HIP events, reusable workspace and shared
  device buffers, with two configured warmups plus untimed setup/capture launches
  per arm and seven alternating AB/BA pairs per block.
- Strict `gemma4_plain` remains registered as the fallback. Production continues
  to request `gemma4_staged`; specialization is internal to its launch.

## Validation

### Baseline and acceptance

ROCm preflight loads `libamdhip64.so` and identifies Radeon 8060S/gfx1151.
`python3 scripts/check_lineage.py --kind kernel --file '*gemma4*' --diff stat`
selects zero external sources: this family is in-tree work, not a port.

The acceptance policy was written before candidate measurements: strict raw-bit
parity and primitive/ownership gates must pass; compare three independent
seven-pair AB/BA blocks over all eight shapes. Each pooled per-shape median
candidate/baseline ratio must be at most 1.02, with at least one ratio below 1.0
and that improvement reproduced in at least two blocks. The 2% margin is timing
noninferiority, not a numerical tolerance or permission to claim every shape
faster. Validate the retained candidate through public generation and cached
profiler smoke before commit.
