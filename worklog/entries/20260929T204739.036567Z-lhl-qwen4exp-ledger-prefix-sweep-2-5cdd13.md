# Eight more stale ledger status prefixes corrected to match their own conclusions

## Summary

A systematic sweep of `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md` for rows whose **State** cell begins
with a status word (`OPEN`, `BLOCKED`, `PARTIAL`) that the same cell's appended note then
**contradicts** found **16** candidates and **8** genuine contradictions. All 8 prefixes are now
corrected to match the row's own conclusion.

This is the same defect class as commit `b6c8c4e0f`, which corrected five rows. The sweep shows the
class was not exhausted by that fix - it recurs wherever a row is parked and later resolved by an
appended note rather than by editing the original prefix.

## Changes

**Documentation only.** `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md`: **8 lines changed, 8 inserted /
8 deleted, no row added or removed, no column-count change** (verified by comparing the parsed
table structure before and after). Every appended `**...**` note is preserved **verbatim** - only
the stale prefix was replaced.

| row | stale prefix | corrected prefix |
|---|---|---|
| `QA-9` | `OPEN — audit only; may close as already implemented` | `CLOSED — ALREADY IMPLEMENTED` |
| `DE-4` | `OPEN` | `CLOSED — PREMISE REFUTED BY X-5, NO MECHANISM TO EXPLOIT` |

**`QA-9` is the clearest case**: its prefix read `OPEN — audit only; may close as already
implemented` while its own body opened with the literal words `**CLOSED - ALREADY IMPLEMENTED
(20260929T).**` The row disagreed with itself.

## Method, and why the count is 8 rather than 16

The sweep parsed every table row, took the **last** cell as State (the tables have 5, 6 and 7
column shapes, so a fixed index misreads some rows), and flagged cells where a status word appears
at position 0 **and** a resolving marker (`ALREADY`, `EXHAUSTED`, `REFUTED`, `CLOSED`, `MEASURED`,
`COMPLETE`, …) appears later in the same cell.

16 rows matched. **8 were false positives**, and each was read in full before being left alone:

- **`DP-9`** - matched only because the phrase `measured-owner prerequisite` contains "measured".
  No resolving note exists.
- **`MR-4`** - `BLOCKED on the MX-1 build and gate` is still true; the note reports progress on a
  *prerequisite*, not resolution.
- **`QA-2`** - `DIAGNOSIS CORRECTED, DIRECTION STRENGTHENED` corrects the evidence reading but the
  row remains genuinely open. **It stays open.**
- **`DE-1`, `DE-5`** - the note says the `X-4` dependency is *satisfied*, which unblocks the row; it
  does not claim the row's own experiment is done.
- **`MT-3`, `MT-4`** - `STILL BLOCKED` confirms the `BLOCKED` prefix rather than contradicting it.
- **`DP-8`** - `PARTIAL` is an accurate state; the row genuinely has follow-on work.

**The rule applied: correct a prefix only where the body unambiguously resolves or restates the
state.** Where a note reports progress toward an open row, the prefix stands.

## Validation

- Table structure compared before/after: 60 rows before, 60 after; **no column-count changes, no
  rows added or removed**.
- Diff is exactly `8 8` (`--numstat`), i.e. one line touched per corrected row.
- Each of the 8 new prefixes was verified to render at the head of its cell with the original
  appended note following intact.
- Each of the 8 false positives was read in full and deliberately left unchanged.

## Limits

**Status-prefix bookkeeping only - no experiment, no measurement, no performance claim.** The
corrections restate what each row's own already-committed note concludes; no underlying evidence is
re-derived or re-checked here. A row marked `CLOSED` by this commit is closed **on the strength of
its own recorded evidence**, which was not re-verified.
