# TP2 Packet 1: implicit device and default-stream ownership audit

## Summary

Packet 1 asks for an audit of core, weight loading, runtime workspaces, graphs,
the native cycle ABI, the sampler, and global caches for implicit device-zero and
default-stream ownership. This is that audit. It found one structural hazard and
no live bug.

**The hazard.** HIP kernel host wrappers take an explicit stream and **no
device**, so a launch lands on whatever device the calling thread currently has
selected. In `laguna_kv_attention.hip` the wrapper
`hipengine_laguna_global_head_rmsnorm_rope_write_kv_f32_bf16_spans` ends its
signature with `hipStream_t stream` and launches with `hipLaunchKernelGGL(...,
stream, ...)`; there is no device argument to pass and no device check to fail.
The same shape holds across the tree: **51** launch modules, **31** identical
`_check_launch` definitions, and **452** call sites under `hipengine/kernels/`
(54 files tree-wide match the launch pattern). None of them can detect that the
thread is pointed at the wrong device.

**Why it is not a live bug today.** Every path that allocates, copies, or frees
is either device-explicit or device-attributed, and the single-device engine
never changes the current device, so the implicit choice is correct by
construction. It becomes a real defect the moment a rank-bound runner drives two
devices from one thread: a section that forgets its device scope does not raise,
it computes on device 0 with rank 1's pointers.

**The mitigation that exists.** `scoped_current_device` in
`hipengine/core/device.py` selects a device and restores the previous one on
success and on exception. `RankRuntime.activate()` in
`hipengine/distributed/context.py` is that context manager bound to a rank, and
it is the mechanism `hipengine/distributed/` uses everywhere: `context.py` and
`rccl.py` are the only modules in the package that select a device, and neither
calls `hipSetDevice` directly. Rank binding therefore has exactly one primitive
to route through, which is what Packet 3 needs.

## Subsystem findings

| Subsystem | Verdict | Evidence |
| --- | --- | --- |
| Core | explicit or attributed | `core/memory.py` `malloc(device=…)`, device-selecting `free`, `copy_device_to_device` with cross-device refusal. Even the implicit path records the owner: `malloc` with `device=None` still sets `DeviceBuffer.device` from the runtime's current device (`memory.py:139-141`), so a mis-attributed buffer is detectable rather than invisible. |
| Weight loading | explicit-capable | `device: Device \| None` is threaded through `loading/materialize.py`, `laguna_gguf_materialize.py`, `maple.py`, `evie.py`, and `dflash.py`. The `None` default resolves to the current device, so the loader inherits the caller's binding. |
| Runtime workspaces | inherited, single site | `runtime/native_sampler.py:605` allocates its workspace through `malloc(...)` with the runtime and no device, so it is attributed to the current device. Every other workspace is built from `DeviceMemoryArena` or `malloc` and follows the same rule. |
| Graphs | device-explicit by construction | The native submission context is bound to a specific PCI BDF rather than to a thread-local device: `core/pm4/transport.py:550` and `:587` pass `runtime.device_pci_bus_id()` into `NativePm4Context.create`. A context for device 0 cannot silently serve device 1. |
| Native cycle ABI | device-explicit by construction | Same PM4 context path; the cycle ABI is instantiated from a graph manifest against that BDF-bound context. |
| Sampler | host-side, one device touch | `generation/sampling.py` and `dispatch/sampling.py` build host-side plans and parameter blocks; the only device interaction is the workspace allocation above. |
| Global caches | correct, with a caveat | `core/build.py:429` `_LOADED_LIB_CACHE` and `core/pm4/graph.py:97` `_DSO_CACHE` are keyed without a device component. That is right for host-global DSO images, and it is exactly why the hazard above matters: the cached artifact is device-neutral, and device code is bound at launch time from thread state, not from the cache key. |

## Default streams

No audit finding. Kernel wrappers take the stream as an explicit parameter and
the launch sites pass one through; the collective transport creates its own
non-blocking streams through `RankRuntime.stream_create`. The default stream is
not the mechanism that decides placement here, and a rank's stream is created
under that rank's device scope, so stream and device agree.

## Changes

- `tests/test_unit_core_device_ownership.py`: two audit fences.
  `test_kernel_launch_surface_stays_visible_to_the_audit` pins the launch surface
  (51 modules, 31 check definitions, 452 call sites) and asserts the wrapper
  signature really has a stream and no device, so the audit cannot go stale
  silently. `test_distributed_package_binds_devices_through_one_mechanism`
  asserts that `context.py` and `rccl.py` are the only device selectors in the
  package and that neither uses `hipSetDevice`/`set_device` directly.
