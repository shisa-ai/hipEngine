# Task 43: the AR control arm was a duplicate MTP arm - the same env-strip footgun, one namespace over

## Summary

The corrected task-39 sweep (`bg-238`, four arms across two server processes)
finished, and its "AR control" arm is not an autoregressive baseline. Every
"AR" row is byte-identical to its MTP counterpart: same `generated_ids`, same
`effective_route`, same `speculative_cycles`. The two arms were the same
measurement taken twice, so their near-1.00 ratio is an artifact of being the
same run, not evidence that speculation does not help.

The cause is the footgun this task family was already chasing, in a different
variable namespace. The arm selected AR with
`BENCH_EXTRA_JSON='{"speculative_mtp": false}'`, and the launcher ran
`exec env -i`, which forwards a hand-written list of variables. That list
carries `HIPENGINE_HIP_ARCH` and `HIPENGINE_MTP2_OUTPUT_SPANS`, so
`BENCH_EXTRA_JSON` was stripped before the harness read it. Every artifact
records `"request_extras": {}`.

Evidence, `ar-*` versus its `mtp-*` twin on the same server process:

| shape | ids identical | route (both) | cycles |
| --- | --- | --- | --- |
| 512 | yes | `speculative_mtp` | 55 / 55 |
| 1024 | yes | `speculative_mtp` | 23 / 23 |
| 2048 | yes | `default` | - |
| 4096 | yes | `default` | - |
| 8192 | yes | `default` | - |

and at the raised window, 512/1024/2048/4096/8192 all `speculative_mtp` with
cycles 55/44/64/54/55 matching exactly.

Two things follow. First, task #39's acceptance criterion - a true same-protocol
no-MTP autoregressive baseline - is **still unmet**; three attempts have now
failed to produce one. Second, the environment preflight committed in
`de70150b6` would **not** have caught this: it covers `HIPENGINE_*` only, and
the stripped variable here was `BENCH_EXTRA_JSON`. The committed fix is
necessary but not sufficient, and that gap is the point of this entry.

## What the sweep does establish

Route and coverage are server-reported facts rather than timings, so they
survive the broken control arm:

- Default window (1,023): MTP coverage 0.992 at 517 prompt tokens, 0.602 at
  945, then MTP declines entirely at 1,804+ (`effective_route=default`,
  `decision_reason=backend_k0_fallback`, `fallback_event_counts` of
  `no_provider: 127`).
- Raised window (8,192): MTP coverage **0.992 at every shape up to 6,972
  prompt tokens**.

So the admission window is a real lever, and `target_graph_context_bucket_miss`
is not the binding constraint once the window admits the request: the 49
bucket misses seen at 945 tokens disappear when the window is raised. What the
window buys in tok/s is **unmeasured**, because there is no AR denominator. The
apparent 1.36-1.82x across the default-window AR rows and the raised-window MTP
rows confounds a route change with a window change and must not be reported as
an MTP speedup.

## Changes

- `scripts/gguf_mtp_server_pair_bench.py`
  - `route_mismatches(result, expected=...)` names every recorded run whose
    `effective_route` differs from the arm's declared route, reading both the
    `route` summary and each entry in `runs`.
  - `--expect-route {any,default,speculative_mtp}` makes the harness refuse to
    write its artifact (exit 3, message on stderr) when any run disagrees. The
    intent is declared on the command line rather than in the environment,
    because an environment-declared arm loses its intent exactly when a
    launcher clears the environment.
- `tests/test_unit_gguf_mtp_server_pair_bench_acceptance.py` - 6 new tests:
  a matching arm passes, the recorded duplicate-route shape is named, one
  degraded shape invalidates the arm, a missing route is a mismatch rather than
  a pass, prompt rows are checked as well as shapes, and the CLI offers the
  flag.

## Next

- Read `bg-240`. If server A's request-field AR arm fails its route contract
  (exit 3), the `speculative_mtp: false` request field does not disable MTP and
  every AR baseline must come from a `--speculative-mtp-serving off` server.
  Either outcome is a finding, and the harness now says which one it is instead
  of recording a duplicate as a control.
- Extend the environment preflight beyond `HIPENGINE_*`. The general rule is
  that any variable a launcher forwards by hand can be lost, so the check
  should cover the harness namespace too (`BENCH_*`), and ideally a launcher
  should forward the whole namespace rather than a list. The forward-all wrapper
  pattern is now in `benchmarks/HARNESSES.md`; `/tmp/t43-env.sh` is the working
  example.
- Three failed attempts at one baseline is itself the finding: the missing
  control was never a modelling question, it was a launch-plumbing question
  that failed silently twice in two different namespaces. Assert the intent,
  and let the harness refuse to write an artifact when the arm did not run it.
