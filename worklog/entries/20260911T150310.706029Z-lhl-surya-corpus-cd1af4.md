# Surya held-out OCR corpus: two-column and list layouts, torch-oracle gated

## Summary

The last pending coverage item. Every page fixture so far is single-column
prose: `page_small.png` and `page_rect.png` are bar patterns whose oracle
output is a degenerate repeated `<ul><li>` run, and `page_full.png` is one
column of prose plus a small table. Added two held-out layouts with real words
that the single-column fixtures structurally cannot produce, so the GPU lane
cannot pass them by generalizing from what is already covered.

## Changes

- `scripts/surya_oracle_torch.py`: extracted the TrueType font lookup into
  `_find_font()` (previously inline in `_make_synthetic_page_full`) and added
  `_make_synthetic_page_columns` / `_make_synthetic_page_list`.
- `scripts/surya_oracle_greedy.py`: new `--case corpus` writing
  `page_columns.png`, `page_list.png` and `oracle_corpus.json` (ids + text per
  page). Both pages are 512x512 — a multiple of the resize factor, so the grid
  is a clean 1x32x32 and the CPU-vision cost stays at ~4.6 s rather than the
  ~18.5 s a 1024x1024 page costs.
- `tests/test_surya_gpu.py`: parametrized
  `test_gpu_ocr_corpus_matches_oracle` over `columns` / `list`, gating GPU
  greedy IDs against the torch fp32 oracle exactly, plus a non-degeneracy
  assertion (>= 10 distinct ids) and a JSON parse.
- `tests/fixtures/surya/`: `page_columns.png`, `page_list.png`,
  `oracle_corpus.json`.

## What the layouts exercise

| Page | Grid | EOS at | Decoded labels |
| --- | --- | --- | --- |
| `page_columns.png` | 1x32x32 | 94 | `Section-Header` (title), then a left pair (x 65-419) and a right pair (x 543-897) |
| `page_list.png` | 1x32x32 | 46 | `Section-Header` + `List-Group` + `Text` |

`page_columns.png` is the interesting one: the oracle keeps the two prose
columns apart as separate left-column and right-column blocks, so this gates
column detection and reading order rather than just text finding.
`page_list.png` is the only fixture that reaches the `List-Group` label.

Both pages reach a natural EOS well inside the 96-token budget, so the parity
comparison is against a complete answer, not a truncated one. Both outputs are
valid JSON ending in `]`.

## Validation

- Both corpus cases pass on gfx1151.
- Reproducibility: re-running `--case corpus` regenerates all three fixtures
  byte-identical (`cmp` clean for both PNGs and `oracle_corpus.json`), and
  `git status` is unchanged afterwards.
- Independent cross-check before committing: the GPU and NumPy CPU reference
  agree on both pages (columns 64/64 ids in a 64-token probe, list 46/46),
  so the torch oracle is not the only lane confirming them.
- Full Surya bundle on gfx1151: 98 passed.
