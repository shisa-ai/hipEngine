# yue2 paired CFG branch forward on gfx1100

## Summary

The YuE2 AR decode runs two CFG branches over one set of weights and spent 95% of a step in the
projection forward. `Yue2ArRuntime.forward_layers_paired` now advances both branches in one pass:
each projection is a single two-row launch instead of two one-row launches, so the weight stream is
issued once for both rows. The AR step goes from **37.96 ms to 32.10 ms (1.18x)** at product depth
and the full product request from **90.36 s to 79.60 s (RTF 1.21 -> 1.069)** with the generated
audio bit-identical to the pre-change run.

Measured on `epyc` / Radeon Pro W7900 (`gfx1100`, ROCm 7.2), `m-a-p/YuE2-3B@29b3558` +
`m-a-p/YuE2-Vae@9a94e1d`, BF16.

## Changes

- `hipengine/kernels/hip_gfx1100/linear/dense_gemv.hip`, `dense_gemv.py`: two BF16-output two-row
  kernels, `hipengine_dense_gemv_out_bf16_rowtile2` (the `o` and `down` projections) and
  `hipengine_dense_dual_gemv_out_bf16_rowtile2` (the `gate`/`up` projection). Both keep the
  single-row kernel's K traversal, tail handling and local-256 reduction tree, so a row's result is
  bit-identical to the single-row kernel's; the existing F32-output `..._bf16_f32_out_rowtile2`
  covers `q`, `k` and `v`. Registered through `hipengine/kernels/vibevoice.py`'s primitive list.
- `hipengine/runtime/yue2_ar.py`: per-branch pair scratch buffers plus `forward_layers_paired`,
  which pairs every projection, the bf16 casts, the q/k head norms and the SiLU multiply, and keeps
  per-branch what genuinely differs: KV writes and attention reads (different caches and spans) and
  the two rotary calls (different positions). `forward_layers` is untouched, so the single-branch
  route and the prefill path are unchanged.
- `hipengine/runtime/yue2_session.py`: the AR loop calls the paired forward when both branches are
  live.
- `tests/test_unit_yue2_ar_gemv_rowtile2.py`: per-row bit-identity gates for both new kernels on the
  production shapes plus rows 1 and 3 (an odd row count runs the second block with one row).
  `tests/test_unit_yue2_session.py`: the fake runtime grows the paired entry point, so the CFG
  session tests assert the same per-branch decode records as before.

## Validation

- Bit-identity of the paired path against two serial `forward_layers` calls: 12 steps after 900
  warm steps (context ~1010), comparing the logits and both branches' hidden rows every step:
  0 mismatches, worst absolute delta 0.0. A shallower 6-step/40-warm-step run agrees.
- `uv run pytest tests/test_unit_yue2_ar_gemv_rowtile2.py tests/test_unit_yue2_ar_runtime.py
  tests/test_unit_yue2_session.py`: 40 passed (15 of them the rowtile gates).
- `scripts/yue2_session_gate.py`: 3/3 cases PASS with teacher-forced agreement identical to the
  committed `gfx1100` artifact (ABC 0.991 / 0.998, semantic 0.980 / 0.969 / 0.967).
- Product path through `hipengine.LLM.generate()`: 1 862 frames / 74.479 s of audio in 79.60 s
  (RTF 1.069) once warm, `repeat_bit_identical: true`, audio identity
  `02dda95062bf9c1c00e433cedcba9ba385432f554c16db48fe25fc333526ab14` — unchanged from the
  qualification run at `9b1e0fc41`, and no torch import.
- `scripts/yue2_ar_step_profile.py --tokens 150 --depth 900 --sync [--paired]`: head 1.08 ms,
  sampler 0.81 ms, forward 36.10 -> 30.22 ms. Depth scan of the paired forward: 12.18 ms at 98
  tokens of context, 30.22 ms at 998.

## Next

- Span attention is now the largest term at product depth: 18.0 ms of the 30.22 ms paired forward at
  998 tokens of context (60%), growing linearly. `vv_attention_spans` launches one 256-thread
  block per query head (16 blocks for 40 CUs) and reads the bf16 K/V rows with a per-token stride, so
  the warps issue uncoalesced 2-byte loads. Fixing it means a different reduction order, which is a
  production-variant numerics gate rather than a bit-identical swap; not attempted here.
- A discarded per-kernel microbenchmark measured 1.3-3.0 TB/s on these matrix sizes because the
  weights stay in Navi31's Infinity Cache across repetitions. Do not use cache-resident GEMV
  microbenchmarks to reason about this model: the real step streams 2.8 GB per branch from HBM.
