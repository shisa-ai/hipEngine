# Rebind PARO full-attention scratch views after row-count changes

## Summary

Fix repeated-request PARO MTP output drift by binding full-attention scratch views to the executing row count. The repair changes no kernel arithmetic and adds no flag.

## Changes

- `_ensure_full_prefill_scratch` now reuses a view only when its row count and query dtype match the requested layout. Capacity alone is insufficient: `reserve_full_attention_scratch` places the key view after `tokens * 2 * q_width`, while the one-row fused Q/K projection writes the key immediately after one query row. Reusing a two-row view reads old bytes as the prompt key.
- Added `tests/test_unit_paro_prefill_scratch_shape.py`, covering 2-to-1, 32-to-1, 32-to-7 and same-layout reuse. Three tests failed before the repair; all four pass afterward.
- This defect predates the concurrent cache-only prompt optimization. Clean `1906b54d2` and the working candidate produced the same singleton cold/warm divergence before this repair. At length one the cache-only optimization executes no historical rows.
