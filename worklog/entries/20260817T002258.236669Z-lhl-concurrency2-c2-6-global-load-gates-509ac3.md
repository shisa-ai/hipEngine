# Adapt C2-6 load gates to fixed global pages

## Summary

Adapted the long-context/pressure and production-load protocols from Generation-1 chunk growth/shrink assumptions to load-time `GlobalKVPoolSet` capacity and generation semantics. Also fixed direct-script module resolution so a gate cannot silently execute another editable hipEngine checkout.

- Global pool capacity now honors a configured high-water ceiling at each idle reconfiguration and increments storage generation on every rebuild.
- Global allocation failures feed the compatibility pressure-rejection counter while growth/shrink remain zero by design.
- Long-context pool planning uses simultaneous fungible-page sums rather than one-contiguous-run chunk packing.
- Pressure lifecycle expects a fixed 134-page generation, an exact 32K survivor, retryable 4K rejection, zero final ownership, and no growth/shrink.

- Production route evidence now falls back to physical plans sampled directly from `live_loop_snapshot()` when the legacy poll-hook timeline is empty.
- The long-context gate now uses Generation-2 `token_budget` scheduling.
