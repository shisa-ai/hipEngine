# TP2 uneven split: admit the uneven shard widths to the dense pair+SiLU allowlist

## Summary

The first end-to-end run of the uneven split generated the right tokens but
reported `variant=None` on both ranks: `GGUF_DENSE_PAIR_SILU_DECODE_POLICIES` is
an **exact-shape allowlist** holding only `(1, 5120, 17408)` (TP1) and
`(1, 5120, 8704)` (the even TP2 shard), so moving the boundary to 7168/10240
dropped both ranks to the unfused three-launch chain. That is a silent
performance regression hidden inside the rebalance - the fused route is one
launch where the fallback is three - and it would have made an even-vs-uneven
wall comparison measure the fusion loss instead of the balance gain.

The kernel's own contract never excluded those widths:
`dense_t16_pair_decode_shape_error` requires only `rows == 1`,
`in_features % 256 == 0` and `out_features % 16 == 0`, and it admits every
candidate width including ones the solve never proposed. So this was an
allowlist gap, not a kernel limit, and the fix is a measurement rather than a
kernel change: both new widths are now **bit-identical to the unfused chain on
both ranks** on real layer-0 weights, and the two rows are admitted.

## Changes

- `scripts/tp2_mlp_pair_admission_probe.py` (new): builds each rank's
  resident-layout payload from the shard manifest for an arbitrary split,
  runs the unfused chain and the fused candidate on the same bf16 input bytes,
  and compares `activated` and the down partial byte for byte. Admission
  requires the kernel contract to accept the width **and** every compared field
  to be bit-identical on every rank; a failed launch, a missing field or a
  shape mismatch all count as *not* admitted, because absence of a difference is
  not evidence of equality. The verdict rule is pure and unit-tested.
- `hipengine/kernels/hip_gfx1100/__init__.py`: `(1, 5120, 7168)` and
  `(1, 5120, 10240)` join the `MOSTLY_Q4_K_M` pair+SiLU allowlist with the
  measurement cited inline. The launcher still validates the shape before any
  HIP contact, so an unadmitted width still falls back safely.
- `tests/test_unit_qwen35_gguf_geometry_policy.py`: the three TP2 shard widths
  resolve, and a width the solve has not admitted (8960) stays unresolved
  rather than snapping to a nearby row - the allowlist is exact-shape on
  purpose.
- `scripts/tp2_uneven_split_smoke.py` (new, promoted from a scratch script):
  the end-to-end uneven-vs-even smoke, with the per-rank widths, per-rank
  variants, token ids, teacher-forced logits and top-1 agreement in its
  artifact. It exits non-zero on a token mismatch, a shape mismatch or any
  flipped top-1; logit *values* are reported as context, not as a pass rule,
  because the split legitimately regroups the `ffn_down` sum.
- `benchmarks/results/2026-09-18-w7900-tp2-pair-route-admission-uneven.json`
  (new): the admission measurement.

## Validation

- `python3 -m pytest tests/test_unit_scripts_tp2_mlp_pair_admission_probe.py
  tests/test_unit_scripts_tp2_uneven_split_smoke.py
  tests/test_unit_qwen35_gguf_geometry_policy.py` - all pass (16 + 12 + 7).
- Admission measurement on the two-card host, layer 0, real Q4_K_M weights, at
  the 0.417145/0.582855 split: rank 0 (W7900) width 7168 and rank 1
  (RX 7900 XTX) width 10240, both `activated` and the down partial
  **0 differing elements** against the unfused chain; kernel contract `None`
  for both widths. The probe is not vacuous - the fused path calls
  `launch_gguf_linear_pair_silu` with the explicit variant and raises if it does
  not launch.
- Re-run smoke after the rows landed: both ranks resolve
  `dense_dual_local32_bf16_bf16_out`, the uneven session still generates the
  same tokens as the even split, and every teacher-forced top-1 agrees.
