# c1-c8 MTP server bench pins its own worktree on sys.path

## Summary

`scripts/gguf_mtp_c1c8_server_bench.py` imported `hipengine` before doing
anything about `sys.path`. The venv installs `hipengine` as an editable
pointing at `/home/lhl/hipEngine-main`, and running a script puts the script's
own directory (not the working directory) at `sys.path[0]`, so the bench
resolved the **other** worktree's source and measured it.

I hit this while starting the UD c1-c8 run: the first attempt failed with
`unsupported Qwen3.5 GGUF tensor type 'Q3_K' outside rank-3 expert slots` from
`/home/lhl/hipEngine-main/hipengine/loading/qwen35_gguf_materialize.py` while
the same artifact loads fine from this worktree. Nothing in the output said
which tree ran.

The three UD MTP scripts (`ud_mtp_paired.py`, `ud_mtp_ar_verify_numerics_gate.py`,
`gguf_mtp_verifier_rocprof.py`) already insert their own `REPO_ROOT` at
`sys.path[0]` and have a test for it; this bench did not.

## Changes

- `scripts/gguf_mtp_c1c8_server_bench.py`: `REPO_ROOT` and the `sys.path`
  insert now precede the `hipengine` imports, with the reason recorded in a
  comment.
- `tests/test_gguf_mtp_c1c8_server_bench.py`: a reload-based test asserting
  `REPO_ROOT` is this worktree and that `hipengine.__file__` resolves under it.

## Validation

- `uv run pytest tests/test_gguf_mtp_c1c8_server_bench.py -q` — 24 passed.
- Direct check: running from `/tmp` with only `scripts/` on `sys.path` and the
  plain venv interpreter now reports
  `hipengine /home/lhl/hipEngine-ud/hipengine/__init__.py`, where before it
  reported the `hipEngine-main` path.

## Next

The bench also refuses to run on a dirty worktree, so any edit to it must be
committed before a measured run. That check is why this fix landed before the
UD c1-c8 sweep rather than alongside it.
