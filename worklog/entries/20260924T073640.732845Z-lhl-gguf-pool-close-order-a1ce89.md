# Engine close releases the packed workspace before the KV pool

## Summary

`Qwen35GGUFResidentModelRunner.close()` failed at shutdown after any INT8 MTP
server session:

```
RuntimeError: cannot close global device KV pool with private workspace
  hipengine/generation/qwen35_gguf.py:6771 in _teardown_kv_pool -> pool.close()
  hipengine/kvcache/device_global.py:638
```

The owner's packed workspace holds a private-workspace *reservation* in the
pool, and `GlobalDeviceKVPool.close()` refuses to close while one is held. The
guarded release that frees it is `release_idle_packed_workspace`, which
`_teardown_kv_pool` runs only when it is asked to (`release_workspace_state`).
`close()` passed `False`, so the reservation survived to `pool.close()`; the
resize and reconfigure paths already passed `True`. The `False` was harmless
when it was written -- only the packed workspace *lease* existed then, and the
lease is released unconditionally -- but `reserve_private_workspace` landed
afterwards (`e2dccb3a0`, `441d3c483`) and made the pool refuse to close while a
reservation is held. The fix is the one line that restores the documented order
("when the owner-shared packed workspace borrows arena planes it must also be
freed first").

This is not caused by the INT8 width change in `7c3914162`: the failure
reproduces at automatic width 1, which engaged MTP before that change and is
untouched by it. It is why the readiness row's named sweep could not produce an
artifact at all -- every cell ran, then the TestClient's lifespan shutdown raised
before the script wrote its JSON.

## Changes

- `hipengine/generation/qwen35_gguf.py`: `close()` now calls
  `_teardown_kv_pool(release_workspace_state=True)`, with the reason recorded at
  the call site.
- `tests/test_unit_gguf_packed_workspace_stability.py`: added
  `test_engine_close_releases_the_owner_workspace_before_the_pool`. It holds a
  real private-workspace reservation in a fake-backed `GlobalDeviceKVPool`,
  asserts the pool refuses to close while it is held, then drives the engine's
  own `close()` and asserts the owner's release ran first, the pool closed, and
  `private_workspace_bytes` is back to zero.
