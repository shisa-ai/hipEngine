# Run Inkling loop controllers on the device for fast prefill

## Summary

Inkling GGUF `fast` now forms the loop-controller input, and gates, blends and normalizes the controller output, in two device kernels inside the controller projection exchange. At 575 input tokens on W7900 the public route took 4.12 s instead of 5.02 s. Generated tokens match the host path on both GPUs, and KL from `strict` stays at the level of the host path. Scalar decode, `strict` and the unnamed profile keep the host expression, so decode speed is unchanged. This was not timed on Strix Halo.

## Changes

- Add `norm/inkling2_controller.hip`. `input` writes `[rms(x) | rms(message)]` for the down projection. `blend_norm` applies `(1 - tanh(forget)) * x + tanh(gain) * message`, RMS-normalizes it and scales by the norm weight. Both read controller-major rows and keep each operation separately rounded.
- Register `inkling2_controller` on gfx1100 and gfx1151 with `host_blend_norm` as the strict control, and name its `committed_block_controllers` scope in the execution manifest.
- `project_controllers_normed` on the GGUF projections uploads inputs, messages and norm weights once, runs the chain, and downloads the normed rows. The session uses it for multi-row controller merges in committed sessions. Staged decoding, undo and scalar rows keep the host path, and the norm moved inside `merge_controllers` so both paths apply it once.
