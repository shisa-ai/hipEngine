# Add post-binder overrides to the context decode profiler

## Summary

The prefill profiler accepts `--override HIPENGINE_KEY=VALUE` and records the
resulting route environment; the context decode profiler did not, so
`capture-hipengine` failed at its decode phase with an argparse exit whenever an
override was passed. Decode now accepts and records the same override, reusing
the prefill helper rather than a second implementation, so one override applies
to both phases of a capture instead of only the prefill half.

## Changes

- `scripts/qwen4exp_context_decode_profile.py`: imports
  `_parse_overrides` and `_apply_post_binder_overrides` from
  `scripts/qwen4exp_profile_gap.py`, adds `--override`, applies it after the
  production binder and before warmup, and records `named_profile_intact`,
  `configuration_class`, `overrides`, `override_stage`, `bound_route_env` and
  `route_env` under `profile`.
- No default changes. With no `--override` the applied environment and the
  child's behavior are unchanged; the added report fields describe that state
  rather than altering it.

## Validation

- `.venv/bin/python -m pytest tests/test_unit_qwen4exp_context_decode_profile.py
  tests/test_unit_qwen4exp_profile_gap.py` → 17 passed.
- `--help` on the decode profiler shows the new argument; both scripts parse
  and import cleanly.
- The override is applied at the same stage as the prefill profiler
  (`post_profile_binder_pre_measurement`), so a capture cannot report an
  override that was never in effect.
