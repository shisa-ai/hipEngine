# Reject a shared small-chunk DMS prefill override

## Summary

A diagnostic-only 256-row shared prefill override reduces recurrent-layer
work but substantially increases full-attention work. Do not apply it as a
production fix. Investigate independent per-family partitioning instead.

## Changes

No repository runtime changes. Diagnostic scripts live under
`~/gate-runs/qwen38-edge-cache-repaired-20260926/`:
`profile-prefill-stages.py` enables the existing synchronized recurrent-stage
timers; `profile-prefill-small-chunks.py` additionally monkeypatches the manual
chunk size to 256 for this isolated experiment only.

## Validation

Both scripts complete public MTP generation on physical host `gfx1151`, AMD
gfx1151, Qwen3.8-27B Q4_K_M, production, BF16 DMS, radix cache, 4,097 prompt
tokens, eight output-token limit, temperature zero. Run each using
`bash /tmp/t17-env.sh python` followed by the script path above. Exact model,
sidecar, and constructor settings are in each script.

- Synchronized method-time totals: original recurrent 11.152 s, full attention
  3.017 s; small shared chunks recurrent 8.804 s, full attention 27.699 s.
- Artifacts: `prefill-stage-profile/layers.json` and
  `prefill-small-chunk-profile/layers.json`.
- Stage timings attribute much of the large recurrent-layer cost to projection
  and feed-forward calls, not just recurrence.
- These are single-prompt instrumented attribution results, not serving speed
  or quality claims. The slower diagnostic override is not promoted. No
  numerical gate is asserted; output equality was not tested for this override.

## Next

Investigate independent recurrent subchunks within larger full-attention
chunks, accounting for scratch metadata and DMS cache capture boundaries.
Do not repeat the global small-chunk experiment. Dense INT8 numerical repair
and the six-arm comparison remain open.
