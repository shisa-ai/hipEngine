# Record the first resident block traversal attempt

## Summary

The device-resident block traversal was written and it ran end to end on a 64-token prefill, but its logits disagree with the host path by KL 9.2, so the attempt was reverted rather than shipped. The committed state is unchanged: the host traversal is the only block path, and the arena support it would use (`plan.device`, `device=` on the expert chain, the residual kernels) stays in place and unused.

## Changes

- None committed. This records six defects that had to be fixed before the traversal would run at all, and what remains.

## What the attempt established

- `_resident_block` needs `projection.resident()` to be reentrant: the arena holds the projection lock for the whole block, while `resident_vector`, `project_from_device` and `project_experts_mixed_rows` each take the same lock. `Inkling2DeviceDense` uses a plain `Lock`, so the first attempt deadlocked; `RLock` fixes it.
- The residual launchers must be imported where registration happens (`hipengine/generation/inkling2_gguf.py`), or `supports_resident_block` is false and the traversal silently never runs.
- `_attention_plan` has to return the plan and let the caller project it, and the traversal must pass shape placeholders for `inputs` whenever the real inputs are device pointers.
- The router projection needs the tensor name from `weights.names`, not the alias.
- Loop message passes also occur on local core layers, where the attention read produces one row that all three controllers share; the fourth message row is the one the mlp controller consumes.

## Validation

- A 64-token prefill through the traversal completes and returns finite logits, but against the host path: KL 9.24, max absolute difference 21.9, top-20 overlap 3 of 20, and the final output normalization overflows. That is a layout or bookkeeping error, not a missing stage, since every stage ran.
- `tests/test_unit_inkling2_gguf_runtime.py` and the committed GPU suites pass at this commit; the tree is clean and the host block path is the one in use.

## What remains wrong

- Unexamined suspects, in order: the stack write before the attention read at a residual-block boundary (the host appends `_rms(h)` after the attention, so the boundary visit's read must see it only as the partial); the prelude snapshot and its two rotating regions across repeated core passes; and whether the mlp read's `_rms(a)` write lands at the same slot the host's `values` list uses when the previous visit was a boundary.
- The state-by-state harness cannot check this path: it captures per-visit hidden states, and the traversal only runs with `capture is None`. A comparison of final logits per depth is the usable check, and it needs to pass before any timing.

## Next

- Rebuild the traversal with the fixes above, then debug the layout against a two-visit prefix (layer 0 and layer 1) before running a full block, comparing the device `h` and stack rows against the host arrays one visit at a time.
