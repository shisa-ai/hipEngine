## Validation

- This is the **pre-output** instance: the failing row had no committed output
  (`answer_chars=0`), so the client sees a consumable HTTP error before the first
  chunk. The contract that commit `02ae1c256` fixes is the post-commit one, and
  it is not exercised here.
- The site is the packed multi-row work-batch prefill
  (`_try_prefill_native_work_batch`), not `_prefill_native_row`, so the
  per-session fallback added by `02ae1c256` does not cover it. The containment
  layer from `de6d31685` classifies it as `state_mutation=partial` and reports a
  named `execution_failed` 500 instead of the bare
  `unsupported_parameter` 400 the same guard produced on 2026-09-18.
- The guard needs `max_live_count >= 1024` with no slot-local full attention.
  With `attn_aotriton_min_tokens = 512` that is a non-contiguous COW allocation
  (`device_kv_nonidentity_scatter`) or a slab whose longest slot stays under the
  threshold; an ordinary long prompt keeps slot-local attention and does not
  reach it. At c=8 the resident KV pool fragments, which is why this run hit it
  while the c=1 and c=2 runs did not.
