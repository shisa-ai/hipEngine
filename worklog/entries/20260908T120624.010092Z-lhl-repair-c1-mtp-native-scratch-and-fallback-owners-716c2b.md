# Repair C1 MTP native scratch and fallback ownership

## Summary

The requested RX 7900 XTX comparison exposed real C1 MTP failures in the
direct dense GGUF suite. Investigated on the identical Qwen3.8-27B Q4_K_M
file (SHA-256 7b2aec3b9ababdfd75aa17552ee95607d866e44decf547f6f12fcef85cc89f1b),
physical GPU1 / 0000:10:00.0 / 0xcc4d02090dc9c3ff.

The default-capacity trace reaches position 93 and correctly selects serial
verification for rows ending at 96, but the initial-state-only journal cannot
capture serial rows. At configured capacity 1024, the first target verification
produces invalid INT32_MAX token IDs. An eager per-layer capture localizes NaNs
to layer 0's Conv/GDN handoff, not the final sampler or the drafter.

The 1024-row prefill arena places linear_qkv, conv_out and recurrent_bf16 at
offset zero. Bulk prefill stages QKV through another representation before
reusing that storage; the native BF16-input chain does not. Its FP32 convolution
write overwrites later BF16 input rows, and its direct BF16 GDN output also
shares the convolution input. This is a lifetime/control bug, not allowable
numerical drift.

## Changes

- Give native verification a row-sized, separately owned FP32 convolution
  handoff. Keep the large bulk-prefill arena and its optimized lifetimes
  unchanged. Track the new pointer in native graph binding signatures; reuse,
  grow, slot-view cleanup and final teardown follow the existing verify owner.
- Preserve the compact producer-owned native journal. Lazily allocate and
  reuse a separate full consumer journal for serial fallback; keep both alive
  so captured native pointers remain valid, and close both exactly once.
- Bound the immutable captured context extent by the backend's existing graph
  limit, not only the live end position. Expose qualified short buckets through
  the existing cached-handoff alias; do not widen gfx1100's 95-position limit.
- Check the same native policy before device-only proposal launch. Keep
  positive short-output tails on the existing N2 accept/commit contract instead
  of sending placeholder IDs through a host path.
- A delayed-H2D unit test independently exposes mutation of proposal position
  upload arrays before consumption. Use the existing by-value device metadata
  setter, preserving the advanced host bookkeeping without that source race.
- No device kernel bodies, arithmetic, backend/model/quant selection branches,
  dependencies, or new environment flags are introduced.
