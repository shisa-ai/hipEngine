# Repair stale CPU Qwen shared-batch MTP fixtures

## Summary

The completed no-ROCm Python 3.12 run (235 failures/errors in
`/tmp/hipengine-v080-ci-suite.xml`) carried 225 failures with one cause:
`AttributeError: 'types.SimpleNamespace' object has no attribute 'plan'` raised
from `Qwen4ExpGGUFBatchRunner.__init__` while `SubmitPollTextGenerator` prepared
the resident serving runner. `4e4ccba1e` made the shared Flash-Next AR decode
batch the default and pinned the request-owned c1 path in every unit module that
builds a stand-in resident, but three integration modules that import the shared
`_driver`/`driver` helpers were missed: an autouse fixture in one test module
does not apply to another module that imports its helper.

The repair pins `HIPENGINE_QWEN4_EXP_AR_BATCH=0` in those three modules, which is
the same fixture and rationale the eleven existing unit modules use, and updates
one stale public-telemetry expectation. No production code, runtime default, or
feature gate changed. The tests keep driving real MTP speculative execution:
each still asserts `verify` calls, non-zero `mtp_cycles_count` /
`mtp_generated_draft_tokens`, and request-owned target/draft positions.

## Changes

- `tests/test_integration_qwen4exp_request_lifetime.py`,
  `tests/test_integration_server_controlled_speculation.py`, and
  `tests/test_integration_server_sampled_speculation.py`: add the autouse
  `_request_owned_c1_path` fixture that pins `HIPENGINE_QWEN4_EXP_AR_BATCH=0`.
  These modules drive the c1 request-owned MTP path around stand-in runners; the
  shared batch path needs a resident with real device weights and has its own
  CPU suite in `tests/test_unit_qwen4exp_ar_batch_decode.py`.
- `tests/test_unit_qwen4exp_mtp_submission.py` and
  `tests/test_unit_qwen4exp_mtp_resident_sampling.py`: document on `_driver()`
  and `driver()` that the caller owns that pin, so the next consumer of the
  shared helper does not rediscover this failure. Docstrings only; no behavior
  change.
- `tests/test_integration_server_api.py`: replace the removed
  `qualified_max_slots == 4` / `qualified_max_positions == 2048` capability
  assertions with the envelope the server reports today (`enabled`,
  `rollback_env`, `max_rows`), and pin `AR_BATCH_ENV` so the `enabled` assertion
  does not depend on the ambient environment.
