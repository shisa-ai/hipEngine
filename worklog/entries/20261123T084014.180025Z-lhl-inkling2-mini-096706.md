# Screen padded Inkling relative-bias prefixes

## Summary

Padding a narrowed relative-bias product preserved the reachable bits on the tested OpenBLAS host. Do not make the host-specific column rule a runtime default.

## Changes

- Scratch only. On NumPy 2.4.6 with one OpenBLAS thread, random width screens matched the original 1,024-column product at widths 320 and 640, but not at several other aligned widths. For real rows, round the live count up to the next multiple of 320, capped at the full width.

## Validation

- Repeated the [real-row probe](20261123T083516.589910Z-lhl-inkling2-mini-72b3cd.md) on `epyc`/W7900, mainline `UD-Q4_K_M`, fast FP32 KV, same prompts and sampling, at `8d30c6acf71c44c84ded7e9ffe23283ab73597d9`. Every reachable bias element matched bitwise at 47, 151, 575 and 1,027 input tokens. The median of shape-level median host product times was 11.28 → 3.93 microseconds at 47 input and 11.32 → 6.83 at 575; the full-window arm made no change. Log: `/tmp/kendex-pi-bg/bg-282-1795423073779.log`. This is a leaf timing, not a request speedup.

## Next

- Preserve the existing full host calculation. A future narrower implementation needs a portable arithmetic contract; matching a host BLAS blocking choice on one installation is not that contract.
