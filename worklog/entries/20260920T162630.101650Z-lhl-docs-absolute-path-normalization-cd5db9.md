# Remove hard-coded home directories from docs and gate against them

## Summary

Lead directive: no hard-coded external absolute path should remain in our docs.
The trigger was `docs/source_lineage.json`, where the previous commit's textual
link rewrite had mangled two entries pointing into `~/amd-gpu-tuning/` — a
separate repository. That was reverted there; this unit removes the underlying
class of problem.

Survey before the change: 237 occurrences of `/home/lhl/` across 55 files in
`docs/`, led by `~/llama.cpp` (56), `~/amd-gpu-tuning` (41), `~/miniforge3`
(17), `~/omlx` (12), `~/vllm` (10). A path through one person's home directory
is correct for exactly one reader.

`~/` was already the dominant convention rather than a new invention: `docs/`
carried 75 `~/amd-gpu-tuning` against 41 absolute, and `AGENTS.md` has always
listed the external reference repos as `~/amd-gpu-tuning/`, `~/FastDMS/`,
`~/FastKMS/`. This normalizes to the form already in use.

## Changes

- Replaced `/home/lhl/` with `~/` across `docs/**/*.md`,
  `docs/source_lineage.json`, `AGENTS.md`, `TODO.md`, and `benchmarks/**/*.md`:
  292 paths across 65 files.
- Excluded from the rewrite, because they record what something said rather than
  instructing: `benchmarks/results/` evidence artifacts, `docs/testing/` dated
  migration records, `docs/examples/` published configs, `worklog/entries/`
  (immutable), and byte-frozen `WORKLOG-LEGACY.md`.
- Converted in-repo self-references from a home-directory path to a
  repo-relative one, since `~/hipEngine` assumes a checkout location:
  `~/hipEngine/.venv/bin/python` and `~/hipEngine-main/.venv/bin/python3` to
  `.venv/bin/python[3]` in `campaigns/AGENTIC-QUALITY2.md`,
  `campaigns/QWEN36-35B-ZBOOK-PRODUCTION-NUMERICS.md`,
  `archive/OPTIMIZE-serving.md`; five `cd ~/hipEngine` lines in
  `reference/MTP.md` to `# from the repository root`; the worktree line and one
  comment in `reference/TUNING-gguf.md`; a cross-doc pointer in
  `reference/GGUF.md` to a relative link; `reference/MARLIN.md`'s "Target repo"
  to "this repository"; and the sample `"repo_root"` value in `BENCHMARK.md` to
  an explicit placeholder.
- Left `~/hipEngine-agentic-quality2`, `~/hipEngine-specdec2-perf`,
  `~/hipEngine-ud-quants`, and `~/hipEngine-main` where they record which
  worktree a closed campaign actually ran in. Those are historical facts, not
  instructions.
- Added an absolute-path gate to `scripts/docs/check_docs.py`: it fails on
  `/home/<user>/` and `/Users/<user>/` in `AGENTS.md`, `docs/`, and
  `benchmarks/` prose, naming file, line, and the offending prefix. Documented
  the rule in `scripts/docs/README.md` and as an `AGENTS.md` ground rule.

## Validation

- `python3 scripts/docs/check_all.py`: all 4 gates pass.
- Gate negative-tested: appending `See /home/someone/models for weights.` to
  `docs/MODELS.md` produces
  `error: docs/MODELS.md:76: hard-coded home directory '/home/someone'` and
  exit 1; after restoring the file, exit 0. The gate fires and clears.
- `python3 scripts/check_lineage.py --kind doc`: exit 0, 6 tracked sources
  resolved, repo root printed as the expanded absolute path. The manifest's new
  `~/` entries resolve because `check_lineage.py:470` already calls
  `Path(value).expanduser()`, so no consumer change was needed.
- `uv run pytest -q` (default unit tier): the only failures remain the two
  pre-existing `test_unit_qwen35_gguf_capacity.py` int8-KV default tests, which
  fail identically at HEAD and come from `5a71809cc`.
- Change scope audited before commit: no file under `benchmarks/results/`,
  `worklog/entries/`, `docs/testing/`, or `WORKLOG-LEGACY.md` was modified.
