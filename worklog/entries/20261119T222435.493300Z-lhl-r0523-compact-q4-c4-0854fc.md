# Isolate four-row compact Q4 gate/up workgroups

## Summary

The four-row compact Q4 gate/up kernel produced unequal BF16 outputs for byte-identical rows before any downstream operation. Across 42 captured launches the differing element was always in row 1 at column 0 of an eight-column tile. In 41 cases all four immediate replays with unchanged operands produced equal rows. The layer-0 convolution state update, previously suspected, matched its exact shift-and-insert oracle even during failing requests.

## Changes

- Keep a single packed launch at width four but assign each row its own workgroup. This isolates accumulation, reduction and gate/up exchange; changing only the final writer had not eliminated the failure. The underlying hardware or compiler mechanism is not established.
- Add repeated bit comparisons with an independent pack8 kernel for duplicate rows. The high-repeat public-server run, not the synthetic test alone, demonstrates the original intermittent failure.

## Validation

- All eight focused GPU tests passed on the W7900: `test_q4_t16_dense_dual_c4_duplicate_rows_stay_identical` and all widths of `test_q4_t16_dense_rowtiles_match_pack8_production_bits`.
- The matched uninstrumented strict HTTP burst went from 10 mismatches to none across 120 measured four-request outputs. Median aggregate output throughput fell from 58.85 to 45.59 tokens/s (22.53%). Both runs used native packed decode; neither observed live overlap before the first completion. See `benchmarks/results/2026-11-19-w7900-r0523-compact-q4-c4-correctness.json` for the workload, commands, and separate outcomes.

- The distinct-prompt clearing workload passed under the default graph policy: 120/120 measured four-request outputs matched, strict repeat determinism passed, and `gguf_packed_ar_server_decode` ran. Both matched diagnostic packets used duplicate prompts and therefore failed the harness's distinct-oracle cardinality check, not its blocking live-admission check.
