# qwen38 gfx1151 c8 native gate/up rowtile8 + packed-AR native-batch fix

## Summary

First unit of the c=8 GEMV decode campaign. The c8 packed-AR decode path
(`_enqueue_packed_decode_model_step`, used by both eager `step_batch_native`
and graph capture) was falling back to **WMMA prefill kernels** for the dense
Q4 gate/up pair at rows>4 (c8 step 408.9 ms, 19.3 tok/s aggregate, 1.49x c1).
Root cause was twofold:

1. The qmicro Q8_1x2 rowtile8 kernel (`q4_k_qmicro_t16_dense_dual_q8_1x2_
   rowtile8_dp4a_silu_gemv_kernel`) instantiated ROW_TILE 2..4 only; the
   `GGUF_DENSE_PAIR_SILU_NATIVE_DECODE_POLICIES` covered c1 and rows 2-4.
2. `_enqueue_packed_decode_model_step` never entered `native_batch_decode_
   session(True)`, so even rows 2-4 did not take the rowtile8 branch in the
   packed-AR path (only the `_enqueue_native_rows_model` verification path
   did).

## Changes

- `kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.hip`: added
  `Q4_QMICRO_Q8X2_ROWTILE8_CASE(5..8)` and widened the launch guard to rows
  [2,8]. The template already carries independent per-row accumulators, so
  one qmicro weight traversal serves all 2..8 rows without changing any row's
  dp4a/FMA/reduction tree (BF16-bit exact to serial c1 by construction).
- `kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.py`: wrapper row guard
  `[2,4]` -> `[2,8]`.
- `kernels/hip_gfx1151/__init__.py`: `GGUF_DENSE_PAIR_SILU_NATIVE_DECODE_
  POLICIES` for Q4_K_S now covers rows 2..64 (rowtile8, chunked >8); c>=512
  routes to WMMA prefill before this policy is consulted.
- `runtime/gguf_linear.py`: `qmicro_q8x2_rowbatch` branch now chunks any
  c>8 into <=8-row groups (`_rowtile8_row_chunks`, all groups >= 2, tail-1
  folded into the prior group) so "any c=N" shares one weight traversal per
  group; exact because groups are row-independent (per-row Q8_1x2
  quantization + per-row SiLU).
- `runtime/qwen35_gguf_runner.py`: `_enqueue_packed_decode_model_step` now
  enters `native_batch_decode_session(True)` so both eager `step_batch_native`
  and graph capture take the rowtile8 branch for rows 2..8.
- `tests/test_gguf_t16_selected_gemv_decode.py`: RED parametrization
  extended to rows [2,3,4,5,6,7,8].

## Validation

- RED: `test_qmicro_q4_dense_dual_q8_1x2_shared_rowbatch_matches_serial_c1_bits`
  passes for rows 2..8 (BF16-bit exact to serial c1).
- Packed-AR bench (`gguf_packed_ar_bench.py`, Q4_K_S / gfx1151 / p512 / tok
  9707 / 64 steps): c1 = 12.85, c4 = **42.5 agg (10.6/stream, 3.31x c1, no
  regression)**, native_c8 = **25.2 agg (3.15/stream, 1.96x c1)**; c1-c2-c4
  prefix exact, native_c8 rows match c4, repeatable.
- `rocprofv3` c1/c8 profile: c8 step 408.9 -> **312.4 ms**; the dense Q4
  gate/up pair now runs the rowtile8 kernel (64x, ~61 ms in dense_projection)
  instead of 340 WMMA prefill dispatches. Remaining c8 cost is single Q4/Q5
  projections (attn_qkv, attn_q/k/v/o, attn_gate, ffn_down, ssm_out) still
  dispatching WMMA prefill at rows 5-8 (their rowtile kernels cap at rows 4)
  = 212x Q4 (183.7 ms) + 60x Q5 (42.8 ms). That is unit 2 of the campaign.
- c4 does not regress: single Q4/Q5 projections at rows 2-4 already use the
  rowtile path; only rows 5-8 fall to WMMA.
