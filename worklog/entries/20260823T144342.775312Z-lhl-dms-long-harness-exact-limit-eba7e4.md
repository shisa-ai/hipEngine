# Use exact decode capacity in DMS long harness

## Summary

The first two 256K command shapes failed before GPU execution because the long
harness provisioned an unnecessary extra scratch position beyond actual decode
appends. A sampled output does not consume KV capacity until supplied as the
next step input.

## Changes

- Size resident scratch as `prompt_tokens + decode_steps` exactly.
- Preserve compact append reserve independently through `dms_max_new_tokens`.

## Validation

- A two-step decode appends at positions `prompt_tokens` and
  `prompt_tokens + 1`; the session bound is exclusive and therefore needs
  exactly `prompt_tokens + 2` positions.
- Real exact-capacity 768+2 integrated smoke passes: finite decode IDs
  198/285, 1.54159x compression, and zero tracked bytes after close.
- Ruff, py_compile, worklog, and diff checks pass.
- `bg-15` requested 262,147 positions and `bg-16` requested 262,145; both failed
  in `_FullStackScratch.allocate` before model execution.

## Next

  262,144-position limit.
