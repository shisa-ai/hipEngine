# Long-context verifier route probe committed, pair harness records routing, drift gate fixed

## Summary

Three instruments the long-context staged-linear admission needs to be
reviewable, plus the published-command drift failure they exposed. The route
probe that proved which long-context verifier owner ran lived only under
`/tmp`, and the retained packet
`benchmarks/results/2026-09-18-gfx1151-qwen38-long-context-eager-verifier-staged-chain.json`
recorded that path as its `command`, so
`tests/test_unit_scripts_check_published_command_drift.py` failed the repo gate
with `SCRIPT-NOT-IN-REPO` (it was one of the 12 pre-existing unit-tier failures
seen earlier this session). The probe is now committed as
`scripts/gguf_mtp_route_owner_probe.py` and the artifact cites it; no exception
entry was added, because the row is genuinely re-runnable this way and a dated
exception would have left a published packet whose command nobody can execute.

`scripts/gguf_mtp_server_pair_bench.py` now records what each arm observed about
itself — the `hipengine` routing block (effective route, decision reason, MTP
output coverage, speculative cycles, fallback event counts) and, with
`--identity-tokens N`, one non-streaming greedy probe per row whose exact
generated ids make the two arms comparable token for token. A serving ratio is
only a speculative ratio if the row says it engaged speculation, and the two
arms of a route change have to be shown to differ in route rather than in
configuration. `include_hipengine` rides on `stream_options` by default with
`BENCH_INCLUDE_HIPENGINE=0` as the documented opt-out for another engine's
server.

`scripts/gguf_mtp_pair_rollup.py` joins the arm artifacts of one or more server
processes into the compact row set a rollup cites, including per-row text and
exact-id identity and a candidate-versus-control comparison of route engagement
and of each arm's own AR control rate.

## Changes

- `scripts/gguf_mtp_route_owner_probe.py` (new): wraps
  `scripts/gguf_mtp_long_context_gate.py`, passes every gate flag through
  unchanged, and counts staged-chain calls, scalar row-wise owner calls with the
  call stacks that reached them, FFN rows per layer, and every staged split-K
  plan resolution. `HIPENGINE_LC_PROBE_FORCE_SCALAR=1` forces the scalar owner
  while keeping the per-row views, and the report records whether that
  diagnostic arm was active. Paths are repo-relative; the `/tmp` sentinel that
  selected the diagnostic arm is gone.
- `tests/test_unit_scripts_gguf_mtp_route_owner_probe.py` (new): pins the
  repo-relative source, the environment gating of the forced-scalar arm, the
  self-describing report fields, flag passthrough via `--help`, and that the
  retained packet's recorded commands name a committed script.
- `benchmarks/results/2026-09-18-gfx1151-qwen38-long-context-eager-verifier-staged-chain.json`:
  `command`, `command_template`, `source`, `protocol.harness` and the baseline
  description now name the committed probe; the measured rows are untouched.
- `scripts/gguf_mtp_server_pair_bench.py`: routing capture (`route_summary`,
  `include_hipengine`), the non-streaming identity probe, and the docstring for
  both.
- `scripts/gguf_mtp_pair_rollup.py` (new): paired-arm rollup with cross-arm
  identity and route-engagement comparison.
- `benchmarks/HARNESSES.md`: catalog rows for the probe, the pair bench and the
  rollup.
