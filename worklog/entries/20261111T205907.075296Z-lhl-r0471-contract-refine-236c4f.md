# R0471 step_batch_native vs step_rows_native contract refinement

## Summary

Refines the R0471 ownership design (`worklog/entries/20261111T204805.104767Z-lhl-r0471-ownership-design-550251.md`)
with the exact per-step call contracts, read from source. No code, selector, or
arithmetic change. This pins the precise reconciliation the integration must perform.

## Changes

- No code change. Design checkpoint only: records the two step-method contracts and
  the narrow opt-in engagement conditions for a native-row route.

## Validation

Source inspection (no GPU run):

- Resident scheduler packed step `_step_native_chunk`
  (`hipengine/generation/qwen35_gguf.py:12146`) calls
  `execution_owner.step_batch_native(tokens, sessions=[slot.session ...],
  positions=[slot.seq_position ...], return_logits=..., scatter_state=False,
  physical_rows=width, active_slot_indices=active_indices)`. Sessions and positions
  are passed explicitly per call; the owner's own cursors are not the source of truth.
  It handles graph replay, dirty-state flush on session-tuple change, native sampler
  rows, and `MemoryAdmissionRefused` -> serial fallback.
- Native-row owner step `step_rows_native`
  (`hipengine/runtime/qwen35_gguf_runner.py:21819`) instead reads
  `self.row_positions`, requires `positions` to equal those cursors, requires
  `rows <= self.max_batch_size`, and raises NotImplementedError unless
  `slot_indices == range(rows)` (compact physical slots). It drives
  `self._target_scratch_owner.set_full_attention_positions(...)` and
  `self._native_compact_scratch(rows, ...)`, then increments the owner cursors.
- Contract mismatch: the scheduler passes per-slot sessions/positions (possibly
  non-compact lanes), while `step_rows_native` demands owner cursors pre-synced and
  compact lanes. Slot views share `_target_scratch_owner` with the batch owner, so
  recurrent/KV scratch is already owner-wide; the cursors and lane compaction are the
  reconciliation gap.

## Next

- Implement an opt-in native-row route in `_step_native_chunk` that engages only when
  (a) the optional DP4A/native-row selector is engaged, (b) `active_indices ==
  range(width)` (compact lanes), and (c) all rows are greedy (no native sampler).
  Before calling `step_rows_native`, sync the batch owner's `row_positions` from the
  slot views' `seq_position`; after, scatter the incremented cursors back. Preserve
  packed/serial as the default and the `MemoryAdmissionRefused` fallback.
- Add host ownership/transition tests first (cursor sync, compact-lane gate, non-compact
  refusal, fallback preservation), then public engaged/unengaged generation reporting
  the actual native-row launch and bound kernel/converter/workspace from the resident
  certificate. Do not close R0471 from certificate membership alone.
