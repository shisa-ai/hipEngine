# Independent-request GDN token mixer over request-owned state slabs

## Summary

Adds the N-request form of the Qwen4Exp GDN decode step. The c1 oracle
`run_qwen4_exp_gdn_token_mixer` (`runtime/qwen4_exp_runner.py:7080`) takes one
Conv row pointer and one recurrent row pointer, and the runner reaches them
through a per-layer offset — its only "state index" is the layer ordinal. This
unit replaces that axis with physical request slots:

- `Qwen4ExpBatchGdnState` (new, one GDN layer) owns
  `[state_slots][num_v_heads][128][128]` recurrent and
  `[state_slots][qkv_width][conv_kernel]` Conv F32 slabs plus the
  `int64[rows]` row-to-slot index vector, and admits a row set with `prepare`.
- `run_qwen4_exp_batch_gdn_token_mixer` runs one decode step for the admitted
  rows with one dispatch per stage: four projections, the indexed Conv decode,
  the indexed recurrence/norm/gate, and the output projection. No per-request
  step loop and no row-count special case.

Both device owners are the already-committed request-indexed F32 primitives
(`qwen4_exp_linear_attn_conv_decode_indexed_f32`,
`qwen4_exp_gdn_decode_rowsplit_indexed_f32`), so this unit adds no kernel. The
c1 path is untouched and remains the fallback.

Not in scope, and not done: runner wiring, prefill chunks, PLE, the sparse QSA
index path, server/generation/defaults, commits. No production-quality or speed
claim.

## Changes

- `hipengine/runtime/qwen4_exp_batch_gdn.py` (new, 719 lines):
  - `Qwen4ExpBatchGdnState.allocate(state_slots, num_k_heads, num_v_heads,
    head_dim, conv_kernel, runtime=None)`: both slabs zeroed (a fresh request's
    state is zero, so "never written" and "fresh" are the same checkable value),
    an `int64[state_slots]` index buffer, and the geometry bounds the two
    primitives and the host cannot address (`state_slots` <= the indexed slab
    width, `qkv_width` <= the indexed conv channel bound, `conv_kernel` <= its
    kernel bound, `num_v_heads % num_k_heads`, int64 byte products) checked
    before a runtime is resolved or a byte allocated.
  - `prepare(slot_ids)`: the primitives' own admission helper
    (`qwen4_exp_gdn_indexed_state_indices`) is the slot rule — distinct, in
    range, one per row — so this module does not restate it. Validation runs
    before the upload; a rejected call leaves the published rows and the device
    vector unchanged, and a copy failure clears the active set instead of
    publishing half a mapping. The upload copies exactly `rows` int64 values
    (the buffer is slot-width; a whole-buffer copy would read past a shorter
    host vector).
  - Lifecycle: `closing` is set before the first free, `_require_open` rejects
    uploads from then on, and `close` frees newest-first, popping only after a
    free returns, so a partial failure is retried without a double free. Same
    shape as the batch attention owner (`runtime/qwen4_exp_batch_state.py`).
  - `recurrent_slot_ptr(slot)` / `conv_slot_ptr(slot)`: validated slot
    addresses, so a caller can seed or move one request's state with the
    existing copy helpers instead of recomputing strides.
  - `run_qwen4_exp_batch_gdn_token_mixer(mixed_ptr, weights, *, state, scratch,
    rows, hidden, num_k_heads, num_v_heads, head_dim, conv_kernel,
    conv_weight_ptr, dt_bias_ptr, a_ptr, norm_weight_ptr, stream=0,
    runtime=None)`: reuses `Qwen4ExpGDNScratch` and the c1 operand pointers, so
    the c1 comparison differs only in the two state owners.
  - `_validate` admits a call before the first dispatch: closed/closing
    scratch/state, runtime identity across the three owners, positive geometry,
    `num_v_heads % num_k_heads`, `head_dim == 128` (the indexed recurrence
    owner's compiled geometry), geometry equal to the state owner, the indexed
    row/slab/channel/kernel bounds, `qkv_width % 4` (float4 Q/K loads),
    required projections and non-zero operand pointers, `rows == prepared rows`,
    a re-admission of the *published* index vector, int64/float4 alignment of
    the index vector and scratch Conv buffer, per-buffer scratch capacity, and
    the five projection source shapes. The output projection runs last, after
    both indexed kernels have committed state, so its geometry is preflighted
    rather than discovered after the write.
- `tests/test_unit_qwen4exp_batch_gdn.py` (new, 13 tests): every device call is a
  module-level name replaced by recorders. Asserts the exact 7-dispatch stage
  sequence and its row count for N=1, 2, 4 (so a per-request loop cannot pass),
  the pointers/metadata that reach each kernel (`indices.ptr` into both indexed
  kernels, `state_slots`, `channels`, `num_k_heads`/`num_v_heads`/head dims),
  owner allocation (two memsets, disjoint slot addresses striding by one slot's
  bytes, slot-width index buffer), `prepare` (row order preserved, permuted and
  shrinking sets, leading-rows-only upload with the exact byte count),
  no reallocation across changing active sets, 16 no-dispatch rejection cases,
  duplicate/out-of-range/typed slot rejection with the host mirror unchanged,
  re-admission of a tampered index vector, unprepared/closed/closing rejection,
  the partial-close retry (uploads refused once cleanup begins, remainder freed
  exactly once), and owner geometry bounds.
- `tests/test_gpu_qwen4exp_batch_gdn.py` (new, 4 tests / 8 items): compact dense
  F32 GGUF fixtures reused from
  `tests/test_gpu_qwen4_exp_runner_gr._dense_f32_weight`, hidden 8, 2 k heads,
  4 v heads, head_dim 128, conv kernel 4, 4 slots, each slot seeded with a
  distinct-scale Conv and recurrent state so a row reading the wrong slot cannot
  agree by accident. N1/N2/N4 including permuted slot orders and 2-3 repeated
  steps; every step is compared against (a) an independent c1
  `run_qwen4_exp_gdn_token_mixer` run per row from that row's slot state and
  (b) a CPU oracle that runs the whole step over the whole slab
  (`gdn_prefill_recurrent_segments` with one segment per row plus
  `sigmoid_gated_rmsnorm`), so slot addressing is checked arithmetically and not
  only by canaries. Slots outside the active set are asserted byte-identical;
  a repeated step from the same seeded state is asserted byte-identical; a
  rejected call (row count, head_dim, kernel, duplicate slot) leaves both slabs
  byte-identical.

The asserted bounds are `rtol=atol=4e-6` for both comparisons, i.e. the measured
envelope (<= 1.1e-6 absolute, <= 6.1e-7 relative) with margin, and the signal
magnitude is O(1)-O(5), so the tolerance is not vacuous. Bit equality is
deliberately not asserted: the batch path uses the row-split recurrence owner
(FP32 summation order, one state pass instead of two dot products) and a
row-count-dependent projection GEMM, both of which differ from the c1 owner by
round-off only.

Exact control asserted on every case:

- `state.active.slot_ids` and `indices_host` equal the caller's row order, so the
  mapping is the caller's, not slot order.
- Slots outside the active set are byte-identical in both slabs across every
  step, including across a changing active-set schedule
  (`[0,1] -> [2,3] -> [1] -> [3,2,0]`), which is what would break first under
  cross-request aliasing.
- Each active slot's Conv and recurrent bytes equal the independent c1 run for
  that row, so a row's state advanced exactly once, in its own slot.
- A repeated step from the same seeded state reproduces the output and both
  slabs byte-for-byte.
- Rejected calls (row count, `head_dim`, kernel, duplicate slot) leave both
  slabs byte-identical: nothing reaches a kernel.

## Next

- Runner integration (not done here): `runtime/qwen4_exp_runner.py` still
  computes `gdn_state_index` as a layer ordinal and passes
  `conv_state_ptr`/`recurrent_state_ptr` into the c1 mixer
  (`:8817-8832` region). Wiring this unit needs the runner to own one
  `Qwen4ExpBatchGdnState` per GDN layer, a request-to-slot assignment shared
  with the attention owner's slot ids, a per-step `prepare(slot_ids)` on each
  layer, and an explicit state move (`SlotMove(request, old, new)`) on slot
  compaction — a shared slab does not move state by itself.
- Prefill chunks are not covered. The indexed recurrence is a one-token-per-row
  decode owner; a multi-token chunk needs the prefill owners plus per-token
  state rows, and a chunk's rows are sequence positions, not independent
  requests, so they must not be admitted as active rows of this state.
- PLE (`qwen4exp.ple.layers`) and the sparse QSA index path are separate owners
  and untouched. `head_dim == 128` is the indexed recurrence owner's compiled
  geometry; a model with another head dim keeps the c1 path.
- Capacity contract: today c2 costs 2x the full per-request state. This owner
  makes the slab explicit and request-indexed, but the capacity statement is
  still `state_slots * (recurrent + Conv) bytes per layer`; nothing here shares
  or compacts slots.
- No production-profile gate was run. Evidence is a CPU oracle plus per-row c1
  comparison on fixture weights at one layer; the calibrated mean/p95/p99/max
  KL, top-1-by-category, determinism/isolation, BF16-relative, and task gates in
  `docs/EXECUTION-PROFILES.md` are unrun on a real checkpoint. No speed claim.
