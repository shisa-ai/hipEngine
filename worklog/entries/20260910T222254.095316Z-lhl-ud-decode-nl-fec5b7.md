# Decode lever 2: IQ4_NL local32 decode owner - K_M 26.46 -> 27.67, K_S 25.53 -> 26.77 tok/s

## Summary

The IQ4_NL dense tensors (7 in K_M: blk.1-3 ffn_down + attention roles)
ran the strict GEMV at 199-392 us/launch for shapes the local32 owner
serves at 67-84 us. The sibling kernel transfers the XS owner's geometry
directly - IQ4_NL shares the element-to-byte/nibble mapping (byte
2+(k&15), nibble (k>>4)&1), so each lane's 8 contiguous k span one nibble
half and one 8-byte payload window; the 18-byte block carries only the
plain f16 d (no hi/scale header). Decode: K_M 26.46 -> 27.67 tok/s, K_S
25.53 -> 26.77 (plain: 34.12 / 30.55).

Two integration defects were caught and fixed before any evidence was
accepted: (a) the 18-byte block stride leaves the payload only 2-aligned,
so the window is read as four u16s instead of two u32s (misaligned u32
loads produced NaN); (b) the raw-ABI launcher does not pass the quant -
the strict kernels bind it via functools.partial at registration, and
the local32 registration did not, so the NL tensors ran the XS kernel on
NL-format weights (clean-input/garbage-output isolated the offending
calls). The registration now binds per-quant partials.
