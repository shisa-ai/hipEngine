# Retire expert-grid environment fallback

## Summary

Publish the existing both-family expert-grid default through every execution
profile and remove the runtime process fallback after diagnostic callers have
migrated to owner policy. Arithmetic, registered variants and default family
selection are unchanged.

## Changes

- Strict, production and batch-invariant bind `ExpertGridPolicy(True, True)`
  on generator/current runners; existing constructor, late-clone and batch
  transport carries it. Unbound calls use the same both-family constant.
- Remove the sole runtime read of `HIPENGINE_QWEN4_EXP_EXACT_EXPERT_GRID`.
  Only candidate-AR/profile-gap explicit syntax parsing remains under
  `hipengine/` and `scripts/`; these bind owner policy without process writes.
- Change pair/bundle selector tests to pass explicit disabled family policy.
  Add stale/invalid-process isolation checks and all-profile publication checks
  with no process writes, current-runner publication and late inheritance.
- Public tests preserve and restore the published default rather than assuming
  an unbound owner; a profile-default case loads with invalid ambient syntax
  and verifies actual expert-grid launches with no diagnostic grid binding.
