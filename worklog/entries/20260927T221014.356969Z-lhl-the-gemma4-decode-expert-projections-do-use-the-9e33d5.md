# The gemma4 decode expert projections do use the scalar Q5_1 GEMV
## Summary
The previous entry found that the Q5_1 decode GEMV walks the contraction one
element per thread per iteration while the Q4_K and pack8 GEMVs walk eight, and
explicitly recorded that **which variant actually runs in decode was not
established**. It is established now, and the answer is the scalar one.
## The evidence
**1. gemma4 does not use the profile file.** `qwen4_exp_profiles.py` holds the
`_selection` entries that pick between the four Q5_1 GEMV variants by row count,
but grepping `hipengine/runtime/gemma4.py`, `hipengine/generation/gemma4_gguf.py`
and `hipengine/runtime/gguf_linear.py` for `qwen4_exp_profiles` returns nothing.
So none of those profile selections applies to this model, and the variant is
whatever registration provides.
**2. Registration provides the scalar variant for the expert layer.**
`hipengine/kernels/hip_gfx1100/quant/qwen4_exp_q5_1.py:1097-1109`:
```python
for layer in ("linear", "moe_linear"):
    register(
        KernelKey("hip_gfx1100", layer, "gguf_q5_1", "selected_gemv_bf16_bf16_out"),
        qwen4_exp_q5_1_selected_gemv_bf16_bf16_out,
        replace=replace,
    )
```
`selected_gemv_bf16_bf16_out` is the **scalar** kernel at
`qwen4_exp_q5_1.hip:1169`. The vectorised siblings (`wave64`,
`logical256_t64`, `logical256_t128`) are registered beside it but are chosen by
the profile file that gemma4 does not use.
**3. The model's own module documents this route.** `hipengine/runtime/gemma4.py`
carries a stage table whose expert-projections row reads:
```
expert projections   ``linear/<quant>/selected_gemv_bf16_bf16_out``
```
That is the same variant name, documented as the route the model takes.
## What this establishes, and what it does not
**Establishes:** the Q5_1 decode expert projections route through the scalar
`selected_gemv_bf16_bf16_out` kernel. The earlier "this could be dead code"
caveat is resolved — it is not dead code, it is the route.
**Does not establish:** that vectorising it will recover the bandwidth gap. The
access shape is now a confirmed property of the running path rather than a
hypothesis about a file, but the causal link to the measured 31 percent of peak
is still unmeasured, and Q5_1 is 29 of the 60 expert tensors, so even a full
recovery there is bounded.
