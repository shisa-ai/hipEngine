# Add Qwen4Exp H256 wave8 sparse attention

## Summary

Added a registered, default-off T1 H256 sparse-QSA candidate. Eight wave32s per
query head process interleaved selected-token subsequences and merge their
online-softmax partials in fixed wave order. The registered 256-thread strict
kernel remains fallback.

## Changes

- Added raw-pointer HIP/Python wrappers and registry key
  `qsa_sparse_attention/bf16_kv/production_wave8_h256_spans`.
- Added gfx1151 alias/fallback resolution coverage and an actual
  12Q/2KV/H256/2,048-selected production-envelope test.
- Added `HIPENGINE_QWEN4_EXP_QSA_WAVE32_H256=1` as a temporary default-off
  candidate selector and its removal trigger in `docs/REFACTOR.md`.

## Validation

RED first: the actual-shape and registry tests failed before the candidate
existed.

The first implementation reconstructed the strict H256 dimension tree inside
one wave. It differed only at low FP32 bits (max absolute 1.40e-9) but was
**9.923 ms versus 2.145 ms strict (0.216x)** because 12 total waves cannot hide
the serial 2,048-token dependency. It was removed rather than retained.

The replacement uses eight waves/head and one 8.1-KiB shared partial buffer.
Actual-shape strict-parent envelope passes at max absolute **1.63e-8**. It is
T1, not exact, because wave-subsequence softmax partials are merged after the
per-wave loops. Twelve cached wall samples measure strict **2.179 ms** median
versus wave8 **0.481 ms**, a **4.534x** primitive ratio. Focused QSA registry,
actual-shape, and runner tests pass (6/6); gfx1151 candidate and strict fallback
keys both resolve.
