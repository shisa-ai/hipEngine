# 24 GB DMS output clamp, memory-bound draft vocabulary, capacity gate

## Summary

Lead decisions from the 2026-10-21 review, applied: clamp DMS `max_tokens` to
the compact store and say so at startup; drop the MTP draft vocabulary cache
when the context falls short of the maximum; refresh the README 24 GB table;
add a test so 24 GB capacity cannot regress silently again.

Commits: `cb90e7976` (draft vocabulary), `c844af981` (DMS sizing and clamp),
`0710386f0` (pool reserve double charge), `07cdd7b22` (capacity gate).
Follows `20261021T124122.156806Z-lhl-xtx-24gb-context-recovery-036e5a.md`.

## Changes

- DMS exact-budget sidecars price the store for the served context's retained
  rows (`window + 1` newest plus one in `ratio` older, cross-checked against
  `build_dms_exact_budget_eviction`). `register_batch` clamps each DMS row's
  `max_tokens` to `retained(context) - retained(prompt)`, so a clamped request
  finishes with "length"; the engine loop asks runners for a per-prompt limit
  (`scheduler_max_new_tokens_for_prompt`). The banner prints the limits.
- The NextN hot-vocabulary head is freed after sizing when the context cannot
  reach the model maximum or the pinned context; an explicit env value wins.
- The packed verify linear state was charged to the KV pool budget and also
  kept out of it through the execution reserve. Removing the reserve copy fixed
  a two-slot server refusing one full-depth request.
- `tests/test_slow_qwen38_24gb_serving_capacity.py` (slow tier) runs real
  `hipengine serve` on a 24 GB-class card; `docs/reference/PUBLISH.md` runs it
  before a release because `--suite all` on a 48 GB card skips it.

## Validation

- Unit: new DMS clamp (27), draft vocabulary (7) and reserve (2) cases; the
  reserve and draft-size cases were RED on the previous commit. Default unit
  tier with GPUs hidden: the same 145 no-device failures as base, none new.
- The gate's first XTX runs failed twice, both real: MTP startup raised
  `'Tensor' object has no attribute 'nbytes'` (the draft-head size read used an
  attribute only the test double had; the double now has the real shape), and
  the two-slot default refused a 34K prompt with "cannot allocate 133 KV pages
  in one backing chunk within the pool budget" (pool: 137 pages, 129 free,
  budget 159 pages, 318 MB charged to the 303 MiB packed linear state).
- Final XTX results (artifact
  `benchmarks/results/2026-10-22-xtx-24gb-dms-clamp-hot-vocab.json`):

  | Case | Slots | Auto context | Prompt served |
  | --- | ---: | ---: | ---: |
  | BF16+MTP default | 2 | 35,072 | 34,023 + 4 concurrent |
  | BF16+MTP c=1 | 1 | 61,440 | 59,603 |
  | INT8+MTP | 1 | 71,680 | 69,533 + 4 concurrent |
  | BF16 MTP-off c=1 | 1 | 83,456 | passed depth check |
  | INT8 MTP-off c=1 | 1 | 98,304 | 95,363 |
  | DMS INT8+MTP | 1 | 262,144 | 254,283 |

- W7900 DMS clamp: 16,384 context, 13,993-token prompt, `max_tokens` 2,000 →
  1,196 tokens with finish_reason "length". A W7900 BF16+MTP server reaches
  262,144 and keeps the draft vocabulary head.
