# Preserve UTF-8 token bytes through Flash-Next logprobs

## Summary

Preserve original tokenizer bytes for Flash-Next selected/top logprobs and
align HTTP visibility windows on decoded character spans. This repairs the CPU
reproduction of the live Japanese failure recorded in
`20261017T201255.959796Z-lhl-qwen4exp-sampling-http-diagnostic-3b1329.md`.
Live requalification and task 17 remain open.

## Changes

- Add optional immutable, JSON-compatible selected/top byte arrays to
  `TokenLogprob`; old producers may leave them unknown. API mapping/object
  coercion preserves these fields.
- Expose reversible GGUF byte-BPE decoding and capture selected/top bytes in
  Flash-Next direct and request-owned resident AR. No sampling math changes.
- Align offsets, stop trimming, reasoning content selection and stream spans
  with an incremental UTF-8 decoder. Adjacent fragments can share one character.
  Invalid/incomplete sequences retain their bytes and replacement-character
  spans; whole-token scores are never divided into substring probabilities.
- Use the response reasoning splitter for metadata, including prompt-opened
  reasoning, rather than a separate parser that always assumed closed reasoning.
- Chat selected/top entries now expose available bytes. Legacy completion maps
  cannot represent two candidates whose individual text is both `�`, so a
  lossless `hipengine.top_logprob_tokens` candidate list and selected
  `hipengine.token_bytes` accompany the legacy fields. Document this contract in
  `docs/TOKEN-LOGPROBS.md`.
