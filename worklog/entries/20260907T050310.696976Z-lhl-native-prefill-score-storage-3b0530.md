# Bound native prefill score storage without changing arithmetic

## Summary

Fixed the native BF16-oracle prefill launch that blocks dense INT8 serving
near 16K. The server traceback confirms the failing route. Long-context
scores now use the already-owned split partial-output arena in bounded query
batches; the kernel retains its original warp partition, score/softmax/value
accumulation order and final BF16 rounding. No new allocation or environment
flag is introduced. This unit qualifies the kernel repair, not the complete
INT8 capacity task: server remeasurement and model quality gates follow.

## Changes

- `paged_attn_decode.hip`: one global-score template specialization of the
  existing BF16-gated prefill body; short-context shared scores remain.
  The new launch uses `(threads + head_dim) * 4` shared bytes independent
  of context. The original launch requested `(context + threads + dim) * 4`
  and exceeded 64 KiB above context 16,064 at D256/64 threads.
- `paged_attn_decode.py`: use global scores when the shared allocation would
  exceed 64 KiB. Batch size is bounded by the declared split arena capacity;
  reject missing/undersized scratch before launch. Preserve row-local spans,
  padded gate strides, caller stream and workspace lifetime. Preserve rank
  when slicing one-page row tables.
- Register explicit `causal_gqa_gate_bf16_global_scores` for short-context
  parent comparisons; the existing native variant remains the automatic
  short/global storage selector. Arithmetic is unchanged, not a new
  production numerical approximation.
- Add CPU launch/ownership tests and GPU analytic, CPU-reference, exact
  parent-parity, repeated-output and workspace-batch-invariance tests.
- Update `docs/KERNELS.md` with storage/ABI behavior. This is in-tree work,
  not an external port; the narrow lineage query selected no parent source.
