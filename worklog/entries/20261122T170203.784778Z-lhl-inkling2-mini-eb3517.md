# Keep local Inkling key and value convolution on device

## Summary

Static local K/V convolution now runs in place on grouped GGUF projection outputs before the existing download. This avoids downloading unconvolved K/V and uploading it again along with the static taps.

## Changes

- Reuse the same short-convolution launches and visit-owned histories. Leave dynamic taps, provisional rollback, ungrouped projections, and the original checkpoint path unchanged. No kernel code or arithmetic changed.

## Validation

- Added a grouped projection callback test, which failed before implementation and passed together with the GPU short-convolution and packed-projection tests. The CPU unit suite, strict CPU fixtures, registry and smoke-plan checks also passed.
- On W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL, compared the new route with the previous route inside the public `LLM.generate_detailed()` path using `fast`, FP32 KV, greedy decoding, no prompt reuse and no drafting. All eight decode-logit hashes and nine generated IDs matched at 47, 575 and 1,027 input tokens. The new route removed 180, 340 and 500 static exchanges respectively on each GPU, halving the static K/V convolution exchange count. Dynamic exchange counts were unchanged. This counts the intermediate transfer removed, not a measured wall-time improvement. Logs: `/tmp/kendex-pi-bg/bg-129-1795366983765.log` and `/tmp/kendex-pi-bg/bg-130-1795366983787.log`.
