# step 2 has a precise interface the speculative provider registry key

## Summary

`20260928T073437` planned the Gemma 4 MTP work in four steps and called step 2 -- the
provider -- "the real work". Reading the registry turns that into a named interface and a
confirmed absence.

## The mechanism

`hipengine/speculative/registry.py` is a plugin registry keyed by a four-axis key:

```python
@dataclass(frozen=True, slots=True)
class SpeculativeProviderKey:
    provider: str
    target_model: str
    backend: str
    quant: str
```

with `register_speculative_provider(key, ...)` at line 168 and a
`SpeculativeTextProvider` protocol at line 146 whose contract is
`generate_detailed(request) -> list[Any]`. That protocol is exactly what the generator
delegates to, so **step 2 is "register a provider", not "invent an interface"**.

The working example is `hipengine/generation/qwen4_exp_mtp.py:362`:

```python
register_speculative_provider(
    SpeculativeProviderKey(
        provider=_PROVIDER,
        target_model="qwen4_exp_gguf",
        backend="hip_gfx1151",
        quant=quant,
    ),
    ...
)
```

## The confirmed absence

`ls hipengine/generation/` gives `gemma4_gguf.py` and no `gemma4_mtp.py`. **No Gemma 4
speculative provider is registered**, which is the concrete form of the
`supports_speculative_mtp = False` that `20260928T073254` observed.

So step 2 is: **a new `hipengine/generation/gemma4_mtp.py` that registers a provider under
`SpeculativeProviderKey(provider=..., target_model="gemma4_gguf", backend="hip_gfx1151",
quant=quant)`**, implementing `generate_detailed(request)` over the existing
`Gemma4MtpDrafter` and `Gemma4Runner`.

## A note on the key

`target_model` in the key names the **generator implementation** (`"qwen4_exp_gguf"`), not
a weight file or a checksum. It selects which provider code runs for a given generator,
which is the plugin-registration pattern the four-axis registry is for -- not an
admission gate on artifact identity. Recording the distinction because the field name
reads like the latter and it is not.
