# Expand Q3 embedding row ownership and vocabulary bounds

## Summary

Expand the U5 Q3 embedding leaf contract checks without changing kernels,
math, resident policy or dispatch. Existing coverage only exercised three
valid IDs against the real-row fixture.

## Changes

- Select the K_S token embedding fixture explicitly; the previous test chose
  the first Q3 entry, which was an FFN matrix of the same K. The fixture stores
  the first and last actual embedding rows as a two-row miniature vocabulary.
- Parameterize actual-K real-row embedding over rows 1/2/3/4/5/7/8/9/12/16/28/32,
  valid boundary/repeated IDs and negative/out-of-vocabulary/int64-extreme IDs.
- Require invalid-ID output rows to remain untouched, matching the kernel's
  existing early return. This is leaf memory-safety behavior, not a public
  promise to accept invalid tokens. Check both output canaries and unchanged
  input IDs/weight bytes. Repeat each launch three times.
- Add zero weight/output pointer and row overflow host rejection checks.
- RED-first rationale: coverage extension of existing behavior, not a math or
  implementation change. Tests assert the independently decoded fixture and
  explicit ownership contract; they do not derive expectations from the kernel.
