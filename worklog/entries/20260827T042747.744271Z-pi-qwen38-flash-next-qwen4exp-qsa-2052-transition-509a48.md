# Qualify first real Qwen4Exp sparse QSA row

## Summary

Qualified the first real native sparse-QSA row at token 2,052 on the pinned
Q4-XL artifact. Strict serial and size-2 chunked execution both pass the frozen
llama.cpp BF16-KV oracle and clean teardown.

## Changes

- Extended `qwen4_exp_compare_logits.py` with an explicit llama `-b` control so
  prompts above llama.cpp's default batch limit fail neither silently nor at
  `llama_decode`.
- In `both` mode, report the previously missing binding teacher→strict-serial
  metric in addition to teacher→chunk and serial→chunk.
- Added a regression asserting the frozen oracle command receives `-b 2052`.
- Retained compact transition evidence at
  `benchmarks/results/2026-08-27-gfx1151-qwen38-flash-next-qsa-2052-transition.json`.

## Validation

- First attempt failed before hipEngine because frozen llama.cpp asserted
  `n_tokens_all <= cparams.n_batch`; this was an oracle invocation failure and
  produced no model result. The corrected `--llama-batch 2052` run passed.
- Exact workload: `' a'` repeated 2,052 times, token ID 264 repeated 2,052,
  context/batch 2,052, size-2 hipEngine chunks, physical host `zbook`, Ryzen AI
  Max+ Pro 395 / Radeon 8060S gfx1151, pinned Unsloth UD-Q4_K_XL four-part
  artifact. Exact shell command is retained in the compact artifact.
- Teacher/serial/chunk top-1 are all 264. Teacher→serial KL is 0.00007649,
  teacher→chunk KL 0.00004976, and serial→chunk KL 0.00003954.
- Serial prefill measured 381.725 s and chunked prefill 245.855 s (1.553×,
  35.59% lower wall). This repeated-token transition row is diagnostic, not a
  public long-context performance claim.
- Tracked peak was 82,720,880,528 bytes; close returned active allocations and
  current bytes to zero.
- `uv run pytest -q tests/test_qwen4_exp_compare_logits.py` -> 4 passed.
