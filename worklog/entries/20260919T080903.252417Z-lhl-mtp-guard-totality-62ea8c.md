# The MTP guard is total over the request vocabulary, and finish-rule settings stay blockers

## Summary

`docs/AGENTIC.md` §P1.5 requires every field that changes token selection or
post-accept finish behavior to keep an advertised MTP blocker *and* a test. The
guard satisfied that for the fields it named, but nothing tied the advertised
list to the request vocabulary, and the sampled route's servable set had grown
to include four fields the route cannot serve.

Both are fixed here, with no change to shipped serving behavior (the sampled
route is closed by evidence and stays closed):

1. **The sampled servable set is now exactly the sampling law.**
   `SAMPLED_MTP_SERVABLE_BLOCKERS` drops `min_tokens`, `eos_token_id`,
   `stop_token_ids`, and `stop_token_sequences`, and they join
   `SAMPLED_MTP_UNSERVABLE_BLOCKERS`. The route reproduces the sampler's
   *selection*: `hipengine/speculative/sampling.py` requires the caller to apply
   the request pipeline (bias, penalties, suppression, temperature, top-k,
   top-p, min-p), and the induced-law gate measures exactly that set. It does
   not reproduce the sampler's *finish* rule: the cycle commit
   (`_commit_eager_cycle_row`) ends a row only when its last visible token is
   the row's EOS, and the greedy route makes that the only reachable EOS
   position with `greedy_chain_eos_limit` — a bound a stochastic accept does not
   have. So a stop token, a stop sequence, or EOS can land mid-cycle and the
   commit path would publish the tokens after it. `min_tokens` travels with
   them because the floor is an EOS-suppression processor, observable only
   through the EOS finish rule it depends on.
2. **The guard is total over the request vocabulary.** A new test classifies
   every `PerRowSamplingParams` field as either an advertised blocker (with the
   two request-side aliases `suppress_tokens`/`stop_tokens` mapped to their
   blocker names) or an explicitly named selection-preserving field with the
   reason it cannot change the greedy decision: `top_k`/`top_p`/`min_p`
   (truncation filters are inert on a raw argmax), `seed` (selects the stream,
   not the decision), the three `*_reason` labels (they label a queue that is
   itself a blocker), and the three thinking-budget fields (active only as a
   pair; a partial configuration builds no budget state). A newly added sampler
   field now fails the test instead of being admitted by omission.

## Changes

- `hipengine/generation/sampling.py`: the two blocker sets and their
  docstrings, split into "sampling law" and "finish rule / metadata" families.
- `tests/test_unit_speculative_sampling_modes.py`: the four fields move from
  `_SERVABLE` to `_UNSERVABLE` (RED first: `supports_sampled_speculative_mtp`
  returned True for all four at the parent); the servable set is pinned to the
  law plus `ignore_eos`; the finish-rule fields are pinned to
  `processed_argmax`; the vocabulary-totality test; the engine-loop greedy
  assertions for the selection-preserving settings; and the two row-level tests
  that encoded the old claim now use a law-only field with the EOS negative case
  spelled out.
- `tests/test_integration_server_api.py`: an endpoint matrix asserting each
  stop-semantics field keeps an explicit MTP request on the autoregressive route
  with its blocker named — including `stop` strings the tokenizer lowers to
  `stop_token_ids`/`stop_token_sequences`, and a non-tokenizable `stop` string
  that stays a text-level post-trim and therefore keeps MTP.
- `tests/test_unit_qwen35_gguf_mtp2_seam.py`: a mechanism test pinning the
  commit path's finish rule (only a trailing EOS finishes a row; a mid-cycle
  stop token, a mid-cycle stop sequence, and an EOS below the min-token floor
  all commit the token past the boundary), so the blocker's rationale fails
  loudly if the finish rule is implemented later.
- `docs/AGENTIC.md` §P1.5 and `docs/REFACTOR.md`: the completeness requirement
  and the sampled route's removal gate now state the law/finish-rule split.

## Next

- Two follow-ups recorded, neither in this unit. The greedy route's EOS
  relaxation is runner-owned (`speculative_eos_supported`, true for an enabled
  adapter on a physical c1 row) and the engine loop honors it, but the server's
  route decision does not consult it, so an explicit-EOS c=1 request is still
  sent to K0/AR. Reconciling them would admit MTP for clients that pass
  `eos_token_id` explicitly; it needs live token/finish-reason parity evidence
  on the greedy path first, and the reverse direction (the engine branch
  becoming unreachable) is the cheaper fallback if that evidence fails.
- The sampled route's finish rule is the device-side accept follow-up already
  tracked in `docs/REFACTOR.md`: a stop-at-emission rule and a min-token floor
  are what would move these four fields back to servable, and that needs a
  finish-rule gate rather than the induced-law gate.
