# Restore Qwen GGUF detokenization ownership

## Summary

The first AQ2 Qwen3.6 live baseline attempt stopped before generation because
`/v1/hipengine/capabilities` truthfully observed the public `LLM.detokenize`
method but the model-owning `EngineService` delegated that control operation to
`Qwen35GGUFBringupGenerator`, which did not implement it. The server returned
HTTP 500 with `AttributeError`; canonical workload rendering could therefore not
round-trip token IDs. The equivalent Laguna generator already owned this method.

RED reproduced the missing model-owned surface directly. GREEN adds the same
bounded tokenizer delegation to Qwen, including `skip_special`, without changing
model arithmetic, prompts, sampling, or GPU paths. This is a runtime capability
correctness repair, not quality or performance evidence.

## Changes

- Added `Qwen35GGUFBringupGenerator.detokenize`, delegating normalized integer
  IDs and `skip_special` to its GGUF tokenizer.
- Extended the lightweight Qwen generator tokenizer fixture and added a direct
  special-token-inclusive/excluding contract test.
- Kept the failed pre-generation attempt under
  `/tmp/hipengine-agentic-quality2/20260825-aq2-v2-qwen36-180246/`; it is not a
  benchmark row.
