# Make the host/device split honest in both harnesses and add a bench-side host profiler (DE-11)

## Summary

Three harness changes, no engine change. They implement the two removal
conditions `docs/REFACTOR.md` records for the invalid host/device loop split and
build the instrument `DE-11` names as its action.

**1. The probe can now measure the split it claims.** `qwen4exp_decode_host_bound_probe.py`
gains `--skip-token-readback`. Without it the per-step blocking device-to-host
copy of the argmax result already synchronizes, so the "host enqueue" window is
per-step *wall* and `device_drain_ms` is zero by construction. With it the drain
becomes a measurement, and `host_bound` is only computed when the flag is set -
otherwise it is `null` with a `host_bound_note` saying why. The docstring now
states that `--skip-token-readback` is required for the split to mean anything
and that the probe's absolute rates run about 15% (p512) and 47% (p4096) above
the canonical bench's because it never warms the PLE page cache and runs both
cases in one process. Its `--host-profile` mode (cProfile over the decode loop,
top functions by tottime with callers) is retained.

**2. The canonical bench profiles its own decode loop.** New `--host-profile`
runs one extra `reset()` + `prefill()` + 128-step pass after the measured
repetitions, under cProfile, and records the top 30 functions by tottime with
call counts and shares into `artifact["host_profiles"]`. This is the DE-11
instrument: `wall - kernel_sum` says how much of a step is not device kernel
time but not what it is, and attributing it needs the bench's own loop rather
than a second harness's. The pass is extra and resets first, so it neither grows
the sequence nor perturbs the samples.

**3. The bench's split comment and its `--capture-mode` protocol record** (from
the companion unit) already warn that the split cannot attribute the two windows.
`docs/REFACTOR.md` carries the removal condition for both harnesses.

## Changes

- `scripts/qwen4exp_decode_host_bound_probe.py`: `--skip-token-readback` (a
  `copy_device_to_host` patch that short-circuits the 8-byte token copy, so the
  runner still takes its next token from the device argmax buffer and the
  executed token sequence and kernels are unchanged); `host_bound` is `None`
  unless the flag is set, with an explanatory note; the `host_enqueue` loop is
  labelled as per-step wall when the readback is present; docstring rewritten
  with the tautology and the absolute-rate calibration. `--host-profile` /
  `--profile-steps` (already in the working tree from the attribution attempt)
  are included.
- `scripts/qwen4exp_canonical_ar_bench.py`: `--host-profile` on the `hipengine`
  subcommand and `_hipengine_host_profile(...)`, which resets, prefills, profiles
  the 128-step decode loop, and returns `{case_id, transitions, total_s,
  entries[]}` with each entry's function, file, line, ncalls, tottime and share.
  The artifact gains a `host_profiles` list.
- `tests/test_unit_qwen4exp_canonical_ar_bench.py`: two new tests - the parser
  accepts `--host-profile` (default off), and `_hipengine_host_profile` resets
  before prefilling, runs exactly `transitions` steps, and returns shares in
  descending order with the profiled loop present. **17 passed** (2 new).
- `benchmarks/results/2026-10-04-qwen4exp-build-resolution-memo/`: the six
  canonical-bench A/B artifacts referenced by
  `20261004T083532.632371Z-lhl-qwen4exp-build-resolution-memo-dacd00.md` but not
  committed with it.
- No engine, kernel, flag, default or retained metric row changed.
