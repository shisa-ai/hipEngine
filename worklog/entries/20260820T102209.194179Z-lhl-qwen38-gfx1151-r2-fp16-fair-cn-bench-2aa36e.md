# fp16 indexed-singleton decode kernel + fair c1/c4/native_c8 FP32-vs-FP16 benchmark

## Summary

Completes the decode-side of the fair FP32-vs-FP16 production measurement
(tasks #16/#21). The prior FP16 packed-AR run (2026-08-20 18:42, confounded)
used the segments fallback for the c4/native_c8 decode because no fp16-state
indexed-singleton kernel existed; c4/c8 therefore ran a different decode
kernel than the FP32 baseline (17:48), confounding the comparison.

  on `state_t` (all state reads/writes through `gdn_state_read/write_qwen35`);
  strict launchers explicitly instantiate `float`; new `_fp16state` half_t

  `_resolve_gguf_linear_attention_decode_batch_plan` keeps the indexed-
  singleton decode path under the flag via the fp16-state sibling (no FP32
  indexed kernel against a half-sized buffer).
- `hip_gfx1151/__init__.py`: `bf16_indexed_singleton_fp16state` override maps
  to the shared-statecache24 fp16 wrapper.
- Tests: RED fp16 indexed one-token-per-row kernel vs host fp16 replay

(fair fp16 indexed-singleton decode), run back-to-back with a fresh FP32
baseline on the same warm GPU (fp16 10:25Z, fp32 10:30Z, same cached builds,
