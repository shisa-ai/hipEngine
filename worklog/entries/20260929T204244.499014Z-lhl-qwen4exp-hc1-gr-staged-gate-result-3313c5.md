**The selector's own comment predicted it:** "the GR numerical gate is a cliff at ~5e-9
prefill-boundary KL and this route's screened drift is ~1e-6 relative L2". "Arithmetic intact" and
"inside the calibrated envelope" are different claims, and the second one failed.

**A gate trap found running this, recorded in `docs/REFACTOR.md`.** The first attempt was a
**control that looked green**: `candidate_dispatch_calls: 0`, all 18 trajectories bit-identical,
every individual quality gate `true`. Cause: all four GR selectors require `rows > 256`, while the
layer2 gate's **default** suites give 18 prompts of **39-71 tokens**, so prefill is a single short
call and every GR route declines. **The gate is fail-closed and refused it** - `measurement_valid`
requires `counter["calls"] > 0` whenever the candidate declares a dispatch target - so no false
pass was certified. The fix is to also pass
`benchmarks/prompts/qwen4exp-natural-long-tasks-v1.jsonl` (438/508/424/512 tokens, all four
required categories, written for exactly this row floor). **Consequence for the record:** the two
pre-existing GR candidates (`production_gr_up_restore`, `production_gr_up_wide`) have **no gate
artifact in `benchmarks/results/`**, and a default-suite run of either would be a control for the
same reason.

**A second operational trap:** `tracked_clean` is evaluated near the **end** of `run()`, so an edit
made while a gate run is in flight invalidates that run's artifact rather than stopping it. Two
attempts were discarded for that reason (`gate.json` - default suites, a control;
`gate-longform.json` - correct suites, tree dirtied mid-run by a `docs/REFACTOR.md` edit).
`gate-final.json` is the clean artifact.
