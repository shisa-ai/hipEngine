# the MMQ32 staging loop is KSUB-aware, so a wide pass syncs once per KSUB

## Summary

`20260928T214500` made `MMQ_K` a template parameter with a default of 32. **This entry makes
the staging loop and the compute consume `KSUB = MMQ_K / 32` subblocks per pass, which is the
edit that actually removes barriers.**

## How it is done without re-indenting the staging body

The loop still walks `k32` one subblock at a time and stages into shared memory exactly as
before -- the only change is **which slot it writes**:

```cpp
const int kslot = k32 % KSUB;
weight_tile[col_offset * KSUB + kslot] = ...;
activation_tile[load_activation_row * KSUB + kslot] = ...;
if (kslot != KSUB - 1) {
  continue;
}
__syncthreads();
... consume all KSUB slots ...
```

**The caches already live in shared memory, so they survive the intervening iterations.** Only
the sync-and-consume step needs to happen once per `KSUB`, and the `continue` is what defers
it. That avoids restructuring the ~140-line staging body -- the two staging sites and the
compute are the whole diff.

The compute moves its `weight_cache` load inside a new `for (int s = 0; s < KSUB; ++s)` loop
and indexes `weight_tile[(tiwr * TM + cr) * KSUB + s]` and
`activation_tile[(wsic * 4 + tiwc) * KSUB + s]`. **Each subblock keeps its own `dm` pair**, so
the scale/min application moves inside the `s` loop with it -- which is required for
correctness, not just tidiness: a 128-wide pass spans four different `d`/`dmin` values.

The two tile index spaces agree: `tiwr` and `col_offset` are both 0..31 column indices
(`tiwr` from the thread id, `col_offset` from `load_weight_col = tid >> 2`).

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_q4_k_q8_1_selected_prefill.hip`: `kslot` added to
  the staging loop; the three staging writes and the compute indexed by `KSUB`; the sync and
  consume guarded on the last slot.

## Validation

`KSUB = 1` gives `kslot == 0 == KSUB - 1`, so the `continue` never fires and every index
collapses to the original expression. The gate is therefore the existing parity suite:

```
HIPENGINE_HIP_ARCH=gfx1151 ROCR_VISIBLE_DEVICES=0 \
  uv run pytest tests/test_gpu_gguf_q4_k_q8_1_selected_prefill.py -q
# 69 passed, exit=0
```

**No performance claim is made here.** This entry lands the mechanism; the wide instantiation
is what can move the rate.
