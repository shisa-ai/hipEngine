# DMS sidecar qualified on XTX local Q4_K_M via container-equivalence binding extension

## Summary

Campaign-lead directive: extend the trained DMS sidecar's strict model-hash
binding to the local Q4_K_M build instead of downloading the required 17.1 GiB
GGUF revision onto a 99%-full disk. The 1,024-byte difference between the two
builds was proven container-level, a derived local package was created with
recorded provenance, and the full XTX qualification chain then passed:
gfx1100 backend gate (widths 1-32), same-owner dense/no-evict/sidecar
comparison at 768 and 16,384 tokens, and the integrated 16,384-token compact
serving smoke with full memory accounting.

## Changes

- Proved GGUF build equivalence without the download: both GGUF v3 files
  (`unsloth/Qwen3.8-27B-GGUF@4121cb19` sha `7e78da5d…` 17,106,775,008 B vs
  local `7b2aec3b…` 17,106,773,984 B) have byte-identical 866-tensor tables
  (names/shapes/qtypes/data offsets) and 51 metadata KVs; the only metadata
  difference is `tokenizer.chat_template` (+1,048 bytes, chat text, no
  compute effect). 14×256 KiB tensor-body range samples spanning the full
  file (output.weight, blk.0/15/31/47, blk.64.nextn, token_embd) all match
  byte-for-byte via HTTP range requests against the remote revision.
- Created `/models/dms/qwen38-27b-q4km-dms-w8192-local/` (uncommitted local
  package): byte-copy of the sidecar safetensors + derived `dms_metadata.json`
  with `artifact_fingerprint` set to the local sha and an
  `artifact_binding_extension` block recording the original fingerprint,
  original metadata sha, the directive, the equivalence evidence, and the
  scope caveat (weight-identity only; XTX gates still required). The original
  HF cache snapshot is untouched.
- Added `GGUF_FULL_ATTN_QK_POSTPROCESS_DECODE_POLICIES` to
  `hipengine/kernels/hip_gfx1100/__init__.py` admitting (1, 24, 4, 256) →
  `qwen35_position_qk_bf16_f32`: external DMS serving requires the fused Q/K
  postprocess composite, which was policy-gated gfx1151-only although the
  identical kernel was already registered on gfx1100. The policy is now
  shared by dense full-attention decode on the qualified shape.
- Updated `tests/test_qwen38_full_attn_qk_postprocess.py` routing test:
  gfx1100 now routes the qualified shape; other shapes still miss.

  manifest builder (seed 20260907, wikimedia/wikipedia 20231101 en/ja + CPython

  scope caveat in the payload: NOT train-disjoint (no training-time source

  traces, and indicative KL/top-1 only.
- Updated `docs/QWEN38-27B-GFX1100-24GB-CAPACITY.md` Packet 4: binding item
