# Qualify SPECDEC2 compaction and neighbor substitution

## Summary

Expose scheduler/model compaction as a serialized EngineService control and
qualify the real S4 stagger→compact→substitute lifecycle. A short row retires,
the surviving request moves from scheduler slot 1 to 0 while its request-owned
target/provider state remains attached, and a newly admitted request takes the
free neighbor slot and completes exact speculative output.

## Changes

- Add `EngineService.compact()` and route it through the existing sole-driver
  control queue.
- Add the SubmitPoll wrapper's locked `compact()` method so service control
  reaches `ResidentEngineLoop.compact()` rather than falling through to the
  model generator.
- Add `scripts/specdec2_s4_compaction_gate.py` with exact slot-map, move,
  substitute-output, GPU accept/group-commit, cancellation, and final-drain
  assertions.
- Add a focused service test proving compaction runs on the driver thread.

## Validation

```text
uv run --with pytest --with fastapi --with httpx python -m pytest -q tests/test_generation_engine_service.py::test_engine_service_serializes_compaction_on_driver_thread
```

passes.

Hardware gate on host `gfx1151`, AMD Radeon 8060S, Qwen3.8-27B Q4_K_S, BF16
KV, strict FP32 state, queue2, cached builds:

```text
env HIPENGINE_HIP_ARCH=gfx1151 HIP_VISIBLE_DEVICES=0 GPU_MAX_HW_QUEUES=2 HIPENGINE_REQUIRE_CACHED_BUILD=1 HIPENGINE_COMPILER_VERSION_FILE=/tmp/hipengine-hipcc-version.txt .venv/bin/python scripts/specdec2_s4_compaction_gate.py --model /models/gguf/Qwen3.8-27B-Q4_K_S.gguf --output /tmp/specdec2-s4-compaction.json --fail-on-fail
```

passes. Before compaction the physical scheduler map is `[None,1]`; the sole
move is request 1 slot `1→0`; after compaction the map is `[1,None]`; request 2
then substitutes into the free neighbor and emits exact IDs `[271,9419,0]`
through physical GPU accept/group commit. The long survivor cancels normally and
final active ownership is zero.
