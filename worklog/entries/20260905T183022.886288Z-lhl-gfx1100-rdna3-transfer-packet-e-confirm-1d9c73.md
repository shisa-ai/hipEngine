# gfx1100 rdna3 transfer packet E Q6 lm-head C8 partition confirm

## Summary

Audit packet E (docs/20260905-gfx1100-audit.md) closes as **confirmed with no
capability change**. Its RED step asked to prove the W7900-resolved lm-head
rowtile caps at 6 rows; that premise is false at this revision. Qwen3.8-27B's
`root.lm_head` resolves to `gguf_q6_k_t16_qmicro_planar_v1`, whose registered
`t16_gemv_rowtile_bf16_f32_out` advertises `_hipengine_max_rows = 8`, and
`GGUF_Q6_LM_HEAD_MAX_CHUNK` has been 8 on `hip_gfx1100` since `86c92a784`
(2026-09-02). The audit's starting revision `58b7e77ff` branched before that
commit; merge `cca981f08` brought it onto `main`. The physical width-8 verifier
root head is therefore already one rows-8 launch, and the trace confirms the
single-launch partition beats 6+2 on device time.

## Changes

- No capability, route, or kernel changed. `GGUF_Q6_LM_HEAD_MAX_CHUNK` stays 8
  and `HIPENGINE_GGUF_Q6_LM_HEAD_MAX_CHUNK` stays the documented rollback
  (docs/REFACTOR.md "2026-09-02 gfx1100 planar-Q6 root R8 rollback").
- Added scripts/gfx1100_packet_e_lm_head_resolution.py (commit 41c8d959a):
  materializes only `root.lm_head` from a real GGUF and reports the resolved
  four-axis dispatch key, the primitive width bound, and the chunk partition
  per width for each candidate max chunk. Diagnostic only.
- Added tests/test_qwen35_gguf_verify_lm_head_top1.py::
  `test_gfx1100_lm_head_rowtile_width_bound_comes_from_the_resolved_quant`
  (commit 41c8d959a). Every prior test in that file monkeypatched
  `_verify_lm_head_rowtile_max_rows`, so nothing pinned the registry values the
  packet depends on. The new test pins `gguf_q6_k_t16_v1` = 6,
  `gguf_q6_k_t16_qmicro_planar_v1` = 8, and the package chunk = 8 together.
- Corrected the audit doc: the "Current policy at the handoff revision" table's
  Q6 LM-head row no longer describes the tree, and packet E now carries a
  measured outcome section.
- Backfilled the C2 and D1 retentions into benchmarks/README.md (commit
  9a27f55c6); they had changed the default direct packed-AR decode route but
  never reached the rollup.
