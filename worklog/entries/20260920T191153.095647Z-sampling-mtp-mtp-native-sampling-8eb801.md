# Use shared native GPU sampling for automatic sampled MTP

## Summary

User directed sampled MTP to work with the newly default-on native GPU sampler.
The patch reuses the existing sorted native sampler for target-prefix draws,
instead of maintaining a separate device probability/rejection implementation.
CPU, GPU primitive/graph, and real-model HTTP validation pass. Supported
Qwen3.8 Q4_K_M gfx1151 sampled singleton requests now enter MTP automatically.

## Changes

- `native_sampler.py`: graph-owned `NativeSamplerChainWorkspace` calls the same
  sorted primitive as AR. Per-row seeds fold absolute token positions into the
  existing native row/step ABI. The sampler never advances live request state;
  only emitted tokens advance the counter at transaction commit.
- For a deterministic draft, compare each token with the independently sampled
  target token for its prefix. A match accepts the draft with probability
  p(draft); a mismatch already has the residual conditional distribution.
  Full acceptance uses the last target draw as the bonus. The existing
  prefix-match/commit kernel owns state selection, output limits and cursors.
  No new HIP kernel or sampler arithmetic was introduced.
- `gguf_native_spec_cycle.py`: captured sampled graphs now enqueue shared
  native sampling then the existing accept/commit kernel. Remove the duplicated
  device row-stat/residual sampler from the serving graph. Graph-owned sampler
  allocations are closed on teardown and capture failure. The standalone
  coupled-accept primitives remain available as test/debugging oracles.
- `qwen35_gguf_mtp2.py`: admit native-sampled rows; stage immutable sampler
  parameters/seed/step rather than consuming and rewinding PCG draws. The
  captured route handles full-vocabulary sampling without history processors.
  Bounded top-k, processors and strict native sampling use eager per-prefix
  selection with private history clones and the same NativeSamplerWorkspace.
  Eager native verification also exposes its resident device logits directly;
  only the serial debugging oracle requires a reported full-logit readback.
  Host rows retain the CPU coupled-accept oracle.
- `models/qwen35.py`: separate the automatic sampled singleton policy from
  the old greedy C2 policy. Scope is the existing Qwen3.8 Q4_K_M/gfx1151
  artifact, BF16 KV, capacity four, one active request, K3. Do not implicitly
  advertise sampled c2 support through the old mixed-mode row.
- Add focused unit/GPU tests and update API/sampling documentation.
- Existing unstaged prefix/runner/benchmark changes and the audit worker's
  concurrent commit `52cb4b5a7` were not altered.
