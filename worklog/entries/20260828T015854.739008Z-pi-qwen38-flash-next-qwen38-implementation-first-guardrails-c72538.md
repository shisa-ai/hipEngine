# Require short-context implementation before scaling

## Summary

Reordered the Qwen3.8 campaign around a binding implementation-first rule:
finish the basic product at 512/1K, optimize short-context prefill, and only
then qualify longer contexts when explicit throughput thresholds permit them.

## Changes

- Added hard full-model escalation thresholds: 4K requires 20 tok/s, 16K
  requires 50 tok/s, 64K requires 100 tok/s, and 128K+ requires 200 tok/s.
- Defined qualifying throughput as retained same-host natural complete-model
  prefill at an already-permitted context; microbenchmarks, repeated-token-only
  rows, external engines, and rejected numerical profiles cannot unlock scale.
- Defined the 512/1K basic product gate: audit llama.cpp PR #27742 then
  EngramHalo; complete text AR public surfaces, MTP, basic vision, lifecycle,
  and c2 isolation before returning to long context.
- Existing 4K/16K/64K artifacts remain historical evidence but are not rerun
  below the ladder. Reduced position/control fixtures are the only exemption.
- Mirrored the policy in `docs/BENCHMARK.md` so standard workload guidance does
  not accidentally trigger an expensive campaign run.
