# Close backend-neutral SPECDEC2 lifecycle and streaming

## Summary

Closed the backend-neutral S2 lifecycle. Staged submissions now carry exact
public sampling semantics into scheduler policy, support pending cancellation
while target work is in flight, roll back at the safe precommit boundary, and
publish no cancelled tokens. Blocking and SSE consume identical committed IDs
and finish details. Two speculative requests stagger retirement and refill,
including K3 and physical-slot permutation. Multi-prompt children, expired
deadlines, unsupported-sampling K0 fallback, target failure/AR health, and
shutdown drain are all covered.

## Changes

- Added thread-safe per-request cancellation probes to ordinary speculative loop
  submissions and passed pending cancelled IDs to staged target execution.
- Added cancelled-cycle handling that reclaims only cancelled requests without
  publishing committed token events.
- Added generic `PerRowSamplingParams.from_generation_request()` and carried the
  exact public request into speculative policy; unsupported stochastic settings
  now choose K0 before provider claims/prepare.
- Preserved existing finish details during speculative output normalization when
  the normalized reason is unchanged, fixing blocking/SSE length metadata drift.
- Expanded fake loop/service gates for K3 stagger/refill, cancellation with zero
  visible tail, blocking/SSE parity, shutdown boundary/drain, multi-prompt IDs/
  accounting, pre-open deadline failure, and unsupported-sampling K0.
- Marked S2 complete and advanced the normative handoff to gfx1151 S3.
