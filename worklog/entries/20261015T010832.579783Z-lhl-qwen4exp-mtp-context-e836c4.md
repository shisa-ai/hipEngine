# Qwen4Exp MTP context admission

## Summary

Removed the Qwen4Exp MTP provider's hard 1K bring-up ceiling. Draft capacity now follows the target runner/model context and is admitted only when the draft's own KV allocation fits a conservative free-memory reserve. Public capability metadata reports the actual admitted limit.

## Changes

- `hipengine/generation/qwen4_exp_mtp.py` now uses the target runner capacity rather than `min(..., 1024)` and reports it in `context_limit`.
- `hipengine/runtime/qwen4_exp_mtp.py` validates capacity against the model context and checks estimated draft KV bytes against available HIP memory before allocation.
- Updated provider and rollback fakes for the compact proposal argument and added a regression covering a 1,020-token prompt crossing the former limit.

## Validation

- `uv run pytest -q tests/test_unit_qwen4_exp_mtp_provider.py tests/test_unit_qwen4exp_mtp_*.py tests/test_live_qwen4_exp_mtp_runner.py` — 10 passed, 1 skipped.
- The live GPU runner test remains skipped in this CPU-only validation environment; full long-context GPU generation, rejection rollback, and public-server MTP telemetry still require the model/runtime gate.
