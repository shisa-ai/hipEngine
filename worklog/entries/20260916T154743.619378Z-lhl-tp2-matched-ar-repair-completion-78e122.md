# Matched-AR repair completion: suite matching, keyed reps, Latin rotation, safe validation

## Summary

Review found my previous report over-claimed: "all six repaired" was false.
This entry records the additional CPU repairs that close the concrete gaps and
corrects the claim. `scripts/tp2_matched_ar_baseline.py` now compares returned
prompt identity against the declared suite, keys results by `(rep, arm)`,
rotates arms in a Latin square, uses deterministic content hashes, validates
before aggregation, persists per-prompt rows and run/teardown provenance, and
suppresses ratios while input matching or provenance is unverified. No GPU run.

## Changes

- **Suite/row matching (was missing entirely).** `validate_arm_rows` rejects
  zero rows, duplicate ids, missing/extra ids, reordered ids, and a changed
  category. `cross_arm_token_hashes` requires every arm to report the same
  `prompt_token_sha256` per prompt. This is an input/tokenizer identity check
  only; cross-arm *generated* token equality is deliberately not required.
- **Keyed results.** `runs` is now a `dict[(rep, arm)]`; a failed early rep no
  longer shifts a later rep's success into its slot. Regression test:
  `test_main_keeps_reps_keyed_when_an_early_arm_fails`.
- **Latin-square rotation.** Three reps rotate `tp1-d0`/`tp2`/`tp1-d1` so no arm
  is always first (`test_main_uses_a_latin_square_rotation`). Each arm remains a
  separate process, so no resident sessions overlap.
- **Deterministic hashes.** `prompt_ids_sha256` and `prompt_token_sha256` use
  `sha256` over UTF-8 JSON, never Python `hash()` (which is
  `PYTHONHASHSEED`-randomized). A cross-interpreter test pins this.
- **Validate before aggregation.** `validate_accounting` reads every numeric
  field through `_as_int`/`_as_float`, so missing/`None`/NaN fields produce
  failure strings instead of raising in `float()`/`sum()`; aggregation is only
  attempted after row validation and is still wrapped as a backstop.
- **Persisted evidence.** Each arm entry now carries `prompt_metrics` (the raw
  per-prompt rows), `command`, `log`, `device`, TP2 `devices`/`route`,
  `session_capture_ms`, `session_destroy_ms`, and TP1 `tp1_provenance` /
  `tp1_timing_protocol`; `provenance.runs` lists all nine executions.
- **TP2 destruction measured.** `run_tp2_arm` times `session.close()` into
  `session_destroy_ms`; device identities and route are captured before close.
- **Ratios suppressed more broadly.** `unverified = accounting_failures or
  matching_failures or provenance_gaps`; a missing TP1 provenance is recorded as
  a `provenance_gap` blocker rather than silently accepted.
- **Empty suite still emits an artifact.** A missing suite now produces a
  blocked artifact instead of an early return.
- **Overhead documented.** `window_overhead_note` records that TP1 checks logit
  finiteness inside its timed loop while TP2 does its per-step argmax/list work
  inside the session call and its final `np.stack`/argmax after the timer, so the
  rates are a diagnostic comparison, not a product baseline.
- `scripts/gguf_true_ar_category_bench.py`: per-prompt rows carry
  `prompt_token_sha256`.
- Tests: 35 matched-AR tests (was 30), including new coverage for zero/duplicate
  rows, wrong token hash, missing field, empty suite, missing TP1 provenance,
  Latin rotation, and the early-failure/keyed-rep regression.
