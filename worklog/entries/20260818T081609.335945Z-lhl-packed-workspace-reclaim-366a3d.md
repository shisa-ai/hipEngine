# retain owner-shared packed workspace across reclaim

## Summary

`_GGUFResidentLoopRow` reclaim no longer frees the owner-shared packed
workspace. The slab is union-geometry and shared by every resident view after
the 4a85ce9f1/f948e493f owner-shared bookkeeping, so the `capacity > 2`
per-reclaim release (added when each session owned a private slab) forced a
same-size hot-path HIP reallocation on the next packed step. The accepted
C2-6 canonical packet (ff440cd01) recorded 246 release events / 242.39 GiB
cumulative released bytes (~0.985 GiB per event), violating the CONCURRENCY2
workspace-reuse and no-hot-path-allocation invariants (docs/CONCURRENCY2.md
"Hot-path HIP allocation and surprise pool growth are disabled" and
"Workspaces are reserved by the resource ledger and reused"). Release remains
a close-path operation: session close frees the workspace directly, and the
guarded `release_idle_packed_workspace()` stays as a close/idle-only public
API now tracked in docs/REFACTOR.md.

## Changes

- `hipengine/generation/qwen35_gguf.py`: `_release_row_resources` drops the
