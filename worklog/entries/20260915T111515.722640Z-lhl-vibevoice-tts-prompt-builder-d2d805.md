# In-tree VibeVoice-TTS prompt builder, pinned to the oracle fixtures

## Summary

Every TTS measurement so far ran the one or two requests whose prompt tokens the
frozen fixtures happen to record. A quality suite over held-out requests needs
prompts for scripts the fixtures do not contain, which means reproducing the
fork's prompt construction in-tree. `hipengine/loading/vibevoice_tts_prompt.py`
does that, and the two fixtures we can check pin it: for both `single` and `two`
the built `input_ids` **and** `speech_input_mask` equal the oracle's exactly
(121 and 352 tokens).

## The trap

The fork derives a speaker's voice-prompt token count from that speaker's own
reference-audio length, `ceil(samples / 3200)`, *before* the batch pads every
speaker to the longest one. The `two` fixture stores both references padded to
665600 samples, so taking the count from the array shape gives 208 latents for
each speaker instead of 70 and 208. That builds a 490-token prompt where the
oracle has 352 — a request the model was never trained to see, and one that would
have looked plausible in a transcript.

`test_padded_reference_length_is_not_the_voice_prompt_length` asserts the
inflated prompt does **not** match the oracle, so the distinction stays
load-bearing. (The `single` case skips: there, padding and the true length
coincide, so the two cannot be told apart.)

## Tokenizer provenance

The `microsoft/VibeVoice-1.5B` snapshot ships no `tokenizer.json`, so the builder
takes a tokenizer explicitly and the test points it at the sibling
`microsoft/VibeVoice-ASR-HF` checkpoint. That substitution is asserted, not
assumed: if the tokenizer did not reproduce both fixtures token-for-token the
test would fail. The builder also refuses a script whose speaker ids do not match
the number of supplied reference voices, and refuses a non-positive token count.

## Changes

- `hipengine/loading/vibevoice_tts_prompt.py` (new): `build_tts_prompt`,
  `parse_speaker_script`, `vae_token_count`, `load_tts_tokenizer`, `TtsPrompt`.
  Special-token ids are imported from
  `hipengine.loading.vibevoice_tts_session` rather than redeclared.
- `tests/test_unit_vibevoice_tts_prompt.py` (new): the reproduction assertions,
  the padding trap, the token-count rounding, and the parser's renumbering and
  rejection behaviour.

## Validation

- `pytest tests/test_unit_vibevoice_tts_prompt.py` -> 9 passed, 1 skipped.
- `pytest tests/ -k vibevoice` -> 115 passed, 3 skipped, 2 failed (the
  pre-existing ASR WER driver tests).
