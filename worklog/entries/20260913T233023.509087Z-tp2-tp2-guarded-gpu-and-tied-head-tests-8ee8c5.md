# TP2 Packet 1/2: guarded two-GPU tests and the tied-head manifest case

## Summary

Two checklist items that were only covered indirectly now have direct tests.

- **Packet 1's two-GPU coverage** was the collective bench script plus its
  artifact. `tests/test_gpu_distributed_transport.py` adds four guarded GPU
  tests that run only when two HIP devices are present: a real two-rank RCCL
  group all-reduce checked against the arithmetic sum on both ranks, rank-bound
  context device selection and restore, a real KV claim that allocates on device
  and rolls back when rank 1 fails, and the peer-access probe answering rather
  than raising.
- **Packet 2's tied-head case** was untested. `token_embd.weight` and
  `output.weight` are separate tensors in this model, so the tied layout was
  never exercised. A real-model test now removes `output.weight` from the
  inventory, asserts the config resolves the head to the embedding, and asserts
  the manifest neither invents a head tensor nor changes any other tensor's plan.

The KV claim test also pins a real contract detail: an allocator that fails
*after* taking device memory must release that buffer itself, because `claim_all`
can only roll back buffers it successfully collected. The test asserts no device
buffer survives a failed claim.
