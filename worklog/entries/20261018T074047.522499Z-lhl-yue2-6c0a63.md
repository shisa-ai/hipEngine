# yue2 split-K decode attention on gfx1100

## Summary

After the paired-branch forward, span attention was 18.0 ms of a 30.22 ms paired forward at product
depth (60%), growing linearly in context. The strict span kernel launches one 256-thread block per
query head (16 blocks for 40 CUs on a decode step) and reads the KV rows with a per-token stride, so
its warps issue uncoalesced 2-byte loads and most of the device idles.

The decode route is now the `vv_attention_spans` **production** variant: one block per (KV head, KV
split) with that KV head's query group folded in, a warp covering head_dim so each KV row is one
coalesced run, and the split's scores staged in shared memory. Only the softmax reduction order
changes, so the strict kernel stays the registered parent.

Measured on `epyc` / Radeon Pro W7900 (`gfx1100`, ROCm 7.2), `m-a-p/YuE2-3B@29b3558` +
`m-a-p/YuE2-Vae@9a94e1d`, BF16. AR step at 98 / 998 / 2 098 tokens of context: **12.79 -> 11.93**,
**30.81 -> 12.54**, **53.30 -> 13.52 ms** (1.07x / 2.46x / 3.94x). The step becomes nearly
context-independent because the KV scan stops dominating. The product path goes from RTF 1.069 to
**0.579**.

## Changes

- `hipengine/kernels/hip_gfx1100/vibevoice/attention_spans_splitk.hip` + `.py`: the split-K kernel,
  its combine kernel, and the wrappers. The partial kernel takes one block per (KV head, split, row),
  derives the split range from the device-side context, stages `q` and the chunk's scores in shared
  memory, and publishes per-split (max, sum, unnormalized value row); the combine kernel rescales by
  `exp(m_s - M)` and divides by the combined normalizer.
- `hipengine/kernels/hip_gfx1100/vibevoice/registered.py`: registers it as
  `KernelKey(backend, 'vv_attention_spans', 'bf16', 'production')`.
- `hipengine/kernels/vibevoice.py`: the resolver exposes it as `vv_attention_spans_production` when a
  backend has it registered, so selection stays in the registry.
- `hipengine/runtime/yue2_ar.py`: `attention_route` (`auto` | `strict` | `splitk`), the split
  workspace, and `_decode_attention`, which both decode paths call. The prefill path keeps the
  strict kernel. `attention_route="strict"` is the rollback and the A/B arm.
- `hipengine/runtime/yue2_session.py`: the timing payload reports the route that ran instead of a
  fixed `"spans"`.
- `scripts/yue2_ar_attention_splitk.py`: the A/B harness (numerics and step time from one process).
  `scripts/yue2_ar_replay.py` grows `--attention-route`; `scripts/yue2_ar_step_profile.py` is from the
  paired-forward unit.
- `tests/test_unit_yue2_attention_splitk.py`: agreement with the strict parent across seven
  (context, splits) pairs including a single live token, an uneven division and a 32-split product
  depth, the evict-mask path, determinism, the reject paths, and the split-count bound.

## Validation

- Kernel gate: `uv run pytest tests/test_unit_yue2_attention_splitk.py` — 11 passed. Both kernels are
  also checked against an independent NumPy causal-softmax reference; the split-K route agrees to
  <1e-5 in every case, which is fp32 rounding.
- Teacher-forced A/B against the strict route, 16 steps at each of three depths (98 / 998 / 2 098
  tokens of context): mean row KL 5.1e-4-8.4e-4, max 2.1e-3, top-1 agreement 47/48, largest
  branch-hidden relative delta 2.2% on bf16 rows.
- Model-level gate: `scripts/yue2_ar_replay.py --attention-route splitk` over the committed 18 cases
  / 576 rows measures pooled mean KL **1.02e-3** and top-1 **96.18%** against the pinned upstream
  oracle, versus the strict route's 1.05e-3 and 95.31% on the same host. Agreement with the reference
  does not move.
- Product path: one live request plus an in-process repeat, `repeat_bit_identical: true`,
  non-silent fraction 0.9999, no truncation, no torch import, RTF 0.579.
- `uv run pytest tests/test_unit_yue2_session.py tests/test_unit_yue2_ar_runtime.py` — 34 passed
  (the fake runtime grows `attention_route` so the session timing payload stays a plain attribute
  read).

## Next

- The route is not bit-identical, so a sampled trajectory can diverge from the strict one: the
  committed `cot="off"` product request emits **1 065 latent frames instead of 1 862**. That is
  inherent to a non-bit-identical arithmetic path under a sampler and is recorded as the decision's
  consequence in `docs/EXECUTION-PROFILES.md` §2.12, not treated as a defect. Task quality (blinded
  listening, lyric adherence) remains unrun on this host for either route — the standing M8 gap.
- Two bugs found and fixed while bringing the kernel up, both worth remembering: a warp's lanes all
  walk the same token set, so a per-warp sum must not be shuffle-reduced across lanes (it multiplied
  the normalizer by the warp size); and the combine must weight the numerator by `exp(m_s - M)` only,
  because the partial rows are already summed — including `l_s` there multiplies the result by the
  split's normalizer.
