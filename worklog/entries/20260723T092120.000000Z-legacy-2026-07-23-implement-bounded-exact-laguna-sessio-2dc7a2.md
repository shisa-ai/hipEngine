## Changes


- Added one bounded generator-owned resident continuation slot keyed by SHA-256 of auth principal plus explicit chat-session ID. After a safe `append_visible_only`/`append_all` terminal result, Laguna records exactly the tokens already processed into KV (`prompt + generated[:-1]`), leaving the final sampled token as the first candidate suffix token. A later request reuses state only when key, TTL, exact token prefix, nonempty suffix, and session/KV position all agree; every mismatch, unsafe cache action, error, cancellation, or different principal/session resets to ordinary full prefill.
- Request-local session ownership now crosses the generic `SamplingParams`/`GenerationRequest` boundary without backend dispatch branches. Capable engines advertise one-slot resident KV commit and allow stateful streaming; other engines retain the old transcript-only capability and streaming rejection. Telemetry distinguishes `session_prepare_mode=reuse`, `resident_kv_reused`, and exact `prefix_reused_tokens` while retaining full prompt usage and suffix-only prefill wall.
- RED/GREEN covers the final-unprocessed-token case, exact suffix prefill, prompt mismatch, auth/session-key mismatch, unsafe `append_none`, reset fallback, blocking/stream auth scoping, and capability truthfulness. Focused generation/registry reports 46 passes and the complete server API file reports 529 passes. `py_compile` and diff checks pass.
