# HC-1: the GR staged-f32 variant is registered and selectable, gate blocked on layer scoping

## Summary

HC-1's staged-f32 GR-up prototype is now **registered as a variant and reachable
from the engine behind a default-off selector**. The production gate cannot be
run for it yet, and the blocker is concrete: every route in the gate script is
layer-scoped, and the GR read path has no layer index to scope by.

## What landed

- `gguf_q8_0_gr_staged_f32.py` registers
  `coltile2_branch4_rowbatch4_staged_f32` under `linear+gr_gated_mean`. The
  registration lives in the prototype module so the dependency points at the
  registry rather than back into `gguf_k_gemv`. Registration is deliberately
  separate from selection.
- `qwen4_exp_runner.py` gains `_qwen4_exp_gr_staged_enabled(rows, low_rank)`
  (env `HIPENGINE_QWEN4_EXP_GR_STAGED`, default off, `rows > 256`,
  `low_rank % 64 == 0`) and a dispatch branch inserted between `gr_iu8` and
  `fused_up`, mirroring the `gr_wide` branch: staged GEMM plus the retained exact
  sigmoid and gated-mean epilogue.
- `tests/test_unit_qwen4exp_gr_staged_dispatch.py`: 7 unit tests pinning
  registration, the tile name the screen and gate script both use, default-off,
  the row floor, the K-alignment decline, and that `""`/`0`/`false`/`False` stay
  off.

The launcher's ABI `(x, qweight, out, rows, in_features, out_features)` maps
identically to `gguf_q8_0_dense_wide256_f32_f32_out`, which is why the dispatch
branch could mirror `gr_wide` directly rather than needing an adapter.

## Why the gate did not run

Not "needs more evidence" - a specific structural blocker.

`scripts/execution_profile_q8_wmma_prefill_layers_gate.py` builds every route
from `Route.env_for`, which formats `{layers}` into the selector's env value. All
of its routes are **layer-scoped**. But `run_qwen4_exp_gr_read` takes no layer
index:

```python
def run_qwen4_exp_gr_read(
    residual_ptr, norm_weight_ptr, down_weight, up_weight, inject_weight,
    scratch, *, rows, branches, hidden, low_rank, eps=1e-6, stream=0, runtime=None,
)
```

So a layer-scoped GR selector cannot be expressed without threading a layer
argument through the GR call chain. Running the gate without that would engage
the staged tile on **every** layer instead of the named scope, which is not the
comparison the gate's scope checks are built to certify.

I chose to land the wiring and record this rather than start a call-chain change I
could not finish and validate in the remaining budget.

## A related result that does NOT transfer

The **dense linear** staged tile is a different kernel on a different layer
(`KernelKey(..., "linear", ...)`, `staged_f32_bm128_bn64_bk32`, env
`HIPENGINE_QWEN4_EXP_Q8_STAGED_F32_LAYERS`). Its gate has already run and reaches
`status=complete, canonical=True` on layers 16-47 and 14-47
(`benchmarks/results/2026-09-29-q8-staged-f32-dense-prefill-layers-gate/`).

That is encouraging but **not evidence for this route**: different layer,
different epilogue, and the GR dispatch records its own prefill-boundary KL
cliff. I am recording it as adjacent context, not as a partial result.
