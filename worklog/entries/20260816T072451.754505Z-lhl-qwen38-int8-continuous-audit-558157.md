# Correct Qwen3.8 INT8 continuous-batching interpretation

## Summary

Corrects the continuous-batching interpretation in
`20260816T071413.192306Z-lhl-qwen38-int8-context-quality-concurrency-dfa478.md`.
That entry's capacity and quality measurements remain valid, but its conclusion
that the exact route is only queue coalescing was too broad: the soak used
blocking non-streaming requests, and `/ready` emitted a hardcoded false
capability. The measured protocol did not exercise the resident controlled-SSE
lifecycle.

## Changes

- Traced blocking requests through `_GenerationBatcher._run_group()`: one
  compatible static HTTP group calls `generate_detailed()` to completion before
  the batcher accepts the next blocking group. The observed c2/c2+c2/c1+c3+c4
  rows are therefore HTTP call shapes, not live occupancy transitions.
- Traced SSE through `_launch_controlled_stream()`: independent producer tasks
  submit to one `SubmitPollTextGenerator`, whose tick lock is released after
  every model transition.
- Confirmed `Qwen35GGUFBringupGenerator.create_resident_model_runner()` selects
  `Qwen35GGUFResidentModelRunner`. The resident owner already implements atomic
  request-sized KV admission, chunked prefill/decode selection, occupancy-
  adaptive physical groups, stable request-owned sessions/KV, compaction,
  cancellation, and reclaim.
- Found `/ready` and Prometheus called `_scheduler_fairness_capability()` without
  the loaded engine, unlike `/v1/hipengine/capabilities`; added an engine-aware
  telemetry fix with RED/GREEN coverage.
- Corrected the concurrency harness so `--streaming-primary` also uses SSE for
  the staggered live-admission phase, polls resident occupancy through join and
  retirement, and records whether the join occurred inside the first request's
  client-observed streaming decode interval.
- The real storage limit remains: packed AR rejects every direct no-mirror INT8
  layout, while <=8K retains a BF16 mirror. Efficient long c>N therefore still
  requires direct INT8 packed attention even if the short controlled lifecycle
  qualifies.

## Validation

- RED: the controlled-streaming server test failed because `/ready` returned
  `continuous_decode=false` while capabilities returned true.
- GREEN: the focused server test passes after `/ready` and Prometheus derive the
  flag from the loaded engine.
- Rejected first W7900 audit `/tmp/qwen38-w7900-int8-continuous-audit-r1.json`
  (`06ebe677...`): it ended `failed_gate` because zero configured warmups made
  the generic gate false, and more importantly its stagger helper still sent
  blocking requests. Its `admission_during_first=true` proved only that HTTP
  requests queued before the first blocking response; it is not controlled-SSE
  resident evidence.
- Accepted corrected W7900 audit
  `/tmp/qwen38-w7900-int8-continuous-audit-r2.json` (`b528fbdc...`), exact
  command retained in the compact benchmark artifact. Model/quant/KV was
  Qwen3.8-27B Q4_K_M with FP32 per-token/head INT8 KV on gfx1100 GPU0; shape was
  512 prompt + 24 decode tokens at c1/c2/c4, one warmup and one measured blocking
  burst, one simultaneous SSE burst, then staggered c1->c4 SSE.
- Corrected audit result: `accepted_backend_packet`, every blocking warmup and
  measured row exact, every simultaneous SSE row exact, and staggered rows 4/4
  exact. Resident metrics observed c1 at `active_mask=1000` with
  `last_work_kind=decode` before joining the other three. Occupancy then moved
  `0->1->4->3->2->1->0`; all four rows used
  `gguf_packed_ar_server_decode` with `native_caware_decode=true`.
  Admitted/reclaimed deltas were `4/4`; final active rows, occupied slots, and
  refcounted pages were all zero. Prometheus reported
  `continuous_decode="true"`.
- Diagnostic SSE rates were c1/c2/c4 `11.974/8.266/10.760 tok/s`; they are not
  performance claims because this was one polled lifecycle run. c2/c4 also
  missed the arbitrary 0.5-second ITL SLO on some requests; that does not alter
  exactness or lifecycle qualification and is retained as a serving-tuning
  signal.
- Focused CPU validation: `tests/test_server_f1_concurrency_bench.py` passes
  25/25 and the engine-aware server capability test passes 1/1.
