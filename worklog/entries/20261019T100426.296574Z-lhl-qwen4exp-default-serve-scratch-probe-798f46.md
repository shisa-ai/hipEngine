# Flash-Next default serve startup scratch probe

## Summary

`hipengine serve --model <Flash-Next UD-Q4_K_XL> --speculative-provider
qwen4_exp_mtp --draft-model <Q8_0 MTP>`, with no `--max-active-requests`,
failed startup:

```
startup scratch_probe failed: RuntimeError: Qwen4Exp resident runner capacity
cannot change while live
```

The engine loop builds the resident runner first with `capacity=None`, which
resolves to the plugin's production width 2. The server's scratch probe then
asks for width `max(1, max_active_requests or 1)` = 1, and
`prepare_request_scratch` called `create_resident_model_runner(capacity=1)`,
which refuses to change a live runner's width. Both merge parents compute the
probe width the same way, so this predates the origin/main merge; every
recorded qualification run passed `--max-active-requests` explicitly and never
reached the default.

## Changes

- `hipengine/generation/qwen4_exp_gguf.py`: `prepare_request_scratch` reuses a
  live resident runner whose capacity covers the probe width. Its `prepare()`
  allocates every slot at full context, so the wider pool proves the narrower
  probe. A probe wider than the live runner still raises.
- `tests/test_unit_qwen4_exp_resident_serving.py`: RED test for a width-1
  probe against a live width-2 runner, plus a width-2 probe on the same runner.
