# Record host `/dev/null` corruption before repair

## Summary

Host `/dev/null` unexpectedly became a root-owned regular file instead of the
required character device, breaking Git and subprocess validation. This entry
records the pre-repair state before restoring the standard device node.

## Changes

- No repository implementation change caused or attempts to explain the host
  mutation.
- Pre-repair `ls -l /dev/null`: `-rw-r--r-- 1 root root 17 Aug 28 01:59`.
- Pre-repair `stat`: regular file, mode 644, root:root, device tuple `0:0`.
- Pre-repair bytes: `/usr/bin/snapper\n`.
- Symptom: `git diff --check` and `git rev-parse HEAD` fail with
  `could not open '/dev/null' for reading and writing: Permission denied`;
  transient `/bin/bash ENOENT` also occurred before clearing completed
  background-task records.

## Validation

- After the harness restart, `/dev/null` is restored as
  `crw-rw-rw- root:root 1,3` (character device, mode 0666).
- `ctypes.CDLL('libamdhip64.so')` reports `hip OK`.
- `git rev-parse --short HEAD` reports `cefba4e19`; `git diff --check` passes.
- No ROCm or repository restoration was required.
