# Muse Glimmer decode: exact grouped Q4 + hoisted Q6 GEMVs

## Summary

Decode budget re-measured (rocprofv3 kernel trace, 512 ctx, 20 steps): step
90.9 ms = kernels 84.1 + intra-graph gaps 6.1 (1204 launches, ~4-5 us per
boundary) + host 0.67. Q4 GEMV 59.4 ms, Q6 15.4, Q5 head 4.5, norms 2.9,
attention 1.35. The prior "211 GB/s ceiling" was a DtoD copy: a read-only
grid-stride kernel reaches ~240 GB/s on this host, and a pure read through the
per-wave T16 tile walk ~222 GB/s, so decode GEMVs were not at roofline (Q4
~208-211, Q6 ~190, narrow K/V/V 41-57 GB/s).

Landed two exact (bit-identical) decode GEMV owners and routed the Glimmer
decode graph through them:

- Q4T16 tile16 grouped GEMV: one wave owns a whole 16-column tile, lane keeps
  the local32 K ownership/FMA order/wave reduction, nibbles load as 4x uint4;
  up to four projections sharing one input run in one launch (Q/K/V/gate,
  gate/up). Per launch on gfx1151 at production flags: Q/K/V/gate 1.19x
  (2 waves), gate/up 1.04x (1), attn_output 1.06x (4), Q4 down 1.02x (1).
- Hoisted planar Q6T16 GEMV: same local128 ownership/reduction as the planar
  owner, d/scales hoisted, records read as dwords: ffn_down 1.09x, attn_v 1.7x.

Because both are bit-identical to the launch_gguf_linear decode owners, the
exact-rows DFlash verify owners still match AR decode KV.
