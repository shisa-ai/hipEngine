# Qualify eager long-context MTP correctness

## Summary

Added the RF1 direct oracle and real-provider harness for eager long-context
dense GGUF MTP. The retained 1024-ending gfx1151 smoke proves host target rows
and real NextN proposals remain off the reusable graph, use the long split-K
attention owner, and match strict/AR through every B3 acceptance depth. This
completes the harness unit, not RF1 qualification; multi-context task evidence
remains required before RF2 graph work.

## Changes

- Added `scripts/gguf_mtp_long_context_gate.py` with cycle-end keyed B1/B2/B3
  cases, inclusive-range/K-suffix parsing, stable compact JSON output, model/repo/
  host provenance, and fail-closed verdicts.
- Compared eager-native rows against an independently journaled serial-exact
  verifier for full logits/top-1/acceptance, every Conv/GDN resident state,
  touched BF16 key/value rows, selected hidden, cursor, selected-state commit,
  and post-commit rollback.
- Counted the concrete split-K attention leaf and checked resident split-workspace
  capacity for every long cycle while requiring zero target-graph submissions.
- Added teacher-built controlled B3 reject, partial-1, partial-2, and full-accept
  cases plus optional real NextN generation with cycle logits, host proposals,
  exact true-AR IDs, draft-tail repair telemetry, and no proposal/target chaining.
- Added focused CPU schema/planning tests and documented the harness under RF1 in
  `docs/MTP-FIX.md`. The short graph's 1023 context limit and server routing were
  not changed.
