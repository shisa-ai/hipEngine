# Screen LDS large-tile pack8 GEMM

## Summary

X2-K1 ported llama.cpp's LDS-staged large-tile GEMM structure onto pack8
in-kernel dequant. Result: bit-exact but only parity versus the routed
small-tile pack8 WMMA leaf on gfx1151 wave32, so it is registered as a
diagnostic and not routed.

## Changes

- `gguf_q4_k_pack8_prefill_wmma64_kernel` (128x64 block tile, 256 threads,
  BK=32 LDS f16 staging with per-step shared scale/min planes) plus export,
  wrapper, and registry variant `pack8_wmma64_prefill_bf16_bf16_out`.
- Correctness fixtures `tests/test_gguf_q4_k_pack8_wmma64_prefill.py` over
  four shapes including non-multiple-row guards.
- `docs/REFACTOR.md` entry documenting the unrouted diagnostic and its
  removal condition; campaign doc section 2.39 records the screen.

## Validation

- Fixtures: 4/4 pass (CPU f32 oracle within the accepted WMMA tolerance
  class, top-1 >= 90%).
- Actual-weight screen (rows=512, marker-timed, same session):
  routed small tile 0.375/0.351 ms per mat (gate/down, ~10.0/10.7 TFLOPS);
  best LDS configs tie (64x64 0.437/0.423, 64x128 0.410/0.465); 128x64
  ~1.4x slower; all LDS outputs bit-exact vs the small tile (max diff 0.0).
  Vulkan same-day reference 0.328/0.317 ms -> routed leaf within ~14%/10%.
- Dispatch tests 99/99 pass; production route unchanged (small-tile).

## Next

- Wave64 WMMA variant is the untested residual lever for the last ~10-15%.
- Priority moves to X2-K2 (GDN register-state prefill scan; 33.7/27.5 ms
  matched gaps for Q8/Q4) and X2-K5 (Q6-down native consumer).
