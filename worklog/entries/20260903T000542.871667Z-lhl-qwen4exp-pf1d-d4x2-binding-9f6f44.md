# PF-1d d4x2 policy binding surface

## Summary

Added the policy-owned activation-plane binding the whole-model gate needs to
run the d4x2 candidate without touching engine dispatch conditionals: the
registered `Q8MMQPrefillPolicy` gains a validated `planes` field (2 or 3,
default 3), the f32 MMQ dispatch honors it to select the registered d4x2
variant and its new `raw_mmq_d4x2_f32` route/launcher, and a pure-Python RED
test locks the binding (planes=2 -> d4x2 route, default -> production d4x3,
no session -> strict path untouched).
