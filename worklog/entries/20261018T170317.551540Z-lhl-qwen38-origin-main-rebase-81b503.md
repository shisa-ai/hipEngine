# Rebase qwen3.8-flash-next onto origin/main 52b087148

## Summary

`qwen3.8-flash-next` now carries `origin/main` (`52b087148`) as a merge
parent. Thirty-three files conflicted. Every resolution keeps both sides'
behaviour rather than picking one: the append-only rollups carry both
branches' rows, the engine service keeps our specdec driver and gains main's
fatal-cleanup acknowledgement, and the server keeps main's literal-stop
stream alongside our stop filter.

Four defects surfaced only after the per-file resolutions were staged, which
is why the whole-tree run is the gate for this unit rather than the merge
itself.

## Changes

Resolution-level, beyond the mechanical union:

- `hipengine/generation/engine_service.py`: a `shutdown` command queued while
  the driver is publishing a fatal failure is now acknowledged with
  `finish(value=True)` instead of failed with the driver's own error. Main's
  `test_close_during_fatal_cleanup_does_not_wait_for_abandoned_command`
  asserts that a caller enqueueing shutdown after fatal publication gets a
  clean `close()`, not the request failure. The first attempt passed
  `result=True` to a keyword-only `finish(*, value=..., error=...)`, which
  raised `TypeError` inside the driver's `finally` and left the caller
  blocked on `response.result()` forever; that is a hang, not a test
  failure, and it is recorded here so the shape of the mistake is not
  repeated.
- `hipengine/core/build.py`: added `HIPENGINE_NO_MCUMODE_FAMILIES` to
  `_BUILD_ENV_KEYS`. Main reads that knob in the flag builder, so a build made
  with a family suppressed would otherwise reuse a cached artifact compiled
  without the suppression.
- `hipengine/quant/gguf_t16.py`: the three-way merge concatenated two
  `repack_gguf_q5_1_tile16` definitions — main's at line 335 returning
  `GGUFQ51Tile16` and ours at line 1500 returning `GGUFQ5KTile16`. The later
  definition silently shadowed the earlier, so the merged module ran ours'
  body behind main's name. Ours' copy is removed; main's refactored
  implementation is the single definition and both Q5_1 tile suites pass
  against it.
- `hipengine/generation/qwen4_exp_serving_mtp.py`: declares
  `speculative_sampled_mode_supported = False`. The merged planner routes
  temperature rows through `processed` for this provider because it serves
  them from its own verifier; removing the declaration fails five tests in
  `tests/test_unit_qwen4exp_mtp_streaming.py` and
  `tests/test_unit_server_composite_cancellation.py`, so the flag is load
  bearing rather than cosmetic.
- `benchmarks/README.md` / `benchmarks/HISTORY.md`: the union scoreboard was
  270,409 bytes / 4,121 lines / 303 `results/` links, over the compactness
  contract enforced by
  `tests/test_integration_benchmark_readme_sync.py` (< 200,000 bytes,
  < 3,000 lines, < 300 links). Moved, verbatim, to HISTORY.md: the dated
  2026-09 MTP/prefix/workspace notes, the superseded Gemma 4 checkpoint
  ladders, and the detailed cross-engine prefill screens. The scoreboard now
  measures 196,717 bytes / 2,972 lines / 258 links and keeps both sides'
  current rows and evidence links; `scripts/sync_benchmark_readme.py
  --check` passes.
- `tests/test_gpu_qwen4exp_q4_iu8_j32_tile.py`: five H2D uploads passed an
  inline `host_array_ptr(np.zeros(1, dtype=np.int32))` temporary. Main's
  device-memory hygiene scanner rejects that shape repo-wide, so the calls now
  go through a `_zero_count` helper that binds the host array first. The copy
  is the synchronous `hipMemcpy`, so the old form was not a live
  use-after-free; the helper keeps the scanner's rule unconditional instead of
  carving out an exception.
- Stale-test repairs that both parents failed on this host, inherited by the
  merge rather than caused by it:
  `tests/test_unit_gemma4_assistant_forward_guard.py` asserted the sidecar
  directory is named `MTP`, but the artifact ships flat beside the backbone
  and the resolver accepts both layouts; the assertion now accepts either
  location. `tests/test_unit_vibevoice_tts_diffusion.py` failed on the numpy
  2.5 series. Measured on this host: numpy 2.4.4 and 2.4.6 pass all eight
  nodes, while 2.5.2, 2.5.3 and 2.5.4 all land in the divergent basin (late
  `eps` 0.3655 of peak against the 0.08 bound). The worklog entry
  `20260923T065521.980836Z-lhl-vibevoice-tts-restore-late-gate-88ec6c.md`
  records 2.5.3 as passing, so that row no longer holds for the current
  wheels; the determinant is the numpy minor series, not one release.
  `pyproject.toml`'s `dev` extra now carries `numpy<2.5`, which keeps the test
  environment on the calibrated series. That is a test-environment bound, not
  a runtime constraint: the product path does not use this fixture chain.

### Behaviour the mechanical resolution lost

The first resolution of `hipengine/server/api.py` and
`hipengine/generation/engine_service.py` took `origin/main`'s side of six
behavioural decisions that this branch had already settled. Each is a real
defect, not a stale test, and each was reproduced against a clean `HEAD`
worktree before being repaired:

- **Logprobs on the generic speculative route.** The merged
  `_queue_generation` block only kept the batcher for
  `_SPECULATIVE_MTP_BATCH_ROUTE`, so a `logprobs` request on the provider
  route (`speculative: true` with an external provider) fell through to the
  direct autoregressive call and lost its per-token metadata. `HEAD` treats
  every speculative route as batcher-only; the merged check is now the same
  three-route set.
- **`_coalesce_stream_logprobs` was dropped.** A byte-level tokenizer
  publishes an incomplete UTF-8 fragment as a chunk with no text. `HEAD` held
  that chunk's `TokenLogprob` and attached it to the character that completes
  next; the merged streamer discarded it, so `token_bytes` for `回答。`
  reconstructed to `\x9e\x94\x82` and could not rebuild the served text. The
  helper is restored and `_LiteralStopStream.feed` now passes a text-less
  chunk through instead of stripping its records.
- **Prepare failures were relabelled.** The blanket
  `except Exception -> ResidentPreparationError` in the resident-prepare phase
  converted `EngineServiceClosed`, `GenerationAdmissionRejected` and plain
  server faults into `503 resident_prepare_failed`, hiding the typed code each
  one already had. The phase now logs the operator remedy and re-raises;
  `MemoryAdmissionRefused` also keeps its `insufficient_memory` code instead
  of being caught by the `MemoryError` clause it subclasses.
- **`service_health()["failure"]` named the wrapper.** A contained device
  fault is reported through `GenerationExecutionFailed`, so a readiness probe
  could not tell a `RuntimeError` from a HIP fault. The field now reports the
  wrapper's `cause_type`.
- **Explicit MTP after an operator rollback.** `origin/main` refuses an
  explicit `speculative_mtp` request with the typed rollback reason and keeps
  the AR fallback only for automatic intent. That contract is newer and
  stricter than this branch's silent fallback, so the branch's test now
  asserts the typed `503` and that neither the AR nor the speculative call
  ran.
- **`_QueuedGeneration` field name.** The merged class uses `origin/main`'s
  `thinking_policy`; the branch's coalescing test still passed
  `mtp_thinking_policy`.
