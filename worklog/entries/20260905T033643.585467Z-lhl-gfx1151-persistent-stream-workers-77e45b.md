# Reject persistent streamed workers on gfx1151

## Summary

Rejected persistent streamed workers for the shared GGUF model loop. The live
gfx1151 Qwen3.8 C8/K3 staged-server route constructs no generation-side thread
pools, so the source-audit candidate has no product owner to optimize. The three
`ThreadPoolExecutor` sites are confined to direct compatibility/control loops.

A temporary reusable-pool diagnostic did identify real HIP thread-local startup
cost in the legacy Qwen3.6 MoE draft sub-window, but complete call and cycle
walls each won only two of four counterbalanced pairs. This does not satisfy the
complete-server/load retention gate, and adding long-lived worker/context/
environment lifecycle to the product loop would optimize an oracle path rather
than serving.

## Changes

- Added the compact rejected-decision artifact
  `benchmarks/results/2026-09-05-gfx1151-persistent-stream-workers-rejected.json`.
- Updated the gfx1100 audit handoff to exclude persistent workers from the
  transfer packet unless W7900 profiling changes the live-owner premise.
- Made no runtime change. Existing per-call pools remain inside the direct
  controls covered by the GGUF duplicate-loop refactor entry.

## Validation

- Source inventory found exactly three product-tree `ThreadPoolExecutor` call
  sites, all in `hipengine/generation/qwen35_gguf.py` direct control helpers.
- A traced one-prompt Qwen3.8 C8/K3 production server diagnostic engaged MTP,
  remained AR-equal and self-exact, drained tracked memory to zero, and recorded
  four HTTP-harness pools but zero generation pools.
- A direct dense Qwen3.8 C8 control generated eight exact 24-token rows and also
  recorded zero pools.
- A cached direct Qwen3.6 MoE C8 control generated eight exact 24-token rows and
  recorded eight eight-worker draft pools plus eight two-worker verifier pools.
  Its measured eight-cycle wall was 1,491.917 ms.
- A direct Qwen3.6 MoE C9 packed-AR control generated nine exact eight-token rows
  and recorded seven two-worker pools.
- Five trials of 200 no-op cycles estimated median reusable-pool savings of
  0.023/0.048/0.067 ms for 2/4/8 workers. The C8 draft-plus-verify estimate is
  0.725 ms over eight cycles, 0.049% of the measured legacy cycle wall.
- The out-of-tree MoE C8 A/B used one warmup per arm and measured
  control/candidate/candidate/control/control/candidate/candidate/control.
  Complete call medians were 2,131.774/2,086.919 ms, but only 2/4 matched pairs
  won. Draft-stream medians were 329.990/323.317 ms and won 4/4; verifier and
  complete-cycle walls won only 2/4. Every generated-ID hash matched, and pool
  shutdown plus model close returned the process to `MainThread` only.
- A live Qwen3.6 MoE C8 reachability trace failed before decode with
  `MoE MTP2 prefill lost its target-hidden sink`. Disabling the final-output-mask
  capability produced the same failure, ruling out the 2026-09-05 mask as its
  cause. This pre-existing/out-of-scope limitation did not create a generation
  pool before failure.
