# current server attribution separates C1 kernels from C2-C3 admission

## Summary

Two independent current-HEAD, production, full-suite C1-C3 one-token packets
resolve the apparent conflict between “~97% WMMA” and “~0.4 s non-kernel.” Both
were overgeneralizations. C1 is genuinely native-prefill dominated: the complete
synchronized native call is **268.3 ms / 298.4 ms (89.9%)**, render is zero,
tokenize plus admission preparation is under 1 ms, and only 29.7 ms remains.
That supports kernel work at C1, while preserving the distinction between a
native-call timer and the prior rocprof kernel-family accounting.

C2/C3 expose a different owner. The explicit-AR benchmark arm sets
`speculative_mtp=false`, so the server launches every request as an independent
queue item. Despite a 20 ms batch window, all 40 C2/C3 queue shapes report
`request_count=1`; EngineService admission then races. Across both packets only
**5/20 C2 waves** formed one size-2 native group. C3 formed **5/20 size-3** groups
and **15/20 size-2** groups, leaving one request's prefill serialized. The large
“remaining” interval is therefore earlier serialized model work, not measured
CPU overhead.

The omitted-request automatic arm is a causal control. Its policy declines MTP
(`resident_capacity_not_qualified`), executes the same exact default/K0 backend,
and produces identical IDs, but the server first queues the whole wave. It forms
full groups **20/20 at C2 and C3**, is stable to 1.07%/1.47%, and measures
**259.3 / 344.4 prompt tok/s**, or **1.082x / 1.329x** the strongest peer. No MTP
cycle ran. Thus C2/C3 should fix admission coalescing before kernel work; C1
remains a native-prefill kernel target.
