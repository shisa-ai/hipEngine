# Close SPECDEC2-PERF P4 device cycle

## Summary

Close SPECDEC2-PERF P4 on stable `gfx1151` with a retained C1 graph/device
cycle and a mechanically closed but performance-blocked physical C2/C4 device
boundary. Proposal IDs now remain on device through target embedding; compact
target results feed GPU acceptance; selected target hidden/Conv/GDN/KV and
provider repair/commit execute before one bounded final-result readback. CPU
acceptance is an opt-in qualification oracle rather than a production boundary.

Canonical strict C1/K2 full-suite throughput is **15.732 tok/s versus 10.913
true AR (1.442x)**; all four categories improve. Physical C2/C4 is exact and
allocation/copy clean but remains **5.618/9.183 tok/s versus 15.530/28.766 true
AR** because only **18.43%** of candidates are accepted. P4 therefore closes the
structural boundary without promoting physical performance or automatic policy;
K0 remains automatic/product.

## Changes

- Enable staged C1 proposal graph ownership and N2 target→accept→selected-commit
  graph replay with dynamic device metadata.
- Add physical GPU accept/compact-result, selected-state commit, provider device
  repair, device output, and bounded final readback.
- Add stable C2/C4 target/accept/output slabs and preserve transaction/generation
  identities through device descriptors.
- Own N2 linear-state commit pointer tables per graph rather than allowing
  session-shared table mutation.
- Keep one-slot packed-prefill state import on the strict per-layer D2D fallback;
  repeated gfx1151 single-slot pointer-table imports faulted despite live,
  in-bounds operands. C2/C4 multi-slot imports retain fused/chunked ownership.
- Close all P4.1-P4.3 checkboxes in `docs/SPECDEC2-PERF.md` and publish the
  compact artifact/rollup/changelog.

## Validation

- host `gfx1151`, AMD Radeon 8060S Graphics, `hip_gfx1151`;
- Qwen3.8-27B GGUF `Q4_K_S`, BF16 KV, strict FP32 recurrent state;

  counterbalanced runs, true no-MTP AR denominator;

Retained full-suite results:

- C1: **30/30 exact**, 272 graph cycles, acceptance histogram
  `{0:35,1:41,2:196}`, acceptance **433/538 = 80.48%**, **15.732 vs 10.913
  tok/s (1.442x)**; category speedups code/general-en/general-ja/mixed
  **1.457/1.452/1.423/1.420x**.

  **366/1,986 = 18.43%**, **5.618 vs 15.530 tok/s (0.362x)**.
- C4: **30/30 exact**, 2,040 eager physical cycles, acceptance
  **732/3,972 = 18.43%**, **9.183 vs 28.766 tok/s (0.319x)**.
- All C1/C2/C4 K1-K3 oracle corners pass; observed trajectories cover reject,
  partial, and full acceptance. Zero recoverable failures and zero candidate D2H.
- Every full-suite physical and C1 cycle allocation sample is zero. Every load
  closes to zero active allocations/current bytes with total allocated == freed.
