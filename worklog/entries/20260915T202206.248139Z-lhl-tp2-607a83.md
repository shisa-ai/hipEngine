# tp2 sharded output head: -3.2% decode p50, bit-identical gates

## Summary

Packet 3's remaining decision item - "measure head cost, shard the
vocabulary only if worthwhile" - is decided YES for the Qwen3.8-27B artifact:
the head is the single largest per-token weight read (248,320 x 5,120 Q6_K =
1.04 GB), measured at ~0.5-0.7 ms/token of the 24.87 ms wall. The sharded
head (`head_shard`, now the tp2 production default; `head_shard=False` is the
explicit opt-out and bisection control) splits the head's vocabulary rows
into contiguous Q6_K block-aligned ranges (485 blocks = 124,160 rows per
rank), and both ranks run their shard GEMV concurrently in the tail; the
host reads both f32 rows and takes the concatenated argmax.

Exactness: the head GEMV is row-independent, so per-rank row shards produce
bit-identical logit values to the replicated head, and the concatenated
argmax keeps the replicated head's first-maximum global tie-break. The
split geometry is derived from the engine's own materialization plan (layout
`gguf_q6_k_t16_qmicro_planar_v1` at this artifact - never guessed), must be
a whole number of 256-value blocks, and the shard row count must be a
multiple of the t16 16-row tile. Each rank's runner defers the replicated
head allocation (`deferred_device_slots`), freeing 1.04 GB per group and
improving the XTX's headroom.

## Changes

- `hipengine/distributed/head_shard.py`: the head split plan and
  materializer (block-aligned contiguous row ranges, layout from the
  engine's own materialization plan, t16 repack per rank).
- `hipengine/distributed/tp2_generate.py`: `head_shard` knob (tp2 default
  on), per-rank shard build with replica deferral, sharded tail with the
  concatenated exact argmax, teardown.
- `hipengine/runtime/qwen35_gguf_runner.py`: generic `deferred_device_slots`
  pass-through.
- `hipengine/core/memory.py`: 256 MiB-bounded synchronous H2D chunks.
- Tests: head-shard plan geometry units, session wiring units, fake-env
  copy fix; `scripts/tp2_mlp_generate_e2e.py --head-shard/--no-head-shard`.

## Validation

- CPU units: plan geometry (block alignment, byte counts, row ranges,
  refusals for unsplittable/unaligned geometry), session wiring (per-rank
  shard uploads from the resolved layout, replica deferral, both ranks'
  tail GEMVs, concatenated argmax with the exact tie-break, teardown).
- Full-model e2e (W7900 + RX 7900 XTX, fingerprint a0b9749e2d7b): teacher
  gates identical to the replicated-head run to all recorded digits (mean
  KL 3.945e-04, max KL 2.365e-03, top-1 100% vs both TP1 controls); TP2
  repeat bit-exact. Decode p50 median 24.887 -> 24.081 ms/token (-3.2%);
  the head stage's summed cost roughly halved (0.033-0.046 -> 0.019-0.027 s
  per arm), matching the design.
- A standalone-launch probe (shard GEMV outside a runner session) produced
  NaNs on device 0 with the same dispatch key; the launch depends on runner
  session state, so validation was done through the real runner per the
  standing guidance. The probe is not retained as evidence.

## Notes

- The unit-test fake env initially copied queued full-width rows with the
  row's own width instead of the requested byte count; with two half-buffer
  readbacks per step that overflowed the destination and corrupted the host
  heap (pytest GC segfault). The fake now honors `nbytes` like the real
  `copy_device_to_host` API, and `queue_logits` queues proper per-rank
  halves.
- `copy_host_to_device` now bounds synchronous H2D chunks at 256 MiB: the
  driver hard-aborts (not an error code) on multi-100MB single copies, and
  the resident head upload crosses that threshold.
- Remaining wall is ~24.1 ms/token, ~2.2 ms/token faster than the matched
  XTX TP1 control (26.3) at this workload.
