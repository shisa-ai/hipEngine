# Qualify YuE2 inference on gfx1100

## Summary

YuE2 inference runs correctly on `gfx1100`. Every YuE2 correctness gate passes
against the same committed fixtures that were recorded on `gfx1151`, and the
product path generates audio unassisted through `LLM.generate_song()` and
`POST /v1/audio/songs` with no torch in the process. The checkpoints were
downloaded at the pinned revisions and their payloads verify against their
`weights_manifest.json` hashes. This closes the correctness, capacity, and
product half of M8 for the default claim hardware; the held-out task-quality
suite and a matched reference arm were not run, so no quality-equivalence or
speed-ratio claim is made.

Host: `epyc`, AMD Ryzen 9 5950X, Radeon Pro W7900 (96 CU, 48 GB, `gfx1100`),
ROCm 7.2 / HIP 7.2.53211, `backend=hip_gfx1100` selected from `hip_arch` with
`backend="auto"`. Checkpoints `m-a-p/YuE2-3B@29b3558` (`model.safetensors`
sha256 `1d55c42c…`) and `m-a-p/YuE2-Vae@9a94e1d`.

## Changes

- Fixed `scripts/yue2_session_gate.py`, which could no longer run. It built
  `Yue2ArRuntime(weights, branches=2)` at the runtime's own 4 096-position
  default while the committed greedy fixtures request the product's 4 096-token
  ABC budget behind a 109-token prefix, so `generate_tokens` refused the request
  by name (`109 + 4096 > 4096`). The gate now builds the runtime at
  `DEFAULT_AR_CONTEXT` (16 000), the context the song pipeline allocates. The
  check that refused it is the product fix from `bda73bef7`; the stale gate, not
  the check, was the defect, and it was host-independent (pure Python
  validation), so this was not a gfx1100 finding.
- Added the eight gate/product artifacts under `benchmarks/results/` and the
  gfx1100 rows in `benchmarks/README.md`, `benchmarks/CHANGELOG.md`,
  `docs/MODELS.md`, and `docs/model-cards/MODEL-YUE2.md`.

No kernel, runtime, or loader change was needed for `gfx1100`. The YuE2 kernels
live under `hip_gfx1100/` and were already the code path both RDNA3 backends
compile; nothing on this host required a new variant.

→ **338 passed, 0 skipped**. `uv run pytest tests/ -k yue2` → 303 collected,
exit 0 (the only skips are two unrelated `qwen38_dms` torch-guard modules).

Stage times from the repeat: semantic **69.56 s** (1 863 tokens, 26.8 tok/s,
37.3 ms/token), acoustic solver **12.56 s** (6.75 ms/frame), FP32 Oobleck decode
**8.22 s** (4.41 ms/frame). Audio was finite, 100% non-silent, RMS 0.156, and
neither phase truncated. `session.ar.runtime.backend` and the NAR kernel
namespace both report `hip_gfx1100`; `torch` was never imported.

Server: `hipengine serve --model … --vae-model …` built the song pipeline in
**27.5 s** with a **13.23 GiB** peak device allocation of 44.98 GiB, answered
`/ready` 200, and served `POST /v1/audio/songs` (`cot="off"`, `steps=8`) as a
200 with the identity/frames/duration headers and a 23.5 MB, 48 kHz stereo WAV:
3 065 frames, 122.599 s of audio, 176.04 s of generation, peak 1.0 at the signed
16-bit serialization boundary, RMS 0.1416, 99.35% non-silent, channel
correlation 0.84.

The hipBLASLt selection transfers. `scripts/hipblaslt_algo_scan.py` on this
device returns `FAST_ALGORITHM_INDEX = 4` as fastest for all four YuE2 solver
shapes (0.105-0.507 ms, 51.9-73.4 TFLOP/s), 4.5-6.4x faster than index 0, so
the fixed index chosen on `gfx1151` is not a gfx1100 penalty.

Not run: the held-out task-quality suite (lyric adherence, blinded listening)
and any matched reference arm. There is no torch oracle on this host, so the
numbers above are absolute gfx1100 measurements and no gfx1100 speed ratio
against the reference is claimed. Per-unit-work rates against the gfx1151
reference comparison from M7 (AR 37.3 ms/token here, solver 6.75 ms/frame,
decoder 4.41 ms/frame) are a cross-host observation, not a same-host ratio.
