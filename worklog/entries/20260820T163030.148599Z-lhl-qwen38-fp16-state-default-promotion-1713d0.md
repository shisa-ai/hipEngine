# Promote gfx1151 Qwen3.8 FP16 recurrent state by default

## Summary

Promoted FP16 recurrent-state storage as the scoped legacy default for
Qwen3.8-27B Q4_K_S on gfx1151 after removal of the fixed magnitude threshold.
The scope matches the complete retained evidence; Q4_K_M, gfx1100, and other
file types remain FP32 by default. An explicit environment value always wins,
so `HIPENGINE_GGUF_FP16_RECURRENT_STATE=0` is the strict-storage rollback.

## Changes

- Added gfx1151 backend capability
  `GGUF_FP16_RECURRENT_STATE_DEFAULT_FILE_TYPES={"mostly_q4_k_s"}`.
- Reworked frozen dtype resolution so the runner resolves backend first,
  materializes/discovers the GGUF file type, then freezes the allocation ABI
  before any recurrent session/scratch allocation.
- Kept explicit `=0`/`=1` override semantics and all chain-journal/MTP
  fail-closed guards.
- Added default-scope/rollback RED plus real no-env/opt-out/forced-on Qwen3.8
  packed prefill/decode coverage. Documented the environment in `docs/ENVS.md`.
- Updated the stale gfx1151 GDN-plan resolution count from 32 to 35; the three
  new registered compact/FP16 plan members predate this unit and the old count
  was no longer accurate.
