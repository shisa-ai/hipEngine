# profile-env restore aborts the all suite: latent order-dependent GPU corruption

## Summary

A test-only isolation fix that restored the profile-bound env vars to their
collection-time baseline after each test made `pytest --suite all`
**deterministically abort** (SIGABRT, exit 134) at node 4267 of 19131
(`tests/test_gpu_qwen35_paged_kv_head_major.py::test_paged_bf16_head_major_copy_matches_permuted_numpy_oracle[1]`,
inside `hipengine/core/hip.py:114 memcpy`). The fix is reverted here. What it
surfaced is a real, still-unfixed defect: with the profile env vars at
baseline, some test earlier in the prefix leaves the device in a state that
aborts a later device memcpy. The env leak the fix removed was masking it.

## Changes

- `tests/conftest.py` restored to its pre-`b4f128d16` content (the 45-line
  profile-env restore in `pytest_runtest_teardown` is removed). The pre-existing
  kernel-registry and runtime-profile-registry restores are untouched.
- No production code changed. `b4f128d16` remains in history; this entry
  supersedes its effect.

## Validation

A/B on one machine, same interpreter (`python3` = miniforge3, pytest 8,
`torch 2.13.0+rocm10.0.0`), same explicit 4267-node prefix, same
`--suite all` config:

- With the restore (`b4f128d16`, worktree `hipEngine-main`): `PREFIX=134`,
  one `Fatal Python error: Aborted` at the memcpy above. Reproduced twice
  (full-suite run, then prefix replay).
- Without the restore (worktree at `d83289a7b`, differing from `b4f128d16`
  in `tests/conftest.py` only): `PREFIX_PRE=1`, no abort, two ordinary
  failures (`test_gpu_device_memory_hygiene.py::test_unpinned_h2d_source_is_never_an_inline_temporary`,
  `test_gpu_qwen35_gguf_gdn_prefill_correctness.py::test_gdn_prefill_paths_match_cpu_oracle_qwen36_shape`).
- Confounders ruled out: `LD_LIBRARY_PATH` is byte-identical under plain
  `python3` and `uv run` (both resolve miniforge3's pip `_rocm_sdk_*`), and
  `.venv` contains neither pytest, torch, nor ROCm libs, so `uv run pytest`
  was executing miniforge3's pytest all along. The crashing test file has no
  torch usage, is untouched by this line, and passes in isolation.
- Not the trigger: the crashing test alone passes; the GDN prefill
  correctness file alone passes (`EXIT=0`); the abort needs the prefix.

Prefix reproduction (from repo root):

```bash
python3 -m pytest --suite all --collect-only 2>/dev/null | grep "::" > /tmp/nodes.txt
idx=$(grep -n "test_paged_bf16_head_major_copy_matches_permuted_numpy_oracle" /tmp/nodes.txt | head -1 | cut -d: -f1)
head -$idx /tmp/nodes.txt > /tmp/prefix_nodes.txt
mapfile -t nodes < /tmp/prefix_nodes.txt
python3 -m pytest -q --suite all "${nodes[@]}"
```

`mapfile` is required: parametrized node ids contain spaces, so `$(cat ...)`
splits them and pytest exits 4 without running anything.
