# Gemma 4: give the windowed path an independent oracle at the gate shape

## Summary

Punchlist V2 asked for an independent oracle because every gate so far compares
two hipEngine arms against a captured baseline, and V5 spelled out the
consequence: "both are hipEngine arms, so a shared wrong mask is invisible."
The row offered two options — score 4096-token prefill logits against
llama.cpp's, or add a naive CPU reference for windowed attention.

The naive reference turned out to be mostly *built* already, which is why the
row's status was stale rather than its intent. The pieces that existed:

- `hipengine/kernels/cpu_reference/gemma4.py` implements the mask
  (`gemma4_attention_mask`: `key <= query` plus `key > query - window`) and the
  forward pass, and `tests/test_unit_gemma4_keep_mask_reference.py` pins the
  production builder against it, including the exclusive bound at `q - k == W`.
- `tests/test_unit_gemma4_attention_flash_admission.py` closes the *routing*
  seam: `aotriton_prefill_admits` returns False the moment `keys >
  sliding_window` (1024 admits, 1025 does not, 7777 does not), and the flash
  kernel reads no mask at all. So a binding window always reaches the exact
  kernel that reads `keep_mask`, and a vacuous one reaches flash where causal
  and causal+window are identical.
- `13564b97d` added
  `test_attention_prefill_matches_the_reference_through_the_production_mask`,
  which runs production `_keep_mask` through the HIP kernel into numpy.

**The hole was scale.** That composition test runs `head_dim=16`, at most six
rows, and a four-token window. The failure modes V2 exists to catch — the
pass-1 skip over fully-masked key tiles that V3 discovered, and the window
bound applied across a key walk thousands of tiles long — cannot appear at
that size, and the production dispatch had never been exercised at the geometry
V1 actually gates.

`test_windowed_attention_matches_the_reference_at_the_gate_shape` closes it at
`start=3584 rows=512 keys=4096`, the last block of a 4096-token prefill, in
both layer classes: sliding (`head_dim` 256, window 1024, where the window
binds — row 0 sees exactly 1024 of 4096 columns and no row exceeds `window`)
and global (`head_dim` 512, `sliding_window=None`, where the assertion is the
opposite — `max(axis=1) == keys`, so no window leaks into a layer that declares
none). Both agree with the numpy reference at `atol=rtol=1e-5`.

A defect fell out of the same read: three attention tests in that file built
device allocations through `_Device()` with no `@_needs_hip` marker. The
session-level guard in `tests/conftest.py` only fires for tests requesting the
`hip_test_target_arch` fixture, which none of them do, so a no-ROCm runner
would error them instead of skipping — the exact failure AGENTS.md's guard rule
exists to prevent. All three now carry the marker.

Two wrong assertions were written and corrected before the test was right,
worth recording because both were confident and both were backwards: the
window's visible span is `(start - window, start]`, not `[:window]`, and a
query's own key sits at column `start + i`, not `i`, because the mask spans the
whole cached range rather than the block.
