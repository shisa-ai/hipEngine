# D6 norm fusion: tail fold lands, stream-aware grouping

## Summary

Punchlist D6 (norm family, 301 launches/token, ~1.55 ms) went through three
stages: census-driven analysis, a RED/GREEN bit-exact fold, and a same-lane
measurement. The row's proposed grouping did not survive the layer composer:
the "three normalizations reading one input" triple was already a pair (D5
folded the weightless router norm into `router_topk_fused`), and the surviving
pair is **cross-stream** — `pre_ffw_norm` on the main stream,
`pre_ffw_norm_2` on `moe_stream` — so fusing it costs a moved entry event and
nets ~2-3 µs/layer; the better design (carry pre2's weighted output inside
`router_topk_fused`, which already computes the identical `inv_rms` from the
same input) is recorded for a follow-up iteration. The tail chain
`post_ffw_norm_1 -> branch_add -> add_rmsnorm_scale` IS strictly sequential
with single-consumer intermediates, and that is what landed:
`gemma4_dense_combine_rmsnorm_scale_bf16` computes all three stages in one
256-thread block, with every intermediate passing through the chain's exact
bf16 rounding and every reduction keeping its own tree. Measured: decode norm
301 -> 271 launches and 1.5552 -> 1.5159 ms/token at 1024, decode device busy
-0.65%, prefill busy -1.5/-6.9 ms; topline flat inside sample noise (the
honest reading of a sub-1% busy move). Arithmetic is bit-identical everywhere,
so no promotion gate applies.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_norm.hip`:
  - `gemma4_multi_rmsnorm_kernel` + `hipengine_gemma4_multi_rmsnorm_bf16` —
    up to three outputs in one launch (count 1..3, null weight = weightless
    expression); each output's reduction tree and write expression mirror its
    standalone kernel, and the trailing `__syncthreads()` fences `partial[]`
    between outputs.
  - `gemma4_dense_combine_rmsnorm_scale_kernel` +
    `hipengine_gemma4_dense_combine_rmsnorm_scale_bf16` — the tail fold.
    Stage 1 normalizes dense (post_ffw_norm_1); stage 2 re-quantizes
    `dense_norm` to bf16, adds experts and re-quantizes the sum exactly as
    `branch_add` would, accumulating the tail sumsq over those rounded values
    in the stride `add_rmsnorm_scale` uses; stage 3 applies
    `(residual + normed) * layer_scalar` in place. A `__syncthreads()` after
    `inv_rms1` fences the shared reduction buffer.

    stray `eps, hidden_size); return ...; }` fragment after the
    `add_rmsnorm_scale` launcher; removed before any build.
