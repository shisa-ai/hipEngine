# Retain singleton and packed target ownership specializations

## Summary

Close R0402 by retaining singleton/session-local and packed/physical target
verifiers as supported specializations. No dispatch or arithmetic changed.

## Changes

- Document the independent provider and target ownership boundaries at
  `_ensure_active_singleton_target_verifier` and `_execute_target_frontier_batch`
  in `hipengine/generation/qwen35_gguf_mtp2.py`.
- A lone non-physical-C1 request owns its session-local transactional verifier,
  graph buckets and selected-row commit/rollback lifetime. Physical groups,
  including admitted physical C1, use the packed target owner. Request-state
  retirement owns singleton teardown; no verifier is shared between requests.
- Preserve backend capabilities, sampled acceptance, DMS, cancellation and
  nonzero resident-slot survivors. Remove the completed duplication entry from
  `docs/REFACTOR.md`; mark the durable checklist row completed.
- Convergence is not required. A future convergence proposal must add packed
  graph capture and a matched public C1 route comparison before removing the
  singleton specialization. The server benchmark does not provide that A/B.
