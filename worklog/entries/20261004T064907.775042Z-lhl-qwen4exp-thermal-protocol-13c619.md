# Sustained load throttles gfx1151 to ~60% prefill; the fair llama.cpp basis is 0.68x prefill and 0.80-0.96x decode

## Summary

Two methodology findings, both measured, neither an engine change. **No kernel,
default, flag or dispatch changed and no metric row moved.**

1. **Sustained load thermally throttles this host, and any long in-process
   suite measures the throttle rather than the engine.** The APU reaches
   **98 °C** and loses roughly **40% of prefill throughput**, cooling 98 -> 39 °C
   in about two minutes. Inside one 12-case suite run, decode falls **17.68 ->
   10.14 tok/s** on the same case mix minutes apart. Temperature alone is not
   the trigger: three consecutive single-case processes at 48-54 °C are
   indistinguishable (prefill 269.66 / 270.45 / 270.97, decode 17.46 / 17.48 /
   17.45). A separate, smaller in-process effect costs **~9% of prefill** after
   eight passes and does not touch decode.
2. **The campaign's llama.cpp reference row does not reproduce, and the real
   gap is far smaller than the gufo comparison suggested.** The ledger's
   `6011c34ce` row (321.3 / 415.1 / 459.0) is not present in the local checkout;
   the HIP build is `002a12ad2`. Measured under one protocol, one shape per
   process: **llama.cpp 385.97 / 421.60 / 421.87 prefill and 21.85 / 22.04 /
   21.89 decode at p512 / 1K / 4K, against hipEngine 264.0 / 287.2 / 295.0 and
   20.98 / 19.40 / 17.40**. That is **0.68-0.70x prefill and 0.80-0.96x
   decode** - a completely different campaign from the 5.78x gap to gufo, which
   is not llama.cpp and is not what the objective names first.

**The most actionable result is the decode trend.** llama.cpp's decode is
**flat** across context (21.85 / 22.04 / 21.89) while hipEngine's falls **17%**
(20.98 -> 19.40 -> 17.40). All six hipEngine rows sit in the same 48-56 °C band,
so this is context-driven, not thermal. Decode is **0.96x at 512, 0.88x at 1K,
0.80x at 4K** - essentially matched at 512 and falling with every token of
context, which is exactly the wrong direction for the objective's 8K-256K
stages.

## Changes

No code changed. This entry records a measurement protocol and the baseline it
produces.

### The throttle

Inside one suite run (chunk 1024, one process, warmup + 3 repetitions per case,
fixture order):

| sample | case | prefill tok/s | decode tok/s |
| --- | --- | ---: | ---: |
| `[measure 0]` | code-p512 | 264.88 | **20.98** |
| `[measure 0]` | code-p1024 | 262.09 | 19.46 |
| `[measure 1]` | code-p4096 | 249.14 | **17.68** |
| `[measure 1]` | mixed_ja_en-p4096 | 249.55 | **13.79** |
| `[measure 2]` | code-p4096 | 248.26 | **12.42** |
| `[measure 2]` | general_ja-p4096 | 254.19 | **10.14** |

The step is abrupt and lands mid-run. The APU was at 98 °C when the run was
stopped; load average was 2.36 with no competing process, so this is thermal
and not contention.

Three single-case processes, each ~90 s, starting at 39-48 °C and ending at
53-54 °C, show no such effect - so the trigger is sustained load, not the
temperature at which a measurement starts.

### The in-process prefill loss

| case | inside the suite | fresh process | ratio |
| --- | ---: | ---: | ---: |
| code-p512 | 264.88 | 264.0 | 1.00 |
| code-p1024 | 262.09 | **287.24** | 0.91 |
| code-p4096 | 249.17 | **270.69** | 0.92 |

Prefill moves and decode does not, which is the signature of a
bandwidth-hungry phase losing memory throughput rather than a latency-bound
one. **That mechanism is an inference and is not established here** - no
per-domain thermal or clock telemetry was captured.

### The fair llama.cpp basis

`llama-bench -ngl 999 -fa 1 -r 3`, one shape per process, cooldown to <= 50 °C,
same host and same model file:

| shape | llama.cpp `002a12ad2` | hipEngine | ratio |
| --- | ---: | ---: | ---: |
| pp512 | 385.97 ± 43.58 | 264.0 | 0.684x |
| pp1024 | 421.60 ± 1.41 | 287.2 | 0.681x |
| pp4096 | 421.87 ± 2.85 | 295.0 (chunk 4096) | 0.699x |
| tg128 at p512 | 21.85 ± 0.12 | 20.98 | 0.960x |
| tg128 at p1024 | 22.04 ± 0.07 | 19.40 | 0.880x |
| tg128 at p4096 | 21.89 ± 0.14 | 17.40 | 0.795x |

llama.cpp's pp512 spread is 11% over three repetitions, the same instability
this host shows elsewhere; pp1024 and pp4096 are tight.

### The chunk effect is shape-dependent

| case | smaller chunk | larger chunk | delta |
| --- | ---: | ---: | ---: |
| code-p512 | 265.18 (512) | 263.89 (1024) | -0.5% |
| code-p1024 | 287.24 (1024) | 286.94 (2048) | -0.1% |
| code-p4096 | 270.69 (1024) | 295.01 (4096) | **+9.0%** |

A blanket larger chunk is not a win and neither is a blanket smaller one; the
gain appears only when the chunk covers the whole prompt. This supersedes the
chunk sweep in `20261004T020800.274714Z`, whose arms ran against a different
code tree.

## Validation

- Thermal evidence: one 12-case suite run at HEAD, logged in full, with the
  step change located by sample index; APU temperature and `power1_average`
  read from `/sys/class/drm/card1/device/hwmon/hwmon6/`; load average checked
  to exclude contention.
- Hot-demo control: three consecutive single-case processes with start and end
  temperatures recorded, all within 1% of each other.
- hipEngine baseline: six configurations, one case per process, cooldown to
  <= 50 °C before each, warmup + 3 repetitions, `uv run`,
  `--require-cached-build`, start and end temperatures recorded for each.
- llama.cpp: three shapes, one per process, same cooldown discipline, three
  repetitions, build string recorded (`002a12ad2`).
- All raw logs and artifact JSON under
  `benchmarks/results/2026-10-04-qwen4exp-thermal-protocol-and-llamacpp-basis/`.

## Limits

- One host (`gfx1151`, machine-id `55ea6c509d0b49eea8de7094a1023668`), one
  model file, one quant, one execution profile, one category (`code`) per
  shape.
- The llama.cpp rows are one build (`002a12ad2`), **not** the ledger's
  `6011c34ce`, and `llama-bench` and the hipEngine harness share neither
  tokenizer nor prompt, so this is same-shape rather than same-prompt.
- Temperature is `temp1_input` only. No per-domain thermal or clock telemetry,
  so the mechanism behind the ~9% in-process prefill loss is inferred from
  which metric moves.
- The -0.5% and -0.1% chunk deltas are at or below the arms' within-run spread
  and are reported as "no gain", not as regressions.
- hipEngine's decode rows at p1024 and p4096 carry an unexplained
  first-repetition outlier (20.22 then 19.51 / 19.40); the median is quoted.
- Whether the 98 °C throttle would also hit a differently-cooled host, or a
  gfx1100 W7900, is unknown.
