# Screen exact greedy sampling after Inkling logit softcap

## Summary

The current Inkling head applies a model-declared soft cap before host sampling. Raw GPU argmax is not an exact replacement, because the cap can turn unequal FP32 inputs into an equal capped pair and change the lowest-ID winner.

## Changes

- No runtime changes. Screened the exactness premise and instrumented the existing streamed route to measure host selection independently of the head projection. The instrumentation compares the raw argmax with the actual selected token but does not affect sampling.

## Validation

- The pinned Loom checkpoint declares `final_logit_softcapping=30`. With raw FP32 logits `[60.0, 60.000003814697266]`, `30 * np.tanh(raw / 30)` returns two copies of `28.920827865600586`: raw `argmax` returns ID 1, while the existing sampler returns ID 0. The existing GPU soft-cap implementation also documents independent `tanhf` rounding against NumPy.
- `python -u ./hipengine_inkling_sampler_screen.py "$model" "$backend"` ran the public stream with 47, 151, and 575 input tokens and 48 generated tokens each, greedy, no prefix reuse or drafting, hipEngine `b84972617`, FP32 KV. On the pinned Loom Q4_K_XL and Strix Halo Radeon 8060S (`gfx1151`), median host `select_token` time per cell was 304–332 microseconds. On mainline Q4_K_M and Radeon Pro W7900 (`gfx1100`), it was 240–283 microseconds. Timing excludes the head projection and copy, soft-cap calculation, and instrumentation. No capped ties or raw/capped winner differences occurred in the 144 sampled rows per checkpoint; that observation does not invalidate the constructed tie. Logs: `/tmp/kendex-pi-bg/bg-47-1795319039089.log` and `/tmp/kendex-pi-bg/bg-48-1795319039102.log`.
