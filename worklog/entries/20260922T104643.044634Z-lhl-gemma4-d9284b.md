# Materialize Gemma 4 GGUF tensors into the reference layout

## Summary

Joins the loader's structural contract to the validated NumPy reference forward.
`materialize_gemma4_reference_weights` maps every Gemma 4 GGUF tensor slot onto
the `Gemma4LayerWeights` attribute that consumes it, and converts the GGUF config
into a `Gemma4TextConfig` with real per-layer geometry.

Two conversions are not renames, and both are checked rather than assumed:

- **The fused expert projection is already in the layout the reference wants.**
  `ffn_gate_up_exps.weight` is `(experts, 2 * moe_intermediate, hidden)` with the
  gate in the first half. The reference consumes the same fused layout, so the
  split is a width validation rather than a copy. The first-half-is-gate
  convention was confirmed against `llama-graph.cpp`, which views offset 0 as the
  gate and `n_ff * nb[0]` as up, and against the converter's `modify_tensors`.
- **The per-expert scale is the router's, not the down projection's.**
  `ffn_down_exps.scale` is `router.per_expert_scale`, applied to the expert
  *output* before the routing weight. That matches the reference, which was
  validated against HF at 1e-6. `llama-graph.cpp` applies `down_exps_s` in the
  same place.

A guard that could never fire was removed during this unit. It would have
rejected a `rope_freqs.weight` present on a fully rotated config, but
`has_global_rope_freqs` is itself derived from that tensor, so the branch was
unreachable. The reachable contract — an absent sentinel tensor means the global
layers rotate every pair — is the loader's decision and is now pinned by a test
here instead of duplicated.

## Changes

- `hipengine/loading/gemma4_gguf_materialize.py` (new):
  `gemma4_reference_config_from_gguf`, `split_fused_expert_gate_up`,
  `materialize_gemma4_reference_weights`, and `Gemma4GGUFReferenceWeights`. The
  `tensor_reader` parameter lets a test drive the whole mapping without
  dequantizing a 17 GB file.
- `tests/test_unit_gemma4_gguf_materialize.py` (new): 13 unit tests.

## Validation

```bash
uv run pytest tests/test_unit_gemma4_gguf_materialize.py -q
# 13 passed
```

Every slot is compared value-for-value against the raw dequantized payload read
directly by tensor name, so a mis-wired slot fails even when its shape happens to
match. Also covered: tied embeddings (no `output.weight`), `v_proj` present on
sliding layers and `None` on global ones, the fused expert width check, dual
attention geometry surviving the conversion, a full reference forward on the
materialized fixture weights producing finite softcapped logits, and a narrowed
(`float16`) materialization that still runs.
