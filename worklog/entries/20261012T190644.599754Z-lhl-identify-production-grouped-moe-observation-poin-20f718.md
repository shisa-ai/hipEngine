# Identify production grouped MoE observation point

## Summary

The uncached capture failed its engagement assertion because the production
Q4 path does not use the pair2 `moe_linear` keys that the wrapper instruments.
Source inspection identified the real observation point: the grouped Q4
prefill scheduler builds `group_expert_start`, runs grouped scatter/gather,
then selects `qwen35_moe_mmq32_tile_map`, exact grouped Q4, or T16/WMMA owners.
The tile histogram must be captured from those grouped metadata buffers before
the selected owner launch.

## Changes

- Added the production grouped-MoE observation point to
  `docs/QWEN4EXP-CROSS-ENGINE-GAP-MATRIX.md`.
- Preserved the failed capture artifact as a scope diagnostic; no speed or
  correctness claim is attached to it.

## Validation

- Inspected `hipengine/runtime/qwen4_exp_runner.py` around the grouped Q4
  scheduler and owner selection.
- Confirmed the failed capture completed execution but collected zero records,
  consistent with the wrong wrapper key.

## Next

Add diagnostic-only instrumentation around the grouped scheduler's
`group_expert_start`, `group_wmma_total`, and `group_tile_expert` buffers, then
replay the resulting histogram through the external tile-policy model.
