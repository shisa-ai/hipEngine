# retract the padded gate comparison and fix owner ownership

## Summary

Supersedes the *gate* half of
`20260919T211109.966601Z-lhl-tp2-f16-rocblas-prefill-owner-integrated-but-gat-e41c1f.md`.
That entry concluded the source-F16 prefill owner "fails the gate" and that the
512-row baseline is "numerically broken". **Both conclusions are retracted: the
comparison was invalid.** A reviewer caught it, and it is a real error, not a
presentation problem.

The padded run extended the student prompt to 512 tokens to reach the policy's
admitted row count, but `teacher = arrays[index]` still held logits captured for
the original 52-64 token prompt, and the forced trajectory differed too. The
resulting KL and top-1 numbers compare **different contexts**, not implementation
drift. They neither qualify nor disqualify the owner, and they say nothing about
the 512-row baseline either.

## Changes

- `scripts/tp2_bulk_prefill_diagnostic.py`
  - `--t16-f16-rocblas-prefill default` now maps to `None` (omit the flag) instead
    of `True`. The old mapping made every value except `off` enable a default-off
    candidate, so an explicit `default` silently overrode the safety decision.
  - `--pad-prompt-tokens` retained but documented as **dispatch coverage only**;
    it is not a qualification path, because no matching teacher exists.
- `hipengine/distributed/tp2_generate.py`
  - `_ensure_rank_f16_rocblas_planes` returns immediately when the owner is
    disabled. It previously allocated unconditionally, so the default path paid
    the scratch for a feature it never entered.
  - `_release_rank_f16_rocblas_planes` now calls `Rocblas.close()` per rank under
    that rank's device scope, and continues past a failure so one rank cannot
    strand the other's resources. The handles wrap `rocblas_create_handle` and
    are not destroyed by dropping the reference; the previous code cleared the
    dictionary and leaked one handle per rank per session.
  - The default-off comment now records the candidate as **unqualified**, with
    the retraction, rather than as rejected by a gate.
- `tests/test_unit_tp2_t16_f16_rocblas_prefill_owner.py` - rewritten as
  behavioral tests with mocked device scope, allocator and owner builder.
- `docs/REFACTOR.md` - status is "integrated, unqualified, opt-in"; the gate
  numbers and the "baseline is broken" claim are replaced by the retraction.

## Validation

The three ownership bugs are pinned by tests that were confirmed **RED** against
the pre-fix code (re-introducing them failed exactly
`test_disabled_owner_allocates_nothing`,
`test_cleanup_closes_every_handle_and_releases_every_plane`, and
`test_cleanup_continues_after_a_failing_close`), and GREEN after. 13 pass.

Integrated measurement through the **real flag**, reproducible:

```
python3 scripts/tp2_prefill_context_ab.py --mode owner --arm-b all5 --rounds 4 \
    --json /tmp/owner-ab.json
```

| arm | samples (ms) | median |
| --- | --- | --- |
| owner off | 494.2, 493.7, 494.6, 495.9 | 494.4 |
| owner on | 475.9, 475.5, 476.4, 476.6 | 476.2 |

`+3.83%`, paired deltas +3.835/+3.828/+3.823/+4.055, within-arm drift < 0.35%.

The same run records what each arm actually did, which is the part the previous
entry could not show:

| arm | enabled | planes rows | scratch | owner builds | handles |
| --- | --- | --- | --- | ---: | --- |
| A | False | none | **0.0 MiB/rank** | **0** | none |
| B | True | 512, 512 | 41.0 MiB/rank | **128** | 0, 1 |

`owner_builds` counts contexts that installed an owner, read from the
contextvar, so a fallback is not counted as execution. 128 = 64 layers x 2 ranks.
A first version of this counter reset after the snapshot rather than before the
run and reported 128 builds for the *disabled* arm; that is fixed, and it is why
the numbers are reported per arm here rather than once for the run.

Scratch is **41.0 MiB/rank** measured at rows=512, not the 48 MiB/rank estimated
in the superseded entry.
