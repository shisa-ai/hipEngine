# Preserve DMS INT8 in the public compact serving adapter

## Summary

The public compact DMS adapter now preserves an explicit INT8 codec instead of rejecting it or forcing BF16. The existing INT8 backend, retention policy and arithmetic are unchanged. A public HTTP request completed with compact INT8 diagnostics at a configured context of 262144; this is not a full-depth capacity or numerical-quality measurement.

## Changes

- Allow `int8_per_token_head` alongside BF16 in `LLM(dms=...)` and `ServerConfig(dms=...)`; keep BF16 as the automatic default.
- Bind `DMSConfig.metadata_path` before KV preparation so the existing compact backend factory and FP32 scale policy are selected.
- Avoid duplicate metadata keyword arguments when constructing a compact session and report the actual prepared codec in retention metadata.
- Preserve single-request ownership, prefix-cache exclusion and speculative-serving exclusion.
