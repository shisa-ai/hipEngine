# Size packed prefill scratch for total rows

## Summary

Fixed a packed long-prefill workspace dimension bug exposed by the Qwen3.8
production context gate. The packed scratch allocation used per-slot maximum
sequence length as its total row capacity. A multi-slot/chunk prefill can have
`union_rows > union_max_seq`; c2 4K attempted rows=4096 with capacity=1024 and
failed closed before model work.

## Changes

- Allocate `_GGUFFullAttentionPrefillScratch` with capacity
  `max(union_rows, union_max_seq)`. Packed target state keeps its per-slot
  sequence axis; only scratch backing covers the independent total-row axis.
- Added RED/GREEN coverage for 4,096 packed rows with 1,024 per-slot sequence
  capacity. The test asserts both row and backing capacity.

## Validation

- Actual RED on clean `57f3db690`, gfx1151 Qwen3.8 Q4_K_S FP16 queue2:
  1K initialized, c2 4K returned `capacity 1024 must be >= rows 4096`; the engine
  closed, memory/process ownership recovered, no KFD PID survived.
- Unit RED reproduced `scratch.rows=4096`, `max_positions=1024`.
- GREEN: complete workspace-stability file -> 8 passed; affected packed
  verify/workspace/prefill selection -> 91 passed. Python compilation and
  `git diff --check` pass.
- This is allocation geometry only; no arithmetic, dispatch route, or output
  association changes.
