# Live lifecycle arms for the DMS + INT8 MTP store journal

## Summary

Task #26's four arms are live and green on this host. Each opens a real verify
cycle on a resident DMS+INT8 session -- which appends its rows to the DMS store --
aborts it the way a cancellation, a deadline, or a disconnect aborts one, and
asserts the store came back to exactly its pre-cycle state before a following
cycle commits the autoregressive tokens. **4 passed**, live tier.

## Changes

- `tests/test_live_dms_int8_mtp_lifecycle.py` (new, 4 arms). It reuses the DMS
  parity gate's harness (`_dms_session`, `_prefill`, `_ar_arm`, the category
  prompts and the same constants) rather than building another one.
  - `_store_signature` reads every field the acceptance names: host payload and
    scale planes, positions, live counts, evict mask, range capacity, base
    offsets, extents, the extent pool's and the ledger's own allocator state, and
    the device payload store's K/V payload, scale, position, evict and live-count
    planes. It **asserts the device store exists** rather than skipping those
    planes when it is absent.
  - Every arm asserts the open cycle really mutated the store before it aborts,
    so a rollback assertion cannot pass vacuously.
  - Arm 1 cancellation (`GenerationCancelled`), arm 2 a real expired deadline
    through the module's own `_deadline_checkpoint(0.0)` factory
    (`GenerationDeadlineExceeded`) with a second unwind asserted idempotent, arm 3
    an unexpected mid-cycle exception (`ConnectionResetError`), arm 4 the
    session-level allocation trace. Arms 1-3 each end with a fresh cycle that
    must still commit exactly the autoregressive tokens.
  - Arm 4 takes `memory_stats()["active_allocations"]` before the session and
    requires it back after teardown with an open, uncommitted cycle.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: a new checked row for the
  lifecycle arms, and the prefix-reuse row narrowed -- its lifecycle half is now
  covered and only prefix reuse after a cancelled request, MTP on and off, is
  still open.

## Validation

- `run1151 pytest tests/test_live_dms_int8_mtp_lifecycle.py --suite live` --
  **4 passed**, run twice: once with the signature as first written, and again
  after it was made to require the device payload store, which confirms the
  device planes are compared and restored rather than silently skipped.
- `python3 scripts/docs/check_all.py` -- all 4 passed.
- No production code changed, so the DMS parity gate is unaffected by this unit.
