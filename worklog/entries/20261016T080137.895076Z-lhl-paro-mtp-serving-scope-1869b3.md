# Resolve explicit PARO MTP through the serving route

## Summary

Closed the PARO explicit-request gap from the MTP-SERVING matrix: an explicit `speculative_mtp` request on the packed-PARO model now resolves through the OpenAI route instead of failing with no typed plan. The model plugin declares its C1 chain implementation scope and the generator exposes the resolver, so every axis outside the scope is refused by name rather than silently downgraded.

This is task #31's first unit. The sampled decider itself is deliberately NOT advertised: the declaration stays greedy-only until the decider is real, and an explicit sampled request refuses with `mtp_sampling_unsupported` — the honest current state.
