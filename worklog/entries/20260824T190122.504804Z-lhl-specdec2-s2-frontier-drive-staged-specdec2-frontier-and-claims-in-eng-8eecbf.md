# Drive staged SPECDEC2 frontier and claims in EngineLoop

## Summary

Made Generation-2 the explicit stage driver for backend-neutral SPECDEC2 work.
For runners exposing the staged contract, the loop now obtains all target,
provider, and transient claims, composes one operation claim, reserves it before
provider preparation, runs one proposal, derives root IDs/positions from
scheduler-owned committed state, builds `TargetFrontier`, executes target/atomic
commit, and releases the reservation. Any stage exception invokes provider-cycle
rollback and releases before propagating.

The previous opaque `execute_speculative_cycle()` remains a temporary fake/oracle
fallback for runners not yet migrated; the staged route takes precedence.

## Changes

- Moved `compose_speculative_claims()` to production transaction ownership while
  preserving the simulator compatibility export.
- Added staged claims/reserve/release, prepare, propose, frontier, target, and
  rollback orchestration to `ResidentEngineLoop`.
- Validated candidate request/slot/count/root ownership against the scheduler and
  target result ownership against the complete composed claim.
- Added fake staged-runner tests proving exact stage order, scheduler root token/
  position materialization, complete claim composition/release, target frontier
  topology, rollback, no visible mutation after failure, and next-tick AR health.
- Replaced package-level speculative imports in generation modules with direct
  module imports to remove a discovered initialization cycle.
- Updated the normative S2 punchlist.
