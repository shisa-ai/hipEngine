# gfx1100 MTP CK matrix blocked by serving evidence gate

## Summary

The C1-C8 x K1-K4 qualification sweep is **blocked**: a cell cannot be measured
until it already has evidence, and it cannot have evidence until it is
measured. K4 support and the depth-cap unification landed (`c6e55a147`) and are
retained. The sweep also produced a material finding that changes what the
matrix is for: **both currently qualified MTP cells now run at or below their
own AR arm**.

## Changes

- Retained from `c6e55a147`: `MTP2_MAX_CANDIDATE_DEPTH` 3 -> 4 as the single
  source of truth, replacing three duplicated caps; `capability()` decline
  reasons; adapter-resolution tracing.
- `GGUF_SPECDEC2_MTP2_PHYSICAL_WIDTH_DEPTHS` was opened to all 32 cells for
  sweeping and has been **restored** to its qualified 4-cell set, because
  opening it does not make cells reachable and an open table misrepresents what
  is available.

## Validation

### Two gates found

1. **C1 is hard-disabled on the physical path.**
   `partition_max_requests` computes `resolved = bound if bound > 1 else 0`, so
   any group resolving to width 1 is forced to K0. C1 MTP exists only through
   the separate `GGUF_SPECDEC2_MTP2_C1` singleton route, which is why
   Qwen3.6-27B publishes a C1/K3 number while this bench never engages at
   capacity 1. Confirmed by zero MTP cycles at capacity 1 in explicit and
   automatic modes.
2. **Cells are gated on pre-existing serving evidence.**
   `hipengine/models/qwen35.py` holds `SpeculativeMTPServingEvidence` records
   keyed by backend, arch, quant, profile, execution-profile manifest sha256,
   KV storage, realized group rows, resident capacity, candidate budget,
   sampling mode, context bounds, and output horizon. Opening the width/depth
   table to all 32 cells was necessary but **not sufficient**: at C2, K1/K3/K4
   still reported `engaged 0/10` in **both** explicit and automatic request
   modes. Only C2/K2, which has a record, engaged.

This is a deliberate fail-closed design and it is circular for qualification:
producing the evidence a cell needs requires running the cell. Sweeping
requires an explicit screening bypass for unqualified cells, comparable to the
`--packed-prefill-candidate` admission mode on the profile-gate harness. That
is the concrete blocker.

### Material finding: AR has overtaken MTP

Same host, same suite, same protocol, each width at its own resident capacity:

| Cell | AR published | AR now | dAR | MTP published | MTP now | dMTP | ratio published | ratio now |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| C2/K2 | 30.720 | 41.769 | **+35.96%** | 36.726 | 38.328 | +4.36% | 1.1955x | **0.9176x** |
| C8/K3 | 88.250 | 91.969 | +4.21% | 98.643 | 91.421 | -7.32% | 1.1178x | **0.9940x** |

At C2 the AR arm gained 36% while MTP gained 4%, inverting the published win.
Both cells stay 10/10 token-exact and C2/K2 keeps healthy draft acceptance
(0.9006), so this is an economics change, not a correctness regression. It also
explains the packet G non-reproduction of the C8/K3 row recorded in
`20260905T200354.451403Z-lhl-gfx1100-rdna3-transfer-packet-g-reject-152bd6.md`:
that row did not regress so much as get overtaken by its own baseline.

Non-engaged rows in the artifact (C2 K1/K3/K4) compare two AR-equivalent arms
and are diagnostic only; their ~0.999 ratios are not MTP measurements.

## Next

   no new (C, K) cell can ever be qualified on this backend.
2. Before qualifying more cells, settle whether MTP still earns its place here:
   both qualified cells now lose to AR, so the optimal policy on current
   evidence trends toward K0 for this model, and the two published MTP rows
   should be re-examined rather than extended.
3. K4 is reachable in code but has never engaged, so it remains unmeasured.
4. The public C2/K2 (1.1970x) and C8/K3 (1.1178x) README rows both overstate
   current behaviour; the C8 row is already flagged under review and C2 now
   needs the same treatment.
