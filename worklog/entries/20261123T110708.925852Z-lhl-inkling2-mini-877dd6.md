# Verify device-gathered Inkling expert scales

## Summary

The NVFP4 gate/up, down and ordered mix chain produced the same output bits with GPU-gathered scales and one shared ID record, holding the expert IDs and mixture weights fixed.

## Changes

- Scratch only. Upload the physical layer's gate and down scale tables once per replay. Gather both scale arrays on the device from the fixed selected IDs, reuse those IDs for both projections, and keep the existing expert kernels and mix.

## Validation

- On `epyc`/W7900, mainline Inkling 2 Mini `UD-Q4_K_M`, `517c32c411006155a21a6a0b9ede875611f9a1b8`, `fast` manifest `ec04e8bdf2c53c55ebe895c0f905f388a72bb691af0658265dfc8b4676e1cb27`, FP32 KV, greedy with no prefix reuse or drafting. Compile `hipcc -O3 -shared -fPIC --offload-arch=gfx1100 /tmp/hipengine_inkling_resident_scales.hip -o "$probe_so"`; run `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. HIPENGINE_REQUIRE_CACHED_BUILD=1 python -u /tmp/hipengine_inkling_resident_scales.py "$model" "$probe_so" "$revision"`.
- At 47 and 575 input tokens, five-output requests supplied 176 real NVFP4 visits each. Each replay used the 2,304-input gate/up path with both scale arrays present. The gathered scales and every mixed output bit matched the existing host-staged control. Each replay uploaded 40 distinct physical scale tables. This was a fixed-route replay without recurrent convolution mutation; it does not validate router arithmetic, full resident serving, or latency. Log: `/tmp/kendex-pi-bg/bg-333-1795431998787.log`.
