# Route unfamiliar GGUF manifests by capability

## Summary

Issue #8's plain-manifest allowlist is removed. Unfamiliar layouts retain generic policy routing and are checked against tensor consumers rather than a list of measured hashes. Packaged MTP vocabulary maps now bind only to the ordered tokenizer vocabulary, not model names, layer counts, weight quantization, or admission presets.

## Changes

- Remove `_PINNED_PLAIN_CONTROL_FINGERPRINTS`; both report-based and map-based policy identity helpers return the generic identity when no specialized UD preset applies. Specialized historical UD policy identities remain unchanged.
- Retain manifest fingerprints for provenance/certificate ownership, not as a prerequisite for generic routing. The legacy sentinel remains accepted by existing policy callers but admission no longer emits it.
- Validate hot-vocabulary size, ordered-tokenizer hash, token encoding, ID bounds and ordering. Ignore source model metadata that cannot change token-ID compatibility. A different tokenizer still cannot reuse the map.
- Add CPU regressions for unfamiliar report/map fingerprints and tokenizer-compatible models with different metadata; update obsolete identity-refusal assertions. Add public MTP checks on Q4_K_S and UD-Q4_K_M.
- Parent Git metadata was deleted during this unit. The reclone restored pushed history; surviving worktree files were backed up and reconnected with `git worktree repair`. The unpushed issue #10 audit was recreated as `dbbfad743` without changing its contents.
