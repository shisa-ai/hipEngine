# W7900: gate published artifact commands against HEAD argparse

## Summary

Published benchmark rows were losing their repro recipes silently, twice in one session. Added
`scripts/check_published_command_drift.py`, which AST-extracts the declared flags of every tool invoked
by an artifact cited in `benchmarks/README.md` and refuses commands that use a flag the tool no longer
declares, commands whose script lives outside the repo, and commands citing tools that are not in the
tree. Current state: **51 cited artifacts, 0 violations, 4 pre-existing problems recorded as dated
exceptions.**

## Changes

New tool plus `tests/test_scripts_check_published_command_drift.py` (9 tests, RED first). Fixed one of
the two instances I caused: `2026-08-30-w7900-q4km-c1c8-hipengine-grouped-prefill-promotion.json` - the
headline grouped-prefill row - recorded `--require-mtp`, which argparse no longer accepts, and omitted
`--model` after the tool default moved to Qwen3.6-27B, so a literal rerun would have measured a
different model. Its `command` is now HEAD-valid, the historical string is preserved in
`command_as_run`, and `command_drift` records why and how far it is verified. `docs/REFACTOR.md`
ledger row updated. No engine behaviour changed.

## Validation

The gate is parse-level and side-effect free (no import, no GPU). Two bugs found while building it are
worth recording because both would have made a green gate meaningless:

- My first AST pass scanned `add_argument` **keywords** as option names, so any script with a typed
  argument (`type=Path`, `default=...`) looked "un-inspectable" and was skipped. That silently blinded
  the gate for exactly the tools that matter, including the one holding `--require-mtp`. Now only
  positional arguments are treated as option strings, and dynamic option names still return None.
- The citation regex matched `.json` inside `.jsonl`, so the prompt suite was cited as a nonexistent
  artifact. Fixed with a lookahead.

Tests pin: a valid command passes; a removed flag is `UNKNOWN-FLAG`; `--flag=value` matches on the
name; `/tmp` scripts are `SCRIPT-NOT-IN-REPO`; deleted tools are `SCRIPT-MISSING`; allowlisted problems
are reported but not failing; a stale allowlist entry fails the gate by itself; and the real repository
passes with the recorded exceptions.

Why not all artifacts: auditing every recorded command found **125 distinct historical drifts across
1579 `scripts/*.py` commands** (flags removed months after the run, tools long gone). That is not a
fixable backlog, so the gate polices the published set and lists the rest. Four of those - a cuda-lane
and two gfx1151 rows whose commands invoke `/tmp` scripts, plus a survey citing a never-committed
`scripts/conc_bench.py` - are named in `EXCEPTIONS` with dates and left untouched, because a published
row's provenance belongs to its author.
