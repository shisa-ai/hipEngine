# Fix GGUF device KV pool pressure eviction owner

## Summary

A resident dense GGUF server (`hipengine serve` on Qwen3.8-27B Q4_K_M, gfx1151)
failed its engine closed on the first request whose prompt plus `max_tokens`
exceeded the device KV pool floor. The pool's `on_pressure` callback resolved
`evict_prefix_cache_for_pressure` through the session's `_resident_batch_owner`,
which on a session names the *session* that owns shared session-level resources
(bulk prefill scratch, packed workspace, packed verify state). That object owns
no prefix cache, so the callback raised
`AttributeError: 'Qwen35GGUFResidentSession' object has no attribute
'evict_prefix_cache_for_pressure'` from `qwen35_gguf_runner.py:18560`, and the
engine then reported `engine service is closed after a fatal execution failure`
for every later request until restart. The handler method lives on
`Qwen35GGUFResidentModelRunner`, which owns the retained prefix snapshots.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: replaced the `on_pressure` lambda in
  `Qwen35GGUFResidentSession.create_global_device_kv_pool` with
  `Qwen35GGUFResidentSession._on_device_kv_pool_pressure`, which resolves the
  handler from a `_kv_pool_pressure_owner` published on the pool-owning session
  and returns `None` (a no-op) when nothing usable is published. The stale
  comment above `before_grow` no longer claims both callbacks read
  `_resident_batch_owner`.
- `hipengine/generation/qwen35_gguf.py`: `Qwen35GGUFResidentModelRunner` publishes
  itself as `_kv_pool_pressure_owner` on the factory session before creating the
  global pool, next to the existing `kv_pool_memory_budget_mib` handoff.
- `tests/test_unit_gguf_packed_workspace_stability.py`: added
  `test_pool_pressure_reclaims_through_the_published_prefix_cache_owner` and
  updated `test_pool_pressure_callbacks_tolerate_a_session_without_a_batch_owner`,
  which previously mirrored the removed `_resident_batch_owner` pressure shape.

  force reclamation is the remaining check.
