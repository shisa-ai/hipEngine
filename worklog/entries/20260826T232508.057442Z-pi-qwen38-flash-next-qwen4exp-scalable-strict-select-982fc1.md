# Replace quadratic QSA selector in complete runner

## Summary

Replaced the complete runner's reduced-fixture single-thread QSA selector with
an exact scalable host control fallback. Native projection/pool/norm/RoPE/score
and sparse original-K/V attention remain on GPU.

## Changes

- The prior device selector scanned every block once per budget slot and then
  rescanned all prior selections, `O(blocks * budget²)` in one thread: roughly
  17 billion comparisons/layer/token at 262K. It remains a focused primitive
  oracle but is no longer reachable from complete long-context execution.
- The strict runner copies one score row, applies finite-checked NumPy
  lexicographic `(-score, block_start)` ordering, sorts selected starts for
  chronological K/V expansion, and uploads the bounded selected metadata.
- Added the temporary strict fallback/removal gate to `docs/REFACTOR.md` and
  corrected the kernel catalog; a scalable exact GPU top-512 successor remains
  required before F6/performance closure.

## Validation

- 65,536-block all-tie fixture selects starts 0..510 plus the unique final
  maximum exactly. Five host-selector measurements were 0.326 ms cold then
  0.090-0.100 ms warm on this host.
- Index-state and integrated dense→sparse runner files -> `5 passed`.
- Cache-only gfx1151 rocprof node passed; database
  `/tmp/qwen4exp-qsa-host-select-rocprof/zbook/809512_results.db` contains index
  norm/RoPE 2,404 ns, pool 3,126 ns, score 1,844 ns, and sparse paged attention
  4,929 ns; no quadratic selector kernel appears and no compiler ran.
