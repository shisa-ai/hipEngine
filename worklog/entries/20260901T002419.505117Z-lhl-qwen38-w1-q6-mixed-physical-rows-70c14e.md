# Restore mixed physical rows for W1 C8 transaction

## Summary

The R32-only capability interpretation was wrong: logical C8/K3 emits mixed
physical R20/R24/R32 verifier subshapes. Removing R20/R24 collapsed a one-prompt
C8 candidate from the prior ~39 tok/s regime to 25.25 tok/s. Logical C6 likewise
collapsed to 23.65 tok/s in the joint run. Exactness remained intact, localizing
the issue to incomplete transaction coverage rather than arithmetic.

## Changes

Restored all measured physical rows to the default-off capability table and its
dispatch test. Logical-width activation must be selected outside leaf dispatch;
the physical table alone cannot distinguish C6 from C8.

## Validation

Focused lifecycle runs passed exactness/route/budget and exposed the sized
complete-wall regression. Dispatch tests cover R20/R24/R32. No default changed.

## Next

verifier method, then design an outer capability/context owner if retained.
