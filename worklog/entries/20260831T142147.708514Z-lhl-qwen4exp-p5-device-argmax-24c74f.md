# Add Qwen4Exp device greedy argmax

## Summary

Added a default-off P5 output boundary for normal greedy generation. The lm head
still materializes exact F32 logits on device, then registered `argmax_f32`
selects top-1 and only one int64 token is copied to the host. Direct runner,
MTP, benchmark, and debug calls retain full logits by default.

## Changes

- Added argmax scratch ownership and `_finish_lm_head(capture_logits=...)` to the
  Qwen4Exp runner.
- Added `capture_logits` to step/prefill APIs while preserving default full-logit
  behavior.
- Normal serial, multimodal, and continuous greedy generation select compact
  output only behind `HIPENGINE_QWEN4_EXP_DEVICE_ARGMAX=1`.
- Extended the counterbalanced route harness so the candidate decode route uses
  compact output and hashes complete generated token sequences.
- Added profile binder/candidate coverage and refactor trigger.

## Validation

- Existing registered F32 argmax remains the selected raw-pointer kernel and
  preserves lower-index tie behavior.
- Generator/model/route/profile focused bundle: 27 passed.
- Route helper under the candidate passes `capture_logits=False` to prefill and
  every decode step; default mode passes no new kwargs and preserves old mocks.
- No profile default changed; full logits remain the direct-runner default and
  explicit correctness/debug surface.
