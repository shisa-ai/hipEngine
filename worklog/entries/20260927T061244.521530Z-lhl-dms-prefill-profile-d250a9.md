# Separate DMS prefill queue waits from cache transfers

## Summary

DMS cold-prefix capture appeared expensive in cProfile, but synchronizing
before each read establishes that GPU queue waits dominate the recorded time.
Do not remove cache snapshots based on that attribution. Layer-family isolation
points instead to recurrent prefill at the large chunk width.

## Changes

- No runtime changes. External diagnostic scripts and outputs are under
  `~/gate-runs/qwen38-edge-cache-repaired-20260926/`.
- `profile-prefill-host.py` profiles the public runner's `prefill_batch` for
  dense and DMS. An initial wrapper around resident `prefill` missed the dense
  route; it was replaced before interpreting the comparison.
- `profile-prefill-readback.py` synchronizes before cold readback, separating
  pending GPU time from transfer/allocation time.
- `profile-prefill-layers.py` synchronizes around full/recurrent layer methods.
  These synchronizations are diagnostic only and are not production changes.

## Validation

All three final scripts complete public MTP requests on physical host
`gfx1151`, AMD gfx1151, Qwen3.8-27B Q4_K_M, production, BF16 KV, radix caching,
4,097 prompt tokens, eight output-token limit, temperature zero. DMS uses the
existing external sidecar. Exact constructors and artifact paths are in the
scripts. Commands are `bash /tmp/t17-env.sh python` followed by the script path
above. This is attribution, not a throughput or speedup benchmark.

- Readback diagnostic: 132 cold reads, 470,624,576 bytes; explicit queue waits
  total 13.203 seconds versus 0.128 seconds in subsequent read/allocation calls.
  Artifact: `prefill-readback-profile/readbacks.json`.
- Layer diagnostic: 48 recurrent layers at 4,093 rows total 10.674 seconds;
  their four-row tail totals 0.186 seconds. Full-attention method invocations
  total 3.017 seconds. Artifact: `prefill-layer-profile/layers.json`.
- cProfile includes lazy draft-model loading and instrumentation overhead;
  dense/DMS profile totals are not valid serving throughput comparisons.
- No correctness promotion is claimed: these runs profile the already-tested
  runtime at the entry's base commit and do not change arithmetic.
