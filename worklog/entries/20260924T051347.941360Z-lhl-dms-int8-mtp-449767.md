# DMS admission axis: a DMS row presents the uniform layout INT8 MTP already declares

## Summary

Task #12 is in progress; this unit closes its admission and documentation half.
The premise that DMS needs the INT8 MTP declaration's `kv_layouts` widened
beyond `("uniform",)` does not hold, and the measurement says so: DMS is a
retention policy over the same paged planes, not another storage layout, so a
DMS row presents the same `"uniform"` layout the declaration already covers and
`mtp_kv_layout_unsupported` is not a DMS refusal. No production change is
needed for that axis. What remains for #12 is the live MTP-versus-AR parity
gate, which needs DMS sidecar artifacts that are not on this host.

## Changes

- `tests/test_unit_int8_mtp_serving.py`: new
  `test_dms_retention_presents_the_uniform_layout_int8_mtp_declares`. It builds
  the policy a DMS INT8 session resolves (`FixedPagedKVPolicy(storage_dtype=
  INT8_PER_TOKEN_HEAD)`, no `kv_policy` passed by the DMS scripts), asserts its
  `storage_layout` is `"uniform"`, asserts the INT8 serving plan admits a key at
  that layout with an empty `failed_axes`, and pins that the one layout still
  refused is `tail4_hadamard_group32` -- a different storage layout, not a DMS
  policy.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: the DMS Extension checklist now
  records what #9, #10, and #11 delivered (per-head variable spans and scale
  planes; eviction/compaction journalling; accepted-mutation-only commits with
  rollback), retires the stale "until those operations exist, report the missing
  DMS transaction contract" line, and states the remaining live-parity item with
  its exact blocking prerequisite. The acceptance-test list gains
  `tests/test_unit_int8_mtp_serving.py`.
- No production code changed. The finding is that the admission axis was already
  correct; the deliverable is the pin that keeps it correct.
