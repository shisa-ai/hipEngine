# Gemma 4 dense Q8_0 prefill tile: flatten the shape cascade

## Summary

`gguf_q8_0_prefill_wmma_kernel` is the largest single item in Gemma 4's
post-flash prefill budget: 79.4 ms of a 277 ms 512-row block-pass, 158.9 ms per
1024-token prefill, 28.7%. Its `_default_tiles` shape cascade picked `tile_m`
32 or 64 for every one of Gemma's dense shapes and loses 1.17-1.94x at rows
>= 128 and 1.72-3.31x at rows 8 and 31 against `(16, 32)`, which is fastest or
tied at all thirteen shapes measured across six row counts. The heuristic is now
flat: `(16, 32)` at rows >= 32, `(16, 16)` below.

W7900 prefill 1702.8 -> 1791.1 tok/s (+5.2%), XTX 1886.8 -> 1988.7 (+5.4%),
decode flat, peak unchanged, `public_path_parity` true. **Bit-identical**: the
teacher-forced gate returns exactly its previous verdict.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_q8_0_prefill.py`: `_default_tiles`
  collapses the shape cascade to `(16, 32)` / `(16, 16)`. `in_features` no
  longer selects anything; it stays in the signature because callers pass the
  shape as a unit.
- `tests/test_gpu_gguf_q8_0_wmma_prefill.py`: the pinning test is re-anchored to
  the new sweep, including the Gemma shapes the cascade sent to 32/64.
- `scripts/gemma4_dense_q8_route_probe.py`: route census plus the int8 MMQ A/B,
  carried as a monkeypatch so the candidate gate is measured before any code
  change.
- `scripts/gemma4_dense_q8_tile_sweep.py`: the per-shape, per-row-count tile
  table.
- Docs: campaign iteration 154, recommended-order items 3 and 5 updated;
  `benchmarks/README.md` Gemma section, `benchmarks/CHANGELOG.md`,
  `benchmarks/results/2026-09-27-gemma4-q8-wmma-tile16-{xtx,w7900}.json`.
