# Generate production oracles on measured owner

## Summary

Added a canonical same-owner oracle protocol to remove the repeatedly faulting multi-process oracle-to-measured GPU handoff. Exact references now run as serial c1 children on the already loaded EngineService owner before benchmark capture hooks, HTTP metrics, tuning, or measured workloads.

## Changes

- Added `--oracle-mode same_owner|isolated`; `same_owner` is the production default while bounded worker processes remain diagnostic.
- Generate every unique prompt trajectory serially through `LLM.generate_detailed()` with greedy top-1/ignore-EOS and exact requested length.
- Require generated token IDs for every oracle and assert active/pending/model rows drain to zero before measurement.
- Create benchmark capture hooks, server metrics, and measured memory baseline only after oracle drain; oracle work cannot inflate measured HTTP counters.
- Record exact oracle mode and final ownership in artifact provenance.
