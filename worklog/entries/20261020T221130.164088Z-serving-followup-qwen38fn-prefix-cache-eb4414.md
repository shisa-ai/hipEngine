# Flash-Next prefix reuse: streamed telemetry, cache-off A/B, docs

## Summary

Closes the open items from
`worklog/entries/20261020T210425.576540Z-serving-followup-qwen38fn-prefix-cache-007489.md`.
Streamed AR replies now report prefix reuse, the cache-on/off output A/B passes
on hardware, and the Flash-Next cache is documented.

## Changes

- The Flash-Next runner's terminal stream chunk carries the request telemetry
  (AR batch widths plus `prefix_cache`). A stream that has published text never
  receives the reclaimed output, so streamed AR replies previously had no
  `cached_tokens` and no prefix diagnostics.
- `docs/API.md` "Flash-Next prefix reuse"; `docs/ENVS.md` rows for
  `HIPENGINE_PREFIX_CACHE` and the Flash-Next budget default.
- `benchmarks/results/2026-10-21-gfx1151-flashnext-prefix-reuse.json` and a
  CHANGELOG line.

## Validation

- 115 focused serving unit tests pass, including a new streamed follow-up test.
- `hipengine serve` on gfx1151 (production, BF16 KV), one process per arm,
  seven streamed greedy requests over a 24.8K-token reference: all seven
  outputs identical with the cache on and off. Time to first token, off → on:
  follow-up 21.1 → 0.61 s, identical retry 21.2 → 0.57 s, edit at 70% depth
  21.2 → 10.1 s (13,312 tokens reused), explicit-MTP follow-up 60.3 → 0.61 s.
  Restores take 7.6-11.5 ms. Sixteen checkpoints held 3.96 GB.
- `docs/check_all.py` 4/4 passed.

## Next

- No disk tier: checkpoints do not survive a server restart.
