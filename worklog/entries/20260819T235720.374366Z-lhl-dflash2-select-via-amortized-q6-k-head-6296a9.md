# DFlash2 select via amortized Q6_K head: 70ms -> 22ms, B3 suite +15%

## Summary

Replaced the drafter's select-path logits computation with the session's
amortized Q6_K t16 lm-head rowtile. The drafter's `select` previously computed
`draft_hidden @ head^T` with a 2.54 GiB dequantized-BF16 output head every
cycle (~70ms, dominated by the head read); the resident session already holds a
Q6_K t16 head (`HIPENGINE_GGUF_LM_HEAD_Q6_X8_SIDECAR`) that is ~4x smaller and
has a weight-amortized rowtile that reads it once across the block rows.

Measured select cost at block 4 (fox, gfx1151): **70ms -> 22ms** (logits 43ms
-> 12ms via rowtile; top16+selector 14ms -> 10ms). B3 full 10-prompt suite:
**7.70 -> 8.85 tok/s (+15%), 0.575x -> 0.66x AR**, AR-exact on all 10 rows,
acceptance unchanged (2.80) — the Q6 head produces identical drafter behavior
(recall@1/@16/unary bit-for-bit consistent with the BF16 head). B7 also works
(rows=7 chunks to [5,2] in the amortized rowtile).

## Changes

- `scripts/dflash2_gguf_cycle.py`: added `_draft_logits_q6_head()` which tries
  the session's `_verify_lm_head_rowtile_chunked` (amortized Q6, rows 2-6 or
  chunked 7 -> [5,2]), falls back to `launch_gguf_linear` on the Q6 head, then
  to the original BF16-head `select`. Both native cycles (batch + sequential)
  pass `drafter.logits.ptr` as `logits_f32_ptr` to `select` when the Q6 path
  succeeds. Follows the earlier unary fix (top-1 of top-16, no full-logit host
  copy).

## Validation

- B3 fox: AR-exact 40/40, acceptance 1.82, recall 0.486/0.892/0.514 unchanged;
  tokens/s 5.28 -> 5.87.
- B3 suite (10 prompts): mean 8.85 tok/s (was 7.70), ar_agree=1.00 every row.
- B7 fox: select 22ms, tokens/s 2.19 -> 2.33, AR-exact.
