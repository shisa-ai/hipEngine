# Opened - the dense_wide and wmma 16-47 certificates are bit-identical, and neither proves its route ran

## Summary

Follow-on from `20260930T110625` (the stale `wmma` certificate). That entry's
"Next" said to sweep the other prefill-route certificates for the same
decode-path exposure. The sweep did that and **found something different from
what it went looking for.**

**Two gate certificates for different routes, 13 days apart, at different
commits, record bit-identical published logits:**

| artifact | route | created | commit | strict | candidate |
| --- | --- | --- | --- | --- | --- |
| `2026-09-17-q8-dense-wide-16-47-gate/artifact-layers16-47-4cat.json` | `dense_wide` | 2026-09-16 | `1f06cd5e3` | `550bb9b8…` | `65370710…` |
| `2026-09-29-…/artifact-control-wmma16-47-vs-exact-dwcleared.json` | `wmma` | 2026-09-29 | `ccd9f7a84` | `550bb9b8…` | `65370710…` |

Teacher identity is **expected** - both gates clear every selector for the
teacher arm, so both teachers are the same exact chain.

**Candidate identity is not.** The two gates bind different selectors (`wmma`
clears `dense_wide` in both arms; `dense_wide` clears `wmma` in both arms) and
record different candidate chains, `wmma_prefill_f32_f32_out` and
`dense_wide256_f32_f32_out`.

**And neither artifact can settle it**, because neither carries a
`route_engagement` block - engagement recording was added later, in `056e6fbd8`.
So neither certificate proves its candidate route engaged, and the recorded
`candidate_chain` is a label rather than a measurement.

## What HEAD says

HEAD records engagement, so the same gate can be asked directly. Reduced
protocol, `--route dense_wide --layers 16-47`, artifact
`dense-wide-16-47-engagement-probe.json`:

```
candidate_route_engaged: False
teacher_route_engaged  : False
wmma_route_engaged_candidate_only: False
  native_batch_decode_session: teacher 0.0 / candidate 0.0 / differs False
  q4k_rowtile:                 teacher 1.0 / candidate 1.0 / differs False
  wmma_prefill:                teacher 0.0 / candidate 0.0 / differs False
kl_mean: 9.399214e-04 | kl_max: 1.231981e-02 | top1: 0.96
```

**No selector state differs between the arms**, and the same reduced protocol for
`--route wmma` returns the same `kl_mean`/`kl_max` to every printed digit.

The arms still differ (`kl_mean` is not zero), so `candidate_route_engaged:
False` is not "the arms are identical" - it is "this route's own selector state
does not distinguish them".

## What this does and does not establish

- **Does establish:** the two certificates are bit-identical in both hashes; at
  HEAD the two `--route` values give bit-identical results; neither certificate
  carries engagement evidence.
- **Does not establish:** that either gate is a false pass. `dense_wide` may
  legitimately be the parent the `wmma` selector resolves through - but **then
  the two gates are not independent certificates and must not be cited as
  such**, which is itself a qualification-accounting correction.
- **Not checked:** the full 12-case/128-step `--route dense_wide` run at HEAD.
  The comparison above is the reduced screen only.

This is deliberately recorded as an **open lead, not a finding**. Two earlier
false-pass discoveries in this campaign (`WMMA-ROUTE-FALSE-PASS.md`, and the
staged-f32 run whose `measurement_valid` was true over a replayed teacher) both
began as "the numbers agree too well". This one has the same shape, and the
honest state is that it is unexplained in either direction.

**The systemic point:** the campaign's engagement recording was added *after*
these certificates were produced, so every certificate older than `056e6fbd8`
is unverifiable on the question of whether its route ran. That is a property of
the artifact set, not of any one route.
