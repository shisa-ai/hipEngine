# Isolate expert arithmetic in packed Inkling verification

## Summary

Using ordinary fast Q8 activation arithmetic for the verifier's routed experts did not resolve target score drift on its own. It restored the original winner at the reported review position but did not reduce median logit error on either tested history.

## Changes

- Scratch only. Teacher-force the same ordinary tokens through the scalar target, the existing two-row verifier, and a two-row verifier using the ordinary scalar expert arithmetic. Keep every block in this diagnostic so errors can accumulate. Apply the existing convolution transform to each arm; the scratch Q8 arm moves the result through host memory before the transform and is not a speed candidate.

## Validation

- On `epyc` (W7900, gfx1100), mainline `UD-Q4_K_M`, `83409c515b926d32705af67b55712af78358d3d7`, `fast` manifest `ec04e8bdf2c53c55ebe895c0f905f388a72bb691af0658265dfc8b4676e1cb27`, FP32 KV, no reuse or drafting, use `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. HIPENGINE_REQUIRE_CACHED_BUILD=1 python -u /tmp/hipengine_inkling_dspark_verify_q8_attribution.py "$model" "$revision"`. Replayed the ordinary 20-token continuations of 54-input `code_topological_sort` and 90-input `mixed_ja_en_review` from the prompt suite.
- At the reported review divergence the largest absolute logit difference fell from 1.148 to 0.907, and the Q8 diagnostic arm agreed with ordinary argmax. Median per-row RMS error across that history increased from 0.125 to 0.138, and code history median increased from 0.080 to 0.096. The Q8 arm also changed the final code-history argmax. The experiment does not prove which remaining subsystem dominates drift. Raw rows: `/tmp/kendex-pi-bg/bg-273-1795421357173.log`.
