# E3 per-tensor repack: report surfaces now mirror the planner; runtime allocation unchanged

## Summary

Campaign UD-GFX1151-OPTIMIZE2 experiment E3 (C2/H3/H5/H7), executed as
loop iteration 6 of `ud-gfx1151-opt2/run-20260923-opt2`.

**H5's divergence located — the planner never diverged.** Production
`materialize_qwen35_gguf_weights()` passes `decode_repack=None` straight to
`plan_qwen35_gguf_materialization()`, which resolves `None` through
`HIPENGINE_GGUF_DECODE_REPACK` (default on) and applies UD-U3 per-tensor
eligibility (`resolve_ud_repack_eligibility()`, default `per-tensor`). The
runtime therefore always planned the UD file's eligible Q4/Q5/Q6/Q8 tensors
into T16/x8/planar layouts — E1's live route probe was the true view.

The stale `repack=OFF` lived on two **report** surfaces:

1. `preflight_qwen35_gguf_artifact()` (`qwen35_gguf_admission.py`): the
   `repack_veto is None` branch computed `bool(decode_repack) and not
   gguf_ar_decode_repack_veto(...)` — coercing the production default `None`
   to `False`, and pre-applying the historical model-wide raw-IQ veto without
   consulting `resolve_ud_repack_eligibility()`.
2. `scripts/gguf_quant_route_audit.py`: pre-applied the same model-wide veto
   itself (`repack = requested and not raw_iq`) on the false belief that
   "the production AR planner vetoes decode repack itself for raw-IQ AR
   layers".

Together these made the audit record `decode_repack_enabled=false` for the
UD file while the runtime loaded it with T16 routes — exactly C2's open
reconciliation and E1's live-vs-audit divergence.
