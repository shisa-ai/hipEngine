# Pinpoint the resident block divergence to the first message pass

## Summary

Comparing the block against the host per visit puts the first divergence exactly at visit 18, the first `message_pass` visit, and nowhere earlier. Every visit through 17 agrees to 5e-05. The message window is not the whole story: shifting it moves the error by about one unit but never clears it.

## Changes

- Per-visit comparison at 64 rows using `prefill_block(capture=...)`, which records the hidden state entering each visit, against `_resident_block(limit=k)`, which returns the state after `k` visits.

## Validation

64-row block, `Inkling-2-Mini-UD-Q4_K_M-mainline.gguf`, `hip_gfx1100`, fast profile, max absolute difference against the host state after the same number of visits:

- `k = 18` compares the block's state after visit 17 with the host's state *entering* visit 18, which the host has already restored to the prelude snapshot. It is not a divergence; ignore it.
- Visit 18 is the first `message_pass` visit and also `restart_from_prelude`, so the restart and the message read are both in play.
- Message-window variants, measured at `k = 19` and `k = 20`: `saved + 1, count - saved - 1` gives 6.065 and 1.096e+01; `saved + 2, count - saved - 2` gives 4.778 and 9.342e+00; `saved + 2, count - saved - 1` gives 5.614 and 8.507e+00. All variants change the result by about one unit, so the window is not the only defect.
- The reference reads `blocks[len(prelude_blocks) + 1:]` plus `_rms(previous_partial)`. The block writes the partial at `start + blocks`, which with the original window is index `count` and therefore overwrites the row that holds the previous pass's last block. That off-by-one is real but does not explain the magnitude.

## Next

- Check the restart restore itself before the message read: the block restores `h` from `saved_h` and the stack from `snapshot`, both captured at the first core-entry visit. If `saved_h` were captured after the visit's own write, the restored `h` would be wrong for every row, which matches a whole-block error rather than a few rows.
- The controller branch is the other untested part of this visit. It is the only visit where `plan.controllers` is set, so it is the only visit that exercises `_controller_input` with a message group, and it is exercised nowhere else in the block path.
