# Live packed-graph churn gate: every reallocation invalidates the binding

## Summary

Task #13 is closed. `tests/test_live_gguf_packed_graph_churn.py` drives a real
captured packed decode graph on the gfx1151 GPU through the four churn events
the resident runner guards, and asserts for each one that the live graph is
closed before the next capture reproduces the cold baseline exactly. The gate
is RED-verified against the guards themselves: removing the invalidation call
from three separate sites fails exactly the three tests that cover them.

## Changes

- New live gate `tests/test_live_gguf_packed_graph_churn.py` (6 tests). The
  fixture is the proven BF16 packed-graph recipe: `Qwen3.8-27B-Q4_K_M`,
  `max_sequence_length=1536`, `kv_scale_dtype=FP32`,
  `FixedPagedKVPolicy(block_size=256, storage_dtype=BF16)`, and
  `_GGUF_INT8_SHORT_BF16_MIRROR_MAX_POSITIONS = 0` so the short prompt stays on
  the plain BF16 mirror route.
- Coverage, one test per churn axis:
  - control: a plain reset/prefill cycle reproduces the tokens and reallocates
    nothing;
  - slot reassignment: `prefill_batch_native` takes the slots, so the previous
    occupant's graph must not survive;
  - verify-workspace growth: `_ensure_packed_verify_workspace` at a wider row
    and context geometry;
  - lm-head plane growth: `_ensure_verify_lm_head_buffers` past capacity;
  - cancellation/teardown: `close()` leaves no replayable handle;
  - KV scale reallocation: unreachable by design, pinned as a named refusal.
- No production change was needed. The guards already existed at
  `qwen35_gguf_runner.py:24087` (packed prefill), `:28123` (verify-workspace
  growth), `:30533` (lm-head growth), `:24285` (resumable prefill), `:18820`
  (device KV pool rebind), and on the session close path. This unit pins them
  from the outside, through the shipping entry points.

## Validation

Measured on the free gfx1151 GPU via the TheRock environment
(`source /tmp/gfx1151-env.sh && run1151 timeout 2300 .venv/bin/python -m pytest
tests/test_live_gguf_packed_graph_churn.py --suite live -v`):

- GREEN: `6 passed in 49.39s` (one 27B load, 45.5s of it).
- RED: with the `_invalidate_live_packed_decode_graphs()` call removed from
  lines 24087, 28123, and 30533, the run is `3 failed, 3 passed` — failing
  exactly `test_prefill_reassignment_invalidates_the_live_graph`,
  `test_verify_workspace_growth_invalidates_the_live_graph`, and
  `test_lm_head_growth_invalidates_the_live_graph`, with the control, the INT8
  refusal, and the close test correctly unaffected. Source restored
  byte-identical afterwards (`git diff` empty).

Two findings that shaped the assertions, both measured rather than assumed:

1. `buffer_identity_sha256` is **per-capture**, not per-binding-set. The capture
   binds its own feedback planes (`generated_tokens`, `generated_hidden`,
   `record_index`, `active_mask_device`), which are allocated fresh each time,
   so the full key differs between two captures that reallocated nothing. A
   field-by-field key diff across two cold cycles shows
   `buffer_identity_sha256` and its derived `key_sha256` as the only differing
   fields; `state_generations`, `buffer_count`, and every owner plane are
   identical. That is conservative rather than wrong — a stale binding can never
   hash equal — but it means the identity hash alone cannot prove growth, so the
   growth tests assert the owner-owned plane set directly via
   `_packed_graph_buffer_ptrs` (extras excluded) plus the measured geometry
   change, and assert the identity hash only as a secondary check.
2. The packed verify scratch is already prefill-shaped
   (`rows == max_sequence_length == 1536`) after a prefill, so a fixed small
   growth target does not grow it. The workspace case now grows relative to the
   live scratch.
