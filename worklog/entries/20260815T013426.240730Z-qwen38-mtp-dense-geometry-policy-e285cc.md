# Key dense GGUF policies by architecture geometry

## Summary

Dense Qwen35 GGUF performance-policy admission now uses immutable architecture
geometry plus quant metadata rather than `general.name`. Qwen3.6-27B,
Qwen3.8-27B, and renamed finetunes with the same validated topology therefore
share the gfx1100 policy while geometry drift fails closed. The MTP verifier now
inherits the concrete target backend instead of silently defaulting to
gfx1100.

## Changes

- Added `GGUFModelGeometry` and validated dense-H5120 / MoE-H2048-E256 geometry
  constants under `hipengine/kernels/policy.py`.
- Propagated the geometry through resident target and adapted NextN weights.
- Re-keyed decode-transport, small-weight arena, decode-scratch arena, unequal
  Q4 pair, source-F16, and dense prefill-liveness package policies by
  `(geometry, file_type)`.
- Removed production dispatch checks against `Qwen3.6-27B`; `model_name`
  remains provenance-only.
- Made `Qwen35GGUFTransactionalVerifier` inherit the target backend and reject
  cross-backend overrides.
- Retained intentional hardware boundaries: native PM4 remains gfx1100-only;
  gfx1151 retains HIP graph and independently gated generic dense layouts.
- Scoped the gfx1100 sole-T16/PM4 product test away from gfx1151; portable
  gfx1151 B3 behavior is covered by the independent smoke below.
- Updated architecture/refactor documentation and RED/GREEN coverage.
