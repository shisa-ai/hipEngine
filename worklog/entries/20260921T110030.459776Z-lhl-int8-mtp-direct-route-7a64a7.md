# Direct INT8 route runs the declared contract under diagnostic_override

## Summary

The direct-INT8 route refused a configuration no command could open. Under the
documented `diagnostic_override` the engine had already answered the *selection*
question — the operator forced INT8 — but route resolution still required
`runtime_action == "admit"`, so the kernels were never consulted. The route now
selects its execution bounds by runtime action and resolves the leaf the
declaration names.

## The two questions this separates

- **May this session execute persistent mirror-free INT8?** Answered by the
  kernels. `_runnable_no_mirror_int8_capability` allows an explicit
  `diagnostic_override`, because excluding it leaves a configuration no command
  can open. Route resolution uses this.
- **Is this session admitted to allocate mirror-free INT8?** Answered by
  evidence quality. `_admitted_no_mirror_int8_capability` stays strict: it still
  requires `runtime_action == "admit"` and still governs
  `retain_int8_bf16_mirrors` and the caller in
  `hipengine/generation/qwen35_gguf.py:2010`. A rejected artifact remains a legal
  reason for the engine to decline INT8 *selection*, and it does — the request
  falls closed to BF16 unless the operator sets the override.

Both now share `_mirror_free_direct_int8_capability`, which owns the one
interesting decision: **which mapping supplies the bounds.**

`_direct_int8_execution_source` returns:

- the capability mapping itself when `runtime_action == "admit"`, so the bounds
  come from the retained measurement when one exists and from the declaration
  otherwise;
- the **declaration** when the action is `diagnostic_override`, because the
  rejected evidence row records `max_direct_rows=0` and carries no decode variant
  at all. A zero there means no width passed the quality gate — not that the
  kernels cannot execute one. Under an override the declaration is the only
  statement about what the kernels implement;
- `None` otherwise, including the engine's own `fallback_bf16`, so an
  accidental resolution is not a deliberate direct-INT8 selection.

## Why the override was the blocker, not the kernel

`per_token_head_gqa_splitk_gate_bf16_batch_strided_spans` **is** registered for
`hip_gfx1151`. Only the `runtime_action == "admit"` conjunct excluded it. The
registry lookup in `_qualified_kv_decode_batch_route` is the real capability
check and it runs either way, so a contract no kernel registers still refuses —
pinned by test.

### Not run: the live gfx1151 acceptance

The live run needs a second hipEngine server on this host, and the co-resident
server holds 96.3 GiB of GTT, leaving less than the engine's own 3 GiB reserve
after the model loads. Its startup ladder halved the context
23552 -> 11776 -> 5888 -> 2816 and failed at every step, so no context or
active-request setting fits. The route resolution is exercised through the real
plugin and runner helpers instead. Recorded as not-run for a resource reason, not
as a defect.
