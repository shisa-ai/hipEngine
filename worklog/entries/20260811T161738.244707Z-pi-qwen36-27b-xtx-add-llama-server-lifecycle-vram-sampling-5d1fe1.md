# Add llama server lifecycle VRAM sampling

## Summary

Extended the external llama.cpp MTP/context benchmark to sample the same
whole-device amdgpu memory domain for base and MTP server lifecycles. Sampling
is explicit (`--sample-memory`) so old diagnostics remain compatible. Each
server row now separates the complete process high-water from startup, natural,
token-repeat, and teardown scopes and records absolute baseline/peak/final,
peak delta, sample count, polling interval, total memory, DRM card, PCI ID, and
sysfs path.

## Changes

- Added `_ServerMemoryRecorder` and `_run_server_mode` to
  `scripts/llamacpp_mtp_bench.py`; exception paths stop active phase/process
  samplers and terminate the server before returning.
- Added `--sample-memory`, `--poll`, `--memory-domain`, `--card-name`,
  `--pci-id`, and `--card-index`; multiple physical selectors fail early.
- Added RED/GREEN fake-sysfs and fake-subprocess lifecycle tests, plus artifact
  config coverage.
- Marked campaign P0.4 complete and added the XTX `card0`/5 ms flags to every
  context-AR and natural-MTP command skeleton.
