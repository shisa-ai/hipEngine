# R0523 full-attention KV path code inspection: context_batch (not split-K) for ctx<1024; metadata/commit/block-table ordered

## Summary

Code inspection of the packed full-attention decode KV path (the localized origin
of the R0523 race, layer 47). Findings:

- Route selection (`qwen35_gguf_full_attention_decode_batch.py`): for
  max_context_len < 1024 the decode uses `context_batch`
  (`bf16_context_batch_paged_c1_exact_spans`), NOT the split-K path. The failing
  context is 585, so the split-K workspace / parallel-reduce is NOT involved.
  Split-K only engages at context >= 1024.
- The context_batch kernel reads `KVLiveSpans.base_offsets` / `live_counts`
  (the attention ABI), prepared in-graph by the metadata kernel.
- Metadata kernel (`state.hip:293 prepare_packed_decode_metadata_from_positions_kernel`):
  single launch; thread 0 writes cu_q/cu_k/atomic, per-row threads write
  contexts/state_indices, block_table threads write the identity table. Distinct
  writes, no intra-kernel race. For arena leases the block-table output is
  redirected to a discard buffer (`gguf_packed_decode_graph.py:540`), preserving
  the authoritative host-staged page map.
- Commit kernel (`commit_packed_decode_graph_step_kernel`): single-thread, advances
  positions/contexts and records tokens; ordered after the model step.
- KV write (`qwen35_write_paged_kv_mixed_value_bf16_prompt_spans`) precedes the
  attention read on the same stream.

No ownership race found by inspection yet; all examined seams are stream-ordered
with distinct writes. The race is timing-sensitive (observer effect shifts onset),
so static inspection alone has not isolated it.
