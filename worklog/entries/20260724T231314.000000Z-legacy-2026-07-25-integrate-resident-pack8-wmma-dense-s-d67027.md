## Changes


- The first exact eight-row LDS-sharing FMA attempt is rejected and fully removed. At M512/K3072/N1024 it regressed the retained pack8 kernel **1.2851 -> 1.3273 ms**, and a same-session compounded pp512 screen regressed **155.899 -> 155.102 tok/s**. Two barriers per K256 and local256 scheduling erased the nominal weight reuse.
- Added the separately registered `pack8_wmma_prefill_bf16_bf16_out` leaf. One wave computes a 64-column x 16-row tile, decodes nibbles directly from the existing `[N/8,K]` int32 pack8 plane, reads the existing `[K/32,N]` effective FP32 scale/min planes, converts weight/activation fragments to FP16, and accumulates with FP32 WMMA. There is no raw/T16 sidecar and no cache rebuild.
- The synthetic boundary fixture is BF16-bit identical to the established raw-Q4 WMMA kernel and passes its independent CPU-reference tolerance/KL/top-1 gate. Production-shape tile medians are 16x16 **0.3817**, 32x16 **0.2670**, 64x16 **0.2407**, 16x32 **0.4521**, 32x32 **0.2754**, and 64x32 **0.3518 ms**; retained pack8 is **1.2695 ms**, so selected 64x16 is **5.275x** faster.
- Laguna exposes explicit `dense_q4_prefill_mode=wmma_pack8` from 16 rows for layer-0 Q4 gate/up and every sparse-layer shared Q4 gate/up/down projection. Rows below 16, decode, missing registry keys, and non-Q4 layouts retain their existing routes. The eager owner loads the WMMA library once and closes with unchanged scratch/resident weight bytes.
- With D4x3 selected gate/up and row-scaled hipBLASLt held on, a same-session retained-dense versus 64x32 screen measures **3.323144 s / 154.071 tok/s** versus **3.155161 s / 162.274 tok/s**, all next token 2930. The selected 64x16 default then measures **3.124218 s / 163.881 tok/s** over two runs, again token 2930. These dirty-tree diagnostics exclude model load and are not clean retained claims; complete cumulative quality/category admission remains open.
- Focused kernel/dispatch/runner validation reports all pass with two expected skips.
