# Live check: mixed-policy batching and streaming through hipengine serve

## Summary

The policy-batching fix (73cd16fda) was validated at the batcher level only. This
is the live run through `hipengine serve`, on one server with
`--speculative-mtp-serving enabled --speculative-mtp-thinking hard
--generation-batch-window-ms 50`, one chat request per arm, `max_tokens=10`,
`hard_think_cap=8`, temperature 0.7.

The first attempt could not have exercised the coalescing fix: the pair used
different seeds, so the sampling keys differed and nothing could coalesce. The
`generation_batch_window_ms` default is 0 (off), so the server only coalesces at
all when the window is opted in. Both are recorded here because a live check that
cannot coalesce proves nothing about the group key.

## Changes

- No source changes. This entry records the live validation of the fix committed
  in 73cd16fda (batch compatibility and the streaming dispatch boundary) and the
  two probe defects that had to be corrected before the run proved anything.

## Validation

- Coalescing control (two `hard` requests, identical sampling, same seed):
  `backend_groups[0].actual_group_rows == [2]` on both responses, so the pair
  really shared one engine call.
- Mixed policy, hard-first and hint-first, identical sampling and seed:
  `actual_group_rows == [1]` on every response, so the pair did not coalesce.
  The hard request reported `phase: answer` in both arrival orders (its cap of 8
  was enforced, close forced inside the 10-token budget) and the hint request
  reported `phase: reasoning` (its budget was relaxed, no forced close). Under
  the defect the hint-first order cleared both budgets and the hard request would
  have stayed in reasoning.
- Streaming (SSE, same request shape): `hard` finished with
  `finish_details.phase == "answer"`, `hint` with `"reasoning"`, matching the
  blocking path for each policy. Under the defect the hint stream kept the
  budget and would have finished in `answer`.
- Every request reported route `speculative_mtp`, so the policy split was
  exercised on the route that applies it.
