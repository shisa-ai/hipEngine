# Right-size compact GDN prefill QK scratch

## Summary

Profiled package-default Qwen3.6-27B eager decode at 4K and 8K on the RX 7900 XTX, then retained an exact residency-only cleanup for the compact peer-GDN prefill route. Both depths execute 953 kernels/token. The 4K-to-8K GPU-kernel increase, 29.810 to 31.313 ms/token, is almost entirely full-attention core growth, 4.740 to 6.588 ms/token; resident weight traffic is depth-flat and prior sole-T16/raw-sidecar alternatives remain excluded.

The compact GDN kernels materialize normalized Q/K once for each of 16 K heads, but session planning still reserved two 48-V-head planes. Right-sizing those views reduces the 4K-capped bulk scratch owner from 602.690 to 495.315 MiB and tracked/owned session memory by exactly 112,590,848 bytes (107.375 MiB) at both 4K and 8K. Same-process A/B shows no prefill or decode regression and preserves exact token 9707 with finite logits.

## Changes

- Size compact peer-GDN `prefill_query` and `prefill_key` from the effective construction-time route as `rows * num_k_heads * head_k_dim * FP32`; value remains per V head.
- Preserve full V-head Q/K capacity for explicit `chain_peer_wave32` fallback sessions.
- Reject widening the environment-selected GDN route after session allocation before a peer kernel can overrun compact Q/K storage.
- Add RED/current-path, explicit fallback, and post-allocation mode-change coverage.
