# Apply Inkling output gain inside target attention

## Summary

Apply the staged attention gain in the output write. Remove the separate pointwise kernel and retain the ungated path for callers that do not provide a gain.

## Changes

- Keep the FP32 division and multiplication order in each attention kernel. Leave key/value writes and rollback unchanged.

## Validation

- `epyc` / Radeon Pro W7900 (`gfx1100`), original `thinkingmachines/Inkling-2-Mini` revision `ed40e7da625f594fc9c4990f5f66be24873c22d7`, `inkling2_mixed`, FP32 KV, single-request ordinary greedy decode. Baseline `684f2e1db`.
- `bash /tmp/hipengine-inkling2-verify.sh attentiongatestore`: warm median 16.3648 to 16.4527 tok/s at five input / 24 output tokens (three runs per arm, no overlap). The synthetic 512-input / 128-output case measured 14.0264 and 14.0530 tok/s with identical IDs; one run per arm does not establish a precise gain.
- The warm trace showed 48 fewer device launches per token, all from the removed gate. All 54 focused tests passed. Public text and single-image packed DSpark matched ordinary and baseline IDs and counts; speculative throughput was not remeasured.
