# Add long DMS fine-tune initialization and row validation

## Summary

Extended the sidecar trainer for long-weight fine-tuning without consuming the
fresh v3 final heldout. The trainer can initialize from the retained short
sidecar and deterministically reserve disjoint row-modulus validation examples
inside every calibration shard when the label manifest has no validation
sequences.

## Changes

- Added strict `--initial-sidecar` BF16 tensor-name/shape loading and hash
  provenance before optimizer construction.
- Added `--derive-validation-modulus N`: remainder-zero rows from every
  sequence/layer become validation, all other rows train, with no overlap.
- Resume identity, metadata, and training summary bind both controls.
- Existing manifest-provided validation remains default and cannot be combined
  with derived validation.

## Validation

- Exact full-prefix stride-one long labels completed for four 32K calibration
  sequences / 64 layers / 131,072 tokens; manifest SHA
  `2a47af1139e9f7ad19dc08081f7fd428b2ad77fe41c12457fb7df37032b3cdfc`,
  clean `81006abb5`, deterministic ROCm provenance.
- Three trainer tests pass, including a real 1-epoch initialized run whose
  6x2x8x2 = 192 validation decisions prove row-modulus isolation and whose
  exported metadata binds initialization/split controls.
- Ruff, py_compile, and diff checks pass.
