# Batch PARO historical prompt priming through the shared sink

## Summary

PARO now sends bounded target-hidden chunks through the shared prompt sink.
Historical rows use batched normalization and KV-only priming; the final row
still computes the predictor. The public device oracle and all 294 paired
timing calls pass with identical state/output/acceptance. On Framework Desktop /
Radeon 8060S, packed Qwen3.6-35B-A3B ParoQuant W4, BF16 KV, one request/candidate
and 128 EOS-ignored greedy outputs, 4K first-token latency falls 6.021 → 5.094 s;
natural whole-call throughput improves 59.575 → 59.818 tok/s (+0.41%), confirmed
at +0.40%. Decode is effectively flat. This compares prompt implementations
within MTP, not MTP against AR.

## Changes

- Added a bounded bulk workspace to `NativeMTP`, with preflight capacity
  checks, partial-allocation cleanup, and final predictor preservation.
- Integrated the shared chunk planner and publication ledger into the PARO
  adapter. The public path batches 16 historical rows and publishes the final
  predictor row separately. No kernel arithmetic or decode variant changes.
- Added row-batched target output normalization and public route counters for
  bulk rows/chunks. The parent serial route is selected only by the archived
  benchmark's method substitution; there is no new product flag.

## Validation

- Device oracle: 16 lengths, 64 public calls comparing full, serial KV-only,
  bulk, and repeated bulk priming. Live KV bytes, final predictor state, token
  IDs and acceptance agree. Lengths cover both sides of chunk boundaries and
  unrelated values; tracked allocations are released.
- Focused CPU tests, default unit suite, compileall, fixture checks, tier
  discovery, registry, CPU fixtures and smoke-add-plan passed before measurement.
- First paired sweep validates 168 calls across all 18 natural/category-heldout
  prompts and 512/1024/4096 controls. Authoritative output IDs decode to coherent
  prefixes; ignored EOS explains repeated dialogue on short prompts. This is
  output sanity, not a task-completion quality claim.
- The 35-minute job limit interrupted confirmation after 15 completed cases
  and two pairs of the next case. The original artifact is preserved as
  `confirmation-timeout-partial.json`. The resume driver preserves the 15
  complete records exactly and restarts the interrupted case with its warmup.
  Cleanup of the terminated process was not observed; first-sweep, resumed
  confirmation and attribution processes close with zero tracked allocations.
- Independent validation certifies all 294 timing calls; 12 separate
  synchronized attribution calls preserve IDs and acceptance. Exact commands,
  timing methodology, source patch and results are in the evidence NOTES.
- Documentation gates and audit pass; the benchmark README-sync suite passes
  all 12 tests. The scoreboard reached its 3000-line limit, so the preceding
  two-row rollback table was condensed into one sentence without losing data.
- Evidence directory: `benchmarks/results/2026-10-24-gfx1151-paro-bulk-prompt/`.
  Frozen implementation hashes still match. Validator negative controls pass;
  resume validation accepts unchanged preserved records and rejects edits.
