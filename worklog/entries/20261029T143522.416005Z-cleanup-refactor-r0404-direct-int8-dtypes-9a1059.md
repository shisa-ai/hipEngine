# Repair GGUF direct INT8 prefill gate and output dtype adapters

## Summary

Repair actual dtype handoffs on GGUF direct INT8 prefill without editing kernel
bodies, resource plans or arithmetic defaults. The BF16 qgate producer was
passed directly to leaves expecting FP16. Hadamard also wrote FP16 output into
the BF16 projection input. The runner now adapts both boundaries in place.
Move only the post-repair calibrated quality evaluation to the deferred ledger.

## Changes

- `qwen35_split_qgate_bf16_kernel` writes BF16 gate bits. Direct sequential,
  flash, WMMA and Hadamard prefill kernels all declare FP16 gate pointers.
  Convert the row-local gate after Q/K/V preparation and before direct attention
  using the existing `bf16_to_fp16` wrapper on the caller stream. No additional
  allocation or producer change; ordinary native/AOTriton routes keep BF16.
- Per-token/head direct leaves already return BF16. Hadamard returns FP16;
  convert its output using existing `fp16_to_bf16` before the GGUF attention
  output projection reads it. No low-level ABI, registry or kernel changes.
- Numerical CPU orchestration regression invokes the real layer method with
  independent leaf doubles. Check gate values at the consumer and gated output
  at the projection for four direct leaves, BF16 native control and unrelated
  row counts. The GPU Hadamard check uses an independent CPU KV/attention oracle,
  both scale dtypes and in-place real cast launches.
- Correct ENVS selector/default descriptions and runner policy comment. Remove
  old ledger speed/capacity history and the dead-code label. Historical quality
  failures predate these adapters, so their entire discrepancy cannot be
  assigned to INT8 quantization alone. Preserve those artifacts unchanged;
  leave the arithmetic default and explicit direct execution unchanged. The
  deferred entry names a concrete repaired-evaluator command and separate
  Hadamard/category/heldout/repeat/isolation/task requirements.
