# Remove graph-instance confounding from restoration measurements

## Summary

The separate-cache restoration measurements show decode-rate differences even
when the decode algorithms are unchanged. Different graph instances/capture
streams are a nuisance variable. Compare the same captured decode units in
one three-arm run before interpreting the effect of ordered attention.

## Changes

- Add opt-in shared decode graphs guarded by an explicit reviewed flag set.
  Q8 down/prefill grouping and uncaptured QSA attention switches are allowed;
  captured decode changes such as DP4A are rejected.
- Add multiple candidate arms with Latin-square position balance and opposite
  neighbor directions across case parity. One baseline is shared explicitly;
  each candidate gets its own paired summary.
- Record graph statistics and arm identity. No runtime/kernel arithmetic change.

## Validation

- CPU protocol tests3 pass: safe flags, rejected captured-unit mutation, and
  three-arm position/direction balance.
- Original ordered A/B completes72 samples and exact output/state repeats.
  4K PP improves~37-39%, but TG is+37% for code and-5.4/-5.8/-6.4%
  for EN/JA/mixed. Do not infer an intrinsic kernel cause from that alone.
- Prefill-only independent-cache A/B also shows decode-rate changes with
  unchanged decode kernels. Stopped the owned process with SIGINT; the raw
  partial packet is retained as incomplete, not a completed matrix.
- Raw packets: blockscale-ordered-ab.json and blockscale-quad-ab.json under
  /tmp/hipengine-journey-execute-20260914. No unfavorable samples deleted.
