# W7900 Qwen3.8: order-swap A/B confirms the rows33 prefill floor; clean route delta replaces a contaminated figure

## Summary

A background A/B notification made me suspect the promoted fused gate/up prefill
floor was resting on a biased measurement, because the retained rows12 artifact
shows +3.1%/+4.12% at rows 16/32 which *looked* like negative controls. It wasn't:
that artifact is the rows12 step (`change.new = 12`), where the owner is genuinely
active at rows 16 and 32, so those are real gains, not noise. The suspicion still
deserved a measurement, so this unit runs the A/B properly - both arm orders, on
the shipping route, no instrumentation - and it confirms the effect while
measuring the harness bias that the claim has to clear. It also replaces one
number I published earlier that was contaminated by stage-timing syncs.

Measured: the 45-row prefill gain from admitting the fused dual+SiLU owner is
**+4.24%** when the control runs first and **+3.69%** when the candidate runs
first (mean **+3.97%**), and the true negative control - rows 16 with candidate
floor 33 and control floor 512, where dispatch is byte-identical in both arms -
gives **+0.01%** and **-0.84%**. So arm order is worth at most ~0.9% here and the
promoted floor is worth about four points. Every run produced token id 9707.

## Changes

- `scripts/gguf_prefill_rowgate_probe.py`: docstring now states the three
  measurement rules this unit learned, because violating any of them silently
  changes the answer - pass `--public-ar-profile` (worth 1.65x on 45-row prefill),
  never combine with `--gpu-stage-timings` (per-stage device syncs inflate wall),

  bias. No behavior change.

## Validation

W7900 (gfx1100/RDNA3), Qwen3.8-27B-Q4_K_M, production profile, `--public-ar-profile`,
`--warmup-runs 1 --measured-runs 2`, `--require-cached-build`, one fresh process per
arm, `HE_DUAL_WMMA_SILU_MIN_ROWS` = 512 (control) vs 33 (candidate):

| rows | order | control s | candidate s | gain |
| --- | --- | --- | --- | --- |
| 16 (dispatch-identical) | control first | 0.2392 | 0.2392 | +0.01% |
| 16 (dispatch-identical) | candidate first | 0.2364 | 0.2384 | -0.84% |
| 45 (owner admitted) | control first | 0.2802 | 0.2683 | **+4.24%** |
| 45 (owner admitted) | candidate first | 0.2798 | 0.2695 | **+3.69%** |

- Both orders positive at rows 45 with the sign stable, and the negative control
  spans +-0.9%, so the effect is not an ordering artifact. Raw per-arm files:
  `/tmp/he-oswap-{A,B}_{ctrl,cand}_{16,45}.json`; driver `/tmp/he_oswap.sh`.
- Route correction. A clean off-route run (same shape, same floor, no
  `--public-ar-profile`, no stage timings) gives **0.4458 s / 100.9 tok/s** with
  `shipping_ar_route_mismatch: true` and `effective_use_wmma_prefill_all:
  [false, false, false]`, against 0.2694 s on the shipping route - the shipping
  route is **1.65x** faster on 45-row prefill. This supersedes the 0.4573 s figure
  in `20260830T013638.124038Z-lhl-w7900-qwen38-small-row-prefill-attribution-4aa3bb.md`,
  which had been captured with `--gpu-stage-timings` (~2.5% inflation). The
  conclusion of that entry is unchanged; only the number moves.
- Today's earlier promotions are therefore unaffected: bit-parity fixtures gave
  identical arithmetic, and the prefill gain is reproducible in both arm orders.
