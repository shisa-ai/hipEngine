# the prefill benchmark is synthetic so the missing model does not block the prefill work and the baseline reproduces within 0.3 percent

## Summary

Looking for the model to measure the decode branches' relative cost found that **the Gemma 4
GGUF is not on this machine** -- and then that **it does not need to be**, because the prefill
benchmark is attention-isolated and synthetic. **The prefill baseline reproduces on this host
within 0.3%, which unblocks requirement 4.**

## The hardware and the model

`hostname` is **zbook**; `rocm-smi --showproductname` reports **AMD Radeon 8060S Graphics**,
which is **gfx1151**. The artifact's `host_arch` is `gfx1151`, so **the baselines were measured
on this machine.**

**The Gemma 4 GGUF is not here.** `find / -maxdepth 6 -name "*.gguf" -size +1G` returns only
Qwen3.8 artifacts and a VibeVoice model. The root filesystem is **96% full (87 GB free)**.

## The benchmark does not need it

`scripts/gemma4_attention_prefill_bench.py` imports only `numpy`, `hipengine.core.memory`,
`hipengine.core.hip`, and `gemma4_attention`. **It allocates synthetic inputs and never
touches a model or a GGUF.** The isolation is the reason it survives the artifact's absence.

## The baseline reproduces

`env -u ROCR_VISIBLE_DEVICES PYTHONPATH=. .venv/bin/python
scripts/gemma4_attention_prefill_bench.py --tokens 2048`:

| case | artifact | this run |
|---|---|---|
| swa 256d 16q/8kv window=1024 | 62.23 ms, 414.2 GFLOP/s | **62.25 ms, 414.1** |
| swa 256d window=0 (probe) | 77.48 ms, 443.7 | **77.81 ms, 441.8** |
| full 512d 16q/2kv | 130.27 ms, 527.8 | **130.54 ms, 526.7** |
| 30-layer total | 2207.2 ms | **2208.9 ms** |

**Within 0.3% on every row.** So the measurement environment is live and reproducible on this
host, and the baseline is independently confirmed rather than taken from the artifact.

## What this unblocks, and what it does not

**Unblocks:** the prefill work -- requirement 4, the largest item in the objective. **The tiled
variant can be written, measured, and compared here**, with the existing bit-exact test as the
strict variant's gate and a new tolerance test for the production variant.

**Still blocked:** the decode branch-cost measurement, because the dense and MoE dimensions
come from the GGUF rather than a config, and any end-to-end decode or MTP measurement. **Those
need the model, which is absent.**

**A correction to my own framing:** the previous iteration recorded the absent model as the
reason the branch-cost measurement could not be taken, and I was about to generalise that to
the prefill work as well. **It does not generalise.** The prefill bench is attention-isolated
by design, which is exactly why it is unaffected.
