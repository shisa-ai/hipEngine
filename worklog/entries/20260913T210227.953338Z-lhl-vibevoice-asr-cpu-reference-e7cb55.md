# VibeVoice ASR CPU reference and torch-free loader

## Summary

Adds the numpy-only CPU reference for the VibeVoice-ASR audio front-end, the
torch-free safetensors loader for the original checkpoint, the torch oracle
fixture script, and the live CPU-parity test. Follow-up to
`20260913T205511.895783Z-lhl-vibevoice-asr-native-e620fe.md`.

## Changes

- `hipengine/kernels/cpu_reference/vibevoice_asr.py`: causal conv1d (shape-
  inferred left-pad, im2col+einsum, groups support), RMSNorm, erf-GELU
  (scipy fast path, math.erf fallback), ConvNeXt block, full encoder
  forward, recorded-noise acoustic sampling, connector linear-norm-linear.
  FP32 accumulation, optional FP16/BF16 stored-output rounding.
- `hipengine/loading/vibevoice_asr.py`: BF16 safetensors -> FP32 numpy
  without torch. Stage order inferred from tensor shapes (in-channel
  progression; kernel = 2*stride), asserting ratios (2,2,4,5,5,8), depths
  (3,3,3,3,3,3,8), stride product 3200, head wiring. Original config's
  encoder_ratios [8,5,5,4,2,2] confirmed misleading for execution order.
- `scripts/vibevoice_asr_oracle_torch.py`: fixture generator for trace
  (0.5 s per-stage), boundary (3199/3200/3201), chunk-cache (60 s + 30 s
  with single-pass equivalence assert), and LM (processor-built request,
  greedy 16 tokens, teacher-forced top-10 logprobs) npz fixtures.
- `tests/test_live_vibevoice_asr_cpu_reference.py`: parity gates; skips
  pre-fixture/pre-checkpoint.

## Validation

- CPU reference smoke on real original weights: both encoders forward
  end-to-end; latent frames match floor(L/3200); finite outputs.
  NOT yet parity-checked vs torch (HF artifact still downloading, ~4.3/18 GB
  at commit time). Zero-fixture regression re-run before commit: OK.
- `scripts/check_test_tiers.py`: 0 issues. Live test collects/skips cleanly
  with `--suite live`.
