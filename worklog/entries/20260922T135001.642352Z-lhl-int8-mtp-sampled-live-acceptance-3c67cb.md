# Measure the sampled MTP route on INT8 KV through the server

## Summary

Task 5's code change landed on 2026-09-21 (`848a96529`): the three INT8
declarations list `sampling_modes=("greedy_fast", "sampled")`, and the runtime
gate was never the blocker because `_sampled_route_qualified` matches on backend,
architecture, weight quant and artifact size and never on KV storage. What was
missing was the live half of the acceptance, recorded then as not-run for the
GTT resource conflict. That conflict is gone (the co-resident server no longer
exists), so this unit measures it.

**Measured, on the INT8 cell through HTTP.** Four sampler families --
temperature/top_p, penalties, `logit_bias`, `suppress_token_ids` -- across three
prompts and two runs:

- every speculative arm reported `used=true` with real cycle counts (8-15 cycles
  per request); every baseline arm reported `used=false`, `route=default`,
  `cycles=0`, so the comparison is against true no-MTP autoregressive decoding;
- finish reason and the usage triple match in all 12 request pairs per run;
- two seeded runs of the whole matrix produced identical ids **and** identical
  cycle counts for both arms;
- 12 of 12 seeded speculative requests emitted exactly the ids their own no-MTP
  baseline emitted. That was not required and it is not a proof of the
  distribution -- it is what a shared seeded draw stream produces when the
  coupling is exact -- but it is the strongest end-to-end signal a token
  comparison can give, and it is recorded as an observation rather than as the
  claim.

**Induced-law gate re-run on the same revision:** verdict pass, 824 comparisons
with max total variation 4.53e-16 and max KL 9.03e-16 against a 1e-9 tolerance,
144/144 autoregressive-law agreements, and an 18-row Monte-Carlo arm with top-1
agreement 1.0 -- identical to the 2026-09-18 artifact. The law is unchanged by
the declaration, which is the point: the declaration says what runs, the gate
says the route it runs is exact.

The completion-details half of `usage` is reported per arm and deliberately not
compared: it carries draft accept counts a no-MTP baseline cannot have, so
comparing it would fail by construction. Finish reason and the usage triple are
the parity contract the task names.

## Changes

- `scripts/int8_mtp_sampled_gate.py` (new): the live half of the sampled-route
declaration. It refuses a server that is not the INT8 cell, refuses a KV
diagnostic-override run unless `--allow-kv-diagnostic-override` is passed (so an
override measurement can never be read as a qualified one), requires the
speculative arm to have speculated, requires finish reason and usage parity with
the request's own baseline, and requires the second seeded run to reproduce the
first.
- `tests/test_unit_int8_mtp_sampled_gate.py` (new, 9 cases): the gate driven
against a fake server that violates exactly one thing at a time -- no
speculation, zero cycles, finish-reason drift, usage drift, a second run that
does not reproduce, a non-INT8 server, and an override server without the flag.
A gate that can only pass is indistinguishable from no gate.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: the sampled gate joins the
command list, with the induced-law gate named as its server-free counterpart.
- New evidence artifact
  `benchmarks/results/2026-09-22-gfx1151-qwen38-int8-mtp-sampled-serving.json`:
the gate report plus the induced-law summary and one representative row per
prompt.

## Validation

Host `gfx1151`, backend `hip_gfx1151`, Qwen3.8-27B Q4_K_M (17,106,775,008 bytes),
uniform per-token/head INT8 K/V with FP32 scales, `--max-context-tokens 9216`,
production profile, candidate budget three, revision `1ef7126af`. The artifact's
compact INT8 quality record is rejected, so the server runs under the documented
diagnostic override; the gate records `capability_status=rejected`,
`runtime_action=diagnostic_override`, `persistent_bf16_mirror=false`.

```bash
.venv/bin/python scripts/int8_mtp_sampled_gate.py \
  --base-url http://127.0.0.1:18198 --model int8-lru-diag-20260922 \
  --allow-kv-diagnostic-override --json /tmp/int8-mtp-sampled-gate.json

bash /tmp/therock-env.sh /home/lhl/miniforge3/envs/vllm/bin/python \
  scripts/mtp_sampled_accept_distribution_gate.py --use-wmma-prefill \
  --use-gemv-decode --backend hip_gfx1151 --output /tmp/induced-law-20260922.json
```

Exit zero on both. The gate was re-run after the override guard was added and
produced byte-identical cycles and ids, so the artifact and the committed gate are
the same measurement. `tests/test_unit_int8_mtp_sampled_gate.py` passes (9), and
the full default unit tier passes.
