# Test compensated dense split accumulation

## Summary

The split leaf's natural-input attribution identified long-K accumulation as a
larger error source than operand reconstruction alone. A compensated repair
passes the new long-K RED and the existing GPU bundle, while retaining the
strict range fallback. The route is still default-off and has no model-level
qualification.

## Changes

- Add compensated ordinary F32 accumulation for high-high dots, using a
  positive/negative WMMA pair and TwoSum correction stored in the scaled cross
  plane. Cross products remain separately accumulated; non-split variants are
  unchanged.
- Add a GPU long-K RED for K=2560 and K=10240 against an independent F64
  reference. No runtime selector or production threshold changed.
- Update `docs/REFACTOR.md` with the repair/revert condition and retain compact
  operation-level evidence in `benchmarks/results/2026-10-05-qwen4exp-dense-split-model/`.

## Validation

- RED before the repair: long-K GPU test failed at relative L2 `2.508e-7`
  (K2560) and `4.719e-7` (K10240) against the new `<1.2e-7` target.
- GREEN after the repair: `tests/test_gpu_qwen4exp_dense_split_wmma.py`
  passes all 10 tests. The dense-wide and activation-hoist GPU bundle passes
  37 tests; the three-file CPU diagnostic bundle passes 20 tests.
- The repaired long-K values are `1.019e-7` (K2560) and `1.019e-7` (K10240).
  The cached-only rocprof trace shows the split kernel at 256 VGPR, 55,808 B
  LDS, 16 B scratch and 311,900 ns / 1,233,229 ns for the two test shapes.
  The baseline trace had 248 VGPR and 0 B scratch; this is a resource-cost
  change, not a production qualification result.
- The 15-case compensated operation screen measures parent → candidate sums
  of 28.777 → 18.828 ms (rows512), 57.486 → 37.960 ms (rows1024), and
  228.139 → 149.753 ms (rows4096); per-case speedups are 1.270–2.031x and
  both order strata improve. Its candidate CPU-F64 sampled top-1 is 100%.
  Artifact: `benchmarks/results/2026-10-05-qwen4exp-dense-split-model/compensated-screen.json`.
- The prior natural-input model trajectory packet remains valid for locating
  the issue, but must not be reused as post-repair model evidence. Full strict
  teacher, heldout, task/control/BF16-relative, and engine-wall gates are still
  required.
