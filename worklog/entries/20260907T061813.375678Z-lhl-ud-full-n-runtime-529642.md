# Qualify full-width raw UD runtime projections

## Summary

All 822 fixture/caller numerical cases have passing evidence on zbook /
gfx1151: 654 IQ/Q3 cases in the repaired focused run and 168 Q5/Q6 cases in
the original broad run. Twelve CPU HIP-guard checks also pass (final rerun:
0.35s). This does not qualify whole-model quality, T16 residents, or gfx1100.

## Changes

Extend `test_dense_full_output_geometry` in `tests/test_gguf_ud_dense.py` to
exercise both the raw leaf wrapper and actual `launch_gguf_linear` dispatch.
Use the detected physical backend without an environment backend override,
BF16/F32 output, rows1/8/32, all seven fixture types, and actual full-N shapes
filled by repeating two independent first/last weight-row fixtures. This tests
output geometry, not the entire published tensor payload. IQ2_XS raw residency
is explicit test construction, not a change to its BF16 model fallback.

Both callers now poison every output row before each of three launches to
detect missed writes independently of the previous result. Exact independent
reference bits and boundary canaries remain binding. No runtime code changes.

Extend `tests/test_gguf_ud_q56_roles.py` with a leaf/runtime caller axis too.
It retains seven published role/K combinations, sampled and full-payload N,
rows1/8/32, BF16/F32 output, float64 independent dot/KL checks, output-dtype
top-1, boundary canaries, and exact repeated row-isolation checks. Runtime
calls use actual default raw dispatch with GEMV decode enabled and WMMA prefill
disabled. Do not inject the leaf library for runtime calls: aligned c1 Q5/Q6
can select a pack8 decode wrapper. Let the runtime build/resolve the library
for its selected wrapper rather than forcing the leaf's library. These checks do not qualify T16 model residency.

## Review repairs

A read-only review found three gaps: physical backend selection did not bind
JIT architecture; a loadable HIP library did not establish device availability;
and singleton writes were compared only after a complete sweep, allowing an
earlier stray write to be repaired by a later launch.

`tests/_ud_hip.py` now checks HIP device count before builds/allocations,
requires one visible supported device and one unambiguous detected physical
architecture, and scopes `HIPENGINE_HIP_ARCH` to the
detected backend for the entire fixture lifetime, including lazy runtime
builds. Known unavailable-device statuses skip; unexpected statuses fail.
`tests/test_ud_hip_guard.py` verifies those cases and architecture restoration.
Q5/Q6 now reads and compares the whole buffer after each singleton launch,
updating only that row in the expected snapshot.
