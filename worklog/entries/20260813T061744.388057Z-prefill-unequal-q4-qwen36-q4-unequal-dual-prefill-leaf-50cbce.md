# Admit unequal Q4T16 prefill leaf

## Summary

Admitted a temporary exact unequal-output Q4T16 dual-WMMA prefill leaf for the
Qwen3.6-27B linear-attention `attn_qkv` K5120/N10240 plus `attn_gate`
K5120/N6144 operation boundary. This is a leaf admission, not yet a production
performance claim.

## Changes

- Added one paired-prefix kernel that reuses each K16 BF16 activation fragment
  across independent QKV/gate T16 weights for the shared 6,144 output columns.
- Added a stride-aware retained-geometry tail kernel for QKV's remaining 4,096
  columns, a raw-pointer wrapper, RED/GREEN tests, and a reusable actual-weight
  counterbalanced screen. Registry/runtime ownership is deliberately deferred
  to the separate qualification unit.
- Added no persistent layout, workspace, sidecar, decode route, or small-row
  owner. Both outputs retain their singleton K16 WMMA sequence and direct BF16
  publication boundary.

## Validation

- RED first: the named wrapper/kernel contract was absent.
- Focused synthetic HIP comparison passes at M512/M513/M1024 with byte-exact
  QKV and gate outputs versus two retained shared-B singleton projections.
- Actual `blk.8` Q4/Q4 weights, 15 counterbalanced pairs per row and board:
  XTX speedups are **1.285x / 1.164x / 1.128x** and W7900 speedups are
  **1.296x / 1.167x / 1.138x** at M512/M1024/M4096. All **90/90** pairs win;
  all QKV/gate BF16 bytes match. Sources:
  `/tmp/qwen36-q4-unequal-dual-prefill-{xtx,w7900}-final.json`.
- `rocprofv3 --kernel-trace` records both named candidate bodies at M512. The
  paired prefix and tail are each WG128, scratch0; LDS is 32/24 KiB and VGPR is
  256. Trace: `/tmp/qwen36-q4-unequal-dual-rocprof/unequal-dual_kernel_trace.csv`.
- Focused registry/contract tests, Python compilation, and `git diff --check`
  pass.
