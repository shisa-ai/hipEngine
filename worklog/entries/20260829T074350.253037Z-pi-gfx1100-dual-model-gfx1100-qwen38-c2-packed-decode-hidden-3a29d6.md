# Fix packed decode stale target hidden

## Summary

Root-cause and fix the post-K0 stale-proposal defect from the cooldown
audit: the packed AR batch decode (`step_batch_native`) never refreshed
per-session `_last_target_hidden_ptr`, so any speculative proposal seeded
after a packed AR decode consumed a verify-era hidden row and predicted from
a two-position-lagged context.

## Changes

- `step_batch_native` now copies each active session's final hidden row from
  `packed_scratch.norm` into its private one-row buffer and updates
  `_last_target_hidden_ptr`, mirroring the verify-commit path's
  target-attached contract (commit `6b580ad25`).

## Validation

- Cooldown one-shot rerun: en post-reject acceptance 2/12 (0.167) -> 4/6,
  aggregate 1.1480x -> 1.1700x, overall acceptance 0.7609 -> 0.8095; code
  holds 0.8254 / 1.1823x. The stale-hidden mechanism is confirmed and
  repaired.
- Default no-cooldown rerun: acceptance 0.8029 with every category identical
  to four decimals (0.7292/0.8182/0.8485/0.9062), ratio 1.1890x vs 1.1902x
  (AR variance), 10/10 exact, zero failures, full drain - the retained
  default path never seeds after packed AR decodes, so the fix is
  output-neutral there and the retained rows6-padded economics stand.
- Cooldown policy verdict: 1.1700x < 1.1890x at D24, so the policy is not
  retained as default; `HIPENGINE_SPECDEC2_POST_REJECT_COOLDOWN` stays off.
