# 2026-06-24 — GGUF INT8 KV non-contiguous mask diagnostic

## Changes


- Added guarded diagnostic support for non-contiguous GGUF `int8_per_token_head` long-context layouts via `HIPENGINE_GGUF_INT8_KV_BF16_FULL_LAYERS` (zero-based full-attention BF16-primary index list/ranges, e.g. `0-5,7`). The admitted no-env default remains prefix `8`; custom masks require `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1` unless they exactly match the default prefix.
- W7900/GPU0 4K mirrored layer-local probe (`scripts/qwen35_gguf_int8_layer_probe.py --prompt-length 4K --max-sequence-length 8192 --scale-dtype fp32`, cached TheRock 7.13 compiler env) showed single-layer INT8 drift is worst for full-attention layers 0..4, while layers 5..9 are individually top-1 clean at 4K/1. Suffix probes still showed combination sensitivity: suffix from layer 3 passed 4K/1, suffix from 5 and 7 flipped top-1, suffix from 8 passed.
- Tested two long non-contiguous 3-INT8-layer masks that skip the known-sensitive layer 7 with the W7900 no-mirror `128K/16` BF16-vs-INT8 gate, both under `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1` and `HIPENGINE_GGUF_INT8_KV_BF16_FULL_LAYERS`:
  - INT8 layers `{6,8,9}` / BF16 `0-5,7`: rejected, `KL mean=0.0517025`, `KL max=0.264995`, top-1 `0.823529`, candidate peak/current `25.366/24.615 GiB` (`/tmp/gguf-int8-mask-6-8-9-128k-d16.json`).
  - INT8 layers `{5,8,9}` / BF16 `0-4,6,7`: rejected, `KL mean=0.0711423`, `KL max=0.269526`, top-1 `0.882353`, candidate peak/current `25.366/24.615 GiB` (`/tmp/gguf-int8-mask-5-8-9-128k-d16.json`).
- Conclusion: non-contiguous per-token/head INT8 masks did not beat the current prefix-8 guard. The remaining plausible GGUF KV paths are a different calibrated KV format (for example key-only/value-BF16 or blockwise Q8 with real HIP write/decode kernels and long guards) or non-KV residency reduction. Compact artifact: `benchmarks/results/2026-06-24-w7900-gguf-q4km-int8kv-noncontiguous-mask-diagnostic.json`.
