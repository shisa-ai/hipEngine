# Gemma 4 P2: staging costs 1.0% of budget, so the kernel body stays untouched

## Summary

The previous entry left P2's dtype fork open on purpose: `launch_fattn` asserts
F32 Q, F32 output and F16 mask and stages F16 KV, while Gemma holds BF16 Q/out,
a uint8 keep mask and a BF16 cache, and I wrote that the staging might eat the
win. This entry closes it with a measurement, and the measurement says my
framing was wrong.

## What was measured

`/tmp/p2port/dtype_bench.hip` runs exactly the four transforms the wrapper
would have to perform, at the real global-layer geometry (tokens 512, keys
1024, 16 query heads, 2 KV heads, head_dim 512), on the AMD Radeon Pro W7900
the baseline artifacts were frozen on. Element-wise transforms are bandwidth
bound, so the benchmark uses equally cheap stand-in conversions rather than the
production ones — the number is about traffic, which is what dominates.

| transform | traffic | time | bandwidth |
| --- | ---: | ---: | ---: |
| Q bf16 -> f32 | 25.8 MiB | 0.0374 ms | 673 GB/s |
| KV bf16 -> f16 | 4.3 MiB | 0.0107 ms | 391 GB/s |
| mask u8 -> f16 | 1.6 MiB | 0.0091 ms | 172 GB/s |
| out f32 -> bf16 | 25.8 MiB | 0.0245 ms | 1028 GB/s |
| **per layer** | | **0.0817 ms** | |
| **x 5 global layers** | | **0.4087 ms** | |

**0.4087 ms against a 39.2 ms budget: 1.0%.**

## Decision

**Stage exactly as `launch_fattn` does and leave the kernel body untouched.**

That is the option that was rejected last iteration out of caution, and it is
the right one for a second reason beyond the number: an unmodified kernel body
stays verifiable against upstream. A bf16-native rewrite would have made every
future comparison "our fork versus theirs" instead of "the same code, wired
differently."

## The correction

The previous entry warned that staging "costs roughly 16 MB of f32 Q writes per
global layer per call … before the kernel runs a single FMA," implying it was a
serious claim against 39.2 ms. It treated a byte count as a cost. 25.8 MiB at
673 GB/s is 37 microseconds. The warning is recorded as a correction rather than
quietly dropped, because acting on it would have forked the kernel body and
added an f16 KV mirror to the paged-KV machinery — a real architectural change
avoided by a cheap measurement.

- Microbenchmark built with `hipcc --offload-arch=gfx1100 -O3` and run on the
  W7900; 20 timed iterations per transform after a warm-up, reported in ms and
  GB/s. Bandwidths (673 / 1028 GB/s) are in the right range for that part,
  which is a sanity check that the harness is measuring traffic and not noise.
- `python3 scripts/docs/check_all.py`: three gates pass; `published command
  drift` remains the pre-existing violation from `97d65ae0b`.
