# Close Qwen4Exp P2 exact scheduling family

## Summary

Closed the current P2 exact schedule-only family after three independent
mechanisms failed to produce a retainable whole-model win. Layers 3–26 still
own 1.849 s, but the evidence now localizes that residual to projection kernel
quality/data reuse rather than routing tails, expert worker count, serial
output width, or simple intra-CTA output concurrency. P3 is the highest-value
independent next phase while any future P2 design develops a materially new
reuse mechanism.

## Changes

- Updated the performance campaign with the P2 closure condition and rerank.
- Updated `docs/REFACTOR.md` to prevent new temporary selectors for the same
  exhausted schedule family.
- No runtime or kernel default changed.

## Evidence

- Expert worker grid 64→128:
  - both Q4+Q5_1 1.0016x, 95% CI 0.9993–1.0039;
  - Q4-only 1.0026x, CI 0.9981–1.0070;
  - Q5_1-only 0.9981x, CI 0.9950–1.0011.
- Wider serial output loops:
  - combined Q4 output8 + Q5_1 output16 0.9944x, CI 0.9897–0.9992;
  - isolated arms also non-positive.
- Concurrent Q4 output ownership with two independent exact 128-thread teams:
  0.9978x, CI 0.9927–1.0028.
- All candidates were BF16-bit exact in focused GPU tests; all candidate code
  and selectors were removed after their decisions.
- The fresh P2 profile remains the owner evidence: layers 3–26
  gate/up/down/tail `852.343/984.542/11.933 ms` (activation included in tail),
  with median 8.5 rows per active expert.

## Next

- Profile P3 shared expert, router, dense projection, and gated-residual prefill
  under current production. Select one operation-complete exact/T1 composition.
- Reopen P2 only for a mechanism that changes concurrent weight/activation reuse
  or uses independently justified T1 arithmetic; it must restart RED, actual-
  weight, whole-role, and complete-profile gates.
