# Emit selected and strict manifest hashes from direct and server paths (PN1)

## Summary

Completed the PN1 punchlist item "emit selected and strict manifest hashes
from direct and server paths". `ResolvedRuntimeProfile` now carries both the
selected and the strict immutable manifest hashes, and both are surfaced on the
generator/engine-loop direct path and the server `/v1/models`
`execution_profile` block.

## Changes

- `hipengine/execution_profiles.py`: added `strict_manifest_sha256` to
  `ResolvedRuntimeProfile`; `resolve_runtime_profile` builds the independent
  strict manifest from the strict plan's kv/graph policy and selections and
  hashes it. `construct_generator` sets
  `execution_profile_strict_manifest_sha256` on the profile-aware generator.
- `hipengine/generation/engine_loop.py`: forwards
  `execution_profile_strict_manifest_sha256` from the inner generator.
- `hipengine/llm.py`: new `execution_profile_strict_manifest_sha256` property
  (resolves without constructing a generator).
- `hipengine/server/api.py`: `_server_execution_profile` now reports
  `strict_manifest_sha256` alongside `manifest_sha256` (both engine and
  engine-None branches).
- Tests: `test_execution_profile_runtime.py` (LLM + generator strict-hash
  assertions, differs from the selected production hash),
  `test_qwen36_gguf_profiles.py` (generator strict hash equals independently
  resolved strict plan hash; strict==strict selected hash), and
  `test_server_api.py` (models endpoint reports the strict hash; engine-None
  blocks include `strict_manifest_sha256: None`).
- `docs/QWEN36-35B-ZBOOK-PRODUCTION-NUMERICS.md`: punchlist item checked.
