# Measure and gate the diffusion invariant cache: 1.139x on the diffusion frame at idle

## Summary

Measures and gates the invariant-work caching in the VibeVoice-TTS diffusion head,
landed in `7d3403163` with a carried claim of **1.0939x / ~99 ms per request**. That
claim was measured before the device solver loop (`69ec1b5dc`) changed the frame's
structure, and it was never gated by a same-session end-to-end A/B at idle.

Re-measured at HEAD by forcing the two weight-read caches to miss:

| Metric | Cached | Uncached | Delta |
| --- | ---: | ---: | ---: |
| Diffusion stage | 1.086 s | 1.2365 s | **-12.2% (1.1386x)** |
| Warm synthesis | 4.0445 s | 4.1865 s | -3.4% |
| Pooled RTF | 1.213 | 1.256 | -3.4% |

The carried 1.0939x is **superseded upward** by 1.1386x; at ~6.0 ms per frame the
per-request saving is ~150 ms, against the carried ~99 ms.

**This run is the first caching measurement whose absolute figures are comparable to
the retained headline.** The cached arm measures pooled RTF 1.204/1.222 against the
retained 1.201, so the host was idle — unlike the device-solver A/B in
`20260916T033657.511650Z`, which ran at load average 13.3 and whose absolute RTF
(~2.5) is not comparable to anything. The previous entry's own conclusion was that
the end-to-end figure "is corroborating, not decisive"; this A/B makes it decisive,
with both interleaved pairs agreeing (1.259 -> 1.204 and 1.253 -> 1.222).

The original entry attributes the win to skipped **weight reads** (4.72 MB per step
for `cond_proj`, 5.51 MB per step for the timestep MLP). The measured 1.1386x on the
diffusion frame is consistent with that mechanism.

### Arm scope is a lower bound

The uncached arm disables **two of the three** caches: it clears `_t_mlp_cache` and
sets `_cond_proj_key = None` before every `forward_into` call. The third cache —
`silu(c)` hoisted above the layer loop — is a source-level restructure and stays
active in both arms, so the measured delta is a **lower bound** on the full change.
The hoist's own cost is 4 kernel launches per step of a 128-row op, small next to the
weight-read traffic the other two caches remove.

## Validation

### Cache neutrality — exact

Cached vs uncached, over **all 25 recorded calls and every one of the 20 solver
steps**, comparing per-step `eps` and `speech`:

- `eps`: **0 of 500 steps differ**, max absolute difference 0.0
- `speech`: **0 of 500 steps differ**, max absolute difference 0.0

This is the correctness claim the caching change actually makes — the same kernels
write the same values, which are stored rather than recomputed — and it holds
bit-for-bit rather than within a tolerance.

### Frozen fixture parity — every margin reproduces the baseline

The gate metric is call0 GPU vs the CPU reference, relative to per-step peak
(`tests/test_live_vibevoice_tts_diffusion_gpu.py`):

| Comparison | Measured | Gate | Recorded baseline |
| --- | ---: | ---: | ---: |
| eps, pre-amplification | 0.00847 | 0.025 | 0.0085 |
| speech, pre-amplification | 0.01439 | 0.025 | 0.0144 |
| eps, whole trajectory | 0.0393 | 0.08 | 0.039 |
| speech, whole trajectory | 0.02013 | 0.05 | — |
| final latent vs CPU ref | 0.00603 | 0.05 | 0.006 |
| final latent vs fixture | 0.00877 | 0.06 | 0.009 |
| scaled latent vs fixture | 0.0085 | 0.08 | 0.009 |

Every value reproduces the number recorded in the test's baseline comment to its
quoted precision, so the caching change moves no margin at all.

**A raw GPU-vs-fixture comparison over all 25 calls is not a gate and was not used as
one.** Measured that way the worst absolute difference is 0.0664 on `eps` and 0.0625
on `speech`, both above the frozen single-speaker thresholds. That is the fixture's
late-step chaos, not a defect: the frozen test compares GPU against the **CPU
reference** (which shares the same conditioning) and compares against the fixture only
for the final and scaled latents, relative to peak. The fixture's post-amplification
trajectory diverges from *both* implementations — the test's own docstring records
0.32 of peak on eps at step 19 for the two-speaker case. Reporting the raw number
against the frozen thresholds would be a category error.

### Session A/B protocol

One process, one machine state, arm order cached/uncached/cached/uncached, 3 repeats
per arm, full frozen single-speaker request (121-token prompt, 27 generated tokens,
25 diffusion frames at 20 solver steps, CFG 1.3, 3.333 s of audio). `chain_exact` is
true in all four runs. Command: `uv run python /tmp/ab_cache.py`.
