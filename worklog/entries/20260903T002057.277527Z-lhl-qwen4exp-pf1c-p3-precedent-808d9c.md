# PF-1c lever-1 correction: P3 precedent and stale-blocker test

## Summary

The PF-1c "extend MMQ to the coltile-served shapes" lever collides with a
measured precedent: the (2560 -> 6144) GDN attention-gate row IS the rejected
P3 candidate (`2026-08-31-gfx1151-qwen38-flash-next-p3-q8-mmq-attn-gate-rejected.json`),
which passed every numerical scope (mean/p95/max KL
3.16e-4/0.00180/0.00668, 447/450 top-1) and improved p508 by 3.52%, but was
rejected on same-schedule state repeatability (candidate repeat 1 vs 2-3 on
`code_merge_intervals`), with the named prerequisite "localize MMQ
workspace/correction warmup state".

## Decision

1. PF-1c lever 1 for the 6144-out shape is a retest of the P3 route, not a
   fresh candidate. Its blocker may be stale: the new plane-gate harness
   (candidate x3 after a strict run, logits-level capture, `runner.reset()`
   between trajectories) has repeat determinism 3/3 green on the code
   category — the exact class of first-run effect P3 saw on its state-hash
   capture surface. Cheap discriminating experiment once the GPU frees:
   run the same harness with candidate policy = original + the
   `(2560, 6144)` row (env-free, via policy min_rows copy). Determinism pass
   => the P3 blocker was capture-surface-specific or since-fixed; proceed to
   the numerics verdict with that artifact cited. Determinism fail => the
   warmup-state localization prerequisite binds; record PF-1c lever 1 as
   blocked on it.
2. The remaining coltile grid (out=2560, ~48 launches/chunk) still needs its
   (in, out) attribution from the runner before a policy row exists for it;
   defer to the trace-join after the gate run.
