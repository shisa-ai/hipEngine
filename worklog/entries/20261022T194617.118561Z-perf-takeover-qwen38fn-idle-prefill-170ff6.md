# Use admitted capacity for idle prefill

## Summary

The Qwen4Exp generator now uses admitted runner capacity for both its idle
round budget and its per-chunk scheduler limit, instead of applying the generic
1024-token slice cap. The existing 1024-token decode-active round budget and
explicit environment overrides remain unchanged. The lead requested the larger
idle default after the measured gain and cross-chunk output differences were
reported. This product-default decision is separate from numerical gate closure;
the strict-teacher findings below remain open.

## Changes

- Diagnostic drivers under `/tmp/qwen38fn-prefill-20261022/`:
  `chunk_checkpoint.py` measures the public HTTP route with explicit chunk
  overrides; `analyze_chunks.py` records mismatches without weakening the
  original exact-output comparator; `chunk_numerics.py` compares both sizes
  on aligned strict trajectories and repeats the candidate.
- `engine_loop_config_defaults` now sets `max_prefill_chunk_tokens` from the
  runner's admitted chunk. Explicit environment overrides retain precedence.
  New tests exercise 512, 1024, 1537 and 4096 token chunks, idle/decode-active
  transitions, cancellation and explicit overrides. Four RED cases failed
  before the change; all 50 focused tests pass afterward. Root README remains
  untouched.
