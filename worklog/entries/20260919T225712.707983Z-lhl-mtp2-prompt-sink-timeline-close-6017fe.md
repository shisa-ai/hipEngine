# MTP prompt sink closes on a completed timeline instead of the last prefill call

## Summary

The NextN prompt sink is now closed by whoever knows the prompt is complete,
not by the prefill call that happened to consume the last row. This was the
blocker recorded in
`20260919T225422.403743Z-lhl-mtp2-prefix-checkpoint-sink-finish-e52730`: every
sink site in the runner passed its own call's row count to `finish`, which is
only correct while one call covers a whole prompt. A reused-prefix suffix is
prefilled in chunks, so the first segment closed a 300-row timeline at 256 rows
and every hit row failed with `streaming NextN prompt sink finished before every
row was consumed`.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: the two `finish` sites that used a
  call-local row count (`prefill_batch_native` and the slot-local per-token
  loop) now finish the sink only when that call covers the whole timeline, and
  leave it open otherwise. The two sites that already used
  `sink.total_rows` behind a `finish` flag were already correct.
- `hipengine/generation/qwen35_gguf_mtp2.py`: `finish_prompt_streaming` closes
  the sink itself before `take_final_pending_buffer`, and a sink that is missing
  rows is refused through `_abort_prompt_streaming` with
  `mtp2_prompt_fallback_reason = "prompt_stream_incomplete_k0"` instead of
  raising. A sink that does not report its progress (a test double) is treated
  as complete, so the refusal is only ever made on proof.
- `tests/test_unit_qwen35_gguf_mtp2_c1_physical.py`: two REDs -- the completing
  prompt closes a sink the prefill left open, and a sink that missed rows falls
  back to AR rather than failing the request.
