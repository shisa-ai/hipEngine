# X-5 audit complete: no kernel in the tree has any scratch segment

## Summary

X-5 records halo-box PR #87: a kernel with a private segment throttled **every later
scratch-enabled dispatch ~3.3x** (their Q5_1 expert-down GEMV: 220 -> 67 us). Its next
step was to *"List `private_segment_fixed_size` for every Qwen4Exp kernel in the prefill
and decode census."*

**Audited: 2,245 kernels across all 101 `.hip` sources in the tree, and ZERO have a
non-zero private segment.**

| | |
|---|---:|
| `.hip` sources in the tree | 101 |
| compiled | **101** |
| failed | **0** |
| **kernels audited** | **2,245** |
| **non-zero `private_segment_fixed_size`** | **0** |

## Why this is the whole tree, not a sample

All 101 `.hip` files live under `hipengine/kernels/hip_gfx1100/`; `hip_gfx1151` compiles
those same shared gfx11 sources. The audit is per-kernel, so it covers prefill and decode
alike. I checked this rather than assuming it: my first pass audited only the 5 sources
containing the hottest kernels, which would have been a 5-of-101 sample - not enough to
claim anything tree-wide. The 101-file run is the honest version.

## What it means

**The halo-box mechanism has neither a trigger nor a victim here.** Their throttle needed
a kernel that allocates a private segment. None in this tree does, so none depends on one.
There is nothing to disassemble, nothing to A/B, and no register-only-barrier candidate to
test - X-5's stated precondition is not met anywhere.

X-5's named trigger is also not ours: `flash_attn_ext_f16` is a **llama.cpp** kernel name
and does not appear in this tree.

## A secondary finding worth keeping

`private_segment_fixed_size` is non-zero whenever a kernel uses a stack - **including
register spills**. Zero across 2,245 kernels therefore means **no kernel in this tree
spills registers**. That is a clean register-allocation result, and it independently
explains why the register censuses in this campaign find kernels sitting at their
occupancy ceilings rather than paying spill traffic.

## Validation

- 101 of 101 sources compiled with zero failures; the audit reads
  `.private_segment_fixed_size` from the assembler directives of every `@function`, so a
  kernel that failed to compile would have been silently absent. Zero failures means the
  coverage claim holds.
- The "whole tree" claim is verified by enumerating `.hip` files per backend directory,
  not assumed.
- The named trigger's absence is verified by searching the tree, not assumed.
- Ledger IDs unchanged (70).
- **Static property, not a measurement.** It cannot observe a throttle; it establishes
  only that the condition X-5 names is absent. A throttle with a different trigger would
  not be detected. Compile-only, no numerical or performance claim.

## Next
