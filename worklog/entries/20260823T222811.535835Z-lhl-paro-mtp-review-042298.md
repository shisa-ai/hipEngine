# Review current PARO MTP fast/strict routes and shared proposer

## Summary

The engine architecture does not need to be discarded, but the stitched PARO
MTP provider needs a bounded redesign before more verifier tuning. The prior
`7.48%` current-packed acceptance diagnosis was stale: its July N4 evidence
predated the August 16 grouped PARO GDN-head fix. Current fast and strict routes
are identical for D24 IDs and acceptance. The fast verifier is genuinely faster
but not production-safe beyond the short gate; the strict verifier is a valid
state/token oracle. The shared proposer has three contract defects that now rank
above verifier optimization.

## Changes

- Added compact diagnostic artifact
  `benchmarks/results/2026-08-24-w7900-paro-mtp-fast-strict-review.json`.
- Updated `docs/MTP.md` current status to supersede the stale July acceptance
  interpretation and record the new repair order.
- **Current D24 canonical raw suite:** fast `decode_batched` and strict `c1_loop`
  both pass exact `10/10` prompts / `240/240` IDs and have identical accepted
  traces: `79/151 = 52.32%` draft acceptance, `79/240 = 32.92%`
  accepted/output. Fast is `97.950 tok/s`, `0.8775x` AR, `15.382 ms/cycle`;
  strict is `90.405`, `0.8114x`, `16.727 ms/cycle`. Fast saves
  `1.346 ms/cycle` and is 8.35% faster than strict on this diagnostic.
- **Current proposer cap census:** `32/72 = 44.44%` rejected drafts have a target
  token outside cap65536. General Japanese is the failure concentration:
  `24/30` rejections are cap-guaranteed and accepted/output is only 16.67%.
  A three-prompt full-vocab F16 screen raises acceptance English
  `64.29 -> 76.92%`, JA plan `27.78 -> 41.18%`, and JA explain
  `15.00 -> 21.05%`; only JA plan improves actual economics
  (`0.7853 -> 0.8271x`) because full F16 scoring adds about 0.9-1.1 ms proposal
  cost. The target's resident full-vocab W8A16 scorer is the logical reusable
  replacement.
- **State audit:** fast differs from serial AR at cycle 1 despite matching target
  tokens through cycle 8: `57/60` linear-state and `20/20` K/V records fail;
  scratch-to-resident commit itself is exact. Strict passes cycles 1/2/4/8 with
  zero failures across all 60 linear and 20 K/V records.
- **Longer horizon:** fast D64 thinking-off code heldout happens to pass and beat
  AR (`1.0496x`), but `general_en_explain` first diverges exactly at output index
  24 (`AR=13`, fast=`4016`), immediately after the D24 gate. The fast packet was
  stopped at that binding heldout failure. Strict D64 passes all four category
  heldouts / 256 IDs exactly, at `0.8418x` AR, pooled `72/181 = 39.78%` draft
  acceptance and 28.13% accepted/output.
- **Static proposer audit:** the prompt token shift/position offset matches
  nano-vLLM. The broken boundaries are:
  1. PARO captures a pre-final-norm last-layer BF16 tap; nano-vLLM-amd
     `5d8f496da5e3` and vLLM `470229c37efa` feed final output-normalized target
     hidden states to Qwen3.5 MTP.
  2. After verify/commit, the persistent proposer advances from its own previous
     MTP hidden and does not consume the selected target hidden/final row required
     by `docs/MTP.md`; it only receives target hidden during prompt prefill.
  3. The proposer owns a private F16 lm-head and scores only the first 65,536 of
     248,320 rows, whereas target AR/verifier owns a full-vocab W8A16 head.
- Strict/fast are also manually composed from several environment flags rather
  than selected through one registered strict/production PARO MTP manifest,
  allowing unsupported hybrid combinations.
