# Muse Glimmer WMMA GQA flash-prefill attention

## Summary

Wrote a WMMA flash-prefill attention kernel for Glimmer (GQA-packed 16:1,
contiguous KV, causal+SWA, FP32 online softmax) and wired it into the bulk
prefill path. Prefill rises +2.0% / +3.6% / +8.2% at 512/1K/4K. Correctness
gates green (KL/top-1 semantic anchors; argmax exact). The bit-identical
DFlash verify path is untouched (still the scalar decode-equivalent kernel).

## Changes

- `kernels/hip_gfx1100/attention/muse_glimmer_flash_prefill.{hip,py}`: one
  block per (token, KV head); the 16 Q heads of a KV head pack the WMMA row
  dimension. QK^T and PV use 16x16x16 f16 WMMA; K/V for each 16-key slice
  staged in LDS once and reused across the 16 heads. The P fragment gathers
  each key's probability from the half_id lane owning score key=2*j+half_id
  (own/partner shuffle); V is loaded transposed for the PV A-fragment.
- `runtime/muse_glimmer.py`: bulk prefill (tokens>1, not exact-multirow verify)
  routes to the WMMA kernel; decode and the bit-identical verify keep the
  scalar key-split owner.
- `tests/test_live_muse_glimmer_runner.py`: per-id top-20 diagnostic bound
  0.06 -> 0.07 (WMMA online-softmax reduction-order drift, observed max
  0.0615 vs the prior kernel's 0.0501). KL<=0.05 and top-1 remain the binding
  semantic gates and pass.

## Validation

- Kernel vs scalar attention: cosine 1.00001, maxerr 0.0005 (random Q/K/V,
  causal full attention).
- Kernel speed vs scalar: 512 2.11->1.30ms (1.62x), 1K 7.07->5.15ms (1.37x),
  4K 109.2->83.5ms (1.31x).
- `tests/test_live_muse_glimmer_runner.py`: 4/4 (llama.cpp oracle argmax +
  top-20; CPU-reference argmax + KL<=0.05; prefill/decode consistency; greedy
  coherence). `tests/test_live_muse_glimmer_dflash_exactness.py`: 2/2.
- Full AR bench (3 shapes x3): prefill 326.8 / 309.8 / 260.4 (was 320.4 /
  298.9 / 240.7); decode unchanged 11.14 / 11.03 / 10.84. llama.cpp targets
  394.4 / 385.8 / 376.3 prefill — gap remains (projections are 72.8% of
  prefill).
