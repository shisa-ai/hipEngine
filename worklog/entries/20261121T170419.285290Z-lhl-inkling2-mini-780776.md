# Reproduce Loom Inkling and check speculative output on Strix Halo

## Summary

Reproduced Loom inference on Strix Halo with the pinned Inkling GGUF and measured an ordinary decoding reference. Depth-one drafting finished sooner on these requests but changed streamed reasoning on four of six paired prompts. The differences repeated in reverse run order, so the speedup does not establish output-preserving parity.

## Changes

- No product code or defaults changed. Downloaded the target, drafter, and tokenizer into the local package and verified all three against its lockfile. Elastic backing failed during compilation (`TARGET/059`): the derived `pool_arg` value 3,643,200 exceeded the declared maximum of 2,097,152. The documented `--pool_backing=fixed` reached readiness. The smoke tests returned `Paris` and the same reasoning text at both depths.

- Greedy localhost `POST /v1/chat/completions`, one single-stream warmup per depth after the Paris smoke. Three requests per depth and prompt length. All requests processed either 47 or 575 input tokens and emitted 128 tokens with zero cached input tokens. Responses contained only reasoning at the output cap, despite the request's thinking options. Time to first token is request submission to first nonempty streamed text or reasoning delta; end-to-end is request submission to the end of the stream. At 47 input tokens, median first-delta time was 0.226 s ordinary and 0.206 s depth one; median end-to-end was 3.268 and 2.881 s. At 575 input tokens, those medians were 0.524 and 0.501 s, and 3.749 and 3.366 s, respectively. Observed decode intervals produce estimates of 41.77 and 47.48 tok/s at 47 input tokens and 39.38 and 44.33 tok/s at 575 input tokens (`127 / first-to-last delta` per request, then median; not server token timestamps). The 575-token requests recorded 136 accepted inputs from 243 draft proposals. This is a diagnostic, not a speed claim for equal outputs or a reproduction of the published card's workloads.
- Streamed reasoning hashes matched between modes for one of three prompts at each length. In the reverse-order `repeat` run, the first prompt at each length reproduced its original hash in both repeats within each mode, but differed across depths. That confirms a repeatable output difference in this configuration; it does not identify where token selection diverges.
