# Measure agentic ownership against idle baseline

## Summary

The AQ2 untimed cache-warm request completed all four model turns, then the
collector timed out while enforcing final ownership. Public state was idle in
all request/session dimensions, but the Qwen server reported 128 refcounted and
128 pinned KV pages both before and after generation. These pages are the
model-lifetime prepared resident allocation established during startup, not
request leakage. The old collector incorrectly assumed every server starts with
zero persistent KV ownership.

RED covers both layers: generic ownership normalization could not admit an
explicit persistent baseline, and the live quality collector rejected an
otherwise-idle fake server whose stable startup pool matched the real Qwen
shape. GREEN records the idle pre-request refcount/pin baseline and requires
strictly zero final deltas. A one-page delta still fails. Final quality artifact
ownership remains all-zero; persistent model allocation is separately auditable
in configuration.

This changes evidence accounting only. It does not alter model allocation,
release behavior, generation, arithmetic, prompts, sampling, or GPU execution.
The warmup outputs are not retained as quality evidence.

## Changes

- Added optional non-negative persistent refcount/pin baselines to
  `final_ownership_from_server`; cache and request ownership remain separately
  accounted and any positive final request delta fails.
- Made the quality collector verify an initially idle server, record its
  persistent ownership baseline in checkpoints/final records, and reuse that
  exact baseline for final zero-delta validation.
- Added schema/runtime validation for the two baseline fields.
- Added RED/GREEN coverage for stable 128-page ownership and a rejected
  one-page leak.
- Clarified the AQ2 ledger and artifact contract: zero final ownership means
  zero request/session delta relative to recorded model-lifetime allocation.
