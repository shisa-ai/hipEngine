# VibeVoice Q4_K_M GGUF via llama-quantize backbone-only + merge

## Summary

Q4_K_M GGUF of VibeVoice-ASR: backbone-only llama-quantize plus a merge
step that re-attaches untouched BF16 encoders; 16.66 GB -> 6.75 GB.

## Changes

- `scripts/vibevoice_asr_to_gguf.py`: `--llama-names` mode (Qwen2
  backbone renamed to llama.cpp names, arch=llama, llama.* KV added) so
  llama-quantize accepts the file; `--skip-sections` to emit a
  backbone-only GGUF; fixed rms_norm_eps metadata to f32 (u32 truncated
  1e-6 to 0).
- `scripts/vibevoice_asr_gguf_merge.py`: staples BF16 encoder/projector
  tensors from the full export onto the quantized backbone. Needed
  because llama-quantize fallback-quantizes unrecognized tensors
  (encoder 2-D FFNs -> Q4_K, 3-D convs silently re-rounded to F16),
  which we reject: the encoders stay BF16 byte-identical.
- `scripts/vibevoice_asr_wer.py`: Open-ASR-Leaderboard-style WER gate
  (LibriSpeech test-clean FLACs -> 24 kHz, Whisper EnglishTextNormalizer
  + jiwer, structured-output Content extraction; the HF datasets
  librispeech_asr stream is script-based and dead on datasets>=3).

## Validation

- Final /tmp/vibevoice-asr-q4km.gguf: 901 tensors, types {704 BF16,
  169 Q4_K, 28 Q6_K (attn_output)}; 0 non-BF16 encoder tensors;
  lm_head byte-identical (--leave-output-tensor); metadata round-trips
  (spec geometry, arrays, rms_norm_eps 1e-6 correct).
- Dequant spot checks vs HF bf16 source: q_proj/down_proj rel-max
  3.5-5.4%, cosine 0.9973; output.weight cos 1.000000.
- Exporter full-file roundtrip (901/901 byte-identical) re-verified
  after the NAME_MAP change.
