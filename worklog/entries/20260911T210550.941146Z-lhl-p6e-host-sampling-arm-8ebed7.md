# P6e host-sampling arm: the host sampler is exercised and still yields to a seeded survivor

## Summary

P6's coverage list names "native and host sampling" as modes to cover. Every arm in
this harness ran greedy (`temperature: 0.0`), which is a third path again —
`GREEDY_FAST`, neither native nor host sampling. So the mode P6 names was
uncovered. This unit adds a host-sampling arm and asserts the sampling route rather
than inferring it from the text.

## Changes

- `_host_sampling_payload()` builds a request that must take the host sampler.
  Native GPU sampling declines when `top_k` exceeds `_MAX_NATIVE_GPU_TOP_K` (64), so
  `top_k=100` with `temperature=1.0` forces `HOST_LOGITS_SAMPLE`. A `seed` keeps the
  arm deterministic, which is what makes a survivor comparable to a reference at
  temperature above zero at all.
- `_stream_completion()` accepts a `payload` override so an arm can select a
  different sampling route.
- New arm: a seeded host-sampling reference on the short prompt, then a long
  host-sampling request in flight with a seeded short host-sampling survivor.
- New gate `host_sampling_survivor_exact`: the `host_sampler_requests` route counter
  must move, both requests must return 200, the reference must produce text, and the
  survivor text must equal it. Failures name the specific condition.

## Validation

| Reading | Value |
| --- | --- |
| `host_sampler_requests` delta | **3.0** |
| `native_sampler_requests` delta | **0.0** |

| survivor status / text length | 200 / 48 chars |
| survivor text equals reference | yes |

All **ten** gates PASS. The zero native delta is the load-bearing part: text
equality alone would also have passed on the native sampler, so the counter is what
establishes that this arm exercised the route it claims to. Artifact:
[`P6e service cancel/refill proof`](results/2026-09-11-w7900-p6e-cancel-refill-service-proof.json).

50 tests pass. `performance_claim: false`, no scoreboard row.

## Two rejected attempts, both caught by the gate

1. The first payload used `top_logprobs > top_k > 0`, which does block native
   sampling but is **not an accepted request parameter** on `/v1/completions`. Both
   requests returned HTTP 400 with `unsupported_parameter`, the arm recorded zero
   host-sampler requests, and the gate **failed** — which is the behaviour that
   matters. A gate that had keyed only on "the requests completed" would have passed
   on two error responses.
2. `top_k > 64` replaces it and is an accepted parameter.

## Honest limits

- The arm exercises the host sampler on the short prompt and on a long prompt, but
  the *yield* evidence is that the survivor completed while the long host-sampling
  request was in flight; it does not separately measure the long request's decode
  gap under host sampling.
- `native_sampler_requests` staying at zero shows the host route ran, not that the
  native route is broken. P6 also names native sampling as a mode to cover, and this
  harness still does not assert a native-sampling arm.
- The seed makes the comparison meaningful only if the implementation's RNG is
  reproducible across the two requests; that held here, but a change to seeding
  would surface as a text mismatch rather than a clearer diagnosis.
- Greedy arms elsewhere remain greedy, so the harness now covers three sampling
  paths but asserts the route only for the host one.
