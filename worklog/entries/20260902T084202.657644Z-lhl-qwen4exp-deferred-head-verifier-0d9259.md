# Qwen4Exp deferred-head verifier rejection

## Summary

Rejected the strict serial-body/deferred-head verifier candidate. Preserving serial target body order and batching only final GR/head scoring is bit-exact at every rows2-8 width, but its 0.172-ms B2 head saving cannot pay for required D2D transaction ownership. The complete candidate regresses 3.52% and was removed before provider wiring.

## Changes

- Prototyped serial body execution that captured pre-head residual rows and scored them with rows-capable GR/lm-head storage.
- Ran restored-state rows2-8 RED against the serial oracle.
- Measured warmed counterbalanced B2 both without and with required transaction begin/commit.
- Removed the uncommitted candidate; retained output storage, D2D snapshot/transaction, and serial-oracle primitives.

## Validation

- Rows 2 through 8: bit-exact tokens, hidden rows, every full-logit row, GDN matrix/conv, PLE conv, residual state, position, and PLE hashes. Maximum hidden/logit difference is zero.
- Head-only B2, 3 warmups + 10 AB/BA samples: serial **126.763 ms**, deferred **126.592 ms**, `s=1.00136`.
- Complete B2 including candidate begin/commit: serial `W=127.693 ms`, candidate `C=132.354 ms`, `s=0.96478`, **+4.661 ms / 3.52% regression**.
- Full-suite reference remains MTP 51.711 s versus true AR 49.383 s; measured serial target owner is 87.652 ms/row.
- No profiler or whole-model run followed because complete-boundary economics failed first. Serial oracle remains strict fallback.
- Focused tests, JSON, worklog, campaign counter, syntax, and diff checks pass.
