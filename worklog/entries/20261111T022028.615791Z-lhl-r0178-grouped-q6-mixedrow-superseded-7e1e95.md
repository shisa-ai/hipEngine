# Close R0178 grouped-Q6 mixed-row as superseded by production WMMA target precedence

## Summary

Close R0178 (public grouped-Q6 mixed-row validation) as a gate no public route
can clear on the dense gfx1100 artifact. The planar-Q6 mixed-rowtile grouped
owner (`_Q6_T16_QMICRO_PLANAR_ROWTILE_COL8_GROUPED_ROWS8_BF16_BF16` prefix +
tail in `gguf_q6_k_t16_qmicro_planar_gemv_decode_bf16_bf16_out`) lives in the
GEMV decode producer, but the public MTP target never reaches that producer in
production: the target forces the WMMA prefill band, and the only profiles that
turn WMMA off also turn the mixed-row policy off. This confirms and makes
mechanistic the 2026-11-08 finding that R0178-R0182 grouped owners are
superseded by source-Q5/WMMA precedence on this artifact. No arithmetic or
default changed.

## Changes

- `docs/REFACTOR.md`: remove R0178 (superseded rollback/diagnostic owner; no
  public clearing route on this artifact).

## Validation

Public rollback attempt (real `create_app`/TestClient server via
`scripts/gguf_mtp_c1c8_server_bench.py`, `/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`,
`hip_gfx1100`, GPU0 W7900, hermetic TheRock env, rocprofv3 kernel trace):

- Run with `HIPENGINE_GGUF_DIAGNOSTIC_WMMA_PREFILL=0` +
  `HIPENGINE_C8_Q6_DP4A_GROUPED=0`, C8/K3/D24: engaged 10/10, `ar_mtp_equal`
  10/10, memory clean. Trace
  (`/tmp/refactor-gfx1100/r0178-trace-c8/epyc/2396089_kernel_trace.csv`) still
  shows `q6_k_t16_qmicro_planar_wmma_prefill_shared_bf16` (3800) +
  `q6_k_t16_qmicro_planar_wmma_prefill_bf16` (2280) and ZERO grouped-Q6 kernels.
  The diagnostic env does not control the MTP target.

Mechanism (source inspection):

- Target WMMA decision is `mtp_serving_target_use_wmma_prefill`
  (`hipengine/runtime/gguf_linear.py:1057`), called at
  `hipengine/generation/qwen35_gguf_mtp2.py:5311`. Returns True iff
  `profile == "production"` and not `profile_fell_back_to_strict`. No env
  override exists.
- The dense gfx1100 production binder
  (`hipengine/generation/qwen35_dense_gfx1100_profiles.py`) never sets
  `fell_back_to_strict`, so the target is always WMMA in production.
- `resolve_physical_target_rows`
  (`hipengine/generation/physical_target_rows.py:131`) returns an empty plan for
  any non-production profile, so the strict profile disables `mixed_q6_rowtiles`
  too. The mixed-row grouped owner needs the production profile for its policy
  but the production profile forces the WMMA owner that supersedes it.

Therefore no `hipengine serve` configuration on this artifact engages the
grouped-Q6 mixed-row owner; the entry's public-route clearing action is
unsatisfiable. The owner remains registered as the rollback/diagnostic path
(its grouped-vs-repeated bit parity is covered separately, per the entry's own
note that direct GPU parity is distinct from public routing).
