# Close Qwen3.8 gfx1151 memory parity

## Summary

Retained a fail-closed private-c1 memory package for Qwen3.8-27B Q4_K_S on
Radeon 8060S / gfx1151. Direct candidate measurements put process-run GTT at
**15.275/15.710/15.727 GiB** for 512/1K/4K and **15.899 GiB** for exact native
B3. Those rows are respectively **3.233%/0.670%/1.728%/2.805% below** the lower
valid llama.cpp comparator. Every retained shape finishes at token 9707, the
full ten-prompt B3 suite is exact with GPU/CPU acceptance agreement, and tracked
ownership returns to zero.

The retained package deliberately does **not** include the initially attractive
bulk-prefill aliases. Stronger final-logit and full-trajectory checks proved
owner-slot, single-arena, priority, hidden-buffer, direct file-mmap, and short-
session variants unsafe. Only exact mechanisms remain. This is a retained-
development task-24 result from the candidate diff over `4aa4bb654`; task 26
owns the clean post-commit milestone refresh and final campaign closure.

## Changes

- Added geometry/quant-scoped gfx1151 Q4_K_S policies:
  - widen the private-c1 selective immutable-weight arena through the first
    complete 80-MiB inventory crossover;
  - expose the existing 188 logical decode state/KV/workspace ranges through
    one physical owner;
  - keep all bulk-prefill fields dedicated, but cap only 4K-class capacity to
    exact 1,024-row outer chunks.
- Added private-c1 mapped Q4 token embedding on gfx1151 using an anonymous,
  contiguous, byte-for-byte copy of the 715,161,600-byte compressed table.
  Directly registering the GGUF file mmap is not retained because complete-model
  trajectories changed. Q8_0 keeps its existing CPU-copy route; shared/wider/
  device-forced consumers keep device ownership.
- Reduced native B1-B3 rollback state to the one initial snapshot it reads.
  Native committed rows already remain in the target session's row journal.
  Serial-exact and native B4 keep full per-row copies; the final B4 admission
  guard derives from `_effective_target_verify_mode(..., rows=B+1)`.
- Extended benchmark mapped-storage telemetry so artifacts distinguish
  `hip_registered_host_copy` from direct `hip_registered_gguf_mmap`.
- Added focused policy, host-copy/lifecycle, dedicated-scratch/row-cap, native-
  journal, and B4 fallback tests.
- Published the retained-development artifact and synchronized the campaign,
  benchmark rollup/changelog, and refactor ledger.

## Decisions and rejected candidates

- **Reject bulk owner slots and single arena.** At 512 both preserved repeated
  top-1 9707 but changed the dedicated oracle final logit from
  **25.418247** to **22-23**. They are not exact.
- **Reject 4K priority recoloring and hidden-owner reuse.** Full trajectories
  diverged; finite-output checks had hidden the corruption.
- **Reject short-session liveness.** The fail-closed gate caught corruption in
  the next proposal token even after isolating Q8 workspace.
- **Reject direct file-backed mmap registration.** It changed complete-model
  trajectories on gfx1151. The anonymous copied mapping passes the same strict
  final-logit and category gates.
- **Reject producer-folded initial snapshots.** It is exact but costs about 4%
  target-verify wall. Consumer-owned initial-only rollback removes the bytes
  without changing a production kernel.
- **Keep wide weights and one decode-scratch owner.** They reduce physical HIP
  ownership with unchanged requested bytes and exact output. Prior task-22
  speed-only rejection of wide Q4_K_M ownership does not apply to this separate
  Q4_K_S whole-GTT objective; the final combined rows remain inside the frozen
  1% wall guard.
- **Keep dedicated 1K outer chunks at 4K.** This removes the high-leverage 4K
  bulk-scratch growth without any overlapping fields.
- **Keep anonymous mapped Q4 embedding.** Adjacent unsampled full-suite host vs
  device is **+0.012% true AR / -0.027% B3**, while host removes exactly
  715,161,600 tracked bytes.

### Exact B3 memory and performance

The full ten-prompt category suite with native B3, one warmup, 240 timed
transitions, and continuous memory sampling reports:

- process GTT **15.898693 GiB** versus valid llama HIP B3
  **16.357529 GiB (-2.805%)**;
- tracked peak **15.655732 GiB**, down **7.439%** from task 23;
- RSS peak **4.986034 GiB** and system-available drop **17.370876 GiB**;
- B3 **23.81744 tok/s / 1.7901x own AR**, 161/248 accepted/proposed, 87 cycles,
  and 335 target rows;
- all ten greedy trajectories exact, all GPU acceptance decisions equal CPU,
  and zero active/tracked allocation after close.

A sampler-free candidate rerun measures true AR **13.36153** and B3
**23.92210 tok/s**. Its immediately adjacent device-embedding control is
**13.35991 / 23.92859 tok/s**. The mapped-host causal deltas are therefore
**+0.012% AR / -0.027% B3**, not the larger cross-session variance against the
prior one-run publication.

The final strict repeated-token audit confirms the production 512 and 4K
trajectories retain final logit **25.41824722290039** and mapped storage reports
`hip_registered_host_copy`, 715,161,600 bytes, `owns_buffer=false`.
