# Close Qwen3.8 add-RMSNorm Q8 publication

## Summary

Do not implement producer-owned Q8_1x2 publication inside the fixed-H5120
add-RMSNorm kernel. The committed 4K trace has 64 such boundaries/token, but
each standalone pack exposes 160 independent local32 blocks while the norm
producer exposes one local256 block/eight waves. Folding publication into that
producer would force 160 packs through 20 serial wave rounds.

## Changes

- Reran no benchmark and changed no production code.
- Bound the active trace precisely: 64 boundaries/token; norm, first gap, Q8_1x2
  pack, and second gap cost 0.167450/0.125795/0.096021/0.125887 ms/token.
- Reused the directly applicable gfx1151 rejection at
  `benchmarks/results/2026-07-31-gfx1151-laguna-d9-q8-pack-fusion-rejected.json`.
  That byte-exact one-block/eight-wave producer already regressed the combined
  leaf 22.085% with only 96 packs/twelve serial rounds.
- Updated the Qwen3.8 campaign so future reranks do not repeat this ownership
  seam.

## Validation

- Current trace: `/tmp/qwen38-task22-alpha-beta-conv/profile-ab/candidate/
  p4096-ar16_kernel_trace.csv`, exactly 1,024 matching triplets over 16 tokens.
- Current standalone Q8_1x2 geometry is local32 with 5,120 total threads, i.e.
  160 workgroups per layer. Fixed-H5120 norm is local256 with eight waves.
- Prior exact gfx1151 candidate preserved hidden BF16, normalized BF16, and all
  Q8_1 bytes, yet changed 0.007578 -> 0.009251 ms (+22.085%). The Qwen3.8
  serialization factor is worse, not materially different.

## Next

- Keep P5 open. Rerank independent projection work for a graph-safe scheduling
  premise that preserves block-level parallelism; do not revisit producer-owned
  norm-to-Q8 publication without a multi-block synchronization mechanism that
  first beats the standalone pack.
