# Head-sharded attention is worth 7.0% of the TP2 prefill, measured

## Summary

The head-sharded attention route is 7.0% faster than the replicated one at 512
tokens: **998.0 -> 1067.6 tok/s** (513.045 -> 479.580 ms), measured as a paired
A/B in one session rather than against a stored baseline. The attention half of
the split landed as predicted; the added reduction is what the prediction got
wrong, and it is the reason the win is 6.5% instead of 11.7%.

## Changes

- `scripts/tp2_prefill_phase_attribution.py`: `--attention-shard` selects the
  route, `--save-logits` writes the prefill's logits so the two arms can be
  compared, and `attn_reduce` is a phase of its own. It has to be: the
  head-sharded route's second reduction sits between the attention output and
  the norm that consumes the sum, which is inside what used to be the
  `norm_residual` span, and folding it there would hide the term the A/B exists
  to measure. The helper is called on both routes (a no-op when replicated), so
  the replicated arm reports it as the zero-width span it is (0.33 ms).
- `tests/test_unit_scripts_tp2_prefill_phase_attribution.py`: the phase-sum
  fixture gains `attn_reduce` and the slot table is asserted, so the boundary
  cannot drift out of the contract silently.
- `benchmarks/results/2026-09-25-w7900-tp2-attention-shard-prefill-ab.json`,
  `benchmarks/README.md`, `benchmarks/CHANGELOG.md`: the artifact, the row and
  the dated changelog line.

## Validation

`uv run python scripts/tp2_prefill_phase_attribution.py --prompt-tokens 512
--repeats 3 [--attention-shard] --save-logits ... --json ...`, four runs in one
background task in the order replicated, sharded, replicated, sharded, on
`epyc` (W7900 `0000:0d:00.0` rank 0 + RX 7900 XTX rank 1), same model
(`/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`), same session configuration
(`mode=tp2`, `bulk_prefill=True`, graphed schedule, `reduce_mode=device`, even
split, `logits_rows=1`).

- Walls: replicated `[513.045, 515.874]`, sharded `[479.580, 484.549]`. Min-vs-min
  **-33.464 ms (-6.52%)**, worst-vs-worst **-31.325 ms (-6.07%)**, and the slowest
  sharded run is faster than the fastest replicated run, so the two arms do not
  overlap.
- Rank 0 is the pacer and its phase deltas are the whole result: attention
  -109.06, `attn_reduce` +88.81, `mlp` -12.94 (`mlp_chain` -13.93,
  `mlp_exchange` +1.08), everything else under 0.4 ms. Phase sum 513.0 -> 479.6
  against the measured 513.045 -> 479.580 wall.
- Rank 1: attention -91.02, `attn_reduce` +95.56, `mlp_exchange` -28.50, so the
  balance change is visible as absorbed spin wait rather than as arithmetic.
- Correctness at the timed shape: `replicated_logits.npy` against
  `sharded_logits.npy` gives **mean KL 7.32659e-06, top-1 agreement 1.0000**,
  identical top-5. The broader gate is the 64-token agreement probe (mean KL
  0.001169, top-1 0.9844, exact host-sum reduction check at every layer of 0-4).
- `python3 scripts/sync_benchmark_readme.py --check`: synchronized.
  `python3 scripts/check_artifact_provenance.py`: 0 violations.
- `uv run --with pytest python -m pytest
  tests/test_unit_scripts_tp2_prefill_phase_attribution.py -q`: 10 passed. The
  phase-sum test fails on the new slot table before the fixture update.

## Next

- **The promotion blocker is the decode trajectory, not the prefill.** The flag
  reaches `_capture_layer_graph` as well as the bulk prefill, so a decode
  trajectory of the sharded route needs the production-profile gates before
  `attention_shard` can become the default. The replicated route stays the
  default and the registered fallback.
- The reduction is the largest single remaining term in the sharded route (177
  ms of 480 ms across both reductions, 1.38-1.39 ms/layer each). Both are near
  this host's measured staged-collective ceiling rather than at it, so the open
  question is whether the peer-spin path can reach the 11.52 GB/s
  `broadcast:rows1024:fp32` figure, worth roughly 0.5 ms/layer per reduction.
