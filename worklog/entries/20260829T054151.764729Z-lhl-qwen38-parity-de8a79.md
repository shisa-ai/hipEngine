# Parity P2.3: measured low-M dense Q4T16 prefill owner band (rows 17-64)

## Summary

First retained kernel unit of the external-parity campaign. The gfx1151 dense
Q4T16 prefill selector now routes rows 17-64 on the six physical Qwen3.8
standard-Q4 shapes to the existing 32-thread single-wave WMMA owner
(`gguf_q4_t16_dense_wmma_prefill_bf16_kernel`, 48 cols x 64-row capacity)
instead of the LDS-staged shared-B owner (48 cols x 256-row capacity).
Selection basis is a new measured owner crossover, not analogy.

Measurement (new harness `scripts/gguf_q4_t16_dense_prefill_owner_microbench.py`,
synthetic Q4T16 weights, warmup 4-5 + 20-25 iters, all outputs bit-exact
across siblings with max_abs 0.0):

- Dominant shape 5120->17408: rows 45 shared_b 1.568 ms vs single-wave 0.932
  ms (-40.6%); rows 64: -42.8%; crossover to shared_b between rows 80 and 96.
- All six shapes at rows 24/45/64: single-wave wins by 4-68%; at rows 80-96
  the field is mixed, so the admitted band stops at 64.
- Real-shape census (per-launch): 128x (5120->17408), 48x (5120->6144),
  32x (17408->5120), 24x (5120->10240), 24x (5120->12288), 16x (6144->5120),
  24x (5120->1024 router, unadmitted) per 45-token pass.

Real-model results (physical gfx1151 host, standard Q4_K_M parity model,
same protocol as the P1.3 baseline):

- Isolated forced-bulk prefill 45 tokens: **0.515 -> 0.418 s (-18.9%)**,
  n=3, medians 0.417-0.418.
- rocprof measured-pass kernel trace: single-wave owner 257.9 ms x 277
  launches; shared-B residue 5.25 ms x 25 (unadmitted shapes, fail-closed);
  pass GPU busy 534.2 -> 442.8 ms. Kernel-name/duration evidence per
  docs/KERNELS.md recorded in the artifact.

Dispatch safety: the change lives inside the existing gfx1151 rows/shape
selector for variant `t16_wmma_prefill_bf16_bf16_out` (same pattern as the
admitted small-M table); no registry key, plan selection, or manifest change.
The qualified C2/C3 rowtile cells (decode verifier shapes, rows <= 12) and
all slabs > 64 rows are untouched; unadmitted shapes retain shared-B.
