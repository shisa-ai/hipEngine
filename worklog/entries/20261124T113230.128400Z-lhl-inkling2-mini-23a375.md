# Restore the re-entry attention output as the defect

## Summary

The re-entry stack write is correct and the value written is wrong. Row 2 equals the normalization of the block's own attention output to 2.460e-06, and that attention output is 3.379 from the host's. The defect is therefore the attention output at the loop re-entry, and every downstream error follows from it.

## Changes

- Dumped the block's attention output, the stack row written from it and the visit count in one run.

## Validation

64 rows, fast profile, `hip_gfx1100`, host and block captured in one process.

| comparison | value |
| --- | ---: |
| stack row 2 vs `rms(block attention output)` | 2.460e-06 |
| block attention output vs host `a` | 3.379e+00 |
| stack row 2 vs `rms(host a)` | 8.717e+00 |

- The write is self-consistent, so the write index and the normalization are correct and only the value is wrong.
- The row-by-row match from the previous window is explained: rows 0 and 1 are prelude and boundary rows and are exact, and row 2 inherits the attention-output error.
- This restores the 3.379 branch reading on a self-consistent measurement. The earlier substitution in which replacing the attention output changed nothing conflicts with it and remains unexplained; the substitution harness wrote into `at("branch")` after the launch, which is the same location the output is read from, so the two cannot both be right.
