# Capture explicit AR and mixed Flash-Next HTTP economics

## Summary

A finite streamed HTTP capture compares true autoregressive requests with one
explicit multi-token prediction (MTP) request beside AR peers. It records
request controls and physical target telemetry separately. This entry adds the
capture tool, not a performance result.

## Changes

- `scripts/qwen38fn_mixed_economics.py` explicitly sets `speculative_mtp: false`
  in the AR arm and `true` for exactly one request in the mixed arm. Defaults
  cover widths 1/2/4/8, 64 tokens, three repetitions, alternating arm order and
  one discarded warmup.
- Both canonical category and heldout suites are loaded through the existing
  normalized prompt loader. Per-wave prompt selection is identical between
  arms; `--waves-per-cell` permits full-suite coverage instead of treating one
  wave as the category suite.
- Stream arrival times, coalesced token counts, final IDs, route/acceptance
  diagnostics, throughput and AR-peer latency are captured. No intermediate
  token timestamps are invented. Missing baseline telemetry stays missing.
- Source identity, command, suite hashes and decode snapshots accompany each
  capture. Physical requests and target verification rows are not conflated.

## Validation

- `.venv/bin/python -m pytest tests/test_unit_qwen38fn_mixed_economics.py -q`:
  38 pass, including explicit arm flags, odd/partial groups, streamed accounting,
  coalescing, missing telemetry, wave aggregation, ordering and prompt loading.
- RED-first was not used for this diagnostic-only script. Synthetic accounting
  tests were added before its first live execution. No production source or
  execution policy changes in this unit.
- Live measurement has not run yet. A green CPU test does not establish serving
  economics or that the mixed target route ran.
