# Separate Inkling four-request prefill gains from run order

## Summary

Alternating prefill schedules in one warm W7900 process shortened the measured prefill phase at both lengths. Decode time was nearly unchanged. This did not reproduce the short-cohort regression seen when switching whole source archives.

## Changes

- Scratch only. Keep one loaded engine and switch the NVFP4, Q5_K and Q8_0 tiled projection launchers and input layout between the old and current paths. Time prompt-block processing and decode separately; leave ordinary decode unchanged.

## Validation

HIPENGINE_REQUIRE_CACHED_BUILD=1 python -u /tmp/hipengine_inkling_cohort_prefill_ablation.py "$model" "$revision" "$old_k" "$old_fp4"`. Each measured cohort exercised four-wide decode and matched its serial controls. Use three warmed pairs in each run order at each length. An initial script attempted to read the device owner before the lazy load; it failed before measuring and was repaired by warming first.
- At 47 input tokens, median prefill time was 1.705 → 1.673 s with the old schedule first and 1.710 → 1.674 s with the current schedule first. Corresponding totals were 4.215 → 4.183 s and 4.242 → 4.181 s. At 151 input, prefill was 5.347 → 5.177 s and 5.317 → 5.168 s. Decode medians were close in both orders and at both lengths. The warm ablation narrows the effect to prefill in the measured workload; it does not explain the source-archive order effect or establish HTTP or Loom performance.
