# Reject Qwen4Exp router fused stable top-10

## Summary

Rejected and removed two exact projection+stable-top-10 variants. Both reuse
the retained F32 tile4 arithmetic and reproduce full logits, selected IDs,
routing weights, and reusable counter state exactly, but counter-last global
coordination costs more than the eliminated selector launch at rows508.

## Changes

- Prototyped a tile-level last-block selector and a second design assigning the
  last four completing expert CTAs to the four token rows.
- Added direct rows5/508 exact/replay RED coverage during screening.
- Removed all candidate code and tests after the binding microbenchmark loss.
- Added compact rejection evidence and updated the P3 campaign/changelog.

## Validation

- Both designs pass exact direct output checks:
  - all 512 F32 logits bit-exact to the retained tile4 producer;
  - stable top-10 IDs and F32 routing weights bit-exact to separate
    `router_select`;
  - all completion/select counters return to zero and replay exactly.
- Serial selector per tile at rows508: chain `1.877 ms`, fused `2.105 ms`
  (`0.892x`).
- Four parallel selector CTAs per tile: chain `1.877 ms`, fused `2.128 ms`
  (`0.882x`). Rows2 improves only 1.045x and cannot justify the rows508 loss.
- Candidate patch was reversed cleanly; no runtime or kernel candidate remains.

## Next

Do not retry a counter-last router fusion unless a design eliminates global
coordination or avoids materializing all 512 logits. Continue an independent
P3 shared-expert or GR operation-complete unit; retain exact tile4 plus the
separate stable selector as default.
