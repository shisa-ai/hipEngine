# Keep packed Inkling block attention output on device

## Summary

Committed-block GGUF prefill can pass attention output directly to its output projection and static convolution. The attention output no longer needs a device-to-host copy followed by a host-to-device upload.

## Changes

- Apply the existing host-computed gain on device with the same FP32 multiplication used by decode. Borrow the projection output buffer for the block and download only the convolved result. Keep the unfused path for provisional blocks and other model owners.

## Validation

- RED: the GPU fixture failed because committed blocks did not accept gain. GREEN: gain and ring behavior agreed bitwise with the serial attention plus host multiplication. The device projection test preserved the matrix path for both a one-row block and multiple rows, and confirmed the output consumer saw the expected shape.
- The CPU deterministic bundle passed. Cached `rocprofv3 --kernel-trace` on W7900 captured nine committed-block attention launches with positive durations in the focused fixture.
- `python -u ./hipengine_inkling_block_projection_probe.py "$model" "$backend"`, W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL, FP32 KV, greedy, no reuse or drafting. Against the same runtime with the block handoff disabled, first-token logits matched bitwise at 47 and 151 input in strict and at 151 in fast. All eight generated IDs matched at all tested depths, including fast at 575 and 1,027 input. All committed blocks invoked the handoff in the enabled arm, including 40 calls across ring wrap at 1,027 input on each device. This verifies dispatch and parity, not latency.
