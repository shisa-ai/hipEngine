# Own Q6 prefill cache resources through model teardown

## Summary

Replace shape-only module-global Q6 full-GEMM caches with explicit session-owned
scratch. The public 2053-token Qwen3.8 request now returns tracked allocation
bytes to zero on close, compared with the prior 727,711,744-byte residual.
Output IDs and all non-timing diagnostics match the recorded baseline.

## Changes

- Q6 workspace ownership distinguishes runtime, device and stream; a lock keeps
  dequantization and GEMM submission together. Retire streams before releasing
  temporary weights, output planes, workspace, descriptors and library handles.
- Qwen resident sessions and Muse Glimmer sessions bind their owners through the
  existing F16 staging context. Slot views do not inherit owning cache references.
  Only registered callables declaring the owner type receive its keyword.
- Direct kernel callers use a temporary owner. Plan/allocation failures clean up;
  failed synchronization retains queued-work resources for later safe retirement.
- Arithmetic and timing-based algorithm selection are unchanged. This is resource
  ownership work, not promotion of a different numerical path. No new flags.
