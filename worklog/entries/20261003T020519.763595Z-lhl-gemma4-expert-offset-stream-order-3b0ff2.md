# Order the Gemma expert-offset host read after its producer

## Summary

The BF16 by-offset expert fallback read compacted expert offsets on the default
stream while their producer ran on the nonblocking MoE stream. The blocking
D2H copy did not establish that cross-stream dependency. Dense/incremental
parity failed on the synthetic BF16-pointer layer even though captured
attention, dense and expert intermediates matched after synchronization.

Synchronizing the producing stream before the host read repairs all three
fixture seeds without changing arithmetic or thresholds. The registered
quantized selected/grouped paths do not use this host-offset fallback.

## Changes

- `gemma4_experts.py`: wait for a nonzero producer stream before collecting
  expert offsets used to size the per-expert launch. The default stream and
  quantized selected/grouped paths are unchanged.
- `test_unit_gemma4_gpu_kernels.py`: CPU-only ownership test verifies wait/read/
  launch order, row slices and stream forwarding. Expand the original
  dense/incremental parity test to seeds 777, 778 and 991, preserving its bound
  and HIP-availability guard.
- An attempted timing-event adjustment passed the original seed but failed the
  expanded seeds. It was removed; no event-policy change is in this commit.
