# P6f layer-boundary state/KV gate closed on GPU; the gate found a harness defect

## Summary

Task `#21` (P6f) named "layer-boundary state/KV validation on the actual
executor" and "exact KV/control fixtures" as the first two outstanding packet
gates blocking promotion of the layer-outer packed executor. Both are now closed
on GPU by a fifth gate in the P6e resumable-prefill proof.

The gate fingerprints the **committed** per-layer direct INT8 K/V payload, its
fp32 per-token-head scales, and the linear conv/recurrent state after the
segmented resumable prefill, and requires every one of them to equal the
one-shot reference's. Measured on the W7900 with Qwen3.8-27B `Q4_K_M` INT8 KV
(3,072-row prompt, 16 segments of 4 layers): **64 planes compared — 16
full-attention K/V pairs plus 48 linear layers — 0 mismatches**, all five gates
pass, `passed: true`, `performance_claim: false`.

The first run of the new gate reported `passed: false` with 8 mismatching
full-attention layers (35, 39, 43, 47, 51, 55, 59, 63). The defect was in the
gate, not the executor, and finding that out took four controlled GPU
follow-ups plus a unit test:

| Follow-up | Question | Result |
| --- | --- | --- |
| Four-session comparison, no interleaved decode (`/tmp/p6f_state_diag.py`) | Is the difference chunk-outer vs layer-outer? | chunk-outer ×2 and resumable at layer budgets 4 and 7 all agreed byte-for-byte on all 16 K/V payloads |
| Pristine-reference comparison (`/tmp/p6f_localize_diag.py`) | Does the resumable arm match a reference captured right after Arm A? | `final_mismatches: []` — 0 of 16 layers differ |
| Pointer + mutation characterization (`/tmp/p6f_characterize_diag.py`) | Are planes shared, and does Arm B mutate the finished session? | planes are per-session (`planes_shared_between_sessions` all false); the finished session was not mutated; resumable matched the pristine reference |
| Full-scale unit test | Where is the uninitialized memory? | the **scale planes** were hashed in full |

Root cause: `_capture_prefill_state` hashed each scale tensor over its **entire
full-context allocation**, while the payload was already clamped to the
committed prefix. The resident planes are sized for the full context and
`reset()` does not clear them, so the tail beyond `session.position` still holds
uninitialized bytes; those differ between two independently allocated sessions.
The mismatching layers were simply the ones whose tail happened to differ.

The executor was never wrong. This is worth recording explicitly because the
naive reading of the first artifact was "the resumable prefill writes wrong INT8
K/V for the last 8 attention layers", which would have been a serious
correctness claim.

## Changes

- `scripts/gguf_resumable_prefill_gpu_proof.py`:
  - New `layer_boundary_state` gate in `evaluate_gates`, with the number of
    planes compared, the mismatch count, and up to 8 mismatch records.
  - New `_device_hash`, `_committed_prefix_nbytes`, `_capture_prefill_state`,
    and `_state_mismatches` helpers. `_committed_prefix_nbytes` derives each
    plane's row width from that plane's own size and total row count, so it
    stays correct for `per_token_head`, `block16`, and `hadamard_group32` scales

## Honest limits

- The gate has one green GPU run after the fix. The pre-fix failure reproduced
  deterministically twice, and the fix removes a deterministic arithmetic error,
  but a repeat run would be the stronger stability check.
- The comparison is byte-exact between the two executors on this shape. It does
  not establish byte-exactness for other prompt lengths, other `max_positions`,
  or the `block16`/`hadamard_group32` scale granularities; the prefix arithmetic
  is unit-tested for all three, but only `per_token_head` has been measured.
- The comparison reads the raw backing plane and relies on the direct route's
  contiguous device KV. The proof already gates that route, and the payload
  comparison agreed across four sessions, so the assumption is exercised rather
  than untested.
- No throughput claim: `performance_claim: false`, and no scoreboard row
  changed.
