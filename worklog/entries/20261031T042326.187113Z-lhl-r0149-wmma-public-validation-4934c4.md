# Repair and validate WMMA scope diagnostics and concurrent execution

## Summary

Completed parent review of the WMMA scope transport in `eae532d1d` and
repaired two defects that its focused suite missed: the layer gate treated
rollback records as a scope report, and concurrent owner contexts shared the
legacy WMMA enablement toggle. Arithmetic and profile defaults are unchanged.

## Changes

- The layer gate now yields the actual resolved scope while its override is
  active. Its regression checks the same `to_report()` operation used in the
  public gate, rather than only entering the context.
- `wmma_prefill_session()` uses a ContextVar token instead of writing the
  process-wide legacy toggle. Explicit kwargs still win, nested true/false/None
  sessions retain their ordering, and explicit None delegates to the generic
  environment. `set_wmma_prefill_enabled()` remains the legacy process setter.
- The typed layer scope opens that execution-local enablement context, so
  dispatch admission, filter and memo dimensions cannot disagree across
  concurrent requests. Removed the runner's redundant global-toggle context.
- Added deterministic threaded overlap, both owner construction orders, late
  runner inheritance, empty/global opt-in, nested override precedence and an
  actual populated-cache candidate/control/candidate launch regression.
- `docs/ENVS.md` documents the explicit scope API. `docs/REFACTOR.md` removes
  completed owner transport and retains only named direct/unbound parser
  migrations and independent wide-route work.
