# YuE2 hipBLASLt algorithm selection by measured index

## Summary

With the attention kernel fixed, the NAR solve's cost moved to its projection path:
3.89 s of a 11.10 s two-step solve across 800 hipBLASLt dispatches. Both YuE2
runtimes built their problems with

```python
algorithms = [a for a in problem.algorithms(16) if a.workspace_size == 0]
self._lt_algos[shape] = algorithms[0]
```

which is hipBLASLt's own heuristic order, not a measured one, and hipBLASLt does
not sort by measured time. `scripts/hipblaslt_algo_scan.py` times every
zero-workspace candidate on the device: **the first entry is 1.4-5.7x slower than
the measured best** on these shapes, while the fifth entry (`FAST_ALGORITHM_INDEX
= 4`) is fastest in 11 of 16 scanned shapes and within 15% of fastest in the rest
(the rows=1 cases, where every candidate is under 0.5 ms).

Selecting by that index takes the projections for one two-step solve from **3.89 s
to 0.94 s (4.14x)**, the solve itself from 11.10 s to **7.95 s**, and at the
product's 32 steps from 116.53 s to **81.13 s**. The AR batched prefill route shares
the same defect and the same fix: its 18-case replay total goes from 91.3 s to
**77.6 s** while its pooled mean KL improves from 2.11e-3 to **1.16e-3** and its
worst case's max KL from 9.10e-2 to **7.10e-3**.

The choice is a fixed index rather than a runtime autotune, so two runs of the same
input select the same algorithm and stay comparable; an autotune would make the
selected algorithm a function of machine state and break run-to-run
reproducibility for no measured gain.

## Changes

- `hipengine/core/hipblaslt.py`: `FAST_ALGORITHM_INDEX = 4`, plus
  `HipblasLtProblem.zero_workspace_algorithms()` and `.fast_algorithm()`. The
  docstring carries the measured spread and the reproducibility reason for a fixed
  index. The existing `algorithm(preferred_index=4)` convenience selector is
  unchanged, and the Laguna routes that use their own tuned indices are untouched.
- `hipengine/runtime/yue2_ar.py:_prepare_lt`: selects with `fast_algorithm()`.
- `hipengine/runtime/yue2_nar.py:_prepare_gemm`: selects with `fast_algorithm()`.
  Both keep the previous failure behavior (a RuntimeError when no zero-workspace
  candidate exists, which `_prefill_batched` catches to fall back to the strict
  route).
- `scripts/hipblaslt_algo_scan.py`: new. Times every zero-workspace candidate for a
  shape on the device and reports each one's time and TFLOP/s plus the ratio
  between the first and the best.

## Validation

This change alters production arithmetic, so the evidence is the profile gates
rather than bit parity.

- `python3 scripts/hipblaslt_algo_scan.py --rows 1299 --repeat 6` and the same at
  rows 1, 64, 512, 2048: at rows 1299 the four production shapes measure
  6.25/7.03/2.37/1.18 ms at index 0 against **1.62/1.66/0.83/0.33 ms** at index 4
  (3.86x / 4.23x / 2.86x / 3.59x, and 20.2 / 19.7 / 13.1 / 16.6 TFLOP/s).
- M4 solver gates, all three, all pass: chunk0 latents **rel L2 0.01248, cosine
  0.999923, 15.7% BF16-exact** (recorded 0.01225 / 0.999926 / 16.2%), multi-chunk
  0.01071 / 0.999944 (unchanged to the last digit), restricted visibility 0.00905 /
  0.999960 (recorded 0.00885 / 0.999962).
- `python3 scripts/yue2_ar_replay.py`: status **pass**, 18 cases, pooled mean KL
  2.11e-3 -> **1.16e-3**, worst-case max KL 9.10e-2 -> **7.10e-3**, top-1 96.70% ->
  95.49%, top-8 96.05% -> 95.88%, prefill total 91.3 s -> 77.6 s.
- `python3 scripts/yue2_session_gate.py`: **PASS** on all three cases, with the
  semantic teacher-forced agreement slightly better on every one (97.9/96.9/96.1%
  -> 98.2/97.1/96.7%) and ABC 99.1%/100% -> 99.1%/99.7%.
- `python3 scripts/yue2_e2e_gate.py --only mandarin-off-s1234 --skip-live`: 2 steps
  **7.95 s solve + 20.06 s decode = 28.02 s**, 32 steps **81.13 s + 20.10 s =
  101.23 s**, both at 1297/1297 frames, 2490176/2490176 samples, bit-identical
  determinism and `torch imported: False`.
- `python3 -m pytest tests/test_unit_yue2_*.py tests/test_gpu_hipblaslt.py`: 221
  passed.
- Artifact: `benchmarks/results/yue2_m7_gemm_algorithm_20260917.json`.

Host: zbook, AMD Radeon 8060S / gfx1151, 40 CU, ROCm 7.15.26333. Every figure is
gfx1151; gfx1100 is unverified for this route. The measured index is a property of
this hipBLASLt build on this host, which is the fragility `docs/ROCM-AI.md` already
records; `scripts/hipblaslt_algo_scan.py` is the way to re-establish it on another
ROCm version or device.
