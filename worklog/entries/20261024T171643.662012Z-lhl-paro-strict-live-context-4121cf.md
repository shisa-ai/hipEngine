# Match strict verifier attention selection to scalar AR

## Summary

The strict public verifier now selects full attention from each row's live
context, just as scalar AR does. Its spans previously advertised the 8192-token
capacity at a 29-token context, forcing split-K while AR selected dense
attention. Before the fix, the code prompt first diverged at output index 89.
After it, all 129 generated tokens match, and the captured hidden, full-logit
and committed state comparisons are byte-exact.

## Changes

- Pass the known row position into `_verify_chain_row_spans` in both its scalar
  and row-context batched callers. Set append/decode bounds to position and
  position + 1 rather than allocation capacity. No new flag or arithmetic kernel.
- Add seven CPU regression positions: 28, 116, 511, 1022, 1023, 1024, 1759.
  They cover both sides of the 1024-token selector and unrelated contexts.
- Record the before/after public crossed-state capture in
  `benchmarks/results/2026-10-24-w7900-paro-strict-crossed-state.json`.

## Validation

  repair. The pre-fix live capture also starts from byte-identical initial
  AR/verifier states but produces different hidden, logits and committed state.
- GREEN: `uv run pytest -q tests/test_unit_paro_verifier_context.py
  tests/test_unit_paro_mtp_depths.py tests/test_unit_paro_mtp_provider_contract.py
  tests/test_unit_qwen35_paro_mtp2_seam.py
  tests/test_unit_qwen35_resident_batch_layout.py` passes all 235 cases.
- `uv run ruff check tests/test_unit_paro_verifier_context.py` passes.
- Live W7900 strict/BF16/B3 public requests use the packed MTP model, greedy
  ignore-EOS sampling, 129 outputs, 8192 capacity, CPU acceptance validation and
  an unfused full LM head. At root indices 0, 83, 87 and 91, all eight crossed
  forwards (AR-carried and verifier-carried at each index) produce exact hidden
  and logits equality; selected canonical state also matches. Full-distribution
  KL is zero in every compared row. AR/verifier carried states are byte-identical
  at all four checkpoints. Restoring and replaying the public call reproduces
  its original logits and state exactly at each capture.
- The pre-fix run has initial same-state hidden/logit/state differences and a

  attributing the result solely to accumulated rounding or near ties.
