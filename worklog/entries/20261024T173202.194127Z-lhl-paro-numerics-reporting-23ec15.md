# Report PARO numerical samples without policy overclaims

## Summary

The B1 PARO teacher-forced numerical diagnostic now reports current sparse-MoE
and historical mean/tail sample comparisons separately, without deciding a
production-policy gate from one prompt. Registered manifests, observed route
flags and capture hashes replace stale claims that the production verifier is
unregistered. This corrects the reporting recommendations in
`20261024T134128.306639Z-lhl-paro-correctness-review-25a9ba.md`.

## Changes

- Report both named envelopes and their raw metrics. The sparse-MoE envelope
  uses median/p90 KL, flip damage and global/category top-1 observations;
  the historical envelope preserves its mean/tail and top-1 comparisons.
- Keep every rate comparison observational, including Wilson intervals beyond
  a limit. One prompt never becomes a full protocol by accumulating 1,548 rows.
  Continuous comparisons have no calibrated controls or screen/full ratio
  interval here, so policy decisions remain inconclusive at every sample size.
- Separate independent execution failures (nonfinite logits/KL, prefill-root,
  route, task-decision or manifest disagreement) from numerical observations.
  Schema v5 exposes `execution_checks`, `policy_decision`, sample scope and
  explicit qualification limits. Exit 0 means a clean but inconclusive sample;
  exit 1 means execution failure, 2 usage error and 3 diagnostic-scope error.
- Read strict/production manifests from the registry; bind captures to prompt,
  manifest, rows and cycles. Record ambient selectors and actual route flags.
  Restrict this diagnostic to gfx1100 because its binder/manifests describe
  that backend; this does not change normal runtime model admission.
- Add regressions for policy boundaries, execution failures, backend provenance
  and envelope disagreement. Compare whether each envelope exceeds any sample
  limits, not their differently named metric lists, when reporting disagreement.
