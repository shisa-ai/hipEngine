# Match the convolution taps and retire the plan comparison

## Summary

The block and the host build their convolution taps from the same expressions, so the taps are not the re-entry defect. The planned plan-field comparison is not available either: the host builds its attention inline in `_prepare_layer` and never constructs an attention plan.

## Changes

- No code change; both questions were settled by reading the two implementations.

## Validation

| use | host | block |
| --- | --- | --- |
| dynamic taps | `static_w` transposed and reshaped to `(nkv * dim, ksize)` | `static_taps`, identical |
| static taps | `sconv.weight[:, 0, ::-1]` | `kv_taps`, identical |

- The host selects between them with `device_conv` and `static_conv` on the same `not visit.is_local` condition the plan uses.
- `_prepare_layer` reaches the attention through inline closures and `device_conv`, and never calls `_attention_plan`, so there is no plan object on the host side to compare fields against.

## Next

- Compare the remaining launch-level difference: the host's `device_conv` closure and the plan's `convolve` closure, argument by argument, including the row shapes passed to `apply_dynamic` and whether the output projection consumes the same convolution state. If those agree, the defect is in the attention kernel's argument list, and the comparison moves inside `project_attention_resident` for the re-entry visit only.
