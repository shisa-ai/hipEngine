# Split the colliding Q5_1 T16 layouts after the main merge

## Summary

Both parents of the origin/main merge (`5decbf124`) defined
`repack_gguf_q5_1_tile16` / `unpack_gguf_q5_1_tile16` and `GGUF_Q5_1_T16_*`
in `hipengine/quant/gguf_t16.py` with different byte layouts:

- branch (`4c8ce6b5c`): packed — d | m | ql nibble planes | qh words,
  384 bytes per 16-column block. Read by the expert-major Q5_1 WMMA kernel
  (`Q5_1_T16_*` in `gguf_k_t16_selected_prefill.hip`) and populated by
  `qwen4_exp_materialize.py` for the qwen4exp T16 down route.
- main (`52b087148`): the registered `gguf_q5_1_t16_v1` layout — d | m |
  pre-expanded value planes in 16-K tiles, 576 bytes. Read by main's Gemma 4
  loader and the grouped Q5_1 T16 prefill kernel.

The merge kept only main's definitions, so the branch's consumers got main's
layout. `tests/test_gpu_gguf_q5_1_t16_expert_major_wmma.py` passed on the
branch and failed 4/4 at the merge (KL 0.16-1.14 against 0.05). The qwen4exp
T16 down route is env-gated off by default, so the default qwen4exp path was
not affected.

## Changes

- `gguf_t16.py`: restore the branch layout as
  `repack_gguf_q5_1_tile16_packed` / `unpack_gguf_q5_1_tile16_packed` with
  `GGUF_Q5_1_PACKED_T16_*` constants. The bodies are the branch's verbatim
  under the new names; the output is byte-identical to `4c8ce6b5c`'s repack.
- Point the branch-side consumers at the packed names:
  `loading/qwen4_exp_materialize.py`, the `qwen4_exp_runner.py` comment,
  `scripts/qwen4exp_moe_owner_ab.py`, `scripts/qwen4exp_t16_populate_tiles.py`,
  `tests/test_gpu_gguf_q5_1_t16_expert_major_wmma.py`,
  `tests/test_unit_gguf_q5_1_tile16.py`, `docs/QWEN4EXP-T16-RESIDENCY.md`, and
  the kernel's layout comment. Main's consumers keep the unsuffixed names.
