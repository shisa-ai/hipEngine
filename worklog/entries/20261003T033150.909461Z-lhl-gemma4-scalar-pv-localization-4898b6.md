# Ascending FP32 PV removes drift with strict scores and statistics

## Summary

With strict QK scores, global strict softmax statistics and no full-attention
split, replacing residual WMMA P*V with ascending-key FP32 P*V reproduces both
saved failing chains bitwise. Code merge-intervals and mixed-summary each have
64 identical logit rows, zero KL and top-1 agreement 1.0. The same score/global
statistics control with residual WMMA P*V failed both chains in
`20261003T032450.914501Z-lhl-gemma4-global-statistics-localization-5962c4.md`.

This localizes the remaining drift in that controlled configuration to the
combined probability representation/P*V accumulation changes. It does not
separate BF16 residual probability approximation from WMMA accumulation order,
and does not certify the original WMMA score or online-softmax arithmetic.
The diagnostic is multi-pass, leaves ordinary expert routing unchanged, and is
not a shipping optimization. No performance claim or production promotion.

## Changes

- `benchmarks/results/2026-10-03-gemma4-scalar-pv-localization.json`: helper source
  and hashes, identical-input checks, two complete 64-row screens and explicit
  bitwise logit comparisons.
- External helper computes strict scores/global statistics, converts scores to
  FP32 unnormalized weights, and calls the strict ascending-key decode P*V helper
  from independent row/head blocks. The external selected WMMA launch executes,
  then its output is replaced before the model consumes it. No teacher-dependent
  expert decisions are copied or changed. Raw data/builds stay under `/tmp/`.
- No shipping source, registry, sampler or default changed.
