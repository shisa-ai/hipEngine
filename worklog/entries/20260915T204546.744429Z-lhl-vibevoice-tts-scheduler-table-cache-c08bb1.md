# Cache the solver alpha-bar tables: 524 us/frame of pure recomputation removed, bit-identical

## Summary

`DPMSolverMultistepScheduler.__init__` rebuilt the alpha-bar tables on every
construction, and `sample_speech_tokens` constructs a scheduler once per diffusion
frame -- 25 times per request. The build is a Python-level loop over all 1000
training steps using fp32 scalar arithmetic (it mirrors torch's sequential fp32
accumulation, so it cannot be vectorised), measured at **524 us per construction**.
The tables depend only on `num_train_timesteps`, so they are now computed once and
shared. **13.10 ms per 25-frame request** of pure recomputation removed, with the
tables verified bit-identical.

## Changes

- `hipengine/kernels/cpu_reference/vibevoice_tts_diffusion.py`: new module-level
  `_ALPHA_BAR_TABLES` and `_alpha_bar_tables(num_train_timesteps)`, which builds
  `(alphas_cumprod, init_sigmas)` once per schedule and returns the cached pair.
  `DPMSolverMultistepScheduler.__init__` now takes both from it instead of
  recomputing. The arithmetic is unchanged -- the same `betas_for_alpha_bar` call
  and the same sequential fp32 cumulative product.
- `tests/test_unit_vibevoice_diffusion_scheduler_cache.py`: new. Pins bit-equality
  of the cached tables against an independent recomputation, that repeated
  construction reuses one pair, that a different `num_train_timesteps` gets its own
  tables, and that scheduler observable state (`_step_index`, `lower_order_nums`,
  `model_outputs`) is unaffected.

Safety of sharing: the scheduler writes `self.alphas_cumprod` but never reads it
back, and reads `self.init_sigmas` read-only via `np.interp` in `set_timesteps`.
Neither table is mutated, so sharing across instances cannot leak state. This was
checked by grep before the change.

## Validation

```
alphas_cumprod bit-identical vs independent recomputation: True
init_sigmas    bit-identical vs independent recomputation: True
cold (builds tables): 524.1 us
warm (cached)       :   0.1 us   -> 524.0 us saved per frame
per 25-frame session: 13.10 ms saved
```

- `uv run pytest tests/test_unit_vibevoice_diffusion_scheduler_cache.py` -> 4 passed.
- `uv run pytest tests/ -k vibevoice` -> exit 0, 100% progress, no failures
  (same ~126 passed / 11 skipped as before the change).
- `chain_exact: true` and `negative_conditions_match: true` on the real request,
  so the generated token chain is unchanged.

### On the end-to-end RTF

The confirming bench run measured `pooled_rtf` 1.381 / `warm_synthesis_seconds`
4.605, which is **not** a regression: every stage was uniformly elevated (lm 1.450
-> 1.665, diffusion 1.298 -> 1.413, decode 0.301 -> 0.379, semantic 0.781 -> 0.930),
consistent with sustained host load across many runs on this shared machine. A
0.33% effect cannot be resolved against that noise, so the change is justified by
the direct micro-measurement (524 us x 25 = 13.10 ms) plus bit-exactness, not by the
end-to-end RTF. The benchmark artifact was restored rather than overwritten with the
noisy run.

## Next

This is a waste-elimination, not a structural fix. The diffusion stage's real cost
remains `forward()` at 83% (41.382 ms/frame across 42 kernels per step) plus a
6446 us/frame D2H/H2D sync cost that is 76% of the host loop. The device-side CFG
combine and DPM step from iteration 34 remains the cleanest structural target, worth
up to ~0.16-0.21 s (~4-5% of warm).
