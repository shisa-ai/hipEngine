# Extract packed verifier layer-stack owner

## Summary

Moved the packed verifier's inline layer walk out of
`Qwen35GGUFResidentSession.verify_target_blocks_batch` into
`hipengine/runtime/qwen35_gguf_verify_layer_stack.py`, and integrated that owner
into the actual runner at parent commit `792108e0c`. The owner holds the
synchronous layer ordering, the BF16 hidden ping-pong, the two aggregate
wall-clock stage marks (`packed_verify_linear_attn_layers`,
`packed_verify_full_attn_layers`) and the packed full-attention GPU mark
(`packed_verify_gpu_full_attn_layers`).

The first revision exposed a single binding record with an operation string and
an arbitrary `run_rows` thunk. The parent rejected that as a callback schedule:
the string merely labelled a closure and the orchestration stayed hidden. The
integrated API uses three typed binding variants with fixed fields and the
executor's own call sites:

- `VerifyOrdinaryLinearLayer(layer_id, rows, run_linear_rows, scratch,
  decode_scratch, linear_state_rows, commit_final_linear_state, stream)`
- `VerifyMoeC2LinearLayer(layer_id, rows, run_moe_c2_linear_rows, scratch,
  decode_scratch, linear_state_rows, state_capacity, state_indices, stream)`
- `VerifyFullAttentionLayer(layer_id, rows, run_full_attention_rows, scratch,
  split_workspace, stream)`
- `VerifyLayerStackHidden(first, first_ptr, second, second_ptr)` - the pointer
  fields are the execution view; the buffer fields only let the caller receive
  the final endpoint.

Each `run_*` field is the selected function object, and `_run_layer` spells out
every argument at the call site (rows, decode scratch, state rows, capacity,
indices, split workspace, stream, the fixed `expert_sidecar=None` /
`hidden_f32_ptr=None` / `out_f32_ptr=None` / `stage_timings=None` /
`sync_stage_timings=False` values, the fixed stage prefixes, and the executor's
recorder). Nothing is invoked through `**kwargs`, `partial`, `getattr` or a
callback bag. The session resolves values only; it passes no runner, session or
scratch proxy.

The runner keeps ownership of everything else: layout, initial-state sync,
embeddings, output norm, hidden-seed copy, sampling/LM head, scatter,
cursor/commit/rollback, cancellation, recorder lifetime and graph/prefix
ownership. The new session adapter `_packed_verify_layer_stack_plan` resolves
every layer binding before execution.

The integration diff touches only the owner import block, the packed layer loop
and the new adapter. The committed FP16 recurrent-state work
(`_freeze_fp16_recurrent_state`, `_resolve_fp16_recurrent_state`) and the
Q4 rowtile bindings are unchanged; the only moved line that mentions recurrent
state is the `linear_decode_scratch` rebind, now inside the adapter.

## Changes

- New `hipengine/runtime/qwen35_gguf_verify_layer_stack.py`: the typed binding
  variants above, `VerifyLayerStackGeometry`, `VerifyLayerStackPlan`,
  operation Protocols (`LinearRowsOperation`, `MoeC2LinearRowsOperation`,
  `FullAttentionRowsOperation`), stage/prefix constants, `_validate_plan`,
  `_run_layer` (explicit call sites) and
  `run_verify_layer_stack(plan, *, stage_timings, gpu_stage_recorder=None)`.
  The module imports only `__future__`, `time`, `dataclasses`, `typing` and
  `hipengine.loading.qwen35_gguf`.
- `hipengine/runtime/qwen35_gguf_runner.py` (integrated): owner import block;
  the inline packed loop and the `src`/`dst`/`linear_decode_scratch` preamble
  are deleted; `src = run_verify_layer_stack(self._packed_verify_layer_stack_plan(...), ...)`
  runs inside the existing selected-operation contexts; the new
  `_packed_verify_layer_stack_plan` adapter sits after
  `verify_target_blocks_batch`.
- `tests/test_unit_mtp_sampled_concurrency.py`: the one necessary retarget.
  `test_packed_verifier_preserves_resident_initial_state_owner` now reads the
  adapter method, because the preserved `linear_state_owner` IfExp moved there
  verbatim. The test body and evaluation are unchanged. No other existing test
  needed editing: the GPU integer-MMQ test still finds
  `_q6_integer_mmq_context(target_verifier=True)` in the method, and the
  timing-teardown, packed-layout and layer-execution suites are unchanged.
- New `tests/test_unit_qwen35_gguf_verify_layer_stack.py`: ownership boundary
  (imports, frozen field lists, no `operation`/`run_rows` fields, no `**`
  call unpacking, no `partial`/`getattr`), exact fixed-argument assertions for
  ordinary linear, MoE C2 and full attention, ordering/ping-pong/stage/GPU-mark
  execution, plan-consistency rejection, operation/GPU-mark/stage-sink failure
  containment, the 24-case packed-verifier control trace, failure containment
  through `verify_target_blocks_batch` (ordinary linear, MoE C2, full
  attention, GPU mark), session-resolves-first, fail-before-any-op on an
  unsupported layer type, and the runner-delegation boundary.
- New `tests/fixtures/qwen35_gguf_verify_layer_stack_control.json`: the exact
  operation/argument/stage/mutation trace captured from the committed inline
  loop at `b1a621b75`, before any edit. It is unchanged by the API revision and
  still matches exactly after integration.

Moved symbols and side effects:

- The executor now owns the argument mapping for all three selected operations;
  the adapter supplies only resolved values and the function objects.
- `_verify_linear_state_row_pair`, `_packed_full_attention_scratch_for_layer`
  and the `cos_table`/`sin_table` rebind now run during plan construction,
  inside the same selected-operation contexts as before. They are host-only
  lookups/replaces on this path.
- Two intentional differences: an unsupported `layer_types` entry now raises
  before any layer runs (it used to raise after earlier layers ran), and
  per-layer resolution is no longer charged to that layer's aggregate
  wall-clock mark.
