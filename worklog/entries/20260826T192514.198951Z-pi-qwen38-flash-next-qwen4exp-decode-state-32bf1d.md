# Own transactional Qwen4Exp decode state

## Summary

Added explicit persistent Qwen4Exp decode-state ownership for FP32 GDN matrix
state, FP32 GDN Conv histories, FP32 PLE dilation history, and widened BF16
residual state with transaction snapshot/restore semantics.

## Changes

- One owner allocates/zeros all four state classes, reports bytes independently,
  unwinds partial allocation failures, and closes in reverse idempotently.
- Snapshot copies every owner to immutable host arrays; restore validates owner
  set and byte sizes before device copies. This is the correctness fallback for
  cancellation/rollback before device journals are optimized.

## Validation

- RED: state test failed collection because `Qwen4ExpDecodeState` did not exist.
- GREEN: `uv run pytest -q tests/test_qwen4_exp_state.py` -> passed on
  Radeon 8060S/gfx1151.
- State + runner GR focused bundle -> `2 passed`.
- Every owner was filled with a distinct byte pattern, snapshotted, zeroed and
  observed zero on device, restored array-exact, then closed twice; post-close
  snapshot fails closed.
