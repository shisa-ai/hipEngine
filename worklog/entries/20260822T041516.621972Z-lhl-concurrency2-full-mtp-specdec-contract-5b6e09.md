# Specify full MTP and SpecDec support in Concurrency2

## Summary

Made full MTP and generic speculative decoding an explicit Generation-2
continuous-serving contract rather than an inferred consequence of the existing
`NativeSpecCycle` milestones. The target replica's `EngineService` remains the
sole request, transaction, resource, and output owner; proposal and verifier work
enter the same scheduler as bounded peer work classes.

The contract distinguishes independent request count `C` from flattened
verifier rows `V`, requires one-to-many row ownership and chain/tree metadata,
keeps verifier cost maps separate from AR/D2 maps, and defines atomic provider +
target resource claims, transaction/failure behavior, fairness charging,
streaming/sampling semantics, graph keys, backend inheritance, implementation
order, and the full product gate. Existing guarded GGUF MTP and `N0`-`N4`
components are migration inputs, not a claim of full continuous SpecDec support.

## Changes

- Added a `C2-S MTP/SpecDec integration` row to the current product-status table.
- Added `docs/CONCURRENCY2.md` "Full MTP and generic speculative-decoding
  support" with normative scheduler-facing `SpeculativeRequestState`,
  `DraftBatch`, `SpecTransaction`, and `AcceptResult` shapes.
- Defined plugin/resource ownership, work-based fairness and budgets,
  verifier-specific lowering/cost evidence, exact commit/rollback and
  pre-/post-launch fallback rules, streaming/stop/RNG semantics, and bounded
  native-cycle behavior.
- Clarified that shared host orchestration is inherited by gfx1151 while kernels,
  graphs, transaction layouts, cost maps, correctness, and performance promotion
  remain backend/model/provider-specific qualifications.
- Added ordered `SPEC-C0` through `SPEC-C5` implementation units and a complete
  continuous-serving acceptance matrix, including full multi-prompt `mtp-bench`
  categories/heldouts against a true same-protocol AR baseline.
