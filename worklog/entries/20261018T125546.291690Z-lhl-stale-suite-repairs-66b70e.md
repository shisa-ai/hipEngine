# Repair stale default-suite tests and stop profile env leaking across tests

## Summary

The whole-suite gate now completes without aborting and the failures it exposed
were stale tests, not product defects. Six distinct causes, each fixed at the
cause rather than by weakening an assertion: an over-size benchmark scoreboard,
a provenance checker that mis-normalised a doubly decorated quant key, two
dry-run build tests that assumed a bare environment, a reasoning test that
asserted on the whole response body instead of the served text, a fake request
missing two fields the normaliser reads, and profile binders leaking
`HIPENGINE_*` variables into later tests in the same process.

## Changes

- `benchmarks/README.md`, `benchmarks/HISTORY.md`: nine superseded
  diagnostic/screen sections moved to the archive so the scoreboard is back
  under its 150 KB compactness contract (153,971 -> 143,338 bytes), with the
  intro and `Last updated` line kept in the scoreboard.
- `scripts/check_artifact_provenance.py`: `_norm_quant` strips decorations in a
  loop. It returned after one strip, so `gguf_ud_q4_k_xl` read as `UDQ4KXL`
  while its own display form `UD-Q4_K_XL` read as `Q4KXL` and the artifact was
  reported as a quant/model conflict.
- `tests/test_unit_scripts_check_artifact_provenance.py`: new case for the
  doubly decorated key.
- `tests/test_unit_build.py`, `tests/test_unit_smoke_add_plan.py`: clear
  `HIP_DEVICE_LIB_PATH` and `HIPENGINE_ROCM_DEVICE_LIB_PATH`, so the dry-run
  plan is the same in a developer shell as in CI. The production behaviour that
  adds `--rocm-device-lib-path` when the variable is set is unchanged.
- `tests/test_integration_poolside_v1_reasoning.py`: assert the stop marker is
  absent from `content`/`reasoning_content` and that `matched_stop` names it.
  The documented telemetry reports which stop string matched, so a body-wide
  substring check was wrong; the "nothing behind the stop" check stays.
- `tests/test_gpu_qwen38_packed_c1_accept_depth_gpu.py`: the fake request now
  carries `grammar` and `thinking_hard_token_cap`, the two fields the
  speculative normaliser reads when it decides whether a stop is a grammar
  completion or a budget exhaustion.
- `tests/conftest.py`: the existing collection-time baseline and per-test
  restore now also covers `HIPENGINE_*` environment variables, because profile
  binders write them straight into `os.environ` and never restore them.
