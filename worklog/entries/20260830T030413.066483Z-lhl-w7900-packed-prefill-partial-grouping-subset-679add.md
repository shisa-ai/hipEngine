# W7900 Qwen3.8: grouped AR prefill takes the compatible subset instead of refusing the wave

## Summary

`_try_prefill_native_work_batch` refused an entire multi-request prefill item if any
single row was incompatible, and `prefill_batch` then prefilled **all** rows serially.
Because the scheduler selects the first `max_rows` active requests without testing
compatibility, one lane over `DEFAULT_MAX_PREFILL_CHUNK_TOKENS` (256) - or one
prefix-reusing lane - was enough to cancel grouping for every other lane in the wave.
The guard now partitions: it groups the largest compatible subset and returns the
handled request ids; the caller skips them and serially prefills the remainder.

Found by writing the fixture I had just ledgered in `docs/REFACTOR.md`, not by a
measurement: the standard suite (35-67 tokens) cannot produce this case, so the
end-to-end capability-8 run in flight would never have shown it.

## Changes

- `hipengine/generation/qwen35_gguf.py`:
  - `_try_prefill_native_work_batch` returns `frozenset[int]` of handled request ids
    instead of `bool`; per-row eligibility became a list comprehension, and a subset of
    one is still refused (`len(eligible) <= 1`), so behaviour is unchanged for waves
    where nothing or everything is compatible.
  - `prefill_batch` consumes that set: it no longer returns early, it skips handled
    ids and serially prefills the rest. Skipping is required - handled rows already had
    `prefill_tokens_seen` set and their native prefill finished, so re-prefilling them
    would duplicate KV.
  - Still inert by default: the route is unreachable while `packed_prefill_max_rows`
    is 1, and with an empty handled set `prefill_batch` behaves exactly as before.
- `tests/test_generation_qwen35_gguf_sampling.py`:
  `test_resident_ar_packed_prefill_survives_one_over_long_lane` written RED first (the
  guard returned `False`, so seven compatible lanes fell back to serial); now green, it
  asserts seven grouped rows in one call **and** `prefill_tokens_seen == 0` for the
  long lane, which is what proves the long lane was left for the chunked path rather
  than silently consumed.
  The two earlier guard-level tests were retargeted from `is True` to set equality;
  their semantic claims (mixed lengths group; per-row lengths are forwarded) are
  unchanged.
- `docs/REFACTOR.md`: the ledger item now separates what landed from what is open.

## Validation

- RED observed first: `assert False is True` - "a single over-long lane refused the
  whole item".
- `pytest tests/test_generation_qwen35_gguf_sampling.py tests/test_gguf_prefix_cache_runner.py -q`
  -> **127 passed, 1 skipped**, including the five pre-existing packed-prefill tests
  (`runs_one_native_c8_slab`, `notimplemented_falls_back`, the serving-route
  mixed-length test, and the capability tripwire).
- File parses; edits applied by atomic `os.replace` so an arm importing mid-edit could
  not see a partial module.
