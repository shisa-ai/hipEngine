# Correct PF-5 tile-16 to binding Hv48

## Summary

Correct the PF-5 tile-16 candidate and invalidate its first whole-model A/B.
The binding Qwen3.8-Flash-Next geometry is Hk=16/Hv=48/D=128, derived from
`gdn_group_count=16`, `gdn_time_step_rank=48`, and `gdn_state_size=128`. The
first candidate wrapper and tests covered Hv=32 only.

The first A/B also did not change the live route. `run_qwen4_exp_gdn()` calls
the imported `qwen4_exp_gdn_prefill_columnwarps_f32` function directly, while
`/tmp/pf5_tiled16_wall_ab.py` replaced only the hip_gfx1100 registry key after
the gfx1151 aliases had already been created. Both arms therefore executed the
same columnwarp function. Its apparent -0.019%/-0.123%/-0.026% result is pure
no-op timing noise and must not be published as a tile-16 rejection. This also
supersedes multiloop iteration 2's revert interpretation; no rejection artifact
was emitted.

The kernel body itself is head-count-generic. Extending the validated wrapper
to Hv=48 passes exact output/state parity and improves the binding 512-row
operation-complete leaf by 35.287%, so a corrected, fail-closed route A/B is
warranted.

## Changes

- Extended the raw HIP launcher and Python wrapper envelope from Hv=32 to
  Hv in {32,48}; Hk=16 and Dk=Dv=128 remain exact requirements.
- Expanded `tests/test_qwen4_exp_gdn_tiled16_prefill.py` to cover binding Hv=48
  at rows 16, 17, and 64, retaining the Hv=32 regression anchor.
- Corrected the stable `docs/KERNELS.md` envelope to Hk16/Hv32-or-48/D128.
- No runtime route, execution-profile manifest, or default changed in this
  unit. The columnwarp parent and serial strict fallback remain registered.
