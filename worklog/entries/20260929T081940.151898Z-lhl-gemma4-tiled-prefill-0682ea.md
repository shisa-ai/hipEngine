# Port the tiled flash prefill kernel at head_dim 512 and prove parity

## Summary

P2's device code is now a repo kernel with a hipEngine-shaped launcher, and it
agrees with the exact kernel on every shape it claims to execute.

`hipengine/kernels/hip_gfx1100/gemma4/gemma4_attention_tiled.hip` is the
llama.cpp `fattn-tile.cuh` device region (plus its `common.cuh` helpers) with a
host launcher appended. The device body is byte-identical to upstream so it
stays diffable; everything Gemma-specific lives in the launcher. The launcher
stages dtype exactly as upstream's `launch_fattn` does — bf16→f32 for Q,
bf16→f16 for K/V, u8→f16 for the keep mask, f32→bf16 for the output — so the
kernel body needed no fork. Measured earlier at 0.0817 ms per layer
(0.41 ms across the five global layers, 1.0% of the 39.2 ms budget).

Two descriptor bugs were found and fixed during bring-up, and both are worth
knowing because neither produces a crash:

- **Strides.** ggml's `nb[2] = ne[1]*nb[1]`, so the stride to the next query
  head is `head_dim * tokens`, not `head_dim * num_heads`; likewise `* keys` for
  K/V. Both errors evaluate to zero at head 0, which is why a single-head probe
  passes while the worst error lands on head 8.
- **Input layout.** The kernel indexes ggml's `(head_dim, tokens, heads)` —
  element `h*(T*D) + t*D + d`, head *outermost* — while hipEngine stores
  `(tokens, num_heads, head_dim)`. Staging in source order scrambles every logit
  while still emitting finite output.

A third artefact was a false lead: output that looked shifted by exactly one
element was really f32→bf16 *truncation*, because the probe's consecutive
reference values happened to sit one bf16 ULP apart. The write now rounds to
nearest even.

The port also pinned down two capability rules the kernel genuinely needs, both
now enforced in the HIP return codes and re-checked in Python:

- `keys` must be a multiple of 128. At `ncols2 > 1` the kernel takes the KV loop
  branch documented "without out-of-bounds checks", which steps by `nbatch_fa`
  and loads a full tile, so a partial tail would read past K/V and the mask.
- `num_heads` and `num_heads/num_kv_heads` must each be a multiple of 8. The
  launch computes `grid.z = ntiles_z_gqa * ne12` while the kernel decodes
  `sequence = z/(ne02/ncols2)`; those agree only when `ncols2` divides the GQA
  ratio, otherwise `sequence` runs past `ne03` and writes off the output.

Neither rule is a measurement gate — each is arithmetic on the requested shape,
and each names what to change to satisfy it.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_attention_tiled.hip` — ported
  device region + host launcher, with a lineage header citing `fattn-tile.cuh`
  and documenting the layout/stride/mask traps and the return codes.
- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_attention_tiled.py` —
  `build_gemma4_attention_tiled()` (`family=gemma4_attention_tiled`,
  `profile=prefill`), `gemma4_attention_tiled_admits()` for pre-allocation shape
  checks, and `gemma4_attention_prefill_tiled()`, which takes the same twelve
  arguments in the same order as `gemma4_attention_prefill_bf16` so only the
  symbol changes at a future dispatch site. Unsupported shapes raise
  `Gemma4AttentionTiledUnsupported` naming the violated constraint.
- `tests/test_gpu_gemma4_attention_tiled_parity.py` — exact-vs-tiled numerical
  parity over 10 shapes, plus a test pinning the two symbols apart so parity
  cannot pass by calling the kernel under comparison.
- `tests/test_unit_gemma4_attention_tiled_admission.py` — 11 GPU-free cases over
  the capability rules, including accepted shapes (so acceptance is not an
  artefact of one combination) and a check that no refusal message mentions
  measurement or qualification.
- `audit/` — the two new kernel rows triaged `ORPHAN-KERNEL` / `defer` expiring
  2026-10-13, with the evidence and the named closing step.

## Validation

- `pytest tests/test_unit_gemma4_attention_tiled_admission.py tests/test_gpu_gemma4_attention_tiled_parity.py` → **31 passed**. The build ran through
  `build_hip` on a real `hipcc --offload-arch=gfx1100` compile of the new source.
- Parity cases: tokens 1, 3, 4, 5, 8, 64, 128, 512; keys 128, 256, 512, 1024;
  a sliding-window keep mask and a window wider than the range; the real
  global-layer geometry (512×1024, 16/2 heads, head_dim 512). `atol 1e-2 /
  rtol 2e-2` on BF16 output. Separately, against an independent f32 CPU
  reference the worst absolute error was 3.9e-3 ≈ 2 bf16 ULP.
- Existing Gemma attention tests still pass:
  `pytest tests/test_unit_gemma4_attention_{geometry,routing,scratch,flash_admission}.py` → 32 passed.
- `python3 audit/audit.py check` → gate error list now byte-identical to the
  baseline taken with these four files absent (`kernel` back to 2 untriaged,
  triaged 104→106). The 7 remaining errors are pre-existing and untouched.
- `scripts/check_lineage.py` crashes on a missing external reference repo
  (`~/models/hipengine_sources/poolside-llama.cpp-laguna`), unrelated to this
  change; `docs/source_lineage.json` carries no gemma4 entries today, so none was
  added.
