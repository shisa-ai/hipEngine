# Retire experimental Maple runtime fusions (R0373/R0374)

## Summary

Lead decision (2026-11-07): remove both experimental Maple runtime fusions. They
were `HIPENGINE_MAPLE_FUSE_MOE` (bit-exact, but about 9% slower per MoE layer than
the unfused pair) and `HIPENGINE_MAPLE_FUSE_QKATTN`. Decode now always runs the
unfused primitive chains in both the HIP and CUDA Maple runtimes. The fused kernels
stay as kernel-level primitives with their kernel tests; the CUDA copies cannot be
built on this host, and keeping both sides keeps the change symmetric.

## Changes

- `hipengine/runtime/maple.py`, `hipengine/runtime/maple_cuda.py`: removed the
  selectors, fused branches and fused-kernel imports. The decode graph key is now `()`.
- `scripts/maple_c1_bench.py`: dropped the two selectors from the recorded list.
- Tests: the graph-key test now asserts an empty key; removed the selector-snapshot
  and fusion-recapture tests from `tests/test_gpu_maple_runtime.py`.
- `docs/ENVS.md`: both rows say retired.

## Validation

- `tests/test_unit_maple_graph_selection.py tests/test_gpu_maple_runtime.py
  tests/test_gpu_maple_ternary_kernels.py tests/test_gpu_maple_attention_kernels.py`:
  56 passed on gfx1151. The Maple checkpoint is not available locally, so there was
