# Muse Glimmer DFlash beats llama.cpp draft-dflash (Gate B)

DFlash decode **22.49 tok/s** (transition-normalized 22.42) on the 10-prompt

## Changes

- `runtime/gguf_linear.py`: `launch_gguf_linear_exact_rows` now routes the Q5/Q6
  T16 decode parent (`t16_gemv_decode_*`) to its parent-parity rowtile sibling
  (`t16_gemv_rowtile_*`, rows 2-8) instead of re-reading the weight per row.
  Bit-identical (0 diff) and weight-amortized: Q5 head 37.4 -> 10.4 ms at rows=8.
- `runtime/muse_glimmer_dflash.py`: drafter projections use the exact-row owners
  (Q4 rowtile ~198 GB/s vs WMMA 37 GB/s; Q5/Q6 rowtile); `draft_block` accepts a
  variable block size (2..block_size) so only the verified rows are drafted.
- `generation/muse_glimmer_dflash.py`: (1) draft only anchor + n_draft masks
  (not the full trained block); (2) fold the bonus/corrected token into the next
  verify as root row 0 (deferred boundary), removing the separate ~88 ms decode
  forward — its KV/logits/taps amortize with the draft block (~9 ms marginal).
