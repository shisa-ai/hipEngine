# Make audit identities and decision aging durable

## Summary

Completed the audit lifecycle implementation inherited from the interrupted
session. Ordinary source movement no longer changes finding identity; ambiguous
or conflicting matches remain visible. The ordinary audit check passes with
unchanged budget ceilings and selectors. This is a tooling and data-migration
unit, not a fresh judgment on every recorded cleanup item.

All 4,483 prior decision records survive: 2,458 live and 2,025 archived. Their
judgments, notes, authors, review dates, deadlines and resolved flags are
unchanged. No decision was bulk-reaffirmed to make a check green.

## Changes

- Stub findings use full parsed statements; other code findings use site text.
  Keys include enclosing function/class names instead of line numbers. Duplicate
  groups include block composition; when
  block chains cannot distinguish members, a semantic scope fingerprint prevents
  source-order transfers. Blank lines/comments do not change that fingerprint.
  Function renames and duplicate-group semantic changes intentionally reopen
  rows rather than guessing. Doc-path findings use document + target identity.
- Rebinding accepts tied historical decisions only when tag, disposition,
  severity and expiry agree. It chooses the latest review deterministically,
  preserves the evidence hash, and still refuses one decision matching multiple
  new sites equally well.
- Evidence hashing ignores positions, file/body size and elapsed age, but keeps
  reader paths, defaults, continuation evidence and semantic numbers. Resolved
  decisions become stale if their facts change. Invalid expiry dates fail
  validation, and the state table distinguishes expired from stale decisions.
- `refresh` archives absent decisions after both scans. Potential matches for
  open rows remain live for investigation. `archive` lists history;
  `archive --apply` performs both scans and archives without changing budgets.
  Archived records never automatically attach to new rows. Empty live-kind files
  are cleared, and retrying after an interrupted archive does not duplicate it.
- `check --review` adds a strict maintenance check for stale/expired decisions;
  the normal budget check still reports them without pretending they are newly
  untriaged rows. Duplicate row IDs fail before a generated store is written.
- Replaced the inherited bulk hash reset with exact historical recovery: searched
  747 committed inventory/finding blobs and translated 2,434 live decisions using
  2,433 distinct legacy hashes. Each legacy hash was recomputed before conversion.
  Twenty-four decisions lacked recoverable evidence and keep their original
  hashes. `audit/migrations/evidence-basis-v1.json` records the 107 source blobs
  used by the live translations, plus the missing IDs and 363 identity moves.
  Each site move matched a unique exact location and identical title, evidence
  and signals on the unchanged runtime tree. No similarity guess was used for
  this one-time migration.
- Updated `audit/README.md`. The root product README and unrelated scratch work
  were not edited. No runtime, kernel arithmetic or dependency manifest changed.
- RED-first was partly inherited: the predecessor left an untested prototype.
  New identity regressions were checked against its older behavior (seven failed),
  and invalid-expiry validation was observed failing before its repair. The final
  focused suite covers archival retry, empty-store persistence, conflicting ties,
  stale resolutions, duplicate groups, long statements and review-gate behavior.
