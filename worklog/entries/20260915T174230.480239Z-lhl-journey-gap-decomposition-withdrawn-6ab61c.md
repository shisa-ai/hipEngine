# Withdraw the Flash-Next gap decomposition; add request-delimited per-role cost

## Summary

Three corrections to the record committed in `c6f149655`, and the replacement
measurement that the corrected work points at.

**Withdrawn: the 1.65x x 3.38x gap decomposition.** Telescoping two ratios is
algebra, not a causal decomposition. "Kernel quality at equal arithmetic" was
never demonstrated - accumulation, operand precision, repair strategy, KV type
and execution shape all differ between the two engines. "1.65x is a lower bound"
does not follow either, because selector count does not bound performance and
the effects can interact non-monotonically; the census at `53512b509` is not a
measurement of today's code with every selector restored.

**Withdrawn: "repair is only 6.3%, so correctness is not the bottleneck."**
Explicit repair kernels are only part of the cost of preserving arithmetic.
Multi-plane computation, staging and choosing slower primary kernels also
contribute, and the dominant projection kernel may itself be a
correctness-driven fallback. Slow implementation and arithmetic-policy cost are
not mutually exclusive explanations, so the 6.3% figure cannot carry that
conclusion.

**Corrected: pwilkin's dense comparison.** The record said "about 2770 ms". That
was a whole-window sum used as a per-prefill figure. The per-prefill total is
1387.5 ms, so the dense ratio is 7.3x, not 3.6x.

**Flagged: the `gr_read` row is not comparable across engines.** Upstream
reports 0.0 ms because it has no hyper-connection kernels at all; that work runs
through its generic matmuls and elementwise ops. A zero there means "classified
elsewhere", not "not computed".

## Evidence

Request-delimited, role-marked capture of the current production default,
`code-p4096`, chunk1024, BF16 KV, warm PLE, warmup excluded:

- 9652 kernels, **22368.1 ms attributed over a 22932.5 ms window, 0 ms
  unattributed (100%)**.
- `moe:expert_gate` **6667.6 ms (29.8%)**, the single largest role.
- Q8_0 dense projections next: `attn_qkv` 2724.2, `ssm_out` 1967.1,
  `attn_gate` 1584.2, `attn_q` 1282.3, `attn_output` 659.6, `hc_attn_down`
  551.6, `hc_ffn_down` 547.0, `shared_*` 758.4.
- Every Q8_0 projection runs at **2140-3466 GFLOP/s, 14.5-23.4% of this part's
  14.8 TFLOP/s FP32 peak**, across shapes from 10240x320 to 2560x12288.

The tile mechanism, read from source rather than inferred:
hipEngine's dominant variant is
`gguf_k_prefill_out_coltile_rowbatch_kernel<float, float, 8, 8, 4>` -
`COL_TILE=8, ROW_BATCH=4`, so each thread holds 32 accumulators and each decoded
weight feeds 4 FMAs. pwilkin's `mmb_dense_kernel<128, 128, 32, 64, WT>` decodes
128 weights per `k` and does 128x128 FMAs; the big-tile form reaches 128x256.
That is 32x to 64x the reuse per decoded weight, with a 256-thread block against
hipEngine's 128. MMB also converts the activation to BF16 once per matmul, can
keep the output in BF16, and uses a preprocessed shadow buffer for IQ4_NL and
Q6_K. `mmb_min_t()` is 512, so the path is prefill-only.

## Limits

- **No comparator column.** The per-role table is hipEngine-only. Applying the
  same tensor-role mapping to the llama.cpp-family engines is the next step;
  a name-based comparison cannot do it, because upstream folds its
  hyper-connection work into generic matmuls.
- **Five roles have no recoverable shape** in this table (MoE, QSA, GR, GDN,
  indexer) because they launch through their own helpers rather than the GGUF
  quant path. They are marked as unavailable rather than reported as zero.
- **GFLOP/s excludes dequantization work**, so share-of-peak is not an
  efficiency verdict on its own. The reuse-per-decoded-weight figure is the one
  that bears on the mechanism.
- **Not a microbenchmark.** These are in-context costs inside a real prefill,
  including launch overhead and cache state.
- **Not an equal-arithmetic comparison**, and no causal factor is claimed.
- The rate table in the 2026-09-15 artifact still mixes estimators across
  engines and has not been validated for identical case IDs, token hashes and
  repetition counts. That is stated in the rollup as indicative only.
