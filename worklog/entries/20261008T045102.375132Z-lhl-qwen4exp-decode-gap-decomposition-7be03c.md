# Decode depth remainder fully decomposed into inter-kernel dispatch gaps

## Summary

Gap analysis over the DE-11 head-refresh traces closes the decode-depth
question: kernels plus inter-kernel gaps account for the decode wall exactly at
both depths. p512: 44.28 + 4.66 = 48.94 ms/step; p4096: 45.01 + 11.53 =
56.54 ms/step (both counterbalanced arms agree). There are ~1,740-1,815 gaps
per step - one per launch - with a mean gap of 2.7 us at p512 growing to 6.4 us
at p4096. The depth-growth remainder is GPU-side dispatch gap time.

## Changes

- :
  per-arm kernel/gap decomposition with top-gap distribution and the conclusion.
- No engine, kernel, profile or default change.

## Validation

- The decomposition is exact (kernels+gaps equals the window span at both
  depths, both arms), uses the committed thermal-gated traces, and is
  consistent with the build-identity A/B tie: host Python cost removal moved
  nothing because the remainder is not host time.

## Next

- The structural fix for the next unit: fewer, larger launches. The engine
  already replays the per-layer MoE as one HIP graph; extending graph capture
  to the whole decode step (or fusing launch chains) collapses the ~1,800
  per-step dispatch gaps and projects p4096 decode from ~56 ms/step toward the
  ~45 ms kernel floor (~21+ tok/s from the current 16.7 canonical). This is a
  major, multi-session build: capture scope (attention/QSA/GDN/dense/norm/
  rotary chains), per-step dynamic inputs (token, positions, live spans),
  stateful tensors, exactness gates and the registered non-graph fallback.
