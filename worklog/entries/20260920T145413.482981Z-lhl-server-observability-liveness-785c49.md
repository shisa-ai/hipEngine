# Keep server observation waits off the event loop and map command timeouts

## Summary

Review of `43ea7d415..9bb97889d` found that `--info` synchronously requested
engine snapshots on the HTTP event loop and that inner generation handlers
converted `EngineCommandTimeout` into `generation_failed`. Engine work may wait
for the GPU, but these waits must not prevent unrelated HTTP requests from
being received and handled.

Snapshot waits now run on worker threads for request summaries, optional stream
metadata, readiness, and metrics. Command timeouts use the same retryable
`engine_unavailable` mapping as a closed service, including SSE error events.

## Changes

- `hipengine/server/api.py`: added an asynchronous KV payload helper and moved
  all request-time KV snapshot call sites onto it. Readiness and metrics await
  snapshots off-loop, then read shared server counters/session state on-loop.
  An empty snapshot prevents downstream helpers from retrying a failed snapshot
  synchronously. The multimodal fallback token count also runs off-loop.
- All four inner generation exception handlers now handle both
  `EngineServiceClosed` and `EngineCommandTimeout`.
- `tests/test_integration_server_api.py`: regression coverage for blocking/SSE
  completion tokenization timeouts and mid-stream failures for completions,
  singleton chat, and live multi-choice chat. Twelve blocked-snapshot cases
  cover readiness, metrics, info-only summaries, optional metadata, and buffered
  versus live multi-choice chat.
- The snapshot regression waits for a real blocked call before checking that
  `/health` and `/v1/models` complete, verifies snapshot thread identity, and
  releases the driver via an independent watchdog on failure.
