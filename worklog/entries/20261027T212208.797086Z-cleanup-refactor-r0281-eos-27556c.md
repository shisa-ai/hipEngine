# Load PARO special token metadata at the model boundary

## Summary

The Qwen3.5/PARO model plugin now loads normalized checkpoint special-token
metadata. Generation no longer discovers Qwen marker strings on each EOS check.
A public request also exposed an existing ignored `eos_token_id` override;
this unit repairs it rather than creating another deferred item.

## Changes

- Add `Qwen35ParoTokenizer`, delegating encoding/decoding to the existing
  tokenizer while owning EOS/BOS/PAD metadata. Generation configuration takes
  precedence over tokenizer configuration and nested/root model configuration.
  Metadata-free Qwen checkpoints resolve their compatibility markers once at load.
- Supply that adapter through `QWEN35_PARO_MOE.load_tokenizer()` and the resident
  loader. Remove generator-local marker lookup and normalization duplication.
- Honor the original request's explicit EOS in greedy, sampled, stream, batch and
  resident completion checks and finish details. Inferred primary sampler EOS is
  not an explicit override: both checkpoint EOS IDs still terminate normally.
  `ignore_eos` and explicit stop-token behavior remain distinct.
- Remove the completed Cleanup Ledger row and record its disposition in the
  durable sweep. No kernel, arithmetic, backend default or README changes.

  Tests cover greedy/processed generation, prompt lists, streaming, override

- Compileall, the complete default CPU pytest run, fixture checks, registry,
