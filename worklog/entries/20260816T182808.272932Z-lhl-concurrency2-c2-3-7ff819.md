# Concurrency2 C2-3 global KV pool and dense backends

## Summary

Implemented C2-3's load-time global KV pool substrate and first dense backend compositions. BF16 and artifact-qualified no-mirror INT8 now share one resource/admission/page lifecycle with stable arbitrary-page plane tables; the scheduler and resident loop consume only request IDs and backend `KVBatchView` data.

## Changes

- Added `GlobalKVPoolSet` with stable per-plane page-pointer tables and metadata descriptors, noncontiguous page allocation, typed private/shared/growth-credit leases, explicit page states, COW, session pins, in-flight epochs, exact reclaim, and conservation checks.
- Added `DenseKVCacheBackend` for BF16 and no-mirror per-token/head INT8. Both use the same estimator, ledger, global pool, growth-credit, pressure, cancel, rollback, prepare, and reclaim lifecycle; only pool planes, storage dtype, artifact identity, and kernel bundle differ.
- Added `DenseKVArtifactQualification`, which rejects INT8 adapters unless the exact artifact records KL <= 0.05, top-1 >= 90%, no BF16 mirror, and an evidence source.
- Added `DenseKVAdmissionManager` plus `DenseKVResidentRunnerAdapter`; the adapter refuses legacy runner entry points and requires prefill/decode kernels to receive a generation-checked backend `KVBatchView` with stable storage-plane pointers.
- Extended opaque `ResourceClaimSet` metadata for backend-only typed materialization facts while keeping ledger/scheduler codec-neutral; bounded active reservation records are removed on rollback/reclaim.
- Relabeled `DeviceChunkedKVPool` as the Generation-1 single-backing compatibility allocator and added its two-gfx11 removal trigger to `docs/REFACTOR.md`.
- Updated `CONCURRENCY2.md` and `KVCACHE.md`; the new host substrate makes no performance/product-support claim before C2-6 hardware qualification.
