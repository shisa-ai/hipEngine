# R0387 rocprof dense-down census filter counts col8_residual variant

## Summary

Fix the R0387 rocprofv3 packed-decode census false-negative on the dense
Qwen3.8-27B c2 lane. `build_c3_family_census` counted the dense Q6 down owner by
an output-signature filter (`unsigned char const*, unsigned short*`) that missed
the `…rowtile_col8_residual_kernel` variant (its extra residual input is
`unsigned short const*`). At c2 the down splits 32 col8 + 32 col8_residual = 64,
but the filter counted 32 and failed `len == total_layers`, false-failing an
otherwise token-exact, route-clean census. This continues
[`worklog/entries/20261110T221602.442597Z-lhl-r0387-packed-step-c4-nondeterminism-15b932.md`](20261110T221602.442597Z-lhl-r0387-packed-step-c4-nondeterminism-15b932.md).

## Changes

- `scripts/gguf_packed_ar_rocprof.py`: match the dense down owners by the
  `q6_k_t16_qmicro_planar_gemv_rowtile_col8` name, which counts both the col8 and
  col8_residual variants and excludes the float-output lm_head rowtile. This is a
  comparison-interface (census) correction only; no runtime/dispatch change.
- `tests/test_unit_gguf_packed_ar_rocprof.py`: add a regression census fixture
  (64 gate/up + 32 col8 + 32 col8_residual + lm_head rowtile + top1_gather).
- Refreshed `benchmarks/results/2026-11-10-w7900-qwen38-27b-q4km-r0387-packed-rocprof-c2-census.json`
  with the now-passing c2 census.
