# fp16-state packed AR prefill (segmented decode_order) + production-route packed path

## Summary

Enables the packed AR benchmark (`gguf_packed_ar_bench.py --route production`)
for c1/c4/native_c8 with and without `HIPENGINE_GGUF_FP16_RECURRENT_STATE`,
the measurement needed to collapse the fp16 recurrent-state flag (task #16).

Two blockers were removed:

1. **Stale packed-AR verify-capture guards.** `prefill_batch_native` and
   `step_batch_native` (packed AR prefill/decode) hard-required
   `HIPENGINE_GGUF_VERIFY_CAPTURE_PREFILL_GDN`, which is incompatible with the
   production route (`--route production` removes it). The packed path is
   self-contained: prefill uses the segmented in-place per-slot state
   (`gdn_active_segments` = slot count, no per-token state-rows capture) and
   decode is c1-exact per slot via `_run_linear_attention_attn_only`; neither
   touches verify-capture. Proven by a gfx1151 Qwen3.8-27B Q4_K_S smoke: with
   the guard bypassed under the production env, packed == scalar prefill 2/2
   top-1 (KL 3e-4) and decode 2/2. The packed target verifier guard (which
   captures per-token state rows) is unchanged.

2. **Missing fp16 in-place segmented decode_order prefill kernel.** The packed
   AR multi-slot prefill writer (per-slot packed state mutated in place) was
   still FP32-only, so c4/native_c8 + fp16 raised. Templated
   `qwen35_gdn_prefill_recurrent_rmsnorm_gate_decode_order_segments_kernel` on
   `state_t` (all state reads/writes through `gdn_state_read/write_qwen35`),
   added the `_fp16state` launcher/wrapper/symbol/export/registry entry, and
   routed `_run_linear_attention_prefill_layer_rows` through a new
   `_gdn_decode_order_segments_inplace_kernel()` selector (fp16 under the flag,
   strict FP32 identity otherwise).

## Changes

- `hipengine/kernels/hip_gfx1100/linear_attn/gdn.hip`: template the in-place
  segmented decode_order kernel on `state_t`; strict launcher now explicitly
  instantiates `float` (HIP launch macro does not apply a default template
  arg through `float*`); new `hipengine_..._decode_order_segments_fp16state`
  half_t launcher.
- `gdn.py` / `linear_attn/__init__.py`: `_fp16state` symbol + wrapper +
  registry key (`decode_order_bf16_segments_fp16state`) + export.
- `qwen35_gguf_runner.py`: removed the two stale packed-AR guards (prefill +
  decode); added `_gdn_decode_order_segments_inplace_kernel()` and routed the
  segmented prefill dispatch through it (removed the fp16 fail-closed guard at
  that site).
- Tests: `test_fp16_state_decode_order_segments_inplace_matches_host_replay`
  (RED vs host fp16 replay), `test_gdn_decode_order_segments_inplace_kernel_selects_fp16_under_flag`
  (CPU dispatch), `test_qwen35_gguf_packed_ar_prefill_decode_runs_without_verify_capture`
  (GPU production-route packed prefill+decode == scalar).
- `docs/REFACTOR.md`: packed-AR guards and in-place segmented writer moved out
  of the fp16 fail-closed list.

## Validation

- gfx1151 fresh HIP build; RED fp16 in-place segments kernel matches host
  fp16-state replay (two-segment packed, rtol 5e-2/2e-3), and the existing
  fp16 decode_order state-rows RED tests stay green.
- Strict FP32 oracle tests (`test_gdn_prefill_segments_mutating_matches_per_segment_decode_order`,
  `test_gdn_prefill_state_rows_no_copy_matches_mutating_capture`,
  `test_gdn_prefill_segments_state_rows_no_copy_matches_per_segment_capture`)

- CPU selector tests pass; gfx1151 Qwen3.8-27B Q4_K_S packed prefill+decode in
  the production route (no verify-capture) matches scalar (2/2, KL ~3e-4).
