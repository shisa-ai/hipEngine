# Expose Inkling 2 Mini DSpark verification through LLM

## Summary

Expose the original DSpark sidecar for text and single-image requests with `SamplingParams(speculative_mtp=True)`. The CPU reference verifies candidates serially; it is a correctness path, not an acceleration claim.

## Changes

- Verify each proposed token against the shared target sampler. A mismatch drops the remaining candidates; only target-selected tokens reach either cache.
- Include the provider, verification mode, proposed token count, and accepted token count in generation diagnostics. Use a separate model-owned multimodal hook so an unsupported explicit request still fails.

## Validation

- All 23 focused Inkling tests passed, including a candidate rejection with a discarded suffix and equality against ordinary decoding.
- Real-checkpoint public API comparison matched ordinary decoding token-for-token for both text (` Paris.`) and a solid red image (` red.`). Both requests verified an accepted DSpark candidate. The default CPU bundle passed.
