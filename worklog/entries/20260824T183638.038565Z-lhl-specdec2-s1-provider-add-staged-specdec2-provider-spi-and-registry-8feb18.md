# Add staged SPECDEC2 provider SPI and registry

## Summary

Added the bounded staged-provider boundary required for scheduler-owned
SPECDEC2 cycles. Providers now expose capability, complete claims, prepare,
propose, commit, rollback, and close stages; the protocol contains no generate
or stream method. A separate exact-key staged registry reuses the existing
provider/target/backend/quant key without aliasing or replacing the legacy
whole-request oracle registry.

## Changes

- Added `hipengine/speculative/provider.py` with typed cold request semantics,
  runtime-checkable `StagedSpeculativeProvider`, and construction validation.
- Reject staged objects missing any bounded stage and reject hybrid objects that
  still expose whole-request generation methods.
- Added parallel register/resolve/list/construct APIs to
  `hipengine/speculative/registry.py` using the existing exact four axes.
- Kept legacy `SpeculativeTextProvider` registration unchanged for migration
  parity/rollback.
- Exported all staged APIs and added focused RED/GREEN tests in
  `tests/test_specdec2_provider.py`.
