# DSpine speed: GPU refine +20% (3.57->4.30 tok/s); method 0.38x AR, not competitive

## Summary

Task #18. Profiled the DSpine cycle (phase timing, one process): target verify
879 ms/block (74%), CPU transition-cache refine 231 ms (19%), backbone+bridge
forward 46 ms, project+append 37 ms. Refine sub-profile: head projection
(15x5120x248320 linear) 163 ms + argsort/topk 43 ms dominate. Moved both to the
GPU (WMMA head projection + dflash2_top16_rows), keeping the small [n,K,K] score
table + chain walk on the host via a new refine_greedy_from_cand oracle split.

## Changes

- hipengine/kernels/cpu_reference/dspine.py: split refine_greedy into
  refine_greedy (CPU RED reference, unchanged output) + refine_greedy_from_cand
  (score table + chain walk given precomputed top-K cand).
- hipengine/runtime/dspine.py: refine_gpu (lazy 2.5 GB BF16 head upload + WMMA
  projection + device top-16 + host chain walk).
- hipengine/speculative/dspine_cycle.py: candidate_budget + use_gpu_refine opts.
- hipengine/generation/qwen35_gguf_dspine.py: persist the drafter across requests
  (amortize head/weight upload) and use GPU refine on the production path.
- scripts/qwen38_dspine_baseline.py: --candidate-budget, --gpu-refine, persistent
  drafter across the suite.

## Validation

Real model Qwen3.8-27B-Q4_K_M + DSpine-b16, gfx1151, full ten-prompt mtpbench:
- GPU refine drafts bit-identical to CPU refine on a probe block (cpu==gpu True);
  refine_greedy CPU oracle test still 3 passed.
- Warm GPU refine 50.6 ms vs CPU 231 ms (~4.6x sub-window). One-time head upload
  ~1.76 s amortized by the persistent drafter (warmup discards it).
- Full suite, 1 rep, 25 tokens: CPU refine 3.57 tok/s -> GPU refine 4.30 tok/s
  (+20%), exact=True both, acceptance unchanged 0.214, AR 11.35. Public
  LLM.generate_speculative produces AR-exact IDs via the GPU-refine provider.
- Candidate-budget sweep (3/4/5/8): 2.18/2.08/2.39/1.24 tok/s — all slower than
  full block; the fixed per-block overhead dominates, so budget is not the lever.

## Finding

DSpine at 4.30 tok/s is 0.38x AR and the slowest campaign method (MTP B3 18.05,
DFlash2 B3 9.50). Its ~3.2 tok/cycle acceptance is at/above DFlash2/MTP parity,
but the 16-row block verify (74% of cycle) + 5-layer drafter forward overhead
outweigh it. Like DFlash2, DSpine is not competitive on this target; the deficit
is structural cost, not drafting quality. The GPU-refine kernel win is retained.
