# Census raw-trace root is per shape, not one shared path

## Summary

`scripts/gguf_mtp_verifier_rocprof.py` defaulted `--raw-root` to one fixed
path and `shutil.rmtree`'d it at the start of every run. A sweep over verifier
row counts therefore kept only the last shape's kernel trace, while every
earlier artifact still recorded a `kernel_trace_csv` pointer to the file that
had just been deleted and rewritten by a different shape.

I hit this while capturing the representative verifier rows: the rows-4 trace
was gone by the time I wanted to confirm which template instantiations ran, and
the surviving CSV belonged to the rows-5 run.

## Changes

- `scripts/gguf_mtp_verifier_rocprof.py`: `--raw-root` now defaults to
  `None`, and `_resolve_raw_root` derives a per-shape path from the mode,
  block rows, and quant when it is unset. An explicit `--raw-root` is
  unchanged. `_default_raw_root` is separate so it is testable without running
  the profiler.
- `tests/test_scripts_gguf_mtp_verifier_rocprof.py`: two tests, one that
  different shapes get different roots and one that an explicit path still wins.

## Validation

- `uv run pytest tests/test_scripts_gguf_mtp_verifier_rocprof.py -q` — 19 passed.
- The trace path is only used by the profiler parent, so no GPU run is needed
  to check the derivation.
