# Measure the pinned Strix Halo ordinary streaming gap

## Summary

The explicit hipEngine `fast` route does not match pinned Loom on the two ordinary streaming workloads tested on Strix Halo. The largest observed gap is time to first text at 575 input tokens. This is a complete-stack diagnostic, not a matched-output or matched-KV benchmark.

## Changes

- No runtime changes. Served the same lockfile-pinned `UD-Q4_K_XL` target on `strixhalo` (Radeon 8060S, `gfx1151`, Linux `7.3.0-1-mainline`) with hipEngine `33e0e9719` and [pinned Loom `277f099b`](20261121T170419.285290Z-lhl-inkling2-mini-780776.md). The harness rehashed the target and tokenizer. Both servers ran individually, at context capacity 4,096, with no speculative tokens or prompt reuse, greedy sampling and one sequence. ## Validation

After one eight-output warmup per server launch, each order ran five paired prompts per length (Example A–E on the same task). All requests ended at the 128-output length cap; each engine reproduced its own text for every prompt across orders. No cross-engine text pair matched. hipEngine used explicit token IDs at `/v1/completions` and FP32 KV; Loom used the chat endpoint and [FP16 KV](20261122T023533.738557Z-lhl-inkling2-mini-38c5ef.md). The pinned Loom renderer and tokenizer give the supplied ID digests, and usage confirmed the expected input counts; Loom does not return the actual input or generated IDs. Loom reported zero cached tokens and hipEngine ran with prefix caching disabled.
