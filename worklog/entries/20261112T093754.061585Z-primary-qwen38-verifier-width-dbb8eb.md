# Profile target verifier width costs on the public owner

## Summary

Measure fixed-prefix verification widths 1/2/3/4/6/8 on zbook / Radeon 8060S,
Qwen3.8-27B Q4_K_M, before selecting any shared-kernel optimization. The baseline
is the shipping public owner's production profile at `8fe2ba4ec`; no kernel or
arithmetic change is included in this diagnostic.

## Changes

- Add a driver that borrows a public LLM owner's session, records the profile
  manifest and frozen verifier controls, constructs a greedy teacher checked
  against public AR, and restores the same prefix before each measured call.
  Alternate forward/reverse width order; warm every shape before measurement.
- Profile short/long contexts with ROCTx windows. Width one is eager because
  the native graph supports only 2..8 rows; record that distinction rather than
  attributing all width-one differences to per-row arithmetic.
- Add a trace reducer using the existing overlap-aware device/API/copy union
  accounting. Keep full kernel names, compact attribution and input hashes;
  raw profiler traces remain local.

## Validation

  `_linear_state_snapshot()` returns `(live_destination, backup)` pairs, not
  Conv/GDN pairs. The initial helper cloned both, so restoration changed only
  the clones. Add a RED/GREEN test that preserves the live destination and

- Corrected unprofiled sweep completed with all measured IDs matching the

## Findings

- Both sweeps completed with exact public/teacher/verifier IDs. Unprofiled median
  milliseconds at widths 1/2/3/4/6/8: context64
  103.06/100.15/114.73/122.14/149.37/167.83; context2048
  107.40/115.52/127.26/144.13/177.25/213.28. One row uses eager verification;
  every measured wider call uses the graph with no capture. These are fixed
  prefix diagnostics, not acceptance or task-quality measurements.
- Six-to-eight-row marginal cost is 9.23 ms/row at context64 and 18.01 ms/row
  at context2048. Kernel attribution shows multiple growing projections, not
  just gate/up. At context2048 the scalar split-K attention producer repeats
  per row and is the largest width-eight family (71.82 ms/call in the trace).
  HIP API duration overlaps GPU execution and is not additive host overhead.
- This corrects the bandwidth-floor interpretation in
  `20261109T194610.307247Z-lhl-qwen38-27b-specdec-6c6104.md`. Its equal DSpine
  throughput at six/eight rows also changed acceptance. Using its aggregates
  implies roughly 9.14 ms of cycle cost per added row, not a measured verifier
  slope; short-output truncation and mixed aggregation limit that inference.
- Preserve samples, canonical provenance, profile manifest, input hashes and
  full kernel-name attribution in
  `benchmarks/results/2026-11-12-qwen38-verifier-width/`. Benchmark rollup links
  these diagnostics without a root README edit. Focused protocol/attribution
  tests, documentation, fixtures, test tiers, compileall and diff checks pass.
- No kernel change is justified by this profiling unit alone. Broad projection
  and attention redesigns require their own arithmetic/control gates. Continue
  the requested matched public comparison with the current working paths; do
  not turn this measurement step into an unbounded tuning campaign. Keep EAGLE
  tree deferred: the measured marginal cost exceeds the suggested 6 ms trigger.
