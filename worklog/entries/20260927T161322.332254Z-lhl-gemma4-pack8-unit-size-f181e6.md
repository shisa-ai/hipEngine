# The pack8 port needs multi-allocation support, so it is a real unit

## Summary

The implementation unit's true size, from reading `gemma4_gguf_device.py`'s plan
and materialize paths. **It is not a branch.**

`materialize_gemma4_gguf_device_weight` (:203) reads one array with
`reader.tensor_data` and branches only on `dtype`/`source_dtype` before a single
`load_host_array_to_device_as_dtype` call - so a weight is **exactly one
allocation**. The pack8 layout is **three arrays**: `qweight` (int32), `scales`
and `mins` (fp32, shape `[in_features/32, out_features]`).

So the unit needs:

1. Multi-allocation support in `Gemma4GGUFDeviceWeight` and the materialize path.
2. `_plan_one` (:123) choosing the layout for q4_k expert tensors - it already
   gates on rank-2-or-3 and on `_RAW_BLOCK_TYPES`.
3. The kernel's three pointers threaded through the MoE route.
4. A correctness gate.

**Residency is not free either.** The synthetic repack of the 285.5 MB raw expert
tensor produced a `22528 x 2816` int32 `qweight` plus fp32 `scales` and `mins`, so
the resident cost of this tensor roughly doubles - though the raw copy could then
be dropped, which makes it a memory-budget decision rather than a simple win.

That is the honest shape of the next unit, and it is larger than "port a layout
constant". Recording it here rather than starting it, because a partial port -
layout without the route, or route without the layout - would be a half-done
change in the tree, and the correctness gate needs both halves present.

## Validation

- Read from the materialize function's control flow and the repack's actual output
  shapes, not estimated.
- The residency claim is arithmetic on the measured repack output against the
  source tensor's declared size.
- **Not verified:** whether dropping the raw copy is possible, which depends on
  whether anything else reads the raw layout for these tensors.

## Next

- Implement as one unit: multi-allocation weights, the q4_k pack8 plan branch, the
  `moe_linear` / `expert_pack8_selected_bf16_bf16_out` route lookup with the
  existing route as fallback, then a correctness gate against the current route
  and a decode measurement.
- Decide the residency question deliberately: whether to keep both the raw and
  packed copies for the expert tensors, or drop the raw one once the route is
  promoted.
- The prize is roughly 4-6x on a line that is 28.0% of decode, which is more than
  the whole 2X decode target, so this is worth a proper unit.
