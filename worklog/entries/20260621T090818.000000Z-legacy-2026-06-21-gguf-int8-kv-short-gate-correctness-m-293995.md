## Changes


- Diagnosed the explicit GGUF Q4_K_M INT8-KV short-gate ID drift by dumping BF16-vs-INT8 logits for GPU1 short prompts. Prefill logits are identical because the INT8 path still uses the BF16/AOTriton oracle for prefill attention. The first decode step showed the real drift: at `512` prompt tokens INT8 kept top-1 `318` but had `KL(BF16||INT8)=0.243`; at `4096` prompt tokens INT8 changed top-1 `11048 -> 246834` with `KL=0.552`, `max_abs=7.11`, `mean_abs=0.790`. FP32 INT8 scales helped but still failed top-1 (`11048 -> 40218`, `KL=0.308`), so scale dtype alone is not a correctness fix.
- Implemented a short-context BF16 mirror for explicit GGUF `int8_per_token_head`: when the resident session's rounded max context is `<=8192`, full-attention layers retain a BF16 mirror cache alongside the INT8 cache. Bulk prefill writes the BF16 mirror and retained INT8 cache; decode writes both, then routes attention through the BF16 mirror. Longer sessions keep the prior INT8-only capacity path. This is a residual-cache-style correctness guard for short gates, not a 128K quality claim.
- Validation: `python3 -m py_compile hipengine/runtime/qwen35_gguf_runner.py tests/test_qwen35_gguf_int8_kv_policy.py tests/test_qwen35_gguf_decode_repack_dispatch.py`; `python3 -m ruff check hipengine/runtime/qwen35_gguf_runner.py tests/test_qwen35_gguf_int8_kv_policy.py tests/test_qwen35_gguf_decode_repack_dispatch.py`; `python3 -m pytest tests/test_qwen35_gguf_int8_kv_policy.py tests/test_qwen35_gguf_decode_repack_dispatch.py -q` -> `9 passed`.
- GPU1 correctness probes after the mirror: `/tmp/gguf-int8-correctness-int8fp16-mirror.json` matched BF16 logits exactly for prompt `512` and `4096` first decode (`KL=0`, `max_abs=0`, same top-5). Graph decode one-run sanity with `--kv-storage int8_per_token_head`: `512/128` final ID `[318]`, decode `123.444 tok/s`, peak `21.350 GiB` (`/tmp/hipengine-gguf-int8kv-short-mirror-512-graph-1run.json`); `4K/128` final ID `[220]`, decode `112.689 tok/s`, peak `22.537 GiB` (`/tmp/hipengine-gguf-int8kv-short-mirror-4k-graph-1run.json`). These one-runs are correctness diagnostics only; prefill timings in the cold one-run harness were dominated by current GGUF prefill/lazy path behavior and are not retained perf claims.
