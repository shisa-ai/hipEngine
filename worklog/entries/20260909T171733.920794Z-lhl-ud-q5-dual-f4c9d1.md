# Q5 T16 dual fused-SiLU prefill kernel + 8r2 bulk singles: +8-9% prefill

## Summary

UD impact-list task 4: Q5 T16 WMMA prefill was ~23% of prefill with no pair
fusion. Wrote the dual fused-SiLU Q5 T16 prefill kernel modeled on
`gguf_q4_k_t16_dense_dual_wmma_prefill_silu` (gguf_k_t16_selected_prefill.hip),
gated it bit-exact against the unfused chain, and measured E2E. The task's
+14% target assumed more pairable share than the artifact has: only 9 of 131
Q5_K tensors are same-layer ffn_gate+ffn_up pairs (~5.5% of prefill), so the
dual alone lands +2.8%. The remaining gap was closed structurally: the same
eight-wave decode insight applied to the unpaired singles (a 256-row-block
shared-LDS owner, `shared8r2`) adds +5.4%, for +8.2% E2E on the XTX and +9.0%
on the W7900 (paired A/B), decode unchanged on both cards.

## Measurements

Leaf (XTX, GPU1, blk.25.ffn_gate/up 17408x5120, 512 rows):

| arm | time |
|---|---:|
| plain single x2 + silu (production chain) | 6.09-6.15 ms |
| dual fused-SiLU (4-wave port, first cut) | 6.12 ms |
| Q4 dual calibration (same shape/FLOPs) | 3.26 ms (56 TFLOPS) |
| **dual fused-SiLU (8-wave, final)** | **3.77 ms (48.5 TFLOPS/pair)** |

The first-cut port was a wash: the Q5 element decode (ql nibble + qh bit) is
~2x the Q4 decode, and the 128-thread phase-separated decode became the
bottleneck. Widening the block to 256 threads (8 waves x 2 row tiles) halves
the per-thread decode and recovers the Q4-dual-class rate. A 512-row block
(`<4,8>`) regresses to 4.93 ms (VGPR pressure), so 256-row blocks are the
default.

## Changes

- `gguf_k_t16_selected_prefill.hip`: the Q5 dual kernel
  (`gguf_q5_k_t16_dense_dual_wmma_prefill_silu_bf16_kernel`, template
  row_tiles/waves/threads, generalized decode mapping) with five exports
  (default `<2,8,256>` 256-row, row128 `<1,8,256>`, row64/row48/row32
  128-thread retiles) and the `shared8r2`/`shared8r4` single-matrix launch
  exports.
- `gguf_k_t16_selected_prefill.py`: wrappers, `linear_pair_silu`
  registrations for `gguf_q5_k_t16_v1` (all five variants), and the
  row-qualified gfx1100 dense owner selector (rows >= 257 -> shared8r2).
- `gguf_linear.py`: `launch_gguf_linear_pair_silu` resolves the Q5 pair
  variant by rows (the Q4 path's structure; `dense_pair_quant` now admits
  `gguf_q5_k_t16_v1`).
- `scripts/gguf_q5_t16_dual_silu_gate.py`: the bit-exactness gate on real
  tensors.
- `tests/test_gguf_q5_k_t16_dense.py`: synthetic-fixture tests - the dual vs
  the unfused chain at five row counts, the 8r2/selector vs the plain single,
  and the variant/registration contracts.
