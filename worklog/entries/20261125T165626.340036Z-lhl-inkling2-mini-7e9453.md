# Give each row of an Inkling block convolution its own thread

## Summary

The block short convolution gave one thread to each channel and walked the rows of a prompt block
in order, shifting a history of four values at every row. A 256-row block has 1,024 channels for
the key and value convolutions, so the kernel ran 1,024 threads on 45 compute units and took
about 300 us. In the `production` prefill trace on the W7900 it was the third stage: 466 of
3,598 ms of kernel time at 2,057 prompt tokens (13%) and 128 of 1,002 ms at 575.

A row of the convolution reads its own input and the three inputs before it, so the rows do not
depend on one another. The block kernels now give one thread to each (row, channel) and sum in the
serial kernel's order; a second launch commits the history from the untouched input. One row keeps
the serial kernel, which may write over its input. A block of several rows writes into an output
of its own, because its inputs are other rows' outputs otherwise: `Inkling2DeviceConvolution` holds
a scratch for that and copies the result back for the two callers that convolve in place. The
arithmetic is unchanged and the results are bit for bit the serial ones.

## Changes

- `quant/inkling2_short_conv.hip`: `short_conv_rows`, `short_conv_dynamic_rows` and
  `short_conv_commit` serve blocks of several rows; the serial kernels stay as
  `hipengine_inkling2_short_conv_block_serial` and `hipengine_inkling2_short_conv_dynamic_serial`.
  Both entries refuse a block of several rows whose output is its input.
- `inkling2_short_conv.py`: the dynamic launcher takes `out`; both launchers refuse what the
  entries refuse.
- `Inkling2DeviceConvolution`: a scratch output for `apply_static` and `apply_dynamic` at several
  rows, copied back on the same stream. One row and the undo path are as before.
- `docs/KERNELS.md` describes the two forms.

## Validation

- `tests/test_gpu_inkling2_short_conv.py`: 221 passed on the W7900. New cases compare output and
  history as uint32 for 1 to 256 rows, 100 to 2,304 channels, one, three and four taps, static and
  per-row taps, and the projected dynamic kernel at 8 heads of 128, 3 of 67 and 2 of 32. The
  existing cases still hold, among them a block split at rows (0, 1), (1, 8), (8, 11) and (11, 12)
  with the first row convolved in place, which is what showed that the history must be committed
  from the input before anything writes over it.
- The Inkling GPU and unit test files pass with the model present: 638 in 4 minutes 25 seconds.
