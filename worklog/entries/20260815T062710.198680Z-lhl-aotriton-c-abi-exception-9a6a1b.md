# AOTriton C ABI exception containment

## Summary

Vendored AOTriton v3 can throw `std::runtime_error` while selecting/launching a
solution.  Five Q8 mixed-shape coredumps showed that exception crossing
`hipengine_aotriton_attn_fwd_v3_compact_varlen`'s `extern "C"` boundary into
ctypes, where C++ calls `std::terminate` and aborts Python.  The C ABI now
catches vendor exceptions and converts them to `hipErrorUnknown`, allowing the
existing Python `_check_hip` path to raise a normal fail-closed `HipError`.

No automatic attention fallback is attempted after an exception because the
wrapper cannot prove whether a vendor dispatch was partially submitted.  An
explicit Python error is the correctness-preserving policy.  Successful v2/v3
routes, including current p512 production AOTriton, are unchanged.

## Changes

- Marked the three direct-vendor C entry points `noexcept`: GPU compatibility,
  v2 compact-varlen attention, and v3 compact-varlen attention.
- Added catch-all guards that return `hipErrorUnknown`; the v2 guard releases
  its per-call causal atomic allocation before returning.
- Added a source-contract RED/GREEN test freezing the exception-safe C ABI.
