# Muse tuning anti-overfit check: tuned DFlash path runs through the real server API, token-exact vs AR

## Summary

Lead asked whether this session's Muse tuning (LDS-padded prefill/verify, adaptive-split shared
decode attention, combine live-scan, norm) is overfitted to the mtpbench harness or actually works
through the real `hipengine serve` OpenAI-compatible API. Answer: **not overfitted.** The tuned
DFlash path executes through the server and is output-invariant — AR and DFlash return identical
token IDs for short-chat, raw-completion, and 6011-token long-context prompts; repeats are
deterministic; buffered output equals streaming. No production code changed; this is an evidence
unit.

## Validation

- **Server integration bundle:** `tests/test_integration_server_*.py` (27 files) — **1043 passed, 0
  failed, 0 skipped**.
- **Live server exercise** (`hipengine serve` under `rocprofv3 --kernel-trace`, production defaults,
  `--speculative-provider dflash --draft-model dflash-Muse-Glimmer-30B-Q4_K_M.gguf --kv-storage

    `muse_glimmer_flash_prefill_wmma_mt_kernel` ×1144 (LDS-padded), shared decode attention ×13520
