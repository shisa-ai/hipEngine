# Retain Qwen3.6-27B sole-T16 XTX first fit

## Summary

Retained the first operation-complete Qwen3.6-27B Q4_K_M layout that fits the
23.984-GiB RX 7900 XTX. All 288 rank-2 Q4 weights now own one
`gguf_q4_k_t16_v1/tiles` payload instead of pack8 plus T16. The plan census
moves 10,790,502,400 alternate-layout bytes to zero. This is an implementation
checkpoint, not campaign closure: the best current 512/1 diagnostic is
695.854 prefill tok/s at 16.749 tracked GiB, below the frozen 974.252-tok/s HIP
speed gate and above the 15.690-GiB Vulkan memory ceiling.

## Changes

- Added package-capability-driven sole-Q4T16 materialization for target and
  trailing NextN weights. The legacy dual-layout plan remains an explicit
  control, while normal gfx1100 materialization uploads T16 directly and never
  builds pack8 first. gfx1151 remains excluded pending its own gate.
- Routed canonical T16 bytes through exact c1 single/dual-SiLU decode,
  rows-2-4 verifier owners, dense prefill, and same-layout unfused fallbacks.
  Removed llama-compatible Q8 raw/sidecar overrides that violated the
  single-layout plan invariant.
- Added dense Q4/Q5/Q6 T16 prefill owners. Actual-weight screens retained Q4
  48x64, Q5 32x64, and planar-Q6 48x64 wave tiles. Q4 then gained a local128
  exact cooperative owner: four waves share one decoded 48-column K256 B slab
  across 256 input rows. Paired actual-layer speedups are exact and positive;
  Q4 shared-B is 1.216x on FFN gate and 1.235x on attention gate at M512.
- Added mapping/residency/NextN and GPU CPU-reference coverage, including Q4
  rows 16/33/512/1024/4096, Q5 row tails, Q6 row tails, canonical c1 and
  verifier dispatch, and no-shadow allocation assertions.
- Published
  `benchmarks/results/2026-08-12-qwen36-27b-xtx-sole-t16-first-fit.json` and
  updated the campaign, kernel catalog, benchmark rollup, and changelog.
