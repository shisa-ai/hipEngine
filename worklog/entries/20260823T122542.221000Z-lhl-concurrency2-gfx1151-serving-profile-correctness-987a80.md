# Make gfx1151 serving correctness profile-aware

## Summary

Made the F1 serving harness enforce the distinction in
`docs/EXECUTION-PROFILES.md`: control/ownership and same-schedule determinism
remain binding, while c1/cN generated-ID equality binds strict evidence but is
only diagnostic for production evidence. The default remains strict, so this
unit does not silently change prior benchmark behavior or runtime dispatch.

Production is an evidence contract, not a public runtime-profile claim. It can
represent either a named qualified profile or the explicitly labeled Qwen3.8
scoped legacy-default candidate. In both cases the harness fails closed unless a
matching complete correctness bundle is present.

## Changes

- Bumped the serving artifact schema to 2 and added
  `--correctness-profile strict|production` plus
  `--production-correctness-artifact`. The selector controls benchmark binding
  only; it does not set `HIPENGINE_EXECUTION_PROFILE` or add hot-path dispatch.
- Added fail-closed validation for bundle kind
  `hipengine_server_production_correctness_bundle`: same physical host, model
  fingerprint, backend, registry quant, KV policy, explicit FP16 recurrent-state
  environment, no physical-width override, runtime-equivalent source ancestry,
  immutable source-artifact hashes, registered strict fallback, and passed
  numerical, repeat-determinism, isolation, control/ownership, lifecycle,
  BF16-relative, and task-quality gates.
- Mechanically rechecks the calibrated production envelope (mean/p95/p99/max KL
  and overall top-1), scope failures, and required manual outlier review instead
  of trusting a top-level pass bit. Scoped legacy candidates must explicitly
  keep `profile_qualification_claim=false`; named production must claim true.
- Split serving row verdicts into binding control mismatches and diagnostic
  generated-ID mismatches. Production still rejects unknown prompt ownership,
  malformed token IDs, or wrong completion counts.
- Added three-run schedule-local output determinism as a binding row gate.
  Streaming now reports correctness-qualified throughput separately from exact-
  trajectory diagnostic throughput; SLO goodput uses profile-qualified rows.
