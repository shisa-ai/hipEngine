# DMS INT8 MTP parity gate against DMS INT8 AR

## Summary

DMS+INT8 MTP now has a live gate against DMS+INT8 AR on one shared retention
policy, and it passes on all four mtp-bench categories plus a forced
partial-acceptance case. Building the gate exposed a real defect in the device
payload store: `restore` brought back the payload, position, eviction and scale
planes but not the per-head live counts, so any commit that kept only part of an
appended prefix, or any rollback, left the device counts at their post-append
values and the next append failed its host/device cross-check. That is fixed and
pinned. The INT8 admission half of the task was already delivered and committed
(`eb1dda1f1`, and the decline removal in `5505f4a60`); this unit adds the live
evidence and the documentation.

## Changes

- `tests/test_live_dms_int8_mtp_parity.py` (new, live tier): both arms are
  resident `Qwen35GGUFResidentSession` DMS rows sharing one policy — same
  `dms_metadata_path`, same `create_dms_int8_evaluation_backend` factory, same
  backend. One prompt per category from
  `benchmarks/prompts/mtpbench-code-general-ja.jsonl` at a 768-token context,
  deterministically repeated so the 256-token DMS window forces compaction.
  Each arm decodes 12 tokens; the speculative arm runs three cycles of three
  candidates plus a bonus token, drafted from the AR arm's own output, which
  isolates the retention and transaction axes from draft quality. An autouse
  fixture snapshots the complete kernel table on the first case and restores it
  on later ones: this backend's package is imported lazily after the shared
  conftest takes its collection-time baseline, so its aliases (including the
  `dflash_accept_chain` kernel the verifier resolves in its constructor) would
  otherwise survive only the first case.
- `hipengine/kvcache/dms_device.py`: `DMSDevicePayloadSnapshot` carries the
  per-head live counts; `snapshot` reads them and `restore` writes them back with
  the other planes, inside the existing validate-every-extent-before-mutating
  discipline.
- `tests/test_gpu_dms_int8_device_payloads.py`: asserts the restored live-count
  plane. RED before the fix (`[1]: 16 (ACTUAL), 15 (DESIRED)`), GREEN after.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: the DMS parity item is now
  checked with its exact tested scope, the stale "artifacts are not on this host"
  note is corrected, the device-store restore is recorded, and the remaining-open
  list no longer names compact-DMS transactions.
- `docs/ENVS.md`: `HIPENGINE_DMS_MTP_MODEL` and `HIPENGINE_DMS_MTP_METADATA` in
  the test-gate section.

## Next

Pre-existing and independent: the DMS device append kernel corrupts one slot
when its in-place compaction drops at least one row. In `dms_append_decode_kernel`
pass 2, thread `k` writes slot `k-1` while thread `k-1` re-reads slot `k-1`, so
one position is duplicated and another lost; the count is unchanged, which is why
`finalize_device_append`'s host/device cross-check cannot see it. The 8193/16385
parametrizations of `test_gpu_dms_int8_device_payloads.py` are the gate that
catches it (`missing_from_device=[3743], extra_on_device=[]`). Fixing it is a
kernel unit with its own lineage and correctness gates; the live DMS+INT8 parity
gate cannot see it because both arms share the same kernel behavior.
