# Scope SPECDEC2 provider fingerprints to owned slots

## Summary

The P7 C2 provider-fingerprint qualification found that staged repeats were
identical and generated IDs matched true AR/direct, but the diagnostic hashed
both physical KV slots for each request. It therefore reported twice the direct
KV byte count and could not bind staged provider state to the direct oracle.
Scope the fingerprint to the request-owned slot and make direct equality a
binding provider gate.

## Changes

- Divide owner-level KV backing by physical slot count and hash only the visible
  rows beginning at the request slot's byte offset.
- Reject non-positive slot counts and backing that is not exactly divisible by
  slot and position dimensions.
- Require direct provider fingerprint equality in `specdec2_c1_gate.py` when
  provider fingerprint qualification is enabled.
- Add a fake-runtime RED/GREEN test asserting exact C2 slot-1 pointers and byte
  counts.

## Validation

- Before repair, `/tmp/specdec2-p7-c2-provider-fingerprint.json` passed exact
  generated IDs and staged-repeat fingerprints but reported **622,592 staged
  bytes vs 311,296 direct bytes** solely because C2 hashed the full backing.
- `uv run pytest -q tests/test_qwen35_gguf_nextn_checkpoint.py tests/test_specdec2_c1_gate.py tests/test_qwen35_gguf_mtp2_seam.py` passes.
