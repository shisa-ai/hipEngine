# The MMQ gate/up route ships on, and the flag becomes a rollback lever

## Summary

The fused int8 MMQ32 expert gate/up route is now the default path, and
`HIPENGINE_GEMMA4_MOE_GATE_UP_MMQ` is a rollback lever: unset means on, and a
falsy value restores the fp32 grouped route.

This follows the lead's decision on the gfx1100 branch, where making the route
the default was the single largest prefill step (675 -> 1367 tok/s, +102%) after
the teacher-forced check passed at worst-case KL 0.0013 and 0.00077 against the
0.05 bar with no top-1 changes. The clearing condition this flag carried in its
own definition was to re-run the gate once that decision landed and then make
this the default; the decision has landed. This branch reaches the same
conclusion independently: on realistic prose and on a truncated Python snippet
the route matches the fp32 arm token for token, and the flag's recorded cause did
not reproduce.

The flag's sense inverting is the part with teeth. Both campaign harnesses
selected their arms by popping the variable for fp32 and setting it for the
route, which under the new sense would have left the route on for *both* arms and
had the probes compare it with itself while reporting agreement. Both now set the
value explicitly, and `tests/test_unit_gemma4_expert_route.py` pins both halves.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py`: the route is on by
  default; only an explicit falsy value disables it, so a typo cannot silently
  downgrade the default path. The comment records the decision, the measurement,
  the original kl_max breach and why it no longer holds the route back.
- `scripts/gemma4_mmq_prefill_length_probe.py`,
  `scripts/gemma4_mmq_arm_attribution.py`: arm selection sets `0` rather than
  popping, which is what keeps the fp32 arm actually fp32.
- `scripts/gemma4_mmq_default_route_check.py`: the end-to-end check, kept so the
  next change to this default can re-run it.
- `tests/test_unit_gemma4_expert_route.py`: pins that unset is on, that the falsy
  set rolls back, and that an unrecognised value does not downgrade the default.
- `docs/REFACTOR.md`, `docs/ENVS.md`: the flag is a rollback lever whose removal
  condition is now a recorded teacher-forced gate verdict for the new default.
  ENVS also notes that `capture` must run with the variable set to `0`, since
  capture otherwise freezes the new default and the gate would compare the route
  with itself.

## Validation

- RED/GREEN on the flag test: the previous predicate returns False for an unset
  variable, so the new test's first assertion fails on it. `48 passed` on the
  unit tier afterwards.
- End-to-end through `hipengine.LLM.generate()` on the real UD-Q4_K_XL artifact,
  one load, two generations:
  - default (unset): `enabled=True`, `gate_up_mmq32` 29, `grouped_prefill` 30.
  - rollback (`0`): `enabled=False`, no `gate_up_mmq32`, `grouped_prefill` 59.
  - 29 + 30 = 59, so the gate/up projections move between the two routes exactly,
    and both arms produced the same continuation.
- The route predicate is read per projection rather than at load, which is why
  one load can measure both arms; that is what makes this check cheap enough to
  keep.
- `python3 audit/audit.py check` and the documentation gates run with this change.
