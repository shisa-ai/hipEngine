# Design cross-model speculative contract matrix

## Summary

Defined the narrowest shared contract matrix for the Generation-2 staged speculative seam without changing production code. The existing focused test file is the implementation of this matrix and already covers the required model-shaped owners, ownership boundaries, KV metadata variants, and sampling decisions.

## Matrix

| Contract surface | Dense Qwen GGUF | Qwen MoE GGUF | Qwen PARO | DMS compact KV | Required assertion |
| --- | --- | --- | --- | --- | --- |
| Staged owner resolution | yes | yes | yes | explicit refusal | `StagedSpeculativeRunner` validates and resolves; DMS does not silently opt in |
| Concurrent staged state | two interleaved stream IDs | two interleaved stream IDs | two interleaved stream IDs | no target work | prepare/propose state remains isolated by stream and owner |
| KV binding | paged BF16, packed scratch | dense INT8 metadata, packed scratch | paged BF16, packed scratch | compact INT8 metadata, reversible journal | storage view, codec scales, retention topology, and transaction mode are self-consistent |
| Cross-shape mismatch | reject DMS view and wrong transaction mode | same capability invariant | same capability invariant | remains unavailable | reject by named `ValueError`, never reinterpret metadata |
| Greedy capability | admitted | admitted | admitted | refused by name | supported mode remains `greedy` |
| Sampled capability | refused by named mode reason | admitted and advertises `sampled` | refused by named mode reason | refused by named DMS reason | no sampled request is downgraded to greedy or AR through the staged owner |
| User-visible DMS boundary | n/a | n/a | n/a | `configure_engine_loop` refusal | error names `speculative_mtp_serving='off'` as clearing setting |

The matrix deliberately uses lightweight owners for shared lifecycle properties and keeps model-specific delegation in the existing dense/MoE/PARO seam tests. Existing provider, frontier, and sampling tests remain the supporting fixtures: provider validation covers incomplete/hybrid owners, frontier tests cover typed KV and transaction invariants, and sampling tests cover the complete sampled blocker vocabulary.
