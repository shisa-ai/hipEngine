# Verify the advertised decode route live at three server configurations and correct the resident-prepare guidance

## Summary

The decode-route advertisement landed with unit and integration coverage but had
never been read from a real Flash-Next process. It is now verified against three
live configurations, and the negative configuration exposed a second defect.

Advertised versus executed, all measured on this host:

| Configuration | Advertised `path` | `enabled` | Executed evidence |
| --- | --- | --- | --- |
| switch off | `qwen4exp_c1_request_owned_step` | `false` | no batch state before or after two concurrent requests |
| `AR_BATCH=1`, `SLOTS=4` | `qwen4exp_full_model_ar_batch` | `true` | four concurrent requests ran as `step_widths {"4": 2}`, two steps, four HTTP 200 |
| `AR_BATCH=1`, `SLOTS=9` | refused at startup | — | readiness `status: error`, stage `resident_prepare`, message names `SLOTS=9 exceeds the qualified physical width 4` |

The defect: every `resident_prepare` failure carried the guidance "Try a lower
`--max-context-tokens` or `--kv-storage int8_per_token_head`." That advice cannot
fix a width bound, and it points an operator at two settings that are not the
problem. The guidance now depends on the failure: an allocation error keeps the
capacity hint, anything else names a configuration error and defers to the log
line that carries the exact setting. The startup log and the readiness payload
use one helper, so they cannot disagree.

The refusal itself is correct and unchanged: an unqualified width stops the
server instead of silently serving on C1 with the switch on.

## Changes

- `hipengine/server/api.py`: added `_resident_prepare_guidance(exc)` and used it
  for both the startup log line and the readiness guidance. The allocation hint
  now requires an allocation shape (a quantity and a memory context), so an
  unrelated "requires ..." sentence cannot borrow it.
- `scripts/qwen4exp_decode_capability_probe.py`: new diagnostic that reads
  capabilities and `/v1/hipengine/decode` before and after real concurrent
  generation and fails on disagreement, on a switch that contradicts the
  server's environment, or on an advertised width the server never ran.
- `tests/test_unit_server_startup_guidance.py`: 9 parametrized cases over the classifier.
- `benchmarks/results/2026-10-18-zbook-qwen4exp-decode-capability-{off,w4,invalid-slots}.json`:
  the three live artifacts, 9 + 9 + 5 checks.
- `docs/QWEN4EXP-PRODUCTION-SERVING.md`: PS9 records the live evidence and what
  remains open.
