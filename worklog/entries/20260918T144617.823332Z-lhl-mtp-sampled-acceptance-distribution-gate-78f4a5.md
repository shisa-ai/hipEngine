# Sampled MTP acceptance: exact on real target rows, route still closed

## Summary

Temperature sampling is the largest remaining reason a real request cannot use MTP
at all: every processor except an EOS gate makes the row non-speculative, so a
served workload at `temperature > 0` runs autoregressive regardless of how well the
draft model performs. The blocker was never acceptance itself but the *accept
rule*: the verifier's argmax accept emits `argmax(p)` where the autoregressive path
emits a draw from `p`, so a speculative cycle at temperature is a different
distribution than the request asked for.

This unit adds the missing half of the sampled route and proves its arithmetic on
real target rows, while keeping the route **closed to serving**: the accept rule now
emits the drafted token with probability `min(1, p/q)` and otherwise resamples from
`normalize(max(0, p - q))`, which is exactly `p`-distributed, and the adapter reaches
it only when a model-plugin **evidence row** for `(backend, arch, quant, artifact
size)` advertises the `sampled` sampling mode. No such row exists yet, so shipped
behavior is unchanged: the engine loop's new `sampled` planner mode resolves against
a capability that still advertises `("greedy",)` and falls back to the
autoregressive step with `UNSUPPORTED_SAMPLING`.

The gate that has to pass before such a row can be written now passes on real
gfx1151 logits (Qwen3.8-27B `Q4_K_M`, three prompts, eight decode steps each):
**824/824 induced-law comparisons exact** (max total variation 4.5e-16, max KL
9.0e-16, top-1 agreement 1.0 against a 1e-9 tolerance) over supports up to 248,320
tokens, **144/144** autoregressive-law agreements, and a black-box Monte-Carlo arm
that drives the real accept/resample walk 4,000 times per sampler config with
top-1 agreement 1.0 and no cell failures. So the sampled accept is not merely
"close": on the model's own next-token rows the emitted token is the
autoregressive token's law.

## Changes

- `hipengine/speculative/sampling.py` (new): `SparseDistribution`,
  `processed_distribution`, `acceptance_probability`, `residual_distribution`,
  `sampled_accept_from_distributions`. The accept walk returns per-row accepted
  tokens plus the bonus/residual token, drawing from a caller-supplied unit
  interval stream so the row's own sampler stream stays the only randomness.
- `hipengine/generation/sampling.py`: `speculative_serving_sampling_mode`
  (`greedy_fast` / `processed_argmax` / `sampled`) and the servable/unservable
  blocker split (`SAMPLED_MTP_SERVABLE_BLOCKERS`, `sampled_speculative_mtp_blockers`,
  `supports_sampled_speculative_mtp`). Servable: temperature, `top_p`, `top_k`,
  `min_p`, repetition/presence/frequency penalties, `logit_bias`, suppressed ids,
  `min_tokens`, stop ids/sequences, `ignore_eos`, an EOS gate. Unservable (route
  keeps the autoregressive step): `logprobs`/`top_logprobs`, forced tokens,
  post-thinking forcing, forced sequence completion, JSON close forcing, and the
  thinking hard cap.
- `hipengine/generation/mtp_sampled_accept.py` (new): turns the verifier's own
  `target_logits` into per-row accept summaries using the request's live
  `RowSamplingState` and the adapter's token decoder.
- `hipengine/generation/qwen35_gguf_mtp2.py`: the sampled route. `propose_batch`
  skips the device proposal for a sampled row and proposes eagerly on the host;
  `execute_target_frontier` verifies with `return_logits=True`, no device
  proposal, no graph, replaces the argmax kernel's summary with the sampled one,
  and observes every emitted token back into the row's sampler state.
  `capability()` advertises `("greedy",)` or `("greedy", "sampled")` from
  `_sampled_route_qualified()`.
- `hipengine/generation/engine_loop.py`: the planner reports `sampled` for a row
  whose only blockers are servable ones; the policy turns an unadvertised mode
  into `UNSUPPORTED_SAMPLING`, so this is inert until a row exists.
- `hipengine/server/api.py`: both serving-plan entry points use
  `speculative_serving_sampling_mode`, so the plan and the planner agree on the
  vocabulary.
- `scripts/mtp_sampled_accept_distribution_gate.py` (new): the gate. It integrates
  the *decision rule* in closed form and compares the induced law against the
  autoregressive law, checks that `select_token`'s reported probability is the
  token's weight in the law, and drives the real walk under Monte-Carlo.
- The artifact keeps the gate's summary and one representative row per prompt;
  the measured run's other seven rows per prompt are summarized by the same
  maxima the summary reports.
- Tests: `tests/test_unit_speculative_sampling_modes.py` (27), the gate's own
  oracle `tests/test_unit_mtp_sampled_accept_distribution_gate.py` (9), plus the
  mechanism tests in `tests/test_unit_speculative_sampling.py` and
  `tests/test_unit_mtp_sampled_accept.py`.

## Validation

Gate, three default prompts x eight decode steps, 4,000 Monte-Carlo draws,
`/home/lhl/miniforge3/envs/vllm/bin/python scripts/mtp_sampled_accept_distribution_gate.py
--use-wmma-prefill --use-gemv-decode --backend hip_gfx1151` on zbook
(Ryzen AI MAX+ PRO 395 / Radeon 8060S, gfx1151), artifact
`benchmarks/results/2026-09-18-gfx1151-qwen38-mtp-sampled-accept-distribution-gate.json`:

- exact induced-law identity: 824 comparisons, max total variation 4.53e-16, max
  KL 9.03e-16, max absolute deviation 8.88e-16, top-1 agreement 1.0, no failures;
- autoregressive law: 144/144 reported probabilities equal their weight in the law,
  supports up to 248,320 tokens (mean 165,550);
- Monte-Carlo arm: 18 rows (4,000 draws each), top-1 agreement 1.0, no cell over
  its limit; 236 s wall for the whole gate including the 51 s resident-session
  open.

The gate's integrator is itself verified against a brute-force enumeration of the
same rule (400 random distribution pairs, max deviation 2.2e-16), including the
degenerate `q == p` case where the residual has no mass, and a 200k-token support
that the previous `O(|q| x |res|)` integration could never have finished - the
first version of this gate stalled for 18 minutes on the first prompt because of
it, which is why the closed form (`min(p, q)` plus the residual mass carried by
`1 - sum min(p, q)`) is now the only implementation. Its Monte-Carlo arm is
calibrated per cell rather than by a total-variation band: a 4-sigma TV band on a
two-way split is exceeded by 1.5% of seeds (200-seed measurement), so the criterion
is now an exact Poisson tail for cells whose expected count is small and a 5-sigma
normal limit above that, and a test patches the walk to accept every draft to
confirm the criterion fires.

Unit tests: `tests/test_unit_speculative_sampling_modes.py`,

`tests/test_unit_mtp_sampled_accept.py`, `tests/test_unit_speculative_sampling.py`,

## Next

- The serving arm is what decides whether the row is ever written: the same
  ShareGPT workload that measured **11.76 tok/s true AR against 9.37 automatic** at
  c=1 (and 23.46 against 11.74 on the tree whose verifier reproduced the target's
  own path) must be re-measured at `temperature > 0` with the sampled route open,
  against a matched true-AR control inside the same load. Until that measurement
  exists, the evidence row stays unwritten and every temperature request keeps
  running autoregressive.
- The sampled route currently forces the eager host proposal and forbids the
  target graph, because the accept summary has to come from host logits. The
  graph path needs a device-side accept that reads the row's sampler state; that
  is a separate unit and the reason the route is not merely "a flag away".
- `speculative_sampling_mode`'s `processed` mode is now only reachable for
  unservable processors; if the serving arm fails, the unservable set is where the
  remaining coverage work belongs (in particular `logprobs`, which is common in
  real clients and cheap to serve from the sampled distribution).
