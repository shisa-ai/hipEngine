# R0137 verifier prefill-GDN capture owner transport

## Summary

`HIPENGINE_GGUF_VERIFY_CAPTURE_PREFILL_GDN` selects the captured-row producer
for the target verifier (prefill-shaped no-copy Conv/GDN state rows versus the
decode-order chain) and is a hard precondition of the packed target verifier.
The process environment remains the unbound/direct diagnostic input, but it is
no longer the carrier between owners. A profile binds the decision on the
generator, the runner freezes it before any session or weight exists, sessions
inherit the frozen bool at construction, and every verifier operation that
requires the mode states it explicitly. The unbound default is resolved once at
construction; later ambient mutation cannot retarget an owner, and no
production read consults ambient state to accommodate a test double.

## Changes

- `runtime/qwen35_gguf_runner.py`: owner field
  `target_verifier_prefill_gdn_capture`, idempotent
  `_freeze_verifier_prefill_gdn_capture()` called from the initializer, session
  inheritance of the frozen bool, `capture_prefill_gdn` on
  `verify_target_block` / `verify_target_blocks_batch`, and the resolved pass
  mode bound into the layer-stack linear operation. The packed-verifier guard
  reads the resolved pass value. `_prefill_gdn_capture_for_call` and
  `_capture_prefill_gdn_for_call` read explicit input first, then the
  constructor-owned bool; neither resolves ambient lazily.
- `runtime/gguf_native_spec_cycle.py`: the capture mode is a new
  `_native_target_configuration_key` axis, inserted after
  `capture_linear_state_rows`, and a required input of `compatible_with`,
  `can_launch`, and `launch_ineligibility_reason`. A decode-order graph
  therefore rejects a capture-order call with
  `target_graph_configuration_miss` instead of replaying the wrong producer.
  The four capture/verify/cycle entry points take `capture_prefill_gdn` and
  resolve it from the session's frozen decision.
- `runtime/qwen35_gguf_mtp.py`: device-proposal eligibility states the mode.
- `runtime/qwen35_gguf_nextn.py`: owner transport through the NextN executor.
- `generation/qwen35_gguf.py`: generator field, session/runner transport,
  live-session validation, and explicit `capture_prefill_gdn=True` on the five
  verifier calls that require it (startup warmup packed verifier, MTP-serving
  per-session and packed verifiers, llama-compat per-session verifier, and the
  llama-compat native complete cycle).
- `generation/qwen35_gguf_mtp2.py`, `generation/qwen35_gguf_moe_mtp2.py`:
  packed verifier, sampled graph warmups, and the MoE C1 cycle state the mode.
- `generation/qwen35_dense_gfx1100_profiles.py`,
  `generation/qwen35_dense_gfx1151_profiles.py`: bind the owner decision
  instead of writing the environment. MoE gfx1100 inherits the dense binder;
  MoE gfx1151 declares no capture decision and stays unbound.

### Removed environment scopes and why

Nineteen `_temporary_env({"HIPENGINE_GGUF_VERIFY_CAPTURE_PREFILL_GDN": "1"})`
scopes were removed from `generation/qwen35_gguf.py`:

- Seventeen wrapped packed-AR prefill/decode/serving call sites whose routes
  never request captured linear-state rows, so the selector was inert:
  startup warmup packed prefill (1937), `_try_prefill_ar_serving_slots_batch`
  (4311), streamed packed decode chunks (4523, 4574), the AR serving prefill
  wrapper (5259), the AR serving stream (8581, 8600),
  `_try_prefill_native_work_batch` (9836), `_prefill_native_row` (11062),
  `_prefill_sampled_row` (11300), `_prefill_processed_argmax_chunk`
  (11419/11484/11555), `_prefill_native_chunk` (11680/11784), and
  `_step_native_chunk` (12487). `_packed_ar_prefill_linear_state_plan` always
  returns `transient_state_rows=0` / `capture_token_state_rows=False`, and the
  packed decode step runs the attn-only linear path, which takes no capture
  flag.
- Two were the route scopes that actually carried the requirement:
  `_staged_adapter_arch_environment` and `execute_speculative_cycle`. Both now
  publish only the target architecture, and the staged adapters pass
  `capture_prefill_gdn=True` on the calls that need it.
- `_LLAMA_COMPAT_MTP_ENV` no longer carries the selector; the llama-compat and
  MTP-serving verifier calls state it explicitly.

### Dense generator -> NextN seam failure and repair

A public parent probe under a dense owner (`target_verifier_prefill_gdn_capture
= True`) with the ambient input at `0` showed the NextN draft runner resolving
`None -> False`: `Qwen35GGUFBringupGenerator._acquire_dense_mtp_draft_provider`
passed only the Q4-rowtile and FP16 fields to
`Qwen35GGUFNextNDraftProvider.from_model`, so the runtime constructor's new
parameter kept its `None` default. The probe failed with zero allocations;
artifacts were preserved by the parent as
`/tmp/r0137-gdn-public-strict-initial-nextn-miss.json` and `.log`.

Repair: the same seam now forwards
`target_verifier_prefill_gdn_capture=getattr(self,
"target_verifier_prefill_gdn_capture", None)`, so the provider, executor,
runner and session all receive the owner decision and the runner freezes it
before any NextN weight or session exists.

All generator -> NextN constructor calls were checked: `qwen35_gguf.py:3472` is
the only `Qwen35GGUFNextNDraftProvider.from_model` site, and `from_model`
forwards `**executor_kwargs` to `Qwen35GGUFNextNExecutor`, which forwards the
field to both its runner and its batch session. `_new_mtp_draft_runner` is the
legacy resident MTP draft runner, not a NextN provider. The four
`_acquire_dense_mtp_draft_provider` callers (three in
`generation/qwen35_gguf_mtp2.py`, one in `generation/qwen35_gguf.py`) all route
through the repaired seam.

RED test: two cases in
`tests/test_unit_qwen35_gguf_verify_capture_prefill_gdn_owner_transport.py`
exercise the real `_acquire_dense_mtp_draft_provider` with a fake provider that
records its constructor kwargs. They failed with `KeyError:
'target_verifier_prefill_gdn_capture'` before the repair. They cover
`True`/`False`/`None` transport and pool reuse (release then re-acquire returns
the same provider, one construction, same key, owner still `True`).

## Transactional verifier → N2 graph seam

`Qwen35GGUFTransactionalVerifier` (`runtime/qwen35_gguf_mtp.py`) is the
public-MTP owner: it always requests `capture_linear_state_rows=True` and
`defer_linear_state_commit=True`, and the staged adapter used to wrap the whole
cycle in ambient `capture=True`. After the owner move, `prepare()` still built
`native_kwargs` without the mode, so the spec cycle resolved the session's
frozen bool, while `device_proposal_ready()` read
`target.verifier_prefill_gdn_capture` directly. An unbound or explicit-False
target therefore captured (or rebuilt) a decode-order graph during transactional
verification even though the adapter's prefill warmup had cached a capture-order
graph, and eligibility then reported `target_graph_configuration_miss` against
that cached graph.

Two rejected repairs, recorded so neither returns:

- Forcing `True` in `runtime/qwen35_gguf_mtp.py` alone would have changed six
  direct diagnostics. `scripts/gguf_mtp_lifecycle_gate.py`,
  `gguf_mtp_long_context_gate.py`, `gguf_mtp_long_context_task_gate.py`,
  `gguf_mtp_prompt_priming_bench.py`, `qwen35_gguf_mtp_e2e.py`, and
  `qwen36_dense_gguf_suite.py` construct `Qwen35GGUFMTPDecodeSession` directly
  and set no capture env (grep: 0 occurrences in all six), so they ran
  decode-order before this unit.
- Deriving the mode from the cached graph (`graph.capture_prefill_gdn`) let warm
  cache contents choose arithmetic: an owner=False operation silently switched
  to `True` only because a graph happened to be cached, and it would miss again
  after eviction. Cache metadata is not operation policy.

Accepted repair: the verifier declares its own mode.

- `Qwen35GGUFTransactionalVerifier.__init__` takes
  `capture_prefill_gdn: bool | None = None`, validates it, and stores it as
  `self.capture_prefill_gdn`. `None` means "defer to the session's frozen
  decision".
- `_declared_capture_mode()` returns the declared bool, otherwise
  `target.verifier_prefill_gdn_capture`. It never reads graph metadata.
- `prepare()` states it in `native_kwargs`; `device_proposal_ready()` states it
  in the eligibility call. Both are independent of cache presence, so eviction
  does not change the requested producer.
- `generation/qwen35_gguf_mtp2.py` passes `capture_prefill_gdn=True` at its
  three public staged-adapter construction sites (batch verifier, singleton
  verifier, provider-group verifier), matching the scope the removed ambient
  write used to force.
- The `Qwen35GGUFNativeB2TargetGraph.capture_prefill_gdn` field added for the
  rejected lookup is removed; the capture mode remains a required
  `_native_target_configuration_key` axis.

Direct diagnostic compatibility: a standalone `Qwen35GGUFMTPDecodeSession` or
verifier constructed without the argument keeps the session's frozen decision,
so the six gate scripts run the route they ran before. The public staged adapter
declares `True`, and the dense generator's direct
`Qwen35GGUFMTPDecodeSession` (`generation/qwen35_gguf.py:4756`, no explicit
verifier) resolves through its profile-bound session, which is `True` for the
dense profiles.

The transactional seam repair changes only the declaration and transport of
capture mode; it does not change arithmetic or defaults.
