# Admit speculative BF16 independently of INT8 scale metadata

## Summary

Generic `speculative: true` admission now ignores scale metadata when the
loaded KV storage is BF16. This fixes rejection under the CLI's FP32 scale
default without admitting INT8 to a BF16-only provider route.

## Changes

- Resolve storage from loaded-engine capability provenance, with the existing
  KV policy resolver as a compatibility fallback for engines without provenance.
- Keep the explicit requested-storage guard. Also reject effective non-BF16
  storage even if the requested spelling is `auto` or `bf16` and INT8 scale
  metadata otherwise looks valid. Preserve non-BF16 scale diagnostics.
- Add CLI-default and explicit-policy unit coverage, real chat request schema
  coverage, and mocked HTTP completion/chat admission cases. Negative HTTP
  cases verify rejection before prepare or generation.
- The independent implementation child was reviewed by the parent. Parent review
  identified the effective-INT8/auto bypass in the initial patch; the child
  reproduced and repaired it. Parent also corrected the unit chat fixture to
  instantiate `ChatCompletionRequest`, not a completion with extra fields.
