# Surya OCR transcription acceptance and numerical gate

## Summary

The Surya lane's only end-to-end gate was "reproduce the committed oracle's
greedy token ids". That is regression coverage, not transcription
qualification, and it is weaker than it looks: the committed
`oracle_greedy.json` continuation is a degenerate repeated `<ul><li>` run
produced by the ad-hoc prompt `"Transcribe this page."`, which is not one of
Surya's training-time prompts. A lane could pass by reproducing garbage, and
the layout-JSON cases cannot measure whether any text was read at all.

This unit adds (a) the intended full-page HTML transcription protocol with a
torch-free parser, (b) a scorer that measures transcription against the text
actually drawn on each fixture page, and (c) a teacher-forced full-vocabulary
KL / top-1 gate so a changed-arithmetic route can be qualified by drift rather
than by all-or-nothing ID equality.

## Changes

- `hipengine/generation/surya_protocol.py` — new torch-free, stdlib-only
  module: the pinned training-time prompt strings
  (`FULL_PAGE_HTML_PROMPT`, `LAYOUT_JSON_PROMPT`, `BLOCK_HTML_PROMPT`) and
  `parse_full_page_html` / `extract_text` / `extract_tables`. Replaces the
  ad-hoc `"Transcribe this page."` prompt as the protocol under test.

## Validation

- `pytest tests/test_surya_protocol.py` — 19 pure tests, RED first
  (`ModuleNotFoundError`), green after the module landed. Covers top-level
  block discovery, nested debug-attribute stripping, code fences, malformed
  bboxes, entity decoding, block-separated text, and table structure.
- Parser checked by hand against real fp32 output for `page_mixed.png` and
  `page_table.png`: 3 and 2 blocks with correct labels/bboxes, and the table
  read back as a 4-column header plus 7 data rows with `<`/`>` unescaped.
