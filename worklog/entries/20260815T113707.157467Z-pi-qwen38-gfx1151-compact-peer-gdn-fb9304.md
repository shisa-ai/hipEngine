# Qualify Qwen3.8 gfx1151 compact-peer GDN

## Summary

P3 qualifies the existing compact-peer wave32/XOR recurrence for Qwen3.8's
16K/48V/128x128 GDN geometry on gfx1151, with one necessary repair: unchunked
4K loses to scalar-exact direct LDS32, while state-carrying 1K recurrence chunks
are peer-bit-exact and win every 512/1K/4K gate. The backend auto policy is
quant/shape scoped; direct LDS32 remains the architecture's explicit exact
rollback.

## Changes

- Generalized `scripts/gguf_gdn_compact_peer_bench.py` to accept K/V-head
  geometry, compare compact-peer against both peer-wave and production direct
  LDS32 complete chains, record scalar-oracle error, and screen a state-carrying
  recurrence chunk.
- Added gfx1151 Q4_K_M `(16,48,128,128)` auto policy for
  `chain_compact_peer_wave32` and a backend capability fixing the recurrence
  chunk at 1,024 rows. Prepare and RMSNorm still run once over the complete
  prefill; only recurrence is chunked.
- Runtime consumes that architecture capability generically, offsets compact
  Q/K, V, beta/decay, and output pointers per chunk, and carries one recurrent
  state through all launches. Session-frozen route and plugin-selected compact
  scratch capacity remain intact.

  speedups 1.5172x / 1.4786x / 1.4224x at 512/1K/4K. Candidate output and

  scalar-exact production oracle, maximum BF16 output error is 0.001953125 and
  maximum state error is 2.24e-8. Compact Q/K saves 16/32/128 MiB versus
