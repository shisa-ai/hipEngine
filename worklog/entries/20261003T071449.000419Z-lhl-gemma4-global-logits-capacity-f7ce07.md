# Gemma BF16 bounded global-logit attention capacity repair

## Summary

Gemma BF16 attention moves the existing class kernel's logits to request-owned
global workspace when its resident LDS row exceeds 64 KiB. This repairs the
recorded capacity-16640 construction failure without changing arithmetic.
The real 16384-prompt +128-output request completes at capacity16640 with finite
logits and the fallback selected through LLM.generate. No throughput comparison
is asserted. Prior baseline numerical campaign tasks are not reopened.

## Changes

- The class kernel has a compile-time global-logit storage sibling. Only logits
  move; denominator partitions, logit reduction and ascending-key V chains are
  unchanged. LDS is 528 floats (2112 bytes) for head dimensions 256/512.
- Python selects the workspace-carrying decode ABI for long multi-row prefill,
  disables flash selection on this fallback, and uses existing stream-owned
  scratch. Query rows are batched in groups of at most four to bound global
  workspace per layer as well as LDS. Unsupported head geometries retain
  their LDS bound.
- Runtime validation consumes the selected BF16 requirement; INT8 limits and
  the layer's mask/live-span materialization are unchanged.
