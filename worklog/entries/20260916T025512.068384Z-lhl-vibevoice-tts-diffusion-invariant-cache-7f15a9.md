# Cache the diffusion head's invariant work: 1.094x on the diffusion frame (~99 ms/request)

## Summary

The diffusion head recomputed three things that cannot change between the calls that
recompute them. All three are now cached, which removes **weight reads**, not just
copies -- the distinction that the neutral condition-upload experiment in
`20260915T205238.929028Z` did not test:

| Work | Invariant across | Recompute cost skipped |
| --- | --- | --- |
| `cond_proj(condition)` | the 20 solver steps of one frame | 4.72 MB of weights per step |
| timestep MLP (`t_mlp_0` + `silu` + `t_mlp_2`) | the 25 frames of a request (the 20-step schedule repeats) | 5.51 MB of weights per step |
| `silu(c)` | the head layers and the final projection within a step | 4 kernel launches per step |

**Measured by an interleaved A/B: 1.0939x on the diffusion frame, ~99 ms per
request.** Correctness is preserved by construction -- the same kernels write the
same values, which are stored rather than recomputed -- and confirmed by the fixture
parity tests, `chain_exact`, and `negative_conditions_match`.

## Changes

`hipengine/runtime/vibevoice_tts_diffusion.py`:

- `_t_mlp_cache: dict[float, DeviceBuffer]`, keyed by the bf16-rounded timestep. The
  first frame fills all 20 entries; later frames reuse them.
- `_cond_proj_key`, holding the last uploaded condition bytes. The copy **and** the
  `cond_proj` GEMV are skipped when the condition is unchanged.
- `silu(c)` hoisted above the layer loop and reused by every `L{i}_adaLN` and
  `final_adaLN`. Nothing in the loop writes `b["silu"]`.
- `close()` frees the cached buffers.

### Speed -- and why the first number I took was wrong

A cross-process comparison against the previously recorded 46.297 ms/frame suggested
**1.2649x (+242 ms/request)**. That is inflated: sustained load heats the GPU, so a
fresh process is fast and then settles. Per-frame profile of the same process:

```
frame 1 (cold cache fill) : 109.8 ms
frames 2-3                :  35.9, 35.5 ms
frames 4-8                :  40.7, 42.6, 42.4, 42.5, 42.5 ms
```

So I ran an interleaved A/B instead, toggling the cache off (clearing it) and on
between consecutive frames in one process:

```
cached  : 35.6 41.5 42.8 42.5 42.3 42.3 42.3 42.3   median 42.34  min 35.57
uncached: 37.5 46.9 46.3 45.8 46.5 46.9 45.3 46.3   median 46.32  min 37.46
=> 1.0939x median, +99.4 ms/request
```

Both arms drift identically, which is what makes the interleaved comparison the
trustworthy one. **1.0939x is the number to quote, not 1.2649x.**

The saving exceeds the pure-bandwidth estimate (4.91 GB skipped / 175 GB/s = 28 ms),
which is expected: these are `rows=2` GEMVs where the block-wide reduction tree, not
the stream, dominates, so removing the call saves more than its weight bytes.

### End-to-end

```
uv run python scripts/vibevoice_tts_session_bench.py --repeats 3
-> pooled_rtf 1.204, warm 4.012 s
   lm 1.530  diffusion 1.178  semantic 0.792  decode 0.329  prompt 0.184
```

The diffusion stage moved 1.230 -> 1.178 s (-52 ms). That is smaller than the
per-frame A/B's ~99 ms and sits inside this harness's run-to-run spread (the retained
1.201 and a verification re-run at 1.228 bound it), so **the per-frame A/B is the
evidence for the win and the end-to-end figure is corroborating, not decisive.**

### First-frame cost

The cold frame is 109.8 ms against ~46 ms warm, because it fills all 20 timestep-MLP
entries. That is not extra work -- the uncached path computes those same 20 MLPs,
spread across the frame -- it is the same work concentrated into one frame. A request
pays it once.
