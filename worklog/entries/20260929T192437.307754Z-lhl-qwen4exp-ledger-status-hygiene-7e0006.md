# Five stale ledger status prefixes corrected to match their own recorded conclusions

## Summary

Five ledger rows led with an `OPEN`/`A` status while their own appended bodies concluded that
the row was closed. The status column is the ledger's primary scanning aid, so a reader would
have misread **five closed rows as open work**.

| row | stale prefix | body actually concluded |
|---|---|---|
| X-5 | `OPEN — audit first` | AUDIT COMPLETE |
| EG-3 | `OPEN, no experiment` | STAYS CLOSED |
| QA-5 | `OPEN, re-rank` | CLOSED AS STALE PREMISE |
| RT-3 | `OPEN — after fixed-chunk measurements` | PREMISE FALSIFIED |
| MT-1 | `OPEN — primary verifier experiment` | BODY PASS FOUND |

All five were advanced during this session: the body was rewritten with the new conclusion but
the leading status phrase was not, which is exactly how this drifts.

## Changes

- `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md`: five leading status phrases corrected.
- `benchmarks/CHANGELOG.md`: dated entry.

## Validation

- **Only the leading status phrase changed.** No finding, measurement, number or conclusion was
  altered; each replacement is drawn from the row's own recorded wording.
- Re-checked programmatically afterwards: **zero** remaining rows lead with a status that
  contradicts a closed conclusion, **70** rows, **70** unique IDs (unchanged).
- The detection rule is stated so it can be re-run: a row whose status begins `OPEN`/`A`/`B`/`C`
  while its body contains any of AUDIT COMPLETE, STAYS CLOSED, CLOSED AS, REJECTED, RESOLVED,
  FALSIFIED, COMPLETE, PASSES, NOT PROMOTED, MEASURED AND CLOSED, BODY PASS FOUND.
- Docs-only change; no GPU run and no performance claim.

## Next

Worth keeping: when a row's body is rewritten with a conclusion, update its leading status
phrase in the same edit.
