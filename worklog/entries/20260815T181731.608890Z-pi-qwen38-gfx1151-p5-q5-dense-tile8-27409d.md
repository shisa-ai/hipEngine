# Screen Qwen3.8 gfx1151 dense Q5T16 tile8 decode

## Summary

Screen one exact dense-Q5T16 tile8 owner for Qwen3.8's 48 recurrent-output
projections at rows1/K6144/N5120. The post-Q8_1x2 graph assigns **696.793 ms /
6.668%** selected kernel wall to this family. A candidate must save **104.496
ms**, or **14.997%** family time (**>=1.1764x**), to clear the campaign's 1%
request gate.

## Changes

- No production policy or resident-layout change before admission. Add one
  diagnostic sibling over the same `gguf_q5_k_t16_v1` payload that splits each
  16-column output tile into two independent 8-column local128 workgroups.
- Preserve every output's production K ownership, FMA sequence, wave32 tree,
  ordered wave-0..3 reduction, and BF16 store; only independent output-column
  ownership changes. The ordinary dense Q5T16 projection remains the fallback.
- This is an in-tree transfer from the retained gfx1151 selected-Q5 tile8 owner,
  which improved K512/N2048 selected rows by 1.1707x while cutting 128 -> 56
  VGPR. That result is a credible premise, not transferable Qwen3.8 evidence.
- The lineage audit is blocked before filtering by the absent optional
  `/home/lhl/amd-gpu-tuning/reference/atlas` checkout. No external body is
  copied.

  owner and the CPU Q5_K gate.

## Decision

fallback; residency, workspace, native rows, peer shapes, and peer backends are
unchanged. This is a retained P5 development improvement, not a clean topline.
P5 remains open because the current AR path still trails clean llama.cpp Vulkan.
