# Separate static MTP group bound from current row

## Summary

The first real automatic C2 evidence exposed a remaining D1 modeling bug:
`SpeculativeMTPServingDecision.static_eligibility` copied the current key's
`realized_group_rows`, despite its own contract documenting that this field is
an evidence bound rather than a prediction. A request admitted at C1 therefore
advertised max rows1 and could never form the qualified C2 group.

## Changes

- Add an optional model-evidence `max_realized_group_rows` bound, defaulting to
  the row's exact realized width and constrained between that width and resident
  capacity.
- Carry the bound through admitted decision fingerprints/telemetry into typed
  static eligibility; dynamic exact-row matching remains unchanged.
- Add a production cap4/C1 intent row with max group2 so independent requests
  may form C2; the exact C2 row still owns K3 selection after grouping.

## Validation

- Serving capability and MTP2 seam tests pass **74/74**.
- The C1 static decision is automatic-eligible with max group2; C2 resolves the
  exact automatic K3 row; D25 remains fail-closed.
- No backend/provider mutation or C/K selection moves into static admission.
