# Close out the INT8 readiness checklist, CHANGELOG scope, and API admission note

## Summary

The readiness checklist's open rows are now closed with the surface each was
actually tested at, except one that stays open with a concrete limitation and its
owner. CHANGELOG's unreleased section states the INT8 MTP sampling/packed/DMS
scope, and API.md documents the resident-memory admission budget. All four doc
gates pass.

## Changes

- `docs/reference/INT8-MTP-SERVER-READINESS.md`: 12 rows resolved -- 11 checked
  with their tested surface, 1 left open.
  - Checked: structural reasons before mutation (sampling blockers, named layout
    refusal, named packed capability miss, pre-allocation resource refusal);
    candidate depth and context from implementation capacity (the 1024-token
    live-context gate is gone); graph reuse after cancellation/growth/
    reassignment/scale reallocation; the unified admission budget; pool growth
    and final reclaim (with the shrink half named as a pinned no-op, since
    `shrink_idle` returns 0); multiple choices, tools and structured output with
    the nested route report; event-loop responsiveness under driver pressure;
    error status and retryability; the public matrix at the shipping profile;
    determinism and neighbour isolation; and the performance claim's artifact.
  - Left open: prefix reuse after a cancelled request, with MTP enabled and
    disabled. Its stated owner, the live lifecycle arms, is still open, and the
    remaining gap is named precisely: the session-level allocation trace for a
    request cancelled *after* its prefix was reused.
  - Scope notes rather than claims: tree masks are not a route this engine
    implements (the candidate ladder is a linear chain), and stop/cancel/refill
    transitions are covered by the lifecycle and teardown gates rather than by
    the matrix run.
- `CHANGELOG.md`: a Known Limitations subsection under Unreleased covering the
  supported INT8 speculative scope (dense GGUF with a NextN head, uniform paged
  per-token/head INT8 K/V, fp32 per-token-head scales, packed widths up to the
  artifact's admitted no-mirror capability), compact DMS as a retention topology
  that verifies through the serial-exact route because the packed decode graph is
  BF16-only, where the route report actually lives, and the structured-request
  decline with its one recoverable precommit fallback.
- `docs/API.md`: the resident-memory budget prices target KV and scales, draft
  KV, verifier scratch, the decode graph and retained prefix entries together,
  refuses before allocation naming the consumer, and is answered as capacity
  rather than as an internal fault.
- `tests/test_live_mtp_http_surface.py`: the port is no longer an environment
  override. The docs gate correctly flagged the knob as undocumented, and a
  test-only variable does not belong in the env-var reference; the default was
  already the value used by the passing run.
