# AR-only NextN omission proven; MTP K0-to-K blocked

## Summary

Packet 2's AR-only proof is complete: with MTP serving off (the retained
default), the materialization plan omits the 4 NextN tensors (0.052 GiB source
bytes in the GGUF) and the resident census holds 851 tensors / 15.992 GiB with
zero NextN bytes. The dense NextN draft provider is acquired lazily only when
a request engages the route and is pooled after engagement (never
load/unloaded per decode cycle), so "true AR-only" is the default
configuration, not something to build. The K0->K resident delta (draft weights
+ runner/session + graphs + hidden capture) is blocked by an MTP-serving
functional bug and is recorded for the MTP campaign:

- Server startup scratch probe with `--speculative-mtp-serving enabled`
  (N=2, ctx 3072) fails: `KeyError 'blk.40.attn_q_norm.weight'`. The NextN
  block resolver is correct for this model — block 64, all 17 required
  tensors present, `has_mtp=True` verified against the GGUF — so the stale
  blk.40 comes from a serving-path constant, not the model.
- The in-process c=1 retained hot loop fails with `ValueError: token id
  2147483647 is outside vocabulary size 248320` (the packed-kernel
  invalid-token sentinel reached the output ids).
- The packed MTP warmup is width-gated: at `max_active_requests=1` it skips
  with `batch_width_le_1_or_disabled`; widths engage at N>=2, making the
  server startup warmup the intended engagement vehicle (which is exactly
  what crashes).

## Changes

- `scripts/qwen38_xtx_allocation_ledger.py`: new `--speculative-mtp-serving`
  flag. `off` (default) records the AR-only proof fields; `enabled` runs the
  server startup-warmup path (`prepare_request_scratch` under
  `HIPENGINE_GGUF_MTP_SERVER_STARTUP_WARMUP=1`), records the warmup gate
  result, and points at the probe as the K0->K vehicle. Post-hoc draft
  acquisition on an AR-only load cannot work by design (the plan
  deliberately omitted NextN), which the ledger now documents.
- Artifact:
  `benchmarks/results/2026-09-06-rx7900xtx-capacity-ar-only-nextn-omission.json`.
