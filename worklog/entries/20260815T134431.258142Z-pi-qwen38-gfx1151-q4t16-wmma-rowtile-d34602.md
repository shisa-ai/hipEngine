# Screen gfx1151 Q4T16 WMMA row amortization

## Summary

Rejected the gfx1151 32-column x 128-row dual-Q4T16 gate/up+SiLU
geometry. The smaller row live range is BF16-bit exact, but it loses at every
required Qwen3.8 prefill row and wins none of 45 counterbalanced pairs. Keep
the retained zero-spill 32-column x 256-row kernel byte-for-byte.

## Changes

- Temporarily reduced the operation-complete dual-Q4T16 producer from four to
  two WMMA row tiles per wave and changed the matching workgroup grid from 256
  to 128 rows. This preserves K16 WMMA order and the exact BF16 SiLU boundary.
- Restored
  `hipengine/kernels/hip_gfx1100/quant/gguf_k_t16_selected_prefill.hip`
  byte-for-byte after the leaf failed. No kernel, route, flag, or runtime change
  ships from this unit.
- Added compact rejection evidence at
  `benchmarks/results/2026-08-15-gfx1151-qwen38-27b-q4t16-row128-rejected.json`.

## Validation

- Actual immutable `blk.0.ffn_gate.weight` and `blk.0.ffn_up.weight`,
  K5,120/N17,408, 100,270,080 source bytes, 3 warmups and 15 alternating HIP
  event pairs per row: retained/candidate speedup is **0.8787x** at M512,
  **0.8916x** at M1024, and **0.9007x** at M4096. Candidate wall is
  13.81%/12.16%/11.03% higher and it wins **0/45** pairs.
- All three outputs are BF16-bit identical to retained, all are finite, and
  tracked teardown returns exactly to zero bytes.
- Source restoration passes `git diff --exit-code`; this rejected leaf does not
  justify an expensive full-model shape or natural gate.

## Next

- Do not continue blind Q4T16 row geometry. Use the post-Q5 M2 ledger to select
  a different native Q4/Q6 producer schedule with a new mechanism and a
  projected >=1% request saving.
