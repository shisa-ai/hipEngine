# Add packed verifier numerical capture

## Summary

Added diagnostic-only packed-verifier normalized-hidden capture so physical
MTP production candidates can undergo strict-teacher full-logit evaluation.
The generic direct-batch execution-profile evaluator does not exercise the
7×(root+K3)=R28 target shape. Capturing the exact BF16 lm-head inputs is compact
(~0.29 MB/R28 cycle); the unchanged Q6 root reconstructs full logits offline.

## Changes

- `HIPENGINE_GGUF_PACKED_VERIFY_CAPTURE_DIR=<dir>` writes one aligned NPZ per
  packed target call with BF16 normalized hidden rows, input IDs, positions,
  cumulative slot rows, request IDs, and transaction IDs.
- The hook is absent from the normal path except for one empty environment
  lookup; capture uses the default-stream blocking dependency only in explicit
  diagnostic runs.
- Added a CPU contract test proving row/identity alignment and exact BF16 bytes.

## Validation

- `tests/test_qwen35_gguf_target_rows.py::test_packed_verify_norm_capture_writes_aligned_diagnostic_rows`
  and the existing device-candidate staging contract pass (`2 passed`).
- Python compilation passes. No model/GPU run is needed to validate NPZ ABI;
  the C7 strict/candidate capture run is the next unit.
