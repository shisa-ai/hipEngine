# Bind native rows to scheduler KV leases and validate selected DP4A

## Summary

Public two-request generation on the W7900 now reaches native-row decode with and without the optional selected Q6_K DP4A adapter.

## Changes

- Use row-local attention spans for packed prefill and retain the single-sequence wrapper for individual requests.
- Request native-row execution at resident session construction. Admit low-numbered physical slots first on that route, bind their common BF16 KV chunk, and keep request cursors aligned. Incompatible leases retain the packed/serial route.
- Size the Q8_1 conversion workspace for all resident rows.

## Validation

- Focused prefill, capacity, scheduler, invocation, selected-adapter and execution authorization tests passed.
- Through `LLM.generate_detailed()`, Qwen3.6-35B-A3B-UD-Q3_K_M ran four native-row decode steps per arm on gfx1100 with `HIPENGINE_GGUF_DECODE_REPACK=0` and `HIPENGINE_GGUF_RAW_SELECTED_DP4A` set to `0` or `1`. Both arms returned the same text for the two five-token requests. The disabled arm observed 24 calls to the unconverted selected Q6_K leaf; the enabled arm observed 12 calls to `gguf_q4_k_quantize_bf16_q8_1` and 24 calls to `hipengine_gguf_q6_k_selected_pack8_gemv_q8_1_dp4a_bf16_bf16_out`.
- The enabled resident certificate records three native-row bindings for `gguf_q6_k_selected_pack8_q8_1_dp4a_gemv_bf16_bf16_out`, with the Q8_1 converter and `moe_q8_1` scratch-plan workspace. The disabled certificate contains the unconverted bindings. This validates engagement, not numerical equivalence across workloads or throughput.
