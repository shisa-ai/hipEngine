# PF-1b dense parity oracles green on current path

## Summary

Added `tests/test_qwen4exp_pf1_dense_parity.py`: production-shape parity
gates for the three PF-1 kernel families, all green on the unmodified
kernels. These are the RED surfaces PF-1c/PF-1d variants must keep green
before any whole-model A/B.

## Changes

- New test file only; no production code touched.
- `make_q8_0_weight_large`: vectorized Q8_0 fixture generator (the existing
  `make_q8_0_weight` int16 pattern overflows past ~4.6k output rows, below
  the 12,288-wide production shapes). Same 34-byte block layout (fp16 scale +
  32 int8), bounded deterministic pattern.

## Test inventory (19 tests, all green, zbook/gfx1151)

1. `test_pf1_mmq_policy_gates_production_shapes` (7 shapes): the
   `QWEN4EXP_Q8_MMQ_PREFILL_POLICY` gates admit rows 64–2048 and reject
   rows 32/4096 at every production `(hidden, out_features)` shape.
2. `test_pf1_mmq_chain_production_shapes` (7 shapes × current variant):
   production chain (`quantize_f32_d4x3` → guarded MMQ f32 at
   risk_threshold=0.0 → sparse exact repair) at rows=512 with seeded F32
   activations: repeat bit-equal; bounded vs the registered strict fallback
   `coltile8_rowbatch4_f32_f32_out` (max abs < 2e-3, mean rel < 1e-4, top-1
   equal) — the same envelope as the retained
   `test_qwen4exp_f32_mmq_chain_bounded_against_exact_f32_owner`, now at all
   policy shapes instead of one.
3. `test_pf1_coltile_strict_chain_bit_parity_at_production_shapes`
   (4 shapes): `coltile8_rowbatch4` == `coltile4_rowbatch8` ==
   `coltile16_rowbatch4` F32 bits at (2560, {96, 512, 2048, 2560}) rows=512.
4. `test_pf1_selected_q8_0_down_matches_cpu_reference`: the selected Q8_0
   down ABI (x_rows source rows × k selected experts, rows % x_rows == 0 —
   the observed 512→5120 top-10 gather) vs the per-row CPU
   `gguf_q8_0_gemv` oracle (bf16 boundary respected), repeat deterministic.

Oracle identities: strict coltile chain = cross-variant bit equality
(no reassociation); MMQ chain = production-profile bounded contract vs the
exact owner (deterministic, top-1, envelope); selected path = CPU dequant
matmul tolerance + determinism. Future PF-1c/d variants register in
`MMQ_CHAIN_VARIANTS` / `COLTILE_VARIANTS` / `SELECTED_VARIANTS`.
