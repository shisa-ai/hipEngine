# Exercise the served song path end to end with an explicit decoder

## Summary

The served song path had been exercised two ways that did not overlap: a full
request on a server that resolved the decoder from the Hugging Face cache, and a
metadata-only start on a server given `--vae-model`. This unit ran a real request
through the second: `hipengine serve --model m-a-p/YuE2-3B --vae-model <explicit
snapshot>`, one `curl` request, and the returned audio checked against the
response's own metadata.

The two independent processes produced byte-identical audio, which is the
strongest available check that the intended route ran: the flag and the cache
fallback resolved the same decoder, and the pipeline is deterministic across
processes for the same request.

## Changes

None. This unit is the exercise and its recorded result.

Commands:

```bash
hipengine serve --model m-a-p/YuE2-3B \
  --vae-model ~/.cache/huggingface/hub/models--m-a-p--YuE2-Vae/snapshots/9a94e1d0ea9f8087e98f77fa88df4a4068104d2a \
  --served-model-name yue2 --host 127.0.0.1 --port 8127

curl -sS -D headers.txt -o song.wav -X POST http://127.0.0.1:8127/v1/audio/songs \
  -H 'Content-Type: application/json' \
  -d '{"model":"yue2","style":"warm acoustic pop, fingerpicked guitar, female lead",
       "lyrics":"[verse]\nMorning light across the floor","cot":"off","steps":4,
       "seed":20261003,"request_id":"task9-live"}'
```

## Validation

Startup: `surfaces=song`, `song_session_s=6.809`, `startup_total_s=6.846`; `/ready`
200 with `backend=hip_gfx1151`, `quant=bf16` and every text timing null;
capabilities reported `loaded=true`, `endpoint=/v1/audio/songs`,
`response_formats=["wav","json"]`, the `--vae-model` path as `decoder` (no
`decoder_source` key, so the flag and not the cache), `cot_modes=["full","melody","off"]`,
and `ode_steps.default=32`.

Request: HTTP 200, `audio/wav`, 30,612,268 bytes in 410.7 s wall clock
(`X-Hipengine-Generation-Seconds: 410.667`). Server log:
`SONG: request_id=d636c4bfd9b5afe7 frames=3986 samples=7653056 duration=159.44s
seconds=410.7 truncated={'abc': False, 'semantic': False}`.

Audio: 2 channels, 16-bit PCM, 48 kHz, 7,653,056 frames = 159.439 s, peak 0.9150,
RMS 0.1030, per-channel peaks [0.901, 0.915], not silent.
File sha256 `313952a2050afd60f01c78e0e70bfd455a634ff09ee8673b2e132dab715172ac`.

Metadata agrees with the body: `X-Hipengine-Frames: 3986` and
`X-Hipengine-Duration-Seconds: 159.439` match the WAV's own frame count and
duration; `Content-Disposition: attachment; filename="task9-live.wav"` carries the
request's `request_id`; `Content-Type: audio/wav`.

Determinism across processes: `X-Hipengine-Latent-Identity`
`ed7b48f4b4219d2a37afb4b08f4f764b73d07b6903164e6e86033dde14b40a26` and
`X-Hipengine-Audio-Identity`
`7b3504140649c78c43a6bdfa1b7c8a6d4229cef6f2c0b76099ae066ecfe9ae6e` are identical
to the earlier port-8123 run, and `cmp` reports the two WAV files byte-identical
(same sha256). The two runs differ only in how the decoder directory was resolved.

Route: the response identities come from the pipeline result, the server built the
pipeline at startup (`song_session_s`), the GPU was 95-97% busy during the request
and 0% after, and the decoder directory the flag named is the one capabilities
reports. The `hip_gfx1151` runtime set the LLM-path exercise
(`worklog/entries/20261003T213100.386548Z-lhl-yue2-llm-path-exercise-3eca0c.md`)
confirmed is what `LLM.generate_song()` reaches.
