# Gemma4 D12 INT8-vs-BF16 teacher-forced screening, allocations and chunk continuity

## Summary

The next bounded D12 evaluation unit after the owner/route integration
(`20261002T192854.243394Z`). It answers the three questions that unit left
open, with a diagnostic and **not** a promotion:

1. **Screening quality.** Same-artifact, same-chain teacher-forced
   full-vocabulary logits, BF16 arm versus INT8-per-token/head arm. The INT8
   arm **fails** the binding `docs/EXECUTION-PROFILES.md` §6.1 envelope on this
   artifact and these prompts: combined 96 paired rows, KL mean `0.1426`
   (bar `1e-3`), p95 `0.8951` (bar `5e-3`), p99/max `2.4264` (bars `2e-2` /
   `5e-2`), top-1 `87.5%` (bar `99%`), 12 flips. This is a **deterministic
   numerical difference** between the two arms: both arms repeat bit-identically
   (exact raw-byte equality), so no run-to-run variation was observed under this
   repeated schedule. The cause remains unlocalized; the screen does not by
   itself exclude a wiring, consumer, or arithmetic mismatch.
2. **Execution and scheduling witnesses.** The INT8 runner's chunked prefill
   and absolute-position decode ran as scheduled: a 1087-token prefill staged
   two blocks at offsets 0 and 1024, 96 decode steps ran at increasing absolute
   offsets, and the registered writer and both consumers were selected on every
   call. Registration and offsets witness execution and scheduling; they are
   not a whole-model numerical-continuity oracle.
3. **Measured owned allocations.** At context 8192 / `max_block` 1024 the INT8
   total after construction (runner buffers `0.013 GB` + owner `2.133 GB`) is
   `2.146 GB` against the BF16 total (runner buffers, which include the K/V
   caches, `1.858 GB`), so this configuration does **not** save resident memory
   — the per-layer FP32 query/context scratch outweighs the halved payload.

The diagnostic is bounded and runnable: the script writes its artifact and
returns non-zero on a quality failure rather than refusing to run or gating the
runtime. No production kernel, runtime arithmetic, default, flag, or admission
path changed.

## What was tested, and which contract

The evaluator is reused verbatim from `scripts/gemma4_teacher_forced_gate.py`
(`evaluate`, `THRESHOLDS`, `row_kl_divergence`, nearest-rank tails, the <500-row
zero-flip screening rule). Direction is `kl(bf16 || int8)`.

Frozen contract: `docs/EXECUTION-PROFILES.md` §6.1 calibrated production
envelope (mean KL ≤ `1e-3`, p95 ≤ `5e-3`, p99 ≤ `2e-2`, max ≤ `5e-2`, top-1
≥ `99%`) plus the September 10 2026 small-chain rule (a <500-row screen passes
only with zero top-1 flips). A KV-representation change is a T3 representation
change (§5), so the standard envelope is a *diagnostic screen* here, not an
automatic-admission qualification; a different pre-existing quantized-KV
envelope was not found to apply to Gemma 4.

**Mechanism (hypothesis, not established).** The evidence is a deterministic
numerical difference; it does not by itself exclude a wiring, consumer, or
arithmetic mismatch, and the two observations below are consistent with several
causes. Two observations:

- The per-row KL is bimodal: rows where the model's next-token distribution is
  a near-delta show KL ~`1e-7`, while broad rows reach `1.7`–`2.4`. The
  near-delta rows still carry large logit shifts (top logit moved by ~1–2 units;
  full-vocabulary L2 difference hundreds to thousands), so the perturbation is
  present on every row and only becomes a KL failure where the distribution is
  wide.
- A bounded probe (`quant-probe.py`, output `quant-probe.log`, both outside the
  repository) captured the writer's BF16 K input and compared it with
  `float32(int8) * float32(scale)` over the same slots: relative L2 error
  `1.512%` (layer 0, sliding, head_dim 256, per-row max `1.821%`) and `1.180%`
  (layer 5, full attention, head_dim 512, `k_eq_v`, per-row max `4.162%`).

K-reconstruction error at two layers does not establish that quantization is
the sole cause of the full-model drift, nor that it is amplified through all 30
layers. The mechanism is a **hypothesis** pending a controlled comparison that
holds the consumer fixed while swapping in an unquantized representation of the
same written values, plus per-layer localization of where the divergence first
appears. Until that runs, "the quantizer, not the consumer" is not established.
