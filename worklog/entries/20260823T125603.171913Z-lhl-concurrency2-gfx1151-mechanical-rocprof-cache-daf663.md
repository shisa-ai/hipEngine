# Add mechanical isolated-cache rocprof workflow

## Summary

Added a mechanical, isolated-cache workflow for Generation-2 GGUF owner
profiling. A profiled process can no longer rely on an informal earlier warmup:
the workflow builds into a new scoped cache outside rocprof, proves the exact
workload starts cache-only, then optionally wraps only the final direct child.
Compiler activity or any cache mutation is a hard failure.

This unit implements and host-tests the mechanism only. It does not populate the
real Qwen3.8 cache or launch a GPU/profiler workload; task #14 performs the first
clean preparation and task #18 performs retained traces.

## Changes

- Added process-wide `HIPENGINE_BUILD_CACHE_ROOT` and
  `HIPENGINE_REQUIRE_CACHED_BUILD`. They cover every HIP/CUDA JIT builder,
  including lazy libraries without per-call flags; explicit per-call cache roots
  remain higher precedence. The resolved cache root is part of the loaded-library
  cache key.
- Extended `gguf_continuous_owner_profile_child.py` with explicit isolated cache
  root and `--require-cached-build`. It resolves gfx arch from the backend,
  requires a pinned compiler-version file in cache-only mode, exports selected
  build environment, and records cache/compiler provenance in its child JSON.
- Added `scripts/gguf_continuous_owner_rocprof.py` with three separate process
  stages: unprofiled build, unprofiled cache-only warm, and optional direct-child
  rocprof. `--rebuild` requires a new/empty scoped cache and refuses deletion;
  shared `~/.cache/hipengine/build` is never cleared or modified by policy.
- Cache snapshots hash every file's relative path, content, size, mode, and
  mtime. Parsed build manifests record family, build profile, full cache key,
  target arch, manifest hash, and code-object hashes. The artifact also records
  source commit/tree, sampled model identity, and compiler-file hash.
- Cache-only stages prepend a failing `hipcc` guard, poll the complete descendant
  tree for hipcc/clang processes, and compare immutable snapshots. rocprof runs
  kernel, marker, HIP-runtime, and memory-copy traces around exactly one final
  `gguf_continuous_owner_profile_child.py --profile --require-cached-build`
  command—never a prompt/economics parent that launches nested children.
- Profile artifacts extract actual queue IDs/count when the kernel CSV exposes a
  recognized queue column; absence remains explicit instead of inferring a count
  from `GPU_MAX_HW_QUEUES`.
- Updated `docs/KERNELS.md`, artifact provenance, and `docs/REFACTOR.md` with the
  command/protocol and later consolidation trigger.
