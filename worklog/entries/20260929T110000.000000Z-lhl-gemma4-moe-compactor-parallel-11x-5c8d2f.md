# the MoE compactor runs 11.6x faster on its registered parallel kernel

## Summary

`20260929T103000` priced the expert block's glue and found its largest single term:
**`group compact (active)` at 12.354 ms over 30 calls, 1.88 percent of the prefill**. It also
noted that 0.41 ms per call to write ~49 KB is not a bandwidth figure at any bandwidth.

The cause is in the launcher:

```cpp
// hipengine_qwen35_moe_group_compact_active
hipLaunchKernelGGL(qwen35_moe_group_compact_active_kernel,
                   dim3(1),          // <- one block
                   dim3(256), ...);

// hipengine_qwen35_moe_group_compact_active_parallel
hipLaunchKernelGGL(..., dim3(static_cast<unsigned int>(num_experts)),  // <- one block per expert
                   dim3(256), ...);
```

**One block of 256 threads was compacting every lane, on a part with 40 CUs.** The parallel
sibling launches 128 blocks.

## Why this was not already on

The parallel compactor is not new or experimental. It is registered, it is exported from
`hipengine/kernels/hip_gfx1100/moe/__init__.py`, it has its own tests
(`tests/test_gpu_laguna_h7u_parallel_moe_compaction.py`,
`tests/test_gpu_qwen35_moe_group_scatter_plan.py`), and the **CUDA backend imports it**
(`hipengine/kernels/cuda_sm120a/moe/__init__.py`). It is selected through a registered
capability:

```
$ python -c 'from hipengine.runtime.laguna_moe import resolve_laguna_group_compact_mode as r; print(r("hip_gfx1100"), r("hip_gfx1151"))'
parallel parallel
```

**Both backends already declared `LAGUNA_MOE_GROUP_COMPACT_MODE = "parallel"`.** The only caller
of the resolver was `hipengine/runtime/laguna_gguf_runner.py`; **the gemma4 expert forward never
consulted it and always took the serial kernel.** The mode was set to on and nothing on this
path read it.

## Bit-exact, measured

The compaction order determines `sorted_lanes`, which determines the row order fed to both
projections and the summation order of the weighted accumulate, so a different order would be an
arithmetic change needing the full execution-profile gate. `scripts/gemma4_group_compact_equivalence.py`
runs both compactors on the same routing and compares all three outputs:

```
tokens=1     top_k=8  IDENTICAL
tokens=512   top_k=8  IDENTICAL
tokens=4096  top_k=8  IDENTICAL
tokens=777   top_k=4  IDENTICAL
VERDICT: ALL IDENTICAL
```

That is the prefill shape, a decode shape, a larger case, and a size unrelated to either. **The
parallel compactor is stable -- it preserves the serial lane order exactly -- so the swap is a
performance change and not an arithmetic one.**

## Measured

**In place**, HIP event pair on the leaf (`scripts/gemma4_expert_mmq_wrapper_split.py`):

| part | serial | parallel |
| --- | ---: | ---: |
| **group compact (active)** | **12.354 ms** | **1.067 ms** |
| sum of parts | 152.063 ms | 144.983 ms |

**11.6x on the kernel, 11.3 ms recovered.**

**End to end**, same-session interleaved A/B restoring the parent revision of the one changed
file for the baseline arm (the protocol the accepted
`2026-09-28-gemma4-q5-1-down-mmq-load-width` candidate used):

| round | baseline (serial) | candidate (parallel) | delta |
| --- | ---: | ---: | ---: |
| 1 | 0.6618 s | 0.6534 s | **-8.4 ms** |
| 2 | 0.6631 s | 0.6578 s | **-5.3 ms** |

`public_generated_equals_expected` was `True` in all four runs.

**The end-to-end delta is 1.0-1.3 percent, which is inside this host's ~1.5 percent session noise
floor (`20260929T100000`).** It is credible because it has the same sign in both interleaved
rounds, but it is not independently resolvable here. **The claim this entry makes is the
kernel-isolation number, 12.354 -> 1.067 ms, and the A/B is supporting evidence, not the
primary result.**

## Changes

`hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py`: resolve
`resolve_laguna_group_compact_mode(gate_up_proj.backend)` and pass `parallel=` to
`qwen35_moe_group_compact_active`. No backend branch, no new flag -- the existing registered
capability is the lever, and `"serial"` remains the rollback.

`scripts/gemma4_group_compact_equivalence.py`: the equivalence check, kept as the oracle for this
choice.
