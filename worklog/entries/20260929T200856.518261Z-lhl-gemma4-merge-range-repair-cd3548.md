# Repair dense Q8 WMMA overflow and finish gemma4 merge

## Summary

Continue the pending merge of `780d24f293c2eb964ac2e5548e0153cd5bacf952`
into `gemma4`. The nine unmerged index paths already contained proposed
resolutions. The remaining dense-down workaround disabled WMMA unconditionally,
although the failure was caused by FP16 operand overflow on large BF16 inputs.
The user requested a repair, completion of the merge, and a push to `gemma4`.
No subagents were used.

## Changes

- Keep all Gemma dense projections eligible for WMMA prefill; remove the
  blanket `dense_act` opt-out and its per-projection Boolean parameter.
- T16 Q8 single-, two-, four-wave and dual-output WMMA kernels check the
  accumulator exponent before storing. Non-finite elements are recomputed
  from the original activation and Q8 weights with FP32 dequantization and
  accumulation. Finite WMMA elements are unchanged. There is no clamp, host
  readback, new launch, environment flag, or artifact-identity gate.
- This is a correctness repair, not promotion of a different finite-input
  arithmetic policy. Normal output bytes retain the existing WMMA contract;
  the formerly non-finite domain is checked against the CPU FP32 oracle with
  `rtol=1e-2`, `atol=1e-2 * max(abs(reference_row))`, including BF16 rounding.
  Existing registered T16 GEMV variants remain available as reference routes.
- Preserve the oversized synthetic fixture rather than weakening it. The new
  GPU-tier test covers rows 4/17/33, ordinary/boundary/overflow/mixed inputs,
  single/two/four-wave schedules, deterministic repeats, dual-output repair,
  and the actual Gemma runner with default expert selection. The previous
  uncommitted GPU test addition is moved out of the unit-tier runner file.
- Add `scripts/gemma4_dense_range_ab.py` for same-residency library comparison,
  public generation, resolved variants, and uncapped teacher-logit hashes.
  Keep diagnostic evidence in
  `benchmarks/results/2026-09-29-gemma4-dense-range-repair.json` and link it
  from the benchmark notes without replacing the 512/128 topline.
