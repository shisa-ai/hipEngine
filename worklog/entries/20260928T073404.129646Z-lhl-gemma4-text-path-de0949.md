# a live test now covers the gemma 4 text path that no benchmark exercises

## Summary

`20260928T073326` found that every Gemma 4 benchmark drives the model with raw token ids,
so tokenization, the chat template and text decoding are exercised by none of them. This
adds the test that covers that path.

## The gap

`gemma4_campaign_bench.py:484`:

```python
output = llm.generate_detailed(list(prompt_ids), params)[0]
```

with `prompt_ids` synthetic (`range(1000, 1000 + n)`). Kernel throughput does not care what
the ids mean, so this is the right instrument for what those benches measure -- but a
green benchmark run says nothing about the path a user actually reaches. The
chat-template requirement that `20260928T073326` resolved by hand was invisible to the
entire suite.

## The test

`tests/test_live_gemma4_text_path.py`, two cases:

| test | asserts |
|---|---|
| `test_chat_templated_prompt_generates_text` | a chat-templated prompt produces non-empty output, containing no `<eos>`, longer than 20 characters |
| `test_the_text_path_is_not_the_token_id_path` | both entry points -- `generate()` with text and `generate_detailed()` with ids -- produce output |

Guarded on HIP availability and artifact presence via the existing `_hip_available` helper
and the artifact path, matching `tests/test_live_gguf_mtp_eos.py`. Named `test_live_` so it
is not in the reviewed unit tier and does not run on a no-ROCm runner.

The first test is the one that would have caught the raw-prompt behaviour. The second
exists because the two entry points differ in tokenization and chat framing and are
therefore not interchangeable; it pins that they are both reachable rather than asserting
anything about their agreement.

## What this does not do

It does not test the **raw** prompt path, which is deliberate: asserting that a raw prompt
returns EOS would pin a behaviour of the model rather than a contract of the engine, and
that behaviour could legitimately change if the tokenizer starts applying a template
automatically. The comment at the top of the file records the observation instead.
