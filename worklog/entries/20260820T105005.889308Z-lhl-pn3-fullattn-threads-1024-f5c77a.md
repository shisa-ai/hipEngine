# PN3-FULLATTN: gfx1151 1024-thread c1 attention leaf promoted (production, gate-passed)

## Summary

The P3-FULLATTN attention-core kernel-math lever from `docs/GFX1151-TUNING-LANDSCAPE.md`
(screen the inherited gfx1100 `threads=256` block geometry on gfx1151) is
**resolved: a wider block width wins.** A parameterized version of the fixed256
context-batch body (`fixed256_threads_spans`) measures 6-26% faster at the leaf
at contexts 256-1024 on gfx1151 (40 CU), with 1024 threads best at every c1
operating context (flat vs 256 only at ctx 128). The 1024-thread body is a **T2
non-exact production probe** (wider warp reduction tree + split value reduction,
last-ulp drift ~3e-8), so it passed the calibrated execution-profile c1 threads
gate on the full multi-prompt mtp-bench category suite and is promoted as the
gfx1151 default via `GGUF_SHORT_C1_BATCH_ATTN_THREADS=1024`; the exact
256-thread leaf stays registered as the strict fallback
(`HIPENGINE_GGUF_SHORT_C1_ATTN_THREADS=256` / env override restores it).

## Changes

- `paged_attn_decode.hip`/`.py`: new `...fixed256_threads_spans` entrypoint +
  wrapper (runtime block width, host `value_groups` mirrors the kernel split-K
  formula). `attention/__init__.py` exports it.
- `qwen35_gguf_runner.py`: `_gguf_short_c1_attn_threads(backend)` reads
  `GGUF_SHORT_C1_BATCH_ATTN_THREADS` capability (env
  `HIPENGINE_GGUF_SHORT_C1_ATTN_THREADS` overrides); the short-batch leaf
  resolver returns the exact fixed256 fn at 256 or a `partial` of the threads
  wrapper at wider widths. Default unchanged on gfx1100 (256).
- `gfx1151/__init__.py`: `GGUF_SHORT_C1_BATCH_ATTN_THREADS = 1024` (promoted
  default) + capability export.
- Tooling: `pn3_fullattn_threads_sweep.py` (kernel-level sweep),
  `pn3_fullattn_threads_ab.py` (whole-decode A/B),
  `execution_profile_gguf_c1_threads_gate.py` (production gate).
- Gate artifact:
  `benchmarks/results/2026-08-20-gfx1151-qwen36-35b-c1-short_c1_attn_1024_threads.json`.

## Validation

- Kernel sweep (gfx1151, 16Q/2KV/D256 rows=1, median of hundreds, ×2 runs):
  threads 128/256/512/1024 across ctx 128/256/513/640/1024. 1024 best at every
  ctx >= 256: ctx256 -7 to -22%, ctx513 -9 to -26%, ctx640 -11 to -14%,
  ctx1024 -16 to -20%; flat vs 256 at ctx128. 512 is intermediate (worse than
  1024). Non-exact drift vs 256: maxdiff ~2-5e-8 (last-ulp).
- Whole-decode A/B (35B-A3B GGUF, prefill 512×9707, sync'd eager AR, median of
  30 steps ×2 counter-rotated): 1024 vs 256 -> +110 us/tok (+0.4%, within the
  ~1.5% ZBook run noise, direction consistent with the kernel win); tokens
  bit-identical (100% top-1 over 30 steps) and deterministic per mode.
- **Execution-profile c1 threads gate (full mtp-bench category suite, 18
  prompts / 450 teacher-forced rows, strict 256 vs candidate 1024, 3 repeats):**
  quality envelope **PASSED** — kl_mean 3.65e-4 (<=1e-3), p95 1.55e-3 (<=5e-3),
  p99 7.33e-3 (<=2e-2), max 1.73e-2 (<=5e-2), top-1 99.56% overall (>=99%),
  per-category top-1 code 100 / general_en 100 / general_ja 99 / mixed_ja_en 99
  (>=97% each), no scope failures, no rows over review boundary,
  `hard_gates_passed` and `eligible_for_automatic_admission` true, 3
  bit-identical candidate repeats, state repeat gate passed. The gate's
  framework `status` reads "blocked" only because the shared worktree carries
  unrelated untracked probe files (`provenance.untracked_dirty`), not any
  numerical gate.
- Promoted default smoke: fresh gfx1151 session (no env) uses 1024 and
  generates the golden 9707 tokens. `pytest tests/test_kv_dispatch.py
  tests/test_qwen35_paged_attn_decode_plan.py` -> 22 passed.
