# Make lifecycle GDN profile explicit

## Summary

Made the cN lifecycle harness capable of validating the production GDN prefill
policy without weakening its strict default. The first FP16 c13 attempt stopped
before lifecycle work because the harness unconditionally forced strict
`exact`, while FP16 state correctly fails closed unless Q4_K_S uses the backend
`auto` policy resolving to compact-peer-wave32.

## Changes

- Added `--gdn-prefill-mode {exact,auto}` to
  `scripts/gguf_arbitrary_c_lifecycle.py`; default remains strict `exact`.
- The lifecycle environment now pins the requested mode, allowing production
  FP16 validation to select `auto` explicitly while preserving all exact
  control/ownership, graph, compaction, and teardown gates.
- Added parser/default coverage for both strict and production selections.

## Validation

- RED: the new parser contract failed because no profile-aware argument existed.
- GREEN: `uv run pytest -q tests/test_gguf_arbitrary_c_lifecycle.py` -> 10
  passed. Python compilation and `git diff --check` pass.
- The stopped GPU attempt failed closed with the intended runtime guard and
  emitted no result artifact; the GPU returned idle with no surviving KFD PID.
