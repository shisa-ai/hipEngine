# Admit packed multi-choice MTP past a 1024-token live context

## Summary

A multi-choice (n=2) MTP group at a prompt of about 1,020 tokens or more
returned correct autoregressive ids while running zero speculative cycles. Two
refusals inside the cycle caused it, and both are now gone.

**The verifier guard.** `verify_target_blocks_batch` refused
`layout.max_live_count >= 1024` with `packed target verifier currently requires
context < 1024`, four lines above the workspace it allocates for exactly that
case (`if int(layout.max_live_count) >= 1024 or (retained_decode_kernel is not
None and rows > 1)`). The guard was a 2026-07 policy boundary, never
numerically qualified past 1024, and its triage row justified it as reaching the
user cleanly as an HTTP 400 -- which is not what happens on the MTP path: the
refusal is raised inside a speculative cycle, `recover_cycle_failure` turns it
into an autoregressive fallback, and the retired rows leave a planner reason
that does not mention context at all. Its prefill twin was removed on 2026-09-18
after fixture evidence past 1024 (`docs/REFACTOR.md:339`); this is the same shape
of gate on the same threshold.

**The draft workspace.** Removing the guard exposed the next refusal:
`long-context packed AR decode requires a row-sized split-K workspace`, raised by
`step_hidden_batch_native` because the NextN draft step ran the same row-bulk
attention as the target while passing `split_workspace=None`. It now sizes one
from its live span, exactly as `step_batch_native` and the target verifier do.
Below the threshold the route is unchanged and still allocates nothing.

**The invisible part.** Neither refusal could be read from the response: the
failed cycle is recovered by decoding autoregressively and its rows are retired,
so every later step reported `no_provider` with
`provider_decline_reason='request N unregistered or disabled'` -- a message about
registration for a failure about context. `hipengine/speculative/accounting.py`
now publishes the recorded `(category, detail)` pairs beside the existing counts.
That is what made the gate report below name both the real cause and the planner
reason, and it is what would have made this finding take minutes instead of a
diagnostic sweep.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: the packed target verifier guard is
  removed; `step_hidden_batch_native` allocates and passes a row-sized split-K
  workspace when its live span reaches the split threshold.
- `hipengine/speculative/accounting.py`: the specdec2 block publishes
  `failure_reasons` (category and detail).
- `tests/test_unit_qwen35_gguf_hidden_batch_split.py`: four cases -- the draft
  step allocates at and above the threshold with the live span as its size, keeps
  the unsplit route below it, and the verifier guard's message is absent from the
  module. The two threshold cases failed before the change for the right reason
  (`ensure_calls == []`) and the guard case failed on the message still being
  present.
- New evidence artifact
  `benchmarks/results/2026-09-22-gfx1151-int8-mtp-packed-admission-past-1024.json`.

## Validation

Host `gfx1151`, backend `hip_gfx1151`, Qwen3.8-27B Q4_K_M (17,106,773,984 bytes,
SHA256 `7e78da5d...6fe169`), uniform per-token/head INT8 K/V with FP32 scales,
`--max-context-tokens 9216`, production profile, candidate budget three, gate and
accounting revision `927d3ae1e`. Environment as in the artifact; the rejected
artifact ran under the documented diagnostic override.

Numerical oracle, the gate that decides whether the guard may go: for each
prompt length it runs autoregressive one row, MTP two rows, and MTP one row, and
requires both choices of the group and the single MTP row to reproduce the
baseline ids exactly.

```bash
.venv/bin/python /tmp/packed_verifier_oracle.py 1020 2048 3072 4096
```

`PASSED: True` over both endpoints at all four lengths, with the group and the
single row each running 8-11 cycles and zero cycle failures recorded on the
server. 1020 tokens on `/v1/completions` is the shortest length that previously
failed: 10 cycles, `speculative_qualified`, ids identical.

End-to-end gate:

```bash
.venv/bin/python scripts/int8_mtp_server_gate.py \
  --base-url http://127.0.0.1:18198 --model int8-lru-diag-20260922 \
  --allow-kv-diagnostic-override --long-prompt-tokens 2048,4096 \
  --json /tmp/int8-lru-fixed-matrix.json
```

Exit zero, `passed: true`, 40 rows, and the row that found the gap now reports
`long_prompt.multichoice.speculates: true` with `cycles: [8, 8]` and both choices
identical to the autoregressive baseline. Repeatability ran over 20 rows in
reverse order and the isolation check ran its target beside the 4,096-token row.

Focused unit tests pass (4 new cases, two of which failed before the change for
the right reason). The full default unit tier passes at 10,148 passed and 55
skipped, four more tests than before this unit.
