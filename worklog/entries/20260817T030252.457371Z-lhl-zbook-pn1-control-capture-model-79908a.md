# Add deterministic control-capture model and fixtures (PN1 part 2)

## Summary

Added the deterministic control-capture model, serializers, and independent
expected-control fixture builder for the Qwen3.6 GGUF c1 teacher-forced
schedule, with 15 RED/GREEN tests. This establishes the PN1 standardized
actual-control capture contract (all 33 `ControlRecord` fields) and the
mismatch-detection negatives, without touching the hot path or requiring a GPU
run.

## Changes

- Added `hipengine/benchmark/control_capture.py`: `RowControlPrimitives`
  (observable scheduling primitives per row), `derive_control_record`
  (deterministic full-record derivation), `derive_control_records`,
  `build_control_capture`, `build_control_fixture`, and canonical ownership
  hash helpers (active-mask, mask-manifest, route-decision,
  route-scatter-owner, transaction-id).
- Added `tests/test_control_capture.py` (15 tests): schema round-trip through
  the existing loaders, per-field correctness, hash determinism/sensitivity,
  `compare_control_records` catching injected corruption (swapped physical
  slot/row, wrong request-owner key, wrong position/context, wrong KV base
  offset, stale graph bucket, lifecycle-leak missing record), invalid
  primitives rejection, and fixture/capture agreement for an identical c1
  schedule.
- Updated `docs/QWEN36-35B-ZBOOK-PRODUCTION-NUMERICS.md` PN1 punchlist.

## Validation

- `uv run pytest -q tests/test_control_capture.py` (15 passed) and the shared
  profile bundle (50 passed): control-capture, execution-profiles, runtime,
  evaluator, and qwen36 profile-plan tests all green.
- The route hashes are canonical ownership hashes (not raw expert logits);
  binding for strict captures and diagnostic for production candidates per the
  execution-profile gate.
- CPU-only unit; no GPU run or performance claim in this unit. The live
  producer harness (read session position/token per row, emit capture +
  fixture, invoke the gate) and the no-change GPU smoke remain open.
