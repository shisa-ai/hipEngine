# W7900: grouped prefill lifted the MTP arm too, and the flat K3 line was prefill

## Summary

Derived from two retained packets, no GPU time. The grouped-prefill change that shipped as
`72a29e9ad` is usually described by its AR effect (C8 45.68 -> 78.67). Comparing the MTP arm of the
same two packets gives +31.8% at C2 rising to +76.5% at C8, with C1 flat. That reframes the K3
scoreboard: pre-grouping MTP sat flat at 30.2-31.7 tok/s across C1-C8 while AR climbed 22.1-45.7,
which read as "speculative decoding degrades with batch width". It was prefill all the way along.

## Changes

Artifact `2026-08-30-w7900-q4km-c1c8-grouped-prefill-mtp-arm-effect.json` plus a changelog line. No
engine change, no README row - the post values are already the published `hipEngine explicit K3` row.

## Validation

Both packets are `status=complete, passed=true`, same model, same prompt file, `mtp_engaged` 80/80 and
`correctness.passed` 80/80 in each. Exactly three commits touch `hipengine/` or `kernels/` between the
producers and all three are the grouping work (`9f2297314`, `35794a1bb`, `eb17bb589`), so the delta is
attributable. Means over 10 prompts per width:

Two independent reasons to trust the comparison. The AR column reproduces the ship commit's own
headline (`45.68 -> 78.67`) from the same two packets, so this is the same A/B the promotion used, not
a fresh one; and C1 is a null control that moves -0.4% and -0.6%, inside the ~0.4% AR run-to-run drift,
at exactly the width where `native_full_prefill_groups` is 0 and grouping cannot fire.
