# Publish safe text prefixes for stop-filtered streams

## Summary

Single-response completion and chat streams publish safe prefixes when text stops are requested. A suffix that could complete a stop remains buffered; a stop-tokenization mismatch no longer forces full-response buffering. Live hardware qualification is pending.

## Changes

- `_stop_filtered_stream` filters before SSE and reasoning splitting. It holds incomplete stop prefixes and crossing token/UTF-8 groups, handles overlapping stops, and flushes unmatched suffixes at EOF.
- Matching suppresses subsequent text but drains backend events to preserve committed IDs, usage and MTP counters. The terminal reason becomes `stop`. This does not implement early backend cancellation when token matching misses a text stop.
- Partial tokens are not assigned invented logprob records; the existing response serializer omits records crossing a text-stop boundary. Cancellation closes the underlying async iterator; driver failures propagate.
- Removed the full-response stop guard for eligible single-response streams. Other existing buffering guards (structured validation, unsupported logprobs, multiple responses, echo and tools) are unchanged.
