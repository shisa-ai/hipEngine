# Comparative WER driver fails qualification (exit 1) when any lane has malformed transcripts

## Summary

Malformed generations are excluded from WER per lane independently, so two
lanes can end up scored over different clip sets and their WERs stop being
directly comparable. The harness reported the exclusions but did not act on
them, so a run where one lane dropped clips still looked like a clean pass.

The verdict is now a separate, enforced decision. The per-lane WERs stay in the
artifact as diagnostics, and the driver returns **exit code 1** whenever any
lane has a malformed transcript, with a stderr line naming the reason. The
artifact is still written on failure so the run is diagnosable.

The decision logic was inline in ``main()`` and therefore untestable; it is now
the module-level pure function ``qualify_lanes(systems)``.

## Changes

- `scripts/vibevoice_asr_wer_full.py`: `qualify_lanes()` extracted from
  `main()`, returning the rule, total malformed count, per-lane scored clip
  counts, a `same_clip_set` flag and `passed`. `main()` writes it into
  `results["qualification"]` and returns 1 when it fails.
- `tests/test_unit_vibevoice_wer_qualification.py`: new.

## Validation

- `python3 -m pytest tests/test_unit_vibevoice_wer_qualification.py`: 5 passed.
  - Verdict: clean lanes pass; one malformed lane fails, with
    `same_clip_set` False and `scored_clip_counts == {"torch": 0, "hipq4": 1}`.
  - Diagnostics survive a failed qualification: the scored lane keeps its
    `wer_pct` and the malformed lane is marked `wer_excludes_malformed`.
  - **Exit code**, driven through the real `main()` with the lane subprocesses
    stubbed: 1 with a malformed torch lane, 0 when all lanes are clean, and the
    artifact is written in both cases. This is the part that could not be
    checked by asserting on the verdict alone.
- `python3 -m pytest` over the vibevoice unit tier: **67 passed**.
- Real driver, 3 clips, clean lanes: exit 0, "qualification passed".
