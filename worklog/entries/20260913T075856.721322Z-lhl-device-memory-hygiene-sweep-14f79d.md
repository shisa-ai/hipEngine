# Device-memory hygiene sweep: two assumed-zero buffers fixed, H2D sources guarded

## Summary

Task #88. The Surya/Evie `x * 0.0` state re-zero (task #80) and the short-lived
H2D source behind the kv_spans scatter failure (task #83) were treated as two
fixed runners; this sweep asked whether the class is broader. It is: the
poison probe found a read-before-write in **both** TimesFM runners, and a static
sweep found the unfixed twin of the Surya pointer-array upload in the **Evie**
runner plus 10 always-allocating H2D sources across `hipengine/`, `tests/`, and
`scripts/`. Everything found is fixed, each with a test that fails on the old
code, and the source class now has a permanent AST guard.

Method is the one that localized the Surya NaN: run the workload, `memset(buf,
0xFF, buf.nbytes)` every per-call device buffer the runner owns (never weights
or once-uploaded metadata), run again, require bit-identical output; on a
mismatch re-run one buffer group at a time to name the offender. Helper is
`tests/_poison_probe.py` (`assert_poison_invariant`, `collect_device_buffers`,
`group_by_prefix`).

## Changes

**Fixed defects (each one is a real read-before-write, not a latent-style nit):**

- `hipengine/runtime/timesfm_decode.py` -- the batched attention GEMMs sweep the
  whole KV cache including the AR slots the prefill has not written, masking
  them with a zero weight. `0 * garbage` is 0 only while the garbage is finite,
  and the caches were zeroed when they were *allocated*, so the second decode on
  a reused buffer set read whatever the allocator handed back. Poisoning the V
  caches alone made **20480 of 40960 output values non-finite**; poisoning every
  other per-call buffer was bit-identical. Fix: `_zero_caches` memsets K and V
  before every decode (a per-call scale-by-zero would not do -- `x * 0.0` is a
  no-op for a NaN), and the allocation-time memset is removed.
- `hipengine/runtime/timesfm3_decode.py` -- `q_offset` is a constant-zero input
  to the attention kernels that is never uploaded per call, so its value was
  whatever the allocation held. Poisoning it alone moved the decode by
  **5.8e+02**. Fix: `_zero_q_offset` per decode, allocation-time memset removed.
- `hipengine/runtime/evie.py::_dev_ptr_array` -- the unfixed twin of
  `SuryaGpuRunner._dev_ptr_array`: it re-uploaded the pointer list on every call
  from a host array that went out of scope when the method returned, which is
  the task-#83 hazard (the DMA of an unpinned source reads the host buffer after
  `hipMemcpy` returns). Fix: upload on cache miss only -- the cache key is the
  whole pointer list, so a hit is already correct -- and `device_synchronize()`
  before the source is released. This also removes one H2D per batched GEMM call
  (not measured; no perf claim).

**Static sweep -- 10 always-allocating `host_array_ptr(...)` sources hoisted into
named locals and synchronized where the copy is not already followed by a sync:**
`timesfm_decode.py` (`num_masked`, `next_index`), `timesfm3_decode.py`
(`front_masked`), `qwen35_gguf_runner.py` (`np.asarray([0], dtype=int32)`),
`tests/test_maple_graph_capture.py`, `tests/test_moonshine_cuda_sm120a_attention.py`,
`tests/test_gguf_k_t16_dense_f16_activation_prefill.py`,
`scripts/gguf_launch_overhead_bench.py`, `scripts/pn3_fullattn_splitk_vs_leaf.py`.

**New gates:**

- `tests/test_device_memory_hygiene.py` -- AST scan over `hipengine/`, `tests/`,
  `scripts/`, `benchmarks/` rejecting an always-allocating array (`np.zeros*`,
  `np.ones*`, `np.full*`, `np.array`, `np.asarray`, `np.tile`, `.astype(...)`,
  `.copy()`, `.flatten()`) as a `host_array_ptr` argument, plus a self-check that
  the lint still flags what it is meant to catch. `view`/`reshape`/`ravel` are
  deliberately not flagged (they return a view whose base the caller holds).
  The same file carries the Evie pointer-array RED test.
- `tests/test_timesfm_gpu_decode.py`, `tests/test_timesfm3_gpu_decode.py` --
  poison probes for the two fixed runners.
- `tests/test_laguna_moe_gpu.py::test_laguna_moe_is_invariant_to_poisoned_scratch_memory`
  (`c1` and `rows`) -- the first probe for a runner that turned out **clean**:
  both entry points are bit-identical with the whole MoE scratch poisoned. The
  one buffer the allocator zeroes (`selected_down_completion`) is written per
  call, and the rest are written before they are read.

**Blocked probes (concrete blocker, not "needs more evidence"):** every runner
whose real-device workload needs a checkpoint that is not on this host.
`maple*` (no cached Maple checkpoint), `laguna_gguf_runner` end to end (no
`/home/lhl/models/gguf/laguna-s-2.1-Q4_K_M.gguf`), `qwen4_exp_runner` (no
Qwen4Exp GGUF), `qwen35_gguf_runner` (no `/models/gguf/*.gguf`). The
`gguf_decode_graph` / `gguf_packed_decode_graph` capture tests are fully
monkeypatched, so they hold no real device buffers to poison. Running
`assert_poison_invariant` on any of them once the checkpoint lands is the
remaining work; the recipe is in `docs/KERNELS.md`.

No benchmark rollup: this unit makes no performance claim.
