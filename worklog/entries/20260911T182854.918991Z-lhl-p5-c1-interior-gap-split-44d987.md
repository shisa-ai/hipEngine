# 73% of the C1 decode inter-kernel gap is host Python: a graph replay is the lever

## Summary

The previous unit measured the C1 decode step window as exactly the GPU span
(36.434 ms) with 19.421 ms of inter-kernel gap, and recorded that decomposing that
gap would decide between fusion and graph capture. This unit does it, by re-parsing
the same committed trace (`--trace-dir`, no new GPU run).

Method: per window, merge the kernel intervals, take the gaps between consecutive
merged intervals, and intersect each gap with the window's HIP API intervals. Gap
time covered by an API interval is host time inside the runtime; uncovered gap time
is host Python with no API call in flight.

| Interior gap component | Per step | Share |
| --- | --- | --- |
| No HIP API call in flight (host Python between launches) | 14.055 ms | 73.1% |
| Inside a HIP API call (launch latency and call overhead) | 5.163 ms | 26.9% |
| Total interior gap | 19.218 ms | 100% |

Across 391.16 gap entries/step, the mean gap is 49.13 us: 35.93 us of Python and
13.20 us of API. (391 entries/step is lower than the ~793 launches/step because
dispatch intervals overlap — overlap ratio 1.83 — so many launches fall inside a
merged kernel interval and create no gap.)

## The lever

**A captured graph replay is the stronger lever.** It removes the per-launch host
cost on replay, so it targets the full 19.218 ms/step rather than a fraction of it.
Graph capture already exists on the c8 packed route while the C1 route is eager.

Fusion (fewer, larger kernels) reduces the number of gap entries and the Python
between them, but only in proportion to the launch-count reduction, so it recovers
a fraction of the 14.055 ms rather than all of it.

## Validation

- `uv run pytest tests/test_gguf_c1_decode_attribution.py -q` — 38 passed.
- Re-parse of the committed W7900 / gfx1100 trace, 62 step windows, 2048 prompt
  rows, Qwen3.8-27B `Q4_K_M`, INT8 KV. Values above.

Honest limits, recorded in the artifact:

- Gap time is attributed to "inside a HIP API call" versus not, and a call
  straddling a gap edge is clipped to the part inside it.
- Trace timestamps share the profiler's clock domain, and gap edges inherit
  whatever rounding the trace applies.
- One trace, one prompt length (2048 rows), one width (C1). The mix of gap entries
  may differ at deeper contexts where attention kernels grow.
- **This says where the gap is spent, not what a graph replay would actually
  recover.** Capture and replay overhead, unsupported operations, and memory-pool
  constraints are unmeasured here, so the 19.218 ms/step is a ceiling on the
  opportunity rather than a predicted win.
- No optimization was attempted.
- `performance_claim` is false and no scoreboard row changed.
