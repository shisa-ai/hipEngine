# Diagnose native-spec full-suite teardown stall

## Summary

Task #78 closes the apparent native-spec hang observed in both broad
campaign-validation attempts as a transient **GPU SQ interrupt storm**, not a
native-spec graph deadlock. The compact pytest output had 35 result dots, not
41, so the visible boundary was before node 36
`test_native_b3_target_reuses_one_dynamic_native_graph_across_positions`, a
fake-session test, rather than the final Qwen3.6-35B real-model node. The stalled
process consumed approximately one CPU and reported 100% GPU use with only
approximately 1% VRAM. Kernel logs at the stop-progress timestamps report
hundreds of suppressed gfx1100 `sq_intr` errors; clean-device reproductions emit
no such errors and pass the same boundary normally.

## Changes

- No production or test code changed. The fault is below the Python test/node
  boundary, did not reproduce on a clean device, and supplies no safe kernel to
  patch. A speculative native-spec change would target code the evidence clears.
- Durable operator classification: when a broad GPU run stops advancing while
  GPU use remains 100%, check the contemporaneous kernel log before assigning
  the stall to the last displayed pytest node. An `amdgpu ... sq_intr` storm
  invalidates that process as a correctness result; terminate it, confirm the
  device returns idle, and rerun the affected boundary in a fresh process.
