# EAGLE-4 persistent-KV context drafter: acceptance 0.9->3.0/draft, AR-exact

## Summary

Task #23 (P0-1, reviewer §6.3-1). The EAGLE-4 drafter attended only over its own
1..n draft rows and never saw the committed context, so chain acceptance was
~0.9/draft (0.38x AR). Added a persistent drafter K/V cache: prefill from the
prompt's fused features (one rows=P Q/K/V projection), decode each draft step as
rows=1 against the cache, and append the K/V of accepted rows (re-derived from the
target aux) after each verify. This is both the acceptance fix and the speed fix
(removes the per-step full-sequence recompute).

A numpy context-acceptance experiment first established the cause and the fix:
with the correct aux layers `[3,31,59]` (config `eagle_aux_hidden_state_layer_ids`,
tap depths `layer_id+1 = [4,32,60]`), a context-aware draft lifts the general
prompt from 1/8 to 7/8 accepted tokens; the stateless draft stays at 1/8. (An
early experiment hardcoded `[2,32,62]` — wrong layers — and an off-by-one in the
EAGLE `(feature_i, token_{i+1})` token alignment; both were corrected before
trusting the result.)

## Changes

- `hipengine/runtime/eagle4.py`: split `_layer` into `_qkv`/`_attend`/`_ffn`;
  added `prefill_context`, `draft_greedy_chain_cached`, `append_committed`,
  `_store_kv`, `_last_position_feature`. Sequence buffers split-sized: input/QKV
  projection + persistent K/V cache to `max_context_len`, FFN + efficient-head
  scratch to `max_seq` (the vocab-sized head scratch must not scale with context).
- `hipengine/speculative/eagle4_cycle.py`: `run_eagle4_cycle` now prefills the
  context KV once, drafts via `draft_greedy_chain_cached`, and calls
  `append_committed(new_aux, accept[1:] + [bonus])` after each verified block.
- `hipengine/generation/qwen35_gguf_eagle4.py`: provider recreates the native
  drafter when a request needs a longer context; default `candidate_budget` 1 -> 2
  (the measured KV optimum).
- `scripts/qwen38_eagle4_baseline.py`: pass `max_context_len` to the native drafter.
- `tests/test_gpu_eagle4_kv_cache.py`: GPU-guarded RED tests — cached draft ==
  numpy context reference (prefill + decode), and `append_committed` extends the
  context correctly. Synthetic weights, no real model needed.

Bug fixed during bring-up: `_last_position_feature` conflated the q_out row index
with the absolute position. After `append_committed`'s `_qkv(m)`, q_out holds m
rows (0..m-1) but the query position is `base+m-1`; copying `q_out[base+m-1]` read
out of bounds. Separated `q_row` (row index) from `query_pos` (absolute position).
The lossless cycle masked this (verification corrects any draft), so it surfaced
only as suppressed acceptance until the synthetic append test caught it.

## Validation

- `tests/test_gpu_eagle4_kv_cache.py`: 2/2 pass (cached == numpy context reference,
  including append_committed). `tests/test_unit_eagle4_cpu_oracle.py` +
  `tests/test_gpu_eagle4_kernels.py`: 8/8 pass (refactor preserved the old path).
- Single-block GPU cached draft matches the numpy context draft token-for-token
  (8/8) on code/math/general; general acceptance 7/8.
- Multi-block cycle (40 tokens, 4 prompts): AR-exact 40/40, acceptance
  2.64-3.00/draft, 9-10 tok/s.
- Depth sweep, full ten-prompt mtpbench suite (gfx1151, Qwen3.8-27B-Q4_K_M, 25 new
  tokens, 1 rep, single load): n_draft 1/2/3/4/6/8 ->
  9.65/10.42/10.34/10.26/8.04/4.59 tok/s = 0.86/0.93/0.92/0.92/0.72/0.41x AR;
  acceptance 0.75/1.30/1.67/2.00/2.31/2.52 per draft; **all depths AR-exact**.
  Optimum n_draft=2 (0.93x AR).
- `python3 audit/audit.py check`: ok.

Finding: context KV lifts acceptance ~3x and speed 0.38x -> 0.93x AR, but EAGLE-4
remains below AR. Acceptance rises with depth while the per-step efficient-head
cost (low-rank retrieve over the full vocab + top-K + shortlist scoring) rises
faster, so speed peaks shallow (n_draft=2) and falls off sharply deeper. This is
architectural: EAGLE-4 drafts autoregressively (one vocab-sized head per step),
unlike DFlash2's parallel block draft. EAGLE-4 is correct and lossless but the
slowest of the three drafters on this hardware (DFlash2 ~1.55x, DSpine ~1.07x).
