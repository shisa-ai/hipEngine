# TP2 decode launch inventory: 14 launches/layer per rank, norm chain already fused, exchange absorbs skew

## Summary

The campaign's next lever was described as "reduce the per-layer launch count in
the attention/GDN half", which was a direction without a target list. There is
now a target list, and it closes two hypotheses. Per rank per decode step the
production route submits **901 kernel launches plus 132 device copies**, i.e.
14.06 launches per layer; the pacer rank does 19.949 ms/step of kernel time
against rank 1's 20.502. The per-layer norm/residual chain is **already fused**
(one `add_rmsnorm` instantiation, one plain input norm, one exchange-epilogue
add), and the cross-rank exchange is **not on the critical path**: its spin
kernel is ~4 us per layer on the pacer and ~66 us per layer on the faster rank,
which is rank skew being absorbed rather than work to remove.

## Changes

- `scripts/tp2_decode_kernel_inventory.py` (new): runs the production decode step
  inside one ROCTX region bounded by device synchronizations, then rolls up a
  `rocprofv3` kernel trace per rank. The per-rank split is verified from the
  trace: one probe launch per rank with a distinct element count (1,024 vs
  65,536 elements of the same cast kernel) maps `Agent_Id` to a rank by grid
  size, and an unverifiable mapping is reported as unavailable instead of
  guessed. Prebuilds outside the profiler and requires the cache inside it, per
  the JIT-cache rule.
- `tests/test_unit_scripts_tp2_decode_kernel_inventory.py` (new): 9 tests over
  synthetic traces - region selection and rejection, in-region filtering,
  `Agent_Id` kept as the trace's string label, the probe-based rank map and its
  refusal paths, copy/kernel separation, and the min/p50/p90 spread that
  distinguishes a working kernel from a waiting one.
- `docs/QWEN38-27B-GFX1100-TP2.md`: new "per-layer launch inventory" subsection
  with the per-rank table, the two closed hypotheses, and the remaining levers.
- `benchmarks/results/2026-09-18-w7900-tp2-decode-kernel-inventory.json` plus
  the `benchmarks/README.md` evidence link and a `benchmarks/CHANGELOG.md` entry.
