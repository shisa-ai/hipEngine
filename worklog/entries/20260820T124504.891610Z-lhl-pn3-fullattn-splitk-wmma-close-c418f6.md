# PN3-FULLATTN: split-K no-win + WMMA closed; c1 attention leaf at practical optimum

## Summary

The two remaining P3-FULLATTN attention-core levers from the landscape are
closed. **Split-K is a measured no-win for the 35B c1 short-batch window**
(20-45% slower at contexts 513-768; the apparent ~1023 crossover is run noise
and flips between runs), so the existing routing (fixed256-1024 leaf for
contexts < 1024, split-K GQA for >= 1024) is already correct. **WMMA-tile is
closed on analysis**: the c1 leaf is a one-query-head-per-block (M=1) kernel
whose 16x16 WMMA tiles would waste 15/16 lanes, it is memory-latency-bound not
compute-bound (WMMA accelerates compute), and no in-tree WMMA kernel targets the
16Q/2KV/D256 paged c1 shape (the laguna WMMA decode kernels are DFlash/dense
GQA6 shapes). The c1 attention leaf is therefore at its practical optimum on
gfx1151: 1024-thread geometry (promoted, gate-passed), gate already negligible
(fused-gate was a no-win), split-K no-win, WMMA mismatched. The remaining
full-attention headroom is in the QKV/output projections
(`launch_gguf_linear`), which the landscape assigns to a separate owner.

## Changes

- Added diagnostic `scripts/pn3_fullattn_splitk_vs_leaf.py` (split-K
  `qwen35_paged_full_attn_decode_split_k_gate_bf16_spans` vs fixed256-1024+gate
  micro-benchmark at contexts 513/640/768/1023, splits 2/3/4, plus a focused

- No routing change: fixed256-1024 leaf stays the <1024 default; split-K stays
  the >=1024 path.

## Validation

- Kernel-level micro (gfx1151, 16Q/2KV/D256 rows=1 bs=256, median of hundreds
  of reps, 3 runs):
  - ctx 513: fixed1024+gate 74-75us vs splitK2 94-95us / splitK3 103-110us.
  - ctx 640: fixed 84-86us vs splitK2 104-106us / splitK3 115-120us.
  - ctx 768: fixed 85-94us vs splitK2 96-103us / splitK3 124-127us.
  - ctx 1023: fixed 104-123us vs splitK2 101-109us / splitK3 121-126us /
    splitK4 140-141us — the splitK2 "win" at 1023 flips between runs
    (fixed 104 vs splitK2 109 in the last run), i.e. within the ~15-20%
    run variance at the top of the window; not a reliable crossover.
- Aggregate wall impact of any top-of-window crossover is <0.1% (the c1 window
  is 511 steps; only the top ~70 contexts could benefit and split-K loses the
  bulk). Not worth a non-exact production gate.
- WMMA: closed on structural analysis (M=1 per block; latency-bound leaf;
  no in-tree 16Q/2KV WMMA decode kernel to A/B; new kernel would be high-effort
  with the tile-mismatch penalty).
