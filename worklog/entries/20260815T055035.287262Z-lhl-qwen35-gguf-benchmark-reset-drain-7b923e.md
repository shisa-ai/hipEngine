# Drain resident benchmark work before reset

## Summary

The approved p16-p4096 sweep exposed a deterministic benchmark-lifecycle abort:
a current Q8_0 persistent session sized for p4096 completed p16-p511, then
aborted at p512 with `std::runtime_error: FAILURE at Line 264`. A standalone
p512/max4098 run and a p511-p512-p4096 sequence passed; the full no-WMMA and
explicit queue-drain controls passed. Draining stream 0 before benchmark reset
closes the failure without entering any timed window or changing runtime reset's
asynchronous public contract.

## Changes

- Added `_reset_existing_session()` to the shared GGUF benchmark driver. It
  synchronizes the prior default-stream workload, then calls `session.reset()`.
- Routed persistent benchmark iterations through the helper before prefill
  timing starts. Public `Qwen35GGUFResidentSession.reset(stream=...)` remains
  asynchronous and unchanged.
- Added a RED/GREEN ordering test proving synchronization precedes state zeroing.

## Validation

- RED: the new focused test failed because `_reset_existing_session` did not
  exist. GREEN: the focused test passes.
- Two full current Q8 no-drain p16/32/64/128/256/511/512/513/768/1024/4096
  processes reproduced the abort at p512 after all earlier rows.
- Controls: standalone p512/max4098 and p511-p512-p4096 pass; forcing exact GDN
  and raising the AOTriton threshold still abort; `--no-use-wmma-prefill`,
  `--prefill-queue-drain chunk`, and `layer` pass. A gdb-perturbed run also
  passes, identifying a host-submission/retirement lifecycle sensitivity rather
  than deterministic math.
- The exact previously failing no-drain matrix passes after the helper, including
  finite p512 and p4096 rows. The synchronization occurs before the benchmark's
  `prefill_start`, so throughput scope is unchanged while repetitions become
  independent.
- `uv run pytest -q tests/test_qwen35_gguf_bench_metadata.py
  tests/test_gfx1151_readme_refresh.py` passes all 22 tests; `python3 -m
  py_compile` and static checks also pass.
