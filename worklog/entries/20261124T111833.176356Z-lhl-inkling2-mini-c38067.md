# Withdraw the resident block message-window off-by-one

## Summary

The message window is correct as written. The claim in `20261124T120434.*-lhl-inkling2-mini-*.md` that the partial overwrites the previous pass's last block came from shifting the block-row to host-block mapping by one. With the mapping derived properly, rows `[saved+1, count]` are exactly `blocks[prelude+1:]` plus the partial, so the window needs no change.

## Changes

- Derived the mapping from the host's append site and the block's write site instead of from the row counts alone.
- Confirmed that `_read_blocks` is bypassed in the common case: `_ResidualRows.read` builds a row-major `(rows, blocks, hidden)` matrix and mixes over the middle axis, which is the same logical tensor the kernel builds in block-major order. The two layouts are equivalent, so the kernel is not reading a transposed tensor.

## Validation

- Block row `j` holds the same normalized row as host `blocks[j]`: both are the row appended for visit `j`, and the block writes it at index `count` after incrementing, which is `j + 1` for visit `j` only if row 0 is the entry row. Reading `[saved+1, count]` therefore covers `blocks[saved+1 .. count-1]` plus the partial at `count`, which is what the host reads.
- The three window variants measured earlier differ by about one unit at `k = 19` because they drop or add one row from a window that is already correct; none of them is a fix.
