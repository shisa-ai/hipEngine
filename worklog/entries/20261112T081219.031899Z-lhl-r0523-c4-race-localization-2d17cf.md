# R0523 c4 race: GDN path fully eliminated; shared-resident state, per-slot capture absent; owner unpinned

## Summary

Completed the GDN dispatch-path elimination for the R0523 c4 packed-decode race.
State-hash hooks were placed on every candidate GDN path and fired as follows:
native-row path 0 events; per-row `run_linear_attention_attn_only` only for the c1
oracle; chain-journal path 0 events (used_chain_journal=False); the ACTIVE path is the
fallback per-row loop in `_run_linear_attention_attn_chain_rows_exact`, and it runs with
`linear_state_rows=None` — i.e. NO per-slot GDN journals; all four slots are processed
against the single shared resident conv/recurrent state. The per-row GDN kernels have no
cross-row race, so the intermittent owner is the shared-resident GDN state sequencing
across slots/steps, which the current hooks cannot resolve per slot. Owner remains
unpinned after ~30 iterations; R0523 is parked as a hard race. No production behavior
changed; all `_r0523_*` hooks are env-gated (off by default) and uncommitted.
