# Enforce Gemma cross-engine benchmark correctness and provenance

## Summary

Repair benchmark acceptance defects before refreshing Gemma performance
against llama.cpp. No production kernel or arithmetic changes. The depth
comparison remains open; the live checks here validate harness behavior, not
an accepted performance improvement.

## Changes

- Require finite host logits before every greedy sample and finite durations
  for every measured row; a legal single-output row may have zero decode time.
- Require all warmups, samples and the untouched public route to return the
  expected exact ID count and the same IDs. Strict JSON disallows NaN/Infinity.
  Public API finiteness stays explicitly unknown: ID equality does not expose
  every intermediate public logit row.
- Comparator acceptance requires actual `prompt_n` equal to the entire prompt
  and `cache_n == 0`, rather than only the requested `tokens_evaluated` count.
  Retain generated IDs, content, stop type, settings and original timing fields.
- Record physical hostname, HIP device identity, model fingerprint, server
  binary SHA-256/version, source dirty state, and comparator environment.
  Require embedded executable commit to match the supplied source revision.
- Parse observed runtime context, KV dtype lines, flash-attention/device lines,
  graph fallback lines and server graph-reuse counters. Missing observations
  stay unknown; absence of a fallback message is not proof graphs executed.
  Acceptance requires observed slot capacity to equal the requested capacity.
- Align sweep capacity to a multiple of 256 at or above prompt+output, matching
  llama.cpp rounding. The explicit host idle limit is 256 MiB; the initial
  128 MiB refusal was display memory, not a concurrent compute process.
