# Screen decode GEMV team structures

## Summary

X2-K3 screened the llama-shaped wave-stripe c1 GEMV structure against the
production decode leaves. Pack8: 1.16x win validated but modest. Q5T16: the
first wave32 mapping regressed (0.70x/0.40x) and the fresh per-leaf baseline
shows the remaining decode gap is a distributed ~1.2-1.4x grind, not one
structural fix. No production change; kernels reverted.

## Changes

- None landed. Probe kernels and screens live under /tmp/d08-x/
  (bw_probe.hip, q5t16_screen.py, bw_run4.py); the unproven Q5T16 wave32
  sibling was reverted before commit.

## Validation

- Streaming ceiling (float4 grid-stride, 154 MiB): 234 GB/s host-timed.
- Pack8 c1 [3584,1024] actual weights: production t32 16.0 us (115 GB/s on
  qweight, 172 incl F32 scale planes) vs wave-stripe probe 13.9 us (132/198
  GB/s), outputs bit-comparable (max diff 1e-6, top-1 exact) -> 1.16x.
- The D3 fused dual t128 already runs ~177 GB/s incl scales, so the pack8
  production swap is only ~0.25 ms/token (~3-4% decode).
- Q5T16 direct leaves on actual tiles: QKV [6144,1024] 39.9 us = 111 GB/s,
  SSM-out [2048,1024] 18.1 us = 81 GB/s - materially faster than the
  M12-era 64 GB/s pool estimate implied. Wave32-v1 sibling measured 0.70x/
  0.40x with wrong output (mapping bug plus uncoalesced lane strides);
  reverted rather than iterated.
- Harness caveat: loading a raw CDLL alongside the engine corrupts the
  wall-clock markers in-process; X2-K3 screens used host-side sync timing
  validated against the streaming ceiling.

## Next
