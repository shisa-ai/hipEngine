# Make the device exchange timeout block-uniform, and verify the head-shard axis and reduction by content

## Summary

An external review of `1f283f02e` raised three findings. All three are answered
here, and two of them were answered by replacing an argument with a measurement:

1. **The timeout path returned before a block-wide barrier.** The spin kernel's
   lead thread `return`ed on timeout, leaving the rest of the block to reach
   `__syncthreads()`. That is a divergent exit before a barrier, and nothing
   established that AMD hardware guarantees the remaining block's barrier
   completes. The lead thread now records the timeout and falls through to the
   barrier, so the block is uniform by construction.
2. **The reported value-head ownership contradicted the code.** The previous
   entry explained the per-tile shard rule as "contiguous within each segment",
   which reads as one contiguous global range. The real mapping is per-tile:
   rank 0 owns source value heads `[0,8) [16,24) [32,40)`, rank 1 owns
   `[8,16) [24,32) [40,48)`. The explanation was wrong even though the rule was
   not; the rule is now verified against the bytes of the real checkpoint
   rather than against itself.
3. **Rank agreement does not prove reduction correctness.** Correct: the
   spin-add writes both ranks' rows from the same operands, so agreement is by
   construction. The reduction is now checked against a host sum of the
   partials the ranks actually wrote, both at the driver level and at the model
   level.

The head-sharded bulk prefill is still wrong; this entry does not fix it. What
it does is remove the reduction and the axis interpretation from the hypothesis
list with content-level evidence, so the remaining search is the sharded
compute.

## Changes

### 1. `hipengine/distributed/device_exchange_host.cpp`: block-uniform timeout

`tp2_dev_spin_add_bf16` before:

```cpp
if (threadIdx.x == 0) {
  while (*remote_flag < expected) {
    if (++spins >= max_spins) { atomicExch(timeout_flag, 1u); return; }  // divergent
    ...
  }
}
__syncthreads();          // the other threads arrive here with lane 0 gone
```

After:

```cpp
if (threadIdx.x == 0) {
  while (*remote_flag < expected && spins < max_spins) { ++spins; ... }
  if (*remote_flag < expected) { atomicExch(timeout_flag, 1u); }
}
__syncthreads();          // no thread can skip this
if (*timeout_flag != 0u) { return; }   // uniform: the whole block reads one flag
```

No thread returns before the barrier any more, and the post-barrier test reads a
single value for the whole block, so the block leaves together.

Host propagation was already in place and is unchanged: `tp2_dev_exchange_wait`
syncs each rank's stream, reads its timeout flag, and returns `kErrHip` with
`ex->error` set to `spin timeout on rank N: the peer did not publish within the
spin budget`. The Python wrapper turns that into a `TransportStateError` and
poisons the handle, so `step_begin`, `bump`, `enqueue_rank`, and `wait` all
refuse further work.

### 2. `tests/test_gpu_distributed_staged_compiled.py`: missing peer, in isolation

`test_device_exchange_spin_timeout_fails_instead_of_hanging` now pins the three
properties that matter, in order: the bounded spin returns the rank's stream
(`wait` cannot block forever), the host surfaces the timeout as a poisoned
handle (the rank group cannot continue), and the timed-out exchange publishes
nothing (the output row is `memset` to `0xAB` and must still read `0xAB`, so a
stale or partial row cannot pass as a result). Only rank 0 enqueues; rank 1
never publishes. The two buffers the test allocated are now freed.

### 3. `tests/test_unit_loading_qwen35_gguf_shards.py`: the axis, from the bytes

New section 2b derives the expected mapping from the two references that define
the file format, not from this planner:

* llama.cpp `convert_hf_to_gguf.py`, `_LinearAttentionVReorderBase`: HF stores V
  heads grouped by K head (`[G0_v0..v{r-1}, G1_v0..v{r-1}, ...]`) and GGUF
  stores them tiled (`[K0, K1, ..., K0, K1, ...]`).
* llama.cpp `src/models/qwen35.cpp`: the fused qkv rows are `key_dim` q rows,
  then `key_dim` k rows, then the value rows, and `ggml_repeat_4d(q_conv, ...,
  num_v_heads, ...)` tiles the K heads across the V axis, so V head `v` pairs
  with K head `v % n_k_heads`.

The check is on payload bytes: every local head-sized row block is hashed and
matched back to the source head block with the same bytes, so the mapping is
read out of the file rather than assumed. Two heads can hold byte-identical
blocks in a real checkpoint (`blk.0.ssm_a` has 40 distinct values across 48
heads), so a slot is compared against its candidate set and the test requires at
least one unambiguous slot so it cannot pass vacuously.

Coverage: `blk.0.attn_gate.weight`, `blk.0.ssm_alpha.weight`,
`blk.0.ssm_beta.weight`, `blk.0.ssm_a`, `blk.0.ssm_dt.bias` (row identity plus
the pairing invariant `global_v % k_heads == rank * local_k + local_slot %
local_k`, which is what the rank-local `v % n_k_heads` kernel pairing needs);
`blk.0.attn_qkv.weight` and `blk.0.ssm_conv1d.weight` (the q and k blocks are
byte-compared against the K heads the value block's *content* says the rank
owns); `blk.0.ssm_out.weight` (each tile's column run, sampled over rows).

The check bites: rewriting the derivation to the HF grouped order fails all six
row-identity and qkv checks, and swapping the two ranks' column ownership in the
`ssm_out` derivation fails that check.

### 4. `scripts/tp2_head_shard_agreement_probe.py`: the reduction, from a host sum

`_compare` now runs `_reduction_check` per captured layer: the consumed row on
each rank must equal `bf16_rne(f32(partial_rank0) + f32(partial_rank1))`
bit-for-bit, where the partials are the buffers the ranks actually wrote before
the reduction. This is a different claim from "the ranks agree": two ranks
reading the same wrong slot, a doubled partial, and a stale row all produce
agreement, and the check rejects all three.
