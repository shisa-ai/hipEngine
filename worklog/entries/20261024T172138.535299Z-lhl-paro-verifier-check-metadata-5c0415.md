# Report unperformed PARO verifier checks as unknown

## Summary

Trusted GPU acceptance no longer returns `true` for checks it never performed.
Both chain and tree results return `None` for CPU-oracle agreement and finiteness
when their fast path did not read top-1 logits. JSON explicitly identifies the
finiteness scope as `top1_values` or `not_checked`; it does not assert that the
full vocabulary logits were inspected.

## Changes

- Make the two result fields nullable. CPU validation and CPU-owned modes still
  report their actual checks. Trusted GPU mode keeps its existing execution path.
- Extend the executable acceptance regression to assert unknown versus checked
  metadata and the JSON finiteness scope in both chain and tree modes.
- The numerical harness's independent full-logit finiteness checks are a separate
  reporting unit; they must not infer success from these result fields.
