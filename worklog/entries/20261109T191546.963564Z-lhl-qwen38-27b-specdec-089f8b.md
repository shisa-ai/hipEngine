# EAGLE-4 n_draft re-sweep: n_draft=2 stays optimal post-optimization

## Summary

Re-swept EAGLE-4 `n_draft` after the graph-verify + device-projection optimizations changed the cycle cost curve (the prior optimum was set pre-optimization). `n_draft=2` remains optimal; deeper drafts decline monotonically because acceptance drops faster than the extra draft step amortizes.

## Changes

- No code change. Measurement-only: `scripts/qwen38_eagle4_baseline.py --n-draft {2,3,4} --reps 3 --max-new-tokens 25` on 10 mtpbench prompts, each arm vs its own back-to-back AR.
- Artifact: `benchmarks/results/2026-11-09-gfx1151-qwen38-27b-eagle4-ndraft-resweep.json`.

## Validation

- All arms AR-exact (`exact_all=True`). Measured (gfx1151/Qwen3.8-27B-Q4_K_M, throttled ZBook diagnostic):
  - n_draft=2: 13.90 tok/s, 1.31x AR, acceptance 0.650.
  - n_draft=3: 13.57 tok/s, 1.20x AR, acceptance 0.556.
  - n_draft=4: 12.84 tok/s, 1.14x AR, acceptance 0.501.
- AR reference drifted 9.0->11.3 tok/s across runs (thermal), so cross-run absolute ratios are not comparable; the within-sweep monotonic ordering (each arm vs its own AR) is robust.
