# Complete RF4 MTP API semantics

## Summary

Completed RF4 API semantics for dense GGUF MTP on gfx1151. Both OpenAI
endpoints, route policies, direct usage/extension reporting, controls,
sessions, and eager/lazy restart now have real evidence. Automatic MTP remains
disabled with zero certified default scopes.

## Changes

- Centralized the automatic fallback reason as
  `automatic_mtp_scope_not_promoted` and linked current RF2 evidence instead of
  the obsolete claim that dense compatibility MTP is inexact.
- Capabilities now distinguish configured policy, loaded engine/model MTP
  availability, certified default scopes, and automatic promotion state.
- Auto-fallback response extensions report requested route and stable reason;
  realized MTP reports thinking policy and whether controls are prompt-hint-only.
- Fixed speculative EOS/stop ordering: publication now retires at the first
  terminal token before length completion, preventing a cycle that fills
  `max_tokens` from exposing an overshoot token.
- Added real eager/lazy API gate, fake endpoint/session/rejection coverage, and
  scheduler RED tests for EOS/stop inside length-filling speculative output.
- Updated `docs/API.md` to make direct response/runtime records authoritative;
  optional Prometheus mirrors are not campaign dependencies.
