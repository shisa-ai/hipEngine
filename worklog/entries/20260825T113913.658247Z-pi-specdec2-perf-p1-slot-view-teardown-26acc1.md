# Close resident slot-view verify buffers

## Summary

The clean full C2/C4 P1 bridge was exact but rejected by final ownership: 15
tracked allocations / 12,166,728 bytes survived `LLM.close()`. Two focused
reproductions localized every live pointer to
`Qwen35GGUFResidentSession._ensure_verify_block_buffers()` on resident slot
views: each of three lightweight views retained three 737,280-byte hidden
buffers, one 288-byte token-ID buffer, and one 8-byte token counter.

`resident_slot_view()` copied the owner session and correctly reset shared
ownership fields, but it did not reset verifier result pointers. Packed prefill
then grew view-local buffers. Capacity teardown cleared the view lease list and
closed only the batch owner, so the view-local allocations had no closer.

## Changes

- Reset all verifier hidden/token/LM/linear state pointers, host tables, and
  capacities when creating a resident slot view; never inherit owner pointers.
- Add a narrow `_close_resident_slot_view_buffers()` lifecycle that frees only
  allocations allowed to grow locally on a view. It does not touch shared target
  scratch, packed workspace state, weights, or runner ownership.
- Have the batch owner close all registered slot-view local buffers before its
  own ordinary teardown.
- Add RED coverage that failed on inherited verify pointers, then prove all
  local pointers free exactly once while shared owner/scratch identity remains.
