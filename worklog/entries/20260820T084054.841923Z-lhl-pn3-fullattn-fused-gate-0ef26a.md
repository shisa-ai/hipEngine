# PN3-FULLATTN: fused fixed256+gate is a measured no-win

## Summary

The first structural P3-FULLATTN candidate from `docs/GFX1151-TUNING-LANDSCAPE.md` —
fusing the private-c1 fixed256 context-batch attention leaf with the BF16 sigmoid
gate multiply (one kernel instead of fixed256→F32→gate_mul→BF16) — is a **measured
no-win** on the 35B-A3B c1 protocol. It was bit-exact correct (tokens identical,
all `9707`, zero mismatches) and eliminated 10 gate_mul launches per token, but the
gate_mul is only ~1 µs of a ~95 µs attention call: the fused leaf is flat to +0.7%
at kernel level, and the whole-decode A/B is within run noise (consistently slightly
negative, −0.4 to −1.5% across runs with ±1.5% run variance). The fusion has no
headroom to win because decode is GPU-bound and the gate launch is fully hidden
under GPU execution. **Reverted entirely** (kernel, wrapper, dispatch kind/route,
registration, runner wiring, capability, env flag, RED test, both tests, three
diagnostic scripts); the default decode path is byte-identical to the pre-candidate
state at `698465c5a`. The real P3-FULLATTN lever is the attention-core kernel math
itself (the ~0.095 ms/call fixed256 scan at context 513), not the gate.

## Validation

- RED test passed pre-revert: fused kernel bit-exact vs unfused chain
  (`mismatches=0/4096`, KL 0.0, top-1 100%); production-profile `GGUF` capture run
  matched the golden 9707-token generation across four counter-rotated A/B legs.
- **Micro-benchmark** `pn3_fullattn_fused_gate_micro.py` (deleted with revert; evidence
  recorded here): real c1 shape 16Q/2KV/D256, context 513, 500+50 reps ×4 legs on
  W7900/gfx1100. chain (fixed256+gate) = 0.095 ms/call, fused = 0.094 ms/call,
  delta +1 µs/call (+0.72%, within noise). The gate_mul is ~1% of the attention call.
- **Whole-decode A/B** (`pn3_fullattn_fused_gate_ab.py`, 35B-A3B GGUF session, 512×9707
  prefill, sync'd eager AR, median of 30 steps ×2 counter-rotated): gate_mul calls per
  measured window unfused=400 vs fused=0 (all removed); tokens bit-identical across all
  legs (`u1==f1 True`, ...); mean unfused 26.106 ms/tok vs fused 26.501 ms/tok
  (delta −395 µs/tok, −1.49%, within the ±1.5% run-variance band; earlier legs showed
  −0.4% to −1.5%).
- Post-revert: `uv run pytest tests/test_kv_dispatch.py tests/test_qwen35_paged_attn_decode_plan.py -q`
  → 22 passed. Tree is byte-identical to `698465c5a`.

## Next

- Do NOT re-try the gate fusion unless the decode becomes host-bound or the gate_mul
  becomes non-trivial (e.g. a later fused output-projection). The gate_mul is ~1 µs
  per call and GPU-bound decode hides the launch; there is no headroom.
- P3-FULLATTN's real lever is the attention-core kernel math: the fixed256
  context-batch scan (~0.095 ms/call @ context 513, 10 calls/token). Next candidates
  per the landscape: thread-geometry sweep for the shared `.hip` template
  (gfx1151-specific `threads` override), and only then split-K3 / split-policy or
  WMMA/tile variants on the retained c1 exact spine. All measurements must stay on the
  full multi-prompt mtp-bench category suite, never a single fixed prompt.
