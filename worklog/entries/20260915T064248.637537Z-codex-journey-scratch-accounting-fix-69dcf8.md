# Derive chunk-aware mandatory scratch admission

## Summary

Replace the fixed-only scratch assumption on the public generator path with
max(existing4GiB floor,mandatory chunk/context footprint). Keep the separate
4GiB reserve and staging reservation unchanged.

## Changes

- Add a pure sizing breakdown for base decode/prefill scratch, attention
  metadata and worst-case repair queues, checked against actual allocators.
- Pass prefill size into context admission and include context-dependent
  scratch in auto-capacity search. Old direct callers without chunk preserve
  the prior floor-only behavior.
- Schema3 allocation probes check device scratch without crediting the host
  staging reservation. Preserve legacy margin fields for historical packets.
- No kernel arithmetic, dispatch, default chunk or optional-resource policy
  is changed. Optional MMQ/graph/verify/transaction resources stay unqualified
  by this base-footprint estimate.
