# Batch runner ownership and failure recovery

## Summary

Repairs to `Qwen4ExpGGUFBatchRunner` (`50c42bb29`) requested by parent review
before any serving integration. Four changes, all uncommitted:

1. **A failed step poisons its rows.** The previous version only *documented*
   that a failure leaves state partially advanced. Now the mutation phase of
   `step` is a guarded region: any exception after the first device write marks
   every row's slot poisoned, and `step` and `import_prefilled` refuse a poisoned
   slot until `reset_slot(slot, owner)` or `release` + `admit` succeeds.
   `poisoned_slots` and `is_poisoned(slot)` publish the state to a scheduler.
2. **Preflight never poisons.** Validation runs before the guarded region and
   writes nothing, so a rejected call leaves every slot healthy (asserted).
3. **Strict integer admission.** Token ids, slot indices, and owner tokens go
   through `operator.index` with an explicit bool rejection. Previously
   `np.asarray(token_ids, dtype=np.int64)` truncated `3.7` to `3`, accepted
   `True` as `1`, and `_plan_step` did `int(slot)` on the caller's value.
4. **Owner tokens are required for a named row set.** `step(..., slots=[...])`
   without `owners=[...]` is a `ValueError`; each token is checked against the
   slot's current owner, so a stale handle from a released request cannot advance
   whichever request was re-admitted into that physical slot. The default form
   (`slots=None`, every admitted slot) needs no tokens because it names nothing.

Uncommitted working-tree changes only. No serving path, no default, no engine,
kernel, or doc change: the `docs/REFACTOR.md` section and the `50c42bb29` worklog
entry are committed and were left untouched, per the review instruction that the
committed entry is immutable.

## Why poisoning is the enforcement, not a retry

The step is not transactional. A failure after the QSA mixer's index append
leaves the slot's index cursor advanced, its KV bytes written, and its PLE
n-gram history advanced, while the runner's position mirror still holds the
pre-step value. A retry would append the token a second time at a position the
index already covers, so the request would silently continue from corrupted
state — the failure mode the review asked to close. Poisoning makes the refusal
explicit and leaves the choice of recovery (reset in place, or release and
re-admit) to the caller.

The poison mark is cleared only *after* the zeroing succeeds, so a reset whose
memset fails leaves the slot refusing work; a unit test injects exactly that
failure and asserts the poison survives it.

Poisoning is scoped to the row set. The N-row stages write only the rows'
slots, so a slot outside the failed row set is unaffected and keeps decoding
(asserted on GPU by comparing it against a c1 reference).

Fault-injection detail (GPU, gfx1151): the wrapper calls the real stage and then
raises once, so the device state is genuinely advanced when the step fails. For
the GDN case the test downloads the row's GDN recurrent slot and asserts it is
non-zero; for the index case it asserts the index cursor advanced to 1 while
`position(slot)` is still 0. Both then assert: retry refused (`poisoned`),
explicit-slots retry refused, unaffected slot's logits match a c1 reference
(`<= 2e-2`, measured `0.0` on this fixture), `reset_slot` recovers that slot and
only that slot, and `release` + `admit` recovers the other with a fresh c1
comparison.

The import test installs a `memcpy`-counting runtime proxy that raises on the
third copy (after the first block's key and value are written, before its index
keys), asserts the target slot is poisoned, the spare slot still steps, a retry
is refused, and a reset then lets the import complete and match the reference.
