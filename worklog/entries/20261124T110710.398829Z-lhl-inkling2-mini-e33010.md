# Measure the resident block traversal end to end

## Summary

The resident block traversal is numerically sound: on a 64-row block it produces the same top-1 token as the host and a KL of 2.185e-04, the same order as the resident-attention path already on the default path (1.259e-04). It is not bit-exact with the host, so enabling it is a promotion decision, not a correctness fix.

## Changes

- Measured `_resident_block` against `prefill_block` over a whole 48-visit block instead of per visit, because the capture trace is ambiguous across a restart.
- Comparison: the device's final hidden row and residual stack, passed through `_output_hidden` and the output head, against the host's `prefill_block` logits.

## Validation

- 64-row block, `Inkling-2-Mini-UD-Q4_K_M-mainline.gguf`, `hip_gfx1100`, fast profile: KL 2.185e-04, top-1 1217 on both sides, max absolute logit difference 6.927, mean 1.415, residual stack 4 blocks.
- Reference points: the resident-attention path gives KL 1.259e-04 with 4 of 4 top-1 agreement over the same prompt set; the host traversal is the oracle here.

## Next

- Decide promotion against the campaign's KL envelope rather than against bit-exactness. If the envelope admits 2.185e-04, set `resident_block` on the model and re-run the prompt-set verification; if not, find which of the added kernels carries the extra 9e-05.
- The candidate for that extra error is the residual read and the per-visit normalization: they now run through `residual_read` and `row_norm_mul` where the host uses `_mix_residual_rows` and `_rms` in float64.
