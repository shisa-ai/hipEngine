# QSA three-pass fusion recon: sequential pipeline, scores+coefficients is the fusion target

## Summary

Recon of the QSA v2 sparse-attention three-pass chain
(qsa_sparse_attention_paged_bf16_ordered_{scores,coefficients,values}_v2_f32
in hipengine/kernels/hip_gfx1100/attention/qwen4_exp_qsa.hip) establishes
the dependency structure and the fusion target:

- **scores** (grid q_heads x warps): QK dot per selected token; writes
  scores[q_head * selected_count + i]. Shared budget: token indices only.
- **coefficients** (grid q_heads, one block): reads ALL scores, computes the
  chunked warp-parallel running-max prefix and the alpha/beta online-softmax
  recurrence (sh_alpha[i], sh_beta[i]), writes the two coefficient planes and
  the denominator back into scores[base]. Shared budget: 3 x selected_count
  floats + 8 warp totals.
- **values** (grid q_heads, dim-major threads): reads the coefficients,
  denominator and value_cache, computes the linear-recurrence accumulator per
  dimension. Shared budget: alpha+beta+tokens.

**The passes are a strict sequential pipeline** (coefficients needs every
score; values needs every coefficient), not independent shared-load stages -
so the fusion is scores+coefficients into one kernel (keeping scores resident
in shared memory instead of the global round-trip, saving one launch and one
global read per q_head per step), with values left separate because its
parallelization is dim-major rather than token-major. The scores+coefficients
fusion preserves the arithmetic verbatim (the same chunked prefix-max and
recurrence in one block) and is therefore T0-eligible: a scheduling-only
sibling with the unfused pair as the registered fallback.

**Sizing from the committed trace**: the QSA sections own 147 launches/step
(12/layer across 12 QSA layers + GDN decode); the fusion removes 2 of the
12 per layer per step = 24 launches/step plus their intra-section gaps - a
smaller prize than T16 but in-envelope.
