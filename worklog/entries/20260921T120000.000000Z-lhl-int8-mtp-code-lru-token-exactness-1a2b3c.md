# Correct the INT8 MTP category-gate record and isolate the repair path

## Summary

The recorded 108-request INT8 MTP result was overstated for the local gfx1151
Qwen3.8-27B Q4_K_M artifact. The compact INT8 route is reachable only through
the explicit approximate-KV diagnostic override, and its existing quality record
is rejected (top-1 agreement 0.7778 versus the 0.90 gate). On `code_lru_cache`,
INT8 AR decodes `LRU Cache` while INT8 MTP decodes `LRUCache`; the difference is
one token/space within the 24-token output. The same defect is documented at
v0.6.0, so it is not a v0.6.1 regression.

The readiness document now treats the old 108-request statement as superseded
diagnostic evidence. The category gate reports the first differing token and
fails the row with prompt and endpoint context, preventing a misleading summary.

## Changes

- `scripts/int8_mtp_server_gate.py`: add a token-exactness comparator that
  reports the first mismatch, both token IDs, and both output lengths.
- `tests/test_unit_int8_mtp_server_gate.py`: cover a one-token mismatch.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: correct the historical evidence
  wording and distinguish the local rejected artifact from the independent W7900
  evidence.

## Solution path

1. Reproduce `code_lru_cache` with the same server command, diagnostic override,
   prompt rendering, and 24-token budget. Capture AR and MTP token IDs plus the
   first mismatch index; do not compare decoded strings alone.
2. Run the same prompt through three controls: BF16 AR/MTP, INT8 AR/MTP with the
   BF16 mirror, and direct INT8 AR/MTP. This separates approximate-KV quality
   drift from the MTP verifier/commit path.
3. At the first differing history position, teacher-force the same target input
   through the serial exact verifier and the native/block verifier. If serial
   exact agrees with INT8 AR, use it as the diagnostic correctness fallback while
   the native verifier is repaired; if both disagree, investigate the direct
   INT8 attention path and its scale/span metadata first.
4. Compare the target logits before acceptance and after the selected-state
   commit. A match before commit but divergence after commit points to linear
   state or cache commit ownership, not quantization arithmetic.
5. Only after the local artifact is repaired should the full 18-prompt,
   blocking/chat/SSE and lifecycle gates be rerun. A new qualified artifact is
   required before any INT8 quality or production claim can be made.
