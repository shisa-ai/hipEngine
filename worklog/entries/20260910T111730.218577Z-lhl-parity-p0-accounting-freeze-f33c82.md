# P0: owner-deduplicated workspace telemetry and parity measurement freeze

## Summary

Roadmap P0 (first tranche): F6's shared-owner double counting is fixed, the
prefill transient owners (oracles, hidden/bulk) and actual-vs-legacy executor
mode are now observable, the R0-R4 matched case manifest with exact token-ID
fixtures is published, the A/B agreement gate fails closed on a missing arm,
and the withdrawn GDN-arithmetic attribution is scrubbed from live
descriptions.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`:
  `packed_workspace_nbytes()` now counts the separately owned
  `full_attn_split_growth_buffers` of the verify scratch (they are freed with
  the workspace, so released-bytes reporting must include them).
- `hipengine/generation/qwen35_gguf.py`:
  - `packed_workspace_owner_inventory(sessions)`: pointer-deduplicated
    workspace bytes across resident sessions - shared slot views report their
    workspace once (the F6 repro: two views of one 1,024-byte allocation
    summed to 2,048).
  - `prefill_transient_owner_inventory(sessions)`: oracle owner count/bytes
    (live per-layer/shared pairs, unique buffers), pool-backed oracle capacity
    positions, hidden+bulk owner bytes, the legacy INT8 lifetime plan mode and
    the *actual* last packed executor route + per-layer flag as separate
    fields.
  - `observability_snapshot()`: `packed_workspace_current_bytes` is now the
    owner-deduplicated unique-allocation total; new
    `packed_workspace_owner_sessions`,
    `packed_workspace_leased_pool_bytes` (pinned pool-plane pages - a distinct
    accounting domain), an explicit note field, and the
    `prefill_transients` block.
  - The stale routing comment at the c1 base-zero branch now states the
    current reason (mixed executors across bases) and marks the historical
    GDN-arithmetic divergence as withdrawn.
- `scripts/gguf_prefill_route_ab.py`:
  - `--assert-entry-agreement` with fewer than two measured arms now exits 1
    with an explicit message (previously a silent pass).
  - Docstring updated: the entry divergence explanation is the executor
    schedule + attention-kernel reduction order, not the withdrawn GDN
    state-capture arithmetic.
- `benchmarks/parity/r0r4-c1-fixture.json` (new): the R0-R4 matched case
  manifest - exact 2,048-token fixture (sha256
  f039271637d8b14213b49c6380efed7d45131d064ae66d876fcd0d510e5419c9),
  boundary definitions, stage timing list, control freeze list, and
  comparison rules. Referenced from `benchmarks/HARNESSES.md`.
