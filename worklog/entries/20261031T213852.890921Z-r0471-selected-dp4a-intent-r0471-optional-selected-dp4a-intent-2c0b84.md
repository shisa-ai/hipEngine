# Optional selected DP4A invocation intent binds conversion, kernel and workspace

## Summary

R0471. The shared selected-call contract could detect the optional DP4A routes
(`HIPENGINE_GGUF_RAW_SELECTED_DP4A`, `HIPENGINE_GGUF_T16_SELECTED_DP4A`,
`HIPENGINE_GGUF_Q4K_SELECTED_DUAL_DP4A`) but refused them, because its intent
had no representation for the Q8_1 conversion they execute. That refusal is
gone for a call whose intent represents the route. The representation is the
invocation interface, not a new gate: the selectors still decide whether a call
takes the route, one plan binds both arithmetic contracts, and the bound record
says which one ran.

Five routes are declared in `SELECTED_OPTIONAL_ADAPTERS`, each naming the call
kind, resident quant, consumed allocation, launched dp4a kernel, selecting
selectors, and (for the raw pack8 singles) the out-features multiple the kernel
is registered for. `SelectedCallIntent` gained `optional_adapter` and
`workspace_owner`; `bind_selected_call` gained the route/engagement checks and
records `adapter_kernels` and `SelectedWorkspace(owner, lifetime,
rows_per_token, in_features)`.

The workspace is the resident scratch slot the plan already prices
(`SELECTED_Q8_1_WORKSPACE_OWNER = "moe_q8_1"`,
`SELECTED_WORKSPACE_LIFETIME = "scratch_plan"`). The runner's
`_optional_q8_1_workspace_ptr` now reads that slot by the shared name, so a
bound workspace owner and the runtime operand cannot drift. No kernel body,
arithmetic, default, or env flag changed; row limits, ordered dual partners, the
strict two-single fallback and the F32 capabilities are unchanged.
