# Bounded XTX TP1-route visibility diagnostic: logical 0 remaps to the XTX

## Summary

First bounded step of the narrow XTX TP1-route diagnosis: confirm whether the
RX 7900 XTX fault is a visibility/remapping problem before touching any kernel.
It is not. Under `HIP_VISIBLE_DEVICES=1` and `ROCR_VISIBLE_DEVICES=1`, HIP
reports exactly one device and logical device 0 is the RX 7900 XTX
(PCI `0000:10:00.0`); under `HIP_VISIBLE_DEVICES=0` logical 0 is the W7900; with
no override the physical order is W7900 then XTX. No model session was built and
no kernel was launched, so this stage cannot fault the GPU.

This is a scope-narrowing result, not a fix. The earlier standalone repro
(graph replay → memory access fault; eager → uninitialized token id
`9223372036854775807`) still stands, and the graph-replay/eager kernel path on
the XTX is the remaining suspect.

## Changes

- `scripts/tp2_xtx_route_visibility_probe.py` (new): enumerates HIP devices in a
  fresh subprocess per `HIP_VISIBLE_DEVICES`/`ROCR_VISIBLE_DEVICES` combination
  (HIP caches the visible set at library load, so in-process changes do not
  re-enumerate), prints each logical device's name/uuid/pci, and records
  `hip_visible_devices_1_logical0_is_xtx`. No weights, no kernels.
- `tests/test_unit_scripts_tp2_xtx_route_visibility_probe.py` (new, 3 tests):
  mapping true/false and enumeration-failure recording, with `subprocess.run`
  monkeypatched so no HIP library is required.

## Validation

- `python3 scripts/tp2_xtx_route_visibility_probe.py --json /tmp/xtx-visibility.json`
  on this host: `HIP_VISIBLE_DEVICES=1` → count=1, `0:AMD Radeon RX 7900 XTX
  @0000:10:00.0`; `HIP_VISIBLE_DEVICES=0` → count=1, `0:AMD Radeon Pro W7900
  @0000:0d:00.0`; no override → count=2 in physical order; `ROCR_VISIBLE_DEVICES=1`
  → count=1, logical 0 is the XTX. `hip_visible_devices_1_logical0_is_xtx: true`.
- `python3 -m pytest tests/test_unit_scripts_tp2_xtx_route_visibility_probe.py`
  — **3 passed**.
- No model session, no kernel, no GPU fault, no reset.
