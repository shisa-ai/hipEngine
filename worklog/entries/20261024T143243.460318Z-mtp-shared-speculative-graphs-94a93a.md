# Share speculative graph ownership and evaluate PARO replay

## Summary

The public PARO graph test reproduces the missing route: a 37-token request
runs only eager verification. The graph-cache refactor, GGUF NextN migration
and PARO adoption now share one lifecycle helper
(`hipengine/speculative/graph_stage.py`, committed in `393b5a987`). PARO
captures and replays one verifier `VERIFY|ACCEPT` graph per row/split/mode
bucket. The full comparison rejects graph-auto as the default: natural decode
is 3.23% slower than eager, confirmed at 3.06%. The adapter honors the planner's
eager preference while keeping graph plans executable. No graph speedup is
claimed.

## Changes

- Added a public graph/eager oracle that compares every completed speculative
  cycle's live target KV, recurrent state, hidden state and draft state, plus
  output IDs and acceptance. Explicit graph plans and repeated graph calls must
  actually replay and report the graph route, while ordinary public calls must
  report eager. Neither route may leave a graph the runtime refused to release.
- PARO replaced its `_verify_graph_cache` dict with `SpecGraphStageCache`. The
  cache entry owns a resumable `release()`: each successfully destroyed handle
  is zeroed so a retry skips it, and a capture that fails retains its handles on
  `_verify_graph_partials` instead of dropping the only reference. A refused
  release refuses the next capture (`GRAPH_STAGE_RELEASE_BACKLOG`) rather than
  accumulating abandoned captures.
- The verifier graph key now carries the per-row attention split counts
  (`_verify_graph_split_bucket`), which the decode-attention kernel bakes into
  its grid and reduction order. `chain_attn_mode='decode_batched'` is
  graph-eligible for that reason: a cycle whose split count differs re-captures
  instead of replaying a narrower reduction. The binding also fingerprints
  every device allocation the recorded kernels dereference (session buffers,
  per-layer linear/full state views, scratch dicts, and the prefill workspace
  table) plus the route configuration, so a moved pointer re-captures instead
  of replaying freed memory.
- `Qwen35ParoMTP2Adapter` declares `graph_supported=True`, requests reusable
  verification for graph plans and reports the route the target actually
  executed (`_executed_graph_route`), matching the GGUF MTP adapters. A cycle
  that cannot capture falls back to the direct pass and reports
  `capture_failed_fallback`; per `docs/EXECUTION-PROFILES.md`, that is a
  per-cycle miss, not a permanent revocation.
- Removed the old `HIPENGINE_VERIFY_GRAPH_RECAPTURE` diagnostic: bound address
  and split identities plus public graph/eager state tests now cover the stale
  pointer defect it worked around. Explicit `graph_mode='validate'` still
  provides a direct-versus-fresh-graph diagnostic without an environment flag.

## Decision

Keep the shared lifecycle and bound replay implementation, but reject automatic
graph selection as a one-candidate speed optimization on the measured host.
The existing planner selects eager; graph plans remain supported. There is no
new flag and no capability refusal. The cleanup ledger names the observed
slowdown and the exact comparison that can clear the eager preference.
The deeper-candidate and cross-model completion rows remain open in the active
matrix; this commit does not claim the larger assignment is finished.
