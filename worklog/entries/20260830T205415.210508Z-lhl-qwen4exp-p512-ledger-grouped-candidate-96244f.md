# Fresh p512 production ledger + grouped-routing candidate

## Summary

Established a fresh real-weight p512 production ledger for the Qwen4Exp model
on zbook/gfx1151, and measured a grouped-routing candidate against it. This is
the campaign's "fresh p512 device-role ledger" (P0) and a candidate screen for
the P1/P2 grouped Q5_K gate/up WMMA routing direction.

## Changes

- Added `scripts/qwen4exp_candidate_ar.py`: a candidate driver that re-applies
  routing env overrides after the production profile binder resets them, so a
  candidate route can be measured on the canonical fixture without a retained
  claim.
- Measured the production p512 baseline and a `HIPENGINE_QWEN4_EXP_GROUPED_MOE_PREFILL=1`
  candidate on the canonical p512 fixture (4 categories, 512 tokens).

## Validation

Local zbook/gfx1151, production profile, canonical p512 fixture, 1 warmup + 1
measured repeat, deterministic (all cases `all_cases_deterministic=True`):

| Case | baseline pp tok/s | candidate pp tok/s | delta |
| --- | ---: | ---: | ---: |
| code-p512 | 93.36 | 99.77 | +6.9% |
| general_en-p512 | 93.46 | 100.82 | +7.9% |
| general_ja-p512 | 93.74 | 100.95 | +7.7% |
| mixed_ja_en-p512 | 93.62 | 98.82 | +5.6% |

p512 aggregate: baseline **93.54** tok/s prefill / 13.97 decode; candidate
**100.08** tok/s prefill / 13.91 decode (**+7.0% prefill**). Decode unchanged.

Candidate output token IDs differ from baseline (arithmetic changed), so the
grouped route is production-class and requires the full KL/top-1 packet gate
before any promotion. The `GROUPED_MOE_PREFILL=1` flag routes ALL Q4/Q5 layers
through grouped paths, not layer 2 alone, so this is a direction screen, not a
layer-2-isolated result. The strict p512 chunked correctness compare on an
ad-hoc 322-token prompt was inconclusive (KL 2.44 even on the strict path),
so correctness must be judged by the canonical heldout/packet gate, not that
prompt.
