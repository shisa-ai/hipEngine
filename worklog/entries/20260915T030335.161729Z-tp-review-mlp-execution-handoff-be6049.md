# Audit TP progress and define the one-layer execution milestone

## Summary

Reviewed `20a7abe93`, `151c44204`, `580598a49`, and `e9e678b02`.
The task list is not authoritative; current source and artifacts show the
native A/B corrections, incumbent layout resolution, explicit partial-dtype
choices and threshold separation. The next performance milestone is actual
rank-local one-layer MLP execution, not another metadata-only probe.

Two focused defects need repair first: the admission probe invokes a real
launcher with null pointers, and projection certification ignores inconsistent
inputs and accepts nonexistent evidence paths. No implementation files changed
in this review.

## Changes

### P1: metadata probe can launch a GPU kernel with null pointers

`scripts/tp2_mlp_shard_plan_probe.py:fused_path_admission` calls
`gguf_q4_k_t16_dense_dual_local32_silu_bf16_bf16_out` with four zero pointers
and a valid shape. The launcher validates dimensions, loads its kernel library
and HIP runtime, then calls the native launch function. It is not a pure validator.
An exception after that point cannot establish safe shape acceptance, and an
asynchronous device fault is not prevented by catching Python exceptions.

The probe calls this helper even without `--device`; unguarded tests also call
it. Do not run these tests or the host probe on a real GPU as written.
Extract a pure shape validator or inject a non-launching library/runtime in
tests. Add a host-only guard proving no JIT/HIP/launch path is reached.
Use valid device allocations for subsequent execution qualification.

CPU-only reproduction with both library/runtime factories replaced by fakes
recorded a native call with arguments
`[NULL, NULL, NULL, NULL, 1, 5120, 8704, NULL]`. No actual HIP call was made.

### P1: projection can certify internally inconsistent evidence

`scripts/tp_break_even.py:build_report` records a collective count/latency
mismatch in `errors`, but does not include those errors in `withheld_reasons`
or certification. `pre_packet3_gate.satisfied` checks only whether the supplied
evidence list is nonempty.

CPU reproduction: two 30 tok/s arms with 16 GiB full/8 GiB rank weights,
one fixed-share row at zero, collective_ms=1, reduction_points=128, source
marginal=1000 us, and evidence `['/missing/not-an-artifact.json']` reports
the expected communication mismatch (128 ms versus 1 ms), yet `certified=True`.

Make errors binding and validate evidence existence, schema, identity and
verdict before claiming the evidence gate passed. Alternatively keep this
calculator explicitly advisory and rename/remove certification. Separating
1.0x break-even from 1.3x aspiration is correct, but neither constitutes
model correctness or measured engine speedup. The existing native artifact is
still withheld; this repro concerns the gate implementation.

### P2: device materialization evidence is narrower than the task label

`device_stage()` loads the full selected MLP on visible device 0, reads it back,
then compares host-generated shard tiles with corresponding full tiles.
This is useful incumbent resident-byte parity. It does not allocate/upload
separate rank-local weights on both devices or validate their kernel consumers.
The scope string correctly disclaims execution, but task #43 bullet 1 should
distinguish this from a completed rank-local device loader.

Next implement a minimal rank-local loader over the existing incumbent
spec/repack path; preserve global model geometry separately from local linear
dimensions. Record actual allocation bytes per rank, including sidecars and
workspace, and verify no full-model device intermediate appears.

### P2: fused admission query is not the full policy selector

The helper unions shapes from every model/quant policy and always calls the
Q4 kernel; its quant_type argument is unused, and it assumes N=2 by integer
halving (including silently flooring odd intermediates). The real selector in
`qwen35_gguf_runner.py:_gguf_dense_pair_silu_decode_variant` uses model/quant
identity and potentially the native-decode capability before shape selection.
Resolve that actual identity and local shape. Reject impossible partitions.

The reported missing `(1,5120,8704)` admission for the target is a credible
optimization candidate, not proof the kernel computes correct shard outputs.
Run a guarded fused-versus-unfused local test before extending scoped admission.
Do not add a shape merely to make the projection work.
