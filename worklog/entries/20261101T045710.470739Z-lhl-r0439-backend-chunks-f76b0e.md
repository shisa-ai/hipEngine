# Move shared prefill chunk fallback into backend capability policy

## Summary

Move the unchanged gfx1151 automatic linear/MoE fallback into backend-owned
capability data shared by GGUF and PARO. GGUF's geometry/quant row remains a
more specific input; PARO does not infer that row from hidden size. Same-host
public generation and native automatic/explicit chunk checks pass. Remove R0439
from the active ledger; this entry records its decision and evidence.

## Changes

- `PREFILL_CHUNK_SIZES = (256, 256)` belongs to gfx1151's capability policy,
  not a central runtime architecture table. Both sessions and the GGUF capacity
  estimator pass their backend to the one final-size resolver.
- Keep any manual chunk field as whole-config authority; disabled tuning never
  consults backend policy. Geometry overrides backend fallback; absent geometry
  uses the fallback, and unknown architectures/backends keep shape/memory sizes.
- Arch-only direct resolver callers resolve a known backend's policy without a
  second table of sizes. Existing tuning reason/source fields stay unchanged.
- Preserve exact target-architecture matching for arch-only calls. This move
  does not add support for compound architecture aliases or change their old
  unknown-architecture fallback behavior.
