# Confine KV pool allocations to one storage chunk

## Summary

The last KV-pool growth defect is fixed. The GPU memory fault was not stale
pointer tables, which is what the previous entry and `docs/REFACTOR.md`
recorded: `bind_device_kv_allocation` hands the session one backing chunk's
cache buffers while the block table carries global page ids, and every KV
kernel addresses a chunk as `base + page * stride`. A grown pool handed out
allocations whose pages sat in the appended chunk, so the write ran off the end
of the first one. Allocations are now confined to a single chunk. With the
fault gone, the wide retained working set turns out to be a regression.

## Changes

- `hipengine/kvcache/global_pool.py`: `_select_free` takes `within=(low, high)`
  and filters candidates to that half-open page-id range; `_find_free_run`
  accepts the same candidate set; `allocate` exposes `within_page_range` and
  rejects shared pages outside it.
- `hipengine/kvcache/device_global.py`: the pool tracks
  `_chunks: [(start, pages, backing)]`, seeded with the initial backing and
  appended on growth. New `_allocate_within_one_chunk` tries chunks in page-id
  order (or only the chunk holding the shared prefix) and re-raises the last
  failure, so callers still see `MemoryError` or `DeviceKVContiguityError`
  rather than an unbindable placement. `_allocation` reports the owning chunk's
  `backing` and `chunk_start_block_id` instead of chunk 0's.
- `hipengine/kvcache/device_global.py`: `admit_with_shared_prefix` no longer
  grows. Growth appends a separate chunk and a shared admission must place its
  suffix beside its prefix, so growing could only enlarge the pool permanently
  without helping. It asks `_on_pressure` (eviction frees pages inside existing
  chunks) and otherwise declines with `MemoryError`, which admission already
  turns into the private-allocation fallback.
- `hipengine/runtime/qwen35_gguf_runner.py`: `grow_storage` returns its new
  chunk's backing as a third element; two-element returns still work.

## Validation

- `tests/ -k "kvcache or prefix or device_kv or pool or engine_loop"` — the only
  failure is the pre-existing `test_unit_grammar_masks` `llguidance` import.
- `test_shared_prefix_admission_grows_only_for_private_suffix` rewritten to the
  confinement contract: a two-page suffix cannot join a prefix in a chunk with
  one free page, so the admission declines, a private allocation then lands in
  the appended chunk (`chunk_start_block_id == 3`), and a one-page suffix that
  does fit still reuses the prefix in chunk 0.
- Served multi-turn A/B, zbook / gfx1151, Qwen3.6-35B-A3B `UD-Q4_K_M`, with
  `HIPENGINE_GGUF_PREFIX_RETAINED_SNAPSHOTS=16`, which previously faulted the
  GPU after six lanes: it now completes, and is worse than the default
  retention.

  | config | hits/lookups | reused tokens | wall vs off |
  | --- | ---: | ---: | ---: |
  | default retention | 16/27 | 42,496 | **-18.6%** |
  | retained 16 | 18/27 | 46,592 | **+9.5%** |

  Per lane at retained 16: cumulative coding 114,139 -> 168,111 ms (+47.3%)
  despite 8 of 9 hits, fixture coding 113,708 -> 90,681 ms, ShareGPT
  123,651 -> 126,225 ms. The extra pinned pages push the pool into growth and
  eviction, and that costs more than the two additional hits return.

## Next

- `GlobalDeviceKVPool.shrink_idle` is a stub returning 0, so a pool that grows
  stays grown for its lifetime. Returning idle chunks would make the growth
  path fully reversible.
- The wide retained set stays opt-in on measured cost rather than on safety.
