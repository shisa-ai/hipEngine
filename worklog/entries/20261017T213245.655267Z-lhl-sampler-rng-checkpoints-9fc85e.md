# Preserve exact sampler RNG checkpoints across forced tokens

## Summary

`RowSamplingState.clone()` reconstructed the RNG from the emitted-token count.
Forced and greedy tokens emit without drawing, so a checkpoint after either
advanced the RNG incorrectly. A draw without observation was also lost. The
clone now copies the actual generator state, independently of output history.
This repair is required before integrating forced/structured MTP controls;
HTTP admission for those controls is not changed by this unit.

## Changes

- Add keyword-only `rng_draw_count` to row sampling state. `random_unit()`
  increments it only after a successful draw; `observe()` still increments the
  output step only. Explicit reconstruction accepts a draw count, including
  zero, independently of output steps. Omitted counts preserve the prior
  step-only constructor behavior for compatibility.
- Clone with zero initialization draws, then copy the actual bit-generator
  state and count. Clones do not replay the entire generation history into RNG
  or share mutable RNG state. Existing processor queues/DFA cloning is unchanged.
- Flash-Next speculative transactions record the actual draw counter instead
  of assuming one draw per emitted token for every positive-temperature request.
  No new flag, GPU arithmetic or dispatch path.
- Repair two stale grammar finish fixtures to declare the resident row's
  `mtp_output=None` field. Their prior failure predates this RNG repair; do not
  weaken the runtime row contract with permissive attribute access.
