# EVIE batch review: add ownership gates and reproduce cache use-after-free

## Summary

Reviewed `d1cf71dbf` and added missing regression tests at the user's explicit
request: "if important tests missing, let's add them; if they fail, we will
bounce those to our coder to fix." Six new GPU ownership checks pass; a
CPU-only allocation/dispatch test exposes a deterministic use-after-free.
The failing test is intentionally committed as a RED handoff, not marked
xfail and not accompanied by an implementation repair.

### P1: Attention cache eviction frees an operand still in use

`hipengine/runtime/evie.py:357` evicts entries from both score and plane
caches on a cache miss, protecting only the requested key. An attention call
can retrieve a cached QKV plane and subsequently request a missing score
buffer; that request can free the QKV allocation held in the caller's local
variable. `_attention_from_packed` then submits its released pointers to
rocBLAS at line 781. The preceding cache-bounding fix introduced this lifetime
problem; the new ragged/multi-page API makes mixed-shape coverage essential.

The committed CPU regression calls text attention at lengths 560, 8, 6,
then vision attention at patch counts 560, 576, 560. A fake allocator returns
unique addresses and records frees; every kernel/GEMM submission checks its
operands against released address ranges. The last call submits a freed QKV
operand. No device allocation or GPU launch is involved, and failure is
independent of allocator address reuse luck. Pin all live operands until the
attention call finishes, or perform eviction only at a safe operation boundary.
Increasing the cache cap alone is not a robust ownership fix.

### P1: Reassociation replaced the strict kernel without its profile gate

`evie_ops.hip:934` replaces serial GDN L2 summation with a lane/butterfly
reduction under the same symbol. This changes arithmetic on both FP32 and
FP16 routes. The artifact calls reduction reassociation T1, while the normative
classification names reduction reordering T2. The old strict implementation
is not retained as a registered fallback for this changed primitive.
`tests/test_evie_gpu_runtime_fp16.py:99` lowers document minimum cosine from
0.99854 to 0.99845 after observing the new result. Re-pinning one fixture and
reporting a better MaxSim delta do not constitute the full predeclared profile
adjudication required by the previous gate and EXECUTION-PROFILES. Preserve
the measured candidate, but retain the strict parent path and complete the
retrieval-specific candidate/heldout gate rather than silently redefining it.
No new numerical failure beyond the documented prior-envelope change is
claimed by this review.

### P2: Performance result is not yet reproducible from the committed bench

The new artifact records 1172.7 ms on real-processor inputs/full scoring, but
contains no exact command or retained matched-input harness. The changed
`scripts/evie_hip_bench.py` still uses its synthetic token templates and
times only zipped pairs, even with `--batched --accuracy`; full scoring in
accuracy mode occurs outside the timer. It reproduces the separate ~1134-ms
bench protocol, not the reported matched 1.11x comparison. Preserve both
protocol identities and commit the executable matched harness/commands.
The bench's sequential-mode comment also incorrectly says preprocessing
is timed; preprocessing now occurs before both branches.

`benchmarks/README.md` still says the old sequential path loses to Torch,
and the commit contains no rollup/changelog/catalog updates despite retained
performance and kernel changes. Update those as part of campaign closure.
Teacher-score fidelity on eight synthetic pages is useful diagnostic evidence,
not a general retrieval-quality verdict; it does not close the real-corpus
ranking qualification. No new benchmark or speed measurement was run here.

### What the additional tests establish

The batched attention/conv/GDN wiring is consistent with per-segment execution.
The original six batched tests instantiate only FP32 and only query inputs.
New tests cover both FP32 and FP16, A|B versus A|C and B|A versus C|A,
distinct image pixels, padding compression, repeatability, and unequal-size
documents (a fixture page paired with a 4x4-patch/four-image-token page).
All six cases pass. These deliberately compare unchanged rows at the same
batch shape/schedule; they do not invent a new cross-width numerical tolerance
or claim a general quality envelope.
