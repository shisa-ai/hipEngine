# R0523 early-window KV+conv+rec trace: conv/rec clean at steps 1-8; KV hash confounded by arena page_ids

## Summary

Extended the env-gated R0523 tracer (`_r0523_trace_packed_state` in
`hipengine/generation/qwen35_gguf.py`) to also hash per-row packed-KV planes
(`HIPENGINE_R0523_TRACE_KV=1`) alongside conv/recurrent state, and ran a 40-rep
c4 burst hashing decode steps 1-8 every step
(`run-r0523-kv-trace.sh`, artifact `r0523-kv-trace.json`).

Result: the race still reproduced (1/40 measured, request_index=1, decode pos 73,
6866->3154), but the per-row conv AND recurrent digests are byte-identical
(same multiset) across ALL measured repeats at every step 1-8 — including the
repeat that later flipped. The only conv/rec divergence is the live-admission
repeat (different prompt = known false positive). So the corruption does NOT
originate in conv/recurrent state within the first 8 decode steps.

The per-row KV digests differ across EVERY repeat (not just the corrupted one),
so they cannot be used for attribution as hashed: the packed KV backing is a
GlobalDeviceKVPool arena lease with arbitrary slot-major `page_ids`, and the
tracer hashed the dense plane slot-major (identity assumption). Physical page
placement differs per repeat, confounding the digest. KV attribution needs to
hash through `state.page_ids` (logical slot order), not the raw plane offset.
