# Track eager exchange submissions without blocking graph capture

## Summary

An eager `enqueue_rank` after a successful `wait`, without another counter
bump, was accepted but not tracked. `reset_timeouts` or `step_begin` could then
clear its unobserved timeout. Graph capture also calls `enqueue_rank`, so
counting all calls would break the first execution after recording.

## Changes

- Query `hipStreamIsCapturing` before the native enqueue. Return an enqueue-only
  success code for active capture, and ordinary success for eager submission.
- Mark eager success as unobserved work regardless of whether a counter bump
  preceded it. Only a successful wait permits another timeout clear.
- Keep reduction kernels and arithmetic unchanged. Graph replay still uses the
  existing step-begin/wait schedule; this does not support arbitrary replay
  outside that schedule.
- Replace the fake capture test's assumption with explicit capture status.
  Add fresh and post-wait eager submission cases for both clearing methods.
- Add a HIP-guarded real capture/replay test followed by a one-sided eager
  enqueue on a previously unused slot. Both clears refuse, wait reports the
  timeout, and the handle is poisoned.
