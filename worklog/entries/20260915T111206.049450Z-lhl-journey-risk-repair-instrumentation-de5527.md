# Add iu8 risk+repair rate instrumentation and first measurement

## Summary

The exact iu8 risk+repair routes collect per-output risk indices into a device
queue that is consumed by the sparse exact-repair kernel and never observed.
Add an opt-in readback so the repair rate — the number that decides whether the
pattern is worth extending to another arithmetic family — is measurable. First
measurement on the current production default at code/4K: **0.712% aggregate
repair rate over 4.93e9 outputs, 0.803% worst single call, zero over-capacity
events.** The fast int8 path therefore keeps ~99.3% of its work.

## Changes

- `hipengine/runtime/qwen4_exp_runner.py`: add `RISK_DIAGNOSTICS_ENV`
  (`HIPENGINE_QWEN4_EXP_RISK_DIAGNOSTICS`), a bounded per-call observation
  record, `_observe_qwen4_exp_risk_queue`, and
  `summarize_qwen4_exp_risk_diagnostics` (per route/role and route/role/layer
  calls, outputs, risk, aggregate and worst-case repair rate, over-capacity
  count). The readback follows the existing in-tree pattern
  (`stream_synchronize` then `copy_device_to_host`) and is inert unless the env
  gate is set, so the default path gains no synchronization.
- One call site: the `Q4_IU8_EXACT` risk+repair branch, after
  `sparse_exact_repair` and before the fused SiLU.
- `scripts/qwen4exp_profile_gap.py`: add `--risk-diagnostics` (prefill only)
  and report the summary; add `Q4_IU8_EXACT`, `Q4_IU8_RISK_MULT`,
  `Q4_IU8_PLANES` and `PLE_WARM` to the recorded route environment so a profile
  proves which variant ran.
- `tests/test_unit_qwen4exp_risk_diagnostics.py`: 14 tests covering the env
  gate, the readback, the reported rate, over-capacity flagging, the record
  limit and the aggregation.

## Next

- Use the instrument to rank the nine still-disabled arithmetic families by
  seconds recoverable rather than historical headline gain.
- The 0.712% rate is the template datum for that ranking: it shows a
  risk+repair route can stay bit-identical to its exact parent while keeping
  ~99.3% of the fast kernel's work. It does not by itself show that any other
  family has a comparably low trigger rate, which is why each family must be
  measured on real production inputs.
- The same run captured real expert populations per layer (512 experts, 349
  active at layer 0, median 23 rows per active expert, max 185, top_k 10) for
