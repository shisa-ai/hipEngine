# Add firewall-safe long DMS bias calibration

## Summary

Added the lowest-cost valid repair path for the 32K sidecar rejection: a
source-disjoint long calibration/heldout corpus builder and GPU score-only
per-layer/head bias calibrator. This avoids O(T^2) attention-label construction
unless threshold/bias-only repair fails.

## Changes

- `qwen38_dms_build_long_manifest.py` deterministically excludes every prior
  CPython path and Wikipedia page ID, uses no benchmark/screening prompts, and
  creates one 32K calibration plus one disjoint 32K heldout sequence per
  code/English/Japanese/mixed category. It records tokenizer, source hashes,
  licenses/revisions, split, and clean Git provenance.
- `qwen38_dms_calibrate_long_bias.py` captures only exact-stage external-linear
  scores on GPU, chooses eligible-history CR2 score medians independently for
  all 16x4 layer/heads on calibration rows, folds them into the 64 BF16 biases,
  keeps all 327,680 learned weights unchanged, emits strict metadata/provenance,
  and reloads through the normal torch-free validator.
- Added deterministic helper/format tests and documented both tools.

## Validation

- Preliminary real corpus construction produced eight exact 32,768-token rows
  from 64 unique sources with zero source overlap between sequences. The normal
  capture-manifest validator accepts all eight and all four categories.
- The minimal BF16 safetensors writer round-trips the complete retained
  16x4x5120 sidecar through the production loader with weight/bias equality and
  the exact expected 655,640-byte size.
- Initial focused bundle had one incorrect test expectation while production
  code remained sound; focused repair now passes 4/4. The earlier combined
  external/HIP bundle had all other 13 tests pass. Ruff, py_compile, and diff
  checks pass.
