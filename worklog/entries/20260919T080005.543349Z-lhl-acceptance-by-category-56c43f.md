# Acceptance by mtp-bench category: code 0.786 against general_ja 0.462, and the pair harness now records it

## Summary

The natural ShareGPT comparison (`9861eb537`) reported acceptance 0.667-0.692
across its lanes and left "acceptance by mtp-bench category" unmeasured, because
`scripts/gguf_mtp_server_pair_bench.py` stored a prompt row's coverage and cycle
counts but not its accepted-draft counts. It now reads
`accepted_draft_tokens`/`rejected_draft_tokens` from the extension block the
served row reports itself, falling back to the OpenAI
`usage.completion_tokens_details` key, and keeps them in the stored row
(`53c7b65ee`, RED/GREEN in
`tests/test_unit_gguf_mtp_server_pair_bench_acceptance.py`).

Re-measured on the promoted route with the same protocol the retained category
rows use (`--prompts-file benchmarks/prompts/mtpbench-code-general-ja.jsonl
--pad-to-tokens 3530 --decode 128 --repeats 2`, adapter window raised to 8,192):

| category | prompts | cycles | accepted | acceptance |
| --- | ---: | ---: | ---: | ---: |
| code | 4 | 151 | 356 | **0.786** |
| mixed_ja_en | 2 | 91 | 163 | 0.597 |
| general_en | 2 | 102 | 151 | 0.493 |
| general_ja | 2 | 106 | 147 | 0.462 |

Per prompt, acceptance runs from **0.417** (`general_ja_explain`, 16.3 tok/s) to
**0.867** (`code_markdown_table`, 27.2 tok/s), and the decode rate tracks it.
Coverage is flat at 0.984-0.992 in every category, and every row reports
`effective_route=speculative_mtp` with
`decision_reason=qualified_automatic_realized_singleton_c1_b3`, so the spread is
which drafts the verifier accepts and not whether speculation engaged.

This supersedes the "acceptance by category is not measured" line in the Next
section of `worklog/entries/20260919T070732.907714Z-...-069207.md`; that entry's
rate and identity results are unchanged, and its 0.667-0.692 natural-lane figures
are the mixed-prompt average over this spread.

## Changes

- `scripts/gguf_mtp_server_pair_bench.py`: `route_summary` takes the usage block,
  reads the accepted/rejected draft counts from the extension first and the
  OpenAI key second, and `ROUTE_ROW_KEYS` keeps them in the stored prompt row.
- `tests/test_unit_gguf_mtp_server_pair_bench_acceptance.py`: four cases (extension
  path, usage fallback, missing usage, stored-row keys), the first three RED
  before the patch.
- `benchmarks/results/2026-09-19-gfx1151-qwen38-natural-sharegpt-mtp-route-comparison.json`:
  new `acceptance_by_category` block with the per-prompt rows and the
  category rollup, plus a guard entry classifying "acceptance is uniform across
  categories" as a known failure.
- `benchmarks/CHANGELOG.md`: the same dated rollup line extended.
