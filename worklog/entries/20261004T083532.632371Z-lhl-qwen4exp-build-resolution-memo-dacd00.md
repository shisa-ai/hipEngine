# Memoize the build-resolution cache-hit path; it is off the Qwen4Exp decode critical path at p512

## Summary

`build_hip(load=True)` already avoided rebuilding through `_LOADED_LIB_CACHE`,
but reaching that cache re-derived the key on every call: the four-variable
compiler-version environment identity, the target arch, the implicit cache root,
the fail-closed switch, and a `Path` round-trip per source. The launch path calls
`build_X(load=True)` **once per kernel launch** with none of those arguments
explicit, so a Qwen4Exp decode step paid the derivation ~918 times. The prior R7
wrapper-host screen priced the version resolution alone at 919 resolves and
~8.8 ms per decode step; this unit removes the rest of the derivation.

Measured per-call cost, same host, pinned compiler version file, warm caches:
`build_gguf_k_gemv(load=True)` **5.13 -> 2.60 us** and
`build_qwen4_exp_gr(load=True)` 5.13 -> 2.61 us, a 49% reduction. The remaining
2.6 us is the environment identity that keeps the memo from hiding an
environment change; a bare dictionary lookup is ~0.3 us.

**End to end this is neutral at p512 and possibly small at p4096, and that is
the more useful result.** A counter-rotated A/B (base / memo / base) on the
canonical bench, one case per process, production profile, compact capture
kwargs, chunk 1024, one warmup and one measured repetition:

| case | base-a | memo | base-b | base mean | delta |
| --- | ---: | ---: | ---: | ---: | ---: |
| code-p512 decode tok/s | 21.017 | 21.032 | 21.039 | 21.028 | **+0.02%** |
| code-p512 prefill tok/s | 265.068 | 265.273 | 265.407 | 265.237 | **+0.01%** |
| code-p4096 decode tok/s | 17.248 | 17.748 | 17.374 | 17.311 | **+2.53%** |
| code-p4096 prefill tok/s | 272.545 | 271.447 | 272.615 | 272.580 | -0.42% |

Removing 2.3 ms/step of host work changed p512 by 0.02% against a 0.05%
base-to-base spread, so **at p512 the host dispatch path has at least 2.3 ms of
slack per step and is not the binding constraint.** The p4096 decode delta is
above the 0.73% base-to-base spread with both baselines below the candidate, but
17.748 is also the top of this metric's cross-session range (17.17-17.75), so it
is recorded as suggestive rather than as a retained headline win. The p4096
prefill -0.42% is a single-sample dip outside a 0.03% base spread and is read as
drift, not a regression from a change that only removes work.

**Consequence for the active decode hypothesis:** the loop's iteration-14
hypothesis ("the step's rate is set by Python/ctypes host work") is **not
supported at p512** by a direct subtraction of host work. See the companion
entry on the token-readback split for what the step's limit actually is.

## Changes

- `hipengine/core/build.py`: add `_RESOLUTION_CACHE`, keyed on the call
  arguments plus `_resolution_environment_identity(compiler)` - the complete set
  of build-affecting environment inputs (four compiler-version override
  variables, `HIPENGINE_HIP_ARCH`/`HIPENGINE_HIP_OFFLOAD_ARCH`,
  `HIPENGINE_BUILD_CACHE_ROOT`, `HIPENGINE_REQUIRE_CACHED_BUILD`). A cache hit
  is now one environment read plus a dictionary lookup. `force=True` bypasses
  the memo; `load=False` and `dry_run=True` are not memoized. New
  `invalidate_build_resolution()` drops both the memo and `_LOADED_LIB_CACHE`.
  The key is built from the raw arguments (`str(s)` on sources, not
  `str(Path(s))`), which is what removes the per-call `pathlib._parse_path`
  cost; because it is the *arguments* rather than the resolved values, a
  differing environment produces a distinct key rather than a collision.
- `tests/test_unit_build.py`: three tests - the memo skips repeated derivation
  while still honouring a changed `HIPENGINE_HIP_ARCH` (the contract
  `test_build_hip_loaded_cache_distinguishes_environment_target_arch` pins),
  `force=True` still re-loads, and `invalidate_build_resolution()` empties both
  caches.
- No kernel, no arithmetic, no dispatch and no default changed.
