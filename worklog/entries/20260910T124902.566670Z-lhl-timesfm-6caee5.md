# TimesFM 3.0 500M support — contract, loader, CPU reference

## Summary

Tier-1 port of google/timesfm-3.0-pytorch mirroring the 2.5
ac5c5cbc0 unit: pinned model contract + plugin registration,
torch-free FP32 checkpoint loader, and a NumPy CPU reference of
forward() + the non-autoregressive decode() (single pass, no AR loop),
validated against a vendored-torch oracle fixture at max_abs 5.7e-6.

## Context

User asked for TimesFM-3.0 support while on main. TimesFM 3.0 is a
substantially different architecture from 2.5: Stacked Mixing
Transformer with non-causal variate attention across up to 32 variates
(targets + past-only + past-future covariates), non-autoregressive
CPM-masked horizon decoding with patch stitching, linear detrending,
iterative CPM RevIN refinement, ReLU activations (not Swish), no
biases anywhere except the output head, and torch nn.RMSNorm
semantics (eps = finfo(float32).eps = 1.1920929e-7, NOT 2.5's 1e-6).

Reference lineage: google-research/timesfm master
src/timesfm3/torch/{model,transformer,dense,normalization,util,cpm_revin_refine,configs}.py
(Apache-2.0), fetched and inspected at /tmp/tfm3; vendored into
scripts/timesfm3_oracle_torch.py for the oracle.

## Changes

- hipengine/models/timesfm3.py: TimesFM3ModelSpec (445 tensors,
  330,710,976 params pinned), parse with full drift rejection
  (num_layers pinned to 20), expected weight manifest, weight-index
  validation, TimesFM3Model plugin registered as "timesfm_3p0" /
  architecture "TimesFM3Torch"; exports wired into
  hipengine/models/__init__.py.
- hipengine/loading/timesfm3.py: torch-free FP32 materialization
  (mirror of the 2.5 loader), resident bytes == contract bytes
  (1,322,843,904).
- hipengine/kernels/cpu_reference/timesfm3.py: NumPy port of forward +
  decode including running stats, future-covariate roll, CPM masking,
  seq/variate attention with SDPA semantics (scores * sqrt(head_dim),
  fully-masked rows -> zeros matching the CPU SDPA backend; such rows
  only exist at leading-pad positions decode() slices away), stitching,
  detrending, CPM iterative RevIN refine.
- scripts/timesfm3_oracle_torch.py: vendored torch reference
  (fixture generator only; hot path stays torch-free) + seeded fixture
  tests/fixtures/cpu_reference/timesfm_3p0_decode.npz (batch 2:
  multivariate-with-covariates element and univariate-with-front-pad
  element, context 512, horizon 96).
- tests/test_timesfm3_model_contract.py (5 tests),
  tests/test_timesfm3_cpu_reference.py (3 tests).

## Validation

- Numpy-vs-torch decode parity: max_abs 5.7e-6 (mean 7.5e-7) over
  (2, 4, 96, 9) logits; deterministic repeat runs bitwise equal.
- pytest tests/test_timesfm3_model_contract.py
  tests/test_timesfm3_cpu_reference.py: 8 passed; 2.5 contract + CPU
  reference + generation registry re-run green (no regressions).
- GPU loader smoke: load_timesfm3_model on the cached snapshot
  materializes 1.32 GB FP32 and frees cleanly.

## Decisions

- Mirror the 2.5 tier-1 scope first (contract + loader + CPU
  reference + oracle). GPU decode is a separate campaign: the 3.0
  forward is one prefill-shaped pass over (b, v, n) with variate
  attention (no AR loop, no KV cache), so the kernel plan differs
  substantially from the 2.5 decoder and deserves its own profiling
  entry point.
- RMSNorm epsilon fixed at finfo(float32).eps per torch nn.RMSNorm
  (verified empirically against torch 2.13.0+rocm).
- SDPA fully-masked-row semantics verified empirically (zeros on CPU
  backend, not NaN and not uniform 1/S); the numpy reference mirrors
  this because such rows exist only at leading-pad positions.
