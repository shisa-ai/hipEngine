# Map Qwen3.6 token table and promote c1 PM4

## Summary

Retained a private-c1 mapped-host owner for the 715,161,600-byte raw Q4_K
Qwen3.6-27B token table. The contiguous GGUF mmap is page-locked and exposed to
the existing registry embedding kernel through `hipHostRegisterMapped`, without
a VRAM shadow. Tracked residency drops 16.749321 -> 16.083275 GiB (-3.977%) and
same-workload sampled peak delta drops 17.347168 -> 16.679199 GiB (-3.851%);
the standard 512/128 PM4 row peaks at 16.712402 GiB. Three 512/128
reset/replays show PM4 at 33.423773 decode tok/s vs HIP graph at 32.897226
(+1.601%), so the model-specific private-c1 >=128 policy now defaults to PM4.
Decode clears its frozen gate; prefill and memory remain open.

## Changes

- Added the gfx1100 `GGUF_MAPPED_HOST_TOKEN_EMBEDDING_C1` package capability.
  Private-c1 auto placement defers the raw token table, pins its existing mmap,
  creates a non-owning device-visible allocation view, and keeps the original
  resident weight map allocation-free. gfx1151 retains its qualified CPU-copy
  Q8_0 route and explicitly does not inherit this mapped path.
- All pointer-fed embedding consumers, including whole-step graphs, now receive
  the mapped owner instead of transactionally rehydrating VRAM. The decode graph
  identity includes the mapped address. Close clears graphs first, unregisters
  the host range exactly once, then releases the reader/mmap.
- Extended benchmark metadata with mapped-host ownership and full graph transport
  provenance. This records stable graph keys, transport, replay counts, native
  fallbacks, generation/child state, and PM4 retirement rather than inferring
  the selected transport.
- Added a narrow package policy for `Qwen3.6-27B/MOSTLY_Q4_K_M`: PM4 only for
  physical rows=1 and replay horizons >=128. Horizons <128 and all wider rows
  remain HIP graph until measured.
- Published
  `benchmarks/results/2026-08-12-qwen36-27b-xtx-mapped-host-embedding.json` and
  updated the campaign scorecard, kernel catalog, benchmark rollup, and
  changelog.
