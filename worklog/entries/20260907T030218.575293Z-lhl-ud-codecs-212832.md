# Add independent UD codec fixtures and IQ3_S IQ2_S CPU decoders

## Summary

The new user objective prioritizes published UD end-to-end inference over
further certificate cleanup. The first missing arithmetic prerequisite is now
implemented: CPU IQ3_S and IQ2_S decode, checked against independent C output.
This does not add dense GPU consumers or claim published-model generation.

## Changes

- Add a fixture generator that compiles an exact Git archive of
  llama.cpp@17252c769a63c1cb650ce98ae309cf4de0da7778. The earlier campaign pin
  4d9176092d00586775af140581bb0b558ddc4389 is unavailable in the local clone.
  No donor checkout was changed and no prebuilt library was trusted.
- Port IQ3_S/IQ2_S CPU math from `ggml/src/ggml-quants.c` and the codebooks
  from `ggml/src/ggml-common.h`. Runtime codebooks are generated separately;
  the expected F32 values come from the donor's compiled decoder, not those
  generated runtime tables. Preserve the MIT license and source hashes.
- Committed synthetic fixture covers seven type ABIs, every IQ2_S/IQ3_S grid
  at nonzero scale, all sign bytes/high bits and subscale nibbles, finite fp16
  scale corners including signed zero/subnormal/max, and multiple row shapes.
  Tests compare F32 bit patterns, including signed zero. BF16/FP16 activation
  rounding and GPU accumulation are not covered by this codec contract.
- CPU decoder availability does not override dense route admission. The existing
  18/41 refusal regressions still pass. No registry, materializer, kernel,
  profile or default execution path changed.
