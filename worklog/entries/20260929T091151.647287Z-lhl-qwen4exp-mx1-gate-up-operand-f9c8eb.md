# MX-1 gate/up activation term: F16 operands 5.6-10.9x below the BF16 floor

## Summary

The MX-1 operand packet covered `expert_down` on real activations but only had
weight-decode coverage for `expert_gate_up` (Q4_K, 94 of the 144 expert
tensors), because no real gate/up input activation had been captured. **That gap
is now closed.** A second natural-input capture of the MoE block input that both
gate and up read shows the F16-operand SwiGLU result differing from the exact
F32 result by **5.6x to 10.9x less than the BF16 rounding the path already
applies**, on every measured Q4_K layer, with no F16 overflow.

Both halves of the expert pair now have real-activation operand evidence, so
MX-1's first experiment is complete. No runtime, kernel or default changed.

## Changes

- `scripts/qwen4exp_q4k_gate_up_input_capture.py`: hooks the Q4_K gate/up parent
  (`gguf_q4_k_selected_dual_wmma_iu8_risk_prefill_bf16_bf16_out`) on a live
  prefill and snapshots the MoE block input plus the compact expert starts.
- `scripts/qwen4exp_mx1_f16_operand_packet.py`: adds Part C, the gate/up SwiGLU
  comparison on that capture.
- `benchmarks/results/2026-09-29-qwen4exp-mx1-f16-operand/`: packet, artifact
  and README updated with Part C.

## Result

Capture: `general_en-p4096`, 10,240 rows, K=2560, 512 experts, BF16 bits
(decoded and asserted exactly). Comparison is on `silu(gate) * up`, the tensor
the down projection consumes, not the two raw outputs.

| Quant | Layers | Candidate RMS | BF16 floor RMS | Ratio |
| --- | ---: | ---: | ---: | ---: |
| Q4_K | 13 | 1.00e-5 to 1.41e-5 | 5.62e-5 to 8.60e-5 | 0.092 to 0.179 |

Worst ratio 0.179. Activation magnitude peaks at 7.438 against the F16 maximum
65504: no overflow, finite everywhere.

Combined with the earlier parts, MX-1's operand budget is now:

| Part | Coverage | Worst candidate/floor ratio |
| --- | --- | ---: |
| A | all 144 expert tensors, 4 quants, weight decode | F16 limit (max rel 4.88e-4), no overflow |
| B | all 48 `expert_down` layers, real activations | 0.125 |
| C | 13 `expert_gate_up` layers, real activations | 0.179 |

## Validation

- The capture is from the production grouped MoE route on a canonical
  natural-input case; its BF16 decode is asserted, not assumed.
- Both arms use the same accumulation, so the difference isolates the operand
  representation.
- Part C covers 13 of the 48 gate/up layers, all Q4_K. The two Q5_K gate/up
  tensors are covered by Part A's weight decode only.
- No GPU kernel changed, so no profiler trace applies.
