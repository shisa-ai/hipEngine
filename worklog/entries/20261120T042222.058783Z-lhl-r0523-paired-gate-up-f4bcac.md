# Reuse compact Q4 gate/up weights across pairs at width four

## Summary

Two independent two-row tiles reuse decoded weights without restoring the four-row accumulator implicated in R0523. The change applies only to four-row compact Q4 gate/up launches on gfx1100.

## Changes

- Use the existing two-row specialization twice in one launch. Other widths and the BF16 arithmetic are unchanged.

## Validation

- Eight focused GPU tests passed, including bit comparisons against the independent pack8 implementation at widths 2–8.
- On `epyc` / W7900, Qwen3.8-27B-Q4_K_M, median four-request aggregate HTTP throughput rose from 45.59 to 54.32 output tokens/s (+19.16%) on the matched 512-input/128-output strict burst. Both runs matched the single-request oracle on all 120 measured outputs. The duplicate-prompt stress intentionally fails the harness's distinct-oracle cardinality check; it is not a qualifying packet.
- A separate live producer probe checked at least 245,760 four-row launches with identical inputs and found no unequal intermediate BF16 rows. The uninstrumented distinct-prompt run under the default graph policy passed the full harness with native packed decode and 120/120 exact measured outputs. Commands and metrics: `benchmarks/results/2026-11-20-w7900-r0523-pair2.json`.
