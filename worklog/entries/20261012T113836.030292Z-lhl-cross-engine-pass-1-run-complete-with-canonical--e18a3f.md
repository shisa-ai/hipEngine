# Cross-engine pass-1 run complete with canonical rates and gate scores

## Summary

Pass 1 of the cross-engine comparison campaign executed end-to-end on the
idle gfx1151 host: canonical 12-case exact-token protocol for hipEngine
production, halo-box master, and gufo v0.12.0 on the same four-shard
UD-Q4_K_XL, plus the 18-prompt quality battery and the G0-G4 score against
the strict teacher. Results in
`benchmarks/results/2026-10-12-qwen4exp-cross-engine-pass1/`.

## Decisions and findings

- The host had rebooted out of its power profile (tuned inactive,
  governor `powersave`); restored `accelerator-performance` +
  `performance` before measuring and verified after every block. Kernel is
  now `7.2.9-2-cachyos` (prior records: `7.1.6`).
- gufo v0.12.0's RAM continuation cache serves identical prompt re-requests
  from memory (`prefill_tokens=0`), and its completions endpoint has no
  per-request `cache_prompt`. The cold-prompt protocol therefore runs gufo
  with `--cache-ram-bytes 1`; verified cache=miss/cache_n=0 on repeats. The
  harness `cache_n=0` guard remains as enforcement.
- halo-box master requires `-fa on`; a bare `-fa` is a usage error.
- The hipEngine leg needed one unmeasured prebuild pass (`qwen4_exp_gr`
  cache key changed with the K320 promotion) before the
  `--require-cached-build` measured block.
- Harness fixes found by the run, all committed with this unit: the bench's
  health wait now detects a dead server instead of burning the startup
  timeout; the comparator's server runners pass `--host/--port` to the
  server (they previously listened on defaults while the client waited
  elsewhere); llama.cpp probs parsing accepts the current
  `completion_probabilities[].top_logprobs` schema; the truncated-KL
  computation now floors absent tokens at epsilon instead of exp(0) - the
  old behavior exploded G2 whenever two top-20 lists genuinely differed
  (halo-box's mean KL dropped from an artifactual 5.48 to 0.24 after the
  fix; production's 0.0052 is the correct same-teacher distance).
