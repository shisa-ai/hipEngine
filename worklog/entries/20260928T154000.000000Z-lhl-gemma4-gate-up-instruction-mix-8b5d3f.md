# the gate/up kernel's mix is 0.8, not 6.3: the two expert kernels do not share a cause

## Summary

The Q5_1 down projection spends 30 percent of its instructions in `expand_hi_bits`,
scattering Q5_1's fifth bit back into position -- 404 bit-manipulation instructions
against 64 dp4a, a ratio of **6.3**. If the Q4_K gate/up kernel had a similar ratio, the
49 GB/s both kernels land on would have one explanation.

**It does not.** The production gate/up symbol is
`hipengine_gguf_q4_k_selected_dual_q8_1_ds4_mmq32_fused_prefill_compact32_bf16_bf16_out`,
which compiles to **1,630 instructions with 192 dp4a and 154 bit-manipulation, a ratio
of 0.8.** The hypothesis is refuted, and the file's other gate/up variants bracket it:

| kernel | instrs | dp4a | bit-manip | ratio |
| --- | ---: | ---: | ---: | ---: |
| `..._ds4_mmq32_fused_prefill_compact32_` (**production**) | 1,630 | 192 | 154 | **0.8** |
| `..._ds4_mmq32_prefill_compact32_` | 910 | 64 | 74 | 1.2 |
| `..._t16_..._ds4_mmq32_...` | 1,611 | 192 | 149 | 0.8 |
| `..._t16_..._ds4_f32_mmq...` | 2,604 | 264 | 129 | 0.5 |
| `..._ds4_wmma32_prefill...` | 2,395 | 0 | 254 | -- (WMMA, no dp4a) |
| **Q5_1 down (for comparison)** | **897** | **64** | **404** | **6.3** |

**The down projection is the outlier, not the shared pattern.**

## What the refutation buys

**The two kernels have instruction mixes eight times apart and land on the same 49 GB/s.**
That is a stronger statement about where the constraint lives than the shared-cause
hypothesis would have been: if the mix does not set the rate, the rate is set downstream
of the instruction stream, in the memory system or the activation load path. A kernel
that issues six bit-manipulation instructions per dot product and a kernel that issues
0.8 reach the same weight throughput, so neither is instruction-bound at this rate.

It also means **the `expand_hi_bits` finding is a down-projection finding, not an expert
block finding.** Its 30 percent share is real and it is specific to Q5_1's layout; it
does not generalise to the kernel that costs 156.5 ms, and the layout-change candidate
should be scoped to the down projection alone.

**And the file already contains five registered gate/up routes** -- the production
`fused` compact32, an unfused compact32, an x8 variant, a t16 variant, and a WMMA
variant -- which is the fused/strict-unfused pairing the architecture requires. Their
mixes differ substantially (dp4a counts of 64, 192, 264 and 0), so the route choice
already selects among materially different instruction mixes; which one is fastest at
512 rows has not been measured this unit.

## Next

- **The shared 49 GB/s is a memory-system property, and the activation load path is now
  the leading candidate** because it is the one thing the two kernels genuinely share.
  Each thread reads its rows' activations from a working set that fits in L1 while the
  weight stream comes from L2 or DRAM; if the activation reads are issued serially
  behind the weight unpack the kernel stalls with the DRAM bus idle, which is what a
  19-percent-of-peak weight rate with an unsaturated arithmetic unit looks like.
- **Which gate/up route is fastest at 512 rows is unmeasured and cheap to measure.**
  Five routes with dp4a counts of 64, 192, 264 and 0 are registered; `--tile` or route
  selection already exists in the harnesses. That is a same-shape comparison with no
  code change, unlike everything else left on this list.
- **Scope the layout-change candidate to the down projection.** Its justification is
  `expand_hi_bits`, which the gate/up kernel does not have.
