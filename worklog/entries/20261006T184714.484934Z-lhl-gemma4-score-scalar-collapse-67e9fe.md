# Collapse score-kernel scalar overhead with exact-row variants

## Summary

PMC counters on the staged score kernel (3-pass rocprofv3 at 8192, zbook/Radeon
8060S) showed it was not stalled on LDS, occupancy or registers — it was
issuing SCALAR instructions at 2.4x its VALU count and branches at 0.5x VALU.
The 2026-10-05 correction was right that Q is already staged; the wall was the
control flow around the tree, not data movement. Per (row, key) the unrolled
8-row loop re-emitted `r >= resident` predicates, a `keep` branch and a
`lane == 0` store predicate per row, plus int64 address multiply-adds per row
per key, plus a runtime `head_dim == 512` tree ternary per logit.

This unit collapses that overhead while keeping the strict warp-key tree,
softmax and ascending-key P*V chains untouched: the score kernel is now
templated on `(kLeaves, kResidentRows, kExactRows)` mirroring the PV launcher's
exact-variant dispatch (ratios 1/2/4/8 compile the row count in and make the
per-key row predicate dead), one `keep` branch per key covers all resident
rows, per-row workspace and Q-tile pointers are hoisted out of the key loop,
and the key loop runs in 32-bit arithmetic (key indices fit an int by the
existing static_assert). The masked path keeps the NaN-exact
`fmaxf(running_max, -INFINITY)` so a NaN logit behaves exactly as before.

Measured: score-kernel SALU 1.187e12 -> 2.97e11 (-75%), branches 2.926e11 ->
7.05e10 (-76%), SQ_CYCLES 4.109e11 -> 2.747e11 (-33%) at 8192. Profiled
prefill at 8192 moved 575/564 -> 628/623 tok/s. Production route at 32768
(context 33024, one warmup, one sample): prefill 326.17 -> 351.18 tok/s
(+7.7%), decode 21.25 -> 21.61 tok/s, public-path parity True. The metric is
the beat-llamacpp-all-depths loop's verify artifact.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_attention_staged.hip`: score
  kernel templated on `(kLeaves, kResidentRows, kExactRows)`; new
  `launch_gemma4_attention_staged_score_variant` and
  `launch_gemma4_attention_staged_score` dispatch helpers ahead of
  `launch_gemma4_attention_staged` (head_dim picks kLeaves 16/8; the PV
  resident-rows table picks the exact/generic variant). No change to the
  workspace layout, softmax, PV kernels, or the C ABI exports.
