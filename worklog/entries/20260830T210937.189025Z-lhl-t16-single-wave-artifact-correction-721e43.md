# correct the single-wave shape artifact's merged measurement table

## Summary

This supersedes the measurement table in
`worklog/entries/20260830T210732.962111Z-lhl-t16-single-wave-shapes-0f9201.md` (that entry stays immutable).
The promotion it recorded is correct and stays in the tree. Its **artifact table was not one protocol**: I
merged rows from the 15-rep `--all-shapes` sweep with rows from two 20-rep single-shape pin-down runs into a
single per-shape map without labelling the source, and the unlabelled merge happened to flatter the weakest
edge of the claim. Re-reading the committed artifact against the source JSONs found three mismatched cells.
The material one: `(5120,12288)` at rows 128 measured **0.970** in the sweep and **1.022** in the pin-down, so
that shape's band edge straddles parity and is noise-bounded, not the clean 1.02x the table implied.

## Changes

- `benchmarks/results/2026-08-30-w7900-q4km-t16-single-wave-shapes-accepted.json`: `single_wave_ratio_vs_shared_b`
  now holds per-run measurements keyed by run name (`sweep_15rep_all_shapes`, `pindown_20rep_5120x12288`,
  `pindown_20rep_5120x10240`), rebuilt programmatically from the sweep JSON rather than typed. Added

- One `benchmarks/CHANGELOG.md` correction: `1.02x-1.28x at rows 2-128` becomes `1.10x-1.28x through rows
  112`, the `(5120,10240)` row-128 digit becomes the sweep value `1.08x`, and the `(5120,12288)` row-128 noise
  is stated in place instead of being quoted as a win.
- No code change. `GGUF_Q4_T16_PHYSICAL_SINGLE_WAVE_SHAPES` and
  `GGUF_Q4_T16_PHYSICAL_SINGLE_WAVE_MAX_ROWS = 128` are left as shipped, for the reason in Validation.

## Validation

Regenerated from the files, not from memory: `shapes.json` (15 reps), `12288.json` and `10240.json` (20 reps),
all on `4f6fb3041`. Points spanning over 3% between runs: `(5120,12288)` rows 67 (1.106 / 1.075, wins in both)
and rows 128 (0.970 / 1.022, straddles parity). `(5120,10240)` rows 128 differs by 2.7% (1.083 / 1.110) and
wins in both. ULP 0 and finite outputs held at every point in every run, so the promoted arithmetic is
unaffected; only the size of the row-128 effect for one shape was overstated.

Why the band stays at 128: narrowing `(5120,12288)` to 112 on the strength of one of two disagreeing runs
would be fitting the declared band to a single measurement, which is the failure mode this campaign keeps
auditing for. The worst case of leaving it is a sub-3% kernel delta at exactly row 128 on one shape, inside
the measurement's own spread; the strongest supported region for all three shapes is rows 2-112.
