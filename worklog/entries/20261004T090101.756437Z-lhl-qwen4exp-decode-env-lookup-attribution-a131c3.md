# The decode step's non-kernel remainder is 14,293 environment lookups per step

## Summary

`DE-11` in `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md` prices the decode step's
non-kernel remainder at **1.47 ms/step at p512 and 10.56 ms/step at p4096** and
names its action as attributing that remainder from the bench's own loop. This
is that attribution, and it names one dominant cause.

**A decode step makes 14,293 `os.environ` lookups.** Every one goes through four
Python frames - `collections.abc.get` -> `os.__getitem__` -> `os.encode` ->
`str.encode` - and the block is **24.8% of the loop's profiled host time**. With
`str.strip` at 19,973/step (2.6%), `os.decode` at 5,340/step, and
`_resolution_environment_identity` (2.6%) plus `build_hip` (1.9%) on top,
**about a third of the profiled host time is environment-variable handling.**

Caller attribution for the lookups:

| caller | lookups/step | share of all |
| --- | ---: | ---: |
| `_resolution_environment_identity` (`core/build.py:486`) | **7,656** | **53.6%** |
| `launch_gguf_linear` (`runtime/gguf_linear.py`) | 1,090 | 7.6% |
| `_q8_dense_wide_enabled` | 545 | 3.8% |
| `_q8_dense_wide_layers` | 545 | 3.8% |
| `_env_wmma_prefill_enabled` | 545 | 3.8% |
| remainder (below the top-5 cutoff) | ~3,912 | 27.4% |

**`build_hip` is called 957 times per decode step** - once per kernel launch -
and each call re-derives its resolution identity from **eight** environment
variables. Micro-benchmarked on this host, an 8-key identity costs **2.281 us**
via `os.environ.get(str)` (1.800 us via `os.environb.get(bytes)`, 0.116 us as
plain dict lookups), so that term alone is **2.18 ms/step** and the whole
memoized call is 2.60 us = **2.49 ms/step**. This is the residue the earlier
memo unit (`20261004T083532`) left behind: it removed the key *derivation* but
kept the environment *read*, which is now the largest single host cost.

**`_q8_dense_wide_layers` is called 545 times per step and re-parsed its variable
on every call** - `raw.split(",")` plus a `part.strip()` and an `int(part)` per
entry. The production scope names 32 layers, so that is **~17,000 `str.strip`
calls and ~17,000 `int()` calls per step** for a value that cannot have changed,
and it is where the measured 19,973 strips/step come from. Its 5.5% tottime plus
most of the strip share makes it the second-largest host cost in the step.

**Three fixes follow and are cheap and exact:** memoize the layer-scope parse on
the raw string (one shared parser for the three scopes), memoize the boolean env
flags and the two raw values that go into the launch cache key, and either
eliminate the per-launch `build_X(load=True)` call or make its identity read
cheaper. The first two are implemented in the companion unit; the third is the
larger architectural change and is recorded in `docs/REFACTOR.md`.

## Changes

- `scripts/qwen4exp_canonical_ar_bench.py`: `_hipengine_host_profile` entries
  now carry their **top five callers** (function, file, line, ncalls, tottime).
  The caller attribution is what turned a list of expensive functions into a
  list of call sites; without it `os.__getitem__` at 9.5% names no owner.
- `benchmarks/results/2026-10-04-qwen4exp-decode-host-profile/`: three artifacts
  (`code-p4096-callers.json` authoritative, `code-p4096.json`, `code-p512.json`)
  and a README carrying the tables, the instrument, and the limits.
- No engine change in this unit.

## Validation

Hardware: AMD Radeon 8060S / `gfx1151` (Strix Halo Framework host), machine-id
`55ea6c509d0b49eea8de7094a1023668`, ROCm 7.15.26333,
`HIPENGINE_HIP_ARCH=gfx1151`. Model: Qwen3.8-Flash-Next
`unsloth-...-UD-Q4_K_XL`, production profile, BF16 KV, greedy AR, chunk 1024,
warm PLE, one case per process.

- Command: `uv run python scripts/qwen4exp_canonical_ar_bench.py hipengine
  --model-root <UD-Q4_K_XL> --case-id code-p4096 --prefill-chunk-size 1024
  --execution-profile production --ple-cache-mode warm --warmups 1
  --repetitions 1 --host-profile --compiler-version-file
  /tmp/hipengine-hipcc-version.txt --require-cached-build --output <out>.json`.
- Measured 56.398 ms/step, profiled pass 61.331 ms/step over 128 steps, so the
  profiler inflates by 8.7%. Read the call counts and the caller attribution as
  exact and the shares as indicative.
- Micro-benchmark, `timeit` over 200,000 iterations of the 8-key identity:
  `os.environ.get(str)` **2.281 us**, `os.environb.get(bytes)` 1.800 us, plain
  dict 0.116 us.
- `uv run pytest tests/test_unit_qwen4exp_canonical_ar_bench.py`: 17 passed
  (the caller-attribution change is covered by the existing profiler test, which
  asserts the entry shape).

## Next

- Eliminate the per-launch `build_X(load=True)` call - 957 calls/step, 2.49
  ms/step - by resolving the library once per launch site rather than per
  launch. That is the single largest remaining host lever and it is recorded in
  `docs/REFACTOR.md`.
- The `os.decode` 5,340/step and `_contextvars.ContextVar.get` 5,995/step
  entries are not yet attributed; `ContextVar.get` at ~6,000/step in a
  single-threaded decode loop is worth a look.
- `dense_gemv_out_f32` is 168 Python calls/step at 4.9% tottime; that is a
  call-count problem in a dispatch wrapper, not a kernel problem.
