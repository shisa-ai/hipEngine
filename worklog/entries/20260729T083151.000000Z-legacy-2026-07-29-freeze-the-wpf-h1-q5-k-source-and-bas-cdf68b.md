## Changes

No external tree is modified.
- Freeze llama.cpp HIP `c0bc8591e8815c63cb01dd3f051a8b0df02501c9` as the implementation source. The extracted source hashes are `mmq.cu` `4e471565...b7a8`, `mmq.cuh` `d260abb4...1407`, `mmq-config-rdna4.cuh` `7273c222...05f3`, `quantize.cu` `de1a9a73...4ef5`, `mmq-load-tiles.cuh` `6ceb698e...a19`, `mmq-vec-dot.cuh` `e118f96f...34f5`, and `mma.cuh` `c7e0f333...d1af`. The first four agree with the already published comparator manifest; the latter three close the device-body source map needed for a literal port.
- The source contract is not the rejected D4/D8/D8R8 MMQ32 design. `quantize_mmq_q8_1<DS4>` stores one K-major 144-byte record per `(K128, row)`: four FP16 `(scale, pre-quantization sum)` pairs followed by 128 signed bytes. Q5_K weight loading expands each raw 176-byte K256 block to unsigned 5-bit bytes and FP16 `(d*scale, -dmin*min)` pairs. The consumer uses local `(32,8)=256`, I128/J128/K256, 57,856 bytes of dynamic LDS, eight RDNA3 integer-WMMA waves, and separate dot and affine-min accumulation terms. The current trace selects J128 at VGPR232/248 and scratch0; N48/N72 use the source fallback specialization while every wider production N is I128-aligned.
- Freeze hipEngine's primitive ABI as BF16 row-major input `[M,K]`, a caller-owned K-major DS4 workspace `[K/128,M]`, raw output-major Q5_K GGUF bytes `[N,K/256*176]`, and row-major BF16 or F32 output `[M,N]`. Device bodies take only raw pointers. The BF16 boundary is converted to F32 for source-faithful scale/sum/rounding arithmetic; this remains an unavoidable engine-boundary difference from llama.cpp's F32 graph. No weight sidecar is permitted. The largest actual M512 Q5 input, K9216, needs a bounded **5,308,416-byte** DS4 workspace, reusable across all projections and recoverable at teardown.
- Freeze the actual-shape leaf at all eight disjoint Q5 configurations and **235** M512 invocations: BF16-out `(K,N)` 3072x1024 (92), 3072x12288 (2), 6144x3072 (12), and 9216x3072 (35); F32-out 3072x48 (12), 3072x72 (35), 3072x6144 (12), and 3072x9216 (35). The matched retained trace is **1,274.342 ms** for those 235 hipEngine bodies versus **58.951 ms** for exactly 235 llama.cpp Q5 MMQs, a **21.617x** body ratio. The direct-M512 request remains **169.228 tok/s** versus **694.184 tok/s**; the current exact role-qualified coltile remains the registered fallback.
- RED/GREEN is frozen before device implementation: (1) a CPU DS4 producer oracle checks K-major bytes, FP16 metadata, round-away quantization, zero groups, and 127/128/129 row tails; (2) Q5 BF16/F32 outputs are compared with the CPU-reference/raw exact path on aligned and N-tail fixtures, requiring finite outputs, KL <=0.05, and top-1 >=90%; (3) registry/build/backend-scope tests require separately named gfx1100-only producer and consumer keys with gfx1151 fail-closed; (4) a cached-only `rocprofv3` run must name the producer and the 256-thread I128/J128/K256 consumer with plausible resources/durations; and (5) the all-eight-role M512 leaf measures inclusive producer+consumer cost and allocation recovery before runtime integration. Any production promotion additionally requires the complete 18-prompt/576-step train+heldout and category-heldout quality lanes, counter-ordered 512/1K timing, deterministic state/lifecycle, and a clean reprofile. The fixed M512 stream cannot waive quality.
