# W7900: GEMV decode preference is inert on the dense GGUF path - neutral arm explained by the MoE-only safety gate

## Summary

Task #14's first hypothesis is measured and rejected, and the neutrality is explained by source
rather than left as a puzzle. Turning the GEMV decode preference off changes nothing: **C1 22.170 vs
22.250 tok/s (0.996x) and C2 31.087 vs 31.290 (0.993x)**, medians of 10 prompts each, same driver.
`use_gemv_decode` is not a dense-path route knob at all - `qwen35_gguf_runner.py:13292` feeds it into
`Qwen35GGUFFastPathSafety(requested_gemv_decode=...)`, whose only two consumers (`disabled_wmma`,
`disabled_gemv`) are gated on `is_qwen35moe`. On this dense model the flag changes one field of a
safety record. Artifact
`benchmarks/results/2026-08-30-w7900-q4km-gemv-decode-preference-arm.json`.

## Changes

Artifact above, plus a `docs/REFACTOR.md` extension to today's route-boolean section recording that
the GEMV decode half is inert at the consumer, not merely by pooling, so the 11 literal
`use_gemv_decode=True` sites are dead weight on the dense path. No engine code changed; the flip was
applied in memory by a /tmp driver and those packets stay diagnostic.

## Validation

The control is what makes "neutral" meaningful here rather than another vacuous arm. The resolver
logged exactly 3 calls, all `incoming=True -> resolved=False`: the decision is made **per session at
construction, not per step**, so 3 log lines is the complete evidence that the flip applied. Both arms
ran through the same driver, which installs the wrapper in the baseline arm too, so the monkeypatch is
not a variable. Baseline reproduces the earlier direct-bench run within 0.7-0.8% (22.409/31.537 vs
22.250/31.290).

Two instrument constraints shaped the method and are worth repeating: the bench refuses to run against
a dirty worktree (`gguf_mtp_c1c8_server_bench.py:651`), which rules out scratch edits for this tool
(the prefill GEMV arm was measured with one because the first-token probe lacks that guard); and the
resolver precedence is explicit kwarg > session > env with 11 sites passing `True`, so no environment
variable can reach this route. Patching `gguf_linear.gguf_gemv_decode_enabled` alone is also not
enough - the runner imports the name directly, so its namespace must be patched too.
