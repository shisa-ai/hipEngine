# Implement cooperative raw Q5 staging candidate

## Summary

ED-1's raw-byte staging prototypes lose the initial real-weight/synthetic-routing
screen. Main-kernel median is 9.147 ms for j16, 18.312 ms for staged j32
(+100.20%), and 28.919 ms for staged j16 (+216.17%). Both staged paths preserve
output bits and risk sets. Archive the complete prototype patch, rather than
keeping slower default-off runtime paths. ED-1 real-population qualification
remains open; this is not a blanket rejection of staging.

## Changes

- `qwen4_exp_q5_1.hip`: optional STAGE_WEIGHTS template parameter, raw
  128-column x8-subblock x24-byte shared weight tile, coalesced uint32 loads,
  reuse for both row groups. Existing arithmetic and repair unchanged.
- Built j16/j32 staged exports, Python wrappers and explicit registry keys;
  no runtime dispatch/default changed. All prototype code, test and screen
  are archived in `benchmarks/results/2026-09-29-qwen4exp-ed1-lds-screen/candidate.patch`
  and removed from the active source tree after the negative screen.
- GPU test compares raw outputs and sorted risk sets against j16 and j32,
  repeating staged j32 launches, empty experts/ragged rows/K and N tails.
