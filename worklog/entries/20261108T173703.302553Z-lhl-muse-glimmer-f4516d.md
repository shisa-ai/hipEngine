# Muse Glimmer draft head uses single-wave Q5 rowtile: -39% head, acceptance-neutral

## Summary

Task #3 (§11 #3) draft-head lever. The DFlash drafter's shared lm_head (Q5_K,
202,048 vocab) ran through launch_gguf_linear_exact_rows -> the parent-parity
four-wave Q5 rowtile (~7.2 ms/cycle at block rows). The draft head only proposes
tokens; it owes no bit-exactness to the target decode (verify stays exact, so
DFlash IDs == true AR regardless of draft numerics; campaign P3's binding draft
gate is acceptance + exact ID equality, not draft logit parity). A faster
single-wave Q5 rowtile already existed as a registered production-profile
variant (one wave32 owns 8 columns over the whole K, subblock scale/min decode
hoisted, no cross-wave exchange; documented 670-888 GB/s vs the four-wave's
406-704). Registered it for gfx1151 (was gfx1100-only) and routed the draft head
to it via a capability-driven registry resolve, guarded to its rows 2..8 shape,
with the exact_rows owner as the fallback for other row counts / quants.

Measured: draft head kernel 7.18 -> 4.37 ms/cycle (-39%, rocprof, context-
independent weight GEMV); draft_block 24.8 -> 21.9 ms. Full mtpbench suite at
budget 4 back-to-back A/B: acceptance IDENTICAL (0.4272 both arms, 1232/2884 --
the reassociation flipped zero proposal argmaxes), DFlash IDs == AR both arms,
decode 21.79 -> 22.41 tok/s (+2.8%). Long-context back-to-back A/B (single-wave
vs four-wave on the same resident KV, controls laptop thermal drift): 32K
204.9 -> 197.0 ms/cycle (-7.9), 126K 241.5 -> 234.5 (-7.0), acceptance identical
(0.556 / 0.512), exact both. Absolute cycle times are thermally inflated this
session (~200 ms vs ~141 earlier); the attributable head-kernel saving is the
rocprof -2.81 ms, and the A/B confirms a non-regressive cycle win.

The draft ATTENTION lever (§11 #3's other half, ~9.2 ms/cycle on the strict
scalar Gemma4 block kernel) is NOT done here: the drafter attention is
non-causal windowed (block rows attend bidirectionally), and every available
flash route is causal-only and/or head_dim-256-only (AOTriton admission also
requires keys<=window), so it needs a new non-causal WMMA block-flash kernel --
a separate kernel unit, documented as follow-up.
