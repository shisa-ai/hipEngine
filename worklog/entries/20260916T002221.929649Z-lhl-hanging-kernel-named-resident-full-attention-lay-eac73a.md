# Hanging kernel named: resident full-attention layer 3 decode never completes

## Summary

The per-primitive HIP event probe
(`scripts/tp2_resident_decode_event_probe.py`) bracketed every
`_run_linear_attention_layer` / `_run_full_attention_layer` call with an
event pair and queried all events while the resident sequential prefill was
blocked. Verdict: layers 0, 1, 2 (linear/GDN) **started and completed**;
**layer 3 — the first full-attention layer (`full_attention_interval = 4`) —
started but never completed**, and nothing after it ran. The livelocked
kernel is inside `_run_full_attention_layer`'s decode route on gfx1100.

This matches the bulk-prefill NaN signature (entry ee20cd): layer 3, the
first full-attention layer, is where both the eager decode (livelock) and
the bulk prefill (NaN logits) break on this lane — two symptoms, same layer
type, same resident-route owner. The tp2 harness's
`_run_full_attention_attn_only` leaf runs clean on this host, so the defect
is inside `_run_full_attention_layer`'s decode dispatch (paged-KV decode
append/gate/route kernels), not the attention math itself.

## Changes

- `scripts/tp2_resident_decode_event_probe.py`: monkeypatched per-primitive
  event pairs + main-thread event query while prefill runs in a worker
  thread (self-dumping faulthandler retained). 512 layer events, all
  queried. No engine edits.

## Validation

- Probe output (bg log /tmp/resident_probe.log): `linear_attention_layer:0..2
  started=True completed=True`, `full_attention_layer:3 started=True
  completed=False`, `linear_attention_layer:4.. started=False` (never
  reached). Consistent with all four stall repros (GPU ~94-100%, host blocked
  at the first sample readback).
