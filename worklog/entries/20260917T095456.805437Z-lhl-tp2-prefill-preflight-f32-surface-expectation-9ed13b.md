# Repair the stale batched-route preflight expectation left by the f32 down-partial surface row

## Summary

`tests/test_unit_tp2_prefill_shard.py::test_batched_route_preflight_blocks_an_unsupported_dtype_route`
had been failing since `0e4966906` (the f32 down-partial unit), in that commit's
own tree and every tree after it. It asserted that a Q4_K t16 shard with
`partial_dtype="f32"` has no batched route and that `_require_batched_route(4)`
therefore raises `MlpShardRankError`. `0e4966906` added exactly the surface row
that test's premise denied:

```
_row(LAYOUT_GGUF_Q4_K_T16, GGUF_ACTIVATION_BF16, GGUF_OUTPUT_F32,
     "linear", "gguf_q4_k_t16_v1", "dense_single_local32_bf16_f32_out", "t16")
```

so `resolve_gguf_linear_dispatch(..., output_dtype="f32", rows=4)` now resolves
`t16_wmma_prefill_bf16_f32_out` and the preflight correctly does not raise. The
guard itself was never broken - only the expectation. Verified pre-existing by
running the node in a clean `git worktree` at `d70e655a0`, where it fails
identically.

## Changes

`tests/test_unit_tp2_prefill_shard.py`:

- New `test_batched_route_preflight_admits_the_f32_down_partial_route`: the
  Q4_K t16 f32 rows=4 case must **not** raise, with the surface row and the
  commit that added it named, so the admitted case and the refusal read as one
  contract and the Q4_K assertion is not "restored" later by mistake.
- `test_batched_route_preflight_blocks_an_unsupported_dtype_route` now uses
  `gguf_q5_k_t16_v1`, which still has no f32-output surface row
  (`resolve_gguf_linear_dispatch` raises `ValueError: unsupported GGUF linear
  dispatch: layout='gguf_q5_k_t16_v1', activation='bf16', output='f32'`), so the
  refusal path keeps its coverage.

## Validation

```
python3 -m pytest tests/test_unit_tp2_prefill_shard.py -q   # 13 passed
```

No production code changed; this is a test-expectation repair for a defect the
f32 down-partial unit introduced in its own commit.
