# the prefill selection served decode, the gate caught it, and the KL gate now passes

## Summary

`select_prefill_attention` matched a prefill candidate on head geometry alone,
so a one-token decode step ran a kernel tiled 16 query rows wide on all 30
layers and never reached the decode kernel the strict path routes to. Decode
lost 10.3 percent. `scripts/gemma4_teacher_forced_gate.py` found it, because its
route check asserts on observed launcher selections rather than on the requested
policy. The selector now takes the block width and a block of one keeps the
strict kernel; the `docs/EXECUTION-PROFILES.md` section 6 KL gate then passes
with 29x to 458x margin and the max KL falls 8x, from 1.389e-02 to 1.740e-03.


Corrects `worklog/entries/20260928T203205.309813Z-lhl-gemma4-full-layer-prefill-attention-wmma-ecc8b4.md`,
whose kernel work stands but whose routing was wrong and whose "gate not run"
note is now resolved.

## Changes

### The defect

`select_prefill_attention` matched a candidate on head geometry alone, and
`gemma4_layer.py` asked it for **every** block. So a one-token decode step was
served by a kernel whose tiling is 16 query rows wide: 15 of every 16 WMMA ops
wasted, and the decode kernel that `gemma4_attention_prefill_bf16` routes to at
`tokens == 1` never reached at all.

Measured on a single decode step, by patching every launcher the profile can
select:

```
BEFORE  {('gemma4_attention_prefill_wmma_bf16',      1, 256): 25,
         ('gemma4_attention_prefill_wmma_full_bf16', 1, 512):  5,
         ('_launch_prefill',                         1, ...):  0}
AFTER   {('_launch_prefill', 1, ...): 30}
```

and on a 100-token prefill: 25 sliding + 5 full WMMA, 0 strict. So the split is
clean in both directions, which is the property that was missing.

Cost while it was broken, 512-token prompt, same run:

| | strict | production |
| --- | ---: | ---: |
| decode tok/s | 28.23 | **25.33** |

10.3 percent off decode, for a change that was only meant to touch prefill.

### How it was found, and why that matters more than the fix

Not by a test. By `scripts/gemma4_teacher_forced_gate.py`, whose first run on
this candidate returned `failed: ["no_decode_launches_observed"]` with
`decode_launches: 0`. `require_candidate_route` asserts on **observed launcher
selections**, not on the requested slice policy, so it cannot be satisfied by a
policy that is merely written down. That is the whole reason it noticed.

This is the second time this unit's own routing blinded an instrument: the
census script patched attention on the layer module, which the variant selection
made dead. Both were found by a tool that measures what ran rather than what was
asked for. Recorded in `docs/REFACTOR.md` under the same lesson.

### The fix

`select_prefill_attention` and `_select_prefill_attention` take `tokens`; a block
of one or fewer returns the strict kernel with `reason` starting `decode:` rather
than a capability miss, so a log line distinguishes "refused, it is a decode
step" from "refused, wrong geometry". `None` means the caller asked about
geometry alone and keeps the old answer, which is what the selection tests want.
`gemma4_layer.py` passes `tokens=rows`.

### The gate now passes

`benchmarks/results/2026-09-29-gemma4-teacher-forced-gate-prefill-attention.json`.
Shipping path against a frozen strict baseline, campaign chain, 2048 prompt
tokens with 1024 prefilled, 1023 scored rows, vocab 262144:

| | measured | limit | margin |
| --- | ---: | ---: | ---: |
| mean KL | 4.679e-06 | 1e-3 | 214x |
| p95 KL | 1.091e-05 | 5e-3 | 458x |
| p99 KL | 5.206e-05 | 2e-2 | 384x |
| max KL | 1.740e-03 | 5e-2 | 29x |
| top-1 | 1.000, 0 flips | 0.99 | pass |

`passed: true`, `failed: []`, decode split observed on 30690 launches over keys
1024-2047. The pre-fix run of the same gate reported a max KL of 1.389e-02; the
8x reduction is the prefill tiling's arithmetic leaving the decode path, so the
gate was measuring the defect rather than the change.

`promotion_qualified` is still false and should be: this evaluator is a single
teacher-forced chain, so it supplies no category, isolation or task gates, and
1023 rows on one chain is not the 500-1000 *paired* row standard. That set is
tracked in `docs/campaigns/GEMMA4-26B-A4B-OPTIMIZATION.md`.
