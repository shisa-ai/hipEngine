# Extract OpenAI request schemas from the server API

## Summary

`hipengine/server/api.py` no longer defines the OpenAI request models. They now
live in `hipengine/server/schemas.py`, which depends only on Pydantic and
`typing`. `api.py` imports and re-exports the same class objects, so existing
imports and FastAPI route annotations are unchanged.

`hipengine/server/__init__.py` now exports `ServerConfig`, `create_app`, and
`render_chat_prompt` lazily through standard PEP 562 module `__getattr__`
attributes. A real `import hipengine.server.schemas` therefore stays schema-only
instead of pulling in `api` through the package initializer. The lazy exports
resolve to the same API-owned objects and are cached in package globals.

This is a move-only boundary unit under RF-7. No route, validation rule,
default, extra-field policy, response shape, arithmetic, flag, or scheduling
behavior changed.

## Changes

- `hipengine/server/schemas.py` (new)
  - Owns `_OpenAIBaseModel` plus `SongGenerationRequest`, `CompletionRequest`,
    `ChatMessage`, `ChatCompletionRequest`, `SessionForkRequest`,
    `SessionRollbackRequest`, `TokenizeRequest`, `DetokenizeRequest`,
    `TokenDiagnosticRequest`, and `FitContextRequest`.
  - Preserves the Pydantic v2 `ConfigDict(extra="allow")` / v1 `Config.extra`
    compatibility branch and every field annotation, order, default, and
    constraint.
- `hipengine/server/api.py`
  - Removed the moved definitions and the now-unused `pydantic` imports.
  - Imports the schemas module and deliberately re-exports every moved class,
    including the private `_OpenAIBaseModel`, from the existing import surface.
- `hipengine/server/__init__.py`
  - Replaced the eager `from hipengine.server.api import ...` with lazy
    `__getattr__` exports for the same three public names, preserving `__all__`,
    `dir()`, repeated-access identity, and `from hipengine.server import api`.
- `tests/test_unit_server_schema_boundary.py` (new)
  - Pins the schema module's Pydantic/stdlib-only dependency, standalone file
    import without `hipengine`/`api`/`torch`, compatibility identity, field
    order/required sets, JSON-schema shape and constraints, valid dumps with
    extra fields, per-request default lists, and exact validation error
    types/locations.
  - Adds subprocess checks for the real `import hipengine.server.schemas`
    contract and for the lazy server exports resolving to API-owned objects.
