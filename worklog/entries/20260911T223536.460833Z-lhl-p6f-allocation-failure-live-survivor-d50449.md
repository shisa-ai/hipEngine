# P6f gate 4: allocation-failure injection with a live survivor

## Summary

Task `#21` (P6f) lists six gates the resumable layer-outer prefill depends on:
layer-boundary state/KV validation on the actual executor, shifted/ragged
layouts, aliasing, allocation-failure injection with a live survivor,
suspended-owner accounting alongside decode scratch, and explicit unsupported
fallback peaks. This entry audits all six against existing coverage and closes
the one that is both genuinely uncovered and CPU-checkable: allocation-failure
injection with a live survivor.

Audit result, by gate:

| Gate | Existing coverage | Verdict |
| --- | --- | --- |
| Suspended owners alongside decode scratch | `test_suspended_owner_appears_in_prefill_transient_inventory`; `_GGUFResumablePrefillScratch` is counted in `prefill_transient_owner_inventory` | covered |
| Explicit unsupported fallback peaks | `test_qwen35_gguf_int8_kv_policy.py` pins `chunk_outer_layer_local_oracles` with `projected_peak_delta_bytes > 0` and `projected_peak_saving_bytes == 0`; the planner never budgets a request as layer-outer when that peak is higher | covered |
| Cancellation cleanup | `test_resumable_row_release_frees_suspended_buffers`, `test_layer_outer_cancellation_releases_and_survives` | covered |
| Shifted/ragged layouts | planner-level ragged CPU tests exist (`test_gguf_packed_ar_prefill_chunk_plan_preserves_fitting_ragged_slab`); the outstanding item is GPU coverage, which the CPU suite cannot supply | partial (GPU-gated) |
| Layer-boundary state/KV validation on the actual executor | the P6e GPU proof's `exact_continuation` gate compares the final token between arms; there is no direct per-boundary hidden/KV comparison | partial (GPU-gated) |
| Aliasing | `test_int8_layer_outer_hidden_alias.py` pins the alias gate; the alias interaction with the suspended save/restore is not exercised | partial (GPU-gated) |
| **Allocation-failure injection with a live survivor** | **none** — `_GGUFResumablePrefillScratch` had zero test references | **closed here** |

The three GPU-gated rows are not closable with CPU tests. They remain the
reason the layer-outer route is still default-off pending P6f.

## Changes

- `tests/test_gguf_resumable_layer_outer_prefill.py`: two new tests.
  - `test_scratch_allocation_failure_frees_the_partial_allocation` injects a
    failure into the third `malloc` of `_GGUFResumablePrefillScratch.allocate`
    and asserts the two buffers already taken are freed in reverse order and
    the error propagates. This is the only place a suspended prefill takes new
    device memory, so it is the realistic injection point.
  - `test_allocation_failure_at_a_yield_leaves_the_session_usable` injects a
    failure into the second `malloc` at a real segment yield, after the
    budgeted layers have run. It asserts the layers really ran before the
    failure, the partial allocation was returned, no suspended owner survived,
    and the same session then runs the next prefill to completion (the live
    survivor).
- `hipengine/generation/qwen35_gguf.py`: `prefill_transient_owner_inventory`
  read the session's `kv_attention_source` with a bare `getattr(..., None)`.
  That property is a live-session property that raises `RuntimeError` for a
  closed or partially constructed session, so the scrape propagated the error
  instead of reporting an unknown source. The read now catches
  `RuntimeError`/`AttributeError` and records `None`, matching the defensive
  style of the neighbouring `oracle_capacity_positions` read in the same loop.
- `tests/test_gguf_packed_workspace_stability.py`: pin the closed-session
  contract — `kv_attention_sources == [None, None]` for sessions with no live
  KV layout (exported as `"none"` by `_string_value_counts`).

The telemetry regression was introduced by this loop's own commit `545c63dac`
("fix: the P6e service harness never enables INT8 KV, so the route was
unreachable"), which added the field. It broke the pre-existing
`test_prefill_transient_inventory_reports_owners_and_modes`; that test fails on
`efff12044` and passes after this change.
