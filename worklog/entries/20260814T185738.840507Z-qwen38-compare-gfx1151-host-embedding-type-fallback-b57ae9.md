# Fail closed gfx1151 host embedding by GGML type

## Summary

Fixed a gfx1151 loader-policy regression discovered before the requested
Qwen3.6-27B versus Qwen3.8-27B comparison. Automatic private-c1 placement sent
their raw Q4_K token tables to the CPU-copy host route qualified only for Q8_0,
so both models failed during resident construction instead of reaching prefill.
Automatic placement now fails closed to the existing device owner by GGML type;
explicit host requests remain strict.

## Changes

- Declared `Q8_0` as the gfx1151 CPU-copy host-token type contract and exported
  the capability with the backend package.
- Extended the existing load-time model-info inspection to read the token-table
  type for both CPU-copy and mapped-host automatic policies.
- Added the same unsupported-type device fallback already used by mapped-host
  placement, without changing the qualified Q8_0 route or explicit placement.
- Added RED/GREEN coverage for Q8_0 admission and Q4_K rejection.

## Validation

- The RED node failed with Q4_K resolving to
  `("host", "gfx1151_private_c1_auto")` instead of the required device fallback.
- `PYTHONPATH=. uv run pytest -q tests/test_qwen35_gguf_host_token_embedding.py`
  passes: `15 passed`.
- The real gfx1151 package resolves Q8_0 to host and Q4_K/Q6_K to
  `("device", "host_type_device_fallback")`.
- The pre-fix clean dense-27B prebuild failed after model materialization with
  `ValueError: host token embedding requires raw Q8_0 ... got ... gguf_q4_k`;
  raw evidence remains under
  `/tmp/hipengine-qwen36-qwen38-compare-20260814-185054/`.
