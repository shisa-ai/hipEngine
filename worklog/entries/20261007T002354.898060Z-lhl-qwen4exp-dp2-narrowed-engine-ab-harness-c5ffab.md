# Align DP-2 engine A/B with narrowed row admission

## Summary

The DP-2 engine A/B still required chunk1024 and expected pairs at rows1024
although commit `42dd3e04b` narrowed native admission to rows4096. With the
current policy that command cannot exercise the candidate. The harness now
reads row admission from the backend capability, defaults to chunk4096, and
retains chunk1024 as a zero-engagement control. No production code or defaults
changed; this repair prepares the missing narrowed-policy A/B.

## Changes

- Derive admitted rows from `GGUF_DENSE_WIDE_F16_PAIR_POLICIES` using the same
  registry-axis key as the runtime. Count pairs for each executed admitted chunk;
  do not infer chunk width from whole-prompt length.
- Default `--prefill-chunk-size` to 4096, allow 1024 as a control, and record the
  actual admitted rows in the protocol. The existing 61-pair count, canonical 12
  plus 16 heldout cases, D128, warmup/three-repeat and counterbalanced arm order
  remain unchanged.
- Keep an explicit historical admission override on the count helper for old
  rows1024/4096 evidence. Tests verify native policy, unadmitted short/tail
  chunks, multiple 4096 chunks, historical counts, parser defaults and exact
  zero-engagement controls.
