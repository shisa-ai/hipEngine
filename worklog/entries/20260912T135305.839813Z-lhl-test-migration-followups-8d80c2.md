# Test-migration follow-ups: source pins and the Qwen4Exp admission fixture

## Summary

Close follow-ups 1 and 3 of `docs/testing/TEST-MIGRATION.md` (follow-up 2
landed in `20260912T132634.029954Z-lhl-published-command-drift-gate-ac99d5.md`).

Follow-up 1 named eight failing source-hash assertions in five Laguna
source-default modules. Auditing them showed one recurring cause: most pinned a
*whole file* that a later, unrelated campaign had extended. The files involved
are shared registry, dispatch, and kernel modules that every Qwen3.8, Qwen4Exp,
and execution-profile campaign edits, so a whole-file pin turns any unrelated
addition into a contract failure and invites re-baselining without evidence.
The repairs pin the symbol each contract actually owns, with the audit recorded
at the constant.

Follow-up 3 was a stale synthetic fixture, not a HIP dependency: the
construction-failure case reached `get_hip_runtime()` and also read
`model_map.config.context_length`, which the fake model map did not provide.

Running the GPU tier for the affected family was not part of the naming pass
and found five more stale pins of the same kind; those are repaired here too.
The remaining follow-ups (4, 5) are unchanged.

## Changes

- `tests/_laguna_policy_pin.py` (new): pins the source text of all 39
  module-level `LAGUNA_*` assignments in
  `hipengine/kernels/hip_gfx1100/__init__.py`, with `exclude=` for the one or
  two flags a calling contract exists to flip, a failure message that names the
  added/removed/changed assignments, and an idempotent `--refresh`.
- Unit `h7u`, `h8a`, `h8b` and GPU `h7u`: the normalized gfx1100 package hash
  is replaced by that policy pin. The gfx1151 peer-package pins are dropped;
  each test already asserts its own capability-isolation contract against
  `hip_gfx1151` directly, and that file is shared with every campaign.
- Unit `h8a`: the `hipengine/runtime/gguf_linear.py` whole-file pin is replaced
  by symbol pins for `Q5F32ResidentPlane` and
  `_launch_raw_k_f32_resident_activation_tile_k_row`, byte-identical to the
  recorded revision despite 502 changed lines elsewhere in the file. The
  migrated GPU `h8a` test file's own hash is re-baselined for the rename.
- Unit `h7c`/`h7i` and GPU `h7c`: `_raw_k_prefill_rowbatch_dispatch` gained a
  Q8_0 rowbatch/coltile branch in `665e9a147`, scoped to gfx1151 in `053165acc`.
  Every Q5/Q6 branch is unchanged (rowbatch capability read, `in_features`
  multiple, `prefill_` variant strip,
  `coltile2_rowbatch16`/`coltile4_rowbatch8` choice, role-variant lookup), so
  the pin moves to the live hash with that audit recorded.
- GPU `h7c`: the generic incumbent `gguf_k_prefill_out_coltile_rowbatch_kernel`
  and its launcher moved through four post-`h7c` campaigns, all of which added
  `if constexpr (qtype == 8)` branches and widened the accumulator
  `static_assert` to admit a 64-wide Q8 tile. Q5_K and Q6_K keep their previous
  branches and 32-accumulator tile, so both pins are re-baselined.
- GPU `h7e`: the whole `gguf_q8_0_mmq_prefill.hip` producer pin is replaced by
  declaration pins for the two `bf16_d4`/`bf16_d4x2` exports. The file gained
  512 lines of unrelated f32, prepacked, and tiled MMQ kernels; the d4x2
  fallback symbols are byte-identical to the recorded revision.
- GPU `h7u` and `h7y`: artifact `source_sha256` keys are recorded under
  pre-migration paths, so both now map them to current module names. Every
  renamed module is byte-identical to its recorded hash except
  `tests/test_gpu_laguna_kv_attention.py`, which `h7y` had already
  re-baselined for the gfx1151 handoff; that re-baseline is now reachable.
- `tests/test_gpu_generation_qwen4_exp_gguf.py` →
  `tests/test_unit_generation_qwen4_exp_gguf.py`: the construction-failure case
  supplies a fake HIP runtime, a fake admission record, and a model map carrying
