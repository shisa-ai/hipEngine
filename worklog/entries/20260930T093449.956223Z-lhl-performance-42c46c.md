# D2 flash decode post-commit wall A/B and rocprofv3 hang symptoms

## Summary

D2 flash-decoding landed in `a0fc5b16a` with its promotion gate passed
(KL mean 7.75e-6, top-1 100% over 1023 paired rows). The registered
census metric, however, is the rocprof-derived *busy* ms/tok (14.175 at
base), and `rocprofv3 --kernel-trace` stopped completing on this host
mid-session, so this entry records (a) a back-to-back wall-clock A/B of
the flash default against the base chain with the identical census
command, and (b) the profiler symptoms, recorded before any restore as
`docs/OPTIMIZATION.md` §9 requires.

rocprofv3 symptoms (2026-09-30, from ~16:11 local):

- `rocprofv3 --kernel-trace --output-format csv -d <dir> -o run --`
  around `scripts/gemma4_family_census.py drive` never completed: three
  attempts at 20/50/60 minutes, killed only by command timeout. The log
  ends at the tool's `HSA version 1.18.0 initialized` line and no trace
  CSV is ever written (rocprof emits traces at exit, so a timeout kill
  loses everything).
- The pattern is not a dead child: the `--warm-only` variant's child
  was observed alive at 105% CPU with 19.3 GB VRAM allocated minutes
  past its `timeout 300`, and wrappers killed by the harness left that
  child orphaned -- it held GPU1 and caused a subsequent run to fail
  with `HIP error 2: out of memory` during weight load until the
  orphan was killed manually.
- A non-HIP child (`/bin/echo`) profiles and exits fine, so the tool
  itself works; the stall begins on the HSA/hip-init path of a Python
  GPU workload. A single-test pytest under the same flags also failed
  to finish within 240 seconds, which normally runs in under a minute.
- No environment restore was attempted; symptoms only, per §9.

Wall A/B (GPU1 `ROCR_VISIBLE_DEVICES=1`, identical command, adjacent
runs, base files restored via `git checkout 7ddffcfa6 -- <3 files>` and
reverted to `a0fc5b16a` immediately after):

```
python -m scripts.gemma4_family_census drive --prompt 1024 --decode 64 --prefill-repeats 2
```

| arm | decode tok/s | decode wall ms/tok |
| --- | ---: | ---: |
| base 7ddffcfa6 (split/single chain) | 66.16 | 15.115 |
| flash a0fc5b16a (shipping default) | 77.74 | 12.864 |

Decode wall improves **-2.251 ms/tok (-14.9%)**, throughput +17.5%.
Prefill is flat (2777.8 vs 2786.1 tok/s, within run noise). Because
busy time is bounded above by wall time, flash busy <= 12.864 ms/tok,
so the busy improvement against the 14.175 base is at least 1.31
ms/tok regardless of when the profiler recovers.
