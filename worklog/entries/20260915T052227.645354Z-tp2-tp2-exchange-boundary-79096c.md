# Connect the staged exchange with f32 partials and validate the residual boundary

## Summary

TP2-C is done. Three decisions and their validation:

1. **Down-partial dtype: f32.** The incumbent down kernel supports
   `output_dtype='f32'` (used by the runner's f32 paths), and the runner's
   f32-residual decode mode consumes an f32 stream. An f32 partial is the
   kernel's f32 accumulator written out unrounded, so no per-rank bf16 rounding
   precedes the sum, and the reduced f32 vector feeds the f32 residual path with
   no conversion. The contract emulation now has both dtypes and a test proves
   they are different contracts (the f32 partial is the exact f32 matmul; the
   bf16 partial is that value rounded).
2. **Transport: the staged exchange.** `PinnedStaging` page-locks one host
   buffer (a pageable D2H is staged through a driver bounce buffer - an
   unmeasured extra copy). `staged_exchange_reduce` D2Hs each rank's partial on
   that rank's own stream (so stream order places the copy after the GEMV that
   produced it), waits, sums in f32 on the host, and H2Ds the reduced vector to
   every rank - both ranks must hold the reduced hidden state, because the next
   layer is replicated. Each rank's H2D is read back and verified (max abs 0.0
   on both).
3. **Boundary: validated.** `residual_boundary` computes next = residual + mlp
   in f32 then the next block's input RMSNorm (CPU reference) from the TP2
   reduction, the TP1 teacher, and the f64 truth.

## Changes

`scripts/tp2_mlp_slice_e2e.py`: `PinnedStaging`, `staged_exchange_reduce`,
`residual_boundary`, the f32 contract emulation, per-rank reduced buffers, and
the boundary comparisons in the report under `reduction` and `stages`.

One real defect found and fixed on the way: `run_rank_chain_fused` allocated
its down buffer at the bf16 size while its launch had been switched to f32
output, a 10 KB device buffer overflow past the allocation - which surfaced as a
bogus HIP status 1 on a *later, unrelated* launch. The buffer is sized for its
output dtype now. This is also why the teacher appeared to break after the
exchange: it was the candidate's overflow, not the exchange.

## Validation

```
uv run python3 scripts/tp2_mlp_slice_e2e.py --model /models/gguf/Qwen3.8-27B-Q4_K_M.gguf \
  --layer 0 --json benchmarks/results/2026-09-15-w7900-tp2-mlp-slice-e2e.json
uv run pytest tests/test_unit_scripts_tp2_mlp_slice_e2e.py
```

9 tests pass including the two-GPU end-to-end. Measured on this host (two AMD
Radeon Pro W7900, Q4_K_M, layer 0, seed 20260915):

| comparison | max abs | mean rel |
| --- | ---: | ---: |
| rank partial vs f32 contract | 7.7e-08 | 1.7e-05 |
| TP2 sum vs TP1 teacher | 1.9e-09 | 1.4e-07 |
| TP2 sum vs f64 truth | 3.9e-05 | 2.0e-03 |
| TP1 teacher vs f64 truth | 3.9e-05 | 2.0e-03 |
| boundary next_hidden TP2 vs TP1 | 1.5e-08 | 1.4e-08 |
| boundary next_norm TP2 vs TP1 | 3.6e-07 | 2.3e-08 |
| boundary next_norm TP2 vs truth | 7.0e-04 | 3.2e-04 |

Reading: with f32 partials, **TP2 and TP1 agree to f32 accumulation noise**
(1.4e-07 mean relative) - the two-GPU slice is numerically the same computation
as the unsharded one, not merely inside a tolerance. The boundary the replicated
next layer consumes matches TP1 the same way. The remaining distance to the f64
truth (2.0e-3) is the bf16 activation contract, identical on both paths. The
exchange moved 40960 D2H bytes and 40960 H2D bytes per reduction and both ranks'
H2D round-trips verified exactly. The fused candidate remains bit-exact with the
unfused baseline.
