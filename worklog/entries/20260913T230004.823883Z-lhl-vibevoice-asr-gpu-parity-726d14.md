# VibeVoice front-end validated vs torch-GPU bf16 oracle

## Summary

The torch-free HIP VibeVoice-ASR audio front-end is now parity-validated
against torch on both lanes required by the goal: torch CPU fp32 (exact
recorded-noise fixtures) and torch GPU bf16 (gfx1151). Follow-up to
`20260913T222905.987716Z-lhl-vibevoice-asr-torch-fixtures-7a6297.md`.

## Changes

- Torch-GPU bf16 fixture set under `tests/fixtures/vibevoice_asr_gpu/`
  (same deterministic PCM/noise; `.float()` widened dumps so bf16 tensors
  reach numpy).
- `test_frontend_matches_torch_gpu_bf16`: HIP front-end vs torch GPU
  trace fixture, recorded noise, rel <= 5e-2 gate on connector-sum
  embeddings.
- Oracle script: bf16 chunk-vs-single divergence (acoustic 0.25 /
  semantic 0.16, an HF chunk-cache bf16 carry quirk; fp32 is 1e-5 exact)
  is recorded as a warning, not a gate.

  7/7 pass on gfx1151, including HIP-vs-torch-GPU-bf16 embeds parity.
