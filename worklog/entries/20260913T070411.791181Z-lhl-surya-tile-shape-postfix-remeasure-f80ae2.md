# Surya tile shape: per-path policy, the narrow-budget regression, and the post-fix re-measurement

## Summary

Task #87 re-measured both tiled score matrices under the rule that #86 landed
(`b55470ae6`, the envelope consulted only while the byte budget alone would
leave the grid in one or two tiles). **The re-measurement found that rule
regressing supported vision configurations, so it is replaced here by a
per-path policy**, and both paths are re-measured under the replacement.

The regression is measured, not inferred
(`benchmarks/results/2026-09-13-gfx1151-surya-vision-narrow-budget-check.json`,
one runner per shape, two reverse passes, pass check 5/5):

| 4096 patches (page_ja) | #86 rule | pre-#86 rule | delta |
| --- | ---: | ---: | ---: |
| 64 MiB budget | 320 rows, 1081.07 ms | 128 rows, 882.39 ms | **-18.4%** |
| 128 MiB budget | 672 rows, 1378.13 ms | 128 rows, 882.39 ms | **-36.1%** |

The 4096-patch shape curve has a spike band between roughly 256 and 1344 rows
(recorded in `docs/REFACTOR.md`), and #86's tile-count threshold let budgets in
the 32-256 MiB range keep the budget's own width inside that band. The plans it
changed, computed from the shipped constants:

| grid | budgets | #86 | now |
| --- | --- | --- | --- |
| 4096 patches | 32/64/128/192/256 MiB | 160/320/672/1024/1344 rows | 128 |
| 1024 patches | 16 MiB | 320 rows | 128 |
| 6400 patches | 512 MiB | 1728 rows | 192 |
| 6400 patches | 128/192/256 MiB | 416/640/864 rows | 192 |

So the fix is a **per-path shape policy**: `plan_score_tiles` gains a keyword
`shape_envelope` (default `True`), the vision tower keeps the unconditional
`max(128, ceil(rows / 32))` envelope, and the text prefill passes `False` and
takes the byte budget's own width. `SHAPE_TILE_CAP_MAX_TILES` and the
conditional are deleted.

The cost of the correction is the 5.7% #86 bought on the 6400-patch grid under
the default budget (it returns to 192 rows, 2130.22 ms, measured here); that
anomaly (96 rows is 9% faster) stays open in `docs/REFACTOR.md` rather than
bought with a rule that regresses a supported budget. The text prefill's gain is
kept and is now measured *inside one artifact* against the old cap's shape.

**Post-fix, on a quiet gfx1151, both paths re-measured:**

| path | old cap's shape | production plan | same-run delta |
| --- | ---: | ---: | ---: |
| text 16384 tokens | 256 rows, 17.598 s | 1024 rows, 16.952 s | **-3.7%** |
| text 8580 tokens | 256 rows, 7.628 s | 1952 rows, 7.574 s | -0.7% |
| vision 4096 patches (512 MiB) | 128 rows, 880.96 ms | 128 rows, 880.96 ms | unchanged |
| vision 4096 patches (64 MiB) | 128 rows, 882.58 ms | 128 rows, 882.58 ms | fixed (-18.4% vs #86) |
| vision 6400 patches (512 MiB) | 192 rows, 2130.22 ms | 192 rows, 2130.22 ms | #86's -5.7% given back |
| vision 34320 patches (A4) | 320 rows, 43355.60 ms | 320 rows, 43355.60 ms | unchanged (0.09% off 43318.30) |

Small prompts are why the text path needs no envelope of its own, measured here
(`...-surya-text-prefill-small-prompts.json`): at 1024 tokens the whole dense
matrix is 0.779 s against 0.775 s at 128 rows, and at 4096 tokens 3.442 s
against 3.401 s — within 1.2% of the best measured shape, where the same dense
tile costs the vision tower 19-43%.

## The rule

```
block = budget_bytes // (heads * rows * 4)      # widest tile that fits
if shape_envelope:                              # vision: True, text: False
    block = min(block, max(SHAPE_TILE_ROWS, ceil(rows / SHAPE_TILE_DIVISOR)))
block -= block % SHAPE_TILE_MULTIPLE            # whole 32-lane wavefronts
block = min(block, rows); block = max(block, 1)
```

Both paths still share the arithmetic (the budget derivation, the wavefront
rounding, the clamp, the tiny-budget `block == 1` contract); the shape policy is
the one parameter that differs, and it is a keyword on the planner rather than a
branch in dispatch or a family flag in engine code. `plan_vision_attention`
remains the vision-shaped name and passes `True`.

## Changes

- `hipengine/runtime/surya.py`: `SHAPE_TILE_CAP_MAX_TILES` and the tile-count
  conditional are gone; `plan_score_tiles` takes `shape_envelope=True`;
  `plan_vision_attention` passes it explicitly; both `prefill_block` and
  `prefill_scratch_bytes` pass `False`. The constants block comment now carries
  both policies, the regression table, and the reason the envelope stays
  unconditional for vision. The estimate's calibration table returns to the
  6400-patch 34-tile row (2131.13 ms measured, 2050.19 ms estimated), and
  `vision_patch_ceiling`'s docstring returns to the under-2% non-monotone
  statement, re-measured: 14 descending steps in 1..20000 patches, the largest
  -1.8% at 5089, with the bisection equal to a brute-force scan at 0.5/1/1.2/2/
  10/60/120 s (the 120 s default is 56856 patches, unchanged).
- `scripts/surya_attention_memory.py`: both text planner calls pass
  `shape_envelope=False`; `_production_envelope`/`_shape_envelope` are replaced
  by `_production_multiple`/`_wavefront_rounding`, because the text path no
  longer consults the envelope and only the rounding still needs lifting for a
  `--text-blocks` row (the script's artifact records the new policy and drops
  `production_envelope`).
- `scripts/surya_vision_tiling_cost.py`: the docstring no longer describes the
  tile-count threshold.
- Tests: `test_prefill_tile_plan_keeps_the_budget_shape_where_it_already_splits`
  becomes `test_prefill_tile_plan_takes_the_budget_width_not_the_vision_envelope`
  (1024 tokens now keeps the whole dense matrix, 1952/1024 at 8580/16384, and
  the vision planner differs on the same inputs);
  `test_shape_cap_only_overrides_a_budget_that_leaves_two_tiles` becomes
  `test_vision_shape_envelope_is_not_a_tile_count_threshold` (every budget from
  32 to 512 MiB at 4096 patches is capped to 128, the text path keeps 320 on the
  same input, 6400 is 192, the A4 is 320); `test_prefill_and_vision_share_one_planner`
  now also pins the text policy's bound; the text-path budget tests pass
  `shape_envelope=False` explicitly; `tests/test_surya_bench_harness.py`'s lift
  test pins the named width and the rounding lift instead of the envelope;
  `tests/test_surya_gpu.py`'s admission test passes the text policy.
- Docs: `docs/MODEL-SURYA.md` (the text and envelope paragraphs),
  `docs/REFACTOR.md` (the entry is now "the vision envelope's mid-size anomaly":
  the 3-tile band is resolved by construction, the 6400-patch anomaly and the
  reported ceiling's sub-2% steps stay open), `benchmarks/README.md`'s protocol
  note, and `benchmarks/CHANGELOG.md`.
