# DSpine CPU oracle validated: injection + transition-cache math, DSpine==AR single prompt

## Summary

Task #17 progress (correctness foundation). Implemented the clean-room DSpine CPU
oracle (hipengine/kernels/cpu_reference/dspine.py): block-causal DFlash-style
backbone (reusing the DFlash2 CPU attention/ops helpers) + per-layer adjacent
causal injection (bridge_write) + transition-cache greedy refinement
(refine_greedy). Written from the paper equations, no vendored code.

Validated against the real Qwen3.8-27B Q4_K_M target + the Apache-2.0
tencent/Qwen3.8-27B-DSpine-b16 weights (snapshot ea909c0f): a scratch cycle driver
(prefill tap capture → drafter.forward → refine_greedy → verify_target_block →
accept) produced **24/24 greedy tokens == true AR (1.000)** on a coding prompt.
The injection + transition-cache math is correct.

Generalized the target prefill tap capture: DFlash2HiddenCaptureTargets previously
rejected any depth outside DFLASH2_TAP_DEPTHS; the capture function itself is
generic (keys off targets.buffers[depth]), so relaxed the validation to accept any
positive post-layer depth. DSpine's tap layers [1,16,31,46,61] (depths +1) now
capture; DFlash2 callers unaffected.
