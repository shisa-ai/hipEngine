# Triage the audit rows that block the v0.7.0 release gate

## Summary

`python3 audit/audit.py check` was failing on `main` before any release work
started: 2 `stub` rows and 13 `ungoverned-flag-branch` rows were untriaged
against a per-kind ceiling of 0. All 15 were false positives, and each is now
recorded `NOT-DEBT` / `keep` with the evidence that settles it. The gate exits 0.

The 13 `ungoverned-flag-branch` rows are one cause. The extractor's
`FLAG_IN_LINE` regex matches any `HIPENGINE_[A-Z0-9_]+` token on a line, so it
fired on the env-var-to-CLI-flag mapping layer in
`hipengine/server/__main__.py` (lines 306, 309, 314, 317, 322, 325, 334, 339,
348, 353, 404, 407) and on the value reader at
`hipengine/runtime/qwen35_gguf_runner.py:36191`. Those lines are `argparse`
`default=` expressions, help strings that document the variable, or a
threshold reader that returns `_GDN_PREFILL_SEGMENT_THRESHOLD_DEFAULT` (256,
defined at `:35745`) when unset. None of them is a conditional branch. The same
flags' inventory rows were already decided `NOT-DEBT` / `keep`, so the findings
were re-litigating a settled question at shifted line numbers.

The 2 `stub` rows are a capacity refusal and an internal consistency guard that
both use `NotImplementedError` because that type is this engine's declared
in-band decline protocol, not because the work is unimplemented. Both packed-path
callers treat it that way — `hipengine/generation/qwen35_gguf.py:3496` in
`_step_ar_serving_slot_chunk_packed` and `:10903` in `_step_native_chunk` are
`except NotImplementedError: return None/False`, after which the caller falls
back to the per-slot AR path and records the route in `_route_counts`.
