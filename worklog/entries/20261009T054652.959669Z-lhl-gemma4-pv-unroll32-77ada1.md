# Widen the staged PV singleton decode window to 32 keys

## Summary

The deep-decode target is the staged singleton P*V: at 131072 it was 67
percent of decode kernel time with PMC counters showing latency exposure
(SQ_WAIT_ANY 5.7 per cycle, DRAM at ~5 percent of this part's rate), and
the shipped unroll-8 window had already proven the mechanism (+31 percent
decode at 131072 on 2026-10-06). The singleton's per-thread V walk loads
2 bytes per key with one dependent chain; the width of the in-flight
window is the only latency-hiding lever inside the bit-identical contract.

The window width is now a template parameter with 8/16/32 instantiations
selected per call by `HIPENGINE_GEMMA4_PV_UNROLL` (default 32), read per
launch so one process can interleave arms. The per-(row, dimension)
accumulation stays one ascending-key FMA sequence at every width, so all
widths are bit-identical.

Leaf A/B (`/tmp/multiloop-beat-llamacpp/pv_unroll_leaf_ab.json`, interleaved,
decode geometry, both layer head geometries):

| geometry | keys | u16/u8 | u32/u8 |
| --- | ---: | ---: | ---: |
| sliding (16q/8kv, hd 256) | 262144 | 0.813 | **0.742** |
| global (16q/2kv, hd 512) | 65536 | 0.765 | 0.645 |
| global | 131072 | 0.775 | 0.667 |
| global | 262144 | 0.774 | **0.664** |

u32 wins everywhere, monotonically with depth; bit-identity asserted
between all arms at every point.

End to end on the restored 262015 state (the cross-process KV harness; the
state was minted this session, 59 GiB, prefill 796.9 s = 329 tok/s, decode
7.38 tok/s at width 8): width 32 measures **10.21 tok/s** at 262015 --
**+38 percent**, and **1.42x llama.cpp's 7.21** at the same depth. The
restored decode's 128 greedy IDs equal the mint-time decode's exactly
(`/tmp/multiloop-beat-llamacpp/kvrestore_262015_pv32.json` vs
`kvsave_262015.json`). The campaign's deep-decode gap (0.76x on the
2026-10-06 record, 5.51 vs 7.21) is closed to a 1.42x lead.

  default (staged-vs-strict bit-identical across the fixture matrix,
  including the singleton decomposition dispatch test).

  mint-time decode; 10.21 tok/s.
