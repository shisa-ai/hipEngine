# Profile W7900 PARO verifier costs before depth sweep

## Summary

The lead authorized profiling all PARO verifier savings opportunities, followed
by a B1/B2/B3 depth sweep. Measure before changing the verifier. The incumbent
production path has an existing strict-teacher Japanese numerical failure;
that remains a finding, not a restriction on running evaluation.

## Changes

- Baseline source: `3a1f070c7`, Qwen3.6-35B-A3B packed PARO plus BF16 MTP
  sidecar, production profile, BF16 KV, W7900 device 0 on this physical host.
- Use the ten-prompt category/heldout suite through public blocking AR and MTP
  APIs, with one warmup and three counterbalanced measured pairs per prompt and
  output limit. Limits 25/129 include the prefill-produced first token, so they
  cover 24/128 subsequent decode tokens. Use one resident owner with an 8192-token
  capacity for both arms; loading is outside request timings.
- Add unrelated 512/4096-token context probes by prefixing background tokens to
  the code prompt. Preserve exact token rows in artifacts.
- Keep instrumentation out of production files. The scratch profiler wraps live
  public-runner methods with nested ROCTX ranges and captures kernel, HIP API,
  and memory-copy traces. Associate asynchronous GPU work with host regions via
  correlation IDs, not an assumption that host returns imply GPU completion.
- Independently review backup/rollback, provider update, graph/launch overhead,
  readback/commit, projection weight reuse, output head, and K>1 adapter gaps.
- Scratch commands and outputs: `/tmp/paro-verifier-profile.py`,
  `/tmp/paro-verifier-run.sh`, `/tmp/hipengine-paro-verifier-20261024/`. These are
  diagnostic while the profile and correctness review are incomplete.
