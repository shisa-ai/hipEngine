# The strict dense IQ row slab was reading every weight twice at verifier rows

## Summary

`gguf_iq_dense_strict_kernel` is the exactness-contract owner for Q3_K, IQ3_S,
IQ3_XXS, IQ2_S and IQ2_XS dense projections, and at the native verifier's 3-row
block it was launched with a 2-row slab. `grid.y` is `ceil(rows/R)`, so every
weight slice was read **twice**. Choosing the smallest supported slab at or
*above* the row count makes `grid.y` one and removes the re-read.

Interleaved A/B on the same host and device, three old-rule runs against two
new-rule runs: the strict family falls **4.264 -> 3.179 ms/step (-25.4%)** and
the whole verifier **38.275 -> 37.039 ms/step (-3.23%)**. Every old-rule run
exceeds every new-rule run, so the two bands do not overlap.

The change is arithmetic-neutral by the kernel's own declared contract, and that
is verified directly rather than assumed: the section-6.1 teacher-forced gate
reports **identical numbers to the last digit** under both rules on UD-Q4_K_M
(mean 3.435e-05, p95 2.112e-04, p99 2.904e-04, max 2.952e-04, top-1 1.0000,
deterministic). On UD-Q4_K_S the new rule passes at mean 1.871e-05, p95
1.115e-04, p99 3.704e-04, max 4.865e-04, top-1 1.0000.

## Changes

`_row_batch()` in `hipengine/kernels/hip_gfx1100/quant/gguf_iq_dense.py` used to
return the largest slab in `(1, 2, 4, 8)` at or below `rows`; it now returns the
smallest slab at or above `rows`. `HIPENGINE_GGUF_IQ_DENSE_ROW_BATCH_DOWN=1`
restores the old rule for rollback and bisection.

### Why the new rule cannot lose

`R` is a launch-geometry parameter only. `gguf_iq_dense.hip` documents it as
"R only changes how many prompt rows one block owns; the per-(row, column) k
ownership, FMA order, shuffle tree and serial wave-0..3 sum are all unchanged,
so every R produces bit-identical outputs", and phase B pads with
`xv[r] = row0+r < rows ? bf16_load(...) : 0.0f` while the store is guarded by
`row0+r < rows`, so `R > rows` is safe.

That makes the comparison exact. For a prompt of `rows` rows the total row-lane
work per column tile is `ceil(rows/R) * R` and the weight traffic is
`ceil(rows/R)` reads. For every `rows <= 8` the new rule returns the next power
of two at or above `rows`, which makes `ceil(rows/R) = 1`; the old rule's
`ceil(rows/R) * R` is then either equal (rows=3: 4 lanes both ways; rows=5,6,7:
8 lanes both ways) or larger. So the new rule is never worse on compute and
strictly better on traffic.

### How the double read was found

The verifier-window census attributed kernels to the `gguf_mtp_verify_block_N`
marker ranges. `gguf_iq_dense_strict_kernel` was **4.28 ms/step, 11.2% of the
UD-Q4_K_M verifier**, for tensors that are only 2.6% of the model's weight
bytes. Its template arguments in the trace were `<3, true, 8, 2>` and
`<2, true, 8, 2>` - Q3_K and IQ3_S with `R=2` - and `Grid_Size_Y` was 2 on every
call. The model carries seven Q3_K and four IQ3_S tensors, matching the 11 calls
per step exactly.

At `R=2` the largest shape (N=17408, K=5120, Q3_K) cost 380.3 us per call for
78.0 MB of weight traffic, which is 205 GB/s. At `R=4` the same call costs
252.4 us for 39.0 MB, which is 155 GB/s. The kernel is therefore
instruction-bound, not bandwidth-bound, and the win comes from halving the
traffic while holding the row-lane work constant - not from approaching the
roofline.

**The paired suite does not separate this change from run-to-run spread.** The

outlier rather than a change in this run (the arm has measured 31.31-31.36 in
every other run since 2026-09-12). The retention rests on the verifier
sub-window A/B above, where the two bands do not overlap, and on the exact
section-6.1 identity.

## Next

The strict owner is instruction-bound at ~155 GB/s of the 960 GB/s roofline, so
the remaining lever is its decode, not its launch geometry: phase B issues
per-element byte loads (`b[...]`) where the local32 owner reads the same bytes
as u32. Widening those loads to 32-bit words does not change any decoded value
or FP operation, so it is arithmetic-neutral in the same sense this change is -
but it touches the kernel body that carries the strict exactness contract, so it
owes a RED fixture and the full section-6.1 gate.
