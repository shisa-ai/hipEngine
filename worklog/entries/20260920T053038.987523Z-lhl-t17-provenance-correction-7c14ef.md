# Correction: the c=8 closure artifacts are the second of two sequential identical runs

## Summary

Provenance correction for `worklog/entries/20260920T052944.836518Z-lhl-t17-closure-ar-fallback-aa8730.md`.
`/tmp/t17-closure.sh` was launched twice and the two runs were **sequential, not
concurrent** (bg-179 server start 21:02:17 UTC, done 21:05:38; bg-180 server
start 21:06:38, done 21:10:12). The script opens with `rm -rf "$OUT"`, so the
second run destroyed the first run's artifacts. Every `/tmp/t17/` number cited in
the earlier entry is therefore from the **second** run (bg-180), on tree
`d805bfae4e54f05c1b62c00621a129cfca6fab6d` with an empty `dirty.txt`.

The numbers themselves are unchanged and were re-read from the surviving
artifacts to confirm: `off` `failed_requests` 0, `accounted_requests` 0,
`ar_output_tokens` 0, `ar_tokens_by_reason` `{}`; `on` `failed_requests` 0,
`accounted_requests` 8, `ar_output_tokens` 256, `ar_tokens_by_reason`
`{"no_provider": 248}`.

This matters for the open question in that entry rather than for its arithmetic.
Two independent runs both completed with `exit=0` in both arms, which is weak
evidence that the arm behavior is stable; but because the first run's artifacts
were deleted, whether the two runs produced *identical* token attribution is
unknown and cannot be recovered. A repeat intended to establish reproducibility
must use a distinct output directory per run.
