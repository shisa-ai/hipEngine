# Reject Qwen4Exp P2 wider output tiles

## Summary

Implemented and rejected exact wider output tiles for the two co-primary early
MoE projection owners. Doubling Q4 output ownership from 4 to 8 columns and
Q5_1 from 8 to 16 halves their output-grid CTAs but doubles each CTA's serial
output loop. All outputs remain BF16-bit exact; all complete p508 variants are
neutral or slower, and the combined route is a statistically resolved
regression. Candidate code was removed.

## Changes

- Temporarily added Q4 row8/output8/expertgrid64 and Q5_1
  row8/output16/expertgrid64 HIP exports, wrappers, registry entries, and
  isolated/combined runner selectors.
- Extended the existing Q4/Q5_1 RED tests to require exact equality with the
  incumbent output4/output8 owners.
- Removed all candidate source and selector changes after timing.
- Added compact rejection artifact
  `benchmarks/results/2026-08-31-gfx1151-qwen38-flash-next-p2-wider-output-tiles-rejected.json`
  and updated the campaign/changelog.

## Validation

- 20 focused Q4/Q5_1 GPU tests passed with candidate BF16 payloads bit-exact to
  the current strict owners.
- Same-residency p508, one warmup and five counterbalanced pairs per mode:
  - both wide: ratio mean `0.994404`, 95% CI `[0.989654, 0.999154]`;
  - Q4 output8 only: `0.996755`, `[0.992184, 1.001325]`;
  - Q5_1 output16 only: `0.997980`, `[0.995698, 1.000262]`.
- All modes share the exact incumbent logits hash and repeat exactly.
- Candidate code was removed; incumbent focused tests were rerun and remain 20/20.
- Raw paired JSON/log hashes are retained in the compact artifact.

## Next

- Do not widen sequential output loops further. The next mechanism must create
  concurrent reuse—such as sharing one activation load across multiple output
  owners without serializing complete fixed-K reductions—or remove an
  operation boundary while preserving exact/T1 arithmetic.
