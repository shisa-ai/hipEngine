# gemma4-moe-down-amortized

## Summary

The Q5_1 down projection was the largest single item in the default prefill
after iteration 61 (1130 ms of 3348 ms, 33.7%, 19.5 ms per call) and its owner
had the same nest the Q4_K owner had before that iteration: output column
outer, row batch inner, input re-read once per column. The same swap applies,
but it is not the same win -- the Q5_1 owner is not input-bound. Amortizing four
output columns alone moved it 51.3 -> 49.8 ms in an isolated A/B.

What it *is* bound by is the per-column weight metadata. `dequant_q5_1` reads
the block's `d`, `m` and `qh` words from global for every (thread, column) pair,
so each thread issues four loads for eight FMAs and the same block header is
re-read by all 32 lanes that share it. Preloading those three words once per
block into shared memory -- the kernel's existing `SHARED_METADATA` option, which
the launchers here had never enabled -- is the lever, and it only pays off
together with the amortized nest, because the slab then serves four output
columns instead of one.

The shipped route takes the projection from 19.5 to 15.3 ms per call and the
layer total from 3348 to 3130 ms (304.8 -> 327.0 tok/s) on the W7900 lane and
from 319.0 to 341.0 tok/s on the RX 7900 XTX lane. Output is bit-identical:
`kl_max` is exactly 0.000000 over 1023 teacher-forced rows.

Cumulative for the campaign's prefill column: 128.5 -> 341.0 tok/s (+165%),
first-token latency 7.97 -> 3.00 s, decode flat at 43.87.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/qwen4_exp_q5_1.hip`: the grouped Q5_1
  prefill kernel takes a fourth template argument, `AMORTIZE_INPUT`, which swaps
  the nest the same way the Q4_K owner's does; the partial scratch and the
  metadata slabs both become `OUT_BATCH` wide. Default false, so every existing
  instantiation is unchanged. A new launcher
  `hipengine_qwen4_exp_q5_1_selected_grouped_prefill_compact_rowbatch8_out4_amortized_bf16_bf16_out`
  instantiates `<4, 4, true, true>` -- row batch 4, four output columns, shared
  metadata, amortized nest -- and sizes the dynamic shared memory for the
  partials plus the three metadata slabs.
- `hipengine/kernels/hip_gfx1100/quant/qwen4_exp_q5_1.py`: wrapper and registry
  entry for
  `selected_grouped_prefill_compact_rowbatch8_out4_amortized_bf16_bf16_out`.
- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py`:
  `gemma4_project_experts_grouped` probes the amortized variant first and falls
  back to the row-batch variant.

## Shape selection

Isolated A/B on the real artifact (8192 compact rows, in 704, out 2816, 128
experts), round-robin interleaved with the incumbent and reported as medians
because run-to-run drift on this machine reached 45% between back-to-back
passes of the *same* configuration:

| owner | ms | vs incumbent | bits |
| --- | ---: | ---: | --- |
| row-batch `<8, 1>`, no shared metadata (incumbent) | 37.1 | 1.00x | - |
| amortized `<8, 4>`, no shared metadata | 36.8 | 1.01x | identical |
| amortized `<2, 4>`, shared metadata | 28.1 | 1.32x | identical |
| amortized `<4, 4>`, shared metadata | 28.2 | 1.32x | identical |
| amortized `<2, 8>`, shared metadata | 30.7 | 1.21x | identical |
| amortized `<4, 8>`, shared metadata | 71.0 | 0.52x | identical |

`<4, 4>` is taken over `<2, 4>` at the same speed because it halves the weight
passes. `<4, 8>` loses badly: its 34 KB of partial scratch plus metadata leaves
one CTA per CU. The shipped wrappers re-measured at 1.29-1.35x across 2048, 4096
and 8192 compact rows.

**A probe-order bug was caught by the census, not by the isolated A/B.** The
first version of the Gemma probe listed the row-batch variant first, so the
amortized owner resolved but was never reached; the census showed the projection
at 1137 ms against 1130 and the isolated benchmark showed 1.29x at the same
time. The probe list now puts the amortized variant first, which is what the
census confirms: 890 ms over 58 calls.

## Validation

Teacher-forced gate, default route, prompt 2048 with prefill 1024, 1023 scored
rows: `kl_max` 0.000000, top-1 rate 1.0, zero flips, pass. The route is
bit-identical, so no promotion gate applies.

Campaign bench, RX 7900 XTX, 1024 prompt / 128 output, three samples after one
full-shape warmup, public `LLM.generate` path: prefill 3.00 s (341 tok/s), first
token 3.00 s, decode 43.8715 tok/s, wall 5.89 s, `public_path_parity` true.

Tests: 35 pass across the Q5_1 selected, Q5_1 MMQ selected, Q4_K prefill and
Gemma 4 MoE-routing suites. The shipped wrappers were also A/B'd for bit
equality directly: 0 of 23,068,672 output elements differ.
