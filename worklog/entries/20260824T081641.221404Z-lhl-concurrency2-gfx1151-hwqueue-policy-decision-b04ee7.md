# Retain gfx1151 hardware queue2 policy

## Summary

Selected and retained the existing explicit gfx1151 `GPU_MAX_HW_QUEUES=2`
backend default after completing the full `1,2,4,8,unset` campaign. All five
policies are mechanically stable, but no alternative has a generic,
repeatable, SLO-qualified advantage. The package default does not change; the
temporary comparison seam is removed.

## Validation

Decision inputs, all same host/model/profile:

- correctness: 1,950 direct-width + 1,170 FP16-state rows, calibrated profile,
  c13 exact control/lifecycle;
- core: 10 c17/c32 children, all mechanically stable;
- full width: 10 children / 130 executions. Normalized versus queue2,
  q1/q4/q8/unset = -0.75%/-0.64%/-0.50%/-0.42%; queue8 c32 loses in both
  broad blocks (-3.68%/-6.90%);
- load: 10 children / 90 workloads / 2,100 exact control records. Normalized
  q1/q4/q8/unset = -0.57%/+0.47%/-0.67%/-0.09%; no alternative fixes heavy
  ITL/soak SLOs;
- context/graph/prefix: 20 children. Normalized q1/q4/q8/unset =
  -0.09%/-0.03%/-0.07%/+0.03%; all pressure/graph/prefix mechanics pass, 32K
  remains SLO-blocked, 64K c2 unsupported; and
- cache-only direct c8 p128/d8 queue2 and unset profiles share immutable cache,
  invoke no compiler, and each observe runtime Queue_Id `[1]` in their measured
  single-stream scope. This does not reveal maximum allocatable queues and gives
  unset no advantage.

No MES lockup, child timeout, or KFD survivor occurs in retained matrices.
Cleanup validation: 95 backend/server/rocprof/lifecycle tests plus 34
production-load/long-context tests pass; Python compilation, JSON validation,
Worklog2, README sync, and `git diff --check` pass.

Remaining capacity blockers are independent of queue policy: c8 partial SLO,
c9+ fixed-width SLO failure, heavy arrival/soak ITL/E2E, 32K TTFT/E2E, and 64K
c2 support.
