# W7900 Qwen3.8: packed prefill state mismatch is arithmetic-class, not a slot bug; the qualifying gate is missing

## Summary

The c>N admission blocker recorded as "packed prefill fails the state-equality
oracle" is now localized, and it is not what that phrasing implies. On this tree
the packed final-row prompt prefill is already default-on for c>N AR serving
(`HIPENGINE_GGUF_AR_PACKED_PREFILL` is the rollback opt-out), while
`scripts/gguf_packed_ar_state_oracle.py --prefill-mode packed` asserts *byte*
equality of the persisted Conv/GDN and live-KV state against an independent
strict-c1 teacher. Those two facts cannot coexist as a defect claim, because the
two sides do not compute the same final state at all: the candidate runs
`packed_linear_state_route=segmented_in_place_final_state` with per-token state
capture disabled, the teacher runs `gdn_prefill_mode=exact` with per-token state
capture and commits the last row. I classified the mismatch set to decide which
of "wrong value", "wrong slot", or "different arithmetic" it is, and it is the
third. No route is being promoted or demoted here; the finding is that the
binding evidence for this default-on route does not exist yet.

## Changes

- Added `scripts/gguf_state_slot_hash_match.py`: reads an oracle JSON and buckets
  every `(phase, component, part, layer)` group into same-index / permuted /
  unmatched by comparing the stored blake2b hashes across rows. `permuted > 0` is
  the signature of a slot-index defect (`base + state_index * row_nbytes` slicing
  in `qwen35_gguf_runner.py`); `unmatched` means the value equals no reference
  state at any slot. Validated against a synthetic packet that encodes a
  deliberate row-0/row-1 state swap, which it reports as `permuted`.

## Validation

Correctness diagnostic; `performance_claim: false`. W7900 / gfx1100,
Qwen3.8-27B-Q4_K_M, production profile, `--prompt-length 45 --decode-steps 4
--gdn-prefill-mode exact --decode-mode eager`,
`HIPENGINE_EXECUTION_PROFILE=production HIP_VISIBLE_DEVICES=0
ROCR_VISIBLE_DEVICES=0`, `--compiler-version-file
/tmp/compiler-version-gfx1100.txt`:

```
.venv/bin/python scripts/gguf_packed_ar_state_oracle.py \
  --model /models/gguf/Qwen3.8-27B-Q4_K_M.gguf --backend hip_gfx1100 \
  --rows {2,8} --prefill-mode packed --gdn-prefill-mode exact \
  --decode-mode eager --decode-steps 4 --prompt-length 45 \
  --json /tmp/he-oracle-packed-r{2,8}.json          # and --capture-layer-hidden
.venv/bin/python scripts/gguf_state_slot_hash_match.py /tmp/he-oracle-packed-r2.json
```

- First-token equality holds at both widths (`tokens_exact: true`), and the plan
  reports no silent degradation: `route: slot_fair_bounded_rounds`,
  `slot_serial_fallback: false`, `all_active_slots_represented: true`.
- State: `initial_state_exact: false` / `final_state_exact: false` at both
  widths; 252 (rows 2) and 1008 (rows 8) prefill-phase mismatch rows, 253 and
  1013 post-decode, over the same **126** `(component, part, layer)` groups. KV
  hits land on exactly the 16 full-attention layers (3, 7, …, 63), so the layer
  targeting is right.
- **Zero groups are `permuted`**; every group is `unmatched`, and packed hashes
  differ *between* rows in all 126 groups. So state does reach each slot's own
  row, the slots are not cross-wired, and no group matches any reference state.
  At rows 2 the whole prompt is one 90-row chunk, so this is not a
  chunk-boundary handoff defect (rows 8 splits 45 into 32+13 because
  `row_capacity=256`, and behaves identically).
- Magnitude (`--capture-layer-hidden`): 631/640 comparisons differ at rows 2 and
  2525/2560 at rows 8, median `max_abs=0.25`, max 19.5, median 4488 of ~5106
  elements differing (~88%). That is pervasive bit-level reassociation at
  roughly one BF16 ulp over the top of the activation range — not a rounding
  artifact on a few elements, and not a wrong slot.
- Consequence: byte equality is unachievable for this route while the teacher
  persists per-token-exact state, so the oracle can neither qualify nor displace
  it. The applicable contract is the production-profile mean/tail/top-1 gate.
  `scripts/execution_profile_gguf_batch_route_gate.py` requalifies GGUF batch
  routes against independent strict-c1 teachers but exercises packed *decode*
  only, so the packed *prefill* state handoff currently has no profile evidence
  at any width — which is the actual gap.
