# R0137 F32/R28 construction ownership and graph-resource repair

## Summary

Moves the remaining gfx1100 F32 residual, F32 post-norm and R28 settings from
profile environment publication to explicit generator, runner, session and
NextN inputs. Strict binds all three off; dense production binds F32 off and
R28 on unless the construction diagnostic overrides it; MoE production binds
F32 on and R28 off. No successor process-global binding cache is introduced.
Unbound/direct callers keep their diagnostic environment behavior.

Verifier operation inputs override the bound owner, which overrides unbound
ambient diagnostics. Native graph identity includes these selections; K1's
F32 disable is an explicit invocation input rather than an environment edit.
The selected post-norm input reaches the FFN operation, and R28 reaches the
actual pair-SiLU selector while preserving capability, shape, quantization and
periodic-exact-layer checks.

Parent review also repairs three owner-transport defects in the initial
uncommitted candidate.

1. Unbound R28 again uses the historical shared policy cache verbatim. The
   prior candidate read the ambient R28 variable on every unbound launch while
   leaving the old cache entry in place, which changed unbound behavior. Only a
   bound `r28_enabled` value bypasses the cache now.
2. `verify_target_block` now validates the F32 residual pair and scratch
   actually selected for the operation. Reusable target graphs pass their
   graph-owned `hidden_f32_a`/`hidden_f32_b` and the prebuilt bulk scratch;
   direct calls still validate the resident pair. The validator uses an unset
   sentinel so a selected `None` fails instead of falling back to a different
   resident buffer.
3. Native graph admission now resolves F32 residual through the session method
   or the actual bound runner, not by calling the module helper with the session
   object. The module helper reads an owner attribute; the session stores the
   decision on `session.runner`. This wrong-owner read is a real defect and is
   fixed, but the earlier report's attribution of the bg598 `verify=[]` result
   to a token-embedding admission rejection is withdrawn. The bg598 artifact
   had ambient residual `1` but no `HIPENGINE_GGUF_VERIFY_F32_TOKEN_EMBEDDING`
   input, and it contains neither `public_metadata` nor
   `last_native_spec_target_fallback_reason`. Its `checks` stop at the two
   `constructed` ambient snapshots; the later runner-field checks never ran.
   It cannot show that a token-embedding rejection occurred. The exact bg598
   admission/fallback reason is not recoverable from that artifact; the paired
   rerun must record `last_batch_generation` /
   `last_native_spec_target_fallback_reason`.

The bg598 run is a `hip_gfx1151` live diagnostic with post-construction
generator overrides. The new binder matrix below is a `hip_gfx1100` code-level
profile test. They exercise different scopes and are not evidence for each
other.

The obsolete `_call_with_f32_verifier_disabled` environment wrapper is removed.
Its old unit test is migrated to the actual explicit K1 failure seam, which
asserts both explicit `False` operation inputs and unchanged environment. Layer
boundary capture now receives the call-resolved post-norm decision, so its
`attn_norm_f32_scratch` and `attn_post_norm_f32` metadata cannot read a
different selector than execution.

No arithmetic defaults were changed. No docs or server files were edited.

## Parent live diagnosis and real tensor regression

Initial paired checks wrote diagnostic values after public `tokenize()` had
already constructed the generator, shared runner and reserved sessions. Writes
on the service wrapper did not reach the consumer; later writes on the actual
generator were still too late for the reserved sessions. These attempts matched
tokens but did not exercise the intended verifier and are not passing evidence.

The repaired temporary harness binds the three explicit fields at the existing
gfx1151 construction binder, before the runner/session exist, then interleaves
coexisting owners under opposite ambient settings. This tests the common
transport on available hardware, not the actual gfx1100 profile or R28 kernel.
The old raw controls are public `LLM.generate_detailed()` calls instrumented
with leaf spies, not direct-kernel calls despite their `leaf-control` filename.

That run recorded source path, HEAD, runner source hash and per-output telemetry.
Owner-off reached MTP verification; owner-on reported
`precommit_failure_ar_fallback` with
`RuntimeError:GGUF verifier F32 residual hidden_f32_a is closed or undersized`.
The graph buffers are real `Tensor` handles with `numel` and `dtype`, not a
`nbytes` attribute. The validator incorrectly read them as zero-sized. Earlier
host stubs exposed `nbytes` and missed this ABI mismatch. The validator now
computes tensor capacity from `numel * dtype.itemsize` and rejects null pointers.

RED real-handle coverage (`/tmp/r0137-f32-real-tensor-red.log`): 4 failed,
3 passed. It includes row counts 1, 2 and 5, null handles and an undersized
second tensor. GREEN affected profiles, R28, verifier and native-cycle checks
(`/tmp/r0137-f32-real-tensor-green.log`): 164 passed, 1 GPU-only skip.
The diagnostic failure report is
`/tmp/r0137-f32-paired-bound-dense-0-1.json`; it records a clean teardown.
