# Bind ordered QSA prerequisite to execution ownership

## Summary

Move R0450's ordered-QSA prerequisite transport into explicit profile/runner
ownership while preserving unordered, ordered-v1 and runner-owned ordered-v2
arithmetic choices. Baselines and CPU RED tests preceded the implementation.

## Changes

- The runtime now forwards `qsa_ordered_decode` through scalar target and draft
  layers, with profile publication and serving clone inheritance. The H256
  guard, separate v2 count/registry checks and batch rows selector are unchanged.
- Campaign and drift controls read the runner prerequisite. Candidate and
  snapshot-based scripts carry explicit declarations and reconstructed binding
  values rather than process overrides. Whole-layer graph probes forward it.
- Parent review found `prefill_restore_ab` passing a candidate's `None` into
  the boolean scope, silently disabling the production reference. A guarded
  arm scope now preserves undeclared values, with dynamic regression checks.
  This was a caller migration defect, not an arithmetic change.
- Review also found that shared `bind_candidate_owners()` omitted the ordered
  route and its v2 leaf. Both are now bound on the measured runner when declared,
  reported with effective values and restored on normal or exceptional exit.
  Twelve dynamic cases cover declared None/False/True, both published values
  and both exit modes; the initial six-case test failed before this repair.
- The environment reference documents the retired control; the audit flag row
  records remaining diagnostic literals as discarded transport, not selection.
