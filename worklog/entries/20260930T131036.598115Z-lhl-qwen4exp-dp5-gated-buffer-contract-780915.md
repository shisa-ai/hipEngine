# DP-5 is gated, not actionable: it needs a producer-to-consumer F16 buffer contract that does not exist

## Summary

DP-5 was the highest-ranked remaining build candidate after its consumer census, and the row
reads as a bounded kernel change - "move the F16 write into the HC mix epilogue first". The
code was checked before starting it, and **the change cannot be made as described.** The cast
path has no "input already F16" check, and none is possible with the current ownership: the
route binds **exactly one** bounded scratch buffer shared by every consumer and overwritten
per launch, so there is nowhere for a producer to publish a persistent F16 copy and no
protocol for a consumer to accept one. DP-5 is reclassified from actionable to **gated**.

## A verification mistake caught in this iteration

The first attempt to update §11 used a hardcoded census string in the *verifier*,
so it reported 23/15/32/1 while the ledger still held 24/14 - it verified my intent
instead of the artifact. The edit script had also died on an assertion whose
pattern was wrong (a colon where I had written `**`), so nothing had been written
at all.

The re-run parses the census table **out of the ledger** and checks each class's
declared count against its own listed IDs. That is the form that can fail.

## Why the re-scoping matters more than the 0.36%

DP-5's action cell told a reader to move an F16 write into an epilogue. That reads
as an afternoon of work. It is actually a change to how the runtime owns
activation buffers across an op boundary, and the measured prize is 55.9 ms =
0.36% of prefill. Without this note the next reader - or the next agent - starts the
epilogue edit and discovers the ownership problem after committing to the work.
