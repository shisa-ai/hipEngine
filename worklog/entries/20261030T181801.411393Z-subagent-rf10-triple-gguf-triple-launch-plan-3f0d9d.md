# Add typed triple launch planning to GGUF linear runtime

## Summary

RF-10 triple slice. `launch_gguf_linear_triple` previously resolved three
dispatches, the WMMA decline, the Q8T16 owner check and the exact-versus-rowtile
choice inline while binding raw tile pointers. The launch path now resolves a
private, immutable `_GGUFTripleLaunchPlan` at the shape/resource boundary and
executes it immediately.

The plan carries the backend, shape, three `_GGUFTripleOperand` contracts
(layout, quant, output width, owner slot, dispatch), the selected operation, the
fused owner `KernelKey`, resolved threads, the WMMA policy input, the declared
fallback reason and the registry generation. It contains no device pointers,
tile allocations or scratch generations. Execution re-reads each weight's
`tiles` allocation, so a resident reallocation is picked up only when its owner
slot, logical geometry and byte count still match the plan; it rejects a plan
reused with a different layout, quant key, backend, owner slot, shape, allocation
size or registry generation.

The plan is intentionally not exported and has no execution-profile owner. It
is launch-local: callers must re-resolve after a profile or registry change. A
future owner-bound reusable plan must carry a token derived from
`ResolvedRuntimeProfile` under RF-1/RF-10, not an `ExecutionProfile` enum.

Public behavior is preserved: `launch_gguf_linear_triple` keeps its signature and
return contract, resolves with the existing ambient WMMA/rowtile resolvers, and
returns `False` for the same declines. The private resolver accepts explicit
`use_wmma_prefill` and `rowtile_all` inputs for tests and future owner plumbing,
instead of adding another ambient global.
