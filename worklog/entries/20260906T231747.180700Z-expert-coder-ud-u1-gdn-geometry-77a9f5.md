# Validate shared GDN invocation geometry

## Summary

P2 follow-up to [the integrated F3/F4 entry](20260906T210704.107736Z-expert-coder-ud-u1-invocation-binding-wip-ab056a.md)
and commit `910152628`: recording GDN geometry did not qualify it. A filtered
`layers.0.ssm_a` plan with 3 key heads and 16 value heads previously minted a
complete certificate although the real wrapper rejected it. Likewise c1
value-head dimension 129 exceeded the wrapper's limit but qualified.

Shared CPU-safe geometry validation now runs before a positive invocation is
recorded. Invalid geometry remains in independently required slot/invocation
accounting, refuses the report, cannot mint and cannot compare successfully
against a valid certificate. Implementation is complete pending independent
review. F1 execution dependency/entry authorization and F5 profile binding
remain OPEN. No .hip, math, numerical/default policy, kernel, U2+ or GPU work.

## Changes

- `qwen35_gguf_consumer_surface.py` owns `validate_gdn_geometry`: positive key
  and value head counts, value heads divisible by key heads, positive key/value
  dimensions, and c1/row-local `head_v_dim <= 128`. Actual c1 lowp F32/FP16-state
  wrappers call it through `_check_gdn_shape`; segmented F32/FP16-state and
  baseline fused prefill wrappers call it through `_check_prefill_shape`.
  The latter retain their existing uncapped positive value-head contract.
  Existing positive token/segment checks remain at the wrappers; admission's
  row domains already require positive tokens. Exact-chain specializations
  retain their additional existing constraints; their rules were not imposed
  on the different qualified baseline boundary.
- `gdn_value_head_dim` owns exact inner-size / value-head derivation, requiring
  positive inner size and head count and exact divisibility. Both admission
  and the actual runner `ssm_value_dim` property use it, so an incomplete head
  cannot be silently truncated into a valid-looking invocation.
- Adjacent `validate_conv_geometry` shares the existing positive channels and
  kernel-size rules between conv wrappers and admission's conv invocation.
  No new convolution or GDN storage/entry dependency authorization is claimed.
- `Qwen35GGUFOperationCoverage.invocation` validates geometry against the
  resolved consumer boundary. Existing ValueError-to-consumer-refusal handling
  preserves independent required accounting without changes to certificate,
  partner, backend, dtype, row, or resident identity comparison.
- New `tests/test_gguf_gdn_geometry_contract.py`: negative report/mint/transfer
  and accounting tests; real typed-wrapper mocks for c1, row-local, segmented
  and prefill including both state types; value-head bounds 1/127/128/129;
  key head neighbors 1/2/16 and incompatible 3; runner exact-division tests;
  conv geometry parity. Payload reads and allocator calls are forbidden.
  The selected scalar's source shape remains 16 value heads in the compatible
  and two reported failure cases; other out-of-scope synthetic layer tensors
  are not asserted as a complete physically valid model. Explicit zero
  dimensions are intentionally invalid metadata negatives.
- `docs/UD-QUANTS.md` records this geometry follow-up as pending independent
  review and leaves F1/F5 open. No architectural plan or temporary flag changed.
