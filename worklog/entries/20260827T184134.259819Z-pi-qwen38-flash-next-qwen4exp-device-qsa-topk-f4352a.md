# Move QSA top-k selection to device

## Summary

Promoted device-only exact QSA top-512 selection and sorted token expansion.
Natural 4K prefill improves 3.00% while removing every score D2H synchronization,
host lexsort, and selection-metadata H2D from the sparse prompt path.

## Changes

- Added a one-CTA four-pass nonnegative-FP32 radix threshold kernel. Stable
  wave-prefix compaction chooses lower block indices at exact threshold ties,
  expands each block to four ascending token positions, and appends only the
  real incomplete tail.
- Added a registered raw-pointer wrapper under
  `qsa_select_blocks/f32_i64/strict_device_expand`.
- Added `select_positions_device()` and switched c1 plus row-bulk QSA selection
  to device scores/top-k. Prompt metadata is written directly on device; one
  D2D copy per layer/chunk retains the latest selection for diagnostics.
- Updated the natural gate to download final selections/scores only after its
  timed runtime execution.
- Artifact:
  `benchmarks/results/2026-08-27-gfx1151-qwen38-flash-next-device-qsa-topk.json`.

## Validation

- RED: the top-k wrapper did not exist.
- Exact tie/tail fixtures pass at query positions 4,094 and 4,095.
- Random host-lexsort parity passes at 513, 4,096, and 65,536 blocks.
- QSA HIP/runner/retrieval focused bundle: 15 passed.
- 65,536-block micro: device 128.224 us, host lexsort 3,656.215 us (28.51x),
  before counting D2H synchronization.
- Cached `rocprofv3 --kernel-trace` records
  `qsa_topk_expand_f32_i64_kernel` at 114,416/179,980/669,181 ns for
  513/4,096/65,536 blocks, workgroup 1,024, 24 VGPR, zero scratch.
- Natural 4K: persistent+host-topk 303.528 s → device-topk 294.434 s
  (-2.996%, 1.031x). Versus the pre-QSA-units 304.944 s, total -3.447%.
- Removed 75,399,168 score D2H bytes / 24,540 synchronizations, 18,849,792
  host-sorted score values, and 403,341,312 metadata H2D bytes. Retained final
  diagnostic D2D is 6,302,208 bytes.
- Generated IDs unchanged; exact `VIOLET-7391`, 12/12 needle selection,
  Transformers positions 2,048/2,048, exact replay/rollback, zero teardown.
- Initial post-change score-error fields were stale host-mirror garbage after
  removing runtime D2H; they were non-binding and are not retained. The script
  now explicitly downloads the final score row after timing.
