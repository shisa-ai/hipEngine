# Expose compact BF16 DMS through public single-request serving

## Summary

Expose the existing Qwen GGUF compact BF16 DMS session through the public LLM
and HTTP server, without adding a scheduler or binding dense global-pool KV over
compact retention state.

## Changes

- Add typed `DMSConfig` and generator capability-based configuration. Unsupported
  generators and explicit incompatible storage/concurrency/prefix/speculation
  fail rather than ignoring the request. Python omitted settings resolve to the
  implemented single-request composition; server settings must be explicit.
- The model adapter uses the normal resident scheduler for streaming, admission,
  cancellation, deadlines, sampling, and output processing. It collects prefill
  chunks for the existing full-prompt DMS prefill and uses eager compact decode.
- Keep weights shared, but close request sessions on reclaim because dense
  `reset()` does not reset the compact owner. This prevents stale compact leases
  on reuse. No alternate scheduler, kernel, arithmetic, or environment flag.
- Add retention metadata, CPU configuration tests, public lifecycle tests,
  `--dms-metadata` / `--dms-prefill-mode`, and `docs/reference/DMS-SERVING.md`.
- RED-first was not used for initial wiring: existing low-level primitives were
  integrated with a real public request first. Live testing caught an incorrect
  test assertion treating `memory_stats()` as an object, repaired to dictionary
  keys. Integration testing caught an unconditional new keyword sent to a legacy
  constructor double; omit the keyword for non-DMS servers.

## Validation

- Public smoke `/tmp/dms-public-smoke.py`: two sequential greedy public requests
  returned identical output on gfx1151, local Qwen3.8-27B-Q4_K_M GGUF and the local
  W8192 sidecar at context 1024. No throughput or quality claim.
- Initial full live lifecycle test passed after the assertion repair:
  `HIPENGINE_HIP_ARCH=gfx1151 uv run pytest -xq tests/test_live_dms_public_serving.py`.
  Real compact backend ownership was observed during streaming; dense global
  pool was absent. Stream cancellation followed by identical generation, sampled
  generation, HTTP `/ready`, completion and teardown allocation equality passed.
- Expanded live validation passed all three modes: dense_pool/sidecar,
  layer_outer/sidecar, and dense_pool/no_evict. Log:
  `/tmp/dms-public-modes.log`. These are ownership checks, not a claim of
  numerical equality between dense and compact attention.
- Final default unit tier passed with exit 0; log
  `/tmp/dms-public-unit-final.log`.
- Focused configuration, compact allocator and layer-outer tests pass. The server
  API integration file passes after focused repair. Existing tool-stream,
  tool-constraint, model-protocol and prefix integration tests pass.
- CPU fixture, registry/CPU smoke, compileall and documentation gates pass.
- The audit gate reports the existing untriaged backlog, assigned to task 6;
  no budget changes. Generated inventory is left for that cleanup unit.
