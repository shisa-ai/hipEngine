# Retain sole-T16 Q4 dual-WMMA SiLU prefill

## Summary

Reopened the previously exhausted Qwen3.6-27B prefill objective with a materially
new operation-complete sole-resident Q4 dataflow. One four-wave kernel now owns
the dense K=5,120/N=17,408 FFN gate/up pair and SiLU at M>=512, reusing each
BF16 activation fragment across both independent T16 weights and eliminating
both global projection intermediates. It is BF16-bit exact to the unfused
projection-boundary chain, adds no workspace or persistent payload, and improves
full prefill on both gfx1100 boards at every 512/1K/4K target.

## Changes

- Added and registered `dense_dual_wmma_prefill_bf16_bf16_out` under the
  `linear_pair_silu/gguf_q4_k_t16_v1` operation key.
- Added a 128-thread/four-wave HIP kernel that decodes two sole-T16 slabs into
  one 32-KiB LDS union, loads each activation K16 fragment once, applies both
  FP16-WMMA projections, explicitly rounds both results to BF16 in LDS, and
  applies SiLU before one BF16 global output write.
- Routed only the Qwen3.6 dense FFN shape at rows >=512. Rows below 512,
  unsupported shapes/layouts, registry misses, decode, and verifier/MTP small
  rows retain the existing registered unfused owners.
- Added dispatch/fallback tests and HIP equality tests including the M513 row
  tail. Updated the kernel catalog, compact benchmark artifact, scoreboards,
  campaign status, and changelog.
