# EAGLE-4 cycle on graph-captured native target verify (part a integration)

## Summary

Task #25 part (a), integration increment (campaign §6.2-3, §6.4 P1 row 1). The
EAGLE-4 cycle now runs its target verify through the reusable native target graph
(`verify_qwen35_gguf_native_b2_target`) instead of eager `verify_target_block`,
with the aux-layer rows captured into graph-owned device FP32 buffers (the
prerequisite landed in 0b9a75a6a). The graph captures once per context bucket and
replays with one launch, removing the eager per-cycle host dispatch and the
per-cycle aux D2H from the verify phase. The drafter still owns accept + append;
the host deferred linear-state commit (`_commit_verify_linear_state_row`) works
unchanged because the graph launch repopulates the session hidden-seed and
linear-state row buffers.

Measured A/B (gfx1151, Qwen3.8-27B-Q4_K_M, n_draft=2, 3 prompts x 25 tokens, 33
cycles, same process/thermal state, median per cycle):

| phase | eager | graph |
| --- | --- | --- |
| verify | 140.8 ms | 126.2 ms |
| draft | 51.2 ms | 51.9 ms |
| aux+append | 14.3 ms | 16.0 ms |
| cycle wall | 217.3 ms | 195.3 ms |

Graph ran 33/33 cycles (no fallback). Verify+aux combined 155->142 ms (the aux D2H
moves out of verify into the append phase). Cycle wall -10%. The win is modest
because the graph-captured device route is slower than the eager device route:
the eager verify is dispatch-bound (~131 ms host enqueue vs ~98 ms synced device),
but the graph replay's device compute is ~120 ms — the graph freezes a slower
native-attention route (per-row decode scratches + context bucket) than the eager
bulk schedule. Closing that device-route gap is the next perf lever; the infra
here is what makes it addressable.

## Changes

- `hipengine/runtime/gguf_native_spec_cycle.py`: thread `capture_layer_output_hidden`
  through `_native_target_configuration_key`, the graph dataclass
  (`capture_layer_output_hidden`, `layer_output_hidden_rows`), `compatible_with` /
  `launch_ineligibility_reason` / `can_launch`, the capture function (normalize +
  validate aux ids, reserve one graph-owned FP32 `(rows, hidden)` tensor per layer,
  pass `capture_layer_output_hidden` + `_graph_layer_output_hidden_bufs` to the
  enqueue-only verify), the non-device-accept launch (expose
  `layer_output_hidden_device` ptrs on the result), and the entry point (eager
  fallback kwargs, aux-aware cache key, alias read/write guarded off for aux).
- `hipengine/runtime/qwen35_gguf_runner.py`: `Qwen35GGUFBlockVerifyResult` gains
  `layer_output_hidden_device: dict[int,int] | None`; enqueue-only aux validation
  accepts a Tensor destination (numel x itemsize) as well as a DeviceBuffer.
- `hipengine/speculative/eagle4_cycle.py`: `run_eagle4_cycle` verifies via the graph
  entry point (fallback=True), counts `graph_verify_cycles`, and reads aux rows
  from the device pointers when present (host projection unchanged for now).
- `tests/test_gpu_native_target_graph_aux_device.py`: HIP-guarded real-model test —
  graph tokens == eager, graph submitted (no fallback), aux device rows finite +
  correct shape + gross-bug guard, replay from cache.
