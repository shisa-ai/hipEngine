# Expose integer-dot Inkling through the explicit fast profile

## Summary

Expose the verified integer-dot NVFP4 projection through the explicit `fast` execution profile on both gfx11 targets. Default and `strict` retain the existing FP32 projector.

## Changes

- Register the raw NVFP4 kernel with its packed Q8 activation step. Confine selection to single-token, eight-route projections with the tested inputs and output widths. Other shapes and prefill keep the existing exact path. Reserve quantization scratch under the projection owner's lock and release it on close.
- Bind `fast` and `strict` through the public profile registry, with the exact register-table NVFP4 kernel declared as the fallback. No environment flag or artifact identity gate is introduced.

## Validation

- The profile test first failed on missing strict and fast registration. It now verifies that `fast` resolves on both backends, points to the declared strict fallback, and is not the default. Focused W7900 tests matched both projection widths to the quantized CPU reference, including zero groups, optional scales, independently permuted routes, and out-of-range route handling.
- The CPU deterministic and documentation gates passed. On both real checkpoints, public `LLM.stream_detailed()` selected the requested strict or fast profile and preserved all nine generated IDs at 47 and 151 inputs. The Strix `rocprofv3` kernel trace showed 704 FP32 expert projections in each eight-step strict mark, and 704 Q8 packing plus 704 integer projection launches in each fast mark. The [short numerical result](20261122T042314.583479Z-lhl-inkling2-mini-fbe423.md) and [wrap/isolation result](20261122T042949.371522Z-lhl-inkling2-mini-dadf33.md) are for the scratch precursor, not production admission.
