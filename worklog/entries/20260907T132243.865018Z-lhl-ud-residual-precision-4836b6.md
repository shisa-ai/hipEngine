# Diagnose UD residual precision with a scalar-exact control

## Summary

The BF16 control for the residual-precision experiment reproduces the prior
scalar raw Q5/Q6 capture bitwise at all 36 full-vocabulary logit rows. F32
residuals lower the subset's mean KL, but still fail the mean and p99 limits;
the worst error moves to another prompt. Residual precision alone does not
resolve the numerical blocker. No default changes.

This follows [the common-KV numerical failure](20260907T130613.611855Z-lhl-ud-common-kv-0e56e0.md).

## Changes

No runtime changes. On zbook / Radeon 8060S / gfx1151, the existing one-row
verifier runs the published Qwen3.8-27B UD Q4_K_M file with identical compact
raw Q5/Q6 residency in both arms. It changes only the requested residual
precision, holding BF16 embeddings, BF16 KV, row LM-head routing and the
one-token schedule fixed. Prompts 0, 4, 10 and 17 use the existing 512-token
synthetic contexts followed by eight forced continuation tokens. This selected
subset diagnoses arithmetic; it is not the complete task-quality suite.

`/tmp/ud-residual-precision-compare.py` checks source/input hashes,
actual resident-manifest equality, finite logit geometry and bitwise BF16
control parity. It reports teacher-to-candidate KL by prompt and position,
plus the paired F32-minus-BF16 teacher-KL difference. Input hashes are in
`/tmp/ud-residual-precision-input-manifest.json`.

```bash
PYTHONPATH=. OPENBLAS_NUM_THREADS=4 \
HIPENGINE_COMPILER_VERSION_FILE=/tmp/ud-hipcc-version.txt \
.venv/bin/python -u /tmp/ud-residual-precision-probe.py bf16
PYTHONPATH=. OPENBLAS_NUM_THREADS=4 \
HIPENGINE_COMPILER_VERSION_FILE=/tmp/ud-hipcc-version.txt \
.venv/bin/python -u /tmp/ud-residual-precision-probe.py f32
OPENBLAS_NUM_THREADS=4 .venv/bin/python /tmp/ud-residual-precision-compare.py
```

## Validation

The BF16 control matches the prior scalar raw capture bitwise: mean/max KL
zero and 36/36 top-1 matches. Against the common-BF16-KV teacher, its selected
subset has mean KL 0.001828660492, p95 0.010120554202, maximum 0.030410558805
and 36/36 top-1 matches. Do not compare these subset aggregates to the prior
162-position full-suite aggregates as an improvement or regression.

The shared CPU comparator passes an analytical teacher-to-candidate KL check
for distributions [0.5, 0.5] and [0.75, 0.25], independent logit-shift
invariance, and rejection of unequal shapes and NaN/Inf inputs. The queued
comparison script passes `python3 -m py_compile`.

Both capture arms and the queued comparison completed successfully. Their
851-slot actual resident manifests are equal. The compact artifact
`benchmarks/results/2026-09-07-zbook-ud-residual-precision.json` preserves
source snapshots, input/output hashes, runtime commit, per-position results
and the actual manifest.

| Residual | Mean KL | p95 KL | p99 KL | Maximum KL | Top-1 |
| --- | --- | --- | --- | --- | --- |
| BF16 | 0.001828660492 | 0.010120554202 | 0.023376708515 | 0.030410558805 | 36/36 |
| F32 | 0.001381784513 | 0.003574629860 | 0.021304369463 | 0.030485508999 | 36/36 |

Against the unchanged aggregate limits, BF16 fails mean, p95 and p99; F32
fails mean and p99. F32 lowers prompt 10's maximum from 0.03041056 to
0.00333836, but raises prompt 4's maximum from 0.01005612 to 0.03048551.
This is not a uniformly improved path or a complete qualification gate.

Source inspection confirms an integration boundary: public scalar `step()`
calls `_run_current_hidden_to_final_hidden`, whose layer loop uses BF16
hidden buffers and does not forward F32 residual pointers. The verifier
flag therefore does not repair public scalar decoding by itself. Its F32
path retains BF16 projection inputs; it is not a full-F32 model graph.
