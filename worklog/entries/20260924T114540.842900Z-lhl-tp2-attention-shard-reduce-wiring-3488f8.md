# Wire the head-sharded attention-output reduce into every path that runs a layer

## Summary

Head sharding makes each rank's attention phase produce a hidden-size *partial*:
the rank's own heads' contribution to `attn_output` (full attention) or `ssm_out`
(GDN). The post-attention norm consumes the **sum**, so a head-sharded layer that
does not reduce between the two produces output that is wrong rather than slow -
each rank's residual would carry only its own half.

This unit wires that reduce into all three places a layer actually runs. It is
three call sites rather than one because the session reaches a layer three
different ways, each with its own reduction mechanism:

| Path | Mechanism | Slot |
| --- | --- | --- |
| `_bulk_attention_reduce` (bulk prefill) | `_bulk_shard_group.reduce_device_payload(..., phase=1)` | `2*(layer%2)+1` |
| `_reduce_attention_partial_eager` (`_enqueue_layer`) | `_shard_group.reduce_device_payload(..., phase=1)` | `2*(layer%2)+1` |
| `enqueue_rank` inside `_capture_layer_graph` | the session exchange, captured into the layer's graph | `layer_count + layer` |

The first two use the group's exchange because that is where their MLP reduction
already goes; the captured path uses the session's exchange because that is where
its MLP reduction already goes. Only one mechanism is live per phase, and the two
exchanges have separate counters and staging, so they do not interact.

The reduce goes between the attention phase and the post-attention norm and
nowhere else, which is the ordering the layer already had: attention writes
`attn_out`, the norm reads it.

## Changes

- `_bulk_attention_reduce` + `_bulk_attention_output_ptr`: the bulk loop now
  reduces the partial and the norm reads the reduced buffer.
  `_bulk_shard_group` gets `reductions_per_layer=2` and a per-rank
  `_bulk_attn_reduced` buffer.
- `_reduce_attention_partial_eager` + `_attention_reduce_output` /
  `_attention_reduce_destination` / `_attention_exchange_slot`: the eager decode
  body reduces through the decode group's exchange.
- `_capture_layer_graph` enqueues the attention reduction inside the layer's own
  graph. It cannot defer it to the next layer's segment the way the MLP partial
  is deferred, because the partial is both produced and consumed inside one
  graph.
- The session exchange widens to `num_layers = layer_count * 2` when head
  sharding is on, and the attention reduction takes slots `layer_count + layer`
  rather than renumbering the MLP's. **The unsharded slot layout is therefore
  unchanged**, so the validated graphed decode schedule is not perturbed.
- The decode group also gets `reductions_per_layer=2`, which is what admits
  `phase=1` on its exchange.
- Each reduce writes a destination buffer distinct from the rank's own partial.
  The spin-add kernel declares its input and its output `__restrict__`, so an
  in-place update would make that contract false for a read-modify-write it does
  not need to perform.
- `docs/REFACTOR.md` updated: the guard is gone, and the entry now records that
  `_enqueue_layer` and `_capture_layer_graph` are two copies of one layer body
  that have to stay in sync.

## Validation

Unit tier, all CPU (fakes, no GPU):

```
python3 -m pytest tests/test_unit_distributed_*.py
240 passed in 21.63s
```

The three new tests pin the wiring contract rather than the arithmetic:
`test_bulk_attention_reduce_takes_the_attention_phase_slot` (the reduce takes
`phase=1`, reads each rank's own `attn_out`, and writes the separate destination
the norm then reads), `..._is_a_no_op_without_head_sharding` (the unsharded route
issues no reduce and still reads `attn_out`), and `..._needs_the_device_reduction`
(a host-reduced group refuses instead of silently skipping the sum). The GPU
attention-shard test's guard assertion is replaced by a check that the attention
slots start after the MLP's (`[4, 5, 6, 7]` for a four-layer config).

**End-to-end numerical validation is not yet done.** The second GPU is shared
with a benchmark campaign from `/home/lhl/hipEngine-gemma4` that holds 19-23 GB
of the 25.7 GB XTX for minutes at a time; a two-rank session needs ~15 GiB per
rank. Three attempts either OOM'd in `_build_rank` or were overtaken by the next
campaign run. The run is queued behind a free-VRAM gate and writes each route's
logits as soon as they exist, so the outcome lands in this entry's follow-up
rather than being assumed here.
