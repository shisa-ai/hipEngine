# Q5_1 selected MMQ kernel; packet pending layer screen

## Summary

New raw-Q5_1 selected-expert MMQ consumer (Q8_1 d4x3 activations, DP4A
sudot4, plane-order nibbles, register accumulators over 16-row passes) with a
RED-test harness and env-gated runner wiring. At the real down shape
(5080 compact rows, 512 experts, 640->2560) it measures 5.06 ms vs the strict
grouped owner's 38.40 ms (7.6x); combined with the certified Q8 dense MMQ the
p508 strict wall falls 8.270 -> 5.928 s (-28.3%, 85.7 tok/s) with the
single-plane producer. The complete 450-row packet FAILED on the full-layer
configuration (mixed_ja_en mean KL 1.44e-3 over its category gate; one
first-run-only state SHA row with trajectory determinism exact), so the env
stays default-off and the next unit is the per-layer admissibility screen
that every prior MoE production variant required.

## Validation

- Microbench (real shape, best-of-10): owner 38.40 ms, MMQ (1-plane) 5.06 ms.
- p508 combined candidate (Q8+Q5_1 MMQ, 1-plane producer): median 5.928 s /
  85.70 tok/s vs strict 8.270 s (-28.3%); deterministic SHA, top-1 unchanged.
  d4x3 variant: 6.428 s / 79.03 tok/s.
- 450-row/three-repeat gate, full-layer Q5_1 MMQ (d4x3): mean/p95/p99/max KL
  6.93e-4/2.72e-3/8.42e-3/3.91e-2, top-1 446/450; code 1.66e-4 passes;
  mixed_ja_en 1.44e-3 mean FAILS its category gate; one prompt's first
  candidate state SHA differs from repeats 2-3 (trajectory SHAs exact).
  NOT admitted; earlier single-plane run measured 8.76e-4 mean, 444/450.
- Kernel-level fixes found by measurement: sub-block stride bug (w_block not
  advanced per sub), plane-order nibble layout (repo dequant is low-plane
  values 0-15 / high-plane 16-31), and the m*sum correction must apply only
  on plane 0 (residual-plane sums must not enter).
