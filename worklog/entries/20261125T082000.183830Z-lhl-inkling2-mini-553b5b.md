# Prepare Inkling attention inputs in one launch per row group

## Summary

Second unit of the decode fusion work (task 10), after
[the shared route inputs](20261125T081020.500625Z-lhl-inkling2-mini-fac8ee.md). Each attention visit
ran four single-block launches to prepare its rows: the query clip, the key clip, the value
normalization and the relative clip. They are now one launch of four blocks per row, each block
the arithmetic of the kernel it replaces.

**Decode bench, `fast` with the resident traversal and device routes** (256-row blocks, 128
outputs, five repetitions, W7900, mainline `UD-Q4_K_M`, working tree over `e9839db2f`):

The first token is unchanged within run-to-run spread.

## Changes

- `inkling2_attention_prepare.hip`: `inkling2_prepare_group` and the entry point
  `hipengine_inkling2_attention_prepare_group`, registered as
  `inkling2_attention_prepare/inkling2_mixed/group` on both HIP backends. The relative clip keeps
  its own width; `logscale` applies the position scale to the query and relative clips only.
- `Inkling2GGUFDeviceProjections._attention_kernels` takes the group when it is registered and
  keeps the four launches otherwise.

## Validation

- `tests/test_gpu_inkling2_prepare_group.py` (4 passed on the W7900): for one and five rows, with
  and without the position scale, the group's four outputs equal the separate launches bit for bit.
- The nine Inkling GPU test files pass on the W7900: 61 passed in the run without the model, and
  the four model-level block-route tests passed with `HIPENGINE_INKLING2_MINI_GGUF` set.
- The public route ran the group in the bench above: resolved profile `fast`, no fallback, the
  same 128 output tokens at every depth in both arms.
