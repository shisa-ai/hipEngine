# Repair physical MTP provider and target reseed ownership

## Summary

Root-cause and repair the W7900 physical dense C2/K1 acceptance collapse. The
original clean gate was exact but accepted only `1/8` drafts and ran at `0.503x`
AR. Differential candidate/target/state tracing shows the first physical
candidate vector and GPU accept are correct. The collapse begins after the first
cycle through two missing ownership contracts:

1. packed NextN execution advanced the session's next-input cursor but also
   published it as the last consumed position/context, so checkpoints and P7
   after-root snapshots were one token ahead; and
2. physical target selected-state commit installed FP32 hidden seed, recurrent
   state, KV, and cursors but omitted the selected pre-output-norm BF16 trunk row
   consumed by the next target-attached NextN proposal. Every later cycle reused
   stale prompt hidden.

With both repaired, the same C2/K1 D8 diagnostic remains exact, acceptance rises
`1/8 -> 4/6` (`12.5% -> 66.7%`), wall improves `1.7056 -> 1.4755 s`, and the
AR ratio improves `0.503x -> 0.584x`. This is a real acceptance/dataflow repair,
not yet a physical capability or performance promotion.

## Changes

- Add a consumed-position publisher after physical hidden-row execution:
  `position_host=input_position`, `context=input_position+1`, while the resident
  session cursor remains the next input position.
- Make P7 after-root metadata store consumed position/context and restore the
  session's next cursor from context instead of conflating all three values.
- Extend device target results with pre-output-norm BF16 trunk rows.
- Select/commit one BF16 trunk row per request through the existing device
  `dflash_commit_chain_i32` owner and update stable `last_target_hidden` before
  the next provider proposal.
- Add RED/GREEN tests for packed cursor publication, after-root metadata, device
  result shape, and selected target-hidden commit calls.

## Validation

- Candidate differential: C1 and initial C2 candidates agree (`198@37 -> 8160`,
  `248068@36 -> 271`) and CPU/GPU accept agree. Before repair later C2 candidates
  were `198/727` versus C1 `264/8160`.
- Provider state differential localized reject repair from C2 cursor `37/38`
  versus C1 `36/37`; cursor RED/GREEN restores `36/37`. Remaining visible KV
  drift identified physical arithmetic separately from the acceptance collapse.
- Dirty-source W7900 GPU0 D8 causal gate after full repair: exact IDs,
  accept histories `[1,0,1]` and `[0,1,1]`, wall `1.475456 s` versus AR
  `0.861863 s` (`0.5841x`).
- Affected provider/checkpoint/MTP2/packed-target/service/perf-bridge bundle:
  164 passed. Python compile and diff checks pass.
