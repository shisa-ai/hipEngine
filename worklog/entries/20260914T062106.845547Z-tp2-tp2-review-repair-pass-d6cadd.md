# Review repair pass: KV-head replication, the free() regression, and the break-even count

## Summary

External review of the Packet 0-2 completion claim found three defects. All three
are confirmed here; two are fixed in this pass and the third is fixed with the
number that replaces it. This entry supersedes the completion claim in
`worklog/entries/20260913T233937.141001Z-tp2-tp2-packets-0-2-complete-d666f9.md`
and the go verdict in
`worklog/entries/20260913T232704.019802Z-tp2-tp2-break-even-go-no-go-e4a15b.md`.

**1. The branch does change `hipengine/core/memory.py`, and it caused the unit
failure.** The completion entry claimed the failing packed-prefill cancellation
test was "outside this packet" because no file in its path appeared in
`git diff --name-only 7fecb576c..HEAD`. That diff base is wrong: `7fecb576c` is
itself the second commit on this branch, and the file it excludes is exactly the
one that commit changed. Against the branch point `a9aa29c36`, `core/memory.py`
has 94 insertions and 6 deletions. `free()` began reading `buffer.device`
unconditionally, and the test injects `SimpleNamespace(ptr=..., nbytes=...)`
stand-ins, so the call raised `AttributeError` where it previously called
`runtime.free(buffer.ptr)`. Reviewer repro: restoring only the pre-branch `free()`
makes the test pass.

Fixed: `_buffer_device()` reads the attribute with a fallback, so unattributed
`DeviceBuffer`s and duck-typed stand-ins keep the previous current-device
semantics while attributed buffers still select their own device.
`copy_device_to_device` uses the same accessor so it raises its documented
`ValueError` instead of `AttributeError`. New test
`test_free_accepts_unattributed_and_duck_typed_buffers` covers both buffer shapes
and the copy refusal; the previously failing test now passes.

**2. The break-even used 36 collectives per token; the inventory says 128.** The
model has 64 autoregressive blocks (65 declared, block 64 is the MTP block) and
every block contributes exactly two row-split (input-axis) tensors - 64
`ffn_down`, 48 `ssm_out`, 16 `attn_output` - so a decode token has **128**
cross-rank reductions. The 36 was hand-written in the shard-planner entry and
never checked against the manifest, and the projection then compared that budget
against itself.

Corrected projection (128 x 28.6-35 us = **3.66-4.48 ms** per token against
33.5-35.8 ms of single-GPU decode, 11-13% rather than 3-6%):

| Device | Break-even budget | Headroom | Projected speedup | Rows below 1.3x |
| --- | --- | --- | --- | --- |
| W7900 (27.9 tok/s) | 11.23-16.04 ms | 2.5-4.4x | 1.23-1.53x | 2 of 8 (both 30% fixed share) |
| XTX (29.82 tok/s) | 12.96-18.52 ms | 2.9-5.1x | 1.34-1.80x | 0 of 8 |

The verdict changes from "every row clears the target" to "14 of 16 rows", and
`collective_would_have_to_be_worse_by` falls from 7.5x to 2.5x. The exposed
collective *count* is now the binding constraint: per-op latency would have to
improve 2.5x for the worst row, while halving the number of exposed reductions
would restore the margin. The decision is therefore **conditional go** -
proceed to Packet 3 on the XTX projection, treat the W7900 30%-fixed-share
corner as a known marginal case, and make exposed-reduction reduction a Packet 3
requirement rather than an optimization.

**3. KV-head replication assigned the wrong heads.** `partition_groups`
replicated with round-robin (`rank % groups`) when a segment held fewer groups
than ranks. On the KV axis that hands rank 1 KV head 1 while rank 1's own query
heads (3-5 of 24, six query heads per KV head) attend to KV head 0. At degree 8
with 24 query heads and 4 KV heads, **6 of 8 ranks** received a KV head their
queries never read - silent wrong attention, not a refusal. Replication is now
block replication (`rank // (world_size // groups)`), so consecutive ranks share
a head, which matches the consecutive query-head blocks; a group count that
cannot be replicated uniformly is refused instead of handed out unevenly. The
test that enshrined round-robin is corrected and a new invariant test asserts
the property directly: for every degree, a rank's KV heads are exactly the ones
covering its own query-head block.

This is unreachable at N<=4 for Qwen3.8-27B (kv_heads=4 and larger degrees are
refused by the MLP row-split divisibility), so no measured result in this branch
is affected. It is reachable for models with fewer KV heads than ranks, and it
was reachable in the helper's own tested contract.
