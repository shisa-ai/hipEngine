# Build deterministic DMS oracle labels

## Summary

Implemented deterministic future-attention distillation labels over the
checksummed exact-GGUF capture format. The CPU FP64 oracle is normative; a tiled
deterministic ROCm/PyTorch implementation provides practical corpus throughput
without changing label semantics.

## Changes

- Added dense causal GQA probability reconstruction from captured post-head-
  norm/RoPE Q/K. A key receives future-use mass only for queries after it has
  left the configured grace window.
- Added independent per-layer/KV-head ranking with an exact target live budget,
  protected-window exclusion, and deterministic ascending `(score, position)`
  ties.
- Added a compact label artifact: one checksummed NPZ per sequence/layer carrying
  BF16 hidden bits, future-use scores, eligibility, and eviction labels, plus
  model/corpus/tokenizer/physical-map/objective/compute provenance.
- Added strict source/label manifest and shard verification, full-sequence and
  cross-layer token/position checks, malformed-array rejection, and atomic
  output writes.
- Added `scripts/qwen38_dms_build_labels.py`; CPU mode uses FP64 NumPy and GPU
  mode uses bounded query tiles, FP32 ROCm softmax, deterministic algorithms,
  and explicit compute-dtype provenance.
- Updated `KVCACHE.md` with the oracle and budget semantics.

## Validation

- RED: oracle-label tests failed collection before `dms_labels.py` existed.
- Six focused label tests pass under the system PyTorch/ROCm environment,
  including CPU hand calculations, per-head independence, exact budget/window/
  tie behavior, malformed capture rejection, and GPU-vs-CPU parity.
- The tiled GPU oracle matches CPU FP64 within `rtol=atol=1e-6` and two GPU runs
  are byte-identical.
- The wider uv capture/label/schema bundle passes with the GPU-only node skipped
  in the torch-free environment; targeted Ruff, `py_compile`, and diff checks
  pass.
- Exact-27B mechanical capture replay produced 64/64 CR2/window1 label shards
  across all four categories, zero protected-window violations, and exactly two
  evictions per KV head. Final label manifest SHA-256:
  `6324b0c60a09c362b19bfed2f9edf9ef436c35a41536b24aaaddbbbfd6b617ec`.
  This remains fixture/plumbing evidence, not training or quality evidence.
