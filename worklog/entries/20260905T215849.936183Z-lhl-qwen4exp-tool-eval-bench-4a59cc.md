# Tool-eval-bench three-lane behavior screen on zbook

## Summary

First cross-engine task-behavior screen: ran the 69-scenario tool-eval-bench
suite (`SeraphimSerapis/tool-eval-bench@cf54b4bfe`, seed 42, temperature 0,
`--no-think`) against three Flash-Next `UD-Q4_K_XL` lanes on zbook, one
resident model at a time: halo-box PR11 (`build-hip-patched`, 16384 ctx),
upstream `f1793c1c4` patched HIP (16384 ctx), and hipEngine production
(2051 ctx — its certified Flash-Next serving limit).

Headline full-suite scores are **hb-pr11 88/100**, **upstream 88/100**,
**hipEngine 9/100**. The hipEngine number is capacity-dominated, not behavior:
`Qwen4Exp` production serving caps sequences at
`max_sequence_length=2051` (`hipengine/generation/qwen4_exp_gguf.py:59`), and
58/69 scenarios were rejected `context_length_exceeded` (suite peak ~6.4K
tokens/request). This quantifies the P10 long-context product gap against a
concrete benchmark. A separate observation: the server's `auto` context
sizing ignores the 2051 runner cap (min(model max, allocatable KV)) and
startup/chat then fails until `--max-context-tokens 2051` is passed
explicitly.

On the only matched subset — 11 scenarios (22 points) that fit hipEngine's
capacity — hb-pr11 scores **21/22 (95.5%)**, upstream **20/22 (90.9%)**,
hipEngine **13/22 (59.1%)**. Pattern: hipEngine made the same tool-discipline
and safety decisions as both llama lanes on all 11 (no tool misuse, no
injection compliance) but was scored partial on 8 for unclear or missing
natural-language explanation. Zero `finish_reason=length` in hipEngine
traces, so partials are evaluator verdicts, not truncation.

One genuine fork-vs-upstream delta: TC-43 (refuse-without-query) — hb-pr11
asked for clarification (pass); upstream called `web_search` with an invented
query `latest news` (partial). Both llama lanes also shared 4 harness-grammar
400 rejections (TC-65/66/67/69, category O) scored partial by grace — a
harness↔llama.cpp grammar compatibility gap, so structured output is
effectively unscreened.

Caveats: single run per lane (no `--trials`); context 16384 vs 2051 by
product capacity; `max_tokens` 4096 vs 1024 per request; reasoning disabled
everywhere (with-thinking arm untested). Screening evidence only —
`performance_claim=false`; not an engine-quality verdict without the survey
section-7 packet.
