# Parity P2.3: 16-col occupancy variant rejected — dequant ALU throughput is the low-M ceiling

## Summary

Research iteration of the external-parity campaign (P2.3 deep-bandwidth
track). Hypothesis: the 32-thread single-wave Q4T16 owner underfills the
72-CU device at low M (~363 blocks at 5120->17408), so a 16-column
instantiation (3x block count, identical per-tile K16 WMMA order, bit-exact
by construction) should lift effective weight bandwidth.

Result (synthetic microbench, dominant shape 5120->17408, warmup 4 + 20
iters, cross-owner outputs bit-exact):

- rows=45: shared_b 1.559 ms / default(48-col) 0.927 ms / 16-col 0.918 ms
  — the 16-col variant is neutral (+1%) over the retained owner.
- rows=64: default 0.978 ms vs 16-col 1.103 ms — 16-col is 12.8% WORSE.

Conclusion: block count / occupancy is NOT the low-M limiter. Both 32-thread
owners plateau at ~52-56 GB/s effective weight bandwidth, so the ceiling is
per-lane work — the scalar nibble-unpack + fp16 scale/min dequant chain
executed serially over blocks_per_row per column. The next real lever is a
deeper kernel rewrite: vectorized dequant (multi-column-pair unpack per
instruction, e.g. 32-bit packed loads feeding 2 columns), wider per-thread
column ownership, or a differently-shaped producer. Those change instruction
mix but can keep per-weight math identical (bit-exact) if the K16 WMMA
association and operand values are preserved.

The experimental kernel/wrapper/microbench changes were reverted (no dead
variant left in-tree; the rejected idea and its numbers live here).
