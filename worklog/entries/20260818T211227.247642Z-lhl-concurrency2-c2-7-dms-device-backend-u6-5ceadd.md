# C2-7 U6: device-backed DMS compact backend (BF16), opt-in

## Summary

Wires the registered `dms_compact` HIP kernels (U1-U4) into
`DMSCompactBackend` as an opt-in device payload path: the BF16 K/V
payload lives solely in per-layer device slot buffers and the host keeps
only the O(rows x heads x capacity) extent metadata, so the no-shadow
property holds on the host. The host parent remains the registered
fallback (no-HIP hosts and the default configuration are unchanged).
This is the integration half of "port streaming no-shadow prefill pack
and compact decode in BF16"; production defaulting stays behind the C2-7
product gate (see Blockers).

## Changes

- `hipengine/kvcache/dms_device.py` (new): `DMSDevicePayloadStore` owns
  the per-layer device slot pools (BF16 K/V, int32 positions, uint8
  evict) + shared staging buffers, resolves the three registered
  kernels, and exposes `pack_layer` / `append_layer` / `attention_layer`
  / `layer_view` / `close`. Construction requires the HIP runtime and
  the registered kernels; either missing raises
  `DMSDeviceUnavailable`, which the backend converts to host mode.
  `HIPENGINE_DMS_DEVICE_TRIPWIRE=1` (default off) reads back the
  append-kernel overflow status as a state-drift canary.
- `DMSCompactBackend` (`hipengine/kvcache/dms.py`): new
  `device_payloads` constructor flag (or
  `HIPENGINE_DMS_DEVICE_PAYLOADS`), BF16-only (INT8 + device is
  rejected); `device_payloads_enabled` property; `close()`;
  `device_layer_view()` (readback, test/observability);
  `compact_decode_attention(request_id, layer, q, *, q_ptr, out_ptr,
  scale)` (host Q upload or device Q pointer, host readback or device
  out). `streaming_pack` and `append_decode` gain device branches that
  keep the exact host metadata computation and skip the host payload
  storage. `observability_snapshot` reports `device_payloads`.
  `_bf16_bits` (RNE, identical arithmetic to the bf16 payload codec)
  quantizes uploads.
- `docs/REFACTOR.md`: removal conditions for both env flags.
- `docs/CONCURRENCY2.md`: C2-7 status records the opt-in integration.
- RED test `tests/test_kvcache_dms_device_hip.py` (5 tests, 3 GPU):
  flag parsing, INT8 rejection, bit-exact pack/append/attention parity
  vs a host-mode backend (metadata, slot payload bits, attention KL/top-1
  vs `compact_attention_reference`), fail-closed overflow (MemoryError,
  host metadata and device buffers byte-identical afterwards), and
  determinism across two fresh device backends.

## Validation

- RED-first: 5/5 failed on the missing `device_payloads` kwarg before
  implementation; 5/5 green after on this W7900 host (2026-08-18).
- Parity gate measured: device slot payloads bit-exact vs the host
  parent's bf16 payloads; attention max abs diff ~1e-7 (gate 1e-4 /
  KL 0.05); metadata identical across all requests/layers/heads after
  pack + 3 appends.
- Neighbor gates green alongside: `test_kvcache_dms.py` (17/17, host
  behavior of the refactored pack/append unchanged) + the full DMS
  kernel suite (25/25). Lint clean on touched files.
- Test-infrastructure finding: `tests/conftest.py` snapshots the kernel
  registry after collection and restores it after every test; the
  dms_compact module is lazily imported (first import happens inside the
  backend), so a test that constructs a device backend first registers
  the kernels after the snapshot and the next test loses them
  (`MissingKernelError`). The test module now imports
  `hipengine.kernels.hip_gfx1100.attention` at top level (matching the
  sibling kernel test files) so the registration is in the collection
  baseline; the store additionally maps any resolve failure to
  `DMSDeviceUnavailable` so an unregistered device path degrades to the
  host fallback instead of crashing the backend.
- Design decision (recorded, not faked): device-mode `append_decode`
  pre-checks the full keep-recompute for every (layer, head) before any
  device mutation, so overflow fails atomically. The host parent
  partially updates earlier (layer, head) pairs before raising on a
  later one; the device path deliberately does not replicate that
  artifact.

## Blockers (carried from U5)

- Product defaulting of device mode stays off until: trained
  `dms_metadata.json`, rocprof kernel-identity rows (blocked on this
  W7900 host by the deterministic `rocprofv3 --kernel-trace` dispatch
  hang), and the c1-c32 lifecycle rerun on a stable GPU.
- The runner/execution-view wiring (real `KVLiveSpans` device handles
  instead of the placeholder 0x6D... addresses, per-batch metadata
  staging) is the next unit; `compact_decode_attention` +
  `device_layer_view` are the hooks it consumes.
