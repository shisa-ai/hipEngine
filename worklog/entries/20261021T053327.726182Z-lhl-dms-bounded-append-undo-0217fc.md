# Bound speculative DMS undo to append-tail writes

## Summary

The default compact-DMS serial verifier now uses one host-owned append-tail undo image per speculative cycle when no existing or new eviction candidate can expire through the full row horizon and all heads have reserved capacity. Intermediate row checkpoints share that image. Other cycles use the existing full-store transaction. Retention, codec arithmetic, model execution and GPU allocation sizes are unchanged. The enclosing transaction keeps its initial undo image until verifier finalization, including after accepted-prefix selection.

## Changes

- Add `DMSAppendOperation`, per-head no-expiry/capacity proof, metadata-only row checkpoints and suffix rollback. Store ownership and extent layout must stay fixed; host-reference payloads and noncanonical unused host metadata use the full transaction.
- Add device append-tail snapshot/restore helpers for BF16 and INT8 payloads, FP32 scales, positions, eviction flags and device live counts. Helpers validate all inputs before mutation, require live device planes, allocate no GPU memory and do not mutate the shared host snapshot.
- Integrate bounded undo into `_DMSStoreJournal` without a flag. Expose cumulative `append_journal_transactions` and `full_journal_transactions` in DMS operation diagnostics.
- Keep initial undo until `Qwen35GGUFTransactionalVerifier.finish()`. Prefix selection no longer destroys rollback ability before resident restoration, position publication, synchronization and scheduler commit finish. Open-journal close restores resident state as well as KV and remains retryable after a copy failure.
- Add backend, device-helper, integrated fake-device and finalization tests. Existing journal tests explicitly finalize successful selections before teardown.
