### Cross-cache layout and device argmax closure

- RED extends projection/glue tests before runtime wiring. Five CPU-reachable nodes fail only on absent head-major pair and FP16 argmax wrappers; target-only gates remain skipped. GREEN adds `moonshine_cross_kv_precompute/pair_head_major_fp32_accum`: it reuses the exact paired FP32 reduction and stores each `[row,head,dim]` result directly at resident `[head,row,dim]` offsets. The existing row-major pair remains registered. Four-row gfx1151 output matches the transposed NumPy oracle within family max-abs **3.052e-5**.
- Add `moonshine_argmax/fp16/lowest_id` as one local256 block over resident FP16 logits. It keeps lowest-token-ID tie semantics, writes one int64 result, uses fixed kernel LDS rather than caller scratch, and passes a production-vocabulary tie at IDs 7/11 by selecting 7. Projection+glue tests pass **12/12** on gfx1151.
- Cache-only profiles name `moonshine_f16_projection_pair_head_major_kernel` at **17.073 us**, local256/VGPR16/SGPR128/LDS512/scratch0, and `moonshine_argmax_fp16_kernel` at **31.219 us**, local256/VGPR16/SGPR128/LDS3072/scratch0. Both smokes are finite/all-correct and compile only during the preceding prebuild. This closes the first decoder-composition subtask; resident orchestration follows separately.

### Complete resident unfused decoder chain

- RED extends the fake-runtime owner before implementation: it requires explicit injected/prebuilt library ownership, encoder shape/dtype/mask rejection, exactly eight head-major precompute calls, strict sequential token/cache state, the exact **132-call** embedding + 8x16-layer + final-norm/LM/argmax order, retained-cross reset, and unchanged tracked allocations.
