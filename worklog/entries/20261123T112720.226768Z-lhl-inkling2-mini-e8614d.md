# Screen eight-output Inkling NVFP4 tiles

## Summary

The eight-output scratch leaf preserved every tested output bit. On Strix Halo it shortened all wide gate/up and down cells in both timing orders. W7900 gate/up results were mixed, including a regression at 13 rows.

## Changes

- Scratch only. Add an eight-output launch of the current exact NVFP4 tile when the width is divisible by the full eight-output workgroup. Leave narrower or unaligned dispatch unchanged.

## Validation

- Compare `b0b3c1ef13748dfec3fd0aa895a486d07ea32f41` four-output control with the scratch eight-output specialization on Radeon 8060S (`strixhalo`, gfx1151) and Radeon Pro W7900 (`epyc`, gfx1100): compile both sources with `hipcc -O3 -shared -fPIC --offload-arch="$arch"`, then run `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. python -u /tmp/hipengine_inkling_nvfp4_pair_output_probe.py "$backend" "$control_so" "$candidate_so"`. Both passed all 12 bitwise cases: synthetic scaled 128-expert banks, 13/47/64 uniform or 64 skewed token rows, shared gate/up input, repeated down input, and a 19-output control that does not take the new route.
- For 64 uniform tokens on Strix, GPU-event medians were 3.852 → 3.537 ms for gate/up and 2.100 → 1.975 ms for down, across three eight-launch samples per arm in each order. W7900 at 13 uniform rows was 0.591 → 0.611 ms for gate/up and 0.261 → 0.249 ms for down. Timings exclude copies and model work; no checkpoint was loaded.
