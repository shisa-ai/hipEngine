# Bind staged Q8 gate DPP isolation to owners

## Summary

The staged-F32 layer-gate arms close their DPP preemptor on generator/current
and late-runner owners. They no longer write/restore a process key to expose
the exact parent. Unrelated routes preserve their DPP choices.

## Changes

- `_apply_route_env` binds `q8_dpp_reduction_enabled(generator, False)` only
  for staged routes, alongside the existing rowtile launch session and explicit
  WMMA/dense-wide policies. `process_env_for` no longer reports a DPP write;
  artifacts name the DPP owner stand-down in both arms.
- Unit tests exercise all staged route/teacher pairs at two and 73 rows with
  actual linear dispatch, explicit launch-session transport, caller process
  preservation and exception restoration of missing owner attributes.
- Public staged tests assert generator/runner DPP state and process preservation
  during capture, including cached repeats and exact control repeats. The
  engaging public tests start with an opposing enabled process input.
- No profile, kernel, arithmetic or production default changes.
