# Retire remaining PARO scratch views after allocation failure

## Summary

Repair scratch-allocation failure cleanup left outside the earlier verifier-cache
fixes. Scalar full-attention/MLP canonicalization, post-prefill decode restoration,
and adjacent prefill helpers could retain Python views into freed workspace
buffers after a replacement allocation failed. Preserve arithmetic, successful
layouts, allocation policy, product defaults and published benchmark values.

- Route scalar full-attention and MLP replacement and post-prefill full/linear/MLP
  restoration through the existing scoped cleanup helpers. Generalize the
  full-attention-only helper to serve other resident scratch fields.
- Clear the affected linear/full/MLP prefill field on partial reservation
  failure. Preserve a different MLP policy's still-live resident field; retire
  captured verifier graphs before propagating the original error.
- Add 26 RED regressions using the real `RuntimeWorkspace` and a tracked fake
  allocator. Inject failure at the first and third replacement allocations,
  then require resident eviction, live-pointer reconstruction on retry and
  allocation-free same-shape reuse. Add two cross-policy preservation cases.
  Post-prefill cases also check graph retirement and unrelated live pointers.
- T0 host ownership/lifecycle change only; no kernel or arithmetic change.
  The oracle is allocator liveness and workspace accounting, not token equality.
  Public token comparisons are an additional successful-path smoke check.
