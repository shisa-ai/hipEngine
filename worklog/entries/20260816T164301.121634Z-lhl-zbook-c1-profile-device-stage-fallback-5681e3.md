# Use device stages for zero-duration gfx1151 traces

## Summary

Handled the known ZBook rocprofv3 zero-duration limitation without inventing
kernel timing. The c1 adapter now keeps rocprof as exact dispatch/role evidence
and falls back to the runtime's same-stream device wall-clock stage boundaries
for timing and mechanism selection.

## Changes

- Detect whether any selected rocprof kernel has positive duration.
- Positive-duration hosts retain the normal kernel/role Amdahl table.
- Zero-duration hosts launch one cache-only, instrumented eager child and rank
  its device stage markers by per-token time; rocprof still supplies exact marker
  windows, launch counts, symbols, resources, and role correlations.
- Artifacts state the timing authority and preserve both commands/hashes.
- Added RED/GREEN coverage for device-stage ranking and zero-duration role launch
  census.

## Validation

- Failed clean profile at `a1bd33cd1`: exact baseline `22.965 tok/s`; rocprof
  captured **19,323** dispatches, 24/24 decode windows, and role markers, but
  **0** positive-duration rows. It makes no profile/optimization claim.
- Focused adapter plus inherited rocprof tests pass `11/11`; Python compilation
  and `git diff --check` pass.
