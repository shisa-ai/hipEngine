# Batch causal Inkling attention and KV cache commit

## Summary

Run causal attention for each committed Inkling prompt block in one launch, then commit its key/value rows to the cache in a separate launch. This removes per-token attention synchronization without changing the reduction order or overwriting history before it is read.

## Changes

- Each query row reads prior KV from its visit's persistent bank and current-block KV from staging. The tiled kernel visits the same physical slots as scalar attention. The commit writes only the surviving suffix if the block spans more than one cache window.
- One-row decode and provisional DSpark verification keep their existing paths. In particular, provisional verification still journals each row's cache changes for prefix rollback.
