# RF7 session snapshot owner and shared chat validation

## Summary

Moved chat-session snapshot payload construction, envelope validation,
transcript validation, and the GET/POST snapshot routes out of
``create_app``. The pure owner raises typed ``SessionStateError`` values; the
application's existing session-error seam translates them. The GET route keeps
the original ``snapshot_record`` lease, so tokenizer metadata and payload
construction still run while the session lock is held.

The snapshot candidate initially copied six chat validators. They now live in
one pure ``chat_validation`` owner consumed by both the chat-prompt path and the
snapshot restore path. The API translates its typed failure at the existing HTTP
boundary; the snapshot owner translates it at its existing state-error seam.

## Changes

- ``hipengine/server/session_snapshots.py``: pure snapshot owner with
  ``CHAT_SESSION_SNAPSHOT_SCHEMA``, explicit ``SessionSnapshotModel``,
  ``build_chat_session_snapshot``, ``restore_chat_session_from_snapshot``, and
  snapshot-specific envelope/message/timestamp validation. It imports no
  FastAPI, application module, engine, server config, or application state.
- ``hipengine/server/chat_validation.py``: single pure owner for
  ``CHAT_MESSAGE_ROLES``, ``ChatValidationError``, role validation, tool-field
  validation, tool-call normalization, and tool-transcript validation. It
  imports no HTTP, engine, config, or application-state module.
- ``hipengine/server/session_snapshot_routes.py``: GET/POST route owner with
  explicit ``store``, ``auth_dependency``, ``error_translator``, ``model``,
  ``schema``, ``snapshot_tokenizer_metadata`` and
  ``current_tokenizer_metadata`` dependencies. No app bag or callback bag.
- ``hipengine/server/api.py``: removed the nested snapshot payload/restore
  functions, old snapshot routes, old snapshot validators, and the six copied
  chat validators. The public ``render_chat_prompt`` entry point now calls the
  shared validators through one ``_chat_validation_http_error`` translation
  seam; its implementation is ``_render_chat_prompt_unchecked``. The snapshot
  router is composed with the same store, real auth dependency, existing
  session-error translator, and narrow tokenizer metadata operations.
  ``app.state.hipengine_chat_sessions``
  and the other map identities are unchanged.
- ``tests/test_unit_server_chat_validation.py``: typed shared error, chat-path
  HTTP translation for role/tool-field/tool-call/transcript failures, snapshot
  state-error translation, and a single-source dependency check.
- ``tests/test_unit_server_session_snapshots.py``: validation-order table,
  tokenizer-operation timing, payload deep-copy, route lease timing, 404
  translation, metadata-failure cleanup, and dependency-boundary checks.
- ``tests/test_unit_server_pure_owner_consumers.py``: registers the new pure
  owners and keeps direct-import enforcement.

## Ordering and lifetime evidence

- The snapshot unit table pins object -> schema -> resident_state_reuse -> model
  -> tokenizer -> session -> messages -> created -> updated, with exact status,
  code, param, and message for each representative failure.
- Shared-validation tests pin the typed error fields and both translations:
  chat-prompt failures remain ``OpenAIHTTPError`` with the same HTTP shape;
  snapshot failures remain ``SessionStateError`` with the same fields. The
  single-source test proves the six validators and role constants are defined
  only in ``chat_validation`` and imported by both consumers.
- The tokenizer operation is not called when the snapshot tokenizer is absent;
  it is called after model validation and before session validation; a
  ``None`` current metadata result preserves the unloaded-model skip.
- The route test observes ``store.lease_active`` true during tokenizer metadata
  construction. A metadata exception releases the lease and leaves the original
  transcript record intact. A separate route test confirms the missing-session
  404 is translated inside the lease.
- Existing integration tests preserve auth on both routes, snapshot round-trip,
  model/tokenizer compatibility, cap refusal, and app-state map identity.

## Dependency choices

- Shared validation raises ``ChatValidationError`` rather than importing either
  HTTP or state-error types. This keeps one implementation and puts translation
  at the two existing seams.
- API keeps one public ``render_chat_prompt`` translation wrapper around
  ``_render_chat_prompt_unchecked`` so prompt-rendering call sites and public
  behavior are unchanged. All six private validator copies were removed rather
  than re-exported.
- Snapshot catches ``ChatValidationError`` only around message validation and
  converts it to ``SessionStateError``; snapshot-specific envelope errors remain
  directly typed.
