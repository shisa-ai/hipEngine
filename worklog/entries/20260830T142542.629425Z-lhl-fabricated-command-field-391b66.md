# I wrote a command line no process ever ran into a provenance field; the gate now rejects that

## Summary

The provenance block I added to
`benchmarks/results/2026-08-30-w7900-q4km-c1c8-admission-decomposition-post-grouping.json` was built
from `collect_artifact_provenance()`, so its host, commit and timestamp were observed - but its
`command` field was not. I wrote:

```json
["/home/lhl/hipEngine-main/.venv/bin/python", "<inline builder>", "/tmp/he-parity/decomp-ar.json",
 "->", "2026-08-30-w7900-q4km-c1c8-admission-decomposition-post-grouping.json"]
```

No process ever ran that. `"<inline builder>"` and `"->"` are not argv tokens; the work was an inline
heredoc with no argv. Everything else in the artifact was real, which is what makes this the most
dangerous shape of the error: one fabricated field inside otherwise-derived provenance reads as
verified provenance.

## Changes

- Artifact corrected: `command` is now `null`, with `command_note` naming the superseded value, and
  `measured_packet` / `packet_launcher` / `packet_argv` pointing at `/tmp/he-parity/decomp-ar.json`,
  its launcher `/tmp/he-parity/after-oracle.sh`, and the reason its argv is unrecoverable (the packet
  predates c6bae4667). The builder round-trips this file exactly, so the edit is surgical.
- `scripts/check_artifact_provenance.py`: new `PLACEHOLDER-COMMAND` warning. Key-scoped to
  `command`/`cmd`/`argv`/`cli`/`invocation`, matching `<lowercase token>` patterns. Warning tier, not a
  violation, because some artifacts deliberately store a command template - but a template must say so.
- `benchmarks/results/2026-08-30-w7900-q4km-c1c8-submodule-decomposition.json`: got that label
  (`command_kind: TEMPLATE, not an invocation`) because its recorded command carries `<d1>`/`<k3>`/
  `<peer>` slots; its numbers are untouched.
- `docs/PUBLISH.md`: the checklist bullet now lists all four warning types and the current totals
  (52 cited artifacts, 0 violations, 3 warnings).
- 4 new tests in `tests/test_scripts_check_artifact_provenance.py`; 24 pass in the file.

## Finding

The rule fires twice on the existing corpus, and both hits are legitimate rather than noise:

- `2026-08-28-gfx1151-qwen38-external-reproduction-survey.json`: a real env-prefixed invocation with
  one elided value, `PYTHONPATH=<detached-head>`. Not reproducible verbatim, which is exactly what the
  warning says. Left unedited - it is another lane's evidence and the warning is the correct response.
- `2026-08-30-w7900-q4km-c1c8-submodule-decomposition.json`: a template, now labelled.

My own fixed artifact no longer trips it, which is the check that the rule is aimed at my error and not
at prose that happens to contain angle brackets (a separate test pins that scoping).

## Next

- Standing rule, restated because this is the third provenance-field invention today: a provenance
  field is observed or it is `null` with an explanation. Never reconstructed, never "obviously right".
- If an artifact genuinely cannot record its invocation, the writer should emit `command: null` and a
  `command_kind`. A template string is fine only when labelled as one.
