# Align native bulk row1 gate with production profile

## Summary

Reconciled task #31 with the normative production-profile contract. The legacy
Qwen3.6 gfx1100 test required a native two-row verifier to reproduce scalar c1
FP32 hidden and Conv/GDN state bytes. That is no longer a valid binding gate:
the native route uses width-specific projection/MoE arithmetic and reassociated
GDN, while exact control/ownership and same-route determinism remain mandatory.

An instrumented current-model run localized the first difference to layer 0:
only 14 output values differ, max absolute `3.0517578125e-05`; the difference
accumulates to all 2,048 final hidden values (max `0.5011177`) while both target
tokens remain identical. Enabling the production prefill-GDN capture control
does not change this. This is arithmetic composition drift, not evidence of a
row/slot/state transfer bug.

The corrected gate binds scalar target IDs and finite state, while the adjacent
same-route test remains byte-exact across full bulk execution versus deferred
row-1 commit, following token, hidden rows, and every Conv/GDN state element.
Distributional promotion remains owned by the external execution-profile
quality gate.

## Changes

- Updated the module contract to distinguish scalar-exact and native-production
  verifier guarantees.
- Renamed the stale scalar-byte test to
  `test_native_bulk_direct_commit_row1_preserves_scalar_tokens`.

  target/following-token equality and finite hidden/state checks.
