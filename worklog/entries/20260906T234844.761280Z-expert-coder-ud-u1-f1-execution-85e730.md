## Changes

Design call graph and authorization boundaries:

### Before allocation

- `Qwen35GGUFBringupGenerator`'s selected native batch route passes explicit
  `execution_routes=("eager", "native_rows", "native_graph")` to its resident
  session. Its shared-runner construction carries the configured native scope.
  `Qwen35GGUFResidentSession` passes the requested routes to the actual
  `Qwen35GGUFFullStackRunner`, which resolves them through
  `loading/qwen35_gguf_execution.execution_operations` and supplies
  `requested_operations` to the actual materializer. A real session → runner →
  loader test observes this request and the real admission/payload boundary.
- The materializer makes native requests additive to `DEFAULT_AR_OPERATIONS`.
  A diagnostic operation selection cannot erase required ordinary calls when
  asking to run native. Known native state storage is derived from header
  identity and existing policy before materialization. This is ABI selection,
  not repair or authorization of F5's named profile binder.
- Shared native dependency enumeration includes embedding, all projection and
  recurrent auxiliary roles, norm, BF16-input/F32-output head, router and
  selected MoE gate/up/down roles. Native coverage reuses accepted shared
  consumer owners, with native row limits. Selected call topology adds native
  to the accepted `default_selected_call_intents` owner; paired/weighted and
  ordered two-single fallback semantics are unchanged. No new dispatch table.
- Real unsupported BF16 embedding and F32 native head fixtures refuse before
  payload reads or allocator calls. There is no fabricated F32 scratch.norm or
  multirow BF16 embedding adapter. The actual embedding runtime passes rows to
  the shared resolver and refuses singleton-only BF16 before registry/leaf
  entry; raw lookup still forwards rows. No math or kernel changes.
- Session-known rows outside 2–8, host embedding, expert-sidecar and non-BF16 KV
  native requests refuse before model allocation. Native deferred-device loads
  refuse before payload/allocation. Later unanticipated native requests cannot
  acquire authorization by replanning already allocated weights.

### Before entry and replay

- The real loader publishes its existing certificate plus an immutable
  `ResidentExecutionBinding` snapshot of config, qualified preset and actual
  allocation/view/alias metadata. That snapshot alone grants nothing. Legacy
  or manually constructed residents default to no authority.
- `authorize_native_execution` rebinds actual resident specs and actual native
  operand intent using the accepted F4 coverage/selected APIs. It builds an
  intended invocation contract over existing residents, then calls
  `certificate_covers_artifact`; it does not invoke the materialization
  planner, read payloads, allocate, or mint a post-allocation certificate.
  Completeness is checked before narrowing. Native intent uses BF16 head
  input, real recurrent state storage, shared row domains, model geometry and
  every ordered selected partner. Full slot accounting must match; a positive
  gate-only selected diagnostic certificate cannot authorize native full MoE.
- Actual `step_rows_native`, `capture_native_rows_graph`, direct enqueue and
  direct native layer entries enforce the contract. Session guards precede
  position publication, scratch preparation, streams/capture, embedding,
  kernels and state writers. Scratch checks bind row capacity, extents,
  recurrent storage, non-overlapping state owners and selected MoE capacity.
  Direct enqueue cannot substitute foreign scratch/state owners.
- Replay checks current authorization and the captured resident/row/state,
  physical buffer, span-role and context-bound identity before token H2D,
  positions or graph launch. Changing rows cannot widen a cached certificate.
  Mutable position *contents* remain normal runtime state, not hashed inputs.
- Existing eager/c1, row-local and bulk-prefill scopes remain separate; this
  unit does not globally select native mode or replace their executors. A
  native request on eager-only residents fails closed. Qualified default
  plain/MoE admission and explicit existing selected fallbacks are preserved.
  Availability/ABI checks still grant no named numerical-profile permission.
