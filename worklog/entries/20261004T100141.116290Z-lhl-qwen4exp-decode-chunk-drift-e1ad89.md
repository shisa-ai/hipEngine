# Sequential p4096 runs drift 8% on gfx1151; interleaved, the promoted chunk 1024 buys +9.06% prefill for -1.15% decode

## Summary

**A sequential A/B design produced a plausible performance finding that was
false, and the interleaved design that replaced it produced the real one.** Both
halves are recorded because the first is the reason the second is trustworthy.

**The confounded reading.** Five sequential fresh-process runs at `code-p4096`
(chunks 512 / 1024 / 2048 / 4096 / 512) read decode **19.603 / 18.930 / 18.549 /
18.222 / 18.065** tok/s with within-arm spreads under 0.5%. The first four are
monotone and non-overlapping, which reads as a prefill-versus-decode trade knob
worth -7.1% decode. The fifth is a **repeat of the first configuration** and it
returns the **lowest** value in the session, while the prefill column keeps its
chunk shape and peaks at chunk 2048. Decode tracked run order; prefill tracked
chunk. One cause cannot explain both, so the decode column was drift.

**The interleaved measurement.** `chunk 512` against `chunk 1024` at
`code-p4096`, **A/B/A/B/A/B in one session**, 150 s cooldowns, one process per
arm, 1 warmup + 3 repetitions:

| chunk | prefill tok/s | within-arm spread | decode tok/s | within-arm spread |
| ---: | ---: | ---: | ---: | ---: |
| 512 | 249.76 (249.70 / 249.76 / 249.83) | 0.051% | 18.120 (18.110 / 18.118 / 18.133) | 0.127% |
| 1024 | 272.38 (271.60 / 272.78 / 272.77) | 0.433% | 17.911 (17.857 / 17.935 / 17.942) | 0.479% |

**Effect: chunk 1024 against 512 is +9.06% prefill and -1.15% decode.** Every
arm is fully separated on both columns (prefill 249.70-249.83 against
271.60-272.78; decode 18.110-18.133 against 17.857-17.942) and no sample
overlaps.

**The drift floor is the finding.** Interleaving took within-arm repeatability
from **8.0%** (sequential, same configuration, same session) to **0.05-0.48%**.
A non-interleaved `code-p4096` comparison on this host cannot resolve anything
below roughly 8%.

**This validates `RT-1`'s promoted chunk default on both axes.** `RT-1` promoted
chunk 1024 (serving) and qualified 2048/4096 on **prefill-only** evidence - its
own state cell and the scoreboard's chunk section both say so ("It is not a
decode-latency-under-concurrency claim"). The decode cost of that promotion is
now measured at **-1.15%**, eight times smaller than its **+9.06%** prefill
benefit. **No default changed and no metric row moved**; this closes the
decode-side gap in the evidence for a live default rather than altering it.

**The control that separates the two columns** is run 5 against run 1: same
configuration, same session, **8.0% apart on decode**. The interleaved session's
chunk-512 prefill (249.76) reproduces run 5 (249.83) rather than run 1 (262.41),
so the sequential session's first run is the outlier, not its last.

**Cross-session agreement where it should hold.** The interleaved chunk-1024
prefill (272.38) sits 0.03% from the value recorded in `benchmarks/CHANGELOG.md`
for this tree (272.46), and the sequential `code-p512` and `code-p1024` runs at
chunk 1024 (265.33 / 20.985 and 286.64 / 19.901) sit within 0.5-1.0% of the
`2026-10-04-qwen4exp-thermal-protocol-and-llamacpp-basis` fresh-process values
(263.96 / 20.98 and 287.05 / 19.70). The absolute `code-p4096` level in this
session is **lower** than that packet's (249.76 against 270.57 at chunk 512's
sibling configuration), which is why this entry claims the **within-session
paired** deltas and not absolute rates.

**Consistent with the host's recorded thermal behaviour.**
`2026-10-04-qwen4exp-thermal-protocol-and-llamacpp-basis` measures this APU at
98 °C under sustained prefill load with roughly 40% prefill throughput loss, and
its required protocol is one case per process with a cooldown to <=50 °C before
each run. That protocol controls the **start** temperature but not the
**between-arm ordering**, which is what the sequential design got wrong.

## Next

**Two things this changes.**

1. **`RT-1`'s decode-side gap is closed and the promotion stands.** The serving
   default is chunk 1024 and the canonical bench's own default is 512; the pair
   is now measured, not assumed, and the trade favours the promoted default.

2. **The `DE-11` decode non-kernel remainder is not reproducible at this drift
   floor and should be re-derived from a paired measurement.** `DE-11` records
   the canonical bench's decode wall as **47.656 ms/step at p512 and 57.694 at
   p4096** and subtracts a separately-captured kernel sum to get a remainder that
   "grows 7x". Those two walls are the
   `2026-10-04-qwen4exp-thermal-protocol-and-llamacpp-basis` fresh-process
   readings at **chunk 1024** (20.98 and 17.33 tok/s). In this session the p512
   value reproduces to 0.02% (20.985) but the p4096 value reads **18.930**, 8.7%
   higher - i.e. **at or inside the 8% sequential drift this entry measures**.
   The remainder is a difference of two quantities captured in different
   sessions, so it inherits that drift. Measuring wall and kernel sum in one
   interleaved capture is the fix.

**Not a blocker and not a retraction of anything else.** `RT-1`'s prefill
measurement is unaffected (its arms were interleaved and separated 5.70x), the
`DP-7`/`RT-1` chunk qualification stands, and the dense-wide scope ladder's
14-47 open item is unaffected - it already uses an interleaved A/B/C design and
already reports its own effect as below the drift floor.
