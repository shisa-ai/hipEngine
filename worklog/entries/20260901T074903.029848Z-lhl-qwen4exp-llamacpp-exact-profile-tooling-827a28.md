# Add exact-token llama.cpp attach profiler

## Summary

Added a direct-attach llama.cpp profiler so the canonical comparator ledger can
use the committed exact token arrays without tracing model load, a nested Python
launcher, or repeated-token `llama-bench` input.

## Changes

- Added `scripts/qwen4exp_llamacpp_exact_profile.py` to start one already-built
  server, warm exact cases, and attach `rocprofv3` directly to the server PID for
  each measured request.
- Prefill traces submit the exact fixture prompt with `cache_prompt=false` and
  one sampled output.
- Decode traces first cache the exact prompt, append its sampled root token, and
  trace evaluation of only that token. This produces live-513/1025/4097 c1
  transitions matched to the hipEngine context profiler.
- Each row records request payload/timing, exact token hashes, server/source/diff
  identity, profiler command/log, and hashes for every raw CSV. The tool rejects
  a prefill token-count mismatch, failed cache reuse, missing kernel trace, or a
  failed profiler attach.
- Added pure parser/payload/exact-ID tests; the tests require no ROCm runtime.

## Validation

- RED: `tests/test_qwen4exp_llamacpp_exact_profile.py` initially failed all three
  tests because the durable tool did not exist.
- GREEN: the focused file passes **3/3**; `py_compile`, command help, and
  `git diff --check` pass.
- The exact retained comparator was independently rebuilt in `/tmp` at upstream
  `f1793c1c4` with documented patch digest `a37fa3bb…`, HIP graphs/MFMA MMQ on,
  and gfx1151 target. The runtime profile itself follows from the clean committed
  tool in the next unit.
