# DMS C>1 structurally blocked: single _dms_decode_owner slot on shared runner

## Summary

Attempted DMS C2/C4/C8 concurrency on the XTX (iteration 19). Found a
structural blocker before any concurrency number could exist: the shared
`Qwen35GGUFFullStackRunner` routes external DMS decode through ONE
`_dms_decode_owner` slot. With two simultaneous DMS resident sessions, the
second session's prefill finalize overwrites the slot, and the first
session's decode deterministically fails with "DMS direct append
device/host live-count mismatch" on its first decode step. Both prefills
succeed (dense owner + two compact backends coexist within budget), so the
blocker is decode routing, not memory.

## Changes

- Added `scripts/qwen38_dms_concurrency_probe.py`: N simultaneous DMS
  resident sessions on one shared runner, disjoint validation-stream prompt
  slices, sequential prefills, round-robin interleaved decode, per-session
  DMS snapshots and memory checkpoints. Header documents the known blocker;
  the probe is the repro tool for the per-session-owner-routing fix.
- Campaign doc Packet 4 C2/C4/C8 note updated with the blocker evidence.

## Validation

- Repro (sessions=2, prompt 16,384 each, decode 4, backend hip_gfx1100):
  both prefills pass; first decode step raises
  `RuntimeError("DMS direct append device/host live-count mismatch")` from
  `hipengine/kvcache/dms.py:1695`; 0 decode rows survive. Trace: decode
  dispatch resolves `_dms_decode_owner` from the runner
  (`qwen35_gguf_runner.py:8451`), the slot is overwritten at
  `:15291` (`self.runner.__dict__["_dms_decode_owner"] = self`) and popped
  only by the owner itself at `:27779`.
- Not a probe bug: the quality-suite arms work because sessions are
  sequential (each closes before the next opens, popping/restoring the slot).
- Classification: capability blocker for DMS C>1 on the current tree; the
  fix is per-session owner routing through the decode dispatch (feature
  work, not a measurement).

## Next

- Either implement per-session DMS decode-owner routing (feature) or record
  DMS C>1 as unsupported on this tree. Heterogeneous lengths, cancellation,
  and pressure/refill remain measurable only within the single-owner C1
  protocol until then.
