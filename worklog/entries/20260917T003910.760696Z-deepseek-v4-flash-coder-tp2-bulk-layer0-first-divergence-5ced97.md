# Layer-0 earliest divergent operation: the TP2 bulk QKV projection

## Summary

Re-ran the layer-0 comparison between the **resident TP1 bulk teacher** and the
**TP2 bulk candidate** with a capture that reads each field immediately after
its own producer, on the producer's stream, with layouts derived from the
producer call site instead of from the allocation size. The corrected capture
overturns the previous "first divergence is the GDN output" conclusion.

**Earliest verified differing operation:** the Q6_K `attn_qkv` projection.
With identical layer input (`sha256 306c076e9d0adb2214074d7e27d85d7249da2e38fc44614bd776c0cffbda9c5f`),
identical layer-0 weights, identical all-zero initial conv/recurrent state and
the same `chain_compact_peer_wave32` GDN mode:

| field | producer | shape | rel | max_abs | bit-equal |
| --- | --- | --- | --- | --- | --- |
| `norm` | `gguf_rmsnorm_bf16_f32_weight` | bf16 [64, 5120] | 0 | 0 | **yes** |
| **`linear_qkv`** | **`attn_qkv` (Q6_K) projection** | **bf16 [64, 10240]** | **3.73e-03** | **0.25** | no |
| `linear_z` | `attn_gate` (Q4_K) projection | bf16 [64, 6144] | 0 | 0 | **yes** |
| `linear_alpha` / `linear_beta` | alpha/beta singletons | bf16 [64, 48] | 0 | 0 | **yes** |
| `linear_qkv_f32` | `bf16_to_f32` | f32 [64, 10240] | 3.73e-03 | 0.25 | no |
| `conv_out` | `qwen35_linear_attn_conv_prefill_f32` | f32 [64, 10240] | 1.69e-03 | 6.84e-02 | no |
| `prefill_query` / `prefill_key` | compact-peer prepare | f32 [64, 2048] | 6.99e-03 / 3.31e-03 | 6.97e-03 | no |
| `prefill_value` | compact-peer prepare | f32 [64, 6144] | 1.69e-03 | 6.84e-02 | no |
| `prefill_beta` / `prefill_decay` | compact-peer prepare | f32 [64, 48] | 0 | 0 | **yes** |
| `recurrent_out` | recurrent wave32 | f32 [64, 6144] | 9.61e-04 | 3.20e-03 | no |
| `recurrent_bf16` | rmsnorm gate | bf16 [64, 6144] | 1.51e-03 | 3.91e-03 | no |
| `attn_out` | ssm_out q8 singleton | bf16 [64, 5120] | 6.98e-05 | 1.95e-03 | no |

TP2 rank 0 and rank 1 are **bit-identical for all 15 fields**, so the capture is
reliable; the differences are teacher-vs-TP2, not capture noise.

**Verified cause (control, not arithmetic drift):** `MlpTP2GenerationSession.bulk_prefill`
calls the shared resident layer helpers directly from
`hipengine/distributed/tp2_generate.py`, while `Qwen35GGUFResidentSession` wraps
its entire bulk prefill in the session-scoped GGUF linear dispatch owners:

`q8_t16_two_wave_prefill_session`, `wmma_prefill_session`,
`gemv_decode_session`, `q8_t16_dual_wmma_prefill_session`,
`q4_pack8_dual_wmma_silu_prefill_session`, `q4_t16_unequal_pair_prefill_session`,
`_prefill_f16_staging_context`, `_q6_integer_mmq_context`,
`_iq_dense_mmq_context`, `_q8_mmq_prefill_context`,
`_q6_f16_rocblas_prefill_context` (`qwen35_gguf_runner.py:20031-20055`).

Those context variables participate in `launch_gguf_linear`'s dispatch
resolution **and in its dispatch cache key**
(`gguf_linear.py:3354`, and `_q6_t16_f16_rocblas_prefill_dispatch` at
`gguf_linear.py:6326`), so the Q6_K `attn_qkv` projection resolves a different
kernel on each route. That explains why the Q4_K `attn_gate` projection from the
same launch group is bit-identical while the Q6_K `attn_qkv` projection is not:
only the Q6 path is rewritten by `_q6_f16_rocblas_prefill_context`.

Corrections to the previous report, as requested:

- GDN is part of the attention path, so the earlier evidence did **not** exclude
  prefill attention. It is now excluded for the upstream part: `norm`,
  `linear_z`, `linear_alpha`, `linear_beta`, `prefill_beta`, `prefill_decay` are
  all bit-identical, and the QKV projection is the first difference.
- A smaller initial difference can grow differently, so nothing here establishes
  a decode-side defect. No decode-side claim is made.
- The earlier "first divergence is the GDN output" finding is superseded: that
  capture read every scratch field once after the helper returned and derived
  widths from the allocation rather than the producer, so `conv_out` and
  `linear_qkv` were dtype-misread.

## Changes

- `scripts/tp2_layer0_capture.py` (new, CPU-only): producer-derived capture
  descriptors plus arena lifetime/alias validation
  (`descriptor`, `aliasing_pairs`, `build_capture_plan`,
  `validate_capture_order`, `describe_layer0_linear`). Widths/dtypes come from
  the producer call sites (`linear_layer0_widths`); lifetimes come from the
  allocator's own `_GGUF_PREFILL_SCRATCH_DENSE_LIFETIMES`/`allocation_lifetimes`.
- `scripts/tp2_bulk_vs_resident_layer0.py` (rewritten): hooks each layer-0
  producer (`_run_attention_norm_rows`, the alpha/beta call boundary,
  `_linear_attn_conv_prefill_kernel`, the GDN plan's
  prepare/recurrent/rmsnorm-gate, the ssm_out singleton launchers), reads the
  produced field immediately after the launch on the producer's stream,
  records a launch log of the actually-selected kernels, the helper arguments,
  the allocator's `allocation_mode`/`allocation_groups`/
  `allocation_inplace_aliases`/`allocation_lifetimes`, the layer-0 weight
  hashes and the initial conv/recurrent state hashes.
- `hipengine/runtime/gguf_linear.py`: additive accessor
  `gguf_prefill_dispatch_context()` reporting the session-scoped dispatch
  toggles, so "same environment" is not mistaken for "same route".
- `tests/test_unit_scripts_tp2_layer0_capture.py` (new, 28 CPU tests):
  descriptor validation (bool/float/zero rows, unknown dtype, null pointer,
  over-read past the allocation, degenerate lifetimes), producer-derived widths,
  row-count-vs-capacity, real lifetime-table alias semantics, capture-plan
  ordering, rejection of the historical end-of-layer bulk read, and a CPU
  smoke test that installs the real hook surface (a typo there now fails in
  seconds instead of after two model loads).
- `tests/test_unit_distributed_tp2_generate.py`: `RunnerSpy` records the active
  dispatch context at each prefill-attention call; new
  `test_bulk_prefill_establishes_the_resident_dispatch_context` marked
  `xfail(strict=False)` because the TP2 bulk path does not yet establish the
  resident context.
- `docs/REFACTOR.md`: open-defect entry with the measured evidence and the fix
  condition. `docs/QWEN38-27B-GFX1100-TP2.md`: P2 GPU-evidence + blocker
  updated. `benchmarks/CHANGELOG.md`: dated correction line.
  `benchmarks/results/2026-09-17-w7900-tp2-bulk-vs-resident-tp1-layer0.json`:
  rewritten with the corrected capture, descriptors, allocation report, launch
  logs, weight/state hashes and comparison.

No production arithmetic changed. The bulk route stays opt-in/default-off and
no numerical threshold was relaxed.
