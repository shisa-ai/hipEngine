# Gemma4 D12 INT8-vs-BF16 attention-boundary localization

## Summary

The bounded follow-up the screening unit (`20261002T200024.233968Z`) asked for:
localize the deterministic INT8-vs-BF16 KV numerical difference at the attention
boundary, on the already-frozen short English chain, without porting a new
quantizer. Measured, on one forced decode position (absolute position 63, after
the 63-token prefill):

1. **First divergence is the layer-0 attention output.** Across all 30 layers the
   whole-model INT8 and BF16 arms carry **bit-identical** hidden input, query,
   written K and written V at layer 0, and a different context output there
   (3821/4096 BF16 elements changed, relative L2 `1.97e-2`). The **first
   divergent input is layer 1**; from there the per-layer output error grows from
   `1.96e-2` (layer 0) to `0.22–0.63` (layers 17–29) through the residual stream.
2. **INT8 passes its frozen CPU comparison; BF16 fails its frozen max-absolute
   comparison.** On the
   captured common BF16 K/V and query, the production INT8 consumer (FP32)
   matches the common CPU algorithm to relative L2 `3.86e-7` (layer 0) and
   `1.69e-7` (layer 5), max abs `~1–3e-6`, well inside its frozen `1e-4`. The
   production BF16 output matches it only to rel L2 `1.5571e-3` (layer 0) and
   `1.6564e-3` (layer 5), max abs `0.0297155` and `0.0077708`. **Both exceed the
   frozen `5e-3` max-abs tolerance, so the frozen BF16 consumer control is
   reported FAILED**; the tolerance was not relaxed. The observed error is the
   BF16 readback floor: at layer 0 the observed rel L2/max abs **equal** the floor
   bit-for-bit and the production BF16 output **matches the BF16 rounding of the
   CPU control by literal raw bytes**; at layer 5 the observed rel L2 is above
   the floor but by less than the separately recorded `1e-6` allowance
   (`1.6564248e-3` vs `1.6564211e-3`) and raw-byte equality is **false**.
   Reduction-order differences are a possible explanation, not an established
   cause. That close-but-not-equal distinction is recorded, not collapsed into
   "the difference is the representation error". Generated notes distinguish
   exact equality, floor plus `1e-6`, and exceeding that comparison allowance.
3. **On the fixed input the difference is dominated by the KV representation,
   not consumer arithmetic.** The common CPU algorithm on BF16 values versus on
   `float32(int8) * float32(stored scale)` differs by relative L2 `1.958e-2`
   (layer 0, sliding, `k_eq_v` false) and `7.759e-3` (layer 5, full, `k_eq_v`
   true); the production BF16-vs-INT8 difference is `1.973e-2` and `8.078e-3`.
   The original-versus-reconstructed comparison over the **complete** 64-slot
   K/V (prefill plus decode) gives, at layer 0, key rel L2 `1.48e-2` / max abs
   `6.55e-3` and value rel L2 `1.68e-2` / max abs `5.98e-2`; at layer 5, key
   `1.08e-2` / `2.39e-3` and value `1.08e-2` / `3.82e-2`.
4. **The replay reproduces the whole-model INT8 output bit-for-bit where the
   inputs are identical** (layer 0: relative L2 `0.0`, raw bytes equal), and
   differs where the whole-model inputs already differ (layer 5: `3.568e-2`, raw
   bytes not equal). The layer-5 whole-model arms are therefore *not* a
   fixed-input comparison; the replay supplies one and the distinction is
   recorded, not collapsed.

This is a **measurement**, not a mechanism proof. It does not establish "not
wiring", "not a race", "quantizer only", or intrinsic amplification. It
localizes the injection point, matches both consumers against one fixed
algorithm, and measures the fixed-input representation error.

## What was tested, and which contract

Diagnostic only. The script is a harness that calls existing registered kernels
and uses temporary diagnostic device buffers; no production source, kernel,
runtime, flag, admission or default changed. The comparison is the attention
boundary itself — the same BF16 query and written K/V fed to both consumers —
not a difference inferred from final model logits.

**Scope of the CPU comparison.** The common CPU algorithm reuses the existing
quantized oracle's own head row and mask semantics
(`hipengine.kernels.cpu_reference.gemma4_int8._attention_head_row`): a key is
visible when its absolute position is non-negative, no later than the query
position, and — on a sliding layer — strictly inside the window. The mask is
reused, not redefined. It is therefore a **shared-function consistency check**
(the GPU consumer and the CPU path agree when both run the same function), not an
independent second oracle, and the quantized-oracle self-check is the same kind
of statement. The artifact names this scope
(`cpu_shared_function_self_check_scope`) and records the CPU oracle and
dequantization source hashes (`cpu_control_source_sha256`).

Frozen before measurement:

- **Chain.** `prose_en_short` from the committed screening artifact
  `benchmarks/results/2026-10-02-gemma4-d12-int8-kv-teacher-forced.json`: 96
  prompt ids, prefill 63, first scored decode position 63, scored rows 32, chain
  sha256
  `ac020238439bfd683dc7ec9a7200440b182277f7931cad3c83ceeae5a80d9e32`. The loader
  recomputes that hash from the ids, requires it to equal the **independently
  pinned** constant `FROZEN_CHAIN_SHA256`, and requires `prompt_tokens`,
  `prefill` and `scored_rows` to equal their pinned values (`96`/`63`/`32`). A
  tampered prompt array whose supplied hash was recomputed to match is refused,
  as is altered prefill metadata; the pins are a diagnostic input invariant, not
  runtime identity admission, and gate no execution. No new or tuned prompt was
  introduced.
- **Tolerances** (`TOLERANCES`, asserted by a unit test): CPU shared-function
  self-check rel L2 `1e-6`; INT8 consumer vs CPU rel L2 and max abs `1e-4`; BF16
  consumer vs CPU rel L2 and max abs `5e-3`. The BF16 production output is read
  back BF16-narrowed, so the declared `max_abs` tolerance sits below the BF16
  rounding floor. The artifact records the floor beside the frozen tolerance, a
  `bf16_consumer_within_readback_floor` flag and a
  `bf16_consumer_matches_readback_floor_exactly` flag rather than relaxing the
  tolerance after seeing the result.
- **Arithmetic-order differences** are recorded verbatim in the artifact
  (`arithmetic_order_notes`): the CPU control uses numpy/BLAS `keys @ q`, `np.exp`
  softmax and a slot-order weighted sum; the GPU INT8 consumer uses per-warp
  strided partial dots reduced by a shuffle tree, `expf` softmax with a block
  max, and a slot-order weighted sum, all FP32; the GPU BF16 consumer uses the
  same products and stride-tree order as the exact prefill kernel. Only the
  reduction tree and the `exp` implementation differ; the frozen thresholds
  are evaluated as declared and can fail when BF16 rounding exceeds them.

## Frozen instrumentation

At the real attention boundary of each layer the capture reads the layer's hidden
input (before the call) and its BF16 `q_rot`, `k_rot`, `v` and `context` (after
the call, from the layer scratch), plus the INT8 arm's FP32 consumer scratch. It
records layer geometry (heads, KV heads, head_dim, sliding window, `k_eq_v`),
absolute positions (`write_offset..write_offset+rows`), the causal-plus-window
mask semantics, attention scale `1.0`, and attention logit softcap `null`. The
BF16 arm's selected route at this position is `exact` (one row is a decode step,
so the tiled and aotriton prefill routes do not admit it); the INT8 arm selects
writer `int8_per_token_head/per_token_head_bf16_spans` and consumer
`paged_attn_decode/int8_per_token_head/gemma4_direct_spans`.

## What remains unknown

- This is one forced position, two replayed layers, one host and one artifact.
  It localizes the first observed decode-boundary difference and measures both
  consumer comparisons against one CPU algorithm: INT8 passes its frozen
  control, while BF16 fails its max-absolute control. It does not prove the
  difference is "only" the quantizer across
  positions, nor exclude a state/control defect that happens to be identical at
  layer 0's inputs. The whole-model arms' bit-identical layer-0 inputs are
  measured, not assumed.
- **The earliest prefill divergence was not captured.** Prefill hidden input and
  context were recorded only at the two replay layers, so the localization above
  is a statement about the first observed **decode** boundary; the first
  divergent layer during prefill was not measured. The written prefill K/V
  equality is likewise measured at the two replay layers only, over each layer's
  complete 64-slot prefill history, not across all 30 layers.
- The quantization error is per-token/per-head KV representation error at these
  two layers. Whether a different quantizer (for example per-channel scales)
  would reduce it is a separate question and was deliberately not investigated.
- The replay matches the whole-model INT8 output exactly only where the whole
  model's inputs are identical; the layer-5 whole-model comparison is recorded as
  a non-fixed-input difference (`3.568e-2`).
