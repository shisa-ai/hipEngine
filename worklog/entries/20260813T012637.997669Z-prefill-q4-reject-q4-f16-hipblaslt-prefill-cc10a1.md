# Reject Q4 F16 hipBLASLt prefill

## Summary

Screened a materially different library consumer for the remaining exact Q4
FFN gate/up family: all 32 zero-algorithm-workspace hipBLASLt heuristics at
M512/1K/4K and output tiles 256/512/1024. The best large-row algorithm beats
both exact T16 and bounded rocBLAS at 1K/4K, but every M512 tile loses and the
hipBLASLt handle itself regresses device residency. The required uniform,
byte-neutral gate therefore rejects the route before runtime or W7900 work.

## Changes

- Added a compact rejection artifact with actual immutable weight identity,
  every tile's speedup, best-cell inclusive medians, leaf quality, memory
  deltas, exact command, source hashes, and decision.
- Updated the prefill exhaustion ledger, XTX scorecard, benchmark rollup, and
  changelog to record that hipBLASLt does not reopen the closed objective.
- Left production code, Q4 dispatch, decode, MTP, immutable payload ownership,
  and tracked scratch unchanged.

## Validation

- Best inclusive hipBLASLt versus exact T16 is
  **0.691x/1.051x/1.183x** at M512/1K/4K using tile 1024. M512 records **0/7**
  wins; 1K and 4K each record **7/7** wins.
- Versus bounded rocBLAS, the same cells are
  **0.803x/1.106x/1.218x**. All 32 heuristics report zero algorithm workspace.
- Leaf quality passes: minimum top-1 **99.414%**, maximum KL
  **1.0749e-6**, maximum absolute BF16-output difference **0.0078125** versus
  retained exact T16.
- The live hipBLASLt handle reduces free device memory by **180,355,072 bytes /
  172 MiB**; after handle close the process remains **192,937,984 bytes /
  184 MiB** below its pre-handle level.
- JSON syntax, `git diff --check`, and `scripts/worklog.py check` pass.

## Next

- Preserve the current exact-T16 and bounded rocBLAS owners. Reopen prefill
  parity only under the existing materially-new-dataflow/compiler/hardware
  conditions; do not add hipBLASLt for this non-uniform, memory-regressive path.
