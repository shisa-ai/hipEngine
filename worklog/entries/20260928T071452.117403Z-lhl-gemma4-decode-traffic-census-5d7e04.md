# spy_selected's accounting is correct and my earlier claim that it was wrong was mistaken

## Summary

`20260928T064512` asserts that `spy_selected`'s unpacking is wrong, reading
`selected_ptr, out_ptr, x_rows, rows` where dimensions are expected, and tells
the next reader to re-derive its byte figures. **That claim is false.** The spy's
real signature is

```python
def spy_selected(weight, x_ptr, selected_ptr, out_ptr, *a, **kw):
```

so `a` is `(x_rows, rows, num_experts, in_features, out_features)` and the code's

```python
rows, num_experts, in_features, out_features = a[1], a[2], a[3], a[4]
```

assigns `rows, num_experts, in_features, out_features` -- all four correct. I
made the claim by reading the *installed function* as `(weight, *a)` and then
comparing that assumed signature against `inspect.signature` of the real
function. The assumed signature was wrong, not the spy.

What remains true from that entry: `spy_mmq` counts the MMQ gate/up call and
never sums bytes, and `gemma4_project_experts_down_mmq` is not hooked at all. The
MMQ byte under-count is real and is the reason the re-run's 1868.4 MB is not the
current traffic. Only the `spy_selected` half of the diagnosis was wrong, and its
figures -- 793.4 MB q4_k and 528.9 MB q5_1 in `20260927T225558` -- are not
suspect on these grounds.

The census's *comment* above `spy_selected` is stale and is what misled me: it
documents `(x, selected, qweight, out, x_rows, rows, num_experts, in_features,
out_features)`, with `x` first and `qweight` fourth, where the real order is
`weight, x_ptr, selected_ptr, out_ptr, ...`. The comment should be fixed; the
code should not.

## Validation

```python
orig_selected = ex.gemma4_project_experts_selected
...
def spy_selected(weight, x_ptr, selected_ptr, out_ptr, *a, **kw):
    ...
    rows, num_experts, in_features, out_features = a[1], a[2], a[3], a[4]
```

against the real signature, read via `inspect.signature` on
`hipengine.kernels.hip_gfx1100.gemma4.gemma4_experts`:

```
gemma4_project_experts_selected(weight, x_ptr, selected_ptr, out_ptr, x_rows,
    rows, num_experts, in_features, out_features, *, stream) -> bool
```

`a` therefore begins after `out_ptr`, so `a[1]` is `rows`, `a[2]` is
`num_experts`, `a[3]` is `in_features` and `a[4]` is `out_features`. The four
assignments match. `spy_dense` uses the same convention (its own signature spells
the trailing arguments out explicitly) and its bytes reconcile exactly against
the printed shape table, 1866.7 MB for dense `gguf_q8_0`, which is the
independent check that this reading of the convention is right.
