# Matched AR baseline cell C1: TP2 vs optimized TP1, XTX arm blocked

## Summary

Built the matched-protocol harness for the first declared AR cell (C1: context
128 / output 128, full 18-prompt canonical+heldout suite, greedy, no EOS stop)
and ran it. **The cell is blocked**: the optimized TP1 resident graph-replay
route cannot run on the RX 7900 XTX (device 1), so the matched
TP2-vs-faster-TP1 ratio cannot be produced. TP2 and the W7900 TP1 arm both run
and pass accounting; their diagnostic ratio is 1.23-1.25x, which is **not** the
baseline because the XTX is the faster single-GPU arm and is missing.

Per the assignment, the eager TP1 control was **not** substituted for the
optimized route.

## Changes

- `scripts/tp2_matched_ar_baseline.py`
  - Declares cell C1 normatively.
  - `validate_accounting()` (pure, fail-closed): per prompt, timed decode
    transitions must equal the declared output tokens; the context position at
    timing start must equal `prompt_tokens + warmup` (so a nonzero warmup, which
    would start TP1 one position later than TP2, is rejected); the generated
    count must match each arm's prefill-sample convention (TP1 keeps the prefill
    sample, TP2 does not); full-vocabulary logits must be transferred on every
    timed decode step on both arms; EOS policy must be `none`; final logits must
    be finite.
  - `decode_ms_excluding_capture()` removes the TP1 per-prompt graph-capture term
    so the headline rate is capture-neutral on both arms; capture is reported
    separately.
  - Orchestrator runs each arm in its own process (a resident TP2 session and a
    resident TP1 session must not hold contexts concurrently) and records
    per-arm blockers instead of crashing.
- `scripts/gguf_true_ar_category_bench.py`
  - `--logits-every-decode-step` so the TP1 route matches the TP2 session's
    inherent per-step full-logit readback.
  - Records `timed_decode_transitions`, `context_position_at_timing_start`,
    `generated_count`, `logits_per_decode_step`, `eos_policy`.
  - **Latent-bug fix:** it passed `kv_scale_dtype=None` from
    `resolve_kv_selection("bf16")`, overriding the resident session's FP16
    default and failing every run with `ValueError: None is not a valid DType`.
    Now falls back to the session default.
- `tests/test_unit_scripts_tp2_matched_ar_baseline.py` — 11 CPU tests: accounting
  acceptance per arm, timed-transition mismatch, context-position mismatch,
  generated-count convention, non-finite/EOS/logits flags, capture exclusion,
  faster-arm ratio selection, `--reps < 3` rejection, and the predeclared cell.

## Blocker

The optimized TP1 resident route (`Qwen35GGUFResidentSession` via
`gguf_true_ar_category_bench.py`) does not run on device 1:

- graph replay: `Memory access fault by GPU node-2 ... on address (nil) / GPU
  Hang`, rc=-6, reproduced standalone (`HIP_VISIBLE_DEVICES=1`, one prompt) both
  with and without `--logits-every-decode-step`, so it is not the new flag.
- eager (`--no-graph-replay-decode`): `ValueError: token_id
  9223372036854775807 outside [0, 248320)` — an uninitialized token id.

The GPUs are healthy after each fault (idle, ~28 MB VRAM used); no reset was
performed. This is the same device-1 pathology family as the earlier TP1/TP2
teardown faults.
