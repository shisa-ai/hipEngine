# Add native phase and prefix-prepared HTTP benchmark contracts

## Summary

Extend the existing HTTP economics harness with native phase accounting and a
prefix-prepared cohort mode. Fix its unsupported metadata parameter using the
actual server request validator as a regression oracle. The product API is
unchanged; no kernel arithmetic changes.

## Changes

- Remove the unsupported top-level `include_hipengine` request parameter.
  Blocking responses already carry choice telemetry. Pin thinking off, EOS
  ignoring, greedy sampling and the requested speculative route; reject short
  completions even when their internal token counts are consistent.
- Validate native phase counts against generated IDs and usage, including
  cached/new prompt counts, finite durations and the first-token boundary.
  Keep summed output-count decode rates (Gufo's published convention), summed
  transition-count rates and whole-cohort throughput separate.
- Add `--prepared`: render chat prompts with the server, tokenize the rendered
  text, prefill every exact prompt minus its final token before the timed
  cohort, and require precisely that cached prefix during measurement. Accept
  frozen raw-token JSONL rows as well. This adaptation is explicitly distinct
  from Gufo's identical-prompt preparation.
- Exclude client construction and preparation from cohort wall; start ready
  workers through a barrier. Preserve preparation records and failures. Missing
  native timing is unavailable, never zero cost.
- Default to three measured repetitions with rotating arm order. Capture
  prompt hashes, commands and harness source before/after separately from the
  supplied resident-server manifest. Suppress ratios on any route or source
  failure. Document the adapter without claiming the open BASE packet done.

## Validation

- RED: both request-contract cases reproduce the unsupported-parameter error;
  the 28 initial prepared-phase cases fail for absent helpers. GREEN: 89 focused
  tests pass across prepared HTTP, economics and canonical comparator controls.
- `bg-11` completed successfully: full CPU deterministic bundle, real
  two-request AR/all-MTP/mixed HTTP validation with both raw IDs and
  server-rendered chat, and all four documentation gates. The validator ran
  unprepared and prefix-prepared waves, checked 12 measured responses and
  six preparation responses, and confirmed exact prefix reuse and route
  selection. Compact evidence:
  `benchmarks/results/20261021-qwen38fn-prepared-http-contracts.json`.
- These eight-output requests validate the harness, not performance. The
  supplied server manifest identifies its source, command and host; the
  harness records before/after source equality and exact request hashes.
