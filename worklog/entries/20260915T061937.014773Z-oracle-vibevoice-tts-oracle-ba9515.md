# Freeze the VibeVoice-TTS oracle: pinned checkpoint, fork, env, smoke test

## Summary

Step 1 of docs/MODEL-VIBEVOICE-TTS.md is done. The oracle is frozen and
produces speech on the W7900 under the pinned environment:

- Checkpoint microsoft/VibeVoice-1.5B @ c00898d2... downloaded to
  /models/vibevoice/VibeVoice-1.5B (5.1 GB, not committed).
- Community fork vibevoice-community/VibeVoice @ 952326dd cloned to
  /home/lhl/VibeVoice-community (read-only peer), installed editable
  --no-deps into a pinned venv /home/lhl/venvs/vibevoice-oracle
  (transformers 4.51.3 as the fork requires, diffusers 0.39.0, librosa;
  torch 2.10.0+rocm reused from the base env via --system-site-packages).
- Env quirk: the base env's CUDA flash_attn breaks transformers 4.51.3's
  import probe inside this ROCm venv; the venv's sitecustomize.py patches
  the probe to report flash_attn missing, so the oracle runs SDPA.
- Smoke test (demo harness, seed 20260915, Alice, one sentence): 148 tokens,
  27 generated, 3.33 s audio at 24 kHz, peak 0.348, RTF 3.75x under
  PyTorch-ROCm bf16 on the W7900.

Measured contract captured in docs/VIBEVOICE-TTS-CONTRACT.md with the full
inventory in benchmarks/results/2026-09-15-vibevoice-tts-oracle-inventory.json:
speech token ids (151652/151653/151654, eos 151643), latent scale 0.1962890625
/ bias -0.04931640625, 20-step DPM-solver timesteps/sigmas, codec depths/ratios,
per-module weight inventory (2704M + tied lm_head 233.4M).

scripts/vibevoice_tts_oracle_torch.py is the in-repo oracle driver: it writes
the inventory JSON and optional fixtures (token ids + waveform) for the
boundary gates.

## Changes

## Decisions

- Pinned the fork's transformers==4.51.3 in the venv instead of adapting the
  fork to the system transformers 5.13: the fork's modular code predates the
  transformers 5.x API changes and the oracle environment must be frozen, not
  modernized. The engine venv stays torch-free; the oracle driver runs only in
  the oracle venv.
- Blocking flash_attn via a patched availability probe (sitecustomize) rather
  than uninstalling the base env's package: the base env is shared; the patch
  affects only this venv.

## Validation

- Oracle smoke test executed on the W7900 (command in the contract doc):
  148 tokens, 3.33 s audio, 24 kHz, peak 0.348, non-silent fraction 0.895,
  no errors in the run log.
- scripts/vibevoice_tts_oracle_torch.py re-ran generation in-repo with the
  same seed and wrote the inventory JSON and fixtures; the inventory matches
  the reviewed doc's geometry table (width 1536 / 28 layers / 12Q-2KV / FFN
  8960 / codec ratios [8,5,5,4,2,2]).
- No engine-runtime code changed; the engine venv remains torch-free.
