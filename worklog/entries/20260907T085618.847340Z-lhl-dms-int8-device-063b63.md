# Add compact DMS INT8 device payloads and numerical gates

## Summary

The user reprioritized DMS INT8 integration over further dense boundary probes.
This unit implements the missing compact INT8 device payload store and kernels.
It does not enable model serving or create a model qualification artifact.
Dense INT8's highest demonstrated context is 54,272 tokens; no maximum is claimed.

## Changes

- Add registered gfx1100 INT8 pack, append/evict, and bounded split-K attention.
  Inputs are BF16 K/V; persistent payloads are signed INT8 with separate FP32
  K/V scales per token/head. The existing BF16 reducer is shared unchanged.
- Preserve eviction flags, positions and counts exactly. Ordered compaction
  moves payload bytes and scales without re-quantization and fails closed on
  capacity overflow. CPU codec/retention/attention oracles remain available.
- Add codec selection to DMSDevicePayloadStore, scale readback and exact scale
  snapshots. Restore validates all extents before writing any device bytes.
- Keep DMSCompactBackend's BF16-only device admission and resident factory
  unchanged until the next host integration unit and model qualification.
- Track serialized pack/append tuning debt in docs/REFACTOR.md. This is not
  a performance win or a claim of optimal serving throughput.
