# Correct Qwen3.8 soak physical-residency accounting

## Summary

Corrected the soak artifact after the first offered-c8 run exposed the registry-selected physical cap: Qwen3.8 accepts eight simultaneous HTTP clients, but the current plain-AR route groups them into two c4 waves. The previous `aggregate_live_context_tokens` label was therefore wrong for c8 even though the request/memory measurements were real.

## Changes

- Renamed the offered-width field and now derives effective physical residency from the server's actual initialized KV pages.
- Records maximum simultaneously resident context, whether queue waves are required, and every response's authoritative `hipengine.generation_shape`.
- Adds an execution-shape rollup with queue-group counts and physical backend widths; missing shape metadata now fails closed.
- Added focused tests for physical-capacity derivation and generation-shape retention/rollup.
