# Screen table-driven Inkling relative-bias attention

## Summary

The table-driven attention prototype eliminated the host bias projection for committed prefill blocks, but changed rounding. It passed the short numerical screen. The Strix Halo timing difference was too small for two pairs to justify integration.

## Changes

- Scratch only. Upload the 16-element relative query per head and use a resident, lag-major coefficient table in the tiled attention kernel. Keep the compact materialized-bias path for the control, decode, and provisional rows. Both arms use the same causal ring, sink, and history-commit ordering.

## Validation

- Built the prototype with `python3 /tmp/hipengine_inkling_table_bias_build.py hipengine/kernels/hip_gfx1100/attention/inkling2_target_attention.hip "$source"` and `hipcc -O3 -shared -fPIC --offload-arch="$arch" "$source" -o "$so"`. Ran `python -u ./hipengine_inkling_table_bias_trial.py "$model" "$backend" "$so"` at `294c0b1e4` on W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL. Both leaf fixtures passed against materialized bias at `atol=2e-6, rtol=5e-6`, including uneven blocks and wrap.
- The public `fast` route used FP32 KV and greedy generation without prompt reuse or drafting. All tested first-token argmax IDs agreed at 47, 151, 575 and 1,027 input tokens; maximum first-logit KL was below `4e-12`. All eight generated IDs matched at 151 and 575 on both devices. At 575 input the bias-specific payload fell from 846,402,048 to 42,393,600 bytes, excluding the one-time coefficient-table upload.
- At 575 input, median control/trial request seconds were 7.159/6.634 on W7900 and 10.446/10.249 on Strix Halo, from two warm samples per arm in reversed order. This is not a matched Loom comparison. Logs: `/tmp/kendex-pi-bg/bg-102-1795328613284.log`, `/tmp/kendex-pi-bg/bg-103-1795328613301.log`.
