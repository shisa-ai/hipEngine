# Confirm Qwen3.6 and Qwen3.8 dense speed equivalence

## Summary

Confirmed the requested Qwen3.6-27B versus Qwen3.8-27B `Q4_K_M` speed
equivalence on Radeon 8060S/gfx1151 at 512/128. Qwen3.8 differs by only
**+0.0537% prefill** and **-0.0348% decode**; complete measured wall differs by
**+0.0021%**, tracked peak is byte-identical, and both clear the predeclared
absolute 3% equivalence rule. This is a compatibility/speed diagnostic rather
than a cross-model quality or topline claim.

## Changes

- Retained a compact comparison artifact with full model SHA-256 values,
  clean-component provenance, every timing sample, memory/graph/correctness
  sanity, raw-source hashes, the initial loader blocker, and the decision.
- Added a compact benchmark changelog entry while keeping the numeric diagnostic
  out of the current scoreboard/topline, as required for rows without a quality
  gate.
- Kept the benchmark separate from the preceding `caf544241` loader-policy fix
  so the measured revision is a clean committed implementation.

## Validation

- Both files have the same qwen35 execution configuration, 866 tensor
  descriptors, shape/type counts, and 17,095,778,304 tensor payload bytes;
  their full-file SHA-256 values differ as expected for different weights.
- Clean hermetic TheRock gfx1151 runs at commit `caf544241`: repeated token
  9707, one discarded warmup, three measured persistent-session resets,
  effective bulk WMMA prefill, effective GEMV decode, and cached 128-step
  state-bound HIP graph replay with zero native fallback.
- Qwen3.6 medians: **84.7744 prefill / 7.06873 decode tok/s / 24.3112 s wall**.
  Qwen3.8 medians: **84.8199 / 7.06627 tok/s / 24.3117 s wall**. Prefill CV is
  0.213%/0.271%; decode CV is 0.0071%/0.0027%.
- All measured final logits are finite, every model's three final IDs are
  stable at 9707, every graph replays 128 steps, tracked teardown reaches zero,
  and both tracked peaks are exactly 33,993,777,540 bytes (31.659 GiB).
- Raw evidence is under
  `/tmp/hipengine-qwen36-qwen38-compare-20260814-185850`; the compact artifact
  SHA-256 is `5def0ab52f8c58360dd14622a2daf08d88c911a7ccbee8e9b143be0502182447`.

## Next

  dense-27B sole-T16/prefill/PM4 policies are explicitly keyed to
  `Qwen3.6-27B`; Qwen3.8 needs an independent correctness/performance transfer
  gate on that hardware before those optimized policies can be extended.
