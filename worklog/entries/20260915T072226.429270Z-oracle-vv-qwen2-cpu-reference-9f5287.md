# Qwen2 backbone CPU reference validated against the pinned HF oracle

## Summary

M3a opened with the oracle-side mirror: hipengine/kernels/cpu_reference/
vibevoice_qwen2.py implements the full backbone forward in FP32 numpy
(Qwen2Geometry 1536/28L/12Q/2KV/128/8960/151936, theta 1e6, eps 1e-6, tied
embeddings), the BF16 weight loader with the full shape contract, and
prefill/decode hidden-state plus tied-logit entry points.

Three defects were caught before any device work, each by a RED unit test:

1. Causal masking for cached attention: a plain tril over
   (tokens, total_len) masks the whole cached prefix for every query row
   after the first; the diagonal must shift by past_len
   (np.tril(..., k=total_len - tokens)).
2. attention_forward returned a cache containing only the current layer's
   k/v, so threading one cache dict through the layer loop dropped every
   other layer's sequence state; the cache now merges the incoming state.
3. RoPE convention: the reference used interleaved (GPT-J) pairs while
   Qwen2 uses rotate-half (NeoX, contiguous halves with duplicated
   cos/sin tables). Fixed rope_cos_sin to full-width duplicated tables and
   apply_rope to the half-split form.
