# Bind paired MTP to production graph AR

## Summary

The paired natural25 suite used synchronous scalar `step()` as its true-AR
performance denominator even though hipEngine's production single-row AR path
is state-bound decode-graph replay. GPU1 tracing proved the two paths execute
the same device work (28.77 eager vs 28.88 graph ms/transition, about 860
launches) while eager host submission stretches wall to 65-69 ms/transition
against 31 ms for graph. The prior XTX rates and every ratio derived from them
are therefore invalid.

Changed the suite's default no-MTP arm to recorded decode-graph replay. The
graph records every generated transition on device so AR/MTP token-ID
comparison remains complete, while graph capture and the one final ID readback
are reported separately from decode wall. The paired protocol now pins this
mode and evidence completeness rejects an eager payload.

## Changes

- Added `--ar-decode-mode {graph,eager}` to
  `scripts/qwen36_dense_gguf_suite.py`, defaulting to `graph`; retained eager
  only as a synchronous diagnostic control.
- Added graph capture/replay/record/readback lifecycle and per-row transport,
  capture, and readback metadata to the true-AR runner.
- Added `ar_decode_mode=graph` to `PAIRED_PROTOCOL`, resolved commands, and
  payload identity validation.
- Mechanically invalidated the old GPU1/XTX paired artifact and removed its
  rates from the current benchmark scoreboard. Preserved non-timing
  determinism, acceptance, near-tie, and state-ownership observations.
