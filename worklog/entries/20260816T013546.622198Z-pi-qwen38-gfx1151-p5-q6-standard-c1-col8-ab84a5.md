# Reject gfx1151 standard-Q6 c1 col8 decode

## Summary

Reject the exact standard-Q6 c1 col8 output subdivision for Qwen3.8's 24
K5,120/N10,240 recurrent-QKV projections. On a **123.047-MiB** rotating pool of
three actual QKV weights, the candidate is BF16-bit exact but measures
**0.611306 -> 0.611347 ms (0.99993x, 9/15 wins)**. It projects
**-0.005 ms / -0.0004%** of selected 4K graph wall, far below the >=1% gate.

## Changes

- RED extended the existing standard-Q6 col8 exactness fixture to rows1 and
  failed at the intended missing C-launch case. GREEN instantiated the existing
  exact local128 col8 body at rows1 for both BF16 and FP32 output.
- Screened actual `blk.0`, `blk.28`, and `blk.62` Q6 recurrent-QKV weights as
  one rotating pool. More than 64 MiB of immutable T16 bytes lies between
  repeats of each role, avoiding a small-buffer MALL result.
- Preserved the rejection at
  `benchmarks/results/2026-08-16-gfx1151-qwen38-27b-q6-standard-c1-col8-rejected.json`
  and restored all transient kernel/test changes before publication.

## Validation

- RED fails with `HIP error 1: invalid argument`; GREEN passes both rows1
  BF16-output and FP32-output bit-exact nodes on gfx1151.
- All three actual outputs are finite and BF16-bit exact with zero mismatches,
  KL 0, 3/3 top-1 agreement, and tracked memory 0 -> 0 bytes.
- Current standard-Q6 owns **76.579996 ms / 5.925%** of the selected 16-token
  4K trace. Clearing 1% complete wall requires **1.20305x** family speedup; the
  measured route is neutral/slightly negative and therefore receives no
  runtime or full-model gate.
- `git diff --exit-code` over the transient source/test paths passes after
  restoration. The screen uses cached gfx1151 code after the GREEN build.

## Next

  the same stream across twice as many blocks; rerank a different complete
