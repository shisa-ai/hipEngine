# VibeVoice-TTS session: unassisted negative path and voice-prompt entry point

## Summary

Two integration defects that the existing gates could not see are fixed, and a
gate is added for each. First, `generate()` always called
`_negative_condition(None)`, so the negative LM pushed the speech-start
embedding on every frame and the accumulated-feedback branch was dead code; the
session tests injected recorded negative conditions, so they compared fixture
values against themselves. Second, `voice_prompt_rows()` had three defects
(a stray `[0]` index, a padding expression that appended a whole extra frame
for aligned input, and an RNG that only existed after `generate()` ran), and no
test called it.

The generated token chain stays exact even with a completely wrong negative
branch, which is why this needed a condition-level gate rather than a chain
gate.

## Changes

- `hipengine/runtime/vibevoice_tts_session.py`:
  - `generate()` now passes the previous diffusion frame's feedback embedding to
    `_negative_condition`, so the negative LM accumulates
    `[embed(speech_start), feedback_0, ..., feedback_{n-1}]` as the fork does.
    `_negative_reset()` clears the tracked feedback at speech boundaries.
  - `voice_prompt_rows()` drops the `[0]` index (the encoder already returns
    `(frames, hidden)`), derives the frame count from the encoder result instead
    of recomputing it, and fixes the pad expression to `(-size) % 3200` so an
    aligned reference is not padded by a whole extra frame.
  - The RNG is created in `__init__` instead of inside `generate()`, so the
    voice prompt can be prepared first, and one stream now covers the voice
    draw plus every diffusion draw. `generate()` no longer re-seeds, which
    matches the fork's single `torch.manual_seed` before generation.
- `tests/test_live_vibevoice_tts_session_gpu.py`: new
  `test_session_negative_path_without_injection` supplies recorded noise but no
  `neg_hook`, so the session's own negative branch runs. New
  `test_voice_prompt_rows_matches_reference` calls `voice_prompt_rows()` directly
  instead of reconstructing the chain inline. The previous inline test is
  replaced by `test_voice_prompt_scaled_features_match_reference`, which takes
  `sampled` from the entry point and checks only the scale/bias arithmetic
  against `features_scaled`.

## Validation

- `uv run pytest tests/test_live_vibevoice_tts_session_gpu.py -v` — 7 passed,
  1 xfailed.
- The unassisted negative path reproduces the oracle's exact 27-token chain and
  matches the `callN_neg_condition` fixtures at relative error 0.014 / 0.012 /
  0.020 for calls 0 / 1 / 2 and 0.111 / 0.060 for calls 12 / 24.
- The gate is discriminating, verified by emulating the old behaviour (pass
  `None` to `_negative_condition`): calls 1 / 2 / 12 / 24 move to relative error
  1.51 / 1.68 / 2.15 / 2.02, while the token chain stays exact. So a chain-only
  gate would have kept accepting the defect.
- `voice_prompt_rows()` now returns `(70, 64)` for the pinned reference; the
  previous code raised `cannot reshape array of size 64 into shape (70, 64)`.
- Hardware: AMD RYZEN AI MAX+ PRO 395 w/ Radeon 8060S (gfx1151).
