# Surya OCR over the OpenAI-compatible HTTP API: engine-declared vision bounds and media form

## Summary

Surya OCR now runs through `hipserver`'s `/v1/chat/completions` multimodal
branch. The branch was Qwen4Exp-shaped in three ways that made it unusable for a
page-scale OCR model, and each is now an engine declaration rather than a
hardcoded constant:

1. **Decoded-image bound.** `decode_bounded_png_data_url` capped every image at
   1024 px a side. A 300-DPI A4 page is 2480x3508, so every real page was
   rejected with `unsupported PNG geometry`. The bound now comes from the
   engine's declared `vision_max_pixels` (Surya: `SURYA_MAX_PIXELS`, 16.78 MP →
   4096 px side), and the compressed-payload bound scales with the admitted
   area because a 300-DPI document does not compress like a thumbnail. An
   engine that declares nothing keeps the previous 1 MP / 1024 px / 8 MiB
   scope exactly.
2. **Media form.** The branch handed the engine a Qwen4Exp-specific
   `{"items": [...]}` mapping. Surya's generator takes one RGB array. An engine
   now declares `vision_media_input` (`"items"` default, `"image_array"` for
   Surya), and `media_for_engine` adapts; a request with more than one image to
   a single-image model is a 400, not a silent reshape.
3. **Prompt markers and error text.** The extractor appended Qwen4Exp's
   `<|vision_start|><|image_pad|><|vision_end|>` to the prompt, which would have
   corrupted Surya's prompt: `render_chat_prompt` derives the image pad span
   from the patch grid itself. The markers are now engine-declared
   (`vision_prompt_marker`, `""` for Surya), and the Qwen4Exp-branded error
   strings are model-neutral.

An image-only request (no text part, or whitespace) now substitutes the
engine's declared `vision_default_prompt`. Surya is prompt-driven — the text
*is* the task — so an empty prompt would have produced garbage rather than a
transcription. A caller driving a different protocol (`LAYOUT_JSON`,
`BLOCK_HTML`) still passes it explicitly and gets it verbatim.

## Changes

- `hipengine/server/multimodal.py` — `resolve_vision_http_limits`,
  `vision_max_side`, `vision_prompt_markers`, `media_for_engine`; `max_pixels`
  and marker parameters on the extractor; `decode_bounded_png_data_url` gains
  `max_pixels`. `extract_qwen4_exp_chat_media` is renamed to the model-neutral
  `extract_chat_media`; the only caller (a test) is updated, so no compatibility
  alias was left behind.
- `hipengine/server/api.py` — `ServerConfig.vision_max_pixels` /
  `vision_max_image_bytes` (validated positive-or-None), limits and markers
  resolved from the attached engine per request, media adapted before the
  generator call, default-prompt substitution.
- `hipengine/server/__main__.py` — `--vision-max-pixels` /
  `--vision-max-image-bytes` plus `HIPENGINE_VISION_MAX_PIXELS` /
  `HIPENGINE_VISION_MAX_IMAGE_BYTES`.
- `hipengine/generation/surya.py`, `hipengine/generation/surya_gpu.py` —
  declare `vision_max_pixels`, `vision_media_input`, `vision_default_prompt`,
  `vision_prompt_marker`.
- `tests/test_surya_server_multimodal.py` — new; `tests/test_qwen4_exp_server_multimodal.py`
  follows the rename.

The new file's 15 cases are the load-bearing ones. The A4 case is not a
synthetic stand-in: `test_the_committed_a4_page_decodes_under_the_surya_bound`
decodes the committed 2480x3508 `page_a4.png` fixture and asserts it *is*
rejected under the Qwen4Exp scope it used to be limited to, so the bound change
is pinned in both directions. The end-to-end cases assert the generator receives
a bare `np.ndarray` (not the items mapping) and that the prompt is exactly
`FULL_PAGE_HTML_PROMPT` with no inline marker. The fake LLM reads its vision
declarations off `SuryaOCRGenerator` rather than restating them, so the server
tests fail if the generator's declaration drifts. `_Qwen4ExpLikeLLM` declares no
vision attributes at all and pins the unchanged 1 MP / 1024 px / 8 MiB default.

Not validated: no HTTP request has been served by a real loaded Surya
checkpoint. Every case above uses a fake generator behind `create_app(llm=...)`,
which exercises the transport, bounds, media adaptation, and prompt selection
but not the model. The transcription quality of the A4 page through this path is
therefore unmeasured — and the direct-call measurement is currently a failure
(see Next).
