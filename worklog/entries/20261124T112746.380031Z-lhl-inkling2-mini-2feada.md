# Bisect the loop re-entry by substitution

## Summary

Replacing the block's own values at the loop re-entry with the host's makes the next visit worse for the attention input and the branch, and materially better for the third message. The message result contradicts an earlier measurement in which that message agreed with the host to 9.5e-06, so the substitution harness needs one more check before its numbers are used.

## Changes

- Added env-gated substitution of the attention input, the branch and the third message at the loop re-entry, loading the host values captured from the same process's `prefill_block` traversal.

## Validation

64 rows, fast profile, `hip_gfx1100`, all four runs in one process, compared against the host's own `prefill_block` capture at boundary 19.

| substituted | k=19 max abs |
| --- | ---: |
| none | 6.065e+00 |
| attention input | 9.163e+00 |
| branch | 7.720e+00 |
| third message | 4.311e+00 |

- The baseline reproduces 6.065 exactly across processes, so the block is reproducible for this measurement.
- Substituting the attention input or the branch makes the result worse, so those two values are the best available in the block's own state and neither is the defect.
- Substituting the third message moves the result by 1.75, which cannot come from a 9.5e-06 difference. Either the host capture in this harness is taken at a different visit than the block's re-entry, or the earlier message comparison was not measuring the same bytes. The 9.5e-06 agreement was measured as query-major against the same host array, so the visit alignment is the likelier fault.

## Next

- Confirm the substitution harness is visit-aligned before drawing anything from the message row: print the boundary index of the host capture and of the block's re-entry in the same run. If they differ, fix the capture; if they agree, dump the block's third message and the host's in the same run that performs the substitution.
