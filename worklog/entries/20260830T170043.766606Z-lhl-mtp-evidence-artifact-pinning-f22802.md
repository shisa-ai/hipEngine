# Declared MTP serving evidence is pinned to a different model artifact

## Summary

Answers step 2 of `20260830T165837` (was it artifact identity drift?). It is not drift
of a file: the declared
MTP serving evidence belongs to a different model. `model_artifact_identity`
(`hipengine/models/kv_capabilities.py`) is a cached **full-file** SHA-256 whose
`size_bytes` comes from `stat()`
- the raw weights file, not a materialized plan - and the serving key takes `artifact_sha256` /
`artifact_size_bytes` from that identity via `weight_index.path` or `model_path`
(`hipengine/generation/qwen35_gguf.py:918-934`, same shape at `:1689`). The rows declared in
`hipengine/models/qwen35.py` pin `artifact_size_bytes = 22_663_387_424`, which equals
`/models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` byte-for-byte, while the C1-C8 matrix loads
`/models/gguf/Qwen3.8-27B-Q4_K_M.gguf` at 17,106,773,984. So the artifact axis cannot
match for the benchmarked
model at any width, and automatic MTP cannot qualify for Qwen3.8-27B on this host
regardless of width, batch
shape, or capacity.
