# Accept gfx1151 Q5T16 0.8B QKV route

## Summary

D08-P1 found a shipped-route miss rather than a kernel-arithmetic problem: all
18 Q5_K linear-attention QKV weights in Qwen3.5-0.8B Q4_K_M were expanded to
BF16 on gfx1151 even though the existing Q5T16 direct, rowtile, and WMMA leaves
cover the exact `[6144,1024]` shape. Admit one sole-resident Q5T16 policy for
that exact role/shape. Keep Qwen3.6 Q5T16 `ssm_out` and its fused recurrent
families excluded on gfx1151.

## Changes

- Added backend capability `GGUF_DENSE_Q5_T16_QKV=True` only to gfx1151 and
  exposed the three existing generic Q5T16 linear variants there.
- Scoped the materialization policy to `layers.*.attn_qkv` with exact shape
  `(6144,1024)`; no duplicate resident layout is retained.
- Set the measured native rowtile bound to c4 and repaired generic native T16
  dispatch so c5-c8 falls through to its registered same-ABI WMMA sibling
  instead of calling a c1-only decoder with an invalid row count.
- Added RED/GREEN policy, backend-registry, and native-dispatch tests.
- Updated the campaign punchlist and benchmark rollup with the accepted route.
