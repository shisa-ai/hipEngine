# Retire request-local ngram composition from dense MTP2 adapter (R0204)

## Summary

The request-local n-gram + MTP2 catch-up composition (`ngram_enabled=True`,
`ngram_config=NgramModConfig(...)`) was a default-off diagnostic candidate with
recorded failures: the strict D96 SQL terminal-suffix failure and the production
D120 numerical-tail rejection. No wider-frontier repair was funded, so the runtime
composition is retired under the lead's 2026-11-07 retire-failed-candidates
decision. `hipengine/speculative/ngram_mod.py` and its unit tests remain as the
research reference.

## Changes

- `hipengine/generation/qwen35_gguf_mtp2.py`: removed the `ngram_enabled`/`ngram_config`
  constructor inputs, `_NgramBatchDeviceProposal`, the n-gram cycle token workspace,
  `_try_ngram_proposal`, the n-gram branches in `propose_batch` and in single- and
  batch-verify, `_repair_provider_states_from_ngram_target_rows`, the
  `proposal_ngram`/`ngram_candidate_tokens`/`proposal_source` request state and the
  release/close hooks. Ordinary MTP2 host, device and batch-device proposal paths
  are unchanged.
- Deleted `tests/test_unit_ngram_adapter_configuration.py` and the three n-gram tests
  in `tests/test_unit_qwen35_gguf_mtp2_seam.py`; `scripts/qwen38_packed_c1_teacher_run.py`
  no longer passes `ngram_enabled=False`.
- `docs/ENVS.md`: the retired-n-gram note says the composition is gone.

## Validation

- `tests/test_unit_qwen35_gguf_mtp2_seam.py`, `tests/test_unit_speculative_ngram_mod.py`,
  `tests/test_live_generation_qwen35_gguf_sampling.py`: 326 passed, 1 skipped.
- Public `LLM.generate(speculative_mtp=True)` on Qwen3.8-27B-UD-Q4_K_M (gfx1151), widths
  1-4, two repeats each: every row token-identical to AR; zero tracked allocations after
  close. A separate width-2 run confirms the route: 18 `Qwen35GGUFMTP2Adapter.propose_batch`
  calls.
