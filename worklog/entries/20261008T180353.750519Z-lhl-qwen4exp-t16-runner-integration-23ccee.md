# T16 runner integration lands: +6.15% p4096 prefill on the 30-layer window

## Summary

The T16 gate/up route is integrated into the production runner and measured at
the engine level. The env-gated branch (HIPENGINE_QWEN4_EXP_T16_GATE_UP=1,
default off) in the Q4 gate/up dispatch looks up per-weight T16 tiles in a
module-level cache keyed by the gate weight's raw device pointer and calls the
T16 dual compensated kernel over the same compact maps, then the existing
dual-out SiLU - replacing the iu8-risk + sparse repair chain for that call. A
cache miss falls through to the production iu8 chain, so the strict fallback
is structural and the default path is untouched.

The same-residency engine A/B on code-p4096 with a 30-of-47-layer tile window
(the full 47-layer tile set at ~43 GiB does not fit alongside the resident raw
weights in the 120 GiB UMA; 37.1 GiB free after model load bounds the window):
**prefill 351.468 -> 373.088 tok/s (+6.15%)**, decode 18.081 -> 17.990
(within noise; the T16 branch is prefill-only). Cross-arm outputs are not
identical (arithmetic-changing T1: F16 WMMA with compensated accumulate) -
the binding correctness authority is the layer2 production gate, and this A/B
measures performance. Extrapolated to all 47 layers the projection is
**~+9-10% prefill at p4096**, the campaign's first 1500-class lever.

  the 30-layer-window A/B artifact.

## Validation

- 43 focused tests green after the runner change; the default path is untouched
  (env default off; cache miss falls back to the production chain).
- Engine A/B: one residency, balanced arms, warmups both arms, engagement via
  the populated cache (30 layers), prefill +6.15% at p4096, decode unchanged
  within noise. The T1 numerical question (prefill_last) is for the layer2
  gate, not this A/B.
