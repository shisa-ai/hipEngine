# Give each Inkling block attention row and KV head one wave

## Summary

Campaign step 3, item 7 (task 17). Prompt-block attention gave one 128-thread block to each (query
head, row) and walked the live context 16 keys at a time with three barriers per step. It was the
largest prefill stage at 2,057 prompt tokens: 2.0 of 5.3 s of kernel time. A kernel with one 32-lane
group per (row, KV head) now serves those blocks in `fast`: a group takes its KV head's three query
heads, reads keys and values as 16-byte vectors, and keeps the softmax and the value sums in
registers. It changes the reduction order, so the tiled kernel stays as the control and the judge
is the profile gate.

once; 24 query heads over 8 KV heads of width 128, relative width 32):

## Changes

- `inkling2_target_attention.hip`: `inkling2_target_attention_waves<GROUPS>` and the entry
  `hipengine_inkling2_target_attention_block_waves`, registered as
  `inkling2_target_attention/inkling2_mixed/block_table_waves` on both HIP backends. Per pass four
  groups of eight lanes each take one key; a lane holds sixteen columns of that key and of the
  query heads. The dot product sums the eight column chunks of a lane and then the eight lanes;
  the running maximum is taken per pass of four keys. The block's `__launch_bounds__` lets a lane
  keep its query and value columns in registers: at the compiler's default the kernel spilled 568
  bytes per lane and ran 3,946 us on a 256-row block.
- The launcher takes 128-wide heads with one to four query heads per KV head, a relative width that
  is a multiple of four up to 32, and 16-byte-aligned rows. Other shapes go to the tiled kernel.
- `Inkling2GGUFGenerator` selects `block_table_waves` for `fast` where it is registered; the plan's
  `resident_block_relative_bias` selection names it with `block_sigmoid` as the strict fallback.

## Validation

- `tests/test_gpu_inkling2_wave_attention.py` (10 passed on the W7900): against the tiled kernel
  for 1, 3, 5, 17, 33, 64 and 130 rows over capacities 5 to 1,024, including rings that wrap and
  three, two and one query head per KV head, within 5e-5 absolute and 1e-3 relative (largest
  observed difference 3.3e-5); against float64 causal attention for every row of a 150-row
  sequence; with evicted slots and a permuted slot map; and a 67-wide head routed to the tiled
  kernel bit for bit. A second owner repeats the first bit for bit.
- Two defects were found by these tests before any model ran: the table bias was scaled with the
  dot product, and the final sum over the four keys ran on lanes 0 to 7 only, which reads nothing
  useful from a lane that skips a shuffle.
- The Inkling GPU and unit test files pass on the W7900 with the model present: 405 passed in
  3 minutes.
- **Profile gate, working tree, 687 rows against strict.** `fast_resident` and `fast_graph` pass
  all six gates: KL median 1.4e-13, p90 0.00060, top-1 0.9985, no damaged flip, bit-identical
  repeats and isolated requests. `fast` without the route flags fails the code scope: KL p90
  0.097 against 0.020 and 7 of 48 rows with a damaged flip against at most 3. That scope also
  failed at `ec2fa6d32` with the tiled kernel, at KL p90 0.027 and 1 of 48. Both runs prefill
  through the same blocks and differ in how the experts are routed. The harness marks all three
  rows invalid for a claim because the tree was uncommitted; clean-tree rows follow.
