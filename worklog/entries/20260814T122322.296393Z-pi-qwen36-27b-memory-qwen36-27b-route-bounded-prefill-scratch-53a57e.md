# Retain dense 27B route-bounded prefill scratch

## Summary

Retained a model-scoped dense-prefill lifetime improvement without changing the 4096-row full-attention query geometry. Dense SiLU now replaces the dead BF16 gate plane in place, and the arena planner represents the gate and up halves with distinct physical subrange lifetimes so unrelated stage-disjoint fields can still reuse the dead up half safely. The final XTX matrix reduces tracked peak by 8.9375/18.75/20.625/20.625 MiB and whole-device peak by 11.160/17.965/21.750/21.547 MiB at 512/1K/4K/8K; prefill/decode movement stays within 0.171%.

This is a retained incremental win, not memory parity. Whole-device peak is now 16.083/16.287/17.001/17.256 GiB, still 0.394/0.587/1.089/1.090 GiB above the lower llama.cpp Vulkan floors. The memory objective therefore remains open.

## Changes

- Made `silu_mul_separate_out_kernel` alias-safe for gate/output while retaining the unchanged elementwise BF16 formula and the ordinary unfused fallback.
- Added explicit in-place-alias and physical-subrange metadata to the single-arena liveness planner; the dense 27B `ffn_intermediate` view now owns the first half of `ffn_gate_up` without allowing any other simultaneously-live allocation to overlap it.
- Extended benchmark scratch census output with the intentional alias and subrange lifetimes.
- Added RED/GREEN allocation coverage and a HIP exact-bit test for BF16 gate replacement.
- Rejected and removed a larger combined candidate that also sized linear-attention scratch to 1024 rows. Its first 8K run failed closed because the outer scheduler requires 4096-row linear scratch; an exact subchunk repair completed with finite/exact output and lower memory but regressed 8K prefill 820.061 -> 795.989 tok/s (-2.94%). No chunking/scheduling change remains.
