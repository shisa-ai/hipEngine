# Snapshot arena pooling and the one-row reused-suffix route

## Summary

Two prefix-cache costs removed. Snapshot capture allocated one device buffer
per GDN conv and recurrent state - 36 on Qwen3.5-0.8B, 54 on Qwen3.6-35B - on
every eligible turn whether or not the snapshot was ever reused. It now carves
one pooled arena, and the arena from an evicted snapshot is recycled, so a
steady-state capture allocates nothing. Separately, a one-token reused suffix
no longer takes the batched route: a one-row prefill leaves the bulk schedule,
which made such a hit disagree with the miss it replaced.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: new
  `_GGUFPrefixSnapshotArenaPool` (retains up to four arenas per exact capacity)
  and a per-session accessor. `capture_prefix_state_snapshot` sizes one arena
  from the 4096-aligned per-layer totals and carves non-owning views from it.
  `Qwen35GGUFPrefixStateSnapshot` gains `arena`/`arena_pool`; `close()` returns
  the arena to the pool instead of freeing each view, which would have been a
  double free.
- `hipengine/runtime/qwen35_gguf_runner.py`: `_run_post_attention_ffn_rows`
  gains `force_bulk_rows`, passed by the three prefill call sites
  (`_run_full_attention_prefill_layer_aotriton`, and both FFN dispatches in
  `_run_linear_attention_prefill_layer_rows`). It keeps a one-row prefill off
  the dense GEMV decode variants. Decode callers are untouched.
- `hipengine/generation/qwen35_gguf.py`:
  `_gguf_prefix_batched_suffix_chunk_eligible` routes a suffix chunk shorter
  than two rows to the serial step, and `_gguf_prefix_suffix_segments` no
  longer splits in a way that strands a single token.

## Validation

- Capture cost, gfx1151, measured by counting `malloc` through both the runner
  and `hipengine.core.memory` (`DeviceMemoryArena.create` goes through the
  latter), six captures with older snapshots closed so the pool can recycle:
  * Qwen3.5-0.8B, 20.6 MB snapshots: **36 mallocs every capture** on the
    pre-fix baseline (b4f99f27b, measured in a worktree at that commit) versus
    **1 then 0** after; steady-state wall 0.78 ms -> 0.58 ms.
  * Qwen3.6-35B-A3B UD-Q4_K_M, 66.8 MB snapshots: **1 then 0** mallocs, wall
    **5.57 ms -> 0.73 ms** per capture.
- Snapshot restore stays exact with pooled arenas:
  `scripts/gguf_prefix_reuse_gate.py --prompt-file
  benchmarks/prompts/mtpbench-code-general-ja.jsonl --prompt-category code
  --prefix-tokens 1024 --suffix-tokens 200 --max-sequence-length 2048
  --teacher-forced-steps 16` with `HIPENGINE_GGUF_PREFIX_BATCHED_SUFFIX=0`
  reports `status: passed`, `initial_state_exact: true`, `kl_mean 0.0`,
  `top1 1.0` on Qwen3.6-35B-A3B.
- Unit: `test_unit_gguf_prefix_cache_runner.py`,
  `test_unit_gguf_packed_verify_layout.py`,
  `test_unit_gguf_packed_workspace_stability.py`,
  `test_unit_kvcache_backend_prefix.py`, `test_unit_gguf_prefix_reuse_bench.py`,
  `test_unit_prefix_cache_multiturn_bench.py`,
  `test_unit_qwen35_gguf_capacity.py`,
  `test_unit_qwen35_gguf_prefill_scratch_liveness.py` - exit 0, zero failures.
- Live: `tests/test_live_qwen35_gguf_chunked_prefill.py` - exit 0.
- The one-row route change is pinned by the reuse tests, which now assert the
  serial step for a 257-token prompt over a 256-token prefix instead of a
  one-row batched prefill.
