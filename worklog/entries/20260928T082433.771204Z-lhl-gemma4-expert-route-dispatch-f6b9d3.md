# the expert route dispatcher is unreachable so its pack8 preference is dead code

## Summary

`20260928T081147` got the mechanism wrong and this corrects it. That entry said
the packed expert layout is never built because "`hipengine/runtime/gemma4.py`
contains no reference to the packed layout at all". The loader **does** build it:
`hipengine/loading/gemma4_gguf_device.py` defines
`_PACK8_ALLOCATION_NAMES = ("qweight", "scales", "mins")` and materialises
`("scales", scales, DType.FP32)` and `("mins", mins, DType.FP32)`. Searching one
file for the layout name was the wrong test, and the conclusion it produced was
wrong.

The real mechanism is stronger. **`gemma4_project_experts_rows` -- the route
dispatcher that documents the four-route preference order -- is called from
nowhere in `hipengine/`.** Neither is `gemma4_project_experts_pack8`. The only
caller of `pack8` is `rows` itself, and `rows` has no caller:

```
grep -rn "project_experts_rows\|project_experts_pack8" hipengine/ --include=*.py \
  | grep -v "def \|gemma4_experts.py"
(no output)
```

So the dispatcher and every route behind it are unreachable, and the decode path
reaches its kernels by calling route-specific entry points directly --
`gemma4_project_experts_gate_up_mmq` and `_down_mmq`. The documented preference
order is not a live policy being evaluated and overridden; it is a policy nothing
executes.

That reframes the `pack8_selected` finding. `22d80e1c7` measured the packed
representation 1.25x faster than the raw one on identical shapes (54.0 against
43.4 GB/s on Q4_K gate/up), and `rows` documents it as preferred over
`selected_gemv`. But there is no routing decision to flip: the packed layout is
already materialised at load time and simply never read, because the only code
that would choose it is dead. Using it is new wiring, not enabling a flag.

## Validation

```
grep -rn "project_experts_rows\|project_experts_pack8" hipengine/ --include=*.py \
  | grep -v "def \|gemma4_experts.py"
```

returns nothing, and `gemma4_project_experts_pack8` is called only from
`gemma4_project_experts_rows` inside `gemma4_experts.py`. `_PACK8_ALLOCATION_NAMES`
and the `scales`/`mins` payloads are at `hipengine/loading/gemma4_gguf_device.py`
lines 59, 467 and 468.

The parts of `20260928T081147` that stand: the decode default is an MMQ32 prefill
kernel that packs activations and takes a `copy_device_to_host`; `pack8_selected`
is 1.25x faster than `selected` on identical shapes; and `pack8_selected` has
never been run as a decode route.

The parts that do not: the claim that the runtime never requests the packed
layout, and the implied remedy that a planner change would enable it. The layout
is already there.
