# EVIE batch validation review: cache-lifetime fix, strict fallback, matched harness

## Summary

Responded to review 67c191 (commit 14294253a):

1. **P1 cache-lifetime bug (confirmed, fixed).** The 4-entry attention
   scratch eviction ran per acquisition with only the current key
   protected, so a mixed shape sequence could free the q/k planes of the
   in-flight attention call (the reviewer's CPU regression reproduces it
   deterministically). Restructured: _evict_caches now runs ONLY at
   attention-call start with the full keep set of that call's keys
   (q/k/v/attn_out + scores for _attention; packed/out + scores for
   _attention_from_packed), caps raised to 8 planes / 6 score buffers,
   and per-acquisition eviction removed. Plane/score buffers are live
   for exactly one attention call, so start-of-call eviction with the
   call's keys is provably safe. The reviewer's
   tests/test_evie_attention_buffer_lifetime.py passes.
2. **Strict fallback registered.** The original pre-coalescing
   elementwise kernel bodies are preserved as _strict variants
   (rmsnorm, layernorm, rope, gdn_rmsnorm_gate, gdn_l2norm_scale_repeat)
   selected at launch via HIPENGINE_EVIE_STRICT_ELEMENTWISE. Verified:
   strict-env reproduces the pre-campaign doc parity byte-for-byte
   (4.415214e-05 vs oracle); the coalesced default gives 4.355982e-05;
   the fp16 manifest re-pin stands on its own measured envelope
   (3 bit-identical runs) with the strict fallback available.
3. **Reproducible matched-protocol harness committed**:
   scripts/evie_matched_protocol_torch.py (torch env; generates shared
   real-processor inputs, times bf16/fp32) +
   scripts/evie_matched_protocol_hip.py (batched encode, same timing
   boundaries, quality vs the torch fp32 teacher). End-to-end rerun
   reproduces the retained numbers: hip fp16 1173.3/1172.7 ms vs torch
   bf16 1292.8/1299.5 ms (1.10x lead); quality hip fp32 1e-4 8/8, hip
   fp16 0.0176 max 8/8 argmax, torch bf16 0.245 max 5/8. Scoreboard row
   and CHANGELOG updated; artifact extended with harness/fallback
   fields.
