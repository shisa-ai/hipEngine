# Port local DMS/XML commits onto upstream main

## Summary

Five local commits from 2026-10-28/29 (INT8 compact DMS serving, DMS prompt
hidden backing, DMS prefill control, XML tool-parser parity, DMS readiness
provenance) were replayed onto origin/main `2db46eda9`, whose DMS session
acquisition, bulk-prefill hidden storage, engine service, chat-output parser
and readiness payload had all been reworked in the meantime. Each commit was
checked against upstream for what was still missing; all five still added
behavior upstream lacked. Their original worklog entries are kept unchanged;
this entry records how the port differs from them. The pre-rebase tip is kept
locally as `backup/main-pre-rebase-20261124` (`21ff2949c`).

## Changes

- INT8 DMS serving: upstream already chooses the INT8 compact backend at shared
  session construction; kept the `LLM`/`ServerConfig` changes that stop
  rewriting explicit `int8_per_token_head` to BF16 for DMS, and DMS metadata
  that reports the prepared codec.
- DMS prompt hidden backing: rebuilt on upstream's grow-on-demand hidden
  capacity instead of the original free-and-reallocate. Layer-outer DMS starts
  chunk-sized and grows to the prompt length at DMS prefill entry, never to the
  configured logical context.
- DMS prefill control: landed thread-safe frontend tokenization, child-scoped
  stop intent, prefill checkpoints, quiesce-before-free cleanup, and rollback of
  bound and unbound submissions on a partial admission failure. Not landed:
  closing the service when reclamation fails, and withdrawing queued commands
  whose caller timed out. Upstream keeps a child's cancel-time close error local
  (`test_generic_only_real_adapter_retires_paused_child[close_error]`) and keeps
  queued admission owned until it runs or retires; those contracts stand, and
  the four tests that asserted the opposite were dropped. An admission-rollback
  reclaim error is published on the child's terminal instead.
- XML tool parsing: the final-parser fix moved to `hipengine/server/chat_output.py`
  (two move-pin AST hashes re-pinned); endpoint tests moved to
  `tests/test_integration_server_tools.py` and
  `tests/test_integration_server_replay.py`.
- DMS readiness: the `/ready` DMS status/policy/active-store/last-observed fields
  and the request-configuration markers are now rendered by
  `hipengine/server/readiness.py` from a new `dms_retention` snapshot input.
  The DMS runner's own policy record call was dropped because shared session
  construction already records it.

## Validation

- RED against origin/main code: the XML/server test files 65 failed; the DMS
  readiness/public-config/metrics files 13 failed; the hidden-backing tests 10
  failed. All pass on the port.
- Default unit tier (`uv run pytest`): 29,073 passed, 115 skipped, 15 failed,
  all 15 in `tests/test_unit_dms_request_ownership.py` from the redundant DMS
  policy call; after removing it that file plus the DMS public-config and
  readiness files: 41 passed.
- Server/tool/chat/readiness plus DMS/engine-service/generation integration
  bundles: 4,390 passed, 31 skipped (the same 15 failures, since repaired).
- Public `hipengine serve` on W7900 (gfx1100), Qwen3.8-27B-Q4_K_M with the local
  W8192 DMS sidecar, `--kv-storage int8_per_token_head --dms-prefill-mode
  layer_outer --max-context-tokens 32768`: `/ready` reported DMS `prepared` with
  INT8 per-token-head storage and an observed INT8 compact store; a plain chat,
  a streamed XML tool call (`{"command":"ls -la /tmp"}`, finish `tool_calls`),
  a long-prompt stream disconnected after 3 chunks, and a refill all succeeded;
  `/ready` stayed `ready` with no active stores afterward. No errors in the
  server log.
