# c8 FFN gate/up: add ROW_TILE=8 dense dual rowtile SiLU (weight read once)

## Summary

The c8 (rows=8) FFN gate/up (the dominant FFN cost, 5120x17408 x2) was falling
back to the slow `t16_wmma_prefill` GEMM because the dense dual rowtile SiLU was
gated to rows 2-4. Added a native ROW_TILE=8 instantiation of the dense dual
rowtile SiLU (weight read once for all 8 rows) instead of a 2x4 split. c8
improved **125.4 ms -> 116.9 ms/step, 63.6 -> 68.6 tok/s** (2.25x c1),
prefix-exact and repeatable; c2/c4 unchanged (`c1_c2_c4_prefix_exact = True`).
c8 is still NOT close-to-linear (per-row 14.6 ms vs c4 10.7 ms): the FFN is now
~2x c4 (expected for 2x rows), so the remaining excess is the GDN/attention
(non-FFN) stage scaling ~2.6x c4 for 2x rows — that is the next bottleneck.

## Changes

`hipengine/kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.hip`:
- `q4_k_t16_dense_dual_rowtile_silu_gemv_kernel`: `__shared__ uint16_t
  projected[2][4][kTileCols]` -> `[2][ROW_TILE][kTileCols]`. The middle dim was
  hardcoded to the 4-row max, which would overflow for ROW_TILE=8. Templated, so
  ROW_TILE=2/3/4 are unchanged (`[2][N][8]`) and ROW_TILE=8 is `[2][8][8]`
  (256 B shared). The SiLU reduce loop already iterates ROW_TILE.
- `launch_q4_dense_dual_rowtile_silu`: `rows > 4` -> `rows > 8` and added
  `Q4_T16_DENSE_DUAL_ROWTILE_CASE(8)` (instantiates the kernel at ROW_TILE=8;
  block 64 = gate wave + up wave, weight read once).

`hipengine/kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.py`:
- `_check_dense_q4_t16_rowtile_shape`: rows `2..4` -> `2..4 or 8`.

`hipengine/runtime/gguf_linear.py`:
- `_q4_t16_dual_rowtile_silu_dispatch`: allow `rows == 8` for the `sole_t16`
  path only (the pack8 path stays rows 2-4). Keeps the exact 5120x17408 shape
  gate.

## Validation

Qwen3.8-27B-Q4_K_M / W7900 / gguf_packed_ar_bench p128-d8 warmup1 measured2
(artifact /tmp/hb-c1248-r8.json):
- **c1_c2_c4_prefix_exact = True**, all runs repeatable -> c2/c4 not regressed by
  the shared kernel/dispatch change; c8 passed + repeatable (deterministic, exact).
- c1/c2/c4 = 33.0 / 37.2 / 42.9 ms; 30.43 / 53.87 / 94.46 tok/s (1.00x/1.77x/
  3.10x c1) — matches the committed 19d08b8bf values within run-to-run variance.
- native_c8: **116.9 ms/step, 68.6 tok/s** (was 125.4 ms / 63.6 tok/s with the
  2x4 split; the gate/up now uses ROW_TILE=8, weight read once).
- c8 per-row 14.6 ms vs c4 per-row 10.7 ms: still not close-to-linear. The FFN
  is ~2x c4 (reasonable); the non-FFN (GDN 48 layers + full-attention 16 layers)
  scales ~2.6x c4 for 2x rows — the remaining c8 bottleneck.
