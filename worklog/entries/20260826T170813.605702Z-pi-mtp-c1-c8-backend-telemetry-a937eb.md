# Use backend telemetry for historical MTP engagement

## Summary

Added backend-owned MTP engagement proof for historical server responses that
correctly select route `speculative_mtp` but predate compact response-level MTP
usage summaries. The OLD Qwen3.6-35B llama-compat C1 preflight produced
~70-89 tok/s versus ~31 tok/s AR with deterministic outputs, but response
summaries were empty and the harness correctly withheld the result.

## Changes

- Snapshot `generator.last_batch_generation` after each completed arm.
- Require a GGUF MTP path, matching batch width, nonzero total draft tokens, and
  nonzero direct/per-request cycle records.
- Accept a cell when either current response telemetry or historical backend
  telemetry proves engagement; timing and correctness contracts are unchanged.
- Added positive historical and AR/K0 negative tests.

## Validation

- Before this change, OLD C1 completed all prompts but reported 0/10 engaged.
- Focused harness tests pass 7/7; `py_compile` and diff hygiene pass.
