# Record the post-visit capture trap a second time

## Summary

The host's `blocks` list captured from `_prepare_layer` is post-visit, so it already contains the row the visit appended and cannot be used as the input to that visit's residual read. The 12.66 attention-read difference this produced is withdrawn.

## Changes

- No code change; the comparison was withdrawn after checking how the reference was built.

## Validation

- `_prepare_layer` appends `_rms(h)` to `blocks` for a stride layer before the MLP read, and the list is shared with the caller, so a capture taken after the call sees one more row than the read did.
- Recomputing the reference read from that list therefore uses one row too many. The block reads `count + 1` rows with `count = 1` after the restore, and the host reads `blocks + 1` with one block, which is the same two rows.
- Rows 0 and 1 of the stack are exact against a capture taken the same way, because they are prelude and boundary rows that the visit does not append to.

## Next

- Capture the read's block list from inside `_prepare_layer` before the append, or reconstruct it as `blocks[:-1]` for a stride layer, and repeat the attention-read comparison for the re-entry visit. Until that is done the re-entry attention read is unverified rather than wrong.
