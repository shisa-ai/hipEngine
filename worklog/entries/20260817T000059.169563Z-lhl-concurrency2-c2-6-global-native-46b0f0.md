# Concurrency2 global pool and physical c2 native promotion

## Summary

Resolved Task 19's short-request hardware blocker. The live gfx1100 Qwen3.6 GGUF BF16 route now uses `GlobalKVPoolSet`, exact shared-slot native execution, and registered physical c2 decomposition through logical c32. The earlier serial slot fallback remains the numerical fallback. C2-6 as a whole remains open for model long-context, graph/prefix page changes, SLO/soak, second-gfx11, and external gates.

## Changes

- Added `GlobalDeviceKVPool`, a resident-plugin bridge over `GlobalKVPoolSet` with arbitrary free-page leases, cache/COW/pin ownership, stable storage generation, fixed capacity, and legacy-shaped allocation envelopes only at the model binding boundary.
- Qwen now allocates one load-time device KV arena and one pointer table for every full-attention key/value/mirror/scale plane, publishes `global-arbitrary-pages:g1`, and selects that pool before the old chunk fallback.
- Scoped the Q8_1/dp4a direct-top1 shortcut to c1 after its multi-row output produced an invalid sentinel. Multi-row uses the existing Q6 rowtile-logits plus GPU argmax chain without full-logit D2H.
- Registered gfx1100 shared-slot physical widths `(1, 2)`. Wider logical widths lower to c2 groups plus an honest c1 edge; physical c4/c8 remain absent.
- Flush the batch owner's canonical packed state before a different session tuple or serial edge reuses the workspace. This repairs c2-group composition beyond the first decode step.
- Corrected native F1 route validation to use resident execution telemetry rather than per-HTTP-call prompt grouping.
- Added pool fragmentation/cache/pin/capacity/lifecycle tests, direct-top1 scope coverage, registered-width lowering coverage, and global-pool request diagnostics/observability.
