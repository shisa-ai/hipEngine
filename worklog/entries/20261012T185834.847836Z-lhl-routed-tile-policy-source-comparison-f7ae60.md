# Routed tile policy source comparison

## Summary

The source comparison now identifies a concrete apples-to-apples experiment for
the routed-expert gap. gufo chooses a 16..80-column tile by minimizing a
count-aware padding/panel cost over the observed per-expert histogram, then
uploads a tile map. hipEngine also uses count-aware grouped metadata and
multiple 48/64/128-row maps, including a fused F16 gate/up path, but its
objective, map ownership, and route admission differ. The local screen shows
that nominal tile width materially changes cost, so the histogram and selected
map must be replayed across implementations.

## Changes

- Added the gufo-versus-hipEngine routed-tile source comparison to
  `docs/QWEN4EXP-CROSS-ENGINE-GAP-MATRIX.md`.
- Recorded gufo source locations in `executor.cpp` and `qfn_mmq.hip.cpp`, and
  the corresponding hipEngine routed dispatch locations.

## Validation

- Source inspection confirms gufo's cost sweep over widths 16..80 and its
  count-derived tile-map upload.
- The committed synthetic screen confirms tile16 beats tile32 by about 2.2x
  on both balanced and sparse distributions.
- No runtime behavior changed.

`code-p4096` in both engines, then replay those same distributions through the
same-operand routed kernels.
