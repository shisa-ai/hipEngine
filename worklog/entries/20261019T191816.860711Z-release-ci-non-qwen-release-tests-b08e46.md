# Repair non-Qwen no-ROCm release test failures

## Summary

The completed no-ROCm Python 3.12 run (235 failures/errors in
`/tmp/hipengine-v080-ci-suite.xml`) left nine failures outside the Qwen
shared-batch MTP cause. All nine were stale test expectations or a missing
guard, not product defects: no production module, runtime default, artifact
resolution rule, or evidence gate changed.

Two GPU nodes in `tests/test_gpu_gemma4_expert_route_true_geometry.py` called
`malloc` and therefore `get_hip_runtime()` with no availability guard, so a
no-ROCm host raised `OSError: libamdhip64.so` instead of skipping. The other
seven were expectations that production has since moved past:

- `run_qwen35_gguf_native_mtp_cycle` now passes `sampled_accept` and
  `sampled_accept_state` to `verify_target_block_native_cycle`, and the target
  graph cache key gained the sampled-accept bit as a fourth element. The
  greedy-cycle expectation and the short/split-k bucket expectation still
  described the older shapes.
- `tests/test_unit_gemma4_runner_lifecycle.py` had acquired a `pytest.skip` for
  the HIP runtime on a CPU-only case. That skip broke the contract
  `tests/test_integration_gemma4_no_hip_lifecycle.py` exists to enforce: the two
  modules it re-runs in a subprocess that prohibits `ctypes.CDLL("libamdhip64.so")`
  must pass with nothing skipped. It also contradicted the durable audit
  decision for `unguarded-hip-test/tests/test_unit_gemma4_runner_lifecycle.py`,
  which records the module as CPU-only and states that a skip guard there would
  be wrong.
- `test_pinned_ud_q4_k_m_resolves_through_manifest_not_stamp` gates on the UD
  artifact but then reads the plain `Q4_K_M` control, which is absent on this
  box. Its `Q4_K_S` sibling already guards that control; this one did not.
- The assistant-forward guard compared `HEAD.parent` against `BACKBONE.parent`
  lexically. `/models` is a symlink to `/home/lhl/models` here, and sidecar
  discovery returns resolved paths, so the guard failed on two spellings of one
  directory rather than on a stale pin.

## Changes

- `tests/test_gpu_gemma4_expert_route_true_geometry.py`: add the module's
  existing `@_needs_hip` marker to
  `test_mmq_route_does_not_read_its_scratch_capacity` and
  `test_mmq_route_row_zero_is_invariant_under_an_appended_row`. Both drive the
  real MMQ route through `malloc`, so they are GPU tests that were missing the
  guard the rest of the module already carries.
- `tests/test_unit_gemma4_runner_lifecycle.py`: drop the HIP skip from
  `test_multi_block_forward_takes_the_head_only_on_the_final_block` and give it
  `_FakePrefillStageRuntime`, a stand-in for the stream and event handles the
  pipelined prefill staging requests once every launch is replaced. The case
  stays in the CPU module, keeps its norm/projection launch-count assertions,
  and gains a check that both blocks actually staged, so the counts can no
  longer pass vacuously on a single block. No test moved between tiers.
- `tests/test_live_gguf_native_spec_cycle.py`: add
  `"sampled_accept": False` / `"sampled_accept_state": None` to the expected
  verify kwargs of the greedy complete cycle, and extend the expected target
  graph cache keys to the four-element form `(rows - 1, device_accept_commit,
  context_limit, sampled_accept)`. Both expectations now assert the greedy route
  explicitly rather than omitting the fields.
- `tests/test_live_gguf_ud_admission.py`: skip
  `test_pinned_ud_q4_k_m_resolves_through_manifest_not_stamp` when
  `PLAIN_Q4_K_M` is absent, naming the missing path, exactly as the `Q4_K_S`
  sibling does. The negative-control assertion is unchanged and still runs
  wherever the control exists.
- `tests/test_unit_gemma4_assistant_forward_guard.py`: compare resolved paths
  (`module.BACKBONE.resolve().parent`, `module.HEAD.resolve().parent`). The
  invariant is unchanged: the resolved head must sit beside the backbone or in
  its `MTP/` directory.
