# Match the re-entry stack row by row

## Summary

Two of the three stack rows the block reads at the loop re-entry are exact and the third is 8.717 wrong. That third row is the one the block materializes from the attention output, and it matches neither the host attention output, its normalization, nor any prelude row, which contradicts an earlier measurement in which the attention output itself agreed to 7.629e-06.

## Changes

- Dumped the block's stack rows, its visit count sequence and the host's block count sequence.

## Validation

64 rows, fast profile, `hip_gfx1100`, host and block captured in one process.

| row | block vs host |
| ---: | ---: |
| 0, prelude | 1.907e-06 |
| 1, boundary | 5.722e-06 |
| 2, materialized from the attention output | 8.717e+00 |

- The visit counts agree: the host holds one prelude row at the loop entry, the block restores `saved = 1`, and both skip two rows when they index the abandoned pass. Widening the copies to `saved + 1` was therefore wrong and is reverted.
- Row 2 matches neither the host attention output (1.992e+01), its normalization (8.717e+00), nor prelude row 0 (3.223e+01).
- An earlier run measured the block attention output against the host's at 7.629e-06 at the same visit. If that reading was right, row 2 should agree to about 1e-05. The two measurements cannot both hold, and the discrepancy is unresolved.
