# Add bounded exact-Q4 DMS capture

## Summary

Added a default-off, bounded exact-GGUF capture path for external DMS training.
The runtime tap exports only the 16 physical full-attention layers, names their
compact indices separately, captures the schema-v2 normalized pre-Q input stage,
and leaves ordinary `LLM.generate()` behavior unchanged. Raw capture shards stay
outside Git.

## Changes

- Added `DMSCaptureWriter` and a strict manifest loader. Each prefill chunk is an
  atomic checksummed NPZ containing BF16-bit normalized hidden rows, token IDs,
  positions, and post-head-norm/RoPE Q/K. FP32 Q/K is the exact default; an
  explicit FP16 storage diagnostic is disclosed in the manifest.
- Added deterministic next-token teacher top-K/logsumexp capture, complete
  per-layer sequence coverage checks, size bounds, path confinement,
  source/command/host provenance, and manifest/companion SHA-256 files.
- Added the default-off `dms_capture` sink to GGUF bulk prefill. It validates the
  loaded model's full-attention map and geometry, synchronously copies the exact
  intermediate buffers before reuse, and rejects serial/native-mode or
  no-logits capture requests before mutation.
- Added `scripts/qwen38_dms_capture.py` with exact Qwen3.8 Q4_K_M geometry/hash
  validation, tokenizer fingerprinting, versioned corpus-manifest validation,
  category/split/provenance requirements, and hard rejection of the evaluation-
  only mtp-bench source.
- Added CPU writer/manifest/data-policy tests and a HIP-guarded real-GGUF prefill
  integration test.
- Documented the capture format in `KVCACHE.md` and its removal/promotion trigger
  in `REFACTOR.md`.
