# Reject long SPECDEC2 eager activation

## Summary

Reject automatic long-context eager SPECDEC2 admission from P2 evidence. Exact
streaming activation works through p16K and retains only one 10 KiB carried row,
but current Generation-2 uses shifted scheduler KV pages and the packed target
prefill owner. Complete staged/direct wall is **23.242/19.338 s at p4K** and
**106.362/86.433 s at p16K** (1.202x/1.231x regression). The attempted C1
scalar TargetHiddenChunkSink route correctly declined shifted block-table
allocations and did not change p4K wall; it is rejected and not retained.

P2 should retain streaming only inside the previously qualified short context.
Longer rows select K0 before speculative mutation until a separate exact shifted-
page eager target owner passes its own gate.

## Changes

- Restore `SpeculativeCapability.max_context_tokens` to min(1023, live target
  capacity).
- Remove the unmeasured scalar C1 branch/test; physical and shifted ownership
  remain packed.
- Preserve long target/session capacity and streaming primitives for future
  qualification, but do not expose them through current speculative policy.

## Validation

- Clean p128/p512/p4K/p16K streaming diagnostics are exact and zero-final-
  ownership; p4K/p16K numeric regressions above reject long admission.
- Dirty p4K scalar candidate remains exact but unchanged at 23.245 s and reports
  `native_compact_prefill=true`, proving shifted page ownership stayed packed.
- Focused policy/adapter/sink/bridge tests and Python compilation pass.
