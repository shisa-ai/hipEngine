# Review Eaman MTP Compact Rollback for gfx1151 follow-up

## Summary

Reviewed the Eaman llama.cpp MTP Compact Rollback implementation against the
completed gfx1151 CONCURRENCY2 campaign and current hipEngine target-state
ownership. Compact rollback is a real new **capacity** candidate, not evidence
for a throughput win: it decouples draft maximum from retained recurrent
rollback rows, uses one pre-reserved per-slot device checkpoint, and replays
already selected target inputs only after a rejection exceeds the retained
depth. The source report explicitly labels its headline context/TG rows
directional rather than a matched A/B.

The local runtime already owns an initial Conv/GDN checkpoint and a target-only
state replay path, but still allocates every native verify-row Conv/GDN state.
That makes a bounded D1 experiment plausible. It is not yet justified: the
83,794,462-byte request allocation is unattributed, the fingerprinted product
key rejects context 68, and the closed campaign has no c>1 product cell.
