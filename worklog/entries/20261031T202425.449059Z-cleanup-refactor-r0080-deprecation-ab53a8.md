# Warn on the legacy speculative candidate-budget alias

## Summary

R0080 now has the explicit compatibility transition: a valid legacy-only
`HIPENGINE_GGUF_MTP_CANDIDATE_BUDGET` request emits a `FutureWarning` and still
returns its exact requested depth. The alias remains functional; no fallback
read, capability check, or requested-depth rewrite was added.

## Changes

- `hipengine/speculative/candidate_budget.py` warns from the one shared
  resolver only when the canonical name is absent and the legacy name resolves
  to a valid positive integer. Canonical-only and agreeing-name requests do not
  warn. Malformed, non-positive, and conflicting values raise before the
  warning branch.
- `FutureWarning` is used instead of `DeprecationWarning` because the setting is
  operator-facing and Python hides `DeprecationWarning` outside `__main__`.
  `stacklevel=2` attributes the warning to the resolver caller.
- Direct-caller docstrings/help in `hipengine/llm.py`,
  `hipengine/generation/qwen35_gguf.py`, and `hipengine/server/__main__.py`
  describe the legacy name as deprecated while keeping the generic direct
  provider default and explicit constructor precedence unchanged.
- Caller inventory: active scripts and examples already write only
  `HIPENGINE_SPECULATIVE_CANDIDATE_BUDGET` (`gguf_mtp_c1c8_server_bench.py`,
  `qwen38_packet5_k4_watchdog_probe.py`, `specdec2_c1_gate.py`,
  `specdec2_perf_bridge.py`, `specdec2_s6_category_gate.py`,
  `qwen36_moe_mtp2_production_gate.py`). No active script/example migration was
  left to do. Legacy names in tests and historical evidence were preserved.
- Compatibility tests now assert the warning through the direct `LLM`,
  server CLI, and direct generator surfaces while retaining their exact-depth
  and reporting assertions.
