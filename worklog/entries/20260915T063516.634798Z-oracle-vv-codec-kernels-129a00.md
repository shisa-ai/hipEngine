# Port the VibeVoice codec decoder primitives to HIP kernels

## Summary

M2b is done: all eight decoder primitives now run as raw-pointer HIP kernels
on the W7900 and match the CPU reference.

hipengine/kernels/hip_gfx1100/vibevoice/codec_ops.hip defines
conv1d_valid_dense, conv1d_valid_depthwise, conv_transpose1d_causal,
rmsnorm_channels, gelu_erf, add, channel_scale and linear; codec_ops.py wraps
them with ctypes and registers the four-axis keys
(hip_gfx1100, <primitive>, fp32, vv_codec_v1).

Validation (tests/test_gpu_vibevoice_codec_ops.py, 10 tests, all passing):
every primitive is compared against
hipengine/kernels/cpu_reference/vibevoice_codec.py on the same fp32 inputs
with calibrated tolerances (1e-4 to 1e-6 by primitive); the transposed conv
is parametrized over all four decoder strides (2/4/5/8 with k = 2*stride).

rocprofv3 --kernel-trace (prebuilt .so, compiler-version file,
/tmp/vv/rocprof/vvcodec_results.db): hipengine_vv_conv1d_valid_dense_f32 ran
5 times under its expected name, 25.7-37.0 us per launch at the bring-up
shape (2048 outputs x 8 positions x 448-tap dot, one thread per element) -
plausible for an untuned first cut; tuning is later work.

## Decisions

- One thread per output element for the first cut: correctness against the
  reference gates first, tuning after the model module composes the full
  decode and the launch profile is known.
- Fixed a device page fault during bring-up: the transposed-conv tap loop
  allowed (j - tap) / stride to go negative for tap > j; the guard now
  skips taps above j (matching the reference's keep mask).
