# Fix Qwen4Exp PLE prompt staging ownership

## Summary

Fixed Qwen4Exp chunk prefill's PLE two-buffer staging ownership. Earlier prompt
rows were overwritten before stacking, causing the large fast-prefill KL
failure. Corrected full-stack top-1 is 100% and max KL is 0.0155, though
production mean/p95 remain above promotion limits.

## Changes

- Added `stage_qwen4_exp_ple_rows`, which copies each ring view immediately into
  one owned contiguous FP32 prompt matrix.
- Replaced delayed `np.stack` over aliased two-buffer views.
- Added a ring-alias regression that fails under delayed copying.
- Retained corrected evidence at
  `benchmarks/results/2026-08-27-gfx1151-qwen38-flash-next-ple-staging-fix.json`.

## Validation

- Focused PLE/QSA/GDN/MoE bundle: 11 passed.
- Every layer-0 final row was captured: bulk differences are tiny ULPs (many
  rows exact; max BF16 difference 4.88e-4). Correct PLE input no longer shows
  the prior ~0.38 corruption.
- Plain chunk64 natural suite before→after: mean KL 0.13033→0.00564, max
  0.64962→0.02663, top-1 94.44→100%; corrected speed 13.47 tok/s.
- Full grouped/WMMA/peer stack before→after: mean KL 0.17169→0.00476, max
  1.34378→0.01548, top-1 94.44→100%; corrected speed 35.43 tok/s.
- Warm repeated-token p512 remains 211.76 tok/s.
- Fast stack remains default-off because mean/p95 0.00476/0.01458 exceed the
  production limits 0.001/0.005, despite every row staying below 0.02.
