# Qwen4Exp MTP batched verify with state commit

## Summary

Qwen4Exp MTP is now above true AR on the full 10-prompt category suite:
1.107x at budget 3 (25.06 vs 22.64 tok/s), 1.125x at budget 4, from 0.825x
with serial verification. Mixed JA/EN is still 0.92x (acceptance 39%).

## Changes

- `4b5d80a3e` per-token GDN (row-split) and conv state capture kernels.
- `f4e939a48` `verify_target_block_state_rows` / `commit_target_block_rows`
  in the runner (capture by ContextVar keyed on the GDN state pointer; the
  mixer raises if a capture was requested and a non-capturing owner ran);
  provider uses one pass per cycle; `scripts/qwen4exp_mtp_inprocess_bench.py`.

  (bit-identical), 3-row verify 76.3 -> 59.5 ms.

Comparison with the in-tree Qwen3.5 GGUF MTP (asked for by the owner): the
Qwen3.5 runner already verified with per-row linear-attention state rows
(`capture_linear_state_rows`, `*_state_rows` GDN/conv kernels) and
committed the accepted row; Qwen4Exp lacked that and replayed or verified
serially. Gemma 4 MTP code is not in this tree (checked `hipEngine`,
`hipEngine-main` and all branches); the only Gemma 4 sources on the host
are in `~/atlas` (AGPLv3, not ported) and `~/amd-gpu-tuning` notes.

## Validation

- GPU tests: state-row kernels vs prefix runs (bit-exact), rowtile parity.
- Probe: full and partial accept followed by decode reproduce the AR tokens
  (12/12, 10/10); acceptance identical between serial and batched verify.
- Full-suite economics: `benchmarks/results/2026-10-14-qwen4exp-mtp-batched-verify/`.
  8/10 MTP outputs equal the AR arm; the two divergences come from the
  prefill-shaped verify arithmetic (production profile), not control.
