# Remove rejected GGUF MTP final-state fastpath

## Summary

Removed the default-off no-capture/final-state MTP verifier path. It preserved
acceptance but regressed c4 76.83 to 66.75 tok/s because partial/reject cycles
restored a snapshot and replayed the consumed prefix. Serving verification now
has one state contract: capture verifier linear-state rows, defer commit, and
commit the accepted row (directly or from the packed owner).

## Changes

- Removed `HIPENGINE_GGUF_MTP_SERVER_VERIFY_FINAL_STATE_FASTPATH`, its resolver,
  and all serial, packed, and single-request branch points.
- Packed and per-slot target jobs now unconditionally request
  `capture_linear_state_rows=True` and `defer_linear_state_commit=True`.
- Simplified direct commit: partial and direct-exact full blocks require captured
  rows; deferred packed owners commit the accepted row in place. The separately
  required serial-exact replay for non-direct full blocks remains unchanged.
- Replaced positive-path tests with absence and captured-partial-commit
  contracts; retained deferred-scatter, packed fallback, and normal MTP tests.
- Removed completed entries from `docs/REFACTOR.md`; immutable rejection evidence
  remains in artifacts/worklogs.

## Validation

- RED: the removed-route absence contract failed while the env/branches existed.
- GREEN focused verifier bundle: 5 passed (absence, packed verifier,
  deferred-owner commit, captured partial commit, batch-notimplemented fallback).
- Additional ordinary-route bundle: 3 passed (single-request llama-compat MTP,
  c2 resident slots, deferred-scatter default/opt-out).
- `python3 -m py_compile` and `git diff --check` pass.

untouched. No target arithmetic, candidate acceptance, kernel, registry, or
