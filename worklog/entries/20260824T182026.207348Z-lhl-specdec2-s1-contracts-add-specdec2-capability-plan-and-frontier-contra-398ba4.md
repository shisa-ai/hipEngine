# Add SPECDEC2 capability plan and frontier contracts

## Summary

Implemented the first SPECDEC2 S1 production contracts: one immutable composed
capability, pre-mutation mixed K/K0 request plans, host/device candidate graphs,
and root-only or candidate target frontiers. The contracts remain backend-
neutral and torch-free; host-visible candidates project through the retained
`DraftBatch`/`TargetVerifyBatch` oracle topology, while device token buffers do
not require a host candidate copy.

## Changes

- Added `hipengine/speculative/frontier.py` with typed attachment, catch-up,
  transaction-mode, and stable plan-reason enums.
- Added `SpeculativeCapability` shape/sampling/graph/eager/fallback validation.
- Added `SpecRequestPlan`, including mixed K0/speculative groups and honest
  physical proposal/target decomposition.
- Added `CandidateGraph` request-local parent/depth/slot ownership with host or
  torch-free device token descriptors.
- Added `TargetFrontier` for AR root-only and root+candidate work, preserving
  existing `TargetVerifyBatch` topology for host oracle paths.
- Exported the records from `hipengine.speculative` and added focused RED/GREEN
  tests in `tests/test_specdec2_contracts.py`.
- Updated the normative S1 punchlist.
