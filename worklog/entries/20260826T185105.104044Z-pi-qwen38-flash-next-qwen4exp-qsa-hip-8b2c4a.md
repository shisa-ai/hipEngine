# Add strict Qwen4Exp QSA control primitives

## Summary

Added strict native QSA control primitives for complete-block FP32 pooling,
post-pool norm/interleaved partial RoPE, per-index-head rectified scoring, and
deterministic eligible-block selection.

## Changes

- Pool consumes explicit physical member indices and logical block starts, so it
  does not assume contiguous append-only cache slots.
- Score applies ReLU to each head dot before summing and scales by sqrt(index dim).
- Selection masks incomplete/future blocks, chooses the requested budget,
  resolves ties to lower logical starts, sorts retained starts, and reports a
  per-query count. This strict scalar selector is a correctness fallback; a
  parallel production selector remains F6 optimization work.
- Registered strict gfx1100 variants with automatic gfx1151 peer aliases.

## Validation

- RED: build/registry test failed because the QSA HIP module did not exist.
- GREEN: `uv run pytest -q tests/test_qwen4_exp_qsa_hip.py` -> `2 passed` on
  Radeon 8060S/gfx1151, including first JIT build.
- Native pool/norm/RoPE and score match the NumPy oracle within 2e-5 at official
  index geometry (4 heads x 128); selection is integer-exact for three query
  boundaries and exact lower-start tie cases.
- New in-tree code follows the frozen QSA CPU oracle; lineage command blocker is
  unchanged and no external kernel body was copied.
