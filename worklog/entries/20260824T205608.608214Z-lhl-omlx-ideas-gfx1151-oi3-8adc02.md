# Evaluate streaming exact NextN prompt priming

## Summary

Retained `OI-3` on the Radeon 8060S/gfx1151 Qwen3.8-27B `Q4_K_M`
path. Target prefill now emits completed pre-output-norm hidden chunks to a
request-owned sink. The sink preserves the llama-compatible shifted timeline
(`token[0] + zero`, then `token[i] + target_hidden[i-1]`), carries one 10,240-byte
BF16 row across target chunks, and enqueues the existing NextN block on the
target stream without scoring discarded prompt predictions.

This is T0: target arithmetic is unchanged, NextN block/cache mutations execute
in the same token/position order, and only non-state-mutating output norm/LM-head
work is removed. The implementation was inspired by oMLX prompt priming at
`/home/lhl/omlx@f244ac0` (`omlx/patches/mlx_lm_mtp/prompt_priming.py`); no donor
code was copied and no Metal geometry was assumed portable.

## Changes

- Added a `TargetHiddenChunkSink` contract to resident GGUF target prefill and
  emitted both layer-outer and chunk-outer hidden spans before their buffers are
  reused. The token-serial fallback emits one-row chunks through the same
  contract.
- Added `_StreamingNextNPromptSink`, with exact request/offset/stream ownership,
  warm-prefix support, cancellation checkpoints, one carried hidden row, and
  fail-closed cleanup.
- Added nonblocking `Qwen35GGUFNextNExecutor.enqueue_prompt_rows()`. It reuses
  `_run_block()` exactly, uploads token/position metadata on the target stream,
  keeps pageable host staging alive through target readback, and skips discarded
  prompt scoring.
- Replaced `_prefill_target_and_draft()`'s `P * hidden` slab and post-prefill
  `run_step()` loop with the streaming sink. The slab capture API remains only
  for diagnostics.
- Added `scripts/gguf_mtp_prompt_priming_bench.py`, RED/fake-runtime coverage,
  the compact retained artifact, and benchmark/doc rollups.
