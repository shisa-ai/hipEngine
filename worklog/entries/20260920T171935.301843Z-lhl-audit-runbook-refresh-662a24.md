# Make the audit README an agent runbook, add refresh and EXACTNESS-REJECT

## Summary

`audit/README.md` explained the model well but was reference material, not
instructions: an agent reading it would know what existed and not what to do
first, next, or how to finish. Rewritten as a runbook, plus three functional
gaps closed that the review exposed.

## Changes

- **`audit/README.md` rewritten** (163 -> ~380 lines) around three explicit
  workflows — Gather, Triage, Fix — with the rule that only one is done per
  session, because they produce different kinds of commit. Added a "Start here",
  an "Extending it" section with working code samples for a new extractor and a
  new check, and per-disposition guidance on when each applies. Corrected the
  opening statistics, which still said 3,333 worklog entries against a current
  10,568.
- **`audit.py refresh`** — one command that rescans the catalogue, re-runs the
  code checks, re-matches decisions onto rows whose text changed, regenerates the
  `docs/` indexes via `scripts/docs/check_docs.py --write`, ratchets the budget
  down, writes a dated report, and ends with a "needs a human" section. Placed at
  the top of the README as the thing to run every time.
- **Budget ratchet.** `save_budget(..., lower_only=True)` never raises a ceiling.
  Without it an automatic refresh would quietly absorb every new piece of debt
  into the budget and the gate would stop meaning anything. Raising the ceiling
  stays a deliberate act.
- **Agent split.** `cleanup-triage` was granted `Bash, Read, Grep, Glob` — no
  write tools — so it could not actually fix anything despite being described as
  doing so. It is now explicitly read-only and decides; a new `cleanup-fix` agent
  carries `Edit, Write` and clears the queue. The split also enforces the
  one-workflow-per-session rule at the tool level.
- **New `EXACTNESS-REJECT` tag.** The `candidate` extractor already emits a
  signal for candidates rejected while citing an exactness bar (30 rows), but
  there was no tag for it, so triage would have collapsed it into generic
  `LOST-OPT`. The distinction matters and has a different remedy: a `LOST-OPT`
  was never promoted for some reason, while an `EXACTNESS-REJECT` was actively
  discarded for failing a bar `docs/OPTIMIZATION.md` 4.1 says cannot stand alone.
  It pairs with `qualify`, and the note must name the production gate the
  candidate should have been measured against.

## Validation

- Every command the README promises was executed and exits 0: `status`, `queue`,
  `open` with `--stale`/`--signal`, `expiring`, `orphans`, `show`, `budget`,
  `report`, `refresh`. An earlier sweep reported four false failures; the harness
  was wrong, not the commands — zsh does not word-split unquoted variables, so
  each command string reached argparse as one argument.
- The "Extending it" code samples were checked against the live API:
  `finding(kind, key, title, location, *, fix, why, evidence=None)` and the seven
  `Row` fields match what the README shows.
- `python3 -m unittest discover -s audit/tests -t audit`: 26 tests pass, up from
  23. Three new ones pin the ratchet: `lower_only` refuses to raise a ceiling,
  still lowers as rows are triaged, and an explicit `budget` call may raise.
- `python3 audit/audit.py check`: exit 0. `python3 scripts/docs/check_all.py`:
  all 4 gates pass.
- Removed two redundant `audit/runs/` directories generated while testing
  `refresh`; they were untracked build artifacts from this session, not audit
  records.

## State of the first audit

Gathering is complete and committed: 2,095 rows (1,623 inventory + 472
findings), 2 triaged, budget recorded across both stores, three dated runs.
Triage and fixing have not started — that is the next session's work, and the
two agents now exist to do it.
