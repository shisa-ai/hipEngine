# Q5T16 true rowtile rows 5-8 primitive parity

## Summary

First kernel unit for concurrency priority 1 (Q5T16 true rowtile rows 5-8).
The `q5_k_t16_dense_rowtile_col4_gemv_kernel` is already templated on
`ROW_TILE` and computes each row independently with the exact direct-producer
K order / wave32 tree / ordered wave-0..3 reduction, so extending it to rows
5-8 is a pure dispatch/validation change — no arithmetic change per row.
Before this unit the Python launcher and the C++ `launch_q5_dense_rowtile_col4`
switch accepted only rows 2-4 and rows 5-8 fell to the padded-WMMA projection
(48 Q5 calls, e.g. 21.31 ms at c5 vs 3.34 ms true rowtile at c4).

## Changes

- `tests/test_gguf_t16_selected_gemv_decode.py`:
  `test_q5_t16_dense_decode_and_rowtile_match_selected_production_bits`
  parametrize widened `[1,2,3,4]` -> `[1,2,3,4,5,6,7,8]` (RED first).
- `hipengine/kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.py`:
  `_check_dense_q5_t16_shape` rowtile gate `(2,3,4)` -> `(2,3,4,5,6,7,8)`.
- `hipengine/kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.hip`:
  `launch_q5_dense_rowtile_col4` guard `rows > 4` -> `rows > 8` and added
  switch cases 5,6,7,8 to `Q5_T16_DENSE_ROWTILE_COL4_CASE`.

## Validation

- RED: widening the parametrize without the launcher change fails on rows
  5,6,7,8 with `ValueError: dense Q5T16 rowtile requires rows in 2..4`.
- GREEN: after the three edits, all 8 rows pass `assert_array_equal` against
  the direct producer (`gguf_q5_k_t16_selected_gemv_bf16_bf16_out`) and
  `assert_allclose` against `gguf_quant_gemv(..., Q5_K)` within `_TOL`.
- Full `-k q5` bundle of `tests/test_gguf_t16_selected_gemv_decode.py`
  passes (34 passed).
- W7900 / gfx1100 present; HIP runtime available.
