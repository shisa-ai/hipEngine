# K0-off points measured; opt_in warmup hang confirmed

## Summary

The Packet 2 K0 clause ("Measure MTP-capable K0 both before and after active
MTP; do not call it unloaded") now has its "before" half measured. The K0-off
pair re-ran post-scratch-cap with the fixed probe (`facc0dc9f`): N=2 request
peaks 21.307 GiB at context 1024 and 21.578 GiB at context 1536, both `ok`
from cold with clean ownership. Pre-cap 1536 (22.574 GiB, /tmp-only) improved
by 0.996 GiB, consistent with the retained-scratch reduction. The MTP-armed
opt_in mode cannot reach readiness, and the failure is now characterized
precisely from its server log:

- `STARTUP_SCRATCH_PROBE: failed at probe_prompt_tokens=1023: engine service
  command timed out` — the MTP warmup path hangs the engine-service child at
  width 2, where the `enabled` mode crashes the same path with the
  `blk.40.attn_q_norm.weight` KeyError. Both non-off serving modes are
  unusable at startup.

Pre-compaction attempts (bg-16..bg-19, commit 667ba49) failed on the probe
prompt-fit off-by-one (fixed in the scratch-row-cap unit) and left successful
pre-cap points uncommitted in /tmp only.

## Operational note

One re-run tripped a 1536 `not_idle`: the preceding opt_in probe had hung for
its full 700 s outer `timeout`, which SIGKILLed the probe without its cleanup
finally and orphaned the server child, poisoning the next run's idle gate.
The card verified clean (28 MiB used) before the re-run. Never wrap probe
points in an outer `timeout` without checking `pgrep hipengine.server`
between points after any kill.
