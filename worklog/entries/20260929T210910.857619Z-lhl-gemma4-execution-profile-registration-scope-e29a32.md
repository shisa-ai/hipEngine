# Scope the gemma4 execution-profile registration build (#43)

## Summary

Rescoped the standing task "register gemma4 in EXECUTION-PROFILES §2.1" from a
document edit into the build it actually is, and pinned its blocker to code
facts rather than to a pending decision. §2.1's registered list is the selector
for which arithmetic an omitted profile gets, so adding a combination there is
an arithmetic promotion, and §2.1 requires each listed combination to be
covered by a decision section with a registered strict fallback. The campaign
already named `scripts/execution_profile_gate.py` as the clearing command; what
was missing is how much must exist before that command can even be invoked.

**The headline code fact:** gemma4 has no profiles module and makes **zero**
`register_runtime_profile_plan` calls. `hipengine/generation/` contains only
`gemma4_gguf.py` for this family, and neither it nor `hipengine/runtime/gemma4.py`
mentions `execution_profile` at all. Only `qwen36_gguf_profiles.py`,
`qwen36_gguf_gfx1100_profiles.py`, `qwen38_gguf_profiles.py`,
`qwen4_exp_profiles.py` and `speculative/paro_mtp_profiles.py` register plans.
gemma4 therefore resolves through the migration path today, which is exactly
what §2.1 says an unregistered combination does -- it loads and runs, just not
on `production` arithmetic by default. Registration is not admission, so
nothing here is blocked on being allowed to execute.

## Validation

Read-only investigation; every claim below is a direct observation.

- **Registration API:** `register_runtime_profile_plan(*, model, backend,
  quant, profile, plan, replace=False)` at `hipengine/execution_profiles.py:345`
  keys a `RuntimeProfileKey(model, backend, quant, profile)` and rejects
  duplicates. Plans are `RuntimeProfilePlan` objects (cold-path profile
  construction). This is the call gemma4 has never made.
- **The gate's inputs** (`scripts/execution_profile_gate.py --help`):
  `--variant-manifest`, `--strict-manifest`, `--strict-capture`,
  `--candidate-capture`, `--expected-controls`, `--strict-expected-controls`,
  `--task-results`, `--arithmetic-class {T0,T1,T2,T3}`, plus optional
  `--repeat-capture`, `--isolation-capture`, `--batch-invariant-capture`,
  `--comparison-controls`, `--thresholds`, `--bf16-logits`. It evaluates
  captures; it does not produce them.
- **Template and its Qwen coupling:** `scripts/execution_profile_gguf_control_smoke.py`
  is 906 lines and does produce everything the gate consumes -- "emits the
  standardized actual-control capture from live resident-session state, builds
  the independent expected-control fixtures from the schedule spec, writes the
  RunCapture manifests + variant manifests + task results, and evaluates
  everything through `execution_profile_gate.py`". Its Qwen3.6-specific surface
  is narrow: `DEFAULT_GDN_MODE = "chain_lds32_direct_nonvolatile"` at `:57`,
  the `from scripts.gguf_gdn_trajectory_gate import _gdn_mode` import at `:174`,
  and the `with _gdn_mode(gdn_mode):` block at `:186`. Its own help scopes it to
  "a small teacher-forced c1 schedule on a Qwen3.6 GGUF model". Core functions:
  `_trajectory_with_controls` `:157`, `_assemble_capture` `:288`,
  `_write_fixture` `:340`, `_full_suite_expected_records` `:362`,
  `_write_full_suite_fixtures` `:384`, `_run_task_artifact` `:433`,
  `main` `:566`.
- **Ingredients that already exist, with sizes:**
  `scripts/gemma4_teacher_forced_gate.py` 483 lines (teacher-forced capture at
  `--prompt 2048 --prefill 1024`, already the campaign's logits gate),
  `scripts/gemma4_real_generate.py` 130 lines (resident session),
  `scripts/qwen36_execution_profile_adapter.py` 145 lines (small, adaptable, but
  its own help warns it "does not invent control telemetry"),
  `scripts/quant_quality/qwen36_teacher.py` 845 lines (the teacher fixture to
  be replaced). Neither gemma4 script emits controls today.
- **Cost and prize, as the campaign states them:** a "bounded multi-session
  build against a working template... larger than any single iteration, and it
  produces no speedup of its own. It converts the existing verified 1393 into
  the default 1393" (2.06x against today's 675).
- **Why it cannot close in one session:** pieces (A) profile-plan registration,
  (B) the control producer, (C) the teacher fixture must all exist before a
  single gate invocation is even possible, and the gate run itself is a GPU
  artifact production pass.
