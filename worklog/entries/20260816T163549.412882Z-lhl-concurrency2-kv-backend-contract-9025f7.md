# Make continuous batching KV-backend agnostic

## Summary

Refined the approved Generation-2 concurrency architecture so replacing BF16
with INT8 or a later multi-plane/composed KV format cannot require another
continuous-batching implementation. The core EngineService, request lifecycle,
fairness, completion, cancellation, and overload design is unchanged; the
scheduler/KV boundary is now a generic resolved `KVCacheBackend` with atomic
resource claims, backend-declared global pool sets, storage views, and common
conformance tests.

The review used read-only `/home/lhl/kvcache-quantization-research` at `31979ce`,
including the hot/cold composition plans, packed HIGGS/AQUA prototypes,
OSCAR mixed BF16/INT2 audit, DMS-to-vLLM analysis, and FastDMS compact manager/
scheduler. The decisive requirement is broader than a `storage_dtype` enum:
HIGGS/TurboQuant own index/scale/codebook planes, AQUA has heterogeneous
cross-layer residual state, OSCAR has BF16 and INT2 regions plus demotion, DMS
changes physical liveness, and KVTC is a cold codec.

## Changes

- Defined `KVBackendSpec` composition keys for retention topology, hot
  codec/layout, cold tier, artifact identity, prefix/transaction capabilities,
  and registered kernel bundles.
- Replaced scalar page/token admission as the C2 target with atomic named
  `ResourceClaimSet`/`ResourceDelta` accounting over backend-declared
  `KVPoolPlan` planes and lifetimes.
- Kept `KVLiveSpans` as the mandatory liveness ABI while adding a registered
  `KVStorageView` for stable payload/scale/zero/codebook/tier plane views.
- Clarified one active backend per loaded model replica initially, exact
  fingerprint compatibility for prefix/graph state, and drain/transcode rather
  than live byte reinterpretation when changing backends.
- Added fake BF16, INT8 multi-plane, mixed-tier, and DMS-like backends to C2-0;
  dense BF16/qualified INT8 same-scheduler gates to C2-3; DMS codec-composition
  closure to C2-7; and optional cold tiering to C2-8.
- Added one common backend-conformance suite covering c1-c32 scheduling,
  per-plane conservation, prefix/transactions, demotion/compaction, concurrent
  abort/retract/slot reuse, graphs, pressure, and final drain.
- Updated `KVCACHE.md` and `PLAN.md` so current INT8 work is the first real
  dense-INT8 backend implementation, not a separate scheduler, and future DMS
  payload replacement follows the same rule. Preserved the independently
  committed `IKV-C1` unit at `c2ca58171`.
