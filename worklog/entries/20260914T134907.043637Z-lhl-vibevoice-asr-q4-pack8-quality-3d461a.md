# Q4 pack8 quality-neutral: 20-clip re-check 1.487% == bf16; matched decode 1.50x; prefill route correction

## Summary

The raw-block pack8 decode path is **quality-neutral and 1.50x faster than dense
bf16 decode** under a matched protocol.

Quality: a 20-clip Q4 lane run with the pack8 path scores **1.487%**, identical
to the bf16 lane on the same 20 clips, with **0/20 per-clip WER differences**,
18/20 transcripts byte-identical and **0 malformed transcripts**.

Speed: both lanes were then measured in **one process, with the same loop, the
same fixture and the same prompt rows** — Q4 **48.1 ms/token** (48.1/49.3/50.8)
vs dense bf16 **72.2 ms/token** (72.2/73.3/74.5), i.e. **1.50x**, at 6.10 GB of
resident weights against 16.66 GB.

## Next

- **Route correction, and it invalidates my own prefill framing.** The prefill
  figure quoted in the previous entry ("3.80 s for 89 rows") came from a loop
  that drives `push_token` + `forward_layers` per row, so it measures the
  **row-by-row** route. Driving the bf16 lane the same way gives 5.87 s for the
  same 89 rows (66 ms/row) — bf16's ~0.30 s for 146 rows is its **batched
  hipBLASLt** route, which that loop never exercises. Comparing Q4's row-by-row
  time against bf16's batched time conflated two different routes. The real
  deficit: Q4 has no batched prefill route at all (~6.3 s for 146 rows) against
  bf16's batched ~0.30 s.
- **Next unit: a batched Q4 prefill route.** This is the dominant remaining
  cost and the largest single lever left. Candidate paths in-tree: the batched
  Q4_K prefill kernels (measured earlier at 164 ms gate / 158 ms down for 146
  rows, ~15 s per request — not viable as-is), the Q4_K/Q6_K WMMA prefill
  families for these shapes, or repacking the prefill weights to fp16 and
  reusing the hipBLASLt route bf16 already uses. The reviewer's prioritization
  holds.
- Stored-hypothesis inconsistency worth remembering: the 50-clip gate artifact
  holds **extracted** transcript content while the Q4 driver now stores **raw**
  model output, because the contract was split mid-workstream. Scoring either
  requires the matching helper (`_wer_pct_content` vs `_wer_pct`); mixing them
  raises. New runs should record the raw text plus the parse status.
