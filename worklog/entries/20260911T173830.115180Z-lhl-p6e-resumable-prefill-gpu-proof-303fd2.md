# P6e GPU proof: resumable INT8 prefill yields; fresh-session KeyError found and fixed

## Summary

P6a made the compact INT8 prefill return control between bounded layer segments,
P6b gave the suspended request its own state so interleaved packed decode cannot
overwrite it, and P6c pinned the checkpoint contract. **Every one of those tests is
a CPU test with a monkeypatched recorder.** Nothing had verified on hardware that a
segment does real GPU work, that a suspended prefill survives a real interleaved
decode, or that the interleaved decode gap stays bounded. That is P6e.

The GPU proof passes all four gates, and it immediately found a production crash
that the CPU tests structurally could not reach.

**The defect.** The resumable segment increments four plan counters
(`output_norm_rows`, `lm_head_sample_rows`, `target_hidden_norm_rows`,
`hidden_seed_norm_rows`) with `+=`, but only the one-shot entry
(`_prefill_batch_native_impl`) ever builds that plan dict. The field's default is
`{}`, so a fresh session's first long prompt raised
`KeyError: 'output_norm_rows'` in the sampling tail. P6c's fixture
(`_resumable_owner`) pre-populated `{"output_norm_rows": 0,
"lm_head_sample_rows": 0}` — exactly the counters production fails to initialize.
The test double supplied the state production was responsible for, which is why 19
CPU tests passed while the first real GPU call crashed. Any fresh session whose
first request is a long prompt would have hit this.

**Why this is the point of P6e.** A monkeypatched executor cannot reach the
sampling tail, so no amount of CPU testing would have found this. The unit's value
is not only the passing gates but the class of bug that only hardware exposes.

## Changes

- `scripts/gguf_resumable_prefill_gpu_proof.py` (new). One resident INT8-direct
  batch, three sessions (one-shot target, resumable target, interleaved decoder).
  Reads the real bulk-prefill row capacity rather than assuming one. Arm A runs
  the one-shot packed entry; Arm B runs
  `prefill_batch_native_layer_outer_resumable` in bounded layer segments with a
  decode step on the third session between every pair. `evaluate_gates` is split
  out as a pure function so the gates can be driven through their failure paths.
  Exits non-zero when a gate fails.
- `hipengine/runtime/qwen35_gguf_runner.py`. The resumable setup seeds the four
  counters via `setdefault` before the layer loop.
- `tests/test_gguf_resumable_prefill_gpu_proof.py` (new, 16 tests). Drives each
  gate's failure path with synthetic measurements, pins the dataclass default, and
  asserts the P6c fixture no longer pre-populates the plan.
- `tests/test_gguf_resumable_layer_outer_prefill.py`. `_resumable_owner` now uses
  `last_packed_prefill_plan={}` (the real default) instead of pre-seeding two
  counters, so those 19 tests actually cover the initialization.
- `benchmarks/results/2026-09-11-w7900-p6e-resumable-prefill-gpu-proof.json`,
  `benchmarks/CHANGELOG.md`, `benchmarks/HARNESSES.md`.

## Validation

RED then GREEN, on the exact traceback line the GPU run produced:

- **RED**: changing the fixture to the real default failed 6 tests with
  `KeyError: 'output_norm_rows'` at `qwen35_gguf_runner.py:23388` — the same line
  and the same error as the GPU run, now reproducible on CPU in seconds.
- **GREEN**: seeding the counters in the resumable setup passes all 19.

GPU proof on the declared hardware (W7900 / gfx1100), cache-only
(`HIPENGINE_REQUIRE_CACHED_BUILD=1` plus a pinned compiler-version file), 3,072
prompt rows against a real row capacity of 1,024 (3 planned rounds), layer budget
4, 24 decode tokens:

| Gate | Result |
| --- | --- |
| Exact continuation | PASS — Arm A and Arm B both sample token 265 |
| Real yield | PASS — 16 segments, minimum 258.6 ms (floor 1.0 ms) |
| Bounded decode gap | PASS — interleaved p95 33.673 / max 33.691 ms vs standalone p95 33.595 / max 39.102 ms |
| Cleanup | PASS — peak suspended 211.5 MB, released before the checkpoint returns |

Walls: Arm A 4.165 s, Arm B 4.768 s. Sixteen segments at ~258-300 ms account for
the whole one-shot wall, so segmentation is not adding meaningful overhead and the
yield is genuinely interleaved, not a re-run.

Honest limits:

- The decode gap is at parity because the interleaved decoder runs *between*
  segments, not during one. The proof bounds the gap at segment boundaries; it does
  not measure preemption inside a segment, which is not what P6 implements.
- `performance_claim` is false and no scoreboard row changed: this is a
  control-and-liveness proof, not a throughput result.
- The service-level half of P6e remains open: `gguf_live_server_bench.py` has no
  cancel path, so "cancel during real prefill; refill and verify survivors" with
  declared p95/p99 acknowledgement limits still needs harness work. This unit
  proves the mechanism that the service proof depends on.
- Only one layer budget (4) and one prompt shape were run; the gates are declared
  constants, not swept.
