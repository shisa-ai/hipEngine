# Harden gfx1151 WMMA dispatch contracts

## Summary

Review of D08-X2-K5 found two fail-closed/plugin-contract gaps. The dense-BF16
BK32 kernel was selected using only N alignment, while its final K iteration
unconditionally loaded all 32 elements; a non-multiple K could read past both
activation and weight allocations. The resident-pack8 bulk pair fallback
checked a four-axis key but directly invoked a gfx1151-named Python wrapper,
ignoring the function registered behind that key.

## Changes

- Dense WMMA dispatch now requires positive `in_features` divisible by 32.
- The public Python launch wrapper rejects unaligned K before library/runtime
  access, and the HIP C export independently rejects `in_features % BK != 0`.
- The pack8 bulk-pair capability fallback now constructs one backend-resolved
  `KernelKey`, resolves its function through the registry, uses its quant/
  variant library key, and invokes that registered function for both outputs.
- Removed the gfx1151-specific pack8 prefill wrapper import from generic runtime
  code.
- Added RED/GREEN dispatch, wrapper, and registry-replacement tests.

## Validation

- RED: unaligned K selected the WMMA leaf; the wrapper reached library lookup;
  the pair route called the direct wrapper instead of the registered fake.
- GREEN focused nodes: 3 passed.
- `uv run pytest -q tests/test_gguf_linear_dispatch.py` — 97 passed.
- `uv run pytest -q tests/test_dense_prefill_wmma.py` — 5 passed, including
  four ROCm kernel/reference shapes after the HIP source guard changed.
- Isolated `tests/test_gfx1151_backend.py` reached one pre-existing registry
  order dependency: the Q5T16 WMMA alias was absent when its test ran alone.
  The same file passed in the preceding 127-test GDN/backend bundle before this
  unit, and this unit does not edit Q5T16 registration; no broad rerun was made.
