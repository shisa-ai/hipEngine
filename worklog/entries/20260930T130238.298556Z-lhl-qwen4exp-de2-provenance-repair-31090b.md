## The process mistake, recorded so it is not repeated

The repair commit that touched the earlier entry ran as:

```bash
git add <paths> && python3 scripts/worklog.py check 2>&1 | tail -1 && git commit ...
```

`worklog.py check` exited non-zero with *"tracked worklog content is immutable"*,
but the pipeline's status is `tail`'s, which is 0, so `&&` proceeded and the
commit landed. **Do not pipe a validator whose exit code gates a commit.** Check
the validator's status directly, or use `set -o pipefail`. This is the second
time in this session that a masked exit code produced a state the validator had
already rejected.
