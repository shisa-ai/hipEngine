# Repair the MTP verify-journal route contract: serial rows at the gfx1100 native context limit

## Summary

Native GGUF MTP crashed on gfx1100 for any request whose decode crossed
target position 95: `RuntimeError: initial-state-only journal cannot
capture serial rows` (`hipengine/runtime/qwen35_gguf_mtp.py:733`). The
10-prompt natural25 suite completed 9/10 and died on the tenth prompt,
exactly as recorded in `0afb8968b` on 2026-09-07.

Root cause is a contract mismatch, not a benchmark artifact.
`_StateJournal` is allocated once per `Qwen35GGUFTransactionalVerifier`,
but its mode was decided by `_initial_state_only_journal_applies`, which
passed only `rows=max_candidate_budget+1` to
`_effective_target_verify_mode` and therefore never saw the
backend/`end_position` clause. At verify time `prepare()` computes the
route with `backend` and `end_position=initial_position+batch.rows`, so
past the gfx1100 native target context limit
(`GGUF_SPECDEC2_NATIVE_TARGET_MAX_CONTEXT = 95` in
`hipengine/kernels/hip_gfx1100/__init__.py:686`; gfx1151 declares 65544)
the route becomes `serial_exact` and calls `capture_row`, which the
initial-state-only journal refuses by design.

Quantitatively confirmed on the suite's own prompts (plain
`Qwen3.8-27B-Q4_K_M`, chat template, reasoning off): prompts 0-8 encode
to 39-64 tokens, the tenth (`mixed_ja_en_review`) to 71. With 25 visible
outputs the tenth reaches position 96, so only it crosses the limit. The
AR arm of every prompt passes because AR never enters the verifier.

## Changes

- `hipengine/runtime/qwen35_gguf_mtp.py`
  - `_initial_state_only_journal_applies` now requires `backend` and
    `max_end_position` and evaluates the same predicate the runtime route
    uses. An unbounded position range returns `False`: a serial fallback
    can appear at any later position.
  - `_journal_position_bound` returns
    `scratch.max_positions + max_candidate_budget + 1`, the largest
    `end_position` the resident session can reach (the resident scratch
    fixes `max_positions` at construction; no runtime growth path exists).
  - `_verify_journal_plan` returns
    `(initial_state_only, producer_capture_initial_state)` and pairs
    producer capture with the initial-state-only journal only. Producer
    capture borrows a **one-row** rollback buffer
    (`_acquire_verify_initial_state_capture`: "Borrow one-row rollback
    buffers only for an exact producer plan"), so keeping it alongside a
    row-capable journal would have written past that buffer at
    `_capture_state_index(row+1)` - a silent out-of-bounds device write
    rather than the previous clean refusal. A row-capable journal now owns
    its own `max_rows + 1` snapshots.
  - `_require_serial_capable_journal` fails closed in `prepare()` after the
    effective mode is known and **before** `capture_initial`, so a future
    contract drift surfaces before any state mutation instead of mid-loop.
  - `_capture_state_index`/`_restore_state_index` validate the index
    against `state_row_capacity` (1 for initial-state-only, `max_rows + 1`
    otherwise), converting any future mis-sized snapshot buffer from
    device-memory corruption into a clear error.
- `tests/test_qwen35_gguf_mtp_session.py`: the existing predicate
  assertions move to the bounded signature; new tests cover the reachable
  position range (gfx1100 at 96 vs 95, unbounded ranges), the
  fail-closed route guard, the producer-capture pairing, and the
  `state_row_capacity` mapping.
- `docs/REFACTOR.md`: the +606 MiB gfx1100 journal cost and the two
  memory-recovery designs that would keep the contract sound.

(`AttributeError: _require_serial_capable_journal`, and the predicate
admitting gfx1100 at `max_end_position=96`), then passed.
