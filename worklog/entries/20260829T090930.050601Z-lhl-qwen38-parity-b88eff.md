# Parity P2.3: single-wave owner is latency-bound, not ALU-bound

## Summary

Hardware-counter attribution of the retained 32-thread single-wave Q4T16
owner at the dominant parity shape (rows=45, in=5120, out=17408), 12-launch
isolated loop under `rocprofv3 --pmc` (gfx1151, TheRock):

- `SQ_INSTS_VALU` = **47.33M instructions per launch**; at 887.8 us average
  duration that is ~53 G wave-instr/s vs ~464 G/s issue peak (40 CU x 4 SIMD
  x 2.9 GHz) = **11.5% of issue peak** -> NOT VALU-issue-bound. This
  falsifies the "scalar dequant ALU ceiling" reading of iteration 7.
- **VGPR_Count = 248 per thread**; the whole launch is only 363 waves
  (grid 363 x 32 threads) over 160 wave-issue slots -> ~2.3 waves/slot,
  residency-capped by the 248-VGPR footprint (acc[3][4] float8 alone is ~96
  VGPRs). With so few resident waves, global-load latency cannot be hidden:
  the kernel is **latency-bound at ~56-58 GB/s effective** (51.6 MB weight
  stream / 891 us).
- This reconciles iteration 7: tripling block count (16-col variant) with
  the same per-thread VGPR pressure adds queued waves, not resident waves,
  hence flat-to-worse performance.
- Note: SQ_WAVES counter read 0 (broken counter on this stack); grid/VGPR
  and instruction numbers are reliable.

## Levers this implies (ranked)

1. Cut per-thread VGPR footprint (fewer accumulator tiles per block, e.g.
   OUT_TILES=1 AND ROW_TILES=2, or spill-free restructuring) so more waves
   fit per SIMD; combined with more blocks this finally adds resident waves.
2. Intra-wave latency hiding: LDS double-buffer prefetch of the next K256
   block while WMMA consumes the current one (single-wave shape; unlike
   shared_b, no padded row waves).
3. Split-K across blocks with a deterministic fixed-order reduction -
   changes accumulation order (not bit-exact) -> requires the
   production-profile reassociation gates (docs/EXECUTION-PROFILES.md),
   i.e. the full T1/T2 campaign path.
