# MX-1 is refuted — the full F16 route fails worse than its own gate/up half, so the repair is not removable by operand class

## Summary

`MX-1` is the ledger's largest remaining lever: the routed-expert repair is
**1,219.978 ms = 7.75%** of the 15,741.963 ms prefill union, and the row's route is "F16
routed experts with **no repair**" — Q4_K/Q5_1/Q8_0 decoded to F16, F16 WMMA, F32
accumulate, gate/up paired, **down writes F16**.

Reconnaissance found **both halves already ship** as F16 WMMA selected-MoE prefill
kernels, so the row's prescribed build was unnecessary, and the two runs below measured
the route instead of writing it.

**Result: the full route fails, and fails worse than its own gate/up half.**

| metric | **full MX-1 route** | gate/up-only F16 | plain iu8 | limit |
| --- | ---: | ---: | ---: | ---: |
| mean KL | **7.288e-4** | 4.584e-4 | 5.278e-4 | 1e-3 |
| p95 | **3.4452e-3** | 2.5307e-3 | 2.8062e-3 | 5e-3 |
| p99 | **1.1172e-2** | 5.1165e-3 | 5.2674e-3 | 2e-2 |
| max | **1.8181e-2** | 6.3267e-3 | 2.4688e-2 | 5e-2 |
| top-1 | **0.99333** (447/450) | 0.99778 (449) | 0.99556 (448) | 0.99 |
| **failing scopes** | **4** | 2 | 2 | — |

Failing scopes: `general_ja`, `mixed_ja_en`, `prefill_last`, `prefill_to_c1` — the
gate/up-only variant failed only the last two. On the binding `prefill_last` scope
(18 rows) the full route runs at **mean 1.848e-3 (1.85x over)** and **p95 7.716e-3
(1.54x over)**, against the gate/up-only variant's 1.13x and 1.013x.

## What this establishes

**Adding the F16 down roughly doubles the drift** — mean 4.584e-4 → 7.288e-4, p99
5.1165e-3 → 1.1172e-2, top-1 449 → 447 matches, failing scopes 2 → 4. The F16 down
contributes error on the same order as the F16 gate/up, and the two compound.

**MX-1 is therefore refuted**, on three independent grounds:

1. The full route fails the calibrated envelope.
2. It fails **worse than its own gate/up half**, so the down half cannot rescue it.
3. It fails against a bar **production meets exactly** — the iu8-risk route carries the
   repair precisely so its arithmetic is bit-identical to the strict parent, i.e. zero
   deviation from the strict teacher by construction.

Together with the earlier `repair_free_gate_up` result (plain iu8, no repair: 2.16x over
on `prefill_last` mean), **two distinct operand classes have now been measured and both
fail** — and F16 is the tighter of the two, which is what makes the closure decisive
rather than merely negative. **The repair is load-bearing on the prefill path and the
1,219.978 ms is not recoverable by operand class.**

## Configuration and engagement

Three flags, because the down dispatch tests `exact_grouped_down` **before** `q5_wmma`:

```
4559  if down == gguf_q5_1
4571    if q5_mmq:
4603    elif exact_grouped_down:   ← production chain (exact row_publish + repair)
4751    elif q5_wmma:              ← F16 down owner
```

`EXACT_GROUPED_Q4=0` + `EXACT_GROUPED_DOWN=0` + `Q5_1_WMMA=1`.

Engagement verified **before** the run: **47 F16 gate/up + 43 F16 down calls, zero
repair calls on either half.** The counts are not 48 each because layer 2's gate/up is
Q5_K and 5 down layers are Q8_0 — matching the ledger's census (94 Q4_K / 43 Q5_1 /
2 Q5_K / 5 Q8_0 = 144). This mattered: the first attempt at the down leg silently did
not engage, because `exact_grouped_down` (default 1) wins the chain — a second flag
would have been missed without the probe.
