# A4 8580-image-token prefill verified from the prompt the generator builds

## Summary

The 8580-image-token figure for the A4 page was a grid calculation: 220x156
patches, 2x2 merge. It is now verified against the prompt the model is actually
fed, which is the form the page-scale memory plan needs it in.

`render_chat_prompt` — the same call `SuryaOCRGeneratorGPU._generate_ocr`
makes, with the same `n_image_tokens` derived from `preprocess_image_surya` —
returns **8701** `input_ids` for `page_a4.png`: 121 text tokens and 8580 image
pads. The image pads are contiguous (one vision span), there are no other image
flags, and `len(input_ids) == len(mm_token_type_ids)`. That list is the
`input_ids` the prefill receives, so the prefill length is 8701 with 8580
vision slots, not 8580 tokens of text plus an unknown image span.

The serving path independently agrees: the HTTP response for this page reports
`usage.prompt_tokens` 8701, and the generator computes that as
`len(input_ids)` rather than by tokenizing text (see the HTTP serving entry).

This closes the last inference in the A4 evidence set. The remaining items —
fixture, ground truth, GPU end-to-end run, EOS, scoring, artifact, rollup — were
already demonstrated in `20260912T104315.968324Z-lhl-surya-a4-ground-truth-1c1fe9`.
