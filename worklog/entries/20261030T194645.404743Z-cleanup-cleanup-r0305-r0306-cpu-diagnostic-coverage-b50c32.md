# R0305 R0306 CPU diagnostic coverage

## Summary

Added CPU diagnostic coverage for R0305 and R0306 without changing runtime behavior or claiming ledger closure. The new tests pin the native F32 residual/token-embedding refusal, the populated BF16-mirror plus F32-seed verifier input path, and the host draft trace across repeated proposals on one runner with different dense-cache offsets and proposal depths. The draft test does not exercise target commit or reset; those lifecycle calls remain live validation.

## Changes

- `tests/test_unit_gguf_mtp_native_state_attribution.py`: added a direct `NATIVE_REFUSED_ENV_PAIR` refusal test through `_env_contract()`, plus a positive control with only one member enabled.
- `tests/test_unit_qwen35_gguf_verify_f32_token_embedding.py`: added a populated `verify_target_block()` contract using host stubs. It asserts the BF16 `launch_gguf_embedding` mirror runs first, the requested F32 rows are uploaded to `_verify_hidden_f32_a` through the real seed helper, and that buffer becomes the actual linear-attention layer `hidden_f32_ptr` before output normalization.
- `tests/test_unit_mtp_resident_draft_device_commit.py`: renamed the draft test to `test_host_draft_trace_metadata_and_values_across_repeated_proposals` and reused one runner across three proposals. It covers dense-cache offsets 0, 2, and 4 with proposal widths 2, 2, and 1, verifies summaries are replaced rather than accumulated, and compares independently computed summaries (hash, mean, rms, min/max, first/last rows) plus `depth`, `token_id`, and `position` metadata. The dense-cache offset and proposal width are explicitly not accepted-commit counts.

This file has no narrow realistic fixture for those target/verifier lifecycle calls, and adding a fake scheduler/verifier transaction would not make commit or reset real. No reset method was invented.
