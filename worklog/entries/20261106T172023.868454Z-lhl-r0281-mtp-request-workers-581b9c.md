# Reuse compatibility MTP workers for one request

## Summary

Compatibility MTP draft and chunk-verifier work now share one bounded request pool. This changes worker lifetime only; it does not claim a performance improvement or change the resident MTP2 scheduler.

## Changes

- `_run_mtp_serving_slots` owns a pool sized to its initial slots and lends it to draft/verifier phases through the slots. Shrinking groups reuse it. The context drains/shuts down before the outer request releases streams or sessions.
- Direct one-cycle callers without a request pool retain their existing bounded per-call pool.
- Existing ordered future retrieval, successful sibling snapshot cleanup and first-error propagation remain unchanged.
- Tests cover success/failure shutdown, shrinking groups, pool reuse and sibling cleanup with a request-owned pool.
