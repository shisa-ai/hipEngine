# repair T16 row sweep counterbalancing

## Summary

Task #25 found that `scripts/gguf_t16_prefill_row_sweep.py` did not implement the protocol its docstring and retained artifacts claimed: it ran each arm twice back-to-back in one fixed arm order, selected the faster pass, and stored correctness output in mutable shared-buffer state. This checkpoint repairs the measurement harness before any replacement timing is collected. It does not change a production kernel or dispatch route.

## Changes

- Added an explicit counterbalanced schedule. Every pair runs all arms forward and reverse; repeated pairs reverse the pair order too (`F/R`, then `R/F`) to avoid coupling drift to the same first direction.
- Replaced best-of-two with the median of all counterbalanced pass medians. Each result records pass index, pair, direction, arm position, direction-specific ratios, and whether the candidate is non-regressive in both directions.
- `_timed` now returns an owned output snapshot captured outside the timing window. Per-pass candidate snapshots are compared with the same-pass shared-B snapshot and checked finite per arm, so a later arm cannot overwrite correctness provenance.
- Added `--order-pairs` and an optional `--arms` subset (which must contain shared-B) so the repaired row-edge experiment can run only the relevant reference/candidate leaves.
- Added CPU-only RED/GREEN tests for the exact schedule and immutable output capture.

## Validation

- RED: `.venv/bin/python -m pytest -q tests/test_gguf_t16_prefill_row_sweep.py` failed 2/2 because `_counterbalanced_schedule` did not exist and `_timed` returned only mutable-state timing metadata.
- GREEN: the same command passes 2/2 after the repair.
- `.venv/bin/python -m py_compile scripts/gguf_t16_prefill_row_sweep.py` and `git diff --check` pass.
