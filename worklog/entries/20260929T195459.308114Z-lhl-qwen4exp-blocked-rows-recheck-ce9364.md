# DE-4 refuted by X-5; MT-3 and MT-4 re-checked and still blocked, now for precise reasons

## Summary

Three rows re-checked against work completed earlier in this session. One premise is refuted;
two blockers are unchanged but now stated precisely enough to act on.

## DE-4 - premise refuted by X-5

The row is a single line: *"Scratch throttle - see `X-5`"*, noting *"A 3.3x per-dispatch
penalty would dominate a GEMV"*.

X-5's audit is complete and found the precondition **absent tree-wide**: **2,245 kernels across
all 101 `.hip` sources, zero with a non-zero `private_segment_fixed_size`**. The halo-box 3.3x
throttle needed a kernel allocating a private segment, and none in this tree does - so **there
is nothing to disassemble, nothing to A/B, and no candidate**. The row inherits that closure.

`X-5`'s named trigger is also not ours: `flash_attn_ext_f16` is a **llama.cpp** kernel name and
does not appear in this tree.

## MT-4 - still blocked, and the reason is now precise

The row says *"Re-open after `MT-1` changes the economics"*. MT-1 has since found its body
pass - but **MT-1 explicitly records that its result is NOT an end-to-end verifier speedup**:
it is the kernel pair only, it *"does NOT cover DE-1"*, and part of the 1.85x is launch-count
reduction rather than throughput.

So the economics have **not** changed. MT-4's own reason for closing was that deleting the full
head entirely still left serial MTP at 0.964x AR, and an uncomposed sub-linear body pass does
not alter that.

## MT-3 - still blocked, on MT-2

The row waits on `MT-1`/`MT-2`. MT-1's pass is found but its remaining unit - composing it into
a verifier body pass and measuring the complete pass - is undone, and **`MT-2` is still open**.
The row needs both.
