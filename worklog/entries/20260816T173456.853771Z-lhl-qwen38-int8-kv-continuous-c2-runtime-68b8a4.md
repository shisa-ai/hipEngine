# Wire fail-closed Qwen3.8 row-batched INT8 decode

## Summary

Adds the dormant runtime/manifest wiring needed to exercise the registered
IKV-C2 row-batched INT8 attention leaf without changing the qualified
production route. The exact `7b2aec...` gfx1100 artifact still declares
`max_direct_rows=1`, so logical c2/c4 remains on the committed serial-c1
fallback. A diagnostic capability copy can raise the width to exercise the new
route before promotion.

The route executes correctly under the expected registry key and reports no
host model-row loop, but the first varied page-boundary c4 model gate is not
exact: one of 20 token decisions differs and max KL is `0.10433994`. A focused
one-step rerun localizes byte divergence to layer 0 for every row, before the
new row-batched full-attention consumer can be isolated as the owner. IKV-C2 is
therefore not promoted or marked complete.

## Changes

- Extended artifact evidence with an optional registered decode-batch variant;
  the qualified artifact resolves the exact four-axis kernel key while retaining
  physical width one.
- Added per-session `packed_decode_max_rows` and a fail-closed resolver so
  unknown artifacts, missing variants, unsupported widths, mixed kernels, and
  c1 all preserve the existing fallback.
- Routed qualified c>N full-attention decode through separate append-position
  and post-append context-count `KVLiveSpans`, direct INT8 payload/scale planes,
  row-sized split-K workspace, and the registered batch producer/reducer.
- Added truthful `kv_live_spans_int8_batch` execution-manifest support and made
  generation consume the generic per-session packed-width capability rather
  than a quant-specific scheduler branch.
- Added a GPU1-only pre-promotion harness for varied c2/c4 prompts, logits,
  token trajectories, layer-output localization, state/KV/scale hashes, and
  route ownership. The explicit `--diagnostic-direct-rows` override never
  mutates committed capability evidence.
