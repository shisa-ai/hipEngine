# Fix YuE2 long-song NAR attention corruption

## Summary

YuE2 songs longer than approximately 82 seconds were corrupted by the NAR query tiling path. The attention ABI conflated query rows with the total NAR key rows, so tiles after the first attended to an incomplete key set. The VAE decode path was separately audited: it rejects non-finite latents, preserves unclipped FP32 output like the reference, and its tiled/full decode regression remains passing. PCM export clipping is limited to the signed 16-bit WAV serialization boundary.

## Changes

- Added an optional `nar_rows` key-count argument to the scalar and WMMA NAR attention wrappers and HIP kernels. Existing direct callers default it to `rows`; tiled NAR execution passes the full chunk row count.
- Added a GPU regression for a short query tile attending over a larger bidirectional NAR key set.
- Preserved tiled query scratch allocation and the existing scalar fallback.

## Validation

- `python -m pytest -q tests/test_unit_yue2_nar_kernels.py` — 23 collected, passed (ROCm available).
- `python -m pytest -q tests/test_unit_yue2_nar.py tests/test_unit_yue2_product.py tests/test_unit_yue2_vae.py` — 39 passed.
- End-to-end YuE2 rap re-solve through the production generator with default `_TILE_ROWS=2048` completed successfully; fixed output remained finite and matched the previously validated single-tile repair behavior.
- The independent upstream comparison localized the prior defect: NAR velocity rel-L2 at 3452 frames fell from 0.499 with the old tiled key count to 0.025 with one full key set; full-song latent rel-L2 against the reference was 0.039 with the repair versus 0.80 before it.
