# R0404 gate false-pass: three-defect root cause fixed, direct INT8 engages

## Summary

The R0404 clearing gate (`scripts/execution_profile_gguf_int8_direct_prefill_gate.py`)
was **false-passing**: both arms ran BF16, so the strict-vs-candidate comparison was a
trivial bit-identity that said nothing about the direct INT8 prefill leaf. Three stacked
gate-side defects caused it; all are now fixed and the direct route genuinely engages.
No production runtime code changed — every fix is in the gate harness.

1. **Env timing** (fixed earlier, `febeba7da`): `PURE_INT8_ENV` was applied only inside the
   per-arm route blocks, after the resident session was constructed. The session fixes
   `kv_storage_dtype` and the BF16 mirror layer set at construction, so it built the default
   8-layer BF16 mirror. Fix: construct the session inside the pure-INT8 env.
2. **`kv_capability=None`**: the session admits mirror-free INT8 only when
   `kv_capability.runtime_action == "admit"`; the gate passed `None`, so admission failed
   closed to BF16 even with the INT8 policy. Fix: resolve the capability exactly as the
   shipping generator (`generation/qwen35_gguf.py::_resolve_int8_kv_capability`) — artifact
   identity + execution fingerprint, backend/target arch, weight quant, KV contract — then
   call the model plugin's resolver (plugin chosen from the GGUF architecture so dense and
   MoE each use their own declarations). Pass it to the session; abort loudly if not admitted
   or if the session backend diverges from the capability backend.
3. **Cached lifetime plan**: `_release_bulk_prefill_workspace` frees the workspace buffers but
   keeps `_int8_prefill_lifetime_plan`, built lazily from the FIRST (strict, `DIRECT=0`) arm's
   env. The candidate arm (`DIRECT=1`) reused the oracle-bridge plan, so
   `_full_attention_prefill_scratch_for_layer` never selected `chunk_outer_direct_int8`, the
   bulk views carried BF16 spans, and the direct branch
   (`qwen35_gguf_full_attention_bulk.py:311`) never fired. Fix: `_rearm_bulk_workspace` resets
   `session._int8_prefill_lifetime_plan = None` so each arm re-plans under its own
   `HIPENGINE_GGUF_INT8_PREFILL_DIRECT` value.

## Changes

- `scripts/execution_profile_gguf_int8_direct_prefill_gate.py`:
  - `_capture`: resolve INT8 KV capability (identity, fingerprint, backend/arch, quant, KV
    contract) via the architecture-resolved model plugin; pass `kv_capability` to the
    session; raise `GateError` on non-admit or backend mismatch.
  - `_rearm_bulk_workspace`: reset the cached `_int8_prefill_lifetime_plan` after release so
    the next arm re-plans its env.
