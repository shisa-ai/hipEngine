# U6 UD MTP certification unit: draft operation set, residency ownership, six gated items

## Summary

U6 is now a defined certification unit rather than a withheld flag. The six
required elements are written as `Qwen35GGUFUDMTPCertificationItem` records
(`_UD_MTP_CERTIFICATIONS` in `hipengine/loading/qwen35_gguf_admission.py`), each
carrying a contract, in-tree evidence, a `qualified` flag, and — when open — a
concrete `blocker`. `_UD_MTP_PRESET_FINGERPRINTS` is **derived** from that table
and admits only a complete unit, so MTP scope can no longer be hand-granted and
an incomplete unit cannot leak admission. Both UD records exist and are
incomplete, so the pin stays empty.

Two previously unenforced elements are now real contracts:

- **blk.64 draft operation set.** `QWEN35_GGUF_OP_MTP_NEXTN_DRAFT` was declared
  with role classes but excluded from `checked_ops`, so draft slots were
  enumerated and planner-validated but never coverage-checked. It is now
  **slot-scoped**: every `nextn_block.*` slot must resolve a record in the new
  `_draft_coverage()` (raw `Q6_K`/`Q8_0` projections through the shared
  `launch_gguf_linear` dispatch; the registered F32-weight RMSNorm wrapper for
  the draft norms), while the AR slot scope is unchanged. The plain control's
  `Q4_K` pack8 draft is refused instead of silently certified.
- **Draft residency and `eh_proj`/head ownership.** The draft fallback slots
  were enumerated as `nextn_block.N.fallback:<slot>`, which resolved no role
  class and planned a different layout than the materializer (which uses
  `root.<slot>`). They are now dropped as duplicates of the already-enumerated
  `root.*` residents, and replaced by an explicit borrow-identity check: each
  `nextn_map.fallback_tensors[slot]` must name a resident this artifact already
  plans with the identical source tensor, else the preflight refuses with stage
  `fallback_unowned`. Measured on both pinned artifacts: `token_embedding` and
  `lm_head` fall back to the target root residents; the draft's `output_norm`
  falls back to its own `shared_head_norm` (declared self-alias, no second
  copy); `eh_proj` is draft-owned.

## Changes

- `hipengine/loading/qwen35_gguf_admission.py`
  - `Qwen35GGUFUDMTPCertificationItem` / `Qwen35GGUFUDMTPCertification` and
    `_UD_MTP_CERTIFICATIONS` for both pinned UD fingerprints; `_UD_MTP_PRESET_FINGERPRINTS`
    derived via `is_complete()`.
  - `_draft_coverage()`: the certified blk.64 draft operation set, appended to
    `CERTIFIED_OPERATION_COVERAGE`.
  - Slot-scoped `slot_scope_ops` in the per-slot planning loop; draft records
    are required only for `nextn_block.*`.
  - NextN fallback borrow-identity check (`fallback_unowned` refusal) replacing
    the duplicate fallback slot enumeration. The refused slot is added to
    `required_plan_slots` as required-but-unrecorded, so the refusal makes
    `plan_contract.is_complete()` false instead of only marking `unsupported`.
  - `_OPERATION_ROLE_CLASSES[QWEN35_GGUF_OP_MTP_NEXTN_DRAFT]` reduced to the
    transformer-block role classes; `token_embedding`/`lm_head` are borrowed and
    certified under the AR root scope.
- `hipengine/loading/qwen35_gguf_consumer_surface.py`: `OPERATION_ROW_LIMITS`
  gains `mtp_nextn_draft: (1, 8)`.
- `tests/test_ud_mtp_certification.py`: six-item record integrity, residency and
  borrow identity, `fallback_unowned` refusal, slot-scoped draft certification,
  foreign-signature refusal, UD journal row-capability, plus the pin-derivation
  test converted from `monkeypatch.setitem` to `setattr` (the pin is a
  `MappingProxyType` now).
- `tests/test_gguf_ud_admission.py`: the coverage-convention test admits the
  draft operation.
- `scripts/ud_mtp_certification.py`: the emitted report now carries
  `certification_unit` (declared envelope, `pin_granted`, `blocked_items`, and
  each open item's `blocker`) so a candidate run states what still blocks the
  derived pin.
- `docs/UD-QUANTS.md`, `docs/REFACTOR.md`: U6 section and withheld-pin ledger
  updated to the derived-pin mechanism.
