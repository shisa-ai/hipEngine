# UD-U1 repair regression F2: type-aware raw moe_experts coverage index

## Summary

Second review round of the UD-U1 repairs (commit `1016e8744` baseline): only
F6 was accepted; the review found that the F2 repair itself introduced a
functionality regression. The repair-2 IQ3_XXS records (commit `cd73d1cef`)
reused the earlier raw records' `(operation, role_class, resident_layout)`
coverage-index key and `_COVERAGE_INDEX` was last-write-wins, so the IQ3_XXS
record silently displaced Q3_K/Q4_K/Q5_K/Q6_K/IQ2_XS/IQ4_XS raw rank-3
experts. A rank-3 Q4_K MoE map with `decode_repack=False` (the materializer
keeps those experts raw) was refused `consumer_unqualified`
("no certified consumer for role_class='moe_experts' source=Q4_K
layout='raw_gguf'"), and mixed-IQ expert maps broke the same way. This unit
restores the regression without pretending different formats share one kernel
quant key: the index is keyed per concrete GGML source type and each format
keeps its own consumer record.

## Changes

- `hipengine/loading/qwen35_gguf_admission.py`:
  - `_build_coverage_index(records)` builds the index over
    `(operation, role_class, resident_layout, source_ggml_type)` and raises
    `ValueError` when two DIFFERENT records claim the same source type for
    the same (operation, role_class, layout) — the old silent
    last-write-wins displacement becomes an import-time invariant failure.
  - `_COVERAGE_INDEX` is built through it (4-tuple keys);
    `_coverage_for(operation, role_class, layout, source_type)` looks up per
    concrete source type; the preflight passes `tensor.ggml_type_name` and
    the redundant `not in record.source_ggml_types` check is subsumed.
  - `qualified_records` is deduplicated per record content
    (`dict.fromkeys(qualified.values())`) so multiple slots/types sharing one
    record still report it once.
- `tests/test_gguf_ud_admission.py` (RED first):
  - Parameterized `test_rank3_raw_expert_coverage_is_type_aware_per_format`
    over all seven already-supported raw expert types (Q3_K, Q4_K, Q5_K,
    Q6_K, IQ2_XS, IQ4_XS, IQ3_XXS): each stays supported on the raw layout
    with `decode_repack=False`, and each keeps its own concrete consumer
    metadata (IQ3_XXS → gguf_iq3_xxs selected consumers; the others → the
    gguf_q*_k raw selected-expert family; moe_selected, bf16 in/out, both row
    scopes).
  - `test_mixed_expert_type_map_keeps_every_formats_consumer`: mixed
    IQ2_XS/Q4_K/IQ4_XS expert slots are each covered by their own record.
  - `test_iq3_xxs_moe_contract_stays_raw_only_and_repacked_contracts_unchanged`:
    per-format layout requirements — IQ3_XXS is claimed only on raw (no T16/X8
    repack exists) and repacked expert records never claim it.
  - `test_coverage_index_is_unambiguous_per_source_type`: invariant test — a
    fake record re-claiming Q4_K on the raw moe_experts bucket raises
    `ValueError` from `_build_coverage_index` instead of displacing.
  - `test_repacked_moe_experts_still_qualify_with_decode_repack`: guard that
    the T16 expert families were not narrowed by the fix.
  - Negative rank-2 dense IQ3_XXS refusal is unchanged
    (`test_rank2_dense_iq3_xxs_is_refused_not_silently_supported`, pre-existing).
