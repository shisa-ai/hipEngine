# Suppress literal stop strings before SSE publication

## Summary

Live completion and chat streams previously published literal stop strings
before post-trimming the final response. Stops split across SSE chunks or
inside a token could therefore leak. The post-trim path also discarded final
generated IDs and speculative attribution.

## Changes

- Add request-local stop-prefix buffering before SSE publication and before
  reasoning/content splitting. Preserve original chunk boundaries when no
  truncation is needed; flush unmatched prefixes at normal completion.
- Keep requests without stops on their original chunk path. State is not shared
  across requests. Closing the wrapper closes the controlled source iterator.
- Drain the backend after a literal match while suppressing further text, so
  final generated IDs, usage, and MTP attribution survive. This fixes visible
  stop semantics; it does not guarantee early computation termination for
  substrings the runtime token matcher cannot recognize.
- A stop that cuts through a logprob token preserves its ID and visible
  fragment but omits that fragment's probability instead of inventing one.
- Preserve terminal metadata after flushing held text and override the finish
  reason to stop without reporting an obsolete output-length limit.
- No kernel, arithmetic, routing-default, dependency, or flag change.
