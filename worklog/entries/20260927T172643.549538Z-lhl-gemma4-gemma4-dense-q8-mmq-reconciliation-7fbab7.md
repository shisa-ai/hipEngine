# Reconcile the dense Q8_0 MMQ penalty: one change, two denominators

## Summary

The campaign doc carried two different figures for one change. Iteration 150
(`780d24f29`) recorded the dense Q8_0 MMQ chain as **29% slower** than the bf16
WMMA owner; iteration 154 (`07e1364be`) recorded the same route as **44%
slower**. Both were correct as measured, and the difference is the denominator,
not the change.

Re-measured with one method at both row counts (`gemma4_dense_q8_route_probe.py
--arm both --repeats 3`, medians, W7900, both GPUs idle):

| rows | WMMA owner | MMQ chain | ratio |
| ---: | ---: | ---: | ---: |
| 512 | 246.0 ms | 373.0 ms | 1.516 |
| 1024 | 532.0 ms | 778.5 ms | 1.463 |

The penalty is 1.46-1.52x at both widths, so row count does not explain the gap.
Iteration 150's comparison ran at 1024/1373 = **745.8 ms** of prefill, before the
AOTriton attention change; the same prefill's forward is now **532.0 ms**. A
fixed ~0.25 s cost against a base that shrank 29% reads as a larger percentage
without the change becoming worse.

The absolute deltas agree across both harnesses: the probe adds **+246.5 ms** at
1024 tokens and iteration 150's campaign-bench run added **+225.7 ms**
(745.8 -> 971.5 ms), within 9%. The remainder is scope — the bench's
`prefill_s` includes the first-token and sampling step, the probe's raw
`runner.forward` wall does not.

Both arms were confirmed to target the identical leaf
(`mmq128_prefill_q8_1_d4x3_guarded_bf16_bf16_out`, `abi` `raw_mmq_d4x3`), so this
is one change measured twice rather than two related ones.
