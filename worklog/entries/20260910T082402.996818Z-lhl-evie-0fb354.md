# EVIE batched encode campaign: 2.13s -> 1.13s, beats torch bf16

## Summary

Executed the batch-review plan (648bca / b11a16) in full. New
segment-batched encode paths (encode_queries / encode_documents) with
exact isolation, plus the elementwise-kernel coalescing pass the batched
profile exposed.

### Batched encode (ragged segments, no padding)

- Dense projections run once over the concatenated stream; attention runs
  per segment via pointer-offset sub-ranges (B x L^2, not (B L)^2); conv
  and GDN recurrence use the existing qwen35 segments kernels with
  per-segment zeroed state slots. Per-segment rope positions; per-page
  visual features concatenated in stream order (the embed kernel's
  positional walk makes ownership follow from order).
- Two state-slab bugs found by the isolation tests and fixed: the
  segments conv wrapper's trailing state kernel writes each segment's
  final conv state into its slot, so the slab must be re-zeroed every
  layer (first run polluted layer N with layer N-1 state, 0.117 drift);
  visual row counts must come from image-token counts, not buffer
  nbytes (allocation padding shifted every later page's rows).
- Isolation contract (tests/test_evie_gpu_runtime_batched.py): distinct
  same-length neighbors A|B vs A|C leave A bit-identical; identical
  repeats match sequential bit-exactly at equal batch shape; ragged
  shapes (different GEMM m) within 2e-5; segment lengths 1/2/3/5 match
  sequential; fixed batches repeat bit-exactly. fp32 batched vs
  torch-fp32 oracle scores agree to 1e-4.

### Elementwise-kernel coalescing (T1 reduction reorder)

The batched profile (HIP-event timing) showed the norm/rope/l2norm
kernels were one-thread-per-row serial loops: gdn_l2norm_scale_repeat
148.6 ms, rope 57.9, layernorm 58.9, gdn_rmsnorm_gate 49.6 of a 1376 ms
8-doc encode. Rewrites: all-thread coalesced writes after the block
reduction (norms), thread-per-(row,d) rope (bit-identical math), one
warp per (token,head) with butterfly shuffle for l2norm_scale_repeat.
After: 6.8/7.6/8.5/11.7 ms; batched 8-doc encode 1376 -> 1081 ms.

### Results (matched protocol, real processor inputs, best of 3)

- fp16 batched: doc 1027.4 ms, query 139.7 ms, total 1172.7 ms vs
  torch bf16 1074.1/224.2/1299.5 — hipEngine leads by 1.11x overall
  (1.04x doc, 1.61x query).
- Bench protocol (synthetic pages, preprocessing outside timing):
  fp16 8p+8q 1133.8 ms (sequential 1812.4 with new kernels, 2114
  before the campaign).
- fp32 strict batched: 6199.5 ms (sequential 7717).
- Retrieval quality unchanged: hip-fp16 preserves the torch-fp32 argmax
  ranking 8/8 (torch bf16 5/8), max rel 0.24% vs bf16's 3.5%.
- fp16 manifest re-recorded after the reduction reorder: q mean/min
  0.9999986/0.9999924, d mean/min 0.9999491/0.9984596, maxsim delta
  2.9e-5 (was 6.2e-4).
