# Hide Gemma explicit single-token stops and preserve SSE attribution

## Summary

The four-model public matrix exposed a Gemma stop defect. Both AR and MTP
stopped at the requested single token, but reported it as EOS and included it
in visible text. Blocking chat post-trimmed the text; SSE exposed it and then
discarded final IDs and MTP attribution when its own stop handler fired.

## Changes

- Report explicit single-token stops as `stop_sequence`, not `eos_token_id`,
  in Gemma AR and MTP. The existing sequence visibility rule now excludes the
  token from text while preserving it in generated IDs and usage.
- Cover the prefill token, accepted drafts, and later cycles with eight CPU
  regressions. Update two existing tests that expected the old EOS field.
- No kernel, arithmetic, route-selection, or product-default change.
