# Qwen4Exp checked full-rows dense Q8 DPP promoted to production default

## Summary

The checked-int32/full-four-row dense Q8 DPP sibling
(`coltile8_rowbatch4_wave_scale_pipelined_dpp_checked_full_rows_f32_f32_out`)
is now the production default leaf for its qualified shape window: the six
declared dense Q8_0 geometries of the Qwen4Exp lane between 512 and 4096
complete rows. It is a T0 exact-class variant (same ordered FMA/DPP
arithmetic as the plain DPP leaf; bit-identical outputs), so the promotion
changes scheduling only. Every other Q8_0 dense shape — decode rows, prefill
tails, unqualified geometry — keeps the plain DPP parent, which remains
registered as the strict fallback.

This banks the prefill win qualified by the 2026-10-07 screen, natural-input,
full model-state and complete-engine A/B chain: cooled canonical client wall
457.017 -> 447.633 s (-2.05%), prefill 294.68->308.43 / 320.15->335.63 /
327.42->340.24 tok/s at p512/p1024/p4096 (+4.7/+4.8/+3.9%), decode flat
(20.40->20.37 / 19.85->19.73 / 16.75->16.94). The controlling same-residency
balanced A/B measured prefill 1.0450x, decode 1.0122x, client wall 0.9748x
with all 12 trajectories exact and zero teardown allocations.

## Validation

- Exactness: 12/12 canonical cases produced identical output token-ID
  digests between the off/on arms of a fresh production-path pair (compact
  capture); the committed same-residency A/B independently shows
  cross_mode_output_exact on all 12 cases with 3,564 candidate calls and a
  kernel trace carrying the expected `int,true` signature.
- Performance (cooled, idle-settled, single model residency, chunk 4096,
  1 warmup + 3 repetitions, 128 decode transitions): total client wall
  457.017 -> 447.633 s (-2.05%); prefill +4.7/+4.8/+3.9% at p512/p1024/p4096;
  decode unchanged within noise. The loop's keep decision is recorded in the
  qwen4exp-faster/ar-speed-20261007 multiloop state.
- Tests: focused unit bundle (wave route, dense split route, natural-owner
  contracts, layer2 gate) 38 passed; GPU dispatch test passed; full unit
  suite 8,495 passed at the pre-promotion commit (conftest baseline fix,
  committed separately as 082f4612a).

**Measurement-protocol finding (important for future perf work on this
host):** four consecutive full-load canonical runs degraded monotonically
regardless of arm — identical off-arm code drifted 457.017 -> 470.627 s, and
an on-arm run chained immediately after another full run hit 500.302 s. The
host shows ~1.5-3%/run sustained-load drift, worst on bandwidth-bound p4096
decode (GPU recovered to 41 C at full clocks minutes after). Cross-process
single-arm comparisons cannot resolve sub-3% effects here: use an
idle-settled run (>=18 min), a same-session reference arm, or the
same-residency balanced A/B harness. The cooled re-measure landed on the
A/B's prediction (457.017 x 0.9748 ~ 445.5 vs measured 447.6).
