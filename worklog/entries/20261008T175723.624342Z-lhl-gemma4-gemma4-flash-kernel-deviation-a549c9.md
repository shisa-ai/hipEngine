# No flash-kernel arithmetic regression: the route's kernel is bit-identical across the window

## Summary

Resolves the open question left by
`worklog/entries/20261008T174856.609217Z-lhl-gemma4-gemma4-short-route-vs-exact-f6ba87.md`
("not established: whether the flash kernel's arithmetic regressed, or the model
became more sensitive to it"). **It did not regress.** The flash kernel's output
is bit-identical between `abf639894` (2026-09-30, where the route landed) and
HEAD, across 24 cases covering both production packings, three mask modes, two
dtypes, and keys 2,047 and 4,096 -- every printed deviation matches to the last
digit.

Measured deviation, flash against the single kernel on one input per case
(raw ABI, alternating, seed 20260930), `max_abs/scale`:

| dtype | range over 24 cases | note |
| --- | --- | --- |
| f32 | **4.71e-7 .. 9.11e-7** | the arithmetic agreement; 1e-6, not 1e-4 |
| bf16 | 0.0 .. 1.50e-3 | mostly exactly 0: the pre-rounding difference is below one bf16 quantum, and the non-zero rows are ULP-boundary flips |

So the kernel agrees with the single kernel **three orders of magnitude more
tightly** than the 1e-4 the battery asserts, and identically on both trees. That
clears this unit's tuning ladder (`ea5597a1c`, `5faef25f4`, `3a55f9ad5`,
`37ba3b3da`, `308c4c38c`) of any numerical effect: `kFlashThreads` 128 -> 256,
`__launch_bounds__`, the phase-B dimension loop, the denominator broadcast, and
the three-deep V pipeline are all arithmetic-preserving, as designed. It also
rules out the single kernel having moved: a change to either side would have
changed the *difference*, and the difference is unchanged.

**What follows for the model-level result.** On HEAD the same route choice moves
the teacher-forced trajectory by mean KL 5.38e-3 (all layers) / 1.23e-2 (sliding
layers only); on the 2026-09-30 tree it moved it by 7.75e-6. With the kernel
identical, that change is on the model side: the same ~1e-6 attention difference
is amplified more by the model as it stands now than it was then. The metric's
own behaviour supports amplification rather than a systematic per-layer error:
it is **not monotone** in the number of flash layers -- putting the 5 global
layers on flash as well *reduces* the mean KL from 1.23e-2 to 5.38e-3, which a
systematic per-layer error cannot do. A chaotic trajectory divergence can.

The envelope-scope question from the previous entry is unaffected and still
stands: the shipped route exceeds the mean/p99/max bars, and whether those bars
are a promotion gate or a production contract is a decision, not a measurement.

## Validation

- 24 of 24 cases compare equal between the two trees (`rows_identical: 24`),
  which is the regression question answered directly.
- The diagnostic is deterministic: repeated runs on the same tree reproduce
  every value, and the two trees' independent builds produce identical numbers.
- The battery (`tests/test_gpu_gemma4_flash_decode.py`, 60 cases) passes on
  HEAD, and its asserted bound (1e-4 f32) is now known to be ~100x looser than
  the measured agreement.
- Case matrix: sliding (head_dim 256, ratio 2) and global (head_dim 512,
  ratio 8) x f32/bf16 x keep/window/holes x keys 2,047/4,096, slices 64.

## Next

- **The amplification itself is now the open question**, and it is a property of
  the model rather than of the attention route: something in the 2026-10-01 ..
  10-07 work made the decode trajectory far more sensitive to a 1e-6 attention
  difference. Worth knowing before judging any further decode-attention
  candidate by this instrument, because the same candidate that measured 5e-6
  on 2026-09-30 would measure ~1e-2 today without its arithmetic changing.
- **One mechanism the kernel-level test cannot see:** it builds its own mask. If
  the production sliding decode reaches the flash route with different *inputs*
  (a window/row_offset-trimmed KV view rather than a mask), a route-level
  difference would show up at the model level while the kernel stays
  bit-identical. That is testable by extending this diagnostic with the
  window/row_offset parameters and is the next thing to try if the amplification
  explanation does not hold up.
- Task 53 (gate the sliding route above its entry band, keys 2,048-15,856)
  becomes more valuable, not less: if the model is this sensitive, the route's
  behaviour where it has never been measured matters more.
