# Concurrency2 C2-6 shared-slot fallback correction

## Summary

Corrects the earlier C2-6 blocker diagnosis without claiming C2-6 closure. The independently submitted row mismatch came from constructing one complete GGUF session per resident row and from using slot views through scalar prefill. One batch-shaped target scratch owner with lightweight slot-local recurrent/KV/cursor views plus owner-packed prefill now provides an exact physical-c1 numerical fallback through logical c32. Native shared-slot packed decode and arbitrary-page Generation-2 device execution remain blocked.

## Changes

- Key shared GGUF sessions by `max_batch_size`, allocate one load-time batch-shaped owner, and expose allocation-free slot views over its preallocated recurrent/full-attention state rows.
- Keep execution/prefill/packed workspaces under the owner while each slot retains independent scratch slices, cursor, graph bookkeeping, and dynamic KV lease.
- Route every Generation-2 slot, including c1, through owner-packed prefill; route packed execution APIs through the owner.
- Fail shared-slot physical cN decode closed with the explicit `shared_slot_packed_decode_unqualified` reason after c4 and c8 both reproduced the second-row invalid-token sentinel.
- Make same-server c1 trajectories the F1 oracle, avoid a redundant second model load, treat zero requested warmups as skipped/pass, and accept honest mixed fallback telemetry when solitary and co-resident requests occur in one run.
- Retain and document the Generation-1 `DeviceChunkedKVPool` compatibility seam. The global arbitrary-page runner adapter is still not device-wired.
