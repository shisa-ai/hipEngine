# Gemma 4 Q5_K gate_up MMQ32 leaf: pre-flight and scope

## Summary

Pre-flight for punchlist P3 Step 2 — "add a Q5_K tile loader to the int8 MMQ32
gate_up leaf" — completed before any code, per `docs/OPTIMIZATION.md` §3. No
kernel has been written yet; this entry records what the port actually involves
so the next unit starts from a correct scope rather than the original estimate.

**The row splits, and only the gate_up half is open.** P3 Step 1 established
that layer 29's Q8_0 down was a *routing* defect (fixed in `7a91b5735`) while
its Q5_K gate_up is a genuine *missing leaf*: it falls back to
`gguf_q4_k_selected_dual_grouped_rowbatch` at 21.9 ms / 1024, against
llama.cpp's ordinary MMQ at 2.6 ms for the same work. One layer costs 13.8% of
prefill, so the row estimates ~60 ms at 1024 and ~258 ms at 4096.

**Scope correction: the port touches 49 sites, not 23.** The task record cited
23 sites for the Q4_K-specific symbols in
`hipengine/kernels/hip_gfx1100/quant/gguf_q4_k_q8_1_selected_prefill.hip`, but
the actual count is 49. The five cited definition lines are all still exact —
`gguf_q4_k_scale :159`, `gguf_q4_k_min :167`, `gguf_q4_k_quant :175`,
`pack_q4_k_u8x4 :202`, `q4_k_mmq32_cache :493` — so the estimate counted the
definitions and missed the 44 use sites. Three of those are
`__shared__ q4_k_mmq32_cache weight_tile[32]` declarations at :1478, :1523 and
:1574 that hardcode the cache struct's layout, pinned by
`static_assert(sizeof(q4_k_mmq32_cache) == 20)` at :499. The file itself is
7408 lines, not the 7399 recorded. Q5_K's extra `qh[32]` plane is what makes a
`_MMQ_DUAL_QUANT_KEY` widening misdecode rather than merely under-optimized, so
this remains a source port and not a guard change.

**Dispatch gate.** `gemma4_experts.py:635` sets
`_MMQ_DUAL_QUANT_KEY = "gguf_q4_k"`, checked at `:944`; gate_up resolution
builds `KernelKey(backend, "moe_linear", quant_key, variant)` at `:758`, `:827`,
`:1195`, `:1278`, where `variant` is
`_WMMA_DUAL_PREFILL_COMP_VARIANT` or `_WMMA_DUAL_PREFILL_VARIANT`.

**In-repo precedent for adding a quant MMQ consumer** is `926f8b47a` (Q5_1):
a self-contained 198-line `.hip`, a 140-line build wrapper, a 172-line GPU test,
a 60-line worklog entry and a gate artifact — all new files rather than edits to
a large family file. It shipped **default off with a named concrete cause**
("Full-layer 450-row packet fails mixed_ja_en (1.44e-3) + one first-run state
row: env stays off pending the per-layer admissibility screen"), which is the
model to follow if the Q5_K leaf needs an admissibility screen.
