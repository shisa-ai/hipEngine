# G3 long-context task generator/evaluator and free-running diagnostic

## Summary

Implemented the frozen G3 long-context task generator/evaluator and the
non-binding free-running diagnostic required by
docs/campaigns/DMS-SELECTOR-IMPROVEMENT.md Sections 4, 5, and 11 (Phase A
evaluation-support prerequisites). One pure library, one explicit
build/run/compare CLI, and one pure unit-test file; no GPU, model, or
network run was performed and no existing evaluator or campaign file was
touched.

## Changes

- `hipengine/benchmark/dms_tasks.py` (new, stdlib-only pure module): frozen
  24-case matrix (retrieval / two-hop / variable-state x code /
  general_en / general_ja / mixed_ja_en x early / recent), exact target
  token length with recorded dependency/query positions (early dependencies
  outside W256 at the cut: distance > 256; recent within 128 tokens),
  per-case seed/nonce derivation, source-disjoint filler sliced from the one
  assigned split with answer-token-sequence absence enforcement, filler
  correlation reporting (reused sources/prefixes are correlated, not
  independent), deterministic English/Japanese/mixed/code templates,
  `parse_answer` exact-nonce scoring, `compare_g3` (candidate >= dense
  overall and per family/category/placement/tested-length, baseline
  reported separately and never gating, dense failures retained, paired
  case deltas, identity/hash mismatch rejection), and `free_running_metrics`
  (first divergence / comparable prefix / fixed-length token match,
  non-binding). Answer keys are evaluator-only, never a selector
  feature/control signal; each answer occurs exactly once, inside its
  dependency statement where the task semantics require it.
- `scripts/qwen38_dms_campaign_tasks.py` (new CLI): `build` (sealed data
  manifest/split + exact model tokenizer + target context 32K/128K + suite
  + seed -> immutable 24-case task manifest), `run` (exactly one arm
  dense/no_evict/sidecar under a dense-compatible greedy schedule with a
  fixed max answer length; records generated tokens/text, parser verdict,
  DMS route/capacity/count digest with no silent fallback, memory
  teardown-to-baseline, model/metadata/task/evaluator hashes; dense arm
  carries no metadata, DMS arms require it; `--diagnostic free-running`
  runs the non-binding 256-token diagnostic on ordinary sealed prompts),
  and `compare` (frozen G3 over dense/baseline/candidate result files from
  the same task manifest). Runtime imports stay inside execution paths.
- `tests/test_unit_dms_campaign_tasks.py` (new, 22 tests, tokenization
  injected as a deterministic fake): exact matrix/order, exact lengths and
  positions at 4096 and the frozen 32768 length, determinism and seed
  sensitivity, answer uniqueness/absence/query non-leak, placement distance
  rules, tampering rejection, language/category template distinctness,
  correlated filler reporting, parser positives/negatives, G3 global and
  per-scope failure cases, dense-failure retention with paired deltas,
  baseline separate reporting, identity/arm/metadata/case-set mismatch
  rejection, free-running metrics, and all three CLI parsers.
