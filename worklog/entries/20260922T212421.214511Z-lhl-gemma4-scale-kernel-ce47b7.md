# gemma4_scale_bf16 closes the last missing op before the runner

## Summary

Added `gemma4_scale_bf16` — elementwise `out = x * scale` over bf16 — to the
Gemma 4 norm family, with tests. This was the one op the runner needed that no
existing kernel provided.

With it, every stage of the Gemma 4 forward pass now has a kernel:

| stage | route |
| --- | --- |
| embedding gather | `embedding/gguf_q8_0/lookup_bf16_out` (raw layout) |
| embedding scale | `scale/gguf/gemma4_plain` |
| per-layer forward | `gemma4_layer_forward_bf16` |
| expert projections | `linear/<quant>/selected_gemv_bf16_bf16_out` |
| final norm | `rmsnorm/gguf/gemma4_plain` |
| lm_head | `launch_gguf_linear`, `output_dtype="f32"` |

What remains is assembly: the runner, the generation adapter, and the end-to-end
run. No further kernel discovery is expected.

## Why the scale is not foldable

Gemma 4 computes `hidden = embedding[ids] * sqrt(hidden_size)`. The layer's first
op is an RMSNorm, and an RMSNorm is scale-invariant — so it is tempting to skip
the multiply and let the norm absorb it.

That is wrong. The scaled embedding **is** the residual stream. The layer adds
its attention and MLP outputs back to the un-normalized residual, so dropping the
factor leaves the residual short by `sqrt(hidden_size)` — 53.066 at
`hidden_size = 2816`. The norm would not see the error, and the logits would.

## The test

`test_scale_multiplies_a_row_by_a_scalar` is parametrized over
`[1.0, 53.066, 0.5, -2.0, 0.0]`. The oracle multiplies the **bf16-rounded
input**, not the original f32, so the only error the assertion attributes to the
kernel is the output rounding rather than input quantization the kernel never
controlled.

- `53.066` is the real model's factor, so the case that matters is covered
  directly.
- `1.0` and `0.5` check the multiply is a multiply rather than something that
  happens to be right at one factor.
- `0.0` is included because a kernel that special-cased zero would be wrong in a
  way a non-zero test would not see.
- `-2.0` covers the sign.

`test_scale_is_correct_in_place` covers `out_ptr == x_ptr`, which the runner uses
to scale the embedding buffer without a second allocation. That is safe here
because each thread reads its own element before writing it.

The degenerate-shape test gained `rows = 0` and `hidden_size = 0` cases.
