# Add deterministic subsampled long DMS labels

## Summary

Static per-layer/head bias calibration is exhausted: both effective CR2 and the
single conservative CR1.5 rescue fail the same 32K Japanese development
trajectory, so long-context learned weights are required. Added deterministic
query-stride subsampling to the exact full-prefix future-attention label builder
to make 32K labels computationally feasible without truncating keys/history.

## Changes

- GPU label oracle accepts `--query-stride N`; every Nth causal query is scored
  against all 32K keys, retaining full-prefix positions and protected-window
  semantics while approximating future-attention mass.
- Query tiling counts sampled queries, provenance/backend identity includes the
  stride, and CPU mode rejects non-unit stride.
- Default stride remains one and therefore preserves prior exact behavior.

## Validation

- CR1.5 development screen: aggregate max/mean KL 0.12991/0.006284 and 96.875%
  top-1; Japanese max KL 0.12991/top-1 87.5%; other categories pass. This is
  still rejected despite only 1.437-1.559x compression.
- Label suite: 6 passed / 1 skipped in the uv environment. The real PyTorch ROCm
  stride/default deterministic GPU node separately passes with system Python.
- Ruff, py_compile, and diff checks pass.

## Next

- Capture four source-disjoint 32K calibration sequences at exact Q4 behavior
  with FP16 Q/K storage, then benchmark one label shard across stride candidates
  before launching the full label set.
- Train weights on long labels and reserve the v3 zero-overlap corpus for final
  integrated evidence.
