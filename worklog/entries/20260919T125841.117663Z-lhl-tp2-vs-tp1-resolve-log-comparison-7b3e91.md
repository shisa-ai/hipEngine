# Produced the TP1 route's resolve log; it does not settle the divergence

## Summary

The TP1 reference capture records no resolve log, so the bulk prefill's dispatch
decisions could not be diffed against it. Producing that log was the cheapest way
to test the leading hypothesis for the gate failure - that the two routes resolve
different kernels for the same weight and rows.

The log now exists, and it shows one leaf that appears only on the TP1 side:
`dense_dual_wmma_prefill_row64_bf16_bf16_out` is resolved 128 times by the TP1
route and **does not appear anywhere in the TP2 route's 450-entry log**. Both
routes resolve `dense_dual_local32_bf16_bf16_out` for decode, so that leaf is
shared and is not the difference.

**That is not enough to conclude a mismatch, and the entry should not be read as
one.** The two probes did not run at the same row count or over the same prompts:
the TP1 probe used `capacity=200` with a 64-token prompt, while the TP2
diagnostic used its bulk capacity over two prompts. A row-dependent dispatch
would produce exactly this leaf difference with no mismatch at all. Two further
facts point the same way: the TP2 route's dominant prefill kernel in the phase
attribution (`gguf_q4_t16_dense_wmma_prefill_shared_b`, 41.8% of the wall) does
not correspond to any TP1 leaf either, and the TP1 reference's own scope manifest
declares `c1_full_mlp_variant: dense_dual_local32_bf16_bf16_out` while the run
actually resolved `dense_dual_wmma_prefill_row64` for the prefill - the declared
c1 variant is not what a bulk prefill uses on either route.

The correct reading is that the comparison is confounded by row count, and the
hypothesis is still open.

## What the probe did establish

- The TP1 reference route is a **resident control** session
  (`create_resident_control`), not an `MlpTP2GenerationSession(mode="tp1")`. Any
  future like-for-like probe has to build that session, not the TP2 class.
- The resolve logger from `scripts/tp2_bulk_prefill_diagnostic.py` attaches to
  the resident control path unchanged, so the instrument generalizes.
- A prefill-only probe is misleading on its own: the first run showed
  `dense_dual_wmma_prefill_row64` with 64 calls and no `dense_dual_local32` at
  all, which read like a clean mismatch. Adding eight decode tokens made both
  leaves appear. Leaf-set comparison needs every phase the other side exercised.

## Next

Re-run both probes at one declared row count over the same prompt and diff the
leaf sets. That is a single cheap run each and it either names the mismatched
kernel or closes the hypothesis, which decides whether the attention divergence
is a dispatch problem or a kernel-level one. Until then, no kernel work on the
Q6_K `attn_qkv` projection is justified - the cheaper explanation is untested.

The route's state is otherwise unchanged: prefill 1032.9 tok/s (26.3x the
token-serial start), gate failing for a real and reproducible reason, and the
divergence localized to layer 0's attention in the replicated phase.
