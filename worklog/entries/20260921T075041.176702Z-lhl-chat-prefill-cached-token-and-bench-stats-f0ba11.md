# chat prefill, cached-token, and /bench stats

## Summary

`hipengine chat` now reports prefill and cached-token stats beside the decode
rate, and `/bench` measures prefill, decode, and prefix-cache reuse for the
MTP-on and MTP-off routes of the running server. The server side adds the
vLLM-compatible `usage.prompt_tokens_details.cached_tokens` field, read from the
per-request prefix-cache diagnostics the GGUF resident loop already publishes.

## Changes

- `hipengine/server/api.py`: `_usage()` now adds
  `prompt_tokens_details.cached_tokens`, summed from
  `telemetry.diagnostics.prefix_cache.reused_tokens` across the request's
  outputs and clamped to `prompt_tokens`. It is omitted entirely when no output
  carried prefix telemetry, so the server never reports a zero it did not
  measure; a cache that was consulted and missed reports `0`. New helpers
  `_prefix_cache_diagnostics` and `_prefix_cached_token_total` mirror the
  existing `_mtp_accepted_rejected_counts` idiom.
- `hipengine/chat_cli.py`: `_stream_events` requests `include_hipengine` and
  yields `("meta", ...)` payloads. `_Turn` keeps that metadata and exposes
  prefill/decode/cache metrics that prefer engine-reported timing
  (`backend_prefill_ms`, `decode_tokens_per_second`) and fall back to client
  clocks. The per-reply stats line became
  `N tokens · prefill X tok/s · decode X tok/s · cached N · ttft · total`, and
  `/usage` gained a cumulative `cached` row. New `/bench [prompt_tokens]
  [max_tokens]` command (defaults 512/32) sends one cold and one repeat request
  per route and prints `route / cache / prefill / decode / ttft` rows. Each route
  gets its own nonce-prefixed prompt so one route's cold run cannot hit the
  other's cache entry, and a route the server refuses is reported as a note
  instead of failing the bench. The plain client runs the same measurements.
- Tests: `tests/test_unit_server_prefix_cache_usage.py` (hit, measured miss,
  no-telemetry omission, prompt clamp, batched sum, coexistence with MTP
  acceptance), `tests/test_integration_server_prefix_cache_usage.py` (streamed
  and blocking chat usage through a real app with a fake engine), and new cases
  in `tests/test_unit_chat_cli.py` (stats line, usage-vs-diagnostics precedence,
  client-timing fallback, `/usage` cached row, `/bench` route isolation, refused
  route, argument errors, plain-mode output).
- Docs: `docs/API.md` gains a prefix-cache usage section and no longer lists
  cache hit/miss as an unavailable signal; the README chat paragraph mentions
  the stats and `/bench`.

## Validation

- Live, `qwen3.8-27b` on hip_gfx1151 with `--prefix-cache radix`, driven through
  the real rich client: `/bench 512 24` reported MTP on `526 tok · 244 tok/s`
  prefill at `2.16s` ttft and `26.2 tok/s` decode, then `hit 512` with `14 tok`
  prefilled at `0.55s` ttft; MTP off reported `528 tok · 294 tok/s` prefill and
  `10.8 tok/s` decode, then `hit 512` at `0.45s` ttft.
- Live, two-turn conversation sharing a ~525-token prefix: turn two printed
  `27 tokens · prefill 55 tok/s · decode 34.5 tok/s · cached 512 · ttft 0.49s`
  and `/usage` printed `cached 512 tokens · 48.3% of in`, both read from
  `choices[].hipengine.diagnostics.prefix_cache` because the running server
  predates the new usage field.
- Tests: `tests/test_unit_chat_cli.py` 26 passed / 2 skipped (rich available),
  `tests/test_unit_server_prefix_cache_usage.py` 6 passed,
  `tests/test_integration_server_prefix_cache_usage.py` 4 passed.
- `python3 scripts/docs/check_all.py`: all 4 documentation gates passed.
- Not verified live: `usage.prompt_tokens_details.cached_tokens` on the
  long-running server, which still runs the pre-change code. It is covered by
  the integration tests through a real app and by the `_usage` unit tests; the
  chat client reads the same count from stream diagnostics either way.
