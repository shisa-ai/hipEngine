# Preserve explicit MTP intent and implement Gemma generation controls

## Summary

Gemma explicit MTP no longer silently becomes AR after invalid requests open the
runtime breaker, or when the HTTP queue groups requests beyond the provider's
single-prompt capability. Unsupported controls are validated before scheduler
mutation. Supported thinking budgets, min_tokens, logprobs and token-sequence
stops run on both AR and MTP.

## Changes

- `hipengine/server/api.py`: client errors do not count as runtime breaker
  failures. An unavailable explicit request fails by name instead of silently
  decoding through AR; automatic fallback retains its route reason. Runtime
  response metadata preserves explicit/automatic intent. Independently scheduled
  MTP clients no longer wait for a prior HTTP request to finish before admission;
  provider widths still apply. A ready provider with no fallback position no
  longer reports root bookkeeping `no_provider` as a request fallback.
- `hipengine/generation/engine_loop.py`: forward a compatibility generator's MTP
  width and invoke its request validator before admission.
- `hipengine/generation/gemma4_gguf.py`: declare the singleton provider width,
  expose pre-admission validation, implement shared controls and logprob output,
  return zero-token requests without device work, and advertise buffered SSE
  logprobs. Thinking-budget finish metadata now names the reasoning/answer phase.
- `hipengine/generation/gemma4_sampling.py`: share budget, EOS suppression,
  sequence matching and logprob laws between AR and MTP. Preserve full-support
  greedy versus filtered sampled logprob semantics. Explicit control checkpoints
  precede selection mutations; published tokens discard rollback snapshots.
- `hipengine/generation/gemma4_mtp.py`: consume forced close tokens on both draft
  and target walks; restore controls after speculative proposal; truncate stops
  at the exact published prefix and restore its control state. Detect a sequence
  ending on the first prefill token. Forward logprobs in stream chunks.
- `scripts/mtp_http_replay.py`: replay captured public requests and reject HTTP
  success without actual explicit MTP. Keep reasoning/content channels separate.
- Focused integration and unit tests cover refusal behavior, singleton queue
  width, controls, stop boundaries, logprobs, zero-token requests and replay
  assertions. No kernel arithmetic was changed in this unit.

`min_tokens` suppresses model EOS, not custom stop ids/sequences, matching the
shared sampler contract. RED tests also reproduced two review findings: the
prefill stop emitted an extra token, and stopping during the first forced-close
row restored the already-popped queue rather than the pre-selection queue.
