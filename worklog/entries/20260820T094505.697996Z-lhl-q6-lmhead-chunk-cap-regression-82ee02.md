# Repair Q6 LM-head chunk cap regression from decc1a728

## Summary

`decc1a728` removed the `max_chunk = min(max_chunk, 4)` cap in
`Qwen35GGUFResidentSession._verify_lm_head_rowtile_chunked` to "restore
backend-qualified Q6 LM-head chunk sizes 6/5". On this branch the gfx1100
lm_head materializes as planar-qmicro `gguf_q6_k_t16_qmicro_planar_v1`, whose
`t16_gemv_rowtile_bf16_f32_out` owner
(`gguf_q6_k_t16_qmicro_planar_gemv_rowtile_bf16_f32_out`) accepts only rows in
[2, 4]. Removing the cap made rows 5/6 chunks fail at prefill with
`ValueError: qmicro planar rowtile requires rows in [2, 4]`, which blocked the
full-model c1-c8 benchmark.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: restored
  `max_chunk = min(max_chunk, 4)` in `_verify_lm_head_rowtile_chunked` with a
  comment noting the planar-qmicro [2, 4] owner and that the backend-qualified
  6/5 value is reachable only after a rowtile owner supports rows 5-6
  (tracked as the planar-qmicro Q6T16 rows 5-8 unit).
- `tests/test_qwen35_gguf_verify_lm_head_top1.py`: updated the two chunked
  planner tests to expect 4-row chunks (rows=12 -> 4+4+4; rows=8 -> 4+4) for
  the planar-qmicro [2, 4] owner. `test_small_b_rowtile_chunks_avoid_single_row_tail`
  still asserts the uncapped raw `_small_b_rowtile_chunks` and is unchanged.

## Validation

- `tests/test_qwen35_gguf_verify_lm_head_top1.py` passes (9 passed).
- Unblocked the full Qwen3.8-27B c1-c8 packed benchmark (previously failed at
  prefill with the rows-[2,4] ValueError).

## Next

- The planar-qmicro Q6T16 true col8 rowtile rows 5-8 unit (concurrency
  priority 2) will let the backend-qualified 6/5 chunk sizes become reachable
  again; that unit should relax or remove this cap.
