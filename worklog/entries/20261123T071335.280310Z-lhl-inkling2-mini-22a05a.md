# Inspect the pinned Inkling DSpark GGUF sidecar

## Summary

The pinned Loom DSpark sidecar is structurally compatible with the existing Inkling recurrent draft runtime. A header-only inspection established the tensor aliases and draft geometry; it did not validate proposals or enable drafting for GGUF.

## Changes

- No runtime changes. Inspect the [pinned device package](20261121T170419.285290Z-lhl-inkling2-mini-780776.md) on `strixhalo` using `hipengine.loading.gguf.scan_gguf`, and read only the small fuse tensor with `GGUFReader.dequantize_tensor`. Cross-check the package's generated `llm.loom` against `hipengine/runtime/inkling2_mini_dspark.py`.

## Validation

- The sidecar declares `dflash` with three draft layers, block size eight, noncausal noise-block attention, four target taps `[5, 23, 41, 48]`, and the local/global/local window pattern. Its hidden width, logical vocabulary size and logit cap agree with the target. Its 54 tensors use Q8_0 for attention and feed-forward matrices, BF16 for the recurrent head matrices and token table, and FP32 for norms, biases and fuse logits. The padded draft token table can be indexed with the target's smaller logical vocabulary.
- `dspark_fuse.weight` holds logits rather than normalized weights. The pinned generated `g_dsp_fuse_norm` normalizes across taps for each draft layer, matching the existing runtime's softmax direction. Pin the legacy-to-runtime names for the context K/V projections, fuse logits, recurrent joint projection and hidden correction before exercising proposals. This structure does not prove bitwise parity with Loom's quantized activation projections.
