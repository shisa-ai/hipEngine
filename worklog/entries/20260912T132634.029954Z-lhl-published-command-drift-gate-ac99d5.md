# Published-command drift gate: composed parsers and renamed targets

## Summary

Resolve follow-up 2 of `docs/testing/TEST-MIGRATION.md`. The gate reported 29
unknown flags and three missing scripts on HEAD. Auditing each report showed
29 of the flags are declared, just not in the file the checker read, and the
missing scripts split into one never-committed scratch tool and five test
modules the tier migration renamed. Fix the checker's model of a recorded
command instead of adding exceptions or rewriting measured provenance.

## Changes

- Read the composed parser. A published command runs the parser the script
  builds, so the gate now follows `suite.build_parser()` and shared helpers
  such as `add_kv_policy_args(parser, ...)`, and expands the
  `action=argparse.BooleanOptionalAction` negation (`--no-warmup`). Both
  composition patterns are repo-local module functions reached through a
  literal import; a spread option tuple (`*legacy_storage_flags`) is resolved
  from the call site. This cleared all 29 false `UNKNOWN-FLAG` reports, which
  were 27 from `scripts/gguf_native_context_gate.py` (parser composed from
  `scripts/qwen36_dense_gguf_suite.build_parser`) and two from
  `scripts/qwen35_gguf_bench.py` (`--kv-storage`, `--kv-scale-dtype`).
- Validate every `.py` target in a command, not only the first. The DMS
  artifact recorded a five-module pytest invocation; checking only the first
  token hid four renamed targets. A pytest invocation is no longer checked
  against a test module's (nonexistent) argparse CLI.
- Resolve a recorded test path through `docs/testing/test-tier-migration-2026-09-12.json`,
  the migration's own rename record, and report the redirect in
  `renamed_targets`. The artifact keeps the path that existed when the row was
  measured; a reader gets the current path. A path that is neither present nor
  recorded is still a `SCRIPT-MISSING` violation.
- Report `scripts_skipped` so a script whose CLI cannot be read statically is
  visible instead of silently dropping out of the gate, which is how the
  `--require-mtp` drift was originally missed. On HEAD that is one pre-existing
  case: `scripts/qwen35_batch_retained_bench.py` builds option names from an
  imported `_RETAINED_GATE_FLAGS` constant.
- Add the dated exception for
  `.worklog/tmp_m3_bench.py` in
  `2026-08-31-gfx1151-qwen38-mtp-c1-streaming-width1-retained.json`, matching
  the two existing `/tmp`-script entries. That row's command ran a scratch tool
  that was never committed, so it is unreproducible rather than drifted; the
  owner should re-measure with a committed tool.
