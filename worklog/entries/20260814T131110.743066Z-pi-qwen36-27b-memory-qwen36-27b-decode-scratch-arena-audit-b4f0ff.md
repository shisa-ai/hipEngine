# Select dense 27B decode-scratch arena

## Summary

Selected a model-scoped single-owner arena for the persistent c1 decode scratch as the next dense-27B memory candidate. The current `_FullStackScratch` requests the correct **203.768/236.065/429.848/688.226 MiB** at 512/1K/4K/8K but spreads it across **188 physical HIP allocations**. Fresh XTX probes reduce those to one allocation and save **64/96/98/100 MiB** of actual `hipMemGetInfo` usage without changing requested bytes, pointers exposed to kernels, math, KV layout, or scheduling.

This candidate is incremental, not sufficient for Vulkan parity by itself. The currently published whole-device gaps remain **0.394/0.587/1.089/1.090 GiB**, so the objective stays open even if the arena qualifies.

## Changes

- Reconciled the current after-load ownership census: fixed sole-T16 weights are 15.280 GiB; decode scratch is 0.199/0.231/0.420/0.672 GiB; session buffers are 0.108/0.170/0.543/0.549 GiB at 512/1K/4K/8K.
- Reconstructed `_FullStackScratch` for Qwen3.6-27B at requested capacities 640/1152/4224/8320. Every row has 188 owners: 48 three-MiB recurrent states, 48 0.15625-MiB convolution states, 32 BF16 KV planes, and 60 smaller metadata/work buffers.
- Rejected full-attention-only in-place aliases as the next allocation target: the current 4096-row single arena is bounded by the 467.5625-MiB linear stage-4 clique, so modeled `full_q/full_query_raw`, raw/normalized Q, attention/gate, and full-output aliases save **0 physical bytes**.
- Ranked normalized-GDN `prefill_value -> recurrent_out` in-place reuse second. It models a **66.5-MiB** 4096-row arena reduction but requires an explicit kernel alias oracle; owner packing has no kernel or arithmetic change and attacks the fixed untracked gap directly.

## Validation

- Current four-shape JSON ownership was recomputed from `/tmp/qwen36-27b-memory-goal/gate-plane-alias-{512,1024,4096,8192}.json`.
- A temporary `/tmp/scratch_commit_probe.py` reconstructed exact production allocation sizes, then compared separate owners with one 256-byte-aligned owner in fresh isolated processes on RX 7900 XTX (`HIP_VISIBLE_DEVICES=1`). Separate/packed `hipMemGetInfo` deltas were **414/350, 480/384, 674/576, and 936/836 MiB** at requested capacities 640/1152/4224/8320.
- The probe allocates and touches identical requested bytes in both modes and frees every owner; it is diagnostic-only and leaves no repository surface.
- Working tree was clean and synchronized before this decision; both gfx1100 devices and HIP were available.
