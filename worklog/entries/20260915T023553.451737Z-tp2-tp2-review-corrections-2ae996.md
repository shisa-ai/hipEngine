# Resolve the incumbent layouts from the planner and correct the AR block inventory

## Summary

Review of the MLP probe returned five findings; all were valid. The most serious
is that the probe **guessed the resident layout and guessed wrong**: it declared
the Q6_K down projection raw storage, while the incumbent plan resolves it to
`gguf_q6_k_t16_qmicro_planar_v1`. The probe now resolves every layout through the
engine's own planner. Also corrects a block-inventory error in
`20260914T205548.472962Z-tp2-tp2-mlp-shard-plan-probe-1a8424`: the AR model has
**16 full-attention blocks, not 17**. The 17th was the excluded MTP/NextN block
(block 64), which is not part of the AR cost model.

## Changes

**1. The dispatch-equality check was withdrawn as tautological.** It passed
identical `_Weight` stand-ins (layout, quant, backend) to the resolver twice and
compared the resulting keys, which shows only that identical inputs select
identical keys. It said nothing about whether a kernel accepts or correctly
executes a shard. Removed, along with the stand-in classes; the artifact now
carries an explicit `scope` field stating it is a host-payload prerequisite that
does not qualify device execution, and a test asserts that the withdrawn claim is
absent.

**2. Layouts now come from the incumbent planner.** New
`resolve_incumbent_plan()` runs the engine's real chain:
`build_qwen35_gguf_tensor_map` then `plan_qwen35_gguf_materialization` with the
flags `resolve_gguf_dense_flags` derives from backend capabilities and the
environment, and `decode_repack=gguf_decode_repack_enabled(None)`. The resolved
incumbent set on this host is:

| Slot | Layout | Quant key | Allocations |
| --- | --- | --- | --- |
| `ffn_gate` | `gguf_q4_k_t16_v1` | `gguf_q4_k_t16_v1` | tiles |
| `ffn_up` | `gguf_q4_k_t16_v1` | `gguf_q4_k_t16_v1` | tiles |
| `ffn_down` | `gguf_q6_k_t16_qmicro_planar_v1` | `gguf_q6_k_t16_qmicro_planar_v1` | tiles |

with `decode_repack=True` and `dense_q6_qmicro_planar=True`. So all three MLP
tensors are repacked t16 residents and **none is raw**. The repack table is now
keyed by layout, and an unknown layout is refused rather than falling back - the
probe failed loudly on the planar layout before the repack was added, which is the
behaviour that should have existed from the start.

**3. The reduction dtype is explicitly unresolved.** The probe previously declared
a 20,480-byte fp32 exchange while selecting a bf16-output down projection, which
is incoherent. It now records both options with their costs and leaves `selected:
null`: fp32 partials (requires the down projection to emit f32) or bf16 partials
converted to f32 before summation, with the note that conversion does not recover
precision already lost at each partial's bf16 rounding and that the conversion
itself costs time. Resolution belongs in the execution test, against the actual
output dtype.

**4. Model identity is content-bound.** `model_hash` is now
`build_qwen35_gguf_role_manifest(model_map).fingerprint` - role names, layer
scopes, shapes and storage types - instead of the placeholder `"mlp-probe"`.

**5. The A/B driver keeps every repetition's verdict.** `python_ladders` is a
list, not a single overwritten dict; the report carries per-repetition verdicts
(dependency verdict, its depth, the three vector-check findings, and every depth's
final-value match) and requires **all** of them to pass before `matched` is true.
A missing vector check is treated as a failure rather than as unknown. The Python
arm now closes its RCCL transport in `finally` after freeing its buffers, and a
close failure is recorded rather than raised.

## Validation

```
uv run python3 scripts/tp2_mlp_shard_plan_probe.py --model /models/gguf/Qwen3.8-27B-Q4_K_M.gguf \
  --layer 0 --world-size 2 \
  --json benchmarks/results/2026-09-15-w7900-tp2-mlp-shard-plan-probe.json
uv run python3 scripts/tp_staged_exchange_native_ab.py --depths 1,4,16,32,64,128 \
  --count 5120 --iterations 20 --warmup 6 --reps 2 \
  --json benchmarks/results/2026-09-14-w7900-tp2-staged-exchange-native-ab.json
uv run pytest tests/test_unit_scripts_tp2_mlp_shard_plan_probe.py \
  tests/test_unit_scripts_tp_staged_exchange_native_ab.py
```

Probe: five questions answered yes, 17 tests pass. The repack commutes with the
split for **all three** tensors under the incumbent layouts - gate/up on the
out-tile axis (`out_tiles[0:544]`, `[544:1088]`) and down on the block axis
(`blocks[0:34]`, `[34:68]` of 68) - so the row-split case is now checked, not just
the column-split case.

A/B: three matched runs now give **1.956x, 1.946x, 1.910x** (native 20.45-20.87 us
against Python 39.57-40.62 us per reduction). The docs report the range rather
than a point value, because the spread is real run-to-run variance on both arms.

## Next

The probe is a host-payload prerequisite, not device qualification. The remaining
packet is unchanged and now better specified: resolve the actual down-projection
output dtype and pick the reduction option explicitly; materialize full and local
device weights through the incumbent path; execute gate/up -> activation -> down on
both ranks and validate the partials against an independent CPU split oracle;
connect the partials through the native exchange into the residual/next consumer,
adding the residual once and verifying the boundary against TP1; then measure
complete TP1 and TP2 segment walls including conversions, ordering and
communication, and sweep the actual MLP quant/layout geometries before choosing
MLP-only or full TP.
