# P2 dispatch: the five global layers now route to the tiled prefill kernel

## Summary

P2's tiled prefill kernel existed but nothing selected it: no consumer resolved
the `prefill_attention` registry key, and `gemma4_layer_forward_bf16` chose
between AOTriton and the exact block kernel with no third option. This unit
wires the route and proves through the production entry point that a head_dim
512 global block actually executes it.

Routing is one pure function, `_select_prefill_route`, returning `"tiled"`,
`"aotriton"` or `"exact"` from arithmetic on the dimensions alone — tiled needs
head_dim 512, a key count divisible by 128 and head counts that tile evenly;
AOTriton needs head_dim 256, a self-derivable causal mask and more than one
row; everything else falls through to the exact kernel, which accepts any
shape. Nothing consults a model name, a file, a hash, or whether a combination
has been measured, and no shape resolves to no kernel. Because the two
specialized sets are disjoint (256 vs 512) priority never has to choose
between them.

`last_prefill_attention_route()` reports what the most recent forward selected.
It exists because finite output proves the layer ran, not *which kernel it ran*
— and without it the central claim of this unit would be unverifiable.

Two findings worth more than the dispatch itself:

**The CPU-reference layer test is only valid while the router agrees.** At
`tokens=32, top_k=3` the GPU layer diverged from `gemma4_decoder_layer_forward`
by 0.33 relative — one row, one column (row 19, col 23), deterministic across
four bit-identical runs. Bisecting the stage: attention matched an independent
numpy softmax oracle to 0.002–0.003 at 16/32/64 tokens, and rope matched the
CPU rotation to 0.0038, so neither was at fault. Setting `top_k = num_experts`
(routing irrelevant) collapsed the error to 0.0216 with no bad rows. The cause
is the **router selecting different experts**: bf16 logits on the GPU against
f32 on the CPU, where a row whose third- and fourth-ranked scores tie inside
bf16 rounding picks a different expert and differs by a whole expert's output.
It is a precision property of the router, not a defect in attention, so the
test neutralizes routing rather than absorbing the failure into a looser
tolerance.

**4.6% is this geometry's bf16 floor, not an attention error.** With routing
neutralized at the real global-layer shape, the tiled route lands 4.63% against
the reference and the pre-existing exact route lands 4.74% — the two agree to
0.5%, so the gap is bf16 rounding accumulated over roughly ten chained stages
at head_dim 512/128 tokens/hidden 256. The existing layer test documents the
same effect at 1.2–1.4% for its much smaller shape. The guard is set at 8%
with that measurement recorded beside it; a structural mistake lands an order
of magnitude higher.

Also this unit: triaged two worklog rows this session had pushed past
