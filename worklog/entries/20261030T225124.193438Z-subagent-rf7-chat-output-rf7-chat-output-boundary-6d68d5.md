# Extract pure chat-output parsing from the server API

## Summary

`hipengine/server/api.py` no longer defines the pure reasoning/tool-output
parser. It now lives in `hipengine/server/chat_output.py`, which imports only
the standard library: `collections.abc`, `dataclasses`, `json`, `re`, `uuid`,
and `typing`. It imports neither FastAPI/Starlette nor
`hipengine.server.api`, and no engine, generation, runtime, model, KV-cache,
speculative, dispatch, or loading module.

The moved definitions are the reasoning splitter (`_ReasoningSplitter`), the
reasoning split/phase helpers (`_split_reasoning`, `_tag_suffix_len`,
`_classify_chat_length_phase`, `_has_unclosed_tool_call`,
`_looks_like_partial_json`), terminal-marker stripping
(`_strip_chat_terminal_markers`), the tool-envelope parser
(`_parse_chat_tool_calls` and its block finder, JSON/XML/receipt helpers), the
marker/residue constants they use, and the parser result dataclasses
(`_ReasoningSplit`, `_ParsedToolCall`, `_ParsedChatOutput`, `_ReasoningPart`,
`_ToolCallBlock`). `_tool_call_name_prefix_text` moved with its only caller
(`_is_incomplete_duplicate_tool_prefix_control_residue`).

Engine-specific protocol adaptation (`_parse_chat_tool_calls_for_engine`,
`_reasoning_initially_open_for_prompt`), request validation, HTTP errors,
response shaping (`_chat_message_from_parsed`,
`_enrich_chat_tool_finish_details`), streaming and metrics stay in `api.py`.

This is a move-only boundary unit under RF-7. No algorithm, dataclass field,
source span, marker, typing rule, default, error, response shape, route, or
scheduling behavior changed. The owner takes explicit text/protocol-schema/
`initially_open` inputs and holds no application state.

## Changes

- `hipengine/server/chat_output.py` (new)
  - Owns the 37-name compatibility surface plus the two internal XML regexes
    `_XML_FUNCTION_ENVELOPE_RE` and `_XML_PARAMETER_RE`.
  - Definition text was sliced byte-for-byte from `HEAD:hipengine/server/api.py`
    at base `b1a621b75`; `ast.dump` for all 39 moved nodes is identical to the
    pre-move AST (captured before editing).
- `hipengine/server/api.py`
  - Removed the moved definitions (571 lines) and added an explicit
    `from hipengine.server.chat_output import (...)` block for all 37 names.
    Identity is preserved: `hipengine.server.api._ParsedChatOutput is
    hipengine.server.chat_output._ParsedChatOutput`, and so on.
  - No import was removed; `json`, `re`, `uuid`, `dataclass`, `Mapping`,
    `Sequence`, and `Any` remain used by the engine/validation/response code.
- `tests/test_unit_server_chat_output_boundary.py` (new, 235 tests)
  - Pins stdlib-only AST imports, standalone file load with no `hipengine` or
    HTTP/engine module in `sys.modules`, package import without the HTTP app,
    the exact pre-move AST hash for all 39 moved nodes, `api.py` importing every
    moved name from the owner and defining none of them, and object identity
    through `api`.
  - Embeds the pre-move oracle for reasoning splits (closed, unclosed,
    prompt-open, channel tags, terminal markers), chunk-split reasoning with
    source spans, split terminal markers held until `finish_parts`, terminal
    and edge-marker stripping, template-control residue, length-phase
    classification, JSON and Qwen XML envelopes, malformed/incomplete XML/JSON,
    bare JSON, duplicate envelopes, no-tools and tools XML parsing, chat-template
    residue around envelopes,
    string-versus-JSON argument typing for `type`, `type` lists, `enum`,
    `oneOf`, `anyOf`, `allOf`, and exact tool-block source offsets.
- Compatibility-import removal condition (parent owns docs): the import block
  in `api.py` exists only for consumers that still resolve these names through
  `hipengine.server.api` (tests, scripts, and the engine/response code that
  imports them today). Once `_parse_chat_tool_calls_for_engine`,
  `_chat_message_from_parsed`, `_enrich_chat_tool_finish_details`, the
  streaming splitter call sites, request-validation block scanning, and the
  engine tool-prefix tokenization import the owner module directly — and no
  test or script imports a moved name from `hipengine.server.api` — the whole
  `from hipengine.server.chat_output import (...)` block can be deleted. Do not
  keep it as a permanent re-export layer.
