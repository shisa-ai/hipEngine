# MX-1's Q5_K gate/up gap closed: layer 2 is admissible, and the row's status was stale

## Summary

MX-1's recorded limit was: *"Part C covers 13 of the 48 gate/up layers (all Q4_K); the
two Q5_K gate/up tensors (layer 2 and one other) are not in the real-activation sample."*

**Measured. Layer 2 is the only Q5_K gate/up layer, and it is admissible.**

| quantity | value |
|---|---:|
| `swiglu_error_f16_vs_f32` rms_abs | **1.0677e-05** |
| `swiglu_error_bf16_floor_vs_f32` rms_abs | **6.7016e-05** |
| ratio (rms) | **0.159 -> 6.3x below the floor** |
| max_abs, candidate vs floor | 3.317e-04 vs 3.362e-03 -> **10.1x below** |
| `candidate_below_bf16_floor` | **true** |
| activation overflow | 0 |

310 of 512 experts, 10,240 rows. The Q4_K layers span 0.092-0.179, so layer 2's 0.159
sits **inside that range** - Q5_K is not an outlier.

## The row's status was stale

MX-1 says *"Gate/up has weight coverage only (no real gate/up input capture yet)"*. That
is not true: `part_c_real_activation_gate_up` **exists in the artifact** and does use a
real capture (`/tmp/q4k-gate-up-input-general_en-p4096.npz`, sha256 `bbdc4c08...`). The
true remaining gap was the narrower Q5_K one quoted above, now closed.

Also, the artifact's "layer 2 and one other" is wrong: scanning all 4 shards gives 47
Q4_K + **1** Q5_K gate/up layers.

## A limitation this run exposed, applying to Part C as a whole

The capture holds **one** activation block: `x_bits` is `(10240, 2560)`, with a single
`expert_start` array and one `case_id`. It is **not per-layer**. So **every layer Part C
measures - including this run's layer 2 - is measured against the same MoE block input.**

That makes Part C a **shared-activation operand-error budget**, not a per-layer-exact
measurement. It does not invalidate the budget: the question is how F16 operand rounding
compares to the BF16 rounding already in the path, which is dominated by the weights and
the activation *distribution*. But the per-layer figures should not be read as if each
layer saw its own hidden state. I record this because the existing artifact does not
state it, and a reader would reasonably assume otherwise.
