# Speed probe fails closed and records full trajectories

## Summary

Review feedback on the speed campaign's probe: it recorded nonfinite logits
without failing, continued past failed arms and still returned success,
saved only the first four output tokens, and never stated its decode
seeding. All four fixed.

## Changes

- campaign-artifacts/c1-k-sweep/dense_vs_dms_speed_probe.py:
  - _check_finite: any nonfinite decode logit aborts the arm (the
    single-arm subprocess exits nonzero; the finiteness gate is
    per-step with step indices in the error).
  - _arm_row: records the full output_tokens trajectory, its sha256
    (int64 token bytes), the decode seeding (last prompt token re-fed,
    with the constant-across-arms note), and keeps first_output_tokens
    for compatibility with existing part readers.
  - Orchestrator: tracks failed arms, writes status arm_failed, and
    exits 1 when any arm failed.
- tests/test_dense_vs_dms_speed_probe.py: five CPU tests pinning the
  finiteness gate (pass and fail-closed with step indices), the
  trajectory/seed record, and the orchestrator's nonzero exit on a
  failed arm (fake subprocess) plus zero when all pass.

## Validation

- 5/5 CPU tests green; probe parses and CLI verified.
- On-device smoke (GPU0/W7900, dms-int8, 512 tokens, 4 steps): full
  trajectory [685, 279, 1120, 314] — matching the earlier short-context
  sweep's first four tokens for the same arm (cross-run agreement) —
  sha256 and decode_seed recorded, status diagnostic_not_a_benchmark,
  exit 0.

## Next

- The previously published short-context sweep and 16K artifacts were
  produced with the pre-fix probe; their passing arms are unaffected
  (all finite, all succeeded), but future A/Bs record full trajectories
  by default and fail closed.
