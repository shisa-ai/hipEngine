# llama.cpp PR 29510 kv_rows review: penalty absent in hipEngine

## Summary

Reviewed llama.cpp PR #29510 (`llama + CUDA: flash_attn_ext_rows (fix unified
kv for multi-seq)`, am17an, draft, reviewed 2026-11-08 at PR head
`5b5ff4c98634d14fb3f225af6ef837cb62171bea`; full diff saved during review at
`/tmp/pr29510.diff`, 3436 lines, 50 files). Decision: **do not port**. The
penalty the PR removes does not exist in hipEngine: our attention already
iterates only each sequence's own live KV through per-sequence page tables
(`KVLiveSpans`) and varlen segment bounds. The PR's `kv_rows` indirection is
the row-granular form of the paged indirection hipEngine ships on every
attention path, for every supported model family.

What the PR fixes in llama.cpp: with the unified KV cache (`-kvu`), every
attention op receives the whole cache as K/V (up to the full cache extent,
e.g. 400K cells) plus a dense `[n_kv, n_tokens]` mask that -INFs out other
sequences' cells. Multi-seq batches pay host-side O(n_kv x n_tokens) mask
construction and kernel-side mask bandwidth/tile scanning over the full
extent although each sequence needs only its own cells. The PR adds
`ggml_flash_attn_ext_rows`: per-slice cell lists `kv_rows [n_kv_rows,
n_slices]` built from new per-sequence cell bitsets, a compact per-slice
mask, and K/V row gathering in the CUDA MMA-f16 kernel, so the KV loop runs
over the longest sequence's cell count (padded to 256) instead of the cache
extent. Reported by the PR author on RTX Pro 6000, 4 x 99,936-token prompts,
400K cache, Q8_0 models: Gemma-26B-A4B prefill 2982.14 -> 8625.75 t/s
(2.89x), decode 273.42 -> 288.11 t/s (1.054x); Qwen3.8-27B prefill
1106.13 -> 2778.22 t/s (2.51x), decode 90.29 -> 102.08 t/s (1.131x).
These are the PR's numbers, not hipEngine measurements.

Why it does not apply to hipEngine:

1. **No dense cross-sequence KQ mask exists.** No `kq_mask`/`attn_mask`
   tensor appears in any paged attention kernel or wrapper. Causality is
   `visible_len = min(context_len, position + 1)` plus varlen segment
   bounds; the only masks are per-slot `evict_mask` liveness within one
   sequence's own spans (DMS/SWA) and scheduler active-row masks for batch
   width padding, which never enter KV iteration.
2. **Decode already iterates per-sequence live tokens only.** The batched
   kernel `qwen35_paged_full_attn_decode_context_tensor_batch_kernel`
   (`hipengine/kernels/hip_gfx1100/attention/paged_attn_decode.hip:358`)
   reads `context_len_ptr[row]` and
   `row_block_table = block_table + row * block_table_len`, then loops
   `token < context_len`. The shared pool's total size never enters the
   loop. The production GGUF resident runner builds exactly this layout
   per slot (`hipengine/runtime/qwen35_gguf_runner.py:2237-2272`,
   `_full_attn_shared_batch_spans` at :5700 -> `KVLiveSpans.paged_uniform`).
3. **Multi-seq prefill is already compact varlen.** `CompactPromptSlab`
   packs c>N prompts into one slab and attends block-diagonally through
   `cu_seqlens_q/k`: native
   `qwen35_paged_full_attn_prefill_varlen_gqa_gate_fp16_kernel`
   (`paged_attn_decode.hip:2859`, per-row page table + segment bounds) and
   AOTriton `attn_fwd_compact_varlen`
   (`hipengine/kernels/hip_gfx1100/attention/aotriton_wrap.py:124`). See
   `docs/reference/PREFILL.md` "Compact c>N slab".
4. **Even the dense-span consumers are single-request.** `paged_dense`
   spans in `hipengine/runtime/laguna_kv.py:3229` (scalar live count, one
   request's capacity backed by global physical pages) and
   `hipengine/runtime/surya.py:696` ("One immutable view per request") never
   mix sequences; `evict_mask` marks eviction inside one sequence.
5. **DMS is already beyond row lists.** `dms_compact.py` attention consumes
   token-granular compact extents (`base_offsets` + `live_counts`,
   per-head-variable spans), which is what the PR author says `kv_rows`
   may grow into ("rows are pages of size 1 at the moment, but that can
   change").
6. **The unified-cache benefits the PR preserves are already ours.**
   Shared physical pools without per-sequence capacity partitioning
   (`GlobalKVPoolSet`/`GlobalKVPool`, C2), radix prefix sharing (C2-4), and
   COW are shipped; `docs/reference/KVCACHE.md` records measured c8
   aggregate HTTP wall +59.27% over serial c1 on the C2-6 global-pool route
   (prior measurement, cited as corroboration, not re-measured here).

Model coverage: the compact design is model-agnostic by construction.
`KVLiveSpans` is the mandatory ABI for every paged KV write and attention
decode kernel (AGENTS.md invariant; `docs/reference/KVCACHE.md`), and the
Qwen3.5/3.6/3.8 PARO and GGUF, Gemma4/Laguna SWA, Qwen4-exp QSA, Surya, and
DMS paths all consume per-sequence spans. "Works across all supported
models" is already true of the mechanism the PR introduces.

PR caveats that further weaken a port case: still draft; ggerganov objects
that the restructured mask breaks Metal's -INF block-skip fast path and
asks for `kv_rows` as an additive input instead; the CUDA `kv_rows` path
requires NVIDIA Turing+ MMA and explicitly excludes AMD MFMA
(`fattn.cu`: `GGML_CUDA_CC_IS_NVIDIA(cc) && turing_mma_available(cc)`), so
there is no HIP kernel to lift; a graph-reallocation regression needed
follow-up PR #31570.
