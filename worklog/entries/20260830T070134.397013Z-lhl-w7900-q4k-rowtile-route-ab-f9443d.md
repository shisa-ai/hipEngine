# W7900: the rowtile env A/B was invalid, and the position bias it measured instead
## Summary

The A/B I designed straight from the rows-scaling trace was invalid, and the reason is now pinned in
code and on the GPU. `HIPENGINE_GGUF_Q4K_ROWTILE` does not steer the AR decode route, so the
four packets I ran compared the same kernels twice. The result is a null with a known cause, not
evidence about the route. The byproduct is the more useful number: process position is worth 2.2% at
width 2, measured rather than assumed.

## Changes

- `tests/test_runtime_gguf_linear_q4k_rowtile_knob.py` (9 CPU-only tests) - env truth table, the
  resolver's independence, rows=1 outside the route, the 2..8 cap, the three consumer sites, and the
  precedence chain session > env and kwarg > session.
- `docs/BENCHMARK.md` - two subsections: the harness exit code is a verdict not a write receipt, and
  session pinning beats env knobs on the server route.
- Artifact `2026-08-30-w7900-q4km-ar-rows-scaling-kernel-trace.json` gains `route_ab_invalid` with
  the medians, the invalidity, and what would actually answer the question.

## Validation

1. Read the dispatch: for `LAYOUT_GGUF_Q4_K_T16`, `resolve_gguf_linear_dispatch` returns
   `t16_wmma_prefill_bf16_bf16_out` for every `rows > 1`, env or not. My test asserted the knob
   must change the dispatch there and failed - correctly, but it was testing the wrong function. The
   flag is read at the launch sites: `launch_gguf_linear:2447`, `launch_gguf_linear_pair:4182`,
   `launch_gguf_linear_pair_silu:4658`.
2. Ran ON,OFF,OFF,ON at width 2, pure AR, 20 cells per packet, `mtp_engaged=0/40`. Medians 32.028 /
   31.675 / 31.518 / 31.332; mode means 31.680 vs 31.597 (+0.26%), sign flipping between position
   pairs. Process position is worth 2.2% (same setting, first vs last slot), which turns the
   changelog's "~1-2 points of drift" rule of thumb into a measured quantity.
3. Before calling it a null result, traced the OFF run: 164,798 rowtile launches vs 164,460 at the
   default. Identical route, so the env never reached it. Precedence is kwarg > session > env
   (`gguf_linear.py:1516`) and the resident serving route opens the session, pinning the flag. The
   comment that env "still controls the default for plain bench/diagnostic invocations" was the
   warning; I read it as applying to one sibling flag instead of the pattern.
4. The same re-read settled a control worry from the trace: every kernel in both traces runs on one
   worker thread (869469 at width 1, 873535 at width 2; the other thread has 322 launches / ~6 ms),
   so the width-2 rowtile kernels cannot be the nominal MTP arm leaking in on its own thread.
5. Process note: my first commit went through because `worklog.py check` was piped into `tail`,
   so the shell took its exit status and the chain continued past a validation error (missing `##
   Validation` heading). Validator output must be checked by status, not by eye.
