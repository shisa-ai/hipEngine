# Evaluate exact-shape Moonshine encoder graph cache

## Summary

Evaluated and rejected a bounded exact-shape encoder+handoff+cross-KV CUDA graph cache. Keying by exact `(sample_count, encoder_frames)` avoided the known GroupNorm padding error and retained exact text, but complete E2 moved only 39.207/46.310→39.204/46.300 ms P50/P95 (0.008%/0.023%). This is a null result and cannot justify graph memory, first-seen capture cost, LRU complexity, or production lifecycle surface. The full prototype was removed.

## Changes

- Prototyped a bounded ordered LRU of exact-shape encoder-chain graphs, including cache hit/miss/eviction telemetry, first-use capture outside the driver's internal timing, exact graph selection, and exec-before-graph teardown.
- Added a CPU LRU/eviction/ownership test. The existing one-fixture encoder graph and GroupNorm no-padding contract remained unchanged.
- Ran an actual 20-fixture alternating screen, then removed all source and test changes.
- Published `benchmarks/results/2026-08-27-cuda-sm120a-moonshine-exact-shape-graph-cache-rejected.json` and one benchmark changelog row. The ignored prototype diff and observations are pinned by SHA-256.

## Validation

- CPU driver bundle passed 8/8 with the prototype, including exact LRU order, hit/miss counts, and exec/graph destruction on eviction.
- 20 FLEURS-through-EOU fixtures, two warmup traversals, five alternating iterations, 100 observations per route: baseline 39.207145/46.309980 ms; cache 39.204149/46.299538 ms P50/P95. Saved only 0.002996/0.010442 ms (0.00764%/0.02255%); all 200 observations exact.
- Verified source/test diff was empty after prototype removal. Compact JSON parse, raw observation/prototype-diff hashes, worklog check, and `git diff --check` passed.

## Next

- Do not retain exact-shape graph caching. Treat the encoder as device-work bound and continue with family/kernel candidates. Preserve the no-padding GroupNorm rule.
