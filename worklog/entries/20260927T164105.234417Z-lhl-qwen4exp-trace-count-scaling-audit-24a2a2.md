# Trace-scaling audit: raw-trace counts left at 2x

## Summary

Audited every durable artifact this session produced against
`role-analysis.json` `exact_role_kernels` as the 1x authority. The ms figures are
correct everywhere. A second, previously unreported defect affects the **count**
columns: wherever `ms` was halved from the raw 2-repetition rocprofv3 CSV, the
launch count `n` was left at the raw 2x value, in an artifact whose own header
says "at 1x".

Three sites were affected, not one:

| site | field | was | corrected to | 1x authority |
| --- | --- | ---: | ---: | ---: |
| `2026-09-27-qsa-prefill-grid-resolution/resolution.json` | 9 `n` fields | 72/48/48/96/48/96/96/48/96 | 36/24/24/48/24/48/48/24/48 | `exact_role_kernels` rows |
| `2026-09-27-qsa-prefill-grid-resolution/README.md` | family table + "24 launches each over 24 QSA layers" | 72... | 36... | same |
| `2026-09-27-moe-reduce-attribution/attribution.json` + `README.md` | `n` for the two conversion kernels | 768, 384 | 384, 192 | same |

The `2026-09-27-qsa-prefill-grid-resolution` artifact was corrected once already
in `5aaafb52d`, but that fix addressed the 2x `ms` error and the name filter and
left `n` at 2x. This entry completes it.

The "24 launches each over 24 QSA layers" sentence was wrong twice over: 24 is
the raw count (1x is 12) and the QSA layer count is 12, not 24. The model
metadata settles the layer count: `qwen4exp.attention.compress_ratios` is a
48-element list with a nonzero entry every fourth position (indices 3, 7, ...,
47), so the compressed-attention layers are 3, 7, ..., 47 - twelve of them. The
1x `qsa_sparse_attention_h256_wave_rows_f32_kernel` row count is 24 = 12 layers x
2 sparse chunks, which matches.

The count error is not cosmetic. `801.2 / 72` reads as 11.1 ms per launch; the
1x figure is `801.2 / 36` = 22.3 ms per launch, so a per-launch cost derived from
the published table is wrong by exactly 2x. Per-launch cost is the quantity the
kernel-level ranking is built on.
