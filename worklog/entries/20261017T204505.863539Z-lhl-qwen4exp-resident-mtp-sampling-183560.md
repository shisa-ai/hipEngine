# Bind sampled MTP to resident request transactions

## Summary

Resident Flash-Next MTP now consumes request-owned sampler state and publishes
selected/top logprobs only after the target/draft transaction commits. CPU
fixtures verify real speculative cycles, not silent K0 fallback. Public HTTP
sampling admission is still closed; task 17 and GPU qualification remain open.

## Changes

- Reuse the provider's early sampling/control validation at resident admission.
  Advertise scheduler `processed` semantics only on this provider's capability;
  no shared scheduler rules or other providers change.
- Pass the existing resident row's sampler and logical row index to the provider
  iterator. Clone it before each bounded step; restore RNG/history on rollback
  and close the cancelled iterator. Capture actual pre-cycle RNG counters for
  admitted sampling (one draw per output; forced-token controls remain rejected).
- Publish progress logprobs after commit, beside the committed IDs. Final finish
  details retain the actual MTP sampler mode. Existing output trimming removes
  EOS logprobs but keeps EOS in generated IDs and usage.
- Replace a stale bias-rejection fixture with an unsupported forced-token case.
  No kernel, model arithmetic, scheduler ownership or automatic-MTP policy change.
