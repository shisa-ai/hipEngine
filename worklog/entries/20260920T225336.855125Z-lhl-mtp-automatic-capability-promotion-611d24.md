# Automatic MTP on implementation capability, and a startup line that states the resolved route

## Summary

Lead directive: every artifact the kernels support is automatic-eligible for MTP,
and no measurement is required to promote it; the physical cell table is the
gate. The BF16 and MoE implementation declarations now carry
`automatic_eligible=True`, so an artifact with no retained row of its own is
promoted automatically instead of running AR until someone measures it.

This closes the user-visible half of `d603dcdbf`. That commit made capability the
admission axis, but automatic policy still stayed with retained evidence, so a
supported-but-unmeasured artifact (the Qwen3.8-27B `UD-Q4_K_M` file on gfx1151)
was admitted for explicit requests and refused for automatic ones. `hipengine
chat` never sends `speculative_mtp`, so every chat turn took the automatic route
and ran AR: 5.7-6.6 tok/s against 12.2-13.8 tok/s for the same server with an
explicit field. The startup summary reported `MTP enabled` throughout, because it
keyed on `serving_route` (configured and engine-capable) rather than on the
resolved plan.

## Changes

- `models/qwen35.py`: `automatic_eligible=True` on the four dense BF16
  declarations and the MoE BF16 declaration. Replaced the comment asserting
  "BF16 stays evidence-gated for automatic intent" with the capability rule.
- `models/qwen35.py`: no change to any retained evidence row. A cell whose own
  row records `..._measured_slower_than_ar_2026_09_06` keeps
  `automatic_eligible=false`, and because the resolver consults evidence rows
  before declarations, those cells stay out of automatic policy. The declaration
  is only reached by cells no row covers.
- `server/api.py`: new `_speculation_startup_text` reads the resolved plan and
  reports `MTP unavailable (<reason>)` when it refuses, the plan's selected depth
  rather than the configured default, and an `(unmeasured)` marker when the
  admission's reason is not `qualified_*`. Wired into `_log_pretty_startup_summary`.
- `server/api.py`: `_warn_unservable_mtp_budget` no longer attributes a refusal
  to "the retained evidence", which stopped being true when admission became
  capability-based.
- `docs/API.md`: replaced the "one exact scope is automatic" paragraph, which
  `d603dcdbf` had already invalidated, with the capability rule and the physical
  cell table that actually bounds automatic speculation.
- `docs/REFACTOR.md`: recorded that the screening guard now blocks BF16 screening
  (see below).

  so the automatic route has not been exercised on real hardware. Needs a restart
  with `--model /models/gguf/Qwen3.8-27B-UD-Q4_K_M.gguf` and a request that omits
  `speculative_mtp`; expect `used=true` at K3 and roughly 12 tok/s against the

  `MTP enabled, candidate budget 3 (unmeasured)`.
- **Screening interaction, identified by inspection and not yet exercised.** The
  `HIPENGINE_MTP2_SCREEN_UNQUALIFIED_CELLS` guard requires every request's static
  eligibility to carry `automatic_eligible=false`, which was an invariant only
  while automatic eligibility implied a retained row. Now it also blocks
  screening every BF16 cell the declarations cover. Cells with an explicit-only
  row remain screenable; cells with no row do not. Extending the campaign matrix
  therefore needs the guard keyed on the listed cell table rather than on
  `automatic_eligible`; recorded in `docs/REFACTOR.md` for the campaign owner,
  since removing the guard lets screening widen automatic intent.
- No throughput claim is made here beyond the AR-versus-explicit-MTP rates
  measured earlier in this session. The automatic route's rate is unmeasured.
