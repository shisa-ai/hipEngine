# The MTP c1c8 bench can select and record its KV cell

## Summary

`scripts/gguf_mtp_c1c8_server_bench.py` built `LLM` and `ServerConfig` without a
KV storage selector, so every artifact it produced ran the product default --
`/ready` reports `effective_kv_storage: bf16` for that construction -- including
the artifacts named `int8kv`. The previous entry recorded that finding; this is
the harness half of it.

The bench now takes `--kv-storage`, passes it to both objects, records the
requested and effective cell in `protocol`, keeps the server's whole
`kv_capability` block in the artifact, and **refuses to run** when the requested
cell did not resolve, naming the fallback reason. An artifact that cannot say
which cell it measured cannot be told apart from a default-KV run, which is
exactly how the mislabelled family got written.

## Changes

- `scripts/gguf_mtp_c1c8_server_bench.py`: added `--kv-storage` (default `None`,
  meaning the product default), threaded into `LLM(kv_storage=...)` and
  `ServerConfig(kv_storage=...)`; reads `/ready` once inside the client context;
  asserts the effective storage matches a requested one; records
  `protocol.requested_kv_storage`, `protocol.effective_kv_storage`, and a
  top-level `kv_capability`.

## Validation

- `tests/test_unit_gguf_mtp_c1c8_server_bench.py` -- passed.
- `--help` renders the new flag with its fallback semantics.
- The run that uses it is the corrected INT8 automatic sweep, which follows this
  commit.
