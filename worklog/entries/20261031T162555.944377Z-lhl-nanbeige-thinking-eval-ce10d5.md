# Nanbeige thinking evaluation protocol and memory prerequisite

## Summary

Evaluate Nanbeige on zbook / gfx1151 with thinking enabled and a user-required
65,536-token output allowance. Separate runtime parity from model quality.
No evaluation result or published-score reproduction is claimed yet.

## Changes

- Freeze paired smoke prompts before execution: integer multiplication, Python
  square function, Japanese capital, and the unchanged unified-memory explanation
  from the earlier verification. Use greedy generation for engine comparison,
  identical checkpoint/template/prompt IDs and an EOS-terminated output with
  `max_new_tokens=65536`. Preserve full reasoning and final answer separately.
- Reference: isolated Transformers process, loading the same FP8 checkpoint and
  explicitly dequantizing its per-output-channel weights to BF16. Compare prompt
  IDs and completed outputs; teacher-forced logits at matched prefixes are
  diagnostics, not a bit-equality assertion across different attention arithmetic.
  Never import torch into the hipEngine runtime.
- Instruction benchmark: full IFBench test set, official verifiers and
  prompt-level loose accuracy, with strict metrics also retained. Its published
  protocol uses temperature zero and scores answers after reasoning removal.
  Keep the same 65,536 output allowance and report truncation separately.
- The official Nanbeige card lists reasoning/agent benchmarks but no IFBench or
  IFEval score. The FP8 publisher's knowledge/tool suite is a different protocol.
  Therefore IFBench is an independent quality check, not a reproduction of a
  published Nanbeige score. Pin dataset/scorer revisions before running.
- Sources inspected:
  https://huggingface.co/Nanbeige/Nanbeige4.3-33B/blob/main/README.md,
  https://huggingface.co/primitive-ai/Nanbeige4.3-33B-FP8/blob/main/README.md,
  https://github.com/allenai/IFBench/blob/main/README.md.

## Validation

- Existing isolated environment `~/venvs/vibevoice-tts-oracle` imports torch
  2.13.0+rocm10.0.0 and Transformers 4.51.3; CUDA/HIP availability reports true.
  Actual reference model compatibility remains to be exercised.
- HIP reports 71,608,426,496 free bytes. From checkpoint dimensions, resident
  BF16 weights plus KV for 69,632 total tokens require approximately 75.5 GiB
  before scratch. The output allowance must not be reduced to fit.
- Existing llama.cpp servers: Muse-Glimmer on port 18080 (PID 70188), Shisa on
  port 8000 (PID 170976). Neither was stopped or altered. Requested user
  permission to stop them before allocating the evaluation model.
- Single-turn prompts do not need previous-turn reasoning preservation; the
  official card's `preserve_thinking=true` evaluation note matters for multi-turn
  comparisons. No claim of matching its undisclosed benchmark-specific recipes.
