# Separate DMS host prefix retention budget from dense state

## Summary

DMS host prefix snapshots include cold dense prompt KV, predictor planes and
trunk hidden rows in addition to compact decode state and recurrence. Sharing
the dense cache's 1 GiB ceiling forces long DMS snapshots to retain only a
partial prefix. The bounded-prefix repair prevents complete cache rejection,
but partial hits still require substantial suffix prefill.

## Changes

- Use a separate 4 GiB default host-byte ceiling for DMS prefix retention.
  Allocation is on demand, not a reservation. Dense retention stays at 1 GiB.
- Preserve `HIPENGINE_GGUF_PREFIX_RETAINED_STATE_BYTES` as an explicit override
  for either route, including smaller budgets. No new environment variable,
  KV format, arithmetic, or artifact-specific dispatch was added.
- Document the host-memory tradeoff in `docs/ENVS.md` and add CPU tests for
  defaults and explicit limits below and above the defaults.
