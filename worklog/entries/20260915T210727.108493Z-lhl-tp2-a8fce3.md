# tp2 device-timeline attribution via HIP events: wall is 99.7% device

## Summary

With `rocprofv3 --kernel-trace` blocked over the two-GPU TP2 session
(recorded earlier as a blocked loop iteration), the token wall is attributed
with HIP stream events instead: `scripts/tp2_stage_device_attribution.py`
runs the production graphed step's exact internal calls (metadata enqueue,
layer graph launches, production tail via `_finish_step`) with per-rank
event pairs recorded between the phases, and averages the per-rank device
spans over 32 measured decode steps after one production warmup.

Measured (W7900 + RX 7900 XTX, Qwen3.8-27B Q4_K_M, fingerprint a0b9749e2d7b,
max_sequence_length 256, production defaults: graphed schedule, device-side
exchange, sharded head):

- wall: 24.37 ms/step
- rank0: metadata 0.31, layers 22.73, tail 1.25 ms/step (device total 24.29)
- rank1: metadata 0.29, layers 22.67, tail 1.32 ms/step (device total 24.28)
- rank skew (layers): 0.06 ms/step
- host idle + sampling sync: 0.07 ms/step

## Findings

- The wall is 99.7% device execution. The host is no longer a lever: the
  graphed + device-exchange + sharded-head stack submits 128 graph launches
  per token and the device keeps both ranks 99.7% busy.
- The layer burst is 93% of the wall: 65 layers at ~350 µs/layer of graph
  execution on each rank (replicated attention/GDN, half-width MLP, and the
  in-graph exchange lockstep).
- Rank skew is negligible (0.06 ms/step): the lockstep exchange keeps the
  two GPUs aligned; there is no idle-gap lever between ranks.

## Changes

- `scripts/tp2_stage_device_attribution.py`: the event-based attribution
  child (diagnostic only; drives production internals, no engine changes).

## Validation

- Event semantics on this stack were probed first: re-recording an event
  updates its timestamp once the event has been synchronized (a 64 MiB
  async memset measures a stable ~0.14 ms span across reused and recreated
  event pairs). Two earlier child drafts produced garbage purely from
  unit bugs (treating `event_elapsed_time_ms` output as seconds, and
  querying an event before its record completed: HIP error 600), not from
  event-semantics limits.
- The child's measured steps run the production tail and sharded-head
  argmax; the numbers above were reproduced across four runs of the child
  (the first two exposed the unit bugs).

## Next

floor: per-kernel attribution of one rank in isolation (exchange disabled,
per the recorded rocprof mitigations) to find launch gaps and
attention/GDN/GEMV efficiency at rows=1; then Packet 4 item 5's rank-local
shape tuning through the four-axis registry.
