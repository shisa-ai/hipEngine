# XTX capacity: rescale the long-context pressure gate and run XTX admission pressure

## Summary

Packet 1's remaining item — atomic admission against complete claims with
bounded rejection and exact reclaim — ran on the XTX through the long-context
pressure gate, rescaled to card-feasible contexts. The gate gained
`--required-contexts` (threaded through pool plan, workload specs, pressure
specs, and admission metadata), lazy workload defaults, KV-policy plumbing, and
a reference session that chunks with the served `--prefill-chunk-tokens` so
both sides take identical dispatch routes. The matched BF16 run at contexts
512/1024/2048 passed every substantive gate: all six workloads (route
evidence, 10/10-class exactness, SLOs), the pressure contract (live row
completed while the 1024-token candidate received retryable 429 `engine_busy`
with exact admission metadata requested=5 vs capacity=39 units), pool
shrink/regrow with fresh block ids, graph rebind evidence, memory recovery,
and exact ownership drain.

## Changes

- `scripts/gguf_long_context_pressure_gate.py`: context parameterization
  (`_context_label`, plan fields `contexts`/`mixed_contexts`/
  `pressure_live_context`/`pressure_reject_context`), `--required-contexts`,
  empty `--workloads` meaning all, `--kv-storage`/`--kv-scale-dtype`/
  `--kv-scale-granularity` plumbed to both `LLM` construction kwargs and
  `ServerConfig`, reference session `prefill_chunk_size` matched to the served
  chunking, context-derived regrow workload naming.
- `tests/test_gguf_long_context_pressure_gate.py`: rescale test for the
  small-card plan/workload/pressure surface and degenerate-context rejection.
- XTX findings recorded along the way: the dual-session exactness harness does
  not fit at 3.1K max-sequence (prepared LLM 20.677 GiB tracked with the exact
  packed env + reference session ~3.3 GiB > 24 GB card), INT8 KV forces
  `serial_fallback` in the continuous owner (documented fail-closed: deferred
  dynamic KV and packed c>N kernels require BF16), and the served-vs-reference
  chunk mismatch surfaced an unqualified T16 F16/rocBLAS pair dispatch at
  1024/2048-row reference chunks on gfx1100.
