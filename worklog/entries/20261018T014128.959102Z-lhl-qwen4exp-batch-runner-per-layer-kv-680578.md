# One batch KV cache per QSA layer

## Summary

`Qwen4ExpGGUFBatchRunner` allocated **one** paged K/V cache and gave every QSA
layer that same cache. The c1 runner keeps one `Qwen4ExpDenseAttentionState` per
QSA layer, so the batch path was wrong for any model with more than one QSA
layer — the production Qwen3.8-Flash artifact has 12 of 48 layers. Every QSA
layer wrote its keys and values at the same physical block and position, so the
second layer overwrote the first, and `import_prefilled` copied layer by layer
into one buffer, leaving only the last layer's state.

The defect was invisible in the existing GPU suite because the synthetic fixture
geometry has exactly one QSA layer. It was found while writing
`scripts/qwen4exp_batch_runner_real_smoke.py` for a real-artifact run, not by a
test.

## Changes

- `hipengine/runtime/qwen4_exp_batch_runner.py`
  - `attention_states: tuple[Qwen4ExpBatchAttentionState, ...]` replaces the
    single `attention_state`, allocated `cfg.qsa_layer_count` times. Each index
    state binds to its own layer's attention owner.
  - `_zero_slot` memsets every layer's key and value cache, not only the first.
  - `_execute_step` prepares every layer's spans and passes
    `attention_states[qsa_binding.qsa_state_index]` to the layer mixer.
  - `import_prefilled` validates geometry and disjointness per layer against
    that layer's own destination cache, and `_copy_prefilled_state` copies into
    `attention_states[layer]`.
  - `_require_attention_states()` replaces `_require_attention()`.
- `tests/_qwen4_exp_batch_fixtures.py`: `TWO_QSA_LAYER_TYPES` and
  `two_qsa_config()`, a four-layer geometry with two QSA layers.
- `tests/test_unit_qwen4exp_batch_runner.py`:
  `test_each_qsa_layer_owns_its_own_paged_kv_cache` asserts two distinct
  attention owners and two distinct index owners are dispatched, that both are
  prepared for the stepped rows, and that admitting a slot memsets
  `2 * layers * blocks_per_request` K/V blocks.
- `tests/test_gpu_qwen4exp_batch_runner.py`:
  `_build_weights` takes a config, `_build_bundle` / `_release_bundle` /
  `_module_monkeypatch` are extracted so the new `two_qsa_model` fixture shares
  them, `_slot_kv` honours its `layer` argument, and
  `test_two_qsa_layers_keep_separate_caches_and_match_c1` checks distinct
  caches, per-layer cache bytes against two independent c1 runners over four
  steps, and logit parity.
- `scripts/qwen4exp_batch_runner_real_smoke.py`: the state digest hashes every
  QSA layer's K/V instead of only the first.

RED evidence, reverting only the per-layer allocation (one shared cache) with
the two-QSA-layer geometry:

- unit: `test_each_qsa_layer_owns_its_own_paged_kv_cache` fails on "each QSA
  layer needs its own K/V owner" — one distinct owner is dispatched for two
  layers.
- GPU: `test_two_qsa_layers_keep_separate_caches_and_match_c1` fails at
  `first is not second`; the cache-byte assertion is independently RED because
  the shared cache leaves layer 0 holding layer 1's keys, measured 0.1826 max
  deviation from the c1 reference against `STATE_ATOL = 5e-2`.

Measured directly on the shared-cache shape (probe, not a committed test):
`batch layer0 vs c1 layer0 = 0.182617`, `batch layer1 vs c1 layer1 = 0.000000`
— the second import overwrites the first layer's blocks.

## Next

The synthetic fixture cannot see cache-content bugs through the logits: zeroing
every QSA K/V cache before a c1 or batch step leaves the logits bit-identical at
weight scale 0.1, and raising `attn_output` to scale 2.0 did not change that, so
the mixer's contribution is dropped at the BF16 residual write rather than being
rounded away. Per-layer cache bytes are therefore the only RED signal here and
are asserted directly. Making the fixture's QSA mixer reach the logits is a
separate test-infrastructure task.

No serving wiring, engine, dispatch, or doc change. `docs/REFACTOR.md` untouched
because nothing here is a temporary flag or fallback path.
