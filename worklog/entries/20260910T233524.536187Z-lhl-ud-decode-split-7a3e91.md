# Decode lever 2b: split/scale IQ local32 owners - the remaining strict population

## Summary

The strict-IQ decode population after the XS/NL owners is dominated by
the split/scale family: IQ3_S (K_S 3.00 ms/tok over 15 launches, K_M
0.82 ms/4), IQ3_XXS (K_S 0.83 ms/5), IQ2_S (0.22 ms/1) and IQ2_XS
(0.21 ms/1); Q3_K (2.41/1.41 ms) stays outside - its superblock layout
does not map to the lane geometry. One templated kernel
(gguf_iq_split_local32_gemv_kernel<Q, WAVES>, Q in {2,4,5,6}) transfers
the XS/NL owner's geometry: each lane's 8 contiguous k map to exactly
one 8-element slot (IQ2_S/XS) or two 4-element grid slots (IQ3_S/XXS)
of its 32-element group, so the per-lane payload is a handful of
metadata bytes per column per 256-block. Grid staging follows the
strict kernel's own measurements: iq3_grid (2 KB) and iq3_xxs_grid
(1 KB) stage in LDS, IQ2_XS_GRID_PACKED (1 KB) stages, iq2_s_grid
(8 KB) stays __constant__ (staging measured -10.6% on the strict
owner).

## Defects caught by the evidence process

1. IQ3_XXS grid index is per FOUR elements (b[2+g*8+j/4]), not per
   slot - the first cut read one index byte per lane and matched the
   strict host model it was written against instead of the kernel
   (both wrong the same way). Caught by the one-hot elementwise probe
   (k=0..3 exact, k>=5 wrong); the element-to-element permutation
   analysis showed no clean remap, which localized the bug to the
   operand rather than the mapping.
2. The committed natural-prompt probe had gone stale: it pinned
   all-strict vs an XS-only candidate (arms that no longer match any
   production boundary), and its all-strict incumbent has a NaN
   fragility on rare self-generated prompts (K_M seed 11). The probe
   now derives both arms from the shipped policy (candidate =
   shipped, incumbent = shipped minus the gated quants) and generates
   the natural prompt under the incumbent so the probe is stable
   regardless of what the candidate adds.

## K_M tail: per-slot decode pins (bisection record)

The warned-about local32 tail compounding materialized on K_M: with
all four quants routed the tokenized category suite failed the
5e-2 pooled max (seed 7: 5.19e-2, mixed_ja_en single-position
outlier, p99 2.8e-3; pinning the three ffn_down slots still left
seed 11 at 1.785e-1 in mixed_ja_en with p99 3.4e-3). The fix follows
the prefill Q3_K precedent (layers.0.ffn_up): a decode-side strict
slot table (GGUF_IQ_DENSE_DECODE_STRICT_SLOTS, its own contextvar,
keyed by the same (file_type, preset) identity) pins all four K_M
IQ3_S slots to the strict per-row GEMV. K_M's IQ3_S population is
0.82 ms/tok (4 launches); K_S's is 3.0 ms/tok - the route's value is
K_S, and K_S (a different artifact identity) keeps it. K_M category
gates with the pins: see below.

K_M category gates with all four pins: PASS on all three runs
(mean 1.666e-4, p99 2.731e-3, max 3.947e-2, top-1 99.57%) -
bit-identical to the NL-round admitted state, which is itself the
end-to-end proof that the pins engage (the unpinned state measured
5.19e-2 on the same fixture). The category gate is seed-independent
(fixed fixture prompts extended by the incumbent's greedy
continuation), so the per-seed runs are reruns of one measurement.
K_S category gates: PASS (mean 9.96e-5, p99 1.41e-3, max 6.60e-3,
top-1 99.83%).

Final decode numbers (GPU1 XTX, 512/128, median of 3):
- K_S 26.77 -> 28.41 tok/s (+6.1%): IQ3_S 3.0 ms/tok + IQ3_XXS 0.83 +
  IQ2_S/XS 0.42 strict population moves to the local32 owner.
- K_M 27.67 -> 27.70: the four IQ3_S slots stay strict (0.82 ms/tok
  population, tail-gated), so K_M is unchanged within noise.
- Prefill unchanged (902 / 889 tok/s).
- Campaign cumulative: K_M 26.20 -> 27.70 (+5.7%), K_S 25.53 -> 28.41
  (+11.3%). Remaining strict decode population: Q3_K only (K_S 2.41,
  K_M 1.41 ms/tok).
