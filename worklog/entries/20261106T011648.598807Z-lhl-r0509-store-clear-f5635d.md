# Drain all provider checkpoints after a release failure

## Summary

Apply the same independent-owner drain rule to the provider checkpoint store:
a failed first release must not skip later payloads or retain dead lookup keys.

## Changes

- Detach entries before clearing payloads, attempt each release, then re-raise
  the first failure with later failures recorded as notes. No retry of an
  already-attempted idempotent release is introduced.
- This does not implement R0509's shared budget or public pressure validation.
