# Project packed GGUF NVFP4 rows on gfx11

## Summary

Add the direct GGUF NVFP4 projection primitive for `gfx1100` and `gfx1151`. It reads weights in their original GGUF layout and applies the expert's outer scale at the FP32 output. Model execution does not yet call this primitive.

## Changes

- Register `linear/gguf_nvfp4/gemv_f32_f32_out` for both gfx11 backends. Each wave projects one output from raw 36-byte blocks without widening or repacking the bank. Multiple FP32 input rows are supported.
- Decode the split low/high nibbles and unsigned E4M3 block scales using the in-tree GGUF CPU decoder's contract. No external kernel source copied.

## Validation

- `OPENBLAS_NUM_THREADS=1 python -m pytest -q tests/test_gpu_gguf_nvfp4_gemv.py`: RED on `epyc` for the missing primitive; GREEN on Radeon Pro W7900 (`gfx1100`) and on `strixhalo`, Radeon 8060S (`gfx1151`). The three shapes cover single and multiple input rows, non-aligned output widths, the two checkpoint expert input widths, special scale bytes, and positive/negative outer factors. Results stayed within the FP32 FMA/reduction error bound against FP64 reference dots; all argmax results and the KL smoke gate passed.
- On Strix Halo, use `env -u HIP_PATH -u ROCM_PATH -u HIP_INCLUDE_PATH -u HIP_LIB_PATH` with `~/mambaforge/envs/therock/bin` first in `PATH`; inherited ROCm paths pointed the compiler at a stack without its device bitcode. No machine configuration changed.
- After warming the build on each host, saved `hipcc --version` and ran `HIPENGINE_REQUIRE_CACHED_BUILD=1 HIPENGINE_COMPILER_VERSION_FILE="$PWD/hipcc-version.txt" rocprofv3 --kernel-trace --output-format csv --output-directory "$PWD/nvfp4-trace" -- python -m pytest --tb=short -q tests/test_gpu_gguf_nvfp4_gemv.py`. Both traces show `gguf_nvfp4_gemv_f32_kernel` with positive durations for all three shapes. This is a dispatch smoke, not a benchmark.
