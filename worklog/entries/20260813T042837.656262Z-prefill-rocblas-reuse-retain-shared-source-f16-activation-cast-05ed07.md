# Retain shared source-F16 activation cast

## Summary

Retained an exact shared-activation boundary for full-attention K/V pairs when
both operands already route through bounded source-F16 rocBLAS. The pair owner
casts the common BF16 norm input once, then executes the same two sequential
T16 dequantize/GEMM/output-cast chains. It removes 16 launches at M512, reduces
the verified cast sub-window and total kernel sum, and changes no allocation,
projection arithmetic, output, decode, or MTP path.

## Changes

- Added an explicit `cast_activation` control to the internal bounded T16
  launcher; singleton behavior remains unchanged by default.
- Added a mixed-Q4/Q6-capable pair route only when both projections are admitted
  by the existing bounded policy and have matching in-place behavior. Mixed
  candidate/exact and mismatched in-place pairs retain singleton fallback.
- Added dispatch coverage proving one cast-enabled and one cast-disabled launch
  with unchanged shape-scoped solution index selection.

## Validation

- Cached XTX M512 candidate/control traces: activation casts **136 -> 120**,
  total dispatches **3,190 -> 3,174**, cast kernel sum **3.638709 -> 3.442917 ms
  (-5.38%)**, and all kernels **579.815269 -> 578.389973 ms (-0.246%)**.
  Dequant/GEMM/output-cast counts remain exactly **552/552/552**.
- Seven-pair full-prefill A/B is small/noisy as expected: XTX
  +0.004%/+0.023%/+0.101% and W7900 +0.066%/-0.036%/+0.127% at 512/1K/4K;
  all output IDs match, and tracked peak bytes are unchanged.
- Full ten-prompt/four-category expanded-prompt quality: **330/330 top-1,
  KL max 0, deterministic candidate repeats**, with exact free-running IDs.
