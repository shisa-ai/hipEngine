# Startup probe prices its width; a failed eager startup exits

## Summary

The startup scratch probe now prices the width it is about to allocate, retries at one
slot when a wider allocation fails, and a fatal eager-startup failure ends the process
instead of leaving it listening unready. The probe width widening from the previous
unit is reverted: it demanded the route width in full-context resident sessions, which
this box cannot hold.

## Changes

- Reverted the probe widening (`_startup_scratch_probe_batch_size`): the probe runs at
  the configured request width again. Unset `--max-active-requests` means the probe
  stays at one request.
- Added `_startup_probe_width_reduction`: before a width>1 probe runs, it prices one
  session at the auto-sized context through the new public
  `Qwen35GGUFGenerator.resident_capacity_estimate` and reduces the probe to one slot
  when `width * per_session_bytes` exceeds usable free memory. The reduction is
  recorded in `startup.checks.scratch_probe` (`status: "reduced"`, `width_reduction`)
  and in the `/ready` diagnostics, so a warmup that did not run at the route width is
  visible rather than silent.
- Added a retry: a probe that raises at width>1 is retried at width 1
  (`failed_attempts`), and only a width-1 failure is fatal.
- Added `StartupFailure` and `fail_startup`: `engine_create`, `resident_prepare`,
  `raw_warmup`, and `scratch_probe` record their diagnosis and then raise out of the
  ASGI lifespan. Uvicorn turns a lifespan startup exception into `sys.exit(3)`, so the
  supervisor sees a non-zero exit instead of a process answering 503.
- Added the new probe tests, updated the failed-startup test for exit semantics, and
  updated `docs/API.md`, `docs/ENVS.md`, `docs/reference/AGENTIC.md`, and a
  `docs/REFACTOR.md` entry for the remaining warmup limitation.

## Validation

- `pytest tests/test_integration_server_api.py`: 671 passed (includes the 4 new/updated
  probe and startup-exit tests).
- `pytest tests/test_unit_qwen35_gguf_capacity.py tests/test_integration_qwen35_gguf_resident_prerequisites.py tests/test_unit_chat_cli.py`: 110 passed.
- `python3 scripts/docs/check_all.py`: all 4 gates passed.
- Root cause of the reported startup OOM, from the run's own log: the probe asked for
  `max_batch_size=4`, the capacity estimate prices **one** session, and each probe slot
  is its own resident session with preallocated KV pages and workspace lease. The
  estimate therefore said a 100864-token context fitted, while four such sessions could
  not, and the ladder's four attempts (100864, 50432, 25088, 12544) all failed.
- Not verified: the restart measurement of this change on the box. The probe reduction
  path is covered by fake-based tests; the real server restart and the cold MTP TTFT
  measurement are the next step in this unit.
