# Tie provider checkpoint lifetime to target eviction and adapter close

## Summary

Provider checkpoints were not cleared by adapter shutdown and were independent
of target-prefix eviction. Both paths now release checkpoint payloads exactly
once. If an MTP request matches target KV but no usable provider checkpoint,
it performs a normal prefill rather than silently losing MTP.

## Changes

- Adapter `close()` clears its checkpoint store before provider teardown.
- Target prefix eviction also discards the matching provider checkpoint.
- Before prefix reuse for a speculative request, validate provider checkpoint
  availability against the exact prefix and physical block ids. A missing
  provider checkpoint records `provider_checkpoint_unavailable` and recomputes
  the prompt while preserving speculative intent.
- Tests assert release at eviction time, idempotent shutdown, and preserved MTP
  intent on an unusable target-only hit.
