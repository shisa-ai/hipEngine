# matched llamacpp comparison establishes the real tp2 gap

## Summary

The current gap is now established by a matched measurement rather than an
inherited number, and it is **smaller than the recorded reference implied**.

Same host, same model bytes (`7b2aec3b…`), 512-token prompt, 128 decode tokens,
f16 KV, c=1, three repetitions, prefill and decode measured separately:

| engine | transport | prefill tok/s | decode tok/s |
| --- | --- | ---: | ---: |
| llama.cpp TP=2 | `-sm tensor -ts 1/1`, NCCL allreduce | **1328.4 ± 10.5** | 41.46 ± 0.46 |
| llama.cpp TP=2 | `-sm tensor`, internal q8 allreduce, P2P on | 1321.3 ± 12.1 | 41.38 ± 0.38 |
| hipEngine TP2 | rank-local bulk prefill, host-staged exchange | **1035.2** | 39.17 |
| llama.cpp TP=1 | single device | 934.8 ± 2.9 | 30.39 ± 0.04 |

**Prefill deficit 28.3%** (needs +28.3% throughput, i.e. ~**109 ms** off a
494.6 ms prefill), **decode deficit 5.9%**.

The previously recorded llama.cpp TP=2 reference of **1474.6 tok/s does not
reproduce.** The same build (`15995a1`), model bytes and host measure 1328.4, and
the number stays in the 1321-1328 range under the internal-allreduce and P2P
flags the original note attributes to it. That note's **TP=1 companion does
reproduce** (934.8 against a recorded 941.8, -0.7%), so this is specific to the
tensor-split arm, not a host-wide clock or thermal difference. 1474.6 is now
marked unreproduced rather than used to size the work.
