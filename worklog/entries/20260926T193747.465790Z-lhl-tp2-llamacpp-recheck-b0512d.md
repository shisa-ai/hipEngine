# Re-measure the matched llama.cpp TP2 comparison after the spin-add change

## Summary

The matched llama.cpp comparison in `benchmarks/README.md` was measured on
2026-09-25 with the hipEngine leg at 1066.3 tok/s, and it stated that prefill was
"20.0% behind" llama.cpp's tensor split with "about 96 ms to remove from a 480 ms
prefill". `8c4a5a040` moved the hipEngine leg to 1214.8 tok/s, which makes that
sentence wrong. Rather than divide a new hipEngine number by an old llama.cpp
one, both arms the comparison turns on were re-measured back to back in one
window on this host.

The deficit is now **6.8%** (about **28 ms** of a 421 ms prefill), and decode is
level. The re-measure also invalidates a second claim in the same section: the
"prefill scaling is the weaker one, which is where the 20% deficit lives"
sentence. TP2 prefill scaling is now the same on both engines over each one's
best single card.

## Validation

- Same window, same host, same model bytes (`2512f262...`, 17.1 GB), same shape
  (512-token prompt, 128 decode tokens, f16 KV both engines, c=1, three
  repetitions), both legs run back to back in one command:

  | engine | prefill tok/s | decode tok/s |
  | --- | ---: | ---: |
  | llama.cpp TP=2 `-sm tensor -ts 1/1` | 1302.8 ± 20.2 | 41.07 ± 0.50 |
  | hipEngine TP2 (bulk, head-sharded) | **1214.8** (runs 1219.8/1214.8/1209.7) | **41.66** |

- Commands: `llama-bench -m /models/gguf/Qwen3.8-27B-Q4_K_M.gguf -p 512 -n 128
  -r 3 -ngl 999 -ctk f16 -ctv f16 -fa auto -sm tensor -ts 1/1`, and
  `uv run python scripts/tp2_c1_bench.py --mode tp2 --bulk-prefill
  --prompt-length 512 --decode-tokens 128 --repeats 3`. The hipEngine leg
  resolved `schedule=graphed`, `prefill_schedule=bulk-tp2`,
  `reduce_mode=device`, `attention_shard=true`, so it is the shipped default
  route and not a diagnostic.
- Ratios, computed from the artifacts rather than by hand: hipEngine prefill
  0.9325x llama.cpp's tensor split, decode 1.0143x; llama.cpp's tensor split
  1.2316x its XTX and 1.3889x its W7900, hipEngine 1.2295x and 1.3830x.
- A first version of the artifact computed llama.cpp's scaling against
  *hipEngine's* single-card controls and reported 1.32x/1.48x. That was wrong and
  was fixed before the rollup was written; both engines' single-card legs are now
  read from the artifacts that measured them.
- `scripts/sync_benchmark_readme.py --check` passes.
