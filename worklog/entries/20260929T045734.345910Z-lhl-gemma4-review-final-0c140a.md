# Close Gemma 4 correctness review with matching softcap semantics

## Summary

The final independent review of `4a44f921c` confirmed the stop, request,
probe and verification-phase fixes, but identified a remaining softcap
sampling mismatch. It is now reproduced and fixed. The correctness repair
work is complete; this is not closure of the campaign's general 2x speed or
quality objective.

## Changes

- MTP target prefill and verification use the runner's default final-logit
  softcap, matching plain generation. Raw logits remain available for
  diagnostics but are no longer used by MTP target token selection.
- Add a CPU regression with leading raw logits `[20*C, 21*C]`. Float32 tanh
  saturates both to `C`, so plain generation chooses the first index. Before
  the fix MTP chose the second index at all eight sampled positions; after
  the fix it chooses the first. This covers prefill and verify selection.
- Retain final public-run correctness evidence in
  `benchmarks/results/2026-09-29-gemma4-mtp-final-correctness.json`, with token
  IDs and model/draft provenance. Timings are omitted to avoid treating this
  single-sample diagnostic as a performance result.
