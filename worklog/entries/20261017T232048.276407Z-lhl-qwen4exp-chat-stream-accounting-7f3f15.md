# Avoid per-token driver controls during chat streaming

## Summary

Chat stream accounting now consumes backend cumulative token counts instead of re-tokenizing every visible delta. This removes a serialized driver control from the chunk delivery path when authoritative metadata is available. Live per-cycle delivery still needs a follow-up check.

## Changes

- `EngineService.count_tokens` queues a driver control; the chat HTTP loop invoked it for each visible delta. The completion loop already used chunk telemetry. Chat now uses the same `observe_stream_chunk` accounting for ordinary and final splitter parts, retaining the existing fallback when metadata is absent.
- Added an HTTP regression assertion forbidding per-token display-text counts for resident chunks. It failed on chat with metadata before the repair and passes afterward.
- Updated the backend-decode-state HTTP fixture to expect the authoritative three committed tokens rather than the two words obtained by re-tokenizing `backend reply`.
