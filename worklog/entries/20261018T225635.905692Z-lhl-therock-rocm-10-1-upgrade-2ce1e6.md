# Upgrade the gfx1151 TheRock environment to ROCm 10.1.0

## Summary

The gfx1151 development environment at `~/mambaforge/envs/therock` moved from
stable TheRock ROCm 10.0.0 to 10.1.0. The upgrade is validated for SDK health,
fresh HIP JIT compilation, graph capture/replay, PyTorch, torchvision device
kernels, the profiler, and one full-model `hipengine.LLM.generate()` call.

Three issues surfaced that the setup docs did not cover: ROCm 10.1.0 no longer
ships `rocm-smi`, AMD never published `torchvision 0.29.0+rocm10.1.0`, and
`pip --upgrade-strategy eager` resolves a numpy major bump that breaks unrelated
packages. All three are now documented with their workarounds.

This is an environment refresh, not a performance promotion. No benchmark row
was produced or re-attributed.

The user-surface call was the load-bearing check:

```python
llm = LLM("/models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_S.gguf", backend="hip_gfx1151")
llm.generate("The capital of France is", SamplingParams(max_tokens=16, temperature=0.0))
# ' Paris.\nThe capital of France is Paris.\nThe capital of France is'
```

Cold generation took 234.7 s, which covers the full 21 GB GGUF load and first-run
JIT compilation of the model's kernel set on the new toolchain. That number is a
correctness-smoke duration, not a throughput measurement, and must not be quoted
as one.

Compiler warnings during the JIT build were non-fatal: a `loop not unrolled`
pass-failure on `gguf_q8_0_t16_prefill_wmma_kernel`, and an
`amdgpu-waves-per-eu` occupancy miss (desired 4, final 2) on
`qwen35_gdn_prefill_recurrent_decode_order_exact_lds32_kernel`. Both are
compiler diagnostics on existing kernels, not upgrade regressions; neither
changed output correctness.

`docs` gates: `python3 scripts/docs/check_all.py` — all 4 passed.
