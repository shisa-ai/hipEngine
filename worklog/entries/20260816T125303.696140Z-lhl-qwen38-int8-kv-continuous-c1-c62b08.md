# Implement IKV-C1 compact serial INT8 KV residency

## Summary

**Target correction:** retained qualification for this unit is RX 7900 XTX
GPU1 / DRM card0 only. Diagnostic runs accidentally launched on GPU0/W7900 are
not campaign evidence; that board is reserved for another agent and must not be
used again in this unit. Audit found that `server_f1_concurrency_bench.py`
returned from its hipEngine command branch before applying `--gpu`, so the flag
had been ignored. The first repair set both ROCm selectors and was rejected
with HIP error 100 because the second selector filtered the remapped view to
zero devices. The harness now sets only `HIP_VISIBLE_DEVICES` before that
return and removes inherited `ROCR_VISIBLE_DEVICES`; a live mem-info guard
confirms selector 1 exposes the 23.984-GiB XTX.

IKV-C1 remains **blocked**. The candidate runtime distinguishes resident
layout identity from row-batched-attention eligibility and serializes direct
INT8 decode, but no logical c2+ capability is retainable yet. All C1 source
changes remain uncommitted; production stays at the previously committed c1
admission bound.

The GPU-selection harness fix is independently complete and committed as
`9d61747f2`. Every true qualification attempt below ran with child environment
`HIP_VISIBLE_DEVICES=1`; `/sys/class/drm/card0` reported 23.984 GiB and
`rocm-smi --showmeminfo vram` showed allocation growth only on GPU1.

## Changes

- Added candidate capability fields for persistent mirror ownership and bounded
  serial residency, direct-INT8 serial decode selection, logical-C/physical-c1
  route telemetry, per-request KV byte audits, and Prometheus ownership gauges.
- Buffered scheduler chunks so the no-mirror route receives the complete prompt.
- Added vocabulary-range publication guards: corrupt shifted rows now fail
  closed instead of returning HTTP 200 with `INT64_MAX`.
- Corrected the confirmed prefill-address bug: the transient BF16 oracle keeps
  its identity row-major page table, while retained INT8 payload/scales use a
  separate row-major table repeating the request's physical page IDs. Retained
  caches and scale planes remain at backing-base pointers, so the offset is
  applied exactly once.
- Rejected and removed speculative dedicated-chunk, workspace-borrowing,
  workspace-priming, and token-serial-prefill experiments after they failed the
  varied-prompt c2 equality gate.

## Validation

- Focused host packet after cleanup: 183 GGUF generation/device-KV/layout/
  capability tests passed. The benchmark harness packet passed 25/25.
- True XTX RED (`/tmp/qwen38-ikv-c1-xtx-c2-r3.json`): c2 shifted row failed
  closed at token `INT64_MAX`, position 512, local base row 768.
- Layer diagnostic localized the first non-finite output to full-attention layer
  3. Scale readback showed that the retained writer had inherited the transient
  identity table; the physical-table repair removed the NaN/invalid token.
- Post-repair identical-prompt XTX c2 was exact across warmup, measured, and
  live rows (`/tmp/qwen38-ikv-c1-xtx-identical-r1.json`). This proves the
  shifted physical payload/table contract can execute without corruption.
- The required varied-prompt p512 gate still fails. A fresh XTX c1 row-1 oracle
  returned `[9707, 9707]`, while c2 row 1 varied across attempts (`[9708,
  9708]`, `[264, 220]`, `[13, 271]`, and other finite trajectories). No result
  was retained. Peak XTX VRAM in representative c2 attempts was 18.59 GiB.
- A p16 fresh-oracle diagnostic was exact, showing the remaining defect is
  long-prefill/session-shape dependent rather than a universal page-table
  failure. Attempts to force token-serial p512 changed the trajectory and were
  rejected rather than redefining the oracle.
