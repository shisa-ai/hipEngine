# Eliminate empty split-K work in mixed-length batched decode attention

## Summary

Implements the reviewer's first-choice optimization from the PR #29510 review
(`20261108T144148...-llamacpp-kv-rows-review-6399a2.md`, probe
`20261108T145807...-pr29510-pool-probe-91864c.md`): the production split-K
batched decode launched a rectangular `kv_heads x num_splits x rows` grid with
`num_splits = ceil(max_context_len/256)`, so short rows in mixed-length batches
launched empty split blocks that zeroed partial buffers, and the gate reducers
read every split including empty ones.

Change (no flag, on by default, valid-split arithmetic unchanged):

- Batch-exclusive context kernels (`..._ctx_tensor_gqa_batch_kernel` 16Q/2KV
  and 24Q/4KV, `..._ctx_tensor_gqa_int8_batch_kernel`) now early-return on
  empty splits without sentinel zeroing.
- Batch gate reducers (bf16/fp16 template + strided) gain an optional
  `context_len_ptr`/`chunk_size` ABI and bound every loop by
  `min(num_splits, ceil(live_counts[row]/chunk_size))`, derived device-side
  from the same `live_counts` the context kernels read. Null pointer keeps
  legacy behavior. All batch wrapper call sites pass the bounds.
- Grid dimensions are unchanged, so HIP graph capture/replay is unaffected;
  the graph-replay test updates device `live_counts` and replays without
  recapture. The warp-split context kernel keeps its zeroing because it is
  shared with the c1 non-batch reducer, which still reads all splits; its
  batch reducer is bounded anyway.

Measured on gfx1151 / Radeon 8060S, ROCm SDK 10.0.0, host `gfx1151`
(kernel-level probe, 24Q/4KV/head-256, production wrapper + runner
`num_splits` formula; before artifact
`2026-11-08-pr29510-paged-decode-pool-invariance-diagnostic.json`, after
`2026-11-08-pr29510-empty-split-elimination-after-diagnostic.json`):

| Arm | Before | After | Delta |
| --- | ---: | ---: | ---: |
| B7 short 4x1K, 512 splits | 671.4 us | 135.9 us | **-79.8%** |
| B6 mixed [128K,1K,1K,1K] | 3129.6 us | 2849.4 us | **-9.0%** |
| B1 mixed [32K,1K,1K,1K] | 862.4 us | 817.6 us | **-5.2%** |
| B3 short 4x1K, 128 splits | 157.6 us | 135.6 us | -14.0% |
| Controls (A1/A2/B2/B5/B8) | — | — | within +/-0.4% |

Empty-split overhead at 512 splits fell 591.2 -> 54.5 us (91% removed) and no
longer scales with the longest context: the ~54 us residual is constant
early-exit block dispatch at 128 and 512 splits alike. B4 compact control
moved 80.2 -> 81.5 us (+1.6%), within prior run variance (80.0/80.2 in earlier
runs); the bounds add one load and integer division per reducer block.
Kernel-level evidence only: no end-to-end serving speedup is claimed.

## Changes

- `hipengine/kernels/hip_gfx1100/attention/paged_attn_decode.hip`: early-exit
  empty splits in the two batch-exclusive context kernels; optional per-row
  bounds in both batch gate reducer kernels and their three extern C
  launchers.
- `hipengine/kernels/hip_gfx1100/attention/paged_attn_decode.py`:
  `_launch_gate_reduce_batch{,_strided}` accept `context_len_ptr`/`chunk_size`;
  the bf16/fp16 GQA batch, warp batch, and INT8 strided batch wrappers pass
  `spans.live_counts.ptr` and `chunk_size`.
- `tests/test_gpu_qwen35_split_batch_empty_splits.py`: 13 GPU tests (oracle
  parity across four wrapper variants and boundary/unrelated context lengths,
  byte-exact batch-composition invariance, NaN-poisoned invalid partials
  through the bounded reducer, graph replay with device-side bound updates).
- `scripts/exercise_split_batch_surface.py`: mixed-length concurrent
  completions + telemetry probe used for the production-surface check.
- `benchmarks/results/2026-11-08-pr29510-empty-split-elimination-after-diagnostic.json`.
- `benchmarks/CHANGELOG.md` one-liner.
