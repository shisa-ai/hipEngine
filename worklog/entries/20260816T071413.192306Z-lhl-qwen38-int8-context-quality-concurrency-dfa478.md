# Close Qwen3.8 INT8 context and W7900 frontiers

## Summary

Closed the guard-free Qwen3.8-27B pure-INT8 c1 page boundary on RX 7900 XTX,
extended matched BF16-vs-INT8 quality to that prompt length on W7900, and
measured the W7900 c1/c2/c4/c8 server frontier. The exact Qwen3.8 INT8 server
route is queue coalescing rather than retained continuous batching.

## Changes

- RX 7900 XTX c1: 129,024 total tokens (504 pages) passed one exact natural
  request at 23.962624 GiB peak / 0.021751 GiB headroom with clean ownership.
  The next page, 129,280 tokens, stalled raw warmup beyond 600 seconds;
  129,536 repeated the stall and 130,048 returned HIP OOM. The prior 114,688
  row remains the strongest repetition at four exact natural requests.
- W7900 matched quality at 129,024 prompt tokens plus 16 teacher-forced steps:
  mean/max KL 0.000010379/0.000135450, 100% top-1, all logits finite, all 16
  full-attention layers INT8, zero BF16 mirror bytes. This is the explicit
  bounded `mixed_v1` control, not the complete 11-prompt long-context suite.
- W7900 server: c1 passed the model-native 262,144-token limit at
  29.441/15.543 GiB peak/headroom. c2/c4/c8 passed 8,192/request, then all
  rejected 8,448 in `resident_prepare` because no-mirror packed INT8 is not
  admitted. Observed physical groups were c2, c2+c2, and c1+c3+c4.
- Added `--prompt-id` to the mixed-KV quality harness in commit `e610a1fde` so
  expensive bounded long rows can select the retained representative control
  without weakening the complete-suite default.
- Published compact evidence in
  `benchmarks/results/2026-08-16-qwen38-27b-actual-context-quality-w7900.json`
  and updated the superseded XTX artifact, benchmark rollup/changelog, and KV
  report.
