# Muse Glimmer AR resume: profiling confirms the projection kernels dominate

## Summary

Resumed Gate A (AR) after the DFlash win. Re-measured the baseline (unchanged
by the DFlash work, which used a separate exact-verify path) and profiled both
prefill and decode with rocprofv3 kernel traces. The tractable WMMA leaf
tuning is exhausted; the remaining gap to llama.cpp is the quantized
projection efficiency, which points at int8 MMQ (llama.cpp's approach).

## Changes

- None to production code this unit (profiling + leaf sweep only).

## Validation

Baseline re-measure (3 shapes x3, /tmp/glimmer-ar-resume.json): prefill
320.4 / 298.9 / 240.7, decode 11.17 / 11.05 / 10.84 at 512/1K/4K. llama.cpp
P0 targets: prefill 394.4/385.8/376.3, decode 12.24/12.17/12.05.

Prefill kernel breakdown (512, rocprofv3): Q4 T16 dense WMMA 44.5%, Q6 T16
WMMA 28.3% (projections 72.8% combined), GQA flash attention 25.0%, norms/
activations ~2%.

Q4 WMMA leaf sweep at rows=512 (ffn 6656->19968, 136 GFLOP): the current
default shared_b / shared_b_w64 is already the fastest at 25.1 TFLOPS; every
other registered leaf (row64, b2w2, b3w8r3, b2w4, b2r1, lowvgpr48, lowvgpr,
single-wave) is slower (10-18 TFLOPS). attn_q 6656->4096: shared_b 23.2
TFLOPS best. ~25 TFLOPS is ~35% of the gfx1151 bf16 WMMA peak; no available
leaf closes that gap.

Decode kernel breakdown (rocprofv3): Q4 local32 GEMV 56.9%, Q6 qmicro_planar
GEMV 14.7% (projections 71.6%), Q5 head 4.6%, norms ~3%, attention 0.9%
(the key-split flash-decoding kernel is already fast), KV append/casts <1%.
Decode is memory-bound on the weight reads; the Q4 local32 micro-tuning space
was searched and rejected in prior worklogs (local64, coalesced-K, dp4a,
static-K).

## Findings / path forward

- Prefill: leaf selection is optimal among registered kernels. Closing the
  65-82% gap needs int8 MMQ prefill (RDNA3 int8 WMMA is ~2x bf16 peak, which
  is how llama.cpp's MMQ reaches 394 tok/s). A Q6 planar integer-MQQ
  (t16_q8_1_planar_integer_mmq64x64) owner exists for verify; enabling it for
  Glimmer prefill is an arithmetic-changing production default and requires
  the EXECUTION-PROFILES.md calibrated numerical gate + a strict fallback.
- Decode: the +9% gap is the GEMV bandwidth + the extra Glimmer per-layer ops
  (2 post-norms + sigmoid gate + QK-norm). Norm fusion is worth ~1-2%; the
  GEMV itself is near the tuned roofline. Hard to close fully without int8.
