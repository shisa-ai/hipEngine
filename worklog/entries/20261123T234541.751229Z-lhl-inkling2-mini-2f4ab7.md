# Measure fast Inkling prefill block widths and kernel limits

## Summary

Under `fast`, wider prefill blocks did not make grouped experts faster. At 256-row blocks the NVFP4 tile kernel took 704.39 ms against 629.14 ms at 64 rows, although the blocks re-read the expert weights three times fewer. The kernel is limited by its FP32 dot products, not by weight traffic. Session time fell about 6%, the public route showed no change, and wider blocks are not bit-exact, so the default stays at 64. This corrects two figures in the [Maya review](20261123T233607.588698Z-lhl-inkling2-mini-826f0a.md): it used a 576 GB/s W7900 peak where [the roofline model](../../docs/ROOFLINE.md) has 864 GB/s, and it inferred from the bandwidth bound that only fewer re-reads help. A compute-efficient grouped expert kernel is the prerequisite, at any width.

## Validation

- On `epyc`/W7900, mainline Inkling 2 Mini `UD-Q4_K_M`, runtime code of `cd69bbd64f109e8fe699510ef0012166603165b9` (the later commits are documentation), fast manifest `ec04e8bdf2c53c55ebe895c0f905f388a72bb691af0658265dfc8b4676e1cb27`, FP32 KV, greedy, no reuse or drafting. Timing: `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. HIPENGINE_REQUIRE_CACHED_BUILD=1 python -u /tmp/hipengine_inkling_fast_width_time.py "$model" hip_gfx1100 "$revision" 575 1027`, two warmed runs per width in each order. Session medians at 575 input were 5.464 s (64), 5.140 (128), 5.137 (256) and 5.256 (512); at 1,027 input 10.321, 9.699, 9.647 and 10.073. Peak allocated memory was the same at every width.
- Through `LLM.generate_detailed()` with only the model's block width changed, no width beat width 64 by more than its own run-to-run variation: 5.48 to 5.55 s at 575 input and 9.51 to 10.05 s at 1,027 across all runs. The scheduler's 64-token chunk was not raised, so that combination is untested.
- First-token logits against width 64: across the tested lengths, width 128 differed by at most 2.2e-5 to 3.5e-2, width 256 by 2.3e-5 to 4.3e-2 and width 512 by 2.3e-5 to 1.33. Differences above 0.01 arise at lengths that end in a single-row block or that use 512-row blocks. The first token matched in all 25 comparisons against width 64 and in the 32 public runs.
- Trace at `f0a0927b32e8cfed9413b92feba33036234f3fa9`: `rocprofv3 --kernel-trace --marker-trace --output-format csv` around `/tmp/hipengine_inkling_width_trace.py "$model" hip_gfx1100 "$revision" 575`, with a precomputed compiler-version file and `require_cached`. Summed device kernels per 575-input prefill, width 64 against 256: grouped NVFP4 629.14 against 704.39 ms, Q5_K tiles 194.68 against 172.59, tiled attention 182.40 against 151.76, dense Q8 209.30 against 202.07, block convolution 105.63 against 114.59; all kernels 1,644.99 against 1,457.87 ms over 10,899 against 3,891 launches.
- The NVFP4 experts of that prompt are 3.223 TFLOP, so the tile kernel runs at 5.12 TFLOP/s at width 64, 8% of the roofline model's 61.3 TFLOP/s FP32 peak. Nine 64-row blocks re-read 227.0 GB of NVFP4 weights, 262.8 ms at the 864 GB/s peak; the kernel takes 2.4 times that. Kernels fill 1,645 of the 5,112 ms traced window at width 64, so the host leaves the GPU idle for about two thirds of it under the profiler.
