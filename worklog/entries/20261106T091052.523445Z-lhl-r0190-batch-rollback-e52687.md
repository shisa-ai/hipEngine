# Drain failed batch replay provider ownership

## Summary

Batch provider setup now drains every owned request and returns the provider
pool owner when replay fails, even if a request release raises. The admission
error remains primary; cleanup errors are attached as notes.

## Changes

- Contain individual root-buffer, request and pool-release errors during setup
  rollback, and detach bookkeeping independently of release success.
- Remove the unused local verifier map: this path never populates it.
- Add a RED/GREEN regression with replay failure and a failing first release,
  checking the peer release, pool return and empty group/state bookkeeping.

## Validation

- RED: first request release replaces the replay exception and prevents peer
  release and pool return.
- GREEN: `uv run pytest -o addopts='' -q
  tests/test_unit_qwen35_gguf_mtp2_seam.py
