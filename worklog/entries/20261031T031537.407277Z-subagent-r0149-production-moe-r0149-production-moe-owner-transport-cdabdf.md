# R0149 production MoE prefill owner transport

## Summary

The production grouped-MoE prefill gate is now owner state. The production
binder publishes `production_moe_prefill_enabled` on the generator and its
current runner, `resolve_production_moe_prefill()` reports the decision, and
`production_moe_prefill_enabled(owner, ...)` overrides it on the generator and
runner without allocation. The binder no longer writes
`HIPENGINE_QWEN4_EXP_PRODUCTION_MOE_PREFILL`; a caller value that differs from
the published decision is reported once as inert.

The historical process key remains only as the direct/unbound fallback. Its
raw boolean parser is unchanged: the exact strings `""`, `0`, `false`, and
`False` disable it, so `FALSE` and padded values stay enabled. The consumer
keeps the rows>=16 guard first, then the owner/fallback decision, then the
slot-path and layer-capability guards, so a narrow width never reads ambient
state.

The batch capture key carries the decision only where the consumer can select
it. At `rows >= 16` the key includes the resolved owner (or its direct
fallback); below 16 it carries a stable false and does not resolve the ambient
key. Both the GDN and QSA segments use the same term. The AR batch carrier,
mixed-target pass, clone path, and `_inherit_lane_decisions()` forward the
field.

Defaults are unchanged: production UD-Q4_K_XL and strict publish `False`;
the historical Q4_K_M production plan publishes `True`.

## Provenance repair

Parent review found that the layer2 candidate report recorded the environment
but not the resolved owner decision, and that both scripts treated an explicit
production-MoE override as a named-profile run.

`scripts/qwen4exp_layer2_profile_gate.py` now binds the candidate owner through
`_bind_candidate_production_moe_prefill()`, which returns
`resolve_production_moe_prefill()` while the scope is active. The report carries
`candidate.production_moe_prefill_enabled` (the value the measured rows used)
and `candidate.production_moe_prefill_override` (the arm's explicit `True`,
`False`, or `None`). `candidate_named_profile_intact` is false whenever that
override is not `None`.

`scripts/qwen4exp_profile_gap.py` now uses `_named_profile_intact()` and
`_configuration_class()`: an explicit `--production-moe-prefill on` or `off`
makes `named_profile_intact` false and classifies the run as
`diagnostic_post_binder_override`, while an absent argument preserves the
named-profile path.
