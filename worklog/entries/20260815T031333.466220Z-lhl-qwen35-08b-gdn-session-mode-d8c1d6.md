# Freeze GDN mode at session scratch

## Summary

Author and second-opinion reviews corrected the merge analysis: the claimed
current gfx1151 0.8B >=768-row alias hazard is NOT reachable today (dense
models need a GGUF_DENSE_PREFILL_SCRATCH_LIVENESS_POLICIES entry gfx1151
does not provide, and 0.8B K/V head counts are equal anyway). The merged
quant-shape-aware helper stays (functionally correct). Both reviews converge
on refined Option C: resolve the final GDN mode once at session-scratch
construction (env + quant-shape + exact + availability fallback), store it on
the per-session scratch (runners are shared), and have Q/K sizing, liveness,
conv_out lifetime, and dispatch consume the stored value, preserving an
explicit diagnostic alternation path for the semantic-gate harness. The
second review also found a real gap: the post-allocation Q/K capacity guard
covers normalized peer routes only (compact->chain 4->32 head flip runs
unguarded), plus split->fused conv_out lifetime drift.

## Changes

- Single resolver _gguf_gdn_prefill_session_mode(backend, weights, cfg)
  replacing _gguf_gdn_prefill_effective_mode everywhere (allocation sizing,
  liveness fields, arena fused-check, dispatch).
- _GGUFFullAttentionPrefillScratch gains frozen gdn_effective_mode and
  gdn_mode_diagnostic resolved at allocate().
- _run_gdn_prefill consumes the frozen mode unless the diagnostic
  superset-scratch flag is set (env alternation preserved for the semantic
  gate); the Q/K capacity guard remains for diagnostic transitions.
- New session-mode test matrix per both reviews.

## Validation

- Resolver matrix incl. gfx1100 compact, gfx1151 Q4/Q8 cluster8, unkeyed
  direct, explicit/exact, availability fallback.
- Dense gfx1151 0.8B liveness-is-None contract test at >=768 rows.
- Dispatch freeze: post-construction env flip cannot change a production
  session's mode; diagnostic scratch alternates.
- 0.8B Q4/Q8 exact-core GPU smoke unchanged.
- Existing routing/liveness/gfx1151/gfx1100-right-sizing suites green.
