# Add EOS-aware conditional Moonshine decode

## Summary

Added an opt-in, truly EOS-aware CUDA `sm_120a` Moonshine decode control. One top-level CUDA graph contains two conditional WHILE nodes: positions 0-6 replay the retained t32 child graph, positions 7-193 replay the retained t256 child graph, and a one-thread device condition kernel stops each loop from the sticky device EOS flag and exact device position. A generation now has one host graph launch and no intermediate host EOS read or graph relaunch. Exact fixture/token/lifecycle gates pass. The six very-short-file diagnostic regressed 1.66%, while a downstream 20-fixture/100-observation warm-E2 screen improved P50/P95 1.90%/1.56%; the capability remains opt-in pending the downstream seven-pair and full-FLEURS promotion gates.

## Changes

- Added `moonshine_set_decode_condition_kernel` and host graph construction helpers in the CUDA Moonshine glue library. The graph owns two conditional handles and WHILE nodes; each body uses the already-captured exact token graph as a child and updates its condition after token/result publication.
- Added `moonshine_create_eos_decode_graph` to the raw-pointer wrapper with strict handle/pointer/capacity validation and explicit returned graph/graph-exec ownership.
- Added `MoonshineCudaEosDecodeGraph`, idempotent capture, exact generated-position readback, one-launch `graph_decode_to_eos`, child replay accounting, contract telemetry, and top-graph-before-child teardown to `MoonshineCudaResidentRuntime`.
- Added `--eos-conditional` to the complete Moonshine driver. It requires device-owned decode, is mutually exclusive with fixed decode batching, records preparation/runtime identity, and remains default-off.
- Added RED/GREEN wrapper, validation, fake-runtime capture/replay/accounting/teardown, and real model-derived conditional-EOS tests. The four targeted tests first failed because the graph wrapper/runtime APIs did not exist.
- Updated the kernel catalog and Moonshine transfer guide. Published the compact default-off candidate packet and a benchmark changelog entry; no public/root benchmark topline changed.

## Validation

- Four RED tests failed before implementation with missing wrapper/runtime APIs, then passed after GREEN.
- CPU/no-GPU files `tests/test_moonshine_cuda_sm120a_glue.py tests/test_moonshine_cuda_sm120a_runtime.py`: passed all runnable tests; CUDA-gated tests skipped as configured.
- Real CUDA targeted gate: publish-result plus conditional exact-stream tests passed 2/2 using the pinned model-derived fixture bundle. The conditional path reproduced exact reference tokens through first EOS and exact generated length on both detailed fixtures.
- Broad real-CUDA two-file run passed every collected test except one unrelated fixture-data failure: the available six-file bundle does not contain `decoder.position_1.final_hidden` required by the old full-hidden test. Per focused-repair policy, the passing broad result plus targeted conditional gates were retained rather than repeating the same missing-data failure.
- Six retained 2-11-token complete-ASR smoke (one warmup/two attempts per file): baseline 4.668 ms versus conditional 4.745 ms median-of-medians, a 1.66% regression; all outputs exact. This blocks an unconditional hipEngine default.
- Downstream ASR target screen (20 FLEURS-through-EOU fixtures, five alternating iterations, 100 observations per route): baseline 40.059/47.325 ms versus conditional 39.299/46.588 ms P50/P95, saving 0.760/0.738 ms (1.90%/1.56%), with 200/200 route observations matching expected text. This is screening, not promotion evidence.
- Nsight Systems 2026.1.3 with `--cuda-graph-trace=node:host-and-device` recorded 36 publish/embedding kernels and 42 `moonshine_set_decode_condition_kernel` calls: one post-token condition per 36 generated steps plus one second-bucket precondition for each of six fixtures. All six profiled outputs were exact.
- Compilation, focused pytest, driver smoke, JSON parse, raw SHA-256, docs context, worklog checks, diff checks, and final NVIDIA process cleanup passed.
- `python3 scripts/check_lineage.py --kind kernel --diff stat` could not run because `$HOME/amd-gpu-tuning/reference/atlas` is absent on this host. This control kernel has no external source lineage; the environmental limitation is retained in the artifact.
