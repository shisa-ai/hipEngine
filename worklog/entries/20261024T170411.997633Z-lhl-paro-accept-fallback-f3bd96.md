# Commit CPU-selected PARO acceptance state consistently

## Summary

The non-graph PARO verifier now commits the CPU oracle's Conv/GDN row when
CPU acceptance differs from the GPU summary. The device selector is used only
when its GPU decision agrees with the authoritative summary. This repairs the
conditional state-ownership defect identified in
`20261024T134128.306639Z-lhl-paro-correctness-review-25a9ba.md`; no observed
acceptance disagreement in the earlier numerical captures is implied.

## Changes

- Add an executable fake-session regression that runs the real bulk verifier
  orchestration for trusted GPU, CPU validation, and CPU-owned acceptance, with
  matching and injected mismatching GPU decisions. Its state commit models the
  fused kernel's device-pointer precedence and checks canonical state, selected
  hidden pointer, host position, and mismatch metadata together.
- Bypass the stale device row pointer on disagreement. The existing per-layer
  copy path uses the authoritative host row; normal matching GPU decisions keep
  their fused commit. Native graph-owned mismatches still fail explicitly.
  Source inspection found the same selector defect in the sibling tree
  verifier; the repair and parametrized regression cover that path too.
