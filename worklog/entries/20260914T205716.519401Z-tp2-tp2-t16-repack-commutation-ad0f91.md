# The t16 repack commutes with a tile-aligned column split

## Summary

A rank can repack its own Q4_K slice and get exactly the corresponding tile range
of the full-tensor repack: **544 of 1088 tiles per rank, bit-identical on both
ranks**. This is the last materialization prerequisite for the shard MLP segment,
and it is now a checked probe question rather than an assumption.

## Changes

Added as the probe's fourth question in `scripts/tp2_mlp_shard_plan_probe.py`,
with tests in `tests/test_unit_scripts_tp2_mlp_shard_plan_probe.py` (11 pass) and
the artifact regenerated at
`benchmarks/results/2026-09-15-w7900-tp2-mlp-shard-plan-probe.json`.

The check: for each t16 tensor, repack the full source payload and each rank-local
slice, then compare `repack(local)[0]` against
`repack(full)[0, tile_start:tile_stop]` where the tile bounds come from the
slice's axis range divided by `GGUF_T16_COLS`. Both ranks of both Q4_K tensors
match. The Q6_K down projection resolves to the raw layout and is used as source
bytes with no repack, so it is recorded as not-applicable rather than as a pass.

**Why this is worth a probe question.** The failure mode is silent. A
non-commuting repack - a split that does not land on a tile boundary, or a repack
whose tile order depends on the full row count - would still produce a
correctly-shaped local weight and plausible-looking output. It would just not be
the TP1 weights, so every shard segment time measured on it would be measuring the
wrong tensor while looking valid. The split here happens to be tile-aligned
(8704 = 544 x 16), which is a property of this geometry rather than a guarantee,
so the check has to run per geometry.

## Validation

```
uv run python3 scripts/tp2_mlp_shard_plan_probe.py --model /models/gguf/Qwen3.8-27B-Q4_K_M.gguf \
  --layer 0 --world-size 2 \
  --json benchmarks/results/2026-09-15-w7900-tp2-mlp-shard-plan-probe.json
uv run pytest tests/test_unit_scripts_tp2_mlp_shard_plan_probe.py
```

Five questions answered yes, 11 tests pass. The probe exits non-zero if any
question is answered no.

A first attempt at this check compared against the wrong axis of the t16 tile
array (which carries a leading experts axis) and reported a false negative. The
corrected comparison is the one recorded above; the correction is noted because
the wrong-axis form is the easy mistake to repeat.
