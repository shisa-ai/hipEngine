# Surya full-page OCR coverage: torch/CPU/GPU three-way exact parity at 1024x1024

## Summary

Surya GPU coverage was limited to `page_small.png` (256x256) and
`page_rect.png` (320x192), both synthetic bar patterns whose oracle
continuation is a degenerate repeated `<ul><li>` run. Greedy-ID parity against
a repeating sequence is a weak gate: a wrong-but-plausible logit ordering can
still reproduce it. `docs/MODEL-SURYA.md` listed full-page coverage as pending.

Added `page_full.png`, a deterministic 1024x1024 page with real words
(heading, prose, rule, table) that yields a 1x64x64 patch grid and 1024 merged
visual tokens, plus a dedicated torch oracle for it. On that page the
**torch fp32 oracle, the NumPy CPU reference, and the gfx1151 HIP lane all
produce the identical 78-token layout-JSON output** — a long, non-degenerate
sequence where a small numerical difference would flip an argmax.

The decoded output is verifiable by inspection, not just self-consistent: the
first record is `{"label": "Section-Header", "bbox": "54 50 389 94"}` for a
heading drawn at pixel (60, 50) with a 40 pt font, and the following `Text`
records bracket the prose block drawn from y=140 to y=378.

## Changes

- `scripts/surya_oracle_torch.py`: add `_make_synthetic_page_full()`, a
  deterministic 1024x1024 renderer (DejaVu Sans, geometry a multiple of 32 so
  the smart-resize path is a no-op). Font lookup tries the common Linux
  locations; the fixture PNG is committed, so tests never render.
- `scripts/surya_oracle_fullpage.py` (new): torch fp32 oracle generator for
  the full-page case. Writes `oracle_fullpage.npz` (vision_merged,
  logits_first, greedy_ids, processor inputs) and
  `oracle_fullpage_greedy.json` (ids + decoded text). Deliberately additive —
  it does not regenerate the existing fixtures, which were captured with an
  older transformers and are not reproducible from the committed script.
- `tests/fixtures/surya/page_full.png` (new, 56 KB),
  `tests/fixtures/surya/oracle_fullpage.npz` (new, 4.1 MB),
  `tests/fixtures/surya/oracle_fullpage_greedy.json` (new).
- `tests/test_surya_gpu.py`
  - `test_gpu_full_page_layout_matches_oracle`: full GPU pipeline
    (vision -> prefill -> greedy decode) vs the torch reference, exact ID
    match.
  - `test_gpu_full_page_vision_matches_oracle`: vision tower at 4096 patches
    vs the oracle `vision_merged`, so an end-to-end failure can be localized
    to vision or decoder without paying for the ~19 s NumPy vision forward.
  - `_full_page_inputs()` helper.
- `docs/MODEL-SURYA.md`: status table split into "Full-page coverage" (done)
  and "Multi-page held-out OCR corpus" (still pending), plus the three-way
  parity statement in the correctness-gates paragraph.

## Validation

Three-way comparison on the committed `page_full.png`, all lanes run in one
process, `HIPENGINE_HIP_ARCH=gfx1151`:

| Pair | Exact | First divergence | Lengths |
| --- | --- | --- | --- |
| torch vs CPU reference | yes | none | 78, 78 |
| torch vs GPU lane | yes | none | 78, 78 |
| CPU reference vs GPU lane | yes | none | 78, 78 |

Decoded text is identical across all three and matches the drawn geometry.

Vision-tower magnitudes at full-page scale (grid 1x64x64, 1024 merged tokens):

| Pair | max abs | mean abs |
| --- | --- | --- |
| CPU reference vs torch oracle | 2.591e-04 | 2.449e-07 |
| GPU lane vs torch oracle | 9.189e-04 | 9.687e-07 |
| GPU lane vs CPU reference | 9.254e-04 | 9.457e-07 |

RED/GREEN on the new gate: perturbing reference index 40 by one token makes
`test_gpu_full_page_layout_matches_oracle` fail with
`diverged from the torch fp32 reference at index 40 (gpu len=78, ref len=78)`;
restoring it passes.

`HIPENGINE_HIP_ARCH=gfx1151 python3 -m pytest tests/test_surya_gpu.py -q` →
10 passed. The full Surya bundle (model contract, oracle fixtures, text
decoder, vision, e2e, public API, generation contract, GPU) → 89 passed.

Lane costs on this page, for future test-budget decisions: CPU reference
18.5 s vision + 8.4 s prefill + 13.4 s for 48 decode steps; GPU lane 1.2 s +
0.9 s + 1.5 s. The committed test only runs the GPU lane (~4 s) and compares
against the stored reference.
