# Keep PARO aggregation and repeat reviews observational

## Summary

The aggregate and repeat-review consumers now preserve the numerical reporting
contract introduced in `cd0f306a4`: sample observations do not become automatic
admission or full-policy verdicts when pooled or repeated. Execution failures
remain separate and include every repeat, not only the canonical trajectory.

## Changes

- Report both current sparse-MoE and historical mean/tail envelopes, per-source
  manifests/attestations, explicit sample scope and inconclusive policy.
  Remove automatic-admission and numerical-repeat-gate statuses. Matrix and
  repeat schemas become v2; clean execution exits 0, failed execution exits 1.
- Keep one canonical trajectory per prompt in the numerical denominator.
  Validate model/backend, prompt uniqueness, legacy and registered manifest
  identity. Repeats additionally validate every source's complete manifests.
- Report old numerical `checks` booleans as compatibility observations only;
  never use them to decide repeat status. Byte-repeat disagreement can fail
  its distinct execution contract without becoming a numerical-policy verdict.
- Reject duplicate resolved input paths, including symlink aliases, and invalid
  capture hashes. Normalize valid hexadecimal hashes before comparison.
- Propagate noncanonical execution and aggregation failures into status,
  consolidated failure lists, qualification counts and all-repeat provenance.
  Legacy captures without separate execution records remain explicitly unknown;
  their historical numerical rejection is not relabelled an execution failure.
