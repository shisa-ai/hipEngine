# Shipped-default baseline and attribution refresh at HEAD

## Summary

The campaign's topline screen and its role attribution now both describe the path
that ships, at `42ce71156`. The screen is the first full 12-case PP/TG matrix for
this model measured on the post-promotion default; the attribution replaces the
pre-promotion ranking and shows the promotion moved `dense_projection` from
10562.2 ms to 5234.8 ms while every other family stayed within 0.5%.

Two findings change the campaign's priority order:

1. **The MoE pair is now the largest owner.** `expert_gate_up` (3402.4 ms) plus
   `expert_down` (2382.3 ms) is 34.6% of the 16733.4 ms attributed window and
   4.61 s of the 12.97 s gap to the comparator's PR #63 build.
2. **The dense family's remaining cost is mostly the un-promoted layers.**
   Layers 0-15 spend 3262.5 ms on the same Q8_0 GEMM roles that cost 1404.2 ms at
   layers 16-47. Applying the promoted route's measured per-launch times to the
   layers 0-15 role set gives about 798 ms, a 2.5 s opportunity — five times the
   0.5 s the pre-promotion byte-share interpolation predicted, and larger than
   the F16-activation work measured in the companion entry.

`fell_back_to_strict: false`):

| Category | 512 PP / TG | 1024 PP / TG | 4096 PP / TG |

| code | 238.7 / 17.70 | 252.3 / 17.19 | 240.4 / 16.22 |
| general_en | 239.5 / 17.68 | 254.1 / 17.18 | 242.8 / 16.27 |
| general_ja | 241.6 / 17.67 | 254.2 / 17.20 | 243.1 / 16.29 |
| mixed_ja_en | 238.2 / 17.70 | 252.6 / 17.19 | 241.3 / 16.24 |

The `code-p4096` prefill (17041 ms) agrees with the route A/B's wide arm
(17.217 s) to 1.0%, which is the check that this run measures the promoted path.
The 2026-09-13 journey row (294.1 PP / 19.17 TG at 4096) came from the
fifteen-recovery-flag composition that failed the numerical envelope
(max KL 0.0546) and is not this run's denominator.

Attribution integrity: window 17196.5 ms, attributed 16733.4 ms, unattributed
0.0 ms, 9652 kernels, census 1595 launches (1056 wide), no unmapped symbol over
the 1 ms floor. The window is 0.9% above the unprofiled 17041 ms, which is
profiler overhead.

Known limitation, recorded rather than smoothed: samples 31-35 of the screen
degrade monotonically (4096 decode 16.195 → 12.123 tok/s, then 512 decode 17.7 →
15.8). The GPU was at 41 °C and the host load average 1.2 immediately after, and
nothing else held `/dev/kfd`, so it is not sustained throttling; the cause is
unidentified. It costs the 512/1024 rows nothing and lowers the 4096 decode
aggregate by about 5%. The README reports both the artifact's aggregate and the
stable window.
