# Qwen4Exp GDN eight-wave norm gate and all-layer tiled recurrence in fast

## Summary

Two GDN prefill changes. A bit-identical eight-wave norm/gate kernel
replaces the per-pair one in every profile, and the `fast` profile runs the
tiled recurrence at all 36 GDN layers. Canonical 12-case protocol (Radeon
8060S / gfx1151, `UD-Q4_K_XL`, chunk 4096): `fast` prefill 728.9 / 868.4 /
1002.2 to **769.8 / 935.1 / 1104.8 tok/s**, 12/12 cases positive, decode
unchanged; 2.51x / 2.82x / 3.28x the `production` run measured back to back
(306.6 / 331.4 / 337.2). GDN kernel time per code-p4096 prefill in `fast`
falls from 742 ms to 347 ms and the kernel total from 4049 ms to 3657 ms.

## Decisions

- **The norm/gate was a launch-geometry problem, not an arithmetic one.**
  One 32-thread workgroup per (token, head) is 196,608 workgroups per layer
  at 4096 tokens. Packing eight pairs per workgroup, one per wave, keeps
  every wave's arithmetic and reduction unchanged, so the kernel is
  bit-identical (T0) and replaces the parent at all four internal launch
  sites in every profile. The parent stays reachable as the strict
  reference for the parity test.
- **Production takes the exact kernel by default.** It generates identical
  tokens in 12/12 canonical cases; its prefill moved +0.07 / +0.42 / +0.60%
  against a run about eight hours earlier in the same boot, which is inside
  cross-run variation, so no production rate claim is made beyond
  non-regression. The profile is the direct evidence (10.4 ms to 1.3 ms per
  layer).
- **Tiled recurrence everywhere is a `fast` route.** `production` certifies
  it for layers 27-47; below that the two recurrences differ in summation
  order. The window is a binder-owned value with no manifest row; the gap is
  recorded in `docs/REFACTOR.md`.
- **Older GDN alternates stay off.** The peer prefill route measured slower
  in an earlier sweep.
