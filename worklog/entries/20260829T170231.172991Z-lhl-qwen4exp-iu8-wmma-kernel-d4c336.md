# Add iu8-WMMA Q4_K selected dual kernel

## Summary

Added `gguf_q4_k_selected_dual_wmma_iu8_prefill_bf16_bf16_out`: the
llama.cpp mul_mat_q-class MoE gate/up kernel using the RDNA3.5 iu8 wave-MMA
with per-32-k-subblock int8 requantization of activations (LDS-staged,
cooperative) and Q4_K weights (per-thread column owners) and f32 rescale at
every subblock boundary. At the real Qwen4Exp shape (5080 rows, 512 experts,
dual 2048->640) it reaches **8.70 ms best / 3.06 TF/s** vs the certified
f16-WMMA route's 12.9 ms / 2.07 TF/s and llama mul_mat_q's 4.9 ms / 3.4
TF/s. Registered default-off under variant
`selected_dual_wmma_iu8_prefill_bf16_bf16_out`.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_q4_k_selected_prefill.hip`:
  new kernel (128-thread blocks, 4 warps x 32 weight columns per warp, 16-row
  expert tiles via the existing compact ABI, LDS q8 activation tile with
  bank-conflict padding), host launcher, extern C wrapper. ABI per the pinned
  probe (worklog iu8-wmma-abi): B-side thread = weight column, A-side lanes
  {0,2..14}/{17,19..31} carry 8 activation rows replicated per D-row half,
  identity byte->k.
- `.../gguf_q4_k_selected_prefill.py`: `_launch_wmma_iu8`, public wrapper,
  registry entry.
- `tests/test_gguf_q4_k_iu8_wmma_selected_prefill.py`: NumPy dequant
  reference comparison at dp4a-class tolerance (5e-2 of row max), 4 shape
  cases (1-16 experts, K 256-2048, out 128-640), HIP-guarded.

## Validation

- pytest 4/4 pass; existing selected-WMMA tests 17/17 pass (no regression).
- Microbench: iu8 8.70 ms best / 9.10 median (3.06 TF/s); f16 tm16 12.88 /
  15.38 (2.07); rowbatch owner 22.7 (1.18). Correctness vs f16 kernel:
  p99 error 0.92% of row max (dp4a class), max_abs 2.25 on outputs ~245.
- rocprofv3 kernel-trace: kernel runs as
  `gguf_q4_k_selected_dual_wmma_iu8_prefill_kernel`, 3 launches at 8.77 ms.
- Lineage: ggml-org/llama.cpp@17252c769 ggml/src/ggml-cuda/{mmq.cuh,
  mma.cuh} RDNA3 int path; ABI empirically pinned in-tree probes.
