# Gate slot-local AOTriton admission; quality passes, state gate pre-existing

## Summary

Adapted `scripts/execution_profile_gguf_int8_direct_prefill_gate.py` to A/B the
`HIPENGINE_GGUF_INT8_PREFILL_SLOT_LOCAL_AOTRITON` flag on the entry point it
actually affects, and ran the complete 18-prompt category + heldout suite. Every
calibrated quality threshold passes with 47-98x margin and top-1 is 1.000. The
gate's overall status is `failed_or_screen_only` for one reason that is
**demonstrably pre-existing and independent of the candidate**: the state
fingerprint reports `finite: false` on this route, including in a control run
where strict and candidate produced byte-identical state.

Promotion of the default is therefore a human-lead call, not something this unit
takes. The flag stays default OFF.

## Decisions

- **Gate the packed entry, not the scalar one.** The shipped gate drives
  `session.prefill` (`_run_logits_trajectory`), where this flag is inert, so the
  existing gate would have measured nothing. `--prefill-entry packed_slot_local`
  drives `prefill_batch_native`, which
  `_gguf_single_row_block_table_prefill_required` forces every `int8_direct`
  session onto.
- **`--bulk-attention-mode native` is not a usable proxy.** It dispatches to
  `_run_native_attention_bulk_ffn_layer_rows`, a different fused
  attention+FFN implementation, not the split-K paged fallback this flag
  toggles. Using it would have compared the wrong pair.
- **Short prompts are provably unaffected.** AOTriton engages only at or above
  `attn_aotriton_min_tokens` (512) and the suite is 39-71 tokens per prompt, so
  at production settings both arms run the identical native kernel:
  `max_abs_logit_delta` is exactly 0.0 and `strict_and_candidate_bytes_equal` is
  true. The change only affects prompts of 512+ rows, which is where the 2.74x
  was measured. This is now a `GateError` instead of a footnote, so the gate can
  never again report a trivially identical pass.
- **Left padding, not a task claim.** Reaching the 512+ row regime with this
  suite needs `--min-prompt-rows`. Padding is left-side so the evaluated
  final-row logits still belong to the real prompt's last token and both arms
  consume byte-identical inputs. The run is a numerical-envelope gate over the
  padded shape; it is explicitly not a task-quality claim about padded prompts,
  and the artifact records `prompts_left_padded`.
- **The state-gate failure is not attributable to the candidate.** In the
  unpadded control the arms are byte-identical
  (`strict_and_candidate_bytes_equal: true`, `max_abs_logit_delta: 0`) and
  `finite` is still `false`. `build_state_repeat_gate` requires
  `strict.finite and all(candidate.finite)`, so it is the shared route's state
  that is non-finite. `layout_stable` and `repeatable` pass in every run, the
  logits are finite, and the candidate state is byte-stable across 3 repeats, so
  the likely cause is unwritten slack in a captured KV/state buffer rather than
  corrupted math. Not diagnosed to a specific buffer in this unit.
- **No task gate was run.** Promotion evidence is therefore incomplete by
  `docs/EXECUTION-PROFILES.md` even setting the state gate aside.
