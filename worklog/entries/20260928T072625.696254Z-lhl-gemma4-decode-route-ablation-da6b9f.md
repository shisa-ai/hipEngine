# the expert share is below the ablation's own noise floor and every other arm is resolvable

## Summary

`20260928T072536` left a contradiction open: `no_experts` measured 1.5% while a memory
floor says the expert weights should cost ~19%. The JSON carries two repeats per arm at
two output lengths, so the noise floor is computable from the same run. Computing it
resolves the question of which numbers in the table are measurements at all.

Each arm's delta is compared against the propagated spread of its own repeats and the
baseline's, over the 32-token difference:

| arm | delta | noise | delta/noise | |
|---|---|---|---|---|
| `no_dense_q8_both` | 15.23 ms | 0.39 ms | **38.69** | resolvable |
| `no_moe_elementwise` | 3.09 ms | 0.17 ms | 18.44 | resolvable |
| `no_all_gemv` | 15.10 ms | 0.85 ms | 17.82 | resolvable |
| `no_dense_q8_bf16` | 7.14 ms | 0.55 ms | 13.02 | resolvable |
| `no_norm_rope` | 4.05 ms | 0.31 ms | 12.93 | resolvable |
| `no_router` | 2.76 ms | 0.22 ms | 12.34 | resolvable |
| `no_lm_head_q8_f32` | 3.79 ms | 0.37 ms | 10.15 | resolvable |
| `no_attention` | 2.06 ms | 0.56 ms | 3.68 | resolvable |
| **`no_experts`** | **0.54 ms** | **0.83 ms** | **0.65** | **noise-dominated** |

## What this settles

**`no_experts` is not a measurement.** Its delta is smaller than its own run-to-run
spread. The honest statement is `0.54 +/- 0.83 ms/token`, consistent with anything from
0 to about 1.4% of the step. It cannot be read as "the expert path is free", and the
1.5% figure in `20260928T072450` should not be quoted at all.

**Every other arm is resolvable**, the weakest being `no_attention` at 3.68 sigma and the
strongest `no_dense_q8_both` at 38.69 sigma. The table's other shares stand as measured.

## What this does not settle, and it is now bounded

The memory floor predicted ~6.6 ms/token for the expert weights. That is roughly **8
sigma above this arm's noise**, so the measurement does not merely fail to confirm the
floor -- it **excludes** it. One of these must be wrong:

1. the `experts` hook under-intercepts, so the arm skips only part of the route; or
2. the floor arithmetic is wrong -- the artifact's expert tensors may hold far fewer
   active parameters than "A4B" implies, or Q4_K_M's expert tensors may not be Q4_K.

A 6.6 ms effect could not hide in 0.83 ms of noise, so this is not a sensitivity problem.
It is a wrong model or a wrong hook, and I did not determine which.

## Why the noise floor was worth computing

The ablation prints a share table and no uncertainty, and a share table with no
uncertainty invites reading every row as a fact. One row was not. The two repeats were
already in the artifact; the check cost one command and no GPU time.

This is the same failure as `20260928T072536` one level down. There I failed to check a
number against a bound I had. Here the bound was in the same file I had already loaded.
