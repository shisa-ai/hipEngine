# Cross-engine comparison campaign: kyojin/gufo/strix-llama.cpp under the canonical protocol

## Summary

The human owner redirected the Qwen4Exp campaign from ledger-exhaustion to a
cross-engine comparison: run kyojin (Yamz-Labs), gufo, and halo-box
`strix-llama.cpp` against hipEngine's exact canonical protocol and production
quality gates, establish reproducible benchmarking, make the gate definitions
explicit, and set up per-operator microbenchmarking so we can see what each
engine is doing differently. This unit establishes the protocol and builds the
first harness pieces; measurement runs follow.

## Decisions

- The canonical comparison basis is the committed 12-case exact-token fixture
  (`benchmarks/fixtures/qwen4exp_canonical_ar_p512_p1024_p4096.json`), the
  QWEN4EXP-STATUS 1.2 protocol: prefill-only wall, one warmup, three
  repetitions, median per case, equal-weight mean; decode measured separately
  over 128 transitions. The new `docs/CROSS-ENGINE-PROTOCOL.md` is normative
  for the campaign.
- Quality gates are split: hipEngine-internal gates (calibrated KL envelope,
  layer2 strict-teacher gate, task battery) stay hipEngine-only; external
  engines get a characterization ladder (G0 identity/protocol, G1 greedy token
  agreement vs the strict teacher, G2 aligned logprob metrics where the engine
  exposes logits, G3 determinism, G4 the shared task battery). gufo exposes
  no logits, so its G2 is not applicable and G1 carries the quality signal;
  this follows the 2026-10-04 same-file finding.
- kyojin runs a different weights format (EXL3 pack, ~95 GB) — its rows are
  engine-plus-format rows and never enter same-file ratios.
- Engine pins, pass 1: hipEngine HEAD; halo-box master `6aa81b88e`
  (2026-10-09) freshly built HIP (done, `v0.5.0-dev`, in
  `/home/lhl/comparators-20261012/build-halobox`); gufo `v0.12.0`
  (2026-10-11) building from source with the TheRock toolchain (the
  `98641a6` prebuilt from 2026-10-04 is the fallback pin).
- BLOCKER, human decision required: the kyojin leg needs ~120 GiB free on the
  100%-full 473 GiB NVMe (95 GiB EXL3 pack + ~25 GiB ROCm-torch venv/SDK).
  Retirement candidates are listed in task #9 and belong to the human owner;
  nothing was deleted by this work.

## Changes

- `docs/CROSS-ENGINE-PROTOCOL.md` (new): normative protocol, gate ladder,
  microbenchmark method, artifact/rollup rules, engine pin table.
- `scripts/qwen4exp_canonical_ar_bench.py`: new `openai` mode — an
  OpenAI-completions adapter for text-driven engines (gufo, kyojin) on the
  same fixture, with per-case detokenize/retokenize identity verification
  (mismatched cases are disqualified and recorded, never re-aligned),
  engine-reported `timings.prompt_ms` as the prefill wall, `cache_n=0`
  enforcement on measured rows, exact output ids via `return_token_ids` where
  available (gufo: completion text re-tokenized, recorded per row), and an
  artifact schema compatible with the existing `compare` mode.
- `tests/test_unit_qwen4exp_canonical_ar_bench.py`: six new adapter unit
  tests (payload shape per adapter, response mapping, id-source preference,
  prompt-token mismatch rejection, usage fallback, round-trip disqualification).
