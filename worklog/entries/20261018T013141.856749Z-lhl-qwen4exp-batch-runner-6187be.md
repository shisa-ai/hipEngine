# Full-model N-row batch decode runner

## Summary

One full Qwen4Exp decode step for N independent requests in one layer
traversal, composed from the four committed per-stage owners: the batch
attention state (`3f096fe5a`), the dense QSA mixer (`cf9a213c5`), the GDN
indexed mixer (`7935b4fda`), the PLE indexed-conv stage (`cfdb0b5be`), the
request-owned QSA index state (`bee0ef3b7`), and the mixed dense/sparse QSA
mixer (`e930816f5`).

`Qwen4ExpGGUFBatchRunner` owns physical state slots, not requests. `admit(slot)`
returns an owner token, `step(tokens, slots=...)` advances one token per row in
the caller's row order, and `release(slot, owner)` refuses a stale handle.
State is addressed by slot, so `slot_ids` may be any permutation of the admitted
slots and row `r` reads and writes only `slot_ids[r]`. The runner reuses the
committed GR/MoE/projection helpers the c1 runner uses; the only stage owners it
swaps are the mixers, and the whole row set is validated before the first device
write.

`import_prefilled` is the hand-off from the c1 prefill path: it copies one
prefilled request's paged K/V blocks, raw index keys, every GDN layer's
recurrent/conv row, the PLE conv history, and the PLE n-gram history into an
admitted slot. Pooled index keys are re-derived by the next selection rather
than copied.

No serving path, no default, no engine change, no kernel change, no doc change
beyond this unit's `docs/REFACTOR.md` debt section. `docs/PLAN.md` is unchanged
because the phase plan already lists the batch runner as the next step.

## Design decisions

**Ownership by slot, not by request.** Every owner in this lineage already takes
`(slot_ids, positions)`, so the runner adds no second addressing scheme: the row
set is a permutation of admitted slots, and `_plan_step` rejects a duplicate
slot, an unadmitted slot, an out-of-vocabulary token, a position past the
per-slot capacity, a context that needs more paged blocks than a slot holds, and
a context past the index capacity — all before the first prepare. A rejected step
dispatches nothing and leaves the position mirror untouched (asserted).

**`capture_logits` both ways.** `capture_logits=True` downloads the
`[rows, vocab]` matrix; `capture_logits=False` takes the committed row-wise
argmax kernel and downloads `[rows]` ids. Both paths are tested on GPU against
each other.

**Import is a per-block copy, not a scatter.** The committed
`qwen4_exp_qsa_scatter_index_keys_f32` reads its source *contiguously* and writes
through one block table, which is right for the append path (the source is a
freshly projected chunk in position order) and wrong for a hand-off (the source
is a slab addressed by the *source's* physical block ids). The first version of
this unit used that scatter; it passed the GPU test only because a fresh c1
runner's block table is the identity. The import now copies each block prefix
explicitly: source offset from the source's block id, destination offset from the
slot's block id, and only the valid rows of the last block, so a source's
unwritten tail cannot land in a new request's slot. A unit test drives source
blocks `[7, 9]` into slot blocks `[2, 3]` with a 300-position prefix and asserts
the exact offsets and lengths (`256` then `44` rows).

**Slot reuse goes through the index owner's reset.** `_zero_slot` memsets the
persistent slabs and then calls `index_state.reset_slot(slot)`, which advances
that slot's generation. Writing `cursor_host`/`pooled_count_host` directly would
have left a rollback token from the previous request applicable to the new one's
keys; the generation bump is what invalidates it. A unit test asserts the
generation advances on `admit`, `reset_slot`, and `release`.

**Recovery is release-and-readmit.** The stages are not transactional: a device
failure after the index append leaves the affected slots partially advanced.
The docstring states that instead of implying a retry; `release`/`reset_slot`
and re-admission is the documented recovery, and both zero the slot.

## A real bug found by the GPU test

`step`'s logits readback called `copy_device_to_host(host_array_ptr(logits),
self.logits, runtime=...)` without a size. The default size is the *source
buffer's* size, and the logits buffer is allocated for `state_slots` rows, so a
two-row step wrote 768 bytes into a 512-byte host array. The step itself returned
correct logits; the process aborted at exit with `corrupted size vs. prev_size`.
Bisecting the step with stage no-ops localized it to the download in three runs.
Both downloads (logits and argmax ids) now pass an explicit size, and the test
helper `_download` asserts `host.nbytes <= buffer.nbytes` before copying.

Fixture geometry for the GPU comparison: 3 slots, `max_positions=300`,
`block_size=256`, hidden 256, residual 512, 2 branches, 2 query heads / 1 KV head
of 8 dimensions, index 2 heads x 8 dimensions, ratio 2, budget 2 (bound 5), GDN
2 k-heads / 4 v-heads of 128 dimensions, conv kernel 4, 4 experts top-2, ffn 256,
vocab 64. Two requests start at positions 0 on slots 2 and 0 and advance seven
steps, so steps 5 and 6 run the sparse selection for both rows and select from
keys captured while the rows were still dense.

**Control, exact.** Row-to-slot mapping and positions after every step; each
row's K/V lands only in its own slot; slot 1 (never stepped) stays bit-zero in
the KV cache and the index slab; a repeat run from the same state reproduces the
logits and state bytes; the same two requests permuted across rows reproduce each
slot's own state byte for byte; a malformed row set, a foreign owner token, and a
mismatched import source dispatch nothing and change no bytes; release and
re-admit start from zero.

**Arithmetic, measured.** Per step, `max|c1 - batch|` was printed for both rows
and both state families. Worst observed values over seven steps:

| quantity | worst `max|c1 - batch|` |
| --- | --- |
| logits, row 0 and row 1 | `0.000e+00` (bit-identical) |
| GDN recurrent state | `9.3e-10` |
| GDN conv state | `0.000e+00` |
| index raw keys | `0.000e+00` |
| PLE n-gram history | equal |
| c1 import step logits | within `2e-2` (asserted bound) |

The two rows' logits differ by `3.4e-03` to `1.1e-02` across the same steps,
which is asserted (`ROW_DISTINCT_MIN = 1e-4`): without it a transposed row/slot
map could pass a row-equality check. The asserted bounds (`LOGIT_ATOL = 2e-2`,
`STATE_ATOL = 5e-2`) are the measured envelope with wide margin because the GEMM
and GDN variants are selected per target arch and only gfx1151 has been measured.
The fixture's logits concentrate on one vocab id, so the argmax-path test checks
per-row equality against the host argmax of the identical step rather than id
diversity.

No production-profile numerics, no task gate, no serving path, no speed claim:
this unit is the runner, its focused tests, and the c1 hand-off. Nothing here
says how the batch path behaves on a real checkpoint, at longer contexts, or
against the calibrated envelope in `docs/EXECUTION-PROFILES.md`.

## Next

- **Prefill chunks.** A slot holds one live token per step; a multi-token chunk
  needs the prefill owners plus per-token state rows.
- **MTP.** Not claimed: no replay after a rewind, and the index append is
  append-only.
- **Capacity and compaction.** Slots are fixed at construction and nothing is
  shared, migrated, or compacted; the state move on compaction is unimplemented.
- **Kernel variants.** The generic `..._rows_f32` QSA bodies are used for every
  head dim; the `h256_wave_rows`/`rows_wave32` variants are still unwired.
- **Serving.** `decode_batch` still loops c1 runners. Wiring the batch runner
  into the engine needs the scheduler-side slot assignment, the prefill-to-decode
  hand-off policy, and the production numerical gate.
- **Debt** recorded in `docs/REFACTOR.md`: the per-block import copy loop, the
  four-way `_zero_slot`, and the duplicated admission mirrors.
