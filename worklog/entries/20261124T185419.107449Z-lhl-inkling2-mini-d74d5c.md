# Fix the Inkling GGUF resident decode path, record its graph from the first step, and find where its time goes

## Summary

Campaign task 5, the opt-in whole-token decode graph. The graph now reproduces the resident eager
path exactly and records from the first decode step of a session, so it runs on ordinary prompts.
Getting there found that the resident path it replays returned wrong output on every request after
the first in a process, and that two kernel choices made the path slower than the default at depth.

Measured on `epyc` (Radeon Pro W7900, gfx1100, HIP 7.2.53211), mainline `UD-Q4_K_M`, FP32 KV,
one greedy stream, prefix cache off, drafting off, `fast` profile, 128 outputs and three
repetitions after one warmup, with this unit's changes in the tree:

| Path | 47 prompt tokens | 1,717 prompt tokens | Known-answer cases | Teacher-forced KL against `strict` |
| --- | ---: | ---: | ---: | ---: |
| Default (no Inkling variable) | 18.01 tok/s, 55.5 ms | 17.52 tok/s, 57.1 ms | 9 of 12 | mean 1.98e-3, top-1 99.5% |
| Device routes | not timed | not timed | 9 of 12, default's IDs | mean 1.28e-3, top-1 99.5% |
| Device routes + resident decode | 32.89 tok/s, 30.4 ms | 14.18 tok/s, 70.5 ms | 9 of 12, default's IDs | mean 1.39e-3, top-1 99.5% |
| Device routes + resident decode + graph | 33.33 tok/s, 30.0 ms | 14.20 tok/s, 70.4 ms | 9 of 12, default's IDs | mean 1.39e-3, top-1 99.5% |

- **The resident path was wrong after the first request.** Its residual-read queries were uploaded
  once into the step arena. That arena is shared scratch: the next request's prompt blocks wrote
  over it. The known-answer check scored 2 of 12 for resident decode and for the graph, against 9 of
  12 for the default path, with the first token right and the rest babble. The queries now live in
  the projection's residency. The same check scores 9 of 12 with the default path's IDs.
- **Replay is exact.** Five fresh 48-token greedy graph runs each after a different-length warm
  request, at 67 and at 1,717 prompt tokens, matched resident eager with zero logit difference at
  every one of 47 steps. The same 640 teacher-forced rows give the graph and resident eager
  identical KL statistics.
- **Where the time goes.** A kernel trace of the default path puts 19.7 ms of the 57 ms step into
  1,618 kernels after 1,717 prompt tokens (17.4 ms into 1,568 after 47). The rest is host work
  between them. The resident path removes that host work and is then bound by its own kernels.
- **Two kernel choices cost 76 ms per step at depth.** Single-row projections went through rocBLAS
  GEMM, which answers them with a 64x64-tile Tensile kernel at 143 µs against 12 µs for GEMV: 215
  launches, 30.6 ms. Attention runs the block kernel at one row: 919 µs per visit at 1,717 keys,
  45.5 ms of the step. The first is fixed here (96.6 to 70.5 ms per token at 1,717). The second is
  the next unit.
- **The default `fast` path measures 1.98e-3 mean KL against `strict` on this suite**, above the
  1e-3 envelope in [Execution Profiles §6](../../docs/EXECUTION-PROFILES.md#6-production-numerical-gate).
  This is a development measurement with the gate's row metric, not a gate run: 20 prompts (the 12
  known-answer prompts and 8 plain prompts), 32 teacher-forced rows each. It matters for the step
  that makes a plan the default.

## Changes

- `hipengine/runtime/inkling2_gguf.py`: `_query_bank` replaces `_stage_query_uploads`. The
  residual-read queries are one array in the projection's residency; the step arena no longer has a
  `queries` region. `_graph_step` records whenever the session has KV state and the position is at
  or below the log-scaling floor; `_graph_min_position` is removed.
- `hipengine/runtime/inkling2_device_attention.py`: a recorded `step_block_resident` bakes
  `min(extent, capacity)` instead of `min(extent, live)`, because a replay serves later steps with
  more live keys. The eager path is unchanged.

The graph at 1,717 tokens ran 92.0 ms of kernels inside a 105.9 ms step under the profiler, so it
is bound by kernels, not by launches. Every value in the tiled attention row is a serial walk over
the live keys: about 0.5 µs per key, one value vector loaded from global memory per iteration of
the online-softmax chain. The default path's `split_values` kernels have the same chain shape; the
chunked variant hides it with 27 parallel blocks.

## What the earlier numbers were

Any rate or output recorded for resident decode before this unit, in a process that had already
served a request, was taken with overwritten queries. That applies to the first measurements of
this session, whose harness warms up before it measures: 10.3 tok/s at 1,717 prompt tokens and an
output that repeated one token. The timings still describe the kernels that ran; the outputs do not
describe the model. I have not established which procedure the November 24 entry behind R0527
used. Its claim that the 48-token greedy chain is token-identical to the eager path did not hold
on the known-answer prompts once a request had come first, and the two divergent runs in its graph
sample may have had the same cause.
