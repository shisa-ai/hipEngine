# MTP six-node GPU failures are order-dependent VRAM exhaustion

## Summary

The six MTP GPU nodes recorded by the interrupted `bg59` full-suite run are not
independently defective. All six pass fresh, both at the task's stated commit
`8a9b6e113` and at HEAD `bb17f2f63`, run standalone and run together in one
process. They fail only inside a long full-suite process.

The mechanism is process-global VRAM exhaustion. Every failing node constructs
`Qwen35GGUFResidentSession(model_path=Qwen3.6-35B-A3B-UD-Q4_K_M.gguf)`, whose
weight materialization needs about 20.5 GiB and whose first `hipMalloc` is
where a starved load dies. A bounded pre-MTP prefix run held a persistent
27.6-31.2 GiB allocation on GPU0 (48.3 GiB total) before the MTP files, leaving
too little free VRAM for that load. The failure is deterministic under a
synthetic hold: with 24 GiB already allocated on GPU0, the resident node fails
with `hipengine.core.hip.HipError: HIP error 2: out of memory` inside
`hipengine/loading/materialize.py` `hipMalloc`.

No MTP test or MTP production file is implicated, so no MTP-scoped repair is
made. The persistent allocation's owner is not yet localized.
