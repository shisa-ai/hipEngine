# WMMA tile sweep and mul_mat_q port plan

## Summary

Measured the existing Q4_K dual WMMA compact kernel against the retained
rowbatch_bf16 owner at the real MoE shape (5080 rows, 512 experts, 2048->640
dual, 26.63 GFLOP). Best tile (16,16) reaches 12.97 ms best / 2.05 TF/s vs the
owner's 22.67 ms / 1.18 TF/s; stable (64,16) gives 19.17 ms / 1.39 TF/s. llama
mul_mat_q WMMA reference is 4.9 ms / 3.4 TF/s. The WMMA arithmetic class is
already in-tree (f32 accumulator, f32 scale application, f16 operands) and is
numerically compatible with the current production stack's bf16-FMA class.

- Tile sweep recorded in the module-parity microbench artifact.
- Defined the next optimization unit: port the llama mul_mat_q dataflow
  (SRAM-staged I x J tiles, cooperative K loads, multi-warp blocks) to a new
  selected-expert kernel; lineage ggml-org/llama.cpp@17252c769
  ggml/src/ggml-cuda/mmq.cuh + mma.cuh + mmq-config-rdna3-5.cuh.

## Validation

  script and JSON at /tmp/qwen4exp_q4k_wmma_vs_rowbench.py and
  /tmp/qwen4exp-q4k-wmma-vs-rowbench.json.
- FLOP accounting: dual 5080x640x2048x2x2 = 26.63 GFLOP per launch.
