# Recycle bounded verifier hidden scratch at 4K

## Summary

The max-capacity Qwen3.8-27B gfx1151 B3 sweep consistently reached an HSA page
fault when target verification began after a 4,096-token prefill. The verifier
was indexing the reusable prefill hidden scratch by the absolute context start,
although the right-sized scratch allocation held only 4,096 rows. The first
four-row target block therefore wrote rows 4,096-4,099 beyond the allocation.
The verifier now recycles the dead prefill scratch from row zero whenever the
absolute slice would exceed its bounded capacity. No model math, resident
ownership, target row shape, or transaction semantics changes.

## Changes

- Added `_gguf_verify_hidden_scratch_row_start()` with explicit start, row-count,
  and capacity validation.
- Kept the existing absolute offset while it fits, retained row zero for
  prebuilt bulk scratch, and selected row zero for a post-prefill target block
  that would exceed the bounded hidden allocation.
- Added boundary RED/GREEN coverage for starts 2,048, 4,094, and 4,096, the
  prebuilt route, and an oversized target block.
