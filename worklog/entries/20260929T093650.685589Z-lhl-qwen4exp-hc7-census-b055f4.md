# HC-7 census: the stream-boundary class ceiling is 2% of prefill

## Summary

Ledger HC-7 asked for a last-reader census of the remaining stream
intermediates before removing or fusing any. It is done, and it closes the item:
the whole class has a **2.03% ceiling**, and the one redundant intermediate found
prices at **0.10% of prefill**.

The census was designed around HC-3's lesson. That item was recorded as "no
arithmetic risk -> remove the write" and measured 2% **slower** when the write
was removed. A census that only classifies writes as dead or live would repeat
that mistake, so this one prices the owners.

Three results:

1. **The prefill is kernel-bound.** 15600.44 ms of kernels in a 16159.40 ms
   window, 558.97 ms outside. Adding device copies moves that by 2.71 ms.
2. **The class ceiling is 2.03%.** The family taxonomy sums to exactly its
   kernel union (15741.963 ms), and `elementwise_norm` - which holds every
   stream elementwise op, conversion and norm - is 319.494 ms.
3. **One redundant intermediate, priced at 0.10%.** `scratch.moe_f32` is
   written by `bf16_to_f32(moe.output)` and read only by
   `qwen4_exp_gr_write_bf16_f32`. The pair fuses **bit-identically**.

A trap is also documented so it is not cited later: the artifact's host-API
table shows 246 `hipMemcpy` calls summing to 14086.59 ms, which looks like 87%
of wall time. It is host time blocked on stream drain. **Only 5 device copy rows
exist in the window, totalling 2.711 ms.**

## Validation

No new measurement. The census is arithmetic over an existing, already-validated
artifact, and the two checks that make it trustworthy are in the packet:

- The family taxonomy sums to **exactly** the audit window's kernel union
  (15741.963 ms), so attribution is complete and no family is hidden in a
  residual bucket.
- The two captures in that artifact are separate runs with separate kernel
  unions (15741.96 ms audit, 15600.44 ms memory) and separate wall windows
  (16319.89 ms, 16159.40 ms). Every ratio in the packet is computed within one
  window and names which. An earlier draft of `census.json` mixed them; it was
  corrected before commit.

Bit-identity of the proposed `moe_f32` fusion is read off the kernel source
rather than measured: `gr_write_bf16_f32_kernel` takes `block_output` only as
`scatter * block_output[block_offset + column]`, so an inline bf16->f32 convert
yields the same f32 operand. That is a source argument, not a test result.

Host identity is inherited from the source artifact: Radeon 8060S (gfx1151),
machine-id `55ea6c509d0b49eea8de7094a1023668`, kernel 7.1.6-1-cachyos.
