# The TP2 prefill gap is unsharded attention, and it is worth 11.7%

## Summary

Attribution, not a performance change. The TP2 bulk prefill runs 490.8 ms at 512
tokens (1043.2 tok/s) against llama.cpp TP=2's measured 385.4 ms, and the whole
104.8 ms gap now decomposes into two measured terms.

Rank 0 (W7900) is the pacer. Its prefill is 233.4 ms of attention, 188.4 ms of
sharded MLP chain and 59.4 ms of exchange - 7.52 ms per layer, all of it
device-busy.

| phase (rank 0) | per layer | per prefill | share of wall |
| --- | ---: | ---: | ---: |
| attention (replicated) | 3.647 | 233.39 | 47.6% |
| mlp_chain (sharded) | 2.944 | 188.43 | 38.4% |
| mlp_exchange | 0.928 | 59.42 | 12.1% |
| other (norms, residuals, tail) | 0.149 | 9.54 | 1.9% |

The attention phase is **fully replicated**. `_bulk_attention_layer`
(`hipengine/distributed/tp2_generate.py:968`) calls the full-width
`_run_full_attention_prefill_attn_rows` and
`_run_linear_attention_prefill_attn_rows`, which project `2 * q_width` and read
the unsharded `attn_q`/`attn_k`/`attn_v`/`attn_output` weights, so both ranks
execute identical attention work. That is the missing half of the TP2 speedup:
llama.cpp's `-sm tensor` shards attention as well as the MLP.

A head split removes 116.7 ms of replicated work for one added reduce, worth
**57.3 ms (11.7%)**, and it accounts for the gap exactly: 116.7 (attention half)
+ 188.4 (chain) + 118.8 (two reduces at this route's 0.93 ms/layer) + 9.5 (other)
= 433.5 ms, and the 48.1 ms left against the fork's 385.4 ms is exactly the
0.38 ms/layer by which this route's reduce exceeds the 0.55 ms/layer that
385.4 ms implies.

## Validation

`scripts/tp2_prefill_phase_attribution.py --prompt-tokens 512 --repeats 3
--per-layer --json /tmp/tp2_phase_perlayer_even.json`, exit 0, on the same host
(epyc, W7900 at `0000:0d:00.0` + RX 7900 XTX at `0000:10:00.0`), same model
(`/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`), even split, `reduce_mode=device`,
source-F16 owner off.

- Headline wall 490.778 ms over paired samples `[490.778, 491.505, 491.558]`;
  uninstrumented 487.2 ms, so the instrumentation costs 0.74%.
- Phase sums cover 99.4% of the wall on both ranks and both ranks total 488.0 ms,
  so the ranks are balanced and the pacer's own span is the wall.
- **Attention is device-bound, not enqueue-bound**: 233.39 ms device span against
  78.30 ms host span.
- **Per layer type**: the 48 linear-attention (GDN) layers carry 180.99 ms
  (3.771 ms/layer) and the 16 full-attention layers carry 52.64 ms
  (3.290 ms/layer), so GDN is 77.5% of the phase.
- **GEMM-bound, not kernel-bound**: at 512 tokens the phase's arithmetic is
  119.5 GFLOP/layer (GDN) and 113.8 GFLOP/layer (full attention), giving 31.7 and
  34.6 TFLOP/s against 46.5 TFLOP/s for the sharded MLP chain at the even split's
  8704-wide shard (136.9 GFLOP/layer). The attention phase therefore runs at
  68-74% of the chain's rate, which is the smaller GEMM shapes (k/v at N=1024,
  o_proj and ssm_out at N=5120) rather than a kernel problem, and the projections
  dominate the phase, so a head split halves it.
- **Rank skew**: device 0 is slower at every replicated phase (attention 233.39
  vs 208.86; chain 188.43 vs 168.04), so the even split makes the slower card the
  pacer and device 1 absorbs 45.9 ms of extra spin wait inside `mlp_exchange`.
- **The reduce is near the platform floor.** `mlp_exchange` moves 5.24 MB per
  rank per direction (bf16 partial, 512x5120) at ~11.3 GB/s of PCIe traffic,
  against 7.09 GB/s (`all_reduce:rows1024:bf16`) and 11.52 GB/s
  (`broadcast:rows1024:fp32`) measured for the staged transports on this host in
  `benchmarks/results/tp2_collective_bench.json`. Replacing the peer-spin read
  with a copy-engine transfer would not beat that ceiling, so the exchange is not
  the recoverable cost.

Two alternatives were ruled out by existing measurement rather than by new work:

- **The source-F16 rocBLAS prefill owner** (`use_t16_f16_rocblas_prefill`, off by
  default) is worth +3.97% (490.0 -> 471.3 ms, commit `22b874f78`) and fails the
  production envelope on the repaired matching-teacher gate (heldout mean_kl
  0.001148 against a 0.001 bound, max_kl 0.056886 against 0.05). It is not a path
  to the gap.
- **The uneven split** is already applied and already measured: 0.44/0.56 gives
  484.2 ms against the even split's 490.1 ms (+1.2%), because the attention phase
  is replicated and cannot be rebalanced - only the 188.4 ms chain can, and the
  sum of the two chains grows (356.5 -> 385.3 ms) as the split moves away from
  even.

`python3 scripts/sync_benchmark_readme.py --check`: synchronized.

## Next

Implement full-attention head sharding, then linear-attention group/state
sharding (the plan doc's order). The infrastructure is closer than it looks: the
shard manifest already computes both slice sets (`attn_q`/`attn_k`/`attn_v` as
head groups, `attn_output` and `ssm_out` row-split, `attn_qkv`/`attn_gate`/
`ssm_alpha`/`ssm_beta`/`ssm_a`/`ssm_dt.bias`/`ssm_conv1d` by GDN value head) and
`_rank_payload` in `hipengine/distributed/shard_weights.py` already slices any
role, so the work is admitting the `group` kind to the payload builder and giving
each rank a sharded attention geometry. Expected 490.8 -> ~433.5 ms (1043 ->
1181 tok/s) before any reduce improvement.
