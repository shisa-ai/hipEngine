## Corrections

1. **Arithmetic correction (envelope artifact ea8e2a274):** the commit
   message said "995/996"; the artifact's correct counts are **991/996
   agreements (99.50%)** - five flips. These are observed rates over this
   probe's rows, not an established "true" flip rate.

2. **The "T1 is BLOCKED for decode routes" claim in the September 10
   worklog is withdrawn as normative guidance.** It described the
   screening harness's trajectory-exactness scope, not the binding
   contract. The normative route is production correctness
   (docs/EXECUTION-PROFILES.md 6.1): exact control/ownership plus the
   calibrated envelope. A trajectory mismatch routes to the declared
   production gates rather than blocking. No further exact-reduction
   tuning rounds unless production numerics actually fail.

3. **The 996-row envelope result is incremental-drift evidence, not
   promotion evidence.** It compares against the production incumbent
   (not the declared strict teacher), runs two repeats per arm (the
   calibration standard is three), and does not include the state/
   isolation gates or heldout/task checks the contract requires. It is
   retained as the drift characterization of the packet; full
   qualification of the combined production stack is separate.

4. **Campaign projection correction (R11 paragraph at the R2e entry):**
   "down bit-exact" couples the slower exact-tree kernel (134.5us, -14%
   vs the incumbent) with projected TG gains. The speed in the R11
   projection comes from the T1 vectorized down (68.6us, +72%) and the
   warp256 gate/up (56.6us, 2.0x). The projected pair gain is a
   projection, not an achieved decode win; it holds only if the
   respective packets pass the production envelope and the
   same-residency serving-path A/B.

## Probe isolation hardening

`scripts/qwen4exp_moe_decode_warp_logits_probe.py` now controls BOTH
route flags explicitly in every arm (an externally-set DOWN env can no
longer leak into the incumbent), selects packets explicitly
(`--packet dual|fast-down|pair`), records both flags and the arm
configuration in the report, and clears both flags on exit. The
combined-packet run launched before this hardening toggled both flags
per arm in its private copy (isolation was correct there), but the
committed script did not - fixed.
