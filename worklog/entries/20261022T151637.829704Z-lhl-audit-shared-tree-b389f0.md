# Audit rows become a cache of the tracked tree

## Summary

The audit was a treadmill for several agents sharing one checkout.

- `check` failed with "inventory was stale" after any commit that moved a line.
  The committed 5.7 MB of `audit/inventory/` and `audit/findings/` JSON stores
  locations, so any agent's commit, or a merge from origin, left everyone's
  copy behind. Two agents regenerating it conflicted.
- Scans read the working directory. Another agent's untracked script or
  unstaged worklog entry changed your gate result.

Rows are now a git-ignored local cache: a pure function of the tracked tree,
recomputed whenever a fingerprint of the tree and the extractor code changes.
Scans read only tracked and staged files. The committed audit state is the
decisions, the budget and the migration records.

## Changes

- `audit/hipaudit/core.py`:
  - `tree_files()` and `in_tree()` enumerate and test membership against
    `git ls-files` (tracked plus staged). They fall back to the filesystem
    outside the repository, for test fixtures.
  - `tree_fingerprint()` hashes the paths, sizes and mtimes of tracked files,
    plus the extractor sources.
  - `load_triage()` keeps the most recently reviewed copy of a duplicated id,
    and `load_archive()` drops repeated lines.
- Extractors (corpus, docs, kernels, ledger, worklog, doc-path-drift) read the
  tracked tree. Worklog entries count once staged, matching
  `scripts/worklog.py check`.
- `audit/audit.py`:
  - `ensure_current()` reuses the cache while the fingerprint matches; every
    row-reading command calls it.
  - `check` no longer fails on drift. `--rescan` (alias `--refresh`) forces a
    rescan.
- `report.save_budget` rewrites only when a ceiling moves, so concurrent
  refreshes do not conflict over the date.
- `.gitignore`: `audit/inventory/`, `audit/findings/`, `audit/runs/`, all now
  untracked. `.gitattributes`: `merge=union` for `audit/triage/*.jsonl` and
  the archive.
- `audit/README.md` has a "Several agents, one tree" section. The agent
  playbooks call the rows a cache.
- `kernel/.../gemma4_rope.py` (expired) is resolved: `runtime/gemma4.py:58` and
  `runtime/gemma4_assistant.py:86` import it.

## Validation

- `python3 -m unittest discover -s audit/tests`: OK (131). New tests cover:
  - cache reuse and invalidation;
  - an untracked file left out of the tree;
  - the union-merge duplicate keeping the later review.
- `python3 audit/audit.py check`: `audit: ok` in 41 s on a changed tree; a
  cached `status` takes 0.2 s.
