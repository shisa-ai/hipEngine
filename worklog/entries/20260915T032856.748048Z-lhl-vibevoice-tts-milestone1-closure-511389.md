# VibeVoice-TTS milestone 1 closed: fixtures frozen, weights fully accounted for

## Summary

Milestone 1 of `docs/MODEL-VIBEVOICE-TTS.md` is complete. All six closure
criteria are met, with the weight inventory as the last one to be filled.

The headline numbers: the checkpoint is **1204 tensors, 2,704,021,987
parameters, 5.037 GiB**, and **every one of them is accounted for** -- zero
orphan keys, and the single key absent from the checkpoint (`lm_head.weight`) is
tied to `embed_tokens.weight` with verified shared storage. The frozen fixtures
reproduce **byte-identically** from a fresh run.

## Changes

- `scripts/vibevoice_tts_weight_inventory.py` (new): reads safetensors headers
  (shapes and dtypes only, so it does not materialise 5.4 GB) and reports tensor
  counts, parameters and bytes per component. With `--verify-model` it loads the
  fork's model and checks for orphans, missing keys, and that the `lm_head` tie
  is real storage sharing.
- `tests/fixtures/vibevoice_tts/weight_inventory.json` (new artifact).

## Notes

- **The "1.5B" label is the language model alone.** `model.language_model` is
  1,543,714,304 parameters, and the tokenizers, diffusion head and connectors add
  another 1,160,307,683. This is the concrete accounting behind the doc's warning
  that the label names only the LM scale.
- **The two scaling factors are buffers, not parameters.** `register_buffer` puts
  them in the state dict and on disk but not in `.parameters()`. My first
  comparison used `.parameters()` and disagreed with the header count by exactly
  2; the fix was to compare against the state dict excluding tied keys. Worth
  recording because the failure looked like a real accounting discrepancy rather
  than a classification detail.
- **`lm_head.weight` is genuinely tied, not a same-shaped copy.** The check
  asserts `data_ptr` equality between `lm_head.weight` and
  `embed_tokens.weight`, so a silent untie would fail the script rather than
  leave the key set looking fine while the arithmetic changed.
- The inventory script reads only safetensors headers, so it runs in the
  hipEngine venv as well; only `--verify-model` needs the oracle venv.
- Unchanged caveat: all of this was produced on gfx1151 (Radeon 8060S), not the
  default gfx1100, and these are reference outputs rather than hipEngine
  performance claims.
