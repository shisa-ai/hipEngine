# P6e harness now refuses to certify the wrong route: fail-fast on the effective KV layout

## Summary

The previous unit fixed the harness's KV configuration and got all eight gates
green on the resumable INT8 route. It did not stop the next edit, or an explicit
`--kv-storage` override, from silently reverting to BF16 and producing eight green
gates that describe the default route — which is exactly the false-positive class
this whole audit found. This unit adds the guard the reviewer asked for: assert the
effective layout before the workload runs, and abort if it is wrong.

## Changes

- `_assert_resumable_configuration()` reads the effective
  `kv_attention_source` for the resident sessions and returns a pass/fail record
  with the observed sources, the required source, and a detail message that names
  the fix.
- The harness asserts immediately after the reference run — the first point at
  which a session exists — and **before** the cancellation, blocking, and
  slow-consumer arms, so a wrong route produces no gates at all rather than
  misleading ones.
- On failure it prints the reason to stderr, writes an artifact with
  `aborted_before_workload: true` and `gates: {}`, and exits non-zero.
- `--require-resumable-route` / `--no-require-resumable-route` (default required)
  allows the default route to be exercised deliberately.
- The configuration record is included in the **passing** artifact too, so the
  evidence shows the assertion ran rather than only showing it when it fails.

## Validation

**RED case**, `--kv-storage auto` (the historical misconfiguration):

```
EXIT_CODE=1
passed: False | aborted: True | claim: False
gates: {}
effective sources: {'bf16': 2.0} | resumable sessions: 0.0
reason names the fix: True
```

The abort fires before the workload, reports the measured source rather than an
assumption, and the message names both remedies. Artifact:
[`abort on wrong route`](results/2026-09-11-w7900-p6e-cancel-refill-abort-on-wrong-route.json).

A first attempt at this guard returned a bare integer where `main()` expects the
artifact dict, so a clean fail-fast surfaced as `TypeError: 'int' object is not
subscriptable` with the reason buried above it. Fixed, with a test that inspects
the abort path so the shape cannot regress.

**GREEN case**, default INT8 configuration, full workload:

| Reading | Value |
| --- | --- |
| `passed` | true |
| `configuration.passed` | true (`required: true`) |
| `configuration.effective_kv_sources` | `{"int8_direct": 2.0}` |
| `oracle_observed_peak_owners` | 1.0 |
| all eight gates | PASS |
| acknowledgement | 763.963 ms |
| refill / reference max gap | 38.553 / 41.844 ms |

Three consecutive INT8 runs now agree to within 0.08% on acknowledgement
(764.591 / 764.025 / 763.963 ms) and within 2.4% on the refill gap. Artifact:
[`P6e service cancel/refill proof`](results/2026-09-11-w7900-p6e-cancel-refill-service-proof.json).

38 tests pass in `tests/test_gguf_p6e_cancel_refill_proof.py`. `performance_claim`

## Honest limits

- The assertion reads the settled per-session value after the reference run, so a
  session that changed layout later in the run would not be caught.
- `effective_kv_sources` counts sessions, not requests. A run where one session is
  resumable passes even if another is not; the gate reports the counts so this is
  visible rather than implied.
- The guard asserts the *layout*, not that the layer-outer executor was selected.
  Route selection is evidenced separately by the while-live oracle-owner peak,
  which is the signal the engagement gate keys on.
- Layer budget 4 and a 600 ms cancellation delay are the only settings exercised
  here, so the reviewer's coverage requests remain open.
