# Correct the full-attention shared-memory byte figures

## Summary

Supersedes the shared-memory byte figures in
`worklog/entries/20260927T175027.679637Z-lhl-qwen4exp-fullattn-context-promoted-9304df.md`.

That entry quoted the promoted route's dynamic shared-memory request as
**25,607 bytes** for the int64 offset table and **17,223 bytes** for the int32
table at `max_context_len` 2048. The correct values are **26,663** and **18,471**
bytes.

The error was using the `..._c1_exact_spans` launcher's float budget,

    (max_context_len + threads) * sizeof(float) = (2048 + 256) * 4 = 9,216 B

instead of the `..._batch_fixed256_spans` and promoted launchers' budget,

    (max_context_len + max_warps + head_dim + value_groups * head_dim)
        * sizeof(float) = (2048 + 8 + 256 + 256) * 4 = 10,272 B

a 1,056-byte understatement that carried through to both totals.

## Changes

- `benchmarks/results/2026-09-27-fullattn-context-promoted/README.md`:
  25,607 -> 26,663 and 17,223 -> 18,471 bytes.
- `benchmarks/results/2026-09-27-fullattn-context-promoted/promoted-route.json`:
  the same two figures, plus a new `shared_memory_bytes` block carrying the
  formula, both launch geometries, and this correction.
- No code, test, or benchmark command changed.

## What is affected and what is not

Not affected: every measured timing, the byte-identity result, the 1.403x and
1.260x lever attribution, and the residency conclusions. 26,663 bytes gives
`floor(65536 / 26663) = 2` blocks per CU and 18,471 gives
`floor(65536 / 18471) = 3`, which are the same two and three blocks the entry
claimed, so the argument that residency was the binding constraint stands on the
same evidence.

Affected and corrected here: the byte totals in the benchmark artifact README and
`promoted-route.json`. The artifact now also records the formula, both launch
geometries, and this correction, so the derivation is checkable rather than
restated.

Not corrected in place: the worklog entry itself. Committed entries are immutable,
so this decision entry is the correction of record and the promoted-route entry
should be read with this one.
