# Read the Inkling controller rows in place

## Summary

Fourth unit of the decode fusion work (task 10), after
[the residual step](20261125T100950.825067Z-lhl-inkling2-mini-faaea7.md). The controller
chain packed its inputs before running: six device copies and one host upload at each attention
visit that has controllers, and nine device copies at each MLP controller blend. Two kernels now
read the input, message and norm weight rows where they are. Each block of the resident traversal
is bit for bit what the packed kernels give.

**Decode bench** (`fast`, W7900, mainline `UD-Q4_K_M`, 128 outputs, five repetitions after one
warmup, `scripts/inkling2_decode_bench.py --prompt-tokens 47 575 2057 --reps 5 --warmup 1
--counts`). The eager resident arm alternates the committed tree with the working tree, two runs
each; the decode graph and public rows are one run each.

## Changes

- `inkling2_controller.hip`: the row bodies of the input and blend kernels are device functions;
  `inkling2_controller_input_direct` and `inkling2_controller_blend_norm_direct` call them with one
  input, message and weight pointer per controller. Registered as `input_direct` and
  `blend_norm_direct` on both HIP backends.
- `Inkling2GGUFDeviceProjections._controller_kernels_direct` runs the chain over rows that stay
  where they are. The cursor then holds only what the chain writes: down inputs, the two gate
  projections, the blended rows and the gate values. That is smaller than the packed extent the
  caller already reserves, so no arena grows.
- `_resident_body` hands the attention visit's input and message rows and the norm weight vectors
  to the plan instead of copying them; `blend_controllers_resident` takes the in-place path when
  the kernels are registered.

## Validation

- `tests/test_gpu_inkling2_controller_direct.py` (5 passed on the W7900): with inputs, messages and
  weights in separate allocations per controller, the in-place kernels equal the packed ones bit
  for bit for 1, 2 and 3 controllers over 1, 2, 3 and 5 rows.
- The Inkling GPU and unit test files pass on the W7900 with the model present: 395 passed in
  3 minutes with `HIPENGINE_INKLING2_MINI_GGUF` and `HIPENGINE_INKLING2_TEST_BACKEND=hip_gfx1100`
  set. Without the first variable the five model-level tests are skipped; without the second the
  profile-gate smoke test fails on `resolved_backend must be concrete, not 'auto'`, which predates
  this unit.
- A `rocprofv3 --kernel-trace` of the resident arm (47 and 1,717 prompt tokens, 33 outputs;
  `/tmp/inkling-fuse-u6/e`) shows `inkling2_controller_input_direct` at 5.2 microseconds median and
  `inkling2_controller_blend_norm_direct` at 8.0, and 3,840 copy kernels against 16,180 before.
- The first version of this unit failed in prefill: a patch overwrote the `norm_names` parameter
  of `_attention_plan` with an empty tuple. The model-level tests above catch it; the kernel tests
  alone did not.
