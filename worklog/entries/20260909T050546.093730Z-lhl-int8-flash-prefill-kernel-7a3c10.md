# INT8 flash prefill kernel + dense chunk row-cap fix

## Summary

Tile/split-K the direct INT8 prefill attention kernel toward AOTriton-competitive speed (the recorded next step from 41f19ea95), plus a pre-existing dense chunk row-cap crash fix it exposed.

## Question

The oracle-free direct INT8 prefill route (HIPENGINE_GGUF_INT8_PREFILL_DIRECT,
default OFF, commit 41f19ea95) was speed-blocked: its sequential online-softmax
kernel measured 164.2 tok/s at 8,192 tokens versus the oracle route's 761.6
(4.6x), attributed to the attention kernel. Tile/split-K it toward
AOTriton-competitive speed so the capacity ladder (and promotion) become
practical.

## Findings

1. **The 4.6x attribution was mis-baselined.** The 761.6-vs-164 comparison held
   only under the `--public-ar-profile` fast path (WMMA prefill projections);
   without it every route measures ~160 tok/s regardless of attention kernel.
   Reproduced 767.0/767.4 tok/s for the oracle control with the exact
   engine-comparison command (RX 7900 XTX GPU1, isolated).
2. **A pre-existing crash blocked mid-context harness points**: the gfx1100
   dense H5120 Q4_K_M scratch row-cap policy (1,024 rows at capacities above
   1K) disagreed with the auto chunk policy (4,096-row full-attention query
   chunks below the 52K low-memory threshold), so `for_chunk` overflowed the
   positions buffer (`copy size 32768 exceeds device buffer size 8192`) on the
   committed tree at 8,192/16,384 tokens. Fixed by clamping both chunk-size
   resolutions to the row cap (`_dense_prefill_scratch_row_cap`).
3. **Kernel bottleneck sequence (synthetic worst-chunk probe, 16 launches,
   HIP-event GPU time)**: sequential 2,846 ms/layer-chunk -> per-q-head
   two-pass 2,846 (no gain; 12x/6x K/V re-read per q head) -> GQA-grouped
   flash (no staging) 216 -> +token-tile ILP 178 -> +shift block mapping 156
   -> +cooperative 16B-vector LDS tile staging 141 (on a synthetic 96/8/128
   shape) -> **final 6-warp/24q/4kv/256d build: 78.1 ms/layer-chunk**. The
   wall was never raw bandwidth: it was the per-token dependent global-load
   chain and the per-q-head K/V traffic amplification.
4. **End-to-end (harness protocol, `--public-ar-profile`, 8,192 tokens)**:
   oracle route 767.4 tok/s; direct+sequential 164; direct+flash **552.5**
   (72% of oracle, 3.37x over sequential; decode 33.8 tok/s unchanged). The
   remaining 1.39x is the scalar dot/exp instruction budget; closing it needs
   a WMMA/MFMA score GEMM (recorded as next step).
