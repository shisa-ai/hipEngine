# Capture whole-token Inkling 2 decode as a HIP graph (opt-in)

## Summary

Whole-token decode graph capture for the device-resident Inkling 2 GGUF path
(`HIPENGINE_INKLING2_DECODE_GRAPH=1`, default off). The first decode step of a session runs
eager (priming the residency caches) and then records the step into a
`hipStreamCaptureModeRelaxed` graph; later steps replay it. A device-side tick kernel
(`inkling2_resident_tick`) bumps a counter and rewrites every visit's `(live, position)`
KV header inside the graph, so the per-step host upload of headers is gone. Baked
position-dependent constants are made safe by the capture gate: every visit's KV window
must be saturated (`min(extent, capacity)` below the current position) and the graph is
retired once the position crosses the log-scaling floor. The attention kernel reads its
headers out of a device buffer written by the tick (`capture_headers` on the device
attention session); the clip factor depends only on the baked floor, which is constant up
to the retirement point.

Capture-time uploads are the silent-corruption trap in relaxed capture mode, so
`enqueue_upload`/`download` now go through a pinned-and-baked path during capture
(dedicated pinned buffer per upload, registered with the runtime for the graph's
lifetime, capped), and any host download inside capture raises instead of reading stale
bytes. Every kernel launch in the decode traversal now routes through `capture_stream()`
(stream 0 outside capture, the capture stream inside), including rocBLAS and the expert
chain.

## Status: works mechanically, output equivalence NOT established

Measured on the W7900 (UD-Q4_K_M artifact, fast profile, device routes on, 48-token greedy,
~1750-token prompt):

- Capture succeeds; replay runs; the run completes and emits coherent text. No speedup at
  this prompt size (3.22 vs 3.23 tok/s; the wall is prefill-dominated).
- Output equivalence with the eager path is NOT shown. One of three 48-token graph runs
  matched eager token-for-token; the other two followed a different greedy branch from
  token 5. Three eager runs were mutually identical. Whether this is run-to-run kernel
  nondeterminism or a capture defect is unresolved; neither has been excluded.
- Because capture is relaxed mode, any uncaptured upload would corrupt silently; the new
  pinned-upload guard closes that class of bug by construction, but the residual
  nondeterminism is not yet attributed.

Per R0528 (added with this entry) the flag stays opt-in until the flip rate is understood
and a measured win exists; nothing default-reachable changed.

## Changes

- `hipengine/core/hip.py`: `capture_stream()` accessor; docstring states falsy stream joins
  the capture while one is active.
- `hipengine/core/rocblas.py`, all `inkling2_*` kernel wrappers, `inkling2_gguf_device.py`,
  `inkling2_activation_transfer.py`: launches/copies route through the capture stream;
  uploads during capture are pinned and baked into the graph; downloads during capture raise.
- `hipengine/kernels/hip_gfx1100/norm/inkling2_residual.hip` (+ `.py`): stream parameter on
  the residual kernels plus the new `inkling2_resident_tick` header-writer kernel.
- `hipengine/runtime/inkling2_gguf.py`: `_graph_step`/`_capture_graph`/`_record_graph`/
  `_replay_graph`/`_discard_capture`/`_drop_graph_state`; capture gate (saturation + floor);
  per-session re-capture; eager fallback on any capture failure.
- `hipengine/runtime/inkling2_device_attention.py`: `capture_headers` mode; position check
  skipped while recording (the graph owns position bookkeeping).
- Docs/audit: `HIPENGINE_INKLING2_DECODE_GRAPH` documented in `docs/ENVS.md`, new
  `docs/REFACTOR.md` R0528, flag triaged in `audit/triage/flag.jsonl` (GATE-CATCH22/qualify).
