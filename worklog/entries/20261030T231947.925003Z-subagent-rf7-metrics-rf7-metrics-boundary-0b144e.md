# Extract explicit Prometheus metrics ownership from the server API

## Summary

`hipengine/server/api.py` no longer owns the Prometheus counters, metric
normalization or text exposition. They now live in
`hipengine/server/metrics.py`, which imports only the standard library:
`collections.abc`, `dataclasses`, `math`, `types` and `typing`. It imports
neither FastAPI/Starlette nor `hipengine.server.api`, and no engine,
generation-scheduling, runtime, model, KV-cache, speculative, dispatch or
loading module.

The owner takes explicit data only: a `_ServerMetrics` counter object, a
recursively immutable `_MetricsSnapshot`, and the graph histogram bucket names
the graph cache declares. The application reads the raw live snapshot once,
normalizes the known resident/pool/graph/queue/scheduler fields, and passes
only that output to the snapshot. The snapshot carries the normalized resident
metric values (including the normalized execution manifest), normalized KV-pool
values, normalized graph values, normalized queue values, session counts, MTP
serving state and normalized scheduler-fairness capability. The owner performs
counter accumulation, non-negative/string-count normalization, pool/graph/
queue/resident/prefix-cache normalization, MTP acceptance-rate arithmetic,
label escaping, value formatting, HELP/TYPE ordering and the full Prometheus
exposition.

Engine capability discovery, model lifecycle, live-snapshot reads, stats-object
attribute reads, queue getter reads, and service-health/readiness attribution
stay in `api.py`.

## Changes

- `hipengine/server/metrics.py` (new)
  - Owns `_ServerMetrics`, `_MetricsSnapshot`, `_KV_POOL_METRIC_DEFAULTS`,
    `_nested_mapping`, `_non_negative_metric_value`, `_string_value_counts`,
    `_non_negative_metric_mapping`, `_prefix_cache_metric_values`,
    `_resident_loop_metric_values`, `_kv_pool_metric_values`,
    `_generation_queue_metric_values`, `_graph_bucket_metric_values`,
    `_mtp_acceptance_rate_metric`, `_scheduler_metric_values`,
    `_escape_prometheus_label_value`, `_format_metric_value`,
    `_append_resident_latency_metrics`, `_append_labeled_gauge_metrics`,
    `_append_labeled_counter_metrics`, and `_render_prometheus_metrics`.
  - `_MetricsSnapshot` is a frozen dataclass whose mapping fields are
    recursively closed at construction: mappings become `MappingProxyType`,
    lists become `_FrozenList` (an immutable tuple subclass that thaws back to
    `list`), tuples stay tuples, and primitive leaves stay unchanged. It holds
    normalized metric output, not the raw live snapshot. The application
    normalizes known fields first, so unknown live extras are dropped and
    object-valued numeric leaves keep the old 0/default behavior before the
    freezer runs. Any other leaf at this boundary is a bug and raises
    `TypeError`; no live engine object is intentionally passed in.
  - `_execution_manifest_metric_values` selects and normalizes the manifest
    fields the exposition consumes before they enter the immutable snapshot.
    Unknown manifest extras are dropped without touching them; known string
    fields are converted with `str` and known flags with `bool`, matching the
    pre-move renderer. This keeps an object-valued unused manifest field from
    reaching the boundary while preserving the old labels for known fields.
  - `_render_prometheus_metrics` consumes the already-normalized snapshot
    fields directly; it no longer re-normalizes the raw live snapshot. This is
    why a falsey scalar label, a numeric object or an unknown extra cannot
    change the public 500/200 shape at render time.
  - `_prefix_cache_metric_values` thaws its frozen input back to ordinary
    mutable dicts/lists for the readiness payload; the unused `deepcopy`
    import is gone. `_render_prometheus_metrics` now reads normalized snapshot
    fields instead of normalizing raw resident/pool/graph/queue data itself.
  - The graph histogram bucket names are passed to `_graph_bucket_metric_values`
    by the application collector before the snapshot is built, so the owner
    does not import `hipengine.generation.batch_scheduler` (the tuple's
    definition site) or any other scheduling module.
- `hipengine/server/api.py`
  - Removed the `_ServerMetrics` class, the metric normalization/exposition
    helpers, and `_GRAPH_KERNEL_TIME_HISTOGRAM_BUCKET_SET`.
  - Imports only names used by the application collector, readiness/stream
    helpers and endpoint. Unused formatting/counter-label helpers are not
    re-exported merely to preserve private implementation names.
    Existing integration consumers of `_ServerMetrics` still resolve the same
    owner class through the application's ordinary import.
  - Added application collectors `_metrics_pool_source`,
    `_metrics_graph_source` and `_metrics_snapshot`; the `/metrics` route now
    reads the live loop once, builds one `_MetricsSnapshot`, and calls the owner.
    `_metrics_snapshot` normalizes the consumed execution-manifest fields inside
    the resident metric mapping before freezing it; no raw manifest is retained.
  - Renamed the readiness-only wrappers to `_live_pool_metric_values` and
    `_live_graph_metric_values`; they resolve raw data and delegate to the
    owner. `_kv_pool_stream_payload`, `_kv_pool_metric_values_from_stats`,
    `_first_stats_object`, `_stats_to_mapping`, `_mtp_serving_metric`,
    `_scheduler_fairness_capability`, and every service-health/readiness
    function stay in `api.py`.
  - No chat-output, JSON Schema, request-schema or other parent-committed
    parser owner changed. The only diff hunk touching the chat-output import
    block is the new metrics import appended after it.
- `tests/test_unit_server_metrics_boundary.py` (new, 68 tests)
  - Pins stdlib-only AST imports, standalone file load with no `hipengine`,
    FastAPI, Starlette or torch in `sys.modules`, package import without the
    HTTP app/engine, API aliases and identities, and the absence of moved
    definitions in `api.py`.
  - Compares the owner against the pre-move corpus: 3 complete `/metrics`
    render outputs, 45 normalization cases (resident, prefix cache, pool,
    queue, graph, string counts, non-negative values, formatting, escaping),
    5 counter-accumulation cases, and 12 unchanged-definition AST hashes.
    `_prefix_cache_metric_values` is excluded from the AST-hash check because
    its final return changed from `deepcopy` to the frozen-snapshot thaw; its
    output, including nested collections, is covered by the corpus and the thaw
    test.
  - Adds focused absent/full/malformed optional-data checks, MTP off/on, queue
    pressure and cancellation counters, pool/graph counts, recursive snapshot
    immutability (mutating the nested source after construction and attempting
    nested writes), unknown-extra dropping before the snapshot, falsey scalar
    labels keeping their pre-move defaults, a pre-move object control with
    object-valued numeric/flag leaves, prefix-cache thaw back to mutable
    lists/dicts, and two independent counter owners.
- `tests/fixtures/rf7_metrics_premove_corpus.json` (new)
  - Oracle captured from `HEAD:hipengine/server/api.py` at `c16bc3daf` before
    the move. It contains the full pre-move render text, normalization results,
    counter fields and AST hashes; it is not a restatement of the new module.
