# Add long-prompt rows to the INT8 MTP public matrix

## Summary

Task #19's checklist names short and long prompts, but every gate input was
short: the category suite's prompts are tens of tokens and the prefix gate's
512-token prefixes were the longest input any gate sent. The category gate now
takes `--long-prompt-tokens`, which appends rows built by binary-searching the
longest prefix of committed repository prose under each requested token count.
The prose is the point: a prompt that tiles one paragraph can drive a degenerate
loop, and two configurations that both emit that loop would agree trivially.

On the mirror-free uniform scope the full matrix now passes with 2,048- and
4,096-token rows on both endpoints (40 rows, 9 and 8 speculative cycles, ids
identical to each row's own autoregressive baseline), and the reversed-schedule
repeatability pass grew from 18 to 20 rows because the long rows are in it. The
isolation check now runs its target concurrently with a 4,096-token neighbour
rather than a short one.

The long-prompt multi-choice check found a real gap: **a grouped (n=2) request at
a prompt of about 1,020 tokens or more returns correct autoregressive ids and
runs zero speculative cycles.** Measured boundary: 64/256/512/768/896/960/1000
tokens speculate, 1020/1023/1024/1025/2048/3072/4096 do not. The cause is a chain
of two refusals, and neither was visible in the response:

1. `packed target verifier currently requires context < 1024`
   (`runtime/qwen35_gguf_runner.py:21839`) -- a 2026-07 policy gate, never
   numerically qualified past 1024. It is triaged NOT-DEBT in
   `audit/triage/stub.jsonl` on the grounds that a refusal reaches the user
   cleanly, which is not what happens here: the refusal is raised inside a
   speculative cycle, is caught by `recover_cycle_failure`, and becomes an
   autoregressive fallback.
2. Removing that guard (nothing else) moved the refusal to
   `long-context packed AR decode requires a row-sized split-K workspace`
   (`:5908`), reached with `split_workspace=None` on a layer whose scratch had no
   retained planes and no retained kernel.
3. The failed cycle retires its rows, so every later step reported the planner
   reason `no_provider` with `provider_decline_reason='request N unregistered or
   disabled'` -- a message about registration for a failure about context.

One 4,096-token chat group speculated eight cycles with identical ids while that
experiment was in place, so the packed path is not categorically incapable past
1024; the remaining limit is admission or workspace sizing. The guard was
restored rather than left removed on the strength of a single observation, and
the gap is recorded as task #22 with the full evidence.

## Changes

- `scripts/int8_mtp_server_gate.py`: `--long-prompt-tokens` adds long rows to the
  same schedule, so they inherit the triple, the repeatability pass and the
  isolation check; `long_prompt_text` binary-searches the prefix; the long
  multi-choice check asserts token identity at every length, requires both
  choices to agree about their route, and requires a non-speculating group to
  name its cause. `build_parser` is extracted from `main` so the default can be
  tested.
- `hipengine/speculative/accounting.py`: the specdec2 block now publishes the
  recorded `failure_reasons` (category and detail) beside the existing counts.
  The category alone cannot answer why, and the detail did not survive the
  fallback that it explains.
- `tests/test_unit_int8_mtp_server_gate_long_prompt.py`: 12 cases over prefix
  selection, row construction, the multi-choice contract and the CLI default.
- `tests/test_unit_mtp_output_accounting.py`: 2 cases for the published detail,
  including a list with no trailing detail.
- New evidence artifact
  `benchmarks/results/2026-09-22-gfx1151-int8-mtp-long-prompt-matrix.json`:
  the gate report, plus the finding's boundary observations, guard sites and
  verbatim traces, labeled as diagnostics rather than gate results.
