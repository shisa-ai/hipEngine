# Independent-request PLE stage over request-owned Conv-history slots

## Summary

Adds the N-request form of the Qwen4Exp PLE stage. The c1 oracle
`run_qwen4_exp_ple` (`runtime/qwen4_exp_runner.py:6931`) takes one
`conv_history_ptr` and one token stream, so its dilated-Conv stage reads and
shifts *that* history; serving N resident requests needs N full history copies
or a per-request step loop.

This unit replaces that axis with physical request slots:

- `Qwen4ExpBatchPleState` owns one PLE stage's
  `[state_slots][(conv_kernel-1)*dilation][channels]` F32 history slab plus the
  `int64[rows]` row-to-slot index vector, and admits a row set with `prepare`.
- `run_qwen4_exp_batch_ple_stage` runs one token for every admitted row with one
  dispatch per stage, handing the Conv stage the row-to-slot vector so each row
  shifts only its own request's history.

Nine of the ten stages are the same row-independent owners the c1 path already
calls (their grid is the row count); only the Conv stage changes owner, from the
strict single-row owner to the committed `qwen4exp_ple_indexed_decode`. No
kernel was added. The c1 path is untouched and remains the fallback.

Not in scope, and not done: runner wiring, PLE hash orchestration, prefill
chunks, server/generation/defaults, commits. No production numerical or serving
claim.

## Changes

- `hipengine/runtime/qwen4_exp_batch_ple.py` (new, 771 lines):
  - `Qwen4ExpBatchPleState.allocate(state_slots, branches, hidden, conv_kernel,
    dilation, runtime=None)`: history slab zeroed (a fresh request's history is
    zero), an `int64[state_slots]` index buffer, and every bound the indexed
    decode enforces (`state_slots`, `channels`, `conv_kernel`, `dilation`,
    `history_rows`) plus the int64 byte product checked before a runtime is
    resolved or a byte allocated.
  - `prepare(slot_ids)`: the primitive's own admission helper
    (`qwen4_exp_ple_indexed_state_indices`) is the slot rule — distinct, in
    range, one per row — so this module does not restate it. Validation runs
    before the upload, the upload copies exactly `rows` int64 values (the buffer
    is slot-width), and a copy failure clears the active set instead of
    publishing half a mapping.
  - Lifecycle: `closing` set before the first free, `_require_open` rejects
    uploads from then on, `close` frees newest-first popping only after a free
    returns, so a partial failure is retried without a double free.
  - `history_slot_ptr(slot)`: validated per-request address, so a caller can
    seed or move one request's history with the existing copy helpers.
  - `run_qwen4_exp_batch_ple_stage(residual_ptr, embedding_ptr, weights, *,
    state, scratch, norm_key_ptr, norm_query_ptr, norm_conv_ptr,
    conv_weight_ptr, rows, branches, hidden, conv_kernel, dilation, eps=1e-6,
    stream=0, runtime=None)`: same parameter order as the c1 oracle, reusing
    `Qwen4ExpPLEScratch`, so the c1 comparison differs only in the Conv owner.
    Ten dispatches: `ple_key` and `ple_value` projections,
    `grouped_rmsnorm_f32`, `grouped_rmsnorm_bf16_f32`,
    `ple_signed_sqrt_gate_f32`, `ple_repeat_gated_value_f32`,
    `grouped_rmsnorm_f32`, the indexed Conv, `scaled_silu_f32`, and
    `ple_add_delta_bf16_f32`.
  - `_resolve_indexed_conv` resolves the Conv route from the projection weight's
    backend through the registry: `load_backend_kernel_package(backend)` then an
    **exact-key** `is_registered` check before `resolve`. Exact-key first matters
    because `resolve` applies generic fallbacks (variant, quant, then the
    cpu_reference catch-all) and a silent fallback to the single-row owner would
    hand it a slot vector it does not accept; the error names the missing
    variant and states that the single-request stage remains the fallback. The
    backend comes from the weight, so this is the registry mechanism, not a
    backend branch.
  - `_validate` admits a call before the first dispatch, hence before the only
    history write: closed/closing scratch/state, runtime identity across the
    three owners, positive geometry, finite positive `eps`, geometry equal to the
    state owner, the indexed decode bounds, the row bound, required projections
    and non-zero residual/embedding/norm/conv pointers, `rows == prepared rows`,
    a re-admission of the *published* index vector, int64 alignment of that
    vector, per-buffer scratch capacity (including the BF16 output width), the
    two projection source shapes, and the Conv route resolution.
- `tests/test_unit_qwen4exp_batch_ple.py` (new, 13 tests): every device call is a
  module-level name and the Conv route is a monkeypatched resolver. Asserts the
  exact 10-dispatch stage sequence and its row count for N=1, 2, 4 (so a
  per-request loop cannot pass), the pointers/metadata reaching each stage
  (`indices.ptr` into the Conv, `state_slots`, `channels`, kernel, dilation,
  packed element counts for the elementwise stages, the residual-delta operand
  order), owner allocation (one memset, slot addresses striding by one slot's
  bytes, slot-width index buffer), `prepare` (row order preserved, permuted and
  shrinking sets, leading-rows-only upload with the exact byte count), no
  reallocation across changing active sets, 15 no-dispatch rejection cases,
  duplicate/out-of-range/typed slot rejection with the host mirror unchanged,
  re-admission of a tampered index vector, unprepared/closed/closing rejection,
  the partial-close retry, owner geometry bounds, and the resolver's exact-key
  behaviour (missing variant reported, no silent fallback).
- `tests/test_gpu_qwen4exp_batch_ple.py` (new, 5 tests / 11 items): compact dense
  F32 GGUF fixtures reused from
  `tests/test_gpu_qwen4_exp_runner_gr._dense_f32_weight`, branches 2, hidden 4,
  channels 8, Conv kernel 4, 4 slots, each slot seeded with a distinct-scale
  history so a row reading the wrong slot cannot agree by accident. C1/C2/C4 with
  permuted slot orders, dilation 1 and 3, and repeated steps chosen to cross the
  history boundary (dilation 1 holds 3 rows and runs 12 steps; dilation 3 holds
  9 rows and runs 8 and 12 steps). Every step is compared against (a) an
  independent single-request `run_qwen4_exp_ple` run per row from that row's slot
  history and (b) the committed CPU reference `ple_injection` run per row with
  that slot's `PLEConvState`. Slots outside the active set are asserted
  byte-identical; a repeated step from the same seeded history is asserted
  byte-identical; a rejected call (row count, dilation, Conv pointer, duplicate
  slot) leaves the slab byte-identical; one test asserts the resolved Conv route
  *is* the committed indexed decode for a real backend, so a registry fallback
  cannot pass silently.

Every comparison measured **exactly zero**: the batch stage reproduces both the
independent single-request stage and the CPU reference bit-for-bit in BF16
output bits and in F32 history bytes. That is the expected outcome — stages
1-7, 9, 10 are the same kernels, and the indexed Conv owner's block body repeats
the single-row owner's statements (the primitive's own test asserts that
contract). A wider probe at branches 2 / hidden 256 / channels 512 / 4 rows also
measured 0/2048 differing bits, so the compact fixture is not hiding a
row-dependent projection variant.

The asserted gate is nevertheless **one BF16 ULP** (`rtol = 2**-8` plus a
matching absolute term) rather than bit equality, and the history is asserted at
`rtol = atol = 2e-6`. A future row-count-dependent projection variant would
legitimately move the output by a BF16 rounding step, and the test then reports
the count of differing bits and the float deviation instead of failing on an
implementation detail that is not an ownership contract.

Exact control asserted on every case:

- `state.active.slot_ids` and `indices_host` equal the caller's row order.
- Slots outside the active set are byte-identical across every step, including a
  changing active-set schedule (`[0,1] -> [2,3] -> [1] -> [3,2,0]`).
- Each active slot's history equals both that row's independent c1 run and the
  CPU reference, so a row's history advanced exactly once, in its own slot.
- A repeated step from the same seeded history reproduces the output bits and
  the whole slab byte-for-byte.
- Rejected calls leave the slab byte-identical: nothing reaches a kernel.

## Next

- Runner integration (not done here): the runner's PLE call site still passes
  `conv_history_ptr=self.state.ple_conv.ptr` with `rows=1`. Wiring this unit
  needs the runner to own one `Qwen4ExpBatchPleState`, a request-to-slot
  assignment shared with the attention/GDN owners, a per-step
  `prepare(slot_ids)`, and an explicit history move on slot compaction.
- PLE hash orchestration stays outside this unit: the caller supplies the staged
  embedding rows (`embedding_ptr`). The hash-table walk, the staged ring view
  (`stage_qwen4_exp_ple_rows`), and the IQ4_NL decode are unchanged.
- Prefill chunks are not covered: a chunk's rows are one request's consecutive
  positions, not independent requests, and must not be admitted as active rows.
  The c1 stage remains the owner for those (its multi-row path is exercised by
  `tests/test_gpu_qwen4_exp_runner_ple.py`).
- `head_dim`/width bounds come from the indexed decode (`channels <= 2**20`,
  `(kernel-1)*dilation <= 65536`, `dilation <= 1024`). A model outside those
  bounds keeps the c1 path; nothing here adds a fallback of its own.
- No production numerical or serving claim. Evidence is one PLE layer on fixture
  weights against a per-row c1 stage and the committed CPU reference; the
  calibrated profile gates in `docs/EXECUTION-PROFILES.md` and any speed claim
  are unrun.
