# W4A16 becomes the dense raw-IQ prefill default

## Summary

Acts on the gate-reference correction. Scored the way
`EXECUTION-PROFILES.md` section 6 specifies - candidate production against
hipEngine strict - the integer-MMQ route breaches the binding 5e-2 absolute
maximum-row ceiling while W4A16 passes every threshold, so W4A16 takes the
default at **150.3 tok/s** against the integer route's 171.9, a 12% cost.

## Changes

- `hip_gfx1151/__init__.py`: `GGUF_IQ_DENSE_MMQ_PREFILL_POLICY` renamed to
  `GGUF_IQ_DENSE_PREFILL_POLICY` - it selects among routes now, and the old
  name would actively mislead. Variants point at W4A16;
  `_IQ_DENSE_INTEGER_MMQ_VARIANT` is kept beside it so a route swap is a
  one-word edit, with the strict-referenced table in the comment.
- `gguf_linear.py`: `_iq_dense_mmq_prefill_dispatch` renamed to
  `_iq_dense_prefill_dispatch`; the activation-plane requirement is now
  **route-specific** (W4A16 reads activations directly and needs none).
- `qwen35_gguf_runner.py`: the prefill session opens either way, but the
  ~10 MB plane is allocated only when a policy entry actually selects the
  integer-MMQ route.

## A defaults bug this surfaced, and the fix

Switching the default broke `test_gguf_ud_dense.py::test_dense_full_output_geometry`
for the runtime caller at rows >= 8. The cause is worth recording: the
integer-MMQ route declined whenever no activation workspace was bound, so **the
workspace requirement had been acting as the opt-in gate**. Ad-hoc
`launch_gguf_linear` callers therefore kept the strict owner by accident.
W4A16 needs no workspace, so as first written it engaged for *every* caller and
silently replaced exact results with approximate ones.

Fixed by making the session itself the opt-in: `iq_dense_mmq_session` now
accepts a workspace-free form that marks the execution owner without
allocating, the dispatch requires an open session for **either** route, and
only the integer-MMQ variant additionally requires a usable plane
(`iq_dense_mmq_has_workspace`). The dense bit-exactness test passes again for
the right reason rather than by coincidence.

| --- | --- | --- | --- | --- | --- | --- |

All against hipEngine strict over 162 teacher-forced rows. Envelope: mean 1e-3,
p95 5e-3, p99 2e-2, max 5e-2 ceiling, top-1 >= 99%. W4A16 is the only arm that
passes all of them.

rocprofv3 confirms the route: `gguf_iq_prefill_wmma_kernel<0,...,16,128>` at
117 calls / 1110 ms replaces the integer MMQ; total prefill GPU 3455 ms. Q3_K
remains on the strict GEMV at 637 ms (18.4%) - it has no MMQ or W4A16-eligible
contract issue, just no route yet.
