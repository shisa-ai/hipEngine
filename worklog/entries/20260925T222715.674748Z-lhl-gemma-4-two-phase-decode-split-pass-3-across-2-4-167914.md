# Gemma 4 two-phase decode split: pass 3 across 2-4 key slices (+3.26% decode, gate pending)

## Summary

The decode attention kernel's parallelism is structurally low: `grid = tokens *
num_heads` launches 16 blocks on a 96-CU GPU. The two-phase split divides pass 3's
weighted-V sum across 2-4 key slices, which the scale probe's block-count curve says
is the right shape, and it changes only the association order of an f32 sum. It
measures **45.4170 tok/s** against the incumbent's 43.9827 (**+3.26%**). Its
execution-profile gate has never reached a numerics verdict because a peer job holds
~6.9 GiB on the target device, so the split sits behind a precondition constant with
the clearing command written beside it.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_attention.hip`: the key-class decode
  kernel takes an optional split phase-1 mode (`split_weights`, `split_header`); with
  both null it is byte-for-byte the kernel it was. New
  `gemma4_attention_decode_slice_kernel` accumulates the weighted V sum over its
  slice of the key range, and `gemma4_attention_decode_combine_kernel` sums slices in
  ascending order and divides by phase 1's denominator.
  `hipengine_gemma4_decode_split_workspace_bytes` is exported so the launcher and the
  kernel cannot disagree about the workspace layout.
- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_attention.py`: `decode_slices` (2
  slices from 513-1024 keys, 4 from 1025 up, 1 below 512), a per-stream grow-only
  workspace cache, the decode launch path, and `_SPLIT_GATE_PASSED` with its
  clearing command.
- `tests/test_gpu_gemma4_attention_decode_parity.py`: `_raw_launch` now passes the
  decode symbols' full argument list - the old 12-argument call would have handed
  the kernel a garbage workspace pointer once the parameters existed - plus eight
  A/B tests of the split against the single-kernel path on the artifact's two real
  geometries at 1024, 2055 and 8192 keys.
- `docs/campaigns/GEMMA4-26B-A4B-OPTIMIZATION.md`: the implementation, the measured
  speed and the open question about the pass-3 share. `docs/REFACTOR.md`: the
  precondition and its clearing command.
