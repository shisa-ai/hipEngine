# Keep dynamic Inkling key and value convolution on device

## Summary

Ordinary GGUF generation now applies dynamic key/value convolution before downloading the grouped projections. The convolution reads compact per-head tap projections on the device instead of expanding them on the host and uploading them again.

## Changes

- Register `projected_dynamic` on gfx1100 and gfx1151. Reuse the existing visit-owned histories, static tap storage, FP32 tap addition, and ordered accumulation. Provisional updates retain the expanded-tap path and its undo journal. The original checkpoint path is unchanged.

## Validation

- The three projected-convolution cases failed before implementation and passed on both GPUs afterward. The W7900 kernel trace recorded 36 `inkling2_short_conv_dynamic` launches with positive durations. The focused GPU and unit tests, deterministic CPU suite, fixtures, registry and smoke checks, and documentation gates passed.
- Compared the default path with the expanded-tap control using `/tmp/hipengine_inkling_dynamic_kv_projection_probe.py "$model" "$backend"` through `LLM.generate_detailed()` with `fast`, FP32 KV, greedy sampling, no prefix reuse, and no drafting. W7900 used mainline Q4_K_M and Strix Halo used the pinned Loom Q4_K_XL. All eight scored decode logits matched bit-for-bit and all nine generated IDs matched at 47, 575, and 1,027 input tokens. The default eliminated 72, 136, and 200 separate dynamic convolution exchanges respectively on each GPU. Static exchange counts were unchanged. This verifies the removed exchanges, not a latency improvement.
