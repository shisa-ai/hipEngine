# Oracle-free direct INT8 prefill attention on the GGUF route

## Summary

Second capacity lever for the 2026-09-08 engine-comparison doc priority
(the first, the single-plane hidden alias, moved the bound 131,072 ->
155,648). The remaining full-capacity transients on the pure-INT8 route
are the shared BF16 K/V oracle pair (4,096 B/token) and the full-capacity
hidden plane (10,240 B/token). The PARO runner already carries an
oracle-free `streaming_direct` INT8 prefill attention
(`HIPENGINE_QWEN35_INT8_PREFILL_ATTENTION`); this unit ports that
structure to the GGUF resident route as
`HIPENGINE_GGUF_INT8_PREFILL_DIRECT` (default OFF).

## Decisions

- Plan: `direct_int8_prefill=True` resolves the lifetime plan to a new
  `chunk_outer_direct_int8` mode (zero oracle cost, chunk-sized hidden,
  required_hidden_capacity = chunk rows), so the pre-existing chunk-outer
  loop replaces the full-capacity layer_outer planes entirely.
- Scratch: `_full_attention_prefill_scratch_for_layer` returns the
  retained INT8 caches as the attention K/V source with INT8 append spans
  (write-through) and read spans built through the retained physical page
  table (`_int8_retained_prefill_spans` over the prefill spans); no
  oracle allocation, no retained double-write.
- Kernel: found and fixed a latent dtype bug while porting - the int8
  groupwise prefill kernel stores `half_t` (fp16) into `full_gated`,
  which every GGUF-route consumer reads as BF16. The PARO route is an
  fp16 pipeline (correct there); the GGUF route needs the new BF16-output
  sibling `qwen35_paged_attn_prefill_int8_gqa_gate_bf16_out_spans`
  (`..._int8_scale_f32_bf16out_spans`, `out_bf16` template parameter).
  The pre-existing `direct_hadamard_int8` GGUF branch is dead code with
  the same latent mismatch; it now shares the fixed out type but stays
  unexercised (recorded in docs/REFACTOR.md).

## Validation

- GPU1 (RX 7900 XTX), pure-INT8 comparison protocol, 8,192 tokens:
  control (oracle route) peak 16.8951 GiB / prefill 761.58 tok/s;
  direct peak 16.8018 GiB (oracle 0.031 GiB + hidden plane->chunk-sized
  0.063 GiB removed) with mode chunk_outer_direct_int8, 0 oracle
  buffers, finite logits, greedy argmax correct.
- Real-prompt characterization (8,192-token composed mtpbench prompt,
  32 greedy outputs, fresh process per arm): **32/32 token IDs
  identical** to the oracle route.
- Prefill speed cost: 761.6 -> 164.2 tok/s (4.6x slower) - the groupwise
  INT8 prefill kernel is a sequential online-softmax loop; this is the
  documented reason the gate stays default OFF.
- Capacity ladder with direct=1: BLOCKED BY SPEED. The 163,840-token
  point was stopped after ~80 minutes (per-token attention cost grows
  with context in the sequential online-softmax kernel, so long-context
  ladders are impractical at 4.6x-and-worse prefill cost). The projected
  bound (weights + INT8 KV + scales + chunk-sized scratch, roughly the
  external engines' 196,608 structure) is NOT a measured claim.
- Artifact: benchmarks/results/2026-09-09-rx7900xtx-gguf-int8-direct-
  prefill-blocked.json (A/B, real-prompt agreement, blocker).
- Gate stays default OFF. GPU1 returned to baseline (28 MB VRAM).
