# VibeVoice registered kernels, spans ownership and prefill fallback

## Summary

Replace raw decoder cache addressing with KVLiveSpans and resolve VibeVoice primitives/fallbacks through backend peer registrations.

## Changes

- Both HIP peers register the encoder, casts, GEMVs, RoPE, KV write and attention primitives. Runtimes resolve callables once at construction and import backend-neutral host layout helpers. Frontend GEMM exposes WMMA/strict variants; decoder prefill exposes hipBLASLt/strict incremental variants. Selected variants and strict fallbacks have manifests/hashes. These identities do not themselves certify production numerics.
- New block-size-one uniform KVLiveSpans write/attention surfaces consume logical-to-physical maps, per-row int64 counts/positions, physical token positions and eviction masks. Decoder uses them in both prefill and decode. Capacity above 16,000 is rejected before model allocation; no hour-long capacity is claimed.
- hipBLASLt negotiates all shape algorithms before touching hidden/KV state and falls back to the registered incremental chain if the library/algorithms are unavailable. Runtime launch failures propagate. Resolved fallback callables are owned by the runner, so subsequent registry changes cannot alter its path. Close is idempotent and releases the previously omitted qkv scratch buffer.
- New device code derives from in-tree encoder.hip at d5425739; no external kernel was copied. Catalog and cleanup ledger updated.
