# Close R0281-MTP-CAP bounded MTP batch policy validation

## Summary

The three bounded MTP batch constants (`_MTP_SERVING_PREFILL_MAX_SLOTS`,
`_MTP_SERVING_VERIFY_MAX_SLOTS`, `_MTP_WARMUP_BATCH_MAX_SLOTS`, all four) were
validated on the routes that actually read them. Closed R0281-MTP-CAP with no
policy change.

Route ownership correction: the prefill and verifier constants are read only by
`Qwen35GGUFBringupGenerator.generate_speculative_mtp_detailed`, the direct MoE
compatibility route (`specdec2_perf_bridge`, direct callers). Public
`LLM.generate(speculative_mtp=True)` goes through EngineService child ownership
and never calls `_try_open_mtp_serving_slots_batch_prefill` or
`_try_verify_mtp_serving_cycles_batch` (traced: zero calls at widths 2 and 4 on
dense Qwen3.8-27B). The warmup constant is read by the server startup scratch
probe, which is public.

## Changes

- Removed the R0281-MTP-CAP entry from `docs/REFACTOR.md`. No code change.
