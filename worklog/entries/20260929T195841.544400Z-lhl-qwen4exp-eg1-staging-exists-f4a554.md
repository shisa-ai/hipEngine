# EG-1's gate/up default is the same gather shape ED-1 measured, and the staging it proposes is already the registered fallback

## Summary

EG-1's row was parked "OPEN, after ED-1" waiting for ED-1 to answer the traffic question
before building LDS staging for gate/up. Two source facts close that wait and change what
the row's next experiment should be.

1. EG-1's gate/up default is the **same gather-shaped design ED-1 measured**, so ED-1's
   negative result is evidence about it - not only about the down owner.
2. The staging EG-1 proposes to build **already exists**, as the registered fallback on
   the same route.

So the open work is a dispatch comparison between two variants that both already exist,
not kernel construction. This is a source-reading correction with no new measurement; the
row's status stays OPEN.

## Evidence

**The default is the gather shape.** For `moe_linear` /
`prefill_rows_ge64_exact_grouped_q4_gate_up`, `hipengine/generation/qwen4_exp_profiles.py`
selects `selected_dual_wmma_iu8_risk_prefill_bf16_bf16_out`.
`gguf_q4_k_selected_dual_wmma_iu8_risk_prefill_kernel` assigns one output column per lane
(`global_col = col_base + warp_col * 32 + lane`) and each lane reads its own `row_bytes`
weight row (`block_base = qweight + expert_id * (local_out_features * row_bytes) +
local_col * row_bytes`). That is the structure ED-1's screen measured losing 48/48.

The row's own citation `qwen4_exp_q5_1.hip:1069` is
`__shared__ int lds_row_atrisk[TILE_ROWS]`, inside `q5_1_selected_wmma_iu8_risk_prefill_kernel`
- the same family.

**The staging already exists.** `selected_dual_grouped_rowbatch8_out4_expertgrid64_bf16_bf16_out`
is the declared fallback for that route.
`gguf_q4_k_selected_dual_grouped_rowbatch_bf16_kernel<row_batch=8, out_batch=4, true>` runs
with the `PAIR_BLOCK_WEIGHTS` template argument true, and under it every thread takes a
strided share of `q4_blocks * Q4_K_SUBBLOCKS`, writing `d_scales_a` / `dmin_mins_a` /
`d_scales_b` / `dmin_mins_b`, then `__syncthreads()`. It precomputes `d*scale` and
`dmin*min` per subblock, which the down owner does not. `weight_a` and `weight_b` are
computed outside the `for (base = start; base < end; base += ROW_BATCH)` loop, so the
weight row is reused across every row of the expert.
