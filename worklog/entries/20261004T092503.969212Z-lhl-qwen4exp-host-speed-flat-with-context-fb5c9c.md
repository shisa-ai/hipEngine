# The host CPU is flat with context: the decode wall's growth is device-side gaps, not host work

## Summary

`DE-11` prices the decode step's non-kernel remainder at **1.47 ms/step at p512
and 10.56 ms/step at p4096** and the previous entry in this series attributed
14,293 `os.environ` lookups per step to it. **This unit refutes the host-side
reading of that remainder**, on three measurements.

**1. Two ablations of comparable host work, and neither transfers.**

| ablation | real host work removed | p512 | p4096 |
| --- | ---: | ---: | ---: |
| build-resolution memo (`20261004T083532`) | ~2.3 ms/step | +0.02% | **+2.53%** |
| layer-scope env memo (this unit) | ~2.2 ms/step | -0.06% | **-0.45%** |

Both are exact and both remove real work, and at p4096 they disagree in sign.
The layer-scope A/B has a **0.15% base-to-base spread** on p4096 decode
(17.836 / 17.863) and puts the candidate at 17.770, below both baselines; the
memo A/B's spread was 0.73% and put its candidate at the top of the metric's
cross-session range. **The honest reading is that a ~2 ms/step host ablation does
not reliably move this wall in either direction.**

**2. The host CPU does not slow down as context grows.**
`scripts/qwen4exp_host_speed_vs_context_probe.py` inserts a fixed,
context-independent host workload into the decode loop - one block per step, 32
iterations of eight `os.environ.get` calls through the same four-frame path the
profile blames - and times that block:

| case | host burn us/step | vs idle GPU | wall ms/step |
| --- | ---: | ---: | ---: |
| (GPU idle) | 67.499 | 1.000 | - |
| code-p512 | 70.816 | 1.049 | 79.829 |
| code-p1024 | 70.912 | 1.051 | 81.156 |
| code-p4096 | **71.478** | 1.059 | **109.763** |

**The same workload costs +0.93% more at p4096 while the wall grows +37.5%.** The
"GPU working set starves the CPU's cache and bandwidth" mechanism is refuted:
running under GPU load costs ~5% against an idle GPU, and that penalty is flat
with context.

**3. `--host-profile`'s tottime is not a valid basis for ranking host work.**
The diff that motivated the mechanism test showed every host function's tottime
growing ~25% while its call count grew 2-4%, which is the signature the
mechanism test was built to check. **It is a cProfile artifact**: the profiler's
own inflation grows from 5.9% at p512 (50.44 profiled against 47.64 measured) to
8.7% at p4096 (61.33 against 56.40), which inflates every function roughly in
proportion. **Call counts and caller attribution are exact; tottime is not.**

**What that leaves.** The wall grows **+10.04 ms/step (+21%)** where the device
kernel sum grows **+2.0%**, the host CPU is flat, and host call counts grow 2-4%.
So the growth is in the **gaps between kernels or in device-side work outside
kernel durations**. The earlier `X-4` measurement is consistent: the kernel sum
is stable to 1.0% while the step span varies 2.8x, and the median inter-kernel
gap swings 23x across repetitions (53.60 / 58.46 / 2.28 us). **This restores the
launch/transition lever, but for a device-side reason rather than the withdrawn
host-enqueue reason.**

**Decision on the layer-scope memo: kept.** It is exact - `_parse_layer_scope` is
a pure function of the raw string, and the caller still reads the environment on
every call, so a change selects a different key rather than a stale entry - it
removes a measured ~2.2 ms/step of real work, and it cannot regress because the
same frozenset object is returned. It is **not claimed as a win**: the measured
deltas are -0.06% / +0.14% / -0.44% / +0.01% against base spreads of
0.19% / 0.33% / 0.15% / 0.07%.

## Changes

- `hipengine/runtime/gguf_linear.py`: `_parse_layer_scope(raw)` - one memoized
  parser keyed on the raw string, shared by `_q8_dense_wide_layers`,
  `_q8_wmma_layers_scope` and `_q8_staged_f32_layers`; `_env_flag_enabled(name,
  default)` and `_raw_env_value(name, default)` for the per-launch boolean flags
  and the two raw values that go into the launch cache key
  (`_q8_dpp_reduction_raw`, `_q4_pack8_wmma_bulk_raw`). Every resolver still
  reads its variable on every call; only the repeated parse and the repeated
  `.strip().lower()` are memoized.
- `tests/test_unit_qwen4exp_layer_scope_env_memo.py` (new, 6 tests): the shared
  parse agrees with a fresh parse for every spelling, one value does not leak
  between the three scopes, a changed variable takes effect on the next call with
  no cache reset, 50 calls with one value add one cache entry and return one
  object, and the flag/raw resolvers observe changes.
- `scripts/qwen4exp_host_speed_vs_context_probe.py` (new): the fixed-host-workload
  probe, plus its artifact and README under
  `benchmarks/results/2026-10-04-qwen4exp-host-speed-vs-context/`.
- `benchmarks/results/2026-10-04-qwen4exp-layer-scope-env-memo/`: the six
  counter-rotated A/B artifacts.
- No kernel, arithmetic, dispatch or default changed.

## Next

- **The decode target is now device-side gaps.** Attribute them: the launch
  count grows only 4.7% (1,729 -> 1,811 per step) while the wall grows 21%, so it
  is not launch *count* either - something makes the device transition more
  expensive with context. A per-step gap census from a non-profiled
  device-side trace, or a wall-versus-depth curve at 512/1024/2048/4096 with the
  kernel sum at each point, is the next unit.
- The per-launch `build_X(load=True)` call (957/step, ~2.49 ms/step) is still
  worth removing on exactness grounds, but **the two ablations above say not to
  expect wall movement from it**. Recorded in `docs/REFACTOR.md`.
