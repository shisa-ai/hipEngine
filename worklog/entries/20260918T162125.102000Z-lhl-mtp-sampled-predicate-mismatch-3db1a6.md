# Sampled route: row intent works, the adapter predicate still disagrees with itself

## Summary

Moving the temporary `sampled` entry from the diagnostic row to the
**automatic-eligible** row `qwen38-q4km-gfx1151-strict-bf16-cap4-realized-c1-b3`
did clear the static-intent gate: a `temperature 0.7` request now reports
`static_intent_allowed=true`, `selected_route=speculative_mtp`,
`effective_route=speculative_mtp`, `selected_candidate_count=3`, and
`k0_class=not_k0`, with `policy_reason=qualified_automatic_realized_singleton_c1_b3`.
That is a real advance over the previous round, where the same request reported
`static_intent_allowed=false` and `selected_route=default`.

It is still not enough: `draft_cycles=0` and **254 `no_provider` events** over 256
autoregressive tokens, and an env-guarded print at the head of the adapter's
sampled proposal branch never fires. So `_sampled_route_request(request_id)`
returns **False inside `propose_batch`** even though the same predicate is what
lets the capability advertise `sampled` in the first place - the row has intent,
the plan asks for three candidates, and the adapter still does not take its
sampled branch.

The two conjuncts of `_sampled_route_request` are
`_sampled_route_qualified()` (static: an evidence row listing `sampled` for this
backend, architecture, quant, and artifact size) and
`speculative_sampling_mode(row params) == "sampled"` where the params come from
`row.sampling_request` or, failing that, `row.request`. Both are true by
inspection for this request, so the next run has to print them rather than
reason about them.
