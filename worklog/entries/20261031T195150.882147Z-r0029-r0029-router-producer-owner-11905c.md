# R0029 router producer is plan-owned runner state

## Summary

`HIPENGINE_QWEN4_EXP_ROUTER_VARIANT` no longer selects the router-logit producer.
The plan publishes it as request-local runner state (`runner.router_producer_variant`),
the launch selection reads only that field, and the four gate harnesses name their
arm on the runner they measure through `router_producer_variant(runner, mode)`.
The migration preserves tile4, ordered-DPP, F16-GEMM and warp-reduce primitive
choices without promoting the rejected warp composition. R0029 is removed from
the ledger after host and public selection checks; R0030's independent
arithmetic/selection-semantics decision stays open.

## Changes

- `hipengine/runtime/qwen4_exp_runner.py`: removed `_ROUTER_PRODUCER_VARIANT_ENV`
  and the `os.environ` read in `_qwen4_exp_router_producer_variant`, which now takes
  `requested: str | None` (None keeps the exact tile4 parent, the F16 GEMM keeps its
  64-row hand-off to ordered DPP). Added the `router_producer_variant(runner, mode)`
  scope (validate, bind, restore on error, yields the prior value). Added the
  `router_producer_variant` parameter to `run_qwen4_exp_moe` and the three layer
  entries, the runner class field, its constructor argument, and the four
  resident-runner call sites. No kernel body changed.
- `hipengine/generation/qwen4_exp_profiles.py`: `_selected_router_producer_variant`
  no longer reads the environment (plan default only: DPP on the recovery plan,
  tile4 otherwise); `_f16_route_selections` always performs its documented
  DPP -> F16-operand GEMM replacement instead of branching on a caller-named key;
  the binder publishes the manifest's `router_logits` selection to the generator and
  the runner it finds, and still reports a pre-bind caller value as discarded
  through `_record_owner_transport`.
- `hipengine/generation/qwen4_exp_gguf.py`: `_inherit_lane_decisions` copies the
  producer to c1 staging clones.
- `hipengine/runtime/qwen4_exp_batch_runner.py`: the batch owner carries the field,
  both layer entries and `_layer_ffn` forward it to `run_qwen4_exp_moe`, and
  `_expert_down_policy` appends the named producer (not a boolean rung) so a
  captured segment cannot replay under a different router kernel.
- `hipengine/generation/qwen4_exp_ar_batch.py`: the batch carrier copies the
  generator's published producer.
- `scripts/qwen4exp_layer2_profile_gate.py`: `CandidateSpec.router_producer_variant`
  (bound with the scope around the measured rows, recorded in the artifact, counted
  in `_candidate_named_profile_intact`); the F16-route isolation arms declare
  ordered DPP, `recovery_plus_indexer_router_f16` and the fast-composition arm
  declare the F16 GEMM, and the warp-reduce arm declares its own producer with its
  existing registry-key dispatch counting.
- `scripts/qwen4exp_profile_gap.py`: `--router-producer-variant` replaces the
  override key, which `--override` now rejects with that flag named; the producer is
  bound after the binder and reported.
- `scripts/qwen4exp_halo_box_campaign_ab.py`: `_apply_mode` no longer writes the key;
  `route_scope("router-dpp", mode, runner)` binds tile4 before / DPP after.
- `scripts/qwen4exp_row4_state_gate.py`: `apply_state_gate_mode` is a no-op for the
  package and `flag` is empty, so `arm_control`'s `route_scope` is the only selector.
- `docs/ENVS.md`: the row is now `retired` and names the runner field, the scope and
  the profile-gap flag.
