# Implement SPECDEC2 P4 device chain

## Summary

P4 starts from the retained P3 stable-pointer state and preserves strict
Generation-2 transaction, rollback, provider, output, and K0 ownership. The
boundary audit found two different debts. Staged C1 forces `allow_graph=False`
and therefore never reaches the already-retained cached proposal-event -> N2
target graph handoff. Physical C2/C4 already carries proposal IDs into packed
target embedding on device, but packed target then synchronizes and reads every
target top-1 plus every FP32 hidden row; the adapter separately reads candidate
IDs, reconstructs a Python `TargetVerifyBatch`, uploads accept inputs, reads a
seven-field summary, runs the CPU oracle, repairs provider state from host
proposal objects, and chooses target state from host accepted counts.

The minimum strict route is therefore not a new target math kernel. It is stable
device descriptors around retained arithmetic: warm/use the C1 proposal graph;
return packed target input/top-1/hidden/deferred-state views without D2H; D2D
reorder proposal and target IDs into persistent accept buffers; select target
hidden/Conv/GDN/KV/cursors from GPU accept buffers; read one bounded committed
output/status payload; and repair the provider from retained device proposal
IDs/hidden rows without reconstructing rejected candidate IDs. CPU reconstruction
remains an explicit qualification/debug oracle outside the promoted cycle.

## Implementation checkpoint

The GREEN implementation now:

- pre-captures request-local C1 proposal/N2 target graphs and verifier buckets
  during prompt activation, before the hot cycle;
- carries one C1 proposal event/result/hidden-row descriptor through the staged
  `CandidateGraph`, retires it in the cached N2 target graph, accepts and
  commits on device, and reads only compact visible/status output;
- returns request/slot/transaction-bound packed C2/C4 input/top-1/hidden/state
  descriptors without target or hidden D2H;
- D2D-reorders physical candidate and target IDs into persistent accept buffers,
  enqueues GPU accept, selects hidden/Conv/GDN/KV/cursor state from accept-buffer
  pointers, then performs the sole bounded result readback;
- repairs C1/C2/C4 NextN state from retained device proposal IDs/hidden rows,
  with host root replay only where canonical rollback requires it;
- preallocates physical selected-state pointer tables during prompt activation,
  so every measured C1/C2/C4 K2 cycle allocates/frees zero; and
- keeps the CPU accept reconstruction behind the temporary qualification-only
  `HIPENGINE_SPECDEC2_DEVICE_CHAIN_ORACLE=1` seam documented in
  `docs/REFACTOR.md`.

No target/draft arithmetic, kernel body, registry key, automatic K0 policy,
streaming-activation scope, physical replay fallback, or long-context policy
changed.
