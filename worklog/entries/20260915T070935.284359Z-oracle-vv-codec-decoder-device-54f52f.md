# Compose the codec primitives into the device-resident decoder

## Summary

M2c is done: hipengine/models/vibevoice_codec.py composes the vv_codec_v1
HIP primitives into the full acoustic decoder. Weights upload once as FP32
(~1.4 GB resident); conv-window caches are device ping/pong buffers sized by
each stage's cumulative hop; scratch is one bump arena sized by an exact
mirror of the allocation sequence. Streaming decodes copy only the latent
chunk in and PCM out; decode_full pads with zeros and leaves caches
untouched. Torch is not imported on the path.

Two device-safety defects were caught and fixed during bring-up, both of the
same class (window buffers sized for frame counts instead of upsampled
signal lengths):

1. The streaming convtr kept its kept output as a strided view over the
   windowed output; downstream raw-pointer kernels read it as dense. The
   convtr kernel now takes keep_from/kept_len and writes only the kept tail,
   compacted dense.
2. Non-streaming and late-stage streaming windows overflowed the fixed
   cache buffers (a 1.2 MB write into a 22 KB buffer at stage 3 full mode;
   stage-2+ streaming windows up to frames*1600 columns). Non-streaming
   calls now use exact-size arena windows; cache buffers are sized
   context + max_chunk_frames * cumulative_hop per stage.

The overflow produced nondeterministic neighbor corruption: short sequences
passed (pytest 12/12) while longer sequences page-faulted or produced
garbage, and a few crashed GPU contexts left transient fallout that
disappeared on later clean runs.

tests/test_gpu_vibevoice_codec_ops.py + tests/test_gpu_vibevoice_codec_decoder.py
+ tests/test_unit_cpu_reference_vibevoice_codec.py: 31 passed.

scripts/vibevoice_codec_oracle_export.py (oracle venv, torch CPU) exported
oracle_full/oracle_stream for the seeded 6-frame latent;
scripts/vibevoice_codec_gpu_reference_check.py (project venv, no torch)
compared (benchmarks/results/2026-09-15-vibevoice-codec-gpu-reference.json):

- GPU full vs CPU reference: max_abs 3.06e-10
- GPU streaming vs CPU reference: 2.84e-10
- GPU streaming vs GPU full: bit-exact (array_equal true)
- GPU 2-frame chunked vs reference: 2.84e-10
- GPU post-reset streaming vs reference: 2.84e-10
- GPU full vs torch oracle: 2.91e-10
- GPU streaming vs torch oracle: 5.00e-10

All errors sit at the FP32 accumulation-order floor (relative to waveform
peak: 3.3-5.8e-6), matching the reference-vs-oracle floor recorded in
2026-09-15-vibevoice-codec-cpu-reference.json.

Protocol note: the oracle venv's loaded ROCm-torch runtime interferes with
the module path when torch is imported first in the same process, so the
oracle export and the GPU check run in separate processes by design.
