# Migrate dense route and layer gate diagnostics to owner policies

## Summary

Migrate the dense-route comparison and layer gate before changing profile
publication. The binder and other diagnostic callers still use legacy keys;
R0425/R0426 remain open until their readers migrate together.

## Changes

- Both interfaces bind restoring WMMA and dense-wide owner controls, rather
  than writing wide process keys. Layer zero and empty/all semantics stay
  distinct, and existing process selectors (including staged-F32) stay intact.
- Add `Q8DenseWidePolicy.to_report()` and publish selected owner policies in
  both diagnostic artifacts, separately from ambient environment snapshots.
- Public tests exercise each interface through `LLM.generate_detailed()` and
  inspect final launches after cache lookup. Staged-F32 probes check the owner
  instead of an environment value that no longer selects it.

## Validation

- RED: nine new interface cases fail on the old environment-only controls.
- GREEN: 54 focused tests pass, covering restoring owners, environment
  preservation, policy reports, exact-parent staged comparisons and WMMA
  transport (`/tmp/r0426-diagnostic-owner-final-focused.xml`).
- All seven public tests pass without skips
  (`/tmp/r0426-diagnostic-owner-public.xml`): direct, layer-gate and dense-A/B
  controls engage final wide launches only in the enabled arm, repeat exactly
  within each arm and restore owners/allocations. Staged-F32 probes at lengths
  2 and 73 engage named layers; one-row controls remain inactive.
- Documentation, audit, test-tier, compilation and whitespace gates pass. No
  production arithmetic or profile selection changes in this unit.
