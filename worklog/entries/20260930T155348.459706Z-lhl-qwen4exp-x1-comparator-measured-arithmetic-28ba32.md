# X-1's local half closes and refutes its own derived bound — the comparator is 5.2x coarser than our F16 route, not 33x

## Summary

`X-1`'s first bounded experiment is *"score the already-captured identical-operand
MMB packet against F64 using the replay bridge."* **It had already been run on
2026-09-16** in `benchmarks/results/2026-09-16-cross-engine-replay/`; the ledger row was
never updated. The reference there is a genuine F64 matmul (`x64 @ w64.T` over the
packet's own dequantized weights and f32 activations), not a simulation.

The measurement refutes the derived bound that `E10` was written to check.

| | max abs vs exact F64 | mean abs vs exact F64 | normalized (÷13.595) |
| --- | ---: | ---: | ---: |
| hipEngine production | 2.06e-06 | 4.33e-08 | **1.51e-07** |
| **pinned comparator** | **1.466e-02** | **7.87e-04** | **1.078e-03** |
| comparator, the *withdrawn derived bound* | 0.0922–0.0978 | — | 6.8e-3 – 7.2e-3 |

Comparator: `mmb_dense_kernel<128, 256, 64, 64, 1>`, halo-box PR #63 `c4aa30229`.
**Mean-abs gap on byte-identical operands: 18,171x.**

The comparator tracks the both-operands-bf16 reference to 2.17e-06 mean abs,
confirming the arithmetic class it declares (it dequantizes Q8_0 to bf16 in LDS and
converts the activation to bf16 once per graph).

## Why the withdrawn bound was wrong

The derived row added `max_abs_vs_bf16both` (0.09499 — our F16 kernel's deviation from
a bf16-both reference) to our F16 kernel's own 0.00283 from exact. That is a
**triangle-inequality bound on elementwise maxima**:

```
max abs(a - c)  <=  max abs(a - b) + max abs(b - c)     -- valid
max abs(a - c)  >=  max abs(a - b) - max abs(b - c)     -- INVALID
```

The upper bound holds, so the derived row was never *false* — but it is useless as an
estimate, because the element attaining one maximum need not contribute to the other.
Here the two maxima sit at different elements and the bound lands **6.3x** above the
directly measured value.

## What it revises

The campaign carried two claims built on that bound:

1. **"The comparator's arithmetic is about 33x coarser than the path we spent this
   campaign gating."** Measured: `1.078e-3 / 2.08e-4` = **5.2x**. The correction is
   **6.4x**.
2. **"A BF16 variant ... at the cost of moving from `2.08e-4` to roughly `7e-3`
   relative."** Measured: **`1.078e-3`** — a **5.2x** move, not 33x.

Both are corrected in `docs/QWEN4EXP-STATUS.md` §2.6 and
`docs/QWEN4EXP-EXTERNAL-FORKS-REVIEW.md`, with the derived row struck through and the
measured row in its place.

## Consequence for DP-4

`DP-4` was gated on *"close `X-1`'s F64 packet first; only build a BF16 arm if
finite-range or measured producer/consumer cost motivates it."* The measured cost of
the BF16 class is now known and is **5.2x** our F16 route rather than 33x, so the
motivation condition is met. `DP-4` moves from evidence-gated to open on two remaining
conditions: a finite-range screen, and producer/consumer cost measured on same tiles
and real inputs.

## Validation

- The normalization scale is confirmed twice independently: the review states the exact
  F64 reference's max abs is `13.595`; `2.0555e-06 / 13.595 = 1.512e-7` reproduces the
  table's F32 row exactly, and `0.00283 / 13.595 = 2.082e-4` reproduces the F16 row.
- The comparator's normalized figure is stable to four significant figures either way:
  `hipengine_vs_comparator.max_abs` is `1.4659e-02` and hipEngine's own distance from
  exact is 2.06e-06, so the interval is `1.07812e-03` … `1.07842e-03`.
- Whole-ledger table integrity re-checked: 0 rows with a wrong cell count.

## Scope and limits

- **Neither figure is a task-quality claim.** This is one projection on one packet;
  route and scope admission is separate, and production correctness remains the
  admission criterion.
- **BF16 has 8 exponent bits to F16's 5**, so a precision-only ranking is not
  universal; the finite-range screen `DP-4` still requires is exactly about that.
- The comparator's 7.87e-04 mean-abs error is a statement about **its** acceptance
  criterion, not a licence to relax hipEngine's envelope.
- The packet arrays themselves are no longer on disk (they were captured on the gfx1151
  host), so this work reads the retained artifact and the review's recorded scale rather
  than recomputing from bytes.
