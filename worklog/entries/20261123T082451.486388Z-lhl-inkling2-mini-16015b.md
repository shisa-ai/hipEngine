# Screen exact reuse of Inkling residual rows

## Summary

Reusing normalized residual rows reduced ordinary scalar depth-mixing work on W7900 without changing scored logits or outputs.

## Changes

- Scratch only. Keep one reusable residual matrix during each scalar token. Copy a completed normalized row only when its source changes, and replace the current partial row on every read. Use the same contiguous matrix shape and dot products as the original stack.

## Validation

- On `epyc` (W7900, gfx1100), mainline `UD-Q4_K_M`, `50c3ee60a12c2467071dead6ae230716bb9bebd6`, `fast` manifest `ec04e8bdf2c53c55ebe895c0f905f388a72bb691af0658265dfc8b4676e1cb27`, FP32 KV, greedy, no prefix reuse or drafting. `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. HIPENGINE_REQUIRE_CACHED_BUILD=1 python -u /tmp/hipengine_inkling_reuse_residual_stack.py "$model" "$revision"` exercised 47- and 575-input prompts with 12 outputs, warmed, alternating both arm orders. All 11 ordinary decode logit rows per request matched bit-for-bit, as did token IDs, text and finish details.
- Completed residual row copies fell from 2,860 to 968 across each 11-step decode. At 47 input the median sum of timed depth-mixing calls fell from 50.95 to 44.35 ms; at 575 it fell from 51.29 to 44.93 ms. This is instrumented host phase time, not a Strix or Loom comparison.
