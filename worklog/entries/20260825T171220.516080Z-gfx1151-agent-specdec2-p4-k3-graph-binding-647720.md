# Fix SPECDEC2 K3 graph binding

## Summary

The first clean strict C1 K1-K3 qualification packet passed K1 and K2 but K3
faulted the GPU in captured `linear_state_pair_commit_chunked_i32`. The fault
occurred only when the activation-captured N2 graph was reused by a later
request. Audit found that `_native_target_binding_signature()` covered captured
linear-state row buffers but omitted the four device pointer-table allocations
consumed by the commit kernel. A target-session reset/rebind could therefore
leave a graph eligible while its captured table addresses were stale.

No K3 result is retained from the faulting run. P4 closure remains blocked until
the clean K3 oracle and downstream matrix pass.

## Changes

- Include source/destination Conv/GDN pointer-table buffers in the native target
  graph binding-generation signature.
- Make activation-time `prepare_native_spec_target_graph()` revalidate the
  complete existing graph binding/configuration and close/recapture a mismatch.
- Add a direct regression test proving the pointer tables participate in the
  binding signature.
