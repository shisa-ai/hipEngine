## The census's own method has a defect

The census deliberately reads the **end** of each status cell, and justifies it: *"several rows'
opening prefixes are stale; see the DE-1 correction in the same commit"*. **DE-1 is exactly the
row that defeats that rule.** Its cell *opens* with the terminal conclusion and its *tail* is a
limits-and-evidence statement with no state token — so a tail-reading classifier returns
"actionable" for a row whose own first word is `CLOSED`.

The rule should be: **a row is closed if a terminal marker appears anywhere in its status cell**,
with the end-of-cell read used only to resolve *contradictions* between a stale prefix and a later
conclusion. Applied that way, DE-1 classifies correctly and no other row in the 18 changes.

**A second defect, smaller:** `DP-6`'s entire status cell is **29 characters** — `"A (for layers
already on F16)"` — with no state token at all. It cannot be classified by any rule, and it is
carrying an open row in the punchlist on an undocumented state.

## Validation

Every classification is read from the row's own status cell and quoted, not inferred. The 18-row
actionable set from the 2026-09-30 census was diffed row by row rather than re-deriving all 72,
because an automated classifier over 72 long cells was tried first and produced 51 "open" — it
swallowed rows whose tails contain no state token, which is the same failure mode as the census's
own defect. That attempt is recorded here rather than discarded, because it is the evidence for
why the end-of-cell rule needs the anywhere-in-cell fallback.

**Limits.** Read-only, no GPU. `RT-1`'s classification is the judgement call in this table: its
cell head still reads `OPEN` while the segment that realises its lever is present, so it is
reported as "lever realised" rather than closed on my authority. `DP-6` is unclassifiable rather
than classified.
