# gufo-vs-hipEngine same-file gfx1151 comparison

## Summary

Same-file, same-host comparison of the prebuilt gufo edge binary
(`98641a6`, binary sha256 `8ca63994…`) against hipEngine `f31997b7` on the
Radeon 8060S (gfx1151). Qwen3.8-27B `Q4_K_M` and Qwen3.8-Flash-Next
`UD-Q4_K_XL` (four shards, gufo-published sha256 match) were each run on both
engines. gufo **cannot load** the local 35B-A3B (no MoE weight loader) or our
Flash-Next MTP sidecar; both were left uncompared rather than approximated.
No hipEngine default, registry entry, or kernel changed.

## Validation

- Host state `accelerator-performance` / `performance` verified at the start and
  end of every block; no other GPU process. Every point has ≥2 measured
  repetitions and a reported spread.
- 27B `Q4_K_M`, same file: hipEngine prefill **+3.5% / +4.2%** at 1K / 4K
  (per-shape, 406.18/398.82 vs gufo 392.36/382.74); gufo **+22.6% / +31.1%** at
  32K / 64K (360.22/336.92 vs 293.95/256.99); decode tied (12.18 vs 12.11).
  512 prefill inconclusive (protocol/session-size sensitive, 357–408 pp).
- Flash-Next `UD-Q4_K_XL`: gufo prefill **4.6x / 6.0x / 7.0x** at 512/1K/4K;
  gufo decode **1.34x** at d0 (26.71 vs 19.87). gufo MTP 1.47x its own AR
  (bench, output sha identical); hipEngine MTP 0.80x its own AR (request wall) —
  different protocols, not compared.
- Accuracy: gufo AR == gufo MTP on 10/10 committed-suite prompts; hipEngine
  AR == hipEngine MTP on 10/10; cross-engine greedy AR 9/10, diverging at
  generated-token 15 of `general_ja_explain` (`や` vs `）`). gufo exposes no
  logits, so no cross-engine KL envelope is reachable.
- gufo's published 27B `656.33 pp` row is not reproducible from this binary:
  `gufo serve` and `gufo bench` agree (380 vs 393), an IQ4_XS-mixed proxy file
  measures 761.90 pp, and the published build revision `628ed18e` is not in the
  local history. Gap attributed to file/quant composition, build revision
  untestable.
