# R0523 prompt-structure + page-binding inspection: race follows logical request 1

## Summary

Continues the R0523 c4 packed-decode race attribution (prior checkpoints
71c3ddd00, fdd869f53, dfa8c1be0, 81c40dc25, 835d06f06, efc4029d5). Host-side
inspection of the remaining KV/page-ownership seams found them correct, and a
new structural fact about the reproduction narrows the hypothesis: the four c4
prompts are identical except the final token, and the divergence always lands
on logical request 1.

## Changes

- Inspection only; no production code changed. The env-gated R0523 diagnostic
  tracer remains in `hipengine/generation/qwen35_gguf.py` (uncommitted) and must
  be reverted before any production commit.
- New findings recorded:
  - `_rebind_packed_verify_layout_pages` (qwen35_gguf_runner.py:2374) gives each
    slot its own physical pages (`base = slot_index * blocks_per_slot`); no
    cross-row page alias. Identity mappings return the layout unchanged.
  - `_packed_graph_block_table_is_device_rebuildable` + capture
    (gguf_packed_decode_graph.py:302,513-548): a GlobalDeviceKVPool workspace
    lease keeps the authoritative block table and redirects the in-graph
    metadata refresh's block-table output to a discard buffer, so replay cannot
    clobber the leased mapping. Private chunks use the rebuildable identity.
  - Capture body (gguf_packed_decode_graph.py:565-684): per replay step the
    order is metadata_kernel -> `_enqueue_packed_decode_model_step` -> commit,
    all on one captured stream; KV write and attention are stream-ordered.
  - `request_index` in scripts/server_f1_concurrency_bench.py is the logical
    HTTP request index (set at :1082 from the burst `index`), not a physical
    slot row. So "always request_index=1" means the second logical request.
  - `_prompt_rows` (server_f1_concurrency_bench.py:843): the c4 prompts are
    `[token_id]*prompt_length` with only the LAST token differing by row
    (`token_id + row%4`). The race always hits the row whose last token is
    `token_id+1`.
