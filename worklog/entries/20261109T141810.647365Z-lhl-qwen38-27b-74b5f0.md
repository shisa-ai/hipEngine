# Enqueue-only target verify: graph-owned aux-layer device capture (part a prerequisite)

## Summary

Task #25 part (a), first increment (campaign §6.2-3, §6.4 P1 row 1). The
generic-drafter cycles (EAGLE-4/DSpine) call eager `verify_target_block` with
`capture_layer_output_hidden`, which copies 3 (EAGLE) / 5 (DSpine) aux layers ×
rows × 5120 to host numpy every cycle; enqueue-only verify explicitly refused
layer captures, blocking graph-captured verify. This unit adds the runner
capability: enqueue-only verify now accepts graph-owned per-layer FP32
destinations (`_graph_layer_output_hidden_bufs`) and writes the aux rows D2D
(bf16→f32, or f32 memcpy under f32-residual) instead of a host copy. The copy
mirrors the existing graph-owned pre-output-norm capture and reads rows at
`scratch_row_start` (0 for a reusable/prebuilt graph scratch), not the eager
`start` offset.

Measured baseline that motivates the graph-capture integration (gfx1151,
Qwen3.8-27B-Q4_K_M, n_draft=2, 33 cycles, median): draft 51.3 ms, **verify
141.0 ms**, accept+commit 0.41 ms, aux-concat+append 17.6 ms. Verify is 67% of
the cycle. Synced stage timing shows the layer stack's device compute is ~98 ms
while the async host enqueue is ~131 ms — the eager verify is dispatch-bound, so
graph capture (capture once, replay with one launch) removes the dispatch
overhead and the per-cycle aux D2H, targeting the ~98 ms device floor.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py` `verify_target_block`: new
  `_graph_layer_output_hidden_bufs: Mapping[int, object] | None` param; enqueue-only
  validation now requires a correctly-sized graph-owned FP32 destination per
  captured layer (still refuses boundary captures); the private-controls guard
  rejects the new param outside enqueue-only; the layer-stack output capture is a
  named closure that does D2D into the graph buffer in enqueue-only mode and keeps
  the legacy host copy otherwise.
- `tests/test_gpu_gguf_verify_aux_device_capture.py`: 2 HIP-guarded real-model
  tests (bit-exact aux + tokens vs eager host capture; refusal without a device
  destination).

## Validation

- RED->GREEN: test failed on the missing kwarg, then 2/2 pass. Aux rows and greedy
  tokens are bit-exact vs the eager host capture in bulk mode (the supported
  enqueue-only config without a reusable graph scratch).
- Native-mode finding (diagnostic, not a defect in this change): native enqueue-only
  WITHOUT `_prebuilt_bulk_scratch`/dynamic-cursor/native-row-scratches mis-reads the
  first row's context even with no aux capture (token 13 vs 248046). MTP always
  supplies that reusable-scratch machinery for native mode; the generic-cycle
  integration must too. The aux D2D capture itself is mode-independent.
- No regression: public `LLM(speculative_provider="eagle4")` route still AR-exact
  (24 tokens) through the eager verify + host aux capture; runner parses; 11
  host-only native-spec-cycle unit tests pass; `audit/audit.py check` ok.
