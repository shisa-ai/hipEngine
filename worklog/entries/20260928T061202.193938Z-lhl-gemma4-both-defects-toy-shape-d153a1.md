# both expert defects are toy-shape artifacts so production prefill is unaffected and both routes stay on

## Summary

Both row-count divergences found in the expert forward are now measured at the
shape the model actually runs, and **both are invariant there**.

| route | true geometry | measurement |
| --- | --- | --- |
| fused gate/up MMQ | 2816 in, 704 intermediate, 128 experts | invariant (`20260928T060531`) |
| down MMQ | 2816 out, 704 in, Q8_0 | **invariant** (this unit) |

`tests/test_gpu_gemma4_expert_route_true_geometry.py` is **11 passed, exit 0**.

The down case uses the artifact's real quant -- the fixture's `ffn_down_exps` is
`gguf_q8_0`, which `20260928T060700` established after the previous unit had
assumed Q4_K -- and the real `704` input width, which Q8_0's 32-element blocks
divide exactly (`704 = 22 x 32`), so no shape substitution was needed.

## What this settles

**Production prefill is unaffected by either defect.** Both are properties of
the fixture's degenerate geometry, not of the routes where the model runs.

**Both routes stay on by default, and no default change is warranted.** This is
the outcome that matters for the objective: the fused gate/up MMQ is the
measured faster path (1.27x on the 512/128 prefill), and the down MMQ is what
the docstring calls the largest single route in gfx1151 prefill. Turning either
off on the strength of a toy-shape measurement would have traded real throughput
for a defect that is not present at production shapes.

**The fix is narrow and is a coverage fix.** What is wrong is these routes at the
fixture's shape, which is the shape the rest of the expert coverage uses and the
shape `tests/test_gpu_gemma4_expert_row_invariance.py` runs at. A route that is
wrong at a shape its own coverage uses is worth repairing -- and the two xfails
in that file are the record of it -- but it is not a production defect.

## The pattern, now confirmed twice

Both defects have the same shape of cause. The fixture's geometry is degenerate
in a way the true geometry is not:

| | fixture | true |
| --- | --- | --- |
| gate/up K | 256 = **exactly one** Q4_K block | 2816 = 11 blocks |
| gate/up fused width | 128 = **exactly one** column tile, no partial | 1408 = 11 tiles |
| down K | 64 = **below** one Q4_K block and one Q8_1 group | 704 = 3 blocks with a partial tail |
| experts | 4 | 128 |

Both defects live at the *boundary-free* end of that table -- a dimension of
exactly one tile or block, or below one. That is consistent with a tile or block
walk that is correct for interior blocks and wrong when there is exactly one, or
when the whole dimension is inside a single block.

## Changes

- `tests/test_gpu_gemma4_expert_route_true_geometry.py`: the down case added,
  `test_down_mmq_route_row_zero_is_invariant_under_an_appended_row`, with the
  import and `@_needs_hip` guard the other cases use. It asserts the route
  actually served (`served is True`) so it fails loudly if the Q8_0 weight is
  declined, and asserts row 0 is identical across row counts before relying on
  it, so it cannot pass vacuously.

## Validation

- `uv run pytest tests/test_gpu_gemma4_expert_route_true_geometry.py` on the
  8060S (gfx1151): **11 passed**, exit 0.
- The down case compares the route's own output at two row counts, so the
  comparison is bit equality against itself and involves no external reference.
- The Q8_0 quant is the artifact's own, read from the loaded weights in
  `20260928T060700`, not assumed.

## Next

Repair the two MMQ routes at the fixture's shapes, which turns the two xfails in
`tests/test_gpu_gemma4_expert_row_invariance.py` into passes. The block and tile
boundary is the place to look: both defects sit where a dimension is exactly one
block or tile, or below one. If the degenerate shapes turn out to be unsupported
by design, the alternative is to decline them explicitly and route to the grouped
family, which is a decision to record rather than a silent wrong answer.
