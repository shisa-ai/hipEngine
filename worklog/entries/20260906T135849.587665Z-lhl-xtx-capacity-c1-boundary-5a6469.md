# XTX capacity: refine C1 pass/fail boundaries and align the probe lease baseline

## Summary

Packet 5's C1 boundary is now refined at page-aligned 256-token steps on both
KV routes, measured after the capacity-honest workspace right-size with exact
token accounting and clean post-request ownership. BF16 last pass moves from
3,072 to **3,840 tokens** (3,328 / 3,584 / 3,840 pass at 21.324 / 21.525 /
21.820 GiB request peaks; 4,096 still fails eager warmup). The qualified INT8
fp32 per-token/head route last pass moves from 4,096 to **4,864 tokens**
(4,352 / 4,608 / 4,864 pass at 21.841 / 21.843 / 21.849 GiB; 5,120 still first
fails) — INT8 buys about one additional page-aligned step (~1K tokens) of
context at equal peak on the 24 GB card. The first probe attempt reported
`ownership_unknown` on every point because the probe's persistent workspace
baseline still assumed the historical 8-slot lease; the probe expectation now
mirrors the capacity-honest server formula (`max(1, N)` slots), and the
ownership checks run green.
