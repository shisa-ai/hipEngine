# Gate the TP2 bulk prefill route on the full suite

## Summary

TP2 prefill is the largest remaining gap in the route: the committed token-serial
schedule runs at 39-43 tok/s against the single-card bulk route's ~876 and the
llama.cpp tensor split's 1474. A rank-local bulk prefill path exists and is
opt-in, but it had never been scored by the **full-suite production gate** -
`--tp2-bulk-prefill` was wired only into the sustained-arm path, so the committed
gate always measured the token-serial route. That is now fixed, which is the
prerequisite for deciding anything about the bulk candidate.

Two things were established before the gating run:

1. **The bulk route still works after the rank residency change.** The rank MLP
   slot allowlist removed the resident full-width MLP from `tp2` runners, and the
   bulk path is the one route that could plausibly have depended on it. It does
   not: the 12-row smoke below runs both schedules in one process and both
   produce the same argmax tokens.
2. **Its accuracy is far better than the last recorded measurement.** The
   documented post-dispatch-context numbers were bulk-vs-teacher max KL 0.167053
   on `mixed_ja_en_translate`; the same prompt now measures **0.000372** with
   100% top-1 and zero flips.

## Changes

- `scripts/tp2_teacher_coverage_broad.py` — `_session_factory` gains
  `bulk_prefill`, the full-suite arm loop passes it for the `tp2` arm only, and
  `--tp2-bulk-prefill`'s help now says it applies to both the full-suite run and
  the sustained-arm path. The tp1 controls never receive it, so they stay the
  comparison basis, exactly like `--shard-fractions`.
- `tests/test_unit_scripts_tp2_teacher_harness.py` — the coverage fixture records
  the sessions it builds and a new test asserts the flag reaches the `tp2` arm
  and **not** the two tp1 controls.

## Validation

- `python3 -m pytest tests/test_unit_scripts_tp2_teacher_harness.py -q` → **67
  passed**.
- `teacher_forced_logits` dispatches to `self.bulk_prefill(...)` when
  `bulk_prefill_enabled`, so the gate's per-arm trajectory capture does exercise
  the candidate rather than silently re-measuring token-serial.
- 12-row smoke, both schedules in one process
  (`scripts/tp2_bulk_prefill_diagnostic.py --smoke-rows 12 --compare-serial`):
  - `mixed_ja_en_translate` (64 prompt tokens): bulk-vs-teacher max KL
    **0.0003716**, mean 7.171e-05, p95 2.381e-04, p99 3.449e-04, top-1 **100%**,
    0 flips, gate **passed**; bulk-vs-serial max KL 2.430e-04 with 0 flips; bulk,
    serial and teacher argmax are identical on all 12 rows.
  - `heldout_mixed_summary` (52 prompt tokens): bulk-vs-teacher max KL
    **0.0004543**, mean 1.162e-04, top-1 **91.67%** (1 flip) so the category bar
    fails on this window. The flip is the **last** row and bulk and serial share
    the same argmax there (28452 against the teacher's 196726), i.e. it is a
    property of both TP2 schedules on this 12-row window, not a bulk regression.
- Not yet run: the full-suite gate with `--tp2-bulk-prefill` (in flight).
