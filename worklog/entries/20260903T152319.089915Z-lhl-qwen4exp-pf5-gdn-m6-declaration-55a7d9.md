# PF-5 GDN M6 port declaration: arithmetic class, lineage status, RED plan

## Summary

PF-5 opening declaration for the ordered punchlist item 3: port the M6 GDN
launch geometry from the halo-box PR11 `gated_delta_net.cu` parent into the
in-tree owner `hipengine/kernels/hip_gfx1100/linear_attn/qwen4_exp_gdn.{hip,py}`
(registry entry `gdn_recurrence_norm_gate`, `f32_state` family).

- **Scope:** two candidate levers, both launch-geometry/state-residency only:
  1. 32 warps/block for the S_v=128 GDN prefill/recurrence family (the current
     owner launches with far fewer warps; PR11 measured its own kernel-family
     sum at p4096 drop 2,139.4 -> 648.0 ms with this geometry).
  2. Token-tile-16 state-in-register prefill (carry the recurrent state in
     registers across 16 tokens instead of round-tripping through LDS/global
     per token).
- **Arithmetic class: T0 candidate.** Both levers preserve the FP32 recurrent
  accumulation order if implemented as declared: warp-level shuffle reductions
  inside a fixed per-column order, no cross-lane reassociation, no precision
  change, no fusion with the RMSNorm/gate composite unless that composite is
  itself exact-parity RED against its strict fallback. If any implementation
  detail forces a reassociation, the class escalates to T1 and the unit stops
  until PF-0 (natural-text fixture) exists and a full section 6.2 packet is
  run. This escalation rule is binding.
- **Registered strict fallback (named per loop contract):** the current
  unmodified `gdn_recurrence_norm_gate` (`f32_state`) owner plus the
  `linear_attn_prefill_prepare` primitive chain, both already registered under
  their four-axis registry keys; the candidate variant registers as a new
  variant key on the same (backend, layer, quant) axes with the strict owner
  retained as fallback.
