# Share GGUF prompt chunk planning and publication

## Summary

Extract prompt-chunk shape policy and successful-enqueue accounting from GGUF-specific code. Dense and MoE public generation preserve output IDs, chunk boundaries and acceptance decisions against clean `1906b54d2`. This unit makes no performance claim.

## Changes

- `hipengine/speculative/prompt_prime.py` owns the common `PromptPrimeSink` protocol, immutable chunk/plan records, and two-phase `PromptPrimeLedger`. A chunk is checked before device work and published after its enqueues succeed.
- Dense `_StreamingNextNPromptSink` uses the common split planner for row limits and prefix boundaries, preserving carried-row alignment, borrowed-buffer lifetime, final-row transfer and provider-specific launches.
- MoE `_MoeTargetHiddenSink` uses position-addressed publication. It intentionally does not inherit the dense sink's contiguous append requirement. `TargetHiddenChunkSink` remains an alias at its existing import location.
- `docs/PLAN.md` names the shared owner. The existing `HIPENGINE_MTP2_TRACE_DECLINE` diagnostic branches moved; audit decisions preserve their prior deferred debt rather than introducing new decisions about the flag. Audit refresh also sorted an unchanged stub-triage row.
- Parent integration review found that MoE close constructed a synthetic request ID `-1`, rejected by the new ledger. A RED test reproduced the failure. Teardown now detaches the target buffer directly, without inventing a request; repeated close frees each buffer once.
- PARO cache-only priming is a separate concurrent logical unit; the full optimization matrix remains open in `docs/reference/SHARED-SPECULATIVE-OPTIMIZATION.md`.
