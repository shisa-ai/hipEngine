# Remove slot-local per-slab KV import; disprove the import attribution

## Summary

Reviewer-ordered unit 2: profile, then remove, the slot-local per-slab
whole-history KV import. Both halves are done; the important outcome is the
corrected attribution: **the import was dead work, not the long-prompt
bottleneck**, and the previous unit's claim to that effect is withdrawn here.

## Decisions

- **Withdraw the import attribution.** The 2026-09-10 per-layer-oracle unit
  recorded the per-slab import as "the real cause of the slow long-prompt
  server path". With the import fully removed and wall time unmoved at every
  measured shape, that is disproven at these shapes. The removal stands on its
  own merits (910 MiB of dead copies and 7,168 dead dispatches removed at
  8 chunks, quadratic dead work at fixed chunk size) and is described as
  reduced copies/dispatches, not a throughput win.
- **Keep the change unconditional per route, not per chunk count.** A
  single-chunk slab never imported anything anyway (position zero), so there
  is no behavioral split to preserve; the flag mirrors the scatter-side
  `copy_kv` for symmetry.
- **Two rocprofv3 attempts were stopped, not debugged.** Both stalled in
  `hipcc --version` compiler-version discovery under the profiler (the
  hazard is cataloged in docs/KERNELS.md and RDNA3-TUNING-GUIDE §4.9; I
  failed to check them before launching). The working recipe is now recorded
  in HARNESSES.md and the probe docstring so the follow-up starts correct.
