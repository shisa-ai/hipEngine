# Fix Gemma 4 untied-head slot and per-layer FFN geometry

## Summary

Two runtime defects are fixed. The resident planner names the untied output
projection slot ``lm_head`` (its GGUF tensor is ``output.weight``), but
``load_gemma4_device_weights`` looked it up as ``output``, so every untied
artifact failed to load with a slot-missing error. Separately,
``gemma4_text_config_from_gguf`` collapses the artifact's per-layer
``feed_forward_length`` array to its maximum, and the runner handed that maximum
to every layer as its dense-MLP width. The layer forward sizes the dense
projections from the scratch it is given, so a layer narrower than the maximum
dispatched ``mlp_gate_proj``/``mlp_up_proj``/``mlp_down_proj`` at the wrong
width and read past the weight. Kernel arithmetic is unchanged.

## Changes

- `hipengine/runtime/gemma4.py`
  - `load_gemma4_device_weights` now resolves the untied head with
    ``require("lm_head")``, matching the planner's slot path.
  - `Gemma4DeviceWeights` carries ``dense_intermediate: tuple[int, ...]``, the
    per-layer dense-MLP widths. The loader derives each width from the layer's
    planned ``ffn_gate`` spec (logical shape's leading dimension is the
    projection's ``out_features``), so no separate metadata path can drift from
    the resident tensor.
  - `Gemma4Runner.__post_init__` sizes each layer's scratch from that layer's
    own width via ``getattr(self.weights, "dense_intermediate", ())``, falling
    back to the config's single value for synthetic weights objects. A width
    count that disagrees with the layer count raises rather than silently
    truncating.
  - No change to `gemma4_text_config_from_gguf`: `intermediate_size` remains the
    maximum for the CPU reference, which reads each layer's width from its own
    weight shape and therefore already supports unequal layers.
- `tests/test_unit_gemma4_weight_geometry.py` (new, CPU-only)
  - Drives the real `load_gemma4_device_weights` over tiny in-memory GGUF
    fixtures with `materialize_gemma4_gguf_device_weight` and
    `load_host_array_to_device_as_dtype` faked. No HIP import, device, or kernel
    launch.
  - Covers untied-head loading, tied artifacts staying headless, per-layer width
    preservation, per-layer scratch sizing, and the exact dense projection
    `out_features`/`in_features` captured by running the real
    `gemma4_layer_forward_bf16` on each runner scratch with the layer kernels
    replaced by recorders.
