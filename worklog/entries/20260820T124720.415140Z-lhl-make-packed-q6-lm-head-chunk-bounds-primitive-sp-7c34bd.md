# Make packed Q6 lm-head chunk bounds primitive-specific

## Summary

Review of the Q5/Q6 rows5-8 handoff found a real regression in `a2cf2fc99`.
That commit globally applied `max_chunk=min(configured,4)` inside
`_verify_lm_head_rowtile_chunked` because Qwen3.8's planar-qmicro Q6 FP32
rowtile supports only rows2-4. The same function also serves standard Q6T16,
whose registered FP32 rowtile supports rows2-6 and whose retained package
policies are gfx1100=6 and gfx1151=5. The global cap silently disabled those
retained 6+2 / 5+3 routes and made their package capability/rollback controls
ineffective.

Width support now comes from metadata on the resolved four-axis primitive:
standard Q6 FP32 rowtile declares max rows 6; planar-qmicro FP32 rowtile declares
max rows 4. The chunk planner intersects this primitive bound with the backend
package/env choice. There is no backend or quant branch in model code, and
missing metadata fails closed to the ordinary linear fallback.

The BF16-output planar-qmicro rows2-8 promotion is unchanged. This repair
concerns only the root LM-head's separate FP32-output rowtile.

## Changes

- Add `_hipengine_max_rows=6` to the standard Q6T16 BF16→FP32 rowtile wrapper.
- Add `_hipengine_max_rows=4` to the planar-qmicro Q6T16 BF16→FP32 rowtile
  wrapper.
- Add `Qwen35GGUFResidentSession._verify_lm_head_rowtile_max_rows()` to resolve
  the root head's ordinary four-axis rowtile key and read its declared bound.
- Intersect configured package/env chunk size with that primitive bound.
- Pin standard-Q6 gfx1100 6+6, gfx1151 5+3, env rollback 6+2, and planar-qmicro
  cap4 behavior in focused tests.
