# Fix embedded Qwen4Exp tool protocol and add grammar masking

## Summary

Fix Qwen4Exp tools through the model-owned embedded GGUF template and XML parser,
while preserving generic JSON calls. Add request-owned llguidance schema/grammar
masks before greedy argmax. User explicitly expanded scope to grammar support
and authorized downloading tool-eval-bench. This took longer than expected;
the user requested a status clarification before resuming.

## Changes

- Immutable Jinja sandbox renders the actual embedded template; normalize OpenAI
  history arguments from JSON strings to objects without mutating requests.
  Preserve model reasoning convention, explicit effort and grouped tool results.
- Model-owned XML typed parameters/multiple calls, JSON-envelope compatibility,
  fail-closed malformed/duplicate parameters and reasoning-span exclusion.
  Bare JSON fallback requires declared tools and is disabled for structured answers.
- New hard dependency llguidance>=1.8,<2 (installed1.8.0), Torch-free tokenizer
  from Rust-tokenizers JSON. No Transformers import. Source API consulted at
  guidance-ai/llguidance@bae21e505859b9a338b7aeefaa8a64319ba41831.
- JSON Schema, object, regex, choice and GBNF/Lark plus XML tool grammars.
  Request grouping carries grammar; per-row matcher isolation; constrained logits
  D2H/mask precedes argmax and explicitly selected token feeds next step.
  Ordinary unconstrained compact device-token path stays unchanged.
- Required/named/single-tool masks supersede generic JSON forced prefixes only
  for the model-owned XML route. Combined tools/schema admit tool calls or a
  valid answer; tool calls are not judged as JSON answers.
- Lazy chat resolves model protocol before render; capability reporting scoped
  to model. Speculative/multimodal grammar paths reject rather than bypass masks.
