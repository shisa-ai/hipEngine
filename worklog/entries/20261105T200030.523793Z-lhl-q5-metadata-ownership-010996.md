# Unify Q5 metadata diagnostic forwarding

## Summary

Keep independent constructor-owned Q5 metadata diagnostics and unify target-AR
forwarding so load and borrowed-weight sessions cannot drift in their CLI mapping.

## Changes

- Both target-AR construction sites call one pure metadata-options helper.
  Output, query/gate and shared-pair opt-outs remain independent; omitted values
  still defer to backend capabilities. Effective result fields are unchanged.
- Add independent forwarding and resolver tests; parameterize query/gate pair
  binding over fixed-metadata and ordinary variants, without a mixed quad.
- No runtime arithmetic, defaults or registered fallback changes.
- RED-first was not used: this removes duplicated forwarding with unchanged
  behavior, then adds regression coverage for that preserved contract.

## Validation

- Q5 control retirement, runner, target-AR, Q5 SWAR pair and mixed pair unit
  files pass (`/tmp/q5-metadata-ownership.xml`).
- Tests confirm pair binding, not real device arithmetic. Primitive comparisons
  remain locally startable; public actual-weight validation needs Laguna weights.
