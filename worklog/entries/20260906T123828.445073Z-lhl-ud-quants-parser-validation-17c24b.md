# UD-U0a parser validation audit repair

## Summary

Completed the interrupted UD-U0a unit: `scripts/gguf_quant_route_audit.py` now
performs two-tier GGUF parser validation with a structured diagnostic mode, and
`tests/test_scripts_gguf_quant_route_audit.py` pins the contract. Strictly
parser-only: metadata and tensor-info bytes are inspected, no weights are read,
no model support is claimed, no GPU or runtime code is touched, and real-file
smoke is deferred to U0b.

Format-layer admission is separated from consumer qualification. Complete files
are admitted by production `scan_gguf` and marked format-valid (format-layer
only, never "model loads"); files production refuses fall into an explicit
partial diagnostic mode whose bounded mirror reports unsupported version,
duplicate metadata keys/tensor names, invalid alignment, and incomplete
descriptor table versus incomplete payload as distinct statuses, and never
marks a refused file format-valid or loadable (CLI prints "NOT loadable").

A fresh review raised three binding findings, all repaired here with targeted
RED/GREEN regressions: (1) `_SCAN_REFUSAL_ERRORS` missed the plain
ValueError/TypeError surfaces production uses to refuse hostile metadata —
`int()` on a string or array `general.alignment`, `GGUFValueType()` on an
unknown metadata value-type id, `quant_shape_to_byte_shape` on a
block-layout-violating shape — so `validate_parser`/CLI crashed instead of
writing a JSON verdict; (2) the diagnostic mirror still substituted
`GGUF_DEFAULT_ALIGNMENT` after rejecting an invalid alignment, inventing
offsets — it now keeps `data_start=None`, `data_complete=False`, and builds no
tensor records; (3) a descriptor with an unresolvable size (unknown type id,
bad block shape) was dropped and the empty range loop then claimed
`data_complete=True` — unresolved sizes are now tracked and keep
`data_complete=False`. A forced planner-qualification exception coverage pin
(error-shaped backend entry, exit 0) was added; it was GREEN on arrival.

## Changes

- `scripts/gguf_quant_route_audit.py`: added `ParserValidation` dataclass,
  `validate_parser` (production scan first, mirror-gap guard stays refused),
  and `diagnose_header` (fail-closed bounded mirror: stops at the first loss of
  structural boundary, unknowns stay unknown). Widened `_SCAN_REFUSAL_ERRORS`
  with documented ValueError/TypeError; removed the invented default-alignment
  offsets; track unresolvable descriptor sizes for `data_complete`; CLI report
  gains a `parser_validation` section, prints format-valid/"NOT loadable"
  verdicts, and keeps route/plugin-map sections best-effort diagnostic-only.
  `read_header` remains backward compatible.
- `tests/test_scripts_gguf_quant_route_audit.py`: preserved the five original
  guard tests; added 13 test functions (22 cases) covering the two-tier
  contract, per-finding regressions above, and the planner-error CLI pin.
  Test-harness note: the module defines dataclasses, so the importlib harness
  must register the module in `sys.modules` before `exec_module`.
- `docs/UD-QUANTS.md`: marked only the U0 parser-validation RED checkbox done;
  all other U0 tasks and support claims remain open.
