# Localize the resident block divergence to the third residual row

## Summary

Dumping the block's residual stack at the first message pass and matching each row against the host's blocks shows rows 0 and 1 exact and row 2 wrong by 14.4. The stack convention is therefore correct and the host mapping is one-to-one by index; the defect is in the row written during the abandoned pass, not in the message window, the restart, or the partial.

## Changes

- Instrumented the block's message-pass branch to download the residual region, and captured the host's `blocks` list at the same layer.
- Reverted the experiment that read the partial from the post-restart hidden state.

## Validation

64 rows, `Inkling-2-Mini-UD-Q4_K_M-mainline.gguf`, `hip_gfx1100`, fast profile. `stride` is 6 and `core_start` is 6, so the loop re-enters at the visit whose `weight_layer` is 6, and the host holds four residual blocks at that layer (0, 6, 12 and the current one).

Nearest-match of each block stack row against the host's blocks at the message pass:

| block row | nearest host block | max abs |
| ---: | ---: | ---: |
| 0 | 0 | 1.907e-06 |
| 1 | 1 | 5.722e-06 |
| 2 | 2 | 1.441e+01 |
| 3 | 2 | 2.436e+01 |

- Row 3 is the partial written from the pre-restart hidden state, so its mismatch is expected and it has no true match.
- Rows 0 and 1 matching by index confirms the convention: each visit writes the row for the hidden state entering it, and the host appends the same value at the same index.
- Row 2 is the row written during the abandoned pass at the visit whose `weight_layer` is 12. Its hidden state matches the host to 2.8e-06 (measured per visit), yet its stored row is 14.4 off, so the row write or a later overwrite of that row is wrong rather than the state.
- Writing the partial from the post-restart hidden state instead of the pre-restart one raises the next-visit error from 6.065 to 1.850e+01, so the pre-restart source is correct and the change was reverted.
