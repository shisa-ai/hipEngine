# R0523 per-layer hidden trace: corruption originates in full-attention layer 47 (KV path), not GDN/conv

## Summary

Used the in-graph per-layer hidden recording (`record_layer_output_hidden`, all
64 layers) with a hidden-only tracer (one D2H per replay, no per-step conv/rec/KV
hashing) to localize the R0523 c4 race with minimal observer effect. Two bursts:

- Aggregate hidden (steps 1-12, 40 reps, `r0523-hidden-trace.json`): race 1/40
  (req1/pos73/6866->3154); hidden state first diverges at step 4 (rep32), step 5
  (rep9), step 7 (rep25). Conv/recurrent state stayed byte-clean (prior entry).
- Per-layer hidden (steps 1-10, 40 reps, `r0523-layer-trace.json`): race 3/40
  (req3/pos17/16->15 and 2x req1/pos73/6866->3154). Earliest measured-rep
  divergence: rep6 step=5 LAYER=47; corruption then propagates through layers
  48-55 (most-frequently divergent).

Confirmed from GGUF metadata (`scan_gguf`): architecture qwen35, block_count 65,
`full_attention_interval=4`, so layer_types = full_attention at (i+1)%4==0.
Layer 47 is FULL_ATTENTION (48%4==0); layers 45/46 are linear_attention.

CONCLUSION: the corruption originates in a FULL-ATTENTION layer's output (the
paged-KV read/write / attention / o_proj path), NOT in the GDN/conv linear-attention
state update. This is consistent with conv/recurrent state being clean and rules
out the single-row GDN recurrent kernel as the origin. The race still always hits
logical request_index=1 in the dominant pos-73 signature.
