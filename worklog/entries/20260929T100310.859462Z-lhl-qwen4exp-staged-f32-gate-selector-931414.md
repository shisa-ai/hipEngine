# Gate the staged-f32 route and price DP-5/DP-6 from X-3

## Summary

Two things, both aimed at the same question: which remaining ledger rows are
actually actionable.

**1. The staged-f32 route is now gate-selectable.** Added a `staged_f32` entry to
`SELECTORS` in `scripts/execution_profile_q8_wmma_prefill_layers_gate.py` and the
matching `STAGED_F32_LAYERS_ENV` constant. The gate is running at full scope
(0-47), canonical depth (128 decode steps), 3 repeats, all 12 cases.

The route needs **both** wide selectors cleared in **both** arms, for a reason
that is not obvious and that the sibling `dense_wide` entry documents for its own
case: the staged tile replaces the leaf of the *exact* coltile chain, and its
dispatch declines any variant the wide or WMMA routes have already rewritten. If
the wide selector stayed bound, the candidate arm would resolve to a wide/WMMA
variant, the staged tile would never be selected, and the run would silently
measure the exact chain against itself and report a near-zero KL. Verified the
wiring end-to-end before launching rather than discovering it in the artifact:
candidate arm resolves to `staged_f32_bm128_bn64_bk32`, teacher arm and
out-of-scope layers resolve to
`coltile8_rowbatch4_wave_scale_pipelined_f32_f32_out`.

That pre-flight check also caught that `--layers` reaches the selector through
`_parse_layers`, which normalizes `0-15` to a comma list. My first check passed
the raw range string and got `ValueError: invalid literal for int() with base 10:
'0-15'` - a false alarm about my parser, not a real bug, but it only surfaced
because the check ran through the real path.

**2. DP-5 and DP-6 are priced from evidence that already exists.** Both rows were
gated on "price it in the X-3 capture", and section 1.3 has carried the numbers
since 2026-09-28 without either row recording them.

- **DP-5 is priced and its earlier framing was wrong by an order of magnitude.**
  F16 staging casts total **131.001 ms** of a 15,741.963 ms kernel union (0.83%).
  The row previously cited "the measured sharing term of the current staging is
  only 7.478 ms" and treated that as evidence the row was low-value. 131.001 ms
  is 17.5x that. It is a ceiling, not the recoverable part - the F16 stores
  remain, only the separate pass disappears - but it is 17.5x more than the
  number the row was dismissed on.
- **DP-6 is partially priced, and deliberately not marked rankable.** The whole
  norms bucket is 319.494 ms (2.03%), which upper-bounds the q/k-norm plus RoPE
  passes. The SSM causal conv and KV store are not split out. 319.494 ms covers
  more passes than this row would fuse, so it must not be used to rank DP-6
  against DP-5's 131.001 ms.
