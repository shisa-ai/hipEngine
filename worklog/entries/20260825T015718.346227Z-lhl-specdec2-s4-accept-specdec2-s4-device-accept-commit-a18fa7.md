# Batch gfx1151 SPECDEC2 accept and selected commit

## Summary

Replace request-local host acceptance and selected target-state installation
with one physical-group GPU accept payload and one packed-owner commit call. The
existing DFlash accept kernel emits accepted counts, commit rows/tokens/
positions, next tokens, full-accept flags, and compact lengths for C2/C4. The
adapter compares the GPU summary to the strict CPU oracle before mutation, then
the packed target owner installs each independently selected hidden/Conv/GDN/KV
row as one group operation with one fused linear-state commit.

The output owner remains Generation-2 and provider checkpoint repair remains
independent per request. This unit does not promote automatic speculation; true
AR still wins the measured cells.

## Changes

- Add a stable R16/C4 `TargetVerifyBufferOwner`, remaining-budget vector, and
  packed seven-field accept payload to the MTP2 adapter; free it with adapter
  lifecycle.
- Launch one `dflash_accept_chain_i32_packed` per physical target batch and read
  one bounded group payload. Reconstruct a `TargetAcceptSummary` and require
  exact equality with the CPU accept oracle.
- Add `_commit_deferred_packed_verify_states_batch`: gather all selected
  target hidden and linear-state rows, copy accepted KV prefixes, issue one
  fused linear-state pair commit for all request/layer entries, and publish each
  exact cursor.
- Replace the adapter's per-request selected-state commit loop with the group
  commit and add binding device-accept/selected-commit telemetry.
- Add a controlled correctness-only C2 neighbor gate: request 0 full-accepts K2
  while request 1 rejects at the root, then an unmodified speculative pair must
  recover exact strict IDs.
- Extend the strict C2/C4 gate to require one GPU accept and one selected-commit
  batch per physical target batch.
