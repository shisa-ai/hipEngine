# RF7 chat result validation owner

## Summary

Extracted the tool and structured chat-result validators from
`hipengine/server/api.py` into
`hipengine/server/chat_result_policy.py`. The owner receives explicit
normalized `ToolResultPolicy` / `StructuredResultPolicy` records plus the pure
`_ParsedChatOutput` parser result. It has no request-model, engine, app-state,
`OpenAIHTTPError`, or callback-bag dependency; it reuses the pure JSON Schema
value validator.

The application keeps ordered request validators, response shaping, hard-error
and finish policy, engine/protocol/sampling/prompt adapters, and the small
request-to-policy builders. In particular, `_validate_chat_tool_result` keeps
the no-tools short-circuit before building a policy, and
`_structured_output_failure_reason` keeps the old branch order. Each structured
branch builds only the normalized values that branch uses, so guided regex,
schema, choice, and patch values are not evaluated on inactive, `length`, or
`tool_calls` branches.

## Changes

- `hipengine/server/chat_result_policy.py` (new): tool validation, tool
  schema/name helpers, structured response-format and guided failure reasons,
  guided-patch parsing, JSON-object length-prefix validation, and
  `json_schema_root_object`.
- `hipengine/server/api.py`: imports the owner; keeps the no-tools tool wrapper,
  the structured branch/finish wrapper, `_structured_json_object_prefix_validation`,
  `_json_object_close_forcing`, and `_strict_tool_validation_enabled` (which
  still takes the request and supplies explicit policy inputs). Removed the
  moved implementations and the unused `_is_json_object_text` helper.
- `tests/test_unit_server_chat_result_policy.py` (new): 76 tests covering the
  captured tool/structured goldens, public exception fields, control-helper
  call order, direct owner validation, and owner dependency purity.
- `tests/fixtures/chat_result_policy_golden.json` (new): 17 tool cases and 36
  structured cases captured from `16864d1f9` before the move. It records failure
  strings, parsed results, exception fields, and the old control-helper trace.
- `tests/test_unit_server_pure_owner_consumers.py`: registered the new owner.

Fixture provenance: captured by importing the pre-move `hipengine.server.api`
at `16864d1f9`, instrumenting the structured control helpers, and executing the
old `_validate_chat_tool_result`, `_structured_output_failure_reason`, and
`_structured_length_failure_reason` entry points against explicit fixed parser
outputs and request payloads. The fixture pins the lazy short-circuits for
no-tools, non-strict tools, `tool_calls`, `length`, inactive guided fields,
invalid guided-patch fenced values, and JSON-schema extraction only after JSON
