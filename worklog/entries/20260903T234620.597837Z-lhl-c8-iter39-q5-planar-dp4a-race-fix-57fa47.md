# c8 iter39: grouped planar-Q5 dp4a output-col race fix + leaf win 9/9

## Summary

The grouped planar-Q5 dp4a sibling (rows 8-64) was producing nondeterministic
outputs on every launch. Root cause found and fixed: the output store used
`col = col_base + c` (the 8-column half offset only), omitting the
`out_tile * 16` term — workgroups 2k and 2k+2 wrote the same output
addresses with different 16-row tiles' data, so the final value depended on
workgroup scheduling order. The recurring "stale" values were the other
tiles' *correct* outputs winning the race (state A = tile 0, B = tile 1,
C = tile 2 for any given column), which is why they looked like old-build
outputs. Fix: `col = out_group * kCols + c` (the Q6 grouped kernel's
`out_group * kTileCols` form). After the fix the 128-thread xchg reduction
(the suspected culprit for most of the session) is fully deterministic and
was restored unchanged.
