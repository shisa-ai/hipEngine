# LDS padding fixes 131K prefill inversion: +29.8%, bit-exact, 1.10x llama.cpp

## Summary

Closed #25. The profile (see the checkpoint entries on this topic) showed
flash-prefill WMMA attention was 52.3% of the 131K prefill wall at ~26% of
bf16 WMMA peak. Root cause: the mt kernel staged K/V tiles at row stride
HEAD_DIM=128 halves (256 B). That stride put all 16 lanes of every k_frag
read on one LDS bank group (16-way conflict) and the staging writes on 8 of
32 banks (32-way). Padding the row stride by 2 halves (MT_KV_STRIDE=130,
260 B) shifts each row by one bank word: k_frag reads conflict-free, staging
spreads over all 32 banks. Layout only — per-key arithmetic and tile order
unchanged, so no reassociation/promotion gate was required; bit-parity was
the gate.

End-to-end prefill (muse_glimmer_ar_bench, 2 reps median, same host/day as
the before rows; llama.cpp comparator = upstream HEAD 3b4d6ab3f):

| ctx | before | after | gain | vs llama.cpp |
| ---: | ---: | ---: | ---: | --- |
| 512 | 553.2 | 557.9 | +0.9% | 1.119x |
| 1024 | 581.6 | 591.5 | +1.7% | 1.195x |
| 4096 | 544.7 | 570.8 | +4.8% | 1.191x |
| 32768 | 452.2 | 507.2 | +12.2% | 1.061x -> 1.190x |
| 131072 | 286.4 | 371.6 | **+29.8%** | **0.846x -> 1.098x** |

131K TTFT 456.5 -> 347.4 s (llama.cpp 387.3 s). The long-context prefill
inversion is fixed; hipEngine now leads prefill at every measured shape
(1.10-1.20x). Decode unchanged (path untouched).
