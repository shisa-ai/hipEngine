records the runner design and one concrete gap found while planning it, so the
next session starts from the plan rather than rediscovering it.

## The gap: the embedding scale

The reference does `hidden = embedding[ids] * sqrt(hidden_size)`. This is not
skippable even though the layer's first op is an RMSNorm, which is
scale-invariant: the scaled embedding *is* the residual stream, and the attention
and MLP outputs are added back to it. Skipping the scale would leave the residual
stream wrong by `sqrt(hidden_size)`.

There is no kernel that multiplies a bf16 row by a float scalar. Searched
`hipengine/kernels/hip_gfx1100/` for one:

- `f32_scale_rows_to_bf16` — f32 input, not bf16.
- `bf16_to_fp16_scaled_rows` — converts to fp16.
- `evie_scaled_add` — a different op in the Evie family.
- `gemma4_router_prescale_bf16` — hard-codes `hidden_size**-0.5` and is fused into
  the router.

So the runner needs a small `gemma4_scale_bf16(x, out, rows, hidden_size, scale)`
kernel. It is a few lines, has an obvious oracle (NumPy multiply), and belongs in
the gemma4 norm family beside `gemma4_branch_add_bf16`.

The alternative — folding the scale into the embedding gather — would mean a
per-quant embedding kernel variant, which is more work for less clarity.

## Runner shape

`hipengine/runtime/gemma4.py`:

- `load_gemma4_device_weights(reader, ...)` → `Gemma4DeviceWeights`: the embedding,
  final norm, lm_head (or `None` when tied), and a `Gemma4LayerPointers` per layer
  assembled from the quantized projections and f32 norms. Reuses
  `plan_gemma4_gguf_resident_specs` / `materialize_gemma4_gguf_device_weight`, so
  the tensor→slot mapping is the one already tested.
- `Gemma4Runner`: owns the KV cache and scratch, and exposes `reset()`,
  `prefill_native(token_ids)`, and `step(token_id)`.

Details worth carrying over:

- RoPE tables are per layer, not per model: `config.geometry(layer)` differs
  between sliding and full layers. `gemma4_rope_cos_sin_tables(geometry.rope,
  positions)` takes positions, so build them per layer per call — they are small.
- The mask is `(rows, write_offset + rows)` uint8, causal plus the sliding window
  when `geometry.sliding_window` is set.
- lm_head runs on the last row only (`rows=1`), then `final_logit_softcapping`
  on the host before argmax.
