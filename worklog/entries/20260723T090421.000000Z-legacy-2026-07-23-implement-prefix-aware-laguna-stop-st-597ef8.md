# 2026-07-23 — Implement prefix-aware Laguna stop streaming (S3)

## Summary

- Historical pre-Worklog2 journal entry, ported verbatim from `WORKLOG-LEGACY.md` (source lines 177565-177570).
- First appended to the journal in commit `71f2af03` (subject: perf: emit stop-safe Laguna tokens eagerly).

## Changes


- Replaced blanket `longest_stop_sequence - 1` withholding with a bounded set of every proper configured token prefix. After each nonterminal token, Laguna retains only the longest pending suffix that can still become a stop and emits every earlier token through the existing incremental UTF-8 decoder. Terminal stop suppression and blocking semantics are unchanged; no prompt, stop string, or token ID is special-cased.
- RED had all four latency/edge fixtures fail on blanket holdback: a nonmatching first token arrived only in the terminal `ABC` chunk, a failed prefix delayed `DA` through terminal `DAB`, overlap emitted `D`/`T14` separately instead of the earliest safe `DT14`, and split UTF-8 delayed `é` until terminal `éx`. GREEN covers those cases plus exact/shared/suffix-contained stops, request-order semantics, `min_tokens`, max-length flush, EOT, abandonment/cancellation, and blocking/stream equality; the complete Laguna generation file reports 30 passes.
- Added `scripts/laguna_stop_holdback_bench.py`, a host-only production-stream integration probe with deterministic delayed resident-token arrivals. Script smoke, `py_compile`, and diff checks pass; clean baseline/candidate measurement at the retained 61 ms/token interval is next.
