# Keep the Q5 four-wave rowtile parity reference (R0479)

## Summary

R0479's "keep the distinct reference" branch is satisfied: the four-wave WG128
owner `t16_gemv_rowtile_bf16_bf16_out` stays registered next to the single-wave
production owner `t16_gemv_rowtile_single_wave_bf16_bf16_out`, the capability
table still names the production owner, and a live consumer still needs the
four-wave body. Nothing was deleted, rebound, or migrated, so no device parity
comparison is owed.

The decisive consumer is not a test. On `hip_gfx1151` the Q5 rows-2-8 rowtile
name resolves to a backend wrapper that delegates to the gfx1100 four-wave body
for every shape outside `_GGUF_Q5_T16_ROWTILE_COL8_SHAPES`
(`{(6144,5120), (17408,5120), (5120,10240)}`), and gfx1151 declares no
single-wave replacement for `gguf_q5_k_t16_v1` (its
`GGUF_T16_NATIVE_ROWTILE_SINGLE_WAVE_BY_QUANT` read is `{}`). So the four-wave
body is live production arithmetic on gfx1151 for rows 2-4 of `(5120,17408)`,
`(12288,5120)`, `(10240,5120)`, `(1024,5120)` and `(5120,6144)`, and for rows
2-8 of `(5120,1024)`, whose row cap is 8. Deleting or rebinding it is an
arithmetic change on a shipped path, not a cleanup.
