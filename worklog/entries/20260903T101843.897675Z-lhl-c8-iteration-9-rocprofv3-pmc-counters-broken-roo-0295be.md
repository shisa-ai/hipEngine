# C8 iteration 9: rocprofv3 PMC counters broken; roofline fallback for Q4 grouped owners

## Summary

Attempted to close the C8-P2 "Inspect current ISA/resource counters" item using
rocprofv3 hardware counters (SQ_INSTS, SQ_INSTS_VALU, SQ_INSTS_VMEM,
SQ_BUSY_CYCLES, SQ_WAVES) on the grouped Q4 R6/R8 owners. PMC collection is
broken on this stack, so the item was resolved via a roofline fallback analysis
using already-measured complete-profile data.

## Changes

- Documented two rocprofv3 tooling issues (docs/KERNELS.md gotcha 8):
  1. PMC collection is broken: under `--pmc`/`-i` input (as `pmc:` lines or
     `{"jobs":[{"pmc":[...]}]}` JSON), the profiled app never launches (app
     time 0.000000 sec) and no output is produced; the process hangs until
     killed.
  2. `timeout` cannot kill a hung rocprofv3: its error signal handler traps
     SIGTERM and then blocks indefinitely "waiting for 1 children to exit".
     Durable fix for callers: `timeout -k 10 <seconds> rocprofv3 ...` or
     `pkill -9 -f rocprofv3`.
- docs/QWEN38-GFX1100-C8-K3-CAMPAIGN.md: marked the C8-P2 "Inspect current
  ISA/resource counters" item resolved with the roofline fallback verdict and
  a reopen condition (working PMC collection on this stack).
- docs/KERNELS.md: added gotcha 8 documenting both issues.

Per docs/ROOFLINE.md, a well-written bandwidth-bound kernel reaches 75-85% of
the 864 GB/s peak for large sequential streams; low-occupancy/small-working-set
kernels reach 40-60% (345-520 GB/s). The llama.cpp HIP reference
back-calculates to ~232-258 GB/s at model level. The measured ~90-164 GB/s is
therefore NOT at the bound: the "already bandwidth-bound, screening closed"
hypothesis is rejected by measurement. Q4 grouped owners have roughly 1.5-2x
headroom versus the reference effective rate.
