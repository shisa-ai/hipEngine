# Add target-distribution sampling to Flash-Next MTP

## Summary

The direct Flash-Next MTP provider supports target-distribution sampling and
processed greedy selection, with per-request RNG and selected/top logprobs.
This is a host-control implementation unit, not HTTP qualification or a speedup
claim. Resident/server admission still rejects or falls back for these controls;
task 17 remains open until that integration and live qualification are complete.

## Changes

- Reuse the AR sampler and byte-aware logprob construction for root, serial,
  scheduler K0, candidate and bonus rows. Capture target logits only as needed
  for processed verification; the existing raw-greedy selection is unchanged.
- Keep deterministic greedy proposals. For q=delta(c), drawing x from target p
  and accepting iff x=c gives acceptance mass p(c); a mismatch already follows
  p conditioned on x!=c, the required residual. Thus every committed token is
  distributed as p without a second acceptance draw or draft probability copy.
  Discard later speculative rows after mismatch/EOS without consuming RNG,
  processor history or logprobs. Feed the sampled correction/bonus, not its raw
  argmax, into the next cycle.
- Each iterator owns sampler state. Direct multi-prompt calls pass row indices
  into seed derivation and validate explicit row seeds. Progress and buffered
  provider streams carry only committed-token logprobs.
- Keep early guards for structured/thinking/stops/min-token/alternate-EOS and
  resident-session controls pending PS6. Retarget stale greedy-only admission
  tests to those genuinely unsupported controls.

  repetition/presence/frequency penalties and processed greedy selection.
