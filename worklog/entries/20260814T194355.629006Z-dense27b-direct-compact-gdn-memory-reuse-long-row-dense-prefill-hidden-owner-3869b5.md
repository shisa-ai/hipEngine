# Reuse long-row dense prefill hidden owner

## Summary

Retained model-policy-scoped prefill hidden-owner reuse for dense
Qwen3.6-27B `MOSTLY_Q4_K_M` at scratch rows >=4096. One physical 40-MiB BF16
hidden plane now serves both layer ping-pong roles. This lowers tracked 4K/8K
peaks by exactly 40 MiB without changing kernels, pointer ABIs, decode math, or
MTP math. Memory parity remains open.

## Changes

- Added `hidden_inplace_min_rows=4096` to the registered gfx1100 dense prefill
  scratch policy and centralized model-policy lookup.
- Allocated one shared `DeviceBuffer` for long-row `prefill_hidden_a/b`; kept
  two owners below 4096 rows.
- Deduplicated equal pointers in session teardown ownership and benchmark
  tracked-buffer accounting. The first exact production run exposed the
  duplicate-free bug after producing 129/129 exact IDs; the repaired run exited
  cleanly.
- Added focused short/long allocation coverage and published
  `benchmarks/results/2026-08-14-qwen36-27b-long-row-hidden-owner-reuse-retained.json`.
- Refreshed the canonical benchmark rollup, changelog, campaign status, and root
  README export.
