# XTX eager stage probe: NaN lm-head logits now reproduce on the W7900 too; context suspect

## Summary

Executed the authorized bounded single-prompt eager prefill/step/sampler probe on
the RX 7900 XTX. It localized the failure to the resident **prefill lm-head
logits** (NaN/Inf → `INT64_MAX` token id) rather than graph replay, but the same
failure then reproduced on the **W7900**, which had produced a valid 32.33 tok/s
C1 run earlier the same day. The XTX-specific fault is therefore **not isolated**:
the shared GPU context is now in a state where even the previously-working W7900
route returns NaN logits. Idle health (`rocm-smi`: 0% GPU, normal temps) does not
certify a healthy fault context. No GPU reset was performed.

## Findings

- `HIP_VISIBLE_DEVICES=1` / `ROCR_VISIBLE_DEVICES=1` correctly map logical 0 to
  the RX 7900 XTX (`0000:10:00.0`); `=0` maps to the W7900. Remapping is excluded.
- The true-AR harness CLI default is **`--use-gemv-decode` True**, so the failing
  optimized resident route runs with the `pack8_gemv_decode_*` family active. The
  kernel docstring says the family is "default off", so the CLI default and the
  kernel-level default disagree; this is a concrete lead for the working-vs-failing
  route comparison.
- Minimal probe, single prompt, auto-bulk, `HIP_VISIBLE_DEVICES=1`:
  `build` OK (device RX 7900 XTX), `prefill-auto` FAIL after ~300 ms
  (`FloatingPointError: GGUF resident lm-head logits contain NaN or Inf`),
  `eager-step` FAIL (`ValueError: token_id 9223372036854775807 outside [0, 248320)`),
  `teardown` OK. `first_bad_stage=prefill-auto`.
- Same probe, `HIP_VISIBLE_DEVICES=0` (W7900): **identical** failures.
- Full harness, one canonical prompt, W7900, eager (`--no-graph-replay-decode`,
  4 decode tokens): `session.step` raises `token_id 9223372036854775807`, i.e. the
  prefill sample was already invalid.
- Full harness, one canonical prompt, W7900, graph (`--graph-replay-decode`,
  128 decode tokens): first `graph.read_sample` raises
  `FloatingPointError: GGUF resident lm-head logits contain NaN or Inf`.
- Prior artifact `benchmarks/results/2026-09-16-w7900-tp2-matched-ar-c1-blocked.json`
  records the W7900 `tp1-d0` arm completing 18 prompts at 32.33 tok/s, so the
  W7900 route worked before this session.
- The probe's `use_bulk=False` ("serial") stage did **not** complete within 900 s
  on either device and was killed by `timeout`; it is a probe confound (likely
  cold-JIT or serial-prefill hang), not evidence about the XTX.
- After all runs: `rocm-smi` shows both cards idle at 0% GPU with normal
  temperatures; no reset was issued.

## Changes

- `scripts/tp2_xtx_tp1_eager_stage_probe.py` (new): one prompt, one session,
  flushed `STAGE <name> START/OK/FAIL` logs, `device_synchronize` after every
  stage, sentinel/unwritten-logit classification, optional `--with-graph` and
  `--with-serial` stages, `--os-exit` marked diagnostic-only.
- `tests/test_unit_scripts_tp2_xtx_tp1_eager_stage_probe.py` (new, 4 tests):
  NaN/Inf, all-zero/unwritten, sentinel fraction, argmax/range, missing logits.

## Validation

- `python3 -m pytest tests/test_unit_scripts_tp2_xtx_tp1_eager_stage_probe.py`
  — **4 passed**.
- Probe runs (bounded, single prompt): 4 GPU invocations (XTX auto, W7900 auto x2,
  W7900 full-harness eager, W7900 full-harness graph) plus the earlier
  `use_bulk=False` confound. No reset, no broad sweep.

## Blocker

The current shared GPU context returns NaN lm-head logits on **both** devices, so
the device-1-specific fault cannot be isolated until the context is restored to a
known-good state. A clean re-measurement requires an environment/context recovery
that this unit is not authorized to perform (no GPU reset). The exact XTX-specific
stage in the full harness is therefore **unresolved**; the confirmed stage in the
current context is prefill lm-head logits (NaN) → invalid token id, on both cards.
