# Enable owned complete-prompt DMS cache snapshots

## Summary

DMS no longer forces prefix caching off. The normal cache-on configuration retains one complete-prompt host snapshot and restores it into a new request's private compact store. This is state reuse, not generated-output memoization. The preceding setup repair is `842bb035b`.

## Changes

- `hipengine/kvcache/dms_prefix.py` captures live compact payloads, positions, eviction flags, and INT8 scales without retaining source leases or allocator state. Restore remaps to the destination's independently reserved extents. BF16 host-oracle floats are transported as their lossless BF16 bits. Cache arrays own their storage.
- `hipengine/runtime/dms_prefix.py` adds Conv/GDN and sampled-logit state. The generator retains one snapshot beyond private-session reclamation, clears it on configuration change/close, and restores it before sampling and ordinary decode. Cache diagnostics name the full-prompt scope and host snapshot bytes; live KV bytes remain separate.
- Complete token equality is required. A shorter pruned prompt cannot reproduce fresh longer-prompt prefill: exact-budget decisions depend on full prompt length, and prompt attention precedes compaction. An extended prompt therefore misses rather than silently changing arithmetic. No model allowlist is involved.
- MTP still runs and uses its prompt streaming provider. Its separate NextN prompt state is not snapshotted, so it reports `mtp_prompt_state_not_snapshotted` and executes full prefill. No new flag was introduced. `prefix_cache='off'` remains the ordinary rollback.
- Updated library/server option resolution, CLI help, and `docs/API.md`. Added a reproducible public correctness harness, `scripts/dms_prefix_smoke.py`.
