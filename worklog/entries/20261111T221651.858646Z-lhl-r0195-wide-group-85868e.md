# R0195 wider-group device coverage (8-request capacity, aligned_row_multiple)

## Summary

Extended `tests/test_live_gguf_r0195_physical_target.py` with a wider-group case and
confirmed it on gfx1100 (W7900). The physical group width is bounded by
`physical_max_requests = max(width <= min(owner.capacity, configured_max))` over the
backend width/depth cells (gfx1100 widths {1,2,8}); with `max_active_requests=4` the
capacity capped realized groups at width 2. Raising to 8 prompts +
`max_active_requests=8` + C3 (the `[8,3]` cell) lifts `owner_capacity`,
`physical_max_requests` and `resolved_max_requests` to 8 and realizes a >2-request
verify group. All 3 gate tests pass.

## Changes

- `tests/test_live_gguf_r0195_physical_target.py`: worker/driver now take a
  `num_prompts` argument (`R0195_WORKER=budget:profile:num_prompts`); `_PROMPTS`
  extended to 8; new `test_wider_group_realizes_eight_request_capacity`.
- `docs/REFACTOR.md` R0195: records the wider-group coverage; remaining list narrowed.

## Validation

`tests/test_live_gguf_r0195_physical_target.py` 3 passed in 285.16s on the W7900.
Wider-group case (72s): production C3, 8 prompts -> last_partition owner_capacity=8,
physical_max_requests=8, resolved_max_requests=8; last_target_shape request_count=3
(>=2), reason=aligned_row_multiple, selected_rows=6=logical_rows (6 is a rows6
multiple, so no padding); 8 outputs of 24 tokens each. This adds the
aligned_row_multiple reason to the gate alongside padded_to_row_multiple and
no_padding_policy.
