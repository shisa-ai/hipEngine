# the context refusal is reproduced end to end on the real artifact and costs 0.24s not a load

## Summary

The last unmeasured step is done, on the real artifact rather than a stub.

```
/models/gguf/gemma-4-26B-A4B-it-GGUF/gemma-4-26B-A4B-it-UD-Q4_K_XL.gguf
```

| `context_length` | outcome | wall time |
|---|---|---|
| 32,768 | **REFUSED** | **0.244 s** |
| 8,192 | runner built | 1.094 s |

The refusal, verbatim:

```
Gemma 4 gfx1100 attention requires 133120 bytes of shared memory for head_dim=256,
keys=32768; this kernel supports at most 65536 bytes and needs tiled attention for
this context
```

## Two things this establishes

**The limit is real and user-visible.** Not a code reading any more: a real artifact,
a real context length, a real refusal naming the geometry, the byte count, and the
requirement it misses. `133120 = (256 + 32768 + 256) * 4`, which is the LDS formula
from `20260928T065753`.

**The placement fix works, and the timing shows it.** The refusal at 32,768 costs
**0.244 s**, while a *successful* build at 8,192 costs **1.094 s**. A refusal that
still happened after the load would have cost at least as much as a successful one.
It costs 4.5x less, which is the direct evidence that the check from `20260928T071438`
runs before the load rather than after it.

That comparison is the reason to run this rather than trust the stub test. The stub
proves the ordering; only the real artifact shows the ordering is worth 0.85 s.

## Caveat on the 8,192 row

`weight_index=None` and `model_plugin=None` were passed, so the 1.094 s build is with
a degenerate weight index and is not a fair measure of a full production load. It is
still an upper bound on what the refusal avoids, and it is enough to make the point:
the refusal is cheaper than the thing it precedes.
