# Recover SPECDEC2 postcommit readback failures

## Summary

Repair a real P8 failure-safety hole at the sole bounded device-cycle readback.
The selected target state is committed before accept-summary D2H. An injected
readback exception therefore left host cursors apparently canonical while
Conv/GDN/KV state had advanced; the generic precommit recovery mislabeled the
cycle safe and AR fallback emitted wrong IDs. Rebuild target state from the
scheduler-owned canonical token history before allowing fault-only AR recovery.

## Changes

- Wrap selected target commit/readback failures in an explicit postcommit error
  that cannot pass the cursor-only precommit check.
- On that error only, flush/reset affected target sessions and packed ownership,
  prefill exact `prompt + generated[:-1]`, and verify both the pending canonical
  token and target cursor before returning to AR.
- Preserve provider checkpoint rollback/drop; no steady-cycle snapshot, copy,
  allocation, branch, or benchmark work is added.
- Retarget the S6 failure injector from eliminated candidate materialization to
  the current bounded accept readback, retain concrete error telemetry, and
  distinguish precommit versus postcommit-rebuild contracts.
