# Q5_1T16: stage the expert down prefill's weight fragments through LDS

## Summary

The mid-band census (2026-10-07) put `q5_1_selected_grouped_wmma_prefill` at
12-15 percent of every 8192-32768 prefill step, the second-largest expert GEMM.
An interleaved variant screen at the exact gemma4 down geometry (4096 compact
rows over 128 experts, in 704, out 2816) showed the raw-block grouped WMMA
kernel is 10-20x every alternative already in the tree (rowbatch8 42.3 ms,
pair2_fold_pair 18.4 ms, against WMMA's 2.12 ms per call), so the win had to
come from the kernel itself. PMC counters on the promoted build said the same
thing the Q4_K leaf's history did: SQ_WAIT_INST_ANY-dominated (15.8 per SQ
cycle), ALUStalledByLDS 0 -- an instruction-latency profile, with the inner
loop decoding every weight value from scalar global byte loads.

The fix mirrors the Q4_K T16 recipe: a bit-lossless tile repack plus an LDS
window. `repack_gguf_q5_1_tile16` builds `[E, out_tiles16, blocks_per_row, 576]`
tiles -- d/m fp16 headers per column, and one value byte per (column, K value)
holding the exact integer the raw decoder derives (`low | (high << 4)`), laid
out so a column's 32 values are one contiguous 32-byte run. The new
`q5_1_t16_selected_grouped_prefill` kernel keeps the raw kernel's geometry,
fragment convention, arithmetic, accumulation order, and store loop; the only
change is that each K block's two 512-byte value windows are copied to LDS by
one 128-bit load/store pair per lane and each fragment decode reads four uint32
words from shared memory instead of sixteen scalar global byte loads.

**Measured, interleaved in one process at the in-situ geometry: leaf 2.817 ->
1.714 ms, 1.64x, bit-identical output.** End-to-end paired A/B at 8192 (fresh
process per arm, two rounds, arm order reversed between rounds): **prefill
1163.9/1166.0 -> 1244.3/1245.3 tok/s, 1.069x/1.068x**, both arms status ok with
public path parity True both rounds. At 512 the census's down-wrapper line
(2.55 ms/call, 18.8 percent) disappears into the expert block and prefill moves
1319 -> 1427 tok/s. Raw artifacts under `/tmp/multiloop-beat-llamacpp/`
(`q51_t16_interleaved.json`, `q51t16-e2e-{on,off}-{r1,r2}.json`,
`q51_variants_interleaved.json`).

The raw-block kernel also gained a vectorized activation load (two 128-bit
loads per row fragment instead of sixteen scalar 16-bit gathers) in the same
edit; it measured +1 percent at the leaf and is bit-identical, and it stays --
it is part of the same scheduling cleanup, measured, not promoted on faith.

## Validation

- Unit: 29 passed across the t16 repack tests.
- GPU leaf: bit-identical vs the raw-block kernel at two geometries.
- Interleaved leaf A/B: 1.6435x (old build from HEAD via a worktree cache, new
  build in the same process, 40 alternating iterations).
- E2E: two paired rounds at 8192, both arms `status: ok`, `public_path_parity:
  True`; 1.0691x / 1.0680x prefill, decode unchanged within noise.
- No arithmetic change on any selected path: the tile value byte is the same
  integer the raw decoder computes, scales/mins are the same fp16 bytes, and
  the kernel's per-value expression, WMMA sequence, and accumulation order are
  the raw kernel's. The `compensated` contract is untouched (the t16 route
  declines it).
