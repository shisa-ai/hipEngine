# Retain split GDN conv output lifetime reuse

## Summary

Retained a kernel-neutral dense Qwen3.6-27B memory reduction: split GDN fully consumes `conv_out` during prepare, so its lifetime ends at exclusive stage 4 and the liveness allocator may reuse those pages for `recurrent_out` at stage [4,5). The 4,096-row arena contracts from 467.5625 to 401.0625 MiB (-66.5 MiB) without changing arithmetic, launches, or the raw-pointer ABI. Memory parity remains open: current whole-device gaps to clean llama.cpp Vulkan are 0.341/0.483/0.932/0.933 GiB at 512/1K/4K/8K.

## Changes

- Shortened only split-mode `conv_out` from `[linear,2,5)` to `[linear,2,4)` in `hipengine/runtime/qwen35_gguf_runner.py`; explicit fused GDN retains the conservative stage-5 lifetime.
- Added a deterministic liveness test proving `conv_out`/`recurrent_out` physical overlap across disjoint intervals and the exact 401.0625-MiB long-row arena.
- Removed the rejected direct compact-peer output kernel, wrapper, registry key, source test, and catalog entry added in base commit `214b4b949`; repository greps find no direct/hybrid candidate surface.
- Published `benchmarks/results/2026-08-14-qwen36-27b-split-gdn-conv-lifetime-retained.json` and refreshed the benchmark/campaign rollups.
- Excluded an early 23.91-GiB direct-candidate memory sample after proving another XTX process started after its clean baseline and held about 8.23 GiB. All accepted rows were rerun strictly serial from identical 0.060455-GiB baselines.
