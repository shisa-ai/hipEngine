# Partial-selection top-p: -55 to -88% on real logits, ulp-level drift only

## Summary

Implements the lead-approved sampler tradeoff: bit-exact cross-version seeded
output is **not** a production-correctness requirement
(`EXECUTION-PROFILES.md`: production = same request/seed/resolved
variant/schedule deterministic + bounded implementation drift; cross-version
bit stability is a `strict`-oracle property, not the promotion bar). Shaving
the top-p host cost is therefore a valid default.

`processed_support` gains a partial-selection fast path for the common
top-p-only case (`top_k=0`, `0<top_p<1`, no constraint): adaptive top-K
`argpartition` selects a prefix-superset of the retained support, sorted
exactly once (probability descending, lower-ID on ties), instead of sorting
the full 248K vocabulary. Softmax normalization sums exp in canonical
token-ID order rather than the legacy score-sorted order — per-token
probabilities drift at ulp level only. A mass probe bails out to the legacy
full-sort path when the support is a large fraction of the vocabulary (flat
distributions), where one sort beats repeated partitioning. All other paths
(top_p=1, top_k>0, constrained) keep the legacy arithmetic byte-for-byte.

**Real-logit evidence (the decisive measurement).** Captured three actual
Qwen3.8-27B-UD-Q4_K_M prompt-final logit rows (vocab 248,320; std ~1.8-2.1,
max 12-21 — peaked, support 1-5,364 tokens) via a resident-session prefill,
then A/B'd `processed_support` at T0.7/p0.9, T1.0/p0.95, T0.7/p0.99:
**6.0-6.5 ms -> 0.73-2.83 ms (-54.7% to -88.0%), retained IDs byte-identical
in all 9 configurations.** Real serving logits are peaked, so the fast path
is the common case.

Synthetic envelope: on peaked normals (std 3-5) -75 to -77%; on a
pathologically flat std-1 row (top-p support = 44% of vocab) the mass probe
bails to legacy and pays ~+17% probe overhead. That flat shape does not occur
in the captured real logits; it is documented as the tradeoff boundary, not
hidden. The `sampler_host_cost_probe.py` synthetic std-1 case therefore reads
slightly slower — the real-logit A/B above is the serving-relevant evidence.

## Changes

- `hipengine/generation/sampling.py`: `_partial_top_p_support` (adaptive
  top-K + canonical-ID softmax sum + probability-tie ordering + flat-mass
  bailout returning None) and the `processed_support` branch that uses it and
  falls through to the legacy path on bailout. Ships on by default; no flag.
- `tests/test_unit_sampling_partial_top_p.py`: 38 tests — distribution parity
  vs the embedded legacy implementation across vocab/std/top_p/min_p grids,
  edge shapes (single/two/uniform/ties/tiny-top_p/near-one/masked-tail),
  flat-bailout byte-identity, legacy-path byte-identity (top_p=1/top_k/
  constraint), seeded determinism, and a 20,000-draw empirical frequency check.

## Validation

- New file 38/38; full `tests/test_unit_sampling*.py` suite green (exit 0).
- 300-case randomized sweep (vocab 2K-201K, std 2-8, top_p 0.5-0.99):
  **0 support/order mismatches, 0 top-1 flips, max relative probability drift
  6.35e-16** (ulp). Probability-tie ordering matches the legacy RNG map
  (ordering by probability, not logit, so float32 shift-rounding ties resolve
  to lower-ID exactly as the legacy filter does).
- Real-logit A/B: 9/9 configurations byte-identical retained IDs, -54.7% to
  -88.0% wall. Logits captured to `/tmp/real_logits_qwen38.npy` (not
  committed; reproducible via resident-session prefill of the recorded
  prompts).
- Same-build determinism: seeded `select_token` repeats identical (test);
  cross-version seeded draws can differ only within ulp of a cumulative
  boundary — the accepted tradeoff.
