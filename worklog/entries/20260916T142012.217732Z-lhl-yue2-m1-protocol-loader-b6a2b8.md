# Complete YuE2 M1 protocol/loader/operator contracts and the M0 fixture validator

## Summary

M1 is complete: the torch-free YuE2 protocol, tokenizer, safetensors loader, model
plugin, and CPU operator contracts exist and are gated by 108 unit tests that run
without torch or a GPU. The M0 oracle gained a fail-closed fixture validator, a
frozen integrity index, and a committed oracle-environment record.

Checkpoint-level findings that change downstream work: the released VAE decoder
applies its stride list in reverse layer order (layer 1 is the 6x stage), the Q/K
head norms are trained rather than identity, BF16 bit-pattern storage keeps the
host footprint exactly at the checkpoint payload, and the oracle fixtures were
generated on **gfx1151** (Ryzen AI MAX+ PRO 395 / Radeon 8060S), not gfx1100.

## Changes

- Add `hipengine/tokenization/yue2.py` (141 LoC): Qwen2 BPE over the released
  `qwen.tiktoken`, NFC normalization, ordinary-only encoding, 208 specials with
  the pinned ABC ids (`<abc>` 151847, `</abc>` 151848) and `<extra_N>` layout.

  owned BF16 bit-pattern host weights, FP32 VAE decoder with folded weight norm,

## Validation

- `python3 -m pytest tests/test_unit_yue2_protocol.py tests/test_unit_yue2_tokenizer.py
  tests/test_unit_yue2_operators.py tests/test_unit_yue2_loader.py
  tests/test_unit_yue2_fixtures.py` -> 108 passed in 10.24 s. No torch import
  (`tests/test_unit_yue2_fixtures.py::test_oracle_tooling_imports_no_torch`), no GPU
  allocation, no HIP runtime.
- Fixture identity, byte size, dtype/ndim schema, and cross-file relations
  (length formulas, top-8 ordering vs argmax, id ranges, latent/velocity norms,
  weight-norm fold, manifest consistency) are enforced by
  `python3 scripts/yue2_oracle.py validate`; `--self-test` rejects all eight
  mutation classes (missing file, corrupted payload, unlisted extra file, dropped
  required key, wrong length relation, tampered id, manifest drift, swapped
  prefill logits).
- Loader contract: `weights.bytes == 7261368448` equals the checkpoint payload
  exactly (no FP32 widening), 628/217 mapped tensors, shard identity
  `1d55c42c...` matches the pinned model LFS hash, VAE revision
  `9a94e1d0ea9f8087e98f77fa88df4a4068104d2a` matches the pin.
- Oracle environment record (`tests/fixtures/yue2/oracle_env.json`): python
  3.13.13, torch 2.13.0+rocm10.0.0 (HIP 7.15.26333), numpy 2.4.4, tiktoken 0.14.0,
  device "AMD Radeon 8060S Graphics", `gcn_arch` gfx1151, host `zbook`, upstream
  source hashes for 8 files, shootout wheel sha256 `8801e2c0...` (matches the pin
  in `docs/MODEL-YUE2.md`). The oracle runs the pinned upstream *source* via
  `PYTHONPATH`; the CUDA-locked 0.1.5 wheel is not installed.
- Fixture provenance repairs: the `ar_replay` manifest had recorded the hash of the
  local full-precision artifact, not the committed compact fixture; the VAE
  manifest had recorded the 64-frame decode statistics while the committed fixture
  holds the 3-frame decode. Both now record the committed artifact, and the
  validator fails if those fields are absent.
- Weight-norm fold, stride-order, and length formulas were checked against the
  released checkpoint shapes and the reference formulas: natural VAE length
  `1920*F - 64` holds for F in {1, 2, 3, 16, 64, 1024}; the decoder's per-layer
  upsample strides are [6, 5, 4, 4, 2, 2] with kernels [12, 10, 8, 8, 4, 4].
- RoPE table gate: the reference builds cos/sin from an FP32 angle, so a few-ulp
  table difference is inherent at long positions and high frequencies (F32 angle
  ulp is ~1e-3 rad at position 24576 for the top frequency). The gate is therefore
  <=3 ulp of the F32 angle plus exact agreement for |angle| < 1, and `rotate_half`
  is bit-exact given the reference table (4/131072 BF16 values flip with our own
  table).
