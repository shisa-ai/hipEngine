# GDN port spec from llama layout analysis

## Summary

Analyzed llama's gated_delta_net_cuda (ggml-cuda/gated_delta_net.cu,
lineage ggml-org/llama.cpp@17252c769) against our
qwen4_exp_gdn_prefill_f32_kernel to explain the 8.7x prefill gap (86 ms vs
751 ms at pp508; 2.39 vs 26.8 ms per layer... per launch) and the 7.9x
decode gap. llama's kernel is a plain sequential per-token recurrence — no
chunked parallel scan — but with a parallelization layout that keeps ~4096
warps in flight: grid (H heads, n_seqs, S_v/32-cols), 128-thread blocks of
4 warps, each warp owning one state column with the S_v rows sharded across
32 lanes (s_shard[4] in registers), all reductions via warp shuffles, zero
__syncthreads in the token loop, inputs pre-normalized upstream.

Our kernel assigns ONE BLOCK PER V_HEAD (32 blocks total on 40 CUs) with
threadIdx covering head_v_dim columns and a __syncthreads reduction pair
per token — massively underutilized and sync-bound.
