# gfx1151 35B-A3B: gufo-protocol prefill is flat in depth at ~1455 tok/s, so the 2.13x gap is kernel efficiency

## Summary

Measures gufo's benchmark protocol directly instead of fitting it, and corrects
two readings from the immediately preceding entry
(`20261003T081652.008493Z-lhl-gfx1151-35b-a3b-gufo-reconciliation-attribution-4b8cb5`).

**Protocol, as implemented.** At each depth `d`: build a cached prefix of `d`
tokens and prefill it (untimed), then time a new 2048-token turn's prefill and
the following 128 decode tokens. That is gufo's shape — a cached conversation
prefix plus a new ~2048-token user turn plus 128 output tokens.

**Result, shipping AR route, one resident session, warm iteration then 2 measured
repetitions per depth:**

| depth | pp tok/s (new turn) | tg tok/s | pp samples |
| ---: | ---: | ---: | --- |
| 0 | **1457.7** | 55.46 | 1458.0, 1457.4 |
| 4096 | **1456.1** | 54.46 | 1455.7, 1456.5 |
| 16384 | **1451.5** | 48.85 | 1451.9, 1451.1 |
| gufo | **3095** | 68.43 | - |

**Correction 1: the prefill rate is flat in depth, so the gap is not a
depth-scaling gap.** Marginal pp falls 1457.7 -> 1451.5 tok/s from depth 0 to
depth 16384, a **0.4%** decline. The steep decline in our published ladder
(1369 / 1430 / 1145 / 936 tok/s at 512 / 4K / 32K / 64K) is the average over a
0->D ramp, not the marginal rate, and X-8's "the prefill gap widens with depth"
reading inherits that artifact. Against gufo the ratio is **2.12x at depth 0,
2.13x at depth 4096, 2.13x at depth 16384** — constant. The preceding entry's
"~1380 tok/s marginal at depth 4096" fit was low by ~5%; the measured value is
1456.1.

**Correction 2: the headline prefill gap stands at 2.13x, not 2.16x, and it is
now measured rather than fitted.** The direction of the earlier correction is
unchanged — comparing on gufo's basis does not narrow the gap — but the number
is 2.13x and the reason it does not narrow is that our marginal rate is flat
while the published column is a ramp average.

**The decode column under this protocol is 55.46 / 54.46 / 48.85 tok/s against
gufo's 68.43**, i.e. 1.23x / 1.26x / 1.40x. The decode gap widens with depth
where the prefill gap does not, which is consistent with the preceding entry's
stage budget: the depth-sensitive stages are the attention and KV ones, not the
weight streams that dominate at short context.

## Validation

Host: same physical host as the published gfx1151 lane
(`/etc/machine-id` `55ea6c509d0b49eea8de7094a1023668`), `tuned` profile
`accelerator-performance`, `scaling_governor=performance`. Model
`/models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf`. Route: shipping AR
(`use_wmma_prefill=True`, `use_gemv_decode=True`).

One resident `Qwen35GGUFResidentSession`, `reset()` between depths, one warm
iteration per depth discarded, two measured repetitions per depth. The two
measured pp samples per depth span 0.03-0.06% and the tg samples span 0.5-1.8%,
so the flat prefill curve is well outside the in-session spread. The prefix is
prefilled with the same repeated token id as the turn, so the prefix is a valid
cache state but not a semantically natural conversation; that affects nothing
about the timing basis.
