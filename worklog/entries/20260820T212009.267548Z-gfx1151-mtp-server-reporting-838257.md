# Expose effective MTP state in server responses (vLLM-compatible)

## Summary

QoL request from the handoff: the server never reported its effective MTP state
in request responses, metrics, or startup logs, so an operator could not tell
whether a request actually served through speculative MTP or what the draft
acceptance was. Added vLLM-compatible per-request MTP reporting plus
Prometheus metrics and a startup log line, matching the format vLLM/sglang
expose for speculative decoding.

## Changes

- `hipengine/server/api.py`
  - `_usage` now emits vLLM-compatible
    `usage.completion_tokens_details.accepted_prediction_tokens` /
    `rejected_prediction_tokens` whenever backend `GenerationTelemetry.timing`
    carries `mtp_accepted_draft_tokens` / `mtp_generated_draft_tokens`
    (helper `_mtp_accepted_rejected_counts`). Applies to non-streaming and to
    the final SSE `usage` / `hipengine.usage` payloads. Non-MTP requests omit
    both fields.
  - Non-streaming completion and chat responses now include a top-level
    `hipengine.speculative_mtp` extension (helper `_mtp_response_summary`):
    `effective_route` (from `generation_shape.route`), `used`,
    `draft_tokens`, `accepted_draft_tokens`, `rejected_draft_tokens`,
    `acceptance_rate`, `draft_cycles`.
  - `_ServerMetrics` gains `mtp_requests_total`,
    `mtp_draft_tokens_accepted_total`, `mtp_draft_tokens_rejected_total`
    (accumulated in `record_success` from the usage fields).
  - Prometheus `/metrics` exports `hipengine_mtp_requests_total`,
    `hipengine_mtp_draft_tokens_accepted_total`,
    `hipengine_mtp_draft_tokens_rejected_total`, a cumulative
    `hipengine_mtp_draft_acceptance_rate` gauge, and a static
    `hipengine_mtp_serving` gauge (effective config for the loaded engine).
  - Startup logs one `EFFECTIVE_MTP: serving=... engine_supported=...
    default_enabled=... policy=... thinking=...` line in both eager and lazy
    load paths (`_log_effective_mtp_config`).
- `tests/test_server_api.py`
  - Fake MTP engine now emits MTP timing; extended the explicit-MTP route test
    to assert the new `usage.completion_tokens_details` fields and
    `hipengine.speculative_mtp` summary; added
    `test_metrics_reports_mtp_serving_and_draft_acceptance`.
- `docs/API.md`: new "Speculative MTP usage and effective-state reporting"
  section plus `/metrics` row update.
