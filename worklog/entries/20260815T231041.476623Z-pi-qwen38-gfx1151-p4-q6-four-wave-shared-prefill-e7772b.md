# Screen gfx1151 four-wave shared planar Q6 prefill

## Summary

Retain one materially distinct, exact P4 prefill mechanism for gfx1151. A
128-thread/four-wave workgroup decodes each planar-Q6 48 x 256 slab once into
24 KiB LDS and preserves four independent copies of the retained per-wave
48-column x 64-row K16 WMMA sequence. Scope it only to rows>=512
K17408/N5120 FFN-down; rows<512, narrow V, root, shape misses, and peer backends
retain the one-wave primitive.

The actual wide leaf improves **1.502x/1.421x/1.474x** at 512/1K/4K with
**45/45 paired wins** and BF16-bit identity. Complete same-source prefill moves
**344.886/339.548/334.718 -> 363.521/354.231/349.204 tok/s
(+5.403%/+4.325%/+4.328%)** with identical IDs, tracked peaks, and teardown.
The 512 row now beats clean llama HIP; 1K HIP and 4K HIP/Vulkan remain open.

## Changes

- Added `q6_k_t16_qmicro_planar_wmma_prefill_shared4_bf16_kernel` and a raw-
  pointer C/Python launch wrapper. Four waves retain the prior accumulator,
  K16 load, WMMA, and BF16 store order while cooperatively decoding one 24-KiB
  weight slab instead of four independent copies.
- Registered a gfx1151 backend override for the existing
  `linear/gguf_q6_k_t16_qmicro_planar_v1/t16_wmma_prefill_bf16_bf16_out` key.
  The backend capability admits only `(K,N)=(17,408,5,120)` at rows>=512 and
  otherwise calls the already-registered one-wave fallback.
- Added HIP tests for rows17 and the 256-row boundary at rows257, direct
  CPU-reference quality at rows17, exact registry resolution, qualified-shape
  dispatch, and short/narrow/root fallback behavior.
- No resident layout, payload, workspace, runtime ABI, decode owner, or peer
  backend changes. The complete rows retain the exact
  **16.753/17.178/19.529 GiB** tracked peaks and return zero bytes after close.
