# pin the server's sampled MTP route choice with a test

## Summary

`_speculative_mtp_route_for_request` gained production semantics in 80f895e58
with no test: a request carrying sampling blockers now keeps typed speculative
intent when the engine's evidence admits the sampled mode, where it previously
went to K0 unconditionally. This entry pins that choice, including the shipped
case (no row lists the mode, so nothing changes for a temperature request) and
the case where the sampled route itself refuses a blocker.

## Changes

- `tests/test_unit_speculative_sampling_modes.py`: adds
  `test_server_route_keeps_a_sampled_request_only_with_a_sampled_row`, covering
  five route decisions through the real `_speculative_mtp_route_for_request`
  with a fake engine that advertises exactly the modes its rows declare:
  sampled row + temperature request -> batch route; greedy-only row +
  temperature request -> K0; sampled row + an unservable blocker (logprobs) ->
  K0; automatic mode + sampled row -> automatic route; greedy request with and
  without the sampled row -> automatic route. Adds `_server_config`,
  `_serving_engine`, and `_serving_request` helpers for that call.

## Validation

- `timeout 600 uv run pytest tests/test_unit_speculative_sampling_modes.py -q`:
  31 passed.
- The test is a genuine pin, not a restatement: reverting the 80f895e58 hunk in
  `api.py` (`if blockers: return K0` unconditionally) fails the first assertion,
  because that is exactly the branch the change altered.
