# Env docs: canonical gfx1151 ROCm 10 prefix is envs/therock (Python 3.12), not the Miniforge base prefix

## Summary

`docs/ENVS.md` and `docs/THEROCK.md` described the gfx1151 ROCm 10 stack as
living in the Miniforge **base** prefix (`/home/lhl/miniforge3`, Python 3.13).
That prefix has no ROCm packages at all: `/home/lhl/miniforge3/bin/python -m
rocm_sdk version` fails with `No module named rocm_sdk`, and its `pip list` has
no `rocm*` or `torch`. The live stack is the dedicated environment
`/home/lhl/miniforge3/envs/therock` (a symlink to
`envs/therock10-staging-20260828`), Python **3.12.13**, ROCm **10.0.0**.

Every copy-pasteable wrapper in the gfx1151 sections pointed at the base prefix
and at a `lib/python3.13/site-packages` path, so none of them would have worked
as written. The rollback section pointed at
`~/.local/share/therock-backups/miniforge-rocm715-20260727`, which does not exist
on this host.

## Changes

- `docs/ENVS.md`: TheRock clean-process wrapper now uses
  `ENV_PREFIX=/home/lhl/miniforge3/envs/therock` and
  `SITE=$ENV_PREFIX/lib/python3.12/site-packages`; added a note that the base
  interpreter has no ROCm packages.
- `docs/THEROCK.md`: gfx1151 lane row, "Current gfx1151 Stack", fresh-install,
  in-place-upgrade, shell-setup, clean-process-wrapper, verify, and rollback
  blocks all repointed at `envs/therock` + Python 3.12.
- Documented the `envs/therock` symlink convention: create a dated prefix, then
  repoint the stable symlink. Recorded that the `staging` label in
  `therock10-staging-20260828` is historical and the installed packages are the
  production ROCm 10.0.0 release, not a nightly.
- Package table: Python `3.13.13` -> `3.12.13`. Fresh install: `python=3.13` ->
  `python=3.12`.
- Rollback target corrected to the environment that actually exists,
  `/home/lhl/miniforge3/envs/therock-rocm715-backup-20260828` (Python 3.12.13,
  `rocm`/`rocm-sdk-*` `7.15.0a20260711`); recorded that the `.local/share` and
  `.local/state` paths from the 2026-08-30 upgrade are no longer present.
- Left the W7900 / gfx1100 (`/home/lhl/mambaforge/envs/therock`, ROCm
  `7.13.0a20260423`) content untouched: that is a separate `epyc` host, not this
  machine.

changed gfx1151 sections was then run against the live environment on this host
(Framework Desktop, Radeon 8060S, 40 CU, `gfx1151`, single GPU):

- `python -m rocm_sdk targets` -> includes `gfx1151`

  `.../envs/therock/lib/python3.12/site-packages/_rocm_sdk_devel`

  `libamdhip64.so` loaded via `ctypes`

  clean, `rocm_sdk path --root` resolves
