# Generalize SPECDEC2 failure gate for exact C1

## Summary

Generalize the retained SPECDEC2 S6 failure harness from its hardcoded Q4_K_S
physical-C2/five-token fixture to dynamic C1/C2, max-sequence, and horizon
oracles, then qualify the exact Qwen3.8 Q4_K_M strict C1/natural25 proposal,
target, and readback seams. This is a test-harness unit only; no runtime/default
change and no performance claim.

## Changes

- Add `--concurrency {1,2}`, `--max-sequence-length`, and `--max-tokens` while
  preserving old defaults.
- Derive fault and following-health expected IDs from same-session true AR
  instead of hardcoding five Q4_K_S token IDs.
- Select the actual C1 graph owners:
  `launch_device_proposal`, `verify_target_from_device_proposal`, and the
  transactional verifier `prepare` return seam.
- Make readback recovery expectations concurrency-aware: C1 is still inside the
  transactional verifier journal and restores canonically as precommit;
  physical C>1 retains its packed postcommit target-rebuild contract.
