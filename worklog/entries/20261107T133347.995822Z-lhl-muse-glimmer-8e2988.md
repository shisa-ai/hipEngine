# Muse Glimmer bench timing boundary corrected

## Summary

The AR bench claimed "sampling excluded" but timed np.argmax inside the decode
loop. Fixed to report two explicitly named measurements: decode_model_step_tok_s
(sum of synchronized decode_step walls, the llama-bench tg boundary) and
decode_tok_s (user-facing wall incl greedy argmax). Measured impact of the
argmax is negligible, so the decode gap vs llama.cpp is genuine, not a timing
artifact.

## Changes

- scripts/muse_glimmer_ar_bench.py: per-step decode_step timing accumulated
  separately; row gains decode_model_step_tok_s + samples/median; header and
  timing_boundary metadata corrected to name both boundaries.

## Validation

- 512/128, 2 reps: prefill 337.985 tok/s; decode user-facing 11.200 tok/s;
  model-step 11.204 tok/s. argmax overhead ~0.04% (negligible). The ~6.5%
  host/gap share lives inside decode_step (logits D2H copy + scale/softcap),
  not in the argmax.
