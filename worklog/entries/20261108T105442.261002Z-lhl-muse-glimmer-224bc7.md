# Muse Glimmer resident prefix reuse and context snapshots

## Summary

Muse Glimmer used to reset its single resident KV cache at the start of every
request, so each agent turn repaid the whole prefill (~10 min at 126K, ~29 min
at 260K). The session now records the token id behind every cached position.
A new prompt resumes after the cached common prefix, rounded down to a
1,024-token prefill-chunk boundary, and prefills only the rest. This works for
AR and DFlash, through `LLM.generate()` and `hipengine serve`, with
`--prefix-cache off` as the rollback. `save_context`/`load_context` write and
restore the same state (target KV, drafter KV and token ids) on disk, so a
long-context debug or profile run can skip its prefill.

Why chunk-aligned. A probe at 2,283 tokens compared a resumed prefill with a
fresh one. Resuming at 1024 or 2048 gave bit-identical logits. Resuming at
1088, 1152, 1280, 1500, 1536, 1792, 2000 or 2275 kept the argmax but changed
logits by up to 1.04 (cosine 0.99992–0.99998): the prefill arithmetic depends
on the chunk's composition. Rounding down costs at most 1,023 recomputed tokens
(a few seconds even at 128K). In exchange, a cached or snapshot-loaded run is
bit-identical to a fresh one whenever the reused rows were themselves
prefilled. Rows written during decode are reused too. They carry decode
arithmetic, as in any engine that reuses generated tokens.

DFlash also needs the drafter's KV to hold the same prefix. The provider keeps
its own copy of the token ids behind the drafter rows, and reuse is the
smaller of the two common prefixes, so an AR request in between cannot leave
the drafter stale.

## Changes

- `hipengine/runtime/muse_glimmer.py`: token history; `reusable_prefix`,
  `align_resume` and `prefill(start=)`/`prefill_with_taps(start=)` with
  absolute chunk alignment; `save_kv`/`load_kv`. Image rows end the reusable
  prefix.
- `hipengine/runtime/muse_glimmer_context.py`: snapshot format
  (`context.json`, `tokens.npy`, `target.kv`, `drafter.kv`).
- `hipengine/runtime/muse_glimmer_dflash.py`: drafter `save_kv`/`load_kv`.
- `hipengine/generation/muse_glimmer_gguf.py`: `configure_engine_loop`
  (`prefix_cache` mode), `prefix_reuse_start`, `save_context`/`load_context`,
  and per-request `prefix_cache` telemetry, which feeds
  `usage.prompt_tokens_details.cached_tokens`.
- `hipengine/generation/muse_glimmer_dflash.py`: drafter-aware reuse and
  snapshot hooks.
- `hipengine/generation/engine_loop.py`: `_SubmitPollTextRunner` forwards
  `configure_engine_loop` to generators that bind it, so `--prefix-cache off`
  reaches Muse Glimmer.
- `scripts/muse_glimmer_context_profile.py --context-dir`.
- `docs/API.md` "Muse Glimmer prefix reuse"; `docs/campaigns/MUSE-GLIMMER.md`
  §11.1 (review of the §11 plan, 260K results, revised order).

## Validation

- `tests/test_unit_muse_glimmer_prefix_reuse.py` (7, CPU) and
  `tests/test_unit_engine_loop_prefix_cache_config.py` pass.
- `tests/test_live_muse_glimmer_prefix_cache.py` (4, gfx1151) passes: resumed
  prefill bit-identical; a second turn reuses the cached rows and matches a
  fresh prefill's greedy IDs; DFlash on a reused prefix equals AR; a snapshot
  round-trips for both target and drafter.
- Regression, all passing: `test_live_muse_glimmer_runner`,
  `_dflash_exactness`, `_dflash_gpu`, `_exact_rows`, `_vision_gpu`,
  `test_gpu_muse_glimmer_decode_glue`, `_flash_prefill`.
- `hipengine serve` with DFlash attached, three chat turns over a 4,756-token
  system prompt, gfx1151. AR: 17.7 s, then 4.3 s and 4.2 s with
  `cached_tokens: 4096`. `"speculative": true`: 20.8 s (the drafter did not
  hold the prompt yet), then 2.8 s and 3.1 s with `cached_tokens: 4096`. Each
  turn decoded up to 48 tokens; same text on both paths.
