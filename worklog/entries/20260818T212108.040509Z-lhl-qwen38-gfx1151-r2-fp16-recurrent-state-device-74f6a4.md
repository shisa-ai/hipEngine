# gfx1151 R2 fp16 recurrent state device change (c8 decode)

## Summary

R2 (c=N fp16 recurrent state, ~6% at c8) device change: template the GDN
recurrent-state kernels on a `state_t` storage dtype (fp32 strict vs fp16
production) with fp32 accumulation and RNE half round-trip, and route the
Qwen3.8 Q4_K_S production AR path through the fp16 instantiations under
`HIPENGINE_GGUF_FP16_RECURRENT_STATE`. The full prefill->decode flow now
produces greedy tokens bit-identical to the strict FP32 path (top-1 agreement
1.000 over 16 decode steps on the real 27B model).

## Changes

- `gdn.hip`: added `gdn_state_read_qwen35`/`gdn_state_write_qwen35` (type-safe
  state load/store with `std::remove_cv` so volatile aliases keep exact
  semantics; fp32 instantiation is the identity path, byte-identical to the
  legacy `float*` bodies). Templated on `state_t`:
  - `qwen35_gdn_recurrent_rmsnorm_gate_lowp_kernel` (decode gate, also covers
    the fused f32+bf16-out cast owner)
  - `qwen35_gdn_chain_recurrent_rmsnorm_gate_lowp_c1_exact_tloop_kernel` (chain
    prefill)
  - `qwen35_gdn_recurrent_rmsnorm_gate_segments_lowp_kernel` (segments decode)
  - `qwen35_gdn_prefill_recurrent_compact_normalized_wave32_xor_kernel` +
    `_normalized_wave32_xor_kernel` + `_segments_wave32_xor_kernel` (the
    prefill writer family; `chain_compact_peer_wave32` is the gfx1100/gfx1151
    Q4_K_S production route)
  - Added `half_t` fp16-state `extern "C"` launchers for each production symbol
    plus the fused `...f32_bf16_out_fp16state` and
    `...compact_normalized_wave32_xor_fp16state`.
- `gdn.py` / `linear_attn/__init__.py`: fp16-state wrappers + symbol constants +

- `qwen35_gguf_runner.py`: `_gdn_decode_gate_kernel` /

- `tests/test_qwen35_gguf_gdn_fp16_state.py`: RED tests for chain-prefill +

## Root cause found by e2e debugging

The naive e2e produced NaN in decode with the state buffer corrupted to
alternating huge/±~0.44 fp16 values — the signature of an FP32 kernel writing
fp32 state into the half-sized buffer. Prefill was already correct (state after
prefill was clean fp16), and the plain gate/segments fp16 kernels were clean
standalone. Instrumentation showed `_run_linear_attention_attn_only` never
reached `_gdn_decode_gate_kernel`: the Qwen3.8 Q4_K_S `ssm_out` weight carries
`quant_key='gguf_q5_k_t16_v1'`, which resolves the fused
`gdn_recurrent_rmsnorm_gate+cast` `f32_bf16_out` owner (FP32-state writer).
Adding the fp16-state fused variant fixed the decode; the full flow then matched
strict greedy tokens exactly.

## Validation

  Qwen3.8-27B Q4_K_S gfx1151, 16 decode steps. identical=True,
