# EVIE batched attention + softmax fix

## Summary

Attention (vision + text) rewritten from per-head gather/scatter loops to
rocBLAS batched SGEMMs; the softmax kernel's serial thread-0 passes were
the real attention bottleneck (14.8 ms of 17 ms per vision block). Corrected
benchmark total for the 8-page workload: 15.62 s -> 11.68 s (doc 9.5 s,
query 2.1 s, maxsim 1.2 ms).

## Changes

- `hipengine/core/rocblas.py`: new `sgemm_strided_batched` and
  `sgemm_batched` (device pointer arrays) bindings.
- `hipengine/runtime/evie.py`: `_attention_from_packed` (vision, packed
  qkv, uniform strides) and `_attention` (text, GQA via pointer arrays,
  no k/v repeat materialization) now run 2 batched GEMMs + scale + softmax;
  the AV product writes directly into the packed output (no gathers or
  scatters). Scores scratch is heads*x*y with 16-byte-aligned per-head
  stride.
- `evie_ops.hip`: `evie_softmax_rows_kernel` now uses all threads on
  the exp and normalize passes (was: thread 0, serial). Takes a head
  stride so padded score layouts stay correct for odd token counts.

## Validation

- `tests/test_evie_gpu_runtime.py`: 3/3 after fixing three integration
  bugs (pointer-array aliasing by size-keyed cache; AV B-pointers using the
  unpadded stride; scale range missing padded heads).
- Batched-GEMM bindings unit-verified standalone vs numpy (exact).
- rocprof-style phase timings: vision block attention 25.2 -> 2.1 ms
  (softmax 14.8 -> 0.22 ms); text full-attn layer 8.3 -> 6.6 ms.
- Bench (same protocol, best of 3): 11.68 s total.

## Next

FP32 SGEMM is hardware-walled at ~2 TF/s on this APU (2048x8192x8192
measured 2.06 TF/s). The FP16 matrix-core path (38-42 TF/s per the
timesfm campaign) is the next decisive step — requires the
production-profile numerical gate.
