# Share Qwen4 single-request MTP rollback ownership

## Summary

The Qwen4 single-request MTP cycle now uses the same completed-checkpoint
journal as PARO. A failing target restore no longer skips draft, sampler or
grammar restoration, and iterator cleanup runs even when rollback raises.
Public success-path and device failure tests pass. Evidence and commands are
in [the validation record](../../docs/testing/2026-10-24-qwen4-mtp-journal/NOTES.md).

## Changes

- Capture grammar, sampling, draft and target checkpoints inside the guarded
  operation. Restore completed captures in reverse order.
- Keep undo records until target commit succeeds. Close the iterator in a
  rollback `finally` block.
- Add focused failure, cancellation, capture and commit regression coverage.

## Validation

- Child RED run against parent source: 7 failed, 1 passed. Candidate focused
  tests: 169 passed; parent reran 127 directly affected tests successfully.
- Public `LLM.generate_detailed()` comparison: all 12 parent/candidate/repeat
  calls matched IDs for 37- and 513-token prompts at temperatures 0 and 0.7.
  The automatic-MTP request intent exercised `_advance_mtp` five times in
  every call. Tracked allocations and bytes returned to zero after close.
- First device attempt stopped before generation: sequence capacity 768 gave
  fewer index blocks than the QSA selection budget. The successful attempt
  used sequence capacity 4096 with identical prompt lengths.
- Two public device fault tests passed: post-catch-up cancellation restores
  live target/draft bytes and sampler state, publishes only the committed
  prefix, closes the iterator and allows a following request; capture failure
  restores earlier owners without leaving a transaction lease.
- Default unit suite, compileall, fixture and test-tier checks, registry,
  CPU-fixture and smoke-add-plan checks passed. No new Torch import.
- Audit passed with three verified duplicate graph-key decisions recorded for
  Python 3.12. Python 3.13 has different AST context hashes for the same
  sites; production code and evidence hashes are unchanged. This triage does
  not fix the audit identity defect or alter the budget.
- No performance claim is made.
