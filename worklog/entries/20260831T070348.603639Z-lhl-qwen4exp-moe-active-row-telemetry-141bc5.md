# Add Qwen4Exp MoE active-row telemetry

## Summary

Added a separate diagnostic mode to the durable Qwen4Exp profiler that records
actual per-layer expert routing distributions. This supplies P2's missing
active-row dimension without contaminating the binding role trace: telemetry
and rocprof mode are mutually exclusive, and every telemetry output is labeled
instrumented/non-performance.

## Changes

- Added `--moe-telemetry` to `scripts/qwen4exp_profile_gap.py` for prefill mode.
- Wrapped `run_qwen4_exp_moe` only during measured calls, after warmup. Each
  call copies the selected expert IDs after the original MoE role completes and
  records layer, gate/up/down qtypes, rows, top-k, compact rows, active experts,
  min/median/max rows per active expert, a row-count histogram, and exact
  expert counts.
- Recorded telemetry copy bytes/wall separately and restored the wrapped
  function exactly.
- Rejected `--profile --moe-telemetry` and decode telemetry so the added D2H
  copies cannot be mistaken for a performance trace.
- Documented the required separate-run protocol in the performance campaign.

## Validation

- RED: the pure distribution and parser tests failed before telemetry support.
- GREEN: `uv run pytest -q tests/test_qwen4exp_profile_gap.py` -> 10 passed,
  including wrapper/copy/restore coverage.
- Real p508 production smoke completed 48 layer calls:
  - copied 1,950,720 bytes in 4.136 s of instrumented copy wall;
  - layer 0 has 188/512 active experts, median 27.5 and max 209 rows;
  - layer 2 has 171/512 active experts, median 20 and max 160 rows;
  - all layers report 508 rows, top-10, and 5,080 compact rows;
  - output explicitly says `diagnostic_instrumented_not_performance`.
- Smoke artifact/log remain local at
  `/tmp/qwen4exp-p508-moe-telemetry-smoke.{json,log}`; its 89.79 tok/s is not a
  performance result.
