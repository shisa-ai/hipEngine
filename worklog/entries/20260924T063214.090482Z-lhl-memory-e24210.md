# Named resident-consumer ledger; the packed verify scratch is priced before allocation

## Summary

The pool's byte budget priced two things: its own arena, and one anonymous sum of
"private workspace" charges. An overload therefore reported "arena and private
workspace KV exceed the pool budget" with no way to tell which consumer had to
shrink, and the packed verify state's own scratch buffers -- device mallocs the
state owns -- were allocated without being priced at all. The ledger now carries
named consumers and refuses by name, and the scratch is charged before it is
allocated.

## Changes

- `hipengine/kvcache/device_global.py`: the reservation ledger stores
  `(name, bytes)` instead of bare bytes. New `reserve_resident_bytes(name, nbytes)`
  is the general entry point; `reserve_private_workspace(nbytes, name=...)` keeps
  its signature and now delegates to it, so existing callers are unchanged.
  `private_workspace_bytes` and `accounted_bytes` keep their numeric meaning.
  `resident_consumers` reports the arena first and then every charge in charge
  order. `_check_byte_budget` prices those consumers through
  `price_memory_admission` and raises `MemoryAdmissionRefused`, which names the
  consumer that does not fit; the old message survived only as a bare
  `MemoryError`. The admission import is deferred into the two methods that need
  it because `hipengine.runtime` pulls in the KV cache, so a module-scope edge
  from this package to that one is a circular import.
- `hipengine/runtime/qwen35_gguf_runner.py`: `_GGUFPackedTargetState.allocate`
  charges `packed_verify_scratch` for its conv/recurrent state buffers before
  allocating them, sized as `linear_layers * (conv_state_nbytes +
  recurrent_state_nbytes)` -- exactly the bytes the state then holds. The charge
  token and its pool are stored on the state and released where the existing
  private-workspace token is released in `_free_packed_verify_workspace`, which
  `release_idle_packed_workspace` also funnels through, so there is one release
  site and no leak. The charge is skipped when a pool does not implement the
  ledger, which is why the existing fake pools in tests are unaffected.

## Validation

- `tests/test_unit_kvcache_global_device_pool.py`: 10 new tests. Each of five
  named consumers (target KV scales, draft KV, verifier scratch, captured graphs,
  retained prefix) is the refusal reason when it is the one that does not fit, at
  its own edge with an unrelated consumer holding half the headroom first; the
  exact boundary charge is admitted and one byte more is refused; a byte count
  unrelated to any threshold (77) behaves identically on both sides; the refusal
  carries the API code, names the consumer in its message, is a `MemoryError`,
  and leaves `accounted_bytes` untouched, which is what "before allocating"
  means here. `resident_consumers` order, named private-workspace charges, and
  input validation are covered too. File: 27 passed.
- `tests/test_unit_gguf_packed_verify_layout.py`: 2 new tests. The scratch charge
  is requested exactly once under the name `packed_verify_scratch` and equals the
  bytes of the state's conv/recurrent buffers; a pool without the ledger is
  charged nothing and stores no token. File: 69 passed.
- `tests/test_unit_gguf_packed_workspace_stability.py`: the existing
  `test_private_workspace_budget_and_buffer_lifecycle` was corrected rather than
  worked around. Its success case now asserts both charges (payload plus scratch)
  and the consumer order; its two-page budget case now asserts `calls == 0`,
  because the scratch no longer fits and is priced before the buffers exist --
  previously four buffers were created before the payload was refused. That case
  therefore no longer exercises the payload refusal, so
  `test_private_kv_payload_is_refused_by_name_once_the_scratch_fits` (budget five
  pages, scratch fits, payload does not) restores it and asserts the refusal
  names `private_workspace`, that the four scratch buffers existed and were
  freed, and that the ledger is empty afterwards.
- Bundles: the six-file unit bundle (225 passed) and the four packed-state
  dependants `test_unit_gguf_device_kv_binding`,
  `test_unit_qwen35_gguf_mtp2_seam`, `test_unit_qwen38_packed_c1_commit`,
  `test_unit_qwen38_packed_c1_teacher_candidate` (161 passed) are green.
- Not run: any live arm. The wiring is exercised through the real
  `_GGUFPackedTargetState.allocate` with only `malloc`/`runtime` faked, but no
  end-to-end `hipengine serve` run has confirmed the charge appears in a live
  MTP session's accounting.

  allocates draft KV through `_allocate_mtp_dense_kv` into `self._draft_kv_slabs`
  and target hidden slabs into `self._target_hidden_slabs`; neither charges the

  device memory of its own, so there is nothing separate to price.
