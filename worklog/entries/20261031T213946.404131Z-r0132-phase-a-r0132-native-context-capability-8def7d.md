# Replace native context identity admission with a dense-FFN capacity capability

## Summary

Phase A of R0132 only. The native target context resolver no longer admits a
route by `(GGUFModelGeometry, file_type_name)`. It admits by a declared
structural feed-forward capability, the target's KV storage and recurrent-state
arithmetic, and the target's actual allocated capacity. A capable route is
bounded by `min(caller bound, allocated capacity)`; it is never bounded by a
quant stamp or by the caller's requested end position. MoE keeps the recorded
numeric fallback.

This deliberately changes admission for dense quant stamps that were previously
excluded: a compatible unfamiliar dense layout now uses capacity by capability.
It is not a claim of behavior preservation across those stamps.

## Changes

- `hipengine/kernels/hip_gfx1100/__init__.py`: replace
  `GGUF_SPECDEC2_NATIVE_TARGET_CACHE_CAPACITY_POLICIES` with
  `GGUF_SPECDEC2_NATIVE_TARGET_CAPACITY_FFN_KINDS = frozenset({"dense"})` and
  update `__all__`. gfx1151 declares neither; its 65544 numeric behaviour is
  unchanged.
- `hipengine/runtime/gguf_native_spec_cycle.py`:
  - add `NativeSpecTargetContextResourceError` and export it;
  - add `_native_target_ffn_kind` (`config.is_moe`, then
    `geometry.expert_count`). There is no architecture-name fallback: the
    runtime `Qwen35GGUFConfig` declares `is_moe` and `expert_count`, and
    `GGUFModelGeometry` declares `expert_count`; no non-fixture owner lacks
    both, so an identity-shaped name match is unnecessary;
  - add `_native_target_allocated_capacity`. `scratch.max_positions` is the
    live slot bound. A present nonpositive slot returns None instead of
    falling back to a larger published layout. When the slot is positive, the
    function returns the smallest positive value among the slot,
    `target_layout.max_sequence_length`, and
    `_target_scratch_owner.max_positions`. The published layout is proven to
    be allocated at `hipengine/runtime/qwen35_gguf_runner.py:14033`:
    `Qwen35GGUFResidentSession.__init__` sets
    `max_sequence_length=int(self.scratch.max_positions)`, so it is not the
    caller's requested end position;
  - `native_target_context_limit` keeps the BF16/INT8-per-token-head KV check
    and the FP32 recurrent-state check, replaces the identity lookup with the
    FFN-kind capability, returns `min(default, capacity)`, and raises the named
    resource error when a capable route exposes no positive allocated capacity.
    Its docstring now states that row/topology validation remains in the
    verifier, not in this resolver.
- `scripts/gguf_native_context_gate.py`: the process-local override now clears
  `GGUF_SPECDEC2_NATIVE_TARGET_CAPACITY_FFN_KINDS` instead of the retired
  policy set, so a diagnostic limit applies to every route.
- Focused tests updated in `tests/test_unit_gguf_native_context_gate.py`,
  `tests/test_unit_qwen35_gguf_mtp2_seam.py`, and
  `tests/test_live_gguf_native_spec_cycle.py`. The new assertions cover
  unfamiliar dense quant stamps, the retained MoE fallback, FP16 state and
  unsupported KV bounds, capacity above the caller's end position, and the
  named missing-capacity error, plus the published-owner, zero-capacity,
  conflicting-source, and nonpositive-slot regressions.
