# R0281-FAIR-BURST retained as a documented operator control

## Summary

**Decision: retain `fair_prefill_burst_chunks` and `HIPENGINE_FAIR_PREFILL_BURST_CHUNKS` as the
supported operator scheduling control.** The entry's retention branch required documenting the
control and removing the retirement item. The control is live on four surfaces (engine-loop config
and CLI, generator package defaults, server metrics, load-gate tuning protocol), so replacing it with
a workload-derived policy would have to migrate all of them at once, and no defect justified that
work. Inspection found the documented semantics accurate; one behavior clause was missing, and it is
now recorded. No scheduler behavior, interface, default or arithmetic changed.

## Changes

- `docs/ENVS.md` — `HIPENGINE_FAIR_PREFILL_BURST_CHUNKS` row states the one remaining behavior a
  tuner needs: a lone prompt that still needs prefill keeps one-chunk alternation whatever the bound
  is. The row already carried the default (`1`), the CLI flag, the `fair`-only scope, the positive
  validation and the gfx1151 Q4_K_M package override.
- `docs/REFACTOR.md` — removed the R0281-FAIR-BURST entry; the decision is complete.

No engine, scheduler, generator, metrics, load-gate or protocol file was touched.
