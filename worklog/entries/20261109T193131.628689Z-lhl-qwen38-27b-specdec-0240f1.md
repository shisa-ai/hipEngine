# DSpine P1 device route: graph verify + device tap projection (+11% AR-exact)

## Summary

Ported the EAGLE-4 P1 device-route machinery to DSpine: the cycle now verifies on the graph-captured native target (6 rows, 5 tap layers) and projects the committed tap rows entirely on device, eliminating the per-cycle tap D2H + host concat + host fc projection. Measured +11.3% decode tok/s, AR-exact, acceptance preserved. The win is modest because the verify GEMV device time (6 rows > the `_PACK8_ROWTILE_MAX_ROWS=4` cliff) dominates the cycle; the graph removes dispatch overhead, not GEMV bandwidth — confirming the shared rowtile cliff (task #33) is the next highest-value lever.

## Changes

- `hipengine/kernels/hip_gfx1100/speculative/dspine.hip` / `.py`: new `dspine_concat_taps` kernel + wrapper — fuses the f32->bf16 cast and feature-dim concat of up to 5 FP32 tap buffers into the BF16 `[rows, n*H]` fc input (1 launch instead of 5 casts + concat).
- `hipengine/runtime/dspine.py`: `DSpineNativeDrafter._project_taps_device` (cast+concat -> fc GEMM 25600->5120 -> hidden_norm RMS-norm) and `append_projected_rows_device` (writes projected rows into `projected_ctx` at `ctx_len`, then the already-device `_append_ctx_kv`). DSpine projection is fc-then-norm (no per-chunk norm, unlike EAGLE). Buffers sized to `block_size`.
- `hipengine/speculative/dspine_cycle.py`: eager `session.verify_target_block` -> `verify_qwen35_gguf_native_b2_target(..., fallback=True)`; device aux path when `layer_output_hidden_device` is present, host fallback otherwise; `ctx_len` tracked via `native.ctx_len` (dropped the host `ctx_taps` concat); reports `graph_verify_cycles`.
- `tests/test_gpu_dspine_device_projection.py`: bit-exact numpy oracle for `dspine_concat_taps` across tap counts 1..5 and odd row/hidden geometries (HIP-guarded).
- Artifact: `benchmarks/results/2026-11-09-gfx1151-qwen38-27b-dspine-p1-device-route.json`.
