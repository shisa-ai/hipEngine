# Worklog schema conformance repair: 19 entries fixed, check now clean

## Summary

`python3 scripts/worklog.py check` reported 19 pre-existing errors on `main`: 16
`invalid filename` entries and 3 entries missing a required section. The filename
gate short-circuits entry parsing, so the 16 were hiding further defects: five had
**no frontmatter at all**, eleven had a **9-character `base_commit`** instead of a
full 40-character hash, and eleven were missing canonical sections. Six of the
eleven had a frontmatter `topic` that did not match their filename.

All 19 entries now validate. `check --allow-modified` exits 0 with 2484 valid
entries, and `render` produces the full local view.

## Changes

- **Frontmatter added** to 5 entries that had none
  (`qwen4exp-r11-bitexact-down`, `qwen4exp-r11-corrections`,
  `qwen4exp-r11-strict-envelope`, `qwen4exp-digest-mismatch-repro`,
  `qwen4exp-r13-closure-amendment`), using the filename's stamp/worker as the
  timestamp/worker and the entry's own declared `Source:` commit (or the adding
  commit's parent) as `base_commit`.
- **`base_commit` expanded** to the full 40-character hash in 11 entries
  (`7f98e5106` -> `7f98e51063db3edf6230f3cbaa7df8f9051f0f60` and ten others).
- **Required sections added** where missing: the four canonical sections
  (`## Summary`, `## Changes`, `## Validation`, `## Next`) to 16 entries that
  lacked them, and one missing section each to the 3 entries that were flagged
  (`## Validation` for `evie-03a8fd`, `## Next` for `evie-d4df7e`, `## Changes`
  for `evie-fddba8`). All original prose and every original heading are preserved;
  the new sections are additive and derived from each entry's own content.
- **16 entries renamed** to `{stamp}-{worker}-{topic}-{6hex}.md` with `git mv`
  (history preserved).
- **Cross-references updated** in 6 files: the campaign doc (4 links), the R7
  wrapper-host screen JSON, the v8 retention methodology note, and 3 worklog
  entries that link to renamed siblings.
- One extra heading in `r11-bitexact-down` was renamed from
  `## Next: the fast-bit-exact design (option a)` to
  `## The fast-bit-exact design (option a)`, because the entry now carries a
  canonical `## Next` and two adjacent `Next` headings would be ambiguous.

## Decision

**Frontmatter `topic` is authoritative over the filename.** Where the two
disagreed (6 entries), the file was renamed to the declared topic rather than the
declared topic being rewritten to the filename. `worklog.py new` derives the
filename from `topic`, so the filename is the derived artifact; correcting the
derived name preserves the author's declared metadata. The cost was 4 doc links
plus 1 artifact pointer, all updated in this unit.

**Immutability.** This unit edits and renames 19 already-committed entries, which
`worklog/README.md` ("Immutable after commit": do not modify, rename, or delete)
and the `r13-closure-amendment` precedent otherwise forbid. The owner explicitly
asked for the schema to be repaired in place, and these are **conformance
repairs, not content revisions**: no original prose was deleted or reworded, only
frontmatter added, truncated hashes expanded, missing canonical sections added,
and names corrected. Every added section is derived from that entry's own
existing text. The alternative - a new amendment entry per defect - would add 19
entries to record schema trivia, and the defects would keep failing `check`
meanwhile. `worklog/README.md` was deliberately **not** edited: it is a
high-conflict policy file, and relaxing its immutability prose is the owner's call,
not a side effect of this repair.

  this commit. The authoritative mapping is recorded in the commit message and in
  the Changes list above.
