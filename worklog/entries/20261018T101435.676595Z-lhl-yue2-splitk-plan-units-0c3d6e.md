# HIP multiprocessor count is WGPs, not compute units

## Summary

Corrects the unit explanation in
`worklog/entries/20261018T080555.388880Z-lhl-yue2-splitk-plan-6fe862.md`, which
described HIP's `MultiprocessorCount` of 48 on a 96-CU gfx1100 as "compute units per
shader engine". It is not per shader engine: HIP's device property counts **workgroup
processors**, and RDNA3 packs two compute units into each WGP. The plan's CU-based
arithmetic was already right, because it takes its count from `rocminfo`'s
`Compute Unit`; only the explanation of why the HIP property is unusable was wrong.

## Evidence

A compiled `hipDeviceProp_t` probe on both local cards (W7900 and RX 7900 XTX, both
`gfx1100`) reports:

| Property | Value | Meaning |
| --- | ---: | --- |
| `multiProcessorCount` | 48 | WGPs, not the 96 CUs `rocminfo` reports |
| `maxThreadsPerMultiProcessor` | 2048 | per WGP, so 1024 threads per CU |
| `maxBlocksPerMultiProcessor` | 64 | per WGP |
| `regsPerMultiprocessor` | 196608 | per WGP |
| `sharedMemPerMultiprocessor` | 65536 | per WGP |
| `warpSize` | 32 | wave32 |

`hipDeviceGetAttribute(hipDeviceAttributeMultiprocessorCount, dev)` returns the same
48, so the scalar attribute and the struct agree with each other and disagree with the
CU count by exactly the 2:1 WGP ratio. That is why the split-K plan could not size its
grid from either one: it would have halved every grid.

The occupancy arithmetic cross-checks against the hardware table already in
`docs/RDNA3-TUNING-GUIDE.md` §2.2, which records 32 waves per CU independently:
2048 threads per WGP over two CUs is 1024 threads per CU, which is 32 wave32, which is
four resident 256-thread blocks per CU. The two numbers agree only under the WGP
reading, so they confirm each other.

The CU count is a SKU property, not an ISA one. gfx1100 covers 80, 84 and 96 enabled
CUs (RX 7900 GRE, RX 7900 XT, RX 7900 XTX and the W7900), and harvesting is per card,
so no arch-level multiplier recovers the count. The 2:1 CU-to-WGP ratio is the only
arch-level constant here, and it converts between units rather than counting them.

## Changes

- `hipengine/core/hip.py`: `device_compute_units` docstring now names the unit, records
  the 48-versus-96 measurement and both HIP properties that report WGPs, and states why
  the count has to come from the device.
- `hipengine/kernels/hip_gfx1100/vibevoice/attention_spans_splitk.py`: the
  `BLOCKS_PER_UNIT` comment said one 256-thread block fills a CU. A CU holds 32 wave32,
  so a block is a quarter of one and four blocks per CU is full occupancy; the measured
  floor of two is half occupancy, and the comment now says so.
- `docs/RDNA3-TUNING-GUIDE.md` §2.1: the concrete property mapping, the per-WGP
  occupancy limits, and the SKU-count point.
- The commit message of the split-K plan commit was corrected before it left this host
  (now `1f2b664b3`); no code in it changed.
