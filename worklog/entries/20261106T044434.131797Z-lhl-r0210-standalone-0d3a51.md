# Lease standalone packed backing through a storage owner

## Summary

Standalone packed fallback buffers and optional pool charge now have an explicit
lease owner. PackedWorkspaceOwner releases through the lease rather than treating
these buffers as directly owned state mallocs.

## Changes

- StandalonePackedBackingLease acquires backing/charge atomically and releases
  buffers before charge; completed frees are removed so retries do not double-free.
- Packed state retains its all-buffer inventory for memory reporting, but the
  shared workspace owner excludes lease-owned buffers from direct release.
- Allocation shape, fallback selection, page mapping and kernels are unchanged.
  This is not yet removal of standalone fallback or allocation policy from state.

## Validation

- RED owner fixture could not import the new lease type.
- GREEN affected owner/layout/stability/growth/pool bundle: 202 passed,
  `/tmp/r0210-owner-lease-green.log`.
- Additional interrupted-release retry fixture and changed owner module: 9 passed,
  `/tmp/r0210-owner-retry.log`.
- Public cancel/refill/close passed with one standalone backing lease balanced,
  matching refill tokens and zero live device allocations at close;
  `/tmp/r0210-standalone-public.log`. Audit passes,
  `/tmp/r0210-standalone-audit.log`. Public test injects no-pool
  allocation at packed-state boundary to exercise otherwise uncommon fallback;
  it is not evidence that automatic production selection uses this fallback.
