# QA-9 closed: the pooled-key cache is already implemented, incremental, and tested

## Summary

**QA-9 closes as already implemented.** The row asks for an audit rather than
code: "Inspect the pinned scorer formula and compare actual operands/selections
with our existing pooled bank before proposing code. If only redundant work
disappears, test under `QA-4`; if selection policy/representation changes, declare
a separate configuration rather than silently promoting it."

Audit result: the cache exists, is incremental, is rollback-safe, and is tested.
"Add a cache" is not new work. The external variant is non-bit-exact and therefore
falls under the row's **second** branch - a separate declared configuration.

## The bank already exists and caches incrementally

`Qwen4ExpQSAIndexDeviceState.append` is documented *"Append only newly completed
normalized/RoPE index-key blocks"* and short-circuits:

```python
first = self.pooled_count
if complete <= first:
    return
count = complete - first
qwen4_exp_qsa_pool_norm_rope_f32(... self.pooled_keys.ptr + first * self.index_dim * 4 ...)
self.pooled_count = complete
```

Only `count = complete - first` blocks are pooled, appended at `first * index_dim`.

## And the incrementality is tested, not just readable

This is what makes the audit conclusive. `tests/test_gpu_qwen4_exp_runner_qsa.py`
monkeypatches the pool kernel and asserts the **call counts**:

| action | asserted |
|---|---|
| first select after 6 appends | `pooled_count == 3`, counts `[3]` |
| append 1, select | counts still `[3]` - **nothing pooled** |
| append 1, select | `pooled_count == 4`, counts `[3, 1]` - **only the new block** |
| second call offsets | `member_indices.ptr + 3*2*4`, `pooled_keys.ptr + 3*4*4` |
| `restore_count(6)` | `pooled_count == 3` - **rollback works** |

A reading of the source could be wrong about caching; a call-count assertion
cannot. The test fails if incrementality, offsets, or rollback stop holding.

## The formula is pinned and oracle-tested

`qsa_index_scores` documents the contract - *"Rectify each QSA index-head dot
product before summing heads"* - as `sum_h max(dot(q_h, key_b), 0) /
sqrt(index_dim)`. `qsa_score_f32_kernel` matches it (per-head `dot` over
`index_dim`, then `value += fmaxf(dot, 0.0f)`), and
`test_qwen4_exp_qsa_native_pool_score_select_match_cpu` compares the GPU path
against the CPU reference.

Operands are `pooled_keys[blocks, index_dim]` - one pooled key per **block**, the
same granularity the external cache operates on.
