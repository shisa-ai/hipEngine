# Cross-engine code-p4096 per-operator attribution complete

## Summary

Task #7 complete: one request-delimited code-p4096 prefill per engine
captured under `rocprofv3 --kernel-trace` and attributed by the shared role
map into the cross-engine family table in
`benchmarks/results/2026-10-12-qwen4exp-cross-engine-pass1/`
(`attribution-summary.json` + README section).

## Decisions

- The comparator (`qwen4exp_llamacpp_prefill_comparator.py`) gained an
  `--engine gufo` path (text-driven `/v1/completions`, tokenizer round-trip
  gate, `cache_n=0` guard) and `--warmup-case-id`: gufo v0.12.0's
  `--cache-ram-bytes` does **not** disable its RAM continuation cache
  (config log: `capacity_bytes=1 automatic_bytes=22338777088`), so warming
  with the identical prompt makes the measured request a cache restore.
  The warm-up now uses a different-category case (general_en-p4096), making
  a restore structurally impossible; the guard still verifies `cache_n=0`.
- The role map gained a `gufo` dialect. Two mapper bugs were found by the
  capture and fixed: rules now run on the kernel-name head only (gufo's
  demangled signatures carry parameter types like `AttentionSupportParams`
  that matched the attention rule for dense GEMMs), and the fixed
  `FAMILIES` list gained `expert_fused` - without it, ~790 ms of routed
  expert time was silently dropped from every report. `expert_fused` is
  the honest family: gufo's `RoutedF16GEMMKernel` fuses routed
  gate/up/down in one launch and the name cannot separate them.
- hipEngine's burst held its identical warmup + measured prefill (gap below
  the 250 ms burst threshold). The divisor is exactly 2 and validated: the
  halved kernel sum is 0.998 of the measured wall (12205.9 ms).
