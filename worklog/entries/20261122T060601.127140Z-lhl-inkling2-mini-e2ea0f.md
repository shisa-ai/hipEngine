# Share exact packed Inkling gate inputs across routes

## Summary

The tiled NVFP4 gate/up projection can share one normalized row across a token's routes. The kernel reads the same FP32 values and writes the same route-ordered outputs without uploading a copy for every route.

## Changes

- Add a shared-input variant of the four-route NVFP4 leaf. Select it by registered layout support in `strict`, default, and `fast` GGUF prefill. Retain expanded route inputs for other layouts, ungrouped dispatch, and projections with genuinely different route inputs.

## Validation

- RED: the focused GPU test reported the missing shared-input registry variant before implementation. GREEN: local packed fixtures passed with uneven tile tails, non-power-of-two fanout, scaled and unscaled outputs, and shared versus repeated inputs matching bitwise.
- The deterministic CPU bundle and documentation gates passed. Cached `rocprofv3 --kernel-trace` on W7900 captured both specializations of `gguf_nvfp4_selected_tile4_f32_kernel` with positive durations in the focused fixture.
- `python -u ./hipengine_inkling_shared_input_probe.py "$model" "$backend"`, W7900/mainline Q4_K_M and Strix Halo/pinned Loom Q4_K_XL. In strict and fast, shared input preserved bitwise first logits at 47 and 151 input and all eight greedy IDs at 47, 151 and 575 input. Fast also preserved all eight IDs at 1,027 input, beyond local wrap. The public route invoked the shared kernel with eight routes per input. At 575 input on Strix the projection owner's upload payload in fast fell from 4,249,263,072 to 2,617,109,472 bytes. These are staged host-to-device bytes, not physical bandwidth or a latency claim.
