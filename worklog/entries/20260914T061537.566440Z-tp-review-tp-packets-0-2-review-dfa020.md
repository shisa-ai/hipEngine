# Review TP packets 0-2 and require transport and evidence repairs

## Summary

Review snapshot: commits `c0e17b4bb..aa2cb6288`, before the concurrently ongoing
repair tasks #18-21. Useful shard reconstruction and communication screening
exist, but Packets 0-2 are not ready to certify complete. The published break-even
decision needs new evidence, not merely a corrected summary. This is not a
finding that TP2 cannot win.

The user explicitly assigned runtime fixes to the coder and asked this reviewer
to continue independently. No runtime, test, benchmark, or architecture files
were edited by this review. The new review entry is the sole authored change.

## Changes

### R1 - P1: real RCCL validation occurs after issuing the invalid group

At the reviewed revision, `hipengine/distributed/rccl.py:312-333` calls native
`group_end()` before checking rank completeness or cross-rank shape agreement.
`_enqueue()` has already issued each native collective. A missing rank or
mismatched count/order can therefore enter blocking native code before the
Python rejection or `sync()` deadline is reached. The mock validates first,
so its passing error tests do not establish the real transport contract.

CPU injected-binding reproduction with counts 4 and 8 records
`start, native_reduce(4), native_reduce(8), native_end` before raising
`TransportStateError`. Buffer whole-group requests and validate before native
issue. Separate any supported threaded submission protocol explicitly. This
belongs to the coder's task #19.

### R2 - P1: constructor failure leaks streams and successful communicators

`hipengine/distributed/rccl.py:240-241,417-455` has no encompassing cleanup for
stream creation, unique-ID retrieval or partial rank initialization. Successful
communicators stay in a local list until all ranks succeed. Injecting failure on
rank 1 leaves both streams and rank 0's communicator unfreed; no context object
is returned to let the caller close them.

Initialization also uses blocking calls on non-daemon threads. A timeout does
not cancel those calls or make interpreter shutdown bounded, and the declared
nonblocking communicator path is not implemented. Implement ownership from
first acquisition, one group deadline, and explicit supervised diagnostic versus
serving capability. Task #19 addresses this family.

### R3 - P1: the measured "chain" is not a layer-dependent reduction chain

`scripts/tp_collective_bench.py:430-439` puts every reduction inside one native
group, repeatedly reading unchanged send buffers and overwriting the same receive
buffers. The producer/consumer memsets touch separate four-byte scratch buffers.
No consumer reads the previous reduction and produces the next input.

RCCL defers collective enqueue until group end; the surrounding memsets do not
establish the claimed dependencies. The reported `2 * depth + 1` graph nodes
are consistent with memsets plus one aggregated collective node, not one
independently dependent reduction per layer boundary. Marginal latency from this
test cannot be multiplied into a model-step cost.

Keep these results as aggregated-collective diagnostics. Add a true
producer -> all-rank sum -> dependent consumer -> next producer benchmark, with
the correct group boundary at each sum and a final result depending on every
iteration. Change inputs/check outputs on repeated replay. Recompute the
break-even input from that protocol.

The depth-32 device fault also does not prove a general HIP graph limit of
49 nodes. `docs/QWEN38-27B-GFX1100-TP2.md:142-150` and
`benchmarks/README.md:927-929` overgeneralize one workload failure into a mandatory
two-graph design. Localize the fault and qualify the actual graph composition;
do not intentionally repeat the device-fault case on a shared working host.

### R4 - P1: the break-even decision has independent input and model errors

- The actual GGUF config has 64 blocks: 48 linear-attention and 16 full-attention.
  The N=2 manifest contains 128 row-parallel projections: 64 `ffn_down`,
  48 `ssm_out`, and 16 `attn_output`. Full TP needs those 128 sums, plus any
  embedding/sampling communication, not the published 36. Even MLP-only TP
  needs 64 sums. Derive counts from the manifest. Task #20 covers this.
- The W7900 27.9 tok/s source is
  `benchmarks/results/2026-09-13-w7900-qwen38-q4km-int8-512-128.json`:
  prompt 512, decode 128, INT8 per-token/head KV. It is not the 8192/BF16
  configuration described alongside the XTX 29.82 control in the TP rollup.
  Fresh matched controls or accurately scoped diagnostics are required.
- `scripts/tp_break_even.py:79-143` computes a separate complete TP2 time for
  each participating GPU. The XTX projection excludes waiting for the larger,
  slower W7900 shard. One group's time must sum maxima at each dependency
  boundary and compare against the faster matched TP1 arm. There are not two
  independent TP2 throughput results for the same pair.
- No local shard-shaped kernels were measured, despite the pre-Packet-3 gate.
  Calling the implied bandwidth a projection does not fulfill that gate.
  The reporting expression for implied bandwidth also multiplies by
  `(1 - fixed_share)` instead of dividing by it; it is not the bandwidth
  described in the module's equation.

Withdraw the quantitative go certificate pending these corrections. Permission
to implement a diagnostic AR slice is distinct from certifying break-even.

### R5 - P1: accepted KV replication can pair queries with the wrong KV head

`hipengine/loading/qwen35_gguf_shards.py:460-467` uses `rank % groups` when
replicating fewer KV heads across more ranks, while query heads are contiguous.
For Q=4, KV=2, N=4, expected KV ownership is `[0,0,1,1]`; the reviewed code
returns `[0,1,0,1]`. Coverage/reconstruction still passes. This affects the
generic accepted replication case, not the target model's N=2 nonreplicated
partition. Task #18 is repairing it; test numerical attention and global maps,
not just byte coverage.

### R6 - P1: context accepts a transport with the wrong ordered devices

`hipengine/distributed/context.py:133-139` validates only `world_size` for a
supplied transport. A plan for devices `[0,1]` accepts a transport with devices
`[1,0]`. Rank-local allocations then refer to different GPUs from the
communicator/stream used for the same rank. CPU construction with such a
transport succeeds. Validate ordered devices, transport/runtime compatibility
and algorithm identity, not just count; retain an explicit mock-only path.

### R7 - P2: generic allocations are incorrectly attributed to HIP

`hipengine/core/memory.py:_runtime_device` hardcodes `Device("hip", ...)` for
any runtime with `get_device()`. `CudaRuntime` already has that method and uses
these shared allocation helpers. A real `CudaRuntime` with an injected CUDA
library produces a buffer labelled `hip:0`. `DeviceBuffer` also rejects a
correct CUDA device label. This is a shared architecture regression, not a
TP-only concern. Preserve backend-neutral attribution; no CUDA hardware
execution was performed by this review.

### R8 - P2: manifest hash omits physical row ranges consumed by the loader

`ShardManifest.to_dict()` serializes logical `axis_ranges` and row byte widths,
but not `RowSplitLayout.byte_ranges`. `materialize_slice()` consumes those
physical ranges. Swapping the two ranks' physical byte ranges while retaining
their logical ranges passes `validate_plan_coverage()`, keeps the identical
manifest hash, and changes rank 0's materialized bytes.

Either derive physical ranges from the serialized logical layout or include
them in the identity and validate their correspondence. Hashing a model string
does not close this layout identity hole. This is a consistency defect, not a
cryptographic hash collision.

### R9 - P2: partial graph-capture failure leaks instantiated executables

`scripts/tp_collective_bench.py:536-564` destroys captured graphs on exception
but omits the already-created executable handles. Inject failure while
instantiating rank 1: rank 0's executable was created but never destroyed.
Cleanup must cover every created graph and executable under its owning rank,
including invalidated/partially ended capture state.

### R10 - P2: the common KV resource contract remains unimplemented

`hipengine/distributed/kv.py` creates independent `KvClaim`/`KvClaimSet` classes
and sequential callback allocation. It neither produces `KVPoolPlan`/
`ResourceClaimSet`/`ResourceDelta` nor integrates the existing `ResourceLedger`.
A free-memory check and reverse frees are not scheduler-owned atomic reservation.
The required composite backend/claim boundary is still explicitly listed as
unimplemented in the updated campaign.

The geometry is also an estimate, not an actual backend pool plan: it assumes
equal K/V dimensions and four int32 metadata fields per token/layer.
`KVLiveSpans` actually has mode-specific page tables, counts, optional positions/
masks and dtype rules. `resolve_kv_geometry()` ignores `value_length`.
Use backend-owned pool/plane geometry, generations, lifetimes and all-rank
claims, including communication and recurrent/transaction allocations. Do not
certify this Packet 1 item complete from the current callback tests.

### R11 - P2: UUID extraction truncates binary UUIDs at NUL

`hipengine/core/hip.py:116-125` reads `bytes(uuid.bytes)` from a ctypes
`c_char * 16` structure field. Embedded NUL terminates the field value.
An injected successful HIP call writing `bytes(range(16))` returns length zero;
`device_get_uuid()` then raises instead of returning an identity. Read exactly
16 bytes or use an unsigned-byte array. Tests currently cover only the formatter.

### Other evidence boundaries

- The negative HIP peer-access observation is useful. It does not independently
  prove that BAR size and ACS are both necessary causal blockers or that changing
  both will enable this cross-root-port path. `parse_acs_entries()` treats source
  validation and direct-translated-P2P bits as blanket blockers; report raw
  controls and routing uncertainty instead. Do not advise weakening isolation
  as an established repair from this screen alone.
- `collect_display_load()` skips unreadable process FDs without recording
  incomplete visibility, and stops after the first DRM FD of each process.
  An empty result establishes no observed openers, not proof no compositor
  shares either card.
- `collect_devices()` assigns a deduplicated architecture list by rank rather
  than the selected HIP device index. Reordered/mixed device lists need actual
  per-device identities.
- A faster BF16 collective microbenchmark does not qualify BF16 transport as a
  model-level production prefill default. The campaign's default wording is
  premature while model numerical gates are absent.
