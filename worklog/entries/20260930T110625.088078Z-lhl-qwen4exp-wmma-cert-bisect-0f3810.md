# Bisected - the wmma certificate baseline moved twice, both decode-path promotions

## Summary

Completes the attribution left open by `20260930T102145` and refined by
`20260930T102357`: which commits moved the `wmma` 16-47 gate's baseline, making
the recorded certificate stop reproducing at HEAD.

**Two changes, both decode-path promotions, neither a kernel swap:**

| | commit | subject | teacher hash |
| --- | --- | --- | --- |
| start | `035185fb2` | (the recorded certificate) | `724d1bde44e23a14` |
| change 1 | **`c66db0264`** | perf: promote the decode dp4a linear to the production default | `9d9f3d4a7a7b1f7f` |
| change 2 | **`6c3c46b04`** | perf: promote DE-3 - the decode-shaped pack8 GEMV runs a 256-wide block at narrow projections | `e91c8bb18bc17106` |
| HEAD | `642d90e05` | | `e91c8bb18bc17106` |

HEAD's teacher hash equals the value after change 2, so **exactly these two
changes** lie in the range and there is no third.

**The systemic point.** This gate certifies a **prefill** route but measures its
drift over **128 teacher-forced decode steps**. Its baseline is therefore
decode-path arithmetic, and **any promoted decode-path arithmetic change
invalidates a prefill-route certificate without touching the route under test**.
Neither commit changed `wmma` 16-47. What moved is the measurement's baseline,
which is why the remedy is a re-gate rather than a revert.

## Validation

- **The probe was validated sensitive before any null was trusted.** At
  `035185fb2` the reduced protocol
  (`--case-id code-p512 --case-id general_en-p512 --decode-steps 24
  --repeat-runs 3`) returns teacher `724d1bde44e23a14` with `kl_max`
  **1.530440e-02**, reproducing the recorded certificate's max exactly, and at
  HEAD it returns `e91c8bb18bc17106`. The endpoints differ, so a bisect can
  resolve the boundary.
- Bisect 1 over `035185fb2..HEAD` (88 commits): last good `45a8f5690`, first bad
  `c66db0264`.
- Bisect 2 over `7dbc899f1..HEAD` (47 commits): last good `d49dc011c`, first bad
  `6c3c46b04`.
- Both probes run in a separate `git worktree` (`/tmp/bisect-wt`) because the
  working tree is shared, importing the worktree's `hipengine` via `PYTHONPATH`
  with the main venv's interpreter.
- Each change is consistent with the earlier engagement finding: the gate's
  engagement block counts the **prefill** selectors (`wmma_prefill`,
  `q4k_rowtile`) and covers neither decode route, which is why a genuine
  arithmetic change produced no visible difference there.

**Two hypotheses named in earlier entries are refuted and recorded rather than
dropped:**

- `a9a33dd88` (the dispatch cache-key fix) was named in `20260930T102145` as
  "the most direct explanation for a teacher-side change". The engagement
  comparison refuted it.
- `6c3c46b04` (DE-3) was named in `20260930T102357` as the leading candidate.
  **It is real, but it is the second change, not the first.**

Both were named on plausibility before the cheap decisive check was run - for
the first, a 30-second diff of the two artifacts' engagement fields; for the
second, the bisect itself.
