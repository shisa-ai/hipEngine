# Separate buffered SSE delivery from live decode timing

## Summary

Buffered SSE responses no longer report their final flush as decode throughput.
Live decode timing uses the first and last token-bearing events, excludes the
first chunk's tokens, and does not move the endpoint when done/usage events
arrive. Backend timing remains separate.

All six real Gemma SSE requests passed. Their generated IDs, visible content,
reasoning, and exact usage match the pre-change responses; explicit MTP still
reports that it ran.

## Changes

- `hipengine/server/api.py`: track first/last token counts and timestamps;
  suppress rates for unknown first counts, single chunks, completed first
  backend chunks split into channels, and known buffered replay helpers.
- `tests/test_integration_stream_timing.py`: five RED/GREEN regressions cover
  single-chunk flushing, first-chunk exclusion, terminal delay, missing counts,
  completed-chunk splitting, and precomputed chat fragments.
- `docs/API.md`: document stream-rate semantics, explicit breaker refusal versus
  automatic AR fallback, and the already-shipped Gemma generation controls.
- `benchmarks/results/2026-10-17-gemma-sse-timing.json`: retain exact requests,
  responses, code fingerprint, startup configuration, and per-row assertions.
