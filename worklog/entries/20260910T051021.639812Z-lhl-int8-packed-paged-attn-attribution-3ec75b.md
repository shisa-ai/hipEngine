# Attribute the packed multi-chunk slowdown to the paged prefill attention kernel

## Summary

Reviewer-ordered unit: capture kernel and HIP API timing on the corrected route
and find what accounts for the additional time. Answer, measured:
`qwen35_paged_full_attn_prefill_gqa_gate_bf16_kernel` is 91% of prefill device
time at 8 chunks, with a per-launch cost that grows ~quadratically in the
slab's end context where the algorithmic requirement is linear. No production
code changed in this unit.

## Changes

- `benchmarks/results/2026-09-10-w7900-int8-packed-paged-attn-attribution.json`
  (new): the attribution artifact with the per-slab/per-context tables, the
  device-bound fraction, the kernel-shape mechanism, and the escape hatches.
- `docs/QWEN38-27B-GFX1100-24GB-CAPACITY.md`: the KV-import section's
  "candidate (unprofiled)" replaced with the measured attribution.

## Validation

- Cache-only rocprofv3 (per the recipe recorded last unit:
  `HIPENGINE_COMPILER_VERSION_FILE` + `HIPENGINE_REQUIRE_CACHED_BUILD=1`),
  W7900 GPU0, shipping selectors, int8_per_token_head + FP32 scales,
  max_sequence_length 16,384, the same deterministic prompt as the
  import-removal unit. Both attempted configs completed (2048 and 8192 rows);
  bare rocprofv3 attempts stall in hipcc discovery and are documented as
  such.
- 8192 rows (8 chunks): prefill device time 121.385 s vs 121.862 s
  uninstrumented wall — 99.6% device-bound, so the slowdown is kernel
  efficiency, not host overhead and not copies.
- Per-slab segmentation on embedding launches (one per slab; the 7 decode
  steps identified separately):
  - paged attention: 16 launches/slab, per-launch 33.7 / 89.9 / 236.5 /
    442.9 / 842.9 / 1030.4 / 1218.3 / 3042.1 ms by slab context 1024..8192
    (~90x for 8x context; total 110.989 s = 91% of prefill)
  - every other family flat: ~1.25-1.34 s per slab (WMMA projections, GDN,
    norm, MoE, embedding), i.e. linear as expected
  - decode steps ~0.03 s each (7 steps; not a factor)
- 2048-row cross-check reproduces slab-1/slab-2 per-launch costs (33.7 /
  89.9 ms) and the same flat non-attention floor.

## Decisions

- **The mechanism is shape, not scheduling.** The kernel runs one block per
  (q_head, query row) that serially walks the whole visible context with 32-64
  threads, and its score buffer is dynamic LDS sized by the whole context
  (`(max_context_len + threads + head_dim) * 4` bytes in
  `qwen35_paged_full_attn_prefill_gqa_gate_bf16_spans`): ~4.6 KB at ctx 1024
  -> ~33.5 KB at ctx 8192 per block. Occupancy collapses as slab context
  grows, and the serial page walk cannot hide latency; per-launch cost goes
  ~context^2 and the chunk-outer route's total attention cost ~cubic in chunk
  count (matches the 6.8x wall from 4 to 8 chunks).
- **The layer-outer packed executor would not fix this.** Every schedule still
  attends over the full history per chunk; the parent's advantage is its
  kernel (WMMA bulk), not its loop order. Layer-outer remains the memory fix;
  the speed fix is kernel-level.
- **Escape hatches recorded, not taken:** AOTriton admission on
  transient-oracle layers (built, default OFF; its 2026-09-09 gate ran on the
  corrupted multi-chunk history and must be re-qualified on the corrected
  route), or porting the WMMA score-GEMM structure to the paged path.
