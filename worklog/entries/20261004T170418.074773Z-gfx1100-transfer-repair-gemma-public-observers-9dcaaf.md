# Repair native attention and device-greedy observers

## Summary

The transfer screen exposed two observer defects, not production execution
failures. The public attention observer counted only explicit registry variant
launches, while gfx1100's native Gemma profile requests no attention variants.
The workspace observer watched `runner.forward()`, while public greedy
generation calls `runner.forward_argmax()`.

The original model library substitutions did not exercise staged attention and
are invalid as staged-attention performance evidence. Corrected diagnostic
pairs explicitly request staged attention; shipping defaults are unchanged.

## Changes

- Observe successful native tiled, AOTriton and exact attention wrapper calls
  alongside explicit registry variants. Keep variant selection unchanged and
  restore every wrapped callable when the observation context exits.
- Observe the public device-greedy method, then copy the already-softcapped
  full-vocabulary logits for hashes and finite checks. Do not run the model or
  softcap again, change the returned token, or replace the sampler.
- Record the observer source SHA-256 in each output packet, including runs made
  while the repair is still uncommitted.
- Add CPU regressions for native invocation counts, failure containment,
  argument and return-value preservation, and restoration of instance method
  overrides. Full-vocabulary copies remain untimed correctness instrumentation.
