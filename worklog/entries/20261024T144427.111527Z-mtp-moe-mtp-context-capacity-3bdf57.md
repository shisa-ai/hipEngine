# Size MoE MTP prompt and draft caches from request capacity

## Summary

GGUF MoE MTP previously used a 95-row hidden slab and a separately capped
1,024-row draft cache. The adapter now derives capacity from request extent,
allocated target positions and the native verifier's declared capability.
Public validation passes 22 greedy calls and four sampled calls.
This is a correctness repair, not a speed claim.

## Changes

- Grow hidden and draft-KV slabs on demand, charging the resident pool before
  allocation and preserving the old slab if allocation fails.
- Clean up partial allocations and reject growth while a live sink or request
  still owns the old slab. Validate draft writes against allocated rows.
- Remove the adapter's 95-token capability limit. Explicit MTP requests with no
  candidate context room fail by name; automatic selection records its fallback.
- Select native split attention for long-context graph buckets and bound candidate
  depth to the deepest legal bucket. At transitions, ordinary decode advances
  the provider until speculation fits again instead of permanently disabling MTP.
- Repair the shared dense-KV allocator's value-allocation failure leak for its
  other callers; this adapter already uses grouped allocation rollback.

## Validation

- The parent independently ran the two graph and two MoE unit modules:
  103 tests passed. MoE-specific delegated affected bundle: 384 passed.
- The initial public sweep passed twice at 37/63/94/95/96/257, then caught an
  actual silent fallback at 1,023: a graph-bucket miss disabled MTP permanently.
  The repaired 22-call sweep covers 37/94/1021/1023/1024/1025/1100/1278/1279/1280/1531;
  every request runs MTP, repeats IDs and has no recoverable-failure record.
  Boundary requests use ordinary decode briefly and resume graph cycles.
- An injected 128-position capability limit refuses a 127-token explicit request
  with `MoePromptContextUnsupportedError`, contained to that request. The next
  37-token request reproduces its pre-failure IDs. Both runs close with zero
  tracked allocations. Evidence: `docs/testing/2026-10-24-moe-mtp-context-capacity/`.
- Default CPU run completed with two new boundary fixtures missing their backend;
  repaired focused MoE/native-cycle/graph bundle passes 190 tests, one GPU skip.
  Subsequent shared allocator RED/GREEN and MoE/native-cycle bundle pass 150
  tests, one GPU skip. No broad rerun is needed for these isolated repairs.

- Four sampled public calls at 94/1025, temperature 0.7 and seed 123, run native
  sampled MTP, repeat IDs and close without tracked allocations. Exact commands,
  source hashes and artifacts are in the evidence directory above.
