# Bind Qwen3.8 MTP plan to LLM and OpenAI routing

## Summary

Bind the model-plugin-owned Qwen3.8 Q4_K_M serving plan to the loaded LLM,
Generation-2 owner capacity, OpenAI capabilities, request routing, K0 reasons,
response metadata, and operator rollback. Broad dense inventory no longer
implies a default-safe route. The exact retained scope remains explicit-only;
`auto` and `enabled` both select K0 unless a future evidence row sets
`automatic_eligible=true`.

## Changes

- Add immutable resident-capacity identity to the serving key/evidence; the
  exact scope requires capacity C1 as well as realized group C1.
- Expose `resident_capacity` from the Generation-2 adapter and add generic LLM
  delegation to the model-plugin resolver. The dense GGUF generator supplies
  full cached artifact identity, backend/target, quant, profile/manifest,
  requested/effective KV, shape, sampler, horizon, and memory facts.
- Carry one plan through OpenAI queue grouping and realized-route selection.
  Plan fingerprints prevent incompatible request groups from coalescing.
- Expose `certified_explicit_scope` in capabilities, use the same fingerprint
  for auto/explicit route decisions and rollback, and require
  `automatic_eligible` rather than `supports_default_mtp` for defaults.
- Keep legacy operator-selected explicit compatibility when an engine has no
  typed resolver; track removal of the broad boolean in `docs/REFACTOR.md`.
- Add server RED/GREEN coverage for exact plan propagation, context K0,
  auto/enabled K0, generic-dense default rejection, and rollback identity.
- Publish compact S1 evidence and update API/campaign/changelog documentation.
