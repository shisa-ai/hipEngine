# Journal completed speculative checkpoints and omit append-only KV copies

## Summary

Implemented a shared completed-checkpoint journal and adopted it for PARO provider/target rollback. Target backup copies mutable recurrent/hidden state and cursor metadata, not the append-only KV prefix. Public state-restoration checks pass. On Framework Desktop / Radeon 8060S, packed Qwen3.6-35B-A3B ParoQuant W4, BF16 KV and one request/candidate, natural-suite decode improves 64.45 → 64.58 tok/s and 4K decode 46.16 → 47.03 tok/s, confirmed at +0.31% and +1.90%. This is a within-MTP copy comparison, not an MTP/AR speedup.

## Changes

- `SpeculativeStateJournal` in the existing transaction owner publishes a restore only after capture succeeds, rolls back in reverse order, attempts both owners even if one restore fails, retains failed restores for retry, and clears completed/committed snapshots.
- PARO proposal captures its provider into the journal; target execution captures its spare-slot mutable state with `kv_rows=0`. The verifier explicitly appends KV at the root cursor and hides rejected suffixes through committed metadata, so immutable prefix bytes do not need a second copy. Provider/target arithmetic is unchanged.
- Rollback before target capture can no longer copy a stale spare slot. Repeated outer rollback after an inner restore is idempotent; failed restore cannot recycle the proposer. Additional consumer migrations remain on the active matrix.
- A live public failure-injection test compares mutable state, device/host cursors, provider hidden/KV and live target KV after failures following target verification or provider update.
