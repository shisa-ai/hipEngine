# P6 native-sampling coverage is blocked by a real defect: the packed native sampler has capacity 0

## Summary

P6's coverage list names "native and host sampling". The host half is covered and
asserted. This unit added the native arm, and it did not produce a green result —
it produced a defect. That is the useful outcome, and it is recorded rather than
worked around.

Two distinct behaviours, both measured:

1. **Without `HIPENGINE_QWEN35_NATIVE_SAMPLER`**, a native-shaped request (temperature
   1.0, `top_k=20`, seeded) **silently falls back to the host sampler**: host route
   delta **+3.0**, native route delta **0.0**. So the native mode is not reachable by
   request shape at all. `_native_gpu_sampler_requested()` (`qwen35_gguf.py:10206`)
   reads that environment variable, and with it unset `native_gpu_available` is False
   for every request.

2. **With the flag set**, the request fails before it can produce a token:

   ```
   WARNING: REQUEST_FAILED: POST /v1/completions stream status=400
     code=invalid_request message=packed native sampler row 0 exceeds capacity 0
   ERROR:   REQUEST_FAILED: POST /v1/completions stream status=500
     code=generation_failed message=generation failed: engine service command timed out
   ERROR:   REQUEST_FAILED: POST /v1/completions stream status=500
     code=generation_failed message=generation failed: engine service is closed
   ```

   The sampler then reports **HTTP 200 with an empty completion** (0 characters) and
   the resident route counters reset — which is why the host counter delta reads
   **-3.0** in that run. The 200-with-empty-body is the aftermath of the closed
   engine, not a successful request.

So the packed native sampler is never sized for this route. Enabling the documented
flag does not enable a working sampler; it breaks the engine for the rest of the
session.

## Changes

- `_native_sampling_payload()`: a payload that *should* select `GPU_SAMPLE`
  (temperature above zero, `top_k` within `_MAX_NATIVE_GPU_TOP_K`), seeded for
  determinism.
- `_sampling_arm()`: the arm body factored out of the host arm so native and host are
  measured identically and differ only in the payload that selects the route.
- `_evaluate_sampling_gate(record, label=..., skipped_reason=...)`: a skipped gate
  returns `passed: true, skipped: true` **and** a `blocker` naming the defect plus a
  `detail` carrying the reproduction command. A skip is visible in the artifact
  instead of being inferred from a missing key, and it cannot silently count as
  coverage.
- `--native-sampling-arm` (default **off**): the arm is a diagnostic, not part of the
  default proof, because running it closes the engine and would contaminate the
  gates that measure the resumable yield.
- `NATIVE_SAMPLING_BLOCKER` and `NATIVE_SAMPLING_SKIP_REASON` record the defect and
  the exact reproduction command next to the gate.
- `docs/SERVER-DIRECT-PARITY-ROADMAP.md`: the coverage table's native row now states
  the defect and the reproduction command instead of "not asserted".

## Next

- **Fixing this is out of scope for P6.** The resumable yield is the deliverable and
  it is unaffected: the default proof passes with the native arm off. Sizing the
  packed native sampler for the GGUF resident route is a separate unit, and until it
  lands P6's "native sampling" item cannot be asserted.
- If that unit lands, flip `--native-sampling-arm` on in the retained proof and the
  gate becomes a real assertion with no harness change.
- Remaining P6 coverage (task #26): a longer survivor output than the current
  48-character reference.

## Honest limits

- The native arm does not distinguish "capacity was never allocated" from "capacity
  was allocated as zero for this shape". Both present as `exceeds capacity 0`; the
  fix differs.
- I did not determine whether the empty-text 200 is a deliberate degradation or an
  unhandled error path. It is recorded as observed behaviour, not diagnosed.
- The first native run (flag off) shows only that the host sampler served the
  request. It does not show the native sampler is otherwise correct.
- The `-3.0` host delta is a counter reset, not a decrease. I inferred the reset from
  the negative value plus the closed-engine errors; I did not read the counter
  lifecycle directly.
