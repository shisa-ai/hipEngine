# c8 stage-split measurement: cliff is Q5_K/Q6_K linear fallback, not GDN/full-attn

## Summary

Step 1 of the width-adaptive GEMM plan (`docs/CONCURRENCY2.md` "Next steps") —
measure the c4/c5/c8 stage split to confirm/refute the derived "non-FFN cliff"
(~23 ms at c4 → ~84 ms at c8). The doc's specific hypothesis was a **GDN /
full-attention variant-coverage gap (D3 violation)**. The measurement **refutes
that specific hypothesis** but confirms the broader D3-coverage lens, with a
corrected attribution that changes which fix to pursue.

Instrument: `rocprofv3 --kernel-trace` census of the packed-decode graph replay
(`scripts/gguf_packed_ar_rocprof.py`, prebuilt `.so` + `require_cached` per the
profiling rule), W7900 / gfx1100, Qwen3.8-27B-Q4_K_M, p512. c8 trace from the
prior session; c4 trace + c1 reference measured this session. **The
`scripts/tmp_c8_stage_timing.py` path is a dead end by construction**: the GPU
stage timers are wired only into `step()` (c1) and
`verify_target_blocks_batch()` (MTP verifier), not the packed-decode graph, so
it returns empty for c4/c5/c8 regardless of parameters. The kernel trace is the
correct instrument.

Measured family breakdown (route_check passed, decode window only):

| stage (census family) | c1 (31.5 ms) | c4 (39.3 ms) | c8 (109.8 ms) |
| --- | ---: | ---: | ---: |
| dense_projection (Q4_K rowtile + any Q5/6 rowtile) | 23.7 (75%) | 27.4 (70%) | 26.3 (24%) |
| **Q5_K/Q6_K wmma_prefill (unclassified bucket)** | 0 | **0** | **71.7 (65%)** |
| linear_attention_state (GDN SSM core) | 0.9 | 5.2 | 8.1 |
| full_attention_core | 2.6 | 2.0 | 1.9 |
| norm_residual | 1.6 | 4.6 | 1.7 |

- **full-attention is flat** across c1→c8 (2.6/2.0/1.9 ms). Not a cliff.
- **GDN SSM core rises** (0.9/5.2/8.1 ms) but only to ~8 ms (7% of c8) — real,
  minor.
- The **70.5 ms c4→c8 jump is almost entirely one thing**: the Q5_K/Q6_K padded
  WMMA prefill appears **only at c8** (71.7 ms, 65%) and is **zero at c4**.

**Attribution correction (the reviewer point).** The 71.7 ms bucket is cut by
**quant family**, not stage. It is the **Q5_K/Q6_K linear layers**, which span
FFN, GDN, and attention alike. GGUF tensor mix (ggml type 12=Q4_K, 13=Q5_K,
14=Q6_K):

| role | count | quant |
| --- | --- | --- |
| ffn_gate, ffn_up | 65 each | all Q4_K |
| ffn_down | 32 / 33 | Q4_K / Q6_K |
| ssm_out (GDN output proj) | 48 | Q5_K |
| attn_qkv | 24 / 24 | Q4_K / Q6_K |
| attn_v | 8 / 9 | Q4_K / Q6_K |

So the prior phrasing "the cliff is the attention projections" (and the doc's
"non-FFN = GDN/full-attn") both **mislabel** the bucket: gate/up are all Q4_K
(not in it), ssm_out (GDN) and most of qkv/v (attention) and a third of ffn_down
(FFN) **are** in it. The honest statement: **the cliff is in the Q5_K/Q6_K
linear layers, which span FFN, GDN, and attention.**

**Mechanism (confirmed in source).** Decode rowtile width caps per quant family:

| quant family | decode rowtile cap | source |
| --- | --- | --- |
| Q4_K | 8 (16/32 uncommitted) | `launch_q4_dense_rowtile` |
| Q6_K | 4 or 6 | `gguf_q6_k_t16_gemv.hip:2143,2179,2217,2285,2325` |
| Q5_K | 4 | `launch_q5_dense_rowtile_col4`, `gguf_t16_selected_gemv.hip:6167` |

The engine's **effective width coverage is the MINIMUM across the quant
families present** — for this artifact that is **4** (the Q5_K cap). Every
Q5_K/Q6_K linear layer above width 4 falls to the padded WMMA prefill (computes
64 rows to deliver M). That is exactly why c4 is the throughput peak and c5
collapses.

**Launch-count check (closes the prefill-contamination caveat).** The c8 decode
marker window (872 dispatches) contains **112** Q5_K/Q6_K wmma_prefill launches
(64 Q6_K = 51.69 ms + 48 Q5_K = 19.98 ms = 71.67 ms), matching the predicted
~114 (33 ffn_down + 48 ssm_out + 24 attn_qkv + 9 attn_v; the 2-launch gap is
64 decode layers vs block_count 65). Q5_K = 48 matches ssm_out exactly. So the
71.7 ms is decode-only, not p512 prefill leakage, and ~71.7 ms / 112 calls
≈ **0.64 ms/call** sits in the measured padded-WMMA range.
