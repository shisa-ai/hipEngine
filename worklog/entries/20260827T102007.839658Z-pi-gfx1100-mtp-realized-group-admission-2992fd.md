# Resolve speculative MTP at realized physical group

## Summary

Closed the first shared realized-group admission seam without enabling any new
backend capability or automatic cell. Request-time C1 serving plans were copied
into the HTTP queue; when compatible requests later formed C2, the batcher only
compared C2 to the stale C1 key and selected K0 without re-running the model
plugin resolver. The queue now resolves immutable model evidence at the actual
physical width before backend mutation.

## Changes

- Updated `resolve_speculative_mtp_serving_plan()` to select an exact qualified
  row among multiple C1/C2/resident-capacity entries for one artifact. The prior
  first-row lookup made every later same-artifact width unreachable. On a miss,
  the nearest row supplies a deterministic first failed axis.
- Added `_realized_model_serving_plan()` and queue-group integration so automatic,
  explicit, and typed-K0 speculative intent is re-resolved after compatible
  requests are physically grouped and before generation starts.
- Added RED/GREEN coverage for a promoted request-time C1 plan becoming one
  independently qualified C2 model call, with C2 evidence/fingerprint telemetry
  and no AR/legacy call.
- Added common owner tests for fail-closed unqualified C2 -> one K0 AR batch,
  C1 -> C2 -> C1 request/plan identity, and MTP -> K0 -> MTP cycle boundaries.
- Updated the active campaign punchlist with the audit result and the remaining
  model-specific controlled-streaming/state/KV/physical-telemetry gates.

No gfx1100 package capability, model evidence row, policy default, or performance
claim changed. Current C2 remains K0.
