# Multi-column GDN prefill promoted: 1.34x-1.68x measured, and the rejection it was buried under was a misattribution

## Summary

**A retained performance win, and it was buried under a recorded rejection that its own
artifact contradicted.** The multi-column GDN prefill route is **1.34x-1.68x faster** than
the DPP route it replaces (4.556 -> 3.118 ms at 1K tokens, and faster at every shape from
512 to 4096), at **NMSE ~1.8e-14** - fp32 round-off. It is now the production GDN prefill
selection for `gguf_ud_q4_k_xl`; the DPP route stays registered as the strict fallback.

The route was recorded in the ledger's section-7 "tried and not retained" table as failing
the Japanese complete-EOS task. **It does not fail it.** That row combined two candidates
(`R01` and `R02`) under `R01`'s evidence entry; `R02`'s own artifact states it *"does not
reproduce the single-column Japanese speculative-decoding error"* and passes every declared
numerical limit. `docs/REFACTOR.md` carried a removal instruction whose stated trigger was
"the numerical or operation-complete performance gate rejects it" - **that trigger had not
fired.**

## Validation

- **Performance**: matched warm medians, 12-20 reps per arm, both arms built from the
  same source with `-DHIPENGINE_QWEN4_GDN_DPP=1` and differing only in
  `-DHIPENGINE_QWEN4_GDN_MULTI_COLUMN=1`. 512: 1.864 -> 1.112 ms (1.6756x); 1024:
  4.556 -> 3.118 ms (1.4611x); 2048: 10.583 -> 7.706 ms (1.3733x); 4096:
  22.799 -> 16.997 ms (1.3413x).
- **Numerics**: NMSE 1.795e-14-1.847e-14 on the core output and 7.2e-15-7.6e-15 on the
  recurrent state, stable across all four shapes.
- **Production gates** (already run against this variant on this hardware class):
  short gate mean KL 1.0724e-04 with 593/594 top-1; depth gate passing every declared
  limit (mean 8.92215e-05, p95 4.206676e-04, p99 1.2666802e-03, max 4.4548289e-03,
  top-1 777/780 = 99.615%).
- **Tests**: `pytest tests/ -k "profile or recovery or gdn or qwen4exp"` is green
  (exit 0, no failures).
- `python3 scripts/worklog.py check` passes.

## Two mistakes I made in this unit, both caught by tests

**First**: I promoted the route by editing the `dpp` branch of `_production_selections`
and did not touch the arithmetic-recovery path's `inactive` set. That path deactivates
tiled variants **by name**, so the recovery UD profile started selecting a tiled owner it
must not use. `test_ud_profile_recovers_arithmetic_but_keeps_exact_owners` caught it.

**Second**: having fixed that, I wrote a test asserting the manifest selects the
multi-column route, and it failed - correctly. The production plan is built with
`dpp=quant == "gguf_ud_q4_k_xl"` and `recovery=quant == "gguf_ud_q4_k_xl"`, **the same
condition**, so the recovery pass replaces every `dpp=True` tiled selection with its exact
owner before the manifest is observed. **The `dpp` branch is inert.** The live selection is
the `HIPENGINE_QWEN4_EXP_GDN_TILE16_VARIANT` env binding, consulted by the runner inside the
colwarps/tile16 gate. My manifest assertion was checking a branch that cannot be reached.

That second finding matters beyond this unit: **the manifest's GDN prefill row does not
describe what runs for the UD quant.** A reader auditing the default from the manifest
would conclude the exact owner is selected, which is true, and would not learn that the
runtime env binding overrides it inside the tile16 gate. The new test asserts the env
binding, which is the thing that actually decides.

## Why the win was invisible

The route was not merely unpriced - it was **recorded as rejected**. Three things had to
line up for that to survive, and they did:

1. **Two candidates on one ledger row** ("Journey tiled/DPP (`R01`) / multi-column (`R02`)
   restorations"), inviting them to be read as one item.
2. **One evidence citation for both** - `20260914T201148`, which is `R01`'s entry. Nothing
   pointed a reader at `R02`'s artifact.
3. **A shared-looking failure phrase.** "Japanese complete-EOS" is `R01`'s failure; `R02`
   mentions Japan only to say it does **not** reproduce the error.

A reader following the row's own citation never reaches the artifact that contradicts it.

## Honest scope

One host (`gfx1151` - **not** the W7900/gfx1100 AGENTS.md names as default, so these
figures are not comparable to a gfx1100 lane), one quant, one shape family, GDN prefill
scope only. The route is **not bit-exact** to the DPP incumbent; it is admitted on the
production numerical envelope. Its one task finding is shared with the strict arm and is
recorded rather than dismissed.
