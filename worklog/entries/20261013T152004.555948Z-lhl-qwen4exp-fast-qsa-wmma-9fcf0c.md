# Qwen4Exp fast profile WMMA QSA prefill attention

## Summary

The `fast` profile's prefill attention for the 12 sparse-attention layers
now runs on a WMMA kernel. Canonical 12-case protocol (Radeon 8060S /
gfx1151, `UD-Q4_K_XL`, chunk 4096): prefill 707.3 / 811.4 / 825.0 to
**728.9 / 868.4 / 1002.2 tok/s** at p512/p1024/p4096, 12/12 cases positive,
decode unchanged; 2.38x / 2.63x / 2.99x the same boot's `production` run.
The two attention kernels cost 112 ms per code-p4096 prefill against about
995 ms for the scalar FP32 pair they replace, and the kernel total is
4049 ms (`production` 12186, gufo 2373).

## Decisions

- **Port gufo's `WmmaCausalAttentionKernel` unchanged, adapt around it.**
  It is written for exactly this model's geometry (24 x 256 query heads, two
  KV heads, four-token selection blocks). hipEngine differs in its cache
  (paged BF16 against gufo's contiguous F16) and its selection form
  (position lists against per-query block bitmasks), so two small hipEngine
  kernels bridge those: `PagedKvToF16Kernel` and `SelectionMaskKernel`.
- **Gate stays separate.** The kernel can apply the sigmoid output gate; the
  launch passes no gate and the existing gate kernel runs after it, so the
  dense and sparse windows share one unchanged tail.
- **Whole-context regather per layer per chunk.** 0.3 ms per layer at 4096
  tokens. An incremental per-layer F16 cache is recorded in
  `docs/REFACTOR.md` for long multi-chunk contexts.
- **ABI deviation, recorded.** The gather addresses the paged cache by
  `(block_table, context_len)` rather than `KVLiveSpans`, like the existing
  flash prefill kernel. It is valid only for a dense, non-evicting policy;
  `docs/KERNELS.md` and `docs/REFACTOR.md` say so, with a spans-based gather
  as the condition for any wider use.
- **Selector plus manifest rows.** `HIPENGINE_QWEN4_EXP_QSA_WMMA` is a fast
  selector; the fast plan's sparse-prefill and dense-QSA rows name the
  kernel.
