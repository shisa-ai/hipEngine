# gfx1151 fp16-state verify-capture decode_order prefill dispatch

## Summary

Wires the fp16-state decode_order row-state writers (added in the
20260820T065950 worklog entry / commit 497dab0be) into the verify-capture
prefill GDN path. The previous fail-closed guard in
`_run_linear_attention_prefill_layer_rows` raised when the fp16 flag was
combined with `HIPENGINE_GGUF_VERIFY_CAPTURE_PREFILL_GDN`; the fp16 kernels now
make that combination safe because the recurrent-state and row buffers are
already half-sized under the flag. Strict path stays byte-identical (fp32
identity templates selected when the flag is off).

## Changes

- `qwen35_gguf_runner.py`: removed the fail-closed guard; added module-level
  `_gdn_decode_order_state_rows_kernel()` and
  `_gdn_decode_order_segments_state_rows_kernel()` helpers (mirroring the
  existing `_gdn_decode_gate_kernel` pattern) that select the fp16-state writer
  under `HIPENGINE_GGUF_FP16_RECURRENT_STATE` and the strict FP32 wrapper
  otherwise; the segments/non-segments dispatch in the verify-capture branch
  now calls those helpers. Imported the two fp16 wrappers.
- `tests/test_qwen35_gguf_gdn_prefill_routing.py`: CPU test that the two
  helpers select the fp16-state wrappers under the flag and the FP32 wrappers
  without it.
- `docs/REFACTOR.md`: the decode_order fail-closed guard is removed; the
  remaining fp16-incompatible writers (chain-journal output/snapshot fusion,
  MTP tree/chain verifier, non-compact-peer GDN_PREFILL_MODE) stay gated.

## Validation

- gfx1151 e2e (`/tmp/e2e_fp16_state_smoke.py`, Qwen3.8-27B Q4_K_S): strict vs
  fp16 greedy over 16 decode steps, identical=True, top-1 agreement 1.000,
  no NaN after the runner edits.
- `tests/test_qwen35_gguf_gdn_fp16_state.py` (5 tests) + strict decode-order
  state-rows oracle tests pass on gfx1151.
- `tests/test_qwen35_gguf_gdn_prefill_routing.py` (incl. new helper test),
  `test_qwen35_linear_attn_gdn_plan.py`, `test_qwen35_gguf_gdn_session_mode.py`
  pass.
