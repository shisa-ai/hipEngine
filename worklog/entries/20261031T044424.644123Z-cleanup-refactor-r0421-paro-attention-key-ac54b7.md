# Separate PARO's batch-context attention contract from GGUF's key

## Summary

PARO no longer pins its registry-backed paged KV/attention resolutions to
`hip_gfx1100`. The batch-context decode route now resolves a distinct contract
name, `bf16_context_batch_c1_exact_paro_spans`, against the backend the state
actually executes on. The shared `context_batch` key and every GGUF route are
unchanged: on gfx1151 it still resolves the fixed256 body through the existing
backend override.

Both kernel bodies, the `KVLiveSpans` ABI, the build family, and the packed
prefill schedule are untouched. This is a route-identity change, not an
arithmetic one.

## Changes

- `hipengine/dispatch/kv.py`: new `PagedAttnDecodeKind.CONTEXT_BATCH_C1_EXACT`
  (`context_batch_c1_exact`) and its BF16 route to
  `bf16_context_batch_c1_exact_paro_spans`. `CONTEXT_BATCH` is untouched.
- `hipengine/kernels/hip_gfx1100/attention/paged_attn_decode.py`: one
  registration entry mapping the new variant to the existing
  `qwen35_paged_full_attn_decode_context_bf16_batch_c1_exact_spans` callable.
  No new symbol, library, or build family; the gfx1151 alias pass therefore
  registers the same callable under `hip_gfx1151`, and the variant is
  deliberately absent from `_GFX1151_OVERRIDES`.
- `hipengine/kernels/hip_gfx1151/__init__.py`: comment-only. The override now
  states it is the GGUF short-context route and names PARO's separate contract.
- `hipengine/runtime/qwen35_paro.py`: removed `_PAGED_KV_REGISTRY_BACKEND`. All
  four registry-backed paged call sites (paged KV write, INT8 split-K gate
  decode, INT8 prefill, batch context decode) take
  `self._paged_kv_backend()`. An explicit backend identity is used verbatim and
  never re-detected; the constructor default `"auto"` resolves once per state
  and caches. The batch-context site selects `CONTEXT_BATCH_C1_EXACT`.
- `hipengine/runtime/qwen35_paro_runner.py`: the three production
  `Qwen35ParoDecodeState` construction sites (linear materialize, full
  materialize, prefill scratch owner) pass `backend=self.backend`.
- Tests: `tests/test_unit_kv_dispatch.py` gains the both-backend owner matrix.
  `tests/test_unit_qwen35_decode_state.py` replaces the constant assertion in
  the pin regression with a behavioural one: on the gfx1151 key PARO launches
  the c1-exact leaf and never the fixed256 leaf. New nodes cover both backend
  identities, explicit-versus-lazy-auto binding, all four paged call sites, and
  runner constructor propagation.
