# Widen Inkling production text prefill blocks

## Summary

Increase production Inkling text prefill blocks from 64 to 256 tokens on gfx1100. Warm same-process tests reproduced the latency gain and preserved first-token logits and output IDs across block widths.

## Changes

- Raise the internal prompt block cap. Strict, one-token decode, and prefill with external image embeddings retain their existing schedules.

## Validation

- `epyc`, Radeon Pro W7900 (`gfx1100`), HIP `7.2.53211-3d9ef42`, original `thinkingmachines/Inkling-2-Mini` revision `ed40e7da625f594fc9c4990f5f66be24873c22d7`, production `inkling2_mixed`, FP32 KV, baseline `9a7a2ed28` with the local width change. `PYTHONPATH=. OPENBLAS_NUM_THREADS=1 HIP_VISIBLE_DEVICES=0 HIPENGINE_EXECUTION_PROFILE=production .venv/bin/python -u /tmp/hipengine-inkling2-prefill-ab.py prefill-widths`: 64/128/256 produced identical logits and generated IDs at 42, 512 and 1,537 input tokens. Greedy ordinary single requests, 8/128/8 output tokens, respectively. The 1,537-token prompt wrapped the local cache; one run per width measured 20.363 / 20.250 / 19.299 s to first token.
- `width-confirm` on the same driver: three interleaved warm runs per arm at synthetic 512 input / 128 output. Median time to first token was 6.516 vs. 6.262 s (3.90% lower), with ranges 6.504–6.544 and 6.236–6.312 s. Decode medians were 15.048 and 15.078 tok/s. The default path ran two 256-token blocks; the 64-token control ran eight. Logits and IDs matched exactly.
- Separate fresh-process `width-peak64` / `width-peak256` diagnostics sampled the total device at 25 ms intervals and measured 18.691 vs. 18.793 GiB peak (104 MiB more). In that single run per process, first-token latency was 6.524 vs. 6.774 s; the repeatable warm gain does not establish a fresh-process gain. Public packed DSpark at 67 input / 8 output tokens used a single prompt block, with exact previous output IDs and seven proposed, seven accepted, one target block.
