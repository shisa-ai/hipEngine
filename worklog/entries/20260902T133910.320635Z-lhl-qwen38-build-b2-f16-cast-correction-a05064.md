# Qwen3.8 B2 corrects FP16 cast bit storage

## Summary

B2's first model-level numerical gate exposed and corrected a device-cast bug.
The kernel stored `static_cast<uint16_t>(half_value)`, which numerically
converted FP16 values to integers rather than preserving their IEEE-half bits.
The host-staged sibling tests bypassed that kernel and could not detect the
bug. After changing the destination to `half_t*` and assigning the half value
directly, all ten canonical prompt-tail full-logit rows are bit-identical to
the BF16 fallback. The previous wall screen is invalid for retention and must
be rerun; no B2 performance result is retained yet.

## RED/GREEN

New device test:
`tests/test_gguf_k_t16_dense_f16_activation_prefill.py::test_device_bf16_to_f16_cast_preserves_ieee_half_bits`.
RED observed bits `[0,0,0,0,0,0,1,17,255,65535]` where the host BF16→FP16
oracle expected `[54856,49920,48384,32768,0,11880,15872,19568,23544,31744]`.
Examples: `-3.5→0`, `17.75→17`. GREEN passes exact FP16 bit equality over
negative, signed-zero, fractional, and large finite values.
