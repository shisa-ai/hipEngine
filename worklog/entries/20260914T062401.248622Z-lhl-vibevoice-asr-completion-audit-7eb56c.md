# VibeVoice ASR completion audit: correctness and benchmark gaps

## Summary

Review of the completion claim at `d5425739ec8a0165bcaf22b7d3f3b58796bf8e8c`.
The tree implements a torch-free short-recording HIP pipeline, but does not
complete `docs/MODEL-VIBEVOICE-ASR.md`. The historical timing measurements
are evidence for one diagnostic workload; their protocol does not establish
matched-input correctness or a qualified production speed win.
This entry corrects the completion interpretation in
`20260914T002829.478265Z-lhl-vibevoice-asr-prefill-hipblaslt-7f7c12.md`
and the timestamp/numerics interpretation in the earlier speed entry.

## Changes

- Review only; no runtime, tests, benchmark rollups, or historical entries edited.
- P1: `greedy_generate` executes another forward after emitting the final
  requested token. Neither `push_token` nor `forward_layers` validates the
  position against cache/RoPE capacity. With a two-row prompt, capacity two,
  and one requested token, the function forwards position two. Device cache
  copies and RoPE reads consequently address outside their allocations.
  Validate positions and generation budgets before device work, and stop
  before the unused final forward.
- P1: `vibevoice_asr_bench.py` does not compare the same model inputs. HIP
  reuses NumPy noise; torch draws new, unseeded acoustic noise on each repeat.
  HIP builds its prompt with the original duration while torch receives
  already-padded PCM and derives duration from that array. For 11 seconds,
  these are 11.00 and 11.07 seconds. Torch also runs its feature processor
  again. The timestamp difference cannot be assigned to BF16 arithmetic.
  HIP prompt tokenization is outside its timer while torch processing is
  inside; the script has no explicit discarded warmup despite the artifact's
  "after warmup" description. Match processed PCM, prompt IDs, masks, recorded
  noise, timing boundaries, and per-repetition output before republishing.
- P1: correctness coverage is overstated. The Qwen2 GPU suite loads the CPU
  LM fixture directory, not `vibevoice_asr_gpu`. Both fixtures' 16-token
  continuations are only `assistant\n[{"Start":0,"End":4.0,"Speaker`, without
  transcript content. Of seven encoder tests, one compares against the
  torch-GPU fixture; seven passing GPU tests are not seven torch-GPU fixture
  comparisons. First-position relative max error and prefix argmax checks
  do not supply calibrated full-logit KL mean/tails/max, category quality,
  determinism/isolation, or BF16-relative production gates. Extend the
  teacher-forced captures through content and qualify the default arithmetic
  paths; bit identity is not the promotion criterion.
- P1: runtime integration and required dispatch contracts are absent. There
  is no VibeVoice model/generator plugin; the entry point is a script. Runtime
  modules import backend kernels directly and attention uses contiguous KV
  plus context length rather than `KVLiveSpans`. `_prefill_gemm` is unused
  in the Qwen2 runner: it is not a registered/reachable strict fallback for
  `_prefill_gemm_lt`, which is unconditional and fails if hipBLASLt cannot
  supply an algorithm. An unused helper does not substantiate the worklog's
  registered-fallback claim. Add model/registry integration and ABI-compliant
  attention with selected/fallback manifests.
- P1: chunk carry is missing implementation, not just unmeasured equivalence.
  `_encoder_forward(chunk_tail=...)` ignores its argument; causal prefixes
  remain zero and `forward` processes the entire waveform. Stateful chunk
  equivalence is explicitly step 3 in the model doc, hotwords/structured
  parsing step 4, and production qualification precedes tuning in step 5.
  The model plan does not exempt these from a full implementation. The
  prefill wrapper also rejects contexts above 16,000 positions. Implement
  chunk state, boundary/masking tests and recording reset, and declare the
  actual context limit until larger contexts have a supported path.
- P2: E2E output extraction uses the last occurrence of the ordinary word
  `assistant` in prompt-plus-output text. A transcript containing "my
  assistant called" loses its JSON prefix. Both benchmark lanes duplicate
  this extraction, so the comparison can conceal the same corruption.
  Decode generated IDs separately and validate the structured schema.

- CPU-only control reproduction using the actual generation function, with

  ```python
  from unittest.mock import patch
  from types import SimpleNamespace
  import numpy as np
  import hipengine.runtime.vibevoice_qwen2 as q
  calls = []
  r = SimpleNamespace(
      max_context=2, spec=SimpleNamespace(hidden_size=1), reset=lambda: None,
      prefill_rows=lambda buf, rows, pos: calls.append(('prefill', rows, pos)),
      runtime=SimpleNamespace(memcpy=lambda *args: None),
      _hidden=SimpleNamespace(ptr=1),
      logits_argmax=lambda: (np.array([0., 1.]), 1),
      embed_row=lambda t: np.array([1.]),
      push_token=lambda row, pos: calls.append(('push', pos)),
      forward_layers=lambda pos: calls.append(('forward', pos)))
  with patch.object(q, '_upload', return_value=SimpleNamespace(ptr=1)), \
       patch.object(q, 'free'):
      assert q.greedy_generate(r, [np.array([1.])] * 2, max_new_tokens=1) == [1]
  assert calls == [('prefill', 2, 0), ('push', 2), ('forward', 2)]
  ```

  array length and formats two decimals; local model source at
  `modeling_vibevoice_asr.py:375` samples acoustic scale/noise on inference.
