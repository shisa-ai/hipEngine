# Qwen3.8-27B specdec optimization campaign: transferable Muse Glimmer wins + DSpine/EAGLE-4 comparison

## Summary

Created docs/campaigns/QWEN38-27B-SPECDEC-OPTIMIZATION-CAMPAIGN.md (status:
current). It records (1) which Muse Glimmer long-context optimizations transfer
to Qwen3.8-27B and (2) the evaluation case for two external drafters — DSpine
(Tencent) and EAGLE-4 (Eagle AI) — against the shipping native MTP and the
rejected DFlash2. Plan/evidence register only: no DSpine/EAGLE-4 code is
implemented, and external speedups are vendor measurements on B300/MI355X-class
hardware, explicitly not hipEngine rows.

Key grounded points:
- Baseline (existing closed campaigns): Qwen3.8-27B Q4_K_S gfx1151, AR ~13.1
  tok/s, MTP B3 23.85 tok/s (1.78x AR); DFlash2 rejected at 8.85 tok/s (0.66x
  AR), a cost gap (drafter forward ~96 ms/cycle, verify cost, rowtile admission
  cliff at 4 rows), not acceptance.
- Transfer table: host sampler penalties + Q6 rowtile hoist are shared/free;
  draft head single-wave, non-causal WMMA attention, verify graph, large-chunk
  inject need porting and map onto the DFlash2 cost gaps; the budget finding
  (acceptance-driven optimum) is methodology.
- DSpine: parallel drafter with adjacent causal injection; Apache 2.0;
  Qwen3.8-27B-DSpine-b16 weights (5-layer, 8192 window) use DSpark dynamic
  verification + ReplaySSM for the linear-attention state. Qwen3-8B acceptance
  table: DFlash 5.92 / DFlash2 7.55 / DSpine 7.83 (T=0 avg).
- EAGLE-4: single-layer feature drafter; EAGLE-Harness (cost-aware budget) and
  Efficient LM Head independently mirror our budget + draft-head findings.
  Matched Qwen3.8-27B vendor table (4xB300): EAGLE-4 3.59x vanilla / 1.28x
  DFlash2 at 1 request; MI355X ROCm port exists. Source-available license
  restricts vendoring — treat as baseline + idea source, not a dependency.
