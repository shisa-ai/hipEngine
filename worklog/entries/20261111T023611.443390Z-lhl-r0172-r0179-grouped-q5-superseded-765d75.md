# Close R0172/R0179 grouped-Q5 as superseded by production target WMMA/source-MMQ precedence

## Summary

Close R0172 (public grouped-Q5 C8/R8 validation) and R0179 (public grouped-Q5 R6
validation) as gates no public route can clear on the dense gfx1100 artifact.
The grouped-Q5 owners (`_Q5_DENSE_ROWTILE_GROUPED_ROWS8_BF16` /
`_Q5_DENSE_ROWTILE_GROUPED_ROWS6_BF16` in
`gguf_q5_k_t16_gemv_decode_bf16_bf16_out`) live in the GEMV decode producer and
require the production physical-rowtile policy, but the public MTP target never
reaches that producer in production (WMMA prefill band, with source-MMQ owning
the Q5 down at rows 24/32), and the only profile that turns target WMMA off
(strict) also empties the Q5 rowtile policy. Same mechanism as the R0178 Q6
closure. No arithmetic or default changed.

## Changes

- `docs/REFACTOR.md`: remove R0172 and R0179 (superseded rollback/diagnostic
  owners; no public clearing route on this artifact).

`scripts/gguf_mtp_c1c8_server_bench.py`, `/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`,
`hip_gfx1100`, GPU0 W7900, hermetic TheRock env, rocprofv3 kernel trace):

  `gguf_q5_t16_dense_wmma_prefill_bf16` (1824, WMMA target). ZERO grouped-Q5.
- Strict C8/K3/D24 rollback (`runtime_profile.requested=resolved=strict`,
  `/tmp/refactor-gfx1100/r0179-strict-c8.json` +
  `r0179-trace-c8-strict/epyc/2419912_kernel_trace.csv`): engaged 10/10,
  `ar_mtp_equal` 10/10. Target WMMA/source-MMQ are off (Q5 now
  `q5_k_t16_dense_single_local32_gemv` 48 + single_wave 14976; Q6 now
  rowtile_col8 43415), but still ZERO grouped-Q5 and ZERO grouped-Q6.

Mechanism (source inspection):

- Grouped-Q5 selection requires `q5_t16_physical_rowtile_enabled()` and
  `physical_exact_rowtiles_enabled()`
  (`hipengine/kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.py:1953`), which
  come from the production-only physical-target plan.
- `resolve_physical_target_rows`
  (`hipengine/generation/physical_target_rows.py:131`) returns an empty plan for
  any non-production profile, so strict disables `q5_rowtiles` too.
- In production the target forces WMMA
  (`mtp_serving_target_use_wmma_prefill`, `gguf_linear.py:1057`); the Q5 down at
  rows 24/32 is additionally owned by source-MMQ
  (`_q5_raw_mmq_target_eligible`, `gguf_linear.py:12086`, capability-gated, no
  env rollback). The GEMV producer that holds grouped-Q5 is not reached.

Therefore no `hipengine serve` configuration on this artifact engages the
grouped-Q5 R8/R6 owners; both entries' public-route clearing actions are
unsatisfiable. The owners remain registered as rollback/diagnostic paths; their
grouped-vs-repeated bit parity is covered by
`tests/test_gpu_gguf_t16_selected_gemv_decode.py::test_q5_t16_grouped_rows8_matches_repeated_rows8_bits`
(distinct from public routing, per the entries' own note).
