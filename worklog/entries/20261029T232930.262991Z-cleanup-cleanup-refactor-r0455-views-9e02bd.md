# Name bounded GR scale-only scratch views

## Summary

R0455 scale-only scratch reuse now has named, bounded views. Full FP32
fallback capacity and allocation ownership are unchanged.

## Changes

- `Qwen4ExpGRScratch.inv_rms_view()` borrows the gate plane for FP32 scales;
  `mixed_f16_view()` borrows the unwritten normalized plane for half(mixed).
  Both reject closed scratch, invalid extents and out-of-capacity requests.
- Scale-only norm, up and inject launches use the named views; mirror
  publication uses the bounded image pointer. No device allocation or
  kernel arithmetic changed.
- Keep physical reuse rather than adding separate buffers: these uses have
  disjoint lifetimes from the FP32 fallback. The fallback still needs both
  complete planes. Only the original allocations are freed, once.
- The ledger no longer asks for redundant dedicated allocations. Publication
  and tail-policy cleanup remain open.
