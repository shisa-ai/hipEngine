# YuE2 window-relative sampler: 13.5x on the sampler stages, 1.40x on the production loop

## Summary

The head projects only a phase's window, but the sampler still built a 184 704-element
mask, ran the repetition penalty over the full row, partitioned for top-k, stable-sorted
for top-p, exponentiated the softmax and accumulated a float64 inverse CDF over all of it,
once per step, for 17.7% of the vocabulary that a phase can actually select. Sampling now
happens in window coordinates: `distribution_windowed` returns a `PhaseScores` slice plus
its token offset, and the session loop maps the token back with that offset.

The two entry points share one arithmetic body, `_distribution_slice`, where the full-row
call is the `(low, high) = (0, n)` case. That is the whole equivalence argument: there is
no second implementation to keep in step.

## Changes

- `hipengine/generation/yue2.py`: `PhaseScores`, `_allowed_mask`, `_distribution_slice`,
  `distribution_windowed`; `distribution` is now a thin wrapper over the same body, and
  the legacy `off` variant is a flag on it rather than a separate function.
- `hipengine/runtime/yue2_session.py`: `generate_tokens` slices the head row before
  converting it, combines CFG over the slice, samples in window coordinates and adds the
  offset back to the token.
- `scripts/yue2_sampler_window_validation.py`: equivalence over recorded rows, interleaved
  sampler-cost measurement and a three-arm interleaved loop comparison.

### Stage-by-stage, why the index shift is safe

- **Mask.** Built from `phase_domain` plus `phase_end_token` intersected with the window,
  so a windowed row gets the mask its full-row counterpart would have applied to that
  range. `abc`'s holes between `EOD` and `ABC_END` stay unselectable.
- **Penalty.** History ids outside the window are dropped. Their rows are `-inf` and stay
  `-inf` under `x * alpha` for any `alpha > 0`, so the penalty they receive cannot be
  observed. `window_penalty` also raises on a history id above the row length, which the
  filter is what makes safe.
- **top-k.** Masks by *value* (`scores < threshold`), not by index, so a window shift
  cannot change the survivor set. `top_k` is compared against the full vocabulary, not the
  window width, so a `top_k` larger than the window keeps everything exactly as the full
  row does.
- **top-p.** Sorts with `kind="stable"`, so equal scores keep ascending token order in both
  layouts, and the trailing `-inf` entries contribute `0.0` to the cumulative sum.
- **Draw.** One `uniform()` per step in both layouts.

### Two identity blockers fixed first

Neither is specific to the window, and both are pre-existing:

1. `softmax_f32` summed the whole row, including the `-inf` tail. The masked entries add
   `0.0` exactly, but they change the reduction's grouping, so the same distribution
   presented as a full row and as a window could disagree by an ulp and a draw landing on a
   boundary could pick a different token. The sum now runs over the finite entries only.
2. `sample_categorical` used `searchsorted(cumulative, draw, side="right")` over the whole
   row. Entries past the last positive mass form a flat tail, and a draw that lands exactly
   on the total -- reachable when `uniform() * total` rounds up in fp64 -- would step over
   it and return a token with no mass. The search now stops at the last entry carrying any.
   `uniform()` is in `[0, 1)`, so this is a narrow case, but it is a real one and the
   windowed row's tail is shorter than the full row's.

## Measurements

Host-side sampler cost per step (mask, penalty, top-k, top-p, softmax, draw), interleaved,
medians of 15 pairs on reference-recorded rows:

| Phase | Full row | Window | Speedup | Saved |
| --- | ---: | ---: | ---: | ---: |
| `semantic` (32 769 rows) | 5.86 ms | **0.43 ms** | **13.5x** | 5.44 ms |
| `abc` (151 849 rows) | 3.37 ms | 2.56 ms | 1.32x | 0.81 ms |

Production loop, two-branch CFG, temperature 1.0, top-p 0.95, top-k 100, repetition
penalty 1.2 over 50 tokens, `mandarin-off-s1234`, 48 tokens, three arms inside one
repetition with the order rotated, 5 repetitions per arm:

| Arm | ms/token | Saved vs baseline | Speedup |
| --- | ---: | ---: | ---: |
| full head, full-row sampler | 61.11 (60.71-61.21) | — | — |
| windowed head, full-row sampler | 55.14 (54.97-55.31) | 5.97 ms | 1.108x |
| windowed head, windowed sampler | **43.80** (43.58-43.91) | **17.32 ms** | **1.396x** |

The sampler's own contribution is the difference between the last two arms: 7.35 ms/token,
larger than its 5.44 ms host cost because slicing before `bf16_bits_to_f32` and
`combine_cfg` also shrinks the host-side conversion from 739 KB to 131 KB per branch.

A separate interleaved run of the head-window validation measured the same endpoints as
60.84 → 43.75 ms/token (17.10 ms saved), within 1.3% of this one. The head-window unit's own
loop figure (61.4 → 56.8) is the first two arms of this table and also reproduces.

An earlier run of the new script used `tests/fixtures/yue2/cases/mandarin-off-s1234.npz`,
which has no negative prefix, so the loop ran single-branch: 36.13 → 23.81 ms/token
(12.34 ms saved). The retained artifact uses the `greedy/` fixture, which carries the
negative prefix, because that is the production CFG configuration the other YuE2
benchmarks use. The single-branch run is consistent with the retained one -- roughly half
the absolute cost, same direction, 12.3 ms vs 17.3 ms saved.

step, identical tokens from identical seeds). `top_k` above the window width and above the
vocabulary, `min_tokens` suppression, the legacy `off` arithmetic and a mismatched-slice
call are all tested.

## Next

The sampler is now 0.43 ms of a 43.8 ms/token step, so it is no longer worth attacking. The
remaining host work per step is `bf16_bits_to_f32` and `combine_cfg` over the window slice,
both well under a millisecond. The loop is now dominated by the transformer layers, and the
reviewer's ordering stands: **two-row transformer execution**, i.e. running the conditional
and unconditional branches through one pass instead of two, is the next unit that can move
this number. The shared-weight head already runs once for both branches
(`worklog/entries/20260917T044555.072350Z-lhl-yue2-ar-paired-head-determinism-fab45d.md`);
the layers are the remaining duplication.
