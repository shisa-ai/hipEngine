# R0523 c4 race: all GPU kernels cleared; c4 GDN path contradicts native-row instrumentation; owner unpinned

## Summary

Continued R0523 root-cause. Every rows=4 GPU kernel on the packed c4 decode path was
inspected (via the rocprof bench trace) and is deterministic, so no GPU arithmetic kernel
is the owner. A per-slot GDN state-hash helper placed in the native-row path
(_run_linear_attention_decode_rows_native, reachable, env set) fired 0 events on a 30-rep
c4 run that still reproduced the race (9 flips), while the per-row helper fired only for
the c1 oracle. This contradicts the rocprof trace showing the indexed GDN kernels and
means the c4 GDN decode reaches those kernels through a caller not yet instrumented.
Owner remains unpinned after ~35 iterations. No production behavior changed; all hooks
env-gated (off by default) and uncommitted.

## Changes

- Env-gated per-slot GDN state-hash helper (_r0523_gdn_state_hash) in the native-row path;
  per-row helper (_r0523_gdn_state_hash_perrow) in run_linear_attention_attn_only.
  Diagnostic only; revert before any production commit.

## Validation

Measured (bg-180, 30-rep c4 eager, /tmp/refactor-gfx1100/r0523-gdnstate2.*):
mismatch_count=9 (race persists); 0 R0523GDN (native-row) events, 3 R0523GDNROW (per-row,
c1-only) events. The native-row helper is reachable (no preceding return) and the env was
set, yet fired 0 => the c4 GDN decode does not call _run_linear_attention_decode_rows_native
even though the rocprof bench trace shows the indexed GDN kernels. The actual c4 GDN caller
of the indexed conv/recurrence is not yet identified.
