# Add typed staged-adapter protocol and constructor validation

## Summary

Named the de-facto runner-to-adapter interface every staged target/provider adapter implements. The three production adapters (dense `Qwen35GGUFMTP2Adapter`, `Qwen35GGUFMoEMTP2Adapter`, `Qwen35ParoMTP2Adapter`) shared a 13-method surface that no contract named, so method presence was only discovered at call time. Added `StagedTargetAdapter`, a `runtime_checkable` protocol in `hipengine/speculative/provider.py`, plus `validate_staged_target_adapter`, wired once at each adapter `__init__` tail so an incomplete owner fails at construction with the missing method names instead of surfacing as a mid-cycle `AttributeError`.

## Changes

- `hipengine/speculative/provider.py`: `StagedTargetAdapter` protocol (13 required methods: capability, claims_fit, component_claims, reserve/release_claims, prepare_requests, propose_batch, execute_target_frontier, rollback_cycle, recover_cycle_failure, prepare_k0, register_request, close), `_STAGED_ADAPTER_METHODS`, `validate_staged_target_adapter`, `__all__`.
- `hipengine/speculative/__init__.py`: export both names.
- Optional hooks stay absent from the protocol exactly as the runner seam splits them: `execute_cycle` (MoE opaque C1), `note_speculative_ar_commit` (dense), `kv_live_spans_owner` (PARO), `staged_frontier` (MoE), `release_request` (dense/MoE), `close_requests` (PARO), `containment_evidence` (MoE). Verified per-adapter presence with grep before freezing the required set.
- `hipengine/generation/qwen35_gguf_mtp2.py`, `qwen35_gguf_moe_mtp2.py`, `qwen35_paro_mtp2.py`: import + `validate_staged_target_adapter(self)` as each `__init__` tail statement (verified via AST to sit inside `__init__`).
- `tests/test_unit_specdec2_provider.py`: validator accepts the complete face and proves hooks optional; rejects each missing method by name; pins all three production classes' method surface CPU-only (device construction validates the same contract at runtime).
