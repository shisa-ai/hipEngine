# Muse Glimmer DFlash budget optimum is acceptance-driven; default 4 robust across context

## Summary

Task #2 of the §11.1 long-context track ("context-aware candidate budget").
Swept candidate_budget 2-7 at 2K/512/32K/126K on identical KV (one corpus prompt
per long context, prompt KV snapshotted once via save_context, AR reference +
every budget decoded from the same resident prompt KV via prefix-cache reuse;
128 greedy tokens; DFlash IDs == AR at every point). The budget optimum is
acceptance-driven, not context-driven: for the corpus/agentic prompt the argmax
declines modestly with context (7@2K -> 5@32K -> 4@126K) but the curve is flat
near the peak (budget 3-5 within ~0.5 tok/s at 2K/32K), budget 4 is at/near the
peak at every context and the clear optimum at 126K (19.27 tok/s), and budgets
6-7 regress at length (acceptance falls, ms/cycle rises). The short-context
preference for high budget is a prompt/acceptance effect, not a context effect:
the high-acceptance merge-intervals prompt peaks at 7 (41.9 tok/s @512) while the
natural mtpbench suite peaks at 4 (acceptance ~0.49, Gate B). The §11.1
prediction that the optimum RISES with context after #1 is falsified — it
flat-to-falls. The shipping default candidate_budget=4 is therefore the robust
measured choice (general-suite optimum at short context, universal optimum at
long context). A static context->budget map has no generalizable beneficial
shape, so no runtime policy or flag is added (a map returning the default would
be dead code; raising the short-context default would overfit high-acceptance
prompts against the anti-gaming full-suite rule). The genuine adaptive lever is
acceptance/profit-based online depth adaptation — recommended as a follow-up,
not implemented here (one lever per unit; the existing adaptive_budget.py
controller already owns the DFlash-vs-AR profit signal).

## Validation

Host zbook / Radeon 8060S (gfx1151), Muse-Glimmer-30B-KQuant-17GB-Q4_K_M.gguf +
dflash sidecar, baseline c404c305e. Diagnostic measurement (no arithmetic change).

- Exactness: DFlash generated IDs == true AR for every budget at every context
  (24/24 exact=True). Budget only changes how many tokens commit per cycle, never
  the committed IDs (target-corrected greedy), so any budget is exact.
- Measured decode tok/s (corpus prompt unless noted): 2K b3/4/5 = 22.18/22.16/22.14,
  b7 = 22.71; 32K b4/5 = 22.69/22.71, b6/7 = 20.85/22.30; 126K b4 = 19.27 (peak),
  b5/6/7 = 18.93/17.34/19.04. AR = 12.11/11.76/10.84 at 2K/32K/126K. 512 point is
  the natural merge prompt (b7 = 41.93, acceptance 0.748) — flagged non-comparable.
- Methodology note: the first sweep reload the ~15 GB snapshot per budget from a
  96%-full compressed btrfs disk (~8 min/load at 126K); corrected to load once and
  reuse the resident prompt KV (budgets ~8 s each). Identical-KV guarantee is
  unchanged (resident prompt KV is bit-identical across budgets).
