# The two bodyless 500s were a closed engine service escaping as a plain-text 500

## Summary

The 2026-09-18 observation is diagnosed, not inferred: the run's server log
(`/tmp/mtp-matrix-smoke/server.log`, lines 46-124) and its harness artifact
(`/tmp/mtp-matrix-smoke/matrix-smoke.json`) both survive. One long prompt hit the
packed-prefill `NotImplementedError`, the engine classified it as a **fatal**
execution failure and closed the resident service, and the next two requests
then raised

**`hipengine.generation.engine_service.EngineServiceClosed`** (a plain
`RuntimeError` at the time) from `EngineService._enqueue` ->
`_closed_service_error()` while the server prepared their resident context
(`chat_completions` -> `prepare_prompt` -> `ensure_resident_context` ->
`llm.prepare`). The chat endpoint had no handler for it, so the exception
escaped the ASGI app and Starlette's `ServerErrorMiddleware` answered with its
default plain-text 500. The harness recorded exactly that:

```
{"source_id": "CSi9W7V_52", "case": "beyond", "route_arm": "off",  "prompt_tokens": 1244, "error": "HTTP 500: Internal Server Error"}
{"source_id": "aaHGOPi_0",  "case": "beyond", "route_arm": "auto", "prompt_tokens": 1067, "error": "HTTP 500: Internal Server Error"}
```

No `error.code`, no message, and a `text/plain` body a client cannot tell apart
from a truncation. The fatal classification itself is already gone: commit
`de6d31685` contains a step failure instead of closing the service, and
`02ae1c256` re-routes the shape refusal, so the c=8 re-run of that workload
served seven of eight rows after the same guard fired.

## Changes

- `hipengine/generation/engine_service.py`: `EngineServiceClosed(RuntimeError)`
  is the named type for a closed or unhealthy service; `_closed_service_error()`
  returns it (message unchanged, so existing log text is stable).
  `hipengine/generation/__init__.py` exports it.
- `hipengine/server/api.py`:
  - an app-level `@app.exception_handler(Exception)` answers any escaped fault
    with the OpenAI error shape. Starlette routes a handler registered for
    `Exception` through `ServerErrorMiddleware`, which sends this response and
    then re-raises, so the traceback still reaches the server log. A closed
    service maps to 503 `engine_unavailable` (retryable, `error.message` names
    the fatal cause); anything else maps to 500 `internal_error` with
    `error.hipengine.exception_type`.
  - `_engine_unavailable_error` plus explicit `except EngineServiceClosed`
    clauses in the non-streaming `generate` chain and the three streaming
    generators (`stream_completion_one`, `stream_chat_completion_many`,
    `stream_chat_completion`), so an in-generation close reports 503
    `engine_unavailable` instead of 500 `generation_failed`.
- `docs/API.md`: `engine_unavailable` (503, retryable) and `internal_error`
  (500) join the error taxonomy table; the `execution_failed` row now points at
  `engine_unavailable` for the closed-service case.
