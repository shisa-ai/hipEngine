# YuE2 M2: HIP AR prefill/decode runtime and the replay gate

## Summary

The torch-free YuE2 AR runtime runs on gfx1151 with both prefill routes, decode,
per-branch KV caches, `KVLiveSpans`, and exact per-branch position accounting. The
18-case frozen replay matrix passes on both routes over every recorded
full-vocabulary row and 576 decode-step rows; the table in "Numbers" is the
same-host, same-protocol A/B of the two routes. Every argmax flip is a near-tie:
each flip replaces the reference token with one whose logit is within 0.204
(strict) / 0.105 (hipBLASLt) of it, on logits of magnitude 4-11.

Four real bugs surfaced during bring-up, three of them silent:

1. `push_token` uploaded the BF16 hidden row with
   `copy_host_to_device(buf, host_array_ptr(f32_to_bf16_bits(row)))`. The
   temporary array is released as soon as `host_array_ptr` returns, so the H2D
   copy read freed host memory: every hidden row was garbage, every logit was
   `NaN` or ~1e4, and the failure looked like a kernel bug. Fixed with
   `copy_host_array_to_device`, and guarded structurally by a new AST test
   (`tests/test_unit_yue2_runtime_host_copies.py`) because the failure is
   invisible without a GPU.
2. `runtime.close()` freed the KV caches twice (they are registered in
   `_buffers` *and* freed by an explicit loop), raising `HIP error 1: invalid
   argument` on every teardown after the first.
3. The replay harness compared BF16 bit patterns as if they were FP32 logits
   (`runtime.logits()` defaults to `as_bf16=True` while the reference side is
   upcast to FP32), which reported `KL=inf` and top-1 0 for a correct runtime.
4. The batched prefill route wrote `f32_to_bf16(attn)` into the buffer it then
   handed to hipBLASLt as the O-projection activation. The problem descriptor is
   `HIP_R_16F`, so BF16 bit patterns were interpreted as FP16: the O projection
   produced `std 2.14` where the reference is `std 0.88`, and the error grew
   through the MLP to `max|d| 1748` on the first layer's hidden row. Only the
   *activation* conversions were wrong - every weight matrix is a real FP16 copy
   (`fp16_copy`) - and the three activation conversions that fed Q/K/V and
   gate/up already used `bf16_to_fp16`, so the failure looked shape-specific.
   Fixed by converting the BF16 attention output to FP16 explicitly; the layer
   chain now matches the strict route to one BF16 ulp (O projection `1.7e-4` on
   FP32 accumulation order).

A fourth, subtler *design* error was caught by the gate itself: the CFG cases
with unequal prefixes (`[128, 101]`) decode at **different positions per branch** -
the reference advances a separate cache per branch. Replaying branch 1 at branch
0's position gave mean KL 0.189 / top-1 0.703; per-branch positions give mean KL
1.3e-3 / top-1 0.938 on the same case.

## Changes

- Add `hipengine/runtime/yue2_ar.py` (~830 LoC): `YueE2ArRuntime` with BF16 weight
  residency (6.76 GiB), per-branch BF16 KV caches behind `KVLiveSpans` (identity
  slot map, `token_positions`/`evict_mask` filled uniformly), the decode layer
  chain (RMSNorm -> Q/K/V GEMV -> per-head Q/K norm -> RoPE -> span KV write ->
  span attention -> O projection -> residual -> post-norm -> dual gate/up GEMV ->
  SiLU -> down GEMV -> residual) and two prefill routes: `strict` (row-by-row
  decode-shaped arithmetic) and `hipblaslt` (BF16->FP16 activation, batched
  hipBLASLt GEMMs, `vv_rope_positions_f32`), with automatic fallback to `strict`
  and a recorded `prefill_fallback_reason`.
- Add `scripts/yue2_ar_replay.py`: frozen-matrix replay gate (KL, top-1, top-8
  recall, per-scope envelopes, argmax flips, bit-exact repeat after the whole
  matrix), `--full-artifacts` to score every step the oracle recorded, and
  `--cases` for targeted re-runs.
- Add `tests/test_unit_yue2_ar_gate.py` (9 tests): the gate scores identical rows
  perfectly, reports deliberate perturbations, counts each dropped top-8 id, and
  its KL/softmax/repeat helpers are checked directly. A gate that cannot fail
  proves nothing.
- Add `tests/test_unit_yue2_runtime_host_copies.py` (4 tests): structural guard
  against `host_array_ptr(<temporary>)` in the runtime and loader.
- `scripts/yue2_oracle.py`: the compact `ar_replay` fixture now records
  `full_logits_available` (the pairs actually present in the committed file, not
  the artifact-wide step list), and the validator rejects a file whose
  availability list disagrees with the arrays it contains. The `cases` family
  schema now accepts the mono/stereo PCM excerpt the reference pipeline emits and
  treats `abc_ids` as optional (mode-off requests have no ABC phase), and
  `_mutate_tree` passes `exclude` when it re-freezes a mutated tree.
- `tests/fixtures/yue2/integrity.json` and `tests/fixtures/yue2/cases/`: the
  native-generation oracle output (12 cases, ~8 MB) lands with this unit so the
  shared integrity index matches the tree; M3 consumes it.

## Numbers

18 cases / 112 recorded full-vocabulary rows / 576 decode-step rows. `mean` is
pooled over all rows; `p95`/`p99`/`max` are the worst case in the matrix; top-1
and top-8 are pooled row rates against the reference distribution. The two rows
come from one same-session pair of runs (strict, then batched, back to back), so
the ratio is like-for-like.

| route | mean KL | worst p95 | worst p99 | max KL | top-1 | top-8 recall | max flip gap | prefill total |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| strict | 1.43e-3 | 2.70e-2 | 3.16e-2 | 3.27e-2 | 552/576 = 95.83% | 95.88% | 0.204 | 522.5 s |
| hipblaslt | 2.11e-3 | 7.38e-2 | 8.75e-2 | 9.10e-2 | 557/576 = 96.70% | 96.05% | 0.105 | 91.3 s |

Per-case prefill wall time over the same 18 cases (strict -> batched): L128
3.0-6.1 s -> 0.9-1.8 s, L512 11.1-22.6 s -> 1.7-3.5 s, L2048 58.3-118.3 s ->
10.0-20.2 s; total 522.5 s -> 91.3 s (5.7x, 2.8-6.5x per case), i.e. ~5.0
ms/token at L2048 for the batched route.

Wall times are not stable across sessions: an earlier run of this identical
protocol measured 1084 s for the strict route and 86 s for the batched route, so
the strict route's absolute time moved about 2x between sessions while the
batched route stayed within ~6%. Only the same-session pair above is quoted as
the speedup.

Both routes stay inside the broad floor (mean KL <= 0.05, top-1 >= 90%). The
hipBLASLt route exceeds the production envelope's 5e-2 per-row max-KL ceiling on
one case, `abc-nocfg-L128-s5678` (5 rows, mean 1.92e-2, max 9.10e-2; the strict
route is 7.4e-3 / 3.27e-2 on the same case), which is the flat ABC-planning
distribution where several notation tokens are within a few hundredths of a
logit. Every other case is <= 2.3e-2. The route is deterministic: a repeat of the
whole matrix reproduces the first case bit-for-bit.

Two measurements worth keeping:

- The reference prefill is a single batched forward, so the batched route matches
  its arithmetic class more closely than the row-by-row route: it wins on top-1
  (19 vs 24 flips) and top-8 (96.05% vs 95.88%) while its KL tail is wider.
- The hipBLASLt heuristics pick a `MT32x32x64` Tensile tile for the M=128 GEMMs:
  196 GEMMs cost 102.0 ms for ~361 GFLOP, i.e. ~3.5 TFLOP/s, ~6% of the FP16
  peak. Algorithm selection is the largest measured headroom in the prefill path.

## Next

- M3: native generation (torch-free sampler/RNG, ABC + semantic loops,
  EOS/truncation, staged save/reload, session isolation/cancellation) against the
  `cases` fixtures committed here.
- M3 perf: sweep hipBLASLt algorithm/tile selection for the M=128..2048 GEMM
  shapes, and measure the M sweep before tuning further.
- Reduced head (mask-derived candidate logits) is not implemented; the full
  lm_head is validated. Any reduced head must derive its candidate set from the
  phase/EOS mask, never from the benchmark prompt.
- Q rounding: the reference applies RoPE on BF16 tensors, the runtime keeps the
  rotated query in FP32 and feeds the attention kernel FP32. Both are within a
  BF16 ulp of each other; the FP32 path is the more precise one, so it stays the
  default and no reference-matching rounding was added.
- `abc-nocfg-L128-s5678` is the case to watch when the prefill route or the
  sampler changes; it is the only row set above the 5e-2 max-KL ceiling.
