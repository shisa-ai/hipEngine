# Extract Qwen GGUF graph and KV-pin lifetime owner

## Summary

Moved the resident session's graph/KV-pin lifetime responsibility into
`hipengine/runtime/qwen35_gguf_graph_lifetime.py`. One explicit owner now holds
the decode-graph registry, device-KV pin registry and retained graph submission
contexts, and implements pin/unpin, invalidation, strict packed-workspace
closure, decode-graph teardown and submission-context teardown. The session
keeps its historical attribute names as compatibility properties backed by a
lazy holder, so capture sites, scripts and slot views still append to ordinary
`list`/`dict` objects.

This is one move-only RF-6 boundary. It does not claim RF-6 closure: bulk
attention orchestration, full-stack verification and the PARO decomposition
decision remain.

## Changes

- Added `hipengine/runtime/qwen35_gguf_graph_lifetime.py`:
  - `Qwen35GGUFGraphLifetime` owns `decode_graphs`, `kv_pins` and
    `submission_contexts`.
  - `pin`/`unpin` receive the current `DeviceKVPoolAllocation` and
    `DeviceChunkedKVPool` explicitly; the owner never holds or reaches back
    into a session, and it holds no whole-runner proxy.
  - `blocks_kv_rebind`, `live_graphs`, `close_live_graphs`,
    `close_decode_graphs`, `submission_context` and
    `close_submission_contexts` replace the duplicated runner loops.
  - `close_graph_handles` centralizes distinct-live-handle closure with the
    two existing policies: skip a handle without `close()` for device-KV
    invalidation, raise for packed-workspace resizing.
- `hipengine/runtime/qwen35_gguf_runner.py`:
  - Replaced the three dataclass fields with lazy compatibility properties
    (`_decode_graphs`, `_device_kv_graph_handles`,
    `_decode_graph_submission_contexts`).
  - `resident_slot_view` installs a fresh lifetime holder before resetting
    slot-local bookkeeping, so views never share graph state with the batch
    owner.
  - `_pin_device_kv_graph`, `_unpin_device_kv_graph`,
    `invalidate_device_kv_graphs`, `unbind_device_kv_allocation`,
    `release_idle_packed_workspace`, the three clone-destination guards,
    `_invalidate_live_packed_decode_graphs`, both capture-method submission
    context lookups, `close_decode_graph_submission_contexts` and session close
    now delegate to the owner.
- Added `tests/test_unit_qwen35_gguf_graph_lifetime.py` with 16 focused tests
  covering pin idempotence, missing bindings, pin failure, unpin after detach,
  handles-first close order, strict versus best-effort close, decode-teardown
  failure and retry, submission-context retention/proofs, alias identity, two
  independent sessions over one pool, pool pin counts, unbind ordering and
  cross-session packed invalidation order.
- The implementing worker made no numerical, dispatch or kernel changes.
  Parent added the implemented boundary to `docs/PLAN.md` and
  `docs/reference/QWEN-GGUF-RUNTIME.md`, and narrowed RF6 in
  `docs/REFACTOR.md` to unfinished work and compatibility migration.
