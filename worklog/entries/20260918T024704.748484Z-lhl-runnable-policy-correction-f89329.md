# Separate untested execution from known failures and production claims

## Summary

The user directed a correction to the new production control-plane policy:
prevent known bad behavior, but do not treat almost every untested workload as
bad or unrunnable. Presume implemented paths runnable within their input,
resource and execution contracts, evaluate them on real workloads, and repair
observed failures. Missing evidence does not establish a failure. Claims and
production arithmetic promotion still require the applicable quality and
performance evidence; uncertain state after an actual execution failure still
requires safe recovery or a controlled stop.

This revises the policy introduced by
[the containment/eligibility entry](20260918T015727.780379Z-lhl-make-execution-failure-containment-and-per-reque-abff1a.md).
That committed entry remains unchanged. No runtime selection, guard, numerical
threshold or benchmark result changed in this documentation unit.

## Changes

- `docs/EXECUTION-PROFILES.md` §1.1 separates execution capability, evaluation
  results, and claims/promotion. Evidence describes implementation regimes and
  transitions, not an exhaustive request allowlist. Qualification-only guards
  must permit evaluation and be removed or replaced with concrete constraints.
- §2.9 describes the evidence resolver and explicit screening flags as the
  implemented mechanism, not a permanent policy that unmatched paths are bad.
  §8 preserves public profile guarantees while keeping candidate evaluation
  reachable; §9/§10 distinguish diagnostic execution from qualified claims and
  post-failure recovery from merely selecting strict arithmetic.
- §4.3 permits the smallest established affected ownership scope, including a
  packed group. It covers outstanding device dependencies and host ownership,
  separates committed mutation from recovery outcome, keeps `unknown`
  unclaimable, and labels the GGUF runner's all-HipError/pre-device-only policy
  as an implementation limitation rather than a universal error taxonomy.
  Survivor checks respect production schedule-dependent arithmetic.
- §4.4 separates per-request capabilities from physical scheduling. Groups may
  own shared resources; compatibility, resource, fairness and economic choices
  are legitimate when reported accurately. Neighbor ineligibility must not be
  propagated or hidden behind a generic group refusal.
- `docs/CONCURRENCY.md` aligns Gate 3 and evaluation/promotion guidance, including
  affected-group retirement, cleanup/fatal cases, mixed eligibility, and
  profile-appropriate survivor checks. Removes the stale minimum-material-win
  wording in favor of the existing non-regression promotion contract.
- `docs/PLAN.md` records this architectural policy and removes the blanket
  prerequisite that a qualification foundation be complete before candidate
  implementation or tuning can begin.
- `AGENTS.md` replaces "math changes are guilty until proven correct" with the
  runnable/evaluate/fix rule and preserves correctness gates for promotion, so
  later agents do not reconstruct the rejected missing-evidence policy. The
  fused-kernel invariant now explicitly permits candidate reassociation during
  evaluation while retaining the full gate for default promotion.
