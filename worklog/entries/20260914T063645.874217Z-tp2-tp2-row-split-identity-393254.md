# Cover physical row byte ranges in the manifest identity and validate them

## Summary

Repairs review finding R8 (P2). A row split stores its column ranges compactly and
generates the physical per-row byte segments on demand, so `byte_ranges` - the
ranges `materialize_slice()` actually reads - were absent from
`ShardManifest.to_dict()`. Two manifests with identical logical ranges and
different physical ranges therefore produced the same `manifest_hash()` while
materializing different bytes.

The fix covers both halves of the reviewer's request: the identity now includes
the physical ranges, and `RowSplitLayout` rejects a layout whose physical ranges
do not correspond to its own logical ranges.

## Changes

- `hipengine/loading/qwen35_gguf_shards.py`:
  - `RowSplitLayout` gains required `block_size` and `type_size` fields and
    validates each `(range, byte_range)` pair against the derivation the builder
    uses: `column // block_size * type_size`. Geometry is required rather than
    defaulted so no caller can skip the check by omitting it.
  - `ShardManifest.to_dict()` serializes `byte_ranges` (`null` for non-row
    splits), so the hash covers what the loader reads.
  - The row-split builder passes its quant geometry into the layout.
- `tests/test_unit_loading_qwen35_gguf_shards.py`: five new tests, two existing
  `RowSplitLayout` constructions updated with explicit geometry.

## Validation

- RED before the fix: `'byte_ranges' in Ellipsis` failed with the key absent, and
  the hash-comparison test could not find the field at all; the correspondence
  tests failed on the missing `block_size` argument.
- GREEN after: `tests/test_unit_loading_qwen35_gguf_shards.py`, 69 passed.
- Real model manifest (`/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`): 128 tensors now
  serialize physical row ranges, matching the reviewer's count of 128
  row-parallel projections (64 `ffn_down`, 48 `ssm_out`, 16 `attn_output`).
  N=2 rank bytes 9283527680 / 7525422080, unchanged by this fix.
- New identities: N=2 `fb03060e73f21b0cd12763609cc607df2048ab987569b99b25f264a362352d1c`,
  N=4 `8a735ef063f198cf98c438799d3445b7fb4631be4ce038fbb55a230466791fa3`. They differ
  from the previous values because the serialized form gained a field;
  `benchmarks/results/tp2_shard_plan_report.json` is regenerated to match.

## Consequences

- Any previously recorded N=2/N=4 manifest hash is superseded. The artifact
  holding the old value is regenerated in this unit.
- `RowSplitLayout` is a required-geometry type now; a construction without
  `block_size`/`type_size` raises instead of silently accepting physical ranges
  that no longer correspond to the logical ones.
