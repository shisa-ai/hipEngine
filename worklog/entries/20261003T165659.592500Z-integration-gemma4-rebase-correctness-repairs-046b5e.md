# Repair Gemma rebase graph and Q8 prefill integration

## Summary

The rebase onto `origin/gemma4` at `53bbb6620` finished at `6339dd866`.
This unit repairs graph capture and Q8 prefill routing, reconciles affected
GPU tests with the declared monolithic parent oracle, and records the regression
comparison. It does **not** certify the complete integration or authorize push:
prefill is slower than the untouched pre-rebase default at several measured

## Changes

- Reserve staged attention scratch on the graph capture stream for every selected
  geometry. Eager warmup on another stream cannot reserve that allocation.
- Route dual-resident Q8 WMMA prefill through the existing T16 consumer, after
  WMMA selection. Raw WMMA FP16 activation staging overflowed the synthetic
  fixture's finite GeGLU output; the existing T16 consumer repairs that range.
- Replace host total-row readback in Q4T16 and Q5 iu8 expert gate/up consumers
  with a padded-row launch bound. The tile-map producer initializes unused
  entries to -1; consumers already reject them before reading weights. Preserve
  same-stream risk-count reset and repair ordering. No device arithmetic changed.
- Pin staged parity tests to the original monolithic block entry instead of the
  adaptive public decode wrapper, which can select incoming split/flash routes.
  Replace a stale null-pointer launch test with host-only bounded-LDS admission.
  Update verifier expectation to its explicit `gemma4_plain` route.
- Review 24 shifted audit sites: 17 module-relative/suffix path references,
  six capability errors, and a docstring mistaken for an architecture flag
  branch. Record NOT-DEBT decisions without clearing their underlying ledger
  debt or increasing budgets.
- Preserve restored, unrelated capacity-probe files and their two worklogs
  uncommitted. Benchmark diagnostics are in
  `benchmarks/results/2026-10-03-gemma4-rebase-regression-diagnostic.json`.
