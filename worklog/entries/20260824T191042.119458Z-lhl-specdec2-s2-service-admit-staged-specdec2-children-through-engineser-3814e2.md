# Admit staged SPECDEC2 children through EngineService

## Summary

Connected staged SPECDEC2 intent to the public EngineService child lifecycle
without running provider/target generation in command handling. A staged
`SubmitPollTextGenerator` child tokenizes, submits the ordinary Generation-2
request with speculative intent, registers the resident row, and returns a
bounded multi-tick submission. The service can observe the child as active while
the first target cycle is blocked, proving admission is no longer synonymous
with completed generation.

Legacy whole-request providers keep their existing synthetic-output path as the
explicit unmigrated oracle seam. Staged submissions are identified by route and
use resident-runner completion/take/abort ownership rather than the legacy
`_speculative_outputs_by_request` table.

## Changes

- Made staged resident capability sufficient for `supports_speculative_mtp`.
- Added O(1) staged single/batch submission with ordinary prompt registration,
  cancellation dispatch, finite tick bound, and partial-batch rollback.
- Routed staged generation-complete, result consumption, and abort through the
  normal resident runner while leaving legacy output ownership unchanged.
- Added a blocking target-gate EngineService test proving handle return before
  generation, zero legacy calls, empty synthetic output table, committed IDs,
  exact stage order, and clean child closure.
