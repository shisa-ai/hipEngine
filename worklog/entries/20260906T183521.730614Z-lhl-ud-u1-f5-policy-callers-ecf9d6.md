# F5 stamp-only policy callers bind artifact qualification

## Summary

UD-U1 review finding F5 (HIGH, unchanged since review baseline `1016e8744`):
the `GGUF_UNQUALIFIED_MANIFEST_PRESET` sentinel, pinned plain-control
fingerprint allowlist, and the 3-element `_gguf_policy_identity` existed, but
actual production callers still selected artifact-qualified policy from the
header stamp alone, bypassing the sentinel. Scope of this unit is F5 only:
identity plumbing and defaults for the stamp-only caller class. No kernels,
no numerical algorithms, no F1/F3 work, no U2+. F4 was accepted just before
this unit; F2/F6/Q5-planar remain accepted.

## Caller inventory (runner + loading + audit, CPU source audit)

Artifact-qualified tables/policies whose callers used only stamp or
`(geometry, stamp)` — the F5 bypass class, all repaired here (details below):

1. `Qwen35GGUFFullStackRunner.__post_init__` →
   `_gguf_fp16_recurrent_state_enabled(backend, file_type_name)` — the
   gfx1151 `GGUF_FP16_RECURRENT_STATE_DEFAULT_FILE_TYPES` stamp default
   (certified on the pinned dense Q4_K_S control) applied to any artifact
   sharing the stamp, including unknown non-pinned K_S manifests and UD
   presets. Reviewer's named example 1.
2. `_resolve_gguf_decode_graph_submission_transport` + its two production
   callers (`capture_decode_graph`, `capture_packed_decode_graph`) —
   `GGUF_DECODE_GRAPH_SUBMISSION_POLICIES` rows keyed
   `(geometry, stamp)` read via `policies.get((geometry, stamp))`. Reviewer's
   named example 2.
3. `_resolve_gguf_private_c1_small_weight_arena` (policy-table admission
   route), `_resolve_gguf_private_c1_decode_scratch_arena`, and
   `_resolve_gguf_private_c1_weight_arena_max_allocation_bytes` —
   `GGUF_PRIVATE_C1_{SMALL_WEIGHT,DECODE_SCRATCH}_ARENA_POLICIES` rows keyed
   `(geometry, stamp)`; fed by `Qwen35GGUFResidentSession.__post_init__`
   from the GGUF header only (same bypass class found by the required
   inventory — not just the two named examples).
4. The quant-route audit's `fp16_recurrent_state_default_on` and its shared
   pure mirror `gguf_fp16_recurrent_state_default`
   (`hipengine/loading/qwen35_gguf_policy.py`) reported the stamp-lane
   default with no artifact binding.

Already-safe callers verified (no change needed): every other runner policy
table resolves through the full `_gguf_policy_identity` 3-tuple
(`GGUF_Q8_T16_DUAL_WMMA_PREFILL_POLICIES`, `GGUF_Q4_PACK8_DUAL_WMMA_SILU_...`,

## Scope notes / remaining gaps

- Preset-keyed policy rows (3-tuple keys) are supported by the lookup
  semantics but no backend ships one today; UD artifacts therefore resolve
  generic fallbacks everywhere until U2-U5 certify consumers. No supported
  arithmetic claims were widened.
- The env override (`HIPENGINE_GGUF_FP16_RECURRENT_STATE`) can still force
  FP16 storage for unknown/preset artifacts; that is the documented
  developer opt-out, not a certified default.
- Session-init manifest derivation runs only when arena policy rows exist
  (gfx1100/gfx1151 both do); on a hypothetical backend without them the key
  stays None and no artifact-qualified admission is reachable anyway.
