# Flash-Next token-budget scheduling

## Summary

With the shared batch on by default, a short request that arrived while a
long prompt was prefilling waited for that whole prefill: the `fair` policy
alternates prefill and decode but takes prefill chunks first-come first-served.
Two short requests sent 5 s after a 122,076-token prompt finished at about
170 s, together with it.

## Changes

- `Qwen4ExpGGUFTextGenerator.engine_loop_config_defaults` declares
  `token_budget` with `round_prefill_token_budget` equal to the runner's
  prefill chunk and `round_decode_row_budget` covering the request capacity;
  the serving runner declares `supports_prefill_decode_same_round`. Each round
  runs one prefill chunk, rotating across prefilling requests, and one decode
  step for every decoding row.
- `hipengine/llm.py`: generators may declare the two round budgets
  (`HIPENGINE_ROUND_PREFILL_TOKEN_BUDGET` / `HIPENGINE_ROUND_DECODE_ROW_BUDGET`
  still override).
- `docs/API.md`, the batch module docstring, and a `docs/REFACTOR.md` gap for
  inter-token latency beside a long prefill.

## Validation

- New unit test: a short request submitted behind a 48-token prompt (8-token
  chunks) finishes before that prompt's prefill does; it fails with the old
  `fair` default. Resident-serving, batch decode, LLM generate, and engine
  default tests: 154 passed.
- Live, default `hipengine serve` on gfx1151: the same two short requests
  beside the 122,076-token prompt finished in 31.1 and 38.1 s; the long request
  still answered its needle (`7342`) at 177.0 s on its staging runner.
- Throughput, chat, 128 tokens, wall including prefill: 1 request 32.92 tok/s
  (automatic MTP), 2 concurrent 29.19, 4 concurrent 40.01, 8 concurrent 46.99.
- `qwen4exp_http_grid.py` 50/50 (24/24 MTP probes executed MTP),
  `qwen4exp_http_soak.py --rounds 3` 35/0,
  `qwen4exp_ar_batch_http_check.py --with-mtp` 71/71.
