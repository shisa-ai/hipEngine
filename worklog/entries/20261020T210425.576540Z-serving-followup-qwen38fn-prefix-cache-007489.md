# Flash-Next radix prefix reuse on by default

## Summary

Flash-Next (Qwen4Exp) serving now reuses prompt prefixes under the default
`--prefix-cache radix`. Admission restores the deepest cached checkpoint that is
a strict prefix of the prompt into the request's staging runner (and MTP draft),
then advances the scheduler cursor so only the suffix prefills. Checkpoints hold
QSA K/V rows, raw and pooled index keys, GDN/conv/PLE/residual state, the PLE
n-gram history and, for MTP rows, draft K/V/index plus the previous hidden row.
Rows live in refcounted segments that later checkpoints of the same
computation share. Captures happen at the prompt end, the last chunk boundary
before it, three grid points on prompts of 8K tokens or more, and the divergence
point of a branch. The budget is `HIPENGINE_GGUF_PREFIX_RETAINED_STATE_BYTES`
when set, otherwise half of free device memory capped at 32 GiB. Eviction is
LRU, and a capture never evicts when live rows pin the needed space.

## Changes

New `hipengine/runtime/qwen4_exp_prefix_cache.py` and `hipengine/generation/qwen4_exp_serving_prefix.py`; hooks in the resident runner, runner and draft.

## Validation

- `tests/test_unit_qwen4exp_prefix_cache.py` (6 tests): restore plus suffix is
  byte-identical to a cold prefill through shared segments; strict-prefix and
  draft lookup rules; budget and eviction; resident runner end to end (same
  tokens with the cache on and off, cursor moved past reused tokens).
- The Qwen4Exp, prefix and engine-loop unit suites pass after one focused repair
  to the runner transaction tests.
- `hipengine serve` on gfx1151, production, BF16 KV, 24.8K-token prompt,
  greedy, one run: cold TTFT 59.4 s; follow-up turn 0.68 s; identical retry
  0.61 s; 70%-depth edit 11.8 s; explicit MTP follow-up 0.61 s (reused 24,824
  tokens, 10.5 ms restore); cold MTP 77.1 s.
