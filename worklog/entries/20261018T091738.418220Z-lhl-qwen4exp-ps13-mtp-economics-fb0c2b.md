# qualify served MTP economics and fix the concurrent-token crash

## Summary

MTP economics are now measured on one host in one session, both in-process and
on the served route, and the served route had a production-stopping bug that the
measurement itself exposed.

**Concurrent MTP crashed the resident engine.** Four concurrent MTP requests
returned three `500`s:

```
generation failed: '_CompositeGenerationCancellationToken' object has no
attribute 'cancel_requested'
```

The engine service treats a driver-tick exception as a driver failure, so it tore
the engine down and every later request got `503 engine service is closed`. A
single bug in a request-level probe turned into a dead server. Fixed by giving
the composite token a `cancel_requested` property that mirrors `cancelled`, and
by probing with `getattr` in the serving MTP provider the way the other call
sites already did. RED test:
`tests/test_unit_server_composite_cancellation.py` (7 cases, fails on the old
code with the exact AttributeError).

**The retained 1.273x MTP row is a session artifact.** Re-running that row's own
commit `9a0c408d2` on today's machine measures 1.086x (AR 20.91, MTP 22.70);
HEAD measures 1.163-1.167x (AR 20.48-20.95, MTP 23.83-24.45) with identical
acceptance (0.561) and identical cycle counts prompt for prompt. The same-session
pair is therefore 1.086 → 1.163: HEAD is non-regressive and faster, and the
2026-10-14 absolute rates were not reproducible on this machine.

**Served economics by width** (`scripts/qwen4exp_http_mtp_economics.py`, new):

| width | AR arm | AR tok/s | MTP tok/s | MTP/AR |
| --- | --- | --- | --- | --- |
| 1 | serial c1 (shipped default) | 18.93 | 23.80 | 1.257 |
| 1 | opt-in AR batch path | 13.39 | 23.77 | 1.775 |
| 2 | AR batch path | 18.35 | 24.40 | 1.330 |
| 4 | AR batch path | 28.80 | 24.92 | 0.865 |

MTP throughput is flat across widths because a speculative row keeps a
request-owned c1 runner and never joins a batch step, while AR scales with width.
At width 4 one MTP request runs 1.5-3.1x faster than its AR peers in the same
wave but costs those peers 7-17%, netting -7% aggregate.

## Decisions

- **Serving default stays `--speculative-mtp-serving opt_in`.** Evidence-gated
  `auto` needs an artifact-identity path in `Qwen4ExpGGUFTextGenerator`
  (`_kv_weight_quant_key`, `_kv_model_artifact_identity`) that does not exist;
  Qwen35 has it, Qwen4Exp does not, and inventing an identity for a four-shard
  directory would silently enable MTP for the wrong artifact. The measured scope
  to encode when it exists is `realized_group_rows` 1..2, greedy, budget 3, BF16
  KV, context <= 2048.
- **No default change for AR batching.** The AR batch path is slower than serial
  c1 below four rows (13.39 and 18.35 against 18.93). It is the only route that
  reaches 28.80 at width 4, so the fix is a solo-row fast path, not disabling it.

Both are recorded in `docs/REFACTOR.md` with the measurements and the condition
to revisit.

## Changes

- `hipengine/server/api.py`: `_CompositeGenerationCancellationToken.cancel_requested`.
- `hipengine/generation/qwen4_exp_serving_mtp.py`: probe `cancel_requested` with
  `getattr`, like `engine_service.py` and the HTTP route already did.
- `tests/test_unit_server_composite_cancellation.py`: the crash, the composite
  contract, and the probe's tolerance for a token without the attribute.
- `scripts/qwen4exp_http_mtp_economics.py`: served AR/MTP arms at a fixed width,
  with `mixed` (one MTP request per wave) and a hard check that a requested MTP
  request actually executed MTP.
- `benchmarks/results/2026-10-18-qwen4exp-mtp-economics/`: README plus nine
