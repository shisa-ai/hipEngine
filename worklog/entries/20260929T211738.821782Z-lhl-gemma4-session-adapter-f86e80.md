# Build the Gemma4 control-smoke session adapter (piece B shim)

## Summary

Piece (B)'s contract is a session with `prefill`/`step` returning
`(.logits, .token_id)` under a context manager. Gemma 4 has no such class --
Qwen, Laguna, Qwen4Exp and Paro each have one; gemma 4 has only the runner --
so `hipengine/runtime/gemma4_session.py` supplies it as a thin adapter over
`Gemma4Runner`. Built deliberately without construction logic: the caller owns
weight loading, this class owns the session contract and its lifecycle.

## Decisions

- **`backend` and `target_arch` live on the session, not the runner.** The
  control smoke reads `session.runner.backend` and `session.runner.target_arch`
  (lines 661-662), but `Gemma4Runner` is a dataclass with neither field, so
  the smoke's gemma4 mode will read them off the session instead. Guessing them
  from the weights was rejected: the caller already knows them.
- **`prefill` and `step` both delegate to `forward`.** The runner documents
  this itself: "a decode step is a prefill of one token", so the adapter does
  not duplicate a path that does not exist.
- **The Qwen-shaped keywords (`use_bulk`, `bulk_attention_mode`,
  `capture_hidden_seed_fp32`) are accepted and ignored, not reinterpreted.**
  Gemma 4 has no GDN and no bulk-attention split, so mapping them onto
  something would be inventing a feature; accepting them keeps the shared call
  site honest. Unit-tested so the acceptance is pinned.
- **`return_logits=False` raises `NotImplementedError` naming itself.** The
  runner always returns logits, so honouring the flag would mean doing the work
  and throwing it away. Failing loudly beats silently discarding, and the
  smoke never passes False.
- **`reset()` fails if the runner lacks it**, rather than being faked by
  mutating position -- only the runner knows what accumulated state needs
  clearing.
