# Paged prefill attention route gap profile

## Summary

The prefix-placement cost model guarded against the paged suffix-prefill
route; this unit profiles *why* that route is slow and sizes the kernel
campaign. A new route-forced probe drives the same radix hit through both
routes on identical geometry (forcing `_gguf_device_kv_contiguous_base_row`
to `None` reproduces the exact gapped-route branch) and rocprofv3 attributes
the gap to one kernel family: the native three-pass
`qwen35_paged_full_attn_prefill_gqa_gate_bf16_kernel` costs ~79 ms per
full-attention layer where AOTriton's `attn_fwd` does the same 512-row suffix
over a 2048-token prefix in ~2.3 ms — a ~34x per-launch gap on gfx1151
(Qwen3.5-0.8B, 8q/2kv/256d, 6 full-attn layers). Host TTFT only shows 3.4x
because the 18 linear-attention layers and projections dominate the shared
wall. No production code changed.

## Changes

- `scripts/gguf_prefix_route_rocprof_probe.py` (new, diagnostic): three arms
  (`hit-contiguous`, `hit-paged`, `miss`), verified by the packed-slab plan's
  `device_kv_nonidentity_scatter` flag and by direct block-id contiguity
  evidence. `--mode time` for host timing; `--mode rocprof` wraps one child per
  arm under `rocprofv3 --kernel-trace --hip-runtime-trace` after a
  non-profiled warmup child prebuilds the JIT cache
  (`HIPENGINE_REQUIRE_CACHED_BUILD=1` + pinned
  `HIPENGINE_COMPILER_VERSION_FILE`, per `AGENTS.md` profiler rules).
- Probe route forcing details: the pool is pinned to one chunk (no growth
  window, so placement is a property of the arm, not allocator history) and
  the source is released with `retain_prefix_snapshots=True` to match the
  served multi-turn flow. An active source's decode-tail page lands between
  the shared prefix and the hit's suffix page, which is a *real* gapped
  placement — verified `[12,13] + [15]` against source `[12,13,14]` — so the
  active-source lifecycle is selectable for that case.

## Validation

- Route forcing proof, 0.8B, prefix 512 / suffix 128, gfx1151:
  `hit-contiguous` -> block_ids contiguous, `scatter=False` (slot-local
  AOTriton); `hit-paged` -> `scatter=True`; the probe hard-asserts both.
- Host A/B, 0.8B, prefix 2048 / suffix 512, gfx1151:
  suffix prefill `hit-contiguous` 169.5 ms (0.33 ms/token),
  `hit-paged` 621.7 ms (1.21 ms/token), `miss` 1874.8 ms TTFT — the gapped
  hit is 0.33x the miss it replaces, consistent with the retained 0.63x
  crossover point measured at the same geometry.
- Host A/B on the regression lane, Qwen3.6-35B-A3B `UD-Q4_K_M`
  (16q/2kv/256d, 10 full-attn + 30 linear layers), prefix 2048 / suffix
  6144 (8192 context), gfx1151: `hit-contiguous` suffix prefill **8,185 ms**
  (1.33 ms/token), `hit-paged` **134,511 ms** (21.9 ms/token) — a **16.4x**
  route gap reproducing the production 114 s / 6,186-token lane almost
  exactly; `miss` TTFT 138,672 ms, i.e. the gapped hit sits right at the
  crossover, which is what the 512-token guard protects. Single-run
  diagnostic; the campaign protocol would use the repetition/alternation
  harness.
- rocprofv3 `--kernel-trace`, same geometry, whole-child traces diffed across
  arms (children include one warmup + one measured case):
  - `hit-contiguous`: `attn_fwd` 24 calls / 79.0 ms total; no paged prefill
    kernel launches.
  - `hit-paged`: `qwen35_paged_full_attn_prefill_gqa_gate_bf16_kernel<false,
    false>` 18 calls / 1645.9 ms total; `attn_fwd` only 6 calls / 25.8 ms
    (the warmup source's slot-local prefill). Per suffix case: 6 launches x
    ~79 ms vs AOTriton's 6 x ~2.3 ms.
  - The measured case's own source prefill landed on a gapped placement after
    the warmup fragmented the free list and ran the paged kernel at
    grid rows=2048 (~115 ms/launch) — an unprompted reproduction of the
    production failure mode inside the profiled child.
- Where the gap lives, from the kernel source + trace: the three-pass kernel
  launches one 64-thread block per (q_head, row) with no K/V tiling — each
  block materializes all visible scores in LDS (~11 KB/block at 2.5k context,
  capping occupancy), runs a 3-pass global softmax over them, then a scalar
  sequential value pass with 2-byte loads; and each block re-reads its whole
  visible KV prefix, so KV traffic is redundant by kv_group (4x on 0.8B, 8x
  on the 35B) and again across query rows. AOTriton instead tiles K/V through
  LDS with online softmax and amortizes reads across query-row blocks.
- Kernel trace evidence: `/tmp/gguf-prefix-route-probe-rocprof/artifact.json`
  (diagnostic; not a retained performance claim).
