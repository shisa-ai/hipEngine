# Surya qualification harness fails closed on missing evidence

## Summary

`scripts/surya_perf_compare.py` reported `PASS` on a lane that had no
correctness basis. The gate was
`ids_match is not False and task_format and e2e_agrees`, which meant:

- a case with no reference passed on output format alone, because `ids_match`
  was `None` and `None is not False` is true;
- `decode_repeatable` was recorded but never required, so a decode loop that
  observed its own previous repeat still passed;
- termination was recorded but never compared, to the reference or between the
  timed decode stage and the end-to-end run;
- `_load_oracle` returned `None` for a declared fixture that was missing, so an
  absent file silently became "no reference" rather than an error;
- the docstring promised that a fixture-less case falls back to "the hipEngine
  CPU reference computed in the same process", but `main` only called
  `_load_oracle`. Nothing computed that reference, yet the record still reported
  `correctness_basis: cpu_reference`.

The two committed `rect` rows are the evidence: `ids_match: null`,
`correctness: PASS`, `correctness_basis: cpu_reference`.

## Changes

`_validate` now builds an explicit gate map and fails closed. `PASS` requires
all of: `reference_present`, `ids_match` (full-sequence equality),
`termination_match`, `decode_repeatable`, `e2e_agrees`,
`e2e_termination_agrees`, and `task_format`. Every condition that did not hold
is named in `gate_failures`, so a `FAIL` is self-explaining rather than a label;
the console summary prints those names.

`termination_match` compares the lane's termination against the reference's,
which `_reference_termination` derives as `length` when the reference fills its
budget and `eos` otherwise. Deriving it rather than storing it keeps the check
valid for fixtures captured before the metadata existed, and makes it
impossible to match ids while having terminated differently.

`_load_oracle_record` now raises `FileNotFoundError` for a declared fixture that
is absent and `KeyError` for a declared `oracle_key` that is not in the file.
Only `oracle=None` means "compute the CPU reference".

`_resolve_reference` performs the fallback the docstring promised: a captured
torch fixture when the case declares one, otherwise `_cpu_reference`, which runs
the `hipengine_cpu` lane's pipeline. That makes a GPU lane's `ids_match` a
genuine cross-implementation comparison; for the CPU lane itself the check is
self-consistency, and the reference's own accuracy is gated against the torch
fixtures by `tests/test_surya_e2e.py`. Exactly one case (`rect`) declares no
fixture, and a test pins that.

The artifact protocol gains a `gate` field stating the conditions, because a
`PASS` in a published row has to be auditable without reading the harness. The
basis label is no longer guessed either: a caller that supplies a reference
without naming its source records `unspecified` rather than `torch_fixture`,
so a CPU reference cannot be published as a captured fixture.

## Validation

RED first: 12 new/updated tests were run against the unmodified harness and
failed on the exact defects above (`test_validation_fails_closed_when_no_
reference_is_available`, `test_pass_requires_decode_repeatable`,
`test_pass_requires_termination_to_agree_with_the_reference`,
`test_pass_requires_e2e_termination_to_agree_with_the_decode_stage`,
`test_gate_failures_is_empty_only_for_a_clean_pass`,
`test_reference_termination_comes_from_the_budget`,
`test_a_declared_but_missing_oracle_file_is_an_error`, and four main-loop tests).
After the change: `tests/test_surya_bench_harness.py` 33 passed.

Hardware re-qualification of the previously unverified case:

```
HIPENGINE_HIP_ARCH=gfx1151 python3 scripts/surya_perf_compare.py --cases rect \
  --lanes hipengine_gpu,torch_cuda --runs 3 \
  --out benchmarks/results/2026-09-12-gfx1151-surya-rect-reference.json
```

Host: AMD Ryzen AI Max+ Pro 395, Radeon 8060S (gfx1151). The main loop computed
the CPU reference in-process (3 tokens, terminating on EOS); both lanes matched
it exactly with empty `gate_failures`:

| lane | ids_match | reference | termination | decode_repeatable | e2e_termination | tok/s |
| --- | --- | --- | --- | --- | --- | --- |
| hipengine_gpu | true | cpu_reference, 3 tokens | eos = eos | true | eos | 54.50 |
| torch_cuda | true | cpu_reference, 3 tokens | eos = eos | true | eos | 26.25 |

The superseded run measured the same case at 54.15 and 26.62 tok/s, so the
re-qualification reproduces the timings and adds the missing basis.

Offline evaluation of all 24 committed suite-baseline rows against the new gate:
22 already satisfied every condition; only the two `rect` rows failed
`reference_present` and `ids_match`. Those rows now carry
`qualification: unverified` and `requalified_by` in the baseline artifact, and
the artifact records the gate that was in force at capture time.

## Next

- The other 11 cases' rows were captured under the old gate. They happen to
  satisfy the new one, but a fresh suite run under the new gate would make the
  artifact self-consistent rather than retro-audited.
- Task-level checks still establish output format, not transcription accuracy,
  for a page whose text is not compared. Exact ids against a reference is the
  accuracy gate; where a page has no meaningful text (the synthetic bar
  patterns) the format check is all that can apply.
