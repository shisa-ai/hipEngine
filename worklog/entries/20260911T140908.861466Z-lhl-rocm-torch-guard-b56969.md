# ROCm/torch guard: two stacks cannot share a process

## Summary

`python -m pytest tests/ --co` errored at collection with

    OSError: .../_rocm_sdk_core/lib/libamdhip64.so.7:
    undefined symbol: hsa_amd_vmem_export_fabric_handle, version ROCR_1

attributed to `tests/test_dms_sidecar_training.py`, which interrupted the whole
session. Root cause, established by bisection rather than guessed: `hipengine`
loads the process HIP runtime with `ctypes.CDLL("libamdhip64.so")`
(`hipengine/core/hip.py`), which resolves to the *system* ROCm
(`/opt/rocm/lib/libamdhip64.so.7`, ROCm 7.2). Once that is loaded, torch's
`rocm_sdk.initialize_process()` tries to preload its own
`_rocm_sdk_core/lib/libamdhip64.so.7` and cannot resolve a symbol the
already-loaded system ROCR lacks. Only one ROCm stack can be loaded per process.

Any test module that imports both hipengine and torch hits this: the eleven
`tests/test_dms_*.py` modules that import hipengine poison the process, and the
two torch importers (`test_dms_sidecar_training.py` at module level,
`test_dms_labels.py` inside a test body) then fail. `pytest.importorskip("torch")`
does not help: the failure is an `OSError` from `dlopen`, not an `ImportError`.

The honest outcome in this environment is a skip with a diagnostic, which is what
the repository's HIP-availability-guard rule prescribes for an unusable runtime.
A genuinely working torch bridge would need the environment to expose a single
ROCm install; that is an environment fix, not a repository one.

## Changes

- `tests/_rocm_guard.py` (new): `hip_runtime_available()` plus
  `torch_or_skip(context, module_level=...)`, which probes HIP, catches both
  `ImportError` and `OSError`, and skips with the underlying message.
- `tests/test_dms_sidecar_training.py`: replaced `pytest.importorskip("torch")`
  + `import torch` with the module-level guard.
- `tests/test_dms_labels.py`: replaced the in-test `pytest.importorskip("torch")`
  with the call-time guard.
- `tests/test_rocm_guard.py` (new): 4 CPU tests pinning the guard.
- `docs/TESTING.md`: new section 2.1 documenting the two-stack conflict and the
  required helper.

## Validation

- `python -m pytest tests/ -q --co` - full-suite collection now completes with no
  error (previously interrupted by the collection error).
- `python -m pytest tests/test_dms_sidecar_training.py tests/test_dms_labels.py
  -q -rs` - passes with two explicit skips carrying the `dlopen` diagnostic.
- `python -m pytest tests/test_rocm_guard.py -q` - 4 passed.

## Next

- If the environment is later fixed to a single ROCm install, the guard returns
  torch and the tests run; no change needed.
- The other `test_dms_*` modules still import hipengine, which is fine - they do
  not import torch, so they run normally.
