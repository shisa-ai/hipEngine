# Enable Surya GPU generator on gfx1100

## Summary

Register the Surya OCR 2 GPU generator for `hip_gfx1100` in addition to
`hip_gfx1151`. The runtime (`hipengine/runtime/surya.py`) explicitly targets
"gfx1100-class" RDNA3 devices and builds its kernels from the `hip_gfx1100`
tree; the gfx1151-only registration was a stable-host artifact, not a capability
boundary. Validated end-to-end on the W7900 before shipping. This unblocks the
Surya public-generation entries on this host.

## Changes

- `hipengine/generation/surya_gpu.py`: register the GPU factory for both
  `hip_gfx1100` and `hip_gfx1151` (loop over the two RDNA3 backends); update the
  module/factory docstrings. No arithmetic, kernel, or admission-logic change —
  the same factory and runtime now resolve on both backends.
- `tests/test_unit_surya_generation_contract.py`: add
  `test_surya_gpu_registered_for_both_rdna3_backends` pinning both registrations
  and that each resolves to `make_surya_generator_gpu`.

## Validation

- Capability test first: a driver registered the factory for gfx1100 at runtime
  and served `tests/fixtures/surya/page_rect.png` through the real HTTP chat
  route — status 200, layout-JSON OCR output, clean teardown. Then the production
  registration was added and the driver re-run WITHOUT the runtime override:
  identical result, confirming the shipped registration.
- Prompt-count contract (R0494 Surya half): HTTP usage.prompt_tokens =
  GenerationOutput.prompt_tokens = expanded runner prefill length = 198;
  tracked allocations drain to zero at close
