# Observe the graphed build warmup before the first timeout clear

## Summary

The exchange containment repair (`30608782f`) made an eager `enqueue_rank` count
as unobserved work, which is correct for the rule it enforces but broke the
shipped TP2 route: `_build_graph_schedule` runs one eager warmup token whose
head-sharded attention reductions are submitted on the session's device
exchange, nothing waits for them, and the first step's `step_begin` then refused
to clear the flags. The full workspace ladder failed at position 52 on the
W7900 + RX 7900 XTX with that refusal.

A probe of the real schedule showed the mechanism: the warmup submitted 256
enqueues on the session exchange (64 layers x 2 ranks x 2 phases), the capture
recorded 126 enqueue-only successes that correctly did not count, and the bulk
prefill's 128 counter bumps and single wait belonged to the *group's* separate
exchange object, so nothing observed the session exchange's warmup.

## Changes

- Add `CompiledDeviceExchange.has_unobserved_work`, so a caller about to clear
the timeout flags can ask whether earlier submissions have been observed.
- `_build_graph_schedule` now waits after the eager warmup when that work is
  outstanding. The wait is conditional, so an unsharded graphed build (whose
  warmup submits nothing on this exchange) keeps its previous call sequence.
- Replace the session tests' hand-rolled device-exchange double with the real
  wrapper over a fake driver, including the native driver's capture-status
  answer. The double previously had no unobserved-work rule, so no CPU test
  could catch a schedule that submits work and never observes it.
- Add the regression test: the build must observe the warmup before the first
  `step_begin`, and the exchange must report no unobserved work afterwards.
