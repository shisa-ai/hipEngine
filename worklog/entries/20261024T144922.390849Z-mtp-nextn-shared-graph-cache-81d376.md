# Share speculative graph cache ownership with GGUF NextN

## Summary

Shared graph-stage lifecycle ownership now has a real GGUF NextN consumer.
Six public candidate calls match parent token IDs and actually replay proposal
graphs. This refactor makes no speed claim and does not finish PARO graph adoption.

## Changes

- Add the bounded `SpecGraphStageCache` and immutable address/shape/configuration
  bindings. Providers retain kernels, graph capture and HIP-handle ownership.
- Migrate NextN proposal graphs; invalidate stale bindings, retry capture after
  failures, retain failed releases and report unresolved cleanup to the owner.
- Zero destroyed handles so retries cannot double-destroy them. Release all
  resources before reporting cleanup failures, and do not suppress interrupts.
- Include intermediate scratch and named repacked-weight allocations in bindings.
  Block further captures while partial-capture cleanup still owns resources.
