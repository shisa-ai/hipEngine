# Repair stale packed workspace interleave fake

## Summary

`tests/test_gguf_packed_workspace_stability.py::test_packed_workspace_
interleave_is_alloc_stable` has been failing since the capacity-honest
workspace right-size. Bisected with clean worktrees: passes at f140c72f7
(persistent union-geometry packed workspace), fails at b753495b4 (right-size
packed workspace lease to serving capacity). Root cause is a stale test fake,
not a production defect: the fake owner is built with `object.__new__` and
never sets `max_batch_size`, so `getattr` resolves the dataclass class default
of 1, and the capacity-honest union (`_packed_verify_union_geometry`) sizes
the first allocation to 1 slot — the interleave's slot-4 request must then
free/reallocate by design. Production sessions declare the real serving cap
(max_active_requests), so the first allocation already covers every geometry
the scheduler can request; the right-size evidence stands (no legitimate
>1-slot request exists below the declared cap, MTP widths and packed groups
included).

Repair: the fake declares `max_batch_size = 4` (the interleave's stated
serving cap), and a new contract test pins the capacity-honest first
allocation (`slot_count == max_batch_size`, `gdn_segment_capacity ==
max_batch_size`) — guarding against regression to per-request sizing (churn)
and to the historical fixed 8-slot floor (wasted residency at small caps).
The interleave contract itself is unchanged and enforced.
