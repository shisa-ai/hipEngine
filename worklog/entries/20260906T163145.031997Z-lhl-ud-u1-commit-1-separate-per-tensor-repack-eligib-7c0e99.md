# UD-U1 commit 1: separate per-tensor repack eligibility from global F32 contraction in qwen35_gguf_policy

## Summary

UD-U1 policy prerequisite (`docs/UD-QUANTS.md` section 6): the shared
dense-weight policy now carries two independent predicates — per-tensor repack
eligibility (`gguf_ar_decode_repack_veto`) and global F32 linear contraction
(`gguf_ar_f32_linear_contraction`) — both currently delegating to the existing
`gguf_ar_raw_iq_contract`, so today's behavior is byte-identical while the two
decisions no longer share one flag. MoE semantics are unchanged: the contract
exempts rank-3 expert slots in both predicates.

## Changes

- `hipengine/loading/qwen35_gguf_policy.py`: added
  `gguf_ar_decode_repack_veto` and `gguf_ar_f32_linear_contraction`, exported
  via `__all__`; both delegate to `gguf_ar_raw_iq_contract` (no behavior
  change, no new env flags, no backend/quant branches).
- `hipengine/loading/qwen35_gguf_materialize.py`:
  `plan_qwen35_gguf_materialization` gained optional `repack_veto` /
  `contract_f32_linear` kwargs (None → derived exactly as before; default
  behavior identical for every existing caller).
- RED-first tests in `tests/test_loading_qwen35_gguf_policy.py` and
  `tests/test_qwen35_gguf_materialize_helpers.py` (synthetic raw-IQ AR fixture
  with ffn shapes (17408,5120)/(5120,17408), `dense_q4_t16=True`): each
  predicate returns True on the raw-IQ manifest while the plain Q4_K/F32
  manifest returns False; the two materialization kwargs pin the derived and
  override paths.
