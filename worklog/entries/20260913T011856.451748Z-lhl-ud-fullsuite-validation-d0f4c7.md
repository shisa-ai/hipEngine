# Full-suite validation: one real regression from the evidence ordering, fixed

## Summary

The session's changes were validated with a full `pytest` run. One real
regression was found and fixed; the remaining failures are pre-existing.

## The regression: evidence-tuple position is part of the contract

The UD serving-evidence rows were first **prepended** to
`Qwen35GGUFModel.speculative_mtp_serving_evidence`. That broke 18 tests in
`tests/test_speculative_mtp_serving_capability.py`, which selects rows by
position — `Qwen35GGUFModel().speculative_mtp_serving_evidence[0]` — so every
index shifted by two and the resolver returned a different row than the test
expected.

The fix is to **append** the UD rows instead:

```python
speculative_mtp_serving_evidence = (
    _QWEN38_Q4KM_MTP_SERVING_EVIDENCE
    + _Qwen36_DENSE_Q4KM_MTP_SERVING_EVIDENCE
    # Appended, not prepended: the declaration order is the resolver's
    # tie-break, and the existing rows' positions are part of the retained
    # evidence ordering that the serving tests assert.
    + _UD_Q4K_MTP_SERVING_EVIDENCE
)
```

This is the right fix rather than updating the tests: declaration order is the
resolver's documented tie-break, so appending keeps every existing artifact's
resolution identical and only adds rows for artifacts that had none.

After the fix, `tests/test_speculative_mtp_serving_capability.py`,
`tests/test_ud_mtp_certification.py`, `tests/test_gguf_ud_admission.py`,
`tests/test_ud_mtp_paired.py` and `tests/test_gguf_mtp_c1c8_server_bench.py`
pass together with no failures.
