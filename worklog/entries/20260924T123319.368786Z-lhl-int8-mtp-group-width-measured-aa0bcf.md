# The INT8 c2 and c4 groups verify as real wider groups

## Summary

Task #27's acceptance asks for the c4 row to be read the way the prior artifact
had to be read: per-request cycle and draft counts identical to c1 could mean
singleton cycles sharing a wider batch rather than a wider group. They are
identical at every width, so the question was open and is now measured. The
group is real.

```
scripts/gguf_mtp_packed_group_width_probe.py --widths 2,4 ...
=== packed target verifier group width (jobs per call) ===
  jobs=2: 91 calls
  jobs=4: 91 calls
  total calls: 182
=== end group width ===
```

Every packed verifier call carried the whole group; none carried one job. The
probe patches `Qwen35GGUFResidentSession.verify_target_blocks_batch`, which is
invoked with one job per row of the cycle group, and records `len(jobs)` per
call -- the same number the call publishes to the kernels as
`target_verifier_active_slots`.

## Why the counts are identical, and why the plan could not settle it

`plan_group_rows` is the plan (1, 2, 4 by width) and `verifier_rows` is a
declared shape field, not a counter, so neither answers what ran. Identical
per-request counts are exactly what a fused group produces: all rows step
together, one packed call per cycle carries the whole group, so every row
reports the same cycle count. The sweep's arithmetic agrees with the histogram
-- 83 request-cycles per width at widths 1, 2 and 4, i.e. one group call per
cycle covering 1, 2 and 4 rows.

## Changes

- `scripts/gguf_mtp_packed_group_width_probe.py` (new, `326ed0022`). Wraps the
  benchmark unchanged, adds the patch, prints the histogram at exit, and warns
  when a call in a run wider than one carried a single job.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: the closed row now carries the
  histogram, the reasoning above, and the probe as its method, so the
  engagement at c2 and c4 is not read as route intent alone.

## Validation

The probe was run from its committed path on the same cell the row's sweep used
(`--kv-storage int8_per_token_head --mtp-request-mode automatic`, widths 2 and 4,
resident capacity 4, candidate budget 2, 24 tokens, the same prompt set), with
`HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED=1`. Both widths report every cell
engaged and exact, matching the sweep. The first run of the same code from a
scratch path printed the same histogram, so the measurement is repeatable rather
than a single sample.
