# Repair native rollback and use cache capacity for dense C1 MTP

## Summary

The historical p121/p128 NaN/sentinel no longer reproduces after the C1 scratch
and metadata repairs in `6c01f1f1c`. Untested lengths are not presumed broken:
the dense H5120 Q4_K_M gfx1100 route now uses allocated capacity, not a new
numeric qualification ceiling. Public serving admission is independent.

Long-context testing did find a real remaining bug at the 1024 kernel-family
transition: scalarized native rows omitted initial Conv/GDN snapshots.
Selected state and logits matched AR, but rollback restored incorrect state.
Copying the initial buffers before the first mutation repairs that failure.

## Changes

- Backend geometry/quant policy removes the obsolete p95 workaround for dense
  Q4_K_M with BF16 KV and FP32 recurrent state. Other model/quant/state routes
  retain their existing dispatch. A provisional 256 limit was explored, then
  removed rather than converting test coverage into a capacity restriction.
- Graph-owned metadata no longer depends on bulk-prefill device metadata's
  4096-token threshold. Actual cache capacity, row support and topology
  transitions still control capture; eager native remains valid at transitions.
- Scalarized rows snapshot initial state with stream-ordered D2D copies.
  Eager verification no longer reports stale prior graph telemetry.
- Both runtime and generation construction consult the shared context resolver.
- Diagnostic harnesses now cover explicit historical-policy overrides,
  following-step logits/state, GPU1 interference detection and compact hashed
  summaries. Fixed-length cyclic prompts are diagnostics, not speed evidence.
- The summarizer's optional performance-pair gate requires matching clean
  source/hardware/model, full ten-prompt natural suites, three or more repeats,
  warmup, true AR, exact IDs/GPU acceptance, zero leaked allocations, no
  interference and actual policy engagement. Suite timing labels now use the
  requested output count rather than hardcoding natural25.
