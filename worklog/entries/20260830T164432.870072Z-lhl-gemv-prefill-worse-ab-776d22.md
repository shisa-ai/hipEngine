# All-GEMV small-row prefill is 15-36% worse than WMMA; route A/B closed

## Summary

Measured the route alternative for small-row prefill with the existing diagnostic knob.
**All-GEMV prefill is
15-36% worse than the shipping WMMA route**, so the small-row prefill deficit has no
route-level escape and
belongs to the WMMA kernel itself. This closes the option recorded in the "All-GEMV
small-row prefill A/B"
`docs/REFACTOR.md` item.

## Changes

- No code change; the knob already existed (`HIPENGINE_GGUF_DIAGNOSTIC_WMMA_PREFILL`, read
  at session-acquire
  time, default shipped True). Both arms were run with it, which is exactly what the knob
  was added for.

## Measured

Same protocol both arms: `scripts/gguf_mtp_c1c8_server_bench.py --widths 1,2,3
--candidate-budget 3 --max-tokens
24 --generation2-diagnostic`, 10 prompts, clean tree `ce01b326c`, packets
`/tmp/he-parity/pf-wmma.json` (default) and `pf-gemv.json` (env `=0`). Mean tok/s:

| C | AR WMMA -> GEMV | AR delta | MTP WMMA -> GEMV | MTP delta |
| --- | --- | ---: | --- | ---: |
| 1 | 22.18 -> 18.85 | -15.0% | 31.91 -> 25.41 | -20.4% |
| 2 | 32.33 -> 25.29 | -21.8% | 40.36 -> 28.82 | -28.6% |
| 3 | 45.58 -> 31.97 | -29.9% | 54.95 -> 35.12 | -36.1% |

- Every cell in both arms reports `exact` true (10/10 each). Note this is the cell's self-
  consistency contract
  (`ar_mtp_equal`), not cross-route token equality; cross-route generated ids were not
  compared, and the
  conclusion does not depend on it - the GEMV route loses on wall time regardless.
- Baselines reproduce the rollup within repeat noise (AR C1 22.18 vs published 21.999; C3
  45.58 vs 45.309).

## Consequence for #12

- The deficit is inside the WMMA small-row path, where it was already localized
  (`20260830T153252…`: ~178.9 ms
  compute against an ~18.5 ms streaming floor at ~45 rows). Fixing it means kernel work -
  tiling / occupancy for
  row counts below the tile height - with strict `kernels/cpu_reference/` parity and a
  `rocprofv3` entry, not a
  dispatch choice.
- Do not re-propose the all-GEMV route for small rows; it is measured worse, and
  monotonically worse with width.

## Validation

- Two same-session arms, named packets and command above; deltas computed per width over
  all 10 prompts.
