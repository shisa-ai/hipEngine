# The divergence splits on the batched suffix prefill, and the production-shaped comparison is bit-exact in every category

## Summary

The dense27B oracle divergence is localized: it splits on whether the 200 suffix
tokens go through a **separate batched prefill call**, and the comparison that
reproduces the production schedule is bit-exact and token-exact in every
category, Japanese included. The failing comparisons are all against
shape-different routes whose references disagree with **each other** on the
Japanese prompt, so they cannot define bit-equality for the production shape.
This supersedes the attribution in
`20260919T235416.068373Z-lhl-dense27b-ja-prefill-shape-vote-aec968`, which
labeled the candidate route "256-row chunks". That label was wrong: the gate's
candidate prefills the prefix in a **single** batched call.

## Changes

- None. Two measurements: the served-route chunk-width sweep and a re-read of
  the gate's own route shapes and mismatch summaries.

## Validation

**Route shapes (read from `scripts/gguf_prefix_reuse_gate.py`).**
`_prefill_work` (line 357) puts every token of a prefix into one `WorkItem`, so
the candidate is `prefill_batch(prefix)` then `prefill_batch(suffix)` -- two
batched calls, 1,024 rows and 200 rows. `scheduler_chunk_diagnostic` (lines
608-632) is `prefill_batch_native([prefix], full_prompt_lengths=[1224])` then
`prefill_batch_native([suffix], ...)` -- the same two-call shape through the
native production path. The other two are shape-different:
`one_shot_bulk_diagnostic` is a single `prefill(continued_prompt)` over all
1,224 rows, and the serial route is `prefill(prefix)` plus 200 single-row
`step()`s. The 256-row chunking I previously attributed to the candidate is the
scheduler's tick width in `hipengine/generation/engine_loop.py`
(`HIPENGINE_MAX_PREFILL_CHUNK_TOKENS`), not the gate's candidate.

**The production-shaped comparison passes bit-exactly.**

| category | scheduler boundary / final mismatches | `output_exact` | scheduler token | candidate token |
| --- | --- | --- | --- | --- |
| `code` | 0 / 0 | True | 248046 | 248046 |
| `general_ja` | 0 / 0 | True | 271 | 271 |

`clone_boundary` is 0 in both. So the candidate is bit-identical to an
independently built oracle that reproduces the production schedule, in the
category that fails the outer smoke floor as well as the one that passes it.

**The Japanese references are not self-consistent.** On the same 1,224-token
prompt: one-shot `prefill(prefix)` predicts 174267, one-shot
`prefill(prefix + suffix)` predicts 96026, and `prefill(prefix)` + 200
single-row steps predicts 96026. Two different single-call schedules produce two
different first tokens, and neither matches the production schedule's 271. A
reference that disagrees with itself on the prompt under test cannot define
bit-equality, and the recorded ja `kl_mean` 0.68112127 was measured against that
unstable side, so it measures shape difference rather than accuracy.

**The served route is chunk-width invariant.** Sweeping
`HIPENGINE_MAX_PREFILL_CHUNK_TOKENS` over 128/256/512/1024 (one server per
width, greedy, `speculative_mtp` off, the two `general_ja` suite records
repeated to the target length) gives byte-identical output at every width,
reasoning channel included: sha256 `0eed9388d7cb0150dc4f...` for a 520-token
prompt and `a16610c71f1c324b4f787f05...` for a 1,416-token prompt, both with
`prompt_tokens` identical across widths. So the divergence is not a
chunk-width-dependent defect in the chunked path's cross-chunk state handoff,
which was the alternative reading left open by the superseded entry.

**Bound.** The divergence is confined to shape-different diagnostic routes. The
production schedule is self-consistent across two independent code paths
(0/0 mismatches, matching first tokens in both categories) and stable across
chunk widths 128-1,024 on a 1,416-token Japanese prompt. The gate's binding
comparison should therefore be the production-shaped one (candidate vs
`scheduler_chunk_diagnostic`), with the one-shot and serial routes retained as
diagnostics that record KL and top-1.
