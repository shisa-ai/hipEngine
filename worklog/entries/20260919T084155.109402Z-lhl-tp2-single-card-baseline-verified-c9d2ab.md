# Verify the single-card baseline before trusting the TP2 efficiency claim

## Summary

The previous entry (`20260919T074812.804331Z-lhl-tp2-prefill-scaling-diagnosis-4b71cf.md`)
concluded that each TP2 rank runs at ~65% of the single-card route's efficiency,
using the recorded 875.8 tok/s single-card baseline. That claim had an unverified
assumption underneath it, and checking it was worth the run.

**The risk.** Re-running the same single-card harness on this revision without
`--public-ar-profile` emitted
`shipping_ar_route_mismatch=true` - the *measured* route left `use_wmma_prefill`
off. The TP2 bulk prefill does run WMMA (`gguf_q4_t16_dense_wmma_prefill_shared_b`
is 41.8% of its profiled kernel time). So if the 875.8 baseline had been measured
WMMA-off, the comparison would have been against a crippled baseline and the
efficiency conclusion would have been backwards - the single card would really be
near 1400 tok/s and TP2 would be *behind* it rather than ahead.

**The check.** The shipping route re-measured with `--public-ar-profile`, which
reports `use_wmma_prefill=true`, `effective_use_wmma_prefill_all=[true x4]` and
`shipping_ar_route_mismatch=false`:

| single-card bulk prefill, 512 tokens, shipping route | tok/s |
| --- | ---: |
| sample 1 | 891.86 |
| sample 2 | 890.78 |
| **median** | **890.78** |

That confirms the recorded 875.8 (1.7% apart) rather than contradicting it, so
the efficiency claim stands. The corrected arithmetic:

- single card: 890.8 tok/s = **574.8 ms** for 512 tokens
- TP2: 922.1 tok/s = **555.2 ms**
- wall share 555.2 / 574.8 = **0.966**; work share 0.616
- per-rank efficiency = 0.616 / 0.966 = **0.64** (was reported as 0.65)
- if recovered: 555.2 x 0.64 = 354 ms = **1444 tok/s** (was 1420)

None of this changes the conclusion; it changes the third digit and replaces an
inherited number with one measured on the current revision with the route
explicitly confirmed.
