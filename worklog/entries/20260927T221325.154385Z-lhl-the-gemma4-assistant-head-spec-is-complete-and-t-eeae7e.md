# The gemma4 assistant head spec is complete, and the port is mechanical
## Summary
The previous entry recorded the algorithm from llama.cpp's reference. This entry
records the artifact's own hyperparameters and tensor layout, which together with
the algorithm make the port a mechanical task rather than a design one. The spec
is committed as an artifact so the loader can be written against it.
## The hyperparameters, read from the artifact
| key | value | meaning |
| --- | --- | --- |
| `block_count` | 4 | layers in the head |
| `embedding_length` | 1024 | `n_embd`, the head's width |
| `embedding_length_out` | **2816** | `n_embd_backbone`, the target's width |
| `feed_forward_length` | 8192 | head FFN width |
| `attention.head_count` | 16 | query heads |
| `attention.head_count_kv` | 8 per layer | GQA |
| `attention.key_length` / `value_length` | 512 | full-attention head dim |
| `attention.key_length_swa` / `value_length_swa` | 256 | sliding-window head dim |
| `attention.sliding_window` | 1024 | window |
| `attention.sliding_window_pattern` | per layer | which layers are SWA |
| `attention.shared_kv_layers` | **4** | see below |
| `rope.dimension_count` / `_swa` | 512 / 256 | rotary dims |
| `rope.freq_base` / `_swa` | 1e6 / 1e4 | two RoPE bases |
| `nextn_predict_layers` | 4 | matches `block_count` |

`embedding_length_out = 2816` independently confirms `n_embd_backbone` is the
target's width, which is what makes `2 * 2816 = 5632` the pre-projection input
width. Three sources now agree on that number: the reference's tensor shape, the
artifact's `nextn.pre_projection` dims, and this metadata key.
## The tensor layout
49 tensors, and the structure is uniform:
- **11 tensors per block**, identical names across all four:
  `attn_norm`, `layer_output_scale`, `attn_q`, `attn_q_norm`, `attn_output`,
  `post_attention_norm`, `ffn_norm`, `ffn_gate`, `ffn_up`, `ffn_down`,
  `post_ffw_norm`.
- **5 global tensors**: `token_embd` (Q8_0, 285 MB), `output_norm`,
  `rope_freqs`, `nextn.pre_projection` (Q8_0, 21.9 MB),
  `nextn.post_projection` (Q8_0, 3.1 MB).
**There is no `attn_k` and no `attn_v` in any block.** That is consistent with
`shared_kv_layers = 4` and with the reference calling `build_attn_inp_kv_iswa()`
rather than building its own cache: the head **attends against the backbone's KV
cache** and has no cache of its own. That is a significant simplification for the
port — no KV allocation, no eviction policy, no `KVLiveSpans` plumbing for the
head.
## Why this is mechanical now
- 4 identical blocks of 11 tensors, all Q8_0 for the linear weights and F32 for
  the norms.
- Every primitive the forward needs already exists in this engine: embedding
  gather, scale, concat, a linear, RMS norm, RoPE with two bases, attention with
  GQA and a sliding-window variant, an FFN with a gate, and the two nextn
  projections.
- The KV question is answered by the artifact rather than left open.
