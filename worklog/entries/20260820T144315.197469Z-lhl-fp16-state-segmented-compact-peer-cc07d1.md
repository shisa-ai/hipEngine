# Repair packed fp16-state prefill with segmented compact-peer GDN

## Summary

The clean packed c4/c8 FP16-state gate at `b211201a1` was measurement-valid
but failed binding prefill scopes despite globally small drift. Across 1,170
full-vocabulary rows, global mean/p95/p99/max KL was
`1.23e-4/5.24e-4/1.60e-3/1.22e-2` and top-1 was 99.573%, with exact repeats,
neighbor/permutation isolation, and indexed decode ownership. The failure was
localized to c4/c8 prefill and prefill transitions (top-1 75-96.15%). Packed
c>N had bypassed `chain_compact_peer_wave32` and used the decode-order
segmented fallback, causing an FP16 load/store and rounding boundary on every
prompt token instead of keeping FP32 state in registers like c1 production.

## Changes

- Added FP32 and FP16-state compact normalized-segments wave32-XOR kernels and
  raw-pointer wrappers. Grid axes are segment x V-head x value-column group;
  one wave32 owns a value column, maps compact K-head Q/K by V-head, retains
  four state rows/lane in FP32 registers across the segment, and writes the
  declared state dtype once at the packed chunk boundary.
- Registered both leaves with explicit four-axis variants and extended the GDN
  prefill plan with FP32/FP16 single and segmented compact-peer owners.
- `chain_compact_peer_wave32` now fails closed if the required state-dtype
  owner is absent. Packed c>N uses its segmented sibling; the decode-order
  segmented writer remains a generic fallback for non-compact routes.
- Generalized the host compact-peer oracle to FP32/FP16 storage and added a
  two-segment indexed RED for both. Fixed `test_qwen35_gguf_chunked_prefill.py`
  so its module-level missing-0.8B mark no longer silently skips the separate
  real Qwen3.8 production test, then ran that test with FP32 and FP16 state.
- Updated `docs/KERNELS.md`, `docs/REFACTOR.md`, and recorded the rejected
  baseline plus directional repair screen in
  `benchmarks/results/2026-08-20-gfx1151-qwen38-27b-r2-fp16-packed-prefill-audit.json`.
