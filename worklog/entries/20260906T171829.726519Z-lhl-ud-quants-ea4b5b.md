# UD-U1 repair 6: packed decode graph floor survives preset-bound policy identity

## Summary

U1 finding 6: `Qwen35GGUFResidentSession.packed_decode_graph_min_replay_steps`
unpacked `_gguf_policy_identity(...)` as exactly two elements
(`geometry, file_type_name = identity`), but the identity now carries an
optional third preset key, so any preset-bound resident raised
`ValueError: too many values to unpack (expected 2)` at graph-floor resolution.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`:
  - `packed_decode_graph_min_replay_steps` branches on identity arity instead
    of destructive unpacking and threads `artifact_preset_key` through.
  - `_resolve_gguf_packed_decode_graph_min_replay_steps` gains
    `artifact_preset_key=None`; preset-bound artifacts look up only an exact
    `(geometry, stamp, preset_key)` row and never read plain
    `(geometry, stamp)` rows — the qualification boundary is preserved, not
    discarded (unknown/preset identities fall back to the generic floor).
- Caller inventory (all other `_gguf_policy_identity` call sites are safe with
  both tuple shapes; no change needed):
  - `qwen35_gguf_runner.py` lines 11164, 11193, 11217, 11239, 11286, 11337,
    11405, 11636, 28552, 28613, 28644: use the whole identity as a dict key
    (`policies.get(identity)`) or inside a cache key; a 3-tuple simply misses
    2-tuple-keyed tables, which is the intended boundary.
  - `scripts/execution_profile_gguf_dense_pair_gate.py` and
    `scripts/qwen38_dense_pair_perf.py`: `policies.get(identity)` plus
    `repr(identity)` calibration evidence — arity-agnostic.
  - `tests/test_gguf_ud_admission.py`: constructs both 2- and 3-element
    identities explicitly.

## Validation
