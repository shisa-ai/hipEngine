# Decode Inkling NVFP4 scales from exponent bits

## Summary

Construct NVFP4 scale values from exponent bits rather than calling `ldexpf`. Keep the MXFP8 decode unchanged.

## Changes

- Preserve signed zero, subnormal values, NaNs, and all products and accumulation order. An independent GPU probe matched the previous scale decoder on every input byte.

## Validation

- `epyc` / Radeon Pro W7900 (`gfx1100`), original `thinkingmachines/Inkling-2-Mini` revision `ed40e7da625f594fc9c4990f5f66be24873c22d7`, `inkling2_mixed`, FP32 KV, single-request ordinary greedy decode. Baseline `21c384889`.
- `bash /tmp/hipengine-inkling2-verify.sh nvfp4scalebits`: warm median 15.6605 to 15.8535 tok/s at five input / 24 output tokens (three runs per arm). The synthetic 512-input / 128-output case rose from 13.4816 to 13.6290 tok/s (+1.09%), one run per arm, with identical output IDs.
- Warm trace per token: NVFP4 expert kernels 10.248 to 9.338 ms; MXFP8 unchanged at about 0.992 ms. All 54 focused tests passed. Public text and single-image packed DSpark matched ordinary and baseline IDs and counts; speculative throughput was not remeasured.
