# Gemma 4 P2: flash_attn_tile<512,512,4,8> compiles and instantiates on gfx1100

## Summary

P2 asks for tiled flash attention at head_dim 512 for the five `full_attention`
layers, and offered three routes: port llama.cpp's `flash_attn_tile<512,512,4,8>`,
an AOTriton head_dim-512 image (already closed with evidence), or an in-tree
WMMA kernel. This entry answers the route question by **building the port
target** instead of reasoning about it.

Model geometry, from `config.json`: `head_dim: 256` for sliding layers,
`global_head_dim: 512` for full layers, and exactly five `full_attention`
entries in `layer_types` (indices 5, 11, 17, 23, 29). `attention_k_eq_v: true`
confirms K and V share the projection while keeping distinct cached tensors.

**Result: route (a) compiles and instantiates for gfx1100.** Extraction plus a
small hand-written shim, `hipcc -std=c++17 --offload-arch=gfx1100`:

- zero errors, object 184,808 bytes
- both `_ZL15flash_attn_tileILi512ELi512ELi4ELi8ELb0E…` and `…ELb1E…` present
- `__hip_fatbin_wrapper` and `hipLaunchKernel` resolved

That settles three things the row had only asserted:

1. The RDNA table carries `CASE(512, 512, 32, 256, 2, 128, 64)`. ncols 32 is
   exactly `ncols1=4 x ncols2=8`, so the quoted shape resolves to 256 threads
   and occupancy 2 on RDNA3, and the kernel's
   `static_assert(config != 0)` passes.
2. The source is already ROCm-hardened — it carries its own workaround comment
   for "the ROCm compiler cannot handle templating in `__launch_bounds__`".
3. The dependency surface is tiny: four helpers (`ggml_cuda_get_max_cpy_bytes`,
   `ggml_cuda_unroll`, `ggml_cuda_mad`, `ggml_cuda_memcpy_1`) plus
   `fastdiv`/`fastmodulo`, `warp_reduce_{sum,max}`, `get_alibi_slope`, and
   `FATTN_KQ_MAX_OFFSET` / `NO_DEVICE_CODE` / `GGML_UNUSED_VARS`.

## Reproducing the extraction

```
F=~/amd-gpu-tuning/llama.cpp/ggml/src/ggml-cuda/fattn-tile.cuh
{ sed -n '7,347p' $F; sed -n '348,1115p' $F; } > body.hip
cat shim.hip body.hip inst.hip > t2.hip
hipcc -std=c++17 --offload-arch=gfx1100 -c t2.hip -o t2.o
```

`shim.hip` defines, in this order and no other: `GGML_USE_HIP`, `RDNA`,
`FLASH_ATTN_AVAILABLE`, `GGML_USE_WMMA_FATTN`, `RDNA3`, `FAST_FP16_AVAILABLE`,
`V_DOT2_F32_F16_AVAILABLE`, `FP16_AVAILABLE`, `WARP_SIZE=64`, `half`/`half2`,
the three `GGML_CUDA_CC_*`/`fast_fp16_available` predicates, then the helpers
above. `inst.hip` takes the address of both template instantiations. The live
copy of those three files was built at `/tmp/p2port/` on this machine; the
recipe above regenerates `body.hip` exactly and the shim is described precisely
enough to rewrite, but the shim text itself is not committed — it is scaffolding
for the port, not the port.

## Two traps that both first appeared as green

Both matter because each produced a misleading positive before the real
failure.

**"Compiles clean" with no kernel in the object.** A plain extract reports zero
errors and writes a **848-byte object containing only `__hip_cuid`** — no
kernel symbol, no fatbin. `flash_attn_tile` is `static __global__`, so nothing
referencing it means it is dead-stripped. The zero-error result proved only that
the code type-checks. Taking the kernel's address to force instantiation is what
surfaced every real error below.

**Five errors from one wrong macro.** The device-side config selector is

```c
static constexpr __device__ uint32_t ggml_cuda_fattn_tile_get_config(...) {
#ifdef GGML_USE_HIP
#ifdef RDNA                                  // not RDNA3
    return ggml_cuda_fattn_tile_get_config_amd_rdna(...);
#else
    return ggml_cuda_fattn_tile_get_config_amd(...);
```

Without `GGML_USE_HIP` it takes the `FAST_FP16_AVAILABLE` branch and lands in
`nvidia_fp16`, whose table has ncols entries 4, 8 and 16 but **not 32**. The
config therefore decodes to all zeros, which surfaced as five unrelated-looking
failures: `__launch_bounds__(0,0)` ("min must not be greater than max"),
`static_assert(ggml_cuda_fattn_tile_get_config(512,512,4*8) != 0)`, `cpw` not a
constant expression, a failed `static_assert(cpw == 1 || np == 1)`, and two
zero-length arrays. Defining `GGML_USE_HIP` and `RDNA` cleared all five at once.

A sixth error was independent: ROCm 7.2 requires `__shfl_xor_sync`'s mask to be
64-bit (`sizeof(unsigned int) == 8`). Every call site is in the shim; the kernel
body has none. Fixed with `0xffffffffffffffffULL`.
