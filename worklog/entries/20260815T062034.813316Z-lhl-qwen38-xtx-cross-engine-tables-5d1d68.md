# Publish Qwen3.8 XTX cross-engine tables

## Summary

Published same-file Qwen3.8-27B Q4_K_M comparison tables for the RX 7900 XTX.
The missing hipEngine 1K/4K rows and every llama.cpp HIP/Vulkan row were run
serially after an idle-card admission gate. The retained hipEngine 512 and
natural B3 values come from the immediately preceding clean-idle correction.
All external rows use clean same-commit llama.cpp `c8e03ce8122b7af76f836d53efde6df1ce5ec437`
binaries and the exact current model SHA-256
`7b2aec3b9ababdfd75aa17552ee95607d866e44decf547f6f12fcef85cc89f1b`.

## Changes

- Added `benchmarks/results/2026-08-15-qwen38-27b-xtx-hip-vulkan-comparison.json`
  with exact source/model/build identity, per-sample fixed-shape rates, 17
  SHA-tagged idle-admission snapshots, all ten llama.cpp B1-B5 natural rows,
  category/train/heldout rates, output-ledger hashes, memory/teardown fields,
  and the displayed table calculations.
- Replaced the public RX 7900 XTX 512-only summary with Qwen3.8 512/1K/4K
  prefill and decode tables plus the independently selected natural-MTP rows.
  Updated the detailed benchmark scoreboard and changelog in the same unit.
- The first continuation gate saw only the just-exited hipEngine PID as a stale

  recheck then reported `No KFD PIDs currently running`; the retained 4K and
  every later component were admitted only after that clean snapshot.

Representative fixed-shape commands:

```bash
GPU_MAX_HW_QUEUES=1 HIP_VISIBLE_DEVICES=1 HIPENGINE_HIP_ARCH=gfx1100 \
  PYTHONPATH=. .venv/bin/python3 scripts/qwen35_gguf_bench.py \
  --model /models/gguf/Qwen3.8-27B-Q4_K_M.gguf --quant gguf_q4_k_m \
  --prompt-length {1024|4096} --decode-tokens 128 --warmup-decode-tokens 4 \
  --max-sequence-length {1280|4352} --warmup-runs 1 --measured-runs 3 \
  --persistent-session --graph-replay-decode \
  --compiler-version-file /tmp/hipengine-qwen36-27b-int8-attn-hipcc-version.txt \
  --require-cached-build --json OUT.json

HIP_VISIBLE_DEVICES=1 LD_LIBRARY_PATH="$THEROCK_LIB" PYTHONPATH=. \
  .venv/bin/python3 scripts/llamacpp_bench_with_peak.py \
  --llama-bench "$LLAMA_ROOT/build-hip/bin/llama-bench" \
  --model /models/gguf/Qwen3.8-27B-Q4_K_M.gguf --quant Q4_K_M \
  --backend hip --workloads 512/128 1K/128 4K/128 --repetitions 5 \
  --ngl 99 --flash-attn 1 --cache-type-k f16 --cache-type-v f16 \
  --extra-args='-dev ROCm0' --poll 5 --memory-domain vram --card-name card0
```

The Vulkan prefill command substitutes the same-source Vulkan binary and
`-dev Vulkan1`. Context AR uses `scripts/llamacpp_mtp_bench.py --mode base
--protocol token-repeat --token-id 9707 --shapes 512/128 1024/128 4096/128`.
Natural MTP runs `--mode both --protocol natural --draft-max B` for every
`B=1..5`, all ten committed prompts, 25 visible outputs, and a true AR process
per budget/backend.
