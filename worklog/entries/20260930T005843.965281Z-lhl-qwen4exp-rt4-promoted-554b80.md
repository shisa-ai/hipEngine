# RT-4 bounded KV reset promoted to default

## Summary

The bounded KV reset is **promoted to the default** (`051501e59` shipped it
default-off).  Exactness was proven by **parent parity**, not asserted, and
independently confirmed at the byte level.  The full-capacity clear is now an
opt-out kept for rollback/bisection: `HIPENGINE_QWEN4_EXP_BOUNDED_KV_RESET=0`.

**This supersedes the checkpoint entry
`20260930T002252.520979Z-lhl-qwen4exp-rt4-bounded-kv-reset-8c17af`, which recorded
the flag as default-off pending the gate.**

## Validation

**Parent parity (the binding evidence for a T1 candidate).**  The gate run twice
on Qwen3.8-Flash-Next-UD-Q4_K_XL, `production_baseline` (no flag) and
`bounded_kv_reset` (flag on), both `base_profile="production"` so the flag is the
only variable:

| | `production_baseline` | `bounded_kv_reset` |
| --- | --- | --- |
| `candidate_logits_sha256` | `260979d6...` | **`260979d6...`** identical |
| `strict_logits_sha256` | `e5ae994e...` | **`e5ae994e...`** identical |
| `measurement_valid` | true | true |

The identical **strict** hash across the two runs is the control: the harness is
reproducible, so the identical candidate hash is evidence rather than
coincidence.  The `requires_task_review` status and `kl` envelope are identical in
both runs, i.e. they belong to production-vs-strict, not to this flag.

**Byte-level identity.**  `scripts/qwen4exp_rt4_kv_compare.py`, three arms (flag
off, off, on), code-p1024 at capacity 16384, two requests per runner: **zero
differing bytes at all 12 attention states**, and the flag-off arm matches across
separate processes.  Invariant `last_nonzero < bound` holds everywhere —
1,064,959 vs 1,310,720.

**Performance** (unchanged from the checkpoint entry): reset 15.689/15.519 ms ->
1.133/1.741 ms at 128K, **14.17 ms saved per request**, decode identical in both
regimes.

**Unit:** 6 passed.
