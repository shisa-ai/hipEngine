# Bound RF1 long-context qualification runs

## Summary

Corrected RF1 qualification after the user stopped a monolithic 32K/64K run
that had no progress output or incremental artifact. Long-context reach remains
a valid RF1 gate, but it must be staged, checkpointed, and bounded rather than
expanded as an unobservable Cartesian packet.

## Changes

- Preserved the completed 2K–16K direct and generation evidence and explicitly
  marked the stopped 32K/64K run as non-evidence, not a correctness failure.
- Required independently selectable direct/generation scenarios, flushed
  case-level progress, atomic per-case artifacts, and resumability before any
  further >=32K run.
- Reduced the remaining matrix to pairwise coverage: isolated B3 direct at 32K,
  conditional isolated B3 direct at 64K, generation only at the selected
  practical maximum, and near-cap tails at a moderate context.
- Defined a default 60-minute wall budget for one mechanical maximum-context
  case; a longer attempt requires explicit user approval. A host may certify
  32K as its largest practical RF1 context and route larger contexts to AR.
- Ended the prior coder's GPU lease when its process was stopped; the user then
  assigned exclusive GPU ownership to this primary `MTP-FIX` coder session.
