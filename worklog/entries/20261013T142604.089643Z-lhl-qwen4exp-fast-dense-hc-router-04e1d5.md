# Qwen4Exp fast profile dense all-layer F16, hyper-connection wide route, router warp reduce

## Summary

The `fast` profile gains three route changes that use kernels already
registered in this tree. Canonical 12-case protocol, Radeon 8060S / gfx1151,
`UD-Q4_K_XL`, chunk 4096: prefill **684.8 / 754.4 / 754.7 tok/s** at
p512/p1024/p4096 against 466.3 / 502.2 / 495.1 for the routed-expert-only
`fast` run and 306.4 / 330.0 / 335.2 for `production`, both measured earlier
the same day in the same boot. That is 2.23x / 2.29x / 2.25x `production`,
12/12 cases positive, decode unchanged.

## Decisions

- **Dense F16 wide route at layers 0-47.** The ledger had measured this
  window at +18.9% prefill and rejected it on the production mean-KL floor;
  under `fast` it is in. It also moves the hyper-connection down projection
  (K 10240, N 320) at layers 0-12 onto the wide route.
- **Hyper-connection up on the wide route, not int8 WMMA.** The int8-WMMA
  up/down pair the arithmetic recovery had disabled measured 612 to 680
  tok/s; the wide route for both measured higher (down 685.8, up 717.1), so
  the int8 routes stay off.
- **Router on the warp-reduce FP32 producer.** With routed experts no longer
  dominating the layer the warp-reduce producer measures about 4.6% faster
  than the ordered DPP tile (686.6 to 718.4). This is a manifest selection,
  so the binder publishes it from the fast plan's `router_logits` row.
- **Measured and not kept:** QSA flash prefill at all layers (slower), GDN
  peer prefill at all layers (slower), staged hyper-connection (neutral),
  int8 MMQ for the remaining dense shapes (neutral). Attention and GDN need
  new kernels, not wider windows for the existing alternates.
- **Selector retraction generalized.** `_FAST_SELECTORS` lists the selectors
  only `fast` publishes (`ROUTED_F16`, `GR_WIDE`); a later strict or
  production bind retracts them. The dense window is written by every bind.
- **Known gap, recorded in `docs/REFACTOR.md`:** the dense layer window and
  the hyper-connection up route have no manifest rows, in `fast` or in
  `production`.
