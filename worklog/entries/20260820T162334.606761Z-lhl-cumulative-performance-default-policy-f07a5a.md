# Remove fixed performance materiality threshold

## Summary

Removed the fixed `>=3% SLO-goodput` public-default materiality threshold. It
was introduced on **2026-08-16 20:38:51 +0900** by commit
`648564068dc0b21d755b1c8d748cd75b3147d4fe` (`docs: define execution profiles
and numeric gates`) when `docs/EXECUTION-PROFILES.md` and the production
numerics campaign were first added. The commit records no empirical derivation
for 3%; it was labeled an “initial target.” Applied as a default blocker, it
conflicts with `AGENTS.md`: measured non-regressive wins are first-class and
microseconds compound.

## Changes

- Replaced the threshold with cumulative-performance semantics: every measured,
  correctness-qualified, non-regressive improvement is retained and promoted
  in its validated scope, with no minimum percentage.
- Kept concrete blockers: correctness, ownership, determinism, applicability,
  resources, candidate-caused SLO regression, missing strict fallback, and
  named-profile evidence contracts.
- Clarified that an absolute product/SLO failure shared by control and candidate
  is tracked independently; it does not erase a candidate improvement.
- Updated Qwen3.6 campaign/default rules and its blocked artifact so the failed
  87/120 soak and missing manifest/task/BF16 evidence—not win magnitude—remain
  the reasons its named profile is blocked.
- Reclassified the Qwen3.8 FP16 serving screen as valid faster scoped-default
  evidence: c1 and c8 both improve, while the shared c8 SLO failure remains a
  separate serving-path issue.
