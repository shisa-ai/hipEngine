# Sharded TP2 bulk prefill MLP+residual composition seam

## Summary

With the attention/GDN and post-attention norm+residual subgraphs now factored
out of the resident layer methods, the next integration step is the rank-local
bulk-prefill layer composition. This checkpoint adds the CPU-testable seam
`run_sharded_mlp_with_residual` to the P0/P1 planning module: it runs the shard
group's MLP exactly once on the per-rank `post_norm` rows and then adds the
residual exactly once per rank, which is the "attention helper + P1 group +
single residual" contract the sharded caller must satisfy. The GPU loop is not
wired yet, so the whole bulk route is still reported partial.

## Changes

- `hipengine/distributed/tp2_prefill.py`
  - New `run_sharded_mlp_with_residual(group, *, layer_id, rows,
    post_norm_ptrs, residual_ptrs, out_ptrs, add_residual)`. It validates
    `rows` through `require_rows_value(rows, capacity=group.rows)` (rejects
    non-int / bool / <=0 / over-capacity), requires every rank's `post_norm`,
    `residual` and `out` pointer, calls `group.forward(layer_id,
    post_norm_ptrs, rows=rows)` exactly once, then calls
    `add_residual(device, residual_ptr, mlp_out_ptr, out_ptr, rows)` exactly
    once per rank. It never adds the residual inside the group and never
    re-runs the shard chain, so the MLP+residual arithmetic stays one reduced
    MLP output plus one residual add. Returns the per-rank reduced bf16 MLP
    output pointer.
  - Imports `require_rows_value` from `hipengine.distributed.transport`.
- `tests/test_unit_tp2_prefill_plan.py`
  - RED contract tests with a duck-typed fake group: one group forward (one
    reduction) and one residual add per rank in rank order, consuming the
    group's reduced pointer; a missing rank pointer fails before any group
    call; `rows` of `0`, over-capacity, `1.5` and `True` are rejected before
    any group call.
