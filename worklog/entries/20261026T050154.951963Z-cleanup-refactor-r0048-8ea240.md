# Remove the router full-block SGEMM env lever and move the control into the packet

## Summary

R0048 is executed as a removal. `HIPENGINE_GEMMA4_ROUTER_SGEMM` and its
`getenv` are gone from `gemma4_router_topk_bf16`; the tier now selects on
`tokens >= _ROUTER_SGEMM_MIN_TOKENS` (1024) alone. The shipped default is
unchanged: a full block still takes the F32 rocBLAS SGEMM tier, and narrower
blocks still take the pre-tier schedule (`token_tile_8` where the backend
declares it, otherwise `token_tile_16` above 32 rows, untiled below). The only
behavioral difference is that setting the variable to `0` no longer has any
effect.

The removal condition's two halves were already on file, re-verified at
`fc5895811`:

- The section 2.11 packet
  `benchmarks/results/2026-10-09-gemma4-router-sgemm-section211-packet.json`:
  18 cases / 1,134 rows, global median 1.21e-07 (bar 1e-3), p90 3.68e-03 (bar
  2e-2), flip-damage 0.79% (bar 3%), top-1 98.68% (bar 96%), every case passed
  with tasks non-inferior and repeats/isolation clean. The four 513-token cases
  are exactly the four with zero arm difference, and every case at depth 1031
  or deeper shows one, so the tier demonstrably ran there.
- Four tagged releases (`v0.8.0` 2026-10-20 through `v0.8.3` 2026-10-24) by
  `git grep` at each tag, absent at `v0.7.1`, with no recorded rollback. The
  packet was the only code that set the variable.

The condition's last clause -- the tile schedule stays "the strict-arm owner
for gate captures" -- could not survive the deletion as written, because the
env read was the only route to the tile at full-block geometry. The control
moved into the harness instead of being lost:
`scripts/gemma4_wmma_promotion_packet.py --candidate-kind router` now pins the
strict arm in-process by raising `gemma4_router._ROUTER_SGEMM_MIN_TOKENS` above
any block width, restores the shipped threshold for the candidate arm, and
restores it again from the run's `finally`. That is the mechanism
`scratch/p8_baseline_route_wrapper.py` and
`scratch/p8_gate_baseline_wrapper.py` already used for the teacher-forced gate,
and the guard reads the module global at call time, so the arm is the same one
the env lever produced.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_router.py`: deleted the inline
  `import os as _os`, the `sgemm_enabled` read, and the `and sgemm_enabled`
  conjunct. The guard is `if tokens >= _ROUTER_SGEMM_MIN_TOKENS:`. Replaced the
  lever comment with the threshold-seam note, and updated the adjacent
  tile-branch comment that called itself "the pinned arm when the SGEMM tier is
  rolled back".
- `scripts/gemma4_wmma_promotion_packet.py`: replaced the `_LEVER_KINDS` env
  map with `_CANDIDATE_KINDS`, `ROUTER_STRICT_MIN_TOKENS = 1 << 30`, and
  `RouterThresholdArm` (`select`, `restore`, `strict` context manager).
  `set_lever_arm` now drives that arm instead of writing `os.environ`; the
  router branch no longer arms an env var, and the strict teacher capture is
  scoped with `arm.strict()` so the arm is pinned for it and released to
  candidate on exit. `main`'s `finally` calls `restore()`. `--candidate-kind
  router` is preserved and its help text now names the threshold instead of a
  removed variable. No env arm remains to be inert.
- `docs/ENVS.md`: deleted the lever's row. The coverage gate's read count moves
  978 -> 977 with it.
- `docs/REFACTOR.md`: rewrote the R0048 section as the removal record -- the
  surviving guard and both pre-tier routes, the packet and release evidence,
  the clause that could not survive, and the harness control that replaced it.
- `tests/test_unit_gemma4_router_sgemm_control.py`: new, eight deterministic
  CPU tests. They pin the guard text the arm moves, that the strict threshold
  excludes 1024/2053/4093/8191/32768-row blocks, that the candidate arm and
  `restore()` put the shipped 1024 back (twice, for the finally path), that a
  raising capture inside `strict()` still restores, that neither the router
  module nor the packet contains `os.environ`/`getenv`, and that
  `--candidate-kind router` still parses. The retired variable's name is
  deliberately not spelled in the test: `scripts/check_envs_docs.py` treats
  every `HIPENGINE_*` literal under `tests/` as a read, so naming it would
  force the row back into `docs/ENVS.md`.

Not changed: the tier threshold, the SGEMM tier itself, the pre-tier
schedules, `HIPENGINE_EXECUTION_PROFILE` behavior, the runner, the recorded
packet artifact, `scratch/` wrappers, the audit inventory, and `README.md`.
