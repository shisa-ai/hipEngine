## Decision

Implemented the PF-4 M2 candidate exactly as declared, measured it, and closed
the lever as a **measured loss**. The incumbent 5-op chain
(memset(group_counts) + group_count + group_prefix + memset(scatter_offsets) +
scatter_gather_lowp) stays production; the candidate stays registered as a
strict variant (`KernelKey("hip_gfx1100", "moe_group_map", "generic",
"top10_parallel_i64")`) with its 7 tests. Lever 2 (M5 fused weighted sum) is
unaffected and remains open.

## Summary

PF-4 M2 routing compaction lever closed as a measured loss. The declared
`top10_parallel_i64` candidate (port of halo-box `a7ad7b7f`
`mm_ids_helper_top10_parallel`) was implemented, passes bit-exact parity vs
the incumbent 5-op chain, wins only below the production gate (rows=16,
−24.7%), and loses at the gate (rows=64 +30.8%, 512 +83.1%, 4096 +114.6%).
Incumbent chain stays production; candidate stays registered as a strict
variant with 7 RED-first tests.

### What was built

- `hipengine/kernels/hip_gfx1100/moe/group_scatter.hip`:
  `qwen35_moe_group_map_top10_parallel_kernel` — one 256-thread block (8 warps)
  per expert; each warp walks its token slice two tokens at a time
  (32 lanes / 16 padded top-k slots), warp any-scan (`__shfl_xor` width 16) +
  `__shfl_up` exclusive scan + broadcast, shared `moe_map_store` (22-bit token
  + 10-bit slot packing), cross-warp combine through shared per-warp counts and
  prefixes, then per-expert compact writes of `(sorted_lanes, sorted_experts,
  sorted_weights)` and `expert_start[e]`/`expert_start[E]` (incumbent count
  semantics: only valid expert ids counted). Host wrapper enforces top_k==10,
  total_lanes % 10 == 0, rows < 2^22, shared = rows*4 bytes.
- `group_scatter.py`: `qwen35_moe_group_map_top10_parallel` wrapper + registry
  entry. Repo convention change found during build: HIP here rejects 32-bit
  `_sync` shuffle masks (static assert sizeof(MaskT)==8), so the kernel uses
  the maskless legacy intrinsics like the rest of the tree.
- `tests/test_qwen35_moe_pf4_m2_group_map.py`: RED-first (ImportError history
  in 44a654cfc), now 7 passing: expert_start parity, bijection + per-expert
  lane sets + bit-exact weights + bit-exact gather content, gate/below-gate
  shapes, ABI checks. Fixture samples experts per-token WITHOUT replacement
  (production top-k distinctness invariant — with replacement the M2 store
  mechanism drops lanes, as designed).

### Measurement (kernel-level chain A/B, gfx1151 zbook)

Method: parity first, then 50 warmup + interleaved per-rep
device_synchronize-timed chain calls (200 reps rows<=512, 50 reps rows=4096),
median. Fixture from the test module (skewed per-token distinct top-10).
Incumbent chain includes both memsets (mirrors
`qwen4_exp_runner.py` grouped_prefill block).

| rows | incumbent ms | candidate ms | delta |
| --- | --- | --- | --- |
| 16 (below gate) | 0.0623 | 0.0469 | −24.7% |
| 64 (gate) | 0.0727 | 0.0951 | +30.8% |
| 512 | 0.2234 | 0.4090 | +83.1% |
| 4096 | 1.6699 | 3.5840 | +114.6% |

Parity: bit-exact everywhere (expert_start equality, sorted_lanes permutation,
per-expert lane sets vs `np.where(selected==e)`, weights bit-equal, gather
bit-equal).

**Verdict: measured loss at the production gate (rows>=64).** Root cause: the
per-expert-block mechanism scales O(E×T) serialized warp-scan work — 512
blocks each walking T/8 tokens with shuffle-chain scans; designed for
llama-class E≤32 (halo-box `a7ad7b7f`), hopeless at E=512. The only win is
launch-count below the gate (rows=16), which the gate excludes.

Trace smoke: `rocprofv3 --kernel-trace` shows
`qwen35_moe_group_map_top10_parallel_kernel` dispatched (grid 512×256,
group_segment_size 2176 B = 512×4 store + static) plus
`gather_packed_hidden_kernel`; prebuilt outside the profiler with
`HIPENGINE_COMPILER_VERSION_FILE` + `require_cached`.

No whole-model A/B: a kernel-level loss at the gate shape closes the lever
under the PF-2 / Q4_K-M1 closure precedent.

### Debugging notes worth keeping

## Changes

1. **First A/B GPU memory fault was my driver bug, not a kernel bug:** the
   incumbent `scatter_gather` kernel atomically increments
   `scatter_offsets[expert]`; without the production pre-chain memset the
   offsets accumulate across reps and `out_idx` runs past `compact` → OOB.
   Single-shot parity passes with fresh zeros, which is why the tests never
   caught it. Both the A/B driver and the test fixture now include the
   memsets.
2. **Frozen-pin test failure is pre-existing and unrelated:**
   `tests/test_laguna_h7u_parallel_moe_compaction.py::test_h7u_frozen_target_source_physical_trace_and_timing_contract`
   fails at branch HEAD with my changes stashed — `_POST_MERGE_PACKAGE_SHA256`
   (`hip_gfx1100/__init__.py` normalized content) drifted before this unit.
   Left alone; owner should re-pin.
3. **rocprofv3 JIT-cache key drift:** the cache key differs under the profiler
   even with a version file extracted from the manifest; the working recipe is
   to capture `hipcc --version` output *under rocprofv3 itself* into the
   version file, prebuild outside, then `require_cached`.
