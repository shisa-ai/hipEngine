# Build and gate Qwen3.8 native-XL artifact

## Summary

Completed the `OI-7` source-to-artifact campaign on physical host `zbook`
(AMD Ryzen AI MAX+ PRO 395, Radeon 8060S/gfx1151). The final v2 artifact passes
the paired BF16-relative quality gate and materially improves distributional KL,
but is rejected for deployment because native MTP violates exact target
ownership on one held-out Japanese prompt and both AR/MTP throughput regress
substantially. The artifact-specific loader admission remains research-only and
is entered in `docs/REFACTOR.md` with an exact removal/reopen gate.

## Changes

- Downloaded and SHA-256-verified the two public BF16 source shards from
  `unsloth/Qwen3.8-27B-GGUF@4ca720788d1e01f1bff70c033e0d0028fd02e502`, then
  merged them for independent teacher execution. Shard hashes are
  `b9966e82...191f` and `92e3943c...fa02`; merged hash is `53a3093e...19f2`.
- Materialized native-XL v1 from the full Unsloth `UD-Q4_K_XL` sensitivity map
  and 496-entry importance matrix. V1's Q6 LM head improved KL but narrowly
  missed the teacher-token-PPL paired diagnostic.
- Added an explicit `output.weight: Q6_K -> Q8_0` quality promotion and emitted
  v2 at `5.296285` bpw: `360 F32 / 149 Q4_K / 191 Q5_K / 55 Q6_K / 111 Q8_0`,
  18,087,276,544 tensor bytes. Artifact SHA-256 is
  `f0beea376a60310844b503760c870d6482117d9a93ea61189b88d5b6cccef3b0`;
  exact type-manifest SHA-256 is
  `a45045f99c2a094c244142876e5760474fc9dabc09d22b0aea622d0c15844c3c`.
- Added loader/materialization admission for the exact v2 metadata/type
  manifest, plus an artifact verifier binding metadata, shapes, qtypes, payload,
  target loading, and trailing NextN loading.
- Added BF16-hidden/BF16-weight -> unrounded F32 dense GEMV output support. This
  closes the raw BF16 LM-head dispatch gap, has a CPU-reference exact test, and
  was observed by `rocprofv3` under
  `dense_gemv_out_kernel<unsigned short, float, false>` at 1,884 ns for the
  tiny test shape.
- Disqualified hipEngine's current Qwen3.8 BF16 trunk execution as a quality
  oracle after it generated special-token-heavy trajectories. The old helper is
  now explicit-override diagnostic-only. Added a prompt-ID-exact llama.cpp
  greedy full-logit harness and prepare/finalize tooling instead.
- Captured 90 independent BF16 full-logit rows through llama.cpp Vulkan at
  `749f688fcaa4c472ec034b08cb8a907c45cfaa02`, plus aligned Q4_K_M, v1, and v2
  hipEngine caches. Raw BF16 full-logit SHA-256 is
  `8db7737f3ec17ad58279829b851a2cb6fc83bb16d54a588e852ee23c23b22bb9`.
- Added the compact final decision artifact
  `benchmarks/results/2026-08-25-gfx1151-qwen38-omlx-oi7-native-xl-rejected.json`
  and updated `docs/OLMX-IDEAS.md`, `docs/KERNELS.md`, and `docs/REFACTOR.md`.
