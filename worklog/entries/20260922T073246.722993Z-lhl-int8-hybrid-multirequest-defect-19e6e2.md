# INT8 hybrid layout breaks multi-request decode

## Summary

On the **default** long-context INT8 KV layout, a request that follows a concurrent
autoregressive/speculative pair fails with HTTP 500. The lifecycle gate
(`scripts/int8_mtp_server_lifecycle_gate.py`) fails at
`multichoice_speculates_and_matches_ar`, the check that `e1808ac64` added for the
new packed-INT8-MTP-at-c=N feature. The same gate passes all seven checks when the
full-attention layers are uniformly INT8.

Two distinct causes were observed, both after the concurrent pair:

- `RuntimeError: packed full-attention layers used inconsistent decode paths:
  ['kv_live_spans_batch', 'kv_live_spans_int8_batch']` (`work_kind=decode`)
- `ValueError: prefill chunk extends beyond its declared full prompt length`
  (`work_kind=prefill`)

Both report `state_mutation=partial` and surface as `execution_failed` 500s.

The mechanism is visible in code. `_run_full_attention_decode_batch_layer_rows`
picks one of two route strings: `kv_live_spans_batch` by default, or
`kv_live_spans_int8_batch` when `direct_retained_batch` is true
(`qwen35_gguf_runner.py:5813` and `:5867`). `direct_retained_batch` requires
`rows > 1` plus retained payload/scale planes on that layer's scratch (`:5721`).
`_packed_full_attention_scratch_for_layer` (`:20036`) attaches those planes only
when the layer has INT8 scale metadata; a layer with `metadata is None` keeps
BF16-shaped scratch. The packed decode then collects one route per full-attention
layer (`:26074`) and raises when the set holds more than one value (`:26687`).

So a **hybrid** layer layout — some full-attention layers BF16, the rest INT8 —
cannot satisfy the consistency check once `rows > 1`. The check is correct; the
layout is what splits.

The hybrid layout is the default, not an exotic configuration.
`_gguf_int8_bf16_prefix_full_attention_layers` (`:12876`) returns
`default_prefix = 0 if allow_unverified else _GGUF_INT8_LONG_BF16_PREFIX_FULL_ATTENTION_LAYERS`,
and that constant is `8` (`:11422`). So
`HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1` gives a uniform layout, and
anything else gives a hybrid one. The uniform layout that passes is the diagnostic
path; the hybrid layout that fails is what a normal long-context INT8 server gets.
The prefix is chosen from context length alone, so a qualified artifact would be
hybrid too.

## Changes

No engine change in this unit. Two records were written:

- `CHANGELOG.md` gained the user-visible caveat, including the
  `--max-context-tokens` at or below 8192 workaround, which selects the uniform
  layout.
- This entry carries the mechanism, the four server runs, and the replayed
  sequence.

Two gaps were found in the documentation while tracing the layout:

- `HIPENGINE_GGUF_INT8_KV_BF16_FULL_LAYERS` is the layout escape hatch and is not
  documented in `docs/ENVS.md`.
- Its `0` value means *layer 0*, not *none*. The empty tokens are `none`, `empty`,
  and `-`. A first attempt to force a uniform layout with `=0` silently produced a
  one-layer BF16 prefix and reproduced the failure, which cost one server cycle.
- Setting that variable requires `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1`,
  which is a different variable from the `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED`
  that the readiness wrapper sets. The startup error names the correct one.

## Validation

Server: `gfx1151`, `Qwen3.8-27B-Q4_K_M`, `--max-context-tokens 9216`,
`--max-active-requests 4`, `--kv-storage int8_per_token_head`, the recorded
readiness config plus `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED=1`.

| Layout | Prefix cache | Lifecycle gate |
| --- | --- | --- |
| hybrid (default, prefix 8) | radix | **FAIL** at `multichoice_speculates_and_matches_ar` |
| hybrid (layer 0 only, via `=0`) | off | **FAIL** at the same check |
| hybrid (default, prefix 8) | off | **FAIL** at the same check |
| uniform (`=none` + `..._ALLOW_UNVERIFIED_LONG=1`) | off | **PASS**, 7/7 checks |

The minimal sequence that reproduces the 500, replayed directly against the
default-config server:

1. `speculative_mtp=False` → 200
2. automatic (MTP) → 200
3. concurrent `speculative_mtp=True` and `=False` → 200, 200
4. `speculative_mtp=True, n=2` → **500** (prefill `ValueError`)
5. `speculative_mtp=True, n=2` again → 200

A cold `n=2` request with no concurrent pair preceding it returns 200, so the
trigger is the concurrent pair, not `n=2` alone. The gate's own
`concurrent_mixed_ar_mtp` check passes, because both concurrent requests succeed;
the damage appears on the following request.

Three runs of the failing configuration were made (radix, layer-0, and prefix-off)
and all three failed at the same check. One run of the uniform configuration was
made and passed. Not established: the minimal trigger, and reachability on a
qualified non-override artifact — only this quality-rejected artifact was
available, and the layout follows from context length alone.
