# Bind bounded Qwen4Exp wide-F16 activation staging behind explicit opt-in

## Summary

The Qwen4Exp chunked-prefill call site now binds the existing F16 activation
composite when both the wide route and `HIPENGINE_GGUF_Q8_DENSE_WIDE_F16_ACT=1`
are selected. The runner owns a bounded lazy buffer; the default remains off
pending integrated GPU validation. This is integration work, not a performance
claim or a completed promotion.

## Changes

- `hipengine/runtime/qwen4_exp_runner.py`: bind the workspace around the actual
  chunk loop; allocate once at original workspace capacity; reuse across reset;
  free with runner-owned buffers. Smaller prepared prefill owners do not resize
  this buffer. Disabled contexts hide any outer context's workspace.
- `hipengine/loading/qwen4_exp_scratch.py`: calculate a conservative F16 staging
  bound from dense input widths and `min(context, original chunk)`. For this
  model, the bound is 20 MiB at chunk1024 and 80 MiB at chunk4096. Existing
  per-launch bounds retain the F32-input fallback for oversized inputs.
- `hipengine/loading/qwen4_exp_context.py`: reserve those optional bytes per
  runner, independently of later profile/flag selection, inside the existing
  scratch-floor calculation. The historical mandatory allocation census stays
  unchanged; disabled/default paths allocate no staging buffer.
- New runner-level CPU tests exercise bounded sizing, context clamping,
  allocation failure, opt-out/default behavior, reset/release, actual prefill
  binding and exception restoration, and selected smaller workspaces.
- Updated status and cleanup records. The shared Qwen3.5/3.6 helpers and all
  strict fallbacks remain unchanged. No kernel or numerical policy changed.
