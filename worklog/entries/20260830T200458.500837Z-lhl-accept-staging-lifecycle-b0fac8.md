# MTP accept pinned-staging lifecycle repaired

## Summary

The campaign audit (task #25, `docs/REFACTOR.md`) found that the page-locked accept-upload arena kept by
`790eaee91` as a measured-neutral path documented a fallback it did not implement. Two defects are fixed:
`_accept_staging_backing` called `runtime.host_register()` unguarded, so a `hipHostRegister` failure raised
out of `_enqueue_target_batch_accept` and aborted an otherwise healthy accept cycle instead of selecting the
blocking pageable upload it documents; and `Qwen35GGUFMTP2Adapter.close()` never called `host_unregister()`
nor released the 4 MiB NumPy arena, leaking page-locked host memory for the life of the process on every
adapter. Page-locked memory is scarce and the adapter is constructed per resident runner, so the leak is a
real resource defect, not cosmetic. No rate change is claimed: this path measured neutral
(`20260830T160316…`) and stays neutral.

## Changes

- `hipengine/generation/qwen35_gguf_mtp2.py`:
  - `_accept_staging_backing` now registers inside `try/except`. On failure it clears the arena state through
    `_reset_accept_staging()`, latches `_accept_staging_state = "off"`, and returns `None`, which is exactly
    the value the existing callers already treat as "keep the blocking pageable path". The failure latches
    per adapter instead of retrying a registration the driver just refused.
  - The registered pointer and the runtime's `host_unregister` callable are stored at registration time.
  - New `_release_accept_staging()` unregisters once, is idempotent, clears the arena and the latch before
    invoking the runtime so a failing `hipHostUnregister` still cannot leave the arena referenced, and is
    called from `close()` after the cycle workspace is closed and before the remaining teardown.
- `docs/REFACTOR.md`: the pinned-staging entry now records the repair and keeps the original removal
  condition (delete the whole path if #17's cycle redesign lands).
- `tests/test_qwen35_gguf_mtp2_accept_staging.py` (new, 7 tests, CPU-only): a recording fake runtime drives
  registration failure -> pageable fallback, sticky-off, single registration plus arena reuse, unregister and
  release on close, close without registration, unregister failure still releasing the arena, and no
  re-registration after close.

## Validation

- RED before the fix: 6 of the 7 new tests failed — registration failure escaped, `close()` never
  unregistered, and a closed adapter re-registered a second arena. The two success-path tests passed, so the
  new file isolates the defect rather than the harness.
- GREEN after the fix: `pytest -q tests/test_qwen35_gguf_mtp2_accept_staging.py` -> 7 passed.
- Adjacent suites unchanged: `pytest -q tests/test_qwen35_gguf_mtp2_seam.py` -> 53 passed;
  `tests/test_qwen35_gguf_moe_mtp2.py tests/test_specdec2_s6_failure_gate.py
  tests/test_gguf_mtp_lifecycle_gate.py tests/test_qwen35_gguf_mtp_session.py` -> 51 passed.
- No GPU behaviour change is claimed; no rate claim is made either way. The staging path remains default-on
  and still measured-neutral.
