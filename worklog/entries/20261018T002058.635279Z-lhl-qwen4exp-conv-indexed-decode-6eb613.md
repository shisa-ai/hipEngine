# Indexed Qwen4Exp F32 conv decode: independent rows over per-row state slots

## Summary

Adds the independent-request form of the F32 linear-attention decode
convolution, the second prerequisite for batched (C2/C4) serving after the GDN
recurrent primitive in `e7476fe65`. One launch advances `rows` independent
requests: row `r` reads its own packed hidden row, writes its own output row, and
reads and writes exactly the Conv state slot `state_indices[r]` of a
`[state_slots][channels][kernel_size]` FP32 slab. Slots no row selects keep their
exact bytes.

This is a primitive plus its tests. No runner or dispatch default was changed,
and previously committed entries were left untouched. The catalog is updated
with this unit; the existing single-row F32 owner stays registered as the strict
fallback and the per-row arithmetic oracle.

## Changes

- `hipengine/kernels/hip_gfx1100/linear_attn/conv.hip`
  - `qwen4_exp_linear_attn_conv_decode_indexed_f32_kernel`: the single-row
    `qwen35_linear_attn_conv_decode_kernel` body with row `blockIdx.y` selecting
    the hidden/output row and `state_indices[row]` selecting the state slot. The
    accumulation statements are the single-row owner's, in the same order.
  - Uniform batch ownership check. The decode body shifts and appends inside its
    slot as it runs, so its writes begin in the first loop iteration and the
    batch must be validated before any of them. Warp 0 clears a 4096-bit shared
    bitmap and sets one bit per row, then sets `s_batch_rejected` on an
    out-of-range or duplicate slot; `__syncwarp()` covers the clear-to-scan
    dependency so the check costs one block barrier rather than two. Every block
    returns before any write when it fires. The flag is stored with
    `atomicExch` and the bitmap bits with `atomicOr`; no shared store is written
    concurrently by plain assignment.
  - `kQwen4ExpConvIndexedMaxRows = 64`,
    `kQwen4ExpConvIndexedMaxStateSlots = 4096`,
    `kQwen4ExpConvIndexedMaxChannels = 1048576`,
    `kQwen4ExpConvIndexedMaxKernelSize = 1024`, and the
    `hipengine_qwen4_exp_linear_attn_conv_decode_indexed_f32` launcher.
  - The launcher mirrors every host bound: pointer nullity, row and slab bounds,
    channel and kernel bounds, and 8-byte `state_indices` alignment. The ABI is
    packed-only like the single-row owner (hidden and output rows stride by
    `channels`, the state by `channels * kernel_size` per slot), so there are no
    stride arguments to bound; the channel, kernel and slot bounds keep every
    derived element and byte offset inside signed 64 bits. All operand accesses
    are scalar 32-bit, so the int64 slot vector has an additional alignment term.
- `hipengine/kernels/hip_gfx1100/linear_attn/conv.py`
  - `qwen4_exp_linear_attn_conv_decode_indexed_f32` raw-pointer wrapper with
    `_ARGTYPES_QWEN4_EXP_DECODE_INDEXED_F32` and the module's existing
    `_check_launch` error path.
  - `qwen4_exp_conv_indexed_state_indices`: host admission for the per-row slot
    vector (contiguous `int64`, length `rows`, each in `[0, state_slots)`,
    **distinct**).
  - The four `QWEN4_EXP_CONV_INDEXED_MAX_*` constants, paired with the C
    constants.
  - Registry variant `qwen4exp_conv_indexed_decode` on
    `(hip_gfx1100, linear_attn_conv_decode, f32_state)`.
- `tests/test_unit_qwen4exp_conv_indexed_decode.py` (new, 40 tests): slot
  admission including duplicate rejection and both slab bounds, wrapper shape
  and alignment admission, the C/Python constant pairing, and the CPU oracle
  built on the committed `linear_attn_conv_prefill_segments` with one-token
  segments.
- `tests/test_gpu_qwen4exp_conv_indexed_decode.py` (new, 28 tests): bit-exactness
  vs the single-row owner at N=1/2/4 with permuted slots and two kernel widths,
  untouched-slot canaries, a past-the-last-channel padding canary, uniform batch
  rejection for out-of-range and duplicate slots, duplicate rejection past the
  scan loop's first pass, the 64-row maximum, repeated steps over changing
  slots, deterministic reruns, CPU-oracle round-off, registry resolution, and
  raw C launcher rejection and acceptance. The module carries an explicit
  `ctypes.CDLL("libamdhip64.so")` skip guard.

## Design notes

- **Duplicate slots are an ownership violation, not drift.** The decode body
  shifts the slot in place, so two rows sharing it would interleave their shifts
  and commit a state that is neither row's result, with the survivor decided by
  block completion order. Rejected on the host with a message naming the slot and
  both rows, and rejected on the device as a whole batch. The device path is
  uniform (all-or-nothing) rather than first-writer-wins: committing the rows
  that happen not to collide would be a partial ownership mutation.
- **`state_slots >= rows` is a capacity bound, not a uniqueness check.**
  Uniqueness is enforced separately and is not implied by it.
- **Arithmetic profile is T0.** The block body repeats the single-row owner's
  statements in the same order, so the declared contract is bit-exact equality
  with the single-row owner, and that is asserted rather than assumed. If a
  future edit breaks it, the primitive becomes T2 and needs the production
  numerical gate before use.
- **The check is one barrier, not two.** The clear and scan run inside warp 0
  with `__syncwarp()`, so only the publication of `s_batch_rejected` needs a
  block-wide barrier. This follows the shape measured and accepted for the GDN
  primitive, where placing the check behind two barriers ahead of the strided
  loads cost 4.1x and was rejected.
- **The F32 ABI was added rather than extending the BF16 sibling.** The existing
  `qwen35_linear_attn_conv_decode_indexed_lowp_kernel` is templated on the input
  scalar and takes no slab bound, so it cannot reject a malformed slot vector at
  all. Extending it would have changed an in-use BF16 path; a separate F32 kernel
  keeps that path untouched.
- **Validated admission bounds are new, not inherited.** `valid_conv_shape` only
  checks positivity, so the single-row owner accepts any positive shape. The
  indexed ABI adds the channel and kernel bounds because it multiplies
  caller-supplied shapes into `state_slot * channels * kernel_size` offsets,
  where a wrap would be a silent out-of-slab write.

## Missing evidence

The CPU-reference outer safety gate in `docs/TESTING.md` section 4 is
KL <= 0.05 with top-1 agreement >= 90%, scoped to logit-producing paths. It has
**not** been run for this variant, and the evidence is missing rather than
satisfied: the primitive emits a SiLU'd per-channel vector and an updated Conv
state, neither of which is a logit distribution, the committed CPU reference for
this layer (`linear_attn_conv_prefill_segments`) produces no logits, and nothing
dispatches the variant yet, so no model-level fixture exercises it. Closing it
needs a layer-level fixture that reaches logits. Bit-exact equality with the
dispatched single-row owner bounds the risk but is a per-call identity, not a
distributional comparison through the rest of the model.

## Limitations

- One decode step per row. Nothing here handles a row that must run several
  steps (MTP verification), and mixed AR+MTP rows in one work item are
  undesigned.
- The primitive advances Conv state only. It does not touch GDN recurrent state,
  PLE state, KV cache, or index state.
- The ABI is packed-only, inheriting the single-row owner's shape. A caller with
  padded hidden or output rows cannot express that stride; it must pack first.
- No graph capture, no multi-stream, and no overlap with neighbouring layers was
  tested.
- `channels` was exercised at 64, 128, 256, 300, 320 and 512, and `kernel_size`
  at 2 and 4. The ABI admits up to 1048576 channels and 1024 taps; wider shapes
  are unmeasured.
- Downstream numerical quality (logits, KL, top-1, task quality) is not measured;
  see "Missing evidence".
- The device duplicate scan is a 4096-bit shared bitmap, which is what bounds
  `state_slots` to 4096. A larger pool would need a different check.
- The host slot validator duplicates the semantics of
  `qwen4_exp_gdn_indexed_state_indices` in the GDN package rather than sharing
  one helper, because this unit's edit scope was `conv.{hip,py}`. A shared
  indexed-slot admission helper is a reasonable follow-up once both primitives
  have landed.
