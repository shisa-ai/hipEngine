# Serve prompts at and above the packed-prefill context bound

## Summary

Prompts at and above 1024 tokens are served end to end, and three of the four
host sites that turned the packed route's context refusal into a request
failure now re-route instead. One fatal site remains and is named below with
its owner: a row whose KV allocation needs the block-table-aware prefill route
(a shifted, non-zero-base slab) has no host-side fallback when the packed route
refuses the slab's shape, because the only route that can address its KV is the
one that refused.

**The bound.** `_validate_packed_ar_prefill_context` (owner:
`hipengine/runtime/qwen35_gguf_runner.py`, raised at line 1969, called from
`_prefill_batch_native_single_slab` at line 24512) refuses a slab whose
`max_live_count >= 1024` when no slot needs slot-local full attention
(`attn_aotriton_min_tokens = 512`). It is a *route* limit of the packed paged
AR prefill kernel path, not a context limit: the served context is 8192 tokens.

## Changes

- `qwen35_gguf.py::_try_prefill_native_work_batch` — a grouped work-batch
  prefill that the packed route refuses now reports `frozenset()` instead of
  re-raising, which is the method's documented contract ("callers must fall
  back per request for everything else"). Every row of the item then goes
  through `prefill_batch`'s serial loop and is served. Before, the refusal
  retired every row of the item with an `execution_failed` 500.
- `qwen35_gguf.py::_try_prefill_ar_serving_slots_batch` — a refusal in a later
  width group used to re-raise once earlier groups had been committed. It now
  finishes the remaining groups on the strict per-session route and reports
  those slots as non-compact prefill (telemetry accuracy).
- `qwen35_gguf.py::_try_open_mtp_serving_slots_batch_prefill` — the packed MTP
  serving prefill (the "resident admission window") now releases what it
  acquired and returns `None` on refusal, so `_open_mtp_serving_slots` falls
  back to the per-request slot path instead of failing the request.
- Tests: `tests/test_unit_gguf_packed_verify_layout.py` pins the bound
  (1023 admitted, 1024 refused without slot-local full attention, admitted with
  it, and a long context carried by a 64-token tail chunk refused);
  `tests/test_live_generation_qwen35_gguf_sampling.py::test_resident_packed_prefill_falls_back_when_the_slab_hits_the_context_bound`
  drives two exactly-1024-token prompts through a refusing owner and asserts
  `prefill_batch` serves both rows on the serial route (RED: the refusal
  propagates).

## Next

- Remaining fatal site (blocking task #17): `qwen35_gguf.py::_prefill_native_row`
  re-raises the packed refusal when
  `_gguf_single_row_block_table_prefill_required(lease.session)` is true, i.e.
  `kv_attention_source == "int8_direct"` or
  `_gguf_device_kv_contiguous_base_row(session) != 0` (a shifted slab). The
  strict scalar `session.prefill` route cannot address that KV layout, so the
  fallback has to come from the runtime side: either admit the shape in
  `_validate_packed_ar_prefill_context` (the slot's own live count is what
  decides slot-local full attention, and a full-prompt single-row call is well
  above `attn_aotriton_min_tokens`), or give the block-table-aware route a
  second entry that does not go through the packed slab. Observed in the c=8
  `beyond` run: `request_ids=[8]`, 3,474-token prompt, contained 500 with
  `state_mutation=partial`, traceback `prefill_batch` → `_prefill_native_row`
  → `prefill_batch_native` → `_prefill_batch_native_single_slab` →
  `_validate_packed_ar_prefill_context`.
- The two chunk-drift failures in the same run (`request_ids=[10]`, `[11]`) are
  secondary: they appear only after a row of the same batch was retired, so
  re-check them once the site above is fixed.
