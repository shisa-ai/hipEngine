# R0523 identical non-degenerate prompts: race hits all rows, not positional

## Summary

Two prompt-structure experiments settle the positional-vs-content question for
the R0523 c4 packed-decode race. With identical NON-degenerate prompts the race
hits every row, so it is not a slot/position bug. The baseline's "always
request_index=1" reflects that only row 1 carried the trajectory where the
corruption is detectable, not a row-1-specific ownership fault.

## Changes

- Inspection/experiment only; no production code changed. Env-gated R0523
  diagnostic tracer still in `hipengine/generation/qwen35_gguf.py` (uncommitted);
  revert before any production commit.
- Experiment harness copies (not tracked): `/tmp/refactor-gfx1100/bench_r0523_identical.py`
  (all last=token_id) and `bench_r0523_allplus1.py` (all last=token_id+1);
  run scripts `run-r0523-identical.sh`, `run-r0523-allplus1.sh`.
- Experiment 1 (bg-72, r0523-identical.json): all four prompts last=9707.
  c4 measured 0/240 mismatches, but CONFOUNDED — output is a degenerate
  repetition loop (all 9707, unique=1); oracle passed=false. Baseline row 0
  (last=9707) is likewise the degenerate row and never races.
- Experiment 2 (bg-73, r0523-allplus1.json): all four prompts last=9708,
  identical and NON-degenerate (oracle 75 unique tokens). c4 measured
  exact_rows=230, mismatch_count=10 (10/240). Mismatches span request_index
  0,1,2,3; every one first_mismatch_index=73, expected 6866 observed 3154.
  c1 measured 60/60 exact; repeat_determinism mismatch=10.

## Validation

- Untraced 60-rep c4 bursts (no state hashing -> no observer effect), strict
  profile, native route, bf16 KV, gfx1100, Qwen3.8-27B-Q4_K_M.
- Gate reports failed_gate when mismatches exist; per-phase correctness counts
  are the authoritative signal (Experiment 1's failed_gate was oracle degeneracy,
  not a c4 mismatch).

## Next

- Race is NOT positional. It is tied to the shared trajectory/content (all rows
  with the same prompt can corrupt) and always yields the same step-73
  6866->3154 flip. Leading hypotheses: cross-row contamination of a shared
  packed buffer that only becomes detectable when rows share a trajectory, or a
  trajectory-specific stale/aliased read in the full-attention KV path (layer 47).
- Decisive follow-ups: (a) c2 identical-prompt burst to see if 2 rows suffice;
  (b) device-side in-graph checksum of the KV pages each row reads at step 73 vs
  the c1 oracle; (c) inspect whether identical prompts cause any packed scratch /
  KV page sharing despite prefix_cache=off.
