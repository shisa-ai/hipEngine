# YuE2 M5 FP32 VAE decoder with exact tiled decode

## Summary

The torch-free FP32 Oobleck VAE decoder is implemented and matches the pinned
upstream reference on the same host: a 3-frame latent lands at max abs 1.27e-06
(rel L2 1.99e-06) and a 64-frame latent at max abs 2.99e-06 (rel L2 1.88e-06),
with peak 0.991600 against the reference's 0.991599. Tiled decoding is
bit-identical to the same runtime's full decode. The reference's own tiled and
full decodes differ by 1.33e-06, so all of these figures sit at its FP32 noise
floor rather than at a modelling difference.

## Design

- **FP32 throughout.** The released decoder is FP32 end to end and the reference
  does not reassociate it into another class, so the kernels accumulate in FP32
  with the reference's own loop order: kernel tap outside, input channel inside.
  Weight normalization is folded once at load time
  (`hipengine.loading.yue2.fold_weight_norm`, FP64 norm then FP32 scale, as the
  M1 loader already did) rather than per call.
- **Kernels** (`hipengine/kernels/hip_gfx1100/yue2/vae.hip`): `vae_conv1d_f32`,
  `vae_conv_transpose1d_f32`, `vae_snake_beta_f32` (log-scale alpha/beta, the
  released `1e-9` denominator epsilon) and `vae_add_f32` for residual skips. One
  thread per output element keeps the index arithmetic auditable.
- **Runtime** (`hipengine/runtime/yue2_vae.py`): the decoder chain, plus
  `decode_tiled` which reproduces the reference's schedule exactly - finite
  left/right context per tile, only the exact interior core copied out, no
  crossfade, no boundary smoothing, no zero padding of the final audio, and the
  last tile's crop shorter than its own output because the natural length is
  `1920 * frames - 64`. Completed cores are copied to host as they finish, which
  bounds device residency.
- **Halo from the decoder, not from a constant.**
  `YuE2VaeDecoderWeights.required_halo` walks the decoder's dependency interval
  backwards (transposed convs divide by stride, convs expand by
  `dilation * (kernel - 1)`, residual units keep their identity path) and gives
  **12** frames for a 16-frame core, matching the value recorded with the fixture
  at M0. `decode_tiled` refuses a smaller halo rather than silently cropping
  wrong.

## Defect found

The first SnakeBeta of each residual unit was applied **in place**, so the
residual branch added the unit's activation instead of the unit's input. Every
individual kernel matched its NumPy reference, and the tiled decode matched the
full decode bit-for-bit - the two checks that would normally be run both passed.
It was localized by comparing the chain stage by stage against a NumPy decoder
built from the same folded weights: the first divergence was exactly the residual
add of block 0 unit 0 (max abs 1.59), while every op before it agreed to ~1e-6.
`tests/test_unit_yue2_vae.py` now asserts the chain end to end against that NumPy
reference, so this class of wiring error cannot pass on op-level tests alone.

An earlier, cruder defect was also fixed during bring-up: `_conv` read
`channels_in`/`channels_out` from the weight shape without distinguishing
Conv1d (`[C_out, C_in, K]`) from ConvTranspose1d (`[C_in, C_out, K]`), which
produced an out-of-bounds read and a GPU memory fault.

## Measured (zbook / gfx1151, Ryzen AI MAX+ PRO 395 / Radeon 8060S)

Command: `python3 scripts/yue2_vae_gate.py --json benchmarks/results/yue2_vae_gate_20260916.json`

| Case | Frames | Samples | max abs | rel L2 | Peak | Decode |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| recorded small latent | 3 | 5 696 | 1.267e-06 | 1.985e-06 | 0.483541 | 0.04 s |
| recorded 64-frame latent | 64 | 122 816 | 2.995e-06 | 1.884e-06 | 0.991600 | 0.68 s |
| 64-frame latent, tiled 16/16 | 64 | 122 816 | 2.794e-06 | - | - | 1.51 s |

The reference's own full-vs-tiled difference is 1.33e-06 and the reference peak
is 0.991599; the produced peak is 0.991600 and the produced rms 0.165768 against
the reference's 0.165768. Tiled decode is bit-identical to the native full decode
at both 16/16 and 64/16 (`np.array_equal`), and a 5-frame latent over a 3-frame
core (a partial last tile) is also bit-identical.

Tiled decoding is **slower** than the full decode at 64 frames (1.51 s vs
0.68 s) because each of the four tiles re-decodes its halo context. That is the
reference's own trade: tiling bounds device residency, not wall clock. No
throughput claim is made here.

## Kernel trace

Command (cached-only child, no compiler under the profiler):

```
hipcc --version > /tmp/hipengine-hipcc-version.txt
HIPENGINE_COMPILER_VERSION_FILE=/tmp/hipengine-hipcc-version.txt \
  python3 -c "from hipengine.kernels.hip_gfx1100.yue2 import vae; vae.build_yue2_vae()"
rocprofv3 --kernel-trace --output-format csv -d /tmp/yue2-vae-trace -- \
  python3 scripts/yue2_vae_rocprof_smoke.py \
    --compiler-version-file /tmp/hipengine-hipcc-version.txt
```

One 4-frame full decode plus one tiled decode (2-frame core, 16 frames of halo,
so two tiles): 454 dispatches, 5 distinct names. All four VAE kernels appear, and
the dispatch counts match the schedule exactly (3 decodes x 38 conv1d, x 6
transposed convs, x 43 snake activations, x 18 residual adds):

| Kernel | Dispatches | Total | Average |
| --- | ---: | ---: | ---: |
| `yue2_vae_conv1d_f32_kernel` | 114 | 57.534 ms | 504.68 us |
| `yue2_vae_conv_transpose1d_f32_kernel` | 18 | 57.027 ms | 3168.17 us |
| `yue2_vae_snake_beta_f32_kernel` | 129 | 0.949 ms | 7.35 us |
| `yue2_vae_add_f32_kernel` | 54 | 0.248 ms | 4.60 us |

The transposed convolution is the dominant cost at ~3.2 ms per call (2048 -> 1024
channels, 12-tap) and is the obvious M7 target, along with the 7-tap convs at
~0.5 ms.

## Changes

- `hipengine/kernels/hip_gfx1100/yue2/vae.hip`, `.../vae.py`: new FP32 kernel
  family and launch wrappers.
- `hipengine/runtime/yue2_vae.py`: new decoder runtime with full and bounded
  tiled decode.
- `hipengine/loading/yue2.py`: `YuE2VaeDecoderWeights.required_halo`, the
  dependency-interval walk used for tiling.
- `tests/test_unit_yue2_vae_kernels.py`: kernel gate against the NumPy reference
  (conv1d at four stride/dilation/padding combinations, transposed conv at all
  four released strides, SnakeBeta including a large negative log-beta).
- `tests/test_unit_yue2_vae.py`: chain gate against a NumPy decoder built from
  the same folded weights, tiled-vs-full bit equality, partial last tile,
  natural-length formula, halo rejection, and input validation.
- `scripts/yue2_vae_gate.py`, `scripts/yue2_vae_rocprof_smoke.py`: fixture gate
  and cached-only profiling child.
- `benchmarks/README.md`, `benchmarks/CHANGELOG.md`, `docs/KERNELS.md`,
