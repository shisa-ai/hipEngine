# Gate the INT8 per-head DMS attention the verifier must reuse

## Summary

Task 9 unit 1 needs the verifier to read per-head variable live spans with
their INT8 scale planes, so a DMS row's attention reads the same tokens the
autoregressive route would. Reading the code first changed the shape of that
work: the law already exists and the AR route already uses it.

- `hipengine/kernels/hip_gfx1100/attention/dms_compact_int8.py` implements
  `dms_compact_attn_decode_splitk_int8` and registers it as
  `("dms_compact_attn_decode", "int8_per_token_head", "grouped_gqa_splitk")`.
  It reads `base_offsets`/`live_counts` as `[rows, kv_heads]` -- one dense
  extent per (row, kv head) -- and dequantizes `int8 * scale` per slot, with
  `k_scale`/`v_scale` as `[total_slots]` float32 planes.
- `hipengine/kvcache/dms_device.py` resolves exactly that key for an INT8 DMS
  store, so the AR route is the oracle the verifier must match.
- The verifier does not use it. `_full_attn_int8_verify_fn`
  (`hipengine/runtime/qwen35_gguf_runner.py`) resolves the paged
  `per_token_head_gqa_splitk_gate_bf16_verify_chain_spans` leaf through
  `_full_attn_shared_batch_spans`, which requires `spans_mode == "uniform"`
  and a one-element `live_counts` per row. A DMS span set is
  `spans_mode == "per_head_variable"`, so the builder returns `None` and the
  runtime declines at `qwen35_gguf_mtp2.py:2855`.

This entry records the first increment: the primitive the wiring depends on had
no numerical gate of its own. The BF16 sibling is gated by
`tests/test_gpu_dms_compact_attn_decode_hip.py`; the INT8 kernel's only test
coverage was a codec-qualification refusal in
`tests/test_gpu_kvcache_dms_device_hip.py`.

## Changes

- `tests/test_gpu_dms_compact_attn_decode_int8_hip.py`: a numerical gate for the
  INT8 split-K attention against `compact_attention_reference`, fed the
  dequantized payload so a pass means the kernel read the same tokens the AR
  route would. Cases: variable per-head counts (3 rows x 2 heads, live
  [[3,5],[7,1],[24,2]]), the dedicated wave branch (24q/4kv/256d/rows=1, the
  shape `dms_int8_attn_split_wave_kernel` is selected for), live == 0 writing
  zeros, live == 1 returning the single V row, registration under the INT8 key,
  and wrapper validation before any GPU load. INT8 payload past each head's live
  extent carries 127 with scale 64, so an out-of-extent read corrupts the output
  rather than passing quietly.
- The oracle cannot carry the zero-live edge: `compact_attention_reference`
  range-checks `live` against `(0, capacity]` and raises. The structural test
  covers live == 0 directly against zeros and the V row instead, and the
  numerical cases stay at live >= 1.
