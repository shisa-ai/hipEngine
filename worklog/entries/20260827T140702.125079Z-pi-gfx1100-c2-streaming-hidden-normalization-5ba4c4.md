# Normalize physical streaming hidden rows before NextN

## Summary

Fixed the physical prompt-streaming representation: completed target trunk rows
now pass through the target output norm before NextN consumes them, matching the
qualified host-replay and direct-MTP hidden policy. The prior physical streaming
experiment fed raw pre-output-norm BF16 rows and therefore measured a different
provider trajectory.

## Changes

- Allocate one request-owned bounded normalized hidden chunk buffer per streaming
  sink.
- Attach an output-RMSNorm transform to `_StreamingNextNPromptSink`; target and
  provider operations remain ordered on one stream.
- Free normalization buffers on success, rollback, constructor failure, request
  release, and adapter close.
- Preserve physical streaming default-off pending an independent category/
  economics rerun.
- Extend streaming ownership tests to execute the transform, check weight/row/
  stream arguments, and prove buffer drain.

## Validation

- Root cause: qualified fallback converts post-output-norm F32 capture to BF16;
  direct MTP's streaming path explicitly applies output norm; staged physical
  streaming omitted the transform. Its measured acceptance fell **77.31% ->
  71.07%** and complete throughput to **0.771x AR**, so that raw-row result is
  rejected and not reusable.
- MTP2 seam, streaming sink, and NextN provider bundle: **99 passed**.
- Ruff (with pre-existing E731 ignored) and `git diff --check` pass.
