# Bind GGUF named profiles to actual artifact qualification

## Summary

Close the final known F5 named-profile authorization bypass from the integrated
review, starting at clean `6fb94aae9808e5dd39ba485570a94005ad92615b` on
`ud-quants`. Implementation is complete **pending independent review**. The
assignment accepts bounded F1 load/execution/physical operands, F3/F4 shared
owners/certificates/geometry and F2/F6; it does not accept U1 overall. No other
agents, GPU execution, new kernels, math, numerical certification, performance
claim, dependency, new environment flag, U2, push, publish or deploy work.

The reproduced caller chain was actual `LLM.generate` -> auto/explicit plain
quant key -> plain `resolve_runtime_profile` ->
`ResolvedRuntimeProfile.construct_generator` -> Qwen3.8 production binder ->
FP16 recurrent-state environment `1`. The truthful tiny unknown manifest passes
generic AR admission but has the unqualified sentinel and a false qualified
FP16 default. The binder-generated write was profile authorization, not explicit
user consent. Prior sentinel/policy/physical repairs are preserved.

## Changes

- `RuntimeProfilePlan.qualifier` is a cold plugin hook, not another registry
  axis. Artifact-scoped GGUF strict and production plans register the shared
  qualifier. Resolution validates the strict scope and selected plan against
  actual factory metadata **before** variant-package loading or factory/binder
  calls. Missing context, `weight_index=None`, and a fake object carrying
  `artifact_preset_key=None` fail closed, rather than treating None as proof.
- `loading.qwen35_gguf_admission.qwen35_gguf_artifact_identity_from_info` owns
  the shared header adapter. It builds the actual production AR and structural
  NextN maps and delegates to existing role-manifest/preset admission identity:
  pinned plain `None`, unknown sentinel, and exact UD preset keys remain
  distinct. The runner policy adapter now uses this same owner. No filename
  allowlist, histogram certificate, alternate manifest classifier, fifth axis,
  or backend/quant dispatch branch is introduced.
- `generation.gguf_profile_qualification.qualify_plain_gguf_profile` requires
  actual GGUF header metadata, consistent supplied model path, pinned plain
  admission identity and the existing dense-27B/MoE-35B Q4_K_M profile scope.
  Both backend registrations retain their existing strict/production selections
  and hashes. Small-model/Q4_K_S controls keep their independent plain admission
  and policies; their inclusion in the pin set does not numerically certify
  these verifier-shaped named plans.
- `LLM._resolve_execution_profile` forwards the actual loaded header for both
  public auto and explicit quant selectors. The GGUF control-smoke script's
  direct resolver calls forward its actual scanned header too. Other profile
  plugins without artifact-scoped qualifiers keep their existing contract.
- `ResolvedRuntimeProfile` binds an immutable artifact identity separately from
  its existing variant-manifest hash. Construction revalidates supplied inputs
  before invoking even a custom factory, then validates the returned generator's
  metadata. Custom generators retain `weight_index` and consistent `model_path`
  when supplied. Reuse for another pinned plain artifact, unknown header,
  inconsistent path or absent context refuses. Metadata conflict/immutability
  checks precede binder writes. The public resolved binder is guarded as well:
  it validates generator identity and rejects a different resolved plan before
  calling the private plugin hook. Manually calling private Python functions or
  forging objects is not this API trust boundary.
- Unsupported named profiles clearly refuse. There is no registered,
  artifact-qualified generic strict profile for unknown/UD manifests, so
  successful generic AR operation admission does not imply strict numerical
  certification or authorize a production fallback. Unknown/UD strict,
  production and batch-invariant selections cannot borrow the plain plan.
  Qualified plain batch-invariant requests retain the registered strict
  fallback. Exact UD AR and MTP scope remain separate; K_M/K_S still refuse on
  their 18/41 missing consumers. No F1 C1/native/physical gate is bypassed.
- Explicit documented developer overrides remain independent diagnostic/rollback
  seams. They cannot satisfy the profile qualifier; `FP16=0` and `FP16=1` remain
  unchanged on refusal. Valid strict/production binder values and gfx1100's
  explicit R28/Q6 rollback semantics remain covered. Failed binder application
  restores the prior process environment, and existing outer restore contexts
  still work. Successful legacy binders continue to be process-scoped; no new
  per-generator concurrent environment isolation is claimed. REFACTOR records
  the eventual session-owned policy migration trigger, rather than disguising
  internal binder writes as user consent.
- New `tests/test_gguf_profile_authorization.py` has 63 CPU cases. Actual public
  LLM resolution and public resolved construction/binder chains use the real
  registry and hooks; generator/payload/device boundaries are mocked. Positive
  controls use real local headers through `tests/_gguf_profile_fixture.py`,
  skipping if unavailable, never patching numerical pins. Unknown negatives
  use the existing real block-truthful tiny GGUF writer and remain portable.
  Existing three GGUF binder test files and serving-manifest tests now supply
  actual header context rather than unqualified fake generators. PLAN,
  EXECUTION-PROFILES and UD-QUANTS describe the contract and pending review.
