# Attribute current single-request AR decode costs

## Summary

The lead authorized decode improvements in order: single-request AR attribution,
MTP snapshot/rollback, request-local draft vocabulary, prompt lookup, then
remaining measured small-row kernel work. This unit owns the first packet.
Compare current-source private and shared-batch width-one decode on identical
inputs rather than attributing the old direct/HTTP gap to serving alone: the
older direct result predates the Q4 numerical binding repair.

## Changes

- Added an external diagnostic driver at
  `/tmp/qwen38fn-decode-20261022/ar_attribution.py`. It loads one shared resident
  model plus the existing MTP sidecar, uses the current production profile,
  and imports the same private prefill into a width-one batch slot. This initial
  attribution ran before runtime changes.
- Eight cases cover four categories at fresh 1024/4096 tokens, 63 forced inputs
  from the latest public AR outputs, and two repetitions with reversed arm
  order. Compact outputs, positions and within-route repeat IDs are checked;
  cross-route IDs are diagnostic, not assumed equal.
- All-sparse batch steps now pass the index owner's device selection directly
  to attention. Dense and mixed steps keep their staging path. The host API
  remains available for mixed steps and diagnostics; a borrowed device handle
  is consumed on the same stream before the next selection overwrites it.
- Batch attention now chooses the existing exact head-pair variant for H256,
  page256 and an even query-to-KV-head ratio. Other shapes keep strict rows.
  The batch manifest records the geometry, selected variant and strict rows
  oracle. No kernel body, Q4 binding or arithmetic profile changed.
- RED tests reject the old host handoff and missing shape selection. New tests
  cover permuted rows, wider scratch stride, transitions and stream ordering;
  a manifest test detects a changed geometry/identity binding.
