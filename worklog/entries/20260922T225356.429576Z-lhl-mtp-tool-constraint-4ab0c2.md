# Required tool-call constraints on the live sampled MTP route

## Summary

The `tool_call_constraint` hook now has a live gate case, and that case failed the
first time it ran. Both defects it exposed were in the speculative route, not in
the constraint, and both are fixed in `861a20010`:

1. `sampled_accept_summary` took an `observe_text` argument and never passed it to
   `row_prefix_states` or `row_forced_token_ids`, so the adapter's per-row text
   observer never ran. A cycle's later rows were masked against a DFA that had not
   seen the earlier tokens, and the route could publish a token the request's own
   constraint rejects. The live failure was exactly that: a newline inside a
   required tool envelope, raised by the commit as
   `selected token violates tool_call_constraint`.
2. A row advanced by a violating *draft* token then has no admissible law at all.
   That is expected on the walk -- the autoregressive route never emits such a
   token, the draft may propose one -- and the row is unreachable: the row before
   it is masked against the same DFA and excludes that token, so the accept walk
   corrects there. The walk now records the row's constraint as invalid instead of
   raising, `sampled_accept_from_distributions` accepts `None` for such a row, and
   stepping onto one raises rather than sampling a law that does not exist. The
   commit path keeps the strict check, because a *published* token that violates
   the constraint is a defect.

The gate case uses `mode="required"`, so the constraint admits only the canonical
envelope and the model cannot take the plain-text branch. Greedy, so the two arms
must publish identical ids. Its observable acceptance is one complete envelope:
`<tool_call>{"name":"read","arguments":{"path":"/tmp/notes.txt"}}</tool_call>`.

## Changes

- `scripts/mtp_forced_token_gate.py`: `tool_call_required` case (required-mode
  constraint, 20-token budget, greedy) plus its two checks -- one envelope, and the
  named tool inside it. Both checks moved into the per-arm report, so either arm
  failing to complete the envelope is caught.
- `hipengine/generation/mtp_sampled_accept.py`: pass `observe_text` into both
  walks; `row_forced_token_ids` takes it (a text-keyed constraint *queues* the
  closing suffix that governs a row's edge, so a row that skips the text also skips
  its override); a row whose text constraint is invalid gets a `None` law.
- `hipengine/speculative/sampling.py`: `sampled_accept_from_distributions` takes
  `SparseDistribution | None` per row and raises if the walk steps onto a `None`.
- `hipengine/generation/sampling.py`: `RowSamplingState.token_text_constraint_invalid`
  and `observe_selected_token_text(..., drafted=True)`, which marks a violating
  draft invalid instead of raising. `SparseDistribution` refuses an empty support,
  so "no law" is expressed by the row itself rather than by an empty distribution.
- `hipengine/generation/qwen35_gguf_mtp2.py`: the walk-time observer is built once
  and used by the native-sampler branch too, which had the same missing walk.
- Tests: `tests/test_unit_mtp_sampled_accept.py` drives `sampled_accept_summary`
  (not `row_prefix_states`) so the wiring is what is pinned, plus the
  violating-draft case; `tests/test_unit_mtp_forced_token_gate.py` covers the new
  case's shape and checks; two native-sampling doubles gained the `generator`
  attribute the method reads.
- `benchmarks/results/2026-09-23-gfx1151-qwen38-bf16-mtp-forced-tokens.json`:
  updated with the sixth case, its cycles, and the tool-branch observation. The
  five earlier cases published the same ids as before, so the fix did not move
  them.
