# Audit AGENTIC-QUALITY2 live quality stack

## Summary

Audited the current Qwen automatic-tool runtime and repaired the existing A6
collector before using it as the AQ2 denominator. Current Qwen uses the generic
canonical tool parser and tokenizer-backed `ToolCallConstraintState`; Poolside's
model-owned parser is a separate Laguna path. `tool_choice=auto` permits plain
text, but once a tool branch begins it constrains one declared name, canonical
envelope, and syntactically valid root argument object. Full strict JSON Schema
validation remains post-generation. Decode-time schema anchoring is limited to
the first required string key for required/specific single-tool requests.
There is bounded structural close completion, not a second generation repair.

The previous collector had one binding scoring bug: external-oracle rows were
required to match exact argument text before their executable oracle was
consulted. RED reproduced an equivalent `19 * 37` calculation that passed the
external oracle but was scored `wrong_arguments`. GREEN makes external-oracle
success primary for broad quality while retaining exact arguments as a
diagnostic; legacy suites without an external oracle still require exact
arguments.

AQ1 also makes the live packet auditable/restartable: the collector now verifies
and hashes served model/backend/cache/tokenizer/tool capabilities before any
request, uses a backend-neutral provenance label, records repetitions/output
cap/capabilities, prints flushed per-turn progress, atomically checkpoints
normalized records plus local raw response/prompt IDs, atomically replaces final
JSON, and reports normalized deterministic repeat equality while excluding
random call IDs. Raw checkpoint responses plus response-owned token IDs allow
AQ3 to reconstruct pre-parser text without weakening the public API.
