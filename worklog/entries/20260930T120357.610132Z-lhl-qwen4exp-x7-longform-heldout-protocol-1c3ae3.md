# X-7 long-form heldout: the sibling protocol that can actually engage the route

## Summary

X-7's first missing certificate is category-heldout numerical evidence for the
promoted 16-47 scope. The existing heldout protocol could not produce one: the
18-prompt admission suite tops out at 71 tokens against `dense_wide`'s 257-row
floor, so every heldout run over it compared two runs of the same kernel.

The prior entry established that the blocker is genuine and named the input that
closes it. This entry builds the protocol.

## What changed

**New fixture** - `benchmarks/fixtures/qwen4exp_longform_heldout_4prompt.json`,
built by `scripts/build_qwen4exp_longform_heldout_fixture.py` from
`benchmarks/prompts/qwen4exp-natural-long-tasks-v1.jsonl`. Four natural long
tasks, one per category, all above the floor:

| case | category | tokens | vs 257 floor |
| --- | --- | --- | --- |
| `long_code_booking_merge` | code | 438 | 1.70x |
| `long_general_en_release_decision` | general_en | 508 | 1.98x |
| `long_general_ja_retention_review` | general_ja | 424 | 1.65x |
| `long_mixed_ja_en_acceptance` | mixed_ja_en | 512 | 1.99x |

Same per-case schema as the admission suite (`id`, `category`, `prompt_tokens`,
`prompt_token_ids`, `prompt_token_ids_sha256`, `suite`), so it loads through the
gate's existing `_load_fixture` unchanged. SHA256
`b2d37b8f5f8c33d1b530ffc336e7e1211debccdd582f90437e97805243c0af07`.

The builder asserts the four categories are **exactly** the required set rather
than counting them. A suite that silently dropped `general_ja` would pass a
`len(categories) == 4`-style check only by accident and would leave a category
unqualified while reporting full coverage of what it ran.

**Gate** - the two heldout protocols are now a table, `HELDOUT_PROTOCOLS`, keyed
by fixture hash, carrying each protocol's `kind`, `protocol` string and expected
case-id set together. `_fixture_kind` and `_heldout_coverage` both read it, so a
suite is always accounted for under its own identity and neither can be read as
the other.

The admission protocol's behaviour is unchanged: same hash, same 18 ids, same
protocol string, same coverage record shape.

## A bug the tests caught in my own edit

`heldout_fixture_identity` was still `fixture_sha256 == ADMISSION_FIXTURE_SHA256`
after I moved the id set into the table. The long-form run therefore had all
seven checks correct *except* identity, and `complete` came back `False` on a run
that had genuinely engaged - the exact false-refusal shape this check has
produced once before.

The test caught it; I would not have. It is fixed to
`fixture_sha256 in HELDOUT_PROTOCOLS`, and there is now a test that asserts the
long-form run is `complete` and that its engagement check passes, which fails if
either the identity check or the engagement check regresses.

## Changes

**Tests** - `tests/test_unit_qwen4exp_heldout_coverage.py`, five added:

- `test_longform_fixture_hash_matches_the_file_on_disk` - a drifted hash silently
  disables the only suite that can engage, and the gate would classify it
  `unknown` rather than erroring.
- `test_longform_fixture_is_built_from_its_declared_source` - re-hashes the
  declared prompt suite, so editing either side is caught.
- `test_the_longform_suite_qualifies_the_dense_wide_route` - the reason the
  sibling exists: 512 rows clears 257, the record is `complete`, and the
  canonical `complete` flag still stays `False`.
- `test_the_two_heldout_protocols_are_not_interchangeable` - **both** directions.
  Long-form captures under the admission hash fail on case ids; admission
  captures under the long-form hash fail on case ids *even though the engagement
  check would pass*, so the id check is load-bearing rather than decorative.
- `test_fixture_kind_separates_the_two_protocols` - extended to the new kind.

All 35 tests across the four gate-related files pass.

## Validation

```
uv run --no-sync pytest tests/test_unit_qwen4exp_heldout_coverage.py \
  tests/test_unit_q8_prefill_qualification_coverage.py \
  tests/test_unit_q8_dense_prefill_route_gate.py \
  tests/test_unit_qwen4exp_wmma_gate_route_arms.py -q
# 35 passed
```

Both fixtures load through the gate's own `_load_fixture`. `ADMISSION_FIXTURE_SHA256`
now appears only in its own definition and as a table key - no hardcoded
comparisons remain. The `--fixture` help names the long-form path.

## What this does not establish

**No numerical claim.** The plumbing is validated; whether `dense_wide` at 16-47
passes the long-form heldout gate is a measurement, and it is running
(`benchmarks/results/2026-09-30-qwen4exp-x7-longform-heldout/`). The WMMA route's
heldout evidence already exists and **fails** at prefill->c1 (mean KL 2.06e-3
against a 1e-3 limit), so a passing long-form run for `dense_wide` would be a
route-specific result and not a general clearance.
