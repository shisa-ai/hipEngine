# D4 flash-decoding at head_dim 512 for the global layers

## Summary

Punchlist row D4 ("Split-K flash-decoding at head_dim 512, the same design
as D2") extends the landed D2 flash route to the artifact's five global
layers (q=16, kv=2, head_dim=512, GQA ratio 8, the row that grows 0.75 ->
2.82 ms from 1024 to 4096 context). The design carries over unchanged;
what changes is the packing and the row width:

- The flash kernel is now `template <scalar_t, kQ, kHalves>` with the two
  admitted packings instantiated by a shape dispatcher:
  `kQ == 2, kHalves == 1` (head_dim 256, sliding) and `kQ == 8,
  kHalves == 2` (head_dim 512, global). Any other (head_dim, ratio)
  returns the capability miss and the incumbent split/class chain keeps
  the request, exactly as before.
- Phase A folds the row's two 256-dim halves into the same eight
  per-lane partials before the warp tree -- the class kernel pass-1
  pattern (`q_reg[h][i] * k_row[h * 256 + base + i]`) -- so hd512 keeps
  one tree call per (key, row) with K loaded once per key and shared by
  all eight query rows.
- Phase B and the combine both stride dimensions with the
  `gemma4_decode_pass3` pattern (`d0 = tid*2; d0 += threads*2`), so 128
  threads cover head_dim 512 in two passes. (First GREEN attempt missed
  the combine's stride: hd512 dims 256..511 were never written, which
  localized to `err == |expect|` exactly on the second half.)
- Masked keys now store no logit at all: the weight pass derives `keep`
  from the mask and never reads their slot, so a poisoned workspace
  still cannot leak (the poisoned-workspace tests run per geometry).
- Python `flash_admits` admits exactly `((256, 2), (512, 8))` at
  `tokens == 1`; the C dispatcher re-checks the same two shapes.

## Changes

- `gemma4_attention.hip`: templated flash kernel (kQ/kHalves, half fold,
  strided phase B), strided combine, `gemma4_decode_flash_launch_impl`
  + shape-dispatching `gemma4_decode_flash_launch`; file-scope
  `kFlashQPerKV` constant removed (it is a template parameter now).
- `gemma4_attention.py`: `flash_admits` for both packings, docstring.
- `tests/test_gpu_gemma4_flash_decode.py`: every contract test
  parametrized over `_SLIDING` and `_GLOBAL`, the capability surface
  asserts both positive shapes, `_NON_FLASH` gains (16,4,512) and keeps
  ratio-8-at-256 and ratio-1 as misses; the production-wrapper test runs
  per geometry. 32 -> 60 tests.
