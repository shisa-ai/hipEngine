# Parameterizing the AOTriton window bounds

## Summary

P1's clearing command has been revised twice and both revisions ended on a
test that could not be run: first one needing a runtime that does not ship,
then one needing an integer window bound that **nothing in Python can
express**. This makes the second one executable. `window_left` and
`window_right` become parameters of the shim that hardcoded them, defaulting
to exactly the values it hardcoded — so the change is additive for every
existing caller and the default path is unchanged by construction.

## Changes

- `hipengine/kernels/hip_gfx1100/attention/aotriton_wrap.cc` — two `int32_t`
  parameters on the extern "C" signature; the two hardcoded sentinel
  assignments become reads of those parameters
- `hipengine/kernels/hip_gfx1100/attention/aotriton_wrap.py` —
  `_WINDOW_BOTTOM_RIGHT` / `_WINDOW_TOP_LEFT` constants, two keyword-only
  arguments defaulting to the sentinel, two `c_int32` in `argtypes` and two
  in the call
- This entry

No caller was modified: the three production sites keep their previous
behaviour without any edit of their own.

## The change

`hipengine/kernels/hip_gfx1100/attention/aotriton_wrap.cc` — the extern "C"
signature gains two `int32_t`, and lines 460-461 become:

```cpp
  params.window_left = window_left;
  params.window_right = window_right;
```

`hipengine/kernels/hip_gfx1100/attention/aotriton_wrap.py` — the wrapper
gains two keyword-only arguments defaulting to `_WINDOW_BOTTOM_RIGHT`
(`-2147483646`, AOTriton's `WindowValue::BottomRightAligned`), two
`c_int32` in `argtypes`, and two `c_int32` in the call.

**Defaults equal the previous hardcoded bytes.** That is the whole safety
argument: no existing caller passes the new kwargs, so Gemma 4
(`gemma4_attention.py:743`), the Qwen3.5 runner (`qwen35_gguf_runner.py:5105`)
and Qwen3.5 PARO (`qwen35_paro.py:4048`) all keep sending precisely what they
sent before. The blast radius was wider than one file — three production
callers across two model families — which is exactly why the defaults were
chosen to make the delta zero rather than "reviewed as likely equivalent".

## Why this was worth doing rather than leaving documented

Two iterations ago P1's gate was called out as *a gate nothing can clear*,
which the project treats as a bug in the gate. Iteration 25 then wrote a
replacement gate whose own text said "before any rebuild is considered"
while describing a test that was already answered. A third version that
named an untestable configuration would have been the same defect wearing a
new label. The options were make it runnable or stop claiming it is a gate —
so it is now runnable.

## Validation

Build-cache behaviour was checked first, because a changed `extern "C"`
signature against a stale `.so` is a silent ABI mismatch, and
`hipengine/core/build.py` states *"Build keys hash source bytes, normalized
flags, and compiler versions"*. Confirmed in practice: the build produced a
**new** cache directory `aotriton_wrap-aac8d8a8f45a71e7` alongside the old
`aotriton_wrap-82dfab76fc641c7e`, i.e. the key moved with the source and a
fresh `.so` was compiled rather than the previous one being reused.

- `tests/test_gpu_gemma4_attention_aotriton_parity.py` — the regression
  guard for exactly this claim: flash ≡ exact causal through the parameterized
  path. **Passes**, so the default is unchanged, not merely believed to be.
- `tests/test_unit_aotriton_wrap_exception_boundary.py`,
  `tests/test_unit_aotriton_discovery.py` — **pass**; both reference the symbol.
- Full `-k aotriton` selection — **0 failed, 0 errors**, including the
  Qwen3.5 admission and stream unit tests that exercise the same wrapper.
- Python syntax parsed with `ast` before running anything.
- `argtypes` and the call verified by reading them back after the edit:
  `c_float, c_int32, c_int32, c_int32, c_void_p` = sm_scale, is_causal,
  window_left, window_right, stream — matching the C order.
