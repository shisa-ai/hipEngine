# PARO live rollback oracle boundary

## Summary

The six live failures are explained by an oracle-boundary defect in the tests.
The empty observation lists are an instrumentation artifact, not evidence of a
production state bug. Both tests captured the provider snapshot after
`propose_batch` had already drafted candidates, then compared it with the state
after rollback. The provider journal restores the pre-draft point, so at the
current depth-two default the post-proposal provider fields cannot match. At
depth one the proposer does not advance, which is why the same oracle previously
passed.

The failure was hidden because the tests asserted inside the rollback hook. The
engine catches a rollback exception, recovers the request, and the test then saw
only an empty `restored`/`checked` list instead of the real snapshot mismatch.

The repair captures the provider snapshot before proposal and combines it with
the pre-verify target checkpoint. It records rollback observations instead of
asserting inside the hook, then asserts after generation: the journal was open
before restore and cleared after, the provider result is invalid, the raw
state diff is empty, and the next public request matches its baseline.

The parent live rerun then passed the four graph-replay nodes and target-37 but
failed provider-37. The provider injection condition was still gated on the
pre-proposal provider snapshot, which exists before drafting. At depth two,
`advance_with_previous_hidden` calls `advance_with_target_hidden` during
proposal, so the test injected there, before `_checkpoint_target`, and never
reached the post-target provider reconciliation. The repair adds explicit
per-cycle phases: reset both at proposal start, mark `target_checkpoint` after
`_checkpoint_target`, mark `target_verified` after `_verify_target` returns, and
allow provider injection only when both are true. The test records the phase at
injection and asserts both flags. The pre-proposal provider and pre-verify
target snapshots remain the rollback boundaries.

No runtime, packed-prefill, docs, audit, staging, or commit changes were made.

## Changes

- `tests/test_live_paro_mtp_rollback.py`
  - Added `_PROVIDER_KEYS`, `_snapshot_diff`, and `_result_probe`.
  - Captures provider state before `propose_batch`; combines it with the
    pre-verify target snapshot.
  - Records journal-before/journal-after, result validity, candidate-token
    refusal, and exact snapshot differences after rollback.
  - Adds a baseline and recovered request to prove next-request correctness.
  - Adds explicit proposal/target-checkpoint/target-verified phases and
    records the phase at injection; provider injection requires both target
    phases, so drafting advances cannot trigger it.
- `tests/test_live_paro_mtp_graph.py`
  - Applies the same pre-proposal provider plus pre-verify target oracle.
  - Records rollback observations and asserts journal open/cleared, result
    invalidation, candidate-token refusal, empty state diff, and the existing
    next-request baseline equality.
  - Preserves failure/cancel injection after an actual replayed graph.
- The native-submission error tests and graph parity test are unchanged.
