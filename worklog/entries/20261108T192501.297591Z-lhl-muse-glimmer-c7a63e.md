# Muse Glimmer prefill-inject TTFT: large-chunk WMMA projections (~2.8x faster)

## Summary

Task #6 (§11 #4, lowest priority — fresh-conversation TTFT; the agentic case is
already mitigated by prefix reuse + save/load). The DFlash drafter's `inject`
builds draft K/V from the target's residual taps over the whole prompt. It
chunked at block_size=16 and ran the projections through the exact-row rowtile
owner, which internally chunks at 8 rows — so each fc/K/V weight was re-read
every 8 tokens (fc alone is ~128 MB; ~131 GB of fc reads at 32K). rocprof of an
8K inject: 78% Q4 rowtile + 19% Q6 rowtile (weight reads), 28% host gap.

Injection owes no bit-exactness: it builds the draft KV from target taps; the
draft only proposes and the exact verify corrects every committed token. So the
inject now runs in large chunks (_INJECT_CHUNK=1024, dedicated scratch) through
the WMMA prefill projections, which amortize each weight read over the whole
chunk. Measured fc projection at 1024 rows: exact rowtile 146 ms -> WMMA prefill
28 ms (~5x). The draft block keeps its small-row exact owners (unchanged).

Measured inject (synthetic features, linear rate): 0.215 -> 0.076 ms/token
(~2.8x). 32K: 7.05 -> 2.48 s; 126K: 27.1 (old rate x 126K) -> 9.57 s (measured).
The rate is linear at 1K/8K/32K/126K (no superlinear blowup). This is the
drafter-inject portion of fresh-conversation TTFT; the target prefill is
unchanged.

## Changes

- hipengine/runtime/muse_glimmer_dflash.py: `_INJECT_CHUNK=1024` + dedicated
  inject scratch (`_inj_feat/_inj_hidden/_inj_normed/_inj_k_bf16/_inj_v_bf16/
  _inj_k_f32/_inj_k_rot/_inj_dummy_q/_inj_positions`); `inject` chunks at
  _INJECT_CHUNK and uses `_inject_linear` (launch_gguf_linear use_wmma_prefill)
  instead of the exact-row owner. K rope/casts/KV-append unchanged. The draft
  block path and its exact owners are untouched.
- No flag (default path; the inject arithmetic change is bounded by the exact
  verify, which keeps DFlash IDs == true AR).
