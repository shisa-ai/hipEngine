# Keep Gemma generation kernel dependencies in the collection snapshot

## Summary

The isolated Gemma public-generation test file loaded its generator inside
test bodies. The first test imported the kernel modules and passed, but the
shared teardown restored the earlier collection-time registry snapshot,
which lacked those registrations. Later tests saw cached modules and failed
profile validation with missing kernels. This is test isolation, not a
production missing-kernel capability or a numerical failure.

The test file now imports its generator dependency during collection, before
the existing snapshot hook. No shared test infrastructure, production source,
kernel arithmetic or profile gate changes.

## Changes

- `tests/test_unit_gemma4_generate.py`: move the generator factory import to
  collection time and remove the two redundant function-local imports.
- Add CPU-only strict/production dependency assertions, covering every selected
  and fallback key after prior tests restore the registry. No manual owner list
  or identity admission is added; keys come from the profile plans themselves.
- All existing HIP-availability guards remain on the GPU-backed user-path tests.
