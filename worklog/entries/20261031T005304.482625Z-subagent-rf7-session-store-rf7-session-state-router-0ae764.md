# RF7 session state owner and core session router

## Summary

Moved app-local chat transcript, pending-reservation and continuation state out
of ``create_app`` into ``hipengine/server/chat_sessions.py``. The owner receives
explicit policy values and per-operation data and raises typed
``SessionStateError`` values. Added ``hipengine/server/session_routes.py`` for
the list/delete/fork/rollback routes; snapshot validation and its two routes stay
in the application for the next unit.


## Changes

- ``hipengine/server/chat_sessions.py``: ``ChatSessionStore``, records,
  reservation/continuation operations, transcript commit, fork/rollback/delete,
  listing/summary, and deep-copy helpers. ``snapshot_record`` is a narrow async
  context-manager lease that holds the original session lock through the
  caller's payload construction and 404 handling.
- ``hipengine/server/session_routes.py``: four core session routes with the
  application's real auth dependency and a narrow typed-error translator.
- ``hipengine/server/api.py``: composes the router, translates state errors at
  the existing generation and snapshot operation boundaries, keeps
  ``app.state`` map identities, and passes normalized session counts to
  metrics. Snapshot export uses the store lease so tokenizer and payload
  construction remain inside the session lock.
- Migrated test/support consumers to import ``_chat_session_message_copy`` from
  the owner instead of through ``hipengine.server.api``; added the new owners to
  the pure-owner consumer contract.
- Added ``tests/test_unit_server_chat_sessions.py`` and a zero/None session
  metrics assertion.
