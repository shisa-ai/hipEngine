# Profile the exact dimension-partition candidate

## Summary

The exact dimension-partition candidate's slowdown is in the value pass.
Scoring durations are similar between the cached incumbent and candidate.
At 1024 keys / head dimension 256, scoring medians are 114.710 and 115.944 us;
value-pass medians are 90.161 and 344.050 us. The incumbent also launches a
3.547 us combine. These are isolated attention diagnostics, not end-to-end wins.

Both traces ran on host `epyc`, physical GPU1 RX 7900 XTX, BF16 input/output,
16 query heads, 2 KV heads at dimension 256 or 8 at dimension 512. Keys were
1024, 1152 and 4096. Each shape ran eight invocations; medians exclude the first.
The driver allocates and transfers between invocations, so these traces do not
establish steady-state cache behavior. CSV rows were sorted by Dispatch_Id before
pairing; profiler CSV file order is not necessarily dispatch order.

## Next

The dimension candidate uses the key-split count as its number of dimension
blocks. A 32-thread block therefore processes several dimensions per lane in
separate ascending-key loops. Assigning one dimension to each lane, with enough
blocks to cover the complete head, removes that serial outer loop. It preserves
the order within each dimension but duplicates weight loading across more blocks.
Test correctness, then measure rather than assume that concurrency beats this cost.
