# Stabilize C2 production repeat schedule

## Summary

Separated same-schedule determinism from neighbor permutation isolation in the
new physical C2 numerical gate. The first one-pair run passed every binding
numerical threshold but intentionally reversed pair order on repeat 1, so its
capture positions/schedules differed and the repeat check correctly failed.

## Changes

- Keep all three binding repeat runs on one stable request/slot schedule using a
  deterministic 10 ms submission stagger that still forms physical C2.
- Run a separate reverse-pair pass without correctness capture and require each
  prompt's output to match its same-schedule result.
- Report neighbor permutation isolation independently from repeat determinism.
- Fix the CLI summary field (`numerical.aggregate`).

## Validation

- numerical gate **passed** 48 strict-teacher rows at mean/p95/p99/max KL
  `0.000292/0.001477/0.003502/0.004267`, 100% top-1;
- profiles, task, physical capture, output repeat, and lifecycle passed;
- repeat gate failed only because repeat 1 deliberately reversed the pair and
  shifted physical cycle positions; the CLI also raised a post-write KeyError
  when printing the otherwise valid artifact.

After correction, two host tests, Ruff, compile, and `git diff --check` pass.
