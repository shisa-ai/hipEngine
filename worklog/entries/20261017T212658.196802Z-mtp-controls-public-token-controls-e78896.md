# Resolve minimum-token EOS and whitespace-context stops

## Summary

The fresh Q4_K_S public matrix exposed two API control problems. A request
with `min_tokens` but no explicit `eos_token_id` failed before the generator
could apply its tokenizer EOS. Stop strings encoded without their preceding
space missed the runtime token suffix, so the API trimmed the response only
after generating the full output budget.

## Changes

- Resolve the tokenizer EOS before building `SamplingParams` when `min_tokens`
  is positive and no EOS override is supplied. Preserve explicit IDs, including
  zero. Requests without a minimum keep their original fast-path settings and
  do not initialize a tokenizer for this check. A model without EOS metadata
  gets a named `min_tokens` error explaining the explicit-ID option.
- Lower standalone, space-prefixed, and newline-prefixed stop spellings to the
  existing token stop metadata. Deduplicate encodings and tolerate tokenizers
  that cannot encode a spelling. Stops already beginning with whitespace keep
  their exact spelling. This covers common contextual BPE merges, not every
  possible substring inside a token; response post-trimming still applies.
- Add CPU tests for lazy/wrapped tokenizers, EOS overrides, absent metadata,
  whitespace-context stop encodings and deduplication. Add HTTP adapter tests
  for minimum-token EOS resolution on blocking/streaming chat/completions.
- Apply stream stop suppression before stripping speculative finish metadata.
  Single-token stops, multi-token stops and EOS are hidden while their IDs
  remain accounted. An unmatched partial stop prefix is flushed at a length
  limit instead of disappearing. The authoritative terminal chunk still owns
  the final IDs, finish details and MTP telemetry.
- No kernel, arithmetic, speculative route, or product-default change.
