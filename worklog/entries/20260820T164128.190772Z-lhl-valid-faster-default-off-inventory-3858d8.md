# Inventory faster valid default-off and rejected candidates

## Summary

Audited active default-off/opt-in flags, historical rejected/retained artifacts,
REFACTOR decisions, backend capabilities, and current runtime defaults after
removing the fixed magnitude threshold. Promoted the one complete currently
applicable candidate (gfx1151 Qwen3.8 Q4_K_S FP16 recurrent state). Many
apparently default-off wins are stale pre-promotion labels: Moonshine wave8
stable top-1, Laguna exact WPF/attention changes, short-context device metadata,
and state-bound decode graphs are already defaults.

The remaining faster rows are not one homogeneous promotion queue. Some are
valid only inside an explicit feature/backend that the public runtime does not
currently expose; some are accuracy-traded llama-compat routes; some use prior
prompt identities/history and are invalid under anti-gaming; and many improve a
leaf/direct microbench while regressing the binding server or complete wall.

## Changes

- Added `benchmarks/results/2026-08-20-valid-faster-default-off-inventory.json`.
  It separates:
  1. promoted now;
  2. stale default-off labels already promoted;
  3. genuinely faster/correct narrow candidates with concrete blockers and
     recommended next actions; and
  4. exact leaf wins rejected by binding full-path regressions.
- Highest-priority remaining transfer candidate is Laguna DFlash IQ3 tile4:
  exact complete category/heldout evidence and +4.7%/+4.5% DFlash decode on

  global radix defaulting is not non-regressive on the frozen mixed/agentic
  suite and sampled/LRU scopes remain incomplete.
- DFlash prompt-history stacks are not promoted despite exact fixed-suite speed:
  selecting behavior from prior prompt identity/history violates the repository
  anti-gaming rule and does not establish online generalization.
