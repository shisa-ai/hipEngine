# Factor post-attention norm+residual out of the FFN rows method

## Summary

Second bounded prerequisite for the TP2 bulk prefill integration: the sharded
TP2 MLP path needs the post-attention RMSNorm + residual without the full-width
FFN, so the norm+residual prefix of `_run_post_attention_ffn_rows` is now a
separate method `_run_post_attention_norm_residual_rows`. The FFN method keeps
its signature and now calls the helper, then the unchanged MoE/dense branch.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`
  - New `_run_post_attention_norm_residual_rows`: writes `scratch.post_norm`
    (the FFN input) and, on the BF16-residual path, `scratch.residual`; returns
    the optional F32 post-norm diagnostic pointer. It contains the original
    norm+residual statements verbatim (the F32-residual branch with the
    f32/f32 and f32/bf16 add-RMSNorm variants, and the BF16 branch through
    `_gguf_norm_residual_decode_kernel`).
  - `_run_post_attention_ffn_rows` keeps its public signature, calls the helper
    once, and then runs the unchanged `is_moe` / dense branch. The
    `..._post_norm_residual` sync-stage mark and the recorder mark stay in the
    FFN wrapper, so the diagnostic `t_stage` baseline still flows into the
    following `gate_up` stage exactly as before (the helper does not own any
    stage timing).
- `tests/test_unit_qwen35_gguf_attn_prefill_split.py`
  - Structural guard: `_run_post_attention_norm_residual_rows` is defined once;
    the FFN method calls it once; the helper does not call `_mark_sync_stage`
    or any recorder `.mark(`, while the FFN wrapper still emits
    `..._post_norm_residual`.
  - Mocked launch-sequence contract for the helper: with a fake
    `_gguf_norm_residual_decode_kernel`, exactly one add-RMSNorm launch is
    recorded with the forwarded hidden/attn-out/weight pointers, the
    `post_norm`/`residual` scratch pointers, `rows`, `hidden_size` and `stream`,
    and the helper returns `None` on the BF16-residual path.
  - Mocked composition contract for the FFN method (MoE, rows > 1): the helper
    runs first and the MoE branch runs once, consuming the helper's returned
    F32 post-norm pointer.
