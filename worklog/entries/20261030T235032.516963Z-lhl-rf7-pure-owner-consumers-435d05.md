# RF-7 pure owner consumers import owners directly

## Summary

Finished the RF-7 consumer migration for the four pure server owners
(`schemas.py`, `json_schema.py`, `chat_output.py`, `metrics.py`). Application
code, tests and the one script now import those names from the owner module;
`hipengine/server/api.py` imports only the names its own request handling
references. No parser, schema, metrics or HTTP behavior changed. No
runtime/generation file was touched; the GDN owner migration in that tree is
the parent's.

## Changes

- `hipengine/server/api.py`: removed the compatibility-only imports that no
  application code referenced — `_OpenAIBaseModel` (schemas), 14 JSON Schema
  helpers (only `_JSON_SCHEMA_ANNOTATION_KEYWORDS`,
  `_validate_json_schema_subset`, `_validate_json_schema_value` remain), and 24
  chat-output symbols (13 parser entry points remain). The metrics block was
  already fully used and is unchanged. Import comments now say the module
  imports what it applies rather than that it preserves an import surface.
- `tests/test_unit_server_pure_owner_consumers.py` (new): RED/GREEN gate for
  this unit. It asserts every owner name imported by `api.py` is defined by
  that owner and loaded in `api.py` (no unused re-exports), and statically
  scans `hipengine/`, `tests/` and `scripts/` for owner names imported or
  attribute-accessed through `hipengine.server.api`/`hipengine.server`.
- Boundary tests now pin the owner contract instead of every historical private
  export: `test_unit_server_chat_output_boundary.py` and
  `test_unit_server_json_schema_boundary.py` gained `API_APPLICATION_NAMES`
  (the imported subset) while keeping the full owner-name lists for AST/owner
  definition checks; `test_unit_server_schema_boundary.py` no longer requires
  `api._OpenAIBaseModel`.
- Direct consumers migrated (split mixed `hipengine.server.api` import blocks,
  other API names preserved):
  - chat_output: `tests/test_integration_poolside_v1_reasoning.py`,
    `tests/test_integration_server_controlled_speculation.py`,
    `tests/test_integration_server_logprob_bytes.py`,
    `tests/test_integration_server_request_semantics.py`,
    `tests/test_integration_stream_timing.py`, `tests/test_unit_gemma4_chat.py`.
  - schemas: `scripts/prefix_cache_multiturn_bench.py`,
    `tests/test_integration_server_thinking_reserve.py`,
    `tests/test_integration_server_tools.py`,
    `tests/test_unit_gemma4_chat.py`, `tests/test_unit_grammar_masks.py`,
    `tests/test_unit_qwen4exp_chat_protocol.py`,
    `tests/test_unit_qwen4exp_mtp_economics.py`,
    `tests/test_unit_server_live_many_gate.py`,
    `tests/test_unit_server_request_info.py`,
    `tests/test_unit_server_sampled_speculation_admission.py`,
    `tests/test_unit_server_speculative_provider_kv_admission.py`,
    `tests/test_unit_server_token_controls.py`, plus the shared
    `tests/support/server_api_fakes.py`, `tests/support/server_api_support.py`
    and the sixteen `tests/test_integration_server_*` modules that carry the
    copied shared import block.
  - metrics: `_ServerMetrics` moved to `hipengine.server.metrics` in the same
    shared block and support modules.
  - json_schema: no consumer outside `api.py`, so nothing to migrate.
