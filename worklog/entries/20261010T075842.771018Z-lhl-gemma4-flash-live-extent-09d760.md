# Device-resolved flash geometry captures the mid-depth decode step

## Summary

The flash-decoding phase kernel now derives its slice partitioning per block
from a staged device live-extent slot instead of the baked scalar key count,
so a whole-step graph capture replays the 1024-2175-key band bit-identically
to the launched path. The decode graph extends from its 512-row window to the
mid-depth band with a measured +15.4 percent at 1024 prompt tokens (38.81 vs
33.63 tok/s, 3 samples) and +2.2 percent at 2048 (37.74 vs 36.91); deeper
device-bound steps keep the launched fallback (flat-to-negative from 2560).
The launched path is byte-for-byte unchanged: a null slot reproduces the
scalar partitioning exactly, so no execution-profile gate applies.

## Changes

- `gemma4_attention.hip`: the flash phase kernel gains an optional
  `live_extent` device pointer (`[delta, live]` int32 pair). When present,
  each block re-derives `n = flash_slices(live)` (mirroring the Python
  formula exactly) and the boundaries `delta + live*s/n`; blocks at
  `s >= n` are dead (empty slice, l == 0, skipped by the combine, no reads
  past the live range). When null, the arithmetic is the scalar path's
  unchanged. The C decode ABI (`hipengine_gemma4_attention_decode_bf16/f32`)
  gains the pointer argument at the tail; non-flash routes ignore it.
- `gemma4_attention.py`: `_ARGTYPES_DECODE` gains the pointer; `_launch_prefill`
  resolves a module-level `_capture_live_slots` registration (keyed by
  `(head_dim, num_kv_heads)`) set only inside a graph capture.
- `gemma4_decode_graph.py`: the session allocates a stable per-geometry slot
  via `runner._staging_buffer` (allocation only -- an earlier `_stage_upload`
  version of this registration staged zeros over the pair
  `_stage_live_extents` had just staged and the first replay read live == 0,
  producing NaN; caught by the layer probe, fixed by allocating without
  uploading), stages `[delta, live]` per replay per geometry alongside the
  keep-mask, and registers the slots around the recorded region. The guard
  `_SPLIT_ROUTE_MIN_KEYS = 1024` becomes `_CAPTURE_MAX_KEYS = 2176`: the
  measured engagement bound of the launch-bound prize, not a correctness
  bound (all routes below 15328 keys replay bit-exact; the class-global
  kernel and staged singleton above that remain unvalidated for capture).
- Tests: `_raw_launch` gains `live_extent`/`stream` parameters; a new GPU test
  pins the kernel contract (slot over a frozen superset equals the scalar
  launch at the live extent, byte-for-byte, both geometries, three
  extent/live shapes); the deep-position GPU test now asserts 1024 and 2048
  capture bit-exactly and 4096 takes the measured fallback; the workspace
  unit test's fake runner gains `_stage_upload`/`_staging_buffer`.
- Docs: `docs/ENVS.md` and `docs/REFACTOR.md` describe the slot and the new
  prize-bounded guard with its removal condition.

## Validation

- New GPU kernel-contract test: 6/6 pass (slot(frozen) == scalar(live),
  bit-identical, sliding and global geometries).
- Graph-capture ISO (`/tmp/graph_slot_iso.py`): recording the frozen launch
  under stream capture and replaying equals a direct launch of the same
  args, maxdiff 0.0.
- Session end-to-end (`/tmp/graph_div.py`, 1024-prompt, 8 steps):
  replayed vs launched logits maxabs 0.0 at every step, greedy IDs equal;
  before the zero-upload fix this measured NaN at step 0 and rel ~1.0.
- `tests/test_gpu_gemma4_decode_graph_capture.py`: 2 pass (1024/2048
  capture bit-exact, 4096 fallback bit-exact, bucket machinery intact).
- Full related bundle: 264 pass (flash decode, decode parity, workspace,
  gate, bucket, int8-kv, staged selection).
- User surface: `LLM.generate` greedy IDs 128/128 identical graph-on vs
  graph-off at 1024 and 2048 prompt depths.
- Campaign bench (3 samples, natural tokens, correctness gates pass):
  1024: 38.81 (graph) vs 33.63 (launched), +15.4 percent; 2048: 37.74 vs
  36.91, +2.2; 2560: 37.40 vs 37.68; 3072: 36.91 vs 37.40; 4096: 36.78 vs
  37.15; 8192: 35.74 vs 36.17. The 512 row holds at 37.66 (published
  37.75). Primary 32768: 29.927 (band 29.88-30.01, fallback by design);
  prefill 994.7, inside the 949-995 session band.
- Launched-path bit-identity: the slot is null outside captures, so the
  launched flash partitioning is the shipped scalar formula unchanged; the
  227-test parity/flash bundle passes with no arithmetic gate needed.
