# Enable bounded provider checkpoints with radix prefix caching

## Summary

With radix enabled, target-prefix hits restored no draft-provider state because
provider checkpoint capacity defaulted to zero despite implemented restore.
Bounded capture now defaults to four entries when radix is enabled and none
when prefix caching is off. Zero remains an explicit rollback.

## Changes

- Update default and setup in `generation/qwen35_gguf.py`, configuration tests,
  env documentation and rollback-removal condition.
- Add `scripts/int8_mtp_prefix_gate.py`: require real hits, complete reused
  prefix extent, compact INT8, actual speculative cycles and the same IDs as
  prefix-reusing AR. Unit tests reject misses, partial matches, AR-only output
  and different IDs.
- Integrated prior long-prefill commit809f2b98f as5dc7400a1 after the shared
  runner became clean. Its combined priming/prefix/library/admission bundle
  passes187 tests.
