# PN4: next owner measured — launch_gguf_linear T16 GEMV path ~8.9 ms/token

## Summary

After closing the c1 mechanism search, measured the real complete-wall cost of
the largest GPU slice to name the next dominant owner (marker walls overlap and
overstate).

No-op probe (`scripts/pn4_moe_gpu_cost_probe.py`), sync'd eager decode:

- baseline: 30.65 ms/token
- no `launch_gguf_linear`: 21.76 (-8.89 ms/token)
- + no pair: 20.69 (-9.96)
- + no triple: 20.07 (-10.58)

So the `launch_gguf_linear` GEMV path (attention projections + MoE routing
logits + lm_head + per-layer linears) is the single largest complete-wall
slice at ~8.9 ms/token (~29% of the wall). Since the `launch_gguf_linear`
host fast-path A/B recovered only ~857 us/token, the 8.9 ms is ~mostly GPU
kernel time, not host dispatch.

Census over one step (single-patch, `scripts/` probe): the slice is dominated
by Q8_0 T16 attention projections (attn_q 2048->4096 x40, attn_k/v 2048->512
pair_concat + singleton x80 per decode step) plus ~60 tiny dense 2048->32
routing-logit GEMVs and the Q6 2048->248320 lm_head. The MoE Q4_K experts are
launched through a separate path (not in the patched GEMV launchers' census),
adding ~1.7 ms/token via the pair/triple no-op delta.

Verdict: the dominant slice is the same Q8_0 T16 GEMV family proven at its
practical T0 limit by P3-LAQ1-B, so a T0 bit-exact mechanism on this slice is
not expected to flip a meaningful RED. The only real headroom is a non-T0
(production-envelope) mechanism or a launch restructuring (fuse/batch the
per-layer attention projections and routing logits).
