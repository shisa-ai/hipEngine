# Write BF16 prompt KV rows through device page tables

## Summary

Add the BF16 prompt append kernel needed for GGUF requests whose KV pages do not
share one base address. Each row still uses its own logical position and block
mapping; only the destination page address changes.

## Changes

- Reuse the existing mixed FP32-key/BF16-value prompt conversion kernel for
  both contiguous destinations and device page-pointer tables. Register
  `mixed_bf16_prompt_page_ptrs_spans` for both HIP backends.
- Do not change runtime dispatch or relax allocation confinement. Readers and
  writers must switch together before a request can span chunks.

## Validation

- RED: registry lookup failed for the new variant before implementation.
- W7900/gfx1100: the prompt append matched the contiguous writer and the
  NumPy byte oracle over independently allocated, permuted pages. It wrote across
  a page boundary, skipped a negative position, and left every other row intact.
  The focused paged KV and attention wrapper bundle passed (89 tests).
- Cached-build `rocprofv3 --kernel-trace` confirmed that both contiguous and
  page-pointer template instantiations executed. No gfx1151 device run.

## Next

- Wire this writer together with page-aware prefill readers before admitting
  cross-chunk prefill. Long-context decode, INT8 and DMS still have separate
  chunk-local paths.
