# The verifier row slab reaches the fixed-5120 norm leaf

## Summary

`gguf_norm_fixed5120_wave256_kernel` and both of its registry keys already
existed on this backend, but nothing could reach them. Only the gfx1151 package
declared `GGUF_NORM_RESIDUAL_DECODE_POLICIES`, and its table admits `rows == 1`
alone, so every W7900 call fell through to the generic local256 owner,
which reloads `x` and `add` for its second pass and pays nine tree barriers. That
covers the rows-3 verifier slab and the rows-1 decode alike, which is why the
change moves both the verifier census and the true-AR rate.

Both fixed-5120 entry points now accept the verifier row slab (1-8) and launch
one block per row, and the gfx1100 package declares the policy for rows 1-8
under both the plain and the UD-preset-extended keys. One block owns one row,
so every per-thread partial, the tree shape, and the epilogue are unchanged and
each row's output is bit-identical to the rows-1 launch.

Section-6.1 teacher-forced gate on UD-Q4_K_M, both repeats identical to the
last digit: mean/p95/p99/max KL 2.503e-05 / 1.654e-04 / 2.930e-04 / 2.971e-04,
top-1 1.0000 overall and in every category and at every budget, screen passed.

Measured in the verifier window: the `add_rmsnorm` leaf went from 770.07 to
328.56 ms/step (64 calls, 12.03 -> 5.13 us per call, -57.3%), and the whole
verifier from 37067.3 to 36620.6 ms/step at an unchanged 985 calls/step
(-446.7 ms/step, -1.21%).

The remaining norm-family defect is `gguf_rounded_add_rmsnorm_bf16_f32_weight`,
which is a separate kernel with no fixed-5120 sibling and no policy table:
63 calls per step at 13.37 us, 842.38 ms/step (2.3%). It is the obvious
follow-up and is not attempted here.

## Changes

- `hipengine/kernels/hip_gfx1100/fused/gguf_ops.hip`: both fixed-5120 entry
  points take `1 <= rows <= 8` and launch `dim3(rows)`; the kernel offsets every
  index by `blockIdx.x * kHidden`.
- `hipengine/kernels/hip_gfx1100/fused/gguf_ops.py`: `_check_fixed5120_wave256`
  gains `max_rows` (default 1, so the historical message is unchanged) and both
  fixed-5120 wrappers pass `max_rows=8`.
- `hipengine/kernels/hip_gfx1100/__init__.py`: new
  `GGUF_NORM_RESIDUAL_DECODE_POLICIES` covering `(1..8, 5120)` for
  `MOSTLY_Q4_K_M`, `MOSTLY_Q4_K_S`, and the two `gguf_ud_q4_k_*` preset keys.
- Tests: `test_gguf_norm_residual_fixed5120.py` (row-slab range error),
  `test_qwen35_gguf_prefill_scratch_liveness.py` (gfx1100 now resolves the leaf
  and a shape miss still falls back), `test_gfx1151_backend.py` (the gfx1100
  policy table is no longer empty).

All four arms `binding_passed=True timing_evidence_valid=True`, both UD arms
`complete_exact` 0/20 divergent. The change is bit-identical, so the true-AR
movement is a pure speed effect and the MTP/AR ratio falls only because the
denominator improved: at rows 1 the leaf is 16.9 -> 5.9 us per launch, and 127
norm launches per step is about -1.4 ms on a 31.3 ms single-row step. The MTP B3
step is about twice as long, so the same absolute saving is about half the
percentage and sits inside the acceptance-driven spread.

Tests: `tests/test_gguf_norm_residual_fixed5120.py`,
`tests/test_qwen35_gguf_prefill_scratch_liveness.py`,
`tests/test_gfx1151_backend.py` -> 92 passed.

The first attempt declared the policy for both layers without generalising the
plain-`rmsnorm` entry point, and the prefill path
(`_run_linear_attention_prefill_layer_rows` -> `_run_attention_norm_rows`)
immediately failed with HIP error 1 because the `rmsnorm` leaf still rejected
`rows != 1`. That is why both entry points are generalised here: the policy
table is keyed by shape only, so it cannot express "rows 1-8 for `add_rmsnorm`
but rows 1 for `rmsnorm`".

## Next

Give `gguf_rounded_add_rmsnorm_bf16_f32_weight` the same treatment. It is the
last 3-block grid in the verifier, at 842.38 ms/step (2.3%) and 13.37 us per
call. It needs a `kRoundSum` sibling of the fixed-5120 kernel plus a
rows-aware resolver at `_rounded_add_rmsnorm_fn` (the call site at
`qwen35_gguf_runner.py:9079` already knows `rows`), and the same bit-identity
proof, since its reduction consumes an explicitly rounded BF16 sum.
