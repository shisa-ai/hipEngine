# Diagnose harness OOM and record repaired WMMA numerical screen

## Summary

This entry preserves two results from the WMMA sliding-prefill screen at base
commit `8b0069e8f608607c0fe2107d86d836fa851ebdbf`: the diagnosis of the host OOM
that killed the first attempt, and the completed repaired run.

**Host OOM diagnosis.** The kernel's global OOM killer fired at
2026-10-06 12:28:51 local (`kswapd0 invoked oom-killer`, `constraint=CONSTRAINT_NONE`,
`global_oom`) and killed process 3142970 (`python`), total-vm 86,576,776 kB,
anon-rss 15,229,224 kB. `Free swap = 364kB` of `Total swap = 65731580kB`. The
enclosing `tmux-spawn-f73b5ecd-...scope` reported `Failed with result 'oom-kill'`,
and `user@1000.service` reported that the OOM killer killed processes in the
unit; the OOM report identifies only `python` explicitly. The first attempt's
driver held about 8.0 GiB per arm (8 cases x 1025 rows x 262,144 vocab x 4 B) in
memory for the reference, three candidate repeats, and the control (5 arms),
then stacked them for the evaluator, peaking past 40 GiB; `/tmp` is tmpfs on this
host (32 GiB) and was near-full (31/32 GiB) at the time. This entry does not
attribute the kill to any other specific process.

**Repair.** The out-of-repo temp driver was rewritten to write each arm
case-by-case to disk-backed `.npy` memmaps under `--capture-dir` and to evaluate
by streaming `--batch-rows` rows at a time, so the working set is one band plus a
few row batches instead of five resident arms. The evaluator's per-row scalars
(KL, top-2 margin, logit gap, flip) are retained, so the verdict reproduces
`gemma4_teacher_forced_gate.evaluate` exactly. The preflight refuses a tmpfs
capture directory. CPU-only validation passed 79 cases; the direct-GPU
validation passed 20 cases.

**Completed run.** The repaired driver finished a fresh run (not resumed) and
wrote `/tmp/gemma-llamacpp-512-256k/prefill-sliding-wmma-numerics-r3.json`
(log `/tmp/kendex-pi-bg/bg-142-1791275092450.log`; captures under
`/mnt/nvme1/hipengine-diagnostics/wmma-sliding-r3`). The driver exited 1 because
the candidate **failed the numerical screen** — that is a numerical rejection,
not a runtime failure. The run was valid (2400/2400 expected candidate calls,
three bit-identical repeats), the identity control was exactly zero, and the
WMMA candidate failed all five calibrated limits on the frozen chains.

**Production unchanged.** This is a diagnostic screen; it changes no committed
default, no kernel, and no registry entry. The candidate was a registry-entry

in a `finally`. No performance claim is made. The objective is open.
