# Add current-package direct-width numerical gate

## Summary

Make the batch-route numerical adapter capable of certifying the actual current
package's direct c3/c5/c6/c7 routes on gfx1100/Qwen3.8. The prior adapter was
specific to the gfx1151 Q8T16 c4/c8 candidate: it rejected direct widths and
forced the candidate Q8 rowtile environment, so using it as the lifecycle's
arithmetic-drift waiver would not have proven the routes under promotion.

## Changes

- Add an explicit `current_package_direct` route profile while preserving
  `q8t16_candidate` as the default and leaving its c4/c8 protocol unchanged.
- The direct profile removes diagnostic Q8/router overrides during candidate
  execution, evaluates static c3/c5/c6/c7, uses the c7->c6->c5->c3 retirement
  schedule, retains sparse physical-c8 neighbor coverage, records current-package
  manifests, and requires the full 18-prompt/24-step/3-repeat matrix for a valid
  measurement.
- Expand width-schedule validation to registered c1-c8 values.
- Tighten `gguf_arbitrary_c_lifecycle.py`: cN-versus-c1 arithmetic drift may be
  non-binding only with a clean matching `current_package_direct` artifact that
  includes all c3/c5/c6/c7 static widths. Record the physical-width override in
  lifecycle provenance and remove the stale c1/c2/c4/c8-only note.
