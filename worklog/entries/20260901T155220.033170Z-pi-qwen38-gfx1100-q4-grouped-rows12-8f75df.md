# Screen grouped Q4 physical rows12

## Summary

Rejected and fully removed an unrouted exact grouped-Q4 physical-row12
specialization. Halving R24 encoded-weight traversals from four retained R6
chunks to two R12 chunks does not offset the larger accumulator footprint:
five of seven actual Qwen3.8 Q4 roles lose, with full-K falling to 0.631x and
0/30 paired wins.

## Changes

- Temporarily generalized the retained grouped-R6 launcher and instantiated an
  R12 sibling, with ctypes/registry wiring and a direct exactness test.
- Kept the candidate unrouted and screened it directly against four retained R6
  chunks on all seven actual Q4 role weights.
- Removed the HIP specialization/export, Python wrapper, registry key, and test
  after the leaf rejection; product/test paths are byte-identical to base
  `ff482c0fd`.
- Added compact artifact
  `benchmarks/results/2026-09-02-w7900-q4km-k3-q4-grouped-rows12-rejected.json`
  and cataloged the bounded rejection in `docs/KERNELS.md`.

## Validation

- RED: the direct R24 node failed import before the R12 wrapper existed.
- GREEN: fixture R24 grouped-R12 output is BF16-bit exact to four retained
  grouped-R6 chunks.
- Actual Qwen3.8-27B-Q4_K_M role×R24 screen, 30 counterbalanced HIP-event and
  synchronized-wall pairs per role: all 7 exact, but only FFN-gate/full-Q win
  weakly (1.025x/1.017x event). Recurrent-gate is 0.915x, full-K 0.631x,
  full-output 0.911x, recurrent-QKV 0.993x, and FFN-down 0.956x. Full-K has
  0/30 event and wall wins.
- Post-removal byte comparison against `ff482c0fd` passes for all touched
  product/test files.
- Artifact JSON parse and Worklog2 validation pass before commit.

## Next

- Keep grouped R6 as the physical Q4 owner. Do not revisit larger per-wave
  grouped row tiles without a materially different accumulator/dataflow design.
