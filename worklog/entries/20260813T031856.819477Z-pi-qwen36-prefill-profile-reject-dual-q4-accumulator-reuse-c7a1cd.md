# Reject dual Q4 accumulator reuse

## Summary

Rejected a fundamentally different operation-complete Q4 FFN dataflow that computes gate to the exact BF16 boundary in LDS, then reuses one accumulator bank for up and SiLU. Static phase extraction reduced the kernel from retained VGPR254 to VGPR248 with zero spills, but did not cross an occupancy boundary; the required second activation traversal dominated and regressed every shape.

## Changes

- Prototyped dynamic and statically unrolled whole-matrix phases using one K256 weight slab, one accumulator bank, a 16-KiB rounded-gate tile, one launch, sole-T16 weights, and no global intermediate.
- Preserved each matrix's K16 WMMA sequence, FP32 accumulation association, BF16 projection boundary, and final SiLU arithmetic.
- Restored `gguf_k_t16_selected_prefill.hip` byte-for-byte to the retained `6d8da0157` source after rejection; no production code change ships.

## Validation

- Both forms were BF16-bit exact against the retained operation-complete kernel on actual immutable Qwen3.6-27B `blk.0.ffn_gate.weight` and `blk.0.ffn_up.weight` tensors.
- Dynamic phase loop: VGPR256, 18 VGPR spills, 76 bytes/thread private segment; XTX speedup versus retained was 0.672x/0.671x/0.667x at M512/M1024/M4096, 0/45 paired wins.
- Statically unrolled phases: VGPR248, zero spills/private segment; XTX speedup was 0.682x/0.690x/0.715x at M512/M1024/M4096, 0/45 paired wins.
- Source hash after restore: `858fc6b026a5ced042a84c4bd7a95228356075f85a289fbb4265f05e0d84aab5`, identical to the retained snapshot.

## Next
