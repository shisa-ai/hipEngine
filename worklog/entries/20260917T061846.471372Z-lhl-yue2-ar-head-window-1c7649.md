# YuE2 AR head scoped to the phase window: 4.82x on the semantic head

## Summary

The AR runner projected all 184 704 vocabulary rows for a head that can only emit
semantic codec tokens. `distribution` masks every row outside a phase's domain and the
phase's end token to `-inf` before any other arithmetic
(`tests/test_unit_yue2_protocol.py::test_distribution_masks_phase_domain_and_min_length`
is the existing statement of that), so a phase can only ever select inside a window:
**32 769 rows for `semantic`** (the 32 768 codec tokens plus `MUSIC_END`, 17.7% of the
vocabulary) and 151 849 for `abc`. The head now projects just that slice and returns a
full-vocabulary row that is `-inf` outside it, which is what the sampler would have
masked anyway.

The semantic head goes **3.830 ms -> 0.795 ms (4.82x)** and the production session loop
goes **60.14 -> 56.23 ms per token (1.07x, 3.91 ms per token saved)** with identical
tokens and identical RNG state. Over a 512-token semantic phase that is about 2.0 s of
a roughly 131 s song.

The validation also found a latent sampler bug: the CFG combination turns `-inf - -inf`
into NaN, and `NaN < threshold` is False, so a NaN score silently disabled the top-k
stage. Both the CFG combination and `distribution` now keep non-finite rows non-finite.

## Changes

- `hipengine/generation/yue2.py`:
  - `phase_window(phase)` returns the smallest contiguous range holding
    `phase_domain(phase)` and `phase_end_token(phase)`.
  - `distribution` folds non-finite scores to `-inf` before masking. This is the identity
    on every row the full projection produces and prevents a NaN threshold from silently
    disabling top-k. `_distribution_legacy_off` gets the same fold.
  - `combine_cfg` takes the difference only where both operands are finite, so a masked
    row stays masked instead of becoming NaN. On finite rows the arithmetic is unchanged
    (a test asserts the BF16 value against the reference expression).
- `hipengine/runtime/yue2_ar.py`: `logits(branch, domain=...)` projects the window with
  the same `dense_gemv_bf16_f32_out_rowtile2` kernel, offsetting the weight pointer by
  `low * hidden * 2` and passing the window width as `out_features`, then scatters the
  window into a row that is `-inf` outside. `_reset_logits_cache` clears both the
  full-vocabulary pair and the window fill; every hidden-row writer calls it.
- `hipengine/runtime/yue2_session.py`: the generation loop passes
  `domain=phase_window(phase)`.
- `scripts/yue2_ar_head_window_validation.py` (new): the four-part validation below.
- `tests/test_unit_yue2_protocol.py`: `phase_window` covers exactly the selectable rows
  (checked against `distribution`'s own output), rejects unknown phases, and `combine_cfg`
  keeps masked rows masked while matching the reference expression on finite rows.
- `tests/test_unit_yue2_ar_paired_head.py`: a stub-kernel test that `domain` narrows
  `out_features`, offsets the weight pointer, `-inf`s the rest, shares one fill across
  branches, and refills on a hidden-row move or a domain change.
- `docs/KERNELS.md` (catalog row), `docs/REFACTOR.md` (why the unwindowed route stays),
  `benchmarks/README.md`, `benchmarks/CHANGELOG.md`.

vocabulary, so that phase gains only 1.05x; scoping pays because the semantic phase is
the long one.

## Found on the way: NaN disables the sampler's top-k

The windowed row is `-inf` outside its window, and `combine_cfg` computed
`neg + scale * (pos - neg)`, so `-inf - -inf` produced NaN. `distribution` masks
non-finite rows, but `np.partition`/`scores < threshold` with a NaN threshold removes
nothing (`NaN < t` is False), so the top-k stage silently became a no-op and the
windowed and full rows produced different score rows. The first validation run caught
exactly that: part B failed for `abc` with different masks and a different top-1, and
part D's tokens diverged.

Fixed in two places, both of them the identity on rows the full projection produces:
`distribution` folds non-finite values to `-inf` before masking, and `combine_cfg` keeps
non-finite rows non-finite. The full route is provably unaffected and the replay gate
confirms it byte-for-byte.

## Next

- The sampler still runs its mask, penalty, top-k, top-p and softmax over 184 704
  elements per branch per step, which is the larger remaining host cost (about 5-7 ms per
  token). A window-relative `distribution` would shrink that by the same 5.6x; the
  ordering argument is the same one this unit validated (the masked rows sort last, carry
  zero probability and are removed), but it is a bigger change to reference-mirroring
  code and deserves its own unit and validation.
- The `abc` phase gains almost nothing from scoping; its head cost is not the lever.
- q/k/v/o and gate/up/down still run per branch, and the AR remains 1.78x behind the
  reference on matched work.
