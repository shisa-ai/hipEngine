# DE-2 priced: the shared expert is a Q8_0 block costing 1.36-2.54 ms/step, and the row's 6.19 ms/token exceeds its own container

## Summary

Resolved the DE-2 row's named blocker - a name-to-tensor mapping - from the shipped GGUF header, then
priced the block. **The shared expert is uniformly Q8_0 (not Q4_K), moves 251.17 MB/step, and costs
between 1.36 and 2.54 ms/step. Its hard ceiling is 4.69% of the decode kernel sum, and the row's
historical 6.19 ms/token is larger than the entire measured non-routed block.**

## Changes

- **New `scripts/qwen4exp_de2_shared_expert_pricing.py`** - read-only GGUF header parse; no GPU, no
  model load.
- **New artifact** `benchmarks/results/2026-09-29-qwen4exp-de2-shared-expert-pricing/`
  (`README.md`, `pricing.json`).
- **Updated** the DE-2 row in `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md`.
- **No kernel built and no default changed.**

## The mapping

192 tensors = 48 layers x 4. Types: **144 Q8_0 + 48 F32**; no Q4_K or Q5_1 shared tensor exists.

| tensor | shape | type | bytes/layer |
|---|---|---:|---:|
| `ffn_gate_shexp.weight` | [2560, 640] | **Q8_0** | 1,740,800 |
| `ffn_up_shexp.weight` | [2560, 640] | **Q8_0** | 1,740,800 |
| `ffn_down_shexp.weight` | [640, 2560] | **Q8_0** | 1,740,800 |
| `ffn_gate_inp_shexp.weight` | [2560] | F32 | 10,240 |

**Per-step traffic 251,166,720 B = 251.17 MB**, independently reproducing the 250.68 MB the family
traffic model carried - now from exact payload sizes rather than a bits-per-weight estimate.

**This explains the row's gufo citation.** The action is a fused gate+up Q8_0 GEMV with one activation
quantization and two weight pointers (`qfn_mmq_q8_0_dense_vec_preq`), because the shared expert is
the Q8_0 block. It is a **different quantization class** from the routed experts (Q4_K gate+up, Q5_1
down), which is why the row warns against substituting the competitor's single-plane quantizer.

## The pricing

```
moe family                 24.5504 ms/step
- routed gate+up            14.0126
- routed down                5.4440
= non-routed remainder       5.0938 ms/step   (shared + router + select + combine + misc)
```

That remainder moves 251.17 + 251.66 = 502.82 MB, so it runs at **>= 98.71 GB/s**. Bracketing:

| basis | rate | shared expert | % of 54.218 ms |
|---|---:|---:|---:|
| in-block comparator (router dense GEMV) | 184.66 GB/s | **1.360 ms/step** | 2.51% |
| remainder's implied rate | 98.71 GB/s | **2.544 ms/step** | 4.69% |

## The row's 6.19 ms/token cannot be right

It exceeds the measured cost of the **entire** non-routed block - shared expert, router, top-k select,
combine, and every other non-routed kernel together are 5.0938 ms/step. A component cannot exceed its
container.

## Consequence for the row's action

The fused-gate+up screen stays valid and is now priced:

- **Hard ceiling: 2.544 ms/step = 4.69%** of the decode kernel sum, for a *perfect* shared expert.
- **Realistic: ~0.8-1.6%.** Fusing gate+up targets 167.44 MB of 251.17 MB; a 2x gain there is
  ~0.45-0.85 ms/step.
- **Ranking: DE-1 is roughly 4x DE-2's entire ceiling.** DE-1's routed gate+up owner is 14.013
  ms/step with 10.091 ms/step of headroom, against DE-2's 2.544 ms/step ceiling. This supports the
  ledger's ordering of routed experts above the shared expert.

## Validation

- **The mapping is exact, not estimated**: payload sizes come from parsing all 4 GGUF shards' tensor
  headers (1,224 tensors) and multiplying by the type's block layout (Q8_0 = 34 B / 32 w).
- **It independently reproduces a figure derived by a different method.** The family traffic model's
  250.68 MB was a separate estimate; this parse gives 251.17 MB. Agreement to 0.2% validates both.
- **The bracket uses two measured anchors from the same decode step** (the 184.66 GB/s router dense
  GEMV comparator and the 24.5504 ms moe family), not assumed rates.
- **The container argument is arithmetic**, and it is falsifiable: if the shared expert really cost
  6.19 ms/step the moe family would exceed its measured 24.5504 ms/step.
- **Read-only and side-effect-free**: no GPU, no model load, no default touched.
- **The capture's limitation is stated rather than worked around**: all 5,313 decode-rep kernels carry
  renamed role names and no `shared_*` marker exists, so the within-remainder split cannot be
  measured from it. The bracket is presented as a bound, not an attribution.
- `python3 scripts/worklog.py check`: valid.

## Limits

- **The cost split within the remainder is NOT established.** [1.36, 2.54] ms/step is a bound. The
  true value needs a scoped marker or a name-to-kernel join this capture cannot supply.
- **The comparator rate** (184.66 GB/s) is itself derived from a profiled capture whose per-kernel
  times are diagnostic rather than a serving-path measurement.
- **One model, one quant, one host** (gfx1151).
- **No speedup claimed, no kernel built.**

## Next

- DE-2's action is priced and can be deferred: its ceiling is 4.69% and realistic payoff ~1%, against
  DE-1's measured 10.091 ms/step (18.6%) of headroom. Ranking says finish DE-1 first.
- If DE-2 is pursued, the cheapest correct next step is a **scoped marker** around the shared-expert
