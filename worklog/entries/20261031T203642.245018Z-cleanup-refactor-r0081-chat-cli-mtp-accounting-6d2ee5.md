# Report MTP speculation from committed output, not cycle count

## Summary

R0081 chat-CLI consumer repair. `/bench`'s "mtp on" note decided whether
speculation ran from `diagnostics.specdec2_mtp2.cycles`, but a committed
depth-zero cycle increments `cycles` and attributes no speculative token
(`speculative/accounting.py:record_speculative_outputs`), so an MTP-on route
that only ever committed autoregressive cycles produced no note — the exact
state the note exists to explain. The decision now reads the common
per-request `output_accounting.mtp_output_tokens` first, falls back to the
provider block's own counter, and only then to the legacy cycle count. A
reported zero is noted; an unreported attribution stays silent.

The legacy `diagnostics.specdec2_mtp2` reader is preserved as the fallback.

## Changes

- `hipengine/chat_cli.py`
  - `_mtp_accounting`: reads `hipengine.speculative_mtp.output_accounting`
    (published by both blocking and streaming responses).
  - `_mtp_speculated`: `True`/`False`/`None` from committed speculative output
    tokens — common accounting, then the provider block, then its legacy
    `cycles`. `None` (no attribution at all) is missing telemetry, never a
    declined request.
  - `_Bench.add_run` notes a reported-empty speculative output; the note now
    reads "no speculative token was committed" instead of "no speculative cycle
    ran", because `cycles` never meant the latter.
  - `_mtp_block` is documented as the compatibility reader; `_mtp_cycles` and
    `_mtp_decline_reason` keep their behavior.
- `tests/test_unit_chat_cli.py`
  - The bench fake now publishes the block's `mtp_output_tokens` and the common
    `speculative_mtp.output_accounting` in the done chunk's choice metadata,
    matching `server/stream_events.py:chat_done`.
  - New: AR-only committed cycles are noted; an engaged route is not; the common
    accounting wins over a disagreeing provider block in both directions; the
    same decision holds for the blocking placement (`hipengine.speculative_mtp`
    beside the response) and the streaming placement (in the done choice);
    absence of attribution and a counter-less legacy block keep their fallbacks.
