# Screen Qwen3.8 gfx1151 multistep decode graph replay

## Summary

Screen the existing device-feedback decode graph at 2/4/8 steps per replay.
The first clean post-split-weight p512 trace assigns **10.294538 s** to kernels
inside **10.722353 s** measured decode wall (96.01% reconciliation). A bounded
multi-step graph can amortize up to 3.99% of per-token launch/synchronize/host
residual without changing model math, weights, state/KV updates, or sampling.

## Changes

- Freeze one tuning dimension: current `steps_per_replay=1` versus existing
  device-feedback graph widths 2, 4, and 8. No production code changes before a
  complete same-checkout screen.
- Use token 9707, p512/d128, BF16 KV, one warmup and three measured runs for each
  width. Require exact final IDs, finite logits, unchanged tracked peaks, and
  zero teardown before any natural-suite integration.
- Treat the first two post-retain traces as invalid because compiler-version
  probing inside `rocprofv3` generated fresh JIT identities. The accepted trace
  uses a fixed `HIPENGINE_COMPILER_VERSION_FILE`, an outside-profiler prebuild,
  and has no compiler/linker command in profiler stderr.

## Validation

- Accepted trace:
  `/tmp/qwen38-task22-post-split-weight-rerank-verified/rocprof/gfx1151/1334689_kernel_trace.csv`.
  It contains 119,552 positive-duration dispatches and the expected split-weight
  symbol at 3,931.695 ms / 8,192 calls / 120 VGPR / 512 B LDS / zero scratch.
- Width 1/2/4/8 reduces graph launches **128/64/32/16** while preserving all
  fixed-token IDs, finite logits, the **16.753218-GiB** tracked peak, effective
  HIP graphs, zero native fallbacks, and exact teardown.
- Complete p512 AR is **12.036125 / 12.033899 / 12.040009 / 12.035493 tok/s**.
  Relative to width1, width2/4/8 changes **-0.018% / +0.032% / -0.005%**. The
  best width is two orders of magnitude below the 1% continuation gate, so no
  1K/4K or natural run is warranted.

## Decision

- **Reject** multistep graph replay as a performance route and retain width1.
  The apparent 3.99% profile residual is profiler/accounting wall rather than
  launch/synchronize overhead removable by widening the existing graph.
- Durable evidence:
  `benchmarks/results/2026-08-15-gfx1151-qwen38-27b-multistep-graph-replay-rejected.json`.

## Next

- Return to device-critical operation-complete dataflow. Do not revisit graph
  replay width without a new runtime/driver or measured host-wall premise.
