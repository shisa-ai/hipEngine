# XTX capacity: capacity-honest packed-workspace lease right-sizing (-2.330 GiB measured peak)

## Summary

Packet 1 item 6 required tracing the eight-slot workspace minimum before changing
it; this unit traced it, proved no legitimate >1-slot request exists at C1, and
right-sized both sizing sites. Measured on the XTX (RX 7900 XTX, PCI
0000:10:00.0, Qwen3.8-27B Q4_K_M, BF16 KV, 3072-token context, N=1, MTP off,
prefix off, one cold in-process server): load sysfs 19.742 -> 18.429 GiB
(-1.313), whole-request sampled peak sysfs 23.328 -> 20.998 GiB (-2.330, -10.0%),
tracked allocator peak 19.162 -> 17.849 GiB (-1.313), workspace lease 96 -> 12
pages, pool backing 108 -> 24 pages. The request-stage transient also fell
(3.586 -> 2.569 GiB) because packed-state private buffers scale with the slot
count. The INT8 fp32 per-token/head route serves identically under the smaller
lease (load 18.300, peak 20.841 GiB, 2677-token prompt, output verified).

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py` `_packed_verify_union_geometry`:
  the slot-capacity ceiling now follows the real serving cap
  `max(1, max_batch_size)` instead of an unconditional
  `_PACKED_VERIFY_DEFAULT_SLOT_CAPACITY` (8) floor; absent or invalid caps keep
  the historical 8-slot fallback.
- `hipengine/generation/qwen35_gguf.py` global-pool workspace lease: lease
  `capacity_slots * max(ceil(ctx/256), 4)` pages instead of
  `max(8, capacity) * ...`; the lease and union geometry shrink together so the
  pool-leased backing still covers every servable geometry (fail-closed raise in
  `_GGUFPackedTargetState.allocate` if a lease ever under-covers).
- Tracing evidence for the C1 safety argument: MTP serving widths, packed group
  layouts, and prefill widths are all bounded by `max_active_requests`; the only
  >1-slot path at C1 is the B3 C2-shadow resource ABI
  (`acquire_c1_shadow_lifecycle`), which has zero callers today and would grow
  the packed state through the existing never-shrink union path.
- `hipengine/core/memory.py`: additive `live_allocation_histogram(min_bytes=)`
  accessor over the tracked allocator's live set (count/total/largest/top
  sizes), used by the new attribution probe to catch transient peak composition.
- `scripts/qwen38_xtx_allocation_ledger.py`: Packet 2 attribution probe.
  Device-free planned weight census (851 logical tensors, 0 aliases,
  15.995 GiB planned resident vs 15.932 GiB GGUF file; 4 NextN tensors /
  53.2 MiB present in the file but not planned for residency at MTP off) plus
  in-process live snapshots (`kv_pool_memory_snapshot`, tracked allocator,
  large-allocation histograms sampled concurrently through the request, sysfs
  VramSampler). Diagnostic harness; no route or throughput claim.
- Page-independent per-layer residents identified for future attribution: 32
  identical ~69.7 MiB buffers (2.179 GiB total) present identically before and
  after the right-size, plus 0.580 GiB sysfs-over-tracked external overhead.
