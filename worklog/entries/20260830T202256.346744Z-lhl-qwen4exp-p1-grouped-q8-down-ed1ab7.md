# Q8_0 grouped down microbench: NEGATIVE vs strict selected gemv

## Summary

The P1 device-driven grouped Q8_0 down owner, though BF16-exact (RED passes),
does **not** beat the current layer-2 down default (strict per-expert selected
gemv via `selected_projection`) at any tested shape. On layer-2 frozen-MoE-map
shape (ffn=640 in -> hidden=2560 out, 512 experts) the grouped owner is
~12x (sparse) to ~3x (deep) **slower** than the strict selected gemv, and also
slower than the legacy per-expert WMMA loop. It is a correctness-ready but
perf-negative kernel; it must NOT be promoted to default.

## Changes

- Added `scripts/gguf_q8_0_grouped_down_microbench.py` comparing the
  device-driven grouped owner vs the legacy per-expert WMMA loop vs the strict
  per-expert selected gemv on the layer-2 shape.
- Recorded the negative microbench result (grouped owner slower than strict
  selected gemv).
- Updated `docs/KERNELS.md` (row) and `docs/REFACTOR.md` to mark the grouped
  down owner perf-negative / not-promoted until a re-audited tile/grid beats
  strict.

## Validation

- `python3 scripts/gguf_q8_0_grouped_down_microbench.py --repeats 15` on local
  W7900/gfx1100 (wall-clock medians, device-synchronized):

  ```
  profile   rows  legacy_ms  grouped_ms  strict_ms g/legacy g/strict
  sparse      16      0.233       4.172      0.340     0.06     0.08
  dense       64      2.780       6.315      1.264     0.44     0.20
  deep       256     10.958      14.464      4.867     0.76     0.34
  ```

  `legacy` = per-expert `gguf_q8_0_wmma_prefill_bf16_bf16_out` loop (fp16
  approx). `strict` = `gguf_q8_0_selected_gemv_bf16_bf16_out` on sorted
  per-row expert ids (exact, the current layer-2 down default). `grouped` =
  the new device-driven owner. RED test `test_qwen4_exp_q8_0_grouped_down.py`
  still 4/4 pass (correctness intact; perf is the blocker).

## Root cause

The grouped kernel launches `dim3(out_features, num_experts)` =
2560 x 512 = **1.31M blocks** with `OUT_BATCH=1` and a serial `for expert`
loop per block, plus an outer serial output loop. There is no weight reuse
across rows and no output tile; nearly all blocks exit immediately for empty
experts. The strict selected gemv tiles rows/outputs and reuses weights, so it
is far faster despite the same exact arithmetic.

## Decision

- Keep the device-driven grouped owner **registered and RED-tested** (exact,
  opt-in behind `HIPENGINE_QWEN4_EXP_Q8_0_GROUPED=1`) as a correctness
  artifact and future tuning baseline. Do **not** promote it to default.
- Layer 2's down path stays on the strict selected gemv (the measured-fast
  `strict_ms` row). The "route layer 2 through grouped prefill" P1 item must
  gate on a grouped-down owner that is actually faster than strict, or on the
  Q5_K gate/up WMMA body alone (gate/up is the dominant layer-2 cost), not on
  this down owner.
- Before any future grouped-down tuning, re-audit grid/tile config (OUT_BATCH
  and row/weight reuse) against `selected_gemv`; do not tweak blindly.

## Next

- Route layer 2 on the Q5_K gate/up WMMA body microbench (the dominant
  397.95 ms term), independent of the down owner.
- Only re-tune the grouped down owner if a re-audited tile/grid (weight reuse,
  output tiling, empty-expert skip) can beat strict.
