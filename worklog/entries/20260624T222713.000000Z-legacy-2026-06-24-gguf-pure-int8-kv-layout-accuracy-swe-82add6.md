## Changes


- Extended `scripts/qwen35_gguf_q8_format_sweep.py` to accept arbitrary `block<N>_{fp16,fp32}` all-K/V QDQ formats, so we can test fine-grained INT8 payload layouts without adding a new HIP runtime path first.
- Actual W7900/GPU0 no-mirror pure per-token/head FP32 runtime checks remain rejected even at short prompts with `max_sequence_length=131202` and `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1`: `128/1` `KL mean=0.0823991`, top-1 `0.5`; `512/1` `KL mean=0.0569803`, top-1 `1.0`; `4K/1` `KL mean=0.153975`, top-1 `0.5`. Per-token/head FP16 at `512/1` also fails (`KL mean=0.121436`, top-1 `1.0`), and real HIP block16 FP32 at `512/1` fails harder (`KL mean=0.664146`, top-1 `0.5`).
- Host QDQ all-pure/coarse sweep at `4K/1` confirmed no useful coarse all-Q8 layout passes: per-token/head FP16/FP32, llama-style `q8_0` block32 FP16/FP32, block16/block64, and one-sided variants all fail. A fine-block follow-up (`block16`, `block8`, `block4`, `block2`, `block1`) shows the cutoff: block2 and coarser still fail, while `block1_fp16` and `block1_fp32` pass exactly (`KL=0`, top-1 `1.0`). This proves pure INT8 payload can be exact enough if memory is ignored, but only with per-scalar scale metadata (`block1_fp16` ~150% of BF16 KV; `block1_fp32` ~250%).
- External llama.cpp ROCm `q8_0` K+V comparison on the same GGUF (`/home/lhl/llama.cpp/llama.cpp-hip` commit `e37abd6b5`, `llama-perplexity`, `ctx=4K`, `chunks=1`) completes but fails a hipEngine-like quality bar: mean KLD `1.424879`, max KLD `23.208828`, same-top-p `0.84563`. PARO remains the passing control on the packed PARO model: per-token/head INT8 KV `4K/1` passes with `mean KL=2.09e-7`, top-1 `1.0`.
- Decision: no useful pure GGUF INT8 KV layout is promoted. If we ignore memory, per-scalar scale layouts can make an INT8 payload valid, but any practical coarse layout still needs BF16 prefixing, different calibration/acceptance, or a non-KV residency reduction. Added compact artifact `benchmarks/results/2026-06-24-w7900-gguf-q4km-pure-int8kv-layout-sweep.json` and updated `docs/TUNING-gguf.md`, `benchmarks/README.md`, and `benchmarks/CHANGELOG.md`.
