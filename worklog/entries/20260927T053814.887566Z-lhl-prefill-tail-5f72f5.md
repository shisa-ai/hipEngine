# Bound tiny prefill tails to allocated scratch width

## Summary

A 4,097-token DMS prefill merged its one-row tail into a 4,096-row
chunk, exceeding token/hidden scratch and failing with HIP invalid argument.
Borrow rows from the previous chunk when possible instead of increasing its
width. This fixes the observed production request without changing kernels.

## Changes

- Rebalance short recurrent tails into minimum-width final chunks.
- Capture DMS cache boundaries at those actual partitions, including exact
  prefix reuse with no remaining chunks.
- Add CPU coverage below, at, and above the allocation boundary; update the
  existing live-tier partition assertion.
