# Iteration 18: dense pack8-GEMV decode rewrite rejected at the production gate (association noise)

## Summary

The `HIPENGINE_GGUF_GEMV_DECODE` switch — the last live candidate in the
Gemma 4 decode bottleneck — is **rejected**: it is not a bit-exact
drop-in replacement for the legacy pack8 kernel, its noise fails all five
production limits, and it shows no measurable speed win.

This also closes the mystery opened in iterations 16-17: the
"compact candidate" gate failure was **entirely this dense switch**, and
the compact chain was never the cause.

## Root cause (kernel level)

Both kernels are individually accurate — each is within one bf16 ULP of
the f32 CPU oracle at all seven real dense shapes — but they associate
the reduction differently **by design**:

| | Legacy `gguf_k_pack8_prefill_out_kernel` | Decode kernel |
| --- | --- | --- |
| per-thread k walk | `k += blockDim.x` (unit stride) | `vec_stride = blockDim.x * 8` (eight *consecutive* k) |
| per-term math | `acc += xv * w` | `fmaf(xv, d * qs, acc)` with the per-block scale `d` hoisted |

Different per-thread k-sets ⇒ different f32 rounding ⇒ a small fraction
of bf16 outputs land one ULP apart. Measured on real weights:
1-2 differing elements per 8192 at `blk.5.attn_q.weight`
(in=2816, out=8192); zero on the other six real dense tensors probed in
one pass. The eight-consecutive/hoisted-scale walk *is* the
optimization, so bit-exactness and the speed trick are mutually
exclusive at this design point — the candidate cannot be repaired
without abandoning its reason to exist.

## Attribution (why this is the whole candidate)

- A resolve-level probe diffing every dispatched kernel key between env
  off and env on: **exactly one key changes**, 205 launches
  (`linear|gguf_q8_0|pack8_gemv_bf16_bf16_out` →
  `pack8_gemv_decode_bf16_bf16_out`). No prefill, attention, norm, MoE or
  lm-head dispatch changes (the lm-head asks for f32 output and is not
  rewritten).
- Forcing the rewrite with the env **off** reproduces the env-on logits
  **bit-identically** (`max|diff| = 0.0` over 65 teacher-forced rows):
  one substitution, no second mechanism, no hidden fallback.
- With the env off the current tree is **bit-identical to the frozen
  baseline** (KL 0.0), confirming the iteration-16 commits did not touch
  the default path.

## Gate verdict (1023 rows, frozen baseline)

| Metric | Candidate | Limit |
| --- | --- | --- |
| kl_mean | 0.03106 | 1e-3 |
| kl_p95 | 0.1596 | 5e-3 |
| kl_p99 | 0.7734 | 2e-2 |
| kl_max | 2.4471 | 5e-2 |
| top1_rate | 0.96872 | 0.99 |

All five limits fail; 32/1023 top-1 flips, first at row 11 (logits differ
at the bit level from row 0). Control: `COMPACT_MOE_C1=1` alone gives
KL 0.0 / top1 1.0.

## Performance

No win to trade against the correctness failure: 16p/4o off
46.60 / 48.24 / 47.02 vs on 46.97 / 44.68 / 48.96 tok/s (noise);
1024p/128o combined 23.2045 vs default 23.1326 (+0.31%, inside noise).
