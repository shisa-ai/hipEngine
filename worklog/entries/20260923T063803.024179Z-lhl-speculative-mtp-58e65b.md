# Exercise the thinking cap at both temperatures in the forced-token gate

## Summary

The forced-token gate exercised the thinking budget's hard cap at temperature
0.7 only. The live product-surface probe covered the greedy case, but the durable
artifact did not, so the cap's strongest check -- two arms publishing identical
ids token for token, which compares the close position, the close sequence, and
the answer that follows rather than only the index the close starts at -- existed
only in a session log. A second case runs the same cap at temperature 0.0.

The gate passed with 8 cases on both arms. The MTP and AR arms published all 24
ids identically for the greedy thinking case, with the close at index 8 reached
through 9 cycles; the sampled thinking case kept its 12-token shared prefix and
a draw-dependent continuation, as before.

## Changes

- `scripts/mtp_forced_token_gate.py`: a `thinking_hard_close_greedy` case with
  the sampled case's prompt, close text, and cap at `temperature=0.0`, and the
  close-at-cap acceptance keyed on the case-name prefix so both thinking cases
  share it. `_check` runs per arm, so the position is asserted on both routes.
- `tests/test_unit_mtp_forced_token_gate.py`: the fake's field and default-prefix
  helpers key on the same prefix, plus a test that the two thinking cases differ
  only in temperature.
- `benchmarks/results/2026-09-23-gfx1151-qwen38-bf16-mtp-forced-tokens.json`: the
  fresh 8-case report, with `summary` derived from it (cycles, MTP output tokens,
  and AR output tokens per case), the coverage text, the thinking acceptance, and
  two observations. The first version of this edit hand-wrote the new case's
  cycle count; the report said 9, not the 13 written, which is why every number
  in the artifact is now read out of the report rather than transcribed.
