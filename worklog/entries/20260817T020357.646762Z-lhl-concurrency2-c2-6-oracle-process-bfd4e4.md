# Move production oracles to isolated GPU process

## Summary

Separated diagnostic oracle GPU ownership from measured production ownership at the process boundary. The complete campaign generated all 13 oracle keys successfully but repeatedly page-faulted when measured serving resumed in the same HIP process, even after scratch sessions and model loads were separated in-process.

## Changes

- Added `scripts/gguf_reference_oracle_worker.py`, which owns the oracle model/runtime, emits prompt/token digests and exact generated IDs, then exits directly so the OS retires all HIP state.
- Production load launches the worker before initializing its sole measured model owner, validates child completion, reconstructs immutable prompt/token rows, and records worker provenance.
- The measured owner independently rebuilds the prompt manifest and requires every token digest to equal the isolated oracle manifest before serving.
- Temporary specs/results stay outside Git; model/backend/compiler/cache requirements are explicit child arguments.

## Validation

- Production-load host tests — 20 passed; only two third-party Uvicorn/websockets deprecation warnings.
- Worker/parent Ruff, compileall, JSON roundtrip unit, and diff checks — passed.
- Three prior complete-campaign attempts generated all required oracle IDs and then faulted before tuning on same-process ownership. They remain rejected and motivate this process boundary.
