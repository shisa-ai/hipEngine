# Tune Gemma Q5 staged prefill tile

## Summary

The first measured optimization loop candidate changes the shipping Q5.1
selected grouped staged prefill kernel from a four-column output tile to an
eight-column output tile. The existing dynamic shared-memory allocation already
covered the eight-column tile. The change preserves the generic kernel ABI and
strict fallback.

A cached ROCm trace of the public 32K campaign identified
`q5_1_selected_grouped_prefill_staged_bf16_bf16_kernel` as the largest family,
with about 34.3 seconds of aggregate device duration across 1,856 launches in
that instrumented trace.

## Changes

- Changed `qwen4_exp_q5_1.hip` launch instantiation from `<4, 4, 256>` to
  `<4, 8, 256>`.
- No prompt-specific logic, model allowlist, diagnostic route, or production
  default change was added.

## Validation

- Baseline 64K production decode: 23.6281 tok/s.
- Candidate 64K production decode: 23.6652 tok/s (+0.0371 tok/s, +0.2% in this
  low-variance three-sample measurement).
- All three 64K samples completed with finite output and public path parity.
- Focused Gemma decode/staged/sliding bundle: 162 passed in 2.33 s.
- Public 512-token smoke: passed with path parity on AMD Radeon Pro W7900.
