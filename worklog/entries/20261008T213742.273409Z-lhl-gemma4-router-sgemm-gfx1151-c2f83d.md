# Router SGEMM tier for full prefill blocks on gfx1151: measured win, gate fail on one flip row

## Summary

The mid-band census (2026-10-07) put `qwen35_router_logits_token_tile` at
8-10 percent of the prefill step. On gfx1151 every prefill router call --
including full 1024-row blocks -- runs the capability-declared
`token_tile_8` schedule, because `hipengine/kernels/hip_gfx1151/__init__.py`
declares `LAGUNA_ROUTER_LOGITS_MODE = "token_tile_8"` and the gemma4 route
only reaches the rocBLAS SGEMM tier when the mode is `token_tile_4`. The SGEMM
tier is the measured, teacher-forced-gated production default for exactly
this shape on gfx1100 (commit f34cdccd5: kl_max 0.0141/0.0166, top-1 1.0).

**The perf win is real.** Interleaved leaf A/B at the in-situ geometry
(1024 tokens, hidden 2816, 128 experts, f32 weights), including the tier's
bf16->f32 cast: token_tile_8 0.946 ms vs SGEMM route 0.564 ms per launch,
**1.68x**; max logit delta 1.9e-07 between the arms, 0/1024 top-1 flips on
the fixture (`/tmp/multiloop-beat-llamacpp/router_sgemm_leaf_ab.json`).

**The strict gate fails on one row.** Baselines were captured on the
unmodified tile8 route at 2048/1024 on gfx1151; the candidate moved the SGEMM
tier ahead of the declared tile mode for `tokens >= 1024`; the gate
(`scripts/gemma4_teacher_forced_gate.py gate --prompt 2048 --context 4096
--prefill 1024`) fails: **kl_max 8.5425 on row 602 alone** (bar 0.05),
kl_mean 0.00836 (bar 1e-3), while the next-worst row is 0.00139 and p99 is
7.99e-05; 0 top-1 flips, 1023 paired rows. One position's expert routing
flipped (a near-tie under the 1.9e-07 logit perturbation) and one downstream
decode row carries the divergence. The 5120/4096 gate never ran; the 2048
verdict decides.

Interpretation, recorded honestly: the same tier passed the same gate on
W7900 because that chain had no flip rows. This is the reordering-class
boundary the lead already owns: `HIPENGINE_GEMMA4_MOE_GATE_UP_MMQ` is parked
on "the lead ruling on whether an absolute kl_max applies to a reordering-class
change, which no agent command can clear", and the 2026-10-07 section 2.11
decision scoped a routing-identical KL envelope to the WMMA prefill
candidates. Whether that envelope extends to router-schedule reassociations
is the same question one level down, and it is not mine to answer. The route
change is **reverted**; the tree is back at the tile8 route.
