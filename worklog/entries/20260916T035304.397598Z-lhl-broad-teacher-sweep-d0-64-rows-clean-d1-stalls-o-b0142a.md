# Broad teacher sweep: d0 64 rows clean; d1 stalls on longer chat rows

## Summary

First pass of the lead-requested broadened AR teacher coverage
(`scripts/tp2_teacher_coverage_broad.py`, 64 chat-templated prompt rows
across code / general English / general Japanese / mixed, sequential arms
because three resident sessions cannot coexist in VRAM):

- tp1-d0 (W7900): 64/64 rows swept cleanly (~2.8 s/row after a 91 s build).
- tp1-d1 (RX 7900 XTX): session built, then the sweep **stalled mid-run** —
  GPU[1] at 0% with the process alive (host waiting in a readback), >35
  minutes without progress. Killed at the budget.

Key difference from every clean run of the same control: this sweep uses
**longer chat-templated rows** (roughly 30-60 tokens, versus the fixed
16-token diagnostic sequence). That points at a chunk/context-boundary
condition on device 1's harness teacher path — one of exactly the gates the
lead asked to run. It does NOT yet impugn the 16-row gate (both controls
ran clean there repeatedly), but it does mean the d1 control's clean
coverage does not extend to longer rows, and the row-length boundary on
device 1 must be mapped before any AR-qualification claim.
