# Reconcile offline DMS capture API with live device collector

## Summary

Move R0278 to an explicit offline capture ownership decision. The old description
incorrectly conflates a synchronous training sink with a live device serving
collector; preserve both until the offline API decision is made.

## Changes

- `scripts/qwen38_dms_capture.py` still passes `DMSCaptureWriter`; capture/label
  modules and live capture tests consume its checksummed manifest. Trained
  candidate and capture evidence already exist in `docs/reference/DMS.md`.
  The initial-training removal trigger has elapsed, but the API has real users.
- `_capture_dms_full_attention_prefill_chunk()` checks `capture_device_chunk`
  first and returns before synchronization/host copies for the serving
  `_ExternalDMSDevicePrefillCollector`. `prefill()` rejects an explicit sink
  when serving owns that collector. Deleting the shared hook would break the
  device path rather than just remove an offline tap.
- Bottom decision names model-plugin capture ownership or complete offline
  retirement; preserve device callbacks and migrate CLI/tests together with
  manifest/stage/layer/teacher-logit checks. No runtime, default or API change.
- Historical entry remains in `1c24bfdf1:docs/REFACTOR.md`; sweep SHA-256
  `b1778eb7a9083c7a227124a863c1317a05dd4a3cfa7501aed7e3bc8600ac8475`.
