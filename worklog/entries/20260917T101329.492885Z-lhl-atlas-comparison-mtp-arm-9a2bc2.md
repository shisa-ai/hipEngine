# Measure the hipEngine MTP arm of the Atlas comparison

## Summary

The Atlas comparison had no hipEngine MTP column because the original run's
requests failed four admission axes that no longer exist. With admission
physical (commit `25121713c`), the hipEngine side was rerun on the same host with
both arms: AR (`--speculative-mtp-serving off`) and MTP (`enabled` with
`--speculative-candidate-budget 3`). Atlas was not rerun and its rows are
unchanged.

Result at 16,384-token sessions, 128 outputs, greedy, matched same-session arms:

| Target prompt | AR tok/s | MTP K=3 tok/s | Ratio |
| ---: | ---: | ---: | ---: |
| ~512 (517) | 11.87 | 18.20 | 1.53x |
| ~1024 (945) | 11.72 | 17.20 | 1.47x |
| ~4096 (3530) | 10.96 | 10.94 | 1.00x |

The AR rates reproduce the original run within 0.01 tok/s at all three shapes,
which is what makes the MTP column comparable to the existing Atlas rows.

Two gates, neither visible in the response body, explain the shape dependence:

- **Candidate depth.** The server default `--speculative-candidate-budget` is 4.
  No retained Qwen3.8 row uses 4 (11 rows pin 3, 3 rows pin 2), so the default
  returns `candidate_budget_not_qualified` / `permanent_ar` and MTP never
  engages. The measured arm pins the qualified depth 3, which admits
  `qwen38-q4km-gfx1151-strict-bf16-cap4-realized-c1-b3` (automatic-eligible).
- **Prompt-priming window.** The MTP path refuses a prompt when
  `prompt_tokens + 1 >= min(1023, max_sequence_length)`, recording
  `target_context_k0` (`hipengine/generation/qwen35_gguf_mtp2.py`), so the
  3,530-token shape runs AR even though admission and routing both select
  `speculative_mtp`. The response reports `effective_route: default` with
  `decision_reason: backend_k0_fallback` and nothing else.

Draft accounting from a non-streaming probe of the same prompts: 0.442 accept
rate over 55 cycles at ~512 against 0.889 over 21 cycles at ~1024. The shorter
shape accepts less than half its drafts, which is why it gains less than the
longer one despite the same candidate depth.

Correctness observation: the first 600 generated characters are identical
between the AR and MTP arms at all three shapes, which is the comparison
document's own output-agreement basis and covers the whole 128-token generation
at these shapes.

## Next

- The default candidate-budget mismatch in `docs/REFACTOR.md` is the next
  decision: pin a qualified depth per model or warn at startup. Until it is
  resolved, every MTP recipe must pass `--speculative-candidate-budget 3`.
- The 1,022-token prompt-priming window is the other structural limit. Raising it
  would extend MTP to the shapes where the comparison's Atlas MTP rows still win
  (21.01 tok/s at ~3,507 prompt tokens against hipEngine's 10.94 AR rate), so it
  is the largest single MTP opportunity visible in this comparison. It needs a
  kernel/verifier qualification at longer contexts before it can be a claim.
