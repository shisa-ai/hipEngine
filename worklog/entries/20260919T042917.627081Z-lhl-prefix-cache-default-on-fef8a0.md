# Enable radix prefix caching by default and bound grown-pool allocations

## Summary

`prefix_cache` now defaults to `radix`. The measured win is -18.6% wall and
+22.9% output rate on the served multi-turn lanes; the accepted cost is that a
cache hit above 2,048 tokens of context can differ from a miss by one BF16 unit
in the last place and occasionally pick a different token. The public README
documents both. A third KV-pool growth defect is fixed (bind-time validation
against the wrong page bound); a fourth is open and is why the wide retained
working set stays opt-in.

## Changes

- `hipengine/kvcache/radix.py`: `PREFIX_CACHE_DEFAULT = "radix"`;
  `resolve_prefix_cache_mode(None)` resolves to it. `hipengine/kvcache/__init__`
  exports it and `hipengine/generation/engine_loop.py` uses it for the
  `EngineLoopConfig` default and the CLI fallback. `--prefix-cache off` and
  `HIPENGINE_PREFIX_CACHE=off` are the opt-out.
- `hipengine/kvcache/pool.py`: `DeviceKVPoolAllocation.pool_page_capacity`
  (default `None`, preserving the single-chunk contract).
  `hipengine/kvcache/device_global.py` fills it from the pool capacity.
- `hipengine/runtime/qwen35_gguf_runner.py`: new
  `_validate_bound_blocks_against_capacity`; `bind_device_kv_allocation` uses it
  when the allocation carries a pool capacity, and keeps the per-chunk check
  otherwise. A grown pool keeps page ids stable and reaches every page through
  its pointer tables, so the first chunk's page count was the wrong bound.
- `benchmarks/README.md` gains a `### Prefix caching` section inside the public
  TOPLINE block (the block is budget-checked, so two restating paragraphs
  elsewhere were tightened to fit) and the default note now reads on-by-default.
  `README.md` regenerated with `scripts/sync_benchmark_readme.py --write`.
- Tests: `test_bound_blocks_validate_against_pool_capacity_after_growth`. Two
  existing tests updated to the arena-pooled capture shape
  (`test_gguf_prefix_state_snapshot_outlives_source_session_and_restores_boundary`
  now asserts one arena allocation and that `close()` recycles rather than frees)
  and one to the new default (`test_radix_cache_hits_full_blocks...`).

## Validation

- Unit: `tests/ -k "prefix or kvcache or engine_loop or device_kv"` — the only
  failure is `test_unit_grammar_masks.py::test_server_schema_does_not_use_json_tool_prefix_for_xml_engine`,
  `ModuleNotFoundError: No module named 'llguidance'`, which reproduces at
  cb1960a33 in a clean worktree and is an unrelated missing optional dependency.
- `scripts/sync_benchmark_readme.py --check` passes.
- Growth behaviour, measured rather than assumed:
  * eviction precedes growth: `_ensure_free_pages` calls `_on_pressure`
    (`evict_prefix_cache_for_pressure`) and only grows when that cannot free
    enough; at `max_pages` it raises `MemoryError` instead of growing.
  * the pool never shrinks: `GlobalDeviceKVPool.shrink_idle` is a stub
    returning 0, so grown capacity is held for the pool's lifetime.
  * `kv_pool_high_water_pages` defaults to `None`, i.e. unbounded headroom, so
    growth is reachable under sustained pressure; setting it keeps the pool on
    the eviction path.
- The wide retained arm (`HIPENGINE_GGUF_PREFIX_RETAINED_SNAPSHOTS=16`) now
  clears six lanes before faulting with `HSA_STATUS_ERROR_MEMORY_FAULT` in
  `qwen35_write_paged_kv_mixed_value_prompt_position_tensor_kernel`, because
  `grow_storage` frees the old pointer tables while a session bound before the
  growth still holds them. Ledgered in `docs/REFACTOR.md`. The default retained
  budget does not grow the pool, and that configuration produced the retained
  A/B.

## Next

- Republish pointer-table pointers into every bound session on growth (or defer
  the free), which unblocks the wide retained working set.
- The >2048 bit-exactness bound is documented and accepted, not fixed. The
  measured fix is a canonical query chunking: no quality cost (split beats the
  single call against a serial reference on two of three prompts) but 1.12x
  prefill at 2048-token chunks, 1.22x at 1024 and 2.71x at 256, and reuse
  granularity follows the chunk size.
