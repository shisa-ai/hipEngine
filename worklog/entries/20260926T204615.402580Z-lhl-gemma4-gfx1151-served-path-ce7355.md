# Gemma 4 served path verified on gfx1151

## Summary

The gfx1151 bring-up unit (`8ff1b6673`) verified `hipengine.LLM.generate()` on
this host but stopped at that boundary; the served path was still unexercised.
`hipengine serve` now has a real request behind it on the Strix Halo box
(Radeon 8060S, gfx1151) with the `UD-Q4_K_XL` artifact, and the routed-expert
route that request took is recorded rather than inferred from timings.

No production code changed. The registration unit's gap analysis holds: the
gfx1151 kernel package already aliases the gfx11 bodies and the JIT compiles
them natively, so the only thing missing was the generator registration.

- None to production code. This entry records verification evidence for the
  acceptance criteria of the gfx1151 bring-up unit.

- `pytest tests/test_unit_gemma4_generate.py -q` on this host: 5 passed (the
  three that failed before `8ff1b6673` were the `hip_gfx1151` resolution
  failure).
- Served path, in-process so the route counter is readable for the served
