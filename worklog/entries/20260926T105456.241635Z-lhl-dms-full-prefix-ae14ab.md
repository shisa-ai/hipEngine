# DMS cold prefix and NextN cache implementation

## Summary

DMS partial-prefix and NextN reuse are enabled for BF16 and INT8 under the default radix cache, extending the earlier complete-prompt-only implementation.

Compact decode KV cannot reconstruct prompt attention after pruning. The cache therefore owns cold BF16 pre-compaction KV, raw predictor scores, and target trunk hidden rows on the host. Extended prompts restore prefix recurrence and pre-compaction KV, run only the suffix, then recompute full-prompt selection and compact decode storage. No dense device decode shadow is introduced.

## Changes

- Added host cold-prefill state and full-prompt score reselection, including shared-oracle layer-outer capture/restore.
- Reuse existing NextN checkpoint ownership for exact and extended prompts. AR-origin cache entries can prime NextN from cached target hidden rows without target replay.
- Added a byte-bounded, multi-entry LRU and block-boundary recurrent snapshots for branches diverging before the cached prompt ends. Selected 256-token boundaries are bounded by recurrent-state bytes; full-prompt boundaries remain reusable.
- NextN sinks split hidden chunks at the selected boundaries and capture provider state there. Telemetry distinguishes newly primed draft rows from restored rows.
- No RED-first for the initial public prototype: the existing restriction prevented exercising restoration; used cached/uncached public execution to develop the owned state contract, then added regression tests. New predictor stride, selection, LRU, and multiple-checkpoint tests cover that contract.
