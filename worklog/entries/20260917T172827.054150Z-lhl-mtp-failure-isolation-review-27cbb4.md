# Separate execution failure containment from MTP coverage repairs

## Summary

The architecture review supplied by the user targeted `9b6c258ba`. Review at
`371961c66` confirms its main concerns: escaped execution-tick exceptions close
the shared service, and a row-local speculative refusal can turn its whole
decode group into AR. CPU probes reproduced both. However, the concurrent prompt
activation crash is already repaired by `c48367c85`, and the service does have
local handling for submission, admission rejection and completion failures.
The missing boundary is in shared model execution, not every request operation.

Do not implement containment as a broad exception catch followed by continued
execution. Recovery must establish which state was touched, whether GPU work
completed, and whether the affected ownership group can be reclaimed or rebuilt
without invalidating survivors. An unrecoverable device/shared-owner failure
must still make the service unhealthy and trigger controlled restart.

## Changes

This is a review record only. Other workers had unstaged changes in runtime,
API, accounting, tests and the ShareGPT harness; none were edited or staged.

### Findings and corrections

- `engine_service.py::_drive` catches an exception escaping `poll`, calls
  `_fail_all`, closes the driver and marks the service closed. Submission/control
  handling, `rejected` events and completion handling already have smaller error
  boundaries. The proposed work is execution-tick containment with explicit
  recovery ownership, not adding a generic HTTP catch or swallowing BaseException.
- `qwen35_gguf_mtp2.py::claims_fit` requires all plan request IDs to be speculative
  IDs. `engine_loop.py` responds to a claims miss by replanning all rows with
  `claims_fit=False`. Desired counts remain positive for a row that exhausts
  context, so the existing desired-AR/speculative subset split does not isolate
  that row. Capability checks can also decline a whole group before any mixed
  plan exists; a repair limited to splitting the final plan is insufficient.
- The prompt activation guard now returns `prompt_activation_in_flight` and
  disables MTP on new rows instead of raising. It preserves existing streaming
  sinks. This repairs that outage trigger but remains a coverage compromise:
  activation ownership is still shared and refused rows do not regain their
  missing draft prompt state later in the request.
- Post-fix evidence in
  `benchmarks/results/2026-09-17-gfx1151-qwen38-sharegpt-mtp-routing.json` and
  `20260917T170041.952528Z-lhl-sharegpt-mtp-routing-pass-420a07.md` reports zero
  failures at c4/c8, with recorder MTP output shares 12.7%/15.6%. These are
  existing routing measurements, not new rates measured by this review. They
  invalidate the statement that c4 is still crashing but confirm low concurrent
  coverage. The workload uses a 128-output override and is not a complete
  natural-length/quality evaluation or a matched MTP-versus-AR throughput gate.
- Prefix reuse excludes the row from prompt streaming. This is a real MTP state
  restoration gap when reuse occurs, but prefix caching defaults to `off` in
  `ServerConfig` and the CLI. A shared system prompt alone does not make every
  later request a cache hit. Cache configuration, eligibility and actual hits
  must be measured before calling it the largest current coverage loss.
- gfx1151 has C1-C4 production cells and a distinct C8/K3 cell, as well as
  over-width subgroup and automatic-serving restrictions. Client concurrency,
  resident capacity and the realized physical group are different quantities.
  Do not summarize all of them as an absolute C4 kernel ceiling. Current
  default-serving evidence can be singleton-only even when physical wider
  primitives exist. Remeasure supported wider paths in controlled experiments.
- The global split-attention threshold still couples AR and MTP performance.
  The desired fix is a verifier-specific valid schedule/batched split attention,
  not globally disabling a useful AR attention path. Preserve valid fast work
  before a boundary, handle only the crossing locally, and rejoin a valid fast
  path afterward.
- The MTP breaker is restart-scoped and the selected MTP batch route raises 503
  when its scope is open. AR fallback for a healthy target can be a separate
  routing improvement; it is not safe if target/device state is uncertain.

## Next

Split the work into bounded units, keeping the already-landed guard repair:

1. **Execution containment and error reporting.** Carry failing work IDs,
   ownership group, phase and mutation status. For a pre-mutation request error,
   terminate/reclaim that request. After mutation, fence relevant work and prove
   rollback, rebuild or safe group retirement before continuing. Preserve the
   fatal path for poisoned device/shared state. Test local prefill/decode faults,
   packed-group faults, cleanup failure and fatal GPU-state simulation; survivors
   must match controls and a subsequent request must succeed when recovery is
   safe. Report the actual fault rather than generic memory advice.
2. **Concurrent prompt ownership and per-row execution partitioning.** Scope
   claims by the real provider owner, not an unconditionally global slot. If
   independent priming is impossible, schedule it without losing the required
   hidden-state stream. Resolve eligibility per row, group compatible speculative
   rows and AR rows before combined capability/claim checks, preserve original
   fallback reasons, and execute each row once per tick through the existing
   scheduler. Do not create separate loops or move stable slot ownership.
3. **Real-workload speed and correctness.** Re-run ShareGPT with natural lengths
   and wider/multi-turn contexts, explicit true-AR controls and current candidate
   MTP. Include a healthy short row beside a crossing row, prefix-hit beside miss,
   provider refusal beside ready provider, cancellation/refill and changing widths.
   Require survivor correctness, no spurious fallback caused solely by a neighbor,
   no duplicated work, and report latency/throughput by actual executed groups.
4. **Long-context verifier, cache and wider cells.** Repair the verifier's
   split-attention/batching coupling; restore or recompute draft state for cache
   hits; remeasure C5-C8 economics. Old qualification limits may be bypassed for
   structurally valid experiments, not treated as evidence of impossibility.
   Non-greedy acceptance and processors require their own semantic implementation.
   Promote only with exact control/ownership and the applicable production
   numerical/determinism/isolation/task gates, not blanket bit-identity rejection.

Maximizing MTP usage alone is not the product objective. Optimize correct useful
throughput and latency: a local economical AR decision is acceptable; unrelated
rows losing a valid fast path because of accidental group coupling is not.
