# Use global KV page addresses in packed verifier copies

## Summary

Packed verifier copies now resolve the session-side address of each KV plane from the global pool's page ID. They no longer derive that address from one chunk's base pointer. Private and legacy sessions keep the existing copy path.

## Changes

- Resolve global page pointers for payload, mirror and scale planes during gather and scatter. Retain the packed workspace's existing address mapping and allocator confinement.

## Validation

- The new host regression failed with the old chunk-base calculation and passed after the change. It covers both copy directions across a page boundary with deliberately different scratch bases and global page pointers. The packed layout, packed import and device KV binding bundles passed.
- Public `LLM.generate_detailed()` on the W7900 with Qwen3.8-27B-Q4_K_M, production, eight requests, candidate budget three and 12 greedy output tokens matched AR at prompt lengths 73 and 257. Both global-page copy directions ran and tracked allocations returned to baseline after close.
- The audit still reports the existing post-merge stub, ungoverned flag and worklog findings; none is introduced by this change.

## Next

- R0207 remains open: migrate the device append and attention paths before permitting a request to span separate backing chunks. This public run exercised the new address lookup, not cross-chunk allocation.
