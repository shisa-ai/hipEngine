# Add the UD MTP serving-evidence rows for automatic admission

## Summary

The U6 pin grants the MTP *scope*, which makes an explicit
`speculative_mtp=true` request engage, but the automatic route kept declining
with `decision_reason: automatic_mtp_scope_not_promoted`. Automatic admission
additionally requires `automatic_eligible` on the
`SpeculativeMTPServingEvidence` row that admits the plan, and no UD artifact had
a row at all.

This unit adds two, one per UD artifact, to
`hipengine/models/qwen35.py` as `_UD_Q4K_MTP_SERVING_EVIDENCE`, prepended to
`Qwen35GGUFModel.speculative_mtp_serving_evidence`.

## The row axes

The UD artifacts share the plain Qwen3.8 dense production manifest and the
`gguf_q4_k_m` / `gguf_q4_k_s` file-type stamps, so the distinguishing axes are
the artifact identity alone:

| Axis | Value |
| --- | --- |
| `artifact_sha256` / `artifact_size_bytes` | K_M `322e194f…` / 16,464,440,224; K_S `75bc9c8a…` / 15,358,213,024 |
| `weight_quant` | `gguf_q4_k_m` / `gguf_q4_k_s` |
| `backend` / `target_arch` | `hip_gfx1100` / `gfx1100` |
| `execution_profile` / manifest sha256 | `production` / `2adc137a…` (read from the run's `runtime_profile.manifest_sha256`) |
| `kv_storage` / `kv_layout` | `bf16` / `uniform` |
| `realized_group_rows` / `resident_capacity` | 1 / 1 |
| `candidate_budget` / `sampling_modes` | 3 / `greedy_fast` |
| `max_sequence_length` | 1024 |
| context / horizon buckets | 4-95 / 24-24 |
| `automatic_eligible` | `True` |

Width 1 is not a default: it is the measured scope. c2 K2 engaged and held
`ar_exact` but only reached 1.0418x, c4 K3 is absent from
`GGUF_SPECDEC2_MTP2_PHYSICAL_WIDTH_DEPTHS["production"]`, and c8 K3 fails with
`HIP error 2: out of memory` at capacity 8. Context stays far below the 1023
sentinel where the adapter refuses MTP and the verifier drops to a per-row
route, so the bucket does not claim either.

The artifact digests were computed with `sha256sum` on the pinned files.

## Why the rows are safe to add

`_evidence_checks` requires an exact match on `artifact_sha256` **and**
`artifact_size_bytes`, so a UD row can never admit the plain lane or the
reverse even though they share a weight-quant stamp and manifest. The row is
also the second half of the two-table split: `_UD_MTP_PRESET_FINGERPRINTS`
grants scope, this table grants automatic eligibility, and neither implies the
other.
