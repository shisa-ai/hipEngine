# The Q8_0 ssm dual_split owner is grid-starved; a wide block is a measured 1.35x, gated on arithmetic

## Summary

`q8_0_t16_dual_split_gemv` runs the `ssm_alpha`/`ssm_beta` pair for all 48
linear-attention layers and cost 0.877 ms/step over 576 calls (48/step) at
18.28 us for 25 MB, or 28.6 GB/s. The cause is not bandwidth: the launcher
sets `grid.x = (out_features_a + out_features_b) / T16_COLS`, so a 48-column
pair gets **six blocks on a 96-CU part**, and with a 128-thread block and four
waves each wave walks a 40-block serial k chain. Tiling the same tensor out to
N=1536 makes the same kernel reach **1097 GB/s**, so the kernel is capable and
the real shape is pure exposed latency.

This unit landed the enabling infrastructure for a wider block and measured
the win, but deliberately left the default at 128 because the wider block
changes the arithmetic of a path this repository has already recorded as
token-diverging.

## Changes

`hipengine/kernels/hip_gfx1100/quant/gguf_q8_0_t16_gemv.hip`

- `valid_threads` is split: it keeps `{64, 128}` for the single, rowtile,
  triple and dp4a owners, and a new `valid_split_threads` admits
  `{64, 128, 256, 512, 1024}` for `launch_dual_split` alone. Widening the
  shared validator would have let the other launchers request block sizes
  their `__launch_bounds__` cannot host.
- `q8_0_t16_dual_split_gemv_kernel` goes from `__launch_bounds__(128, 4)` to
  `__launch_bounds__(1024, 1)`.
- Its reduction buffer goes from `xchg[4 * T16_COLS]` to
  `xchg[32 * T16_COLS]`. This is the load-bearing fix: the reduction walks
  `blockDim.x >> 5` groups, so the four-wave buffer was correct only because
  four waves was the only reachable block size. At 256 threads the extra four
  waves wrote past the array and the oracle test failed with 190 of 192
  elements mismatched.

`hipengine/kernels/hip_gfx1100/quant/gguf_q8_0_t16_gemv.py`

- `_ALLOWED_THREADS` stays `{64, 128}`; `_ALLOWED_SPLIT_THREADS` and
  `_WIDE_SPLIT_SYMBOLS` are added, and `_resolve_threads` takes `default` and
  `allowed` keywords. `_launch_dual_split` is shared by six symbols across
  three kernels with different launch bounds, so the wide default is scoped to
  the two plain entry points whose kernel can host it.
- `_DUAL_SPLIT_DEFAULT_THREADS` is `_DEFAULT_THREADS` (128), with the measured
  256 value and its blocker recorded beside it.

`tests/test_gguf_q8_0_t16_gemv_decode.py`: the dual_split thread-override test
is parametrized over `[0, 64, 128, 256, 512]` so the default and every allowed
block size are checked against the CPU oracle. `threads=0` is the default
case.

`docs/UD-GFX1151-OPTIMIZE.md`: a new open item with the measurements, the
blocker, and the bit-identical alternative.

## Why the default is still 128

The wave count is the k-split factor: four waves each sum a 40-block stride-4
chain, eight waves each sum a 20-block stride-8 chain, and the reduction then
sums the wave partials in index order. Changing it changes the summation order
and therefore the bf16 output of `ssm_alpha`/`ssm_beta`, which feeds the gated
linear attention. The 2026-09-13 Q8T16 rowtile entry records exactly this:
"the broad boolean also changes the `ssm_alpha`/`ssm_beta` arithmetic and
diverges generated tokens, while this shape set does not". So this is a
production-profile arithmetic change and it owes the section-6.1
teacher-forced gate plus the paired AR/MTP protocol. Landing the census win
without that gate would violate the evidence policy.

   `_DUAL_SPLIT_DEFAULT_THREADS = 256`. If both pass, promote the constant and
   update `benchmarks/README.md` and `benchmarks/CHANGELOG.md`.
2. If the gate blocks it, implement the bit-identical route instead:
   block-level split-K. Give each output tile S blocks that each own a
   contiguous, wave-aligned k range and write ordered partials, then reduce
   `for wave: for split:`. The concatenation then reproduces the original
   summation order exactly, so the grid goes to 6 x S with no arithmetic
   change and no gate.
3. The same grid-starvation pattern is worth checking on the other small
   Q8_0 pairs if any appear.
