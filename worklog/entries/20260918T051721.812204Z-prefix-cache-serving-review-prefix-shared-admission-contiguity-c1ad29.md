# Keep shared-prefix admission contiguous for long-context packed prefill

## Summary

With `HIPENGINE_PREFIX_CACHE=radix`, any multi-turn lane whose prompt reached
1024 tokens failed outright on gfx1151:

```
NotImplementedError: packed paged AR prefill currently requires context < 1024
```

The failure is pre-existing at base commit `9493d4224`; it reproduces without
any change from this session.

Mechanism. `GlobalDeviceKVPool.admit_with_shared_prefix` placed the private
suffix at the lowest free page ids. Those pages need not continue the shared
prefix, so a reuse admission could return a prefix-plus-suffix allocation with a
page gap. `_gguf_device_kv_contiguous_base_row` reports a gapped allocation as
non-contiguous, which forces `slot_local_full_prefill = False`, and
`_validate_packed_ar_prefill_context` rejects a non-slot-local packed prefill at
or above 1024 tokens. Fragmentation makes this common: a retained prefix
snapshot from a long-prompt lane pins the pages directly after a shorter lane's
prefix, so the shorter lane's next turn is admitted with a gap.

Reproduced allocation (instrumented run, `slot=0`):
`block_ids=(8193, 8194, ..., 8200, 8233)` with `chunk_start=0`,
`max_live=2094` — 8 shared prefix pages, a 32-page hole, then the suffix.

Three changes fix it:

1. Shared admission prefers a suffix run directly after the shared prefix, so
   the whole allocation stays one contiguous run whenever the pool can place it.
2. `require_contiguous` makes both device pools reject a gapped placement with
   `DeviceKVContiguityError` (a `MemoryError` subclass) instead of returning it.
3. `reserve_admission` asks for contiguity when the prompt reaches
   `PACKED_AR_PREFILL_CONTEXT_LIMIT` and, on rejection, uses the existing
   private-allocation fallback — which now also requires a run, and which may
   reclaim cached prefix pages once through the existing `on_pressure` hook
   (safe there because no shared prefix is being reused).

The packed-pool `allocate` path and the legacy chunked pool carry the same
contract, so a caller cannot silently receive a gapped allocation from either
implementation.

## Changes

- `hipengine/kvcache/global_pool.py`: `GlobalKVPoolSet.allocate` takes
  `require_contiguous`; `_select_free` prefers a run after the shared prefix and
  `_find_free_run` supplies the contiguous-run search; `_take_free` selects then
  claims so a rejected placement leaves the pool untouched.
- `hipengine/kvcache/pool.py`: `DeviceKVContiguityError`; the same contract for
  `DeviceChunkedKVPool.admit_with_shared_prefix` (`_shared_suffix_block_ids`) and
  a `require_contiguous` parameter on `DeviceChunkedKVPool.allocate`, which
  already places one contiguous run per backing chunk.
- `hipengine/kvcache/device_global.py`: thread `require_contiguous` through
  `allocate`, `admit_with_shared_prefix`, and `fork_copy_on_write`; a failed
  contiguous placement in `allocate` reclaims cached prefix pages once and
  retries before failing.
- `hipengine/runtime/qwen35_gguf_runner.py`: name the packed-AR prefill context
  limit `PACKED_AR_PREFILL_CONTEXT_LIMIT` and use it in
  `_validate_packed_ar_prefill_context`.
- `hipengine/generation/qwen35_gguf.py`: `reserve_admission` requests a
  contiguous allocation for long prompts, reports a declined reuse as
  `prefix_fallback_reason = "shared_admission_noncontiguous"`, and requests
  contiguity on the private fallback allocation.
- `tests/test_unit_kvcache_global_device_pool.py`,
  `tests/test_unit_kvcache_policy.py`: placement and rejection contracts for both
  pool implementations. `tests/test_unit_qwen38_m1_shadow_lifecycle.py`: the
  stub pool accepts the new keyword.
