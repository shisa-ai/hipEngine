# T16 production tile-residency design spec

## Summary

The production tile-residency design for the T16 gate/up admission, committed
as the build spec for the next session. The committed integration (23e08679b)
runs the T16 branch from an externally populated module cache, which bounds
the window at 30 of 47 layers (~37 GiB free after model load vs ~43 GiB of
full tile set beside the resident raw weights). The production design removes
the bound by replacing instead of adding:

**Design.** When the lane binds the T16 route (the production binder's env),
the weight materializer builds a  sidecar allocation for
each Q4_K expert gate/up pair via the existing 
(the laguna materializer's proven path), stores it on the GGUFDeviceWeight
alongside the raw allocation, and frees the raw gate/up allocation once the
sidecar is verified (nbytes match the repack contract). The runner branch
then reads the sidecar through the weight object instead of the module cache.
The strict fallback re-materializes the raw weights from the GGUF only if the
route is unbound (the GGUF remains the source of truth; no re-download).

**Layer2-gate wiring.** Register a  CandidateSpec with the
environment override HIPENGINE_QWEN4_EXP_T16_GATE_UP=1 and a populate hook in
the gate harness that builds the sidecars at construction (the same
 path the A/B used, run after generator
construction and before any measured row). The candidate then flows through the
standard 18-prompt layer2 production gate; prefill_last (X-7) is the risk axis,
and the scope-threshold decision remains with the human owner.

**Acceptance targets from the committed evidence.** Full 47-layer window:
~+9-10% aggregate prefill (the 30-layer window measured +6.53% with all 12
cases positive; the owner screen measured 2.17-2.18x per complete operation);
the down-leg T16 layout (which MX-1 named as missing) is the follow-on unit
after gate/up admission.

## Changes

- No engine change in this unit; the design and gate-wiring plan are committed
  as the spec. The committed stages stand at: 4-arm owner A/B (-32.90% median),
  natural-input owner gate (2.17-2.18x), runner integration (env-gated,
  structural fallback, 43 tests green), full 12-case A/B (+6.53% aggregate,
  12/12 positive).

## Validation

- Every stage of the pipeline is committed with its artifact; the design
  builds on the materializer's existing repack path (the laguna materializer
  already materializes T16 dual pairs at load) and the proven A/populate
  helpers (scripts/qwen4exp_t16_populate_tiles.py).
