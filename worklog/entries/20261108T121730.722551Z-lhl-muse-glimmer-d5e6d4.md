# Muse Glimmer shared-row WMMA decode and verify attention

## Summary

Lands §11 lever #1 from `docs/campaigns/MUSE-GLIMMER.md`. AR decode and the
exact DFlash block verify now share one attention kernel,
`muse_glimmer_decode_attention_shared`. Each wave owns one query row and packs
the KV head's 16 Q heads into the WMMA row dimension. Every staged 16-key K/V
tile serves all heads and all verify rows. Keys are cut into absolute 64-key
splits, owned round-robin by 64 blocks per KV head and merged by the existing
(gated) combine. Absolute splits make a verify row bit-identical to the AR
decode step at its position, so DFlash stays exact.

End-to-end A/B: same build, same KV (loaded from `save_context` snapshots), old
kernel patched in for the baseline. gfx1151, coding prompt, 256 greedy tokens,
r=1. A resident llama-server was idle (0 CU) but held 20.7 GB.

| ctx | AR tok/s old → new | AR step ms | DFlash tok/s old → new | verify ms/cycle | DFlash/AR new |
|---|---|---|---|---|---|
| 512 | 12.27 → 12.20 | 81.4 → 81.9 | 30.72 → 30.79 | 104.8 → 104.5 | 2.52x |
| 32K | 11.13 → 11.77 | 89.7 → 84.9 | 15.82 → 18.99 | 139.4 → 110.0 | 1.61x |
| 126K | 9.14 → 10.91 | 109.5 → 91.5 | 10.38 → 17.74 | 235.9 → 122.7 | 1.63x |

DFlash IDs equal AR at every context with both kernels. The isolated kernel,
one full-attention layer (`scripts/muse_glimmer_decode_attn_scale.py`):

| case | old | new |
|---|---|---|
| 131K, 1 row / 5 rows | 2.24 / 10.02 ms | 0.74 / 1.36 ms |
| 262K, 1 row / 5 rows | 4.44 / 22.51 ms | 1.45 / 2.62 ms (1.19x the K/V read floor for 1 row) |
| SWA window 2048 at 32K, 1 / 5 rows | 0.071 / 0.178 ms | 0.038 / 0.057 ms |

Split geometry: 64 keys x 64 blocks. It was the best verify setting at every
context and on SWA layers. For a single row on full layers at 262K, 128 blocks
is ~8% faster (1.34 ms), but decode and verify must share one geometry.

Two defects were found and fixed during the unit.

1. **WMMA is not invariant to zero-probability operands.** The first version
   relied on a tile with masked keys contributing exactly what it contributes
   when the row runs alone. It passed random-data bit-identity tests, but on
   the real model a 5-row verify differed from decode by one BF16 ulp at a
   single element (layer call 13, key_end 35, row 2). Zeroing that tile's
   masked V rows removed the difference; zeroing K did not. The f16 WMMA
   result therefore depends on V entries multiplied by an exact-zero
   probability. A one-row call stages zeros past its position, while the
   block stages the later rows' real V. Over 52 layers the ulp diverged
   DFlash from AR after 20 tokens.

   Fix: each wave skips tiles it cannot see and zeroes the K/V entries it
   cannot see in tiles it sees partly. Fully visible tiles are untouched, so
   there is no measurable cost; zeroing every tile had doubled the 5-row cost.
   The captured case is the fixture
   `fixtures/muse_glimmer/shared_attention_masked_v_case.npz`.
2. **The decode graph silently fell back to eager.** The graph body's local
   import still named the old kernel, so capture raised `NameError` and
   `decode_step` silently ran eager, ~9 ms/step slower at 512. Every
   correctness gate still passed. Fixed, and
   `tests/test_live_muse_glimmer_runner.py::test_decode_replays_the_captured_graph`
   now asserts graph engagement.
