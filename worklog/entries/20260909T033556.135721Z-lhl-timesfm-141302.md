# TimesFM flash attention + HIP-graph negative result

## Summary

Phase-2 optimization levers for the TimesFM GPU decode path, in order:
(1) HIP graph capture — measured as a net loss on this ROCm stack and
reverted (negative result recorded); (2) WMMA flash-attention kernel —
landed; the attention sub-window is decisively faster (0.73 ms/layer
prefill micro-benchmark, scores-buffer round trip eliminated, launches per
layer 5 -> 2) while the wall metric stays flat within AR-feedback noise
(median ~0.0959 vs ~0.0975). Retained per the sub-window-win rule.

## Changes

- `hipengine/kernels/hip_gfx1100/timesfm/timesfm.hip`: new
  `flash_attention_kernel` (template on dtype + threads-per-block) and the
  `timesfm_flash_attention_f16` C launcher (128-thread/4-tile blocks for
  Q >= 64, 32-thread otherwise).
- `hipengine/kernels/hip_gfx1100/timesfm/timesfm.py`:
  `timesfm_flash_attention_f16` wrapper + ABI signature.
- `hipengine/runtime/timesfm_decode.py`: the fp16 attention chain
  (scores GEMM + masked softmax + AV GEMM) is replaced by the flash kernel;
  `timesfm_mask_softmax_f16` import dropped.
- No buffer changes: the `scores` buffer is now unused by the fp16 path
  (still allocated; removal deferred to a refactor pass).

## What was tried (phase-2 levers, in the user-approved order)

### Lever 1: HIP graph capture of the forward — REJECTED (negative result)

Built a full maple-style `_GraphCache` for the TimesFM decoder: per-(n, start,
skip_quantile) lazy capture on second occurrence, structural replay validation
(finite + loose allclose), eager fallback. Results on the bench workload:

- Graph replay measured **0.104-0.109s vs 0.097-0.099s eager** — ROCm graph-node
  execution overhead exceeded the Python/ctypes launch savings on this stack.
- Any capture attempt **persistently slowed later eager runs by ~8%**
  (0.1087s eager-after-capture vs 0.0981s with the capture stream idle), even
  with all eager execution kept off the capture stream.
- rocBLAS FP16 GEMMs are **not deterministic across identical launches**
  (split-K accumulation): two eager decodes of identical inputs differ by up
  to 0.14 after AR-feedback amplification. Bit-parity graph validation is
  impossible; the fp32 strict path remains the exactness contract.
- Code reverted; the lesson: on gfx1151 + this ROCm, graphs are a net loss for
  this launch pattern. Revisit only after a ROCm upgrade, with a fresh A/B.

### Lever 2: WMMA flash attention — LANDED (sub-window win, wall flat)

`flash_attention_kernel` in `kernels/hip_gfx1100/timesfm/timesfm.hip`:
RDNA w32 `__builtin_amdgcn_wmma_f32_16x16x16_f16_w32` with the fragment
conventions probed empirically (and matching the PARO WMMA kernel):

- A fragment: lane loads 16 consecutive k elements of row (lane & 15);
  B fragment: lane loads 16 consecutive k elements of column (lane & 15);
  C fragment: lane holds rows (lane >> 4) + 2j, column (lane & 15).
- Online softmax; per-row statistics reduce across the 16-lane half-groups via
  `__shfl_xor(..., width=16)`. P is staged through LDS between the QK and AV
  WMMA calls (C layout -> A layout).
- Causality skips whole upper-triangle kv tiles; all-masked query rows
  (q+off < num_masked, prefill-only) reproduce the reference uniform-1/S
  softmax by weighting every in-range key with 1 (O = mean of V) — the first
  q tile extends its kv loop to S when such rows exist.
- K/V loads are bounds-guarded for ragged S (S % 16 != 0): the unguarded
  version faulted on standalone allocations (the guard/bench arena masked it).
- 128-thread blocks (4 q tiles) for Q >= 64, else 32-thread blocks (AR).

Micro-benchmark (bench shapes B=8, Q=256/S=268, H=16, D=80):
0.729 ms/layer prefill (0.853 at 32-thread), 0.031 ms/layer AR. Replaces the
scores GEMM + masked-softmax + AV GEMM chain (5 launches -> 2 per layer,
35 MB/layer scores-buffer round trip eliminated).

Wall metric: flat-to-slightly-better (median ~0.0959 vs ~0.0975; multiloop's
significance test cannot call it). **Retained per the sub-window-win rule**
(AGENTS.md: cycle-wall/verified sub-window/launch-count reductions count even
when same-session AR variance hides the headline ratio).

Correctness: fp32 strict parity (atol 5e-4) + fp16 production gate both pass;
pytest 3/3; standalone NumPy oracle comparison of the kernel at B2/B8, ragged
Q/S, and uniform-fallback shapes maxdiff <= 1.1e-3.

## Debugging gotchas recorded for posterity

- `rt.memcpy(ptr, np.ones(n).ctypes.data, n)`: the temporary numpy array is
  freed before the C call dereferences the pointer -> host SIGSEGV that looks
  like a GPU hang. Always bind the array to a name first.
- Pipeline `cmd | tail` reports tail's exit code; a segfaulting python under
  `timeout` prints "dumped core" with rc=0 from `$?`. Redirect to a file and
  check the real exit code.
