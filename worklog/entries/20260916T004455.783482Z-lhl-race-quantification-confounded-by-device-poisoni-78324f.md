# Race quantification confounded by device poisoning; per-process design needed

## Summary

First quantification attempt (`scripts/tp2_resident_race_quantify.py`, N=3
per arm, one process): unwrapped 3/3 STALL, wrapped 3/3 STALL. The arms are
confounded — every attempt after the first stall shares a device whose
livelocked kernel is still spinning (process exit is what reclaims it), so
runs 1..5 inherit a poisoned device regardless of instrumentation. The only
clean-process data points remain: unwrapped fresh-process runs stalled 4/4
across earlier entries; the single fresh-process run with inter-layer HIP
event records completed in 0.3 s (entry 2690c0).

A second distinction also surfaced: pass-through Python wrappers do NOT
mask the race — the masking run had real inter-layer `event_record`
commands on the stream. So the race window is sensitive to the device-side
command-stream layout, not to Python-level timing alone.

## Changes

- `scripts/tp2_resident_race_quantify.py`: committed as the (corrected)
  harness skeleton; its runner loop must move to one subprocess per
  attempt before its numbers mean anything.

## Validation

- In-process quantification log (/tmp/race_quant.log): both arms 3/3 STALL,
  every attempt exactly at the 60 s budget; consistent with device
  poisoning after the first stall rather than arm-independent behavior.

## Next

1. Re-run the quantification with one subprocess per attempt (parent
   orchestrates, child runs one prefill and exits; parent tallies). Report
   stall rates for: unwrapped, pass-through-wrapped, event-record-wrapped.
2. On any hang inside a child with event instrumentation active, the
   per-primitive events name the racing kernel; audit its stream/scope
   dependencies.
3. Keep the MTP unblock path (compose the decode session over the working
   dispatch) independent of this diagnosis.
