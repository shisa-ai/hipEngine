# Synchronize llama HIP exact-core timing

## Summary

The first two llama.cpp HIP pilot rows exposed an asynchronous-boundary bug in
the backend-neutral exact helper: core pp512 reported an impossible 70-71K
tok/s because `llama_decode()` returned before the final HIP work completed.
The pilot was stopped and excluded before completing one block.

## Changes

- Added `llama_synchronize(context)` after core prefill and after the complete
  forced-token decode loop, before each end timestamp.  The public path already
  synchronizes through every logits/top-1 read and is unchanged.
- Vulkan is also synchronized explicitly, making the timing contract backend-
  independent rather than relying on Vulkan's observed blocking behavior.

## Validation

  tg tok/s**; Vulkan **5430.6 / 194.50 / 125.66 tok/s**.  Both core and public
  top-1 repeats are deterministic; all rates are plausible.
