# R7 task #33: digest-mismatch minimal reproducer — mechanism identified

**Date**: 2026-09-10T09:45Z (session local clock offset from entry names)
**Task**: #33 — "Digest-mismatch minimal reproducer: harness reuse vs runtime defect"
**Verdict**: **(a) harness defect** — a `token_id_resident` contract violation in the
A/B harness scripts. Not (b) configuration mixing, not (c) a runtime defect. The
batched-position promotion does **not** need re-examination.

## The contract

`Qwen4ExpGGUFResidentModelRunner._finish_lm_head(capture_logits=False)` publishes the
greedy token to `token_id_buffer` via the device `argmax_f32` kernel. Steps with
`token_id_resident=True` skip the host upload and read `token_id_buffer` directly.
Production honors this pairing:

- generator compact path: `prefill(capture_logits=False)` + steps
  `token_id_resident=True` (consistent — prefill publishes);
- generator controlled path: `prefill(capture_logits=True)` + steps
  `capture_logits=True, token_id_resident=False` (consistent — host round-trip).

## The violation

Every R7 A/B harness script (flawed v8 mid-process toggle experiment AND the
per-process attribution arms) called `runner.prefill(...)` with the default
`capture_logits=True` — token computed host-side via `np.argmax`, `token_id_buffer`
never written — then drove decode steps with `token_id_resident=True`. Each case's
first decode step therefore embedded whatever was last in `token_id_buffer`:

- fresh-process case 1: the fresh (in-practice deterministic) allocation contents;
- later cases / later repetitions: the previous sequence's final argmax token.

## Reproducer evidence (all on code-p512, 48 steps, UD-Q4_K_XL production profile)

1. **Toggle reproducer** (one process, one generator, OFF/ON/OFF/ON toggles of
   `HIPENGINE_QWEN4_EXP_BATCHED_POSITION` + runner attribute): all four toggled runs
   bit-identical. Toggling is exonerated. But the no-toggle **control's first run
   differed from runs 2+** (`3fbadf290fceee64` vs `0017e313cfbd504a` ×2) — first-run
   vs repeat divergence, not flag divergence.
2. **Fresh-process ground truth**: single run = `3fbadf290fceee64` → the fresh-state
   run is the "canonical-family" one; repeats deviate.
3. **`capture_logits=True` localization**: with logits captured every step, three
   consecutive runs are bit-identical, max |Δlogits| = 0 — the mismatch lives in the
   `capture_logits=False` path.
4. **Parameter bisect** (fresh process, 3 runs each):
   - `(logits=0, resident=0)` stable; `(logits=1, resident=1)` stable;
     `(logits=1, resident=0)` stable;
   - `(logits=0, resident=1, hidden=0)` and `(logits=0, resident=1, hidden=1)` both
     diverge as `3fbad… → 0017…` — the trigger pair is exactly
     `capture_logits=False` + `token_id_resident=True`;
   - `capture_target_hidden` is irrelevant.
5. **Flow comparison** (12 canonical cases × 48 steps, `sha256(json.dumps(toks))[:16]`):
   - Flow B (A/B harness pattern) fresh process: `ea0412231532bc7b` — reproduces the
     attribution arms' digest exactly;
   - Flow A (canonical-bench contract — `prefill()`/`step()` with defaults, every
     token uploaded): `19045b7c9fd442e5` — the true canonical-contract digest.

## Consequences

- **v8 mid-process mismatch explained**: the flawed experiment repeated the 12-case
  set six times in one process; repetition 1's case-1 read fresh allocation contents,
  repetitions 2+ read the prior repetition's final token — exactly two digests
  (`ea0412…`/`5d02…`). The OFF/ON toggle correlation was coincidental with run
  order.
- **Attribution artifact (0bf43f1d) stands**: all 12 arm-reps were fresh processes
  with the identical deterministic buffer history, so the digest was identical across
  arms and the arm-equality conclusion is valid. The digest is, however, the
  A/B-harness digest, not the canonical-contract digest (`19045b7c9fd442e5`);
  `digest_erratum` added to the artifact JSON. Per-step kernel work is
  token-independent in volume (fixed top-k expert routing, same shapes), so the TG
  latency deltas are unaffected.
- **Production is safe**: only the harness mixed the contracts; both generator paths
  are internally consistent. No runner fix required.
