# Dense Qwen3.8-27B has no MTP serving evidence rows at all

## Summary

Sharpens `20260830T170043` (commit 8282d512c), whose conclusion still stands but whose
wording was weaker than the
truth. The only MTP serving evidence declared in the model package is
`_QWEN36_MOE_Q4KM_MTP_SERVING_EVIDENCE`,
whose first row carries `evidence_key="qwen36-moe-q4km-gfx1100-production-bf16-c1-k2-d24"`
(`hipengine/models/qwen35.py:23-32`). That is Qwen3.6 MoE `Q4_K_M` in one production
C1/K2/D24 configuration. So
the accurate statement is not that the dense Qwen3.8-27B's evidence is pinned to the
wrong artifact - it is that
**the dense 27B model has no MTP serving evidence rows whatsoever**. Nothing is stale or
mis-pinned; the
qualification was simply never performed for this model, which is why automatic MTP
declines at every width of
the C1-C8 matrix.

## Changes

- No code change. This entry supersedes the wording of `20260830T170043`; its conclusion -
  the artifact axis
  cannot match for the benchmarked model at any width, so the C1-C8 rows are AR-vs-AR by
  construction - is
  unchanged.
- Consequence for the campaign: the C1/C2 headroom measured under forced explicit K3
  (31.455 vs AR 21.999,
  39.820 vs 31.916) is gated behind a qualification that does not exist yet, not behind a
  gate that is merely
  set wrongly.

## Validation

- Constant name and `evidence_key` at `hipengine/models/qwen35.py:23-32`; the declared
  `artifact_size_bytes`

  key built from the dense 27B can match those rows. No new run.
