# Qwen3.8 M2a: admit rows5-8 proposal-head rowtile (wide direct-gemv class)

## Summary

M1's rocprof attribution names two wide-only owners that the width-4 policy
never engages, and the larger one is fully accounted: in the bound-8 C8 run,
`q6_k_t16_qmicro_planar_gemv_bf16_kernel<float>` (the direct per-row lm-head
gemv) runs **116 launches / 4265.6 ms / ~36.8 ms per launch**, exactly
`rows x ~4.6 ms` per-row weight re-reads of the 248320-tied head, while the
identical row counts in the split regime cost ~4.8 ms per chunked sweep. The
cause is admission, not kernel capability:
`GGUF_SPECDEC2_PROPOSAL_LM_HEAD_ROWTILE_POLICIES` admits only rows 2-4, and
one wide proposal carries rows5-8, so `run_batch_proposal_device()` falls to
the direct producer (`last_specdec2_proposal_lm_head_path ==
"row_linear_f32_logits"`). The planar rowtile body itself is already
bit-identical to that direct parent through rows 8 (the pre-existing RED
compared it as `"exact-unadmitted"`), so admitting rows5-8 is a policy change
with an existing exact proof.

## Changes

- `hipengine/kernels/hip_gfx1151/__init__.py`: proposal-head policy extended
  to `(5120, 248320, 5..8)`. Unengaged at the certified width-4 default (the
  proposal group never exceeds four requests), so the production default path
  is untouched; the keys arm automatically when a profile re-lists a bound
  >= 5.
- `tests/test_qwen38_nextn_proposal_head_rowtile.py`: the actual-weight RED
  now asserts the **package route** for every rows2-8 (was rows2-4, with the
  primitive checked as unadmitted beyond), including the guard-word and
  lowest-ID argmax tie contracts.
- Seam package test and laguna `hip_gfx1151/__init__.py` raw-source pins
  refreshed for the policy table (precedent 0125fd17d).
- `tests/test_gguf_q6_k_f16_rocblas_prefill.py` (committed separately as
  07055bec7): actual-shape nodes now skip when the externally removed
  `Qwen3.6-27B-Q4_K_M.gguf` asset is absent.

## Validation

- `pytest`: `test_qwen38_nextn_proposal_head_rowtile.py` (actual-weight
  bit-identity vs the direct parent for rows 2-8, guard words intact,
  argmax ties lowest-ID), `test_qwen35_gguf_mtp2_seam.py`, and the three
  laguna pin suites: 0 failed.
- Route confirmation at runtime: the probe driver logs every
  `_verify_lm_head_rowtile_chunked` decision; the packed **verify** head
  already chunks to <=4 rows and reports `handled=True` for rows 8/16/32, so
  the 4265.6 ms direct class is proposal-only, matching this fix's scope.
