# Bind Q8 MMQ prefill workspace to its execution owner

## Summary

The Q8 MMQ prefill workspace gate is now request-local runner state instead of
the process key `HIPENGINE_QWEN4_EXP_Q8_MMQ_PREFILL`. The historical key remains
only as the direct/unbound fallback, with its exact raw false set preserved
(`""`, `"0"`, `"false"`, `"False"`). A bound owner never reads the key.

The production profile binder publishes the decision on the generator and the
runner it finds, and writes no process key. Existing non-UD production plans
keep their published `True`; UD production, strict, and batch-invariant keep
`False`. The constructor, late-clone path, and lane inheritance carry the owner
decision.

Resource preparation stays an explicit cold-path operation. A prefill that is
enabled without a prepared workspace now raises a named precondition error
instead of silently measuring the scalar owner. The configure path reuses
already-owned buffers before consulting any owner or ambient decision.

The partial-allocation rollback belongs to this precondition because the
workspace is three buffers that must appear together: a failure after the first
allocation has to release the buffers already taken and leave no policy,
library, or buffer ownership behind. The rollback now also preserves the
original allocation error if a `free` itself fails, notes each cleanup
failure on that exception, and still attempts every acquired buffer, so the
caller sees the partial-resource precondition without hiding a leak.
