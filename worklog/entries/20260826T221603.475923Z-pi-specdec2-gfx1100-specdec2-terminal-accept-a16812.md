# Fix terminal bounded MTP accept semantics

## Summary

Fixed the bounded accept contract at the terminal decode boundary. Both the CPU
oracle and gfx1100 `dflash_accept_chain_i32_kernel` had interpreted
`remaining_decode` as accepted-draft room instead of total visible-output room.
A final cycle could therefore accept one draft with `remaining_decode=1`, emit
no correction, and commit target state one row beyond the scheduler-visible
cursor. The Generation-2 35B MoE C1 path now explicitly supports a terminal
K1 verification that accepts zero drafts and emits exactly one corrective
target token; providers without this capability retain K0.

## Changes

- Added fail-closed `terminal_zero_accept_supported` capability metadata and
  enabled it only for `Qwen35GGUFMoEMTP2Adapter`.
- Cleared the shifted-state temporary pointer immediately after successful copy
  so a later setup exception cannot double-free it during cleanup.
- Bounded accepted drafts by `max(0, remaining_decode - 1)` in both the CPU
  `TargetVerifyBatch.accept_from_top1` oracle and the gfx1100 accept kernel.
- Relaxed native complete-cycle graph eligibility to one remaining output only;
  its existing bounded payload ABI now commits the root row and one correction.
- Added focused oracle, planner-capability, and native graph eligibility tests.
  The pre-existing no-capability output-room test remains unchanged and proves
  fail-closed behavior.
