# substitute each rank's attention shards and head-local geometry

## Summary

Step 2 of the head-sharding plan. Each rank's runner now receives its own
attention shards and a config whose head axes are halved, so every attention
width it derives - and therefore every width its kernels launch with - describes
the rank's own slice instead of the full model.

The load-bearing property is that the payloads and the geometry cannot disagree.
The payloads come from the shard planner's manifest; the geometry comes from the
config. If the halved config described a different shape than the shards hold,
the kernels would read the wrong rows **silently**, because both halves would be
internally consistent. Measured on the real model, they agree exactly:

| | unsharded | substituted |
|---|---:|---:|
| `q_width` | 6144 | 3072 |
| `kv_width` | 1024 | 512 |
| `linear_qkv_width` | 10240 | 5120 |
| `ssm_value_dim` | 128 | **128** (per value head) |
| `hidden_size` | 5120 | **5120** (replicated) |
| resident scratch @ 4096 | 413.7 MiB | **208.1 MiB** (ratio 0.503) |

The scratch stack follows because `_FullStackScratch.allocate` sizes KV, conv,
recurrent/alpha state and the rope tables from the same pure sizing plan, so
substituting the config **before** allocation is what makes the residency
per-rank rather than replicated. `kv_payload_bytes` halves exactly.

**Nothing runs yet.** Splitting the heads makes `attn_output`/`ssm_out` a
hidden-size partial per rank, and the post-attention norm consumes the sum, so
without the reduce each rank's residual would carry only its own half - wrong
output, not merely a slow one. `_require_attention_reduce` refuses at
`_bulk_attention_layer` and `_enqueue_layer`, the two points where a layer would
actually run, so a new caller cannot bypass the guard by not knowing about it.
Construction is allowed, which is what makes the substituted geometry real and
testable.

## Changes

- `hipengine/distributed/shard_weights.py`:
  - `ATTENTION_SHARD_AXES` is now the single axis authority, and
    `_preflight_family_axes` reads it instead of its own inline dict, so the
    refusal message and the substitution cannot drift.
  - `attention_sharded_config(config, *, world_size)` halves `head_count`,
    `head_count_kv`, `ssm_group_count`, `ssm_inner_size` and
    `ssm_time_step_rank`, refuses a degree that does not divide an axis, and is
    the identity at `world_size=1`.
  - `SHARD_FAMILIES` and `family_slot_names(family)` expose what a family
    replaces, from the family tables rather than a copy.
- `hipengine/distributed/tp2_generate.py`:
  - `rank_slot_allowlist_from_records(records, *, families=("mlp",))` derives its
    excluded leaves from the family tables. The default is the previous behavior
    (the MLP leaves only), and `families=("mlp", "attention")` drops the
    full-width attention and GDN copies as well - 640 of 851 records on the
    supplied GGUF, leaving 211 resident.
  - `_build_attention_shards` materializes and uploads each rank's shards;
    `_apply_attention_shard` substitutes them plus the halved config into that
    rank's `Qwen35GGUFResidentWeights` through `dataclasses.replace`, leaving the
    frozen dataclasses intact. `ShardWeight` is the `Qwen35GGUFDeviceWeight`
    stand-in the launchers consume, so the layer map takes it unchanged.
  - `self._config` is now the model's own config captured before substitution,
    not the control rank's substituted one. The session describes the model;
    each runner describes its rank.
  - New `attention_shard` parameter, distinct from `head_shard` (which is the
    sharded logits head and already means that throughout this module).
- `docs/REFACTOR.md`: entry recording the flag, the blocker, the removal
  condition, and the shape-key consequence below.
- `tests/test_gpu_distributed_attention_shard.py` (new): the real runner, the
  real substitution, the payload-versus-geometry agreement, and the guard.
- `tests/test_unit_distributed_shard_weights.py` and
  `tests/test_unit_distributed_tp2_generate.py`: pure tests for the halving, the
  refusals, the family leaf names, the allowlist behavior in both modes, and the
  scratch plan.

## Validation

- `python3 -m pytest tests/test_unit_distributed_*.py -q` - 237 passed.
- `python3 -m pytest tests/test_gpu_distributed_attention_shard.py
  tests/test_gpu_distributed_staged_compiled.py
  tests/test_gpu_distributed_shard_components.py -q` - 13 passed, 1 skipped
  (two-device guard). The substitution test runs in 42.5 s.
- Measured on the real model with the route's own allowlist: the geometry table
  above, the attention slots resolving to `ShardWeight` with their planner
  layouts (`gguf_q4_k_t16_v1` for `attn_q`/`attn_k`/`attn_output`,
  `gguf_q6_k_t16_qmicro_planar_v1` for `attn_v`/`attn_qkv`, `dense_f32` for the
  GDN scalars, `gguf_q5_k_t16_v1` for `ssm_out`), non-attention slots untouched,
  and the guard refusing.

Two findings worth carrying forward:

- **The attention shape keys change, so shape-qualified variants fall back.**
  `_gguf_full_attention_split_decode_policy` and `_gguf_grouped_gqa_decode_shape`
  look variants up by a shape tuple containing `head_count`/`head_count_kv`, so a
  halved shape misses those tables and takes the generic path. That fallback is
  *correct* - a variant is only applied at a shape it was qualified at - but the
  sharded shapes need their own qualification before this route can claim those
  variants. Recorded in `docs/REFACTOR.md`.
- **The uploaded weight does not carry a logical shape.** Its tensor proxy is the
  flat repacked payload (`(18186240,)` for `attn_q`), so the planner's
  `local_shape` is the authority on slice geometry. The first version of the test
  asserted against the weight and failed for that reason; the assertion now
  compares the runner's derived width against the planner's declared shape, which
  is the property that actually matters.
