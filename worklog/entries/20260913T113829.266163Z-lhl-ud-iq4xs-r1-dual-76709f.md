# The IQ4_XS rows=1 gate/up dual is bit-exact and 1.14-1.37x, and already admitted

## Summary

The 2026-09-13 rejection of the IQ4_XS gate/up dual+SiLU fusion timed only its
rows 2-4 `ROWS` sibling and left the rows=1 instantiation unmeasured. That
instanton is the register-lean accumulator scheme the rejection note named as the
condition for re-opening, and it is the one the decode path actually uses. It was
measured here: bit-exact, 1.14-1.37x, and already admitted.

## Changes

- `benchmarks/results/2026-09-13-ud-gfx1100-iq4-xs-rows1-dual-silu.json` — new,
  the rate and parity measurement.
- `docs/UD-GFX1151-OPTIMIZE.md` — the item 671 rejection note now records the
  rows=1 measurement and that the rows 2-4 rejection does not apply to it.

## Decision

No kernel change. The fused owner
(`linear_pair_silu/gguf_iq4_xs/local32_pair_silu_bf16_bf16_out`) is already
resolved by `hipengine/runtime/gguf_linear.py` whenever both operands take the
local32 decode owner at rows == 1, so the measured rates are current behaviour
rather than an untaken opportunity. This is a false lead recorded so it is not
pursued again, plus the verified property that makes the earlier rejection note
precise.

## Validation

Two earlier reference computations were wrong and are recorded so the check is
not repeated badly: the first used numpy float64 `exp` where the kernel uses f32
`expf`, and the second compared a bf16-rounded output against an unrounded f32
product. The f32 SiLU with bf16 rounding is the correct reference and matches
exactly.
