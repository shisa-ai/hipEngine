# TP2 Packet 0/1: explicit HIP device ownership primitives

## Summary

Added the minimal explicit-device primitives that Packet 0 screening and Packet 1
rank ownership both need. `HipRuntime` now exposes device count/selection, name,
UUID and PCI bus identity, peer-access query/enable/disable, and an explicit
`hipMemcpyPeer` wrapper. `DeviceBuffer` carries an optional owning device, and
allocation through `core.memory.malloc`/`DeviceMemoryArena.create` attributes the
device and scopes `hipSetDevice` so multi-rank allocation does not leak
thread-local current-device state. `free` and the new `copy_device_to_device`
select/validate the owning device instead of relying on whatever device happens
to be current. Existing single-device behavior is unchanged: derived buffers built
directly by callers stay unattributed (`device is None`) and take the old path.

## Changes

- `hipengine/core/hip.py`: `HipUuid`, `HipDeviceInfo`, `format_hip_uuid`,
  `device_count`, `set_device`, `get_device`, `device_get_name`,
  `device_get_uuid[_bytes]`, `device_info`, `device_can_access_peer`,
  `device_enable_peer_access`, `device_disable_peer_access`, `memcpy_peer`, plus
  `_configure` argtypes/restypes for every new entry point.
- `hipengine/core/device.py`: `Device.parse`, `scoped_current_device` context
  manager (restores the previous device on success and on exception).
- `hipengine/core/memory.py`: optional `DeviceBuffer.device`; `malloc(device=...)`;
  device-selecting `free`; `copy_device_to_device` with attribution/cross-device
  refusal; arena device tagging. Unattributed legacy buffers keep the previous
  current-device semantics.
- `hipengine/core/__init__.py`: export the new device helpers.
- `tests/test_unit_core_device_ownership.py`: 15 CPU-only tests over a fake
  runtime covering UUID formatting, device parsing, scope restore, allocation
  attribution/selection, free selection, copy validation, and arena tagging.
