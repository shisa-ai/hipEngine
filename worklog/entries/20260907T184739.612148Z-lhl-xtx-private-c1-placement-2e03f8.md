# Cut GPU1 DMS C1 peak by routing the probe off the shared runner

## Summary

Memory review target 2, implemented and measured. Single-session (C1) DMS
probe cycles no longer construct a shared `Qwen35GGUFFullStackRunner`; the
resident session owns its runner, so the existing private-C1 placement
policies engage instead of the shared-runner fallbacks. Multi-session cycles
keep exactly one shared runner (unchanged multi-row device placement).

At the 73,728-token C1 INT8 capacity point on GPU1 (RX 7900 XTX), versus the
same-source baseline recorded earlier today:

- token embedding placement: device (`shared_runner_device_fallback`) →
  host (`mapped_host_private_c1_auto`)
- selective small-weight arena: disabled (`shared_runner_fallback`) →
  enabled (`packed_small_weights:897:...`)
- tracked peak: 23.186015 → 22.520570 GiB (**−681.4 MiB**, matching the
  predicted ~682 MiB compressed-embedding size)
- sampled whole-card peak delta: 23.948845 → 22.930042 GiB (**−1043.3 MiB**;
  the extra ~362 MiB beyond tracked comes from placement/arena effects on
  physical allocation)
- sampled headroom: 9.6 → 1052.9 MiB
- probe wall: 268.5 → 265.9 s (no regression at this shape)
- clean drain to zero tracked bytes, returns to card baseline

Arithmetic is unchanged: all eight decode rows are token- and
logits-sha-exact versus the device-placement baseline run (same prompt
identity, same model/metadata/manifest hashes). A C>1 control (sessions=2,
8192 tokens, two refill cycles) is 32/32 decode rows bit-exact between the
old-code and new-code probe scripts at identical arguments, with the
shared-runner device wiring labels intact.

## Changes

- `scripts/qwen38_dms_concurrency_probe.py`: construct the runner only when
  `len(prompts) > 1`; each cycle record gains a `runner_wiring` block
  labeling shared/owned runner, token-embedding placement and reason, and
  small-weight-arena enablement and reason; conditional `runner.close()`.
  Module docstring updated.
- `tests/test_dms_concurrency_runner_wiring.py`: RED-first wiring tests
  (single session private, multi-session shared exactly one runner,
  labeling keys present).
- `benchmarks/results/2026-09-07-rx7900xtx-dms-int8-private-c1-placement-72k.json`
  published with validation, before/after wiring, savings, equality
  evidence and limitations.

## Validation

- RED confirmed before the change (all three new tests failed on the old
  wiring), GREEN after; existing oracle tests pass
  (`tests/test_dms_concurrency_oracle.py`).
- GPU1 measurement via the whole-card 20 ms sampling wrapper (fresh process,
  idle baseline <128 MiB, unique id cc4d02090dc9c3ff, returns-to-baseline).
  Publish script re-validates status/hashes/identity/decode/drain and both
  equality comparisons before writing the artifact.
- C2 control scripts: `git show ce9320ba7:scripts/qwen38_dms_concurrency_probe.py`
  executed from a scratch path inside the worktree versus the changed probe,
  identical arguments.
- Scope: evaluation-only probe route. No capacity-boundary change claimed
  here (ladder re-measurement follows the remaining review targets); no
  throughput, serving or quality claim. Mapped-host token lookups measured
  no wall regression at this shape but latency sensitivity is unqualified.
