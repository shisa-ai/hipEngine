# Share PARO width-group decode execution

## Summary

Share PARO native/serial width-group execution across compatibility generation,
the persistent resident loop and the retained batch benchmark. Keep policy,
request scheduling and telemetry at their existing owners.

## Changes

- Add `hipengine/runtime/qwen35_paro_decode_groups.py` for ordered group
  execution, complete-cover/metadata checks, result cardinality and native
  capability-miss fallback. It owns no width, sampling or artifact policy.
- Replace three duplicate native/serial execution loops. Preserve exact-hybrid
  and device-resident native options, sparse slots, request/result order and
  before/after deadline checks. Remove the resident loop's redundant private
  serial-group wrapper; sampled per-request execution stays separate.
- Move only remaining policy debt to R0281-PARO-WIDTH. The two environment
  controls have different effects and live callers; no flag/default change.
  Current profile admission rejects names/ranges based on measured evidence.
  Record its required capability-based migration rather than repeating the
  obsolete instruction to keep identity gates permanently.
- Historical G5 ownership context is
  `worklog/entries/20260718T151254.000000Z-legacy-2026-07-18-retain-gfx1151-paro-resident-server-s-249ad6.md`.
  This extraction makes no new native-width, numerical or performance claim.

## Validation

- New executor tests fail before implementation, then pass for sparse slot
  order, native/serial groups, exact-hybrid option isolation, capability-only
  retry, error propagation, deadline boundaries, complete cover, metadata
  lengths, empty input and result cardinality.
- Focused executor, generation, retained partition and live-server-bench unit
  files pass, including exact-hybrid, unsupported widths, sparse rows,
  resident native c2 and sampled serial routes. Default CPU suite, compileall,
  fixture and registry/CPU-fixture/smoke-plan checks pass; logs use
  `/tmp/r0281-paro-groups-`.
- gfx1151 public `LLM.generate_detailed()` on the available packed PARO model
  repeats two greedy requests, reaches the shared executor, preserves slots
  and generated IDs, and returns tracked allocations to zero. The initial
  probe incorrectly required simultaneous `[0, 1]` groups; actual selection
  is serial per slot, and the corrected assertion verifies those real calls.
  The profile reports model-snapshot mismatch, so no native-width claim is
  made. Raw local evidence: `/tmp/r0281-paro-groups-public.json`.
- Documentation and audit checks pass; worklog validation and staged review
  precede commit. gfx1100 and native public c2/c4/c8 remain follow-up work in
  the deferred policy item, not failed kernels.
