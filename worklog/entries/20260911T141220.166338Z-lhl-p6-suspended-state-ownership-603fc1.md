# P6b: suspended-prefill state ownership vs interleaved decode

## Summary

P6a made the compact INT8 prefill yield between scheduler polls, which created
a cross-poll ownership problem: the prefill's live state sat in workspaces that
are *shared*, so interleaved packed decode would overwrite it. Verified rather
than assumed - `_ensure_packed_verify_workspace` (runner line 25919) and
`_ensure_bulk_prefill_workspace` (line 15717) both delegate to
`_resident_batch_owner`, so in a resident batch every session view shares one
packed verify workspace (linear conv/recurrent state) and one bulk prefill
workspace (hidden planes A/B, token buffer).

The naive fix - forbidding packed decode while a prefill is suspended - would
defeat P6's purpose, since the yield exists precisely so decode can run between
polls. The chosen fix copies the suspended state into dedicated buffers at each
segment boundary and copies it back on resume, leaving the shared workspace free
for decode. Cost is one extra hidden-plane and linear-state copy per suspended
prefill; the copy is ~0.1 ms at 2 TB/s and the resident memory is now visible in
the existing prefill-transient telemetry.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`
  - `_GGUFResumablePrefillScratch`: allocates two hidden-plane buffers plus one
    conv and one recurrent buffer per linear layer, with all-or-nothing cleanup
    on a partial allocation failure. `save`/`restore` do the D2D copies (device
    synchronize after `save`, because the next work item may run on another
    stream). `release()` is idempotent and clears the owning session's telemetry
    pointer; `nbytes`/`buffers` expose the owner for accounting.
  - `_GGUFResumablePrefillState.scratch` holds the buffers across the
    suspension; allocated lazily on the first yield.
  - The segment executor restores before the layer loop when resuming and saves
    before returning a checkpoint; the completing segment releases.
  - `_prefill_batch_native_layer_outer_segment_guarded` releases on failure, and
    all three segment call sites (first segment, resume, public entry) go
    through it, so a failed segment cannot leak suspended buffers.
- `hipengine/generation/qwen35_gguf.py`
  - `_release_row_resources` frees a suspended row's buffers and clears
    `row.resumable_prefill`, covering cancellation and reclaim.
  - `prefill_transient_owner_inventory` counts the suspended owner in
    `hidden_and_bulk_owner_bytes`, so the extra resident memory shows up in the
    same domain as the other prefill transients (P2 accounting obligation).
- `tests/test_gguf_resumable_layer_outer_prefill.py`: 6 new tests (19 total).
