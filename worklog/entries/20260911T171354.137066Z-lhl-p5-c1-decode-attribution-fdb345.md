# P5 C1 decode attribution: named 16.2 ms/step synchronous readback

## Summary

Roadmap P5 asks for the C1 decode boundary to be attributed across kernel-family,
HIP API, queue-gap, D2H/H2D, telemetry, and host CPU, with graph capture cost and
its amortization stated explicitly. That deliverable was genuinely missing: the
kernel-family artifact is a 1,500-row *prefill* trace and the HIP-API gap artifact
is a c8/specdec route, so neither covers C1 decode on the shipping INT8-KV route.

`scripts/gguf_c1_decode_attribution.py` now closes it. The child runs the raw
resident session (the ladder's R0 arm), prefills, discards warmup, and wraps each
measured decode step in a ROCTx range; `rocprofv3` traces kernels, markers, HIP
runtime calls, and memory copies; the reduction clips every interval to the
measured windows so model load, prefill, and warmup are excluded from every total.

The headline result is a named host stall, not a kernel problem. **44% of the C1
decode step wall (16.24 ms of 36.6 ms) is one synchronous 8-byte D2H readback** at
`qwen35_gguf_runner.py:29221 _read_sample`, which blocks until the decode step's
GPU work drains. The code's own comment says the copy *is* the completion boundary,
so the time is queue drain rather than transfer — confirmed independently by
pairing each `hipMemcpy` with its memory-copy row by correlation id (median API
2.134 ms against median transfer 0.665 ms; up to 208.026 ms of API for a
sub-millisecond copy).

## Changes

- `scripts/gguf_c1_decode_attribution.py` (new). Child mode runs the R0 session
  with per-step ROCTx markers and instruments `runtime.memcpy` to attribute
  synchronous stalls to their Python call site. Parent mode drives `rocprofv3`
  (`--kernel-trace --marker-trace --hip-runtime-trace --memory-copy-trace`) and
  reduces the four CSVs. `--trace-dir` re-parses without a GPU run.
- `tests/test_gguf_c1_decode_attribution.py` (new, 30 tests). Pins kernel
  classification, all four CSV readers, the interval union, window clipping, the
  two balance identities, family shares summing to 100%, the overlap ratio, the
  call-site block, and the API-versus-transfer comparison.
- `benchmarks/results/2026-09-11-w7900-p5-c1-decode-attribution.json` (new).
- `benchmarks/CHANGELOG.md`, `benchmarks/HARNESSES.md` (rollup + catalog).

Three problems were found and fixed during the work rather than shipped:

1. **The first trace had no marker CSV at all.** A `libroctx64.so` from the default
   search path is not the library `rocprofv3` instruments, so the run produced
   kernel and API traces but no marker trace. The generator now symlinks the
   rocprofiler-sdk ROCTX library onto a private `LD_LIBRARY_PATH` prefix (the
   approach `gguf_decode_rocprof.py` already used), records the resolved library in
   the artifact, and fails loudly if the observed window set is not exactly
   `0..decode_tokens-2`.
2. **The first decomposition was wrong and looked fine.** It claimed
   `window = device_union + api_union + residual`, but host API time overlaps
   device time, so the residual came out *negative* (-1.7%) while `balances` still
   reported `True` — the residual was a plug, so the identity could not fail. The
   model is now `window = union(device, api) + residual` with `residual >= 0`
   asserted, plus a separately asserted GPU-idle split
   `api_while_idle + residual = gpu_idle`.
3. **Per-family shares exceeded 100%.** Dispatch intervals on this route overlap
   (sum/union = 1.83), so a share of the device union is meaningless. Shares are
   now of total kernel time (summing to 100%) with the overlap ratio disclosed,
   and intervals are clipped to windows rather than merely overlap-tested, which
   was the other way a total could exceed the measured span.

## Validation

- `uv run pytest tests/test_gguf_c1_decode_attribution.py -q` — 30 passed.
- Single-source profiled run on the declared hardware (W7900 / gfx1100,
  `rocprofv3` 1.3.2), cache-only with `HIPENGINE_REQUIRE_CACHED_BUILD=1` and a
  pinned `HIPENGINE_COMPILER_VERSION_FILE`, 62 steps at 2048 prompt rows:
  measured span 2,269.5 ms (36.605 ms/step; child median 36.478 ms), device union
  1,075.5 ms (47.4%), HIP API union 1,213.5 ms (53.5%, 902 ms overlapping device),
  residual 872.9 ms (38.46%), both balance identities hold, 49,163 in-window
  kernel dispatches (793/step) and 99,200 HIP API calls (1,600/step).
- Kernel families (share of kernel time): Q4 rowtile 61.64%, Q6 rowtile 22.56%,
  paged decode 6.66%, other 6.00%, GDN 3.08%, rocclr copy 0.03%, sampler 0.03%.
- Call-site stall: `_read_sample` 62 calls / 1,007.2 ms (median 16.24 ms),
  `_copy_token_embeddings_to_device` 62 calls / 3.2 ms (median 51.3 us).
- The artifact sets `performance_claim: false`; no metric row changed. Per the
  README's own classification an attribution diagnostic stays in its artifact and
  changelog rather than taking a scoreboard row.

Honest limits, recorded in the artifact rather than glossed:

- Copy byte counts are unavailable. `rocprofv3`'s memory-copy and HIP API traces
  record direction and duration but no transfer size, so copies are reported by
  direction, count, and time. This trace recorded only H2D rows, so the D2H
  direction of the in-window readback is inferred from the code, not the trace.
- The `_read_sample` time is *not* claimed to be removable. It waits for GPU work
  that happens anyway; what it establishes is that the step is host-bound and
  serialized, so the host cannot prepare the next step while the GPU runs. Whether
  deferring the readback hides that time is an unmeasured hypothesis.
- Telemetry cost is inside the residual, not separately measured; the residual is
  reported as unaccounted time rather than attributed to a guessed cause.
- The route is eager, so no graph capture cost is inside the windows. The artifact
  states the amortization rule and cross-references the c8 packet's 0.186 s capture
  as a different route and width rather than reusing it as a C1 figure.

## Next

- Deferring `_read_sample` to overlap the next step's enqueue is the obvious
  follow-up and is unmeasured; it needs a correctness gate, not just a wall-clock
  win, because the readback currently doubles as the completion boundary.
- Batched prefill attribution remains IKV-C3-blocked, and per-request latency at
  C>N is measured but not published as a topline figure.
