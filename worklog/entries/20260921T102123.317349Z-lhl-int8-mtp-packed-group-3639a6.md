# Packed INT8 MTP verify at c=N: bind the retained INT8 planes in the packed target verifier

## Summary

A speculative INT8 request group (`c>1`) now speculates instead of falling back to
autoregressive. Task #1 root-caused the gap to route selection and pinned it with a
RED contract test; this unit lands the route.

The packed target verifier's full-attention layers now bind the retained INT8 payload
planes and their per-token-head scale metadata, so the same row-bulk pass that BF16
uses attends through the retained-decode split-K leaf. Two gates in front of it are
opened in the same unit: multi-session packed direct INT8 prefill, and the model
declaration that refused every realized group above one row.

`verify_target_blocks_batch` had no BF16-specific machinery beyond its two storage
guards — its attention work is delegated to
`_run_full_attention_decode_batch_layer_rows`, which already implements a direct INT8
branch. What was missing was the binding: `retained_decode_kernel`, the retained
payload/scale caches, and a row-sized split-K workspace.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`, `verify_target_blocks_batch`:
  - The storage guard admits `{BF16, INT8_PER_TOKEN_HEAD}` instead of BF16 only
    (runner-level and per-job).
  - Resolves `_packed_ar_direct_decode_kernel_for_sessions` once for the group and
    fails closed with a named capability miss
    (`packed target verifier requires a shared direct INT8 decode leaf at this group
    width`) when the group has no shared direct INT8 leaf. A width the artifact does
    not qualify for is a capability miss, not a silent downgrade.
  - Binds `retained_decode_kernel` on the packed scratch and builds each
    full-attention layer through `_packed_full_attention_scratch_for_layer`, which
    sets the retained payload caches, the INT8 `retained_append_spans` /
    `retained_decode_spans` with scale metadata, and `int8_kv_value_bf16`. For a
    BF16 layer that helper returns the same cache-backed scratch the verifier used
    before, so the BF16 route is unchanged.
  - Allocates `_ensure_packed_ar_attention_workspace` for the group and passes it as
    `split_workspace`, which the direct INT8 branch requires.
- `hipengine/runtime/qwen35_gguf_runner.py`, `_packed_ar_kv_layout_for_sessions`:
  prefill and decode are still distinct work classes, but they write the same packed
  physical cell, so both are bounded by the artifact-qualified direct INT8 width.
  Multi-session packed INT8 prefill no longer collapses to one row.
- `hipengine/models/qwen35.py`: adds `gguf_dense_int8_gfx1151_group_native_chain` and
  `gguf_dense_int8_gfx1100_group_native_chain`, both `max_group_rows=4`, and changes
  the C1 chain's rejection reason from `packed_int8_mtp_not_implemented` to
  `dense_group_above_offered_width`. The INT8 bound is the KV capability's qualified
  direct width (`max_direct_rows=4` on both backends), **not** the backend cell table
  the BF16 split follows — gfx1100 offers 8 cells but qualifies direct INT8 to c4.
- `tests/test_unit_int8_mtp_serving.py`: the contract test loses its
  `xfail(strict=True)` marker (it now passes) and the over-width case moves to
  `realized_group_rows=5 -> dense_group_above_offered_width`.
- `scripts/int8_mtp_server_lifecycle_gate.py`: `n: 2` with `speculative_mtp: true`
  asserted a 501 `packed_int8_mtp_not_implemented`. That request now runs, so the
  check asserts two choices, non-zero cycles on both, and ids equal to the baseline.
- `tests/test_integration_server_api.py`: the mocked unimplemented-MTP plan used the
  now-dead `packed_int8_mtp_not_implemented` reason at `realized_group_rows=2`, which
  is an admitted cell. It now mocks an over-width group.
- `tests/test_unit_gguf_packed_verify_layout.py`: the packed AR layout test asserted
  that a two-session direct INT8 *prefill* raises `single-row prefill`, which is the
  contract the prefill gate above replaces. It now asserts a two-session prefill is
  admitted at the default qualified width, that `physical_rows=9` is refused against
  the default limit of 8, and that `physical_rows=5` is refused against a limit of 4
  (both sides of the threshold, at two different limits).
- `tests/test_unit_llm_mtp_eligibility.py`: the mocked unsupported-contract case used
  the now-dead reason; it now uses `dense_group_above_offered_width`.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: the checklist item and the open-items
  paragraph move physical packed INT8 MTP out of "not implemented".

### Capability boundary, measured

The packed direct-INT8 route is admitted only for an artifact whose compact-INT8
capability is *admitted*: `_admitted_no_mirror_int8_capability` requires
`runtime_action == "admit"` and `max_direct_rows >= 1`. The gfx1151 artifact
(17,106,775,008 bytes, sha `7e78da5d…`) carries a recorded compact-INT8 quality
rejection with `max_direct_rows=0`, so on that artifact the group now reports the named
capability miss and keeps its autoregressive route. Setting
`HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1` forces INT8 *storage* but moves
`runtime_action` off `admit`, so it does not open the packed route either. That is the
documented diagnostic path, and a rejected artifact is a legal refusal.

### One unexplained observation

The first full lifecycle-gate run failed the `n: 2` ids comparison; the second passed
with the same production code (only the assertion's failure message changed). Eleven
subsequent focused rounds — including five replaying that gate's exact request order —
were clean, and no stale server or port conflict was present. The comparison is
therefore recorded as passing with a single unreproduced mismatch, not as proven
deterministic. If it recurs, capture `generated_token_ids` for both the baseline and
the multi-choice rows and diff them at the first divergence.
