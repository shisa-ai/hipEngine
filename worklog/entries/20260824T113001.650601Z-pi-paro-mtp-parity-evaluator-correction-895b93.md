# Correct PARO parity evaluator isolation

## Summary

The first parity entry correctly blocked promotion but misattributed two failures to hipEngine. Running native hipEngine kernels under the system therock/Python environment (chosen only because it contains torch) corrupted target and proposer argmax readback. A two-process evaluator corrects this: native capture runs under project `uv`; CPU/torch reference runs separately from an NPZ capture.

## Changes

- Added native-capture-only mode to `scripts/mtp_paro_proposal_parity.py`.
- Added `scripts/mtp_paro_proposal_reference.py` for CPU/torch comparison without loading the hipEngine HIP runtime in that process.
- Extended fused W8 testing to the real `(rows=1, hidden=2048, vocab=248320, threads=128)` shape.
- Corrected the parity artifact to schema v2. The original immutable worklog remains as historical failed-evaluator context and is superseded by this entry.

## Validation

Project-uv native raw heldout capture:

- target root `271` valid;
- initial, repeated, and fresh-scratch fused W8 top-1 all `71093`;
- materialized native W8 top-1 also `71093`.

Independent CPU/torch reference:

- top-1 equal (`71093`);
- top-8 differs only at rank 8: native `248068`, reference `2`;
- hidden max/mean abs remains `0.09375/0.00726033`, so provider parity still fails and promotion remains blocked.

Full-vocabulary fused-vs-unfused kernel test at 128 threads passed bit-exact. The borrowed scorer and uv-native target sampler are therefore cleared; stage-level proposal hidden parity is the remaining blocker.
