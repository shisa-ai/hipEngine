# Qwen3.8 B3 blocks on physical lane ownership split

## Summary

B3 is blocked after all resource/state prerequisites passed. The existing
physical batch executor equates physical lanes with public scheduler requests;
it cannot represent a compute-only shadow without fabricating public ownership.
Current C1 remains selected and no performance claim is retained.

## Blocker

`_execute_target_frontier_batch` indexes plan IDs into adapter state and
`owner._row`, then carries every lane through target batch IDs, GPU accept,
selected-state commit, telemetry, cancellation, and generated output. B3 needs
a second physical lane with compute=true but publish/commit=false. A synthetic
negative request row would violate exact ownership.

The required refactor separates physical lanes from public request IDs and
carries compute/publish/commit masks end-to-end. Exact source surfaces and
prerequisites are in
`benchmarks/results/2026-09-02-gfx1151-qwen38-b3-m1-physical-lane-blocker.json`.
