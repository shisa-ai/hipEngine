# The bulk prefill's gate failure is real, not a stale reference

## Summary

The device-reduction change is bit-identical to the staged route, so the bulk
prefill's failure of the production KL gate is unrelated to it. Before treating
that failure as a genuine defect, one hypothesis had to be eliminated: the
single-card harness can silently resolve `use_wmma_prefill` **off** while the TP2
bulk route runs WMMA, and the reference was a day old. If the reference had been
captured on a different dispatch, the gate would have been comparing two
different arithmetic routes and the "failure" would have been an artifact.

**The hypothesis is ruled out.** Re-capturing the reference on the current clean
revision reproduces the candidate's metrics to full float precision:

| prompt | mean_kl | p99_kl | max_kl | top-1 |
| --- | ---: | ---: | ---: | ---: |
| `mixed_ja_en_translate` | 0.002557612045921964 | 0.09134977608861948 | 0.16705312926134894 | 1.0 |
| `heldout_mixed_summary` | 0.0024068130614897268 | 0.01873827367731936 | 0.26077550858777865 | 0.984375 |

Every value is identical to the run against the day-old reference, digit for
digit. The new reference records `source_revision 0dced662c` (this HEAD) with an
empty staged diff, so it is the same clean revision, same production profile,
same host and model.

Against the recorded production thresholds (mean 0.001, p95 0.005, p99 0.02,
max 0.05, top-1 0.99) the route fails mean/p99/max on the first prompt and
mean/max plus top-1 on the heldout. Top-1 is perfect on the first prompt.

## Why this matters for the retained optimization

The device reduction landed as a retained performance win while this gate was
already failing. That is the correct call under this repository's rules - the
change is exact (bit-identical logits, not merely close) and non-regressive, and
the blocker is recorded rather than left implicit - but it should be read
honestly: it makes a route that is not yet gate-green 12% faster.

## Where the divergence is

A prior entry localizes it to the **Q6_K `attn_qkv` projection** in the
replicated attention phase (rel 3.73e-03, max_abs 0.25, not bit-equal) with
identical layer input, identical weights and identical zeroed state. That
magnitude is far too large for an accumulation-order difference on a single
projection, which makes a variant or layout difference between the two routes the
leading hypothesis rather than a rounding effect.

The two routes' resolved variants are partly comparable: the TP1 reference's
scope manifest records `c1_full_mlp_variant: dense_dual_local32_bf16_bf16_out`,
and the TP2 resolve log shows the same name for its `linear_pair_silu` leaves, so
the MLP dispatch agrees. The attention projections are where the two logs cannot
be compared yet: the TP2 log shows
`linear gguf_q6_k_t16_qmicro_planar_v1 t16_wmma_prefill_bf16_bf16_out`, and the
reference capture does not record a resolve log.
