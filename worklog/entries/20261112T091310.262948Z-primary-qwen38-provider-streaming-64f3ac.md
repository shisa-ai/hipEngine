# Stream committed feature-drafter tokens through bounded service children

## Summary

EAGLE-4 and DSpine now publish verified tokens incrementally through the service
child lifecycle. Each request leases its own mutable drafter and target state;
completed sequential requests reuse a cached drafter and target session.

## Changes

- Factor shared request ownership and output publication into
  `hipengine/generation/feature_draft.py`. Admission allocates no device state.
  Each advance performs one full prompt prefill or one speculative cycle. Prefill
  is not yet chunked; cancellation cannot interrupt an in-flight prefill/kernel.
- Add incremental cycle iterators; keep the blocking harness functions as
  consumers of those same steps. Preserve proposal, verification and state-commit
  arithmetic. Decode time sums active cycle intervals, excluding service idle
  time between advances; end-to-end time includes those intervals.
- Route committed token/chunk events through the service collector, without
  treating them as compatibility scheduler surrogate tokens. The child owns
  stop-safe text and UTF-8 decoding; the service owns terminal publication and
  validates the complete token history.
- Support multi-token stop sequences, flush incomplete UTF-8 only at terminal,
  and preserve raw generated IDs including suppressed stops. Closing the public
  LLM stream explicitly closes its underlying service iterator.
- On failure/disconnect/deadline/shutdown, close the request's target lease and
  drafter. Free prompt tap buffers even when allocation or prefill raises.
  Interleaved children do not share mutable drafter state. Additional concurrent
  drafters allocate their own device weights; cross-request weight deduplication
  is not part of this change.

## Validation

- RED: the original provider returned whole output on first next(), exposed no
  bounded child, and rejected multi-token stops. The new stream/lifecycle tests
  pass after implementation.
- Focused CPU tests cover lazy admission, one-cycle advancement, early first
  publication through the real service adapter, cancellation, deadline, shutdown,
  allocation/verify failure cleanup, interleaved histories, zero/one/short output
  limits, stop sequences, ignored EOS, UTF-8 pieces and final byte flushing.
  Fake cycles check all-accept/all-reject sequences against a hand-built greedy
  oracle and retain blocking/incremental parity. Existing service, SPECDEC2,
  Laguna provider and request-lifetime integration bundles pass.
- Live public EAGLE/DSpine requests on zbook/Radeon 8060S, `hip_gfx1151`,
  Qwen3.8-27B `Q4_K_M`, English/Japanese prompts and 17 output tokens each pass:
  blocking and streaming IDs equal AR, streamed text equals blocking text, one
  terminal chunk, graph verification and sequential session reuse. A 65-token
  stream abandoned after its first chunk leaves no active service child; the
  following request matches AR. Run the command in
  `20261112T085250.516124Z-primary-qwen38-provider-sessions-0509ac.md` to reproduce
  the expanded live test. No throughput or latency improvement is claimed.
- Documentation, fixtures, test tiers, compileall and CPU smoke modes pass.
  The first combined audit command timed out; a background retry identified the
  fixture-path variables and the bounded-child capability error as new audit
  rows. Verified and triaged those as NOT-DEBT/keep, without raising the budget.
  Final staged audit, worklog and documentation gates pass. The full CPU suite
  (`uv run pytest -q`) passes. After that run, a final scoped cleanup check added
  coverage for target-release failure: the draft must close rather than enter the
  cache when session reset fails. The focused feature-provider bundle passes with
  that repair and the added lifecycle tests.
