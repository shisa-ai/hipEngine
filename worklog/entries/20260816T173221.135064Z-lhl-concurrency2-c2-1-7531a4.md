# Concurrency2 C2-1 EngineService and independent outputs

## Summary

Implemented C2-1 with one dedicated `EngineService` thread as the sole owner of resident submit/poll/take/cancel/shutdown operations. Native resident blocking, SSE, and library calls now submit independent one-prompt children; terminal commit reclaims each child before publishing its isolated result, so a fast request and refill no longer wait for an unrelated long sibling.

## Changes

- Added a bounded service command channel, independently bound blocking/streaming collectors, child handles, parent-to-child splitting, synchronous `generate_detailed()` aggregation, streaming multiplexing, and driver-thread-only control calls.
- Added child-scoped stop-sequence holdback, deadline/disconnect/cancel commands, non-blocking stream backpressure cancellation, terminal error propagation, and active-child shutdown reclaim.
- Added `SubmitPollTextGenerator.abort_submission()` and canonical-token-event disclosure so the service handles native incremental tokens while preserving the explicit non-resident serial bridge.
- Wrapped native resident generators in `EngineService` from `LLM`; non-resident generators remain on the existing compatibility adapter.
- Changed the server batcher to launch production service-backed plain-AR requests independently instead of building static prompt-list model calls. Legacy engines without the capability retain their explicit compatibility grouping path.
- Added a `CHUNK` output event so request-owned collectors can track canonical token ownership separately from stop-safe text publication.
- Marked the C2-1 roadmap checklist complete.
