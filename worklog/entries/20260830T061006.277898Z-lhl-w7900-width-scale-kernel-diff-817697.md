# W7900: instrument for naming per-row decode kernels - width-scale kernel diff with RED coverage

## Summary

Adds the instrument for #14's remaining question, RED-first. The open fact is that decode per-step cost
goes 33.2 ms at width 1 to 50.4 ms at width 2 where a weight-bound batched step should stay near
33 ms, so some decode work is per-row - but which. `scripts/gguf_rocprof_width_scale_diff.py` compares
two `rocprofv3 --kernel-trace` runs taken at different wave widths and classifies every kernel:
`per_row_launches` (launch count scales with rows), `per_row_inside_launch` (launch count flat, each
launch longer), `flat`, or `partial`. No measurement result yet; the trace run is in flight.

## Changes

New `scripts/gguf_rocprof_width_scale_diff.py` and
`tests/test_scripts_gguf_rocprof_width_scale_diff.py` (8 tests, written first and confirmed RED against
the missing module before the implementation existed). It reuses
`gguf_kernel_family_rocprof_summary.load_kernels` by path rather than re-parsing rocprofv3 CSVs, so
there is one trace reader in the tree.

## Validation

Synthetic traces pin the two signatures separately: a kernel whose launches double classifies
`per_row_launches`, one whose launches stay fixed while mean duration doubles classifies
`per_row_inside_launch`, an unchanged kernel classifies `flat`, and the recorded
`expected_scale`/thresholds make the verdict auditable. Refusals are pinned too: non-positive rows, a
narrower candidate than base (so ratios always read as growth), and a missing or CSV-less trace
directory - the last one matters because a silently empty trace is exactly how a vacuous measurement
would arrive. Kernels present in only one arm are listed in `only_in_base` / `only_in_candidate`
instead of being dropped, because an arm that gained a family (for instance an MTP verifier that
engages only at width >= 2) would otherwise be misread as row scaling.

Two flag mistakes found while wiring the runner are worth keeping in mind: the harness refuses
`--expected-mtp-widths` values outside `--widths` but accepts `none`, which asserts "no MTP engaged" at
every measured width and is what makes a pure-AR width comparison possible under
`--mtp-request-mode automatic`; and `rocprofv3 -f` selects the output *format* (`csv`/`json`), not the
file name, which is `-o`.
