# Fix identity-based Flash-Next prefix eviction under pressure

## Summary

The full ordered AR replay reached depth 65536, then failed while preparing the
130925-token prefix for depth 131072. Cache eviction called `list.remove` on a
snapshot dataclass whose generated equality compared NumPy arrays. Removing a
non-first entry tried to broadcast token arrays of lengths 4096 and 8138.
This is an allocation-owner identity bug, not an arithmetic or capacity limit.

## Changes

- Set `PrefixSnapshot` to `@dataclass(eq=False)`: snapshots are mutable
  allocation owners, so list removal must compare object identity. Prompt
  matching and duplicate detection keep their explicit array comparisons.
- Add pressure-eviction regressions for equal lengths, unrelated lengths and
  the exact observed 4096/8138 pair. Refresh the first entry to ensure eviction
  removes the second, then verify surviving lookups, released allocations and
  complete cache cleanup.
- Preserve the failed replay under
  `/tmp/qwen38fn-gufo-20261021/hipengine-ordered-depths/`. Its seven AR rows
  remain diagnostics, not a completed full-depth comparison. The depth 65536
  continuation used the request-owned runner beyond the AR batch pool's 65536
  capacity, as the public route witness records.
