# Retire GGUF KV chunk growth; one stable-address backing

## Summary

Lead decision (2026-11-23): close R0207 by retiring appended-chunk growth
instead of migrating every KV consumer to page-pointer tables. Both target
backends already grow the GGUF global KV pool inside a stable-address HIP VMM
arena (gfx1100 W7900 here: VMM supported, 4 KiB granularity; gfx1151 public run
in `20261024T014146.990093Z-cleanup-qwen-gguf-kv-boundary-05974c.md` allocated
through `_allocate_qwen35_gguf_kv_chunk_vmm`). Chunk confinement only ever
applied to the plain `hipMalloc` fallback. That fallback is now one fixed
backing with no growth provider, so every consumer keeps
`plane_base + page_id * stride` addressing and no allocation can span bases.

## Changes

- `GlobalDeviceKVPool`: one `_backing`; removed `contiguous_growth`, the chunk
  list, `_allocate_within_one_chunk`, `_chunk_for_page`,
  `workspace_backing_for_pages`, `workspace_pages_fit_root_backing` and
  `lease_workspace(within_one_chunk=)`. Growth grows the aggregate free-page
  deficit and adopts the provider's rebuilt root backing. Allocations always
  bind the root backing with `chunk_start_block_id=0`.
- `GlobalKVPoolSet.allocate`: removed `within_page_range`.
- Runner `create_global_device_kv_pool`: non-VMM path allocates one backing and
  passes no grow/shrink/release provider; `max_pages` remains the KV byte
  budget shared with private packed workspaces (pinning it to the initial
  capacity refused `packed_verify_scratch` on every request, found by the
  public probe and fixed before commit). Deleted `grow_storage_chunk`,
  `shrink_storage_chunk`, `release_storage_chunk`.
- `gguf_packed_backing.select_packed_arena_backing`: binds the pool root
  backing with global page ids; no per-chunk rebinding.
- Backed out the unused page-pointer work (cb524b35e, b3a24149f, 9ba169c81,
  3054f042e, 2b9f13002): `*_page_ptrs_spans` write/decode variants, the
  resident `device_kv_page_view`, `request_page_pointers` and
  `page_pointers_for`. No production route reached them. Their worklog
  entries stay as history. 4a3055fa7 (verifier copies resolved by global page)
  is kept; it is correct under one backing.
- `docs/ENVS.md`: `HIPENGINE_KV_POOL_INITIAL_PAGES` is the whole page pool on a
  runtime without HIP VMM. R0207 removed from `docs/REFACTOR.md`.

## Validation

- No-RED rationale: this removes behavior rather than adding it. The old
  chunk-confinement tests went RED against the change and were rewritten to
  assert the new contract: leases span the growth boundary, only the deficit
  grows, a fixed backing refuses growth with "no growth provider", and the
  packed workspace extends eager pages across growth by global id. The
  rewritten tests were not run against the parent.
- R0207 bundle plus adjacent GGUF KV/prefix/packed unit files: 376 passed.
- Full CPU unit tier: 28,998 passed, 115 skipped, 0 failed.
- W7900/gfx1100 `tests/test_gpu_qwen35_paged_kv_head_major.py`: 14 passed
  after the page-pointer kernel back-out.
- Public `hipengine.LLM` probe (Qwen3.6-35B-A3B-UD-Q4_K_M, BF16 KV,
  `max_active_requests=2`, `prefix_cache=radix`, `HIPENGINE_KV_POOL_INITIAL_PAGES=2`):
  short, long, long prefix reuse (5 pages), two-request long batch, stream
  cancellation after 3 chunks, refill, short again. VMM mode grew once
  (16 -> 144 pages) during the batch; forced fixed `hipMalloc` mode
  (`virtual_memory_supported -> False`) stayed at 16 pages, recorded one refused
  growth, and served every step. All 7 outputs were byte-identical across the

  `int8_per_token_head`: all 7 steps byte-identical across VMM and fixed modes;
  VMM grew 16 -> 144 pages, fixed stayed at 16 with one refused growth; prefix
