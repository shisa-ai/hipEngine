# Trace physical MTP proposal and target rows

## Summary

P8 needs to distinguish proposal drift, target drift, and accept-kernel errors
for duplicated physical C2 requests. Existing
`HIPENGINE_SPECDEC2_DEVICE_CHAIN_ORACLE=1` materializes candidates only after
target execution and verifies GPU/CPU accept parity, but discarded the bounded
per-request candidate/target vectors after the check. Add diagnostic-only
telemetry at that existing oracle boundary; the default device chain remains
unchanged and performs no new readback.

## Changes

- Add `_device_chain_oracle_trace_rows()` to render cycle/request/root,
  request-major candidate IDs, target top-1 path, accepted IDs/count, and next
  token from the already-materialized CPU oracle data.
- Append at most 64 records/request to resident-row telemetry only while the
  existing qualification oracle is enabled.
- Expose the bounded trace as
  `specdec2_mtp2_device_chain_oracle_trace`; default production rows emit an
  empty list.
- Add a pure RED/GREEN fixture covering two requests with ragged K2/K1 target
  rows and request-local ordering.
