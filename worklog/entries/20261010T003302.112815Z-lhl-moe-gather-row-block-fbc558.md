# Row-block form for the MoE packed-hidden gather

## Summary

`qwen35_moe_gather_packed_hidden_kernel` was 4.4% of W7900 Gemma 4 prefill
kernel time at 8192 tokens (480 us a call for 8192 x 2816 BF16 elements, about
96 GB/s): one thread per element, an int64 divide per element, and 2-byte
global stores. The launcher now picks a row-block kernel when the row width is
a whole number of 128-bit spans and both buffers are 16-byte aligned: one block
per packed row, eight elements per thread per move, and the lane lookup and
divide once per row. Other shapes keep the element kernel. Both are copies, so
the output bytes are unchanged.

Measured on AMD Radeon Pro W7900, Gemma 4 26B-A4B `UD-Q4_K_XL`, production,
BF16 KV, 128 outputs, one warmup and three samples,
`scripts/gemma4_campaign_bench.py`, before and after on the same tree:
prefill 3164.7 -> 3242.3 tok/s at 512, 2936.1 -> 2986.2 at 8192 and
2335.8 -> 2364.6 at 32768 (1.025x, 1.017x, 1.012x). Decode is level, public
generated ids are equal, and `public_path_parity` is true on all rows. The
512 gain is inside what one three-sample run can resolve; the direction is the
same at all three lengths.

## Changes

- `hipengine/kernels/hip_gfx1100/moe/group_scatter.hip`:
  `qwen35_moe_gather_packed_hidden_rows_kernel` and the shape/alignment
  predicate in `hipengine_qwen35_moe_gather_packed_hidden_lowp`. No Python,
  registry or flag change; the element kernel is the fallback inside the same
  entry point.
- `tests/test_gpu_qwen35_moe_gather_rows.py`: byte equality with a host gather
  for six row-form shapes and two element-form shapes (an unaligned width and
  an unaligned base), with dead lanes, out-of-range tokens and guard words on
  both sides of the written range.
