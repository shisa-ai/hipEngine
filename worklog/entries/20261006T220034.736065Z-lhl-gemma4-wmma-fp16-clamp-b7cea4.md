# Clamp FP16 staging against masked out-of-range V

## Summary

The static review of the 2026-10-03 localization flagged one unverified edge
case, and this unit proves it real and fixes it: the sliding WMMA kernel
stages V for every key of a batch -- including keys the keep-mask hides --
and converts BF16 to FP16 with a plain cast, so a masked V with magnitude
beyond FP16's 65504 range stages infinity, and a masked key's exactly-zero
weight still multiplies it as `0 * inf = NaN` in the tensor core, poisoning
the whole accumulator. The strict kernel never touches masked keys and stays
finite. The full-attention WMMA variant uses native BF16 operands and has no
exposure.

RED/GREEN on the real kernel: a new GPU test hides one column from every row,
puts a BF16-representable 1e30 in it, and compares against strict. Without
the clamp the candidate's visible rows go NaN (1 failed, reproduced); with it
they are finite and match strict within the file's declared tolerance
(21 passed). The fix clamps the staged operand to FP16's range in
`bf16x8_to_half8`; every in-range value is bit-identical to before, so only
values that previously became infinities change.

Also fixed: `test_the_production_profile_routes_both_geometries_to_their_own_candidate`
in `tests/test_gpu_gemma4_attention_prefill_wmma_full.py` still asserted the
pre-demotion production default (WMMA candidates) and has been failing on
committed HEAD; it now asserts the current staged default, with a comment
naming the calibration campaign as where the flip will be felt first.
