# Read backend declarations through explicit policy-module re-exports

## Summary

RF-8 (`a84e0fbe6`) moved the gfx1151 capability and GGUF policy data into
`policy_capability.py`, `policy_gguf.py`, and `policy_laguna.py` and re-exported
every moved name from the package initializer as an explicit
`NAME = _policy_x.NAME` assignment. Both cold source readers only accepted a
literal expression in `hipengine/kernels/<backend>/__init__.py`, so every
gfx1151 capability now read as `nonliteral` and `GGUF_CONSUMER_LAYERS` read as
empty. Consequences: seven nodes in
`tests/test_unit_scripts_gguf_quant_route_audit.py` failed (capability status,
flag resolution, Q5 raw-MMQ sidecar, Q6 planar exclusion), and public GGUF
construction refused gfx1151 with 2549 `consumer_unqualified` slots
(`declared GGUF consumer layers: []`) in `/tmp/rf6-public-graph.json`.

## Changes

- Added `hipengine/loading/backend_source_literals.py`, one shared bounded
  reader used by both cold paths. It resolves, without importing the backend
  package and without evaluating arbitrary code: literals and annotated
  assignments, the existing `frozenset`/`set`/`tuple`/`list` wrapper forms
  (including the empty call), ordered local literal aliases, and explicit
  same-package import aliases/re-exports (absolute
  `from hipengine.kernels.<backend> import policy_x as _policy_x`, relative
  `from . import policy_x` / `from .policy_x import NAME as NAME`, and
  `import hipengine.kernels.<backend>.policy_x as _policy_x`).
- Unreadable stays unreadable, never guessed: import cycles (including a
  self re-export), module aliases bound outside the backend package, missing or
  unparseable modules, non-identifier backend/module paths (no path escape),
  arbitrary calls and expressions all report `nonliteral`. Only module-level
  statements are read, so a declaration inside a conditional or `try` block is
  absent. A missing package reads as `{}`.
- Follow-up contract fixes in the same reader (RED fixtures first):
  every import binding is a module-level name, so a direct re-export
  `from .policy import VALUE as VALUE` appears in the returned mapping (and a
  module-object binding appears as `nonliteral`); imports rebind their local
  name in source order even when rejected as external, so an earlier literal or
  same-package module alias never survives `from os import sep as VALUE` or
  `import os as _policy_x`; malformed wrapper arguments (`frozenset(1)`,
  `set({[]})`, `tuple(1)`) and a shadowed wrapper name
  (`frozenset = build_wrapper()`) are `nonliteral` instead of raising or
  certifying a literal; and a top-level method call (`NAMES.append(...)`) or
  subscript assignment (`NAMES[0][0] = ...`) invalidates the earlier container
  literal. A call on a same-package module alias does not rebind it.
- `hipengine/loading/qwen35_gguf_consumer_surface.py`: replaced the local
  literal-only reader (`_literal_value`, `_iter_module_assignments`,
  `_backend_source_path`) with the shared reader. `backend_gguf_consumer_layers`
  now reads the requested package directly (unknown keys still read as none),
  and both declaration readers take an optional keyword-only `root` so fixtures
  can exercise the alias contract.
- `scripts/gguf_quant_route_audit.py`: replaced its copy of the literal reader
  with the shared reader; `backend_source_assignments` keeps its
  `{name: (value, status)}` shape and now also returns `{}` for a missing
  package instead of raising `FileNotFoundError`.
- No policy literal was duplicated, no default or admission rule changed, no
  backend/model identity is special-cased, and no backend package or torch
  import was added.
- Tests: added `tests/test_unit_gguf_backend_source_literals.py` (literal and
  wrapper forms, absolute/relative import alias chains, ordered local aliases
  and rebinding, import and self cycles, external imports, missing modules,
  arbitrary calls, syntax errors, path escapes, live gfx1100/gfx1151
  declarations, consumer-surface fixture roots, and a subprocess cold contract
  that forbids every `hipengine.kernels.hip_*` / `cuda_*` / torch import).
  Added `test_source_capability_reader_follows_same_package_alias_chain` to the
  audit test file.
