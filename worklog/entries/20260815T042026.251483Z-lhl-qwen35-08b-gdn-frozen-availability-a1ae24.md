# Close GDN frozen-mode availability gap

## Summary

Second-opinion review of `5668bf0de` confirmed the session-scratch freeze and
quant-shape-aware auto fallback, then found one fail-closed regression: exact or
explicit modes were frozen without availability validation, while production
dispatch replaced the original request with `"frozen"` and therefore skipped
its request-keyed unavailable-route checks. A session could reach a null or
incomplete route instead of rejecting construction.

## Changes

- `_gguf_gdn_prefill_session_mode()` now resolves the requested route first,
  validates auto/exact/explicit modes against the supplied or backend plan, and
  raises before scratch construction for unavailable exact/explicit routes.
- Auto retains the established fused-then-chain fallback. A backend whose plan
  cannot be validated (`ValueError`) still preserves its pre-fallback selection.
- Removed a duplicate test definition that caused pytest to collect only one of
  two identically named diagnostic-alternation tests.
- Added RED/GREEN exact and explicit unavailable-route resolver cases, proving
  an invalid mode cannot become a production scratch's frozen owner.

## Validation

- RED: both new resolver cases failed because no `RuntimeError` was raised.
- GREEN: `uv run pytest -q tests/test_qwen35_gguf_gdn_session_mode.py
  tests/test_qwen35_gguf_gdn_prefill_routing.py` — 64 passed.
- Focused bundle: session-mode, GDN routing, prefill scratch liveness, and
  gfx1151 backend tests — 127 passed.
- One attempted bundle named nonexistent `tests/test_gfx1100_backend.py` and
  stopped before collection; the corrected focused bundle above is the evidence.
