# Map packed Inkling GGUF weights and visit state

## Summary

Added a header-driven map for the legacy Loom `inkling2` and mainline `inkling2_loop` layouts. Repeated visits share physical weights and expert scales but have independent state slots. This is the loader and CPU projection oracle, not a public execution route.

## Changes

- Validate declared vocabulary and padded head geometry, per-layer attention, short convolution, routed banks, and loop message and controller tensors. Legacy metadata is indexed in visit order; mainline metadata is indexed by physical layer. Both use the shared Inkling visit plan.
- Map loop message queries to Q, K, V, FFN order. Read packed bytes lazily and decode only the selected expert rows; apply the physical bank's optional F32 scale after projection. No weights are uploaded or expanded by header inspection.
- Checked the format against the pinned Vulkan fork's legacy `src/models/inkling2.cpp` at `99da9b14be5093199f0d19d4813bb3948fab8332` and mainline `src/models/inkling2-loop.cpp` and `src/llama-model.cpp` at `e50c254a22c590c9d2a60db86690d48d42497e2b`. No external code copied.

## Validation

- The new unit suite first failed on the missing loader. `OPENBLAS_NUM_THREADS=1 .venv/bin/python -m pytest -q tests/test_unit_inkling2_gguf.py tests/test_unit_inkling2_mini.py tests/test_unit_gguf_quant_layout.py` passed after implementation.
- The full CPU deterministic bundle also passed: compileall, default pytest, fixture verification, registry/CPU-fixture/build-plan smokes, and a torch-import check on the changed modules.
- Constructed `Inkling2GGUFWeights(GGUFReader(path))` against the [lockfile-verified Loom target](20261121T170419.285290Z-lhl-inkling2-mini-780776.md) on `strixhalo` and the [pinned mainline file](20261121T153001.919971Z-lhl-inkling2-mini-4c8219.md) on `epyc`. Both resolve 24 physical layers, 48 visits and 200,058 model vocabulary rows. Physical layer 6 uses legacy slots 6/18/30 and mainline slots 6/24/36; repeated visits read the expected four query rows from their respective layouts.
- On the mainline file, used the exported `dequantize_row_nvfp4`, `dequantize_row_q5_K` and `dequantize_row_q8_0` from `libggml-base.so` at `e50c254a22c590c9d2a60db86690d48d42497e2b`. For visits 2/6/18/30/44, expert 3, rows 5–8 of both expert projections, NumPy array equality passed for decoded rows and for slice projections with the matching physical scale (FP32 inputs from NumPy seed 569). This checks 32 NVFP4 rows and four each of Q5_K and Q8_0, counting repeated visits; it is not whole-model parity.
