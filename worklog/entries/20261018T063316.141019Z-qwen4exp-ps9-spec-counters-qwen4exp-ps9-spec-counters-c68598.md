# Audit speculative counters against the cycles that ran

## Summary

The speculative counters are consistent with the work the backend actually did,
and a response that claims speculative usage always names the provider that
produced it. 39 live checks over five requests, zero failures.

| request | used | route | draft | accepted | rejected | rate | cycles | provider |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| mtp | true | `speculative_mtp` | 54 | 20 | 34 | 0.370 | 19 | `qwen4_exp_mtp` |
| mtp | true | `speculative_mtp` | 36 | 25 | 11 | 0.694 | 12 | `qwen4_exp_mtp` |
| mtp | true | `speculative_mtp` | 47 | 23 | 24 | 0.489 | 16 | `qwen4_exp_mtp` |
| plain | false | `default` | 0 | 0 | 0 | null | 0 | none |
| plain | false | `default` | 0 | 0 | 0 | null | 0 | none |

Each row's `draft_tokens` equals the candidate count summed over its own
`diagnostics.cycles`, `accepted_draft_tokens` equals the summed per-cycle
`accepted`, `rejected = draft - accepted`, `acceptance_rate` is that ratio, and
`usage.completion_tokens_details.{accepted,rejected}_prediction_tokens` equals
the summary. No `used:true` response lacked a provider.

One expectation I wrote was wrong, not the server: I first asserted that a plain
request carries no `hipengine.speculative_mtp` block. It does carry one, with
`used=false`, `effective_route="default"` and zero counts. That is truthful and
the documented usage contract already says non-MTP requests omit only the
`completion_tokens_details` prediction fields, which they do. The check now
asserts the no-usage claim instead of omission, and the API contract states the
behaviour explicitly so a client does not have to infer it.
