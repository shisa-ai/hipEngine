# c8 iter44 planar-Q6 head rowtile dispatch route

## Summary

Full-vocab planar-Q6 head launches at rows 2-8 (proposal batch top-1 and
accept-commit sampling) resolved the per-row decode kernel, which re-reads the
1042.9 MB head tile set once per row (grid_y = rows): 11.8-14.1 ms per launch
at ~88 GB/s on the W7900, ~3 launches/cycle in the C8/K3 MTP cycle
(rocprofv3 kernel+marker trace of the current-profile run: 2 launches inside
`specdec2_mtp2_proposal`, 1 inside `target_accept_commit_provider`). The
registered planar rowtile leaf reads each tile once for all rows and is
bit-identical to the decode kernel, but nothing routed rows 2-8 to it through
`launch_gguf_linear` (`_variant_for_rows` returns the decode variant unchanged
for the `t16_` family; the session-gated `_native_batch_decode_dispatch`
handles only bf16-out and never fires on the proposal path).

Fix: `_q6_planar_rowtile_dispatch` pipeline step in `launch_gguf_linear`
(before `_wmma_prefill_dispatch`, so an explicit `use_wmma_prefill=True` keeps
WMMA precedence). Routes planar-Q6 rows 2-8 decode leaves to
`t16_gemv_rowtile_bf16_f32_out` / `t16_gemv_rowtile_bf16_bf16_out` when
registered; rows 1 and >8 unchanged.

L1 leaf screen (real head shape 5120x248320, rows=8, HIP events, 3
alternating rounds): decode best 11.777/11.809/14.055 ms (88.6/88.3/74.2 GB/s)
vs rowtile best 2.693/3.682/3.475 ms (387.3/283.3/300.1 GB/s) = 4.37x
operation-wall speedup.
