# Server allocation probe: configurable capacity axes and failure artifacts

## Summary

`scripts/gguf_server_allocation_probe.py` could measure exactly one server
configuration, because its argv hardcoded INT8 KV, MTP off, prefix cache off, a
pinned context, and one active request. It also returned before writing JSON
whenever startup failed, so a failed capacity point left nothing to diagnose.
The probe now exposes the axes that change the resident envelope (BF16 or INT8
KV, MTP policy, optional DMS metadata, automatic context, automatic serving
capacity, prefix cache), records the raw documents the server answers with
instead of a hand-picked subset, and writes its artifact on every exit path.

Review round (parent, this unit, uncommitted): the first version was rejected for
size (1,353 lines), for re-deriving the server's DMS admission rules, for
injecting the two historical INT8 overrides by default, for summarizing `/ready`,
capabilities and the response `hipengine` block down to guessed fields, and for
renaming environment literals so an audit extractor would not see them. This
entry records the corrected design; the numbers below are from the final file.

## Changes

- `scripts/gguf_server_allocation_probe.py` (only production file touched; 760
  lines, ~640 of them code):
  - Axes as flags: `--kv-storage {auto,bf16,int8_per_token_head}`,
    `--speculative-mtp-serving {off,opt_in,auto,enabled}`,
    `--prefix-cache {default,off,radix}`, `--max-context-tokens N|auto`,
    `--max-active-requests N|auto`, `--dms-metadata` / `--dms-metadata-path` /
    `--dms-prefill-mode`, `--kv-scale-dtype`, `--kv-scale-granularity`
    (emitted only for INT8). A full-depth prompt needs no new flag: pass the
    configured context length to `--prompt-rows`, whose help says so.
  - `auto`/`default` reach the server as an omission: `--max-context-tokens`,
    `--max-active-requests` and `--prefix-cache` are absent from the argv when
    the axis is automatic. `--kv-storage` is always passed, so an inherited
    `HIPENGINE_KV_STORAGE` cannot decide the KV policy instead.
  - `resolve_policy` refuses exactly two things: a probe-level contradiction
    (both DMS arguments), and a measurement that an inherited variable would
    silently pin (`HIPENGINE_MAX_CONTEXT_TOKENS`,
    `HIPENGINE_MAX_ACTIVE_REQUESTS`, `HIPENGINE_PREFIX_CACHE`,
    `HIPENGINE_GGUF_AUTO_CONTEXT=0`). Whether an axis *combination* is
    executable is the server's call, so a compact-DMS refusal now arrives as a
    server error and is recorded, not pre-empted here.
  - Environment: nothing is injected by default - the caller's environment is
    the measurement's environment, and `HIP_VISIBLE_DEVICES` /
    `GPU_MAX_HW_QUEUES` are inherited rather than forced. The historical
    `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1` +
    `HIPENGINE_GGUF_INT8_KV_BF16_FULL_LAYERS=none` pair is now opt-in via
    `--legacy-int8-diagnostic-overrides` (int8 runs only; ignored with a note
    otherwise). Every override the probe makes is recorded with its effect, and
    the inherited values of 21 envelope-relevant variables are recorded as-is.
  - Startup is gated on `/ready` returning 200 with `ready: true`, not on the
    metrics endpoint answering. `/ready` and `/v1/hipengine/capabilities` are
    captured before and after the request **whole** (`http_status`, `error`,
    `payload`), so pool, KV-capacity estimate, device and admission fields stay
    re-readable; the `payload` is the server document verbatim.
  - The response block keeps the raw `hipengine` metadata (routing, generation
    shape, MTP accounting, prompt accounting), `usage`, `finish_reason`, the
    generated-text length and head, and - on failure - the first 2,000
    characters of the body.
  - HTTP 200 with an `error` payload, no choices, a missing `finish_reason`, a
    missing `usage`, or zero completion tokens is `request_failed`, not a
    measurement.
  - `run_probe` opens the log, launches, measures and tears down inside nested
    `try`/`finally`, so an unopenable log, a launch failure, an exception in the
    probe body and a teardown failure each become a recorded status; the request
    poller stops in `finally`; a non-passing run carries a bounded log tail.
  - `finish_probe` writes the artifact on every exit path - policy rejection,
    prompt failure, launch failure, startup failure, failed request - and
    without `--json` it goes to a timestamped temp file.
- `tests/test_unit_gguf_server_allocation_probe.py` (new, 61 CPU cases): argv
  construction and automatic omission, policy and environment refusals,
  opt-in legacy overrides, raw-document and raw-metadata recording, response
  classification, readiness/teardown, poller shutdown, failure artifacts, prompt
  determinism, and a whole-`main` policy rejection.

Compatibility: the default invocation still produces the INT8 / MTP-off /
prefix-off / capacity-1 configuration, minus the two INT8 overrides, which now
need `--legacy-int8-diagnostic-overrides`. A row measured without that flag is a
different envelope from the September rows and must not be compared to them as
if it were the same configuration.

## Validation

- `uv run pytest tests/test_unit_gguf_server_allocation_probe.py` - 61 passed,
  ~0.8 s, no GPU, no server, no model.
- `uv run ruff check scripts/gguf_server_allocation_probe.py
  tests/test_unit_gguf_server_allocation_probe.py` - all checks passed.
- `python3 scripts/check_test_tiers.py` - 0 issues.
- CLI, policy rejection: `--dms-metadata a.json --dms-metadata-path b --json
  /tmp/probe-reject.json` exits 1 and writes `status: policy_rejected` with the
  refusal text; no server launched.
- CLI, environment pin: `HIPENGINE_MAX_CONTEXT_TOKENS=8192 python3
  scripts/gguf_server_allocation_probe.py --json /tmp/probe-pin.json` exits 1
  with `status: policy_rejected` naming the variable.
- CLI, real failure path: `--model /tmp/definitely-missing.gguf
  --startup-timeout 45` exits 1 with `status: server_exited_during_startup`,
  `server_teardown: clean`, an empty `environment.overrides`, the exact argv,
  and a 32-line server log tail ending at `Application startup failed`. This
  exercises launch, `/ready` polling, teardown and artifact writing without a
  GPU.
- CLI, legacy opt-in: the same run with `--legacy-int8-diagnostic-overrides`
  records both override values and their effects, and no inherited keys.
- `audit/hipaudit/checks/invariants.py::unguarded_hip_test()` called directly -
  0 rows for the new test file. The test names no ROCm device variable: it
  asserts that every key in the module's own `_CAPTURED_ENV_KEYS` is recorded,
  which is the property under test, rather than hardcoding device-variable
  names. The earlier version exported `_VISIBLE_DEVICES_ENV` /
  `_QUEUE_COUNT_ENV` purely to keep the literal out of the extractor's view;
  those constants are gone.
- Not run: `audit/audit.py check` (pre-existing red: untriaged rows in eight
  kinds at budget 0, and the run rewrites tracked `audit/inventory` and
  `audit/triage` files). No audit file was modified by this unit.
- Not run: any GPU measurement. GPU1 is reserved for the parent session and this
  unit was scoped to the script and its CPU tests.
