# Fix MMQ session identity reuse in dispatch cache

## Summary

The intermittent public MMQ plane override failure exposed a dispatch-cache lifetime defect: the cache stored `id(mmq_session)` after the temporary session could die. A later session could reuse that integer and select an earlier plane count. A deterministic CPU regression reproduces the observed policy-three/launch-two mismatch.

## Changes

- Give each Q8 MMQ session a resource-free identity token and retain that token in the dispatch key. The cache no longer depends on recyclable object IDs and does not retain session resources.
- Exercise the actual launch memo with synthetic pointers and stubbed GPU launches, forcing integer identity collisions and checking alternating two/three/two-plane sessions plus repeated calls within each session.
- No kernels, numerical tolerances, environment defaults, or public assertions changed.
