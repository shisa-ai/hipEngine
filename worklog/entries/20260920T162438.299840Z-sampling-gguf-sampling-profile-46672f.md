# Attribute GGUF sampled AR decode overhead

## Summary

Profiled the resident GGUF AR service on physical host zbook, Radeon 8060S
(gfx1151), Qwen3.8-27B Q4_K_M, strict BF16 KV, capacity 4/occupancy 1,
context limit 8192, MTP and prefix cache off. All 10 mtp-bench category prompts
and 8 category-heldouts run in four arms, twice (forward/reverse arm order),
with 16 output tokens. All 144 requests complete; 72 fixed-seed groups repeat
exactly, and greedy default/eager IDs match. No quality or promotion claim.

The sampled model step is essentially the same cost as greedy. Host selection
adds 49.17 ms/transition; the full-logits copy after scalar synchronization is
only 0.088 ms. Native selection averages 48.39 ms, of which 48.07 ms is its
GPU wait; request means range 38.82–89.17 ms. The GPU top-p implementation
repeatedly scans the vocabulary from one thread to find successive ranks.
A kernel exists, but it is not yet a uniformly fast replacement for the host.

No arm replays a graph: gfx1151 C1 requires 128 remaining transitions, so graph
loss cannot explain these short requests. The host sorts logits and then sorts
probabilities a second time. The first sort alone accounts for 16.90 ms; a
safe ordered-input bypass for the second sort is the next exact candidate.

An earlier single-prompt exploratory run used:

That run did not reproduce the reported 7x difference; it is exploratory only,
not retained speed evidence. Its measurements cannot be conflated with another
physical host or the prior 262144-context server. Likewise, the other agent's
1700-token MTP comparison cannot establish the cause of an earlier 7208-token
AR/AR discrepancy. Existing evidence said that long-context greedy used AR.
