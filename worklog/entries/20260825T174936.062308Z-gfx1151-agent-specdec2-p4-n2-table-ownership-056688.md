# Own SPECDEC2 N2 commit tables per graph

## Summary

Clean multi-request C1 retention exposed a second N2 lifetime defect after the
address-generation fix in `16df9926f`. Five prompts completed exactly, then a
later K2 request faulted inside captured
`linear_state_pair_commit_chunked_i32_kernel`. The graph captured pointers to
session-shared source/destination pointer tables. True-AR, direct legacy MTP,
and verifier setup legitimately reuse and rewrite those same table buffers
between staged requests. Their allocation addresses may remain stable while
table contents point at retired/rebound rows, so an address-only compatibility
signature cannot make the graph safe.

The required owner is the graph, not the mutable resident session. No result
from the faulting C1/full run is retained.

## Changes

- Allocate four immutable graph-workspace pointer tables for Conv/GDN source and
  destination rows when capturing an N2 target graph.
- Snapshot the validated session pointer arrays into those tables before graph
  capture.
- Bind native-cycle control and captured linear-state commit kernels to the
  graph-owned tables.
- Keep compatibility fingerprinting on the actual source-row and destination
  state allocations; remove mutable session-table allocation identity from the
  signature.
- Add a RED/GREEN fake-workspace test proving graph tables copy the pointer
  values and are independent of later session-host-array mutation.
- Route only the one-slot packed-prefill state import through the strict
  per-layer D2D chain; multi-slot C2/C4 imports retain the fused pointer-table
  kernel. A provisional request-local graph invalidation and graph-commit leaf
  downgrade were removed after call-site tracing exonerated N2 replay.
