# Q4 prefill: Q6_K ffn_down writes bf16 straight to the residual (28 fewer launches, bit-identical)

## Summary

`q4_prefill` widened every Q6_K prefill result from bf16 to f32, and the caller
immediately narrowed `ffn_down`'s result back to bf16 for the residual. On this
model 14 of the 28 layers have a Q6_K `ffn_down`, so that pair cost 28 conversion
launches per prefill for no numerical effect.

`gemm_bf16_f32` now takes an optional `bf16_out` target and returns the buffer
holding the result. When a Q6_K down projection supplies one, the WMMA kernel
writes its bf16 output directly into the residual buffer.

The skip is provably exact: bf16 -> f32 widening is exact, and narrowing an
exactly-representable value back to bf16 is the identity. Verified over the full
16-bit bf16 pattern space (1048576 patterns including subnormals, ±0, ±inf and
NaN): 0 mismatches. The end-to-end prefill output is bit-identical — same
`hidden_rows` SHA-256, same logits SHA-256, same logits sum, same argmax token.

**This is a launch-count and memory-traffic reduction, not a speed win.** Prefill
wall time is unchanged: 221.3 ms before vs 222.3 ms after (5-trial medians),
inside a 5-8% run-to-run spread. The 28 removed launches move roughly 53 MB less
data, about 0.35 ms, or 0.3% of prefill. No wall-time claim is made.

## Changes

- `hipengine/kernels/hip_gfx1100/vibevoice/q4.py`: `gemm_bf16_f32` gains
  `bf16_out` and returns the result buffer; the `down_proj` call site passes the
  residual buffer and narrows from f32 only when the result came back f32
  (Q4_K). Module and function docstrings updated.
- `tests/test_gpu_vibevoice_qwen2_q4_runner.py`: two new tests.
- `benchmarks/results/2026-09-14-gfx1151-vibevoice-q4-prefill-q6-down-direct.json`
  and a `benchmarks/CHANGELOG.md` line.

## Validation

- `test_q6_k_down_proj_skips_the_round_trip` counts conversion launches during a
  real prefill: RED on HEAD (28 `bf16_to_f32` calls, expected 14), GREEN after.
  It also pins `f32_to_bf16` at 154 so a reintroduced round trip is caught.
- `test_q6_k_down_proj_direct_bf16_matches_the_round_trip` compares the direct
  route against the widen/narrow route on a real Q6_K `ffn_down` weight and
  requires bit-identical bf16 bytes. This guards the premise and passes on both
  revisions, since it exercises the kernels directly.
- Full run: 54 passed, 1 xfailed across
  `tests/test_gpu_vibevoice_qwen2_q4_runner.py`,
  `tests/test_unit_vibevoice_q4_evidence.py` and
  `tests/test_gpu_vibevoice_qwen2_runner.py`.
- Before/after hashes recorded in the artifact, both revisions run in the same
  session on zbook / gfx1151.

## Next

- The Q6_K `o_proj` branch of `gemm_f32_f32` has the same redundant
  bf16 -> f32 -> bf16 tail. It is deliberately untouched: `o_proj` is Q4_K on
  every layer of this model, so the branch is not exercised and could not be
  validated here. Handle it if a model with a Q6_K `o_proj` is admitted.
- `ffn_down` is only one of the prefill allocations. Prefill scratch is still
  allocated and freed per call (~20 buffers), and the front-end pool frees and
  reallocates its arena on every reset; both are per-request rather than
  per-token.
