## Changes


- Localized the GGUF Q4_K_M pure INT8 KV failure with `scripts/qwen35_gguf_int8_layer_probe.py`. The first full-attention layer (model layer 3) is the main amplifier: running only that layer from INT8 KV on the BF16 trajectory gives `KL=0.618776`, top-1 `11048 -> 246834`; CPU cache decomposition shows value quantization dominates local gated-attention error (`value_only` mean abs `4.65e-4` vs key-only `4.71e-5`). Later full-attention layers are much less sensitive.
- Implemented the long GGUF explicit-INT8 guard as a hybrid primary layout instead of pure INT8: rounded contexts `>8192` keep the first 3 full-attention layers in BF16 primary storage and use INT8 per-token/head KV for the remaining 7 layers. Long hybrid sessions promote scales to FP32; short sessions keep the existing BF16 mirror for exact short-gate decode. `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1` still reproduces the rejected pure INT8-only path, and `HIPENGINE_GGUF_INT8_KV_BF16_PREFIX_FULL_LAYERS` can override the prefix for diagnostics.
- W7900/GPU0 forced-long logit gate with no BF16 mirror now passes: `python3 scripts/qwen35_gguf_int8_kv_correctness.py --model /models/gguf/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf --quant gguf_q4_k_m --prompt-lengths 4K --decode-steps 1 --max-sequence-length 131202 --compiler-version-file /tmp/hipengine-hipcc-version-713.txt --require-cached-build --require-no-bf16-mirror --json /tmp/hipengine-gguf-int8-kv-correctness-4k-hybrid-default-w7900.json` -> accepted, `KL mean=0.014025`, `KL max=0.028051`, top-1 `1.0`, candidate layout `3` BF16 primary / `7` INT8, effective scales `fp32`, mirror count `0`, tracked peak `24.372 GiB` vs BF16 `24.985 GiB`.
