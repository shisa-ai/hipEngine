# INT8 KV shadow audit: zero BF16 shadow proven mid-flight

## Summary

The Packet 3 shadow-proof item is complete. A new probe
(`scripts/qwen38_int8_kv_shadow_audit.py`) runs one INT8 per-token/head
(FP32 scales) request through the LLM lane at 3,168 prompt tokens and
samples `device_kv_layout_audit()` from a side thread while the request row
is still resident — because post-request auditing is too late: the plain
session route releases the pooled allocation at request completion
(`request_pages: 0`), which is why the first ledger-side audit attempt came
back all zeros.

Results (XTX, GPU1, card0 idle):

- 206 mid-flight samples; every sample reports
  `persistent_bf16_payload_bytes == 0` and
  `persistent_bf16_mirror_bytes == 0`.
- INT8 payload and scale bytes equal the declared geometry exactly at every
  sample: `request_pages x 8,388,608` payload and `x 131,072` scales
  (per page: 2 planes x 16 layers x 4 heads x 256 dim x 256 tokens INT8,
  plus 2 x 16 x 4 x 4 B x 256 FP32 scales). Peak residency observed:
  13 pages = 3,328 tokens.
- Pool accounting agrees exactly: 64 planes (32 INT8 payload + 32 scale),
  272,629,760 B for 32 pages = 8,519,680 B/page with zero slack. A BF16
  shadow plane set would cost 16,777,216 B/page — the pool carries none.
- Graph scratch is zero by construction: packed decode graphs hard-require
  BF16 KV (`gguf_packed_decode_graph` raises NotImplementedError), so INT8
  decode runs eager.
- Transient prefill oracle cost at the 4,096-token boundary (ledger point,
  same lane): whole-card request peak 19.192 GiB vs 19.162 GiB after the
  request — the smaller steady cache is not erased by an oversized prefill
  peak, and the INT8 request peaks sit ~1.8-2.1 GiB below the equivalent
  BF16 points at 2,048/3,072.

One incidental GPU fault during probe development ("write access to a
read-only page", abort) occurred only in the standalone
`Qwen35GGUFResidentSession` lane at prompt 2,048 / max_sequence 4,096; the
LLM-lane probe never reproduced it. The standalone lane was abandoned in
favor of the LLM lane; no fault was observed there across repeated runs.
