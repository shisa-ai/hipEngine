# packed workspace lease follows the serving capacity

## Summary

The packed-execution KV workspace lease read its slot term from
`getattr(self._resident_model_runner, "max_batch_size", None)` on the
**resident model runner**, an attribute that runner never has (the generator
holds `_resident_model_runner`; the runner holds `capacity`). The lookup
therefore always returned `None`, `packed_verify_lease_slot_ceiling(None)` fell
back to `_PACKED_VERIFY_DEFAULT_SLOT_CAPACITY = 8`, and every GGUF server pinned
an 8-slot workspace lease regardless of the concurrency it was started with.

The lease now reads `int(self.capacity)` -- the serving capacity the loop
enforces and the number `_acquire_shared_session(max_batch_size=self.capacity)`
builds every resident session with, so it is the same term
`_packed_verify_union_geometry` reads on the batch owner. Slot views carry their
own width of one, which is why the term cannot come from an arbitrary resident
session.

Measured on gfx1151 (Strix Halo, 27B Q4_K_M, BF16 KV, 16 MiB pool pages), same
command both arms, `pinned_pages`/`current_pages`/`HIP used` after a 5,469-token
prompt plus two short prompts:

| config | capacity | lease (before) | lease (after) | pinned pages | HIP used |
| --- | ---: | ---: | ---: | --- | --- |
| 8192-token sessions | 1 | 256 pages (4.00 GiB) | **32 pages (0.50 GiB)** | 256 -> 32 | 33.74 -> 30.24 GiB |
| 8192-token sessions | 4 | 256 pages (4.00 GiB) | **128 pages (2.00 GiB)** | 256 -> 128 | 34.55 -> 32.55 GiB |
| auto context (131072 / 262144) | 1 | 4096 pages (64.00 GiB) | **1024 pages (16.00 GiB)** | 4096 -> 1024 | 89.21 -> 47.00 GiB |
| auto context | 4 | 4096 pages (64.00 GiB) | **4096 pages (64.00 GiB)** | 4096 -> 4096 | 90.06 -> 95.89 GiB |

The C4 auto row is flat on pages because the auto-context resolver traded the
freed lease for context: with the pre-fix 8-slot lease it selected 131072 tokens
(8 x 512 = 4096 pages); with the post-fix 1-slot lease at C1 it selected 262144
(1 x 1024 = 1024 pages), and the C4 arm then pays 4 x 1024 = 4096 pages at the
longer context. Pages are equal, context is doubled.

The slot term is exactly the serving capacity, not capacity+1: an MTP verify
group is K+1 *rows inside one slot*. `verify_target_blocks_batch` builds one job
per request row (`hipengine/generation/qwen35_gguf_mtp2.py`, one job per
`request_id` carrying `input_token_ids = (root, *candidates)`) and one
`_GGUFPackedVerifySlotBlock` per job, under
`target_verifier_active_slots_session(len(jobs))`, so `layout.slot_count` is the
number of speculative rows, at most the serving capacity. The other multi-slot
callers are bounded the same way: packed AR decode passes `slot_count=rows` for a
group the loop caps at the capacity, and `step_hidden_batch_native` refuses
`rows <= 1`, so its `slot_count=rows` cannot exceed the capacity either.
Measured across all 24 geometry calls in the C1 run -- short prompts, an explicit
MTP request, and a 5,469-token prefill -- the largest slot count any layout
requested was 1, the largest union was 1, and the workspace state never
allocated more than one slot. At C4 the same calls union to 4. Nothing in the
workspace path needed the 8-slot floor; the floor was pure over-reservation.

## Changes

- `hipengine/generation/qwen35_gguf.py`: the lease slot term is
  `packed_verify_lease_slot_ceiling(int(self.capacity))`, with the comment
  recording why an arbitrary resident session is not a valid source.
- `scripts/gguf_packed_lease_probe.py`: new committed probe that measures the
  lease, the union geometry, and the workspace allocations at a given capacity
  through the real in-process server, so this row is reproducible from the
  repository instead of a `/tmp` script.
- `tests/test_unit_gguf_prefix_cache_runner.py`: the two lease tests now pin the
  capacity term (2 slots at capacity 2, 1 slot at capacity 1) instead of the
  8-slot fallback, and `_FakeGlobalPoolSession` mirrors the real session ABI
  (batch owner = capacity, slot view = 1).
- `tests/test_unit_gguf_packed_workspace_stability.py`: new
  `test_mtp_verify_width_packs_rows_inside_one_slot` pins the assumption the
  lease term rests on (K=3 verify = 4 rows in 1 slot; 4 target rows = 4 slots).
- `docs/REFACTOR.md`: records the remaining per-slot context term and the
  capacity-estimate gap this repair exposes.

## Validation

`pytest tests/test_unit_gguf_prefix_cache_runner.py -k leases` fails with
`assert 40 == (8 + 4)` (C1 leases 8 slots x 4 pages) and `assert 12 == (8 + 8)`
(capacity 2 leases 8 slots x 4 pages). GREEN with the fix: 79 tests pass across
`tests/test_unit_gguf_prefix_cache_runner.py`,
`tests/test_unit_gguf_packed_workspace_stability.py`,
`tests/test_unit_gguf_long_context_pressure_gate.py`,
`tests/test_unit_qwen35_gguf_capacity.py`, and
`tests/test_unit_gguf_prefix_reuse_gate.py`.

Live measurement, both arms identical except for the lease term
(`HIPENGINE_GGUF_AUTO_CONTEXT=0`, `--max-sequence-length 8192` for the pinned
rows; default auto context for the auto rows), run on gfx1151 with

```
HIPENGINE_GGUF_AUTO_CONTEXT=0 python scripts/gguf_packed_lease_probe.py \
  --capacity {1,4} --max-sequence-length 8192 --out /tmp/lease-committed/c{1,4}.json
```

`scripts/gguf_packed_lease_probe.py` is committed with this change so the row is
reproducible from the repository. It installs in-process probes on
`_packed_verify_union_geometry`, `_ensure_packed_verify_workspace`, and
`_GGUFPackedTargetState.allocate`, drives the real in-process server through
`fastapi.testclient.TestClient` (short prompt auto, short prompt explicit
`speculative_mtp: true`, then a 5,469-token prompt), and records the pool
snapshot from `kv_pool_memory_snapshot()` plus the source digest of the tree it
measured. Every run returned HTTP 200 for all three requests, and the
5,469-token prompt prefilled and generated 8 tokens at both capacities. No
workspace allocation failed at either capacity, and the pre-fix artifacts are
the `pre-c{1,4}.json` siblings (digest `34ab2d65a4653d0d` = `eed290033`).

MTP did not engage in these runs (`route: null`, no `speculative_mtp` payload):
the production serving plan does not admit MTP on this box's gfx1151 cells, so
the verify geometry was exercised through the layout contract test rather than a
live verify group.

Artifacts:
`benchmarks/results/2026-09-19-gfx1151-qwen38-packed-workspace-lease-capacity.json`
(summary, raw-artifact digests) and its `-rows.json` sibling (one row per probe
