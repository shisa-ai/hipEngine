# Muse DFlash online depth adaptation: +3.0% suite tok/s, exact

## Summary

Built and tested the acceptance-triggered online candidate-depth adaptation
the context-budget sweep recommended (sweep entry
`20261108T162214...12f246`: the optimum is acceptance-driven per prompt, not
context-driven; static 4 is robust but cannot capture per-prompt peaks).

**Design.** `hipengine/speculative/adaptive_depth.py` — host-only,
per-request controller. Sustained high acceptance (EWMA ≥ 0.8) probes one
depth up; sustained low (≤ 0.2) probes one depth down; mid-band stays put
(probing there would only cost cycles). A probe runs the neighbor for 4
cycles and keeps it only if its smoothed tokens/ms beats the incumbent by
≥3%; otherwise reverts with a 16-cycle cooldown. Bounds [2, min(7, block−1)].
**Output-invariant by construction**: DFlash verify is target-corrected
greedy, so depth changes tokens-per-cycle, never token identity —
timing-driven decisions cannot change generated IDs or break seeded repeats.

**Fresh Desktop A/B (full 10-prompt mtpbench, 512 outputs, per-prompt AR
exactness; both arms same session conditions):**

| Arm | DFlash tok/s | vs AR | Acceptance | Exact |
| --- | ---: | ---: | ---: | --- |
| Static budget 4 | 26.65 | 2.108x | 0.4859 | 10/10 |
| Adaptive (default) | **27.46 (+3.0%)** | **2.171x** | 0.5487 | 10/10 |

AR control identical across arms (12.64/12.65 tok/s). Per-prompt behavior
matches the design: the four code prompts (high acceptance) climbed to
budgets 5-7 for **+8.3 to +12.8%**; general/mixed prompts descended to 2-3
or stayed, mostly flat; two small regressions (general_en_plan -4.9%,
general_ja_explain -2.3%) where a probe kept a locally-better rate that the
whole prompt didn't sustain — the flat-top variance the sweep documented.
Aggregate non-regressing with exactness preserved → ships **on by default**
(OPTIMIZATION §4.3); `adaptive_depth=False` / `--no-adaptive-depth` /
`LLM(speculative_adaptive_depth=False)` are the static rollback/bisection
levers.

This is a fresh gfx1151 Desktop lane (AR ~12.6 tok/s); the campaign's zbook
Gate-B numbers are a different lane and are not compared.

  suites (gemma4/qwen4exp wiring), and muse prefix-reuse integration green.
- GPU A/B: exactness 10/10 both arms (DFlash IDs == true AR per prompt);
  aggregate +3.0%; acceptance 0.4859 -> 0.5487; per-prompt depth decisions
  recorded in the adaptive artifact (probe/keep/revert traces).

  scripts/muse_glimmer_dflash_bench.py [--no-adaptive-depth] --output <json>`
  with the ENVS.md TheRock library path; defaults = KQuant-17GB target +
  dflash draft, full mtpbench suite, 512 tokens.
