# Extract readiness payload composition from the HTTP application

## Summary

Moved `/health` and `/ready` payload composition out of `create_app()` into
`hipengine/server/readiness.py`. The application still owns every live read:
engine identity/capability, both service-health probes, the live-loop probe,
queue getters, session summary, device/DMS/graph/pool values and config. The
owner receives a normalized `ReadinessSnapshot` and decides status, diagnostics,
payload shape and the 200/503 result. Lifecycle state (`_ReadinessState`),
startup/shutdown, queue admission, scheduling and stream translation did not
move.

## Changes

- `hipengine/server/readiness.py` (new): stdlib-only owner with frozen
  `ReadinessStartup`, `ReadinessConfig`, `ReadinessQueue`, `ReadinessSnapshot`,
  `build_readiness_payload`, `build_health_payload` and
  `readiness_http_status`. It imports only `collections.abc`, `dataclasses` and
  `typing`; no FastAPI, engine, `ServerConfig`, `app.state` or batcher.
- `hipengine/server/api.py`: added the readiness owner import and moved the
  payload body into an application collector inside `readiness_payload()`. The
  collector preserves the first health read for live-probe gating and the second
  read for the final verdict, then detaches model/capability/service/startup/
  graph/pool/prefix-cache/device/scheduler/session/DMS maps before constructing
  the snapshot. Startup fields are read after the live await, so concurrent
  startup mutations keep the previous race behavior. `/health` and `/ready` now
  call the owner builders; paths, payload keys, ordering, diagnostics and status
  codes are unchanged.
- `tests/test_unit_server_readiness_boundary.py` (new, 13 tests): exact health
  body, 200/503, healthy payload shape/order, startup diagnostics order, healthy/
  unavailable/closed/unhealthy service cases, missing service hook, top-level
  map detachment, stdlib-only imports, standalone load with no application or
  engine modules, nested service/startup map detachment through `/ready`, and a
  live-probe race test proving startup state is read after the await.
- `tests/test_unit_server_pure_owner_consumers.py`: added
  `hipengine.server.readiness` to the owner contract so `api.py` cannot acquire
  unused readiness re-exports and consumers cannot reach owner names through the
  application module.
- `worklog/entries/20261031T002155.354979Z-subagent-rf7-readiness-rf7-readiness-boundary-b6c67f.md`
  (this entry). No runtime/generation, docs, audit, README, staging or commit
  changes were made.
