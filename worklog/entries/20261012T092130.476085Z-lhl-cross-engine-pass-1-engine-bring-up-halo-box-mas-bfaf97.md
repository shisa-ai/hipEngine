  `/home/lhl/comparators-20261012/gufo-src/build/release/gufo`, sha256

- gufo build toolchain findings, recorded for reproduction: ninja must come
  from `/home/lhl/miniforge3/envs/vllm/bin` (no system ninja); the v0.12.0
  CMake preset now defaults to `RelWithDebInfo` (`-O2 -g`), so the build pins
  `CMAKE_BUILD_TYPE=Release` (`-O3`) to match the Sept `98641a6` pin and keep
  the performance basis comparable.
- gufo v0.12.0 does not compile against this host's GCC 16.2.1 libstdc++
  without a workaround: its `qwen/hip` translation units include HIP headers
  before `<chrono>`, and TheRock's `hip/amd_detail/host_defines.h` defines
  `__noinline__`, clobbering libstdc++ 16's `[[__gnu__::__noinline__]]` in
  `<format>`. Fixed with a `-include` shim
  (`/home/lhl/comparators-20261012/gufo-libstdcxx-preinclude.h`) that parses
  `<chrono>` first, applied to `CMAKE_CXX_FLAGS` and `CMAKE_HIP_FLAGS`. No
  gufo or SDK source was changed and no arithmetic is affected; the shim is a
  host-toolchain include-order workaround and is recorded here as the
  provenance for the pinned binary. Candidate for an upstream gufo issue.
- Host note for all pass-1 artifacts: the kernel is now `7.2.9-2-cachyos`
  (the 2026-10-04 record was `7.1.6`), and gufo `diagnose` now reports
  fingerprint `ed73bbdd…`. Pass-1 rows are not old-to-new comparisons anyway,
  but the host identity block of every artifact must carry this.
