# Chunk-sized bulk prefill hidden storage with monotonic owner growth

## Summary

The bulk prefill workspace allocated its BF16 hidden planes and INT64 token
buffer at the lifetime plan's `required_hidden_capacity` during session
construction. Plans requiring full-prompt storage therefore allocated the
declared capacity before a request needed those rows. Plans requiring only
chunk-sized storage already allocated one chunk; this change does not reduce
their initial allocation.

Storage is now a separate decision from executor choice. A non-DMS deferred-KV
owner starts chunk-sized and grows monotonically, owner-wide, the first time a
full-prompt consumer needs more rows. The lifetime plan, kernel selection,
oracle policy, chunk sizes, DMS routes, and expert-sidecar route are unchanged.

Main integrated the storage policy with generation sizing and validated the
public server route. The matched INT8/MTP non-DMS control used a 16,384-token
configured window, 12,288 prompt tokens, and 64 generated tokens. Before and
after requests passed with identical prompt hashes and all 64 output token IDs
identical. Wall times were 23.822 s and 23.764 s, respectively; this is a single
control pair, not a speed claim. Main also validated the larger compact-DMS
memory recovery in the companion entry.

## Changes

`hipengine/runtime/qwen35_gguf_runner.py`:

- `_gguf_bulk_prefill_initial_hidden_capacity` — the single storage policy.
  Deferred (chunk-sized) only when `defer_kv_allocation` is set, the session is
  not external-DMS, there is no expert sidecar, and the plan's full-prompt
  capacity exceeds one chunk. Everything else keeps the capacity it had, so
  standalone/CLI, DMS `dense_pool`/`layer_outer`, and expert-sidecar sessions are
  byte-identical. Returns a floor, not a cap.
- `_gguf_bulk_prefill_full_prompt_capacity` — the row ceiling the plan can ever
  ask for (one chunk for a chunk-outer plan, the full context for a layer-outer
  plan). It is exactly the capacity the pre-change allocator always took, so
  clamping growth to it reproduces the pre-change executor choice at every call
  site. A chunk plan therefore never grows and keeps its chunk-outer executor
  and any streamed target-hidden sink sized from it.
- `_gguf_bulk_prefill_hidden_plane_count` — the single plane policy, now used by
  the allocator (`single_plane=`) and reused by growth, so a grown workspace
  cannot change the route-scoped alias decision. Generation sizing can call
  these helpers instead of re-deriving route conditions.
- `_allocate_bulk_prefill_workspace` — uses the helpers, records
  `_bulk_prefill_full_prompt_capacity_rows` (the growth ceiling) and
  `_bulk_prefill_hidden_planes` (policy that survives release/re-acquire).
- `_ensure_bulk_prefill_hidden_capacity` / `_grow_bulk_prefill_hidden_capacity`
  — owner-resolved growth: allocates every replacement before publishing,
  preserves the plane count (aliased stays aliased), invalidates live packed
  decode graphs and synchronizes before freeing, updates the owner `_buffers`
  ledger, rebinds every registered slot view, frees each distinct old buffer
  once, and never shrinks. A partial allocation failure frees only the partial
  replacement set and leaves the live workspace untouched.
- `_bulk_prefill_workspace_owner` / `_bulk_prefill_hidden_capacity_rows` /
  `_rebind_bulk_prefill_workspace_from_owner` /
  `_publish_bulk_prefill_workspace_to_slot_views` — the ownership primitives;
  `_ensure_bulk_prefill_workspace` now reuses the rebind helper so a view cannot
  be left pointing at a released workspace.
- Full-prompt consumers grow before they address storage:
  `_run_bulk_prefill_and_sample` before it reads the `chunk_outer` decision
  (this preserves the pre-change route exactly: a shared-oracle plan still runs
  layer-outer, and a chunk plan still runs chunk-outer);
  `_prefill_batch_native_layer_outer` before its first embedding launch, with the
  plan check kept as the executor gate and a real-capacity check after growth;
  `_prefill_batch_native_layer_outer_segment` before
  `_GGUFResumablePrefillScratch.restore`, because restore truncates to the live
  buffer.

## Validation

- `uv run pytest tests/test_unit_gguf_bulk_prefill_deferred_hidden_capacity.py`
  — 29 new CPU tests: chunk-sized construction, every non-deferred route
  unchanged, grow-to-prompt, monotonic reuse, owner and borrower growth with
  view rebinding and ledger dedup, aliased and two-plane policies, partial
  allocation failure at each replacement, graph-invalidation failure, ceiling
  clamp, sink refusal, release/re-acquire, the three full-prompt call sites
  growing before they read/write storage (the scalar call site is observed
  through a call-through wrapper that records the capacity the route decision
  actually reads; the packed and resumable ones assert the row count and that
  restore has not run), and the chunk-plan regressions: a BF16 /
  `chunk_outer_layer_local_oracles` / `bf16_mirror` deferred owner must not grow
  and must keep `allocated < rows`, so its chunk-outer executor is unchanged.
- RED evidence (scratch script, not committed): the same scenarios run against
  `git show HEAD:hipengine/runtime/qwen35_gguf_runner.py` show HEAD allocating
  83,886,080 hidden bytes (8,192 rows x 5,120 x 2) where the new test expects
  768 rows, HEAD carrying no growth helper, and HEAD's route guard rejecting a
  chunk-sized workspace for the shared-oracle plan
  (`shared INT8 prefill oracle requires full-capacity layer-outer hidden
  ownership`). Growth is load-bearing, not cosmetic.
- Narrow regression set, all passing (exit 0):

  plan's declared capacity and asserts the suspended owner's bytes (captured
  before release) as the telemetry delta, since the bulk workspace legitimately
  keeps its grown rows afterwards.
- `ruff check` on the runner reports only pre-existing findings (unused kernel
  imports, `F821 Any`, `E402`); no new finding in the changed regions.

## Next

- Generation sizing uses the shared initial-capacity and plane-count helpers.
  Main's matched public-server control passed with identical output; evidence is
  in `benchmarks/results/2026-10-20-xtx-compact-dms-serving-memory.json`.
- Growth while a target-hidden sink is already active is conservatively
  refused. A full-prompt caller must grow storage before opening its sink.
  The existing chunk-plan streaming route never requests growth. Its bounded
  normalization buffer is now independent of bulk workspace residency.
- `_int8_layer_outer_shared_oracle_route` has no production caller after this
  allocator change. It is left in place; no dispatch route or flag was added.
- Device-result descriptors from `_describe_packed_verify_device_outputs`
  borrow `_prefill_token_buf` and must not be held across a later growth.
