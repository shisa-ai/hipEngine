# Honor cached compiler metadata in Qwen4Exp profiler

## Summary

The shared Qwen4Exp benchmark host metadata helper spawned hipcc even when
the profiler was given a cached compiler-version file. Honor that file so
cached-only profiling cannot launch the compiler through metadata collection.

## Changes

- Read HIPENGINE_COMPILER_VERSION_FILE when set; retain existing discovery
  for ordinary unconfigured benchmark runs.
- Added a regression test that rejects any hipcc subprocess.
- No runtime, kernel, arithmetic, or timing-boundary changes.

## Validation

- RED: the new host-metadata test failed on the hipcc subprocess assertion.
- GREEN: `.venv/bin/python -m pytest tests/test_qwen4exp_canonical_ar_bench.py
  tests/test_qwen4exp_profile_gap.py -q` passed all 25 tests.
- Initial profile attempts yielded no GPU measurement: the model root needed
  its UD-Q4_K_XL shard subdirectory, then metadata failed on absent PATH hipcc.
