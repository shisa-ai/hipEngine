# Candidate-mode MTP scope grant for the c1-c8 server bench

## Summary

Measuring a UD width cell above resident capacity 1 needs two things the bench
did not have together: the artifact's **MTP scope** and a **physical width** the
serving plan will admit. The bench already had the second
(`--generation2-diagnostic` installs `_diagnostic_plan`, which carries
`max_realized_group_rows` from the backend's
`GGUF_SPECDEC2_MTP2_PHYSICAL_WIDTH_DEPTHS`), and it now has the first as
`--mtp-scope-grant`, which reuses `ud_mtp_paired.mtp_scope_granted` rather than
duplicating the patch.

Without the scope grant the run is refused before any measurement, with the
reason recorded on the wire:

```
GGUF NextN draft materialization refused: artifact preset 'gguf_ud_q4_k_m' is
certified for scopes ['ar'] only; MTP/NextN draft operations require an
explicitly certified MTP scope (AR-only and AR+MTP admission are distinct)
```

That is the same ordering constraint as the serving-evidence row: the U6 pin
mints MTP scope, and the pin needs the width evidence. The grant is the
candidate-mode escape from the cycle, exactly as the paired protocol already
does for its own scope.

## What the grant does and does not do

- It patches `resolve_qwen35_gguf_artifact_preset` in process, for the named
  preset only, and restores it on exit (including on an exception during
  `LLM` construction). The patch never outlives the run.
- It is off by default, needs an explicit flag, and is documented as requiring
  `--generation2-diagnostic`, whose rows the plan itself labels
  `diagnostic_physical_gguf_mtp` with evidence key
  `gguf-c1-c<max>-generation2-diagnostic`.
- It grants *scope*, not *admission*. Width admission still comes from the
  diagnostic plan, and a granted run cannot produce a rate claim: the
  correctness contract stays `ar_exact` and the summary is a diagnostic cell.
- Nothing about the artifact's production admission changes. The U6 records keep
  `qualified=False`, `is_complete()` stays false, and
  `_UD_MTP_PRESET_FINGERPRINTS` stays empty.

## Changes

- `scripts/gguf_mtp_c1c8_server_bench.py`: `--mtp-scope-grant`, with the grant
  entered before `LLM` construction and released in the existing `finally`.
