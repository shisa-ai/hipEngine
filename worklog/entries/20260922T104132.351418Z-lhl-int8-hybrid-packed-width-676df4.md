# Fix the INT8 hybrid-layout packed decode width

## Summary

The HTTP 500 on a long-context INT8 KV server is fixed. A request that followed
a concurrent autoregressive/speculative pair, and a multi-choice request, both
raised before; both now return 200 with results that stay exact against the
autoregressive baseline.

Root cause: `packed_decode_max_rows` was assigned the declared direct width
before the layer layout was computed and was never revisited. A long-context INT8
session keeps a BF16 prefix of full-attention layers for quality, so those layers
have no INT8 scale metadata and no retained planes. The packed decode collects one
full-attention route per layer and raises when the set holds more than one value
(`qwen35_gguf_runner.py:26687`), so the session advertised a width its own layout
could not serve and then rejected the batch it had just built.

The two observed errors had one cause. The decode raise is the primary failure;
its message reports `state_mutation=partial`, and the prefill `ValueError`
("prefill chunk extends beyond its declared full prompt length",
`qwen35_gguf_runner.py:24366`) is a downstream symptom of the position a failed
decode left behind. The prefill error appeared only after an earlier decode
failure in every recorded sequence.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: added `_gguf_packed_decode_max_rows`
  and moved the `packed_decode_max_rows` assignment after
  `int8_bf16_full_attention_layer_indices` is known. The helper returns 1 when the
  layout is hybrid or the retained leaf is absent, and the declared width
  otherwise. The session then refuses the packed step through the existing
  `NotImplementedError` path, which `step_batch_native`'s caller already catches
  (`except NotImplementedError: return None`) and turns into a serialized
  fallback. No math changed.
- `hipengine/generation/qwen35_gguf.py`: `kv_capability_provenance` now reports
  `max_packed_rows`, the effective width, read from the resident sessions. It
  previously differed silently from the declared `max_direct_rows`.
- `scripts/int8_mtp_server_lifecycle_gate.py`: the multi-choice check asserts the
  shape the configuration contracts for. The ids must always match the
  autoregressive baseline; speculation is required when `max_packed_rows >= 2`
  and required absent otherwise. See the gate note below.
- `docs/API.md` documents `max_packed_rows`; `docs/ENVS.md` records that
  `HIPENGINE_GGUF_INT8_KV_BF16_FULL_LAYERS=none` clears the BF16 prefix and
  restores the declared packed width.
- `CHANGELOG.md` gains an Unreleased section.

An earlier attempt was reverted. Relaxing the packed-decode consistency check and
accepting a combined route in the manifest looked plausible, but the manifest is a
profiling contract whose path must name one KVLiveSpans batch route, and the
consistency check is a true invariant once the width is correct. The width was
the wrong layer to fix at.

  previously produced four 500s now returns 200 for every case: cold `n=2`, a
  concurrent AR+MTP pair followed by `n=2` on the same and on a different prompt,
  a concurrent AR+AR pair, a concurrent MTP+MTP pair, a single MTP then `n=2`, and
  a single AR then `n=2`. Zero `REQUEST_FAILED` entries; the only one in the
  final log is the gate's intentional 408 deadline probe.
- **`n=2` stays exact**: two choices, both equal to the autoregressive baseline.
- **`scripts/int8_mtp_server_lifecycle_gate.py` passes 7/7 (exit 0) on the default
  hybrid layout**, on both `--prefix-cache off` and `--prefix-cache radix`. It
  previously failed at `multichoice_speculates_and_matches_ar`.
- **The gate did not get weaker.** On a uniform INT8 layout
  (`HIPENGINE_GGUF_INT8_KV_BF16_FULL_LAYERS=none` plus

  `max_packed_rows: 4` and the gate reports
  `multichoice_speculates_and_matches_ar`, so the strict assertion is still
  exercised and still passes. On the hybrid layout it reports
  `max_packed_rows: 1` and `multichoice_serializes_and_matches_ar`. Both runs exit
  0.
- `scripts/int8_mtp_prefix_gate.py` passes 4/4 after the change (no regression).
- Unit: 101 passed across `test_unit_qwen35_gguf_int8_kv_policy.py`,
  `test_unit_gguf_packed_execution_manifest.py`,
  `test_unit_int8_mtp_server_gate_checks.py`, `test_unit_int8_mtp_serving.py`, and
  `test_unit_qwen38_int8_kv_capability.py`. Four new cases pin

  surrounding code.
- `scripts/docs/check_all.py` all 4 gates pass. `audit/audit.py check` exits 0.

## Next

The cap costs the packed path on a hybrid layout, so long-context INT8 KV
serializes rows where a uniform layout would batch them. That is the correct
trade today, because one packed batch cannot run the retained leaf and the
standard leaf together and the manifest names one route. Restoring the packed
path there needs the manifest to describe a mixed batch and the profiler census
to accept it; that is its own unit.

`audit/audit.py check` surfaced three pre-existing rows when its stale inventory
regenerated, and all three were triaged `NOT-DEBT` with evidence: the two `stub`
rows are uniformity guards in the packed target verifier that refuse a job whose
per-row modes disagree, and the `ungoverned-flag-branch` row names a flag whose
default is an active 256, not off. My two `status: blocked` entries were triaged
`--resolved` against this fix and the v0.6.1 publication.
