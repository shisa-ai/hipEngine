# Prevent text-stop leakage from HTTP streams

## Summary

The live boundary audit passed 80/84 requests. Four English no-logprob SSE stop
requests leaked text beyond the stop, lost canonical IDs, retokenized usage and
incorrectly reported MTP unused. Buffer stop-string requests through the existing
safe detailed-response path until an incremental text filter is implemented.

## Changes

- Completion and chat live-route selectors exclude nonempty stop strings.
  The buffered paths already trim before publication and preserve backend IDs,
  usage, probabilities and MTP metadata. No generation math or admission changes.
- Backend stop sequences are still useful but insufficient: standalone BPE
  encoding need not match in-context tokens. The final HTTP text stop can match
  even when backend token-sequence matching does not. The former live path
  published raw text before checking, then discarded terminal backend detail.
- Add eight real-service HTTP cases across endpoints, spellings and blocking/SSE,
  deliberately making standalone stop tokenization differ from generated tokens.
  Require trimmed output, actual MTP, canonical IDs and exact usage counts.
- Track the buffered fallback and its removal requirements in REFACTOR. This
  also changes AR stop requests to buffered SSE; correctness takes precedence
  over first-token latency until PS7's text-safe incremental filter is proven.
