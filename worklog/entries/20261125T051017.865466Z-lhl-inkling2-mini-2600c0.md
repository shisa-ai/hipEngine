# Build the expert schedule of Inkling prompt blocks on the device

## Summary

With `fast`, the resident traversal and device routes, a prompt block of 192 or more rows now
selects its expert routes on the device and builds its grouped schedule there. Before, every
visit of a block downloaded its normalized rows, ran the router on the host, sorted the routes by
expert and uploaded a schedule. The stage now has no transfer in either direction.

- **Where it runs.** `Inkling2GGUFDeviceProjections.project_experts_block_device_routes`: the
  router logits are projected from the resident rows, `device_routes` selects the routes for all
  rows, one workgroup (`route_schedule_kernel`) writes the expert starts, the 64-row groups, the
  token row of each compact row and the slot of each route, and the grouped projection of
  [b266a65a7](20261125T030054.604272Z-lhl-inkling2-mini-1863be.md) runs unchanged from those arrays.
  The grid keeps a fixed height (at most `min(experts, routes) + ceil(routes / 64)` groups) and the
  kernel skips the groups beyond the device count, so the host never waits for the count.
- **A row's routes stay in expert order.** The device router lists a row's routes in its own order,
  not by expert. The schedule kernel gives each route the slot it has in expert order and gathers
  the mix scales the same way, so the ordered mix adds in the same order as a host-routed block.
- **Routes of one expert may trade places.** The kernel fills an expert's rows with atomics. A
  route's row is computed on its own, so this changes no result: with the same routes and scales
  the device-routed block is bitwise the host-routed one.
- **No new flag.** It follows `HIPENGINE_INKLING2_DEVICE_ROUTES`, which already covers decode rows.

**Working-tree bench over b266a65a7** (in-tree decode bench, `fast`, 256-row blocks, 128 outputs,
five repetitions, W7900, mainline `UD-Q4_K_M`):

| Prompt tokens | First token, host-routed blocks | First token, device-routed blocks | Speedup | Decode, host / device |
| --- | ---: | ---: | ---: | ---: |
| 575 | 1.518 s (1.515 to 1.534) | 1.177 s (1.172 to 1.183) | 1.29 times | 23.93 / 29.29 tok/s |
| 2,057 | 6.496 s (6.420 to 6.571) | 4.991 s (4.981 to 4.993) | 1.30 times | 21.79 / 26.41 tok/s |

- Both arms run the resident traversal; the second also selects decode routes on the device, which
  is what raises decode (R0526). The saving in the block stage is 3.6 ms per visit after 575
  prompt tokens and 3.9 ms after 2,057.
- After 575 prompt tokens the 128 greedy output tokens are `fast`'s. After 2,057 they are not: the
  two arms agree for 23 tokens and then part.
- Why they part: on that prompt the device selected the host router's experts in all 98,304 rows of
  384 block visits; the mix scales differ by at most 1.9e-6 (5.4e-7 relative), and the block's rows
  are computed in another order inside each expert's groups. The prompt-end state therefore differs
  at rounding scale, and a later near-tie goes the other way. A run with decode routes on the
  device and host-routed blocks gives `fast`'s 128 tokens (6.404 s to the first token), which places
  the change in the block stage.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_nvfp4_selected_wmma.hip` and `.py`:
  `route_schedule_kernel` with its launcher, and the grouped projection takes an optional device
  group count. The row rule of the projection is unchanged.
- `hipengine/loading/inkling2_gguf_device.py`: `block_device_routes_supported`,
  `project_experts_block_device_routes`, `_device_schedule`; the launches of the grouped projection
  moved into `_run_wmma`, shared with the host-routed block; the schedule buffers are freed in
  `close`.
- `hipengine/runtime/inkling2_gguf.py`: the expert stage of the resident traversal takes the
  device-routed block when the projection offers it.
- `tests/test_gpu_inkling2_selected_wmma.py`: the schedule against the host's in five cases
  (uniform, skewed, two experts, 65 routes, eight or one route per row), and the two-stage
  projection from a device schedule against the host schedule, bitwise per route.
- `tests/test_gpu_inkling2_device_block_routes.py` (new, model file): no transfer in the device
  stage, scales equal to the host router's, bitwise rows against the host-routed block, and the
  public route calling it once per visit of every full block of a long prompt and never for the
  tail.
- `docs/KERNELS.md`: the source row.

## Validation

- Kernel: the schedule equals the host's (starts, groups, every compact row on its token, every
  route in its expert-order slot with its own scale, untouched entries untouched) in five cases;
  the projection from a device schedule is bitwise the host schedule's per route for both FP16
  variants. The equivalence test was red first: its first form read a token row from the compact
  position instead of the route.
- Model: `tests/test_gpu_inkling2_device_block_routes.py` passes with
  `HIPENGINE_INKLING2_MINI_GGUF` set.
- `tests/test_gpu_inkling2_*.py` in six files (device projections, router, grouped projection,
  block, device block routes, decode rows): 45 passed. `tests/test_unit_inkling2_*.py`: 222 passed.
- The bench rows above were taken on the working tree of this change; the clean-worktree bench and
  the three gate arms follow in a recording entry.
