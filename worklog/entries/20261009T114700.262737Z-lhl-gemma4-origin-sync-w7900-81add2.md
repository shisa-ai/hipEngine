# Merge origin/gemma4 and validate gfx1100 on W7900

## Summary

Merged `origin/gemma4` (`1c79c71be`, 27 commits of Radeon 8060S work) into the
local branch (`79845948c`, 94 commits ahead). On W7900 the merge changes no
output and no route: every teacher-forced capture is bitwise equal before and
after, public generated ids are equal at every length, and throughput is level
on decode and 2.5-3.1% higher on prefill from 8K up.

Measured on AMD Radeon Pro W7900 (gfx1100), Gemma 4 26B-A4B `UD-Q4_K_XL`,
production, BF16 KV, 128 outputs, one warmup and three samples,
`scripts/gemma4_campaign_bench.py`:

| prompt | prefill tok/s before | after | decode tok/s before | after |
| ---: | ---: | ---: | ---: | ---: |
| 512 | 1255.3 | 1249.6 | 70.39 | 70.22 |
| 8192 | 989.9 | 1014.9 | 69.33 | 69.12 |
| 32768 | 864.8 | 892.0 | 54.40 | 54.07 |
| 65536 | 753.1 | 772.8 | 41.91 | 41.75 |

`public_path_parity` is true on all eight rows. The first 512 and 8192
before-rows overlapped a GPU-using unit-test run and were re-measured alone;
the superseded files are kept as `pre-contaminated-perf-*.json`.

The remote work is authored in the shared `hip_gfx1100` kernel tree, so most of
it reaches W7900 through the merge itself: the four-wave Q8_0 T16 expert
gate/up schedule, the Q5_1T16 expert down prefill, the grouped and
scalar-collapsed staged score stage, the pipelined 32-key singleton PV, the
shallow-decode crossover, stream-event scratch retirement, and cross-process
KV save/restore. The router SGEMM tier was already the gfx1100 route.

One promoted remote default does not reach W7900: WMMA prefill attention.
`resolve_gemma4_prefill_attention_variants` returns no request for any backend
but `hip_gfx1151`, so gfx1100 keeps its native prefill attention. A same-process
A/B on W7900 (`scripts/gemma4_prefill_attention_variant_ab.py`, two repeats,
route confirmed by `last_prefill_attention_route()`):

| prompt | shipped (campaign row above) | `gemma4_staged` arm | WMMA arm | WMMA vs shipped |
| ---: | ---: | ---: | ---: | ---: |
| 8192 | 1014.9 | 928.6 | 1193.8 | 1.18x |
| 32768 | 892.0 | 632.2 | 1083.2 | 1.21x |
| 65536 | 772.8 | 449.3 | 967.2 | 1.25x |

The shipped column is a different harness from the two A/B arms, so the ratio
is a cross-harness reading. No gfx1100 numerics packet has been run for the
WMMA arm and no default changed here.
