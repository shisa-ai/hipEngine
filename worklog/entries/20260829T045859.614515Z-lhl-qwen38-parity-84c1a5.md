# Parity P1.3: C1 prefill wall is GPU-bound small-row wmma GEMMs, not serving

## Summary

Measured attribution of hipEngine's C1 prefill deficit (628 ms/request vs the
323-332 ms external winner cluster) on the physical gfx1151 host, current
HEAD, standard Q4_K_M parity model. Methods: frozen-artifact protocol
recovery, cProfile, py-spy dump/record (250 Hz), isolated prefill sweeps
(45/128/512 tokens across three routes and both queue policies), and a
rocprofv3 kernel trace of the 45-token forced-bulk pass.

Findings (per ~45-token C1 request):

1. **Serving stack is not the wall**: request wall == isolated packed-prefill
   wall (626 ms); TestClient + scheduler add ~0-30 ms. This supersedes the
   CONCURRENCY2 T0.2 serving-ownership prior for the prefill arm.
2. **The pass is GPU-bound**: 1380 kernel launches, 534.2 ms GPU busy of
   560.4 ms wall. Not launch-gap-bound at C1.
3. **Top kernel family**: `gguf_q4_t16_dense_wmma_prefill_shared_b_bf16`
   360.6 ms over 298 launches (~1.21 ms avg) at M=45 rows — ~20x the
   bandwidth-ideal weight-sweep time; the wmma tiling underutilizes the
   72-CU device at small M. Q6/Q5 wmma prefill families add ~141 ms.
4. **Packed-vs-bulk route overhead**: ~111 ms at 45 tokens (packed multi-prompt
   route vs single-session forced-bulk owners).
5. Queues are neutral (1q == 2q). Auto-route without force-bulk falls to a
   serial path (8.5 s @512) — script-only, not the serving route.
6. **Notebook correction**: the published 1294.885 tok/s @512 LCP row is
   Qwen3.6-35B-A3B (3B-active MoE), not Qwen3.8-27B; current-head parity-model
   bulk prefill is 402 tok/s @512. No regression — different models.
