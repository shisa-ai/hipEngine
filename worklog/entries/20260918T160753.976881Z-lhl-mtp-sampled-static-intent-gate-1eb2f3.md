# Sampled route: fifth gate is static intent, which needs an automatic-eligible row

## Summary

Two of the sampled route's serving gates are now fixed and committed (`80f895e58`),
and the last one is identified. With those fixes and a temporary evidence-row edit
that puts `sampled` on the **diagnostic** row
(`qwen38-q4km-gfx1151-production-bf16-cap4-c1-intent-k3-d24`,
`automatic_eligible=False`), the server-side plan selects `speculative_mtp` for a
`temperature 0.7` request, but the request still runs autoregressive: 254
`no_provider` events, 0 draft cycles, and - the decisive observation - the
adapter's `capability()` is **never called** (an env-guarded print inside
`_sampled_route_qualified()` never fires across a full run).

That is the signature of the request never acquiring typed speculative intent.
`hipengine/server/api.py:2409` (`_static_eligibility_from_route_decision`) returns
`None` unless the route decision carries `static_intent_allowed`, and the resident
loop schedules a speculative cycle only for rows that carry an eligibility. The
harness reports `static_intent_allowed=false` for exactly these rows, while the
greedy run - which works, 26.93 against 20.64 tok/s - is admitted through the
`automatic_eligible` row `qwen38-q4km-gfx1151-strict-bf16-cap4-realized-c1-b3` and
reports `qualified_automatic_realized_singleton_c1_b3`.

So the remaining gate is not a sampling-mode check at all: **a row that
`automatic_eligible=False` cannot hand a request typed speculative intent**, and
the only row the temporary edit qualified for `sampled` is such a row. The next
attempt must put `sampled` on an `automatic_eligible=True` row for this artifact
(for example `qwen38-q4km-gfx1100...`'s gfx1151 counterpart
`qwen38-q4km-gfx1151-strict-bf16-cap4-realized-c1-b3`, capacity 4, realized rows 1,
budget 3), which is also the row a *retained* `sampled` row should extend.

## Changes

- `80f895e58` (committed): the adapter's capability admits a row when
  `_sampled_route_request` says so instead of requiring `native_greedy`, and the
  server keeps typed speculative intent for a request only the sampled rule can
  serve - but only when `LLM.speculative_mtp_sampling_modes` (new) reports that
  the artifact's evidence rows admit `sampled`. Both are gated on the evidence
  row, so shipped behavior is unchanged while no row lists `sampled`.
- No temporary edit retained; the tree is clean at `80f895e58`.
