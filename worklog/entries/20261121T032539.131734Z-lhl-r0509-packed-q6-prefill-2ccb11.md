# Preserve planar Q6 row parity in grouped prefill

## Summary

On gfx1100, the production eight-request Japanese translation reproducer could emit different tokens across identical prompts. The first-layer planar Q6 query/key/value projection diverged across the packed prompt boundaries before convolution. Public dispatch inspection confirmed the FP16-input hipBLASLt sibling, even though the parent dispatch record named BF16 WMMA. The standalone BF16 leaf was exact on the same weight and captured activations.

## Changes

- Carry the packed multi-sequence layout in the existing FP16 staging workspace scope. A staged leaf that requires a single sequence declines before conversion, so the registered BF16 owner runs instead.
- Declare the planar-Q6 hipBLASLt sibling single-sequence. Keep it for ordinary and single-sequence prefill. Other staged kernels and packed speculative verification remain enabled.

- Focused Q6 workspace, GGUF dispatch-cache and prefill-scope unit tests and GPU workspace tests passed (37). The new scope test failed before the implementation; it covers decline-before-cast, safe-sibling selection and scope restoration.

Actual packed speculative verification remained active; the singleton projection trace observed the affected FP16 sibling decline and exact repeated-prompt QKV output at 420 and 480 packed rows. This was a correctness-only run of the candidate worktree, not a benchmark.
- The original mismatch survived the four-row Q6 head control, verifier padding removal and exact-linear verifier control. CPU and GPU accept agreed on the unpadded failing case. The source-state differences were already present on return from grouped prefill.
