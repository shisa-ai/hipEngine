# 2026-06-08 — C3.0b-1: persistent batch-decode segment-metadata cache (capture-safety prerequisite)

## Summary

- Historical pre-Worklog2 journal entry, ported verbatim from `WORKLOG-LEGACY.md` (source lines 76729-76735).
- First appended to the journal in commit `cbecd25a` (subject: perf: persist c>1 decode segment metadata (cu_seqlens/state_indices)).

## Changes

- Started C3.0b (c>1 decode graph replay). First unit: removed the last per-step device allocation from the batch layer pass. `_batch_decode_segment_metadata` (`hipengine/runtime/qwen35_paro_runner.py`) now caches `cu_seqlens` (`arange(rows+1)`) and `state_indices` (physical slot ids) in dedicated persistent device buffers keyed on `(rows, slots)`; it skips the per-step `malloc`/`free` + two host→device copies when the active batch is unchanged. Mirrors the C3.0a cached full-attention block table. Buffers are pre-sized to `max_batch_size` so a wider batch within capacity reuses them with no realloc. The 3-tuple return keeps an empty buffer tuple as element 3 so the call-site release loop stays a no-op (minimal diff; the giant `try/finally` layer loop is untouched).
- Why: HIP graph capture forbids `hipMalloc`/`hipFree` on the capturing stream. Audit of `_run_layers_batch_decode` (3968–5416) found this was the *only* per-step device alloc in the batch layer pass (`paged_uniform` is a pure dataclass ctor; `_batch_full_spans` block table is already cached; `_ensure_*_scratch` only re-reserves when too small). Removing it makes the batch layer pass allocation-free across a fixed active batch — required before `capture_batch_decode_graph`.
- RED/GREEN: added `tests/test_qwen35_batch_decode_segment_metadata_cache.py` (HIP-guarded, duck-typed stand-in, no 35B model) — asserts device-resident `cu`/`state` values, cache reuse on unchanged key (same tensor ptrs, no new alloc), and `state_indices` refresh on slot change with buffer reuse (no realloc). 2/2 PASS on `HIP_VISIBLE_DEVICES=1`.
- End-to-end correctness gate (`scripts/qwen35_batch_retained_bench.py`, prompt 128 / decode 16 / warmup 4, L40, cached builds, `HIP_VISIBLE_DEVICES=1`): `generated_token_equality` `native_batch_vs_independent_c1` **passed with empty mismatches at c2, c4, c8** — byte-identical to independent per-row c1 decode. Artifacts `/tmp/c3-0b1-c{2,4,8}-equality.json` (not retained; rows stay blocked/non-retained, bench exit 1 as expected).
- Next (C3.0b-2..5): piece A device-token-fed batch embedding (`_set_batch_token_embeddings_from_ptr`), piece B device-resident batch sampler write into `batch_lm_out_index` (no host copy), piece C/E `_step_batch_from_device_tokens` (advance via existing `advance_decode_positions_i64`), piece D/E `capture_batch_decode_graph` + replay.
