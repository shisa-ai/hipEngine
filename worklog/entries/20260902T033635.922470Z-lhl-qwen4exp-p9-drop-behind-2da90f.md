# Add optional load drop-behind

## Summary

Added a safe default-off per-tensor load drop-behind control for one-shot
serving. It advises only successfully device-owned hot tensors and excludes lazy
PLE; reload controls show why it must not become a reload-heavy default.

## Changes

- Materialization optionally reuses one file descriptor/part and applies
  DONTNEED after each successful non-PLE device load, closing descriptors on
  both success and failure.
- Added ordering/scope tests, evidence, refactor removal trigger, and closed P9
  load drop-behind, reducing open-or-partial count 31→30.

## Validation

- RED failed before the advice path existed; focused materialization tests prove
  1,223 load→advice pairs, zero PLE advice, and exception cleanup.
- Two real enabled one-shot/reload processes under `auto` clocks complete in
  47.12/45.67 s, preserve canonical p512 hash, and tear down to zero.
- RSS before request is 243/245 MB (file 92/94 MB), directionally below a prior
  separate-session warm/off 720 MB (file 355 MB); no cross-session speed claim.
- Requests reread 13.75/15.61 GB with 6,093/6,212 major faults. T0 load-memory
  policy; process/request windows overlap. Default-off is strict fallback.

## Next

- Keep only for explicit one-shot low-RSS serving. Remove or replace with a named
  loader policy if that product mode disappears or gains a full contract.
