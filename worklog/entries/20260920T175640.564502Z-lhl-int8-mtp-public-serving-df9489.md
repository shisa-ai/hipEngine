# Enable implementation-based INT8 MTP admission and validate HTTP lifecycle

## Summary

The normal HTTP server now executes dense C1 INT8 MTP under a four-slot
resident owner. Admission describes an executable implementation rather than
claiming BF16-only benchmark evidence applies to INT8. Explicit disable stays
AR; multi-request INT8 MTP selects its named AR fallback before mutation.

All 18 category/heldout prompts match true INT8 AR over blocking and streamed
completions/chat. A separate live lifecycle gate passes automatic intent,
mixed AR/MTP concurrency, multi-choice fallback, stopping, cancellation,
deadlines, reclaim and reuse. The comprehensive checklist is
`docs/reference/INT8-MTP-SERVER-READINESS.md`; it distinguishes these completed
checks from prefix-on, packed verifier, DMS and quality work.

## Changes

- `SpeculativeMTPServingImplementation` declares executable storage/backend/
  depth/group/layout/sampling bounds. Typed static eligibility and decisions
  carry `implementation_key` without fabricating an evidence key or artifact.
- The dense model plugin declares uniform INT8 C1 native verification through
  depth7. Existing BF16 evidence resolution is unchanged.
- Generator plans use prepared effective storage/layout/scales rather than the
  user's unresolved string. Known fallback-to-BF16 requests no longer receive
  misleading INT8 MTP refusals. Implementation-backed storage does not require
  an artifact-size hit in the benchmark table before building its key.
- The adapter accepts implementation-backed C1 depths independently of
  benchmark policy cells, and refuses compact DMS before proposal with
  `compact_dms_mtp_transaction_not_implemented`.
- Removed the evidence-only logical-residency cap that rejected an implemented
  four-slot INT8 serial owner as c0. Existing layout validation, resource
  admission, kernel width selection and approximate-KV quality decisions remain.
- Response routing exposes implementation provenance and effective storage/
  layout/scales. Added public HTTP category/lifecycle scripts and regression
  tests. Test fixes were already committed separately in `49847a169`.
- Other workers own the audit inventory and prefix-cache runtime changes;
  those are not part of this unit.
