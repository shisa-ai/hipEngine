# Run the Qwen2 backbone on the device with f16 primitives

## Summary

M3b: the speech-token backbone now runs end to end on the W7900.
hipengine/kernels/hip_gfx1100/vibevoice/qwen2_ops.hip provides six
f16-storage/f32-accumulate kernels (RMSNorm, rotate-half RoPE, tiled GEMM,
GQA decode attention, chunked causal prefill attention, KV append) in the
codec-ops launcher style; hipengine/models/vibevoice_lm.py composes them
into the 28-layer backbone with resident f16 GEMM weights, f32 norm weights
and projection biases, per-layer KV caches, prefill, incremental decode,
and tied-embedding logits.

Defects caught on the way, each by a failing test or dumped intermediate:

1. Bias and norm-weight buffers must be f32: the GEMM and RMSNorm kernels
   read them as float*.
2. The attention kernels re-applied RoPE to a query the host had already
   roped; the in-kernel rotation was removed.
3. The ctypes wrappers passed (kv_heads, group) where the launchers expect
   (q_heads, kv_heads); the kernel then computed group=0 and indexed
   garbage (identical garbage across different inputs = never-written
   memory was the tell).
4. Position offset versus cache length: the layer call threaded one "past"
   value for both, so layer 2+ of a fresh prefill treated its empty cache
   as if it already held the prefix (attending uninitialized slots and
   appending at the wrong start). The layer now takes (cache_len,
   pos_offset) separately.
