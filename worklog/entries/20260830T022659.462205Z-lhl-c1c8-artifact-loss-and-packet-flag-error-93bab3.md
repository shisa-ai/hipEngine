# W7900: recover the uncommitted C1-C8 cross-engine artifact; my refresh packet used the wrong flags

## Summary

Two separate mistakes, one of them not mine.

**Evidence loss.** `benchmarks/results/2026-08-30-w7900-q4km-c1c8-cross-engine.json` - the
provenance record for the published README C1-C8 complete-wall matrix - existed only as a
**staged, never-committed** file: `git log --all -- <path>` returns nothing, so no ref
ever contained it. It read fine at 11:20 (16,080 bytes, `git ls-files` listed it) and was
gone by 11:24 (absent from worktree, index, and HEAD, `git status` clean because the file
was never tracked at HEAD). My HEAD and reflog were untouched in that window, so an
unstaging plus deletion by another actor in the shared worktree is the only remaining
explanation. I recovered it byte-exact from the dangling blob `b01739368376e23fc1fea1779f4f90317a0408f6`
(16,080 bytes, located with `git cat-file --batch-all-objects --batch-check` filtered on
the known size) and am committing it, because leaving the sole copy staged is what lost it
the first time. If whoever removed it intended its deletion, revert this commit rather than
arguing from the worktree state.

**My measurement error.** The refresh packet I ran at 11:10 came back `status: failed`
(`route_expectation_passed` false at C1/C2/C5/C6, MTP engaged 0/10 cells there). That is my
configuration error: I launched the bench with defaults, and the canonical command recorded
in the recovered artifact is

```
scripts/gguf_mtp_c1c8_server_bench.py --model Qwen3.8-27B-Q4_K_M.gguf --backend hip_gfx1100
  --execution-profile production --widths 1,2,3,4,5,6,7,8 --resident-capacity 8
  --candidate-budget 3 --generation2-diagnostic --mtp-request-mode explicit --max-tokens 24
```

while my run used `candidate_budget: 2` and no `--generation2-diagnostic`. K2 instead of K3
also explains why the MTP arm was *slower* than AR everywhere (-3.12% at C1 to -25.08% at
C5). It is not an engine regression: the engine diff between my packet's commit
(`344a42d70`) and the 09:32 packets' commit (`72957ada2`) is empty, and every commit in
between is tools/tests/docs.

**One finding that is not explained by my flags.** At budget 2, C2 engages 10/10 cells
(+19.78% MTP vs AR) in a two-width `[1,2]` run, but engaged 0/10 at the same budget, same
prompts, same engine code inside the `[1..8]` run. C1 fails to engage in both. So MTP
engagement depends on the requested width sequence within one process, which is worth a
targeted look independent of this packet.
