# Fix the GDN segments-k2 LDS race that made prefill nondeterministic

## Summary

`qwen35_gdn_prefill_recurrent_k2_segments_kernel` (gdn.hip, launched by
`hipengine_qwen35_gdn_prefill_recurrent_segments_k2_f32`) used one `__shared__ float partial[64]`
for both the key-update reduction and the query reduction inside its per-token loop. The
key partial was read at `partial[0]` (to form `delta`) and then overwritten by the query partial
with no barrier between the read and the write. With one 64-wide wavefront that is benign; the
launch is 64 threads, so on wave32 targets the block is two warps and a leading warp can clobber
the slot while a trailing warp still reads it.

Observed effect: two launches on identical buffers disagreed bitwise. At the qwen36 test shape
(64 tokens, 16 k-heads, 32 v-heads, 128/128 dims) the drift was ~1.6e-4 in ~1000 of 524288 state
elements and ~500 of 262144 out elements, with token 0 always identical and later tokens diverging.
That is far above F32 reordering noise and it made
`tests/test_gpu_qwen35_gguf_gdn_prefill_correctness.py::test_gdn_prefill_paths_match_cpu_oracle_qwen36_shape`
flaky (1 failure in 5 standalone runs, and the single failure in the ps17 `--suite all` run).

The sibling non-segmented `qwen35_gdn_prefill_recurrent_k2_kernel` already keeps
`partial_update[2]` and `partial_query[2]` separate, so the segmented variant was the only
one carrying the hazard.

This is a pre-existing defect, not a regression from this branch: the kernel body is unchanged
since it landed, and the failing test also fails at base `998b7b0a4`.

## Changes

- `hipengine/kernels/hip_gfx1100/linear_attn/gdn.hip`: split the segments-k2 LDS scratch into
  `partial_update[64]` and `partial_query[64]`, matching the non-segmented k2 kernel. No
  arithmetic changed; the reduction order (`partial[0..num_warps-1]` summed in ascending warp
  order) is identical.
- `tests/test_gpu_qwen35_gguf_gdn_prefill_correctness.py`:
  `test_gdn_segments_k2_repeat_is_bitwise_stable` runs the segmented chain four times and requires
  bitwise-identical `out` and `state` (`uint32` view). This is the deterministic-repeatability
  gate from `docs/EXECUTION-PROFILES.md` applied to the segmented recurrence.
