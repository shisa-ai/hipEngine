# Stabilize SPECDEC2 cycle hidden slabs

## Summary

Replace the two actual steady-cycle allocation owners with adapter-persistent
max-width BF16 slabs. Warmed-cycle audit on current P2 source separated large
first-cycle lazy target setup from repeat churn:

- C2 steady cycles allocate/free exactly 40,960 bytes each;
- C4 steady cycles allocate/free exactly 81,920 bytes each; and
- source audit maps those bytes to proposal hidden packing plus physical provider
  repair hidden packing (one width×H BF16 buffer each).

The first physical cycle also grows target/graph workspaces (C2 ~977 MB, C4
~1.95 GB); these persist. C1 has one request-bound graph-capture allocation on
the measured request's first cycle, then zero on every subsequent cycle.

## Changes

- Add one adapter-owned `RuntimeWorkspace` with distinct proposal and repair
  tensors shaped `(max_physical_requests, hidden_size)` BF16.
- Reuse stable pointers across all cycles, group shrink/refill, and acceptance
  depths; reject shape drift rather than reallocating silently.
- Add exact `cycle_hidden_rows` work-item claims.
- Free the workspace once at adapter/model close and expose a compact pointer/
  shape contract for testing/diagnostics.
- Remove proposal and physical-repair `malloc/free` from the cycle.
- Add bridge-only per-cycle allocation samples; production timing is untouched.
