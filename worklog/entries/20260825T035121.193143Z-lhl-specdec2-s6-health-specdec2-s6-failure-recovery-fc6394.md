# Recover SPECDEC2 precommit failures through AR

## Summary

Keep the sole Generation-2 driver healthy after provider, packed target, or
post-target readback failures that occur before canonical target commit. The
staged rollback already restores/releases provider checkpoints and disables the
failed request's provider. The engine now asks the runner whether every target
cursor is still canonical; only then does the same decode tick fall back to true
AR. Any late/post-commit cursor change remains fatal rather than risking double
commit.

## Changes

- Add an opt-in `recover_speculative_cycle_failure` runner hook after staged
  rollback and complete-claim release.
- Implement GGUF MTP2 recovery only when every target cursor still equals its
  scheduler-owned slot cursor.
- Record stable `precommit_failure_ar_fallback` reason and per-request count.
- Add a hardware gate injecting one proposal, target, and candidate-readback
  failure, each followed by a different-prompt exact MTP health request.
- Add engine, adapter, and gate-helper tests.

## Validation

Focused engine/frontier, GGUF seam, and gate tests pass. Existing runners without
the recovery hook preserve exception behavior. Hardware proposal/target/readback
injection follows the implementation commit; all faulting rows must finish exact
through AR, all later rows must use MTP exactly, and the same service must drain.
