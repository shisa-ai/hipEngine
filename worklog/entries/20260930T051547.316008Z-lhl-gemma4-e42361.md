# d8 step 3: uniform launch cost, and the X7 host-dependency map for graph capture

## Summary

- Extended `scratch/d8_host_attribution_probe.py` to record per-symbol launch
  host time (the ctypes funnel already had the data; one gate change).
  **Launch cost is uniform 3.1–3.6 us across every kernel wrapper** — fattest
  are `hipengine_gguf_q8_0_pack8_gemv_bf16_bf16_out` (125 calls, 454 us) and
  `hipengine_gemma4_rmsnorm_f32w_bf16` (121 calls, 382 us), but their per-call
  cost matches everything else. No fat wrapper exists to fix, so the only
  launch lever is launch *count* — X7's territory, per the row's own fork.
- Built the X7 host-dependency map the row requires before graph capture
  (`rocprofv3 --hip-runtime-trace` over one 8-step decode; window found by
  launch-density phase, ~45 launches/ms in the final dense phase, artifact
  `benchmarks/results/2026-09-30-gemma4-x7-host-dependency-map.json`):
  - Window 133.9 ms, 15,489 HIP-API calls, total API host time 38.89 ms (29%).
  - **8 sync `hipMemcpy` = 21.22 ms (15.8% of the window): the only
    host-blocking dependency, one logits D2H per step.** Iteration 145's fix
    shows here — the staging/token copies appear as 536 `hipMemcpyAsync` at
    ~2.2 us instead.
  - `hipLaunchKernel` 6,752 calls = 13.08 ms host (9.8%, avg 1.9 us under
    rocprof; the ctypes probe reads 3.1–3.6 us including wrapper overhead),
    each paired 1:1 with `hipGetLastError` (6,752 calls, 0.32 ms).
  - 480 `hipStreamWaitEvent` + 480 `hipEventRecord` (60/step, 2 per layer):
    the engine's inter-stage ordering — capture-compatible.
- **X7 ceiling honesty:** the 13.08 ms of launch host time mostly overlaps
  device work already (probe wall 15.95 vs census busy 14.21 ⇒ ~1.7 ms gap),
  so replay can recover about that gap — not the launch total. The captured
  region must end before the logits D2H and host sampling, since the sampled
  token feeds the next step.
