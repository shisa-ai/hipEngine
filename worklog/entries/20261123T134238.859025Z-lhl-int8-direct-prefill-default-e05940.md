# Promote GGUF direct INT8 prefill to the default

## Summary

Lead decision (2026-11-23): direct (oracle-free) INT8 prefill attention on
mirror-free INT8 KV is now the default. `HIPENGINE_GGUF_INT8_PREFILL_DIRECT`
defaults to `1`; `0` restores the BF16-oracle route as an arithmetic rollback.
R0404 had recorded both numerical gates (per-token-head `kl_mean=1.76e-4`,
`top1=1.0`; tail-four Hadamard `kl_mean=2.57e-5`, `top1=0.9978`) and the
six-category task gate on both layouts as accepted, then closed with promotion
left to the lead. That left a default-off flag with no removal condition, which
was the `ungoverned-flag-branch` row failing `audit/audit.py check`.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: `_gguf_int8_prefill_direct_enabled`
  defaults to True; docstring names R0526.
- `docs/REFACTOR.md`: new R0526 (rollback control; removal after the default
  serves admitted mirror-free INT8 configurations including gfx1151, clearing
  command `scripts/execution_profile_gguf_int8_direct_prefill_task_gate.py`).
- `docs/ENVS.md`: default `1`, category "Arithmetic rollback".
- Tests: `tests/test_unit_gguf_int8_prefill_direct.py` asserts the default
  (RED before the flip: 1 failed, 4 passed); two oracle-planning tests in
  `tests/test_unit_qwen35_gguf_int8_kv_policy.py` now pin `0`, because their
  subject is the oracle route's lifetime plan.
- Same branch, audit gate: the two `step_rows_native` refusals were triaged
  NOT-DEBT/keep (capability guards; the only caller catches them and now counts
  `fallback_reasons["native_rows_capability_miss"]`), and the stale "one shared
  BF16 KV chunk" wording was replaced after R0207. Issue #11 worklog rows were
  resolved (closed as not reproducible), and issue #12 rows were deferred to
  2027-01-31 (still open). The rescan also dropped 13 duplicated kernel
  decisions left by a merge.
