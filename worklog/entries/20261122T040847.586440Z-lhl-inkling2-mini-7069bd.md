# Isolate expert arithmetic differences in pinned Inkling decode

## Summary

Changing the expert activation precision or ranking order in isolation did not recover the pinned Loom reasoning prefix. Keep the default arithmetic while testing the integer-dot path for its own performance and quality.

## Changes

- No runtime changes. On the single-token path only, the first scratch trial quantizes the two selected NVFP4 expert activations to groups of 32, rounds each scale to FP16 as in Loom's `g_quant_q8`, then reconstructs FP32 activations before the existing HIP projections. It does not reproduce Loom's integer accumulation. The second trial retains the same sigmoid and bias but sums the chosen probabilities and mixes outputs in rank order, as in `g_ink_moe_topk`; it does not move expert scales into the mix coefficients.

## Validation

- On Strix Halo (`gfx1151`), hipEngine `1c5c57044` with the pinned Loom Q4_K_XL and the [same greedy 47- and 575-input prompts](20261122T040138.321705Z-lhl-inkling2-mini-78ad60.md), both trials matched the rendered input digest and finished at the 128-token cap. `python -u ./hipengine_inkling_expert_arithmetic_pilot.py "$mode" ./hipengine_inkling_ordinary_output_pilot.py "$model" "$tokenizer"` reported calls from the intended decode path.
- Quantized activations first changed hipEngine's token ID at zero-based index 40 on the short prompt, and did not change IDs on the longer prompt. Rank order alone did not change IDs in either cell. Neither moved hipEngine's first reasoning text difference against Loom from the prior 115/131-character shared prefixes. This is an isolated diagnostic, not evidence about the fully quantized Loom matvec or broader tasks. Log: `/tmp/kendex-pi-bg/bg-57-1795320356809.log`.
