# Add QSA flash prefill kernel (33% family win)

## Summary

First QSA flash prefill kernel landed (gather + flash two-kernel design,
lineage llama fattn-tile scalar path): 7.85-8.4 ms per QSA layer at the
real geometry vs the current spans decode kernel's ~11.8 ms (33% family
win; 141 -> ~95 ms projected at pp508). Correctness verified against a
NumPy paged reference (mean rel 0.14%, bf16-output rounding class).

## Changes

- hipengine/kernels/hip_gfx1100/attention/qwen4_exp_qsa_flash.{hip,py}:
  gather kernel (paged bf16 KV -> contiguous bf16 scratch via block table)
  + flash kernel (block-per-Q-tile, 8 warps, online softmax, Q f32 + K/V
  bf16 in LDS, XOR-butterfly dot reductions, V accumulation fmaf).
- tests/test_qwen4_exp_qsa_flash_prefill.py: 3 shape cases vs NumPy.

## Validation

- pytest 3/3; microbench 7.85 ms best / 8.17 median vs 11.8 current.
- Bring-up found two real bugs: (1) masked keys' dot=0.0 inflated the
  online-softmax max and the accumulator rescale was inside the per-key
  guard so fully-masked tiles descaled l but not acc — fixed with -inf
  masked dots and a once-per-tile rescale; (2) a conditional-ternary
  multiply in the V accumulation miscompiled to zero — fixed with a
  hoisted pointer + fmaf restructure.

## Next

- Route env + screen + packet for the 33% win (numerics are bf16-KV class,
  matching the current kernel).
- Next perf iteration toward llama's 1.2 ms: key-parallel QK layout (lane
  owns key, 256 serial dim FMAs, no butterfly shuffles — the current
  5-shuffle-per-key chain is the measured bottleneck; QT/V-in-LDS changes
  moved it only 8.4->7.85 ms).
