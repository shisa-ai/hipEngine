# compiled staged exchange with mapped-pinned return path for tp2

## Summary

The recorded resume lever from the full-model MLP-only TP2 checkpoint
(20260915T103757.020870Z) is done: the per-layer staged exchange is now driven
from a hipcc-compiled host driver, and the H2D return path is gone - the
reduced f32 payload lives in mapped pinned host memory and both ranks'
boundary-cast kernels read it zero-copy over the bus. Basis: the transport
A/B's compiled arm ran the same batched protocol at 20.8 us per reduction
against ~40 us for the Python loop, and the slice probe attributed ~29 us of
the Python route's wall to the H2D return submissions - protocol overhead
(twelve device switches, eight ctypes submissions per reduction), not copy
bandwidth.

Bit-parity is pinned, not assumed: for the two-rank world the compiled host
sum is the same single f32 addition per element in the same rank order (row 0
+ row 1), and bf16 staging widens by the same bit shift into the high half.
On W7900 + RX 7900 XTX, f32 and bf16 staged partials reduce bit-identically
between the compiled and Python routes across both slot sets, and the
zero-copy consumer contract is verified: `f32_to_bf16` reading the mapped
payload on device 1's own stream produces the same bf16 bits as the device
cast of the Python route's H2D-returned row.

## Changes

- `hipengine/distributed/staged_exchange_host.cpp` (new): the compiled host
  driver. C ABI (`tp2_staged_create/reduce/destroy/last_error`), host-only
  source, built with `build_hip` into the hash-keyed JIT cache
  (`family="tp2-staged-exchange"`, `-std=c++17`). Structure lineage:
  `benchmarks/micro/runners/hip_staged_exchange.hip` (the A/B native arm,
  commit 0627ecae) and the Python route in `hipengine/distributed/staged.py`
  it must stay bit-parity with. It owns both mapped pinned arenas
  (`hipHostMalloc` with the mapped flag), submits both ranks' D2H before
  either wait, waits each stream once, sums in f32 in rank order, and
  publishes the payload's device-visible address - no H2D copy. World != 2
  is rejected at create (the Python route stays the general fallback); any
  HIP error is recorded, the caller's device restored, and a negative code
  returned without advancing the slot.
- `hipengine/distributed/staged_compiled.py` (new): lazy build wrapper plus
  `CompiledStagedExchangeTransport`, the same transport surface the shard
  group consumes (`reduce(partial_ptrs) -> {device: payload_ptr}`,
  `poisoned`, `reductions`, poison-on-failure, exactly-once `close`). The
  wrapper allocates nothing per reduction.
- `hipengine/distributed/shard_group.py`: `driver` knob on
  `MlpShardGroup` - `"python"` (default) selects the original staged route,
  `"compiled"` selects the compiled transport; unknown drivers are rejected.
  Both transports reduce the same partials in the same order, so the reduced
  payload is bit-identical for the two-rank world.
- `hipengine/distributed/tp2_generate.py`: `MlpTP2GenerationSession` threads
  the same `driver` knob into the shard group.
- `scripts/tp2_mlp_generate_e2e.py`: `--driver {python,compiled}` for the
  TP2 arm; the artifact record names the driver.
- Tests: `tests/test_unit_distributed_staged_compiled.py` (11 CPU tests: a
  fake driver library pins construction validation, per-call pointer
  passing, the single payload pointer both ranks consume, poison semantics,
  exactly-once teardown, and the group's driver selection including that the
  boundary cast consumes the mapped pointer), and
  `tests/test_gpu_distributed_staged_compiled.py` (2 HIP-guarded hardware
  tests: bit-parity vs the Python route and a host oracle on both slot sets
  for f32 and bf16 staging; the zero-copy boundary cast on device 1's own
  stream). HIP availability guards per the standing test rule.

## Validation

- Compiled transport vs Python route on hardware, f32 and bf16 staging,
  two slot sets each: reduced payloads bit-identical to each other and to
  the host oracle (probe + `test_gpu_distributed_staged_compiled.py`, both
  passing). Zero-copy `f32_to_bf16` consumer on device 1: bit-identical.
- 11/11 new CPU tests; 130 passed across the TP2 unit bundle
  (`test_unit_distributed_*` + `test_unit_scripts_tp2_mlp_*`), 5 passed in
  the GPU shard-components + compiled-transport hardware tests.
- First e2e attempt failed at the TP2 arm: the compiled create rejected the
  model-owning loop's `streams={device: 0}` because 0 (the per-device
  default stream) failed a null-handle check. Fixed by dropping the check -
  0 is a valid hipStream_t and is exactly what production passes; the
  default-stream composition was re-verified bit-exact on hardware before
  the rerun.
- Full e2e re-run with the compiled driver (all three arms, one process,
  `uv run python3 scripts/tp2_mlp_generate_e2e.py --driver compiled --json
  benchmarks/results/2026-09-15-w7900-tp2-mlp-generate-e2e-compiled-exchange.json`,
  exit 0, W7900 + RX 7900 XTX, fingerprint a0b9749e2d7b):
  - `tp2_vs_tp1_teacher_device0` / `_device1`: mean KL 6.425e-04 (limit
    1e-3), max KL 5.246e-03 (limit 5e-2), top-1 100% - PASS, and identical
    to the Python-route run's metrics to all recorded digits.
  - `tp1_device0_vs_device1_control`: mean KL 0.0, top-1 100% - PASS.
  - TP2 determinism: repeated tokens identical, teacher-forced logits
    bit-identical (max abs diff 0.0).
  - Exchange: 9,216 reductions, in-step wall p50 **156.18 us** (p95
    187.15, mean 146.65) against the Python route's p50 201.18 (p95
    237.76) on the same composition - 1.29x on the exchange segment, ~45
    us/token of protocol overhead and H2D return removed.
  - Decode p50 (matched composition): TP1@W7900 31.76 ms, TP1@XTX 26.29
    ms, TP2 **53.12 ms** (was 56.45). Still slower than either TP1
    control; no speedup claimed.
- Default flipped to `driver="compiled"` in `MlpShardGroup`,
  `MlpTP2GenerationSession`, and the e2e script after the gates passed;
  the Python route is the registered fallback and the world != 2 general
  transport (the compiled driver rejects world != 2 at create).
  `docs/REFACTOR.md` records the knob and its removal condition.

## Next

  is the per-layer dependency wait (real device time on the slower rank)
  plus the replicated-attention enqueue, which stays the dominant wall.
  The next lever on record is unchanged: a batched/graphed TP2 schedule,
  which is also what would let the whole exchange (both transports and the
  knob) be retired.
- Per-layer f32 partial staging (Q6_K layers) is a registered numerical
  candidate; measure it only if the bf16-uniform envelope ever binds.
- Packet 3 step 3 (production-route integration: policy table,
  planner/dispatch admission) remains gated on a concrete speed case.
