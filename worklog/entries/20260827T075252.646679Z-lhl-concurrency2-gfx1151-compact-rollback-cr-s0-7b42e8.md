# Close gfx1151 compact rollback at CR-S0 premise

## Summary

CR-S0 stops Compact Rollback before implementation. Live B1/B2/B3 probes on
the production C1 staged owner prove that one complete target Conv/GDN state
group is **83,361,792 bytes (79.5 MiB)**. The current verifier retains `K+1`
selected-row groups: **166,723,584 / 250,085,376 / 333,447,168 bytes** for
B1/B2/B3, plus one required **83,361,792-byte** initial checkpoint for rollback.
A D1 design could therefore save one/two/three groups: **79.5/159.0/238.5
MiB**, equivalent to at most **1,272/2,544/3,816 BF16-KV tokens**.

This is real capacity, but it cannot unlock a current product cell. The retained
C1 key permits only context 1-67 and rejects context 68 before mutation; c2-c8
remain 70/70 typed K0 because physical streaming/refill/survivor lifecycle and
economics are unqualified. The limiting product plane is qualification and
physical ownership, not memory. Per the CR-S0.0 stop gate, no D1 code, RED
campaign, or redundant full-suite benchmark is admitted.
