# EVIE f16 vision attention

## Summary

Vision-tower attention now runs the fp16 matrix-core path: q/k/v gathered
into per-head-contiguous (heads, tokens, head_dim) f16 planes, two
`gemm_strided_batched_ex` f16/f32acc batched GEMMs, a fused f16
scale+softmax kernel, and an f32 scatter. Benchmark: 3.09 s -> 2.99 s
(doc 2.27 s, query 0.72 s, 8p+8q fp16).

## Changes

- `evie_ops.hip`: `hipengine_evie_scale_softmax_rows_f16`,
  `hipengine_evie_gather_qkv_f16`, `hipengine_evie_scatter_heads_f16`.
- `hipengine/runtime/evie.py`: fp16 branch in `_attention_from_packed`;
  f16 scores + plane scratch helpers (stride padded to 128 elements).

## Validation

- Standalone attention parity: err 2e-4 vs numpy on (37, 16 heads, 64).
- Fixture parity (fp16): visual cos 0.9999932, query cos 0.9999987, doc cos
  0.99995, maxsim 5.9137 vs 5.9114 (+0.04%).
- Strict fp32: tests/test_evie_gpu_runtime.py 3/3.
- Best of 3: 2989.9 ms (doc 2265.7, query 723.7).

## Gotchas recorded

- `gemm_strided_batched_ex` (f16) requires 256-byte-aligned per-batch
  pointers: packed-qkv head strides (64 f16 elements = 128 B) silently
  produce garbage for heads >= 1. Head planes must be padded to a 128-
  element stride.
- Two file-slicing edits with non-unique `s.index()` anchors duplicated
  the _attention..vision_forward region (shadow method definitions) —
  caught because the debug hook never fired; restored from git both times.
  Lesson: always assert-anchor uniqueness before slice-replacing.
