# Identify optional DP4A native-row public integration gap

## Summary

R0471's remaining public `ar_decode_native_rows` comparison cannot be obtained
by rerunning the optional-adapter selector. Public `LLM` generation uses the
resident submit/poll scheduler, whose multi-row step executes
`step_batch_native`. The separate compact native-row session used by
`_generate_greedy_batch` is not that scheduler's fallback. Adding a certificate
operation or changing a factory bit would not prove this integration.

## Changes

- Narrowed R0471's next action to the missing public scheduler integration,
  rather than another ordinary-row probe. The optional selected-call binding
  remains implemented; no execution default or arithmetic changed.
- This entry supplements
  `worklog/entries/20261031T213852.890921Z-r0471-selected-dp4a-intent-r0471-optional-selected-dp4a-intent-2c0b84.md`.
  Its suggested direct `Qwen35GGUFBringupGenerator` call is a compatibility
  diagnostic, not proof of the requested public scheduler route.

## Validation

- `bash /tmp/r0219-run-hip.sh /tmp/r0471-native-public.py /tmp/r0471-native-public-on.json on`
  and the corresponding off command both passed after `5c1edfd5e`.
  Public gfx1151 `LLM.generate_detailed()`, Qwen3.6-35B-A3B UD-Q4_K_M,
  production profile, two prompts of 17/23 tokens and six output tokens each.
  The enabled probe records 200 T16 dual launches and 200 quantizers; the
  disabled probe records neither. Both return allocator counts/bytes to their
  baselines. Their resident certificates cover `ar_decode_rows`/`ar_prefill`,
  not `ar_decode_native_rows`. These are route/lifecycle observations, not
  numerical-quality or performance claims.
- Source trace: `hipengine/llm.py::_construct_text_generator` installs
  `SubmitPollTextGenerator`. The resident executor's `step` uses
  `_step_native_chunk`/`step_batch_native` when packed decode is enabled,
  otherwise `_step_native_serial`. Disabling packed/stream controls does not
  redirect this executor into `_generate_greedy_batch`.
- `tests/test_live_generation_qwen35_gguf_sampling.py` explicitly asserts that
  the resident scheduler does not call either direct prompt-list loop.
- Only the gfx1100 UD-Q3_K_M factory sets `native_batch_decode=True`; its
  selected expert layout lacks an optional adapter. The Q4 factories leave it
  false. This factory restriction is separate from the scheduler ownership
  integration described above.
