# Fail-closed execution profile runtime plumbing

## Summary

Implemented public, torch-free `strict`, `production`, and `batch_invariant`
selection without adding a registry axis or changing the omitted-profile
runtime default. Explicit profiles now resolve once, before generator/resident
runner construction, to immutable model/backend/quant plugin plans over exact
kernel registry variants. Unsupported explicit profiles fail closed; missing
production or batch-invariant scopes use registered strict variants.

This unit changes no model/kernel default and makes no performance claim. It
deliberately does not label any incumbent Qwen3.6 route `strict` before P4
calibration and exact-control capture.

## Changes

- Extended `hipengine.execution_profiles` with a cold-path profile-plan registry,
  per-scope strict fallback merge, exact selected/fallback `KernelKey`
  validation, immutable resolved manifests, model-plugin factory/binder hooks,
  and `HIPENGINE_EXECUTION_PROFILE` normalization. Per-selection
  `registry_quant` preserves the real four-axis key when a layer's kernel quant
  differs from the model artifact quant.
- Added `LLM(..., execution_profile=...)` plus resolved profile, manifest,
  SHA-256, and strict-fallback introspection. The selected profile factory or
  binder runs before resident-runner construction; the shared engine-loop
  wrapper forwards immutable profile metadata. Omitting the selector bypasses
  plan resolution and retains incumbent package behavior during migration.
- Added server `--execution-profile`, environment selection, `ServerConfig`
  forwarding/validation, and model/capability discovery fields for requested
  and resolved profile, manifest hash, strict fallback, and migration status.
- Exposed `ExecutionProfile` from the public package and documented Python/CLI/
  environment behavior in `README.md`, `docs/ENVS.md`,
  `docs/EXECUTION-PROFILES.md`, `docs/PRODUCTION-NUMERICS-CAMPAIGN.md`, and
  `docs/REFACTOR.md`.
- Added RED-first synthetic plugin tests for full strict fallback, per-scope
  fallback, certified production override, unregistered-key rejection,
  immutable manifest binding, legacy-default preservation, API/environment/CLI
  normalization, and server forwarding. Test teardown restores the profile-plan
  registry alongside the kernel registry.
