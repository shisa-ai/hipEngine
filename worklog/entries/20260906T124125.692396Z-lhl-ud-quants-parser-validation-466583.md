# UD-U0a follow-up: range check runs despite unresolved descriptors

Follow-up to 20260906T123828.445073Z-lhl-ud-quants-parser-validation-17c24b.md
(UD-U0a parser validation audit repair). Fixes the sole outstanding reviewer
finding; no campaign checkbox or committed entry was modified.

## Summary

Fresh reviewer finding: in `scripts/gguf_quant_route_audit.py` `diagnose_header`,
the independent payload-range loop over resolved tensors was nested under
`if unresolved == 0:`, so any single unknown descriptor (qtype id outside the
registry) suppressed the range check for the successfully resolved tensors. A
file with one unknown descriptor plus an out-of-range known tensor reported only
`unparseable` and kept `data_complete=True` — the known tensor's missing payload
was never diagnosed. `data_complete = unresolved == 0` stays the initial value
(an empty resolved set must still read incomplete); the range loop now always
runs over the resolved tensors, and an out-of-range known tensor appends an
`incomplete_data` diagnostic and sets `data_complete=False`. Parser scope
otherwise unchanged; no broadened or refactored parsing.

## Changes

- scripts/gguf_quant_route_audit.py: dedented the existing range loop out of the
  `if unresolved == 0:` guard in `diagnose_header` so it always executes over
  successfully resolved tensors; `data_complete` initialization and the
  `incomplete_data` failure message are byte-identical to before.
- tests/test_scripts_gguf_quant_route_audit.py: new
  `test_unknown_descriptor_does_not_skip_range_check_for_known_tensors` writing
  `_header(3,2,0) + _descriptor('unknown', qtype=999) + _descriptor('known')`
  with no payload; asserts diagnostics == ["unparseable", "incomplete_data"],
  table_complete True, data_complete False, format_valid False.
