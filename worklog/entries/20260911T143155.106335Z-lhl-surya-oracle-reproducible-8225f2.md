# Surya greedy oracle fixtures are now reproducible byte-for-byte

## Summary

`tests/fixtures/surya/oracle_greedy.json` is the reference that
`test_surya_e2e`, `test_surya_public_api` and `test_surya_gpu` all gate on, and
it had no committed generator. `scripts/surya_oracle_torch.py` captures logits
and cache states but never emits greedy ids, so the fixture could not be
reproduced or audited.

`scripts/surya_oracle_fullpage.py` already contained the missing greedy
machinery, but was hardwired to the full-size page. Generalized it into
`scripts/surya_oracle_greedy.py` with a `--case {all,image,fullpage}` selector
and a shared `_greedy_from_page` helper, then verified that regenerating from
it reproduces every committed fixture **byte-for-byte**.

## Changes

- `scripts/surya_oracle_fullpage.py` -> `scripts/surya_oracle_greedy.py`
  (`git mv`, so history follows). New `--case` selector:
  - `image` (default part of `all`) — `page_small.png`, 64 greedy tokens ->
    `oracle_greedy.json`. Matches the committed fixture: 64 ids, grid
    1x16x16, prompt sequence length 106.
  - `fullpage` — `page_full.png`, 96 token budget (EOS at 78) ->
    `oracle_fullpage_greedy.json` + `oracle_fullpage.npz`.
- Pinned a canonical `_FULLPAGE_NPZ_KEYS` order. The merger hook fires
  mid-forward, so insertion order alone put `vision_merged` before
  `logits_first`; the explicit order matches the committed archive, which is
  what makes regeneration byte-clean rather than merely content-equal.
- `docs/MODEL-SURYA.md`: status row for fixture reproducibility; updated the
  full-page row to the new script name.
- `tests/test_surya_gpu.py`: two skip messages updated to the new script name.

`scripts/surya_oracle_torch.py` is untouched and still owns
`oracle_image.npz` / `oracle_text.npz` / `oracle_rect.npz`, which were captured
with an older transformers and remain non-reproducible; the new script's
docstring says so.

## Validation

`python3 scripts/surya_oracle_greedy.py --case all --device cpu` on the pinned
checkpoint, then compared against the committed fixtures:

| Fixture | Result |
| --- | --- |
| `oracle_greedy.json` | byte-identical (`cmp` clean) |
| `oracle_fullpage_greedy.json` | byte-identical (`cmp` clean) |
| `oracle_fullpage.npz` | byte-identical (`cmp` clean) |

Content was also checked array-by-array for `oracle_fullpage.npz` before the
key order was pinned: all eight arrays exact-equal, including
`vision_merged` (1024x1024) and `logits_first` (65425), so the only initial
difference was archive key order, not numerics.

`git status -s tests/fixtures/surya/` is empty after regeneration: the fixtures
are unchanged, which is the point — the generator reproduces them rather than
replacing them.
