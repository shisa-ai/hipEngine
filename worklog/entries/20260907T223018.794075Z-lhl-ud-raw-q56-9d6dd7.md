# Raw Q5/Q6 rank-2 residency with gfx1151 rowbatch prefill

## Summary

The decode-profile split by `grid_size_y` (prefill rows=121 vs decode rows=1)
showed the top decode kernel is the dense-BF16 GEMV serving expanded rank-2
Q5_K/Q6_K weights: 36.2% of decode GPU time, already at the 229 GB/s memory
ceiling over ~14 GB of expanded bytes. The only lever is reading fewer bytes.
This unit flips rank-2 Q5_K/Q6_K to raw GGUF residency, enables the WPF-1
rowbatch/coltile prefill machinery on gfx1151, and lands the default flip.

## Changes

- `qwen35_gguf_materialize.py`: rank-2 Q5_K/Q6_K specs plan
  `LAYOUT_RAW_GGUF` (previously non-rank-2 raw, rank-2 dense-BF16 expansion).
- `qwen35_gguf_consumer_surface.py`: `Q5_K` added to
  `RAW_LINEAR_SOURCE_QUANT_KEYS` / `_RAW_LINEAR_OUTPUTS` (Q6_K was already
  present); stale planner-truth comment corrected.
- `hip_gfx1151/__init__.py`: WPF-1 raw-Q5/Q6 rowbatch4/8/16/32 and
  coltile2/4 rowbatch kernels removed from `_GFX1151_ALIAS_EXCLUSIONS`;
  `GGUF_RAW_K_PREFILL_ROWBATCH_SUPPORTED=True`, `ROWBATCH=32`,
  `COLTILE_SUPPORTED=True`, `VARIANT="coltile"` (matching gfx1100). The
  kernels are the shared `gguf_k_gemv` family already running bit-exact
  locally; the previous exclusion was a qualification scope, not a defect.
- `gguf_linear.py`: `_raw_k_prefill_rowbatch` ContextVar default is now
  `None` (no owner) and `launch_gguf_linear` falls back to the backend
  package default when no owner selected a slab; an explicit owner 0 still
  disables the rewrite.
- New RED-first `tests/test_gguf_ud_km_raw_q56.py` (4 tests: raw planning,
  no-expansion guard, surface declaration, zero-refusal preflight).
- Updated planning-truth expectations that asserted the old expansion
  (`test_qwen35_gguf_materialize.py`, `test_gfx1151_backend.py`,
  `test_gguf_k_rowtile_gemv.py`). Also fixed a pre-existing
  `fake_materialize` signature drift (runner passes `requested_operations`
  since 296702ac7) and a stale UD-XL param-table expectation
  (`layers.8.ffn_gate` IQ4_XS has planned raw since 798fd9832; that

## Validation

- RED-first: the new K_M raw-Q56 test failed on planning/surface before the
  implementation and passes after; all listed suites green (E2E acceptance 6,
  materialize/UD admission/parity ~279 cases).
- Perf (gross, zbook, same command as the IQ-kernel artifact):
  K_M decode 5.52 -> 6.39 tok/s (+15.8%); prefill 9.2 -> 7.8 tok/s
  (-15%; without the rowbatch fallback the generic raw prefill measured
  4.6). K_S decode 6.04, prefill 7.0. Counted K_M weight buffers
  21,527 -> 16,550 MB (-23%).
- Numerics: context512 18-prompt teacher gate vs the F16-KV teacher with
  consumed-token histories verified equal to the input binary (the K_S
  input-mismatch lesson applied): new default mean 0.001128 / p95 0.003365 /
  p99 0.024571 / max 0.040433 / top-1 161/162, versus the old expanded
  default mean 0.0013153 / p95 0.0051020 / max 0.0346252 / 161/162. Mean
  and p95 improve; the tail is slightly worse but inside the 0.05 max gate.
  Neither default passes the full c1 aggregate gate (pre-existing recorded
  campaign state); the new default is closer on mean. Artifact:
  `benchmarks/results/2026-09-08-zbook-ud-raw-q56-residency.json`.
- Bit-exactness within the change: rowbatch/coltile prefill kernels are
  bit-exact vs the per-row prefill kernel; the IQ strict kernel is bit-exact
  vs its declared reduction. The only arithmetic change is raw
  dequant-on-the-fly replacing expanded-BF16 rounding, evaluated by the
  teacher gate above.

## Known regression

Prefill is 15% slower than the dense-BF16 default. The structural fix -
multirow weight reuse for the IQ family and bulk prefill scheduling - is the
U6 work; the rowbatch fallback already recovers most of the generic raw
prefill's 2x loss (4.6 -> 7.8 tok/s).
