# P1 device-driven grouped Q8_0 down owner

## Summary

Added the P1 device-driven grouped Q8_0 down owner that replaces the Q8
path's `group_expert_start` D2H copy + Python loop over 512 experts with a
single launch that reads `expert_start` on device and iterates experts via a
fixed worker grid (no host roundtrip). This targets the layer-2 (Q5_K/Q5_K/
Q8_0) and layers-4/30/46/47 (Q4_K/Q4_K/Q8_0) expert-down family, the first
P1 punchlist unit after the inventory RED gate.

## Changes

- New HIP kernel `q8_0_selected_grouped_prefill_bf16_bf16_kernel` in
  `hipengine/kernels/hip_gfx1100/quant/gguf_q8_0_prefill.hip`, mirroring the
  Q5_1 device-driven grouped rowbatch8 dataflow. ABI:
  `(input[compact, in], expert_start[E+1], weights[E,out,in]_q8_0,
  output[compact, out])`. BF16-in/BF16-out with an fp32 reduction tree.
- Python wrapper `gguf_q8_0_selected_grouped_prefill_compact_bf16_bf16_out`
  plus `__all__` export in `gguf_q8_0_prefill.py`.
- Runner wiring in `qwen4_exp_runner.py`: the Q8_0 down branch now selects the
  device-driven owner under `HIPENGINE_QWEN4_EXP_Q8_0_GROUPED=1`; the legacy
  D2H+WMMA loop (`..._Q8_0_GROUPED_WMMA`) and the strict per-expert selected
  gemv remain available opt-outs. Strict stays the default until the full P1
  packet gate passes.
- RED test `tests/test_qwen4_exp_q8_0_grouped_down.py`: BF16-exact to
  `gguf_q8_0_gemv` per grouped row across layer-2-down shape (in=640,
  out=2560), route-order/empty-expert/uneven-tail cases, and a small shape.
- Inventory RED gate `tests/test_qwen4_exp_moe_inventory.py` (quant/shape/
  owner map) from the same unit.
- Docs: KERNELS.md catalog row, REFACTOR.md flag-removal ledger.
