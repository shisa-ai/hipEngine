# Close packed verifier timing recorder on every exit

## Summary

Confirmed the R0281-VERIFY-TIMING teardown gap at `91b27fff0` and closed it.
`Qwen35GGUFResidentSession.verify_target_blocks_batch()` created and started
the opt-in `_HipEventStageRecorder` before embedding, then resolved it only on
the success path. An exception in embedding, layer execution, sampling, or
output scatter left every created HIP event handle unreleased; the recorder's
own resolve-time `finally` could not cover that interval. The packed caller now
owns the recorder through a scope that starts it on entry, resolves it on a
successful exit, and closes it on every exit. The default no-timing path and
the `device_result` bypass are unchanged, and no arithmetic or profiling
default changed.

## Changes

- Added `_close_gguf_stage_recorder()`: closes a recorder twice (the event
  recorder retains handles whose destroy failed so a later close can retry),
  suppresses a persistent cleanup error while a verification exception is
  propagating, and raises it only when no other failure is in flight.
- Added `_PackedVerifyGpuStageRecorderScope` in the existing timing owner,
  re-exported by the runner: starts the recorder on
  `__enter__`, closes it if start fails, resolves on a clean `__exit__`, and
  closes on every exit. `None` recorders are inert, preserving the default
  path.
- Rewrote the packed verifier body from embedding through the final sync as a
  `with _PackedVerifyGpuStageRecorderScope(gpu_stage_recorder, stage_timings)`
  block and removed the explicit `start()`/`resolve_into()` calls. The
  `packed_verify_total` timing still lands after the scope exits.
- Added `tests/test_unit_qwen35_gguf_verify_timing_teardown.py`, which drives
  the real method with CPU stand-ins for GPU work and injects failures at
  recorder start, embedding, layer execution, head sampling, scatter,
  resolve synchronize, and resolve-time destroy. Parent review added a RED
  simultaneous synchronize/destroy failure and repaired
  `_HipEventStageRecorder.resolve_into()` so cleanup cannot mask resolution
  failure. Retained handles remain retryable.
- Added HIP-guarded `tests/test_gpu_qwen35_gguf_verify_timing_lifecycle.py`
  using real event/stream APIs for success and injected start/body/resolve
  failures, with exact created/destroyed handle accounting.
