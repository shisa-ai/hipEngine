# D2a: Native DFlash2 conv + top-16 + selector kernels (RED vs CPU oracle)

## Summary

The two DFlash2-specific native mechanisms are now exact GPU kernels, RED-pinned
against the D0 CPU-reference oracle: the grouped dynamic causal conv
(prepare/finish with strided side views over the 1280-wide projection) and the
low-rank bilinear candidate selector (top-16 + `A(pred)⊙H(h_t)·B(cand)` scores +
greedy walk). Registered for `hip_gfx1100` and `hip_gfx1151`. D2b (attention +
full 5-layer forward wiring) remains.

## Changes

- `hipengine/kernels/hip_gfx1100/speculative/dflash2.hip`:
  - `dflash2_grouped_conv_kernel`: two-tap grouped dynamic causal conv with
    `dyn_offset`/`dyn_stride` so one projection buffer (1280 wide) serves both
    the input side (offset 0) and output side (offset 2*groups). BF16 in/out,
    FP32 accumulate, single output round-trip (zero-padded first row).
  - `dflash2_top16_rows_kernel`: row-wise descending top-16 over FP32 logits
    (one block per row, partial per-thread top-K, block reduce), K=16.
  - `dflash2_selector_proj_kernel` (hidden 5120->256 context gate) +
    `dflash2_selector_walk_kernel` (one thread walks positions, gathering
    predecessor/candidate codebook rows and scoring 16 candidates/position).
- `hipengine/kernels/hip_gfx1100/speculative/dflash2.py`: build + ctypes
  wrappers + registry entries; exported via the speculative package `__init__`
  so `register_gfx1151_kernels` mirrors them to gfx1151 keys.
- `tests/test_dflash2_native_kernels.py`: 6 GPU RED tests (conv standalone,
  conv prepare+finish at rows 1/7/64, top-16, selector). RED contract: BF16
  inputs, CPU oracle on BF16-rounded inputs, and the oracle models the native
  BF16 round-trips (projection output, conv output) so the comparison isolates
  the kernel math.

## Validation

- `uv run pytest tests/test_dflash2_native_kernels.py tests/test_dflash2_cpu_reference.py
  tests/test_dflash2_drafter.py tests/test_dflash2_gguf_capture.py
  tests/test_dflash_metadata.py -q` — 39 passed, 1 pre-existing skip.
- gfx1100 + gfx1151 registry keys present for all three kernels.
- Finding: the WMMA `dflash_dense_bf16_to_bf16_wmma` path has a pre-existing
  rows<16 gfx1151 precision quirk (~0.3% max rel on a few elements for
  rows=1, 5120->1280), while the naive path is exact (4e-8). The conv RED test
  forces the naive projection. This affects the DFlash drafter's small rows<16
  projections if they ever run under the default WMMA env flag; recorded here,
  not chased (out of D2a scope).
