# Remove redundant profile manifest environment publication

## Summary

Execution-profile manifest identity already belongs to the resolved plan and
is copied onto the generator by `ResolvedRuntimeProfile.construct_generator()`.
`LLM` exposes its own resolution through metadata properties; server
capabilities consume those properties, not an environment variable. Remove the
two redundant binder writes rather than adding another identity carrier.

## Changes

- Remove `HIPENGINE_EXECUTION_PROFILE_MANIFEST_SHA256` publication from the
  gfx1151 dense GGUF and Qwen4Exp binders. No runtime reader exists in
  `hipengine/` or `scripts/`; the remaining uses were test expectations and the
  environment reference. Existing caller values remain untouched and inert.
- Keep manifest construction, hashes, generator metadata, native graph keys,
  server capabilities and HTTP response metadata unchanged. No arithmetic,
  selected variant, default, admission rule or capability changes.
- New profile tests construct strict and production owners in both orders,
  check both owners after each construction and preserve either an absent or
  unrelated ambient value. Qwen4Exp also confirms the unused variable no
  longer appears in pre-binder conflict reporting.
- Narrow-GDN and dense-wide-tail tests use the actual
  `construct_generator()` metadata seam instead of asserting a binder's
  process-global publication.
- Update `docs/ENVS.md` and remove only the completed manifest-publication
  work from R0137 in `docs/REFACTOR.md`. Other profile migrations remain open.
