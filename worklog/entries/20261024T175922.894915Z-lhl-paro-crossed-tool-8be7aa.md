# Add a CPU-validated public crossed-state capture tool

## Summary

Add `scripts/mtp_paro_crossed_state.py` for public AR/MTP carried-state,
identical-state verifier, physical-width and route-flag comparisons. Its CPU
orchestration and integrity checks pass; the new tool has not completed a live
GPU capture. Task 17 remains open pending release of the shared W7900, as
recorded in `20261024T174941.091096Z-lhl-paro-crossed-capture-progress-705175.md`.

## Changes

- Run public `LLM.generate_detailed()` and
  `LLM.generate_speculative_mtp_detailed()` arms, capturing full logits, hidden
  rows and selected Conv/GDN/KV state around a requested output-index window.
- Add opt-in `--cross-widths 2,3,4` and
  `--cross-profiles strict,production`. Widths share the same incoming state,
  absolute positions and token prefix. Wider suffix rows use fixed AR teacher
  tokens, including tokens beyond the public output budget; these extra rows
  are explicitly diagnostic and do not extend the public MTP request.
- Preserve the actual incoming verifier attention mode. Profile comparisons
  change arithmetic route flags only, holding that attention mode fixed; they
  are not a comparison of two complete end-to-end execution profiles.
- Restore state and per-hook post-binder route selectors before the untouched
  public replay, then require exact public logits and committed state. Record
  hook failures, recoverable cycles, missing comparisons and raw artifacts;
  any integrity failure prevents a complete report.
- Reserve three candidates for four verifier rows, prepare wider scratch when
  needed and restore public scratch dimensions before replay. Match the real
  resident verifier's required arguments and validate that API in the fake.
- Keep verifier-carried rows as the sole canonical numerical sample. Put
  AR-carried, width, profile and cross-history comparisons in diagnostic
  observations; they are paired checks, not additional independent tokens.
  Mark profile state comparisons incomparable when commit positions differ.
- Hash the adapter, profile binder, resident runtime and numerical helpers.
  The tool emits observations and completeness status only, never an admission
  or production-policy gate. CLI exits: 0 complete, 1 incomplete, 2 usage,
  3 failed. `--help` requires no GPU.

  pre-binder environment restoration, mismatched declared/public attention mode,
  duplicated canonical rows and absent requested profile comparisons. Tail
  teacher reservation and scratch-capacity/restoration contracts have CPU tests.
- `uv run pytest -q tests/test_unit_mtp_paro_crossed_state.py` passes 92 cases.
  The final affected CPU bundle passes 443 cases across this file, numerical,
  aggregate/repeat and fast-state tests, acceptance fallback, depth/provider,
  PARO seam, resident layout and verifier-context tests.
- `uv run ruff check scripts/mtp_paro_crossed_state.py
  tests/test_unit_mtp_paro_crossed_state.py`, `compileall`, `--help` and all four
  documentation gates pass. The audit gate passes without a budget change.
- Independent read-only follow-up confirms all four original material findings
  are repaired and identifies no remaining material defect in that scope.
  Source review and fake-device tests do not establish live GPU compatibility.
- The earlier final-batch attempt failed during model allocation before the
  verifier hooks ran. It exposed the shared-GPU resource conflict, not a
  numerical result. No new-tool performance or numerical-policy claim is made.
