# Add W0 target-window and sweep-economics instrumentation

## Summary

Implemented the first half of extension W0 before any W1 kernel work. GGUF MTP
telemetry now records `perf_counter_ns` boundaries for target submission and
for the full target-through-accept/commit drain window. The wider window is
required because packed target kernels drain asynchronously inside the measured
accept interval. `scripts/mtp_cycle_accounting.py` can correlate those windows
with `rocprofv3` kernel and `FETCH_SIZE` counter CSVs, group target costs by physical
row count and Q4/Q5/Q6 family, and publish measured video-memory fetches.

The accounting output also publishes the campaign's cycle-economics metric.
On the preserved C6/C8 K1 raw run it reproduces **2.1055 / 2.1375 AR-step
equivalents per speculative cycle**, versus **1.7013** required for 1.15x at
the observed 95.65% acceptance. The script distinguishes this steady-cycle
metric from the D24 bootstrap/tail-inflated observed output-per-cycle value.
This is instrumentation only and makes no performance claim.

## Changes

- `hipengine/generation/qwen35_gguf.py`: add target-submit and complete
  target/accept-drain timestamp telemetry and export it in resident observability.
- `hipengine/generation/qwen35_gguf_mtp2.py`: timestamp singleton and physical
  packed target cycles with the host monotonic clock used by rocprofv3.
- `scripts/mtp_cycle_accounting.py`: add steady cycle economics, de-duplicated
  shared-stage milliseconds, static target/proposal weight inventory,
  cycle-window reconstruction, Q4/Q5/Q6 kernel classification, and optional
  `FETCH_SIZE` per-family row curves.
- `tests/test_mtp_cycle_accounting.py`: RED/GREEN coverage for the metric,
  timestamp reconstruction, target-window filtering, quant-family parsing,
  and model-stage ownership.
