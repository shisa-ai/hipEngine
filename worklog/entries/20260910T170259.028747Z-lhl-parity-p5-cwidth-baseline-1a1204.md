# P5 C>1: cwidth decode baseline - the IKV-C2 justification

## Summary

The honest current-state reference the roadmap requires before any C>1
consumer work: N concurrent fixed-fixture completions (2,048-row prompts,
63 decode tokens each, greedy, clean teardown at every width) on the real
INT8 server, one launch per width.

## Changes

- `scripts/gguf_server_cwidth_probe.py` (new) + HARNESSES row + artifact.
- The C>1 gate keeps the per-width pool lease by design, so the
  measurement includes its cost.

## Validation

- C1: 28.4 tok/s aggregate decode.
- C2: 17.6 tok/s aggregate - 31.0% of the serial-aggregate reference
  (2 x 28.4 = 56.8).
- C4: 14.7 tok/s aggregate - 12.9% of serial (4 x 28.4 = 113.6).

The packed batch decode is currently WORSE than the equivalent serial
lanes: batched decode per token costs more than C independent singleton
steps. This is the measured justification for the IKV-C2 row-batched
consumer project (row-batched split-K producer/reducer, scale-aware
per-request KV views, deterministic row isolation) and its acceptance
baseline.

## Next

- IKV-C2 implementation is the multi-day packet; its gate is aggregate
  C2/C4 at or above the serial reference with per-request latency and
  aggregate throughput reported separately.
