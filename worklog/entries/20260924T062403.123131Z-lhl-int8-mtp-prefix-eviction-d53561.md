# Prefix eviction under MTP with reuse parity

## Summary

Prefix hit/miss and eviction under pressure are now gated with MTP enabled and
disabled. `scripts/int8_mtp_prefix_pressure_gate.py` drives the retained prefix
working set to eviction while speculative requests run, and asserts the miss, the
hit, the request diagnostics, the generated ids and the provider position against
the same workload on a cache-disabled server. The gate passes on this host.

The task's premise that eviction needs luck is wrong: the retained working set is
bounded by the request capacity, one durable boundary per active request, and
`_trim_prefix_snapshots` evicts oldest-first. Seeding `2 x capacity` distinct
prompts therefore evicts the oldest half deterministically.

## Changes

- `scripts/int8_mtp_prefix_pressure_gate.py` (new): takes a radix server and a
  cache-off server of the same capacity, verifies each server's `/ready`
  `prefix_cache.mode` rather than trusting the launch, seeds `2 x capacity`
  distinct prompts (the last pair concurrently, so an overlapping speculative
  request is in flight while the cache evicts), then probes four requests:
  evicted + speculative, evicted + autoregressive, resident + speculative,
  resident + autoregressive. It asserts the two miss causes separately
  (`"miss"` versus `"provider_checkpoint_unavailable"`), the reused/matched/
  executed-prefill bookkeeping, the residency bound, ids parity across the reuse
  axis for every probe, and ids parity between the speculative and
  autoregressive arms over the same reused KV.
- `docs/reference/INT8-MTP-SERVER-READINESS.md`: the prefix checklist item is
  split. Hit/miss and eviction under pressure are checked with their exact tested
  scope; reuse after a cancelled request stays open and names the live lifecycle
  arms as its owner. The command list gains the pressure gate, and the override
  note records that it needs two servers plus a matching `--capacity`.

## Validation

Launched on this host, both with `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED=1`
(this artifact has a recorded INT8-KV quality rejection, so the override is
explicit), `--backend hip_gfx1151 --kv-storage int8_per_token_head
--served-model-name int8-mtp --max-active-requests 4 --max-context-tokens 8192`,
one with `--prefix-cache radix` and one with `--prefix-cache off`:

    .venv/bin/python scripts/int8_mtp_prefix_pressure_gate.py \
      --base-url http://127.0.0.1:8098 --no-reuse-base-url http://127.0.0.1:8099 \
      --model int8-mtp --capacity 4 --allow-kv-diagnostic-override \
      --json /tmp/int8-mtp-prefix-pressure.json

Result: `passed: true`. Recorded evidence:

- Radix `/ready`: `mode radix`, `retained_snapshot_limit 4`, `snapshot_limit 4`.
  Cache-off `/ready`: `mode off`, `fallback_reasons {"cache_off": 3}`.
- Seed residency series `[1, 2, 3, 4, 5, 5, 5, 5]`: the retained set stops
  growing at 5 against a capacity of 4, so eviction is exercised.
- `evicted_mtp`: `fallback_reason "miss"`, `matched_tokens 0`, `reused_tokens 0`,
  8 speculative cycles. `evicted_ar`: the same miss.
- `resident_mtp`: `hit`, `matched_tokens 512`, `reused_tokens 512`,
  `source completed_snapshot`, `cache_resident_entries 4`, 8 cycles.
  `resident_ar`: the same hit.
- `resident_mtp` ids equal `resident_ar` ids exactly (24 tokens), and every one
  of the four probes returns the same ids on the cache-off server.

Two harness facts worth keeping. A miss re-populates a boundary, so the two arms
of an evicted probe must use different prompts: the second request on the same
prompt legitimately hits, and the first version of this gate failed on exactly
that. A hit refreshes the boundary it just used, so the resident probe can reuse
one prompt for both arms. True request overlap was not achievable here: the
startup scratch probe runs at width 1 on this host (4 concurrent sessions need
208.20 GiB against 57.07 GiB usable), so the concurrent tail serializes.
