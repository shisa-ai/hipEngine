# RT-1's promotion blocker set is reduced to four named items; promotion stays correctly blocked

## Summary

RT-1 (prefill chunk 4096) is a measured, exact, non-regressive win: **-4.28% to -4.94% at
p4096**, indistinguishable at p1024, and **bit-identical logits on 12 of 12 canonical cases**.
`AGENTS.md` promotes such wins "unless there is a concrete blocker recorded in a durable
worklog entry" - and there is one, in `docs/REFACTOR.md`.

**So not promoting is the correct action.** What this entry does is establish that the
blocker set is now **four precisely-named items** rather than the open-ended
"short-request costs keep 1024 as the default", and that the three largest are cleared with
measurements.

## The mechanism already exists, is tested, and is deliberately unwired

This changes the remaining work from "build a shape policy" to "enable and qualify one".

| piece | state |
|---|---|
| `Qwen4ExpPrefillWorkspace` | owns prefill scratch/inputs independently |
| `_allocate_extra_prefill_workspace` | prepares an inactive runner-owned owner |
| `_configure_prefill_workspace_selection` | selects among prepared owners; allocates nothing; restores borrowed fields on failure |
| per-request selection | `next((w for w in choices if len(tokens) <= w.prefill_chunk_size), choices[-1])` |
| unit coverage | `tests/test_unit_qwen4exp_prefill_owner.py` - ordering, duplicates, foreign owners, capacity, reserve |
| memory accounting | `scripts/qwen4exp_owned_workspace_check.py` - exact budget, decode state preserved |
| **production wiring** | **absent - no caller outside tests** |

## Cleared this session, with measurements

1. **Numerical qualification at the new chunk** - the X-6 chunk-4096 gate passes
   **bit-identically** to chunk 1024: all five KL metrics to the last digit, both logits
   hashes, 12 trajectory hashes, 3 repeats.
2. **Arithmetic neutrality / preserve strict setup** - chunk 1024 vs 4096 publishes
   **identical `logits_sha256` on 12 of 12 canonical cases**.
3. **The short-request loss** - p512 chunk-4096 is **+0.46% mean, smaller than the
   within-arm spread**; p1024 is -0.39%. Indistinguishable, not a loss.

## Still open

1. **"Measure short/long requests on the same prepared owners"** - the specific gap. Every
   measurement so far, including RT-1's and RT-3's, used **one process per arm**, so the
   selection path itself has never been exercised end-to-end on a prepared pair. This is the
   next concrete step and it is bounded.
2. Qualify full state/lifetime and c2 behavior on the selection path.
3. Account for all owners and host staging in public construction - the selector's reserve
   check is explicitly *not* public memory admission.
4. Allocation and lifetime gates for the selector.
