# TP2 Packet 0/1/2: topology screening, rank-bound transport, and byte-preserving GGUF shards

## Summary

Three of the four pre-integration packets are now measured or implemented on the
`tp2` branch: the host/PCIe topology and collective screen (Packet 0), the
rank-bound distributed plan/context and RCCL group transport (Packet 1), and the
immutable TP=N shard planner with byte-preserving GGUF materialization
(Packet 2). No tensor-parallel engine exists yet and no TP speedup is claimed.

Two findings change the shape of the work:

1. **Peer DMA is unavailable on this host, for two independent reasons.**
   `hipDeviceCanAccessPeer` is false in both directions and
   `hipDeviceEnablePeerAccess` fails with HIP error 101. Both cards expose a
   256 MB BAR while the kernel advertises a resize attribute, so the GPUs were
   not brought up with Resizable BAR / Above 4G Decoding. Independently, every
   bridge between the two cards has ACS redirection enabled (see below), which
   sends peer TLPs to the root complex even when the BARs are large enough. All
   collectives therefore host-stage at ~8 GB/s of payload instead of direct peer
   bandwidth. Decode is latency-bound and already acceptable at that bandwidth,
   but prefill and weight movement are not.
2. **The GDN value-head axis is in llama.cpp's tiled order, not a contiguous
   head order.** `k_head = v_head % ssm_group_count`, and the fused `attn_qkv`
   row order is q, k, then a value block that is three tiles of the key-head
   count. A contiguous split of value heads would silently give each rank the
   wrong key head; the planner instead splits the key-head axis contiguously and
   cuts each value tile the same way, which also keeps every `ssm_out` column
   range a whole number of 256-element quant blocks.

## Changes

### Packet 0: topology and collective screening

`scripts/tp_host_inventory.py` and `scripts/tp_collective_bench.py` produce
`benchmarks/results/tp2_host_inventory.json` and
`benchmarks/results/tp2_collective_bench.json` on the target host.

Host and devices (from the artifact):

- Ryzen 9 5950X, 32 threads, 62.7 GiB RAM, one NUMA node, kernel 7.1.3-2-cachyos.
- HIP 0: Radeon Pro W7900, 44.98 GiB total / 44.95 GiB free, `0000:0d:00.0`.
- HIP 1: RX 7900 XTX, 23.98 GiB total / 23.95 GiB free, `0000:10:00.0`.
- Both on separate CPU root ports (`00:03.1`, `00:03.2`), PCIe 4.0 x16
  (`LnkSta: Speed 16GT/s, Width x16`, and `current_link_width` 16, confirmed
  under collective load, not just at rest). `rocm-smi`'s `pcie clock level`
  string and `pp_dpm_pcie` both say `x8`; that is the driver's DPM capability
  table, not the negotiated link, and reporting it as the live width is wrong.
- `can_access_peer` false in both directions; `enable_peer_access` -> HIP 101.
  `resource0_resize` reports resizable support (`0x1ff00` W7900, `0xff00` XTX)
  but the live BAR is 256 MB on both.
- **ACS redirection is enabled on the whole path between the cards**: root ports
  `00:03.1`/`00:03.2` and bridges `0c:00.0`/`0f:00.0` all report
  `ACSCtl: SrcValid+ TransBlk+ ReqRedir+ CmpltRedir+ UpstreamFwd+`, which
  redirects peer TLPs to the root complex. The GPU endpoints themselves carry no
  blocking bits. So peer DMA needs both Resizable BAR / Above 4G Decoding *and*
  ACS redirection off on that path; the second is an IOMMU-isolation tradeoff
  and was deliberately not changed for a benchmark.
- IOMMU is enabled (41 groups); `kernel_cmdline_iommu` is empty. Extended PCIe
  capability space needs root, so `tp_host_inventory.py` retries once through
  `sudo -n` (never prompting) and records `read_via` plus `access_denied`, since
  an unreadable ACS block must not be reported as "no ACS".
- Peer copy, host-staged: 1 MiB bidirectional 5.89 GB/s (cv 1.8%).

Collective latency, full row ladder (rows 1-5 plus 128 and 1024, both dtypes,
both operations, both enqueue modes, both root orders): 28 cases verified with 0
errors (chain N = N dependent all-reduces in one
`ncclGroupStart`/`ncclGroupEnd` group):

Broadcast reaches a higher payload rate than all-reduce because each payload
moves once instead of twice. The earlier run of the same protocol measured the
20 KB case at 28.0 us marginal (253.4 -> 337.5 us), so small-message latency
carries roughly +/-20% run-to-run variance and the decode budget is quoted as a
range. bf16 halves the 1024-row time, as payload-proportional transport should.

Enqueue cost: 49-61 us for a one-op group, 128-166 us for a four-op group, i.e.
~28 us per op inside a group plus ~22 us per group. Threaded enqueue is worse in
every case (1 row fp32 chain 1: 428.6 vs 338.8 us device, 279.8 vs 50.2 us
enqueue; 1024 rows fp32 chain 1: 2954.1 vs 2724.8 us device), so single-thread
group enqueue is the default and no host threads are needed.

Decode budget: 36 collectives/token (2 per MLP, 2 per full-attention, 2 per GDN
layer) x 28-35 us = **1.0-1.25 ms/token**, which is 3-6% of the current
same-host single-GPU decode time (W7900 27.9 tok/s = 35.8 ms/token; XTX
29.82 tok/s at 8192 context = 33.5 ms/token). Halving per-rank weight traffic
(8.65 GiB at the measured ~500 GB/s) projects ~17-19 ms/token, i.e. **1.7-1.9x**,
above the plan's 1.3x target. This is a projection from measured collective
latency and measured single-GPU bandwidth, not a measured engine result.

Prefill budget at 1024 rows: 2.593 ms fp32 or 1.309 ms bf16 per all-reduce x 36
= 93 ms or 47 ms per 1024-token chunk, against 1.18 s of single-GPU prefill at
868.6 tok/s. bf16 transport is the right default for the prefill path.

### Packet 1: rank-bound plan, context, and transport

`hipengine/distributed/`:

- `plan.py`: ordered unique device list, `world_size`, control/draft owners,
  per-rank local geometry, collective schedule with ordered reduction
  boundaries, topology fingerprint, deterministic serialization and hash.
  Rejects duplicate devices, mixed backend/architecture groups, and degrees the
  model cannot support before allocation.
- `context.py`: one rank-local context per rank (device, stream, communicator
  handle, workspace) with scoped current-device selection and restore, plus
  explicit teardown. Group profile is resolved once, not per rank.
- `transport.py`: rank-group `broadcast`/`all_reduce_sum` interface with
  completion and error reporting, sequence/epoch validation, and no model or
  scheduler policy.
- `rccl.py`: `ctypes` binding to `librccl.so` (no torch import) that binds the
  `nccl*` symbols against the installed library, initializes communicators
  separately from collectives, and enqueues each segment as one group.
- `mock.py`: deterministic host-side reference transport for tests.

The measured group semantics matter for the serving path: because one group
covers a whole chain and the first rank's collective does not block the second
rank's enqueue, the layer loop can enqueue every rank's producers and matching
collectives before any wait. Nonblocking communicator/abort handling and the
supervised-diagnostic split from `docs/QWEN38-27B-GFX1100-TP2.md` are still
outstanding and are not claimed here.

### Packet 2: shard planner and byte-preserving materialization

`hipengine/loading/qwen35_gguf_shards.py` resolves one tensor rule per GGUF
tensor into per-rank byte segments and local shapes, then materializes each
rank's payload as a compact copy of the original quant blocks.

- Kinds: `column` (output axis), `row` (input axis, block-aligned), `group`
  (complete head/state groups, possibly multi-segment for fused tensors),
  `replicated`, `owner`.
- Row splits store a compact per-row layout instead of one segment per row, so
  a full manifest stays small (631 KB of canonical JSON for this model).
- `validate_plan_coverage` sweeps the byte ranges and requires an exact tiling
  with uniform multiplicity: no gaps, no overlapping ownership, and replication
  only when it applies to every byte equally. Ragged replication (which would
  double-count a head in the row-parallel sum) is rejected at plan time.
- Degrees are refused before allocation when a head count does not divide
  evenly or a column range is not a whole quant block.
- `gdn_head_map` exposes the global-to-local key/value head mapping that a
  rank-local GDN kernel needs (`local_k_head(local_v) = rank * local_k_heads +
  local_v % local_k_heads`).
- `iter_rank_payloads` is the loader-facing path: it yields one
  `(plan, payload)` at a time so a rank uploads and drops each local tensor
  instead of holding a model copy. `materialize_manifest` (which holds every
  rank's payload) stays a test oracle. `streaming_memory_report` records the
  peak anonymous and resident bytes of that path.

Measured on the real model, rank 1: the N=2 shard set is 7.01 GiB across 851
tensors whose largest member is 34.9 MiB, and streaming the whole set grows
anonymous memory by **36.1 MiB** (N=4: 3.51 GiB across 851 tensors, 17.4 MiB
largest, 37.6 MiB growth). A rank therefore never allocates a second full target
model; the residual growth above one tensor is allocator arena reuse, not a
per-tensor leak. Resident bytes are reported separately because they include
reclaimable file-backed page cache from the source memmap.

Qwen3.8-27B `Q4_K_M` inventory: 851 autoregressive tensors, 15.65 GiB, 64 AR
blocks; the MTP block (`blk.64.*`, 15 tensors) is excluded from the AR set by
`config.ignored_block_ids` and recorded in the manifest notes.

| Degree | rank bytes | manifest hash | byte-exact round trip |
| --- | --- | --- | --- |
| N=1 | 15.652 GiB | `c6dc8b6953a6` | 851/851 tensors |
| N=2 | 8.646 / 7.009 GiB | `6ee685942825` | 851/851 tensors |
| N=4 | 5.143 / 3.506 / 3.506 / 3.506 GiB | `a450ff358957` | 851/851 tensors |
| N=3 | refused | — | `blk.0.attn_gate.weight: segment [0, 2048) holds 16 groups, which does not divide evenly across 3 ranks` |
| N=8 | refused | — | `blk.0.ffn_down.weight: row split of [0, 17408) gives 2176 columns per rank, which is not a multiple of the 256-element quant block` |

`owner_rank` places the rank-owned embedding and vocabulary head (1.64 GiB
together) on the W7900, which keeps the XTX at 7.009 GiB and leaves the larger
card holding the uneven remainder.

Per-tensor layout decisions that the kernel contract forces:

- `attn_q` rows are `[q_head, gate_head]` interleaved (`qwen35_split_qgate`
  addresses `(token * num_q_heads + head) * 2 * head_dim`), so one indivisible
  group is `2 * key_length` and a head-range split is contiguous.
- Full attention uses contiguous query-head ranges with their grouped KV heads
  (`kv_head = q_head / (num_q_heads / num_kv_heads)`), and `attn_output` row
  ranges are whole query heads.
- GDN `attn_qkv`/`ssm_conv1d` rows are q, k, then value tiles; `ssm_out`
  columns are the same value-head axis, so its row split is per tile
  (1024 columns = 4 Q5_K blocks per rank at N=2).
- `ssm_norm`, `attn_q_norm`, `attn_k_norm`, and the two per-layer norms are
  replicated; the GDN per-head RMS norm is local because each rank owns whole
  value heads.
