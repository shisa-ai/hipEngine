# Screen live-column Inkling bias projection

## Summary

Computing only live relative-bias columns reduced host matrix-product time, but the shorter NumPy product did not preserve the reachable bias bits. The runtime continues to calculate the existing full bias and trim only the upload.

## Changes

- Scratch only. Capture real scalar decode inputs and weight views through public generation, then replay the full bias product and a view restricted to the live columns. Leave the production path unchanged.

## Validation

- On `epyc` (W7900, gfx1100), mainline `UD-Q4_K_M`, `f28bf4278672e4b0e78ca6f2411b0233f317b170`, `fast` manifest `ec04e8bdf2c53c55ebe895c0f905f388a72bb691af0658265dfc8b4676e1cb27`, FP32 KV, greedy, no reuse or drafting, use `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. HIPENGINE_REQUIRE_CACHED_BUILD=1 python -u /tmp/hipengine_inkling_bias_live_columns.py "$model" "$revision"`. At each of 47, 151, 575 and 1,027 input tokens, captured 192 visit products across four ordinary decode steps.
- Slicing reduced the median of the shape-level time medians from 11.59 to 1.47 microseconds at 47 input, but changed reachable output bits at all three depths below the full bias window. The maximum absolute error was `1.91e-6`. At 1,027 input all columns were live and results were identical. The isolated comparison timed 16 products per arm in alternating order and did not measure a request speedup. Log: `/tmp/kendex-pi-bg/bg-281-1795422866279.log`.
