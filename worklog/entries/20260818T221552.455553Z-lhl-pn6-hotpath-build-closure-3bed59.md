# PN6 follow-up: 0 per-call build_hip calls on Qwen3.6-35B decode hot path

## Summary

After the PN6 GEMV library hoist (`pn6-gemv-lib-hoist`), a broad census of
`build_hip` calls during Qwen3.6-35B-A3B UD-Q4_K_M eager decode records **zero
build_hip calls over 2 decode steps**. Every kernel library the decode path
needs is either hoisted (PN5 router, PN6 q8_0_t16 / q6_k_t16 / dense_gemv) or
preloaded once at session init (active-expert FFN, attention, norms, MoE). The
remaining per-call `library or build_X(load=True)` sites in
`moe/group_scatter.py` (12), `moe/laguna_router.py` (4), and
`moe/maple_moe.py` (1) are **not on this model's decode path** — the
`qwen35_moe_group_scatter_gather_lowp` wrapper is called 0 times over 3 decode
steps (those routes serve other models / registration paths). This closes the
609-site per-call-build concern for this model's eager decode.
