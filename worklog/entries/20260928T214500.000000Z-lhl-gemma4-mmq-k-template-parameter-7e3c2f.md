# MMQ_K is now a template parameter, so a wider K pass needs no new struct

## Summary

`20260928T210000` found that widening the K staging spans a struct shared by every MMQ32
kernel in the file, and `20260928T212000` quantified why the widening is worth it (176
barriers per block against 5632 dp4a per thread). **This entry lands the first half of the
edit: `MMQ_K` is a template parameter, and the containment problem disappears.**

The struct was never the real obstacle. **The staging formulas already generalize to a global
subblock index**, which is what makes a wider pass a mechanical change:

| what | narrow pass (`k32`) | general (`g = kk * KSUB + s`) |
| --- | --- | --- |
| weight block | `k32 >> 3` | `g >> 3` |
| weight subblock | `k32 & 7` | `g & 7` |
| activation block | `k32 >> 2` | `g >> 2` |
| activation ds4 index | `k32 & 3` | `g & 3` |

A Q4_K superblock is eight subblocks and a `block_q8_1_mmq_ds4` is four ds4 groups, so the
`>> 3` and `>> 2` are the 256- and 128-element groupings **already present in the data**. The
narrow pass just happens to walk them one 32-element slice at a time. **Nothing about the
cache structs encodes the pass width** -- `q4_k_mmq32_cache` holds exactly one subblock, so a
`KSUB`-wide pass indexes `weight_tile[col * KSUB + s]` and needs no new type.

## What landed

```cpp
template <int WEIGHT_LAYOUT, int ACTIVATION_PASSES, bool COLLECT_RISKS,
          bool FUSED_EXPERT_LAYOUT = false, int MMQ_K = 32>
__device__ __forceinline__ void
gguf_q4_k_selected_dual_q8_1_ds4_mmq32_prefill_compact32_body(...)
```

with

```cpp
static_assert(MMQ_K % 32 == 0, "MMQ_K must be a whole number of Q4_K subblocks");
constexpr int KSUB = MMQ_K / 32;
```

**The default of 32 is what keeps the blast radius at one function**: all four existing call
sites (lines 1437, 1480, 1523, 1572) keep instantiating the 32-wide pass and their code
generation is unchanged. There is no call-site churn and no new struct.

## What is left, and it is now small

The remaining edit is the staging loop, and it does **not** need re-indenting the ~140-line
staging body. Stage into `weight_tile[col * KSUB + (k32 % KSUB)]` and
`activation_tile[row * KSUB + (k32 % KSUB)]` on every iteration, and **guard the
`__syncthreads()` pair and the compute with `if (k32 % KSUB == KSUB - 1)`.** The caches live in
shared memory, so they survive across the subblock iterations that fill them; only the
sync-and-consume step needs to happen once per `KSUB`. Then the compute loops `s` over
`0..KSUB-1`, reading each subblock's own `dm` pair.

At `MMQ_K = 128` that takes the gate/up projection from 88 iterations and **176 barriers to 22
iterations and 44.**
