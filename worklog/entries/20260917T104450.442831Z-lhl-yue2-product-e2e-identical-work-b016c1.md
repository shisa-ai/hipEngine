# YuE2 product path on identical work: 1.24x whole-run, AR 1.38x, and the reference's product VAE is not reproducible

## Summary

The AR work of the previous three units (paired-branch head, phase-windowed head,
window-relative sampler) had been measured in isolation - kernel A/Bs, sampler
microbenchmarks, a three-arm loop harness - but never as a whole product run against the
reference on the same job. This unit does that, and the answer is **124.54 s / RTF 2.40
at current HEAD against 155.22 s / RTF 2.99 with the pre-change AR paths** (medians of
three runs each; paired elapsed ratio 1.236, paired AR ratio 1.380). Both arms produced
the same 1 298 tokens, the same 2 492 096 samples and the same PCG64 state digest, so the
ratio is a change in cost and not in output.

The comparison required fixing the protocol first. The earlier whole-path entry compared
our 1 451 generated tokens against the reference's 1 297, because each side sampled its
own trajectory, so the wall clocks were not comparable at all. `scripts/yue2_case_timing.py`
now caps the semantic phase at the reference recording's token count, which makes both
sides run the same job: 1 298 frames against 1 297, 51.92 s against 51.88 s of audio.

The reference's own product run turned out not to be reproducible on this host, and that
finding is as important as our own number. Two fresh runs today take 235.60 s and 260.19 s
against its pinned 137.80 s, and the entire difference is its VAE stage: 170.09 s and
186.35 s against the pinned 69.09 s, while its AR (41.96 and 43.55 against 40.60 s) and
NAR (20.16 and 26.76 against 27.32 s) agree within noise. Its warm tiled decode of these
same latents is 20.15 s, measured in the same session, so even its pinned product run pays
3.5x its own warm decoder and today's runs pay 8.5x. The per-stage matched table is
therefore the implementation comparison, and the whole-path table is the product one.

## Changes

- `scripts/yue2_case_timing.py`: `--full-ar-paths` reconstructs the pre-change AR
  arithmetic (full-vocabulary head, full-row sampler) inside the same harness, so the A/B
  runs the same protocol, the same case and the same session code path. Also caps the
  semantic phase at the reference's token count.
- `scripts/yue2_ar_sampling_cost.py`: measures both sampler layouts (full row and window)
  in one run, reports the host load average with the result because these are CPU-only
  numbers, and no longer prints hardcoded stale step costs. An attempt to fold the product
  loop's context scaling into it was reverted: that measurement needs the session
  machinery in `yue2_case_timing.py`, and the paragraph it fed was rewritten from
  measurements instead.
- `benchmarks/results/yue2_product_case_timing_20260917.json`: rewritten as protocol v3
  with six runs (three per arm), the paired ratios, the identical-output check and all
  three reference rows.
- `benchmarks/results/yue2_ar_matched_timing_20260917.json`,
  `yue2_nar_matched_timing_20260917.json`, `yue2_vae_matched_timing_20260917.json`:
  re-measured at current HEAD in one session, both sides.
- `benchmarks/results/yue2_ar_sampling_cost_20260917.json`: protocol v2, both layouts.
- `benchmarks/README.md`: the product-path section now carries the identical-work table,
  the reference's three rows and the reason the product path is ahead; the matched table
  and the AR analysis paragraph are refreshed (the old paragraph's context-scaling fit and
  7.61 ms sampling cost were measured before the head and sampler changes and no longer
  described the code).
- `benchmarks/CHANGELOG.md`: dated entry with the numbers, the protocol change and the
  reference's spread.

## Validation

- Six product runs, three per arm, interleaved; identical tokens (1 298), samples
  (2 492 096) and PCG64 digest (`e0a78034e85a52f0`) in all six.
- Paired elapsed ratio 1.236 (range 1.213-1.246); paired AR ratio 1.380 (79.22 → 57.34 ms
  per token). RTF ranges do not overlap: 2.30-2.49 against 2.80-3.08.
- NAR and VAE per-frame costs inflate ~20% and ~10% across the three repetitions in both
  arms alike, so only the paired ratios are claimed as arm effects; the absolute seconds
  are not.
- Matched stage re-measurement, both sides in one session: AR 54.94 against 30.88 ms per
  step (1.78x), solver 27.35 s against 21.81 s (1.25x), decoder 20.08 s against 20.15 s
  (level, ours 1.003x faster).
- Sampler cost, 30 medians per call on a quiet host (load 0.26): 7.673 ms per token over
  the full row against 0.715 ms windowed (10.7x).
- Three reference product runs compared stage by stage; the VAE spread reproduces across
  two fresh runs while AR and NAR do not move.
- Traffic arithmetic from the checkpoint's own tensor sizes: 28 layers 2.819 GB plus the
  head (756 MB full, 134 MB windowed) per branch-step; 5.77 GB per token at 57.3 ms is
  ~101 GB/s against the reference's 3.58 GB at ~116 GB/s.
