# gfx1100 MTP-verification tiny-M IU4: control-deficit artifact, no production benefit

## Summary

Ran the tiny-M B4 gate/up leaf on gfx1100 W7900 (rows 2–128, warmups 3,
samples 15, burst 1). The mechanical all-shape inclusive-speedup gate reports
`tiny_m_gate_passed`, but the win is **not an IU4 representation benefit** — it
is a control-bandwidth-deficit + cache artifact:

- The exact rowtile8 qmicro control reaches only **269–502 GB/s = 31–58% of
the 864 GB/s W7900 memory roof** (it was tuned for gfx1151 and does not
saturate gfx1100's higher bandwidth).
- The candidate reaches **891–1458 GB/s = 103–169% of the roof** — impossible
from HBM, so L2/cache-assisted or under-measured work; the candidate's
effective-bandwidth number is not a clean memory-bound result.

So the speedups (1.44/1.27/1.96/2.30× at M2/M3/M4/M5) track the control's
deficit, exactly the §3.1/review-2 marginal-value trap, amplified on gfx1100.
The representation is unchanged (re-quantized S4 from Q4_K_S, ~15.9% weight
NRMSE) and still fails the T3 model-distribution gate on gfx1151; the gfx1100
kernel is bit-exact to the CPU reference, so the same T3 failure applies.

**Decision: no production MTP-verification benefit from IU4 on gfx1100.** The
correct lever is the exact control's own bandwidth fix (R9 item 2), which is
representation-free and would recover most of the apparent win.

## Validation

- Speedups at M2–5: 1.438/1.271/1.956/2.295×; layer-local max KL ~5.4–5.9e-6,
  finite, deterministic.
- Binding roof = memory = 864 GB/s (gfx1100 W7900). Control 269–502 GB/s
  (31–58%); candidate 891–1458 GB/s (103–169%) — exceeds HBM roof, so not a
  clean memory-bound result.
- Candidate arithmetic/task correctness: bit-exact vs CPU reference (verified
  earlier for rows 2–64). T3 model-distribution gate NOT run on gfx1100; the
  identical representation fails it on gfx1151 (R8), so no production promotion.

## Next

- Apply the exact-M4 qmicro bandwidth fix (R9 item 2) to the gfx1100 control
  instead; that recovers the real headroom with zero bytes and zero T3 risk.
