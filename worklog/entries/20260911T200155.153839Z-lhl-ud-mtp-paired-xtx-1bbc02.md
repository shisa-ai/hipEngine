# Paired UD/plain MTP on the XTX, and the UD single-row AR step anomaly

## Summary

The paired UD/plain MTP measurement now exists on a declared and verified device
(GPU1, RX 7900 XTX). All four arms pass every binding control gate and the
hardened protocol-identity checks. The measurement also surfaced a real anomaly
that changes how the UD ratios must be read: UD's single-row AR decode in this
protocol costs about twice the per-step time of the same artifact under the
p512/d128 graph-replay protocol on the same card, while plain agrees across both
protocols. The UD MTP ratios are therefore inflated by their denominator, and the
protocol-internal UD-vs-plain comparison is the trustworthy one.

## Changes

**Measurement.** `scripts/ud_mtp_paired.py --device-index 1 --expect-device
"AMD Radeon RX 7900 XTX" --runs 2 --output
benchmarks/results/paired-ud-plain-mtp-c1-natural25-b3-xtx.json`, c1 /
natural25 / B3, full ten-prompt `mtpbench-code-general-ja` suite, in-protocol
true no-MTP AR denominator, two runs.

All four arms: `evidence_complete`, `true_ar_denominator_present`,
`all_gpu_accept_match_cpu`, `deterministic_repeats`, `faster_than_true_ar`, and
`timing_evidence_valid` all true; `binding_passed` true; exit 0. Acceptance is
effectively identical across arms (0.633-0.637 accepted per cycle, 2.727-2.759
visible per cycle), so the ratio spread is compute rather than acceptance.
`UD-Q4_K_S` keeps the same two `general_ja_plan` near-tie divergences in both
runs (`suite_status=correctness_failed`, 2/20 divergent rows), the 0.0096-logit
single-row-vs-4-row spread permitted as production drift under
`EXECUTION-PROFILES.md` 4.1. The other three arms are `complete_exact` with 0/20
divergent rows.

**Artifact re-derived under the hardened validator.** The run was launched
before the protocol-identity hardening landed, so its first artifact was written
without those checks. Its raw payloads were still on disk, so the artifact was
re-derived with `--from-raw --device-index 1 --expect-device ...`, which now
proves session quant, `target_verify_mode`, `draft_hidden_variant`, run count,
warmup, and the normalized provenance command for all four arms, and records
`timing_evidence_valid=true`.

**The UD single-row AR step anomaly (new, open).** UD AR is 69.3 ms/step (K_M)
and 59.5 (K_S) in this protocol. The campaign's p512/d128 graph-replay decode
for the same artifact on the same card is 33.4 ms/step (29.98 tok/s). Plain
agrees across the two protocols: 27.0 ms/step here vs 28.3 (35.37 tok/s) in the
campaign. So the UD gap is ~2.07x and is not shared by plain.

Three independent pieces of evidence say this is not a device or contention
artifact:

1. The same ~2x UD-vs-plain AR step gap appears on the withdrawn W7900 run
   (UD 65.1 ms/step vs plain 32.8), so it reproduces on a different card.
2. UD's AR rate barely moves between the two cards (15.362 -> 14.438 tok/s)
   while plain's moves with contention (30.442 -> 36.986). A rate that is
   insensitive to a contended card is not GPU-bound.
3. Both arms ran with identical runtime configuration
   (`HIPENGINE_GGUF_DECODE_REPACK` unset, same proposal-graph eligibility), so
   repack is excluded as the cause.

That combination is consistent with per-step host overhead in the UD single-row
AR route rather than GPU work. It is stated as consistent with, not proven: the
direct evidence would be a kernel census on this protocol, which was not taken.
Consequence for reading the table: the UD MTP ratios are measured against this
slow denominator, so 2.4678x does not mean MTP makes UD fast. UD MTP at 35.630
tok/s is only 1.19x the campaign's same-card UD AR decode rate. The
protocol-internal comparison, where both arms pay the same protocol cost, is UD
MTP at 0.563x (K_M) / 0.568x (K_S) of plain MTP.

**Records.** `benchmarks/README.md` publishes the table, the gate results, and
the denominator caveat, and shortens the census withdrawal to a single sentence.
`benchmarks/CHANGELOG.md` gains a dated entry above the retraction.

**Test guard widened.** `test_committed_artifact_is_complete_evidence` is now
parametrized over both artifacts and asserts that every artifact states its
timing verdict explicitly and that a non-invalidated artifact passes
`timing_evidence_valid` and `binding_passed`.
