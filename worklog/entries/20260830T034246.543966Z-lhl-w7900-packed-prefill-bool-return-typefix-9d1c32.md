# W7900 Qwen3.8: fix bool return on the no-native-owner prefill path

## Summary

The subset-grouping change (`35794a1bb`) made `_try_prefill_native_work_batch` return the
handled request ids, and its caller does `int(request_id) in handled`, but one early-exit
path still did `return False`. Any wave whose packed execution owner lacks
`prefill_batch_native` therefore raised `TypeError: argument of type 'bool' is not iterable`
inside `prefill_batch`. This became reachable the moment gfx1100 declared the capability,
because the batch route is now entered by default.

## Changes

- `hipengine/generation/qwen35_gguf.py`: that path returns `frozenset()`; the annotation is
  corrected from `-> bool` to `-> frozenset[int]` (it was stale from before the change), and
  the docstring states the container contract so the next early-exit cannot repeat it.
- New regression test
  `test_gguf_packed_prefill_without_native_owner_returns_a_container` drives exactly that
  shape - an owner with no `prefill_batch_native` - and asserts the return is an empty
  frozenset, that the caller's membership expression does not raise, and that no group is
  counted.
- `test_gguf_submit_poll_runner_owns_and_reuses_resident_sessions` gains
  `native_full_prefill_groups: 0` in its exact route-count assertion, which is what the
  counter added today legitimately contributes in a serial-prefill scenario.

## Validation

The failing test was the discovery route, so RED and GREEN are both on record: before the
fix it failed with the TypeError at `qwen35_gguf.py:6518`; after it, 14 tests pass across
`submit_poll`, the new regression test and today's grouping/capability tests. Full-file run
is in flight.

Worth naming the process failure: I promoted the capability with this path untested, and the
earlier guard tests only exercised owners that *have* the native entry point. Declaring a
capability turns a dormant branch into a shipping branch - the fallback branches are part of
what a promotion qualifies, not just the happy path.

## Next
