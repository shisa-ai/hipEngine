# Bound Gemma 4 runner staging growth and clean up failed construction

## Summary

Two ownership defects in `hipengine/runtime/gemma4.py` are fixed. The reusable
staging buffer allocated exactly the requested size and retained every replaced
allocation, so a keep-mask whose column count grows with the sequence retained
O(n^2) bytes over a session. Growth is now geometric and the retained total is
bounded by a constant multiple of the largest request. Separately, `Gemma4Runner.__post_init__`
allocated its buffers with no exception cleanup, so a mid-constructor
allocation failure leaked every buffer already taken. Construction now releases
all owned allocations before re-raising. Kernel arithmetic and the asynchronous
buffer contract are unchanged: replaced staging allocations are still never
freed while a launch could be reading them.

## Changes

- `hipengine/runtime/gemma4.py`
  - `_staging_buffer` grows to `max(nbytes, held_capacity * 2)` and records the
    allocated capacity, so a rising request replaces the buffer O(log) times and
    the memory a name retains stays within a constant factor of its largest
    request. No allocation is freed on growth.
  - Added `_release_owned()`, shared by `close()` and the constructor failure
    path, which frees scratches then buffers once and clears `_buffers`,
    `_staging`, `_scratches`, `_kv`, and `_caches`.
  - Wrapped the `__post_init__` allocations in `try/except BaseException`; on
    failure it sets `_closed` and calls `_release_owned()` before re-raising, so
    a later `close()` cannot double-free.
  - Refreshed the `_staging_buffer` docstring to describe geometric growth and
    bounded retention.
- `tests/test_unit_gemma4_runner_lifecycle.py` (new, CPU-only)
  - Fake `malloc`/`free` patched onto `hipengine.runtime.gemma4`; a tiny
    in-memory `Gemma4TextConfig` and `SimpleNamespace` weights stand in for the
    artifact. No HIP import, device, or kernel launch.
  - Covers bounded growth, buffer reuse, constructor-failure cleanup (including
    failure after a layer scratch exists), `close()` idempotence with grown
    staging, and exact-once release after a failed construction.
