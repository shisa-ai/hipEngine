# `runtime.memset` is async and ordered with stream-0 kernels

## Summary

The Surya/Evie state re-zero fix replaced a scale-by-zero kernel launch with
`runtime.memset(ptr, 0, nbytes)` at five sites, two of which run per text-decoder
layer inside every prefill (18 layers x 2). `runtime.memset` uses `hipMemset`,
the *synchronous* HIP API, so the obvious worry was that each call would block
the host behind the layers' queued work and turn a 17 s prefill into several
minutes.

**Measured on gfx1151: it does not block, and it is ordered with the kernels.**

```
big 512MB memset (enqueue + wait): 2.47 ms
small 1MB memset queued behind it:  28.4 us
same with hipMemsetAsync:          15.0 us
```

A 1 MiB `hipMemset` issued behind 2.47 ms of already-queued work returns in
28 us, i.e. it only enqueues; the extra ~13 us over `hipMemsetAsync` is call
overhead. Ordering holds because `hipMemset` acts on the NULL stream and the
runner launches its kernels with `stream=0` (`_S = ctypes.c_void_p`, so `_S(0)`
is NULL): same stream, so the re-zero is guaranteed to land before the conv/GDN
kernel that reads the state. The poison regression tests confirm this
empirically -- if the ordering were not guaranteed they would be flaky, and
they are not.

## Why this is recorded

The fix is required for correctness (a scale-by-zero cannot clear a NaN), so the
only open question was whether the *correct* form costs host time in a hot loop.
It does not: one enqueue per re-zero, no device synchronize, and the same bytes
touched as the scale kernel it replaces (96 KiB and 1 MiB per layer, ~40 MB per
prefill, well under 0.1% of the prefill). No prefill A/B was needed once the
blocking hypothesis was ruled out directly.

## Changes

- `docs/KERNELS.md` "Device-memory hygiene": notes that the memset form is free
  in a hot loop, with the measured numbers.

## Validation

Probe script (inline, gfx1151, `HIPENGINE_HIP_ARCH=gfx1151`): allocate a 512 MiB
and a 1 MiB buffer, `device_synchronize`, enqueue a 512 MiB `memset`, time a
1 MiB `memset` behind it, then repeat with `memset_async`, then time the 512 MiB
`memset` with a trailing sync. Correctness of the replacement itself is covered
by `tests/test_surya_gpu.py::test_gpu_state_rezero_clears_recycled_nan` and
`tests/test_evie_gpu_runtime.py::test_state_rezero_clears_recycled_nan`.
