# e8 norm-cost gap attributed - own routing unit, ud-lane norm row missing

## Summary

Iteration 24 executed campaign E8 (attribute the norm-cost gap, H11) from
the existing paired E1 base traces — no new GPU run, per campaign. The
attribution is exact:

- **Conservation:** both arms execute exactly **774 layer-norm instances
  per window** — UD: 384 `gguf_add_rmsnorm_bf16_f32_weight` + 390
  `gguf_rmsnorm_bf16_f32_weight`; plain: 128 + 134 + **512**
  `gguf_norm_fixed5120_wave256<true|false>`.
- **Selection:** plain routes 512/774 (66%) of its instances through the
  specialized fixed-width owner at **3.46/2.77 µs/launch**; UD selects it
  **0 times** and runs everything on the generic pair
  (41.25 / 22.62 µs/launch).
- **Cost:** UD generic norm total 24.66 ms/window vs plain 22.12 ms =
  **+2.54 ms/window** (~0.04% of window kernel time — real but small).
- **What forces the variant:** `_gguf_policy_identity` (runtime) extends
  the policy-table key with the bound `artifact_preset_key` for UD
  artifacts, so UD looks up the 3-tuple
  `(H5120_GEOMETRY, "MOSTLY_Q4_K_M", "gguf_ud_q4_k_m")` in
  `GGUF_NORM_RESIDUAL_DECODE_POLICIES`, which carries only the historical
  2-tuple plain rows. The 3-tuple misses **by design** — the docstring
  states certified-plain rows "can never silently apply to a UD artifact
  that merely shares the stamp … falls back to the generic path" — and the
  caller takes the generic fallback. E6c added the equivalent UD-lane rows
  to `GGUF_DENSE_DOWN_RESIDUAL_DECODE_POLICIES` but never to this norm
  sibling.
- **Rides-with-E6 test:** the residual is already fused inside both arms'
  add-norm kernels, so the gap does not follow the unfused residual.
  **Verdict (campaign's fork): its own routing unit.**
