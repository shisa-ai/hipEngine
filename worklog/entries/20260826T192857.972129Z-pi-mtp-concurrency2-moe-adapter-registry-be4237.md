# Add model-plugin GGUF MTP2 adapter registry

## Summary

Replaced the resident GGUF runner's hardcoded dense/MoE adapter exclusion with a
cold-path model-plugin adapter registry. Dense Qwen GGUF selects `dense_nextn`;
MoE selects the distinct fail-closed `moe_nextn` key. The built-in dense
factory remains unchanged, while unregistered MoE still selects K0 until the
next unit registers the real adapter.

This is an architectural foundation, not a capability or policy promotion.

## Changes

- Added `hipengine/generation/qwen35_gguf_mtp2_registry.py` with explicit
  register/resolve/unregister/list and lazy built-in registration.
- Added `speculative_mtp2_adapter` identities to dense and MoE model plugins.
- Changed `Qwen35GGUFResidentModelRunner._resolved_mtp2_adapter()` to resolve the
  model-plugin key and construct the factory without `config.is_moe`, backend,
  or quant branches. Quant identity comes from the generator's cold resolver.
- Added RED/GREEN tests for distinct plugin identities, unregistered fail-closed
  behavior, and custom MoE factory construction. The RED run failed at import
  before the registry existed.

## Validation

- `uv run pytest -q tests/test_qwen35_gguf_mtp2_seam.py
  tests/test_generation_registry.py tests/test_speculative_provider_registry.py`
  passes 55 tests.
- Dense adapter seam tests remain green; unknown plugin keys return `None` once
  and leave K0 behavior.
- `compileall`, fixture validation, registry/cpu-fixture/smoke-add-plan smokes,
  `git diff --check`, and worklog validation pass.
