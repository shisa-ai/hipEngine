# Gemma 4 five-length llama.cpp BF16 baseline comparison

## Summary

The lead requested a same-GPU prefill/decode comparison at 512, 1024, 4096,
8192 and 16384 prompt tokens before closing the Gemma implementation gaps.
The comparison is complete with a named hipEngine 16K capability failure.
This is diagnostic timing, not a production numerical promotion.

| Prompt | hipEngine prefill | llama.cpp prefill | hipEngine decode | llama.cpp decode |
| --- | ---: | ---: | ---: | ---: |
| 512 | 2388.9 | 3596.7 | 78.39 | 83.18 |
| 1024 | 2341.5 | 3881.4 | 83.10 | 80.30 |
| 4096 | 1435.7 | 3934.3 | 79.88 | 76.41 |
| 8192 | 1126.9 | 3995.7 | 75.63 | 75.49 |
| 16384 | capability failure | 3510.2 | not run | 71.39 |

All rates are tokens per second, medians of six per-sample rates. At 16K the
runner refuses its required 16640 capacity because sliding head_dim 256 needs
68672 shared-memory bytes versus the kernel's 65536-byte limit. The global
512-wide geometry would also exceed its limit. No full-prompt capacity search
or silently shortened workload was used.

Frozen protocol: host `epyc`, physical GPU1 RX 7900 XTX, the existing
`gemma-4-26B-A4B-it-UD-Q4_K_XL.gguf`, BF16 KV, greedy true autoregressive
execution, 128 output tokens with EOS ignored, and the campaign harness's
frozen natural corpus with exact token-ID agreement between engines.
Both engines use capacity 8192 for the first three lengths, 8448 for 8192,
and 16640 for 16384, leaving output room without shortening the prompt.
Run two counterbalanced engine-order blocks (hipEngine/llama.cpp then
llama.cpp/hipEngine), each with one full-shape warmup and three samples.
Record all samples, selected prefill block, public-path parity, failures,
and the phase-accounting difference in the existing comparator harness.

hipEngine source is `ab89f293c`; llama.cpp source is `8cfc315` from the
existing native HIP build. Existing audit changes and scratch outputs belong
to earlier work and are not part of this unit. The BF16 continuation-profile
failure remains open; these timing rows are diagnostics, not new numerical
promotion evidence.
