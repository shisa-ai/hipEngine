# Gemma 4 multi-token flash decode for verify blocks

## Summary

Item 2, first step. A five-row production verify block at 32K keys spent 14.9
ms in the five global layers' flash attention against 3.4 ms for one row: each
token's blocks re-walk the same key slices. `gemma4_attention_decode_flash_multi_kernel`
serves a group of tokens per (KV head, slice) block, loading K and V once per
key for the group and repeating each row's arithmetic in the per-token kernel's
order (tree per key, running max, weight pass, sequential denominator, ordered
V walk), so outputs are bit-identical. Groups: the widest of 8/4/2 whose rows fit
64 KiB LDS and the 32-lane denominator step (global 4, sliding 8); query rows
are staged in their bf16 input type (exact). Not used inside graph captures.

Result is modest: global flash 14.9 -> 13.2 ms at five rows (VGPR 152, one
block per CU slot), verify 39.6 -> 37.4 ms at 32K, 29.0 -> 27.1 at three rows;
8K level. The per-(row, key) warp-tree reduction is the remaining cost, so the
next step changes the dot-product scheme (production arithmetic, gate needed).

Also tried and rejected for verify blocks: routing them through the WMMA flash
prefill kernels (8K five rows 38.0 vs 26.9 ms; 32K 41.1 vs 39.7).
