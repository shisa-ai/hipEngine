# PF-4 M2 routing compaction declaration: arithmetic class, mapping, lineage status

## Summary

Declaration for PF-4 lever 1 (M2 parallel top-10 expert-id compaction, prefill
arm), made before any implementation, per the loop contract and campaign
section 6.5. Binding shape: prefill chunks of rows >= 64 (the M2 gate), 512
experts, top-k 10, compact = rows * 10.

## Changes

- **Arithmetic class: T0.** The M2 mechanism (`mm_ids_helper_top10_parallel`,
  halo-box `a7ad7b7f` `ggml/src/ggml-cuda/mmid.cu`) is an integer-map
  compaction prepass: per-expert blocks (8 warps × 32 lanes), warp-local
  any-scan + `__shfl_up` exclusive scan over 2 tokens × 16 padded top-k slots
  per warp iteration, cross-warp combine through shared `warp_counts` /
  `warp_nex_prev`, emitting per-expert compact ranges and token-slot maps. No
  floating-point arithmetic changes anywhere; all outputs are integer maps and
  boundaries. T1 escalation does not apply unless the implementation is forced
  to reassociate a float reduction, which this lever cannot (the routing
  weights themselves are untouched — they stay whatever the incumbent
  `qwen35_router_select` produced).
- **Registered strict fallback (named per loop contract):** the incumbent
  compaction chain stays registered, production, and untouched:
  `qwen35_moe_group_count` + `qwen35_moe_group_prefix` +
  `qwen35_moe_group_scatter_gather_lowp` (module
  `hipengine/kernels/hip_gfx1100/moe/group_scatter.py`, library
  `qwen35_moe_group_scatter`), invoked from `run_qwen4_exp_moe`
  (`hipengine/runtime/qwen4_exp_runner.py:3152-3186`) with two
  `group_counts`/`group_scatter_offsets` memsets. The candidate registers
  under a NEW variant key; the incumbent chain remains the RED oracle.
- **In-tree ownership mapping (verified this session):** the production
  grouped-MoE prefill route consumes three products of the chain:
  (1) `group_expert_start[E+1]` (exclusive prefix over per-expert routed-lane
  counts) consumed by every grouped prefill kernel;
  (2) `group_sorted_lanes` / `group_sorted_experts` / `group_sorted_weights`
  (compact-slot → token/slot/expert/weight maps) consumed by the down-projection
  scatter-back; (3) `expert_down`-shaped compact activation rows gathered by
  `scatter_gather_lowp` from `hidden_bf16`.
- **Parity subtlety that shapes the RED contract:** the incumbent
  `scatter_gather_lowp` assigns within-expert compact order via atomics on
  `group_scatter_offsets`, so the compact order inside one expert's range is
  NOT a stable oracle (the set of maps is a valid bijection; final outputs are
  order-invariant because each compact row's expert GEMM is independent and
  the scatter-back is keyed by token slot). The T0 contract is therefore:
  (a) `group_expert_start` bit-identical to the incumbent prefix output
  (deterministic), (b) the candidate's maps form the same per-expert
  bijections over the same (token, slot) multiset with the same
  `sorted_weights`/`sorted_experts` content per compact row's token slot,
  and (c) end-to-end runner outputs bit-identical to the incumbent route at
  every compared shape. Compact-row-order equality is explicitly NOT the
  contract.
- **Scope guard:** the candidate fuses count+prefix (and the two memsets)
  into one launch producing `expert_start` plus the scatter maps; whether the
  hidden-row gather stays inside `scatter_gather_lowp` or moves into the
  candidate is an implementation decision to be fixed by the RED test ABI,
  not silently changed later.
- **Lineage status:** `mmid.cu` is NOT tracked in `docs/source_lineage.json`
  (62 tracked files; no mmid entry), so `scripts/check_lineage.py --file
  'mmid.cu'` selects zero sources ("no sources selected") — there is no drift
  target for this file. The source repo is present on disk:
  `/home/lhl/halo-box-strix-llama/hb-pr11` at commit `a7ad7b7f5` (both the
  repo HEAD and the last commit touching `mmid.cu`), matching the campaign
  baseline. Narrowed check on the tracked `mmq-config-rdna3-5.cuh` remains
  GREEN (PF-3 declaration). The missing manifest-tracked `atlas` reference
  repo remains the standing named environment blocker. Source citation for
