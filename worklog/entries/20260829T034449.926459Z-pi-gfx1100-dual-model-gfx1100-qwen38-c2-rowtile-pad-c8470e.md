# Add target verify group row padding primitive

## Summary

Land the pure-dataclass primitive for padding physical target verify groups
up to the backend's admitted rowtile rows (gfx1100 rows6), so K1's R4, K3's
R8-class groups, and K2's ragged 2-5-row cycles stop falling to the shared-B
256-row padded tile (measured ~5.1x cycle cost).

## Changes

- `hipengine/speculative/frontier.py`: `pad_candidate_graph_rows()` appends
  inactive candidate rows owned by the last request, chaining parents/depths,
  extending host tokens with the pad token, and accepting a padded device
  token tensor for device-token graphs.
- `tests/test_specdec2_target_row_pad.py`: RED->GREEN contracts; padded
  `accept_from_top1` is identical to unpadded across accept/reject/partial
  outcome combinations; pad rows never influence accept results.

## Validation

- `uv run pytest tests/test_specdec2_target_row_pad.py` passes (4 tests).
- `uv run pytest tests/test_specdec2_engine_frontier.py
  tests/test_specdec2_contracts.py tests/test_specdec2_provider.py` passes
  (14 tests) - no frontier/contract regressions.
- The GPU accept kernel already honors `active_mask` (max-depth scan and
  match walk skip inactive rows), and inactive rows are production-exercised
  by chain.py budget padding today.
