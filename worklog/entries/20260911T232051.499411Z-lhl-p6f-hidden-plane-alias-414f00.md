# P6f closes: hidden-plane aliasing measured with a two-plane control

## Summary

Task `#21` (P6f) had one packet gate left: "aliasing on this executor". The
finding is that the gate was already being exercised but was not being
*measured*, so the earlier `layer_boundary_state` passes were evidence under an
unknown configuration.

`HIPENGINE_INT8_LAYER_OUTER_HIDDEN_ALIAS` defaults to `1` and is read at
bulk-prefill workspace allocation time (`qwen35_gguf_runner.py`, the
`single_plane=` argument to `_allocate_prefill_hidden_buffers`), which returns
the same buffer for both hidden planes. The suspended-state save copies both
attributes, so a save/restore with the alias on must not lose or duplicate a
plane's contents. The proof did not record which configuration it ran.

Two changes close this:

1. A `hidden_plane_alias` gate measures `_prefill_hidden_a.ptr ==
   _prefill_hidden_b.ptr` in **both** arms and requires the measured
   configuration to match the declaration. Disagreement between the arms fails
   the gate.
2. `--hidden-plane-alias {on,off}` sets the env var for the run, so `off` is a
   genuine two-plane control rather than an assumption. The env var is written
   before any session builds its bulk prefill workspace, and the resolved value
   is recorded in `trace_environment`.

## Measured result

W7900 (gfx1100), Qwen3.8-27B `Q4_K_M`, INT8 KV (`int8_per_token_head`), 3,072
rows, 4-layer segments, 16 segments, `HIP_VISIBLE_DEVICES=0`:

| | alias on (default) | alias off (control) |
| --- | --- | --- |
| `hidden_plane_alias` measured | resumable `true`, reference `true` | resumable `false`, reference `false` |
| `layer_boundary_state` | 64 planes, 0 mismatches | 64 planes, 0 mismatches |
| sampled token (both arms) | 265 | 265 |
| arm A / arm B wall | 4.1615 / 4.7674 s | 4.1724 / 4.7768 s |
| segments (count, min) | 16, 258.864 ms | 16, 258.952 ms |
| interleaved decode p95 / max | 33.577 / 33.580 ms | 33.561 / 33.606 ms |
| standalone decode p95 / max | 33.644 / 39.856 ms | 33.917 / 39.834 ms |
| peak suspended state | 221,773,824 B | 221,773,824 B |
| gates | 7 / 7 | 7 / 7 |

Both runs `passed: true`, `performance_claim: false`.

Two things worth stating plainly:

- The alias was in fact active in the previously committed passing runs, so the
  earlier state-gate result already covered it. What was missing was the
  measurement, not the coverage. The gate now makes that explicit and would
  catch a future drift where the alias silently stops applying.
- Peak suspended state is identical (221,773,824 B) with and without the alias.
  The suspended scratch allocates its own two planes either way, so the alias
  reduces the *workspace* footprint, not the suspended-state cost. No claim is
  made here about the workspace saving; the alias's own memory evidence is the
  2026-09-09 capacity ladder recorded at its definition.

## Honest limits

- One run per configuration. Each configuration is one green run; no repeats.
- "Aliasing on this executor" is interpreted as the INT8 layer-outer route's
  single-plane hidden stream, which is the only aliasing this executor has (the
  DMS route's separate `HIPENGINE_LAYER_OUTER_HIDDEN_ALIAS` gate was covered
  earlier). If the reviewer meant a broader aliasing class, this unit does not
  address it.
- The two-plane control changes only the hidden-plane count; it does not
  re-run the alias's own capacity ladder, so the workspace-footprint saving is
  not re-measured here.
- Byte-exactness is established at the shapes measured. Other KV scale layouts
  (`block16`, `hadamard_group32`) remain unit-tested but unmeasured on hardware.
