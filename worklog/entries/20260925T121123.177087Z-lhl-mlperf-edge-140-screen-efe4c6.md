# Compare hipEngine and llama.cpp on the fixed 140-turn Edge screen

## Summary

The user requested the fixed 140-turn same-GGUF comparison and a detailed speed
breakdown. Both fresh-server arms complete 140/140 turns with valid structured
calls and zero errors, drops, empty outputs or length-limited responses. Mean
latency is 8.925 s for hipEngine and 9.157 s for llama.cpp; inline command IoU
is 0.5586 versus 0.6420. One pass with different outputs does not establish a
stable speed advantage or quality parity. External tools were not executed and
recorded tool delays were not injected.

## Changes

- Freeze all rows for Flask (27 generated turns), Xarray (52) and Pytest (61),
  preserving source order. Upstream loader verifies 140 samples for each arm.
- Both arms use Qwen3.6-27B Q4_K_M, 32768 context, BF16 KV, concurrency 1,
  temperature 0, seed 42, maximum 1024 output tokens, reasoning off. Shipped
  cache policies are recorded rather than silently equated.
- hipEngine source: `2fafa58f5`. llama.cpp HIP binary reports
  `1ebf790cda38d827559548f67b0469189690cc8c`; the checkout HEAD is newer, so
  binary hash/version rather than checkout HEAD identify the measured build.
- Protocol: one fresh-server pass per arm, hipEngine then llama.cpp. An isolated
  llama.cpp tool-call preflight runs before either measured process. Preserve
  client timings and engine timing logs separately; token denominators and
  timing boundaries must not be silently equated.
- Raw root: `~/gate-runs/mlperf-edge-140-20260925`. It contains frozen configs,
  subset/manifest, the corrected Endpoints patch, orchestration/analysis scripts,
  commands, logs, counters and host information.

## Validation

- HIP load and gfx1151 device enumeration pass; no competing servers observed.
- Upstream dataset loader: 140 samples for each configuration; no injected delay.
- llama.cpp preflight returns a structured tool call with BF16 K/V requested.
- Background task `bg-11`, execution `3b46ab46-a7ee-4334-8970-ccc8a7fc543f`,
  completes exit 0 with both arms exit 0. Servers are stopped after each run.
- Issued prompt data matches across all 140 pairs; canonical input lengths span
  1,363–22,902 tokens. All output arguments parse with a nonempty `bash.command`.
  hipEngine emits 140 calls, llama.cpp 141, with one two-call response.
- Route counters confirm 140 hipEngine AR host-sampler requests and no MTP;
  llama.cpp logs no speculative implementation configured. The hipEngine profile
  resolves to production without strict fallback; its manifest hash is recorded
  in the hashed capabilities capture.
- The analysis joins 140 server timing rows per arm in sequential request order;
  independently retokenized full-message totals match the upstream report.
  Mean first-visible-output latency: 2.589 / 2.832 s. Mean post-first-visible
  window: 6.336 / 6.325 s. Measured phase: 1,249.47 / 1,282.06 s (-2.54%).
- Tool command lists are identical on 49/140 pairs. IoU is lower for hipEngine
  on all three trajectories; no BFCL or numerical quality gate has run.
- TPOT is not usable as decode-speed evidence: `TpotTrigger` strips the first
  chunk, potentially deleting the tool name. Both runner logs show the resulting
  chat-template error and fallback. Offline reproduction yields exactly the
  upstream mean TPOT (68.885 / 96.541 ms) using 12,275 / 9,709 post-first token
  estimates against 9,703 / 9,799 full-message estimates. No formula was changed
  and original metrics are preserved. This defect is separate from the repaired
  coordinator clock mismatch; elapsed-time windows remain ordered.
- Engine prompt totals: 276.340 / 257.870 s, with shipped cache reuse. Engine
  generation logs use different boundaries (hipEngine first-token-relative
  stream timing, llama.cpp eval time) and counts, so no intrinsic decode-rate
  ratio is claimed.
- Documentation gates (`python3 scripts/docs/check_all.py`), provenance audit
  (`python3 scripts/check_artifact_provenance.py`) and staged worklog validation
  pass. The provenance audit reports zero violations and 19 warnings.
- No production source or arithmetic changed; RED-first and GPU correctness
