# Cooperative shared-LDS W4A16 prefill owner: IQ4_XS +20% prefill E2E

## Summary

The corrected prefill census (previous entry) showed the one-wave W4A16
IQ4_XS singles at 345.8ms of the 870.7ms K_M prefill wall (39.7%) - the
reviewer's structural suspicion, reopened after the task-7 "moot" closure
was corrected. The new cooperative kernel decodes the weight slab into LDS
once per (32-column x 256-row x 256-K) block instead of once per 64-row
tile, with a fused LDS codebook for the IQ4_XS nibble step. Bit-exact with
the one-wave owner; measured 1.5-2.1x per launch at 128+ rows; E2E prefill
K_M 590.9 -> 709.8 tok/s (+20.1%), K_S 525.5 -> 651.0 (+23.9%), decode
unchanged (26.1 / 25.3 with local32 enabled).

## Kernel

`gguf_iq_prefill_wmma_coop_kernel` (gguf_iq_wmma_prefill.hip), template
`<Q, scalar_t, out_t, OUT_TILES_PER_BLOCK=2, ROW_TILES_PER_WAVE=2,
WAVES_PER_BLOCK=8>`: one 256-thread block owns 32 output columns x 256
activation rows. Per 256-K block:

- decode phase: 256 threads, one column each (col = tid>>3), 32
  consecutive K each; writes the fp16 weight slab to `__shared__
  slab[32][272]` (stride 272 keeps rows 32B-aligned for vector loads).
- WMMA phase: 8 waves x (2 col-tiles x 2 row-tiles) consume the slab with
  the one-wave owner's exact K16 association.

Bit-exactness levers (each individually verified):
- The operand order follows the Q5 family - wmma(activations, weights) -
  so the C-fragment store maps col <- lane16, row <- (half_id + 2j): the
  MIRROR of the one-wave owner's store, which pairs with its swapped
  wmma(weights, activations). Mixing the two conventions computes the
  transpose (caught by the first gate run: 93% mismatch on the wide
  shape).
- The per-element arithmetic is the same iq_weight<Q> expression (or the
  Q==0 fast path below), the K16 tile sequence is unchanged, and the
  hi+lo split path (Q3_K, IQ2_S, IQ2_XS) is preserved in the generic
  branch.

## The two decode-phase walls (measured by stubbing)

1. Register-alignment: the one-wave kernel reaches 28 TFLOPS (its decode
   is amortized by 4-block occupancy). The first coop version measured
   only 1.1-1.3x despite removing the 8x decode redundancy - the decode
   phase was the wall. With the decode stubbed to a constant the coop
   structure runs at 46.6 TFLOPS, so the WMMA+LDS structure was sound
   and the decode phase cost ~0.85ms of a 2.8ms launch.
2. The IQ4_XS decode cost was NOT ALU: full unrolling and hoisting the
   per-group invariants (d, hi word, scale) did nothing. The cost was the
   per-element `__constant__ iq4_values[code]` load - the same divergent
   scalar access the strict decode kernel had measured at 24% (its fused
   codebook comment, 2026-09-09). Porting that 512-entry LDS LUT
   (s_cb[byte] = low-nibble value, s_cb[256+byte] = high) took the launch
   from 1.2x to 1.6-1.8x immediately.

The Q==0 fast path additionally makes the group invariant explicit
(dec_k0 is 32-aligned, so a thread's 32 elements span exactly one scale
group of one 136-byte block; the compiler cannot prove that for the
runtime dec_k0, so the generic form re-loads d/hi/scale 32x).

## Measurements

Leaf (XTX, 512 rows, IQ4_XS, one-wave vs coop, bit-exact 0 mismatches):

| shape | one-wave | coop | speedup |
|---|---:|---:|---:|
| 17408x5120 | 3.28ms | 2.08ms | 1.58x |
| 5120x17408 | 3.64ms | 2.14ms | 1.70x |
| 12288x5120 | 2.38ms | 1.41ms | 1.68x |

Row sweep (17408x5120): 1.12x at 8 rows, 1.04x at 64, 1.80x at 128,
1.56-1.63x at 256-2048. The coop owner wins everywhere >= 8 rows (idle
waves skip the WMMA phase but keep the decode and barriers), so the
policy keeps min_rows=8 and routes IQ4_XS to the coop variant; the other
six W4A16 quants keep the one-wave owner pending their own fast decode
paths.

E2E (XTX, 512/128, 3 measured runs, graph-replay decode):

| artifact | prefill before | prefill after | decode |
|---|---:|---:|---:|
| UD-Q4_K_M | 590.9 | 709.8 (+20.1%) | 26.09 (unchanged) |
| UD-Q4_K_S | 525.5 | 651.0 (+23.9%) | 25.35 (unchanged) |

(Baseline = the Q5-dual-8r2 jsons; their decode columns predate the
local32 enable, which is why the old files show 20.0/18.2 - the decode
comparison is against the local32-enabled level, unchanged by this work.)

Parity ratios vs plain Q4_K_M (982.8 / 34.13): prefill 0.60x -> 0.72x,
decode 0.77x.

## Validation

- Bit-exactness: 0 mismatches vs the one-wave owner on five real IQ4_XS
  tensors at rows 8/64/128/256/512/1024/2048 (both wide shapes).
- tests: test_gguf_iq_wmma_prefill, test_gguf_iq_dense_mmq_route,
  test_gguf_iq_local32_decode,
  test_qwen35_gguf_consumer_surface_parity, test_gguf_q5_k_t16_dense,
  test_gguf_q5_k_mmq_wmma_prefill - all green. Route tests now assert
  against the dispatching backend's own policy entry (the variant is
  quant-conditional since this change).
- A measurement pitfall for the record: the sweep's
  --graph-replay-decode defaults to False for engine=gguf; without the
  flag decode runs eager at 88ms/token and looks like a 2x regression.
