# Persist compressed QSA key blocks

## Summary

Promoted append-only persistent compressed-QSA key preparation. Each complete
four-token block is pooled/normed/rotated once, rather than recomputing every
historical block for every sparse query.

## Changes

- Added `pooled_count` to `Qwen4ExpQSAIndexDeviceState`, bounded by the request
  cursor and rewound with `restore_count()`.
- Added `prepare_complete_blocks()`, which writes only the newly completed
  suffix into the existing paged-owner-aligned pooled-key allocation.
- Prompt chunks prepare all newly completed blocks in one launch before causal
  selection; each query still scores only its visible prefix.
- Added a GPU RED/GREEN test proving reuse, one-block suffix preparation, pointer
  offsets, and rollback ownership.
- Artifact:
  `benchmarks/results/2026-08-27-gfx1151-qwen38-flash-next-persistent-qsa-pool.json`.

## Validation

- RED: new test failed because `pooled_count` did not exist.
- GREEN: `tests/test_qwen4_exp_runner_qsa.py`: 4 passed.
- Same natural 4K gate: before 304.944 s, after 303.528 s (-0.464% wall,
  aggregate delta treated as small/noisy).
- Deterministic prefill structure across 12 QSA layers: pool launches
  24,540→384 (-98.435%); prepared block instances 18,849,792→12,288
  (-99.935%).
- Generated IDs are unchanged; final answer `VIOLET-7391`, all 12 layers retain
  the needle, Transformers CPU selection 2,048/2,048 exact, replay/rollback
  exact, and teardown zero.
