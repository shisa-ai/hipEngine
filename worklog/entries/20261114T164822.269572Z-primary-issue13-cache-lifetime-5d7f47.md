# Isolate transient dispatch cache identities

## Summary

Issue #13 identifies three additional unsafe cache identities. Forced integer-ID collisions replay the previous Q5 source-layout variant, ordered-F32 row policy, and T16 source-F16 row policy. Resource-free session tokens now separate all three, including the T16 pair-dispatch cache.

## Changes

- Add tokens to Q5 raw MMQ, ordered-F32 and T16 source-F16 session owners. Cache keys retain the tokens rather than the sessions, so freed device/library owners are not kept alive.
- Declare these and the existing Q8 token `init=False`: `dataclasses.replace` must construct a new token when making a modified session, rather than copying the old token with a changed policy.
- Audit Q6 integer MMQ separately: its dispatch selector reads only workspace presence; its launch fetches the current workspace. Reuse of a non-null identity does not change that selection. Leave this key unchanged. This does not certify arbitrary external mutation of backend tables.
- No kernel bodies, arithmetic, registry policies or product defaults change.
