# Review follow-up: commit the benchmark harnesses, label execution profiles, and retract an unsupported wall claim

## Summary

Four review findings on the VibeVoice-ASR Q4 scratch/allocation work are
addressed. The changes themselves are retained: all four are byte-exact on the
affected surface, which under `docs/EXECUTION-PROFILES.md` satisfies the
`strict` arithmetic contract, and `strict` is stronger than `production`
requires.

Three of the four findings were real defects in the *evidence*, not in the code:
a decode A/B that compared summed logits instead of the logits themselves, four
performance artifacts whose commands cited uncommitted `/tmp` probes, and a gate
count that could read as a production qualification. The fourth was an
overreach in my own reporting: I claimed the decode lane was "at its wall" and
that a separate prefill GEMM outlier "cannot improve". Neither follows from what
was measured, and neither was ever written to a durable artifact, so this entry
is the only place it needed retracting.

## Changes

### 1. The decode A/B now proves bit identity per token

`scripts/vibevoice_asr_q4_decode_scratch_bench.py` compared a summed logits
value between the two Q4 lanes. A sum can match while individual elements
differ, and the token-chain comparison only fails once a difference is large
enough to move an argmax. Each lane now hashes every decoded token's raw logits
bytes and the run fails on any mismatch.

Measured with `--steps 40 --trials 4 --compare-bf16`:

- 40 tokens, **6,082,560 logits** (40 x 152,064) byte-identical, first mismatch
  none;
- negative control: the dense bf16 lane's per-token logits differ from the Q4
  lane on **40/40** tokens, so the comparison is demonstrably sensitive rather
  than vacuous;
- the win reproduces: **54.25 -> 48.71 ms/token (+11.37%)**, and **1.5541x** the
  dense bf16 lane against 1.3954x with the per-layer malloc.

### 2. The harnesses are committed

Four new scripts under `scripts/`, all reproducing the figures their artifacts
record:

| Script | Covers |
| --- | --- |
| `vibevoice_frontend_scratch_ab.py` | front-end arena rewind A/B, capacity/reset accounting, embedding hash |
| `vibevoice_q4_prefill_scratch_ab.py` | prefill scratch arena A/B, allocation accounting, output hash |
| `vibevoice_q4_prefill_launches.py` | prefill wrapper-call count by name and output hash |
| `vibevoice_q4_decode_phase_split.py` | decode enqueue/drain/logits split, launch count, overlap probe |

Two harness defects were found and fixed while making them reproducible, both of
which had already corrupted recorded evidence:

- **Shared RNG across durations.** The front-end harness drew every clip from
  one `default_rng`, so the 30 s waveform differed between `--seconds 30` and
  `--seconds 11 30`. Clips are now seeded from their own duration, and the
  30 s hash is stable at `5f72a790...` either way. The artifact's recorded
  hashes are regenerated, and a side effect is now visible that the old harness
  was masking: the 30 s one-chunk and three-chunk runs share a waveform and
  produce **identical** embeddings, so chunking does not change this frontend's
  output for this fixture.
- **The prefill shim's free timing.** The removed legacy path freed its scratch
  batch inside its own timed region. The committed A/B substitutes a shim whose
  `take()` frees the previous call's batch before allocating the new one, so a
  timed call still contains one malloc-batch and one free-batch. The first timed
  call has no preceding batch to free, so the legacy cost is *underestimated*
  and the delta is conservative. This is now stated in the script docstring and
  the artifact.

Both artifacts also gained a `reproduction_with_committed_harness` field with a
later run of the committed command, and the decode artifact's mechanism note was
downgraded from a claim to a labelled inference (see below).

### 3. Profiles are labelled; the xfail no longer reads as a promotion blocker

`tests/test_gpu_vibevoice_qwen2_q4_runner.py` compares the batched prefill
against the row-by-row route. Both are *schedules*, and `docs/EXECUTION-PROFILES.md`
section 4.2 plus the `production` profile row make cross-width generated-ID
equality diagnostic rather than a promotion requirement. The two clause
families are therefore different kinds of evidence:

- the four **KL** clauses are the binding production drift bound for this route
  and they pass (mean KL ~7e-4 against a 1e-3 envelope);
- the **top-1 against the sequential route** clause is a cross-schedule
  diagnostic and lands near 95% against a 0.99 envelope, with the untouched
  bf16 lane showing the same effect (87/89).

The clause stays asserted as a non-strict xfail so the unmet part stays visible,
but it is now labelled a cross-schedule diagnostic in the constant's comment,
the test docstring and the xfail reason, and both the file docstring and
`docs/MODEL-VIBEVOICE-ASR.md` state plainly that a green run means the KL drift
bound, the strict fallback and the ownership/reuse gates pass — it does not
certify the model for production. The four scratch changes are byte-exact and
are labelled `strict`-grade, which is stronger than `production` requires.

Also fixed: a stale comment in the KL test still asserted the batched prefill
was non-deterministic in both lanes. That claim was already retracted in
`20260914T180119`; the comment now points at
`test_batched_prefill_is_deterministic` instead.

Stale gate counts were re-measured and corrected: the Q4 runner file is
**16 passed, 1 xfailed** (recorded as 13), and the three-file bundle is
**55 passed, 1 xfailed** (recorded as 54). The five-file bundle is unchanged at
**75 passed, 1 xfailed**.

### 4. The wall and cannot-improve claims are retracted

Two claims I made in conversation were not supported and are withdrawn:

- **"Decode is at its wall."** The overlap probe compares enqueue-N-then-sync
  against sync-every-token: **42.20 vs 42.32 ms/token**, a 0.12 ms/token
  difference. That bounds how much host launch overhead can be adding to the
  measured loop; it does not prove no host overhead remains. The phase split
  (enqueue 18.29, drain 23.74, `logits_argmax` 5.82 ms/token) shows the loop is
  GPU-bound, which is a description of where the time is, not a ceiling proof.
- **"The Q6 batched-prefill GEMM outlier cannot improve."** Decode GEMV
  bandwidth is not evidence about a prefill GEMM. That outlier needs its own
  measurement, which was not done. Skipping further tuning is an effort-budget
  decision, and is now recorded as one.

`scripts/vibevoice_q4_decode_phase_split.py` carries an explicit
"Interpretation limits" section stating both, and the decode artifact's
mechanism note now reads as a labelled inference rather than a claim.
