# Gemma 4: the prefill profile is closed, and host-side work is 0.5%

## Summary

The prefill profile is closed. A `rocprofv3` kernel trace over five timed
512-token prefills shows the device **99.5% busy** (15.014 s of a 15.089 s span),
so host-side work is **15 ms per prefill, 0.5%** - there is nothing to remove.
Per-kernel GPU time, taken as the union of each kernel's dispatch intervals,
sums to **3002.8 ms against a 3003 ms prefill**, so nothing is unattributed.

Three routes are 81% of the prefill (Q4_K expert gate/up 1044.6 ms, Q8_0 dense
projections 717.2 ms, Q5_1 expert down 681.0 ms). Attention is 317.3 ms (10.6%).
Everything else combined - router, expert grouping, lane compaction, hidden
gather, all norms, GeGLU, rotary, weighted accumulate - is **73 ms, 2.4%**. The
task's host-side-redundant-work item is closed by measurement, and the glue is
ruled out as a target.

## Validation

- **Prebuild respected.** The `.so` files were built outside the profiler and the
  profiled process reused the cache, per `docs/OPTIMIZATION.md` section 7; no
  `hipcc` ran inside the trace.
- **The attribution is a union, not a sum.** Summing dispatch durations reports
  3588 ms for a 3018 ms span, because rocprofv3 end stamps overlap the next
  dispatch's start. All 5558 dispatches in the segment are on stream 0, so no two
  kernels run concurrently and the union is the correct attribution.
- **The accounting closes.** Per-kernel unions total 3002.8 ms against a 3003 ms
  prefill. That equality is the check: had attention or any other route still
  been missing, the total would have fallen short.
- **The trace agrees with the public measurement.** The traced span is 3.018 s
  per prefill against 3.002 s untraced, so profiling did not perturb the number
  being explained.
- **Isolated against in-context.** The Q4_K route is 32.52 ms per launch in
  isolation and 36.0 ms in context, because in context each layer's 285 MB of
  expert weights is cold. Only the in-context figure predicts a public delta,
  which is why the accepted row's primary claim is the public A/B.
