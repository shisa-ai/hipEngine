# MX-1 F16 down-only layer2 gate is blocked by a zero tile-row count

## Summary

The MX-1 **down-only** candidate
(`HIPENGINE_QWEN4_EXP_EXACT_GROUPED_DOWN=0` + `HIPENGINE_QWEN4_EXP_Q5_1_WMMA=1`,
gate/up left at production) cannot be qualified on the current tree. The down
dispatch selects the F16-WMMA compact grouped Q5_1 down owner and calls it, but
the runner hands it a host tile-row count of `0`, so the kernel rejects the call
before any arithmetic:

```
ValueError: compact_rows, num_experts, and wmma_total_rows must be positive
  hipengine/kernels/hip_gfx1100/quant/qwen4_exp_q5_1.py:158
  <- hipengine/runtime/qwen4_exp_runner.py:4875
```

No numerical, state, task, or lifecycle verdict exists for this candidate. This
is a concrete dispatch blocker, not a pass and not a rejection, and it is
recorded for parent coordination rather than fixed in-unit (the fix is a runtime
change, which this unit's scope excludes).

## Root cause (verified from code, and reproduced)

- `exact_grouped_down` (`qwen4_exp_runner.py:4153`) is **false** with the
  override.
- `exact_grouped_q4_gate` (`:4160`) stays **true** because its trailing
  `(exact_grouped_down or HIPENGINE_QWEN4_EXP_EXACT_GROUPED_Q4_ALL)` clause keeps
  the production default `EXACT_GROUPED_Q4_ALL=1`. Gate/up stays on the
  production exact iu8-risk+repair route, as intended.
- `q5_wmma` (`:4559`) is **true**; the down chain `if q5_mmq / elif
  exact_grouped_down / elif q5_wmma / else` reaches `elif q5_wmma:` (`:4874`).
- The host `wmma_total_rows` is initialized to `0` at `:4244` and only read back
  from the device when `q4_k_mmq_prefill or (not exact_grouped_down and not
  exact_grouped_q4_gate)` (`:4254-4284`). With gate/up on the production exact
  route, neither holds, so the F16 down kernel receives `0` and raises at
  `qwen4_exp_q5_1.py:158`.
- The full MX-1 route works only because clearing
  `HIPENGINE_QWEN4_EXP_EXACT_GROUPED_Q4=0` also makes `exact_grouped_q4_gate`
  false, which lets the tile map and read-back run. The down-only route leaves
  gate/up at production, so it cannot take that path.

Engagement is established, not vacuous: the traceback passes through
`scripts/qwen4exp_candidate_dispatch.py:43 counted()`, i.e. the counted direct
alias the runner actually calls is the frame that raises. The failure is
structural and independent of prompt count, decode steps, repeats, and free
tokens.
