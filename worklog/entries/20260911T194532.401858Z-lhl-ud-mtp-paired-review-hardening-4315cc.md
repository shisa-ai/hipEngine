# Harden the paired MTP harness: protocol identity, mechanical invalidation, scoped device

## Summary

Review of `ec281e378` found three defects in `scripts/ud_mtp_paired.py` and two
record problems. All five are addressed here. The two high findings were real
holes in the harness that produced the invalid GPU0 measurement: it could accept
a payload from a different protocol, and its invalidation flag was a note rather
than a gate.

## Changes

**1. Evidence completeness now proves protocol identity (High).** Row coverage
says how many rows arrived, not which protocol produced them: a
serial-verifier payload has the same shape as a native-verifier one. Every
dimension the resolved command pinned is now compared against the payload's own
declaration — `provenance.quant` (session quant identity),
`workload.target_verify_mode`, `workload.draft_hidden_variant`,
`workload.runs`, `workload.warmup`, `provenance.repetitions`, and the normalized
`provenance.command`. Each field was mutated independently and all seven
returned `complete=True` before this change; all seven are rejected now.

The command comparison drops two things on purpose: a leading interpreter
element (the payload records the absolute python that ran it, an environment
detail) and `--output` (the payload's landing location, which `--from-raw` may
legitimately relocate). Both tolerances are tested so they cannot hide a real
protocol difference.

**2. Invalidation is now mechanical (High).** `--invalidate` previously wrote a
descriptive `invalidation` block while every pair still reported
`binding_passed=true` and `faster_than_true_ar=true`, and the exit code was
unchanged. `_verdict` now takes `timing_evidence_valid`, exposes it as a binding
gate, and forces `true_ar_denominator_present` and `faster_than_true_ar` to fail
when it is false. `binding_passed` therefore fails, `main()` returns 1, and the
artifact carries a top-level `timing_evidence_valid`. The values the clock
actually produced are preserved verbatim under `timing_as_measured`, so nothing
is lost — it is just not binding. Identity evidence (completeness, determinism,
GPU/CPU acceptance agreement) is deliberately untouched, because contention
changes timing, not token identity.

**3. Device selection is scoped (Medium).** `HIP_VISIBLE_DEVICES` was assigned
globally in `main()` and never restored, repeating the in-process state-leak
class already fixed for admission. It is now a `device_selected()` context
manager that restores both variables on exit, including on failure, and yields
the prior values for the record. It also clears `ROCR_VISIBLE_DEVICES`:
`HIP_VISIBLE_DEVICES` indexes into whatever `ROCR_VISIBLE_DEVICES` left visible,
so with `ROCR_VISIBLE_DEVICES=1` the physical GPU 1 is logical 0 and
`HIP_VISIBLE_DEVICES=1` would select nothing. Clearing it makes
`HIP_VISIBLE_DEVICES` the single source of truth for the physical index.

**4. Artifact hygiene (Medium) — recorded, not acted on.** The
`docs/REFACTOR.md` ledger entry is accurate. Its figure is now reproducible
(`git ls-files benchmarks/results | xargs du -cb | tail -1`, currently 155.7 MB,
was written as a bare "159 MB") and the removal trigger stands. The files belong
to other agents' committed units and `AGENTS.md` forbids cleaning up another
agent's benchmark outputs unless the task asks; this stays a pre-merge
coordination item.

**5. Parity table heading corrected (Medium).** `benchmarks/README.md` labelled
the four-arm A/B "W7900" while the measurement is XTX. The heading now names the
XTX and states that no valid final W7900 parity row exists. Confirmed from the
campaign rollup: `results/final-decode-campaign-2026-09-11/README.md` records
the four-arm decode and census as "GPU1 XTX".

**Invalid artifact patched.** `results/paired-ud-plain-mtp-c1-natural25-b3.json`
had `invalidation.invalid=true` beside `binding_passed=true`. Its stored
evidence now carries the mechanical invalidation gate: each pair gets
`timing_evidence_valid=false`, the two timing gates forced false,
`binding_passed=false`, and the original measured values preserved under
`timing_as_measured`. A `validator.hardened_after_run` note records that the
protocol-identity fields were not re-checked on this artifact, because its raw
payloads were overwritten by the GPU1 re-run.
