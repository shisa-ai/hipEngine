# Map SPECDEC2-PERF P8 FP16 capability gaps

## Summary

P8 is not a new FP16 recurrence campaign. The general gfx1151 Qwen3.8
`Q4_K_S` FP16 state implementation already has typed FP16 scalar, segmented,
indexed-singleton, chain row-journal, compact-peer prefill, and decode-order
writers with FP32 accumulation, and its 1,170-row production numerical/dynamic
packet passed. SPECDEC2 remains fail-closed because its runtime manifest is
strict-only and two cold adapter guards reject FP16 before mutation. The
remaining implementation blocker is narrower but real: the native target graph
requires producer-captured initial Conv/GDN state for rollback, and the
chain-journal snapshot GDN/fused-Q5 owners still write FP32 snapshots.

## Changes

No runtime behavior changed. Audited the profile registry, adapter capability,
target graph/row-journal state ABI, existing kernel catalog/registrations,
historical production evidence, and current strict fallback/lifecycle tests.

## Validation

- ROCm is alive on Radeon 8060S / `gfx1151`.
- `python3 scripts/check_lineage.py --kind kernel --diff stat` reports the known
  cataloged external drifts; no P8 kernel was ported or changed.
- Runtime resolution today:
  - strict manifest hash `0e053fd6...e2bb65b` selects only
    `linear_attn_chain_conv_decode/.../bf16_c1_exact_state_rows_tloop`;
  - explicit `production` falls back to strict (`fell_back_to_strict=true`), so
    it cannot authorize FP16 state.
- Existing registered gfx1151 FP16 leaves include:
  - `gdn_chain_recurrent_rmsnorm_gate/.../bf16_c1_exact_state_rows_tloop_fp16state`;
  - `gdn_recurrent_rmsnorm_gate` scalar/segments/indexed FP16-state variants;
  - `gdn_prefill_recurrent` state-row/segments/compact-peer FP16-state variants;
  - Q5 GDN+cast FP16-state scalar owner.
- Missing for SPECDEC2 target rollback:
  - `gdn_chain_recurrent_rmsnorm_gate+snapshot/.../*_fp16state`;
  - Q5 `gdn_chain_recurrent_rmsnorm_gate+cast{,+snapshot}` FP16-state siblings
    (or a profile-qualified unfused GDN+cast chain replacing those fused owners);
  - runner chain-journal plan selection by the resolved profile/state dtype;
  - profile/state dtype in the native target graph configuration key.
- Cold guards are in `Qwen35GGUFMTP2Adapter.capability()` and `_open_request()`.
  They may be removed only when the resolved production manifest is present,
  not merely when the legacy env flag is set.
- Historical general FP16 evidence is reusable as calibration/source evidence,
  not as SPECDEC2 qualification: KL mean/p95/p99/max
  `1.025e-4/3.192e-4/1.050e-3/3.287e-2`, top-1 99.829%, repeat/isolation and
  dynamic-width gates pass. SPECDEC2 still needs fresh root/parent/candidate/
  selected-commit/rollback/following-AR and complete economics evidence.
