# R0195 exact_row_count shape-miss device coverage

## Summary

Added the `exact_row_count` padding-shape case to the gfx1100 R0195 physical-target
device gate, completing the publicly reachable shape-miss coverage. The reason fires
when `logical_rows = request_count + candidate_rows` lands in the exact row-count set
`[8,28,32]` (`_target_group_pad_rows`, `qwen35_gguf_mtp2.py`).

The trigger is content-dependent: `candidate_rows = sum(device_draft.candidate_counts)`
is the actual NextN draft proposal count, not the budget ceiling. The standard diverse
prompts at C3 proposed only 3 of 6 possible candidates (logical_rows 5 →
`padded_to_row_multiple`). Highly predictable continuations make the draft propose the
full C3 budget for both requests, giving logical_rows = 2 + 2×3 = 8 → `exact_row_count`
with zero padding.

## Changes

- `tests/test_live_gguf_r0195_physical_target.py`: added `_PREDICTABLE_PROMPTS`
  (counting / alphabet continuations) and a `prompt_set` selector threaded through
  `_worker` / `_run_case` / the `R0195_WORKER` spec (4th field, default `default`, so
  existing cases are unchanged). New test
  `test_exact_row_count_shape_attributed_without_padding` runs C3 production with the
  predictable pair and asserts `reason == "exact_row_count"`, `logical_rows == 8`,
  `selected_rows == 8`, `pad_rows == 0`, `request_count == 2`.

## Validation

Measured on gfx1100 (W7900), subprocess-per-case, model
`/models/gguf/Qwen3.8-27B-Q4_K_M.gguf`:

- Probe: standard prompts C3 → logical_rows 5, `padded_to_row_multiple` (draft proposed
  3/6 candidates). Predictable prompts C3 → logical_rows 8, `exact_row_count`, pad 0.
- Gate: `uv run pytest tests/test_live_gguf_r0195_physical_target.py -v` →
  **5 passed in 501.39s** (C1 exact+state, C2 exact+state, C4 named miss, wider-group
  8-request capacity, exact_row_count shape).
