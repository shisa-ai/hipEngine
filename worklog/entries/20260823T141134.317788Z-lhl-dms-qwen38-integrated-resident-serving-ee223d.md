# Wire compact DMS into Qwen3.8 resident serving

## Summary

Wired the exact schema-v2 candidate into the normal Qwen3.8 c1 resident session.
The correctness-first route uses dense BF16 KV only as a temporary prefill
owner, captures sidecar decisions at the exact hidden stage on GPU, packs
survivors directly into a right-sized device compact owner, releases the dense
pool, and routes decode through GPU projection, append, split-K compact
attention, gate, and output projection.

## Changes

- Added explicit `dms_metadata_path` / `dms_max_new_tokens` resident selectors;
  dense remains the default when absent.
- Added GPU prefill decision collection with layer-major device storage and one
  lifecycle-barrier metadata readback.
- Allocate temporary paged dense prefill KV through the existing deferred pool,
  then atomically unbind/release/close it after direct compact pack.
- Allocate compact slots from measured survivor counts plus decode reserve,
  rather than full logical context, and preserve exact artifact/plugin checks.
- Replaced the normal full-attention decode owner with direct DMS append and
  bounded compact attention only after successful pack.
- Added an exact-command long-context smoke harness at
  `scripts/qwen38_dms_integrated_long.py`.

## Validation

- Real 768-token exact-Q4 integrated smoke: prefill output token 25, compact
  31,916/49,152 live/logical cells (1.54004x), one compact decode output token
  198, finite logits, 41 expired rows, no host K/V payload, zero allocations

- Same-resident dense versus integrated heldout `code-08`, four decode steps:

  `0.0002781/0.0001129/0.00006338/0.00004436`. Integrated post-step compression

- Affected focused bundle: 16 passed. Ruff-targeted, py_compile, and diff checks
