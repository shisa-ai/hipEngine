# Admit AOTriton on slot-local INT8 oracle prefill

## Summary

The server INT8 KV route is 27.6x slower than the direct engine on long prompts
(other agent's measured census, `2026-09-09-rx7900xtx-server-int8-route-census.json`).
Localized the largest tractable component: the `int8_direct` route's slot-local
full-attention prefill hard-disables AOTriton for every layer that owns a
transient BF16 oracle, leaving it on the native split-K paged kernel at 16 query
rows per batch. That is the only place in the engine reading a dense BF16 oracle
without AOTriton - the scalar bulk parent and the strict arithmetic declared by
`scripts/execution_profile_gguf_int8_direct_prefill_gate.py` both read the same
oracle pair *through* AOTriton, and `_gguf_int8_prefill_direct_enabled`'s own
docstring names the AOTriton oracle bridge as the fast reference.

Admission is now an opt-in gate, default OFF (bit-identical to the pre-change
tree). Promotion to default needs the production-profile numerics gate because
the attention reduction order changes.

## Decisions

- **Not a bit-exact win.** Flag-on moves final-prefill `logit[0]` by 5.27e-3 at
  4,096 tokens while the 8 greedy continuation IDs stay identical. This is an
  arithmetic change, so it stays default OFF pending the calibrated
  mean/tail/max KL + top-1 gate per `docs/EXECUTION-PROFILES.md`. It is not
  retainable as a strict parity win and no benchmark topline row is claimed.
- **Scoping proven by control arm.** The scalar bulk parent
  (`session.prefill(use_bulk=True)`) is bit-identical across flag states
  (`logit[0]` delta exactly 0), confirming the change touches only the packed
  slot-local path.
- **Packed vs scalar parity is NOT the oracle.** The two prefill entry points
  already disagree on this route before any change (logit max abs diff 7.79,
  top-1 and generated IDs differ at 4,096). That is intended:
  `generation/qwen35_gguf.py:7406-7408` records that they "compare different GDN
  state-capture arithmetic", which is why `int8_direct` is forced onto the packed
  route unconditionally. The binding oracle is packed-before vs packed-after.
- **The packed-workspace double allocation is NOT dead weight.** Earlier reading
  suggested the eager lease (`generation/qwen35_gguf.py:5560-5592`, pool sized to
  exactly 2x declared context) reserved pages the packed state could never
  address, since the verifier is guarded to context < 1024. That is wrong for
  decode: `_sync_packed_decode_initial_state`
  (`runtime/qwen35_gguf_runner.py:25702-25713`) copies the whole KV history
  (`start_position=0, rows=start_position`) from the row's own pages into the
  packed planes on the prefill->decode transition. Shrinking the lease would turn
  a silent over-reservation into a `RuntimeError` at long context. The fix is the
  recorded CONCURRENCY2 task-5 follow-up (packed slots borrow the row's own lease
  pages; flush scatters only conv/recurrent state), captured in `docs/REFACTOR.md`.

## Validation

Harness: `scratchpad/prefill_route_parity.py` (in-process A/B, no server),
deterministic varied prompt (`np.random.default_rng(20260909)`, IDs in
[1000, 32000)), Qwen3.8-27B `Q4_K_M`, `int8_per_token_head` + FP32 scales,
`max_sequence_length` 16384 so the route is `int8_direct` with no BF16 mirror,
env `HIPENGINE_GGUF_INT8_KV_ALLOW_UNVERIFIED_LONG=1`
`HIPENGINE_GGUF_INT8_KV_BF16_FULL_LAYERS=none` (all 16 full-attention layers
INT8, matching the retained direct-route protocol). W7900, gfx1100, GPU0.

- `pytest -q tests/test_qwen35_gguf_slot_local_aotriton_admission.py` - 11 passed
  (RED first: `ImportError` on the missing symbols).
- **Default OFF is bit-identical to the pre-change tree**, both arms: generated
  IDs match and `logit[0]` delta is exactly 0.
- Flag ON at 4,096 tokens, packed slot-local arm: 93.97 -> 129.38 tok/s (1.38x),
  tracked peak 17.6694 -> 17.6457 GiB (-24 MiB), 8 greedy IDs identical,
  `logit[0]` delta 5.27e-3.
- Flag ON at 8,192 tokens, packed slot-local arm: 44.31 -> 121.44 tok/s (2.74x),
  peak 17.7967 -> 17.7731 GiB, same first token. The ratio grows with context, as
  expected for a query-tiled kernel replacing a 16-row split-K one.
- Same-session run-to-run spread on the packed baseline is ~13% (82.71 / 93.97
  tok/s across runs), so treat 4K as 1.4-1.6x and 8K as the firmer point.
- Route context for the same 8,192-token shape: BF16 default 766.0 tok/s,
  oracle-free INT8 WMMA 735.6, INT8+oracle scalar bulk 129.4, INT8+oracle packed
  44.3. This change closes the packed-vs-scalar half only; the remaining ~6x to
  BF16 is the oracle route's own double-write/cast cost, not the attention kernel.

Not run: the production-profile numerics gate. No performance claim is retained
and `benchmarks/README.md` is untouched.
