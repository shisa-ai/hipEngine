# Batch exact Qwen4Exp PLE and Conv prefill

## Summary

Promoted two T0 prefill dataflow contractions: one PLE mmap gather/dequant per
chunk and a registered K4 bulk Conv whose per-row arithmetic/state are bit-exact
to serial decode. p508 launches fall 29,341→11,053 and paired wall improves
1.01% with exact logits.

## Changes

- PLE staging flattens `[chunk_rows,16]` indices, stages once into the existing
  pinned double ring, and exposes that view for the immediate synchronous H2D.
- New Qwen4Exp-only bulk Conv kernel uses strict decode source-level arithmetic
  per row and one final-state update launch; Qwen35 bulk arithmetic is unchanged.
- `HIPENGINE_QWEN4_EXP_EXACT_CONV_PREFILL=0` retains row-serial fallback.
- Reoriented the campaign doc around Q4 parity: exact prefill plumbing, grouped
  selected-expert decode, direct host/launch measurement, Vulkan/HIP reference
  profiling, and separate strict/production targets.

## Validation

- PLE calls p508: 508→2; Conv compute launches 18,432→72 plus 72 state writes;
  total launches 29,341→11,053 (-62.33%).
- Counterbalanced p508 8.785056→8.697485 s, 57.825470→58.407688 tok/s
  (+1.01%, 1.0101x); all logits bits/top-1 exact.
- Conv production-geometry output and final state are F32-bit exact to 17 serial
  decode rows.
- 23 focused GDN/PLE/artifact/generation tests pass.
- Cached rocprof emits `qwen4_exp_linear_attn_conv_prefill_exact_kernel`; no
  compiler child. Cross-run frequency shifted globally, so trace durations are
  not used as the speed claim.
