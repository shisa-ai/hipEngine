# Route observed MoE native-state divergence through serial exact verifier

## Summary

The gfx1151 Qwen3.6 MoE native verifier passed the short teacher-forced row screen but diverged from AR after repeated partial accepts. The divergence was independent of graph replay and device proposal handoff. Explicit MTP therefore keeps running but selects the existing serial-exact target verifier for MoE sessions on gfx1151.

## Changes

- `hipengine/kernels/hip_gfx1151/__init__.py` declares `GGUF_SPECDEC2_MOE_NATIVE_STATE_SAFE = False` with the observed failure as its concrete reason.
- `hipengine/generation/qwen35_gguf_mtp2.py::_target_verify_mode_for_context` reads that backend capability for an actual MoE target and returns `serial_exact` when native was requested. Non-MoE targets, explicit non-native requests, DMS targets, and other backends retain their previous selection.
- `tests/test_unit_qwen35_gguf_mtp2_seam.py` covers the gfx1151 MoE fallback and confirms the dense gfx1151 route remains native.

## Validation

- Teacher-forced native gate on Qwen3.6-35B-A3B Q4_K_M, gfx1151, BF16 KV, prompt window 512, budgets 1 and 2, two repeats: 90 rows; mean KL `3.692e-4`, p95 `2.420e-3`, p99 `4.994e-3`, max `7.382e-3`, top-1 `1.0`, deterministic, passed. This covers early verifier rows but not cumulative accepted-state drift.
- Clean native graph with host proposals still diverged at output index 35 on a 128-token greedy request: AR and MTP both returned HTTP 200, MTP used 48 cycles, and `ids_equal=false`, `first_diff=35`. Raw result: `/tmp/mtp-repair/moe-hostproposal-native.json`.
- Clean native eager verification with host proposals also diverged at output index 35: `ids_equal=false`, `first_diff=35`. Raw result: `/tmp/mtp-repair/moe-hostproposal-eager.json`.
- Clean serial-exact baseline matched AR for all 128 tokens: HTTP 200, MTP used 51 cycles, `ids_equal=true`. Raw result: `/tmp/mtp-repair/moe-serial-clean.json`.
- Public route after the capability fallback: two explicit `speculative_mtp=true` requests and two AR controls on the same 17-token prompt all returned HTTP 200; explicit MTP used MTP and matched AR and its own repeat. Raw result: `/tmp/mtp-repair/moe-auto-serial-fallback.json`.
- Targeted CPU validation: `.venv/bin/python -m pytest tests/test_unit_qwen35_gguf_mtp2_seam.py tests/test_unit_qwen35_gguf_mtp2_c1_physical.py tests/test_unit_mtp_sampler_lifetime.py tests/test_unit_speculative_mtp_serving_capability.py -q` passed.

## Scope and remaining work

This is a correctness containment decision, not a throughput claim. The native MoE path remains implemented but is not selected on gfx1151 because it has an observed cumulative state failure. Re-enable it only after a same-host multi-prompt trajectory gate covers partial accepts beyond the short teacher-forced window and passes. The serial-exact route is slower than native in the measured diagnostics, so native MoE state repair remains the next optimization/correctness task.
