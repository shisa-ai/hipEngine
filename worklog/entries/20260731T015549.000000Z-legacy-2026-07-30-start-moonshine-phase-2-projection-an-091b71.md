### Source-F16 projection family

- RED `uv run --extra dev python -m pytest -q tests/test_moonshine_hip_projection.py` fails **4/4** only because `linear.moonshine_projection` is absent. GREEN adds a dedicated raw-pointer HIP family with FP16 input/weight/output, FP32 accumulation, and single, paired, and triple launches. Explicit keys cover batch-one Q/O, row precompute, paired cross K/V, and triple self Q/K/V; gfx1151 receives native aliases through the existing peer backend package.
- The gfx1151 production-shape gate runs hidden 416, one-row single/triple, and 40-row paired K/V against the independent NumPy oracle. `HIPENGINE_HIP_ARCH=gfx1151 PYTHONNOUSERSITE=1 PYTHONPATH=. mamba run -n therock python -m pytest -q tests/test_moonshine_hip_projection.py` passes **4/4**; the durable smoke is finite/all-close with maximum absolute error **3.0517578125e-5**. One broader `uv` attempt incorrectly entered the GPU test merely because the HIP library was visible, then used a compiler without its device-library path; the guard now requires explicit `HIPENGINE_HIP_ARCH=gfx1151`, while CPU bundles skip and the proper `therock` gate executes it.
- Prebuild with the retained compiler-version file, run the cache-only child, then profile exactly once with `rocprofv3 --kernel-trace`. The trace names `moonshine_f16_projection_kernel`, `moonshine_f16_projection_pair_kernel`, and `moonshine_f16_projection_triple_kernel` at **20.759/56.788/69.772 us** for four 416-wide rows. All use local256, VGPR16, SGPR128, LDS512, and scratch0; no compiler runs inside the profiler. Raw CSV/child JSON remain under `/tmp`.
- The adjacent Moonshine CPU/model/runtime, registry, and Laguna projection selection bundle passes with the intended one non-gfx1151 GPU skip. Ruff, compileall, all seven legacy fixtures, registry smoke, and `git diff --check` pass. This is a correctness/profile baseline only, with no full-decoder or performance-promotion claim.

### Embedding, residual, partial-RoPE, and self-cache glue

All run local256 with LDS0/scratch0; VGPR is 8/8/16/16/24. The adjacent Moonshine families/oracles/model/runtime and registry bundle passes with intended target skips; Ruff, compileall, all legacy fixtures, registry smoke, and diff checks pass. This establishes primitive and bounded-fusion correctness only; attention and the full decoder remain unimplemented.

### Bias-aware FP16 projection boundary

- Add a RED requirement to the existing projection tests before gated-MLP work: `moonshine_projection_bias/single_fp32_accum` must add the FP16 bias to the FP32-reduced dot before rounding. The RED run fails only on the absent wrapper/key. This is required because adding a bias after the already-rounded no-bias projection would not reproduce PyTorch's `Linear` boundary.
- The gfx1151 production-shape projection gate remains **4/4** and now covers the bias-aware hidden-416 path against `moonshine_projection(..., bias)`, with maximum family absolute error unchanged at **3.0517578125e-5**. The cache-only profile names `moonshine_f16_projection_bias_kernel` at **10.620 us**, local256/VGPR16/SGPR128/LDS512/scratch0. Adjacent projection/oracle/registry tests, Ruff, compileall, and diff checks pass. This extends the projection primitive only; gated activation follows separately.

### Gated decoder MLP primitive and Phase 2 glue closure

- RED adds a hand-checkable NumPy `moonshine_gated_silu` contract and HIP wrapper/registry/full-chain tests; four CPU-reachable tests fail only on the absent oracle/module while two gfx1151 gates are target-skipped. GREEN exposes the CPU `value_gate_split` oracle, reuses it inside `moonshine_decoder_mlp`, and adds one raw-pointer FP16 kernel that evaluates SiLU and the value product in FP32 before the FP16 boundary.
- The production chain stays deliberately unfused: bias-aware FP16 `416->3328`, gated SiLU `3328->1664`, bias-aware FP16 `1664->416`, then the already-registered rounded residual. - The cache-only full-chain trace names two `moonshine_f16_projection_bias_kernel` launches plus `moonshine_gated_silu_fp16_kernel` and `moonshine_residual_fp16_kernel` at **51.497/4.289/12.664/2.966 us** for fc1/activation/fc2/residual. The activation is local256/VGPR16/SGPR128/LDS0/scratch0; no compiler runs inside profiling.
- The combined gfx1151 projection/LayerNorm/glue/MLP gate passes **22/22**. The adjacent CPU-targeted Moonshine/oracle/model/runtime/registry bundle passes with intended GPU skips; Ruff, compileall, all legacy fixtures, registry/CPU smokes, and diff checks pass. This completes the projection-and-glue task only. Self/cross attention and full decoder composition remain separately tracked and no end-to-end decoder/performance claim is made.
