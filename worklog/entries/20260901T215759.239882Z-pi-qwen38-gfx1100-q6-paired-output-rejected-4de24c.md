# Reject paired-output planar Q6 ownership

## Summary

Rejected and fully removed paired-output planar-Q6 ownership. The candidate
placed two independent retained WG128/col8 DPP-R8 owners in one WG256 block,
halving `grid.x` while preserving each half's input traversal, arithmetic,
reduction, and store order. It is bit exact but uniformly slower.

## Changes

- Temporarily parameterized the grouped planar-Q6 kernel for one or two output
  owners and added a WG256 paired launcher/wrapper.
- Removed every candidate source path after the actual-weight leaf gate. No
  runtime route, registry entry, environment policy, or test remains.
- Added a compact rejection artifact; no benchmark scoreboard row changed.

## Validation

- Actual Qwen3.8 planar-Q6 recurrent-QKV, full-V, and FFN-down weights at R24
  and R32; 40 alternating HIP-event pairs/cell, three launches/sample.
- All six cells are BF16-bit exact, but every median loses: **0.860–0.907x**.
  The candidate records only **1/240** pair wins total. Representative losses:
  recurrent-QKV R32 **0.4404→0.4935 ms**, full-V R32
  **0.05695→0.06276 ms**, FFN-down R32 **0.6693→0.7779 ms**.
- WG256 reduces block scheduling flexibility/occupancy without reducing total
  weight work or thread count. Rejected before marker or full-suite spend.
- Final source matches `9cd563935`; only this worklog and
  `benchmarks/results/2026-09-02-w7900-q4km-k3-q6-paired-output-rejected.json`
  remain.

## Next

- Keep independent WG128/col8 grouped-R8 ownership. Do not revisit wider Q6
  output ownership without a mechanism that reduces weight work or per-thread
  state rather than only coarsening scheduling.
