# Resident prefill stall is flaky: clean 0.3 s run under event instrumentation

## Summary

With finer-grained event wrappers (attn-only and FFN bracketed separately
from the whole-layer call), the same bare `Qwen35GGUFResidentSession`
sequential prefill that hung four times **completed in 0.3 s**: 1152
per-primitive layer events, all `completed=True`, zero incomplete, valid
first token (5388). The stall is therefore **nondeterministic** — a race,
not a deterministic kernel livelock; the extra event records perturb
host/device timing and mask it. Entry eac73a's "layer 3" verdict was the
race's landing spot that run, not a fixed kernel defect.

This also reframes the bulk-prefill NaN (entry ee20cd): a missing
dependency producing garbage/NaN readbacks and a missing dependency
producing a livelock are the same class of state/control bug (per AGENTS:
do not relabel state/control bugs as numerical drift). Both resident-route
symptoms on this lane are now consistent with one flaky synchronization
defect, timing-sensitive and gfx1151-lane-qualified elsewhere.
