# The conv-state mismatch means the fp32 qkv projection values differ, so the divergence is T2 association drift in the GEMM

## Summary

The conv-state mismatch is an *observation point*, not the origin. The GDN
convolution kernel at `qwen35_gguf_runner.py:8980` writes the state from
`scratch.linear_qkv_f32`, an **fp32** buffer, so a differing conv state means the
qkv projection values feeding it differ at those positions. The convolution
itself is deterministic on equal inputs, so the first divergent value is in the
**qkv projection GEMM** (quantized weights times activations) or in the hidden
input to it, not in the conv.

That places the whole divergence in the doc's **T2 association/layout drift**
class: the packed wave and the single-session path contract the same matrices in
a different tile/accumulation order. Bytes are expected to differ; the binding
question is the numerical envelope, which is exactly what §6.1 measures.

## Validation

- `qwen35_gguf_runner.py:8968-8991` -- the conv prefill kernel takes
  `scratch.linear_qkv_f32` (input, fp32), `conv_state` (in/out), the
  `ssm_conv1d` weight, and `conv_out`, with `rows` and `cfg.ssm_conv_kernel`.
  The state is produced from the fp32 input rows by that one kernel.
- Therefore equal fp32 inputs would give equal states; the recorded layer 1
  (boundary) and layer 0 (post-suffix) `linear.conv` mismatches mean the qkv
  values differ upstream.
- `_capture_state` reads `scratch.layer_conv_states` and
  `scratch.layer_recurrent_states` per layer, which is how the gate observes
  this.

Consistency with the rest of the investigation: the packed oracle reproduces the
candidate bit-exactly (same route, same contraction order), both single-session
variants differ in ~127 of 128 components (different contraction order), the
difference is decision-relevant only at a handful of positions out of 1,024
(11 flips, the largest at `heldout-code` max KL 3.002), and the served route is
byte-stable across prefill chunk widths because it always uses the packed path.
