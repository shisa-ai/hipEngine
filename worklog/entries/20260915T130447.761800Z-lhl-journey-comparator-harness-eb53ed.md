# Add a general llama.cpp-family prefill comparator harness

## Summary

The external comparison the campaign keeps quoting is a single hardcoded binary
in a single-purpose script, so every new engine needed either a copy of that
script or an edit to it. This is the general form: one harness, one arm per
engine, with the things that decide whether a comparison is valid - file, KV
dtype, attention mode, context, batch sizes, threads, case set - as arguments
and recorded in the output rather than implicit.

It also records what the old script did not: the server binary's hash, and for
a git checkout its commit, remote and dirty state. An engine row without those
is not attributable.

## Changes

- `scripts/qwen4exp_llamacpp_prefill_comparator.py`: starts one llama.cpp-family
  server against the pinned UD-Q4_K_XL GGUF, drives prefill-only requests
  (`n_predict=1`) with exact token ids from a canonical fixture, and records the
  server's own `prompt_ms`/`prompt_per_second` plus the client wall.
  `--profile` wraps the server in `rocprofv3` and buckets kernel time by name;
  the profiled run is labelled `diagnostic_profiled_not_performance` because its
  rate is not comparable to an unprofiled one.
- It refuses a context smaller than the largest selected case instead of
  letting the server truncate the prompt silently.
- `tests/test_unit_qwen4exp_llamacpp_comparator.py`: five guards - role
  bucketing is total and deterministic; a typo'd case id selects nothing; the
  4352-token context that the recorded comparator runs used covers the 4K cases
  but not the new p16384 fixture; source state reports commit and dirtiness and
  tolerates a non-git tree.

## Validation

- `.venv/bin/python -m pytest
  tests/test_unit_qwen4exp_llamacpp_comparator.py` → 5 passed.
- End-to-end mechanics validated against the existing halo-box `5f85164` HIP
  build: `code-p512`, one repetition, `prompt_ms=1753.294`, 292.0 tok/s. That
  number is **not** comparable to the recorded 434.3 tok/s for the same binary:
  three HIP builds were compiling on all 32 cores at the time. It is a
  mechanics check, not a measurement.
