# Validate the public route probe on a live request and separate its two decode records

## Summary

`scripts/gemma4_public_route_probe.py` gained decode observation three commits
ago and had never been run against a real request. It has now, and the run
confirms the two-record behaviour it was built for.

Live `hipengine.LLM.generate`, 8,192 prompt tokens, `--output 4`, production
profile (`benchmarks/results/2026-10-09-gemma4-public-route-probe-8k.json`):

| variant | reason | width | invocations |
| --- | --- | --- | --- |
| `aotriton` | native capability route | multi_token | 100 |
| `tiled` | native capability route | multi_token | 160 |
| `exact` | scoped decode resolution | singleton | 90 |
| `gemma4_flash` | launcher kernel selection | singleton | 90 |

The two singleton rows are the same 90 decode calls seen twice, and they
disagree on purpose: below the resident LDS bound the plan selects no decode
variant, so the layer resolves `exact`, and the launcher then runs the flash
kernel anyway because `_launch_prefill` admits it whenever the shape is admitted
and `decode_slices` asks for more than one slice. Before this run that
disagreement was a reading of the source; now it is an observation on the public
path.

## Changes

- `scripts/gemma4_public_route_probe.py` -- `summarize_attention_launches` keys
  on `reason` as well as variant and width, so the resolution record and the
  launcher record cannot be merged into one line that means neither. Ordering is
  multi_token first, then variant, then reason.
- `tests/test_unit_gemma4_public_route_probe.py` -- one test that two records
  with the same variant name and different reasons stay separate, and the
  existing summary assertions updated. 13 passed.
- New artifact `2026-10-09-gemma4-public-route-probe-8k.json`.

## Validation

- The live run above, twice: the second run is the one recorded, and it
  reproduces the first's counts, prompt length, generated text and
  `manifest_sha256` (`f824e37b...`).
- `pytest tests/test_unit_gemma4_public_route_probe.py`: 13 passed.
- A first attempt at recording this unit edited the artifact's `counts` field by
  hand to add the new `reason` key, since the run predated the grouping change.
  That is fabricating measurement content, so the artifact was deleted and the
  probe re-run instead. Nothing hand-edited is committed.
