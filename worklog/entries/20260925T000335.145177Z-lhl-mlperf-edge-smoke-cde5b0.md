## Findings

1. **Empty output is reproduced at the server boundary.** Harness request turn
   45 (scored assistant turn 46) has neither content nor tool calls. A focused
   replay with raw SSE and private diagnostics generated 1,024 tokens, then
   forced tool closure (`tool_call_close_forcing`). The private finish reason
   is `invalid_tool_call`, but public `finish_reason` is `stop` with no output.
   This is not a tokenizer falsely classifying a valid structured call as empty.
2. **Upstream event timing mixes measurement points.** 23 of 26 nonempty
   requests have completion 78–126 microseconds before first-receive. The pinned
   `load_generator/session.py` uses worker `resp.completed_at` for completion
   and coordinator `now_ns` for first-receive. `TpotTrigger` subtracts those
   directly; only two samples populate its post-first-chunk denominator and the
   resulting values are negative. Do not invert these into decode tok/s.
3. **Endpoint output is also buffered on the probed replay request.** Direct
   SSE reproduction of turn 1 emits a role chunk immediately and the entire
   text near completion, with malformed tool markup in ordinary content. This
   is not token-by-token streaming, so fixing only the upstream timestamps
   would not establish token-level TTFT/TPOT.
4. **Actual route is AR.** Before/after counters increase host-sampler requests
   by 27 and MTP requests by zero. The short diagnostic reports
   `processed_argmax`, `gguf_packed_ar_host_sampler_decode`, and
   `processed_logits_required` from tool constraints and stop/repair sequences.
   We did not remove controls to force speculation.
5. **Quality and counting need separate attention.** Two completions report
   `length`; several others emit markup or prose instead of structured calls.
   Client estimates differ from engine counts (first prompt 1,363 versus 1,383).
   All issued event records retain `enable_thinking=false`; no BFCL gate ran.
