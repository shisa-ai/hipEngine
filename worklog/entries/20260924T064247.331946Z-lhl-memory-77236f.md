# Live ownership gate: grow, MTP, reclaim, and close leave zero outstanding allocations

## Summary

Task #16's CPU half pinned the ownership contract on the fake-runtime seam but
its acceptance is a live one, and it had been held back by GTT pressure that is
now gone. `tests/test_live_gguf_pool_ownership.py` drives the real cycle on the
device and the headline assertion passes: after the final reclaim and engine
close, the process-local device allocation tracker is back to its pre-session
baseline.

## Changes

- `tests/test_live_gguf_pool_ownership.py` (new, one live case). Baseline
  `memory_stats()["active_allocations"]`, then on a real INT8-KV resident
  session: create the packed verify workspace and its scratch, run a real MTP
  generation, grow the verifier scratch to a wider geometry, run MTP again on the
  other side of the growth, then close. Asserts the growth widened the workspace,
  that the reclaim guard refuses while a decode graph still binds it, and after
  close that the packed verify state, its scratch, and the retained prefix
  snapshot arena pool are all gone and `active_allocations` equals the baseline.

## Validation

- `source /tmp/gfx1151-env.sh && run1151 .venv/bin/python -m pytest
  tests/test_live_gguf_pool_ownership.py --suite live -v` -- **1 passed in 48s**
  on gfx1151 with 120 GiB free. The MTP generations produced six tokens each; the
  growth moved the scratch rows; the close returned the count to baseline.

## Next

- Findings from building this gate, all confirmed by the runs rather than
  inferred. The resident session has no device KV pool of its own: `_device_kv_pool`
  stays `None` through MTP generation, because the dynamic global pool belongs to
  the generation runner (`Qwen35GGUFResidentModelRunner._kv_pool`) and is created
  by the generator's workspace-lease decision. The packed verify workspace is
  created by `_ensure_packed_verify_workspace` (and by the graph-capture path),
  not by the MTP decode session, and it allocates at the geometry it is asked for,
  so growth means asking for more rows *and* a wider context than the live one.
  `release_idle_packed_workspace` refuses with "cannot release idle workspace
  while a live graph still binds it" after a decode session, which is correct --
  the graph replays raw plane pointers -- and engine close is what tears the
  graphs down and then reclaims.
- Not covered by this gate: pool *page* growth and `shrink_idle`. The global
  device pool is created lazily by the generator, so reaching it needs the
  generation path rather than the resident session, and `shrink_idle` is a
  documented no-op that returns 0 (`DeviceKVPoolStats.shrink_events` is fixed at
  0), so there is no shrink to observe. The pool's close guard does cover the
  leak that matters here: it refuses to close with an unreleased resident charge,
  which is the verifier-scratch charge this task's budget work added.
