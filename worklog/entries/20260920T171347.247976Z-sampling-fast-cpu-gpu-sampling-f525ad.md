# Optimize CPU and full-vocabulary GPU sampling against greedy decode

## Summary

User requests both faster CPU sampling and a full fast GPU sampler, using the
same comparison table and throughput loss versus greedy as the yardstick.
Development, model comparison, lifecycle validation and explicit sampler
provenance are complete. The final same-host table is recorded below.

The prior same-host table is greedy 11.8024 tok/s, original host 7.3754,
probability-sort-bypass host 8.9781, and original native GPU 7.5530. These are
instrumented steady-state decode rates, not HTTP or prefill-inclusive rates.
The new comparison will refresh greedy/host/native under the identical protocol:
zbook / Radeon 8060S, Qwen3.8-27B Q4_K_M, strict BF16 KV, capacity 4 / occupancy 1,
MTP/cache off, all 10 category prompts and 8 heldouts, natural source-text inputs,
16 output tokens, temperature 0.7 / top-p 0.95 / seed 17, two repeats.
Loss percent is `100 * (1 - sampled_tok_s / greedy_tok_s)` from the same run.

## Upstream source review

These are source-inspection findings, not measured upstream performance claims.

- llama.cpp local read-only checkout at `17252c769a63c1cb650ce98ae309cf4de0da7778`,
  `src/llama-sampler.cpp:135,1549`: MIT CPU bucket/partial sorting; top-p starts
  with 256 candidates and expands to the full vocabulary if mass is insufficient.
  This is not a hidden fixed top-k cap. Its backend graph implementation uses
  argsort, softmax and cumulative sum. Host selection uses `std::discrete_distribution`.
- vLLM `49ee12d742b4a5524d2a3a3ee6c3fb77e4913073`,
  `vllm/v1/sample/ops/topk_topp_sampler.py`: Apache-2.0 FlashInfer CUDA sampling
  avoids sorting through rejection sampling; ROCm can use AITER. Per-request
  generators and processed-logprob requirements trigger fallbacks. Native paths
  use Triton/PyTorch filtering followed by exponential-noise sampling.
  Source: https://github.com/vllm-project/vllm/blob/49ee12d742b4a5524d2a3a3ee6c3fb77e4913073/vllm/v1/sample/ops/topk_topp_sampler.py
- SGLang `80da4432d085ed4d6166ef643d9fd2b829dbb0c5`,
  `python/sglang/srt/layers/sampler.py`: Apache-2.0 FlashInfer-backed filtered
  sampling where supported, with a Torch sorting fallback and explicit seeded
  sampling limitations on the FlashInfer route.
  Source: https://github.com/sgl-project/sglang/blob/80da4432d085ed4d6166ef643d9fd2b829dbb0c5/python/sglang/srt/layers/sampler.py
- FlashInfer's inspected `include/flashinfer/sampling.cuh` is Apache-2.0 but
  contains CUDA/CUB/curand and inline PTX dependencies. Direct inclusion is not
  compatible with our torch-free raw-pointer HIP runtime. This source was read
  for algorithm context, not copied into the implementation.

The useful ideas are reusable; framework wrappers, RNG mappings and cutoff/tie
semantics are not interchangeable. No upstream code is copied by the CPU change.
The broad `python3 scripts/check_lineage.py --kind kernel --diff stat` command
fails because `/home/lhl/amd-gpu-tuning/reference/atlas` is absent. A narrow
`--file '*sampl*' --diff stat` succeeds with no selected sources. This external
reference failure is not a kernel correctness result.

## Changes

- CPU candidate ordering uses fast numeric sorting and repairs only equal-score
  groups with unique integer `(group, token-ID)` keys. Already ordered and uniform
  inputs bypass sorting; vocabularies too large for packed keys use stable sorting.
  No candidate truncation, arithmetic change, tie change or RNG change.
- Added frozen-parent ordering tests over full model vocabulary, random/tied/
  uniform/nonfinite inputs, top-k boundaries and seeded token/logprob sequences.
- Added per-arm decode-rate and loss-versus-greedy summaries to the existing
  overhead profiler, with tests. A host-only run has no claimed greedy delta.
- GPU implementation uses full-vocabulary tile sorting, parallel merging and
  FP64 cumulative scans of FP32 weights, without a hidden top-k cap. The
  `sorted_rows_i32` variant preserves the native seed/step/physical-row RNG ABI;
  temperature-only draws change ordering, not the intended categorical law.
  The original registered primitives and explicit `full_vocab_algorithm="strict"`
  workspace choice remain debugging fallbacks.
- Invalid-row failure is transactional: kernels write workspace-owned output
  staging; every row is validated before caller outputs or histories change.
- The lifecycle harness now defaults to `top_k=0`. It checks that released pool
  references and pins equal independently reported workspace lease pages,
  rather than incorrectly demanding zero live workspace pages.
- The comparison reports prefill-inclusive engine end-to-end output tokens/s,
  separate from steady decode. Model preparation and tokenization are excluded;
  these are not HTTP throughput measurements.

## GPU correctness and review repairs

The first review found two real defects: FP32 division before centering could
turn extreme finite tied logits into `inf - inf` and collapse sampling to argmax;
validation of each row immediately before observing it could advance an earlier
row before a later invalid row raised. New regression tests produced 10 failures
and 3 passes before repair. Widening and centering logits before division plus
staged output publication repaired both. The independent reference no longer
copies the overflow fallback.
