# capture current server prefill attribution

## Summary

Task #22 cannot reconcile the earlier “97% WMMA” and “~0.4 s non-kernel”
claims from the existing packets: the server response already carries
`render_ms`, `tokenize_ms`, `admission_prepare_ms`, `prefill_ms`, and
`request_total_ms`, but `scripts/gguf_mtp_c1c8_server_bench.py` discarded them.
The existing `native_full_prefill_groups` counter is cumulative and proves that
grouping occurred, but cannot report the actual group sizes.

The harness now has an opt-in attribution mode that keeps response telemetry and
wraps the real resident runner's `_try_prefill_native_work_batch` method. It does
not construct an independent model/session or replace the server path. The
rollup closes the barrier-to-last-response wall on the latest-completing lane and
leaves every unmeasured interval in an explicit residual instead of assigning it
to host or kernel work by subtraction across unrelated protocols.

## Changes

- Added `--capture-prefill-attribution` to the canonical C1-C8 server harness.
  The default protocol and overhead remain unchanged.
- Captured per-choice backend timing, queue generation shape, before/after
  `native_full_prefill_groups`, and exact handled group sizes/prompt lengths from
  the actual resident grouping entry point.
- Added a pure per-width/arm attribution rollup for render, tokenize,
  admission-prepare, native prefill, EngineLoop residual, queue/response
  residual, group-size histograms, and refused cells.
- Added RED/GREEN unit coverage for response extraction, real-owner traversal and
  wrapping, critical-path arithmetic, group sizes, and the opt-in CLI.
