# Muse Glimmer DFlash draft window attention: non-causal WMMA block-flash (3.2x)

## Summary

Task #7 — the remaining half of §11 #3 (the draft head landed in 47ba148ca).
The drafter's window attention (5 layers, 32 Q / 8 KV heads, d128, block rows
over a 2048 window) ran on the strict scalar Gemma4 block kernel at ~9.2
ms/cycle. Every shipped flash route was incompatible (AOTriton prefill needs
mask_is_causal + head_dim 256 + keys<=window; the muse_glimmer/gemma4 decode
flash is causal). Added a dedicated non-causal windowed WMMA block-flash kernel
adapting the flash-prefill multi-token pattern to the draft's 4:1 GQA: one block
owns TOKENS_PER_BLOCK adjacent query rows of a KV head, each staged 16-key K/V
tile is shared by the waves, and the WMMA row dimension packs the GQA Q heads
(lane16 < GQA active, rest zeroed). The mask is `key > position - window` with NO
causal upper bound (block rows attend later block rows — DFlash non-causal token
mode). TOKENS_PER_BLOCK=1 measured best (40 blocks/layer vs 8 at TPB=8).

This also corrects a latent deviation: the old scalar call passed window>0, and
the scalar kernel's window>0 path assumes sliding-CAUSAL (walk_end=position+1),
so it trimmed the later block keys — the draft was effectively causal within the
block despite the non-causal keep mask. llama.cpp's DFlash uses causal_attn=false
(non-causal). The new kernel is the intended non-causal behavior; the draft
oracle (vs llama.cpp) stays green and acceptance is unchanged.

The draft only proposes, so this is a production flash route (online-softmax
reassociation), not bit-exact to the scalar; the exact target verify keeps DFlash
IDs == true AR.

Measured (back-to-back scalar/WMMA A/B on identical Q/K/V, filled window,
rocprof kernel time, thermal-controlled): scalar 1.44 -> WMMA 0.44 ms per
layer-call (3.2x); per 5-layer cycle ~7.2 -> ~2.2 ms. The attention is
window-bound (2048 keys), so this holds at 32K/126K once the window fills. The
residual limit is GQA=4 using 4 of 16 WMMA rows + limited (token x KV-head)
parallelism; a full-tile 4-head x 4-token packing or key-split flash-decoding is
a possible follow-up.
