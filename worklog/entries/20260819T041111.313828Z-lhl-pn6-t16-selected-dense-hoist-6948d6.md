# PN6 extension: hoist t16_selected library for Qwen3.6-27B dense

## Summary

Applying the PN6 GEMV library hoist to the Qwen3.6-27B dense model
(`qwen35` arch, GGUF `Q4_K_M`, gfx1151): the dense decode path does NOT use the
q8_0_t16 / q6_k_t16 / dense-gemv families that were hoisted for the MoE. Its
`launch_gguf_linear` slice is dominated by the **t16_selected** family
(`gguf_q4_k_t16_v1` -> `dense_dual_local32` / `dense_single_local32` / pair
variants, 128 of 129 resolve calls/step; q6_k_t16_qmicro_planar already covered
by the PN6 q6_k_t16 memo; q5_k_t16_v1 is 1 call). Hoisted
`build_gguf_t16_selected_gemv` into a module memo (25 per-call sites). Per-call
host cost dropped 48.7 -> 23.9 us (host CPU 6.31 -> 3.06 ms/step), but the
counter-rotated wall A/B recovered **~0 wall (-88 us/tok, within noise)** — the
dense `launch_gguf_linear` slice is **GPU-bound**, unlike the MoE slice which was
host-bound.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_t16_selected_gemv.py`:
  `_t16_selected_gemv_library()` memo; 25 per-call
  `build_gguf_t16_selected_gemv(...)` sites (17 `lib = library or build_...()` +
  8 `library = library or build_...(load=True)`) -> memo. Mirrors the PN5/PN6
  pattern. Default-params build only; custom-param callers still call build_hip.

## Validation

Model: Qwen3.6-27B-Q4_K_M (arch `qwen35`, dense), BF16 KV, greedy AR decode,
prefill 512 tokens of `9693`. Session
`Qwen35GGUFResidentSession(..., compiler_version=<pinned>,
require_cached_build=True, backend='hip_gfx1151')`.

- handle identity: `_t16_selected_gemv_library() is build_gguf_t16_selected_gemv(load=True)`
  == True (byte-identical launches by construction).
- per-call launch_gguf_linear: 129/step, median 48.7 us -> 23.9 us; host CPU
  6.31 -> 3.06 ms/step.
- counter-rotated wall A/B (real memo vs simulated old per-call build,

  NEW 100.92/100.92/101.07 median 100.92; OLD 100.34/100.83/101.63 median
  100.83; **-88 us/tok** (no wall recovery; GPU-bound slice).
- decode smoke: MoE 35B-A3B tokens sha256 `4a3c660258c0` (matches the PN6
  validation run exactly) and dense 27B tokens stable -> no regression.
- tests: `test_gguf_t16_selected_gemv_decode.py`,
  `test_gguf_q3_k_selected_gemv.py`, `test_gguf_x8_selected_gemv.py`,
