# Bulk TP2 prefill P2 recon: resident prefill layers are full-width monolithic

## Summary

P2 (rank-local batched attention/GDN prefill) cannot be wired by calling the
resident prefill primitives as-is. This entry records the blocker before any P2
code is written, so the next unit starts from the decomposition point rather
than a risky monolithic reuse.

## Changes

No production code changed. The design doc records the P2 decomposition blocker.

## Finding

`Qwen35GGUFResidentSession`'s bulk-prefill layer loop
(`hipengine/runtime/qwen35_gguf_runner.py` ~L20272-L20340) calls two functions
per layer:

- `_run_linear_attention_prefill_layer_rows` (~L8015)
- `_run_full_attention_prefill_layer_aotriton` (~L4553)

Both take `(layer_id, src_hidden_ptr, dst_hidden_ptr, scratch, rows=chunk_rows,
stream, decode_scratch)` and run the **whole layer**: attention/GDN, then the
**full-width** MLP, then the residual — writing the next hidden rows to
`dst`. They are not attention-only primitives.

Therefore, calling them from the TP2 session per rank would run the full-width
MLP on every rank and only then (if at all) a sharded MLP, i.e. exactly the
forbidden "full-TP1 forward + hidden-state copy" substitution, and/or a
double-applied residual. The TP2 batched prefill must instead:

1. factor the attention/GDN prefill subgraph out of the monolithic layer
   function (keeping its `linear_state_rows` / `commit_final_linear_state`
   contract and its `bulk_scratch.for_chunk` chunk-metadata behavior), or add a
   layer variant that runs attention/GDN and then hands the post-attention-norm
   rows to the sharded batched MLP + reduction; and
2. only then wire chunk boundaries, `KVLiveSpans`, final Conv/GDN state, the
   prefill→decode transition, rank sync, and reset.

## Other observations

- Chunk metadata is request/chunk scoped, not layer scoped:
  `self._bulk_prefill_scratch.for_chunk(chunk_start, chunk_rows,
  total_tokens=rows, ...)` is built once per chunk and reused by every layer.
  The batched TP2 prefill must preserve that ownership (do not rebuild per
  layer, which the comment says created hundreds of copy dispatches at pp512).
- `_run_linear_attention_prefill_layer_rows` already exposes
  `linear_state_rows` and `commit_final_linear_state`, which is the hook for
  carrying the final Conv/GDN state across chunks without committing a partial
  chunk's state.
- The `src`/`dst` hidden ping-pong (`src, dst = dst, src`) is the residual-chain
  ownership the sharded MLP output must feed without an extra full-width copy.
