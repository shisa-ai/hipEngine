# Qwen4Exp fast profile routed-expert F16 GEMMs

## Summary

The `fast` profile's routed experts now run on wide-tile F16 WMMA GEMMs that
read the raw GGUF expert tensors. On the canonical 12-case protocol
(Radeon 8060S / gfx1151, `UD-Q4_K_XL`, chunk 4096), measured back to back:
prefill 306.4 / 330.0 / 335.2 tok/s under `production` against
**466.3 / 502.2 / 495.1** under `fast` (+52.2 / +52.2 / +47.7%), 12/12 cases
positive, decode unchanged. Routed-expert kernel time per code-p4096 prefill
falls from 4621 ms to 695 ms; gufo's fused routed kernel measured 812 ms on
the same host and case. This replaces the T16 down route the profile carried
for one commit, and no second weight copy is resident.

## Decisions

- **Port, with attribution.** `RoutedF16GEMMKernel` and its decode helpers
  come from gufo v0.12.0 (`88090afb`, MIT); the owner approved the port. The
  source file header and `docs/KERNELS.md` record the provenance and
  `docs/source_lineage.json` tracks the parent file.
- **Adapted to the grouped pipeline rather than gufo's.** hipEngine already
  gathers rows by expert, so the kernel takes BF16 rows in grouped order with
  no row indirection and writes BF16 back in the same order; the BF16 to F16
  conversion happens while activations are staged in LDS. The existing
  scatter/gather and weighted reduce are unchanged around it.
- **Device tile map, static grid bound.** gufo builds its tile list on the
  host from counts it reads back. Here `RoutedTileMapKernel` expands the
  grouped int64 prefix on the device and publishes the live count; the GEMM
  grid is sized to `min(rows, experts) + (rows - that) // tile_rows` and
  blocks past the count return immediately. No device read, no sync.
- **Tile widths from the mean bucket.** Gate/up 128 rows when the mean
  expert bucket is at least 64 rows, else 64; down 64 / 48 / 16 at mean
  buckets of 32 / 12. These are first settings, not tuned.
- **Every grouped prefill row count routes.** Q4_K gate/up layers route from
  2 rows and the single Q5_K layer from 64, so each fast-plan scope names
  the kernel that dispatches in it.
- **T16 is out of the plan.** The fast plan no longer selects the T16 down
  route or makes tiles resident; `docs/REFACTOR.md` lists the T16 machinery
  for deletion after the production-gate review.

## Measured

Exact commands, per-case rows, quality score and attribution are in
`benchmarks/results/2026-10-13-qwen4exp-fast-routed-f16/README.md`.

- Canonical 12-case: figures above; both profiles repeat-deterministic.
- Quality against the strict teacher, 18-prompt battery: `fast` 13/18
  strict-exact, aligned top-1 1.00, top-20-proxy mean KL 0.055, max 2.19;
  `production` 15/18, 0.0052, 0.62.
- `rocprofv3 --kernel-trace`, code-p4096, per prefill: gate/up 420.9 ms,
  down 273.9 ms, kernel total 8245 ms (0.997 of the 8273.7 ms wall); other
  families unchanged (dense 3056, hyper-connection 1589, attention 1153,
  router and reduce 712, GDN 590).
