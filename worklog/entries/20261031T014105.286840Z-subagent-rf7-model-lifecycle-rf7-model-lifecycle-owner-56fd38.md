# RF7 loaded-model lifecycle owner

## Summary

Moved the single loaded-model handle lifecycle out of ``create_app`` into
``hipengine/server/model_lifecycle.py``. The owner constructs the one engine
from an explicit ``ModelBuildSpec``, attaches the existing MTP circuit breaker,
marks readiness, drains HTTP work, and closes the engine.

The plan's shutdown timing was wrong and is corrected here: the old code reads
``app.state.hipengine_llm`` **after** awaiting ``generation_batcher.shutdown``.
The batcher can create the engine while draining. ``ModelLifecycle.shutdown``
therefore takes a narrow ``engine_getter`` and calls it only after the drain
returns. A RED test covers a batcher that creates or replaces the engine during
drain.

No scheduler, generation batcher, startup stage, route, auth dependency, app
state field, flag, or default changed.

## Changes

- ``hipengine/server/model_lifecycle.py``: new owner with:
  - ``ModelBuildSpec``: the already-normalized ``LLM`` constructor values.
  - ``ModelLifecycle.build_engine``: constructs through an injected factory,
    preserving the ``api.LLM`` monkeypatch seam and omitted ``dms`` kwarg.
  - ``ModelLifecycle.attach_engine``: first-log when newly built, then breaker
    attach, then ``readiness.model_loaded``.
  - ``ModelLifecycle.shutdown``: readiness draining, batcher drain, then
    ``engine_getter()``, then awaited close through the injected close runner.
  - ``ModelLifecycle.mark_stopped``: final status after the caller stores the
    shutdown result.
- ``hipengine/server/api.py``: ``get_llm`` now assigns the built engine, then
  calls ``attach_engine`` with ``newly_built=True``; existing engines take the
  ``newly_built=False`` path. ``shutdown_model`` looks up readiness at entry,
  passes a narrow after-drain engine getter, uses the existing
  ``run_in_threadpool`` as the close runner, stores the result, then marks
  stopped. App state identities are unchanged.
- ``tests/test_unit_server_model_lifecycle.py``: focused RED/GREEN tests for
  factory kwargs and omitted ``dms``, explicit ``dms``, attach/log/readiness
  order, log and breaker failures, after-drain engine replacement, no-engine
  shutdown, batcher failure, close failure, awaited close runner, injected lazy
  reuse, assignment-before-attach failure, API shutdown replacement, and
  dependency boundaries.
