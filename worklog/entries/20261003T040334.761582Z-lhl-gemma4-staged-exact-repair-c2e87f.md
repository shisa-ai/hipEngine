# Implement an exact staged Gemma attention repair candidate

## Summary

Production Gemma attention now uses strict-order staged score/softmax/P*V
kernels with global score workspace and bounded LDS. The full packet's 18 cases
and 1,152 full-logit rows match strict bitwise; frozen KL/category/repeat/isolation
and task noninferiority bars pass. Final repaired source reproduces both saved
failing chains and runs through actual `LLM.generate()` without substituting
variant selection. No staged speed claim is made.

WMMA score-only and separated probability/P*V controls fail frozen numerical
bars (fc32bf908, ab26d94a8); the strict-score/global-statistics/ascending-FP32-P*V
control reproduces both failing teacher chains bitwise (fbc8f0a2e).


## Changes

- A bounded child assignment owns only four new kernel/wrapper/primitive-test
  files for `gemma4_attention_staged`. Parent owns selection tests, integration,
  production/public-route validation, documentation and commit.
- Parent selection RED defines explicit capability-based `gemma4_staged`
  resolution for query widths 1/7/19/3 and keys 31/257/1025/262144; strict plain
  requests stay unchanged and an unsupported dimension names the miss.
- Initial checkpoint kept shipping defaults unchanged. After primitive validation
  and saved-chain replay, production now requests `gemma4_staged` for both
  geometries, including decode. Strict still requests `gemma4_plain`; explicit
  WMMA requests remain available. Capability planning also consults `staged_plan`.
- Workspace is `(tokens*heads*keys + tokens*heads*ceil(keys/1024) + tokens*heads)*4`
  bytes, with per-stream scratch ownership. LDS is bounded at 8,192 bytes.
  This introduces no token/context threshold or artifact admission list.
