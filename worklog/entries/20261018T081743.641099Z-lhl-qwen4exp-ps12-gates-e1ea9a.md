# close isolation and semantic task-quality gates

## Summary

PS12 asked for isolation, determinism, and semantic task quality, and for a
resolution of the 13/18 strict-exact task count that does not treat token
differences as defects. Both halves now have live evidence.

**Isolation and determinism, width 4, 8 checks, 0 failures:**

- eight distinct prompts replayed concurrently reproduce their solo answers
  exactly, text and token ids
- a repeated request reproduces itself
- three different `max_tokens` budgets in one batch each stop at their own
  limit (16 / 32 / 64 completion tokens)
- two interleaved sessions answer from their own history (`4417` and `9028`)
  with no cross-contamination

**Semantic task quality, 18 cases, 18 pass / 0 partial / 0 fail:** the full
mtp-bench category suite (code, general_en, general_ja, mixed_ja_en) plus the
category heldouts, served over HTTP at temperature 0. No chat-template
scaffolding in any answer, no degenerate repetition (the only repeated
40-character run is the three independent `LRUCache(2)` test setups), and the
requested language in every case.

**Strict-exact 13/18 is diagnostic.** It counts generated-ID agreement with the
strict teacher. The binding gates on the same packet are mean/p95/p99/max KL
6.364e-4/3.637e-3/8.069e-3/9.880e-3, top-1 446/450, and bit-identical repeats.
What would be a defect is a wrong, leaked, repetitive, or wrong-language answer;
none appeared.

## Budget finding

At `max_tokens` 512, 13 of 18 answers hit the length cap. Re-running those 13 at
1400 tokens: 8 finish with `eos`, and the other 5 are cut only in trailing prose
or an appendix after delivering every required element (`general_en_explain` cut
inside its closing sentence, `general_ja_plan` inside an appendix script,
`general_ja_explain` inside the last mitigation bullet,
`heldout_general_en_quant` in the final table row). All four code cases and the
long-form plans complete. The truncation is a budget characteristic of a verbose
model on long-form prompts, not an answer defect.

## Review ownership

The delegated reviewer role could not be launched: its configured model
`gpt-6-astra` resolves to two providers, so the harness refuses the launch. The
review was therefore done by the implementing agent, against each case's own
prompt, with the 1400-token re-run used to separate a budget cap from an
incomplete answer. The verdicts are recorded per case in the artifact so a
second reader can check them without re-running anything.
