# Select K2-only MTP terminal policy

## Summary

Superseded the invalid fully graphed mixed-mode policy with a K2-only
Generation-2 policy. Native K2 and bulk K1 cannot be mixed safely in one live
target trajectory: both K1 graph and K1 eager bulk emit invalid sentinel top-1
`2147483647` after native K2. Instead, the exact native K2 owner runs only while
more than two outputs remain; the final one or two outputs use the ordinary
Generation-2 AR owner directly from graph-committed target state.

## Changes

- `capability()` returns no provider for `remaining_decode <= 2`, before any
  speculative mutation.
- Terminal K0 skips provider catch-up because the request cannot re-enter MTP.
- K2 always uses native N2 graph; no K1 or mixed attention mode remains.
- Removed the exploratory K1 eager ABI/test surface.
- Updated quality control accounting to require only K2 graphs plus a bounded
  zero-to-two-token AR tail.

## Validation

- Fully graphed mixed-mode RED: first prompt K1 graph returned target rows
  `[2147483647, 2147483647]` after eight valid native K2 cycles.
- K1 eager bulk RED: same invalid sentinel after native K2, proving the failure
  is a mixed-mode state transition rather than graph capture.
- Late bulk K2 then K1 also fails and is rejected.
- Dirty one-prompt K2-only smoke completes; warm MTP wall `0.298257s` vs AR
  `0.371220s`, exact 24-token output, real EngineService cycles, zero legacy
  fallback, and clean drain. This is feedback only, not retained performance.
- Combined native-cycle/MoE/quality bundle -> 48 passed; compileall, Ruff, and
  `git diff --check` pass.
