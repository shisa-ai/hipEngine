# Align dense public MTP with bulk AR

## Summary

Repaired dense Qwen3.6 public MTP prompt admission so it uses the same target
bulk-prefill policy as public AR while preserving llama.cpp's shifted NextN
prompt state. The original diagnostic now has exact graph-AR/eager-AR/MTP
25-token IDs and SHA-256 with zero tracked allocations after close. Public dense
MTP uses the established `serial_exact` transactional verifier because the
dense native rows=3 verifier emits `INT32_MAX` top-1 sentinels when its prefix
comes from bulk prefill; that limitation is isolated and recorded rather than
exposed to users. Dense NextN pooling now keys by resident target capacity, so
natural prompts reuse one provider instead of accumulating length-specific
providers.

## Changes

- Added an internal device buffer for every bulk-prefill target trunk-hidden row
  and used shifted `(zero, h0, ..., h[n-2])` rows to catch the NextN prompt state
  up after one target bulk prefill.
- Routed dense public MTP through `transactional_serial_exact` verification while
  retaining the native verifier for its separately gated serial-prefill
  protocol.
- Sized pooled dense NextN providers to the resident target capacity rather than
  each request's exact prompt/decode length.
- Added focused prompt-admission, hidden-row D2D, route-selection, and provider
  capacity/reuse tests; documented the native-after-bulk optimization blocker in
  `docs/REFACTOR.md`.
