# R0523 c4 race onset: step 73, created during layer-0 conv/recurrent (concurrent writer)

## Summary

An entry-vs-exit per-slot hash of the layer-0 GDN state pins the corruption ONSET to
decode **step 73** (the same position as the token flip): the conv+recurrent state is
**clean on entry** to layer 0 and **corrupt on exit**, so the corruption is created
*during* layer 0's conv/recurrent execution, not inherited from a prior step. After
onset it persists (the 389 "corrupt-on-entry" steps are downstream of the 5 onset
steps). It is always slot 1. Both the indexed conv kernel and the indexed recurrent
kernel were inspected and are correct (per-(row,channel) / per-(slot,v_head) indexing,
no overlap, per-workgroup shared memory), so the owner is a **concurrent write to slot
1's state**, not an arithmetic/indexing defect. No production behavior changed; hooks
env-gated and uncommitted.
