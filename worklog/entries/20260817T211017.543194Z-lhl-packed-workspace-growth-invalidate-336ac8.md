# Packed workspace growth invalidates binding graphs instead of failing closed

## Summary

The first post-fix canonical C2-6 gate run confirms the page-fault root
cause: all 13 references complete with no GPU memory fault, and the first
serving poll now surfaces the fail-closed resize error instead of a
segfault — proving the old path freed graph-bound memory exactly there.
Failing closed, however, wedged serving into a 500 loop ("engine service
is closed"). Growth now invalidates binding packed decode graphs first
(mirroring invalidate_device_kv_graphs) and only fails closed for graphs
without close(). The union slot cap also uses the session batch capacity
(prefill can pack up to capacity segments), not the hardcoded width 8.

## Changes

- _assert_no_live_packed_decode_graphs -> _invalidate_live_packed_decode_graphs
  (closes open graphs on owner + views before any free; raises only when a
  graph exposes no close()).
- _packed_verify_union_geometry slots/segments cap =
  max(8, max_batch_size).
- Stability test updated: growth closes the binding graph and proceeds;
  close-less graphs still fail closed.
