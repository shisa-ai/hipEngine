# Untrack agent-runner config folders and drop runner mentions from audit docs

## Summary

Lead direction: per-user agent-runner config folders (`.claude/`, `.codex/`,
`.pi/`) are never checked in. The `.claude/agents/` registration stubs from the
relocation unit were the only tracked runner content, so they are now untracked
and the folder class is git-ignored. The `audit/` docs no longer mention
`.claude` at all — the canonical assignments under `audit/agents/` stand on
their own.

## Changes

- `.gitignore`: the "# pi / agent harness state" section is now
  "# Agent-runner config / harness state (per-user, never checked in)" and
  covers `.claude/`, `.codex/`, `.pi/`, `.multiloop/`. `.pi/` and `.multiloop/`
  were already ignored; `.claude/` and `.codex/` are new entries (`.codex/`
  does not exist in the tree; the entry is protective).
- `git rm -r --cached .claude` — the two registration stubs leave the index.
  Local copies remain on disk as ignored per-user state, the same treatment
  `.pi/` already gets, so local Claude Code subagent registration keeps
  working. Nothing under `.claude/` is in the repository anymore.
- `audit/README.md` "Working it with agents": the runner-registration paragraph
  no longer names `.claude/` or any specific runner. It now says only that
  runner-specific registration is per-user setup that is not checked in, and
  that the files under `agents/` are the canonical copies to point a runner at.
- `AGENTS.md` "Never Committed": added the rule naming the folder class, so
  registration stubs and harness state do not land in the repo again.
