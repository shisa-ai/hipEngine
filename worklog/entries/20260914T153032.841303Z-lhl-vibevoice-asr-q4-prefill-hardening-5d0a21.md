# Q4 prefill: strict quant-type dispatch; evaluator reuses the canonical transcript schema

## Summary

Two review findings, both real, both silent-wrong-answer bugs rather than
crashes.

**1. Batched prefill could route a supported quant type through the wrong
decoder.** `q4_prefill` resolved the weight type as
`GGUF_WEIGHT_TYPES.get(int(w_ptr), GGML_Q4_K)` and branched only on
`== GGML_Q6_K`, so everything else — Q5_K, Q8_0, IQ4_XS, or a pointer the
loader never registered — fell through to the **Q4_K** decoder and produced
wrong logits with no error. Q5_K is the sharp case: the decode GEMV path
supports it (`_pick_gemv` handles Q4_K/Q5_K/Q6_K explicitly), so a Q5_K_M
model would decode correctly and prefill incorrectly. The route now resolves
the type once through `prefill_weight_type`, dispatches Q4_K and Q6_K
explicitly, and raises for anything else; an unregistered pointer raises
rather than being guessed at.

**2. The evaluator accepted segments that violate the transcript schema.**
`scripts/vibevoice_asr_wer.py::parse_transcript` re-implemented a weaker
version of the check that already exists in
`hipengine/generation/vibevoice_protocol.py`. It only required a JSON list
whose elements had a `Content` key, so `[{}]`, `[1]`, `["hello"]`, a segment
missing `Start`/`End`/`Speaker`, `End < Start`, a non-finite time, a `bool`
`Speaker`, and a non-`str` `Content` all scored as ordinary text (usually an
empty hypothesis). A non-dict element would additionally have raised
`AttributeError` out of the scoring path. The evaluator now delegates schema
acceptance to the protocol module, so it is exactly as strict as the engine,
and keeps the `(content, status)` API for the harness.

Neither change alters any previously reported number: re-validating the
stored hypotheses in the 20-clip Q4 artifact and the 8-clip comparative smoke
run gives 0 malformed under the strict schema, so the earlier "0 malformed"
claims hold. This is hardening, not a correction.

The strictness is load-bearing for the comparative run: the 200-clip
three-lane job died in the **torch** lane's post-loop scoring because one of
its 200 hypotheses violated the schema (the strict scorer refused to score
it, which is correct). The harness detected the malformed clip for reporting
and then called the raising scorer on it anyway. Malformed generations are
now excluded from WER and reported per lane, with `malformed == 0` as a
separate gate — a lane that emits garbage must not look better by having
those clips dropped.

## Changes

- `kernels/hip_gfx1100/vibevoice/q4.py`: `prefill_weight_type` /
  `gemm_bf16_f32` / `gemm_f32_f32` replace the defaulted dispatch; every call
  site passes a role name for the error message.
- `scripts/vibevoice_asr_wer.py`: `parse_transcript` delegates to
  `hipengine.generation.vibevoice_protocol.parse_transcript`.
- `scripts/vibevoice_asr_wer_full.py`: malformed transcripts are excluded
  from WER and counted (`malformed_transcripts`, `clips_scored_for_wer`,
  `wer_excludes_malformed`), and the run no longer aborts on the first one.
- `tests/test_unit_vibevoice_q4_evidence.py`: schema-valid `VALID_SEG`
  fixture plus a parametrized rejection test for the ten violation shapes.
  Three existing tests had been asserting acceptance of `[{"Content": ...}]`,
  which is itself a schema violation.
- `tests/test_gpu_vibevoice_qwen2_q4_runner.py`:
  `test_batched_prefill_refuses_unsupported_quant_types`.
- `docs/REFACTOR.md`: Q5_K has no WMMA prefill kernel.

## Validation

- `python3 -m pytest tests/test_unit_vibevoice_q4_evidence.py
  tests/test_unit_vibevoice_control.py tests/test_unit_vibevoice_protocol.py`:
  62 passed.
- `python3 -m pytest tests/test_gpu_vibevoice_qwen2_q4_runner.py`: 9 passed.
  The new dispatch test claims a real layer weight is Q5_K and asserts
  `ValueError`, then claims it is unregistered and asserts `ValueError`;
  without the fix both would route to the Q4_K decoder and raise nothing.
- 18-case status matrix over `parse_transcript`, covering every violation
  shape above, all correct.
- Stored hypotheses from the 20-clip Q4 artifact and the 8-clip comparative
  smoke run: 0 malformed under the strict schema.
