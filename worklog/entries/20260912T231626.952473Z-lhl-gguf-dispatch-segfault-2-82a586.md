# A second dispatch segfault: the fake-kernel registry override is bypassed

## Summary

A second, independent interpreter segfault in
`tests/test_gguf_linear_dispatch.py`, this time in
`test_launch_q6_raw_wmma_prefill_uses_resident_raw_abi`. It is a different
kernel from the first one and it is more informative, because this test is a
**pure dispatch test that must never launch a kernel**.

The test registers a fake:

```python
register(key, fake_kernel, replace=True)
launch_gguf_linear(weight, x_ptr=100, out_ptr=200, rows=512, ...)
```

and asserts the fake was called with the resident raw ABI. The crash traceback
shows the **real** kernel running instead, with the test's sentinel pointers:

```
Fatal Python error: Segmentation fault
  File "hipengine/kernels/hip_gfx1100/quant/gguf_k_gemv.py", line 914 in _launch
  File "hipengine/kernels/hip_gfx1100/quant/gguf_k_gemv.py", line 97 in wrapper
  File "hipengine/runtime/gguf_linear.py", line 6753 in _launch_raw
  File "hipengine/runtime/gguf_linear.py", line 3426 in launch_gguf_linear
  File "tests/test_gguf_linear_dispatch.py", line 2938 in test_launch_q6_raw_wmma_prefill_uses_resident_raw_abi
```

`x_ptr=100`, `qweight=10`, `out_ptr=200` are not device addresses, so the
launch faults the process. The dispatch override is what failed, not the kernel.

## Reproducibility and scope

- Reproduces in isolation in a fresh process, both in this tree and at
  `0f7a54ab7~1`, so it is pre-existing and not from this session's work.
- **Not a stale JIT cache.** The `gguf_k_gemv`, `gguf_t16_selected_gemv` and
  `gguf_q6_k_t16_gemv` families (344 cache directories) were moved aside so the
  next run rebuilt from source, and both crashing nodes still segfaulted. The
  cache was restored afterwards; the entry's JIT-cache hypothesis is therefore
  eliminated for these two nodes.

## Why this matters beyond the two nodes

Both failures are in the same file and both end at the real `fn(...)` call, so
the common factor is the **dispatch-override mechanism used by the whole
dispatch test file**, not two unrelated kernels. A test harness whose
`register(..., replace=True)` can be bypassed will silently exercise real
kernels with synthetic pointers. Every dispatch assertion in that file is
therefore suspect until the resolution path is understood, and the two crashing
nodes are only the loudest symptom — the quiet ones would be tests that pass
because the real kernel happened to tolerate the synthetic arguments.

## Changes

None. This entry records the defect and eliminates the cache hypothesis.

## Validation

- Isolated reruns: core dump, twice, before and after the cache move.
- Pre-session worktree `/tmp/ud-pre2` at `0f7a54ab7~1`: core dump.
- Cache directory count back to 2397 after restore.
