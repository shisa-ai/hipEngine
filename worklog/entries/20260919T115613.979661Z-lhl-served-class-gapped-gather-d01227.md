# Served-class gapped gather completion

## Summary

Follow-up to
`20260919T083403.124513Z-lhl-gapped-slot-local-gather-route-397042.md`
(same unit, post-commit findings): the route-forced probe validated the
gather at `LLM.prepare`-sized sessions, but the served bench runs resident
sessions at the model's full context class. Two production-only defects fell
out of the first served A/B, both fixed and re-measured here: the 262K-class
sessions had no head-major buffers (demand-sized per-session gather buffers
fix it), and 256-row loop chunks below the AOTriton threshold need the forced
AOTriton slots the old packed route used to clear. Final served numbers:
**retained 16 at -20.1% wall / 21.58 tok/s (was -11.0% / 19.03), 18/27 hits
with zero gapped-budget declines (was 14/27 with 3), worst single-turn
prefill 15.1 s (was 114 s)**; the default retention is unchanged at -18.4%.
The wide retained working set is now the strongest measured configuration.

## Finding 1: resident sessions at the 262,144-position class have no head-major buffers

`_ensure_bulk_prefill_workspace` sizes its head-major pair at
`prefill_capacity = max_positions`. Served 35B sessions are built at the
model's full context class (262,144 positions; the bench snapshot's
`oracle_capacity_positions` proves it), which exceeds the validated 64K
head-major allocation class in both tokens (65,792) and bytes (512 MB), so the
pair is never allocated and the first retained-16 arm still declined 3 hits
(`gapped_suffix_exceeds_paged_budget`) - the admission guard was correctly
reporting the fast route as unavailable, because it was.

**Fix:** demand-sized gather buffers. `_gguf_gapped_slot_head_major_scratch`
grows one head-major pair per session, bucketed to 4,096-token multiples of
the context the session actually prefills and capped by the same validated
class limits (released with the session's preflight buffers, reset on slot
views). `_gguf_gapped_slot_local_fast_route_available` now checks the
request's own context instead of the resident capacity, so the admission
guard binds only past the validated class. Verified: the 35B probe at the
bench's 262,144-position class gathers (`suffix 8,706 ms` for 2048+6144, was
134,511 ms on the packed route).

## Finding 2: 256-row loop chunks need the forced AOTriton slots

The engine loop slices long prompts into 256-row prefill calls, below the
512-token AOTriton threshold. Contiguous slots cross the threshold via
`aotriton_min_tokens=1` from `force_aotriton_slots`; the gapped-gather branch
inherited the old packed-route behavior of clearing the force, so every gapped
256-row chunk silently fell to the native three-pass kernel even with the
gather engaged. The instrumented retained-16 arm showed it directly: 25
`gather=True` calls, `slot_local=True`, and one 8,234-token prompt reusing
2,048 tokens still cost **104,482 ms** of prefill - the original 114 s
regression lane, reproduced through the new route.

**Fix:** keep `force_aotriton_slots` when the gather route engages (the
per-slot `allow_aotriton` gate on `head_major_kv_admitted` still bounds it).
After the fix the same lane's slowest turn is under 30 s and the arm as a
whole is the best configuration measured.

## Changes

- `hipengine/runtime/qwen35_gguf_runner.py`: session field
  `_gapped_head_major_cache` (+ view reset, + release in
  `_release_int8_prefill_oracle_buffers`),
  `_gguf_gapped_slot_head_major_scratch` (demand-sized bucketed buffers),
  `_gguf_gapped_slot_local_fast_route_available` now context-based, the
  per-slot gapped branch admits the buffers, and the gather route keeps

  the request's context, not the resident capacity.
- `tests/test_unit_gguf_gapped_slot_local_prefill.py`: the fast-route helper
  is context-based (a 262,144-position resident class is fine; a context
  past the 64K class is not).
- `docs/REFACTOR.md`: kill-switch entry updated for both findings.
