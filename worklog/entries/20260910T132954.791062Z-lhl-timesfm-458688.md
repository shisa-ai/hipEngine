# TimesFM 3.0 review fixes — pad rank, freeze semantics, use_sdpa pin

## Summary

Full review of b8be41c89 found three correctness issues; all fixed and
oracle-verified with a new edge-case fixture. No behavior change on
the base fixture path.

## Context

Pre-GPU full review (reviewer report, no files changed by reviewer).
Findings: [P1] _pad_left assumed 3-D inputs so an explicit global
mask (batch, context) crashed with unaligned contexts; [P2]
freeze_after reset counts to the anchor instead of freezing only
mean/std post-hoc while counts accumulate; [P2] the contract omitted
use_sdpa so a use_sdpa=False checkpoint (manual attention path:
uniform attention on fully-masked rows) would validate although the
NumPy reference always implements SDPA semantics (zeros). Reviewer
also noted the base fixture's "univariate" element actually had two
targets plus covariates, and its 512-point context bypassed all
padding paths.

## Changes

- hipengine/kernels/cpu_reference/timesfm3.py: _pad_left now pads the
  last axis via np.pad regardless of rank; freeze_after freezes
  mean/std post-hoc on the stacked outputs (counts accumulate),
  matching util.get_running_stats + the model's post-hoc overwrite;
  patch_cpm_mask is now optional in timesfm3_forward (torch forward
  accepts None; CPM masking and iterative refine are skipped then).
- hipengine/models/timesfm3.py: contract requires
  use_sdpa=True (attention-semantics pin).
- scripts/timesfm3_oracle_torch.py: --case edge generates
  timesfm_3p0_decode_edge.npz — context 500 (ctx pad 12), horizon 100
  (hor pad 28), explicit global mask (rank-2, sub-patch leading mask),
  TRUE univariate (1 target, no covariates), interior fully-masked
  patch, linear series (apply_detrend=True) vs wavy (False); plus a
  direct forward(freeze_after=2) oracle case.
- tests: edge decode parity, forward+freeze parity, use_sdpa drift
  rejection.

## Validation

- Reviewer's P1 repro (target (1,1,33) + mask (1,33)) now decodes
  finite.
- freeze_after unit: frozen means [1,1,1], counts [4,8,12].
- Edge decode parity vs torch: max_abs 1.1e-5; forward+freeze
  parity max_abs 4.1e-5.
- Base fixture parity unchanged at 5.7e-6.
- pytest: 6 contract + 7 CPU-reference tests green; 2.5
  contract/CPU-ref + generation registry re-run green (30 total).

## Decisions

- use_sdpa pinned (not use_memory_efficient_attention alone) because
  it selects the fully-masked-row semantics that the NumPy reference
  implements.
