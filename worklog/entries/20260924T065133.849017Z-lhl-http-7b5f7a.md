# Live HTTP surface: n>1, tools, and JSON through MTP with AR parity

## Summary

Task #17's unit slices pinned the two server-side decisions -- which requests
reach the live-many path, and which explicit requests are refused by name -- but
its acceptance is about what a client receives. This lands the live arm: a real
`hipengine serve` process on the INT8 KV profile, driven over HTTP, comparing each
constrained request against the same request with `speculative_mtp: false`.
**4 passed in 90.8s.**

## Changes

- `tests/test_live_mtp_http_surface.py` (new, four live cases, one real server
  per module). Module fixture launches `python -m hipengine.server` with
  `--backend hip_gfx1151`, INT8 per-token-head KV with fp32 per-token-head
  scales, `--max-context-tokens 4096`, `--max-active-requests 2`,
  `--speculative-mtp-serving auto`, prefix cache off, and waits on `/ready`
  asserting `effective_kv_storage == int8_per_token_head`.
  - `n=2`: token-exact parity per choice, both choices well formed, and the MTP
    arm really ran (`cycles > 0` while AR reports 0).
  - `tools`: parity with a forced tool call, and the `tool_calls` shape a client
    parses (`type`, non-empty `id`, a declared function name, JSON `arguments`)
    whenever a call is produced.
  - `json_object`: parity and content that parses as JSON on both routes.
  - No silent downgrade: for `n=2`, `tools`, and `json_object` with an explicit
    `speculative_mtp: true`, either MTP ran or the response reports the route it
    took instead.

## Validation

- `source /tmp/gfx1151-env.sh && run1151 .venv/bin/python -m pytest
  tests/test_live_mtp_http_surface.py --suite live -v` -- **4 passed in 90.8s** on
  gfx1151. Observed routes: `n=2` and `tools` ran MTP; `json_object` ran AR with
  the reason reported.
