# the block-width divergence is inside layer zero with an identical embedding input

## Summary

`20260928T054512` established that a two-or-wider block diverges from the
corresponding one-row forwards by 0.8 to 2.2 percent relative L2 in the final
hidden state, and named a candidate list. This unit localizes it and removes
most of that list.

`Gemma4Runner.forward(..., capture_layers=[...])` now appends the residual
stream after each layer, which is the only place a per-layer divergence is
visible from outside. On the fixture artifact (two layers) the divergence is
already present **at layer 0**:

| layer | row 0 relative L2 | row 1 relative L2 |
| --- | --- | --- |
| 0 | **0.006260** | **0.035341** |
| 1 | 0.008416 | 0.022052 |

## What that pins

**The input to layer 0 is identical in both paths.** The embedding gather and
the `sqrt(hidden_size)` scale are elementwise and per-row, so no row-count
dependence can enter before the first layer. The divergence is therefore
introduced *inside* layer 0, not compounded into it from an earlier stage.

**Row 0's attention reads exactly one key.** It is the first token of the block,
so its causal mask keeps only its own position. A 0.63 percent difference across
a single-key `softmax(q·k)·v` is not a reduction-order effect, and the same
argument removes the sliding-window read range, which `_sliding_read_range`
derives from `start` alone and which is a no-op for the first row anyway. What
remains inside the layer is the norm (per-row elementwise, so row-count
independent), the attention kernel, and the MLP.

## Ruled out, with the evidence

| candidate | why it is not the cause |
| --- | --- |
| WMMA prefill rewrite | `_gemma4_block_wmma_session(False)` for a partial block, and `HIPENGINE_GGUF_WMMA_PREFILL` is unset, so `_env_wmma_prefill_enabled()` returns False and the session toggle decides. The rewrite is off for both a one-row and a two-row block. |
| GEMV decode rewrite | `HIPENGINE_GGUF_GEMV_DECODE` is unset, so `_env_gemv_decode_enabled()` returns False. |
| MoE gate/up MMQ route | `HIPENGINE_GEMMA4_MOE_GATE_UP_MMQ=0` does not change the outcome. |
| `_sliding_read_range` | Returns `max(0, start - window + 1)`, a function of `start` only, and the docstring already states its bound is the first row's. |
| Compounding from an earlier stage | The divergence exists at layer 0 with an identical input. |

The `launch_gguf_linear` docstring does describe a `rows > 1` rewrite to the
`wmma_prefill_*` family, which is what made that the leading hypothesis. It is
gated on the resolved opt-in, which is off here, so the docstring's condition is
necessary and not sufficient. That is worth knowing: reading the dispatch text
alone would have produced a wrong answer.

## Remaining candidates

1. `_keep_mask(attention, start, rows)` builds `(rows, start + rows - key_begin)`
   columns, so a two-row block's mask carries one more column than a one-row
   block's. Row 0's entry in that extra column must be zero; if it is not, the
   kernel reads a key that has not been written.
2. The attention kernel's own handling of `rows`, given `key_begin` and a mask
   that both change width with the block.
3. The layer wrapper's per-row path for the norm and the MLP.
4. The default (non-rewritten) dispatch inside `launch_gguf_linear` and the
   experts kernels, on the `rows` argument.

The cheapest decisive probe is now a direct one rather than a bisect: call
`launch_gguf_linear` with `rows=1` and `rows=2` on the same input tensor and
compare row 0, then do the same for the experts entry point. That isolates
family from family in one test instead of narrowing through the model.

## Changes

`hipengine/runtime/gemma4.py`: `forward(..., capture_layers=[])` and the
matching `_forward_block` parameter append the post-layer residual as a
`(rows, hidden)` BF16 array. It is a diagnostic in the same spirit as
`apply_softcap` -- it costs a device-to-host copy per layer, so no generation
path passes it. It is the hook `20260928T054512` said was missing.

## Validation

- Per-layer probe on the 8060S (gfx1151) against the fixture artifact: two
  one-row forwards capturing 30 layers each versus one two-row block capturing
  the same, compared row by row with `||a - b|| / ||a||`.
- The fixture has two layers, so the capture is complete rather than sampled.
- The candidate rulings are code reads of the resolution helpers
  (`_resolve_use_wmma_prefill`, `_resolve_use_gemv_decode`,
  `_gemma4_block_wmma_session`, `_env_wmma_prefill_enabled`,
  `_env_gemv_decode_enabled`) plus an `env | grep` showing neither variable is
  set in the measuring environment.
