# the context refusal now happens before the weight load instead of after

## Summary

The previous entry found the limit and left it as a code reading. Chasing the last
unmeasured step found a real defect in the limit's *placement*: the refusal happened
**after** loading the artifact.

`Gemma4GGUFGenerator._ensure_runner` loaded the weights and then constructed the
runner, and the runner is where `gemma4_require_context_capacity` runs. So a user
asking for a 32k context paid for a multi-gigabyte device load before being told the
context is unservable.

The geometry the ceiling depends on comes from **metadata alone** --
`load_gemma4_device_weights` derived it that way before loading any tensor. So the
check can run first, and now does.

## Changes

- `hipengine/runtime/gemma4.py`: extracts `gemma4_text_config_from_reader`, which
  derives the text config from the reader's metadata and loads no tensor, out of
  `load_gemma4_device_weights`, which now calls it. Adds
  `gemma4_require_context_capacity(config, capacity)`, the ceiling check as a named
  function that is deliberately callable without weights. `Gemma4Runner.__post_init__`
  now calls it instead of inlining the loop.
- `hipengine/generation/gemma4_gguf.py`: `_ensure_runner` calls
  `gemma4_require_context_capacity(gemma4_text_config_from_reader(self.reader),
  self.context_length)` **before** `load_gemma4_device_weights`.
- `tests/test_unit_gemma4_contracts.py`: `test_failed_runner_construction_releases_loaded_weights`
  now stubs `gemma4_text_config_from_reader`. Its subject is weight release, not config
  derivation, so the new prerequisite is stubbed with a geometry-free config.
- `tests/test_unit_gemma4_attention_context_ceiling.py`: adds
  `test_the_generator_refuses_before_loading_any_weights`, which stubs the load to
  fail the test if reached, so a regression that moves the check back after the load
  is caught rather than quietly costing the user a load before the refusal.

## Validation

```
uv run pytest tests/test_unit_gemma4_attention_context_ceiling.py \
                tests/test_unit_gemma4_contracts.py \
                tests/test_unit_gemma4_runner_lifecycle.py -q
# 26 passed
uv run pytest tests/ -q -k "gemma4"
# EXIT=0
```

The contracts test **failed on the first run** of this change, with
`AttributeError: 'object' object has no attribute 'info'`, because it drives
`_ensure_runner` with a stub reader and the new call needs a real one. That is the
test doing its job -- the change added a prerequisite the fixture did not know about
-- and the fix was to stub the prerequisite rather than to weaken the check.

The wider gemma4 selection passes with exit code 0. The runner's own
`gemma4_require_context_capacity` call is unchanged in effect, so the reproduction
from `20260928T070042` still holds.

## What this does not establish

- Still **no end-to-end `LLM.generate()`** above the ceiling. The refusal is now
  reproduced at both the runner constructor and the generator's pre-load path, both
  with stubs; the user-visible surface has not been exercised.
- The load is not made *free*, only skipped. `plan_gemma4_gguf_resident_specs` and
  the metadata read still run; what is avoided is the tensor load.
