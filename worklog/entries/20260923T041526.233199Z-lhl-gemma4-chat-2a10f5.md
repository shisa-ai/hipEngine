# Gemma 4 chat rendering silently disabled reasoning by omitting enable_thinking

## Summary

The Gemma 4 adapter rendered chat prompts without passing `enable_thinking`, and
the canonical template reads it as a bare Jinja variable:

```jinja
{%- set enable_thinking = enable_thinking | default(false) -%}
```

So the flag silently became false, and the template's false branch emits an
**empty thought channel** — `<|channel>thought\n<channel|>` — which tells the
model to skip reasoning. The model still answers; it just never thinks. Nothing
raised, and the prompt looked well-formed.

This is confirmed against the real artifact, not inferred: the prompt recorded
in `/tmp/gemma4_real_run.jsonl` ends
`<|turn>model\n<|channel>thought\n<channel|>`, which is exactly the
`enable_thinking=false` rendering and carries no `<|turn>system` or `<|think|>`.

The template also reads `preserve_thinking` the same way, but that one only
gates how prior tool-call turns are replayed, so its upstream default is
correct and is now passed explicitly rather than left to Jinja.

## Changes

- `hipengine/chat/gemma4.py` (new): `render_gemma4_chat`, following the existing
  `hipengine/chat/` contract. Passes `enable_thinking`, `preserve_thinking`,
  `tools`, `add_generation_prompt`, and the special tokens explicitly.
  `enable_thinking` defaults to **True**.
- `hipengine/generation/gemma4_gguf.py`: `_render_chat_template` delegates to the
  new renderer, and `tokenize_chat` takes `enable_thinking=True`.
- `tests/test_unit_gemma4_chat.py` (new): asserts on the rendered reasoning
  markers rather than on the absence of an exception, since the failure mode is a
  well-formed prompt that disables thinking.

## Validation

- Rendering the real template from `google/gemma-4-26B-A4B-it`:
  - `enable_thinking=True` -> `<bos><|turn>system\n<|think|>\n<turn|>\n<|turn>user\n…`
  - `enable_thinking=False` -> reproduces the broken run's prompt exactly
- `pytest tests/test_unit_gemma4_chat.py` — 5 passed (CPU only, no GPU needed).
- `pytest tests/ -k gemma4` — 169 passed, exit 0, zero failures.

## Next

- Re-run the real-artifact probe once the download finishes and confirm the
  prompt now carries `<|think|>` and that the model actually emits a thought
  channel. The earlier run's token distributions were consistent with a model
  answering without reasoning.

## Why the default is True

Reasoning is what Gemma 4 does; the empty channel is the special case. Defaulting
to false would make the non-reasoning path the shipped behaviour and put the
working path behind a flag, which is the inversion this project's product rules
exist to prevent. A caller who wants the fast non-reasoning path passes
`enable_thinking=False` explicitly.
