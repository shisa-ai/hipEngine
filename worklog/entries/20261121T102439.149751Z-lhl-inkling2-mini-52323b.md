# Stage Inkling decoder dense transfers in pinned host memory

## Summary

Use reusable page-locked host input and output buffers for native BF16 decoder projections. Submit both copies and the original kernels in one stream, then synchronize once before returning an independent host result.

## Changes

- Try page locking on the production decoder dense path. If the host or HIP runtime cannot page-lock the scratch, use the same ordinary copies and projection kernels. The vocabulary head, strict profile, vision and drafter retain their existing transfer paths.
