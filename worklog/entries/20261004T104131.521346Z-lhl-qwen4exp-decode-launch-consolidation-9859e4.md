# Next decode action: test whether the 48 per-layer MoE graph launches carry the step's device-side gap

## Summary

**Handoff, not a result.** Three consecutive loop iterations measured and refuted
attribution hypotheses without moving the metric. This entry records the one
lever the measurements now point to, so the next context does not re-derive it.

## The argument

**The decode step's non-kernel remainder is real, device-side, and large at both
depths.** `DE-11`, after the correction in worklog `20261004T100141`, gives a
kernel sum of **~37.5 ms/step at p512 and ~38.5 at p4096** against walls of
**47.656 and ~55.2-57.7**. So the remainder is **~10.1 ms/step at p512 (~21% of
the step) and ~16.7-19.2 at p4096**.

**What it is not, each from a measurement:**
- not host work - two ablations of ~2 ms/step measure `+2.53%` and `-0.45%`, and
  a fixed context-independent host workload costs only `+0.93%` more at p4096
  while the wall grows `+37.5%` (`DE-11`);
- not kernel bodies - the kernel sum grows `+2.0%` while the wall grows `+18.7%`,
  and `X-4`'s per-family figures are sums of kernel durations so gaps are not in
  them;
- not launch *count* - it grows only `+4.7%` (`1,729 -> 1,811` per step) against a
  `+21%` wall growth (`DE-11`).

**The untested candidate is per-launch device-side transition cost.** `DE-6`
records that **decode has 48 kernel-only MoE graphs** with intra-graph gaps of
**1.35-1.43 ms per ~68** launches. If each of the 48 per-layer graph launches
carries a fixed device-side gap, 48 launches at ~0.2 ms reproduces the ~10 ms
remainder at p512 exactly. `DE-11`'s own next-step text already names launch
consolidation; the correction in `20261004T100141` is what makes it testable at
p512, which is the cheaper case to iterate on.

## Validation

**Not yet performed.** The cheap first experiment is a decode-wall comparison
between the current 48-graph-per-step schedule and a consolidated one, measured
with the interleaved design this session established as mandatory: **A/B/A/B in
one session**, because a non-interleaved `code-p4096` comparison on this host
drifts **8%** while an interleaved one repeats to **0.05-0.48%**
(`benchmarks/results/2026-10-04-qwen4exp-chunk-decode-trade/`).

**Read the wall and the kernel sum from the same session.** `DE-11`'s original
error was subtracting a kernel sum captured on 2026-09-29 from a wall captured
on 2026-10-04, across two promotions worth `-8.660 ms/step`.

**Do not trust the profiler for gap figures.** `X-4` measures the median
inter-kernel gap swinging **23x** across repetitions (`53.60 / 58.46 / 2.28` us)
in a profiled harness, so no gap number from that capture is an engine property.

## Next

**Measure the per-graph-launch gap, then consolidate if it is there.** If 48
graph launches do not account for the remainder, the next candidates in order
are the per-layer launch structure inside the graphs, and then `DE-6`'s PM4 /
retained command lists. If consolidation is not available without an arithmetic
change, that becomes a T1/T2 unit needing the production envelope, and the
cheaper screen first is to count how many distinct graph launches a single
decode step issues and what each costs on an empty graph.
