# DE-1 speed measured: the 30-layer scope is a 3.10% decode regression, the warp SAVES time at that scope, and the 996-row gate never covered the failing case

## Summary

The net cost of the 30-layer scope is now **measured**, not projected. Both arms
ran the same harness (`qwen4exp_context_decode_profile.py --profile
--role-markers` under `rocprofv3`, `code-p4096` at live count 4097, 3
snapshot-restored repetitions, kernel rows sliced to the
`qwen4exp_decode_live4097_rep{0,1,2}` ROCTX windows and divided by 3 - the same
protocol used for the original dp4a promotion). Both arms report
`token_exact=True`, `state_exact=True` and closed lifecycle.

| kernel | base (43L, no warp) | cand (30L + warp) | delta |
| --- | --- | --- | --- |
| **decode kernel sum** | **46.061 ms/step** | **47.486 ms/step** | **+1.426 (+3.10%)** |
| `..._dp4a_silu_logical128_t64` (dp4a owner) | 5.415 (43L) | - | - |
| `..._dp4a_silu_warp256_gemv` (warp) | - | **3.336 (30L)** | - |
| `..._dual_silu_logical128_t64` (exact residual) | 1.485 (5L) | **5.041 (18L)** | **+3.556** |

The decomposition closes: **-2.079** (dp4a owner 5.415 at 43L -> warp 3.336 at
30L) **+ 3.556** (13 more layers on the exact route) **= +1.477**, against the
measured **+1.426**; the 0.05 ms residual is other kernels.

**The projection recorded in the previous entry was right in sign and wrong in
magnitude** - it said -0.266 ms/step, the measurement says **+1.426**. The error
is identified precisely: it scaled the warp's gain by layer count
(2.792 x 30/43 = 1.948), but the warp's real advantage over dp4a **at the same
scope** is only **0.442 ms/step** (3.778 proportional - 3.336 measured). The
2.792 figure was a microbenchmark projection (52.093 us vs 107.416 us per kernel
x 47 kernels), and it does not survive as an end-to-end rate.

**The important correction to the decision framing: the warp is not what costs
time - the scope is.** At a fixed 30-layer scope, adding the warp *saves*
**0.493 ms/step** relative to the same scope without it. So the +1.426 is the
price of the scope reduction, and the warp is a partial rebate on it.

**The 996-row canonical citation in the runner docstring never covered the
failing case.** `_qwen4_exp_moe_decode_warp_enabled` is documented as
"Qualified under the production envelope at 996 shared-chain teacher-forced rows
(all bars pass with 2.6-4.4x margin, top-1 99.50%)". The ledger had already
predicted the problem in this row's own action cell: "Also qualify the 996-row
canonical citation in `docs/EXECUTION-PROFILES.md` 6.1, since that fixture does
not contain `heldout_mixed_review`". It does not, and that is exactly where the
warp fails. **A gate that does not contain the failing case cannot clear it**,
and this is the second time in this row that a fixture-coverage gap produced a
green result on a red condition (the first was `t_all48`'s flip-clean
single-case result, which failed max on the full suite).

**What the admission gate actually says, for contrast:** the production default
(43-layer dp4a logical128, no warp) **passes** the canonical production envelope
with 4-8x margin - mean KL **2.44e-4** vs 1e-3, p99 3.67e-3 vs 2e-2, max
**6.14e-3** vs 5e-2, top-1 **0.9911** - with determinism 3/3 and clean isolation.
The 18-case stress suite is the only place it fails, and that suite is already
recorded as one whose bars cannot rank arms because it fails both arms at the
production scope.

**So the decision is not "promote or reject the warp".** It is:

- The scope reduction costs **+1.426 ms/step = 3.10%** of decode kernel time and
  buys passing on a stress fixture, while the admission gate already passes with
  4-8x margin. **Not adopted on this evidence.**
- The warp cannot be admitted at the production scope (max KL 0.261188, 5.2x
  over the bar), and at the reduced scope it is cheaper than the scope's own
  cost but does not pay for it. **Not promoted.**
- One case remains open and is running as bg-132: the **minimal** scope change
  that excludes only the 13-layer flip group, `{1,3,4,7,12} ∪ [18,48)` = **35
  layers**, which is 8 fewer than production rather than 13. If that passes the
  envelope at a proportionally smaller cost, it is the candidate this row's
  action actually asked for, and the warp rides on it for free (-0.493). If it
  fails, the warp is deleted with this entry as the record.
