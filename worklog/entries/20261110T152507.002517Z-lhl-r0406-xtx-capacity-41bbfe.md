# Refresh RX 7900 XTX single-request capacity bound (R0406)

## Summary

Refresh the RX 7900 XTX (GPU1, gfx1100, 24 GiB) single-request server context
bound for Qwen3.8-27B Q4_K_M with int8_per_token_head KV (fp32 per-token-head
scales), MTP off, prefix-cache off, one resident slot. The confirmed bound is
**92160 tokens**, verified with a full-depth workload. Close R0406.

## Changes

- Added compacted capacity artifact
  `benchmarks/results/2026-11-10-xtx-qwen38-27b-q4km-int8kv-capacity.json`
  (performance_claim false): resolved policy, readiness KV estimate, response,
  allocation domains, clean teardown, and the over-bound rejection.
- Removed R0406 from `docs/REFACTOR.md`.

## Validation

- XTX selected explicitly via `HIP_VISIBLE_DEVICES=1` in the hermetic TheRock
  environment; `scripts/gguf_server_allocation_probe.py` (the real server binary).
- Tier-1 bracket: 54272 / 131072 / 196608 / 262144 all returned `pass`, but the
  server silently caps the resident context; the probe only fills 2048 rows, so a
  tier-1 pass above the bound is misleading. The KV pool budget caps at ~6.18 GiB
  (779 pages) regardless of requested context.
- Full-depth at 196608 (prefill 196592) was REJECTED: server logged "the selected
  context (92160 tokens) is the largest that fits in 7.11 GiB free for 1 resident
  slot" and "request requires 196599 KV positions but resident capacity is 92160".
- Full-depth at 92160 (prefill 92144, 8 decode) PASSED, clean teardown, 240.5 s
  request wall. This confirms the bound.
- Per-token marginal decomposition (56,650 B/token): kv_pool 33,280; INT8 prefill
  transient 12,288; prefill workspace 10,473; context scratch 608. The int8 KV
  payload is leaner than llama.cpp q8_0 (~34,816 B/token); the ~23 KB/token of
  context-scaled prefill workspace/transient is what limits the bound, not the KV
  quantization.

## Next

- Follow-up optimization (not part of R0406): the context-scaled prefill
  workspace/transient (~22.7 KB/token) is the lever to fit more context; sizing it
  to the prefill working set instead of the full resident context would raise the
  bound toward the ~197K tokens the raw int8 KV could hold. A direct llama.cpp q8
  capacity comparison on the XTX would give a hard cross-engine number.
