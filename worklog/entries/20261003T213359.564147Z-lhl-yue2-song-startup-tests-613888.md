# Guard the song startup path with tests

## Summary

The song startup branch -- skip the resident KV prepare, the warmup prompt, the
scratch probe, and the chat smoke, then mark readiness from the built pipeline --
had live-run evidence and no regression guard. `tests/test_unit_server_songs.py`
now drives the ASGI lifespan with a fake song engine and asserts it.

## Changes

- `tests/test_unit_server_songs.py` (25 tests → 33):
  - `test_a_song_model_builds_its_pipeline_at_startup` — the pipeline is built
    exactly once and `/ready` reports 200 with the model loaded.
  - `test_startup_skips_the_text_preparation_and_records_the_song_session` — the
    readiness timings carry `song_session_s` and leave `resident_prepare_s`,
    `warmup_s`, `scratch_probe_s`, `chat_smoke_s`, and `mtp_smoke_s` at `None`.
  - `test_startup_publishes_the_surface_it_resolved` — `app.state.hipengine_generation_surfaces`
    is `("song",)` and a chat request on that app is a 501.
  - `test_a_failed_song_session_ends_startup_instead_of_serving_503s` — a missing
    tokenizer asset raises `StartupFailure` and records the failed stage.
  - `test_a_text_model_does_not_take_the_song_branch` — the same fake that fails
    a text startup (no generation path) reaches the text stages, so the song
    branch is a branch and not the only path through startup.
  - `test_a_song_model_reaches_readiness_without_a_generation_warmup` — that fake
    is a complete song startup, which is what makes the comparison meaningful.
  - `test_the_cli_accepts_the_companion_decoder` — `--vae-model`, the
    `HIPENGINE_YUE2_VAE_DIR` fallback, and the empty-value rejection.
- The fake engine now models the real lifecycle: `session()` builds once and
  `loaded` follows it, rather than being true at construction.

The lifespan needs a client that runs startup and shutdown, which
`httpx.ASGITransport` does not; these tests use `fastapi.testclient.TestClient`
for the startup cases and keep `ASGITransport` for the request cases.

## Validation

The song startup tests pass against the committed startup branch (`ecacea75b`);
no production code changed in this unit.

  scratch_probe_s: null, chat_smoke_s: null, mtp_smoke_s: null,
