# rich help dropped the /bench arguments as markup

## Summary

`/help` in the rich client rendered the `/bench` row as `/bench`, with no
arguments. `_RichChat.help_table` passed `_COMMANDS` strings straight to
`Table.add_row`, and rich reads `[...]` as a style tag, so `[in]` and `[out]`
were parsed as markup and removed from the output. The plain client printed the
same row correctly, which is why the arguments looked documented in one client
and absent in the other.

This corrects the discoverability claim in
`worklog/entries/20260921T080951.973724Z-lhl-startup-warmup-mtp-route-9c2fd3.md`:
the `/bench` help row already carried the arguments before that change; they were
being dropped at render time. `/bench [in] [out]` itself has accepted both
arguments since it was added.

## Changes

- `hipengine/chat_cli.py`: `help_table` adds each row as `Text(name)` /
  `Text(text)`, which rich does not re-parse as markup.
- `tests/test_unit_chat_cli.py`: `test_rich_help_keeps_command_arguments_that_look_like_markup`
  renders the help table and asserts `/bench [in] [out]` survives, along with the
  stated defaults and `/think <mode>`.

## Validation

- Rendered the rich help table at width 100 and read it back: the `/bench` row now
  reads `/bench [in] [out]   measure prefill, decode, and cache reuse; default 512
  in, 32 out`.
- `tests/test_unit_chat_cli.py`: 31 passed.

## Next

- No other rich-rendered string in the client interpolates bracketed text:
  `_RichChat.note` already wraps its text in `Text(...)`, and the `[{model}]`
  prefix is plain-mode output only.
