# Add the resident block arena and its attention plan split

## Summary

The block traversal now has a working arena, a reusable attention plan and a resident controller blend. It reproduces the host traversal exactly for the 18 prelude visits and diverges at the first looped core pass, so it stays unreachable from `_traverse` until the message read is right.

## Changes

- `_attention_plan` builds one visit's attention half and returns it; `_resident_attention` projects the plan it returns, unchanged in behaviour.
- `project_attention_resident` accepts a caller-owned arena: device `sources` plus a `device` cursor, with the branch output left resident.
- `blend_controllers_resident` blends and normalizes resident controller rows inside a caller arena.
- `_resident_block` runs the whole block inside one arena: reads, normalizations, residual adds, the attention half and the expert chain, with only router logits and the final rows crossing the host.
- `Inkling2DeviceDense` takes a reentrant lock, because one resident block holds the arena across calls that take it again.

## Validation

- `tests/test_unit_inkling2_gguf_runtime.py` and `tests/test_unit_inkling2_gguf.py` pass.
- The 64-token resident-attention verification is unchanged by the plan split: `worst_kl_strict` 1.2594e-4, `worst_kl_control` 2.057e-6, 4 of 4 top-1 agreement, identical to the pre-split run.
- A 64-row block against the host traversal: hidden states agree to 3.8e-6 after one visit, 2.5e-5 after 17, and 5.7e-6 after 7. Per-visit branch rows, normalized rows, router logits and expert rows at the last prelude visit all agree to about 1e-5.
- At the first looped core pass the traversal diverges: the message rows disagree with the host by about 37 against a host maximum of 26, and the block hidden state by 285.

## What is still wrong

- The restart at the first looped core pass reads the wrong window. The plan's first core start is itself `restart_from_prelude`, so the host restores the prelude hidden state and keeps `prelude_blocks` as the stack from the earlier pass through the same layer; the arena restores the right hidden rows and the right stack length but the message read's window still disagrees.
- The remaining suspects, in order: the partial row written at `start + blocks` versus the read window `[start, start + blocks]`, and whether the entry written at the restart's own boundary visit is the one the host appends.
- The traversal is not reachable from `_traverse`. `resident_block` is built but unset on the model, so the host traversal remains the only block path. The clearing command is the step harness: compare the device hidden state against the host capture trace after k visits for k in 1..48 and require agreement at every k.

## Next

- Fix the message read window at the first core restart, then re-run the step comparison to k=48 and confirm every visit agrees before wiring the traversal into `_traverse`.
