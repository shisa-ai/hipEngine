# Screen HIP graph replay for packed Inkling experts

## Summary

A six-node HIP graph replayed the packed `fast` expert chain exactly across changing route data, but it was slower than issuing the same kernels eagerly on both GPUs. Do not add graph ownership for this small chain alone. This does not test a longer graph that replaces host-dependent exchanges.

## Changes

- Scratch only. Captured gate/up Q8 packing and NVFP4 projection, split activation, down Q8 packing and NVFP4 projection, and exact ordered mix. Eager and replay used the same kernels, buffers, explicit stream, and arithmetic. The test changed input, expert IDs, outer scales, and route coefficients in-place between correctness calls.

## Validation

- At `a9b17e66a`, built `/tmp/hipengine_inkling_expert_graph_trial.hip` with `hipcc -O3 -shared -fPIC --offload-arch="$arch" -I hipengine/kernels/hip_gfx1100/quant` and ran `OPENBLAS_NUM_THREADS=1 PYTHONPATH=. python -u /tmp/hipengine_inkling_expert_graph_trial.py "$arch" "$library"`. The native graph contained six nodes. Both paths matched the shipping eager result bit-for-bit on all five seeded, changing inputs on W7900 (`epyc`) and Strix Halo (`strixhalo`).
- Synthetic eight-route, 2,304-wide packed leaves, ten alternating samples per arm, 100 chain calls per sample. Median elapsed microseconds per chain with a wait after each call were 116.48 eager versus 123.75 replay on W7900, and 231.67 versus 237.38 on Strix Halo. Waiting once per group also favored eager on both. Timings exclude transfers and graph construction. This is a kernel-chain diagnostic, not a model or serving benchmark. Logs: `/tmp/kendex-pi-bg/bg-140-1795401635924.log` and `/tmp/kendex-pi-bg/bg-142-1795401654796.log`.
