# Repair and freeze the C-width baseline harness

## Summary

Reviewer packet item 4 (roadmap P5). `scripts/gguf_server_cwidth_probe.py` was
the C>1 reference the IKV-C2 work is justified against, and it was broken in
four ways the review found by reading rather than running:

1. it printed a removed variable (``aggregate``), so a successful first-width
   run raised ``NameError`` before writing any artifact - the failure landed
   after all the GPU work;
2. it applied lane 0's ``completion_tokens`` to every lane;
3. it derived decode rates from ``--max-tokens`` (requested, not measured) and
   from a single-lane prefill wall subtracted out of a wall that contained
   width prefills;
4. its "serial reference" was N x the concurrent C1 rate, which one GPU cannot
   multiply - not a measured serial control.

The harness now reports only measured quantities: per-lane ``usage`` counts,
complete-request throughput over each phase's wall, measured decode/prefill
model-step deltas from the server's Prometheus counters, route and fallback
counter deltas (so a width that never grouped cannot be reported as batched),
the last execution manifest's ``logical_c``/``mode`` labels, and a real
same-server serial control with a concurrent-over-serial ratio. There is
deliberately no decode-only tok/s field; the withdrawn estimate is not replaced
by another inference.

## Changes

- `scripts/gguf_server_cwidth_probe.py`
  - New pure functions: `parse_prometheus`, `labeled_counter`, `_usage_counts`,
    `build_phase_record`, `manifest_from_metrics`, `serial_reference`. All
    device/server I/O stays in `main()`, so the accounting rules are testable.
  - Concurrent and serial phases share `build_phase_record`; each records
    per-lane walls and token counts, totals, complete-request throughput,
    measured step counters, counter deltas, and the manifest.
  - `--no-serial-control` opts out; the serial phase runs by default.
  - The artifact records the withdrawal of the old
    `aggregate_decode_tok_s_est` / 31%-13% claims.
- `benchmarks/HARNESSES.md`: the harness row now describes the measured
  protocol and states that no decode-only rate is reported.
- `tests/test_gguf_server_cwidth_probe.py` (new): 12 CPU tests.

## Validation

- `python -m pytest tests/test_gguf_server_cwidth_probe.py -q` - 12 passed.
  Covers: Prometheus parsing keeps finite samples and drops NaN/Inf; labeled
  counter extraction; missing ``usage`` is distinguishable from zero; a
  heterogeneous-completion phase uses each lane's own count (60/63/62, not
  3 x 60); measured step and fallback/route deltas; failed requests and missing
  usage carry no throughput claim; a server without the counters still produces
  a valid record; the serial ratio is a ratio of two measured rates and is
  absent when the control fails; the assembled artifact JSON-dumps; and a
  regression guard against the removed-variable expression.
- `python3 scripts/gguf_server_cwidth_probe.py --help` - parses and exits 0.
