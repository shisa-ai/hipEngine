# TimesFM 2.5 + 3.0 verification on the Framework gfx1151 lane

## Summary

Post-pull verification of the newly merged TimesFM work (2.5 200M and 3.0
500M) on the **Framework Desktop gfx1151 lane** (physical host `gfx1151`,
machine ID `55ea6c509d0b49eea8de7094a1023668`, Ryzen AI Max+ 395 / Radeon
8060S). No code change was required: both models load, both correctness gates
pass, all TimesFM GPU/CPU tests pass, and both decode paths run at their
expected performance. Recorded as a **new independent lane**, not as an
improvement over the retained rows.

## Changes

- `docs/MODEL-TIMESFM.md`, `docs/MODEL-TIMESFM3.md`: add `PYTHONPATH=.` to the
  documented reproduce commands. `hipengine` is not installed into the ROCm
  `therock` environment, so the documented `python3 scripts/...` invocations
  fail with `ModuleNotFoundError: No module named 'hipengine'`; every other
  repo doc that runs scripts against the therock env uses `PYTHONPATH=.`
  (for example `docs/ENVS.md`, `docs/BENCHMARK.md`, `docs/DFLASH.md`).

No model, kernel, loader, or runtime code was modified.

## Validation

Host and environment:

- `hostname` = `gfx1151`; DMI product = `Desktop (AMD Ryzen AI Max 300 Series)`,
  vendor `Framework`, board `FRANMFCP06`; 125 GB LPDDR5X shared.
- `mamba run -n therock rocminfo` reports `AMD RYZEN AI MAX+ 395 w/ Radeon 8060S`
  and `gfx1151`; HIP load check `ctypes.CDLL('libamdhip64.so')` passes.
- ROCm stack: HIP 7.15.26333, AMD clang 23.0.0git. Env prefix resolves to
  `envs/therock10-staging-20260828` (`envs/therock` is a symlink to it).
- Checkpoints were absent from the HF cache and were downloaded with
  `snapshot_download`: `google/timesfm-3.0-pytorch` (1.3 GB) and
  `google/timesfm-2.5-200m-pytorch` (883 MB).

Correctness gates (all pass, `PYTHONPATH=. HIPENGINE_HIP_ARCH=gfx1151`):

| Command | Result |
| --- | --- |
| `python3 scripts/timesfm3_gpu_bench.py --check` | `guard ok: fp32 strict parity + fp16 production gate pass on 3 fixtures` |
| `python3 scripts/timesfm_gpu_bench.py --check` | `guard ok: fp32 strict parity + fp16 production gate both pass` |
| `pytest tests/test_timesfm3_gpu_decode.py tests/test_timesfm_gpu_decode.py -v` | 16 passed (fp32 strict parity, fp16 production gate, determinism, precision rejection; parametrized over the base/edge/covmask fixtures) |

Registry check: `registered_models()` exposes `timesfm_2p5_200m`
(`TimesFmModelForPrediction`) and `timesfm_3p0` (`TimesFM3Torch`).

Timing, `--metric` (best of 5 within each process), three independent process
invocations, GPU otherwise idle:

| Model | Framework lane (this entry) | Retained `zbook` lane |
| --- | --- | --- |
| TimesFM 3.0 (b8/3 var/ctx8192/h512) | 0.2195 / 0.2197 / 0.2199 s | 0.3213 s median (artifact 2026-09-10, varnorm-fusion) |
| TimesFM 2.5 (b8/ctx8192/h512) | 0.0618 / 0.0620 / 0.0621 s | 0.0823 s median (artifact 2026-09-09, quadtile-flash) |

**Lane discipline:** these are two different physical machines with the same
backend/GPU architecture. The Framework Desktop runs the same workload roughly
32% (3.0) and 25% (2.5) faster than the power- and heat-limited zbook lane.
That is a cross-lane absolute-rate difference, not a code improvement, and it
is **not** retainable as an old→new delta. Both columns are single-lane
numbers; no same-host A/B was performed because no code changed.
