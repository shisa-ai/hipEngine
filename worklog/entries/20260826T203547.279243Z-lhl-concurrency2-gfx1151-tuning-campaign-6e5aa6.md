# gfx1151 Q4_K_M AR c1-c8 baseline and MTP crossover attribution

## Summary

Executed T0.1 and T0.3 of `docs/CONCURRENCY2-GFX1151-MTP-TUNING.md` on the
gfx1151 host (Radeon 8060S) at head `3d56a437e`.

T0.1 — matched-quant true-AR c1-c8 blocking sweep (Q4_K_M, BF16 KV, MTP off at
the server, same harness/knobs as the 2026-08-26 MTP diagnostic): AR scales
10.323 / 17.714 / 23.296 / 27.240 / 29.293 / 31.799 / 26.398 / 28.431 tok/s
for c1-c8. Against the committed MTP diagnostic (13.596 / 12.935 / 12.956 /
12.948 / 13.091 / 12.957 / 12.665 / 12.552), MTP wins only c1 (+31.7%) and
loses c2-c8 by 27.0-59.3%. The crossover sits between c1 and c2, confirming
the earlier quant-mismatched indication.

T0.3 — root causes from the MTP raw per-request backend timings: (1) G1 is
prefill, not decode — 512-token packed prefill costs ~4.5 s (~113 tok/s) at
every width, ~48% of the c1 request wall, while the c1 decode phase alone runs
26.7 tok/s (already faster than the 21.16 tok/s direct leaf); (2) G2 is
phase-serial execution — c8 batch wall 81.6 s ≈ 8 x ~10.1 s of per-request
work, verify is ~98% of decode at ~120 ms per 4-position block per slot
(`use_wmma_prefill=False`, chunks of <=4 slots) vs ~33 ms per 8-position
batched AR step; (3) acceptance is stable at width (0.7395 c1, 0.639-0.669
c2-c8; 2.9-3.2 tokens/step), so the serving-route flat line is not an
acceptance collapse — the SPECDEC2-physical 18.43% C2/C4 collapse is a
different surface and remains open as T2.1.

Correctness observation (diagnostic): batched AR flips greedy near-ties on the
repeated-token prompt at c>=4 (up to 12/24 rows at c8; same pattern as the
prior Q4_K_S diagnostic), while target-verified MTP had 0 mismatches at all
widths. The AR run therefore reports status=failed_gate; throughput rows are
intact and this artifact is diagnostic-only, not a retained benchmark row.
