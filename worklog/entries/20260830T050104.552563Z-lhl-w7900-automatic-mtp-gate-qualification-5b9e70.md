# W7900: automatic MTP is blocked by evidence coverage, not by three performance gates

## Summary

Task #11 asked whether the three gates that decline `--mtp-request-mode automatic` at every width on
gfx1100 are doing the right thing. They are right in effect, for reasons that have nothing to do with
performance. There are not three performance gates: there is one missing thing, gfx1100 evidence
coverage, plus an artifact-identity mismatch. `_QWEN38_Q4KM_MTP_SERVING_EVIDENCE`
(`hipengine/models/qwen35.py:192`) has 6 rows for this model: **5 are `hip_gfx1151`** and exactly **1
is `hip_gfx1100`**, and that one qualifies `resident_capacity=2`, `realized_group_rows=2`, candidate
budget **K2** - not the K3 the scoreboard measures.

## Changes

Artifact `2026-08-30-w7900-q4km-automatic-mtp-gate-qualification.json`. No engine change; the table is
a qualification record and editing it is a promotion campaign, not a fix.

## Validation

Per gate, from the code and the committed packets:

| gate | widths | real cause |
| --- | --- | --- |
| `artifact_not_qualified` | C1 | Every row records artifact size 17,106,775,008 bytes; the file at `/models/gguf/Qwen3.8-27B-Q4_K_M.gguf` is **17,106,773,984**, 1,024 bytes smaller. Predicate compares sha256 **and** size (`speculative/serving.py:510`), so no row can match - including the gfx1100 one. The qualified artifact is a different build of the same-named GGUF. (Size by stat; the 16 GB file was not re-hashed.) |
| `resident_capacity_not_qualified` | C2 | The auto packet ran its server at `resident_capacity: 8`; the only gfx1100 row requires 2. Deployment-shape mismatch. |
| `physical_group_not_qualified` | C3-C8 | Requires the row's `realized_group_rows` (2) to equal observed group rows (`api.py:2146`), which are 3-8. Fails by construction above width 2. |

The gates are not over-rejecting physical reality: differencing the cumulative
`physical_width_decode_steps` per cell in the shipped-default packet gives **91-94% of decode steps at
the full logical width** and 6-9% below it at every width C2-C8. Waves do form at their width; the
table just has no rows for them.

Effect check against the current scoreboard: K3 wins at C3 (1.20x) and C4 (1.12x) - exactly the widths
with no gfx1100 rows - and loses at C5-C8 (0.80x/0.68x/0.73x/0.59x), where automatic MTP is also
declined but for the wrong reason. So today the gates enable nothing they should not, and also block
the two widths where enabling would be correct. Both accidents of coverage.
