# Reduce the bulk prefill's MLP partials on the device: +12% prefill

## Summary

The phase attribution showed the sharded MLP's exchange plus its cast costing
1.94 ms/layer, which consumed 67% of the 2.90 ms/layer that halving the MLP
saves. The cost was the staged transport's host round trip: D2H of both ranks'
partials, a host f32 sum **on the critical path** (the device sits idle while it
runs), and then an f32 payload left in pinned host memory that the consumer
reads zero-copy over PCIe before a separate cast kernel narrows it to bf16.

The decode route already had the fix in the other direction:
`CompiledDeviceExchange` sums the two partials in a peer-spin kernel and writes
a **device** bf16 buffer, so no f32 payload crosses PCIe and no cast is needed.
It was decode-only by construction - it rejected `rows != 1` with "batched
prefill uses the staged transports instead".

## Result

| 512-token prompt, 128 decode, c=1, same bench and protocol | Prefill tok/s | Decode tok/s |
| --- | ---: | ---: |
| staged (host-summed) reduction | 922.1 | 38.79 |
| **device reduction** | **1032.9** | 39.27 |

Runs: `[1032.9, ...]` median over 4, p50 499.9 ms. **+12.0% prefill**, decode
unchanged. The phase attribution predicted ~13% from removing the host sum
(~0.7 ms/layer), the f32 PCIe read-back and the cast, minus the spin-add kernel
that replaces them, so the measurement agrees with the model rather than merely
improving.

## Correctness: bit-identical, so the existing gate evidence transfers

The same model, prompt and shape run under both reduce modes:

| prompt | logits_sha256 (host) | logits_sha256 (device) |
| --- | --- | --- |
| `mixed_ja_en_translate` | `b4c14c35c66e7a84…` | `b4c14c35c66e7a84…` |
| `heldout_mixed_summary` | `af4b3ce0095a82ea…` | `af4b3ce0095a82ea…` |

Identical digests, and every gate metric identical to full float precision
(`mean_kl 0.002557612045921964`, `max_kl 0.16705312926134894`, …). The two
routes are not merely close - they are the same bits. That is the expected
outcome: the spin-add kernel computes `narrow_bf16(widen(a) + widen(b))`, which
is exactly the host f32 sum followed by the boundary cast, and a GPU test pins
that parity directly.

The staged transport remains the registered fallback under `reduce_mode="host"`,
and it is byte-for-byte the old path (the new branch is only taken when a device
exchange exists).

## What this does not fix

The bulk prefill route's **pre-existing** KL gap against the TP1 reference is
untouched. Both reduce modes fail that gate with identical metrics
(`mean_kl 0.00256 > 0.001`, `p99_kl 0.091 > 0.02`, `max_kl 0.167 > 0.05` on the
first prompt; 2 flipped rows on the heldout), so the change neither causes nor
hides it. A prior entry localizes the divergence to the **Q6_K `attn_qkv`
projection** in the replicated attention phase (rel 3.73e-03, max_abs 0.25, not
bit-equal), which is a different subsystem from the exchange.

That matters for how this win should be read: it makes a route that is not yet
gate-green 12% faster. The "correct" half of this route is still open, and its
localization is now the more valuable next unit than any further micro-tuning.

## Changes

- `hipengine/distributed/device_exchange_host.cpp` - two entry points splitting
  `step_begin`'s timeout reset from its counter bump, plus the `rows`-aware
  staging the batched path needs.
- `hipengine/distributed/device_exchange_compiled.py` - `rows` support (the
  driver stages a slot as one long row, so a batched caller passes `rows` and the
  element count scales), plus `reset_timeouts` and `bump`.
- `hipengine/distributed/shard_group.py` - `reduce_mode="device"` builds a
  `CompiledDeviceExchange`; `forward` takes the device branch when one exists and
  writes the boundary buffer the residual add already consumes, skipping the
  cast; `begin_device_group`/`finish_device_group` bracket a prefill.
- `hipengine/distributed/tp2_generate.py` - the bulk group inherits the session's
  `reduce_mode`, and the layer loop brackets it with one reset and one wait.
- Tests: batched bit-parity and timeout persistence on the GPU tier; the group's
  bump/slot-alternation, row-count guard and bracket semantics on the unit tier.
