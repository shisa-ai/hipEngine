# Compare public DMS W256 and W8192 sidecars

## Summary

All three public-library arms completed 36 requests each with exact same-arm
repeatability. Both sidecars passed all four-category dense-BF16-teacher
numerical diagnostics at 2048 and 12288 tokens. Neither improves public-call
latency on this workload; compact storage is not a demonstrated speedup.

## Validation

- Physical host `gfx1151`, Radeon 8060S, Qwen3.8-27B Q4_K_M,
  production profile, INT8 per-token/head KV with FP32 scales, concurrency 1,
  prefix cache/MTP off; 32 greedy output tokens with EOS ignored.
- Four category prompts, repeated neutral background, 128/2048/12288 inputs;
  one warmup and two measured repeats per prompt/shape. All arms' exact token
  manifests have identical SHA-256. All 108 requests completed; repeated IDs
  match within each arm. Each sidecar matches dense IDs on 20/24 measured
  requests. Inspected long-input outputs are relevant but truncated at the
  fixed 32-token limit; this is not full task-quality certification.
- At 12288 input tokens, mean public wall seconds dense/W256/W8192 are
  35.751/58.005/58.146. Mean backend prefill milliseconds are
  32740.811/42188.374/42038.257. Mean post-prefill inclusive rates are
  10.810/10.847/10.642 tok/s (31 tokens divided by request-minus-prefill).
  Do not present those rates as public end-to-end throughput or kernel timing.
- Configured historical compression is 2x for both sidecars. Achieved total
  logical/live-row ratios at 12288+31 cached tokens are 1.954x and 1.199x;
  W8192 protects more recent history. DMS device resident bytes are
  229382096 and 363103184. No decode-time evictions were observed in the
  public run: prefill selection supplied the measured compression.
- Long-request tracked allocator peaks are 27177188592 bytes dense versus
  21582188876 bytes for either DMS arm. These include model/workspaces, not
  just KV, and exclude untracked HIP/library allocations. All arms close with
  zero tracked allocations. Do not infer whole-device savings from these.
- Each quality suite has four categories times eight teacher-forced steps per
  mode (`no_evict`, `sidecar`). Every category passes max KL <=0.05 and top-1
  >=0.9; top-1 is 1.0 throughout. Sidecar mean/max KL at 12288:
  W256 4.55545e-5/5.22776e-4, W8192 2.65685e-5/2.46466e-4.
  This small diagnostic is not a production promotion or realistic retrieval gate.
- Exact invocation: `bash /tmp/hipengine-dms-env.sh bash /tmp/run-dms-comparison.sh`.
  Both scripts' full contents are embedded in the artifact as
  `environment_recipe` and `runner_recipe`; each arm also records its command.
  Source revision `fb97e65aca24c4744fed9cfd5704ad1480fa68d2`, clean tree.
  Harness focused CPU validation was 39 passed in the protocol entry.
- Result publication validation: all four documentation gates passed;
  staged worklog validation passed (10801 entries); diff whitespace check passed.
