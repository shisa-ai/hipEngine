# C8 iter30: P4 head traffic measured — traversal-bound, argmax fusion not material

## Summary

Completed the C8-P4 head-shaped-work bullet ("measure weight traffic, output
traffic, and top-1 ownership") from the current C8 profile artifact plus the
quant-layout constants and the runner's head routing. Both head families sit
in the 167-203 GB/s latency-hiding band, output traffic is immaterial, and
argmax fusion fails the bullet's own materiality criterion — so the pool's
lever is reduced weight traversal, not output/top-1 work.

## Findings

- Shapes: vocab_size 248,320, hidden 5120 (from the L3 gate packet metadata);
  the proposal selection head is the separate immutable 131,072-row artifact
  (P5). Q6 qmicro planar T16 block = 3,360 B per 16×256 tile.
- Root full-vocabulary head: 15,520 tiles × 20 blocks × 3,360 B =
  **1,042.9 MB weight/call**. The direct F32 kernel (rows=1; the wrapper
  routes rows<2 there) runs 1 call/cycle at 6.242 ms = **167.1 GB/s**;
  logits output 993 KB (0.095% of traffic).
- Proposal selection head: 8,192 tiles × 20 × 3,360 = **550.5 MB/call**. The
  F32 rowtile col8 kernel runs 3.667 calls/cycle at 9.924 ms total =
  **203.4 GB/s**; logits output ≤7.95 MB/call (0.76%).
- Top-1 ownership: the fused dp4a top-1 path
  (`gguf_q6_k_x8_gemv_decode_q8_1_dp4a_top1_gather_f32`) is registered but
  **env-gated off** (`_GGUF_VERIFY_LM_HEAD_Q6_TOP1_DP4A_ENV` default False,
  rows==1 only). The active route writes full F32 logits and consumes them
  with separate `argmax_f32_rows_i32` (≤8 MB read — below top-10).
- Admissibility verdict: fusing exact argmax removes ≤0.76% of call traffic
  plus one small launch — **not material** by the bullet's own criterion.
  The pool is weight-traversal-bound (167-203 GB/s, the same latency-hiding
  class as the Q4 fused owner's 190 GB/s).
- Identified exact lever: rows-pooling the root row into a rowtile head call.
  The rows=1 direct kernel decodes each weight byte for one row (half the
  per-byte work of the rows=8 rowtile), hence 167 vs 203 GB/s; pooling is
  worth ~1.1 ms/cycle but requires the root hidden to be available at the
  verify batch point — a cycle-structure dependency that must be recorded
  before any screen.
