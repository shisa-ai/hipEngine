# Dimension partition fixes the reproduced KL failure but loses speed

## Summary

An implemented dimension-partition candidate exactly matched the frozen strict
capture across all 1023 teacher-forced rows: maximum KL zero, top-1 100%, with
30,690 observed split launches. It removed key-sum reassociation by giving each
block disjoint output dimensions, each retaining its ascending-key accumulation.
This disproves the claim that a multi-block attention implementation necessarily
fails this numerical comparison. It does not establish complete production
qualification or generalization beyond the tests run.

The candidate was reverted because its measured decode speed regressed. The
user requested full implementation; this experiment is a rejected implementation
attempt, not completion of that request. No numerical threshold changed.

## Changes

Implemented a 32-thread dimension-partition value kernel with shared weights,
using the existing four-deep load pipeline and eliminating the combine launch.
Six new exact-comparison GPU tests covered F32/BF16, odd key counts and excess
slice requests. Four failed before implementation; all six passed afterward.
The full focused attention module passed 83 tests; the Gemma guard passed 446.

A sixteen-deep pipeline retained the six exact-test passes but was slower still.
Both candidates and the candidate-specific tests were reverted; no runtime diff
remains. The complete four-deep patch and reports are preserved in
`benchmarks/results/2026-09-26-gemma4-dimension-partition-rejected.json`.

## Validation

Host `epyc`, physical GPU1 RX 7900 XTX, gfx1100, Gemma 4 26B-A4B-it
UD-Q4_K_XL, BF16 KV, context 8192, greedy. Median of three benchmark samples
at 1024 prompt / 128 output:

| Implementation | Decode tok/s |
| --- | ---: |
| Incumbent, iteration 50 | 45.68345 |
| Dimension partition, pipeline 4 | 37.67212 |
| Dimension partition, pipeline 16 | 33.66907 |

The candidate's public `LLM.generate()` parity check passes. No speed win is
claimed and no secondary workload matrix was spent on this clear regression.
Profiler/promotion checks were not completed for this rejected candidate.

## Next

Do not ship a slower implementation as a campaign win. Profile the candidate's
value pass before further pipeline tuning, or evaluate a numerically improved
key-split accumulator under the unchanged production envelope. Exact equality
was this candidate's deliberate design contract, not a universal promotion bar.
The incumbent's recorded maximum-KL failure remains unresolved.
