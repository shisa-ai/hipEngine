# DE-11 refresh on promoted HEAD: decode depth growth is host-side

## Summary

Re-ran the DE-11 paired wall/kernel decode decomposition and decode-loop
cProfile passes on HEAD `6243efce2` (both exact-class promotions live). The
result is a decisive localization of the decode-depth lever: device kernel
time is flat with depth while the non-kernel remainder more than triples, and
the host-enqueue window exceeds device execution by ~16.6 ms/step at p4096 —
the decode step is host-bound at depth, leaving the device idle ~20% of each
step. The cProfile names the mechanism: ~14.4k os.environ lookups and ~920
per-launch `build_hip` library re-resolutions per decode step, multiplied by
the depth-growing launch count (+75/step at p4096).

## Changes

- Paired split (chunk 1024, full capture, thermal-gated counterbalanced
  session): p512 wall 47.777 / kernel 44.279 / remainder 3.498 ms/step;
  p4096 wall 56.384 / kernel 45.025 / remainder 11.360 ms/step. Kernel time
  grows +1.7% while wall grows +18%; launches grow only +4.3%.
- Compact-path host window (cooled canonical verify): 49.40 -> 61.63 ms/step
  p512 -> p4096 against a ~45 ms device — the host cannot feed the device at
  depth. Removing the gap is worth moving p4096 decode from ~16.7 toward
  ~20+ tok/s (gufo holds 25.96 flat at all depths).
- cProfile of the decode loop: per step ~14.4k os.environ lookups
  (encode/get/__getitem__ cluster, 4.7 -> 6.0 ms/step), 919 -> 958 per-launch
  build_hip re-resolutions with `_resolution_environment_identity`
  (2.2 -> 2.8 ms/step), launch_gguf_linear body 4.0 -> 5.0 ms/step, _launch
  6.4 -> 6.6 ms/step. This is the per-launch `build_X(load=True)` debt
  already tracked in docs/REFACTOR.md.

## Validation

- DE-11 refresh session: 8 counterbalanced thermal-gated runs, join rejects
  mismatched identities; outputs deterministic.
- Diagnostic only: no default, kernel or profile changed by this unit.

## Next

- Concrete fix (next loop iteration): thread the resolved kernel libraries
  through the production launch sites (the `library`/`libraries` parameters
  already exist) so the launch path resolves once per process rather than
  once per launch, per the REFACTOR.md removal condition. Decide explicitly
  that the production launch path does not observe mid-process
  build-identity environment changes: every harness binds environment flags
  before generator construction.
- Expected effect: removes ~5-9 ms/step of host work and halves the marginal
  per-launch cost that the depth-growing launch count multiplies; with the
  step host-bound by ~16.6 ms at p4096, the decode wall should move by most
  of that amount at depth and little at p512 (device-bound).
