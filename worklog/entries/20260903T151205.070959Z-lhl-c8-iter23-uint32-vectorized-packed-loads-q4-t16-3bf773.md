# C8 iter23: uint32 vectorized packed loads for Q4 T16 dense GEMV

## Summary

Re-created and screened the iteration-20 candidate that was lost to the tool
environment glitch: replaced per-byte packed weight loads with one aligned
uint32 load per thread per buffer in the Q4 T16 dense GEMV kernel bodies
(`q4_k_t16_dense_dual_local32_silu_gemv_kernel`,
`q4_k_t16_dense_single_local32_gemv_kernel`,
`q4_k_t16_dense_single_local32_residual_gemv_kernel`). One uint32 load replaces
four byte loads; little-endian byte extraction preserves the exact nibble order,
so the arithmetic (per-row FMA order, scale/min decode, reduction) is unchanged.

## Findings

- Correctness: bit-exact. The leaf A/B on Qwen3.8-27B Q4_K_M layers 0/8/63
  reports `bf16_mismatches = 0` and `bf16_max_ulp = 0` on every layer with
  `candidate_sha256 == control_sha256` (bit-identical outputs vs the unfused
  chain). This exceeds the C8 outer floor (KL <= 0.05, top-1 >= 90%).
- Performance (fused dual-decode vs control unfused chain, 15 ordered pairs per
  layer, median-of-medians; same-host W7900/gfx1100, real device detection):
  - iter20 baseline (per-byte loads): L0 1.109x (11/15), L8 1.124x (12/15),
    L63 1.206x (14/15); geomean 1.146.
  - iter22 candidate (uint32 loads): L0 1.456x (14/15), L8 1.156x (13/15),
    L63 1.161x (11/15); geomean 1.250 (+9.1% aggregate margin).
  - L0 clearly improved (+31%); L8/L63 deltas (+2.9%/-3.7%) are within the
    A/B noise of 15 paired samples (L63 wins 11/15 is near coin-flip).
- Open/partial campaign items unchanged at 35: this is a leaf-screened kernel
  refinement, not a punchlist item closure.
