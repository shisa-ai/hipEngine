# Override and default invariance coverage for MTP screening

## Summary

Test-only unit closing the screening override's contract: the explicit path is
RED-proven against the pre-change serving layer, and the unchanged default is
pinned by invariance guards that pass before and after. No runtime behavior
changed; the implementation landed in `509336419`.

The RED check was run in a scratch worktree at `HEAD~1` rather than by reverting
files here. On the pre-change source the new tests cannot even import
`_mtp_screening_static_eligibility`, so a temporary copy of the old tree was
given only the helper and the reason set — the sharpest available split:

- helper + reason set, no wiring: 4 behavior tests fail
  (`..._keeps_explicit_intent_for_an_unqualified_cell`,
  `..._applies_in_the_default_auto_mode`,
  `..._response_metadata_marks_the_unqualified_cell`,
  `..._realized_re_resolution_carries_screening_intent`) and 6 pass;
- full implementation: 12 pass.

The 6 that pass in both states are the invariance guards the task asked for:
qualified cells keep their evidence-backed plan, `enabled`/`auto` without
explicit intent stay fail-closed, an explicit opt-out stays AR, and the
sampling-mode boundary stays closed.

## Changes

- `tests/test_integration_server_api.py`:
  - `QualifiedServingPlanFakeLLM`, a fake whose payload matches the live
    resolver's `as_dict()` shape (the shared fake omits `static_eligibility`, so
    it cannot express a plan layer that grants typed intent at all);
  - `test_screening_switch_leaves_a_qualified_cell_unchanged` — evidence-backed
    eligibility, `selected_candidate_count == 3`, and no qualification marker,
    with the switch both off and on;
  - `test_screening_switch_does_not_admit_an_enabled_default_request` — the
    server default stays fail-closed and unmarked with screening on;
  - `test_screening_switch_ignores_an_explicit_opt_out` — `speculative_mtp:
    false` never reaches the resolver;
  - `test_screening_override_applies_in_the_default_auto_mode` — the RED case for
    the default `auto` mode;
  - `test_mtp_screening_helper_refuses_plans_it_cannot_authorize` — fail-closed
    on malformed plans and on sampling-mode, artifact-identity, and memory
    reasons.
- `tests/test_unit_speculative_mtp_serving_capability.py`:
  `test_screening_switch_does_not_widen_model_plugin_evidence` pins that the
  model-plugin resolver still refuses candidate-budget, sampling-mode,
  memory-fit, and physical-group axes with the switch on. Screening is a
  serving-layer decision; evidence is never widened.
