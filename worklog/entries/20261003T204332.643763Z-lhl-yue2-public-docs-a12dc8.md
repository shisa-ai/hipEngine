# YuE2 listed on the README and model-support pages, with its entry point documented

## Summary

YuE2 music generation is implemented and merged on `main`, but its public surface did
not say so: the root README's "Supported models" list had no music entry, `docs/MODELS.md`
(the support reference the README links to) had no YuE2 row, and
`docs/model-cards/MODEL-YUE2.md` still described its file layout as a proposal and named a
branch that no longer exists. This unit adds both listings and makes the model card
describe the delivered surface, including the entry point a user actually calls.

## Changes

- `README.md`: a "Music generation" bullet under "Supported models" linking the model
  card, marked early support and Strix Halo measured.
- `docs/MODELS.md`: a YuE2 row (both checkpoints, `gfx1151`, implemented and measured end
  to end); the section heading now names music.
- `docs/model-cards/MODEL-YUE2.md`: "Proposed file layout" becomes "File layout" (every
  listed module exists); the `YuE2Session` paragraph states that orchestration is
  model-owned and that no `LLM` convenience method exists yet; a new "Running it" section
  carries the construction recipe (both loaders, three runtimes, tokenizer, session), the
  request and result contract, the `cot` modes, the step and sampling overrides, and
  per-session serialization; the stale "Last reviewed ... on branch `yue2`" line now names
  the host instead.

## Validation

- The documented recipe was executed against the local `m-a-p/YuE2-3B` and
  `m-a-p/YuE2-Vae` snapshots with greedy sampling capped at 96 semantic tokens: 96 frames,
  184,256 samples, 3.8387 s of audio, peak 0.0025, finite, `torch imported=False`, 10.3 s.
  Same shape as the committed live gate
