# Retire performance caveat clutter from the root README

## Summary

The root README's performance section had accumulated per-row provenance notes,
a dead date column, and methodology caveats that repeated what
`benchmarks/README.md` already records. The lead retired them: the product page
states measured results and the limits a user must act on, and evidence detail
stays in the benchmark report. `README.md` drops 427 -> 362 lines; the exported
TOPLINE block drops 103 -> 76 lines.

## Changes

- `benchmarks/README.md` TOPLINE block (the canonical source for the root
  README export): dropped the `AR measured` date column, the per-table
  provenance paragraphs, and the TimesFM / VibeVoice-ASR result paragraphs;
  removed the redundant `### Performance` heading so the hardware tables sit
  directly under `## Performance highlights`.
- Root README prose: `## Status and limits` cut from 40 lines to 15, the
  coding-agent replay caveat block removed, the duplicated prompt-processing /
  text-generation definition removed (the exported block already defines both),
  and the `Why use hipEngine?` bullets tightened.
- Retired `APIs and supported combinations can still change before 1.0.` from
  the root README and the identical `APIs and measured coverage can still change
  before 1.0.` from `docs/MODELS.md`.
- `tests/test_integration_benchmark_readme_sync.py`: the two assertions that
  required `93.644 tok/s public` and `214.788` to appear in the root README are
  replaced by negative guards on the retired clutter shapes (`AR measured`,
  `In these tests,`, `September 20: Framework Desktop`, `one adapted
  transcript`, `not a general agent-quality benchmark`).
