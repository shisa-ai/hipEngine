# Separate Qwen GGUF KV storage from execution

## Summary

Separate physical KV layout, backing and allocation from the Qwen GGUF execution module. The family name matches GGUF architecture identifiers (`qwen35`, `qwen35moe`); the executor module's bring-up description no longer matches production use.

## Changes

- Extracted 807 lines of physical KV storage into `hipengine/runtime/qwen35_gguf_kv.py`. Allocators take configuration, not a full runner; the executor checks lifetime before passing geometry. Session policy, admission and growth coordination remain in the executor/session module.
- Preserved public layout/backing imports as aliases, including legacy pickle lookup. Updated the module description to production execution and session orchestration; retained `qwen35` because it is the GGUF architecture identifier.
- Added `docs/reference/QWEN-GGUF-RUNTIME.md` with concrete responsibilities and separately scoped future scratch/session/execution boundaries. No mixins or module rename were introduced.
- Physical lines: original runner 40,740 → 39,965; storage module 822; combined 40,787 (+47). This is dependency separation, not code deletion or completion of the whole runtime decomposition.
