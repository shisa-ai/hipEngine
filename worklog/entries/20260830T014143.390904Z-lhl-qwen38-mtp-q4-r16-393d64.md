# Reject exact Q4 true-R16 operation-complete revisit

## Summary

The Q5 true-R16 result justified reopening the prior Q4 leaf-only stop rule once:
submission elimination might have outweighed a slower GPU leaf. It does not.
Exact register-bounded Q4 true-R16 candidates are 43.1-70.3% slower than R8+R8
across all six actual single/dual shapes and lose all 90 timing pairs. Weighted
by model operation counts, Q4 R16 GPU work rises **101.03→156.90 ms (+55.31%)**
while eliminating 200 of 400 launches per physical R16 group.

The bounded operation-complete C4 screen regresses
**29.610→27.717 tok/s (-6.39%)** on `code_merge_intervals`; wall rises
**3.2422→3.4636 s**. Outputs, engagement, and budget remain exact, but the
candidate fails before a full suite. All candidate code and policy are removed.

## Changes

- Temporarily restore the exact register-bounded col4 design at ROW_TILE=16 for
  five single projections and one two-wave gate/up+SiLU composite.
- Compare every actual shape to the retained R8+R8 parent and admit only the
  bounded physical-R16 diagnostic key.
- Remove all candidate kernel/wrapper/registry/runtime/package/test code after
  the complete C4 stop failed.
- Retain only an explicit Q5 actual-test registration fix so sequential local
  actual-weight tests cannot inherit missing gfx1151 aliases.

## Validation

- All six actual shapes are BF16-bit exact with guard regions unchanged.
- Five warmups plus 15 counterbalanced HIP-event pairs per shape: 0/90 wins;
  weighted GPU penalty +55.31%.
- One canonical train prompt, C4/D24/K3, complete server wall: -6.39%, exact,
  engaged, budget-conformant.
- No full-suite run: the candidate is already non-retainable and the anti-gaming
  protocol forbids salvaging a favorable prompt/category subset.
