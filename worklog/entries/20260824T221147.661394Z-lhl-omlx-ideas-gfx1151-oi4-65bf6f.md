# Evaluate draft hidden normalization policy

## Summary

Implemented an immutable `pre_output_norm|post_output_norm` target-to-draft
policy and rejected post-output-norm promotion for gfx1151 Qwen3.8-27B
`Q4_K_M`. The strict/default pre-output-norm route is unchanged.

Post-norm applies the target's final RMSNorm exactly once to every prompt-hidden
chunk and every steady target proposal. Target transaction commit/rollback still
owns the pre-output-norm trunk row, and deeper draft chain steps keep the NextN
head's own normalized hidden. This avoids both policy drift across seams and
accidental double application of the target norm.

## Changes

- Added frozen `Qwen35GGUFDraftHiddenPolicy` with a compact manifest naming
  prompt, proposal, target-commit, and draft-chain conventions.
- Added bounded chunk-local post-norm storage for streamed prompt priming and a
  one-row proposal buffer. Cross-stream proposal graphs receive a fully retired
  normalized row; all buffers close transactionally.
- Added explicit `draft_hidden_variant` to the decoder and
  `--draft-hidden-variant` to `scripts/qwen36_dense_gguf_suite.py`. The package
  default remains `pre_output_norm`; there is no prompt/content-adaptive branch.
- Added direct normalization/manifest/close/transform tests and `RF-OI4` cleanup
  criteria.

## Validation

- Unit bundle passes for policy validation/immutability, one exact target norm,
  strict identity fallback, transformed prompt chunks, owner/cancellation
  ordering, idempotent policy-buffer close, and benchmark CLI wiring.
- Full ten-prompt category/heldout B1/B2/B3 candidate is `complete_exact`: all
  greedy IDs exact, GPU/CPU target acceptance exact, mixed reject/partial/full
  tails exercised across reused requests, and final tracked memory is zero.
- Full candidate versus the retained pre-norm control:

  | Budget | Pre | Post | Speed | Acceptance |
  | ---: | ---: | ---: | ---: | --- |
  | B1 | 17.143 | 17.328 tok/s | +1.08% | 113/131 -> 113/129 |
  | B2 | 20.020 | 20.733 tok/s | +3.56% | 144/200 -> 145/195 |
  | B3 | 21.052 | 20.710 tok/s | **-1.62%** | **159/252 -> 158/255** |

- A dedicated immediate B2 pre/post repeat confirms the aggregate candidate
  signal (**20.211 -> 20.742 tok/s, +2.63%**) and proposal efficiency
  (**144/200 -> 145/195**), but fails binding heldout/Japanese speed gates
  (**-0.71%/-4.50%**). B1 also regresses train/Japanese; B3 regresses aggregate,
  code, Japanese, and mixed. Per-category failure rejects both global and
  budget-scoped promotion.
- The complete suite's repeated AR-before-MTP ordering proves subsequent AR
  health after prior post-norm requests. Unit cancellation checks run before a
  chunk transform; output tails/reset and zero-close are covered by the real
  multi-request suite. The expensive long-context promotion gate was skipped
  after B3 aggregate/acceptance and multiple category gates had already rejected
  the default-off candidate.
