# VibeVoice ASR Qwen2 GPU runner (incremental) parity-proven

## Summary

Torch-free incremental Qwen2 GPU runner for the VibeVoice-ASR text
backbone, reusing in-tree kernels; parity-proven against the torch LM
fixture. Follow-up to
`20260913T230004.823883Z-lhl-vibevoice-asr-gpu-parity-726d14.md`.

## Changes

- `hipengine/runtime/vibevoice_qwen2.py`: dense contiguous-KV
  ``(max_ctx, 4, 128)`` bf16 per layer, single token path for prefill and
  decode. Chain per layer: vv_rmsnorm -> dense GEMV (bf16 x, f32 out) ->
  vv_add_bias_f32 -> rotate-half rope (existing qwen35 kernel,
  per-position cos/sin slices, HF duplicated-half table) -> dense GQA
  decode attention (existing dense variant, fp32 q / bf16 KV) -> o GEMV
  -> residual -> rmsnorm -> dual GEMV (gate|up) -> silu_mul_dual -> down
  GEMV -> residual; final norm + lm head GEMV + host argmax.
- `vv_add_bias_f32` kernel added to the vibevoice family.
- `tests/test_gpu_vibevoice_qwen2_runner.py`: first-position logits
  (rel <= 2e-2, argmax match), full 16-token greedy chain equality, and
  teacher-forced top-1 chain vs the torch fixture.

## Validation

- gfx1151, real weights: logits_pos0 rel 1.4e-2 (argmax match); greedy
  chain 16/16 identical to torch; `--suite gpu` runner tests 3/3 pass.
- Piecewise layer-0 chain vs numpy CPU reference: attention rel 2.3e-3,
  o_proj 1.6e-3, residuals/norms/gate-up/silu all <= 6e-3.
- Bug found by the per-layer RED comparison: down_proj was fed bf16
  `_silu` into the fp32-input GEMV (reads past the buffer -> garbage /
  NaN); fixed to the bf16 GEMV variant.
