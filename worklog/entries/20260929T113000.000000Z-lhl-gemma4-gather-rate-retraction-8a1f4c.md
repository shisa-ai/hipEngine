# retraction: the gather runs at 144 GB/s, not 2.4, and the expert glue has no lever left

## Summary

`20260929T103000` priced the expert block's glue and reported `gather packed hidden` at
**"~23 MB, so ~2.4 GB/s"**, calling it one of two small kernels "doing a little work very
slowly". **That figure is wrong and the conclusion drawn from it is wrong.**

The error is arithmetic: 23 MB is the *per-call* traffic and 9.580 ms is the *total over 30
calls*. Dividing one by the other mixes the two:

```
read  = 4096 lanes x 2816 hidden x 2 B = 23.07 MB
write = 23.07 MB
total = 46.14 MB per call, 1384 MB over 30 calls

per call : 46.14 MB / 0.3193 ms = 144.5 GB/s
30 calls : 1384 MB  / 9.580 ms  = 144.5 GB/s     <- consistent, and correct
```

**144.5 GB/s is above the 127 GB/s the dense GEMM sustains on this host** (`20260929T020000`).
The gather is not slow. It is a scattered-row read whose blocks are already
`(total_elements + 255) / 256` -- about 45,000 of them -- so the geometry is fine too.

## The hypothesis this refutes

The compactor was fixed by finding a `dim3(1)` launch, and the gather had the same
"far-below-bandwidth" signature on paper, so it was the obvious next candidate. **It has neither
the under-parallelised launch nor the low rate.** Checked before changing anything, which is the
lesson `20260928T114215` and `bbe844ecb`/`e88a5322e` both teach about this block.

## What survives, re-derived

The compactor's diagnosis was made with the *same* method and does survive, because its numbers
happen to be tiny on both sides:

```
writes = 4096 lanes x (8 + 8 + 4) B = 81.9 KB per call
81.9 KB / 0.4118 ms = 199 MB/s
```

**199 MB/s for 82 KB is absurd at any bandwidth**, the launch really was `dim3(1)`, and the
measured fix was 11.6x (`20260929T110000`). The entry said "~49 KB" where the correct figure is
81.9 KB; the conclusion is unaffected, but the number was wrong too.

`weighted accumulate`, the next term, is also at bandwidth: it reads `expert_out`
(lanes x hidden x 2 = 23.07 MB) and writes `out` (tokens x hidden x 2 = 2.88 MB), 25.96 MB in
0.1760 ms = **147.5 GB/s**.

## Conclusion: the expert block's glue has no lever left

| part | ms | rate | verdict |
| --- | ---: | ---: | --- |
| group compact (active) | 12.354 -> **1.067** | 199 MB/s -> fixed | **fixed, 11.6x** |
| gather packed hidden | 9.580 | 144.5 GB/s | at bandwidth |
| weighted accumulate | 5.280 | 147.5 GB/s | at bandwidth |
| gelu tanh mul | 2.762 | small | not priced |
| activation pack (down) | 2.619 | small | not priced |
| readback / prefix / count / lane->row | 2.413 | trivial | launch-scale |

**The remaining ~11 ms is at bandwidth or is launch-scale.** The glue is done: it was one
mis-launched kernel, and that kernel is fixed. **Do not schedule the gather.**
