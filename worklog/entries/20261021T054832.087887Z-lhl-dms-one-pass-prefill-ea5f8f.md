# Pack exact-budget DMS prefill in one trunk pass

## Summary

Exact-budget compact-DMS prefill now reserves the score-independent retained count before compute and packs each completed layer in the same trunk execution that captured its scores. The shared BF16 oracle, codec kernels, FP32 scales, retention decisions and synchronous host staging are unchanged. Threshold and diagnostic/control policies retain their decision sweep followed by packing.

## Changes

- Add cached layer-local collector finalization. Each layer's complete score timeline uses the existing exact-budget CPU selector, including oldest-position tie-breaking, then uploads only its decision plane. Global finalization assembles the same token/layer/head decisions without recomputing finished layers. Reject capture after a layer is finalized.
- For contiguous actual prefill count `N`, protected window `W` and integer compression ratio `R`, set `E=max(0,N-W-1)` and reserve `N-E+ceil(E/R)` retained rows per head, plus the unchanged decode reserve. Use actual bulk token count rather than assumed HTTP prompt length.
- Allow decision capture and layer packing in the same layer-outer bulk call. Feed the MTP hidden sink in that call; retain cold prefix bytes/scores before releasing collector inputs. Stage each packed layer to host, then release bulk storage and oracle before restoring all compact layers.
- Close the unpublished backend if reservation, packing or final cleanup fails. Expose `prefill_trunk_passes` in DMS operation diagnostics. Existing threshold lifetime tests continue to cover their two-pass route; new exact-budget tests cover one-pass ordering.
- Address the review's missing-hidden-row case: allocate and own one BF16 row if a partially initialized session lacks its persistent row, copy the published final row, then release bulk storage before compact restoration. Normal session construction already allocates `_hidden_a`; DMS requires `max_batch_size=1`, whereas `resident_slot_view` needs a slot index strictly between zero and `slot_count`, so its shared-owner release guard is unreachable on the current DMS route. No new admission gate is added.
