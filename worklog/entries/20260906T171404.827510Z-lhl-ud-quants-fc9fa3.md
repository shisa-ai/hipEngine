# UD-U1 repair 3: coverage now binds backend keys and materializability before allocation

## Summary

U1 finding 3: `preflight_qwen35_gguf_artifact` qualified slots on
op/role/layout/source only, so (a) `backend='nonexistent'` got a positive
certificate, and (b) a Q6_K head `(257, 256)` with `decode_repack=True` got a
T16 certificate even though `repack_gguf_q6_k_tile16` rejects N not multiple of
16 — a failure that would only surface mid-materialization, after earlier root
allocations. Both prerequisites are now bound inside the preflight, and all
failures aggregate before any allocation.

## Changes

- `hipengine/loading/qwen35_gguf_admission.py`:
  - `_KNOWN_HARDWARE_BACKEND_KEYS` built from the pure metadata maps
    `HIP_BACKEND_TARGET_ARCH` / `CUDA_BACKEND_TARGET_ARCH`
    (`hipengine/kernels/backends.py`, no backend-package import, CPU-safe).
    `preflight_qwen35_gguf_artifact` raises `Qwen35GGUFAdmissionError` for any
    backend key outside that set, before per-slot planning.
  - Per-slot try block now also calls
    `planned_qwen35_gguf_weight_allocation_nbytes(spec)` right after
    `plan_qwen35_gguf_weight_spec`; ValueError becomes a `planner_refused`
    refusal ("T16 shape is not tile-aligned", "pack8 shape is not
    tile-aligned"). All per-slot refusals still aggregate into
    `report.unsupported` before the loader plans or allocates anything.
- `tests/test_gguf_ud_admission.py`:
  - New tests: unknown backend refused (`cpu_reference` and
    `nonexistent-backend` get no certificate); registered keys
    (hip_gfx1100/hip_gfx1151/cuda_sm120a) accepted; Q6_K head (257,256) T16
    refused by preflight with a `_cpu_allocation_fakes` allocator sentinel
    proving zero mallocs/copy_host_to_device calls; misaligned pack8
    projection (300,256 Q4_K, out % 8 != 0) refused as `planner_refused`; and
    a registration-evidence test asserting the certified coverage records'
    exact four-axis keys (including `moe_linear/gguf_iq3_xxs` from repair 2
    and `dense_gemv/bf16/out`) are registrable through the production
    registrars.
  - Synthetic metadata fixtures made block-truthful: `_tensor` now derives
    `byte_shape`/`nbytes` from the real GGUF quant layout
    (`quant_shape_to_byte_shape`/`nbytes_for_shape`) and the fixture geometry
    (hidden 256, vocab 32, ffn 256, ssm inner 256, time-step rank 16) is
    block/tile aligned, so every synthetic map is a possible real file.
