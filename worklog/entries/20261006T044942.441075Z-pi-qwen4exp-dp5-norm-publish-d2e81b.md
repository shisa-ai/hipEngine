# Screen F16 sidecar publication at the HC grouped norm boundary

## Summary

DP-5 screens a grouped-RMSNorm producer that publishes the existing
F32 activation and its IEEE F16 rounding in one launch. The actual HC-down
consumer reads `scratch.normalized`, not GR-mix output. Current HC-down
cast pair pricing is91.103/91.145ms over70calls for code-p4096, a ceiling,
not a predicted net saving. Natural complete norm+cast+same padded HC-down
wins1.096–1.104x at4096 across all four categories, wins1.059x at512code,
and loses0.939x at1024code. All420operations are exact and leak-free.
The producer is now diagnostic; no runtime handoff/default has changed.
The proposed native loan is bounded to exactly4096rows first.

## Changes

- Predeclare a separately registered norm publisher and strict unfused
  norm-plus-cast fallback. Keep parent reductions, multiplications and F32
  publication unchanged; F16 must equal the existing conversion bit-for-bit.
- Screen complete norm+cast versus dual-publication norm before building the
  runtime handoff. No default or profile changes in this screen.
- The selected runtime design is a single-use loan of the already-owned staging
  buffer for immediate norm->HC-down on the same stream. It must name exact
  source pointer/count, stream/runtime and active workspace identity/capacity;
  any overwrite or intervening staging invalidates it. Exit/exception always
  invalidates. Never cache by pointer across launches or allocate a sidecar.
  RED coverage for single-use, mismatch/fallback, nesting, alias/capacity,
  exceptions and independent contexts precedes implementation. Strict and
  unregistered/disabled/missing-workspace/shape paths retain parent norm+cast.
  This contract is predeclared, not yet implemented.
