# Release the Inkling decode graph when its session closes

## Summary

A process that opened the Inkling GGUF model more than once with the decode graph on aborted
after a few models with a GPU page fault. The graph holds a host page it registers for its input
row, and nothing released that page when its session closed: `_drop_graph_state` ran only when
another session wanted the graph or a session passed the log-scaling floor. Found while testing the
production default, which makes the graph the shipped route. The committed tree `832d43611` shows
the fault; releasing the graph at session close removes it.

Which held resource caused the fault was not isolated. Both symptoms fit a host page the runtime
still lists as pinned after its mapping is gone: the faulting address is page aligned, and the copy
that fails is a pageable one.

**A/B** (W7900, `fast` with device routes, resident decode and the graph, one 9-token prompt and 24
output tokens per model, 12 open-generate-close models per run, a second process holding 17 GiB of
device memory beside it, `HIP_LAUNCH_BLOCKING=1`, five runs):

| Tree | Models completed | Outcome |
| --- | ---: | --- |
| `832d43611` | 3 | aborted: `Memory access fault by GPU node-1 on address 0x7fad2dc12000. Reason: Page not present` |
| With this change | 12 | |
| With this change | 12 | |
| `832d43611` | 5 | `hipMemcpy` of a 9,216-byte pageable row returned `invalid argument` |
| With this change | 12 | |

Without the neighbour process the fault came in one of three runs of five models, at the third.
With the graph off, fifteen models in three runs passed.

## Changes

- `Inkling2TextSession.close` tells its model before the attention state goes
  (`release_session`, when the model has it). `Inkling2GGUFText.release_session` drops a graph
  recorded against that session.
- `_drop_graph_state` now releases everything the state holds through `_discard_capture`: before, it
  left the submission transport and the graph object alive on every drop, and only a failed capture
  released them.
- `_discard_capture` also destroys an executable instantiated in place of a transport.
- A session that passes the log-scaling floor retires its own graph and no longer sets the
  process-wide `_graph_disabled`: the next session starts below the floor and records again. The
  flag stays for a failed capture.
- `Inkling2GGUFGenerator.close` drops a graph that is still recorded before it frees the buffers
  the graph names.

## Validation

- `tests/test_unit_inkling2_decode_graph.py`: four new tests cover the release on session close
  (each resource released once, a second call and another session's graph untouched), the order of
  the session's own releases, the floor on one session followed by a new session, and the generator
  close.
- The Inkling GPU and unit test files pass with the model present on the W7900: 423 passed in all
  (422 in the full run and the three of the repaired gate-screen test in a second run; its
  expectation had a wrong index).
- The A/B table above.
