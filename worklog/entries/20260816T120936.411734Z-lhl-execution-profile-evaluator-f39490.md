# Execution profile evaluator foundation

## Summary

Implemented the torch-free, scenario-driven execution-profile evaluation
foundation. It separates exact request/control ownership from strict-teacher
numerical drift, same-schedule repeat determinism, same-width neighbor
isolation, and optional cross-composition invariance. No runtime default,
kernel, model weight, or performance result changed.

## Changes

- Added canonical `strict`, `production`, and `batch_invariant` identities plus
  canonical selected/strict-fallback variant manifests and SHA-256 provenance in
  `hipengine/execution_profiles.py`; this is a selector contract over the
  existing registry `variant` axis, not a fifth registry dimension.
- Added `hipengine/benchmark/execution_profiles.py` with aligned strict-teacher
  mean/p95/p99/max KL, top-1, top-k, teacher-NLL, margin/outlier localization,
  category/shape/transition summaries, exact control comparisons, dynamic
  scenario summaries, repeat/isolation/composition checks, paired BF16-relative
  prompt bootstrap, task verdict binding, capture hashes, and compact artifact
  validation. The KL/NLL/top-k definitions reuse
  `scripts/quant_quality/metrics.py`.
- Exact control records cover physical slot/row/width, input token, position,
  context, complete mask manifest, publication/update order, speculative
  transaction/accepted-token accounting, route/scatter ownership, KV live
  span/append destination, recurrent-state owner/update ordinal,
  KV/state/route finiteness, RNG owner/seed/counter, graph bucket, and lifecycle
  work class. MoE route-decision hashes are strict/repeat diagnostics rather
  than universal production equality, matching the policy
  that bounded upstream drift may change near-tie expert choices. Scenario
  summaries expose raggedness, delayed admission, sparse retirement,
  cancellation/reclaim, compaction, width transitions, and KV page/base
  transitions.
- Added external-NPY capture, actual-control, expected-control, manifest, and
  evaluation JSON schemas plus the generic `scripts/execution_profile_gate.py`
  adapter. Added a Qwen3.6 adapter for existing quant-quality teacher
  fixtures/caches; it deliberately requires
  actual control telemetry carrying the same run ID rather than inventing
  ownership evidence from legacy logits or using telemetry as its own expected
  fixture.
- Documented the executable evaluator contract and example command in
  `docs/TESTING.md`.
- RED was established by the two new test modules failing collection because
  both profile modules were absent. GREEN covers metrics/tails, outlier review,
  non-finite failure, BF16 non-inferiority, dynamic metadata failure
  localization, delayed admission/cancellation/compaction, repeat determinism,
  logical-request invariance, Qwen3.6 adaptation, manifest hashing/fallbacks,
  capture hashing/loading, and end-to-end CLI artifact generation.
