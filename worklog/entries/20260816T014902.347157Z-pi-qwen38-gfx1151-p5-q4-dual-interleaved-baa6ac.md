# Screen Qwen3.8 dual-interleaved Q4 decode

## Summary

Reject the byte-neutral dual-interleaved T16 transfer for the dominant Qwen3.8
serial-c1 dense-Q4 gate/up family. Against the retained residual-Q8_1x2
split-weight owner, the existing exact-BF16-input interleaved route regresses the
three-weight family **1.428673 -> 1.452220 ms (0.98379x, 7/45 wins)** and
projects **-8.131 ms / -0.6291%** selected 4K kernel wall.

## Changes

- No production change. Repacked actual Qwen3.8 layer 0/8/63 gate/up pairs into
  the existing byte-neutral dual-interleaved T16 format and compared its
  BF16-input tile2 consumer against the retained Q8_1x2 producer plus
  split-weight consumer.
- Each source pair is **95.625 MiB** and each separate/interleaved resident pair
  is byte-identical in size at **103,055,360 bytes**, keeping more than 64 MiB
  between repeats.
- Preserved compact evidence at
  `benchmarks/results/2026-08-16-gfx1151-qwen38-27b-q4-dual-interleaved-rejected.json`.

## Validation

- All three actual layers regress: candidate speedups are
  **0.98135x/0.98300x/0.98702x** with only **1/3/3** wins out of 15.
- Both routes are finite, max KL is **2.57e-11**, top-1 agreement is 3/3, and
  tracked ownership returns exactly 0 -> 0 bytes. The interleaved exact-BF16
  arithmetic differs from the retained changed-association route in
  508/471/497 outputs, so it also cannot inherit the current trajectory gate.
- Source-lineage selection reports no external parent for the in-tree selected-
  T16 source. The cached diagnostic used existing wrappers/kernels only and left
  all production source unchanged. Raw leaf SHA-256 is
  `f2b94f5b5d4c354350f70fa4d8427f0ca57db40ed1fe2d6cb115016bf9724a87`.

## Next

- Keep separate plane-major Q4T16 weights and the retained Q8_1x2 split-weight
  owner. Do not build an operation-complete dense dual-interleaved package;
  rerank beyond Q4 gate/up payload interleaving.
