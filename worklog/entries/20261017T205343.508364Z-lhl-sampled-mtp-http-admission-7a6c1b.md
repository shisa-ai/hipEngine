# Admit provider-declared sampled MTP through HTTP

## Summary

Flash-Next HTTP requests can select the implemented target-distribution MTP
sampler through either speculative spelling. CPU HTTP tests execute the real
resident owner with analytic fake logits. GPU qualification and task 17 remain
open; automatic MTP and buffered-streaming policy are unchanged.

## Changes

- Declare the provider's enumerated sampling fields, processed verification and
  deterministic-draft/target-draw algorithm. Admission removes only declared
  blockers; the processed-verifier boolean alone grants nothing. Legacy
  providers retain raw-greedy and generic stop-handling behavior.
- Preserve BF16/c1 and unsupported controls. Flash-Next stops, alternate EOS,
  minimum/forced tokens, grammar, hard thinking and resident sessions fail early
  for generic requests or select the named explicit-MTP-to-AR fallback. Fallback
  metadata no longer falsely lists implemented temperature/logprobs as blockers.
- Route speculative logprob requests through the existing queue/route dispatcher
  instead of the unconditional direct-AR shortcut. This preserves operator
  rollback, admission and circuit-breaker ownership; it adds no scheduler.
- Forward capability metadata through the real LLM/submission/model/provider
  chain. CPU HTTP tests prove actual target verification (not AR labelled MTP)
  for completions/chat, blocking/SSE and with/without logprobs. SSE remains
  buffered; no kernel or profile arithmetic changed.
