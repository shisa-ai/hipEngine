# Drafter quantization profiling: forwards are dispatch-bound (~28% peak BW), quantization upside modest

## Summary

Task #34 step 1 (profile before quantizing): the drafter forwards are **dispatch-bound, not bandwidth-bound**, which dampens the quantization upside. DSpine forward reads 3.2 GB of layer weights in 44.9 ms = 71 GB/s = **28% of the 8060S ~256 GB/s peak**; EAGLE's layer is 712 MB / 10.5 ms = 68 GB/s = **26% of peak**. The ~72% dispatch/latency overhead dominates, so cutting weight bytes only shrinks the bandwidth portion.

## Changes

- No code change. Profiling only (`/tmp/dspine_forward_profile.py`, `/tmp/eagle4_draft_profile.py`).

## Validation

- DSpine forward (5 layers, bs=16): 44.9 ms wall, 3198 MB layer-projection weight read, 71.2 GB/s effective (28% peak).
- EAGLE-4 layer (qkv+attend+ffn, rows=1): ~10.5 ms, ~712 MB, 68 GB/s (26% peak).
- Conservative projection (same kernel efficiency, wall = dispatch + bytes/peak): DSpine Q8 forward 44.9->38.7 ms (-14%), Q4 ->35.5 ms (-21%). The forward is ~16% of the DSpine cycle, so Q4 ~= 3% cycle gain; EAGLE similar (~3%).
- Nuance: the target's optimized Q4_K rowtile kernels may saturate bandwidth better than the BF16 `dflash_dense` kernels the drafters currently use, so the empirical gain could exceed this conservative floor. Only an implementation + measurement resolves it.
