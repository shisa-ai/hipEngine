# Define execution profiles and production numerics campaign

## Summary

Defined the public numerical contract for `strict`, `production`, and
`batch_invariant` execution profiles. The policy keeps request, state, KV,
position, mask, transaction, and sampler ownership exact in every profile while
allowing bounded same-artifact floating-point implementation drift in
`production`.

## Changes

- Added `docs/EXECUTION-PROFILES.md` as the normative profile and numerical-gate
  policy beneath `docs/PLAN.md`.
- Added `docs/PRODUCTION-NUMERICS-CAMPAIGN.md` with the independent evidence
  audit, evaluator design, candidate queue, c1/cN protocol, and phased exit
  gates.
- Reduced `docs/RELAXED.md` to a historical inventory and Git provenance pointer
  so its superseded six-profile/tier rules are no longer presented as active
  policy.
- Separated semantic/control correctness, repeat determinism, and
  batch-composition invariance instead of treating cross-width bit identity as
  the universal production gate.
- Defined provisional teacher-forced KL/top-1 envelopes, BF16-relative
  non-inferiority, dynamic serving/isolation checks, task-quality gates, strict
  fallbacks, manifest provenance, and automatic rejection conditions.
- Kept weight quantization, KV representation, speculative acceptance, and
  sampling policy orthogonal to execution profile; those are not silently
  authorized as implementation drift.
- Specified profile resolution as an immutable selector over the existing
  four-axis registry rather than a fifth dispatch axis.
