# Scope the worklog gate to the commit tree

## Summary

- The installed worklog pre-commit hook validated the entire working tree, so any
  worker's unfinished entry under `worklog/entries/` failed every commit in the
  shared worktree and forced `git commit --no-verify`. Observed on
  `worklog/entries/20260912T134710.640315Z-lhl-gguf-auto-context-sizing-d4b212.md`
  while its required-field placeholders were still unfilled; the only workaround
  was bypassing the hook, which also skipped the entry checks that were correct.
- `scripts/worklog.py check` now validates the **commit tree** (HEAD plus the Git
  index) instead of the working directory. Entry text is read from the index in
  one `git cat-file --batch` call. An untracked entry file is not part of the
  commit, is reported as a note, and can never fail the gate;
  `check --include-unstaged` validates such a file on request.
- Everything staged or tracked is gated exactly as before: staged entries with
  unfinished placeholders, malformed schema, a staged entry whose working-tree
  copy has moved on, in-place edits of committed entries, the frozen legacy pair,
  and unmerged index paths all still fail.

## Changes

- `scripts/worklog.py`: index-scoped validation (`index_listing`,
  `read_index_blobs`, `validate_records`, `filename_errors`),
  `immutability_errors` over `git diff --cached HEAD` plus worktree-vs-index
  divergence, `report_unstaged_entries` notes on stderr,
  `check --include-unstaged`, and `render` merging valid unstaged entries into
  the local view while skipping invalid ones with a note.
- `tests/test_integration_worklog.py`: malformed-entry cases now stage their
  content first; new coverage for an unfinished unstaged entry (check, hook, and
  a real `git commit` with the installed hook), a staged unfinished entry,
  `--include-unstaged`, render with unstaged and invalid entries, and an unmerged
  index conflict.
- Docs: `worklog/README.md` (stage before check, scoping, render note),
  `docs/PLAN-WORKLOG2-revamp.md` §7 scope amendment, the `AGENTS.md` worklog
  bullet, `docs/BENCHMARK.md` step 8, and the `WORKLOG.md` navigation snippet.
- The managed pre-commit hook text is unchanged, so already-installed hooks keep
  matching byte-for-byte and pick up the new semantics without reinstalling.

## Validation

- `uv run pytest tests/test_integration_worklog.py -p no:randomly -q` → 33
  passed, including `test_commit_succeeds_with_unfinished_unstaged_entry_present`,
  which runs the installed hook through a real `git commit` with an unfinished
  untracked entry present.
- `python3 scripts/worklog.py check` on this repository: `worklog: 2745 valid
  entries`, ~0.31 s, unchanged from the working-tree reader.
- Manual temp-repo scenarios: unfinished untracked entry plus staged valid entry
  → exit 0 with a note; staged-then-edited entry → "re-run `git add`"; entry
  conflicted in the index → one "unresolved merge conflict in the Git index"
  error and no immutability noise.
- This commit was made with the hook enabled, without `--no-verify`.
