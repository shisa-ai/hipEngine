# Prevent HIP cache environment leakage in full suite

## Summary

Repair a pre-existing full-suite global-state leak. The continuous-owner cache
contract test called a helper that directly set four `HIPENGINE_*` variables.
When those variables started absent, `monkeypatch.delenv()` recorded no undo,
leaving a temporary deleted cache root, synthetic compiler version, gfx1151 arch,
and `require_cached=1` for every later HIP test. This caused hundreds of false
cache-miss errors in the milestone run.

## Changes

- Register both absent and existing environment states through a sentinel
  `monkeypatch.setenv`/`delenv` pair before direct helper mutation.
- Let pytest reverse the pair after the test, restoring the true original state.

## Validation

The leak test followed in the same pytest process by a real IQ2 HIP kernel gate
passes (3 tests). In the interrupted broad run, the first independent failure
was the pre-existing benchmark-scoreboard 557-line limit; the large subsequent
HIP error cascade was the leaked temporary cache environment. Per focused-repair
policy the broad run is not repeated blindly; the complete SPECDEC2 bundle,
fixture check, and registry smoke remain the milestone evidence.
