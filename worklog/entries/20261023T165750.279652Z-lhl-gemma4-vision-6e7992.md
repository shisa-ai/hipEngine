# Gemma 4 image tower and public generation

## Summary

Implemented torch-free Gemma 4 GGUF image input through the public Python and
HTTP interfaces. Existing text generation and text-only assistant-head MTP keep
their routes. No runtime feature flag or artifact allowlist was added.

## Changes

- Initial review found text/MTP on gfx1100/gfx1151 and shared HTTP image transport,
  but no Gemma vision-sidecar loader, tower or text embedding injection.
- Added metadata/tensor-derived `clip` / `gemma4v` loading, RGB preprocessing,
  an independent NumPy tower, FP32 raw-pointer HIP primitives and a resident
  rocBLAS encoder. Position capacity is checked against actual grids, not every
  hypothetical aspect ratio. Positive image budgets are not an admission enum.
- Image features replace scaled text embeddings without further scaling.
  Sliding layers compose the window with causal-or-same-image visibility;
  global layers stay causal. Prefill chunking never splits an image span.
  Image state is request-local and cleared on exceptions.
- Added factory `vision_model_path`, generator image declarations, expanded
  prompt usage, ordinary Gemma sampling and ordered multi-image input. The
  shared HTTP image branch has an opt-in chat-template/sampling policy for
  Gemma; existing Qwen/Surya rendering is unchanged. Explicit speculative image
  requests fail rather than silently running autoregressively.
- Native vision GQA and clipped linears are named capability misses; the CPU
  oracle models them. INT8 image KV is refused before encoding because its
  consumer has no noncausal image mask. BF16 image generation runs by default
  with an attached sidecar. Audio/video and image-aware MTP are not implemented.
- Added focused CPU/GPU/live/HTTP tests and `docs/reference/GEMMA4-VISION.md`;
  updated the model card, architecture row, kernel catalog and generated docs
  indexes. Root README was not edited.
