# Close BridgeSpec GPU1 feasibility campaign

## Summary

Tested the bounded BridgeSpec B1-B4 mechanisms on physical GPU1, an RX 7900
XTX/gfx1100 with 24 GiB VRAM, against clean hipEngine source
`07f1ba6ae37e7d624c60239cafd51bea8d2beecf`. Keep current defaults. The
40,960-row DFlash head is a real head-level speed opportunity but changes
candidate quality and fails promotion; real-weight DFlash graph work is
kernel-bound rather than launch-bound; exact K/V-only NextN catch-up is already
implemented in current source.

## Validation

- **B1 current baseline:** ten canonical D24 prompts, production/BF16, exact
  same-session AR. Unprofiled C1/K3 is 27.334 -> 41.097 tok/s (1.5035x) and
  automatic C2/K2 is 43.959 -> 63.087 tok/s (1.4351x), all 20 arm cells exact
  and engaged. Under rocprof: 1.5595x and 1.4421x. Current full-process
  ownership remains Q4/Q6 T16-dominant. Capacity-8 C1/K3 OOMs on this 24-GiB
  card, so the forced C1 diagnostic used capacity 1; C2/K2 used capacity 2.
- **B2 40,960-row DFlash head:** one canonical prompt per category, D24,
  sequential exact target verification. Full head: 10.709 tok/s; slice:
  11.866 tok/s (1.1080x). Per-call score wall fell 2.676 -> 1.658 ms, but the
  restricted candidates reduced aggregate mean acceptance 2.462 -> 2.273 and
  recall@16 0.883 -> 0.720; Japanese mean acceptance fell 1.846 -> 1.091.
  Both arms reproduced target AR IDs, but the quality/task gate rejects the
  slice. The native B4 target verifier separately returned INT_MAX sentinels on
  GPU1, so it was not used as binding evidence.
- **B3 complete DFlash graph:** real 5-layer B8 forward + top16 + selector is
  17.225 ms/cycle unprofiled, 17.618 ms under rocprof. Marker-scoped kernels are
  16.452 ms/cycle across 127 launches: dense WMMA 7.601 ms, top16 4.237 ms,
  QKV 2.541 ms, selector walk 1.100 ms, selector projection 0.438 ms. The work
  is ~93% device kernels; graph launch removal cannot approach BridgeSpec's
  claimed 5.7x compression, so no implementation was opened.
- **B4 provider catch-up:** the existing `kv_write_only` branch is byte-exact
  for cache, full follow-on logits/top16/token/logit, and final state. It cuts
  1.261 -> 0.558 ms/tail token unprofiled (2.2607x; 0.703 ms saved) and
  1.589 -> 0.660 ms under rocprof (2.4084x). Marker kernel work falls
  0.929 -> 0.236 ms/token and 288 -> 168 calls across twelve steps. This is
  confirmation of current code, not a new port.
- Raw evidence roots and hashes are recorded in the compact artifact. Ran
  `python3 scripts/worklog.py check` and JSON/artifact validation before commit.
