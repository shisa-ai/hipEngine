# Extending the dense-wide Q8 prefill route to layers 0-47 is +18.9% prefill and +5.8% decode, output-identical on `code-p4096`

## Summary

`PRODUCTION_Q8_DENSE_WIDE_PREFILL_LAYERS` binds the wide-row Q8 route to
**layers 16-47**; layers 0-15 keep the exact coltile chain. Extending the
binding to **0-47** is a large measured win at one shape:

| arm | dense-wide scope | pp tok/s | tg tok/s | output sha256 |
| --- | --- | ---: | ---: | --- |
| A (baseline) | 16-47 | 271.719 | 17.437 | `c18d529b...` |
| B (candidate) | **0-47** | **323.613** | **18.437** | `c18d529b...` |
| C (baseline again) | 16-47 | 272.731 | 17.420 | `c18d529b...` |

**+18.88% prefill, +5.79% decode**, against a same-code A/C drift of
**+0.37% / -0.10%** - a 51x separation. All three arms emit the **identical
generated-token digest**, and it equals the digest of the chunk-1024 and
chunk-4096 runs measured earlier in the same tree.

**This is a candidate, not a promotion.** The route is certified at 16-47 only,
and the production gate at 0-47 has not been run yet; it is running now. The
prior art that matters is in `docs/QWEN4EXP-OPTIMIZATION-LEDGER.md` row DP-8,
and it cuts against a naive reading: a *different* route (the LDS-staged f32
tile) was laddered over the same region and **0-47 failed on mean/p95/top-1**
while 16-47 passed, with the additional finding that drift is **not cumulative
over layers** - 0-7's mean KL (1.354e-3) exceeds 0-47's (1.269e-3), so 8 layers
produce more whole-model divergence than 48. Nothing in that ladder constrains
`dense_wide`, which is a different arithmetic route, but it does mean the
region cannot be assumed benign and the gate is the only admissible evidence.

## Changes

### Experiment

Patched `PRODUCTION_Q8_DENSE_WIDE_PREFILL_LAYERS` from `tuple(range(16, 48))` to
`tuple(range(0, 48))` in `hipengine/generation/qwen4_exp_profiles.py`, ran the
arm, restored the file. The constant is read by the profile's literal env dict,
which `_apply_profile_env` writes **unconditionally**, so an env override cannot
reach it and the file patch is the only way to move this binding.

Patch verified per arm by resolving the constant under `uv run` before the arm
ran: arm A and C reported `len 32 first 16 last 47`, arm B `len 48 first 0 last
47`. The harness records `profile.manifest_sha256`, which is the execution
profile manifest and **does not cover this Python constant**, so the constant
probe is the engagement evidence, not the artifact.

Three arms in one session, one process per arm, order A-B-C, so the baseline is
measured on both sides of the candidate. `code-p4096`, production profile,
chunk 1024, 1 warmup + 3 repetitions, `--require-cached-build`, all under
`uv run`.

### Raw rates

- A (16-47): pp 271.832 / 271.588 / 271.736, tg 17.303 / 17.457 / 17.552
- B (0-47): pp 324.223 / 323.132 / 323.486, tg 18.481 / 18.373 / 18.456
- C (16-47): pp 272.888 / 272.729 / 272.577, tg 17.431 / 17.384 / 17.445

Baseline pooled mean 272.225 pp / 17.429 tg. Candidate against it:
**+18.876% pp**, **+5.786% tg**. Within-arm spread is 0.09% (A), 0.34% (B),
0.11% (C); A-to-C drift is +0.372% pp.

### Why the effect is this size

At chunk 1024 the trace from the earlier chunk-4096 capture puts the exact
coltile chain at **2.737 s per 4096-row prefill over 16 layers** and the wide
route at **0.616 s over 32 layers** - 0.171 s against 0.0193 s per layer. Moving
16 layers from the first to the second predicts roughly 2.4 s off a 14 s
prefill, i.e. ~17%, which is what was measured. The per-layer ratio is not
itself the evidence (the two routes do not serve identical tensors), but the
predicted magnitude and the measured magnitude agree.

- `deterministic: true` in all three arms.
- Per-arm constant probe under `uv run`, output recorded above.
- File restored to `tuple(range(16, 48))` after the run; `git status` clean for
  that path.

## Limits

- **One case, one shape, one quant, one host, one profile.** `code-p4096` only.
  The identical output digest is 129 generated tokens on one prompt and is
  **not** the numerical gate; a token-identity result at this scale is
  consistent with a small KL shift and does not bound one.
- The gate at 0-47 has **not** been run. Promotion is blocked on it.
- The constant patch is outside the recorded `manifest_sha256`, so the artifact
  alone would not show which scope ran; the probe is the evidence.
- No kernel-level trace of the 0-47 arm, so the mechanism is inferred from the
  16-47 trace's per-layer shares rather than measured on the candidate.
- The three arms were not interleaved within a process.
