# The pack8 expert route is wired, and it matches the raw route on the same weight

## Summary

Part two of the pack8 expert port: the route is wired, and the correctness gate
passes.

**The mismatch was one word.** `gemma4_project_experts_selected` resolved
`KernelKey(backend, "linear", quant_key, "selected_gemv_bf16_bf16_out")` while the
pack8 kernel registers under `KernelKey("hip_gfx1100", "moe_linear", "gguf_q4_k",
"expert_pack8_selected_bf16_bf16_out")`. The packed layout was being planned and
materialized while the dispatch never asked for it, because the layer name is what
selects the kernel family and a lookup under the wrong one simply misses.

**The route.** `gemma4_project_experts_pack8` resolves the `moe_linear` key and
passes the six pointers the kernel declares, with `qweight_high` null - required
only for q5_k and q6_k, not for q4_k. It sits in the ladder immediately before
`selected_gemv`: the same per-lane launch shape over the same arithmetic, reading
a representation that has the per-32-value scale and min terms already decoded.

**The gate.** The parity test runs **both routes on one weight object** that
carries both representations, so the only difference between the two calls is
which representation the kernel reads. A repack that mis-shifted the 4-bit lanes,
paired a scale with the wrong 32-value group, or read `mins` where `scales`
belongs would disagree. The raw route is itself pinned against the CPU reference
by an existing test, so agreeing with it transitively pins the packed layout
against that reference.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py`: `_PACK8_LAYER`,
  `_PACK8_VARIANT`, `gemma4_project_experts_pack8`, the ladder entry, and the
  route-preference docstring.
- `tests/test_unit_gemma4_gguf_device.py`: the same-weight parity test and the
  ladder-preference test.
- `tests/test_unit_gemma4_expert_route.py`: `_ResidentWeight` gained
  `has_allocation`, so the double reports faithfully that it carries only raw
  blocks rather than the route having to probe defensively.

## Validation

- `tests/test_unit_gemma4_expert_route.py` and `tests/test_unit_gemma4_gguf_device.py`:
  62 passed.
- The same-weight parity test passes, so the packed layout agrees with the raw one.
- The broader gemma4 unit suite has exactly one failure,
  `test_unit_gemma4_runner.py::test_incremental_decode_matches_a_dense_prefill`,
  which fails with the identical max abs diff of 4.417 with my files stashed, so it
  is pre-existing at HEAD and not a regression from this work.
- **Not verified:** that the pack8 route is actually faster, and that it is reached
  on the real artifact. Both are measurements, not reads, and are next.
