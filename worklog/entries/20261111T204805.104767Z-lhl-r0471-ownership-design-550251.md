# R0471 native-row/scheduler ownership design analysis

## Summary

Source-traced the exact ownership mismatch that blocks R0471's public scheduler
integration, so the next implementation step does not re-derive it. No code,
selector, or arithmetic change; this is a design checkpoint supplementing
`worklog/entries/20261031T230425.271053Z-lhl-r0471-native-public-gap-869c31.md`.

## Changes

- No code, selector, or arithmetic change. Design checkpoint only: records the
  source-traced ownership mismatch and the integration contract for the next step.
- Design implication: integrating the native-row route into the resident scheduler
  is an ownership-model change, not a dispatch-bit flip. It must (a) run
  `step_rows_native` on the batch owner, (b) reconcile the owner's
  `row_positions`/recurrent state with the active slot views' cursors/state,
  (c) compact active rows so slots are `range(rows)`, and (d) preserve packed/serial
  as the default and fallback. The route is opt-in (only when an optional DP4A
  selector is engaged), so the default packed/serial path can be left untouched,
  but the state/KV reconciliation is the hard, defect-prone part.

## Validation

Source inspection (no GPU run):

- Two distinct multi-prompt batch paths in `hipengine/generation/qwen35_gguf.py`:
  1. AR-serving / resident scheduler — taken first when `GREEDY_FAST`, >1 prompt, a
     shared runner, and `_ar_packed_decode_enabled() or _ar_stream_decode_enabled()`
     (line ~4301). Runs `SubmitPollTextGenerator`; per-step dispatch (line ~12029)
     tries `_step_native_chunk` (packed) then `_step_native_serial`.
     `_step_native_chunk` calls `execution_owner.step_batch_native(...)`
     (`hipengine/runtime/qwen35_gguf_runner.py:24971`) — packed AR decode, c1-exact
     per-slot linear attention, row-batched MoE/FFN/full-attention (`ar_decode_rows`).
  2. Compact native-row owner — only when `native_batch_decode=True` and the
     AR-serving branch did not fire (line ~4308). Builds a fresh
     `Qwen35GGUFResidentSession`, calls `_generate_greedy_batch` ->
     `generate_native_greedy_batch`
     (`hipengine/generation/gguf_native_batch_diagnostic.py`), whose decode step is
     `session.step_rows_native(...)`
     (`hipengine/runtime/qwen35_gguf_runner.py:21819`) — the `ar_decode_native_rows`
     route where the optional DP4A adapter engages.
- Resident scheduler ownership (`_reserve_sessions`, line ~10397): one `batch_owner`
  session (`max_batch_size=capacity`) plus `resident_slot_view(i)` for i in
  1..capacity-1.
- `resident_slot_view` (`hipengine/runtime/qwen35_gguf_runner.py:15144`) is a shallow
  `copy(self)`: weights, temp buffers, bulk-prefill scratch, packed workspace and
  `_target_scratch_owner` stay owner-wide; recurrent state, cursor (`_position`),
  graph bookkeeping and KV lease are slot-local; `view.max_batch_size = 1`.
- Mismatch: `step_rows_native` requires `rows <= self.max_batch_size` and compact
  physical slots (`slots == range(rows)`), and reads `self.row_positions`. A slot
  view (max_batch_size=1) cannot host it; only the batch owner can. But the
  scheduler's per-request cursors/state live in the slot views, not the owner's
  compact rows.
