# Pin prefix snapshot arena reclaim to zero live allocations

## Summary

Readiness-checklist item: pool growth/shrink and final request reclaim must
leave no orphaned ownership, with retained target snapshot arenas and dynamic
verifier scratch closed.

The named consumer, `_GGUFPrefixSnapshotArenaPool`
(`hipengine/runtime/qwen35_gguf_runner.py:15674`), had **no test coverage at
all**. It is the "retained target snapshot arenas" the item names: it recycles
whole snapshot arenas so a steady-state capture is memcpy-only, retaining a
bounded number and freeing the rest.

The pool reaches the device only through `hipengine.core.memory.malloc` /
`free`, which delegate to `runtime.malloc` / `runtime.free` and record into the
process-local tracker. A fake runtime therefore exercises the real ownership
path on CPU, and `memory_stats()["active_allocations"]` supplies the
"zero outstanding device allocations" assertion directly. No GPU is needed for
this half, which matters because the live-server half of the acceptance is
blocked on GTT pressure.

`test_unit_int8_mtp_teardown.py` already covers the other two named
requirements at the session level: `test_session_teardown_closes_retained_prefix_arenas`
(closes the pool on teardown, both slot-view and direct, idempotently) and
`test_dynamic_verifier_scratch_growth_belongs_to_session_root`.

## Changes

- `tests/test_unit_gguf_prefix_arena_reclaim.py` (new), six cases:
  - grow past the retention budget, shrink, then close -> retained count caps
    at the budget, the overflow arenas close immediately, and the final
    reclaim returns `active_allocations` to its pre-test baseline with every
    arena closed;
  - retention is keyed by capacity, so a geometry change allocates a
    correctly sized arena instead of reusing a stale one, while same-capacity
    reuse allocates nothing new;
  - a release arriving after `close()` frees the arena rather than retaining
    it in a pool that will never close it again (the engine-close case);
  - `close()` is idempotent and a closed pool refuses `acquire` with a named
    `RuntimeError` rather than silently allocating;
  - `max_retained=0` retains nothing;
  - `DeviceMemoryArena.close()` releases its owner exactly once.

  Each fake runtime draws from its own high, disjoint synthetic address range,
  because the tracker keys live allocations by pointer: reusing a range across
  tests made a `free()` erase another test's live allocation and corrupted the
  baseline.

## Validation

- `pytest tests/test_unit_gguf_prefix_arena_reclaim.py
  tests/test_unit_int8_mtp_teardown.py tests/test_unit_gguf_device_kv_binding.py`
  -> 21 passed.
- Mutation check, to confirm the cases pin the contract rather than passing
  vacuously: making `_GGUFPrefixSnapshotArenaPool.close()` retain its arenas
  instead of closing them fails three cases, including
  `test_prefix_arena_pool_reclaim_leaves_no_live_allocation`. Source restored
  immediately; `git diff` clean afterwards.
- One case initially failed and the failure was the test's own bug, not the
  pool's: an arena still acquired at `close()` time is legitimately live, so
  the case now returns it before the final reclaim. Recorded because it is the
  distinction the item is about — ownership follows the holder, not the pool.
- No RED phase: no defect was found in the pool, so these are regression tests
  for existing correct behaviour.
