# the gemma4 assistant head's KV binding is the backbone's last two layers

## Summary

The gemma4 MTP head's forward was fully specified except for one question: the
head's four blocks create no `attn_k` and no `attn_v`, so which KV do they
attend against? It is resolved, and the answer is short enough to implement
directly.

From `llama.cpp@17252c769`, `src/llama-model.cpp` around line 2578:

```c
if (arch == LLM_ARCH_GEMMA4_ASSISTANT) {
    llama_memory_t mem_other = llama_get_memory(cparams.ctx_other);
    share = [&](int32_t il) {
        const llama_model * model_other = llama_get_model(cparams.ctx_other);
        if (hparams.is_swa(il)) return llama_model_n_layer(model_other) - 2;
        return llama_model_n_layer(model_other) - 1;
    };
    res = new llama_kv_cache_iswa(..., mem_other, filter, reuse, share);
}
```

With a 30-layer backbone: **a sliding-window head block reads backbone layer 28
and a full-attention head block reads backbone layer 29**. The head's K/V
tensors are views, not copies — `llama_kv_cache` pushes a copy of the *layer
struct* for a shared layer, so `k`/`v` point at the same device buffers the
backbone wrote. `attention.shared_kv_layers` is read in `load_arch_hparams`
and never used in `load_arch_tensors`, which is why a loader-side search for it
finds nothing.

The port consequence: the head needs **no KV allocation, no eviction policy and
no `KVLiveSpans` plumbing**. It needs read access to two of the backbone's KV
layer buffers by index, and the draft step's position has to agree with the
position the backbone last wrote. That removes the largest piece of work the
port looked like it would need.

Two other details were read off the reference while confirming this and are easy
to get wrong:

- `hparams.f_attention_scale = 1.0f`. The head does **not** apply
  `1/sqrt(head_dim)`.
- The norm order is **post-norm** for the attention and FFN outputs:
  `post_attention_norm` normalizes the attention output *before* its residual
  add, and `post_ffw_norm` does the same for the FFN. Only `attn_norm` and
  `ffn_norm` are pre-norms.
