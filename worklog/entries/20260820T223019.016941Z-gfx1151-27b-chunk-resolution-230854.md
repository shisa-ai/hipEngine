# Resolve 27B prefill chunk 512-vs-1024 on the 140W gfx1151 lane (null)

## Summary

The ZBook handoff deferred the Qwen3.6-27B (H5120 dense) prefill chunk
512-vs-1024 question to the 140W gfx1151 system because the 60W ZBook cannot
pin clocks and its ~10% clock-band swing swamped the verdict. On this desktop
gfx1151 (`power_dpm_force_performance_level=high` is honored; sustained-load
sclk ~2680-2800 MHz, per-leg swing ~0.8-1.1%) the interleaved protocol
resolves the question as a **null**: chunk size has no measurable effect on
27B dense prefill at 2048 tok, and the retained 35B 512-override "~1.2% win"
does not reproduce on this lane.

## Changes

- Added `scripts/pn3_27b_chunk_resolve.py`: single resident session per
  model, chunk changed in place by mutating `prefill_config` (the runner reads
  `linear_chunk_size` per call, no per-leg model reload), interleaved
  counter-rotated legs, per-leg sclk sampling, thermal pre-warmup,
  `force_high` per leg, and an optional `--no-override` monkeypatch that
  bypasses the H2048-MoE 512-row geometry override so the 35B leg is a true
  512-vs-1024 positive control.
- Fixed `/home/lhl/hipEngine` -> `/home/lhl/hipEngine-main` in the four
  handoff scripts (`pn3_clock_probe.py`, `pn3_27b_chunk_pinned.py`,
  `pn3_aotriton_prefill_isolate.py`, `pn3_moehoist_lib_ab_probe.py`).
- Documented the resolution in `docs/GFX1151-TUNING-LANDSCAPE.md`
  (chunk-policy bullet) and `benchmarks/CHANGELOG.md`.
- Artifact: `benchmarks/results/2026-08-21-gfx1151-27b-35b-prefill-chunk-512-vs-1024-null.json`.

## Validation

- Command (same-host, both models, L=2048): `uv run python
  scripts/pn3_27b_chunk_resolve.py --reps 6 --n-timed 2 --length 2048
  --no-override`.
- Hardware: desktop AMD RYZEN AI MAX+ 395 / Radeon 8060S, gfx1151, 40 CU,
  ROCm/HIP 7.15.0, 128.8 GB shared GTT; perf level forced `high`.
- 27B dense: 512 = 45487 ms median vs 1024 = 45413 ms (12 legs each),
  delta +0.16%, clock swing 1.1% -> null (INCONCLUSIVE within noise; legs
  45590/45551, 45613/45601, 45611/45649, 45368/45327, 45299/45350,
  45251/45292).
- 35B-A3B control (override bypassed): 512 = 9822 ms vs 1024 = 9824 ms,
  delta -0.03%, clock swing 0.8% -> null. The retained ~1.2% 512-win does not
  reproduce on the 140W lane (measured on the 60W ZBook below its ~10% noise
  floor; per the handoff lane policy absolute rates never transfer).
- Found: the 60W `pn3_27b_chunk_pinned.py` 35B sanity leg was a 512-vs-512
  no-op — `_gguf_prefill_chunk_sizes_for` forces (512,512) for the H2048-MoE
  geometry at session init, replacing both configured chunk sizes. This
  explains why the ZBook sanity leg "failed to resolve even the known 1.2%
  35B effect" beyond clock noise.
- Clock probe (`scripts/pn3_clock_probe.py`): 35B prefill steady ~9707-9733 ms
  at 2780-2800 MHz / 95% busy with the pin; trajectory confirms no 2900->band
  collapse like the ZBook.
- No correctness gate needed (wall-time only); chunk-boundary correctness was
  already established exact (KL 0.00013) in the retained 512-override artifact.
