# Separate GGUF concat pair launch planning from execution

## Summary

`launch_gguf_linear_pair_concat` now resolves a private, single-use `_GGUFConcatPairPlan` and executes it immediately. The plan covers the three existing operations: Q8T16 rows1 split outputs, Q8T16 rows>1 row-strided concat, and raw Q8 WMMA concat. It carries only geometry, exact weight operands, operation, resolved thread selection, and fallback reason.

The public signature and boolean return are unchanged. The rows1 path still computes the exact second-half output pointer as `out_ptr + out_features * DType.BF16.itemsize`; rows>1 still uses the single-buffer concat ABI. Dispatch priority, WMMA decline, raw-Q8 gate checks, direct symbol ownership, and exact kwargs are preserved. The main pair plan was not extended.

- `hipengine/runtime/gguf_linear.py`

  - Execution binds the exact weight objects and rejects a foreign owner before launching.
  - Pointers and direct callables are read only at execution.
  - No cache, public reuse API, flag, library kwarg, or generic shape/allocation revalidation was added.
