# Qwen4Exp status doc: the journey-start rate is a composition difference, and the default is the wide route

## Summary

Two things in `docs/QWEN4EXP-STATUS.md` were wrong about the current state, and
one of them mattered to the campaign's headline number.

**The header named the wrong default.** It still said the production default was
the f16 WMMA dense prefill scope at 16-47 since `04f1dde42`; since `15b056111` the
default is the wide-row route (`PRODUCTION_Q8_DENSE_WIDE_PREFILL_LAYERS`) and that
env var is bound empty for this quant.

**"294.1 tok/s in 1.1 and 183.6 in 1.2 are the same engine on different
protocols" was not true.** Both rows are `qwen4exp_canonical_ar_bench` with an
identical recorded protocol (12 cases, 128 decode transitions, chunk1024, warm
PLE, one warmup, three measured repetitions, the same timing-boundary string),
the same fixture (`sha256 42b562bd8e9644be…`) and hash-identical prompts
(`4ea99919…` at `code-p512`). On identical inputs the two rows differ by **1.60x**
(1723 ms against 2760 ms for the same 512-token prompt). The cause is arithmetic:
the 2026-09-13 row was measured at `00602e556`, where the production binder still
bound fifteen arithmetic-recovery flags **on** for `gguf_ud_q4_k_xl`
(`Q8_MMQ_PREFILL`, `GR_IU8`, `GR_IU8_DOWN`, `Q8_IU8_WMM`, `Q4_IU8_PREFILL`,
`GDN_COLWARPS_PREFILL`, `QSA_FLASH_PREFILL`, …), and
`2026-09-14-q8-prefill-numerics` measured that composition's prefill at max KL
`0.0546` — a failed envelope. `49ffa3cb5` then zeroed all fifteen. The magnitude
is consistent: §2.4 measures the overlapping subset alone at +7.808 s on
`code-p4096` (23.648 → 15.840 s).

So the row is neither a protocol difference nor a regression: it is a
**composition difference**, and it is not a rate for the path we ship. It now
says so, and §5 item 1 carries what the HEAD re-measurement must compare
(`prefill_ms` case by case, against a row whose raw per-case walls are not
committed — only medians survive, because the run file was `/tmp/...`).
