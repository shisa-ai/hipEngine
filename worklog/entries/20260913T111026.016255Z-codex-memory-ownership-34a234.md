# Fix owned host uploads and validate cached decoder isolation

## Summary

Reviewed the reported TimesFM, Evie, and Qwen35 GGUF memory hazards on synced
main, independently of the stopped Surya branch. Fixed array-owner lifetime,
TimesFM 2.5 request recovery, Evie mutable-state clearing, and redundant Evie
pointer-table uploads. TimesFM 3's initialized q_offset is a read-only constant;
poisoning it did not establish a request-state bug and no per-call reset was added.

Switched to main after fetching origin. Local main contained two documentation
commits absent from origin/main, so a clean merge (12672962b) preserved them and
incorporated origin/main at 8c74592c2. Surya commits were not cherry-picked.
Existing untracked cospa/, zbook/, and debug scripts were left untouched.

## Changes

- Added copy_host_array_to_device: retain the array through synchronous H2D,
  reject noncontiguous sources, and check source and destination bounds. Copy
  only source bytes by default, including when destination has padding. No
  NumPy import in core and no additional device-wide synchronization.
- Converted all nested call-expression host_array_ptr sources in the four
  reviewed runtime modules. Some ascontiguousarray calls currently return an
  already-owned array; the conversion makes allocating and no-copy cases safe.
  Existing named locals held through synchronous copies need no pinned-staging
  workaround. Asynchronous copies have a separate ownership contract.
- TimesFM 2.5 clears K/V caches on the consuming default stream at decode entry.
  Finite request-history cases already passed before the fix; a nonfinite prior
  forecast contaminated the next valid forecast in both fp32 and fp16. The
  regression uses actual decode calls, without device poisoning.
- Evie initializes single-query and segmented convolution/recurrent state with
  byte clears instead of x * 0. The latter preserves NaNs. The regression dirties
  only mutable per-layer state and checks finite, byte-identical embeddings.
- Evie pointer lists upload on cache miss only. A named local already protected
  the source lifetime here; repeated upload was redundant, not the reported
  asynchronous lifetime defect. Unit coverage asserts ordered pointer contents
  and two uploads for two distinct lists, even when one list is reused.
- Added a bounded syntax guard for temporary pointer sources in these four
  modules, weakref ownership and bounds tests, and real-device temporary-upload
  and immediate source-reuse coverage. Updated the affected GGUF unit mock.
- Added TimesFM 3 same-runner finite/nonfinite history coverage, and Qwen's real
  fused multi-entry state-copy coverage with changing source pointer order and
  dirty destinations. It asserts the fused path actually ran; single-session
  direct-commit coverage alone does not establish that.
- Documented synchronous upload ownership and mutable-state initialization in
  docs/KERNELS.md. No new kernels, arithmetic variants, flags, or dependencies.
