# R0523 rocprof: actual GDN kernels are indexed per-slot (no cross-row race); state prep/ordering is owner

## Summary

rocprofv3 kernel-trace of the EAGER packed c4 step (bg-169) corrected the static
dispatch assumption: the GDN decode actually uses the INDEXED per-slot kernels, not
the chain-journal kernels inspected earlier. All GDN kernels are one block per
(row, head/channel) with per-slot state via state_indices[row]; state_indices is the
identity [0,1,2,3]. No cross-row race exists inside these kernels. The intermittent
owner is therefore the per-slot state PREPARATION / reuse / commit ORDERING, not the
GDN arithmetic. No production behavior changed; diagnostics env-gated, uncommitted.

## Changes

- No new production change; added run-r0523-rocprof-eager.sh (diagnostic harness).

## Validation

Measured (rocprofv3 eager c4, /tmp/refactor-gfx1100/r0523-rocprof-eager/c4/trace/epyc/309886_kernel_trace.csv):
- GDN decode kernels: qwen35_linear_attn_conv_decode_indexed_lowp_kernel and
  qwen35_gdn_recurrent_rmsnorm_gate_indexed_lowp_kernel<u16,0,float> (STATE_CACHE_ROWS=0).
  Both: row=blockIdx, state_slot=state_indices[row], per-slot state offset; one block per

- Attention = context_tensor_batch_kernel<true,2,false,long,1> (the line-358 kernel, inspected clean).
- Single profiled transition was byte-exact (race is intermittent, not expected every step).
