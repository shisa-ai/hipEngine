# DE-6 closes: its precondition came back false, and the refuted figure it carried had its correction in a neighbouring row

## Summary

Scanning the remaining actionable rows for the `Q8_IU8_WMM` pattern — a *measured*
number whose disposition had gone stale — turned up a worse instance than that one,
because this time the correction already existed and simply had not reached the row
that needed it.

`DE-6` is "PM4 / retained command lists", whose cell asserted, as **"the governing new
number for this row"**:

> "DECODE IS NOT KERNEL-BOUND: the unprofiled wall for the same transition is median
> 153.0 ms, so the kernels are only ~35% of a decode step and ~65% is host/launch
> overhead … the runtime side is larger than the device side for a decode step."

**That figure had already been refuted — in `DE-5`'s cell**, a neighbouring row that has
since been closed. `DE-6` is OPEN, so the reader who most needs the correction was
reading the one place it was not.

## The refutation, from the artifact

`benchmarks/results/2026-09-29-qwen4exp-de5-host-overhead-correction/README.md`:

- **It is a cross-run subtraction.** The 153.04 ms wall comes from `decode-warmup.json`
  (`profile: false`, `role_markers: false`) while the 54.218 ms kernel sum comes from
  `decode-profiled.json` (`profile: true`, `role_markers: true`) — whose **own** wall
  median is **225.79 ms**, not 153.0. Subtracting a kernel sum measured in one
  instrumentation state from a wall measured in another is not a decomposition.
- **The same host, model and case decode at 19.134 tok/s = 52.26 ms/token**, which is
  **1.04x** the profiled kernel sum. So the kernel sum agrees with the true step time and
  **the harness's wall is the outlier, inflated ~2.93x**. A 2.93x regression between
  09-13 and 09-29 would be a headline event; `benchmarks/CHANGELOG.md` records only
  improvements in that window.
- **The row's stated target is measured negligible**: the entire synchronous-copy budget
  is **10.2 KiB per step** (~15 µs, ~0.03% of a 52.26 ms step).
- The real remaining host target is `DE-5`'s scope: the wrapper's **~3.6 ms/token**
  (logits D2H, sampling, bookkeeping) = **~6.9%** of a step.

## The precondition, evaluated

`DE-6`'s own First-bounded-experiment column reads *"Only if `X-4` shows an exposed
submission bucket above those gaps."* `X-4` has now been evaluated and there is no such
bucket. Its runtime census, identical across all three repetitions, gives the whole
per-step submission budget as **3 synchronous `memcpy` (10,440 bytes), 12
`memcpy_async` (6,144), 1 `memset` (16) and 48 `graph_launch`** — so the submission path
is **already graph-replayed at 37 kernels per launch**, and `DE-5`'s mechanism cell
records the direct measurement that settles it: *"Layer graphs are measured negative: the
launch host time is already overlapped."*

A retained-command-list or PM4 mechanism would reduce the host cost of 48 launches whose
host time is **already overlapped**, and the 1.35-1.43 ms intra-graph gaps this row names
are **inside** the graph, which retained command lists do not change. So the precondition
is not merely unmet: the bucket that motivated the row was an artifact.

**`DE-6` is closed.** The actionable count falls **20 → 19**.

## The transferable finding, recorded in the census

This is the worst documentation defect found in this campaign so far, and it is a
*class*, not an instance: **a closed row's correction does not reach an open row that
quotes the same measurement.** The census note now says so explicitly — where a shared
measurement is refuted, the correction belongs in **every** cell that quotes it. The
three earlier corrections in this series (GD-1, PL-1, X-7) were all rows that had not
been read against their own evidence; this one is a row that had been corrected
*elsewhere*.
