## Changes

- In-repo kernel work (boundary updated since fork: kernel R&D is now allowed in this tree; AGENTS.md kernel-R&D-in-parent rule intentionally NOT edited to avoid fork merge conflicts). Target chosen from a c8 decode-phase `rocprofv3 --kernel-trace` differential (per-step = (d40-d8)/32, profiled/inflated but distribution-reliable): top decode kernels = MoE expert GEMV `gemv_awq_selected` ~16.1 ms (divergent routing, hard), full-attn ~11.0, **dense dual proj `gemv_awq_dual_pack8` ~9.1**, lm_head `w8a16_linear` ~8.9, GDN recurrent ~5.8, **dense single proj `gemv_awq_pack8` ~5.3**, marlin-K proj ~5.0. The dense projection GEMVs read a single shared weight per c columns and reload it per column → the tractable output-tiling win.
- Implemented `gemv_awq_pack8_output_tiled_kernel<scalar_t, qweight_transposed=false, int C>` (hipengine/kernels/hip_gfx1100/quant/paro_awq_gemv.hip): grid `(out_packed)` (no x_rows axis); one block loads each weight pack ONCE and FMAs it into all C columns via `acc[C][8]` register accumulators. Per-output accumulation order over k and across warps (within-warp `__shfl_down` 16..1, then ascending-warp cross-warp sum through `xchg[4*C*8]` LDS) is identical to the per-row `gemv_awq_pack8_kernel`, so results are byte-identical. Templated/launched for C in {2,4,8}; extern "C" `hipengine_gemv_awq_pack8_output_tiled_bf16/fp16`; Python wrappers `gemv_awq_pack8_output_tiled_bf16/fp16` reusing `_launch_pack8_single`.
- Correctness gate (RED/GREEN): new `tests/test_paro_awq_output_tiled_gemv.py` feeds both kernels identical random AWQ pack8 inputs and asserts byte-exact equality (no tolerance/CPU-ref needed — bit-exact equivalence transfers the strided kernel's existing cpu_reference validation). **48/48 PASS** — rows {2,4,8} × shapes {(256,2),(512,16),(2048,4),(4096,8)} × threads {64,128} × {bf16,fp16}, all byte-identical to `gemv_awq_pack8_strided`.
- Caveat/lesson: a `rocprofv3`-wrapping-`pytest` smoke hung ~2h because the profiled process ran under a therock `PATH`, missed the JIT cache (cache key includes compiler version), and tried to rebuild — `clang++ --version`/`hipcc --version` probes hung (cleared 13 stuck probes, some ~24h old). This is exactly the AGENTS.md "prebuild outside the profiler; never let the profiled process spawn hipcc/clang" rule. Kernel-trace smoke deferred to the integration step, where the kernel appears in the existing safely-captured decode profile. The bit-exact test is the correctness gate.
- Correctness-only milestone; the kernel is not yet wired into the decode path and NO throughput claim is made. Next: integrate behind the c>1 dense projection dispatch (no backend/quant branches), validate generated tokens byte-identical + teacher-forced KL/top-1, then measure c2/c4/c8.
