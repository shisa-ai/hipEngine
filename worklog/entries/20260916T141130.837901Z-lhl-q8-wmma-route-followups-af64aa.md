# Q8 WMMA prefill route: perf-first ordering, provenance paths, binder conflict

## Summary

Follow-up unit to the layer-scope gate committed as `09bf140c8`. A review of
that gate's artifacts found three things that change what should be measured
next, and two reporting defects in how the existing numbers were read.

The ordering correction is the important one. The gate certified the numerical
envelope of `wmma_prefill_f32_f32_out`, selected by
`HIPENGINE_QWEN4_EXP_Q8_WMMA_LAYERS`. That selector is **not** one of the nine
families in the 2026-09-16 recoverable-prefill-time ranking, so the route has no
measured speed at any layer scope. The `+6.614 s / 1.388x` headline in that
ranking belongs to `HIPENGINE_QWEN4_EXP_Q8_IU8_WMM` →
`iu8_wmma_prefill_f32_f32_out`, a different variant with different arithmetic
(`hipengine/runtime/gguf_linear.py:2818`, gated on `rows > 256`).
`docs/REFACTOR.md` additionally records the gated selector as superseded for the
named production profile by the MMQ stack. So the plausible outcome is a route
that passes the envelope at layers 32-47 and buys no time. Perf is measured
before any further numerical work on it.

Two reporting defects in the committed write-up:

- The prefill `max |Δlogit|` pair quoted as `1.86 / 1.34` crosses category sets
  (12 cases over 4 categories versus 3 code-only cases). The controlled
  code→code pair is `1.0028 → 1.34`.
- The "prefill distribution unchanged but logits not identical" open question is
  answerable from the committed artifact and does not need a kernel census. The
  `prefill_last` scope has `strict_margin_min` 14.67 against `steady`'s 0.0021,
  so a 1.86 logit perturbation cannot move that distribution. The prefill row
  also carries the *largest* `max_abs_logit_delta` in the run, which refutes the
  "prefill is not taking the candidate arithmetic" branch outright: a bypassed
  route returns a zero delta. What a census would still establish is coverage,
  not liveness.

## Changes

- `hipengine/benchmark/provenance.py`: artifact provenance schema 3. Records
  `dirty_paths`, `dirty_path_count`, `untracked_paths`,
  `execution_affecting_dirty`, and `execution_affecting_paths` alongside the
  three existing boolean axes. Adds `is_execution_affecting()`, a denylist
  classification so an unrecognised path counts as execution-affecting and only
  prose/evidence trees (`docs/`, `worklog/`, `benchmarks/results/`, `*.md`) are
  excused.
- `benchmarks/schemas/artifact-provenance.schema.json`: schema_version enum
  extended to 3; new fields required at version 3; the `host_name` branch now
  keys on `minimum: 2` rather than `const: 2`.
- `scripts/execution_profile_q8_wmma_prefill_layers_gate.py` and
  `scripts/execution_profile_q8_mmq_plane_gate.py`: `measurement_valid` and the
  qualification blocker now key on `execution_affecting_dirty` rather than the
  coarse `dirty`, with the blocker renamed to
  `execution-affecting worktree provenance`.

Motivation for the provenance change: both arms of the committed gate record
`measurement_valid: false` on tree-state grounds alone. The 32-47 arm that
passes every numerical gate additionally records `unstaged_dirty: true` with
`untracked_count: 5`, so it is not only the untracked `docs/superpowers/`
directory named in the hand-off — a tracked file was modified during that run
and the artifact does not say which. That is unrecoverable after the fact, which
is the defect being closed. Under the coarse rule, any concurrent agent's
scratch file invalidates every measurement in the tree.
