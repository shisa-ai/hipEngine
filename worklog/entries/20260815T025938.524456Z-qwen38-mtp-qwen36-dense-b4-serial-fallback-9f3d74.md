# Repair dense B4 target fallback exactness

## Summary

Supersedes the native-target-fallback portion of
`20260815T024338.527559Z-qwen38-mtp-qwen36-dense-b4-mtp-admission-21aa36.md`.
The first full gate proved that eager root+four native rows can change greedy
outputs even though GPU and CPU acceptance agree on those batched logits. B4
now uses the scalar `serial_exact` target oracle; B1-B3 and B4 tail cycles retain
their existing native graphs.

## Changes

- Added an effective target-mode policy: a requested native verifier falls back
  to `serial_exact` only when the physical target batch exceeds four rows.
- Made that serial fallback take a consumer-owned initial state snapshot even
  when the verifier's B1-B3 configuration normally delegates the snapshot to
  the native producer graph. This preserves rollback on serial errors and
  partial/reject commits.
- Updated the refactor ledger to record the rejected native rows=5 path and the
  real serial-exact B4 seam.
- Added RED/GREEN tests for rows=5 effective-mode selection and the forced
  consumer snapshot.
