## Changes

- `inkling2_residual.hip`: `inkling2_residual_update_rows<ROWS>`, entered through
  `hipengine_inkling2_residual_update` and registered as
  `inkling2_residual/inkling2_mixed/residual_update` on both HIP backends. One block per (row,
  query) forms h, its square sum and the stack row in registers, then the `ROWS` dot products in
  one pass over the query, one block reduction for all of them, and the weighted read. Each value
  keeps the reduction tree of `inkling2_row_add`, `inkling2_row_rms` and `inkling2_residual_read`.
  Row counts above eight fall back to a kernel over the stored rows.
- `inkling2_residual.hip`: `hipengine_inkling2_row_norm_mul_group`, registered as
  `row_norm_mul_group`: one or three input normalizations in one launch, one block per (input,
  row), each row the arithmetic of `inkling2_row_norm_mul`.
- `hipengine/runtime/inkling2_gguf.py` uses both when the backend registers them and keeps the
  separate launches otherwise. A local visit normalizes one input for all three projections.

The first version of the fused step was not bit-identical: unrolled, each copy of `expf` was
optimized on its own and some exponentials differed from the separate kernel by one unit, which
moved every depth weight with them (tokens diverged at 2,057 input). The loop over `expf` stays
rolled.

## Validation

- `tests/test_gpu_inkling2_residual_update.py` (20 passed on the W7900): the fused step equals add,
  stack row and read for 0, 1, 4, 7, 8 and 11 stack rows (eight rows is the largest templated count,
  more take the many-rows kernel), 1, 2 and 3 queries, with and without the add; the grouped norms
  equal the separate ones for 1 and 3 inputs over 1 and 4 rows; all bit for bit.
- A direct comparison over 84 shapes (1 to 7 stack rows, 1, 2, 3 and 5 queries, three seeds) found
  no mismatching element.
- The Inkling GPU and unit test files pass on the W7900: 379 passed, 5 skipped.
- The public route ran both kernels in the bench above: resolved profile `fast`, no fallback, the
  same 128 output tokens at every depth as the committed tree.
- A `rocprofv3 --kernel-trace` of the graph and resident arms (47 and 1,717 prompt tokens, 33
  outputs each; `/tmp/inkling-fuse-u4/e`) shows `inkling2_residual_update_rows<2>` to `<5>` at
  8.0 to 10.2 microseconds median with 48 to 64 vector registers and no scratch memory, and
  `inkling2_row_norm_mul_group` at 5.9 microseconds. `inkling2_residual_read` no longer appears.
- The public arm's distance to the 15:30 run of `ec2fa6d32` is machine state, not code: that tree
  run again at 19:09 reads 17.69, 17.58 and 17.20 tok/s, against 18.13, 17.98 and 17.56 at 15:30.
  A second agent session shares the host. Runs compared in one table above were taken minutes
  apart.
