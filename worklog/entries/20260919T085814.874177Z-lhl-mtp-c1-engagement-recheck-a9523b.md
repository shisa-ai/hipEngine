# c=1 MTP engagement re-verified at b25740a50 on the external porting protocol

## Summary

The external porting record (`~/atlas/docs/porting/QWEN38_STRIX_PORT.md`) had a
2026-09-18 section claiming hipEngine's c=1 MTP route engages and beats its own
AR baseline, measured at `f46912963`. That record was 50 commits stale, and the
intervening work changed route resolution (a new breaker fallback, an EOS
admission probe, the staged linear-attention promotion) — every one of them on
the path that decides whether a request speculates. Re-ran the record's own
client and protocol at the current revision to answer whether the c=1 rows still
hold.

They do, within noise and slightly better. Same box, same client, same shapes,
one `auto`-policy server load for all three arms (the 2026-09-18 table used
`enabled` for the explicit row and `auto` for the default row, so it needed two
loads):

| hipEngine arm | 512/128 | 1024/128 | 4096/128 |
| --- | ---: | ---: | ---: |
| request `speculative_mtp: false` | 11.98 | 11.83 | 11.06 |
| request `speculative_mtp: true` | **20.08** | **17.98** | 11.03 |
| no request field (`auto` default) | **20.09** | **17.97** | 11.03 |
| 2026-09-18 rows, same protocol | 20.01 / 19.98 | 17.84 / 17.81 | 10.95 / 10.94 |

Ratios against the matched in-load AR control: **1.676x at 517 prompt tokens,
1.521x at 945**, 0.998x at 3,530. Every CV is at or below 0.09% and the AR
control reproduces the 2026-09-18 AR row (11.90) to within 0.7%.

A non-streaming route probe on the same load confirms engagement rather than
inferring it from the rate: 517 and 945 tokens report
`effective_route=speculative_mtp` with 55 and 23 cycles at 0.442 and 0.818
acceptance, while 3,530 tokens still declines inside the adapter's 1,023-token
qualified window (selected `speculative_mtp`, effective `default`,
`decision_reason=backend_k0_fallback`) — so the 4096 row is an AR row by design
and not a regression. The arms' first 600 generated characters are byte-identical
on all three shapes.

The external record now has a 2026-09-19 section with these rows and with the
breaker behavior change from the same revision (an open MTP scope resolves to AR
and reports why instead of returning 503). That file lives in another repository
and is left uncommitted there; the claim is retained in-tree through the artifact
and the changelog line.
