# 2026-07-20 — Reject exact Q8 wave-scale broadcast and close local scheduling

## Changes


- The shared gate/up pair was bounded before implementation: at the existing 64-accumulator limit, a dual 8+8x4 block has exactly the same total block count, activation loads, weight loads, and arithmetic as two retained 16x4 leaves; it can only remove at most 40 of 8,705 launches. A dual 16+16x4 block would require 128 accumulators, beyond the already VGPR136 one-block 16x4 leaf. No launch-only composite was added.
- RED then imported a missing exact 16x4 wave-scale wrapper and failed collection. The temporary candidate decoded each Q8 FP16 block scale only in lane zero and broadcast it while preserving every lane's int8 byte and FMA/reduction order; registry plus two primitive shapes were BF16-bit exact.
- Production measurements rejected it immediately: all nine `(rows,K,N)` shapes regressed 38.77–191.80% with zero mismatches. The cache-only symbol remained local128/VGPR136/LDS1KiB/scratch0, proving the regression is the sixteen added wave shuffles per K iteration rather than a spill. Removed all candidate code/tests and restored tracked sources byte-for-byte to `2e2a97a3`. Artifact: `benchmarks/results/2026-07-20-gpu1-q3-exact-q8-wave-scale-rejected.json`.
- Dense-Q8 local geometry/codegen is now closed at exact 16x4 absent a new profile-backed premise: 8x8, 32x2, and wave-scale broadcast all lose, while shared-pair fusion has no material traffic or launch-count bound. Task #24 moves to exact GDN, the next measured family at `1,310.186 ms` / 20.43%.
