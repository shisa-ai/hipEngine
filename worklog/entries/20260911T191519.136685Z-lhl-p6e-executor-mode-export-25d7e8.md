# The P6e decline names its reason: the packed plan is built with no executor_mode, so chunk-outer ran

## Summary

Task #25 step 1. The previous entry proved the layer-outer route does not engage in
the service, but could only *infer* why: it reasoned from an empty
`fallback_reasons` counter, which names no reason. The engine already computed the
answer and dropped it on the floor.

`last_packed_prefill_plan.executor_mode` is collected per session
(`qwen35_gguf.py:264`) into `last_packed_executor_modes`, and the comment two lines
above it states why the field exists:

> The layer-outer executor records its distinction in executor_mode; route alone
> cannot distinguish it from the chunk-outer fallback (reviewer finding 4,
> 2026-09-10).

That value never reached `/metrics`, so the one field built to answer this question
was unobservable from the service.

## Changes

- `hipengine/server/api.py`: the resident `prefill_transients` block now carries
  `executor_modes`, and the Prometheus renderer emits
  `hipengine_resident_prefill_executor_mode_total{mode="..."}`. A new
  `_string_value_counts()` helper counts distinct strings, maps an unset entry to
  `"none"` so it stays visible, and returns empty for a non-list so an absent field
  emits no sample rather than a fabricated zero.
- `scripts/gguf_p6e_cancel_refill_proof.py`: a new `_labeled_metric_values()` reads
  one family label-aware. The existing `_metrics_values()` sums across labels,
  which is right for totals and is precisely what destroys this information. The
  engagement gate now carries the observed modes so a red gate reports what ran.
- Tests: the server fixture gained a `last_packed_executor_modes` entry with an
  assertion for both labels, plus unit tests for the count helper (duplicates,
  unset entries, absent/non-list input) and for label escaping through
  `_append_labeled_counter_metrics`, including a mode string containing a quote and
  a newline. The harness gained tests that the gate reports the observed modes on
  failure, can still pass when `layer_outer_packed` is observed, and that
  `_labeled_metric_values` keeps the label while ignoring other families.

## Honest limits

- `executor_modes` says which executor ran, not which precondition declined. It
  does not by itself distinguish "the layer-outer flag was not consulted on this
  call" from "the `int8_direct` `kv_attention_source` requirement failed" from
  "the call was single-chunk". Narrowing that needs the entry condition
  instrumented, which this unit did not do.
- The string `"None"` is the engine's own representation (`str(None)` on an unset
  plan key). It is unambiguous but inconsistent with the `"none"` the new count
  helper produces for a genuinely absent list entry. Changing the engine's
  spelling would alter an existing diagnostic, so it was left alone and the
  distinction is documented here instead.
- The gate reads a settled scrape after the long request returns, so it reports the
  last plan the sessions recorded, not a per-request history. A run that engaged
  the layer-outer route early and fell back later would read as engaged.
