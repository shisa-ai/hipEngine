# Qwen4Exp AR batch width-4 numerical protocol check

## Summary

The evaluator now scores the AR batch candidate and enforces a separate
admission-scope gate. The complete 18-prompt width-4 run used a **shortened
8-step horizon**: 162 teacher-forced rows, not the normative 450. It passes the
hard numerical gates, but p95 KL is `4.845e-3` against `5e-3` (3% margin), the
`mixed_ja_en` category mean is `1.554e-3`, and the task gate is
`requires_review` (17/18 strict-exact; one deterministic free-run divergence).
The single top-1 mismatch is a near-tie inside the flip-eligible set and is not
by itself a task failure; the free-run text divergence is the review item.

The candidate is also **not admission-eligible on manifest binding**. The c1
profile manifest has 28 selections and none of the six batch path identities:
GDN rowsplit-indexed recurrence, indexed conv, QSA mixed mixer, batch-span KV
write, batch-span decode, and batch PLE. The new eligibility check classifies
that as not admitted. A clean 8-step run cannot be admitted regardless of tree
state, and the existing full-suite artifact predates the check.

## Changes

- `scripts/qwen4exp_ar_batch_candidate.py`: new adapter. Prefill stays on the
  committed c1 runner, one request at a time, and is imported once per request;
  every recorded decode row is one genuine N-row `owner.step`. Composition is
  fixture-order chunks of `width` with the final chunk at natural width.
  Ownership is enforced (distinct slot and owner token, import position equals
  prompt length, position after every step equals `prompt_len + step`), and the
  reservation covers prompt plus teacher-forced length. Width-4 reservations
  are capped at the qualified 2048-position bound. The slot-state fingerprint
  covers live KV blocks, index keys/counts, GDN conv/recurrent rows, PLE
  history, and PLE n-gram history. `BATCH_PATH_IDENTITIES` records the six
  direct-call batch identities and `batch_manifest_binding()` checks whether a
  profile manifest names them.
- `scripts/qwen4exp_layer2_profile_gate.py`: new `ar_batch` candidate,
  `--batch-width`, `--limit-per-category`, and `--protocol-check`. Decode rows
  are labeled by the width they actually ran at (`batch_w4` / `batch_w2`), not
  by the configured maximum. The batch state gate checks repeat determinism,
  layout stability, position against the strict teacher, metadata shape, and
  per-group state distinctness instead of byte equality to the different c1
  layout. `--protocol-check` allows an uncommitted tree and exits 0 on a sound
  protocol run; it cannot mark the candidate admitted.
- New `batch_admission_eligibility()` requires the full named 18-prompt fixture
  with no `--limit`/`--limit-per-category`, at least 24 decode steps (450
  rows), 3 repeats, 32-token free outputs, 2 free runs, a clean tracked tree,
  and a manifest that binds every batch path identity. `status=ineligible`
  reports a non-protocol run that misses the scope; the artifact carries the
  reasons under `admission` and `decision.admitted=false`.
  `batch_admission_decision()` also refuses a short run even if a caller
  wrongly reports `measurement_valid=true`.
- `scripts/execution_profile_gdn_calibration.py`: `build_candidate_quality`
  accepts optional `shape_for_step` / `transition_for_step` callables of
  `(step, prompt_id)`; defaults preserve the c1 labels.
- `tests/test_unit_qwen4exp_ar_batch_candidate.py`: 18 CPU tests for
  composition, ownership/import failures, poisoned-step teardown, free-run
  feeding, the batch state gate, and per-prompt row scopes.
- `tests/test_unit_qwen4exp_ar_batch_admission.py`: 14 CPU tests for the
  normative scope, dirty/subset/limited prompt sets, short repeats/free
  lengths, c1-only vs batch-bound manifests, and the admission decision.

## Next

No further model campaign was run after the review. The parent chooses the
launch. The full admission command, one width at a time, is:

```bash
for W in 1 2 4; do
  python3 scripts/qwen4exp_layer2_profile_gate.py \
    --model-root /models/gguf/unsloth-Qwen3.8-Flash-Next-UD-Q4_K_XL/UD-Q4_K_XL \
    --candidate ar_batch --batch-width "$W" \
    --decode-steps 24 --repeat-runs 3 --free-tokens 32 --free-runs 2 \
    --output "benchmarks/results/2026-10-18-zbook-qwen4exp-arbatch-w${W}-admission.json"
done
```

It requires a clean committed tree, no `--limit`/`--limit-per-category`, and a
profile manifest that binds the six batch identities; with the current c1
manifest each run will report `status=ineligible` for those missing bindings.
Observed runtime: the 18-prompt/8-step width-4 run took 151 s wall including
model load. The 24-step/32-token run does 3x the teacher-forced steps and 4x
the free tokens. The strict pass is identical across widths, but the candidate
step-call count grows with the number of composition groups: 360 teacher calls
at width 4 (5 groups), 648 at width 2 (9 groups), and 1,296 at width 1 (18
groups), before free runs and state fingerprints. Expect roughly 5-8 min for
width 4, 6-10 min for width 2, and 10-15 min for width 1 on this host. These
are estimates from the observed 8-step run, not measured 24-step times.

Remaining review items before promotion: the `code_topological_sort` near-tie
and deterministic free-run divergence, the `mixed_ja_en` mean, the width-2
tail, the manifest binding for the batch path, then contexts above 2048,
ragged AR+MTP physical batching, poisoned-step recovery under load, and the
scheduler/default decision.
