# Acknowledge shutdown queued during fatal driver cleanup

## Summary

A fatal request error can reach the caller before the driver finishes cleanup.
If the caller closes the service in that interval, it enqueues shutdown after
the driver has left its command loop. That response was never completed, so
close waited the entire command timeout and masked the original error.

## Changes

- After cleanup marks the service closed, drain abandoned commands. A queued
  shutdown acknowledges completed cleanup (or its error); other queued commands
  fail explicitly instead of waiting for a driver that has exited.
- Add an event-synchronized CPU regression that forces shutdown into the fatal
  cleanup interval. It fails with EngineCommandTimeout before the repair.
