# Qwen3.8 scaling campaign extension Y: prefill sweep-multiplicity analysis and punchlist

## Summary

Opened extension Y in `docs/QWEN38-GFX1151-SCALING-CAMPAIGN.md` (new section
9) as the successor to the closed P track (P1/P2 named blockers, P3 measured
negative). Planning/analysis unit only — no code, kernel, or measured Y
result yet. Motivation: the external survey refresh shows hipEngine prefill
trailing the best external engine at all eight widths (-4.2..-11.7% at
C1/C3-C7, -34.0%/-19.1% at C2/C8) while AR leads C3-C8, making prefill the
widest uncontested external gap.

The analysis re-reads P1/P2/P3 together and names one structural defect
instead of three walls: the Q4 prefill owner's swept weight bytes scale with
`ceil(rows/16)` (one full ~16.3 GB weight pass per 16-row M-tile at ~184
GB/s/tile), not with sweeps. Cross-check inside P1's own artifact: 16 tiles
x 16.3 GB / 184 GB/s = 1417 ms vs the measured rows256 tick of 1418 ms —
the C8-relevant prefill tick is ~100% explained by re-streamed bytes at
near-roof per-tile rate. This is the same tiles-not-sweeps disease extension
W names in the verify path. P2's 19-24 TF/s dequant/LDS/issue wall is the
second wall behind the first (binds only at multiplicity ~= 1); P3 closed
data-format-only change but not loop-order/dataflow change, and never tested
INT4 (the only raised tensor roof, 118.8 TOP/s).

Gates: C2 >= 211.888 and C8 >= 305.847 prefill tok/s (best-external
2026-08-30 frozen rates; C8 is P2's existing named target), from the
reviewed 139.8/247.3 = +51.6%/+23.7%. Screening arithmetic (explicitly
marked as such in the doc) puts both gates inside sized headroom;
Y0 must replace it with measured bounds before any Y code.
