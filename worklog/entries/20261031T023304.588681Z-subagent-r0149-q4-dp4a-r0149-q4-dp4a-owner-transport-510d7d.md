# R0149 Q4 DP4A decode owner transport

## Summary

The Q4 DP4A decode pair is now request-owned state. The profile binder
publishes `q4_dp4a_decode_enabled` / `q4_dp4a_decode_layers` on the generator
and its current runner, and bound consumers never read the historical
`HIPENGINE_QWEN4_EXP_Q4_DP4A64{,_LAYERS}` pair. Those keys remain only as the
direct/unbound fallback. The original parser semantics are preserved exactly:
the layer list is comma-separated integer values, and the boolean is raw
membership `value not in {"", "0", "false", "False"}`, so odd strings such as
`"FALSE"` stay enabled.

The `decode_dp4a_linear` diagnostic candidate carries
`q4_dp4a_decode_enabled=True`,
`q4_dp4a_decode_layers=frozenset(PRODUCTION_Q4_DP4A_DECODE_LAYERS)` (43 layers:
0,2,5,6,8,9,10,11 and 13-47), `environment={}`, and
`moe_decode_warp=frozenset({"DOWN"})`.

Diagnostic scripts now bind the owner explicitly:
`qwen4exp_layer2_profile_gate.py` uses the `q4_dp4a_decode` context,
`qwen4exp_profile_gap.py` has `--q4-dp4a-decode` / `--q4-dp4a-layers` and
rejects the old pair through `--override`, `qwen4exp_disabled_family_sweep.py`
passes an `owner` argument, `qwen4exp_stateful_layer_graph_probe.py` forwards
the runner fields, and `qwen4exp_decode_sync_ab.py` uses the owner context.

Graph invalidation is complete for the c1 staging path: `step()` resolves the
owner pair and puts it in both the GDN layer-graph key and the MoE graph key,
so changing the fields on a prepared staging runner selects a new graph rather
than replaying a captured one. No explicit cache clear is required.

The public AR path now carries the same owner pair. With
`max_active_requests=1`, `Qwen4ExpResidentServingRunner._prepare_ar_batch()`
still builds a `Qwen4ExpARBatchOwner`, and admitted rows decode through
`Qwen4ExpGGUFBatchRunner`. That runner now has the pair as request-local
fields, `make_qwen4_exp_ar_batch_runner()` copies them from the generator at
construction, both batch layer owners forward them to `_run_layer_ffn`, and
the mixed-target pass reads them from the shared batch owner. The batch capture
key includes the resolved c1 decision, so a segment captured under one pair
does not replay under the other. A bound batch path never reads the ambient
pair; an unbound batch owner keeps the direct fallback for a c1 row only. At
wider rows the pair is inert, so the key carries a stable sentinel and does not
resolve the ambient list for an unrelated multi-row segment.

Docs edits in `docs/ENVS.md` and `docs/REFACTOR.md` describe the new transport
and are left for parent review. The parent owns the final ledger wording and
live validation.

  `owner` argument; `_run` emits `--q4-dp4a-*`.

  assertions to owner assertions.

- `audit/triage/ungoverned-flag-branch.jsonl`: NOT-DEBT/keep triage for the new
