# R0412 retains the generic wave H256 prefill diagnostic

## Summary

**Decision: keep `wave` as an explicit diagnostic value of the runner-owned
`qsa_h256_prefill_mode`.** R0412 asked whether the generic-wave comparison is still useful, with
retirement requiring the `wave` scope value and its campaign/state-gate packages to be removed
together. It is still useful and still implemented, and retiring it would remove a capability rather
than a duplicate: `wave` is the only route to the accepted H256 wave attention leaf at any block size
other than 256. Production and strict publication are unchanged (`page256` and `parent`), and `wave`
is never selected automatically. The entry's own validation had already been executed and recorded,
so the retention branch is complete and R0412 is removed.

The entry's `Scope:` named `HIPENGINE_QWEN4_EXP_QSA_H256_WAVE_PREFILL`, whose transport is retired:
`hipengine/` reads it zero times, `docs/ENVS.md` marks it `retired; ignored`, and
`tests/test_unit_qwen4_exp_profiles.py` asserts a stale value has no effect. The surviving scope is
the runner attribute, which `docs/ENVS.md` already documents. No code, default, arithmetic or
documentation changed apart from removing the completed entry.

## Changes
