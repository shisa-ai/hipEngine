# Qwen4Exp public deferred verifier rejection

## Summary

Rejected default-off public wiring of the exact pooled deferred-head verifier. The full ten-prompt category+heldout suite remains 10/10 exact with identical acceptance, but deferred MTP is 12.7% slower than serial MTP and regresses every category. The provider branch and temporary harness were removed; serial per-candidate target verification remains default.

## Changes

- Prototyped provider use of fixed-chain pooled verification with exact rollback/replay.
- Added a temporary same-process true-AR/serial-MTP/deferred-MTP harness with per-prompt/per-mode warmup and rotating three-way order.
- Removed both uncommitted paths after complete-wall rejection. Retained internal transaction, verifier, and rejection-grid primitives.

## Validation

- Focused provider/transaction/state/output controls passed, 18 tests while the branch existed.
- Ten prompts, all four categories, tg16, B2, raw greedy, `auto`: true AR **16.904 s**, serial MTP `W=22.821 s` (**0.7407x AR**), deferred candidate `C=26.152 s` (**0.6464x AR**, serial/candidate `s=0.8726`).
- Serial and deferred are both 10/10 exact against true AR and have identical per-row/total acceptance. Every category regresses: serial/deferred is 0.8484x code, 0.8585x English, 0.8524x Japanese, and 0.9482x mixed.
- Complete wall includes prompt prefill, draft, target verification, mismatch replay, and host control. Warmups are excluded and arm order rotates by prompt. Lifecycle returns zero bytes.
- No new trace followed because whole-model economics failed. The retained internal route was already traced in the rejection-depth unit. Serial `target.step` remains strict fallback.

## Next

Do not wire final-head-only deferral again. A viable verifier must batch operation-complete target body work or avoid executing and replaying rejected suffix rows.
