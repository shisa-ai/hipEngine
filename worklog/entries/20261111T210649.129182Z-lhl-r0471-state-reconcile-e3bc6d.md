# R0471 position_host sharing + state-layout reconciliation contract

## Summary

Completes the R0471 design by source-tracing the exact cursor/state reconciliation the
resident-scheduler native-row route must perform. Confirms the integration is an
ownership-model change, not a dispatch tweak, and names the defect-prone seams precisely so
the implementation step can be scoped and tested. No production code changed.

## Changes

Source-traced findings (all in `hipengine/runtime/qwen35_gguf_runner.py` unless noted):

- `step_batch_native` (24971) reads each slot view's `.position` directly
  (`position_tuple = tuple(session.position ...)`), validates the caller's `positions`
  against those cursors, and builds physical lanes from the slot views. It does NOT read
  the owner's `row_positions`.
- `step_rows_native` (21819) reads the owner's `row_positions` (17577), requires compact
  slots `range(rows)`, requires `rows >= 2` and `rows <= max_batch_size`, and if a
  `positions` arg is passed it must EQUAL the resident cursors. After the step it does
  `current_positions[slot] += 1`, `owner.set_full_attention_positions(...)`, and
  `self._position = current_positions[0]`. It returns `Qwen35GGUFTargetRowsResult`.
- Cursor sharing: a slot view's scratch is built with
  `position_host=self.position_host[slot:slot+1]` (32144) — a numpy VIEW into the owner's
  `position_host`. So `slot.scratch.position_host[0] IS owner.position_host[slot]`; slot
  steps that write `session.scratch.position_host[0]` already update the owner buffer.
  `set_full_attention_positions` (32225) writes `position_host[:]` + `context_host[:]` and
  copies to device.
- The reconciliation subtlety: `row_positions` overrides `positions[0] = self._position`
  (the owner's scalar cursor), which can diverge from slot-view 0's position. And
  `step_rows_native` updates only the owner's `_position` + the shared buffer, NOT each
  slot view's `_position`/`seq_position`. A scheduler route must (a) align owner
  `_position` with slot-view 0 before the call and (b) scatter incremented cursors back to
  every slot view's `_position` after.
- State-layout seam: `step_rows_native` runs `_native_compact_scratch` +
  `_enqueue_native_rows_model` (native-row Conv/GDN + full-attention layout), while
  `step_batch_native` uses the packed per-slot c1-exact Conv/GDN state
  (`_run_linear_attention_attn_only`). Switching a resident session between the two
  mid-generation requires re-importing/flushing state (cf.
  `flush_packed_decode_state` 27391 and `flush_packed_decode_owners_if_chunk_changed` in
  `qwen35_gguf.py:_step_native_chunk`). This is the defect-prone core, not the cursors.
- Dispatch point (`hipengine/generation/qwen35_gguf.py` ~12032): per physical group, if
  `generator._ar_packed_decode_enabled()` and (active>1 or physical>1) -> `_step_native_chunk`
  else `_step_native_serial`. The opt-in native-row route engages only when
  `native_batch_decode` + compact lanes + all-greedy, preserving packed/serial default and
  the `MemoryAdmissionRefused` -> serial fallback.
