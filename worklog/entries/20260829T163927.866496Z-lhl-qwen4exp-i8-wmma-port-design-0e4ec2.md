# De-risk i8-WMMA MoE kernel port

## Summary

Design decision + de-risk for the next MoE kernel unit. llama.cpp's gfx1151
MMQ uses int8 WMMA (not f16): `mma<16,16,int>(A<16,8,int>, B<16,8,int>)`
maps to two `__builtin_amdgcn_wmma_i32_16x16x16_iu8_w32` calls per 16x16
output tile (mma.cuh RDNA3 branch; gfx1151 is `__GFX11__`/RDNA3_5, so the
`_gfx12` suffixed intrinsics are NOT used), with both operands q8-requantized
into `block_q8_1_mmq` SRAM tiles (int values + half2 d/s per 32-block) and
scales applied in f32 outside the MMA (`sum += dmA.x*dsB.x*C + dmA.y*dsB.y`,
the 1-trick for min offsets). This gives 2x the MAC rate of f16-WMMA plus
cheap nibble->byte weight expansion; numerics are dp4a-class (q8 requant
~2^-8 relative error).

## Changes

- No code yet; this entry records the port design and toolchain facts.

## Validation

- Compile+run probe: non-gfx12 `__builtin_amdgcn_wmma_i32_16x16x16_iu8_w32`
  (A/B as intx4, accumulator intx8, two calls per tile) compiles and runs on
  gfx1151 with plain `hipcc --offload-arch=gfx1151` (no feature flags). The
  `_gfx12` variant segfaults this clang-23 and is not needed.
- llama's mmq.cu builds with exactly `-O3 --offload-arch=gfx1151` (build.ninja
  FLAGS line), confirming no extra feature flags are required.
