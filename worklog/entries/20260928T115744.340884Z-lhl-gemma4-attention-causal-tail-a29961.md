# the attention walk had a lower bound and no upper one: trimming the causal tail is 17.9 percent of prefill attention

## Summary

The prefill attention kernel walks columns `first_kept .. keys-1`. `first_kept`
trims the **leading** run of masked columns, and its justification is written in
the source: `window > 0` promises the mask is sliding-causal, so a row's leading
columns are all zero and the walk can start at the first it can keep.

**The same promise covers the trailing run, and nothing was spending it.** A
sliding-causal mask is zero above the row's own position as well as below its
window. Column 0 is key `key_begin`, so the row's position is `row_offset +
token`, and every column past it is zero -- but the walk ran to `keys-1` anyway.
For a block of 512 rows, the first row walked 512 columns to use 1.

Walking those columns costs what walking real ones costs: pass 1 loads a key row
and runs the whole warp-key reduction to produce `-infinity`, and passes 2 and 3
then read the shared logit it left behind. Pass 3's `if (weight == 0.0f)
continue;` skips the *V load* for them, not the loop iteration or the LDS read.

The fix is one bound:

```cpp
const int64_t walk_end = (window > 0 && row_offset + token + 1 < keys)
                             ? (row_offset + token + 1)
                             : keys;
```

used in pass 1 (both the warp-per-key and block paths), pass 2 and pass 3.

**It is bit-identical, not merely close.** A dropped column has logit
`-infinity`; it does not move `running_max`, and `expf(-infinity - max)` is 0, so
it contributes nothing to the denominator or the numerator. The promise it
relies on is the one `window > 0` already documents, so no ABI changed and no
new argument was added.

## Result

`scripts/gemma4_attention_prefill_bench.py`, both arms in one session, 5 iters
and 2 warmups:

| case | baseline | causal trim | delta |
| --- | ---: | ---: | ---: |
| 512, swa 256d window=1024 | 4.82 ms | **3.89 ms** | **-19.3%** |
| 2048, swa 256d window=1024 | 62.32 ms | **46.31 ms** | **-25.7%** |
| 512, model's 30 layers | 156.5 ms | **132.3 ms** | **-15.5%** |
| 2048, model's 30 layers | 2208.3 ms | **1813.2 ms** | **-17.9%** |

**Two controls that must not move, and do not.** `swa 256d window=0` and
`full 512d window=0` both pass `window == 0`, which is the documented "caller
makes no such promise" case and takes no trim: 78.07 against 77.45 ms and 130.07
against 131.10 ms at 2048, 4.67 against 4.93 and 7.20 against 6.98 ms at 512.
That the two cases the mechanism does not touch are flat is what separates this
from a session-wide speedup.

The 2048 saving is **395 ms of a 4166 ms step**, about 9.5 percent of prefill.

## Changes

`hipengine/kernels/hip_gfx1100/gemma4/gemma4_attention.hip` -- the bound, its
derivation as a comment, and `keys` replaced by `walk_end` in four loops. No
other file changed; the strict kernel is the production path
(`hipengine_gemma4_attention_prefill_bf16` launches `launch_gemma4_attention_prefill`,
not the tiled variant), and the tiled variant is left alone deliberately so the
two can still be compared.

The first attempt at this failed the parity test, and the failure was correct:
the test drives the prefill symbol with `window = 0` and a mask that keeps every
column, so an unconditional bound trimmed columns that shape needs. Gating on
`window > 0` is what makes the change legal, and the test is what found it.

## Next

**The global layers get nothing from this, and they are now the larger half of
attention.** At 2048 the `full 512d` case -- the 5 global layers -- is 655.5 ms
of the 1813.2 ms total, against 1157.7 ms for the 25 sliding ones, and it moved
by -0.7 percent. They pass `window == 0` because `attention.sliding_window is
None`, so they take the no-promise path.

Their mask is causal all the same: `_keep_mask` builds `keep = key_positions <=
queries` and only ANDs the window in when one exists. A global layer's window is
the whole context, so the call site can pass `window = keys` for it -- a faithful
description of the mask it actually built, which then licenses the same trim
through the same documented contract. Their own waste is the same shape: 20
percent of walked columns at 2048, weighted across the four blocks. That is a
caller-side change of one expression.
