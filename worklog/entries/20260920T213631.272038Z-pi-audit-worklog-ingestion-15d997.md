# Inventory the worklog as audit rows: the journal's declared unfinished work

## Summary

The cleanup audit catalogued `docs/REFACTOR.md`, flags, kernels, and campaign
candidates, and its own design entry recorded the journal as the missing fifth
source: "No extractor covers the 3,333 worklog entries yet (68 `blocked`, 19
`handoff`). That was scoped out of the first pass and is the obvious fifth." The
deferral was sequencing — the entry corpus was mid-migration while the legacy
journal was being split into per-entry files — and that migration is now done, so
the corpus is stable enough to inventory.

The design problem is that 10,589 entries are mostly history. Every entry carries
a `status`, and the schema requires a `## Next` section on all of them, so
treating "has a Next" as debt would produce 3,222 rows of forward references to
the *following* unit. The extractor instead emits a row only where the entry
declares unfinished business, by three mechanical markers: an open `status`
(`blocked`, `handoff`, `checkpoint`), a `completed`/`decision` entry whose `Next`
names a blocker, gate, or approval it did not have, or a ported pre-cutoff entry
whose verbatim body carries the journal's own optional `### Next` subsection.

That yields **1,076 rows**: 931 by status (843 checkpoint, 69 blocked, 19
handoff), 36 by dependency wording, and 109 legacy `### Next` markers. Whether the
work was finished later stays a triage decision; a later entry by the same worker
on the same topic prefix is reported as an observation and never closes a row.

## Changes

- `audit/hipaudit/inventory/worklog.py` — the extractor, registered in
  `inventory/__init__.py`. Rows carry `status`, `worker`, `topic`, age,
  `open_by`, the continuation count, the `open_text` that made them rows, and
  which named paths are not in the tree / which named flags no code reads. The
  key is the entry filename stem, which is immutable and unique, so a row never
  needs rebinding; the anchor is the entry path.
- Section parsing is fence-aware, because 13 ported entries wrap their verbatim
  body in a longer fence whose text contains its own `##` headings. Line numbers
  stay exact through the parse so `location` points at the line carrying the
  evidence (`status:` for status rows, `## Next` for dependency rows, `### Next`
  for legacy rows).
- Signals are observations only. Two candidates were cut during development
  because they were regex judgement wearing an observation's clothes: "names no
  condition that would lift it" fired on 807 of 1,076 rows and mislabelled
  entries that did name a way out ("Human approval is required to extend the
  exhausted bounded campaign"), and a bare `foo.py` in prose was being read as a
  repo path. The path pattern now requires a slash.
- `audit/audit.py` — `run_inventory` reported orphans from `load_inventory()`
  while `audit.py orphans` uses `load_all()`, so every `inventory` run printed a
  spurious "474 decision(s) no longer match any row" against the 58 that are
  real. Both now use `load_all()`.
- `audit/tests/test_inventory_worklog.py` — 15 contract tests over a temporary
  entry directory: each marker produces a row, each ordinary shape (a completed
  forward reference, a preserved blocker record, the port's boilerplate `Next`,
  a quoted heading inside a fence) does not, plus row identity, the anchor
  convention, continuation counting, ref checks, line numbers, and a
  non-parsing entry being counted instead of crashing.
- `audit/README.md` and `audit/agents/triage.md` — the extractor table, the
  entry count, and a short section on working worklog rows (resolve against the
  entry or commit that finished the work; check a pre-cutoff row's referent
  against today's tree; `--signal "recorded as blocked"` and
  `--signal "no later entry"` to scope).
- `audit/budget.json` — `worklog: 1076` added as the new kind's ceiling. Only
  that key was touched: a plain `audit.py budget` run would also ratchet the
  other kinds down to their current untriaged counts (the audit lane has triaged
  most of them since the ceiling was recorded), and that ratchet belongs with
  their triage work, not this change.

## Validation

- `python3 -m unittest discover -s audit/tests -t audit` — 44 tests pass (15
  new).
- Two independent extractions produce byte-identical row sets and 1,076 unique
  ids; the extractor runs in 0.8s over 10,589 entries and 50MB.
- `python3 audit/audit.py inventory worklog` — 1,076 rows written to
  `audit/inventory/worklog.json`; meta records 10,589 entries, 0 unparsable,
  and the per-rule split.
- Rule counts were measured against the corpus before the extractor was written
  (931 / 36 / 109) and matched the extraction exactly.
