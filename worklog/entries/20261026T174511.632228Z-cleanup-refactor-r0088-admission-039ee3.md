# Unify decode graph storage admission

## Summary

Use the graph capture capability predicate for resident-session storage
admission so the declared tail-four INT8 layout is not blocked by the
uniform-layout opt-in flag.

## Changes

- Remove the extra all-INT8 flag check in the session eligibility path.
- Preserve BF16 and tail-four admission, uniform INT8 opt-in behavior,
  incompatible-layout rejection and existing horizon/transport policy.
- Add a flag/layout/granularity matrix for both storage admission and the
  session replay-step resolver.
- Public validation exposed automatic capacity planning parsing the layout
  name as a dtype. Resolve the published KV hint through `resolve_kv_policy`
  instead, preserving tail-four layout and scale metadata for sizing.

- Declare the implemented tail-four layout with FP16 group32 scales and
  single-row decode; packed batch decode is not declared. Capability resolution
  and server/KV policy CPU tests pass. Preserve the recorded tail-four failure
  for the historical execution identity using its existing evidence artifact;
  an unfamiliar artifact matching implemented axes still runs. The declaration
  does not select direct no-oracle prefill or enable packed/MTP hybrid kernels.
