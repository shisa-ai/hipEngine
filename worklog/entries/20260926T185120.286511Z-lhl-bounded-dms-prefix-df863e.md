# Retain bounded DMS prefix snapshots from oversized prompts

## Summary

Oversized DMS prompt snapshots previously discarded every captured boundary. The cache now retains the longest captured prefix that fits the existing byte budget, including earlier branch boundaries when they fit. Public MTP validation confirmed partial reuse and matched-partition output equality.

## Changes

- `hipengine/runtime/dms_prefix.py`: admit an owned partial snapshot when the full prompt exceeds the cache budget. Copy truncated planes so NumPy views cannot retain oversized backing allocations. Preserve recurrence and checkpoint identity; never treat a partial snapshot as a complete prompt hit.
- `hipengine/runtime/dms_prefill_cache.py`: prioritize actual recurrent chunk ends when selecting capture boundaries. The original block-grid positions can all fall between chunk ends and produce no completed boundary snapshots.
- `tests/test_unit_dms_prefill_cache.py`: cover two fitting budgets and a too-small budget, branch reuse, owned buffers, incomplete-hit semantics, and natural recurrent checkpoint positions.
