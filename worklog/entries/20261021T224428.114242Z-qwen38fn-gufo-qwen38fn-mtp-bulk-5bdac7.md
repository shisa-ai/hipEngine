# Batch predictor prompt cache projections with scalar reduction order

## Summary

Complete the structural MTP-PREFILL implementation after the scalar cache-only
increment. A request-owned 64-row workspace batches prompt cache construction;
only each chunk's final row computes hidden carry. Target hidden rows are
borrowed synchronously on the device. Implementation, public-route resource
checks and the five matched HTTP workloads pass. This closes MTP-PREFILL,
not the broader campaign or its numerical/task and concurrency gates.

## Changes

- Add a request-owned 64-row workspace with exception-safe allocation and
  close. Existing BF16 gather combines normalized embeddings and hidden
  branches; all model and quant dispatch stays in the registry.
- Add cache-only operation semantics to the existing batched QSA mixer. It
  omits query-index work and attention after writing raw KV/index rows.
- Reuse registered decode reductions across independent projection rows and
  the existing row-capable fused GR decode kernels. Unsupported GR geometry
  or its disabled fusion uses the original scalar chain on scratch views.
  No kernel body, arithmetic threshold or environment flag is added.
- The normal dispatcher executes the first projection group and selects its
  variant. Row-independent GEMV variants batch the remaining rows with the
  parent's thread count. Other variants, including WMMA and T16, keep their
  scalar group shape. This preserves existing policy overrides rather than
  duplicating only part of the dispatch rules.
- The default priming caller commits each logical row only after its
  cancellation check. Staged future KV/index rows stay outside the cursor.
  Stage failure and cancellation restore the index and attention cursors.
  Each chunk ends with one complete scalar row for final hidden carry.
- Target prefill invokes a synchronous consumer after restoring its projection
  contexts and before reusing its workspace. The draft consumes BF16 rows by
  device-to-device copy, including shifted seeds across bounded tiles. Only
  the final target row is exported for prefix snapshots and the next chunk.
  No borrowed device pointer survives the callback. Host input remains usable.
- Both serving and direct provider execution use the device consumer. Serving
  diagnostics report device hidden rows and cache tiles, so public validation
  can establish that the intended implementation ran.
- T0 scheduling/ownership change: reuse existing arithmetic, kernels and
  variants. This is not promotion of the initial generic-prefill arithmetic
  candidate. No kernel body, model admission rule or environment flag changes.
