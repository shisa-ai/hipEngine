# Block PARO fast-verifier numerical gate on evaluator setup wall

## Summary

A strict-teacher full-vocabulary verifier evaluator was implemented, but the first D64 heldout attempt did not reach a measured row within the 15-minute bound. It held two 35B target sessions plus the proposer concurrently (about 85% W7900 VRAM) and remained in setup/JIT work. No numerical pass or performance claim is made.

## Changes

- Added `scripts/mtp_paro_verifier_numerics.py` to compare strict c1-loop and fast decode-batched c2 logits on the same strict-owned proposals, tokens, positions, and commit rows.
- Candidate decisions never own subsequent contexts: a differing candidate commit row is repaired to the strict-selected row before the next cycle.
- The evaluator computes full-vocabulary row KL, p95/p99/max KL, top-1, top-5 overlap, transition labels, finite checks, and the calibrated production thresholds.

## Validation

- `uv run pytest -q tests/test_mtp_paro_verifier_numerics.py` -> `1 passed`.
- `python3 -m py_compile scripts/mtp_paro_verifier_numerics.py` -> pass.
- `uv run` attempt failed before model work because its environment lacks `transformers`.
- System-Python attempt loaded about 85% of W7900 VRAM and stayed active for 15 minutes, then timed out without producing `/tmp/mtp-paro-verifier-numerics-en.json`.
- Existing retained evidence remains binding: fast D64 diverges on `general_en_explain` at output 24 and therefore remains uncertified/unselected; strict remains the registered fallback.

## Next

- Refactor capture to avoid two simultaneous fully resident target sessions, for example strict/candidate sequential captures from a reproducible strict-owned transaction fixture.
- Add phase progress records so model load/JIT and row evaluation are distinguishable.
- Only after the evaluator is tractable, run three repeats over the complete category/shape/transition/task matrix and apply all production thresholds.
