# Compare TP2 bulk with the resident TP1 bulk teacher at layer 0

## Summary

Direct layer-0 comparison of the opt-in TP2 bulk prefill against the actual
quality-gate teacher (optimized resident TP1 bulk, `arm=tp1-d0`) on the saved
64-token `mixed_ja_en_translate` prompt, in one process under the same
production profile. The layer-0 embedding input is **bit-identical**, the
attention norm and the gate projection are **bit-identical**, and the layer-0
attention output projection differs by only 1-2 bf16 ULPs (`attn_out` rel
6.98e-05). The earliest reliably-measured divergence is the layer-0 **GDN
output** (`recurrent_bf16`, rel 1.5e-03 / max_abs 0.0039). No missing helper
argument or state operation was found: `linear_state_rows=None`,
`commit_final_linear_state` effectively `True`, `hidden_f32_ptr`/`out_f32_ptr`
`None`, both scratches expose `post_norm_f32`, and the resident does **not**
chunk the 64-token linear prefill (`for_chunk(0, 64, 64)`). The divergence then
propagates through `post_norm` (rel 3.1e-03) and the layer-0 MLP (layer-1 input
rel 3.4e-03), growing to ~4e-02 by layer 62. The earlier bulk-vs-serial
`attn_out` difference (5.2e-03) is therefore **not** why TP2 bulk differs from
its teacher; the teacher and TP2 bulk agree on the prefill attention to bf16
precision.

## Changes

- `scripts/tp2_bulk_vs_resident_layer0.py` (new, diagnostic only): builds the
  resident TP1 bulk control and the TP2 bulk session under
  `bind_resident_profile("production")`, feeds both the same prompt, hooks
  `_run_linear_attention_prefill_attn_rows` / `_run_post_attention_norm_residual_rows`
  and `for_chunk`, and captures the layer input, `norm`, `linear_qkv`,
  `linear_z`, `conv_out`, `recurrent_out`, `recurrent_bf16`, `attn_out`, the
  committed conv/recurrent state and the helper arguments, per layer.
- No production code changed. No defect was demonstrated, so nothing was fixed.

## Validation

Command: `HIP_VISIBLE_DEVICES=0,1 HIP_PATH=/opt/rocm python3
scripts/tp2_bulk_vs_resident_layer0.py --prompt mixed_ja_en_translate --json
/tmp/tp2_layer0d.json`.

- Same process, same env (production profile bound before both sessions):
  `HIPENGINE_GGUF_VERIFY_CAPTURE_PREFILL_GDN=1`,
  `HIPENGINE_GGUF_FP16_RECURRENT_STATE=0`,
  `HIPENGINE_GGUF_VERIFY_F32_RESIDUAL=0`,
  `HIPENGINE_GGUF_VERIFY_F32_POST_NORM=0`,
  `HIPENGINE_GGUF_Q4_T16_DUAL_SILU_PRODUCTION_R28=1`,
  `HIPENGINE_C8_Q6_DP4A_GROUPED=1`.
- Inputs/rows/positions: both helpers called with `rows=64`; layer-0 input
  buffers are byte-identical (`input` max_abs 0, 655360 bytes each).
- Helper arguments equal in effect: teacher `linear_state_rows=None`,
  `commit_final_linear_state=True`, `hidden_f32_ptr=None`, `out_f32_ptr=None`;
  candidate omits `commit_final_linear_state` (default `True`).
- Resident chunking: `for_chunk` calls are `[0, 64, 64]` only (no chunking).
- Capture reliability: TP2 rank 0 and rank 1 are **bit-identical** for `input`,
  `norm`, `recurrent_bf16` and `attn_out`.
- Teacher vs candidate, layer 0: `norm` bit-equal, `linear_z` bit-equal,
  `recurrent_bf16` rel 1.5e-03 / max_abs 0.0039, `attn_out` rel 6.98e-05 /
  max_abs 0.00195, `residual` rel 6.98e-05, `post_norm` rel 3.09e-03 /
  max_abs 0.0078, layer-1 input rel 3.38e-03 / max_abs 0.125.
- Divergence growth (teacher vs candidate layer input rel): layer 1 3.4e-03,
  layer 6 5.8e-03, layer 20 8.1e-03, layer 52 1.1e-02, layer 62 4.2e-02.
- `linear_qkv`, `conv_out`, `recurrent_out` contain unwritten (uninitialized)
  columns in both routes, so their byte comparison is inconclusive and is not
  used to claim a primitive.
- No full D128 suite, no threshold change, no GPU reset, bulk stays
  opt-in/default-off.

## Next

- If the GDN chain is clean, the divergence is the designed full-width-vs-

  TP2 bulk's final decode KL (0.487) is worse than the TP2 serial's (0.108)
