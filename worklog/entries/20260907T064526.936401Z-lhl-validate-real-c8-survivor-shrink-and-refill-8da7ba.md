# Validate real C8 survivor shrink and refill

## Summary

Actual C8-to-C1-to-C8 shrink/refill passes all 10 category-suite prompts on epyc
W7900 GPU0: all 150 child outputs match independent AR. The run executes 21
initial C8 cycles, 20 native C1 survivor cycles and 26 refilled C8 cycles with
unchanged survivor storage and final request/lease drain. This is a diagnostic
engine boundary, not public or full numerical qualification.

## Changes

- Add `validate_wide_refill`, requiring eight distinct initial backend IDs and
  seven new refill IDs, an actual initial packed eight-request group, its native
  C1 survivor, then a new packed eight-request group containing that same survivor.
  Require unchanged survivor storage, unique physical slots, real active-group
  equality and no target errors. The last initial child is the declared survivor.

## Validation

- Ten CPU cases fail before the helper exists and then pass:
  `.venv/bin/python -m pytest -q -o addopts=''
  tests/test_qwen38_packed_c1_wide_refill.py`.
- Negative cases reject width-two proxies at either endpoint, missing singleton,
  an old peer replacing a refill, moved/shared storage, duplicate IDs, legacy C1,
  and a speculative singleton coexisting with an AR peer.
