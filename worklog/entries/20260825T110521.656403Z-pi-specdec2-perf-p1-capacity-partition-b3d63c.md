# Partition SPECDEC2 bridge by capability capacity

## Summary

The first attempted full K2 C1/C2/C4 invocation used one capacity-4 service.
C2/C4 correctly engaged staged SPECDEC2, but strict C1 correctly selected K0:
the adapter's C1 capability requires a capacity-1 owner while physical C2/C4
uses the C4 capability. The run was stopped after the first C1 route report and
is invalid/non-retainable.

The correct common protocol is two process-local packets: C1 at capacity 1 and
C2/C4 together at capacity 4. Each packet still compares all applicable arms in
one loaded service; the final P1 compact artifact joins only exact same-source
cells.

- Added positive capacity and fail-closed mixed-shape tests.
