# Repair decode timing diagnostic attribution and readback scope

## Summary

The existing skip-readback option did not make the host-bound
inference valid. Calls used today's default full-logit capture, while the patch
only suppressed eight-byte reads, was not restored and matched any eight-byte
buffer. Rewrite the diagnostic around explicit compact resident-token stepping,
scoped copy suppression and neutral interval reporting.

## Changes

- Schema2 replaces host_enqueue/device_drain labels with submission-loop wall
  and trailing-sync-wait intervals; removes host_bound and implied throughput
  attribution. Consecutive loops have different contexts and are not a matched
  throughput comparison.
- Suppress only the exact token buffer's eight-byte read, restore the original
  copy function in finally, consume device-resident tokens, and disable full
  logits/hidden capture explicitly. Close the generator on failures.
- Construct through the resolved profile instead of discarding the resolved
  object, so execution profile is actually applied.
- Retain cProfile mode, labelled as call timings that may include waits, not
  host CPU attribution. Validate positive transitions/profile steps.
- New CPU tests cover neutral report fields, pointer/size matching, exception
  restoration, compact step kwargs and generator failure cleanup. RED-first
  omitted for the extracted helpers: original unsupported inference and patch
  lifetime/capture mismatches were established by source inspection.

- Six focused CPU tests and actual script --help pass, including both loop
