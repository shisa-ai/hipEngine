# C2-7 device port: streaming no-shadow DMS pack + compact decode (BF16)

## Summary

Closes the open C2-7 checkbox "Port streaming no-shadow prefill pack and
compact decode in BF16 first". The host/backend DMS composition (strict
metadata, per-layer/head extents, `per_head_variable` spans, streaming
no-shadow BF16 pack, transactional append/eviction, grouped-GQA CPU
attention) landed 2026-08-17 and is retained. What is missing is the
registered HIP kernel bundle `dms_compact_bf16_streaming_v1`:
`kernels/cpu_reference/dms.py` carries the CPU oracle only, and
`docs/KERNELS.md` states "No gfx11 DMS kernel is registered or defaulted;
porting requires the CPU-reference correctness gate and a rocprof
kernel-identity row on a fresh stable GPU."

The 2026-08-17 hardware blocker ("current W7900 generation repeatedly
page-faulted") is stale: the C2-6 canonical W7900 load closed 2026-08-18
(d7c3996f2) and the S1d lease GPU gate passed the same day (acd9b04b4).
The trained-retrofit-checkpoint blocker for *product promotion* of the
exact Qwen3.6-35B-A3B UD-Q4_K_M artifact remains real and is out of scope
for the kernel port (fixtures carry the RED gate, per docs/TESTING.md).

## Changes

Pipeline placement (verified against FastDMS c602b0e, `models/qwen3.py`):
decision extraction runs on **pre-RoPE Q** (last channel of the first query
head per GQA group, the trained borrowed neuron), K/V pack runs on
**post-RoPE K/V**, decode expire/append runs before compact attention.

Storage ABI is already fixed by `DMSCompactBackend._build_storage_view`
(k/v payload slots of `head_dim` BF16, per-(row,layer,head) base_offsets /
range_capacity / live_counts int32, per-slot token_positions int32 and
evict_mask bool; INT8 adds per-slot scales). Attention consumes
`KVLiveSpans` with `spans_mode="per_head_variable"`: per (row, kv_head) the
live rows are the first `live_counts` slots of the contiguous extent at
`base_offsets` — evicted rows are compacted out, so attention is GQA with a
per-head variable live length over dense-in-extent storage.

### Units

- **U1 `dms_extract_decision`** (bf16, `corrected_mask`): per
  (token, kv_head) read pre-RoPE Q group-first-head last channel,
  `evict = decision > alpha_offset/alpha_scale` (float64 comparison,
  matching the NumPy float64 scalar upcast) or
  `decision*alpha_scale - alpha_offset > 0` for negative scale, store bool,
  zero the borrowed channel in place. Strict RED: bit-exact vs registered
  `cpu_reference` `dms_extract_decision`.
- **U2 `dms_streaming_pack`** (bf16, `count_rank_scatter`): per
  (row, layer, head) two-sided walk — count live
  (`~evict | pos >= current_pos - window`), exclusive rank, scatter K/V
  rows + token_positions + evict flags into the extent, publish
  live_count. Strict RED: bit-exact vs `DMSCompactBackend.streaming_pack`.
- **U3 `dms_append_decode`** (bf16, `compact_append_evict`): per
  (row, layer, head) compact evicted+out-of-window survivors in place,
  append the new row, then evict first-eligible (position order) victims
  until within capacity. Strict RED: bit-exact vs
  `DMSCompactBackend.append_decode` host walk.
- **U4 `dms_compact_attn_decode`** (bf16, `grouped_gqa`): GQA decode
  attention with per-(row, kv_head) live counts over dense-in-extent
  storage. Gate: CPU-reference outer floor KL <= 0.05 and top-1 >= 90% vs
  `compact_attention_reference` (same contract the existing paged decode
  attention kernels carry); strict exact on tiny order-matched fixtures
  where feasible.
- **U5 bundle + catalog**: register `dms_compact_bf16_streaming_v1`
  bundle membership, rocprof kernel-identity rows, `docs/KERNELS.md`
  catalog row, C2-7 status note. Product gate on the exact artifact
  stays blocked by the missing trained `dms_metadata.json` (recorded,
  not faked).

Files: `hipengine/kernels/hip_gfx1100/attention/dms_compact.{hip,py}`
(new family; one .hip/.py pair grows per unit), tests under
`tests/test_dms_*_hip.py`, registration via the module-level
`register_*_kernels()` pattern and `attention/__init__.py` export.

### W7900 rocprof blocker (reproduced 2026-08-19)

`rocprofv3 --kernel-trace` (dev build 1.3.2, `_rocm_sdk_devel`
7.15.0a20260711) deterministically hangs this W7900 host on kernel
dispatch: a profiled child loading a JIT-built module and launching a
kernel blocks in an uninterruptible driver state (timeout(1) itself
freezes; SIGTERM is trapped by the rocprof child wrapper). Plain HIP
malloc/copy under the same trace flags completes; the same SDK profiles
kernels on the gfx1151 zbook host (all recent rocprof evidence is
zbook). This is the same host instability class as the 2026-08-17 C2-7
block entry; the GPU itself stays healthy after each hang
(0.07 s roundtrip). Consequence: the rocprof kernel-identity row for
`dms_extract_decision_kernel` is recorded as blocked on this host (U5
gate), not faked. Strict CPU-reference parity above is the retained
correctness evidence.
