# Bind Qwen4Exp weights to model-neutral dispatch

## Summary

Bound Qwen4Exp physical owners to hipEngine's model-neutral GGUF dispatch ABI.
This corrects the F3 planning shorthand “raw layout”: block-quant tensors use
raw GGUF dispatch, while byte-identical F32/BF16 tensors use their existing
dense dispatch labels without creating replacement or alternate payloads.

## Changes

- Added `quant_key` to planned weights and selected model-neutral layouts from
  source qtype: F32/BF16 direct dense owners, quant blocks raw GGUF owners.
- Added `Qwen4ExpDeviceWeight` with backend identity and named allocation ABI
  accepted by `launch_gguf_linear`/dispatch helpers.
- Materialization wraps each physical allocation in that owner; free semantics
  and one-allocation-per-hot-tensor remain unchanged.

## Validation

- Qwen4Exp materialization/residency tests -> `9 passed`.
- Added real HIP Q8 byte-preservation and model-neutral gfx1151 F32 dispatch
  resolution checks.
- Full GGUF linear-dispatch compatibility bundle with Qwen4Exp -> `133 passed`.
- Device/replacement/alternate byte totals are unchanged from `ff911c6ac`;
  only the dispatch layout labels are corrected.
