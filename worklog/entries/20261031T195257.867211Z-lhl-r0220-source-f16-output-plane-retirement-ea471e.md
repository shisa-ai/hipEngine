# Remove the unused resident source-F16 output scratch plane

## Summary

`90b1424ee` moved bounded source-F16 prefill onto the K16 consumer, which owns
its own FP32 WMMA accumulator and publishes BF16 straight into the
destination. `7b797967d` then removed the resident owner's rocBLAS handle. The
resident owner still sized, allocated, validated as non-empty, liveness-checked
and forwarded an F16 output plane (`q6_f16_out`) that nothing reads: the
wrapper `_launch_t16_f16_rocblas` declares `out_tile_f16_ptr` for existing
callers and never dereferences it.

This unit removes that plane from the prefill plan, from the resident owner and
from the dispatcher, and passes `0` for the wrapper's now-unused sixth
positional argument. The activation and weight-tile planes, every remaining
alias and liveness rule, the direct kernel wrapper's positional and keyword
ABI, the raw-Q6 diagnostic producer and all arithmetic are unchanged.

## Changes

- `hipengine/runtime/qwen35_gguf_prefill_plan.py`: `_PREFILL_SCRATCH_Q6_F16_FIELDS`
  now names only `q6_f16_x` and `q6_f16_weight`; the `q6_f16_out` liveness
  entry, its `rows * max(tile) * FP16` byte computation and its `field_sizes`
  row are gone, so the plane is never sized, allocated or viewed.
- `hipengine/runtime/qwen35_gguf_runner.py`: the resident owner no longer
  forwards `out_f16_ptr`/`out_f16_nbytes` into the session, and
  `_GGUFFullAttentionPrefillScratch` drops the `q6_f16_out` field. Nothing else
  in the runner touched the plane.
- `hipengine/runtime/gguf_linear.py`: `T16F16RocblasPrefillSession` loses both
  output fields, the non-empty plane check, the size gate's `output` entry and
  the `output workspace` live region; `_launch_t16_f16_rocblas` passes `0` in
  the wrapper's output-tile position with a comment saying why. The
  `q6_k_f16_output_nbytes` import is gone. The class docstring now states that
  the owner carries no F16 output plane because the consumer writes BF16 into
  the destination.
- Tests: three RED-first host tests
  (`test_source_f16_plan_omits_the_unread_output_plane`,
  `test_source_f16_owner_builds_without_an_output_plane`,
  `test_source_f16_dispatch_passes_zero_for_the_unused_output_scratch`) plus
  the stale expectations they expose: plan formulas and owner order, the
  three-plane size test renamed to the activation/weight planes, scratch shells
  in the liveness and resumable fixtures, and the pinned `fn()` argument tuples
  in the dispatch tests.

## Limitations

- The 3 MiB saving is the resident arena's; on the dedicated (no-liveness)
  gfx1151 dense path the plane is also gone, but that plan has no arena, so the
  saving there is the plane's own `rows * max(tile) * 2` bytes.
- Removing the field changes the prefill plan identity and the
  `_GGUFFullAttentionPrefillScratch` field set. Every in-tree construction goes
  through `allocate`; nothing constructs the dataclass positionally, and no
  persisted plan or telemetry record names the plane.
- The kernel wrapper still declares `out_tile_f16_ptr` and
  `_launch_q6_f16_rocblas` still acquires a handle for the raw-Q6 diagnostic.
  Both are out of scope here and recorded below.
