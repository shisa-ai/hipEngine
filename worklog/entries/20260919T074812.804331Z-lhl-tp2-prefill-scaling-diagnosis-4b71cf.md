# TP2 prefill saturates; the remaining gap is per-rank efficiency, not fixed cost

## Summary

With the head projection fixed the TP2 bulk prefill runs at **922.1 tok/s** at
512 tokens (from 39.5 before the route was wired). The next question was where
the remaining gap to the fork's TP=2 tensor split (1474.6) lives, and the
answer is not where the previous unit left off.

A prompt-length sweep rules out a per-prefill fixed cost:

| prompt tokens | prefill tok/s | marginal ms/token |
| ---: | ---: | ---: |
| 256 | 787.1 | - |
| 512 | 922.1 | 0.896 |
| 1024 | 964.7 | 0.989 |
| 2048 | 947.9 | 1.074 |

The rate **saturates** near 950-965 tok/s rather than rising with prompt length,
and the marginal cost rises slightly instead of falling. A fixed per-prefill cost
would have shown the opposite shape. So the route is throughput-bound per token.

## The actual loss: per-rank efficiency, not the exchange's latency

Halving the sharded MLP should leave each rank doing about **0.62x** the
single-card work (sharded quantized matmuls are 42.6% of profiled kernel time,
replicated GDN/attention 7.4%, exchange casts 5.5%). The measured wall is
**0.95x** (555 ms vs the single-card route's 585 ms / 875.8 tok/s). So each rank
runs at roughly **65% of the single-card route's efficiency**, and that - not a
latency-bound exchange - is what cancels the parallelism win.

Recovering it would put the route near **1420 tok/s**, essentially the fork's
1474.6. That is the target, and it is a better-posed one than "shard the
attention too": the replicated GDN/attention is only ~7% of profiled kernel time,
so sharding it could not account for a 1.55x gap.

Caveat stated plainly: the 0.62x work share is derived from *profiled* kernel
durations, which are inflated (the same prefill's kernel sum varies 1.7x between
profiled runs at an identical region wall), so the share is an estimate. The
direction is robust: the route gained 1.05x where halving the MLP should have
given about 1.5x.

## Next

1. Split the bulk prefill's wall into shard compute, the staged exchange and its
   `f32_to_bf16` staging casts (113 ms profiled, 2.5 calls/layer, and they exist

   they are pure overhead relative to the single-card route, which needs none.

   half-width shard, which is a kernel-level unit.
