# Make Qwen3.6 GGUF weight duplication mechanically visible

## Summary

Added a metadata-only planned-weight census and an exact physical-range runtime
census so the Qwen3.6 single-layout campaign no longer infers duplication from
whole-device peak deltas.

## Changes

- Added exact allocation-byte planning for pack8, rank-2/rank-3 T16, dense,
  raw, X8, and sidecar residents.
- Added alias-aware planned and runtime census records plus a strict invariant
  that rejects alternate layouts, repeated physical copies of one allocation
  role, and one physical range claimed by unrelated source tensors.
- Froze the current Qwen3.6-27B manifest at 288 duplicated rank-2 Q4 tensors:
  13,998,489,600 pack8 bytes plus 10,790,502,400 T16 bytes.
- Added target/NextN/root-shared reference helpers and disjoint-arena coverage.

## Validation

- RED: `uv run pytest -q tests/test_qwen35_gguf_residency.py` failed at
  collection because the census module did not exist.
- GREEN: `uv run pytest -q tests/test_qwen35_gguf_residency.py
  tests/test_qwen35_gguf_materialize_helpers.py
  tests/test_qwen35_gguf_materialize.py
  tests/test_qwen35_gguf_nextn_materialize.py` -> 12 passed, 20 skipped.
- The actual-model no-GPU census reproduced the campaign's 13.037109375 GiB
  pack8 and 10.0494384765625 GiB T16 figures exactly.
