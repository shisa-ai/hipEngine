# Add public-route Flash-Next short-context allocation probing

## Summary

The shared Tier-1 capacity probe had no branch for the `qwen4exp` GGUF
architecture. Add one before running the campaign's deep hipEngine workloads;
allocation questions must not require full-depth prefills. This is a harness
change, not a model or kernel admission change.

## Changes

- Route by GGUF architecture and create `LLM` with the declared context and
  request width, production/strict profile, BF16 KV and optional MTP sidecar.
  Call public `prepare` and `prepare_request_scratch`, then submit independent
  one-prompt `generate_detailed` calls concurrently through the resident
  service. Require exact output counts and the requested AR/MTP provider witness.
- Accept either a single GGUF file or a directory. Read architecture metadata
  from its first GGUF, but pass the original directory to `LLM` so all model
  shards participate in loading and automatic quant selection.
- Verify the selected context and chunk rather than overriding public
  admission. A requested incompatible KV format fails before allocation.
  Keep qwen35's default INT8 KV behavior and Gemma's existing policy unchanged.
- After the public cohort has drained, reset the primary c1 runner and check
  complete vocabulary logits for a short prefill and decode continuation.
  Name that check's scope separately from the public cohort's token checks.
- Close the LLM on success and failure, retain named allocation errors and
  detect unreleased tracked memory. Record the actual chunk, profile manifest,
  resident/transient allocation counts, request diagnostics and exact command.
- Limit the claim to fixed resident allocations and exercised short-request
  shapes. Prefix-cache growth and deep-dependent transient work still require
  the campaign's full-depth runs.

## Validation

- RED: eight new probe tests fail because the qwen4exp branch does not exist.
  A signature-bound fake runner then exposes the singular `capture_hidden_seed`
  keyword required by `step`; fix it before GPU validation.
- GREEN: 22 focused tests pass across the new branch and both existing probe
  modules. Tests cover capacity versus prompt length, public route and full
  logits, MTP fallback, incompatible chunk/KV, incomplete output, non-finite
  logits, setup failures, smaller-than-requested capacity and leaked memory.
- The full CPU deterministic bundle and all four documentation gates passed.
  The torch audit found comments/docstrings only in runtime files.
- The first real attempt failed before allocation: the validation command
  supplied the metadata-only first shard instead of the complete model
  directory. Preserve its JSON under the `first-shard-failed` suffix. Add a
  failing directory-input test, implement directory metadata discovery without
  changing the LLM input, and rerun the focused bundle successfully.
- The directory-input rerun passed the AR case, including complete cleanup,
  but a single two-prompt MTP request hit the declared one-row group limit.
  Preserve this attempt under the `group-request-attempt` suffix. Change the
  probe to independent concurrent requests, matching the HTTP service's
  request boundaries without reducing width or disabling MTP. Regression
  coverage requires separate worker threads and checks that failed requests
  drain before owner cleanup.
- Real public validation passed with the corrected model directory and
  independent request protocol: AR/MTP at context 4096, width 2, prompt 997;
  then context 133760, width 1, prompt 2052. All six responses returned four
  tokens with the requested provider; all four separate full-vocabulary c1
  checks were finite. Every owner released all tracked allocations and leases.
  The selected runner chunk was 4096. Source and host configuration were
  unchanged; observed GPU temperature moved from 49 to 50 degrees Celsius.
- Compact evidence: `benchmarks/results/20261021-qwen38fn-capacity-contracts.json`.
  It binds source, full model hashes, commands, launch environment, native
  counts, allocation accounting and the raw report hash. It is not throughput
  evidence. Width 2 means concurrent independent requests and a two-slot
  resident pool; the observed AR GPU decode steps were width 1. The deep
  allocation case does not certify execution beyond the batch pool's 65536
  positions; full-depth testing must record the actual selected route.
