# Qwen4Exp P11 candidate packet

## Summary

Rejected promotion of the one-packet-per-cycle output rung. The T0 candidate writes each device argmax ID into a four-int64 device packet and copies the active packet once after the chain. It is exact and improves aggregate wall 1.0103x, but two categories regress and the packet readback remains a synchronization owner. Full output remains default and fallback.

## Changes

- Added a four-int64 request-owned candidate packet to the Qwen4Exp MTP draft runner.
- Compact proposal depths now keep token and hidden chaining resident, append IDs device-to-device, then perform one packet D2H per cycle.
- Preserved direct/full-output `forward`, `compact_output=False`, and the default-off environment selector.

## Validation

- Focused tests pass; the real sidecar compact/debug/replay test passes under `auto` clocks. Compact rows have exact IDs, no host logits/hidden, no per-depth token D2H, and one packet-D2H timing owner.
- Sidecar B2, 3 warmups + 10 samples: full output `O=16.794 ms`, packet `16.591 ms`, `s=1.0123`; IDs exact.
- Warmed four-category same-session AB/BA: `W=6,588.589 ms` full output versus `C=6,521.622 ms` packet, 1.0103x aggregate. Code/general-Japanese are 1.1133x/1.0226x; general-English/mixed are 0.9344x/0.9845x. Exact IDs and zero teardown pass, but binding category non-regression fails.
- Cached B2/tg3 `rocprofv3` trace records 12 each of `argmax_stage1_kernel` and `argmax_stage2_kernel`; raw SHA-256 `0744257af8bcd3f738148733c8209e46ffa9212e193166505856d1c1b1af8063`. Phase telemetry records one packet D2H per proposal cycle.
- Arithmetic class T0; scope is Qwen4Exp Q8 B2 proposal output. Proposal wall includes layer/head/argmax, and packet D2H synchronizes prior queued GPU work. Target verification is unchanged and disjoint. Strict fallback is the default full-output route.
