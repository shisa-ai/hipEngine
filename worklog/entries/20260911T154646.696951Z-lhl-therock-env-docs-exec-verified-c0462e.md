## Changes

1. **`THEROCK.md` Verify block was not executable as written.** It defined only
   `ENV_PREFIX`/`PY`/`ROOT` and never established the SDK's `PATH` or
   `LD_LIBRARY_PATH`, so three of its own checks failed:
   - `rocminfo` and `amd-smi` were invoked bare, but the ROCm CLI tools live in
     `$ROOT/bin` and are not on a fresh shell's `PATH`
     (`command not found`, exit 127).
   - `rocm_sdk test` failed `testCLIUsesDevelRootPath` with
     `FileNotFoundError: 'hipconfig'` (26/27), because `hipconfig` is likewise
     in `$ROOT/bin`.
   - the closing `ctypes.CDLL("libamdhip64.so")` check raised
     `OSError: libamdhip64.so: cannot open shared object file`.

   The block now sets `SITE`, exports `PATH` and `LD_LIBRARY_PATH` (the same
   exports the shell-setup section already installed), and states that those
   exports cover the rest of the section. Run in a genuinely fresh shell
   (`env -i`, no therock on `PATH`, `LD_LIBRARY_PATH` unset) the whole section
   now completes **exit 0**: `pip check` clean, `rocm_sdk version` `10.0.0`,
   targets `gfx1151`, **`Ran 27 tests ... OK`**, `hipcc` `7.15.26333-0000000`,
   `rocminfo` `gfx1151`, `amd-smi` ROCm `10.0.0`, `hipGetDeviceCount 0 1`.
   The `27`-tests-passed claim in the prose is therefore true again.
2. **The HIP smoke-test block could compile but not run.** As written it left
   `LD_LIBRARY_PATH` unset, so the built binary died with
   `libamdhip64.so.7: cannot open shared object file` (exit 127) instead of
   printing `2 3 4 5`. With the now-documented exports it prints `2 3 4 5` and
   exits 0. A note records that compiled binaries need `LD_LIBRARY_PATH` at run
   time, not just compile time.
3. **`docs/TUNING-gfx1151.md` carried the identical stale layout** the task was
   opened to fix, in a third gfx1151 doc: `ENV_PREFIX=/home/lhl/miniforge3`
   (base prefix, no ROCm) and `SITE=$ENV_PREFIX/lib/python3.13/site-packages`
   (nonexistent path), plus a prose line naming the base prefix as the ROCm 10
   source. Repointed to `envs/therock` + `python3.12`, and the reference setup
   now names the environment explicitly. Verified by sourcing the corrected
   block in a fresh shell: `rocm_sdk` `10.0.0`, `hipcc` on the exported `PATH`,
   `libamdhip64.so` loadable, `HIP_DEVICE_LIB_PATH` present.
