# Long-context per-row attention leaves stay exact to 8K spans

## Summary

Extends the validation of
`worklog/entries/20260917T195925.422701Z-lhl-gguf-long-context-eager-staged-attention-2c4ca3.md`
(the commit `085bdd86b` unit) from the 1024/1025 split straddle to 2K, 3.6K and 8K
spans, which is where the per-row split count and the split workspace become the
binding constraint. Nothing about the change is different here; this records the
longer-span evidence the unit's own task asked for.

Every case is **exact against the serial-exact teacher on both routes** -
hidden, touched BF16 K/V rows, Conv/GDN state, logits, top-1, accept summary,
cursor, commit and rollback - including 32 splits per row at 8K against a
33-split workspace. Cases whose rows all resolve the same split count take the
captured target graph and fail only the gate's default eager-route expectation;
the cases whose rows cross a split-count boundary take the eager route and pass.

## Validation

Commands (route probe wrapping `scripts/gguf_mtp_long_context_gate.py`, so the
same in-process run that compares the production verifier against the
serial-exact teacher also reports which route ran):

```bash
/tmp/gpu-main.sh /tmp/lc_path_probe.py --model /home/lhl/models/gguf/Qwen3.8-27B-Q4_K_M.gguf \
  --cycle-ends 2048,2049,3584,3585 --candidate-budgets 2,3 \
  --acceptance-cycle-ends '' --generation-contexts '' --out /tmp/mtp-longer-straddle.json

/tmp/gpu-main.sh /tmp/lc_path_probe.py --model /home/lhl/models/gguf/Qwen3.8-27B-Q4_K_M.gguf \
  --cycle-ends 8192,8193 --candidate-budgets 3 \
  --acceptance-cycle-ends '' --generation-contexts '' --out /tmp/mtp-8k-straddle.json
```

- 2048/2049/3584/3585 (rows 3-4, split-K 48/64 calls): 8 of 8 cases exact on
  every flag. `end2049-*` (start 2045/2046, split counts 8,8,8,9) and
  `end3585-*` (start 3581/3582, 14,14,14,15) take the eager route and pass;
  `end2048-*` and `end3584-*` (uniform split count) take the target graph and
  fail only the route expectation.
- 8192/8193 (rows 4, split-K 64 calls): both cases exact.
  `end8193-b3` takes the eager route and passes with
  `workspace_split_count 33 >= required_split_count 33`; the split plan resolves
  `num_splits 32` for each of its four rows. `end8192-b3` takes the target graph
  and fails only the route expectation.
- 8K is the longest span measured here; the model's resident capacity for this
  host and packet size is derived from the requested cycle ends. A row whose
  split count exceeded the workspace would make
  `_staged_full_attention_row_leaf` decline and keep the row-wise strict owner,
  which is the same exactness at a slower route rather than a wrong answer.
