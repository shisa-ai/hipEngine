# Elastic global KV pool growth foundation

## Summary

Added the allocator foundation for vLLM-style elastic dense GGUF KV storage.
The global page ledger can append pages without rewriting existing page IDs,
and the device wrapper can grow through an explicit runtime callback.

## Changes

- `GlobalKVPoolSet.append_pages()` extends page metadata and publishes a new
  storage-view generation.
- `GlobalDeviceKVPool.grow()` invokes a growth provider after invalidating live
  packed decode graphs.
- The dense GGUF runtime allocates append-only device chunks and refreshes
  per-plane pointer tables while retaining all chunks for teardown.
- Allocation pressure evicts reclaimable prefix snapshots, then grows the
  device pool in chunks up to a live-free-memory-derived page budget.
- Normal, shared-prefix, and workspace allocations all use the same bounded
  pressure/growth path; device metadata descriptors advance with growth.
- Growth is transactional across chunk allocation, pointer-table allocation,
  and descriptor upload; failed descriptor publication leaves the old pool
  topology intact.
- Dense GGUF pool startup uses the configured initial page floor, while
  `max_active_requests` remains scheduler admission/concurrency.
- Observability publishes independent `max_active_requests`, `max_context_tokens`,
  pool `max_pages`, and pool `budget_bytes` values.
- Added optional explicit `kv_pool_memory_budget_mib` configuration and
  `--kv-pool-memory-budget-mib` / `HIPENGINE_KV_POOL_MEMORY_BUDGET_MIB`;
  automatic live-free-memory sizing remains the default.
