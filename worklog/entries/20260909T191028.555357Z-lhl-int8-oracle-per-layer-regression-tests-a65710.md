# P1 oracle-fix regression tests and capacity unqualification

## Summary

Closes the regression-test and publication gaps of the P1 fix
(`20260909T164351.976619Z-lhl-int8-packed-oracle-per-layer-fix-35dd3a.md`),

## Changes

- `tests/test_gguf_int8_prefill_oracle_per_layer.py` (new, 15 host-policy
  tests, no GPU/model required):
  - `_int8_prefill_oracle_cache_for_layer`: one shared pair only under a
    `layer_outer_shared_oracle` plan without the per-layer override; the
    override keys one stable pair per layer; the override never poisons the
    shared key for later readers; non-shared plans and a missing plan key per
    layer regardless; release frees every per-layer pair and re-acquisition
    starts empty.
  - `_prefill_batch_native_impl` / `prefill_batch_native`: multi-chunk calls
    set `_int8_prefill_oracle_per_layer` on every session before the first
    slab (pinned by recording the flag at slab entry, both slabs); tail-chunk
    plans (17 rows / capacity 8 -> chunks [8, 8, 1]) count as multi-chunk;
    single-chunk calls keep shared ownership; a later single-chunk call on
    the same sessions never inherits per-layer keying; a raising slab
    propagates the exception, clears the flag, and releases the oracle
    buffers (owner-as-session arm).
  - `_int8_prefill_oracle_capacity_positions`: the oracle stays sized by the
    whole physical backing pool (`backing_pages * block_size`) even beyond
    `max_positions`, with no-allocation / no-backing / zero-page fallbacks to
    `max_positions`. This pins the invariant behind the reviewer's memory
    note: the oracle is addressed through physical page rows (shared
    prefixes, shifted COW suffixes), so shrinking it to the prompt length
    would strand addresses.
- `benchmarks/README.md`: ladder sentence now marks **INT8 KV server 54,272
  unqualified** (measured pre-fix; the repaired route transiently holds one
  BF16 oracle pair per INT8 layer on multi-chunk prompts, so the number is
  optimistic). `Last updated` -> 2026-09-10. The pre-existing uncommitted
  "eight -> six measured configurations" edit from the census lane was
  preserved untouched.
- `README.md` (root, long-context table): the INT8 row is annotated
  `(re-measuring)` with a one-line reason; `scripts/sync_benchmark_readme.py
  --check` passes.
- `benchmarks/CHANGELOG.md`: dated unqualification entry.
- `docs/QWEN38-27B-GFX1100-24GB-CAPACITY.md`: follow-up note in the P1 section
  recording the tests, the RED evidence, and the unqualification.
