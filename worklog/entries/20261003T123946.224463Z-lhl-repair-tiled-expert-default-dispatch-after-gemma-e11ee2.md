# Repair tiled expert default dispatch after Gemma merge

## Summary

The merge's tiled-layout override forced `auto` into the explicitly pinned
MMQ split-projection chain, bypassing the gate/up rollback lever. Removing it
restores the default dispatch ladder and leaves explicit `mmq` selection
available. The automatic down owner now uses the registered exact chain after
isolating the lossy MMQ continuation failure. All ten default continuation
screens pass; 610 paired logits are byte-identical and real public generation
completes with selected-route counters. Explicit MMQ remains runnable.

This is a dispatch repair, not a new kernel or a numerical-envelope change.
Tiled weights without a serving leaf in the default MMQ family fall through to
the registered grouped/selected owner. A passing numerical row does not prove
that an accelerated MMQ leaf served it; selected-route evidence is required.

## Changes

- Remove the layout-conditioned `use_mmq = True` override.
- Add a CPU-only regression covering default tiled dispatch and its gate/up
  rollback lever, with both parameter cases failing before the change.
- Preserve tiles-only residency and explicit `mmq` selection.
- Default the existing down-MMQ lever to the exact owner because of the
  observed continuation failure; record the named clearing command in the
  ledger and env reference. Preserve the explicit opt-in and all kernels.
- Correct production profile selections for tiled Q4_K gate/up and Q5_1 down.
- Add `scripts/gemma4_generated_history_gate.py` with paired controls, the
  unchanged evaluator, provenance, per-case verdicts and a real public request.
- Add a CPU harness test for request ordering: closing a resident session
  releases its runner, so public generation must happen before session closure.
