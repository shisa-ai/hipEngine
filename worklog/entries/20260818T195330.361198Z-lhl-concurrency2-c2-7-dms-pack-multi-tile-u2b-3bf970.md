# C2-7 U2b: DMS streaming pack multi-tile rank fix, bit-exact

## Summary

Fixes the latent U2 bug filed in
[`20260818T191844.039696Z-lhl-concurrency2-c2-7-dms-device-port-u3-3df0e2.md`](20260818T191844.039696Z-lhl-concurrency2-c2-7-dms-device-port-u3-3df0e2.md):
`dms_streaming_pack_kernel` computed per-thread output ranks as a lane
prefix of per-thread keep counts, which equals the true global keep rank
only while a row fits one 256-token tile. With longer prompts the packed
K/V order was silently wrong (live counts and extent tails looked
plausible, so only a bit-exact payload comparison catches it).

## Changes

- `dms_streaming_pack_kernel` in `dms_compact.hip` rewritten to the
  chunked scan used by U3: pass 1 counts keepers in 256-token chunks
  (Hillis-Steele prefix over per-slot keep flags) and fails closed with
  no extent mutation when the total exceeds the reserved capacity (the
  old code published `live_counts` before its per-write OOB check);
  pass 2 repeats the chunk scan and scatters keepers in token order with
  global rank = running cross-chunk rank + intra-chunk inclusive prefix
  - 1. Input K/V and the slot extent are disjoint, so the chunk-wise
  scan+write is race-free.
- `tests/test_dms_streaming_pack_hip.py`: `_case` gains an optional
  `custom_masks` per-row override; three new GPU cases — a 300-token
  single row, a 300+16 mixed row batch with offset row starts, and the
  discriminating interleaved case where the tile-0 kept tokens are held
  by higher-numbered threads than the tile-1 kept tokens (kept =
  {1} + {118..150} + {267..299}).
- Note: the pre-existing `_eviction_mask` helper's jitter line is a no-op
  (`mask[:n] = True` followed by `|= jitter`), so its masks keep only the
  window plus token 1 — too uniform to trigger the rank bug; the
  regression case therefore uses an explicit interleaved mask.

## Validation

- RED-first: with the pre-fix kernel (git stash of the .hip change), the
  interleaved case fails with a K-payload mismatch while the other two
  multi-tile cases and all pre-existing cases pass; with the fix,
  20/20 green across `test_dms_streaming_pack_hip.py` +
  `test_dms_append_decode_hip.py` + `test_dms_extract_decision_hip.py`
  on this W7900 host (2026-08-18).
- The bug was first reproduced outside pytest with a 300-token row
  keeping 118..299: device packed [256..299, 118..255] where the host
  packed [118..299].
