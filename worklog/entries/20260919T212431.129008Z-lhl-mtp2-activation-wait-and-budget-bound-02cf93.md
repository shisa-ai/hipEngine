# Two MTP questions answered without code

## Summary

Tasks #25 and #32 both asked for a measurement before any implementation, and
both measurements say "do not implement this". One c=1 investigation answered
both: activation waiting costs 2.44% of speculative cycles, and candidate
budgets above 3 are refused by the evidence gate rather than clamped, so the
saturation sweep the task asked for cannot run on this artifact at all.

Neither task needed a code change, and neither produced one.

## #25: activation waiting is not the dominant cost

The task's own stop condition is "stop the experiment if activation waiting is
not the dominant cost". On the qualified c=1 configuration (production profile,
dense 27B `Q4_K_M`, bf16 KV, budget 3, cache off, four 4-turn conversations,
128 output tokens per turn, `--route-mix on`):

- **16 of 16 rows record exactly one `no_provider` event**, 16 events against
  **655 speculative cycles — 2.44% of cycles.** Removing the wait entirely
  bounds the gain at 2.44%.
- `first_fallback_position` is null on every row, so the event is the
  activation cycle at the start of the row's life, not a mid-generation loss.
- The rows are otherwise fully engaged: 2,030 MTP tokens against 18
  autoregressive, coverage 0.984-0.992, accepted drafts per cycle 2.099.

The task's corrected premise already ruled out the c=4 case (those rows are
refused by the static group bound before any provider work, so priming earlier
cannot help them). What remained was this c=1-style wait, and it is 2.4%.

## #32: budgets 4-6 are refused, not clamped

The sweep was attempted first, because a clamp would have made it a
configuration question:

- A server pinned to `--speculative-candidate-budget 5` reports
  `{"requested": 5, "resolved": 5, "source": "explicit"}` at
  `/v1/hipengine/capabilities`, and **refuses both requests at admission** with
  `route_decision_reason=candidate_budget_not_qualified`,
  `effective_route=default`, `requested_route=speculative_mtp`, and zero MTP
  tokens. The refusal is typed and published, which is the honest behavior.
- The mechanism is a comparison, not a clamp:
  `hipengine/speculative/serving.py::_evidence_checks` requires
  `key.candidate_budget <= row.candidate_budget`, and
  `resolve_max_qualified_candidate_budget` returns the deepest retained row for
  the cell. For this artifact (dense 27B `Q4_K_M`, 17,106,773,120 bytes) the
  deepest retained row is
  `qwen36-dense-q4km-gfx1100-production-bf16-c1-k3-d24` at **K=3**; no retained
  row anywhere describes a deeper cell for this artifact.

So no K=4-6 number can exist until a deeper cell is qualified, which needs the
production numerical, quality, and performance artifacts that qualification
requires. That is a qualification campaign, not a sweep.

Accepted drafts per cycle is still rising at K=3 (marginal +0.734 then +0.477
drafts per added verify row) against a rising marginal cost (+7.26 then

budget — it is bounded by the evidence gate, not measured. The K=3 point from
this run sits 0.7% above the earlier sweep's, which is the same-load agreement
that makes the K=1/K=2 points usable beside it.
