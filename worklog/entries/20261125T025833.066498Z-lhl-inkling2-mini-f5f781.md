# Report the HIP status when an NVFP4 Q8 dot launch is refused

## Summary

The five launchers of `gguf_nvfp4_q8_dot.py` raised `HipError` with one argument, a message that
held the status. `HipError` takes the status and a message, so a refused launch would have raised
`TypeError: HipError.__init__() missing 1 required positional argument: 'message'` and hidden the
HIP status. No launch was refused in the recorded runs; the error path had not been exercised.

- **Found by** the refusal test of the grouped WMMA launcher, which used the same raise and failed
  the same way.
- **Fix:** `raise HipError(status, '... failed')` in all five launchers. No kernel changed.
- **Test:** `test_nvfp4_q8_dot_launchers_report_the_status_of_a_refused_launch` calls each
  registered launcher with null inputs; the C launchers refuse them before any kernel runs.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_nvfp4_q8_dot.py`: the five raises.
- `tests/test_gpu_gguf_nvfp4_q8_dot.py`: the refusal test, one case per launcher.

## Validation

- RED: without the fix the five cases fail with the `TypeError`.
- GREEN: `tests/test_gpu_gguf_nvfp4_q8_dot.py`, 17 passed, on the W7900.
