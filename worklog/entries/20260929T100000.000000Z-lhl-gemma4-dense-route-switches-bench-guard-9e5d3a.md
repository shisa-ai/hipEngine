# the dense term's route switches are all noise, and the campaign bench needs --expect-gpu on this host

## Summary

Two negatives and one operational finding. No metric change.

## The dense term has no free lever

The dense term is the largest single term in the prefill census (189.3 ms, 28.3 percent), so its
two route switches were the cheapest remaining A/B. Both are dense-specific and both default on:

| arm | prefill_s | prefill_tps | decode_tps |
| --- | ---: | ---: | ---: |
| default | **0.6495** | **788.3** | 28.19 |
| `HIPENGINE_GGUF_DENSE_WMMA_BULK=0` | 0.6572 | 779.0 | 28.06 |
| `HIPENGINE_GGUF_DENSE_WMMA_RESIDUAL=0` | 0.6594 | 776.4 | 28.16 |

**Both alternatives are slower and the whole spread is inside this host's session noise.** The
dense WMMA bulk and residual paths are correctly enabled, and there is no faster route hiding
behind either switch. Combined with `20260929T020000`'s tile-family sweep, the dense term has
been probed on its routes, its tiles, and its geometry without finding a lever; what remains for
it is the 127 GB/s plateau itself, which is a kernel unit rather than a switch.

## This host's noise floor is ~1.5 percent

The default arm measured **0.6495, 0.6556, 0.6572 and 0.6584 s across four runs in this session**
-- a 1.4 percent spread with no code change. Any arm on this host must clear 1.5 percent before
it is credible, and single-run comparisons below that are not measurements. This is the same
host-to-host and session-to-session caveat `20260928T114215` records, now with a number.

## `gemma4_campaign_bench.py` cannot run on gfx1151 without an override

```
DEFAULT_EXPECT_GPU = "RX 7900 XTX"
parser.add_argument("--expect-gpu", default=DEFAULT_EXPECT_GPU)
...
ERROR: logical HIP device 0 is 'AMD Radeon 8060S Graphics', expected it to contain 'RX 7900 XTX';
check ROCR_VISIBLE_DEVICES/HIP_VISIBLE_DEVICES before measuring
```

The guard is correct -- it exists to stop cross-host comparison -- but the promoted
`2026-09-28-gemma4-q5-1-down-mmq-load-width-accepted` candidate records its protocol as
`scripts/gemma4_campaign_bench.py --prompt 512 --output 128 --samples 3 --warmup 1` on
**"gfx1151 Strix Halo (Radeon 8060S, zbook)"**, which cannot have run as written. The working
invocation on this host is:

```
scripts/gemma4_campaign_bench.py --expect-gpu 8060S --prompt 512 --output 128 --samples 3 --warmup 1
```

This cost two wasted runs to discover. **The accepted candidate's protocol line should carry the
override**, since that row is the one a reader reproduces on this host. Recorded here rather
than edited into a committed artifact.
