# Gemma 4 assistant-head MTP server contract

## Summary

The assistant-head provider was reachable only through an explicit greedy
`speculative_mtp: true` request. Automatic requests, sampled requests, and
streamed requests did not reach it, and the capability banner reported the
route unavailable, because the model plugin declared no executable scope and
the generator exposed no serving resolver or streaming entry point.

This lands the remaining server contract, using the same three-piece shape the
Qwen route uses, with no artifact hash, model name, or known-good list:

- `Gemma4GGUFModel` declares one capability scope
  (`gguf_gemma4_assistant_bf16_c1_chain`): BF16 KV, both gfx1100 and gfx1151,
  one row, candidate depth up to 8, greedy and sampled, automatic-eligible.
  `resolve_speculative_mtp_serving_plan` admits on that declaration and refuses
  only a real capability miss (storage, backend, width, depth, or sampling
  mode).
- `Gemma4GGUFGenerator.resolve_speculative_mtp_serving_plan` builds the
  mechanical identity key (backend, gfx target, KV storage, group width,
  capacity, depth, sampling mode, memory fit) and delegates the decision to the
  model plugin. `auto` storage resolves to the provider's BF16 contract.
- `Gemma4GGUFGenerator.stream_speculative_mtp_detailed` and
  `SubmitPollTextGenerator.stream_speculative_mtp_detailed` expose the
  streaming entry point the server's MTP route calls, so a streamed request
  reaches the provider instead of failing with a missing-method error. A
  non-resident driver delegates to its inner generator and refuses by name when
  the inner has no streaming method.
- `LLM.speculative_mtp_serving_capability` falls back to the implementation
  declarations when a plugin keeps no evidence rows, so the capability banner
  and the `enabled` default route read the same answer the per-request resolver
  gives. Qwen plugins keep their evidence path unchanged.

Single-request scope is carried by the declaration (`max_group_rows=1`): an
explicit two-row request is refused HTTP 501 with
`unsupported_feature`, and streaming requires exactly one prompt.

## Changes

- `hipengine/models/gemma4.py`: capability declaration and
  `resolve_speculative_mtp_serving_plan`.
- `hipengine/generation/gemma4_gguf.py`: `target_arch`,
  `resolve_speculative_mtp_serving_plan`, `stream_speculative_mtp_detailed`.
- `hipengine/generation/engine_loop.py`: non-resident
  `stream_speculative_mtp_detailed` delegation.
- `hipengine/llm.py`: capability fallback to implementation declarations when
  no evidence rows exist.
- `tests/test_unit_gemma4_mtp_serving_route.py`: new focused tests for the
  declaration, the server route (explicit, automatic, sampled, streaming,
  opt-out, named refusals), the generator resolver, streaming reachability, and
  the end-to-end LLM/server route.
