# Account for INT8 serving checkpoints and pool reserves

## Summary

Correct production INT8 memory accounting without changing runtime allocations, kernels or arithmetic. Primary layer-outer hidden buffers alias by default, but resumable server prefill needs separate checkpoint buffers. Both facts must be priced: removing only the redundant primary-plane charge caused a full-depth request to run out of memory.

The historical private-session, MTP-off, layer-outer DMS route passed 131,072 prompt tokens plus eight decode steps on current code, with finite logits and zero tracked allocations after close. This does not replay the 232,448-token record: its original temporary fixture is unavailable. Model/data hashes, command, environment and limitations are in `benchmarks/results/2026-10-20-xtx-dms-layerouter-128k.json`.

## Changes

- Price the actual primary hidden-plane count while preserving the planner's execution choice and existing alias rollback.
- Price two prompt-length checkpoint planes plus one slot's saved linear state per potentially suspended long-context request.
- Share post-pool workspace accounting between automatic sizing and pool admission. Include checkpoints, packed linear state, packed scratch and prefix snapshots, without reserving the already-allocated bulk workspace twice.
- Leave allocation and numerical paths unchanged. Replacing dense-pool DMS with historical two-pass prefill would change the work performed and needs separate performance evaluation.
- Attribute resumable checkpoint ownership to `9c6a62ace6` (2026-09-11), after the September high-capacity harness measurements. It protects suspended requests from shared-workspace overwrite by interleaved decode; deleting it would violate that ownership contract. The private offline harness does not exercise this serving cost.

## Validation

- Six alias-count regression cases failed before implementation and passed afterward. Full-depth execution then exposed the missing checkpoint term despite short-request success.
- The alias-only candidate selected 66,048 tokens with MTP off but failed on a 65,792-token prompt. Instrumentation located the failed 135,266,304-byte allocation in `_int8_prefill_oracle_cache_for_layer` after checkpoint restore. Checkpoint storage explains exactly 1,506,279,424 bytes of the observed owner increase. The pool also held 204,472,320 bytes beyond occupied pages. These are candidate failures, not shipped behavior.
- Checkpoint-only intermediate sizing selected 46,336; its 46,080-token prompt plus 32 decode tokens passed. This preceded final pool-reserve integration and is not final-code validation.
- Six checkpoint allocator-comparison cases cover three lengths and serving widths one/four, including the pool-reserve boundary. Capacity and alias bundle: 94 passed.
- Final-code HTTP matrix: all eight requests passed (four short allocation checks and four full-depth checks). Each generated 32 tokens and remained healthy after the request; MTP response metadata confirms actual use for automatic-MTP rows. Automatic contexts were BF16/MTP 28,160, BF16/MTP-off 55,808, INT8/MTP 17,664 and INT8/MTP-off 46,336. Full-depth prompts used context minus 256 tokens. Commands, source diff/digests, model identity, prompt hashes, generated IDs, routing and sampled whole-card peaks are in `benchmarks/results/2026-10-20-xtx-serving-checkpoint-accounting.json`.
- These are validated automatic settings, not maximum-capacity boundaries. The BF16/MTP full-depth run approached the physical card limit; do not extrapolate headroom to other prompts or workloads. No throughput or full-context quality claim is made.
- Independent final code review found no remaining correctness issues and passed 42 capacity/alias tests. All four documentation gates passed. The earlier broad-suite GPU-environment failures remain recorded in `20261020T165845.054677Z-lhl-xtx-capacity-investigation-9addfe.md`; no clean broad-suite result is claimed.
