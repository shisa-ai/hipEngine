# Q8 iu8-WMMA route gains a role scope so its reopen condition is expressible

## Summary

The generic iu8-WMMA dense Q8_0 route
(`HIPENGINE_QWEN4_EXP_Q8_IU8_WMM`) was a single boolean that claimed every
eligible Q8_0 prefill linear. Its two recorded rejections each closed an *arm*
rather than a role: `20260915T015835` rejected the unchanged generic switch and
said so explicitly ("not role-isolated non-GR work"), and `20260915T022059`
rejected the non-GR arm while recording that it "does not implicate every
projection". `docs/REFACTOR.md` "Non-GR Q8 Diagnostic Scope" had already named
the prerequisite: express the scope through the registered production plan
"after equivalent role/count coverage exists".

The boolean cannot express role coverage. Re-running it can only re-measure the
whole route that already failed. This unit adds the missing control:
`HIPENGINE_QWEN4_EXP_Q8_IU8_WMM_ROLES` narrows the route to named roles, so each
role family can be gated alone.

## Changes

- `hipengine/runtime/gguf_linear.py`
  - `_q8_iu8_wmma_enabled()` — single source of truth for the route's flag;
    the dispatch predicate and the cache key now share it instead of each
    reading the environment separately.
  - `_q8_iu8_wmm_roles()` — parses the role scope. Empty or unset returns
    `None`, meaning every role, which reproduces the whole-route shape that
    already failed.
  - `_weight_role(weight)` — returns a weight's role within its block
    (`layers.5.attn_gate.weight` -> `attn_gate.weight`) or `None` when the
    weight cannot be placed.
  - `_role_in_scope(role, scope)` — dotted-path *prefix* match on whole
    segments, so `attn_gate` selects `layers.5.attn_gate.weight` while `attn`
    does not.
  - `_q8_iu8_wmma_dispatch(...)` gains `weight=` and declines when a scope is
    set and the weight is either out of scope or unplaceable. A scoped route
    must not silently cover a weight it cannot place.
  - `_q8_iu8_role_cache_key(weight)` — extracted, and added to
    `_DISPATCH_RESOLVE_CACHE`'s key. See "The cache-key bug" below.
- `tests/test_unit_qwen4exp_iu8_scope.py` — 13 cases, including the 4-case
  parametrized row-boundary test that already lived in this file.
- `docs/REFACTOR.md` — records the scope as the mechanism the existing
  "Non-GR Q8 Diagnostic Scope" entry asked for, and its removal condition.

### The cache-key bug this unit found and fixed

The route's contribution to the dispatch-resolution cache key was the flag as a
**boolean** — not the role scope:

```python
os.environ.get("HIPENGINE_QWEN4_EXP_Q8_IU8_WMM", "0") not in {"", "0", ...},
```

`launch_gguf_linear` resolves dispatch once per key, so two roles of identical
shape would share a key and the first role's decision would be replayed for
every later role. The scope would then be an artifact of cache-fill order rather
than a contract. This is not hypothetical in this file: the comment immediately
above the key records the identical omission for the WMMA layer scope, where a
gate cleared the scope for its teacher arm, both arms produced the same key, and
the gate reported **bit-identical logits, a KL of exactly zero, and
`measurement_valid: true`** — a silent false pass. The key now carries
`(enabled, scope, role)` via `_q8_iu8_role_cache_key`.

### Why role isolation is the right lever

All 17 Q8_0 roles in this model are geometrically eligible — every one has
`in_features % 32 == 0` and `out_features > 256`:

| role | in_features | out_features | count |
| --- | --- | --- | --- |
| `attn_gate` | 6144 | 2560 | 36 |
| `attn_qkv` | 10240 | 2560 | 36 |
| `ssm_out` | 2560 | 6144 | 36 |
| `attn_q` | 12288 | 2560 | 12 |
| `attn_k` / `attn_v` | 512 | 2560 | 12 each |
| `attn_output` | 2560 | 6144 | 12 |
| `shared_gate` / `shared_up` | 640 | 2560 | 48 each |
| `shared_down` | 2560 | 640 | 48 |
| `hc_attn_up` / `hc_ffn_up` | 10240 | 320 | 48 each |
| `hc_attn_down` / `hc_ffn_down` | 320 | 10240 | 48 each |
| `ple_key` | 10240 | 2560 | 1 |
| `ple_value` | 2560 | 2560 | 1 |
| `expert_down` | 2560 | 640 | 5 |

The recorded whole-route failure is therefore numerical, not a geometry
artifact, and no eligibility rule separates the roles. The role scope is the
only available lever.

## Validation

- `tests/test_unit_qwen4exp_iu8_scope.py`: **13 passed**.
- Adjacent dispatch bundles (`test_unit_qwen4exp_iu8_scope.py`,
  `test_unit_qwen4exp_dense_wide_dispatch.py`,
  `test_unit_qwen4exp_dispatch_counter.py`): **45 passed**.
- **Mutation-tested, not just green.** Six mutations were applied to the
  implementation and each was required to turn the suite red; all six did:

  | mutation | result |
  | --- | --- |
  | M1 scope ignored entirely (`scope = None`) | RED |
  | M2 unplaceable weight treated as in-scope | RED |
  | M3 prefix match relaxed to substring | RED (after adding the segment-wise case) |
  | M4 empty scope means no roles | RED |
  | M5 key = flag only (the exact pre-fix shape) | RED |
  | M6 scope in key but role omitted | RED |

  M3 initially survived and exposed a real gap: the suite did not distinguish
  prefix from substring matching. `test_role_match_is_segment_wise_not_substring`
  was added and now kills it. Baseline and restore were green at every step.
- `slot_path` population was confirmed at the source rather than assumed:
  `qwen4_exp_materialize.py` builds every layer weight as
  `device_spec(f"layers.{layer.layer_id}.{slot}", ref)`, and the slot names in
  `qwen4_exp_gguf.py` (`_COMMON_LAYER_SLOTS`, `_QSA_LAYER_SLOTS`,
  `_GDN_LAYER_SLOTS`, `_PLE_LAYER_SLOTS`) are exactly the roles the scope
  matches. Had `slot_path` been absent, a scoped route would have declined every
  weight and read as "narrowed" while actually being disabled.

## Next

- Run the canonical numerical gate per role, using the scope to isolate each
  role family. The whole-route arm is already known to fail the envelope, so the
  measurement of interest is which roles pass alone and whether any passing set
  is worth promoting.
- If no role set passes, the row is finally rejected and the flag, the scope,
  and the route are removed together.
