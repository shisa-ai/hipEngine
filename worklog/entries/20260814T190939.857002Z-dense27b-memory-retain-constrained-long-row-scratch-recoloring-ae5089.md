# Retain constrained long-row scratch recoloring

## Summary

Retained a capability-scoped long-row scratch-placement order for gfx1100
Qwen3.6-27B Q4_K_M. The 4K-row arena falls from 401.0625 to 372.375 MiB;
tracked peak falls exactly 28.6875 MiB and sampled whole-device peak about
31.47 MiB at both 4K and 8K. Memory parity remains open: current Vulkan gaps
are 0.340/0.482/0.901/0.902 GiB at 512/1K/4K/8K.

## Changes

- Factored deterministic arena planning from allocation and retained the
  established size-first plan as the baseline/fallback.
- Registered `priority_min_live_stages=5` and `priority_min_rows=4096` only for
  the gfx1100 `(Qwen3.6-27B, MOSTLY_Q4_K_M)` dense policy. Eight long-lived
  fields move first; `attn_out` remains at 48.0625 MiB; a candidate is selected
  only when strictly smaller.
- Added RED/GREEN coverage for the exact arena, `attn_out` address, and the
  rows<4096 size-first requirement. Unrestricted recoloring reproducibly made
  the second short-row NextN target-logit row NaN while a size-first control
  passed, so the explicit long-row boundary is a correctness constraint.
- Published the compact artifact and synchronized the benchmark README,
  changelog, and dense campaign summary.
