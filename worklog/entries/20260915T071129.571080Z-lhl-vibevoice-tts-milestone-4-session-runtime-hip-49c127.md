# VibeVoice-TTS milestone 4: torch-free generation session on HIP

## Summary

The full VibeVoice-TTS generation loop now runs torch-free on HIP and
reproduces the frozen torch oracle's constrained greedy chain exactly
(27/27 tokens, 25 diffusion frames, 25 decoded chunks) on the pinned
`microsoft/VibeVoice-1.5B` single-speaker request.

## Changes

- `hipengine/loading/vibevoice_tts_session.py` (new): session bundle loader —
  Qwen2 backbone under the `model.language_model.*` prefix with the **tied**
  lm head (`tie_word_embeddings=True`; logits share the embedding table),
  both SpeechConnector bundles, both tokenizer encoder bundles, and the
  decoder/diffusion bundles by delegation. Pins the fork's control tokens:
  speech start 151652 / end 151653 / diffusion 151654, EOS 151643
  (`<|endoftext|>` — not `<|im_end|>`).
- `hipengine/runtime/vibevoice_tts_session.py` (new): single-sample session —
  two `VibevoiceQwen2Runtime` instances (positive + negative), the frontend
  encoders, the decoder and diffusion head; prompt construction with speech
  rows spliced over placeholders; the fork's 5-token host-side constraint
  mask; boundary resets on speech_start/speech_end; per-frame
  diffusion → decode → semantic encode → `acoustic_connector(latent) +
  semantic_connector(mean)` feedback embedding fed at the next forward.
- `hipengine/runtime/vibevoice_qwen2.py`: added `hidden_state()` — the
  post-final-norm last row (the fork's `last_hidden_state[..., -1]`,
  the diffusion condition). D2H must reinterpret the bf16 buffer as bits;
  reading it as fp32 silently garbage-reinterprets (caught by the fixture).
- `hipengine/runtime/vibevoice_encoder.py`: added `encode_chunk_streaming()`
  — one causal-conv frame batch with a **caller-owned** cross-call tail
  state dict, which the TTS feedback path requires (the fork's
  `use_cache=True` encode continues conv tails across 3200-sample chunks).
- `tests/test_live_vibevoice_tts_session_gpu.py` (new): 5 gates — voice
  prompt path, full 121-position prefill trace, exact chain, condition
  trajectories, decoded PCM.

## Fixture-verified semantics (empirical, not derived)

- Diffusion condition timing: the condition is the hidden of the forward
  that *produced* the diffusion token (prefill's last row for call0), not
  the row after feeding it.
- Negative LM: accumulates `[embed(speech_start), feedback_0, ...,
  feedback_{n-1}]` across the frames of one speech span; the first frame of
  a span pushes the bare `speech_start` id (the fork's inputs_embeds
  override is None there). call0/call1/call2/call12/call24 all match the
  `callN_neg_condition` fixtures at bf16-noise level (rel ≤ 0.011).
- Boundary resets (semantic tails, decoder state, negative cache, noise
  draw counter) fire on the freshly generated token, before its feedback.

## Envelope attribution (measured)

- The encoder/`features_scaled`/`connected` gates sit on the fork's own
  GPU-bf16 noise floor: my CPU fp32 port and GPU runtime agree with each
  other (0.55 abs at the tail), and both sit ~0.87 abs from the fixture
  across the 26-block stack — the same magnitude as fork-GPU-vs-fork-CPU,
  verified by replaying the fork's encoder in the pinned venv
  (/tmp trace matched my port to 2e-4; the fixture differs by 0.87).
- The fork's final prompt frame (69) is a tail-padding-convention outlier
  (~9 abs); frames 0–68 agree and the frozen chain is insensitive to it.
- The generate-phase prefill re-samples the voice prompt (second RNG draw
  not recorded in fixtures), so session conditions carry a ~0.044 rel
  baseline offset vs the explicit-prefill fixtures; the diffusion
  trajectory compounds it with call depth (latent 0.018 → 0.336 by
  call24, PCM peak-relative ≤ 0.20, pooled RMS within 18%) — the same
  inherent bf16-compounding class attributed in milestone 3.
