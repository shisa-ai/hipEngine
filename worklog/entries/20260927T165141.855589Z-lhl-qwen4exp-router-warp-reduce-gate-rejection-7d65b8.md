# Router warp-reduce rejected by the production gate: discrete selection is the amplification node

## Summary

The 450-row production gate **rejected** the warp-per-token router candidate. The
kernel win is real and large, and it still fails admission.

| gate | result |
| --- | --- |
| numerical | **FAILED** |
| task | **FAILED** (`requires_review`, 12/18 exact) |
| state / determinism | passed (3 runs, byte-identical trajectories) |
| lifecycle | passed |

| metric | value | budget | |
| --- | ---: | ---: | --- |
| mean KL | 5.714e-4 | 1e-3 | pass |
| p95 KL | 2.322e-3 | 5e-3 | pass |
| p99 KL | 6.228e-3 | 2e-2 | pass |
| max KL | 3.344e-2 | 5e-2 | pass |
| **top-1 agreement** | **98.67%** (444/450) | >= 99% | **fail** |

Scope failures: `category/mixed_ja_en` (mean KL 1.083e-3), `shape/prefill_last`
and `transition/prefill_to_c1` (mean KL 3.515e-3, 3.5x over budget). The two
`prefill_last` scopes fail on **KL, not top-1** - top-1 is 100% there.

`measurement_valid: true` with `candidate_dispatch_calls: 4320` across
`(rows, 2560, 512)` shapes at rows 39-52. The route admits at `rows >= 2` and the
suite's 39-71 token prompts clear it, so this is a real execution and not the
silent no-op `docs/REFACTOR.md` warns about for `rows > 256` routes.

## The finding: the router's discrete selection is the amplification node

The mechanism is discrete, and the gate's own fields say so:

| field | value |
| --- | ---: |
| `flip_eligible_rows` | 48 (10.7%) |
| `top1_mismatches_flip_eligible` | **6** |
| `top1_mismatches_outside_flip_eligible` | **0** |
| `max_abs_logit_delta` | 1.673 |

Every top-1 mismatch sits on a row whose strict top-1 margin is small enough for
the observed drift to explain it. The router logits feed `qwen35_router_select`,
so a near-tie changes which of the 512 experts is selected, which turns a 4.9e-7
logit difference into an O(1) model-logit change.

**A passing KL envelope next to a failing top-1 is the signature of a discrete
amplification node, not a numerically sloppy kernel.** Mean KL uses 57% of its
budget while top-1 misses by 0.33 points.

This generalises past this candidate. It is the mechanism behind the GR family's
existing note that it "is closed to arithmetic change": a router flip changes
which experts run, so every downstream GR or dense route inherits the same
saturation regardless of how accurate its own arithmetic is. Treat the router
selection as the amplification node for the whole model's arithmetic-change
design space.

**Tuning the router kernel cannot clear this gate.** Any reduction-order change
moves the logits by ~1 ulp and flips the same near-ties. The candidate's 2.16x is
not recoverable by a better kernel of the same shape.

## Next

- **Do not spend another kernel attempt on this route.** The reopening path is to
  make the *selection* invariant rather than the arithmetic: rank experts on a
  quantized logit with a deterministic tie-break so a 1-ulp difference cannot
  reorder them. That has to apply to the reference too, so it re-baselines strict
  and is a campaign-level decision, not a kernel change.
- The 2.16x is worth keeping on record as the size of the prize that the discrete
  selection currently blocks. If a later decision makes selection
  reduction-order-invariant, this candidate is the first thing to re-run.
- The GR section of `docs/REFACTOR.md` should be re-read in this light: its
  "reopen only with a confirmed router-flip mechanism" condition is now met in
  its mechanism but not in its remedy, and the GR routes share this node.
