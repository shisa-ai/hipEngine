# The P6e engagement gate was a false negative; rebuilt on the while-live observed peak it still fails

Supersedes `worklog/entries/20260911T184651.925943Z-lhl-p6e-resumable-path-not-engaged-94394e.md`.

## Summary

The previous entry concluded that the P6e service proof measures the default
chunk-outer route rather than P6's resumable yield. It rested on two claims: that
no harness enables `HIPENGINE_GGUF_PACKED_LAYER_OUTER`, and that a re-run with
the flag on still showed a zero oracle-owner peak. The first claim is solid. The
second was produced by an indicator that cannot work, and this entry corrects it.

## The gate that was wrong

The gate polled `hipengine_resident_prefill_oracle_owner_bytes` /
`hipengine_resident_prefill_oracle_owners` over HTTP from a separate thread
during the blocking arm. `qwen35_gguf_runner.py:22425` documents why that reads
zero regardless of engine behaviour:

> `/metrics` scrapes block on the loop lock while a synchronous prefill runs, so
> out-of-process polling can never observe these buffers while live (F4 in the
> server/direct parity roadmap). This is the while-live capture.

The engine keeps `_int8_prefill_oracle_observed_peak_bytes` /
`_int8_prefill_oracle_observed_peak_owners` as a running max recorded at release
time for exactly this reason. The gate was therefore guaranteed to fail, and its
failure carried no information about the route. This is the same defect class the
gate was added to catch: an assertion that cannot be satisfied by the condition it
claims to test.

## Changes

- The gate now reads `hipengine_resident_prefill_oracle_observed_peak_owners` and
  `_bytes` from a settled scrape after the long request completes, and records the
  live gauge beside them so the false negative stays visible in the artifact.
- The out-of-process oracle poller was deleted, and so was the now-unused
  `_peak_metric_during` helper.
- The harness records `packed_layer_outer_env_seen` (the value the process
  actually sees inside `_temporary_environment`) so "the flag was passed" is no
  longer conflated with "the engine read the flag".
- A unit test asserts `_gguf_packed_layer_outer_enabled()` returns True for `1`,
  False for `0`, and False when unset, so a plumbing failure cannot be mistaken
  for an engine result.
- Tests were added for the corrected gate: it passes on a non-zero observed peak
  while the live gauge reads zero, fails on zero observed peak, fails when the
  metrics are absent, and fails on owners-without-bytes.

## Validation

With the corrected indicator the gate **still fails**, now for a reason it can
actually support:

| Gate | Result |
| --- | --- |
| `cancellation_reached_backend` | PASS |
| `resumable_path_engaged` | **FAIL** |
| `survivors_exact` | PASS |
| `blocking_survivor_exact` | PASS |
| `slow_consumer_survivor_exact` | PASS |
| `bounded_acknowledgement` | PASS |
| `bounded_decode_gap` | PASS |
| `cleanup` | PASS |

Measured: `packed_layer_outer_enabled: true`, `packed_layer_outer_env_seen: "1"`,
`oracle_observed_peak_owners: 0.0`, `oracle_observed_peak_bytes: 0.0`,
`live_oracle_owners: 0.0`.

So the flag reaches the process and the layer-outer route still does not run. The
seven passing gates are genuine measurements of the **default** chunk-outer route.
P6's resumable mechanism remains demonstrated only by the direct-call GPU proof
(`scripts/gguf_resumable_prefill_gpu_proof.py`), which invokes the resumable entry
point directly and bypasses the scheduler.

24 tests pass. `performance_claim` is false and no scoreboard row changes.

## Honest limits

- The gate proves the route did not engage. It does not identify which condition
  declined, because `last_packed_prefill_plan.executor_mode` — the field the code
  says exists to distinguish the layer-outer executor from the chunk-outer
  fallback — is collected in the diagnostics but not exported to `/metrics`.
  `fallback_reasons` is exported as labeled counters, and its absence from the
  scrape means the `int8_direct` branch was not entered at all, but that is
  inference from a counter that was empty rather than a recorded reason.
- The reference and long prompts both ran; only the long-prompt arms are
  instrumented for engagement.

## Next

- Export `last_packed_executor_mode` to `/metrics` so a decline names itself
  instead of being inferred from an absent counter.
- Decide whether the service should be made able to reach the resumable route, or
  whether the service-level P6e claim should be withdrawn and the deliverable
  evidenced by the direct-call proof alone.
