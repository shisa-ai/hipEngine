# Reproducible Q4 prefill benchmark script; artifact command is now executable

## Summary

The prefill artifact's ``protocol.command`` was a placeholder heredoc, so the
headline 1.52x could not be re-run from the repository. It now names a
committed script, and the artifact carries the observed run-to-run spread
rather than a single ratio presented as exact.

``scripts/vibevoice_asr_q4_prefill_bench.py`` loads the dense bf16 lane and the
Q4_K_M lane in one process, builds the fixture prompt once, times
``runtime.prefill_rows`` over N repetitions after a warmup, then runs a greedy
16-token chain in each lane and reports whether the two produced identical
tokens. Both lanes route through ``prefill_rows``: bf16 via hipBLASLt fp16
GEMMs, Q4 via the raw-block Q4_K/Q6_K WMMA prefill kernels.

## Changes

- `scripts/vibevoice_asr_q4_prefill_bench.py`: new, committed.
- `benchmarks/results/2026-09-14-gfx1151-vibevoice-q4-batched-prefill.json`:
  `protocol.command` is the real invocation; new `reproduction` block with five
  runs, the speedup ranges, and a variance note.

## Validation

- The documented command was run verbatim:
  ``python3 scripts/vibevoice_asr_q4_prefill_bench.py --reps 5 --gguf
  /tmp/vibevoice-asr-q4km.gguf`` -> prefill 0.337 vs 0.240 s (**1.40x**),
  greedy 1.502 vs 1.090 s (1.38x), token chains identical, exit 0.
- Five recorded runs: prefill speedup **1.40-1.49x**, greedy **1.34-1.42x**,
  token chains identical in every run.

## Variance, stated rather than hidden

The original measurement recorded 1.52x (0.296 vs 0.195 s). The script
reproduces 1.40-1.49x with both lanes roughly 15% slower in absolute terms.
The zbook is power and thermal limited and other GPU work was running
concurrently, so absolute values drift between sessions while the ratio and the
direction are stable. The artifact now says explicitly that the absolute
numbers are not a publication figure and that final measurements belong on the
desktop gfx1151 under an idle GPU.
