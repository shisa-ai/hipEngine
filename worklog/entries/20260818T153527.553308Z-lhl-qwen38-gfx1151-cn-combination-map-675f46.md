# qwen38 gfx1151 c=N decode combination map

## Summary

Unit 3 of the c=8 GEMV decode campaign: make every decode concurrency c=N
land on a native owner, not WMMA prefill. After unit 2 (single Q4/Q5
projections rowtile 2-8), a dispatch sweep showed single Q4 projections still
fell to `t16_wmma_prefill` for every c in 9..511 (the Q4T16
`rows > 1 -> wmma_prefill` rewrite), Q4 gate/up dual rowtile8 policy capped at
rows 64, and the Q6 lm_head rowtile was still chunked 4+4 at c8. All three
gaps are closed. No decode concurrency below 512 uses WMMA anymore.

## Changes

- `runtime/gguf_linear.py`:
  - `_native_rowtile_chunk_groups(weight, ...)`: in a `native_batch_decode_session`,
    decomposes rows 9..511 into `_rowtile8_row_chunks` groups (all groups 2..8,
    tail-1 folded) when the quant would resolve to a `t16_wmma_prefill` leaf
    AND has a registered native rowtile owner. Q5 keeps its direct grid.y=rows
    leaf (never hits WMMA); rows >= 512 stay on WMMA prefill (bulk regime).
    New `_NATIVE_ROWTILE_CHUNK_MAX_ROWS = 512` bound.
  - `launch_gguf_linear` now iterates those groups (recursing per chunk with
    row offsets) after the exact-shape `_native_split_row_chunk` mechanism.
- `kernels/hip_gfx1151/__init__.py`: `GGUF_DENSE_PAIR_SILU_NATIVE_DECODE_
  POLICIES` gate/up dual rowtile8 admits rows 2..511 (was 2..64); the
  `_rowtile8_row_chunks` dispatch path already handled arbitrary c>8.
- `kernels/hip_gfx1100/quant/gguf_q6_k_t16_gemv.hip`: `launch_q6_t16_rowtile`
  and `launch_q6_t16_rowtile_col8` (standard Q6, 35B) and
  `launch_q6_t16_qmicro_planar_rowtile_col8` (qmicro planar, 27B lm_head) now
  instantiate ROW_TILE 5..8; the qmicro planar f32 symbol routes rows 3..8 to
  col8.
- `runtime/qwen35_gguf_runner.py`: `_verify_lm_head_rowtile` accepts rows 2..8
  (was 2..6), `_verify_lm_head_rowtile_chunked` goes direct to rows 8 and
  `GGUF_Q6_LM_HEAD_MAX_CHUNK` bound is [2,8].
- `kernels/hip_gfx1151/__init__.py`: `GGUF_Q6_LM_HEAD_MAX_CHUNK = 8` (was 5),
  so c8 lm_head is a single rows-8 launch instead of 4+4.

## Validation

- Dispatch: `test_gfx1151_q4_t16_single_c_n_chunks_to_rowtile8_in_native_session`
  (c=9 -> 7+2, c=16 -> 8+8, c=512 stays WMMA, Q5 direct leaf unchanged) and
  `test_gfx1151_q4_t16_gate_up_rowtile8_chunks_rows_65_plus` (c=70 -> eight
  8-row groups + 6-row tail, one q8_1 quantize per group).
- RED: `test_q4_t16_dense_c_n_chunked_rowtile_composes_bit_exact_vs_c1` (rows
  9/10/16/17 chunked vs serial c1, 4/4 bit-exact) and the Q6 lm-head rowtile
  RED now covers rows 2..8 direct (`max_chunk=8`) on the 35B fixture.
- Backend capability tests updated for the extended policy ranges; full
  dispatch/backend/decode/Q6 bundles green.
- Bench (c1/c4/native_c8, 3 measured runs): c1 12.88, c4 42.5 agg (3.30x),
  **native_c8 57.41 tok/s agg (4.46x c1, 7.18/stream)** vs unit-2 56.64
  (+1.36% from the single-launch c8 lm_head), no regression, no env override
  needed (`GGUF_Q6_LM_HEAD_MAX_CHUNK` default 8 replaces the 4/5 workaround).
- `rocprofv3` c8 kernel trace: `q6_k_t16_qmicro_planar_gemv_rowtile_col8_
  kernel<float, 8>` runs once per decode token (8 launches for the 8-row
  steady window) - single rows-8 lm_head launch instead of the prior 4+4
  chunk; no WMMA prefill in the decode step; c1/c8 all tokens exact (9707).
  Note: the 27B lm_head is qmicro-planar Q6, so the standard-Q6 rowtile
  extension (35B fixture) and the qmicro-planar col8 extension were both
  needed; both RED-verified rows 2..8.
- Artifact: `benchmarks/results/2026-08-18-gfx1151-qwen38-27b-cn-
  combination-map.json`; CHANGELOG one-liner added.
