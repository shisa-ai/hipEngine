# Register the staged-f32 dense Q8_0 route, off by default

## Summary

The staged-f32 tile is now a **registered route** rather than a screen prototype,
selected only when `HIPENGINE_QWEN4_EXP_Q8_STAGED_F32_LAYERS` names a layer
scope. This is the step that turns the measured 1.23x-2.22x into something a
production gate can actually evaluate.

**No default changed.** The route is off when nothing binds it, and a test pins
that property directly: with the variable unset, the dispatch returns the exact
leaf object unchanged. That is the load-bearing safety property, because the
route's arithmetic is not bit-identical to the leaf it replaces.

What was wired:

- **Registration.** `STAGED_F32_VARIANT = "staged_f32_bm128_bn64_bk32"` for
  `(hip_gfx1151, linear, gguf_q8_0)`, resolving to `gr_staged_f32_up`.
- **Dispatch.** `_raw_k_staged_f32_dispatch` in `hipengine/runtime/gguf_linear.py`,
  called after `_raw_k_coltile_pipelined_dispatch` so an opt-in scope replaces
  the pipelined exact leaf. It claims only the exact-chain variants, so it can
  never take a dispatch another route already owns.
- **Layer scope.** `_q8_staged_f32_layers()`, parsing a comma-separated scope.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_q8_0_gr_staged_f32.py`: `gr_staged_f32_up`
  now accepts `threads` for the `raw` launch ABI. It raises on any value other
  than `None` or 256 rather than ignoring it, because the tile's block size is
  fixed by its geometry and a caller that believes it is choosing a geometry
  should be told it is not.
- `hipengine/kernels/hip_gfx1151/__init__.py`: `STAGED_F32_VARIANT` and the
  registration block.
- `hipengine/runtime/gguf_linear.py`: `_Q8_STAGED_F32_LAYERS_ENV`,
  `_Q8_STAGED_F32_VARIANT`, `_q8_staged_f32_layers`,
  `_raw_k_staged_f32_dispatch`, and the call site.
- `tests/test_unit_qwen4exp_staged_f32_route.py` (new): 8 tests.
- `docs/REFACTOR.md`: promote-or-remove trigger, plus the two things a future
  reader must know (the `=0` footgun and the duplicated variant name).

The 8 new tests cover, in the order they matter:

1. **`test_dispatch_is_a_no_op_when_the_route_is_unbound`** - with the variable
   unset, the dispatch returns the exact leaf **object identity** unchanged. This
   is the "no default changed" claim as an executable check.
2. **`test_variant_name_agrees_between_runtime_and_backend_package`** - the name
   is a literal in `gguf_linear.py` (so `hipengine.runtime` does not import a
   backend package eagerly) and a constant in the backend package. If they drift,
   the dispatch silently no-ops and the route looks enabled while doing nothing.
3. **`test_dispatch_swaps_only_inside_the_named_scope`** - swaps inside the
   scope, leaves the object untouched outside it, and leaves a weight with no
   layer index alone.
4. **`test_route_is_off_when_nothing_binds_it`** and
   **`test_layer_zero_is_layer_zero_not_off`**.
5. **`test_registration_resolves_to_the_staged_launcher`** - the registered
   callable is the staged launcher, not a sibling.
6. **`test_staged_launcher_rejects_a_geometry_it_would_ignore`**.

**A test caught a real design ambiguity.** The first version asserted that
`=0` means off. It does not and should not: layer 0 is a real index and a
one-layer scope is a legitimate request, so there is no in-band way to spell both
"layer 0" and "off". The parser is right and the test was wrong; the semantics
are now pinned by a dedicated test and the footgun is documented in both the
function docstring and `docs/REFACTOR.md`. This is the opposite of the sibling
wide route, whose parser treats empty as "every layer" - for a route that is not
bit-exact, an unset environment must leave the exact chain in place.

Host for the build/registration check: Radeon 8060S (gfx1151), TheRock staging
`therock10-staging-20260828`, `HIPENGINE_HIP_ARCH=gfx1151`.

## Next

**Run the production gate.** The route is now evaluable by
`scripts/execution_profile_q8_wmma_prefill_layers_gate.py`, which takes routes
via its `SELECTORS` table and evaluates a layer-scoped candidate against the
exact chain on the canonical exact-token fixture with calibrated mean/tail/max KL,
top-1 and same-schedule determinism. Adding the route means a `Route` entry with
`candidate_env={HIPENGINE_QWEN4_EXP_Q8_STAGED_F32_LAYERS: "{layers}"}`,
`teacher_env={...: ""}`, and a new artifact `kind`.

That gate is the remaining blocker. Nothing else about this candidate is
unmeasured except natural activations.

Do not make the route default before the gate passes. `docs/REFACTOR.md`
carries the promote-or-remove trigger and the removal file list.

Task #3 remains open.
