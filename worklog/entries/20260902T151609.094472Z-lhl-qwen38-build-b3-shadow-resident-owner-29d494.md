# Qwen3.8 B3 adds resident shadow owner pool ABI

## Summary

Implemented the unselected resident-owner pool ABI required by B3's adapter
boundary. One shadow acquisition now borrows an additional available session,
allocates separately keyed KV capacity, allocates a hidden row, and exposes the
shadow recurrent scratch. No state is cloned and no physical target route is
selected, so current C1 behavior remains unchanged.

## Ownership and cleanup

`acquire_c1_shadow_resources` validates the negative request key, distinct
slots, real admission, dynamic KV pool, spare session, recurrent scratch, and
real page count before binding the shadow allocation. It pops the lease only
after bind/hidden allocation succeed and available-order ownership is stable.

The lifecycle returns eight non-provider claims (four surfaces × two lanes).
The owner accumulates those claims and finalizes once: free hidden, invalidate
and unbind shadow target graphs/KV, release the shadow KV key, reset the session,
return the lease, and remove the bundle. Abort is whole-bundle and idempotent.
No-free-session failure has zero side effects; bind/hidden/order failures unwind
temporary resources.
