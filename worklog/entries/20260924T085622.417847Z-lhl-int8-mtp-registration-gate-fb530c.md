# The INT8 automatic c2 gate is provider registration, not selection

## Summary

The corrected run reached the INT8 cell for the first time and answered the
readiness row. The INT8 group declaration resolves at a realized width of two;
what stops the cell is that the requests are never registered with the MTP2
provider, so the plan reports AR-only and every step falls back with
`no_provider`.

```
selected_route: speculative_mtp
selection_reason: implemented_gguf_dense_int8_gfx1151_group_native_chain
effective_route: default
decision_reason: backend_k0_fallback
execution.plan_group_rows: 2
execution.plan_ar_only: true
execution.plan_reason: no_provider
execution.provider_readiness: declined
execution.provider_decline_reason: request 26 unregistered or disabled
fallback_reason: no_provider
```

At width 1 the same run reports `plan_ar_only: false`,
`plan_reason: speculative_qualified`, `provider_readiness: ready` and engages.
So this is a registration gap for realized groups wider than one, not a
selection default and not a capability miss.

Both earlier readings of this row are superseded. The static width bound was
real and is fixed (`7c3914162`), but on the INT8 cell it is no longer what
declines the group -- the declaration that resolves is the group chain. The
BF16 evidence-row reading came from running the automatic sweep without a KV
selector, which is why the third cause was misattributed to INT8.
