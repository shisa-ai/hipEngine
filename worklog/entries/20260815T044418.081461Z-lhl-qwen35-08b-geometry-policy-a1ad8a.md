# Key 0.8B decode policies by geometry

## Summary

Three D08 decode policies still keyed backend admission to the mutable GGUF
`general.name` string. That violated the existing geometry-policy rule: renamed
or community exports with identical execution topology lost qualified routes,
while a misleading matching name could admit a different topology. All three
now use immutable geometry plus quant file type.

## Changes

- Added `QWEN35_DENSE_H1024_GEOMETRY`, matching the validated 24-layer 0.8B
  model topology.
- Migrated fused dense pair-SiLU, dense-down residual, and fixed-H1024 norm/
  residual policy keys from `(model_name, file_type)` to `(geometry, file_type)`.
- Reused `_gguf_policy_identity()` at all three runtime consumers, including
  their hot caches; incomplete or malformed compatibility fixtures fail closed.
- Updated backend policy assertions and tests so an arbitrary renamed finetune
  is admitted, while one-field geometry drift, Q8, wrong shape, and peer backend
  all retain fallback owners.

## Validation

- RED: all three qualified-route tests failed when the fixture name changed,
  demonstrating the prior name dependency.
- GREEN focused route nodes: 3 passed.
- `uv run pytest -q tests/test_qwen35_gguf_prefill_scratch_liveness.py` —
  30 passed.
- `uv run pytest -q tests/test_qwen35_gguf_geometry_policy.py` — 5 passed.
- Focused gfx1151 dense-down and norm backend policy nodes — 2 passed.
