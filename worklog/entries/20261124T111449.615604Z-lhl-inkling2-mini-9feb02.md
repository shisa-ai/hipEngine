# Withdraw the resident block row-count dependence

## Summary

The resident block is wrong at every row count, not only above 64. A sweep of 32/64/96/128/151/192 rows shows a max absolute logit difference between 8.4 and 14.5 at all six sizes, so `20261124T111408.733860Z-lhl-inkling2-mini-176b94.md`'s row-count conclusion is withdrawn. The KL varies by prompt from 2.9e-03 to 4.6e-01 at those same sizes, which is why a single 64-row measurement looked clean.

## Changes

- Row sweep on one depth, host `prefill_block` first so the block path is deterministic, comparing block logits against the host for each size.

- Top-1 agrees at every size, so the error is a small set of badly wrong rows rather than a shifted distribution.
- The earlier 64-row KL of 2.185e-04 and the 2.9e-03 here are the same size of error on different prompts; the max-abs column is the stable signal at 7 to 14 logits throughout.
- The four block-only row kernels have no row tiling, so a tile-mask bug is ruled out.
