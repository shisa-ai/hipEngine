# Share dense GGUF C1 checkpoint journal ownership

## Summary

Move the dense GGUF single-request provider/target checkpoint orchestration to the existing `SpeculativeStateJournal`. Kernel calls, arithmetic, graph selection and packed-provider routes are unchanged. Public parent/candidate parity and device failure/cancellation checks pass.

## Changes

- `qwen35_gguf_mtp2.py` captures the provider checkpoint before proposal and registers the prepared target transaction before verification results can be published. Reverse rollback restores target then provider.
- A separate checkpoint restore-eligibility bit distinguishes an open backup from a retired backup awaiting release. Containment after commit or rollback cannot restore a retired backup when release fails.
- Failed restore/release keeps the request registered and disabled until cleanup succeeds. Teardown records completed verifier/buffer/provider/group release phases and retains pending owners. Adapter close continues across request failures and preserves interrupts in a `BaseExceptionGroup`.
- Packed and physical-provider routes retain their explicit checkpoint sites: they do not expose an adapter-level target transaction to transfer. No change to `transaction.py` is needed.

## Validation

- The implementation worker reports 21 focused ownership tests and 718 related tests passing before final cleanup review. Independent validation passes 227 focused tests on the final implementation; the default CPU unit suite and deterministic bundle also pass.
- Review exposed and repaired restore-after-commit, swallowed-restore, repeated-release and cleanup-interrupt failures. Regression tests failed before their repairs.
- Frozen parent and candidate public runs on Radeon 8060S (`gfx1151`), Qwen3.8-27B GGUF Q4_K_M/BF16 KV: 24 calls total, lengths 37/257, one active request greedy and temperature 0.7/seed 871, two active requests greedy, 32 outputs per request and two repeats. IDs, acceptance, candidate counts and sampler routes match. Single-request candidate calls actually capture provider and target through the journal; packed calls keep the old ownership sites.
- Four injected device failure/cancel cases restore the target position, release the journal, preserve the committed cancellation prefix, and match baseline IDs on the next request. Every process closes with zero tracked allocations. Source hashes remain unchanged.
- [Commands, source patch and raw checks](../../docs/testing/2026-10-24-dense-c1-checkpoint-journal/NOTES.md) record the device validation. This is a host ownership refactor, not a performance or quality claim.
