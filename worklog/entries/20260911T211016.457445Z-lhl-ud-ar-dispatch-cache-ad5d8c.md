# Stabilize dense-IQ dispatch cache owner semantics

## Summary

Diagnosed the UD-Q4_K_M natural25 AR denominator on physical GPU1. The
target-only eager path measured 65.05 ms/transition while the same prompt and
resident state measured 31.13 ms/transition through the existing one-step HIP
decode graph. A protocol-matched rocprof census showed essentially identical
GPU work: eager 28.77 ms/transition and graph 28.88 ms/transition. The gap is
therefore eager host submission across roughly 860 kernels, not MTP residency,
prefill mode, contention, or different model arithmetic.

The inspection also found that the GGUF linear dispatch cache keyed the
dense-IQ owner by a transient Python object id. Equivalent owner re-entry
missed the cache, while Python id reuse could make a slot-pinned context reuse
an unpinned local32 dispatch. Replaced object identity with the semantic owner
state. This is a correctness/cache-stability fix, not the primary AR speed fix:
the post-fix eager remeasurement remained 69.29 ms/transition and graph
remained 31.15 ms/transition.

## Changes

- Key dense-IQ dispatch resolution by owner presence, activation-plane
  presence, prefill strict slots, and decode strict slots.
- Added regression coverage proving equivalent owner contexts reuse the cache
  and disabled/unpinned/pinned contexts remain distinct.
- Added a direct state-signature test covering workspace-free and
  workspace-backed owners plus both pin sets.

  `tests/test_gguf_linear_dispatch_cache.py`; `74 passed` across
  `tests/test_gguf_iq_local32_decode.py` and

  measured eager scalar-prefill 65.05 ms/step, eager bulk-prefill
  63.97 ms/step, and graph scalar-prefill 31.13 ms/step before the fix.

  with identical final token `10300`.
- GPU1 cached-only profiler traces:
  `/tmp/ud-ar-eager-rocprof-gpu1/ud-ar-eager_kernel_trace.csv` measured

  uncommitted per artifact policy.
