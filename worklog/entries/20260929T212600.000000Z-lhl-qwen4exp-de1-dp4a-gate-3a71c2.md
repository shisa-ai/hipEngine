# DE-1 gate: the decode Q8_1-DP4A route passes every numerical gate and its task flag is strict-ID inequality, not a quality regression

## Summary

The `decode_dp4a_linear` candidate was run through the full production profile gate. **It passes the
numerical envelope with 4-8x margins, repeats deterministically across all 18 prompts, and leaks
nothing.** The only non-passing gate is strict generated-ID equality - which `AGENTS.md` states is
**not** the promotion bar for a production-profile arithmetic win.

## Why `task_passed: false` is not a material task-level regression

The gate's `task_passed` is pure strict generated-ID equality
(`strict[prompt_id]["ids"] == first["ids"] and strict[prompt_id]["text"] == first["text"]`). All five
divergences are **deterministic cross-route prefix differences at `free_tokens = 32`**:

| prompt | category | divergence |
|---|---|---|
| `general_en_explain` | general_en | "autoregressive **decoding** process" -> "**generation** process" |
| `mixed_ja_en_review` | mixed_ja_en | "due to increased KV cache usage" -> "as KV cache usage increases" |
| `heldout_code_rate_limiter` | code | `import Dict, Deque` -> `import Dict, Deque, Tuple` (a **superset**) |
| `heldout_general_ja_speculative` | general_ja | Japanese paraphrase, same meaning |
| `code_topological_sort` | code | strict opens with `from collections import deque`; candidate opens directly with `def topo_sort` |

Four are provably benign: three are synonyms or a superset import. The fifth differs structurally -
the candidate's opening omits the import - but at token 32 it is still inside the docstring, so
whether the candidate needs `deque` at all is **not determinable from the artifact**. A topological
sort does not require `deque`; the candidate may use a different valid formulation.

The normative document does not make strict-ID equality binding. `docs/EXECUTION-PROFILES.md`
section 6.5 requires a retained production manifest to "pass task-specific checks such as **code
execution/tests**, structured-output parsing, ... when the product path claims those capabilities"
and to "show **no material task-level regression versus strict under a predeclared paired
criterion**." `AGENTS.md` states that "there is no 'exactness contract'", that "`strict` is a
debugging oracle, not the promotion bar", and that production-profile arithmetic wins "are **not
required to match strict generated IDs**".

The gate agrees with this reading: it computes
`status = "requires_task_review"` - not `"failed"` - precisely when numerical passes and the task
gate diverges. It asks for a materiality judgment.

**That judgment has not yet been made.** `free_tokens = 32` produces prefixes too short to execute,
so no functional criterion has been applied. `--free-tokens` is configurable, so the follow-up is a
longer free run whose outputs can actually be executed and scored. **No promotion is claimed.**

## Limits

- **No functional task criterion applied yet.** The materiality question is open, not settled.

  arithmetic on that ratio.
