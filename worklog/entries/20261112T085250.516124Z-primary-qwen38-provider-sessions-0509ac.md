# Reuse target-owned resident sessions for feature drafters

## Summary

EAGLE-4 and DSpine now acquire sessions from their target generator instead of
constructing unowned default sessions. Immutable target weights are shared and
request state resets on return to the pool. The pinned target context remains
binding; the request and its draft workspace must fit it.

## Changes

- Route both providers through `_get_shared_runner()` and
  `_resident_session_scope()` after preparing the requested KV policy. The target
  owner transports its profile, recurrent-state and verifier choices as on the
  other public routes. Unprepared direct callers acquire a bounded request-sized
  session instead of selecting an oversized automatic context.
- Extend the existing session scope with an optional explicit capacity. Catch
  `BaseException` when a lease is abandoned, including generator close, so the
  session is closed rather than lost outside the pool.
- Close the independent provider before target sessions/weights during generator
  teardown. Reject work on closed providers and expired/cancelled requests before
  allocation.
- Put reuse and graph-verifier observations in telemetry's supported diagnostics
  mapping. The previous arbitrary top-level diagnostic fields were discarded by
  telemetry normalization.
