# Decouple SPECDEC2 eager context from graph cap

## Summary

Complete the P2 activation contract by separating long eager SPECDEC2 capacity
from the short reusable target-graph context bucket. The staged capability
previously hard-capped every route at 1023 tokens even though streaming NextN
activation and the resident eager target are owned through the session's
`max_sequence_length`. That would stream p4K/p16K provider state during prefill
and then select K0 before mutation solely because of an unrelated graph bound.

## Changes

- Resolve `SpeculativeCapability.max_context_tokens` from the minimum live target
  session capacity, not 1023.
- Leave native graph context admission/fallback under the target graph's own key;
  the bridge still reports actual graph/eager route.
- Update the focused capability contract from target capacity 4096.
- No graph bucket, arithmetic, backend threshold, or automatic policy changed.
