# Preserve request thinking policy through explicit MTP batching

## Summary

The live control audit's initial thinking check was too weak: it checked reasoning
presence and valid schema, not the hard cap. Inspection found generic MTP emits
four reasoning tokens plus a close delimiter, while explicit MTP emits much
longer reasoning and omits counters. The explicit batcher unconditionally relaxed
thinking controls even under hard policy. Preserve request policy through queue
submission and grouping; only hint policy relaxes controls at actual MTP execution.

## Changes

- Add request-owned `mtp_thinking_policy` to queued generation, submit/stream
  methods and batch execution. Include it in the coalescing key so hard and hint
  requests cannot inherit each other's policy. HTTP entrypoints resolve server
  defaults and request overrides before enqueueing. Legacy internal callers keep
  their prior hint default. Generic speculation and AR fallback remain unchanged.
- Strengthen real-service CPU HTTP assertions to require reasoning counters and
  answer phase, rather than relying on scripted output's naturally short reasoning.
- Strengthen the live probe with tokenizer-derived close IDs, cap plus delimiter
  accounting, consumed close position and nonempty answer-token count. This is a
  new verifier, not evidence that previous weak checks qualified hard controls.
