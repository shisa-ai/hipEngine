# Qwen4Exp prefill hyper-connection GDN and expert-glue kernels

## Summary

Thirteen prefill changes for `qwen4_exp_gguf` / `hip_gfx1151` /
`gguf_ud_q4_k_xl`, `production`, Radeon 8060S / gfx1151 (machine
`55ea6c509d0b49eea8de7094a1023668`), chunk 4096, canonical protocol (one
warmup, three repetitions, compact capture, warm PLE cache), tracked-clean
`21177f07f`:

- Canonical 12-case prefill 779.4 / 977.9 / 1190.3 to 1028.5 / 1276.5 /
  1562.2 tok/s at p512/p1024/p4096 (+32.0% / +30.5% / +31.2%); decode 20.88 /
  20.12 / 20.53.
- 1024/8192/16384 fixture 978.7 / 1158.8 / 1133.1 to 1280.4 / 1526.6 /
  1475.5 tok/s (+30.8% / +31.7% / +30.2%); 24/24 cases deterministic.
- Kernel time per code-p4096 prefill 3409 to 2564 ms (gufo `v0.12.0` 2373).
- Against gufo (2026-10-12, same host, not rerun): 0.94x / 0.86x / 0.90x at
  p512/p1024/p4096; ahead of halo-box at every length.

Eleven of the thirteen are bit-identical to what they replace. Two change
arithmetic: the 48-column GDN gate projections moved from the scalar FP32
GEMV to the F16 WMMA GEMM, and the GDN prefill recurrence moved to a
row-split kernel that sums in a different FP32 order.

## Decisions

- **Bit-identical changes went straight to the default path** with a
  rollback flag each; the two arithmetic changes went in on the user's
  instruction to reach parity first and gate afterwards, and were gated in
  this unit before the rollup.
- **The gate result is the same class as the plan it replaces**: every
  numerical limit passes (mean / p95 / p99 / max KL 6.295e-4 / 3.630e-3 /
  8.495e-3 / 1.034e-2, top-1 448/450, three bit-identical repeats), status
  `requires_task_review` with 13/18 strict-exact free-running tasks against
  15/18 before. The cross-engine battery moved 14/18 to 13/18 with top-1
  agreement 1.00. I kept both arithmetic changes on that basis and recorded
  the task-count movement in the results README rather than hiding it.
- **The long-context gate stays diagnostic.** It measures 2.16e-3 mean KL
  (2.10e-3 for the 2026-10-13 plan), outside the envelope like every
  non-bit-identical plan at that length. The owner decision on how to gate
  long prompts is still open.
- **Workgroup size and CU mode are tuning axes on gfx1151.** The row-split
  GDN recurrence measures 5.58 ms in 128-thread blocks and 7.93 ms in
  256-thread blocks with identical code. Dense wide launches prefer a build
  without `-mcumode` up to 1024 rows and the CU-mode build above; the long-K
  output projection prefers the non-CU 128x128 tile from 1024 rows. Same
  process A/B is required to see these: cross-process runs differed by more
  than the 1% effects being measured and produced two false positives (GR
  and conv families) that the same-process arms refuted.
- **Negative results kept out of the tree**: two bit-exact relayouts of the
  tile-16 GDN recurrence (8.5 and 9.6 ms against 8.0), wider K10240/N320
  tiles, and CU mode for the routed-expert kernels (-1.7%).
