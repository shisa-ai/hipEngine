# PARO packed-prefill schedule boundary

## Summary

Moved the four-operation PARO packed-prefill layer schedule out of
`Qwen35ParoDecodeState` into `hipengine/runtime/qwen35_paro_packed_prefill.py`.
The public state method keeps its signature, `tokens <= 0` validation, truthy
linear-scratch fallback, and `isinstance` grouped-MoE fallback. The owner
receives explicit geometry, borrowed scratch, and four separate selected
callables; it performs no allocation, synchronization, policy lookup, or error
translation.

## Changes

- `hipengine/runtime/qwen35_paro.py`: imports the new owner; the public method is
  a thin adapter with unchanged validation, fallback order, call order, kwargs,
  return identity, and exception propagation.
- `hipengine/runtime/qwen35_paro_packed_prefill.py`: new geometry/scratch
  records, four narrow callable protocols, and the schedule owner. The parent
  state module is imported only under `TYPE_CHECKING`; there is no runtime
  cycle.
- `tests/test_unit_qwen35_paro_packed_prefill_schedule.py`: pre-move control
  comparison, raw tensor identity, exact exception identity and no-later-call,
  fallback order and failure, falsy linear fallback, `isinstance` MoE fallback,
  real adapter delegation, public signature, and structural no-runtime-state-
  import/no-forbidden-effects checks.
- `tests/fixtures/qwen35_paro_packed_prefill_control.json`: captured before
  editing by extracting
  `Qwen35ParoDecodeState.run_linear_attention_moe_packed_prefill_layer_fp16`
  from `git show d1dd4c4af:hipengine/runtime/qwen35_paro.py` and executing it
  with recording fakes. Cases cover tokens 1/3/4/5/7, segments 1/2/3, groups
  32/64/128, both scratch fallbacks, fallback failures, invalid tokens, and all
  four operation failures.
