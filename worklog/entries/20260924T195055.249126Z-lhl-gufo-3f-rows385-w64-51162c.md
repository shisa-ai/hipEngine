# shared_b rows>=385 geometry ablation w64 keep

## Summary

Campaign §3F/§7.4 geometry ablation, prefill27b/null iteration 8 (KEEP,
metric `prefill_tok_s_512` 381.20626 -> 395.43954, new loop best, +3.48%
over the prior best 382.12041).

Dispatch archaeology established why the dominant kernel family runs the
geometry it does: the production key
`(hip_gfx1151, linear, gguf_q4_k_t16_v1, t16_wmma_prefill_bf16_bf16_out)`
resolves to `gguf_q4_k_t16_wmma_prefill_gfx1151_bf16_bf16_out`, a host
router in `hipengine/kernels/hip_gfx1151/__init__.py` whose measured owner
bands all cap at `GGUF_Q4_T16_DENSE_SHARED2_384_MAX_ROWS = 384`. Rows past
384 therefore fall through the final `else` to the 48-column shared-B base —
and that family is 337.9 ms, 25.4% of prefill, in the same-day kernel trace
(160 dispatches per pass at grid.y=2, template `<3, 4, 4>`). No `<4, 8, 2>`
(w64) dispatch appears anywhere in the trace. The wide siblings live in the
same `.hip` as parameterized implementations; `w64` was built explicitly as
a sweep candidate, claims bit-exactness with the 48-column owner, and was
measured 1.1-1.8x at 512 rows on the gfx1100 lineage (RDNA3) — never A/B'd
on this gfx1151 device at the production cell.

Because the loop's prompt verifier forbids editing `hip_gfx1151/`, the
ablation landed in the in-scope python leaf wrapper: for rows >= 385 the
base wrapper delegates to a candidate sibling. Each arm was a direct edit
plus a full `qwen35_readme_sweep.py --engine gguf --workloads 512/128`
run (mean of 3, warmup 1, repeated-token prompt), artifacts under
`/tmp/prefill27b-results/geom/{base,w64,3w8r3,2w2,2w4}.json`:

| rows >= 385 owner | prefill tok/s (mean +- stdev) | vs base | parity |
| --- | --- | --- | --- |
| shared-B 48-col base (stock) | 381.395 +- 0.139 | — | reference |
| **w64 64-col** | **395.440 +- 0.395** | **+3.68%** | identical |
| shared_b3w8r3 | 340.663 +- 0.573 | -10.68% | identical |
| shared_b2w2 | 351.546 +- 0.325 | -7.83% | identical |
| shared_b2w4 | 359.706 +- 0.413 | -5.69% | identical |

w64's +3.68% on a family worth 25.4% of prefill implies ~14% family-level
improvement (337.9 -> ~290 ms), consistent with the gfx1100 prior (1.16x
inside the measured 1.1-1.8x range). Today's stock session band across runs
was 380.96-381.52 tok/s, so the winner clears run-to-run drift by ~4x.
