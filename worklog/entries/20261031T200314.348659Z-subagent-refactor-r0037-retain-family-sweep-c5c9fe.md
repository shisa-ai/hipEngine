# R0037 retain the disabled-family sweep and repair its control and WMMA arms

## Summary

**Decision: retain `scripts/qwen4exp_disabled_family_sweep.py` as the
reproduction path for two cited packets. Do not replace it with
`scripts/qwen4exp_disabled_selector_ranking.py`, and do not delete it.**

The ranking harness cannot cover the six axes R0037 names. Its `ARMS` table
carries only the arithmetic-recovery selectors plus `gr_wide`/`gr_both`/
`all_prefill`; it has no `Q8_DENSE_WIDE_16_47`, no `Q8_WMMA_LAYERS_*`, no
`Q4_DP4A64` and no override control. Its `_run_arm` transports owner state for
`production_moe_prefill` and `q8_mmq_prefill` only, so it cannot send
`--q8-wmma-layers` or `--q4-dp4a-decode/--q4-dp4a-layers` at all. It never
passes `--risk-diagnostics`, so it records no repair rate or `over_capacity`
field, and it has no `--reuse-scratch`, so it cannot rebuild a ranking from
per-arm JSONs already on disk. Its report is per-arm (`arms`), not per-family
(`families`/`ranked_by_seconds_recoverable`). A replacement would be a rewrite
of the cited packet's consumer contract, not a consolidation.

Reproduction was checked rather than assumed. The 2026-09-16 packet's own per-arm
payloads (`raw-*.json`) were copied into a scratch directory and re-aggregated by
the retained driver with `--reuse-scratch`: all seven archived families reproduce
the cited artifact exactly on every shared field (`candidate_median_s`,
`fallback_median_s`, `seconds_recoverable`, `speedup`, `same_logits_as_fallback`,
`named_profile_intact`, `fell_back_to_strict`), in the cited order. No model, GPU,
or child process was involved. The four environment arms verify every requested
pair against the payload's own bound/effective maps; the three owner-transported
arms stay `unknown` rather than being claimed.

Three arm-level defects are repaired here.

1. **The no-op control had become a route-disabling arm.** It carried
   `HIPENGINE_QWEN4_EXP_Q8_DENSE_WIDE=0`, which was inert when `7456b5ebf`
   (2026-09-17 04:24) added it because no profile bound that key.
   `e66e191e9` (2026-09-17 05:53) bound it to `1` over layers 16-47 and
   `f04758c10` moved that scope to 13-47, so from then on the "control"
   disabled the live default route. `dcd1421c1` (2026-10-31) also removed the
   `configure_mmq_prefill_resources()` re-run from
   `_apply_post_binder_overrides` that the arm's comment priced. The sweep's own
   procedure subtracts this arm from every family's saving, so the drift would
   have corrupted the whole table.
2. **The three `Q8_WMMA_LAYERS_*` arms measured the wide route.** The production
   plan binds `HIPENGINE_QWEN4_EXP_Q8_DENSE_WIDE=1` over layers 13-47
   (`PRODUCTION_Q8_DENSE_WIDE_PREFILL_LAYERS`), `_q8_dense_wide_claims_parent`
   accepts the WMMA-rewritten parent (`wmma_<parent>` under ABI `wmma_raw`), and
   `_q8_dense_wide_dispatch` records that the wide route takes precedence where
   its scope covers the layer. A WMMA scope arm that leaves the wide route bound
   therefore measures the wide route under a WMMA name — the same construction
   that produced the 2026-09-29 WMMA gate false pass
   (`benchmarks/results/2026-09-29-q8-staged-f32-dense-prefill-layers-gate/WMMA-ROUTE-FALSE-PASS.md`).
3. **Attribution validated "some key moved", not the requested pairs.** An
   unrelated key changing (for example `GR_IU8`) marked an arm engaged even when
   its own override never landed, so a WMMA arm whose wide-route clear was not
   applied could pass with the wide route still claiming the parent. Attribution
   now checks every requested pair against the child's effective route
   environment, requires at least one of those keys to have moved from the bound
   value, and requires the control to be fully equal (no key moved anywhere).
   A measured row whose attribution is `False` is excluded from
   `ranked_by_seconds_recoverable` and `total_seconds_recoverable` and named in
   `ranking_excludes` with its reason; its measurement stays in `families` as
   taken, because the driver does not rewrite a measurement to make it look
   attributable. `unknown` (no bound/effective pair reported) stays `None` and is
   never promoted to verified.

`Q4_DP4A64` is a decode route and cannot move the measured prefill pass. It stays
in the table for transport coverage only, is never ranked or totalled as a
saving (`savings_eligible: false`), and its archived 2026-09-16 row stays in
`families` as legacy data rather than as a reproduced current saving.

## Changes

- `scripts/qwen4exp_disabled_family_sweep.py`:
  - Docstring states the retention decision (pointing at this entry, not at a
    ledger row this unit proposes removing), what the ranking harness lacks, why
    the WMMA arms clear the wide route, that `Q4_DP4A64` is transport-only, and
    that `attribution_verified` is a binding-level statement and not a launch
    census.
  - `CONTROL_FAMILY`/`CONTROL_KEY` and `_control_override(fallback)`: the
    control's override repeats the value the named profile binder wrote, read
    from the fallback's own `route_env` for
    `HIPENGINE_QWEN4_EXP_Q4_IU8_PREFILL`. The arm is skipped with a recorded
    reason when no inert value exists.
  - `_summarize` now retains `bound_route_env` alongside `route_env`, so every
    requested pair can be checked against the child's own report.
  - `_env_request_applied(result, env, control=...)` validates each requested
    pair against the effective map, names the offending key when it is absent or
    has another value, requires one requested key to have moved, and requires
    full bound/effective equality for the control.
  - `_owner_scope_bound(result, owner)` compares the resolved `q8_wmma_layers`
    scope with the requested layers.
  - `_attribution(result, entry, env)` combines the checks: an arm can carry both
    an environment override and an owner scope, and both must hold. `False` wins
    over `None`, so a mismatch is never downgraded to unknown.
  - Rows carry `attribution_verified`, `attribution_note`, `owner_scope_bound`,
    `env_override_changed_route` and `savings_eligible`; the artifact carries
    `ranking_excludes` (always a list) and `control_route_neutral` derived from
    the control row.
  - `WMMA_ARM_ENV` clears both `HIPENGINE_QWEN4_EXP_Q8_DENSE_WIDE` and
    `..._DENSE_WIDE_LAYERS` on the three WMMA arms, mirroring
    `scripts/execution_profile_q8_wmma_prefill_layers_gate.py`.
  - `main(argv=None)` accepts an explicit argument list, matching the sibling
    ranking harness, so the interface can be replayed on host.
  - Comment on `Q8_DENSE_WIDE_16_47` records that the live scope is now 13-47.
- `tests/test_unit_qwen4exp_disabled_family_sweep.py` (new): pins the six
  reproduction axes, the control's inert-by-construction value, the skip path,
  the WMMA wide-route clearing, the owner-scope check, a host replay of `main()`
  that checks each axis's child command and the artifact fields, the
  route-changing control exclusion, an owner-scope mismatch exclusion, a
  requested value the child did not apply (with an unrelated key changed), a
  requested key absent from the route environment, `Q4_DP4A64` never ranked,
  historical reuse staying `unknown` with its numbers unrewritten, the
  `--reuse-scratch` aggregation, and a parser adapter that feeds every generated
  command to `qwen4exp_profile_gap.build_parser()`/`_parse_overrides`.
- `tests/test_unit_qwen4exp_disabled_selector_ranking.py`: adds a host replay of
  the ranking harness `main()` through a fake child report (arm order, baseline
  ratio, effective-route wiring, owner-transport arm, incremental report write)
  and the unknown-arm refusal. The existing arm-table guards are unchanged.
- `docs/REFACTOR.md`, `README.md`, `docs/ENVS.md` and the shared
  runner/profile files were **not** edited.
