# Reject new audit kinds until their findings are triaged

## Summary

The audit now treats an unrecorded kind as having a zero ceiling. Automatic
refresh cannot accept that kind's open findings as its baseline. This closes
the budget loophole observed during the reconciliation in
`worklog/entries/20261108T145854.907011Z-audit-handoff-audit-decision-reconciliation-cb3c1d.md`.
No inference code, runtime defaults, selectors or existing budget values changed.

## Changes

- `cmd_check` evaluates every kind with gated open rows, using zero when the
  budget omits it. `cmd_status` reports the same over-budget condition, including
  when the budget is empty.
- Lower-only budget writes preserve previously recorded kinds and record every
  observed new kind at zero, including fully triaged kinds. Existing ceilings
  still decrease as rows are triaged; explicit budget writes are unchanged.
- Added regression tests for new kinds, an empty budget, fully triaged new
  kinds and status/check reporting. Existing selector and ratchet tests cover
  the unchanged behavior. Corrected the audit extension instructions so they
  do not tell authors to baseline a new check's open findings.
