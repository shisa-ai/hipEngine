# Down-leg T16 build spec: Q5_1 layout design

## Summary

The down-leg T16 build spec, committed as the next multi-session kernel
unit. The Q5_1 format facts (from hipengine/quant/gguf.py): block size 32
values, block bytes = 2 (d) + 2 (m) + 16 (qh high-bits) + 16 (ql low-bits) =
**36 bytes per 32-value block**; the value = ql[i] | (qh bit i << 4), scaled
d and offset m per block (the Q5_1 layout has no Q5_K-style packed
scale/min superblock). The down experts are 43 Q5_1 layers (the immutable
split from ED-3: layers 0,1,3,5-29,31-45) plus five Q8_0 down layers.

**Design.** Mirror the Q5_K T16 repack (hipengine/quant/gguf_t16.py
repack_gguf_q5_k_tile16) with a Q5_1 tile: 16 output columns per tile
(GGUF_T16_COLS), per-block d/m pairs staged per column, the 4-bit low nibbles
extracted per subblock the same way, and the qh high bits staged as a per-16-
column packed byte plane. The tile byte budget: 16 cols x (2+2) d/m bytes +
subblock ql (32 x 16 x 0.5 B) + the qh plane - computed exactly at build
time from the Q5_K precedent. The down kernel reuses the registered T16
dual gate/up kernel template (the expert-major wmma_comp body) with the Q5_1
decode path and the compensated accumulate, over the same compact selected-
MoE ABI.

**Evidence base for the expected value.** The F16 compact down owner already
measured as the fastest registered down owner (-42.29% median vs the
production iu8 down across 8/8 real-geometry cases); the compensated T16 down
targets the same class of win with the tighter drift the T16 gate/up
demonstrated. The down leg is ~1.5s of the p4096 prefill kernel time, so the
successful admission is another ~10% class prefill lever. **The numerical
admission will meet the prefill_last scope (X-7)** - the down-only F16
variant was rejected there, so the compensated T16 down is the test of whether
the compensation clears what F16-compact could not.
