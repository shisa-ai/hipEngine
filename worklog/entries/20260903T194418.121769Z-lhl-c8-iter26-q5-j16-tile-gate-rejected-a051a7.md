# C8 iter26: J16 tile gate fails both-orders rule; J32 default retained

## Summary

Ran the binding full C8/K3/D24 default-versus-rollback gate for the iter25
J16-minitile candidate (four runs, both process orders), added a pre-declared
two-run extension when session drift confounded the first pair, and applied
the fixed decision rule: retain only if >=3 of 4 order pairs are positive.
Result: 1/4 positive — the default flips back to the literal J32 policy in a
scoped removal commit; the exact J16 diagnostic tooling is retained.

## Findings

- Eight full-suite runs, all packets passed, acceptance ledger identical in
  every run (568 cycles / 1,592 proposed / 1,256 accepted) as guaranteed by
  the bit-exactness contract.
- Order-pair MTP aggregate deltas (candidate vs rollback): r1 (cand first)
  **+0.77%**, r2 (ctrl first) **-0.43%**, r3 (ctrl first) **-1.09%**, r4
  (cand first) **-0.03%**. The first-position arm won 4/4 pairs under a
  monotonic ~0.6%/run session decline (91.05 -> 89.38 tok/s across the
  session). Pooled candidate mean 89.864 vs rollback 90.042 = **-0.20%**.
- A linear-drift re-analysis of the first four runs had suggested +1.09%
  (matching the leaf-implied ~+1.05%), but the extension rejected it: the
  apparent effect was positional, not arm-related.
- Conclusion: the leaf consumer win is real and bit-exact, but it does not
  survive the e2e two-order gate; the leaf's warm burst-timing isolation
  likely overstates the in-cycle benefit. The literal J32 launch policy
  remains the registered default and strict rollback.
