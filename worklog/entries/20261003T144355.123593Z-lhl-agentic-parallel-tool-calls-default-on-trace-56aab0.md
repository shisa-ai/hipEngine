# Refresh parallel tool-call golden trace to default-on contract

## Summary

`tests/test_integration_agentic_harness_traces.py::test_agentic_golden_trace[parallel_tool_calls_without_opt_in_non_streaming]`
failed because its fixture encoded the pre-`9b1010111` contract that parallel
tool calls require explicit `parallel_tool_calls=true`. Commit `9b1010111`
("fix: enable parallel tool calls by default") intentionally changed the
contract to default-on and updated `docs/API.md` and
`tests/test_integration_server_api.py`, but left this golden trace stale.

Intended contract (`hipengine/server/api.py` `_validate_chat_tool_result`):
multiple parsed calls are rejected only when `request.parallel_tool_calls is
False`; omitted or `true` accepts them. `docs/API.md` states "Parallel calls are
allowed when `parallel_tool_calls` is omitted or `true`; explicit `false` limits
output to at most one call." The implementation is correct; the fixture was
stale.

## Changes

- `tests/fixtures/agentic_traces/golden_traces.json`:
  - Renamed `parallel_tool_calls_without_opt_in_non_streaming` to
    `parallel_tool_calls_default_on_non_streaming` and updated `expected` to the
    default-on result: `finish_reason: tool_calls`, two ordered `tool_calls`
    (`read README.md`, `read WORKLOG.md`), and `finish_details.reason:
    tool_calls`.
  - Added `parallel_tool_calls_false_rejected_non_streaming`: same two-call
    output with explicit `parallel_tool_calls: false`, expecting
    `finish_reason: stop`, `finish_details.reason: invalid_tool_call`, no
    `tool_calls`.
- `tests/test_integration_agentic_harness_traces.py`: updated
  `_REQUIRED_AGENTIC_TRACE_COVERAGE["tool_validation"]` to the renamed and new
  trace names.

No implementation change was needed. No assertions were weakened: the old
rejection path is now covered by the explicit-`false` trace, and the default-on
path asserts both calls.
