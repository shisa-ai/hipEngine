# Populate typed KV bindings in production capabilities

## Summary

Closed the gap between the typed KV ownership contract and production: the dense, MoE, and PARO capabilities now populate `SpeculativeKVBinding`, so every speculative frontier carries a self-consistent typed description of the KV store it will touch instead of only the loose string keys. A new `SpeculativeKVBinding.for_resident_target` constructor reads the store's own session declarations (`kv_storage_dtype`, `kv_scale_dtype`, `kv_scale_granularity`), so a binding cannot drift from the store the frontier actually touches. K0/AR root-only frontiers remain unbound by design — no capability, no binding — and that shape stays pinned as legal.

## Changes

- `hipengine/speculative/frontier.py`: `SpeculativeKVBinding.for_resident_target` classmethod (storage dtype + INT8 scale ABI from the target session; backend fingerprint from the session class and dtype; generation stays 1 until sessions expose a pool epoch, documented in the docstring).
- `hipengine/generation/qwen35_gguf_mtp2.py`: dense capability binds `gguf_paged_dense` / `reversible_journal` from its target session.
- `hipengine/generation/qwen35_gguf_moe_mtp2.py`: MoE capability binds the same topology from `targets[0]`.
- `hipengine/generation/qwen35_paro_mtp2.py`: PARO capability binds `paro_paged_bf16` / `packed_scratch` from its session.
- `tests/test_unit_specdec2_contracts.py`: `test_kv_binding_for_resident_target_reads_the_declared_store` — BF16 vs INT8 cells are distinct, scale ABI flows from the session, transaction mode preserved.
- `tests/test_unit_specdec2_cross_model_contracts.py`: frontier test docstring updated — the "no production adapter populates one yet" premise is closed; the None-binding case now documents the K0/AR frontier shape, and the populated/mismatch guards stay.
- DMS stays excluded: its config gate refuses speculative serving, the recorded boundary.
