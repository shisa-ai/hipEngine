# Muse Glimmer DFlash verify uses fused decode glue: 21.64 -> 22.93 tok/s, speedup 1.80 -> 1.88x, exact

## Summary

Carried the fused decode glue into the DFlash block-verify path
(`_forward_block` with `exact_multirow=True`). Verify now runs the multi-row
fused QK-norm/rope/KV-append (one launch instead of bf16_to_f32 x2 + head-norm
rotary + f32_to_bf16 x2 + two KV memcpys) and the sigmoid attention gate inside
the decode-attention combine (`gate_ptr`) instead of a separate gate_mul. The
prefill and eager-decode paths are untouched. Projections stay on the
weight-amortized `exact_rows` owners (already optimal for the weight-bound
block; the rows-1 grouped GEMV would re-read weights per row).

## Changes

- hipengine/runtime/muse_glimmer.py: in the exact_multirow branch, replace the
  seven-launch QK-norm/rope/KV-append chain with
  `muse_glimmer_qk_norm_rope_kv_append(tokens=N)` (rotated Q in the q_rot_f32
  scratch, K/V straight to cache); pass `gate_ptr` to the verify attention and
  skip the standalone `gguf_gate_mul_bf16`. Attention reads `q_attn_ptr`
  (q_rot_f32 for fused verify, q_bf16 otherwise).

## Validation

- Exactness: tests/test_live_muse_glimmer_dflash_exactness.py (DFlash IDs ==
  true AR ten-prompt suite + public speculative surface) and
  test_live_muse_glimmer_runner.py (CPU-reference + llama.cpp-oracle logits,
  coherent greedy, decode==fresh-prefill) all pass on gfx1151.
- Speed (scripts/muse_glimmer_dflash_bench.py, ten-prompt mtpbench, budget 4,
  max-tokens 512, r=1, Radeon 8060S/gfx1151): DFlash 22.926 tok/s
  (transition-norm 22.858) vs AR 12.178 -> speedup 1.883x; exactness_all=True;
  acceptance 2258/4584 = 49.3%, 2.94 tokens/target-forward; beats Gate B
  (21.30). Prior reviewer row was DFlash 21.64 / 1.80x, so the fused verify
  recovers +6% and part of the speedup lost when AR decode got faster. Laptop
  thermals float absolute rates (one short general_ja prompt ran AR>DFlash at
  0/8 acceptance — short-output overhead, aggregate unaffected).
