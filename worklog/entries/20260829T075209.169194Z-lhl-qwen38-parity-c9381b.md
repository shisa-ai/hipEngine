# Parity P2.1: arrival-aware solo batch dispatch removes idle-window latency

## Summary

Serving-policy unit for the external-parity campaign (P2.1 route/overhead).
`_GenerationBatcher._run` slept the full generation batch window
unconditionally before draining the queue, so every solo request on an idle
engine paid the entire window (50 ms in the frozen parity protocol). The
window is now arrival-aware:

- A solo queued submission on an idle engine dispatches after one 2 ms slice.
- Two or more queued submissions, or a busy engine, still honor the full
  window, so concurrent-arrival batching behavior is unchanged.

Measurement (frozen parity protocol, physical gfx1151, standard Q4_K_M,
prefill arm, widths 1-2; low-M owner band already retained):

- `--batch-window-ms 0` control confirmed the cost before the change:
  C1 5.308 -> 4.835 s sweep (84.59 -> 92.87 tok/s), C2 9.883 -> 9.638 s.
- Post-change re-measure at the protocol's own `--batch-window-ms 50`:
  recorded in the retained artifact (solo requests no longer wait the
  window while C2+ coalescing keeps the full window).

## Changes

- `hipengine/server/api.py`: `_SOLO_DISPATCH_SLICE_SECONDS = 0.002` and the
  arrival-aware window in `_GenerationBatcher._run`.
- `tests/test_server_api.py`: RED-first
