# UD gfx1151 optimize2 E6a: Q5 gate/up dual screened bit-exact but 0.93x vs tile8 chain — route not enabled

## Summary

Iteration 11 executed campaign E6 step 1 ("route same-type pairs to existing dual
owners first") and adjudicated the Q5_K same-quant gate/up dual as a **measured
negative: the route stays dormant.** No production code changed.

Investigation located why the rows==1 Q5 dual block in
`launch_gguf_linear_pair_silu` never fires — three stacked causes:

1. The identity policy row (`GGUF_DENSE_PAIR_SILU_DECODE_POLICIES`, UD identity
   `(..., "gguf_ud_q4_k_m")`) returns the **Q4** variant name
   `dense_dual_local32_bf16_bf16_out` (it mirrors plain by design — the IQ4 branch
   selects its own key and ignores the value, but the Q5 block inherits
   `registered_decode_variant` blindly, producing a key unregistered under
   `gguf_q5_k_t16_v1`).
2. Post-E4a both sides dispatch `t16_gemv_decode_tile8_bf16_bf16_out` while the
   rule demands the direct decode key.
3. The earlier `_q5_t16_dense_pair_silu_variant(rows)` branch is dead code for Q5
   (`dense_pair_quant` only ever holds `_Q4_T16_DENSE_QUANTS` members).

The screen then decided the gate: at the production shape (5120, 17408), rows=1,
the dormant dual `gguf_q5_k_t16_dense_dual_silu_gemv` is **bit-exact** against the
production chain (2× tile8 + `silu_mul_separate_out_bf16`) but **loses 0.93×** —
705.6 vs 653.6 µs/layer (allocate-once, warm 20 + 200 measured launches, both
queued on one stream). The dual kernel mirrors the *direct* owner's schedule;
since E4a routed the singles to tile8, the chain beats the dual. Enabling the
route would add ≈9 × 52 µs ≈ +0.47 ms/tok to the 9 (Q5_K,Q5_K) layers — a
regression. Pre-E4a the dual would have won (2× direct ≈ 786 µs > 705.6), which
explains the 2026-09-10 design; the E2c table value incidentally kept it dormant
at the right time.

Verdict: **do not enable.** Dormancy is load-bearing post-E4a. The mechanism
discrepancies (poisoned variant inheritance, dead branch, stale comment) are
recorded in `docs/REFACTOR.md` with the re-screen clearing command.

E6 step 1 status: IQ4 pair-SiLU already firing (19.4 launches/tok, landed in E2,
confirmed by E4c); Q5_K dual screened and rejected; Q5_K/Q6_K/Q3_K single-pair
leftovers are 1-layer each (below any route's fixed cost). **No same-quant route
gap remains** — E6 step 1 closes; step 2 (the 28 mixed-type layers, sized by E4c)
is next.
