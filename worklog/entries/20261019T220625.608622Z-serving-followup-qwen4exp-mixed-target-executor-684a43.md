# Compose shared Flash-Next target verification

## Summary

The provisional full-model executor composes the mixed GDN, QSA and PLE
adapters. It runs shared projections, residual operations, experts and the
output head over every physical row, with depth waves only for dependent
state updates. Serving integration is not implemented by this entry.

## Changes

- `hipengine/runtime/qwen4_exp_mixed_target.py` validates slot admissions and
  starting cursors before allocation, owns per-pass scratch, scores all rows,
  and commits one selected prefix per request.
- N-gram hashing advances in depth order and keeps per-row host snapshots.
  Verification leaves live recurrent/PLE state, positions and hashes unchanged;
  abort restores attention/index visibility. A failed device commit poisons
  participating slots and cannot be retried as a valid transaction.
- CPU tests cover publication destinations, stale admissions, changed cursors,
  invalid accepted depths, abort and failed-commit containment. GPU tests
  compare a synthetic PLE/two-GDN/QSA model against independent request runners
  for rejection, partial/full acceptance and physical row permutations.

## Validation

- RED-first was not used for the initial composition: it calls existing
  arithmetic helpers and was first checked against their real synthetic-model
  oracle. The new CPU failure tests were added before serving integration.
- `.venv/bin/python -m pytest tests/test_unit_qwen4exp_mixed_target.py -q`:
  six pass.
- In the documented clean TheRock environment,
  `python -m pytest tests/test_gpu_qwen4exp_mixed_target.py
  tests/test_gpu_qwen4exp_mixed_ple.py
  tests/test_gpu_qwen4exp_resumable_prefill.py -q -x`: twelve pass on the local
  Radeon 8060S. These are fixture bounds, not a production numerical gate.
- The first twelve-case GPU bundle passed. After review repairs, the expanded
  bundle passes 22 cases, including depth four at each accepted depth, two QSA
  layers, physical permutations, verify/abort/verify and unchanged live GDN/PLE
  bytes and index cursors after abort. Subsequent committed-step logits match
  the independent request oracles within their fixture envelope.
- Twenty-four focused CPU cases pass after lifecycle review repairs: a closing
  pass refuses new work, cleanup frees owned buffers after the live runner has
  closed, primary verify/commit errors survive failed rollback, commit preflight
  checks every QSA token/cursor before live writes, and stale PLE hash cursors
  refuse instead of silently padding history.
- Per-dispatch width is checked against the selected primitives' row constants;
  total verification rows are checked against their state-slab constants. The
  PLE adapter validates its indexed convolution by wave width and runs stateless
  projection/finish over total rows. CPU regressions admit 80 rows at legal
  width and reject an over-wide wave.
- The executor imports without HIP initialization under the repository Python.
  No new kernel, dispatch variant, flag or torch dependency was added.

## Memory cost

The initial executor keeps a recurrent snapshot for every physical row at each
GDN layer until commit. At the model's 48 value heads and head dimension 128,
one recurrent snapshot is 3 MiB. Thirty-six GDN layers and an eight-request,
four-candidate pass (40 physical rows) therefore require 4.21875 GiB for those
recurrent slabs alone, before convolution, attention, logits and scratch.
Allocation also zeroes those slabs. This is a geometry-derived allocation cost,
not measured peak memory. Per-pass allocation and synchronous snapshot copies
remain a concrete optimization target for serving economics.

## Next

  serving unit, not to these runtime adapter checks.
- Reuse or reduce per-pass scratch only after profiling the complete cycle.
  Preserve accepted-prefix snapshots, all-before-mutation validation and fatal
