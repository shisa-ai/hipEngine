# Add long-context gate AR batch arm

## Summary

The long-context gate can now execute the AR batch candidate instead of
silently measuring the c1 trajectory. `--candidate ar_batch` requires
`--batch-width 1` or `2`; width 4 is refused because its live qualification
bound is 2,048 positions, below the 2K-class, 8K, and 16K fixtures. The gate
plans honest N-row groups, runs the existing adapter (c1 prefill, genuine
N-row decode), maps trajectories and slot states back by prompt, and makes the
batch state/ownership gate and batch manifest binding part of the decision.
A missing width or a c1 fallback is a hard error.

## Changes

- `scripts/qwen4exp_long_context_gate.py`: added batch width resolution,
  numeric/retrieval grouping by teacher-forced length, the batch run arm,
  manifest binding to the live profile and source revision, `batch` output
  evidence, and optional binding checks in `decide()`.
- Added exact trajectory-length checks before comparison and injected the
  prompt id into strict c1 state summaries before the adapter's state gate;
  the adapter requires that field.
- `tests/test_unit_qwen4exp_long_context_batch_gate.py`: CPU contracts for
  widths 1 and 2, no c1 fallback, width 4/missing width rejection, group
  planning, N-row call widths, per-request token/state ownership, manifest
  identity, state-gate failure, control basis, and trajectory length.
- `docs/EXECUTION-PROFILES.md` and `benchmarks/HARNESSES.md`: documented the
  batch arm, its width limit, and the absence of a c1 fallback.

## Next

Run the actual long-context gate only after this unit is committed and the
tracked tree is clean. Proposed exact commands, on host `zbook`
(gfx1151/Radeon 8060S), model UD-Q4_K_XL:

```bash
cd /home/lhl/hipEngine
. /tmp/hipenv.sh
$PY scripts/qwen4exp_long_context_gate.py \
  --model-root /models/gguf/unsloth-Qwen3.8-Flash-Next-UD-Q4_K_XL/UD-Q4_K_XL \
  --candidate ar_batch --batch-width 2 \
  --controls 3 --control-seed 1 --decode-steps 24 \
  --candidate-repeats 3 --max-sequence-length 16640 \
  --prefill-chunk-size 4096 \
  --output /tmp/qwen4exp_long_context_ar_batch_w2_20261018.json
```

Repeat with `--batch-width 1` and a `w1` output path. Expected wall time is
about 35-55 minutes per width: the documented production long gate is 24.5
minutes, and the batch arm adds a third candidate repeat plus batch state
snapshots. QSA KV alone is about 0.4 GB per width-2 arm at 16,640 positions
(12 QSA layers x 2 KV heads x 256 head dim x 2 bytes); this is an estimate, not
a measured allocation. The run covers the four long numerical prompts with
three controls and three candidate repeats, all four 8K/16K retrieval prompts,
width-1/2 composition, per-request slot/owner/position and repeat state, and
manifest/profile/source binding. It does not cover performance, capacity, the
short 450-row suite, width 4, or serving. No `--protocol-check` mode exists in
this gate.
