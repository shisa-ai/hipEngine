# Promote the certified Q8 WMMA prefill scope to the production default

## Summary

The f16 WMMA dense Q8_0 prefill route is now a production default at layers
16-47 for `gguf_ud_q4_k_xl`. It is certified and it is faster, so it is promoted
rather than left behind a flag.

**Numerics.** Layers 16-47 passes the calibrated envelope on the full 12-case
protocol: mean KL `3.796e-4` against the `1e-3` limit, p95 `1.762e-3`, p99
`5.424e-3`, max `1.530e-2`, top-1 1538/1548 = `0.99354`, three identical
trajectory hashes, no scope failures, `measurement_valid: true` with no
blockers. All ten top-1 misses fall inside the 154-row flip-eligible set and
none outside it.

**Speed, on the default path with no overrides.**

| Configuration | Logits digest | Median | Delta |
| --- | --- | ---: | ---: |
| old default | `e717076f…` | 23.596 s | — |
| **new default** | `7270a972…` | **19.054 s** | **+4.542 s, 1.238x** |
| certified 16-47 via post-binder override | `7270a972…` | 18.960 s | +4.636 s |

The promoted default and the configuration the gate certified produce
**byte-identical logits** on `code-p4096` (`7270a972…`, `token_id` 248068). The
promotion therefore runs exactly what was measured, rather than something
inferred to be equivalent. `named_profile_intact` is true and
`configuration_class` is `named_profile`, so this is a profile state and not a
diagnostic override.

The override and binder arms agree to 0.5% (18.960 s against 19.054 s), which
also bounds the `--override` confound described below at about 0.09 s rather
than seconds.

## The win is not where the campaign assumed

The linear launch census on the new default path records **2144 launches of
`hipengine_gguf_q8_0_gemv_coltile8_rowbatch4_wave_scale_f32_f32_out` and zero
`wmma_prefill` launches**. Within the `linear` role the Q8 dense projections
still run the exact coltile chain.

So the +4.542 s does not come from the Q8 dense linear route, which is what this
campaign has been attributing it to. The census instruments only
`launch_gguf_linear`, so MoE, GDN and QSA kernels are outside it, and the
selector's env var reaches more than the linear path. The arithmetic and the
time both move, the result is gated, and the mechanism is unattributed. That is
the next thing to measure, with a `rocprofv3 --kernel-trace` rather than the
linear census.

This matters beyond bookkeeping: the remaining dense-projection optimisation
work is targeted at a family that, on this evidence, is not where this
particular win came from.

## Changes

- `hipengine/generation/qwen4_exp_profiles.py`: `PRODUCTION_Q8_WMMA_PREFILL_LAYERS`
  = `range(16, 48)`, bound by the production binder for `gguf_ud_q4_k_xl` only.
  Strict still binds the selector empty and the exact coltile chain remains the
  registered fallback and the owner of every layer below 16.
- `hipengine/runtime/gguf_linear.py`: the dispatch memoization key now carries
  the dense-wide route's enable flag, layer scope, and the weight's layer index.
  Without them the first resolution for a shape was replayed for every layer,
  so a layer scope was an artifact of cache-fill order. Also adds the
  `_q8_dense_wide_dispatch` layer scope itself.
- `tests/test_unit_qwen4_exp_profiles.py`: pins the promoted scope for the
  certified quant and that strict leaves it empty.
- `scripts/qwen4exp_disabled_family_sweep.py`: arms for the 16-47 scope, the
  dense-wide route, and a no-op override control.

## Validation

- Full gate, layers 16-47, 12 cases / 1548 rows / 3 repeats: every calibrated
  gate passes, `measurement_valid: true`, no blockers.
- Default path, `code-p4096`, 2 repetitions, no overrides: 19.054 s against the
  old default's 23.596 s, byte-identical logits to the certified configuration.
- `uv run pytest tests/test_unit_qwen4_exp_profiles.py` — 8 passed.

## Next

  dense linear route, and the campaign's dense-projection priority rests on that
