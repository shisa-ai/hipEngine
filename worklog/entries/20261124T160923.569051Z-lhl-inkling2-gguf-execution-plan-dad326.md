# Add the speculative-decoding plan to the Inkling GGUF campaign

## Summary

The [GGUF implementation plan](../../docs/campaigns/INKLING2-MINI-GGUF-EXECUTION.md) carried DSpark as one conditional paragraph: test depth one against draft-off, with byte bounds. Step 7 now states why it belongs, where drafting stands today, the break-even arithmetic and six ordered units. Speculative decoding is the one decode lever beyond the weight-stream floor. Ordinary decode can beat Loom by at most about 1.3–1.4×, and Loom ships with depth-one drafting on. hipEngine's drafter accepts 87% of depth-one proposals (198 of 227) where Loom accepts 56% and still gains 13–14%. GGUF drafting is not a speedup today: the packed verifier changed one token and was replaced by serial verification, and with the packed verifier on, a two-token window cost 2.1 ordinary tokens.

This unit also records a correction to [the W7900 ceiling probe entry](20261124T151622.193748Z-lhl-inkling2-mini-67f2de.md). It calls 307 GB/s "53% of the 576 GB/s peak". `docs/ROOFLINE.md` §1.4 gives 864 GB/s for this card, so the figure is 36% of the roof. The entry is immutable; the plan now carries the measured rates with the right roof.

## Changes

- Step 7, "Speculative decoding: make the window cheaper than the tokens it saves": the case from the reference engines, today's measured cost, a break-even table, the byte floor for the window and the drafter, and the units in order. The units are a token path built for one to eight rows, one window pass that ports the original checkpoint's provisional-block ownership, exact greedy acceptance through row-shared kernels, a device drafter with a shortlist head to test, device accept and commit, and depth chosen from measured acceptance.
- The work-queue introduction tells the decode units to be built for one to eight rows. The opening paragraph says Loom's shipped decode drafts. Decode-budget item 3 now includes the W7900 probe rates against the 864 GB/s roof.
- No runtime code or default changed.
