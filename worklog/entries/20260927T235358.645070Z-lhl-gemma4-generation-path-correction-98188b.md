# the generation path is correct and the degenerate output was the completion API on a chat model

## Summary

Supersedes the claim in
`worklog/entries/20260927T234104.286365Z-lhl-gemma4-prefill-down-mmq-route-941931.md`
and in `benchmarks/results/2026-09-28-gemma4-prefill-expert-down-route-attribution.json`
that "the model does not generate coherent text on this branch".

**That claim was wrong.** The generation path is correct.

## What actually happened

I ran `LLM.generate("The capital of France is")` and got `" it is it is it is ..."`.
That is a **raw-completion call**. Gemma 4 26B-A4B **-it** is instruction-tuned, so a
raw completion prompt is not a prompt it was trained on, and it degenerates. That is
the API behaving as documented, not a defect.

Through the surface a user reaches, it works:

```
python3 -m hipengine serve --model <UD-Q4_K_XL.gguf>
POST /v1/chat/completions  {"messages":[{"role":"user",
    "content":"What is the capital of France? Answer in one word."}]}
-> "Paris"
```

## Why the earlier entry got it wrong

It read the degenerate completion output as an engine defect and stopped there. The
chain that would have disproved it was one call away, and each link now has a
recorded check:

- **The forward path is self-consistent at real geometry.** A 5-token dense prefill
  and 5 single-token incremental steps over `[2, 818, 5279, 529, 7001]` give
  **max abs diff 0.0** and the same top-5. The KV cache is not the problem.
- **The tokenizer is exact.** `'Hello' -> (9259,)`, roundtrip `'Hello'`;
  `'The capital of France is' -> (818, 5279, 529, 7001, 563)`.
- **The model needs the chat template.** `[2] + ids` gives `thought`; `[105] + ids`
  (`<start_of_turn>`) gives `the` with **`Paris`** in the top five; no prefix gives
  `it`, which is the degenerate output.
- **The engine renders that template.** Feeding the rendered
  `<start_of_turn>user\n...<end_of_turn>\n<start_of_turn>model\n` through
  `Gemma4Runner.forward` gives `The capital of France is Paris.`
- **The server uses the model's own renderer.**
  `_render_chat_prompt_with_model_protocol` calls
  `getattr(target, "render_chat_prompt")` before falling back to the generic
  Qwen-style `render_chat_prompt`, and `Gemma4GGUFGenerator` implements it over
  `hipengine.chat.gemma4.render_gemma4_chat`.

## The one real finding in the earlier alarm

`test_unit_gemma4_runner.py::test_incremental_decode_matches_a_dense_prefill` fails
at `max abs diff 4.417` and **passes nowhere**: it fails identically with the
attention kernel and the down MMQ route both reverted. It is a real pre-existing
defect in that test or the tiny fixture it uses. It is **not** the generation path:
at the real geometry the same comparison is exact to the last bit, and
`test_runner_prefill_matches_the_reference` passes. Recording it as the likely cause
of the degenerate output, as the earlier entry did, was a second error built on the
first.

## Changes

- `benchmarks/results/2026-09-28-gemma4-prefill-expert-down-route-attribution.json`:
  the false caveat is replaced with this correction.

No production code changed. **No performance claim in either artifact changes** --
the +38.0% prefill figure (7.191 -> 5.213 s, 284.8 -> 392.9 tok/s) stands, and its
own correctness evidence (kernel numerics against the grouped owner and an exact
oracle, identical token ids route-on vs route-off) was never dependent on the
generation question.

## Validation

```
env -u HIP_VISIBLE_DEVICES ROCR_VISIBLE_DEVICES=0 PYTHONPATH=. \
  python3 -m hipengine serve --model <UD-Q4_K_XL.gguf>
# routes: ['/health', '/ready', '/v1/chat/completions', '/v1/completions', ...]
# POST /v1/chat/completions -> 'Paris'
```

The first two attempts returned 404 for a different reason worth recording so it is
not re-diagnosed: the server rejects an unknown `model` field with a 404
`model_not_found`, not a 400, so a wrong model name looks like a missing route.
`GET /v1/models` gives the served name.

## Next

`test_incremental_decode_matches_a_dense_prefill` remains open as the one real
defect this alarm turned up, now correctly scoped: it is a divergence that appears
only on the tiny fixture, since the real geometry is bit-exact. Whoever takes it
should start from what differs between the fixture and the artifact -- most likely
the sliding-window pattern or a geometry the fixture does not exercise.
