# Task 5: pool-backed packed KV - S1d lease-path integration

## Summary

S1d completes task #5 (pool-backed packed KV contract unification). The
packed-execution KV workspace now borrows its planes from the
GlobalDeviceKVPool arena under an eager, load-time workspace lease instead of
allocating a private KV chunk. This makes admission accounting see the pinned
workspace pages from the start (net-zero vs today's peak mirror footprint)
and removes the private chunk allocation from `_GGUFPackedTargetState` when a
lease is present. The recovery gate is made lease-aware so the pinned lease
is treated as expected pins, not a leak.

## Changes

- `GlobalDeviceKVPool.backing` accessor exposes the pool's plane backing, so a
  leased workspace addresses `plane_ptr + page_id * plane_page_bytes` exactly
  like the request path (same arena).
- `_GGUFPackedTargetState.allocate(..., kv_pool=...)`: when the pool holds a
  lease under `_GGUF_PACKED_WORKSPACE_LEASE_KEY`, the state takes
  `kv_backing_kind="pool_lease"`, borrows `arena_backing`, and sets
  `page_ids` from the lease pages (validated for layout compatibility and
  page count). No fresh allocation and the plane buffers are not owned.
  Without a lease it keeps the private-chunk path (`kv_backing_kind="private"`).
- Runner `bind_workspace_kv_pool` / `packed_workspace_backing` on
  `Qwen35GGUFResidentSession`, owner-delegating so the shared packed workspace
  sees exactly one pool. `_workspace_kv_pool` is threaded into the union
  workspace allocation.
- Generation layer `configure_engine_loop` now takes an eager workspace lease
  at pool creation, sized `max(8, capacity) * max(mpp, 1024//256)` pages to
  honor the union-geometry 1024-token/slot floor even when request contexts
  are shorter (the GPU gate caught mpp=3 vs the 4-page floor). `_kv_pool`
  `page_capacity` is bumped by the lease so admission sees the pins.
- `_teardown_kv_pool(release_workspace_state=...)` centralizes teardown:
  release idle packed workspace (owner) then release the lease before
  `close()` (which rejects pinned pages); binds the pool to `None` on owner.
  Used by configure reconfig, resize, and shutdown paths.
- Observability: `kv_pool_memory_snapshot` reports
  `packed_workspace_backing` and `packed_workspace_lease_pages`.
- Recovery gate `_memory_recovery_gate` treats
  `packed_workspace_lease_pages` as expected pins (`pinned == lease`,
  `current_pages == free_pages + lease`); a missing lease keeps the
  zero-pin legacy contract and unexpected pins still fail closed.
- Device-metadata gating from S1c covers the leased workspace: a non-identity
  rebound block table fails `_packed_decode_metadata_device_eligible` and
  falls back to host upload / graph gate (decode graphs refresh metadata
  through that same path), so no non-identity pages reach the identity-writing
  `prepare_packed_decode_metadata*` kernels.
