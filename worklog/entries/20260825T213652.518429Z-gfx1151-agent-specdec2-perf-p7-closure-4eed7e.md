# Retain SPECDEC2-PERF P7 conditional provider repair

## Summary

Retain P7 conditional physical-provider repair for strict gfx1151 C2/C4.
Persistent request-slot storage captures provider Conv/GDN state and cursor
after each proposal root. Reject restores that snapshot, accepted `K-1`
publishes the already-current proposal state, full acceptance advances only the
last candidate, and every other depth retains checkpoint restore/replay. The
change is T0 and keeps the shipped exact fallback.

Mixed K2 repair improves **127.743→30.518 ms (4.186x)** at C2 and
**138.779→34.292 ms (4.047x)** at C4. Full-suite physical throughput improves
**5.718→5.796 (+1.37%) / 9.331→9.445 tok/s (+1.22%)**, with every category
positive. C1 is neutral/out of scope. Physical acceptance remains **18.43%** and
throughput remains below true AR, so automatic/product policy stays K0.

## Changes

- Added persistent after-root snapshot/cursor ownership to the NextN executor,
  exact reject restore, K-1 no-op publication, and strict fallback for all other
  partial depths.
- Corrected physical provider qualification to require post-P4 zero candidate
  D2H and to hash request-owned KV rather than the whole multi-slot backing.
- Bound provider determinism by corresponding physical slot and kept direct
  cross-width arithmetic diagnostic; controlled P6→P7 comparison is exact
  **6/6** fingerprints.
- Added root snapshot copy/cursor/reset/slot-reuse tests plus mixed full/K-1/
  reject/K3-intermediate state-machine coverage.
- Closed the P7 checklist and updated the benchmark rollup/changelog/artifact.
