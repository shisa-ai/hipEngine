# close PS9 with measured streaming usage

## Summary

The last open PS9 item was streaming usage accounting. The API documents that
a stream publishes usage only when the request opts in with
`stream_options.include_usage`, so the audit now asks for it. For one request
the terminal SSE payload and the blocking response agree exactly:

```
blocking  {"prompt_tokens": 26, "completion_tokens": 51, "total_tokens": 77}
streaming {"prompt_tokens": 26, "completion_tokens": 51, "total_tokens": 77}
text      matches, completion_tokens > 0
```

The first run of the audit failed this case because it read a stream that never
asked for usage; the failure was in the check, not the server. That is worth
recording: a null usage field means "not requested", not "not accounted".

The finish/route audit now carries 25 checks over six live cases (length, EOS,
request stop, `ignore_eos`, sampled MTP, SSE usage) and the artifact was
regenerated from the passing run.
