# Copy nothing on the host to validate controller plans

## Summary

A host profile of one public 2,057-token prefill at `180688962` (cProfile, 1.81 s under the
profiler) put nearly all host time in waits on the GPU and in two things that were not:

- `_controller_plans` made each controller's hidden and message rows contiguous with
  `np.ascontiguousarray` before checking their shapes. The message of a loop visit is a strided column
  of a (rows, 4, hidden) array, so each check copied 9.4 MB: 144 copies in a 1,024-row block from
  `project_attention_resident` and 12 from the extent probes, 58 ms in a block of 830 ms. The resident
  path reads these rows on the device and the staging path concatenates them; neither reads the
  copy. The check takes `np.asarray`, which converts a dtype and copies nothing else.
- Each attention bank of a request was made at its visit's first block attention, with a blocking
  upload. `reserve_capacity()`, which makes every bank, had no caller.

**First token, both changes against the committed tree** (W7900, `scripts/inkling2_decode_bench.py
--backend hip_gfx1100 --prompt-tokens 47 575 2057 --output-tokens 2 --reps 3 --warmup 1`, omitted
profile; committed and working trees alternate, two runs each).

| Prompt tokens | Committed | Both changes | Ratio | Output tokens |
| --- | ---: | ---: | ---: | --- |
| 47 | 0.193 and 0.198 s | 0.198 s (0.195 to 0.200) | 1.012 | the same tokens |
| 575 | 0.451 and 0.465 s | 0.459 s (0.458 to 0.464) | 1.002 | the same tokens |
| 2,057 | 1.713 and 1.735 s | 1.731 s (1.726 to 1.737) | 1.004 | the same tokens |

Neither change moves the first token. The GPU idle time of a prefill is not host starvation: at
2,057 prompt tokens it is 105 ms of 1,690, of which 39 ms is 6,722 gaps of about 6 us between
consecutive kernels (the device's own dispatch), 33 ms is two gaps of 18.6 and 14.1 ms at the starts
of the second and third blocks, and the rest is smaller gaps. The block starts are host work before
the first launch: a Q8_0 embedding dequantization of the block's rows (`_dequant_q8_0_blocks`),
the entry RMS norm and the first uploads, 11 ms before the first block and 4 ms before the second
in a sampled run, while the GPU has nothing queued.

So the copy stays removed and the bank change does not: making all 48 banks at the first visit
removed the 48 syncs and changed nothing else.
