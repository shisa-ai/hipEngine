# Gemma 4 MTP on gfx1151, W7900 topline row, and OpenAI serving MTP audit

## Summary

Lead request: Gemma 4 MTP numbers for gfx1151, a Gemma 4 row in the W7900
topline table, and confirmation that Gemma 4 MTP serving through the OpenAI
API has no context or route limitations.

**Measured, gfx1151** (Framework Desktop / Radeon 8060S, `6d2150288`, TheRock
ROCm 10 wrapper, production, BF16 KV): `scripts/gemma4_mtp_probe.py` with the
`Q8_0` assistant head, budget 4, both prompt suites (18 prompts x 2 samples),
128 greedy tokens, whole-call rate. Plain 45.5, MTP 69.4 tok/s (mean of row
rates; 68.9 pooled), 1.52x, 72.3% acceptance, 36/36 rows pass, 28/36
token-identical (production verify envelope). W7900 row values come from
existing 2026-10-15 artifacts: 3696.9 / 76.43 (512/128 paired session) and
118.3 MTP (expert-chunk8, budget 4, same 18-prompt protocol).

**Serving audit** (`hipengine serve --speculative-provider gemma4_mtp
--draft-model <Q8_0 head> --speculative-candidate-budget 4
--max-context-tokens 65536`, gfx1151, real HTTP requests):

- Works: `"speculative_mtp": true` greedy runs MTP (`route=speculative_mtp`,
  `sampler_mode=greedy_speculative_mtp`, ~66 vs ~46 tok/s whole call); a
  27,444-token prompt completes on the MTP route (no fixed context cap; the
  provider sizes its scratch from target capacity); thinking mode works and
  splits `reasoning_content`; two concurrent MTP requests both complete
  (serialized, c1).
- Defect 1, default routing: a request without the field runs AR with
  `route_decision.reason=automatic_mtp_scope_not_promoted`,
  `policy_reason=product_qualification_pending` -- an evidence gate, which
  AGENTS.md "Capability is the only gate" does not allow.
- Defect 2, sampled downgrade: `"speculative_mtp": true` with temperature 0.8
  silently runs AR (`unsupported_sampling_k0`); the provider implements
  sampled MTP (measured on W7900 via `LLM`). Explicit request must run or fail.
- Defect 3, streaming: `"speculative_mtp": true, "stream": true` fails with
  "speculative streaming is not supported by this generator" although
  `Gemma4GGUFGenerator.stream_speculative_detailed` exists (route wiring).
- Defect 4, generic route: `"speculative": true` is refused HTTP 400 for every
  request with `blockers: ["kv_scale_dtype"]`: the server config resolves
  `kv_scale_dtype=fp32` for BF16 KV and the `raw_greedy_bf16_c1` guard rejects
  it; sampled additionally blocked on `temperature`.
- Defect 5, startup banner: prints `Speculation MTP unavailable (unresolved)`
  and `Context unknown tokens` while `EFFECTIVE_MTP` reports
  `engine_supported=True` and the MTP warmup ran.
- Minor: top-level `hipengine.speculative_mtp.draft_tokens` etc. read 0 on the
  provider route; the per-choice `diagnostics` carry the real counts.
