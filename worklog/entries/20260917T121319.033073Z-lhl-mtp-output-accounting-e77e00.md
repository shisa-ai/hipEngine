# Attribute every emitted token to MTP or autoregressive execution

## Summary

A speculative response no longer reports `used: true` as if it were full
coverage. Every request that carried speculative intent now publishes an
execution block splitting its emitted tokens into MTP-committed output and
autoregressive output, with the selected-depth histogram, the fallback reason
counts, and the output position where speculation stopped. On the real
default-configuration `gfx1151` server a 945-token prompt with 128 greedy
outputs reports **77 MTP / 51 AR tokens**, `mtp_coverage 0.602`,
`first_fallback_position 78`, and all 128 exact generated IDs accounted; a
3,530-token prompt refused at admission reports `fallback_reason
target_context_k0` beside the preserved `decision_reason backend_k0_fallback`.

The second fix is that streamed speculative requests now report the same
counters as blocking ones. The streaming chunk path published no MTP timing
fields at all, so an SSE summary claimed `effective_route: default` /
`decision_reason: backend_k0_fallback` and zero draft counters for a request
that was in fact running speculative cycles. Arm B below is the same request as
arm A and now reports identical counters and identical output.

## Changes

- `hipengine/speculative/accounting.py` (new): per-request row counters
  (`mtp2_mtp_output_tokens`, `mtp2_ar_output_tokens`,
  `mtp2_ar_step_output_tokens`, `mtp2_first_fallback_position`,
  `mtp2_ar_step_reasons`, `mtp2_cycles`, `mtp2_candidate_counts`,
  `mtp2_accepted_counts`) and one recorder per committed cycle, so the reported
  depth histogram can never disagree with the reported output split.
  `speculative_output_accounting` returns the response block (`None` for a
  request that never carried speculative intent, which keeps plain AR responses
  byte-identical), and `accounting_timing_fields` publishes scalar mirrors only
  for requests that committed at least one cycle, so a zero-cycle refusal cannot
  be mistaken for realized MTP.
- `hipengine/generation/qwen35_gguf_mtp2.py`,
  `hipengine/generation/qwen35_gguf_moe_mtp2.py`: the dense, graph, eager and
  MoE adapters all record cycles through the shared recorder, which removes the
  duplicated `mtp2_cycles += 1` bookkeeping. The singleton target paths and the
  MoE complete-cycle path now index `plan.candidate_counts` / `plan.reasons` by
  their own request id instead of plan position 0, so a mixed plan cannot
  attribute one row's cycle to another. `prepare_k0` records each K0 step of an
  AR-only cycle with the planner reason that selected it and the output index
  its token will occupy.
- `hipengine/generation/qwen35_gguf.py`: rows publish the execution block under
  `diagnostics.specdec2_mtp2` for every request with speculative intent, the
  requested depth is never zeroed by a later refusal, and the streaming chunk
  mirrors the scalar counters into its `timing` map with
  `execution_path=gguf_specdec2_mtp2` when cycles committed. The blocking path
  reuses the same helper instead of recomputing the counters inline.
- `hipengine/server/api.py`: blocking responses, SSE final metadata and SSE
  usage report `mtp_output_tokens`, `ar_output_tokens`, `output_accounting`
  (`completion_tokens`, both counts, `ar_output_tokens_in_cycles`,
  `mtp_coverage`, `reconciled`), `selected_depth_histogram`,
  `fallback_reason_counts`, `fallback_reason` and `first_fallback_position`.
  `decision_reason: backend_k0_fallback` is preserved as the compatibility
  label and the specific refusal is reported beside it.
- `scripts/gguf_mtp_api_gate.py`: a `used: true` row whose output split does not
  reconcile with `usage.completion_tokens` now fails the gate.
- `docs/API.md` (field semantics and the stale "MTP is non-streaming" claim),
  `docs/QWEN38-GFX1151-MTP-SERVING-IMPROVEMENTS.md` (P0 marked done),
  `docs/REFACTOR.md` (two follow-up debts recorded).

Semantics: `ar_output_tokens = completion_tokens - mtp_output_tokens` holds by
construction, because autoregressive output is whatever speculation did not
cover. `first_fallback_position` is `null` when speculation covered every token
after the prompt root, `0` when it covered none, and the emitted-token index of
the first non-speculative token after speculative output otherwise (the prompt
root token is emitted by target prefill, so it is the `+1` in
`mtp_output_tokens + 1`).

Arm A committed 23 cycles (66 drafts, 54 accepted, depth histogram
`{1: 1, 2: 1, 3: 21}`), reported all 128 exact generated IDs, and its fallback
reason counts total 51 - equal to its autoregressive output, so every
autoregressive token in that run carries the planner reason that selected it.
Arm B reported the same counters, the same position, and the same
`accepted_prediction_tokens: 54 / rejected_prediction_tokens: 12` usage details,
with byte-identical 690-character output. Arm C kept
`decision_reason: backend_k0_fallback` and added `fallback_reason:
target_context_k0` with `first_fallback_position: 0`.

The split was then tied to the actual token sequence: the same request served by
the autoregressive route (`--speculative-candidate-budget 4`, so the route stays
`default`) emitted the **identical 128 token IDs and the identical 690-character
text** (sha256 `733cb9781ae74639...`), so arm A's 77/51 split describes the
sequence the speculative route emitted rather than a different one. That arm
carried no speculative intent and therefore omitted the accounting block
entirely instead of reporting zeros, which is what keeps a plain autoregressive
response byte-identical to before. Exact command: `/tmp/run-accounting-ids.sh`.
