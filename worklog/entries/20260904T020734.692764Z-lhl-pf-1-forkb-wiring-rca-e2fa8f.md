# PF-1 fork-b down wiring bug: invalid first whole-model A/B, root cause, fix

## Summary

The first fork-b whole-model A/B (2026-09-04 ~00:07-01:03Z) is **INVALID and
superseded**: the runner wiring passed `group_sorted_lanes` (sorted position →
original lane) as the fork-b kernel's `lane_to_row`, but the qwen4-exp
grouped-prefill scratch buffers (`expert_intermediate`, `expert_down`) are
already indexed by sorted position. The kernel therefore read `x[orig_lane]`
and wrote `out[orig_lane]`, pairing each lane's expert weights with another
lane's data. All 36 whole-model greedy samples diverged in output tokens from
the incumbent (the `qwen4exp_candidate_ar` harness is deterministic — PF-4 arms
matched bitwise — so any divergence is real). The candidate showed +2.35% mean
prefill, which was garbage math, not a measured loss.

## Changes

- `hipengine/kernels/hip_gfx1100/quant/gguf_k_gemv.{hip,py}`: `lane_to_row`
  optional (nullptr → row = sorted position); wrapper accepts None.
- `hipengine/runtime/qwen4_exp_runner.py`: fork-b call passes nullptr.
- `tests/test_qwen4exp_pf1_forkb_selected_down.py`: hardened runner gate
  (bit-equality vs strict, oracle-deviation bound, determinism).

## Root cause

- Kernel semantics are `row = lane_to_row[lane]` for `lane` ranging over the
  expert's sorted positions; the runner's buffers needed `row = lane`.
- The kernel-level RED tests passed because they exercise the general
  selected-gemv contract (x in original order + argsort map), which is self-
  consistent.
- The first runner-level gate compared only final MoE output bits across the
  flag on/off. That gate is necessary but NOT sufficient: the group scatter
  uses `atomicAdd`, so within-expert lane order (and hence the down row
  layout) is nondeterministic per run, and for some scatter orders a wrong
  map can coincidentally produce bit-identical final output (observed: the
  same wrong-map wiring produced bit-equal output in one process and
  corrupted output, oracle rel err ~1.0, in another).

## Fix (commit 2cfd2f16e)

- Kernel: `lane_to_row` is now optional — `nullptr` means `row = lane` (the
  qwen4-exp grouped-prefill scratch layout); the argsort-map contract stays
  tested for general selected-gemv semantics. Runner passes `nullptr`.
- Runner-level gate hardened: (a) whole-MoE output bits vs flag-off strict
  (binding, deterministic), (b) oracle-deviation gate — the fork-b default
  may not deviate from the float64 CPU oracle more than the incumbent strict
  path does on the same fixture, (c) run-to-run determinism of the default
  output. Cross-run `expert_down` bit comparison is explicitly invalid and
  documented as such in the test.
- Controlled kernel-semantics check (outside the runner): nullptr == strict
  owner on sorted-layout inputs; a cross-group permutation map changes the
  output (map is honored); a within-group map is output-preserving.

## Validation

- `tests/test_qwen4exp_pf1_forkb_selected_down.py` 4/4,
  `test_qwen4_exp_runner_moe.py` + `test_qwen4_exp_q8_0_grouped_down.py`
  8/8 (12/12 combined).
- Fixed-wiring runner check: fork-b default == strict bitwise, run-to-run
  deterministic, identical oracle deviation profile to strict.
- Whole-model A/B rerun with the fixed wiring launched as a single clean
  background run (an earlier concurrent double-run of two A/B scripts
  sharing one output directory was killed; its partial artifacts discarded).
