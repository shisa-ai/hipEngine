# Measure the complete TP1 versus TP2 segment walls and profile the exchange

## Summary

TP2-D is done. The complete MLP segment - TP1 fused pair+SiLU plus down GEMV
against the two-GPU rank chain plus staged exchange - is measured on this host
with host walls around synchronized steps and HIP events for per-stage device
time. The headline: **the fused shard route reaches parity with TP1, and the
exchange driven from Python is the whole remaining gap.**

| route | step wall p50 | chains | exchange |
| --- | ---: | ---: | ---: |
| TP1 (fused pair+SiLU + down) | 323.8 us | pair+silu 175.5, down 130.0 | - |
| TP2 fused | 335.6 us | 246.9 | 85.2 |
| TP2 unfused | 401.6 us | 307.2 | 90.7 |

Segment saving: **-11.8 us (fused)**, -77.8 us (unfused). The fused candidate
being bit-exact (TP2-B) is what moves the segment from -78 to -12 us; the
policy table still does not admit the shape, so the route a shard resolves to
today is the unfused one.

## Where the exchange's 85 us goes

Profiled part by part at steady state (`profile_exchange_parts`, now in the
artifact):

| part | p50 |
| --- | ---: |
| gather: both D2H submits + both waits + host f32 sum | 28.6 us |
| full exchange including the H2D return to both ranks | 57.6 us |
| **return path alone** | **29.0 us** |

The return copies to both ranks cost as much as the entire gather. In-step the
exchange measures 85-91 us (higher than the isolated 58), and the transport
A/B's native arm measured **20.8 us per reduction** for the same batched
protocol driven from compiled code. The gap is Python protocol overhead: twelve
`hipSetDevice` switches, eight ctypes `memcpy_async` calls and the syncs, not
copy bandwidth - a 20 KiB payload cannot cost 85 us on a card that moves
hundreds of GB/s.

## Changes

`scripts/tp2_mlp_slice_e2e.py`: `measure_tp1_segment` (async launches, one
synchronized step, event-based stage times), `measure_tp2_segment` (both ranks'
chains launched concurrently, then the exchange; the residual add excluded on
both paths as one identical 5120-vector add), `profile_exchange_parts`, and the
batched submission order in `staged_exchange_reduce` (both D2H submitted before
either wait; H2D submitted without a return wait, ordered by stream order).

## Reading and the tuning targets this sets

The user's frame - a working implementation first, then tuning targets - is now
concrete. The implementation is complete and numerically equivalent to TP1 end
to end (f32 accumulation noise at the boundary). The measured tuning targets:

1. **Compiled exchange submission.** The A/B already measured 20.8 us/reduction
   for this protocol from C++; the engine drives every other kernel through a
   compiled .so + ctypes wrapper, and the exchange should be no exception. At
   ~21-30 us in-step, TP2-fused lands at ~271-280 us against TP1's 323.8 -
   a 1.14-1.19x segment saving, consistent with the break-even's 1.24x at 10%
   fixed share.
2. **The return path.** Mapped pinned memory (`host_register` with the mapping
   flag, per its docstring) would let both ranks' next consumers read the
   reduced vector zero-copy and remove the 29 us return entirely - the
   exchange becomes the 28.6 us gather.
3. **The fused admission.** The kernel is bit-exact at the shard shape (TP2-B);
   admitting `(1, 5120, 8704)` to `GGUF_DENSE_PAIR_SILU_DECODE_POLICIES` under
   the gate the existing entries used is what separates -78 from -12 us today.

The remaining work beyond the MLP slice is #43's attention/GDN extension
(task 7) and the full decode step.
