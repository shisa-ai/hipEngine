# 24 GB serving memory: price, share, and fit what serve allocates

## Summary

Follow-up to `20261020T080210.517783Z-lhl-xtx-27b-mtp-oom-94d47d.md`. On
v0.8.0 a plain `hipengine serve --model Qwen3.8-27B-Q4_K_M.gguf` could not serve
on a 24 GB RX 7900 XTX: the auto context sized against a model that both
over-priced (BF16 transient, private planes for every slot, a 3 GiB reserve)
and never priced what the server allocates after the free-memory reading (bulk
and packed prefill scratch, per-slot recurrent state, prefix snapshots, the
MTP draft and verify rows). The MTP warmup OOMed and closed the engine; with
MTP off the auto context was 5,632 tokens and a 32K BF16 prompt was refused.

This unit removes duplicate memory, prices every remaining consumer from its
allocator, makes the KV pool's budget consistent with that model, and sizes an
unpinned serving capacity against the GPU.

## Changes

- Waste removed:
  - INT8 prefill oracle sized to the session's logical positions instead of
    the whole backing pool (packed callers pass their page range; growth keeps
    earlier rows).
  - BF16 slot-local prefill no longer allocates a full-context private copy of
    packed KV planes (the slab never reads or writes them).
  - One NextN draft block shared by every provider shape; materialized before
    the capacity reading when MTP serving is enabled.
  - KV pool idle floor capped at one full-context request.
  - Packed workspace growth leases idle pool pages before a private chunk.
- Capacity model (`_capacity_route_terms`, `qwen35_gguf_resident_breakdown`):
  bulk/packed prefill scratch by a dry run of their allocator
  (`_gguf_prefill_scratch_nbytes`, byte-exact against GPU allocation), packed
  linear state from geometry, resident scratch at serving capacity with KV for
  one request, INT8 prefill transient from the lifetime planner (per-layer
  oracles under MTP streaming, the shared pair otherwise; zero for BF16),
  prefix snapshots (capacity + 1 transient plus the retained budget), MTP
  verify rows and draft sessions. Reserve default 3072 -> 768 MiB.
- KV pool admission reserve = the priced non-pool allocations that follow
  pool creation (packed scratch, snapshots, transient, speculative) plus the
  reserve less 256 MiB of pre-pool overhead, instead of a fixed 1 GiB.
- Automatic serving capacity when `max_active_requests` is unset: the largest
  of (4, 2, 1) whose priced context reaches 32K (or the pinned context).
- Runtime robustness: pressure eviction also releases idle transient prefix
  captures; a refused packed decode workspace decodes rows individually
  instead of failing requests.
- Committed separately: startup fails (instead of announcing ready) when a
  warmup closed the engine, and the pinned-context warning (`586f2b8e7`);
  ROCm VMM sub-range SetAccess fallback and sticky-error clearing
  (`aaf4a3315`).

## Validation

- RED/GREEN: new `tests/test_unit_qwen35_gguf_capacity_route_terms.py` (19),
  plus oracle, packed workspace growth, pool floor, prefix pressure tests.
  Default unit tier passes except
  `test_unit_qwen4_exp_artifact_quant.py::test_auto_and_explicit_ud_select_identical_profile_manifest`,
  which fails identically on a clean HEAD worktree (gfx1151 backend on this
  gfx1100 host).
- RX 7900 XTX (24 GB), `hipengine serve --model Qwen3.8-27B-Q4_K_M.gguf`, no
  context or capacity flags; each run: one prompt at 97% of the auto context
  (64 output tokens) then 4 concurrent ~2K-token requests:

  | Config | Auto capacity | Auto context | 97% prompt | 4 concurrent | Min free |
  | --- | ---: | ---: | --- | --- | ---: |
  | BF16 + MTP (default) | 1 | 28,160 | ok, acceptance 0.85 | ok | 0.55 GiB |
  | BF16, MTP off | 2 | 45,056 | ok | ok | 0.41 GiB |
  | INT8 + MTP | 1 | 16,128 | ok, acceptance 0.79 | ok | 0.59 GiB |
  | INT8, MTP off | 2 | 45,824 | ok | ok | 0.79 GiB |
  | BF16, MTP off, `--max-active-requests 1` | 1 | 55,808 | ok | — | 0.74 GiB |
  | INT8, MTP off, `--max-active-requests 1` | 1 | 55,808 | ok | — | 1.88 GiB |

- W7900 (48 GB), defaults: auto context 160,768 (v0.8.0: 61,440); a 97% prompt
  and 4 concurrent requests all returned 200 with 6.9 GiB free at the low
  point (measured before the private-plane term was dropped).
- Dry-run scratch sizing matched every real allocation it shadowed
  (e.g. 0.7994 vs 0.7994 GiB at 1,024 rows, 0.0971 vs 0.0971 at 128).
- Multi-turn prefix continuation (30K cached + short suffix, BF16, MTP on and
  off, W7900) allocated no full-length packed planes, which is why private
  growth is no longer priced for a single request.

## Next

- INT8 is still conservative (1.88 GiB unused at c=1): the layer-outer
  transient prices three oracle pairs.
- Packed workspace is rebuilt every 256-row chunk during long prefills
  (~90 GiB of malloc/free churn per 30K prompt): a throughput issue.
- Several concurrent long-context requests still rely on runtime admission
  refusal; they are not priced.
