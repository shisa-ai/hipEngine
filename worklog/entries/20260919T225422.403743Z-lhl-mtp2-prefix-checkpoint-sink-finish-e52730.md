# MTP prefix checkpoint: the prompt sink must close on a completed timeline, not per prefill call

## Summary

The unit that gives prefix-cache hits a draft provider was attempted against a
live workload, reached the intended restore/stream/deepen behavior for the
first time, and then failed every hit row on a pre-existing sink-lifecycle
assumption. It is reverted; the blocker and the three-part fix are recorded
here so the next unit lands them together.

## Changes

- None retained. `hipengine/generation/qwen35_gguf.py`,
  `hipengine/generation/qwen35_gguf_mtp2.py`, and the two touched test files
  were reverted to `600377837`; `git status` is clean.

## Validation

- Live 3-turn prefix-hit workload (server + `/v1/chat/completions`, opt-in
  `HIPENGINE_MTP2_TRACE_DECLINE=1`): with the wiring, requests 3 and 5 restored
  the checkpoint, streamed 256 suffix rows, and captured a new checkpoint at
  512; both then failed with
  `streaming NextN prompt sink finished before every row was consumed`.
- After the revert, the same workload serves both hit rows with
  `activation_reason=prefix_reuse_k0`, `mtp_used=false`, and no errors.
- `uv run --no-sync python -m pytest tests/ -q -k "mtp or prefix"` green
  (exit=0) at the reverted tree.

## Next

- Land the three pieces together: finish the prompt sink only on the call that
  completes its timeline, close it from the adapter before
  `take_final_pending_buffer`, and abort a short sink to the autoregressive
  fallback instead of failing the request.

## Decision

Give prefix-cache hits a draft-provider checkpoint instead of refusing MTP
(design: `20260919T204437.506351Z-lhl-mtp2-prefix-checkpoint-design-276f2b`).
Unit 3 -- wiring the restored provider into the hit row's reused-suffix
prefill -- was implemented, exercised on a live 3-turn prefix-hit workload,
found to fail every hit row, and reverted. The tree is unchanged; the unit is
still open with the blocker localized below.

## What was built and measured

Wiring the sink into the batched reused-suffix route in
`_prefill_native_chunk` (`hipengine/generation/qwen35_gguf.py`, the
`if row.prefix_reused_tokens:` branch) is the correct site: that route is what
prefills a hit row's suffix rows, so it is the only place a hit row's provider
state can come from. With that wiring plus the runner-side activation gates,
the live run showed the intended shape for the first time:

```
[mtp2-prefix-checkpoint] begin_streaming rows=[(3, 3, 256)]
[mtp2-prompt-sink] first consume request=3 chunk_start=0 rows=256
[mtp2-prefix-checkpoint] captured prefix=512 blocks=2 held=2
```

That is a hit row (request 3, `prefix_reused_tokens=256`) restoring the
turn-1 checkpoint at 256, streaming its suffix, and capturing a *new*
checkpoint at 512 -- the turn-2 prompt boundary -- which is the intended
deepening behavior. Requests 5 (turn 3) repeated it.

## Blocker

Every hit row then failed its request:

```
RuntimeError: streaming NextN prompt sink finished before every row was consumed
```

Root cause: `hipengine/runtime/qwen35_gguf_runner.py:21252` closes the sink
inside each `prefill_batch_native` call with
`target_hidden_chunk_sink.finish(request_id=..., total_rows=rows, ...)`, where
`rows` is the width of *that call's* segment. Every existing sink site is a
single call that covers the whole prompt, so `total_rows == sink.total_rows`
held by construction and the contract was never exercised. A reused suffix is
chunked (256 + tail), so the first segment closes a 300-row timeline at 256
rows.

## Fix shape for the next unit

1. `qwen35_gguf_runner.py`: only finish the sink on the call that completes its
   timeline (`rows == sink.total_rows`); leave it open otherwise. Applies to
   the `prefill_batch_native` sink sites, not just this route.
2. Adapter `finish_prompt_streaming`: close the sink itself
   (`sink.finish(request_id=..., total_rows=sink.total_rows, stream=...)`)
   before `take_final_pending_buffer`, since the completing call is not
   guaranteed to be the one that owns the prompt.
3. Route a short sink to the `success=False` abort path so the row falls back
   to autoregressive decoding with a recorded reason instead of failing. A
   request must never fail because MTP could not prime.

Then re-land the three reverted pieces together, since each is only meaningful
with the others: the runner-side activation gates
(`prefill_claim_available`, `prefill_needs_activation`,
`_begin_mtp2_prompt_streaming` selection), the adapter-side restore/warm-sink/
priming-source half, and the prefill wiring. The pre-existing contract test
`test_restored_priming_source_needs_a_validated_checkpoint` encodes the
"refuse when the suffix is unavailable" rule and must be updated in the same
unit, not before it.
