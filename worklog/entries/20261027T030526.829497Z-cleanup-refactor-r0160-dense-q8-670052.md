# Isolate dense Q8 WMMA tile policy by execution owner

## Summary

Replace dense Q8 tile process transport with context-local execution policy,
preserving Qwen's published pair and other models' backend heuristics.

## Changes

- `gguf_q8_0_prefill` exposes `wmma_tile_policy` / `current_wmma_tile_policy` /
  `normalize_wmma_tile_pair` over a `ContextVar`; the retired process keys have
  no reader. `_default_tiles` returns the bound pair, else the arch heuristic;
  an explicit per-side launch argument still wins over both.
- Binding is ownership, not an override: `(None, None)` binds "no policy" and
  masks an outer pair, so a nested runner cannot inherit its caller's tiles.
- The binder publishes `q8_wmma_tiles` (64, 32) on the owning runner and the
  batch carrier instead of writing env keys; the runner field defaults unbound.
- Execution binds: prefill chunk driver, chunk loop, state-row verify (whole
  entry, covering its rows>1 deferred head), deferred-head verify (whole entry),
  batch `step` (carries the pair in the layer capture key), mixed-target
  `verify`. Serial one-row entries (`step`, `prefill_serial`,
  `verify_target_block_serial_exact`) carry no bind.
- The prefill final head runs after the per-chunk scope and stays unbound by
  proof: both calls pass `rows=1`, and `_wmma_prefill_dispatch` declines
  `rows <= 1` before it inspects the quant or `use_wmma`.
- Reset is a strict `ContextVar` token reset: a scope exited from another
  context raises rather than passing, and cancellation closes suspended
  generators in their owning context (`context.run(steps.close)`).
