# Separate Gemma 4 speculative verification from prompt attention

## Summary

The production attention selector treated a multi-row speculative verify as
prompt prefill. Plain decode used the strict attention implementation, while
the verifier used production prefill arithmetic. Four of 18 public-API prompt
comparisons diverged late in a 64-token output. Explicitly distinguishing
verification resolves those four failures without changing prompt prefill.

## Changes

- Add `verification=False` to `Gemma4Runner.forward` and propagate it per block.
  Verification requests the existing strict batched attention implementation,
  which is the target decode arithmetic, and does not opt full blocks into
  dense WMMA prompt prefill. No global execution-profile mutation or scalar
  verifier loop is introduced.
- MTP passes `verification=True` only for draft verification. Its prompt uses
  the same production prefill selection as plain generation.
- CPU tests cover phase forwarding at widths 1, 3, 8 and 11, including full and
  partial chunks. GPU coverage intercepts the actual layer calls and confirms
  production-prefill, verification, production-prefill selection in sequence.
