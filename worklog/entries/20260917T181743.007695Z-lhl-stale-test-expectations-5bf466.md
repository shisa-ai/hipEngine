# Repair two stale test expectations left by earlier contract changes

## Summary

A full-file run of the engine-loop bundle surfaced four failures that predate
this session's working tree. Bisecting them by stashing the working tree and
checking out the candidate commits showed two independent, already-committed
contract changes whose test expectations were never updated. Neither is a code
regression: the production behavior in both cases is the one the earlier commit
measured and intended, and the tests still asserted the superseded policy.

## Changes

### Streaming mailbox bound (`0a184f55d`, 2026-09-17)

That commit replaced the fixed 64-entry engine-to-consumer mailbox with the
child's own output budget (configured value as a floor, 4096-entry hard cap)
because a fixed bound turned a slow consumer into a dead request: a measured
200-token MTP stream was cancelled at 96 tokens with
`budget_pressure=client_backpressure`. It updated the engine-service
backpressure test but missed the same assertion in
`tests/test_integration_generation_batch_scheduler.py`, which still expected
`stream_queue_max_chunks=1` to cancel an 8-token stream.

Repaired by asserting the current contract: with a configured floor of one
chunk and an 8-token budget the slow consumer drains all eight chunks without
cancellation, its neighbor completes, and the adapter's loop state is clean.
The block also pins the reclaim order `[(1, "length"), (0, "length")]`, which is
the order the scheduler actually completes them.

### Packed workspace lease (`9b3cce6ac`, 2026-09-17)

That commit sized the packed workspace lease from the union slot ceiling
(`packed_verify_lease_slot_ceiling`) instead of a hardcoded one slot, because a
one-slot lease went short against the union geometry and the allocation failed
closed at prefill time (1024-token session: lease 4 pages against a 16-page
workspace; 8192-token session: 32 against 36). Two tests in
`tests/test_unit_gguf_prefix_cache_runner.py` still expected the old one-slot
lease (`current_pages == 12`, four leased pages).

Repaired by deriving the expected page count from the same shared helpers the
production code uses (`packed_verify_lease_slot_ceiling`, the 1024-token
per-slot floor), so the assertions track the contract instead of a magic
number. The C1 test's name and docstring no longer claim a one-slot lease.

### Follow-up found while repairing (not fixed here)

`qwen35_gguf.py` reads the lease's slot term from
`getattr(getattr(self, "_resident_model_runner", None), "max_batch_size", None)`
on the generator, but `Qwen35GGUFResidentModelRunner` has no `max_batch_size`
attribute (verified: `getattr(Qwen35GGUFResidentModelRunner, "max_batch_size",
"ABSENT") == "ABSENT"`). The signal is therefore always `None` and the lease
always falls back to `_PACKED_VERIFY_DEFAULT_SLOT_CAPACITY = 8`, which is the
historical 8-slot floor the commit's own comment says it replaced. The effect is
an over-lease, not a short lease, so it is safe but wasteful, and it makes the
code comment ("the lease follows it instead of the historical 8-slot floor")
inaccurate. Recorded as a follow-up task rather than fixed here: the repair
needs the serving capacity plumbed to the pool lease, which is a resource
accounting change with its own measurement.
