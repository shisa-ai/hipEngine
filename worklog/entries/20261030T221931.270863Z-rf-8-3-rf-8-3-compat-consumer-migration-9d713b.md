# RF-8.3 migrate direct test and script capability consumers

## Summary

Migrated the direct test and script consumers of the `hip_gfx1151`
compatibility aliases to `backend_package_capability`. No alias was deleted;
the alias block and `__all__` are unchanged, and no production, runtime,
generation, docs, audit, or lineage file was edited. The two boundary tests
that assert alias identity are intentionally left as the compatibility gate for
the deletion unit.

## Inventory method

An AST scan over `tests/` and `scripts/` built the alias set from the package's
`NAME = _policy_x.NAME` assignments (373 names), then reported:

- direct `from hipengine.kernels.hip_gfx1151 import NAME` imports of aliases;
- attribute reads `X.NAME` where `X` is bound to the package by
  `import ... as X`, `from hipengine.kernels import hip_gfx1151`, or
  `X = import_module("hipengine.kernels.hip_gfx1151")`;
- dynamic `getattr(X, "NAME")` reads on the same binding.

Import/registry functions (`register_gfx1151_kernels`,
`import_gfx1100_kernel_modules`) and implementation kernel symbols
(`gguf_*_gfx1151_bf16_bf16_out`) were excluded. The precise pre-migration
inventory was 42 files: 7 with direct alias imports and 37 with package
attribute reads (some overlap).

## Changes

- `tests/test_unit_gfx1151_backend.py`: removed the 116 alias names from the
  gfx1151 import (the 3 non-alias names stay: two kernel wrappers and
  `register_gfx1151_kernels`), added a `_capability(name)` helper that reads
  `backend_package_capability` live with a missing-name sentinel and no cache,
  and routed 119 alias loads, 8 `gfx1151_backend.NAME` reads, and 9
  `getattr(gfx1151_backend, "NAME", None)` reads through it.
- Direct-import files: `scripts/qwen4exp_f16_pair_engine_ab.py`,
  `tests/test_unit_qwen35_gguf_mtp2_seam.py`,
  `tests/test_unit_qwen4exp_gr_staged_removal.py`,
  `tests/test_unit_qwen4exp_staged_f32_route.py`. Each use now reads
  `backend_package_capability("hip_gfx1151", "NAME")`; registrar imports stay.
  `scripts/qwen38_b1_verifier_owner_map.py` keeps the resolver import inside
  `main()` after its `sys.path.insert(0, str(REPO))` (see Repair below).
- 35 attribute-read files (14 GPU/live tests, 19 unit tests, 2 scripts) now
  read `backend_package_capability("hip_gfx1151", "NAME")` at the same use
  sites. The resolver import is placed after the file's last top-level import,
  except in the B1 script where it is deferred inside `main()`.
- Explicit package overrides are preserved: `tests/test_gpu_gguf_iq_dense_mmq_route.py`
  and `scripts/gguf_iq4_nl_mmq_layer_probe.py` assign the package binding with
  `setattr(be, "GGUF_IQ_DENSE_PREFILL_POLICY", ...)`, and the resolver's
  package-first read observes the override exactly as the alias did.
- Geometry objects and dicts are returned by identity from their owner; no
  copied or cached value was introduced. Scratch check: all 151 migrated
  names resolve to a value equal to the alias, with the same type, and every
  container is the identical owner object.

## Repair: B1 script import boundary

The first RF-8.3 pass put `from hipengine.kernels.backends import
backend_package_capability` at module scope in
`scripts/qwen38_b1_verifier_owner_map.py`. The old backend import was inside
`main()` after `sys.path.insert(0, str(REPO))`, so direct execution from a
fresh uninstalled checkout without `PYTHONPATH` broke. The resolver import
now lives at the same deferred point, and the unused
`import hipengine.kernels.hip_gfx1151 as gfx1151` is removed (its only use
was the shape read replaced by the resolver).

New `tests/test_unit_script_qwen38_b1_verifier_owner_map.py`:

- runs the module with `python -S` (no site-packages, no editable install),
  `runpy.run_path` from a temporary cwd, and `PYTHONPATH` removed; with the
  module-scope import both tests fail with `No module named 'hipengine'`;
- pins the AST contract: no module-level `hipengine` import, and the
  resolver import line follows the `sys.path` insert inside `main()`.

Other touched scripts: `scripts/qwen4exp_f16_pair_engine_ab.py` inserts the
repo root at module scope before its imports and reads the resolver inside
`_admitted_pair_rows`, so it has no ordering issue.
`scripts/gguf_iq4_nl_mmq_layer_probe.py` already imports `hipengine` at
module scope with no path setup (a repo-root-run GPU probe); the resolver
import follows that pre-existing pattern and is not a new regression.

are the deletion unit's first rewrite target.
