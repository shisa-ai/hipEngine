# EVIE bench fix + call-buffer release

## Summary

The first-path "175 s / 8 pages" number was mostly a benchmark bug, not
runtime cost. `scripts/evie_hip_bench.py` passed the page's pixel
dimensions (1, 448, 336) as `image_grid_thw` where the runtime expects
patch units (1, 28, 21) — the vision tower ran on 143,360 patches per
page (1.17 GiB position table) instead of 588. Separately,
`_misc_buffers` accumulated ~750 MB of per-call device allocations per
page, degrading later pages (9.5 s → 24 s per page).

## Changes

- `scripts/evie_hip_bench.py`: grid is now (1, H//16, W//16).
- `hipengine/runtime/evie.py`: `_release_call_buffers()` frees per-call
  misc allocations at the end of `encode_document`/`encode_query`;
  rope-cache tables and the conv state survive; `close()` frees the rest
  once (no double free).

## Validation

- `tests/test_evie_gpu_runtime.py`: 3/3 (caught the rope-cache dangling-
  pointer regression — cached cos/sin tables must be protected from the
  release).
- Corrected benchmark, same host, best of 3: doc 13758 ms / 8 pages
  (1.72 s/page), query 1865 ms / 8, maxsim 0.7 ms, total 15.62 s —
  11.4× better than the recorded first-path 177.8 s. Torch baselines on
  the same host/workload: fp32 4.148 s, bf16 1.356 s.
- The recorded first-path row in `benchmarks/` and MODEL-EVIE.md is
  superseded by this corrected number.
