# Stopped a redundant GPU run: the varlen configuration is production

## Summary

Iteration 25 replaced P1's unexecutable clearing command with a varlen
four-mask re-run and called it "runnable in-tree". Before running it, this
iteration checked what production already launches — and the proposed test
turns out to be **the exact configuration the shipped path already uses**,
whose behaviour the existing parity test already pins. Running it would have
spent a GPU pass on an answer we already have.

## The three lines that settle it

`hipengine/kernels/hip_gfx1100/attention/aotriton_wrap.cc:457-461`:

```cpp
params.causal_type = is_causal != 0
    ? AOTRITON_NS::v3::flash::CausalType::WindowedAttention
    : AOTRITON_NS::v3::flash::CausalType::None;
params.varlen_type = AOTRITON_NS::v3::flash::VarlenType::CompactVarlen;
params.window_left  = AOTRITON_NS::v3::flash::WindowValue::BottomRightAligned;
params.window_right = AOTRITON_NS::v3::flash::WindowValue::BottomRightAligned;
```

That is `WindowedAttention` + `CompactVarlen` + both `BottomRightAligned`
sentinels — byte for byte the configuration iteration 25 proposed to test.
And `gemma4_attention_prefill_aotriton` (line 669) calls
`aotriton_attn_fwd_v3_compact_varlen`, so this is not a side path: it is
what `tests/test_gpu_gemma4_attention_aotriton_parity.py` exercises on every
run, and that test asserts flash ≡ exact causal and passes.

So varlen-plus-both-sentinels **means plain causal**, proven in-tree. The
proposed test's three outcomes collapsed to one known result.

## What is actually untested

A matrix, and exactly one cell is empty:

| | non-varlen | `CompactVarlen` |
| --- | --- | --- |
| both sentinels | causal (sweep) | **causal — parity test, production** |
| integer bounds (`W-1, 0`) | **top-left — P1's sweep** | **← the untested cell** |
| mixed (integer + sentinel) | `window_left` ignored (sweep) | not tried |

P1's sweep covered integer bounds only in the **non-varlen** launch, where
they came back top-left. The varlen side was only ever run with sentinels,
which carry no bound and therefore produce causal. The intersection — an
integer bound under `CompactVarlen`, where `flash.h` says the alignment
markers actually apply — has never run.

**And it cannot be reached from Python today.** `window_left` and
`window_right` appear in **zero** `.py` files in `hipengine/`, and the shim
takes no such parameters — lines 460-461 are assignments, not arguments.

## The gate, revised a second time

**Parameterize `hipengine_aotriton_attn_fwd_v3_compact_varlen` with
`window_left` / `window_right`, thread them through the Python `argtypes`,
then run the four-mask comparison at `rows=512 keys=1536 window=128` with
`window_left = W-1, window_right = 0` under varlen.**

That is a C++ change plus a rebuild, which is exactly why it is a gate to
run deliberately rather than a probe to fire off — and why the previous
wording ("to be run in-tree before any rebuild is considered") was wrong on
its own terms: the test it described needed no rebuild but was already
answered, and the test that is not answered needs one.

Conclusion scope is unchanged from iteration 25: a bottom-right match earns
restoring the plumbing *after* observing the flip; a top-left match closes P1
and leaves P2's option (a) as this gap's only route. Neither is assumed.

## Why the check was worth doing

Iteration 25's checks all passed — the claim was sourced from the shipped
header, corroborated by two artifacts, labelled a hypothesis. It was still
wrong, because none of them asked *whether production already does this*.
A hypothesis can be honestly sourced and still be pre-falsified by code we
wrote ourselves. Reading the parity test and the shim cost one command;
the GPU pass it saved would have been minutes plus a misleading
"confirmed causal" line in the record.
