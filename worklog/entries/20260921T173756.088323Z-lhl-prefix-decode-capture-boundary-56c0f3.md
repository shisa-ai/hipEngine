# Decode-time prefix capture keeps the reachable prompt boundary

## Summary

A cold-then-cached request pair against a live server reused nothing at all
once the prompt was long enough, on the non-speculative route: `cached_tokens=0`
with TTFT 8.19 s against 8.87 s cold at 2048 prompt tokens, and 32.41 s against
32.27 s cold at 8192. The same pair reused the whole prompt at 512 and 1024, and
reused 1792 / 7680 tokens at 2048 / 8192 on the MTP route.

The mechanism is a capture-policy conflict inside one request, not a trie or
pool defect. The decode path calls `_refresh_prefix_cache(row)` after every
token (`hipengine/generation/qwen35_gguf.py`, the per-step call at the end of
the native decode step). Any reply long enough to cross the next 256-token
boundary therefore captures a boundary *past* that request's own prompt end, and
`_capture_prefix_snapshot`'s `superseded_by_row` loop evicted the
prompt-aligned capture it found, keeping one snapshot per request. The survivor
sat deeper than any token count a following turn can match: a client resending
the transcript starts with the previous prompt verbatim, so the deepest boundary
it can reach is the prompt-aligned one. That turn then matched no live prefix at
all, declined the node and re-prefilled the entire prompt — the 0-token reuse
above.

The speculative route was unaffected only because its decode bookkeeping left
`_processed_tokens` unaligned across those steps, so it never captured the
deeper boundary and the prompt-aligned capture survived.

Both boundaries are now captured and both are retained, with an explicit
priority between them: the prompt-aligned boundary outranks a decode-time one,
because a resend reaches only the former while a verbatim continuation reaches
the latter. Under retained-budget pressure the decode-time entry is what gets
trimmed, so a saturated budget degrades to the pre-fix reuse depth rather than
to the miss.

## Changes

- `hipengine/generation/qwen35_gguf.py`
  - `_GGUFPrefixSnapshotEntry.prompt_boundary` records whether an entry is the
    deepest 256-aligned boundary at or before its request's prompt end
    (`len(tokens) == self._prefix_prompt_boundary(row)`, computed in
    `_capture_prefix_snapshot`).
  - `_capture_prefix_snapshot` no longer lets a capture supersede the same row's
    prompt-aligned entry; it still supersedes the row's older decode-time entry,
    so a long reply keeps one decode-time snapshot rather than one per crossed
    boundary.
  - `_trim_prefix_snapshots` excludes prompt-aligned entries from the transient
    trim, so a concurrent long-decode row cannot lose the boundary it is still
    holding, and keeps the retained trim (count and bytes) authoritative for it.
  - `_promote_prefix_snapshots` re-inserts retained prompt-aligned entries last,
    so the retained trim's oldest-first order drops decode-time entries first.
- `tests/test_unit_gguf_prefix_cache_runner.py`
  - `test_decode_time_capture_keeps_the_reachable_prompt_boundary` (new): a
    700-token prompt whose prefill captures 512, then 68 decode steps across the
    next boundary. Asserts both captures exist, that the resend matches 512, and
    that a cumulative continuation still matches 768.
  - `test_retained_budget_drops_the_decode_time_boundary_before_the_prompt_one`
    (new): same shape at a one-entry budget; the prompt-aligned boundary is the
    survivor and the resend still hits.
  - `test_reuse_chain_deepens_across_three_turns` now sizes its budget for both
    boundaries of a turn (capacity 3). Its property is unchanged — the third
    turn still matches deeper than the first hand-off — but at a one-entry
    budget the prompt-aligned boundary is deliberately the survivor, which is
    what the new budget test pins.

  step capturing past the prompt and taking the boundary with it — and passes
  with the fix, with both entries retained and both reuse depths asserted.

## Next

- The retained budget is still `max(1, capacity)` entries while a long-decode
  request can now hold two (the prompt-aligned boundary plus one decode-time
  boundary). Under a saturated budget that costs conversation capacity for
  decode-time depth. Left as-is deliberately: the decode-time entry is trimmed
  first, so the effective floor is the pre-fix behavior.
