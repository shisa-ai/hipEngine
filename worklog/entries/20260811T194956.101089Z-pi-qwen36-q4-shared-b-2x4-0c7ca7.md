# Reject Q4 shared-B 32-column tile

## Summary

Rejected reducing the exact Q4 shared-B dense prefill tile from 48x64 per wave
(3x4 WMMA fragments) to 32x64 (2x4). Lower accumulator pressure did not recover
occupancy value: the extra output blocks and weight-stage duplication made all
three actual Qwen3.6 shapes slower. Production remains 3x4/four-wave shared-B.

## Changes

- Temporarily changed both the shared-B kernel tile and host launch grid from
  48 to 32 output columns. Rebuilt on GPU1, checked BF16 output, ran the existing
  21-pair counterbalanced actual-weight screen, then restored the source exactly.
- No production code or artifact was retained.

## Validation

- BF16 mismatches vs the exact single-wave T16 owner: zero for FFN gate, FFN
  down, and attention gate at M512.
- Counterbalanced geometric speed ratios vs the single-wave owner: FFN gate
  0.7963x, FFN down 0.7768x, attention gate 0.9533x; 0/21 pair wins for each.
  The retained 48-column shared owner had 1.2159x/1.0002x/1.2346x on the same
  roles, so the 32-column variant is decisively dominated.
- `git status` returned clean after restoring both constants.

## Next

- Do not revisit smaller output tiles for this shared-B FP16-WMMA design without
  a different weight staging/dataflow hypothesis. The next Q4 rung must improve
  operand production or use sole raw-GGUF integer MMQ rather than merely reducing
  accumulator count.
