# Logprobs and top_logprobs through speculative MTP

## Summary

Task 7. A request that asks for logprobs is served by the speculative MTP route,
and the metadata it reports for each published token is the value the
autoregressive route reports for the same request -- token for token, in the
blocking and the streaming response, on the greedy and the sampled branch.

The two fields were already declared servable: `logprobs` and `top_logprobs` sit
in `SAMPLED_MTP_SERVABLE_BLOCKERS` (`hipengine/generation/sampling.py`), which
is the set of request fields the sampled route serves, because a cycle can
reproduce the request's own sampling law. What was missing was the metadata
itself. A speculative cycle publishes several tokens at once from verified rows,
and the server's direct autoregressive call for a logprobs request never sees
those rows, so the field was declared servable while nothing produced it.

## Changes

- **Metadata for the published tokens** (`qwen35_gguf_mtp2.py`). A committed
  cycle now scores every token it publishes against the verified row that
  predicted it. `_sampled_accept_summary` returns the native sampler's own
  per-row report when that sampler selected the rows -- the same value the
  autoregressive route reports for the same request, so a host rebuild cannot
  drift in the last digits -- and `_cycle_token_logprobs` applies
  `reported_logprob` (the branch rule `select_token` reports with) to the host
  sampler's logits rows otherwise. Tokens are scored after the finish rule
  selected its terminal prefix, so a cycle that stopped early reports metadata
  for what it published and none for the rest. A length mismatch is a hard
  error, not a partial report.

- **The row sample list carries it** (`qwen35_gguf_mtp2.py`,
  `qwen35_gguf.py`). `row.samples` is what the resident runner turns into
  `GenerationOutput.token_logprobs`, and it was previously left short of
  `slot.generated_ids` for speculative rows, which made the assembly drop the
  metadata for the whole request. A cycle appends one record per published
  token, so the blocking output reports them.

- **Streaming** (`qwen35_gguf.py`, `qwen35_gguf_mtp2.py`). The scheduler builds
  one telemetry-only chunk per token of a cycle and
  `decorate_speculative_stream_events` attached only text. The metadata is now
  attached from a per-request record the commit publishes
  (`publish_cycle_token_samples`), because the decoration happens after the
  commit and a cycle that finishes the request has already reclaimed its row by
  then -- the reason the blocking path works and the stream path did not. The
  record is consumed by token id, kept until the blocking reader is done
  (`take_outputs`), and dropped for an abandoned request (`discard`).

- **Route selection** (`hipengine/server/api.py`). A logprobs request that the
  plan admits to the speculative route goes through the generation batcher like
  any other request; the direct autoregressive call it used to take cannot see
  the verified rows. A request the plan does not admit keeps that call.

- **One decline** (`qwen35_gguf_mtp2.py`). `_device_sampled_accept_plan`
  declines a logprobs request: the captured graph accepts on the device and
  returns no logits row to the host. Such a request falls to the eager host
  accept, which is exact but slower; recorded in `docs/REFACTOR.md` with the
  condition that removes it.

## Validation

- `scripts/mtp_logprobs_gate.py` against the live INT8 server (port 18198,
  Qwen3.8-27B Q4_K_M, `int8_per_token_head`, the documented KV diagnostic
  override). Five checks, all at **zero delta**:

  | check | scope | worst logprob delta |
  | --- | --- | --- |
  | `greedy_metadata` | 48 tokens over 24 MTP cycles vs the AR arm | 0.000e+00 |
  | `sampled_metadata` | 48 of 48 shared positions at temperature 0.35 | 0.000e+00 |
  | `stream_metadata` | 48 streamed tokens vs the blocking arm | 0.000e+00 |
  | `chat_stream_metadata` | 4 chat-streamed tokens vs the chat blocking arm | 0.000e+00 |

  The gate refuses an arm that did not speculate, a mid-stream refusal, a
  streamed token that differs from the blocking one, and a chat stream too short
  to compare. Three full runs of the gate on this server produced the same
  counts and the same zero deltas.

  Artifact: `benchmarks/results/2026-09-23-gfx1151-qwen38-int8-mtp-logprobs.json`.

- Live route confirmation, not only the gate: `execution_path=gguf_specdec2_mtp2`
  with `used=true`, `draft_cycles=9`, `mtp_output_tokens=11` on the metadata
  request; a sampled chat stream at temperature 0.7 published 8 tokens, each
  with `logprobs` and three `top_logprobs`, with no error.

- Unit: 38 in `tests/test_unit_mtp_logprobs.py` (8 new, covering the stream
