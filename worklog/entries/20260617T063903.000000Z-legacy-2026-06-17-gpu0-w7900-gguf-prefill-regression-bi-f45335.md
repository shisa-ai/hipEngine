- Results: before the G-P4 memory fix (`ee28d6f8`) measured `2286.082` / `2532.888` prefill tok/s with IDs `220/570`, peak `24.864596 GiB`; `4c0a2521` measured `2181.710` / `2479.558`, IDs still `220/570`, peak `23.828427 GiB`; `8bbda8c9` stayed similar at `2186.301` / `2479.133`, IDs `220/570`; `e089d1c2` changed IDs to `1813/151531` and measured `2143.889` / `2250.151` prefill tok/s.
- Interpretation: the user's memory-fix hunch is partly right but not the main cause. `4c0a2521` bought ~`1.04 GiB` for a modest prefill cost (`-4.6%` at 512, `-2.1%` at 4K) and preserved IDs. The large 4K prefill regression plus the ID change starts at `e089d1c2` (`perf: GGUF MoE fused activate+down and drop Q8_0 T16 repack`). A temporary e089 patch restoring Q8_0 T16 materialization recovered prefill to `2218.379` / `2485.416` tok/s while IDs stayed changed, so Q8_0 raw-layout dispatch is the main prefill culprit and another e089 runtime/kernel change is the correctness culprit.
- Saved artifact: `benchmarks/results/2026-06-17-gpu0-w7900-gguf-q4ks-prefill-regression-bisect.json`. Next fix should split/revert e089's Q8_0 raw-layout drop and audit the fused selected-expert runtime path separately; do not use the current W7900 row for README scorecard updates.
