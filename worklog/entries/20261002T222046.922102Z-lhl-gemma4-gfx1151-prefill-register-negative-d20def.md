# gemma4 gfx1151: the prefill kernel's register pressure is irreducible from the outside, and the occupancy lever is a dead end

## Summary

The previous entry found the prefill attention kernel register-starved at the
256-VGPR ceiling and measured that halving the accumulator through
`dim_groups = 4` costs more than it buys (1.33x slower). This entry closes the
other two outside-in levers, and both are negative.

**`__launch_bounds__(kThreads, N)` -- the occupancy target the compiler budgets
registers against -- does not help.** Same probe, 65,536 keys, 256 tokens, five
runs per point:

| `minBlocksPerMultiprocessor` | ms |
| --- | --- |
| **1 (shipped)** | **73.70** |
| 2 | 72.17 |
| 3 | 72.36 |
| 4 | 72.82 |
| 6 | 73.39 |
| 8 | **179.55** |

The best arm is 2.1% better than the shipped one, which is inside this probe's
run-to-run spread (the shipped configuration measured 75.31 and 73.70 in
different sessions). At 8 the compiler spills catastrophically and the kernel
becomes 2.4x slower. Reverted; the tree carries `__launch_bounds__(kThreads, 1)`.

An earlier three-run reading of 70.52 ms at `N = 3` looked like a 1.07x win. The
five-run sweep shows it was noise, and it is recorded here so the 70.52 is not
mistaken for a real result later.

## What this establishes

The kernel genuinely needs its 256 VGPRs. Neither the accumulator split
(`dim_groups`) nor the compiler's occupancy target (`launch_bounds`) can be moved
from the outside without making it worse. Combined with the previous entry:

- `dim_groups = 4` -> 99.90 ms (1.33x slower, duplicated score dot)
- `launch_bounds` 2-6 -> 72.2-73.4 ms (noise)
- `launch_bounds` 8 -> 179.55 ms (2.4x slower, spills)

**Every outside-in lever is measured and none of them works.** The fix has to be
structural: change what a wave owns so the accumulator is smaller *without* a
second wave needing the same score, or move the score through LDS so the dot is
issued once.

## Changes

- None. Applied, measured, reverted; the tree is unchanged.

## Validation

- Five runs per arm, median reported, identical buffers and arguments, one full
  layer, all-ones mask.
- The revert is verified by re-reading the source: `__launch_bounds__(kThreads, 1)`
  and `#define GEMMA4_WMMA_FULL_DIM_GROUPS 2`.
- The spread between the two `N = 1` readings across sessions (75.31 and 73.70) is
  2.1%, which is the same size as the best arm's apparent win and is why the win
  is called noise rather than kept.

## Next

- **The structural options, neither designed.** (a) Move the 16x16 score tile
  through LDS so the two dimension-group waves that share a column group do not
  each issue the score dot, which would let `dim_groups = 4` pay for itself. (b)
  Change the accumulator's shape so a wave owns fewer output dimensions without a
  partner needing the same score.
- Both are kernel redesigns with a correctness gate attached, not tuning. The
  kernel is 45.7% of a long-context prefill, so the prize is real and roughly 2x
  on the prefill at 65,536 keys if the register problem is solved.
