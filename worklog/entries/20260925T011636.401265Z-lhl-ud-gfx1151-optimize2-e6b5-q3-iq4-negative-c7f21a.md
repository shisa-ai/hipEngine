# UD gfx1151 optimize2 E6b-5: (Q3_K gate, IQ4_XS up) pair — bit-exact but 0.92–0.99× in five screens; NEGATIVE, route not shipped, kernel retained dormant

## Summary

Iteration 16 built E6 step 2e to the same bar as 2a–2d and **failed
the ≥1.00 screen gate in every run** (0.92, 0.95, 0.97, 0.99 ×50
allocate-once, plus one 0.98 in a waves-sweep run) while staying
**bit-exact every time** at K=5120 (unit) and at (5120, 17408)
rows=1 (production scale). Per the unit's own gate and the E6a
precedent: **negative adjudication, nothing enabled.**

**The lever:** the (Q3_K, IQ4_XS) family — 3 layers (blk.13/15/16,
ordered (11, 23)), the largest of the 9 remaining mixed layers —
needed a fourth side-B chain kind: the bool `UP_IS_Q5` became the int
axis `B_KIND` (0 = Q4 dense chain, 1 = Q5 tile8 emulation, 2 = Q3).
`B_KIND=2` emulates the strict per-row Q3_K GEMV's exact 128-thread
tile (`gguf_iq_dense_strict_kernel<3, true, 8, 1>`) across the pair's
64-thread waves: each hardware wave serially owns strict-waves
`sw = wave, wave+WAVES, …` lane-aligned (lane l holds strict-tid
sw*32+l), reproducing the phase-A `half_load(b+108) * float(scale-32)`
hoist, k-ascending per-thread accumulation (`acc += xv * wv`), the
wave32 shuffle tree, and thread 0's serial wave-0..3 total bit-exactly.
Geometry is E6b-2's mirror: the Python wrapper reorders the route's
(gate, up) arguments so IQ4 keeps side A's slot, and `GATE_IS_Q4=true`
takes the gate from side B's Q3 chain.

**Why it loses:** the two singles already run near-efficiently
back-to-back (~772 µs/layer total), so a fused launch can only claw
back inter-kernel gaps (≤~1%), while the emulation's five phase-A/B
sync rounds and the 32-float `acc3` register footprint (four
strict-waves in flight) cost more than that. A waves=4 sweep (1:1
strict-wave mapping, acc3 collapses to one wave's 8 floats) measured
**0.84× — clearly worse** (side A's split-K and sync behavior
deteriorate); waves=2 stays the wrapper's choice.
