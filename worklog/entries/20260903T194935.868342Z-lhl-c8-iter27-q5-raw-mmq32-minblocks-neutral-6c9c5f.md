# C8 iter27: raw MMQ32 minblocks probe neutral; MLP-limited confirmed

## Summary

Tested the occupancy lever on the raw Q5 MMQ32 owner (which retains the R24
accepted-tail rounds): a templated min-blocks-per-processor launch bound
(4 versus the registered 2) on all 48 ssm_out weights at rows=24. Result is
neutral — 0.9986x aggregate, 25/48 weight wins, bf16 bit-exact — and the
geometry explains why: the grid is 160 blocks and the mb2 resident capacity
is already 192 blocks (2 x 96 CUs), so every block is concurrently resident.
The raw owner is per-block MLP-limited, not occupancy-limited.

## Findings

- Raw owner structure: 160 workgroups x 128 threads, 192 barrier-gated K32
  iterations per block, ~2.9 KB global fetch per iteration with one fetch
  in flight, ~3.4 KB LDS (double-buffering is feasible), ~100-255 GB/s
  effective depending on L2 hit share.
- mb4 leaf: mb2 9.988 ms vs mb4 9.973 ms (ratio 0.9986), 25/48 wins, all
  48 weights bit-exact. The registered default is untouched
  (launch_mmq instantiates minblocks=2).
- Mechanism conclusion: with all blocks resident, per-block MLP (one fetch
  in flight across the serial K32 chain) is the limiter. The next Q5 lever
  is software pipelining: prefetch iteration k+1's tile into registers
  before computing iteration k, one barrier per iteration instead of two
  latency-gated syncs. This would be a kernel-body change and needs the
  full ladder (leaf, strict teacher parity, L2, L3 position-balanced gate).
