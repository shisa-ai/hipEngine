# R0141 GDN w32 diagnostic retained; stale RED-first test prose corrected

## Summary

R0141 asked whether the explicit 32-warp GDN prefill geometry stays as an occupancy comparison or is
retired. **Decision: retain it as a registered, non-default diagnostic.** The inspection found no
defect that would justify retirement: the variant is implemented, resolves to its own function, is
selected by nothing automatically, and its measured-loss artifact names the symbol, so deleting the
code would orphan that record's referent. The only actual defect was the dedicated test's RED-first
prose, which still described the pre-implementation state ("the candidate function does not exist
yet, so both tests below fail"). That prose is corrected to the current parity contract, which is
what R0141's retention branch required.

## Changes

- `tests/test_gpu_qwen4_exp_gdn_w32_prefill.py` — prose only, no test logic:
  - module docstring states the retained-diagnostic status, cites the lever-result artifact, and
    records that the profile layer selects the rowsplit/tiled16/columnwarps/strict owners, never
    this key;
  - the T0 binding oracle is stated correctly as the production columnwarps owner
    (`qwen4_exp_gdn_prefill_columnwarps_f32`, `<4, 4>`), with the serial strict owner held to the
    fixture tolerance envelope — the module docstring previously named the serial strict owner as
    the binding oracle while the test body compared bit-exactly against columnwarps;
  - both test docstrings drop the RED-first paragraphs and state what the test now enforces
    (exact-key resolution; bit-exact parity plus tolerance envelope).
- `docs/REFACTOR.md` — removed the R0141 entry; its decision is complete.

No kernel, wrapper, registry, HIP or profile file was touched. The strict owner
(`qwen4exp_sigmoid_strict_prefill`), `qwen4exp_gdn_columnwarps_prefill` and
`qwen4exp_gdn_tiled16_prefill` remain registered exactly as before.
