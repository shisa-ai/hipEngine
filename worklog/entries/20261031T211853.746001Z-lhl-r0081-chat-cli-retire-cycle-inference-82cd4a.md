# Retire chat /bench cycle-count speculation inference

## Summary

Final chat consumer step of R0081. `/bench`'s "mtp on" note decided whether
speculation ran from `diagnostics.specdec2_mtp2.cycles` whenever neither
committed-output counter was present. A depth-zero cycle increments `cycles`
and attributes no speculative token (`speculative/accounting.py:record_speculative_outputs`),
so a positive legacy count claimed speculation that may never have happened,
and a zero count claimed a decline from a count that means something else.

The three MTP providers now publish `diagnostics.specdec2_mtp2.mtp_output_tokens`
and the public `output_accounting.mtp_output_tokens` on both blocking and
terminal SSE responses (Qwen4Exp `ed85593cf`, Gemma `4c1048c49`, mixed
`1075f391e`), and both routes reconcile, so the cycle fallback has no remaining
publisher to serve. `_mtp_speculated` now answers `None` — missing telemetry,
never a declined request — when neither attribution counter is present.

## Changes

- `hipengine/chat_cli.py`
  - `_mtp_speculated`: public `output_accounting.mtp_output_tokens` first, then
    the provider block's own counter, and nothing else. Explicit zero still
    decides `False`; a positive counter decides `True`; a conflicting pair
    still resolves to the public block.
  - `_mtp_cycles` removed. Its only caller was the retired fallback, so it
    became dead code; the file displays no cycle count, and the bench table's
    `mtp` on/off column and the note text are unchanged.
- `tests/test_unit_chat_cli.py`
  - `test_turn_treats_unreported_speculation_as_missing_evidence`: a
    counter-less provider block now answers `None` for both a zero and a
    positive cycle count, instead of `False`/`True` from cycles.
  - New `test_turn_does_not_claim_speculation_from_a_cycle_count`: legacy
    provider block and legacy summary with positive cycles answer `None`, and
    the same counts decide once either attribution counter arrives.
  - New `test_bench_does_not_infer_a_decline_from_a_cycle_count`: a route whose
    responses carry cycles only (`0` and `3`) prints no "no speculative token
    was committed" note.
  - `_BenchStreamServer` gained `mtp_attribution` (default `True`), which omits
    `mtp_output_tokens` from the provider block and `output_accounting` from the
    done chunk's summary, modeling a pre-counter provider.
- New immutable worklog entry (this file).
