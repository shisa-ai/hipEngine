# Router select+cast fusion built and measured wall-neutral

## Summary

The first fusion candidate from the dispatch-gap ladder - merging the MoE
router's block-parallel top-k/softmax select with the f32->bf16 activation
cast into one kernel - is built, proven bit-identical, and measured
wall-neutral, so it is not promoted. The fused kernel reuses
qwen35_router_select_from_logits verbatim and the same RNE bf16 conversion the
cast kernel uses; the RED/GREEN gate passes 4/4 shape combinations (including
tie-heavy logits, denormals and bf16-boundary values, cross-checked against a
CPU RNE reference), and the same-residency engine A/B confirms cross-mode
outputs EXACT on 12/12 canonical cases. Performance: prefill 342.681 ->
342.835 tok/s (1.0004x), decode 16.569 -> 16.540 (0.9982x), client wall
475.332 -> 475.735 s (1.0008x) - all inside the instrument's noise floor.

The finding: removing 96 of ~1,800 per-step launches (the router chain's two
per MoE layer, each an intra-graph node dispatch in the replayed MoE graph)
does not move the decode wall. The small-gap floor is diffuse; small-fusion
wins are below the same-residency instrument's resolution. The fusion line's
remaining targets are the bigger QSA/attention seams or a solved whole-step
graph (the GDN mixer in-place hazard).

## Validation

- RED/GREEN: 4/4 shapes bit-identical (selection indices, routing weights,
  cast bits), CPU RNE cross-check included.
- Engine A/B: 12/12 cross-mode exact, within-mode deterministic, wall-neutral
  (1.0008x), clean teardown. Not promoted per the acceptance policy; the
  default stays the unfused pair.
