# The IQ4_XS T16 layout does not pay even with the header cost equalized

## Summary

`ud-iq4xs-t16-rejected` closed the IQ4_XS T16 repack as a loss, but its
measurement had a confound: the scratch T16 owner paid **three header loads per
column** (separate `d`, `scales_h` and `scales_l` plane addresses) where the
raw local32 owner pays two, because the raw block stores `d` and `scales_h`
adjacent at bytes `[0:4]`. That is a plausible alternative explanation for the
loss, so this unit removed it.

It is removed and the answer does not change. **The T16 layout is still a loss
for IQ4_XS with the header cost equalized and bit-exactness confirmed.**

## Changes

None retained. The scratch owner was added to a scratch copy of
`hipengine/kernels/hip_gfx1100/quant/gguf_iq_dense.hip` and the file was
restored byte for byte afterwards; `git status -sb` is clean.

## Validation

A scratch owner in the local32 accumulation order whose per-column header is
one `u32` holding `d` and `scales_h` (bytes `[ci*4, ci*4+4)`) plus one `u32`
of `scales_l` at `64 + ci*4` — exactly two header loads per column, matching
the raw owner. The paired header was built in the harness straight from the raw
blocks, where `d` and `scales_h` are already adjacent, so the construction does
not depend on the T16 packer's own header planes. The payload plane is the
committed T16 `qs` plane and is unchanged, so the arithmetic is identical to
the raw owner and the comparison is exact.

`/tmp/phase8/t16pbench.py`, six real IQ4_XS tensors at rows 1 and 3, best of
4 x 30 launches after 3 warmups, both arms at `waves = _local32_waves(K, N)`,
outputs compared bit for bit:

twelve cases (0.52x to 1.15x), reproducing the earlier finding.

### A harness bug worth recording

The first form of this measurement built the paired header with
`np.concatenate` over reshaped views of the packed tile and reported
`exact=False` on all twelve cases. A direct comparison of the committed
tile's planes against the raw bytes showed the `d` and `scales_h` planes are
correct where the packer puts them, so the committed layout and packer were
never in question — the construction was. Rebuilding the header from the raw
blocks fixed it. The lesson is that the independent check has to read the raw
bytes, not another reshape of the artifact under test.


## Next

The IQ4_XS T16 repack is now closed twice, once with the confound and once
without it. Do not re-open it. The measured constraints on
`gguf_iq4_xs_local32_gemv` (31.5% of UD verifier kernel time) are: `COLS` 8,
the `WAVES` heuristic, the `ROWS > 1` launch-bounds floor, a 29% fall from
rows 1 to rows 4 at a fixed byte count, a payload-load count that can be
halved with no benefit, and now a header cost that makes no difference either.
That leaves the decode itself and the memory access pattern, which need a
hardware-counter unit this host cannot provide.
