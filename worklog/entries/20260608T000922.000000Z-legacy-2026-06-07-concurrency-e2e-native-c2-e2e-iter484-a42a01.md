## Changes

- Loop stays paused. Performance investigation of poor native c>1 decode scaling on `HIP_VISIBLE_DEVICES=1` / RX 7900 XTX. Measured medians (BF16-KV PARO, 512/128, batched_lm_head, native_batch no-rowchunk): c1 133.4, c2 102.4 (0.77x c1 — worse than c1), c4 138.4 (1.04x), c8 192.1 tok/s (1.44x); per-request decode 133/51/35/24.
- `rocprofv3 --kernel-trace` differential (decode-tokens 8 vs 40, warmup 8; per-step = (d40-d8)/32). Reliable findings:
  - Dispatch count per decode step: c1 917, c4 5370, c8 9362 (c8 = 10.2x c1, worse than the 8x row count). Decode fires thousands of tiny kernels per step; dispatch count is the dominant wall.
  - c1 graph replay clean delta (authoritative, non-profiled): 134.23 tok/s with graph replay (paro_bench default) vs 110.36 eager = **+21.6%** at 512 context. Larger than the doc's +2.6-3.9% at 4K because short-context kernels are smaller vs per-dispatch overhead.
  - c>1 graph replay is NOT wired (`graph_bucket_stats.replay_kernel_hits=0`): the native batch decode step is not device-resident (per-step host token list, host positions, per-layer host->device block-table copy in `_batch_full_spans`), so it cannot be captured/replayed as-is.
- Profiler caveat: rocprofv3 perturbs/serializes short kernels, so profiled kernel-time sums are inflated (c4/c8 profiled ns/step exceed clean wall/step). Not a clean utilization measure. c1 profiled busy ~2.74 ms vs 7.5 ms wall => <=~37% GPU util even WITH graph replay (upper bound). Reliable signals are dispatch counts and the clean graph-replay delta.
- Conclusion: the core issue is dispatch count, not only missing graph replay. Graph replay (already on at c1) removes per-dispatch HOST latency / per-step host overhead (~+20% at c1, likely more at c>1 where 9362 dispatches/step overwhelm eager host issue) but cannot remove per-dispatch DEVICE (MEC/SPI) overhead; the structural fix is fewer/larger kernels. Levers: (1) wire c-aware decode graph replay (device-resident batch step) — bounded; (2) reduce dispatch count via fusion; (3) BIG LIFT, separate workstream: output-column-tiled c>1 GEMM (load each weight tile once, reuse across all c columns + per-expert token batching) — the only lever toward the c>1 roofline, tracked in docs/CONCURRENCY.md "Decode performance levers".
- Correctness-only; no throughput/scaling claim is retained. Artifact: `benchmarks/results/2026-06-07-hipengine-qwen35-decode-dispatch-profile-484/summary.json` (raw traces kept in `/tmp/prof`, d40 sha256 recorded). docs/CONCURRENCY.md updated with the measured decode-performance levers and the output-tiled-GEMM big-lift note.
