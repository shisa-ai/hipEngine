# A single-width K3 run can report every cell mtp_engaged=False

## Summary

Two measurement-integrity facts from diagnostic runs this turn.

1. A **single-width** K3 invocation can produce a packet whose every cell reports
   `mtp_engaged: false`, i.e. an
   "MTP" column that is literally the AR arm run twice, while still reporting
   `correctness.passed: true` and
   `budget_conformed: true`. Only the `engaged` field reveals it.
2. The published AR C8 row **reproduces across three independent protocols**, so the
   earlier suspicion of a
   same-process sweep artifact is closed.

## Changes

- No code change; this protects how future K3 rows may be read.

## Observed

- `.venv/bin/python /tmp/he-mtp/prof_run.py` (cProfile driver, width 8 only, `--expected-
  mtp-widths 8`,
  `--candidate-budget 3`, `--mtp-request-mode explicit`, `--generation2-diagnostic`,
  `--max-tokens 16`):
  all 10 cells `engaged: False`, mean AR 69.9 vs mean "MTP" 70.4 tok/s, `ar_mtp_equal`
  true, and every cell
  `budget_conformed` true. Cause of non-engagement at a single width was not investigated.
- Retained rows are unaffected: `he-staged.json` has `mtp_engaged` true for all 40 cells,
  and `he-k3-r1/r2.json`
  (widths 1-8) give C1 AR 22.07 against the published 21.999, so the protocol matches the rollup.
- AR C8 reproduced three ways: AR-only control in a fresh process **78.60**, widths 5-8 in
  one process **79.47**,
  published rollup row **78.667**. Spread ~1.1%, within the same-protocol band.

## Consequences

- Any retained or proposed K3 row must state the count of cells with `mtp_engaged` true. A
  `correctness: pass`
  row is not evidence of speculation; `ar_mtp_equal` passing is exactly what a non-engaged
  run looks like.
- The objective's AR column (21.871 -> 44.338, plateauing from C4) is stale: the current
  rollup shows AR rising
  to 78.667 at C8 and leading 7 of 8 widths, losing only C2 (31.916 vs 35.440). Remaining
  deficits are AR C2,
  K3 C5-C8 (47.96-55.86 vs 59.64-94.74), and prefill C1-C3/C6.
- Do not infer sweep-induced degradation from a single-width comparison again; the three-
  way reproduction above
  is the check that closes it.

## Validation

- `mtp_engaged` / `correctness` read from the emitted per-cell JSON lines of the named
  runs; means computed over
  all 10 prompts each. The cProfile rates themselves are not used as rate evidence - only
  the engagement flags
  and the fact that the two arms matched.

## Next

- If single-width K3 profiling is needed again, assert engagement in the driver and stop
  if it is false, or
  profile widths 5-8 as one process (which does engage).
- Prefer the existing AR-only control for isolated AR numbers rather than reading an
  unengaged MTP column.
