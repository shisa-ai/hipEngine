# Surya A4 ground truth was line-level for a wrapped-prose page: a correct transcription scored as CER 0.89

## Summary

The first measurement of the new 300-DPI A4 page read as a bad model failure —
`line_recall` 0.2414, `line_exact_rate` 0.2414, `cer` 0.8901, one reading-order
violation — while the ruled table scored 32/32 cells. That combination was the
clue: the model was fine and the **ground truth was the wrong granularity**.

Dumping the hypothesis settled it. The model returned 13 blocks whose text is
the page verbatim: each paragraph as one `<div data-label="Text">`, the headings
as `Section-Header`, the caption, and the ruled table with its header and all 32
cells. Scored paragraph-to-paragraph, all 12 text units match at normalized
similarity 1.0. The 22 "omitted" lines are the physical lines the renderer
wrapped 5 paragraphs onto: `_draw_text_fit` drew a 4-5 line paragraph as 4-5
separate lines, and the ground truth listed those lines as 4-5 separate units,
so a correct paragraph-level block could not pair with any of them (best
similarity 0.329, worst 0.206) and every character of those paragraphs counted
as an error.

This is the same defect class as the four bench pages that draw text past their
own canvas: the harness read correct output as error. It is the second instance
found in this suite, which is why the fix is not "loosen the threshold".

**Decision:** the A4 ground truth is paragraph-level, because its body is
wrapped prose. The seven smaller pages draw one logical unit per physical line,
so for them the two granularities coincide and their ground truth is unchanged.
The text is not retyped: `_a4_paragraphs()` joins the same
`_A4_ABSTRACT`/`_A4_SECTIONS` constants the page is drawn from, so the expected
text cannot drift from the drawn text, and
`tests/test_surya_transcription_fixtures.py` asserts that a wrapped line is
*not* its own unit.

**Correction to a committed entry.** Worklog entry
`20260912T102908.898036Z-lhl-surya-http-serving-49e812` recorded, in its
"Not validated" and "Next" sections, that the A4 page fails the transcription
acceptance thresholds and that the cause was probably vision resolution or the
tiled vision path. That interpretation is superseded: the model transcribed the
page exactly, and the failure was in the measurement. No part of the HTTP
serving unit is affected, since it was validated against a fake generator and
made no transcription claim.

## Changes

- `scripts/surya_bench_pages.py` — `_a4_paragraphs()`; the `a4` ground truth is
  the 12 paragraph units instead of the 29 drawn lines; `expected_lines`
  docstring now states which granularity applies and why.
- `scripts/surya_transcription_report.py` — `--dump <dir>` writes each page's
  raw hypothesis HTML and a per-line assignment verdict. Without it a scored
  failure is a count, and this defect would have been diagnosed by guessing.
- `scripts/surya_transcription_score.py` — `TranscriptionScore.matches` and
  `.candidates` retain the assignment detail, kept off `as_dict` so committed
  artifacts stay compact.
- `tests/test_surya_transcription.py` — `QUALITY_CASES` = the seven oracle
  pages plus `a4`; the ground-truth and reading-order gates run over it, the
  implementation-parity gates still run only where a torch fp32 reference
  exists.
- `tests/test_surya_transcription_fixtures.py` — pins that the A4 ground truth
  is paragraph-level and derived from the drawn constants.
- `docs/MODEL-SURYA.md` — the A4 section now records the corrected measurement
  and the defect, instead of the superseded failure diagnosis.
