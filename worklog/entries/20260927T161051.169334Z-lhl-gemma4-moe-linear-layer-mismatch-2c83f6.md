# The pack8 expert GEMV is registered under moe_linear, and gemma4 resolves under linear

## Summary

The four-iteration thread from the decode profile resolves, and the answer is a
**registry layer mismatch**, not a missing kernel.

**What exists.** `gguf_expert_pack8_gemv.py` registers
`gguf_q4_k_expert_pack8_selected_bf16_bf16_out` under

```python
KernelKey("hip_gfx1100", "moe_linear", "gguf_q4_k", "expert_pack8_selected_bf16_bf16_out")
```

at :145, with q5_k and q6_k alongside at :150 and :154.
`register_gguf_expert_pack8_gemv_kernels()` is invoked at module import (:263),
so the entry is live. `tests/test_gpu_gguf_expert_pack8_gemv.py` covers the
family, and `repack_gguf_q4_k_pack8` (`gguf_q4_k.py:1316`) produces the
`GGUFQ4KPack8` layout it needs.

**What is missing.** `gemma4_project_experts_selected` resolves with
`KernelKey(weight.backend, "linear", quant_key, _SELECTED_VARIANT)` - layer
**`linear`**, variant `selected_gemv` - and a repository-wide grep for
`expert_pack8` finds **nothing** under `hipengine/kernels/hip_gfx1100/gemma4/`.

So the expert pack8 route exists for this quant type and this backend, is
registered under the `moe_linear` layer, and the gemma4 MoE path never looks
there. The variant name differs too: `expert_pack8_selected_bf16_bf16_out`
against `selected_gemv`.

**The named clearing step:** have the MoE route resolve `moe_linear` /
`expert_pack8_selected` first and fall back to the current `linear` /
`selected_gemv` route. That fallback already exists in the dispatch, so a missing
kernel degrades rather than fails - which also means the change is safe to land
before it is measured.

This is the largest decode line at 28.0%, running at about 15% of bandwidth, so
the headroom behind a correct wiring is roughly 4-6x by the earlier arithmetic.

## Validation

- The registration is read from the `KernelKey` constructor calls, and the
  module-level invocation at :263 confirms it is live rather than merely defined.
- The mismatch is established by reading the resolution key in
  `gemma4_project_experts_selected` against the registered key, and corroborated
  by an empty repository-wide grep for `expert_pack8` under the gemma4 kernel
  directory.
- The layout producer and the test are both located, so this is not a kernel that
  would have to be written.
- **Not yet verified:** that the pack8 expert kernel is correct on gemma4's
  geometry (in_features 2816, out_features 1408, 128 experts) and that the weight
  carries the pack8 layout at load for this artifact. Both must be checked before
  the route is promoted, and the existing fallback means a failure is contained
  rather than fatal.
