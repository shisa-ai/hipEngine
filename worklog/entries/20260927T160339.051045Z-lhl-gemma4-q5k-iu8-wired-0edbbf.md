# The Q5_K iu8 gate/up route is wired but gated off on a launch failure

## Summary

Wired the Q5_K iu8-WMMA risk+repair gate/up route into gemma4, and gated it off
on an observed launch failure rather than leaving it half-landed.

**What is in place.** `Gemma4ExpertScratch` gains a risk counter, a worst-case
risk index queue, and a dedicated WMMA tile walk (`wmma_expert_start`,
`wmma_tile_expert`, `wmma_total`) - dedicated because WMMA packs 16 rows per tile
against the MMQ32 route's 32, so the `mmq_*` buffers are half the size it needs.
`gemma4_project_experts_gate_up_mmq` now dispatches on the quant key, sending
`gguf_q5_k` to the new `_gemma4_project_experts_gate_up_wmma_iu8`, which builds the
WMMA tile map, validates the padded row count against capacity, clears the risk
counter, launches the risk pass at a Kahan multiplier of 4.0, and then runs the
sparse exact repair. The Q4_K path is untouched and the caller is unchanged.

**What blocks it.** With the route enabled the first Q5_K layer raises HIP error 1
(`hipErrorInvalidValue`) out of `_launch_wmma_iu8_risk`. The kernel returns that
code from its own parameter guards before any work, and the obvious candidates all
check out: `in_features` 2816 is a multiple of 256, `out_features` 1408 is a
multiple of 128, the grid is `(22, row_tiles)` with `row_tiles` around 600, the
kernel's shared arrays total about 16 KiB, and the risk pointer and multiplier
arguments match the wrapper's ctypes order. So the mismatch is somewhere I have
not found, and I stopped rather than keep changing a changed-arithmetic path in
the dark.

**Why gated rather than reverted.** The route is fully wired, so the failure can
be worked from a green tree, and the flag carries its own cause and clearing
command as `docs/REFACTOR.md` requires. The default path is verified unchanged
with the flag off.

## Changes

- `hipengine/kernels/hip_gfx1100/gemma4/gemma4_experts.py`: the scratch buffers,
  the quant dispatch, `_gemma4_project_experts_gate_up_wmma_iu8`, the
  `_IU8_RISK_MULTIPLIER` constant, and `gemma4_moe_gate_up_q5k_iu8_enabled`.
- `docs/REFACTOR.md`: the flag's entry, its cause, and its clearing command.

## Validation

- Default path unchanged with the flag off:
  `scripts/gemma4_campaign_bench.py --prompt 512 --output 128 --samples 3` gives
  264-265 tok/s prefill against 266-268 before, decode 21.04, `path parity=True`.
- `tests/test_unit_gemma4_expert_route.py`: exit 0.
- Module imports clean and the flag defaults to False.
- **The enabled path is not validated.** It fails at launch, and no correctness
  claim is made for it.
