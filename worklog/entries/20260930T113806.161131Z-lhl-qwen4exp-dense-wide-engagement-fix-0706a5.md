# Closed the dense_wide engagement gap - the live 16-47 default is now visible to the false-pass detector

## Summary

`20260930T113116` found that the engagement detector added in `056e6fbd8` -
the mechanism that caught the WMMA false pass - could not see the `dense_wide`
route, which is the **live production default at 16-47**. This closes that gap.
Two independent defects were in the way, and both had to be fixed:

1. **No dispatch recorder for the route.** `_record_wmma_prefill_dispatch`
   records only `wmma_prefill`; `_record_selector` records the collateral
   selectors `use_wmma` moves. Nothing recorded `dense_wide`.
2. **The gate read the wrong key.** `_summarise_engagement` hardcoded
   `route = "wmma_prefill"` for the engaged flags, so even with a recorder a
   `--route dense_wide` run could never report its own route engaged.

Fixing only the first would have left the flags wrong; fixing only the second
would have had no data to read.

## Changes

- `hipengine/runtime/gguf_linear.py` - added `_record_route_engagement` and
  calls at all six decision points of `_q8_dense_wide_dispatch`. Recording in
  **both** arms is deliberate: a selector that only records when it fires lands
  in `selectors_observed_in_one_arm_only` and is reported *unobserved* rather
  than engaged. Declined paths record their reason, so a zero rate is
  diagnosable rather than mysterious.
- `scripts/execution_profile_q8_wmma_prefill_layers_gate.py` - added
  `ROUTE_ENGAGEMENT_SELECTORS` (route name -> engagement selector) and made
  `_summarise_engagement` take `route_selector`. **A route with no entry reports
  `route_engagement_recorded: false` with an explanatory note, rather than
  falling back to `wmma_prefill`** - a fallback would answer a different route's
  question and read as a pass.
- `tests/test_unit_qwen4exp_dense_wide_dispatch.py` - two tests pinning that the
  route records in both arms with the right reason, and that each decline names
  itself.
- `tests/test_unit_qwen4exp_wmma_engagement_recorder.py` - the eight existing
  `_summarise_engagement` calls now pass `route_selector="wmma_prefill"` (they
  are about that route), plus three tests: the flag follows the named route, an
  unrecorded route says so, and every mapped route has a row floor so the two
  registries cannot drift apart.
- `docs/REFACTOR.md` - the entry's removal condition is met; updated.

No arithmetic, dispatch decision or default changed. The added calls only
append to a recorder list that is empty unless a gate is measuring.

## Validation

**Unit:** 47 passed across the two engagement/dispatch test files. The full unit
suite was run after the change (see the commit).

**End-to-end, `--route dense_wide --layers 16-47`** (reduced screen, 2 cases,
24 decode steps, 3 repeats, chunk 1024):

| | before the fix | after |
| --- | --- | --- |
| `candidate_route_engaged` | `False` | **`True`** |
| `route` | `wmma_prefill` | **`dense_wide`** |
| `selectors_differing` | `[]` | **`['dense_wide']`** |
| `dense_wide` rates | absent | **t=0.0000 c=0.2640 differs=True** |

**No regression on the `wmma` route** (same protocol): `candidate_route_engaged:
True`, `wmma_prefill` t=0.0000 c=0.2640 differs=True, and `dense_wide` t=0.0000
c=0.0000 differs=False - correct, since the `wmma` gate clears `dense_wide` in
both arms.

Both runs report `gate exit=1` with `status: invalid_or_screen_only`, which is
the reduced protocol's designed outcome, not a failure of the change.

Artifacts: `dense-wide-16-47-engagement-probe-fixed.json`,
`wmma-16-47-engagement-probe-fixed.json`.

## What this does and does not establish

- **Does establish:** the `dense_wide` route's engagement is now observable, the
  gate reports it, and the `wmma` route's reporting is unchanged.
- **Does not establish:** that the canonical re-gate in `20260930T113116`
  measured `dense_wide`. That run predates this fix and still cannot say. The
  canonical re-gate should be repeated now that the route is visible - the
  candidate rate is **0.2640**, not 1.0, because the route claims only the
  16-47 window at eligible shapes, which is consistent with a real route but is
  not proof that the canonical run's drift came from it.
