# GGUF decode-graph default: already engine-on, break-even on gfx1151 dense 27B

## Summary

The requested change ("default to the `HIPENGINE_GGUF_DECODE_GRAPH` path if it is
faster than eager") was investigated and **no engine default was changed, because
the graph is already the engine default and it is not faster.**

Two separate defaults were conflated:

| Layer | Default | Evidence |
| --- | --- | --- |
| Engine (`LLM.generate` / server) | **graph on** | `_gguf_decode_graph_enabled()` reads `HIPENGINE_GGUF_DECODE_GRAPH` with default `"1"` (`hipengine/generation/qwen35_gguf.py:593`) |
| Sweep harness (`scripts/qwen35_readme_sweep.py`) | **eager for GGUF** | `--graph-replay-decode` defaulted to `args.engine == "paro"` |

The engine admits the graph only when the backend package publishes a break-even
and the remaining transitions cover it (`GGUF_DECODE_GRAPH_MIN_REPLAY_STEPS`: **128**
on gfx1151, **24** on gfx1100), so the graph is gated, not unconditional.

Measured on the physical gfx1151 host, the graph is **break-even to slightly
slower** than eager at every decode length (0.995-1.000x, 0.991-0.999x with
capture charged), token-exact throughout. The decode is memory-bandwidth-bound
(~196 GB/s of AR-active weight streaming, ~89% of the documented ~221 GB/s
practical read roof for this host), so removing launch overhead cannot help. This
independently reproduces the near-1% gfx1151 graph benefit already recorded in
`docs/ROOFLINE.md`.

The one real defect found was in the harness, not the engine: its eager default
was stale (left from commit `b4edca09f`, 2026-07-07, which retired the GGUF graph
path before it was reinstated as the engine default), so a bare harness
invocation measured a configuration production does not run. An unset flag now
resolves each workload through the engine's own admission rule.

Published rows are unaffected: every gfx1151 Qwen3.8-27B row already passed
`--graph-replay-decode` explicitly (`2026-08-16-...clean-publication.json`,
`2026-08-17-...q5-source-f16-prefill-retention.json`,
`2026-09-12-...q4km-ar-prefill-refresh.json`), so their numbers already matched
production.

## Changes

- `scripts/qwen35_gguf_bench.py`
  - `_backend_min_replay_steps(session)` — reads the resident session's admitted
    graph break-even.
  - `_default_decode_graph_request(session, decode_tokens)` — mirrors the
    engine's admission: `HIPENGINE_GGUF_DECODE_GRAPH` enabled AND a published
    floor AND `decode_tokens >= floor`.
  - `_decode_graph_disabled_reason(...)` gained an optional `decode_tokens`
    keyword and now reports `below_backend_min_replay_steps`, so artifacts record
    *why* the graph was declined instead of leaving the reason blank.
  - Imports the canonical `_gguf_decode_graph_enabled` from
    `hipengine.generation.qwen35_gguf` (torch-free module; other harnesses such as
    `scripts/specdec2_c1_gate.py` already import private helpers from it) so the
    harness cannot drift from the engine's env handling.
- `scripts/qwen35_readme_sweep.py`
  - `main()` leaves `--graph-replay-decode` unset for GGUF (PARO keeps its
    `True` default) instead of forcing eager.
  - `_run_gguf_sweep` resolves the request once per workload via
    `_resolve_gguf_graph_request`, and validates `--graph-steps-per-replay`
    divisibility after resolution (previously only checked for an explicitly
    requested graph, which the auto path would have bypassed).
  - Module docstring corrected: it claimed GGUF decode "is eager by default
    because the retired GGUF decode-graph path corrupted recurrent state on
    relaunch", which stopped being true once the path was reinstated.
- `tests/test_qwen35_gguf_bench_metadata.py`, `tests/test_gfx1151_readme_refresh.py`
  — RED/GREEN coverage for the resolver, the floor reason, and the absent-capability
  case.
- `benchmarks/results/2026-09-12-gfx1151-qwen38-27b-q4km-decode-graph-vs-eager.json`
  — compact A/B artifact; `benchmarks/CHANGELOG.md` dated one-liner.

- Per-arm standard deviation 0.0004-0.0021 tok/s, so the deficit is measured, not noise.
- Final token ID **9707** identical in both arms at all five shapes (token-exact).
- Capture cost median 9.2-9.7 ms per fresh graph.

Engine-admission parity, flag left unset, one process, gfx1151:

| Shape | `decode_tokens` vs floor 128 | Resolved request | Effective | Decode tok/s |
| --- | --- | --- | --- | ---: |
| 512/32 | below | `False` (eager) | eager | 12.226 / 12.229 |
| 512/128 | at | `True` (graph) | graph | 12.208 / 12.213 |
| 512/256 | above | `True` (graph) | graph | 12.198 / 12.197 |

The harness now reproduces the engine's per-shape decision; warmup repetitions
stay eager as before. Final token ID 9707 at every shape.
