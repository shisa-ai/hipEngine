# Add Qwen4Exp GGUF tokenizer ownership

## Summary

Added a distinct torch-free Qwen4Exp GGUF tokenizer owner while reusing the
proven Qwen35 byte-BPE reconstruction recipe. It preserves the artifact's
chat template and exact BOS/EOS/padding/image token identities for later public
reasoning/tool/vision admission.

## Changes

- Added/exported `Qwen4ExpGGUFTokenizer`; it requires architecture `qwen4exp`
  and tokenizer pair `gpt2/qwen35` rather than admitting unrelated GGUFs.
- Preserved chat template, disabled default BOS insertion, EOS stop ownership,
  and optional explicit BOS behavior.

## Validation

- RED: tokenizer tests failed collection because the Qwen4Exp class did not
  exist.
- GREEN: `uv run pytest -q tests/test_qwen4_exp_tokenizer.py` -> `2 passed`
  against the real frozen Unsloth metadata shard.
- Frozen IDs: `Hello, world!` -> `[9419,11,1814,0]`; Japanese `こんにちは` ->
  `[85951]`; `def fibonacci(n):` -> `[727,73111,1393,1590]`; all decode exactly.
- Qwen4Exp/Qwen35/Laguna compatibility bundle -> `13 passed, 5 skipped`.
