# Migrate server MTP accounting fixtures to request-local blocks

## Summary

`hipengine/server/api.py::_mtp_draft_counts` now reads only
`diagnostics.specdec2_mtp2`, so the server test doubles and summary tests that
still published or asserted legacy draft counts had to move to the
request-local block. The shared MTP fake now publishes a block that matches what
it actually emits, its legacy scalar `mtp_*` counters survive only as
distractors, and the tests that used to prove a fallback read now prove that no
count is inferred from provider aggregates or batch timing. The mixed-pass
public-telemetry fixture was rebuilt on a real `_MixedCommit` ledger because the
aggregate-only row shape it used cannot produce a block at all.

Scope: test fixtures and test expectations only. No production code changed, no
GPU run, no commit.

## Changes

- `tests/support/server_api_fakes.py`: `SpeculativeMTPFakeLLM` publishes
  `_speculative_mtp_execution_block()` -- one committed depth-3 cycle that
  delivered the single token it emits (3 proposals, 0 accepted drafts, 1
  speculative output token) -- in its stream chunk, its scheduler chunk
  telemetry, and its blocking output. The legacy `mtp_cycles_count` /
  `mtp_generated_draft_tokens` / `mtp_accepted_draft_tokens` scalars are kept on
  the blocking row unchanged (they claim 2 accepted drafts) so a fallback read
  is visible in any assertion that reads them.
- `tests/test_integration_server_mtp_accounting.py`:
  - `test_mtp_summary_reads_request_local_blocks_regardless_of_batch_timing`
    replaces the batch-timing-ownership test: two rows share one batch timing
    sample, only one owns it, and both report their own block (totals 4/6/2)
    while the legacy mirror claims 77/99/9.
  - `test_mtp_summary_infers_no_counts_from_legacy_provider_diagnostics`
    replaces the provider-aggregate test and is parametrized over the Gemma
    per-cycle and qwen4_exp scalar shapes: counts are `None`, the summary
    reports zero drafts and no `output_accounting`, and `used` comes from the
    execution path naming MTP, not from a count.
  - `test_mtp_summary_reports_a_zero_cycle_block_as_realized_mtp` replaces the
    owned-zero-timing test: a zero-cycle block on the MTP execution path is
    realized intent with zero counts, the whole delivered token is
    autoregressive, and the row's legacy 3/2 counters stay unread.
  - `test_mtp_summary_reports_resident_dynamic_mtp_after_frontend_k0` now
    carries a block (1 cycle, 2 proposed, 1 accepted) beside a non-owned batch
    timing mirror claiming 8/21/13, and asserts the full summary including the
    output split.
  - `test_explicit_mtp_streaming_uses_committed_speculative_chunks` asserts the
    block-derived streamed summary (3 proposed, 0 accepted, 1 speculative token,
    reconciled) instead of the previous all-zero dict.
  - `test_metrics_reports_mtp_serving_and_draft_acceptance` asserts the
    block-derived totals: 1 MTP request, 0 accepted, 6 rejected (the legacy
    mirror would have reported 4/2).
- `tests/test_unit_qwen4exp_shared_public_telemetry.py`: the mixed row is built
  from a real `_MixedCommit` ledger (four committed depth-3 cycles trimmed to an
  eight-token delivered prefix) so `_mixed_output_accounting` publishes the
  block; the summary is asserted against the delivered block (3 cycles, 9
  proposed, 4 accepted, 7 speculative tokens, reconciled) while the row's
  legacy aggregates still claim 4 cycles / 12 / 6. The AR peer row keeps no
  block and reports no speculation.
